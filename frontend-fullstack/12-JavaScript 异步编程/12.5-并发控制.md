## 概述

并发控制解决「同时发起太多异步操作」的问题：限制并发数量、处理失败重试、超时取消等。这是生产环境网络请求、批量任务的必备能力。

```text
并发控制要解决的核心问题：
1. 并发上限 —— 同时只允许 N 个请求，避免打垮服务/浏览器
2. 失败重试 —— 网络抖动时自动重试
3. 超时 —— 避免请求无限挂起
4. 取消 —— 用户主动中止，释放资源
```

## Promise Pool 并发池

Promise Pool（并发池）控制「一批任务同时只执行 N 个」，一个完成就补位下一个。

```js
async function promisePool(tasks, limit) {
  const results = new Array(tasks.length);
  let index = 0;                    // 下一个待执行任务
  const workers = Array.from({ length: limit }, async () => {
    while (index < tasks.length) {
      const current = index++;
      results[current] = await tasks[current]();
    }
  });
  await Promise.all(workers);       // 等所有 worker 完成
  return results;
}
```

```js
// 使用：10 个任务，同时最多 3 个
const tasks = Array.from({ length: 10 }, (_, i) => async () => {
  console.log('开始', i);
  await new Promise(r => setTimeout(r, 100));
  return i;
});

const results = await promisePool(tasks, 3);
```

```text
并发池的原理：
1. 启动 limit 个 worker
2. 每个 worker 循环从共享 index 取任务执行
3. 一个任务完成，worker 立即取下一个
4. 始终保持最多 limit 个任务在运行
```

## Concurrency Limit 并发限制

并发限制是并发池的核心思想，也可用更简单的方式实现（如分批、信号量）。

```js
// 简单的分批限流：每批 limit 个
async function runInBatches(tasks, limit) {
  const results = [];
  for (let i = 0; i < tasks.length; i += limit) {
    const batch = tasks.slice(i, i + limit);
    const batchResults = await Promise.all(batch.map(t => t()));
    results.push(...batchResults);
  }
  return results;
}
```

```js
// 信号量（Semaphore）实现限流
class Semaphore {
  constructor(max) {
    this.max = max;
    this.running = 0;
    this.queue = [];
  }
  async acquire() {
    if (this.running < this.max) {
      this.running++;
      return;
    }
    await new Promise(resolve => this.queue.push(resolve));
    this.running++;
  }
  release() {
    this.running--;
    const next = this.queue.shift();
    if (next) next();
  }
}
```

```text
并发池 vs 分批：
并发池 —— 动态补位，效率高（有任务完成立即补位）
分批 —— 简单直观，但每批要等最慢的那个完成
```

## Retry 重试

网络请求失败时，按策略自动重试，提高成功率。

```js
async function retry(fn, maxRetries = 3) {
  for (let attempt = 1; attempt <= maxRetries; attempt++) {
    try {
      return await fn();
    } catch (error) {
      if (attempt === maxRetries) throw error;
      console.log(`第 ${attempt} 次失败，重试...`);
    }
  }
}
```

```js
// 使用
const data = await retry(() => fetchData(), 3);
```

```text
重试要点：
1. 次数上限 —— 避免无限重试
2. 延迟 —— 重试间隔用退避策略（见下）
3. 条件 —— 只对可重试错误（网络、5xx）重试，4xx 通常不重试
```

## Exponential Backoff 指数退避

指数退避让重试间隔按指数增长，避免「重试风暴」同时冲击服务。

```js
async function retryWithBackoff(fn, maxRetries = 5, baseDelay = 100) {
  for (let attempt = 0; attempt <= maxRetries; attempt++) {
    try {
      return await fn();
    } catch (error) {
      if (attempt === maxRetries) throw error;
      const delay = baseDelay * 2 ** attempt;   // 100, 200, 400, 800...
      const jitter = Math.random() * baseDelay;  // 加随机抖动
      await new Promise(r => setTimeout(r, delay + jitter));
    }
  }
}
```

```text
指数退避 + 抖动：
间隔：100 → 200 → 400 → 800 → 1600（指数增长）
抖动：加随机值，避免多个客户端同时重试（同步冲击）

这是分布式系统重试的标准做法。
```

## Timeout 超时

超时控制避免请求无限挂起，配合 Promise.race 实现。

```js
function withTimeout(promise, ms) {
  const timeout = new Promise((_, reject) =>
    setTimeout(() => reject(new Error('请求超时')), ms),
  );
  return Promise.race([promise, timeout]);
}

try {
  const data = await withTimeout(fetchData(), 3000);
} catch (e) {
  console.error(e.message);   // '请求超时'
}
```

```js
// 超时 + 重试组合
async function fetchWithTimeoutRetry(url, ms, retries) {
  return retry(() => withTimeout(fetch(url), ms), retries);
}
```

## Cancellation 与 AbortController

AbortController 用于主动取消异步操作（fetch、流、定时器等），释放资源。

```js
const controller = new AbortController();
const { signal } = controller;

// 发起请求，传入 signal
fetch('/api/data', { signal })
  .then(res => res.json())
  .catch(err => {
    if (err.name === 'AbortError') {
      console.log('请求已取消');
    }
  });

// 主动取消
controller.abort();
```

```js
// 取消 + 超时：超时自动取消
function fetchWithAbort(url, ms) {
  const controller = new AbortController();
  const timer = setTimeout(() => controller.abort(), ms);
  return fetch(url, { signal: controller.signal })
    .finally(() => clearTimeout(timer));
}
```

```js
// 取消多个并发请求
const controller = new AbortController();
Promise.all([
  fetch('/a', { signal: controller.signal }),
  fetch('/b', { signal: controller.signal }),
]).catch(err => console.log('批量取消'));
controller.abort();
```

```text
AbortController 的价值：
1. 主动取消 —— 用户离开页面、切换路由时取消未完成请求
2. 释放资源 —— 避免无效请求占用连接
3. 竞态处理 —— 取消过期请求，避免旧数据覆盖新数据
```

## 应用场景实战

### 场景一：批量上传文件（限并发）

```js
const files = [...];   // 100 个文件
const uploadTasks = files.map(file => async () => {
  return await uploadFile(file);
});

const results = await promisePool(uploadTasks, 5);   // 同时最多 5 个
```

### 场景二：搜索框防竞态（取消旧请求）

```js
let controller = null;
async function search(keyword) {
  controller?.abort();                    // 取消上次请求
  controller = new AbortController();
  const res = await fetch(`/search?q=${keyword}`, {
    signal: controller.signal,
  });
  return res.json();
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. 批量任务用并发池，控制并发上限（如 3~5）
2. 重试用指数退避 + 抖动，避免重试风暴
3. 可重试错误（网络/5xx）才重试，4xx 不重试
4. 请求加超时，避免无限挂起
5. 路由切换/组件卸载时用 AbortController 取消请求

### 踩坑记录

```text
坑 1：Promise.all 无并发限制
结论：100 个请求同时发出，服务被打垮、浏览器卡顿。
原因：Promise.all 不限制并发。
解法：用并发池限制同时执行数量。

坑 2：重试无退避
结论：失败后立即重试，多个客户端同时冲击服务。
原因：固定间隔或无间隔重试，形成重试风暴。
解法：指数退避 + 随机抖动。

坑 3：重试不区分错误类型
结论：4xx（如 404）也反复重试，浪费资源。
原因：不判断错误是否可重试。
解法：只对网络错误、5xx、超时重试。

坑 4：竞态导致旧数据覆盖新数据
结论：快速输入时，旧的请求结果后返回，覆盖了最新结果。
原因：多个请求并发，返回顺序不定。
解法：AbortController 取消旧请求，或用请求序号判断。

坑 5：忘清理定时器导致内存泄漏
结论：组件卸载后定时器/请求仍在，报错或泄漏。
原因：超时定时器、AbortController 未清理。
解法：finally 中清理定时器，卸载时 abort。
```

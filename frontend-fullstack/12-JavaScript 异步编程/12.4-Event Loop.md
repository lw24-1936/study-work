## 概述

事件循环（Event Loop）是 JavaScript 实现「单线程 + 异步」的机制：主线程通过调用栈同步执行代码，异步操作交给环境（Web APIs），完成后进入任务队列，事件循环不断把队列中的任务取回调用栈执行。

```text
事件循环的组成部分：
1. Call Stack —— 同步代码执行的地方（后进先出）
2. Web APIs —— 环境提供的异步能力（定时器、网络、DOM 事件）
3. 任务队列 —— 等待执行的回调（宏任务、微任务队列）
4. 渲染 —— 浏览器在任务间隙更新界面

核心：JS 是单线程的，但通过事件循环实现了「非阻塞」的异步。
```

## Call Stack 调用栈

调用栈是同步执行的「现场」，函数调用入栈、返回出栈。栈空时事件循环才会取下一个任务。

```js
function a() { b(); }
function b() { c(); }
function c() { console.log('执行'); }

a();   // a 入栈 → b 入栈 → c 入栈 → c 出栈 → b 出栈 → a 出栈
```

```text
调用栈的意义：
1. 同步代码按调用顺序进出栈
2. 栈溢出 —— 无限递归导致栈满（RangeError）
3. 栈空 —— 事件循环才从队列取任务执行
```

```js
// 栈溢出
function recurse() { recurse(); }
recurse();   // RangeError: Maximum call stack size exceeded
```

## Web APIs 与任务队列

异步操作由环境提供，不在调用栈里等待。完成后，回调进入任务队列，等待事件循环调度。

```js
console.log('1');               // 同步，立即入栈执行

setTimeout(() => {
  console.log('3');             // 异步，定时器到期后进入任务队列
}, 0);

console.log('2');               // 同步

// 输出顺序：1 2 3
```

```text
执行流程：
1. 同步代码依次执行（1、2）
2. setTimeout 交给 Web API 定时，0ms 后回调进入任务队列
3. 调用栈清空后，事件循环取队列中的回调执行（3）

关键：即使 0ms 延迟，也要等同步代码全部执行完。
```

## Task Queue 与 Microtask Queue

任务分「宏任务」和「微任务」两类，微任务优先级更高，每个宏任务执行完后会清空所有微任务。

```text
宏任务（Macrotask / Task）：
setTimeout、setInterval、I/O、事件回调、requestAnimationFrame（渲染相关）

微任务（Microtask）：
Promise.then/catch/finally、async/await、MutationObserver、queueMicrotask

执行顺序：宏任务 → 清空微任务队列 → 渲染 → 下一个宏任务
```

```js
console.log('1');

setTimeout(() => console.log('4'), 0);   // 宏任务

Promise.resolve()
  .then(() => console.log('2'))          // 微任务
  .then(() => console.log('3'));

// 输出：1 2 3 4
// 解释：同步(1) → 微任务(2,3) → 宏任务(4)
```

```text
关键规则：
1. 每个宏任务结束后，立即清空整个微任务队列
2. 微任务里产生的微任务，也在本次清空（直到队列为空）
3. 所以微任务比下一个宏任务更早执行
```

## Macrotask 宏任务

宏任务是事件循环的「主任务」，一次循环处理一个宏任务。

```js
// 多个宏任务按注册顺序依次执行
setTimeout(() => console.log('A'), 0);
setTimeout(() => console.log('B'), 0);
// A B（同类型的宏任务按先后顺序）
```

```text
常见宏任务来源：
setTimeout / setInterval —— 定时器
DOM 事件 —— 点击、键盘等
网络 —— fetch/XHR 回调
MessageChannel / postMessage

宏任务之间：清空微任务 → （可能渲染）→ 下一个宏任务
```

## Rendering Opportunity 渲染时机

浏览器在宏任务与宏任务之间，可能进行渲染。渲染前会先清空微任务。

```text
浏览器帧的节奏：
宏任务 → 微任务 → 渲染（如果需要）→ 宏任务 → ...

渲染时机：
1. 通常一帧（16.6ms）最多渲染一次
2. 渲染前会清空微任务（所以微任务会阻塞渲染）
3. requestAnimationFrame 在渲染前执行
```

```text
性能启示：
1. 大量微任务会延迟渲染（微任务清空前不渲染）
2. 长宏任务会阻塞渲染（主线程被占）
3. 耗时操作应拆分或放入 Worker
```

## requestAnimationFrame 与 requestIdleCallback

rAF 在下一帧渲染前执行回调（适合动画）；rIC 在浏览器空闲时执行（适合低优先级任务）。

```js
// requestAnimationFrame：每帧渲染前执行，与刷新率同步
function animate() {
  updatePosition();
  requestAnimationFrame(animate);   // 下一帧继续
}
requestAnimationFrame(animate);
```

```js
// requestIdleCallback：浏览器空闲时执行
requestIdleCallback(deadline => {
  while (deadline.timeRemaining() > 0) {
    doChunkOfWork();   // 利用剩余时间做低优先级工作
  }
});
```

```text
rAF vs rIC vs 定时器：
requestAnimationFrame —— 渲染前执行，适合动画（每帧一次）
requestIdleCallback —— 空闲时执行，适合非紧急任务（可被取消）
setTimeout —— 宏任务，与渲染无直接关联，不适合动画（不稳定）
```

## 应用场景实战

### 场景一：理解执行顺序

```js
console.log('script start');

setTimeout(() => console.log('setTimeout'), 0);

Promise.resolve()
  .then(() => console.log('promise1'))
  .then(() => console.log('promise2'));

console.log('script end');

// 输出：
// script start
// script end
// promise1
// promise2
// setTimeout
```

### 场景二：拆分长任务避免阻塞

```js
// 把大数据处理拆成小块，让出主线程
async function processLarge(items) {
  for (let i = 0; i < items.length; i++) {
    process(items[i]);
    if (i % 100 === 0) {
      await new Promise(r => setTimeout(r, 0));   // 让出主线程
    }
  }
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. 理解「宏任务 → 微任务 → 渲染」的顺序
2. 动画用 requestAnimationFrame，别用 setTimeout
3. 低优先级任务用 requestIdleCallback 或让出主线程
4. 避免大量微任务阻塞渲染
5. 长任务拆分，避免阻塞主线程导致卡顿

### 踩坑记录

```text
坑 1：以为 setTimeout 0 立即执行
结论：setTimeout(fn, 0) 在同步代码后才执行。
原因：0ms 是最小延迟，回调仍要进队列等待。
解法：理解异步回调都要等调用栈清空。

坑 2：微任务队列无限循环
结论：微任务里不断产生微任务，页面卡死。
原因：微任务清空前不执行宏任务、不渲染。
解法：微任务里避免无限递归产生新微任务。

坑 3：用 setTimeout 做动画抖动
结论：动画卡顿、不稳定。
原因：setTimeout 与渲染不同步，时机不稳定。
解法：动画用 requestAnimationFrame。

坑 4：忘记渲染前会清空微任务
结论：微任务过多导致渲染延迟、页面卡顿。
原因：渲染前必须清空所有微任务。
解法：控制微任务数量，重活放宏任务或 Worker。

坑 5：混淆宏任务与微任务的顺序
结论：预期 setTimeout 先于 Promise.then 执行，实际相反。
原因：微任务优先于下一个宏任务。
解法：牢记每个宏任务后先清空微任务。
```

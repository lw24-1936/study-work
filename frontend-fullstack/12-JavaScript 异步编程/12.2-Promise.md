## 概述

Promise 是异步操作的「容器」，表示一个未来才会完成（或失败）的结果。它解决了回调地狱的嵌套问题，提供链式调用和统一错误处理，是 async/await 的基础。

```text
Promise 的核心价值：
1. 状态机 —— pending → fulfilled / rejected，且不可逆
2. 链式调用 —— then 返回新 Promise，可串联
3. 统一错误 —— 链上任意一环出错，都能被 catch 捕获
4. 信任 —— resolve/reject 只生效一次，结果可多次读取
```

## Promise 与三种状态

Promise 有三种状态，一旦从 pending 变为 fulfilled 或 rejected，就不可再变（settled）。

```text
三种状态：
Pending（进行中）—— 初始状态，结果未定
Fulfilled（已完成）—— 操作成功，有结果值
Rejected（已失败）—— 操作失败，有错误原因

关键：状态转换不可逆（pending → fulfilled 或 pending → rejected），
settled 后状态和值都固定不变。
```

```js
const promise = new Promise((resolve, reject) => {
  // 异步操作
  setTimeout(() => {
    const ok = true;
    ok ? resolve('成功结果') : reject(new Error('失败原因'));
  }, 100);
});

promise.then(
  value => console.log('成功:', value),
  error => console.log('失败:', error.message),
);
```

```text
new Promise(executor) 的执行：
1. executor 立即同步执行
2. resolve(value) → 状态变 fulfilled
3. reject(error) → 状态变 rejected
4. resolve/reject 之后的调用被忽略（只生效一次）
```

## then / catch / finally

then 注册成功/失败回调并返回新 Promise；catch 处理错误；finally 无论成败都执行。

```js
fetchData()
  .then(data => {
    console.log('成功', data);
    return processData(data);   // 返回新值或 Promise，继续链
  })
  .then(result => console.log('处理结果', result))
  .catch(error => console.error('任一环节出错', error))
  .finally(() => console.log('无论如何都执行'));
```

```text
then 返回值的链式传递：
1. 返回普通值 → 下一个 then 收到该值
2. 返回 Promise → 等待它 settle 后传递结果
3. 不返回 → 下一个 then 收到 undefined
4. 抛出异常 → 跳过后续 then，进入 catch
```

```js
// 链式传递
Promise.resolve(1)
  .then(v => v + 1)          // 2
  .then(v => v * 2)          // 4
  .then(v => Promise.resolve(v + 1))  // 5
  .then(v => console.log(v)); // 5
```

## Promise.resolve / reject

Promise.resolve 和 Promise.reject 是快捷方法，用于创建已确定状态的 Promise。

```js
Promise.resolve(42);       // fulfilled，值为 42
Promise.reject('错误');    // rejected，原因为 '错误'

// resolve 对 Promise/类 thenable 的特殊处理
Promise.resolve(Promise.resolve(1));  // 直接采用传入的 Promise
```

```js
// 把任意值包装成 Promise（统一异步语义）
function maybeAsync(value) {
  return Promise.resolve(value);   // 无论 value 是什么，都返回 Promise
}
```

```text
Promise.resolve 的规则：
1. 传入 Promise → 直接返回该 Promise
2. 传入 thenable → 调用其 then 方法
3. 传入普通值 → 包装为 fulfilled Promise
```

## Promise.all / allSettled

Promise.all 等待全部成功（任一失败即失败）；Promise.allSettled 等待全部 settle（无论成败）。

```js
// Promise.all：全部成功才成功，任一失败即失败
Promise.all([fetchA(), fetchB(), fetchC()])
  .then(([a, b, c]) => console.log(a, b, c))   // 按顺序返回结果数组
  .catch(err => console.error('任一失败:', err));

// Promise.allSettled：等待全部结束，各自报告状态
Promise.allSettled([p1, p2, p3]).then(results => {
  results.forEach(r => {
    if (r.status === 'fulfilled') console.log('成功', r.value);
    else console.log('失败', r.reason);
  });
});
```

```text
Promise.all vs allSettled：
all —— 全有全无，适合「必须全部成功」的场景（如批量依赖数据）
allSettled —— 允许部分失败，适合「尽力而为」的场景（如批量上报）
```

## Promise.race / any

Promise.race 返回最先 settle 的结果（无论成败）；Promise.any 返回最先成功的（全部失败才 reject）。

```js
// race：最先 settle 的胜出（含失败）
Promise.race([timeout(), fetchData()])
  .then(data => console.log('最快的结果', data))
  .catch(err => console.error('最快失败', err));

// any：最先成功的胜出（忽略失败）
Promise.any([fetchFromServerA(), fetchFromServerB(), fetchFromServerC()])
  .then(data => console.log('任一成功即可', data))
  .catch(err => console.error('全部失败', err));
```

```text
race vs any：
race —— 第一个 settle（成功或失败）决定结果，常用于超时竞速
any —— 第一个成功决定结果，全部失败才 reject，常用于多路容错

超时控制典型写法：
Promise.race([请求, 超时Promise]) —— 谁先 settle 谁赢。
```

## 应用场景实战

### 场景一：超时控制

```js
function withTimeout(promise, ms) {
  const timeout = new Promise((_, reject) =>
    setTimeout(() => reject(new Error('请求超时')), ms),
  );
  return Promise.race([promise, timeout]);
}

await withTimeout(fetchData(), 3000);
```

### 场景二：并发请求全部成功

```js
// 三个接口互不依赖，并发请求
const [user, orders, cart] = await Promise.all([
  fetchUser(),
  fetchOrders(),
  fetchCart(),
]);
```

## 最佳实践与踩坑记录

### 最佳实践

1. 需要全部成功用 all，允许部分失败用 allSettled
2. 超时控制用 race + 超时 Promise
3. 多路容错用 any
4. 链式调用中始终返回 Promise 或值，避免断链
5. 统一用 catch 兜底，finally 做清理

### 踩坑记录

```text
坑 1：then 里不 return 导致断链
结论：后续 then 拿到 undefined。
原因：then 回调没返回，链式传递中断。
解法：需要传递结果就 return。

坑 2：Promise.all 任一失败全部失败
结论：一个请求失败，其他成功结果也拿不到。
原因：all 是「全有全无」语义。
解法：需要部分成功用 allSettled，或给每个单独 catch。

坑 3：竞速用 race 但想要「成功优先」
结论：race 里失败也参与竞速，可能拿到失败。
原因：race 比较的是「先 settle」，不看成功失败。
解法：成功优先用 any。

坑 4：忘处理 reject 导致 Unhandled Rejection
结论：Promise 失败未 catch，控制台报错甚至崩溃。
原因：rejected 的 Promise 没有 catch 处理。
解法：所有 Promise 链加 catch，或全局监听 unhandledrejection。

坑 5：finally 误以为能改变结果
结论：finally 返回的值被忽略。
原因：finally 不接收也不改变链的结果。
解法：需要改结果用 then，清理逻辑用 finally。
```

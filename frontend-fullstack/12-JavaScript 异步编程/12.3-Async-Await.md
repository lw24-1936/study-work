## 概述

async/await 是 Promise 的语法糖，让异步代码以**同步的写法**表达，彻底解决回调地狱与链式可读性问题。async 函数返回 Promise，await 等待 Promise 完成。

```text
async/await 的本质：
async —— 声明异步函数，返回值自动包装为 Promise
await —— 暂停函数执行，等待 Promise settle 后继续

它没有引入新机制，底层仍是 Promise + 微任务。
```

## async 函数

async 函数返回一个 Promise：return 的值会被包装为 fulfilled，抛出的异常会变成 rejected。

```js
async function foo() {
  return 42;           // 等价 return Promise.resolve(42)
}

foo();                 // Promise { 42 }
foo().then(v => console.log(v));   // 42
```

```js
// async 函数抛错 → rejected Promise
async function bar() {
  throw new Error('出错了');
}
bar().catch(err => console.log(err.message));   // '出错了'
```

```text
async 函数要点：
1. 返回值自动包装为 Promise
2. 抛出异常自动转为 rejected
3. 返回 Promise 时直接采用（不再二次包装）
4. 箭头函数、方法都可用 async
```

## await 表达式

await 等待一个 Promise settle，返回其结果；await 只能在 async 函数内（或模块顶层）使用。

```js
async function load() {
  const data = await fetchData();   // 等待完成，拿到结果
  console.log(data);
  return data;
}
```

```js
// await 非 Promise 值：直接返回该值
const result = await 42;   // 42

// await 顺序执行多个异步
async function process() {
  const user = await getUser(1);
  const orders = await getOrders(user.id);   // 等 user 完成后再执行
  return orders;
}
```

```text
await 的语义：
1. 暂停当前 async 函数执行
2. 等待右侧 Promise settle（不阻塞主线程）
3. fulfilled 返回结果，rejected 抛出异常
4. 顶层 await —— 模块顶层可直接 await（ES2022）
```

## Error Handling 错误处理

async/await 的错误用 try/catch 处理，与同步代码一致。

```js
async function load() {
  try {
    const data = await fetchData();
    return data;
  } catch (error) {
    console.error('加载失败:', error.message);
    return null;             // 兜底返回
  }
}
```

```js
// 未捕获的错误 → 返回 rejected Promise
async function risky() {
  const data = await fetchData();   // 抛错则整个函数 rejected
  return data;
}
risky().catch(err => console.error(err));
```

```text
错误处理模式：
1. try/catch 包裹 —— 捕获单个或多个 await 的错误
2. 链式 catch —— async 函数调用处 .catch 兜底
3. 部分成功 —— 每个 await 单独 try/catch，允许部分失败
```

```js
// 部分失败容忍：各自 catch
async function loadAll() {
  const [a, b] = await Promise.all([
    fetchA().catch(() => null),
    fetchB().catch(() => null),
  ]);
  return { a, b };
}
```

## Sequential Async 串行异步

串行执行：后一个操作依赖前一个的结果，用多个 await 顺序书写。

```js
async function sequential() {
  const user = await getUser();           // 第 1 步
  const orders = await getOrders(user.id); // 依赖 user
  const detail = await getDetail(orders[0].id); // 依赖 orders
  return detail;
}
```

```text
串行 vs 并发：
串行 —— 有依赖关系，必须等前一个完成（await 逐个写）
并发 —— 无依赖关系，应同时发起（Promise.all）
```

## Concurrent Async 并发异步

并发执行：无依赖的异步操作应同时发起，用 Promise.all 等待，而非逐个 await。

```js
// 反例：无依赖却串行，耗时叠加
async function slow() {
  const a = await fetchA();   // 1s
  const b = await fetchB();   // 1s（等 a 完成才发起）
  return [a, b];              // 总耗时约 2s
}

// 正例：并发发起，耗时取最大
async function fast() {
  const [a, b] = await Promise.all([fetchA(), fetchB()]);  // 同时发起
  return [a, b];              // 总耗时约 1s
}
```

```js
// 逐个 await 但提前发起（等价并发）
async function fast2() {
  const pa = fetchA();        // 立即发起
  const pb = fetchB();        // 立即发起
  const a = await pa;
  const b = await pb;
  return [a, b];
}
```

## Promise Queue 队列

Promise 队列用于「顺序执行一批异步任务」，避免同时并发过多。与串行不同，队列常用于任务列表逐个处理。

```js
// 顺序执行队列：上一个完成才执行下一个
async function runQueue(tasks) {
  const results = [];
  for (const task of tasks) {
    results.push(await task());   // 逐个 await，顺序执行
  }
  return results;
}
```

```js
// 用 reduce 实现顺序链
function runSequentially(tasks) {
  return tasks.reduce((chain, task) =>
    chain.then(results =>
      task().then(r => [...results, r]),
    ),
    Promise.resolve([]),
  );
}
```

```text
队列 vs 并发池：
队列 —— 严格顺序，一个接一个，适合有依赖或需限速的任务
并发池 —— 限制同时执行 N 个，兼顾速度与资源（见 [[12.5-并发控制]]）
```

## 应用场景实战

### 场景一：串行 + 并发组合

```js
async function loadDashboard() {
  // 并发加载互不依赖的数据
  const [user, stats] = await Promise.all([fetchUser(), fetchStats()]);
  // 串行：依赖 user.id 的后续请求
  const recent = await fetchRecent(user.id);
  return { user, stats, recent };
}
```

### 场景二：顺序处理任务队列

```js
async function uploadAll(files) {
  const results = [];
  for (const file of files) {
    try {
      results.push(await upload(file));
    } catch (e) {
      results.push({ file, error: e.message });
    }
  }
  return results;
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. 无依赖的异步操作用 Promise.all 并发，别逐个 await
2. 有依赖的用串行 await，保持逻辑清晰
3. 错误用 try/catch，需要部分成功时各自 catch
4. 队列用 for...of + await，别用 forEach
5. 顶层 await 谨慎使用（影响模块加载）

### 踩坑记录

```text
坑 1：forEach 里 await 无效
结论：forEach 里的 await 不阻塞，函数提前返回。
原因：forEach 回调不是 async 上下文，await 不生效。
解法：用 for...of 循环 + await。

坑 2：无依赖却串行 await
结论：接口耗时叠加，性能差。
原因：逐个 await，后一个等前一个完成才发起。
解法：Promise.all 并发发起。

坑 3：忘写 await 导致拿到 Promise
结论：const data = fetchData() 拿到 Promise 而非数据。
原因：async 函数不加 await 直接返回 Promise。
解法：记得 await（或明确需要 Promise 时才不加）。

坑 4：await 在非 async 环境使用
结论：普通函数里 await 报语法错误。
原因：await 只能在 async 函数或模块顶层。
解法：加 async，或用 .then 处理。

坑 5：try/catch 抓不到未 await 的错误
结论：try { fetchData() } 不 await，错误逃逸。
原因：未 await 的 Promise 错误不会同步抛出。
解法：await 后捕获，或 .catch 处理。
```

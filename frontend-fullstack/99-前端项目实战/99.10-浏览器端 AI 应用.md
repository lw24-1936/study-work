## 概述

浏览器端 AI 应用把模型推理搬到浏览器本地：用 WebGPU/WASM 加速、ONNX Runtime Web 或 Transformers.js 加载模型，实现完全离线的推理。好处是数据不出本机、零服务端成本、隐私安全，代价是模型要小、首包要优化。

```text
浏览器端 AI 的技术栈：
1. WebGPU —— 现代 GPU 加速接口，推理算力主力
2. WebAssembly —— 把 C/Rust 推理引擎搬进浏览器
3. ONNX Runtime Web —— 微软的跨端推理运行时
4. Transformers.js —— HuggingFace 的浏览器版 transformers
5. Worker —— 推理放后台线程，不阻塞 UI
```

```js
// Transformers.js 最小示例：情感分析
import { pipeline } from '@xenova/transformers';
const classifier = await pipeline('sentiment-analysis');
const result = await classifier('I love this!');
// [{ label: 'POSITIVE', score: 0.99 }]
```

## WebGPU

WebGPU 是浏览器新一代 GPU 接口，比 WebGL 更底层、性能更好，是浏览器端 AI 推理的算力主力。

```js
// WebGPU 基础：获取设备与队列
const adapter = await navigator.gpu.requestAdapter();
const device = await adapter.requestDevice();
const queue = device.queue;

// 提交一个计算着色器（推理核心）
const commandEncoder = device.createCommandEncoder();
const pass = commandEncoder.beginComputePass();
pass.setPipeline(computePipeline);
pass.setBindGroup(0, bindGroup);
pass.dispatchWorkgroups(workgroupX);
pass.end();
queue.submit([commandEncoder.finish()]);
```

```text
WebGPU 在 AI 里的角色：
1. 计算着色器 —— 矩阵乘法等推理算子用 compute shader 实现
2. 高性能 —— 比 WASM 的 CPU 推理快数倍到数十倍
3. 兼容性 —— Chrome/Edge 支持好，Safari 较新版本支持
4. 降级 —— 不支持时降级到 WASM CPU 推理
```

## WebAssembly

WebAssembly（WASM）把 C/C++/Rust 写的推理引擎编译成浏览器可执行的字节码，提供接近原生的 CPU 推理性能。

```js
// 加载并实例化 WASM 模块
const { instance } = await WebAssembly.instantiateStreaming(
  fetch('inference.wasm'),
  imports,
);
// 调用导出的推理函数
const result = instance.exports.runInference(inputData);
```

```text
WASM 在 AI 里的角色：
1. CPU 推理 —— WebGPU 不可用时的降级方案
2. 现成引擎 —— ONNX Runtime、TensorFlow Lite 都有 WASM 版
3. 内存模型 —— 线性内存 + TypedArray 交换张量数据
4. SIMD —— WASM SIMD 指令加速数值计算
```

## ONNX Runtime Web

ONNX Runtime Web 是微软的浏览器推理运行时，支持 WebGPU 和 WASM 两种后端，加载 ONNX 格式模型。

```js
import * as ort from 'onnxruntime-web';

// 加载模型 + 推理
const session = await ort.InferenceSession.create('model.onnx', {
  executionProviders: ['webgpu', 'wasm'],  // 优先 WebGPU，降级 WASM
});
const input = new ort.Tensor('float32', data, [1, 3, 224, 224]);
const output = await session.run({ input });
```

```text
ONNX Runtime Web 的要点：
1. ONNX 格式 —— 跨框架的模型交换格式
2. 双后端 —— webgpu 加速 + wasm 兜底
3. 模型转换 —— PyTorch 等模型先转 ONNX 再用
4. 量化 —— int8 量化减小体积、加速推理
```

## Transformers.js

Transformers.js 是 HuggingFace 的浏览器版 transformers，API 与 Python 版一致，内置大量预训练模型。

```js
import { pipeline, env } from '@xenova/transformers';

// 文本生成（流式）
const generator = await pipeline('text-generation', 'Xenova/gpt2');
const output = await generator('Once upon a time', {
  max_new_tokens: 50,
  callback_function: (tokens) => {
    // tokens 是增量生成的 token，可流式渲染
  },
});
```

```js
// 特征提取（用于语义搜索 / RAG）
const extractor = await pipeline('feature-extraction', 'Xenova/all-MiniLM-L6-v2');
const embedding = await extractor('什么是闭包？', { pooling: 'mean' });
// embedding.data 是向量，可与向量库做相似度检索
```

## Local Inference

Local Inference（本地推理）让模型在用户设备上运行，数据不离开浏览器。

```text
本地推理 vs 云端推理：
1. 隐私 —— 数据不上传，适合敏感场景
2. 成本 —— 零 API 调用费用
3. 离线 —— 无网络也能用
4. 延迟 —— 免网络往返，但首包要下载模型
5. 限制 —— 模型必须小，算力受设备限制
```

```js
// 本地推理的完整流程
// 1. 检查 WebGPU 可用性
const gpuAvailable = 'gpu' in navigator;
// 2. 加载模型（带进度回调）
const model = await loadModel('tiny-model.onnx', (progress) => {
  updateProgress(progress);  // 显示下载进度
});
// 3. 推理
const result = await model.run(input);
```

## Model Cache

Model Cache 缓存已下载的模型，避免重复下载，第二次打开秒开。

```js
// 用 Cache API 缓存模型文件
async function loadCachedModel(url) {
  const cache = await caches.open('models-v1');
  let response = await cache.match(url);
  if (!response) {
    response = await fetch(url);
    await cache.put(url, response.clone());
  }
  return response.arrayBuffer();
}
```

```text
Model Cache 的策略：
1. Cache API —— 缓存模型二进制，跨会话复用
2. 版本管理 —— 模型更新时改缓存版本号
3. IndexedDB —— 大模型用 IndexedDB 存（Cache API 有配额）
4. 预下载 —— 空闲时后台预取常用模型
```

## Worker

Worker 把推理放到后台线程，避免阻塞主线程，UI 保持流畅。

```js
// 主线程：创建 Worker 并通信
const worker = new Worker('inference-worker.js', { type: 'module' });
worker.postMessage({ type: 'load', url: 'model.onnx' });
worker.postMessage({ type: 'infer', input: data });

worker.onmessage = (e) => {
  if (e.data.type === 'result') {
    renderResult(e.data.output);
  }
};
```

```js
// inference-worker.js：Worker 内做推理
import * as ort from 'onnxruntime-web';
let session;
self.onmessage = async (e) => {
  if (e.data.type === 'load') {
    session = await ort.InferenceSession.create(e.data.url);
    self.postMessage({ type: 'loaded' });
  } else if (e.data.type === 'infer') {
    const output = await session.run(e.data.input);
    self.postMessage({ type: 'result', output });
  }
};
```

## Streaming UI

Streaming UI 让生成式模型的输出逐字显示，配合加载态、进度条提升体验。

```js
// 流式渲染：模型边生成 token 边显示
async function generateStream(prompt) {
  const generator = await pipeline('text-generation', modelId);
  const textEl = document.querySelector('#output');
  await generator(prompt, {
    callback_function: (tokens) => {
      // 增量追加 token
      textEl.textContent += tokens.map(t => t.token).join('');
      // 用 rAF 节流，避免每 token 都强制重排
    },
  });
}
```

```text
Streaming UI 的要点：
1. 逐 token 渲染 —— 生成到哪显示到哪
2. 加载态 —— 模型下载/加载时显示进度条
3. 取消 —— 支持中止推理，释放资源
4. 状态提示 —— 区分「下载中/加载中/推理中/完成」
```

## 应用场景实战

### 场景一：本地图片分类

```js
// 用 Transformers.js 做本地图片分类，数据不上传
import { pipeline } from '@xenova/transformers';

const classifier = await pipeline('image-classification', 'Xenova/vit-base-patch16-224');

const img = document.querySelector('img');
const result = await classifier(img.src);
// [{ label: 'golden retriever', score: 0.98 }, ...]
```

### 场景二：浏览器端语义搜索

```js
// 本地 embedding + 向量相似度，做私有文档搜索
const extractor = await pipeline('feature-extraction', 'Xenova/all-MiniLM-L6-v2');

async function embed(text) {
  const out = await extractor(text, { pooling: 'mean' });
  return Array.from(out.data);  // 向量
}

function cosineSimilarity(a, b) {
  const dot = a.reduce((s, v, i) => s + v * b[i], 0);
  const na = Math.sqrt(a.reduce((s, v) => s + v * v, 0));
  const nb = Math.sqrt(b.reduce((s, v) => s + v * v, 0));
  return dot / (na * nb);
}

// 预计算文档向量，查询时算相似度排序
const queryVec = await embed('查询词');
const results = docs.map(d => ({
  doc: d,
  score: cosineSimilarity(queryVec, d.vec),
})).sort((a, b) => b.score - a.score);
```

## 最佳实践与踩坑记录

### 最佳实践

1. 模型优先选量化版（int8），体积小、推理快
2. 推理放 Worker，别阻塞主线程
3. 模型用 Cache API 缓存，避免重复下载
4. WebGPU 优先，WASM 降级，做能力检测
5. 首包做按需加载，别一次性加载所有模型
6. 提供进度条和取消，长任务要可中断

### 踩坑记录

```text
坑 1：模型太大导致首屏卡死
结论：打开页面就卡住，加载几百 MB 模型。
原因：主线程同步加载大模型，阻塞渲染。
解法：模型量化 + 懒加载 + 放 Worker + 显示进度。

坑 2：WebGPU 不可用时直接报错
结论：Safari 老版本或低端设备上推理失败。
原因：只配了 WebGPU 后端，没有降级。
解法：executionProviders 配 ['webgpu', 'wasm']，自动降级。

坑 3：重复下载模型
结论：每次刷新都重新下载几十 MB 模型。
原因：没有缓存模型文件。
解法：Cache API / IndexedDB 缓存，版本号管理更新。

坑 4：推理阻塞 UI 交互
结论：推理期间页面点击没反应。
原因：推理跑在主线程。
解法：推理移入 Worker，postMessage 通信。

坑 5：流式渲染每 token 强制重排
结论：生成过程页面抖动卡顿。
原因：每来一个 token 都同步改 DOM 触发重排。
解法：requestAnimationFrame 节流，批量更新。
```

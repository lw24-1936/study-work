## 概述

AI Chat 应用是「大模型能力」与「前端交互」的结合：把 LLM API 的流式输出渲染成可读的 Markdown、代码高亮、引用标注，再叠加工具调用、文件上传、RAG 检索、会话记忆等能力，做出 ChatGPT 式的对话产品。

```text
AI Chat 应用的核心模块：
1. LLM API —— 对接大模型，发消息收回复
2. Streaming —— 流式输出，边生成边显示
3. Markdown —— 渲染富文本回复
4. Tool Calling —— 让模型调用外部工具
5. RAG —— 检索增强，回答私有知识
6. Memory —— 会话记忆与上下文管理
```

```js
// 最小可运行的流式对话
const res = await fetch('/api/chat', {
  method: 'POST',
  body: JSON.stringify({ messages: [{ role: 'user', content: '你好' }] }),
});
const reader = res.body.getReader();
const decoder = new TextDecoder();
while (true) {
  const { done, value } = await reader.read();
  if (done) break;
  const chunk = decoder.decode(value);
  renderDelta(chunk);  // 增量渲染到页面
}
```

## LLM API

LLM API 是对话应用的底座，前端通过 REST 或 SSE 调用，发送 messages 数组、接收回复。

```js
// 典型的 Chat Completions 请求
const response = await fetch('https://api.example.com/v1/chat/completions', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json', Authorization: 'Bearer KEY' },
  body: JSON.stringify({
    model: 'gpt-4o',
    messages: [
      { role: 'system', content: '你是一个前端助手' },
      { role: 'user', content: '什么是闭包？' },
    ],
    stream: true,
  }),
});
```

```text
messages 的角色：
1. system —— 系统提示，设定人设与规则
2. user —— 用户消息
3. assistant —— 助手历史回复
4. tool —— 工具调用结果
```

## Streaming

Streaming（流式输出）让模型边生成边返回，用户不必等完整回复，是 AI Chat 体验的核心。

```js
// SSE 流式接收
const source = new EventSource('/api/chat/stream');
source.onmessage = (e) => {
  const delta = JSON.parse(e.data);
  appendText(delta.content);   // 增量追加
};
source.onerror = () => {
  source.close();
  finishStreaming();
};
```

```js
// fetch 读流（更通用，可带 POST body）
async function streamChat(messages, onDelta) {
  const res = await fetch('/api/chat', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ messages, stream: true }),
  });
  const reader = res.body.getReader();
  const decoder = new TextDecoder();
  let buffer = '';
  while (true) {
    const { done, value } = await reader.read();
    if (done) break;
    buffer += decoder.decode(value, { stream: true });
    // 按 SSE 行分割（data: ...）
    const lines = buffer.split('\n');
    buffer = lines.pop();
    for (const line of lines) {
      if (line.startsWith('data: ')) {
        onDelta(JSON.parse(line.slice(6)).content);
      }
    }
  }
}
```

## Markdown

模型回复通常是 Markdown 格式，前端要用 Markdown 渲染器转成 HTML，并做好 XSS 防护。

```js
import { marked } from 'marked';
import DOMPurify from 'dompurify';

// 渲染 + 净化，防止 XSS
const html = marked.parse(markdownText);
const safeHtml = DOMPurify.sanitize(html);
container.innerHTML = safeHtml;
```

```text
Markdown 渲染的要点：
1. 渲染库 —— marked / markdown-it / remark 生态
2. XSS 防护 —— 模型输出不可信，必须 DOMPurify 净化
3. 流式渲染 —— 边生成边重新渲染，注意性能（防抖/节流）
4. 扩展语法 —— 表格、任务列表、数学公式（KaTeX）、mermaid
```

## Code Highlight

回复里的代码块需要语法高亮，前端常用 highlight.js 或 Prism.js。

```js
import hljs from 'highlight.js';
import { marked } from 'marked';
import { markedHighlight } from 'marked-highlight';

marked.use(markedHighlight({
  highlight(code, lang) {
    if (lang && hljs.getLanguage(lang)) {
      return hljs.highlight(code, { language: lang }).value;
    }
    return hljs.highlightAuto(code).value;
  },
}));
```

```text
代码高亮的实现：
1. 渲染时高亮 —— marked 插件在解析代码块时调用 hljs
2. 加复制按钮 —— 代码块右上角复制按钮，提升体验
3. 语言标注 —— 没标注语言时 highlightAuto 自动识别
4. 主题 —— 亮暗两套高亮主题，跟随应用主题
```

## Tool Calling

Tool Calling 让模型调用外部函数（查天气、搜数据库、执行代码），前端负责声明工具并回传调用结果。

```js
// 声明工具，模型返回 tool_calls 指令
const tools = [{
  type: 'function',
  function: {
    name: 'get_weather',
    description: '查询城市天气',
    parameters: {
      type: 'object',
      properties: { city: { type: 'string' } },
      required: ['city'],
    },
  },
}];

// 模型返回后，执行工具并回传结果
const msg = response.choices[0].message;
if (msg.tool_calls) {
  for (const call of msg.tool_calls) {
    const result = await executeTool(call.function.name, JSON.parse(call.function.arguments));
    messages.push({ role: 'tool', tool_call_id: call.id, content: JSON.stringify(result) });
  }
  // 继续请求，让模型基于工具结果生成最终回复
}
```

## File Upload

文件上传让对话支持图片、文档等多模态输入。

```js
// 上传文件并预览
const input = document.querySelector('#file-input');
input.addEventListener('change', async (e) => {
  const file = e.target.files[0];

});
```

## RAG

RAG（检索增强生成）让对话能回答私有知识库的问题：先检索相关文档，再连同问题一起发给模型。

```js
// 前端 RAG 对话：先检索再生成
async function ragChat(question) {
  // 1. 检索相关文档
  const { chunks } = await search(question);  // 向量检索
  // 2. 拼上下文
  const context = chunks.map(c => c.text).join('\n\n');
  // 3. 发给模型
  const prompt = `参考以下资料回答问题：\n\n${context}\n\n问题：${question}`;
  return streamChat([{ role: 'user', content: prompt }], renderDelta);
}
```

## Citation

Citation（引用标注）让回答里的每句话都能追溯到来源，用户点击引用查看原文。

```js
// 回答里的引用标注 [1] [2]，点击跳转到来源
const citations = [
  { id: 1, title: '文档A', url: 'https://...', snippet: '原文片段' },
  { id: 2, title: '文档B', url: 'https://...', snippet: '原文片段' },
];

function renderWithCitation(markdown) {
  // 把 [1] 替换成可点击的引用标签
  return markdown.replace(/\[(\d+)\]/g, (_, id) => {
    const c = citations.find(x => x.id === Number(id));
    return c ? `<sup class="citation" data-id="${c.id}">${id}</sup>` : `[${id}]`;
  });
}
```

## Conversation

Conversation 管理多轮对话：维护消息历史、控制上下文长度、支持新建/切换会话。

```js
// 会话管理（简化）
const conversations = new Map();

function createConversation(id) {
  conversations.set(id, { id, messages: [], title: '新对话' });
}

function addMessage(convId, role, content) {
  const conv = conversations.get(convId);
  conv.messages.push({ role, content });
  // 上下文窗口有限，超长时裁剪
  if (conv.messages.length > 20) {
    conv.messages = conv.messages.slice(-20);
  }
}
```

```text
Conversation 的要点：
1. 上下文窗口 —— 历史消息不能无限累积，超长要裁剪/摘要
2. 会话持久化 —— 存服务端，刷新后恢复
3. 标题生成 —— 用首条消息或模型自动生成标题
4. 分支/删除 —— 支持重新生成、删除某轮对话
```

## Memory

Memory（记忆）让 AI 记住用户偏好和长期信息，跨会话保持一致性。

```js
// 简单记忆：把用户偏好存进 system prompt
const memory = { name: '小明', prefer: '简洁回答' };

function buildSystemPrompt(memory) {
  return [
    '你是一个助手。',
    memory.name && `用户叫${memory.name}。`,
    memory.prefer && `用户偏好${memory.prefer}。`,
  ].filter(Boolean).join('\n');
}
```

```text
Memory 的层次：
1. 短期记忆 —— 当前会话的消息历史
2. 长期记忆 —— 跨会话的用户偏好、事实
3. 记忆提取 —— 从对话中自动提炼值得记住的信息
4. 记忆检索 —— 每次对话前检索相关记忆注入上下文
```

## 应用场景实战

### 场景一：完整流式对话前端

```js
// 一个可用的流式对话组件核心逻辑
async function sendMessage(text) {
  appendMessage('user', text);
  const assistantEl = appendMessage('assistant', '');
  await streamChat([{ role: 'user', content: text }], (delta) => {
    assistantEl.textContent += delta;
  });
  highlightCode(assistantEl);   // 完成后统一高亮代码
}
```

### 场景二：带工具调用的 Agent 循环

```js
// Agent 循环：模型 → 工具 → 模型 → 最终回答
async function agentLoop(userInput) {
  const messages = [{ role: 'user', content: userInput }];
  for (let i = 0; i < 5; i++) {  // 最多循环 5 轮
    const msg = await chat(messages);
    if (msg.tool_calls?.length) {
      messages.push(msg);
      for (const call of msg.tool_calls) {
        const result = await executeTool(call.function.name, JSON.parse(call.function.arguments));
        messages.push({ role: 'tool', tool_call_id: call.id, content: JSON.stringify(result) });
      }
      continue;
    }
    return msg.content;  // 最终回答
  }
  return '达到最大循环次数';
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. 流式输出必做，别让用户干等完整回复
2. 模型输出一律 DOMPurify 净化，防 XSS
3. 上下文超长时裁剪或摘要，控制 token 成本
4. 工具调用设最大循环次数，防止死循环
5. 引用标注可点击，附原文片段
6. 记忆与检索分开：短期用历史，长期用记忆库

### 踩坑记录

```text
坑 1：直接 innerHTML 渲染模型输出
结论：被恶意 prompt 注入，执行了 XSS 脚本。
原因：模型输出不可信，Markdown 里可能含 <script>。
解法：DOMPurify 净化后再渲染，禁用危险标签。

坑 2：流式渲染每次都全量 re-render
结论：长回复卡顿，每来一个字都重新解析整个 Markdown。
原因：没有做增量或节流，频繁触发重渲染。
解法：用 requestAnimationFrame 节流，或只在段落结束时重新渲染。

坑 3：上下文无限累积
结论：token 成本飙升，回复质量下降。
原因：历史消息不裁剪，越来越长。
解法：设最大消息数或总 token 上限，超出裁剪/摘要。

坑 4：工具调用无限循环
结论：模型反复调用同一个工具，请求数爆炸。
原因：没有最大循环次数，工具结果无法让模型收敛。
解法：设循环上限（如 5 轮），超限强制返回中间结果。

坑 5：代码高亮在流式过程中每字触发
结论：代码生成时页面明显卡顿。
原因：边生成边做高亮，开销大。
解法：流式时先纯文本追加，回复完成后再统一高亮。
```

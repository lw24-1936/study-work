## 概述

低代码平台让用户通过拖拽和可视化配置搭建页面/表单/应用，核心思想是「配置即代码」：用一份 JSON Schema 描述页面结构，组件注册表提供可用的积木，渲染器把 Schema 渲染成真实界面，甚至进一步生成源码。

```text
低代码平台的核心链路：
1. Schema —— JSON 描述页面结构与配置
2. Component Registry —— 可用的组件积木库
3. Drag & Drop —— 可视化搭建交互
4. Renderer —— 把 Schema 渲染成界面
5. DSL —— 面向领域的描述语言
6. Code Generation —— 产出可维护源码
```

```text
Schema → 渲染器 → 界面
Schema → 代码生成 → 源码（可二次开发）
```

## Schema

Schema 是低代码平台的「数据底座」，用 JSON 描述页面的组件树、属性、事件、数据绑定。它可序列化存储、可传输、可渲染，是整个平台的单一事实来源。

```json
{
  "type": "page",
  "components": [
    {
      "id": "input_1",
      "type": "input",
      "props": {
        "label": "姓名",
        "placeholder": "请输入姓名",
        "required": true
      }
    },
    {
      "id": "btn_1",
      "type": "button",
      "props": { "text": "提交", "type": "primary" },
      "events": { "onClick": "submitForm" }
    }
  ]
}
```

```text
Schema 设计要点：
1. 组件树用 type + id + props + children 描述
2. 事件用字符串引用动作，运行时解析
3. 支持数据绑定表达式（如 {{ form.name }}）
4. 版本化 Schema，便于回滚与迁移
```

## Component Registry

组件注册表是「积木库」，把每个可拖拽组件（输入框、按钮、表格、图表等）注册成统一接口，包含元信息（名称、图标、默认 props）与渲染函数。平台通过它实现组件的可插拔。

```js
// 组件注册表
const registry = new Map();

function registerComponent(def) {
  registry.set(def.type, def);
}

registerComponent({
  type: 'input',
  name: '输入框',
  icon: 'text-field',
  defaultProps: { label: '', placeholder: '', required: false },
  render: (props) => <Input {...props} />,
});

registerComponent({
  type: 'table',
  name: '表格',
  icon: 'table',
  defaultProps: { columns: [], dataSource: [] },
  render: (props) => <Table {...props} />,
});
```

```text
Component Registry 要点：
1. 统一组件接口：type/name/icon/defaultProps/render
2. 第三方组件通过适配器接入注册表
3. 注册表驱动「组件面板」展示可拖拽项
4. 支持业务自定义组件扩展
```

## Drag & Drop

拖拽是低代码的核心交互：从组件面板拖出组件放到画布，或调整画布内组件的位置与层级。HTML5 Drag & Drop API 或专门的拖拽库（如 dnd-kit、Sortable）承载这一交互。

```js
// HTML5 拖拽：从面板拖到画布
function onPanelDragStart(e, type) {
  e.dataTransfer.setData('componentType', type);
}

function onCanvasDrop(e) {
  const type = e.dataTransfer.getData('componentType');
  const { x, y } = getCanvasCoords(e);
  addComponent({ type, position: { x, y } });   // 添加组件到 Schema
}
```

```text
Drag & Drop 要点：
1. 拖拽携带组件 type，drop 时实例化组件
2. 拖拽过程可视化反馈（占位、高亮、吸附线）
3. 支持调整顺序、嵌套层级（拖入容器）
4. 触屏场景需要额外的 touch 兼容
```

## Renderer

渲染器是「Schema → 界面」的执行引擎，递归遍历 Schema 组件树，从注册表取出组件渲染。它是运行时的核心，也决定平台能渲染出什么样的界面。

```js
// 递归渲染器
function Renderer({ schema }) {
  return renderNode(schema);
}

function renderNode(node) {
  const def = registry.get(node.type);
  if (!def) return null;

  const Comp = def.render;
  const children = node.children?.map(renderNode);

  return (
    <Comp key={node.id} {...node.props} events={node.events}>
      {children}
    </Comp>
  );
}
```

```text
Renderer 要点：
1. 递归遍历组件树，未知类型优雅降级
2. 处理数据绑定与事件绑定
3. 渲染性能：大 Schema 做虚拟化或懒渲染
4. 渲染器与编辑器解耦，预览/运行共用
```

## Form Builder

表单搭建器（Form Builder）是低代码最常见的落地场景，让用户拖拽字段生成表单，配置校验规则、布局、联动。产出是表单 Schema，渲染成可提交的表单。

```js
// 表单 Schema 渲染成受控表单
function FormRenderer({ schema, value, onChange }) {
  return schema.fields.map(field => (
    <FormField
      key={field.id}
      field={field}
      value={value[field.name]}
      onChange={(v) => onChange({ ...value, [field.name]: v })}
    />
  ));
}

const formSchema = {
  fields: [
    { id: 'f1', name: 'name', type: 'input', label: '姓名', rules: [{ required: true }] },
    { id: 'f2', name: 'age', type: 'number', label: '年龄' },
  ],
};
```

```text
Form Builder 要点：
1. 字段类型：输入、选择、日期、级联、文件等
2. 校验规则配置化，渲染时转成表单校验
3. 字段联动（显隐、禁用、选项联动）
4. 布局配置：单列/多列/分组
```

## Page Builder

页面搭建器（Page Builder）面向整页搭建，管理页面级布局、区块、组件编排。它比表单搭建器更通用，支持多页面、页面模板、主题配置。

```js
// 页面 Schema：布局 + 区块 + 组件
const pageSchema = {
  type: 'page',
  layout: { type: 'grid', columns: 12 },
  sections: [
    { id: 'header', type: 'container', children: [/* 顶部组件 */] },
    { id: 'body', type: 'container', children: [/* 主体组件 */] },
    { id: 'footer', type: 'container', children: [/* 底部组件 */] },
  ],
};
```

```text
Page Builder 要点：
1. 页面级结构：布局 + 区块 + 组件树
2. 支持页面模板快速起手
3. 响应式配置：不同断点不同布局
4. 多页面管理与页面间跳转
```

## Plugin

插件机制是低代码平台的扩展点，让第三方开发者注册新组件、新动作、新面板、新渲染逻辑。插件通过平台暴露的 API 注册到注册表或生命周期钩子。

```js
// 插件：注册一个自定义图表组件
export function chartPlugin(platform) {
  platform.registerComponent({
    type: 'line-chart',
    name: '折线图',
    render: (props) => <LineChart data={props.data} />,
  });

  platform.registerAction('fetchData', async (ctx) => {
    const data = await fetch(ctx.url).then(r => r.json());
    return data;
  });
}
```

```text
插件要点：
1. 稳定的插件 API，组件/动作/面板统一注册
2. 插件间隔离，避免互相污染
3. 版本管理与依赖声明
4. 沙箱执行第三方代码，防注入
```

## DSL

DSL（领域特定语言）是面向低代码场景定制的描述语言，通常就是结构化 Schema 的一种形式。相比通用 JSON，DSL 更贴近业务语义，可读性更强，也可能支持表达式与逻辑。

```text
DSL 示例（类 Schema 的描述）：
Page "订单管理" {
  Table "订单列表" {
    columns: [订单号, 金额, 状态]
    dataSource: @api/orders
  }
  Button "新建" { action: openDialog }
}
```

```js
// 实际落地常以 JSON DSL 表达，配合表达式引擎
const dsl = {
  type: 'form',
  fields: [
    { name: 'total', expr: '{{ price * quantity }}' },   // 表达式
    { name: 'status', when: '{{ role === "admin" }}' },   // 条件渲染
  ],
};
```

```text
DSL 要点：
1. 结构化 + 可序列化，便于存储与传输
2. 支持表达式与条件逻辑
3. 可读性优先，降低配置门槛
4. DSL 需配套解析/编译到可执行结构
```

## Code Generation

代码生成把 Schema/DSL 编译成真实的前端源码，让低代码产出的应用可以「出码」后脱离平台独立运行、二次开发。生成代码要可读、可维护、符合工程规范。

```js
// Schema → 源码字符串（简化）
function generateCode(schema) {
  const imports = ['import React from "react";'];
  const lines = ['export default function Page() {', '  return ('];
  schema.components.forEach(c => {
    lines.push(`    <${c.type} ${propsToString(c.props)} />`);
  });
  lines.push('  );', '}');
  return [...imports, '', ...lines].join('\n');
}
```

```text
代码生成要点：
1. 生成代码可读、可维护，而非一次性产物
2. 模板化生成，支持自定义模板
3. 出码与平台解耦，可独立构建运行
4. 处理导入、命名、格式，产物过 lint
```

## 应用场景实战

### 场景一：可视化搭建一个查询表单

```js
// 用户拖出「输入框 + 下拉 + 按钮」，生成如下 Schema
const queryForm = {
  type: 'form',
  fields: [
    { id: 'kw', type: 'input', name: 'keyword', label: '关键词' },
    { id: 'st', type: 'select', name: 'status', label: '状态',
      options: [{ label: '全部', value: '' }, { label: '启用', value: 'on' }] },
    { id: 'btn', type: 'button', text: '查询', events: { onClick: 'search' } },
  ],
};
// 渲染器据此渲染出真实表单
render(<Renderer schema={queryForm} />);
```

### 场景二：Schema 出码为 Vue 组件

```js
// 表单 Schema 生成 Vue 源码
function genVueForm(schema) {
  const template = schema.fields.map(f =>
    `<el-form-item label="${f.label}">` +
    `<el-input v-model="form.${f.name}" />` +
    `</el-form-item>`
  ).join('\n      ');

  return `<template>\n  <el-form>${template}\n  </el-form>\n</template>`;
}

console.log(genVueForm(queryForm));
```

## 最佳实践与踩坑记录

### 最佳实践

1. Schema 作为单一事实来源，界面、预览、运行、出码都从它派生
2. 组件注册表统一接口，第三方组件走适配器接入
3. 渲染器与编辑器解耦，预览和运行共用一个渲染引擎
4. 拖拽提供可视化反馈与层级约束，避免脏状态
5. 插件用沙箱隔离，第三方代码不可信
6. 出码产物走模板化 + lint，保证可维护性

### 踩坑记录

```text
坑 1：Schema 与渲染逻辑耦合
结论：改渲染就要动 Schema，换端复用困难。
原因：Schema 里混入了平台实现细节。
解法：Schema 只描述结构，渲染/出码从 Schema 派生。

坑 2：渲染器遇未知组件类型直接崩溃
结论：历史 Schema 里的旧组件让页面白屏。
原因：组件被移除后渲染器没有降级处理。
解法：未知类型优雅降级，占位提示而非崩溃。

坑 3：拖拽层级不约束产生非法嵌套
结论：按钮里拖进表格，渲染时报错。
原因：没有定义组件的可嵌套规则。
解法：注册表声明 children 约束，拖拽时校验。

坑 4：出码产物不可维护
结论：生成的代码全是魔法命名，无法二次开发。
原因：出码没做可读性与规范处理。
解法：模板化生成 + 语义命名 + lint 格式化。

坑 5：表达式注入漏洞
结论：恶意用户在表达式里执行任意代码。
原因：表达式直接 eval 执行。
解法：用受限表达式引擎或沙箱解析，禁止直接 eval。
```

## 概述

企业后台管理系统（Admin）是前端最常见的项目形态，核心是「数据驱动的 CRUD + 权限控制 + 数据可视化」。它通常包含登录认证、菜单权限、表单录入、表格展示、图表看板、接口对接与自动化测试部署等完整链路。

```text
企业后台的模块构成：
1. 框架层 —— React/Vue + TypeScript + 路由 + 状态管理
2. 权限层 —— 登录认证 + 菜单权限 + RBAC 角色控制
3. 业务层 —— 表单 + 表格 + 看板 + 图表
4. 工程层 —— API 封装 + 单元测试 + E2E + CI/CD
```

```text
典型目录结构：
src/
  api/           # 接口封装
  components/    # 通用组件
  layouts/       # 布局（侧边栏 + 顶栏 + 内容区）
  pages/         # 页面
  router/        # 路由与守卫
  store/         # 状态管理
  utils/         # 工具函数
  types/         # 类型定义
```

## React/Vue

框架选型取决于团队技术栈。React 生态灵活、函数式思想强；Vue 上手快、模板直观。两者都能胜任后台系统，关键是配套生态（组件库、路由、状态库）选齐。

```jsx
// React 版页面骨架
function UserList() {
  const [users, setUsers] = useState([]);
  useEffect(() => { fetchUsers().then(setUsers); }, []);
  return <Table data={users} columns={columns} />;
}
```

```vue
<!-- Vue 版页面骨架 -->
<template>
  <el-table :data="users">
    <el-table-column prop="name" label="姓名" />
  </el-table>
</template>

<script setup>
import { ref, onMounted } from 'vue';
const users = ref([]);
onMounted(async () => { users.value = await fetchUsers(); });
</script>
```

```text
选型考量：
1. 团队熟悉度 —— 决定开发效率
2. 组件库 —— React 用 Ant Design，Vue 用 Element Plus
3. 生态 —— 路由/状态/构建工具配套成熟度
```

## TypeScript

后台系统的业务模型复杂，TypeScript 的类型系统能在编译期拦截大量错误，是大型后台的标配。核心价值在接口类型、组件 Props、枚举与联合类型。

```ts
// 用类型约束业务实体与接口
interface User {
  id: number;
  name: string;
  role: 'admin' | 'editor' | 'viewer';
  email: string;
  createdAt: string;
}

interface PageResult<T> {
  list: T[];
  total: number;
}

async function fetchUsers(page: number): Promise<PageResult<User>> {
  const res = await fetch(`/api/users?page=${page}`);
  return res.json();          // 返回类型被强约束
}
```

```text
TS 在后台的价值：
1. 实体类型 —— 后端字段有明确契约
2. 严格模式 —— strict: true 避免隐式 any
3. 枚举 —— 状态码、角色等用 union 或 enum
4. 泛型 —— 分页、表格等通用结构复用类型
```

## Router

路由承载「页面 → URL」的映射，后台系统的路由通常带权限守卫，动态生成菜单与可访问页面。核心是嵌套路由（布局 + 子页面）与导航守卫。

```js
// React Router 嵌套路由 + 守卫
const router = createBrowserRouter([
  {
    path: '/',
    element: <Layout />,
    children: [
      { path: 'users', element: <RequireAuth role="admin"><UserList /></RequireAuth> },
      { path: 'dashboard', element: <Dashboard /> },
    ],
  },
]);
```

```js
// Vue Router 全局守卫做登录校验
router.beforeEach((to, from, next) => {
  const token = getToken();
  if (to.meta.requiresAuth && !token) {
    next('/login');
  } else {
    next();
  }
});
```

```text
后台路由要点：
1. 嵌套路由 —— 布局组件包裹内容区
2. 动态路由 —— 按权限注册可访问的路由
3. 守卫 —— 登录校验、权限校验统一拦截
4. 懒加载 —— 页面按需加载，减小首屏体积
```

## State Management

后台的全局状态包括用户信息、权限、侧边栏折叠、主题等。轻量场景用 Context/Pinia，复杂场景用 Redux/Zustand。原则是「全局共享的进 store，局部状态留在组件」。

```js
// Zustand 管理用户与权限状态
import { create } from 'zustand';

const useAuthStore = create((set) => ({
  user: null,
  permissions: [],
  login: (user) => set({ user, permissions: user.permissions }),
  logout: () => set({ user: null, permissions: [] }),
}));
```

```text
状态分层建议：
1. 服务端数据（列表、详情）—— 用 TanStack Query 等缓存，别塞进全局 store
2. 全局 UI 状态（主题、侧边栏）—— 放 store
3. 用户/权限 —— 放 store，登录后初始化
4. 组件内部状态 —— 留在组件，别全局化
```

## Permission

权限控制决定「谁能看到什么、能做什么」，分三个层面：路由权限（能否进页面）、菜单权限（能否看到入口）、按钮权限（能否操作）。三者都要有，且后端必须兜底校验。

```js
// 按钮级权限指令
function RequirePermission({ permission, children }) {
  const { permissions } = useAuth();
  if (!permissions.includes(permission)) return null;
  return children;
}

// 用法
<RequirePermission permission="user:delete">
  <Button danger>删除</Button>
</RequirePermission>
```

```text
三层权限：
1. 路由权限 —— 无权限的路由不注册，访问则重定向 403
2. 菜单权限 —— 侧边栏按权限过滤菜单项
3. 按钮权限 —— 无权限的操作按钮不渲染或禁用
```

## RBAC

RBAC（Role-Based Access Control）是权限的模型基础：用户绑定角色，角色绑定权限，权限控制资源。通过「用户-角色-权限」三层解耦，避免给每个用户单独配权限。

```js
// RBAC 数据模型与判断
const role = {
  name: 'editor',
  permissions: ['post:read', 'post:write'],   // 角色 → 权限
};
const user = { name: '张三', roles: ['editor'] };  // 用户 → 角色

function hasPermission(user, required) {
  const perms = user.roles.flatMap(r => roleMap[r].permissions);
  return perms.includes(required);
}

hasPermission(user, 'post:write');   // true
hasPermission(user, 'post:delete');  // false
```

```text
RBAC 的要点：
1. 权限标识用点分命名，如 module:action（user:delete）
2. 用户 → 角色 → 权限，三层解耦便于批量调整
3. 常见角色：admin / editor / viewer
4. 权限树由后端下发，前端据此渲染菜单与按钮
```

## Form

表单是后台的高频场景，核心是「受控组件 + 校验 + 提交」。成熟的表单库（React Hook Form / Formik，Vue 的 VeeValidate）能把状态、校验、错误提示统一管理，避免手写大量 useState。

```jsx
// React Hook Form：注册字段 + 校验规则
import { useForm } from 'react-hook-form';

function UserForm() {
  const { register, handleSubmit, formState: { errors } } = useForm();
  const onSubmit = (data) => createUser(data);

  return (
    <form onSubmit={handleSubmit(onSubmit)}>
      <input {...register('name', { required: '姓名必填', minLength: 2 })} />
      {errors.name && <span>{errors.name.message}</span>}
      <input {...register('email', { pattern: /^\S+@\S+$/ })} />
      <button type="submit">提交</button>
    </form>
  );
}
```

```text
表单工程要点：
1. 校验规则声明式，避免命令式 if 判断堆叠
2. 提交前统一校验，错误信息就近展示
3. 处理异步提交状态（loading/成功/失败）
4. 动态表单（增删行）用受控数组管理
```

## Table

表格是后台最核心的数据展示组件，常见需求：分页、排序、筛选、行选择、列自定义、操作列。成熟的表格组件（Ant Design Table / Element Plus Table）已内置大部分能力。

```jsx
// Ant Design Table：列定义 + 分页 + 行操作
const columns = [
  { title: '姓名', dataIndex: 'name', key: 'name' },
  { title: '角色', dataIndex: 'role', key: 'role' },
  {
    title: '操作',
    key: 'action',
    render: (_, record) => (
      <Space>
        <Button onClick={() => edit(record)}>编辑</Button>
        <Button danger onClick={() => remove(record.id)}>删除</Button>
      </Space>
    ),
  },
];

<Table
  columns={columns}
  dataSource={users}
  rowKey="id"
  pagination={{ pageSize: 20, total }}
  onChange={handleTableChange}   // 翻页/排序/筛选统一入口
/>
```

```text
Table 工程要点：
1. 列定义抽成配置，复杂列用 render 定制
2. 分页参数统一在 onChange 里处理，重新拉取数据
3. 大表格用虚拟滚动，避免一次渲染上万行
4. 列宽、冻结列、汇总行等按需配置
```

## Dashboard

Dashboard 是数据概览页，用卡片 + 图表组合呈现关键指标（KPI）。核心是「指标卡 + 趋势图 + 明细表」的布局，数据来自聚合接口。

```text
Dashboard 布局结构：
[ KPI 卡片行 ]  总用户数 | 今日订单 | 营收 | 转化率
[ 图表区 ]      趋势折线图（左） | 分类饼图（右）
[ 明细区 ]      最近动态 / 待办列表
```

```jsx
// 指标卡片组件
function StatCard({ title, value, delta }) {
  const up = delta >= 0;
  return (
    <div className="stat-card">
      <div className="stat-title">{title}</div>
      <div className="stat-value">{value}</div>
      <div className={up ? 'up' : 'down'}>
        {up ? '↑' : '↓'} {Math.abs(delta)}%
      </div>
    </div>
  );
}
```

## ECharts

ECharts 是后台可视化的事实标准图表库，声明式配置、内置丰富图表类型。用法是「初始化实例 + setOption 更新配置 + 响应式 resize」。

```jsx
// React 中封装 ECharts 折线图
import * as echarts from 'echarts';

function TrendChart({ data }) {
  const ref = useRef(null);

  useEffect(() => {
    const chart = echarts.init(ref.current);
    chart.setOption({
      xAxis: { type: 'category', data: data.labels },
      yAxis: { type: 'value' },
      series: [{ type: 'line', data: data.values, smooth: true }],
    });
    const onResize = () => chart.resize();
    window.addEventListener('resize', onResize);
    return () => { window.removeEventListener('resize', onResize); chart.dispose(); };
  }, [data]);

  return <div ref={ref} style={{ width: '100%', height: 300 }} />;
}
```

```text
ECharts 要点：
1. 组件卸载时 dispose，避免内存泄漏
2. 容器尺寸变化时 resize
3. 大数据量用 dataZoom 或采样降点
4. 主题统一，配色与整体 UI 一致
```

## API

接口层统一封装请求，集中处理 baseURL、鉴权头、错误提示、超时与重试，避免每个页面重复写 fetch 逻辑。

```js
// 统一请求封装 + 拦截器
async function request(url, options = {}) {
  const res = await fetch(`${BASE_URL}${url}`, {
    ...options,
    headers: {
      'Content-Type': 'application/json',
      Authorization: `Bearer ${getToken()}`,
      ...options.headers,
    },
  });
  if (res.status === 401) { logout(); throw new Error('未登录'); }
  if (!res.ok) throw new Error(`请求失败: ${res.status}`);
  return res.json();
}

export const userApi = {
  list: (params) => request('/users', { method: 'GET' }),
  create: (data) => request('/users', { method: 'POST', body: JSON.stringify(data) }),
};
```

```text
API 层规范：
1. 按业务模块拆分，如 userApi、orderApi
2. 统一错误处理与鉴权刷新
3. 类型化返回，接口字段有契约
4. 支持超时、重试、取消（AbortController）
```

## Unit Test

单元测试覆盖工具函数、组件交互与状态逻辑。Jest/Vitest 是主流测试框架，Testing Library 倡导「按用户视角测试行为」而非实现细节。

```js
// Vitest + Testing Library 测试表单提交
import { render, screen, fireEvent } from '@testing-library/react';

test('提交时校验姓名必填', async () => {
  render(<UserForm onSubmit={vi.fn()} />);
  fireEvent.click(screen.getByText('提交'));
  expect(await screen.findByText('姓名必填')).toBeInTheDocument();
});
```

```text
单测策略：
1. 工具函数、权限判断逻辑全量覆盖
2. 核心组件测关键交互与边界
3. Mock 接口，隔离外部依赖
4. 追求覆盖率指标但不唯覆盖率论
```

## E2E

E2E 测试用 Playwright/Cypress 模拟真实用户操作浏览器，验证完整业务流（登录 → 列表 → 新增 → 保存）。它跑得慢但能捕获集成问题。

```js
// Playwright E2E：登录并创建用户
import { test, expect } from '@playwright/test';

test('管理员登录并创建用户', async ({ page }) => {
  await page.goto('/login');
  await page.fill('[name=username]', 'admin');
  await page.fill('[name=password]', 'secret');
  await page.click('button[type=submit]');
  await expect(page).toHaveURL(/dashboard/);

  await page.click('text=用户管理');
  await page.click('text=新增');
  await page.fill('[name=name]', '李四');
  await page.click('text=保存');
  await expect(page.getByText('李四')).toBeVisible();
});
```

```text
E2E 策略：
1. 覆盖核心业务流程，而非穷举所有页面
2. 用稳定的选择器（data-testid 或文本）
3. 测试数据隔离，每个用例独立
4. 接入 CI 定时跑，避免环境漂移
```

## CI/CD

CI/CD 让代码提交后自动构建、测试、部署，是后台系统快速迭代的保障。典型流水线：代码检查 → 单测 → 构建 → 部署到环境。

```yaml
# GitHub Actions 示例
name: CI
on:
  push:
    branches: [main]
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
      - run: npm ci
      - run: npm run lint
      - run: npm run test
      - run: npm run build
      - run: npm run test:e2e
```

```text
CI/CD 流水线：
1. lint + typecheck —— 静态检查，最快反馈
2. unit test —— 单测兜底逻辑正确性
3. build —— 生产构建，校验产物可用
4. deploy —— 构建产物部署到测试/生产环境
```

## 应用场景实战

### 场景一：带权限的动态菜单

```jsx
// 根据后端下发的权限过滤菜单并生成路由
const menuItems = [
  { path: '/dashboard', label: '看板', permission: 'dashboard:view' },
  { path: '/users', label: '用户管理', permission: 'user:view' },
  { path: '/settings', label: '系统设置', permission: 'system:view' },
];

function filterMenus(permissions) {
  return menuItems.filter(m => permissions.includes(m.permission));
}

function Sidebar({ permissions }) {
  const menus = filterMenus(permissions);
  return (
    <ul>
      {menus.map(m => (
        <li key={m.path}><Link to={m.path}>{m.label}</Link></li>
      ))}
    </ul>
  );
}
```

### 场景二：分页表格 + 筛选联动

```jsx
// 筛选条件变化时重置页码并重新请求
function UserPage() {
  const [params, setParams] = useState({ page: 1, pageSize: 20, keyword: '' });
  const { data, isLoading } = useQuery(['users', params], () => userApi.list(params));

  return (
    <>
      <Input.Search
        onSearch={(keyword) => setParams(p => ({ ...p, page: 1, keyword }))}
      />
      <Table
        loading={isLoading}
        columns={columns}
        dataSource={data?.list}
        pagination={{
          current: params.page,
          pageSize: params.pageSize,
          total: data?.total,
          onChange: (page, pageSize) => setParams(p => ({ ...p, page, pageSize })),
        }}
      />
    </>
  );
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. 权限三层（路由/菜单/按钮）齐备，且后端强制校验兜底
2. 服务端数据用 TanStack Query 缓存，别塞进全局 store
3. 表单用声明式校验库，别堆 if 判断
4. 表格列定义抽成配置，分页参数统一管理
5. 图表组件卸载时 dispose、resize 时 resize
6. CI 流水线静态检查 → 单测 → 构建 → 部署逐级把关

### 踩坑记录

```text
坑 1：只在后端做权限、前端不隐藏按钮
结论：用户能看到没权限的按钮，点下去才报 403，体验差。
原因：前后端权限不同步。
解法：前端按权限渲染，后端再校验，双重保险。

坑 2：列表数据塞进全局 store
结论：切页、筛选时状态混乱，内存里堆满过期数据。
原因：把服务端缓存与全局 UI 状态混为一谈。
解法：服务端数据交给缓存库管理，store 只放 UI 状态。

坑 3：ECharts 实例未销毁
结论：反复切换页面内存泄漏，图表越用越卡。
原因：组件卸载时没有 dispose。
解法：useEffect 清理函数里调用 chart.dispose()。

坑 4：E2E 用脆弱的 CSS 选择器
结论：改个样式类名测试就挂，维护成本高。
原因：选择器与实现细节强耦合。
解法：用 data-testid 或稳定的可访问性角色定位。

坑 5：表单提交后不处理 loading 态
结论：用户连点提交，产生重复数据。
原因：没有禁用提交按钮或防抖。
解法：提交期间置 loading 并禁用按钮，成功后跳转或重置。
```

## 概述

企业级组件库是一套统一设计规范、可复用、可维护的 UI 组件集合，目标是「一次开发、全团队复用、体验一致」。它不止是代码，还包含设计令牌、文档（Storybook）、可访问性、测试与发布等完整工程体系。

```text
企业级组件库的构成：
1. 设计层 —— Design Token 统一视觉变量
2. 实现层 —— React/Vue + TypeScript 组件
3. 文档层 —— Storybook 交互式文档
4. 质量层 —— 可访问性 + 单测 + 视觉回归
5. 发布层 —— 版本管理 + npm Publish
```

```text
组件库生命周期：
设计 Token → 组件实现 → Storybook 文档 → 测试 → 发布 → 业务接入
```

## Design Token

Design Token 是设计系统的最小原子——把颜色、字号、间距、圆角等设计决策抽成命名变量。它让设计与代码同源，改一处 Token 全库联动，是组件库视觉一致性的根基。

```js
// Design Token 定义
export const tokens = {
  color: {
    primary: '#4f46e5',
    success: '#16a34a',
    danger: '#dc2626',
    text: '#1f2937',
    bg: '#ffffff',
  },
  spacing: { xs: 4, sm: 8, md: 16, lg: 24, xl: 32 },
  radius: { sm: 4, md: 8, lg: 12 },
  fontSize: { sm: 12, md: 14, lg: 16, xl: 20 },
};
```

```text
Design Token 要点：
1. 命名语义化（primary/danger）而非视觉化（blue/red）
2. 分层：基础 Token → 语义 Token → 组件 Token
3. 输出多端：CSS 变量、JS 对象、多主题
4. 换主题只需换 Token，组件代码不变
```

## React/Vue

组件库需要确定目标框架，React 与 Vue 是最主流的两个选择。组件实现遵循框架规范（React 的函数组件 + Hooks，Vue 的 SFC + 组合式 API），保证使用者上手自然。

```jsx
// React 组件实现
import { tokens } from '../tokens';

export function Button({ variant = 'primary', size = 'md', children, ...rest }) {
  return (
    <button
      className={cx('btn', `btn-${variant}`, `btn-${size}`)}
      style={{ borderRadius: tokens.radius.md, padding: tokens.spacing.sm }}
      {...rest}
    >
      {children}
    </button>
  );
}
```

```vue
<!-- Vue 组件实现 -->
<template>
  <button :class="['btn', `btn-${variant}`]" v-bind="$attrs">
    <slot />
  </button>
</template>

<script setup>
defineProps({ variant: { type: String, default: 'primary' } });
</script>
```

```text
组件实现要点：
1. 统一 Props 命名与默认值
2. 支持受控/非受控两种用法
3. 事件透传（React 的 ...rest，Vue 的 $attrs）
4. 样式隔离，不污染使用方
```

## TypeScript

TypeScript 是组件库的类型基石：Props、事件、泛型都被强类型约束，使用方在编辑器里就能获得完整类型提示，也能在编译期拦截误用。

```ts
// 组件类型定义
export interface ButtonProps
  extends React.ButtonHTMLAttributes<HTMLButtonElement> {
  variant?: 'primary' | 'secondary' | 'danger' | 'ghost';
  size?: 'sm' | 'md' | 'lg';
  loading?: boolean;
}

export const Button: React.FC<ButtonProps> = ({ variant, size, loading, ...rest }) => {
  // ...
};

// 泛型组件（如 Select 保留选项类型）
export function Select<T extends string>(props: {
  value: T;
  options: { label: string; value: T }[];
  onChange: (value: T) => void;
}) { /* ... */ }
```

```text
TypeScript 要点：
1. Props 继承原生 HTML 属性，支持透传
2. 用联合类型约束 variant/size 等枚举
3. 泛型保留类型信息（Select、Table 等）
4. 打包时输出 .d.ts 类型声明文件
```

## Storybook

Storybook 是组件库的交互式开发与文档环境，每个组件写多个 story（使用场景），既能在开发时实时预览，也生成在线文档供团队查阅。

```js
// Button 的 Storybook 故事
import { Button } from './Button';

export default {
  title: 'Components/Button',
  component: Button,
  argTypes: { variant: { control: 'select', options: ['primary', 'danger'] } },
};

export const Primary = {
  args: { variant: 'primary', children: '确认' },
};

export const Danger = {
  args: { variant: 'danger', children: '删除' },
};
```

```text
Storybook 要点：
1. 每个组件覆盖关键状态（默认/禁用/加载/各 variant）
2. 用 controls 支持实时调参
3. 编写文档型 story（MDX）说明用法与设计意图
4. Storybook 作为组件库的「官网」发布
```

## Accessibility

可访问性（a11y）确保组件对所有用户可用，包括键盘操作、屏幕阅读器、颜色对比度。组件库要内置无障碍支持，如语义化标签、ARIA 属性、焦点管理。

```jsx
// 可访问的开关组件
function Switch({ checked, onChange, label }) {
  return (
    <label>
      <input
        type="checkbox"
        role="switch"
        aria-checked={checked}
        checked={checked}
        onChange={e => onChange(e.target.checked)}
      />
      <span>{label}</span>
    </label>
  );
}
```

```text
Accessibility 要点：
1. 语义化标签，交互元素可键盘聚焦操作
2. ARIA 属性补充状态（aria-checked/aria-expanded）
3. 颜色对比度满足 WCAG 标准
4. 用 axe 等工具做自动化无障碍检查
```

## Visual Regression

视觉回归测试通过截图对比，捕获「代码改了但视觉悄悄变了」的问题。组件库用 Storybook 快照 + 视觉回归工具（Chromatic、Playwright screenshot）在 CI 里自动比对像素差异。

```js
// Playwright 视觉回归
import { test, expect } from '@playwright/test';

test('Button 视觉快照', async ({ page }) => {
  await page.goto('/iframe.html?id=components-button--primary');
  const el = page.locator('.btn');
  await expect(el).toHaveScreenshot('button-primary.png');  // 与基准图比对
});
```

```text
视觉回归要点：
1. 每个 story 生成基准快照，改动后自动比对
2. 差异可视化审查，是「有意变更」还是「回归」
3. 跨浏览器、跨分辨率快照
4. 接入 CI，合并前拦截视觉回归
```

## Unit Test

单元测试覆盖组件的交互逻辑与边界行为，用 Testing Library 从用户视角断言（渲染结果、点击行为、回调触发），而非测实现细节。

```js
// Button 单测
import { render, screen, fireEvent } from '@testing-library/react';

test('点击触发 onClick', () => {
  const onClick = vi.fn();
  render(<Button onClick={onClick}>提交</Button>);
  fireEvent.click(screen.getByText('提交'));
  expect(onClick).toHaveBeenCalledTimes(1);
});

test('loading 时禁用点击', () => {
  const onClick = vi.fn();
  render(<Button loading onClick={onClick}>提交</Button>);
  fireEvent.click(screen.getByText('提交'));
  expect(onClick).not.toHaveBeenCalled();
});
```

```text
单测策略：
1. 覆盖核心交互与 Props 边界
2. 断言用户可见行为，不测实现细节
3. 事件回调、禁用态、受控逻辑重点测
4. 覆盖率 + 关键路径并重
```

## npm Publish

组件库通过 npm 发布给团队或社区使用，核心是「版本管理 + 打包产物 + 发布流程」。语义化版本（SemVer）管理变更，打包输出 ESM/CJS + 类型声明，发布走自动化流水线。

```json
{
  "name": "@company/ui",
  "version": "1.2.0",
  "main": "dist/index.cjs",
  "module": "dist/index.js",
  "types": "dist/index.d.ts",
  "exports": {
    ".": {
      "import": "./dist/index.js",
      "require": "./dist/index.cjs",
      "types": "./dist/index.d.ts"
    }
  },
  "sideEffects": false,
  "files": ["dist"]
}
```

```text
npm Publish 要点：
1. SemVer：breaking 升 major，feature 升 minor，fix 升 patch
2. 输出 ESM + CJS + .d.ts，配 exports 字段
3. sideEffects: false 支持 tree-shaking
4. 发布走 CI 自动化，含 changelog 与版本校验
```

## 应用场景实战

### 场景一：主题切换（Design Token 落地）

```js
// 通过 CSS 变量实现运行时换主题
function applyTheme(theme) {
  const root = document.documentElement;
  Object.entries(theme.color).forEach(([k, v]) => {
    root.style.setProperty(`--color-${k}`, v);
  });
}

// 组件样式引用变量，换主题无需改组件
// .btn-primary { background: var(--color-primary); }
applyTheme({ color: { primary: '#0ea5e9', danger: '#ef4444' } });
```

### 场景二：组件打包与 tree-shaking

```js
// 每个组件独立入口，支持按需引入
// src/index.ts 汇总导出
export { Button } from './Button';
export { Input } from './Input';
export { Table } from './Table';

// 使用方按需引入，打包器 tree-shake 掉未用组件
import { Button } from '@company/ui';
```

## 最佳实践与踩坑记录

### 最佳实践

1. Design Token 语义化命名，视觉与代码同源
2. 组件 Props 继承原生属性，支持完整透传
3. 每个组件覆盖关键状态的 Storybook 故事
4. 可访问性内置，键盘与屏幕阅读器可用
5. 视觉回归 + 单测双保险，拦截视觉与逻辑回归
6. SemVer 管理版本，CI 自动化发布

### 踩坑记录

```text
坑 1：组件样式污染使用方
结论：业务页面样式被组件库全局样式覆盖。
原因：组件用了全局 CSS 或未做样式隔离。
解法：CSS Modules / CSS-in-JS / 命名空间隔离。

坑 2：只输出 ESM 或只输出 CJS
结论：部分使用方（旧构建工具）无法使用。
原因：打包产物格式单一。
解法：同时输出 ESM + CJS + .d.ts，配 exports 字段。

坑 3：类型声明缺失
结论：使用方没有类型提示，误用难排查。
原因：打包时没输出 .d.ts。
解法：TS 编译输出类型声明，package.json 配 types。

坑 4：升级 minor 版本引入 breaking change
结论：使用方升级后大面积报错。
原因：把破坏性改动塞进了 minor/patch 版本。
解法：严格遵守 SemVer，breaking 一律升 major。

坑 5：视觉回归误报过多
结论：每次 CI 都因微小像素差异失败，团队麻木。
原因：快照对字体渲染、抗锯齿等不稳定因素敏感。
解法：合理设置阈值，忽略无关区域，定期更新基准。
```

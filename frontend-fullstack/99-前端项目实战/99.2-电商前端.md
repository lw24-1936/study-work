## 概述

电商前端是「流量 → 转化 → 交易」的完整漏斗，商品展示与搜索推荐承接流量，购物车与订单完成转化，支付与优惠券促成交易。它对 SEO、性能、转化率的要求远高于普通站点，通常采用 SSR/SSG 保证首屏与搜索收录。

```text
电商前端的核心链路：
1. 流量层 —— 商品列表、搜索、推荐，把用户带到商品
2. 转化层 —— 商品详情、购物车、优惠券，促成加购下单
3. 交易层 —— 订单、支付、用户中心，完成闭环
4. 工程层 —— SSR/SSG 保 SEO，性能优化保转化率
```

```text
电商页面结构：
首页 → 搜索/分类列表 → 商品详情 → 购物车 → 结算 → 支付 → 订单
```

## 商品

商品模块涵盖商品详情页（SPU/SKU）、图片、规格、库存与价格展示。SKU 是「可售卖的最小单位」，一个 SPU（商品）下有多个 SKU（如颜色/尺码组合），选择规格时联动切换 SKU。

```js
// 商品 SKU 数据结构与规格选择
const product = {
  spuId: 'P001',
  title: '纯棉卫衣',
  specs: [
    { name: '颜色', values: ['黑', '白', '灰'] },
    { name: '尺码', values: ['S', 'M', 'L'] },
  ],
  skus: [
    { id: 'S001', specs: ['黑', 'M'], price: 199, stock: 10 },
    { id: 'S002', specs: ['白', 'L'], price: 199, stock: 0 },
  ],
};

function matchSku(selected, skus) {
  return skus.find(sku =>
    sku.specs.every((v, i) => selected[i] === v)
  );
}
```

```text
商品模块要点：
1. SPU 管描述，SKU 管库存与价格
2. 规格选择联动 SKU，无库存的规格置灰
3. 图片懒加载 + 主图放大预览
4. 价格用分（整数）存储与计算，避免浮点误差
```

## 搜索

搜索是电商最重要的流量入口，核心是「关键词联想 + 结果召回 + 筛选排序」。前端做输入防抖、搜索历史、高亮命中词，后端做分词与倒排索引。

```js
// 搜索联想：输入防抖 + 取消过期请求
let controller = null;
function suggest(keyword) {
  controller?.abort();
  controller = new AbortController();
  fetch(`/api/suggest?q=${encodeURIComponent(keyword)}`, {
    signal: controller.signal,
  }).then(r => r.json()).then(renderSuggest);
}

input.addEventListener('input', debounce(e => {
  if (e.target.value) suggest(e.target.value);
}, 300));
```

```text
搜索要点：
1. 输入防抖，减少无效请求
2. AbortController 取消过期请求，防止结果乱序
3. 搜索结果高亮命中关键词
4. 记录搜索历史与热门搜索词
```

## 推荐

推荐引擎根据用户行为（浏览、加购、购买）和商品相似度做个性化推荐，前端只需渲染推荐位。常见形态有「猜你喜欢」「看了又看」「相关推荐」。

```js
// 推荐位组件：曝光上报 + 点击埋点
function RecommendList({ items, onExpose, onClick }) {
  return (
    <div className="recommend">
      {items.map(item => (
        <ProductCard
          key={item.id}
          item={item}
          onVisible={() => onExpose(item.id)}   // 曝光埋点
          onClick={() => onClick(item.id)}      // 点击埋点
        />
      ))}
    </div>
  );
}
```

```text
推荐要点：
1. 推荐数据由服务端/算法产出，前端负责渲染
2. 曝光与点击埋点回流，供算法迭代
3. 推荐位组件化，可插拔到首页/详情/购物车
4. 个性化与冷启动兜底（无历史时给热销）
```

## 购物车

购物车是转化前的暂存区，核心是「加购、改数量、勾选、合并计价、优惠计算」。状态需要持久化（登录用户存服务端，游客存本地），跨端同步。

```js
// 购物车状态：勾选计价
function cartReducer(state, action) {
  switch (action.type) {
    case 'TOGGLE':
      return state.map(item =>
        item.id === action.id ? { ...item, checked: !item.checked } : item
      );
    case 'CHANGE_QTY':
      return state.map(item =>
        item.id === action.id ? { ...item, qty: action.qty } : item
      );
    default:
      return state;
  }
}

// 只统计勾选商品
const total = cart.filter(i => i.checked)
  .reduce((sum, i) => sum + i.price * i.qty, 0);
```

```text
购物车要点：
1. 游客购物车存 localStorage，登录后合并到服务端
2. 价格、优惠、库存实时校验，下单前二次确认
3. 勾选态与数量变更即时重算总价
4. 库存不足或下架商品给出提示
```

## 订单

订单是交易的核心状态机，状态流转如「待付款 → 待发货 → 待收货 → 已完成」，还有取消、退款等分支。前端要清晰展示状态、支持操作（支付、取消、确认收货）。

```js
// 订单状态机与操作映射
const ORDER_STATUS = {
  pending:   { label: '待付款', actions: ['pay', 'cancel'] },
  paid:      { label: '待发货', actions: [] },
  shipped:   { label: '待收货', actions: ['confirm'] },
  completed: { label: '已完成', actions: ['review'] },
  cancelled: { label: '已取消', actions: [] },
};

function OrderActions({ order }) {
  const actions = ORDER_STATUS[order.status]?.actions || [];
  return actions.map(a => <Button key={a}>{ACTION_LABEL[a]}</Button>);
}
```

```text
订单要点：
1. 状态机驱动，每个状态对应允许的操作集合
2. 倒计时提醒（如 30 分钟内付款）
3. 订单金额与优惠明细清晰展示
4. 状态变更以服务端为准，前端轮询或推送刷新
```

## 支付

支付对接第三方（支付宝/微信/银联）或自建支付网关，前端只负责「发起支付 → 等待结果 → 展示状态」。核心是支付结果的回调与轮询，以及失败后的重试引导。

```js
// 发起支付 + 轮询结果
async function pay(orderId) {
  const { payUrl } = await createPayment(orderId);   // 获取支付链接/二维码
  openPaymentPage(payUrl);

  // 轮询支付结果
  const timer = setInterval(async () => {
    const status = await queryOrder(orderId);
    if (status === 'paid') {
      clearInterval(timer);
      navigate('/pay/success');
    }
  }, 2000);
}
```

```text
支付要点：
1. 支付金额、订单号以服务端为准，前端不能篡改
2. 支付结果靠回调 + 主动轮询双保险
3. 处理重复支付、支付超时、取消等异常分支
4. 敏感操作全程 HTTPS，金额用分存储
```

## 优惠券

优惠券是营销核心，有满减、折扣、无门槛等类型，存在有效期、适用范围、叠加规则等约束。前端负责展示可用券、计算优惠、下单时锁定券。

```js
// 优惠券规则计算
function computeDiscount(coupon, amount) {
  switch (coupon.type) {
    case 'full_reduction':   // 满减
      return amount >= coupon.threshold ? coupon.reduce : 0;
    case 'discount':         // 折扣
      return amount * (1 - coupon.rate);
    case 'cash':             // 无门槛
      return coupon.value;
    default:
      return 0;
  }
}
```

```text
优惠券要点：
1. 可用券列表按商品范围、金额门槛、有效期过滤
2. 优惠叠加规则要清晰，别让用户算不清账
3. 下单时锁定券，防止并发使用
4. 优惠明细逐行展示，含原价、优惠、实付
```

## 用户中心

用户中心聚合订单、地址、收藏、优惠券、账户信息等入口，是「交易闭环 + 复购」的阵地。核心是地址管理（增删改查 + 默认地址）与订单查询。

```js
// 地址管理：默认地址互斥
function setDefault(addresses, id) {
  return addresses.map(a => ({ ...a, isDefault: a.id === id }));
}

// 下单时取默认地址
const defaultAddress = addresses.find(a => a.isDefault);
```

```text
用户中心要点：
1. 地址管理支持增删改查与默认地址
2. 订单列表分状态 tab 展示
3. 收藏、足迹、优惠券等个人资产集中管理
4. 未登录访问时引导登录并回跳
```

## SSR

电商的商品页、列表页需要 SSR（服务端渲染），让搜索引擎和用户第一时间拿到完整 HTML，同时缩短首屏白屏时间。Next.js/Nuxt 是主流方案。

```jsx
// Next.js 商品详情页 SSR
export async function getServerSideProps({ params }) {
  const product = await fetchProduct(params.id);
  return { props: { product } };   // 服务端取数，直接渲染进 HTML
}

function ProductPage({ product }) {
  return (
    <div>
      <h1>{product.title}</h1>
      <p>{product.price}</p>
    </div>
  );
}
```

```text
SSR 在电商的价值：
1. 首屏秒开，降低跳出率
2. HTML 直接可被搜索引擎抓取
3. 商品详情、列表等强 SEO 页面用 SSR
4. 购物车、结算等强交互页面可保留 CSR
```

## SEO

SEO 是电商免费流量的关键，核心是「可抓取的 HTML + 结构化数据 + 规范链接」。技术上靠 SSR/SSG 输出完整内容，配合 meta、sitemap、结构化数据（如 Product schema）。

```jsx
// Next.js SEO：动态 meta + 结构化数据
function ProductPage({ product }) {
  return (
    <Head>
      <title>{product.title}</title>
      <meta name="description" content={product.summary} />
      <link rel="canonical" href={`https://shop.com/p/${product.id}`} />
      <script type="application/ld+json">
        {JSON.stringify({
          '@context': 'https://schema.org',
          '@type': 'Product',
          name: product.title,
          offers: { price: product.price, priceCurrency: 'CNY' },
        })}
      </script>
    </Head>
  );
}
```

```text
SEO 要点：
1. 内容要进 HTML，别全靠 JS 渲染
2. canonical 处理重复 URL，避免权重分散
3. 商品结构化数据帮助搜索引擎展示富结果
4. sitemap.xml 提交收录
```

## 性能优化

性能直接影响电商转化率，慢 1 秒可能导致转化率明显下降。核心是「首屏快、交互快、体积小」：图片优化、代码分割、缓存、预加载。

```jsx
// 图片懒加载 + 响应式图片
<img
  src={item.thumb}
  loading="lazy"
  srcSet={`${item.thumb}?w=480 480w, ${item.thumb}?w=800 800w`}
  sizes="(max-width: 600px) 480px, 800px"
  alt={item.title}
/>

// 路由级代码分割（React lazy）
const ProductPage = lazy(() => import('./ProductPage'));
```

```text
性能优化清单：
1. 图片 WebP/AVIF 格式 + 懒加载 + CDN
2. 路由级代码分割，首屏只加载必要代码
3. 关键资源预加载（preload/prefetch）
4. 接口缓存与合并，减少请求数
```

### 场景一：SKU 规格选择器

```jsx
// 规格选择：点击选中，无库存规格禁用
function SkuSelector({ product }) {
  const [selected, setSelected] = useState({});
  const current = matchSkuBySelection(product, selected);

  return product.specs.map(spec => (
    <div key={spec.name}>
      <span>{spec.name}</span>
      {spec.values.map(v => {
        const disabled = isSpecDisabled(product, selected, spec.name, v);
        return (
          <button
            key={v}
            disabled={disabled}
            className={selected[spec.name] === v ? 'active' : ''}
            onClick={() => setSelected(s => ({ ...s, [spec.name]: v }))}
          >
            {v}
          </button>
        );
      })}
    </div>
  ));
}
```

### 场景二：购物车合并（游客 → 登录）

```js
// 登录后合并本地购物车与服务端购物车
async function mergeCart(localCart, userId) {
  const serverCart = await fetchCart(userId);
  const merged = [...serverCart];
  for (const local of localCart) {
    const exist = merged.find(m => m.skuId === local.skuId);
    if (exist) exist.qty = Math.min(exist.qty + local.qty, exist.stock);
    else merged.push(local);
  }
  await saveCart(userId, merged);
  localStorage.removeItem('cart');   // 清空本地购物车
  return merged;
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. 金额一律用分（整数）存储计算，展示时才转元
2. 商品详情/列表用 SSR 保 SEO，交互页保留 CSR
3. 图片用响应式 + 懒加载 + CDN 多重优化
4. 购物车游客本地、登录服务端，登录时合并
5. 支付金额以服务端为准，前端只发起与展示
6. 埋点覆盖曝光、点击、加购、下单全漏斗

### 踩坑记录

```text
坑 1：价格用浮点数计算
结论：0.1 + 0.2 = 0.30000000000000004，金额出错。
原因：JS 浮点数二进制表示有精度损失。
解法：金额用分（整数）存储计算，展示时 /100 格式化。

坑 2：SPA 导致商品页搜索不到
结论：搜索引擎抓不到内容，SEO 流量归零。
原因：CSR 下 HTML 是空壳，内容靠 JS 渲染。
解法：商品、列表等强 SEO 页面用 SSR/SSG。

坑 3：搜索请求结果乱序
结论：输入「手机」返回了「手机壳」的旧结果。
原因：多个并发请求返回顺序不确定。
解法：用 AbortController 取消旧请求，或比对请求序号。

坑 4：库存不足仍能下单
结论：用户提交订单后才发现没货。
原因：前端只读了下单前的库存快照。
解法：下单时服务端校验库存并扣减，前端提示失败原因。

坑 5：支付结果只靠回调
结论：回调丢失导致订单状态一直「待付款」。
原因：网络抖动可能漏掉支付回调。
解法：回调 + 主动轮询双保险，超时后人工对账。
```

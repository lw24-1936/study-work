## 概述

JavaScript 声明变量的方式有三种：var、let、const。它们在作用域、提升、重复声明上行为差异巨大，是现代 JavaScript 必须掌握的基础。

```text
三种声明对比：
        var          let        const
作用域   函数作用域    块级作用域   块级作用域
提升     是（undefined） 是（TDZ）   是（TDZ）
重复声明 允许          不允许      不允许
重新赋值 允许          允许        不允许（常量）
```

```text
现代实践：
1. 默认用 const（值不变）
2. 需要重新赋值用 let
3. 不用 var（除非维护旧代码）
```

## var 的缺陷

var 只有函数作用域、允许重复声明、存在提升，容易产生隐蔽 bug。

```js
// 缺陷一：没有块级作用域
if (true) {
  var x = 10;
}
console.log(x);   // 10（块外也能访问！）

// 缺陷二：循环变量泄漏
for (var i = 0; i < 3; i++) {}
console.log(i);   // 3（i 泄漏到循环外）
```

```js
// 缺陷三：允许重复声明
var a = 1;
var a = 2;         // 不报错，静默覆盖
console.log(a);    // 2
```

```js
// 缺陷四：循环 + 异步的经典 bug
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);
}
// 输出 3 3 3（var 共享同一个 i，循环结束时都是 3）
```

## let 与 const

let 和 const 是 ES6 引入的块级作用域声明，解决了 var 的大部分问题。

```js
// 块级作用域
if (true) {
  let y = 10;
  const z = 20;
}
// console.log(y);   // ReferenceError（块外不可访问）

// 不允许重复声明
let a = 1;
// let a = 2;        // SyntaxError
```

```js
// const：不可重新赋值（但引用类型内部可改）
const obj = { name: 'a' };
obj.name = 'b';       // 允许（改属性，不是重新赋值）
// obj = {};          // TypeError（重新赋值报错）

const arr = [1, 2];
arr.push(3);          // 允许（修改内容）
```

```js
// let 解决循环 + 异步问题
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);
}
// 输出 0 1 2（每次迭代都有独立的 i）
```

## TDZ 暂时性死区

TDZ（Temporal Dead Zone）指 let/const 声明的变量，在声明语句执行前不可访问，访问会抛 ReferenceError。

```js
// var：提升后为 undefined，可访问
console.log(a);       // undefined
var a = 1;

// let/const：TDZ，访问抛错
console.log(b);       // ReferenceError: Cannot access 'b' before initialization
let b = 2;
```

```text
TDZ 的本质：
let/const 变量在进入作用域时就被「创建」，
但在声明语句执行前处于「未初始化」状态，
这段区域叫暂时性死区（TDZ）。

对比 var：提升后立即初始化为 undefined，所以可访问。
```

```js
// typeof 也受 TDZ 影响
typeof x;             // ReferenceError（TDZ 内）
let x;
```

## Hoisting 变量提升

提升（Hoisting）是 JS 的「声明提前」机制：变量和函数声明在代码执行前被提升到作用域顶部。

```text
提升的三种情况：
var 声明 —— 提升 + 初始化为 undefined
let/const 声明 —— 提升但进入 TDZ（未初始化）
函数声明 —— 整体提升（可提前调用）
```

```js
// var 提升
console.log(a);       // undefined（提升但未赋值）
var a = 1;

// 函数声明提升
sayHi();              // 'hi'（可提前调用）
function sayHi() { console.log('hi'); }

// 函数表达式不整体提升
// fn();              // TypeError（fn 是 undefined）
var fn = function() {};
```

```text
var 提升的完整过程：
var a = 1 实际等价于：
var a;      // 提升（声明提前，初始化为 undefined）
a = 1;      // 赋值留在原地
```

## Scope 作用域

作用域决定变量在何处可访问。JavaScript 有三种作用域。

```text
三种作用域：
1. 全局作用域 —— 顶层声明的变量，处处可访问
2. 函数作用域 —— 函数内声明的 var/let/const，函数外不可访问
3. 块级作用域 —— {} 内声明的 let/const，块外不可访问

作用域链：内层作用域可访问外层，外层不能访问内层。
```

```js
const global = 'global';        // 全局作用域

function fn() {
  const local = 'local';        // 函数作用域
  if (true) {
    const block = 'block';      // 块级作用域
    console.log(global);        // 可访问外层
  }
  // console.log(block);        // ReferenceError（块外不可访问）
}
```

```text
作用域链与闭包的关系：
函数会记住它定义时所在的作用域，
即使函数在其他地方被调用，也能访问定义处的外层变量。
这就是闭包的来源（详见 [[10.5-闭包]]）。
```

## 应用场景实战

### 场景一：循环内正确捕获变量

```js
// 反例：var 导致全部输出 3
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);
}

// 正例：let 每次迭代独立作用域
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);
}
// 0 1 2
```

### 场景二：用 const 提升代码意图

```js
// 明确不变量与可变量
const config = { retries: 3 };   // 配置不变
let attempt = 0;                 // 会变化
while (attempt < config.retries) {
  attempt++;
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. 默认 const，需要重新赋值才用 let，不用 var
2. 声明尽量靠近使用位置，缩小作用域
3. 循环计数、累加器用 let
4. 配置、常量、函数引用用 const
5. 理解 TDZ，避免在声明前使用变量

### 踩坑记录

```text
坑 1：var 循环变量泄漏
结论：for 循环后 i 仍可访问，且值为循环次数。
原因：var 是函数作用域，循环不产生新作用域。
解法：用 let 声明循环变量。

坑 2：var + 异步输出全相同
结论：循环里 setTimeout 全部输出最后一次的值。
原因：var 共享同一变量，异步回调执行时循环已结束。
解法：用 let，或闭包包裹。

坑 3：TDZ 内访问报错
结论：声明前使用 let/const 变量抛 ReferenceError。
原因：TDZ 内变量未初始化。
解法：声明在使用之前，或理解 TDZ 边界。

坑 4：const 对象误以为不可变
结论：以为 const 对象不能改属性。
原因：const 限制的是「重新赋值」，不是内容可变性。
解法：需要冻结用 Object.freeze，或理解 const 语义。

坑 5：函数表达式不能提前调用
结论：提前调用函数表达式报错。
原因：函数表达式不整体提升，只提升变量为 undefined。
解法：函数声明可提升；函数表达式须在定义后调用。
```

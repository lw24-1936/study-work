## 概述

闭包（Closure）是 JavaScript 最核心也最常被考察的概念：函数「记住」了它定义时所在的作用域，即使在该作用域之外被调用，仍能访问其中的变量。它是实现私有变量、函数工厂、模块模式的基础。

```text
闭包的定义：
闭包 = 函数 + 函数定义时所在的作用域（词法环境）

通俗理解：
函数「背」着它出生地的环境到处跑，
无论在哪里调用，都能访问出生地的变量。
```

## Closure 闭包的概念

```js
function outer() {
  const secret = '内部变量';

  function inner() {
    console.log(secret);   // 访问外层变量
  }

  return inner;
}

const fn = outer();        // outer 已执行完毕
fn();                      // '内部变量'（仍能访问 secret）
```

```text
关键点：
1. outer 执行结束后，其作用域本应销毁
2. 但 inner 引用了 secret，导致该作用域被保留
3. 这个被保留的作用域 + inner 就是闭包
```

```text
闭包产生的条件：
1. 函数内定义函数
2. 内层函数引用外层函数的变量
3. 内层函数被返回或传递到外部
```

## Lexical Environment 词法环境

词法环境是 JS 引擎管理作用域的内部结构，由「环境记录」（变量绑定）+「对外层环境的引用」组成。

```text
词法环境结构：
Lexical Environment = {
  环境记录（Environment Record）—— 当前作用域的变量绑定
  外部引用（outer）—— 指向外层词法环境的引用
}

闭包的本质：内层函数的词法环境保留了对它定义处外层环境的引用。
```

```js
function outer() {
  const x = 10;
  // inner 的词法环境：{ x: 10, outer: <全局环境> }
  function inner() {
    console.log(x);
  }
  return inner;
}
```

```text
词法环境的生命周期：
正常情况 —— 函数执行完，词法环境被回收
闭包情况 —— 内层函数引用了变量，词法环境被保留（不被回收）
```

## Scope Chain 作用域链

作用域链由嵌套的词法环境组成，变量查找沿链从内向外进行。

```js
const global = 'global';

function outer() {
  const outerVar = 'outer';

  function inner() {
    const innerVar = 'inner';
    console.log(innerVar);   // 找到：自身
    console.log(outerVar);   // 找到：向上找 outer
    console.log(global);     // 找到：再向上找 global
  }

  inner();
}
```

```text
变量查找顺序：
1. 当前函数作用域
2. 外层函数作用域（闭包）
3. 全局作用域
4. 都找不到 → ReferenceError

作用域链在「函数定义时」就确定（词法作用域），与调用位置无关。
```

## 私有变量

闭包可以创建真正的私有变量：外部无法直接访问，只能通过暴露的接口操作。

```js
function createCounter() {
  let count = 0;          // 私有变量（外部无法直接访问）

  return {
    increment() { return ++count; },
    decrement() { return --count; },
    get() { return count; },
  };
}

const counter = createCounter();
counter.increment();      // 1
counter.increment();      // 2
counter.get();            // 2
counter.count;            // undefined（外部访问不到）
```

```text
私有变量的价值：
1. 数据封装 —— 外部不能直接改内部状态
2. 强制走接口 —— 通过方法控制访问
3. 避免全局污染 —— 状态被限制在闭包内
```

## 函数工厂

闭包让函数可以「定制」：工厂函数返回根据参数定制的函数。

```js
function makeMultiplier(factor) {
  return function(n) {
    return n * factor;     // 捕获 factor
  };
}

const double = makeMultiplier(2);
const triple = makeMultiplier(3);

double(5);      // 10
triple(5);      // 15
// double 和 triple 各自捕获不同的 factor，互不干扰
```

```js
// 更常见的场景：柯里化
const add = a => b => a + b;
const add5 = add(5);
add5(10);       // 15
```

## 模块模式

模块模式用闭包实现命名空间隔离，是早期（ES6 模块之前）的模块化方案。

```js
// 模块模式：IIFE + 闭包
const counterModule = (function() {
  let count = 0;          // 模块私有状态

  return {
    increment() { return ++count; },
    reset() { count = 0; return count; },
  };
})();

counterModule.increment();   // 1
counterModule.reset();       // 0
```

```text
模块模式的两大要素：
1. IIFE（立即执行函数）—— 创建独立作用域
2. 闭包 —— 返回的对象方法能访问私有状态

现代替代：ES Modules 原生提供模块作用域，闭包模块主要用于理解原理。
```

## 应用场景实战

### 场景一：防抖 / 节流（闭包保存计时器状态）

```js
function debounce(fn, delay) {
  let timer = null;          // 闭包保存计时器
  return function(...args) {
    clearTimeout(timer);
    timer = setTimeout(() => fn.apply(this, args), delay);
  };
}

const search = debounce(() => console.log('搜索'), 300);
search();
search();
search();                    // 只触发一次（300ms 后）
```

### 场景二：循环中正确捕获变量

```js
// 用闭包捕获每次迭代的值
for (var i = 0; i < 3; i++) {
  (function(j) {
    setTimeout(() => console.log(j), 0);
  })(i);
}
// 0 1 2

// 现代写法：let 天然解决
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);
}
// 0 1 2
```

## 最佳实践与踩坑记录

### 最佳实践

1. 用闭包封装私有状态，暴露最小接口
2. 循环 + 异步用 let 或闭包捕获，避免共享变量
3. 需要定制函数用工厂函数（闭包捕获参数）
4. 注意闭包的内存：不再使用的闭包及时释放引用
5. 模块化优先用 ES Modules，闭包用于理解原理

### 踩坑记录

```text
坑 1：循环中 var + 闭包共享变量
结论：循环里 setTimeout 全部输出最后一个值。
原因：var 共享同一变量，闭包捕获的是变量引用而非值。
解法：用 let（每轮独立），或 IIFE 传参捕获值。

坑 2：闭包导致内存泄漏
结论：大量闭包持有大对象引用，内存不释放。
原因：闭包保留整个词法环境，被引用的变量无法回收。
解法：不需要时置空引用，避免长生命周期闭包持有大对象。

坑 3：误以为闭包「复制」了变量值
结论：以为闭包保存的是定义时的值快照。
原因：闭包捕获的是「变量引用」，读取的是最新值。
解法：需要快照用 IIFE 传参，或理解引用语义。

坑 4：模块模式多实例状态共享
结论：多次调用工厂，状态互相污染。
原因：闭包共享同一个外部变量。
解法：每个实例用独立的工厂调用（createCounter() 每次新建）。

坑 5：闭包内 this 丢失
结论：闭包函数里 this 不是预期对象。
原因：普通函数 this 由调用方式决定，与定义位置无关。
解法：用箭头函数继承 this，或用 bind 显式绑定。
```

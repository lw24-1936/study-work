## 概述

Worker 的价值不在语法本身，而在于把「会卡住 UI 的重活」从主线程挪走。凡是纯计算、不碰 DOM 的任务，理论上都可以丢进 Worker。

```text
Worker 适用的任务特征：
1. CPU 密集 —— 计算量大，单次执行超 16ms
2. 数据密集 —— 大体积数据解析、转换
3. 纯函数式 —— 不依赖 DOM，输入输出可序列化
4. 可并行 —— 能拆成多个独立子任务

不适合的场景：
1. 频繁小任务 —— 通信开销大于计算本身
2. 强依赖 DOM —— 需要读写页面节点
```

```js
// 通用 Worker 封装：任务派发器
const worker = new Worker('task.js');
function runTask(payload) {
  return new Promise((resolve, reject) => {
    worker.onmessage = (e) => resolve(e.data);
    worker.onerror = (e) => reject(e);
    worker.postMessage(payload);
  });
}
```

## 图片处理

图片处理是 Worker 最经典的应用。ImageData 可以转移，Canvas 也能离屏渲染。

```js
// 主线程：读取图片像素交给 Worker 做灰度化
const img = document.querySelector('img');
const canvas = document.createElement('canvas');
canvas.width = img.width;
canvas.height = img.height;
const ctx = canvas.getContext('2d');
ctx.drawImage(img, 0, 0);
const imageData = ctx.getImageData(0, 0, canvas.width, canvas.height);

// 转移 buffer，零拷贝
worker.postMessage(imageData.data.buffer, [imageData.data.buffer]);
```

```js
// worker.js：灰度化 + 反色
self.onmessage = (e) => {
  const buf = e.data;
  const pixels = new Uint8Array(buf);
  for (let i = 0; i < pixels.length; i += 4) {
    const gray = pixels[i] * 0.299 + pixels[i + 1] * 0.587 + pixels[i + 2] * 0.114;
    pixels[i] = pixels[i + 1] = pixels[i + 2] = gray;
  }
  self.postMessage(buf, [buf]);
};
```

```js
// OffscreenCanvas 让 Canvas 渲染也进 Worker
const offscreen = canvas.transferControlToOffscreen();
worker.postMessage({ canvas: offscreen }, [offscreen]);
```

```text
图片处理要点：
1. ImageData.data.buffer 是 ArrayBuffer，可 Transferable
2. OffscreenCanvas 支持 transferControlToOffscreen 转移控制权
3. 图像滤镜、缩放、压缩、格式转换都是典型场景
```

## 大数据计算

数值密集的计算——质数筛选、矩阵运算、统计聚合——放 Worker 可以避免长任务卡顿。

```js
// worker.js：筛质数
self.onmessage = (e) => {
  const { start, end } = e.data;
  const primes = [];
  for (let n = start; n <= end; n++) {
    let isPrime = n > 1;
    for (let d = 2; d * d <= n; d++) {
      if (n % d === 0) { isPrime = false; break; }
    }
    if (isPrime) primes.push(n);
  }
  self.postMessage(primes);
};
```

```js
// 主线程：把区间拆成 4 段并行计算
const workers = Array.from({ length: 4 }, () => new Worker('prime.js'));
const results = await Promise.all(workers.map((w, i) => {
  return new Promise((resolve) => {
    w.onmessage = (e) => resolve(e.data);
    w.postMessage({ start: i * 25000 + 1, end: (i + 1) * 25000 });
  });
}));
const allPrimes = results.flat();
```

```text
并行拆分模式：
1. 把大区间/大数组按 CPU 核数切成 N 份
2. 每份交给一个 Worker 独立计算
3. 全部完成后合并结果
```

## JSON Parsing

大体积 JSON 的解析（JSON.parse）在主线程会阻塞，挪到 Worker 里解析后把结果传回来。

```js
// worker.js：解析大 JSON
self.onmessage = (e) => {
  const text = e.data;
  const obj = JSON.parse(text);
  self.postMessage(obj);
};
```

```js
// 主线程：读取大 JSON 文本交给 Worker
const text = await fetch('/data/big.json').then((r) => r.text());
const worker = new Worker('parse.js');
worker.onmessage = (e) => console.log(e.data);
worker.postMessage(text);
```

```text
注意点：
1. JSON.parse 结果要结构化克隆回主线程，超大对象仍有开销
2. 更优方案：解析 + 过滤/聚合一起在 Worker 完成，只回传需要的数据
3. 超大 JSON 也可考虑流式解析（如 jsonparse 分块）
```

## 加密

Web Crypto API 的加解密、哈希、签名都是 CPU 密集操作，适合放 Worker。

```js
// worker.js：哈希计算
self.onmessage = async (e) => {
  const data = e.data;
  const digest = await crypto.subtle.digest('SHA-256', data);
  self.postMessage(digest, [digest]);  // 结果 buffer 可转移
};
```

```js
// 主线程
const worker = new Worker('hash.js');
worker.onmessage = (e) => console.log(new Uint8Array(e.data));
worker.postMessage(new TextEncoder().encode('hello world'));
```

```text
加密场景：
1. 密码哈希 —— SHA-256 / bcrypt（纯 JS 实现）
2. 文件完整性校验 —— 大文件分块哈希
3. 对称加密 —— AES-GCM 加解密
4. 密钥派生 —— PBKDF2 慢速派生放 Worker 不卡 UI
```

## 压缩

浏览器内置 CompressionStream / DecompressionStream，配合 Worker 做数据的流式压缩解压。

```js
// worker.js：gzip 压缩
self.onmessage = async (e) => {
  const input = e.data;
  const stream = new Blob([input]).stream().pipeThrough(new CompressionStream('gzip'));
  const compressed = await new Response(stream).arrayBuffer();
  self.postMessage(compressed, [compressed]);
};
```

```js
// 解压
async function decompress(buf) {
  const stream = new Blob([buf]).stream().pipeThrough(new DecompressionStream('gzip'));
  return new Response(stream).arrayBuffer();
}
```

```text
压缩场景：
1. 大 JSON/文本上传前压缩，减少带宽
2. 本地缓存数据压缩，节省存储
3. 支持的格式：gzip、deflate、deflate-raw（取决于浏览器）
```

## AI 推理

浏览器端 AI 推理（WebNN、WebGPU、TensorFlow.js、transformers.js）计算量巨大，天然需要 Worker 承载。

```js
// 主线程：加载模型并推理
import { pipeline } from '@xenova/transformers';
const worker = new Worker(new URL('./ai.js', import.meta.url), { type: 'module' });
worker.onmessage = (e) => console.log('推理结果', e.data);
worker.postMessage({ text: '这是一段待分类的文本' });
```

```js
// ai.js：在 Worker 里跑模型
import { pipeline } from '@xenova/transformers';
let classifier;
self.onmessage = async (e) => {
  if (!classifier) {
    classifier = await pipeline('sentiment-analysis', 'Xenova/distilbert-base-uncased');
  }
  const result = await classifier(e.data.text);
  self.postMessage(result);
};
```

```text
AI 推理要点：
1. 模型加载和推理都极耗 CPU/GPU，必须放 Worker
2. WebGPU 推理在 Worker 里也可以访问 GPU
3. 大模型文件用缓存避免重复下载
```

## WebAssembly

Worker 和 WebAssembly 是绝配：WASM 提供接近原生的计算速度，Worker 提供并行线程。

```js
// 在 Worker 里加载并调用 WASM
// worker.js
let instance;
self.onmessage = async (e) => {
  if (!instance) {
    const { instance: inst } = await WebAssembly.instantiateStreaming(
      fetch('/lib.wasm')
    );
    instance = inst;
  }
  const result = instance.exports.compute(e.data);
  self.postMessage(result);
};
```

```js
// 多线程 WASM：每个 Worker 一个实例，并行计算
const workers = [0, 1, 2, 3].map(() => new Worker('wasm-worker.js'));
```

```text
Worker + WASM 组合：
1. WASM 处理计算密集，Worker 提供多线程并行
2. 编译和实例化一次，复用实例
3. 详见 47 章 WebAssembly
```

## 应用场景实战

### 场景一：大文件分块哈希（不卡 UI）

```js
// 主线程：读取文件分块交给 Worker 逐步哈希
const file = document.querySelector('input[type=file]').files[0];
const worker = new Worker('hash.js');
const chunkSize = 1024 * 1024; // 1MB
worker.onmessage = (e) => console.log('文件哈希', e.data);

const stream = file.stream();
const reader = stream.getReader();
let offset = 0;
worker.postMessage({ cmd: 'init' });
while (true) {
  const { done, value } = await reader.read();
  if (done) break;
  worker.postMessage({ cmd: 'update', data: value, offset }, [value.buffer]);
  offset += value.length;
}
worker.postMessage({ cmd: 'final' });
```

### 场景二：Excel 数据解析与聚合

```js
// 主线程：CSV/Excel 大表解析放 Worker
const worker = new Worker('parse.js');
worker.onmessage = (e) => {
  const { total, avg } = e.data;
  console.log(`共 ${total} 行，平均值 ${avg}`);
};
const text = await fetch('/data/sales.csv').then((r) => r.text());
worker.postMessage(text);
```

```js
// parse.js：解析 CSV 并聚合
self.onmessage = (e) => {
  const lines = e.data.split('\n').slice(1);
  let total = 0, sum = 0;
  for (const line of lines) {
    const cols = line.split(',');
    const amount = Number(cols[2]);
    if (!Number.isNaN(amount)) { total++; sum += amount; }
  }
  self.postMessage({ total, avg: sum / total });
};
```

## 最佳实践与踩坑记录

### 最佳实践

1. 任务超过 16ms 才进 Worker，小任务通信开销反而更慢
2. 大数据量用 Transferable，避免重复拷贝
3. 并行任务按 navigator.hardwareConcurrency 决定 Worker 数量
4. 模型/WASM 实例复用，别每次任务都重新加载
5. 任务拆分要均衡，避免某个 Worker 成为瓶颈

### 踩坑记录

```text
坑 1：小任务反而更慢
结论：简单计算放 Worker 后总耗时增加。
原因：postMessage 序列化 + 线程切换开销大于计算本身。
解法：先测主线程耗时，超 16ms 再上 Worker。

坑 2：回传整个大对象卡顿
结论：Worker 算得快，但结果传回主线程仍卡。
原因：结果对象结构化克隆又复制一遍。
解法：结果用 Transferable，或 Worker 内先聚合只回传摘要。

坑 3：OffscreenCanvas 转移后主线程 canvas 失效
结论：transferControlToOffscreen 后主线程 canvas 被占用。
原因：控制权已转移给 Worker，一个 canvas 同一时刻只能一个线程用。
解法：渲染完再转移回来，或用两个 canvas 轮换。

坑 4：Worker 内 import 失败
结论：ES Module 导入在经典 Worker 里报错。
原因：经典 Worker 默认非模块。
解法：new Worker(url, { type: 'module' }) 显式声明模块模式。

坑 5：加密库依赖 window
结论：部分加密库在 Worker 里初始化报错。
原因：库假设了 window/document 存在。
解法：用 Web Crypto API，或选支持 Worker 环境的库。
```

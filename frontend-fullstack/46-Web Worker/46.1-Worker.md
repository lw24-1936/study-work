## 概述

JavaScript 是单线程语言，主线程既要处理 DOM、渲染，又要跑业务逻辑，遇到重计算会直接卡死界面。Web Worker 把耗时任务丢到后台线程执行，主线程不阻塞，页面保持流畅。

```text
Web Worker 解决的核心问题：
1. 主线程阻塞 —— 重计算、大循环卡死 UI
2. 渲染掉帧 —— 长任务挤占渲染帧
3. 并行能力 —— 多核 CPU 无法被单线程 JS 利用

Worker 的限制：
1. 无 DOM —— 不能操作 document / window
2. 通信靠消息 —— postMessage 传递，结构化克隆
3. 独立全局 —— 用 self 而非 window
```

```js
// 主线程创建 Worker
const worker = new Worker('worker.js');
worker.postMessage({ type: 'start', data: 1000000 });
worker.onmessage = (e) => console.log('结果', e.data);
```

## Worker 类型总览

浏览器和 Node.js 共提供四种 Worker，各有用途。

```text
Dedicated Worker —— 专属 Worker，单个页面独占，主线程与单 Worker 一对一
Shared Worker   —— 共享 Worker，同源多个页面/标签共享同一个实例
Service Worker  —— 服务 Worker，独立于页面，拦截网络请求做离线缓存/PWA
Worker Thread   —— Node.js 的 worker_threads，服务端多线程
```

```text
对比维度          Dedicated      Shared         Service       Worker Thread
运行环境          浏览器          浏览器          浏览器          Node.js
归属              单页面          同源多页面      注册域名        单个 Node 进程
能否操作 DOM      否              否              否             无 DOM
生命周期          页面关闭即止    无引用即止      浏览器调度      手动终止
典型用途          重计算          多标签同步      离线/推送      服务端并行
```

## Dedicated Worker

Dedicated Worker 是最常用的 Worker，由主线程 new Worker 创建，与创建它的页面一一对应。

```js
// worker.js（后台线程）
self.onmessage = (e) => {
  const n = e.data;
  let sum = 0;
  for (let i = 0; i < n; i++) sum += i;
  self.postMessage(sum);
};
```

```js
// 主线程
const worker = new Worker('worker.js');
worker.postMessage(100000000);              // 提交任务
worker.onmessage = (e) => console.log(e.data);  // 收到结果
worker.onerror = (e) => console.error(e.message);
```

```js
// 内联 Worker：用 Blob URL 免去独立文件
const code = 'self.onmessage = (e) => self.postMessage(e.data * 2)';
const blob = new Blob([code], { type: 'application/javascript' });
const url = URL.createObjectURL(blob);
const worker = new Worker(url);
worker.postMessage(21);
worker.onmessage = (e) => console.log(e.data); // 42
```

## postMessage 与 onmessage

Worker 与主线程通过消息通信，数据用结构化克隆算法复制，两边不能共享引用。

```js
// 主线程 → Worker：postMessage 发，onmessage 收
worker.postMessage({ cmd: 'calc', args: [1, 2, 3] });
worker.onmessage = (e) => { /* e.data 是 Worker 回传的数据 */ };

// Worker → 主线程：self.postMessage 发
self.postMessage({ result: 6 });
```

```js
// addEventListener 写法与 onmessage 等价
self.addEventListener('message', (e) => {
  console.log('收到', e.data);
});
```

```text
消息传递要点：
1. 结构化克隆 —— 对象深拷贝，两边改动互不影响
2. 可传递类型 —— 基本类型、对象、数组、ArrayBuffer、Blob 等
3. 不能传 —— 函数、DOM 节点、带循环引用的对象
4. 大对象拷贝有开销 —— 可用 Transferable 零拷贝
```

## Transferable

Transferable（可转移对象）通过转移所有权实现零拷贝，传大 ArrayBuffer 时性能远好于结构化克隆。

```js
// 零拷贝转移 ArrayBuffer 所有权
const buf = new ArrayBuffer(1024 * 1024 * 64); // 64MB
worker.postMessage(buf, [buf]);    // 第二个参数列出要转移的对象
// 转移后主线程的 buf 变为 detached，不可再用
console.log(buf.byteLength); // 0
```

```js
// 未用 Transferable 的代价：复制 64MB 数据
worker.postMessage(buf);  // 结构化克隆，多花一次内存拷贝
```

```text
Transferable 常见对象：
ArrayBuffer、MessagePort、ImageBitmap、OffscreenCanvas、ReadableStream
```

```js
// 转移后重新取回：Worker 计算完再把所有权转回来
// worker.js
self.onmessage = (e) => {
  const buf = e.data;
  const view = new Uint8Array(buf);
  // ... 处理数据
  self.postMessage(buf, [buf]);  // 转回主线程
};
```

## Shared Worker

Shared Worker 被同源的多个页面共享，用于多标签页之间的数据同步和共享连接。

```js
// shared-worker.js
let connections = 0;
self.onconnect = (e) => {
  const port = e.ports[0];
  connections++;
  port.onmessage = (msg) => {
    port.postMessage(`当前连接数 ${connections}，收到 ${msg.data}`);
  };
};
```

```js
// 页面 A 和页面 B 共享同一个实例
const worker = new SharedWorker('shared-worker.js');
worker.port.start();           // 必须显式 start
worker.port.postMessage('hello');
worker.port.onmessage = (e) => console.log(e.data);
```

```text
Shared Worker 要点：
1. 同一源下多个页面 new SharedWorker(同 URL) 得到同一实例
2. 用 port 通信，必须先 port.start()
3. 所有连接页关闭后实例销毁
4. 典型用途 —— 跨标签页共享 WebSocket、同步登录状态
```

## Service Worker

Service Worker 是独立于页面的后台脚本，可拦截并代理网络请求，是 PWA 的基石。详细见 22 章。

```js
// 注册
navigator.serviceWorker.register('/sw.js');

// sw.js —— 拦截请求做缓存
self.addEventListener('fetch', (event) => {
  event.respondWith(
    caches.match(event.request).then((res) => res || fetch(event.request))
  );
});
```

```text
Service Worker 与普通 Worker 的区别：
1. 不绑定页面 —— 页面关闭后仍存活
2. 可拦截请求 —— fetch 事件代理网络
3. 需 HTTPS —— 安全上下文才可注册
4. 生命周期 —— install → activate → fetch
```

## Worker Thread

Node.js 的 worker_threads 模块提供类似 Web Worker 的多线程能力，用于服务端重计算。

```js
// main.js
const { Worker } = require('node:worker_threads');
const worker = new Worker('./calc.js', { workerData: 10000000 });
worker.on('message', (msg) => console.log('结果', msg));
```

```js
// calc.js
const { parentPort, workerData } = require('node:worker_threads');
let sum = 0;
for (let i = 0; i < workerData; i++) sum += i;
parentPort.postMessage(sum);
```

```text
worker_threads 与 Web Worker 对应：
new Worker(url)            → new Worker('./calc.js')
postMessage(初始化数据)     → workerData 选项
self.postMessage           → parentPort.postMessage
SharedArrayBuffer / Atomics 两边通用
```

## SharedArrayBuffer 与 Atomics

SharedArrayBuffer 让多个线程共享同一块内存，配合 Atomics 做原子操作，避免拷贝。

```js
// 主线程创建共享内存
const sab = new SharedArrayBuffer(1024);
const shared = new Int32Array(sab);
worker.postMessage(sab);  // 共享而非拷贝
```

```js
// worker.js
self.onmessage = (e) => {
  const shared = new Int32Array(e.data);
  Atomics.add(shared, 0, 10);       // 原子加 10
  Atomics.store(shared, 1, 42);     // 原子写
};
```

```js
// 主线程等待通知而非轮询
Atomics.wait(shared, 0, 0);    // 阻塞等待 shared[0] 变化
Atomics.notify(shared, 0, 1);  // 唤醒一个等待者
```

```text
Atomics 常用方法：
Atomics.add / sub          —— 原子加减
Atomics.store / load       —— 原子读写
Atomics.compareExchange    —— 原子比较交换（CAS）
Atomics.wait / notify      —— 线程等待/唤醒
```

```text
注意：SharedArrayBuffer 需要跨源隔离（COOP/COEP 响应头）才可用，
这是 Spectre 漏洞之后浏览器加的安全限制。
```

## 应用场景实战

### 场景一：主线程委派大数计算

```js
// fib.js —— 计算斐波那契，不阻塞 UI
self.onmessage = (e) => {
  const n = e.data;
  let a = 0, b = 1;
  for (let i = 0; i < n; i++) [a, b] = [b, a + b];
  self.postMessage(a);
};
```

```js
const worker = new Worker('fib.js');
worker.postMessage(100000);
worker.onmessage = (e) => console.log('fib =', e.data);
```

### 场景二：Shared Worker 同步多标签登录状态

```js
// auth.js —— 一个标签登录，其他标签同步刷新
self.onconnect = (e) => {
  const port = e.ports[0];
  port.onmessage = (msg) => {
    port.postMessage({ type: 'login', user: msg.data });
  };
};
```

```text
跨标签同步的完整方案通常配合 BroadcastChannel 或 localStorage 事件，
Shared Worker 承担「共享连接」的角色，例如多个标签复用同一个 WebSocket。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 重计算（超过 16ms）才考虑 Worker，轻任务放主线程
2. 大 ArrayBuffer 用 Transferable 零拷贝，别用结构化克隆
3. Worker 用完 terminate() 释放线程，避免内存泄漏
4. 需要实时共享状态时用 SharedArrayBuffer + Atomics
5. 传数据用可序列化的纯数据，别传函数和 DOM

### 踩坑记录

```text
坑 1：Worker 内读不到 DOM
结论：worker 里 document/window 是 undefined。
原因：Worker 是独立线程，无渲染上下文。
解法：需要 DOM 数据时在主线程算好再 postMessage 传进去。

坑 2：postMessage 传大对象卡顿
结论：几十 MB 数据 postMessage 明显变慢。
原因：结构化克隆要深拷贝，开销大。
解法：ArrayBuffer/ImageBitmap 用 Transferable 转移所有权。

坑 3：Shared Worker 收不到消息
结论：port 未 start，消息静默丢失。
原因：SharedWorker 必须显式 port.start()。
解法：new SharedWorker 后立即 worker.port.start()。

坑 4：SharedArrayBuffer 在页面里 undefined
结论：new SharedArrayBuffer 报错或为 undefined。
原因：需 COOP/COEP 跨源隔离响应头。
解法：响应头加 Cross-Origin-Opener-Policy: same-origin 和 Cross-Origin-Embedder-Policy: require-corp。

坑 5：Worker 脚本路径错误
结论：new Worker 报 404。
原因：路径相对于页面而非脚本文件。
解法：用相对页面根路径，或 new URL('worker.js', import.meta.url)。
```

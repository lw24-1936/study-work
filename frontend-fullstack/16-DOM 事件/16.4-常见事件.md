## 概述

前端开发离不开事件处理。掌握常用事件的触发时机、冒泡特性与典型用途，能应对绝大多数交互需求。

```text
常用事件分类：
鼠标 —— click、dblclick、mousedown、mouseup、mousemove
指针 —— pointerdown、pointerup（统一鼠标/触摸）
键盘 —— keydown、keyup、keypress（已废弃）
表单 —— input、change、submit
焦点 —— focus、blur、focusin、focusout
滚动/尺寸 —— scroll、resize
```

## 鼠标事件 click / dblclick / mousedown / mouseup / mousemove

```js
element.addEventListener('click', () => console.log('单击'));
element.addEventListener('dblclick', () => console.log('双击'));
element.addEventListener('mousedown', () => console.log('按下'));
element.addEventListener('mouseup', () => console.log('松开'));
element.addEventListener('mousemove', () => console.log('移动'));
```

```text
鼠标事件的触发顺序：
mousedown → mouseup → click（单击完整流程）
mousedown → mouseup → click → mousedown → mouseup → click → dblclick（双击）

mousemove 高频触发，注意性能（节流）。
```

## 指针事件 pointerdown / pointerup

PointerEvent 统一鼠标、触摸、笔输入，现代项目推荐。

```js
element.addEventListener('pointerdown', (e) => {
  console.log('按下', e.pointerType);   // mouse/touch/pen
});
element.addEventListener('pointerup', (e) => {
  console.log('松开');
});
```

```text
指针事件 vs 鼠标事件：
pointerdown/up —— 统一鼠标、触摸、笔（现代推荐）
mousedown/up —— 仅鼠标（老式）

移动端用 pointer 系列，无需分别处理 touch 和 mouse。
```

## 键盘事件 keydown / keyup

```js
document.addEventListener('keydown', (e) => {
  console.log('按下', e.key);
  // 长按会连续触发 keydown
});
document.addEventListener('keyup', (e) => {
  console.log('松开', e.key);
});
```

```text
keydown vs keyup：
keydown —— 按下触发（长按连续触发）
keyup —— 松开触发（一次）

keypress 已废弃，用 keydown 替代。
```

## 表单事件 input / change / submit

```js
// input：输入时实时触发（每次 value 变化）
input.addEventListener('input', (e) => {
  console.log('当前值:', e.target.value);
});

// change：值改变且失焦/提交时触发
input.addEventListener('change', (e) => {
  console.log('最终值:', e.target.value);
});

// submit：表单提交时触发
form.addEventListener('submit', (e) => {
  e.preventDefault();
  console.log('表单提交');
});
```

```text
input vs change：
input —— 实时触发（每输入一个字符）
change —— 值确定后触发（失焦、回车，或复选框/下拉切换）

实时搜索用 input，最终确认用 change。
```

## 焦点事件 focus / blur / focusin / focusout

```js
// focus/blur：不冒泡
input.addEventListener('focus', () => console.log('获得焦点'));
input.addEventListener('blur', () => console.log('失去焦点'));

// focusin/focusout：冒泡（可用于事件委托）
container.addEventListener('focusin', (e) => {
  console.log('内部元素获得焦点', e.target);
});
```

```text
focus/blur vs focusin/focusout：
focus/blur —— 不冒泡
focusin/focusout —— 冒泡（可事件委托）

需要委托或统一处理焦点时，用 focusin/focusout。
```

## scroll 与 resize

```js
// scroll：滚动时触发（高频）
window.addEventListener('scroll', () => {
  console.log('滚动位置:', window.scrollY);
});

// resize：窗口尺寸变化时触发
window.addEventListener('resize', () => {
  console.log('窗口尺寸:', window.innerWidth, window.innerHeight);
});
```

```js
// 高频事件需要节流/防抖
function throttle(fn, delay) {
  let last = 0;
  return function(...args) {
    const now = Date.now();
    if (now - last >= delay) {
      last = now;
      fn.apply(this, args);
    }
  };
}

window.addEventListener('scroll', throttle(handleScroll, 100));
```

```text
scroll/resize 的性能：
这两个事件高频触发，直接处理会导致卡顿。
必须节流（throttle）或防抖（debounce）。

滚动监听用 IntersectionObserver 更高效（现代替代）。
```

## 应用场景实战

### 场景一：实时搜索（input + 防抖）

```js
function debounce(fn, delay) {
  let timer;
  return (...args) => {
    clearTimeout(timer);
    timer = setTimeout(() => fn(...args), delay);
  };
}

input.addEventListener('input', debounce(async (e) => {
  const results = await search(e.target.value);
  renderResults(results);
}, 300));
```

### 场景二：滚动加载更多

```js
window.addEventListener('scroll', throttle(() => {
  if (window.innerHeight + window.scrollY >= document.body.offsetHeight - 100) {
    loadMore();   // 接近底部时加载
  }
}, 200));
```

## 最佳实践与踩坑记录

### 最佳实践

1. 移动端用 pointer 系列统一输入
2. 实时搜索用 input，最终确认用 change
3. scroll/resize 必须节流或防抖
4. 焦点委托用 focusin/focusout
5. keypress 已废弃，用 keydown

### 踩坑记录

```text
坑 1：scroll 未节流导致卡顿
结论：滚动时页面卡顿、掉帧。
原因：scroll 高频触发，直接处理重活。
解法：节流处理，或用 IntersectionObserver。

坑 2：input 与 change 时机混淆
结论：想失焦后再处理，却用了 input 实时触发。
原因：input 每次输入都触发，change 才失焦触发。
解法：实时用 input，确认用 change。

坑 3：移动端同时触发 touch 和 mouse
结论：点击触发两次事件。
原因：浏览器模拟鼠标事件 + 触摸事件。
解法：用 pointer 系列统一，或判断 pointerType。

坑 4：focus 委托无效
结论：在父容器委托 focus 不触发。
原因：focus 不冒泡。
解法：用 focusin（冒泡）。

坑 5：resize 监听在移动端误触发
结论：移动端地址栏伸缩触发 resize。
原因：视口高度变化触发 resize。
解法：用 ResizeObserver 监听具体元素，或注意视口判断。
```

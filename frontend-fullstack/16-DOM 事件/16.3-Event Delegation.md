## 概述

事件委托（Event Delegation）把事件监听器绑定在**父元素**上，利用**事件冒泡**统一处理所有子元素的事件。它解决了动态节点的监听问题，并大幅减少监听器数量。

```text
事件委托的核心思想：
1. 不在每个子元素上绑监听器
2. 只在共同的父元素上绑一次
3. 利用冒泡，子元素的事件冒到父元素
4. 在父元素里判断 e.target 是哪个子元素
```

```js
// 传统：每个按钮都绑监听器（按钮多则监听器多）
document.querySelectorAll('.btn').forEach(btn => {
  btn.addEventListener('click', handleClick);
});

// 事件委托：只绑一次在父容器
document.querySelector('.container').addEventListener('click', (e) => {
  if (e.target.matches('.btn')) {
    handleClick(e);
  }
});
```

## 事件委托的原理

事件委托依赖**冒泡机制**：子元素的事件会冒泡到父元素，父元素即可统一处理。

```html
<ul id="list">
  <li class="item">1</li>
  <li class="item">2</li>
  <li class="item">3</li>
</ul>
```

```js
const list = document.querySelector('#list');

list.addEventListener('click', (e) => {
  const item = e.target.closest('.item');   // 找到被点的 li
  if (!item) return;                         // 点的是 ul 本身则忽略
  console.log('点击了', item.textContent);
});
```

```text
委托处理流程：
1. 点击 li → 事件冒泡到 ul
2. ul 的监听器触发
3. 用 e.target.closest('.item') 找到目标 li
4. 判断是否符合条件，执行逻辑
```

## 动态节点的处理

事件委托最大的优势：**动态添加的子节点无需重新绑定监听器**。

```js
// 动态添加的 li 也能被委托处理（无需再绑监听器）
document.querySelector('#add-btn').addEventListener('click', () => {
  const li = document.createElement('li');
  li.className = 'item';
  li.textContent = '新项';
  document.querySelector('#list').append(li);
  // 这个新的 li 自动被上面的委托处理，无需再 addEventListener
});
```

```text
动态节点的对比：
传统绑定 —— 新增节点要重新 addEventListener（易遗漏）
事件委托 —— 新增节点自动纳入（父元素监听器已覆盖）

这是事件委托最核心的价值。
```

## 冒泡机制的作用

事件委托完全依赖冒泡。理解冒泡才能正确使用委托，并处理特殊事件。

```text
冒泡是委托的基础：
1. 子元素事件向上冒泡到父元素
2. 父元素监听器才能捕获到

不冒泡的事件（focus/blur、load、scroll 等）不能直接委托，
需用冒泡版本（focusin/focusout）或捕获阶段。
```

```js
// focus 不冒泡，用 focusin（冒泡）实现委托
container.addEventListener('focusin', (e) => {
  if (e.target.matches('input')) {
    console.log('输入框获得焦点');
  }
});
```

```js
// 需要阻止冒泡时，委托会失效
child.addEventListener('click', (e) => e.stopPropagation());
// 此时父元素的委托监听器收不到该 child 的点击
```

## 应用场景实战

### 场景一：列表操作（编辑/删除）

```js
const list = document.querySelector('#todo-list');

list.addEventListener('click', (e) => {
  const item = e.target.closest('.todo-item');
  if (!item) return;

  if (e.target.matches('.delete-btn')) {
    item.remove();                    // 删除
  } else if (e.target.matches('.edit-btn')) {
    editTodo(item);                   // 编辑
  }
});
```

### 场景二：表格行点击

```js
document.querySelector('tbody').addEventListener('click', (e) => {
  const row = e.target.closest('tr');
  if (!row) return;
  highlightRow(row);                  // 高亮选中的行
});
```

## 最佳实践与踩坑记录

### 最佳实践

1. 列表、表格等重复结构用事件委托，绑定父容器
2. 用 closest 找目标容器，matches 判断具体按钮
3. 动态内容必须用委托（或每次重新绑定）
4. 不冒泡的事件用冒泡版本（focusin）或捕获
5. 委托处理函数尽早 return，过滤无关目标

### 踩坑记录

```text
坑 1：直接判断 e.target 而非 closest
结论：点击子元素（如 li 内的 span），e.target 是 span 而非 li。
原因：e.target 是「最深」的触发元素。
解法：用 e.target.closest('.item') 向上找到目标。

坑 2：动态节点忘绑监听器
结论：新增的按钮点击无反应。
原因：传统绑定只在初始节点上，新增节点没监听器。
解法：用事件委托，或新增后重新绑定。

坑 3：委托中 stopPropagation 失效
结论：子元素 stopPropagation 后父元素委托收不到。
原因：stopPropagation 阻止冒泡，切断了委托链路。
解法：避免在委托场景的子元素上 stopPropagation。

坑 4：focus/blur 委托无效
结论：委托监听 focus 不触发。
原因：focus/blur 不冒泡。
解法：用 focusin/focusout（冒泡版本）。

坑 5：委托监听器绑得太外层
结论：在 document 上委托所有点击，性能与逻辑混乱。
原因：范围过大，每次点击都触发判断。
解法：绑定到「最小公共父容器」，缩小范围。
```

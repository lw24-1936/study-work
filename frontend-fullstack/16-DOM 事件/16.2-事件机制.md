## 概述

DOM 事件有完整的传播机制：事件从根节点**捕获**下行到目标，再**冒泡**上行回根。理解这三个阶段是事件处理（尤其是事件委托）的基础。

```text
事件传播三阶段：
1. 捕获阶段（Capturing）—— 从 window 向下到目标元素
2. 目标阶段（Target）—— 到达目标元素
3. 冒泡阶段（Bubbling）—— 从目标向上回到 window

默认：addEventListener 在冒泡阶段触发（capture: false）。
```

## Capturing / Target / Bubbling 三个阶段

```html
<div id="outer">
  <div id="inner">点击</div>
</div>
```

```js
const outer = document.querySelector('#outer');
const inner = document.querySelector('#inner');

// 冒泡阶段（默认）
outer.addEventListener('click', () => console.log('outer 冒泡'));
inner.addEventListener('click', () => console.log('inner'));

// 捕获阶段（capture: true）
outer.addEventListener('click', () => console.log('outer 捕获'), true);

// 点击 inner 的输出顺序：
// outer 捕获 → inner → outer 冒泡
```

```text
三阶段的执行顺序：
1. 捕获：从外层到目标（outer 捕获先执行）
2. 目标：目标元素上的监听器（按注册顺序）
3. 冒泡：从目标到外层（outer 冒泡后执行）

记忆：先「由上而下」捕获，再「由下而上」冒泡。
```

```js
// 事件对象的阶段信息
element.addEventListener('click', (e) => {
  console.log(e.eventPhase);   // 1捕获 2目标 3冒泡
});
```

## stopPropagation 停止传播

stopPropagation 阻止事件继续传播（捕获或冒泡），但当前元素上的其他监听器仍会执行。

```js
inner.addEventListener('click', (e) => {
  e.stopPropagation();   // 阻止冒泡，outer 收不到
});

outer.addEventListener('click', () => console.log('不会触发'));
```

```js
// 捕获阶段阻止
outer.addEventListener('click', (e) => {
  e.stopPropagation();   // 阻止继续向下捕获，inner 收不到
}, true);
```

```text
stopPropagation 的作用：
1. 阻止冒泡 —— 内层处理完后不让外层再处理
2. 阻止捕获 —— 外层拦截，不让事件继续下行

注意：只阻止「传播」，不影响当前元素上的其他监听器。
```

## stopImmediatePropagation

stopImmediatePropagation 更彻底：阻止传播，且阻止**同一元素上的其他监听器**执行。

```js
inner.addEventListener('click', () => console.log('监听器 1'));
inner.addEventListener('click', (e) => {
  e.stopImmediatePropagation();
  console.log('监听器 2');
});
inner.addEventListener('click', () => console.log('不会触发'));

// 点击只输出：监听器 1、监听器 2
```

```text
stopPropagation vs stopImmediatePropagation：
stopPropagation —— 阻止传播到其他元素，当前元素其他监听器照常
stopImmediatePropagation —— 阻止传播 + 当前元素后续监听器也不执行
```

## preventDefault 阻止默认行为

preventDefault 阻止浏览器的默认行为（链接跳转、表单提交、右键菜单等），但不阻止事件传播。

```js
// 阻止链接跳转
link.addEventListener('click', (e) => {
  e.preventDefault();
  // 自定义处理
});

// 阻止表单提交
form.addEventListener('submit', (e) => {
  e.preventDefault();   // 不刷新页面
  // Ajax 提交
});

// 阻止右键菜单
document.addEventListener('contextmenu', (e) => e.preventDefault());
```

```text
preventDefault vs stopPropagation：
preventDefault —— 阻止「默认行为」（跳转、提交），不影响传播
stopPropagation —— 阻止「事件传播」，不影响默认行为

二者独立，可同时使用。
```

## passive / once / capture 选项

addEventListener 第三个参数支持选项对象，控制监听器行为。

```js
// once：只触发一次，自动移除
element.addEventListener('click', handler, { once: true });

// passive：不调用 preventDefault（性能优化，滚动更流畅）
element.addEventListener('touchstart', handler, { passive: true });

// capture：在捕获阶段触发
element.addEventListener('click', handler, { capture: true });
```

```text
三个选项：
once —— 触发一次后自动移除
passive —— 声明不调用 preventDefault，浏览器可优化（滚动流畅）
capture —— 在捕获阶段触发（等价第三个参数 true）

passive 的价值：触摸/滚动事件默认 passive 化，避免阻塞滚动。
```

```js
// 组合使用
element.addEventListener('click', handler, {
  once: true,
  capture: true,
});
```

## 应用场景实战

### 场景一：阻止表单默认提交

```js
form.addEventListener('submit', async (e) => {
  e.preventDefault();                    // 阻止刷新
  const data = new FormData(form);
  await fetch('/api/submit', { method: 'POST', body: data });
});
```

### 场景二：阻止事件继续传播

```js
// 弹窗内部点击不触发展开层
modal.addEventListener('click', (e) => {
  e.stopPropagation();   // 阻止冒泡到 document
});
document.addEventListener('click', () => closeModal());
```

## 最佳实践与踩坑记录

### 最佳实践

1. 默认用冒泡阶段（capture: false），除非需要拦截
2. 阻止默认行为用 preventDefault，阻止传播用 stopPropagation
3. 滚动/触摸事件加 passive: true 优化性能
4. 一次性监听用 once: true
5. 理解三阶段顺序，事件委托依赖冒泡

### 踩坑记录

```text
坑 1：preventDefault 与 stopPropagation 混淆
结论：想阻止跳转却用了 stopPropagation，跳转仍发生。
原因：两者作用不同，preventDefault 阻止行为，stopPropagation 阻止传播。
解法：阻止默认行为用 preventDefault。

坑 2：passive 监听器里 preventDefault 无效
结论：passive: true 的监听器里 preventDefault 被忽略。
原因：passive 声明不阻止默认行为，浏览器忽略该调用。
解法：需要 preventDefault 就别用 passive。

坑 3：捕获与冒泡顺序理解错
结论：预期内层先执行，实际外层先执行。
原因：capture: true 的监听器在捕获阶段先触发。
解法：理解「先捕获后冒泡」。

坑 4：stopPropagation 不影响当前元素其他监听器
结论：以为 stopPropagation 后当前元素其他监听器也不执行。
原因：它只阻止传播，当前元素监听器照常。
解法：需要彻底停止用 stopImmediatePropagation。

坑 5：在 passive 默认的滚动里 preventDefault 报错
结论：控制台报 Unable to preventDefault。
原因：touch/wheel 等默认 passive，不能 preventDefault。
解法：需要阻止滚动时，显式 passive: false。
```

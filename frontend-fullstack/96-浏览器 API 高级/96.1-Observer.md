## 概述

Observer 是浏览器提供的一组「观察者」API，用于异步监听 DOM 变化、尺寸变化、可见性变化和性能数据，替代了过去靠事件或轮询实现的笨办法。它们共用一个模式：new 一个 Observer、observe 目标、回调里处理变化、不需要时 disconnect。相比 Mutation Events（已废弃）和轮询，Observer 异步批量、性能更好。

```text
四种 Observer 的职责：
1. MutationObserver —— 监听 DOM 树的变化（增删节点、改属性）
2. ResizeObserver —— 监听元素尺寸变化
3. IntersectionObserver —— 监听元素进出视口
4. PerformanceObserver —— 监听性能条目（mark/measure/资源/长任务）
```

```js
// Observer 的通用使用模式
const observer = new SomeObserver(callback);  // 1. 创建，传回调
observer.observe(target, options);            // 2. 观察目标
// ... 变化时回调异步批量触发
observer.disconnect();                        // 3. 停止观察
```

## MutationObserver

MutationObserver 监听 DOM 树的增删改：子节点变化、属性变化、文本内容变化。它异步批量触发，替代已废弃的同步 Mutation Events（DOMNodeInserted 等），用于监听第三方库或框架对 DOM 的改动。

```js
// 监听目标节点的子节点增删与属性变化
const target = document.querySelector('#list');

const mo = new MutationObserver((mutations) => {
  for (const m of mutations) {
    if (m.type === 'childList') {
      console.log('增删了', m.addedNodes.length, '个新增，', m.removedNodes.length, '个移除');
    } else if (m.type === 'attributes') {
      console.log('属性变化', m.attributeName);
    }
  }
});

mo.observe(target, {
  childList: true,        // 监听子节点增删
  attributes: true,       // 监听属性变化
  subtree: true,          // 监听整棵子树
  attributeFilter: ['class', 'style'], // 只监听指定属性
});

// 触发：target.appendChild(document.createElement('div'));
// 停止：mo.disconnect();
```

```text
MutationObserver 的要点：
1. 异步批量 —— 多次变更合并成一次回调，性能好
2. 配置项 —— childList/attributes/characterData/subtree
3. 替代旧 API —— 取代 Mutation Events
4. 用途 —— 监听第三方 DOM 改动、实现微前端隔离、水印防篡改
```

## ResizeObserver

ResizeObserver 监听元素内容盒尺寸变化，回调能拿到新尺寸。它比 window.resize 精细（监听单个元素而非整个窗口），用于图表自适应、容器尺寸驱动的布局。

```js
// 监听元素尺寸变化，触发重绘
const chart = document.querySelector('#chart');

const ro = new ResizeObserver((entries) => {
  for (const entry of entries) {
    const { width, height } = entry.contentRect;
    console.log('新尺寸:', width, 'x', height);
    redrawChart(width, height);
  }
});

ro.observe(chart);
// 停止：ro.unobserve(chart); 或 ro.disconnect();
```

```text
ResizeObserver 的要点：
1. 监听单元素 —— 比 window.resize 更精细
2. 内容盒尺寸 —— contentRect 不含 padding/border
3. 初始触发 —— observe 时会先触发一次回调，拿到初始尺寸
4. 用途 —— 图表自适应、响应式组件、容器查询兜底
```

## IntersectionObserver

IntersectionObserver 监听元素与视口（或指定根容器）的交叉状态，判断元素是否可见、可见比例多少。它是懒加载、无限滚动、曝光埋点的标准实现，性能远好于 scroll 轮询。

```js
// 懒加载：图片进入视口才加载
const imgs = document.querySelectorAll('img[data-src]');

const io = new IntersectionObserver((entries) => {
  entries.forEach(entry => {
    if (entry.isIntersecting) {
      const img = entry.target;
      img.src = img.dataset.src;
      io.unobserve(img);          // 加载完停止观察
    }
  });
}, {
  root: null,        // 默认视口
  rootMargin: '0px 0px 100px 0px', // 提前 100px 触发
  threshold: 0,      // 刚露头就触发
});

imgs.forEach(img => io.observe(img));
```

```text
IntersectionObserver 的要点：
1. 交叉判断 —— isIntersecting 表示是否可见
2. threshold —— 可见比例阈值，0~1 可配多档
3. rootMargin —— 提前/延后触发，预加载用
4. 用途 —— 懒加载、无限滚动、曝光埋点、吸顶
```

## PerformanceObserver

PerformanceObserver 监听性能条目（PerformanceEntry），覆盖 mark/measure、资源加载、绘制时机、长任务等。它替代手动轮询 performance.getEntries，是新性能数据流的入口。

```js
// 监听三类性能条目
const po = new PerformanceObserver((list) => {
  for (const entry of list.getEntries()) {
    console.log(entry.entryType, entry.name, entry.startTime);
  }
});

po.observe({ entryTypes: ['mark', 'measure', 'resource'] });
// 或用 buffered 拿历史条目：po.observe({ type: 'paint', buffered: true });
```

```text
PerformanceObserver 的要点：
1. 监听性能条目 —— mark/measure/resource/paint/longtask 等
2. buffered —— 设 true 能拿到 observe 之前的历史条目
3. 异步回调 —— 与 Performance Timeline 解耦
4. 用途 —— 采集 Web Vitals、监控长任务、自定义打点
```

## 应用场景实战

### 场景一：图片懒加载 + 无限滚动组合

```js
// 一个完整的懒加载 + 触底加载实现
const feed = document.querySelector('#feed');
const sentinel = document.querySelector('#sentinel');

// 1. 图片懒加载
const lazyIO = new IntersectionObserver((entries) => {
  entries.forEach(e => {
    if (e.isIntersecting) {
      e.target.src = e.target.dataset.src;
      lazyIO.unobserve(e.target);
    }
  });
});
document.querySelectorAll('img[data-src]').forEach(img => lazyIO.observe(img));

// 2. 触底加载更多
const loadIO = new IntersectionObserver((entries) => {
  if (entries[0].isIntersecting) loadMore();
});
loadIO.observe(sentinel);

function loadMore() {
  // 请求下一页数据，追加 DOM，新图片继续交给 lazyIO 观察
  fetchNextPage().then(items => {
    items.forEach(item => {
      const img = document.createElement('img');
      img.dataset.src = item.url;
      feed.appendChild(img);
      lazyIO.observe(img);
    });
  });
}
```

### 场景二：图表容器自适应

```js
// 图表随容器尺寸变化自动重绘
import * as echarts from 'echarts';

const container = document.querySelector('#chart');
const chart = echarts.init(container);

// 用 ResizeObserver 监听容器，替代 window.resize + 防抖
const ro = new ResizeObserver((entries) => {
  for (const entry of entries) {
    chart.resize({ width: entry.contentRect.width, height: entry.contentRect.height });
  }
});
ro.observe(container);

// 组件销毁时清理
// chart.dispose(); ro.disconnect();
```

## 兼容性与选型

### 兼容性

| API | Chrome | Firefox | Safari | 兼容策略 |
| --- | --- | --- | --- | --- |
| MutationObserver | 26+ | 14+ | 7+ | 全绿，无需 polyfill |
| IntersectionObserver | 51+ | 55+ | 12.1+ | IE 不支持，用 intersection-observer polyfill |
| ResizeObserver | 64+ | 69+ | 13.1+ | IE 不支持，用 resize-observer-polyfill |
| PerformanceObserver | 52+ | 57+ | 11+ | IE 不支持，新 entryType 要按需探测 |

```text
兼容注意：
1. 老浏览器 —— MutationObserver 最稳，IntersectionObserver/ResizeObserver 需 polyfill
2. 特性探测 —— 用 'IntersectionObserver' in window 判断，别直接 new
3. ResizeObserver 早期实现 —— 旧 Safari 只支持 callback 参数，无 observe 对象语义
4. polyfill 局限 —— resize polyfill 用 scroll 事件模拟，性能不如原生
```

### 选型：何时用哪个

```text
选型决策：
1. 监听 DOM 结构/属性变化 —— MutationObserver，别无他选
2. 元素进/出视口、懒加载、曝光埋点 —— IntersectionObserver
3. 元素尺寸变化驱动布局/图表 —— ResizeObserver（不是 window.resize）
4. 采集性能数据 —— PerformanceObserver
5. 场景重叠时 —— 懒加载 + 无限滚动都用 IntersectionObserver，一个实例即可
```

```text
常见混淆：
1. ResizeObserver vs window.resize —— 前者监听单元素，后者监听视口，别用 resize 模拟元素变化
2. IntersectionObserver vs scroll 轮询 —— scroll + getBoundingClientRect 每次滚动都强制重排，IO 是异步批量
3. MutationObserver vs 定时器 —— 轮询 DOM 有延迟且耗性能，MO 事件驱动更实时
```

## 最佳实践与踩坑记录

### 最佳实践

1. 用完 unobserve/disconnect，避免回调长期持有引用造成泄漏
2. 懒加载用 rootMargin 提前触发，别等元素完全可见才加载
3. 观察大量元素时用一个 Observer 实例观察所有目标，别每个元素 new 一个
4. PerformanceObserver 设 buffered: true 拿历史条目，避免漏掉早期数据
5. 监听第三方 DOM 改动用 MutationObserver，别用定时器轮询

### 踩坑记录

```text
坑 1：ResizeObserver 循环触发
结论：回调里修改尺寸，触发新回调，报 ResizeObserver loop limit exceeded。
原因：observe 的元素尺寸变化 -> 回调改尺寸 -> 再触发，死循环。
解法：回调里别改被观察元素自身的尺寸，或用 requestAnimationFrame 延迟。

坑 2：忘记 unobserve 懒加载图片
结论：图片加载完成后 Observer 仍持有引用，观察对象越来越多。
原因：没在加载完成后 unobserve，回调反复触发空转。
解法：加载完成立即 io.unobserve(img)。

坑 3：MutationObserver 监听 subtree 性能开销大
结论：大页面监听整个 subtree 导致卡顿。
原因：subtree: true 时任何深层变更都触发回调，变更频繁时开销大。
解法：缩小观察范围，或精确配置 attributeFilter 减少回调。

坑 4：PerformanceObserver 漏掉早期条目
结论：observer 建立之前的性能数据拿不到。
原因：默认只拿 observe 之后产生的条目。
解法：加 buffered: true 获取历史缓冲条目。

坑 5：IntersectionObserver 未设置 root 导致误判
结论：在滚动容器里判断可见性出错。
原因：默认 root 是视口，滚动容器内需要显式指定 root 为该容器。
解法：滚动容器场景显式传 root: scrollContainer。

坑 6：ResizeObserver 不监听 display:none 到显示的变化
结论：元素从 display:none 切回显示时，回调不触发，尺寸拿不到。
原因：display:none 时元素无布局盒子，RO 不产生条目。
解法：显示后先读 getBoundingClientRect 手动初始化，再交给 RO 持续监听。
```

## 概述

Vite 插件基于 Rollup 插件体系扩展而来，同时增加了 Vite 特有的服务端钩子（configureServer、handleHotUpdate 等）。一个 Vite 插件就是一个带 name 和若干钩子的对象。

```text
Vite 插件要点：
1. 兼容大部分 Rollup 插件钩子
2. 新增 Vite 独有的服务端钩子
3. 插件必须声明唯一 name
4. 通过 enforce 控制执行顺序（pre/normal/post）
5. 钩子内用 this 访问插件上下文
```

```js
// 最小 Vite 插件
export default function myPlugin() {
  return {
    name: 'my-plugin',
    enforce: 'pre',
    transform(code, id) {
      if (id.endsWith('.vue')) {
        return code.replace(/__BUILD__/g, '2026-08-13');
      }
    },
  };
}
```

## Plugin API

Vite 插件 API 分为「通用钩子」（继承自 Rollup）与「Vite 专属钩子」。通过 config 钩子还能读取/修改用户配置。

```text
通用钩子（Rollup 兼容）：
transform / load / resolveId / buildStart / generateBundle 等

Vite 专属钩子：
config / configResolved / configureServer / handleHotUpdate
transformIndexHtml / configurePreviewServer
```

```js
export default function plugin() {
  return {
    name: 'demo',
    config(config) {
      // 读取或修改用户配置
      return { define: { __FLAG__: JSON.stringify(true) } };
    },
    configResolved(resolvedConfig) {
      console.log('最终配置', resolvedConfig.root);
    },
  };
}
```

## transform

transform 是核心钩子，对模块源码做转换（编译 TS、注入代码等）。返回 code（新代码）和 map（sourcemap）。

```js
export default function addBanner() {
  return {
    name: 'add-banner',
    transform(code, id) {
      if (!id.endsWith('.js')) return null;
      return {
        code: `/* banner: ${id} */\n${code}`,
        map: null,
      };
    },
  };
}
```

```text
transform 要点：
1. 返回 { code, map } 或 null（不处理）
2. 可用 this.getModuleInfo 获取模块信息
3. 字符串返回值等价于 { code: 返回值 }
```

## resolveId

resolveId 钩子自定义模块解析，把导入的模块 id 解析为真实路径或虚拟模块 id。

```js
export default function virtualModule() {
  const virtualId = 'virtual:message';
  return {
    name: 'virtual-module',
    resolveId(id) {
      if (id === virtualId) return '\0' + virtualId; // 虚拟模块约定前缀
    },
    load(id) {
      if (id === '\0' + virtualId) return `export default 'hello from virtual module'`;
    },
  };
}
```

```js
// 业务代码
import message from 'virtual:message';
console.log(message); // hello from virtual module
```

```text
resolveId 要点：
1. 返回绝对路径表示解析成功
2. 虚拟模块用 '\0' 前缀标记
3. 与 load 配合创建虚拟模块
```

## load

load 钩子加载模块内容，通常在 resolveId 之后执行。可用于虚拟模块返回源码，或替换某些文件的加载结果。

```js
export default function loadText() {
  return {
    name: 'load-text',
    load(id) {
      if (id.endsWith('.text.js')) {
        return `export default '${id.split('/').pop()} loaded'`;
      }
    },
  };
}
```

```text
load 与 transform 区别：
load —— 决定「模块从哪来、原始内容是什么」
transform —— 对已有内容「做转换」
```

## configureServer

configureServer 是 Vite 专属钩子，在开发服务器启动时执行，可添加自定义中间件、监听服务器事件。

```js
export default function apiMock() {
  return {
    name: 'api-mock',
    configureServer(server) {
      // 添加自定义中间件
      server.middlewares.use('/mock', (req, res) => {
        res.setHeader('Content-Type', 'application/json');
        res.end(JSON.stringify({ data: 'mock' }));
      });
    },
  };
}
```

```text
configureServer 要点：
1. 在 dev server 创建后调用
2. 通过 server.middlewares 加中间件
3. 可用 server.ws 操作 WebSocket
```

## handleHotUpdate

handleHotUpdate 是 Vite 专属钩子，自定义 HMR 行为：决定哪些模块受文件变更影响，可返回新模块数组或空数组跳过默认处理。

```js
export default function customHmr() {
  return {
    name: 'custom-hmr',
    handleHotUpdate({ file, modules, server }) {
      // 对特定文件自定义 HMR 范围
      if (file.endsWith('.global.css')) {
        server.ws.send({ type: 'full-reload' }); // 全量刷新
        return [];                                 // 跳过默认模块更新
      }
      return modules; // 默认行为
    },
  };
}
```

```text
handleHotUpdate 要点：
1. 接收 { file, modules, server, timestamp }
2. 返回 [] 表示已手动处理
3. 可发送自定义 WebSocket 消息
```

## 应用场景实战

### 场景一：虚拟环境配置模块插件

```js
// 插件：虚拟 'virtual:env' 模块
export default function envPlugin(env) {
  const virtualId = 'virtual:env';
  return {
    name: 'virtual-env',
    resolveId(id) {
      if (id === virtualId) return '\0' + virtualId;
    },
    load(id) {
      if (id === '\0' + virtualId) {
        return `export default ${JSON.stringify(env)}`;
      }
    },
  };
}

// vite.config.js
import { defineConfig } from 'vite';
import envPlugin from './plugins/env-plugin';
export default defineConfig({ plugins: [envPlugin({ api: '/api', env: 'dev' })] });
```

### 场景二：开发接口 Mock 中间件

```js
export default function mockPlugin() {
  return {
    name: 'mock',
    configureServer(server) {
      server.middlewares.use('/api/user', (req, res) => {
        res.setHeader('Content-Type', 'application/json');
        res.end(JSON.stringify({ id: 1, name: 'Alice' }));
      });
    },
  };
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. 插件 name 必须唯一，便于调试定位
2. 用 enforce 控制执行顺序，避免与其他插件冲突
3. 虚拟模块用 '\0' 前缀约定
4. transform 返回 null 表示不处理该模块
5. handleHotUpdate 返回 [] 时要确保已手动处理，否则 HMR 丢失

### 踩坑记录

```text
坑 1：插件未声明 name
结论：Vite 报错要求插件必须有 name。
原因：Vite 校验插件结构，缺 name 会警告/报错。
解法：每个插件返回对象必须含 name。

坑 2：transform 顺序导致结果被覆盖
结论：插件转换没生效，被其他插件覆盖。
原因：多个插件 transform 链式执行，顺序错误。
解法：用 enforce: 'pre' 提升优先级。

坑 3：虚拟模块未加 \0 前缀
结论：resolveId 返回虚拟路径但 load 收不到。
原因：虚拟模块需 '\0' 前缀标记，否则被当真实文件。
解法：resolveId 返回 '\0' + id，load 里匹配同前缀。

坑 4：configureServer 中间件顺序
结论：mock 中间件没拦截到请求。
原因：中间件注册顺序在 Vite 内部中间件之后。
解法：用 server.middlewares.use 正确位置，或 return 函数在内部中间件前注册。

坑 5：handleHotUpdate 返回 [] 导致无更新
结论：文件改了但页面没反应。
原因：返回 [] 跳过了默认 HMR，又没手动触发更新。
解法：返回 [] 前手动发送 full-reload 或精确更新消息。
```

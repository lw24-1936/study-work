## 概述

Vite 优化分为开发态优化（依赖预构建、按需编译）与生产态优化（分包、资源处理、压缩）。核心目标是让开发更快、产物更优、缓存更高效。

```text
Vite 优化全景：
1. Dependency Optimization —— 预构建依赖，加速开发
2. Chunking —— 分包策略，优化加载与缓存
3. Asset Handling —— 静态资源处理与内联
4. CSS Code Splitting —— CSS 按 chunk 分割
5. Build Target —— 目标浏览器语法级别
```

```text
优化目标：
开发态 —— 冷启动快、HMR 快
生产态 —— 首屏快、缓存好、体积小
```

## Dependency Optimization

依赖优化（预构建）把 node_modules 的依赖用 esbuild 预打包成少量 ESM 文件，解决兼容性与请求数问题，显著加速开发冷启动。

```js
export default {
  optimizeDeps: {
    include: ['lodash-es', 'antd'],        // 强制预构建
    exclude: ['@my-workspace/pkg'],        // 排除（workspace 本地包）
    esbuildOptions: {
      target: 'es2020',
      plugins: [],                          // esbuild 插件
    },
  },
};
```

```text
预构建解决的问题：
1. CommonJS → ESM 兼容转换
2. 数百个小文件合并为少数文件，减少请求
3. 结果缓存，二次启动复用
```

## Chunking

Chunking（分包）把产物拆成多个 chunk，通过 manualChunks 手动分组或让 Rollup 自动分割，优化缓存与并行加载。

```js
export default {
  build: {
    rollupOptions: {
      output: {
        manualChunks: {
          vue: ['vue', 'vue-router', 'pinia'],
          ui: ['ant-design-vue'],
          utils: ['lodash-es', 'dayjs', 'axios'],
        },
      },
    },
  },
};
```

```js
// 或按函数动态分包
manualChunks(id) {
  if (id.includes('node_modules')) {
    if (id.includes('vue')) return 'vue';
    return 'vendor';
  }
}
```

```text
分包策略：
1. 框架代码单独分包（变更少，缓存久）
2. 大库独立分包（并行加载）
3. 业务代码按路由懒加载分包
```

## Asset Handling

Asset Handling 处理图片、字体等静态资源：小于 assetsInlineLimit 的资源内联为 base64，大资源输出为独立文件并带 hash。

```js
export default {
  build: {
    assetsInlineLimit: 4096,               // 小于 4KB 内联
    assetsDir: 'assets',                   // 资源输出目录
    rollupOptions: {
      output: {
        assetFileNames: 'assets/[name].[hash][extname]',
        chunkFileNames: 'js/[name].[hash].js',
        entryFileNames: 'js/[name].[hash].js',
      },
    },
  },
};
```

```text
Asset 处理策略：
1. 小图标（< 4KB）内联，减少请求
2. 大图走文件 + hash，利于缓存
3. 字体/图片按类型分目录输出
```

## CSS Code Splitting

CSS 代码分割让每个异步 chunk 的 CSS 独立成文件，按需加载对应样式，避免一次性加载全部 CSS。默认开启（cssCodeSplit: true）。

```js
export default {
  build: {
    cssCodeSplit: true,          // 开启 CSS 分割（默认）
    cssTarget: 'chrome80',
  },
};
```

```text
CSS 分割行为：
1. 异步 chunk 的 CSS 单独输出
2. 加载该 chunk 时自动加载对应 CSS
3. 关闭后所有 CSS 合并成一个文件
```

```text
何时关闭 cssCodeSplit：
1. CSS 总量很小，合并更省请求
2. 特殊场景需要统一 CSS 加载顺序
```

## Build Target

Build Target 指定产物的目标浏览器语法级别，影响转译与 polyfill 策略。默认 'modules'（支持原生 ESM 的浏览器）。

```js
export default {
  build: {
    target: 'es2015',           // 兼容旧浏览器
    minify: 'esbuild',          // esbuild/terser/自定义
    cssTarget: 'chrome61',
  },
};
```

```text
target 取值：
'modules' —— 支持原生 ESM 的现代浏览器（默认）
'es2015' / 'es2017' 等 —— 指定 ECMAScript 版本
'chrome80' 等 —— 指定具体浏览器版本
```

```text
兼容旧浏览器：
1. 降低 target 到 es2015
2. 配合 @vitejs/plugin-legacy 生成降级产物
3. 注意 esbuild 只做语法降级，不注入 polyfill
```

## 应用场景实战

### 场景一：大型应用完整优化配置

```js
import { defineConfig } from 'vite';
import vue from '@vitejs/plugin-vue';

export default defineConfig({
  plugins: [vue()],
  build: {
    target: 'es2018',
    assetsInlineLimit: 8192,
    cssCodeSplit: true,
    rollupOptions: {
      output: {
        manualChunks: {
          vue: ['vue', 'vue-router', 'pinia'],
          ui: ['ant-design-vue'],
          chart: ['echarts'],
        },
        assetFileNames: 'assets/[name].[hash][extname]',
      },
    },
  },
  optimizeDeps: {
    include: ['echarts', 'ant-design-vue'],
  },
});
```

### 场景二：兼容旧浏览器

```js
import legacy from '@vitejs/plugin-legacy';

export default defineConfig({
  plugins: [
    legacy({ targets: ['defaults', 'not IE 11'] }),
  ],
  build: { target: 'es2015' },
});
```

## 最佳实践与踩坑记录

### 最佳实践

1. 大依赖加入 optimizeDeps.include 提前预构建
2. 框架与 UI 库独立分包，最大化缓存复用
3. 小图标走内联，大资源走文件 hash
4. CSS 分割保持开启，按需加载样式
5. target 按真实用户浏览器范围设定，不过度降级

### 踩坑记录

```text
坑 1：预构建漏掉动态引入的依赖
结论：运行时动态 import 的依赖报错需 reload。
原因：optimizeDeps 静态分析未覆盖动态路径。
解法：把动态依赖显式加入 optimizeDeps.include。

坑 2：manualChunks 拆分过细
结论：HTTP 请求数暴增，加载反而变慢。
原因：chunk 拆分粒度过细，每个小文件一次请求。
解法：按「变更频率」分组，而非按模块细分。

坑 3：assetsInlineLimit 过大
结论：JS 体积膨胀，解析变慢。
原因：大量资源内联 base64，体积增 33%。
解法：内联阈值控制在 4~8KB。

坑 4：CSS 分割与加载顺序问题
结论：样式闪烁或覆盖顺序错乱。
原因：异步 chunk 的 CSS 加载时机导致顺序变化。
解法：关键路径样式内联或统一入口引入。

坑 5：target 降级但未配 legacy 插件
结论：旧浏览器仍无法运行。
原因：esbuild 只降级语法，不注入 polyfill。
解法：配 @vitejs/plugin-legacy 生成 polyfill 降级产物。
```

## 概述

Vite 通过项目根目录的 vite.config.js（或 .ts）配置构建行为，配置文件用 ESM 语法编写，可依据 mode（development/production）和 command（serve/build）动态配置。

```text
vite.config 要点：
1. 使用 ESM 语法 export default
2. defineConfig 提供类型提示
3. 可用函数形式按 mode/command 条件配置
4. 自动加载 .env 环境变量到 import.meta.env
```

```js
// vite.config.js 基础结构
import { defineConfig } from 'vite';
import vue from '@vitejs/plugin-vue';

export default defineConfig(({ command, mode }) => {
  return {
    plugins: [vue()],
    // 根据环境返回不同配置
    base: mode === 'production' ? '/app/' : '/',
  };
});
```

## vite.config

vite.config 是配置文件的主入口，可以导出对象或函数。函数形式可接收 { command, mode, isSsrBuild, isPreview } 参数。

```js
import { defineConfig } from 'vite';

export default defineConfig({
  root: process.cwd(),       // 项目根目录
  base: '/',                 // 资源公共路径
  publicDir: 'public',       // 静态资源目录
  mode: 'development',       // 构建模式
  envDir: '.',               // 环境变量目录
  logLevel: 'info',
});
```

```text
配置文件查找：
1. 默认读取项目根的 vite.config.js/.ts/.mjs
2. 可用 --config 指定其他路径
3. defineConfig 只做类型提示，无运行时作用
```

## plugins

plugins 数组注册 Vite 插件，插件通过钩子扩展开发服务器与构建流程。官方插件如 @vitejs/plugin-vue、@vitejs/plugin-react 负责框架文件的编译。

```js
import { defineConfig } from 'vite';
import vue from '@vitejs/plugin-vue';
import react from '@vitejs/plugin-react';
import legacy from '@vitejs/plugin-legacy';

export default defineConfig({
  plugins: [
    vue(),
    react(),
    legacy({ targets: ['defaults', 'not IE 11'] }), // 兼容旧浏览器
  ],
});
```

```text
插件类型：
1. 框架插件 —— vue/react/svelte 文件编译
2. 功能插件 —— legacy（兼容）、PWA、检查器
3. 自定义插件 —— 通过钩子扩展流程
```

## resolve

resolve 配置模块解析规则，包括别名、扩展名、主入口字段等。

```js
export default defineConfig({
  resolve: {
    alias: { '@': '/src' },
    extensions: ['.js', '.ts', '.jsx', '.tsx', '.vue'],   // 省略扩展名
    dedupe: ['vue'],                                        // 强制单一实例
    mainFields: ['module', 'jsnext:main', 'jsnext'],
  },
});
```

```text
resolve 常见项：
alias —— 路径别名
extensions —— 导入时省略的扩展名
dedupe —— 去重依赖，避免多实例
```

## alias

alias 定义路径别名，简化深层路径的导入。需与 tsconfig 的 paths 保持同步，否则 IDE 与运行时不一致。

```js
import { fileURLToPath, URL } from 'node:url';

export default defineConfig({
  resolve: {
    alias: {
      '@': fileURLToPath(new URL('./src', import.meta.url)),
      '@components': fileURLToPath(new URL('./src/components', import.meta.url)),
    },
  },
});
```

```js
// 业务代码
import Button from '@components/Button.vue'; // 等价于 ./src/components/Button.vue
```

```text
alias 注意：
1. 用 fileURLToPath 保证绝对路径
2. tsconfig.json 同步配 paths
3. HTML 内不支持别名，用相对路径
```

## define

define 在编译期替换全局常量，类似 Webpack 的 DefinePlugin。用于注入版本号、环境标识等。

```js
export default defineConfig({
  define: {
    __APP_VERSION__: JSON.stringify('1.0.0'),
    'process.env.BUILD_TIME': JSON.stringify(new Date().toISOString()),
  },
});
```

```text
define 要点：
1. 值需 JSON.stringify（字符串化）
2. 是编译期文本替换
3. 环境变量默认已暴露为 import.meta.env.VITE_*
```

## server

server 配置开发服务器，包括端口、代理、跨域、热更新等。

```js
export default defineConfig({
  server: {
    port: 5173,               // 端口
    host: '0.0.0.0',          // 允许局域网访问
    open: true,               // 自动打开浏览器
    proxy: {
      '/api': {
        target: 'http://localhost:8080',
        changeOrigin: true,
        rewrite: (path) => path.replace(/^\/api/, ''),
      },
    },
    cors: true,
  },
});
```

```text
server 常见配置：
port/host —— 监听地址
proxy —— 接口代理，解决开发跨域
hmr —— 热更新相关配置
```

## build

build 配置生产构建：输出目录、目标浏览器、压缩、分包等。

```js
export default defineConfig({
  build: {
    outDir: 'dist',             // 输出目录
    target: 'es2015',           // 目标浏览器语法级别
    sourcemap: false,           // 是否生成 sourcemap
    minify: 'esbuild',          // 压缩器（esbuild/terser）
    cssCodeSplit: true,         // CSS 代码分割
    assetsInlineLimit: 4096,    // 小于 4KB 资源内联
    rollupOptions: { output: { manualChunks: { vendor: ['vue'] } } },
  },
});
```

```text
build 关键项：
outDir —— 产物目录
target —— 兼容目标
minify —— 压缩引擎
rollupOptions —— 透传 Rollup 配置
```

## css

css 配置 CSS 处理：预处理器选项、CSS Modules 规则、后处理等。

```js
export default defineConfig({
  css: {
    preprocessorOptions: {
      scss: { additionalData: `@import "@/styles/variables.scss";` },
    },
    modules: { localsConvention: 'camelCase' },
    postcss: './postcss.config.js',
    devSourcemap: true,
  },
});
```

```text
css 配置项：
preprocessorOptions —— 注入 scss/less 全局变量
modules —— CSS Modules 命名规则
postcss —— 指定 postcss 配置
```

## optimizeDeps

optimizeDeps 配置依赖预构建：哪些依赖强制预构建、哪些排除、使用什么转译器。

```js
export default defineConfig({
  optimizeDeps: {
    include: ['lodash-es', 'vue-demi'],   // 强制预构建
    exclude: ['local-package'],           // 排除预构建
    esbuildOptions: { target: 'es2020' },
  },
});
```

```text
optimizeDeps 用途：
1. include 强制预构建，解决自动发现遗漏
2. exclude 排除本地包（link 的 workspace 依赖）
3. esbuildOptions 定制预构建行为
```

## 应用场景实战

### 场景一：Vue 项目完整配置

```js
import { defineConfig } from 'vite';
import vue from '@vitejs/plugin-vue';
import { fileURLToPath, URL } from 'node:url';

export default defineConfig({
  plugins: [vue()],
  resolve: { alias: { '@': fileURLToPath(new URL('./src', import.meta.url)) } },
  server: { port: 3000, proxy: { '/api': 'http://localhost:8080' } },
  css: { preprocessorOptions: { scss: { additionalData: `@use "@/styles/vars.scss" as *;` } } },
  build: { target: 'es2018', rollupOptions: { output: { manualChunks: { vendor: ['vue'] } } } },
});
```

### 场景二：多环境变量注入

```js
// .env.development
// VITE_API_BASE=http://localhost:8080

export default defineConfig(({ mode }) => {
  const env = { development: 'dev', production: 'prod' }[mode] || 'dev';
  return {
    define: { __ENV__: JSON.stringify(env) },
    server: { port: mode === 'development' ? 3000 : 8080 },
  };
});
```

## 最佳实践与踩坑记录

### 最佳实践

1. 用 defineConfig 获得类型提示
2. alias 用 fileURLToPath 生成绝对路径，并同步 tsconfig
3. 环境变量用 VITE_ 前缀暴露给前端
4. 依赖预构建 include 显式声明大依赖
5. 生产分包用 manualChunks 优化缓存

### 踩坑记录

```text
坑 1：alias 配置后 IDE 报找不到模块
结论：运行时正常，但 TS/IDE 红波浪线。
原因：tsconfig.json 未同步 paths 配置。
解法：tsconfig 的 compilerOptions.paths 配相同别名。

坑 2：define 值未字符串化
结论：替换后代码报变量未定义。
原因：define 做文本替换，非字符串被当标识符。
解法：值统一 JSON.stringify。

坑 3：proxy 未配 changeOrigin
结论：后端返回 404 或跨域仍失败。
原因：请求头 Host 未重写，后端按 Host 路由失败。
解法：proxy 目标加 changeOrigin: true。

坑 4：scss 全局变量注入失败
结论：组件里用变量报 undefined。
原因：additionalData 的 @use 语法不对或路径错误。
解法：用 @use "... as *" 并确认路径解析正确。

坑 5：生产构建 target 设太低
结论：产物体积大、兼容性差。
原因：target 未匹配实际用户浏览器范围。
解法：按目标用户浏览器设置 target，如 es2015/es2018。
```

## 概述

Vite 是新一代前端构建工具，核心理念是「开发时利用浏览器原生 ESM 按需加载，生产时用 Rollup 打包」。它用 esbuild 做依赖预构建和转译，解决了传统打包器冷启动慢的问题。

```text
Vite 原理核心：
1. Native ESM —— 开发态直接用浏览器原生模块加载
2. Dev Server —— 按需编译，请求哪个文件编译哪个
3. Dependency Pre-Bundling —— 预构建依赖，处理兼容与加速
4. esbuild —— 用 Go 写的高性能转译器
5. Rollup —— 生产构建的打包器
6. HMR —— 精准热更新，只更新变更模块
```

```text
开发 vs 生产：
开发环境：esbuild 转译 + 原生 ESM 按需加载（快）
生产环境：Rollup 打包 + 优化（产物最优）
```

## Native ESM

Vite 开发时直接利用浏览器对 ES Module 的原生支持，不打包源码，浏览器按 import 语句逐模块请求，实现「按需编译」。

```html
<!-- index.html 直接引入模块 -->
<script type="module" src="/src/main.js"></script>
```

```js
// main.js 中浏览器会发起真实的模块请求
import { createApp } from 'vue';   // 请求 /node_modules/.vite/deps/vue.js
import App from './App.vue';        // 请求 /src/App.vue（按需编译）
```

```text
Native ESM 的优势：
1. 无需全量打包，启动即快
2. 修改哪个模块，只重新编译哪个模块
3. 浏览器原生缓存模块请求
```

## Dev Server

Vite 的 Dev Server 是核心，它拦截浏览器发来的模块请求，按需编译后返回。对 .vue/.jsx 等非浏览器原生格式，在请求时动态转译。

```text
Dev Server 工作流程：
1. 浏览器请求 /src/App.vue
2. Dev Server 拦截请求
3. 用插件（vite 的 vue 插件）把 .vue 编译成 JS
4. 返回编译后的 JS 给浏览器
```

```js
// vite.config.js 配置 dev server
export default {
  server: {
    port: 5173,
    host: true,
    proxy: { '/api': { target: 'http://localhost:3000', changeOrigin: true } },
  },
};
```

## Dependency Pre-Bundling

Vite 用 esbuild 把 node_modules 中的依赖「预打包」成单个 ESM 文件（缓存在 .vite/deps），解决两个问题：CommonJS 转 ESM、减少海量小文件的请求数。

```text
预构建的原因：
1. 兼容性 —— 把 CommonJS 依赖转成 ESM
2. 性能 —— 把 lodash 的几百个文件合并成少数几个
3. 缓存 —— 结果缓存在 node_modules/.vite
```

```js
// 优化预构建配置
export default {
  optimizeDeps: {
    include: ['lodash-es'],       // 强制预构建
    exclude: ['some-local-pkg'],  // 排除预构建
  },
};
```

## esbuild

esbuild 是用 Go 语言编写的超高性能转译器/打包器，Vite 用它做依赖预构建和 TS/JSX 转译，速度比传统工具快 10~100 倍。

```text
esbuild 为什么快：
1. Go 编译为原生二进制，无解释器开销
2. 多核并行处理
3. 从头到尾只遍历一次 AST
```

```js
// Vite 内部用 esbuild 转译 TS
// 但 esbuild 不做类型检查，仅做语法降级
export default {
  esbuild: {
    jsxFactory: 'h',
    jsxFragment: 'Fragment',
  },
};
```

## Rollup

Vite 生产构建使用 Rollup，因为 Rollup 的 Tree Shaking 和产物优化能力更强，且生态成熟（插件丰富）。开发态按需加载，生产态打包优化。

```text
Rollup 在 Vite 中的角色：
1. 生产构建（vite build）的核心打包器
2. 成熟的 Tree Shaking 能力
3. 丰富的插件生态（与 Vite 插件体系兼容）
```

```js
// 生产构建配置
export default {
  build: {
    rollupOptions: {
      input: 'index.html',
      output: { manualChunks: { vendor: ['vue', 'vue-router'] } },
    },
  },
};
```

## HMR

Vite 的 HMR（Hot Module Replacement）基于原生 ESM，精确到「变更的模块」做热替换，不重新加载页面，且状态尽量保留。

```text
HMR 工作流程：
1. 监听文件变化
2. 通过 WebSocket 推送变更通知
3. 浏览器只重新请求变更的模块
4. 框架插件（如 vue/react 插件）做状态保留
```

```js
// 模块内自定义 HMR 行为
if (import.meta.hot) {
  import.meta.hot.accept((newModule) => {
    // 热更新接受，用新模块替换
    console.log('模块已热更新', newModule);
  });
}
```

```text
Vite HMR 优势：
1. 精准到模块，不触发整页刷新
2. 修改 CSS 几乎即时生效
3. 配合 Vue/React 插件保留组件状态
```

## 应用场景实战

### 场景一：开发态代理与按需编译

```js
// vite.config.js
import { defineConfig } from 'vite';
import vue from '@vitejs/plugin-vue';

export default defineConfig({
  plugins: [vue()],
  server: {
    port: 5173,
    proxy: { '/api': { target: 'http://localhost:8080', changeOrigin: true } },
  },
  optimizeDeps: { include: ['axios'] },
});
```

### 场景二：生产构建分包

```js
import { defineConfig } from 'vite';

export default defineConfig({
  build: {
    target: 'es2015',
    outDir: 'dist',
    rollupOptions: {
      output: {
        manualChunks: {
          vue: ['vue', 'vue-router', 'pinia'],
          utils: ['lodash-es', 'dayjs'],
        },
      },
    },
  },
});
```

## 最佳实践与踩坑记录

### 最佳实践

1. 开发依赖放 dependencies，确保预构建正确
2. 大依赖用 optimizeDeps.include 提前预构建
3. 生产用 build.rollupOptions 手动分包
4. 利用 import.meta.env 区分环境
5. 保持 Node 版本较新，Vite 对旧版本支持有限

### 踩坑记录

```text
坑 1：新装的依赖提示页面刷新
结论：新增依赖后 Vite 提示需要 reload。
原因：依赖未被预构建缓存，运行时动态发现。
解法：重启 dev server，或手动加入 optimizeDeps.include。

坑 2：CommonJS 依赖在浏览器报错
结论：某些 CJS 包在开发态运行时报错。
原因：部分 CJS 依赖预构建转 ESM 不完全。
解法：加入 optimizeDeps.include 强制预构建。

坑 3：预构建缓存过期导致诡异错误
结论：改了依赖版本但报的还是旧错误。
原因：node_modules/.vite 缓存未失效。
解法：删除 node_modules/.vite 后重启，或 vite --force。

坑 4：HMR 不生效
结论：改代码后页面整页刷新甚至无变化。
原因：模块未导出正确 HMR 边界，或依赖循环。
解法：检查 import.meta.hot 边界，避免循环依赖。

坑 5：路径别名在 HTML 中失效
结论：HTML 里 import 用了别名报错。
原因：HTML 中的模块请求不经 vite 解析别名。
解法：HTML 里用相对路径，别名只在 JS/组件内使用。
```

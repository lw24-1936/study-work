## 概述

Cookie 是最早的浏览器存储机制，由服务端通过 Set-Cookie 设置，浏览器存储后**随每次请求自动发送**给服务端。它是服务端会话管理的基础，但容量小、有安全隐患。

```text
Cookie 的核心特性：
1. 随请求发送 —— 每次 HTTP 请求自动携带
2. 服务端可读 —— 服务端通过 Set-Cookie 设置、通过请求头读取
3. 容量小 —— 单个约 4KB，数量有限
4. 有过期时间 —— 可设置 Expires/Max-Age
5. 属性丰富 —— Domain、Path、Secure、HttpOnly、SameSite
```

```js
// 读取 Cookie
document.cookie;   // 'name=value; token=xxx; theme=dark'

// 写入 Cookie
document.cookie = 'theme=dark; path=/; max-age=86400';
```

## Cookie 基础

Cookie 是键值对字符串，通过 document.cookie 读写。

```js
// 写入（每次只能写一个）
document.cookie = 'username=Alice';

// 多个 Cookie 用分号分隔
document.cookie;   // 'username=Alice; theme=dark'

// 设置过期等属性
document.cookie = 'token=xxx; max-age=3600; path=/';
```

```js
// 封装 Cookie 读写
function setCookie(name, value, options = {}) {
  let cookie = `${encodeURIComponent(name)}=${encodeURIComponent(value)}`;
  if (options.maxAge) cookie += `; max-age=${options.maxAge}`;
  if (options.path) cookie += `; path=${options.path}`;
  if (options.domain) cookie += `; domain=${options.domain}`;
  if (options.secure) cookie += '; secure';
  document.cookie = cookie;
}

function getCookie(name) {
  const match = document.cookie.match(new RegExp(`(?:^|; )${name}=([^;]*)`));
  return match ? decodeURIComponent(match[1]) : null;
}
```

## Domain 与 Path

Domain 和 Path 决定 Cookie 的作用范围（哪些 URL 会携带）。

```text
Domain：
1. 默认 —— 当前域名（不含子域名）
2. 设置 .example.com —— 含子域名（www、api 等）
3. 不能跨域设置（只能设置自己或父域）

Path：
1. 默认 —— 当前路径
2. 设置 / —— 全站所有路径
3. 只有匹配路径的请求才携带
```

```js
// 全站 + 子域名
document.cookie = 'token=xxx; domain=.example.com; path=/';

// 仅 /admin 路径
document.cookie = 'adminToken=yyy; path=/admin';
```

## Expires 与 Max-Age

两者控制 Cookie 的过期时间。

```text
Expires —— 绝对过期时间（GMT 格式）
Max-Age —— 相对过期时间（秒，优先于 Expires）

不设置过期时间 → 会话 Cookie（关闭浏览器即失效）
```

```js
// Max-Age：1 小时后过期
document.cookie = 'token=xxx; max-age=3600';

// Expires：指定日期
const expires = new Date(Date.now() + 3600 * 1000).toUTCString();
document.cookie = `token=xxx; expires=${expires}`;

// 删除 Cookie：设过期时间为过去
document.cookie = 'token=xxx; max-age=0';
```

## Secure 与 HttpOnly

Secure 和 HttpOnly 是重要的安全属性。

```text
Secure：
1. 只在 HTTPS 连接中发送
2. 防止 Cookie 被明文窃听

HttpOnly：
1. 禁止 JavaScript 访问（document.cookie 读不到）
2. 只能通过 HTTP 传输
3. 防止 XSS 窃取 Cookie
```

```js
// Secure：仅 HTTPS 发送
document.cookie = 'token=xxx; secure';

// HttpOnly 只能由服务端设置（JS 无法设置）
// Set-Cookie: token=xxx; HttpOnly; Secure
```

```text
安全最佳实践：
1. 会话 Cookie 必加 HttpOnly（防 XSS 窃取）
2. 敏感 Cookie 加 Secure（防窃听）
3. HttpOnly + Secure 组合最安全
```

## SameSite

SameSite 控制跨站请求是否携带 Cookie，是防 CSRF 的关键属性。

```text
SameSite 三值：
Strict —— 完全禁止跨站携带（最严格）
Lax —— 允许顶级导航（点击链接）跨站携带（默认，推荐）
None —— 允许跨站携带（必须配合 Secure）
```

```js
// Lax：允许顶级导航，阻止跨站子请求
document.cookie = 'token=xxx; sameSite=lax';

// Strict：完全禁止跨站
document.cookie = 'token=xxx; sameSite=strict';

// None：允许跨站（需 Secure）
document.cookie = 'token=xxx; sameSite=none; secure';
```

```text
SameSite 防 CSRF 原理：
CSRF 攻击依赖「跨站请求自动带 Cookie」。
SameSite=Strict/Lax 阻止跨站请求携带 Cookie，从根源阻断 CSRF。
```

## Partitioned Cookie

Partitioned Cookie（CHIPS）让 Cookie 按「顶级站点」隔离，解决第三方 Cookie 的隐私问题。

```text
Partitioned Cookie 的价值：
1. 第三方 Cookie 按顶级站点分区
2. 同一第三方在不同顶级站点下，Cookie 互不可见
3. 既保留嵌入式场景，又保护隐私

设置：Set-Cookie: __Host-name=value; Secure; Path=/; SameSite=None; Partitioned
```

```text
背景：
浏览器逐步淘汰第三方 Cookie（隐私保护），
Partitioned Cookie 是「保留有限第三方能力」的过渡方案。
```

## 应用场景实战

### 场景一：记住登录状态（会话 Cookie）

```js
// 服务端设置 HttpOnly 会话 Cookie
// Set-Cookie: sessionId=abc123; HttpOnly; Secure; SameSite=Lax; Path=/
```

### 场景二：用户偏好（非敏感）

```js
// 主题偏好（非敏感，可 JS 读写）
setCookie('theme', 'dark', { maxAge: 30 * 24 * 3600, path: '/' });
const theme = getCookie('theme');
```

## 最佳实践与踩坑记录

### 最佳实践

1. 会话标识用 HttpOnly + Secure + SameSite=Lax
2. 非敏感偏好用 localStorage，别滥用 Cookie
3. 容量小（4KB），大数据别存 Cookie
4. 删除 Cookie 用 max-age=0 或过期时间
5. 敏感操作依赖 CSRF Token 或 SameSite，不只靠 Cookie

### 踩坑记录

```text
坑 1：HttpOnly Cookie 用 JS 读不到
结论：document.cookie 读不到 HttpOnly Cookie。
原因：HttpOnly 禁止 JS 访问。
解法：HttpOnly 用于会话，非 HttpOnly 用于 JS 可读的偏好。

坑 2：Cookie 容量超限
结论：大数据存 Cookie 失败或被截断。
原因：单个 Cookie 约 4KB，总数有限。
解法：大数据用 localStorage/IndexedDB。

坑 3：SameSite=None 忘加 Secure
结论：SameSite=None 的 Cookie 被浏览器拒绝。
原因：None 必须配合 Secure。
解法：SameSite=None + Secure 一起设置。

坑 4：跨域 Cookie 设置失败
结论：第三方接口 Set-Cookie 不生效。
原因：跨域 Cookie 需要 credentials + CORS 配置。
解法：fetch/axios 设 credentials: 'include'，服务端 CORS 配 allowCredentials。

坑 5：过期时间时区问题
结论：Expires 格式错误导致 Cookie 立即失效。
原因：Expires 需 GMT 格式（toUTCString）。
解法：用 max-age（相对秒），或 toUTCString 转格式。
```

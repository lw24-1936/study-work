## 概述

IndexedDB 是浏览器的**结构化数据库**，支持大容量存储、索引、事务、异步操作。相比 localStorage（键值、5MB、同步），IndexedDB 能存数百 MB 结构化数据，是离线应用的数据基础。

```text
IndexedDB 的特点：
1. 大容量 —— 可达数百 MB
2. 结构化 —— 存对象、支持索引
3. 事务 —— 保证数据一致性
4. 异步 —— 基于事件/回调（不阻塞主线程）
5. 持久化 —— 数据不随会话消失
```

## Database 与 Object Store

数据库包含多个 Object Store（对象仓库，类似表），每个 store 存一类对象。

```js
// 打开数据库
const request = indexedDB.open('myDB', 1);

request.onupgradeneeded = (e) => {
  const db = e.target.result;
  // 创建对象仓库（类似建表）
  const store = db.createObjectStore('users', { keyPath: 'id' });
  store.createIndex('name', 'name', { unique: false });
};

request.onsuccess = (e) => {
  const db = e.target.result;
  console.log('数据库打开成功');
};

request.onerror = (e) => {
  console.error('打开失败', e.target.error);
};
```

```text
Object Store 的概念：
1. 类似关系数据库的「表」
2. 存同类型的对象
3. keyPath —— 指定主键字段（如 id）
4. autoIncrement —— 自动生成主键
```

## Transaction 事务

事务（Transaction）保证一组操作的原子性，读写操作必须在事务中进行。

```js
const db = /* 已打开的数据库 */;

// 开启事务（指定 store 和模式）
const tx = db.transaction('users', 'readwrite');   // 或 'readonly'
const store = tx.objectStore('users');

// 在事务中操作
store.add({ id: 1, name: 'Alice' });

// 事务完成/失败
tx.oncomplete = () => console.log('事务完成');
tx.onerror = (e) => console.error('事务失败', e.target.error);
```

```text
事务的特点：
1. 原子性 —— 事务内操作要么全成功，要么全失败
2. 两种模式 —— readonly（读）、readwrite（读写）
3. 自动提交 —— 所有请求完成自动提交
4. 异步 —— 事务结束后 oncomplete 触发
```

## Index 索引

索引加速按「非主键字段」的查询。

```js
// 创建索引（在 onupgradeneeded 中）
store.createIndex('name', 'name', { unique: false });
store.createIndex('email', 'email', { unique: true });   // 唯一索引

// 用索引查询
const index = store.index('name');
const request = index.get('Alice');           // 按索引值查询
const range = index.getAll(IDBKeyRange.bound('A', 'Z'));   // 范围查询
```

```text
索引的价值：
1. 快速查询 —— 按非主键字段高效查找
2. 唯一约束 —— unique: true 保证唯一
3. 范围查询 —— IDBKeyRange 支持区间
```

## Cursor 游标

游标（Cursor）遍历查询结果，逐条处理。

```js
const store = tx.objectStore('users');
const request = store.openCursor();

request.onsuccess = (e) => {
  const cursor = e.target.result;
  if (cursor) {
    console.log(cursor.key, cursor.value);   // 当前记录
    cursor.continue();                        // 继续下一条
  }
};
```

```js
// 带条件的游标遍历
const index = store.index('name');
const request = index.openCursor(IDBKeyRange.bound('A', 'Z'));
```

```text
游标的用途：
1. 逐条遍历大量数据
2. 条件遍历（范围）
3. 边遍历边处理（删除、更新）
```

## Version Upgrade 版本升级

版本升级（onupgradeneeded）在数据库结构变化时触发，用于建表、建索引、迁移数据。

```js
const request = indexedDB.open('myDB', 2);   // 版本号从 1 升到 2

request.onupgradeneeded = (e) => {
  const db = e.target.result;
  const oldVersion = e.oldVersion;   // 旧版本号

  if (oldVersion < 1) {
    // 首次创建：建 store
    db.createObjectStore('users', { keyPath: 'id' });
  }
  if (oldVersion < 2) {
    // 升级到 2：加新 store 或索引
    db.createObjectStore('orders', { keyPath: 'id' });
  }
};
```

```text
版本升级的要点：
1. 版本号递增（打开时传更大的版本号）
2. onupgradeneeded 中做结构变更
3. 用 oldVersion 判断升级路径
4. 升级中可做数据迁移
```

## Structured Clone 结构化克隆

IndexedDB 用结构化克隆（Structured Clone）存储对象，支持的类型比 JSON 更丰富。

```text
结构化克隆支持的类型：
1. 基本类型 —— 数字、字符串、布尔、null
2. 对象、数组、Map、Set
3. Date、RegExp
4. ArrayBuffer、TypedArray
5. Blob、File

不支持：函数、DOM 节点、Symbol
```

```js
// 可直接存 Date、Map 等（无需手动转换）
store.add({ id: 1, date: new Date(), tags: new Set(['a', 'b']) });
```

```text
Structured Clone vs JSON：
Structured Clone —— 支持更多类型（Date、Map、Blob 等），IndexedDB 原生支持
JSON —— 只支持纯数据，需手动转换

注意：结构化克隆不克隆函数、原型链。
```

## 应用场景实战

### 场景一：离线数据缓存

```js
// 用 Promise 封装 IndexedDB
function openDB(name, version) {
  return new Promise((resolve, reject) => {
    const request = indexedDB.open(name, version);
    request.onupgradeneeded = e => {
      const db = e.target.result;
      db.createObjectStore('cache', { keyPath: 'id' });
    };
    request.onsuccess = () => resolve(request.result);
    request.onerror = () => reject(request.error);
  });
}

async function cacheData(db, data) {
  const tx = db.transaction('cache', 'readwrite');
  tx.objectStore('cache').put(data);
  return new Promise(r => tx.oncomplete = r);
}
```

### 场景二：用 idb 库简化（推荐）

```js
import { openDB } from 'idb';

const db = await openDB('myDB', 1, {
  upgrade(db) {
    db.createObjectStore('users', { keyPath: 'id' });
  },
});

await db.put('users', { id: 1, name: 'Alice' });
const user = await db.get('users', 1);
```

## 最佳实践与踩坑记录

### 最佳实践

1. 原生 API 繁琐，用 idb/Dexie 库封装
2. 事务尽量短，避免长时间持有
3. 用索引加速查询
4. 版本升级做好迁移
5. 大量数据用游标逐条处理，避免一次性加载

### 踩坑记录

```text
坑 1：事务自动结束
结论：事务外的操作报错（事务已结束）。
原因：事务在所有请求完成后自动提交，异步回调里再操作已失效。
解法：在事务作用域内完成操作，或用新事务。

坑 2：onupgradeneeded 中才能建 store
结论：onupgradeneeded 外 createObjectStore 报错。
原因：结构变更只能在版本升级中。
解法：升版本号，在 onupgradeneeded 中建表。

坑 3：键路径（keyPath）设置错误
结论：add 报错或数据异常。
原因：keyPath 与数据不匹配。
解法：确认 keyPath 字段存在且唯一。

坑 4：一次性加载大量数据卡顿
结论：getAll 加载几十万条，卡顿/内存暴涨。
原因：一次性读取全部数据。
解法：用游标分批处理，或分页查询。

坑 5：忽略事务错误
结论：数据写入失败却无感知。
原因：未监听 tx.onerror。
解法：监听 onerror 和 oncomplete。
```

## 概述

RAG（Retrieval-Augmented Generation，检索增强生成）让大模型基于「外部知识」回答问题：先把文档切块、向量化存入知识库，提问时检索最相关的片段，再把这些片段作为上下文喂给模型生成答案。RAG 前端负责这条链路中所有面向用户的部分——上传文档、预览切块、展示检索结果与引用来源。

```text
RAG 前端要覆盖的环节：
1. 文档上传 —— 上传、解析、入库
2. 切块预览 —— 展示文档如何被切分
3. 检索 —— 提问时检索相关片段
4. 引用 —— 标注答案来自哪段文档
5. 来源预览 —— 展示引用片段原文
6. 向量检索 UI —— 可视化检索结果与相似度
```

## Document Upload

Document Upload 是 RAG 的入口：让用户上传文档（PDF、Word、Markdown、文本），前端负责上传、进度反馈、以及解析状态展示。大文件要分片上传，解析是异步的（可能耗时），UI 需要轮询或订阅解析进度，直到文档完成向量化入库。

```text
文档上传要点：
1. 多格式 —— PDF、docx、md、txt 等
2. 分片上传 —— 大文件切片上传，支持断点续传
3. 异步解析 —— 上传后解析入库，需展示进度
4. 状态反馈 —— 排队中 / 解析中 / 已完成 / 失败
```

```tsx
function DocumentUpload({ onUpload }) {
  const [progress, setProgress] = useState(0);
  const [status, setStatus] = useState('idle');

  async function handleFile(file) {
    setStatus('uploading');
    const form = new FormData();
    form.append('file', file);
    const res = await fetch('/api/documents', { method: 'POST', body: form });
    const { id } = await res.json();
    setStatus('processing');
    // 轮询解析进度
    const timer = setInterval(async () => {
      const r = await fetch(`/api/documents/${id}/status`);
      const s = await r.json();
      setProgress(s.progress);
      if (s.status === 'done') { setStatus('done'); clearInterval(timer); }
    }, 1000);
  }

  return <input type="file" onChange={(e) => handleFile(e.target.files[0])} />;
}
```

## Chunk Preview

Chunk Preview 展示文档「被切成了哪些块」：RAG 按一定策略（固定长度、语义分段、滑窗重叠）把长文档切成多个 chunk，切块质量直接影响检索效果。前端提供切块预览，让用户看到切分边界、重叠区域，必要时手动调整切块策略。

```text
切块预览的价值：
1. 可见切分 —— 展示 chunk 边界与重叠
2. 策略可调 —— chunk 大小、重叠长度可配置
3. 质量检查 —— 用户确认切块是否合理
4. 手动修正 —— 合并/拆分不合理的块
```

```tsx
function ChunkPreview({ chunks }) {
  return (
    <div className="chunks">
      {chunks.map((c, i) => (
        <div key={i} className="chunk">
          <div className="chunk-meta">#{i} · {c.tokens} tokens</div>
          <p>{c.text}</p>
        </div>
      ))}
    </div>
  );
}
```

## Retrieval

Retrieval 是 RAG 的核心动作：把用户查询向量化，在向量库中检索相似度最高的 top-K 片段。前端虽然不直接做向量检索（通常在服务端），但要负责触发检索、展示「正在检索相关文档」的状态，并把检索到的片段呈现为引用和上下文来源。

```text
检索环节的要点：
1. 查询向量化 —— 把问题编码成向量
2. 相似度检索 —— 找 top-K 最相似片段
3. 阈值过滤 —— 相似度低于阈值的丢弃
4. 上下文拼接 —— 命中片段拼成上下文喂给模型
```

```ts
// 前端触发检索并拿到相关片段
async function retrieve(query) {
  const res = await fetch('/api/retrieve', {
    method: 'POST',
    headers: { 'content-type': 'application/json' },
    body: JSON.stringify({ query, topK: 5 }),
  });
  const { chunks } = await res.json();
  return chunks; // [{ id, text, score, source }]
}
```

## Citation

Citation（引用）把答案与来源文档关联起来：模型回答时标注引用了哪个 chunk，前端把这些标注渲染成角标，点击能跳到具体来源。引用让 RAG 答案「可信」——用户能看到每句话的依据，也能验证答案是否真的来自文档而非模型编造。

```text
引用的关键点：
1. 来源标注 —— 答案中插入 [1]、[2] 指向具体 chunk
2. 角标渲染 —— 可点击的引用标记
3. 一一对应 —— 每个引用映射到唯一 chunk
4. 可验证 —— 用户能核对答案是否忠于原文
```

```tsx
// 引用角标 + 来源映射
function Answer({ text, sources }) {
  const parts = text.split(/(\[\d+\])/g);
  return (
    <div>
      {parts.map((p, i) => {
        const m = p.match(/^\[(\d+)\]$/);
        return m ? (
          <sup key={i}>
            <a href={`#src-${m[1]}`}>[{m[1]}]</a>
          </sup>
        ) : (
          <span key={i}>{p}</span>
        );
      })}
      <div className="sources">
        {sources.map((s, i) => (
          <div key={i} id={`src-${i + 1}`}>{s.title} — {s.text}</div>
        ))}
      </div>
    </div>
  );
}
```

## Source Preview

Source Preview 展示引用片段的「原文上下文」：点击引用角标后，弹出或展开该 chunk 的完整原文、所在文档、以及命中位置。它把「答案」和「证据」放在一起对照，是 RAG 建立信任和可调试性的关键交互。

```text
来源预览的实现：
1. 原文展示 —— 显示 chunk 完整文本
2. 来源元信息 —— 文档名、页码、命中片段
3. 高亮命中 —— 高亮与查询相关的关键词
4. 对照查看 —— 答案与来源并排对照
```

```tsx
function SourcePreview({ source, onClose }) {
  return (
    <div className="source-preview">
      <div className="source-header">
        <strong>{source.title}</strong>
        <button onClick={onClose}>关闭</button>
      </div>
      <p className="source-text">{source.text}</p>
      <div className="source-meta">相似度 {source.score.toFixed(3)}</div>
    </div>
  );
}
```

## Vector Search UI

Vector Search UI 是向量检索的可视化界面：展示查询向量命中了哪些 chunk、各自的相似度得分，以及向量空间中的聚类关系。它既用于功能演示（让用户看到「语义相似」如何工作），也用于调试（检查为什么某些片段被召回、某些没有）。

```text
向量检索 UI 的要素：
1. 结果列表 —— 命中 chunk 按相似度排序
2. 相似度得分 —— 展示每个结果的 score
3. 高亮命中 —— 标记查询词在结果中的位置
4. 可视化 —— 向量降维后散点展示聚类
```

```tsx
function VectorSearchResults({ results }) {
  return (
    <ul className="search-results">
      {results.map((r) => (
        <li key={r.id}>
          <div className="score-bar">
            <div className="score-fill" style={{ width: `${r.score * 100}%` }} />
          </div>
          <span className="score">{r.score.toFixed(3)}</span>
          <p className="snippet">{highlight(r.text, r.query)}</p>
        </li>
      ))}
    </ul>
  );
}

function highlight(text, query) {
  return text.replace(new RegExp(`(${query})`, 'gi'), '<mark>$1</mark>');
}
```

## 应用场景实战

### 场景一：文档上传到问答的完整流程

```tsx
// 上传文档 → 切块预览 → 提问 → 带引用答案
export default function RAGPage() {
  const [doc, setDoc] = useState(null);
  const [chunks, setChunks] = useState([]);
  const [answer, setAnswer] = useState(null);

  async function upload(file) {
    const form = new FormData();
    form.append('file', file);
    const res = await fetch('/api/documents', { method: 'POST', body: form });
    const { id, chunks } = await res.json();
    setDoc({ id });
    setChunks(chunks);
  }

  async function ask(query) {
    const res = await fetch('/api/ask', {
      method: 'POST',
      headers: { 'content-type': 'application/json' },
      body: JSON.stringify({ docId: doc.id, query }),
    });
    setAnswer(await res.json());
  }

  return (
    <div>
      <input type="file" onChange={(e) => upload(e.target.files[0])} />
      {chunks.length > 0 && <ChunkPreview chunks={chunks} />}
      <AskBar onAsk={ask} />
      {answer && <Answer text={answer.text} sources={answer.sources} />}
    </div>
  );
}
```

### 场景二：语义搜索 + 相似度可视化

```tsx
// 输入查询 → 展示按相似度排序的检索结果
import { useState } from 'react';

export default function SemanticSearch() {
  const [results, setResults] = useState([]);

  async function search(query) {
    const res = await fetch('/api/search', {
      method: 'POST',
      headers: { 'content-type': 'application/json' },
      body: JSON.stringify({ query }),
    });
    setResults((await res.json()).results);
  }

  return (
    <div>
      <input placeholder="语义搜索…" onKeyDown={(e) => e.key === 'Enter' && search(e.target.value)} />
      <VectorSearchResults results={results} />
    </div>
  );
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. 切块策略要可预览、可调，切块质量决定检索质量
2. 检索结果设相似度阈值，低分片段宁缺毋滥
3. 引用必须可追溯到具体 chunk，答案才有可信度
4. 大文档分片上传 + 异步解析，用进度条反馈
5. 展示来源原文，让用户能对照验证答案

### 踩坑记录

```text
坑 1：切块过粗导致检索不准
结论：检索到的片段包含大量无关内容，答案跑偏。
原因：chunk 太大，命中块里有效信息被稀释。
解法：控制 chunk 大小（通常 300-800 token），按语义分段。

坑 2：切块过细丢失上下文
结论：命中片段孤零零一句话，模型看不懂。
原因：chunk 太小，缺少前后文语境。
解法：增加滑窗重叠（overlap），或检索时附带相邻块。

坑 3：引用角标与实际来源对不上
结论：点击 [2] 跳到的片段和答案说的不是一回事。
原因：检索顺序、去重、重排后序号没对齐来源映射。
解法：引用编号统一基于最终来源列表，渲染时按同一数组索引。

坑 4：上传后立即提问得到「找不到相关内容」
结论：文档刚上传，检索不到任何片段。
原因：解析 + 向量化是异步的，入库还没完成。
解法：上传后轮询解析状态，入库完成前禁用提问或提示处理中。

坑 5：相似度阈值设错导致结果为空或噪声
结论：阈值太高检索为空，太低召回一堆无关片段。
原因：没根据 embedding 模型的实际分布标定阈值。
解法：用真实查询抽样标定阈值，按业务精度/召回需求取舍。
```

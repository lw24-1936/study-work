## 概述

AI UI 是围绕「人机对话」构建的前端界面体系：它不只是展示文本，而是要把流式生成、富文本、代码高亮、引用、工具调用状态、推理过程、人工确认等一系列 LLM 特有信息呈现得清晰、可信、可控。好的 AI UI 让用户「看得懂模型在干什么、为什么这么答」。

```text
AI UI 要解决的核心问题：
1. 流式呈现 —— token 级增量渲染，不整段闪烁
2. 富文本 —— Markdown、代码块、数学公式正确渲染
3. 可信度 —— 引用来源、工具调用过程可追溯
4. 状态可见 —— 推理中、调用工具中、等待人工确认
5. 可干预 —— 用户能暂停、重试、打断、人工接管
```

## Chat UI

Chat UI 是对话界面的骨架：消息列表 + 输入框 + 发送按钮。核心在于消息气泡的布局（用户靠右、助手靠左）、自动滚动到底部、以及「生成中」的占位状态。它必须处理长对话的滚动性能，以及用户打断生成的能力。

```tsx
function MessageList({ messages }) {
  const bottomRef = useRef(null);
  useEffect(() => {
    bottomRef.current?.scrollIntoView({ behavior: 'smooth' });
  }, [messages.length]);

  return (
    <div className="message-list">
      {messages.map((m) => (
        <div key={m.id} className={m.role === 'user' ? 'bubble user' : 'bubble assistant'}>
          {m.content}
        </div>
      ))}
      <div ref={bottomRef} />
    </div>
  );
}
```

## Streaming UI

Streaming UI 处理「内容在持续增长」的渲染：模型逐 token 输出，UI 必须增量追加而非整段替换，否则会闪烁。实现上通常维护一个「流式中的消息」，把到达的增量拼接到其 content 尾部。此外还要处理光标、打字机效果和结束态的收尾。

```tsx
// 增量拼接流式内容
const [streaming, setStreaming] = useState('');

async function send() {
  setStreaming('');
  const res = await fetch('/api/chat', { method: 'POST', body: JSON.stringify({ input }) });
  const reader = res.body.getReader();
  const decoder = new TextDecoder();
  while (true) {
    const { done, value } = await reader.read();
    if (done) break;
    setStreaming((prev) => prev + decoder.decode(value, { stream: true }));
  }
}
```

## Markdown

Markdown 渲染把模型的 markdown 文本转成富文本：标题、列表、表格、加粗、链接、数学公式等。必须注意安全——直接渲染用户/模型内容可能触发 XSS，因此要用专门的渲染库（如 react-markdown、markdown-it）并做 sanitize，而不是 dangerouslySetInnerHTML。

```tsx
import ReactMarkdown from 'react-markdown';
import remarkGfm from 'remark-gfm';
import remarkMath from 'remark-math';
import rehypeKatex from 'rehype-katex';

function MarkdownView({ content }) {
  return (
    <ReactMarkdown
      remarkPlugins={[remarkGfm, remarkMath]}
      rehypePlugins={[rehypeKatex]}
    >
      {content}
    </ReactMarkdown>
  );
}
```

## Code Highlight

Code Highlight 给模型输出的代码块上色：AI 回复经常包含代码，纯文本代码可读性差，需要按语言语法高亮。常见做法是用 Shiki（准确、支持 VS Code 主题）或 highlight.js，配合代码块的语言标注（如 js、python）自动识别。

```tsx
import ReactMarkdown from 'react-markdown';
import { Prism as SyntaxHighlighter } from 'react-syntax-highlighter';

function CodeBlock({ content }) {
  return (
    <ReactMarkdown
      components={{
        code({ inline, className, children }) {
          const match = /language-(\w+)/.exec(className || '');
          return !inline && match ? (
            <SyntaxHighlighter language={match[1]} PreTag="div">
              {String(children).replace(/\n$/, '')}
            </SyntaxHighlighter>
          ) : (
            <code className={className}>{children}</code>
          );
        },
      }}
    >
      {content}
    </ReactMarkdown>
  );
}
```

## Citation

Citation（引用）让 AI 的回答「有据可查」：模型回答时标注它引用了哪些来源，UI 把标注渲染成可点击的引用角标，悬停/点击展示来源详情。这是 RAG 应用建立用户信任的关键——用户能看到答案来自哪里。

```tsx
// 把文本中的 [1]、[2] 渲染成引用角标
function renderWithCitations(text, sources) {
  const parts = text.split(/(\[\d+\])/g);
  return parts.map((part, i) => {
    const match = part.match(/^\[(\d+)\]$/);
    if (!match) return <span key={i}>{part}</span>;
    const src = sources[Number(match[1]) - 1];
    return (
      <sup key={i} className="citation" title={src?.title}>
        <a href={src?.url}>[{match[1]}]</a>
      </sup>
    );
  });
}
```

## Tool Status

Tool Status 展示模型「调用工具」的过程：当模型通过 Tool Calling 去查数据库、调 API 时，UI 应该实时显示「正在查询订单…」「正在检索文档…」的状态，而不是让用户面对一片空白。这让 Agent 行为透明化，是 Agent 类 UI 的核心要素。

```tsx
// 渲染工具调用状态
function ToolCall({ call }) {
  return (
    <div className={`tool-call ${call.status}`}>
      <div className="tool-name">
        {call.status === 'running' ? '执行中' : call.status === 'done' ? '完成' : '失败'}
        {call.name}
      </div>
      <pre className="tool-args">{JSON.stringify(call.arguments, null, 2)}</pre>
      {call.result && <pre className="tool-result">{call.result}</pre>}
    </div>
  );
}
```

## Reasoning Status

Reasoning Status 展示模型的「思考过程」：推理类模型（如 o 系列、DeepSeek R1）会先输出一段 chain-of-thought 推理再给答案。UI 可以选择展示「思考中…」的指示，以及折叠起来的推理原文，让用户理解模型得出结论的逻辑，也便于调试。

```tsx
// 推理过程与最终答案分开呈现
function ReasoningMessage({ reasoning, answer, done }) {
  return (
    <div>
      <details className="reasoning">
        <summary>{done ? '思考过程' : '思考中…'}</summary>
        <p>{reasoning}</p>
      </details>
      {answer && <div className="answer">{answer}</div>}
    </div>
  );
}
```

## Human-in-the-loop

Human-in-the-loop（人工在环）是把关键决策交给用户确认的交互模式：当 Agent 要执行高风险操作（删除数据、发起支付、发送对外消息）时，先暂停并弹出确认，由用户批准或拒绝后再继续。这是 Agent 安全性的关键——重要动作不能全自动执行。

```tsx
// 高风险操作前的人工确认
function ApprovalCard({ action, onApprove, onReject }) {
  return (
    <div className="approval">
      <p>助手请求执行以下操作：</p>
      <pre>{JSON.stringify(action, null, 2)}</pre>
      <div className="approval-actions">
        <button onClick={onApprove}>批准</button>
        <button onClick={onReject}>拒绝</button>
      </div>
    </div>
  );
}
```

## 应用场景实战

### 场景一：带引用的流式问答

```tsx
// 流式输出 + 引用角标 + 来源列表
import { useChat } from '@ai-sdk/react';
import ReactMarkdown from 'react-markdown';

export default function RAGChat() {
  const { messages, input, handleInputChange, handleSubmit } = useChat();
  const last = messages[messages.length - 1];
  return (
    <div>
      {messages.map((m) => (
        <div key={m.id} className={m.role}>
          <ReactMarkdown>{m.content}</ReactMarkdown>
          {m.annotations?.map((a, i) => (
            <sup key={i}><a href={a.url}>[{i + 1}]</a></sup>
          ))}
        </div>
      ))}
      <form onSubmit={handleSubmit}>
        <input value={input} onChange={handleInputChange} placeholder="提问…" />
      </form>
    </div>
  );
}
```

### 场景二：带工具状态和人工确认的 Agent UI

```tsx
// 展示工具调用过程 + 高风险操作确认
function AgentChat({ messages, onApprove, onReject }) {
  return (
    <div>
      {messages.map((m) => (
        <div key={m.id}>
          {m.toolCalls?.map((call) => <ToolCall key={call.id} call={call} />)}
          {m.requiresApproval && (
            <ApprovalCard action={m.pendingAction} onApprove={onApprove} onReject={onReject} />
          )}
          <ReactMarkdown>{m.content}</ReactMarkdown>
        </div>
      ))}
    </div>
  );
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. 流式渲染用增量追加，绝不整段替换
2. Markdown 渲染必须 sanitize，防 XSS
3. 代码块自动识别语言 + 高亮 + 复制按钮
4. 引用角标可点击、来源可追溯，建立信任
5. 工具调用、推理过程状态可见，Agent 行为透明
6. 高风险操作强制人工确认，不留全自动后门

### 踩坑记录

```text
坑 1：流式渲染整段替换 DOM
结论：回复一长，每来一个字都全量 re-render，页面卡顿。
原因：把整个 Markdown 重新解析 + 替换 innerHTML。
解法：增量追加纯文本，用 rAF 节流，段落结束才重新渲染富文本。

坑 2：Markdown 渲染没做 sanitize
结论：模型输出里的 script/onerror 被执行，XSS 攻击。
原因：直接 innerHTML 渲染模型回复，未经过滤。
解法：DOMPurify 净化后再渲染，白名单标签和属性。

坑 3：代码块语言没识别导致高亮错乱
结论：代码块整段纯色或高亮错乱。
原因：模型输出代码块后没带语言标注，或标注不标准。
解法：无语言标注时用 highlightAuto 自动识别，并兜底默认语言。

坑 4：引用角标不可点击、来源丢失
结论：用户看不到引用出处，失去对回答的信任。
原因：只渲染了 [1] 文本，没绑定来源数据和跳转。
解法：引用渲染成可点击角标，点击弹出原文片段或跳转来源。

坑 5：工具调用过程不可见
结论：用户不知道 Agent 在查库/调接口，以为卡死。
原因：工具执行是异步黑盒，前端没展示中间状态。
解法：展示 Tool Status（如「正在查询…」），透明化 Agent 行为。

坑 6：推理过程无提示
结论：推理模型思考几十秒，页面无反馈用户误以为失败。
原因：Reasoning Status 没接，只等最终回复。
解法：展示推理状态（thinking 指示器/中间步骤），流式刷新。
```

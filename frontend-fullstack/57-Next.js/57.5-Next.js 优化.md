## 概述

Next.js 内置了一系列开箱即用的优化组件与能力，覆盖图片、字体、脚本、代码分割、SEO 元数据与流式渲染，让「性能最佳实践」成为默认行为，而不是开发者手动实现。

```text
Next.js 优化能力的全景：
1. Image —— 图片懒加载、尺寸自适应、格式优化（WebP/AVIF）
2. Font —— 字体自托管、零布局偏移、子集化
3. Script —— 第三方脚本的加载策略与优先级控制
4. Dynamic Import —— 组件/库按需加载、SSR 禁用
5. Metadata —— SEO 元数据、Open Graph、结构化
6. Streaming —— 流式渲染，首屏更快
```

## Image

`next/image` 组件是 `<img>` 的增强版：自动懒加载、响应式尺寸、按需生成优化格式，是减少 LCP 与带宽的关键。

```jsx
// next/image 基础用法
import Image from 'next/image';

export default function Hero() {
  return (
    <Image
      src="/images/banner.jpg"
      width={1200}          // 声明尺寸，防止 CLS
      height={600}
      alt="产品横幅"
      priority             // 首屏关键图，禁用懒加载并预加载
    />
  );
}
```

```jsx
// 远程图片：需配置域名白名单
// next.config.js
module.exports = {
  images: {
    remotePatterns: [
      { protocol: 'https', hostname: 'cdn.example.com' },
    ],
  },
};

// 使用远程图片 + 占位符
<Image
  src="https://cdn.example.com/product.jpg"
  width={400}
  height={300}
  alt="商品图"
  fill={false}
  placeholder="blur"
  blurDataURL="data:image/jpeg;base64,..."
/>
```

```text
next/image 的核心优化：
1. 懒加载 —— 默认仅在进入视口时加载
2. 尺寸优化 —— 按设备 DPR 生成合适尺寸
3. 格式优化 —— 自动转 WebP/AVIF
4. 防 CLS —— 强制声明 width/height
5. priority —— 首屏图预加载，优化 LCP
```

## Font

`next/font` 让字体「自托管」，构建时下载字体并生成子集，避免第三方字体服务的额外请求，同时消除字体加载造成的布局偏移（FOUT）。

```jsx
// next/font/google：使用 Google 字体并自动自托管
import { Inter } from 'next/font/google';

const inter = Inter({ subsets: ['latin'], display: 'swap' });

export default function Layout({ children }) {
  return (
    <html lang="zh" className={inter.className}>
      <body>{children}</body>
    </html>
  );
}
```

```jsx
// next/font/local：本地字体文件
import localFont from 'next/font/local';

const myFont = localFont({
  src: './fonts/my-font.woff2',
  display: 'swap',
  variable: '--font-my',
});

export default function Layout({ children }) {
  return <html className={myFont.variable}>{children}</html>;
}
```

```text
next/font 的优化点：
1. 自托管 —— 构建时下载字体，不依赖第三方 CDN
2. 零 CLS —— 字体尺寸提前声明，避免文字跳动
3. 子集化 —— 只加载用到的字符，减小体积
4. 自动 preload —— 关键字体预加载
5. display: swap —— 字体加载前用回退字体，避免 FOIT
```

## Script

`next/script` 组件精确控制第三方脚本的加载时机与执行顺序，避免第三方脚本（分析、广告、客服）阻塞首屏。

```jsx
// next/script 基础用法
import Script from 'next/script';

export default function Layout({ children }) {
  return (
    <html>
      <body>
        {children}
        {/* 页面可交互后再加载（默认 afterInteractive） */}
        <Script
          src="https://www.googletagmanager.com/gtag/js?id=G-XXX"
          strategy="afterInteractive"
        />
        {/* 空闲时才加载（低优先级） */}
        <Script src="/analytics.js" strategy="lazyOnload" />
      </body>
    </html>
  );
}
```

```text
Script 的加载策略（strategy）：
1. beforeInteractive —— 水合前加载（关键脚本，慎用）
2. afterInteractive —— 水合后加载（默认，适合大多数）
3. lazyOnload —— 浏览器空闲时加载（低优先级）
4. worker —— 在 Web Worker 中加载（实验性）

内联脚本用 dangerouslySetInnerHTML 注入。
```

## Dynamic Import

Dynamic Import（动态导入）按需加载组件或库，减小首屏 bundle。`next/dynamic` 额外支持 SSR 禁用、自定义加载态。

```jsx
// next/dynamic 基础：组件懒加载
import dynamic from 'next/dynamic';

const HeavyChart = dynamic(() => import('./HeavyChart'), {
  loading: () => <div>图表加载中...</div>,
});

export default function Page() {
  return <HeavyChart />; // 仅在需要时加载
}
```

```jsx
// ssr: false —— 禁用 SSR（仅客户端渲染）
const ClientOnlyMap = dynamic(() => import('./Map'), {
  ssr: false, // 服务端不渲染，避免 window 依赖报错
});

export default function Page() {
  return <ClientOnlyMap />;
}
```

```jsx
// 命名导出：从库中按需导入
const ReactPlayer = dynamic(() =>
  import('react-player').then((mod) => mod.default),
  { ssr: false }
);
```

## Metadata

Metadata API 统一管理 SEO 元数据（标题、描述、Open Graph、结构化数据），支持静态导出与动态生成，是 SEO 的基础。

```jsx
// 静态元数据：layout.js 或 page.js 中导出
export const metadata = {
  title: '我的博客',
  description: '分享前端与全栈技术',
  openGraph: {
    title: '我的博客',
    description: '分享前端与全栈技术',
    type: 'website',
  },
};

export default function Page() {
  return <div>...</div>;
}
```

```jsx
// 动态元数据：根据路由参数生成
export async function generateMetadata({ params }) {
  const { slug } = await params;
  const post = await fetchPost(slug);
  return {
    title: post.title,
    description: post.excerpt,
    openGraph: { title: post.title, images: [post.cover] },
  };
}
```

```text
Metadata 的关键点：
1. title 支持模板（title.template），子页面自动拼接
2. 覆盖 Open Graph / Twitter Card，分享卡片更美观
3. 结构化数据（JSON-LD）提升富媒体展示
4. 动态页用 generateMetadata 按参数生成
5. 与 next/font 配合，SEO 与性能兼得
```

## Streaming

Streaming（流式渲染）把页面拆块、渐进发送，让用户先看到内容骨架，慢数据稍后补入，显著改善首屏感知。

```jsx
// 路由级：loading.js 自动流式
// app/dashboard/loading.js
export default function Loading() {
  return <div>仪表盘加载中...</div>;
}
```

```jsx
// 组件级：Suspense 边界流式
import { Suspense } from 'react';

export default function ProductPage() {
  return (
    <div>
      <h1>商品详情</h1>
      <ProductInfo />                {/* 立即渲染 */}
      <Suspense fallback={<ReviewsSkeleton />}>
        <Reviews />                  {/* 慢数据，流式补入 */}
      </Suspense>
    </div>
  );
}
```

```text
Streaming 的优化逻辑：
1. 首屏骨架先到 → 降低白屏感知
2. 慢数据不阻塞 → 快内容先行
3. 配合 Suspense/loading.js → 自动拆块
4. 与 RSC 结合 → 服务端流式输出 HTML
```

## 应用场景实战

### 场景一：营销落地页全优化

```jsx
import Image from 'next/image';
import { Inter } from 'next/font/google';
import dynamic from 'next/dynamic';

const inter = Inter({ subsets: ['latin'] });

export const metadata = {
  title: '产品营销页',
  description: '提升转化率',
  openGraph: { title: '产品营销页', type: 'website' },
};

// 首屏外的复杂组件懒加载
const InteractiveDemo = dynamic(() => import('./InteractiveDemo'), {
  ssr: false,
});

export default function Landing() {
  return (
    <main className={inter.className}>
      <Image src="/hero.jpg" width={1600} height={900} alt="主视觉" priority />
      <h1>核心卖点</h1>
      <InteractiveDemo />
    </main>
  );
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. 所有图片用 next/image，首屏关键图加 priority
2. 字体用 next/font 自托管，消除第三方字体请求与 CLS
3. 第三方脚本按需设 strategy，别让它阻塞首屏
4. 大组件/重库用 dynamic import，按需加载
5. 每个页面配 metadata，动态页用 generateMetadata
6. 慢数据用 Suspense/loading.js 流式，别整页等
7. 图片先声明尺寸，配合 blur 占位防 CLS
8. 用 Lighthouse/Web Vitals 验证优化效果

### 踩坑记录

```text
坑 1：next/image 远程图报错
结论：远程图片加载失败，报 hostname 未配置。
原因：next/image 只允许白名单域名。
解法：next.config.js 的 images.remotePatterns 配置域名。

坑 2：字体加载导致文字跳动
结论：页面加载时文字先小后大，CLS 超标。
原因：未用 next/font，系统字体与自定义字体尺寸差异。
解法：用 next/font 自托管 + 提前声明字体尺寸。

坑 3：第三方脚本阻塞首屏
结论：分析/客服脚本拖慢 TTI。
原因：script 标签在 head 同步加载，阻塞渲染。
解法：用 next/script + strategy（afterInteractive/lazyOnload）。

坑 4：动态导入没生效，bundle 仍大
结论：dynamic import 后首屏体积没降。
原因：组件被静态 import 了，或库没有真正拆分。
解法：确认只用 dynamic() 引入，检查 chunk 拆分结果。

坑 5：metadata 不生效
结论：改了 metadata 但 SEO 显示不对。
原因：父级 layout 的 metadata 覆盖，或动态页没写 generateMetadata。
解法：理解 metadata 合并规则，动态页用 generateMetadata。
```

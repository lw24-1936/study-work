## 概述

Next.js 的路由基于「文件系统」，目录结构即路由结构，无需手写路由配置。它有两套路由体系：老旧的 Pages Router 和当前主流的 App Router，后者引入布局、并行路由、拦截路由等高级能力。

```text
Next.js 路由的核心思想：
1. 文件即路由 —— 目录/文件名直接映射为 URL 路径
2. 约定大于配置 —— 特殊文件名有特殊含义（layout/page/loading）
3. 服务端优先 —— App Router 中组件默认在服务端渲染

App Router 目录结构（app/）：
app/
  layout.js          # 根布局（所有页面共享）
  page.js            # 首页（/）
  about/
    page.js          # /about
  blog/
    [slug]/
      page.js        # /blog/:slug 动态路由
    [...rest]/
      page.js        # /blog/a/b/c 捕获所有
```

## App Router

App Router 是 Next.js 13+ 推出的新路由系统，基于 React Server Components，支持嵌套布局、流式渲染、并行路由等现代能力。

```text
App Router 的核心概念：
1. 目录约定 —— 用 app/ 目录组织路由
2. 特殊文件 —— layout/page/loading/error/not-found 等
3. 嵌套布局 —— 每个目录可有 layout，父子嵌套
4. 服务端默认 —— 组件默认服务端渲染
5. 流式 —— 配合 Suspense 与 loading.js 流式渲染

特殊文件：
page.js —— 路由对应的页面内容
layout.js —— 布局（包裹子页面，切换时保留状态）
loading.js —— 加载态（自动用 Suspense 包裹）
error.js —— 错误边界
not-found.js —— 404 页面
```

```jsx
// app/layout.js —— 根布局
export default function RootLayout({ children }) {
  return (
    <html lang="zh">
      <body>
        <header>站点导航</header>
        {children}
        <footer>版权信息</footer>
      </body>
    </html>
  );
}

// app/page.js —— 首页
export default function Home() {
  return <h1>首页</h1>;
}
```

## Pages Router

Pages Router 是 Next.js 传统路由系统（Next.js 13 之前），页面放在 `pages/` 目录，用 `getServerSideProps`/`getStaticProps` 取数据。

```text
Pages Router 的特点：
1. 目录 —— pages/ 下的文件即路由
2. 数据获取 —— getServerSideProps（SSR）/ getStaticProps（SSG）
3. 无布局约定 —— 用 _app.js / _document.js 自定义
4. 客户端渲染 —— 页面组件默认客户端水合

虽然仍可用，但官方主推 App Router，新项目建议用 App Router。
```

```jsx
// pages/about.js —— Pages Router 页面
export default function About({ data }) {
  return <div>{data}</div>;
}

// 数据获取：服务端渲染
export async function getServerSideProps() {
  const data = await fetchData();
  return { props: { data } };
}
```

```text
两代路由对比：
特性           App Router         Pages Router
布局           layout.js 嵌套      _app.js 全局
数据获取       fetch/async 组件    getStaticProps 等
渲染模型       RSC + 流式          传统 SSR/SSG
路由分组       (group)             -
并行/拦截路由   支持               不支持
```

## File Based Routing

File Based Routing（基于文件的路由）是 Next.js 的核心理念：路由由文件系统结构自动推导，无需手动配置路由表。

```text
文件到路由的映射规则：
app/page.js              → /
app/about/page.js        → /about
app/blog/page.js         → /blog
app/blog/[slug]/page.js  → /blog/:slug（动态）
app/docs/[...slug]/page.js → /docs/a/b/c（捕获所有）

特殊文件优先级：
page.js 定义路由内容，layout.js 定义布局，
loading.js/error.js 是内置的流式与错误处理。
```

```text
目录结构示例：
app/
  dashboard/
    layout.js        # /dashboard 的布局
    page.js          # /dashboard
    settings/
      page.js        # /dashboard/settings
  (marketing)/       # 路由分组，不影响 URL
    about/
      page.js        # /about（分组括号不进入 URL）
```

## Dynamic Route

Dynamic Route（动态路由）用方括号 `[param]` 定义带参数的路径段，匹配 `/blog/123` 这类可变路径。

```jsx
// app/blog/[slug]/page.js —— 动态路由
export default async function BlogPost({ params }) {
  const { slug } = await params; // 读取动态参数
  const post = await fetchPost(slug);
  return <article>{post.content}</article>;
}
```

```jsx
// 配合 generateStaticParams 预渲染动态路由
export async function generateStaticParams() {
  const posts = await fetchAllPosts();
  return posts.map((p) => ({ slug: p.slug })); // 预渲染这些路径
}

// 可选参数：用双层括号 [[...]] 让参数可选
// app/shop/[[...slug]]/page.js —— /shop 和 /shop/a/b 都匹配
```

## Catch All

Catch All（捕获所有路由）用省略号 `[...param]` 匹配任意深度的路径段，适合文档站、多级分类等场景。

```jsx
// app/docs/[...slug]/page.js —— 捕获所有段
export default async function Doc({ params }) {
  const { slug } = await params; // slug 是数组，如 ['a','b','c']
  const path = slug.join('/');   // 'a/b/c'
  const doc = await fetchDoc(path);
  return <article>{doc.content}</article>;
}

// /docs/a          → slug = ['a']
// /docs/a/b        → slug = ['a', 'b']
// /docs/a/b/c      → slug = ['a', 'b', 'c']
```

```jsx
// 可选捕获所有：[[...slug]]，根路径也匹配
// app/shop/[[...slug]]/page.js
// /shop            → slug = undefined（根）
// /shop/phones/red → slug = ['phones', 'red']
```

## Parallel Route

Parallel Route（并行路由）用 `@folder` 定义可同时渲染的多个页面槽（slot），让同一页面并存多个独立区域（如仪表盘的多个面板）。

```text
并行路由的价值：
1. 同一 URL 下并行渲染多个独立区域
2. 每个区域有独立的 loading/error 状态
3. 适合仪表盘、多面板布局

目录结构：
app/
  dashboard/
    layout.js
    @analytics/
      page.js      # 分析面板
    @team/
      page.js      # 团队面板
    page.js        # 主内容
```

```jsx
// app/dashboard/layout.js —— 并行槽由 layout 组织
export default function DashboardLayout({ children, analytics, team }) {
  return (
    <div>
      {children}
      {analytics}   {/* @analytics 槽 */}
      {team}        {/* @team 槽 */}
    </div>
  );
}
```

## Intercepting Route

Intercepting Route（拦截路由）用 `(.)` 前缀在导航时「拦截」某个路由，展示在上下文之上（如弹窗），而直接访问该 URL 时展示完整页面。

```text
拦截路由的用途：
1. 列表页点击详情 → 弹窗展示（拦截），不离开列表
2. 直接访问详情 URL / 刷新 → 完整页面（不拦截）

拦截语法（相对路径层级）：
(.)folder   —— 拦截同级
(..)folder  —— 拦截上一级
(..)(..)    —— 拦截上两级
(...)       —— 拦截根级
```

```text
目录结构示例：
app/
  photos/
    page.js              # /photos 列表
    [id]/
      page.js            # /photos/:id 完整详情页
  @modal/
    (.)photos/
      [id]/
        page.js          # 拦截 /photos/:id，以弹窗展示
```

```jsx
// app/@modal/(.)photos/[id]/page.js —— 拦截后的弹窗
export default function PhotoModal({ params }) {
  const { id } = params;
  return (
    <div className="modal">
      <img src={`/photos/${id}.jpg`} />
    </div>
  );
}
```

## 应用场景实战

### 场景一：博客站完整路由结构

```text
app/
  layout.js                 # 全站布局（导航 + footer）
  page.js                   # 首页
  blog/
    page.js                 # 博客列表 /blog
    [slug]/
      page.js               # 文章详情 /blog/my-post
  tags/
    [tag]/
      page.js               # 标签页 /tags/react
  docs/
    [...path]/
      page.js               # 文档 /docs/a/b/c
```

```jsx
// app/blog/[slug]/page.js
export async function generateStaticParams() {
  const posts = await fetchPosts();
  return posts.map((p) => ({ slug: p.slug }));
}

export default async function Post({ params }) {
  const { slug } = await params;
  const post = await fetchPost(slug);
  return <article><h1>{post.title}</h1>{post.body}</article>;
}
```

### 场景二：仪表盘并行路由

// app/dashboard/layout.js —— 三个面板并行渲染
export default function Layout({ children, stats, activity }) {

## 最佳实践与踩坑记录

### 最佳实践

1. 新项目直接用 App Router，避免 Pages Router 迁移成本
2. 共享 UI 放 layout.js，页面切换时保留状态
3. 动态路由配合 generateStaticParams 预渲染，减少运行时开销
4. 并行路由用于多面板布局，每个槽独立 loading/error
5. 拦截路由用于「列表点开弹窗」的流畅体验
6. 用路由分组 (group) 组织代码，而不影响 URL
7. 404 用 not-found.js，错误用 error.js 错误边界
8. 捕获所有路由注意参数可能是数组，处理边界情况

### 踩坑记录

```text
坑 1：params 在 App Router 中是 Promise
结论：直接解构 params 拿不到值。
原因：Next.js 15 起 params/searchParams 变为异步。
解法：await params 后再使用（或用 React 的 use()）。

坑 2：动态路由与静态路由冲突
结论：/blog/new 匹配到了 [slug] 而非预想的静态页。
原因：动态段与静态段重名，静态优先级需明确。
解法：避免重名，或调整目录结构让静态段优先。

坑 3：layout 嵌套过深导致状态丢失
结论：切换路由时某区域状态被重置。
原因：该区域放在了会变化的 layout 而非持久的 layout。
解法：把需保态的 UI 放到正确的 layout 层级。

坑 4：拦截路由直接访问不生效
结论：直接输 URL 看到的是完整页而非弹窗。
原因：拦截只在客户端导航时生效，直接访问走完整页面（预期行为）。
解法：理解拦截语义，弹窗场景确保用户通过列表导航进入。

坑 5：捕获所有路由匹配了不想要的路径
结论：[...slug] 把不该匹配的也吞了。
原因：捕获所有过于宽泛，与相邻路由产生歧义。
解法：用更精确的动态段，或调整目录层级隔离。
```

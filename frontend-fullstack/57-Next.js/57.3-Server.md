## 概述

Next.js App Router 把「服务端能力」从传统的 API 路由扩展到了组件层：Server Component 在服务端渲染、Server Action 直接处理表单提交、Route Handler 提供 REST 接口、Middleware 在请求边界做拦截。四者构成了完整的服务端编程模型。

```text
四种服务端能力的分工：
1. Server Component —— 服务端渲染组件（渲染 + 数据获取）
2. Server Action —— 服务端执行的函数（表单提交/数据变更）
3. Route Handler —— REST API 接口（/api/*）
4. Middleware —— 请求拦截（鉴权/重定向/改写，在边缘运行）

何时用哪个：
渲染 + 读数据 → Server Component
表单提交 + 写数据 → Server Action
对外 API/Webhook → Route Handler
全局鉴权/重定向 → Middleware
```

## Server Component

Server Component（服务端组件）是 App Router 的默认组件类型：在服务端渲染，可直接访问数据库、文件系统、环境变量，代码不打包进客户端 bundle。

```jsx
// 服务端组件（默认）：直接查库，不向客户端暴露敏感逻辑
import { db } from '@/lib/db';

export default async function ProductList() {
  const products = await db.product.findMany({
    where: { status: 'active' },
  });
  return (
    <ul>
      {products.map((p) => (
        <li key={p.id}>{p.name} - {p.price}</li>
      ))}
    </ul>
  );
}
```

```text
Server Component 的能力与限制：
能做的事：
1. 直接访问数据库、文件系统、环境变量
2. 使用 async/await 在服务端取数据
3. 引用服务端专属库（ORM、SDK）

不能做的事：
1. 使用 useState/useEffect 等 Hooks
2. 绑定事件处理（onClick 等）
3. 使用浏览器 API（window/document）

需要交互时，用 'use client' 标记客户端组件。
```

## Server Action

Server Action（服务端动作）是「在服务端执行的函数」，可以直接从客户端组件调用（或作为表单 action），用于处理数据变更，无需手动写 API 路由。

```jsx
// app/actions.js —— 用 'use server' 声明服务端动作
'use server';

import { db } from '@/lib/db';

export async function createPost(formData) {
  const title = formData.get('title');
  const content = formData.get('content');
  await db.post.create({ data: { title, content } });
  // 可选：重新验证相关页面缓存
  // revalidatePath('/posts');
}
```

```jsx
// 客户端组件中调用 Server Action
'use client';
import { createPost } from './actions';

export default function NewPostForm() {
  return (
    <form action={createPost}>   {/* 表单直接提交到服务端动作 */}
      <input name="title" placeholder="标题" />
      <textarea name="content" placeholder="内容" />
      <button type="submit">发布</button>
    </form>
  );
}
```

```jsx
// 或通过 transition 调用（适合非表单场景）
'use client';
import { useTransition } from 'react';
import { createPost } from './actions';

export default function PublishButton() {
  const [isPending, startTransition] = useTransition();
  return (
    <button
      disabled={isPending}
      onClick={() => startTransition(() => createPost({ title: 'x', content: 'y' }))}
    >
      {isPending ? '发布中...' : '发布'}
    </button>
  );
}
```

## Route Handler

Route Handler（路由处理器）在 `app/` 下用 `route.js` 定义，处理标准 HTTP 请求，用于对外提供 REST API、Webhook 接收等场景。

```js
// app/api/posts/route.js —— 处理 /api/posts
import { NextResponse } from 'next/server';

export async function GET(request) {
  const { searchParams } = new URL(request.url);
  const page = searchParams.get('page') || '1';
  const posts = await fetchPosts({ page });
  return NextResponse.json({ data: posts });
}

export async function POST(request) {
  const body = await request.json();
  const post = await createPost(body);
  return NextResponse.json({ data: post }, { status: 201 });
}
```

```js
// app/api/posts/[id]/route.js —— 动态段路由处理器
export async function GET(request, { params }) {
  const { id } = await params; // App Router 中 params 是 Promise
  const post = await fetchPost(id);
  if (!post) {
    return NextResponse.json({ error: 'not found' }, { status: 404 });
  }
  return NextResponse.json({ data: post });
}

export async function DELETE(request, { params }) {
  const { id } = await params;
  await deletePost(id);
  return NextResponse.json({ ok: true });
}
```

```text
Route Handler 的关键点：
1. 文件名固定为 route.js，与 page.js 不能同目录共存
2. 导出 GET/POST/PUT/DELETE/PATCH 等按方法命名
3. 动态段通过第二个参数 { params } 读取
4. 用 NextResponse.json 返回 JSON 响应
5. 可用 runtime = 'edge' 指定在边缘运行
```

## Middleware

Middleware（中间件）在请求到达页面/路由处理器**之前**执行，用于鉴权、重定向、请求改写、A/B 测试等全局逻辑，运行在边缘运行时。

```js
// middleware.js（项目根目录或 src/ 下）
import { NextResponse } from 'next/server';

export function middleware(request) {
  const token = request.cookies.get('token')?.value;
  const { pathname } = request.nextUrl;

  // 未登录访问受保护路由 → 重定向到登录
  if (pathname.startsWith('/dashboard') && !token) {
    return NextResponse.redirect(new URL('/login', request.url));
  }
  return NextResponse.next(); // 放行
}

// 匹配规则：只对特定路径生效
export const config = {
  matcher: ['/dashboard/:path*', '/api/:path*'],
};
```

```js
// 请求改写与响应头示例
export function middleware(request) {
  const { pathname } = request.nextUrl;

  // URL 改写（不改变地址栏）
  if (pathname === '/old-page') {
    return NextResponse.rewrite(new URL('/new-page', request.url));
  }

  // 添加响应头
  const response = NextResponse.next();
  response.headers.set('x-custom-header', 'hello');
  return response;
}
```

```text
Middleware 的特点与限制：
1. 运行在边缘运行时（Edge Runtime），非 Node 环境
2. 在缓存之前执行，可用于动态路由决策
3. 不支持 Node API（fs 等），只能 Web API
4. matcher 用于限定作用路径，提升性能
```

## 应用场景实战

### 场景一：带鉴权的完整表单流

```jsx
// Server Action 处理登录 + 写 Cookie
'use server';
import { cookies } from 'next/headers';
import { verifyUser } from '@/lib/auth';

export async function login(formData) {
  const email = formData.get('email');
  const password = formData.get('password');
  const user = await verifyUser(email, password);
  if (!user) return { error: '邮箱或密码错误' };

  (await cookies()).set('token', user.token, {
    httpOnly: true,
    secure: true,
    sameSite: 'lax',
  });
  return { ok: true };
}
```

```jsx
// 客户端表单
'use client';
import { login } from './actions';

export default function LoginForm() {
  return (
    <form action={login}>
      <input name="email" type="email" required />
      <input name="password" type="password" required />
      <button type="submit">登录</button>
    </form>
  );
}
```

### 场景二：Webhook 接收 + 按需再验证

```js
// app/api/webhook/route.js —— 接收 CMS 回调并刷新缓存
import { revalidateTag } from 'next/cache';

export async function POST(request) {
  const signature = request.headers.get('x-webhook-signature');
  if (!verifySignature(signature, await request.text())) {
    return Response.json({ error: 'invalid signature' }, { status: 401 });
  }
  revalidateTag('cms-content'); // 内容更新，刷新相关页面
  return Response.json({ ok: true });
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. 读数据用 Server Component，写数据用 Server Action，职责分明
2. Server Action 内做输入校验与鉴权，不能信任客户端
3. Route Handler 用于对外 API/Webhook，业务内部优先 Server Action
4. Middleware 只做轻量逻辑（鉴权/重定向），重逻辑放页面/接口
5. 敏感信息（token、密钥）只放服务端，绝不进客户端组件
6. Server Action 用 useTransition 获取 pending 状态，提升体验
7. Route Handler 注意 params 是 Promise，需 await
8. Middleware 运行在边缘，注意不可用 Node API

### 踩坑记录

```text
坑 1：Server Action 被未授权调用
结论：接口被绕过鉴权直接调用，数据泄露。
原因：Server Action 内部没做鉴权，只依赖前端隐藏入口。
解法：Server Action 内部校验登录态与权限，不能信任客户端。

坑 2：route.js 与 page.js 同目录冲突
结论：构建报错。
原因：同一目录不能同时有 page.js 和 route.js。
解法：API 放 /api 目录，页面放 page.js，二者分离。

坑 3：Middleware 用了 Node API 报错
结论：Middleware 中 fs/path 等报错。
原因：Middleware 运行在 Edge Runtime，无 Node 模块。
解法：改用 Web API，或把该逻辑移到 Route Handler/Server Component。

坑 4：Route Handler 的 params 没 await
结论：拿到的是 Promise 对象而非值。
原因：Next.js 15 起 params 是异步的。
解法：const { id } = await params 后再使用。

坑 5：Server Action 中直接返回大对象
结论：客户端拿到的数据过大或含敏感字段。
原因：Server Action 返回值会被序列化传到客户端。
解法：只返回必要字段，敏感数据脱敏后再返回。
```

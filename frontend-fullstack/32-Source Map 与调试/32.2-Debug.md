## 概述

浏览器 DevTools 是前端调试的核心工具，掌握断点、监视、调用栈、性能分析等能力，能高效定位和解决 Bug 与性能问题。

```text
调试核心能力：
1. breakpoint —— 断点，暂停执行
2. conditional breakpoint —— 条件断点，按条件暂停
3. watch —— 监视表达式，实时查看值
4. call stack —— 调用栈，追踪调用链
5. scope —— 作用域，查看变量
6. network —— 网络，分析请求
7. performance —— 性能，分析渲染
8. memory —— 内存，排查泄漏
9. coverage —— 覆盖率，分析未用代码
```

```text
调试流程：
复现问题 → 打断点 → 单步执行 → 观察变量 → 定位根因 → 修复验证
```

## breakpoint

Breakpoint（断点）让代码执行到指定行时暂停，是调试的基础。可在 Sources 面板点击行号设置。

```js
function calculate(a, b) {
  const result = a * b;   // 在此行打断点
  return result;
}
calculate(10, 20);
```

```text
断点类型：
1. 行断点 —— 执行到该行暂停
2. DOM 断点 —— 元素变化时暂停
3. 事件断点 —— 事件触发时暂停
4. XHR 断点 —— 请求发起时暂停
```

```text
断点后的操作：
Step over —— 执行下一行（不进入函数）
Step into —— 进入函数内部
Step out —— 跳出当前函数
Resume —— 继续执行到下一个断点
```

## conditional breakpoint

Conditional Breakpoint（条件断点）只在满足条件时暂停，避免在大循环中反复手动跳过，提高调试效率。

```js
// 循环 1000 次，只在 i === 500 时暂停
for (let i = 0; i < 1000; i++) {
  process(i);   // 右键 → Add conditional breakpoint → 条件 i === 500
}
```

```text
条件断点设置：
1. 右键点击行号
2. 选择 Add conditional breakpoint
3. 输入条件表达式（如 i === 500）
4. 满足条件才暂停
```

```text
适用场景：
1. 大循环中的特定迭代
2. 特定数据触发的 Bug
3. 只在异常值出现时暂停
```

## watch

Watch 面板可以添加表达式，在断点暂停时实时查看表达式的值，也可直接修改值观察影响。

```js
const user = { name: 'Alice', age: 30 };
const greeting = `Hello, ${user.name}`;  // 断点处 watch: user.age
```

```text
Watch 用法：
1. 添加表达式（如 user.age、a + b）
2. 断点暂停时显示当前值
3. 可手动修改值测试不同分支
```

```text
Watch 与 Console 对比：
Watch —— 断点暂停时持续显示表达式值
Console —— 手动输入命令查看
```

## call stack

Call Stack（调用栈）显示当前执行点的函数调用链，从调用入口到当前函数，帮助理解代码执行路径。

```js
function a() { b(); }   // 调用栈：c → b → a
function b() { c(); }
function c() { debugger; }  // 暂停时查看调用栈
a();
```

```text
Call Stack 价值：
1. 查看函数如何被调用到这里
2. 点击栈帧跳到对应代码
3. 理解异步与递归的执行路径
```

## scope

Scope 面板显示当前执行点的变量作用域链：局部变量（Local）、闭包变量（Closure）、全局变量（Global）。

```js
function outer() {
  const x = 1;               // Closure 作用域
  return function inner() {
    const y = 2;             // Local 作用域
    debugger;                // 暂停时查看 Scope
  };
}
outer()();
```

```text
Scope 分类：
Local —— 当前函数局部变量
Closure —— 闭包捕获的外部变量
Script —— 脚本级变量
Global —— 全局变量（window）
```

## network

Network 面板记录所有网络请求，可查看请求头、响应、耗时、瀑布图，用于排查接口问题与资源加载。

```js
// 发起请求后在 Network 面板查看
fetch('/api/user')
  .then((res) => res.json())
  .then((data) => console.log(data));
```

```text
Network 分析要点：
1. 请求状态码（200/404/500）
2. 耗时瀑布图（排队、连接、下载）
3. 请求/响应头与 payload
4. 按类型筛选（XHR/JS/CSS/图片）
```

```text
常见排查：
慢请求 —— 看瀑布图各阶段耗时
接口报错 —— 看状态码与响应体
资源 404 —— 看路径与 publicPath
```

## performance

Performance 面板记录页面运行时的性能数据：JS 执行、渲染、布局、绘制，用于分析卡顿与性能瓶颈。

```js
// 用 performance 标记自定义时间点
performance.mark('start');
doHeavyWork();
performance.mark('end');
performance.measure('heavy-work', 'start', 'end');
```

```text
Performance 分析维度：
1. 加载性能 —— 资源加载耗时
2. 脚本性能 —— JS 执行耗时
3. 渲染性能 —— Layout/Paint 耗时
4. FPS —— 帧率，识别卡顿
```

```text
关键指标：
FP/FCP —— 首次绘制/内容绘制
LCP —— 最大内容绘制
Long Task —— 超过 50ms 的长任务
```

## memory

Memory 面板用于分析内存占用与泄漏，通过堆快照（Heap Snapshot）和分配时间线定位内存问题。

```js
// 潜在内存泄漏：全局变量持续增长
let leaked = [];
function grow() {
  leaked.push(new Array(1000000).fill('x'));
}
setInterval(grow, 1000);
```

```text
内存分析手段：
1. Heap Snapshot —— 堆快照，对比找泄漏对象
2. Allocation Timeline —— 分配时间线，看内存增长
3. 对比快照 —— 找持续增长的对象
```

```text
常见内存泄漏：
1. 全局变量持续累加
2. 未清理的定时器/事件监听
3. 闭包持有大对象引用
```

## coverage

Coverage 面板分析页面 JS/CSS 代码的使用率，标记哪些代码未被使用，用于清理冗余代码。

```text
Coverage 用途：
1. 查看 JS/CSS 代码使用率
2. 标红未使用的代码
3. 指导按需加载与代码清理
```

```text
使用场景：
1. 首屏加载了未使用的 JS/CSS
2. 分析第三方库的冗余引入
3. 评估代码分割效果
```

## 应用场景实战

### 场景一：定位线上偶发 Bug

```js
// 用条件断点定位特定数据触发的 Bug
items.forEach((item) => {
  if (item.status === 'error') {
    handleError(item);   // 条件断点：item.status === 'error'
  }
});
```

### 场景二：分析首屏性能瓶颈

```js
// 标记关键节点，配合 Performance 面板分析
performance.mark('app-start');
renderApp();
performance.mark('app-rendered');
performance.measure('first-render', 'app-start', 'app-rendered');
console.log(performance.getEntriesByName('first-render')[0].duration);
```

## 最佳实践与踩坑记录

### 最佳实践

1. 条件断点替代在循环里打普通断点
2. 结合 Watch + Scope 观察变量变化
3. 用 Call Stack 理解异步调用链
4. Performance 面板定位 Long Task 卡顿
5. Coverage 定期检查代码冗余

### 踩坑记录

```text
坑 1：断点打在压缩代码上行号错乱
结论：生产代码无法断点调试。
原因：压缩后无 Source Map，行号对应不上。
解法：生产构建配 hidden-source-map + 本地还原。

坑 2：异步回调里断点不触发
结论：断点打在异步回调里不生效。
原因：异步代码执行时机不同，断点需打在回调内部。
解法：在回调函数体内打断点，或用 XHR 断点。

坑 3：watch 表达式有副作用
结论：watch 表达式修改了状态，干扰调试。
原因：watch 里写了带副作用的表达式（如 arr.pop()）。
解法：watch 只放只读表达式。

坑 4：内存快照对比遗漏
结论：找不到泄漏对象。
原因：只拍一次快照无法对比。
解法：拍多次快照，用 Comparison 视图对比增长。

坑 5：Network 面板刷新丢失记录
结论：排查时请求记录被清空。
原因：刷新页面或勾选了 Preserve log 未开启。
解法：勾选 Preserve log 保留跨页面请求。
```

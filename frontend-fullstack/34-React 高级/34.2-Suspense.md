## 概述

Suspense 是 React 声明式处理异步的机制：当一个组件「还没准备好」（数据未加载、代码未下载），Suspense 捕获它抛出的 Promise，先渲染 fallback，就绪后自动恢复真实内容。

```text
Suspense 解决的场景：
1. 代码分割 —— 懒加载组件（React.lazy）
2. 数据获取 —— 配合支持 Suspense 的数据源（React Query、Relay、use）
3. 流式 SSR —— 服务端边渲染边发送
```

```jsx
import { Suspense } from 'react';

function App() {
  return (
    <Suspense fallback={<Loading />}>
      <SomeAsyncComponent />
    </Suspense>
  );
}
```

```text
Suspense 的核心约定：
异步组件在「未就绪」时 throw 一个 Promise，
就绪后 throw 新数据（或正常返回），Suspense 负责捕获与重试。
```

## Suspense

Suspense 组件接收 `fallback` 与 `children`：当 children 中有组件处于等待状态时，渲染 fallback；等待结束自动切换回 children。

```jsx
import { Suspense } from 'react';

function Profile() {
  const data = useUserData();  // 未就绪时抛 Promise
  return <div>{data.name}</div>;
}

function Page() {
  return (
    <Suspense fallback={<div>加载中…</div>}>
      <Profile />
    </Suspense>
  );
}
```

```text
fallback 的渲染时机：
1. 首次挂载且子组件等待 → 立即显示 fallback
2. 已显示的内容再次等待 → 保持旧内容（配合 startTransition 时）
3. fallback 可以是任意 React 节点（骨架屏、加载动画）
```

```jsx
// 手动模拟「抛 Promise」的数据源（理解原理）
let cache = null;
function fetchUser() {
  if (!cache) {
    cache = new Promise(resolve =>
      setTimeout(() => resolve({ name: 'Alice' }), 1000)
    );
  }
  if (cache instanceof Promise) {
    throw cache;              // 未就绪：抛出 Promise
  }
  return cache;               // 已就绪：返回数据
}
```

## Suspense Boundary

Suspense Boundary 指每个 `<Suspense>` 划定的「等待边界」：边界内的组件等待不会影响边界外，边界之间相互独立。

```text
边界的作用：
1. 隔离等待范围 —— 只有边界内等待，外部照常渲染
2. 独立 fallback —— 不同区域显示不同的加载占位
3. 渐进式加载 —— 各边界按就绪顺序逐步填充
```

```jsx
function Dashboard() {
  return (
    <div>
      <Header />                              {/* 立即渲染 */}
      <Suspense fallback={<ChartSkeleton />}>
        <Charts />                            {/* 独立的等待区 */}
      </Suspense>
      <Suspense fallback={<TableSkeleton />}>
        <DataTable />                         {/* 另一独立等待区 */}
      </Suspense>
    </div>
  );
}
```

```text
边界设计原则：
1. 一个 Suspense 包裹「一组相关」的异步内容
2. 快速内容与慢内容分到不同边界，避免互相拖累
3. 不要整页包一个边界，那样退化成「整页 loading」
```

## Lazy

`React.lazy` 实现组件级代码分割：组件按需动态 import，加载期间由 Suspense 显示 fallback，减小首屏包体积。

```jsx
import { lazy, Suspense } from 'react';

// 动态导入：只在渲染时才加载对应 chunk
const HeavyChart = lazy(() => import('./HeavyChart'));

function App() {
  return (
    <Suspense fallback={<div>图表加载中…</div>}>
      <HeavyChart />
    </Suspense>
  );
}
```

```jsx
// 路由级懒加载（常见于路由表）
import { lazy } from 'react';
import { Routes, Route } from 'react-router-dom';

const Home = lazy(() => import('./pages/Home'));
const About = lazy(() => import('./pages/About'));

function AppRoutes() {
  return (
    <Suspense fallback={<PageLoading />}>
      <Routes>
        <Route path="/" element={<Home />} />
        <Route path="/about" element={<About />} />
      </Routes>
    </Suspense>
  );
}
```

```text
lazy 注意事项：
1. lazy 组件必须被 Suspense 包裹，否则报错
2. 默认导出需用 default，命名导出需用 .then 转换
3. 配合构建工具自动分包（Vite/Webpack）
```

## Streaming SSR

流式 SSR 让服务端边渲染边输出 HTML 片段，Suspense 边界即「流的分块点」：就绪一段发一段。

```text
流式 SSR 的协作：
1. 服务端渲染外壳并立即 flush
2. 遇到 Suspense 包裹的慢组件，先输出 fallback
3. 慢组件就绪后，把对应 HTML + 内联数据追加到流
4. 浏览器渐进式解析渲染，hydrate 补充交互
```

```jsx
// Next.js App Router 中，Suspense 边界天然支持流式
export default function Page() {
  return (
    <main>
      <h1>商品详情</h1>
      <Suspense fallback={<div>加载价格…</div>}>
        <Price />          {/* 慢查询，就绪后流式追加 */}
      </Suspense>
      <Suspense fallback={<div>加载评论…</div>}>
        <Reviews />        {/* 另一独立流式块 */}
      </Suspense>
    </main>
  );
}
```

```text
流式 SSR 的收益：
1. 用户更快看到首屏外壳（TTFB 降低）
2. 慢接口不再阻塞整页，逐块呈现
3. 结合 RSC 实现细粒度的流式内容
```

## Error Boundary

Suspense 只处理「等待中」，不处理「出错」。异步数据源失败时，需要 Error Boundary 捕获渲染错误并显示降级 UI。

```jsx
import { Suspense, Component } from 'react';

class ErrorBoundary extends Component {
  state = { hasError: false };
  static getDerivedStateFromError() {
    return { hasError: true };
  }
  render() {
    if (this.state.hasError) return <div>加载失败</div>;
    return this.props.children;
  }
}

function SafeAsync({ children }) {
  return (
    <ErrorBoundary>
      <Suspense fallback={<div>加载中…</div>}>
        {children}
      </Suspense>
    </ErrorBoundary>
  );
}
```

```text
Suspense 与 Error Boundary 的分工：
Suspense —— 处理「还没好」（等待 Promise resolve）
Error Boundary —— 处理「出错了」（渲染抛异常/数据源 reject）
两者叠加 = 完整的异步 UI 三态：加载中 / 成功 / 失败
```

## 应用场景实战

### 场景一：路由级代码分割

```jsx
import { lazy, Suspense } from 'react';
import { BrowserRouter, Routes, Route, Link } from 'react-router-dom';

const Dashboard = lazy(() => import('./Dashboard'));
const Settings = lazy(() => import('./Settings'));
const Reports = lazy(() => import('./Reports'));

export default function App() {
  return (
    <BrowserRouter>
      <nav>
        <Link to="/">Dashboard</Link>
        <Link to="/settings">Settings</Link>
        <Link to="/reports">Reports</Link>
      </nav>
      <Suspense fallback={<div>页面加载中…</div>}>
        <Routes>
          <Route path="/" element={<Dashboard />} />
          <Route path="/settings" element={<Settings />} />
          <Route path="/reports" element={<Reports />} />
        </Routes>
      </Suspense>
    </BrowserRouter>
  );
}
```

### 场景二：数据驱动的渐进式仪表盘

```jsx
import { Suspense } from 'react';

function Dashboard() {
  return (
    <div className="dashboard">
      <h2>运营总览</h2>

      <Suspense fallback={<Skeleton type="stat" />}>
        <StatCards />        {/* 关键指标先加载 */}
      </Suspense>

      <Suspense fallback={<Skeleton type="chart" />}>
        <TrendChart />       {/* 图表较慢，独立等待 */}
      </Suspense>

      <Suspense fallback={<Skeleton type="table" />}>
        <RecentOrders />     {/* 表格最慢，最后填充 */}
      </Suspense>
    </div>
  );
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. 用 Suspense 边界隔离慢内容，避免整页 loading
2. lazy 组件必须包裹 Suspense，路由懒加载必配 fallback
3. 每个 Suspense 配一个 ErrorBoundary，补全失败态
4. 按「就绪速度」划分边界，快慢内容分开
5. SSR 场景利用 Suspense 实现流式分块输出

### 踩坑记录

```text
坑 1：lazy 组件忘记包 Suspense
结论：运行时报「A component suspended while responding」。
原因：lazy 加载中抛 Promise，无 Suspense 捕获。
解法：lazy 组件外层必须包 Suspense。

坑 2：fallback 闪烁（内容已就绪却闪一下加载）
结论：已显示的内容切换时出现 loading 闪烁。
原因：未配合 startTransition，等待时直接替换成 fallback。
解法：用 startTransition 触发更新，保留旧内容直到新内容就绪。

坑 3：整页只包一个大 Suspense
结论：一个慢组件拖垮整页，首屏一片 loading。
原因：边界过大，所有异步内容共享一个 fallback。
解法：拆多个边界，按区域独立等待。

坑 4：异步数据源报错时页面卡死在 fallback
结论：一直显示加载中，因为错误没被处理。
原因：Suspense 不捕获 reject，错误向上冒泡。
解法：外层加 ErrorBoundary 捕获并展示失败 UI。

坑 5：在 Suspense 内用 useEffect 请求数据
结论：看不到 Suspense 的等待效果。
原因：普通 useEffect 请求不抛 Promise，Suspense 感知不到。
解法：使用支持 Suspense 的数据源（React Query 的 suspense 模式、use()）。
```

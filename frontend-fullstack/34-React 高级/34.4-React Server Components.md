## 概述

React Server Components（RSC）让组件在**服务端**渲染，只把结果（HTML + 序列化数据）发送给客户端。服务端组件可以直接访问数据库、文件系统等后端资源，且不会增加客户端 JS 体积。

```text
RSC 的核心价值：
1. 零客户端 JS —— 服务端组件不打进客户端 bundle
2. 直连后端 —— 服务端组件可直接查库、读文件
3. 更好的性能 —— 减少客户端下载与解析量
4. 数据获取靠近数据源 —— 少一次 API 往返
```

```text
RSC 与传统 SSR 的区别：
SSR —— 服务端把组件渲染成 HTML 字符串，客户端仍需下载全部 JS 并 hydrate
RSC —— 服务端组件永远只在服务端运行，客户端不下载其代码，
      客户端组件则按需交互，两者混合组成一棵树
```

```jsx
// 服务端组件（默认，无 'use client'）
// 可以直接访问数据库
import { db } from '@/db';

export default async function UserList() {
  const users = await db.query('SELECT * FROM users');  // 直接在服务端查询
  return (
    <ul>
      {users.map(u => <li key={u.id}>{u.name}</li>)}
    </ul>
  );
}
```

## Server Component

Server Component 是默认的组件类型（不写 `'use client'`），只在服务端执行，可访问后端资源，不能使用交互类 Hook 与浏览器 API。

```jsx
// app/page.jsx（服务端组件）
export default async function Page() {
  const posts = await fetch('https://api.example.com/posts')
    .then(r => r.json());

  return (
    <main>
      <h1>文章列表</h1>
      {posts.map(p => <PostCard key={p.id} post={p} />)}
    </main>
  );
}
```

```text
Server Component 的能做什么 / 不能做什么：
能 —— 直接查数据库、读文件、fetch 后端接口、访问环境变量
不能 —— useState/useEffect、事件处理（onClick）、浏览器 API（localStorage）、
       Context 的 Provider（可用部分受限场景）
```

```text
Server Component 的约束原因：
它们不会被打包到客户端，代码里若出现交互逻辑，
会在「序列化边界」处报错，提醒开发者改用客户端组件。
```

## Client Component

Client Component 用 `'use client'` 声明，会被打包发送到浏览器，支持交互、Hooks、浏览器 API。它是「传统 React 组件」在 RSC 体系中的角色。

```jsx
'use client';

import { useState } from 'react';

export default function LikeButton() {
  const [liked, setLiked] = useState(false);

  return (
    <button onClick={() => setLiked(!liked)}>
      {liked ? '已赞' : '点赞'}
    </button>
  );
}
```

```text
Client Component 的特点：
1. 在浏览器中运行（也可在服务端做 SSR 预渲染）
2. 支持事件、状态、Effects、浏览器 API
3. 会进入客户端 bundle，增加 JS 体积
4. 服务端组件可以把客户端组件作为子组件「传下去」
```

```jsx
// 服务端组件组合客户端组件：Server 做数据，Client 做交互
import LikeButton from './LikeButton';  // 客户端组件

export default async function Post({ id }) {
  const post = await getPost(id);       // 服务端取数据

  return (
    <article>
      <h2>{post.title}</h2>
      <p>{post.content}</p>
      <LikeButton initialCount={post.likes} />
    </article>
  );
}
```

## Server Action

Server Action 是在服务端运行的函数，客户端可以直接调用（表单提交、按钮点击），无需手动定义 API 路由。

```jsx
// app/actions.js（服务端 Action）
'use server';

export async function createPost(formData) {
  const title = formData.get('title');
  const content = formData.get('content');
  await db.insert('posts', { title, content });
  return { ok: true };
}
```

```jsx
// app/page.jsx（客户端/服务端组件中调用）
import { createPost } from './actions';

export default function NewPost() {
  return (
    <form action={createPost}>
      <input name="title" placeholder="标题" />
      <textarea name="content" placeholder="内容" />
      <button type="submit">发布</button>
    </form>
  );
}
```

```jsx
// 客户端组件中用 startTransition 调用 Action 并拿到结果
'use client';

import { useTransition } from 'react';
import { createPost } from './actions';

export function SubmitButton() {
  const [isPending, startTransition] = useTransition();

  const onClick = () => {
    startTransition(async () => {
      const result = await createPost({ title: 'hello' });
      console.log(result.ok);
    });
  };

  return <button disabled={isPending} onClick={onClick}>发布</button>;
}
```

```text
Server Action 的优势：
1. 免去手写 API 路由，前端直接调用后端逻辑
2. 表单可无 JS 渐进增强（action 属性原生提交）
3. 自动处理序列化、错误、重定向
```

## Serialization Boundary

Serialization Boundary 是「服务端组件 → 客户端组件」的边界：服务端组件要把 props 传给客户端组件时，这些 props 必须能被序列化（JSON 安全）。

```text
序列化边界的规则：
1. 从 Server 传给 Client 的 props 必须是可序列化的
2. 函数、类实例、Date 等需特殊处理（RSC 支持部分扩展类型）
3. 不能把「服务端函数」直接传给客户端组件（除非是 Server Action）
```

```jsx
// 正确：传普通数据（可序列化）
export default async function Page() {
  const post = await getPost(1);
  return <LikeButton postId={post.id} title={post.title} />;
}

// 错误：传函数（不可序列化，会报错）
export default async function Page() {
  const handler = () => console.log('hi');
  return <Child onClick={handler} />;  // 报错：函数不能跨边界
}
```

```text
常见踩坑：
1. 传了函数/类实例 → 序列化失败报错
2. 传了带方法的对象 → 方法丢失
3. 大数据 prop → 序列化体积大，注意精简
```

## Streaming

Streaming 在 RSC 体系下指：服务端组件边渲染边把结果（HTML + RSC Payload）流式发送，客户端渐进式渲染，慢组件不阻塞首屏。

```jsx
// app/page.jsx：用 Suspense 让慢组件流式加载
import { Suspense } from 'react';

export default function Page() {
  return (
    <div>
      <Header />                              {/* 立即输出 */}
      <Suspense fallback={<p>加载评论…</p>}>
        <Comments />                          {/* 就绪后流式追加 */}
      </Suspense>
    </div>
  );
}
```

```text
流式渲染的协作：
1. 服务端先发送「外壳」HTML
2. 慢组件挂起时，先发 fallback 占位
3. 组件就绪后，把它的 HTML + Payload 作为后续块追加
4. 客户端收到片段即渲染（无需等整页）
```

## RSC Payload

RSC Payload 是服务端发给客户端的「渲染结果描述」：包含组件树结构的引用、序列化的 props 数据、Suspense 边界信息等。客户端据此重建视图，而非下载组件代码。

```text
RSC Payload 的内容：
1. 渲染后的 HTML 片段
2. 序列化的 props（跨边界数据）
3. 组件树的引用信息（哪些是 Server/Client 组件）
4. Suspense 边界的占位与恢复点
```

```text
Payload 的格式示意（简化）：
1:["$","div",null,{"children":[...]}]
2:["$","h1",null,{"children":"标题"}]
M:{"clientRef":"...","chunk":...}
（实际为 React Flight 协议，包含元素描述、数据、指令）
```

```js
// 客户端消费 payload 的流程（简化概念）
async function renderPage() {
  const stream = await fetch('/page', { headers: { RSC: '1' } });
  const payload = await parseFlightStream(stream);
  // 根据 payload 重建组件树并渲染，无需下载服务端组件代码
  renderFromPayload(payload);
}
```

## 应用场景实战

### 场景一：商品详情页（数据在服务端，交互在客户端）

```jsx
// app/product/[id]/page.jsx（服务端组件）
import { Suspense } from 'react';
import { getProduct, getReviews } from '@/db';
import AddToCart from './AddToCart';

export default async function ProductPage({ params }) {
  const product = await getProduct(params.id);

  return (
    <article>
      <h1>{product.name}</h1>
      <p>{product.description}</p>
      <AddToCart productId={product.id} price={product.price} />
      <Suspense fallback={<p>加载评论…</p>}>
        <Reviews reviews={await getReviews(params.id)} />
      </Suspense>
    </article>
  );
}
```

```jsx
// app/product/[id]/AddToCart.jsx（客户端组件）
'use client';

import { useState, useTransition } from 'react';
import { addToCart } from './actions';

export default function AddToCart({ productId, price }) {
  const [qty, setQty] = useState(1);
  const [isPending, startTransition] = useTransition();

  const onClick = () => {
    startTransition(async () => {
      await addToCart({ productId, qty });
    });
  };

  return (
    <div>
      <input type="number" value={qty} onChange={e => setQty(+e.target.value)} />
      <button disabled={isPending} onClick={onClick}>
        加入购物车（￥{price * qty}）
      </button>
    </div>
  );
}
```

### 场景二：表单提交（Server Action）

```jsx
// app/actions.js
'use server';

export async function submitContact(formData) {
  const name = formData.get('name');
  const email = formData.get('email');
  await db.insert('contacts', { name, email });
  return { ok: true };
}
```

```jsx
// app/contact/page.jsx
import { submitContact } from './actions';

export default function ContactPage() {
  return (
    <form action={submitContact}>
      <input name="name" required placeholder="姓名" />
      <input name="email" type="email" required placeholder="邮箱" />
      <button type="submit">提交</button>
    </form>
  );
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. 默认用服务端组件，需要交互/Hooks 时才加 'use client'
2. 数据获取放在服务端组件，交互下放到「叶子」客户端组件
3. 客户端组件尽量小而专，减少进入 bundle 的代码
4. 慢数据用 Suspense 包裹，实现流式渲染
5. 表单优先用 Server Action，免去手写 API

### 踩坑记录

```text
坑 1：给服务端组件加 useState/onClick
结论：运行时报错「useState 不能在 Server Component 使用」。
原因：服务端组件无交互能力，不进客户端 bundle。
解法：把交互部分拆成 'use client' 组件。

坑 2：跨边界传不可序列化的 props
结论：传函数/类实例时报序列化错误。
原因：Server → Client 的 props 必须 JSON 安全。
解法：只传普通数据，函数用 Server Action 或放客户端。

坑 3：客户端组件里直接查数据库
结论：构建报错或运行时报错。
原因：数据库逻辑只在服务端可用，客户端无此环境。
解法：数据获取放服务端组件，通过 props 传给客户端组件。

坑 4：把大对象整体传给客户端组件
结论：Payload 体积膨胀，首屏变慢。
原因：跨边界数据都要序列化传输。
解法：只传客户端真正需要的字段，服务端做裁剪。

坑 5：误解 RSC 会消除所有客户端 JS
结论：以为加了 RSC 就没有 bundle 了。
原因：客户端组件、框架运行时仍需下载。
解法：合理划分组件，最大化服务端渲染比例。
```

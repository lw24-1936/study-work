## 概述

Context 用于跨层级传递数据，避免「逐层传 props」（prop drilling）。它适合全局性的、变化不频繁的数据，如主题、语言、用户信息、依赖注入。

```text
Context 的组成：
1. createContext —— 创建上下文对象
2. Provider —— 提供值，包裹子树
3. Consumer/useContext —— 消费值
```

```jsx
import { createContext, useContext } from 'react';

const ThemeContext = createContext('light');  // 默认值

function ThemedButton() {
  const theme = useContext(ThemeContext);
  return <button className={theme}>按钮</button>;
}

<ThemeContext.Provider value="dark">
  <ThemedButton />  {/* 读到 dark */}
</ThemeContext.Provider>;
```

```text
适用场景：
主题、语言、当前用户、路由、依赖注入、全局配置。
不适用场景：高频变化的状态（用状态管理库更合适）。
```

## Context Provider

Provider 为子树提供 Context 值。值变化时，所有消费该 Context 的组件都会重新渲染。

```jsx
import { createContext, useState } from 'react';

const ThemeContext = createContext('light');

function ThemeProvider({ children }) {
  const [theme, setTheme] = useState('light');
  const toggle = () => setTheme(t => (t === 'light' ? 'dark' : 'light'));

  // 把 value 和操作一起提供（注意：value 是新对象）
  return (
    <ThemeContext.Provider value={{ theme, toggle }}>
      {children}
    </ThemeContext.Provider>
  );
}

function App() {
  return (
    <ThemeProvider>
      <Content />
    </ThemeProvider>
  );
}
```

```jsx
// 嵌套 Provider：内层覆盖外层
<ThemeContext.Provider value="dark">
  <ThemeContext.Provider value="light">
    <ThemedButton />  {/* 读到 light（最近的 Provider 生效） */}
  </ThemeContext.Provider>
</ThemeContext.Provider>;
```

## Consumer

消费 Context 有两种方式：`useContext` Hook（推荐）与 `Context.Consumer` 渲染属性（旧写法、类组件可用）。

```jsx
import { useContext } from 'react';

// 方式一：useContext Hook（现代推荐）
function Header() {
  const { theme } = useContext(ThemeContext);
  return <header className={theme}>标题</header>;
}
```

```jsx
// 方式二：Context.Consumer 渲染属性
function Header() {
  return (
    <ThemeContext.Consumer>
      {({ theme }) => <header className={theme}>标题</header>}
    </ThemeContext.Consumer>
  );
}
```

```jsx
// 封装成自定义 Hook，让消费语义更清晰、可校验
function useTheme() {
  const ctx = useContext(ThemeContext);
  if (ctx === undefined) {
    throw new Error('useTheme 必须在 ThemeProvider 内使用');
  }
  return ctx;
}
```

## Context Performance

Context 最大的性能隐患：Provider 的 value 变化会导致所有消费者（即使只用其中一部分）全部重渲染。需要精细控制 value 的引用稳定性。

```text
性能问题的根源：
1. value 每次渲染都新建对象 → 所有消费者重渲染
2. 大而全的 Context → 任何字段变化都波及全体
3. 消费者不做记忆化 → 无关更新也无法跳过
```

```jsx
// 问题：value 内联对象，每次渲染都变
function App() {
  const [user, setUser] = useState(null);
  return (
    <AuthContext.Provider value={{ user, setUser }}>  {/* 每次新对象 */}
      <Content />
    </AuthContext.Provider>
  );
}
```

```jsx
// 解法：用 useMemo 稳定 value 引用
function App() {
  const [user, setUser] = useState(null);
  const value = useMemo(() => ({ user, setUser }), [user]);
  return (
    <AuthContext.Provider value={value}>
      <Content />
    </AuthContext.Provider>
  );
}
```

```jsx
// 解法：拆分 Context + memo 让无关消费者跳过
const UserContext = createContext(null);
const DispatchContext = createContext(null);

function UserProvider({ children }) {
  const [user, setUser] = useState(null);
  return (
    <UserContext.Provider value={user}>
      <DispatchContext.Provider value={setUser}>
        {children}
      </DispatchContext.Provider>
    </UserContext.Provider>
  );
}
```

## Context Splitting

Context Splitting 是把一个大 Context 拆成多个职责单一的 Context，让不同消费者只订阅自己关心的部分，减少无谓的重渲染。

```text
拆分策略：
1. 按「读频率」拆 —— 高频变化的字段与低频字段分开
2. 按「领域」拆 —— 用户信息、主题、权限各自独立
3. 值变化快的用 Context，更新动作用独立的 DispatchContext
```

```jsx
// 拆成「状态」与「更新函数」两个 Context
const CountContext = createContext(0);
const CountDispatchContext = createContext(null);

function CountProvider({ children }) {
  const [count, setCount] = useState(0);
  return (
    <CountContext.Provider value={count}>
      <CountDispatchContext.Provider value={setCount}>
        {children}
      </CountDispatchContext.Provider>
    </CountContext.Provider>
  );
}

// 只读状态的组件：只在 count 变化时重渲染
function ReadCount() {
  const count = useContext(CountContext);
  return <span>{count}</span>;
}

// 只触发更新的组件：永远不因 count 变化而重渲染
function IncrementButton() {
  const setCount = useContext(CountDispatchContext);
  return <button onClick={() => setCount(c => c + 1)}>+1</button>;
}
```

```text
拆分后收益：
1. 读状态的组件只受状态变化影响
2. 触发更新的组件（setCount 引用稳定）几乎不重渲染
3. 减少 Context 引起的瀑布式重渲染
```

## 应用场景实战

### 场景一：主题切换

```jsx
import { createContext, useContext, useMemo, useState } from 'react';

const ThemeContext = createContext({ theme: 'light', toggle: () => {} });

function ThemeProvider({ children }) {
  const [theme, setTheme] = useState('light');
  const value = useMemo(
    () => ({ theme, toggle: () => setTheme(t => (t === 'light' ? 'dark' : 'light')) }),
    [theme]
  );
  return <ThemeContext.Provider value={value}>{children}</ThemeContext.Provider>;
}

function useTheme() {
  return useContext(ThemeContext);
}

function App() {
  return (
    <ThemeProvider>
      <Toolbar />
    </ThemeProvider>
  );
}

function Toolbar() {
  const { theme, toggle } = useTheme();
  return (
    <div style={{ background: theme === 'dark' ? '#222' : '#fff' }}>
      <button onClick={toggle}>切换主题</button>
    </div>
  );
}
```

### 场景二：全局用户认证

```jsx
import { createContext, useContext, useState, useMemo } from 'react';

const AuthContext = createContext(null);

function AuthProvider({ children }) {
  const [user, setUser] = useState(null);

  const login = async (cred) => {
    const u = await apiLogin(cred);
    setUser(u);
  };
  const logout = () => setUser(null);

  const value = useMemo(() => ({ user, login, logout }), [user]);
  return <AuthContext.Provider value={value}>{children}</AuthContext.Provider>;
}

function useAuth() {
  const ctx = useContext(AuthContext);
  if (!ctx) throw new Error('useAuth 必须在 AuthProvider 内使用');
  return ctx;
}

function UserMenu() {
  const { user, logout } = useAuth();
  return user
    ? <button onClick={logout}>{user.name}（退出）</button>
    : <a href="/login">登录</a>;
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. Context 存「变化不频繁」的全局数据，高频状态用状态库
2. 拆分 Context，消费者只订阅自己需要的部分
3. 用 useMemo 稳定 Provider 的 value 引用
4. 封装 useXxx 自定义 Hook，统一消费并做边界校验
5. 状态与更新函数分开两个 Context，降低重渲染

### 踩坑记录

```text
坑 1：Provider value 内联对象导致全量重渲染
结论：value 变了，所有消费者都重渲染。
原因：每次渲染创建新对象，引用变化。
解法：useMemo 包裹 value，或拆分 Context。

坑 2：把高频状态放进 Context
结论：输入框每敲一个字，整棵子树重渲染。
原因：Context 变化会通知所有消费者，粒度太粗。
解法：高频局部状态留在组件内，或用状态库/拆分 Context。

坑 3：Provider 外的消费者读到默认值
结论：读到默认值而非期望的数据，或 undefined。
原因：组件不在对应 Provider 子树内。
解法：确保层级正确，自定义 Hook 内做 undefined 校验并抛错。

坑 4：用 Context 传递「更新函数」却导致重渲染
结论：只触发更新的按钮也随状态变化重渲染。
原因：状态和函数在同一个 Context，value 一起变。
解法：拆出独立的 DispatchContext，函数引用保持稳定。

坑 5：Context 大而全，牵一发动全身
结论：加一个字段，所有消费者都要评估重渲染。
原因：单一 Context 塞入过多不相关数据。
解法：按领域拆分成多个小 Context。
```

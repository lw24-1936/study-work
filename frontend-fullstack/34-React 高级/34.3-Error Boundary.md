## 概述

Error Boundary（错误边界）是 React 用于捕获「子组件渲染期间抛出的错误」的组件，防止单个组件崩溃导致整棵应用白屏。它通过类组件的两个生命周期方法实现。

```text
错误边界能捕获什么：
1. 子组件渲染期间抛出的错误
2. 子组件生命周期方法中的错误
3. 子组件构造函数中的错误

不能捕获什么：
1. 事件处理器中的错误（不发生在渲染期）
2. 异步代码（setTimeout、Promise）中的错误
3. 服务端渲染中的错误
4. 错误边界自身抛出的错误
```

```jsx
// 最小错误边界实现
import { Component } from 'react';

class ErrorBoundary extends Component {
  state = { hasError: false };

  static getDerivedStateFromError(error) {
    // 渲染期间出错时更新 state，触发降级 UI
    return { hasError: true };
  }

  componentDidCatch(error, info) {
    // 记录错误日志、上报监控
    console.error(error, info.componentStack);
  }

  render() {
    if (this.state.hasError) {
      return this.props.fallback || <div>出错了</div>;
    }
    return this.props.children;
  }
}
```

## Error Boundary

错误边界本质是「用类组件包裹子树，把渲染错误拦截在局部」，React 目前只能用类组件实现（Hooks 无对应机制）。

```text
两个关键生命周期：
1. getDerivedStateFromError —— 返回新 state 以渲染降级 UI（渲染阶段）
2. componentDidCatch —— 用于记录日志、上报（提交阶段）
```

```jsx
class AppErrorBoundary extends Component {
  constructor(props) {
    super(props);
    this.state = { hasError: false, error: null };
  }

  static getDerivedStateFromError(error) {
    return { hasError: true, error };
  }

  componentDidCatch(error, errorInfo) {
    // 上报到监控平台
    reportError({ error, componentStack: errorInfo.componentStack });
  }

  render() {
    if (this.state.hasError) {
      return (
        <div className="error-screen">
          <h2>页面出错了</h2>
          <p>{this.state.error?.message}</p>
        </div>
      );
    }
    return this.props.children;
  }
}
```

```text
错误边界的位置设计：
1. 顶层边界 —— 兜底，防止整页白屏
2. 区域边界 —— 隔离功能模块，一个坏了不影响其他
3. 细粒度边界 —— 包裹易出错的组件（图表、富文本）
```

## Fallback

Fallback 是错误发生时展示的降级 UI，应尽量保留上下文信息，并给出可操作的出口（重试、回首页）。

```jsx
function ErrorFallback({ error, reset }) {
  return (
    <div className="error-fallback">
      <h2>渲染出错了</h2>
      <pre>{error?.message}</pre>
      <button onClick={reset}>重试</button>
      <a href="/">返回首页</a>
    </div>
  );
}

class ErrorBoundary extends Component {
  state = { hasError: false, error: null };
  static getDerivedStateFromError(error) {
    return { hasError: true, error };
  }
  reset = () => this.setState({ hasError: false, error: null });
  render() {
    if (this.state.hasError) {
      return <ErrorFallback error={this.state.error} reset={this.reset} />;
    }
    return this.props.children;
  }
}
```

```text
好的 fallback 应具备：
1. 明确提示「出错了」，而非白屏
2. 展示错误信息或错误码，便于排查
3. 提供重试、返回等操作，不把用户困住
```

## Error Recovery

Error Recovery 指从错误中恢复的能力：通过 key 重置、重试机制、状态重置等手段，让出错区域重新渲染。

```text
恢复的几种手段：
1. 重置边界 state —— 重新渲染 children
2. 改变 key —— 强制重建子树，清空错误状态
3. 重置关联数据源 —— 配合边界重试重新拉取
```

```jsx
class RecoverableBoundary extends Component {
  state = { hasError: false };
  static getDerivedStateFromError() {
    return { hasError: true };
  }
  retry = () => this.setState({ hasError: false });
  render() {
    if (this.state.hasError) {
      return (
        <div>
          <p>加载失败，请重试</p>
          <button onClick={this.retry}>重新加载</button>
        </div>
      );
    }
    return this.props.children;
  }
}
```

```jsx
// 用 key 强制重建出错组件（配合 Error Boundary）
function ProductDetail({ productId }) {
  return (
    <ErrorBoundary key={productId}>
      <ProductContent id={productId} />
    </ErrorBoundary>
  );
  // productId 变化 → key 变化 → 边界与子树重建，自动清除旧错误
}
```

```jsx
// 函数式重试组件（无 key 时手动重置）
function withErrorReset(Component) {
  return function Wrapper(props) {
    const [errorKey, setErrorKey] = useState(0);
    return (
      <ErrorBoundary
        key={errorKey}
        fallback={
          <div>
            <p>出错了</p>
            <button onClick={() => setErrorKey(k => k + 1)}>重试</button>
          </div>
        }
      >
        <Component {...props} />
      </ErrorBoundary>
    );
  };
}
```

## 应用场景实战

### 场景一：全局兜底 + 模块隔离

```jsx
import { Component } from 'react';

class ErrorBoundary extends Component {
  state = { hasError: false };
  static getDerivedStateFromError() {
    return { hasError: true };
  }
  componentDidCatch(error, info) {
    reportError({ error, stack: info.componentStack });
  }
  render() {
    if (this.state.hasError) return this.props.fallback;
    return this.props.children;
  }
}

function App() {
  return (
    <ErrorBoundary fallback={<GlobalError />}>
      <Header />
      <main>
        <ErrorBoundary fallback={<ChartError />}>
          <Charts />            {/* 图表出错不影响其他区域 */}
        </ErrorBoundary>
        <ErrorBoundary fallback={<TableError />}>
          <DataTable />
        </ErrorBoundary>
      </main>
      <Footer />
    </ErrorBoundary>
  );
}
```

### 场景二：懒加载组件的错误兜底

```jsx
import { lazy, Suspense } from 'react';

const Report = lazy(() => import('./Report'));

function ReportSection() {
  return (
    <ErrorBoundary fallback={<div>报表加载失败</div>}>
      <Suspense fallback={<div>报表加载中…</div>}>
        <Report />
      </Suspense>
    </ErrorBoundary>
  );
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. 用「顶层 + 区域」两级边界：全局兜底、模块隔离
2. fallback 提供重试/返回操作，别让用户被困
3. componentDidCatch 中上报错误，配合监控追踪
4. 结合 key 实现错误后的自动重建与恢复
5. 易出错的第三方组件单独包边界

### 踩坑记录

```text
坑 1：误以为边界能捕获事件处理器错误
结论：按钮点击报错导致白屏，边界没拦住。
原因：事件处理器错误不经过渲染阶段，边界不捕获。
解法：事件内 try/catch，或全局 window.onerror 兜底。

坑 2：异步错误（Promise/setTimeout）没被捕获
结论：请求失败、定时器报错时边界无效。
原因：边界只捕获渲染期同步错误。
解法：异步代码内 try/catch，Promise 加 .catch。

坑 3：错误边界自身抛错导致整树崩溃
结论：fallback 渲染本身出错，错误继续向上冒泡。
原因：fallback 逻辑不健壮。
解法：fallback 保持简单，最外层再加一层兜底。

坑 4：用函数组件实现错误边界
结论：无法捕获子组件渲染错误。
原因：React 只认类组件的两个生命周期方法。
解法：用类组件实现（或第三方库如 react-error-boundary）。

坑 5：错误后不重置导致一直显示降级 UI
结论：数据恢复了但界面仍停在错误页。
原因：边界 state.hasError 一旦为 true 不会自动复位。
解法：提供重试按钮、用 key 强制重建。
```

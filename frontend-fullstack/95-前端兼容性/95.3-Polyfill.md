## 概述

Polyfill（垫片）是在运行时补齐浏览器缺失 API 的代码，让老浏览器能使用新特性。核心库是 core-js（标准库 polyfill 大全）和 regenerator-runtime（async/await 转译后的运行时支持）。此外 Promise、Fetch、IntersectionObserver、ResizeObserver 是前端最高频需要单独 polyfill 的 API。

```text
前端常用 polyfill 清单：
1. core-js —— 标准库 polyfill 大全，按需引入 Promise/Array/Map 等
2. regenerator —— async/await 转译后的 generator 运行时
3. Promise —— 异步基础，老浏览器缺失需补
4. Fetch —— 网络请求 API，缺失时用 whatwg-fetch 或 XHR 兜底
5. IntersectionObserver —— 懒加载/曝光埋点依赖，需补
6. ResizeObserver —— 监听元素尺寸变化，需补
```

```js
// polyfill 的通用模式：能力缺失才注入
if (!window.Promise) {
  // 加载或注入 Promise 实现
}
// 业务代码无感使用
new Promise(r => r('ok')).then(console.log);
```

## core-js

core-js 是 JavaScript 标准库的 polyfill 集合，覆盖 Promise、Symbol、Array.prototype.includes、Map/Set、Object.assign 等几乎所有 ES 新 API。配合 Babel 的 useBuiltIns: 'usage' 可以按代码实际用到的 API 自动注入最小集合。

```js
// 手动按需引入 core-js（不依赖构建工具时）
import 'core-js/stable/promise';
import 'core-js/stable/array/includes';
import 'core-js/stable/object/assign';

// 或配合 Babel 自动注入（推荐）
// babel.config.js:
// presets: [['@babel/preset-env', { useBuiltIns: 'usage', corejs: 3 }]]
```

```text
core-js 的要点：
1. 全覆盖 —— ES 新 API 几乎都能在这里找到
2. 按需引入 —— useBuiltIns: 'usage' 只注入代码用到的
3. 版本 —— corejs: 3 是当前主流，别用已弃用的 2
4. 全局污染 —— 默认改全局，介意用 core-js-pure（不污染）
```

## regenerator

regenerator-runtime 是 async/await 和 generator 函数转译后的运行时支持库。Babel 把 async 函数转成 generator + regenerator 驱动，老浏览器需要这个运行时才能执行转译结果。

```js
// async 函数转译前后对照
// 转译前
async function getData() {
  const res = await fetch('/api');
  return res.json();
}

// 转译后（简化示意）依赖 regeneratorRuntime 标记 generator
// var getData = function getData() {
//   return regeneratorRuntime.async(function getData$(_context) { ... });
// };
```

```text
regenerator 的要点：
1. 运行时依赖 —— async/await 转译产物需要它驱动
2. 自动引入 —— @babel/preset-env 转 async 时自动加 regenerator-runtime
3. 体积可观 —— 目标浏览器都支持 async 时（现代浏览器）可不引入
4. 替代 —— 用 @babel/plugin-transform-runtime 避免重复注入
```

## Promise

Promise 是异步编程的基础，IE 11 及老浏览器缺失。polyfill 常用 core-js 的 Promise 实现，或独立库 es6-promise。补上后 async/await 与 then 链才能正常跑。

```js
// Promise polyfill 的判定与用法
if (typeof Promise === 'undefined') {
  // 引入 core-js 的 Promise（构建时）或动态加载
  // import 'core-js/stable/promise';
  // 或在 script 标签里先加载 polyfill
}

// 补上后业务代码无感
Promise.all([fetch1(), fetch2()])
  .then(([a, b]) => console.log(a, b))
  .catch(err => console.error(err));
```

```text
Promise 的要点：
1. 缺失范围 —— IE 11 及更老、老 WebView
2. 补齐来源 —— core-js / es6-promise
3. 连带需求 —— async/await 转译后也依赖 Promise
4. 微任务 —— 优质 polyfill 用 queueMicrotask/setTimeout 模拟
```

## Fetch

Fetch 是现代的 XHR 替代，老浏览器（IE 全系）缺失。polyfill 用 whatwg-fetch（基于 XHR 实现），或 github/fetch。补上后 fetch API 即可在老浏览器使用。

```js
// Fetch polyfill：缺失时引入 whatwg-fetch
if (!window.fetch) {
  // 构建时 import 'whatwg-fetch';
  // 或运行时动态注入
  const s = document.createElement('script');
  s.src = 'https://cdn.jsdelivr.net/npm/whatwg-fetch@3/dist/fetch.umd.js';
  document.head.appendChild(s);
}

// 业务代码无感使用
fetch('/api/users')
  .then(res => res.json())
  .then(data => console.log(data));
```

```text
Fetch 的要点：
1. 缺失范围 —— IE 全系不支持
2. 补齐来源 —— whatwg-fetch（基于 XHR）
3. 差异 —— polyfill 的 fetch 不支持部分能力（如 abort、流式响应体）
4. 判断 —— 用 'fetch' in window 检测
```

## IntersectionObserver

IntersectionObserver（IO）监听元素进出视口，广泛用于懒加载、无限滚动、曝光埋点。老浏览器（Safari < 12.1、IE 全系）缺失，需要 polyfill 或降级到 scroll 监听。

```js
// IntersectionObserver polyfill：缺失时引入或降级
function observeLazy(imgs) {
  if ('IntersectionObserver' in window) {
    const io = new IntersectionObserver((entries) => {
      entries.forEach(e => {
        if (e.isIntersecting) { e.target.src = e.target.dataset.src; io.unobserve(e.target); }
      });
    });
    imgs.forEach(img => io.observe(img));
  } else {
    // 降级：scroll 监听 + getBoundingClientRect
    window.addEventListener('scroll', () => {
      imgs.forEach(img => {
        const r = img.getBoundingClientRect();
        if (r.top < innerHeight && r.bottom > 0 && img.dataset.src) {
          img.src = img.dataset.src;
          delete img.dataset.src;
        }
      });
    });
  }
}
```

```text
IntersectionObserver 的要点：
1. 缺失范围 —— IE 全系、Safari < 12.1
2. 补齐来源 —— intersection-observer polyfill 或手写降级
3. 降级代价 —— scroll 监听触发频繁，需节流
4. 用途 —— 懒加载、无限滚动、元素曝光统计
```

## ResizeObserver

ResizeObserver 监听元素尺寸变化，用于响应式组件、图表自适应、容器查询兜底。支持晚于 IO（Safari < 13.1 缺失），老浏览器需 polyfill。

```js
// ResizeObserver polyfill：缺失时引入 resize-observer-polyfill
if (!('ResizeObserver' in window)) {
  // 构建时 import ResizeObserver from 'resize-observer-polyfill';
  // window.ResizeObserver = ResizeObserver;
}

// 业务代码无感使用：监听容器尺寸变化重绘图表
const ro = new ResizeObserver((entries) => {
  for (const entry of entries) {
    const { width, height } = entry.contentRect;
    console.log('尺寸变化', width, height);
    redrawChart(width, height);
  }
});
ro.observe(document.querySelector('#chart'));
```

```text
ResizeObserver 的要点：
1. 缺失范围 —— Safari < 13.1、IE 全系
2. 补齐来源 —— resize-observer-polyfill
3. 比 window resize 精细 —— 监听单个元素而非整个窗口
4. 用途 —— 图表自适应、容器尺寸驱动布局、长列表重算
```

## 应用场景实战

### 场景一：一次引入全部所需 polyfill

```js
// 入口文件按需引入，构建时用 useBuiltIns 自动注入更省心
// 手动方式：
import 'core-js/stable';
import 'regenerator-runtime/runtime';
import 'whatwg-fetch';

// 自动方式（推荐）：babel.config.js
// module.exports = {
//   presets: [['@babel/preset-env', {
//     targets: '> 0.5%, last 2 versions, not dead',
//     useBuiltIns: 'usage',
//     corejs: 3,
//   }]],
// };
// 这样 Promise/fetch/IO/RO 等都会按代码使用情况自动补齐
```

### 场景二：运行时动态按需加载 polyfill

```js
// 不把 polyfill 打进主包，运行时按需动态加载，减小首屏体积
async function ensurePolyfills() {
  const tasks = [];
  if (!window.Promise) {
    tasks.push(import(/* webpackChunkName: "polyfill-promise" */ 'core-js/stable/promise'));
  }
  if (!window.IntersectionObserver) {
    tasks.push(import('intersection-observer'));
  }
  if (!window.ResizeObserver) {
    tasks.push(import('resize-observer-polyfill'));
  }
  await Promise.all(tasks);
}

ensurePolyfills().then(() => {
  // 补完后启动应用
  bootstrapApp();
});
```

## 最佳实践与踩坑记录

### 最佳实践

1. 用 useBuiltIns: 'usage' 按需注入 polyfill，别全量打包
2. 检测到能力缺失才加载 polyfill，现代浏览器零开销
3. 优先选择官方/社区成熟实现（core-js、whatwg-fetch），别手写
4. 老浏览器对非关键特性用降级而非硬 polyfill，减小体积
5. 关注 polyfill 的行为差异（如 fetch polyfill 不支持 abort）
6. 定期用 caniuse 核对目标浏览器，移除已不再需要的 polyfill

### 踩坑记录

```text
坑 1：全量引入 core-js/stable
结论：bundle 体积暴涨几十 KB，首屏变慢。
原因：把整个 core-js 打进去，不管代码用没用。
解法：useBuiltIns: 'usage' 按代码实际用到的 API 自动注入。

坑 2：只 polyfill fetch 不 polyfill Promise
结论：老浏览器报 Promise is not defined。
原因：whatwg-fetch 内部依赖 Promise，Promise 缺失它跑不了。
解法：Promise 和 fetch 一起补，顺序上先补 Promise。

坑 3：手写 Promise polyfill 用于生产
结论：边界情况处理不全，出现难以排查的 bug。
原因：Promise 规范复杂，手写实现难覆盖 thenable/异常等细节。
解法：用 core-js / es6-promise 等成熟实现。

坑 4：以为 polyfill 能解决语法问题
结论：老浏览器解析箭头函数报 SyntaxError，polyfill 没生效。
原因：polyfill 只补 API，不降语法，新语法要转译。
解法：语法交给 Babel 转译，API 交给 polyfill，两者配合。

坑 5：fetch polyfill 不支持 abort
结论：老浏览器上 AbortController 取消请求无效。
原因：whatwg-fetch 的部分能力与原生 fetch 有差距。
解法：对依赖 abort 的功能做能力检测，不支持时用 XHR 实现。
```

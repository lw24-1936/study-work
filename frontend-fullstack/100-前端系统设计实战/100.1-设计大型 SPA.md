## 概述

设计大型 SPA（Single Page Application）的核心是「分层与隔离」：把代码按模块拆开、把状态按来源分类、把数据流与副作用收敛到统一的 API 层，再配上缓存、错误兜底、监控与可回滚的部署策略。设计得当的 SPA 在几十人协作、上百个页面、上百万行代码的规模下仍能保持可维护、可扩展、可观测。

```text
大型 SPA 的八大设计支柱：
1. Module —— 按领域与依赖边界拆分代码，避免巨型单块
2. Routing —— 路由驱动页面与权限，支持懒加载与嵌套
3. State —— 客户端状态与服务端状态分离管理
4. API —— 统一请求层，收敛鉴权、错误与重试
5. Cache —— 多级缓存，减少重复请求与白屏
6. Error —— 全局错误边界与降级策略
7. Monitoring —— 性能、错误、业务指标三件套
8. Deployment —— 原子化发布、灰度与快速回滚
```

```js
// 大型 SPA 的分层总览（目录结构示意）
src/
  modules/           // 按业务域拆分，每个 module 自治
    user/            // 用户域：页面 + 组件 + hooks + store + api
    order/
  shared/            // 跨域复用的通用层
    components/
    hooks/
    utils/
  app/               // 应用壳：路由、布局、全局 Provider
  api/               // 统一请求层
  store/             // 全局状态
  infra/             // 基础设施：日志、监控、鉴权封装
```

## Module

Module（模块化）是大型 SPA 的第一道防线。按业务域（domain）切分模块，而不是按技术类型（components/pages 全堆一起），让每个模块内部高内聚、模块之间低耦合。

```js
// 模块边界约定：模块只通过 index.ts 暴露公共 API
// modules/user/index.ts
export { UserProfilePage } from './pages/UserProfilePage';
export { useUser } from './hooks/useUser';
export { userStore } from './store/userStore';
export type { User } from './types';

// 其他模块禁止 import 内部路径：
// import { something } from '@/modules/user/utils/private';  // 禁止
```

```text
模块划分的三原则：
1. 按领域切分 —— user/order/payment，而不是 components/utils
2. 单向依赖 —— 底层模块不依赖上层，跨域通过公共层通信
3. 显式公共 API —— index 文件导出，隐藏内部实现
```

## Routing

路由是 SPA 的骨架，决定页面如何组织、按需加载与权限控制。大型应用通常用嵌套路由 + 懒加载，把首屏与按需代码拆开。

```js
// React Router v6 的嵌套路由 + 懒加载
import { lazy, Suspense } from 'react';
import { createBrowserRouter, RouterProvider, Outlet } from 'react-router-dom';

const Dashboard = lazy(() => import('./modules/dashboard/Dashboard'));
const Settings = lazy(() => import('./modules/settings/Settings'));

const router = createBrowserRouter([
  {
    path: '/',
    element: <AppLayout />,      // 应用壳：导航栏 + 布局
    children: [
      {
        path: 'dashboard',
        element: (
          <Suspense fallback={<PageSkeleton />}>
            <Dashboard />
          </Suspense>
        ),
      },
      {
        path: 'settings',
        element: (
          <Suspense fallback={<PageSkeleton />}>
            <Settings />
          </Suspense>
        ),
      },
    ],
  },
]);

function App() {
  return <RouterProvider router={router} />;
}
```

```text
大型 SPA 路由的要点：
1. 懒加载 —— 每个路由一个 chunk，首屏只加载必要代码
2. 嵌套路由 —— 布局与页面解耦，切换页面不重挂布局
3. 权限守卫 —— 在路由层拦截未授权访问
4. 路由级错误边界 —— 单个页面崩溃不影响整体
```

## State

状态管理的第一原则是「分类」：客户端状态（UI 状态、表单、用户偏好）与服务端状态（API 返回的数据）本质不同，应分别处理。客户端状态用 Zustand/Redux，服务端状态用 TanStack Query/SWR 这类带缓存的库。

```js
// 客户端状态：Zustand 管理 UI 状态
import { create } from 'zustand';

export const useUIStore = create((set) => ({
  sidebarOpen: true,
  theme: 'light',
  toggleSidebar: () => set((s) => ({ sidebarOpen: !s.sidebarOpen })),
  setTheme: (theme) => set({ theme }),
}));

// 服务端状态：TanStack Query 管理服务端数据
import { useQuery } from '@tanstack/react-query';

function useOrders(userId) {
  return useQuery({
    queryKey: ['orders', userId],
    queryFn: () => fetchOrders(userId),
    staleTime: 30 * 1000,        // 30 秒内视为新鲜
    retry: 2,                    // 失败重试 2 次
  });
}
```

```text
状态分类与策略：
1. 服务端状态 —— 归属权在服务端，用缓存库管理（stale/refetch）
2. 客户端状态 —— 归属权在 UI，用轻量 store 管理
3. 局部状态 —— 只在单组件用 useState，不上升
4. URL 状态 —— 筛选条件、分页放 URL，可分享可回溯
```

## API

统一 API 层是大型 SPA 的「咽喉」，把所有请求收敛到一个入口，统一处理鉴权 token、错误码、重试与日志。避免在每个组件里散落 fetch/axios 调用。

```js
// 统一请求层：封装鉴权、错误、重试
import axios from 'axios';
import { getToken, refreshToken } from '@/infra/auth';

export const http = axios.create({ baseURL: '/api', timeout: 10_000 });

http.interceptors.request.use(async (config) => {
  const token = await getToken();
  if (token) config.headers.Authorization = `Bearer ${token}`;
  return config;
});

http.interceptors.response.use(
  (res) => res.data,
  async (error) => {
    const { response, config } = error;
    if (response?.status === 401 && !config._retried) {
      config._retried = true;
      await refreshToken();           // 刷新 token 后重放
      return http(config);
    }
    return Promise.reject(normalizeError(error));  // 统一错误结构
  }
);
```

```text
API 层的最佳实践：
1. 单一出口 —— 所有请求走 http 实例，禁止裸 fetch
2. 统一鉴权 —— token 自动注入，401 自动刷新
3. 统一错误 —— 后端错误码转成前端可读结构
4. 类型安全 —— 请求/响应都用 TS 类型约束
```

## Cache

缓存是大型 SPA 性能与体验的关键。多级缓存（HTTP 缓存、内存缓存、持久化缓存）各司其职，减少重复请求、提升二次访问速度。

```js
// 多级缓存示意：内存缓存 + 服务端状态缓存 + HTTP 缓存
const memoryCache = new Map();   // 进程内存缓存，存热点数据

async function getWithMemoryCache(key, fetcher, ttl = 60_000) {
  const hit = memoryCache.get(key);
  if (hit && Date.now() - hit.time < ttl) return hit.value;

  const value = await fetcher();
  memoryCache.set(key, { value, time: Date.now() });
  return value;
}

// 服务端状态缓存：TanStack Query 的 staleTime + gcTime
useQuery({
  queryKey: ['products'],
  queryFn: fetchProducts,
  staleTime: 60_000,   // 60 秒内复用缓存，不重新请求
  gcTime: 5 * 60_000,  // 缓存 5 分钟后回收
});
```

```text
缓存分层与职责：
1. HTTP 缓存 —— 强缓存/协商缓存，静态资源与幂等 GET
2. 服务端状态缓存 —— staleTime 控制新鲜度，自动失效
3. 内存缓存 —— 热点数据、跨页面共享的查询结果
4. 持久化缓存 —— localStorage/IndexedDB 缓存首屏与草稿
```

## Error

大型 SPA 必须「优雅地失败」：错误边界隔离组件崩溃，全局兜底避免白屏，错误上报让问题可追溯。错误分三类：渲染错误、请求错误、运行时错误。

```jsx
// 错误边界：捕获渲染错误，隔离崩溃范围
import { Component } from 'react';

class ErrorBoundary extends Component {
  state = { error: null };

  static getDerivedStateFromError(error) {
    return { error };            // 渲染 fallback
  }

  componentDidCatch(error, info) {
    reportError({ error, info });  // 上报错误
  }

  render() {
    if (this.state.error) {
      return this.props.fallback ?? <div>页面出错了，请刷新重试</div>;
    }
    return this.props.children;
  }
}

// 使用：路由级 + 组件级双层边界
<ErrorBoundary fallback={<GlobalCrash />}>
  <ErrorBoundary fallback={<PageCrash />}>
    <UserProfilePage />
  </ErrorBoundary>
</ErrorBoundary>
```

```text
错误处理三层策略：
1. 组件级边界 —— 单个组件崩溃不拖垮整页
2. 路由级边界 —— 页面崩溃显示兜底页 + 刷新按钮
3. 全局兜底 —— 捕获未处理的 Promise 拒绝与 window.onerror
```

## Monitoring

监控让大型 SPA 从「黑盒」变「白盒」。性能指标（LCP/FID/CLS）、错误信息、业务埋点三类数据一起采集，才能在故障时快速定位。

```js
// 前端监控三类数据的采集示意
import { init, reportError, reportPerformance, reportEvent } from '@/infra/monitor';

init({ appId: 'spa-app', release: 'v1.2.3' });

// 1. 性能指标：采集 Web Vitals
new PerformanceObserver((list) => {
  for (const entry of list.getEntries()) {
    reportPerformance(entry.name, entry.value);   // LCP / CLS / FID
  }
}).observe({ entryTypes: ['largest-contentful-paint', 'layout-shift', 'first-input'] });

// 2. 错误监控：全局捕获
window.addEventListener('unhandledrejection', (e) => reportError(e.reason));
window.addEventListener('error', (e) => reportError(e.error));

// 3. 业务埋点：关键路径事件
reportEvent('order_submitted', { orderId: '123', amount: 99.9 });
```

```text
监控三类指标：
1. 性能指标 —— LCP/FID/CLS/INP，衡量真实用户体验
2. 错误指标 —— JS 错误率、接口错误率、白屏率
3. 业务指标 —— 转化率、留存、关键路径耗时
```

## Deployment

大型 SPA 的部署要支持灰度、回滚与版本可追踪。构建产物带唯一 hash，配合 CDN 与版本清单，实现「发布即回滚」的能力。

```yaml
# 部署流水线示意（简化版 CI）
stages:
  - build
  - deploy

build:
  script:
    - npm ci
    - npm run build          # 产出带 contenthash 的静态文件
    - npm run upload-cdn     # 上传到 CDN，文件名带 hash
  artifacts:
    paths: [dist/]

deploy:
  script:
    - npm run publish-manifest   # 发布版本清单 index.html
  only:
    - main
```

```text
大型 SPA 部署要点：
1. 产物 hash —— 文件名带 contenthash，CDN 永久缓存
2. 原子发布 —— 先上传资源再切换 index.html，避免中间态
3. 灰度发布 —— 按比例/按用户逐步放量，观察指标
4. 快速回滚 —— 切回上一版 index.html 即可，秒级生效
```

## 应用场景实战

### 场景一：一个带缓存与错误兜底的商品列表页

```jsx
// 完整的商品列表页：路由懒加载 + 服务端缓存 + 错误兜底
import { lazy, Suspense } from 'react';
import { useQuery } from '@tanstack/react-query';
import { ErrorBoundary } from '@/app/ErrorBoundary';
import { fetchProducts } from '@/api/products';

function ProductList() {
  const { data, isLoading, error, refetch } = useQuery({
    queryKey: ['products'],
    queryFn: fetchProducts,
    staleTime: 30_000,
    retry: 1,
  });

  if (isLoading) return <Skeleton />;
  if (error) return <ErrorState onRetry={refetch} />;   // 错误兜底 + 重试
  return (
    <ul>
      {data.map((p) => (
        <li key={p.id}>{p.name} - ¥{p.price}</li>
      ))}
    </ul>
  );
}

// 懒加载 + 错误边界组合
export default function ProductListPage() {
  return (
    <ErrorBoundary fallback={<PageCrash />}>
      <Suspense fallback={<Skeleton />}>
        <ProductList />
      </Suspense>
    </ErrorBoundary>
  );
}
```

### 场景二：权限路由守卫

```jsx
// 路由级权限守卫：未登录跳登录页，无权限显示 403
import { Navigate, useLocation } from 'react-router-dom';

function RequireAuth({ children, roles }) {
  const { user } = useAuth();
  const location = useLocation();

  if (!user) {
    return <Navigate to="/login" state={{ from: location }} replace />;
  }
  if (roles && !roles.some((r) => user.roles.includes(r))) {
    return <Navigate to="/403" replace />;
  }
  return children;
}

// 使用：包在需要权限的路由外层
<Route
  path="/admin"
  element={
    <RequireAuth roles={['admin']}>
      <AdminPage />
    </RequireAuth>
  }
/>;
```

## 最佳实践与踩坑记录

### 最佳实践

1. 按业务域切分模块，用 index 文件暴露公共 API，禁止跨模块深引用
2. 服务端状态与客户端状态分库管理，别用单一 Redux 管所有东西
3. 所有请求走统一 API 层，鉴权、错误、重试集中处理
4. 路由一律懒加载，首屏只加载必要 chunk
5. 错误边界分三层（组件/路由/全局），杜绝整页白屏
6. 缓存要设 staleTime，别让每次进入页面都重新请求
7. 构建产物带 contenthash，发布流程支持秒级回滚

### 踩坑记录

```text
坑 1：所有状态塞进一个全局 store
结论：全局 store 膨胀，任何改动都触发大面积重渲染，难以维护。
原因：没区分客户端状态与服务端状态，把服务端数据也放进了 store。
解法：客户端状态用轻量 store，服务端数据交给 TanStack Query 这类缓存库。

坑 2：路由不懒加载，首屏 bundle 巨大
结论：首屏加载 5MB JS，白屏时间长，移动端尤其严重。
原因：所有页面打包进同一个 chunk，一次全下载。
解法：路由级 lazy + Suspense，按需拆分 chunk。

坑 3：缓存设了 staleTime 却从不失效
结论：用户看到的是过期数据，下单后列表不刷新。
原因：只依赖缓存，没处理数据变更后的失效逻辑。
解法：增删改后主动 invalidate 相关 queryKey。

坑 4：错误边界只包了最外层
结论：某个组件崩溃导致整页白屏，用户体验极差。
原因：没有组件级/路由级的细粒度边界。
解法：三层边界，崩溃范围最小化，兜底页给刷新按钮。

坑 5：401 刷新 token 造成请求风暴
结论：多个并发请求同时 401，同时触发刷新，后端压力大。
原因：刷新 token 没有去重，每个请求各自刷新一次。
解法：刷新 token 加单例锁，并发 401 只触发一次刷新。
```

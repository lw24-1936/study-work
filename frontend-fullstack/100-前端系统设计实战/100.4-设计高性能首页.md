## 概述

首页的性能直接影响用户的第一印象与转化率：首屏越快，跳出率越低。高性能首页是一套组合拳——SSR 让首屏内容直达、CDN 缩短物理距离、Critical CSS 让首屏秒渲染、图片与代码分割让资源最小化、流式输出让「可见即所得」。

```text
高性能首页的八大支柱：
1. SSR —— 服务端渲染首屏 HTML，减少白屏
2. CDN —— 就近分发静态资源，缩短网络延迟
3. Cache —— 强缓存 + 协商缓存，二次访问秒开
4. Critical CSS —— 首屏关键样式内联，阻断渲染的 CSS 最小化
5. Image Optimization —— 图片压缩/懒加载/响应式/新格式
6. Code Splitting —— 按路由拆包，首屏只加载必要 JS
7. Preload —— 预加载关键资源，提前进入加载队列
8. Streaming —— 边渲染边输出，渐进式呈现内容
```

```js
// 首页性能的核心指标与目标
const targets = {
  LCP: '2.5s 内',      // 最大内容绘制，首屏核心指标
  FCP: '1.8s 内',      // 首次内容绘制
  INP: '200ms 内',     // 交互延迟
  CLS: '0.1 以下',     // 布局偏移
  TTFB: '800ms 内',    // 首字节时间
};
```

## SSR

SSR（Server-Side Rendering）在服务端把首屏 HTML 渲染好返回给浏览器，浏览器拿到 HTML 即可渲染，无需等 JS 下载执行完。相比纯 CSR 的「白屏 + 加载」，SSR 的 TTFB 到 FCP 的间隔大幅缩短，同时利于 SEO。

```jsx
// Next.js SSR：服务端渲染首屏
// pages/index.js 或 app/page.js
export default async function HomePage() {
  // 在服务端直接获取数据并渲染进 HTML
  const products = await fetch('https://api.acme.com/products').then(r => r.json());

  return (
    <main>
      <h1>热门商品</h1>
      <ul>
        {products.map((p) => (
          <li key={p.id}>{p.name}</li>
        ))}
      </ul>
    </main>
  );
}
// 浏览器收到的 HTML 里已经包含商品列表，无需等待客户端 JS
```

```text
SSR 的收益与代价：
1. 收益 —— 首屏快、SEO 友好、对低端设备更友好
2. 代价 —— 服务端压力大、TTFB 可能变长、需要 Node 运行时
3. 折中 —— SSG 静态预渲染 / ISR 增量再生，平衡速度与实时性
```

## CDN

CDN（Content Delivery Network）把静态资源分发到离用户最近的边缘节点，大幅缩短 RTT。首页的 JS/CSS/图片/字体都应该走 CDN，HTML 也可以边缘缓存甚至边缘渲染。

```text
CDN 的加速原理：
1. 就近访问 —— 用户访问最近的边缘节点，而非源站
2. 内容缓存 —— 静态资源缓存在边缘，命中后不再回源
3. 连接复用 —— 边缘节点与源站长连接，减少建连开销
4. 边缘计算 —— 可在边缘做 SSR、AB 测试、鉴权
```

```js
// 资源走 CDN 的典型配置
// HTML 引用带 CDN 域名的资源
const cdn = 'https://cdn.acme.com';

export const assetUrl = (path) => `${cdn}/${path}`;

// 图片、字体、静态资源统一走 CDN
const heroImage = assetUrl('images/hero.webp');
const fontUrl = assetUrl('fonts/inter.woff2');

// 关键点：CDN 域名与主站不同域，避免携带 Cookie，加速请求
```

## Cache

缓存让「第二次访问」接近「第一次访问本机」。浏览器缓存分层：强缓存（Cache-Control: max-age）直接命中不发请求，协商缓存（ETag/Last-Modified）304 复用。CDN 缓存减少回源，服务端缓存加速 HTML 生成。

```text
缓存响应头配置示例
# 静态资源：带 hash 的长期强缓存
Cache-Control: public, max-age=31536000, immutable

# HTML：短期缓存或协商缓存
Cache-Control: public, max-age=0, must-revalidate

# 接口数据：按新鲜度设缓存
Cache-Control: private, max-age=60
```

```js
// 前端配合：带 hash 的资源名 + 强缓存
// 文件名带 contenthash，内容不变则文件名不变，可永久缓存
// bundle.a1b2c3.js  → 内容变了文件名变，浏览器重新下载
export default defineConfig({
  build: {
    rollupOptions: {
      output: {
        entryFileNames: 'assets/[name].[hash].js',
        chunkFileNames: 'assets/[name].[hash].js',
        assetFileNames: 'assets/[name].[hash][extname]',
      },
    },
  },
});
```

## Critical CSS

Critical CSS 是把「首屏渲染必需的最小 CSS」内联到 HTML 的 `<head>` 里，让浏览器无需等待外部 CSS 文件下载即可渲染首屏。其余 CSS 异步加载，消除 render-blocking CSS。

```html
<!-- 首屏关键 CSS 内联，其余异步加载 -->
<head>
  <style>
    /* Critical CSS：首屏折叠线以上的最小样式 */
    .hero { display: flex; align-items: center; min-height: 60vh; }
    .hero-title { font-size: 2rem; color: #111; }
    .btn { display: inline-block; padding: 12px 24px; background: #3b82f6; }
  </style>
  <!-- 其余 CSS 异步加载，不阻塞渲染 -->
  <link rel="preload" href="/styles/full.css" as="style" onload="this.onload=null;this.rel='stylesheet'">
  <noscript><link rel="stylesheet" href="/styles/full.css"></noscript>
</head>
```

```text
Critical CSS 的落地方式：
1. 工具提取 —— critical、penthouse 从完整 CSS 提取首屏样式
2. 手动维护 —— 首屏组件样式单独内联，其余异步
3. 框架内置 —— Next.js 的 styled-jsx、CSS-in-JS 自动分离
```

## Image Optimization

图片通常是首页体积的大头，优化收益最直接：用 WebP/AVIF 新格式、响应式多尺寸、懒加载首屏外图片、用 CSS 尺寸占位防止 CLS。图片优化做得好，首页体积能砍掉一半以上。

```html
<!-- 图片优化组合拳 -->
<picture>
  <!-- 新格式优先 -->
  <source srcset="hero.avif" type="image/avif">
  <source srcset="hero.webp" type="image/webp">
  <!-- 兜底 -->
  <img
    src="hero.jpg"
    alt="首页主视觉"
    width="1200"
    height="600"
    loading="lazy"
    decoding="async"
    fetchpriority="high"
  >
</picture>
```

```jsx
// Next.js Image 组件：自动压缩、响应式、懒加载、占位
import Image from 'next/image';

function Hero() {
  return (
    <Image
      src="/hero.jpg"
      alt="主视觉"
      width={1200}
      height={600}
      priority                 // 首屏关键图优先加载
      placeholder="blur"       // 模糊占位，防止 CLS
      blurDataURL="data:image/jpeg;base64,..."
    />
  );
}
```

```text
图片优化清单：
1. 格式 —— WebP/AVIF，体积比 JPEG 小 30-50%
2. 尺寸 —— 响应式 srcset，不同 DPR/视口下对应尺寸
3. 懒加载 —— 首屏外 loading=lazy，首屏图 priority
4. 占位 —— 设 width/height 或 blur 占位，防止布局偏移
```

## Code Splitting

代码分割把「一次性加载全部 JS」拆成「按需加载的多个 chunk」，首屏只下载渲染首页所需的代码。路由级分割（每个页面一个 chunk）+ 组件级分割（重型组件按需加载）+ 依赖分割（大库单独缓存）。

```jsx
// 路由级分割：React.lazy 按路由拆包
import { lazy, Suspense } from 'react';

const HomePage = lazy(() => import('./pages/Home'));
const ProductPage = lazy(() => import('./pages/Product'));
const CheckoutPage = lazy(() => import('./pages/Checkout'));

// 只有访问到的页面 chunk 才会被下载
function App() {
  return (
    <Suspense fallback={<PageSkeleton />}>
      <Routes>
        <Route path="/" element={<HomePage />} />
        <Route path="/product" element={<ProductPage />} />
        <Route path="/checkout" element={<CheckoutPage />} />
      </Routes>
    </Suspense>
  );
}
```

```js
// 依赖分割：把稳定的大库单独打包，利于长期缓存
// vite.config.js
export default defineConfig({
  build: {
    rollupOptions: {
      output: {
        manualChunks: {
          vendor: ['react', 'react-dom'],
          charts: ['echarts', 'd3'],
        },
      },
    },
  },
});
```

## Preload

Preload/Prefetch 让浏览器提前加载关键资源，缩短后续请求的等待时间。Preload 用于「当前页面马上要用」的资源，Prefetch 用于「下一步可能要用」的资源，两者都写入 `<link>` 标签。

```html
<!-- Preload：当前页面关键资源，高优先级提前加载 -->
<link rel="preload" href="/fonts/inter.woff2" as="font" type="font/woff2" crossorigin>
<link rel="preload" href="/js/home.chunk.js" as="script">
<link rel="preload" href="/images/hero.webp" as="image">

<!-- Prefetch：下一步可能访问的资源，空闲时低优先级加载 -->
<link rel="prefetch" href="/js/product.chunk.js">

<!-- 预连接：提前建立 TCP/TLS 连接 -->
<link rel="preconnect" href="https://api.acme.com">
<link rel="dns-prefetch" href="https://cdn.acme.com">
```

```text
Preload 使用原则：
1. Preload 只标关键资源 —— 滥用会抢占带宽，适得其反
2. 字体必须 preload —— 否则文本渲染后字体才到，产生闪烁
3. Preconnect 给第三方域 —— 提前握手省去建连耗时
4. Prefetch 给下一步 —— 用户大概率会访问的下个页面
```

## Streaming

流式渲染（Streaming SSR）让服务端边渲染边输出 HTML，浏览器边接收边解析，首屏内容无需等整个页面渲染完。React 18 的 Suspense + renderToPipeableStream 让「慢的组件」不再阻塞「快的组件」。

```jsx
// React 18 流式 SSR：慢组件用 Suspense 包裹，不阻塞整体
import { Suspense } from 'react';
import { renderToPipeableStream } from 'react-dom/server';

// 慢组件：数据要 2 秒才返回
const SlowComments = async () => {
  await sleep(2000);
  return <div>评论区内容</div>;
};

// 页面：标题和首屏内容立即流出，评论区异步补上
function Page() {
  return (
    <main>
      <h1>商品详情</h1>
      <ProductInfo />                       {/* 立即流出 */}
      <Suspense fallback={<div>评论加载中...</div>}>
        <SlowComments />                    {/* 晚 2 秒流出 */}
      </Suspense>
    </main>
  );
}

const { pipe } = renderToPipeableStream(<Page />, {
  onShellReady() { pipe(res); },   // 壳就绪即开始流式输出
});
```

```text
Streaming 的收益：
1. TTFB 到首屏更快 —— 壳 HTML 先到，内容渐进填充
2. 慢组件不阻塞 —— Suspense 隔离慢数据，快内容先行
3. 用户体验更好 —— 用户看到骨架和渐进内容，而非白屏
```

## 应用场景实战

### 场景一：首页完整的性能优化配置（Next.js）

```jsx
// Next.js 首页综合优化示例
import Image from 'next/image';
import { Suspense, lazy } from 'react';
import { headers } from 'next/headers';

// 首屏数据 SSR 获取
export default async function HomePage() {
  const products = await getProducts();
  const HeavyChart = lazy(() => import('./HeavyChart'));

  return (
    <main>
      {/* 首屏关键图：priority 优先加载，blur 占位防 CLS */}
      <Image src="/hero.webp" alt="主视觉" width={1200} height={600}
             priority placeholder="blur" blurDataURL={BLUR} />

      <h1>热门商品</h1>
      <ul>
        {products.map((p) => <li key={p.id}>{p.name}</li>)}
      </ul>

      {/* 重型图表：组件级代码分割，首屏不加载 */}
      <Suspense fallback={<div>图表加载中...</div>}>
        <HeavyChart data={products} />
      </Suspense>
    </main>
  );
}
```

### 场景二：CDN 缓存 + 预加载的静态资源配置

```html
<!-- 完整的高性能首页 HTML 头部 -->
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <title>高性能首页</title>

  <!-- 1. 预连接关键第三方域 -->
  <link rel="preconnect" href="https://cdn.acme.com">
  <link rel="preconnect" href="https://api.acme.com">

  <!-- 2. Critical CSS 内联，首屏秒渲染 -->
  <style>.hero{display:flex;min-height:60vh}.btn{padding:12px 24px;background:#3b82f6}</style>

  <!-- 3. 关键资源 preload -->
  <link rel="preload" href="https://cdn.acme.com/fonts/inter.woff2" as="font" type="font/woff2" crossorigin>

  <!-- 4. 其余 CSS 异步加载 -->
  <link rel="stylesheet" href="https://cdn.acme.com/styles/full.a1b2c3.css" media="print" onload="this.media='all'">

  <!-- 5. 下一步可能访问的页面 prefetch -->
  <link rel="prefetch" href="https://cdn.acme.com/js/product.chunk.js">
</head>
<body>
  <div id="root"></div>
  <!-- 6. 入口脚本 defer，不阻塞 HTML 解析 -->
  <script src="https://cdn.acme.com/js/main.a1b2c3.js" defer></script>
</body>
</html>
```

## 最佳实践与踩坑记录

### 最佳实践

1. 首屏数据 SSR 获取，让 HTML 自带内容，减少白屏
2. 静态资源带 contenthash + 长期强缓存，CDN 就近分发
3. 首屏关键 CSS 内联，其余 CSS 异步加载，消除渲染阻塞
4. 图片用 WebP/AVIF + 响应式 srcset + 懒加载，首屏图 priority
5. 路由级 + 组件级代码分割，首屏只加载必要 JS
6. 字体、首屏大图、关键 chunk 用 preload，第三方域用 preconnect
7. 慢数据用 Suspense + Streaming，快内容先呈现

### 踩坑记录

```text
坑 1：SSR 页面里用了浏览器 API
结论：服务端渲染报 window is not defined，页面 500。
原因：SSR 在 Node 环境执行，没有 window/document。
解法：浏览器 API 放 useEffect 或加 typeof window 判断。

坑 2：图片不设尺寸导致 CLS
结论：图片加载后页面内容跳动，CLS 超标。
原因：img 没有 width/height，布局时高度未知。
解法：图片设宽高比或用占位元素，预留布局空间。

坑 3：preload 滥用
结论：preload 了十几个资源，首屏反而更慢。
原因：preload 抢占带宽，阻塞了更关键资源的下载。
解法：preload 只标 1-3 个最关键资源（字体、首屏图、入口 chunk）。

坑 4：CDN 缓存策略错误导致更新不生效
结论：改了代码但用户还是看到旧版本。
原因：HTML 也设了长期强缓存，新版本没被拉到。
解法：HTML 用短期缓存/协商缓存，带 hash 的静态资源才长期缓存。

坑 5：全量 CSS 阻塞渲染
结论：CSS 文件大，浏览器等 CSS 下载完才渲染首屏。
原因：外部 CSS 是 render-blocking 资源，未做 Critical CSS 拆分。
解法：内联首屏关键 CSS，其余异步加载。
```

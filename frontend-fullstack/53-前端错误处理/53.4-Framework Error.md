## 概述

框架渲染过程中的错误（组件渲染、生命周期、事件处理）不会自动被 try/catch 捕获。React 用 Error Boundary 隔离组件错误，Vue 用全局 errorHandler 捕获，两者都配合全局兜底实现完整的错误处理链路。

```text
为什么框架需要专门的错误处理：
1. 组件渲染错误 —— 一个组件报错会导致整棵树崩溃（白屏）
2. 错误无法被业务代码 try/catch 捕获 —— 发生在框架内部调用
3. 需要局部降级 —— 某个组件坏了，其他部分应继续可用

三层错误处理架构：
组件级（Error Boundary / onErrorCaptured）
  → 框架全局（errorHandler / 全局捕获）
    → 兜底上报（window.onerror / unhandledrejection）
```

```text
React 与 Vue 的错误处理差异：
React —— Error Boundary 类组件 + getDerivedStateFromError
Vue —— errorHandler 全局配置 + onErrorCaptured 生命周期

共同目标：
局部降级（不整体白屏）+ 错误上报（问题可追溯）。
```

## React Error Boundary

Error Boundary 是 React 中捕获子组件渲染错误的类组件，通过 getDerivedStateFromError 和 componentDidCatch 两个生命周期方法，把错误隔离在局部并展示降级 UI。

```jsx
import React from 'react';

class ErrorBoundary extends React.Component {
  constructor(props) {
    super(props);
    this.state = { hasError: false, error: null };
  }

  // 渲染阶段捕获错误，返回新 state 触发降级 UI
  static getDerivedStateFromError(error) {
    return { hasError: true, error };
  }

  // 提交阶段捕获错误，适合做副作用（上报）
  componentDidCatch(error, errorInfo) {
    console.error('组件错误：', error, errorInfo.componentStack);
    reportError({ message: error.message, stack: error.stack, componentStack: errorInfo.componentStack });
  }

  render() {
    if (this.state.hasError) {
      return this.props.fallback || <div>页面出错了，请刷新重试</div>;
    }
    return this.props.children;
  }
}
```

```jsx
// 使用：包裹可能出错的组件
<ErrorBoundary fallback={<h1>订单模块加载失败</h1>}>
  <OrderList />
</ErrorBoundary>

// 多层边界，隔离不同模块
<ErrorBoundary>
  <Header />
  <ErrorBoundary fallback={<div>侧边栏异常</div>}>
    <Sidebar />
  </ErrorBoundary>
  <ErrorBoundary fallback={<div>内容区异常</div>}>
    <Content />
  </ErrorBoundary>
</ErrorBoundary>
```

```jsx
// 函数组件版 Error Boundary（配合 react-error-boundary 库）
import { ErrorBoundary } from 'react-error-boundary';

function Fallback({ error, resetErrorBoundary }) {
  return (
    <div>
      <p>出错了：{error.message}</p>
      <button onClick={resetErrorBoundary}>重试</button>
    </div>
  );
}

function App() {
  return (
    <ErrorBoundary FallbackComponent={Fallback} onReset={() => resetApp()}>
      <Dashboard />
    </ErrorBoundary>
  );
}
```

```text
Error Boundary 的边界与限制：
能捕获 —— 渲染期间、生命周期、构造函数中的错误
不能捕获 ——
1. 事件处理函数中的错误（需 try/catch）
2. 异步代码的错误（setTimeout、Promise）
3. 服务端渲染（SSR）中的错误
4. Error Boundary 自身的错误

实践要点：
1. 事件处理用 try/catch，渲染错误用 Error Boundary
2. 边界粒度 —— 按模块/路由拆分，避免一处崩溃全站白屏
3. componentDidCatch 里做错误上报
```

## Vue Error Handler

Vue 提供全局 errorHandler 配置和组件级 onErrorCaptured 钩子来捕获渲染、生命周期、事件处理中的错误，同样支持局部降级。

```js
// 全局错误处理（main.js）
import { createApp } from 'vue';
import App from './App.vue';

const app = createApp(App);

app.config.errorHandler = (err, instance, info) => {
  // err —— 错误对象
  // instance —— 出错的组件实例
  // info —— 错误来源信息（如 'render function'、'event handler'）
  console.error('Vue 错误：', err, info);
  reportError({ message: err.message, stack: err.stack, info });
};

app.mount('#app');
```

```vue
<!-- 组件级错误捕获 -->
<script setup>
import { onErrorCaptured } from 'vue';

onErrorCaptured((err, instance, info) => {
  console.error('子组件错误：', err, info);
  // 返回 false 阻止错误继续向上传播
  return false;
});
</script>
```

```text
Vue 错误处理的层次：
1. 全局 errorHandler —— 捕获所有未处理的组件错误
2. onErrorCaptured —— 组件级捕获子组件错误，可拦截传播
3. 返回 false —— 阻止错误继续冒泡到全局

errorHandler 能捕获：
渲染函数错误、生命周期钩子错误、事件处理错误、
watch 回调错误、自定义指令错误。

errorHandler 不能捕获：
异步回调（setTimeout/Promise）里的错误（需自行 try/catch）。
```

```js
// Vue Router 的错误处理（路由懒加载失败等）
import { createRouter } from 'vue-router';

const router = createRouter({ /* ... */ });

router.onError((error) => {
  console.error('路由错误：', error);
  reportError({ message: error.message, stack: error.stack });
});
```

## Global Error Handler

框架全局处理之外，还需在最外层用 window.onerror 和 unhandledrejection 兜底，捕获框架没覆盖到的错误（异步错误、事件外错误、第三方脚本等）。

```js
// 全局错误兜底（配合框架错误处理使用）
window.addEventListener('error', (event) => {
  if (event.target === window) {
    // JS 运行错误（框架已处理的不会再到这里）
    reportError({
      type: 'runtime',
      message: event.message,
      stack: event.error?.stack,
      filename: event.filename,
      lineno: event.lineno,
      colno: event.colno,
    });
  }
});

window.addEventListener('unhandledrejection', (event) => {
  reportError({
    type: 'promise',
    message: event.reason?.message || String(event.reason),
    stack: event.reason?.stack,
  });
  event.preventDefault();
});
```

```text
完整的错误处理链路（从内到外）：
1. 局部 —— 组件内 try/catch、Error Boundary、onErrorCaptured
2. 框架全局 —— Vue errorHandler / React 边界树
3. 浏览器全局 —— window.onerror + unhandledrejection
4. 上报 —— 统一 reportError 发送到监控平台

为什么需要多层：
每一层捕获不同来源的错误，层层兜底确保没有漏网之鱼。
框架层负责局部降级（用户体验），全局层负责兜底上报（可观测）。
```

```js
// 统一的 reportError 入口，所有层都汇聚到这里
function reportError(error) {
  const payload = {
    message: error.message || 'Unknown error',
    stack: error.stack || '',
    type: error.type || 'unknown',
    url: location.href,
    time: Date.now(),
    userAgent: navigator.userAgent,
  };

  // 用 sendBeacon 保证页面卸载时也能发出
  if (navigator.sendBeacon) {
    navigator.sendBeacon('/api/report', JSON.stringify(payload));
  } else {
    fetch('/api/report', { method: 'POST', body: JSON.stringify(payload), keepalive: true });
  }
}
```

## 应用场景实战

### 场景一：React 按路由隔离错误

```jsx
import { ErrorBoundary } from 'react-error-boundary';
import { Routes, Route } from 'react-router-dom';

function RouteFallback({ error, resetErrorBoundary }) {
  return (
    <div className="error-page">
      <h2>页面加载失败</h2>
      <p>{error.message}</p>
      <button onClick={resetErrorBoundary}>重新加载</button>
    </div>
  );
}

function App() {
  return (
    <Routes>
      <Route
        path="/orders"
        element={
          <ErrorBoundary
            FallbackComponent={RouteFallback}
            onReset={() => (window.location.href = '/orders')}
          >
            <OrdersPage />
          </ErrorBoundary>
        }
      />
      {/* 其他路由各自包裹独立边界 */}
    </Routes>
  );
}
```

### 场景二：Vue 全局 + 组件级双层处理

```js
// main.js —— 全局兜底
app.config.errorHandler = (err, instance, info) => {
  reportError({ message: err.message, stack: err.stack, info });
};

// 组件内 —— 局部降级
// <script setup>
import { ref, onErrorCaptured } from 'vue';

const failed = ref(false);

onErrorCaptured((err) => {
  failed.value = true;      // 显示降级 UI
  reportError({ message: err.message, stack: err.stack });
  return false;             // 阻止继续传播
});
// </script>

// <template>
// <div v-if="failed" class="fallback">该模块加载失败</div>
// <OrderPanel v-else />
// </template>
```

## 最佳实践与踩坑记录

### 最佳实践

1. React 用 Error Boundary 按模块/路由隔离，避免一处崩溃全站白屏
2. Vue 全局配 errorHandler，关键组件加 onErrorCaptured 局部降级
3. Error Boundary 不能捕获的错误（事件、异步）用 try/catch 补上
4. componentDidCatch / errorHandler 里做错误上报，不吞错误
5. 全局 window.onerror + unhandledrejection 兜底框架漏掉的错误
6. 所有层汇聚到统一 reportError 入口，避免重复实现

### 踩坑记录

```text
坑 1：用 Error Boundary 捕获事件处理错误
结论：点击报错，边界没反应，白屏依旧。
原因：Error Boundary 不捕获事件处理函数里的错误。
解法：事件处理函数内部用 try/catch。

坑 2：Error Boundary 捕获异步错误失败
结论：setTimeout/Promise 里的错误没被边界接住。
原因：异步错误发生在渲染流程之外。
解法：异步代码里 try/catch 或 Promise.catch 处理。

坑 3：全局 errorHandler 吞掉错误导致 UI 不降级
结论：错误被记录但界面无反馈，用户看到空白。
原因：只上报，没有局部降级 UI。
解法：配合 Error Boundary / onErrorCaptured 提供降级界面。

坑 4：错误重复上报
结论：同一个错误上报多次。
原因：组件级和全局层都上报了同一个错误。
解法：设计上报策略（如边界上报、全局只兜底），或做去重。

坑 5：生产环境忘上报，只在控制台打印
结论：线上问题无法追溯。
原因：errorHandler 只 console.error 不上报。
解法：接入错误上报平台，错误自动携带上下文。
```

## 概述

资源错误是脚本、图片、样式、网络请求等资源加载或执行失败产生的错误。它们不经过 try/catch，需要用事件监听、Promise catch 或专门的错误处理机制来捕获，是前端错误监控的重要一环。

```text
资源错误的几种类型：
1. Script Error —— 脚本加载/执行失败，或跨域脚本的匿名错误
2. Image Error —— 图片加载失败
3. CSS Error —— 样式表加载失败
4. Network Error —— fetch/XHR 请求失败

与 JS 运行错误的区别：
JS 运行错误 —— 代码执行中抛出，可被 try/catch 捕获
资源错误 —— 加载/请求层面失败，需事件或 Promise 捕获
```

```js
// 全局捕获资源加载错误（需在捕获阶段监听）
window.addEventListener(
  'error',
  (event) => {
    const target = event.target;
    if (target && target !== window) {
      // 资源加载错误（img/script/link 等）
      console.error('资源加载失败：', target.tagName, target.src || target.href);
    } else {
      // JS 运行错误
      console.error('运行错误：', event.message);
    }
  },
  true   // 关键：捕获阶段才能拿到资源错误
);
```

## Script Error

Script Error 有两种含义：一是脚本加载或执行失败，二是跨域脚本内部错误被浏览器屏蔽后只暴露 "Script error." 这一句无信息的话。

```html
<!-- 脚本加载失败触发 error 事件 -->
<script src="https://cdn.example.com/app.js"></script>

<script>
  // 监听脚本加载失败
  const script = document.querySelector('script');
  script.addEventListener('error', (e) => {
    console.error('脚本加载失败', e);
  });
</script>
```

```text
跨域 Script Error 问题：
当页面加载第三方/CDN 的跨域脚本，且脚本内部抛错时，
浏览器出于安全只上报 "Script error."，不含真实错误信息。

原因：
同源策略下，跨域脚本的错误详情（message、stack）对页面不可见。

解法：
1. script 标签加 crossorigin="anonymous"
2. 服务端响应加 CORS 头：Access-Control-Allow-Origin
3. 两个条件同时满足，浏览器才透传完整错误信息
```

```html
<!-- 正确的跨域脚本加载 -->
<script
  src="https://cdn.example.com/app.js"
  crossorigin="anonymous"
></script>
```

```text
// 服务端响应头
Access-Control-Allow-Origin: https://your-site.com
```

```js
// 全局捕获脚本执行错误
window.addEventListener('error', (event) => {
  if (event.target === window) {
    // 脚本执行错误（区别于资源加载错误）
    console.error(event.message);   // 'Script error.' 或真实信息
    console.error(event.filename);
    console.error(event.lineno);
    console.error(event.error?.stack);
  }
});
```

## Image Error

图片加载失败是前端最常见的资源错误。通过 img 的 error 事件、全局 error 捕获或 onerror 属性处理。

```html
<!-- 方式一：onerror 属性 -->
<img src="broken.jpg" onerror="this.src='fallback.jpg'" />
```

```js
// 方式二：addEventListener
const img = document.querySelector('img');
img.addEventListener('error', () => {
  console.error('图片加载失败', img.src);
  img.src = '/fallback.png';   // 换成兜底图
});
```

```js
// 方式三：全局捕获（捕获阶段）
window.addEventListener(
  'error',
  (e) => {
    if (e.target.tagName === 'IMG') {
      console.error('图片加载失败：', e.target.src);
      reportResourceError('image', e.target.src);
    }
  },
  true
);
```

```js
// 预加载图片并处理失败
function preloadImage(url) {
  return new Promise((resolve, reject) => {
    const img = new Image();
    img.onload = () => resolve(img);
    img.onerror = () => reject(new Error(`图片加载失败: ${url}`));
    img.src = url;
  });
}

await preloadImage('/hero.jpg');
```

```text
图片错误处理要点：
1. error 事件不冒泡 —— 全局监听必须用捕获阶段（第三参数 true）
2. 提供兜底图 —— onerror 里换默认图，避免破图
3. 懒加载 + 错误重试 —— 失败可重试或降级
4. 上报时记录 src —— 便于定位是哪张图、哪个源
```

## CSS Error

CSS 加载失败（link 标签）和 CSS 语法错误的表现与处理方式不同：加载失败可监听，语法错误则静默跳过。

```html
<!-- CSS 加载失败 -->
<link rel="stylesheet" href="https://cdn.example.com/style.css" />
```

```js
// 监听样式表加载失败
document.querySelectorAll('link[rel="stylesheet"]').forEach((link) => {
  link.addEventListener('error', () => {
    console.error('CSS 加载失败：', link.href);
  });
});
```

```text
CSS 错误的特殊性：
1. 加载失败 —— link 的 error 事件可捕获
2. 语法错误 —— 浏览器静默忽略该条规则，不报错、不中断
3. 404 的 CSS —— 不触发 error 事件（因为响应是 HTML 或空）

难点：
CSS 语法错误很难被 JS 直接感知。
方案：
1. 用 CSS 语法检查工具（stylelint）在构建期拦截
2. 检查 document.styleSheets 的 cssRules 是否可读（部分场景）
3. 关键样式用 JS 动态加载并监听 load/error
```

```js
// 动态加载 CSS 并感知成功/失败
function loadCSS(url) {
  return new Promise((resolve, reject) => {
    const link = document.createElement('link');
    link.rel = 'stylesheet';
    link.onload = () => resolve();
    link.onerror = () => reject(new Error(`CSS 加载失败: ${url}`));
    link.href = url;
    document.head.appendChild(link);
  });
}
```

## Network Error

网络请求失败（fetch/XHR）是资源错误中最常见、也最容易处理的一类——fetch 返回 rejected Promise，可用 try/catch 或 .catch 处理。

```js
// fetch 失败处理
async function fetchData(url) {
  try {
    const res = await fetch(url);
    if (!res.ok) {
      throw new Error(`HTTP ${res.status}: ${res.statusText}`);
    }
    return await res.json();
  } catch (err) {
    if (err.name === 'TypeError' && err.message.includes('fetch')) {
      // 网络层失败（DNS 解析失败、连接拒绝、超时）
      console.error('网络错误：', err);
    }
    throw err;
  }
}
```

```js
// 带超时的请求
async function fetchWithTimeout(url, timeout = 8000) {
  const controller = new AbortController();
  const timer = setTimeout(() => controller.abort(), timeout);
  try {
    const res = await fetch(url, { signal: controller.signal });
    return await res.json();
  } catch (err) {
    if (err.name === 'AbortError') {
      throw new Error('请求超时');
    }
    throw err;
  } finally {
    clearTimeout(timer);
  }
}
```

```js
// XHR 的 error 事件
const xhr = new XMLHttpRequest();
xhr.open('GET', '/api/data');
xhr.onerror = () => console.error('XHR 网络错误');
xhr.onload = () => console.log('成功', xhr.responseText);
xhr.send();
```

```text
网络错误的分类与处理：
1. 连接失败 —— fetch 返回 reject（TypeError），catch 处理
2. HTTP 错误状态 —— res.ok 为 false，需手动 throw
3. 超时 —— AbortController 主动中断
4. 离线 —— navigator.onLine 判断 + online 事件监听

区分网络错误和 HTTP 错误很重要：
网络错误 —— 请求根本没成功发出去（断网、DNS、连接拒绝）
HTTP 错误 —— 请求发出去了，服务端返回 4xx/5xx
```

## 应用场景实战

### 场景一：图片懒加载 + 失败兜底

```js
// 图片加载失败自动换兜底图，并上报
function initImageFallback() {
  document.querySelectorAll('img').forEach((img) => {
    img.addEventListener('error', () => {
      img.src = '/assets/fallback.png';
      reportResourceError('image', img.dataset.originalSrc || img.src);
    });
  });
}

// 全局兜底：捕获阶段监听所有图片错误
window.addEventListener(
  'error',
  (e) => {
    if (e.target.tagName === 'IMG') {
      e.target.src = '/assets/fallback.png';
    }
  },
  true
);
```

### 场景二：统一资源错误上报

```js
// 统一的资源错误上报函数
function reportResourceError(type, url, extra = {}) {
  const payload = {
    type,             // 'script' | 'image' | 'css' | 'network'
    url,              // 失败资源的地址
    page: location.href,
    time: Date.now(),
    ...extra,
  };
  navigator.sendBeacon('/api/report/resource-error', JSON.stringify(payload));
}

// 全局捕获
window.addEventListener(
  'error',
  (e) => {
    if (e.target && e.target !== window) {
      const tag = e.target.tagName.toLowerCase();
      const url = e.target.src || e.target.href || '';
      reportResourceError(tag, url);
    }
  },
  true
);

// 网络错误上报
window.addEventListener('unhandledrejection', (e) => {
  if (e.reason?.name === 'TypeError') {
    reportResourceError('network', '', { message: e.reason.message });
  }
});
```

## 最佳实践与踩坑记录

### 最佳实践

1. 全局 error 监听用捕获阶段，才能捕获图片/脚本等资源错误
2. 跨域脚本加 crossorigin="anonymous" + CORS 头，才能拿到完整错误信息
3. 图片提供兜底图，onerror 里替换默认图避免破图
4. 区分网络错误和 HTTP 错误，分别处理
5. 资源错误上报记录 tag 和 url，便于定位具体资源
6. 关键资源（图片/CSS）动态加载用 Promise 包裹并监听 load/error

### 踩坑记录

```text
坑 1：图片 error 事件不冒泡导致监听不到
结论：window 上冒泡监听收不到图片错误。
原因：img 的 error 事件不冒泡。
解法：用捕获阶段（addEventListener 第三参数 true）。

坑 2：跨域脚本只报 Script error
结论：错误信息只有一句 'Script error.'，无法定位。
原因：跨域脚本错误详情被浏览器屏蔽。
解法：script 加 crossorigin="anonymous"，服务端加 CORS 头。

坑 3：404 的 CSS 不触发 error 事件
结论：样式表 404 但监听不到错误。
原因：浏览器把 404 响应当作资源加载（非致命错误）。
解法：动态加载 CSS 并检查加载结果，或构建期校验资源清单。

坑 4：把 HTTP 4xx 当网络错误
结论：404/500 被误判为断网。
原因：fetch 对 4xx/5xx 不 reject，需检查 res.ok。
解法：判断 res.ok，false 时手动抛 HTTP 错误。

坑 5：onerror 属性里写 this.src 死循环
结论：兜底图也加载失败，无限触发 error。
原因：兜底图路径本身不存在。
解法：兜底图加载失败就移除 onerror，或用静态确定存在的兜底图。
```

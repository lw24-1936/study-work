## 概述

Webpack 优化围绕两个核心目标：构建速度与产物质量。产物质量优化（Tree Shaking、代码分割、缓存）决定用户体验，构建速度优化（Persistent Cache、并行压缩）决定开发效率。

```text
Webpack 优化全景：
1. Tree Shaking —— 删除未使用代码
2. Code Splitting —— 拆分代码，按需加载
3. Dynamic Import —— 运行时动态加载模块
4. Lazy Loading —— 路由/组件懒加载
5. Prefetch/Preload —— 资源预取与预加载
6. Cache —— 内容哈希实现长缓存
7. Persistent Cache —— 磁盘缓存加速二次构建
8. Module Federation —— 微前端模块共享
```

## Tree Shaking

Tree Shaking（摇树优化）在打包时移除未被引用的导出代码，基于 ES Module 的静态导入特性实现。生产模式默认开启。

```js
// math.js
export function add(a, b) { return a + b; }
export function unused() { return '不会被用到'; }

// index.js 只引用了 add
import { add } from './math';
console.log(add(1, 2)); // unused 会被摇掉
```

```js
// webpack 配置：package.json 标记无副作用
// package.json
// { "sideEffects": ["*.css"] }
module.exports = {
  mode: 'production',
  optimization: { usedExports: true },
};
```

```text
Tree Shaking 生效条件：
1. 必须使用 ES Module（import/export）
2. 生产模式（mode: 'production'）
3. package.json 正确配置 sideEffects
```

## Code Splitting

Code Splitting（代码分割）把一个大 Bundle 拆成多个小 Chunk，实现按需加载与缓存复用。有三种方式：入口分割、动态导入、SplitChunksPlugin。

```js
module.exports = {
  optimization: {
    splitChunks: {
      chunks: 'all',
      cacheGroups: {
        vendor: { test: /[\\/]node_modules[\\/]/, name: 'vendors', priority: 10 },
      },
    },
  },
};
```

```text
代码分割的收益：
1. 首屏只加载必要代码
2. 公共依赖独立成 vendor chunk 可长期缓存
3. 业务代码变更不影响 vendor 缓存
```

## Dynamic Import

Dynamic Import 用 `import()` 语法在运行时异步加载模块，返回 Promise，是代码分割的基础。

```js
// 点击时才加载模块
button.addEventListener('click', async () => {
  const { render } = await import('./chart');
  render();
});
```

```text
Dynamic Import 要点：
1. import() 返回 Promise
2. 每个动态导入生成独立 chunk
3. 支持魔法注释：/* webpackChunkName: "chart" */
```

## Lazy Loading

Lazy Loading（懒加载）用 Dynamic Import 延迟加载路由或组件，减少首屏体积。React/Vue 路由均基于此实现。

```js
// React Router 懒加载
import { lazy, Suspense } from 'react';
const Dashboard = lazy(() => import('./pages/Dashboard'));

function App() {
  return (
    <Suspense fallback={<div>加载中...</div>}>
      <Dashboard />
    </Suspense>
  );
}
```

```text
懒加载策略：
1. 路由级：每个页面一个 chunk
2. 组件级：首屏不可见的组件延迟加载
3. 配合 Suspense/loading 提供加载反馈
```

## Chunk

Chunk 是代码分割的产物单位，异步 chunk 由动态导入产生。命名与分组策略影响缓存与加载效率。

```js
// 魔法注释自定义 chunk 名
import(/* webpackChunkName: "report" */ './report');
```

```js
// splitChunks 精细控制
module.exports = {
  optimization: {
    splitChunks: {
      chunks: 'all',
      minSize: 20000,          // 小于 20KB 不分割
      maxAsyncRequests: 30,     // 并发异步请求上限
    },
  },
};
```

## Prefetch

Prefetch 在浏览器空闲时预取「未来可能访问」的资源，用于下个页面或下一步操作，优先级低，不阻塞当前页面。

```js
// 用户可能访问的下一路由，空闲时预取
import(/* webpackPrefetch: true */ './next-page');
```

```text
Prefetch 特点：
1. 空闲时加载，不抢占当前带宽
2. 通过 <link rel="prefetch"> 实现
3. 适用于「预测下一步」的场景
```

## Preload

Preload 与当前页面并行加载「即将马上用到」的资源，优先级高，用于关键资源加速。

```js
// 当前页面马上要用的资源，并行预加载
import(/* webpackPreload: true */ './critical-module');
```

```text
Prefetch vs Preload：
Prefetch —— 空闲加载未来资源（低优先级）
Preload —— 并行加载当前急需资源（高优先级）
```

## Cache

Cache 通过 contenthash 文件名实现浏览器长缓存：内容不变则哈希不变，内容变化则哈希变化，配合强缓存策略。

```js
module.exports = {
  output: {
    filename: '[name].[contenthash:8].js',
    chunkFilename: '[name].[contenthash:8].chunk.js',
  },
  optimization: {
    runtimeChunk: 'single',   // 抽离 runtime，避免其变化导致全量失效
    moduleIds: 'deterministic',
  },
};
```

```text
长缓存要点：
1. 文件名带 contenthash
2. runtime 单独抽出（runtimeChunk: 'single'）
3. moduleIds 用 deterministic 保证稳定
4. 服务端对 hash 文件设置 max-age 长缓存
```

## Persistent Cache

Persistent Cache 把构建结果缓存到磁盘，二次构建时复用，大幅缩短冷启动后的构建时间。Webpack 5 内置（cache: { type: 'filesystem' }）。

```js
module.exports = {
  cache: {
    type: 'filesystem',       // 磁盘文件缓存
    buildDependencies: { config: [__filename] }, // 配置变化则失效
  },
};
```

```text
Persistent Cache 收益：
1. 二次构建显著提速（可到秒级）
2. 配置文件变化自动失效重建
3. CI 环境需注意缓存目录持久化
```

## Module Federation

Module Federation（模块联邦）让多个独立构建的应用在运行时共享模块，实现微前端架构，核心是 host 与 remote 的概念。

```js
// remote（被共享方）暴露模块
const { ModuleFederationPlugin } = require('webpack').container;
module.exports = {
  plugins: [
    new ModuleFederationPlugin({
      name: 'app1',
      filename: 'remoteEntry.js',
      exposes: { './Button': './src/Button' },
    }),
  ],
};
```

```js
// host（消费方）引用远程模块
const { ModuleFederationPlugin } = require('webpack').container;
module.exports = {
  plugins: [
    new ModuleFederationPlugin({
      name: 'shell',
      remotes: { app1: 'app1@http://localhost:3001/remoteEntry.js' },
    }),
  ],
};

// 业务代码
import RemoteButton from 'app1/Button';
```

```text
Module Federation 要点：
1. 运行时共享，无需重新构建消费方
2. exposes 暴露模块，remotes 声明依赖
3. 共享依赖用 shared 配置避免重复加载
```

## 应用场景实战

### 场景一：路由级懒加载 + 长缓存

```js
import { lazy, Suspense } from 'react';
const Home = lazy(() => import(/* webpackChunkName: "home" */ './pages/Home'));
const User = lazy(() => import(/* webpackChunkName: "user" */ './pages/User'));

function App() {
  return (
    <Suspense fallback={<div>Loading...</div>}>
      <Home />
      <User />
    </Suspense>
  );
}
```

### 场景二：vendor 拆分 + 持久化缓存

```js
module.exports = {
  mode: 'production',
  output: { filename: '[name].[contenthash:8].js', clean: true },
  cache: { type: 'filesystem', buildDependencies: { config: [__filename] } },
  optimization: {
    runtimeChunk: 'single',
    moduleIds: 'deterministic',
    splitChunks: {
      chunks: 'all',
      cacheGroups: {
        vendor: { test: /[\\/]node_modules[\\/]/, name: 'vendors', chunks: 'all' },
      },
    },
  },
};
```

## 最佳实践与踩坑记录

### 最佳实践

1. Tree Shaking 依赖 ES Module 与正确的 sideEffects
2. 路由级懒加载，首屏只加载必要代码
3. runtimeChunk 单独抽出，稳定长缓存
4. Prefetch 用于下一路由，Preload 用于当前关键资源
5. vendor 拆分 + contenthash 实现依赖缓存复用

### 踩坑记录

```text
坑 1：Tree Shaking 失效
结论：打包后仍包含大量未使用代码。
原因：用了 CommonJS 或 sideEffects 配置错误。
解法：改用 ESM，package.json 正确声明 sideEffects。

坑 2：contenthash 频繁变化导致缓存失效
结论：vendor 每次发布哈希都变，缓存全部失效。
原因：runtime 代码混入业务 chunk，module id 不稳定。
解法：runtimeChunk: 'single' + moduleIds: 'deterministic'。

坑 3：懒加载无 loading 反馈
结论：点击后长时间白屏无提示。
原因：动态导入未配 fallback。
解法：用 Suspense/loading 组件提供加载反馈。

坑 4：Prefetch 滥用
结论：预取了大量不会访问的资源，浪费带宽。
原因：对不确定资源也开了 webpackPrefetch。
解法：只对高概率访问的下一路由预取。

坑 5：Persistent Cache 在 CI 失效
结论：CI 每次构建都慢，缓存没生效。
原因：CI 容器不持久化 node_modules/.cache 目录。
解法：CI 配置缓存目录持久化，或用缓存加速服务。
```

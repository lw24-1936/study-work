## 概述

Loader 是 Webpack 处理「非 JS 文件」的核心机制，它把源文件转换成 Webpack 能识别的模块。Loader 按「从右向左、从下到上」的顺序链式执行，每个 Loader 只负责单一职责。

```text
Loader 核心要点：
1. 把非 JS 文件转成模块（CSS、图片、TS 等）
2. 链式执行，顺序从右向左
3. 每个 loader 单一职责，可组合
4. 通过 module.rules 的 test/use 配置
5. 用 include/exclude 控制处理范围
```

```js
// 链式顺序：sass-loader → css-loader → style-loader
module.exports = {
  module: {
    rules: [
      { test: /\.scss$/, use: ['style-loader', 'css-loader', 'sass-loader'] },
    ],
  },
};
```

## babel-loader

babel-loader 用 Babel 把新版 JavaScript（ES6+、JSX、TS）转译为兼容目标浏览器的代码。

```js
module.exports = {
  module: {
    rules: [
      {
        test: /\.jsx?$/,
        exclude: /node_modules/,
        use: {
          loader: 'babel-loader',
          options: {
            presets: [['@babel/preset-env', { targets: '> 0.25%, not dead' }], '@babel/preset-react'],
          },
        },
      },
    ],
  },
};
```

```text
babel-loader 要点：
1. 只转译 JS 语法，不处理 API（需 polyfill）
2. 必须 exclude node_modules，否则构建极慢
3. 通常配合 .babelrc / babel.config.js 使用
```

## css-loader

css-loader 解析 CSS 中的 @import 和 url()，把 CSS 转成 JS 模块（CommonJS 字符串数组）。

```js
module.exports = {
  module: {
    rules: [
      {
        test: /\.css$/,
        use: [
          'style-loader',
          {
            loader: 'css-loader',
            options: {
              importLoaders: 1, // 让 @import 的资源也经过前面的 loader
              modules: { localIdentName: '[name]__[local]--[hash:base64:5]' }, // CSS Modules
            },
          },
        ],
      },
    ],
  },
};
```

```text
css-loader 职责：
1. 解析 @import 与 url() 依赖
2. 支持 CSS Modules（局部作用域）
3. 输出 JS 字符串，交给 style-loader 或 MiniCssExtractPlugin
```

## style-loader

style-loader 把 css-loader 产出的 CSS 字符串通过 `<style>` 标签注入到页面 DOM 中，用于开发环境热更新。

```js
module.exports = {
  module: {
    rules: [
      { test: /\.css$/, use: ['style-loader', 'css-loader'] },
    ],
  },
};
```

```text
style-loader 特点：
1. 开发环境友好，支持 HMR
2. 运行时注入，会阻塞首屏渲染
3. 生产环境应替换为 MiniCssExtractPlugin（抽离成独立文件）
```

## postcss-loader

postcss-loader 用 PostCSS 对 CSS 做后处理，最典型的是 autoprefixer（自动加浏览器前缀）和 px-to-rem 等插件。

```js
module.exports = {
  module: {
    rules: [
      {
        test: /\.css$/,
        use: [
          'style-loader',
          'css-loader',
          {
            loader: 'postcss-loader',
            options: {
              postcssOptions: {
                plugins: ['autoprefixer'],
              },
            },
          },
        ],
      },
    ],
  },
};
```

```text
PostCSS 与 autoprefixer：
输入：display: flex;
输出：display: -webkit-box; display: -ms-flexbox; display: flex;
```

## sass-loader

sass-loader 把 Sass/SCSS 编译成 CSS，需依赖 sass（Dart Sass）或 node-sass，通常放在链式最右侧（最先执行）。

```js
module.exports = {
  module: {
    rules: [
      {
        test: /\.scss$/,
        use: ['style-loader', 'css-loader', 'postcss-loader', 'sass-loader'],
      },
    ],
  },
};
```

```scss
// 变量与嵌套
$primary: #409eff;
.card {
  color: $primary;
  &:hover { opacity: 0.8; }
}
```

## file-loader

file-loader 把文件拷贝到输出目录并返回 URL，是处理图片、字体等静态资源的传统方式（Webpack 5 已用 asset/resource 取代）。

```js
module.exports = {
  module: {
    rules: [
      {
        test: /\.(png|jpe?g|gif)$/i,
        use: {
          loader: 'file-loader',
          options: { name: '[name].[hash:8].[ext]', outputPath: 'images/' },
        },
      },
    ],
  },
};
```

```text
file-loader 与 asset/resource 等价：
file-loader → type: 'asset/resource'
前者是旧写法，Webpack 5 推荐后者（内置，无需安装）
```

## url-loader

url-loader 在 file-loader 基础上增加「小文件转 base64 内联」的能力：小于 limit 的文件转成 data URI，减少 HTTP 请求。

```js
module.exports = {
  module: {
    rules: [
      {
        test: /\.(png|jpe?g|gif)$/i,
        use: {
          loader: 'url-loader',
          options: {
            limit: 8 * 1024,          // 8KB 以下内联
            fallback: 'file-loader',  // 超过则回退到 file-loader
          },
        },
      },
    ],
  },
};
```

```text
url-loader 与 asset 等价：
url-loader + limit → type: 'asset' + parser.dataUrlCondition.maxSize
内联优点：减少请求数；缺点：增大 JS 体积
```

## 应用场景实战

### 场景一：React + SCSS 完整 Loader 链

```js
module.exports = {
  module: {
    rules: [
      {
        test: /\.jsx?$/,
        exclude: /node_modules/,
        use: { loader: 'babel-loader', options: { presets: ['@babel/preset-env', '@babel/preset-react'] } },
      },
      {
        test: /\.scss$/,
        use: [
          'style-loader',
          { loader: 'css-loader', options: { modules: true } },
          { loader: 'postcss-loader', options: { postcssOptions: { plugins: ['autoprefixer'] } } },
          'sass-loader',
        ],
      },
    ],
  },
};
```

### 场景二：图片按大小内联或输出

```js
module.exports = {
  module: {
    rules: [
      {
        test: /\.(png|jpe?g|gif|svg)$/i,
        type: 'asset',
        parser: { dataUrlCondition: { maxSize: 10 * 1024 } },
        generator: { filename: 'images/[name].[hash:8][ext]' },
      },
    ],
  },
};
```

## 最佳实践与踩坑记录

### 最佳实践

1. 每个 Loader 只做一件事，按职责链式组合
2. babel-loader 必须 exclude node_modules
3. 开发用 style-loader，生产用 MiniCssExtractPlugin.loader
4. Webpack 5 优先用 asset module 取代 file-loader/url-loader
5. sass-loader 放最右，css-loader 放中间，style-loader 放最左

### 踩坑记录

```text
坑 1：Loader 顺序写反
结论：SCSS 编译报语法错误。
原因：sass-loader 必须在 css-loader 之前（右侧）执行。
解法：use 数组顺序为 ['style-loader', 'css-loader', 'sass-loader']。

坑 2：babel-loader 未排除 node_modules
结论：构建极慢甚至内存溢出。
原因：对海量依赖包重复转译。
解法：设置 exclude: /node_modules/。

坑 3：style-loader 用于生产环境
结论：首屏出现白屏、FOUC，CSS 阻塞渲染。
原因：style-loader 运行时注入 JS 内嵌样式。
解法：生产换 MiniCssExtractPlugin.loader 抽离 CSS 文件。

坑 4：url-loader limit 设太大
结论：JS 体积暴涨，反而拖慢加载。
原因：大量图片被内联成 base64，字符串体积膨胀 33%。
解法：limit 控制在 8~10KB，大图走文件输出。

坑 5：css-loader 的 importLoaders 未配置
结论：@import 的 CSS 没经过 postcss-loader 处理。
原因：默认 @import 资源不再回到前面的 loader。
解法：设置 importLoaders 为前置 loader 数量。
```

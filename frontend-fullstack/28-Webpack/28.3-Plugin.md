## 概述

Plugin 通过 Webpack 的钩子机制（Tapable）介入编译全流程，实现 Loader 无法完成的整体性任务：生成 HTML、抽离 CSS、注入环境变量、压缩产物等。它们是 Webpack 生态最活跃的扩展点。

```text
Plugin 核心要点：
1. 基于 Tapable 的 hooks 事件机制
2. 贯穿 compile → emit → done 全生命周期
3. 一个插件通常对应一个独立能力
4. 实例化后放入 plugins 数组
5. 与 Loader 互补：Loader 管模块转换，Plugin 管流程扩展
```

```js
// 自定义 Plugin 的最小结构
class MyPlugin {
  apply(compiler) {
    compiler.hooks.done.tap('MyPlugin', (stats) => {
      console.log('构建完成');
    });
  }
}
module.exports = { plugins: [new MyPlugin()] };
```

## HtmlWebpackPlugin

HtmlWebpackPlugin 根据模板生成 HTML 文件，并自动注入打包后的 JS/CSS 资源，支持多页面。

```js
const HtmlWebpackPlugin = require('html-webpack-plugin');

module.exports = {
  plugins: [
    new HtmlWebpackPlugin({
      template: './public/index.html',
      filename: 'index.html',
      title: '我的应用',
      chunks: ['main'],
      minify: { removeComments: true, collapseWhitespace: true },
    }),
  ],
};
```

```text
HtmlWebpackPlugin 要点：
1. 自动注入带 hash 的 script/link 标签
2. 支持 template 模板变量（如 <%= htmlWebpackPlugin.options.title %>）
3. 多页面时用 chunks 控制每个页面引入哪些产物
```

## MiniCssExtractPlugin

MiniCssExtractPlugin 把 CSS 从 JS 中抽离成独立文件，替代 style-loader 用于生产环境，实现 CSS 并行加载与缓存。

```js
const MiniCssExtractPlugin = require('mini-css-extract-plugin');

module.exports = {
  module: {
    rules: [
      { test: /\.css$/, use: [MiniCssExtractPlugin.loader, 'css-loader'] },
    ],
  },
  plugins: [
    new MiniCssExtractPlugin({ filename: '[name].[contenthash:8].css' }),
  ],
};
```

```text
MiniCssExtractPlugin 优点：
1. CSS 独立成文件，可与 JS 并行加载
2. 配合 contenthash 实现 CSS 长缓存
3. 避免 style-loader 运行时注入的阻塞
```

## DefinePlugin

DefinePlugin 在编译期替换代码中的全局常量，常用于注入环境变量、区分生产/开发环境。

```js
const webpack = require('webpack');

module.exports = {
  plugins: [
    new webpack.DefinePlugin({
      'process.env.NODE_ENV': JSON.stringify('production'),
      'API_BASE': JSON.stringify('https://api.example.com'),
    }),
  ],
};
```

```text
DefinePlugin 要点：
1. 是编译期文本替换，不是运行时注入
2. 值必须 JSON.stringify，否则会被当作标识符
3. 常用于配合条件编译（如 process.env.NODE_ENV === 'production' 被摇树）
```

## EnvironmentPlugin

EnvironmentPlugin 是 DefinePlugin 的便捷封装，自动读取 process.env 中的环境变量注入到构建中。

```js
const webpack = require('webpack');

module.exports = {
  plugins: [
    // 注入所有以 APP_ 开头的环境变量
    new webpack.EnvironmentPlugin({ NODE_ENV: 'development', ...process.env }),
  ],
};
```

```text
EnvironmentPlugin 与 DefinePlugin：
DefinePlugin 手动声明要注入的常量
EnvironmentPlugin 自动从 process.env 读取并注入
前者更灵活，后者更简洁
```

## CopyWebpackPlugin

CopyWebpackPlugin 把静态文件（如 favicon、public 目录下的资源）原样拷贝到输出目录。

```js
const CopyWebpackPlugin = require('copy-webpack-plugin');

module.exports = {
  plugins: [
    new CopyWebpackPlugin({
      patterns: [
        { from: 'public', to: 'public', globOptions: { ignore: ['**/index.html'] } },
        { from: 'src/assets/favicon.ico', to: 'favicon.ico' },
      ],
    }),
  ],
};
```

```text
CopyWebpackPlugin 要点：
1. 适用于无需处理的静态资源
2. 可配置 glob 过滤忽略文件
3. 注意与 HtmlWebpackPlugin 的模板目录避免重复拷贝
```

## TerserPlugin

TerserPlugin 是生产环境默认的 JS 压缩插件，通过 terser 压缩混淆代码、删除注释与死代码。

```js
const TerserPlugin = require('terser-webpack-plugin');

module.exports = {
  mode: 'production',
  optimization: {
    minimize: true,
    minimizer: [
      new TerserPlugin({
        parallel: true,                 // 多进程并行压缩
        terserOptions: {
          compress: { drop_console: true },
          format: { comments: false },
        },
      }),
    ],
  },
};
```

```text
TerserPlugin 要点：
1. mode: 'production' 时自动启用
2. parallel 开启多核并行压缩
3. drop_console 删除 console 语句（慎用，需保留日志时不配）
```

## CompressionPlugin

CompressionPlugin 对产物进行 gzip/brotli 预压缩，生成 .gz/.br 文件，配合服务器静态压缩传输。

```js
const CompressionPlugin = require('compression-webpack-plugin');

module.exports = {
  plugins: [
    new CompressionPlugin({
      algorithm: 'gzip',
      test: /\.(js|css|html|svg)$/,
      threshold: 10240,   // 超过 10KB 才压缩
      minRatio: 0.8,
    }),
  ],
};
```

```text
CompressionPlugin 要点：
1. 生成 .gz 文件，由 Nginx 等直接返回，省去动态压缩
2. 也支持 brotli（压缩率更高）
3. 需服务端配置 Content-Encoding 配合使用
```

## 应用场景实战

### 场景一：生产环境完整 Plugin 配置

```js
const HtmlWebpackPlugin = require('html-webpack-plugin');
const MiniCssExtractPlugin = require('mini-css-extract-plugin');
const CopyWebpackPlugin = require('copy-webpack-plugin');
const TerserPlugin = require('terser-webpack-plugin');
const CompressionPlugin = require('compression-webpack-plugin');
const webpack = require('webpack');

module.exports = {
  mode: 'production',
  plugins: [
    new HtmlWebpackPlugin({ template: './public/index.html' }),
    new MiniCssExtractPlugin({ filename: '[name].[contenthash:8].css' }),
    new CopyWebpackPlugin({ patterns: [{ from: 'public/static', to: 'static' }] }),
    new webpack.DefinePlugin({ 'process.env.NODE_ENV': JSON.stringify('production') }),
    new CompressionPlugin({ algorithm: 'gzip', test: /\.(js|css)$/ }),
  ],
  optimization: {
    minimize: true,
    minimizer: [new TerserPlugin({ parallel: true })],
  },
};
```

### 场景二：自定义构建完成通知插件

```js
class BuildNotifyPlugin {
  apply(compiler) {
    compiler.hooks.done.tap('BuildNotifyPlugin', (stats) => {
      const time = (stats.endTime - stats.startTime) / 1000;
      console.log(`构建完成，耗时 ${time}s，${stats.hasErrors() ? '有错误' : '成功'}`);
    });
  }
}

module.exports = { plugins: [new BuildNotifyPlugin()] };
```

## 最佳实践与踩坑记录

### 最佳实践

1. 生产环境用 MiniCssExtractPlugin 替代 style-loader
2. DefinePlugin 的值务必 JSON.stringify
3. TerserPlugin 开启 parallel 提升压缩速度
4. CompressionPlugin 只在确有 gzip 需求时使用，避免多余文件
5. 大文件静态资源用 CopyWebpackPlugin，小图标走 asset inline

### 踩坑记录

```text
坑 1：DefinePlugin 值未 JSON.stringify
结论：代码里的常量被替换成未定义的标识符报错。
原因：DefinePlugin 做文本替换，非字符串会被当变量名。
解法：值统一 JSON.stringify('xxx')。

坑 2：MiniCssExtractPlugin 与 style-loader 混用
结论：CSS 既被抽离又被注入，重复加载。
原因：同一规则里同时用了两个 loader。
解法：开发 style-loader，生产 MiniCssExtractPlugin.loader，用环境变量区分。

坑 3：HtmlWebpackPlugin 多页面重复注入
结论：每个页面都引用了所有入口的资源。
原因：未用 chunks 指定页面关联的入口。
解法：为每个页面显式配置 chunks。

坑 4：CopyWebpackPlugin 重复拷贝模板
结论：public/index.html 被 HtmlWebpackPlugin 和 Copy 各处理一次。
原因：模板文件同时被两个插件处理。
解法：Copy 配置用 globOptions.ignore 排除 index.html。

坑 5：TerserPlugin drop_console 误删业务日志
结论：生产环境 console 日志全部消失，排查困难。
原因：drop_console 删除了所有 console 语句。
解法：仅删 console.log 保留 console.error，或按需开启。
```

## 概述

Webpack 是一个模块打包器（Module Bundler），它把项目中的各种资源（JS、CSS、图片、字体等）都当作「模块」来处理，从入口开始构建依赖图，最终输出浏览器可运行的静态产物。理解其核心概念是掌握 Webpack 的前提。

```text
Webpack 核心概念：
1. Entry —— 入口，构建依赖图的起点
2. Output —— 出口，产物输出位置与命名规则
3. Loader —— 加载器，把非 JS 文件转换为模块
4. Plugin —— 插件，扩展打包全生命周期的能力
5. Module —— 模块，构建的基本单位（一切皆模块）
6. Chunk —— 代码块，构建过程中的中间产物
7. Bundle —— 打包产物，最终输出的文件
8. Asset —— 静态资源，图片/字体等非 JS 资源
```

```js
// 一个最小可运行的 webpack.config.js
const path = require('path');

module.exports = {
  entry: './src/index.js',          // 入口
  output: {                          // 出口
    path: path.resolve(__dirname, 'dist'),
    filename: 'bundle.js',
  },
  module: {
    rules: [{ test: /\.css$/, use: ['style-loader', 'css-loader'] }],
  },
  plugins: [],
};
```

## Entry

Entry 是 Webpack 构建的起点，Webpack 从这里开始递归解析依赖，生成完整的依赖图。可以有单个入口，也可以有多个入口。

```js
// 单入口（简写）
module.exports = {
  entry: './src/index.js',
};

// 单入口（完整写法，可配置 chunk 名）
module.exports = {
  entry: { main: './src/index.js' },
};

// 多入口（多页应用）
module.exports = {
  entry: {
    home: './src/home.js',
    about: './src/about.js',
  },
};
```

```text
入口的作用：
1. 确定构建起点，递归收集所有依赖
2. 每个入口对应一个 Chunk（及其依赖构成的代码块）
3. 多入口配合多页面应用，产物按入口切分
```

## Output

Output 定义打包产物的输出位置与文件命名规则，常用占位符如 [name]、[hash]、[contenthash]。

```js
const path = require('path');

module.exports = {
  output: {
    path: path.resolve(__dirname, 'dist'),   // 输出目录（绝对路径）
    filename: '[name].[contenthash:8].js',   // 入口产物命名
    chunkFilename: '[name].[contenthash:8].chunk.js', // 异步 chunk 命名
    publicPath: '/',                          // 资源 CDN/部署前缀
    clean: true,                              // 构建前清空输出目录
  },
};
```

```text
常用占位符：
[name] —— chunk 名称（入口名或动态导入名）
[hash] —— 整个构建的哈希
[contenthash] —— 按文件内容生成的哈希（利于缓存）
[id] —— chunk 的模块 id
```

## Loader

Loader 让 Webpack 能处理非 JS 文件（CSS、图片、TS 等）。它把源文件「转换」成可作为模块使用的内容，在 module.rules 中通过 test 匹配文件、use 指定加载器。

```js
module.exports = {
  module: {
    rules: [
      { test: /\.js$/, exclude: /node_modules/, use: 'babel-loader' },
      { test: /\.css$/, use: ['style-loader', 'css-loader'] },
      { test: /\.(png|jpg)$/, type: 'asset/resource' },
    ],
  },
};
```

```text
Loader 特性：
1. 链式调用，从右向左（从下到上）依次执行
2. 每个 loader 只做一件事（单一职责）
3. 匹配用 test（正则），排除用 exclude，包含用 include
```

## Plugin

Plugin 通过钩子（hooks）介入 Webpack 的整个编译流程，能做 Loader 做不到的事（生成 HTML、抽离 CSS、压缩、定义环境变量等）。

```js
const HtmlWebpackPlugin = require('html-webpack-plugin');
const MiniCssExtractPlugin = require('mini-css-extract-plugin');

module.exports = {
  plugins: [
    new HtmlWebpackPlugin({ template: './public/index.html' }),
    new MiniCssExtractPlugin({ filename: '[name].[contenthash].css' }),
  ],
};
```

```text
Plugin 与 Loader 的区别：
Loader —— 转换模块内容（针对文件）
Plugin —— 扩展编译过程（针对整个构建生命周期）
```

## Module

Webpack 中「一切皆模块」：JS 是模块，CSS、图片、字体、JSON 也都是模块。每个模块有依赖关系，Webpack 将其组织成模块图。

```js
// index.js 依赖两个模块
import './style.css';          // CSS 也是一个模块
import logo from './logo.png'; // 图片也是一个模块
import data from './data.json';// JSON 也是一个模块

const img = document.createElement('img');
img.src = logo;
document.body.appendChild(img);
```

```text
模块类型（Module Types）：
javascript/auto —— 默认 JS 模块
asset/resource —— 单独输出文件并导出 URL
asset/inline —— 内联为 data URI
asset/source —— 导出文件原始内容
```

## Chunk

Chunk 是构建过程中的中间代码块，是内存里的组织单位。它来源于入口文件或动态导入，最终会被输出成一个或多个 Bundle 文件。

```js
// 动态导入产生一个新的异步 Chunk
button.addEventListener('click', () => {
  import('./heavy-module').then((m) => m.default());
});
```

```text
Chunk 的来源：
1. 入口 Entry —— 每个入口一个 chunk
2. 动态 import() —— 每个动态导入一个异步 chunk
3. SplitChunksPlugin —— 拆分公共代码产生的 chunk
```

## Bundle

Bundle 是最终写盘输出的文件，是 Chunk 经过编译、优化后的产物。一个 Chunk 可以对应一个或多个 Bundle（例如 JS + CSS）。

```text
Chunk 与 Bundle 的关系：
1. Chunk 是构建内存中的概念，Bundle 是最终产物
2. 通常一个 Chunk 输出一个 JS Bundle
3. 若 chunk 内含 CSS，还会额外输出一个 CSS Bundle
```

## Asset

Asset 指图片、字体、音视频等非 JS 的静态资源。Webpack 5 用 asset module 处理，替代了早期的 file-loader / url-loader。

```js
module.exports = {
  module: {
    rules: [
      {
        test: /\.(png|jpe?g|gif)$/i,
        type: 'asset',                     // 自动在 inline 与 resource 间切换
        parser: { dataUrlCondition: { maxSize: 8 * 1024 } },
      },
      { test: /\.(woff2?|eot|ttf|otf)$/i, type: 'asset/resource' },
    ],
  },
};
```

## 应用场景实战

### 场景一：多页应用打包

```js
const path = require('path');
const HtmlWebpackPlugin = require('html-webpack-plugin');

module.exports = {
  entry: { home: './src/home.js', about: './src/about.js' },
  output: {
    path: path.resolve(__dirname, 'dist'),
    filename: '[name].[contenthash:8].js',
    clean: true,
  },
  plugins: [
    new HtmlWebpackPlugin({ template: './public/index.html', chunks: ['home'], filename: 'home.html' }),
    new HtmlWebpackPlugin({ template: './public/index.html', chunks: ['about'], filename: 'about.html' }),
  ],
};
```

### 场景二：SPA 单页应用

```js
const path = require('path');

module.exports = {
  entry: './src/main.js',
  output: {
    path: path.resolve(__dirname, 'dist'),
    filename: 'app.[contenthash:8].js',
    publicPath: '/',
  },
  devServer: { port: 3000, historyApiFallback: true },
};
```

## 最佳实践与踩坑记录

### 最佳实践

1. 入口与输出都写绝对路径，避免相对路径歧义
2. 产物文件名用 [contenthash] 实现长缓存
3. Loader 用 include/exclude 缩小处理范围，提升构建速度
4. output.clean 开启，避免旧产物残留
5. 理解 Chunk/Bundle/Asset 三者的差异，才能正确配置代码分割

### 踩坑记录

```text
坑 1：publicPath 配错导致资源 404
结论：部署到子路径时，JS/CSS 加载 404。
原因：publicPath 未匹配实际部署路径。
解法：子路径部署时设 output.publicPath = '/sub/' 或 './'。

坑 2：多入口没配 HtmlWebpackPlugin chunks
结论：每个 HTML 都引入了所有入口的产物。
原因：HtmlWebpackPlugin 默认注入全部 chunk。
解法：为每个页面显式指定 chunks。

坑 3：entry 用相对路径失败
结论：构建报错找不到入口文件。
原因：entry 相对路径是相对 webpack 运行目录而非配置文件。
解法：用 path.resolve(__dirname, 'src/index.js')。

坑 4：contenthash 文件名没清旧文件
结论：dist 目录积累大量历史版本文件。
原因：每次构建内容哈希变化都产生新文件。
解法：开启 output.clean 或用 clean-webpack-plugin。

坑 5：asset 类型与 loader 混用冲突
结论：配置了 file-loader 又配 asset/resource，图片输出两次。
原因：Webpack 5 的 asset module 与旧 loader 重复处理。
解法：二选一，Webpack 5 优先使用 asset module。
```

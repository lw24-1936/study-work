## 概述

GraphQL 是一种 API 查询语言，客户端可以**精确指定**需要哪些字段，一次请求获取多个资源，避免 REST 的过度获取（over-fetching）和不足获取（under-fetching）。

```text
GraphQL vs REST：
REST —— 每个资源一个端点，字段由服务端定死
GraphQL —— 单一端点，字段由客户端指定

GraphQL 的优势：
1. 按需获取 —— 只取需要的字段
2. 一次多资源 —— 一个请求拿多个数据
3. 强类型 —— Schema 定义类型，可自省
```

## Schema 与 Type

Schema 是 GraphQL 的类型系统，定义可查询的数据结构和类型。

```graphql
# Schema 定义
type User {
  id: ID!
  name: String!
  age: Int
  posts: [Post!]!
}

type Post {
  id: ID!
  title: String!
  author: User!
}

type Query {
  user(id: ID!): User
  users: [User!]!
}

type Mutation {
  createUser(name: String!): User!
}
```

```text
标量类型（Scalar）：
String、Int、Float、Boolean、ID

类型修饰符：
! —— 非空（必填/不可为 null）
[] —— 列表
```

## Query 查询

Query 是读取操作，客户端指定需要的字段。

```graphql
# 查询：只取 name 和 age
query {
  user(id: "1") {
    name
    age
  }
}
```

```graphql
# 查询带参数
query GetUser($id: ID!) {
  user(id: $id) {
    name
    posts {
      title
    }
  }
}
```

```js
// 客户端请求
const GET_USER = `
  query GetUser($id: ID!) {
    user(id: $id) { name age }
  }
`;

const data = await client.request(GET_USER, { id: '1' });
```

```text
Query 的特点：
1. 只返回请求的字段（按需）
2. 可嵌套查询关联数据（一次多资源）
3. 支持变量（$id）
```

## Mutation 变更

Mutation 是写操作（增删改），语法与 Query 类似。

```graphql
mutation CreateUser($name: String!) {
  createUser(name: $name) {
    id
    name
  }
}
```

```text
Mutation vs Query：
Query —— 读取（可并行）
Mutation —— 写入（串行执行，保证顺序）

语义上明确区分读写。
```

## Subscription 订阅

Subscription 是实时推送，服务端数据变化时主动推给客户端（基于 WebSocket）。

```graphql
subscription {
  messageAdded {
    id
    content
    author
  }
}
```

```js
// 客户端订阅
client.subscribe({
  query: MESSAGE_ADDED,
}).subscribe({
  next: data => console.log('新消息', data),
});
```

```text
Subscription 的用途：
1. 实时聊天、消息推送
2. 实时数据更新（行情、通知）

基于 WebSocket 的持久连接。
```

## Resolver 解析器

Resolver 是服务端实际取数据的函数，为 Schema 的每个字段提供数据。

```js
// 服务端 Resolver
const resolvers = {
  Query: {
    user: (parent, args, context) => {
      return db.findUser(args.id);      // 从数据库取数据
    },
    users: () => db.findAllUsers(),
  },
  User: {
    posts: (user) => db.findPosts(user.id),   // 关联字段
  },
  Mutation: {
    createUser: (parent, args) => db.createUser(args.name),
  },
};
```

```text
Resolver 的四参数：
parent —— 父字段的返回值
args —— 查询参数
context —— 共享上下文（鉴权信息、数据源）
info —— 查询的元信息
```

## Input / Fragment / Directive

GraphQL 提供输入类型、片段、指令等增强语法。

```graphql
# Input：输入类型（用于 mutation 参数）
input UserInput {
  name: String!
  age: Int
}

mutation Create($input: UserInput!) {
  createUser(input: $input) { id }
}
```

```graphql
# Fragment：复用字段集合
fragment UserFields on User {
  id
  name
  age
}

query {
  user(id: "1") { ...UserFields }
}
```

```graphql
# Directive：条件包含/跳过字段
query GetUser($withAge: Boolean!) {
  user(id: "1") {
    name
    age @include(if: $withAge)
  }
}
```

```text
三个增强语法：
Input —— 复用输入参数
Fragment —— 复用字段集合
Directive —— 条件字段（@include / @skip）
```

## GraphQL Client 与 Cache

客户端库（Apollo Client、urql）提供请求、缓存、状态管理等能力。

```js
// Apollo Client 示例
import { ApolloClient, InMemoryCache, gql } from '@apollo/client';

const client = new ApolloClient({
  uri: '/graphql',
  cache: new InMemoryCache(),
});

const { data } = await client.query({
  query: gql`query { users { id name } }`,
});
```

```text
GraphQL Client 的价值：
1. 请求封装 —— 简化查询调用
2. 缓存 —— 本地缓存 + 规范化存储
3. 状态同步 —— 与 UI 框架集成

缓存策略：规范化缓存（按类型 + id 存储），可精确更新。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 客户端只请求需要的字段，避免过度获取
2. 复杂参数用 Input 类型封装
3. 复用字段用 Fragment
4. 分页用游标（cursor）模式
5. 服务端做好 N+1 问题的优化（DataLoader）

### 踩坑记录

```text
坑 1：N+1 查询问题
结论：查询关联字段时，每个子项都发一次数据库查询。
原因：Resolver 逐个解析关联字段，未批量加载。
解法：用 DataLoader 批量加载。

坑 2：过度嵌套查询
结论：深层嵌套导致服务端压力大。
原因：客户端查询过深、字段过多。
解法：限制查询深度，控制复杂度（cost 分析）。

坑 3：Mutation 误用 Query
结论：用 Query 做写操作，缓存和语义混乱。
原因：不区分读写。
解法：写操作用 Mutation。

坑 4：客户端缓存失效
结论：数据更新后缓存没同步。
原因：未正确更新规范化缓存。
解法：用 cache.modify 或 refetch 策略。

坑 5：Subscription 连接管理
结论：订阅连接泄漏或断线不重连。
原因：未管理 WebSocket 生命周期。
解法：组件卸载时取消订阅，断线自动重连。
```

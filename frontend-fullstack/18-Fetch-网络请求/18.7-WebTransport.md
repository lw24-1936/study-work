## 概述

WebTransport 是基于 HTTP/3（QUIC）的新一代传输协议，提供低延迟、多路复用的双向通信，是 WebSocket 的现代继任者。

```text
WebTransport 的优势（相对 WebSocket）：
1. 基于 QUIC —— 更低的建立延迟，抗丢包
2. 多路复用 —— 单连接多流，无队头阻塞
3. 支持数据报 —— 不可靠但低延迟（适合游戏/实时）
4. 双向流 —— 可靠流式传输

现状：较新，浏览器支持逐步完善（Chrome 已支持）。
```

## QUIC 基础

QUIC 是基于 UDP 的传输协议，是 HTTP/3 的基础，也是 WebTransport 的底层。

```text
QUIC 的特点：
1. 基于 UDP —— 自定义可靠传输，不依赖 TCP
2. 低延迟 —— 连接建立快（0-RTT）
3. 无队头阻塞 —— 丢包只影响单个流
4. 内置加密 —— TLS 1.3 集成

对比 TCP：QUIC 解决 TCP 的队头阻塞、连接建立慢等问题。
```

```js
// WebTransport 连接
const transport = new WebTransport('https://example.com:4433/endpoint');

await transport.ready;   // 等待连接建立
console.log('连接建立');
```

## Stream 流

WebTransport 的流支持可靠的有序传输，分单向流和双向流。

```js
// 创建双向流
const stream = await transport.createBidirectionalStream();

// 写入数据
const writer = stream.writable.getWriter();
await writer.write(new Uint8Array([1, 2, 3]));
await writer.close();

// 读取数据
const reader = stream.readable.getReader();
const { value, done } = await reader.read();
```

```js
// 单向流（只发送）
const stream = await transport.createUnidirectionalStream();
const writer = stream.getWriter();
await writer.write(data);
```

```text
流的类型：
双向流（Bidirectional）—— 可读可写
单向流（Unidirectional）—— 只写（客户端到服务端）

流保证：有序、可靠。
```

## Datagram 数据报

Datagram 是不可靠但低延迟的数据报，适合实时场景（游戏状态、实时位置）。

```js
// 发送数据报
const writer = transport.datagrams.writable.getWriter();
await writer.write(new Uint8Array([1, 2, 3]));

// 接收数据报
const reader = transport.datagrams.readable.getReader();
const { value } = await reader.read();
```

```text
Datagram vs Stream：
Datagram —— 不可靠、可能乱序/丢失、低延迟（类似 UDP）
Stream —— 可靠、有序、可能延迟（类似 TCP）

游戏实时状态用 Datagram，文件/消息用 Stream。
```

## Bidirectional Stream 双向流

双向流同时支持读写，是全双工通信的基础。

```js
// 完整的双向流收发
async function communicate(transport) {
  const stream = await transport.createBidirectionalStream();

  const writer = stream.writable.getWriter();
  const reader = stream.readable.getReader();

  // 发送
  await writer.write(encodeData('hello'));

  // 接收
  const { value } = await reader.read();
  console.log('收到:', decodeData(value));

  await writer.close();
}
```

2. 每个流独立收发，互不阻塞
3. 适合需要可靠双向通信的场景

## 应用场景实战

### 场景一：实时游戏（Datagram）

```js
const transport = new WebTransport('https://game.example.com/endpoint');
await transport.ready;

const writer = transport.datagrams.writable.getWriter();

// 高频发送位置（不可靠但低延迟）
function sendPosition(x, y) {
  const data = new Uint8Array([x, y]);
  writer.write(data);   // 不 await（尽力发送）
}
```

### 场景二：文件传输（Stream）

```js
const transport = new WebTransport('https://example.com/endpoint');
await transport.ready;

const stream = await transport.createBidirectionalStream();
const writer = stream.writable.getWriter();

// 分块写入文件数据（可靠有序）
for (const chunk of fileChunks) {
  await writer.write(chunk);
}
await writer.close();
```

## 最佳实践与踩坑记录

### 最佳实践

1. 实时高频数据用 Datagram（低延迟，容忍丢包）
2. 需要可靠传输用 Stream
3. 多路复用：一个连接多个流
4. 检查浏览器支持（feature detection）
5. 生产环境需 HTTPS（QUIC 强制加密）

### 踩坑记录

```text
坑 1：浏览器支持不完整
结论：部分浏览器/环境不支持 WebTransport。
原因：较新的 API，支持度还在普及。
解法：特性检测 + 降级到 WebSocket。

坑 2：Datagram 丢包
结论：数据报丢失，数据不完整。
原因：Datagram 不可靠传输。
解法：需要可靠用 Stream，实时用 Datagram（容忍丢包）。

坑 3：需 HTTPS
结论：非 HTTPS 环境无法建立连接。
原因：QUIC 强制加密（TLS）。
解法：部署 HTTPS，或 localhost 开发。

坑 4：混淆 Stream 与 Datagram
结论：用 Stream 发实时数据，延迟高。
原因：Stream 有可靠传输的开销。
解法：实时用 Datagram，可靠用 Stream。

坑 5：未处理连接关闭
结论：连接关闭后继续读写报错。
原因：未监听 close 事件。
解法：处理 transport.closed，做清理和重连。
```

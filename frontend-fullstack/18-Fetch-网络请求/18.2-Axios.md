## 概述

Axios 是最流行的 HTTP 请求库，基于 Promise，在 fetch 基础上提供了拦截器、超时、取消、自动 JSON 转换等增强能力，浏览器和 Node 均可使用。

```text
Axios 相比 fetch 的增强：
1. 自动 JSON 转换 —— 自动序列化/反序列化
2. 拦截器 —— 请求/响应统一处理
3. 超时 —— 内置 timeout
4. 取消 —— 内置取消机制
5. 默认携带 Cookie —— 同源自动带
6. 响应式错误 —— 非 2xx 自动 reject
```

## Axios 基础用法

```js
// GET
const res = await axios.get('/api/users', { params: { page: 1 } });
res.data;          // 响应数据（已自动解析 JSON）

// POST
await axios.post('/api/users', { name: 'Alice' });

// 通用请求
const res = await axios({
  method: 'post',
  url: '/api/users',
  data: { name: 'Alice' },
});
```

```js
// 创建实例（设置默认配置）
const instance = axios.create({
  baseURL: 'https://api.example.com',
  timeout: 5000,
  headers: { 'X-Custom': 'value' },
});
```

```text
Axios 的响应结构：
res.data —— 响应数据（已解析）
res.status —— 状态码
res.headers —— 响应头
res.config —— 本次请求的配置
```

## Interceptor 拦截器

拦截器在请求发出前、响应返回后统一处理，是 Axios 最强大的特性。

```js
// 请求拦截器：统一加 token
axios.interceptors.request.use(config => {
  config.headers.Authorization = `Bearer ${getToken()}`;
  return config;
}, error => Promise.reject(error));

// 响应拦截器：统一处理错误
axios.interceptors.response.use(
  response => response.data,          // 直接返回数据
  error => {
    if (error.response?.status === 401) {
      redirectToLogin();               // 未授权跳登录
    }
    return Promise.reject(error);
  },
);
```

```js
// 实例级拦截器
const api = axios.create({ baseURL: '/api' });
api.interceptors.request.use(config => {
  config.headers.Authorization = getToken();
  return config;
});
```

```text
拦截器的价值：
1. 请求前 —— 统一加 token、日志、参数处理
2. 响应后 —— 统一错误处理、数据解包、登录失效跳转

多个拦截器按注册顺序执行（请求正向，响应反向）。
```

## Request Config 请求配置

Axios 提供丰富的请求配置项。

```js
axios({
  method: 'post',
  url: '/api/users',
  baseURL: 'https://api.example.com',   // 基础 URL
  timeout: 5000,                        // 超时（毫秒）
  headers: { 'Content-Type': 'application/json' },
  params: { page: 1 },                  // URL 查询参数
  data: { name: 'Alice' },              // 请求体
  withCredentials: true,                // 跨域带 Cookie
  responseType: 'json',                 // 响应类型
  validateStatus: s => s < 500,         // 自定义成功状态
});
```

```text
常用配置项：
baseURL —— 基础 URL（实例化时设）
timeout —— 超时
params —— 查询参数（自动序列化）
data —— 请求体
headers —— 请求头
withCredentials —— 跨域 Cookie
responseType —— json/text/blob/arraybuffer
```

## Response Transform 响应转换

Axios 自动转换请求体和响应体，也支持自定义 transform。

```js
// 默认自动转换：
// 请求：对象 → JSON 字符串
// 响应：JSON 字符串 → 对象

// 自定义 transformResponse
axios.get('/api', {
  transformResponse: [data => {
    // data 是原始字符串，可自定义解析
    return JSON.parse(data);
  }],
});
```

```js
// 响应拦截器里做数据解包
axios.interceptors.response.use(res => res.data);
// 之后使用：const data = await axios.get('/api');
```

## Retry / Timeout / Cancellation

Axios 内置超时和取消，重试需配合拦截器实现。

```js
// 超时
axios.get('/api', { timeout: 3000 })
  .catch(err => {
    if (err.code === 'ECONNABORTED') {
      console.log('请求超时');
    }
  });
```

```js
// 取消
const controller = new AbortController();
axios.get('/api', { signal: controller.signal });

// 取消请求
controller.abort();
```

```js
// 重试（响应拦截器实现）
axios.interceptors.response.use(null, async error => {
  const { config } = error;
  config.retryCount = (config.retryCount || 0) + 1;
  if (config.retryCount <= 3) {
    await new Promise(r => setTimeout(r, config.retryCount * 1000));
    return axios(config);          // 重新发起
  }
  return Promise.reject(error);
});
```

```text
Axios 的取消：
1. 现代用 AbortController（signal）
2. 旧版用 CancelToken（已弃用）

重试要点：限制次数 + 退避延迟，避免重试风暴。
```

## 应用场景实战

### 场景一：封装统一请求实例

```js
const api = axios.create({
  baseURL: '/api',
  timeout: 10000,
});

api.interceptors.request.use(config => {
  config.headers.Authorization = `Bearer ${localStorage.getItem('token')}`;
  return config;
});

api.interceptors.response.use(
  res => res.data,
  error => {
    if (error.response?.status === 401) {
      location.href = '/login';
    }
    return Promise.reject(error);
  },
);

export default api;
```

### 场景二：并发请求

```js
const [user, orders] = await Promise.all([
  api.get('/user'),
  api.get('/orders'),
]);
```

## 最佳实践与踩坑记录

### 最佳实践

1. 用 axios.create 建实例，统一 baseURL 和超时
2. 请求拦截器统一加 token，响应拦截器统一处理错误
3. 取消用 AbortController（signal）
4. 重试用拦截器 + 退避，限制次数
5. 大文件/二进制用 responseType: 'blob'/'arraybuffer'

### 踩坑记录

```text
坑 1：拦截器里忘 return
结论：请求/响应拦截后数据丢失或挂起。
原因：拦截器必须 return config / response。
解法：拦截器末尾 return config（请求）或 response（响应）。

坑 2：错误拦截器未 reject
结论：错误被吞掉，调用方收不到。
原因：错误拦截器没 return Promise.reject(error)。
解法：错误分支 return Promise.reject(error)。

坑 3：并发请求用 Promise.all 无限制
结论：大量请求同时发出。
原因：Promise.all 不限制并发。
解法：用并发池控制数量（见 [[12.5-并发控制]]）。

坑 4：CancelToken 已废弃
结论：用旧 CancelToken API，新版本警告。
原因：CancelToken 被 AbortController 取代。
解法：用 signal: AbortController。

坑 5：baseURL 与 url 拼接歧义
结论：url 以 / 开头时 baseURL 路径被忽略。
原因：绝对路径拼接规则。
解法：统一 url 相对写法，避免歧义。
```

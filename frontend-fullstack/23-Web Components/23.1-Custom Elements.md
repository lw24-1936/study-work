## 概述

Custom Elements 是 Web Components 的核心规范之一，允许开发者定义全新的、语义化的自定义 HTML 标签。自定义元素拥有自己的类、生命周期回调和属性行为，可跨框架复用。

```text
Custom Elements 的价值：
1. 语义化 —— 用 <user-card> 替代一堆 div
2. 可复用 —— 封装逻辑与样式，一处定义处处使用
3. 框架无关 —— 原生浏览器能力，不依赖任何框架
4. 生命周期 —— 挂载/移除/属性变化都有钩子
```

```js
// 定义一个自定义元素
class UserCard extends HTMLElement {
  constructor() {
    super();
    this.innerHTML = '<div>用户卡片</div>';
  }
}
customElements.define('user-card', UserCard);
```

```html
<!-- 使用自定义元素 -->
<user-card></user-card>
```

## HTMLElement

HTMLElement 是所有自定义元素的基类，自定义元素通过继承它获得标准 HTML 元素的全部能力（属性、事件、DOM 操作等）。

```text
继承关系：
HTMLElement → Element → Node → EventTarget

继承 HTMLElement 可获得：
1. 属性读写（getAttribute/setAttribute）
2. 事件绑定（addEventListener）
3. DOM 操作（appendChild/remove）
4. 样式（style 属性、classList）
```

```js
class MyElement extends HTMLElement {
  constructor() {
    super();          // 必须调用父类构造
    this.attachShadow({ mode: 'open' });
    this.shadowRoot.innerHTML = '<p>Hello</p>';
  }
}
```

```text
可继承的扩展类（内置元素扩展）：
class MyButton extends HTMLButtonElement { ... }
customElements.define('my-button', MyButton, { extends: 'button' });
// 使用：<button is="my-button">
```

```text
注意：
1. 构造函数里不能访问属性/子节点（此时元素尚未解析完成）
2. 需要 super() 且不能再有 return
3. 内置元素扩展的兼容性较差（Safari 不支持），谨慎使用
```

## customElements.define

customElements.define 用于注册自定义元素，把标签名绑定到对应的类。注册后才能使用该标签。

```js
customElements.define(name, constructor, options);
// name        —— 标签名，必须含连字符（如 user-card）
// constructor —— 元素类，须继承 HTMLElement
// options     —— 可选，{ extends: 'button' } 用于内置元素扩展
```

```js
// 完整示例
class Tooltip extends HTMLElement {
  constructor() {
    super();
    this.textContent = '提示';
  }
}
customElements.define('my-tooltip', Tooltip);
```

```text
命名规则（硬性要求）：
1. 必须包含连字符 —— 如 my-element、user-card
2. 避免与内置标签冲突 —— 如 div、span 无效
3. 不能重复定义 —— 同一名称定义两次会抛错
```

```js
// 检查是否已定义
if (!customElements.get('user-card')) {
  customElements.define('user-card', UserCard);
}
```

```text
获取已定义元素：
customElements.get('user-card')      // 返回类或 undefined
customElements.whenDefined('user-card')  // 返回 Promise，定义完成后 resolve
```

## Lifecycle Callbacks

生命周期回调是自定义元素在不同阶段自动调用的方法，让开发者能在正确时机执行逻辑。

```text
四个生命周期回调：
1. connectedCallback    —— 元素被插入 DOM 时
2. disconnectedCallback —— 元素从 DOM 移除时
3. adoptedCallback      —— 元素被移动到新文档时
4. attributeChangedCallback —— 监听的属性变化时
```

```js
class Counter extends HTMLElement {
  static get observedAttributes() {
    return ['value'];          // 声明要监听的属性
  }

  constructor() {
    super();
    this._value = 0;
  }

  connectedCallback() {
    // 插入 DOM：初始化、绑定事件、开始定时器
    this.addEventListener('click', () => this._value++);
  }

  disconnectedCallback() {
    // 移除 DOM：清理事件、定时器，防止内存泄漏
  }

  adoptedCallback() {
    // 移动到 iframe 等新文档时触发
  }

  attributeChangedCallback(name, oldVal, newVal) {
    // 属性变化：同步更新内部状态
    console.log(`${name}: ${oldVal} → ${newVal}`);
  }
}
customElements.define('my-counter', Counter);
```

```text
关键规则：
1. connectedCallback 可能被调用多次（元素反复插入/移除）
2. 必须配合 observedAttributes 才会触发 attributeChangedCallback
3. 在 constructor 里拿不到属性，属性监听要等连接后
```

```js
// 属性与回调联动示例
class StatusBadge extends HTMLElement {
  static get observedAttributes() { return ['status']; }

  attributeChangedCallback(name, oldVal, newVal) {
    this.textContent = newVal === 'online' ? '在线' : '离线';
  }
}
customElements.define('status-badge', StatusBadge);

// 修改属性会触发回调
document.querySelector('status-badge').setAttribute('status', 'online');
```

## 应用场景实战

### 场景一：封装用户卡片组件

```js
class UserCard extends HTMLElement {
  static get observedAttributes() { return ['name', 'avatar']; }

  constructor() {
    super();
    this.attachShadow({ mode: 'open' });
  }

  connectedCallback() {
    this.render();
  }

  attributeChangedCallback() {
    this.render();
  }

  render() {
    const name = this.getAttribute('name') || '匿名';
    const avatar = this.getAttribute('avatar') || '/default.png';
    this.shadowRoot.innerHTML = `
      <style>
        .card { display: flex; gap: 8px; align-items: center; }
        img { width: 40px; height: 40px; border-radius: 50%; }
      </style>
      <div class="card">
        <img src="${avatar}" />
        <span>${name}</span>
      </div>
    `;
  }
}
customElements.define('user-card', UserCard);
```

```html
<user-card name="Alice" avatar="/alice.png"></user-card>
```

### 场景二：倒计时组件（含清理）

```js
class Countdown extends HTMLElement {
  connectedCallback() {
    this._timer = setInterval(() => this.update(), 1000);
  }
  disconnectedCallback() {
    clearInterval(this._timer);   // 移除时清理，避免泄漏
  }
  update() {
    this.textContent = new Date().toLocaleTimeString();
  }
}
customElements.define('live-clock', Countdown);
```

## 最佳实践与踩坑记录

### 最佳实践

1. 构造函数只做初始化，DOM 渲染放到 connectedCallback
2. 用 observedAttributes 声明属性监听，避免无效回调
3. disconnectedCallback 里清理事件和定时器，防内存泄漏
4. 标签名必须含连字符，避免与内置元素冲突
5. 复用前用 customElements.get 判断是否已定义

### 踩坑记录

```text
坑 1：重复定义同名元素报错
结论：NotSupportedError，定义失败。
原因：同一标签名 define 两次。
解法：定义前用 customElements.get(name) 判断，或用 whenDefined。

坑 2：标签名没有连字符
结论：定义失败，浏览器报 Invalid name。
原因：自定义元素命名强制要求含连字符。
解法：改成 my-element 这类带连字符的名称。

坑 3：constructor 里读属性拿到 null
结论：构造阶段 getAttribute 返回 null。
原因：构造时属性尚未解析，元素未连接。
解法：属性读取放到 connectedCallback 或 attributeChangedCallback。

坑 4：attributeChangedCallback 不触发
结论：改了属性但回调没执行。
原因：没声明 observedAttributes 静态属性。
解法：加 static get observedAttributes() { return ['xxx']; }。

坑 5：connectedCallback 重复执行导致事件重复绑定
结论：点击一次触发多次。
原因：元素反复插入/移除，每次连接都 addEventListener。
解法：绑定前先判断，或用标志位/AbortController 管理。
```

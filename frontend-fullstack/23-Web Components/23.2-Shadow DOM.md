## 概述

Shadow DOM 为元素提供独立的 DOM 子树和样式作用域，让组件的结构和样式与外部隔离。它是 Web Components 实现「封装」的关键技术，解决全局样式污染和选择器冲突。

```text
Shadow DOM 核心能力：
1. DOM 隔离 —— 内部结构对外部隐藏，外部选择器无法深入
2. 样式隔离 —— 内部样式不外泄，外部样式不侵入
3. 自带作用域 —— 每个 shadow root 都是独立作用域
```

```html
<!-- 宿主元素 -->
<div id="host"></div>
<script>
  const host = document.querySelector('#host');
  const shadow = host.attachShadow({ mode: 'open' });
  shadow.innerHTML = '<p>这是 shadow DOM 内部内容</p>';
</script>
```

```text
关键概念：
Shadow Host —— 挂载 shadow DOM 的元素
Shadow Root —— 影子树的根节点
Shadow Tree —— 影子树内部的结构
Shadow Boundary —— 影子树与外部的分界
```

## Shadow Root

Shadow Root 是通过 attachShadow 创建的影子树根节点，是内部 DOM 与样式隔离的载体。

```js
// 创建 shadow root
const shadowRoot = element.attachShadow({ mode: 'open' });
```

```text
Shadow Root 特性：
1. 一个宿主只能有一个 shadow root（重复 attach 会抛错）
2. 可向内部添加任意 DOM 节点
3. 内部样式只作用于 shadow tree
4. 通过 mode 控制外部是否可访问
```

```js
// 构建完整的影子树
const host = document.getElementById('host');
const root = host.attachShadow({ mode: 'open' });

const style = document.createElement('style');
style.textContent = 'p { color: red; }';   // 只影响 shadow 内部

const p = document.createElement('p');
p.textContent = 'Hello Shadow';

root.append(style, p);
```

```text
可附加 shadow root 的元素：
1. 自定义元素 —— 最常用
2. 部分内置元素 —— div、span、section 等
3. 部分元素不支持 —— 如 input、textarea、img（宿主约束）
```

## Encapsulation

Encapsulation（封装）指 Shadow DOM 让组件的结构和样式与外部相互隔离，外部无法轻易访问或影响内部实现。

```text
封装的三个层面：
1. DOM 封装 —— 外部 querySelector 无法选中内部节点
2. 样式封装 —— 内部样式不外泄，外部样式不侵入
3. 行为封装 —— 内部事件可选择性重定向（composed）
```

```html
<style>
  /* 全局样式：不会影响 shadow 内部的 p */
  p { color: blue; }
</style>
<div id="host"></div>
<script>
  const host = document.getElementById('host');
  host.attachShadow({ mode: 'open' }).innerHTML = `
    <style> p { color: red; } </style>
    <p>内部文字（红色，不受全局蓝色影响）</p>
  `;
</script>
```

```text
样式隔离规则：
1. 外部选择器无法匹配 shadow 内部元素
2. shadow 内部选择器无法匹配外部元素
3. 继承属性（color、font 等）仍会穿透（CSS 继承）
4. 可继承属性用 CSS 自定义属性（变量）实现穿透定制
```

```js
// 验证 DOM 封装
const host = document.getElementById('host');
document.querySelector('p');         // null，选不到内部 p
host.shadowRoot.querySelector('p');  // 才能拿到内部 p
```

## Open

Open 模式（mode: 'open'）允许外部通过宿主元素的 shadowRoot 属性访问影子树，是默认推荐的模式。

```js
const root = host.attachShadow({ mode: 'open' });

// 外部可访问
host.shadowRoot;               // 返回 shadow root
host.shadowRoot.querySelector('p');  // 可操作内部
```

```text
Open 模式特点：
1. 外部可读 shadowRoot，可调试、可定制
2. DevTools 中可直接查看内部结构
3. 灵活度高，适合需要被二次开发的组件
4. 大多数库（Lit 等）默认用 open
```

```js
// open 模式常用于组件内部逻辑，也方便测试
class MyWidget extends HTMLElement {
  constructor() {
    super();
    this.attachShadow({ mode: 'open' });  // 可访问
  }
  connectedCallback() {
    this.shadowRoot.innerHTML = '<button>点击</button>';
  }
}
```

## Closed

Closed 模式（mode: 'closed'）隐藏影子树，外部无法通过 shadowRoot 属性访问，但封装并非绝对安全。

```js
const root = host.attachShadow({ mode: 'closed' });

host.shadowRoot;   // null，外部无法访问
```

```text
Closed 模式特点：
1. 宿主元素的 shadowRoot 属性返回 null
2. 外部无法通过该属性访问内部
3. 适合不希望被外部随意操作的场景
```

```text
重要警示：
Closed 并非真正的安全边界！
1. 通过 attachShadow 的返回值仍持有引用
2. 可通过原型篡改（Element.prototype.attachShadow）绕过
3. 不应依赖 closed 做安全防护，只用于减少误操作
```

```js
// closed 模式的正确使用：内部保存引用
class SecureBox extends HTMLElement {
  constructor() {
    super();
    this._root = this.attachShadow({ mode: 'closed' });
  }
  connectedCallback() {
    this._root.innerHTML = '<p>外部拿不到</p>';
  }
}
```

## Shadow Boundary

Shadow Boundary（影子边界）是影子树与外部文档之间的分界。跨边界的访问和事件传播都有特殊规则。

```text
边界规则：
1. 选择器 —— 外部无法穿透边界选中内部元素
2. 事件 —— 内部事件默认不冒泡到外部（需 composed: true）
3. 访问 —— 只有 open 模式能通过 shadowRoot 跨边界访问
4. 样式 —— 只有继承属性、CSS 变量和 ::part 能跨边界
```

```js
// 事件跨边界：默认不冒泡到外部
const host = document.getElementById('host');
host.attachShadow({ mode: 'open' }).innerHTML = '<button id="btn">点我</button>';

document.addEventListener('click', (e) => {
  console.log('外部收到', e.target);   // 收不到内部 button 的点击（非 composed）
});
```

```text
跨边界传播的事件：
1. 默认 —— 自定义事件在边界处停止，外部监听不到
2. composed: true —— 事件穿过边界，但 event.target 仍是内部元素
3. 需要让外部感知内部事件时，手动 dispatch 或设置 composed
```

```js
// 让内部事件穿透边界
host.shadowRoot.addEventListener('click', () => {
  host.dispatchEvent(new CustomEvent('item-click', {
    bubbles: true,
    composed: true,
  }));
});
```

## 应用场景实战

### 场景一：样式隔离的选项卡组件

```js
class TabGroup extends HTMLElement {
  connectedCallback() {
    this.attachShadow({ mode: 'open' }).innerHTML = `
      <style>
        .tab { padding: 8px 16px; cursor: pointer; }
        .tab.active { background: #eee; font-weight: bold; }
      </style>
      <div class="tabs">
        <span class="tab active">标签一</span>
        <span class="tab">标签二</span>
      </div>
    `;
  }
}
customElements.define('tab-group', TabGroup);
```

```html
<!-- 页面的全局 .tab 样式不会污染组件内部 -->
<tab-group></tab-group>
```

### 场景二：用 CSS 变量定制内部主题

```js
class ThemedBox extends HTMLElement {
  connectedCallback() {
    this.attachShadow({ mode: 'open' }).innerHTML = `
      <style>
        .box { background: var(--box-bg, white); color: var(--box-color, black); }
      </style>
      <div class="box">内容</div>
    `;
  }
}
customElements.define('themed-box', ThemedBox);
```

```html
<!-- 通过 CSS 变量跨边界定制内部样式 -->
<themed-box style="--box-bg: #333; --box-color: #fff;"></themed-box>
```

## 最佳实践与踩坑记录

### 最佳实践

1. 默认用 open 模式，方便调试和二次定制
2. 用 CSS 变量作为内部样式的定制接口，而非依赖继承
3. 不要用 closed 模式做安全防护（可被绕过）
4. 需要外部感知内部事件时显式设置 composed: true
5. 组件内部样式尽量自包含，减少对全局样式的依赖

### 踩坑记录

```text
坑 1：重复 attachShadow 报错
结论：第二次 attachShadow 抛异常。
原因：一个宿主只能有一个 shadow root。
解法：attach 前判断，或在构造函数里只 attach 一次。

坑 2：外部样式无法覆盖内部样式
结论：想改组件内部样式却无效。
原因：Shadow DOM 样式隔离，外部选择器穿不过边界。
解法：用 ::part 暴露部件，或提供 CSS 变量定制接口。

坑 3：内部事件外部监听不到
结论：在页面里 addEventListener 收不到内部点击。
原因：事件在 shadow 边界停止，未设置 composed。
解法：内部事件设 composed: true，或在边界处重新 dispatch。

坑 4：误以为 closed 模式绝对安全
结论：用 closed 保护敏感逻辑，结果被绕过。
原因：closed 可被 attachShadow 引用或原型篡改绕过。
解法：安全逻辑放服务端，closed 仅作代码组织手段。

坑 5：input 等元素无法 attachShadow
结论：对 input 调 attachShadow 抛异常。
原因：部分内置元素有宿主限制，禁止附加 shadow root。
解法：用 div 包裹，或改用自定义元素实现。
```

## 概述

表单状态不只包含「输入值」，还包含脏标记（Dirty）、触摸标记（Touched）、错误信息（Error）、提交状态（Submit）等元数据。理解受控/非受控的区别，以及这些状态如何驱动校验提示与提交按钮，是构建可靠表单的关键。

```text
表单状态核心概念：
1. Controlled —— 受控组件，值由 React state 管理
2. Uncontrolled —— 非受控组件，值由 DOM 自己管理
3. Dirty —— 是否被修改过（对比初始值）
4. Touched —— 是否被交互过（失焦/点击）
5. Error —— 校验错误信息
6. Submit —— 提交状态（进行中/成功/失败）
```

```js
// 表单状态全景
const formState = {
  values: { name: '', email: '' }, // 值
  dirty: false, // 是否修改
  touched: { name: false }, // 是否交互
  errors: { email: '邮箱格式错误' }, // 错误
  isSubmitting: false, // 提交中
  isValid: false, // 是否合法
};
```

## Controlled

受控组件把表单值保存在 React state 中，value 由 state 驱动，onChange 更新 state。数据流单向、可控，是 React 推荐方式。

```jsx
import { useState } from 'react';

function ControlledInput() {
  const [value, setValue] = useState('');
  return (
    <input
      value={value}
      onChange={(e) => setValue(e.target.value)}
    />
  );
}
```

```text
受控组件特点：
1. 值始终来自 state，单一数据源
2. 每次输入触发 onChange 更新 state（触发渲染）
3. 便于校验、格式化、联动
4. 输入频繁时可能有性能开销
```

## Uncontrolled

非受控组件不把值存 state，由 DOM 自己维护，通过 ref 在需要时读取值。适合简单场景或性能敏感场景。

```jsx
import { useRef } from 'react';

function UncontrolledInput() {
  const ref = useRef(null);

  const submit = () => {
    console.log(ref.current.value); // 提交时读取
  };

  return (
    <div>
      <input ref={ref} defaultValue="初始值" />
      <button onClick={submit}>提交</button>
    </div>
  );
}
```

```text
非受控组件特点：
1. 值由 DOM 维护，用 ref 读取
2. 用 defaultValue 设初值（不受控）
3. 不触发频繁渲染，性能更好
4. 校验、联动不如受控灵活
```

```text
选择建议：
受控 —— 需要校验、格式化、联动时（多数表单）
非受控 —— 简单提交、性能敏感时
```

## Dirty

Dirty 表示字段是否被修改过（当前值不同于初始值）。用于判断「用户是否改了内容」、提示未保存等场景。

```jsx
import { useForm } from 'react-hook-form';

function Form() {
  const { register, formState: { isDirty, dirtyFields } } = useForm({
    defaultValues: { name: 'Alice' },
  });

  // isDirty: 整个表单是否被修改
  // dirtyFields: { name: true } 具体字段是否被改
  return (
    <div>
      <input {...register('name')} />
      {isDirty && <span>有未保存的修改</span>}
    </div>
  );
}
```

```text
Dirty 要点：
1. 当前值 !== 初始值 即为 dirty
2. 用于「未保存离开」提示
3. 表单库通常提供 isDirty 与 dirtyFields
```

## Touched

Touched 表示字段是否被用户「交互」过（聚焦后失焦），用于控制「何时显示错误」。常见策略：未 touched 不显示错误，失焦后再显示。

```jsx
import { useForm } from 'react-hook-form';

function Form() {
  const {
    register,
    formState: { touchedFields, errors },
  } = useForm();

  return (
    <div>
      <input {...register('email', { required: '必填' })} />
      {/* 只在 touched 且 error 时显示 */}
      {touchedFields.email && errors.email && <span>{errors.email.message}</span>}
    </div>
  );
}
```

```text
Touched 要点：
1. 字段获得焦点后失焦即 touched
2. 错误提示通常在 touched 后显示，避免一开始就报错
3. 与 Dirty 区别：Dirty 看值是否变，Touched 看是否交互
```

## Error

Error 是校验失败的错误信息，可全局（提交时）或逐字段（失焦时）校验。错误状态驱动错误提示的显示。

```jsx
// 手写错误状态
function Form() {
  const [errors, setErrors] = useState({});

  const validate = (values) => {
    const errs = {};
    if (!values.name) errs.name = '姓名必填';
    return errs;
  };

  const submit = () => {
    const errs = validate(values);
    setErrors(errs);
  };

  return (
    <div>
      <input value={values.name} onChange={...} />
      {errors.name && <span className="error">{errors.name}</span>}
    </div>
  );
}
```

```text
Error 校验时机：
1. 提交时校验 —— 点提交统一校验
2. 失焦时校验 —— 字段 blur 后校验该字段
3. 实时校验 —— 输入即校验（性能开销大）
常见：提交时全量 + 失焦后实时校验。
```

## Submit

Submit 是表单提交状态，包括「是否提交中、成功、失败」。正确管理提交状态能防止重复提交、提供反馈。

```jsx
function Form() {
  const [isSubmitting, setIsSubmitting] = useState(false);
  const [submitError, setSubmitError] = useState(null);

  const onSubmit = async (e) => {
    e.preventDefault();
    setIsSubmitting(true);
    setSubmitError(null);
    try {
      await api.submit(values);
      message.success('提交成功');
    } catch (err) {
      setSubmitError(err.message);
    } finally {
      setIsSubmitting(false);
    }
  };

  return (
    <form onSubmit={onSubmit}>
      <button disabled={isSubmitting}>
        {isSubmitting ? '提交中...' : '提交'}
      </button>
      {submitError && <span>{submitError}</span>}
    </form>
  );
}
```

```text
Submit 要点：
1. isSubmitting 控制按钮禁用，防重复提交
2. 提交成功后重置 dirty/错误状态
3. 区分校验错误（前端）与提交错误（服务端）
```

## 应用场景实战

### 场景一：未保存离开提示（Dirty）

```jsx
import { useEffect } from 'react';
import { useForm } from 'react-hook-form';

function EditForm() {
  const { formState: { isDirty } } = useForm();

  useEffect(() => {
    const handler = (e) => {
      if (isDirty) {
        e.preventDefault();
        e.returnValue = '有未保存的修改';
      }
    };
    window.addEventListener('beforeunload', handler);
    return () => window.removeEventListener('beforeunload', handler);
  }, [isDirty]);

  return <form>...</form>;
}
```

### 场景二：失焦后校验 + 提交防重

```jsx
const { register, handleSubmit, formState: { errors, touchedFields, isSubmitting } } = useForm();

<form onSubmit={handleSubmit(onSubmit)}>
  <input {...register('email', { required: '必填', pattern: { value: /^\S+@\S+$/, message: '格式错误' } })} />
  {touchedFields.email && errors.email && <p>{errors.email.message}</p>}
  <button disabled={isSubmitting}>提交</button>
</form>
```

## 最佳实践与踩坑记录

### 最佳实践

1. 需要校验/联动的表单用受控组件，简单场景用非受控
2. 错误提示在字段 touched 后再显示，避免初始报错
3. 提交按钮用 isSubmitting 禁用，防重复提交
4. 未保存修改用 isDirty 做离开提示
5. 用表单库统一管理这些状态，减少手写样板

### 踩坑记录

```text
坑 1：受控组件 value 设为 undefined/null
结论：React 警告「controlled 变 uncontrolled」。
原因：value 从有值变成 undefined。
解法：始终传字符串，空值时用 ''。

坑 2：非受控组件用 value 而非 defaultValue
结论：输入框无法编辑。
原因：value 会让输入框受控但无 onChange。
解法：非受控用 defaultValue + ref 读取。

坑 3：一开始就显示错误
结论：用户还没输入就报错，体验差。
原因：未用 touched 控制错误显示时机。
解法：touched 后再显示，或提交后再校验。

坑 4：未处理重复提交
结论：双击提交发多次请求。
原因：未在提交中禁用按钮。
解法：isSubmitting 时禁用按钮并提示。

坑 5：混淆 dirty 与 touched
结论：错误提示逻辑判断错误。
原因：dirty 是值变化，touched 是交互过。
解法：显示错误用 touched，未保存判断用 dirty。
```

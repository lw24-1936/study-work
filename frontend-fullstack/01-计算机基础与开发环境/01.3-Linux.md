## 概述

Linux 是前端工程师绕不开的操作系统。本机开发可能用 macOS 或 Windows，但代码最终要跑在 Linux 服务器上：构建机、CI/CD、Node.js 服务、Nginx、Docker、数据库，几乎全部跑在 Linux。

前端学 Linux 不是要当运维，而是要解决三类实际问题：

- 部署：SSH 登录服务器、传文件、启动/重启 Node 服务、看日志定位线上问题
- 效率：用 grep/awk/sed/find 批量处理代码和日志，用脚本自动化重复劳动
- 排障：服务挂了看进程、看端口、看磁盘内存、抓包分析接口请求

本文按"文件系统 → Shell → 命令 → 服务与任务 → 权限 → 日志"的顺序，把前端日常用到的 Linux 知识串起来，每个命令都给出实际用法。

## Linux 文件系统

Linux 一切皆文件，目录结构遵循 FHS（Filesystem Hierarchy Standard）规范：

```text
/           根目录，所有文件从这里出发
/bin        基础命令（ls、cp、mv），软链到 /usr/bin
/sbin       系统管理命令（需要 root 权限）
/usr        用户级软件和库（源码包、npm 全局包常装这里）
/etc        配置文件（nginx、ssh、systemd 都在这）
/var        可变数据：日志（/var/log）、缓存、运行中的 pid
/home       普通用户家目录（/home/user）
/root       root 用户家目录
/tmp        临时文件，重启可能清空
/opt        第三方独立软件（有些公司项目部署在 /opt）
/proc       虚拟文件系统，内核和进程信息（/proc/cpuinfo、/proc/meminfo）
/dev        设备文件（/dev/sda 磁盘、/dev/null 黑洞）
```

前端最常接触的几个目录：

```bash
/etc/nginx/       # Nginx 配置
/var/log/nginx/   # Nginx 日志
/home/user/app/   # 部署的应用代码
/usr/local/bin/   # npm 全局命令、node 软链
```

```text
Linux 没有盘符（C: D:），一切都是从 / 开始的树。挂载（mount）把磁盘分区挂到某个目录，
比如 /dev/sda1 挂到 /。这点和 Windows 不同，Windows 是"每个盘一个根"，Linux 是"一个根挂所有盘"。
```

```bash
# 查看磁盘挂载情况
df -h
lsblk
```

## Shell 与 Bash

Shell 是用户和内核之间的命令解释器。你输入命令，Shell 解析后交给内核执行，再把结果返回。

```text
常见 Shell：
sh    —— 最古老，POSIX 标准
bash  —— Linux 默认，功能最全（Bourne Again Shell）
zsh   —— 扩展版 bash，交互体验更好（macOS 默认）
fish  —— 开箱即用的友好 Shell
```

Bash（Bourne Again Shell）是绝大多数 Linux 发行版的默认 Shell，也是写脚本最通用的选择：

```bash
# 常用 Bash 特性
echo $HOME            # 变量（$ 取值）
export NAME=value     # 导出为环境变量，子进程可见
ls *.js               # 通配符（* 任意字符）
ls {a,b}.js           # 花括号展开（a.js b.js）
cmd1 | cmd2           # 管道：cmd1 输出作为 cmd2 输入
cmd > file            # 重定向输出到文件（覆盖）
cmd >> file           # 追加
cmd 2>&1              # 把错误输出合并到标准输出
$(command)            # 命令替换，取命令输出
&& 和 ||              # 逻辑：前成功才执行 / 前失败才执行
```

```bash
# 一个典型的前端构建脚本
npm run build && tar -czf dist.tar.gz dist && echo "构建打包完成"
```

```text
Bash 脚本第一行写 shebang 指定解释器：
#!/usr/bin/env bash
```

## Zsh

Zsh 是 Bash 的增强版，交互体验更好，macOS 从 2019 年起默认用它。前端常用 Oh My Zsh 这个配置框架来增强它：

```bash
# 安装 Oh My Zsh（国内网络慢时可换镜像）
sh -c "$(curl -fsSL https://raw.githubusercontent.com/ohmyzsh/ohmyzsh/master/tools/install.sh)"
```

```text
Zsh 比 Bash 强的地方（交互层面）：
1. 命令补全更强：路径、命令参数、git 分支都能补全
2. 拼写纠正：输入错误会提示"你是想输入 xxx 吗"
3. 主题和插件：git 状态提示、语法高亮、自动建议（输入时灰字提示历史命令）
4. 目录跳转：d 命令查看目录历史，快速跳转
```

```bash
# 常用 Zsh 插件（在 .zshrc 的 plugins 里配置）
plugins=(git z zsh-autosuggestions zsh-syntax-highlighting)

# z 插件：按访问频率跳目录
z frontend        # 直接跳到最常访问的 frontend 目录
```

```text
Bash 和 Zsh 的脚本语法基本兼容，但脚本文件建议统一用 bash 写（服务器上 bash 一定存在，zsh 不一定）。
Zsh 更值得用在"每天敲命令的交互终端"里，而不是服务器脚本里。
```

## 文本处理三剑客：grep、sed、awk

grep、sed、awk 是 Linux 文本处理的三件套。前端看日志、批量改配置、统计接口耗时，全靠它们。

### grep：搜索

grep 在文件或输入流里按模式匹配行：

```bash
grep "error" app.log              # 搜包含 error 的行
grep -i "error" app.log           # 忽略大小写
grep -n "error" app.log           # 显示行号
grep -v "error" app.log           # 反向：排除含 error 的行
grep -r "TODO" src/               # 递归搜目录
grep -E "error|warn" app.log      # 扩展正则（多个关键词）
grep -P "\d{4}-\d{2}-\d{2}" file  # PCRE 正则（-P）
grep -c "error" app.log           # 只输出匹配行数
grep -A 3 -B 2 "error" app.log    # 匹配行前后各显示 N 行（上下文）
```

```text
前端排障最常用：grep -n "关键词" 日志文件，定位错误行号后结合 -A -B 看上下文。
```

### sed：流编辑

sed 逐行处理文本，做替换、删除、插入，不打开编辑器：

```bash
sed 's/old/new/' file           # 每行替换第一个 old 为 new
sed 's/old/new/g' file          # 全局替换
sed -i 's/old/new/g' file       # 直接写回文件（-i）
sed -n '10,20p' file            # 打印第 10-20 行
sed '/error/d' file             # 删除含 error 的行
```

```bash
# 批量把项目里所有 http:// 换成 https://
sed -i 's/http:\/\//https:\/\//g' *.js
```

```text
注意：sed 的替换分隔符可以用别的字符，处理 URL 这种带 / 的内容时换成 # 更清爽：
sed -i 's#http://#https://#g' *.js
```

### awk：按列处理

awk 把每行按分隔符切成字段，适合处理结构化文本（日志、CSV、命令输出）：

```bash
awk '{print $1}' file                # 打印第 1 列（默认按空格/制表符分隔）
awk -F, '{print $2}' file            # 指定逗号分隔，打印第 2 列
awk '{print $1, $NF}' file           # 第 1 列和最后一列（NF 是字段数）
awk '$3 > 100 {print $1, $3}' file   # 第 3 列大于 100 才打印
awk '{sum += $3} END {print sum}' file  # 汇总第 3 列
```

```bash
# 统计 Nginx access log 里每个接口的请求次数（假设第 7 列是 URL）
awk '{count[$7]++} END {for (url in count) print count[url], url}' access.log | sort -rn | head
```

```text
awk 是弱编程语言：有变量、数组、条件、循环。字段用 $1 $2... 引用，$0 是整行，NF 是字段数，NR 是行号。
END 块在所有行处理完后执行一次，适合做汇总统计。
```

## find 与 xargs

### find：找文件

find 按名称、类型、时间、大小等条件递归找文件：

```bash
find . -name "*.js"              # 按名称（支持通配符）
find . -type f                   # 只找文件（d 是目录）
find . -type f -name "*.log" -mtime +7   # 7 天前修改的日志
find . -size +100M               # 大于 100M 的文件
find . -name "node_modules" -type d     # 找目录
```

```bash
# 找文件并对每个文件执行命令（-exec 或 -delete）
find . -name "*.map" -delete                 # 删除所有 sourcemap
find . -name "*.js" -exec chmod 644 {} \;    # 批量改权限
```

```text
find -exec 的 {} 是匹配到的文件名占位符，\; 表示命令结束。
```

### xargs：把标准输入转成命令参数

管道能接命令的"标准输入"，但很多命令只接受"命令行参数"（比如 rm、cp）。xargs 把前一个命令的输出转成后一个命令的参数：

```bash
# 删掉所有 .log 文件（不用 xargs 的话 rm 不认识管道来的文件名）
find . -name "*.log" | xargs rm

# 常用组合参数
find . -name "*.js" | xargs grep -n "TODO"     # 在所有 js 里搜 TODO
find . -name "*.js" | xargs -I {} mv {} /tmp/  # -I {} 让 {} 代表每个文件名
find . -name "*.jpg" | xargs -n 100 rm         # -n 每次最多传 100 个参数
cat urls.txt | xargs -P 4 -I {} curl -O {}     # -P 4 并行 4 个进程下载
```

```text
xargs 的核心价值：一是把"标准输入"变成"命令行参数"，二是 -P 并行执行提速。
前端批量下载资源、批量替换代码时非常有用。
```

## 网络工具：curl 与 wget

### curl：发请求

curl 是前端最常用的命令行 HTTP 客户端，调试接口必备：

```bash
curl https://api.example.com/users          # GET 请求
curl -X POST https://api.example.com/users \
  -H "Content-Type: application/json" \
  -d '{"name":"test"}'                      # POST JSON
curl -I https://example.com                 # 只看响应头（-I）
curl -L https://example.com                 # 跟随重定向（-L）
curl -o file.json https://api.example.com/data   # 下载到文件
curl -s https://example.com                 # 静默模式（不显示进度条）
curl -v https://example.com                 # 详细输出（看握手过程）
curl -u user:pass https://example.com       # 基本认证
curl --retry 3 https://example.com          # 失败重试 3 次
```

```bash
# 前端联调：完整请求并打印状态码
curl -s -o /dev/null -w "%{http_code}" https://example.com
```

```text
curl 和 wget 的区别：curl 偏"发请求"（支持各种协议和方法，适合调接口），
wget 偏"下载"（支持递归抓取、断点续传，适合下文件）。
```

### wget：下载

```bash
wget https://example.com/file.tar.gz       # 下载到当前目录
wget -O custom.tar.gz https://example.com/file.tar.gz  # 指定文件名
wget -c https://example.com/file.tar.gz    # 断点续传
wget -r -np -k https://example.com/docs/   # 递归下载整个目录
wget --limit-rate=1m https://example.com/big.iso  # 限速
```

## 远程连接与文件传输：ssh、scp、rsync

### ssh：远程登录

ssh 是登录远程服务器的标准方式：

```bash
ssh user@host                    # 密码登录
ssh -p 2222 user@host            # 指定端口
ssh -i ~/.ssh/id_rsa user@host   # 私钥登录
ssh user@host "ls /var/log"      # 不登录，直接远程执行命令
```

```text
SSH 端口转发（前端联调很有用）：
1. 本地转发 -L：把本机端口转发到远程端口
   ssh -L 8080:localhost:3000 user@host
   （访问本机 8080 等于访问远程的 3000，适合连远程开发服务器）
2. 远程转发 -R：把远程端口转发到本机
   ssh -R 8080:localhost:3000 user@host
   （内网穿透思路，让远程能访问你本机的服务）
```

```bash
# 配置免密登录：把本机公钥加到远程 authorized_keys
ssh-keygen -t ed25519 -C "your@email.com"   # 生成密钥对
ssh-copy-id user@host                        # 一键复制公钥
```

### scp：文件传输

scp 基于 SSH 复制文件：

```bash
scp file.txt user@host:/home/user/          # 本地上传到远程
scp user@host:/home/user/file.txt .         # 远程下载到本地
scp -r dist/ user@host:/var/www/            # 递归传目录（-r）
scp -P 2222 file.txt user@host:/home/user/  # 指定端口（注意是大写 -P）
```

### rsync：同步

rsync 增量同步，只传差异部分，比 scp 更适合大目录和频繁同步：

```bash
rsync -avz dist/ user@host:/var/www/dist/       # 同步目录
rsync -avz --delete dist/ user@host:/var/www/dist/  # 删除远程多余文件，完全一致
rsync -avz --exclude 'node_modules' src/ user@host:/app/  # 排除目录
rsync -avz -e "ssh -p 2222" dist/ user@host:/app/  # 自定义 ssh 端口
```

```text
部署前端静态文件时，rsync --delete 能保证远程目录和本地构建产物完全一致，
不会残留上次发布删除的文件。scp 是"全量覆盖"，rsync 是"增量对齐"。
```

## 进程管理：ps、top、htop

### ps：查看进程快照

```bash
ps aux                        # 显示所有进程（BSD 风格）
ps -ef                        # 显示所有进程（System V 风格）
ps aux | grep node            # 找 node 进程
ps -p 1234 -o pid,ppid,cmd    # 看指定进程的 pid、父进程、命令
```

```text
ps aux 每列含义：
USER  PID  %CPU  %MEM  VSZ  RSS  TTY  STAT  START  TIME  COMMAND
前端主要看 PID（进程号）、%CPU、%MEM、COMMAND（启动命令）。
```

### top：实时监控

top 动态刷新显示系统负载和进程排行：

```bash
top
# 交互按键：按 1 看每个 CPU 核心，按 M 按内存排序，按 P 按 CPU 排序，q 退出
```

```text
top 第一行 load average 是"1/5/15 分钟平均负载"，三个数持续接近 CPU 核心数就是满载。
load 高不一定是 CPU 忙，也可能是 IO 等待或大量进程排队。
```

### htop：增强版 top

htop 是 top 的彩色增强版，支持鼠标操作、直接搜索、树形进程视图：

```bash
htop          # 需要先安装：apt install htop / brew install htop
# 功能：F6 选排序字段，F9 杀进程，F5 树形显示父子关系，/ 搜索
```

```text
ps 是快照（执行瞬间的进程表），top/htop 是实时刷新。
日常快速查一个进程用 ps + grep，盯着看资源占用用 top/htop。
```

## 网络状态排查：lsof、netstat、ss、tcpdump

### lsof：列出打开的文件

lsof（list open files）列出进程打开的文件、端口、连接。Linux 一切皆文件，网络连接也是文件：

```bash
lsof -i :8080                 # 谁占用了 8080 端口
lsof -i tcp                   # 所有 TCP 连接
lsof -p 1234                  # 进程 1234 打开的所有文件
lsof /var/log/nginx/access.log  # 谁在写这个日志文件
```

### netstat 与 ss：看端口和连接

netstat 是老命令，ss 是它的现代替代（更快，读内核数据而非 /proc）：

```bash
netstat -tunlp                # 所有监听端口（t=tcp u=udp n=数字 l=监听 p=进程）
ss -tunlp                     # 同样功能，推荐用 ss
ss -s                         # 连接统计汇总
```

```bash
# 前端最常用：查某个端口有没有被占用、被哪个进程占用
ss -tunlp | grep 3000
lsof -i :3000
```

```text
netstat 逐渐被淘汰，很多新发行版默认不装。查端口优先用 ss 或 lsof。
```

### tcpdump：抓包

tcpdump 抓取经过网卡的网络包，分析底层通信：

```bash
tcpdump -i eth0                    # 抓指定网卡的所有包
tcpdump -i any port 80             # 抓 80 端口流量
tcpdump -i any host 10.0.0.5       # 抓和某主机的通信
tcpdump -i any port 443 -w https.pcap   # 抓包存文件（-w），用 Wireshark 分析
tcpdump -r https.pcap              # 读包文件（-r）
tcpdump -n -A port 80              # -n 不解析域名，-A 以 ASCII 显示内容
```

```text
tcpdump 适合排查"接口到底发出去了什么包"：HTTPS 握手失败、DNS 解析异常、
TCP 连接被重置，都能从包里看出来。生产环境慎用（量大），先用 port/host 过滤。
```

## 磁盘与内存监控：df、du、free、iostat

### df：磁盘整体用量

```bash
df -h           # 人类可读格式显示所有分区用量
df -h /var      # 只看某个目录所在分区
```

### du：目录占用

```bash
du -sh *                  # 当前目录下每个文件/目录的大小汇总
du -sh node_modules       # 单个目录大小
du -h --max-depth=1 /var  # 一层深度展开
```

```text
前端常见场景：磁盘满了，用 du -sh * 逐层找哪个目录最大，
往往是 node_modules、日志、构建缓存占了空间。
```

### free：内存

```bash
free -h          # 内存和 swap 用量
free -m          # 以 MB 显示
```

```text
free -h 的 available（可用）比 free（空闲）更有意义：
Linux 会把空闲内存用于缓存，free 低不代表内存不够，available 低才要警惕。
```

### iostat：磁盘 IO

```bash
iostat -x 1      # 每秒刷新一次，看磁盘读写负载
```

```text
关键指标：
%util  —— 磁盘繁忙度，长期接近 100% 说明磁盘是瓶颈
await  —— IO 平均等待时间，远大于几毫秒说明磁盘响应慢
前端构建、数据库写入慢时，用 iostat 判断是不是磁盘 IO 拖了后腿。
```

## 服务管理：systemd

systemd 是 Linux 的服务管理器（PID 1），负责启动、停止、开机自启服务。前端部署 Node.js 服务时，用 systemd 把它变成后台守护进程：

```bash
systemctl status nginx      # 查看服务状态
systemctl start nginx       # 启动
systemctl stop nginx        # 停止
systemctl restart nginx     # 重启
systemctl enable nginx      # 开机自启
systemctl disable nginx     # 取消自启
systemctl list-units --type=service   # 列出所有服务
```

```text
systemd 的单元文件（unit）放在 /etc/systemd/system/*.service，一个 Node 服务的典型单元文件：
```

```ini
# /etc/systemd/system/my-app.service
[Unit]
Description=My Node.js App
After=network.target

[Service]
Type=simple
WorkingDirectory=/home/user/app
ExecStart=/usr/bin/node server.js
Restart=always
Environment=NODE_ENV=production

[Install]
WantedBy=multi-user.target
```

```bash
# 修改单元文件后重载并启动
systemctl daemon-reload
systemctl start my-app
systemctl enable my-app
```

```text
Restart=always 让进程崩溃后自动重启，比 nohup node & 手动后台运行可靠得多。
传统 SysV 的 service 命令（service nginx start）在很多发行版上仍是 systemd 的兼容封装。
```

## 定时任务：cron 与 crontab

cron 是定时任务守护进程（crond），crontab 是编辑定时任务的命令：

```bash
crontab -e      # 编辑当前用户的定时任务
crontab -l      # 列出已有任务
crontab -r      # 删除所有任务
```

```text
crontab 格式（5 个时间字段 + 命令）：
分 时 日 月 周 命令
*  *  *  *  *  /path/to/script.sh
┬  ┬  ┬  ┬  ┬
│  │  │  │  └─ 星期（0-7，0 和 7 都代表周日）
│  │  │  └──── 月份（1-12）
│  │  └─────── 日期（1-31）
│  └────────── 小时（0-23）
└───────────── 分钟（0-59）
```

```bash
# 常用示例
0 2 * * * /home/user/backup.sh        # 每天凌晨 2 点备份
*/10 * * * * /usr/bin/node /app/cron.js  # 每 10 分钟跑一次
0 0 1 * * /app/monthly.sh             # 每月 1 号 0 点
30 9 * * 1-5 /app/workday.sh          # 工作日 9:30
```

```text
前端常见用法：定时清理构建缓存、定时拉取数据、定时生成静态站点、证书续期。
注意：cron 的环境变量和交互 shell 不同，脚本里要用绝对路径或自己 export PATH。
```

## 环境变量与 PATH

环境变量是进程运行时的全局配置，子进程会继承父进程的环境变量：

```bash
export NAME=value        # 设置环境变量（当前 shell 及子进程可见）
echo $NAME               # 读取
unset NAME               # 删除
env                      # 查看当前所有环境变量
NAME=value node app.js   # 只在这一次命令里生效
```

```text
前端相关环境变量：
NODE_ENV  —— 运行环境（development/production）
PATH      —— 命令搜索路径
HOME      —— 用户家目录
```

PATH 是最特殊的环境变量：冒号分隔的目录列表，shell 按顺序在这些目录里找命令：

```bash
echo $PATH
# /usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin

export PATH="$HOME/.local/bin:$PATH"    # 把自定义目录加到最前面（优先匹配）
which node                              # 查看 node 命令的完整路径
```

```text
"command not found" 通常是两种情况：命令没安装，或者装了但 PATH 里没有它所在的目录。
npm 全局安装的包在 $(npm prefix -g)/bin，这个目录不在 PATH 里就找不到命令。
```

```text
环境变量写在哪（按加载顺序）：
1. /etc/profile        —— 系统级，所有用户
2. ~/.bashrc           —— 交互式 shell（每次开终端）
3. ~/.profile          —— 登录 shell
改完要 source ~/.bashrc 或重开终端才生效。
```

## 文件权限：chmod、chown、sudo

Linux 每个文件有三组权限：属主（user）、属组（group）、其他人（other），每组有读（r）、写（w）、执行（x）三种：

```text
-rwxr-xr-- 1 user group 4096 Aug 13 10:00 file.txt
└┬┘└─┬─┘└─┬─┘
 │   │    └─ 其他人权限 r-x（读+执行）
 │   └────── 属组权限 r-x
 └────────── 属主权限 rwx（读+写+执行）
第一个字符：- 普通文件，d 目录，l 软链接
```

```text
权限数字表示（八进制）：
r = 4，w = 2，x = 1
rwx = 7，rw- = 6，r-x = 5，r-- = 4，--- = 0
```

### chmod：改权限

```bash
chmod 755 script.sh        # 属主 rwx，属组 r-x，其他人 r-x
chmod 644 file.txt         # 属主 rw-，属组 r--，其他人 r--
chmod +x script.sh         # 给所有人加执行权限（符号方式）
chmod -R 755 dist/         # 递归改整个目录
```

```text
前端常见：chmod +x 给脚本加执行权限；chmod 600 给 SSH 私钥收紧权限（太宽会报错拒绝使用）。
```

### chown：改属主

```bash
chown user:group file.txt   # 同时改属主和属组
chown -R user:group /app/   # 递归改整个目录
chown -R www-data:www-data /var/www   # Nginx 部署目录常用
```

```text
部署 Node 服务常见问题：文件属主是 root，运行用户是普通用户，导致没权限读写。
用 chown 把应用目录改成运行用户，避免用 root 跑服务（安全隐患）。
```

### sudo：提权

普通用户执行需要 root 权限的命令时用 sudo：

```bash
sudo apt install nginx       # 临时提权执行一条命令
sudo -u www-data whoami      # 以指定用户身份执行
sudo -i                      # 切换到 root shell
```

```text
sudo 权限在 /etc/sudoers 配置（用 visudo 编辑）。原则：能不用 root 就不用，
只在真正需要系统级操作时提权，日常开发用普通用户。
```

## 日志与 journalctl

Linux 日志主要分两类：

```text
1. 传统 syslog 日志：/var/log/ 下的文本文件
   /var/log/syslog   —— 系统主日志
   /var/log/nginx/   —— Nginx 日志
   /var/log/messages —— 部分发行版

2. systemd 日志：journald 统一管理，用 journalctl 查询
```

### 看传统日志文件

```bash
tail -f /var/log/nginx/access.log     # 实时跟踪日志（前端线上排查必用）
tail -n 100 /var/log/syslog           # 最后 100 行
less /var/log/syslog                  # 翻页查看
```

### journalctl：查 systemd 日志

```bash
journalctl -u nginx                   # 看指定服务的日志
journalctl -u my-app -f               # 实时跟踪
journalctl -u my-app --since "1 hour ago"   # 按时间过滤
journalctl -u my-app -n 50            # 最后 50 行
journalctl -b                         # 本次启动以来的日志
```

```text
前端排障习惯：应用如果由 systemd 托管，日志进 journald，用 journalctl -u 服务名 -f 跟踪；
Nginx 等传统服务的日志还是文件，用 tail -f 跟踪。两者都要会。
```

## 应用场景实战

### 场景 1：部署一个 Node.js 服务

从本地构建到服务器上线，一条完整链路：

```bash
# 1. 本地构建
npm run build

# 2. 用 rsync 把构建产物和代码同步到服务器（排除 node_modules）
rsync -avz --delete --exclude 'node_modules' ./ user@server:/home/user/app/

# 3. SSH 登录服务器
ssh user@server

# 4. 服务器上装依赖并启动（用 systemd 托管）
cd /home/user/app
npm install --production

# 5. 配置 systemd 服务（/etc/systemd/system/my-app.service）
sudo tee /etc/systemd/system/my-app.service <<'EOF'
[Unit]
Description=My App
After=network.target

[Service]
WorkingDirectory=/home/user/app
ExecStart=/usr/bin/node server.js
Restart=always
Environment=NODE_ENV=production

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable my-app
sudo systemctl start my-app

# 6. 验证服务起来了
ss -tunlp | grep 3000
journalctl -u my-app -f
```

### 场景 2：线上接口排障

用户反馈接口超时，用命令行定位问题：

```bash
# 1. 先看服务还活着吗
systemctl status my-app
ps aux | grep node

# 2. 端口正常监听吗
ss -tunlp | grep 3000

# 3. 直接 curl 一下接口，看返回和耗时
curl -s -o /dev/null -w "%{http_code} %{time_total}s\n" https://api.example.com/users

# 4. 查日志里的错误和慢请求
grep -n "error\|timeout\|500" /var/log/my-app/app.log | tail -20

# 5. 看服务器资源是不是瓶颈
top
free -h
df -h

# 6. 怀疑是网络问题就抓包看
sudo tcpdump -i any port 3000 -n -c 50
```

### 场景 3：批量处理前端项目文件

项目里 200 个 js 文件要统一改一个 API 域名，一行命令搞定：

```bash
# 找出所有 js 文件，全局替换旧域名
grep -rl "old-api.example.com" src/ | xargs sed -i 's#old-api.example.com#new-api.example.com#g'

# 验证替换结果
grep -rn "new-api.example.com" src/ | wc -l
```

```bash
# 统计项目里每个文件的行数，找最大的文件
find src -name "*.js" -exec wc -l {} + | sort -rn | head -10
```

## 最佳实践与踩坑记录

### 最佳实践

1. 查端口占用优先用 `ss -tunlp` 或 `lsof -i :端口`，netstat 已逐渐淘汰
2. 部署 Node 服务用 systemd（Restart=always）托管，不用 `nohup node &` 裸跑
3. 同步部署目录用 `rsync --delete` 保证远程和本地一致，避免残留旧文件
4. 线上排查日志用 `tail -f` 或 `journalctl -u 服务 -f` 实时跟踪，配合 grep 过滤关键词
5. 脚本里写绝对路径或显式 export PATH，避免 cron 环境下找不到命令
6. 给 SSH 私钥 `chmod 600`，给脚本 `chmod +x`，不用 root 跑应用服务

### 踩坑记录

```text
坑 1：cron 定时任务不执行
结论：脚本在 cron 里跑不起来，手动执行却正常。
原因：cron 环境 PATH 和交互 shell 不同，找不到 node/脚本里的相对路径依赖。
解法：脚本用绝对路径，或在脚本开头 export PATH=/usr/local/bin:$PATH，用 journalctl -u cron 看报错。

坑 2：部署后端口被占用，服务起不来
结论：新服务启动报 EADDRINUSE，端口被旧进程占着。
原因：旧进程没杀干净，或重启脚本没等旧进程退出。
解法：ss -tunlp | grep 端口 找到 PID，kill 后重试；systemd 托管可自动处理。

坑 3：rsync 同步后 node_modules 被清空
结论：同步时误删了服务器上的依赖目录。
原因：用了 --delete 但没排除 node_modules，本地没装依赖，远程对应目录被删。
解法：rsync 加 --exclude 'node_modules'，依赖在服务器上单独 npm install。

坑 4：chmod 777 一锤子解决权限问题
结论：权限报错就 777，留下严重安全隐患。
原因：不理解权限模型，图省事把目录对所有人开放读写执行。
解法：按最小权限原则设置（应用目录 755、配置 644、私钥 600），用 chown 把属主给运行用户。

坑 5：top 看到 load average 高就以为 CPU 满了
结论：load 高不一定是 CPU 瓶颈，盲目加 CPU 配置无效。
原因：load 是"运行中+等待中的任务数"，可能卡在磁盘 IO 或网络等待。
解法：top 看 %us/%wa，iostat 看磁盘，先定位是 CPU、IO 还是锁等待再优化。

坑 6：改了 .bashrc 里的 PATH 不生效
结论：export 了 PATH 但新终端里 which node 还是旧路径。
原因：改完没 source，或 PATH 顺序不对，旧目录排在前面先匹配。
解法：source ~/.bashrc 或重开终端；把新目录放在 PATH 最前面 export PATH="新目录:$PATH"。
```

## 概述

图片是网页中最占体积的资源类型，通常占页面总流量的一半以上。图片优化对性能提升效果最明显，核心是「选对格式、控制尺寸、按需加载」。

```text
图片优化手段：
1. WebP/AVIF —— 现代格式，更高压缩率
2. JPEG/PNG —— 传统格式，按场景选择
3. SVG —— 矢量图，适合图标与图形
4. Responsive Image —— 响应式，按屏幕选图
5. Lazy Load —— 懒加载，按需加载
6. Image Compression —— 压缩，减小体积
7. Sprite —— 雪碧图，合并请求
8. Icon Font —— 图标字体，矢量缩放
```

## WebP

WebP 是 Google 推出的现代图片格式，支持有损与无损压缩，比 JPEG/PNG 体积小 25%~35%，是目前最广泛使用的现代格式。

```html
<picture>
  <source srcset="photo.webp" type="image/webp">
  <img src="photo.jpg" alt="照片">
</picture>
```

```text
WebP 特点：
1. 有损 + 无损，支持透明
2. 比 JPEG 小 25%~35%
3. 除旧版 IE 外主流浏览器全支持
```

## AVIF

AVIF 基于 AV1 视频编码，是新一代图片格式，压缩率比 WebP 更高（体积可再小 20%~50%），但编码速度较慢、兼容性略差。

```html
<picture>
  <source srcset="photo.avif" type="image/avif">
  <source srcset="photo.webp" type="image/webp">
  <img src="photo.jpg" alt="照片">
</picture>
```

```text
AVIF 特点：
1. 压缩率最高，画质更好
2. 支持 HDR、透明、动画
3. 浏览器支持晚于 WebP（Chrome 85+）
```

```text
格式选择策略：
AVIF 优先 → WebP 兜底 → JPEG/PNG 兜底
用 <picture> 依次降级
```

## JPEG

JPEG 是最通用的有损压缩格式，适合照片和复杂色彩图片，但不支持透明。质量参数（quality）控制压缩率。

```html
<img src="photo.jpg" alt="照片" loading="lazy">
```

```text
JPEG 特点：
1. 有损压缩，适合照片
2. 不支持透明
3. 质量 70~85 通常视觉无损
```

## PNG

PNG 是无损压缩格式，支持透明，适合图标、截图、需要清晰边缘的图片，但体积较大。

```html
<img src="logo.png" alt="Logo">
```

```text
PNG 特点：
1. 无损压缩，画质不损失
2. 支持 alpha 透明
3. 适合图标/截图，不适合大照片
```

## SVG

SVG 是矢量图形格式，用 XML 描述图形，任意缩放不失真，体积小，适合图标、Logo、简单插图。

```html
<svg width="100" height="100" viewBox="0 0 100 100">
  <circle cx="50" cy="50" r="40" fill="#409eff" />
</svg>
```

```text
SVG 特点：
1. 矢量，无限缩放不失真
2. 文本格式，可压缩、可内联、可动画
3. 适合图标/图形，不适合复杂照片
```

## Responsive Image

Responsive Image 根据设备屏幕（DPR、宽度）选择合适尺寸和格式的图片，避免小屏加载大图浪费流量。

```html
<!-- 按屏幕宽度选图 -->
<img srcset="small.jpg 480w, medium.jpg 800w, large.jpg 1200w"
     sizes="(max-width: 600px) 480px, 800px"
     src="medium.jpg" alt="响应式图片">
```

```html
<!-- 按 DPR 选图 -->
<img srcset="photo-1x.jpg 1x, photo-2x.jpg 2x, photo-3x.jpg 3x"
     src="photo-1x.jpg" alt="高清屏适配">
```

```text
srcset 两种用法：
1. 宽度描述符（w）+ sizes —— 按布局宽度选
2. 密度描述符（x）—— 按 DPR 选
```

## Lazy Load

Lazy Load 让图片进入视口附近时才加载，减少首屏请求与流量，是性价比最高的优化手段之一。

```html
<!-- 原生懒加载 -->
<img src="photo.jpg" loading="lazy" alt="懒加载图片">
```

```js
// IntersectionObserver 实现懒加载
const observer = new IntersectionObserver((entries) => {
  entries.forEach((entry) => {
    if (entry.isIntersecting) {
      const img = entry.target;
      img.src = img.dataset.src;
      observer.unobserve(img);
    }
  });
});
document.querySelectorAll('img[data-src]').forEach((img) => observer.observe(img));
```

## Image Compression

Image Compression 在保证视觉质量的前提下减小图片体积：选择合适的质量参数、用工具压缩、构建时自动压缩。

```js
// 构建时用 image-minimizer-webpack-plugin 自动压缩
const ImageMinimizerPlugin = require('image-minimizer-webpack-plugin');

module.exports = {
  plugins: [
    new ImageMinimizerPlugin({
      minimizer: {
        implementation: ImageMinimizerPlugin.imageminGenerate,
        options: {
          plugins: [
            ['mozjpeg', { quality: 75 }],
            ['pngquant', { quality: [0.6, 0.8] }],
          ],
        },
      },
    }),
  ],
};
```

```text
压缩策略：
1. 照片 JPEG quality 70~85
2. 有损 PNG 用 pngquant
3. 现代格式优先（WebP/AVIF）
```

## Sprite

Sprite（雪碧图）把多个小图标合并成一张大图，用 background-position 定位显示，减少 HTTP 请求数。

```css
.icon {
  background-image: url('sprite.png');
  width: 32px;
  height: 32px;
}
.icon-home { background-position: 0 0; }
.icon-user { background-position: -32px 0; }
```

```text
Sprite 优点：
1. 合并请求，减少网络开销
2. 适合固定小图标
缺点：
1. 维护成本高，增删图标需重排
2. 图标数量大时雪碧图体积大
```

## Icon Font

Icon Font 把图标做成字体，通过字符码引用，可矢量缩放、变色、灵活调整大小，适合大量图标场景。

```html
<!-- 引入图标字体 -->
<link rel="stylesheet" href="iconfont.css">
<i class="iconfont icon-home"></i>
```

```css
/* 图标字体样式 */
@font-face {
  font-family: 'iconfont';
  src: url('iconfont.woff2') format('woff2');
}
.iconfont { font-family: 'iconfont'; }
.icon-home::before { content: '\e600'; }
```

```text
Icon Font 优缺点：
优点 —— 矢量缩放、变色灵活、体积可控
缺点 —— 单色为主、加载整个字体文件
替代 —— SVG sprite（更现代）
```

## 应用场景实战

### 场景一：现代格式 + 响应式 + 懒加载

```html
<picture>
  <source srcset="hero.avif" type="image/avif">
  <source srcset="hero.webp" type="image/webp">
  <img src="hero.jpg" loading="lazy" alt="首页横幅">
</picture>
```

### 场景二：SVG 图标 + 雪碧图结合

```html
<!-- 内联 SVG（可 CSS 控制颜色） -->
<svg class="icon"><use href="#icon-home"></use></svg>

<!-- SVG 符号定义 -->
<svg style="display:none">
  <symbol id="icon-home" viewBox="0 0 24 24">
    <path d="M12 3l8 8h-3v8h-10v-8H4z"/>
  </symbol>
</svg>
```

## 最佳实践与踩坑记录

### 最佳实践

1. 现代格式优先（AVIF → WebP → JPEG/PNG）
2. 用 `<picture>` + srcset 做响应式与格式降级
3. 图片一律加 loading="lazy"（首屏关键图除外）
4. 图标用 SVG 或图标字体，不用位图
5. 构建时自动压缩，控制质量参数

### 踩坑记录

```text
坑 1：首屏大图也懒加载
结论：LCP 反而变大，首屏更慢。
原因：关键图片懒加载延迟了加载时机。
解法：首屏关键图加 fetchpriority="high"，不懒加载。

坑 2：只提供 WebP 无降级
结论：旧浏览器图片裂开。
原因：未提供 JPEG/PNG 兜底。
解法：用 <picture> 提供多格式降级。

坑 3：srcset 的 sizes 配错
结论：小屏仍加载大图。
原因：sizes 未正确描述布局宽度。
解法：sizes 按 CSS 布局实际宽度填写。

坑 4：PNG 存照片体积巨大
结论：照片用 PNG 导致体积是 JPEG 的数倍。
原因：PNG 无损，不适合照片。
解法：照片用 JPEG/WebP，PNG 只用于透明图标。

坑 5：雪碧图维护混乱
结论：增删图标要重排整个图，易错位。
原因：雪碧图手工管理复杂。
解法：图标改用 SVG sprite 或图标字体，自动生成。
```

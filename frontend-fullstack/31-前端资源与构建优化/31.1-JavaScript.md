## 概述

JavaScript 是前端体积与加载时间的大头，优化 JS 资源对性能影响最大。核心策略是「减少体积、减少请求、按需加载、缓存复用」。

```text
JS 优化手段：
1. Minification —— 压缩混淆，减小体积
2. Tree Shaking —— 删除未使用代码
3. Code Splitting —— 拆分代码，按需加载
4. Dynamic Import —— 运行时动态加载
5. Lazy Loading —— 路由/组件懒加载
6. Chunking —— 分包策略
7. Vendor Chunk —— 第三方依赖独立分包
```

```text
优化目标：
体积更小 → 下载更快
按需加载 → 首屏更快
缓存复用 → 二次访问更快
```

## Minification

Minification（压缩）通过删除空白注释、缩短标识符、简化表达式来减小 JS 体积，是生产构建的标配。

```js
// 压缩前
function calculateTotal(price, quantity) {
  const total = price * quantity; // 计算总价
  return total;
}

// 压缩后（示意）
function a(b,c){return b*c}
```

```text
压缩手段：
1. 删除注释与空白
2. 变量名缩短（mangle）
3. 死代码消除（DCE）
4. 常量折叠与表达式简化
```

```js
// Webpack 用 TerserPlugin 压缩
module.exports = {
  mode: 'production',
  optimization: {
    minimize: true,
    minimizer: [new TerserPlugin({ parallel: true })],
  },
};
```

## Tree Shaking

Tree Shaking 在打包时移除未被引用的导出代码，基于 ESM 静态分析，能显著减小产物体积。

```js
// utils.js
export function used() { return 'used'; }
export function unused() { return 'unused'; }  // 被摇掉

// main.js
import { used } from './utils';
console.log(used());
```

```text
Tree Shaking 前提：
1. ES Module（静态 import/export）
2. 生产模式构建
3. 正确的 sideEffects 声明
```

```json
// package.json 标记无副作用文件
{ "sideEffects": ["*.css", "*.scss"] }
```

## Code Splitting

Code Splitting 把大 Bundle 拆成多个小 chunk，实现按需加载与缓存复用。第三方库与业务代码分离是典型做法。

```js
module.exports = {
  optimization: {
    splitChunks: {
      chunks: 'all',
      minSize: 20000,
      cacheGroups: {
        vendor: { test: /[\\/]node_modules[\\/]/, name: 'vendors' },
      },
    },
  },
};
```

```text
分割维度：
1. 入口分割 —— 多入口各自成 chunk
2. 动态导入分割 —— import() 产生异步 chunk
3. 公共代码分割 —— splitChunks 抽公共依赖
```

## Dynamic Import

Dynamic Import 用 `import()` 在运行时异步加载模块，返回 Promise，是代码分割与懒加载的语法基础。

```js
// 需要时才加载
document.getElementById('btn').onclick = async () => {
  const { default: renderChart } = await import('./chart');
  renderChart();
};
```

```text
Dynamic Import 特点：
1. 返回 Promise，可 await
2. 每个动态导入生成独立 chunk
3. 支持魔法注释控制 chunk 名
```

```js
// 魔法注释指定 chunk 名
import(/* webpackChunkName: "report" */ './report');
```

## Lazy Loading

Lazy Loading（懒加载）把首屏不需要的代码延迟到使用时才加载，减少首屏体积，加快初始渲染。

```js
// React 路由懒加载
import { lazy, Suspense } from 'react';
const Profile = lazy(() => import('./pages/Profile'));

function App() {
  return (
    <Suspense fallback={<div>加载中...</div>}>
      <Profile />
    </Suspense>
  );
}
```

```text
懒加载适用场景：
1. 路由页面 —— 每个页面独立加载
2. 首屏不可见组件 —— 弹窗、抽屉等
3. 按需功能 —— 图表、编辑器等重组件
```

## Chunking

Chunking 是代码分割的具体落地：把产物组织成多个 chunk 文件，平衡「请求数量」与「缓存粒度」。

```text
Chunking 策略：
1. 首屏关键代码合并，减少请求
2. 变更频率不同的代码分离，优化缓存
3. 大体积库独立分包，并行加载
```

```js
// Vite 手动分包
export default {
  build: {
    rollupOptions: {
      output: {
        manualChunks: {
          vue: ['vue', 'vue-router'],
          ui: ['ant-design-vue'],
        },
      },
    },
  },
};
```

## Vendor Chunk

Vendor Chunk 把第三方依赖（node_modules）单独拆成一个 chunk。vendor 代码变更频率低，独立分包后可长期缓存，业务代码迭代不影响它。

```js
module.exports = {
  optimization: {
    splitChunks: {
      cacheGroups: {
        vendor: {
          test: /[\\/]node_modules[\\/]/,
          name: 'vendor',
          chunks: 'all',
          priority: 10,
        },
      },
    },
  },
};
```

```text
Vendor Chunk 的收益：
1. 第三方库变更少，哈希稳定，缓存命中率高
2. 业务代码更新不影响 vendor 缓存
3. 浏览器并行下载 vendor 与业务 chunk
```

## 应用场景实战

### 场景一：大型 SPA 完整 JS 优化

```js
// webpack.config.js
const TerserPlugin = require('terser-webpack-plugin');

module.exports = {
  mode: 'production',
  output: { filename: '[name].[contenthash:8].js' },
  optimization: {
    minimize: true,
    minimizer: [new TerserPlugin({ parallel: true })],
    runtimeChunk: 'single',
    moduleIds: 'deterministic',
    splitChunks: {
      chunks: 'all',
      cacheGroups: {
        vendor: { test: /[\\/]node_modules[\\/]/, name: 'vendors', priority: 10 },
      },
    },
  },
};
```

### 场景二：组件级按需加载

```js
import { useState } from 'react';

function Report() {
  const [Chart, setChart] = useState(null);

  async function loadChart() {
    const mod = await import('echarts');
    setChart(() => mod.default);
  }

  return <button onClick={loadChart}>加载图表</button>;
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. 生产构建必须开启压缩与 Tree Shaking
2. 第三方库独立 vendor chunk，稳定缓存
3. 路由级懒加载，首屏只加载必要代码
4. contenthash + runtimeChunk 稳定长缓存
5. 避免过度分包，平衡请求数与缓存粒度

### 踩坑记录

```text
坑 1：Tree Shaking 对 CJS 失效
结论：CommonJS 库的未使用代码被打进产物。
原因：CJS 无静态结构，无法精确摇树。
解法：优先选 ESM 版本的库（module 字段）。

坑 2：vendor chunk 频繁失效
结论：vendor 哈希每次发布都变。
原因：runtime 与 moduleId 混入导致。
解法：runtimeChunk: 'single' + moduleIds: 'deterministic'。

坑 3：懒加载无 fallback 白屏
结论：点击后长时间无响应。
原因：动态导入未提供加载状态。
解法：Suspense fallback 或 loading 状态。

坑 4：分包过细请求爆炸
结论：首屏 HTTP 请求数激增。
原因：chunk 拆分粒度过小。
解法：按变更频率分组，而非按模块细分。

坑 5：压缩误删关键代码
结论：生产环境功能异常。
原因：drop_console 等激进配置删除了必要逻辑。
解法：压缩配置保守，验证后再收紧。
```

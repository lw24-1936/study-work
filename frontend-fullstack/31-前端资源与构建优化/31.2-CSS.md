## 概述

CSS 优化直接影响首屏渲染速度：CSS 阻塞渲染，体积越大、加载越慢，白屏时间越长。核心策略是「减小体积、按需加载、优先关键样式」。

```text
CSS 优化手段：
1. Minification —— 压缩，减小体积
2. Purge —— 移除未使用的样式
3. Critical CSS —— 首屏关键样式内联
4. Code Splitting —— CSS 按需分割
5. Extraction —— 从 JS 抽离独立 CSS 文件
```

```text
关键认知：
CSS 是渲染阻塞资源 —— 未加载完不渲染页面
优化目标 —— 减少体积 + 加快关键路径
```

## Minification

CSS Minification 删除空白、注释、冗余代码（重复声明、可简写的属性），减小文件体积。

```css
/* 压缩前 */
.button {
  color: #ff0000;
  margin-top: 10px;
  margin-right: 10px;
  margin-bottom: 10px;
  margin-left: 10px;
}

/* 压缩后（示意） */
.button{color:red;margin:10px}
```

```js
// cssnano 是主流 CSS 压缩工具
// postcss.config.js
module.exports = {
  plugins: [require('cssnano')({ preset: 'default' })],
};
```

```text
cssnano 优化项：
1. 删除空白与注释
2. 颜色值简写（#ff0000 → red）
3. 属性简写合并（margin 四值合并）
4. 删除冗余与浏览器前缀
```

## Purge

Purge 移除项目中未被使用的 CSS 规则。CSS 框架（如 Tailwind）生成的 CSS 巨大，Purge 能大幅瘦身。

```js
// Tailwind 的 purge 配置
module.exports = {
  content: ['./src/**/*.{js,jsx,ts,tsx,vue}'],   // 扫描范围
  theme: { extend: {} },
  plugins: [],
};
```

```text
Purge 原理：
1. 扫描源码，收集用到的类名
2. 只保留被引用的 CSS 规则
3. 删除其余规则（大幅减小体积）
```

```js
// 通用方案：PurgeCSS
// postcss.config.js
module.exports = {
  plugins: [
    require('@fullhuman/postcss-purgecss')({
      content: ['./src/**/*.html', './src/**/*.js'],
      safelist: ['body', 'html'],
    }),
  ],
};
```

## Critical CSS

Critical CSS 把「首屏可见区域」所需的样式提取出来内联到 HTML 的 `<style>` 中，让首屏不等待外部 CSS 加载，加速首屏渲染。

```html
<!-- 首屏关键样式内联 -->
<style>
  .hero { font-size: 2rem; color: #333; }
  .navbar { display: flex; }
</style>
<!-- 其余样式异步加载 -->
<link rel="preload" href="styles.css" as="style" onload="this.onload=null;this.rel='stylesheet'">
```

```text
Critical CSS 的价值：
1. 首屏渲染不阻塞在外部 CSS 上
2. 减少 LCP（最大内容绘制）时间
3. 工具：critical、penthouse 自动提取
```

```text
内联 vs 外链的权衡：
内联 —— 首屏快，但 HTML 变大、无法缓存
外链 —— 可缓存，但增加一次请求
最佳 —— 关键样式内联 + 其余外链
```

## Code Splitting

CSS Code Splitting 让每个异步 chunk 的 CSS 独立成文件，按需加载对应样式，避免一次性加载全部 CSS。

```js
// Vite 默认开启 CSS 分割
export default {
  build: {
    cssCodeSplit: true,
  },
};
```

```text
CSS 分割行为：
1. 异步组件的 CSS 单独成文件
2. 加载该组件时自动加载其 CSS
3. 首屏只加载首屏需要的样式
```

```js
// Webpack 用 MiniCssExtractPlugin 实现
const MiniCssExtractPlugin = require('mini-css-extract-plugin');
module.exports = {
  plugins: [new MiniCssExtractPlugin({ filename: '[name].[contenthash].css' })],
};
```

## Extraction

Extraction 把 CSS 从 JS 中抽离成独立的 .css 文件，实现 CSS 与 JS 并行加载、独立缓存，避免 style-loader 的运行时注入。

```js
// Webpack 抽离 CSS
const MiniCssExtractPlugin = require('mini-css-extract-plugin');

module.exports = {
  module: {
    rules: [
      { test: /\.css$/, use: [MiniCssExtractPlugin.loader, 'css-loader'] },
    ],
  },
  plugins: [new MiniCssExtractPlugin()],
};
```

```text
Extraction 的收益：
1. CSS 与 JS 并行下载，不阻塞 JS 执行
2. CSS 独立缓存，样式变更不影响 JS 缓存
3. 避免 style-loader 运行时注入的闪烁
```

## 应用场景实战

### 场景一：生产 CSS 全链路优化

```js
// postcss.config.js —— 压缩 + 清理
module.exports = {
  plugins: [
    require('autoprefixer'),
    require('@fullhuman/postcss-purgecss')({
      content: ['./src/**/*.{js,jsx,ts,tsx,vue,html}'],
      safelist: ['html', 'body'],
    }),
    require('cssnano')({ preset: 'default' }),
  ],
};
```

### 场景二：首屏关键样式内联

```html
<!DOCTYPE html>
<html>
<head>
  <style>
    /* 首屏关键样式 */
    .header { height: 60px; background: #fff; }
    .banner { width: 100%; height: 300px; }
  </style>
  <link rel="preload" href="/styles/app.css" as="style" onload="this.rel='stylesheet'">
</head>
<body>...</body>
</html>
```

## 最佳实践与踩坑记录

### 最佳实践

1. 生产构建必须压缩 CSS（cssnano）
2. 框架类项目开启 Purge，删除无用样式
3. 首屏关键样式内联，其余异步加载
4. CSS 从 JS 抽离，实现并行加载与缓存
5. 按组件分割 CSS，按需加载

### 踩坑记录

```text
坑 1：Purge 误删动态类名
结论：运行时拼接的类名被 Purge 删除。
原因：Purge 只扫描静态字符串，识别不了动态拼接。
解法：safelist 保留动态类名，或避免动态拼接类名。

坑 2：style-loader 用于生产
结论：首屏闪烁、渲染阻塞。
原因：style-loader 运行时注入，阻塞渲染。
解法：生产换 MiniCssExtractPlugin 抽离文件。

坑 3：Critical CSS 内联过多
结论：HTML 体积暴涨，反而变慢。
原因：把全部样式都内联了。
解法：只内联首屏可见的关键样式。

坑 4：CSS 分割导致样式顺序错乱
结论：样式覆盖顺序与预期不符。
原因：异步 chunk 的 CSS 加载时机变化。
解法：关键样式统一入口引入，避免依赖加载顺序。

坑 5：压缩合并属性引发兼容问题
结论：简写属性覆盖了单独的设置。
原因：cssnano 合并 margin 等属性可能产生覆盖。
解法：检查压缩配置，必要时关闭 aggressiveMerge。
```

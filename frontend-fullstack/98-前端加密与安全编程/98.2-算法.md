## 概述

加密算法是 Web Crypto API 的核心内容，分为三大类：哈希算法（SHA 系列，单向不可逆）、对称加密（AES-GCM，同一密钥加解密）、非对称算法（RSA-OAEP、ECDSA、ECDH，公私钥配对）。理解每类算法的用途与边界，是前端做安全编程的基础。

```text
加密算法分类与用途：
1. 哈希（SHA-256/384/512）—— 完整性校验、指纹，不可逆
2. 对称加密（AES-GCM）—— 数据机密性，加解密用同一密钥，速度快
3. 非对称加密（RSA-OAEP）—— 密钥交换、加密小数据，公私钥配对
4. 数字签名（ECDSA）—— 来源认证、防篡改，私钥签公钥验
5. 密钥协商（ECDH）—— 双方在不共享密钥的情况下协商出共享密钥
```

```js
// 算法能力速查
const algorithms = {
  hash:      ['SHA-1', 'SHA-256', 'SHA-384', 'SHA-512'],
  symmetric: ['AES-GCM', 'AES-CBC', 'AES-CTR'],
  asymmetric:['RSA-OAEP', 'RSA-PSS', 'ECDSA', 'ECDH', 'ECDH'],
  hmac:      ['HMAC'],
};
console.log(algorithms);
```

## SHA-256

SHA-256 是 SHA-2 家族中最常用的哈希算法，输出固定 256 位（32 字节）摘要。它计算快、碰撞概率极低，是前端校验完整性、生成指纹的默认选择。

```js
// SHA-256 摘要
async function sha256(input) {
  const data = typeof input === 'string'
    ? new TextEncoder().encode(input)
    : input;                                   // 支持 Uint8Array/ArrayBuffer
  const digest = await crypto.subtle.digest('SHA-256', data);
  return [...new Uint8Array(digest)]
    .map(b => b.toString(16).padStart(2, '0'))
    .join('');
}

sha256('abc').then(hex => console.log(hex));
// 输出固定 64 个 hex 字符（256 bit）
```

```text
SHA-256 的特征：
1. 输出固定 256 bit，即 32 字节 / 64 个 hex 字符
2. 输入长度不限，输出长度恒定
3. 雪崩效应 —— 输入改一个字符，输出完全变样
4. 单向不可逆，无法从摘要还原原文
```

## SHA-384

SHA-384 输出 384 位（48 字节）摘要，安全性略高于 SHA-256，代价是计算稍慢。它常用于需要更高安全强度的场景，例如某些签名算法内部默认的哈希参数。

```js
// SHA-384 摘要
async function sha384(input) {
  const data = new TextEncoder().encode(input);
  const digest = await crypto.subtle.digest('SHA-384', data);
  return [...new Uint8Array(digest)]
    .map(b => b.toString(16).padStart(2, '0'))
    .join('');
}

sha384('abc').then(hex => console.log(hex));   // 96 个 hex 字符
```

```text
SHA-384 的适用场景：
1. 需要 192 位以上安全强度的场景
2. 政府、金融等高合规要求环境
3. 与 SHA-384 配套的签名算法（如 RSA-PSS with SHA-384）
```

## SHA-512

SHA-512 输出 512 位（64 字节）摘要，是 SHA-2 家族中安全强度最高、输出最长的成员。在 64 位机器上，SHA-512 的实际计算速度甚至可能快于 SHA-256，但摘要更长。

```js
// SHA-512 摘要
async function sha512(input) {
  const data = new TextEncoder().encode(input);
  const digest = await crypto.subtle.digest('SHA-512', data);
  return [...new Uint8Array(digest)]
    .map(b => b.toString(16).padStart(2, '0'))
    .join('');
}

sha512('abc').then(hex => console.log(hex));   // 128 个 hex 字符
```

```text
SHA 系列选择建议：
1. 普通场景默认 SHA-256，安全与性能平衡最佳
2. 合规要求更高时用 SHA-384 / SHA-512
3. SHA-1 已被破解，MD5 更不安全，一律禁用
4. 摘要越短越省存储，但安全余量越低，按需权衡
```

## AES-GCM

AES-GCM 是对称加密算法，也是现代前端加密的首选。它是 AEAD（认证加密）算法，加密的同时生成认证标签，能同时保证机密性与完整性，且支持流式处理大数据。

```js
// AES-GCM 加密 + 解密完整示例
async function aesGcmEncrypt(plainText, key) {
  const iv = crypto.getRandomValues(new Uint8Array(12)); // 推荐 12 字节 IV
  const cipher = await crypto.subtle.encrypt(
    { name: 'AES-GCM', iv, additionalData: undefined },
    key,
    new TextEncoder().encode(plainText)
  );
  return { iv, cipher };
}

async function aesGcmDecrypt(iv, cipher, key) {
  const plain = await crypto.subtle.decrypt(
    { name: 'AES-GCM', iv },
    key,
    cipher
  );
  return new TextDecoder().decode(plain);
}

// 生成 256 位密钥并跑通全流程
const key = await crypto.subtle.generateKey(
  { name: 'AES-GCM', length: 256 }, true, ['encrypt', 'decrypt']
);
const { iv, cipher } = await aesGcmEncrypt('机密数据', key);
const original = await aesGcmDecrypt(iv, cipher, key);
console.log(original); // '机密数据'
```

```text
AES-GCM 的关键参数：
1. 密钥长度 —— 128 / 192 / 256 位，256 位最安全
2. IV —— 推荐 12 字节，每次加密必须随机且不重复
3. 认证标签 —— 密文末尾自动附带，解密时校验完整性
4. additionalData —— 可附带未加密但需认证的附加数据（如协议头）
```

## RSA-OAEP

RSA-OAEP 是非对称加密算法，用公钥加密、私钥解密。它基于大整数分解难题，安全性高，但速度慢且只能加密有限长度数据，通常用于加密对称密钥（密钥包裹）。

```js
// RSA-OAEP 加密 + 解密
async function rsaEncrypt(plainText, publicKey) {
  const cipher = await crypto.subtle.encrypt(
    { name: 'RSA-OAEP' },
    publicKey,
    new TextEncoder().encode(plainText)
  );
  return cipher;
}

async function rsaDecrypt(cipher, privateKey) {
  const plain = await crypto.subtle.decrypt(
    { name: 'RSA-OAEP' },
    privateKey,
    cipher
  );
  return new TextDecoder().decode(plain);
}

// 生成 2048 位密钥对
const keyPair = await crypto.subtle.generateKey(
  { name: 'RSA-OAEP', modulusLength: 2048, publicExponent: new Uint8Array([1, 0, 1]), hash: 'SHA-256' },
  true,
  ['encrypt', 'decrypt']
);
const cipher = await rsaEncrypt('小数据', keyPair.publicKey);
const text = await rsaDecrypt(cipher, keyPair.privateKey);
console.log(text); // '小数据'
```

```text
RSA-OAEP 的边界：
1. 2048 位密钥最多加密约 190 字节明文（受 OAEP 填充影响）
2. 加密大数据会报错，应改用「RSA 包裹 AES 密钥 + AES 加密数据」
3. 模长越长越安全，2048 位是当前最低推荐，3072 位更稳妥
4. publicExponent 通常用 65537（即 [1,0,1]）
```

## ECDSA

ECDSA 是基于椭圆曲线的数字签名算法，私钥签名、公钥验签。相比 RSA，它在相同安全强度下密钥更短、速度更快，是现代签名方案的默认选择。

```js
// ECDSA 签名 + 验签
async function ecdsaSign(message, privateKey) {
  const sig = await crypto.subtle.sign(
    { name: 'ECDSA', hash: 'SHA-256' },
    privateKey,
    new TextEncoder().encode(message)
  );
  return sig;
}

async function ecdsaVerify(message, sig, publicKey) {
  return crypto.subtle.verify(
    { name: 'ECDSA', hash: 'SHA-256' },
    publicKey,
    sig,
    new TextEncoder().encode(message)
  );
}

const keyPair = await crypto.subtle.generateKey(
  { name: 'ECDSA', namedCurve: 'P-256' }, true, ['sign', 'verify']
);
const sig = await ecdsaSign('订单已支付', keyPair.privateKey);
const valid = await ecdsaVerify('订单已支付', sig, keyPair.publicKey);
console.log(valid); // true
```

```text
ECDSA 的曲线选择：
1. P-256 —— 最常用，安全与性能平衡
2. P-384 —— 更高安全强度
3. P-521 —— 最高安全强度（注意不是 P-512）
4. 签名是随机化的，同一数据两次签名结果不同
```

## ECDH

ECDH 是椭圆曲线密钥协商算法，让通信双方在不直接传输密钥的情况下，各自用「对方公钥 + 自己私钥」推导出相同的共享密钥，用于后续对称加密。

```js
// ECDH 密钥协商
async function ecdhSharedSecret(publicKey, privateKey) {
  const bits = await crypto.subtle.deriveBits(
    { name: 'ECDH', public: publicKey },   // 对方的公钥
    privateKey,                            // 自己的私钥
    256                                     // 导出 256 位共享密钥
  );
  return bits;
}

// 双方各自生成密钥对
const alice = await crypto.subtle.generateKey(
  { name: 'ECDH', namedCurve: 'P-256' }, true, ['deriveBits']
);
const bob = await crypto.subtle.generateKey(
  { name: 'ECDH', namedCurve: 'P-256' }, true, ['deriveBits']
);

// 双方推导出的共享密钥一致
const secretA = await ecdhSharedSecret(bob.publicKey, alice.privateKey);
const secretB = await ecdhSharedSecret(alice.publicKey, bob.privateKey);
console.log(secretA, secretB); // 两者相同
```

```text
ECDH 的机制：
1. 双方只交换公钥，私钥始终留在本地
2. 数学上 ensure 双方算出的共享密钥一致
3. 共享密钥通常再经 KDF（密钥派生）加工成实际加密密钥
4. 只防窃听，不防中间人，需配合身份认证
```

## 应用场景实战

### 场景一：用 RSA 包裹 AES 密钥实现混合加密

```js
// 混合加密：AES 加密数据，RSA 加密 AES 密钥
async function hybridEncrypt(plainText, rsaPublicKey) {
  const aesKey = await crypto.subtle.generateKey(
    { name: 'AES-GCM', length: 256 }, true, ['encrypt']
  );
  const iv = crypto.getRandomValues(new Uint8Array(12));
  const cipher = await crypto.subtle.encrypt(
    { name: 'AES-GCM', iv }, aesKey, new TextEncoder().encode(plainText)
  );
  // 用 RSA 公钥包裹 AES 密钥
  const rawKey = await crypto.subtle.exportKey('raw', aesKey);
  const wrappedKey = await crypto.subtle.encrypt(
    { name: 'RSA-OAEP' }, rsaPublicKey, rawKey
  );
  return { iv, cipher, wrappedKey };
}
```

### 场景二：请求签名（防篡改）

```js
// 客户端用私钥对请求体签名，服务端用公钥验签
async function signRequest(body, privateKey) {
  const payload = JSON.stringify(body);
  const sig = await crypto.subtle.sign(
    { name: 'ECDSA', hash: 'SHA-256' },
    privateKey,
    new TextEncoder().encode(payload)
  );
  return {
    body,
    signature: btoa(String.fromCharCode(...new Uint8Array(sig)))
  };
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. 哈希默认 SHA-256，杜绝 SHA-1 与 MD5
2. 对称加密一律 AES-GCM，禁用已被攻破的 ECB 模式与无认证的 CBC
3. 非对称算法只用于包裹密钥或加密小数据，大数据走对称加密
4. RSA 密钥至少 2048 位，椭圆曲线优先 P-256
5. ECDH 协商出的共享密钥要再经 KDF 派生，别直接当加密密钥
6. IV、nonce 等随机量每次操作都重新生成，永不重复

### 踩坑记录

```text
坑 1：用 RSA 直接加密大文件
结论：超过模长限制直接抛错，或性能极差。
原因：RSA-OAEP 只能加密远小于密钥模长的数据。
解法：用 AES-GCM 加密数据，再用 RSA 包裹 AES 密钥。

坑 2：AES 用了 ECB 模式
结论：相同明文块加密出相同密文块，图案泄露。
原因：ECB 模式无 IV、无链接，缺乏扩散性。
解法：改用 AES-GCM（AEAD）或至少 CBC+随机 IV。

坑 3：ECDSA 验签结果与直觉相反
结论：把 verify 的 false 当异常处理，逻辑写错。
原因：verify 只返回布尔值，签名无效不抛异常。
解法：按返回值分支处理，false 即拒绝该数据。

坑 4：混淆了签名与加密的方向
结论：用私钥「加密」、公钥「解密」，导致任何人都能解。
原因：非对称加密是「公钥加密、私钥解密」，签名才是「私钥签、公钥验」。
解法：理清四种原语的方向，加密与签名分开用。

坑 5：ECDH 未认证导致中间人攻击
结论：攻击者替换双方公钥后窃取通信内容。
原因：ECDH 只防窃听，不验证对方身份。
解法：公钥传输走签名或证书认证，确认对方身份后再协商。
```

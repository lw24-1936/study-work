## 概述

CSS 性能的核心是「浏览器渲染流水线」——修改一个 CSS 属性，浏览器要经历 Layout（布局）、Paint（绘制）、Composite（合成）三个阶段。不同属性触发的阶段不同，代价也不同：改 transform/opacity 只触发合成（最便宜），改 width/height 触发全流程（最贵）。选对属性，动画才流畅。

```text
CSS 性能的黄金法则：
动画/高频变化的属性，只动 transform 和 opacity，
它们只触发 Composite（合成），不触发 Layout/Paint。
```

## 浏览器渲染流水线：Layout、Paint、Composite

浏览器把 CSS 变成屏幕像素，经历三个阶段：

```text
Layout（布局/重排）—— 计算元素的位置和尺寸
Paint（绘制/重绘）—— 绘制元素的视觉（颜色、边框、阴影）
Composite（合成）—— 把各图层合并成最终画面
```

```text
三个阶段的代价：
Layout —— 最贵（影响整个页面布局，可能级联）
Paint —— 次贵（重新绘制像素）
Composite —— 最便宜（图层合成，GPU 处理）
```

```text
哪些属性触发哪个阶段：
触发 Layout（最贵）—— width、height、margin、padding、top/left、
                      font-size、display 等（改变布局）

触发 Paint（次贵）—— color、background、border、box-shadow、
                      visibility 等（改变视觉但不改变布局）

只触发 Composite（最便宜）—— transform、opacity（改变合成层）
```

```text
属性代价分类（记住）：
布局属性（改了就重排）—— width/height/margin/padding/top/left/display
绘制属性（改了就重绘）—— color/background/border/shadow
合成属性（只合成）—— transform/opacity/filter
```

```text
为什么「布局属性」最贵：
改 width 会触发 Layout，Layout 可能级联影响其他元素的位置，
整个页面的布局都要重算，成本最高。
```

## Transform 与 Opacity 的高性能

transform 和 opacity 是「合成层」属性，动画它们最流畅：

```css
/* 高性能动画：只动 transform 和 opacity */
.box {
  transition: transform 0.3s, opacity 0.3s;
}
.box:hover {
  transform: translateY(-4px);
  opacity: 0.8;
}
```

```text
transform/opacity 为什么快：
1. 只触发 Composite（不重排不重绘）
2. 由 GPU 处理（合成层在 GPU 上操作）
3. 不打断主线程（主线程空闲做其他事）
```

```text
性能对比（同样实现位移）：
transform: translateX(100px) —— 合成层，GPU 处理，流畅
left: 100px —— 触发 Layout，主线程重排，可能卡顿

结论：动画位移用 transform，不用 left/top/margin。
```

```text
替代方案（用合成属性替代布局属性）：
位移 —— transform: translate 替代 left/top/margin
缩放 —— transform: scale 替代 width/height
显隐 —— opacity 替代 visibility（需保留交互时慎用）
```

## will-change 提前优化

will-change 提前告诉浏览器「这个元素将要变化」，浏览器提前做优化准备：

```css
.box {
  will-change: transform;   /* 预告 transform 将变化 */
  will-change: opacity;     /* 预告 opacity 将变化 */
}
```

```text
will-change 的作用：
1. 提示浏览器「这个属性即将动画」
2. 浏览器提前创建合成层，动画开始时无需额外开销
3. 避免动画第一帧的卡顿
```

```text
will-change 的使用原则（重要）：
1. 只对「即将动画」的元素用，不要全局滥用
2. 动画结束后移除 will-change（否则一直占资源）
3. 不要给大量元素同时设 will-change（内存暴涨）
```

```css
/* 正确用法：hover 前后切换 will-change */
.box:hover {
  will-change: transform;  /* 悬停时预告（即将动画） */
}
.box {
  will-change: auto;       /* 平时释放 */
}
```

```text
will-change 的坑：
1. 长期保持 will-change 会占用 GPU 内存（合成层常驻）
2. 大量元素设 will-change 导致内存暴涨、反而变慢
3. 用「临时触发」模式（hover 时加，离开移除）而非常驻
```

## GPU Compositing 合成

合成是把「多层」合并成最终画面的过程，是高性能动画的基础。

```text
合成的机制：
1. 浏览器把某些元素「提升」到独立合成层（GPU 层）
2. 合成层的变化由 GPU 处理，不打扰主线程
3. 最终把多层合成成屏幕画面
```

```text
哪些操作会创建合成层（元素被提升到 GPU）：
1. transform / opacity 动画
2. will-change: transform / opacity
3. position: fixed
4. 3D transform（translateZ 等）
5. video、canvas 等
```

```text
合成层的代价（权衡）：
1. 每个合成层占用 GPU 内存
2. 层太多 → 内存暴涨 → 反而变慢
3. 「层爆炸」——大量元素被提升，内存不足

所以 will-change 和合成层都要克制使用。
```

```text
性能优化的完整思路：
1. 动画只用 transform/opacity（走合成）
2. will-change 临时触发，不常驻
3. 避免动画布局属性（width/left/top）
4. 用 DevTools Performance 面板分析卡顿原因
```

## 应用场景实战

### 场景一：高性能的列表滚动动画

```css
/* 列表项淡入（只动 transform + opacity） */
.list-item {
  opacity: 0;
  transform: translateY(20px);
  animation: fade-in-up 0.4s ease-out forwards;
}
@keyframes fade-in-up {
  to {
    opacity: 1;
    transform: translateY(0);
  }
}
```

### 场景二：will-change 的正确用法

```css
/* 拖拽元素：拖拽时开启 will-change，结束释放 */
.draggable {
  will-change: auto;
}
.draggable:active {
  will-change: transform;  /* 拖拽期间预告 */
}
```

### 场景三：对比高性能 vs 低性能写法

```css
/* 低性能：动画 left（触发 Layout） */
.slide-bad {
  position: relative;
  left: 0;
  transition: left 0.3s;
}
.slide-bad:hover { left: 100px; }

/* 高性能：动画 transform（只触发 Composite） */
.slide-good {
  transition: transform 0.3s;
}
.slide-good:hover { transform: translateX(100px); }
```

## 最佳实践与踩坑记录

### 最佳实践

1. 动画只用 transform 和 opacity（走合成，GPU 加速）
2. 位移用 translate 不用 left/top，缩放用 scale 不用 width
3. will-change 临时触发（hover/active 时加），不常驻
4. 避免动画布局属性（width/margin/top），它们触发重排
5. 用 DevTools Performance 面板定位卡顿，而非凭感觉优化

### 踩坑记录

```text
坑 1：动画 width/left 导致卡顿
结论：动画掉帧，滚动/位移卡顿。
原因：width/left 触发 Layout（重排），主线程阻塞。
解法：改用 transform: scale / translate。

坑 2：will-change 全局滥用导致内存暴涨
结论：给大量元素常驻 will-change，页面越来越卡。
原因：每个 will-change 都创建合成层，占 GPU 内存。
解法：will-change 临时触发（hover 时加），离开移除。

坑 3：误以为 box-shadow 动画高性能
结论：阴影动画卡顿。
原因：box-shadow 触发 Paint（重绘），不是合成层属性。
解法：阴影动画少用，或用 transform 模拟（预渲染阴影图层）。

坑 4：合成层太多导致「层爆炸」
结论：大量 3D transform/fixed 元素，GPU 内存耗尽。
原因：每个合成层占内存，层太多反而慢。
解法：控制合成层数量，合并相邻层，避免不必要的 3D。

坑 5：优化方向错误（过度优化）
结论：花大量时间「优化」其实不卡的地方。
原因：没先测量就优化，凭感觉。
解法：先用 Performance 面板测量，定位真正的瓶颈再优化。
```

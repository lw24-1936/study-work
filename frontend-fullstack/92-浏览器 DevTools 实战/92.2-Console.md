## 概述

Console（控制台）是 DevTools 的交互式命令行，既能输出日志、错误与警告，也能直接执行 JavaScript 表达式，是前端调试最频繁的入口。它运行在当前页面的全局上下文里，可以实时读写页面状态。

```text
Console 的核心能力：
1. 输出 —— console.log/info/warn/error 等日志分类展示
2. 执行 —— 输入任意 JS 表达式，回车即执行并回显结果
3. 上下文 —— 运行在页面 window 上下文中，可访问全局变量与 DOM
4. 过滤 —— 按级别（Error/Warning/Info）或关键词过滤海量日志
```

```js
// 基础日志方法
console.log('普通信息');
console.warn('警告，可能有问题');
console.error('错误，需要处理');
console.table([{ id: 1, name: 'vue' }, { id: 2, name: 'react' }]); // 表格展示
```

## JavaScript

Console 本质是一个 REPL（读取-求值-打印循环），可以直接执行 JavaScript 并访问页面作用域里的变量、函数与全局对象。它还能用 `$0` 引用 Elements 面板当前选中的节点，`$` 则是 querySelector 的别名。

```js
// Console 里直接操作页面状态
const app = document.querySelector('#app');
app.style.background = 'red';       // 直接改样式
$0;                                // Elements 面板当前选中的元素
$$('div');                         // 相当于 document.querySelectorAll('div')
localStorage.setItem('k', 'v');    // 操作存储
```

```text
Console 执行 JS 的要点：
1. REPL —— 多行输入用 Shift+Enter 换行，Enter 执行
2. 实时求值 —— 输入时实时预览表达式结果（Eager Evaluation）
3. 异步友好 —— 支持 await，直接 await fetch(...) 拿结果
4. 变量访问 —— 能读到闭包外的全局，但读不到模块内部私有变量
```

## Error

Error 是 Console 里最需要重视的输出：JS 运行时抛出的未捕获异常、Promise 未处理的 rejection、资源加载失败都会以红色错误呈现，并附带堆栈信息，点堆栈可直接跳转到 Sources 对应行。

```js
// 会抛到 Console 的错误
function boom() { throw new Error('出错了'); }
boom(); // Console 输出：Uncaught Error: 出错了，带调用堆栈

// 未处理的 Promise rejection
Promise.reject(new Error('异步错误'));
// Console 输出：Uncaught (in promise) Error: 异步错误
```

```text
Error 的排查要点：
1. 堆栈 —— 从下往上读，最上面是出错点，下面是调用链
2. 点击跳转 —— 点堆栈帧跳到 Sources 对应源码行，可设断点
3. 未捕获 vs 捕获 —— 只有未捕获的才报红，被 try/catch 吞掉的静默
4. source map —— 生产代码堆栈可通过 Source Map 还原到源码
```

## Warning

Warning 是浏览器的「黄牌」提示：不是致命错误，但可能是性能、兼容性、废弃 API 或安全方面的隐患。常见如 React/Vue 的开发期警告、废弃的浏览器 API、第三方 Cookie 即将失效等，长期忽视会积累成真问题。

```js
// 触发常见警告
console.warn('该 API 已废弃，请迁移到新接口');

// 浏览器自身的警告示例：
// [Deprecation] Synchronous XMLHttpRequest on the main thread is deprecated
```

```text
Warning 的处理原则：
1. 不要忽略 —— 警告常是未来报错的「预演」
2. 分类 —— 框架警告（如 React key 警告）与浏览器警告分开处理
3. 生产清理 —— 上线前确认没有遗留的废弃 API 或开发期警告
4. 过滤 —— 大量噪音时按级别筛选，优先处理 Error 再处理 Warning
```

## Network

Console 里也承载一部分网络排查：fetch/XHR 失败、资源加载失败（404、CORS 被拦）、混合内容（HTTPS 页面加载 HTTP 资源）都会在 Console 报错，与 Network 面板互补。

```js
// 触发网络相关错误
fetch('/api/not-exist').then(r => {
  if (!r.ok) throw new Error(`HTTP ${r.status}`);
});
// Console 输出 404 错误，Network 面板里能看到完整请求

// CORS 错误
// Console 输出：Access to fetch at '...' has been blocked by CORS policy
```

```text
Console 里的网络问题：
1. 404/500 —— 请求发出但服务端返回错误码
2. CORS —— 被同源策略拦截，浏览器先报错，请求可能根本没到服务端
3. 混合内容 —— HTTPS 页面里的 HTTP 资源被阻止加载
4. 失败请求详情 —— Console 里点错误可跳转到 Network 面板看完整信息
```

## 进阶技巧与选型

### 快捷键与隐藏功能

```text
Console 的高频快捷键：
1. Ctrl+L —— 清空控制台（保留页面状态，不刷新页面）
2. Shift+Enter —— 多行输入换行，Enter 执行
3. 上下方向键 —— 浏览历史命令；先输入前缀再按上键可按前缀过滤
4. Tab —— 自动补全属性与方法名
5. 选中节点后右键 → Reveal in Elements panel，或直接用 $0 引用
```

```text
内置快捷变量（资深必备）：
1. $0-$4 —— 最近在 Elements 选中的 5 个节点，$0 最新
2. $_ —— 上一次表达式的求值结果，方便连算
3. $ —— document.querySelector 的别名
4. $$ —— document.querySelectorAll 的别名，返回真数组
5. $$x('//div') —— 按 XPath 查询节点
6. inspect(obj) —— 把对象/节点在对应面板里打开
7. keys(obj) / values(obj) —— 取对象的键 / 值
8. copy(obj) —— 把结果复制到剪贴板，直接粘给后端或同事
```

```text
输出与计时技巧：
1. console.time('label') / console.timeEnd('label') —— 打印区间耗时
2. console.timeLog('label') —— 中间打点，不结束计时
3. console.count('label') —— 统计调用次数，查「这函数到底执行了几次」
4. console.trace() —— 打印当前调用堆栈
5. console.assert(cond, msg) —— 条件为假才报错
6. console.group / console.groupEnd —— 折叠分组，理清海量日志
7. console.dir(obj) —— 以对象树展示 DOM 节点的属性（而非 HTML 结构）
8. %c —— 给日志加 CSS 样式，做醒目标记
9. console.table(arr) —— 数组对象表格化，支持按列排序
```

```text
断点式调试（Console 侧）：
1. monitor(fn) —— 每次调用该函数都打印入参
2. unmonitor(fn) —— 取消 monitor
3. debug(fn) —— 调用该函数时自动进入断点，等价于在 Sources 里设断点
4. undebug(fn) —— 取消 debug
5. Live Expressions —— 眼睛图标，把表达式常驻显示在 Console 顶部并实时刷新
```

### 选型：Console vs Sources vs Network

```text
选型速查：
1. 快速验证一段逻辑 / 看个返回值 → Console
2. 单步跟踪、看变量作用域、条件断点 → Sources 断点
3. 看请求失败原因 / 响应内容 → Network
4. 让某个函数「一调用就停」 → Console 里 debug(fn)
5. 盯着某变量的实时变化 → Live Expressions
```

### 性能与兼容性注意

```text
Console 的注意点：
1. 大量日志拖慢页面 —— 循环里 console.log 会显著拖慢执行，上线前移除或降级
2. 生产环境 log 泄露 —— 日志可能带 token/用户数据，构建时移除
3. 对象惰性展开 —— 打印引用类型，展开时才求值，看到的是「现在」的值
4. 保留日志 —— 勾选 Preserve log 才能跨刷新保留，默认刷新即清
```

## 应用场景实战

### 场景一：调试一个未捕获的异常

```text
步骤：
1. Console 里看到红色 Uncaught Error，记下错误信息
2. 点堆栈最上面的帧，跳到 Sources 里出错的那一行
3. 在该行设断点，刷新复现，观察变量值
4. 需要看调用链时，点 Console 里堆栈的下一帧逐步回溯
5. 修复后确认 Console 无新错误，再继续
```

### 场景二：用 Console 快速验证一段逻辑

```js
// 不确定数组去重写法是否正确，直接在 Console 试
const arr = [1, 2, 2, 3, 3, 3];
[...new Set(arr)];      // [1, 2, 3]

// 验证一个 API 的返回结构
await fetch('/api/user').then(r => r.json());
// 直接看到返回对象，不用写临时文件

// 测一个日期计算
new Date('2026-08-13').getDay(); // 4（星期四）
```

## 最佳实践与踩坑记录

### 最佳实践

1. 用 console.table 展示数组对象，比 console.log 直观得多
2. 打日志带上上下文标识（如 `[UserModule]`），方便过滤
3. 调试完删掉临时 console.log，交给 lint 的 no-console 规则兜底
4. 善用 `$0`/`$`/`$$` 快捷引用，少写重复的 querySelector
5. 异步错误用 await 或 .catch 捕获，别让 rejection 静默丢失

### 踩坑记录

```text
坑 1：console.log 打印对象看到的是「当时快照」
结论：打印对象后修改它，展开时看到的是修改后的值。
原因：浏览器对对象是惰性展开，展示的是引用当前状态。
解法：用 console.log(JSON.stringify(obj)) 或 console.table 打印快照。

坑 2：try/catch 把错误吞了，Console 一片干净
结论：功能坏了但 Console 无报错，难以定位。
原因：catch 块里没做任何处理，异常被静默吞掉。
解法：catch 里至少 console.error(err)，或抛给上层统一处理。

坑 3：忽略 warning，最终踩到弃用 API
结论：某 API 一直警告，某天浏览器升级后直接报错。
原因：警告期没迁移，浏览器移除该 API 后从「警告」变「错误」。
解法：看到 Deprecation 警告就排期迁移，别拖到不可用。

坑 4：混淆「Console 上下文」与「页面模块作用域」
结论：想访问某变量但提示 is not defined。
原因：模块/闭包内的私有变量不在全局，Console 访问不到。
解法：把要调试的变量临时挂到 window 上，或断点进入对应作用域。

坑 5：生产环境残留 console.log
结论：日志泄露内部数据，且拖慢页面。
原因：开发期日志没清理就上线。
解法：构建时用插件移除，配合 eslint no-console 约束。

坑 6：在循环里打 console.log 定位，结果把页面卡死
结论：加日志后页面明显变慢，甚至假死。
原因：高频循环里每次迭代都格式化并输出日志，I/O 开销巨大。
解法：用 console.count 统计次数，或只在命中条件时打一次，调试完立即删除。
```

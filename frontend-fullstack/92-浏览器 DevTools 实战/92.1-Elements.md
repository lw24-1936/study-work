## 概述

Elements（元素）面板是 DevTools 里最常用的面板，用来实时查看和编辑页面的 DOM 树与 CSS 样式。它不展示「源码」，而是展示浏览器实际解析、计算后的「当前 DOM 与样式」，因此是排查布局、样式、结构问题的第一现场。

```text
Elements 面板能做什么：
1. 查看 —— 实时 DOM 树与每个节点的盒模型、计算样式
2. 编辑 —— 直接改属性、改样式，改动即时生效（仅内存，刷新即还原）
3. 定位 —— 右键节点可滚动到视口、聚焦、审查子节点
4. 诊断 —— 用 Computed 面板看「最终生效」的样式来源
```

```html
<!-- 页面源码与 DOM 树并不等同 -->
<div id="app"></div>
<script>
  // 运行时向 DOM 插入节点，源码里看不到，但 Elements 能看到
  const p = document.createElement('p');
  p.textContent = 'runtime added';
  document.getElementById('app').appendChild(p);
</script>
```

## DOM

DOM（文档对象模型）是浏览器把 HTML 解析后建立的树形结构，Elements 面板展示的就是这棵树。通过它可以查看节点层级、属性、事件监听器，以及「源码」与「运行时 DOM」的差异。

```js
// 在 Console 里操作 DOM，Elements 面板会实时同步
const el = document.querySelector('#app');
el.setAttribute('data-x', '1');     // 属性会出现在面板里
console.log(el.innerHTML);          // 查看运行时 HTML
```

```text
DOM 面板的要点：
1. 实时性 —— DOM 由 JS 动态改变，面板永远显示当前状态
2. 事件监听器 —— 选中节点右侧可看绑定的 listeners 及其来源文件
3. 断点 —— 对节点设置「子树修改/属性修改/节点移除」断点，捕获谁改的 DOM
4. 与源码不同 —— 源码是静态文本，DOM 是解析 + JS 执行后的产物
```

## CSS

Elements 面板的 Styles 栏是调试 CSS 的核心工具：显示某个元素「命中了哪些规则」，每条规则来自哪个文件哪一行，谁覆盖了谁；Computed 栏则给出最终生效的每一个属性值。

```css
/* 两条规则竞争同一个属性，Styles 栏会画出覆盖关系 */
.box { color: red; }
.box { color: blue; } /* 后者胜出，Styles 里红字被划掉 */
```

```text
CSS 调试的要点：
1. 覆盖划线 —— 被更高优先级/更靠后规则覆盖的声明会显示删除线
2. 伪类强制 —— 可强制 :hover/:focus/:visited 状态，方便调交互样式
3. 实时编辑 —— 点任意值可改，改颜色有取色器，改数值可用方向键微调
4. Computed —— 展开某项能看到「这个值最终来自哪条规则」
```

## Layout

Layout 是盒模型与定位的可视化：选中元素后，Styles 栏下方或 Computed 栏会显示 content/padding/border/margin 的四层盒模型，鼠标悬停还能在页面上高亮对应区域。它是排查「元素为什么出现在这里」「宽高为什么不对」的第一工具。

```css
/* 盒模型的四层 */
.box {
  width: 100px;      /* content 内容区 */
  padding: 10px;     /* 内边距 */
  border: 2px;       /* 边框 */
  margin: 20px;      /* 外边距 */
}
/* 元素总占位宽度 = 100 + 10*2 + 2*2 + 20*2 */
```

```text
Layout 排查要点：
1. 盒模型 —— 悬停高亮四层，快速确认是谁撑大了元素
2. 定位 —— 看 position/float/flex/grid 的实际计算值
3. 溢出 —— 内容超出容器时，判断是 overflow 还是尺寸计算错误
4. 单位换算 —— Computed 把 rem/%/vw 都换算成最终 px
```

## Accessibility

Accessibility（无障碍）是 Elements 面板里的一个子面板，用来查看页面的无障碍树（Accessibility Tree）——它是屏幕阅读器等辅助技术实际「读到」的结构，与 DOM 树不同，它只保留有语义、可被朗读的部分。

```html
<!-- 无障碍树会把这些元素按语义组织 -->
<button aria-label="关闭弹窗">
  <svg><path d="..."/></svg>
</button>
<!-- 无障碍树看到的是：按钮，名字 "关闭弹窗"，而非 svg/path -->
```

```text
Accessibility 面板的要点：
1. 无障碍树 —— 与 DOM 树分离，只含语义节点与可访问名称
2. 可访问名称 —— 来自文本、aria-label、title 等，按优先级计算
3. 对比度 —— 相邻的 Lighthouse 或颜色面板可查文本对比度是否达标
4. 角色检查 —— 确认按钮是 button 角色、链接是 link 角色，别被误读
```

## 进阶技巧与选型

### 快捷键与隐藏功能

```text
高频快捷键与操作：
1. Ctrl+F —— 在 DOM 树里搜索，支持 CSS 选择器（如 .box、#app div）
2. H 键 —— 快速隐藏/显示选中节点，排查「这个元素到底占不占位」
3. Delete —— 删除选中节点（仅内存，刷新还原）
4. 双击属性/文本 —— 直接编辑，Esc 取消，Enter 提交
5. 方向键 —— 选中数值后上下键微调 1，Shift+方向键微调 10
6. 右键节点 → Break on —— subtree/attribute/node removal 三种 DOM 断点
```

```text
右键 Copy 菜单的实用项：
1. Copy selector —— 生成最短可复用的 CSS 选择器
2. Copy JS path —— 生成 document.querySelector 路径，直接粘到 Console
3. Copy element —— 复制完整 outerHTML
4. Copy styles —— 复制该元素命中规则的源码片段
5. Copy XPath —— 生成 XPath，供自动化测试/爬虫使用
```

```text
样式编辑的隐藏能力：
1. 颜色值点色块 —— 打开取色器，可在页面上任意位置取色
2. 阴影 —— 点 box-shadow 值旁图标，打开阴影可视化编辑器
3. 缓动曲线 —— 点 transition/animation 的 cubic-bezier 图标，可视化调曲线
4. 单位切换 —— 长度值上右键可切换 px/em/rem/vw 等单位
```

### 选型：什么时候用哪个面板

```text
面板选型速查：
1. 看「当前 DOM 结构 / 实时样式」 → Elements
2. 看「源码长什么样、断点调试 JS」 → Sources
3. 看「样式为什么卡、重排重绘」 → Performance（Layout/Paint 阶段）
4. 看「无障碍树 / 对比度」 → Elements 的 Accessibility 子面板
5. 看「某条请求与 DOM 的关联」 → Network 的 Initiator
```

### 性能与兼容性注意

```text
Elements 面板自身的注意点：
1. 巨型 DOM —— 上万节点时 Elements 面板会明显卡顿，优先用 Console 的 $$ 或 JS 过滤
2. user agent shadow DOM —— 原生控件（input/video）内部结构默认隐藏，需在设置里勾选 Show user agent shadow DOM
3. :visited 隐私限制 —— 浏览器对 :visited 只允许改颜色，样式面板查不到真实 visited 状态
4. 强制状态是「叠加」的 —— 同时勾 :hover 和 :focus 才能看到组合态，单一状态会漏掉交互 bug
```

## 应用场景实战

### 场景一：定位「样式没生效」的问题

```text
排查套路：
1. 选中元素，看 Styles 栏有没有出现你的规则
2. 没出现 → 选择器没命中，检查类名/结构，或看是不是被框架重写了
3. 出现了但被划掉 → 优先级不够，看是谁覆盖的（Computed 里查来源）
4. 命中且没划掉 → 看 Computed 最终值，确认是否被浏览器默认样式影响
5. 都正常还不生效 → 检查是不是 CSS 没加载、或 :hover 等状态问题
```

### 场景二：找出「谁改了这段 DOM」

```js
// 用 DOM 断点捕获运行时修改
// 操作：Elements 里右键节点 → Break on → subtree modifications
// 触发：当有脚本修改该节点子树时，DevTools 会停在对应 JS 处

// 配合 Console 也可以手动监听
const target = document.querySelector('#app');
new MutationObserver(() => {
  debugger; // 任何子节点变化都会暂停到这里
}).observe(target, { childList: true, subtree: true });
```

## 最佳实践与踩坑记录

### 最佳实践

1. 先看 Computed 再看 Styles，最终生效值才是真相
2. 用「强制伪类状态」调试 :hover，别靠鼠标反复悬停
3. 改动在面板里即时生效，但确定后记得同步回源码，否则刷新就丢
4. 用 DOM 断点而非「加 console.log」定位谁改了节点
5. 无障碍问题在面板里查无障碍树，别只看 DOM 结构

### 踩坑记录

```text
坑 1：以为改的是源码，刷新后改动消失
结论：在 Elements 里改了半天，刷新全没了。
原因：面板改的是内存中的 DOM 与样式，不写回源文件。
解法：把确定的修改同步到源码，或用 Sources 面板的本地覆盖。

坑 2：样式命中却被划掉，误以为没生效
结论：看到规则出现但样式没应用，以为是 bug。
原因：被更高优先级规则覆盖，Styles 里其实有删除线提示。
解法：看 Computed 面板，找到最终胜出的规则来源。

坑 3：class 名带特殊字符，选择器没命中
结论：用了 col-span-1/2 这类带斜杠的类名，查询时出错。
原因：CSS 选择器里 / 等字符需要转义。
解法：querySelector 里用 CSS.escape() 转义特殊字符。

坑 4：把 DOM 树当成了源码
结论：以为页面显示的结构就是 HTML 文件里的结构。
原因：DOM 是解析 + JS 动态操作后的结果，与源码不同。
解法：看原始源码用 Sources 面板，看运行结果用 Elements。

坑 5：忽视无障碍树，只关注视觉结构
结论：视觉上正常的按钮，读屏软件读不出名字。
原因：只有图标没有文本/aria-label，可访问名称为空。
解法：补 aria-label 或 sr-only 文本，并在 Accessibility 面板验证。

坑 6：只在面板验证了 :hover，真机上 :focus/:active 态没测
结论：桌面 hover 样式正常，移动端或键盘操作下交互态缺失、样式错乱。
原因：强制伪类一次只模拟单一状态，真实交互常是组合态（hover+focus、focus+active），移动端还没有 hover。
解法：分别强制各状态并叠加勾选验证组合态；移动端重点测 :active 与 :focus。
```

## 概述

Theme 是一组 Design Token 的集合，通过切换变量集合在同一套组件上实现不同外观。常见的主题维度有明暗模式、高对比度、品牌换肤等。核心思路是**组件只引用语义变量，主题只负责替换变量值**。

```text
主题机制的三层结构：
1. 语义变量层 —— 组件引用的接口（--color-bg、--color-text）
2. 主题定义层 —— 每个主题给语义变量赋值（light/dark 各一套）
3. 切换层 —— 通过 class 或 data 属性选择当前生效的主题
```

```css
/* 组件只依赖语义变量，不关心当前主题 */
.button {
  background: var(--color-primary);
  color: var(--color-text-on-primary);
}
```

## Light 与 Dark

明暗主题是最高频的主题场景，通过根节点的 data-theme 属性或 class 切换变量定义。

```css
:root, [data-theme='light'] {
  --color-bg: #ffffff;
  --color-text: #1f2937;
  --color-primary: #2563eb;
}

[data-theme='dark'] {
  --color-bg: #111827;
  --color-text: #f3f4f6;
  --color-primary: #60a5fa;
}
```

```js
// 切换主题：设置根节点 data-theme 属性即可
function setTheme(theme) {
  document.documentElement.setAttribute('data-theme', theme);
  localStorage.setItem('theme', theme);
}

// 初始加载：优先跟随系统，其次读本地偏好
const saved = localStorage.getItem('theme');
const preferred = saved || (matchMedia('(prefers-color-scheme: dark)').matches ? 'dark' : 'light');
setTheme(preferred);
```

```css
/* 纯 CSS 跟随系统：免 JS */
@media (prefers-color-scheme: dark) {
  :root:not([data-theme='light']) {
    --color-bg: #111827;
    --color-text: #f3f4f6;
  }
}
```

## High Contrast

高对比度主题为弱视用户提升前景/背景对比度，通常满足 WCAG AAA 级别（正文对比度 7:1 以上）。实现上仍是换一套变量值。

```css
[data-theme='high-contrast'] {
  --color-bg: #000000;
  --color-text: #ffffff;
  --color-primary: #ffff00;
  --color-border: #ffffff;
  --border-width: 2px;         /* 加粗边框强化边界 */
}
```

```css
/* 跟随系统高对比度偏好（Windows 高对比模式） */
@media (prefers-contrast: more) {
  :root {
    --color-text: #000;
    --color-bg: #fff;
    --border-width: 2px;
  }
}
```

## Brand Theme

Brand Theme 是品牌换肤：同一套组件，通过换品牌色、字体、Logo 等 Token 值呈现不同品牌外观，常见于 SaaS 多租户白标场景。

```css
/* 默认品牌 */
[data-brand='default'] {
  --color-primary: #2563eb;
  --font-family: 'PingFang SC', sans-serif;
}

/* 租户 A 品牌 */
[data-brand='tenant-a'] {
  --color-primary: #16a34a;
  --font-family: 'Tenant A Font', sans-serif;
}

/* 租户 B 品牌 */
[data-brand='tenant-b'] {
  --color-primary: #dc2626;
  --font-family: 'Tenant B Font', sans-serif;
}
```

```js
// 运行时按租户注入品牌变量
function applyBrand(brand) {
  const tokens = { 'tenant-a': { primary: '#16a34a' }, 'tenant-b': { primary: '#dc2626' } };
  const { primary } = tokens[brand] ?? {};
  if (primary) document.documentElement.style.setProperty('--color-primary', primary);
}
```

## Runtime Theme

Runtime Theme 是运行时动态生成/覆盖主题，不依赖预先写死的 CSS 文件，适合用户自定义主题色、动态品牌色等场景。

```js
// 运行时覆盖单个变量：用户自定义主题色
function setPrimaryColor(hex) {
  document.documentElement.style.setProperty('--color-primary', hex);
}

// 运行时批量应用一套主题（从接口返回的 Token 配置）
function applyRuntimeTheme(tokens) {
  const root = document.documentElement.style;
  Object.entries(tokens).forEach(([key, value]) => {
    root.setProperty(`--${key}`, value);
  });
}
```

```js
// 基于主色动态派生 hover/disabled 色（用 color-mix 计算）
function deriveTheme(primary) {
  const root = document.documentElement.style;
  root.setProperty('--color-primary', primary);
  root.setProperty('--color-primary-hover', `color-mix(in srgb, ${primary} 85%, black)`);
  root.setProperty('--color-primary-disabled', `color-mix(in srgb, ${primary} 40%, white)`);
}
```

## CSS Variables

CSS 变量（自定义属性）是主题机制的技术基石：作用域可继承、可被内联覆盖、可运行时读取与修改。

```css
/* 变量作用域：定义在 :root 全局可用，定义在 .card 仅卡片内可用 */
:root { --color-primary: #2563eb; }
.card { --card-padding: 16px; padding: var(--card-padding); }
```

```js
// 读取变量（含继承后的计算值）
getComputedStyle(document.documentElement).getPropertyValue('--color-primary');

// 读取变量原始字符串
document.documentElement.style.getPropertyValue('--color-primary');
```

```css
/* 变量可带 fallback，可参与计算 */
.button { color: var(--color-text-on-primary, #fff); }
.card { padding: calc(var(--space-4, 16px) * 2); }
```

## 应用场景实战

### 场景一：明暗主题 + 跟随系统 + 本地持久化

```html
<button id="toggle">切换主题</button>
<script>
  const root = document.documentElement;

  function apply(theme) {
    root.setAttribute('data-theme', theme);
    localStorage.setItem('theme', theme);
  }

  // 初始化：本地偏好 > 系统偏好
  const saved = localStorage.getItem('theme');
  apply(saved || (matchMedia('(prefers-color-scheme: dark)').matches ? 'dark' : 'light'));

  document.getElementById('toggle').onclick = () => {
    const next = root.getAttribute('data-theme') === 'dark' ? 'light' : 'dark';
    apply(next);
  };
</script>
```

```css
:root, [data-theme='light'] { --color-bg: #fff; --color-text: #111; }
[data-theme='dark'] { --color-bg: #111; --color-text: #fff; }
body { background: var(--color-bg); color: var(--color-text); }
```

### 场景二：多租户白标换肤

```js
// 从接口拉取租户主题 Token，运行时注入
async function loadTenantTheme(tenantId) {
  const tokens = await fetch(`/api/theme/${tenantId}`).then(r => r.json());
  const root = document.documentElement.style;
  tokens.forEach(({ name, value }) => root.setProperty(`--${name}`, value));
}

loadTenantTheme('tenant-a');
```

## 最佳实践与踩坑记录

### 最佳实践

1. 组件只引用语义变量，主题只替换变量值，二者解耦
2. 深色主题不要简单反色，需单独设计（阴影、层级、对比度都要重调）
3. 主题切换用 data-theme 属性而非 class，语义更清晰
4. 持久化主题偏好，并处理系统偏好变化（监听 change 事件）
5. 提供 prefers-reduced-motion / prefers-contrast 的无障碍主题支持

### 踩坑记录

```text
坑 1：深色主题直接反色
结论：深色模式里阴影看不见、层级关系丢失。
原因：把 --color-bg 和 --color-text 简单对调，阴影还是黑色投影。
解法：深色主题单独设计，投影改为更高透明度或加亮边框区分层级。

坑 2：切换主题时出现闪烁（FOUC）
结论：页面先闪一下浅色再变深色。
原因：主题判断脚本放在 DOM 之后执行，首帧渲染用了默认主题。
解法：在 head 内联一段脚本，DOM 渲染前就设置 data-theme。

坑 3：第三方组件颜色不跟随主题
结论：引入的 UI 库组件仍显示默认主题色。
原因：组件库内部有独立主题机制，不吃你的 CSS 变量。
解法：用组件库提供的主题定制入口（如 ConfigProvider），或注入其约定的 CSS 变量。

坑 4：内联 style 覆盖了主题变量
结论：动态改 --color-primary 不生效。
原因：之前用 style.setProperty 直接内联写死了值，优先级高于 data-theme 里的定义。
解法：运行时主题统一走一套写入路径，避免内联与主题文件两处写同一变量。

坑 5：忽略系统主题变化
结论：用户切换系统深色模式，页面不跟随。
原因：只读了一次 prefers-color-scheme，没有监听变化。
解法：matchMedia(...).addEventListener('change', ...) 实时响应。
```

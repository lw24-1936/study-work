## 概述

Electron 工程化覆盖从打包、签名到自动更新的完整发布链路。核心工具是 electron-builder（或 electron-forge），配合平台签名与更新服务。

```text
工程化链路：
1. Packaging —— 打包为各平台安装包
2. Code Signing —— 签名，保证可信与通过系统校验
3. Auto Update —— 自动下载并安装新版本
4. Native Module —— 原生模块的编译与集成
```

```json
// package.json 关键字段
{
  "name": "my-app",
  "version": "1.0.0",
  "main": "main.js",
  "scripts": {
    "build": "electron-builder",
    "dist": "electron-builder --publish always"
  }
}
```

## Auto Update

自动更新让应用能静默获取并应用新版本，是桌面应用分发的重要能力。

```text
更新方案：
1. electron-updater —— 配合 electron-builder，最常用
2. 更新源 —— GitHub Releases、S3、自建服务器
3. 流程 —— 检查 → 下载 → 校验 → 安装 → 重启
```

```js
// 主进程集成自动更新
const { autoUpdater } = require('electron-updater');
const { dialog } = require('electron');

function setupAutoUpdate() {
  // 检查更新
  autoUpdater.checkForUpdatesAndNotify();

  autoUpdater.on('update-available', (info) => {
    console.log('发现新版本', info.version);
  });

  autoUpdater.on('update-downloaded', (info) => {
    // 下载完成，提示用户重启安装
    dialog.showMessageBox({
      message: `新版本 ${info.version} 已就绪，是否立即重启？`,
      buttons: ['立即重启', '稍后'],
    }).then(({ response }) => {
      if (response === 0) autoUpdater.quitAndInstall();
    });
  });

  autoUpdater.on('error', (err) => {
    console.error('更新失败', err);
  });
}

app.whenReady().then(() => {
  setupAutoUpdate();
});
```

```text
更新配置（electron-builder）：
publish:
  provider: github
  owner: yourname
  repo: my-app
```

## Packaging

打包将应用编译为各平台的可分发安装包。

```text
打包工具与产物：
1. electron-builder —— 配置简单，社区主流
2. electron-forge —— 官方维护，插件化
3. 产物 —— Windows（NSIS/msi）、macOS（dmg/zip）、Linux（AppImage/deb）
```

```yaml
# electron-builder.yml
appId: com.example.myapp
productName: MyApp
directories:
  output: dist
files:
  - "**/*"
mac:
  target:
    - dmg
  category: public.app-category.productivity
win:
  target:
    - nsis
linux:
  target:
    - AppImage
  category: Utility
```

```text
打包要点：
1. 体积优化 —— 排除无用依赖，压缩 asar
2. asar 打包 —— 源码打包进 asar 归档
3. 多平台 —— 通常需在对应平台或 CI 上构建
```

## Code Signing

代码签名让安装包通过系统信任校验，避免「未知开发者」警告。

```text
签名作用：
1. 身份可信 —— 证明软件来源
2. 完整性 —— 防篡改
3. 系统要求 —— macOS 公证、Windows SmartScreen
```

```text
macOS 签名与公证：
1. Developer ID 证书签名
2. notarize（公证）—— 提交 Apple 审核
3. 未签名 —— 用户需手动绕过 Gatekeeper
```

```yaml
# electron-builder.yml 签名配置
mac:
  identity: "Developer ID Application: Your Name (TEAMID)"
  hardenedRuntime: true
  gatekeeperAssess: false
  notarize:
    teamId: TEAMID
```

```text
Windows 签名：
1. 代码签名证书（OV/EV）
2. EV 证书获得 SmartScreen 即时信誉
3. 通过 signTool 或 electron-builder 配置
```

## Native Module

Native Module 是编译到原生代码的 Node 模块，打包时需针对 Electron 重新编译。

```text
原生模块特点：
1. C/C++ 编写（如 better-sqlite3、sharp）
2. 与 Node ABI 绑定，Electron 与 Node ABI 不同
3. 需 electron-rebuild 重新编译
4. 需区分运行时（Electron 而非 Node）
```

```bash
# 安装并重建原生模块
npm install better-sqlite3
npx electron-rebuild -f -w better-sqlite3
```

```json
// package.json 配置 postinstall
{
  "scripts": {
    "postinstall": "electron-builder install-app-deps"
  }
}
```

```text
注意事项：
1. 原生模块需为 Electron 目标版本编译
2. CI 中确保 electron-rebuild 执行
3. 优先选纯 JS 替代方案，减少维护成本
4. 也可用 N-API 编写，实现跨运行时兼容
```

## 应用场景实战

### 场景一：完整的发布配置

```yaml
# electron-builder.yml
appId: com.example.notes
productName: Notes
files:
  - "main.js"
  - "preload.js"
  - "dist/**"
publish:
  provider: github
  owner: yourname
  repo: notes

  target: [dmg, zip]
  hardenedRuntime: true
win:
  target: [nsis]

  oneClick: false
```

## 最佳实践与踩坑记录

### 最佳实践

1. 用 electron-builder 统一打包配置，脚本化发布
2. macOS 必须签名 + 公证，否则用户无法正常安装
3. 原生模块用 electron-rebuild 针对 Electron 重编译
4. 自动更新要处理「下载失败」「用户拒绝」等分支
5. 版本号严格遵循 SemVer，更新源与版本对应

### 踩坑记录

```text
坑 1：原生模块打包后运行报错
结论：开发正常，打包后 require 报 NODE_MODULE_VERSION 不匹配。
原因：模块按 Node ABI 编译，Electron ABI 不同。
解法：electron-rebuild 或 install-app-deps 重编译。

坑 2：macOS 提示「已损坏无法打开」
结论：用户下载 dmg 后无法打开。
原因：未签名/未公证，被 Gatekeeper 拦截。
解法：配置签名证书并做 notarize 公证。

坑 3：自动更新不触发
结论：checkForUpdates 无反应。
原因：publish 配置缺失，或版本号未递增。
解法：配置更新源，确认新版本号大于当前版本。

坑 4：打包体积过大
结论：安装包几百 MB。
原因：依赖未精简，devDependencies 被打进产物。
解法：依赖分类，排除 dev 依赖，用 asar 压缩。

坑 5：路径在打包后失效
结论：读取静态资源 404 或文件不存在。
原因：开发路径与 asar 内路径不一致。
解法：用 app.getAppPath()/process.resourcesPath 定位资源。
```

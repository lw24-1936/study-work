## 概述

音视频播放涉及三个层次：底层 HTMLMediaElement 提供统一的播放接口；中间层 Video Controls、Subtitle、Track 负责交互与字幕；顶层 HLS/DASH 协议实现流式与自适应码率播放。

```text
播放技术栈：
1. HTMLMediaElement —— 播放的核心对象（audio/video 的共同基类）
2. Video Controls —— 原生/自定义控制条
3. Subtitle + Track —— 字幕与文本轨道
4. HLS / DASH —— 流媒体协议，切片 + 自适应码率
```

## HTMLMediaElement

HTMLMediaElement 是 Audio 与 Video 共同的接口，统一了加载、播放、状态查询的能力。

```text
核心状态属性：
1. readyState —— 0~4，4 表示 HAVE_ENOUGH_DATA 可流畅播放
2. networkState —— 网络加载状态
3. buffered —— 已缓冲时间区间
4. seeking —— 是否正在 seek
5. paused / ended —— 播放状态
```

```js
const video = document.querySelector('video');

// 加载状态
video.addEventListener('loadedmetadata', () => console.log(video.duration));
video.addEventListener('canplay', () => console.log('可以播放'));
video.addEventListener('waiting', () => console.log('缓冲中'));
video.addEventListener('playing', () => console.log('开始播放'));
video.addEventListener('seeking', () => console.log('跳转中'));
video.addEventListener('seeked', () => console.log('跳转完成'));
```

```js
// 关键方法与属性
video.playbackRate = 1.25;        // 倍速
video.currentTime = 120;          // 跳转
video.volume = 0.8;
video.muted = false;

// 缓冲区间（TimeRanges）
for (let i = 0; i < video.buffered.length; i++) {
  console.log(video.buffered.start(i), video.buffered.end(i));
}
```

## Video Controls

视频控制条提供播放/暂停、进度、音量、全屏等交互。原生 controls 属性开箱即用，复杂需求需自定义控制条。

```html
<!-- 原生控制条 -->
<video controls></video>
```

```js
// 自定义控制条：进度条
const playBtn = document.querySelector('.play-btn');
const progress = document.querySelector('.progress');
const video = document.querySelector('video');

playBtn.addEventListener('click', () => {
  if (video.paused) {
    video.play();
    playBtn.textContent = '暂停';
  } else {
    video.pause();
    playBtn.textContent = '播放';
  }
});

video.addEventListener('timeupdate', () => {
  const percent = (video.currentTime / video.duration) * 100;
  progress.style.width = `${percent}%`;
});

// 点击进度条跳转
document.querySelector('.progress-bar').addEventListener('click', (e) => {
  const rect = e.currentTarget.getBoundingClientRect();
  const ratio = (e.clientX - rect.left) / rect.width;
  video.currentTime = ratio * video.duration;
});
```

```js
// 全屏控制
const fullscreenBtn = document.querySelector('.fullscreen');
fullscreenBtn.addEventListener('click', () => {
  if (document.fullscreenElement) {
    document.exitFullscreen();
  } else {
    video.requestFullscreen();
  }
});
```

## Subtitle

字幕通过 <track> 元素挂载，支持 WebVTT 格式。可为同一视频提供多语言字幕，按用户选择切换。

```html
<video controls>
  <source src="movie.mp4" type="video/mp4" />
  <track kind="subtitles" src="subs-zh.vtt" srclang="zh" label="中文" default />
  <track kind="subtitles" src="subs-en.vtt" srclang="en" label="English" />
</video>
```

```text
WebVTT 字幕文件格式（.vtt）：
WEBVTT

00:00:01.000 --> 00:00:04.000
第一句字幕

00:00:05.000 --> 00:00:08.000
第二句字幕
```

```js
// 动态切换字幕轨道
const tracks = video.textTracks;
for (let i = 0; i < tracks.length; i++) {
  tracks[i].mode = tracks[i].language === 'zh' ? 'showing' : 'hidden';
}
```

## Track

Track（文本轨道）不只用于字幕，还支持字幕、标题、章节、描述、元数据等多种类型，由 kind 属性区分。

```text
Track 的 kind 类型：
1. subtitles —— 字幕（翻译对话）
2. captions —— 说明文字（含音效，服务于听障）
3. descriptions —— 画面描述（服务于视障）
4. chapters —— 章节（视频分段导航）
5. metadata —— 元数据（JS 使用，不显示）
```

```html
<video controls>
  <track kind="captions" src="captions.vtt" srclang="zh" label="说明" />
  <track kind="chapters" src="chapters.vtt" srclang="zh" />
  <track kind="metadata" src="data.vtt" />
</video>
```

```js
// 读取 chapter 轨道实现分段跳转
const chapterTrack = [...video.textTracks].find((t) => t.kind === 'chapters');
chapterTrack.addEventListener('cuechange', () => {
  const cue = chapterTrack.activeCues?.[0];
  if (cue) console.log('当前章节：', cue.text);
});
```

## HLS

HLS（HTTP Live Streaming）是 Apple 提出的流媒体协议，将视频切成多段小 TS/fMP4 文件，通过 m3u8 清单索引。支持自适应码率（多码率切换）。

```text
HLS 工作原理：
1. 视频被切成若干秒一个的小分片
2. .m3u8 清单列出所有分片地址与码率
3. 播放器按网络状况动态切换码率
4. 基于 HTTP，CDN 友好，无需专用服务器
```

```text
# master.m3u8（多码率清单）
#EXTM3U
#EXT-X-STREAM-INF:BANDWIDTH=800000,RESOLUTION=640x360
low/index.m3u8
#EXT-X-STREAM-INF:BANDWIDTH=2800000,RESOLUTION=1280x720
high/index.m3u8
```

```js
// 用 hls.js 在 MSE 上播放 HLS
import Hls from 'hls.js';

const video = document.querySelector('video');
if (Hls.isSupported()) {
  const hls = new Hls();
  hls.loadSource('https://example.com/stream.m3u8');
  hls.attachMedia(video);
  hls.on(Hls.Events.MANIFEST_PARSED, () => video.play());
} else if (video.canPlayType('application/vnd.apple.mpegurl')) {
  // Safari 原生支持 HLS
  video.src = 'https://example.com/stream.m3u8';
}
```

```text
HLS 特点：
1. 兼容性极好（Safari 原生支持）
2. 延迟较高（传统 HLS 约 6~30 秒，LL-HLS 可到 2~3 秒）
3. 直播与点播通用
```

## DASH

DASH（Dynamic Adaptive Streaming over HTTP）是 MPEG 标准的自适应流媒体协议，基于 MPD 清单，格式中立（不绑定 TS），延迟更低、更灵活。

```text
DASH 工作原理：
1. 媒体描述在 .mpd（Media Presentation Description）清单
2. 分片基于 ISO-BMFF（fMP4），与 MSE 天然契合
3. 按带宽动态切换 Representation（码率档位）
```

```js
// 用 dash.js 播放 DASH
import dashjs from 'dashjs';

const player = dashjs.MediaPlayer().create();
player.initialize(document.querySelector('video'), 'https://example.com/manifest.mpd', true);
```

```text
HLS 与 DASH 对比：
1. 封装：HLS 传统用 TS（现支持 fMP4），DASH 用 fMP4
2. 清单：HLS 用 m3u8，DASH 用 MPD
3. 兼容：HLS 更好（Safari 原生），DASH 依赖 MSE
4. 延迟：DASH 通常更低，HLS 生态更成熟
5. 选择：面向全端优先 HLS，专业低延迟场景考虑 DASH
```

## 应用场景实战

### 场景一：多码率 HLS 播放器

```js
import Hls from 'hls.js';

function initPlayer(url) {
  const video = document.querySelector('video');
  if (Hls.isSupported()) {
    const hls = new Hls({ maxBufferLength: 30 });
    hls.loadSource(url);
    hls.attachMedia(video);
    hls.on(Hls.Events.LEVEL_SWITCHED, (e, data) => {
      console.log('码率档位切换：', data.level);
    });
  } else if (video.canPlayType('application/vnd.apple.mpegurl')) {
    video.src = url;
  }
}
```

### 场景二：带章节导航的课程视频

```js
const video = document.querySelector('video');
const chapterTrack = [...video.textTracks].find((t) => t.kind === 'chapters');

chapterTrack.addEventListener('cuechange', () => {
  const cue = chapterTrack.activeCues?.[0];
  if (cue) document.querySelector('.chapter-title').textContent = cue.text;
});

// 章节列表点击跳转
document.querySelectorAll('.chapter-item').forEach((item) => {
  item.addEventListener('click', () => {
    video.currentTime = Number(item.dataset.time);
    video.play();
  });
});
```

## 最佳实践与踩坑记录

### 最佳实践

1. 用 canPlayType 或 MSE 检测后再选播放方案
2. 视频用 CDN + 分片协议（HLS/DASH）传输，别整文件直传
3. preload="metadata" 平衡首屏与带宽
4. 字幕用 WebVTT，多语言用 track 切换
5. 直播场景优先 HLS（LL-HLS 降低延迟），点播按需选 DASH
6. 自定义控制条要补齐键盘与无障碍支持

### 踩坑记录

```text
坑 1：Safari 播放 m3u8 但 Chrome 不行
结论：直接给 video.src 设 m3u8 只在 Safari 生效。
原因：Chrome 不支持原生 HLS，需要 MSE + hls.js。
解法：用 Hls.isSupported() 分支处理。

坑 2：字幕跨域加载失败
结论：track 字幕不显示。
原因：字幕文件跨域未配 CORS。
解法：字幕资源加 crossOrigin，服务端允许跨域。

坑 3：HLS 卡顿缓冲
结论：播放频繁缓冲、画面停顿。
原因：码率过高或缓冲策略不当。
解法：调整 maxBufferLength，启用自动码率切换。

坑 4：currentTime 设置无效
结论：video.currentTime 赋值后跳转不生效。
原因：视频尚未加载元数据，duration 未知。
解法：在 loadedmetadata 之后设置 currentTime。

坑 5：自定义控制条与原生 controls 冲突
结论：自定义按钮和原生控制条都显示。
原因：未移除 controls 属性。
解法：去掉 controls 属性，纯自定义实现。
```

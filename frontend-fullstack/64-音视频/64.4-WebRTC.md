## 概述

WebRTC 的媒体层负责「采集、控制、传输」三件事：通过 getUserMedia 采集摄像头/麦克风，通过 getDisplayMedia 采集屏幕，通过 Track 管理媒体轨道，通过 Codec/Bitrate/网络自适应保障传输质量。

```text
媒体处理链路：
采集（Camera/Mic/Screen）
→ 轨道（AudioTrack/VideoTrack）
→ 编码（Codec）
→ 码率控制（Bitrate）
→ 网络自适应（Network Adaptation）
→ 传输到对端
```

## Camera

摄像头采集通过 getUserMedia 实现，可指定分辨率、帧率、前后摄像头等约束条件。

```js
// 基础采集
const stream = await navigator.mediaDevices.getUserMedia({ video: true });
video.srcObject = stream;
```

```js
// 精确约束：分辨率与帧率
const stream = await navigator.mediaDevices.getUserMedia({
  video: {
    width: { ideal: 1280 },
    height: { ideal: 720 },
    frameRate: { ideal: 30 },
    facingMode: 'user',          // user 前置 / environment 后置
  },
});
```

```js
// 枚举设备并切换摄像头
const devices = await navigator.mediaDevices.enumerateDevices();
const cameras = devices.filter((d) => d.kind === 'videoinput');
const stream = await navigator.mediaDevices.getUserMedia({
  video: { deviceId: cameras[0].deviceId },
});
```

```text
约束（Constraints）关键点：
1. ideal —— 期望值，尽量满足
2. min/max —— 硬性范围
3. exact —— 精确匹配，不满足则失败
```

## Microphone

麦克风采集同样通过 getUserMedia，支持回声消除、降噪、自动增益等音频处理。

```js
const stream = await navigator.mediaDevices.getUserMedia({
  audio: {
    echoCancellation: true,      // 回声消除
    noiseSuppression: true,      // 降噪
    autoGainControl: true,       // 自动增益
    sampleRate: 48000,
  },
});
```

```js
// 音量检测
const audioCtx = new AudioContext();
const source = audioCtx.createMediaStreamSource(stream);
const analyser = audioCtx.createAnalyser();
source.connect(analyser);

const data = new Uint8Array(analyser.frequencyBinCount);
function checkLevel() {
  analyser.getByteTimeDomainData(data);
  const level = Math.max(...data) - 128;   // 音量峰值
  document.querySelector('.level').style.height = `${level}px`;
  requestAnimationFrame(checkLevel);
}
checkLevel();
```

## Screen Share

屏幕共享通过 getDisplayMedia 实现，可共享整个屏幕、窗口或浏览器标签页。

```js
const displayStream = await navigator.mediaDevices.getDisplayMedia({
  video: { frameRate: 30 },
  audio: true,                   // 可选，共享系统音频
});
previewVideo.srcObject = displayStream;

// 用户点击「停止共享」时触发
displayStream.getVideoTracks()[0].addEventListener('ended', () => {
  console.log('用户停止了共享');
});
```

```text
屏幕共享要点：
1. 必须用户手势触发（安全限制）
2. 需 HTTPS 或 localhost
3. ended 事件监听用户主动停止
```

## Audio Track 与 Video Track

MediaStream 由多条 Track 组成，Track 是媒体控制的最小单位，可独立启停、开关、替换。

```text
Track 类型：
1. MediaStreamAudioTrack —— 音频轨道
2. MediaStreamVideoTrack —— 视频轨道

关键方法：
1. stop() —— 停止轨道（释放设备）
2. enabled —— 开关轨道（不释放，画面冻结）
3. getSettings() —— 读取实际生效的约束
```

```js
const stream = await navigator.mediaDevices.getUserMedia({ video: true, audio: true });
const [videoTrack] = stream.getVideoTracks();
const [audioTrack] = stream.getAudioTracks();

videoTrack.enabled = false;   // 关闭画面（不释放设备）
audioTrack.enabled = false;   // 静音

console.log(videoTrack.getSettings().width);   // 实际分辨率

videoTrack.stop();            // 彻底释放
```

```js
// 动态替换轨道（切换摄像头）
const newStream = await navigator.mediaDevices.getUserMedia({
  video: { deviceId: otherCameraId },
});
const newTrack = newStream.getVideoTracks()[0];
const sender = pc.getSenders().find((s) => s.track?.kind === 'video');
await sender.replaceTrack(newTrack);
```

## Codec

Codec（编解码器）负责音视频的压缩与解压。WebRTC 中双方通过 SDP 协商选择共同支持的编解码器。

```text
常用音频编解码器：
1. Opus —— WebRTC 默认，低延迟、高质量
2. G.711 —— 传统电话语音，兼容性好

常用视频编解码器：
1. VP8 / VP9 —— Google 开源，免费
2. H.264 —— 兼容性最好，硬件加速广泛
3. AV1 —— 新一代，压缩率更高，编码成本高
```

```js
// 查看协商出的实际编解码器
const stats = await pc.getStats();
stats.forEach((r) => {
  if (r.type === 'codec') {
    console.log('编解码器：', r.mimeType, r.clockRate);
  }
});
```

```text
选型建议：
1. 通用通话优先 VP8/VP9 + Opus（免费、稳定）
2. 需要硬件加速/兼容老设备优先 H.264
3. 带宽敏感场景考虑 AV1（需硬件支持）
```

## Bitrate

Bitrate（码率）指单位时间传输的数据量，直接决定音视频质量与带宽占用。码率越高质量越好，但占用带宽越大。

```text
码率参考（视频）：
1. 360p —— 约 500~800 Kbps
2. 720p —— 约 1.5~2.5 Mbps
3. 1080p —— 约 3~5 Mbps

音频：Opus 约 32~128 Kbps
```

```js
// 限制发送码率
const sender = pc.getSenders().find((s) => s.track?.kind === 'video');
const params = sender.getParameters();
if (!params.encodings) params.encodings = [{}];
params.encodings[0].maxBitrate = 1500000;    // 1.5 Mbps
await sender.setParameters(params);
```

## Network Adaptation

网络自适应指根据实时网络状况（丢包、延迟、带宽）动态调整编码参数，保障通话流畅优先于清晰。

```text
自适应策略：
1. 丢包率上升 → 降码率、降分辨率
2. 带宽充足 → 升码率、升分辨率
3. 延迟增大 → 降帧率或码率
4. 抖动增大 → 增加缓冲（jitter buffer）
```

```js
// 基于 getStats 实现简单自适应
async function adaptQuality(pc) {
  const stats = await pc.getStats();
  let packetsLost = 0, packetsSent = 0;
  stats.forEach((r) => {
    if (r.type === 'outbound-rtp' && r.kind === 'video') {
      packetsLost = r.packetsLost || 0;
      packetsSent = r.packetsSent || 0;
    }
  });
  const lossRate = packetsSent ? packetsLost / packetsSent : 0;

  const sender = pc.getSenders().find((s) => s.track?.kind === 'video');
  const params = sender.getParameters();
  params.encodings[0].maxBitrate = lossRate > 0.1
    ? 500000     // 丢包严重 → 500 Kbps
    : 1500000;   // 正常 → 1.5 Mbps
  await sender.setParameters(params);
}
```

## 应用场景实战

### 场景一：带画质切换的视频通话

```js
const qualityMap = {
  low: { width: 320, height: 240, maxBitrate: 300000 },
  high: { width: 1280, height: 720, maxBitrate: 2000000 },
};

async function switchQuality(level) {
  const q = qualityMap[level];
  const sender = pc.getSenders().find((s) => s.track?.kind === 'video');
  const params = sender.getParameters();
  params.encodings[0].maxBitrate = q.maxBitrate;
  await sender.setParameters(params);

  await sender.track.applyConstraints({ width: q.width, height: q.height });
}
```

### 场景二：通话前设备检测

```js
async function deviceCheck() {
  const devices = await navigator.mediaDevices.enumerateDevices();
  const hasCamera = devices.some((d) => d.kind === 'videoinput');
  const hasMic = devices.some((d) => d.kind === 'audioinput');

  if (!hasCamera || !hasMic) {
    alert('请接入摄像头和麦克风');
    return;
  }
  const stream = await navigator.mediaDevices.getUserMedia({ video: true, audio: true });
  const [vt] = stream.getVideoTracks();
  console.log('采集分辨率：', vt.getSettings().width, vt.getSettings().height);
  stream.getTracks().forEach((t) => t.stop());
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. 采集约束用 ideal 而非 exact，避免设备不支持导致失败
2. 通话结束必须 track.stop() 释放设备
3. 切换设备用 replaceTrack，避免重建整个连接
4. 用 maxBitrate 控制上行带宽，保护弱网用户
5. 基于 getStats 的丢包率做自适应降码率
6. 屏幕共享需监听 ended 事件，处理用户主动停止

### 踩坑记录

```text
坑 1：exact 约束导致采集失败
结论：指定 exact 分辨率后 getUserMedia 报 OverconstrainedError。
原因：设备不支持该精确值。
解法：用 ideal 或范围约束，让浏览器就近匹配。

坑 2：切换摄像头后对端无画面
结论：本地替换设备，对端黑屏。
原因：直接改 stream 而非 replaceTrack，连接仍发送旧 track。
解法：用 sender.replaceTrack(newTrack)。

坑 3：getSettings 返回与约束不符
结论：设置 1080p 实际采集 720p。
原因：浏览器根据设备能力就近匹配。
解法：用 getSettings() 读实际值，不要假设。

坑 4：码率设置不生效
结论：setParameters 后码率没变化。
原因：encodings 数组未正确初始化或 maxBitrate 格式错误。
解法：先 getParameters 再改 encodings[0].maxBitrate。

坑 5：屏幕共享无声音
结论：共享画面但没有系统音频。
原因：getDisplayMedia 未设 audio: true，或浏览器限制。
解法：传 audio: true，并注意 Safari 需额外配置。
```

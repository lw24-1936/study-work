## 概述

高级类型是在基础类型之上的「类型编程」能力：条件类型做分支、映射类型做变换、模板字面量类型拼字符串、可辨识联合做穷尽检查。掌握这些才能在复杂业务里写出精确的类型，而不是退回到 any。

```text
高级类型解决的核心问题：
1. 条件类型 —— 类型层面的 if/else，支持分配律
2. 映射类型 —— 批量改写对象键值
3. 模板字面量 —— 基于字符串拼接生成键名/联合
4. 可辨识联合 —— 用 discriminant 收窄联合类型
5. 品牌类型 —— 给基础类型打标，防止混用
```

## 条件类型

条件类型语法是 `T extends U ? X : Y`，配合联合类型会「分配」（每个成员分别判断再合并结果）。

```ts
// 基础条件类型
type IsString<T> = T extends string ? true : false;

type A = IsString<string>;   // true
type B = IsString<number>;   // false
```

```ts
// 分配条件类型：联合的每个成员分别判断
type ToArray<T> = T extends any ? T[] : never;

type Arr = ToArray<string | number>;  // string[] | number[]
```

```ts
// 分配律导致的行为差异（用 [] 包裹可关闭分配）
type Wrapped<T> = [T] extends [any] ? T[] : never;

type Arr2 = Wrapped<string | number>;  // (string | number)[]
```

```ts
// 条件类型 + infer 提取
type Unwrap<T> = T extends Promise<infer U> ? U : T;
```

## 映射类型

映射类型用 `[K in Keys]` 遍历键，批量生成新的对象类型，配合 `+`/`-` 修改修饰符。

```ts
// 基础映射：遍历所有键
type Nullable<T> = { [K in keyof T]: T[K] | null };

interface User {
  id: number;
  name: string;
}

type NullableUser = Nullable<User>;
// { id: number | null; name: string | null }
```

```ts
// 修改修饰符：去掉 readonly 和可选
type Mutable<T> = { -readonly [K in keyof T]-?: T[K] };
```

```ts
// 键重映射（as 子句）：改键名
type Getters<T> = {
  [K in keyof T as `get${Capitalize<string & K>}`]: () => T[K];
};

type UserGetters = Getters<User>;
// { getId: () => number; getName: () => string }
```

## 模板字面量类型

模板字面量类型用 `` `...` `` 在类型层面拼接字符串，常用于生成事件名、Action 类型等。

```ts
type Event = 'click' | 'focus' | 'blur';
type EventName = `on${Capitalize<Event>}`;
// 'onClick' | 'onFocus' | 'onBlur'
```

```ts
// 生成路由路径
type Method = 'get' | 'post';
type Path = '/users' | '/posts';
type Api = `${Method} ${Path}`;
// 'get /users' | 'get /posts' | 'post /users' | 'post /posts'
```

```ts
// 用模板字面量约束对象键
type Prefix = 'data' | 'error';
type LoadingKeys = `${Prefix}Loading`;
// 'dataLoading' | 'errorLoading'
```

## 递归类型

递归类型让类型引用自身，用于描述树、链表、嵌套 JSON 等自相似结构。

```ts
// 递归描述树节点
interface TreeNode {
  value: number;
  children?: TreeNode[];
}

const tree: TreeNode = {
  value: 1,
  children: [
    { value: 2 },
    { value: 3, children: [{ value: 4 }] },
  ],
};
```

```ts
// 递归映射：深层只读
type DeepReadonly<T> = {
  readonly [K in keyof T]: T[K] extends object ? DeepReadonly<T[K]> : T[K];
};

interface Config {
  nested: { value: number };
}
type RO = DeepReadonly<Config>;
// { readonly nested: { readonly value: number } }
```

```ts
// 递归描述嵌套数组
type NestedArray<T> = T | NestedArray<T>[];

const na: NestedArray<number> = [1, [2, [3]]];
```

## 可辨识联合

可辨识联合（Discriminated Union）是带共同判别字段（discriminant）的联合类型，switch/if 判断该字段即可收窄到具体成员。

```ts
type Shape =
  | { kind: 'circle'; radius: number }
  | { kind: 'square'; side: number }
  | { kind: 'rectangle'; width: number; height: number };

function area(shape: Shape): number {
  switch (shape.kind) {
    case 'circle':
      return Math.PI * shape.radius ** 2;
    case 'square':
      return shape.side ** 2;
    case 'rectangle':
      return shape.width * shape.height;
  }
}
```

```ts
// 穷尽检查：加 never 分支，漏写成员时编译报错
function assertNever(x: never): never {
  throw new Error('Unexpected: ' + x);
}

function areaExhaustive(shape: Shape): number {
  switch (shape.kind) {
    case 'circle':
      return Math.PI * shape.radius ** 2;
    case 'square':
      return shape.side ** 2;
    case 'rectangle':
      return shape.width * shape.height;
    default:
      return assertNever(shape);  // 新增成员漏处理会在这里报错
  }
}
```

## 品牌类型

品牌类型（Branded Type）给基础类型附加一个不可见的「牌子」，让同是 string 的两个类型不能混用，防止把用户 ID 传给订单 ID。

```ts
type Brand<T, B extends string> = T & { readonly __brand: B };

type UserId = Brand<string, 'UserId'>;
type OrderId = Brand<string, 'OrderId'>;

function createUserId(id: string): UserId {
  return id as UserId;  // 通过断言显式打标
}

function getOrder(orderId: OrderId): void {}

const uid = createUserId('u-1');
// getOrder(uid);  // 错误：UserId 不能赋给 OrderId
```

```ts
// 运行时校验 + 类型打标组合
function toUserId(raw: string): UserId {
  if (!raw.startsWith('u-')) {
    throw new Error('invalid user id');
  }
  return raw as UserId;
}
```

## 类型守卫

类型守卫（Type Guard）在运行时收窄变量的类型，内置的有 `typeof`、`in`、`instanceof`。

```ts
// typeof 收窄
function pad(value: string | number): string {
  if (typeof value === 'string') {
    return value.padStart(4, '0');
  }
  return value.toString();
}
```

```ts
// in 收窄（判断对象是否含某属性）
type Fish = { swim: () => void };
type Bird = { fly: () => void };

function move(animal: Fish | Bird): void {
  if ('swim' in animal) {
    animal.swim();
  } else {
    animal.fly();
  }
}
```

```ts
// instanceof 收窄
function formatDate(d: Date | string): string {
  if (d instanceof Date) {
    return d.toISOString();
  }
  return new Date(d).toISOString();
}
```

## 自定义类型守卫

自定义类型守卫是返回值为 `x is Type` 的函数，让编译器信任你的运行时判断逻辑。

```ts
interface Admin {
  name: string;
  role: 'admin';
  permissions: string[];
}
interface Guest {
  name: string;
  role: 'guest';
}

type Account = Admin | Guest;

function isAdmin(account: Account): account is Admin {
  return account.role === 'admin';
}

function showPermissions(account: Account): void {
  if (isAdmin(account)) {
    console.log(account.permissions);  // 收窄为 Admin
  }
}
```

```ts
// 守卫数组元素
function isNumber(value: unknown): value is number {
  return typeof value === 'number';
}

const mixed: unknown[] = [1, 'a', 2, 'b'];
const nums = mixed.filter(isNumber);  // number[]
```

## 断言函数

断言函数（Assertion Function）的返回类型是 `asserts condition`，函数正常返回即代表条件成立，否则抛错，编译器据此收窄类型。

```ts
function assert(condition: unknown, message: string): asserts condition {
  if (!condition) {
    throw new Error(message);
  }
}

function greet(input: string | null): void {
  assert(input !== null, 'input is null');
  console.log(input.toUpperCase());  // 收窄为 string
}
```

```ts
// asserts x is Type：直接断言变量是某类型
function assertString(value: unknown): asserts value is string {
  if (typeof value !== 'string') {
    throw new TypeError('not a string');
  }
}

function process(value: unknown): void {
  assertString(value);
  value.toUpperCase();  // 收窄为 string
}
```

## 应用场景实战

### 场景一：Redux 风格的 Action + Reducer（可辨识联合）

```ts
type Action =
  | { type: 'add'; payload: number }
  | { type: 'subtract'; payload: number }
  | { type: 'reset' };

function reducer(state: number, action: Action): number {
  switch (action.type) {
    case 'add':
      return state + action.payload;
    case 'subtract':
      return state - action.payload;
    case 'reset':
      return 0;
  }
}

reducer(5, { type: 'add', payload: 3 });  // 8
```

### 场景二：表单字段的派生类型（模板字面量）

```ts
type Field = 'name' | 'email' | 'password';

type FormState = {
  [K in Field]: string;
} & {
  [K in Field as `${K}Error`]: string | null;
};

const form: FormState = {
  name: '',
  email: '',
  password: '',
  nameError: null,
  emailError: '格式不正确',
  passwordError: null,
};
```

## 最佳实践与踩坑记录

### 最佳实践

1. 用可辨识联合替代「多字段可选」的接口，配合 never 分支做穷尽检查
2. 自定义类型守卫封装复杂判断，让编译器信任运行时逻辑
3. 品牌类型防「基础类型混用」，在 ID 类字段上尤其值得用
4. 映射类型的键重映射（as 子句）可同时生成多个关联字段
5. 递归类型注意递归终止条件，避免无限展开

### 踩坑记录

```text
坑 1：条件类型对裸联合类型分配导致结果意外
结论：ToArray<string | number> 得到 string[] | number[]，不是 (string | number)[]。
原因：裸类型参数在条件类型中会分配，逐个成员判断。
解法：需要整体判断时用方括号包裹，如 [T] extends [any]。

坑 2：可辨识联合的 discriminant 必须用字面量类型
结论：discriminant 声明成 string 时 switch 无法收窄。
原因：非字面量类型无法区分成员。
解法：判别字段用字面量联合，如 kind: 'circle' | 'square'。

坑 3：递归类型没有终止条件导致无限展开
结论：递归类型在复杂结构上可能报「类型实例化过深」。
原因：递归没有 base case 或展开层数超过限制。
解法：给递归加明确的终止分支，控制嵌套深度。

坑 4：断言函数必须在函数末尾抛错
结论：asserts 函数若在条件不满足时不抛错，类型收窄会失效。
原因：断言函数的语义是「正常返回即条件成立」，不抛错编译器仍假设成立。
解法：条件不满足时一定要 throw，否则类型不安全。

坑 5：品牌类型用交叉类型时丢失
结论：把 Brand 类型赋给普通 string 再传回时，品牌信息可能被擦除。
原因：品牌信息只在编译期存在，赋值给宽类型后丢失。
解法：全程保持品牌类型，避免中间用普通 string 中转。
```

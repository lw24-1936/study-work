## 概述

泛型（Generics）让类型成为「参数」，在定义函数、接口、类时先不写死类型，调用时再传入具体类型。它解决的核心问题是「保留类型信息的前提下复用代码」，避免用 `any` 丢失类型安全，也避免为每个类型重复写一份逻辑。

```text
泛型的核心价值：
1. 复用 —— 一份逻辑适用于多种类型
2. 类型安全 —— 保留入参与返回值之间的类型关联
3. 灵活 —— 配合约束、keyof、infer 可表达复杂类型关系
```

```ts
// 不用泛型：只能接受 number，或退回 any 丢失类型
function identityNumber(x: number): number { return x; }

// 用泛型：类型随调用推断，保留关联
function identity<T>(x: T): T { return x; }

identity(1);       // T = number
identity('hello'); // T = string
```

## 泛型函数

泛型函数用 `<T>` 声明类型参数，参数类型、返回值类型都可以引用 T。

```ts
// 单个类型参数
function first<T>(arr: T[]): T | undefined {
  return arr[0];
}

first([1, 2, 3]);       // number | undefined
first(['a', 'b']);      // string | undefined
```

```ts
// 多个类型参数
function pair<K, V>(key: K, value: V): [K, V] {
  return [key, value];
}

pair('name', 42);       // [string, number]
```

```ts
// 箭头函数写法
const map = <T, U>(arr: T[], fn: (item: T) => U): U[] => arr.map(fn);

map([1, 2, 3], n => String(n));  // string[]
```

```ts
// 调用时显式指定类型参数
function createArray<T>(length: number, value: T): T[] {
  return new Array(length).fill(value);
}

createArray<number>(3, 0);      // 显式指定 T = number
createArray(3, 0);              // 自动推断
```

## 泛型接口

接口可以用泛型描述「容器」或「工厂」等结构，实例化时传入具体类型。

```ts
interface Box<T> {
  value: T;
  get(): T;
  set(value: T): void;
}

const numBox: Box<number> = {
  value: 1,
  get() { return this.value; },
  set(value) { this.value = value; },
};

numBox.set(2);
```

```ts
// 泛型接口描述函数签名
interface Transformer<T, R> {
  (input: T): R;
}

const toString: Transformer<number, string> = n => String(n);
toString(42);  // '42'
```

```ts
// 泛型接口 + 默认类型参数
interface ApiResponse<T = unknown> {
  code: number;
  data: T;
  message: string;
}

const ok: ApiResponse<{ id: number }> = {
  code: 0,
  data: { id: 1 },
  message: 'success',
};
```

## 泛型类

泛型类让类的字段、方法共享同一个类型参数，典型例子是栈、队列、集合等数据结构。

```ts
class Stack<T> {
  private items: T[] = [];

  push(item: T): void {
    this.items.push(item);
  }

  pop(): T | undefined {
    return this.items.pop();
  }

  get size(): number {
    return this.items.length;
  }
}

const numStack = new Stack<number>();
numStack.push(1);
numStack.push(2);
numStack.pop();   // 2
```

```ts
// 泛型类实现泛型接口
interface Collection<T> {
  add(item: T): void;
  all(): T[];
}

class List<T> implements Collection<T> {
  private data: T[] = [];

  add(item: T): void {
    this.data.push(item);
  }

  all(): T[] {
    return [...this.data];
  }
}
```

```ts
// 注意：类的静态成员不能使用类上的类型参数
class Bad<T> {
  // static create(): T { }   // 错误：静态成员不能引用类的类型参数
}
```

## 泛型约束

泛型约束用 `extends` 限制类型参数必须满足某个形状，从而能在函数体内安全地访问特定属性。

```ts
// 约束 T 必须有 length 属性
function logLength<T extends { length: number }>(value: T): number {
  return value.length;
}

logLength('abc');       // 3
logLength([1, 2, 3]);   // 3
// logLength(123);      // 错误：number 没有 length
```

```ts
// 用接口做约束
interface Named {
  name: string;
}

function greet<T extends Named>(item: T): string {
  return `Hello, ${item.name}`;
}

greet({ name: 'Alice', age: 30 });
```

```ts
// 类型参数之间互相约束
function copyProps<T, K extends keyof T>(target: T, source: K): T[K] {
  return target[source];
}

copyProps({ a: 1, b: 'x' }, 'a');  // number
```

```ts
// 约束配合默认值
function createEntity<T extends { id: number } = { id: number }>(data: T): T {
  return data;
}
```

## keyof 与 typeof

`keyof` 取出对象类型所有键组成的联合类型；`typeof` 在类型上下文中把「值」转成「类型」。

```ts
// keyof：取键名联合
interface User {
  id: number;
  name: string;
  email: string;
}

type UserKey = keyof User;  // 'id' | 'name' | 'email'

function getProp<T, K extends keyof T>(obj: T, key: K): T[K] {
  return obj[key];
}

const user: User = { id: 1, name: 'Alice', email: 'a@x.com' };
getProp(user, 'name');   // string
// getProp(user, 'age'); // 错误：'age' 不是 User 的键
```

```ts
// typeof：值转类型（类型查询）
const config = {
  host: 'localhost',
  port: 8080,
  secure: true,
};

type Config = typeof config;
// { host: string; port: number; secure: boolean }

function connect(cfg: Config): void {
  console.log(cfg.host, cfg.port);
}
```

```ts
// typeof + keyof 组合：从已有对象推导可接受的键
const routes = {
  home: '/',
  about: '/about',
  login: '/login',
};

type RouteName = keyof typeof routes;  // 'home' | 'about' | 'login'

function navigate(name: RouteName): void {
  console.log(routes[name]);
}

navigate('home');
// navigate('settings');  // 错误
```

## infer

`infer` 只能在条件类型中使用，用于「推断」某个位置的具体类型，典型场景是提取函数返回值、Promise 包裹的类型、数组元素类型等。

```ts
// 提取函数返回值类型（手写版 ReturnType）
type MyReturnType<T> = T extends (...args: any[]) => infer R ? R : never;

type Fn = (x: number) => string;
type Result = MyReturnType<Fn>;  // string
```

```ts
// 提取 Promise 包裹的类型（手写版 Awaited）
type MyAwaited<T> = T extends Promise<infer U> ? MyAwaited<U> : T;

type T1 = MyAwaited<Promise<number>>;          // number
type T2 = MyAwaited<Promise<Promise<string>>>; // string（递归解包）
```

```ts
// 提取数组元素类型
type ElementOf<T> = T extends (infer E)[] ? E : never;

type E = ElementOf<string[]>;  // string
```

```ts
// 提取函数第一个参数
type FirstArg<T> = T extends (first: infer F, ...rest: any[]) => any ? F : never;

type A = FirstArg<(a: number, b: string) => void>;  // number
```

## 应用场景实战

### 场景一：通用 API 请求函数（保留响应类型）

```ts
interface ApiResult<T> {
  code: number;
  data: T;
  message: string;
}

async function request<T>(url: string): Promise<ApiResult<T>> {
  const res = await fetch(url);
  return res.json() as Promise<ApiResult<T>>;
}

interface UserInfo {
  id: number;
  name: string;
}

// 调用时指定 T，拿到强类型 data
request<UserInfo>('/api/user').then(res => {
  console.log(res.data.name);  // 类型安全
});
```

### 场景二：类型安全的 EventEmitter

```ts
type EventMap = {
  click: { x: number; y: number };
  input: { value: string };
};

class Emitter<Events extends Record<string, any>> {
  private handlers: { [K in keyof Events]?: Array<(payload: Events[K]) => void> } = {};

  on<K extends keyof Events>(event: K, handler: (payload: Events[K]) => void): void {
    (this.handlers[event] ??= []).push(handler);
  }

  emit<K extends keyof Events>(event: K, payload: Events[K]): void {
    this.handlers[event]?.forEach(fn => fn(payload));
  }
}

const emitter = new Emitter<EventMap>();
emitter.on('click', ({ x, y }) => console.log(x, y));
emitter.emit('click', { x: 1, y: 2 });
```

## 最佳实践与踩坑记录

### 最佳实践

1. 泛型命名用单个大写字母（T、K、V），多个时用有意义的名称（TKey、TValue）
2. 能用约束（extends）就不要用 any，保证函数体内能安全访问属性
3. 用 `keyof` + 约束做「键安全的取值函数」，替代裸的 `obj[key]`
4. 提取嵌套类型优先用标准库工具类型（ReturnType、Awaited），复杂场景再用 infer
5. 泛型类型参数尽量让编译器推断，只在无法推断时显式传入

### 踩坑记录

```text
坑 1：泛型函数里直接访问 T 的属性报错
结论：在泛型函数体里访问 value.length 报「类型 T 上不存在属性 length」。
原因：T 默认是任意类型，没有约束时编译器不允许访问任何具体属性。
解法：给 T 加约束 extends { length: number }，或用类型收窄。

坑 2：箭头函数泛型在 .tsx 文件中报错
结论：<T>(x: T) => T 在 .tsx 里被解析成 JSX 标签。
解法：写成 <T,>(x: T) => T，加一个逗号避免歧义。

坑 3：infer 用在条件类型之外报错
结论：type X = infer T 直接报「找不到 infer 声明的 T」。
原因：infer 只能在条件类型 extends 子句的 true 分支中使用。
解法：套一层 T extends ... ? infer U : never。

坑 4：泛型类静态方法无法引用类型参数
结论：静态成员引用 T 报「静态成员不能引用类的类型参数」。
原因：静态成员属于类本身，不随实例类型参数变化。
解法：把类型参数移到静态方法自己的签名上，如 static create<T>(v: T)。

坑 5：用 any 偷懒导致类型关联断裂
结论：函数返回 any 后调用方拿不到正确类型。
原因：any 会关闭类型检查并向上传染。
解法：改用泛型或 unknown，保留入参与返回值的类型关联。
```

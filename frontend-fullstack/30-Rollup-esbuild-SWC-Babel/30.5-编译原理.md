## 概述

编译原理是理解 Babel、SWC、esbuild、TypeScript 等一切前端工具的基础。编译的通用流程是：词法分析 → 语法分析 → 语义转换 → 代码生成，中间以 AST 为核心数据结构。

```text
编译流水线：
1. Lexer —— 词法分析，字符流 → Token 流
2. Parser —— 语法分析，Token 流 → AST
3. AST —— 抽象语法树，中间表示
4. Transform —— 语义转换，修改 AST
5. Code Generator —— 代码生成，AST → 目标代码
```

```text
扩展概念：
Source Map —— 映射目标代码到源码
Transpilation —— 同语言版本转换（转译）
Minification —— 压缩混淆
```

## Lexer

Lexer（词法分析器）把源代码字符串切分成一个个 Token（词法单元），每个 Token 有类型与值，是编译的第一步。

```text
源码：const a = 10;
Token 流：
[Keyword(const)] [Identifier(a)] [Punctuator(=)] [Numeric(10)] [Punctuator(;)]
```

```js
// 极简词法分析器示意
function lexer(code) {
  const tokens = [];
  const re = /\s*(const|let|var|\d+|[a-zA-Z_$][\w$]*|[=;+])/g;
  let m;
  while ((m = re.exec(code))) {
    tokens.push({ value: m[1] });
  }
  return tokens;
}
console.log(lexer('const a = 10;'));
```

## Parser

Parser（语法分析器）读取 Token 流，按照语法规则构建出树形结构（AST）。它验证语法正确性，并建立语句间的层级关系。

```js
// 用 acorn 解析源码
import { parse } from 'acorn';

const ast = parse('const a = 10;', { ecmaVersion: 2020 });
console.log(ast.body[0].type); // 'VariableDeclaration'
```

```text
Parser 要点：
1. 输入 Token 流，输出 AST
2. 递归下降/LR 等算法实现
3. 语法错误在此阶段抛出
```

## AST

AST（抽象语法树）是源码的抽象结构表示，去掉了空格、分号等无关细节，保留语义结构。所有转换都基于 AST 进行。

```js
import { parse } from '@babel/parser';
import traverse from '@babel/traverse';

const ast = parse('function add(a, b) { return a + b; }');
traverse(ast, {
  FunctionDeclaration(path) {
    console.log('函数名:', path.node.id.name); // 'add'
    console.log('参数:', path.node.params.map((p) => p.name)); // ['a', 'b']
  },
});
```

```text
AST 的价值：
1. 结构化的代码表示，便于分析
2. 遍历/修改节点实现转换
3. 是 lint、格式化、编译等工具的基础
```

## Transform

Transform 阶段遍历 AST 并按规则修改节点，实现语法降级、代码优化、注入等转换。这是编译最核心、最灵活的阶段。

```js
import { parse } from '@babel/parser';
import traverse from '@babel/traverse';
import generate from '@babel/generator';

const ast = parse('const double = (x) => x * 2;');
traverse(ast, {
  ArrowFunctionExpression(path) {
    // 箭头函数转普通函数
    const [param] = path.node.params;
    const body = path.node.body;
    path.replaceWithSourceString(`function (${param.name}) { return ${generate(body).code}; }`);
  },
});
console.log(generate(ast).code);
```

```text
Transform 典型应用：
1. 语法降级（箭头函数 → 普通函数）
2. 代码注入（插桩、埋点）
3. 优化（常量折叠、死代码消除）
```

## Code Generator

Code Generator 把转换后的 AST 重新生成代码字符串，可控制缩进、注释、格式等。

```js
import { parse } from '@babel/parser';
import generate from '@babel/generator';

const ast = parse('const a=1;');
const { code, map } = generate(ast, {
  comments: false,
  sourceMaps: true,
});
console.log(code); // 'const a = 1;'
```

```text
Code Generator 要点：
1. AST → 代码字符串
2. 可配置格式（缩进、引号风格）
3. 可同步生成 sourcemap
```

## Source Map

Source Map 记录「目标代码」与「源码」之间的位置映射，让浏览器在运行压缩/转译后的代码时，能还原到原始源码位置进行调试。

```json
{
  "version": 3,
  "sources": ["src/index.js"],
  "names": ["a"],
  "mappings": "AAAA,CAAC"
}
```

```text
Source Map 字段：
version —— 版本（3）
sources —— 源文件列表
names —— 标识符列表
mappings —— VLQ 编码的位置映射
```

## Transpilation

Transpilation（转译）指「同语言不同版本」的转换，如 ES6 → ES5、TS → JS、JSX → JS。它不改变语言，只改变语法版本。

```text
转译 vs 编译：
转译（transpile）—— 源语言与目标语言同族（JS → JS）
编译（compile）—— 跨语言（TS → JS、C → 汇编）
```

```js
// TS 转译示例
// 输入：const s: string = 'hello';
// 输出：const s = 'hello';  （类型被剥离）
```

## Minification

Minification（压缩）通过删除空白注释、缩短标识符、简化表达式等手段，减小代码体积。是转译后的常见后续步骤。

```text
压缩手段：
1. 删除空白与注释
2. 变量名缩短（mangle）
3. 死代码消除
4. 表达式简化（常量折叠）
```

```js
// 压缩前后对比
// 前：function add(a, b) { return a + b; } console.log(add(1, 2));
// 后：function add(a,b){return a+b}console.log(add(1,2));
```

## 应用场景实战

### 场景一：实现一个完整的转译管道

```js
import { parse } from '@babel/parser';
import traverse from '@babel/traverse';
import generate from '@babel/generator';

function transpile(code) {
  const ast = parse(code, { sourceType: 'module' });        // 1. 解析
  traverse(ast, {                                           // 2. 转换
    ArrowFunctionExpression(path) {
      path.node.type = 'FunctionExpression';
    },
  });
  return generate(ast, { sourceMaps: true });               // 3. 生成
}

const result = transpile('const f = () => 1;');
console.log(result.code);
console.log(result.map); // sourcemap
```

### 场景二：用 AST 统计代码复杂度

```js
import { parse } from '@babel/parser';
import traverse from '@babel/traverse';

function countCyclomatic(code) {
  const ast = parse(code);
  let complexity = 1;
  traverse(ast, {
    IfStatement() { complexity += 1; },
    ForStatement() { complexity += 1; },
    WhileStatement() { complexity += 1; },
    CaseStatement() { complexity += 1; },
  });
  return complexity;
}
console.log(countCyclomatic('if (a) { for (;;) {} }')); // 3
```

## 最佳实践与踩坑记录

### 最佳实践

1. 理解「词法 → 语法 → 转换 → 生成」四段流水线
2. 用 AST 工具（如 astexplorer）可视化调试
3. 转换逻辑用 visitor 模式组织，按节点类型分离
4. 生成代码时保留 sourcemap 便于调试
5. 转译与压缩分离，职责清晰

### 踩坑记录

```text
坑 1：Parser 未开启对应语法插件
结论：解析 JSX/TS 报语法错误。
原因：parser 默认不支持非标准语法。
解法：配置 plugins: ['jsx', 'typescript']。

坑 2：Transform 修改 AST 未处理 sourcemap
结论：调试时代码位置错乱。
原因：只改 AST 没同步生成 sourcemap。
解法：generate 开启 sourceMaps: true。

坑 3：转译与 polyfill 混淆
结论：语法降级了但 API 仍报错。
原因：转译只处理语法，API 需 polyfill。
解法：语法用转译，API 用 polyfill（core-js）。

坑 4：AST 遍历时修改结构导致漏遍历
结论：部分节点未按预期处理。
原因：遍历中直接修改结构，path 引用失效。
解法：用 path.replaceWith 等 API，收集后统一处理。

坑 5：mappings 编码理解错误
结论：手写 sourcemap 时位置映射错误。
原因：mappings 是 VLQ 增量编码，非直接坐标。
解法：用库生成 sourcemap，不手写。
```

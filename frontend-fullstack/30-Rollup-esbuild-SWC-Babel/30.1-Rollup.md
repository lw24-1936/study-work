## 概述

Rollup 是专注 ES Module 的打包器，以「Tree Shaking 彻底、产物干净」著称，是构建 JavaScript 库（npm 包）的首选工具，也是 Vite 生产构建的底层引擎。

```text
Rollup 核心特点：
1. ESM —— 以 ES Module 为核心，产物简洁
2. Tree Shaking —— 静态分析，摇树彻底
3. Plugin —— 丰富的插件生态
4. Bundle —— 输出 IIFE/CJS/UMD/ESM 多种格式
5. Code Splitting —— 支持动态导入分包
6. Library Build —— 面向库开发的打包体验
```

```js
// rollup.config.js
export default {
  input: 'src/index.js',
  output: {
    file: 'dist/bundle.js',
    format: 'esm',   // iife/cjs/umd/esm/amd
  },
};
```

## ESM

Rollup 以 ES Module 为输入与输出的核心格式。它利用 ESM 的静态结构（import/export 在编译期确定）做精确分析，因此 Tree Shaking 能力极强。

```js
// src/index.js
import { add } from './math.js';
export const result = add(1, 2);
```

```text
ESM 对 Rollup 的意义：
1. 静态 import/export，可编译期分析依赖
2. 输出可生成多种模块格式（cjs/umd/esm）
3. 与 CommonJS 相比更利于摇树
```

```js
// 输出多种格式
export default {
  input: 'src/index.js',
  output: [
    { file: 'dist/bundle.esm.js', format: 'es' },
    { file: 'dist/bundle.cjs.js', format: 'cjs' },
    { file: 'dist/bundle.umd.js', format: 'umd', name: 'MyLib' },
  ],
};
```

## Tree Shaking

Tree Shaking 移除未使用的导出代码。Rollup 基于 ESM 静态分析，能精确识别「导出了但没人引用」的代码并删除，产物极干净。

```js
// math.js
export function used() { return 'used'; }
export function unused() { return 'unused'; }  // 会被摇掉

// main.js
import { used } from './math';
console.log(used());
// 打包结果只包含 used 函数
```

```text
Rollup Tree Shaking 特点：
1. 基于 ESM 静态分析，精确到导出级别
2. 配合 sideEffects 声明可进一步删除副作用代码
3. 产物比 Webpack 更干净（适合库开发）
```

## Plugin

Rollup 插件体系是打包流程的扩展点，钩子分为构建阶段（resolveId、load、transform）与输出阶段（renderChunk、generateBundle）。

```js
// 自定义 Rollup 插件
export default function myPlugin() {
  return {
    name: 'my-plugin',
    resolveId(id) { /* 解析模块 */ },
    load(id) { /* 加载内容 */ },
    transform(code, id) {
      if (id.endsWith('.js')) return code.replace(/DEBUG/g, 'false');
    },
  };
}
```

```text
常用 Rollup 插件：
@rollup/plugin-node-resolve —— 解析 node_modules
@rollup/plugin-commonjs —— 转换 CommonJS
@rollup/plugin-babel —— Babel 转译
@rollup/plugin-terser —— 压缩
```

## Bundle

Bundle 是 Rollup 打包的核心概念：把多个模块合并成单个文件。输出格式（format）决定产物形态。

```js
export default {
  input: 'src/index.js',
  output: {
    file: 'dist/lib.js',
    format: 'umd',         // 兼容多种环境
    name: 'MyLibrary',     // UMD 全局变量名
    sourcemap: true,
    banner: '/* my lib v1.0.0 */',
  },
};
```

```text
输出格式（format）：
iife —— 浏览器 script 直接执行
cjs —— Node.js require
es/esm —— 浏览器/打包器 import
umd —— 同时支持 script 与 require/import
```

## Code Splitting

Rollup 支持动态 import() 实现代码分割，配合 output.dir 输出多个 chunk 文件。

```js
export default {
  input: 'src/index.js',
  output: {
    dir: 'dist',
    format: 'esm',
    chunkFileNames: '[name]-[hash].js',
  },
};
```

```js
// src/index.js 动态导入产生独立 chunk
export async function loadHeavy() {
  const { heavy } = await import('./heavy.js');
  return heavy();
}
```

```text
Code Splitting 要点：
1. 动态 import() 自动产生异步 chunk
2. 需 output.dir 而非 output.file
3. 手动 chunk 可用 output.manualChunks
```

## Library Build

Rollup 是构建 npm 库的首选：天然输出多种格式、Tree Shaking 彻底、产物可被下游继续摇树。

```js
export default {
  input: 'src/index.js',
  external: ['react', 'react-dom'],   // 外部依赖不打包
  output: [
    { file: 'dist/index.esm.js', format: 'es' },
    { file: 'dist/index.cjs.js', format: 'cjs' },
  ],
};
```

```json
// package.json 声明多格式入口
{
  "main": "dist/index.cjs.js",
  "module": "dist/index.esm.js",
  "types": "dist/index.d.ts"
}
```

```text
库开发要点：
1. external 排除 peer 依赖（如 react）
2. 同时输出 ESM + CJS，兼顾不同环境
3. 保留 ESM 格式让下游能继续 Tree Shaking
```

## 应用场景实战

### 场景一：构建通用工具库

```js
// rollup.config.js
import resolve from '@rollup/plugin-node-resolve';
import commonjs from '@rollup/plugin-commonjs';
import { terser } from 'rollup-plugin-terser';

export default {
  input: 'src/index.js',
  external: ['lodash-es'],
  plugins: [resolve(), commonjs()],
  output: [
    { file: 'dist/index.esm.js', format: 'es' },
    { file: 'dist/index.cjs.js', format: 'cjs' },
    { file: 'dist/index.umd.min.js', format: 'umd', name: 'Utils', plugins: [terser()] },
  ],
};
```

### 场景二：多入口分包构建

```js
export default {
  input: {
    main: 'src/main.js',
    admin: 'src/admin.js',
  },
  output: {
    dir: 'dist',
    format: 'esm',
    entryFileNames: '[name].js',
  },
};
```

## 最佳实践与踩坑记录

### 最佳实践

1. 库开发首选 Rollup，产物干净可被下游摇树
2. external 排除 peer 依赖，避免重复打包
3. 同时输出 ESM 与 CJS 格式
4. 用 @rollup/plugin-commonjs 处理第三方 CJS 依赖
5. 保留 sourcemap 便于调试

### 踩坑记录

```text
坑 1：CommonJS 依赖打包报错
结论：import CJS 包时报未导出 default。
原因：Rollup 核心只认 ESM，CJS 需转换。
解法：加 @rollup/plugin-commonjs 插件。

坑 2：未配 external 导致 react 被打进库
结论：库产物体积暴增，且下游出现多实例问题。
原因：peer 依赖被打进产物。
解法：external: ['react', 'react-dom'] 并声明 peerDependencies。

坑 3：code splitting 用了 output.file
结论：动态导入分包报错。
原因：output.file 只支持单文件，分包需 output.dir。
解法：改用 output.dir 输出目录。

坑 4：Tree Shaking 误删副作用代码
结论：CSS import 等副作用代码被删。
原因：未在 package.json 声明 sideEffects。
解法：sideEffects: ["*.css"] 标记有副作用的文件。

坑 5：UMD 未设 name
结论：浏览器 script 引入时全局变量未定义。
原因：UMD 格式需要 name 指定全局变量名。
解法：output 中 name: 'MyLib'。
```

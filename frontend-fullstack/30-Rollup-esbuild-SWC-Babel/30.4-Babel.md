## 概述

Babel 是 JavaScript 编译器，把新版语法（ES6+、JSX、TS）转译为兼容目标环境的代码。它的核心是「解析 → 转换 → 生成」三段式流水线，基于 AST 完成变换。

```text
Babel 核心要点：
1. AST —— 抽象语法树，转换的中间表示
2. Parser —— 源码解析为 AST
3. Transform —— 遍历并修改 AST
4. Plugin —— 最小转换单元
5. Preset —— 插件集合
6. Polyfill —— 补齐缺失的 API
7. Babel Runtime —— 辅助函数复用，避免重复注入
```

```text
Babel 工作流程：
源码 → @babel/parser 解析 → AST → 插件遍历修改 AST → @babel/generator 生成 → 目标代码
```

## AST

AST（Abstract Syntax Tree）是源代码的树形结构表示，Babel 的转换就是在 AST 上增删改节点。

```js
import { parse } from '@babel/parser';
import traverse from '@babel/traverse';
import generate from '@babel/generator';

const code = 'const a = 1;';
const ast = parse(code);        // 源码 → AST
traverse(ast, {                 // 遍历 AST
  VariableDeclaration(path) {
    console.log(path.node.kind); // 'const'
  },
});
const output = generate(ast);    // AST → 代码
console.log(output.code);
```

```text
AST 节点类型：
Program —— 根节点
VariableDeclaration —— 变量声明
FunctionDeclaration —— 函数声明
ImportDeclaration —— 导入声明
```

## Parser

Babel 的 Parser（@babel/parser，原 babylon）把源码解析成 AST，支持最新的 ECMAScript 语法及 JSX、TypeScript 等扩展。

```js
import { parse } from '@babel/parser';

const ast = parse('const x = <div>hello</div>;', {
  sourceType: 'module',       // script/module/unambiguous
  plugins: ['jsx', 'typescript'],
});
```

```text
Parser 配置：
sourceType —— 模块类型（module 允许 import/export）
plugins —— 启用 jsx、typescript、decorators 等语法
```

## Transform

Transform 阶段遍历 AST 并对节点做修改，是 Babel 转换的核心。通过 traverse 访问器访问特定类型节点并操作 path。

```js
import { parse } from '@babel/parser';
import traverse from '@babel/traverse';

const ast = parse('const a = 1;');
traverse(ast, {
  enter(path) {
    // 进入每个节点
  },
  Identifier(path) {
    // 访问所有标识符节点
    if (path.node.name === 'a') path.node.name = 'renamed';
  },
});
```

```text
Transform 机制：
1. traverse 深度优先遍历 AST
2. 访问器按节点类型匹配
3. path 提供节点操作与替换 API
```

## Plugin

Plugin 是 Babel 的最小转换单元，一个插件负责一种语法转换。自定义插件就是一个返回 visitor 对象的函数。

```js
// 自定义 Babel 插件：把 console.log 的字符串反转
export default function reverseLog() {
  return {
    name: 'reverse-log',
    visitor: {
      CallExpression(path) {
        if (path.node.callee.type === 'MemberExpression' &&
            path.node.callee.object.name === 'console') {
          const arg = path.node.arguments[0];
          if (arg && arg.type === 'StringLiteral') {
            arg.value = arg.value.split('').reverse().join('');
          }
        }
      },
    },
  };
}
```

```text
Plugin 要点：
1. visitor 按节点类型定义处理逻辑
2. 用 path 操作节点（替换/插入/删除）
3. 官方插件如 @babel/plugin-transform-arrow-functions
```

## Preset

Preset 是一组插件的集合，简化配置。常用 preset：@babel/preset-env（按目标环境自动选插件）、@babel/preset-react、@babel/preset-typescript。

```json
{
  "presets": [
    ["@babel/preset-env", { "targets": "> 0.25%, not dead" }],
    "@babel/preset-react",
    "@babel/preset-typescript"
  ]
}
```

```text
常用 Preset：
preset-env —— 按 browserslist 目标自动加载语法插件
preset-react —— JSX 转换
preset-typescript —— TS 剥离
```

## Polyfill

Polyfill 补齐目标环境缺失的 API（如 Promise、Array.includes）。preset-env 通过 useBuiltIns 按需引入 core-js。

```json
{
  "presets": [
    ["@babel/preset-env", {
      "targets": { "ie": 11 },
      "useBuiltIns": "usage",      // 按需自动引入
      "corejs": 3
    }]
  ]
}
```

```text
useBuiltIns 取值：
false —— 不自动引入（默认）
usage —— 按代码实际使用按需引入
entry —— 入口全量引入
```

```text
注意区分：
语法转换（箭头函数等）→ 插件完成
API 补齐（Promise 等）→ polyfill 完成
```

## Babel Runtime

@babel/runtime 与 @babel/plugin-transform-runtime 复用辅助函数（如 _extends、_classCallCheck），避免在每个文件重复注入，减小产物体积。

```json
{
  "plugins": [
    ["@babel/plugin-transform-runtime", {
      "corejs": 3,
      "helpers": true,
      "regenerator": true
    }]
  ]
}
```

```text
transform-runtime 的作用：
1. 复用 helpers，避免每个文件重复注入
2. 复用 regenerator（async/await 运行时）
3. 避免污染全局（适合库开发）
```

```text
@babel/runtime 与 polyfill 区别：
transform-runtime —— 局部引入，不污染全局，适合库
polyfill（useBuiltIns）—— 全局补齐，适合应用
```

## 应用场景实战

### 场景一：项目级 babel.config.js

```js
module.exports = {
  presets: [
    ['@babel/preset-env', { targets: '> 0.25%, not dead', useBuiltIns: 'usage', corejs: 3 }],
    ['@babel/preset-react', { runtime: 'automatic' }],
    '@babel/preset-typescript',
  ],
  plugins: [
    ['@babel/plugin-transform-runtime', { corejs: 3 }],
  ],
};
```

### 场景二：自定义代码检查插件

```js
export default function noAlert() {
  return {
    name: 'no-alert',
    visitor: {
      CallExpression(path) {
        if (path.node.callee.name === 'alert') {
          throw path.buildCodeFrameError('禁止使用 alert');
        }
      },
    },
  };
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. 用 preset-env + browserslist 按需转译
2. 应用用 useBuiltIns: 'usage' 按需 polyfill
3. 库用 transform-runtime 避免全局污染
4. 插件按需配置，不盲目堆砌
5. corejs 版本显式指定，避免警告

### 踩坑记录

```text
坑 1：忘记配 polyfill
结论：旧浏览器 API 报错 undefined。
原因：Babel 只转语法，不补 API。
解法：useBuiltIns: 'usage' + corejs: 3。

坑 2：useBuiltIns 与 transform-runtime 混用冲突
结论：polyfill 重复或报错。
原因：两者都注入 polyfill，机制不同。
解法：二选一（应用用 useBuiltIns，库用 runtime）。

坑 3：corejs 版本警告
结论：控制台警告 corejs 版本未指定。
原因：useBuiltIns 或 transform-runtime 需显式 corejs。
解法：显式写 corejs: 3。

坑 4：preset 顺序错误
结论：转换结果异常。
原因：preset 从后往前执行，顺序敏感。
解法：preset-env 放最后（最先声明）。

坑 5：babel.config 与 .babelrc 混淆
结论：配置不生效。
原因：babel.config.js 作用于整个项目，.babelrc 作用于文件相对目录。
解法：项目级统一用 babel.config.js。
```

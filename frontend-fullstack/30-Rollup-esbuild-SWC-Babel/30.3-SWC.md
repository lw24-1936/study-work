## 概述

SWC（Speedy Web Compiler）是用 Rust 编写的超高速 JS/TS 编译器，可作为 Babel 的替代品，被 Next.js、Deno 等大量项目采用，也是 React Compiler 等工具的基础。

```text
SWC 核心能力：
1. Rust —— 高性能、内存安全的系统语言实现
2. Parser —— 解析 JS/TS/JSX 语法树
3. Transformer —— 语法转译与代码变换
4. Minifier —— 代码压缩
```

```text
SWC 与 Babel：
SWC —— Rust 实现，快数十倍，功能覆盖 Babel 主体
Babel —— JS 实现，生态庞大、插件极多
```

```js
// .swcrc 配置
{
  "jsc": {
    "parser": { "syntax": "typescript", "tsx": true },
    "target": "es2018",
    "transform": { "react": { "runtime": "automatic" } }
  },
  "minify": false
}
```

## Rust

SWC 用 Rust 编写，Rust 的高性能与内存安全特性让 SWC 在编译速度上远超 JS 实现的同类工具。

```text
Rust 带来的优势：
1. 编译为原生机器码，无运行时开销
2. 零成本抽象 + 无 GC，性能接近 C/C++
3. 内存安全，避免悬垂指针等错误
4. 可编译为 WASM，在浏览器/Node 中运行
```

```text
SWC 的生态应用：
1. Next.js —— 默认编译器（替代 Babel）
2. Deno —— 内置代码打包与转译
3. Parcel —— 底层转译引擎
4. 各种 Rust 工具链的基础
```

## Parser

SWC 的 Parser 解析 JavaScript/TypeScript/JSX 语法，产出高效的内存 AST 结构，速度是 Babel 解析器的数十倍。

```js
// SWC API 解析代码
import { parseSync } from '@swc/core';

const ast = parseSync('const x: number = 1;', {
  syntax: 'typescript',
  tsx: false,
});
console.log(ast.type); // 'Module'
```

```text
Parser 要点：
1. 支持 syntax: ecmascript / typescript
2. 支持 jsx/tsx 语法开关
3. 产出紧凑的 Rust AST（映射到 JS 对象）
```

## Transformer

Transformer 对 AST 做变换：语法降级、JSX 转 JS、装饰器、代码改写等，功能对应 Babel 的 transform 能力。

```js
// SWC API 转译
import { transformSync } from '@swc/core';

const { code } = transformSync(
  `const greet = (name) => `Hello, ${name}`;`,
  {
    jsc: { target: 'es5' },  // 降级到 ES5
    minify: false,
  }
);
console.log(code);
```

```text
Transformer 常用场景：
1. target 降级（es5/es2018 等）
2. JSX/TS 转 JS
3. React runtime 转换（classic/automatic）
4. 装饰器、模块转换
```

## Minifier

SWC 内置 Minifier，压缩速度远快于 terser，Next.js 等框架用它做生产压缩。

```js
import { minifySync } from '@swc/core';

const result = minifySync(
  `function add(a, b) { return a + b; } console.log(add(1, 2));`,
  { compress: true, mangle: true }
);
console.log(result.code);
```

```text
Minifier 要点：
1. compress —— 压缩语法与死代码
2. mangle —— 变量名混淆
3. 速度远超 terser，质量接近
```

## 应用场景实战

### 场景一：Next.js 式转译配置

```js
// .swcrc —— 转译 TSX + React
{
  "jsc": {
    "parser": { "syntax": "typescript", "tsx": true, "decorators": true },
    "target": "es2017",
    "transform": { "react": { "runtime": "automatic", "development": true } }
  },
  "module": { "type": "es6" }
}
```

### 场景二：脚本批量转译压缩

```js
import { transformFileSync } from '@swc/core';
import { readdirSync } from 'node:fs';

for (const file of readdirSync('src')) {
  const { code } = transformFileSync(`src/${file}`, {
    jsc: { target: 'es2018' },
    minify: true,
  });
  console.log(`${file} -> ${code.length} bytes`);
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. 追求构建速度优先选 SWC 替代 Babel
2. 转译配置集中到 .swcrc，保持团队一致
3. TS 类型检查仍需 tsc（SWC 不做类型校验）
4. 需要极特殊 Babel 插件时，可 SWC + Babel 混用
5. minify 与 compress/mangle 组合按需开启

### 踩坑记录

```text
坑 1：SWC 不做类型检查
结论：转译通过但类型有误。
原因：SWC 只剥离类型，不校验。
解法：CI 加 tsc --noEmit。

坑 2：某些 Babel 插件无 SWC 等价物
结论：迁移 SWC 后个别插件失效。
原因：Babel 生态插件极多，SWC 覆盖不全。
解法：特殊插件用 @swc/plugin 或保留局部 Babel。

坑 3：target 与 module 配置冲突
结论：转译结果不符合预期环境。
原因：jsc.target 与 module.type 配置不一致。
解法：明确目标环境，统一配置。

坑 4：JSX runtime 配错
结论：React 17+ 仍注入 React 引用报错。
原因：transform.react.runtime 未设 automatic。
解法：runtime: 'automatic' 适配新版 JSX 转换。

坑 5：minify 压缩后 sourcemap 错位
结论：调试时行号对不上。
原因：minify 与 sourcemap 未正确关联。
解法：开启 sourceMaps: true 并保留原文件。
```

## 概述

esbuild 是用 Go 编写的极速打包器/转译器，比传统 JavaScript 工具快 10~100 倍。它集解析、打包、转译、压缩于一体，是 Vite 依赖预构建与转译的底层引擎。

```text
esbuild 核心能力：
1. Parser —— 极快的语法解析
2. Bundler —— 模块打包与依赖解析
3. Transformer —— TS/JSX 语法降级转译
4. Minifier —— 代码压缩混淆
5. Plugin —— 插件扩展机制
```

```text
为什么快：
1. Go 原生二进制，无 JS 解释器开销
2. 多核并行处理
3. 单次遍历完成解析到生成
```

```js
// esbuild CLI 用法
// npx esbuild src/index.js --bundle --minify --outfile=dist/out.js
```

## Parser

esbuild 的 Parser 用 Go 实现，解析 JS/TS/JSX 语法树速度极快，支持 ES 最新语法与 TypeScript 类型标注（不做类型检查）。

```text
esbuild Parser 特点：
1. Go 实现，解析速度远超 JS 实现
2. 支持 JSX/TS/最新 ES 语法
3. 只解析语法，不做类型检查
```

```js
// esbuild API 解析
import { transform } from 'esbuild';

const result = await transform('const x: number = 1;', {
  loader: 'ts',       // 指定解析器按 TS 处理
  target: 'es2015',   // 目标语法级别
});
console.log(result.code); // const x = 1;
```

## Bundler

esbuild 的 Bundler 解析模块依赖并把多个文件打包成单个产物，支持 ESM 与 CommonJS 混合依赖。

```js
// build.js
import { build } from 'esbuild';

await build({
  entryPoints: ['src/index.js'],
  bundle: true,               // 开启打包
  outfile: 'dist/bundle.js',
  format: 'esm',              // iife/cjs/esm
  platform: 'browser',
  external: ['react'],        // 排除外部依赖
});
```

```text
Bundler 要点：
1. 支持多入口与代码分割（splitting）
2. 自动处理 ESM/CJS 混合依赖
3. 打包与压缩可同一命令完成
```

## Transformer

Transformer 做语法转译（transpile）：把新版语法降级到目标版本，处理 JSX、TypeScript 等。注意 esbuild 只降级语法，不注入 polyfill。

```js
import { transform } from 'esbuild';

const { code } = await transform(
  `const fn = (x) => x ?? 'default';`,
  { target: 'es2015' }  // 箭头函数等降级为 es2015 语法
);
console.log(code);
```

```text
Transformer 边界：
能做 —— 语法降级（箭头函数、可选链、解构等）
不能做 —— polyfill（Promise、Map 等 API 需另配）
```

## Minifier

esbuild 内置 Minifier，压缩速度极快，质量接近 terser。Vite 生产构建默认用它做压缩。

```js
import { build } from 'esbuild';

await build({
  entryPoints: ['src/index.js'],
  bundle: true,
  minify: true,          // 开启压缩
  minifyWhitespace: true,
  minifyIdentifiers: true,
  minifySyntax: true,
  outfile: 'dist/out.min.js',
});
```

```text
Minifier 特点：
1. 极快，比 terser 快数十倍
2. 压缩质量略低于 terser（极致场景可换）
3. 支持三大维度：空白/标识符/语法
```

## Plugin

esbuild 提供 Plugin 机制，通过 onResolve/onLoad 等钩子扩展解析与加载流程，但插件体系较 Rollup/Webpack 简单（异步钩子有限）。

```js
// 自定义 esbuild 插件：加载虚拟模块
const virtualPlugin = {
  name: 'virtual',
  setup(build) {
    build.onResolve({ filter: /^virtual:/ }, (args) => ({ path: args.path, namespace: 'virtual' }));
    build.onLoad({ filter: /.*/, namespace: 'virtual' }, (args) => ({
      contents: `export default 'virtual content'`,
      loader: 'js',
    }));
  },
};

await build({ entryPoints: ['src/index.js'], bundle: true, plugins: [virtualPlugin] });
```

```text
esbuild 插件钩子：
onResolve —— 自定义模块解析
onLoad —— 自定义模块内容加载
onStart/onEnd —— 构建开始/结束回调
```

## 应用场景实战

### 场景一：库的快速打包压缩

```js
import { build } from 'esbuild';

await build({
  entryPoints: ['src/index.ts'],
  bundle: true,
  minify: true,
  sourcemap: true,
  target: ['es2020', 'node18'],
  outfile: 'dist/index.js',
});
```

### 场景二：Vite 式依赖预构建

```js
import { build } from 'esbuild';

// 把 CJS 依赖预打包成单个 ESM 文件
await build({
  entryPoints: ['node_modules/some-cjs-lib/index.js'],
  bundle: true,
  format: 'esm',
  platform: 'browser',
  outfile: '.cache/deps/some-cjs-lib.js',
});
```

## 最佳实践与踩坑记录

### 最佳实践

1. 用 esbuild 做转译与压缩，速度优先
2. 打包库时 external 排除 peer 依赖
3. 注意 esbuild 不做 polyfill，需另配
4. 生产构建可用 esbuild 压缩替代 terser 提速
5. TS 场景仍需 tsc 做类型检查（esbuild 不检查类型）

### 踩坑记录

```text
坑 1：TS 类型错误未发现
结论：esbuild 转译通过，但类型实际有误。
原因：esbuild 只剥离类型，不做类型检查。
解法：CI 中加 tsc --noEmit 做类型校验。

坑 2：语法降级但 API 未 polyfill
结论：旧浏览器报 Promise/Map 等未定义。
原因：esbuild 只降级语法，不注入 polyfill。
解法：配合 core-js 或手动引入 polyfill。

坑 3：插件钩子异步受限
结论：复杂异步逻辑在 esbuild 插件中难实现。
原因：esbuild 插件体系较简单，钩子有限。
解法：复杂场景改用 Rollup 插件（如 Vite 中）。

坑 4：target 设太低导致产物膨胀
结论：降级过多使产物体积增大。
原因：语法降级需注入大量辅助代码。
解法：target 按真实浏览器范围设定。

坑 5：splitting 与 cjs 格式冲突
结论：代码分割时 format:cjs 报错。
原因：esbuild 的 splitting 仅支持 esm 格式。
解法：分包时用 format: 'esm'。
```

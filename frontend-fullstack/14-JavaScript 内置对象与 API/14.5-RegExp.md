## 概述

正则表达式（RegExp）是强大的文本模式匹配工具，用于查找、验证、替换、提取字符串。掌握正则能大幅提升文本处理能力。

```text
正则的两大用途：
1. 验证 —— 判断字符串是否符合格式（邮箱、手机号、URL）
2. 提取/替换 —— 从文本中提取或替换特定内容

两种创建方式：
字面量 —— /pattern/flags（静态，编译一次）
构造函数 —— new RegExp(pattern, flags)（动态，可拼接）
```

## Pattern 模式

模式由普通字符和元字符组成，元字符有特殊含义。

```js
// 普通字符：精确匹配
/abc/.test('abc');        // true
/abc/.test('ab');         // false

// 元字符
/a.c/                     // . 匹配任意单字符（除换行）
/^abc/                    // ^ 匹配开头
/abc$/                    // $ 匹配结尾
/ab*c/                    // * 前面字符 0 次或多次
/ab+c/                    // + 前面字符 1 次或多次
/ab?c/                    // ? 前面字符 0 次或 1 次
/a{2,4}/                  // {2,4} 2 到 4 次
```

```js
// 转义：匹配元字符本身要加反斜杠
/\./.test('a.b');         // 匹配字面点号
/\*/.test('a*b');
```

```text
量词（重复次数）：
* —— 0 次或多次
+ —— 1 次或多次
? —— 0 次或 1 次
{n} —— 恰好 n 次
{n,} —— 至少 n 次
{n,m} —— n 到 m 次

贪婪 vs 懒惰：默认贪婪（尽量多），加 ? 变懒惰（尽量少）。
```

## Character Class 字符类

字符类匹配一组字符中的任意一个。

```js
/[abc]/          // 匹配 a、b、c 任意一个
/[a-z]/          // 小写字母
/[0-9]/          // 数字
/[A-Za-z]/       // 字母
/[^abc]/         // 取反：非 a、b、c

// 预定义字符类
/\d/             // 数字 [0-9]
/\w/             // 单词字符 [A-Za-z0-9_]
/\s/             // 空白字符
/\D/             // 非数字
/\W/             // 非单词字符
/\S/             // 非空白
```

```js
// 组合使用
/[\d]{3}/         // 3 个数字
/[a-zA-Z0-9_]+/   // 一个或多个字母数字下划线
```

```js
// Unicode 属性转义（配合 u 标志）
/\p{Letter}/u     // 任意字母（含中文等）
/\p{Number}/u     // 任意数字
```

## Group 与 Capture 分组捕获

分组用括号包裹，捕获匹配结果，可后续引用或提取。

```js
// 捕获分组
const match = '2026-01-15'.match(/(\d{4})-(\d{2})-(\d{2})/);
match[1];          // '2026'（第一个分组）
match[2];          // '01'
match[3];          // '15'
```

```js
// 命名捕获分组（ES2018）
const m = '2026-01-15'.match(/(?<year>\d{4})-(?<month>\d{2})-(?<day>\d{2})/);
m.groups.year;     // '2026'
m.groups.month;    // '01'
m.groups.day;      // '15'
```

```js
// 非捕获分组（?: 不捕获，仅用于分组逻辑）
/(?:https?|ftp):\/\//   // 分组但不捕获协议
```

```text
分组的三种形式：
(abc) —— 捕获分组（可提取、可反向引用）
(?<name>abc) —— 命名捕获分组
(?:abc) —— 非捕获分组（仅逻辑分组）
```

## Lookahead 与 Lookbehind 断言

断言匹配「位置」而非字符：前向断言（lookahead）看后面，后向断言（lookbehind）看前面。

```js
// 正向前瞻 (?=...)：后面是...的位置
/\d+(?=元)/.exec('价格 100 元');    // 匹配 '100'（后面是「元」）

// 负向前瞻 (?!...)：后面不是...的位置
/\d+(?!元)/.exec('价格 100 元');    // 匹配不到 100（后面是元）
```

```js
// 正向后顾 (?<=...)：前面是...的位置（ES2018）
/(?<=￥)\d+/.exec('￥100');         // 匹配 '100'（前面是￥）

// 负向后顾 (?<!...)：前面不是...的位置
/(?<!￥)\d+/.exec('￥100');         // 匹配不到
```

```text
四种断言：
(?=X) —— 正向前瞻（后面是 X）
(?!X) —— 负向前瞻（后面不是 X）
(?<=X) —— 正向后顾（前面是 X，ES2018）
(?<!X) —— 负向后顾（前面不是 X）

断言不消耗字符，只匹配位置。
```

## Backreference 反向引用

反向引用引用之前捕获的分组，用于匹配「重复出现的内容」。

```js
// \1 引用第一个分组
/(\w+)\s+\1/.test('hello hello');   // true（相同的词重复）
/(\w+)\s+\1/.test('hello world');   // false

// 命名分组反向引用
/(?<word>\w+)\s+\k<word>/.test('hello hello');   // true
```

```js
// 典型：匹配成对的引号
/(['"]).*?\1/.exec('"hello"');      // 匹配 '"hello"'（引号配对）
```

## Flags 标志（Global / Unicode / Sticky）

标志改变匹配行为。

```js
// 常用标志
/g   // global：全局匹配（找所有）
/i   // ignoreCase：忽略大小写
/m   // multiline：多行模式（^$ 匹配行首行尾）
/s   // dotAll：. 匹配换行
/u   // unicode：Unicode 模式（正确处理代理对）
/y   // sticky：粘性匹配（从 lastIndex 精确匹配）
```

```js
// global：找所有匹配
'hello hello'.match(/hello/g);    // ['hello', 'hello']

// ignoreCase
/abc/i.test('ABC');               // true

// multiline
/^b/m.test('a\nb');               // true（行首 b）
```

```js
// unicode：正确处理 emoji 等
'😀'.match(/./u);                 // ['😀']（u 标志）
'😀'.match(/./);                  // 匹配半个（无 u）

// sticky：从 lastIndex 精确匹配
const re = /a/y;
re.lastIndex = 1;
re.exec('ba');                    // 匹配下标 1 的 a
```

```text
标志组合：
/i 与 /u 可组合（/iu 忽略大小写 + Unicode）
/g 与 /y 互斥（不能同时）
```

## 应用场景实战

### 场景一：邮箱验证

```js
const emailRe = /^[\w.-]+@[\w-]+\.[\w.]+$/;
emailRe.test('user@example.com');   // true
emailRe.test('invalid@@');          // false
```

### 场景二：提取 URL 参数

```js
const url = 'https://example.com?page=2&sort=asc';
const params = {};
url.replace(/[?&](\w+)=([^&]+)/g, (_, k, v) => {
  params[k] = v;
});
// { page: '2', sort: 'asc' }
```

## 最佳实践与踩坑记录

### 最佳实践

1. 验证类正则加 ^...$ 锚定，避免部分匹配
2. 处理 Unicode（emoji、中文）加 u 标志
3. 提取用命名捕获分组，可读性更好
4. 复杂正则加注释或用工具（如 regex101）验证
5. 动态拼接正则用构造函数，注意转义

### 踩坑记录

```text
坑 1：全局标志的 lastIndex 状态
结论：/a/g 多次 exec 结果不一致。
原因：g 标志下 lastIndex 会移动，需手动重置。
解法：循环中注意 lastIndex，或 match（不依赖 lastIndex）。

坑 2：忘加锚定导致部分匹配
结论：/abc/ 匹配到 'xxabcxx' 也算通过。
原因：正则默认匹配子串。
解法：验证类加 ^...$。

坑 3：点号 . 不匹配换行
结论：/a.b/ 匹配不到 'a\nb'。
原因：. 默认不匹配换行符。
解法：加 s 标志，或用 [\s\S]。

坑 4：贪婪匹配过多
结论：/a.*b/ 匹配到过长内容。
原因：.* 贪婪，尽量多匹配。
解法：加 ? 变懒惰（.*?），或精确字符类。

坑 5：特殊字符忘转义
结论：匹配 . 或 * 字面量出错。
原因：这些是元字符，需转义。
解法：\. \* \+ 等转义，或动态构造时用转义函数。
```

## 概述

Map 和 Set 是 ES6 引入的集合类型，弥补了普通对象（键只能是字符串）和数组（查找慢、去重麻烦）的不足。WeakMap/WeakSet 则是「弱引用」版本，用于缓存与元数据。

```text
四种集合的定位：
Map —— 键值对，键可以是任意类型（对象、函数、任意值）
Set —— 唯一值的集合，自动去重
WeakMap —— 键必须是对象，弱引用（可被 GC 回收）
WeakSet —— 值必须是对象，弱引用

对比：
普通对象 —— 键只能是字符串/Symbol，有原型链风险
Map —— 键任意类型、有序、有 size、可迭代
```

## Map 映射

Map 是键值对集合，键可以是任意类型，保持插入顺序。

```js
const map = new Map();

// 增删改查
map.set('name', 'Alice');
map.set(1, 'one');
map.set({ id: 1 }, 'object key');   // 对象作键
map.get('name');                    // 'Alice'
map.has('name');                    // true
map.delete('name');                 // true
map.size;                           // 元素数量
```

```js
// 遍历
for (const [key, value] of map) {
  console.log(key, value);
}

map.forEach((value, key) => console.log(key, value));
map.keys();       // 键迭代器
map.values();     // 值迭代器
```

```js
// 初始化与转换
const m = new Map([['a', 1], ['b', 2]]);

// Map ↔ 对象
const obj = Object.fromEntries(m);      // Map → 对象
const back = new Map(Object.entries(obj));  // 对象 → Map

// Map ↔ 数组
[...m];                                  // [['a',1],['b',2]]
```

```text
Map vs 普通对象：
Map —— 键任意类型、有序、有 size、可迭代、无原型污染
对象 —— 键只能是字符串、无序（数字键特殊）、有原型链风险

需要「字典」或「任意类型键」时，优先 Map。
```

## WeakMap 弱映射

WeakMap 的键必须是对象，且是**弱引用**（不阻止垃圾回收），常用于缓存、私有数据。

```js
const wm = new WeakMap();

const key = { id: 1 };
wm.set(key, 'metadata');
wm.get(key);          // 'metadata'
wm.has(key);          // true
wm.delete(key);       // true
```

```js
// 典型用途：缓存计算结果（对象作键，对象销毁缓存自动释放）
const cache = new WeakMap();

function getArea(shape) {
  if (cache.has(shape)) return cache.get(shape);
  const area = shape.width * shape.height;
  cache.set(shape, area);
  return area;
}
```

```js
// 私有数据：WeakMap 存实例私有状态
const privateData = new WeakMap();

class User {
  constructor(name) {
    privateData.set(this, { name });
  }
  getName() {
    return privateData.get(this).name;
  }
}
```

```text
WeakMap 的限制（与 Map 的区别）：
1. 键必须是对象（不能是原始值）
2. 弱引用 —— 键对象无其他引用时可被 GC，避免内存泄漏
3. 不可迭代 —— 无 size、无 keys/values/entries（因为随时可能被回收）
4. 用途 —— 缓存、私有数据、元数据，键的生命周期与对象绑定
```

## Set 集合

Set 是唯一值的集合，自动去重，保持插入顺序。

```js
const set = new Set();

set.add(1);
set.add(2);
set.add(2);          // 重复值被忽略
set.size;            // 2

set.has(1);          // true
set.delete(1);       // true
```

```js
// 去重
const unique = [...new Set([1, 2, 2, 3, 3, 3])];   // [1, 2, 3]

// 遍历
for (const v of set) console.log(v);
```

```js
// 集合运算
const a = new Set([1, 2, 3]);
const b = new Set([2, 3, 4]);

// 并集
new Set([...a, ...b]);          // {1,2,3,4}
// 交集
new Set([...a].filter(x => b.has(x)));   // {2,3}
// 差集
new Set([...a].filter(x => !b.has(x)));  // {1}
```

```text
Set 的价值：
1. 去重 —— 一行代码去重数组
2. 存在判断 —— has 比 includes 更语义化（O(1)）
3. 集合运算 —— 并集、交集、差集
```

## WeakSet 弱集合

WeakSet 的值必须是对象，且是弱引用，常用于标记对象状态。

```js
const ws = new WeakSet();

const obj1 = { id: 1 };
ws.add(obj1);
ws.has(obj1);        // true
ws.delete(obj1);     // true
```

```js
// 典型用途：标记「已处理」的对象
const visited = new WeakSet();

function process(node) {
  if (visited.has(node)) return;   // 已处理，跳过
  visited.add(node);
  // ... 处理
}
```

```text
WeakSet 的限制：
1. 值必须是对象
2. 弱引用（不阻止 GC）
3. 不可迭代（无 size、无遍历）
4. 用途 —— 标记对象状态、去重对象引用
```

## 应用场景实战

### 场景一：用 Map 做高效查找

```js
// 对象数组转 Map，按 id 快速查找
const users = [{ id: 1, name: 'A' }, { id: 2, name: 'B' }];
const userMap = new Map(users.map(u => [u.id, u]));

userMap.get(2);   // { id: 2, name: 'B' }（O(1) 查找）
```

### 场景二：WeakMap 缓存防泄漏

```js
const cache = new WeakMap();
function compute(obj) {
  if (cache.has(obj)) return cache.get(obj);
  const result = expensiveCalc(obj);
  cache.set(obj, result);
  return result;
}
// obj 被外部释放后，缓存条目自动回收，不泄漏
```

## 最佳实践与踩坑记录

### 最佳实践

1. 字典/任意类型键用 Map，别用普通对象
2. 去重用 Set，存在判断用 Set.has
3. 缓存对象计算结果用 WeakMap（防内存泄漏）
4. 私有数据可用 WeakMap（键绑定实例）
5. 标记对象状态用 WeakSet

### 踩坑记录

```text
坑 1：用普通对象当字典导致原型污染
结论：obj['__proto__'] 等键引发安全问题。
原因：对象有原型链，特殊键名会冲突。
解法：用 Map 或 Object.create(null)。

坑 2：WeakMap 键用原始值
结论：wm.set('key', 1) 报 TypeError。
原因：WeakMap 键必须是对象。
解法：用 Map（键任意类型），或把原始值包成对象。

坑 3：WeakMap 不可遍历
结论：想遍历 WeakMap 发现没有 size/keys。
原因：弱引用设计，内容随时可能被 GC。
解法：需要遍历用 Map。

坑 4：Map 的键是对象时用 === 比较
结论：两个「相同内容」的对象是不同的键。
原因：Map 键按引用（SameValueZero）比较。
解法：需要按内容作键，用字符串序列化或自定义键。

坑 5：Set 存对象去重失败
结论：两个内容相同的对象都能加入 Set。
原因：Set 按引用去重，不同对象引用不相等。
解法：去重基础类型用 Set，对象去重需按字段处理。
```

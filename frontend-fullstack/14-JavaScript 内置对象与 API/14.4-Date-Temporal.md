## 概述

Date 是 JavaScript 处理日期时间的内置对象，但它的 API 设计混乱、时区处理易错。Temporal 是正在推进的新标准，提供更清晰、不可变的日期时间处理。

```text
日期时间处理的核心难点：
1. 时区 —— 同一时刻在不同地区显示不同
2. 格式化 —— 各地区日期格式不同
3. 可变性 —— Date 对象可变，容易被意外修改
4. 精度 —— 秒、毫秒、微秒、纳秒

现状：Date 仍是主流，Temporal 是未来（Stage 3 提案）。
```

## Date 对象

Date 表示时间点，内部是 UTC 时间戳（毫秒），提供大量读写方法。

```js
// 创建
const now = new Date();                    // 当前时间
const specific = new Date('2026-01-15');   // 指定日期字符串
const fromParts = new Date(2026, 0, 15);   // 年月日（月从 0 开始！）
const fromTimestamp = new Date(1700000000000);  // 时间戳
```

```js
// 读取（本地时间）
const d = new Date('2026-01-15T10:30:00');
d.getFullYear();      // 2026
d.getMonth();         // 0（1 月，月从 0 开始！）
d.getDate();          // 15
d.getHours();         // 10（本地时区）
d.getDay();           // 星期几（0=周日）

// 读取（UTC）
d.getUTCFullYear();
d.getUTCHours();
```

```js
// 时间戳与格式化
d.getTime();          // 毫秒时间戳
Date.now();           // 当前时间戳（毫秒）
d.toISOString();      // '2026-01-15T02:30:00.000Z'（UTC 标准格式）
```

```text
Date 的坑：
1. 月份从 0 开始 —— getMonth() 返回 0-11
2. 解析字符串差异 —— new Date('2026-01-15') 是 UTC，'2026/01/15' 是本地
3. 可变对象 —— setXxx 会修改原 Date
4. 时区混乱 —— getHours 本地、getUTCHours UTC
```

## Timezone 时区

Date 内部存 UTC 时间戳，显示时按本地时区。时区是「同一时刻的不同表示」。

```js
const d = new Date('2026-01-15T10:30:00Z');   // UTC 10:30

// 本地时区显示
d.getHours();          // 取决于运行环境的时区（如北京 UTC+8 → 18）
d.getUTCHours();       // 10（始终 UTC）
```

```js
// 获取时区偏移（分钟）
d.getTimezoneOffset();  // 本地时区相对 UTC 的偏移（如 UTC+8 → -480）
```

```text
时区处理的要点：
1. 存储用 UTC（时间戳/ISO 字符串）
2. 显示时转本地时区
3. 跨时区应用要明确「展示时区」与「存储时区」
```

```js
// 获取时区名（现代 API）
Intl.DateTimeFormat().resolvedOptions().timeZone;   // 'Asia/Shanghai'
```

## UTC 协调世界时

UTC 是时间基准，Date 内部就是 UTC 时间戳。读写都有 UTC 对应方法。

```js
const d = new Date();

// 本地 vs UTC 方法对照
d.getHours();        // 本地小时
d.getUTCHours();     // UTC 小时
d.setHours(10);      // 设本地小时
d.setUTCHours(10);   // 设 UTC 小时
```

```js
// ISO 8601 标准格式（UTC）
const iso = new Date().toISOString();   // '2026-08-13T12:00:00.000Z'
```

```text
UTC 的使用原则：
1. 持久化存 UTC（ISO 字符串或时间戳）
2. 计算用时间戳（毫秒差值）
3. 展示转本地或目标时区
```

## Intl.DateTimeFormat 格式化

Intl.DateTimeFormat 按地区（locale）格式化日期时间，替代手写格式化。

```js
const d = new Date('2026-01-15T10:30:00');

// 基础格式化
new Intl.DateTimeFormat('zh-CN').format(d);        // '2026/1/15'
new Intl.DateTimeFormat('en-US').format(d);        // '1/15/2026'

// 指定格式
new Intl.DateTimeFormat('zh-CN', {
  year: 'numeric',
  month: 'long',
  day: 'numeric',
  weekday: 'long',
}).format(d);                                       // '2026年1月15日星期四'

// 时间
new Intl.DateTimeFormat('en-US', {
  hour: 'numeric',
  minute: 'numeric',
  hour12: true,
}).format(d);                                       // '10:30 AM'
```

```js
// 指定时区格式化
new Intl.DateTimeFormat('zh-CN', {
  timeZone: 'America/New_York',
  dateStyle: 'full',
  timeStyle: 'long',
}).format(d);
```

```text
Intl.DateTimeFormat 的价值：
1. 本地化 —— 自动按地区格式
2. 时区转换 —— timeZone 选项指定时区
3. 避免手写 —— 不用自己拼 YYYY-MM-DD
```

## Temporal 新日期 API

Temporal 是 TC39 正在推进的新日期时间 API（Stage 3），解决 Date 的混乱，提供不可变、区分「时刻/日期/时区」的清晰模型。

```text
Temporal 的核心类型：
Temporal.Instant —— 精确时刻（时间戳，纳秒精度）
Temporal.PlainDate —— 纯日期（无时区，如 2026-01-15）
Temporal.PlainTime —— 纯时间（无时区）
Temporal.PlainDateTime —— 日期+时间（无时区）
Temporal.ZonedDateTime —— 带时区的日期时间
Temporal.Duration —— 时长
```

```js
// Temporal 示例（需 polyfill 或支持环境）
const date = Temporal.PlainDate.from('2026-01-15');
date.year;              // 2026
date.month;             // 1（月从 1 开始！修正了 Date 的坑）

const zoned = Temporal.ZonedDateTime.from('2026-01-15T10:30[Asia/Shanghai]');
zoned.withTimeZone('UTC');   // 时区转换

const duration = Temporal.Duration.from({ hours: 1, minutes: 30 });
```

```text
Temporal vs Date：
Temporal —— 不可变、月从 1 开始、区分日期/时刻/时区、纳秒精度
Date —— 可变、月从 0 开始、概念混淆、毫秒精度

Temporal 目前是 Stage 3 提案，生产需 polyfill（@js-temporal/polyfill）。
```

## 应用场景实战

### 场景一：格式化展示日期

```js
function formatDate(isoString) {
  return new Intl.DateTimeFormat('zh-CN', {
    year: 'numeric',
    month: '2-digit',
    day: '2-digit',
  }).format(new Date(isoString));
}
formatDate('2026-01-15T10:30:00Z');   // '2026/01/15'
```

### 场景二：计算时间差

```js
const start = new Date('2026-01-01').getTime();
const end = new Date('2026-01-15').getTime();

const diffDays = (end - start) / (1000 * 60 * 60 * 24);   // 14
```

## 最佳实践与踩坑记录

### 最佳实践

1. 持久化存 UTC（ISO 字符串或时间戳）
2. 格式化用 Intl.DateTimeFormat，别手写
3. 月份注意从 0 开始（Date），或直接用 Temporal
4. 时间差计算用时间戳（毫秒）
5. 跨时区显示用 timeZone 选项

### 踩坑记录

```text
坑 1：月份从 0 开始
结论：getMonth() 返回 0 代表 1 月，new Date(2026, 0) 是 1 月。
原因：历史设计，月份 0-11。
解法：+1 处理，或直接用 Temporal（月从 1 开始）。

坑 2：字符串解析时区歧义
结论：new Date('2026-01-15') 与 '2026/01/15' 时区不同。
原因：ISO 格式按 UTC，斜杠格式按本地。
解法：统一用 ISO 8601 或时间戳。

坑 3：getHours 返回本地时区
结论：服务器（UTC）和浏览器（本地）的 getHours 不同。
原因：getHours 是本地时间，getUTCHours 是 UTC。
解法：明确用 UTC 方法或指定时区格式化。

坑 4：Date 对象可变
结论：setXxx 修改原对象，多处共享导致错乱。
原因：Date 是可变对象。
解法：需要不可变时用时间戳或 Temporal。

坑 5：用 Date 做日期运算（加减天）
结论：直接加毫秒在天数上出错（跨时区/夏令时）。
原因：天不是固定毫秒数（夏令时 23/25 小时）。
解法：用 Temporal 的 add 方法，或手动处理日历。
```

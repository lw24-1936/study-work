## 概述

原始类型（Primitive）是 JavaScript 最基础的值类型，共有 7 种。它们与对象（Object）在存储、比较、可变性上有着本质区别，理解这些区别是理解 JavaScript 一切行为的地基。

```text
7 种原始类型：
Undefined、Null、Boolean、Number、BigInt、String、Symbol

三大核心特性：
1. Immutable —— 不可变，值不能被修改
2. Value Semantics —— 值语义，按值存储与比较
3. Boxing —— 需要时可临时装箱为对象
```

## Primitive 原始值

原始值直接存储在变量中（通常栈上），不通过引用访问。它们没有属性、没有方法（方法调用依赖临时装箱）。

```js
// 原始值
const str = 'hello';
const num = 42;
const bool = true;
const nil = null;
const undef = undefined;
const big = 42n;
const sym = Symbol('x');

// 原始值「看似」有方法，其实是装箱
'hello'.toUpperCase();    // 运行时临时装箱为 String 对象
(42).toString();          // 同理
```

```text
原始值的识别：
typeof 返回对应类型（null 除外，历史返回 'object'）
原始值可以直接 === 比较，比较的是值本身
```

## Immutable 不可变性

原始值一旦创建就**不可修改**。任何「修改」操作实际上是创建新值并重新绑定变量。

```js
let s = 'hello';
s.toUpperCase();     // 返回 'HELLO'，但不改变 s
console.log(s);      // 'hello'（原值不变）

s = s.toUpperCase(); // 重新赋值才「改变」变量
console.log(s);      // 'HELLO'
```

```text
不可变性的含义：
1. 值本身无法被篡改 —— 没有方法能改 'hello' 的内部字符
2. 「修改」= 创建新值 + 重新赋值
3. 对比对象：对象可变，能直接改内部属性
```

```js
// 对比：对象可变
const obj = { name: 'a' };
obj.name = 'b';      // 直接改属性，对象本身没变
console.log(obj);    // { name: 'b' }
```

## Value Semantics 值语义

原始类型遵循**值语义**：赋值是值拷贝，比较是值比较；而对象遵循引用语义。

```js
// 值语义：赋值拷贝值
let a = 10;
let b = a;
b = 20;
console.log(a);      // 10（不受 b 影响）

// 值语义：比较值
'abc' === 'abc';     // true
10 === 10;           // true

// 对比：对象引用语义
const o1 = { x: 1 };
const o2 = o1;
o2.x = 2;
console.log(o1.x);   // 2（同一引用，互相影响）
```

```text
值语义 vs 引用语义总结：
原始类型 —— 值本身，赋值/传参是拷贝，比较是值相等
对象类型 —— 引用地址，赋值/传参是引用，比较是地址相同
```

## Boxing 装箱与拆箱

Boxing（装箱）：访问原始值的方法/属性时，引擎临时把它包装成对应的对象类型；Boxing 的反向操作是 Unboxing（拆箱）。

```text
装箱机制：
String 原始值 → new String() 对象（调用方法后立即丢弃）
Number 原始值 → new Number() 对象
Boolean 原始值 → new Boolean() 对象

Symbol/BigInt 也有包装对象，但通常不直接 new。
```

```js
// 自动装箱：'hello' 是原始值，调用 toUpperCase 时临时装箱
const upper = 'hello'.toUpperCase();

// 等价于引擎内部：
// const tmp = new String('hello');
// const upper = tmp.toUpperCase();
```

```js
// 显式装箱（不推荐，会产生对象）
const boxed = new String('hello');
typeof boxed;        // 'object'（不再是原始值）
typeof 'hello';      // 'string'

boxed === 'hello';   // false（对象 !== 原始值）
```

```text
装箱的陷阱：
new String('x') 创建的是对象，不是原始值。
对象在条件判断中永远为真（即使值是空串）。
所以 new Boolean(false) 是真值！这就是避免显式装箱的原因。
```

```js
// 拆箱：对象转原始值
const n = new Number(42);
n + 0;               // 42（拆箱为原始值参与运算）
```

## 原始类型 vs 对象

```text
对比维度       原始类型          对象
可变性         不可变            可变
存储           按值（栈）        按引用（堆）
比较           值相等            引用相等
属性           无（临时装箱）    有
类型判定       typeof            instanceof / Object.prototype.toString
```

```js
// 类型判定差异
typeof 'x';                          // 'string'
typeof {};                           // 'object'
Object.prototype.toString.call([]);  // '[object Array]'
Object.prototype.toString.call('x'); // '[object String]'
```

## 应用场景实战

### 场景一：函数参数不会意外被修改

```js
// 原始类型传参是值拷贝，函数内改不影响外部
function change(n) {
  n = 999;
  return n;
}
let count = 1;
change(count);
console.log(count);    // 1（外部不变）

// 对象传参是引用，会被修改
function changeObj(o) {
  o.n = 999;
}
const obj = { n: 1 };
changeObj(obj);
console.log(obj.n);    // 999（被修改了）
```

### 场景二：避免显式装箱

```js
// 反例：new String 产生对象，条件判断永远真
const flag = new Boolean(false);
if (flag) console.log('永远会打印');   // 因为对象是真值

// 正例：直接用原始值
const flag2 = false;
if (flag2) console.log('不会打印');
```

## 最佳实践与踩坑记录

### 最佳实践

1. 永远用原始值（'x'、42、false），不要 new String/Number/Boolean
2. 理解传参：原始类型按值、对象按引用，避免意外修改
3. 比较原始值用 ===，比较对象前先想清楚是比引用还是内容
4. 利用不可变性：原始值做 key、做比较都安全
5. 需要「可修改的字符串/数字」场景时，显式用数组或对象

### 踩坑记录

```text
坑 1：new Boolean(false) 是真值
结论：if (new Boolean(false)) 进了 true 分支。
原因：对象无论内容如何，条件判断都为真。
解法：不要显式装箱，直接用原始布尔值。

坑 2：字符串「修改」无效
结论：str[0] = 'X' 没报错但没生效。
原因：原始值不可变，索引赋值被静默忽略（非严格模式）。
解法：用 str.replace 或拆成数组再 join。

坑 3：比较时混淆值语义与引用语义
结论：两个内容相同的对象 === 为 false。
原因：对象比较引用，内容相同不代表引用相同。
解法：对象比引用用 ===，比内容用深比较或 JSON.stringify。

坑 4：原始值当对象用导致性能损耗
结论：高频调用原始值方法有装箱开销。
原因：每次方法调用都临时装箱。
解法：极热路径可用缓存或避免频繁装箱（一般无需过度优化）。

坑 5：null 的类型判断
结论：typeof null 得到 'object'。
原因：历史 bug。
解法：null 用 === null 判断，不要依赖 typeof。
```

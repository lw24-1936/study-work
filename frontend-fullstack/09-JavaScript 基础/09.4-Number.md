## 概述

JavaScript 只有一种数值类型 Number，采用 IEEE 754 双精度浮点数格式，既表示整数也表示小数。这一设计带来了精度、特殊值等需要特别注意的问题。

```text
Number 的核心问题：
1. 双精度浮点 —— 所有数字都是 64 位浮点，没有真正的整数类型
2. 精度上限 —— 安全整数范围 ±(2^53 - 1)
3. 浮点误差 —— 0.1 + 0.2 !== 0.3
4. 特殊值 —— NaN、Infinity、-0
```

## IEEE 754 双精度浮点

Number 遵循 IEEE 754 双精度（64 位）标准：1 位符号 + 11 位指数 + 52 位尾数，用二进制科学计数法存储。

```text
64 位分布：
符号位（1 bit）—— 正负号
指数位（11 bit）—— 决定数值范围（约 ±1.8e308）
尾数位（52 bit）—— 决定精度（有效数字约 15-17 位十进制）

本质：十进制小数转二进制时，很多小数是无限循环的，存储时被截断，产生误差。
```

```js
// 浮点误差
0.1 + 0.2;           // 0.30000000000000004
0.1 + 0.2 === 0.3;   // false

// 正确比较方式
Math.abs(0.1 + 0.2 - 0.3) < Number.EPSILON;   // true
```

```text
浮点误差的应对：
1. 金额计算 —— 转成分（整数）运算，避免小数
2. 比较 —— 用 Number.EPSILON 容差判断
3. 展示 —— 用 toFixed 保留位数（注意它返回字符串）
```

```js
// 金额：用整数分计算
const total = (0.1 * 100 + 0.2 * 100) / 100;   // 0.3
// 或直接以分为单位
const cents = 10 + 20;                          // 30 分
```

## NaN 非数值

NaN（Not a Number）表示「非数值」，是 Number 类型的一个特殊值，用于表示无法计算的结果。

```text
NaN 的特性：
1. 任何涉及 NaN 的运算结果都是 NaN
2. NaN 不等于任何值，包括它自己
3. typeof NaN 是 'number'
```

```js
NaN;                 // NaN
0 / 0;               // NaN
parseInt('abc');     // NaN
Number('abc');       // NaN
Math.sqrt(-1);       // NaN

NaN === NaN;         // false（不等自身）
```

```js
// 判断 NaN 必须用 Number.isNaN 或 isNaN
Number.isNaN(NaN);   // true
isNaN(NaN);          // true

// 二者的区别：全局 isNaN 会先做类型转换
Number.isNaN('abc'); // false（'abc' 不是 number 类型，不做转换）
isNaN('abc');        // true（先 Number('abc') 得到 NaN）
```

## Infinity 与 -0

Infinity 表示正无穷（数值溢出），-Infinity 表示负无穷；-0 是一个特殊的负零。

```js
1 / 0;               // Infinity
-1 / 0;              // -Infinity
Number.MAX_VALUE * 2; // Infinity（溢出）

Infinity > 999999;   // true
```

```text
-0 的诡异之处：
0 === -0 为 true（严格相等），但 1 / 0 与 1 / -0 不同。
```

```js
-0;                  // -0
0 === -0;            // true
1 / 0;               // Infinity
1 / -0;              // -Infinity

// 判断 -0：Object.is
Object.is(-0, 0);    // false
Object.is(-0, -0);   // true
```

```text
Object.is 与 === 的区别：
Object.is(NaN, NaN)  // true（=== 为 false）
Object.is(-0, 0)     // false（=== 为 true）
其余情况与 === 一致。
```

## Number.MAX_SAFE_INTEGER 安全整数

Number 能精确表示的整数范围是 ±(2^53 - 1)，超出后相邻整数无法区分，会产生精度丢失。

```js
Number.MAX_SAFE_INTEGER;   // 9007199254740991（2^53 - 1）
Number.MIN_SAFE_INTEGER;   // -9007199254740991

// 安全范围内
Number.isSafeInteger(9007199254740991);   // true

// 超出安全范围，精度丢失
9007199254740992;   // 9007199254740992
9007199254740993;   // 9007199254740992（被四舍五入到同一个值！）
```

```text
安全整数的意义：
1. 超过 MAX_SAFE_INTEGER 的整数运算不可靠
2. 判断用 Number.isSafeInteger()
3. 大数据 ID（如雪花 ID）需用 BigInt 或字符串传输
```

## Number.isNaN / isFinite / isInteger

ES6 引入的 Number 静态方法，相比全局函数更严格（不做隐式类型转换）。

```text
三个严格判断方法：
Number.isNaN(value)      —— 值是否严格等于 NaN（不转换）
Number.isFinite(value)   —— 值是否为有限数（不转换）
Number.isInteger(value)  —— 值是否为整数（不转换）
```

```js
// Number.isNaN vs 全局 isNaN
Number.isNaN('abc');   // false（不转换）
isNaN('abc');          // true（先转换）

// Number.isFinite vs 全局 isFinite
Number.isFinite('42'); // false（字符串不转换）
isFinite('42');        // true（先转换）

// Number.isInteger
Number.isInteger(42);      // true
Number.isInteger(42.0);    // true
Number.isInteger(42.5);    // false
Number.isInteger('42');    // false（不转换）
```

```text
使用建议：
优先用 Number.* 系列（严格、无隐式转换陷阱），
全局 isNaN / isFinite 仅在明确需要先转换时使用。
```

## BigInt 大整数

BigInt 是 ES2020 引入的独立类型，用于表示任意精度的大整数，弥补 Number 的精度上限。

```js
const big = 9007199254740993n;   // n 后缀
const b2 = BigInt(42);            // 从 Number 转换

big + 1n;                         // 9007199254740994n（精确）
```

```text
BigInt 使用限制：
1. 不能与 Number 直接运算 —— 1n + 1 报错，需 BigInt(1) + 1n
2. 不能用于 Math 方法 —— Math.max(1n, 2n) 报错
3. 与 Number 宽松相等、严格不等 —— 1n == 1 true，1n === 1 false
4. 不支持 JSON.stringify —— 序列化会报错，需先转字符串
```

```js
// 混算需显式转换
BigInt(1) + 1n;        // 2n

// 比较
1n == 1;               // true（宽松）
1n === 1;              // false（严格，类型不同）

// 大数 ID 场景：后端返回字符串，前端用 BigInt 处理
const id = BigInt('900719925474099312345');
```

## 应用场景实战

### 场景一：金额精确计算

```js
// 反例：浮点直接算
0.1 + 0.2;               // 0.30000000000000004

// 正例：转整数分计算
function addMoney(a, b) {
  return (Math.round(a * 100) + Math.round(b * 100)) / 100;
}
addMoney(0.1, 0.2);      // 0.3
```

### 场景二：大数 ID 处理

```js
// 后端返回超长 ID（字符串），前端避免 Number 丢失精度
const rawId = '900719925474099312345';
const id = BigInt(rawId);
// 展示或传输时转回字符串
id.toString();
```

## 最佳实践与踩坑记录

### 最佳实践

1. 金额用整数（分）或 BigInt，避免浮点运算
2. 比较浮点数用 Number.EPSILON 容差
3. 判断 NaN 用 Number.isNaN，避免全局 isNaN 的转换坑
4. 大整数（ID、哈希）用 BigInt 或字符串，不用 Number
5. 用 Object.is 精确区分 -0 与 0（需要时）

### 踩坑记录

```text
坑 1：0.1 + 0.2 !== 0.3
结论：浮点运算结果有误差。
原因：二进制无法精确表示十进制小数。
解法：金额转整数、比较用 EPSILON、展示用 toFixed。

坑 2：NaN !== NaN
结论：用 === 判断 NaN 永远 false。
原因：NaN 设计上不等于任何值。
解法：用 Number.isNaN(value)。

坑 3：全局 isNaN 误判字符串
结论：isNaN('123') 返回 false（其实是数字），isNaN('') 返回 false。
原因：全局 isNaN 先做 Number() 转换，'' 转成 0。
解法：用 Number.isNaN 严格判断。

坑 4：大整数 ID 精度丢失
结论：ID 前后不一致，尾数变了。
原因：超过 Number.MAX_SAFE_INTEGER。
解法：BigInt 或字符串传输，前端不转 Number。

坑 5：BigInt 序列化报错
结论：JSON.stringify 含 BigInt 抛异常。
原因：BigInt 不在 JSON 支持类型内。
解法：序列化前 BigInt 转字符串，或自定义 toJSON。
```

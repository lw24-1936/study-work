## 概述

ES Modules（ESM）是 ECMAScript 官方的模块规范，用 import/export 组织代码。它是静态的、异步的，是浏览器与 Node.js 现代项目的事实标准。

```text
ESM 核心特性：
1. 静态结构 —— 导入导出在编译期确定（可做 tree shaking）
2. 异步加载 —— 浏览器中并行加载依赖
3. 引用绑定 —— 导入的是「实时引用」，非值拷贝
4. 严格模式 —— 模块自动处于严格模式
5. 作用域隔离 —— 顶层 this 为 undefined
```

## import 引入

import 静态导入模块，在模块顶部声明。

```js
// 命名导入
import { add, multiply } from './utils.js';

// 默认导入
import greet from './greet.js';

// 命名空间导入
import * as utils from './utils.js';

// 混合导入
import greet, { add } from './math.js';

// 仅执行副作用（不导入任何绑定）
import './init.js';
```

```text
import 的特点：
1. 静态声明 —— 必须在模块顶部，不能写在条件/循环里
2. 提升 —— import 声明会被提升到顶部
3. 路径必须完整 —— 浏览器中需带扩展名（.js），Node 也有规则
4. 只读 —— 导入的绑定不能重新赋值
```

## export 导出

export 导出命名绑定，供其他模块导入。

```js
// 命名导出（声明时导出）
export const PI = 3.14;
export function add(a, b) { return a + b; }
export class Point {}

// 声明后统一导出
const x = 1;
const y = 2;
export { x, y };

// 重命名导出
export { x as xx, y as yy };
```

```js
// 重新导出（re-export）
export { foo } from './a.js';
export * from './b.js';              // 全量转发
export { default } from './c.js';    // 转发默认导出
```

## Default Export 默认导出

默认导出是模块的「主要」导出，每个模块最多一个，导入时可用任意名字。

```js
// 默认导出
export default function greet(name) {
  return `Hello, ${name}`;
}

// 或
export default class User {}
```

```js
// 默认导入（名字任意）
import greet from './greet.js';
import anyName from './greet.js';   // 名字可自定义
```

```text
默认导出 vs 命名导出：
默认导出 —— 一个模块一个，导入名可自定义，适合「主功能」
命名导出 —— 可多个，导入名必须匹配（可 as 重命名），适合「工具集」
```

## Named Export 命名导出

命名导出通过名字匹配导入，可导出多个绑定，支持 as 重命名。

```js
// utils.js —— 多个命名导出
export const add = (a, b) => a + b;
export const multiply = (a, b) => a * b;
export const divide = (a, b) => a / b;
```

```js
// 命名导入
import { add, multiply } from './utils.js';

// 重命名导入
import { add as sum } from './utils.js';

// 命名空间导入（一次性拿全部）
import * as utils from './utils.js';
utils.add(1, 2);
```

## Dynamic Import 动态导入

import() 动态导入模块，返回 Promise，支持按需加载、条件加载。

```js
// 动态导入：返回 Promise
import('./module.js').then(module => {
  module.default();   // 默认导出
  module.named();     // 命名导出
});
```

```js
// 按需加载：路由懒加载
const route = await import(`./pages/${name}.js`);

// 条件加载
if (featureEnabled) {
  const { heavy } = await import('./heavy.js');
  heavy();
}
```

```text
动态导入的价值：
1. 按需加载 —— 组件/路由懒加载，减小首屏体积
2. 条件加载 —— 只在需要时加载
3. 代码分割 —— 配合构建工具拆包
4. 与静态 import 不同 —— 可在函数内、条件内使用
```

## import.meta 模块元信息

import.meta 提供当前模块的元信息，如 import.meta.url（模块 URL）。

```js
// 模块自身的 URL
console.log(import.meta.url);
// 浏览器：http://example.com/app.js
// Node：file:///path/to/app.js

// 获取当前目录
const dir = new URL('.', import.meta.url).pathname;

// import.meta.env（Vite 等工具注入）
console.log(import.meta.env.MODE);
```

```text
import.meta 的用途：
1. import.meta.url —— 获取模块 URL（定位资源）
2. import.meta.resolve —— 解析模块路径
3. 构建工具注入 —— import.meta.env（Vite）、import.meta.glob 等
```

## 应用场景实战

### 场景一：统一出口（barrel 模式）

```js
// index.js —— 统一导出，简化导入路径
export { default as Button } from './Button.js';
export { default as Input } from './Input.js';
export * from './utils.js';

// 使用
import { Button, Input } from './components/index.js';
```

### 场景二：路由懒加载

```js
const routes = [
  { path: '/home', component: () => import('./Home.js') },
  { path: '/about', component: () => import('./About.js') },
];
```

## 最佳实践与踩坑记录

### 最佳实践

1. 优先用命名导出（利于 tree shaking），默认导出用于单一主功能
2. 组件库用 barrel 文件统一出口
3. 懒加载用动态 import，配合代码分割
4. 避免循环依赖
5. 明确扩展名与路径，跨环境一致性

### 踩坑记录

```text
坑 1：默认导入名与导出名混淆
结论：默认导出用命名导入方式，拿到 undefined。
原因：默认导出要用默认导入语法，命名导出要用花括号。
解法：import defaultX from './m'（默认），import { named } from './m'（命名）。

坑 2：命名导出后声明
结论：export { x } 后修改 x，导入方拿到最新值（实时引用）。
原因：ESM 是引用绑定，非值拷贝。
解法：理解实时引用语义，避免导出可变绑定。

坑 3：浏览器里 import 忘扩展名
结论：import './utils' 报 404。
原因：浏览器不会自动补 .js 扩展名。
解法：浏览器环境写全扩展名 .js。

坑 4：静态 import 写在条件里
结论：if 里写 import 报语法错误。
原因：静态 import 只能在模块顶层。
解法：条件加载用动态 import()。

坑 5：混用默认与命名导出
结论：import defaultX, { named } 顺序或语法写错。
原因：默认导入在前，命名导入在后，语法固定。
解法：import 默认名, { 命名 } from '...'。
```

## 概述

CommonJS 是 Node.js 的默认模块规范，用 require 引入、module.exports 导出。它是同步的、运行时的，服务于服务端「本地文件加载」的场景。

```text
CommonJS 核心特性：
1. 同步加载 —— require 时同步读取并执行模块
2. 运行时解析 —— 模块结构在运行时才确定
3. 值拷贝 —— 导出的值是对原值的拷贝
4. 缓存 —— 同一模块只加载执行一次
5. 作用域隔离 —— 每个模块有独立作用域
```

## require 引入

require 同步加载模块，返回模块的导出对象。

```js
// 引入内置模块
const fs = require('fs');
const path = require('path');

// 引入本地模块（相对路径）
const utils = require('./utils.js');

// 引入 npm 包（从 node_modules 查找）
const express = require('express');

// 引入 JSON（直接解析为对象）
const config = require('./config.json');
```

```text
require 的查找规则：
1. 核心模块（fs、path）—— 直接返回
2. 相对/绝对路径（./、../、/）—— 按路径查找
3. 裸模块名（express）—— 沿 node_modules 逐级向上查找
4. 找不到 → 抛 MODULE_NOT_FOUND
```

## module.exports 导出

module.exports 是模块的导出对象，require 返回的就是它。

```js
// utils.js
function add(a, b) { return a + b; }
function multiply(a, b) { return a * b; }

module.exports = {
  add,
  multiply,
};
```

```js
// main.js
const utils = require('./utils.js');
utils.add(1, 2);        // 3
```

```js
// 导出单个函数
module.exports = function greet(name) {
  return `Hello, ${name}`;
};

// 引入后直接调用
const greet = require('./greet.js');
greet('Alice');
```

```text
module.exports 的本质：
1. 每个模块是一个函数，参数包含 module、exports
2. module.exports 是最终导出的对象
3. require 返回 module.exports
```

## exports 简写

exports 是 module.exports 的引用，可直接挂属性，但不能重新赋值。

```js
// 正例：exports 挂属性（等价 module.exports.xxx = xxx）
exports.add = function(a, b) { return a + b; };
exports.multiply = function(a, b) { return a * b; };
```

```js
// 反例：重新赋值 exports 会失效
exports = { add: function() {} };   // 无效！exports 被重新赋值，断了引用

// 正确：要导出整个对象，用 module.exports
module.exports = { add: function() {} };
```

```text
exports vs module.exports：
exports —— module.exports 的别名（引用）
挂属性 —— exports.foo = xxx（二者都行）
整体替换 —— 只能用 module.exports = xxx（重新赋值 exports 无效）

原因：require 返回的是 module.exports，重新赋值 exports 只改了局部变量。
```

## require cache 缓存

require 有缓存机制：同一模块只加载执行一次，后续 require 直接返回缓存。

```js
// counter.js
console.log('模块被执行');
module.exports = { count: 0 };
```

```js
// main.js
const c1 = require('./counter.js');   // 打印「模块被执行」
const c2 = require('./counter.js');   // 不再打印（命中缓存）

c1 === c2;          // true（同一个对象）
```

```js
// 查看缓存
console.log(require.cache);           // 缓存对象

// 清除缓存（强制重新加载）
delete require.cache[require.resolve('./counter.js')];
```

```text
缓存的含义：
1. 模块初始化只执行一次
2. 所有 require 共享同一个导出对象（单例）
3. 适合放「有状态」的共享实例（如连接池）

注意：缓存的是「执行结果」，若导出的是函数工厂，则每次调用可产生新实例。
```

## 应用场景实战

### 场景一：导出函数工厂（避免缓存单例）

```js
// createStore.js —— 导出工厂，每次调用返回新实例
module.exports = function createStore() {
  return { count: 0 };
};

// 使用
const createStore = require('./createStore');
const store1 = createStore();   // 独立实例
const store2 = createStore();   // 独立实例
```

### 场景二：模块级共享状态

```js
// config.js —— 模块单例，共享配置
module.exports = {
  env: 'production',
  apiBase: 'https://api.example.com',
};
```

## 最佳实践与踩坑记录

### 最佳实践

1. 导出对象用 module.exports，别用 exports 整体赋值
2. 需要多实例用工厂函数导出，需要单例用对象导出
3. 理解缓存机制，避免误以为「重新 require 会重新执行」
4. 新项目（尤其前端）优先 ES Modules
5. require 动态拼接路径要谨慎（缓存与解析）

### 踩坑记录

```text
坑 1：exports 重新赋值失效
结论：exports = {...} 后导出为空对象。
原因：exports 只是 module.exports 的引用，重新赋值断了引用。
解法：整体导出用 module.exports，挂属性用 exports.xxx。

坑 2：误以为 require 会重新执行
结论：改了模块文件，但 require 拿到旧结果。
原因：require 缓存，第二次直接返回缓存。
解法：开发期清缓存，或用支持热更新的工具。

坑 3：循环依赖
结论：a require b，b require a，得到不完整的导出。
原因：循环依赖导致部分导出为 undefined。
解法：避免循环依赖，或延迟 require（函数内 require）。

坑 4：混用 ES Modules 与 CommonJS
结论：import 与 require 混用报错或不一致。
原因：两套模块系统语义不同（同步 vs 异步、拷贝 vs 引用）。
解法：统一模块系统，或用工具转译。

坑 5：导出值拷贝的误解
结论：修改导入的「值」，原模块不受影响（但对象属性会受影响）。
原因：CommonJS 导出值拷贝，但对象是引用。
解法：理解「基本类型拷贝、对象共享引用」。
```

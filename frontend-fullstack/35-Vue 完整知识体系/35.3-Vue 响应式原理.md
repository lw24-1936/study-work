## 概述

Vue 3 的响应式系统基于 ES6 Proxy 实现：读取属性时「追踪依赖」（收集 effect），写入属性时「触发更新」（通知 effect 重新执行）。相比 Vue 2 的 Object.defineProperty，Proxy 能拦截新增/删除属性、数组索引等操作。

```text
响应式系统的核心环节：
1. Reactive —— 用 Proxy 把对象包装成响应式代理
2. Ref —— 基本类型的响应式引用（内部走 Reactive 或 getter）
3. Proxy —— 拦截 get/set/deleteProperty 等操作
4. Dependency Tracking —— 读取时收集依赖（track）
5. Trigger —— 写入时触发依赖（trigger）
6. Effect —— 副作用函数，代表一次渲染/监听
7. Scheduler —— 调度器，批量异步执行 effect
```

```js
import { reactive, effect } from '@vue/reactivity';

const state = reactive({ count: 0 });
effect(() => {
  console.log(state.count); // 依赖收集：count -> effect
});
state.count = 1; // 触发更新，重新执行 effect
```

## Reactive

`reactive` 通过 `new Proxy(target, handlers)` 创建响应式对象，读取时 track，写入时 trigger。它使用 WeakMap 缓存，避免重复代理同一对象。

```js
import { reactive } from 'vue';

const state = reactive({
  count: 0,
  nested: { value: 1 },
});

state.count++; // 触发更新
state.nested.value++; // 深层响应式（读取 nested 时惰性代理）
state.newKey = 'a'; // 新增属性也响应式（Proxy 优势）
```

```text
Reactive 内部结构（简化）：
const reactiveMap = new WeakMap();
function reactive(target) {
  if (reactiveMap.has(target)) return reactiveMap.get(target);
  const proxy = new Proxy(target, baseHandlers);
  reactiveMap.set(target, proxy);
  return proxy;
}
```

## Ref

`ref` 用于基本类型，返回 `{ value }` 对象。通过 getter/setter 实现：读取 `.value` 时 track，写入时 trigger；对象则内部转成 reactive。

```js
import { ref } from 'vue';

const count = ref(0);

// 简化实现
class RefImpl {
  constructor(value) {
    this._value = value;
    this.dep = new Set(); // 依赖集合
  }
  get value() {
    track(this, 'value'); // 收集依赖
    return this._value;
  }
  set value(newVal) {
    if (newVal === this._value) return;
    this._value = newVal;
    trigger(this, 'value'); // 触发更新
  }
}
```

```text
Ref vs Reactive：
Ref —— 包装基本类型，需 .value，模板自动解包
Reactive —— 包装对象，直接访问，深层响应
```

## Proxy

Proxy 是响应式的基石，能拦截 13 种操作。Vue 3 用它替代 Vue 2 的 Object.defineProperty。

```js
const target = { count: 0 };
const proxy = new Proxy(target, {
  get(obj, key, receiver) {
    console.log('读取', key);
    return Reflect.get(obj, key, receiver);
  },
  set(obj, key, value, receiver) {
    console.log('写入', key, value);
    return Reflect.set(obj, key, value, receiver);
  },
  deleteProperty(obj, key) {
    console.log('删除', key);
    return Reflect.deleteProperty(obj, key);
  },
  has(obj, key) {
    console.log('in 判断', key);
    return Reflect.has(obj, key);
  },
});

proxy.count = 1; // 写入 count 1
```

```text
Proxy 相比 defineProperty 的优势：
1. 拦截新增/删除属性（defineProperty 无法拦截）
2. 拦截数组索引与 length 变化
3. 拦截 in、for...in 等操作
4. 惰性代理 —— 访问嵌套对象时才代理，性能更好
```

## Dependency Tracking

依赖追踪（track）发生在读取属性时：把「当前正在执行的 effect」记录到该属性的依赖集合中，建立「属性 → effect」的映射。

```js
// 依赖容器：targetMap -> key -> dep(Set<effect>)
const targetMap = new WeakMap();
let activeEffect = null; // 当前执行的 effect

function track(target, key) {
  if (!activeEffect) return; // 非 effect 内读取，不追踪
  let depsMap = targetMap.get(target);
  if (!depsMap) targetMap.set(target, (depsMap = new Map()));
  let dep = depsMap.get(key);
  if (!dep) depsMap.set(key, (dep = new Set()));
  dep.add(activeEffect); // 记录依赖
  activeEffect.deps.push(dep); // 反向记录，便于清理
}
```

```text
依赖追踪的数据结构：
targetMap（WeakMap）: target -> depsMap
depsMap（Map）: key -> dep
dep（Set）: 该 key 关联的所有 effect
```

## Trigger

触发更新（trigger）发生在写入属性时：找到该属性对应的依赖集合，通知所有 effect 重新执行。

```js
function trigger(target, key) {
  const depsMap = targetMap.get(target);
  if (!depsMap) return;
  const dep = depsMap.get(key);
  if (dep) {
    dep.forEach((effect) => {
      // 交给调度器执行（而非直接执行）
      if (effect.scheduler) {
        effect.scheduler();
      } else {
        effect.run();
      }
    });
  }
}
```

```text
trigger 细节：
1. 触发当前 key 的依赖
2. 数组 length 变化还会触发索引相关依赖
3. 有 scheduler 则交给 scheduler，否则直接 run
```

## Effect

Effect 是响应式系统中的「副作用函数」，代表一次渲染函数、computed 计算或 watch 回调。执行时通过 `activeEffect` 标记当前 effect，从而被 track 收集。

```js
class ReactiveEffect {
  constructor(fn, scheduler = null) {
    this.fn = fn;
    this.scheduler = scheduler;
    this.deps = [];
  }
  run() {
    // 执行前设置 activeEffect，让 track 能收集到自己
    cleanup(this); // 先清理旧依赖
    activeEffect = this;
    const result = this.fn();
    activeEffect = null;
    return result;
  }
}

function effect(fn, options = {}) {
  const _effect = new ReactiveEffect(fn, options.scheduler);
  _effect.run(); // 首次执行，收集依赖
  return _effect;
}

function cleanup(effect) {
  // 每次运行前清除旧依赖，避免脏依赖
  effect.deps.forEach((dep) => dep.delete(effect));
  effect.deps.length = 0;
}
```

```text
effect 的作用：
1. 组件的渲染函数是一个 effect
2. computed 内部是一个 effect
3. watch/watchEffect 内部是 effect
```

## Scheduler

Scheduler 是 effect 的调度器，用于控制更新时机。Vue 用调度器把多次数据变更合并为一次异步批量更新（微任务队列）。

```js
// 带调度器的 effect
const queue = new Set();
let flushing = false;

function queueJob(job) {
  queue.add(job);
  if (!flushing) {
    flushing = true;
    Promise.resolve().then(() => {
      queue.forEach((job) => job());
      queue.clear();
      flushing = false;
    });
  }
}

const state = reactive({ count: 0 });
effect(
  () => console.log(state.count),
  {
    scheduler(fn) {
      queueJob(fn); // 批量调度，不立即执行
    },
  },
);

state.count = 1;
state.count = 2; // 两次变更，最终只执行一次 effect
```

```text
Scheduler 的意义：
1. 批量更新 —— 同一 tick 多次变更合并为一次渲染
2. 避免重复计算 —— computed 惰性求值
3. nextTick 基于调度队列实现
```

## 应用场景实战

### 场景一：手写 mini 响应式系统

```js
const targetMap = new WeakMap();
let activeEffect = null;

function reactive(target) {
  return new Proxy(target, {
    get(obj, key) {
      track(obj, key);
      return Reflect.get(obj, key);
    },
    set(obj, key, value) {
      Reflect.set(obj, key, value);
      trigger(obj, key);
      return true;
    },
  });
}

function track(target, key) {
  if (!activeEffect) return;
  let depsMap = targetMap.get(target);
  if (!depsMap) targetMap.set(target, (depsMap = new Map()));
  let dep = depsMap.get(key);
  if (!dep) depsMap.set(key, (dep = new Set()));
  dep.add(activeEffect);
}

function trigger(target, key) {
  const dep = targetMap.get(target)?.get(key);
  dep?.forEach((fn) => fn());
}

function effect(fn) {
  activeEffect = fn;
  fn();
  activeEffect = null;
}

const state = reactive({ count: 0 });
effect(() => console.log(state.count)); // 0
state.count = 1; // 1
```

### 场景二：用 scheduler 实现防抖更新

```js
const state = reactive({ text: '' });
effect(
  () => render(state.text),
  {
    scheduler(fn) {
      clearTimeout(timer);
      timer = setTimeout(fn, 200); // 防抖
    },
  },
);
state.text = 'a';
state.text = 'ab';
state.text = 'abc'; // 只渲染一次 'abc'
```

## 最佳实践与踩坑记录

### 最佳实践

1. 理解「读取追踪、写入触发」是理解 Vue 响应式的钥匙
2. 避免在响应式对象上做无谓的深拷贝，破坏代理引用
3. 大对象惰性代理，只访问实际用到的嵌套层级
4. 用 computed 缓存派生值，减少 effect 重复执行
5. 熟悉 nextTick 与调度队列，正确处理异步更新时序

### 踩坑记录

```text
坑 1：reactive 对象整体替换丢失响应
结论：重新赋值整个 reactive 变量后，更新不再触发。
原因：新的普通对象没有被 Proxy 代理。
解法：用 Object.assign 修改，或把变量声明为 ref 包裹对象。

坑 2：解构 reactive 后失去响应
结论：const { count } = reactive({ count: 0 }) 后 count 不再响应。
原因：解构是值拷贝，脱离代理。
解法：用 toRefs 或 computed。

坑 3：effect 中收集了脏依赖
结论：分支条件变化后，effect 仍被无关属性触发。
原因：旧依赖未清理，遗留脏依赖。
解法：每次 run 前 cleanup 清空旧依赖（Vue 内部已处理）。

坑 4：Proxy 不能代理基本类型
结论：reactive(1) 报错或无效。
原因：Proxy 只能代理对象。
解法：基本类型用 ref。

坑 5：误以为修改立即更新 DOM
结论：连续改数据后立刻读 DOM 拿到旧值。
原因：更新是异步批量的（调度器）。
解法：用 nextTick 等待 DOM 更新完成。
```

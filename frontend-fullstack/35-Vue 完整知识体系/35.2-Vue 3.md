## 概述

Vue 3 引入了 Composition API，用 `setup` 函数组织逻辑，配合 `ref`/`reactive` 等响应式 API，解决了 Options API 中逻辑分散、复用困难的问题。其底层基于 Proxy 实现响应式，性能更强。

```text
Vue 3 核心 API：
1. Composition API —— 按功能组织代码，逻辑聚合
2. Options API —— 按选项（data/methods/computed）组织，Vue 2 风格
3. setup —— 组合式 API 的入口，在组件创建前执行
4. ref —— 基本类型的响应式包装（.value 访问）
5. reactive —— 对象的响应式代理（直接访问属性）
6. computed —— 计算属性（有缓存）
7. watch —— 监听特定数据源变化
8. watchEffect —— 自动追踪依赖并执行副作用
9. provide/inject —— 跨层级传递数据（依赖注入）
10. nextTick —— 等待 DOM 更新后执行回调
```

```js
import { ref } from 'vue';

export default {
  setup() {
    const count = ref(0);
    const increment = () => count.value += 1;
    return { count, increment };
  },
};
```

## Composition API

Composition API 允许在 `setup` 中按「功能」聚合逻辑，配合自定义组合式函数（composables）实现逻辑复用。

```js
// useCounter.js —— 组合式函数
import { ref, computed } from 'vue';

export function useCounter(initial = 0) {
  const count = ref(initial);
  const double = computed(() => count.value * 2);
  const increment = () => count.value += 1;
  return { count, double, increment };
}
```

```js
// 组件中使用
import { useCounter } from './useCounter';

export default {
  setup() {
    const { count, double, increment } = useCounter();
    return { count, double, increment };
  },
};
```

```text
Composition API 优点：
1. 逻辑聚合 —— 同一功能代码集中在一起，便于维护
2. 逻辑复用 —— 组合式函数无 this，易于抽取复用
3. TypeScript 友好 —— 类型推导更自然
```

## Options API

Options API 是 Vue 2 的组织方式，把代码按 data、methods、computed、watch 等选项分类。Vue 3 仍完整支持，两者可混用。

```js
export default {
  data() {
    return { count: 0 };
  },
  computed: {
    double() {
      return this.count * 2;
    },
  },
  methods: {
    increment() {
      this.count += 1;
    },
  },
  watch: {
    count(val) {
      console.log(val);
    },
  },
};
```

```text
Options API vs Composition API：
Options —— 简单组件直观，复杂组件逻辑分散
Composition —— 复杂组件逻辑清晰，复用方便
二者可共存，按场景选择。
```

## setup

`setup` 是组合式 API 的入口，在 `beforeCreate` 之前执行，此时组件实例尚未创建，不能使用 `this`。

```js
export default {
  props: { title: String },
  setup(props, context) {
    // props 是响应式的，解构会失去响应性
    const { title } = props; // 失去响应性，不推荐

    // context 包含 attrs、slots、emit、expose
    const { emit, slots, attrs, expose } = context;

    const handle = () => emit('update');

    return { handle };
  },
};
```

```html
<!-- <script setup> 语法糖，更简洁 -->
<script setup>
import { ref } from 'vue';

const count = ref(0);
const increment = () => count.value += 1;

defineProps({ title: String });
const emit = defineEmits(['update']);
</script>
```

## ref

`ref` 用于包装基本类型（也可包装对象），返回响应式引用对象，通过 `.value` 访问和修改。

```js
import { ref } from 'vue';

const count = ref(0);
count.value += 1; // 修改触发更新
console.log(count.value); // 1

// 包装对象
const user = ref({ name: 'Alice' });
user.value.name = 'Bob'; // 对象内部是 reactive 的
```

```html
<!-- 模板中自动解包，无需 .value -->
<template>
  <p>{{ count }}</p>
  <button @click="count++">+1</button>
</template>
```

```text
ref 要点：
1. JS 中访问需 .value，模板中自动解包
2. 对象会被内部转为 reactive
3. 顶层 ref 在模板中自动解包，嵌套对象里的 ref 不解包
```

## reactive

`reactive` 用 Proxy 将对象转换为响应式代理，直接访问属性，无需 `.value`。

```js
import { reactive } from 'vue';

const state = reactive({
  count: 0,
  user: { name: 'Alice' },
});

state.count += 1; // 直接修改
state.user.name = 'Bob'; // 深层响应式
```

```text
reactive 要点：
1. 只适用于对象（数组、Map、Set 等），不适合基本类型
2. 深层响应式，嵌套对象自动代理
3. 解构或赋值给新变量会失去响应性（用 toRefs 保持）
4. 不能整体替换（const state = reactive(obj); state = {...} 丢失响应）
```

```js
import { reactive, toRefs } from 'vue';

const state = reactive({ count: 0 });
const { count } = toRefs(state); // 解构后仍响应式
```

## computed

Computed 返回只读的响应式引用，依赖变化时才重新计算，结果被缓存。

```js
import { ref, computed } from 'vue';

const price = ref(100);
const count = ref(2);
const total = computed(() => price.value * count.value);

console.log(total.value); // 200

// 可写计算属性
const double = computed({
  get: () => count.value * 2,
  set: (val) => (count.value = val / 2),
});
double.value = 10; // count 变为 5
```

## watch

Watch 监听一个或多个响应式数据源，源变化时执行回调（默认惰性，首次不执行）。

```js
import { ref, reactive, watch } from 'vue';

const count = ref(0);
const state = reactive({ name: 'a', age: 1 });

// 监听 ref
watch(count, (newVal, oldVal) => {
  console.log(newVal, oldVal);
});

// 监听 getter
watch(() => state.name, (newVal) => console.log(newVal));

// 监听多个源
watch([count, () => state.age], ([c, a], [oc, oa]) => {
  console.log(c, a);
});

// 深度监听
watch(
  () => state,
  (val) => console.log(val),
  { deep: true, immediate: true },
);
```

## watchEffect

`watchEffect` 自动追踪回调中访问的所有响应式依赖，任一依赖变化即重新执行，且立即执行一次。

```js
import { ref, watchEffect } from 'vue';

const keyword = ref('');
const loading = ref(false);

// 立即执行，自动追踪 keyword.value
watchEffect(() => {
  console.log('搜索:', keyword.value);
});

// 自动停止（组件卸载时）
// 手动停止
const stop = watchEffect(() => {
  console.log(keyword.value);
});
stop(); // 停止监听
```

```text
watchEffect vs watch：
watchEffect —— 自动收集依赖，立即执行，不关心旧值
watch —— 显式指定数据源，可拿新旧值，默认惰性
```

## provide

`provide` 在祖先组件提供数据，供后代组件注入，无需逐层传递 Props。

```js
// 祖先组件
import { provide, ref } from 'vue';

export default {
  setup() {
    const theme = ref('dark');
    provide('theme', theme); // 提供响应式值
  },
};
```

## inject

`inject` 在后代组件中读取祖先提供的数据。

```js
// 后代组件
import { inject } from 'vue';

export default {
  setup() {
    const theme = inject('theme', 'light'); // 第二个参数是默认值
    return { theme };
  },
};
```

```html
<!-- <script setup> 写法 -->
<script setup>
import { provide, inject, ref } from 'vue';

// 祖先
const theme = ref('dark');
provide('theme', theme);

// 后代
const theme = inject('theme', 'light');
</script>
```

## nextTick

`nextTick` 返回一个 Promise，在 DOM 更新完成后 resolve，用于在数据变更后访问最新 DOM。

```js
import { ref, nextTick } from 'vue';

const count = ref(0);
const el = ref(null);

async function update() {
  count.value += 1;
  // DOM 尚未更新
  console.log(el.value.textContent); // 旧值
  await nextTick();
  console.log(el.value.textContent); // 新值
}
```

```text
nextTick 原理：
Vue 的 DOM 更新是异步批量的，数据变化后不会立即更新 DOM。
nextTick 把回调放进微任务队列，等本轮更新完成后执行。
```

## 应用场景实战

### 场景一：搜索防抖（watch + watchEffect）

```js
import { ref, watch } from 'vue';

export function useSearch() {
  const keyword = ref('');
  const result = ref([]);
  let timer = null;

  watch(keyword, (val) => {
    clearTimeout(timer);
    timer = setTimeout(async () => {
      result.value = await fetchSearch(val);
    }, 300);
  });

  return { keyword, result };
}
```

### 场景二：主题切换（provide/inject）

```js
// 祖先提供主题
const theme = ref('light');
const toggle = () => (theme.value = theme.value === 'light' ? 'dark' : 'light');
provide('theme', { theme, toggle });

// 任意后代注入
const { theme, toggle } = inject('theme');
```

## 最佳实践与踩坑记录

### 最佳实践

1. 复杂逻辑抽取为组合式函数（composables），命名 use 开头
2. 基本类型用 ref，对象用 reactive，按需选择
3. 派生数据用 computed，副作用用 watch/watchEffect
4. 跨层级通信优先 provide/inject，避免 Props 逐层透传
5. DOM 操作后需要最新值用 nextTick

### 踩坑记录

```text
坑 1：reactive 解构失去响应性
结论：解构 reactive 对象后，变量变化不触发更新。
原因：解构是值拷贝，脱离 Proxy 代理。
解法：用 toRefs 保持引用，或改用 ref。

坑 2：ref 在模板中嵌套不自动解包
结论：对象里的 ref 属性在模板中不自动解包。
原因：只有顶层 ref 才在模板自动解包。
解法：访问时手动 .value，或把 ref 提到顶层。

坑 3：watchEffect 误监听到无关依赖
结论：副作用里访问了额外数据，导致频繁触发。
原因：watchEffect 自动收集所有访问过的响应式依赖。
解法：精确控制依赖访问，或改用 watch 显式指定源。

坑 4：provide 普通值不响应式
结论：provide 一个普通对象，后代拿不到更新。
原因：provide 的普通值非响应式，变化不会通知。
解法：provide ref/reactive 值。

坑 5：setup 里用 this
结论：setup 中 this 是 undefined。
原因：setup 在实例创建前执行，this 不可用。
解法：使用 props、context 参数，不用 this。
```

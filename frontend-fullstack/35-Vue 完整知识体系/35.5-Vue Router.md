## 概述

Vue Router 是 Vue 官方的路由管理器，基于 History API 或 hash 实现 SPA 的页面切换。它把 URL 映射到组件，通过 `<router-view>` 渲染匹配的组件，并支持嵌套、动态、懒加载路由与导航守卫。

```text
Vue Router 核心概念：
1. Route —— 单条路由配置（path + component）
2. Router —— 路由实例，管理路由表与导航状态
3. Navigation Guard —— 导航守卫，拦截/放行导航
4. Dynamic Route —— 动态路由，路径带参数（/user/:id）
5. Nested Route —— 嵌套路由，父组件内渲染子路由
6. Lazy Route —— 懒加载，按需加载组件（代码分割）
```

```js
import { createRouter, createWebHistory } from 'vue-router';

const routes = [
  { path: '/', component: Home },
  { path: '/about', component: About },
];

const router = createRouter({
  history: createWebHistory(),
  routes,
});

export default router;
```

## Route

Route 是路由表的一项配置，描述路径与组件的映射关系，包含 path、name、component、meta 等字段。

```js
const routes = [
  {
    path: '/user/:id', // 动态路径参数
    name: 'user', // 命名路由
    component: User,
    meta: { requiresAuth: true }, // 元信息
  },
  {
    path: '/about',
    component: () => import('./About.vue'), // 懒加载
    redirect: '/', // 重定向
  },
];
```

```text
Route 常用字段：
path —— 路径（支持参数 :id、通配符 *）
name —— 命名路由，跳转时可用 { name: 'user' }
component —— 对应组件
meta —— 自定义元信息（权限、标题等）
redirect / alias —— 重定向与别名
children —— 嵌套子路由
```

## Router

Router 是路由实例，通过 createRouter 创建，负责解析 URL、维护当前路由状态、驱动 `<router-view>` 渲染。

```js
import { createRouter, createWebHistory, createWebHashHistory } from 'vue-router';

// History 模式（需要服务端配合重定向）
const router = createRouter({
  history: createWebHistory(), // URL 无 #，需服务端 fallback
  routes,
});

// Hash 模式（无需服务端配置）
const hashRouter = createRouter({
  history: createWebHashHistory(), // URL 带 #，兼容性好
  routes,
});

// 编程式导航
router.push('/about');
router.push({ name: 'user', params: { id: 1 } });
router.replace('/home');
router.back();
router.forward();
```

```text
History vs Hash 模式：
History —— URL 干净（/about），刷新需要服务端重定向到 index.html
Hash —— URL 带 #（/#/about），无需服务端配置
```

## Navigation Guard

导航守卫在路由跳转前后执行，用于鉴权、权限校验、数据预取、取消导航等。分为全局守卫、路由守卫、组件内守卫。

```js
// 全局前置守卫
router.beforeEach((to, from) => {
  if (to.meta.requiresAuth && !isLoggedIn()) {
    return { name: 'login', query: { redirect: to.fullPath } };
  }
  // 返回 true 或 undefined 放行
  return true;
});

// 全局后置钩子（无 next，不能取消导航）
router.afterEach((to, from) => {
  document.title = to.meta.title;
});
```

```js
// 路由独享守卫
const routes = [
  {
    path: '/admin',
    component: Admin,
    beforeEnter: (to, from) => {
      if (!hasPermission()) return '/login';
    },
  },
];
```

```js
// 组件内守卫
export default {
  beforeRouteEnter(to, from, next) {
    next((vm) => vm.init()); // 进入前
  },
  beforeRouteUpdate(to, from) {}, // 复用组件时（参数变化）
  beforeRouteLeave(to, from) {
    if (!confirm('离开？')) return false; // 阻止离开
  },
};
```

```text
守卫执行顺序：
beforeRouteLeave → beforeEach → beforeRouteUpdate → beforeEnter
→ 组件渲染 → beforeRouteEnter → afterEach
返回值：true/undefined 放行，false 取消，路由对象重定向。
```

## Dynamic Route

动态路由在路径中使用参数占位符（:id），同一组件根据参数渲染不同内容。

```js
const routes = [
  { path: '/user/:id', component: UserDetail },
];

// 跳转
router.push('/user/123');
```

```html
<!-- UserDetail.vue -->
<template>
  <div>用户 ID：{{ $route.params.id }}</div>
</template>
<script setup>
import { useRoute } from 'vue-router';
const route = useRoute();
console.log(route.params.id); // '123'
</script>
```

```text
动态路由要点：
1. 参数变化复用组件时，用 watch 监听 $route.params 或 beforeRouteUpdate
2. 可选参数用 ?，如 /user/:id?
3. 通配符 * 匹配任意路径（放最后）
4. props: true 可将参数作为 props 传给组件
```

## Nested Route

嵌套路由让子路由在父组件的 `<router-view>` 中渲染，适合「布局 + 内容」的页面结构。

```js
const routes = [
  {
    path: '/user',
    component: UserLayout, // 父组件，包含 <router-view>
    children: [
      { path: '', component: UserProfile }, // /user 默认
      { path: 'posts', component: UserPosts }, // /user/posts
      { path: 'settings', component: UserSettings }, // /user/settings
    ],
  },
];
```

```html
<!-- UserLayout.vue -->
<template>
  <div class="layout">
    <nav>侧边栏</nav>
    <router-view /> <!-- 渲染子路由组件 -->
  </div>
</template>
```

## Lazy Route

懒加载路由通过动态 import 按需加载组件，实现代码分割，减少首屏体积。

```js
const routes = [
  {
    path: '/dashboard',
    // 动态 import，构建时拆分为独立 chunk
    component: () => import('./views/Dashboard.vue'),
  },
  {
    path: '/settings',
    component: () => import('./views/Settings.vue'),
  },
];
```

```text
懒加载的价值：
1. 减小首屏 JS 体积，加快加载
2. 按路由拆 chunk，访问时才下载
3. 配合 prefetch 提升切换体验
```

## 应用场景实战

### 场景一：登录鉴权 + 重定向回跳

```js
router.beforeEach((to) => {
  const token = localStorage.getItem('token');
  if (to.meta.requiresAuth && !token) {
    return { name: 'login', query: { redirect: to.fullPath } };
  }
  return true;
});

// 登录成功后跳回原页面
const redirect = route.query.redirect || '/';
router.push(redirect);
```

### 场景二：带侧边栏布局的嵌套路由

```js
const routes = [
  {
    path: '/admin',
    component: AdminLayout,
    meta: { requiresAuth: true },
    children: [
      { path: 'users', component: () => import('./admin/Users.vue') },
      { path: 'orders', component: () => import('./admin/Orders.vue') },
    ],
  },
];
```

## 最佳实践与踩坑记录

### 最佳实践

1. 路由组件一律用懒加载，减小首屏体积
2. 鉴权逻辑放全局 beforeEach，权限细粒度用 meta + 守卫
3. 路由参数用 props 传递，组件解耦 $route
4. 嵌套路由子路径用相对路径（不加 /），避免绝对路径踩坑
5. 404 通配路由放最后，避免吞掉正常路由

### 踩坑记录

```text
坑 1：History 模式刷新 404
结论：直接访问子路由或刷新页面返回 404。
原因：服务端没有把未知路径回退到 index.html。
解法：Nginx 配 try_files $uri /index.html，或改用 hash 模式。

坑 2：动态参数复用组件不更新
结论：/user/1 跳到 /user/2，组件数据不刷新。
原因：同一组件复用，不会重新 mounted。
解法：watch 监听 route.params，或用 beforeRouteUpdate。

坑 3：子路由用绝对路径
结论：children 里写 /posts 变成顶层路由。
原因：以 / 开头是绝对路径，脱离父级。
解法：子路由写相对路径 posts（不带 /）。

坑 4：守卫里忘记 return
结论：导航卡住或报错。
原因：守卫没有明确放行/重定向。
解法：确保返回 true/undefined（放行）或路由对象（重定向）。

坑 5：beforeRouteEnter 里用 this
结论：this 为 undefined。
原因：此时组件实例尚未创建。
解法：用 next(vm => {}) 回调获取实例。
```

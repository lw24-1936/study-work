## 概述

Vue 的模板需要先编译为渲染函数（render function），渲染函数执行生成 VNode（虚拟节点），再通过 Patch（diff 算法）把 VNode 更新到真实 DOM。整个流程是「模板 → AST → 转换 → 代码生成 → 渲染函数 → VNode → Patch」。

```text
Vue 编译与渲染管线：
1. Template Compiler —— 模板字符串编译为渲染函数
2. AST —— 模板解析出的抽象语法树
3. Transform —— 对 AST 做转换优化（静态提升等）
4. Codegen —— 由 AST 生成渲染函数代码
5. Render Function —— 执行后返回 VNode 树
6. VNode —— 描述 DOM 的虚拟节点
7. Patch —— 新旧 VNode 对比并更新 DOM（diff）
```

```js
// 模板
const template = `<div><p>{{ msg }}</p></div>`;

// 编译后的渲染函数（简化）
function render(_ctx) {
  return createElementVNode('div', null, [
    createElementVNode('p', null, _ctx.msg),
  ]);
}
```

## Template Compiler

模板编译器负责把模板字符串解析成渲染函数，包含解析（parse）、转换（transform）、生成（generate）三个阶段。

```js
import { compile } from 'vue';

const { code } = compile(`<div>{{ msg }}</div>`);
console.log(code);
// 输出类似：
// function render(_ctx, _cache) {
//   return _openBlock(), _createElementBlock("div", null, _toDisplayString(_ctx.msg))
// }
```

```text
编译器三阶段：
1. parse —— 模板字符串 → AST
2. transform —— AST 优化与转换（标记静态节点、v-if 拆分等）
3. generate —— AST → 渲染函数代码字符串
```

## AST

AST（抽象语法树）是模板的结构化表示，每个节点包含类型、标签、属性、子节点等信息。

```text
<div id="app"><p>hello</p></div> 解析后的 AST（简化）：
{
  type: 0,          // 节点类型（0 元素、1 文本等）
  tag: 'div',
  props: [{ type: 6, name: 'id', value: { content: 'app' } }],
  children: [
    {
      type: 0,
      tag: 'p',
      children: [
        { type: 1, content: 'hello' }  // 文本节点
      ]
    }
  ]
}
```

```text
AST 节点类型：
1. Element —— 元素节点（type 0）
2. Text —— 文本节点（type 1）
3. Comment —— 注释节点
4. Interpolation —— 插值 {{ }}（type 5）
5. Directive —— 指令节点（v-if/v-for 等）
```

## Transform

Transform 阶段对 AST 做转换和优化，核心优化之一是「静态提升」（hoistStatic）：把不依赖响应式数据的静态节点提升到渲染函数外，避免每次渲染重复创建。

```text
静态提升示例：
模板：<div><p>静态文本</p><p>{{ msg }}</p></div>

未优化：每次渲染都创建两个 p 的 VNode
优化后：静态 <p>静态文本</p> 的 VNode 被提升为常量，渲染时复用
```

```js
// 静态提升后的渲染函数（简化）
const _hoisted_1 = createElementVNode('p', null, '静态文本');
function render(_ctx) {
  return createElementVNode('div', null, [
    _hoisted_1,
    createElementVNode('p', null, _ctx.msg),
  ]);
}
```

```text
Transform 其它优化：
1. 静态提升 —— 静态节点提升为常量
2. 预字符串化 —— 连续静态节点合并为一个字符串
3. 补丁标记（PatchFlag） —— 标记动态节点，diff 时跳过静态部分
4. 缓存事件处理函数
```

## Codegen

Codegen 把转换后的 AST 生成渲染函数代码字符串，使用 `createElementVNode`、`createTextVNode`、`openBlock` 等运行时辅助函数。

```text
模板：<div id="app" @click="onClick">{{ msg }}</div>
生成代码（简化）：
import { createElementVNode as _createElementVNode,
  toDisplayString as _toDisplayString,
  openBlock as _openBlock,
  createElementBlock as _createElementBlock } from "vue"

function render(_ctx, _cache) {
  return (_openBlock(),
    _createElementBlock("div", {
      id: "app",
      onClick: _ctx.onClick
    }, _toDisplayString(_ctx.msg), 1))
}
```

## Render Function

渲染函数返回 VNode 树，可手写渲染函数替代模板，获得更灵活的控制。

```js
import { h } from 'vue';

// h(tag, props, children)
const vnode = h('div', { id: 'app' }, [
  h('p', null, 'hello'),
  h('p', null, this.msg),
]);
```

```js
// 用渲染函数写组件
export default {
  props: { items: Array },
  render() {
    return h(
      'ul',
      null,
      this.items.map((item) => h('li', { key: item.id }, item.name)),
    );
  },
};
```

```text
模板 vs 渲染函数：
模板 —— 声明式、直观，编译优化好（推荐）
渲染函数 —— 灵活，适合动态复杂逻辑
```

## VNode

VNode（虚拟节点）是描述真实 DOM 的轻量 JS 对象，包含标签、属性、子节点、动态标记等信息。它是渲染与 diff 的基本单位。

```js
// VNode 结构（简化）
{
  type: 'div',              // 标签或组件
  props: { id: 'app' },     // 属性
  children: [ ... ],        // 子 VNode
  key: null,                // 用于 diff 的唯一标识
  el: null,                 // 对应真实 DOM（挂载后）
  shapeFlag: 1,             // 节点类型标志
  patchFlag: 1,             // 动态标记（如 TEXT、CLASS）
}
```

```text
VNode 的价值：
1. 用 JS 对象描述 UI，可跨平台（DOM、Native、SSR）
2. diff 时对比新旧 VNode，最小化 DOM 操作
3. patchFlag 标记动态部分，提升 diff 性能
```

## Patch

Patch 是 diff 算法的核心：对比新旧 VNode，找出差异并更新真实 DOM。分为挂载（mount）和更新（update）两个阶段。

```js
function patch(oldVNode, newVNode, container) {
  if (oldVNode === newVNode) return;
  // 类型不同，直接替换
  if (oldVNode.type !== newVNode.type) {
    unmount(oldVNode);
    mount(newVNode, container);
    return;
  }
  // 相同类型，复用节点，更新属性与子节点
  const el = (newVNode.el = oldVNode.el);
  patchProps(el, newVNode.props);
  patchChildren(oldVNode, newVNode, el);
}
```

```text
Patch 优化手段：
1. PatchFlag —— 静态节点跳过 diff
2. key —— 精准复用节点，减少移动
3. 最长递增子序列 —— 最小化移动次数
4. 靶向更新 —— 只更新变化的属性/文本
```

## 应用场景实战

### 场景一：手写渲染函数创建列表

```js
import { h } from 'vue';

export default {
  data() {
    return { list: [{ id: 1, name: 'A' }, { id: 2, name: 'B' }] };
  },
  render() {
    return h('ul', this.list.map((item) => h('li', { key: item.id }, item.name)));
  },
};
```

### 场景二：动态组件渲染

```js
import { h } from 'vue';
import CompA from './CompA.vue';
import CompB from './CompB.vue';

export default {
  data() {
    return { comp: CompA };
  },
  render() {
    // 动态切换组件类型
    return h(this.comp, { msg: 'hello' });
  },
};
```

## 最佳实践与踩坑记录

### 最佳实践

1. 优先用模板，交给编译器做静态提升等优化
2. 列表渲染一定配稳定 key，提升 diff 复用率
3. 复杂条件渲染拆成小组件，减少整块 diff
4. 静态内容尽量写成纯静态模板，享受静态提升
5. 理解 patchFlag，避免把动态绑定写成静态导致不更新

### 踩坑记录

```text
坑 1：v-for 不配 key 导致复用错乱
结论：列表更新时内容错位、输入框状态串位。
原因：无 key 时 diff 用索引复用节点。
解法：配稳定的业务唯一 key。

坑 2：key 用索引导致状态错乱
结论：增删/排序后复用错误节点。
原因：索引不是稳定标识。
解法：用业务 id，不用 index。

坑 3：在渲染函数里直接改响应式数据
结论：无限循环渲染。
原因：渲染函数是 effect，内部改数据触发自己重跑。
解法：副作用放事件或生命周期，渲染保持纯净。

坑 4：同一位置切换不同类型组件丢状态
结论：组件状态被重置。
原因：VNode type 不同会卸载重建。
解法：用 key 或 v-if/v-else 保持类型一致。

坑 5：手写 render 忘返回 VNode
结论：组件渲染为空白。
原因：渲染函数必须 return VNode。
解法：确保 render 函数返回 h() 结果。
```

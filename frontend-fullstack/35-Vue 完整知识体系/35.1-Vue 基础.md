## 概述

Vue 是一个渐进式 JavaScript 框架，核心思想是「声明式渲染 + 响应式数据 + 组件化」。模板（Template）描述 UI，组件（Component）组织代码，响应式系统自动把数据变化同步到视图。

```text
Vue 基础的核心组成：
1. Template —— 声明式描述 UI，编译成渲染函数
2. Component —— 可复用的独立单元（含模板、逻辑、样式）
3. Props —— 父组件向子组件传数据（单向数据流）
4. Emits —— 子组件向父组件发事件（向上通信）
5. Slots —— 内容分发，父组件注入子组件的内容
6. Directives —— v-if/v-for/v-model 等模板指令
7. Computed —— 基于响应式数据的派生值（有缓存）
8. Watch —— 监听数据变化执行副作用
9. Lifecycle —— 组件从创建到销毁的钩子
```

```js
import { createApp } from 'vue';

const App = {
  template: `<h1>{{ message }}</h1>`,
  data() {
    return { message: 'Hello Vue' };
  },
};

createApp(App).mount('#app');
```

## Template

Template 是 Vue 的声明式模板语法，最终被编译为渲染函数。支持插值、指令、表达式。

```html
<template>
  <div>
    <!-- 文本插值 -->
    <p>{{ message }}</p>
    <!-- 属性绑定 -->
    <img :src="url" :alt="alt" />
    <!-- 事件绑定 -->
    <button @click="handleClick">点击</button>
    <!-- 表达式（单条语句） -->
    <p>{{ count + 1 }}</p>
  </div>
</template>
```

```js
export default {
  data() {
    return { message: 'hi', url: '/a.png', alt: '图', count: 1 };
  },
  methods: {
    handleClick() {
      this.count += 1;
    },
  },
};
```

## Component

组件是可复用的独立单元，包含模板、逻辑与样式。Vue 中组件通过 `components` 选项注册，或用 SFC（.vue 文件）组织。

```js
// 子组件
const MyButton = {
  template: `<button @click="onClick">点我</button>`,
  emits: ['click'],
  methods: {
    onClick() {
      this.$emit('click');
    },
  },
};

// 父组件注册并使用
const Parent = {
  components: { MyButton },
  template: `<MyButton @click="say" />`,
  methods: {
    say() {
      console.log('clicked');
    },
  },
};
```

```text
组件命名与注册：
1. 局部注册 —— components 选项（推荐，便于 tree-shaking）
2. 全局注册 —— app.component()（适合通用基础组件）
3. SFC —— .vue 文件，template + script + style 三块
```

## Props

Props 是父组件传递给子组件的数据，遵循单向数据流：父 → 子，子组件不应直接修改 Props。

```html
<!-- 父组件 -->
<Child :title="title" :count="10" />
```

```js
// 子组件
export default {
  props: {
    title: { type: String, required: true },
    count: { type: Number, default: 0 },
  },
  template: `<p>{{ title }} - {{ count }}</p>`,
};
```

```text
Props 要点：
1. 单向数据流 —— 子组件不能修改 Props，应通过 Emits 通知父组件
2. 类型校验 —— type/required/default/validator
3. 命名 —— JS 中 camelCase，模板中 kebab-case（:user-name）
```

## Emits

Emits 是子组件向父组件通信的机制：子组件 `$emit('事件名', 参数)`，父组件用 `@事件名` 监听。

```js
// 子组件
export default {
  emits: ['update'], // 声明事件
  methods: {
    submit() {
      this.$emit('update', { id: 1 });
    },
  },
};
```

```html
<!-- 父组件 -->
<Child @update="onUpdate" />
```

```js
// 父组件
export default {
  methods: {
    onUpdate(payload) {
      console.log(payload.id); // 1
    },
  },
};
```

```text
v-model 本质：
v-model="value" 等价于 :value="value" + @input="value = $event"
组件上使用 v-model 会绑定 modelValue 属性并监听 update:modelValue 事件。
```

## Slots

Slots（插槽）用于内容分发，让父组件把内容注入子组件的指定位置。分为默认插槽、具名插槽、作用域插槽。

```html
<!-- 子组件 -->
<div class="card">
  <header><slot name="header"></slot></header>
  <main><slot></slot></main>
  <footer><slot name="footer"></slot></footer>
</div>
```

```html
<!-- 父组件 -->
<Card>
  <template #header>标题</template>
  <p>默认内容</p>
  <template #footer>底部</template>
</Card>
```

```html
<!-- 作用域插槽：子组件向父组件暴露数据 -->
<!-- 子组件 -->
<ul>
  <li v-for="item in items" :key="item.id">
    <slot :item="item">{{ item.name }}</slot>
  </li>
</ul>
```

```html
<!-- 父组件使用作用域插槽 -->
<ItemList :items="items" v-slot="{ item }">
  <b>{{ item.name }}</b>
</ItemList>
```

## Directives

指令是带 `v-` 前缀的特殊属性，用于在模板中声明式操作 DOM。

```html
<template>
  <div>
    <!-- 条件渲染 -->
    <p v-if="ok">显示</p>
    <p v-else>隐藏</p>
    <!-- 列表渲染 -->
    <li v-for="(item, i) in list" :key="item.id">{{ i }} - {{ item.name }}</li>
    <!-- 双向绑定 -->
    <input v-model="text" />
    <!-- 一次性渲染 -->
    <span v-once>{{ static }}</span>
    <!-- 跳过编译 -->
    <div v-pre>{{ 这里原样输出 }}</div>
    <!-- 动态绑定 -->
    <div v-bind="attrs" />
  </div>
</template>
```

```text
常用指令：
v-if / v-else / v-else-if —— 条件渲染（销毁/重建节点）
v-show —— 切换 display（始终渲染）
v-for —— 列表渲染，必须配 :key
v-model —— 表单双向绑定
v-on（@） —— 事件监听
v-bind（:） —— 属性绑定
v-once / v-pre / v-cloak —— 性能与编译相关
```

## Computed

Computed 是计算属性，基于响应式依赖派生新值，并且有缓存：依赖不变时不重新计算。

```js
export default {
  data() {
    return { price: 100, count: 2 };
  },
  computed: {
    total() {
      return this.price * this.count; // 依赖 price、count
    },
    // 可写计算属性
    double: {
      get() {
        return this.count * 2;
      },
      set(val) {
        this.count = val / 2;
      },
    },
  },
};
```

```text
Computed vs 方法：
Computed —— 有缓存，依赖不变则直接返回缓存值，适合派生数据
方法 —— 每次调用都执行，适合有副作用的操作
```

## Watch

Watch 监听响应式数据的变化并执行副作用（异步请求、手动操作 DOM 等）。

```js
export default {
  data() {
    return { keyword: '' };
  },
  watch: {
    keyword(newVal, oldVal) {
      console.log(newVal, oldVal);
    },
    // 深度监听对象
    user: {
      handler(val) {
        console.log(val);
      },
      deep: true,
      immediate: true, // 立即执行一次
    },
  },
};
```

```text
Watch vs Computed：
Computed —— 派生新值，有缓存，不执行副作用
Watch —— 观察变化执行副作用（请求、计时器等）
能 computed 就不用 watch。
```

## Lifecycle

生命周期钩子描述组件从创建到销毁的各个阶段。

```js
export default {
  beforeCreate() {
    // 实例初始化后、数据/事件配置前
  },
  created() {
    // 实例创建完成，可访问 data/computed/methods，未挂载 DOM
  },
  beforeMount() {
    // 挂载前，模板已编译，未生成 DOM
  },
  mounted() {
    // DOM 挂载完成，可操作 DOM、发起请求
  },
  beforeUpdate() {
    // 数据变化、DOM 更新前
  },
  updated() {
    // DOM 更新后
  },
  beforeUnmount() {
    // 卸载前，清理定时器/监听
  },
  unmounted() {
    // 卸载完成
  },
};
```

```text
生命周期流程：
create（初始化） → mount（挂载） → update（更新） → unmount（卸载）
常用：created 发请求、mounted 操作 DOM、beforeUnmount 清理资源。
```

## 应用场景实战

### 场景一：可复用的分页组件（Props + Emits）

```html
<!-- Pager.vue -->
<template>
  <div>
    <button :disabled="page <= 1" @click="$emit('change', page - 1)">上一页</button>
    <span>{{ page }} / {{ total }}</span>
    <button :disabled="page >= total" @click="$emit('change', page + 1)">下一页</button>
  </div>
</template>
<script>
export default {
  props: {
    page: { type: Number, required: true },
    total: { type: Number, required: true },
  },
  emits: ['change'],
};
</script>
```

```html
<!-- 父组件使用 -->
<Pager :page="page" :total="10" @change="page = $event" />
```

### 场景二：带默认内容的卡片（Slots）

```html
<Card>
  <template #header><h2>文章标题</h2></template>
  <p>正文内容...</p>
  <template #footer><button>收藏</button></template>
</Card>
```

## 最佳实践与踩坑记录

### 最佳实践

1. 组件单向数据流：子组件不直接改 Props，用 Emits 通知父组件
2. v-for 必须配稳定的 :key，避免用索引当 key
3. 派生数据用 Computed，副作用用 Watch
4. 组件命名统一 PascalCase，模板中用 kebab-case
5. 在 beforeUnmount 清理定时器、事件监听，避免内存泄漏

### 踩坑记录

```text
坑 1：直接修改 Props
结论：子组件里改 Props 不生效或报警告。
原因：Props 单向数据流，子组件不能改父组件数据。
解法：用 Emits 通知父组件修改，或用计算属性派生副本。

坑 2：v-for 用索引当 key
结论：列表重排序/增删时 DOM 复用错乱。
原因：索引不稳定，无法唯一标识节点。
解法：用业务唯一 id 作为 key。

坑 3：Computed 里写副作用
结论：计算属性行为不可预期。
原因：Computed 应纯净，只派生数据。
解法：副作用（请求、修改其它状态）放 Watch 或方法里。

坑 4：Watch 监听对象不生效
结论：对象内部属性变化监听不到。
原因：默认浅监听，只比较引用。
解法：加 deep: true，或监听具体属性路径（'user.name'）。

坑 5：在 created 里操作 DOM
结论：拿到的是 undefined 或 null。
原因：created 阶段 DOM 尚未挂载。
解法：DOM 操作放到 mounted 里，或用 nextTick。
```

## 概述

数据结构是算法的基础，选对数据结构往往比写出精妙的算法更重要。前端场景里，Array 和 Hash Table 是最常用的，而 Stack、Queue、Heap、Tree、Graph 则藏在路由、任务调度、依赖分析等日常功能的底层实现中。理解每种结构的增删查复杂度和适用场景，才能在做性能优化和系统设计时有据可依。

```text
常用数据结构的复杂度速查：
1. Array —— 按下标访问 O(1)，插入/删除 O(n)
2. Linked List —— 头尾插入 O(1)，按值查找 O(n)
3. Stack / Queue —— 入出 O(1)，LIFO / FIFO
4. Hash Table —— 平均增删查 O(1)，最坏 O(n)
5. Heap —— 取最值 O(1)，插入/删除 O(log n)
6. Tree —— 平衡时查找 O(log n)，退化时 O(n)
7. Trie —— 按前缀查找 O(k)，k 为字符串长度
8. Graph —— 遍历 O(V+E)
```

## Array

Array（数组）是连续内存的线性结构，按下标随机访问是 O(1)，是前端使用频率最高的结构。JS 的数组是动态的，自动扩容，还内置了 push/pop/map/filter 等大量方法。

```js
// 数组的基本操作
const arr = [1, 2, 3];
arr.push(4);          // 尾部追加 O(1)
arr.pop();            // 尾部弹出 O(1)
arr[0];               // 按下标访问 O(1)
arr.unshift(0);       // 头部插入 O(n)，所有元素后移
arr.splice(1, 1);     // 中间删除 O(n)

// 遍历
arr.forEach(n => console.log(n));
const doubled = arr.map(n => n * 2);
```

```text
Array 的要点：
1. 随机访问快 —— 按下标 O(1)，适合频繁查询
2. 头部/中间插入慢 —— 要移动元素 O(n)
3. 尾部操作快 —— push/pop 均摊 O(1)
4. 连续内存 —— 对 CPU 缓存友好，遍历效率高
```

## Linked List

Linked List（链表）通过指针把节点串起来，节点分散在内存中，插入删除只需改指针，是 O(1)。它不擅长随机访问，但适合频繁在中间插入删除的场景。

```js
class ListNode {
  constructor(val, next = null) {
    this.val = val;
    this.next = next;
  }
}

// 构建 1 -> 2 -> 3
const head = new ListNode(1, new ListNode(2, new ListNode(3)));

// 在头部插入新节点 O(1)
const newHead = new ListNode(0, head);

// 遍历链表
let cur = newHead;
while (cur) {
  console.log(cur.val);
  cur = cur.next;
}
```

```text
Linked List 的要点：
1. 插入删除快 —— 改指针即可 O(1)（已知位置时）
2. 随机访问慢 —— 必须从头遍历 O(n)
3. 内存不连续 —— 对缓存不友好
4. 额外指针开销 —— 每个节点多存一个 next 引用
```

## Stack

Stack（栈）是后进先出（LIFO）的结构，只能在一端操作。它天然适合「后进先出」的场景：函数调用栈、括号匹配、撤销操作、DFS 回溯等。JS 数组的 push/pop 就是现成的栈。

```js
const stack = [];
stack.push(1);       // 入栈
stack.push(2);
stack.push(3);
stack.pop();         // 3，后进先出
stack[stack.length - 1];  // 查看栈顶元素 2

// 应用：括号匹配
function isValid(s) {
  const stack = [];
  const map = { ')': '(', ']': '[', '}': '{' };
  for (const ch of s) {
    if (!map[ch]) {
      stack.push(ch);
    } else if (stack.pop() !== map[ch]) {
      return false;
    }
  }
  return stack.length === 0;
}
console.log(isValid('()[]{}')); // true
```

```text
Stack 的要点：
1. LIFO —— 后进先出，只在一端操作
2. 入栈/出栈 O(1) —— JS 用数组 push/pop 模拟
3. 应用 —— 括号匹配、撤销、DFS、表达式求值
4. 本质 —— 递归的迭代化工具，函数调用栈就是栈
```

## Queue

Queue（队列）是先进先出（FIFO）的结构，一端入队一端出队。它适合「按顺序处理」的场景：消息队列、BFS 遍历、任务调度、浏览器的宏任务队列等。

```js
const queue = [];
queue.push(1);        // 入队（尾部）
queue.push(2);
queue.shift();        // 出队（头部）1，先进先出
// 注意：shift 是 O(n)，高频场景应改用循环队列或链表实现

// 应用：BFS 层序遍历二叉树
function levelOrder(root) {
  if (!root) return [];
  const res = [];
  const q = [root];
  while (q.length) {
    const node = q.shift();
    res.push(node.val);
    if (node.left) q.push(node.left);
    if (node.right) q.push(node.right);
  }
  return res;
}
```

```text
Queue 的要点：
1. FIFO —— 先进先出，一端入一端出
2. 入队/出队 O(1) —— JS 数组 shift 是 O(n)，可用双指针优化
3. 应用 —— BFS、消息队列、任务调度、缓存淘汰
4. 变体 —— 循环队列、优先队列（用堆实现）
```

## Deque

Deque（双端队列）允许在两端都进行插入和删除，兼具栈和队列的能力。它适合「滑动窗口」这类需要从两端操作的问题，也是单调队列的基础结构。

```js
// 用数组模拟双端队列
const deque = [1, 2, 3];
deque.push(4);        // 尾部入队
deque.unshift(0);     // 头部入队
deque.pop();          // 尾部出队
deque.shift();        // 头部出队

// 应用：滑动窗口最大值（单调队列思路）
function maxSlidingWindow(nums, k) {
  const res = [];
  const dq = []; // 存下标，队首是当前窗口最大值
  for (let i = 0; i < nums.length; i++) {
    while (dq.length && nums[dq[dq.length - 1]] <= nums[i]) dq.pop();
    dq.push(i);
    if (dq[0] <= i - k) dq.shift();
    if (i >= k - 1) res.push(nums[dq[0]]);
  }
  return res;
}
console.log(maxSlidingWindow([1, 3, -1, -3, 5], 3)); // [3,3,5]
```

```text
Deque 的要点：
1. 两端可操作 —— 头尾插入删除都 O(1)（链表/循环数组实现）
2. 单调队列 —— 维护单调性，求滑动窗口最值 O(n)
3. 应用 —— 滑动窗口、BFS 0-1 边、最近使用记录
4. JS 实现 —— 数组 unshift/shift 是 O(n)，需注意性能
```

## Hash Table

Hash Table（哈希表）通过哈希函数把键映射到桶，平均增删查都是 O(1)，是「以空间换时间」的典型。JS 的 Object 和 Map 就是哈希表的实现，前端几乎所有缓存、去重、计数都靠它。

```js
// Map 的使用
const map = new Map();
map.set('a', 1);
map.get('a');         // 1
map.has('a');         // true
map.delete('a');

// 应用：两数之和
function twoSum(nums, target) {
  const seen = new Map();
  for (let i = 0; i < nums.length; i++) {
    const need = target - nums[i];
    if (seen.has(need)) return [seen.get(need), i];
    seen.set(nums[i], i);
  }
  return [];
}
console.log(twoSum([2, 7, 11, 15], 9)); // [0,1]
```

```text
Hash Table 的要点：
1. 平均 O(1) —— 增删查都快，最坏退化 O(n)
2. 键需可哈希 —— 字符串/数字常见，对象作键用 Map
3. 无顺序 —— 遍历顺序不保证插入顺序（Map 保证）
4. 应用 —— 去重、计数、缓存、快速查找、两数之和
5. 冲突处理 —— 链地址法/开放寻址法
```

## Heap

Heap（堆）是一种特殊的完全二叉树，满足「父节点总比子节点大（大顶堆）或小（小顶堆）」。它支持 O(1) 取最值、O(log n) 插入和删除，是优先队列的实现方式。JS 没有内置堆，需手写或用数组模拟。

```js
// 小顶堆的简易实现
class MinHeap {
  constructor() {
    this.heap = [];
  }
  push(val) {
    this.heap.push(val);
    let i = this.heap.length - 1;
    while (i > 0) {
      const p = (i - 1) >> 1;
      if (this.heap[p] <= this.heap[i]) break;
      [this.heap[p], this.heap[i]] = [this.heap[i], this.heap[p]];
      i = p;
    }
  }
  pop() {
    const top = this.heap[0];
    const last = this.heap.pop();
    if (this.heap.length) {
      this.heap[0] = last;
      this._sink(0);
    }
    return top;
  }
  _sink(i) {
    const n = this.heap.length;
    while (true) {
      let min = i;
      const l = i * 2 + 1, r = i * 2 + 2;
      if (l < n && this.heap[l] < this.heap[min]) min = l;
      if (r < n && this.heap[r] < this.heap[min]) min = r;
      if (min === i) break;
      [this.heap[i], this.heap[min]] = [this.heap[min], this.heap[i]];
      i = min;
    }
  }
  get top() { return this.heap[0]; }
}

const h = new MinHeap();
[5, 3, 8, 1].forEach(n => h.push(n));
console.log(h.pop()); // 1
console.log(h.pop()); // 3
```

```text
Heap 的要点：
1. 取最值 O(1) —— 堆顶就是最大/最小值
2. 插入/删除 O(log n) —— 上浮/下沉调整
3. 完全二叉树 —— 可用数组存储，父 i 子 2i+1/2i+2
4. 应用 —— Top K、优先队列、任务调度、Dijkstra
5. JS 无内置 —— 需手写或用库
```

## Tree

Tree（树）是层次化的非线性结构，节点有父子关系，广泛用于表达层级数据：DOM 树、文件目录、组件树、JSON 结构等。二叉树是基础，DFS 和 BFS 是两大遍历范式。

```js
// 二叉树节点
function TreeNode(val, left, right) {
  this.val = val;
  this.left = left || null;
  this.right = right || null;
}

const root = new TreeNode(1,
  new TreeNode(2, new TreeNode(4), new TreeNode(5)),
  new TreeNode(3)
);

// 前序遍历（DFS）
function preorder(node) {
  if (!node) return;
  console.log(node.val);
  preorder(node.left);
  preorder(node.right);
}
preorder(root); // 1 2 4 5 3
```

```text
Tree 的要点：
1. 层次结构 —— 表达父子/包含关系
2. DFS —— 前序/中序/后序，递归或栈实现
3. BFS —— 层序遍历，用队列实现
4. 应用 —— DOM、虚拟 DOM、文件树、组织架构
5. 二叉树 —— 最常用的树形结构，衍生 BST/AVL/红黑树
```

## Trie

Trie（前缀树/字典树）用树形结构存储字符串集合，共享公共前缀，按前缀查找是 O(k)（k 为字符串长度）。它是搜索引擎补全、输入法联想、敏感词过滤的底层结构。

```js
class TrieNode {
  constructor() {
    this.children = new Map();
    this.isEnd = false;
  }
}

class Trie {
  constructor() {
    this.root = new TrieNode();
  }
  insert(word) {
    let node = this.root;
    for (const ch of word) {
      if (!node.children.has(ch)) node.children.set(ch, new TrieNode());
      node = node.children.get(ch);
    }
    node.isEnd = true;
  }
  search(word) {
    let node = this.root;
    for (const ch of word) {
      if (!node.children.has(ch)) return false;
      node = node.children.get(ch);
    }
    return node.isEnd;
  }
  startsWith(prefix) {
    let node = this.root;
    for (const ch of prefix) {
      if (!node.children.has(ch)) return false;
      node = node.children.get(ch);
    }
    return true;
  }
}

const trie = new Trie();
trie.insert('app');
trie.insert('apple');
console.log(trie.search('app'));    // true
console.log(trie.startsWith('ap')); // true
```

```text
Trie 的要点：
1. 前缀共享 —— 公共前缀只存一份，省空间
2. 前缀查找 O(k) —— 与字符串长度相关，与词库大小无关
3. 应用 —— 搜索补全、输入法、敏感词过滤、IP 路由
4. 空间开销 —— 节点多，可用压缩 Trie 优化
```

## Graph

Graph（图）由顶点和边组成，表达任意多对多的关系。前端里依赖图（模块依赖）、路由图、社交关系图都是图结构。核心算法是 DFS 和 BFS，衍生出拓扑排序、最短路径等。

```js
// 邻接表表示图：a -> b, c
const graph = new Map();
function addEdge(from, to) {
  if (!graph.has(from)) graph.set(from, []);
  graph.get(from).push(to);
}
addEdge('a', 'b');
addEdge('a', 'c');
addEdge('b', 'd');
addEdge('c', 'd');

// BFS 遍历
function bfs(start) {
  const visited = new Set();
  const queue = [start];
  visited.add(start);
  while (queue.length) {
    const node = queue.shift();
    console.log(node);
    for (const next of graph.get(node) || []) {
      if (!visited.has(next)) {
        visited.add(next);
        queue.push(next);
      }
    }
  }
}
bfs('a'); // a b c d
```

```text
Graph 的要点：
1. 表示方式 —— 邻接表（省空间）/ 邻接矩阵（查边快）
2. 遍历 —— BFS 求最短路径，DFS 找环、拓扑
3. 有向/无向 —— 边是否有方向
4. 应用 —— 依赖图、路由、社交关系、编译的模块解析
5. 复杂度 —— 遍历 O(V+E)
```

## 应用场景实战

### 场景一：用 Map + Heap 实现 Top K 热搜

```js
// 统计词频，用小顶堆维护 Top K，堆大小恒为 K
function topKFrequent(words, k) {
  const count = new Map();
  for (const w of words) count.set(w, (count.get(w) || 0) + 1);

  const heap = []; // 小顶堆，按词频排序
  for (const [word, freq] of count) {
    heap.push({ word, freq });
    heap.sort((a, b) => a.freq - b.freq);
    if (heap.length > k) heap.shift(); // 弹出最小
  }
  return heap.map(x => x.word);
}
console.log(topKFrequent(['a', 'b', 'a', 'c', 'b', 'a'], 2)); // ['b','a']
```

### 场景二：用图 + 拓扑排序处理模块依赖

```js
// 拓扑排序：按依赖顺序排列模块，检测循环依赖
function topologicalSort(graph) {
  const indegree = new Map();
  for (const [node, deps] of graph) {
    if (!indegree.has(node)) indegree.set(node, 0);
    for (const dep of deps) indegree.set(dep, (indegree.get(dep) || 0) + 1);
  }
  const queue = [];
  for (const [node, deg] of indegree) if (deg === 0) queue.push(node);

  const order = [];
  while (queue.length) {
    const node = queue.shift();
    order.push(node);
    for (const dep of graph.get(node) || []) {
      indegree.set(dep, indegree.get(dep) - 1);
      if (indegree.get(dep) === 0) queue.push(dep);
    }
  }
  return order.length === indegree.size ? order : '存在循环依赖';
}
const g = new Map([
  ['a', ['b', 'c']],
  ['b', ['d']],
  ['c', ['d']],
  ['d', []],
]);
console.log(topologicalSort(g)); // ['a','b','c','d']
```

## 最佳实践与踩坑记录

### 最佳实践

1. 优先用 Array 和 Map 解决九成问题，别一上来就套复杂结构
2. 需要「后进先出」就想到栈，需要「先进先出」就想到队列
3. Top K / 求最值优先用堆，别每次都 sort
4. 前缀匹配、自动补全场景优先用 Trie，而不是遍历词库
5. 依赖关系、多对多关系用图建模，配合 DFS/BFS 和拓扑排序
6. 用复杂度意识选结构：先算清增删查哪个操作最频繁

### 踩坑记录

```text
坑 1：用数组 shift 当队列，复杂度翻车
结论：BFS 或任务队列里频繁 shift，数据量大时卡顿明显。
原因：数组 shift 会移动所有后续元素，是 O(n) 而非 O(1)。
解法：用双指针/链表实现队列，或直接用队列结构。

坑 2：需要 Top K 时每次都全量 sort
结论：每次排序 O(n log n)，数据一大性能差。
原因：没有意识到堆才是求最值的正确结构。
解法：用小顶堆维护 K 个元素，复杂度降到 O(n log K)。

坑 3：用 Object 当哈希表，键被原型污染
结论：key 为 __proto__/constructor 时行为异常。
原因：Object 有原型链，特殊键会命中原型属性。
解法：需要纯键值映射时用 Map，键任意类型且无原型污染。

坑 4：递归遍历深树导致栈溢出
结论：遍历很深的树（如深 DOM 树）时 RangeError 栈溢出。
原因：递归深度超过调用栈上限。
解法：改用显式栈迭代遍历，或使用尾递归优化。

坑 5：图遍历没记录 visited 导致死循环
结论：有环的图（依赖图、社交图）遍历时无限循环。
原因：忘了标记已访问节点，环上反复走。
解法：DFS/BFS 都维护 visited 集合，进入节点即标记。
```

## 概述

前端常用算法是把「数据结构与算法」落到真实业务里的那批：虚拟列表解决长列表渲染，Diff 和 Reconciliation 是框架更新的核心，LRU 缓存做资源淘汰，防抖节流优化高频事件，调度器管理任务优先级，依赖图和拓扑排序支撑打包与模块加载。这些算法看似分散，本质都是「用合适的结构在正确的时间做最少的事」。

```text
前端常用算法的归类：
1. 渲染优化 —— Virtual List、Diff、Reconciliation
2. 缓存淘汰 —— LRU Cache
3. 高频事件 —— Debounce、Throttle
4. 任务调度 —— Scheduler
5. 模块依赖 —— Dependency Graph、Topological Sort
6. 事件优化 —— Event Delegation
```

## Virtual List

Virtual List（虚拟列表）只渲染可视区域内的列表项，用滚动位置算出该渲染哪一段数据，解决「万级列表卡死」的问题。核心是：固定行高 + 可视范围计算 + 上下偏移，把渲染成本从 O(n) 降到 O(可视数量)。

```js
// 固定行高的虚拟列表核心逻辑
class VirtualList {
  constructor({ itemHeight, viewportHeight, total }) {
    this.itemHeight = itemHeight;
    this.viewportHeight = viewportHeight;
    this.total = total;
    this.scrollTop = 0;
  }
  get range() {
    const start = Math.floor(this.scrollTop / this.itemHeight);
    const visibleCount = Math.ceil(this.viewportHeight / this.itemHeight);
    const end = Math.min(start + visibleCount + 2, this.total); // 多渲染 2 个缓冲
    return { start, end };
  }
  get offsetY() {
    // 顶部被裁剪的高度，用来撑起占位
    return Math.floor(this.scrollTop / this.itemHeight) * this.itemHeight;
  }
  get totalHeight() {
    return this.total * this.itemHeight;
  }
}

const list = new VirtualList({ itemHeight: 40, viewportHeight: 400, total: 100000 });
list.scrollTop = 5000;
console.log(list.range);    // { start: 125, end: 137 }
console.log(list.offsetY);  // 5000
```

```text
Virtual List 的要点：
1. 只渲染可见项 —— 渲染量由视口高度决定，与总数据量无关
2. 撑高占位 —— 容器总高度 = 总行数 x 行高，滚动条才正确
3. 偏移定位 —— 用 translateY/absolute 把可见项放到正确位置
4. 变高场景 —— 行高不固定时需预估高度 + 动态校正
```

## Diff

Diff（差异比对）是计算「新旧两个结构之间最小差异」的算法。在框架里，它指比对新旧虚拟 DOM 树，找出哪些节点需要更新，从而用最少的 DOM 操作完成更新。经典思路是同层比较 + 双指针，复杂度 O(n)。

```js
// 简化版 Diff：比对新旧子节点数组，生成操作
function diff(oldList, newList) {
  const ops = [];
  const oldIndexMap = new Map();
  oldList.forEach((item, i) => oldIndexMap.set(item, i));

  let lastIndex = 0;
  newList.forEach((item, i) => {
    if (oldIndexMap.has(item)) {
      const oldIndex = oldIndexMap.get(item);
      if (oldIndex < lastIndex) {
        ops.push({ type: 'move', item, to: i });
      } else {
        lastIndex = oldIndex;
      }
    } else {
      ops.push({ type: 'add', item, to: i });
    }
  });
  oldList.forEach(item => {
    if (!newList.includes(item)) ops.push({ type: 'remove', item });
  });
  return ops;
}
console.log(diff(['a', 'b', 'c'], ['c', 'b', 'd']));
```

```text
Diff 的要点：
1. 同层比较 —— 只比同一层级，跨层级直接替换
2. 双指针 —— 头尾同时比较，减少移动
3. key 复用 —— 有 key 才能识别节点是否可复用
4. 复杂度 —— 无 key 或纯暴力是 O(n³)，优化后 O(n)
```

## Reconciliation

Reconciliation（协调/调和）是框架把 Diff 结果应用到真实 DOM 的完整过程：先比对虚拟 DOM 找出差异，再决定是更新、复用还是重建节点。它是 React/Vue 更新机制的总称，Diff 只是其中一环。

```js
// 简化版 Reconciliation：根据 diff 结果更新 DOM
function patch(container, vnode) {
  const el = document.createElement(vnode.tag);
  for (const [key, value] of Object.entries(vnode.props || {})) {
    el.setAttribute(key, value);
  }
  (vnode.children || []).forEach(child => {
    el.appendChild(patch(document.createDocumentFragment(), child));
  });
  container.appendChild(el);
  return el;
}

// 判断节点类型是否相同，决定复用还是重建
function isSameNode(a, b) {
  return a && b && a.tag === b.tag && a.key === b.key;
}
```

```text
Reconciliation 的要点：
1. 三步 —— render 产出新树、diff 找差异、commit 更新 DOM
2. 复用优先 —— key 相同且类型相同则复用节点
3. 类型不同 —— 直接销毁重建，不递归比对
4. 可中断 —— React Fiber 把协调拆成可中断的小任务
```

## LRU Cache

LRU Cache（最近最少使用缓存）在容量满时淘汰最久没访问的项。实现靠「哈希表 + 双向链表」：哈希表 O(1) 定位节点，链表维护访问顺序，访问时把节点移到头部，淘汰时删除尾部。

```js
class LRUCache {
  constructor(capacity) {
    this.capacity = capacity;
    this.map = new Map();
  }
  get(key) {
    if (!this.map.has(key)) return -1;
    const val = this.map.get(key);
    this.map.delete(key);
    this.map.set(key, val); // 重新插入，移到最新
    return val;
  }
  put(key, val) {
    if (this.map.has(key)) this.map.delete(key);
    this.map.set(key, val);
    if (this.map.size > this.capacity) {
      // Map 迭代顺序 = 插入顺序，首个即最久未使用
      this.map.delete(this.map.keys().next().value);
    }
  }
}

const cache = new LRUCache(2);
cache.put(1, 'a');
cache.put(2, 'b');
cache.get(1);        // 访问 1，1 变最新
cache.put(3, 'c');   // 淘汰 2
console.log(cache.map.has(2)); // false
```

```text
LRU Cache 的要点：
1. 淘汰策略 —— 删除最久未使用的项
2. 哈希 + 链表 —— Map 定位 O(1)，链表维护顺序 O(1)
3. JS 技巧 —— Map 迭代顺序即插入顺序，天然适合 LRU
4. 应用 —— 内存缓存、图片缓存、Keep-Alive 组件缓存
```

## Debounce

Debounce（防抖）在事件停止触发一段时间后才执行，多次触发只执行最后一次。它适合输入框搜索、窗口 resize、按钮防重复点击等「只关心最终结果」的场景。

```js
// 防抖：停止触发 delay 毫秒后才执行
function debounce(fn, delay = 300) {
  let timer = null;
  return function (...args) {
    clearTimeout(timer);
    timer = setTimeout(() => fn.apply(this, args), delay);
  };
}

// 应用：输入框搜索
const search = debounce((keyword) => {
  console.log('搜索：', keyword);
}, 300);

// 快速输入「abc」，只在停下 300ms 后执行一次「搜索：abc」
search('a');
search('ab');
search('abc');
```

```text
Debounce 的要点：
1. 只执行最后一次 —— 前面触发被不断重置定时器
2. 适用 —— 搜索联想、resize、表单校验、防重复提交
3. 注意 this —— 用 apply 保留调用上下文
4. 变体 —— 立即执行版（先执行再防抖），用于按钮点击
```

## Throttle

Throttle（节流）固定时间间隔内最多执行一次，无论触发多频繁。它适合滚动监听、拖拽、mousemove 等「需要持续响应但不必每次」的场景，保证函数以稳定的频率执行。

```js
// 节流：每 delay 毫秒最多执行一次
function throttle(fn, delay = 300) {
  let last = 0;
  return function (...args) {
    const now = Date.now();
    if (now - last >= delay) {
      last = now;
      fn.apply(this, args);
    }
  };
}

// 应用：滚动监听
const onScroll = throttle(() => {
  console.log('滚动位置：', window.scrollY);
}, 200);
window.addEventListener('scroll', onScroll);
```

```text
Throttle 的要点：
1. 固定频率执行 —— 时间戳或定时器实现
2. 适用 —— scroll、mousemove、拖拽、resize 持续触发
3. 与防抖区别 —— 防抖是「停止后再执行」，节流是「持续但限频」
4. 变体 —— 首尾都执行版本（前缘 + 后缘）
```

## Event Delegation

Event Delegation（事件委托）利用事件冒泡，把子元素的事件统一绑定到父元素上，通过 event.target 判断实际触发者。这样动态添加的子元素无需重复绑定，大幅减少监听器数量。

```js
// 事件委托：给父容器绑一次，处理所有子项点击
document.getElementById('list').addEventListener('click', (e) => {
  const item = e.target.closest('.list-item');
  if (!item) return;
  console.log('点击了：', item.dataset.id);
  // 动态新增的 .list-item 也自动生效，无需重新绑定
});

// 匹配按钮类型
document.getElementById('list').addEventListener('click', (e) => {
  if (e.target.matches('.delete-btn')) {
    e.target.closest('.list-item').remove();
  }
});
```

```text
Event Delegation 的要点：
1. 依赖冒泡 —— 事件从目标冒泡到父元素
2. 一次绑定 —— 父元素上绑一次，动态子元素自动生效
3. target 判断 —— 用 closest/matches 过滤实际目标
4. 应用 —— 列表点击、表格操作、动态渲染的列表
5. 注意 —— focus/blur 等不冒泡的事件无法委托
```

## Scheduler

Scheduler（调度器）按优先级安排任务的执行顺序和时间，让高优任务先跑、耗时任务可中断让位。前端的调度器核心是「优先级队列 + 时间分片」，React 的并发调度和浏览器的事件循环都体现这一思想。

```js
// 简化版优先级调度器：用小顶堆按优先级执行任务
class Scheduler {
  constructor() {
    this.tasks = []; // [{ priority, fn }]
  }
  addTask(priority, fn) {
    this.tasks.push({ priority, fn });
    this.tasks.sort((a, b) => a.priority - b.priority); // 小顶堆思想
  }
  run() {
    while (this.tasks.length) {
      const task = this.tasks.shift();
      task.fn();
    }
  }
}

const s = new Scheduler();
s.addTask(3, () => console.log('低优任务'));
s.addTask(1, () => console.log('高优任务'));
s.addTask(2, () => console.log('中优任务'));
s.run(); // 高优 → 中优 → 低优
```

```text
Scheduler 的要点：
1. 优先级队列 —— 高优任务先出队
2. 时间分片 —— 大任务切成小片，避免长时间阻塞
3. 可中断 —— 任务执行中可让出主线程给更高优任务
4. 应用 —— React 并发渲染、任务队列、请求调度
```

## Dependency Graph

Dependency Graph（依赖图）用图表示模块之间的依赖关系，节点是模块，边是「A 依赖 B」。它是打包器（Webpack/Vite）、模块加载器和 Monorepo 工具计算构建顺序、检测循环依赖的基础。

```js
// 构建依赖图：模块 id -> 它依赖的模块列表
function buildDependencyGraph(modules) {
  const graph = new Map();
  for (const mod of modules) {
    graph.set(mod.id, mod.dependencies || []);
  }
  return graph;
}

const modules = [
  { id: 'entry', dependencies: ['a', 'b'] },
  { id: 'a', dependencies: ['c'] },
  { id: 'b', dependencies: ['c'] },
  { id: 'c', dependencies: [] },
];
const graph = buildDependencyGraph(modules);
console.log(graph.get('entry')); // ['a', 'b']
```

```text
Dependency Graph 的要点：
1. 有向图 —— 边从「依赖方」指向「被依赖方」
2. 用途 —— 确定打包顺序、tree-shaking、热更新传播
3. 循环检测 —— 有环则说明模块互相依赖，需报错
4. 构建产物 —— Webpack 的 module graph 就是依赖图
```

## Topological Sort

Topological Sort（拓扑排序）对有向无环图（DAG）的顶点线性排序，保证每条边的起点排在终点之前。它给出「按依赖顺序执行」的合法顺序，用于模块加载、任务调度、编译依赖解析。

```js
// 拓扑排序（Kahn 算法，基于入度）
function topologicalSort(graph) {
  const indegree = new Map();
  for (const [node, deps] of graph) {
    if (!indegree.has(node)) indegree.set(node, 0);
    for (const dep of deps) {
      indegree.set(dep, (indegree.get(dep) || 0) + 1);
    }
  }
  const queue = [];
  for (const [node, deg] of indegree) {
    if (deg === 0) queue.push(node);
  }
  const order = [];
  while (queue.length) {
    const node = queue.shift();
    order.push(node);
    for (const dep of graph.get(node) || []) {
      indegree.set(dep, indegree.get(dep) - 1);
      if (indegree.get(dep) === 0) queue.push(dep);
    }
  }
  // 排序节点数少于总节点数，说明有环
  return order.length === indegree.size ? order : null;
}

const g = new Map([
  ['a', ['b']],
  ['b', ['c']],
  ['c', []],
]);
console.log(topologicalSort(g)); // ['a', 'b', 'c']
```

```text
Topological Sort 的要点：
1. 前提 —— 图必须是无环的（DAG）
2. Kahn 算法 —— 反复取出入度为 0 的节点
3. 判环 —— 排序结果数量少于节点数即有环
4. 应用 —— 模块加载顺序、构建依赖、任务编排
```

### 场景二：用虚拟列表渲染 10 万行数据

```html
<!-- 固定行高虚拟列表，DOM 里始终只有几十个节点 -->
<div id="viewport" style="height:400px;overflow:auto">
  <div id="spacer"></div>
  <div id="content"></div>
</div>
<script>
  const TOTAL = 100000, ITEM_HEIGHT = 40;
  const spacer = document.getElementById('spacer');
  const content = document.getElementById('content');
  spacer.style.height = TOTAL * ITEM_HEIGHT + 'px';

  function render(scrollTop) {
    const start = Math.floor(scrollTop / ITEM_HEIGHT);
    const count = Math.ceil(400 / ITEM_HEIGHT) + 2;
    content.style.transform = `translateY(${start * ITEM_HEIGHT}px)`;
    content.innerHTML = Array.from({ length: count }, (_, i) =>
      `<div style="height:${ITEM_HEIGHT}px">第 ${start + i} 行</div>`
    ).join('');
  }
  document.getElementById('viewport')
    .addEventListener('scroll', (e) => render(e.target.scrollTop));
  render(0);
</script>
```

## 最佳实践与踩坑记录

### 最佳实践

1. 长列表（超过千行）一定要上虚拟列表，别硬渲染全量 DOM
2. 列表项要传稳定的 key，Diff 才能正确复用节点，避免错乱
3. 搜索输入用防抖，滚动/拖拽用节流，别混用
4. 列表事件用事件委托，动态节点自动生效且省内存
5. 缓存淘汰优先想到 LRU，JS 里用 Map 即可简单实现
6. 模块/任务有依赖顺序时，用拓扑排序，别手写顺序硬编码

### 踩坑记录

```text
坑 1：列表项用数组下标当 key
结论：列表重排或插入时，DOM 复用错乱，状态串位。
原因：index 不是稳定标识，重排后同一 index 指向不同数据。
解法：用业务唯一 id 当 key，保证 Diff 能正确识别节点。

坑 2：防抖节流混淆，滚动卡顿
结论：滚动监听用了防抖，滚动过程中完全不响应，体验割裂。
原因：没区分「停止后执行」和「持续限频」的语义。
解法：滚动/拖拽/mousemove 用节流，输入搜索/按钮用防抖。

坑 3：虚拟列表不设置容器总高度
结论：滚动条拉不到底，后面的数据永远看不到。
原因：只渲染了可见项，却没撑起占位高度。
解法：容器总高度 = 总数据量 x 行高（或预估高度之和）。

坑 4：LRU 用数组存访问记录，每次淘汰 O(n)
结论：缓存读写频繁时性能差。
原因：用数组 indexOf 找最久未使用项，是 O(n) 扫描。
解法：用 Map（或哈希 + 双向链表），get/put 都 O(1)。

坑 5：事件委托没过滤 target
结论：点到子元素空白处也触发了处理逻辑，行为异常。
原因：直接在父元素回调里处理，没判断实际触发者。
解法：用 e.target.closest/matches 过滤到目标元素再处理。
```

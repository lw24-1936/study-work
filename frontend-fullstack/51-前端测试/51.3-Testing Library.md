## 概述

Testing Library 是一套"从用户视角测试"的工具族，核心是 DOM Testing Library，React/Vue 等框架各有适配层。它的哲学是：测试应该关注用户看到什么、能做什么，而不是组件的内部实现。

```text
Testing Library 的核心理念：
1. 从用户角度找元素 —— 用 role、label、文本，而不是 CSS 类名或组件实例
2. 从用户角度交互 —— 点击、输入、聚焦，模拟真实操作
3. 从用户角度断言 —— 断言可见内容、可访问性状态

这个理念的直接收益：
测试贴近真实使用，重构内部实现不破坏测试，天然兼顾可访问性。
```

```text
// 家族构成
@testing-library/dom       —— 核心，框架无关的 DOM 查询与事件
@testing-library/react     —— React 适配（render + RTL 钩子）
@testing-library/vue       —— Vue 适配
@testing-library/user-event —— 模拟真实用户交互（推荐替代 fireEvent）
@testing-library/jest-dom  —— 扩展 DOM 相关匹配器
```

```text
查询优先级（官方推荐，从高到低）：
getByRole / findByRole —— 最贴近用户和可访问性
getByLabelText —— 表单字段
getByPlaceholderText —— 占位符
getByText —— 可见文本
getByDisplayValue —— 输入值
getByAltText —— 图片 alt
getByTitle —— title 属性
getByTestId —— 兜底（找不到合适查询时最后的选择）
```

## DOM Testing Library

DOM Testing Library 是核心层，提供查询（query）、事件（fireEvent）和等待（waitFor）能力，框架适配层都建立在它之上。

```js
// 核心查询 API 的三种变体
import { screen, getByText } from '@testing-library/dom';

// getBy* —— 找不到抛错（同步）
// queryBy* —— 找不到返回 null（用于断言"不存在"）
// findBy* —— 异步等待元素出现（用于异步渲染）
```

```js
// 查询示例
const button = screen.getByRole('button', { name: '提交' });      // 按钮 + 文本
const input = screen.getByLabelText('用户名');                      // 关联 label
const heading = screen.getByRole('heading', { level: 1 });          // h1
const notFound = screen.queryByText('不存在的内容');                // 返回 null
```

```js
// 异步等待：元素出现
import { screen, waitFor } from '@testing-library/dom';

await screen.findByText('加载完成');           // 等待文本出现

await waitFor(() => {
  expect(screen.getByText('数据已更新')).toBeInTheDocument();
});
```

```text
查询 API 的语义：
getBy* —— 同步，找不到立即抛错，适合"应该已存在"
queryBy* —— 同步，找不到返回 null，适合断言"不存在"
findBy* —— 异步，内部 waitFor，适合"稍后会出现"
```

## React Testing Library

React Testing Library（RTL）是 React 的适配层，提供 render、screen、cleanup 和 React 专用钩子，是 React 组件测试的事实标准。

```jsx
// 被测组件
function Counter() {
  const [count, setCount] = React.useState(0);
  return (
    <div>
      <p>当前计数：{count}</p>
      <button onClick={() => setCount(c => c + 1)}>加一</button>
    </div>
  );
}
```

```jsx
// 组件测试
import { render, screen } from '@testing-library/react';
import userEvent from '@testing-library/user-event';
import Counter from './Counter';

test('点击按钮计数加一', async () => {
  render(<Counter />);

  expect(screen.getByText('当前计数：0')).toBeInTheDocument();

  await userEvent.click(screen.getByRole('button', { name: '加一' }));

  expect(screen.getByText('当前计数：1')).toBeInTheDocument();
});
```

```jsx
// 测试受控表单 + 提交
import { render, screen } from '@testing-library/react';
import userEvent from '@testing-library/user-event';

function LoginForm({ onSubmit }) {
  const [name, setName] = React.useState('');
  return (
    <form onSubmit={e => { e.preventDefault(); onSubmit(name); }}>
      <label htmlFor="name">用户名</label>
      <input id="name" value={name} onChange={e => setName(e.target.value)} />
      <button type="submit">登录</button>
    </form>
  );
}

test('提交时回传用户名', async () => {
  const onSubmit = vi.fn();
  render(<LoginForm onSubmit={onSubmit} />);

  await userEvent.type(screen.getByLabelText('用户名'), 'alice');
  await userEvent.click(screen.getByRole('button', { name: '登录' }));

  expect(onSubmit).toHaveBeenCalledWith('alice');
});
```

```text
React Testing Library 要点：
1. render 渲染到内存 DOM，screen 是全局查询入口
2. 用 jest-dom 扩展的匹配器（toBeInTheDocument、toBeDisabled）
3. 状态更新后用 findBy*/waitFor 等待，不用 act 手动包裹（RTL 已处理）
```

## Vue Testing Library

Vue Testing Library 是 Vue 3 的适配层，同样遵循"用户视角"理念，与 Vue Test Utils 相比更贴近 Testing Library 的查询风格。

```vue
<!-- 被测组件 Counter.vue -->
<script setup>
import { ref } from 'vue';
const count = ref(0);
</script>

<template>
  <div>
    <p>当前计数：{{ count }}</p>
    <button @click="count++">加一</button>
  </div>
</template>
```

```js
// 组件测试
import { render, screen } from '@testing-library/vue';
import userEvent from '@testing-library/user-event';
import Counter from './Counter.vue';

test('点击按钮计数加一', async () => {
  render(Counter);

  expect(screen.getByText('当前计数：0')).toBeInTheDocument();

  await userEvent.click(screen.getByRole('button', { name: '加一' }));

  expect(screen.getByText('当前计数：1')).toBeInTheDocument();
});
```

```js
// 测试 props 与事件
import { render, screen } from '@testing-library/vue';

test('渲染传入的标题并触发事件', async () => {
  const { emitted } = render(MyButton, {
    props: { label: '保存' },
  });

  const button = screen.getByRole('button', { name: '保存' });
  await userEvent.click(button);

  expect(emitted()).toHaveProperty('click');
});
```

```text
Vue Testing Library 要点：
1. render(Component, { props, slots, global }) 支持完整组件配置
2. emitted() 返回组件触发的事件记录
3. 需要 @testing-library/jest-dom 和 user-event 配套
```

## User Event

user-event 是模拟真实用户交互的库，相比 fireEvent 的底层事件分发，它模拟完整交互序列（如点击 = 聚焦 + 按下 + 抬起），更接近真实浏览器行为。

```text
fireEvent vs userEvent：
fireEvent —— 触发单个底层事件（fireEvent.click 只派发 click）
userEvent —— 模拟真实交互序列（userEvent.click 会先 focus 再 pointer 再 click）

推荐用 userEvent，更真实、能暴露 fireEvent 测不出的问题
（如按钮 disabled 时 userEvent 点不进去，fireEvent 却"点得动"）。
```

```js
import userEvent from '@testing-library/user-event';

const user = userEvent.setup();   // 推荐用 setup 创建实例

// 常用交互
await user.click(button);                    // 点击
await user.type(input, 'hello');             // 逐字输入
await user.clear(input);                     // 清空
await user.selectOptions(select, 'option');  // 下拉选择
await user.dblClick(element);                // 双击
await user.hover(element);                   // 悬停
await user.upload(input, file);              // 上传文件
await user.keyboard('{Enter}');              // 键盘按键
await user.tab();                            // Tab 切换焦点
```

```js
// 完整示例：搜索框输入 + 回车
test('输入关键词回车触发搜索', async () => {
  const onSearch = vi.fn();
  render(<SearchBox onSearch={onSearch} />);

  const user = userEvent.setup();
  await user.type(screen.getByRole('textbox'), 'react');
  await user.keyboard('{Enter}');

  expect(onSearch).toHaveBeenCalledWith('react');
});
```

```text
userEvent 使用要点：
1. 用 userEvent.setup() 创建实例，方法都是异步的（await）
2. type 是逐字符输入，会触发每次 onChange（受控组件要注意）
3. 粘贴大段文本用 user.paste 或 fireEvent.change 更高效
```

## 应用场景实战

### 场景一：测试异步数据加载组件

```jsx
import { render, screen } from '@testing-library/react';
import UserProfile from './UserProfile';

// UserProfile 挂载后调 /api/user/1 并渲染
test('加载完成后显示用户信息', async () => {
  render(<UserProfile id={1} />);

  // 加载中
  expect(screen.getByText('加载中...')).toBeInTheDocument();

  // 等待异步数据渲染
  expect(await screen.findByText('Alice')).toBeInTheDocument();
  expect(screen.getByText('alice@example.com')).toBeInTheDocument();
});
```

### 场景二：测试表单校验流程

```jsx
import { render, screen } from '@testing-library/react';
import userEvent from '@testing-library/user-event';
import RegistrationForm from './RegistrationForm';

test('空表单提交显示所有校验错误', async () => {
  render(<RegistrationForm />);
  const user = userEvent.setup();

  await user.click(screen.getByRole('button', { name: '注册' }));

  expect(await screen.findByText('请输入用户名')).toBeInTheDocument();
  expect(screen.getByText('请输入邮箱')).toBeInTheDocument();

  // 填入有效值后错误消失
  await user.type(screen.getByLabelText('用户名'), 'alice');
  await user.type(screen.getByLabelText('邮箱'), 'alice@example.com');
  await user.click(screen.getByRole('button', { name: '注册' }));

  expect(screen.queryByText('请输入用户名')).not.toBeInTheDocument();
});
```

## 最佳实践与踩坑记录

### 最佳实践

1. 查询优先用 getByRole/getByLabelText，最后才用 getByTestId
2. 交互用 userEvent.setup()，不用 fireEvent（除非确有必要）
3. 断言用户可见的结果，不断言内部 state 和实现细节
4. 异步渲染用 findBy*/waitFor，不写手动 sleep
5. jest-dom 的匹配器（toBeDisabled、toBeChecked）让断言更语义化
6. 测试命名描述用户行为（"点击后显示错误"），而非实现（"setState 被调用"）

### 踩坑记录

```text
坑 1：过度使用 getByTestId
结论：测试和 DOM 结构强耦合，重构即挂。
原因：图省事给每个元素加 testid，绕开了语义查询。
解法：优先 role/label/text，testid 只作为最后兜底。

坑 2：用 fireEvent 测 disabled 按钮
结论：disabled 按钮"点击成功"，测出假阳性。
原因：fireEvent.click 绕过 disabled 限制直接派发事件。
解法：用 userEvent.click，它尊重真实交互约束。

坑 3：act 警告
结论：测试报 "not wrapped in act(...)" 警告。
原因：状态更新发生在测试外的异步回调里。
解法：用 findBy*/waitFor 等待，RTL 已正确包裹 act。

坑 4：type 输入中文/特殊字符异常
结论：userEvent.type 对某些字符处理不一致。
原因：type 逐字符触发 keydown/keyup，特殊字符映射复杂。
解法：整段赋值用 user.paste 或 fireEvent.change 设置 value。

坑 5：异步组件没等待就断言
结论：测试断言时数据还没渲染，报"找不到元素"。
原因：用 getByText 同步查询异步渲染的内容。
解法：改用 findByText 或 waitFor 等待元素出现。
```

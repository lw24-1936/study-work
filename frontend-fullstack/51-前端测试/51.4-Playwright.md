## 概述

Playwright 是微软开源的端到端测试框架，一个 API 驱动 Chromium、Firefox、WebKit 三大浏览器，并内置自动等待、Trace 录制、网络拦截、截图录屏等能力，是目前 E2E 测试的事实标准之一。

```text
Playwright 的核心优势：
1. 多浏览器 —— 一套脚本跑 Chromium / Firefox / WebKit
2. 自动等待 —— 点击、断言前自动等元素可交互、可见
3. 强大调试 —— Trace Viewer 回放每一步操作
4. 网络控制 —— 拦截、Mock、监听请求响应
5. 并行隔离 —— 每个测试独立浏览器上下文，互不污染
```

```js
// 最小可运行示例
import { test, expect } from '@playwright/test';

test('首页标题正确', async ({ page }) => {
  await page.goto('https://example.com');
  await expect(page).toHaveTitle(/Example/);
});
```

```text
Playwright 的抽象层级：
Browser（浏览器进程）
  └─ Context（浏览器上下文，隔离 Cookie/Storage）
       └─ Page（单个标签页）
            └─ Locator（页面上的元素定位器）
```

## Browser

Browser 表示一个浏览器进程，通过 `chromium.launch()` 启动。测试框架通常由 fixture 自动管理，但也可以手动控制。

```js
import { chromium } from 'playwright';

// 启动浏览器（有头模式便于调试）
const browser = await chromium.launch({ headless: false });

// 创建上下文
const context = await browser.newContext({
  viewport: { width: 1280, height: 720 },
  locale: 'zh-CN',
});

const page = await context.newPage();
await page.goto('https://example.com');

await browser.close();
```

```text
Browser 的关键概念：
1. launch —— 启动浏览器进程（headless 控制是否显示窗口）
2. newContext —— 创建隔离的浏览器上下文
3. close —— 关闭浏览器，释放进程

Browser 与 Context 的区别：
Browser 是进程级，Context 是会话级。
一个 Browser 可开多个 Context，Context 之间 Cookie、Storage、登录态完全隔离，
这就是 Playwright 测试能并行且互不干扰的原因。
```

```js
// 多个 Context 模拟多个独立用户
const browser = await chromium.launch();
const userA = await browser.newContext();
const userB = await browser.newContext();

const pageA = await userA.newPage();
const pageB = await userB.newPage();
// pageA 与 pageB 的登录态、Cookie 互不影响
```

## Page

Page 代表一个标签页，是绝大多数操作的入口：导航、点击、截图、获取内容都通过 Page 进行。

```js
import { test, expect } from '@playwright/test';

test('Page 常用操作', async ({ page }) => {
  // 导航
  await page.goto('https://example.com/login');

  // 前进后退
  await page.goBack();
  await page.goForward();

  // 获取 URL 与标题
  console.log(page.url());
  console.log(await page.title());

  // 执行 JavaScript
  const result = await page.evaluate(() => document.title);

  // 等待导航
  await Promise.all([
    page.waitForURL('**/dashboard'),
    page.getByRole('button', { name: '登录' }).click(),
  ]);
});
```

```text
Page 常用 API 分类：
1. 导航 —— goto / goBack / goForward / reload
2. 信息 —— url / title / content
3. 交互 —— click / fill / selectOption / check
4. 等待 —— waitForURL / waitForSelector / waitForLoadState
5. 脚本 —— evaluate / evaluateHandle（在页面上下文执行 JS）
```

```js
// 常见等待策略
await page.waitForLoadState('networkidle');  // 网络空闲
await page.waitForSelector('.result');        // 元素出现
await page.waitForTimeout(1000);              // 固定等待（尽量少用）
```

## Locator

Locator 是 Playwright 定位元素的方式，代表"如何找到某个元素"，只有在交互或断言时才真正解析。它支持自动等待和链式筛选。

```js
import { test, expect } from '@playwright/test';

test('Locator 定位方式', async ({ page }) => {
  await page.goto('https://example.com/form');

  // 按角色（推荐，最贴近用户视角）
  await page.getByRole('button', { name: '提交' }).click();

  // 按标签（表单控件）
  await page.getByLabel('用户名').fill('alice');

  // 按文本
  await page.getByText('欢迎回来').click();

  // 按占位符
  await page.getByPlaceholder('请输入密码').fill('secret');

  // CSS / XPath 选择器
  await page.locator('.submit-btn').click();
  await page.locator('//button[contains(text(), "确定")]').click();
});
```

```text
Locator 定位优先级（从高到低）：
1. getByRole —— 语义角色，最贴近用户与可访问性
2. getByLabel —— 表单标签
3. getByPlaceholder —— 占位符
4. getByText —— 可见文本
5. getByTestId —— 测试专用 data-testid
6. CSS / XPath —— 兜底方案

原则：优先用 role/label/text，少用脆弱的 CSS 类名。
```

```js
// Locator 链式筛选与过滤
const list = page.getByRole('list');
const firstItem = list.getByRole('listitem').first();
const item = list.getByRole('listitem').filter({ hasText: '订单' });

// 计数与断言
await expect(list.getByRole('listitem')).toHaveCount(3);

// 遍历元素
const items = page.getByRole('listitem');
for (let i = 0; i < (await items.count()); i++) {
  console.log(await items.nth(i).textContent());
}
```

## Assertion

Playwright 用独立的 expect 断言库，断言会自动重试直到通过或超时，这解决了"点击后立即断言"的竞态问题。

```js
import { test, expect } from '@playwright/test';

test('常见断言', async ({ page }) => {
  await page.goto('https://example.com/dashboard');

  // 可见性
  await expect(page.getByText('订单列表')).toBeVisible();

  // 文本内容
  await expect(page.locator('.price')).toHaveText('¥99.00');

  // 值
  await expect(page.getByLabel('用户名')).toHaveValue('alice');

  // 计数
  await expect(page.getByRole('listitem')).toHaveCount(5);

  // URL / 标题
  await expect(page).toHaveURL(/dashboard/);
  await expect(page).toHaveTitle('控制台');

  // 属性
  await expect(page.getByRole('button', { name: '提交' })).toBeDisabled();

  // 截图对比
  await expect(page).toHaveScreenshot('home.png');
});
```

```text
自动重试的机制：
expect 默认在超时时间内不断重试断言，直到通过。
这就是为什么"点击后立即断言结果"不需要手动 sleep。

可配置超时：
1. expect 超时默认 5 秒
2. 在 playwright.config.js 里设置 expect: { timeout: 10000 }
3. 单个断言可传第二参数覆盖：expect(x).toBeVisible({ timeout: 3000 })
```

```js
// 软断言：收集所有失败而非在第一个失败处停止
test('软断言', async ({ page }) => {
  await page.goto('https://example.com');
  await expect.soft(page.getByText('标题')).toBeVisible();
  await expect.soft(page.getByRole('button')).toBeVisible();
  // 两个断言都会执行并一起报告
});
```

## Trace

Trace 是 Playwright 的"录制回放"能力，记录测试的每一步操作、截图、网络请求、控制台日志，用 Trace Viewer 可视化回放，是定位偶发失败的神器。

```js
// playwright.config.js
import { defineConfig } from '@playwright/test';

export default defineConfig({
  use: {
    // 失败时自动保留 trace
    trace: 'retain-on-failure',
    screenshot: 'only-on-failure',
    video: 'retain-on-failure',
  },
});
```

```bash
# 查看 trace
npx playwright show-trace test-results/example-xxx/trace.zip
```

```text
trace 的四种模式：
1. off —— 不记录
2. on —— 每次都记录
3. retain-on-failure —— 仅在失败时保留（推荐）
4. on-first-retry —— 首次失败重试时记录

Trace Viewer 能看什么：
1. 逐步回放每一步操作（点击、输入、导航）
2. 每步前后的页面截图
3. 网络请求与响应
4. 控制台日志与错误
5. 源码定位（配合 source map）
```

## Screenshot

Playwright 支持全页、元素、可视区域截图，可用于视觉回归测试和失败排查。

```js
import { test, expect } from '@playwright/test';

test('截图能力', async ({ page }) => {
  await page.goto('https://example.com');

  // 可视区域截图
  await page.screenshot({ path: 'viewport.png' });

  // 全页截图
  await page.screenshot({ path: 'fullpage.png', fullPage: true });

  // 元素截图
  await page.locator('.chart').screenshot({ path: 'chart.png' });

  // 截图对比（视觉回归）
  await expect(page).toHaveScreenshot('home.png');
});
```

```text
截图的应用场景：
1. 失败排查 —— 失败时自动截图，快速定位现场
2. 视觉回归 —— toHaveScreenshot 与基线对比，发现样式回归
3. 文档生成 —— 自动生成 UI 文档配图

toHaveScreenshot 的工作流：
首次运行生成基线截图，后续运行逐像素对比，
有差异则报错，人工确认后更新基线：
npx playwright test --update-snapshots
```

## Video

Video 记录整个测试过程的视频，失败时回放可以还原用户操作的完整路径，比截图更完整。

```js
// playwright.config.js
import { defineConfig } from '@playwright/test';

export default defineConfig({
  use: {
    video: 'retain-on-failure',  // 失败保留视频
  },
});
```

```js
// 测试内单独控制
test('录制视频', async ({ page, browserName }) => {
  await page.goto('https://example.com');
  await page.getByRole('button', { name: '开始' }).click();

  // 测试结束后，视频保存在 test-results 目录
});
```

```text
video 的配置：
1. off —— 不录制（默认，性能最好）
2. on —— 每次都录制
3. retain-on-failure —— 仅失败保留（推荐）
4. on-first-retry —— 重试时录制

注意：
视频录制会增加测试耗时，默认关闭或仅失败保留，
避免拖慢 CI。视频文件保存在 test-results/<测试名>/ 下。
```

## Network Mock

Playwright 可以在网络层拦截、修改、伪造请求与响应，用于隔离后端依赖、测试边界场景、稳定测试环境。

```js
import { test, expect } from '@playwright/test';

test('拦截并 Mock API 响应', async ({ page }) => {
  // Mock 单个接口
  await page.route('**/api/users', (route) => {
    route.fulfill({
      status: 200,
      contentType: 'application/json',
      body: JSON.stringify([{ id: 1, name: 'Alice' }]),
    });
  });

  await page.goto('https://example.com');
  await expect(page.getByText('Alice')).toBeVisible();
});
```

```js
// 拦截并修改真实请求
await page.route('**/api/orders', async (route) => {
  const response = await route.fetch();   // 真实请求
  const body = await response.json();
  body.push({ id: 999, name: 'mock order' });
  await route.fulfill({ response, json: body });
});

// 直接 abort（模拟网络失败）
await page.route('**/api/payment', (route) => route.abort());

// 延迟响应（模拟慢接口）
await page.route('**/api/search', async (route) => {
  await new Promise((r) => setTimeout(r, 3000));
  await route.continue();
});
```

```js
// 监听网络请求（不拦截）
const requests = [];
page.on('request', (req) => requests.push(req.url()));
page.on('response', (res) => console.log(res.status(), res.url()));

// 等待某个请求完成
const [response] = await Promise.all([
  page.waitForResponse('**/api/login'),
  page.getByRole('button', { name: '登录' }).click(),
]);
expect(response.status()).toBe(200);
```

```text
route 的三个核心操作：
1. fulfill —— 直接返回伪造响应（不走网络）
2. continue —— 放行真实请求（可先修改请求）
3. abort —— 中断请求（模拟失败）

Network Mock 的价值：
1. 隔离后端 —— 后端未就绪也能测前端
2. 测试边界 —— 轻松模拟 500、超时、慢响应
3. 稳定测试 —— 摆脱对真实数据的依赖
```

## 应用场景实战

### 场景一：登录并提交订单的完整 E2E

```js
import { test, expect } from '@playwright/test';

test.describe('订单流程', () => {
  test.beforeEach(async ({ page }) => {
    await page.goto('https://example.com/login');
    await page.getByLabel('用户名').fill('alice');
    await page.getByLabel('密码').fill('secret123');
    await page.getByRole('button', { name: '登录' }).click();
    await expect(page).toHaveURL(/dashboard/);
  });

  test('登录后创建订单', async ({ page }) => {
    await page.getByRole('button', { name: '新建订单' }).click();
    await page.getByLabel('商品').fill('MacBook Pro');
    await page.getByLabel('数量').fill('1');
    await page.getByRole('button', { name: '提交' }).click();

    await expect(page.getByText('订单创建成功')).toBeVisible();
  });
});
```

### 场景二：Mock 后端实现前后端并行开发

```js
import { test, expect } from '@playwright/test';

test('后端未就绪时 Mock 接口测前端', async ({ page }) => {
  // 一次性 Mock 多个接口
  await page.route('**/api/**', (route) => {
    const url = route.request().url();
    if (url.includes('/api/user')) {
      return route.fulfill({
        json: { id: 1, name: 'Alice', role: 'admin' },
      });
    }
    if (url.includes('/api/orders')) {
      return route.fulfill({
        json: { list: [{ id: 1, total: 99 }], total: 1 },
      });
    }
    return route.continue();
  });

  await page.goto('https://example.com');
  await expect(page.getByText('Alice')).toBeVisible();
  await expect(page.getByText('¥99.00')).toBeVisible();
});
```

## 最佳实践与踩坑记录

### 最佳实践

1. 用 getByRole/getByLabel 定位，少用脆弱的 CSS 类名
2. 依赖自动等待，避免 waitForTimeout 固定等待
3. 每个测试独立上下文，不共享登录态和数据
4. trace/screenshot/video 用 retain-on-failure，失败时自动留证
5. 网络 Mock 隔离后端，让 E2E 稳定可控
6. 用软断言（expect.soft）在表单类测试里一次收集多个问题

### 踩坑记录

```text
坑 1：点击后立即断言偶发失败
结论：断言偶尔红，重跑又绿。
原因：没利用自动重试，或用了 toBe(true) 这类不重试的断言。
解法：用 Playwright 的 expect（自动重试），别用原生判断。

坑 2：CSS 类名定位脆弱
结论：改个样式类名，测试全挂。
原因：依赖了会频繁变动的 CSS 类名。
解法：改用 role/label/testid 等语义定位。

坑 3：测试间共享状态导致顺序依赖
结论：用例换个顺序就挂。
原因：多个测试复用同一个登录态或数据。
解法：beforeEach 独立登录，或每个测试独立造数据。

坑 4：全页截图包含动态内容导致视觉回归误报
结论：时钟、广告等动态元素让截图对比一直失败。
原因：基线包含不稳定区域。
解法：截图前 mask 动态区域，或固定时间/数据。

坑 5：录制视频导致 CI 变慢
结论：全量视频让测试时长翻倍。
原因：每次都录视频且保留。
解法：video 用 retain-on-failure，只留失败现场。
```

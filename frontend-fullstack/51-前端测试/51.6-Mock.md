## 概述

Mock 是在测试或开发阶段用假数据替代真实依赖的技术。前端最常 Mock 的是 API——后端未就绪、测试要隔离外部服务、或需要模拟边界场景（报错、慢响应）时，用 Mock 让前端独立运行。

```text
前端 Mock 的三种层次：
1. 函数级 Mock —— 替换单个函数/模块（jest.fn、vi.fn）
2. 网络级 Mock —— 拦截 HTTP 请求（MSW、Playwright route）
3. 数据级 Mock —— 用假数据替换真实响应（Mock Data）

网络级 Mock 是前端最核心的场景，因为它让前端彻底摆脱后端依赖。
```

```js
// 函数级 Mock（单元测试）
import { vi } from 'vitest';
const fn = vi.fn().mockReturnValue(42);
fn();                    // 返回 42
expect(fn).toHaveBeenCalledTimes(1);
```

```text
为什么用网络级 Mock（MSW）而不是直接 Mock axios/fetch：
1. 拦截在 Service Worker 层，测试代码和业务代码都无感知
2. 同一套 Mock 定义可复用到开发、测试、演示环境
3. 不侵入业务代码，不需要改 import 或注入依赖
```

## MSW 与 Mock Service Worker

MSW（Mock Service Worker）是一个 API Mock 库，通过在浏览器注册 Service Worker 拦截真实的网络请求，用定义的 handler 返回 Mock 响应。请求照常发出，被 Worker 在底层接管，业务代码完全无感知。

```js
// src/mocks/handlers.js —— 定义 Mock 接口
import { http, HttpResponse } from 'msw';

export const handlers = [
  http.get('/api/users', () => {
    return HttpResponse.json([
      { id: 1, name: 'Alice' },
      { id: 2, name: 'Bob' },
    ]);
  }),

  http.post('/api/login', async ({ request }) => {
    const { username } = await request.json();
    return HttpResponse.json({ token: `${username}-token` });
  }),

  http.get('/api/error', () => {
    return HttpResponse.json({ message: '服务器错误' }, { status: 500 });
  }),
];
```

```js
// src/mocks/browser.js —— 浏览器环境启动 Worker
import { setupWorker } from 'msw/browser';
import { handlers } from './handlers';

export const worker = setupWorker(...handlers);

// 应用入口处按环境启动
if (process.env.NODE_ENV === 'development') {
  worker.start();
}
```

```bash
# 初始化 MSW，生成 Service Worker 文件
npx msw init public/ --save
```

```text
MSW 的工作原理：
1. 注册 Service Worker 拦截页面发出的所有网络请求
2. 请求被转发到 MSW，匹配已定义的 handler
3. 命中 handler 则返回 Mock 响应，未命中则放行到真实网络

关键优势：
1. 网络层拦截 —— 业务代码（fetch/axios）完全不用改
2. 一次定义多处复用 —— 开发、单测、E2E 共用同一套 handler
3. 真实请求语义 —— request/response 与真实网络一致
```

```js
// Node 环境（单测、SSR）用 setupServer
import { setupServer } from 'msw/node';
import { handlers } from './handlers';

const server = setupServer(...handlers);

beforeAll(() => server.listen());
afterEach(() => server.resetHandlers());
afterAll(() => server.close());
```

## API Mock

API Mock 是把某个接口的响应替换为假数据。除了 MSW，还有多种方式，各有适用场景。

```js
// 方式一：MSW handler 拦截
import { http, HttpResponse } from 'msw';
http.get('/api/product', () =>
  HttpResponse.json({ id: 1, name: 'MacBook', price: 9999 })
);
```

```js
// 方式二：Vite 开发服务器代理到本地 Mock 服务
// vite.config.js
export default {
  server: {
    proxy: {
      '/api': {
        target: 'http://localhost:3001', // 本地 mock 服务
        changeOrigin: true,
      },
    },
  },
};
```

```js
// 方式三：json-server 快速起一个 Mock 后端
// db.json
{
  "users": [{ "id": 1, "name": "Alice" }],
  "orders": [{ "id": 1, "userId": 1, "total": 99 }]
}
```

```bash
# 启动 json-server，自动生成 REST 接口
npx json-server --watch db.json --port 3001
```

```text
API Mock 方案对比：
MSW —— 网络层拦截，无真实请求，可复用，适合前端自主 Mock
json-server —— 快速生成真实 REST 后端，适合原型和联调前
代理转发 —— 转发到本地 Mock 服务，适合已有 Mock 后端
Playwright route —— 测试内动态拦截，适合 E2E 边界场景

选择原则：
开发联调前用 MSW/json-server，E2E 边界场景用测试框架的拦截能力。
```

## Mock Data

Mock Data 是用于替换真实数据的假数据。好的 Mock Data 要真实、稳定、可控，还要能覆盖边界和异常情况。

```js
// 用 faker 生成逼真的假数据
import { faker } from '@faker-js/faker';

export function createUser(overrides = {}) {
  return {
    id: faker.string.uuid(),
    name: faker.person.fullName(),
    email: faker.internet.email(),
    avatar: faker.image.avatar(),
    ...overrides,
  };
}

export const users = Array.from({ length: 20 }, () => createUser());
```

```js
// 用工厂函数 + 覆盖，生成特定场景的数据
import { createUser } from './mockData';

const admin = createUser({ role: 'admin' });          // 管理员
const vip = createUser({ role: 'vip', level: 5 });    // VIP 用户
const empty = createUser({ name: '' });               // 异常：空名字
```

```text
Mock Data 的设计要点：
1. 真实性 —— 字段、类型、格式贴近真实数据
2. 稳定性 —— 不依赖随机导致测试偶发失败（随机也要可固定 seed）
3. 可控性 —— 工厂函数 + overrides 精确控制字段
4. 覆盖度 —— 正常 + 边界 + 异常三种数据都要有

faker 的 seed 固定随机：
faker.seed(123) 之后生成的数据可复现，避免测试偶发失败。
```

```js
// 固定随机种子，保证测试稳定
import { faker } from '@faker-js/faker';

beforeEach(() => {
  faker.seed(42);   // 每次生成相同的数据序列
});
```

## 应用场景实战

### 场景一：前后端并行开发

```js
// 后端接口还没写好，前端用 MSW 定义契约先行开发
// src/mocks/handlers.js
import { http, HttpResponse } from 'msw';

export const handlers = [
  http.get('/api/dashboard', () =>
    HttpResponse.json({
      totalUsers: 1280,
      totalOrders: 456,
      revenue: 128500,
    })
  ),
  http.get('/api/recent-orders', () =>
    HttpResponse.json([
      { id: 1, product: 'MacBook', total: 9999, status: 'paid' },
      { id: 2, product: 'iPhone', total: 6999, status: 'pending' },
    ])
  ),
];

// 应用启动时启动 Worker，前端即可独立开发
if (import.meta.env.DEV) {
  const { worker } = await import('./mocks/browser');
  await worker.start();
}
```

### 场景二：单测里 Mock API 测试数据流

```js
import { render, screen } from '@testing-library/react';
import { setupServer } from 'msw/node';
import { http, HttpResponse } from 'msw';
import UserList from './UserList';

const server = setupServer(
  http.get('/api/users', () =>
    HttpResponse.json([{ id: 1, name: 'Alice' }])
  )
);

beforeAll(() => server.listen());
afterEach(() => server.resetHandlers());
afterAll(() => server.close());

test('渲染用户列表', async () => {
  render(<UserList />);
  expect(await screen.findByText('Alice')).toBeInTheDocument();
});

test('接口失败显示错误提示', async () => {
  server.use(
    http.get('/api/users', () => HttpResponse.json(null, { status: 500 }))
  );
  render(<UserList />);
  expect(await screen.findByText('加载失败')).toBeInTheDocument();
});
```

## 最佳实践与踩坑记录

### 最佳实践

1. 用 MSW 做网络层 Mock，业务代码零侵入、多处复用
2. 同一套 handler 复用到开发、单测、E2E，减少重复定义
3. Mock Data 用工厂函数 + overrides，覆盖正常、边界、异常
4. 随机数据用 faker.seed 固定，避免测试偶发失败
5. Node 单测用 setupServer，浏览器开发用 setupWorker
6. 未命中的请求放行真实网络，Mock 与真实共存

### 踩坑记录

```text
坑 1：Mock 数据过于理想化
结论：测试全绿，真实环境一上线就出问题。
原因：Mock Data 只有正常数据，没有边界和异常。
解法：覆盖空数据、长文本、特殊字符、500 等边界场景。

坑 2：随机数据导致测试偶发失败
结论：同一测试时过时挂。
原因：faker 每次生成不同数据，断言依赖具体值。
解法：用 faker.seed 固定随机种子，或断言结构而非具体值。

坑 3：Mock 没覆盖到的请求穿透到真实后端
结论：测试环境意外打到真实接口。
原因：handler 未定义完整，未命中请求放行。
解法：用 onUnhandledRequest 检测，未 mock 的请求告警或报错。

坑 4：MSW Worker 未注册就发请求
结论：页面报 Service Worker 未找到。
原因：没运行 npx msw init 生成 worker 文件。
解法：初始化生成 mockServiceWorker.js 并正确托管。

坑 5：单测里 Worker 和 Server 混用
结论：Node 环境跑 setupWorker 报错。
原因：Node 无浏览器环境，需用 setupServer。
解法：浏览器用 setupWorker，Node/单测用 setupServer。
```

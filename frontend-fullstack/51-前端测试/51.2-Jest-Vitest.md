## 概述

Jest 是 Facebook 出品的 JavaScript 测试框架，一度是前端测试的事实标准；Vitest 是面向 Vite 生态的新一代测试框架，API 与 Jest 高度兼容，但启动更快、原生支持 ESM 和 Vite 配置。

```text
两者对比：
Jest —— 成熟稳定、生态最大、默认 CommonJS（ESM 支持需配置）
Vitest —— 快（基于 Vite 的 esbuild 转译）、ESM 原生、与 Vite 项目无缝集成

选型：
Vite 项目 → Vitest（零配置体验）
老项目 / 非 Vite → Jest（生态成熟）
```

```js
// 两者 API 几乎一致，测试写法互通
import { describe, it, expect } from 'vitest';  // Jest 则是全局或从 '@jest/globals' 导入

describe('sum', () => {
  it('两数相加', () => {
    expect(sum(1, 2)).toBe(3);
  });
});
```

```text
测试框架提供的核心能力：
1. Test —— 定义测试用例
2. Expect —— 断言
3. Mock/Spy/Stub —— 隔离依赖、验证调用
4. Snapshot —— 快照对比
5. Coverage —— 覆盖率统计
6. Fake Timer —— 控制时间
```

## Test

Test（用例）是测试的最小组织单位，用 `test`/`it` 定义，配合 `describe` 分组。生命周期钩子管理前置/清理。

```js
import { describe, test, it, expect, beforeAll, beforeEach, afterEach, afterAll } from 'vitest';

describe('用户服务', () => {
  let db;

  beforeAll(() => { db = connect(); });        // 整个套件执行一次
  beforeEach(() => { db.reset(); });            // 每个用例前执行
  afterEach(() => { db.cleanup(); });           // 每个用例后执行
  afterAll(() => { db.close(); });              // 套件结束后执行

  test('创建用户', () => {
    const user = db.create({ name: 'Alice' });
    expect(user.name).toBe('Alice');
  });

  it('it 是 test 的别名', () => {
    expect(1 + 1).toBe(2);
  });
});
```

```js
// 跳过和聚焦
test.skip('还没实现的用例', () => {});
test.todo('待办用例');

test.only('调试时只跑这一个', () => {
  expect(true).toBe(true);
});

// 参数化测试
test.each([
  [1, 1, 2],
  [1, 2, 3],
  [2, 2, 4],
])('%i + %i = %i', (a, b, expected) => {
  expect(a + b).toBe(expected);
});
```

```text
Test 的要点：
1. 用例名描述行为，读起来像一句话（"创建用户时生成唯一 ID"）
2. 每个用例独立，不依赖其他用例的状态
3. describe 可以嵌套，按模块/功能组织
```

## Expect

Expect 是断言入口，提供大量匹配器（matcher）判断实际值是否符合预期。选对匹配器能让断言更精确、失败信息更清晰。

```js
import { expect } from 'vitest';

// 相等性
expect(2 + 2).toBe(4);                    // 严格相等（===）
expect({ a: 1 }).toEqual({ a: 1 });        // 深度相等
expect({ a: 1 }).not.toBe({ a: 1 });       // 引用不等

// 真值
expect(null).toBeNull();
expect(undefined).toBeUndefined();
expect(0).toBeFalsy();
expect('x').toBeTruthy();

// 数字
expect(0.1 + 0.2).toBeCloseTo(0.3);        // 浮点比较
expect(5).toBeGreaterThan(3);
expect(5).toBeLessThanOrEqual(5);

// 字符串
expect('hello world').toMatch(/world/);
expect('hello').toContain('ell');

// 数组/对象
expect([1, 2, 3]).toContain(2);
expect({ name: 'Alice', age: 30 }).toMatchObject({ name: 'Alice' });

// 异常
expect(() => { throw new Error('boom'); }).toThrow('boom');
```

```js
// 异步断言
test('异步', async () => {
  await expect(fetchUser(1)).resolves.toEqual({ id: 1 });
  await expect(fetchUser(999)).rejects.toThrow('not found');
});
```

```text
匹配器选择建议：
toBe —— 基本类型严格相等
toEqual —— 对象/数组深度比较
toBeCloseTo —— 浮点数
toMatchObject —— 对象部分匹配（只关心部分字段时用，避免整对象断言脆弱）
```

## Mock、Spy 与 Stub

三者都是"测试替身"，隔离被测单元的外部依赖。Mock 整体替换，Spy 包装并记录调用，Stub 只替换返回值。

```text
概念区分：
Mock —— 整体替换整个模块/函数，自定义行为
Spy —— 包装真实实现，记录调用（调用次数、参数），可保留原行为
Stub —— 只关注"返回什么"，不关心调用细节

工程里三者常混用，核心能力：
1. 替换实现（隔离网络、数据库等外部依赖）
2. 记录调用（断言某个函数被调了几次、传了什么参数）
```

```js
// vi.fn() 创建 mock 函数
import { vi, expect } from 'vitest';

const mockFn = vi.fn();
mockFn.mockReturnValue(42);           // 固定返回值
mockFn.mockImplementation(x => x * 2); // 自定义实现

mockFn(5);
expect(mockFn).toHaveBeenCalled();        // 被调用过
expect(mockFn).toHaveBeenCalledWith(5);   // 以 5 调用过
expect(mockFn).toHaveBeenCalledTimes(1);  // 调用一次
expect(mockFn).toHaveReturnedWith(10);    // 返回 10
```

```js
// vi.spyOn —— spy 一个对象的方法，可保留原实现
const user = {
  getName() { return 'Alice'; },
  save() { /* 调 API */ }
};

const spy = vi.spyOn(user, 'getName');
user.getName();
expect(spy).toHaveBeenCalled();

// 替换实现
vi.spyOn(user, 'save').mockResolvedValue(true);
await user.save();
expect(user.save).toHaveBeenCalled();
```

```js
// vi.mock —— 整体 mock 一个模块（如 axios）
vi.mock('axios');

import axios from 'axios';
import { fetchUsers } from './users';

test('获取用户列表', async () => {
  axios.get.mockResolvedValue({ data: [{ id: 1, name: 'Alice' }] });
  const users = await fetchUsers();
  expect(users).toEqual([{ id: 1, name: 'Alice' }]);
});
```

```text
Mock 的使用原则：
1. 只 mock 外部边界（网络、存储、第三方），不 mock 被测代码本身
2. 过度 mock 会让测试测的是"mock"而非真实逻辑
3. spyOn 后记得 mockRestore，避免污染其他用例
```

## Snapshot

快照测试把输出序列化后存成文件，下次跑测试对比，输出变化时提示更新。适合测稳定的大对象、渲染结果。

```js
import { expect, test } from 'vitest';

test('配置对象快照', () => {
  const config = {
    theme: 'dark',
    locales: ['zh', 'en'],
    features: { beta: true, darkMode: true },
  };
  expect(config).toMatchSnapshot();
});
```

```jsx
// 组件渲染快照（React）
import { render } from '@testing-library/react';
import { Button } from './Button';

test('Button 快照', () => {
  const { container } = render(<Button variant="primary">确定</Button>);
  expect(container.firstChild).toMatchSnapshot();
});
```

```text
快照测试的注意点：
1. 快照太大（整个页面）等于没测，难以 review
2. 快照应小且聚焦（单个组件、稳定配置）
3. 更新快照要审慎（-u 全量更新会掩盖意外变化）
4. 输出含随机值/时间戳时先固定，否则每次都不一致
```

## Coverage

覆盖率统计测试覆盖了多少代码，帮定位"没测到的分支"，但覆盖率高不等于测试质量高。

```text
覆盖率维度：
语句（Statements）—— 执行到的语句比例
分支（Branches）—— if/else、switch 分支覆盖
函数（Functions）—— 调用到的函数比例
行（Lines）—— 执行到的行比例
```

```js
// vitest.config.js 开启覆盖率（需 @vitest/coverage-v8）
import { defineConfig } from 'vitest/config';

export default defineConfig({
  test: {
    coverage: {
      provider: 'v8',
      reporter: ['text', 'html'],
      include: ['src/**/*.js'],
      exclude: ['src/**/*.test.js'],
      thresholds: {
        lines: 80,        // 低于 80% 则失败
        functions: 80,
        branches: 70,
      },
    },
  },
});
```

```bash
# 命令行生成覆盖率
npx vitest run --coverage
```

```text
覆盖率的使用建议：
1. 设置阈值（如 80%）作为 CI 门禁，防止覆盖率滑坡
2. 关注"未覆盖的分支"而非只盯百分比
3. 覆盖率是下限不是目标——100% 覆盖也可能是无效测试
```

## Fake Timer

假定时器控制 setTimeout/setInterval/Date 等时间相关 API，让"依赖时间的逻辑"可以同步、确定地测试，不用真实等待。

```js
import { vi, test, expect } from 'vitest';

test('防抖函数', () => {
  vi.useFakeTimers();
  const fn = vi.fn();
  const debounced = debounce(fn, 1000);

  debounced();
  debounced();
  debounced();

  vi.advanceTimersByTime(1000);   // 快进 1000ms
  expect(fn).toHaveBeenCalledTimes(1);

  vi.useRealTimers();             // 恢复真实计时器
});
```

```js
// 控制 Date
test('指定当前时间', () => {
  vi.useFakeTimers();
  vi.setSystemTime(new Date('2026-08-13T00:00:00Z'));

  expect(new Date().toISOString()).toBe('2026-08-13T00:00:00.000Z');

  vi.useRealTimers();
});
```

```text
Fake Timer 的常用方法：
vi.useFakeTimers() —— 启用假定时器
vi.advanceTimersByTime(ms) —— 快进指定毫秒
vi.runAllTimers() —— 跑完所有定时器
vi.setSystemTime(date) —— 设置"当前时间"
vi.useRealTimers() —— 恢复真实定时器（别忘了恢复）
```

## 应用场景实战

### 场景一：测试带网络请求的模块

```js
// userService.js
import axios from 'axios';

export async function getUser(id) {
  const res = await axios.get(`/api/users/${id}`);
  return res.data;
}
```

```js
// userService.test.js —— mock axios 隔离网络
import { vi, describe, it, expect } from 'vitest';
import axios from 'axios';
import { getUser } from './userService';

vi.mock('axios');

describe('getUser', () => {
  it('返回用户数据', async () => {
    axios.get.mockResolvedValue({ data: { id: 1, name: 'Alice' } });
    await expect(getUser(1)).resolves.toEqual({ id: 1, name: 'Alice' });
    expect(axios.get).toHaveBeenCalledWith('/api/users/1');
  });

  it('接口报错时抛异常', async () => {
    axios.get.mockRejectedValue(new Error('网络错误'));
    await expect(getUser(1)).rejects.toThrow('网络错误');
  });
});
```

### 场景二：测试定时器驱动的轮询逻辑

```js
// poller.js —— 每隔 interval 调一次回调
export function startPolling(callback, interval) {
  const id = setInterval(callback, interval);
  return () => clearInterval(id);
}
```

```js
import { vi, test, expect } from 'vitest';
import { startPolling } from './poller';

test('轮询按固定间隔触发回调', () => {
  vi.useFakeTimers();
  const callback = vi.fn();
  const stop = startPolling(callback, 5000);

  vi.advanceTimersByTime(5000);
  expect(callback).toHaveBeenCalledTimes(1);

  vi.advanceTimersByTime(10000);
  expect(callback).toHaveBeenCalledTimes(3);

  stop();
  vi.advanceTimersByTime(5000);
  expect(callback).toHaveBeenCalledTimes(3);   // 停止后不再触发

  vi.useRealTimers();
});
```

## 最佳实践与踩坑记录

### 最佳实践

1. Vite 项目用 Vitest，享受零配置和高速启动
2. 只 mock 外部边界（网络、存储），不 mock 被测模块自身
3. 匹配器选 toEqual/toMatchObject 精确断言，避免整对象脆弱断言
4. spyOn 用 mockRestore/restoreAllMocks 清理，防止用例间污染
5. 快照保持小而聚焦，更新快照走 review 流程
6. 覆盖率设阈值接入 CI，但把它当底线而非目标

### 踩坑记录

```text
坑 1：mock 之后忘了恢复，污染后续用例
结论：后面的用例莫名失败，行为与预期不符。
原因：spyOn/mock 的替换状态跨用例残留。
解法：afterEach 里 vi.restoreAllMocks()，或每个用例局部 mock。

坑 2：浮点断言用 toBe 失败
结论：expect(0.1 + 0.2).toBe(0.3) 报错。
原因：浮点精度问题，0.1+0.2 实际是 0.30000000000000004。
解法：用 toBeCloseTo(0.3)。

坑 3：快照包含随机值/时间戳，每次都不一致
结论：快照测试永远失败，无法通过。
原因：输出里有随机 ID、当前时间等不稳定内容。
解法：mock 随机源、固定时间，或用 toMatchSnapshot({ id: expect.any(String) })。

坑 4：假定时器与真实定时器混用
结论：测试卡住或假定时器未恢复导致后续用例异常。
原因：useFakeTimers 后没 useRealTimers 恢复。
解法：afterEach 里恢复真实定时器，或用 vi.useFakeTimers 的作用域版本。

坑 5：覆盖率 100% 但没测到关键逻辑
结论：覆盖率好看，上线仍有 bug。
原因：测试只追求行覆盖，没覆盖边界和分支语义。
解法：关注分支覆盖和断言质量，别只盯百分比。
```

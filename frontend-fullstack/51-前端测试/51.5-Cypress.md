## 概述

Cypress 是面向开发者的前端测试框架，运行在浏览器内部，与测试代码同进程、同事件循环，因此可以实时调试、自动等待、直接控制网络。它同时支持 E2E 测试和组件测试，是 Playwright 之外的另一主流选择。

```text
Cypress 的核心特点：
1. 运行在浏览器内 —— 与页面同进程，可直接操作 DOM
2. 自动等待 —— 命令自动重试直到元素可交互
3. 时间旅行 —— 每一步操作都可回放查看
4. 网络控制 —— cy.intercept 拦截、Mock 请求
5. 双模式 —— E2E 测试 + 组件测试
```

```js
// 最小可运行示例
describe('首页', () => {
  it('显示欢迎语', () => {
    cy.visit('/');
    cy.contains('欢迎').should('be.visible');
  });
});
```

```text
Cypress 与 Playwright 的差异：
Cypress —— 单浏览器内核（Chromium 系），运行在浏览器内，命令链式（cy.xxx）
Playwright —— 多浏览器（Chromium/Firefox/WebKit），驱动外部浏览器，API 更对象化

选择建议：
已深度绑定 Chrome 生态、喜欢链式语法和组件测试一体化的团队选 Cypress；
需要多浏览器覆盖、并行性能更优的团队选 Playwright。
```

## Component Testing

Cypress 的组件测试让开发者直接在 Cypress 环境里挂载并测试单个组件，无需启动完整应用，速度接近单元测试，又保留真实浏览器 DOM 的交互能力。

```jsx
// Counter.cy.jsx —— 组件测试
import Counter from './Counter';

describe('Counter 组件', () => {
  it('点击按钮计数加一', () => {
    cy.mount(<Counter initial={0} />);
    cy.contains('0').should('be.visible');
    cy.get('button').click();
    cy.contains('1').should('be.visible');
  });

  it('支持自定义初始值', () => {
    cy.mount(<Counter initial={5} />);
    cy.contains('5').should('be.visible');
  });
});
```

```jsx
// 被测组件 Counter.jsx
import { useState } from 'react';

export default function Counter({ initial = 0 }) {
  const [count, setCount] = useState(initial);
  return (
    <div>
      <span data-cy="count">{count}</span>
      <button onClick={() => setCount(count + 1)}>增加</button>
    </div>
  );
}
```

```js
// cypress.config.js —— 配置组件测试
import { defineConfig } from 'cypress';

export default defineConfig({
  component: {
    devServer: {
      framework: 'react',
      bundler: 'vite',
    },
  },
  e2e: {
    baseUrl: 'http://localhost:5173',
  },
});
```

```text
组件测试的适用场景：
1. 交互密集的组件（表单、弹窗、下拉、滑块）
2. 状态机复杂的组件（多状态切换）
3. 需要真实 DOM 行为的组件（滚动、焦点、拖拽）

与 E2E 的分工：
组件测试 —— 单个组件的行为正确性（快、多）
E2E 测试 —— 完整用户流程的正确性（慢、少）
```

## E2E

E2E 测试驱动完整应用走真实用户路径。Cypress 的 E2E 通过 `cy.visit` 访问应用，用链式命令模拟用户操作并断言结果。

```js
describe('登录流程', () => {
  beforeEach(() => {
    cy.visit('/login');
  });

  it('用户成功登录', () => {
    cy.get('input[name="username"]').type('alice');
    cy.get('input[name="password"]').type('secret123');
    cy.get('button[type="submit"]').click();

    cy.url().should('include', '/dashboard');
    cy.contains('欢迎，alice').should('be.visible');
  });

  it('空用户名显示校验错误', () => {
    cy.get('button[type="submit"]').click();
    cy.contains('请输入用户名').should('be.visible');
  });
});
```

```text
Cypress 的链式命令机制：
每个 cy.xxx 命令都是异步的，加入命令队列按序执行。
.should() 会不断重试，直到断言通过或超时（默认 4 秒）。

常用命令：
1. 导航 —— cy.visit / cy.go / cy.reload
2. 查询 —— cy.get / cy.contains / cy.find
3. 交互 —— cy.click / cy.type / cy.select / cy.check
4. 断言 —— cy.should / cy.expect（.should 链式风格）
5. 其他 —— cy.url / cy.title / cy.wrap
```

```js
// 自定义命令复用公共逻辑
// cypress/support/commands.js
Cypress.Commands.add('login', (username, password) => {
  cy.visit('/login');
  cy.get('input[name="username"]').type(username);
  cy.get('input[name="password"]').type(password);
  cy.get('button[type="submit"]').click();
});

// 测试中使用
it('登录后查看订单', () => {
  cy.login('alice', 'secret123');
  cy.contains('我的订单').click();
  cy.get('.order-item').should('have.length', 3);
});
```

## Intercept

`cy.intercept` 拦截网络请求，可以断言请求、修改响应、Mock 数据、模拟错误，是 Cypress 隔离后端和控制测试场景的核心手段。

```js
describe('网络拦截', () => {
  it('Mock 接口响应', () => {
    cy.intercept('GET', '/api/users', {
      statusCode: 200,
      body: [{ id: 1, name: 'Alice' }],
    }).as('getUsers');

    cy.visit('/');
    cy.wait('@getUsers');
    cy.contains('Alice').should('be.visible');
  });

  it('模拟接口报错', () => {
    cy.intercept('POST', '/api/order', {
      statusCode: 500,
      body: { message: '服务器错误' },
    }).as('createOrder');

    cy.get('button').contains('提交').click();
    cy.wait('@createOrder');
    cy.contains('服务器错误').should('be.visible');
  });
});
```

```js
// 断言真实请求的参数
cy.intercept('POST', '/api/login').as('login');
cy.get('button').click();
cy.wait('@login').its('request.body').should('deep.equal', {
  username: 'alice',
  password: 'secret123',
});

// 修改真实响应
cy.intercept('GET', '/api/orders', (req) => {
  req.reply((res) => {
    res.body.push({ id: 999, total: 0 });
  });
});

// 延迟响应模拟慢接口
cy.intercept('GET', '/api/search', (req) => {
  req.reply((res) => {
    setTimeout(() => res.send(res.body), 3000);
  });
});
```

```text
cy.intercept 的用法：
1. 匹配 —— 方法 + URL 或 RouteMatcher 对象
2. 响应 —— 直接返回静态响应，或用回调动态构造
3. 别名 —— .as('name') 配合 cy.wait('@name') 等待

RouteMatcher 支持：
path、url、method、query、headers、body 等精确或通配匹配。
```

## Fixture

Fixture 是把 Mock 数据抽离到 JSON 文件，测试里通过 `cy.fixture` 读取，避免把大段测试数据写在测试代码里，也让数据可复用、可维护。

```json
// cypress/fixtures/users.json
{
  "admin": { "id": 1, "name": "Alice", "role": "admin" },
  "guest": { "id": 2, "name": "Bob", "role": "guest" }
}
```

```json
// cypress/fixtures/orders.json
{
  "list": [
    { "id": 1, "product": "MacBook", "total": 9999 },
    { "id": 2, "product": "iPhone", "total": 6999 }
  ]
}
```

```js
describe('使用 Fixture', () => {
  it('用 fixture 数据 Mock 接口', () => {
    cy.fixture('orders').then((orders) => {
      cy.intercept('GET', '/api/orders', orders).as('orders');
    });

    cy.visit('/orders');
    cy.wait('@orders');
    cy.get('.order-item').should('have.length', 2);
  });

  it('fixture 直接用于表单填充', () => {
    cy.fixture('users').then((users) => {
      cy.get('input[name="name"]').type(users.admin.name);
    });
  });
});
```

```js
// 简化写法：拦截时直接引用 fixture 路径
cy.intercept('GET', '/api/users', { fixture: 'users.json' }).as('users');
```

```text
Fixture 的实践要点：
1. 目录 —— 默认在 cypress/fixtures/ 下
2. 格式 —— 常用 JSON，也支持其他格式
3. 读取 —— cy.fixture('文件名')，返回 Promise
4. 价值 —— 数据与测试解耦，多人复用同一套测试数据

适合用 fixture 的数据：
用户信息、商品列表、订单、下拉选项等结构稳定的 Mock 数据。
```

## 应用场景实战

### 场景一：用组件测试覆盖复杂交互组件

```jsx
// Dropdown.cy.jsx —— 下拉组件交互测试
import Dropdown from './Dropdown';

describe('Dropdown 组件', () => {
  const options = ['选项一', '选项二', '选项三'];

  it('点击展开选项列表', () => {
    cy.mount(<Dropdown options={options} />);
    cy.get('[data-cy="trigger"]').click();
    cy.get('[data-cy="option"]').should('have.length', 3);
  });

  it('选择后显示选中值并收起', () => {
    cy.mount(<Dropdown options={options} />);
    cy.get('[data-cy="trigger"]').click();
    cy.contains('选项二').click();
    cy.get('[data-cy="trigger"]').should('contain', '选项二');
    cy.get('[data-cy="option"]').should('not.exist');
  });
});
```

### 场景二：完整购物流程 E2E + 网络隔离

```js
describe('购物流程', () => {
  beforeEach(() => {
    // 统一 Mock 后端
    cy.intercept('GET', '/api/products', { fixture: 'products.json' }).as('products');
    cy.intercept('POST', '/api/orders', { statusCode: 201, body: { id: 1 } }).as('order');
    cy.visit('/');
  });

  it('添加商品到购物车并下单', () => {
    cy.wait('@products');
    cy.get('.product-card').first().find('button').click();
    cy.get('.cart-badge').should('contain', '1');
    cy.get('button').contains('结算').click();
    cy.get('button').contains('提交订单').click();
    cy.wait('@order').its('response.statusCode').should('eq', 201);
    cy.contains('下单成功').should('be.visible');
  });
});
```

## 最佳实践与踩坑记录

### 最佳实践

1. 用 data-cy / data-testid 选择器定位，避免脆弱的结构选择器
2. 用 cy.intercept + fixture 隔离后端，让测试稳定可控
3. 公共操作抽成自定义命令，避免测试代码重复
4. 组件测试覆盖交互组件，E2E 只覆盖黄金路径
5. 善用别名（.as + cy.wait），确保网络请求完成再断言
6. 断言用 should 自动重试，不依赖固定等待 cy.wait(ms)

### 踩坑记录

```text
坑 1：cy.wait(固定毫秒) 导致测试不稳定
结论：偶发失败，慢环境下必挂。
原因：固定等待时间无法匹配真实加载耗时。
解法：用 cy.wait('@alias') 等请求，或用 should 自动重试。

坑 2：结构选择器脆弱
结论：页面 DOM 一改，测试全红。
原因：依赖 .container > div > span 这类层级选择器。
解法：加 data-cy 测试专用属性，或用语义化选择器。

坑 3：测试间状态串扰
结论：用例依赖执行顺序。
原因：测试间共享了 localStorage、Cookie 或后端数据。
解法：beforeEach 清理状态，每个测试独立造数据。

坑 4：忘 wait 网络请求
结论：请求还没返回就断言，偶发失败。
原因：发起请求后没等响应就查结果。
解法：cy.intercept 加 .as 别名，配合 cy.wait 等待。

坑 5：组件测试与 E2E 配置混淆
结论：组件测试跑成了 E2E 或反之。
原因：cypress.config.js 里 component 与 e2e 配置未区分。
解法：分别配置 component.devServer 和 e2e.baseUrl。
```

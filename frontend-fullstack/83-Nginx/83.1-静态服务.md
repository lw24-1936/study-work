## 概述

Nginx 静态服务是指用 Nginx 直接把磁盘上的静态文件（HTML/JS/CSS/图片）返回给客户端，是前端部署最基础的形态。它用 root 指定文件根目录、location 匹配请求路径、index 指定默认文档、try_files 做查找回退，四条指令组合起来就能托管一个完整的前端站点。

```text
静态服务的四条核心指令：
1. root —— 指定静态文件的根目录
2. location —— 按路径匹配请求，分发到不同处理逻辑
3. index —— 指定目录请求时默认返回的文件
4. try_files —— 按顺序查找文件，找不到时回退
```

```nginx
# 最小静态服务配置
server {
    listen 80;
    server_name example.com;
    root /var/www/html;
    index index.html;
}
```

## root

root 指令指定静态文件的根目录，Nginx 会把请求的 URI 拼接到 root 后面去查找文件。例如 root 是 /var/www/html，请求 /assets/app.js 就映射到 /var/www/html/assets/app.js。root 可以配置在 http、server、location 多个层级，继承关系是「内层覆盖外层」。

```nginx
server {
    listen 80;
    # 站点根目录，所有 location 默认继承
    root /var/www/html;

    # 图片单独指向另一个目录
    location /images/ {
        root /var/www/static;
        # 此时 /images/a.png 映射到 /var/www/static/images/a.png
    }
}
```

```text
root 的要点：
1. 拼接规则 —— 实际路径 = root 值 + 请求 URI
2. 作用域 —— 可配置在 http/server/location，内层覆盖外层
3. 常见坑 —— root 与 location 里的路径会拼接，容易写重
4. 与 alias 的区别 —— alias 是替换前缀，root 是拼接完整路径
```

## location

location 指令按请求 URI 匹配规则，把请求分发到不同的处理逻辑。匹配有优先级：精确匹配 `=`、前缀匹配 `^~`、正则匹配 `~` / `~*`，以及普通前缀匹配，最长匹配优先。它让同一个 server 可以为静态文件、代理、缓存等不同场景配置不同行为。

```nginx
server {
    # 精确匹配：只处理这个路径
    location = /healthz {
        return 200 "ok";
    }

    # 前缀匹配，优先级高于正则
    location ^~ /assets/ {
        expires 1y;
        add_header Cache-Control "public, immutable";
    }

    # 正则匹配，不区分大小写
    location ~* \.(css|js|png|jpg)$ {
        expires 7d;
    }

    # 兜底匹配
    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

```text
location 匹配优先级（从高到低）：
1. 精确匹配 = —— 命中即止
2. 前缀匹配 ^~ —— 命中即止，不再看正则
3. 正则匹配 ~ / ~* —— 按书写顺序，先命中先胜
4. 普通前缀匹配 —— 取最长前缀
5. 兜底 / —— 都没有命中时
```

## index

index 指令指定「请求一个目录」时默认返回的文件。比如请求 / 时，Nginx 会依次查找 index.html、index.htm，返回第一个存在的。它是「目录请求」的默认文档规则，配合 root 决定首页和目录导航的返回内容。

```nginx
server {
    root /var/www/html;
    # 请求目录时依次查找这些文件
    index index.html index.htm;
}
```

```text
index 的行为：
1. 目录请求 —— 请求 / 或 /docs/ 时触发 index 查找
2. 顺序查找 —— 按声明顺序找第一个存在的文件
3. 内部重定向 —— 命中 index.html 后内部跳转，URI 不变
4. 常配合 —— 与 root 组合决定站点首页
```

## try_files

try_files 是前端静态服务最重要的指令：按顺序尝试多个文件或路径，全部不存在时执行最后的回退动作（通常是返回 index.html 或跳转 404）。它是 SPA history 路由的基础——未知路径统一回退到 index.html，交给前端路由处理。

```nginx
server {
    root /var/www/html;
    index index.html;

    location / {
        # 先找文件，再找目录，最后回退到 index.html
        try_files $uri $uri/ /index.html;
    }
}
```

```text
try_files 的执行逻辑：
1. $uri —— 按请求路径找文件，命中直接返回
2. $uri/ —— 找对应目录，命中则触发 index
3. /index.html —— 都没命中，回退到 index.html（SPA 关键）
4. =404 —— 也可以回退到 404 状态码
```

```text
try_files 的常见变体：
1. try_files $uri $uri/ /index.html; —— SPA 回退
2. try_files $uri $uri/ =404; —— 严格模式，找不到就 404
3. try_files $uri @backend; —— 回退到命名 location（代理）
```

## 应用场景实战

### 场景一：托管一个多页静态站点

```nginx
# 静态站点 + 图片长缓存 + 健康检查
server {
    listen 80;
    server_name docs.example.com;
    root /var/www/docs;
    index index.html;

    # 静态资源长缓存
    location ~* \.(css|js|png|jpg|svg|woff2)$ {
        expires 1y;
        add_header Cache-Control "public, immutable";
    }

    # 目录请求默认文档
    location / {
        try_files $uri $uri/ =404;
    }

    # 健康检查
    location = /healthz {
        return 200 "ok";
    }
}
```

### 场景二：静态文件 + API 反代共存的站点

```nginx
server {
    listen 80;
    server_name app.example.com;
    root /var/www/app;
    index index.html;

    # 前端页面，SPA 回退
    location / {
        try_files $uri $uri/ /index.html;
    }

    # API 请求转发到后端
    location /api/ {
        proxy_pass http://backend:3000;
    }
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. 带 hash 的静态资源设 immutable 长缓存，减少重复请求
2. 用 try_files 处理 SPA 回退，未知路径统一到 index.html
3. 静态服务和反向代理分 location 配置，路径清晰职责单一
4. 预留 /healthz 健康检查端点，方便 K8s 就绪探测
5. location 匹配用精确或 ^~ 前缀，避免正则误伤和性能损耗

### 踩坑记录

```text
坑 1：root 路径写重导致文件找不到
结论：请求 404，日志显示路径被拼接成了重复的目录。
原因：location 里的路径和 root 拼接，例如 root /var/www/html 配 location /html/。
解法：理解 root 是「拼接完整 URI」，用 alias 或调整目录结构，测试用 curl -I 验证。

坑 2：SPA 刷新子路由直接 404
结论：刷新 /about 页面时 Nginx 按文件查找，找不到就 404。
原因：没有 try_files 回退到 index.html，前端路由没有机会接管。
解法：location / 加 try_files $uri $uri/ /index.html;。

坑 3：location 正则匹配优先级搞反
结论：配置了精确规则却不生效，被正则或前缀规则抢走。
原因：不熟悉 location 匹配优先级，规则顺序混乱。
解法：牢记优先级：= > ^~ > 正则 > 普通前缀，精确规则用 = 或 ^~。

坑 4：index 配置了但首页还是 404
结论：访问 / 返回 404，但 index.html 明明存在。
原因：root 指向的目录不对，或 index 文件不叫 index.html。
解法：核对 root 实际路径，确认 index 文件名与配置一致。

坑 5：try_files 回退写成目录导致循环
结论：请求陷入内部重定向循环，最终 500。
原因：try_files 最后回退到目录而非文件，目录又触发 index，可能循环。
解法：回退目标用明确文件（/index.html）或命名 location（@backend）或 =404。
```

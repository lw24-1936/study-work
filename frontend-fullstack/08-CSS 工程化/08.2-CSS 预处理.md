## 概述

CSS 预处理器的目标：给原生 CSS 补充**变量、嵌套、复用、运算**等编程能力，编译后输出标准 CSS。原生 CSS 已逐步支持变量和部分函数，但预处理器的 mixin、函数、嵌套仍是工程化开发的重要工具。

```text
预处理器的价值：
1. 变量复用 —— 颜色、间距统一定义，一处改处处改
2. 嵌套 —— 结构直观，避免重复写父选择器
3. 复用 —— mixin / extend 消除重复样式块
4. 逻辑 —— 条件、循环、函数让样式具备计算能力

三大预处理器：
Sass  —— 功能最全，生态最广（.scss 语法）
Less  —— 早期流行，可运行在浏览器端
Stylus —— 语法极简（省略括号分号），现较少见
```

## Sass 与 SCSS

Sass 有两种语法：缩进语法（`.sass`，无括号分号）和 SCSS（`.scss`，兼容 CSS 语法）。现代项目几乎都用 SCSS。

```text
Sass vs SCSS：
.sass —— 靠缩进，省略 {} 和 ;
.scss —— 完全兼容 CSS 语法，可渐进迁移

.scss 是事实标准，新项目默认 .scss。
```

```scss
// .scss 语法
$primary: #0066cc;

.button {
  background: $primary;
  &:hover { background: darken($primary, 10%); }
}
```

```text
Sass 编译：
1. dart-sass —— 官方推荐，纯 Dart 实现，性能好
2. node-sass —— 已废弃，依赖 libsass C++ 库

命令：sass input.scss output.css
```

## Less

Less 语法与 SCSS 类似，用 `@` 声明变量，早期因可运行在浏览器（less.js）而流行，现已基本被 Sass 取代，但在部分旧项目与 UI 库（Ant Design 早期）中仍可见。

```less
@primary: #0066cc;

.button {
  background: @primary;
  &:hover { background: darken(@primary, 10%); }
}
```

```text
Less vs Sass：
变量符号 —— Less 用 @，Sass 用 $
功能 —— Sass 的函数、模块、循环更丰富
生态 —— Sass 更主流，Less 存量项目较多

选择建议：新项目统一 Sass，维护旧项目遵循既有约定。
```

## Variables 变量

变量是预处理最基础的能力，支持类型、运算、作用域，可减少硬编码。

```scss
// 声明与使用
$primary: #0066cc;
$spacing: 16px;
$font-stack: 'Helvetica', sans-serif;

.card {
  color: $primary;
  padding: $spacing * 2;   // 运算
  font-family: $font-stack;
}
```

```scss
// 作用域：局部变量优先，!global 强制全局
$color: red;

.box {
  $color: blue;          // 局部变量
  color: $color;         // blue
}

.other {
  color: $color;         // red（外部不受影响）
}
```

```text
Sass 变量 vs CSS 变量：
Sass 变量 —— 编译期替换，构建后消失，不能运行时改
CSS 变量 —— 运行时存在，可继承、可被 JS 操作、可动态切换

现代实践：主题/动态值用 CSS 变量，编译期常量（断点、z-index 序列）可用 Sass 变量。
```

## Nesting 嵌套

嵌套让选择器结构与 HTML 结构对应，配合 `&` 引用父选择器。

```scss
.card {
  padding: 16px;

  .title {                 // 后代选择器 .card .title
    font-size: 18px;
  }

  &:hover {                // & 引用父选择器 .card:hover
    border-color: #0066cc;
  }

  &--primary {             // .card--primary
    background: #0066cc;
  }
}
```

```text
嵌套注意事项：
1. 避免过深 —— 嵌套超过 3 层会增加特异性、难维护
2. & 的妙用 —— & 可组合 BEM 命名（&--modifier、&__element）
3. 属性嵌套 —— 部分属性也支持嵌套（font: { size: 16px; weight: 600; }）
```

## Mixins 混入

Mixin 是可复用的样式块，支持参数与默认值，是预处理器的核心复用能力。

```scss
// 基础 mixin
@mixin flex-center {
  display: flex;
  align-items: center;
  justify-content: center;
}

// 带参数的 mixin
@mixin rounded($radius: 8px) {
  border-radius: $radius;
}

// 使用 @include 引入
.modal {
  @include flex-center;
  @include rounded(12px);
}
```

```scss
// 可变参数与内容块
@mixin media($breakpoint) {
  @media (min-width: $breakpoint) { @content; }
}

.container {
  padding: 16px;

  @include media(768px) {
    padding: 24px;
  }
}
```

```text
Mixin vs Extend：
Mixin —— 每次 @include 都复制一份样式，灵活（可传参），但会增大产物
Extend —— 复用选择器（群组化），产物更小，但不能传参、跨媒体查询受限

一般优先用 Mixin，Extend 仅在确定无副作用时使用。
```

## Functions 函数

Sass 提供内置函数（颜色、数值、字符串、列表、Map），也支持自定义 `@function`。

```scss
// 内置函数
$base: #0066cc;

.btn {
  background: $base;
  color: lighten($base, 40%);   // 变亮
  border: 1px solid darken($base, 10%); // 变暗
}

// 自定义函数
@function spacing($n) {
  @return $n * 8px;
}

.card {
  padding: spacing(2);   // 16px
  margin: spacing(3);    // 24px
}
```

```text
常用内置函数分类：
颜色 —— lighten / darken / rgba / mix / adjust-hue
数值 —— abs / min / max / round / ceil / floor
字符串 —— str-length / str-index / to-upper-case
列表/Map —— length / nth / map-get / map-merge

注意：Sass 函数是编译期的，无法访问运行时值。
```

## Extend 继承

`@extend` 让一个选择器继承另一个选择器的全部样式，编译时通过选择器群组实现复用。

```scss
.message {
  padding: 8px 12px;
  border: 1px solid #ccc;
}

.message-error {
  @extend .message;      // 继承 .message 全部样式
  border-color: #cc3300;
  color: #cc3300;
}
```

```css
/* 编译结果：选择器被合并 */
.message, .message-error {
  padding: 8px 12px;
  border: 1px solid #ccc;
}
.message-error {
  border-color: #cc3300;
  color: #cc3300;
}
```

```text
Extend 的陷阱：
1. 不能跨媒体查询 —— @media 内的类不能被外部 extend
2. 选择器顺序敏感 —— 继承链会影响生成顺序
3. 过度使用难追踪 —— 群组选择器让来源不直观

结论：能用 Mixin 就不建议 Extend，除非明确需要减小产物体积。
```

## 应用场景实战

### 场景一：主题系统 —— Sass 变量 + CSS 变量

```scss
// 编译期常量用 Sass 变量
$breakpoints: (sm: 640px, md: 768px, lg: 1024px);

// 运行时主题用 CSS 变量
:root {
  --color-primary: #0066cc;
}

.theme-dark {
  --color-primary: #3399ff;
}
```

### 场景二：响应式工具 —— 媒体查询 mixin

```scss
@mixin respond($size) {
  @if $size == md {
    @media (min-width: 768px) { @content; }
  }
}

.grid {
  grid-template-columns: 1fr;
  @include respond(md) {
    grid-template-columns: repeat(3, 1fr);
  }
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. 新项目统一 SCSS，避免多种预处理器混用
2. 变量分层：编译期常量用 Sass 变量，运行时主题用 CSS 变量
3. 用 mixin 封装高频模式（flex 居中、媒体查询、文本截断）
4. 嵌套不超过 3 层，BEM 命名配合 `&` 书写
5. 抽离 `variables.scss`、`mixins.scss`、`functions.scss` 分层管理

### 踩坑记录

```text
坑 1：变量名用 @ 与 $ 混淆
结论：Less 项目里写了 $primary，编译报错。
原因：Less 用 @，Sass 用 $，语法不通用。
解法：确认项目预处理器，统一变量前缀。

坑 2：嵌套过深导致特异性爆炸
结论：.a .b .c .d 写法难以覆盖。
原因：嵌套顺手越写越深，没有约束。
解法：嵌套 ≤3 层，配合 lint 规则 max-nesting-depth。

坑 3：Sass 变量当 CSS 变量用
结论：想用 JS 动态改颜色，发现 Sass 变量改不了。
原因：Sass 变量编译期就被替换，运行时不存在。
解法：需要运行时改的值用 CSS 变量（--name）。

坑 4：Extend 跨媒体查询失效
结论：@media 内 extend 外部类不生效。
原因：Extend 不能跨 @media 作用域。
解法：媒体查询内用 mixin 或重复写，不用 extend。

坑 5：darken/lighten 结果不符合预期
结论：颜色变亮变暗效果怪。
原因：darken/lighten 在 HSL 空间调整，视觉感知非线性。
解法：现代推荐 color.scale() 或 CSS 的 color-mix() 调整明度。
```

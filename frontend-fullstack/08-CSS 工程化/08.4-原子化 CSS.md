## 概述

原子化 CSS（Atomic CSS）把样式拆成**单一职责的原子类**，每个类只表达一个样式属性，在 HTML 中通过组合类名完成布局与外观。与 BEM 等「语义化组件类」相反，它追求「样式即类名、所见即所得」。

```text
原子化 CSS 的核心思想：
1. 一个类对应一个（或极少数）CSS 声明
2. 类名直接表达视觉结果（p-4 = padding: 1rem）
3. 样式复用靠「组合类」，而非「写新类」
4. 与 Design Token 强绑定，保证设计一致性

对比传统方案：
传统（BEM）—— 写语义类 .card__title，样式在 CSS 文件里
原子化 —— 写工具类 text-lg font-bold，样式由工具按需生成
```

## Utility Class 工具类

工具类是原子化 CSS 的最小单位，命名遵循「属性缩写 + 值」的约定。

```text
常见工具类命名约定（Tailwind 风格）：
布局 —— flex、grid、block、inline-flex
间距 —— p-4、px-2、m-8、mt-1（padding/margin + 尺寸档位）
尺寸 —— w-full、h-16、max-w-md
颜色 —— bg-blue-600、text-white、border-gray-200
排版 —— text-lg、font-semibold、leading-relaxed
圆角/阴影 —— rounded-lg、shadow-sm
状态 —— hover:bg-blue-700、focus:ring、disabled:opacity-50
```

```html
<div class="p-4 bg-white rounded-lg shadow-sm hover:shadow-md">
  <h2 class="text-lg font-semibold text-gray-900">标题</h2>
  <p class="mt-2 text-sm text-gray-600">描述</p>
</div>
```

```text
工具类的优势：
1. 所见即所得 —— 看 HTML 就知道长什么样
2. 无需命名 —— 不用绞尽脑汁起语义类名
3. 强一致性 —— 全部来自 Design Token，不会出现随意值
4. 高度复用 —— 相同样式就是相同类，产物可去重
```

## Tailwind CSS

Tailwind 是最主流的原子化 CSS 框架，提供完整的预设工具类 + 配置驱动的 Design Token + JIT 按需生成。

```text
Tailwind 核心概念：
1. 配置驱动 —— tailwind.config.js 定义主题（颜色、间距、断点）
2. JIT 引擎 —— 扫描源码，只生成用到的类，产物极小
3. 响应式 —— 前缀 sm: md: lg: 实现断点样式
4. 状态变体 —— hover: focus: dark: 等前缀
5. 插件系统 —— 官方与社区插件扩展
```

```js
// tailwind.config.js
export default {
  content: ['./src/**/*.{js,ts,jsx,tsx}'],
  theme: {
    extend: {
      colors: {
        primary: '#0066cc',
      },
    },
  },
};
```

```html
<!-- 使用自定义主题 + 响应式 + 状态 -->
<button class="bg-primary text-white px-4 py-2 rounded
               hover:bg-blue-700 md:px-6">
  提交
</button>
```

```text
Tailwind 处理流程：
1. 构建时扫描 content 配置的文件
2. 提取所有出现的类名
3. 按主题配置生成对应 CSS
4. 未使用的类不生成（Tree Shaking）

优势：开发快、一致性强、产物可控
代价：HTML 类名长、需学习类名映射
```

## UnoCSS

UnoCSS 是新一代原子化引擎，定位「更快、更灵活」的 Tailwind 替代方案，支持即时按需生成与多种 preset。

```text
UnoCSS 特点：
1. 极致性能 —— 无解析开销，按需生成比 Tailwind JIT 更快
2. Preset 机制 —— 兼容 Tailwind/Windi 的 preset，可自定义
3. 属性化模式 —— 可写 class="text-red" 或属性 w-4=""
4. 图标集成 —— 内置 Icon preset，类名即图标
5. 灵活的匹配器 —— 用正则自定义规则
```

```js
// uno.config.ts
import { defineConfig, presetUno, presetIcons } from 'unocss';

export default defineConfig({
  presets: [
    presetUno(),      // 兼容 Tailwind 语义
    presetIcons(),    // 图标支持
  ],
});
```

```html
<!-- 属性化写法 -->
<div m="4" p="x-2 y-1" flex items-center>
  <i i-carbon-user />
</div>
```

## Windi CSS

Windi CSS 是 UnoCSS 的前身，同样是按需生成的原子化引擎，现已停止维护，其作者转向 UnoCSS，社区建议迁移到 UnoCSS。

```text
Windi CSS 现状：
1. 已不再积极维护（作者转入 UnoCSS）
2. 设计思想被 UnoCSS 继承并增强
3. 存量项目可平滑迁移到 UnoCSS（语法兼容）

选型建议：新项目直接在 Tailwind 或 UnoCSS 之间选择。
```

```text
Tailwind vs UnoCSS：
性能 —— UnoCSS 更快（零解析、即时生成）
生态 —— Tailwind 更成熟（组件库、插件、教程）
灵活性 —— UnoCSS 更灵活（属性模式、自定义规则）
团队 —— Tailwind 更保守稳妥，UnoCSS 适合追求极致的场景
```

## Design Token 设计令牌

原子化 CSS 的一致性，本质依赖 Design Token——把颜色、间距、字号等设计决策固化成命名变量，工具类从令牌生成。

```text
Design Token 分层：
1. 原始值（Primitive） —— blue-500 = #0066cc、space-4 = 16px
2. 语义值（Semantic） —— color-primary = blue-500、bg-surface
3. 组件值（Component） —— button-bg = color-primary

原子化框架的 theme 配置即「原始值层」，语义层通过别名映射。
```

```js
// 语义化令牌映射到原子类
theme: {
  colors: {
    primary: '#0066cc',
    danger: '#cc3300',
    surface: '#ffffff',
  },
  spacing: {
    sm: '8px',
    md: '16px',
    lg: '24px',
  },
},
```

```html
<!-- 原子类即令牌的载体 -->
<button class="bg-primary text-white px-md py-sm rounded">
  提交
</button>
```

```text
Design Token 的价值：
1. 一致 —— 全站只有一套颜色/间距，杜绝「10 种相近蓝」
2. 可主题化 —— 改令牌即换肤，深色模式/多品牌轻松切换
3. 可维护 —— 设计变更只改令牌，工具类自动跟随
```

## 应用场景实战

### 场景一：快速搭建营销页

```html
<section class="bg-gray-50 py-20">
  <div class="max-w-4xl mx-auto text-center">
    <h1 class="text-4xl font-bold text-gray-900">产品标题</h1>
    <p class="mt-4 text-lg text-gray-600">产品描述</p>
  </div>
</section>
```

### 场景二：自定义令牌 + 深色模式

```js
theme: {
  colors: { primary: '#0066cc' },
},
```

```html
<button class="bg-primary dark:bg-blue-400 text-white">
  深色模式自动切换
</button>
```

## 最佳实践与踩坑记录

### 最佳实践

1. 原子类必须基于 Design Token，禁止任意值（或用括号约束）
2. 重复出现的类组合抽取为组件，避免多处复制长类名
3. 用 @apply 或组件抽象封装高频模式，控制 HTML 复杂度
4. 响应式遵循「移动优先」，先写基础类再加 md:/lg: 前缀
5. 团队统一框架（Tailwind 或 UnoCSS），不混用

### 踩坑记录

```text
坑 1：动态拼接类名导致样式丢失
结论：bg-${color}-500 这样拼接，样式没生成。
原因：JIT 扫描源码按字面量提取，拼接出的完整类名扫描不到。
解法：写全类名或用 safelist，或用映射表返回完整类名。

坑 2：任意值滥用破坏一致性
结论：项目出现大量 w-[137px] 这样的魔法值。
原因：为图省事绕过令牌直接写任意值。
解法：优先用令牌，确实需要才用任意值并 review 收敛。

坑 3：类名过长影响可读性
结论：一个 div 挂 15 个类，HTML 难读。
原因：所有样式都堆在类里，没有组件抽象。
解法：高频组合抽成组件，或用 @apply 封装。

坑 4：忽略 content 配置导致样式缺失
结论：新目录下的类没有生成。
原因：content 扫描路径没包含新目录。
解法：确保 content 覆盖所有模板文件路径。

坑 5：未理解响应式前缀方向
结论：lg:flex 以为是「大屏以下生效」，实际相反。
原因：响应式前缀是 min-width，表示「该断点及以上」。
解法：牢记移动优先，sm:/md:/lg: 都是「不小于该断点」时生效。
```

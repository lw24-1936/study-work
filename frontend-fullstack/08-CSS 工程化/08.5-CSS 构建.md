## 概述

CSS 构建是前端工程化的一环：把源码中的样式（原生 CSS、SCSS、CSS-in-JS、原子类）经过**转换、兼容、压缩、优化**，产出最终上线的 CSS 产物。目标是体积小、兼容好、加载快。

```text
CSS 构建流程：
源码样式（.scss/.css/.css.ts/原子类）
   → 编译（Sass/Less/CSS-in-JS 提取）
   → PostCSS 处理（前缀、未来语法降级、模块化）
   → 优化（Tree Shaking、去重）
   → 压缩（Minify）
   → 产物（.css 文件，可含 Code Splitting 分包）
```

## PostCSS 处理管线

PostCSS 是 CSS 的「Babel」——一个基于插件的转换管线，自身不做事，靠插件实现各种能力。

```text
PostCSS 原理：
1. 解析 CSS 为 AST（抽象语法树）
2. 插件遍历 AST 做转换
3. 重新生成 CSS 文本

核心价值：统一的插件生态，绝大多数 CSS 工具都以 PostCSS 插件形式存在。
```

```js
// postcss.config.js
module.exports = {
  plugins: {
    'autoprefixer': {},        // 自动加前缀
    'postcss-preset-env': {},  // 未来语法降级（含 nesting、custom media 等）
    'postcss-nested': {},      // 嵌套语法展开
  },
};
```

```text
PostCSS 与 Sass 的分工：
Sass —— 编译期：变量、mixin、嵌套、函数等「增强语法」
PostCSS —— 后处理：前缀、降级、压缩等「兼容与优化」

二者可组合：.scss 先由 Sass 编译成 .css，再交给 PostCSS 处理。
```

## Autoprefixer 前缀自动补全

Autoprefixer 是最常用的 PostCSS 插件，根据 browserslist 配置，自动为 CSS 属性添加浏览器厂商前缀。

```text
Autoprefixer 机制：
1. 读取 browserslist 配置（目标浏览器范围）
2. 结合 caniuse 数据判断哪些属性需要前缀
3. 自动添加 -webkit- / -moz- / -ms- 等前缀
4. 移除已不需要的前缀（浏览器已支持时）
```

```css
/* 输入 */
.user-select-none {
  user-select: none;
}

/* 输出（按 browserslist 决定前缀范围） */
.user-select-none {
  -webkit-user-select: none;
  -moz-user-select: none;
  -ms-user-select: none;
  user-select: none;
}
```

```json
// package.json 中的 browserslist
{
  "browserslist": [
    "> 0.5%",
    "last 2 versions",
    "not dead"
  ]
}
```

```text
Autoprefixer 的价值：
1. 写标准语法，前缀交给工具
2. 精确 —— 只加目标浏览器需要的，不多加
3. 反向清理 —— 旧前缀自动移除
```

## CSS Minify 压缩

CSS Minify 移除空格、注释、冗余符号，压缩产物体积。常用 cssnano（PostCSS 插件）或构建工具内置压缩器。

```text
cssnano 的压缩策略：
1. 移除空格、换行、注释
2. 合并相同声明（margin: 0 0 0 0 → margin: 0）
3. 简化颜色值（#ffffff → #fff）
4. 缩短 0 值（0px → 0）
5. 移除冗余单位与默认值
6. 重排序声明以提升 gzip 压缩率
```

```css
/* 压缩前 */
.card {
  padding: 0px 0px 0px 0px;
  background: #ffffff;
  /* 注释 */
  margin: 0;
}

/* 压缩后 */
.card{padding:0;background:#fff;margin:0}
```

```text
压缩注意：
1. 压缩主要收益来自 gzip 前的体积减少，最终以 gzip 后为准
2. 保留 source map 以便线上调试
3. 生产构建开启，开发构建关闭（可读性优先）
```

## CSS Tree Shaking 移除未用样式

CSS Tree Shaking（如 PurgeCSS、Tailwind JIT、UnCSS）扫描源码，移除未被引用的选择器，解决「删了组件 CSS 还在」的累积问题。

```text
CSS Tree Shaking 原理：
1. 扫描 HTML/JS/模板源码
2. 提取出现的类名、ID、标签
3. 与 CSS 中的选择器比对
4. 移除从未出现的选择器

适用场景：
传统全局 CSS（BEM 等）→ PurgeCSS / UnCSS
原子化 CSS → 框架内置 JIT 按需生成
```

```js
// PurgeCSS 配置
{
  content: ['./src/**/*.html', './src/**/*.js'],
  css: ['./src/**/*.css'],
  safelist: ['is-active', /^keep-/],
}
```

```text
Tree Shaking 的坑：
1. 动态类名 —— 拼接、运行时生成的类名会被误删
2. 第三方样式 —— 可能误删库的隐藏选择器
3. 需要 safelist 保护动态类
```

## CSS Code Splitting 代码分割

CSS Code Splitting 把 CSS 按路由/组件拆成多个文件，实现按需加载，避免首屏加载全部样式。

```text
CSS 分割策略：
1. 按路由拆分 —— 每个页面入口对应一份 CSS，路由切换时加载
2. 按组件拆分 —— 组件懒加载时，其样式一并懒加载
3. 抽取公共 —— 多页共用的样式抽成 common chunk
```

```jsx
// 组件懒加载会带动其 CSS 一起分割
const Chart = React.lazy(() => import('./Chart'));

// import './Chart.css' 会随 Chart 组件一起按需加载
```

```text
分割的收益与代价：
收益 —— 首屏只加载必要样式，加速渲染
代价 —— 请求数增加、需处理加载顺序（避免样式闪烁）

配合 HTTP/2 与缓存，收益通常大于代价。
```

## CSS Extraction 样式提取

CSS Extraction 把 JS 里（CSS-in-JS、import './x.css'）的样式提取成独立 `.css` 文件，而非运行时注入 `<style>`。

```text
提取的意义：
1. 并行加载 —— CSS 与 JS 并行下载，不阻塞 JS 执行
2. 可缓存 —— 独立 .css 文件利于长效缓存
3. 避免闪烁 —— 样式在 HTML 阶段就加载，无 FOUC

构建工具实现：
Webpack —— mini-css-extract-plugin
Vite —— 生产构建默认提取
```

```js
// webpack.config.js
const MiniCssExtractPlugin = require('mini-css-extract-plugin');

module.exports = {
  module: {
    rules: [
      {
        test: /\.css$/,
        use: [MiniCssExtractPlugin.loader, 'css-loader'],
      },
    ],
  },
  plugins: [new MiniCssExtractPlugin({ filename: '[name].[contenthash].css' })],
};
```

```text
开发 vs 生产：
开发 —— 样式注入 <style>（HMR 快）
生产 —— 提取成 .css 文件（性能优先）
```

## 应用场景实战

### 场景一：现代项目标准 CSS 管线

```text
SCSS 源码
  → sass 编译成 CSS
  → PostCSS（autoprefixer + postcss-preset-env）
  → cssnano 压缩
  → mini-css-extract 提取 + contenthash 命名
  → 产出 ./dist/assets/index.[hash].css
```

### 场景二：原子化框架的构建

```text
Tailwind/UnoCSS 源码扫描
  → JIT 按需生成工具类 CSS
  → PostCSS 处理（前缀、压缩）
  → 产出体积极小、只含用到的类
```

## 最佳实践与踩坑记录

### 最佳实践

1. 生产构建必须开启 CSS 压缩与提取
2. 用 browserslist 统一 Autoprefixer 与 Babel 的目标范围
3. 传统全局 CSS 项目接入 Tree Shaking，控制产物膨胀
4. CSS 产物用 contenthash 命名，实现长效缓存
5. 按路由做 CSS 分割，减少首屏样式体积

### 踩坑记录

```text
坑 1：Tree Shaking 误删动态类名
结论：上线后部分动态样式消失。
原因：JS 拼接的类名扫描不到，被 PurgeCSS 移除。
解法：safelist 保护动态类，或避免动态拼接类名。

坑 2：Autoprefixer 加了多余前缀
结论：产物里满是 -webkit- 前缀，体积膨胀。
原因：browserslist 范围过宽（如包含 IE 11）。
解法：收敛 browserslist 到真实支持的浏览器范围。

坑 3：CSS 提取后出现样式闪烁
结论：首屏先无样式后闪出。
原因：CSS 与 JS 加载顺序、异步组件样式未提前加载。
解法：关键 CSS 内联，或预加载异步 chunk 的样式。

坑 4：contenthash 未生效导致缓存失效
结论：改 CSS 后 hash 没变，用户拿到旧缓存。
原因：文件名未用 contenthash 或提取插件配置错。
解法：产物名用 [contenthash]，确保内容变更 hash 变更。

坑 5：开发环境也开了压缩
结论：HMR 变慢、报错难定位。
原因：开发环境未关闭 minify 和 source map 缺失。
解法：压缩仅在生产开启，开发保留 source map。
```

## 概述

文件处理是前端的常见需求：上传、预览、下载、二进制数据处理。核心是 File、Blob（文件对象）与 ArrayBuffer、TypedArray（二进制数据）。

```text
二进制数据处理的核心类型：
Blob —— 二进制大对象（文件、图片等原始数据）
File —— 继承自 Blob，带文件名等元信息
ArrayBuffer —— 原始二进制缓冲区（字节数组）
TypedArray —— 类型化视图（操作 ArrayBuffer）
DataView —— 灵活的字节级读写
FileReader —— 读取 File/Blob 内容
```

## File 与 Blob

Blob 是不可变的二进制数据，File 是带元信息的 Blob（文件名、类型、大小）。

```js
// 获取 File（文件输入）
const input = document.querySelector('input[type=file]');
input.addEventListener('change', () => {
  const file = input.files[0];
  console.log(file.name);      // 文件名
  console.log(file.size);      // 大小（字节）
  console.log(file.type);      // MIME 类型
});

// File 继承自 Blob
file instanceof Blob;          // true
```

```js
// 创建 Blob
const blob = new Blob(['Hello World'], { type: 'text/plain' });
blob.size;                     // 11
blob.type;                     // 'text/plain'

// 从数组创建
const data = new Blob([JSON.stringify({ a: 1 })], { type: 'application/json' });
```

```js
// 切片（分片上传）
const chunk = file.slice(0, 1024 * 1024);   // 前 1MB
```

## FileReader 读取文件

FileReader 异步读取 File/Blob 内容为不同格式。

```js
const reader = new FileReader();

// 读取为文本
reader.readAsText(file);
reader.onload = () => console.log(reader.result);   // 文本内容

// 读取为 Data URL（预览图片）
reader.readAsDataURL(file);
reader.onload = () => {
  img.src = reader.result;   // 'data:image/png;base64,...'
};

// 读取为 ArrayBuffer
reader.readAsArrayBuffer(file);
reader.onload = () => {
  const buffer = reader.result;   // ArrayBuffer
};
```

```js
// 用 Promise 封装
function readAsText(file) {
  return new Promise((resolve, reject) => {
    const reader = new FileReader();
    reader.onload = () => resolve(reader.result);
    reader.onerror = reject;
    reader.readAsText(file);
  });
}

const content = await readAsText(file);
```

## ArrayBuffer 与 DataView

ArrayBuffer 是固定长度的原始二进制缓冲区，DataView 提供灵活的字节读写。

```js
// 创建 ArrayBuffer（16 字节）
const buffer = new ArrayBuffer(16);
buffer.byteLength;             // 16

// DataView 灵活读写（可指定字节序）
const view = new DataView(buffer);
view.setInt8(0, 127);          // 在偏移 0 写 int8
view.setInt16(1, 300, true);   // 小端序写 int16
view.getInt16(1, true);        // 读回 300
```

```text
ArrayBuffer vs DataView vs TypedArray：
ArrayBuffer —— 原始字节缓冲区（不能直接读写）
DataView —— 灵活视图（任意偏移、字节序，但每次调用有开销）
TypedArray —— 固定类型视图（高效，但类型和偏移固定）
```

## TypedArray 类型化数组

TypedArray 是操作 ArrayBuffer 的类型化视图，提供高效的数组式访问。

```js
// 常用 TypedArray 类型
const int8 = new Int8Array(4);        // 8 位整数
const uint8 = new Uint8Array(4);      // 8 位无符号
const int16 = new Int16Array(4);      // 16 位整数
const uint32 = new Uint32Array(4);    // 32 位无符号
const float32 = new Float32Array(4);  // 32 位浮点
const float64 = new Float64Array(4);  // 64 位浮点
```

```js
// 数组式访问
const arr = new Uint8Array([1, 2, 3, 255]);
arr[0];              // 1
arr.length;          // 4
arr.buffer;          // 底层 ArrayBuffer

// 字节序
const uint16 = new Uint16Array([0x1234]);
new Uint8Array(uint16.buffer);   // [0x34, 0x12]（小端序）
```

```text
TypedArray 的用途：
1. 高效处理二进制（音视频、图像、网络协议）
2. WebGL、Canvas 像素数据
3. 文件上传、WebSocket 二进制
```

## URL.createObjectURL 对象 URL

createObjectURL 为 Blob/File 创建临时的对象 URL，用于预览、下载。

```js
// 图片预览
const url = URL.createObjectURL(file);
img.src = url;

// 下载文件
const blob = new Blob(['内容'], { type: 'text/plain' });
const url2 = URL.createObjectURL(blob);
const a = document.createElement('a');
a.href = url2;
a.download = 'file.txt';
a.click();
```

```js
// 释放对象 URL（重要！避免内存泄漏）
URL.revokeObjectURL(url);
```

```text
createObjectURL 的注意：
1. 生成的 URL 是临时的（blob: 开头）
2. 用完必须 revokeObjectURL 释放
3. 图片预览用完及时释放
```

## 应用场景实战

### 场景一：图片上传预览

```js
input.addEventListener('change', (e) => {
  const file = e.target.files[0];
  if (!file) return;

  const url = URL.createObjectURL(file);
  preview.src = url;

  // 加载完成后释放（或用完后手动 revoke）
  preview.onload = () => URL.revokeObjectURL(url);
});
```

### 场景二：文件分片上传

```js
async function uploadChunks(file, chunkSize = 1024 * 1024) {
  const chunks = Math.ceil(file.size / chunkSize);
  for (let i = 0; i < chunks; i++) {
    const chunk = file.slice(i * chunkSize, (i + 1) * chunkSize);
    await fetch('/api/upload', { method: 'POST', body: chunk });
  }
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. createObjectURL 用完 revoke，避免内存泄漏
2. 读文件用 FileReader + Promise 封装
3. 二进制处理用 TypedArray/DataView
4. 大文件上传分片处理
5. 字节序（大小端）处理用 DataView 明确指定

### 踩坑记录

```text
坑 1：createObjectURL 未释放
结论：频繁预览导致内存占用上升。
原因：对象 URL 未 revoke，一直占用内存。
解法：用完 URL.revokeObjectURL(url)。

坑 2：FileReader 异步读取时机
结论：读取后立即访问 result 得到 null。
原因：FileReader 异步，需 onload 回调。
解法：用 onload 或 Promise 封装 await。

坑 3：Blob 不可变
结论：想修改 Blob 内容做不到。
原因：Blob 是不可变对象。
解法：需要修改用 ArrayBuffer/TypedArray，或重新构造 Blob。

坑 4：大文件一次性读取内存溢出
结论：超大文件 readAsDataURL 内存爆炸。
原因：一次性读入内存，Data URL 还会 base64 膨胀。
解法：分片读取，或直接用 blob URL 流式处理。

坑 5：TypedArray 字节序误解
结论：跨端传输时数据错乱。
原因：不同平台字节序（大小端）不同。
解法：网络传输用 DataView 明确字节序，或统一大端序。
```

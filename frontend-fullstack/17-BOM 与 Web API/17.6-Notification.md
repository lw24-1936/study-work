## 概述

Notification API 让网页能发送系统级通知，Push Notification 则让服务端能主动推送（即使页面关闭）。二者结合构成完整的通知能力。

```text
两类通知：
Notification API —— 页面运行时发送系统通知（需页面开着）
Push Notification —— 服务端推送（配合 Service Worker，页面可关闭）

关键点：都需要用户授权，且部分平台（iOS）有额外限制。
```

## Notification API

Notification 发送系统通知，需先请求权限。

```js
// 创建通知（需已授权）
const notification = new Notification('标题', {
  body: '通知内容',
  icon: '/icon.png',
  tag: 'unique-tag',           // 相同 tag 的通知会替换
  silent: false,
});

// 通知事件
notification.onclick = () => {
  window.focus();
  notification.close();
};
```

```js
// 发送通知的完整流程
async function notify(title, options) {
  if (!('Notification' in window)) {
    console.log('不支持通知');
    return;
  }
  if (Notification.permission === 'granted') {
    new Notification(title, options);
  } else if (Notification.permission !== 'denied') {
    const permission = await Notification.requestPermission();
    if (permission === 'granted') {
      new Notification(title, options);
    }
  }
}
```

```text
Notification 的关键点：
1. 先请求权限（requestPermission）
2. permission 状态：granted / denied / default
3. tag 相同会替换旧通知
4. 需在安全上下文（HTTPS）
```

## Permission 权限

通知需要用户授权，权限状态通过 Notification.permission 查询。

```js
// 查询权限状态
Notification.permission;   // 'granted' | 'denied' | 'default'

// 请求权限（需用户手势触发）
Notification.requestPermission().then(permission => {
  if (permission === 'granted') {
    console.log('已授权');
  } else {
    console.log('被拒绝');
  }
});
```

```text
权限三态：
granted —— 已授权（可发通知）
denied —— 已拒绝（不可发，且不能再次请求）
default —— 未决定（可请求）

注意：requestPermission 通常需在用户手势（点击）中调用。
```

## Push Notification 推送通知

Push Notification 需要 Service Worker 支持：服务端通过 Push API 推送，Service Worker 接收并显示通知。

```js
// 订阅推送（需 Service Worker）
async function subscribePush() {
  const registration = await navigator.serviceWorker.ready;
  const subscription = await registration.pushManager.subscribe({
    userVisibleOnly: true,
    applicationServerKey: publicKey,   // VAPID 公钥
  });
  // 把 subscription 发送到服务端存储
  await fetch('/api/subscribe', {
    method: 'POST',
    body: JSON.stringify(subscription),
  });
}
```

```js
// Service Worker 中接收推送并显示通知
self.addEventListener('push', (event) => {
  const data = event.data?.json() ?? {};
  event.waitUntil(
    self.registration.showNotification(data.title, {
      body: data.body,
    }),
  );
});
```

```text
Push Notification 的流程：
1. 注册 Service Worker
2. 用户授权通知
3. 客户端订阅（pushManager.subscribe）
4. 把 subscription 发给服务端
5. 服务端用 Push API 推送
6. Service Worker 接收并 showNotification
```

## 应用场景实战

### 场景一：站内提醒

```js
async function showReminder(title, body) {

    new Notification(title, { body });
  } else if (Notification.permission !== 'denied') {
```

## 最佳实践与踩坑记录

### 最佳实践

1. 请求权限绑定用户手势，别在页面加载时自动请求
2. 用 tag 去重，避免通知堆积
3. 通知点击后聚焦页面并关闭通知
4. 服务端推送配 Service Worker，实现页面关闭也能收
5. 权限被拒后不要反复请求，引导用户手动开启

### 踩坑记录

```text
坑 1：页面加载时请求权限被忽略
结论：自动 requestPermission 无效或被浏览器忽略。
原因：浏览器要求用户手势触发权限请求。
解法：在用户点击（如「开启通知」按钮）里请求。

坑 2：iOS 需要 PWA 安装
结论：iOS Safari 上 Notification 不可用。
原因：iOS 要求 PWA 添加到主屏幕后才支持通知。
解法：检测环境，引导用户添加到主屏幕。

坑 3：权限被拒后再次请求无效
结论：requestPermission 返回 denied，无法再弹授权。
原因：denied 状态不能再次请求。
解法：引导用户去浏览器设置手动开启。

坑 4：非 HTTPS 环境通知不可用
结论：Notification 在 HTTP 下报错。
原因：通知要求安全上下文。
解法：部署 HTTPS 或本地 localhost 开发。

坑 5：通知堆积
结论：相同通知多次弹出，骚扰用户。
原因：未设置 tag，通知不合并。
解法：相同内容用同一 tag，自动替换旧通知。
```

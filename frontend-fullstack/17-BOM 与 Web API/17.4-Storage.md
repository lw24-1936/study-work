## 概述

浏览器提供多种客户端存储方案，从简单的键值对到结构化数据库，适用于不同的数据规模与场景。

```text
存储方案对比：
localStorage —— 简单键值对（字符串），持久化，约 5MB
sessionStorage —— 会话级键值对，关闭标签页清除
Cookie —— 随请求发送，服务端可读（约 4KB）
IndexedDB —— 结构化数据库，大容量，异步，支持索引
Cache API —— 缓存请求响应（Service Worker 常用）
```

## localStorage 与 sessionStorage

两者都是简单键值存储，只能存字符串，API 相同，区别在生命周期。

```js
// localStorage：持久化（关闭浏览器仍保留）
localStorage.setItem('theme', 'dark');
localStorage.getItem('theme');        // 'dark'
localStorage.removeItem('theme');
localStorage.clear();                 // 清空所有

// sessionStorage：会话级（关闭标签页清除）
sessionStorage.setItem('temp', 'value');
```

```js
// 只能存字符串，对象需 JSON 序列化
const user = { name: 'Alice', age: 30 };
localStorage.setItem('user', JSON.stringify(user));
const loaded = JSON.parse(localStorage.getItem('user'));
```

```js
// 遍历所有键
for (let i = 0; i < localStorage.length; i++) {
  const key = localStorage.key(i);
  console.log(key, localStorage.getItem(key));
}
```

```text
localStorage vs sessionStorage：
localStorage —— 持久化，所有同源标签页共享
sessionStorage —— 会话级，每个标签页独立，关闭清除

限制：
1. 只能存字符串（对象需 JSON）
2. 同步操作（大量数据会阻塞）
3. 容量约 5MB
```

## Storage Event 存储事件

Storage Event 在**其他标签页**修改 localStorage 时触发（同一页修改不触发）。

```js
// 监听其他标签页的存储变化（跨标签页通信）
window.addEventListener('storage', (e) => {
  console.log(e.key);        // 变化的键
  console.log(e.oldValue);   // 旧值
  console.log(e.newValue);   // 新值
  console.log(e.url);        // 触发变化的页面 URL
});
```

```js
// 典型：跨标签页同步登录状态
window.addEventListener('storage', (e) => {
  if (e.key === 'token') {
    updateAuthState(e.newValue);
  }
});
```

```text
Storage Event 的特点：
1. 只在「其他标签页」修改时触发（本页不触发）
2. 用于跨标签页通信/同步
3. 同源限制
```

## IndexedDB 索引数据库

IndexedDB 是浏览器内置的**结构化数据库**，支持大容量、索引、事务、异步操作。

```js
// 打开数据库
const request = indexedDB.open('myDB', 1);

request.onupgradeneeded = (e) => {
  const db = e.target.result;
  const store = db.createObjectStore('users', { keyPath: 'id' });
  store.createIndex('name', 'name', { unique: false });
};

request.onsuccess = (e) => {
  const db = e.target.result;
  // 读写操作
};
```

```js
// 添加数据（事务）
const tx = db.transaction('users', 'readwrite');
const store = tx.objectStore('users');
store.add({ id: 1, name: 'Alice' });
```

```text
IndexedDB 的特点：
1. 大容量 —— 可达数百 MB
2. 结构化 —— 存对象、支持索引、事务
3. 异步 —— 基于事件/回调（或 Promise 封装）
4. 复杂 —— 原生 API 繁琐，常用库封装（idb、Dexie）

适用：缓存大量结构化数据（离线应用、本地数据库）。
```

## Cache API 缓存

Cache API 缓存请求/响应，是 Service Worker 离线能力的核心。

```js
// 打开缓存
const cache = await caches.open('my-cache');

// 缓存请求响应
await cache.add('/api/data');           // 缓存单个请求
await cache.addAll(['/a.js', '/b.css']); // 缓存多个

// 读取
const response = await cache.match('/api/data');
```

```js
// 典型 Service Worker 缓存策略
self.addEventListener('fetch', (e) => {
  e.respondWith(
    caches.match(e.request).then(cached => cached || fetch(e.request)),
  );
});
```

```text
Cache API 的特点：
1. 缓存 Request/Response 对
2. 配合 Service Worker 实现离线
3. 支持缓存策略（缓存优先、网络优先等）
```

## 应用场景实战

### 场景一：持久化用户偏好

```js
function savePreference(key, value) {
  localStorage.setItem(key, JSON.stringify(value));
}
function loadPreference(key, fallback) {
  const raw = localStorage.getItem(key);
  return raw ? JSON.parse(raw) : fallback;
}

savePreference('theme', 'dark');
loadPreference('theme', 'light');   // 'dark'
```

### 场景二：跨标签页同步

```js
// 页面 A：登录后写 token
localStorage.setItem('token', 'xxx');

// 页面 B：监听并同步
window.addEventListener('storage', (e) => {
  if (e.key === 'token') refreshUI(e.newValue);
});
```

## 最佳实践与踩坑记录

### 最佳实践

1. 简单持久化用 localStorage，对象记得 JSON 序列化
2. 会话级临时数据用 sessionStorage
3. 大量结构化数据用 IndexedDB（配 idb 库）
4. 离线资源缓存用 Cache API + Service Worker
5. 敏感数据（token）不存 localStorage（易被 XSS 窃取）

### 踩坑记录

```text
坑 1：localStorage 存对象忘序列化
结论：存对象得到 '[object Object]'。
原因：storage 只能存字符串，对象被强转。
解法：JSON.stringify 存，JSON.parse 取。

坑 2：JSON.parse 解析失败
结论：取回数据 parse 抛错。
原因：存的数据损坏或格式不对。
解法：try/catch 包裹，或 safeParse 兜底。

坑 3：Storage Event 本页不触发
结论：同页面修改监听不到 storage 事件。
原因：storage 事件只跨标签页触发。
解法：本页直接用返回值，跨页用 storage 事件。

坑 4：localStorage 同步阻塞
结论：大量数据读写卡顿。
原因：localStorage 同步操作，阻塞主线程。
解法：大数据用 IndexedDB（异步）。

坑 5：隐私模式 localStorage 受限
结论：隐私模式下 localStorage 抛异常或容量极小。
原因：部分浏览器隐私模式限制存储。
解法：存储前 try/catch，或用内存降级方案。
```

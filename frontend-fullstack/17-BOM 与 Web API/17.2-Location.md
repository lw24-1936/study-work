## 概述

Location 表示当前文档的 URL，是解析和操作地址的核心对象。它既是「当前地址的组成部分」，也能控制页面跳转。

```text
示例 URL：
https://user:pass@example.com:8080/path/to/page?query=1#section

protocol  —— https:
host      —— example.com:8080（hostname + port）
hostname  —— example.com
port      —— 8080
pathname  —— /path/to/page
search    —— ?query=1（查询字符串）
hash      —— #section（片段）
href      —— 完整 URL
```

## URL 组成部分

Location 把 URL 拆解成各个部分，每个属性都可读写。

```js
// 假设当前 URL：https://example.com:8080/path?page=2#top
location.href;       // 完整 URL
location.protocol;   // 'https:'
location.host;       // 'example.com:8080'
location.hostname;   // 'example.com'
location.port;       // '8080'
location.pathname;   // '/path'
location.search;     // '?page=2'
location.hash;       // '#top'
```

```text
各属性的读写：
读 —— 获取当前 URL 的对应部分
写 —— 修改对应部分（修改 href、hash 等会触发跳转/滚动）
```

## href / protocol / host / port

```js
// href：完整 URL（读写）
location.href;                    // 当前地址
location.href = '/new-page';      // 跳转（可后退）

// protocol：协议
location.protocol;                // 'https:'

// host：主机名 + 端口
location.host;                    // 'example.com:8080'

// hostname：主机名（无端口）
location.hostname;                // 'example.com'

// port：端口
location.port;                    // '8080'（默认端口为空字符串）
```

```text
host vs hostname：
host —— 含端口（example.com:8080）
hostname —— 不含端口（example.com）

protocol 含冒号（https:），判断时注意。
```

## pathname / search / hash

```js
// pathname：路径
location.pathname;                // '/path/to/page'

// search：查询字符串（含 ?）
location.search;                  // '?page=2&sort=asc'

// hash：片段（含 #）
location.hash;                    // '#top'
location.hash = '#new-section';   // 修改 hash（不刷新，触发 hashchange）
```

```js
// 解析查询参数
function getQueryParams() {
  const params = new URLSearchParams(location.search);
  return Object.fromEntries(params);
}
// { page: '2', sort: 'asc' }
```

```js
// 用 URL 对象解析完整地址（更强大）
const url = new URL(location.href);
url.searchParams.get('page');     // '2'
url.searchParams.set('page', '3'); // 修改参数
```

```text
hash 的特性：
1. 修改 hash 不刷新页面，但会产生历史记录
2. 触发 hashchange 事件
3. 早期 SPA 路由用 hash（#/page），现代用 history API
```

## assign / replace / reload 跳转

三个方法控制页面跳转，区别在于历史记录。

```js
// assign：跳转，保留当前页在历史（可后退）
location.assign('/new-page');

// replace：替换当前页（不可后退）
location.replace('/login');

// reload：刷新页面
location.reload();           // 刷新（可能用缓存）
location.reload(true);       // 强制刷新（忽略缓存，参数已废弃）
```

```text
三种跳转的区别：
assign(url) —— 等价 location.href = url，可后退
replace(url) —— 替换当前历史，不可后退
reload() —— 重新加载当前页

href 赋值 = assign；replace 用于「登录后跳转」等不可回退场景。
```

## 应用场景实战

### 场景一：解析 URL 参数

```js
const url = new URL(location.href);
const page = url.searchParams.get('page') || 1;
const sort = url.searchParams.get('sort') || 'asc';
```

### 场景二：登录后不可回退跳转

```js
function loginSuccess() {
  location.replace('/dashboard');   // 替换，防止回到登录页
}
```

### 场景三：SPA 锚点滚动

```js
location.hash = 'section-2';   // 滚动到 id=section-2 的元素
```

## 最佳实践与踩坑记录

### 最佳实践

1. 解析 URL 用 URL 对象 / URLSearchParams，别手写正则
2. 跳转用 location.href 或 assign，不可回退用 replace
3. 读取参数用 searchParams.get，注意默认值
4. SPA 路由用 history API，hash 路由仅兼容旧环境
5. 修改 hash 前确认是否需要触发 hashchange 逻辑

### 踩坑记录

```text
坑 1：search 含 ? 号
结论：location.search 返回 '?page=2'，忘记去掉 ?。
原因：search 包含问号。
解法：用 URLSearchParams 解析，自动处理 ?。

坑 2：hash 值读写遗漏 #
结论：location.hash = 'top' 得到的其实是 '#top'。
原因：hash 属性自动补 #。
解法：读取时注意去掉 #，或直接整段处理。

坑 3：replace 后无法后退
结论：登录页 replace 后，后退回不到登录页。
原因：replace 替换了历史记录。
解法：明确场景，需要可回退用 assign/href。

坑 4：手写正则解析 query
结论：手写解析 query 出错（编码、重复键、+号）。
原因：query 解析边界情况多。
解法：用 URLSearchParams 或 URL 对象。

坑 5：reload 参数误解
结论：reload(true) 强制刷新已废弃。
原因：该布尔参数在现代标准中移除。
解法：用 location.reload()，缓存策略交给服务端 header。
```

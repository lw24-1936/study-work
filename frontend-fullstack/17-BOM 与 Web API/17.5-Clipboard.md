## 概述

Clipboard API 提供读写系统剪贴板的能力。它取代了旧的 document.execCommand('copy')，是异步的、基于 Promise 的现代方案。

```text
剪贴板能力：
读文本 —— navigator.clipboard.readText()
写文本 —— navigator.clipboard.writeText()
读写富内容 —— read() / write() + ClipboardItem

旧方案：document.execCommand('copy')（同步，已废弃）
新方案：Clipboard API（异步，需权限/安全上下文）
```

## Clipboard API

Clipboard API 通过 navigator.clipboard 访问，需要在安全上下文（HTTPS 或 localhost）。

```js
// 入口
navigator.clipboard;

// 所有方法返回 Promise
navigator.clipboard.writeText('text').then(() => {
  console.log('已复制');
});
```

```js
// 检测是否可用
if (navigator.clipboard) {
  // 支持 Clipboard API
} else {
  // 降级到 execCommand
}
```

```text
Clipboard API 的限制：
1. 安全上下文 —— HTTPS 或 localhost
2. 权限 —— 读取需用户授权，写入通常需用户手势
3. 异步 —— Promise 返回
```

## readText 读取文本

readText 读取剪贴板中的纯文本。

```js
// 读取文本（需用户授权）
async function pasteText() {
  try {
    const text = await navigator.clipboard.readText();
    console.log('剪贴板内容:', text);
  } catch (err) {
    console.error('读取失败:', err);
  }
}
```

```text
readText 的权限：
1. 浏览器会询问用户是否允许读取
2. 未授权或被拒绝时抛异常
3. 通常需要用户手势（如点击「粘贴」按钮）
```

## writeText 写入文本

writeText 把文本写入剪贴板。

```js
// 复制文本
async function copyText(text) {
  try {
    await navigator.clipboard.writeText(text);
    console.log('复制成功');
  } catch (err) {
    console.error('复制失败:', err);
  }
}

copyText('要复制的内容');
```

```js
// 典型：点击复制按钮
copyBtn.addEventListener('click', async () => {
  await navigator.clipboard.writeText('https://example.com');
  showToast('链接已复制');
});
```

```text
writeText 的特点：
1. 通常需要用户手势（点击等）
2. 写入无需额外权限（读取才需要）
3. 自动处理权限与焦点
```

## ClipboardItem 富内容

ClipboardItem 支持读写非文本内容（图片、HTML 等），通过 read()/write() 操作。

```js
// 写入图片
async function copyImage(blob) {
  const item = new ClipboardItem({ 'image/png': blob });
  await navigator.clipboard.write([item]);
}
```

```js
// 读取富内容
async function pasteRich() {
  const items = await navigator.clipboard.read();
  for (const item of items) {
    if (item.types.includes('image/png')) {
      const blob = await item.getType('image/png');
      // 处理图片
    }
  }
}
```

```text
ClipboardItem 支持的 MIME 类型：
text/plain、text/html、image/png、image/jpeg 等

富内容读写需要更高的权限，且各浏览器支持度不同。
```

## 应用场景实战

### 场景一：复制到剪贴板（带降级）

```js
async function copyToClipboard(text) {
  try {
    if (navigator.clipboard) {
      await navigator.clipboard.writeText(text);
      return true;
    }
    // 降级：execCommand（旧浏览器）
    const textarea = document.createElement('textarea');
    textarea.value = text;
    document.body.appendChild(textarea);
    textarea.select();
    document.execCommand('copy');
    textarea.remove();
    return true;
  } catch {
    return false;
  }
}
```

### 场景二：截图复制

```js
async function copyScreenshot(canvas) {
  const blob = await new Promise(r => canvas.toBlob(r, 'image/png'));
  await navigator.clipboard.write([
    new ClipboardItem({ 'image/png': blob }),
  ]);
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. 优先用 Clipboard API，旧浏览器降级 execCommand
2. 复制操作绑定用户手势（点击），提高成功率
3. 读取文本需处理权限拒绝（try/catch）
4. 检测 navigator.clipboard 是否存在
5. 敏感内容复制后考虑清空剪贴板

### 踩坑记录

```text
坑 1：非安全上下文 Clipboard 不可用
结论：HTTP 环境下 navigator.clipboard 是 undefined。
原因：Clipboard API 要求 HTTPS 或 localhost。
解法：部署 HTTPS，或用 execCommand 降级。

坑 2：读取权限被拒绝
结论：readText 抛异常。
原因：用户拒绝剪贴板读取权限。
解法：try/catch 处理，提示用户授权。

坑 3：无用户手势写入失败
结论：页面加载时自动复制失败。
原因：浏览器要求用户手势触发写入。
解法：在点击等用户事件里调用复制。

坑 4：execCommand 已废弃但仍在用
结论：依赖旧 API，未来可能移除。
原因：execCommand 已废弃。
解法：优先 Clipboard API，execCommand 仅降级。

坑 5：复制后焦点丢失
结论：点击复制后页面滚动或选区变化。
原因：execCommand 降级方案 select() 影响焦点。
解法：用 Clipboard API（无需选中文本）。
```

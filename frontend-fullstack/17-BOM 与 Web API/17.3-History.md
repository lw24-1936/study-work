## 概述

History 管理浏览器会话的历史记录，是 SPA（单页应用）路由的基础。通过 pushState/replaceState 在不刷新页面的情况下改变 URL。

```text
History 的两类能力：
1. 导航 —— back、forward、go（前进后退）
2. 状态管理 —— pushState、replaceState（SPA 路由）

SPA 路由原理：
pushState 改变 URL（不刷新）→ 监听 popstate → 根据 URL 渲染对应组件
```

## history 基础方法

```js
// 历史长度
history.length;               // 会话中的记录数

// 前进后退
history.back();               // 后退一页
history.forward();            // 前进一页
history.go(-1);               // 后退一页（等价 back）
history.go(1);                // 前进一页
history.go(0);                // 刷新当前页
```

```text
history 对象：
length —— 历史记录数
state —— 当前记录的状态对象（pushState 传入的）
scrollRestoration —— 滚动恢复设置
```

## pushState 添加记录

pushState 向历史栈**添加**一条新记录，改变 URL 但不刷新页面。

```js
// pushState(state, title, url)
history.pushState({ page: 'about' }, '', '/about');

// 三个参数：
// state —— 状态对象（可序列化，稍后通过 history.state 读取）
// title —— 标题（大多数浏览器忽略，传空）
// url —— 新 URL（同源，可为空）
```

```js
// 典型 SPA 路由跳转
function navigate(path) {
  history.pushState({ path }, '', path);
  renderRoute(path);   // 根据路径渲染组件
}
```

```text
pushState 的特点：
1. 不刷新页面 —— 只改 URL 和添加历史记录
2. 同源限制 —— URL 必须同源
3. 触发 popstate？—— 不会（只有后退/前进才触发）
4. 状态可恢复 —— 后退时 history.state 拿回状态
```

## replaceState 替换记录

replaceState 替换**当前**历史记录，不新增，后退时不会回到被替换的页面。

```js
// 替换当前记录（不新增历史）
history.replaceState({ page: 'login' }, '', '/login');
```

```js
// 典型：登录后替换，避免后退回登录页
function loginSuccess() {
  history.replaceState(null, '', '/dashboard');
  renderRoute('/dashboard');
}
```

```text
pushState vs replaceState：
pushState —— 新增记录（可后退回原页面）
replaceState —— 替换当前记录（后退不回原页面）

replaceState 常用于「重定向后修正 URL」或「不可回退的跳转」。
```

## popstate 事件

popstate 在**历史记录变化**（后退/前进）时触发，是 SPA 路由的监听点。

```js
window.addEventListener('popstate', (e) => {
  console.log('URL 变化:', location.pathname);
  console.log('状态:', e.state);   // pushState 时传入的 state
  renderRoute(location.pathname);  // 重新渲染
});
```

```js
// hashchange：hash 路由的监听事件（旧方案）
window.addEventListener('hashchange', () => {
  console.log('hash 变化:', location.hash);
});
```

```text
popstate 的触发时机：
1. 用户点击浏览器后退/前进按钮
2. history.back()/forward()/go() 调用

不触发的情况：
pushState / replaceState 本身不触发 popstate！
（需要手动调用渲染逻辑）
```

## back / forward / go 导航

```js
history.back();        // 后退一页
history.forward();     // 前进一页
history.go(-2);        // 后退两页
history.go(2);         // 前进两页
history.go(0);         // 刷新当前页
```

```text
导航方法的关系：
back() = go(-1)
forward() = go(1)

这些方法会触发 popstate 事件。
```

## 应用场景实战

### 场景一：简易 SPA 路由

```js
function navigate(path) {
  history.pushState({ path }, '', path);
  render(path);
}

window.addEventListener('popstate', (e) => {
  render(e.state?.path || location.pathname);
});

function render(path) {
  const view = routes[path] || routes['/404'];
  document.querySelector('#app').innerHTML = view;
}
```

### 场景二：模态框关闭恢复 URL

```js
// 打开弹窗：添加历史记录
function openModal() {
  history.pushState({ modal: true }, '', '#modal');
  showModal();
}

// 监听 popstate，后退时关闭弹窗
window.addEventListener('popstate', () => {
  closeModal();
});
```

## 最佳实践与踩坑记录

### 最佳实践

1. SPA 路由用 pushState + popstate 监听
2. 不可回退的跳转用 replaceState
3. pushState 后手动调用渲染（它不触发 popstate）
4. 状态对象可序列化（勿存函数/DOM）
5. 用 hash 路由仅兼容旧环境，现代用 history 路由

### 踩坑记录

```text
坑 1：pushState 不触发 popstate
结论：pushState 后界面没变化。
原因：pushState 只改 URL，不触发 popstate。
解法：pushState 后手动调用渲染逻辑。

坑 2：pushState 状态对象不可序列化
结论：存了函数/DOM，后退时报错或丢失。
原因：state 需结构化克隆（可序列化）。
解法：state 只存纯数据（对象、字符串、数字）。

坑 3：replaceState 后后退跳过了期望页面
结论：后退没有回到上一个页面。
原因：replaceState 替换了当前记录。
解法：需要保留历史用 pushState。

坑 4：跨域 URL 传给 pushState
结论：pushState('/x', '', 'https://other.com') 报错。
原因：pushState 的 URL 必须同源。
解法：只用同源路径。

坑 5：hash 路由与 history 路由混用
结论：路由状态混乱。
原因：两套路由机制冲突。
解法：项目统一用一种路由方案。
```

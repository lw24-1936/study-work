## 概述

DOM 遍历是在节点树中移动：向上找父节点、向下找子节点、水平找兄弟节点。核心是区分「元素遍历」与「节点遍历」（后者包含文本/注释）。

```text
遍历的两套 API：
元素遍历（只含元素，现代推荐）：
parentElement、children、firstElementChild、nextElementSibling 等

节点遍历（含文本/注释）：
parentNode、childNodes、firstChild、nextSibling 等
```

## parentNode 父节点

parentNode 返回父节点（任意类型），parentElement 返回父元素（null 若非元素）。

```js
const el = document.querySelector('.child');

el.parentNode;          // 父节点（可能是 Document 等）
el.parentElement;       // 父元素（父节点是元素时返回，否则 null）
```

```js
// 一直向上遍历祖先
let node = el;
while ((node = node.parentNode)) {
  console.log(node.tagName);
}
```

```text
parentNode vs parentElement：
parentNode —— 父节点（可能是 Document、DocumentFragment）
parentElement —— 父元素（父节点必须是 Element，否则 null）

差异只在「文档根」等边界场景，日常两者等价。
```

## children 与 childNodes

children 返回子**元素**（HTMLCollection），childNodes 返回所有子**节点**（含文本/注释）。

```html
<div id="box">
  文本节点
  <span>元素</span>
  <!-- 注释 -->
</div>
```

```js
const box = document.querySelector('#box');

box.children;        // [span]（只含元素，忽略文本和注释）
box.childNodes;      // [Text, span, Text, Comment]（含文本/注释/换行）
```

```js
// children 是 HTMLCollection（动态）
box.children.length;
[...box.children];     // 转数组
```

```text
children vs childNodes：
children —— 子元素集合（Element 集合），日常首选
childNodes —— 所有子节点（含文本、注释、换行空白）

遍历「子元素」用 children，避免文本节点干扰。
```

## firstChild / lastChild

firstChild 返回第一个子节点（可能文本），firstElementChild 返回第一个子元素。

```js
box.firstChild;          // 第一个子节点（可能是空白文本）
box.firstElementChild;   // 第一个子元素（span）
box.lastChild;           // 最后一个子节点
box.lastElementChild;    // 最后一个子元素
```

```text
firstChild vs firstElementChild：
firstChild —— 第一个节点（含文本，缩进换行也算）
firstElementChild —— 第一个元素（跳过文本）

遍历元素用 Element 系列，避免拿到空白文本节点。
```

## nextSibling / previousSibling 兄弟节点

兄弟遍历同样分节点版与元素版。

```js
el.nextSibling;             // 下一个兄弟节点（含文本）
el.nextElementSibling;      // 下一个兄弟元素
el.previousSibling;         // 上一个兄弟节点
el.previousElementSibling;  // 上一个兄弟元素
```

```js
// 遍历所有兄弟元素
let sibling = el.parentElement.firstElementChild;
while (sibling) {
  console.log(sibling);
  sibling = sibling.nextElementSibling;
}
```

```text
nextSibling vs nextElementSibling：
nextSibling —— 下一个节点（含空白文本）
nextElementSibling —— 下一个元素

日常用 Element 系列，避免空白文本节点干扰。
```

## 元素专用遍历

Element 系列 API 只遍历元素，是现代推荐的方式。

```text
元素遍历完整 API：
parentElement —— 父元素
children —— 子元素集合
firstElementChild / lastElementChild —— 首/末子元素
nextElementSibling / previousElementSibling —— 前后兄弟元素
childElementCount —— 子元素数量
```

```js
const box = document.querySelector('#box');

box.childElementCount;           // 子元素数量
box.firstElementChild;           // 第一个子元素
box.lastElementChild;            // 最后一个子元素

for (const child of box.children) {
  console.log(child);            // 只遍历元素
}
```

```text
为什么优先 Element 系列：
1. 只含元素，忽略文本/注释/空白节点
2. 语义清晰，避免 nodeType 过滤
3. 现代 API，性能与可读性更好
```

## 应用场景实战

### 场景一：遍历表格行

```js
const tbody = document.querySelector('tbody');
for (const row of tbody.children) {           // 只遍历 tr 元素
  const name = row.children[0].textContent;   // 第一个 td
  console.log(name);
}
```

### 场景二：实现简单导航（上下兄弟）

```js
function nextItem(el) {
  return el.nextElementSibling;
}
function prevItem(el) {
  return el.previousElementSibling;
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. 遍历子元素用 children，别用 childNodes
2. 兄弟遍历用 nextElementSibling 系列，避免文本节点
3. 向上查找用 closest（支持选择器），比手动 parentNode 循环简洁
4. 需要包含文本节点时才用 childNodes/nodeType
5. 缓存遍历结果，避免重复 DOM 访问

### 踩坑记录

```text
坑 1：childNodes 拿到空白文本节点
结论：遍历 childNodes 得到缩进/换行的空白文本。
原因：HTML 源码的缩进换行也是文本节点。
解法：用 children（只含元素），或过滤 nodeType。

坑 2：nextSibling 拿到文本节点
结论：nextSibling 返回空白文本而非下一个元素。
原因：节点遍历包含文本。
解法：用 nextElementSibling。

坑 3：parentElement 在文档根为 null
结论：html 元素的 parentElement 是 null。
原因：html 的父节点是 Document，不是 Element。
解法：需要父节点（含 Document）用 parentNode。

坑 4：children 是动态集合
结论：遍历时修改 DOM 导致跳过/重复。
原因：HTMLCollection 实时反映变化。
解法：先转数组 [...children] 再遍历，或倒序遍历。

坑 5：误用 childElementCount 当 children.length
结论：两者结果不同时困惑。
原因：childElementCount 是元素数，children.length 也应是元素数（通常一致）。
解法：都用 children.length 或 childElementCount，保持一致即可。
```

## 概述

DOM（Document Object Model）是浏览器把 HTML 文档解析成的树状对象模型。JavaScript 通过 DOM 读写页面内容与结构。

```text
DOM 的本质：
1. 树结构 —— 文档是根，元素/文本/注释是节点
2. 对象模型 —— 每个节点都是可操作的对象
3. 编程接口 —— 通过 API 查询、修改、遍历

节点类型（nodeType）：
1 元素节点（Element）—— <div> 等
3 文本节点（Text）—— 标签内的文字
8 注释节点（Comment）
9 文档节点（Document）
11 文档片段（DocumentFragment）
```

## Document 文档对象

Document 是 DOM 树的根，代表整个文档，是访问页面的入口。

```js
document;                 // 文档对象
document.documentElement; // <html> 元素
document.head;            // <head> 元素
document.body;            // <body> 元素
document.title;           // 页面标题（可读写）
```

```js
// 文档信息
document.readyState;      // 'loading' | 'interactive' | 'complete'
document.URL;             // 当前 URL
document.domain;          // 域名
```

```text
Document 的职责：
1. 提供文档级访问入口（body、head、title）
2. 创建节点（createElement、createTextNode）
3. 查询节点（getElementById、querySelector）
4. 文档状态（readyState、事件）
```

## Node 与 Element

Node 是所有节点的基类，Element 是元素节点的类型。关系：Element 继承自 Node。

```text
Node（节点基类）—— 文本、注释、文档都是 Node
Element（元素）—— 只有标签（div、span 等）是 Element

区分：
<div>text</div>
   ├── 是 Element（div）
   └── 内部 text 是 Text 节点（不是 Element）
```

```js
const div = document.querySelector('div');

div instanceof Node;       // true
div instanceof Element;    // true

div.nodeType;              // 1（元素节点）
div.nodeName;              // 'DIV'（大写标签名）
div.tagName;               // 'DIV'
```

```js
// 文本节点不是 Element
div.firstChild.nodeType;   // 3（文本节点）
div.firstChild instanceof Element;   // false
```

```text
Node vs Element 的 API 差异：
Node —— nodeType、nodeName、parentNode、childNodes（含文本/注释）
Element —— tagName、children（只含元素）、attributes、classList
```

## Text 与 Comment 节点

文本和注释也是节点，操作时需注意（childNodes 含文本，children 不含）。

```js
const div = document.querySelector('div');
// <div>Hello<!-- 注释 --></div>

div.childNodes;         // [Text("Hello"), Comment(" 注释 ")]
div.children;           // []（无元素子节点）

// 创建文本和注释
document.createTextNode('文本');
document.createComment('注释');
```

```js
// 读写文本内容（textContent 会转义）
div.textContent = '新文本';     // 替换所有子节点为纯文本
div.textContent;                // '新文本'
```

```text
文本处理的三个属性（易混淆）：
textContent —— 纯文本（所有子节点的文本），写时转义 HTML
innerHTML —— HTML 字符串（会解析标签），有 XSS 风险
innerText —— 渲染后的可见文本（考虑 CSS），性能较差
```

## DocumentFragment 文档片段

DocumentFragment 是「轻量容器」，批量插入节点时减少 DOM 操作次数。

```js
const fragment = document.createDocumentFragment();

for (let i = 0; i < 100; i++) {
  const li = document.createElement('li');
  li.textContent = `Item ${i}`;
  fragment.appendChild(li);     // 先追加到片段（不触发渲染）
}

document.querySelector('ul').appendChild(fragment);   // 一次性插入
```

```text
DocumentFragment 的价值：
1. 批量操作 —— 先在片段里组装，再一次插入 DOM
2. 性能 —— 减少回流/重绘次数
3. 插入后消失 —— 片段本身不留在 DOM 中，只插入其子节点
```

## ShadowRoot 影子根

ShadowRoot 是 Shadow DOM 的根，提供样式和结构的封装隔离（Web Components 的核心）。

```js
const host = document.querySelector('#my-element');

// 附加 shadow root
const shadow = host.attachShadow({ mode: 'open' });

// shadow 内部独立的结构与样式
shadow.innerHTML = `
  <style>
    button { background: #0066cc; color: white; }
  </style>
  <button>组件按钮</button>
`;
```

```text
Shadow DOM 的价值：
1. 样式隔离 —— shadow 内样式不影响外部
2. 结构封装 —— 内部结构对外部隐藏
3. Web Components 基础 —— 自定义元素 + shadow DOM

mode: 'open'（可外部访问）vs 'closed'（完全封闭）。
```

## 应用场景实战

### 场景一：批量渲染列表

```js
function renderList(items) {
  const fragment = document.createDocumentFragment();
  items.forEach(item => {
    const li = document.createElement('li');
    li.textContent = item;
    fragment.appendChild(li);
  });
  document.querySelector('ul').append(fragment);   // 一次插入
}
```

### 场景二：区分元素与文本节点

```js
const node = div.firstChild;
if (node.nodeType === Node.ELEMENT_NODE) {
  // 元素节点处理
} else if (node.nodeType === Node.TEXT_NODE) {
  // 文本节点处理
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. 批量插入用 DocumentFragment，减少 DOM 操作
2. 纯文本用 textContent，避免 innerHTML 的 XSS 风险
3. 需要样式封装用 Shadow DOM
4. 区分 children（元素）与 childNodes（含文本）
5. 用 nodeType 判断节点类型

### 踩坑记录

```text
坑 1：childNodes 含文本节点
结论：遍历 childNodes 得到空白文本节点。
原因：HTML 缩进/换行也是文本节点。
解法：遍历 children（只含元素），或过滤 nodeType。

坑 2：innerHTML 的 XSS 风险
结论：innerHTML 插入用户输入导致脚本注入。
原因：innerHTML 会解析 HTML 标签。
解法：用户输入用 textContent，或做转义。

坑 3：DocumentFragment 插入后消失
结论：插入后 fragment 空了。
原因：append 移动 fragment 的子节点，片段本身清空。
解法：理解「移动」语义，需要复用就克隆。

坑 4：textContent 与 innerHTML 混淆
结论：textContent 赋值 '<b>x</b>' 显示字面量，innerHTML 显示粗体。
原因：textContent 转义，innerHTML 解析。
解法：纯文本用 textContent，HTML 用 innerHTML（注意安全）。

坑 5：Shadow DOM 样式泄漏
结论：shadow 内样式不影响外部，反之也难。
原因：样式隔离是 shadow DOM 特性。
解法：需要全局样式用 CSS 变量穿透，或 :host 定制。
```

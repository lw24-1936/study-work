## 概述

文件上传是前端把本地文件（图片、视频、文档）发送到服务端的过程，涉及四个核心概念：File（用户选择的文件）、Blob（二进制数据块）、FormData（表单数据容器）、Multipart（多部分编码格式）。理解它们的关系是做好上传功能的基础。

```text
文件上传的四个核心概念：
1. File —— 用户通过 input/file 选择或拖拽得到的文件对象
2. Blob —— 不可变的二进制数据块，File 继承自它
3. FormData —— 组装上传数据的容器，可混合文件与普通字段
4. Multipart —— multipart/form-data 编码，请求体的分块格式
```

```js
// 一次最简单的上传
const input = document.querySelector('input[type="file"]');
input.addEventListener('change', async () => {
  const file = input.files[0];
  const formData = new FormData();
  formData.append('file', file);
  await fetch('/api/upload', { method: 'POST', body: formData });
});
```

## File

File 对象表示用户选择的文件，通过 input 的 files 属性或拖拽事件的 dataTransfer.files 获取。它继承自 Blob，额外携带文件名（name）、大小（size）、类型（type）、最后修改时间（lastModified）等元信息。

```js
// 从 input 或拖拽获取 File 对象
const input = document.querySelector('input[type="file"]');
input.addEventListener('change', () => {
  const file = input.files[0];
  console.log('文件名:', file.name);
  console.log('大小:', file.size, 'bytes');
  console.log('类型:', file.type);          // 如 image/png
  console.log('最后修改:', new Date(file.lastModified));
});

// 拖拽获取
dropZone.addEventListener('drop', (e) => {
  e.preventDefault();
  const files = e.dataTransfer.files;        // FileList
  console.log('拖入', files.length, '个文件');
});
```

```text
File 的要点：
1. 来源 —— input.files 或 dataTransfer.files
2. 元信息 —— name/size/type/lastModified
3. 继承 Blob —— 拥有 Blob 的全部方法（slice 等）
4. FileList —— 类数组对象，可用 Array.from 转数组
```

## Blob

Blob（Binary Large Object）是不可变的二进制数据块，File 是其子类。Blob 可以手动创建（new Blob）、切片（slice）、读取（arrayBuffer/text），也用于生成 URL（createObjectURL）和拼接文件。

```js
// 创建、切片、读取 Blob
const blob = new Blob(['hello world'], { type: 'text/plain' });
console.log('大小:', blob.size);

const slice = blob.slice(0, 5);              // 切片
slice.text().then(t => console.log('切片内容:', t)); // 'hello'

// 生成可访问的 URL
const url = URL.createObjectURL(blob);
console.log('blob url:', url);
URL.revokeObjectURL(url);                     // 用完释放
```

```text
Blob 的要点：
1. 不可变 —— 创建后内容不变，切片/拼接生成新 Blob
2. slice —— 大文件切片的基础（见 97.2 大文件）
3. createObjectURL —— 生成内存 URL，用于预览/下载
4. 读内容 —— text()/arrayBuffer()/stream() 异步读取
```

## FormData

FormData 是组装上传数据的容器，用 append 添加字段，支持混合文件与普通文本。它可以直接作为 fetch/XMLHttpRequest 的 body，浏览器会自动设置 Content-Type 为 multipart/form-data（含 boundary）。

```js
// FormData 组装上传数据
const formData = new FormData();
formData.append('file', file);           // 文件
formData.append('title', '我的头像');     // 普通字段
formData.append('tags', 'a');            // 同名多值
formData.append('tags', 'b');

// 读取内容（注意：无法直接读取文件二进制，只能遍历）
for (const [key, value] of formData.entries()) {
  console.log(key, value instanceof File ? value.name : value);
}

// 作为请求体
fetch('/api/upload', { method: 'POST', body: formData });
```

```text
FormData 的要点：
1. append —— 添加字段，同名可多值
2. 混合 —— 文件与普通字段共存
3. 自动编码 —— 浏览器自动设 multipart/form-data 与 boundary
4. 读取限制 —— 只读键值，不读文件二进制内容
```

## Multipart

Multipart 是 HTTP 请求体的「多部分」编码格式，multipart/form-data 用 boundary（边界字符串）把多个字段分隔成独立部分，每部分有自己的 Content-Disposition 头。文件上传正是用这种格式把文件二进制和其他字段一起发送。

```text
multipart/form-data 请求体结构：
--boundary
Content-Disposition: form-data; name="title"

我的头像
--boundary
Content-Disposition: form-data; name="file"; filename="avatar.png"
Content-Type: image/png

<文件二进制>
--boundary--
```

```js
// 手动构造 multipart 请求体（理解格式用，实际交给 FormData）
function buildMultipart(fields, file) {
  const boundary = '----MyBoundary' + Math.random().toString(16).slice(2);
  const parts = [];
  for (const [name, value] of Object.entries(fields)) {
    parts.push(`--${boundary}\r\nContent-Disposition: form-data; name="${name}"\r\n\r\n${value}\r\n`);
  }
  parts.push(`--${boundary}\r\nContent-Disposition: form-data; name="file"; filename="${file.name}"\r\nContent-Type: ${file.type}\r\n\r\n`);
  const body = new Blob([...parts.map(p => new TextEncoder().encode(p)), file, new TextEncoder().encode(`\r\n--${boundary}--\r\n`)]);
  return { body, contentType: `multipart/form-data; boundary=${boundary}` };
}
```

```text
Multipart 的要点：
1. boundary —— 分隔各部分的边界字符串
2. 每部分独立 —— 各自带 Content-Disposition 头
3. 文件部分 —— 含 filename 与 Content-Type
4. 结尾 —— 以 boundary + -- 结束
```

## 应用场景实战

### 场景一：带进度条的文件上传

```js
// 用 XMLHttpRequest 获取上传进度，展示进度条
function uploadWithProgress(file, onProgress) {
  const xhr = new XMLHttpRequest();
  xhr.open('POST', '/api/upload');

  xhr.upload.onprogress = (e) => {
    if (e.lengthComputable) {
      const percent = (e.loaded / e.total) * 100;
      onProgress(percent);
    }
  };

  const formData = new FormData();
  formData.append('file', file);
  xhr.send(formData);
  return xhr;
}

uploadWithProgress(file, (p) => {
  progressBar.style.width = p + '%';
});
```

### 场景二：图片选择即时预览

```js
// 选择图片后立即用 createObjectURL 预览，再上传
const input = document.querySelector('input[type="file"]');
const preview = document.querySelector('#preview');

input.addEventListener('change', () => {
  const file = input.files[0];
  if (!file.type.startsWith('image/')) return;

  const url = URL.createObjectURL(file);
  preview.src = url;
  preview.onload = () => URL.revokeObjectURL(url);  // 显示后释放内存 URL

  // 同时准备上传
  const fd = new FormData();
  fd.append('file', file);
  fetch('/api/upload', { method: 'POST', body: fd });
});
```

## 最佳实践与踩坑记录

### 最佳实践

1. 用 FormData 组装上传，别手动拼 multipart（易出错且难维护）
2. 上传进度用 XHR 的 upload.onprogress，fetch 不支持上传进度
3. 预览用 createObjectURL，显示完及时 revokeObjectURL 释放内存
4. 前端先校验文件类型与大小，再发起上传，减少无效请求
5. 拖拽区要 preventDefault 阻止浏览器默认打开文件

### 踩坑记录

```text
坑 1：fetch 拿不到上传进度
结论：用 fetch 上传大文件，进度条不动。
原因：fetch 不支持上传进度，只有 XHR 有 upload.onprogress。
解法：需要进度用 XMLHttpRequest，或 fetch + Streams（复杂）。

坑 2：手动设置 Content-Type 导致 boundary 丢失
结论：手动设 Content-Type 后服务端解析失败。
原因：multipart 的 boundary 由浏览器自动生成，手动设会丢 boundary。
解法：用 FormData 让浏览器自动设，别手动写 Content-Type。

坑 3：忘记 revokeObjectURL
结论：反复预览图片，内存持续上涨。
原因：createObjectURL 生成的 blob URL 占用内存，不释放会累积。
解法：图片加载完成（onload）后 revokeObjectURL。

坑 4：上传超大文件导致请求超时
结论：几百 MB 的文件一次上传，超时或内存溢出。
原因：一次性读入并发送整个文件。
解法：大文件走分片上传（见 97.2 大文件）。

坑 5：拖拽区没阻止默认行为
结论：拖文件到页面上，浏览器直接打开该文件离开页面。
原因：没在 dragover/drop 里 preventDefault。
解法：dragover 和 drop 都调 e.preventDefault()。
```

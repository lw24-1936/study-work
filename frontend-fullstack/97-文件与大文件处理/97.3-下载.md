## 概述

文件下载是前端把服务端数据保存到本地磁盘的过程，核心机制有四种：Blob Download（把数据转成 Blob 再触发保存）、Stream Download（流式读取响应体，边下载边处理）、Range Request（分段请求文件）、Resume Download（断点续传下载）。大文件下载靠流式与 Range 配合实现。

```text
四种下载机制：
1. Blob Download —— 拿到完整数据 -> 转 Blob -> 触发浏览器保存
2. Stream Download —— fetch 响应体流式读取，边收边写/边处理
3. Range Request —— HTTP Range 头分段请求文件的某部分
4. Resume Download —— 记录已下载字节，断点续传
```

```js
// 最简单的下载：a 标签 + download 属性
function downloadByUrl(url, filename) {
  const a = document.createElement('a');
  a.href = url;
  a.download = filename;   // 触发下载而非跳转
  a.click();
}
```

## Blob Download

Blob Download 是把数据（字符串、二进制、接口返回）转成 Blob，再用 createObjectURL 生成链接触发下载。它适用于导出 CSV/JSON、下载接口返回的文件流、前端生成的文件等场景。

```js
// 1. 前端生成 CSV 并下载
function downloadCSV(rows) {
  const csv = rows.map(r => r.join(',')).join('\n');
  const blob = new Blob(['\uFEFF' + csv], { type: 'text/csv;charset=utf-8' });
  const url = URL.createObjectURL(blob);
  const a = document.createElement('a');
  a.href = url;
  a.download = 'export.csv';
  a.click();
  URL.revokeObjectURL(url);   // 触发后释放
}

// 2. 下载接口返回的二进制（需先读成 blob）
async function downloadFromApi(filename) {
  const res = await fetch(`/api/download?name=${filename}`);
  const blob = await res.blob();
  const url = URL.createObjectURL(blob);
  const a = document.createElement('a');
  a.href = url;
  a.download = filename;
  a.click();
  URL.revokeObjectURL(url);
}
```

```text
Blob Download 的要点：
1. 数据转 Blob —— 字符串/数组/ArrayBuffer 都能 new Blob
2. createObjectURL —— 生成临时 URL 触发下载
3. revoke —— 触发后释放 URL，防内存累积
4. BOM —— 中文 CSV 加 \uFEFF 防 Excel 乱码
```

## Stream Download

Stream Download 用 fetch 拿到响应体的 ReadableStream，流式读取，边接收边处理（写文件、解压、处理分块），不必等整个文件下载完才处理。这在大文件下载、实时解析场景非常有用。

```js
// 流式读取响应体，边下载边统计进度
async function streamDownload(url, onProgress) {
  const res = await fetch(url);
  const total = Number(res.headers.get('Content-Length'));
  const reader = res.body.getReader();
  const chunks = [];
  let received = 0;

  while (true) {
    const { done, value } = await reader.read();
    if (done) break;
    chunks.push(value);
    received += value.length;
    onProgress(received / total);
  }

  // 拼成完整 Blob 后保存
  const blob = new Blob(chunks);
  const url2 = URL.createObjectURL(blob);
  const a = document.createElement('a');
  a.href = url2;
  a.download = 'file.bin';
  a.click();
  URL.revokeObjectURL(url2);
}
```

```text
Stream Download 的要点：
1. ReadableStream —— res.body 是流，getReader 逐块读
2. 边收边处理 —— 不等全部完成，实时处理分块
3. 进度 —— 按已收字节 / Content-Length 算
4. 内存友好 —— 大文件不必一次性读入内存
```

## Range Request

Range Request 用 HTTP Range 请求头分段获取文件的某部分字节（如 bytes=0-1023），服务端返回 206 Partial Content。它用于视频拖动、分段下载、断点续传，是「只取需要的部分」的机制。

```js
// 分段请求文件的某一部分
async function fetchRange(url, start, end) {
  const res = await fetch(url, {
    headers: { Range: `bytes=${start}-${end}` },
  });
  console.log('状态:', res.status);           // 206 Partial Content
  console.log('范围:', res.headers.get('Content-Range'));
  const blob = await res.blob();
  return blob;                                // 只包含请求的那一段
}

// 检查服务端是否支持 Range
async function supportsRange(url) {
  const res = await fetch(url, { headers: { Range: 'bytes=0-0' } });
  return res.status === 206;
}
```

```text
Range Request 的要点：
1. Range 头 —— bytes=start-end，指定要哪段
2. 206 响应 —— Partial Content，带 Content-Range
3. 用途 —— 视频拖动、分段下载、断点续传
4. 依赖服务端 —— 服务端需支持 Range，否则返回 200 全量
```

## Resume Download

Resume Download（断点续传下载）利用 Range 请求，记录已下载的字节数，中断后从断点继续请求剩余部分，把新数据追加到已下载内容之后，最终拼成完整文件。

```js
// 断点续传下载：记录已下载字节，中断后从断点继续
async function resumeDownload(url) {
  const CHUNK = 1024 * 1024;          // 每次 1MB
  const chunks = [];
  let start = 0;
  let total = null;

  // 首次请求拿总大小
  const head = await fetch(url);
  total = Number(head.headers.get('Content-Length'));

  while (start < total) {
    const end = Math.min(start + CHUNK - 1, total - 1);
    const res = await fetch(url, {
      headers: { Range: `bytes=${start}-${end}` },
    });
    if (res.status !== 206) throw new Error('服务端不支持 Range');
    chunks.push(await res.arrayBuffer());
    start += CHUNK;
    onProgress(start / total);
  }

  // 合并所有段，保存完整文件
  const blob = new Blob(chunks);
  const a = document.createElement('a');
  a.href = URL.createObjectURL(blob);
  a.download = 'file.bin';
  a.click();
}
```

```text
Resume Download 的要点：
1. 分段请求 —— 用 Range 每次取一段
2. 记录进度 —— start 变量保存已下载字节
3. 断点恢复 —— 中断后从 start 继续，不重头下
4. 合并 —— 各段拼成完整 Blob 再保存
```

## 应用场景实战

### 场景一：带进度条的大文件下载

```js
// 流式下载 + 进度显示 + 保存
async function downloadWithProgress(url, filename, progressEl) {
  const res = await fetch(url);
  const total = Number(res.headers.get('Content-Length'));
  const reader = res.body.getReader();
  const chunks = [];
  let received = 0;

  while (true) {
    const { done, value } = await reader.read();
    if (done) break;
    chunks.push(value);
    received += value.length;
    progressEl.style.width = ((received / total) * 100).toFixed(1) + '%';
  }

  const blob = new Blob(chunks);
  const a = document.createElement('a');
  a.href = URL.createObjectURL(blob);
  a.download = filename;
  a.click();
  URL.revokeObjectURL(a.href);
}
```

### 场景二：导出 Excel（CSV）+ 图片下载

```js
// 1. 导出表格为 CSV（Blob Download）
function exportTable(tableId) {
  const rows = [...document.querySelectorAll(`#${tableId} tr`)].map(tr =>
    [...tr.querySelectorAll('th,td')].map(td => td.textContent.trim())
  );
  const csv = rows.map(r => r.join(',')).join('\n');
  const blob = new Blob(['\uFEFF' + csv], { type: 'text/csv;charset=utf-8' });
  const a = document.createElement('a');
  a.href = URL.createObjectURL(blob);
  a.download = 'table.csv';
  a.click();
  URL.revokeObjectURL(a.href);
}

// 2. 下载当前页面截图（canvas 转 Blob）
function downloadSnapshot(canvas) {
  canvas.toBlob((blob) => {
    const a = document.createElement('a');
    a.href = URL.createObjectURL(blob);
    a.download = 'snapshot.png';
    a.click();
    URL.revokeObjectURL(a.href);
  }, 'image/png');
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. Blob 下载后及时 revokeObjectURL，防内存累积
2. 大文件用流式读取 + 进度显示，别一次性读入内存
3. 中文 CSV 加 \uFEFF BOM，避免 Excel 打开乱码
4. 断点续传前先探服务端是否支持 Range（206 判断）
5. 导出文件名做编码处理，防中文文件名乱码
6. Range 请求分段大小适中，太大占内存、太小请求多

### 踩坑记录

```text
坑 1：中文文件名下载乱码
结论：下载的文件名中文变成乱码或 %E4%B8%AD。
原因：文件名未做 URL 编码，Content-Disposition 编码不一致。
解法：服务端用 encodeURIComponent + 正确编码头，前端 download 属性用原名。

坑 2：下载接口返回 JSON 报错也触发保存
结论：下载失败时把错误 JSON 存成了文件。
原因：未检查响应状态/类型，直接把响应当文件保存。
解法：先判断 res.ok 和 Content-Type，失败时抛错提示。

坑 3：大文件下载内存溢出
结论：下载几个 GB 的文件页面崩溃。
原因：一次性 res.blob() 或 arrayBuffer 读入整个文件。
解法：流式读取 res.body，边收边写，或分段 Range 下载。

坑 4：服务端不支持 Range 却用分段下载
结论：分段请求返回 200 全量，下载反而重复。
原因：服务端不识别 Range 头，每次返回完整文件。
解法：先探 Range 支持（请求 bytes=0-0 看是否 206），不支持则退回整文件。

坑 5：忘记 revokeObjectURL
结论：批量导出多次后内存上涨。
原因：每次 createObjectURL 生成的 URL 未释放。
解法：a.click() 触发后立即 revokeObjectURL(url)。
```

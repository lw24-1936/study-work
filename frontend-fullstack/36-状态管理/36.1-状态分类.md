## 概述

前端状态可按「来源、作用域、生命周期」分类。正确分类是选对状态管理方案的前提：局部状态用组件 state，全局状态用 Redux/Zustand/Pinia，服务端状态用 TanStack Query 等。分类不清会导致状态冗余、同步困难和性能问题。

```text
前端状态的六大分类：
1. Local State —— 组件内部状态（useState/ref）
2. Global State —— 跨组件共享的应用状态（用户、主题）
3. Server State —— 来自服务端的数据（列表、详情）
4. URL State —— 体现在 URL 上的状态（查询参数、路由）
5. Form State —— 表单输入、校验、提交状态
6. Cache State —— 缓存数据（接口缓存、计算结果）
```

```js
// 不同类型状态的典型载体
const [isOpen, setOpen] = useState(false); // Local
useStore((s) => s.user); // Global
useQuery(['users'], fetchUsers); // Server
useSearchParams(); // URL
useForm(); // Form
localStorage.getItem('theme'); // Cache
```

## Local State

局部状态是单个组件内部使用的状态，生命周期与组件一致，用组件自身的 state 管理即可，无需引入全局方案。

```js
import { useState } from 'react';

function Dropdown() {
  const [open, setOpen] = useState(false); // 局部状态
  return (
    <div>
      <button onClick={() => setOpen(!open)}>切换</button>
      {open && <ul>...</ul>}
    </div>
  );
}
```

```js
// Vue 局部状态
import { ref } from 'vue';
const visible = ref(false); // 组件内 ref
```

```text
Local State 判断标准：
1. 只被当前组件使用
2. 不跨组件共享
3. 组件卸载后无需保留
符合以上就留在组件内，不要提升为全局。
```

## Global State

全局状态是跨组件共享的应用级状态，如登录用户、主题、购物车、全局配置等，需要集中管理避免 Props 逐层透传。

```js
// React Context（轻量全局）
const UserContext = createContext(null);
function App() {
  const [user, setUser] = useState(null);
  return (
    <UserContext.Provider value={{ user, setUser }}>
      <Children />
    </UserContext.Provider>
  );
}
```

```js
// Zustand（更完善的全局方案）
import { create } from 'zustand';

const useUserStore = create((set) => ({
  user: null,
  login: (u) => set({ user: u }),
  logout: () => set({ user: null }),
}));
```

```text
Global State 判断标准：
1. 多个组件读写
2. 应用生命周期内长期存在
3. 跨页面/模块共享
满足条件才用全局方案，避免滥用。
```

## Server State

服务端状态是从后端接口获取的数据，具有「异步获取、可能过期、需要重试、跨组件共享」等特点。它本质上和服务端是「同一份数据」，前端只是缓存副本。

```js
// TanStack Query 管理服务端状态
import { useQuery } from '@tanstack/react-query';

function UserList() {
  const { data, isLoading, error } = useQuery({
    queryKey: ['users'],
    queryFn: () => fetch('/api/users').then((r) => r.json()),
  });
  if (isLoading) return <p>加载中...</p>;
  return <ul>{data.map((u) => <li key={u.id}>{u.name}</li>)}</ul>;
}
```

```text
Server State 特点：
1. 异步获取，有加载/错误/成功状态
2. 会过期（stale），需要刷新
3. 与后端共享所有权，前端是缓存
4. 需要去重、重试、乐观更新等
适合用专用库（TanStack Query/SWR/RTK Query），不要塞进手写全局 store。
```

## URL State

URL 状态是反映在地址栏的状态，如路由路径、查询参数、分页、筛选条件等。它可分享、可收藏、可前进后退，是「持久化在 URL 上的全局状态」。

```js
import { useSearchParams } from 'react-router-dom';

function SearchPage() {
  const [params, setParams] = useSearchParams();
  const page = params.get('page') || '1';
  const keyword = params.get('q') || '';

  const setPage = (p) => {
    params.set('page', p);
    setParams(params);
  };
}
```

```text
URL State 的价值：
1. 可分享 —— 复制链接即可还原状态
2. 可收藏 —— 用户保存当前视图
3. 可前进后退 —— 浏览器原生支持
分页、筛选、搜索词等建议放 URL。
```

## Form State

表单状态包括输入值、校验错误、脏标记（dirty）、触摸标记（touched）、提交状态等。表单状态变化频繁、校验逻辑复杂，适合专用表单库管理。

```js
import { useForm } from 'react-hook-form';

function LoginForm() {
  const { register, handleSubmit, formState } = useForm();
  const { errors, isDirty, isSubmitting } = formState;

  const onSubmit = (data) => console.log(data);
  return (
    <form onSubmit={handleSubmit(onSubmit)}>
      <input {...register('email', { required: '必填' })} />
      {errors.email && <span>{errors.email.message}</span>}
      <button disabled={isSubmitting}>提交</button>
    </form>
  );
}
```

```text
Form State 特点：
1. 高频变化（每次键入）
2. 状态维度多（值、错误、dirty、touched）
3. 校验与提交逻辑复杂
4. 通常不需要全局共享
```

## Cache State

缓存状态是用于加速的派生数据副本，如接口响应缓存、计算结果缓存、localStorage 持久化的偏好等。

```js
// 接口响应缓存（TanStack Query 内置）
useQuery({ queryKey: ['user', 1], queryFn: fetchUser, staleTime: 60_000 });

// 计算结果缓存
import { useMemo } from 'react';
const filtered = useMemo(() => list.filter((x) => x.active), [list]);

// 本地持久化
localStorage.setItem('theme', 'dark');
const theme = localStorage.getItem('theme');
```

```text
Cache State 注意：
1. 缓存需要失效策略（staleTime、ttl、手动失效）
2. 缓存与服务端数据可能不一致，需处理过期
3. 本地缓存要考虑序列化与版本
```

## 应用场景实战

### 场景一：列表页的状态分层

```js
function ProductListPage() {
  // URL State：分页与筛选（可分享）
  const [params, setParams] = useSearchParams();
  const page = Number(params.get('page')) || 1;
  const category = params.get('category') || 'all';

  // Server State：列表数据（缓存 + 自动刷新）
  const { data } = useQuery({
    queryKey: ['products', page, category],
    queryFn: () => fetchProducts({ page, category }),
  });

  // Local State：仅本页使用的弹窗
  const [previewId, setPreviewId] = useState(null);

  return <ProductList data={data} onPreview={setPreviewId} />;
}
```

### 场景二：购物车（Global + Cache）

```js
const useCartStore = create(
  persist(
    (set) => ({
      items: [],
      add: (item) => set((s) => ({ items: [...s.items, item] })),
      remove: (id) => set((s) => ({ items: s.items.filter((i) => i.id !== id) })),
    }),
    { name: 'cart' }, // 持久化到 localStorage（Cache）
  ),
);
```

## 最佳实践与踩坑记录

### 最佳实践

1. 先分类再选方案：Local 用组件 state，Server 用查询库，Global 用全局 store
2. URL 承载可分享状态（分页、筛选、搜索词）
3. 服务端数据不要手动同步进全局 store，交给 TanStack Query
4. 避免状态提升过度：只在真正共享时才提升
5. 表单状态用表单库，别手写一堆 useState 拼校验

### 踩坑记录

```text
坑 1：把所有状态塞进 Redux
结论：局部状态进全局 store，代码臃肿、重渲染频繁。
原因：未区分状态类型，滥用全局方案。
解法：局部状态留组件，只有共享状态才进全局 store。

坑 2：服务端数据手动写进 store
结论：缓存过期、重复请求、同步逻辑复杂。
原因：把 Server State 当 Global State 管理。
解法：用 TanStack Query 等专用库管理服务端状态。

坑 3：筛选/分页不放 URL
结论：刷新后状态丢失，无法分享链接。
原因：可分享状态未持久化到 URL。
解法：分页、筛选、搜索词用 URL 参数。

坑 4：表单状态放全局 store
结论：键入一次触发全局更新，性能差且难维护。
原因：高频局部状态错误提升。
解法：表单状态用表单库或组件局部管理。

坑 5：缓存没有失效策略
结论：展示过期数据或反复请求。
原因：缓存未设 staleTime/失效机制。
解法：设置合理的 staleTime、缓存时间，主动失效。
```

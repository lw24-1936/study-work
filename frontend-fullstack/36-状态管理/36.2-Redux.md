## 概述

Redux 是可预测的状态容器，遵循「单一数据源、状态只读、纯函数修改」三大原则。通过 Action 描述「发生了什么」，Reducer 纯函数计算「新状态」，Store 集中存储状态。Redux Toolkit 是官方推荐写法，大幅简化样板代码。

```text
Redux 核心组成：
1. Store —— 集中存储状态的单一数据源
2. Action —— 描述变更的普通对象（type + payload）
3. Reducer —— 纯函数，根据 action 计算新状态
4. Dispatch —— 派发 action 触发状态更新
5. Middleware —— 拦截 dispatch，处理异步/日志等
6. Selector —— 从 store 中选取数据的函数
7. Redux Toolkit —— 官方工具集，简化 Redux 开发
8. RTK Query —— 内建的数据获取与缓存方案
```

```js
import { configureStore, createSlice } from '@reduxjs/toolkit';

const counterSlice = createSlice({
  name: 'counter',
  initialState: { value: 0 },
  reducers: {
    increment: (state) => { state.value += 1; },
    addBy: (state, action) => { state.value += action.payload; },
  },
});

const store = configureStore({ reducer: { counter: counterSlice.reducer } });
store.dispatch(counterSlice.actions.increment());
console.log(store.getState()); // { counter: { value: 1 } }
```

## Store

Store 是应用的单一数据源，集中保存整棵状态树。用 `configureStore` 创建，内部组合多个 reducer，并提供 getState、dispatch、subscribe 方法。

```js
import { configureStore } from '@reduxjs/toolkit';
import counterReducer from './counterSlice';
import userReducer from './userSlice';

const store = configureStore({
  reducer: {
    counter: counterReducer,
    user: userReducer,
  },
  middleware: (getDefaultMiddleware) => getDefaultMiddleware(),
});

store.getState(); // 读取整个状态树
store.dispatch({ type: 'counter/increment' }); // 派发
const unsub = store.subscribe(() => console.log('状态变化'));
unsub(); // 取消订阅
```

```text
Store 三原则：
1. 单一数据源 —— 整个应用一个 store
2. 状态只读 —— 只能通过 dispatch 变更
3. 纯函数修改 —— reducer 必须是纯函数
```

## Action

Action 是描述「发生了什么」的普通对象，必须有 `type` 字段，可携带 `payload`。Redux Toolkit 的 createSlice 会自动生成 action creator。

```js
// 普通 action
const action = { type: 'counter/add', payload: 5 };

// action creator
const addBy = (amount) => ({ type: 'counter/add', payload: amount });

// Redux Toolkit 自动生成
counterSlice.actions.addBy(5); // { type: 'counter/addBy', payload: 5 }
```

```text
Action 约定：
1. type 必须唯一，通常用 'slice/action' 命名
2. payload 放变更数据
3. 用 action creator 生成，避免手写字符串
```

## Reducer

Reducer 是纯函数，接收当前状态和 action，返回新状态。不能有副作用，不能直接修改原状态（传统写法需返回新对象）。

```js
// 传统 reducer（不可变更新）
function counterReducer(state = { value: 0 }, action) {
  switch (action.type) {
    case 'counter/increment':
      return { ...state, value: state.value + 1 };
    case 'counter/add':
      return { ...state, value: state.value + action.payload };
    default:
      return state;
  }
}
```

```js
// Redux Toolkit：createSlice 内部用 Immer 允许「可变」写法
import { createSlice } from '@reduxjs/toolkit';

const counterSlice = createSlice({
  name: 'counter',
  initialState: { value: 0 },
  reducers: {
    increment(state) {
      state.value += 1; // Immer 自动转成不可变更新
    },
    addBy(state, action) {
      state.value += action.payload;
    },
  },
});
```

```text
Reducer 要点：
1. 纯函数：相同输入必得相同输出
2. 不直接改原状态（Immer 除外）
3. 不执行副作用（请求、随机数、时间）
4. 未知 action 返回原状态
```

## Dispatch

Dispatch 是触发状态更新的唯一方式，把 action 派发给 store，store 交给 reducer 计算新状态。

```js
store.dispatch({ type: 'counter/increment' });
store.dispatch(counterSlice.actions.addBy(10));
```

```js
// React 中使用
import { useDispatch } from 'react-redux';

function Counter() {
  const dispatch = useDispatch();
  return (
    <button onClick={() => dispatch(counterSlice.actions.increment())}>
      +1
    </button>
  );
}
```

```text
Dispatch 流程：
dispatch(action) → middleware 链 → reducer → 生成新状态 → 通知订阅者
```

## Middleware

Middleware 在 dispatch 和 reducer 之间拦截 action，用于日志、异步请求、错误处理等。Redux Thunk 是最常见的异步中间件。

```js
// thunk：异步 action creator
const fetchUser = (id) => async (dispatch, getState) => {
  dispatch({ type: 'user/loading' });
  try {
    const user = await api.getUser(id);
    dispatch({ type: 'user/success', payload: user });
  } catch (err) {
    dispatch({ type: 'user/error', payload: err.message });
  }
};

// 派发 thunk
store.dispatch(fetchUser(1));
```

```js
// 自定义中间件（日志）
const logger = (store) => (next) => (action) => {
  console.log('dispatching', action);
  const result = next(action);
  console.log('next state', store.getState());
  return result;
};
```

```text
常见中间件：
redux-thunk —— 处理异步 action（函数形式）
redux-saga —— 用 generator 管理副作用
redux-logger —— 开发日志
RTK 默认已包含 thunk。
```

## Selector

Selector 是从 store 中选取派生数据的函数，配合 useMemo/Reselect 缓存计算结果，避免重复计算。

```js
import { useSelector } from 'react-redux';

// 基本 selector
const value = useSelector((state) => state.counter.value);

// 派生 selector（配合 createSelector 缓存）
import { createSelector } from '@reduxjs/toolkit';

const selectItems = (state) => state.cart.items;
const selectTotal = createSelector([selectItems], (items) =>
  items.reduce((sum, i) => sum + i.price, 0),
);

const total = useSelector(selectTotal);
```

```text
Selector 要点：
1. 只选需要的片段，避免过度订阅
2. 用 createSelector 缓存派生计算
3. 避免每次 render 新建 selector 导致缓存失效
```

## Redux Toolkit

Redux Toolkit（RTK）是官方推荐的工具集，内置 createSlice、configureStore、createAsyncThunk、Immer 等，大幅减少样板代码。

```js
import { createSlice, createAsyncThunk, configureStore } from '@reduxjs/toolkit';

// 异步 thunk
export const fetchUsers = createAsyncThunk('users/fetch', async () => {
  const res = await fetch('/api/users');
  return res.json();
});

const usersSlice = createSlice({
  name: 'users',
  initialState: { list: [], status: 'idle', error: null },
  reducers: {},
  extraReducers: (builder) => {
    builder
      .addCase(fetchUsers.pending, (state) => { state.status = 'loading'; })
      .addCase(fetchUsers.fulfilled, (state, action) => {
        state.status = 'succeeded';
        state.list = action.payload;
      })
      .addCase(fetchUsers.rejected, (state, action) => {
        state.status = 'failed';
        state.error = action.error.message;
      });
  },
});

const store = configureStore({ reducer: { users: usersSlice.reducer } });
```

```text
RTK 优点：
1. createSlice 自动生成 action + reducer
2. Immer 支持可变写法，自动不可变更新
3. createAsyncThunk 标准化异步流程
4. configureStore 默认配置好中间件与 DevTools
```

## RTK Query

RTK Query 是 RTK 内建的数据获取与缓存方案，管理服务端状态：请求、缓存、失效、重试，避免手写异步逻辑。

```js
import { createApi, fetchBaseQuery } from '@reduxjs/toolkit/query/react';

export const api = createApi({
  reducerPath: 'api',
  baseQuery: fetchBaseQuery({ baseUrl: '/api' }),
  tagTypes: ['User'],
  endpoints: (builder) => ({
    getUsers: builder.query({
      query: () => '/users',
      providesTags: ['User'],
    }),
    addUser: builder.mutation({
      query: (body) => ({ url: '/users', method: 'POST', body }),
      invalidatesTags: ['User'], // 失效后自动重新请求
    }),
  }),
});

export const { useGetUsersQuery, useAddUserMutation } = api;
```

```js
function UserList() {
  const { data, isLoading, error } = useGetUsersQuery();
  const [addUser] = useAddUserMutation();
  return <button onClick={() => addUser({ name: '新用户' })}>添加</button>;
}
```

## 应用场景实战

### 场景一：购物车（Slice + Selector）

```js
const cartSlice = createSlice({
  name: 'cart',
  initialState: { items: [] },
  reducers: {
    add: (state, action) => { state.items.push(action.payload); },
    remove: (state, action) => {
      state.items = state.items.filter((i) => i.id !== action.payload);
    },
  },
});

const selectTotal = createSelector(
  [(state) => state.cart.items],
  (items) => items.reduce((s, i) => s + i.price, 0),
);
```

### 场景二：用户列表（RTK Query 自动缓存）

```js
const { data: users, isLoading } = useGetUsersQuery();
// 缓存自动管理，多个组件共享，重复请求自动去重
```

## 最佳实践与踩坑记录

### 最佳实践

1. 用 Redux Toolkit，不要手写传统 Redux 样板
2. 服务端数据用 RTK Query，不用手写 thunk 管理请求
3. Selector 只订阅需要的片段，避免整棵状态树订阅
4. 派生数据用 createSelector 缓存
5. 状态结构扁平化，避免深层嵌套

### 踩坑记录

```text
坑 1：reducer 直接修改原状态
结论：状态变化不触发订阅，UI 不更新。
原因：违反不可变更新，Redux 靠引用变化判断更新。
解法：传统写法返回新对象；RTK 用 Immer 可变写法。

坑 2：reducer 里写副作用
结论：状态不可预测、难以调试。
原因：reducer 必须是纯函数。
解法：副作用放 middleware/thunk，reducer 只计算状态。

坑 3：selector 过度订阅
结论：无关状态变化导致组件频繁重渲染。
原因：订阅了整棵状态树或过大片段。
解法：细粒度 selector + createSelector。

坑 4：异步请求状态手写
结论：loading/error 状态管理混乱。
原因：手动维护请求状态易漏。
解法：用 RTK Query 或 createAsyncThunk。

坑 5：忘记 invalidatesTags
结论：数据变更后列表不刷新。
原因：缓存未失效，仍返回旧数据。
解法：mutation 里正确设置 invalidatesTags。
```

## 概述

TanStack Query（原 React Query）是服务端状态管理库，专注解决「请求、缓存、同步、失效」问题。它以 queryKey 为缓存键，自动管理加载/错误状态、缓存与过期、后台刷新、重试与乐观更新，让服务端数据不再手动塞进全局 store。

```text
TanStack Query 核心概念：
1. Query —— 读请求（useQuery），按 key 缓存
2. Mutation —— 写请求（useMutation），支持失效与乐观更新
3. Cache —— 以 queryKey 为键的缓存，组件共享
4. Stale —— 过期状态，过期后触发后台重新获取
5. Refetch —— 重新获取数据
6. Retry —— 失败自动重试
7. Optimistic Update —— 乐观更新，先改 UI 再同步
8. Infinite Query —— 无限滚动/分页加载
```

```js
import { useQuery } from '@tanstack/react-query';

function Users() {
  const { data, isLoading, error } = useQuery({
    queryKey: ['users'],
    queryFn: () => fetch('/api/users').then((r) => r.json()),
  });
  if (isLoading) return <p>加载中...</p>;
  if (error) return <p>出错了</p>;
  return <ul>{data.map((u) => <li key={u.id}>{u.name}</li>)}</ul>;
}
```

## Query

Query 是读操作，`useQuery` 接收 queryKey（缓存键）和 queryFn（获取函数），返回数据与状态。

```js
import { useQuery } from '@tanstack/react-query';

const fetchUser = async ({ queryKey }) => {
  const [, id] = queryKey; // ['user', id]
  return fetch(`/api/users/${id}`).then((r) => r.json());
};

function UserDetail({ id }) {
  const { data, isLoading, isError, isFetching, refetch } = useQuery({
    queryKey: ['user', id],
    queryFn: fetchUser,
    enabled: !!id, // 条件启用
    staleTime: 60_000,
  });

  return <div>{isLoading ? '加载中' : data.name}</div>;
}
```

```text
useQuery 返回的状态：
isLoading —— 首次加载中
isFetching —— 任意获取中（含后台刷新）
isError / error —— 错误
data —— 数据
refetch —— 手动重新获取
enabled —— 条件启用请求
```

## Mutation

Mutation 是写操作，`useMutation` 处理增删改。返回 mutate 函数和状态，常配合 invalidateQueries 刷新缓存。

```js
import { useMutation, useQueryClient } from '@tanstack/react-query';

function AddUser() {
  const queryClient = useQueryClient();

  const mutation = useMutation({
    mutationFn: (newUser) =>
      fetch('/api/users', {
        method: 'POST',
        body: JSON.stringify(newUser),
      }).then((r) => r.json()),
    onSuccess: () => {
      // 写成功后使 ['users'] 缓存失效，触发重新获取
      queryClient.invalidateQueries({ queryKey: ['users'] });
    },
  });

  return (
    <button onClick={() => mutation.mutate({ name: 'Alice' })} disabled={mutation.isPending}>
      添加
    </button>
  );
}
```

```text
Mutation 状态：
isPending —— 请求进行中
isSuccess / isError —— 结果
variables —— 本次提交的数据
reset —— 重置状态
```

## Cache

Cache 是 queryKey 对应的缓存数据，多个组件共享同一份缓存，相同 key 的请求自动去重，避免重复请求。

```js
// 两个组件使用相同 queryKey，共享缓存，只发一次请求
function A() {
  return useQuery({ queryKey: ['users'], queryFn: fetchUsers });
}
function B() {
  return useQuery({ queryKey: ['users'], queryFn: fetchUsers });
}
```

```js
// 直接操作缓存
import { useQueryClient } from '@tanstack/react-query';

const queryClient = useQueryClient();

// 读取缓存
const cached = queryClient.getQueryData(['users']);

// 写入缓存
queryClient.setQueryData(['users'], newData);

// 手动失效
queryClient.invalidateQueries({ queryKey: ['users'] });
```

```text
Cache 要点：
1. 以 queryKey 为键（数组，可结构化）
2. 默认内存缓存，可配置 gcTime（垃圾回收时间）
3. 相同 key 请求自动去重
```

## Stale

Stale（过期）决定数据是否需要重新获取。数据默认立即过期（staleTime = 0），组件挂载或窗口聚焦时会后台重新获取。设置 staleTime 可延长新鲜期。

```js
useQuery({
  queryKey: ['config'],
  queryFn: fetchConfig,
  staleTime: 5 * 60 * 1000, // 5 分钟内视为新鲜，不重新请求
});
```

```text
Stale 机制：
staleTime = 0（默认）—— 数据立即过期
数据新鲜（fresh）时直接使用缓存，不重新请求
数据过期（stale）时触发后台重新获取（不阻塞 UI）
```

## Refetch

Refetch 是重新获取数据，可手动触发（refetch 函数），或由条件自动触发（挂载、窗口聚焦、网络恢复、间隔轮询）。

```js
function Users() {
  const { data, refetch, isRefetching } = useQuery({
    queryKey: ['users'],
    queryFn: fetchUsers,
    refetchOnWindowFocus: true, // 窗口聚焦重新获取
    refetchInterval: 30_000, // 每 30 秒轮询
    refetchOnMount: true, // 挂载时重新获取
  });

  return (
    <button onClick={() => refetch()} disabled={isRefetching}>
      刷新
    </button>
  );
}
```

```text
自动 Refetch 时机：
1. 组件挂载（数据过期时）
2. 窗口重新聚焦
3. 网络恢复
4. 定时轮询（refetchInterval）
```

## Retry

Retry 是请求失败后自动重试。默认重试 3 次（指数退避），可配置重试次数、条件与延迟。

```js
useQuery({
  queryKey: ['users'],
  queryFn: fetchUsers,
  retry: 3, // 失败重试 3 次
  retryDelay: (attempt) => Math.min(1000 * 2 ** attempt, 30000), // 指数退避
  // 按错误类型决定是否重试
  retry: (failureCount, error) =>
    error.status === 404 ? false : failureCount < 3,
});
```

```text
Retry 配置：
retry —— 次数或函数（false 不重试）
retryDelay —— 重试间隔
Mutation 默认不重试，Query 默认重试 3 次
```

## Optimistic Update

乐观更新指「先假设请求成功，立即更新 UI，失败再回滚」，提升交互流畅度。

```js
const mutation = useMutation({
  mutationFn: updateTodo,
  onMutate: async (newTodo) => {
    await queryClient.cancelQueries({ queryKey: ['todos'] }); // 取消进行中的请求
    const previous = queryClient.getQueryData(['todos']); // 备份旧数据

    // 乐观更新
    queryClient.setQueryData(['todos'], (old) =>
      old.map((t) => (t.id === newTodo.id ? newTodo : t)),
    );

    return { previous }; // 返回回滚数据
  },
  onError: (err, newTodo, context) => {
    // 失败回滚
    queryClient.setQueryData(['todos'], context.previous);
  },
  onSettled: () => {
    queryClient.invalidateQueries({ queryKey: ['todos'] }); // 最终同步
  },
});
```

```text
乐观更新流程：
onMutate → 乐观改缓存 → 发请求 → 成功/失败
成功 → invalidate 同步；失败 → onError 回滚
```

## Infinite Query

Infinite Query 用于无限滚动或「加载更多」分页，通过 getNextPageParam 获取下一页参数。

```js
import { useInfiniteQuery } from '@tanstack/react-query';

function Feed() {
  const {
    data,
    fetchNextPage,
    hasNextPage,
    isFetchingNextPage,
  } = useInfiniteQuery({
    queryKey: ['feed'],
    queryFn: ({ pageParam = 1 }) =>
      fetch(`/api/feed?page=${pageParam}`).then((r) => r.json()),
    getNextPageParam: (lastPage, pages) =>
      lastPage.hasMore ? pages.length + 1 : undefined,
    initialPageParam: 1,
  });

  return (
    <div>
      {data?.pages.flatMap((page) => page.items).map((item) => (
        <div key={item.id}>{item.title}</div>
      ))}
      {hasNextPage && (
        <button onClick={() => fetchNextPage()} disabled={isFetchingNextPage}>
          加载更多
        </button>
      )}
    </div>
  );
}
```

```text
Infinite Query 要点：
data.pages —— 每一页的数组
getNextPageParam —— 计算下一页参数，返回 undefined 停止
fetchNextPage —— 加载下一页
hasNextPage —— 是否还有下一页
```

## 应用场景实战

### 场景一：列表 + 删除（Mutation + 失效刷新）

```js
function TodoList() {
  const { data: todos } = useQuery({ queryKey: ['todos'], queryFn: fetchTodos });
  const queryClient = useQueryClient();

  const deleteTodo = useMutation({
    mutationFn: (id) => fetch(`/api/todos/${id}`, { method: 'DELETE' }),
    onSuccess: () => queryClient.invalidateQueries({ queryKey: ['todos'] }),
  });

  return (
    <ul>
      {todos?.map((t) => (
        <li key={t.id}>
          {t.title}
          <button onClick={() => deleteTodo.mutate(t.id)}>删除</button>
        </li>
      ))}
    </ul>
  );
}
```

### 场景二：无限滚动列表

```js
// 见 Infinite Query 示例，配合 IntersectionObserver 在滚动到底部时 fetchNextPage
useEffect(() => {
  if (!ref.current) return;
  const obs = new IntersectionObserver((entries) => {
    if (entries[0].isIntersecting && hasNextPage) fetchNextPage();
  });
  obs.observe(ref.current);
  return () => obs.disconnect();
}, [hasNextPage, fetchNextPage]);
```

## 最佳实践与踩坑记录

### 最佳实践

1. queryKey 结构化（如 ['user', id]），保证唯一与可失效
2. 服务端数据统一走 TanStack Query，不手动进全局 store
3. 写操作后用 invalidateQueries 刷新相关缓存
4. 高频变更场景用乐观更新提升体验
5. 合理设置 staleTime 与 gcTime，平衡新鲜度与请求量

### 踩坑记录

```text
坑 1：queryKey 不稳定导致缓存失效
结论：每次渲染生成新 key，缓存命中不了，重复请求。
原因：queryKey 内联了对象/数组字面量。
解法：用稳定、可序列化的 key，避免内联新引用。

坑 2：写操作后不刷新缓存
结论：列表显示旧数据。
原因：mutation 成功后未使缓存失效。
解法：onSuccess 里 invalidateQueries 对应 key。

坑 3：enabled 未设置导致错误请求
结论：依赖数据未就绪就发请求。
原因：未用 enabled 条件控制。
解法：enabled: !!id 等条件启用。

坑 4：无限滚动 key 未分页导致串页
结论：多页数据混在一起。
原因：getNextPageParam 逻辑错误或 key 不含分页。
解法：正确返回 pageParam，key 包含分页维度。

坑 5：乐观更新失败未回滚
结论：失败后 UI 停在错误状态。
原因：未在 onError 回滚备份数据。
解法：onMutate 备份、onError 回滚、onSettled 同步。
```

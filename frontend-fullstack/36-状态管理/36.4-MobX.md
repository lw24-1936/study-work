## 概述

MobX 是透明的响应式状态管理库，核心是「可观察状态 + 自动推导」。状态用 observable 标记，派生值用 computed 计算，副作用用 reaction 响应。任何在追踪上下文中被读取的 observable，变化时都会自动触发依赖更新。

```text
MobX 核心概念：
1. Observable —— 可观察状态，变化时通知依赖
2. Action —— 修改状态的操作，开启批处理
3. Computed —— 派生值，依赖变化时惰性重算
4. Reaction —— 副作用，观察状态变化自动执行
```

```js
import { makeObservable, observable, action, computed } from 'mobx';

class Store {
  todos = [];

  constructor() {
    makeObservable(this, {
      todos: observable,
      add: action,
      count: computed,
    });
  }

  add(todo) {
    this.todos.push(todo);
  }

  get count() {
    return this.todos.length;
  }
}
```

## Observable

Observable 把普通数据变成可观察状态，读取时收集依赖，修改时通知。支持对象、数组、类属性、Map/Set 等。

```js
import { observable, makeObservable, makeAutoObservable } from 'mobx';

// makeAutoObservable 自动推断（最常用）
class UserStore {
  name = 'Alice';
  age = 20;

  constructor() {
    makeAutoObservable(this); // 自动标记属性 observable、方法 action、getter computed
  }
}

// 手动标记
class Store {
  items = [];
  constructor() {
    makeObservable(this, {
      items: observable,
    });
  }
}

// observable 工厂函数（对象/数组）
const state = observable({
  count: 0,
  list: [1, 2, 3],
});
```

```text
Observable 要点：
1. makeAutoObservable 自动推断，减少样板
2. 读取即收集依赖，写入即触发
3. 只有被追踪上下文读取的属性才建立依赖
```

## Action

Action 是修改状态的函数，内部修改会被批处理，且开启严格模式时，状态只能在 action 中修改。

```js
import { makeAutoObservable, action } from 'mobx';

class CartStore {
  items = [];

  constructor() {
    makeAutoObservable(this);
  }

  add(item) {
    this.items.push(item); // 自动是 action
  }

  // 异步 action 需要 runInAction 或 flow
  async load() {
    const data = await fetch('/api/items').then((r) => r.json());
    runInAction(() => {
      this.items = data; // 异步回调中修改需包裹
    });
  }
}
```

```js
import { runInAction } from 'mobx';

// runInAction 在异步回调中修改状态
setTimeout(() => {
  runInAction(() => {
    store.items.push({ id: 1 });
  });
}, 1000);
```

```text
Action 的作用：
1. 批处理 —— 一次 action 内多次修改只触发一次更新
2. 语义清晰 —— 明确状态变更入口
3. 严格模式 —— enforceActions 强制在 action 内修改
```

## Computed

Computed 是派生值，基于 observable 自动计算，结果被缓存，依赖不变时不重新计算。

```js
import { makeAutoObservable, computed } from 'mobx';

class Store {
  price = 100;
  count = 2;

  constructor() {
    makeAutoObservable(this);
  }

  get total() {
    // 自动是 computed
    return this.price * this.count;
  }

  get doubleCount() {
    return this.count * 2;
  }
}
```

```text
Computed 要点：
1. 惰性求值 —— 只在被读取且依赖变化时重算
2. 缓存 —— 依赖不变直接返回缓存
3. 纯派生 —— 不应有副作用
```

## Reaction

Reaction 观察 observable 的变化并执行副作用。常用 autorun、reaction、when 三种 API。

```js
import { autorun, reaction, when } from 'mobx';

// autorun：自动追踪所有读取的 observable
const dispose1 = autorun(() => {
  console.log('total:', store.total); // total 变化时执行
});

// reaction：显式指定数据源，可拿新旧值
const dispose2 = reaction(
  () => store.count, // 数据源
  (count, prevCount) => {
    console.log(count, prevCount);
  },
);

// when：条件满足时执行一次
when(
  () => store.count > 10,
  () => console.log('count 超过 10'),
);

dispose1(); // 停止观察
dispose2();
```

```js
// React 组件中用 observer 建立响应
import { observer } from 'mobx-react-lite';

const Counter = observer(() => {
  return <div>{store.count}</div>; // count 变化自动重渲染
});
```

```text
三种 reaction 区别：
autorun —— 自动收集依赖，立即执行
reaction —— 显式数据源，可拿新旧值，不立即执行
when —— 条件满足执行一次后自动停止
```

## 应用场景实战

### 场景一：购物车（Store + observer）

```js
import { makeAutoObservable } from 'mobx';
import { observer } from 'mobx-react-lite';

class CartStore {
  items = [];
  constructor() {
    makeAutoObservable(this);
  }
  add(item) {
    this.items.push(item);
  }
  get totalPrice() {
    return this.items.reduce((s, i) => s + i.price, 0);
  }
  get count() {
    return this.items.length;
  }
}

const cart = new CartStore();

const Cart = observer(() => (
  <div>
    <span>共 {cart.count} 件，合计 {cart.totalPrice} 元</span>
  </div>
));
```

### 场景二：搜索自动请求（reaction 防抖）

```js
import { reaction } from 'mobx';

reaction(
  () => store.keyword,
  (keyword) => {
    clearTimeout(timer);
    timer = setTimeout(() => fetchResults(keyword), 300);
  },
);
```

## 最佳实践与踩坑记录

### 最佳实践

1. 用 makeAutoObservable 减少样板代码
2. 状态修改统一走 action，开启 enforceActions 严格模式
3. 派生值用 computed 缓存，避免重复计算
4. 异步修改用 runInAction 包裹
5. 副作用用 autorun/reaction，记得 dispose 清理

### 踩坑记录

```text
坑 1：异步回调直接改状态不生效
结论：Promise/setTimeout 里修改状态，UI 不更新或警告。
原因：异步回调脱离了 action 上下文，未批处理。
解法：用 runInAction 包裹修改。

坑 2：computed 里写副作用
结论：行为不可预测。
原因：computed 应纯净派生。
解法：副作用放 autorun/reaction。

坑 3：autorun 追踪到无关依赖
结论：访问了无关 observable，导致频繁触发。
原因：autorun 自动收集所有读取的 observable。
解法：用 reaction 显式指定数据源。

坑 4：reaction 不 dispose 导致泄漏
结论：组件卸载后仍监听，内存泄漏。
原因：autorun/reaction 返回的 dispose 未调用。
解法：在 useEffect cleanup 或 beforeUnmount 中 dispose。

坑 5：忘记用 observer 包裹组件
结论：状态变化组件不更新。
原因：组件未建立响应式追踪。
解法：用 observer 包裹函数组件。
```

## 概述

Pinia 是 Vue 的官方状态管理库，是 Vuex 的继任者。它基于 Composition API，支持多个独立 store、完整的 TypeScript 推断、无需 mutation，API 简洁直观，是 Vue 3 状态管理的首选。

```text
Pinia 核心概念：
1. Store —— defineStore 定义的响应式状态容器
2. State —— store 中的响应式数据
3. Getter —— 派生计算值（类似 computed）
4. Action —— 修改状态的函数（支持异步）
5. Plugin —— 扩展 store 功能的插件
```

```js
import { defineStore } from 'pinia';

export const useCounterStore = defineStore('counter', {
  state: () => ({ count: 0 }),
  getters: {
    double: (state) => state.count * 2,
  },
  actions: {
    increment() {
      this.count += 1;
    },
  },
});
```

## Store

Store 是 Pinia 的核心单元，用 `defineStore(id, options)` 定义。支持 Options 风格和 Setup 风格两种写法。

```js
import { defineStore } from 'pinia';

// Options 风格
export const useUserStore = defineStore('user', {
  state: () => ({ name: 'Alice', age: 20 }),
  getters: {
    adult: (state) => state.age >= 18,
  },
  actions: {
    setName(name) {
      this.name = name;
    },
  },
});
```

```js
// Setup 风格（类似组合式函数）
import { ref, computed } from 'vue';
import { defineStore } from 'pinia';

export const useUserStore = defineStore('user', () => {
  const name = ref('Alice');
  const age = ref(20);
  const adult = computed(() => age.value >= 18);
  function setName(n) {
    name.value = n;
  }
  return { name, age, adult, setName };
});
```

```js
// 组件中使用
import { useUserStore } from './stores/user';

const store = useUserStore();
store.name; // 读取
store.setName('Bob'); // 调用 action
```

```text
Store 要点：
1. 每个 store 是独立命名空间
2. Options 风格适合熟悉 Vuex 的开发者
3. Setup 风格适合 Composition API 习惯
4. store 实例是响应式的，直接解构会丢失响应（用 storeToRefs）
```

## State

State 是 store 中的响应式数据，是数据的唯一真实来源。

```js
export const useCartStore = defineStore('cart', {
  state: () => ({
    items: [],
    loading: false,
  }),
});
```

```js
// 访问与修改
const cart = useCartStore();

cart.items; // 读取
cart.items.push({ id: 1 }); // 直接修改（响应式）
cart.$patch({ loading: true }); // 批量修改
cart.$patch((state) => {
  state.items = [...state.items, { id: 2 }];
});
cart.$reset(); // 重置为初始状态
```

```js
// 解构保持响应式
import { storeToRefs } from 'pinia';
const { items, loading } = storeToRefs(cart); // 响应式引用
const { add } = cart; // action 可直接解构
```

```text
State 操作：
$patch —— 批量修改（对象或函数）
$reset —— 重置到初始状态
$state —— 整体替换状态
```

## Getter

Getter 是派生计算值，等价于 computed，依赖 state 或其他 getter，结果缓存。

```js
export const useCartStore = defineStore('cart', {
  state: () => ({ items: [] }),
  getters: {
    count: (state) => state.items.length,
    totalPrice: (state) => state.items.reduce((s, i) => s + i.price, 0),
    // 使用其它 getter（不能传 this 到箭头函数，用 state 参数）
    expensive: (state) => state.totalPrice > 1000,
  },
});
```

```js
// 非箭头函数可用 this 访问其它 getter
export const useCartStore = defineStore('cart', {
  state: () => ({ items: [] }),
  getters: {
    count(state) {
      return state.items.length;
    },
    summary() {
      return `共 ${this.count} 件`; // this 指向 store
    },
  },
});
```

```text
Getter 要点：
1. 结果缓存，依赖不变不重算
2. 箭头函数用第一个参数 state
3. 普通函数可用 this 访问其它 getter/state
```

## Action

Action 是修改状态的函数，可以是同步或异步，内部用 `this` 访问 store。

```js
export const useUserStore = defineStore('user', {
  state: () => ({ user: null, loading: false }),
  actions: {
    async fetchUser(id) {
      this.loading = true;
      try {
        this.user = await api.getUser(id);
      } finally {
        this.loading = false;
      }
    },
    // action 间互相调用
    async refresh() {
      await this.fetchUser(this.user.id);
    },
  },
});
```

```text
Action 要点：
1. 支持 async/await
2. 可调用其它 action（this.xxx）
3. 与 Vuex 不同，无需 mutation，直接改 state
```

## Plugin

Plugin 是扩展 store 的机制，可给每个 store 添加属性、方法，或做持久化、日志等增强。

```js
import { createPinia } from 'pinia';

// 自定义插件：给每个 store 添加一个方法
function myPlugin({ store }) {
  store.hello = () => console.log('hello from', store.$id);
  // 监听 state 变化
  store.$subscribe((mutation, state) => {
    console.log(mutation.type, state);
  });
}

const pinia = createPinia();
pinia.use(myPlugin);
```

```js
// 持久化插件（配合 pinia-plugin-persistedstate）
import piniaPluginPersistedstate from 'pinia-plugin-persistedstate';

const pinia = createPinia();
pinia.use(piniaPluginPersistedstate);

// store 中开启持久化
export const useStore = defineStore('app', {
  state: () => ({ theme: 'light' }),
  persist: true, // 自动持久化到 localStorage
});
```

```text
Plugin 常用场景：
1. 持久化（persist）
2. 日志/DevTools
3. 给 store 注入通用方法
4. 状态快照、同步
```

## 应用场景实战

### 场景一：购物车（含持久化与派生）

```js
import { defineStore } from 'pinia';

export const useCartStore = defineStore('cart', {
  state: () => ({ items: [] }),
  getters: {
    count: (state) => state.items.length,
    total: (state) => state.items.reduce((s, i) => s + i.price, 0),
  },
  actions: {
    add(item) {
      this.items.push(item);
    },
    remove(id) {
      this.items = this.items.filter((i) => i.id !== id);
    },
    clear() {
      this.items = [];
    },
  },
  persist: true,
});
```

### 场景二：登录用户（Setup 风格 + 异步）

```js
export const useAuthStore = defineStore('auth', () => {
  const token = ref(localStorage.getItem('token') || '');
  const user = ref(null);
  const isLogin = computed(() => !!token.value);

  async function login(username, password) {
    const res = await api.login({ username, password });
    token.value = res.token;
    localStorage.setItem('token', res.token);
  }

  function logout() {
    token.value = '';
    user.value = null;
    localStorage.removeItem('token');
  }

  return { token, user, isLogin, login, logout };
});
```

## 最佳实践与踩坑记录

### 最佳实践

1. 按业务领域拆分多个 store，避免巨型 store
2. Setup 风格更贴合 Composition API，推荐使用
3. 解构 state/getter 用 storeToRefs，action 直接解构
4. 需要跨页面持久化的状态用 persist 插件
5. 异步请求状态（loading/error）统一在 action 中维护

### 踩坑记录

```text
坑 1：直接解构 state 丢失响应性
结论：const { count } = store 后 count 不更新。
原因：解构是值拷贝，脱离响应式。
解法：用 storeToRefs(store) 解构。

坑 2：getter 箭头函数里用 this
结论：this 为 undefined，访问不到其它 getter。
原因：箭头函数不绑定 this。
解法：箭头函数用 state 参数，普通函数用 this。

坑 3：在组件外使用 store 未传 pinia 实例
结论：报错「getActivePinia」。
原因：store 必须在 pinia 安装后使用。
解法：确保 app.use(pinia) 已执行，或传 pinia 实例。

坑 4：persist 未配置版本迁移
结论：数据结构变更后旧缓存导致报错。
原因：持久化数据与新版结构不符。
解法：persist 配置 version + migrate。

坑 5：action 中误用箭头函数导致 this 丢失
结论：this 指向错误，访问不到 state。
原因：定义 action 时用了箭头函数。
解法：action 用普通方法定义（或 Setup 风格用闭包变量）。
```

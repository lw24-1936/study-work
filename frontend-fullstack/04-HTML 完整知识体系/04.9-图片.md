## 概述

图片通常占据网页最多的流量（平均超过一半），是性能优化的重点。这篇笔记聚焦图片优化的完整技术：响应式图片（srcset/sizes/picture）、懒加载、异步解码——目标是在「清晰」和「快速」之间找到平衡。

```text
图片优化的四个维度：
1. 选对格式 —— AVIF/WebP 比 JPEG/PNG 小 30%+
2. 选对尺寸 —— 按需加载，不放大图缩小用
3. 按需加载 —— 懒加载，视口外的不加载
4. 正确解码 —— 异步解码，不阻塞渲染
```

## src 与图片加载

src 是图片最基本的加载方式，一张图一个地址。

```html
<img src="photo.jpg" alt="照片">
```

```text
src 的局限：
1. 所有设备加载同一张图 —— 手机也加载给电脑准备的大图
2. 不能按屏幕/DPR/格式动态选择
3. 浪费移动端流量，拖慢加载
```

```text
图片加载的流程：
1. 浏览器解析到 img 标签
2. 请求 src 指向的图片
3. 下载完成，解码，渲染
```

```text
src 的编码形式：
1. 路径 URL —— 常规（/images/photo.jpg）
2. Data URL —— base64 内嵌（data:image/png;base64,...），小图标适用
3. 用 CSS background-image 也是一种图片加载方式（语义不同）
```

## srcset 与 sizes 分辨率切换

srcset 提供多张候选图，浏览器按屏幕 DPR 选择，sizes 告诉浏览器「图片显示多大」。

```html
<img
  src="photo.jpg"
  srcset="photo-1x.jpg 1x, photo-2x.jpg 2x, photo-3x.jpg 3x"
  alt="照片">
```

```text
srcset 的 x 描述符（按设备像素比 DPR）：
1x —— 普通屏
2x —— Retina 屏（2 倍像素）
3x —— 3 倍屏

浏览器根据设备 DPR 选对应倍率的图。
```

```html
<!-- 用宽度描述符 w + sizes（更精确的响应式） -->
<img
  src="photo-small.jpg"
  srcset="photo-400.jpg 400w, photo-800.jpg 800w, photo-1200.jpg 1200w"
  sizes="(max-width: 600px) 100vw, 50vw"
  alt="照片">
```

```text
w 描述符 + sizes 的机制：
1. srcset 的 400w/800w/1200w 声明图片的「实际宽度」
2. sizes 声明图片在「不同视口」下显示多大
   (max-width: 600px) 100vw —— 窄屏图片占满屏宽
   50vw —— 宽屏图片占一半屏宽
3. 浏览器计算：视口 1200px 宽屏 → 图片显示 600px → 选最接近的 800w 图
```

```text
sizes 的语法：
sizes="(媒体查询) 显示宽度, (媒体查询) 显示宽度, 默认宽度"

单位：vw（视口宽度百分比）、px（固定像素）。
```

## picture 与 art direction

picture 提供更强的控制，包括「艺术指导」（不同屏幕用不同裁剪的图）。

```html
<picture>
  <!-- 窄屏用竖版裁剪图 -->
  <source media="(max-width: 600px)" srcset="hero-portrait.jpg">
  <!-- 宽屏用横版图 -->
  <source media="(min-width: 601px)" srcset="hero-landscape.jpg">
  <img src="hero-landscape.jpg" alt="主图">
</picture>
```

```text
art direction（艺术指导）：
不同屏幕布局下，图片的「构图」应该不同。
手机上用竖版特写，桌面上用横版全景——不只是尺寸不同，是裁剪/构图不同。
这是 srcset 做不到的（srcset 只换分辨率，picture 能换构图）。
```

```text
picture 的三种典型用法：
1. 格式切换 —— source type 按支持选 AVIF/WebP/JPEG
2. 分辨率切换 —— source srcset 按 DPR/宽度选
3. 艺术指导 —— source media 按视口选不同构图
```

## responsive image 响应式图片

响应式图片是「让图片适配不同设备」的整体方案，综合运用上面的技术：

```html
<!-- 完整的响应式图片示例 -->
<picture>
  <!-- 格式优先：现代格式优先，旧格式兜底 -->
  <source type="image/avif" srcset="photo.avif 1x, photo@2x.avif 2x">
  <source type="image/webp" srcset="photo.webp 1x, photo@2x.webp 2x">
  <!-- 尺寸 + 艺术指导 -->
  <source media="(max-width: 600px)" srcset="photo-mobile.jpg">
  <!-- 兜底 -->
  <img src="photo.jpg" srcset="photo@2x.jpg 2x" alt="照片">
</picture>
```

```text
响应式图片的完整策略：
1. 格式 —— AVIF/WebP 优先，JPEG 兜底（省 30%+ 体积）
2. 分辨率 —— 按 DPR 提供 1x/2x/3x（高清屏不模糊，普通屏不浪费）
3. 尺寸 —— 按显示大小提供多宽度（w + sizes）
4. 艺术指导 —— 按视口选构图（picture + media）
```

```text
响应式图片的收益：
1. 移动端省流量（不加载桌面大图）
2. 高清屏清晰（加载 2x 图）
3. 全端加载更快（现代格式 + 合适尺寸）
```

## lazy loading 懒加载

懒加载让「视口外的图片」不加载，滚动到附近才加载，显著提升首屏速度。

```html
<img src="photo.jpg" loading="lazy" alt="照片">
```

```text
loading 属性：
loading="lazy"    —— 懒加载（视口外不加载）
loading="eager"   —— 立即加载（默认）
```

```text
懒加载的机制：
1. 图片滚动到视口附近（阈值内）才开始加载
2. 原生实现，无需 JS（现代浏览器支持）
3. 首屏图片不要 lazy（反而慢），只懒加载视口外的图片
```

```js
// JS 懒加载（IntersectionObserver，老浏览器或更细控制）
const imgs = document.querySelectorAll('img[data-src]');
const observer = new IntersectionObserver((entries) => {
  entries.forEach(entry => {
    if (entry.isIntersecting) {
      const img = entry.target;
      img.src = img.dataset.src;
      observer.unobserve(img);
    }
  });
});
imgs.forEach(img => observer.observe(img));
```

```text
懒加载的注意点：
1. 首屏关键图片（LCP 元素）不要懒加载，反而拖慢 LCP
2. 懒加载图片要写 width/height，避免加载后布局抖动
3. 用原生 loading="lazy" 优先，JS 方案兜底老浏览器
```

## decoding 异步解码

decoding 控制图片解码时机，避免大图解码阻塞主线程。

```html
<img src="photo.jpg" decoding="async" alt="照片">
```

```text
decoding 的取值：
decoding="async" —— 异步解码（不阻塞其他内容渲染）
decoding="sync"  —— 同步解码（默认，可能阻塞）
decoding="auto"  —— 浏览器自定（默认）
```

```text
decoding="async" 的适用场景：
1. 视口外的大图（不急着显示，异步解码）
2. 大量图片的页面（避免解码阻塞）
3. 配合 loading="lazy" 使用效果更好
```

## 应用场景实战

### 场景一：电商商品图的完整优化

```html
<picture>
  <!-- 现代格式优先 -->
  <source type="image/avif" srcset="product-400.avif 400w, product-800.avif 800w">
  <source type="image/webp" srcset="product-400.webp 400w, product-800.webp 800w">
  <!-- 兜底 JPEG -->
  <img
    src="product-400.jpg"
    srcset="product-400.jpg 400w, product-800.jpg 800w"
    sizes="(max-width: 600px) 100vw, 33vw"
    alt="商品图片"
    loading="lazy"
    decoding="async"
    width="400"
    height="400">
</picture>
```

### 场景二：首屏 hero 图优化（不懒加载）

```html
<!-- 首屏 hero 图：立即加载 + 优先格式 + 预留尺寸 -->
<picture>
  <source type="image/avif" srcset="hero.avif">
  <source type="image/webp" srcset="hero.webp">
  <img
    src="hero.jpg"
    alt="首页主视觉"
    decoding="async"
    width="1200"
    height="600"
    fetchpriority="high">
</picture>
```

```text
首屏图 vs 视口外图的策略差异：
首屏图（LCP 元素）—— 立即加载（不 lazy）+ fetchpriority="high" 提升优先级
视口外图 —— lazy 加载 + decoding="async"
```

## 最佳实践与踩坑记录

### 最佳实践

1. 图片用 AVIF/WebP 格式（picture+source 按支持降级）
2. 用 srcset+sizes 按 DPR 和显示宽度提供合适尺寸
3. 首屏图不懒加载，视口外图 loading="lazy"
4. 大图/视口外图加 decoding="async"
5. img 写 width/height 预留空间，避免 CLS
6. 首屏 LCP 图片加 fetchpriority="high"

### 踩坑记录

```text
坑 1：首屏图片也懒加载
结论：LCP 指标变差，首屏反而更慢。
原因：懒加载延迟了首屏关键图片的加载。
解法：首屏 LCP 图不 lazy（eager），视口外图才 lazy。

坑 2：只提供一张大图给所有设备
结论：手机加载了给桌面准备的大图，浪费流量。
原因：没做响应式图片，src 单一。
解法：srcset+sizes 提供多尺寸，picture 切换格式。

坑 3：srcset 的 w 描述符和 sizes 配错
结论：浏览器选的图尺寸不对（过大或模糊）。
原因：w 描述符写的是图片实际宽度，sizes 写显示宽度，两者关系没搞清。
解法：w 写图片真实像素宽度，sizes 写该图在不同视口的显示宽度。

坑 4：懒加载图片没写宽高
结论：图片加载后页面跳动（CLS 高）。
原因：懒加载图片加载前没有占位，加载后撑开布局。
解法：懒加载图片写 width/height 或 CSS aspect-ratio。

坑 5：Data URL 内嵌大图
结论：大图用 base64 内嵌，HTML 体积暴涨，解析变慢。
原因：base64 比二进制大 33%，大图内嵌得不偿失。
解法：只对小图标（<几 KB）用 Data URL，大图用独立文件 + 缓存。
```

## 概述

语义化标签是 HTML5 引入的一批「有含义」的标签，用它们替代无意义的 div，让页面结构对机器（搜索引擎、屏幕阅读器）也可读。语义化的价值不在视觉效果，而在于「可访问性 + SEO + 可维护性」——div 堆出来的页面，机器和读屏软件都「看不懂」。

```text
语义化的三层价值：
1. 可访问性 —— 屏幕阅读器能按语义导航（跳转到 main、nav）
2. SEO —— 搜索引擎理解页面结构，抓取更准确
3. 可维护性 —— 代码结构清晰，开发者一眼看懂布局
```

```html
<!-- 无意义：全是 div，机器无法理解结构 -->
<div class="header">...</div>
<div class="nav">...</div>
<div class="content">...</div>

<!-- 语义化：标签本身说明含义 -->
<header>...</header>
<nav>...</nav>
<main>...</main>
```

## 页面结构标签：header、nav、main、footer

### header

页面的页眉区，通常放标题、logo、导航。

```html
<header>
  <h1>网站名称</h1>
  <nav>...</nav>
</header>
```

```text
header 的用法：
1. 页面级 header —— 整个页面的头部
2. 区块级 header —— article/section 内部的头部（如文章标题区）
一个页面可以有多个 header（分别属于不同区块）。
```

### nav

导航区，放主导航、侧边导航等链接组。

```html
<nav aria-label="主导航">
  <ul>
    <li><a href="/">首页</a></li>
    <li><a href="/blog">博客</a></li>
  </ul>
</nav>
```

```text
nav 的要点：
1. 只放「主要导航链接组」，不是所有链接都放 nav
2. 页脚里的小链接组通常用 footer 而非 nav
3. 多个 nav 用 aria-label 区分（主/次导航）
```

### main

页面的主要内容区，每个页面只能有一个 main。

```html
<main>
  <!-- 页面的核心内容 -->
</main>
```

```text
main 的关键约束：
1. 一个页面只能有一个 main（且不能嵌套在 article/aside 里）
2. 屏幕阅读器提供「跳到主要内容」快捷键，直接定位到 main
3. 这是「跳过导航直接读内容」无障碍特性的基础
```

### footer

页脚区，放版权、联系方式、相关链接。

```html
<footer>
  <p>© 2026 网站名称</p>
  <address>联系邮箱：contact@example.com</address>
</footer>
```

## 内容分区：section、article、aside

### section

页面或文章中的独立章节，有标题的区块。

```html
<section>
  <h2>第一章</h2>
  <p>内容...</p>
</section>
```

```text
section vs div：
section —— 有语义的章节，通常带标题（h2-h6），文档大纲的一部分
div    —— 无语义的容器，纯布局用

判断标准：这个区块能在大纲里作为一个「章节」吗？能就是 section。
```

### article

独立、完整、可单独分发的内容块（文章、帖子、评论）。

```html
<article>
  <h2>文章标题</h2>
  <p>文章内容...</p>
</article>
```

```text
article vs section：
article —— 独立完整的内容（脱离上下文也能独立理解，如一篇博客、一条评论）
section —— 页面/文章的组成部分（依赖上下文）

判断标准：这段内容能不能独立「转发/聚合」？能就是 article。
```

### aside

与主要内容相关但「次要」的侧边内容（侧边栏、相关链接、广告）。

```html
<aside>
  <h3>相关阅读</h3>
  <ul><li><a href="#">...</a></li></ul>
</aside>
```

## 内容标注：address、figure、figcaption、time、mark

### address

联系信息（作者、联系方式），通常放 article 或 footer 里。

```html
<address>
  作者：张三<br>
  邮箱：<a href="mailto:zhang@example.com">zhang@example.com</a>
</address>
```

### figure 与 figcaption

figure 是「带说明的独立内容」（图片、代码、图表），figcaption 是它的标题。

```html
<figure>
  <img src="chart.png" alt="数据增长曲线">
  <figcaption>图 1：2026 年数据增长曲线</figcaption>
</figure>
```

```text
figure 的要点：
1. 图片 + 说明标题的组合
2. 可被整体移动而不影响主内容流
3. figcaption 是 figure 的第一个或最后一个子元素
```

### time

表示时间/日期，带机器可读的 datetime 属性。

```html
<time datetime="2026-08-13">2026 年 8 月 13 日</time>
```

```text
time 的 datetime 属性：
机器可读的标准时间格式（YYYY-MM-DD），
显示文本可以人性化（「8 月 13 日」），datetime 供程序解析。
```

### mark

高亮标记的文本（如搜索结果里高亮的关键词）。

```html
<p>搜索结果包含 <mark>HTML</mark> 相关文章 3 篇。</p>
```

## 交互组件：details、summary

details 是可折叠的内容块，summary 是它的标题。原生实现「手风琴」效果，无需 JS。

```html
<details>
  <summary>什么是语义化标签？</summary>
  <p>语义化标签是有含义的 HTML 标签，如 header、nav、main 等。</p>
</details>
```

```text
details/summary 的要点：
1. 原生折叠展开，无需 JS
2. summary 是可点击的标题，details 是展开的内容
3. 可用 open 属性默认展开：<details open>
4. 配合 name 属性可做「互斥手风琴」（只展开一个）
```

## 应用场景实战

### 场景一：搭建语义化的博客页面结构

```html
<body>
  <header>
    <h1>前端学习笔记</h1>
    <nav aria-label="主导航">
      <a href="/">首页</a>
      <a href="/blog">博客</a>
      <a href="/about">关于</a>
    </nav>
  </header>

  <main>
    <article>
      <header>
        <h2>HTML 语义化标签</h2>
        <time datetime="2026-08-13">2026-08-13</time>
      </header>
      <section>
        <h3>什么是语义化</h3>
        <p>...</p>
      </section>
      <footer>
        <address>作者：张三</address>
      </footer>
    </article>
    <aside>
      <h3>相关文章</h3>
      <ul>...</ul>
    </aside>
  </main>

  <footer>
    <p>© 2026 前端学习笔记</p>
  </footer>
</body>
```

### 场景二：改造 div 堆砌的老代码

```html
<!-- 改造前：div 堆砌，无语义 -->
<div class="header">
  <div class="nav">...</div>
</div>
<div class="content">
  <div class="post">...</div>
</div>
<div class="footer">...</div>

<!-- 改造后：语义化 -->
<header>
  <nav>...</nav>
</header>
<main>
  <article>...</article>
</main>
<footer>...</footer>
```

## 最佳实践与踩坑记录

### 最佳实践

1. 用语义标签替代 div（header/nav/main/footer/section/article）
2. 一个页面只有一个 main，main 不嵌套在 article/aside 里
3. 判断 section vs article：能否独立分发，能就 article
4. figure 配 figcaption 给图片/图表加说明
5. details/summary 做原生折叠，不重复造轮子
6. 多个 nav/header 用 aria-label 区分

### 踩坑记录

```text
坑 1：把所有区块都当 section 用
结论：页面里全是 section，语义和 div 一样混乱。
原因：没理解 section 是「有标题的文档章节」，不是通用容器。
解法：纯布局用 div，真正的文档章节才用 section。

坑 2：main 用了多个或嵌套
结论：屏幕阅读器「跳到主内容」定位错乱。
原因：一个页面只能有一个 main。
解法：全局只有一个 main，其余用 section/div。

坑 3：article 和 section 混用
结论：语义混乱，搜索引擎和阅读器无法正确理解内容层次。
原因：没区分「独立内容」和「组成部分」。
解法：独立可分发内容用 article，页面章节用 section。

坑 4：figcaption 位置错误
结论：图片说明关联不到图片。
原因：figcaption 不是 figure 的首/尾子元素，语义关联失效。
解法：figcaption 放 figure 的第一个或最后一个子元素。

坑 5：details/summary 嵌套 summary 标签
结论：折叠组件异常。
原因：summary 只能作为 details 的直接子元素，且 details 里只能有一个 summary。
解法：每个 details 一个 summary，嵌套折叠用嵌套 details。
```

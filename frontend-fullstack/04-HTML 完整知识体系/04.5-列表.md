## 概述

列表是网页最常见的结构之一，HTML 提供三类列表：无序列表（ul）、有序列表（ol）、定义列表（dl）。列表的正确用法远不止「前面加个点」——它承载导航、菜单、步骤等大量语义，也是屏幕阅读器能正确「数出来有几项」的基础。

```text
三类列表：
ul —— 无序列表（项目符号，无先后）
ol —— 有序列表（数字编号，有先后）
dl —— 定义列表（术语 + 定义）
```

## 无序列表 ul 与 li

ul（unordered list）表示无序列表，li（list item）是列表项。

```html
<ul>
  <li>苹果</li>
  <li>香蕉</li>
  <li>橙子</li>
</ul>
```

```text
ul 的典型用途：
1. 导航菜单（nav 里的链接组）
2. 功能列表、标签列表
3. 任何「无顺序」的项目集合
```

```html
<!-- 导航菜单的标准结构 -->
<nav>
  <ul>
    <li><a href="/">首页</a></li>
    <li><a href="/blog">博客</a></li>
    <li><a href="/about">关于</a></li>
  </ul>
</nav>
```

## 有序列表 ol

ol（ordered list）表示有序列表，用数字编号，强调顺序。

```html
<ol>
  <li>第一步：安装依赖</li>
  <li>第二步：配置环境</li>
  <li>第三步：启动服务</li>
</ol>
```

```text
ol 的典型用途：
1. 操作步骤（教程、安装指南）
2. 排名列表
3. 有先后顺序的内容
```

```text
ol 的属性：
type —— 编号类型（1/A/a/I/i）
start —— 起始编号（从几开始）
reversed —— 倒序编号
```

```html
<ol start="3" type="a">
  <li>从 c 开始编号</li>
  <li>...</li>
</ol>
```

```text
ul vs ol 的选择：
有顺序/步骤 → ol（数字编号表达先后）
无顺序/并列 → ul（项目符号表达并列）

不要用 ul 配 CSS 数字来假装 ol（语义错，屏幕阅读器读不出顺序）。
```

## 定义列表 dl、dt、dd

dl（definition list）是「术语 + 定义」的列表，dt 是术语，dd 是定义/描述。

```html
<dl>
  <dt>HTML</dt>
  <dd>网页的标记语言，定义结构。</dd>
  <dt>CSS</dt>
  <dd>网页的样式语言，定义外观。</dd>
</dl>
```

```text
dl 的典型用途：
1. 术语表、词典
2. 键值对展示（元数据：如商品参数）
3. FAQ（问题 dt + 答案 dd）
```

```html
<!-- 商品参数（键值对） -->
<dl>
  <dt>屏幕尺寸</dt>
  <dd>6.1 英寸</dd>
  <dt>分辨率</dt>
  <dd>2532 × 1170</dd>
</dl>
```

```text
dl 的规则：
1. 一个 dt 可以对应多个 dd
2. 一个 dl 里可以有多个 dt/dd 组
3. dt 和 dd 是 dl 的直接子元素
```

## 列表嵌套与语义

列表可以嵌套，形成层级结构（如多级菜单、目录树）。

```html
<ul>
  <li>前端
    <ul>
      <li>HTML</li>
      <li>CSS</li>
      <li>JavaScript</li>
    </ul>
  </li>
  <li>后端
    <ul>
      <li>Node.js</li>
      <li>Java</li>
    </ul>
  </li>
</ul>
```

```text
嵌套的正确结构：
子列表必须放在父 li 的内部（li > ul），
不能直接放在 ul 下（ul > ul 是错的）。

正确：<ul><li>父项<ul><li>子项</li></ul></li></ul>
错误：<ul><li>父项</li><ul><li>子项</li></ul></ul>
```

```text
列表的语义价值（可访问性）：
屏幕阅读器会播报「列表，3 项」，
用正确的列表标签，视障用户才能理解内容的列表结构。
用 div 堆出来的「伪列表」读不出列表语义。
```

## 应用场景实战

### 场景一：面包屑导航

```html
<!-- 面包屑：用 ol 表达层级顺序 -->
<nav aria-label="面包屑">
  <ol>
    <li><a href="/">首页</a></li>
    <li><a href="/blog">博客</a></li>
    <li>HTML 列表</li>
  </ol>
</nav>
```

### 场景二：FAQ 用定义列表

```html
<dl>
  <dt>什么是语义化 HTML？</dt>
  <dd>语义化 HTML 是使用有含义的标签描述内容结构。</dd>
  <dt>为什么要用列表标签？</dt>
  <dd>列表标签让屏幕阅读器和搜索引擎正确理解列表结构。</dd>
</dl>
```

## 最佳实践与踩坑记录

### 最佳实践

1. 有顺序用 ol，无顺序用 ul，术语/键值对用 dl
2. 导航菜单用 ul>li>a 的标准结构
3. 嵌套列表子列表放父 li 内部（li>ul），不直接放 ul 下
4. 用列表表达真正的列表内容，不用 div 堆伪列表
5. 步骤类内容用 ol（数字编号语义），不手动写「1. 2. 3.」

### 踩坑记录

```text
坑 1：用 ul 配 CSS 数字模拟有序列表
结论：视觉上是有序的，但屏幕阅读器读不出「第几项」。
原因：ul 无语义顺序，CSS 的计数器只是视觉。
解法：有顺序用 ol，让语义和视觉一致。

坑 2：嵌套列表写错层级
结论：子列表直接放 ul 下（ul>ul），语义混乱，渲染异常。
原因：子列表必须是 li 的子元素。
解法：子列表放父 li 内部：<li>父项<ul><li>子项</li></ul></li>。

坑 3：用 div 堆「伪列表」
结论：屏幕阅读器读不出列表结构，SEO 抓不到列表语义。
原因：div 无语义，只是布局容器。
解法：真正的列表用 ul/ol/dl，样式用 CSS 改。

坑 4：dl 里放无关内容
结论：dl 里塞了非术语/定义的内容，语义混乱。
原因：误把 dl 当普通容器。
解法：dl 只放「术语-定义」或「键-值」成对内容。

坑 5：手动写序号而非 ol
结论：内容里硬编码「1. 2. 3.」，增删条目要手动改所有序号。
原因：没用 ol 自动编号。
解法：用 ol 自动编号，增删条目序号自动调整。
```

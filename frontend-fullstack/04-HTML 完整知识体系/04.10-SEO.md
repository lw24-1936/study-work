## 概述

SEO（Search Engine Optimization）让网页在搜索引擎中更容易被抓取和理解，从而获得更好的排名。前端能做的 SEO 集中在「HTML 层」：语义化标签、meta 信息、结构化数据、以及 SSR（让爬虫能读到内容）。这篇笔记覆盖前端视角的 SEO 技术。

```text
前端 SEO 的三个层次：
1. 基础 —— 语义化 HTML + title/description
2. 进阶 —— canonical、robots、sitemap、Open Graph
3. 高级 —— 结构化数据（JSON-LD）+ SSR
```

## 基础 meta：title、description、keywords

### title

页面标题，是 SEO 最重要的 meta，也是搜索结果的主标题。

```html
<title>前端完整知识库 - HTML 基础</title>
```

```text
title 的 SEO 要点：
1. 每个页面唯一，描述页面核心内容
2. 长度约 50-60 字符（太长被截断）
3. 关键词靠前（重要信息放前面）
```

### description

页面描述，搜索结果标题下的摘要文字。

```html
<meta name="description" content="HTML 基础教程：文档结构、DOCTYPE、meta 标签详解">
```

```text
description 的要点：
1. 概括页面内容，长度约 150-160 字符
2. 吸引点击（影响点击率，间接影响排名）
3. 搜索引擎可能不用你的 description 而自己生成摘要
```

### keywords

关键词，历史遗留，现代搜索引擎已基本忽略。

```html
<meta name="keywords" content="前端, HTML, SEO">
```

```text
keywords 的现状：
Google 已明确声明不参考 keywords（早期被滥用刷关键词）。
写了无害但几乎无用，现代 SEO 不依赖它。
```

## canonical 规范链接

canonical 声明「这个页面的规范 URL」，解决重复内容问题。

```html
<link rel="canonical" href="https://example.com/page">
```

```text
canonical 解决的问题：
同一内容有多个 URL 时（带参数、带 www、https/http），
搜索引擎会认为是重复内容，分散权重。

canonical 告诉搜索引擎：「这些 URL 都指向这一个规范版本」，
把权重集中到规范 URL。
```

```text
canonical 的典型场景：
1. http/https 双版本
2. www/非 www 双版本
3. 带追踪参数的 URL（?utm_source=...）
4. 分页、排序、筛选产生的多 URL
```

## robots 与 Robots.txt

### robots meta

robots meta 控制「当前页面」是否被索引、是否跟踪链接。

```html
<meta name="robots" content="index, follow">
<meta name="robots" content="noindex, nofollow">
```

```text
robots 的取值：
index / noindex     —— 是否索引本页
follow / nofollow   —— 是否跟踪本页的链接

组合：
index, follow    —— 索引 + 跟踪（默认）
noindex, follow  —— 不索引 + 跟踪
noindex, nofollow —— 都不（完全屏蔽）
```

### Robots.txt

Robots.txt 是网站根目录的文件，控制爬虫「能爬哪些路径」（站点级控制）。

```text
# robots.txt（位于 https://example.com/robots.txt）
User-agent: *        # 所有爬虫
Allow: /             # 允许爬取根目录
Disallow: /admin/    # 禁止爬 /admin/
Disallow: /private/  # 禁止爬 /private/

User-agent: Googlebot
Disallow: /temp/
```

```text
robots.txt vs robots meta：
robots.txt —— 站点级，控制「爬不爬」某个路径（爬虫抓取前先读它）
robots meta —— 页面级，控制「索引不索引」单个页面

区别：robots.txt 禁止「抓取」，meta noindex 禁止「索引」。
```

## Sitemap 站点地图

Sitemap 是列出网站所有页面的 XML 文件，帮助搜索引擎发现页面。

```xml
<?xml version="1.0" encoding="UTF-8"?>
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
  <url>
    <loc>https://example.com/</loc>
    <lastmod>2026-08-13</lastmod>
    <changefreq>weekly</changefreq>
    <priority>1.0</priority>
  </url>
  <url>
    <loc>https://example.com/blog/html-basics</loc>
    <lastmod>2026-08-13</lastmod>
  </url>
</urlset>
```

```text
sitemap 的作用：
1. 主动告诉搜索引擎「我有哪些页面」（尤其新站/深层页面）
2. 提供更新时间和优先级信息

提交方式：robots.txt 里声明 sitemap 位置，或在 Search Console 提交。
```

```text
# robots.txt 里声明 sitemap
Sitemap: https://example.com/sitemap.xml
```

## Open Graph 与 Twitter Card

### Open Graph

Open Graph（OG）是社交分享的元信息，控制页面被分享到微信/Facebook 时显示的卡片。

```html
<meta property="og:title" content="页面标题">
<meta property="og:description" content="页面描述">
<meta property="og:image" content="https://example.com/og-image.jpg">
<meta property="og:url" content="https://example.com/page">
<meta property="og:type" content="website">
```

```text
Open Graph 的作用：
页面被分享到社交平台时，展示标题、描述、缩略图卡片。
没有 OG，分享出去就是光秃秃的 URL。

关键字段：
og:title / og:description / og:image / og:url / og:type
```

### Twitter Card

Twitter Card 是 Twitter 专属的分享卡片，类似 OG：

```html
<meta name="twitter:card" content="summary_large_image">
<meta name="twitter:title" content="页面标题">
<meta name="twitter:description" content="页面描述">
<meta name="twitter:image" content="https://example.com/twitter-image.jpg">
```

```text
Open Graph vs Twitter Card：
OG —— 通用（Facebook、微信、大多数平台）
Twitter Card —— Twitter 专属

实践：两者都配，Twitter 会优先用 twitter:*，缺失时回退到 og:*。
```

## Structured Data 与 JSON-LD

结构化数据用机器可读的格式描述页面内容，让搜索引擎「理解」而不只是「抓取」。

```html
<!-- JSON-LD 结构化数据 -->
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "Article",
  "headline": "HTML 基础教程",
  "author": { "@type": "Person", "name": "张三" },
  "datePublished": "2026-08-13"
}
</script>
```

```text
结构化数据的作用：
1. 富摘要（Rich Snippet）—— 搜索结果里显示星级、价格、FAQ 等增强信息
2. 语义理解 —— 让搜索引擎准确理解内容（是文章、产品、还是事件）

常见类型：Article、Product、Recipe、FAQPage、Organization、BreadcrumbList。
```

```text
JSON-LD vs 其他格式：
JSON-LD —— 现代推荐（独立 script 块，不侵入 HTML 结构）
Microdata —— 在 HTML 标签上加 itemprop（侵入性强，已少用）
RDFa —— 类似 Microdata

Google 官方推荐 JSON-LD。
```

## SSR SEO

SSR（Server-Side Rendering）对 SEO 至关重要，因为「爬虫能不能读到内容」取决于渲染方式。

```text
CSR（客户端渲染）的 SEO 问题：
SPA 用 JS 渲染，首屏 HTML 是空壳（<div id="app"></div>），
爬虫抓到的 HTML 里没有内容。

SSR（服务端渲染）的 SEO 优势：
服务端直接返回渲染好的 HTML，爬虫能直接读到完整内容。
```

```text
现代爬虫的现状：
1. Googlebot 能执行 JS（但延迟、资源消耗高，不完全可靠）
2. 其他搜索引擎/社交爬虫（微信、Twitter）大多不执行 JS
3. SSR/SSG 仍是 SEO 的可靠保证
```

```text
SEO 友好的渲染方案：
1. SSR —— 每次请求服务端渲染（动态内容）
2. SSG —— 构建时预渲染成静态 HTML（内容不变）
3. ISR —— 增量静态再生（定期更新静态页）
4. 预渲染 —— 对爬虫返回预渲染的 HTML（Prerender 服务）

详见 56-SSR-SSG-ISR。
```

### 场景一：完整的前端 SEO 头部配置

```html
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">

  <!-- 基础 SEO -->
  <title>HTML 基础教程 | 前端完整知识库</title>
  <meta name="description" content="HTML 基础教程：文档结构、DOCTYPE、meta 标签、script 加载策略详解。">

  <link rel="canonical" href="https://example.com/html-basics">

  <!-- Open Graph -->
  <meta property="og:type" content="article">
  <meta property="og:title" content="HTML 基础教程">
  <meta property="og:description" content="HTML 基础教程：文档结构、DOCTYPE、meta 标签详解。">
  <meta property="og:image" content="https://example.com/og/html-basics.jpg">
  <meta property="og:url" content="https://example.com/html-basics">

  <!-- Twitter Card -->
  <meta name="twitter:card" content="summary_large_image">
  <meta name="twitter:title" content="HTML 基础教程">
  <meta name="twitter:description" content="HTML 基础教程：文档结构、DOCTYPE、meta 标签详解。">
  <meta name="twitter:image" content="https://example.com/og/html-basics.jpg">

  <!-- 结构化数据 -->
  <script type="application/ld+json">
```

## 最佳实践与踩坑记录

### 最佳实践

1. 每个页面有唯一的 title（50-60 字符）和 description（150-160 字符）
2. 重复内容用 canonical 声明规范 URL，集中权重
3. robots.txt 屏蔽后台/API 等不该被抓的路径
4. 提供 sitemap.xml 并在 robots.txt 声明
5. 配全 Open Graph（分享卡片）+ Twitter Card
6. 内容用 JSON-LD 结构化数据，争取富摘要
7. SEO 关键页面走 SSR/SSG，保证爬虫能读到内容

### 踩坑记录

```text
坑 1：SPA 不做 SSR 导致搜索不到内容
结论：搜索引擎抓到的 HTML 是空壳，内容靠 JS 渲染，收录差。
原因：爬虫（尤其社交爬虫）不执行 JS，读不到内容。
解法：SEO 关键页面用 SSR/SSG，或对爬虫做预渲染。

坑 2：canonical 指向错误页面
结论：权重集中到错误 URL，正确页面排名差。
原因：canonical 配置错（指到首页、指到其他页面）。
解法：canonical 指向「本页面的规范 URL」，每个页面指向自己。

坑 3：noindex 误加导致整站不被收录
结论：页面在搜索引擎里搜不到。
原因：误加了 robots meta noindex，或 robots.txt 误屏蔽。
解法：检查 robots meta 和 robots.txt，只对真正不想收录的页面屏蔽。

坑 4：Open Graph 图片尺寸不符
结论：分享卡片显示模糊或裁切异常。
原因：og:image 尺寸不符合平台要求（微信/Facebook 有推荐尺寸）。
解法：og:image 用 1200×630 左右的图，保证清晰。

坑 5：JSON-LD 格式错误
结论：富摘要不生效，甚至被搜索引擎忽略。
原因：JSON-LD 语法错误或 schema 字段不对。
解法：用 Google Rich Results Test 验证结构化数据正确性。
```

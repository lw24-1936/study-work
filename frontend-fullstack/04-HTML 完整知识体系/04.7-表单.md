## 概述

表单是用户向服务器提交数据的入口，是 Web 交互的核心。HTML 表单提供了丰富的控件类型和原生校验能力，配合 label 实现可访问性。这篇笔记覆盖表单的完整知识：form 结构、input 全部类型、其他控件、校验机制。

```text
表单的三大组成部分：
1. 控件 —— input/select/textarea 等输入元素
2. 标签 —— label 关联控件，说明用途
3. 提交 —— button 触发提交，form 决定提交到哪里
```

## form 与表单基础

form 是表单容器，定义提交目标和方式。

```html
<form action="/api/submit" method="post">
  <!-- 表单控件 -->
  <button type="submit">提交</button>
</form>
```

```text
form 的关键属性：
action —— 提交到的 URL（省略则提交到当前页）
method —— 提交方式（get/post）
enctype —— 编码类型（文件上传要 multipart/form-data）
autocomplete —— 是否允许浏览器自动填充
novalidate —— 禁用原生校验
```

```text
method 的选择：
GET  —— 数据放 URL 查询串（可见、可缓存、有长度限制），用于查询/搜索
POST —— 数据放请求体（不可见、无长度限制），用于提交/创建

表单提交数据用 POST，搜索用 GET。
```

## input 类型全览

input 是表单最核心的控件，type 属性决定控件类型。input 是「自闭合」标签（无子元素）。

```text
文本类：
text     —— 单行文本（默认）
password —— 密码（输入被遮挡）
email    —— 邮箱（带格式校验）
number   —— 数字（带步进器）
tel      —— 电话（移动端弹出数字键盘）
url      —— 网址（带格式校验）
search   —— 搜索框（带清除按钮）

选择类：
checkbox —— 复选框（多选）
radio    —— 单选按钮（同 name 互斥）

日期时间类：
date     —— 日期（年-月-日）
time     —— 时间

其他：
file     —— 文件上传
hidden   —— 隐藏字段（用户不可见）
range    —— 滑块
color    —— 颜色选择器
```

```html
<!-- 文本类 -->
<input type="text" placeholder="请输入姓名">
<input type="password" placeholder="请输入密码">
<input type="email" placeholder="邮箱">
<input type="number" min="0" max="100" step="1">
<input type="tel" placeholder="手机号">
<input type="url" placeholder="网址">
<input type="search" placeholder="搜索">

<!-- 选择类 -->
<input type="checkbox" name="hobby" value="reading"> 阅读
<input type="radio" name="gender" value="male"> 男
<input type="radio" name="gender" value="female"> 女

<!-- 日期时间 -->
<input type="date">
<input type="time">

<!-- 其他 -->
<input type="file" accept="image/*">
<input type="hidden" name="id" value="123">
<input type="range" min="0" max="100">
<input type="color">
```

```text
checkbox vs radio：
checkbox —— 复选，多个可同时选中
radio    —— 单选，同 name 的一组互斥（只能选一个）

radio 的关键：同一组的 radio 必须 name 相同，才能互斥。
```

```text
file 的关键属性：
accept —— 限制可选择的文件类型（accept="image/*" 只选图片）
multiple —— 允许选多个文件
文件上传时 form 的 enctype 必须 multipart/form-data。
```

```text
hidden 的用途：
隐藏字段，用户不可见，随表单一起提交。
常用于传 id、token 等状态数据（但注意：用户可改，不能放敏感逻辑）。
```

## textarea、select、option、optgroup、datalist

### textarea 多行文本

textarea 是「成对」标签（有子元素），用于多行文本输入。

```html
<textarea rows="5" cols="40" placeholder="请输入描述">默认内容</textarea>
```

```text
textarea vs input text：
textarea —— 多行文本，适合长内容（描述、评论）
input text —— 单行文本，适合短内容（姓名、标题）
```

### select、option、optgroup 下拉选择

```html
<select name="city">
  <option value="beijing">北京</option>
  <option value="shanghai">上海</option>
  <optgroup label="广东省">
    <option value="guangzhou">广州</option>
    <option value="shenzhen">深圳</option>
  </optgroup>
</select>
```

```text
select —— 下拉选择框
option —— 选项（value 是提交值，标签是显示文本）
optgroup —— 选项分组（不可选，只做分组标题）

默认选中：给 option 加 selected 属性。
```

### datalist 输入建议

datalist 给 input 提供「输入建议」列表（自动补全）：

```html
<input list="cities" placeholder="输入或选择城市">
<datalist id="cities">
  <option value="北京">
  <option value="上海">
  <option value="广州">
</datalist>
```

```text
datalist vs select：
datalist —— 可输入 + 建议（输入时联想）
select   —— 只能从固定选项选

datalist 通过 input 的 list 属性关联 datalist 的 id。
```

## button 与 label

### button

button 是按钮，type 决定行为：

```html
<button type="submit">提交</button>
<button type="reset">重置</button>
<button type="button">普通按钮（不提交）</button>
```

```text
button 的 type 三值：
submit —— 提交表单（form 内默认）
reset  —— 重置表单
button —— 普通按钮，不提交（配合 JS 用）

坑：form 里的 button 默认 type="submit"，不加 type 会意外提交。
```

```text
button vs input type="submit"：
button —— 语义清晰，可放任意内容（图标+文字），推荐
input  —— 只能纯文本按钮

现代表单一律用 button。
```

### label

label 关联表单控件，点击 label 聚焦对应控件，也是可访问性的关键。

```html
<!-- 方式 1：label 包裹控件 -->
<label>
  姓名：<input type="text" name="name">
</label>

<!-- 方式 2：for 属性关联 id -->
<label for="name">姓名：</label>
<input type="text" id="name" name="name">
```

```text
label 的作用：
1. 点击 label 文字自动聚焦/选中控件
2. 屏幕阅读器读出「标签 + 控件」的关联
3. 点 checkbox/radio 的文字也能选中（扩大点击区域）
```

```text
label 的两种关联方式：
1. 包裹 —— label 直接包住控件
2. for/id —— label 的 for 指向控件的 id

推荐 for/id（结构更灵活），包裹方式简单直接。
```

## fieldset 与 legend

fieldset 是表单的「分组容器」，legend 是分组的标题。

```html
<fieldset>
  <legend>个人信息</legend>
  <label for="name">姓名：</label>
  <input type="text" id="name">
</fieldset>

<fieldset>
  <legend>性别</legend>
  <label><input type="radio" name="gender" value="male"> 男</label>
  <label><input type="radio" name="gender" value="female"> 女</label>
</fieldset>
```

```text
fieldset/legend 的用途：
1. 把长表单按逻辑分组（个人信息、收货地址）
2. legend 是分组的标题（屏幕阅读器播报分组）
3. 配合 disabled 可禁用整组控件
```

## autocomplete 与 validation 表单校验

### autocomplete

autocomplete 控制浏览器「自动填充」行为：

```html
<input type="text" name="username" autocomplete="username">
<input type="password" name="password" autocomplete="current-password">
<input type="text" autocomplete="off">
```

```text
autocomplete 的作用：
1. 允许浏览器记住并自动填充（提升用户体验）
2. 敏感字段（验证码、一次性密码）设 off 或 one-time-code 禁止填充

常见值：username、current-password、new-password、email、tel、off。
```

### validation 原生校验

HTML5 提供原生表单校验，无需 JS：

```html
<form>
  <input type="email" required>   <!-- required 必填 -->
  <input type="text" minlength="2" maxlength="20">
  <input type="number" min="1" max="100">
  <input type="text" pattern="[A-Za-z0-9]+">
</form>
```

```text
原生校验属性：
required     —— 必填
minlength / maxlength —— 长度限制
min / max    —— 数值范围
pattern      —— 正则校验
type         —— 类型校验（email/url 自动格式校验）
```

```text
原生校验的机制：
1. 提交时自动校验，不通过则阻止提交并提示
2. :invalid/:valid 伪类可给合法/非法状态加样式
3. 用 novalidate 禁用原生校验，改用 JS 校验（自定义提示）
```

```css
input:invalid {
  border-color: #e74c3c;
}
```

```text
原生校验 vs JS 校验：
原生校验 —— 简单、免费、但提示样式不可控
JS 校验   —— 灵活、自定义提示、但要多写代码
实践：两者配合，原生做基础校验，JS 做复杂逻辑和自定义提示。
```

## 应用场景实战

### 场景一：完整的注册表单

```html
<form action="/api/register" method="post">
  <fieldset>
    <legend>账号信息</legend>
    <label for="email">邮箱：</label>
    <input type="email" id="email" name="email" required autocomplete="email">

    <label for="password">密码：</label>
    <input type="password" id="password" name="password"
           required minlength="8" autocomplete="new-password">
  </fieldset>

  <fieldset>
    <legend>个人资料</legend>
    <label for="name">姓名：</label>
    <input type="text" id="name" name="name" required>

    <label for="city">城市：</label>
    <select id="city" name="city">
      <option value="beijing">北京</option>
      <option value="shanghai">上海</option>
    </select>
  </fieldset>

  <label>
    <input type="checkbox" name="agree" required> 我已阅读并同意条款
  </label>

  <button type="submit">注册</button>
</form>
```

### 场景二：文件上传表单

```html
<form action="/api/upload" method="post" enctype="multipart/form-data">
  <label for="file">选择文件：</label>
  <input type="file" id="file" name="file" accept=".pdf,.doc,.jpg,.png">
  <button type="submit">上传</button>
</form>
```

## 最佳实践与踩坑记录

### 最佳实践

1. 每个控件配 label（for/id 关联），保证可访问性
2. button 明确 type（submit/reset/button），避免意外提交
3. 文件上传 form 加 enctype="multipart/form-data"
4. 敏感字段（验证码）设 autocomplete="off" 或 one-time-code
5. 原生校验（required/pattern/minlength）做基础，JS 做复杂校验
6. 长表单用 fieldset/legend 分组

### 踩坑记录

```text
坑 1：button 忘写 type 导致意外提交
结论：点了「取消」按钮，表单被提交了。
原因：form 里 button 默认 type="submit"。
解法：非提交按钮显式写 type="button"。

坑 2：radio 组 name 不一致无法互斥
结论：多个单选按钮能同时选中。
原因：同组 radio 必须 name 相同才能互斥。
解法：同一单选组的 radio 用相同 name。

坑 3：文件上传没设 enctype 导致后端收不到文件
结论：上传表单提交了，后端只收到文件名收不到内容。
原因：默认 enctype 是 application/x-www-form-urlencoded，不能传文件。
解法：文件上传 form 设 enctype="multipart/form-data"。

坑 4：控件没配 label 导致可访问性差
结论：屏幕阅读器读不出控件用途，点击文字不能聚焦控件。
原因：没关联 label。
解法：每个控件配 label（for/id 关联）。

坑 5：原生校验提示样式不可控
结论：校验提示语言/样式和产品不符。
原因：原生校验提示由浏览器控制。
解法：复杂校验用 JS 自定义提示（setCustomValidity 或自建校验层）。
```

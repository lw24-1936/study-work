## 概述

文本是网页最基本的内容。HTML 提供了一套文本标签，用来表达文本的「语义」——这是标题还是段落、这是强调还是引用。用对文本标签，屏幕阅读器才能正确朗读，搜索引擎才能准确理解内容层次。

```text
文本标签的两类：
1. 结构标签 —— 组织内容层次（h1-h6 标题、p 段落）
2. 语义标签 —— 标注文字含义（strong 强调、code 代码、blockquote 引用）
```

## 标题与段落：h1-h6、p

### h1-h6 标题

h1 到 h6 是六级标题，表示内容层次，h1 最高、h6 最低。

```html
<h1>一级标题</h1>
<h2>二级标题</h2>
<h3>三级标题</h3>
<!-- ... 一直到 h6 -->
```

```text
标题的正确用法：
1. 层级递进 —— h1 下用 h2，h2 下用 h3，不跳级（h1 直接到 h4 是错的）
2. 一个页面一个 h1 —— 页面主标题
3. 标题是「内容层次」不是「字号」—— 想要大字用 CSS 改 font-size，
   不要为了字号大小乱用标题层级
```

### p 段落

p 表示段落，是最常用的文本容器。

```html
<p>这是一个段落。</p>
<p>这是另一个段落。</p>
```

## 强调与语气：strong、em、b、i、small

这四个标签长得像（都涉及加粗/斜体），但语义不同：

```html
<strong>重要内容（语义强调）</strong>
<em>语气强调（重读）</em>
<b>视觉加粗（无语义）</b>
<i>视觉斜体（无语义，用于术语/外语）</i>
<small>次要说明（小字）</small>
```

```text
strong vs b：
strong —— 语义「重要」，屏幕阅读器会加重朗读，SEO 有信号
b      —— 纯视觉加粗，无语义

em vs i：
em —— 语义「强调/重读」，改变语气
i  —— 纯视觉斜体，无语义（现在常用于术语、外语词、图标）

small —— 语义「次要说明」（免责声明、版权），默认小字
```

```text
选择原则：
表达语义用 strong/em，纯装饰用 b/i（或干脆用 CSS）。
SEO 和可访问性看重 strong/em 的语义。
```

## 代码与引用：code、pre、blockquote、q、cite

### code 与 pre

code 表示行内代码，pre 表示预格式化的代码块（保留空格和换行）。

```html
<p>用 <code>console.log()</code> 打印日志。</p>

<pre><code>
function hello() {
  console.log('hello');
}
</code></pre>
```

```text
code vs pre：
code —— 行内代码片段（一段文字里的代码）
pre  —— 代码块（保留换行、空格、缩进）

两者常组合：pre 里放 code，展示多行代码块。
```

### blockquote 与 q

blockquote 表示块级引用（大段引用），q 表示行内引用（短引用）。

```html
<blockquote cite="https://example.com/source">
  <p>这是被引用的一大段话。</p>
</blockquote>

<p>他说：<q>知识就是力量</q>。</p>
```

```text
blockquote vs q：
blockquote —— 块级引用（整段），可带 cite 属性标注来源
q          —— 行内引用（短句），浏览器自动加引号
```

### cite

cite 表示作品标题（书名、文章名、电影名），是「引用来源」。

```html
<p>我最近在读 <cite>《JavaScript 高级程序设计》</cite>。</p>
```

```text
cite 的两个含义（易混淆）：
1. cite 标签 —— 作品标题（《书名》）
2. cite 属性 —— 引用来源 URL（blockquote/q 上的 cite="url"）
```

## 其他：span、abbr、sub、sup

### span

span 是无语义的行内容器，用于给一段文字局部加样式或挂事件。

```html
<p>这是 <span class="highlight">高亮</span> 的文字。</p>
```

```text
span vs div：
span —— 行内（inline）容器，不换行
div  —— 块级（block）容器，换行
都无语义，纯粹是样式/脚本的挂载点。
```

### abbr

abbr 表示缩写，title 属性写全称。

```html
<p><abbr title="HyperText Markup Language">HTML</abbr> 是网页的标记语言。</p>
```

### sub 与 sup

sub 下标、sup 上标，用于化学式、数学、脚注。

```html
<p>水的化学式：H<sub>2</sub>O</p>
<p>面积单位：m<sup>2</sup></p>
```

## 应用场景实战

### 场景一：写一篇结构清晰的文档

```html
<article>
  <h1>Web 性能优化指南</h1>

  <h2>网络优化</h2>
  <p>网络优化是性能优化的第一步，核心是<strong>减少请求数</strong>和<strong>缩小传输体积</strong>。</p>

  <h2>渲染优化</h2>
  <p>渲染优化的关键是避免<em>强制同步布局</em>。</p>

  <h3>示例代码</h3>
  <pre><code>const el = document.querySelector('.box');</code></pre>

  <blockquote>
    <p>性能不是玄学，是可以用指标衡量的。</p>
  </blockquote>
</article>
```

### 场景二：正确标注技术文档里的术语

```html
<!-- 术语、缩写、代码的正确标注 -->
<p>
  <abbr title="Content Delivery Network">CDN</abbr> 通过边缘节点加速内容分发，
  前端加载 <code>app.js</code> 时可以用 <span class="hl">动态导入</span> 优化首屏。
</p>

<!-- 化学式、数学式 -->
<p>算法复杂度 O(n<sup>2</sup>) 需要优化。</p>
```

## 最佳实践与踩坑记录

### 最佳实践

1. 标题按层级递进（h1→h2→h3），不跳级，一个页面一个 h1
2. 语义强调用 strong/em，纯装饰用 b/i 或 CSS
3. 代码块用 pre+code 组合，行内代码用 code
4. 大段引用用 blockquote（带 cite 属性），短引用用 q
5. 缩写用 abbr 带 title 全称，化学式/数学式用 sub/sup
6. 想改字号/加粗样式用 CSS，不为了外观滥用标题层级

### 踩坑记录

```text
坑 1：为了字体大小滥用标题标签
结论：页面里一堆 h1/h2，只是为了让字大点，语义全乱。
原因：把标题当「字号」用，不是当「层级」用。
解法：标题只表达层级，字号用 CSS 控制。

坑 2：标题层级跳级
结论：h1 直接跳 h4，文档大纲不连贯。
原因：为了视觉需要跳过中间层级。
解法：按 h1→h2→h3 递进，视觉差异用 CSS 处理。

坑 3：b 和 strong、i 和 em 混用
结论：语义混乱，屏幕阅读器读不出重点，SEO 信号丢失。
原因：不知道两者语义差异。
解法：需要语义用 strong/em，纯视觉用 b/i 或 CSS。

坑 4：blockquote 用于缩进而非引用
结论：用 blockquote 做缩进，语义错误，屏幕阅读器读成「引用」。
原因：blockquote 默认有缩进样式，被当缩进工具用。
解法：缩进用 CSS margin/padding，blockquote 只用于真正的引用。

坑 5：pre 里没转义 HTML 特殊字符
结论：pre 里的 <div> 被当标签解析，显示错误。
原因：pre 只保留空白，不转义 < > & 等字符。
解法：pre 里的 HTML 代码要转义（&lt; &gt; &amp;），或配合代码高亮库处理。
```

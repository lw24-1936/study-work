## 概述

链接（a 标签）是 Web 的基础——超链接把整个互联网连成一张网。链接不只是「跳转」，还涉及新窗口打开、下载、安全（rel）、锚点定位等细节。这篇笔记讲 a 标签的完整用法。

```html
<a href="https://example.com">访问示例网站</a>
```

## a 标签与 href

a（anchor，锚）标签定义超链接，href（hypertext reference）指定目标地址。

```html
<a href="https://example.com">绝对 URL</a>
<a href="/about">相对 URL（根路径）</a>
<a href="../page.html">相对 URL（相对当前路径）</a>
<a href="#section">页内锚点</a>
<a href="javascript:void(0)">执行 JS（不推荐）</a>
```

```text
href 的取值类型：
1. 绝对 URL —— 完整地址（https://...）
2. 相对 URL —— 相对当前页面的路径（/ 根、./ 当前、../ 上级）
3. 锚点 —— #id，跳转到页面内元素
4. 协议 —— mailto:、tel:、javascript: 等
```

```text
a 标签的关键语义：
1. 有 href 才是真正的链接（可点击、可跳转、可被搜索引擎抓取）
2. 没有 href 的 a 只是「占位」（不推荐当按钮用）
3. 链接文字（anchor text）要描述目标内容，而非「点这里」
```

```text
a 当按钮 vs button（语义区分）：
a href —— 跳转到另一个位置/页面（导航）
button  —— 执行某个动作（提交、开关、弹窗）

跳转用 a，动作用 button，不要混用（影响可访问性）。
```

## target 打开方式

target 指定链接在哪个窗口打开：

```html
<a href="/page" target="_self">当前窗口打开（默认）</a>
<a href="/page" target="_blank">新窗口打开</a>
<a href="/page" target="_parent">父框架打开</a>
<a href="/page" target="_top">顶层框架打开</a>
```

```text
target="_blank" 的安全问题：
新窗口打开时，新页面能通过 window.opener 访问原页面，
可能被恶意页面利用（tabnabbing，标签页劫持）。
```

```html
<!-- 安全的新窗口打开：加 rel="noopener" -->
<a href="/page" target="_blank" rel="noopener noreferrer">安全新窗口</a>
```

```text
noopener 与 noreferrer：
noopener —— 新页面拿不到 window.opener（防劫持）
noreferrer —— 不发送 Referer 头（隐含 noopener）

实践：target="_blank" 一律配 rel="noopener"（或 noreferrer）。
```

## rel 关系属性

rel 声明当前页面与目标的关系，是安全（noopener）和 SEO 的重要属性。

```html
<a href="/page" rel="noopener">防劫持</a>
<a href="/page" rel="nofollow">不传递权重</a>
<a href="/page" rel="sponsored">广告链接</a>
<a href="/page" rel="ugc">用户生成内容链接</a>
<a href="/page" rel="external">外部链接</a>
```

```text
rel 的常见取值：
noopener    —— 安全：新窗口不共享 opener
noreferrer  —— 不发送 Referer（含 noopener）
nofollow    —— SEO：不传递链接权重（不背书）
sponsored   —— 广告/赞助链接
ugc         —— 用户生成内容（评论区链接）
external    —— 外部链接
```

```text
SEO 角度的 rel：
nofollow —— 告诉搜索引擎「不要因为我的链接给目标站加分」。
评论区、不可信内容的链接都应加 nofollow（防垃圾外链）。
```

## download 下载

download 属性让链接触发下载而非跳转：

```html
<a href="/files/report.pdf" download>下载报告</a>
<a href="/files/report.pdf" download="2026年度报告.pdf">自定义文件名下载</a>
```

```text
download 的要点：
1. 触发下载而非打开（浏览器直接下载文件）
2. download="文件名" 自定义下载文件名
3. 同源有效 —— 跨域资源的 download 属性会被忽略（浏览器限制）
```

## mailto、tel 与特殊协议

href 可以触发邮件、电话等特殊协议：

```html
<a href="mailto:contact@example.com">发邮件</a>
<a href="mailto:contact@example.com?subject=咨询&body=你好">带主题和正文的邮件</a>
<a href="tel:+8613800138000">拨打电话</a>
<a href="sms:+8613800138000">发短信</a>
```

```text
mailto 的参数：
mailto:地址?subject=主题&body=正文&cc=抄送&bcc=密送

tel 的要点：
移动端浏览器识别 tel: 协议，点击直接拨号。
```

## anchor 锚点

锚点是「页内跳转」，通过 #id 定位到页面内的元素。

```html
<!-- 定义锚点目标（任意元素加 id） -->
<h2 id="section-2">第二章</h2>

<!-- 跳转到锚点 -->
<a href="#section-2">跳转到第二章</a>

<!-- 跳转到其他页面的锚点 -->
<a href="/page.html#section-2">跳转到其他页面的锚点</a>
```

```text
锚点的机制：
1. href="#id" 跳转到页内 id 对应的元素
2. 浏览器滚动到目标元素，URL 变成 /page#id
3. 可用 CSS :target 选择器给锚点目标加样式
4. 改变 hash 不刷新页面（SPA hash 路由的原理）
```

```css
/* :target —— 给被锚点定位的元素加高亮 */
h2:target {
  background: #fff3cd;
}
```

## 应用场景实战

### 场景一：安全的外部链接组件

```html
<!-- 外部链接：新窗口打开 + 防劫持 + 不泄露 Referer -->
<a href="https://external.com" target="_blank" rel="noopener noreferrer">
  外部链接
</a>

<!-- 用户生成内容里的链接：加 nofollow 防垃圾外链 -->
<a href="https://user-content.com" rel="nofollow ugc">用户发布的链接</a>
```

### 场景二：带参数的邮件链接

```html
<!-- 点击打开邮件客户端，自动填充主题和正文 -->
<a href="mailto:support@example.com?subject=问题反馈&body=请描述你的问题：">
  提交问题反馈
</a>
```

## 最佳实践与踩坑记录

### 最佳实践

1. target="_blank" 一律配 rel="noopener"（防标签页劫持）
2. 链接文字描述目标内容，不用「点这里」「了解更多」这类空泛文字
3. 跳转用 a，动作（提交/弹窗）用 button，不混用
4. 评论区/用户生成内容的链接加 rel="nofollow"
5. 下载链接用 download 属性，跨域下载注意 download 会失效

### 踩坑记录

```text
坑 1：target="_blank" 不加 noopener 导致标签页劫持
结论：新页面能通过 window.opener 把原页面重定向到钓鱼站。
原因：新窗口共享 opener，恶意页面可操控原页面。
解法：target="_blank" 配 rel="noopener"。

坑 2：用 a href="javascript:void(0)" 当按钮
结论：无法用键盘触发、右键「在新标签打开」失效、可访问性差。
原因：a 的语义是导航，不是动作。
解法：动作用 button，导航用 a href。

坑 3：链接文字空泛影响 SEO 和可访问性
结论：屏幕阅读器读「点这里」「了解更多」，用户不知道链接去哪。
原因：链接文字没描述目标内容。
解法：链接文字写清目标（「查看 HTML 基础文档」而非「点这里」）。

坑 4：跨域 download 失效
结论：download 属性不生效，链接变成跳转打开文件。
原因：浏览器限制，跨域资源的 download 属性被忽略（安全考虑）。
解法：同源下载用 download；跨域需要服务器配 Content-Disposition: attachment。

坑 5：mailto 里特殊字符没编码
结论：邮件主题/正文里的 &、空格等导致内容错乱。
原因：mailto URL 里的参数要 URL 编码。
解法：对 subject/body 参数做 encodeURIComponent 编码。
```

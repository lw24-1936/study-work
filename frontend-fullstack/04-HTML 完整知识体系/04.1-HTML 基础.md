## 概述

HTML（HyperText Markup Language）定义网页的结构和内容。它不是编程语言，而是标记语言——用标签描述内容是什么（标题、段落、图片），而不是怎么呈现（那是 CSS 的事）。这篇笔记讲 HTML 文档的骨架：DOCTYPE、html/head/body 结构、meta 元信息，以及 script/link 等关键标签的正确用法。

```text
HTML 的三层职责划分：
HTML —— 内容结构（这段文字是标题还是段落）
CSS  —— 视觉样式（这段文字长什么样）
JS   —— 交互行为（点击这段文字发生什么）
```

## HTML 文档结构

一个规范的 HTML 文档由固定的骨架组成：

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>页面标题</title>
  <link rel="stylesheet" href="style.css">
</head>
<body>
  <!-- 页面内容 -->
  <h1>这是标题</h1>
  <p>这是段落</p>
  <script src="app.js"></script>
</body>
</html>
```

```text
文档结构拆解：
<!DOCTYPE html>  —— 声明文档类型（HTML5）
<html>           —— 根元素，包裹整个页面
  <head>         —— 元信息区（不显示在页面上）
  <body>         —— 内容区（用户看到的一切）
```

```text
HTML 的两个核心特性：
1. 树形结构 —— 标签嵌套形成 DOM 树，浏览器按树渲染
2. 语义化 —— 标签描述内容含义，而非外观
```

## DOCTYPE

DOCTYPE 声明告诉浏览器「用什么标准解析这个文档」，必须写在第一行。

```html
<!DOCTYPE html>   <!-- HTML5 标准声明 -->
```

```text
DOCTYPE 的作用：
1. 触发标准模式（Standards Mode）—— 浏览器按标准规范渲染
2. 没有 DOCTYPE 或写错 → 触发怪异模式（Quirks Mode），
   浏览器按老旧的兼容规则渲染，布局错乱

历史：HTML4 时代 DOCTYPE 很长（要写 DTD），HTML5 简化为一行。
```

```text
标准模式 vs 怪异模式：
标准模式 —— 现代标准渲染，行为一致
怪异模式 —— 兼容老网页，盒模型等行为不同（老 IE 的 box-sizing）

前端只需记住：永远写 <!DOCTYPE html>，避免怪异模式。
```

## html、head 与 body

### html

html 是根元素，`lang` 属性声明页面语言（影响屏幕阅读器发音和搜索引擎）。

```html
<html lang="zh-CN">  <!-- 中文 -->
<html lang="en">     <!-- 英文 -->
```

```text
lang 属性的重要性：
1. 屏幕阅读器 —— 用对应语言的发音规则朗读
2. 搜索引擎 —— 判断页面语言
3. 浏览器 —— 字体选择、翻译提示
```

### head

head 是元信息区，内容不直接显示在页面上，但影响页面的行为、SEO、加载。

```html
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>页面标题</title>
  <meta name="description" content="页面描述">
  <link rel="stylesheet" href="style.css">
  <script src="app.js" defer></script>
</head>
```

### body

body 是用户看到的内容区，所有可见元素都放在这里。

```text
head vs body：
head —— 元信息，用户不可见（标题、编码、样式引用、SEO 信息）
body —— 内容，用户可见（文字、图片、按钮等一切）
```

## meta 元信息

meta 标签提供文档的元数据，常见用法：

```html
<!-- 字符编码（必须，放在 head 最前面） -->
<meta charset="UTF-8">

<!-- 视口（移动端适配必备） -->
<meta name="viewport" content="width=device-width, initial-scale=1.0">

<!-- 页面描述（SEO 用） -->
<meta name="description" content="这是页面的描述">

<!-- 关键字（SEO，现代搜索引擎已不重视） -->
<meta name="keywords" content="前端, HTML">

<!-- 作者 -->
<meta name="author" content="张三">

<!-- robots 控制搜索引擎抓取 -->
<meta name="robots" content="index, follow">
```

```text
charset 的坑：
charset 必须声明，且尽量放在 head 最前面（前 1024 字节内），
否则浏览器可能用错误编码解析，中文乱码。

viewport 的坑：
移动端不写 viewport，页面会按桌面宽度渲染，手机上缩小到看不清。
width=device-width 让页面宽度等于设备宽度。
```

```text
meta 的分类：
1. charset —— 字符编码
2. name/content —— 元信息（description/keywords/viewport/robots）
3. http-equiv —— HTTP 头等价（如 refresh 刷新、Content-Security-Policy）
```

## title、link 与 style

### title

title 定义页面标题，显示在浏览器标签页，也是 SEO 的核心。

```html
<title>前端完整知识库 - HTML 基础</title>
```

```text
title 的要点：
1. 浏览器标签页显示
2. 搜索引擎结果标题
3. 收藏夹名称
4. 每个页面都应有唯一的 title
```

### link

link 引入外部资源，最常用的是样式表：

```html
<link rel="stylesheet" href="style.css">
<link rel="icon" href="favicon.ico">
<link rel="preload" href="font.woff2" as="font" crossorigin>
```

```text
link 的常见用途：
1. rel="stylesheet" —— 引入 CSS
2. rel="icon" —— 网站图标（favicon）
3. rel="preload" —— 预加载资源
4. rel="canonical" —— 声明规范 URL（SEO）
```

### style

style 标签写内联 CSS（写在 head 或 body 里），一般不如外链 CSS 常用。

```html
<style>
  body { font-family: sans-serif; }
</style>
```

## script 与 noscript

### script

script 引入或内联 JavaScript：

```html
<!-- 外链脚本 -->
<script src="app.js"></script>

<!-- 内联脚本 -->
<script>
  console.log('hello');
</script>
```

```text
script 的加载策略（关键）：
<script>              —— 阻塞解析，下载并执行完才继续渲染（会阻塞页面）
<script defer>        —— 异步下载，HTML 解析完按顺序执行（推荐）
<script async>        —— 异步下载，下载完立即执行（顺序不保证）
<script type="module">—— ES 模块，默认 defer 行为，且受 CORS 约束
```

```text
defer vs async：
defer —— 下载不阻塞解析，DOM 解析完成后、DOMContentLoaded 前按顺序执行
async —— 下载不阻塞解析，下载完立即执行（可能打乱顺序）

实践：
1. 依赖 DOM 或需要执行顺序 → defer
2. 独立脚本（统计、广告）→ async
3. 放在 body 末尾的脚本天然接近 defer 效果
```

### noscript

noscript 提供「浏览器禁用 JS 时」的替代内容：

```html
<script src="app.js"></script>
<noscript>
  您的浏览器禁用了 JavaScript，请启用后访问完整功能。
</noscript>
```

```text
noscript 的用途：
当浏览器不支持或禁用 JS 时，显示 noscript 里的内容。
是渐进增强的一部分——保证无 JS 环境也有基本提示。
```

## 应用场景实战

### 场景一：新建一个规范的 HTML5 页面模板

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <meta name="description" content="页面描述，用于 SEO">
  <title>页面标题</title>
  <link rel="icon" href="/favicon.ico">
  <link rel="stylesheet" href="/style.css">
  <script src="/app.js" defer></script>
</head>
<body>
  <h1>页面标题</h1>
  <p>页面内容</p>
  <noscript>请启用 JavaScript 以使用完整功能。</noscript>
</body>
</html>
```

### 场景二：排查中文乱码

```text
现象：页面中文显示为乱码。

排查：
1. 检查 <meta charset="UTF-8"> 是否存在、是否在 head 最前
2. 检查文件本身是否保存为 UTF-8 编码
3. 检查服务器响应头 Content-Type 的 charset 是否声明 UTF-8

三者（meta、文件编码、HTTP 头）不一致就乱码，需统一。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 第一行写 `<!DOCTYPE html>`，避免怪异模式
2. charset 放 head 最前，文件、meta、HTTP 头三处编码统一 UTF-8
3. 移动端页面必写 viewport meta
4. 每个页面有唯一的 title 和 description
5. 脚本用 defer（依赖 DOM/顺序）或 async（独立脚本），避免阻塞渲染
6. html 标签加 lang 属性

### 踩坑记录

```text
坑 1：漏写 DOCTYPE 进入怪异模式
结论：布局和预期不符，不同浏览器表现不一致。
原因：没有标准模式声明，浏览器用兼容规则渲染。
解法：第一行写 <!DOCTYPE html>。

坑 2：charset 位置太靠后导致乱码
结论：中文乱码，即使写了 charset。
原因：charset 没在前 1024 字节内，浏览器已按默认编码解析。
解法：charset 放 head 第一个子元素位置。

坑 3：移动端页面字体极小
结论：手机上页面缩得很小，要手动放大。
原因：漏写 viewport meta，浏览器按桌面宽度渲染再缩小。
解法：加 <meta name="viewport" content="width=device-width, initial-scale=1.0">。

坑 4：script 阻塞页面渲染
结论：页面白屏，等脚本下载执行完才显示。
原因：script 放 head 且无 defer/async，阻塞 HTML 解析。
解法：脚本用 defer，或放 body 末尾。

坑 5：lang 属性缺失影响无障碍和 SEO
结论：屏幕阅读器用默认语言朗读，读不准；搜索引擎判断语言困难。
原因：没声明 html lang。
解法：html 标签加 lang="zh-CN" 等对应语言。
```

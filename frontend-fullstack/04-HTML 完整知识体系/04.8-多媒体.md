## 概述

多媒体标签让网页嵌入图片、音频、视频和外部内容。前端关注的核心是：响应式图片（不同设备加载不同尺寸/格式）、视频的格式兼容、以及 iframe 的安全。这篇笔记覆盖 img、picture、audio/video、iframe 等多媒体标签的用法。

```text
多媒体标签一览：
img     —— 图片
picture —— 响应式图片容器（多 source 备选）
audio   —— 音频
video   —— 视频
iframe  —— 内嵌其他页面
embed/object —— 嵌入外部插件内容（老技术，少用）
```

## img 图片

img 是最基础的图片标签，用 src 指定图片地址。

```html
<img src="photo.jpg" alt="一张风景照" width="400" height="300">
```

```text
img 的关键属性：
src    —— 图片地址
alt    —— 替代文本（图片加载失败时显示，屏幕阅读器朗读）
width/height —— 宽高（写真实尺寸可避免布局抖动）
loading —— lazy 懒加载
decoding —— async 异步解码
```

```text
alt 属性（重要）：
1. 有意义图片 —— 写描述性 alt（描述图片内容）
2. 纯装饰图片 —— 写空 alt=""（让屏幕阅读器跳过）
3. 缺 alt —— 屏幕阅读器读文件名，体验差
```

```text
img 的加载细节：
1. 默认同步加载（阻塞渲染）
2. loading="lazy" 懒加载（滚动到视口才加载）
3. decoding="async" 异步解码（不阻塞主线程）
```

## picture 与 source 响应式图片

picture 配合 source，根据条件加载不同图片（响应式图片的核心）：

```html
<picture>
  <!-- 支持 AVIF 的浏览器用 AVIF -->
  <source srcset="photo.avif" type="image/avif">
  <!-- 支持 WebP 的用 WebP -->
  <source srcset="photo.webp" type="image/webp">
  <!-- 兜底：JPG -->
  <img src="photo.jpg" alt="一张照片">
</picture>
```

```text
picture 的作用：
1. 格式切换 —— 按浏览器支持选择 AVIF/WebP/JPEG
2. 分辨率切换 —— 按屏幕 DPR 选 1x/2x/3x 图
3. 艺术指导（art direction）—— 按视口宽度选不同裁剪的图
```

```text
source 的用法：
srcset —— 候选图片列表
type   —— 图片 MIME 类型（浏览器据此判断支持性）
media  —— 媒体查询条件（满足才用这个 source）
```

```text
picture 的解析规则：
浏览器从上到下找第一个「满足条件」的 source，用它；
都不满足则用 img 兜底。
img 是必写的兜底（也是 picture 的实际渲染元素）。
```

## audio 与 video

### audio 音频

```html
<audio controls>
  <source src="audio.ogg" type="audio/ogg">
  <source src="audio.mp3" type="audio/mpeg">
  您的浏览器不支持音频播放。
</audio>
```

### video 视频

```html
<video controls width="640" poster="poster.jpg">
  <source src="video.webm" type="video/webm">
  <source src="video.mp4" type="video/mp4">
  您的浏览器不支持视频播放。
</video>
```

```text
video 的关键属性：
controls —— 显示播放控件
autoplay —— 自动播放（浏览器限制：需静音 muted 才允许）
muted    —— 静音
loop     —— 循环
poster   —— 封面图（播放前显示）
preload  —— 预加载策略（none/metadata/auto）
```

```text
video/audio 的格式兼容：
不同浏览器支持的格式不同，所以提供多个 source 备选：
video —— webm（开源）+ mp4（兼容好）
audio —— ogg + mp3

浏览器从上到下选第一个支持的类型。
```

```text
autoplay 的坑：
现代浏览器禁止「带声音的自动播放」（用户体验/流量考虑）。
要自动播放必须 muted（静音自动播放是允许的）。
```

## track 字幕

track 给音视频提供字幕、章节等文本轨道。

```html
<video controls>
  <source src="video.mp4" type="video/mp4">
  <track src="captions.vtt" kind="subtitles" srclang="zh" label="中文">
  <track src="captions-en.vtt" kind="subtitles" srclang="en" label="English">
</video>
```

```text
track 的属性：
src     —— 字幕文件地址（WebVTT 格式 .vtt）
kind    —— 轨道类型（subtitles 字幕、captions 说明字幕、descriptions 描述）
srclang —— 字幕语言
label   —— 显示名称（用户选择字幕时看到）
default —— 默认启用的字幕
```

## iframe 内嵌框架

iframe 在当前页面内嵌另一个页面，用于嵌入视频、地图、第三方内容。

```html
<iframe src="https://example.com/embed" width="600" height="400"></iframe>
```

```text
iframe 的常见用途：
1. 嵌入第三方内容（YouTube 视频、地图、支付页）
2. 隔离内容（广告、第三方组件）
3. 微前端的一种实现方式
```

```text
iframe 的安全属性：
sandbox —— 沙箱限制（禁脚本、禁表单、禁同源访问等）
loading —— lazy 懒加载
referrerpolicy —— 控制 Referer 发送
```

```html
<!-- 安全地嵌入第三方内容 -->
<iframe src="https://third-party.com"
        sandbox="allow-scripts allow-same-origin"
        loading="lazy"></iframe>
```

```text
sandbox 的作用：
默认（空 sandbox）iframe 里的页面几乎无权限。
按需用 allow-* 放行：
allow-scripts —— 允许脚本
allow-same-origin —— 允许同源访问（与 allow-scripts 同用有风险）
allow-forms / allow-popups —— 允许表单/弹窗
```

```text
iframe 的缺点：
1. 性能 —— 额外的文档加载
2. SEO —— iframe 内容不参与父页面的 SEO
3. 安全 —— 需要 sandbox 防护
```

## embed 与 object

embed 和 object 是嵌入外部内容（PDF、Flash、插件）的老标签，现代已少用。

```html
<embed src="file.pdf" type="application/pdf" width="600" height="400">
<object data="file.pdf" type="application/pdf" width="600" height="400">
  <p>无法显示 PDF，<a href="file.pdf">点击下载</a></p>
</object>
```

```text
embed vs object：
embed —— 自闭合，简单嵌入（历史遗留）
object —— 成对标签，可提供 fallback 内容，功能更完整

现代替代：PDF 用 <iframe> 或浏览器原生 PDF 查看器，
Flash 已死，embed/object 基本只用于兼容老内容。
```

## 应用场景实战

### 场景一：完整的响应式图片方案

```html
<picture>
  <!-- 移动端小图（窄屏用裁剪图） -->
  <source media="(max-width: 600px)" srcset="hero-mobile.jpg">
  <!-- 高清屏 2x 图 -->
  <source srcset="hero-2x.jpg 2x, hero.jpg 1x">
  <!-- 兜底 -->
  <img src="hero.jpg" alt="产品主图" loading="lazy" decoding="async">
</picture>
```

### 场景二：嵌入 YouTube 视频（安全 iframe）

```html
<iframe
  src="https://www.youtube.com/embed/VIDEO_ID"
  title="视频标题"
  width="560"
  height="315"
  loading="lazy"
  allow="accelerometer; autoplay; encrypted-media; gyroscope"
  allowfullscreen>
</iframe>
```

## 最佳实践与踩坑记录

### 最佳实践

1. 图片必写 alt（有意义写描述，装饰图写空 alt=""）
2. img 写真实 width/height，避免布局抖动（CLS）
3. 响应式图片用 picture+source（格式切换 + 分辨率切换）
4. 视频提供 webm + mp4 双格式，兼容不同浏览器
5. 第三方 iframe 加 sandbox 限制权限
6. 图片懒加载（loading="lazy"），视频预加载用 preload="metadata"

### 踩坑记录

```text
坑 1：图片缺 alt 影响可访问性和 SEO
结论：屏幕阅读器读文件名，图片加载失败无提示。
原因：没写 alt。
解法：有意义图片写描述 alt，装饰图写 alt=""。

坑 2：图片没写宽高导致布局抖动
结论：图片加载后页面内容跳动（CLS 指标差）。
原因：没预留宽高，图片加载前后布局变化。
解法：img 写 width/height（或用 CSS aspect-ratio 预留空间）。

坑 3：视频 autoplay 带声音无效
结论：写了 autoplay 但视频不自动播放。
原因：浏览器禁止带声音自动播放。
解法：加 muted 属性（静音自动播放），或等用户交互后再播放。

坑 4：iframe 不加 sandbox 有安全风险
结论：嵌入的第三方内容可访问父页面、执行恶意脚本。
原因：默认 iframe 权限较大。
解法：加 sandbox 属性，按需 allow-* 放行。

坑 5：picture 里漏写 img 兜底
结论：不支持 picture/source 的浏览器什么都不显示。
原因：picture 里 img 是必写的兜底元素。
解法：picture 里最后必须写 img（兜底 + 实际渲染元素）。

坑 6：懒加载图片在首屏不加载
结论：首屏图片也 lazy，导致首屏慢（反而更慢）。
原因：首屏图片不该懒加载，lazy 只用于视口外的图片。
解法：首屏关键图片不设 loading="lazy"，视口外图片才懒加载。
```

## 概述

Express 是 Node.js 生态历史最悠久、使用最广泛的 Web 框架。它把 HTTP 服务器的核心能力抽象成「中间件 + 路由」，请求沿中间件链依次穿过，最终由匹配的路由处理器响应。

```text
Express 的核心组成：
1. Middleware —— 函数组成的处理链，按注册顺序依次执行
2. Router —— 模块化的路由容器，可挂载到不同路径前缀
3. Request —— 封装请求（参数、头、body）
4. Response —— 封装响应（状态码、头、发送数据）
5. Error Handling —— 四参数中间件统一兜底错误
```

```js
const express = require('express');
const app = express();

app.get('/', (req, res) => res.send('Hello Express'));

app.listen(3000, () => console.log('listening on 3000'));
```

## Middleware

中间件是 `(req, res, next)` 函数，是 Express 的骨架。所有请求处理（日志、解析、鉴权、响应）本质上都是中间件。

```js
const express = require('express');
const app = express();

// 应用级中间件：所有请求都会经过
app.use((req, res, next) => {
  console.log(`${req.method} ${req.url}`);
  next(); // 必须调用 next 才能继续往下走
});

// 路径限定中间件
app.use('/api', (req, res, next) => {
  req.startTime = Date.now();
  next();
});

app.get('/api/users', (req, res) => {
  res.json({ elapsed: Date.now() - req.startTime });
});

app.listen(3000);
```

```text
中间件的执行模型：
1. 按注册顺序依次执行，形成「洋葱模型」前的线性链
2. 每个中间件决定：继续 next() 或直接结束响应
3. 不调用 next() 且不响应 → 请求会挂起
4. next('route') 跳过当前路由其余处理器
5. next(err) 跳入错误处理中间件
```

```js
// 内置中间件
app.use(express.json());        // 解析 JSON body
app.use(express.urlencoded({ extended: true })); // 解析表单 body
app.use(express.static('public')); // 静态文件

// 第三方中间件
const morgan = require('morgan');
app.use(morgan('combined'));    // 日志
```

## Router

Router 是可挂载的「迷你 Express」，用于按功能模块拆分路由，避免单一 app 文件无限膨胀。

```js
// routes/users.js
const express = require('express');
const router = express.Router();

router.get('/', (req, res) => res.json([{ id: 1, name: 'Alice' }]));
router.get('/:id', (req, res) => res.json({ id: req.params.id }));
router.post('/', (req, res) => res.status(201).json(req.body));

module.exports = router;
```

```js
// app.js 挂载
const usersRouter = require('./routes/users');
app.use('/users', usersRouter); // /users、/users/:id
```

```text
Router 的用法：
1. express.Router() 创建独立路由容器
2. app.use(path, router) 挂载到路径前缀
3. router.use() 也可给路由加子中间件
4. router.route('/x').get().post() 链式注册
```

## Request

req 对象封装了请求信息：URL 参数、查询串、请求头、body 等。

```js
app.get('/users/:id', (req, res) => {
  const { id } = req.params;      // 路由参数 → /users/42
  const { page } = req.query;     // 查询串 → ?page=2
  const token = req.get('Authorization'); // 请求头
  const { name } = req.body;      // 需先 app.use(express.json())
  const ip = req.ip;              // 客户端 IP
  const host = req.hostname;      // Host 头

  res.json({ id, page, token, name, ip, host });
});
```

```text
req 常用属性：
1. req.params —— 路由参数（/users/:id）
2. req.query —— 查询字符串对象（?a=1&b=2）
3. req.body —— 请求体（依赖解析中间件）
4. req.headers / req.get(name) —— 请求头
5. req.method / req.path / req.url —— 方法与路径
6. req.cookies —— 需 cookie-parser
```

## Response

res 对象负责写回响应：状态码、响应头、数据体。方法可链式调用。

```js
app.get('/download', (req, res) => {
  res
    .status(200)                    // 状态码
    .set('Content-Type', 'text/plain')
    .json({ ok: true });            // 序列化 JSON 发送
});

app.get('/file', (req, res) => {
  res.download('./report.pdf');     // 触发下载
});

app.get('/redirect', (req, res) => {
  res.redirect(301, '/new-url');    // 重定向
});
```

```text
res 常用方法：
1. res.send(body) —— 自动推断类型（字符串/html/对象）
2. res.json(obj) —— 强制 JSON 序列化
3. res.status(code) —— 设置状态码（可链式）
4. res.set / res.header —— 设置响应头
5. res.redirect(url) —— 重定向
6. res.sendFile / res.download —— 文件下载
7. res.end() —— 结束响应（无 body）
```

## Error Handling

错误处理中间件签名是四个参数 `(err, req, res, next)`，Express 靠参数个数识别它。它必须放在所有普通路由之后。

```js
const express = require('express');
const app = express();

app.get('/ok', (req, res) => res.json({ ok: true }));

// 抛出同步错误 / 传递异步错误
app.get('/fail', (req, res, next) => {
  try {
    throw new Error('boom');
  } catch (err) {
    next(err); // 交给错误处理中间件
  }
});

// 异步错误也要 next(err)
app.get('/async-fail', async (req, res, next) => {
  try {
    await Promise.reject(new Error('async boom'));
  } catch (err) {
    next(err);
  }
});

// 兜底错误处理中间件（必须有 4 个参数）
app.use((err, req, res, next) => {
  console.error(err.stack);
  res.status(err.status || 500).json({ message: err.message });
});

// 404 兜底（放在所有路由后、错误处理前）
app.use((req, res) => res.status(404).json({ message: 'Not Found' }));

app.listen(3000);
```

```text
错误处理要点：
1. 错误中间件必须写 4 个参数（err 排第一）
2. 同步抛错 Express 会自动捕获，异步必须手动 next(err)
3. 404 兜底用普通中间件放在最后
4. 错误中间件要放在 404 之后、所有路由之后
5. async 路由可用包装器或 express-async-errors 自动捕获
```

```js
// async 路由统一包装器（避免每个 try/catch）
const wrap = (fn) => (req, res, next) => fn(req, res, next).catch(next);
app.get('/data', wrap(async (req, res) => {
  const data = await fetchData();
  res.json(data);
}));
```

## 应用场景实战

### 场景一：RESTful API 服务

```js
const express = require('express');
const app = express();
app.use(express.json());

const db = new Map();
let seq = 0;

app.get('/todos', (req, res) => res.json([...db.values()]));
app.get('/todos/:id', (req, res) => {
  const t = db.get(Number(req.params.id));
  t ? res.json(t) : res.status(404).json({ message: 'not found' });
});
app.post('/todos', (req, res) => {
  const todo = { id: ++seq, text: req.body.text, done: false };
  db.set(todo.id, todo);
  res.status(201).json(todo);
});
app.patch('/todos/:id', (req, res) => {
  const t = db.get(Number(req.params.id));
  if (!t) return res.status(404).json({ message: 'not found' });
  Object.assign(t, req.body);
  res.json(t);
});

app.use((err, req, res, next) => res.status(500).json({ message: err.message }));
app.listen(3000);
```

### 场景二：鉴权 + 权限中间件

```js
// 鉴权中间件：解析 token → 挂到 req.user
function auth(req, res, next) {
  const token = req.get('Authorization')?.replace('Bearer ', '');
  if (!token) return res.status(401).json({ message: 'unauthorized' });
  req.user = { id: 1, role: 'admin' }; // 实际应校验 token
  next();
}

// 权限中间件工厂
function requireRole(role) {
  return (req, res, next) =>
    req.user?.role === role ? next() : res.status(403).json({ message: 'forbidden' });
}

app.get('/admin', auth, requireRole('admin'), (req, res) => {
  res.json({ secret: 'admin only' });
});
```

## 最佳实践与踩坑记录

### 最佳实践

1. 路由用 Router 按模块拆分，别全堆在 app.js
2. 中间件链顺序敏感：解析 body 要在路由之前
3. 异步错误必须 next(err) 或统一包装，否则进程挂起
4. 错误处理中间件放在所有路由之后、带 4 个参数
5. 敏感信息（token、密码）不要写进日志
6. 生产环境关掉 `app.disable('x-powered-by')` 隐藏框架指纹

### 踩坑记录

```text
坑 1：忘记调用 next 导致请求挂起
结论：请求一直转圈，前端超时。
原因：中间件既不 next() 也不响应。
解法：每个中间件要么 next()，要么结束响应。

坑 2：异步错误没捕获导致进程崩溃或挂起
结论：async 路由 reject 后无响应，甚至进程退出。
原因：Express 4 不捕获 Promise 的 rejection。
解法：async 路由内 try/catch + next(err)，或统一 wrap 包装。

坑 3：body 解析中间件顺序错误
结论：req.body 是 undefined。
原因：express.json() 没在路由之前注册。
解法：app.use(express.json()) 放在所有路由最前面。

坑 4：错误处理中间件不生效
结论：错误直接抛给客户端，返回 HTML 堆栈。
原因：错误中间件参数不足 4 个，或被当成普通中间件。
解法：确认签名 (err, req, res, next)，并放路由最后。

坑 5：路由挂载路径与子路由冲突
结论：子路由里写了绝对路径 /users 结果变成 /users/users。
原因：router 里用了 /users，挂载时又加了前缀。
解法：子路由内写相对路径，路径前缀统一在挂载处加。
```

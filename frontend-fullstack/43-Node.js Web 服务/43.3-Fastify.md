## 概述

Fastify 是主打性能的 Node.js Web 框架，通过 JSON Schema 声明输入输出、提前编译序列化器，在保证 DX 的同时把吞吐做到接近原生 HTTP 的水平。它用「插件 + 封装上下文」组织代码，天然支持异步和日志。

```text
Fastify 的四个核心卖点：
1. Plugin —— 插件体系 + 封装上下文，实现作用域隔离
2. Schema —— 用 JSON Schema 声明请求/响应结构
3. Validation —— 依据 Schema 自动校验入参，非法直接 400
4. Serialization —— 依据 Schema 编译序列化器，比 JSON.stringify 快
```

```js
const fastify = require('fastify')({ logger: true });

fastify.get('/', async () => ({ hello: 'world' }));

fastify.listen({ port: 3000 });
```

## Plugin

插件是 Fastify 组织代码的基本单元，用 `fastify.register(plugin, opts)` 注册。每个 register 都会创建一个「封装上下文」，插件内注册的钩子、装饰、路由默认不泄漏到外层。

```js
const fastify = require('fastify')();

// 定义一个插件
async function userRoutes(instance, opts) {
  instance.decorate('db', opts.db); // 装饰只在插件作用域可见

  instance.get('/users', async () => {
    return instance.db.listUsers();
  });
}

fastify.register(userRoutes, { db: { listUsers: () => ['Alice', 'Bob'] } });
fastify.register(userRoutes, { prefix: '/v2', db: fakeDb2 });

fastify.listen({ port: 3000 });
```

```text
插件体系的要点：
1. register(plugin, opts) —— 插件接收封装后的 instance 和选项
2. 封装上下文 —— 每个插件有自己的作用域
3. 钩子/装饰默认私有 —— 不影响兄弟插件和父作用域
4. fastify-plugin 可打破封装 —— 让装饰对上层可见
5. prefix 选项 —— 给插件内所有路由加统一前缀
```

```js
// fastify-plugin：让装饰、钩子对全局可见
const fp = require('fastify-plugin');

async function dbPlugin(instance) {
  instance.decorate('db', connectDb());
}

module.exports = fp(dbPlugin); // 不加 fp 则 db 只在本插件可见
```

## Schema

JSON Schema 是 Fastify 的「契约」，声明路由的 params、querystring、headers、body、response。声明后框架自动做校验和序列化。

```js
const fastify = require('fastify')();

const userSchema = {
  body: {
    type: 'object',
    required: ['name'],
    properties: {
      name: { type: 'string', minLength: 1 },
      age: { type: 'integer', minimum: 0 },
    },
  },
  response: {
    200: {
      type: 'object',
      properties: {
        id: { type: 'integer' },
        name: { type: 'string' },
      },
    },
  },
};

fastify.post('/users', { schema: userSchema }, async (req) => {
  return { id: 1, name: req.body.name };
});

fastify.listen({ port: 3000 });
```

```text
Schema 可声明的部分：
1. params —— 路由参数（/users/:id）
2. querystring —— 查询串
3. headers —— 请求头
4. body —— 请求体
5. response —— 按状态码声明响应结构（用于序列化）
```

```js
// 用 $ref 复用 Schema，避免重复声明
fastify.addSchema({
  $id: 'user',
  type: 'object',
  properties: { id: { type: 'integer' }, name: { type: 'string' } },
});

fastify.get('/users/:id', {
  schema: { response: { 200: { $ref: 'user' } } },
}, async (req) => ({ id: Number(req.params.id), name: 'Alice' }));
```

## Validation

声明 Schema 后，Fastify 会自动校验入参：参数缺失、类型不符、长度越界等，直接返回 400 并附上错误原因，业务代码无需手写校验。

```js
const fastify = require('fastify')();

fastify.post('/signup', {
  schema: {
    body: {
      type: 'object',
      required: ['email', 'password'],
      properties: {
        email: { type: 'string', format: 'email' },
        password: { type: 'string', minLength: 8 },
      },
    },
  },
}, async (req) => ({ ok: true, email: req.body.email }));

// 非法请求（缺 email、密码太短）会被框架拦截，返回 400 + 错误详情
fastify.listen({ port: 3000 });
```

```text
校验行为：
1. 入参不符合 Schema → 返回 400，body 含错误原因
2. 可自定义校验库 —— ajv 或 ajv 替代品
3. setErrorHandler 可统一自定义错误响应格式
4. 校验发生在 handler 之前，handler 拿到的一定是合法数据
```

```js
// 自定义校验错误响应
fastify.setErrorHandler((err, req, reply) => {
  if (err.validation) {
    return reply.status(400).send({ code: 'VALIDATION', detail: err.message });
  }
  reply.send(err);
});
```

## Serialization

Fastify 用声明的 response Schema 预编译序列化函数（基于 fast-json-stringify），比通用的 JSON.stringify 快得多，这也是它吞吐高的关键原因之一。

```js
const fastify = require('fastify')();

const schema = {
  response: {
    200: {
      type: 'object',
      properties: {
        id: { type: 'integer' },
        name: { type: 'string' },
      },
    },
  },
};

fastify.get('/user', { schema }, async () => {
  return { id: 1, name: 'Alice', extra: 'ignored' }; // extra 不会出现在响应里
});

fastify.listen({ port: 3000 });
```

```text
序列化机制：
1. 声明 response Schema → 框架预编译序列化函数
2. 序列化时只输出 Schema 里声明的字段
3. 比 JSON.stringify 快 2~10 倍（无运行时反射）
4. 未声明 response Schema → 回退 JSON.stringify
5. 大对象 + 高并发场景收益最明显
```

```js
// 自定义序列化器（特殊类型如 BigInt）
fastify.get('/custom', {
  schema: { response: { 200: { type: 'object' } } },
}, async () => ({ value: 123n })); // 需自定义 serialization 处理 BigInt
```

## 应用场景实战

### 场景一：带校验和序列化的用户 CRUD

```js
const fastify = require('fastify')({ logger: true });

const body = {
  type: 'object',
  required: ['name'],
  properties: { name: { type: 'string' }, age: { type: 'integer', minimum: 0 } },
};
const response = {
  type: 'object',
  properties: { id: { type: 'integer' }, name: { type: 'string' } },
};

fastify.get('/users', { schema: { response: { 200: { type: 'array', items: response } } } },
  async () => [{ id: 1, name: 'Alice' }]);

fastify.post('/users', { schema: { body, response: { 201: response } } },
  async (req, reply) => {
    const user = await db.create(req.body);
    return reply.status(201).send(user);
  });

fastify.listen({ port: 3000 });
```

### 场景二：插件拆分为独立模块

```js
// plugins/auth.js —— 鉴权插件
const fp = require('fastify-plugin');

async function auth(instance) {
  instance.decorate('authenticate', async (req, reply) => {
    const token = req.headers.authorization;
    if (!token) return reply.status(401).send({ message: 'unauthorized' });
    req.user = verify(token);
  });
}
module.exports = fp(auth);
```

```js
// app.js —— 组装
const fastify = require('fastify')();
const auth = require('./plugins/auth');

fastify.register(auth); // 全局可见（因用了 fastify-plugin）

fastify.get('/me', { onRequest: [fastify.authenticate] }, async (req) => {
  return { user: req.user };
});

fastify.listen({ port: 3000 });
```

## 最佳实践与踩坑记录

### 最佳实践

1. 路由一定要声明 response Schema，吃满序列化加速
2. 共享 Schema 用 addSchema + $ref，避免重复声明
3. 需要全局可见的装饰/钩子用 fastify-plugin 包装
4. 敏感路由用 onRequest 钩子做鉴权，别写进每个 handler
5. 生产环境开启 logger 并配置 redact 脱敏
6. 插件按功能拆分 register，用 prefix 隔离路径

### 踩坑记录

```text
坑 1：插件内装饰外部不可见
结论：父作用域调用 instance.decorate 出的方法报 undefined。
原因：封装上下文使装饰默认私有。
解法：需要对外可见的插件用 fastify-plugin 包装。

坑 2：response Schema 字段名拼错导致响应为空
结论：返回对象字段被静默丢弃。
原因：序列化器只输出 Schema 声明的字段。
解法：核对 Schema 字段名与返回对象一致。

坑 3：未声明 Schema 时性能没提升
结论：吞吐和 Express 差不多。
原因：没声明 response Schema，回退 JSON.stringify。
解法：关键热路径路由补全 Schema。

坑 4：校验错误格式不统一
结论：默认错误结构和前端约定不一致。
原因：没自定义 setErrorHandler。
解法：统一 setErrorHandler 输出错误码和详情。

坑 5：async 钩子里忘了 return reply
结论：请求挂起无响应。
原因：钩子里 reply.status().send() 没 return，函数继续执行。
解法：拦截类钩子用 return reply... 提前结束。
```

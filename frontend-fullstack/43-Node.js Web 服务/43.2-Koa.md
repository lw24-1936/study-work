## 概述

Koa 由 Express 原班人马打造，抛弃了 Express 的回调式中间件与内置能力，改为「async/await 洋葱模型 + 极简内核」。它把 req/res 合并成 ctx 上下文，中间件既是请求入口也是响应出口，能真正做到「先进入、后离开」。

```text
Koa 与 Express 的核心差异：
1. 洋葱模型 —— 中间件进入后还能返回继续执行（next 之后的代码）
2. 纯 async —— 中间件全是 async 函数，天然支持 await
3. ctx 上下文 —— 合并 req/res，挂载所有状态
4. 极简内核 —— 不含路由、body 解析，全部靠中间件补充
```

```js
const Koa = require('koa');
const app = new Koa();

app.use(async (ctx) => {
  ctx.body = 'Hello Koa';
});

app.listen(3000);
```

## Middleware

Koa 中间件是 `async (ctx, next) => {}`。洋葱模型的核心在于 `next()` 前后的代码：调用 next 前是「请求进入」，await next 返回后是「响应离开」。

```js
const Koa = require('koa');
const app = new Koa();

app.use(async (ctx, next) => {
  const start = Date.now();
  console.log('1 进入');
  await next();                 // 进入内层中间件
  console.log('1 离开', Date.now() - start, 'ms');
});

app.use(async (ctx, next) => {
  console.log('2 进入');
  await next();
  console.log('2 离开');
});

app.use(async (ctx) => {
  console.log('3 执行（最内层）');
  ctx.body = 'done';
});

// 输出顺序：1进入 → 2进入 → 3执行 → 2离开 → 1离开
app.listen(3000);
```

```text
洋葱模型执行顺序：
1. 请求自上而下依次进入每个中间件
2. 遇到 await next() 暂停，进入下一层
3. 最内层处理完响应后，自下而上依次返回
4. next() 之后的代码 = 响应阶段的收尾逻辑
```

```js
// 用洋葱模型实现「响应计时 + 统一设置响应头」
app.use(async (ctx, next) => {
  const t = Date.now();
  await next();
  ctx.set('X-Response-Time', `${Date.now() - t}ms`);
});
```

## Context

ctx 是 Koa 的核心抽象，把 Node 原生的 req/res 及其常用方法合并到一个对象上，并提供了 request/response 两层代理。

```js
app.use(async (ctx) => {
  ctx.req;          // Node 原生 request
  ctx.res;          // Node 原生 response
  ctx.request;      // Koa 的 request 包装
  ctx.response;     // Koa 的 response 包装

  ctx.method;       // 请求方法
  ctx.url;          // 完整 URL
  ctx.path;         // 路径（不含查询串）
  ctx.query;        // 查询串对象
  ctx.params;       // 路由参数（需 koa-router）
  ctx.request.body; // 请求体（需 koa-bodyparser）

  ctx.status = 200; // 状态码
  ctx.body = 'ok';  // 响应体（string/Buffer/Stream/object）
  ctx.set('X-Token', 'abc'); // 设置响应头
  ctx.type = 'json';         // Content-Type

  ctx.throw(400, 'bad request'); // 抛错 → 交给错误处理
});
```

```text
ctx 的取值优先级（同名属性）：
1. ctx 直接访问 —— 委托给 request 或 response
2. ctx.request —— 请求相关（method、url、query、header）
3. ctx.response —— 响应相关（status、body、type）
4. ctx.state —— 官方推荐的在中间件间传递数据的地方
```

```js
// ctx.state 用于中间件间传递数据
app.use(async (ctx, next) => {
  ctx.state.user = { id: 1, name: 'Alice' }; // 鉴权中间件写入
  await next();
});

app.use(async (ctx) => {
  ctx.body = { user: ctx.state.user }; // 下游读取
});
```

## Async Middleware

Koa 中间件天然是 async 函数，可以用 await 等待异步操作，错误会被 Koa 统一捕获——这是它比 Express 更优雅的地方。

```js
const Koa = require('koa');
const app = new Koa();

// 异步中间件：await 数据库/接口调用，错误自动捕获
app.use(async (ctx) => {
  const user = await db.getUser(ctx.query.id); // 无需 try/catch
  const posts = await db.getPosts(user.id);
  ctx.body = { user, posts };
});

// 顶层错误处理中间件（放在最前面）
app.use(async (ctx, next) => {
  try {
    await next();
  } catch (err) {
    ctx.status = err.status || 500;
    ctx.body = { message: err.message };
    ctx.app.emit('error', err, ctx); // 通知日志
  }
});

app.on('error', (err) => console.error('app error:', err));

app.listen(3000);
```

```text
async 中间件的优势：
1. await 直接等待 Promise，代码扁平无回调地狱
2. 中间件内部抛错会沿 await 链冒泡到外层
3. 最外层 try/catch 即可统一兜底所有错误
4. 配合 koa-router 实现带路径的 async 处理
```

```js
// 结合 @koa/router
const Router = require('@koa/router');
const router = new Router();

router.get('/users/:id', async (ctx) => {
  ctx.body = { id: ctx.params.id };
});

app.use(router.routes());
app.use(router.allowedMethods()); // 405/501 兜底
```

## 应用场景实战

### 场景一：统一鉴权 + 日志中间件

```js
const Koa = require('koa');
const app = new Koa();

// 请求日志 + 计时
app.use(async (ctx, next) => {
  const t = Date.now();
  await next();
  console.log(`${ctx.method} ${ctx.url} ${ctx.status} ${Date.now() - t}ms`);
});

// 鉴权
app.use(async (ctx, next) => {
  const token = ctx.get('Authorization');
  if (!token) ctx.throw(401, 'unauthorized');
  ctx.state.user = verify(token); // 校验并写入
  await next();
});

// 错误兜底
app.use(async (ctx, next) => {
  try {
    await next();
  } catch (err) {
    ctx.status = err.status || 500;
    ctx.body = { message: err.message };
  }
});

app.use(async (ctx) => {
  ctx.body = { user: ctx.state.user };
});

app.listen(3000);
```

### 场景二：响应压缩与缓存头

```js
const Koa = require('koa');
const compress = require('koa-compress');
const app = new Koa();

// 压缩中间件（洋葱模型在外层）
app.use(compress());

app.use(async (ctx, next) => {
  await next();
  // 响应阶段统一设置缓存头
  ctx.set('Cache-Control', 'public, max-age=3600');
});

app.use(async (ctx) => {
  ctx.body = { data: 'cached payload' };
});

app.listen(3000);
```

## 最佳实践与踩坑记录

### 最佳实践

1. 错误处理中间件放在最前面，用 try/catch 包裹 await next()
2. 中间件间共享数据用 ctx.state，别乱挂 ctx 自定义属性
3. 洋葱模型下「进入」和「离开」逻辑要分清，计时应放在 next 后
4. body 解析、压缩、日志等通用能力都靠社区中间件补齐
5. 通过 ctx.app.emit('error') 通知错误日志，避免重复打印
6. 用 @koa/router 的 allowedMethods() 兜底未实现的 HTTP 方法

### 踩坑记录

```text
坑 1：忘记 await next()
结论：内层中间件没执行，或响应顺序错乱。
原因：next() 返回 Promise，不 await 就不会等内层跑完。
解法：洋葱模型里必须 await next()。

坑 2：在 next() 之后才设置响应状态
结论：客户端收到错误的状态码或 body。
原因：响应阶段设置 status/body 会覆盖内层已写的结果。
解法：进入阶段设置默认值，离开阶段只做读取/收尾。

坑 3：错误处理中间件顺序放错
结论：错误未被捕获直接抛给客户端。
原因：错误中间件必须在外层（最前面），try/catch 才包得住内层。
解法：错误兜底中间件放 app.use 第一条。

坑 4：ctx.body 被重复赋值
结论：响应内容异常或报错。
原因：洋葱模型多个中间件都写 ctx.body。
解法：约定只有最内层业务中间件写 body。

坑 5：误用 ctx.req 原生对象
结论：拿不到 Koa 提供的便捷属性。
原因：ctx.req 是 Node 原生对象，没有 ctx.query 等封装。
解法：统一用 ctx 或 ctx.request/ctx.response。
```

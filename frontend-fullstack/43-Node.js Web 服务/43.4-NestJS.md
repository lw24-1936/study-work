## 概述

NestJS 是基于 TypeScript 的企业级 Node.js 框架，借鉴 Angular 的模块化与依赖注入思想，用装饰器把架构约束起来：Module 组织代码、Controller 处理路由、Provider 承载业务、Guard/Pipe/Interceptor 处理横切关注点。底层默认用 Express，也可切换为 Fastify。

```text
NestJS 的架构分层：
1. Module —— 应用按领域拆成模块，管理依赖
2. Controller —— 接收请求、路由分发、返回响应
3. Provider —— 可注入的服务（业务逻辑、数据库、工具）
4. 请求生命周期 —— Middleware → Guard → Interceptor → Pipe → Handler
5. Decorator —— 声明式标注类、方法、参数的元数据
```

```ts
import { NestFactory } from '@nestjs/core';
import { Module, Controller, Get } from '@nestjs/common';

@Controller()
class AppController {
  @Get()
  hello() {
    return 'Hello NestJS';
  }
}

@Module({ controllers: [AppController] })
class AppModule {}

async function bootstrap() {
  const app = await NestFactory.create(AppModule);
  await app.listen(3000);
}
bootstrap();
```

## Module

Module 是依赖注入的边界，用 `@Module` 装饰器声明自己拥有哪些 controller/provider，以及导入哪些外部模块、导出哪些 provider 给其他模块用。

```ts
import { Module } from '@nestjs/common';
import { CatsController } from './cats.controller';
import { CatsService } from './cats.service';

@Module({
  controllers: [CatsController],   // 本模块的路由
  providers: [CatsService],        // 本模块可注入的服务
  imports: [DatabaseModule],       // 引入其他模块
  exports: [CatsService],          // 导出给其他模块使用
})
export class CatsModule {}
```

```ts
// 根模块 + 全局模块
@Module({
  imports: [CatsModule, AuthModule],
})
export class AppModule {}

@Global() // 全局模块：导出后无需逐处 imports
@Module({ providers: [ConfigService], exports: [ConfigService] })
export class ConfigModule {}
```

```text
Module 的职责：
1. controllers —— 声明路由处理器
2. providers —— 声明可注入服务
3. imports —— 引入其他模块（获得其 exports）
4. exports —— 对外暴露的 provider
5. @Global() —— 标记全局模块，避免到处 imports
```

## Controller

Controller 用 `@Controller(path)` 声明路由前缀，方法上用 `@Get/@Post/@Put/@Delete/@Patch` 声明具体路由，参数用装饰器提取。

```ts
import { Controller, Get, Post, Body, Param, Query } from '@nestjs/common';

@Controller('cats')
export class CatsController {
  @Get()
  findAll(@Query('page') page = 1) {
    return `page ${page}`;
  }

  @Get(':id')
  findOne(@Param('id') id: string) {
    return { id };
  }

  @Post()
  create(@Body() body: any) {
    return { created: true, body };
  }
}
```

```text
Controller 的参数装饰器：
1. @Param('id') —— 路由参数
2. @Query('page') —— 查询串
3. @Body() —— 请求体
4. @Headers('x-token') —— 请求头
5. @Req() / @Res() —— 底层原生 request/response
```

## Provider

Provider 是「可注入的服务」，用 `@Injectable()` 标记的类，通常承载业务逻辑。Nest 的 DI 容器会负责实例化和注入。

```ts
import { Injectable } from '@nestjs/common';

@Injectable()
export class CatsService {
  private cats = [{ id: 1, name: 'Tom' }];

  findAll() {
    return this.cats;
  }

  create(cat: { name: string }) {
    this.cats.push({ id: this.cats.length + 1, ...cat });
    return this.cats.at(-1);
  }
}
```

```ts
// 注入到 Controller
@Controller('cats')
export class CatsController {
  constructor(private readonly catsService: CatsService) {} // 构造器注入

  @Get()
  findAll() {
    return this.catsService.findAll();
  }
}
```

```text
Provider 的几种注入 token：
1. 类本身 —— 默认用类作为 token
2. useValue —— 注入常量/配置对象
3. useFactory —— 工厂函数动态创建
4. useClass —— 用子类/别名替换
5. useExisting —— 复用已有 provider
```

```ts
@Module({
  providers: [
    { provide: 'CONFIG', useValue: { host: 'localhost' } },
    { provide: CatsService, useClass: CatsService },
  ],
})
export class AppModule {}
```

## Dependency Injection

Nest 通过构造器注入实现 DI：容器根据类型/元数据自动解析依赖并注入。核心是「控制反转」，组件只声明需要什么，不负责自己 new。

```ts
@Injectable()
export class DatabaseService {
  query(sql: string) {
    return [`result of ${sql}`];
  }
}

@Injectable()
export class UserService {
  // 声明依赖，由容器注入
  constructor(private readonly db: DatabaseService) {}

  getUsers() {
    return this.db.query('SELECT * FROM users');
  }
}
```

```text
DI 的三个作用域：
1. DEFAULT —— 单例，整个应用共享一个实例（默认）
2. REQUEST —— 每个请求一个实例
3. TRANSIENT —— 每次注入都创建新实例
```

```ts
import { Injectable, Scope } from '@nestjs/common';

@Injectable({ scope: Scope.REQUEST })
export class RequestScopedService {}
```

```ts
// 注入时用 @Inject 指定 token（字符串 token 必须显式指定）
constructor(@Inject('CONFIG') private config: { host: string }) {}
```

## Guard

Guard 用于鉴权，实现 `CanActivate` 接口，返回 boolean 或 Promise。它在路由处理前执行，false 则拒绝请求（403）。

```ts
import { Injectable, CanActivate, ExecutionContext } from '@nestjs/common';

@Injectable()
export class AuthGuard implements CanActivate {
  canActivate(context: ExecutionContext): boolean {
    const req = context.switchToHttp().getRequest();
    const token = req.headers.authorization;
    return !!token && token.startsWith('Bearer ');
  }
}
```

```ts
// 使用
@Controller('admin')
@UseGuards(AuthGuard) // 类级：整个 controller 生效
export class AdminController {
  @Get()
  secret() {
    return { secret: true };
  }
}
```

```text
Guard 的要点：
1. 实现 CanActivate.canActivate()
2. @UseGuards() 可用在类或方法上
3. 返回 false → 403 Forbidden
4. 可通过 Reflector 读自定义元数据做细粒度权限
```

## Interceptor

Interceptor 实现 `NestInterceptor`，可在 handler 执行前/后做拦截，常用于响应包装、日志、缓存、数据转换。

```ts
import { CallHandler, ExecutionContext, Injectable, NestInterceptor } from '@nestjs/common';
import { Observable } from 'rxjs';
import { map } from 'rxjs/operators';

@Injectable()
export class TransformInterceptor implements NestInterceptor {
  intercept(context: ExecutionContext, next: CallHandler): Observable<any> {
    return next.handle().pipe(
      map((data) => ({ code: 0, data, message: 'ok' })), // 统一响应包裹
    );
  }
}
```

```ts
// 全局注册
const app = await NestFactory.create(AppModule);
app.useGlobalInterceptors(new TransformInterceptor());
```

```text
Interceptor 的能力：
1. 在 next.handle() 前执行 —— 预处理
2. 在 pipe(map) 里执行 —— 后处理/响应转换
3. 记录耗时 —— 进入前后打时间戳
4. 可吞掉异常做降级 —— 配合 catchError
```

## Pipe

Pipe 用于数据校验与转换，实现 `PipeTransform`。内置 ValidationPipe 配合 class-validator 的 DTO 做入参校验最常用。

```ts
import { IsString, IsInt, Min, IsEmail } from 'class-validator';

export class CreateCatDto {
  @IsString()
  name: string;

  @IsInt()
  @Min(0)
  age: number;

  @IsEmail()
  email: string;
}
```

```ts
import { Body, Controller, Post, UsePipes, ValidationPipe } from '@nestjs/common';

@Controller('cats')
export class CatsController {
  @Post()
  @UsePipes(new ValidationPipe()) // 校验失败自动返回 400
  create(@Body() dto: CreateCatDto) {
    return { created: true, dto };
  }
}
```

```text
Pipe 的两种作用：
1. 校验 —— 数据不合法抛异常（400）
2. 转换 —— 把字符串转成数字/布尔等（transform: true）
```

```ts
// 自定义转换 Pipe
@Injectable()
export class ParseIntPipe implements PipeTransform {
  transform(value: string) {
    const v = parseInt(value, 10);
    if (Number.isNaN(v)) throw new BadRequestException('not a number');
    return v;
  }
}

@Get(':id')
findOne(@Param('id', ParseIntPipe) id: number) {
  return { id }; // id 已是 number
}
```

## Middleware

Nest 的 Middleware 类似 Express 中间件，实现 `NestMiddleware` 接口，在 Guard 之前执行，适用于 body 解析、日志等贴近 HTTP 层的通用逻辑。

```ts
import { Injectable, NestMiddleware } from '@nestjs/common';
import { Request, Response, NextFunction } from 'express';

@Injectable()
export class LoggerMiddleware implements NestMiddleware {
  use(req: Request, res: Response, next: NextFunction) {
    console.log(`${req.method} ${req.url}`);
    next();
  }
}
```

```ts
// 在模块里配置：应用到 /cats 路径
@Module({})
export class AppModule implements NestModule {
  configure(consumer: MiddlewareConsumer) {
    consumer.apply(LoggerMiddleware).forRoutes('cats');
  }
}
```

```text
请求处理顺序：
1. Middleware —— 最外层，接近 HTTP
2. Guard —— 鉴权
3. Interceptor（前置）—— 拦截进入
4. Pipe —— 校验/转换入参
5. Handler —— 业务处理
6. Interceptor（后置）—— 响应处理
```

## Decorator

Nest 大量使用装饰器。除了内置的，还可以用 `createParamDecorator` 自定义参数装饰器，把重复的取值逻辑抽离。

```ts
import { createParamDecorator, ExecutionContext } from '@nestjs/common';

// 自定义 @CurrentUser() 参数装饰器
export const CurrentUser = createParamDecorator(
  (data: unknown, ctx: ExecutionContext) => {
    const req = ctx.switchToHttp().getRequest();
    return req.user;
  },
);
```

```ts
@Get('me')
me(@CurrentUser() user: any) {
  return { user };
}
```

```text
自定义装饰器的类型：
1. 参数装饰器 —— createParamDecorator 提取请求信息
2. 方法/类装饰器 —— @SetMetadata 打元数据 + Reflector 读取
3. 组合装饰器 —— applyDecorators 合并多个装饰器
```

```ts
import { applyDecorators, SetMetadata } from '@nestjs/common';

export const Roles = (...roles: string[]) => applyDecorators(SetMetadata('roles', roles));
```

## 应用场景实战

### 场景一：完整的 CRUD 模块

```ts
// user.dto.ts
import { IsEmail, IsString, MinLength } from 'class-validator';

export class CreateUserDto {
  @IsEmail()
  email: string;

  @IsString()
  @MinLength(8)
  password: string;
}
```

```ts
// user.service.ts
import { Injectable } from '@nestjs/common';

@Injectable()
export class UserService {
  private users = [];
  create(dto: CreateUserDto) {
    this.users.push({ id: this.users.length + 1, ...dto });
    return this.users.at(-1);
  }
  findAll() {
    return this.users;
  }
}
```

```ts
// user.controller.ts
@Controller('users')
export class UserController {
  constructor(private readonly userService: UserService) {}

  @Get()
  findAll() {
    return this.userService.findAll();
  }

  @Post()
  @UsePipes(new ValidationPipe())
  create(@Body() dto: CreateUserDto) {
    return this.userService.create(dto);
  }
}
```

### 场景二：鉴权 + 权限 + 响应包裹组合

```ts
// 全局拦截器统一响应格式
app.useGlobalInterceptors(new TransformInterceptor());

// 全局守卫鉴权
app.useGlobalGuards(new AuthGuard());

// 控制器用 @Roles 声明权限，自定义守卫读元数据
@Controller('reports')
@UseGuards(RolesGuard)
export class ReportController {
  @Get()
  @Roles('admin')
  report() {
    return { revenue: 10000 };
  }
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. 一个领域一个 Module，模块通过 imports/exports 明确依赖边界
2. Controller 保持「薄」，业务逻辑下沉到 Provider（Service）
3. 入参校验统一用 ValidationPipe + class-validator DTO
4. 鉴权用 Guard、响应包裹用 Interceptor、入参用 Pipe，各司其职
5. 全局注册的 Guard/Pipe/Interceptor 记得在依赖注入时显式声明
6. 避免在 Controller 直接 new Service，一律走构造器注入

### 踩坑记录

```text
坑 1：Service 未加入 providers 导致注入失败
结论：启动报错 Nest can't resolve dependencies。
原因：@Injectable 的类没在 Module.providers 里注册。
解法：把服务加进对应 Module 的 providers 数组。

坑 2：全局注册的 Guard 无法注入依赖
结论：在 useGlobalGuards 里 new 的实例拿不到其他 provider。
原因：全局注册绕过容器，需用 APP_GUARD token 注册。
解法：providers 里 provide: APP_GUARD, useClass: AuthGuard。

坑 3：ValidationPipe 不生效
结论：非法入参照样进入 handler。
原因：没在方法/类上加 @UsePipes，或 DTO 没配 class-validator。
解法：加 @UsePipes(new ValidationPipe()) 并给 DTO 写装饰器。

坑 4：Module 循环依赖
结论：两个模块互相 imports 报错。
原因：A imports B，B imports A。
解法：用 forwardRef(() => B) 打破，或抽公共模块。

坑 5：忘了 transform: true
结论：@Param('id') 拿到的是字符串。
原因：ValidationPipe 默认不做类型转换。
解法：new ValidationPipe({ transform: true })。
```

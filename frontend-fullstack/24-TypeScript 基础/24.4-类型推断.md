## 概述

类型推断是 TypeScript 在未显式标注类型时，自动推导变量类型的能力。它让代码既获得类型安全，又保持简洁，是 TypeScript 日常开发最常用的机制。

```text
推断的核心机制：
1. inference —— 从初始值自动推导类型
2. contextual typing —— 从上下文推导参数类型
3. widening —— 字面量类型拓宽为更宽类型
4. narrowing —— 通过判断收窄联合类型
5. control flow analysis —— 基于控制流分析类型变化
```

```ts
// 无需标注，自动推断
let name = 'Alice';        // 推断为 string
let count = 0;             // 推断为 number
let list = [1, 2, 3];      // 推断为 number[]
```

## inference

Inference（类型推断）指编译器根据变量初始值、函数返回值等自动推导类型，无需显式标注。

```ts
// 变量推断
let message = 'hello';        // string
let num = 42;                 // number
let flag = true;              // boolean

// 函数返回值推断
function add(a: number, b: number) {
  return a + b;               // 返回类型自动推断为 number
}
```

```ts
// 对象与数组推断
const user = { name: 'Alice', age: 18 };   // { name: string; age: number }
const nums = [1, 2, 3];                     // number[]
const mixed = [1, 'two'];                   // (string | number)[]
```

```ts
// 泛型推断：从参数推断类型参数
function identity<T>(value: T) {
  return value;
}
const result = identity('hello');   // T 推断为 string，result 为 string
```

```text
最佳实践：
能推断就不要显式标注（减少冗余），
但公共 API、复杂返回值建议显式标注以提高可读性。
```

## contextual typing

Contextual typing（上下文类型）指根据变量所在位置的预期类型，推断函数参数等类型，常见于回调函数。

```ts
// 事件监听：callback 参数类型由 addEventListener 的签名推断
window.addEventListener('click', (event) => {
  // event 被上下文推断为 MouseEvent，无需标注
  console.log(event.clientX);
});
```

```ts
// 数组方法回调
const nums = [1, 2, 3];
const doubled = nums.map((n) => n * 2);   // n 推断为 number
```

```ts
// 显式标注回调类型（当上下文不足时）
const handler = (e: KeyboardEvent) => {
  console.log(e.key);
};
```

```text
上下文类型来源：
1. 函数参数 —— 由函数签名提供
2. 变量赋值 —— 由左侧标注类型提供
3. 返回语句 —— 由函数返回类型标注提供
```

## widening

Widening（类型拓宽）指字面量类型在 let 声明时自动拓宽为更宽的基础类型，以避免过窄的类型限制。

```ts
let name = 'Alice';   // 拓宽为 string（而非 'Alice'）
let num = 42;         // 拓宽为 number（而非 42）

name = 'Bob';         // 合法，因为已是 string
num = 100;            // 合法
```

```ts
// const 声明不拓宽，保留字面量类型
const greeting = 'hello';   // 类型是 'hello'（字面量）
// greeting = 'hi';         // 报错：不能改字面量
```

```ts
// 对象属性会被拓宽
const config = {
  mode: 'dark',   // 拓宽为 string
};
config.mode = 'light';   // 合法
```

```ts
// 防止拓宽：用 as const 或显式标注
const strictConfig = {
  mode: 'dark',
} as const;              // mode 类型固定为 'dark'
// strictConfig.mode = 'light';  // 报错
```

```text
拓宽规则：
1. let 声明的字面量 → 拓宽为基础类型
2. const 声明的字面量 → 保留字面量类型
3. 对象属性、数组元素 → 默认拓宽
4. 需要字面量类型时用 as const
```

## narrowing

Narrowing（类型收窄）指通过类型判断（typeof、instanceof、in 等）把宽泛的联合类型收窄为具体类型。

```ts
function format(value: string | number) {
  if (typeof value === 'string') {
    return value.toUpperCase();   // 收窄为 string
  }
  return value.toFixed(2);        // 收窄为 number
}
```

```ts
// instanceof 收窄
class Dog { bark() {} }
class Cat { meow() {} }

function speak(animal: Dog | Cat) {
  if (animal instanceof Dog) {
    animal.bark();   // 收窄为 Dog
  } else {
    animal.meow();   // 收窄为 Cat
  }
}
```

```ts
// in 收窄
type Circle = { radius: number };
type Square = { side: number };

function area(shape: Circle | Square) {
  if ('radius' in shape) {
    return Math.PI * shape.radius ** 2;   // Circle
  }
  return shape.side ** 2;                 // Square
}
```

```text
常用收窄方式：
1. typeof —— 收窄原始类型
2. instanceof —— 收窄类实例
3. in —— 收窄对象形状
4. 自定义类型守卫（is 谓词）
5. 判空（!== null）与真值判断
```

## control flow analysis

Control flow analysis（控制流分析）指编译器跟踪代码执行路径，在不同分支中自动更新变量的类型。

```ts
function getLength(value: string | null) {
  if (value === null) {
    return 0;         // 此分支 value 是 null
  }
  return value.length;   // 此分支 value 是 string（已排除 null）
}
```

```ts
// 赋值后的类型变化
let value: string | number = 'hello';
value.toUpperCase();   // string

value = 42;
value.toFixed();       // number（控制流分析更新了类型）
```

```ts
// 提前返回（early return）收窄
function process(input: string | undefined) {
  if (!input) return;      // 提前返回，排除 undefined
  input.toUpperCase();     // 此处 input 是 string
}
```

```ts
// 判别联合的控制流分析
type Result =
  | { ok: true; data: string }
  | { ok: false; error: string };

function handle(r: Result) {
  if (r.ok) {
    console.log(r.data);   // ok 为 true 时，data 可用
  } else {
    console.log(r.error);  // ok 为 false 时，error 可用
  }
}
```

```text
控制流分析能力：
1. 基于 if/switch/三元等分支收窄
2. 跟踪变量重新赋值后的类型
3. 识别 early return 后的可达代码类型
4. 分析判别联合的 discriminated union
```

## 应用场景实战

### 场景一：处理可选参数与判空

```ts
function greet(user?: { name: string } | null) {
  if (!user) {
    return 'Hello, guest';     // 控制流分析排除 null/undefined
  }
  return `Hello, ${user.name}`;   // 此处 user 是 { name: string }
}
```

### 场景二：判别联合处理异步状态

```ts
type AsyncState<T> =
  | { status: 'loading' }
  | { status: 'success'; data: T }
  | { status: 'error'; message: string };

function render<T>(state: AsyncState<T>): string {
  switch (state.status) {
    case 'loading': return '加载中...';
    case 'success': return `数据: ${state.data}`;
    case 'error': return `错误: ${state.message}`;
  }
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. 能推断就不显式标注，保持代码简洁
2. 需要固定字面量类型时用 const 或 as const
3. 善用控制流分析的 early return 收窄
4. 异步状态用判别联合，让编译器自动收窄
5. 公共 API 显式标注返回类型，提升可读性

### 踩坑记录

```text
坑 1：let 变量字面量被拓宽
结论：期望字面量类型却得到基础类型。
原因：let 声明会触发 widening。
解法：用 const，或用 as const 断言。

坑 2：回调参数报隐式 any
结论：map 回调参数类型报 any。
原因：上下文类型不足，编译器无法推断。
解法：显式标注参数类型，或确保上下文有类型信息。

坑 3：对象属性拓宽导致类型过宽
结论：config.mode 被推断为 string，丢失字面量。
原因：对象属性默认拓宽。
解法：用 as const 或显式类型标注。

坑 4：收窄失效（在闭包里用收窄变量）
结论：回调里变量类型又变回联合。
原因：闭包内的变量类型不会随外部收窄。
解法：把收窄结果赋值给 const 常量再进闭包。

坑 5：早期返回后未收窄
结论：判空后仍报可能为 undefined。
原因：判断条件写错（如只判 falsy 或判反了）。
解法：用 !value 或 value === null/undefined 明确收窄。
```

## 概述

TypeScript 在 JavaScript 之上提供了静态类型系统，通过类型标注在编译期发现错误。理解基础类型是掌握 TypeScript 的第一步。

```text
类型系统分类：
1. 原始类型 —— string、number、boolean、bigint、symbol、null、undefined
2. 引用类型 —— object、array、function
3. 特殊类型 —— any、unknown、never、void
```

```ts
// 类型标注
let name: string = 'Alice';
let age: number = 18;
let isAdmin: boolean = false;
```

## string

string 表示字符串类型，用单引号、双引号或模板字符串声明。

```ts
let s1: string = 'hello';
let s2: string = "world";
let s3: string = `模板字符串 ${s1}`;

// 常用操作
s1.toUpperCase();
s1.length;
s1.includes('h');
```

```ts
// 类型不匹配会报错
let name: string = 'Alice';
// name = 123;  // 报错：number 不能赋给 string
```

```ts
// 字符串模板与类型
function greet(user: string): string {
  return `Hello, ${user}`;
}
```

## number

number 表示数字类型，涵盖整数和浮点数，也包含 Infinity 和 NaN。

```ts
let int: number = 42;
let float: number = 3.14;
let hex: number = 0xff;       // 255
let binary: number = 0b1010;  // 10
let nan: number = NaN;
let inf: number = Infinity;
```

```ts
// 运算
let sum: number = int + float;
let rounded: number = Math.round(3.7);   // 4
```

```text
注意：
TypeScript 的 number 都是 IEEE 754 双精度浮点数，
没有区分 int/float/long，大整数精度问题用 bigint 解决。
```

## boolean

boolean 表示布尔类型，只有 true 和 false 两个值。

```ts
let isDone: boolean = true;
let isOpen: boolean = false;

// 常见于条件判断与状态标记
if (isDone) {
  console.log('完成');
}
```

```ts
// 注意：Boolean 包装对象不等于 boolean
let b1: boolean = true;              // 正确
// let b2: boolean = new Boolean(true);  // 报错：Boolean 对象不能赋给 boolean
```

```text
类型陷阱：
new Boolean(true) 返回的是对象，不是原始布尔值，
应该直接用字面量 true/false。
```

## bigint

bigint 表示任意精度的整数，用于超过 number 安全范围（2^53 - 1）的大整数，需 ES2020+ 环境。

```ts
let big: bigint = 12345678901234567890n;
let big2: bigint = BigInt(100);

// 运算（只能 bigint 与 bigint 运算）
let sum: bigint = big + big2;
```

```ts
// 不能混用 bigint 和 number
// let wrong: bigint = 100n + 100;  // 报错
let ok: bigint = 100n + BigInt(100);
```

```text
使用场景：
1. 超出安全范围的大整数（如雪花 ID）
2. 精度要求极高的金额计算（配合整数分）
注意：bigint 不能直接用 JSON.stringify，需转字符串。
```

## symbol

symbol 表示唯一且不可变的值，常用作对象属性键，避免命名冲突。

```ts
let s1: symbol = Symbol('desc');
let s2: symbol = Symbol('desc');
s1 === s2;   // false，每个 symbol 都唯一
```

```ts
// 作为对象属性键
const id = Symbol('id');
const obj = {
  [id]: 'unique-value',
  name: 'normal',
};
obj[id];   // 'unique-value'
```

```ts
// symbol 不会出现在普通遍历中
Object.keys(obj);       // ['name']，不含 symbol 键
Object.getOwnPropertySymbols(obj);  // [Symbol(id)]
```

## null 与 undefined

null 和 undefined 分别表示「空值」和「未定义」，默认是所有类型的子类型（严格模式除外）。

```ts
let u: undefined = undefined;
let n: null = null;

// 默认情况下可赋给其他类型（需关闭 strictNullChecks）
let name: string = 'Alice';
// name = null;   // strictNullChecks 开启时会报错
```

```ts
// 严格模式下的推荐写法：用联合类型显式表示可空
let maybeName: string | null = null;
maybeName = 'Alice';
```

```text
区别：
undefined —— 变量已声明但未赋值，或函数无返回值
null      —— 显式赋值的空值，表示「没有对象」
```

```ts
// 常见应用：可选参数与空值处理
function findUser(id: number): string | undefined {
  // 未找到时返回 undefined
  return undefined;
}
```

## object

object 表示非原始类型（除 string/number/boolean/bigint/symbol/null/undefined 之外的一切）。

```ts
let obj: object = { name: 'Alice' };
let arr: object = [1, 2, 3];
let fn: object = () => {};

// object 类型太宽泛，无法访问具体属性
// obj.name;  // 报错：object 上没有 name 属性
```

```ts
// 推荐：用接口或对象字面量类型描述具体结构
let user: { name: string; age: number } = { name: 'Alice', age: 18 };
user.name;   // 可访问
```

```text
注意：
1. 用 object 标注太宽泛，会丢失属性访问能力
2. 具体对象结构用 interface 或 type 描述
3. 数组、函数、类实例都属于 object
```

## unknown 与 any

unknown 表示「未知类型」，是类型安全的 any；any 表示「任意类型」，会关闭类型检查。

```ts
let anyVal: any = 'hello';
anyVal = 123;          // 合法
anyVal.toUpperCase();  // 不报错，但运行时可能崩溃

let unknownVal: unknown = 'hello';
unknownVal = 123;      // 合法
// unknownVal.toUpperCase();  // 报错：unknown 不能直接操作
```

```ts
// unknown 必须先收窄类型才能使用
if (typeof unknownVal === 'string') {
  unknownVal.toUpperCase();   // 安全，已收窄为 string
}
```

```text
对比：
any    —— 放弃检查，等于退回 JS，可做任何操作（危险）
unknown —— 保持检查，必须收窄后才能操作（安全）
```

```ts
// 最佳实践：函数入参用 unknown，先验证再用
function process(input: unknown) {
  if (typeof input === 'number') {
    return input * 2;
  }
  throw new Error('类型错误');
}
```

## never 与 void

never 表示「永不存在的值」，用于抛出异常或死循环的函数；void 表示「没有返回值」，用于无返回的函数。

```ts
// void：函数没有返回值
function log(msg: string): void {
  console.log(msg);
}

// never：函数永远不会正常返回
function fail(msg: string): never {
  throw new Error(msg);
}

function infinite(): never {
  while (true) {}
}
```

```ts
// never 用于穷尽检查
type Shape = 'circle' | 'square';
function area(s: Shape): number {
  switch (s) {
    case 'circle': return 3.14;
    case 'square': return 4;
    default:
      const exhaustive: never = s;   // 若漏掉分支，此处报错
      return exhaustive;
  }
}
```

```text
区别：
void   —— 函数执行完返回 undefined（有返回点）
never  —— 函数永远到不了 return（抛错或死循环）
never 是所有类型的子类型，可赋给任何类型；任何类型都不能赋给 never。
```

## 应用场景实战

### 场景一：定义业务实体的基础类型

```ts
interface User {
  id: bigint;                    // 雪花 ID，用 bigint
  name: string;
  age: number;
  isVip: boolean;
  nickname?: string;             // 可空
  token?: string | null;         // 显式可空
}

const user: User = {
  id: 12345678901234567890n,
  name: 'Alice',
  age: 25,
  isVip: true,
};
```

### 场景二：处理未知外部数据

```ts
// 解析 API 返回，用 unknown 保证安全
function parseResponse(raw: unknown): User | undefined {
  if (typeof raw !== 'object' || raw === null) return undefined;
  const obj = raw as Record<string, unknown>;
  if (typeof obj.name === 'string' && typeof obj.age === 'number') {
    return { id: 0n, name: obj.name, age: obj.age, isVip: false };
  }
  return undefined;
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. 能标注具体类型就别用 any，用 unknown 处理未知输入
2. 开启 strictNullChecks，显式声明可空类型（string | null）
3. 大整数用 bigint，金额用「分」为单位的整数
4. 对象结构用 interface/type 描述，别用宽泛的 object
5. 函数无返回用 void，抛错/死循环用 never

### 踩坑记录

```text
坑 1：滥用 any 丢失类型检查
结论：代码看似通过，运行时却报错。
原因：any 关闭了类型检查，等于退回 JavaScript。
解法：用 unknown 或具体类型替代，必要时用类型收窄。

坑 2：bigint 与 number 混用报错
结论：100n + 100 直接报类型错误。
原因：bigint 和 number 不能直接运算。
解法：统一用 BigInt() 转换后再运算。

坑 3：new Boolean 赋给 boolean 报错
结论：let b: boolean = new Boolean(true) 编译失败。
原因：包装对象 Boolean 不是原始类型 boolean。
解法：直接用字面量 true/false。

坑 4：JSON 序列化 bigint 抛异常
结论：JSON.stringify 含 bigint 的对象报错。
原因：bigint 不被 JSON 支持。
解法：序列化前把 bigint 转成字符串。

坑 5：object 类型无法访问属性
结论：标注 object 后访问属性报错。
原因：object 是宽泛类型，不含具体属性签名。
解法：用 interface 或对象字面量类型描述具体结构。
```

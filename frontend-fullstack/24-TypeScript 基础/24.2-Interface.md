## 概述

Interface（接口）是 TypeScript 描述对象结构、约束类型形状的核心工具。它定义「一个对象应该有哪些属性、是什么类型」，是面向对象与结构化类型的基石。

```text
Interface 的能力：
1. 描述对象结构 —— 定义属性名与类型
2. 可选属性 —— optional property
3. 只读属性 —— readonly
4. 索引签名 —— index signature
5. 继承扩展 —— extends
6. 声明合并 —— declaration merging
```

```ts
interface User {
  name: string;
  age: number;
}
const u: User = { name: 'Alice', age: 18 };
```

## interface

interface 用于定义类型契约，规定对象的属性结构。类型检查基于「结构」，而非名称（结构化类型系统）。

```ts
interface Point {
  x: number;
  y: number;
}

function draw(p: Point) {
  console.log(p.x, p.y);
}

// 结构匹配即可，无需显式声明 implements
draw({ x: 10, y: 20 });
```

```ts
// 接口也可描述函数和类
interface Comparator {
  (a: number, b: number): number;   // 函数签名
}

interface Entity {
  id: number;
  save(): void;                     // 方法签名
}
```

```text
interface 与 type 的区别：
1. interface 可声明合并（同名自动合并），type 不行
2. interface 只能用对象/函数结构，type 可表示任意类型（联合、元组等）
3. interface 更面向「扩展」，type 更面向「组合」
```

## optional property

Optional property（可选属性）用 ? 标记，表示该属性可以不存在。访问可选属性时类型会自动加上 undefined。

```ts
interface Config {
  url: string;
  timeout?: number;      // 可选
  retries?: number;      // 可选
}

const c1: Config = { url: '/api' };                 // 合法，省略可选属性
const c2: Config = { url: '/api', timeout: 1000 };
```

```ts
// 访问可选属性需处理 undefined
if (c1.timeout !== undefined) {
  console.log(c1.timeout);   // 收窄为 number
}
c1.timeout?.toFixed();        // 可选链
```

```text
可选属性本质：
timeout?: number 等价于 timeout?: number | undefined，
使用前需做空值判断或可选链。
```

## readonly

readonly 标记属性为只读，初始化后不可修改。它只在编译期生效，运行时不阻止修改。

```ts
interface User {
  readonly id: number;
  name: string;
}

const u: User = { id: 1, name: 'Alice' };
// u.id = 2;   // 报错：只读属性不能赋值
u.name = 'Bob';   // 合法
```

```ts
// 只读数组
const nums: readonly number[] = [1, 2, 3];
// nums.push(4);   // 报错：readonly 数组不能 push
```

```text
注意：
1. readonly 是编译期约束，编译后可被绕过
2. 对象属性只读 ≠ 对象本身只读（可用 const 或 as const）
3. readonly 数组不能用会改变原数组的方法（push/pop/sort）
```

## index signature

Index signature（索引签名）允许对象拥有「任意多个」符合某类型的属性，用键的类型约束属性名。

```ts
interface StringMap {
  [key: string]: string;    // 任意字符串键，值必须是 string
}

const map: StringMap = {
  name: 'Alice',
  city: '北京',
};
```

```ts
// 数字索引签名（常用于数组）
interface NumberMap {
  [index: number]: string;
}
const arr: NumberMap = ['a', 'b', 'c'];
arr[0];   // 'a'
```

```ts
// 索引签名与具体属性共存时，具体属性类型必须兼容
interface Dictionary {
  [key: string]: number;
  length: number;      // 兼容，number 满足索引签名
  // name: string;     // 报错：string 不满足 number 索引签名
}
```

```text
使用场景：
1. 字典/映射类数据结构
2. 未知键名的动态配置对象
3. 键类型只能是 string 或 number
```

## extends

extends 用于接口继承，子接口获得父接口的所有成员，并可扩展新成员，支持多重继承。

```ts
interface Animal {
  name: string;
}

interface Dog extends Animal {
  bark(): void;
}

const dog: Dog = { name: '旺财', bark: () => console.log('汪') };
```

```ts
// 多重继承
interface Flyable { fly(): void; }
interface Swimmable { swim(): void; }

interface Duck extends Flyable, Swimmable {
  quack(): void;
}

const duck: Duck = {
  fly: () => {},
  swim: () => {},
  quack: () => {},
};
```

```ts
// 继承时覆盖父接口成员（类型需兼容）
interface ReadonlyUser {
  readonly id: number;
}
interface MutableUser extends ReadonlyUser {
  // id: string;  // 报错：与父接口冲突
}
```

## declaration merging

Declaration merging（声明合并）指同名 interface 会自动合并成一个接口，属性叠加。这是 interface 独有的能力，type 别名不支持。

```ts
interface Box {
  width: number;
}

interface Box {
  height: number;   // 自动合并到 Box
}

const box: Box = { width: 10, height: 20 };   // 两个属性都可用
```

```ts
// 典型应用：给第三方库扩展类型
interface Window {
  myGlobal: string;   // 合并到全局 Window 接口
}

// 现在可以访问
window.myGlobal;
```

```text
声明合并规则：
1. 同名 interface 的属性会合并
2. 同名方法会形成重载（顺序：后声明的优先）
3. 属性类型冲突会报错
```

```ts
// 方法重载的合并顺序
interface Logger {
  log(msg: string): void;
}
interface Logger {
  log(level: number): void;
}
// 合并后 log 有两个重载签名
```

## 应用场景实战

### 场景一：API 响应类型定义

```ts
interface ApiResponse<T> {
  code: number;
  message: string;
  data: T;
}

interface User {
  readonly id: number;
  name: string;
  email?: string;
}

interface Pagination {
  page: number;
  pageSize: number;
  total: number;
}

interface UserList {
  list: User[];
  pagination: Pagination;
}

// 组装类型
type UserListResponse = ApiResponse<UserList>;
```

### 场景二：可扩展的组件 Props

```ts
interface BaseProps {
  id: string;
  className?: string;
  [key: `data-${string}`]: string | undefined;  // 支持 data-* 属性
}

interface ButtonProps extends BaseProps {
  label: string;
  disabled?: boolean;
  onClick?: () => void;
}

function Button(props: ButtonProps) {
  const { label, disabled, onClick, ...rest } = props;
  return { label, disabled, onClick, rest };
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. 描述对象结构优先用 interface，组合类型用 type
2. 可空属性用 ? 标记，避免强制传 undefined
3. 不可变标识（id 等）用 readonly
4. 字典/动态键对象用索引签名
5. 给第三方库扩展类型用声明合并（interface）

### 踩坑记录

```text
坑 1：同名 type 与 interface 混淆合并行为
结论：以为 type 也能像 interface 一样自动合并。
原因：只有 interface 支持声明合并，type 别名重复定义报错。
解法：需要合并能力时用 interface。

坑 2：readonly 误以为运行时不可变
结论：运行时仍能改只读属性，出现意外修改。
原因：readonly 只在编译期检查，编译后无约束。
解法：需要真不可变用 Object.freeze 或运行时方案。

坑 3：可选属性访问未做空值判断
结论：访问可选属性报 undefined 相关错误。
原因：timeout?: number 本质是 number | undefined。
解法：用可选链 ?. 或先判空。

坑 4：索引签名与具体属性类型冲突
结论：加了索引签名后，其他属性类型报错。
原因：具体属性类型必须兼容索引签名类型。
解法：统一索引签名类型，或用联合类型放宽。

坑 5：extends 继承后属性被意外覆盖
结论：子接口属性与父接口冲突报错。
原因：覆盖的类型与父接口不兼容。
解法：保持类型兼容，或调整设计避免冲突。
```

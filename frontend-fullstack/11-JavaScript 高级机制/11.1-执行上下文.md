## 概述

执行上下文（Execution Context）是 JavaScript 引擎执行代码时的「运行环境」，包含变量、作用域、this 等信息。理解执行上下文的创建与销毁，是理解提升、闭包、作用域链的底层基础。

```text
执行上下文包含三部分：
1. 词法环境（Lexical Environment）—— 变量/函数绑定 + 外层引用
2. 变量环境（Variable Environment）—— var 声明绑定（特殊词法环境）
3. this 绑定 —— 当前执行上下文的 this 值

两类执行上下文：
全局执行上下文 —— 代码开始执行时创建，唯一
函数执行上下文 —— 每次函数调用创建，调用结束销毁
```

## Global Execution Context 全局执行上下文

全局执行上下文是 JS 引擎启动时创建的第一个上下文，整个程序只有一个。

```text
全局执行上下文的特征：
1. 程序启动时创建，程序结束才销毁
2. 全局变量、函数声明绑定在这里
3. 全局 this 指向全局对象（浏览器 window / Node globalThis）
4. 位于执行上下文栈的最底部
```

```js
// 全局代码
var a = 1;              // 绑定到全局环境
function foo() {}       // 函数声明提升到全局环境

console.log(this === window);   // true（浏览器环境）
```

```text
全局环境的两层：
外层（对象环境记录）—— 全局对象（window）的属性（var、函数声明）
内层（声明环境记录）—— let/const/class 等块级声明（不在 window 上）
```

```js
// var 与 let 在全局的差异
var a = 1;
let b = 2;

window.a;        // 1（var 挂到全局对象）
window.b;        // undefined（let 不挂到全局对象）
```

## Function Execution Context 函数执行上下文

每次调用函数都会创建一个新的函数执行上下文，函数执行完毕后销毁（除非被闭包引用）。

```text
函数执行上下文的创建（调用时）分两步：
1. 创建阶段 —— 建立词法环境、变量环境、this 绑定、处理参数
2. 执行阶段 —— 逐行执行代码、变量赋值、函数调用

创建阶段的「提升」：
函数声明 → 整体提升
var 声明 → 提升为 undefined
let/const → 提升但进入 TDZ
```

```js
function foo(x) {
  var a = 1;
  let b = 2;
  return x + a + b;
}

foo(10);   // 调用时创建函数执行上下文，返回后销毁
```

## Lexical Environment 词法环境

词法环境是管理**标识符绑定**的内部结构，每个执行上下文都有一个。

```text
词法环境组成：
1. 环境记录（Environment Record）—— 当前作用域的变量/函数/参数绑定
2. 外部引用（outer）—— 指向外层词法环境（形成作用域链）

类型：
全局词法环境 —— 程序级
函数词法环境 —— 每次函数调用
块级词法环境 —— 每个 {} 块
```

```js
function outer() {
  const x = 10;          // 记录在 outer 的词法环境
  function inner() {
    console.log(x);      // 通过 outer 引用向上查找 x
  }
  return inner;
}
```

```text
词法环境与闭包：
当内层函数引用外层变量时，外层词法环境被保留（不随函数结束销毁），
这就是闭包的底层机制。
```

## Variable Environment 变量环境

变量环境是「特殊的词法环境」，专门存放 var 声明。它与词法环境在多数情况下相同，区别在 var 的处理。

```text
变量环境 vs 词法环境：
词法环境 —— 存放 let、const、class 等块级声明
变量环境 —— 存放 var 声明（函数作用域）

ES6 引入 let/const 后，为区分二者而设。
变量环境实际是词法环境的变体，多数教材二者可等同理解。
```

```js
function demo() {
  var a = 1;       // 进入变量环境
  let b = 2;       // 进入词法环境（块级）
  const c = 3;     // 进入词法环境

  if (true) {
    var d = 4;     // 仍在函数级变量环境（var 无块级）
    let e = 5;     // 块级词法环境
  }
}
```

## Environment Record 环境记录

环境记录是词法环境内部的实际存储结构，保存标识符到值的映射。

```text
环境记录的类型：
1. 声明式环境记录 —— 函数/块作用域的变量绑定（let/const/函数）
2. 对象式环境记录 —— 全局对象的属性绑定（var、全局函数）
3. 全局环境记录 —— 组合上面两种（全局特有）

每种记录都提供 hasBinding、getBindingValue、setMutableBinding 等操作。
```

```js
// 环境记录的直观理解：作用域内的「变量表」
function fn() {
  // 环境记录 = { x: undefined → 10, inner: <函数> }
  var x = 10;
  function inner() {}
}
```

## 执行上下文栈

执行上下文栈（调用栈，Call Stack）是 LIFO（后进先出）结构，管理上下文的创建与销毁。

```text
调用栈机制：
1. 程序启动 → 全局上下文入栈（栈底）
2. 调用函数 → 函数上下文入栈（栈顶）
3. 函数返回 → 函数上下文出栈销毁
4. 栈顶始终是「正在执行」的上下文
```

```js
function a() {
  b();          // b 入栈
  // b 出栈
}
function b() {
  console.log('b');
}

a();            // a 入栈 → b 入栈 → b 出栈 → a 出栈
```

```text
栈溢出（Stack Overflow）：
无限递归会导致调用栈无限增长，超出限制报 RangeError: Maximum call stack size exceeded。
```

```js
function recurse() { recurse(); }
recurse();       // RangeError: Maximum call stack size exceeded
```

## 应用场景实战

### 场景一：理解提升现象

```js
console.log(typeof foo);   // 'function'（函数声明整体提升）
console.log(typeof bar);   // 'undefined'（var 提升为 undefined）
// console.log(baz);       // ReferenceError（let 处于 TDZ）

function foo() {}
var bar = 1;
let baz = 2;
```

### 场景二：递归改迭代避免栈溢出

```js
// 递归：深数据会栈溢出
function sumRec(n) {
  return n <= 0 ? 0 : n + sumRec(n - 1);
}

// 迭代：避免栈溢出
function sumIter(n) {
  let total = 0;
  for (let i = 1; i <= n; i++) total += i;
  return total;
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. 理解「创建阶段做提升、执行阶段做赋值」的时序
2. 用 let/const 替代 var，减少提升带来的困惑
3. 递归注意栈深度，深递归改用迭代或尾调用优化
4. 全局变量尽量少，避免污染全局环境记录
5. 理解闭包 = 保留词法环境，及时释放不再使用的引用

### 踩坑记录

```text
坑 1：混淆提升与赋值
结论：console.log(a) 得到 undefined，以为是「没提升」。
原因：var 提升的是声明（undefined），赋值仍留在原地。
解法：理解「声明提升、赋值不提升」。

坑 2：函数表达式不能提前调用
结论：提前调用函数表达式报 TypeError。
原因：函数表达式只提升变量（undefined），函数体不提升。
解法：用函数声明，或在定义后调用。

坑 3：let 在 TDZ 内访问报错
结论：声明前访问 let 变量抛 ReferenceError。
原因：let 提升但进入 TDZ（未初始化）。
解法：声明在访问之前。

坑 4：深递归栈溢出
结论：递归处理大数据报 Maximum call stack size exceeded。
原因：每层调用占栈空间，深度超限。
解法：改迭代，或尾调用优化，或分批处理。

坑 5：误以为 var 有块级作用域
结论：if 块内 var 的变量块外可访问。
原因：var 是函数作用域，块不产生新作用域。
解法：用 let/const 实现块级作用域。
```

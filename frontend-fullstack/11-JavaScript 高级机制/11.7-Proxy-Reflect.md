## 概述

Proxy 用于**拦截**对象的操作，Reflect 提供**统一执行**这些操作的方法。二者配合构成 JavaScript 的元编程能力。

```text
Proxy —— 在目标对象外包一层「代理」，拦截读写等操作
Reflect —— 一组函数，以函数形式执行对象的默认操作

二者的关系：
Proxy 的每个 trap（陷阱）都与 Reflect 的方法一一对应，
trap 内调用 Reflect 可以执行默认行为。
```

## Proxy 代理

Proxy 通过 `new Proxy(target, handler)` 创建，handler 定义拦截哪些操作。

```js
const target = { name: 'Alice' };

const proxy = new Proxy(target, {
  get(obj, key) {
    console.log(`读取 ${key}`);
    return obj[key];
  },
  set(obj, key, value) {
    console.log(`设置 ${key} = ${value}`);
    obj[key] = value;
    return true;
  },
});

proxy.name;          // 打印「读取 name」，返回 'Alice'
proxy.age = 30;      // 打印「设置 age = 30」
```

```text
Proxy 的 13 个陷阱（trap）：
get / set / has / deleteProperty / ownKeys /
getOwnPropertyDescriptor / defineProperty / preventExtensions /
getPrototypeOf / setPrototypeOf / isExtensible /
apply / construct
```

```js
// 完整 handler 结构
const handler = {
  get(target, key, receiver) { return Reflect.get(target, key, receiver); },
  set(target, key, value, receiver) { return Reflect.set(target, key, value, receiver); },
  has(target, key) { return Reflect.has(target, key); },
  deleteProperty(target, key) { return Reflect.deleteProperty(target, key); },
  ownKeys(target) { return Reflect.ownKeys(target); },
  apply(target, thisArg, args) { return Reflect.apply(target, thisArg, args); },
  construct(target, args) { return Reflect.construct(target, args); },
};
```

## get / set 陷阱

get 拦截读取，set 拦截写入，是最常用的两个陷阱，可实现响应式、数据校验等。

```js
// get 陷阱：默认值
const withDefault = new Proxy({}, {
  get(target, key) {
    return key in target ? target[key] : '默认值';
  },
});
withDefault.anything;    // '默认值'
```

```js
// set 陷阱：数据校验
const user = new Proxy({}, {
  set(target, key, value) {
    if (key === 'age' && (value < 0 || value > 150)) {
      throw new Error('年龄非法');
    }
    target[key] = value;
    return true;             // 必须返回 true，否则静默失败/报错
  },
});
user.age = 30;               // 正常
// user.age = -1;            // 抛错
```

```text
get/set 的 receiver 参数：
receiver 指向「实际触发操作的代理」，
用于正确传递 this（尤其涉及原型链继承时）。
```

```js
// 响应式的雏形：set 时触发回调
function reactive(target, onChange) {
  return new Proxy(target, {
    set(obj, key, value) {
      obj[key] = value;
      onChange(key, value);
      return true;
    },
  });
}
```

## has / deleteProperty 陷阱

has 拦截 `in` 运算符，deleteProperty 拦截 delete 操作。

```js
const hidden = new Proxy({ secret: 1, visible: 2 }, {
  has(target, key) {
    if (key === 'secret') return false;   // 隐藏 secret 的存在
    return Reflect.has(target, key);
  },
});

'secret' in hidden;    // false（被隐藏）
'visible' in hidden;   // true
```

```js
const protected = new Proxy({ locked: 1, free: 2 }, {
  deleteProperty(target, key) {
    if (key === 'locked') return false;   // 禁止删除
    return Reflect.deleteProperty(target, key);
  },
});

delete protected.locked;   // false（删除被拦截）
delete protected.free;     // true
```

## ownKeys 陷阱

ownKeys 拦截 Object.keys、for...in、Object.getOwnPropertyNames 等操作，可隐藏或排序键。

```js
const filtered = new Proxy({ _private: 1, a: 2, b: 3 }, {
  ownKeys(target) {
    // 过滤下划线开头的「私有」键
    return Reflect.ownKeys(target).filter(k => !String(k).startsWith('_'));
  },
});

Object.keys(filtered);   // ['a', 'b']（_private 被隐藏）
```

```text
ownKeys 的约束：
1. 返回结果必须是数组（含字符串和 Symbol）
2. 不能包含不可配置的属性键（否则报错）
3. 需与 getOwnPropertyDescriptor 配合，否则行为不一致
```

## apply / construct 陷阱

apply 拦截函数调用，construct 拦截 new 操作。

```js
// apply：给函数加日志
function sum(a, b) { return a + b; }

const loggedSum = new Proxy(sum, {
  apply(target, thisArg, args) {
    console.log(`调用 sum(${args})`);
    return Reflect.apply(target, thisArg, args);
  },
});

loggedSum(1, 2);         // 打印日志，返回 3
```

```js
// construct：拦截 new，实现单例
class Service {}
let instance = null;

const Singleton = new Proxy(Service, {
  construct(target, args) {
    if (!instance) instance = new target(...args);
    return instance;
  },
});

const a = new Singleton();
const b = new Singleton();
a === b;                 // true（单例）
```

## Reflect 反射

Reflect 把对象操作统一为函数式 API，返回值更规范（布尔/结果，而非抛错）。

```text
Reflect 的价值：
1. 函数式 —— Reflect.get(obj, key) 替代 obj[key]
2. 返回值一致 —— defineProperty 等返回布尔而非抛错
3. 与 Proxy 对应 —— 每个 trap 都有对应的 Reflect 方法
4. 明确失败 —— deleteProperty 返回 false 而非静默
```

```js
const obj = { name: 'Alice' };

Reflect.get(obj, 'name');         // 'Alice'（替代 obj.name）
Reflect.set(obj, 'age', 30);      // true（替代 obj.age = 30）
Reflect.has(obj, 'name');         // true（替代 'name' in obj）
Reflect.deleteProperty(obj, 'x'); // false（替代 delete obj.x）
Reflect.ownKeys(obj);             // ['name', 'age']
```

```text
Reflect vs Object 的对应：
Object.defineProperty → Reflect.defineProperty（返回布尔）
delete obj.k → Reflect.deleteProperty（返回布尔）
key in obj → Reflect.has
Object.keys → Reflect.ownKeys（含 Symbol）
Function.apply → Reflect.apply
```

```js
// 典型模式：Proxy trap 内用 Reflect 执行默认行为
const proxy = new Proxy(target, {
  get(target, key, receiver) {
    // 自定义逻辑...
    return Reflect.get(target, key, receiver);   // 默认读取
  },
});
```

## 应用场景实战

### 场景一：响应式数据（Vue 3 原理）

```js
function reactive(target) {
  return new Proxy(target, {
    get(obj, key) {
      track(key);          // 依赖收集
      return Reflect.get(obj, key);
    },
    set(obj, key, value) {
      Reflect.set(obj, key, value);
      trigger(key);        // 触发更新
      return true;
    },
  });
}

const state = reactive({ count: 0 });
state.count++;             // 自动触发依赖更新
```

### 场景二：对象访问守卫

```js
function guarded(obj, allowedKeys) {
  return new Proxy(obj, {
    get(target, key) {
      if (!allowedKeys.includes(key)) {
        throw new Error(`禁止访问 ${key}`);
      }
      return Reflect.get(target, key);
    },
  });
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. trap 内用 Reflect 执行默认行为，避免破坏语义
2. set/deleteProperty 等 trap 必须返回正确的布尔值
3. 响应式、校验、日志等横切逻辑用 Proxy 优雅实现
4. ownKeys 需与 getOwnPropertyDescriptor 保持一致
5. Proxy 无法完全模拟目标对象，需理解其边界

### 踩坑记录

```text
坑 1：set trap 不返回 true
结论：赋值静默失败（严格模式抛 TypeError）。
原因：set trap 必须返回 true 表示成功。
解法：trap 末尾 return true（或 Reflect.set 的返回值）。

坑 2：ownKeys 返回不可配置键
结论：Object.keys 抛 TypeError。
原因：ownKeys 不能省略不可配置属性键。
解法：返回结果必须包含所有不可配置属性。

坑 3：Proxy 的 this 指向代理而非目标
结论：方法内 this 是代理对象，可能触发意外的 trap。
原因：通过代理调用方法，this 绑定到代理。
解法：用 receiver 正确传递，或绑定目标。

坑 4：Reflect 与 Proxy 不配合导致递归
结论：trap 内又访问代理，无限触发 trap。
原因：trap 内用了代理而非目标/Reflect。
解法：trap 内用 target 或 Reflect，别再用 proxy。

坑 5：以为 Proxy 能拦截所有操作
结论：部分操作（如严格相等 ===）无法拦截。
原因：Proxy 只能拦截 13 种 trap，=== 等无 trap。
解法：理解 Proxy 能力边界，复杂需求用其他手段。
```

## 概述

this 是函数执行时的动态上下文，它的值**在函数调用时确定**（箭头函数除外），由调用方式决定，而非定义位置。掌握 this 的绑定规则是理解 JavaScript 的关键。

```text
this 的确定方式（按优先级从高到低）：
1. new 绑定 —— 构造函数调用，this 指向新实例
2. 显式绑定 —— call / apply / bind，this 指向指定对象
3. 隐式绑定 —— 对象方法调用，this 指向调用对象
4. 默认绑定 —— 普通函数调用，this 指向全局（严格模式 undefined）

例外：箭头函数没有自己的 this，继承外层（词法绑定）。
```

## Global this 全局 this

全局作用域或普通函数调用中，this 指向全局对象（严格模式为 undefined）。

```js
// 全局 this
console.log(this === window);   // true（浏览器）
console.log(this);              // globalThis

// 普通函数调用（默认绑定）
function fn() {
  console.log(this);            // window（非严格模式）
}
fn();
```

```js
// 严格模式：普通函数 this 为 undefined
'use strict';
function strictFn() {
  console.log(this);            // undefined
}
strictFn();
```

```text
默认绑定的规则：
非严格模式 —— this 指向全局对象
严格模式 —— this 为 undefined

注意：函数体是否严格模式，取决于函数自身的声明，与调用位置无关。
```

## Object Method 对象方法中的 this

作为对象方法调用时，this 指向**调用该方法的对象**（隐式绑定）。

```js
const user = {
  name: 'Alice',
  greet() {
    console.log(this.name);     // this 指向 user
  },
};

user.greet();                   // 'Alice'
```

```text
隐式绑定的坑：方法被「提取」后调用，this 会丢失。
```

```js
const user = {
  name: 'Alice',
  greet() { console.log(this.name); },
};

const g = user.greet;   // 提取方法
g();                    // undefined（this 丢失，指向全局）
```

```js
// 嵌套对象：this 指向最近调用对象
const obj = {
  name: 'obj',
  inner: {
    name: 'inner',
    greet() { console.log(this.name); },
  },
};
obj.inner.greet();      // 'inner'（最近调用者）
```

## Constructor 构造函数中的 this

用 new 调用构造函数时，this 指向新创建的实例对象（new 绑定）。

```js
function Person(name) {
  this.name = name;      // this 指向新实例
}

const p = new Person('Alice');
p.name;                  // 'Alice'
```

```text
new 的执行过程：
1. 创建一个新空对象
2. 新对象的原型指向构造函数的 prototype
3. this 绑定到新对象
4. 执行构造函数体
5. 返回新对象（除非显式返回对象）
```

```js
// class 构造函数的 this 同理
class Dog {
  constructor(name) {
    this.name = name;
  }
}
const d = new Dog('wang');
d.name;                 // 'wang'
```

## call / apply / bind 显式绑定

call、apply、bind 可以**显式指定** this 的值（显式绑定）。

```text
call(thisArg, arg1, arg2, ...)  —— 立即调用，参数逐个传
apply(thisArg, [argsArray])     —— 立即调用，参数用数组传
bind(thisArg, arg1, ...)        —— 返回新函数，不立即调用
```

```js
function greet(greeting, punctuation) {
  console.log(`${greeting}, ${this.name}${punctuation}`);
}

const user = { name: 'Alice' };

greet.call(user, 'Hello', '!');       // Hello, Alice!
greet.apply(user, ['Hi', '?']);       // Hi, Alice?
const bound = greet.bind(user, 'Hey'); // 返回新函数
bound('.');                            // Hey, Alice.
```

```js
// bind 的典型用途：固定 this，解决回调中的 this 丢失
const obj = {
  name: 'Alice',
  greet() { console.log(this.name); },
};

setTimeout(obj.greet, 0);              // undefined（this 丢失）
setTimeout(obj.greet.bind(obj), 0);    // 'Alice'（bind 固定）
```

```text
call / apply / bind 的选择：
立即调用 + 参数列表 → call
立即调用 + 参数数组 → apply（现在多用展开符 + call 替代）
延迟调用 / 固定 this → bind
```

## Arrow Function 箭头函数的 this

箭头函数**没有自己的 this**，它的 this 是词法继承自**定义时**的外层作用域，且不能被 call/apply/bind 改变。

```js
const user = {
  name: 'Alice',
  greet() {
    // 箭头函数继承 greet 的 this（即 user）
    setTimeout(() => {
      console.log(this.name);    // 'Alice'
    }, 100);
  },
};
user.greet();
```

```js
// 箭头函数的 this 无法被改变
const arrow = () => console.log(this);
const obj = { name: 'x' };
arrow.call(obj);        // 仍指向定义处外层，call 无效
```

```text
箭头函数 vs 普通函数：
箭头函数 —— this 词法绑定（继承外层），不能 new，无 arguments
普通函数 —— this 动态绑定（由调用方式决定）

回调、事件处理器需要继承 this 时 → 箭头函数
对象方法、构造函数需要动态 this → 普通函数
```

## this Binding 绑定规则总结

```text
绑定优先级（从高到低）：
1. new 绑定 —— new fn()，this = 新实例
2. 显式绑定 —— call/apply/bind，this = 指定对象
3. 隐式绑定 —— obj.fn()，this = 调用对象
4. 默认绑定 —— fn()，this = 全局 / undefined（严格）

箭头函数例外：永远继承外层（词法），不受上述规则影响。
```

```js
// 优先级验证：显式绑定 > 隐式绑定
function fn() { console.log(this.name); }
const obj = { name: 'obj', fn };
const other = { name: 'other' };

obj.fn();                    // 'obj'（隐式）
obj.fn.call(other);          // 'other'（显式覆盖隐式）
```

```js
// new 绑定 > 显式绑定
function Fn(name) { this.name = name; }
const bound = Fn.bind({ name: 'bound' });
const instance = new bound('instance');
instance.name;               // 'instance'（new 优先级更高）
```

## 应用场景实战

### 场景一：类组件事件处理绑定 this

```js
class Button {
  constructor() {
    this.count = 0;
    // 绑定 this（或用箭头函数字段）
    this.handleClick = this.handleClick.bind(this);
  }
  handleClick() {
    this.count++;
  }
}
```

### 场景二：函数借用其他对象的方法

```js
// 用 call/apply 借用数组方法
const arrayLike = { 0: 'a', 1: 'b', length: 2 };

Array.prototype.forEach.call(arrayLike, (item) => {
  console.log(item);      // a b
});

const max = Math.max.apply(null, [1, 5, 3]);   // 5
```

## 最佳实践与踩坑记录

### 最佳实践

1. 回调需继承 this 用箭头函数
2. 对象方法、构造函数用普通函数或方法简写
3. 需要固定 this 用 bind（或箭头函数）
4. 优先用箭头函数避免 this 丢失，减少 bind 样板
5. 理解优先级：new > 显式 > 隐式 > 默认

### 踩坑记录

```text
坑 1：方法提取后 this 丢失
结论：const g = obj.fn; g() 后 this 不是 obj。
原因：提取后是普通函数调用（默认绑定）。
解法：用 bind 固定，或箭头函数字段。

坑 2：箭头函数当对象方法
结论：对象方法用箭头函数，this 指向外层而非对象。
原因：箭头函数词法继承外层 this。
解法：对象方法用普通函数或方法简写。

坑 3：回调中 this 指向全局
结论：setTimeout(obj.fn) 里 this 不是 obj。
原因：回调是普通函数调用，this 默认绑定。
解法：箭头函数包裹，或 bind 绑定。

坑 4：strict 模式下 this 为 undefined
结论：严格模式下普通函数 this 是 undefined，访问属性报错。
原因：严格模式默认绑定不指向全局。
解法：明确 this 绑定，或避免依赖默认 this。

坑 5：箭头函数 this 无法用 call 改
结论：arrow.call(obj) 无效。
原因：箭头函数 this 词法绑定，忽略 call/apply/bind。
解法：需要动态 this 用普通函数。
```

## 概述

WASM 不是「一门语言」，而是「一个编译目标」。任何能编译成 WASM 的语言都可以在浏览器运行。选哪种语言，取决于你想复用什么生态、团队熟悉什么、以及产物体积的接受度。

```text
主流编译到 WASM 的语言：
1. C / C++   —— 生态最庞大，Emscripten 支持最成熟
2. Rust      —— 内存安全 + 现代工具链，前端最爱
3. AssemblyScript —— TS 语法，前端零学习成本
4. Go        —— 后端团队熟悉，但产物偏大
5. Zig / Kotlin / Swift 等也在跟进
```

```text
选型考虑维度：
1. 要复用的库 —— C/C++ 生态最全（ffmpeg、sqlite、openssl）
2. 团队背景 —— 前端选 AssemblyScript，后端选 Rust/Go
3. 产物体积 —— AssemblyScript 最小，Go 最大
4. 性能要求 —— C/C++/Rust 最优
5. 与 JS 互操作 —— 都靠 wasm-bindgen / embind 之类胶水
```

## C / C++

C/C++ 通过 Emscripten（emcc 编译器）编译到 WASM，能移植海量现有库，是 WASM 生态的根基。

```c
// add.c —— 简单加法
int add(int a, int b) {
    return a + b;
}
```

```bash
# 用 Emscripten 编译
emcc add.c -o add.js -s EXPORTED_FUNCTIONS='["_add"]' -s EXPORTED_RUNTIME_METHODS='["cwrap"]'
```

```js
// 浏览器里调用
const Module = await loadWasmModule();
const add = Module.cwrap('add', 'number', ['number', 'number']);
add(2, 3); // 5
```

```c
// 操作共享内存：C 里写数组，JS 里读
#include <emscripten.h>

EMSCRIPTEN_KEEPALIVE
void fill(int *ptr, int len) {
    for (int i = 0; i < len; i++) ptr[i] = i;
}
```

```text
C/C++ 要点：
1. Emscripten 是事实标准，兼容 POSIX/OpenGL/文件系统模拟
2. 可移植 ffmpeg、sqlite、zlib、openssl 等成熟库
3. 需要处理手动内存管理，容易出越界/泄漏
4. EXPORTED_FUNCTIONS 要显式导出函数，否则被裁剪
```

## Rust

Rust 通过 wasm-pack / wasm-bindgen 编译到 WASM，内存安全、工具链现代，是当前前端社区的首选。

```rust
// src/lib.rs
use wasm_bindgen::prelude::*;

#[wasm_bindgen]
pub fn add(a: i32, b: i32) -> i32 {
    a + b
}

#[wasm_bindgen]
pub struct Counter {
    count: i32,
}

#[wasm_bindgen]
impl Counter {
    pub fn new() -> Counter {
        Counter { count: 0 }
    }
    pub fn increment(&mut self) {
        self.count += 1;
    }
    pub fn get(&self) -> i32 {
        self.count
    }
}
```

```bash
# 用 wasm-pack 构建，生成 JS 胶水 + wasm
wasm-pack build --target web
```

```js
// 前端使用
import init, { add, Counter } from './pkg/my_lib.js';

await init();
console.log(add(1, 2));        // 3

const c = Counter.new();
c.increment();
console.log(c.get());          // 1
```

```text
Rust 要点：
1. wasm-bindgen 自动生成 JS 胶水，类型自动转换
2. 内存安全，编译期排除大部分内存 bug
3. 与 JS 互操作方便（wasm-bindgen 支持字符串/对象/闭包）
4. 生态有 serde、wasm-bindgen-futures 等
5. 编译慢、体积需要 wasm-opt 优化
```

## AssemblyScript

AssemblyScript 是 TypeScript 的严格子集，语法几乎一致，前端开发者零成本上手，产物最小。

```ts
// index.ts
export function add(a: i32, b: i32): i32 {
  return a + b;
}

export function fibonacci(n: i32): i32 {
  if (n < 2) return n;
  return fibonacci(n - 1) + fibonacci(n - 2);
}
```

```bash
# 用 asc 编译
npx asc index.ts -o index.wasm --exportRuntime
```

```js
// 前端加载
const { instance } = await WebAssembly.instantiateStreaming(fetch('index.wasm'));
instance.exports.add(2, 3);        // 5
instance.exports.fibonacci(20);    // 6765
```

```text
AssemblyScript 要点：
1. 语法接近 TypeScript，前端友好
2. 类型用 i32/i64/f32/f64/bool，不用 number
3. 产物最小（无 GC 的裸 WASM 时）
4. 不支持闭包、any 等 TS 特性，是「严格子集」
5. 生态较小，适合中小型模块
```

## Go

Go 通过标准库 syscall/js 或 TinyGo 编译到 WASM，后端团队可以直接复用代码。

```go
// main.go
package main

import "syscall/js"

func add(this js.Value, args []js.Value) interface{} {
    return args[0].Int() + args[1].Int()
}

func main() {
    c := make(chan struct{})
    js.Global().Set("add", js.FuncOf(add))
    <-c // 阻塞保持运行
}
```

```bash
# 标准 Go 编译到 WASM
GOOS=js GOARCH=wasm go build -o main.wasm main.go
cp "$(go env GOROOT)/misc/wasm/wasm_exec.js" .
```

```js
// 前端加载（需 wasm_exec.js 胶水）
const go = new Go();
const { instance } = await WebAssembly.instantiateStreaming(fetch('main.wasm'), go.importObject);
go.run(instance);
console.log(globalThis.add(2, 3)); // 5
```

```bash
# TinyGo 编译（产物更小，但不支持完整标准库）
tinygo build -o main.wasm -target wasm main.go
```

```text
Go 要点：
1. 标准 Go 用 syscall/js 手动桥接，胶水繁琐
2. wasm_exec.js 是官方胶水，需配合 go.run
3. 产物大（含 Go 运行时 + GC），几 MB 起步
4. TinyGo 产物小但标准库支持不全
5. 适合后端团队复用 Go 代码
```

## 语言选型对比

```text
语言            上手成本    产物体积    性能      生态复用      工具链成熟度
C/C++           高          小(优化后)  最优      最强(ffmpeg等) Emscripten 最成熟
Rust            中          小          优        强(crates)    wasm-pack 成熟
AssemblyScript  低(前端)    最小        良        弱            asc 简单
Go              低(后端)    大(含GC)    良        中            syscall/js 繁琐
```

```text
选型建议：
1. 移植 C/C++ 老库(ffmpeg/sqlite) → C/C++ + Emscripten
2. 新写高性能模块、长期维护 → Rust + wasm-pack
3. 前端团队快速出活 → AssemblyScript
4. 复用后端 Go 代码 → Go / TinyGo
5. 对体积敏感(首屏加载) → AssemblyScript / Rust(wasm-opt)
```

## 应用场景实战

### 场景一：Rust 写的高性能哈希

```rust
// src/lib.rs
use wasm_bindgen::prelude::*;

#[wasm_bindgen]
pub fn hash_string(input: &str) -> u32 {
    let mut hash: u32 = 5381;
    for b in input.bytes() {
        hash = hash.wrapping_mul(33).wrapping_add(b as u32);
    }
    hash
}
```

```js
import init, { hash_string } from './pkg/hash.js';
await init();
console.log(hash_string('hello')); // 210640932
```

### 场景二：AssemblyScript 写图像滤镜

```ts
// filter.ts
export function invert(ptr: usize, len: i32): void {
  for (let i = 0; i < len; i += 4) {
    store<u8>(ptr + i, 255 - load<u8>(ptr + i));
    store<u8>(ptr + i + 1, 255 - load<u8>(ptr + i + 1));
    store<u8>(ptr + i + 2, 255 - load<u8>(ptr + i + 2));
  }
}
```

```js
const { instance } = await WebAssembly.instantiateStreaming(fetch('filter.wasm'));
const memory = instance.exports.memory;
const pixels = new Uint8Array(memory.buffer, 0, imageData.data.length);
pixels.set(imageData.data);
instance.exports.invert(0, pixels.length);   // 原地反色
```

## 最佳实践与踩坑记录

### 最佳实践

1. 前端团队优先 AssemblyScript，后端/系统团队优先 Rust
2. 复用成熟 C 库时直接用 Emscripten 移植，别自己重写
3. 产物体积敏感时跑 wasm-opt / tinygo，别忽略优化
4. Rust 用 wasm-bindgen 自动生成胶水，避免手写桥接
5. 跨语言传大数据统一走共享内存，别走函数参数

### 踩坑记录

```text
坑 1：AssemblyScript 误用 TS 的 number
结论：用 number 类型编译报错或行为异常。
原因：AS 是严格子集，整型必须显式 i32/i64。
解法：所有数值类型显式声明，别依赖 any/number 推断。

坑 2：Go WASM 产物过大
结论：一个 hello world 的 wasm 就几 MB。
原因：包含完整 Go 运行时和 GC。
解法：体积敏感用 TinyGo，或接受首屏用流式编译缓解。

坑 3：Emscripten 导出函数被裁剪
结论：C 函数编译后 JS 里调用不到。
原因：默认开启死代码消除，未声明的函数被裁剪。
解法：加 EMSCRIPTEN_KEEPALIVE 或 EXPORTED_FUNCTIONS 显式导出。

坑 4：Rust 字符串类型不匹配
结论：直接 pub fn f(s: String) 生成胶水报错。
原因：wasm-bindgen 对字符串有特定约束（&str/String 可，但要注意所有权）。
解法：参数用 &str，返回值用 String，由 wasm-bindgen 处理转换。

坑 5：Go 忘记阻塞主流程
结论：wasm 加载后函数注册了但调用无反应。
原因：main() 返回后 Go 运行时停止。
解法：用 channel 阻塞（<-c）保持运行时存活。
```

## 概述

WebAssembly（简称 WASM）是一种可移植的二进制指令格式，让 C/C++/Rust 等语言编译后能在浏览器里以接近原生的速度运行。它是 JS 之外浏览器原生支持的第二种语言。

```text
WebAssembly 解决的核心问题：
1. JS 性能上限 —— 解释/即时编译，难以达到原生速度
2. 语言单一 —— 只能用 JS，无法复用其他语言生态
3. 计算密集场景 —— 游戏、图像、音视频、加密跑不动

核心特性：
1. 二进制格式 —— 体积小、解析快，可流式编译
2. 静态类型 —— 编译期确定类型，运行快
3. 沙箱隔离 —— 与 JS 共享浏览器安全模型
4. 可移植 —— 一次编译，多平台运行
```

```js
// 加载并实例化一个 WASM 模块
const { instance } = await WebAssembly.instantiateStreaming(
  fetch('module.wasm')
);
instance.exports.add(1, 2); // 调用 WASM 导出的函数
```

## WebAssembly 是什么

WASM 有文本格式（WAT）和二进制格式（wasm）两种表示，浏览器执行的是二进制格式。

```wat
;; 文本格式 WAT —— 可读的汇编风格
(module
  (func $add (param $a i32) (param $b i32) (result i32)
    local.get $a
    local.get $b
    i32.add)
  (export "add" (func $add)))
```

```text
WAT 与 wasm 的关系：
1. WAT —— S 表达式文本，人可读，用于调试
2. wasm —— 二进制，机器执行，体积更小
3. 两者等价，可互相转换（wat2wasm / wasm2wat）

值类型（当前 MVP）：
i32 / i64 —— 32/64 位整数
f32 / f64 —— 32/64 位浮点数
v128     —— SIMD 128 位向量
```

```text
WASM 的安全模型：
1. 线性内存 —— 独立于 JS 堆的一块连续内存
2. 边界检查 —— 每次内存访问都校验越界
3. 无直接系统调用 —— 只能调用导入的函数
4. 控制流完整 —— 只允许结构化跳转，无 goto
```

## Module

Module（模块）是编译后的 WASM 代码单元，对应一个 wasm 文件。它只是「代码」，不能直接执行。

```js
// 编译一个模块（不实例化）
const module = await WebAssembly.compileStreaming(fetch('module.wasm'));
console.log(module instanceof WebAssembly.Module); // true
```

```js
// 从字节数组编译
const bytes = await fetch('module.wasm').then((r) => r.arrayBuffer());
const module = await WebAssembly.compile(bytes);
```

```text
Module 要点：
1. 编译产物，不可变、可共享
2. 一个 Module 可实例化多次（每个实例内存独立）
3. compile 只编译不执行，instantiate 编译 + 实例化
4. 编译开销大，应编译一次、复用多次
```

## Instance

Instance（实例）是 Module 的一次「运行实体」，包含自己的内存、函数表、全局变量。模块是模板，实例是真正可调用的对象。

```js
// instantiateStreaming：一步完成编译 + 实例化
const { instance } = await WebAssembly.instantiateStreaming(
  fetch('module.wasm'),
  imports
);

// instance.exports 拿到导出的函数和内存
instance.exports.add(2, 3);       // 5
instance.exports.memory;          // WebAssembly.Memory
```

```js
// 手动两步：先 compile 再 instantiate（可复用模块）
const module = await WebAssembly.compileStreaming(fetch('module.wasm'));
const instance1 = await WebAssembly.instantiate(module, imports);
const instance2 = await WebAssembly.instantiate(module, imports);
// instance1 和 instance2 各自独立的内存和状态
```

```text
Instance 要点：
1. instance.exports —— 模块导出的函数/内存/表
2. instance = Module + 导入 + 独立运行时状态
3. 同一 Module 多实例互不影响
```

## Memory

Memory 是 WASM 的线性内存，是一块可增长的连续 ArrayBuffer，JS 和 WASM 共享读写。

```wat
;; 模块内声明并导出一页内存（64KB）
(module
  (memory (export "memory") 1))
```

```js
// JS 侧读写 WASM 内存
const memory = instance.exports.memory;
const view = new Uint8Array(memory.buffer);
view[0] = 42;                    // 写入
console.log(view[0]);            // 读取 42
```

```js
// 内存增长（以 64KB 页为单位）
memory.grow(1);                  // 增加 1 页
const newView = new Uint8Array(memory.buffer);
```

```text
Memory 要点：
1. 单位是页 —— 1 页 = 64KB
2. 可增长 —— grow(n) 增加 n 页，返回旧页数
3. buffer 会变 —— grow 后旧 view 失效，要重新取
4. JS 和 WASM 共享 —— 传大数据的零拷贝通道
5. 32 位寻址 —— 最大 4GB
```

## Table

Table 是函数引用表，用于间接调用（函数指针），是实现回调、虚函数、动态分发的基础。

```wat
;; 声明一个函数表
(module
  (type $binop (func (param i32 i32) (result i32)))
  (table (export "tbl") 2 funcref)
  (elem (i32.const 0) $add $sub)
  (func $add (param i32 i32) (result i32) local.get 0 local.get 1 i32.add)
  (func $sub (param i32 i32) (result i32) local.get 0 local.get 1 i32.sub))
```

```js
// JS 侧：通过表间接调用函数
const tbl = instance.exports.tbl;
const add = tbl.get(0);   // 取函数引用
add(3, 4);                // 调用 → 7
```

```text
Table 要点：
1. 存 funcref（函数引用），用于间接调用
2. 可用 call_indirect 按索引调用
3. JS 只能操作 funcref 表，externref 表受限
4. 是实现函数指针、动态分发的机制
```

## Function

Function 是 WASM 的执行单元。JS 和 WASM 之间通过导入/导出函数互相调用。

```wat
(module
  ;; 导入一个 JS 函数
  (import "env" "log" (func $log (param i32)))
  ;; 导出一个函数
  (func (export "double") (param i32) (result i32)
    local.get 0
    i32.const 2
    i32.mul))
```

```js
// JS 提供导入函数，拿到导出函数
const imports = {
  env: {
    log: (n) => console.log('WASM 调用 JS', n),
  },
};
const { instance } = await WebAssembly.instantiateStreaming(
  fetch('module.wasm'),
  imports
);
instance.exports.double(21);   // 42
```

```text
Function 要点：
1. 导出函数 —— WASM 提供给 JS 调用
2. 导入函数 —— JS 提供给 WASM 调用（回调/系统能力）
3. 参数/返回值只能用 i32/i64/f32/f64/v128
4. 复杂数据靠共享 Memory 传递指针
```

## Import 与 Export

Import（导入）和 Export（导出）是 WASM 与宿主环境（JS）交互的接口。

```js
// 一个完整的导入导出示例
const importObject = {
  env: {
    memory: new WebAssembly.Memory({ initial: 1 }), // 导入内存
    abort: () => { throw new Error('abort'); },      // 导入函数
  },
};

const { instance } = await WebAssembly.instantiateStreaming(
  fetch('module.wasm'),
  importObject
);

// 遍历所有导出
const exportsList = Object.keys(instance.exports);
console.log('导出项', exportsList);
```

```js
// 静态检查模块的导入导出（无需实例化）
const module = await WebAssembly.compileStreaming(fetch('module.wasm'));
console.log(WebAssembly.Module.imports(module));   // 需要的导入
console.log(WebAssembly.Module.exports(module));   // 提供的导出
```

```text
Import/Export 要点：
1. import —— 模块声明的「外部依赖」，实例化时必须提供
2. export —— 模块对外暴露的「能力」，实例化后通过 exports 访问
3. 可导入/导出：函数、内存、表、全局变量
4. Module.imports / Module.exports 可静态检查依赖
```

## 应用场景实战

### 场景一：JS 调 WASM 计算斐波那契

```wat
;; fib.wat —— 递归计算
(module
  (func $fib (export "fib") (param $n i32) (result i32)
    (if (result i32) (i32.lt_s (local.get $n) (i32.const 2))
      (then (local.get $n))
      (else
        (i32.add
          (call $fib (i32.sub (local.get $n) (i32.const 1)))
          (call $fib (i32.sub (local.get $n) (i32.const 2))))))))
```

```js
const { instance } = await WebAssembly.instantiateStreaming(fetch('fib.wasm'));
console.time('wasm');
const result = instance.exports.fib(35);
console.timeEnd('wasm');
console.log('fib(35) =', result);
```

### 场景二：通过共享内存交换大数组

```wat
(module
  (memory (export "memory") 1)
  (func (export "fill") (param $len i32)
    (local $i i32)
    (loop $l
      (i32.store8 (local.get $i) (i32.rem_u (local.get $i) (i32.const 256)))
      (local.set $i (i32.add (local.get $i) (i32.const 1)))
      (br_if $l (i32.lt_s (local.get $i) (local.get $len))))))
```

```js
const { instance } = await WebAssembly.instantiateStreaming(fetch('fill.wasm'));
instance.exports.fill(1000);
const bytes = new Uint8Array(instance.exports.memory.buffer, 0, 1000);
console.log(bytes);  // 0,1,2,...,255,0,1,...
```

## 最佳实践与踩坑记录

### 最佳实践

1. 编译一次、复用多次，避免重复 compile 的开销
2. 大数组走 Memory 共享，别走函数参数反复拷贝
3. grow 内存后重新取 buffer，旧 TypedArray 会失效
4. 用 instantiateStreaming 享受流式编译，别先下载再编译
5. 类型只支持数字，复杂数据用指针 + 共享内存约定

### 踩坑记录

```text
坑 1：内存 grow 后旧视图失效
结论：grow 后旧 Uint8Array 读不到新数据或报错。
原因：grow 可能重新分配 buffer，旧的 TypedArray 还指向旧 buffer。
解法：每次 grow 后重新 new Uint8Array(memory.buffer)。

坑 2：直接传 JS 字符串给 WASM 函数
结论：传字符串调用 WASM 函数得到错误结果。
原因：WASM 函数只接受 i32/i64/f32/f64，字符串不是合法类型。
解法：把字符串编码进 Memory，传指针 + 长度。

坑 3：忘记提供导入导致实例化失败
结论：instantiate 报 LinkError。
原因：模块声明的 import 在 importObject 里没有对应项。
解法：用 Module.imports 先检查需要哪些导入。

坑 4：非 MIME 类型导致流式编译失败
结论：instantiateStreaming 报类型错误。
原因：服务端返回的 Content-Type 不是 application/wasm。
解法：服务端配置正确 MIME，或退回 fetch + arrayBuffer + compile。

坑 5：误以为 WASM 一定比 JS 快
结论：简单计算 WASM 反而慢。
原因：WASM 与 JS 之间有调用边界开销。
原因补充：纯数值密集、长时间循环才是 WASM 优势区。
解法：计算量小用 JS，计算量大再上 WASM。
```

## 概述

WASM 真正大放异彩的地方是计算密集型场景——这些场景用纯 JS 要么慢到不可用，要么根本做不到。业界已有一批成熟案例证明 WASM 在浏览器里的生产力。

```text
WASM 的典型应用领域：
1. 图像处理 —— 滤镜、格式转换、压缩（photopea、squoosh）
2. 音视频 —— 编解码、转码（ffmpeg.wasm）
3. CAD —— 三维建模、几何计算（Figma、AutoCAD Web）
4. 游戏 —— 游戏引擎、物理模拟（Unity、Godot）
5. 加密 —— 哈希、签名、加解密
6. AI 推理 —— 模型推理、特征提取
7. 数据处理 —— 大表计算、正则、解析
```

```text
为什么这些场景选 WASM：
1. 计算密集，JS 达不到性能要求
2. 有现成的 C/C++/Rust 库可直接移植
3. 需要复用桌面/服务端的成熟算法
4. 对内存和计算有精细控制的需求
```

## 图像处理

图像处理是最成熟的 WASM 应用领域，滤镜、压缩、格式转换都能做到接近原生速度。

```js
// Squoosh 的做法：用 WASM 实现编解码器
// 加载一个 WASM 图像编码器
import { encode } from './codec.js';

async function compressImage(imageData) {
  const { encode } = await loadEncoder('mozjpeg');
  const result = await encode(imageData, { quality: 75 });
  return result; // 压缩后的 JPEG 数据
}
```

```text
图像处理典型应用：
1. 在线图片编辑 —— Photopea（类 Photoshop 的网页版）
2. 图片压缩 —— Squoosh（Google 的在线压缩工具）
3. 格式转换 —— HEIC → JPEG、WebP 编码
4. 滤镜与特效 —— 像素级操作用 SIMD 加速
```

```js
// 像素级批量处理：亮度调整
// 在 WASM 内存里原地处理，避免来回拷贝
function adjustBrightness(instance, len, amount) {
  const memory = new Uint8Array(instance.exports.memory.buffer);
  for (let i = 0; i < len; i++) {
    memory[i] = Math.min(255, memory[i] + amount);
  }
}
```

## 音视频

音视频编解码是 WASM 的杀手级场景，ffmpeg.wasm 让浏览器里直接跑完整的 ffmpeg。

```js
// ffmpeg.wasm：在浏览器转码视频
import { FFmpeg } from '@ffmpeg/ffmpeg';

const ffmpeg = new FFmpeg();
await ffmpeg.load();

// 把文件写进虚拟文件系统
await ffmpeg.writeFile('input.mp4', await fetchFile('./input.mp4'));

// 转码命令
await ffmpeg.exec(['-i', 'input.mp4', '-vcodec', 'libx264', 'output.mp4']);

// 读回结果
const data = await ffmpeg.readFile('output.mp4');
```

```text
音视频典型应用：
1. 视频转码 —— ffmpeg.wasm 浏览器本地转格式
2. 音频处理 —— 混音、降噪、采样率转换
3. 视频剪辑 —— 在线剪辑工具不传服务器
4. 格式解封装 —— 浏览器不支持的容器格式解码
```

```text
注意：
音视频编解码计算量大，纯 WASM 可能仍慢，
更好的方案是配合 WebCodecs（硬件加速）或 WebGPU。
```

## CAD

CAD（计算机辅助设计）需要精确的几何计算和复杂算法，Figma、AutoCAD Web 都用 WASM 承载核心计算。

```js
// 几何计算：WASM 处理布尔运算（并集/交集/差集）
// 基于 OpenCASCADE 或类似几何内核编译到 WASM
import { computeUnion } from './geometry.js';

const meshA = loadMesh('part-a.stl');
const meshB = loadMesh('part-b.stl');
const unionMesh = computeUnion(meshA, meshB); // 布尔并集
```

```text
CAD 典型应用：
1. 三维建模 —— 在线 CAD 设计工具
2. 几何内核 —— 布尔运算、曲面求交
3. 渲染准备 —— 网格简化、拓扑处理
4. 工程计算 —— 有限元、应力分析
```

```text
代表性案例：
1. Figma —— 用 WASM 处理矢量图形的核心运算
2. AutoCAD Web —— 桌面 CAD 的浏览器版
3. Onshape —— 云端 CAD 平台
```

## 游戏

游戏引擎（Unity、Unreal、Godot）都支持编译到 WASM，让 3A 级画面跑在浏览器里。

```js
// Unity WebGL 导出：游戏核心是 WASM
const buildUrl = 'Build/game.wasm';
const config = { dataUrl: 'Build/game.data', frameworkUrl: 'Build/game.framework.js' };
// 由 Unity 生成的 loader 负责加载 wasm 并驱动游戏循环
createUnityInstance(canvas, config).then((unityInstance) => {
  unityInstance.SendMessage('GameController', 'StartGame');
});
```

```text
游戏典型应用：
1. 游戏引擎导出 —— Unity/Unreal/Godot → Web
2. 物理引擎 —— Box2D、Bullet 的 WASM 版本
3. 碰撞检测 —— 大量物体的碰撞计算
4. 脚本执行 —— Lua 等游戏脚本的 WASM 运行时
```

```text
性能要点：
1. 渲染靠 WebGL/WebGPU，逻辑靠 WASM
2. 多线程物理模拟用 WASM Threads + SharedArrayBuffer
3. 资产（贴图/音频）流式加载
```

## 加密

加密算法对性能和抗时序攻击要求高，WASM 提供原生速度的同时避免 JS 实现的弱点。

```js
// 用 WASM 加速的加密库做文件哈希
import { createHash } from './sha256.js';

async function hashFile(file) {
  const hasher = await createHash('sha256');
  const buf = await file.arrayBuffer();
  return hasher.update(new Uint8Array(buf)).digest('hex');
}
```

```text
加密典型应用：
1. 哈希 —— SHA-256/512，文件指纹
2. 签名验证 —— Ed25519、RSA 验签
3. 加解密 —— AES、ChaCha20 批量加解密
4. 密钥派生 —— PBKDF2/Argon2 密码哈希
```

```text
与 Web Crypto 的对比：
1. Web Crypto 是浏览器内置，但算法固定、无自定义
2. WASM 可移植任意算法库，速度接近原生
3. 两者可混用：内置优先，特殊算法用 WASM
```

## AI 推理

AI 推理是 WASM 的新兴战场，让模型在浏览器本地跑，保护隐私、降低延迟。

```js
// 用 transformers.js（WASM 后端）跑文本分类
import { pipeline } from '@xenova/transformers';

const classifier = await pipeline('sentiment-analysis', 'Xenova/distilbert-base-uncased');
const result = await classifier('I love WebAssembly!');
// [{ label: 'POSITIVE', score: 0.99 }]
```

```text
AI 推理典型应用：
1. 文本分类/情感分析 —— 中小模型浏览器本地跑
2. 语音识别 —— Whisper 的浏览器版
3. 目标检测 —— YOLO 系列 WASM 版本
4. 特征提取 —— 图像/文本 embedding
```

```text
推理后端选择：
1. WASM —— CPU 推理，兼容性最好
2. WebGPU —— GPU 加速，性能高但需硬件支持
3. WebNN —— 走原生 AI 加速器，最省电
```

## 数据处理

大数据的解析、转换、计算放 WASM 能显著提速，尤其正则、CSV/JSON 解析、统计聚合。

```js
// 用 WASM 加速的 CSV 解析器
import { parseCSV } from './csv-wasm.js';

const text = await fetch('/data/large.csv').then((r) => r.text());
const rows = parseCSV(text);  // WASM 内部解析，返回结构化数据
```

```text
数据处理典型应用：
1. CSV/JSON 大文件解析
2. 正则匹配 —— RE2 等高性能正则引擎
3. 统计聚合 —— 分位数、分组计算
4. 数据库 —— SQLite WASM（sql.js）在浏览器跑 SQL
```

```js
// sql.js：浏览器里的 SQLite
import initSqlJs from 'sql.js';
const SQL = await initSqlJs({ locateFile: (f) => `https://cdn.jsdelivr.net/npm/sql.js/dist/${f}` });
const db = new SQL.Database();
db.run('CREATE TABLE users (id INT, name TEXT)');
db.run("INSERT INTO users VALUES (1, 'Alice')");
const res = db.exec('SELECT * FROM users');
console.log(res[0].values); // 结果：[1, 'Alice']
```

## 应用场景实战

### 场景一：浏览器本地 PDF 预览与文本提取

```js
// 用 pdf.js（WASM 加速）渲染 PDF
import * as pdfjsLib from 'pdfjs-dist';

pdfjsLib.GlobalWorkerOptions.workerSrc = 'pdf.worker.js';
const pdf = await pdfjsLib.getDocument('document.pdf').promise;
const page = await pdf.getPage(1);
const content = await page.getTextContent();
console.log(content.items.map((i) => i.str).join(''));
```

### 场景二：大文件流式哈希 + 去重

```js
// 结合 Worker + WASM 做文件指纹
const worker = new Worker('hash-worker.js');
worker.onmessage = (e) => {
  const { hash } = e.data;
  if (seenHashes.has(hash)) {
    console.log('重复文件，跳过');
  } else {
    seenHashes.add(hash);
    console.log('新文件，指纹', hash);
  }
};
worker.postMessage({ type: 'hash', file });
```

```text
完整的去重方案通常还要配合内容寻址存储，
这里 WASM 只负责快速计算哈希，Worker 负责不阻塞 UI。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 先判断场景是否真需要 WASM，简单计算用 JS 反而更快
2. 复用成熟库（ffmpeg/sqlite/OpenCASCADE），别自己造轮子
3. 大模块配 Worker，避免加载和计算卡主线程
4. 体积敏感时用流式编译 + 代码分割，别一次加载全部
5. 优先 WebCodecs/WebGPU 等硬件加速 API，WASM 做兜底

### 踩坑记录

```text
坑 1：误以为 WASM 万能，简单场景反而变慢
结论：一个加法函数用 WASM 比 JS 慢。
原因：WASM 与 JS 之间有调用边界和序列化开销。
解法：只在计算密集、长时间循环场景用 WASM。

坑 2：大 WASM 模块首屏加载慢
结论：几 MB 的 wasm 拖慢首屏。
原因：同步加载阻塞渲染。
解法：instantiateStreaming + 按需加载 + gzip/brotli 压缩。

坑 3：音视频编解码纯 WASM 性能不够
结论：转码速度远低于原生。
原因：纯软件编解码，没有硬件加速。
解法：优先 WebCodecs，WASM 处理它不支持的格式。

坑 4：WASM 内存与 JS 数组来回拷贝
结论：图像处理频繁转换导致性能差。
原因：JS 数组 ↔ WASM 内存反复拷贝。
解法：数据一次写入 WASM 内存，原地处理完再读出。

坑 5：忽略 WASM 的调试体验
结论：线上 WASM 报错难以定位。
原因：二进制格式没有源码映射。
解法：开发环境保留 DWARF 调试信息 + source map。
```

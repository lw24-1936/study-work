## 概述

把高级语言编译成 WASM 只是第一步，工程化要解决的还有：JS 与 WASM 的互操作胶水、系统能力模拟、性能特性（SIMD/多线程）、以及加载时的编译优化。

```text
WASM 工程化的几个层面：
1. 互操作胶水 —— wasm-bindgen（Rust）、embind（C++）
2. 系统模拟 —— Emscripten 模拟文件系统/网络/OpenGL
3. 运行时标准 —— WASI 定义非浏览器的系统接口
4. 性能特性 —— SIMD 单指令多数据、Threads 多线程
5. 加载优化 —— Streaming Compilation 边下载边编译
```

```text
核心目标：
1. 让 JS 调 WASM 像调普通函数一样自然
2. 让 C/Rust 代码在浏览器外也能跑（WASI）
3. 把编译/加载开销降到最低
```

## wasm-bindgen

wasm-bindgen 是 Rust 生态的互操作工具，自动生成 JS 胶水，处理类型转换、字符串、闭包、类等复杂交互。

```rust
// src/lib.rs
use wasm_bindgen::prelude::*;

// 字符串在 JS 和 Rust 之间自动转换
#[wasm_bindgen]
pub fn greet(name: &str) -> String {
    format!("Hello, {}!", name)
}

// 接收 JS 闭包作为回调
#[wasm_bindgen]
pub fn on_event(callback: &js_sys::Function) {
    callback.call1(&JsValue::NULL, &JsValue::from_str("fired"));
}

// 导出结构体
#[wasm_bindgen]
pub struct Point {
    pub x: f64,
    pub y: f64,
}

#[wasm_bindgen]
impl Point {
    #[wasm_bindgen(constructor)]
    pub fn new(x: f64, y: f64) -> Point {
        Point { x, y }
    }
    pub fn norm(&self) -> f64 {
        (self.x * self.x + self.y * self.y).sqrt()
    }
}
```

```js
// 生成的胶水让调用很自然
import init, { greet, Point } from './pkg/lib.js';
await init();
greet('WASM');              // "Hello, WASM!"
const p = new Point(3, 4);
p.norm();                   // 5
```

```text
wasm-bindgen 能力：
1. 类型映射 —— Rust 类型 ↔ JS 类型自动转换
2. 字符串 —— &str/String 与 JS String 双向转换
3. 闭包 —— JS 函数传进 Rust，Rust 函数暴露给 JS
4. 结构体/枚举 —— 导出为 JS 类，支持构造函数和方法
5. serde —— JSON 序列化与 JS 对象互转
```

## Emscripten

Emscripten 是 C/C++ 的 WASM 编译工具链，核心价值是模拟 POSIX 环境，让 Unix 程序几乎不改代码就能跑在浏览器。

```c
// file.c —— 使用标准 C 文件操作
#include <stdio.h>
#include <emscripten.h>

EMSCRIPTEN_KEEPALIVE
void write_and_read() {
    FILE *f = fopen("/data/test.txt", "w");
    fprintf(f, "hello wasm");
    fclose(f);

    char buf[64];
    f = fopen("/data/test.txt", "r");
    fgets(buf, sizeof(buf), f);
    printf("%s\n", buf);
    fclose(f);
}
```

```bash
# 编译时挂载虚拟文件系统
emcc file.c -o file.js -s EXPORTED_FUNCTIONS='["_write_and_read"]' \
  --preload-file data/
```

```js
// 浏览器端：文件系统是虚拟的，存在内存里
const Module = await loadModule();
Module.ccall('write_and_read', null, [], []);
```

```text
Emscripten 提供的模拟层：
1. 虚拟文件系统 —— MEMFS/IDBFS，内存或 IndexedDB 存储
2. POSIX 系统调用 —— fork、socket 的有限模拟
3. OpenGL/WebGL —— GL 代码映射到 WebGL
4. 标准 C 库 —— libc、libcxx 移植
```

## WASI

WASI（WebAssembly System Interface）是 WASM 在浏览器之外的系统接口标准，让 WASM 成为通用的跨平台运行时格式。

```rust
// 一个 WASI 程序：读文件、打印
use std::env;
use std::fs;

fn main() {
    let args: Vec<String> = env::args().collect();
    let path = args.get(1).map(|s| s.as_str()).unwrap_or("input.txt");
    let content = fs::read_to_string(path).unwrap();
    println!("{}", content);
}
```

```bash
# 编译成 WASI 目标
rustc --target wasm32-wasip1 main.rs -o main.wasm

# 用 Wasmtime 运行（任意平台）
wasmtime main.wasm input.txt
```

```text
WASI 的意义：
1. 浏览器 WASM 无系统调用，WASI 补齐了这块
2. 定义文件系统、网络、时钟等标准接口
3. 同一份 wasm 跑在浏览器、服务器、边缘、嵌入式
4. 运行时有 Wasmtime、WasmEdge、wasmer 等
```

## SIMD

SIMD（Single Instruction Multiple Data）让一条指令同时处理多个数据，WASM 的 128 位 SIMD 大幅加速图像、音视频、数值计算。

```wat
;; 使用 v128 向量类型做 4 个 i32 同时相加
(module
  (func (export "add4") (param v128 v128) (result v128)
    local.get 0
    local.get 1
    i32x4.add))
```

```rust
// Rust 里用 SIMD 内在函数
use std::arch::wasm32::*;

#[target_feature(enable = "simd128")]
pub unsafe fn sum_i32x4(a: v128, b: v128) -> v128 {
    i32x4_add(a, b)
}
```

```js
// 检测 SIMD：没有独立的 JS 开关，需编译一个含 v128 指令的模块探测
// 一个「() -> v128」的函数，函数体是 i32.const 0; i32x4.splat; end
const SIMD_PROBE = new Uint8Array([
  0x00, 0x61, 0x73, 0x6d, 0x01, 0x00, 0x00, 0x00, // \0asm + version
  0x01, 0x05, 0x01, 0x60, 0x00, 0x01, 0x7b,       // type: () -> v128
  0x03, 0x02, 0x01, 0x00,                          // func
  0x0a, 0x08, 0x01, 0x06, 0x00,                    // code: 1 body, size 6
  0x41, 0x00, 0xfd, 0x0c, 0x0b,                    // i32.const 0; i32x4.splat; end
]);
const simdSupported = WebAssembly.validate(SIMD_PROBE);
console.log('SIMD 支持', simdSupported);
```

```text
SIMD 要点：
1. 128 位向量，可并行 4 个 i32/f32 或 16 个 i8
2. 图像像素、音频采样、矩阵运算是典型受益场景
3. 需编译时开启 -msimd128（Emscripten）或 target_feature（Rust）
4. 现代浏览器基本都已支持
```

## Threads

WASM Threads 让模块内部使用 pthreads 风格的多线程，配合 SharedArrayBuffer 和 Atomics 实现真正的并行。

```c
// threads.c —— 使用 pthread 并行
#include <pthread.h>
#include <emscripten.h>

void *worker(void *arg) {
    int *result = (int *)arg;
    *result = 42;
    return NULL;
}

EMSCRIPTEN_KEEPALIVE
int run_thread() {
    pthread_t thread;
    int result = 0;
    pthread_create(&thread, NULL, worker, &result);
    pthread_join(thread, NULL);
    return result;
}
```

```bash
# 开启线程支持编译（需要 COOP/COEP 跨源隔离）
emcc threads.c -o threads.js -s USE_PTHREADS=1 -pthread
```

```text
WASM Threads 要点：
1. 基于 pthreads 模型，需要 USE_PTHREADS=1
2. 依赖 SharedArrayBuffer，浏览器需 COOP/COEP 响应头
3. 配合 Atomics.wait/notify 做线程同步
4. 更轻量的方案是 Web Worker + 多个 WASM 实例
```

## Streaming Compilation

Streaming Compilation（流式编译）让浏览器边下载边编译 WASM，而不是等下载完才开始，显著降低首屏延迟。

```js
// 推荐：instantiateStreaming 边下载边编译
const { instance } = await WebAssembly.instantiateStreaming(
  fetch('module.wasm')
);
```

```js
// 不推荐：先完整下载，再编译，多等一次网络往返
const bytes = await fetch('module.wasm').then((r) => r.arrayBuffer());
const { instance } = await WebAssembly.instantiate(bytes);
```

```text
流式编译要点：
1. fetch 返回的 Response body 是流，直接喂给编译器
2. 下载与编译并行，节省一个网络往返的时间
3. 要求服务端返回 application/wasm 的 MIME 类型
4. compileStreaming / instantiateStreaming 都支持流式
```

```js
// 构建工具侧：让打包器识别 wasm（Vite 示例）
// vite.config.js
export default {
  optimizeDeps: {
    exclude: ['my-wasm-package'],
  },
};
```

## 应用场景实战

### 场景一：Rust + wasm-bindgen 写 MD5 模块

```rust
// src/lib.rs
use wasm_bindgen::prelude::*;

#[wasm_bindgen]
pub fn to_hex(bytes: &[u8]) -> String {
    bytes.iter().map(|b| format!("{:02x}", b)).collect()
}

#[wasm_bindgen]
pub fn djb2(input: &str) -> u32 {
    let mut hash: u32 = 5381;
    for b in input.bytes() {
        hash = hash.wrapping_mul(33).wrapping_add(b as u32);
    }
    hash
}
```

```js
import init, { djb2, to_hex } from './pkg/hash.js';
await init();
console.log(djb2('hello'));            // 210640932
console.log(to_hex(new Uint8Array([0, 255, 16]))); // "00ff10"
```

### 场景二：C + Emscripten 移植经典算法库

```c
// qsort.c —— 复用一个 C 排序实现
#include <stdlib.h>
#include <emscripten.h>

int cmp(const void *a, const void *b) {
    return (*(int *)a - *(int *)b);
}

EMSCRIPTEN_KEEPALIVE
void sort_ints(int *arr, int len) {
    qsort(arr, len, sizeof(int), cmp);
}
```

```js
const Module = await loadModule();
const sort = Module.cwrap('sort_ints', null, ['number', 'number']);
const arr = new Int32Array([5, 3, 8, 1, 9]);
sort(arr.byteOffset, arr.length);
console.log(arr); // [1, 3, 5, 8, 9]
```

## 最佳实践与踩坑记录

### 最佳实践

1. 加载优先用 instantiateStreaming，别先下载再编译
2. Rust 项目统一走 wasm-bindgen，别手写桥接胶水
3. 服务端配置 application/wasm MIME，否则流式编译报错
4. SIMD/Threads 用前先 feature-detect，给降级方案
5. WASM 产物用 wasm-opt 优化体积，用 gzip/brotli 传输

### 踩坑记录

```text
坑 1：流式编译报 MIME 类型错误
结论：instantiateStreaming 抛 TypeError。
原因：服务端 Content-Type 不是 application/wasm。
解法：配置 MIME，或退回 fetch + arrayBuffer + instantiate。

坑 2：Threads 模式下 SharedArrayBuffer 不可用
结论：USE_PTHREADS=1 的程序在页面里跑不起来。
原因：多线程依赖 SharedArrayBuffer，需要 COOP/COEP 跨源隔离。
解法：响应头加 COOP: same-origin 和 COEP: require-corp。

坑 3：Emscripten 虚拟文件系统数据丢失
结论：写入 MEMFS 的文件刷新页面后消失。
原因：MEMFS 只存在内存，不持久化。
解法：用 IDBFS 并调用 FS.syncfs 同步到 IndexedDB。

坑 4：wasm-bindgen 闭包内存泄漏
结论：JS 回调频繁注册导致内存增长。
原因：闭包跨语言边界后 Rust 侧持有引用，不主动释放。
解法：用 forget 前先记录，用完调用闭包的 drop 释放。

坑 5：SIMD 在旧浏览器崩
结论：开了 SIMD 的模块在旧浏览器实例化失败。
原因：旧引擎不支持 128 位 SIMD 指令。
解法：编译两份（SIMD/非 SIMD），运行时 feature-detect 选择。
```

## 概述

React 性能优化的核心是「减少不必要的重渲染」。React 默认父组件更新会连带子组件重渲染，优化的本质是：跳过无关重渲染（memo/useMemo/useCallback）、缩小上下文影响面（Context Splitting）、延迟加载（Lazy/Suspense）、减少 DOM 节点（Virtual List），并用 Profiler 定位瓶颈。

```text
React 重渲染的触发：
1. 组件自身 state 变化
2. 父组件重渲染（子组件默认跟着渲染）
3. 消费的 Context value 变化
4. store 更新（Redux/Zustand 等）
```

```text
优化的总原则：
1. 先测量再优化 —— 用 Profiler 找到真正慢的组件
2. 减少重渲染范围 —— memo、selector、context 拆分
3. 减少渲染成本 —— useMemo 缓存计算、虚拟列表
```

## memo

React.memo 是高阶组件，浅比较 props：props 不变就跳过重渲染。适合「props 稳定、渲染昂贵」的纯展示组件。

```jsx
import { memo } from 'react';

// 只有 props 变化时才重渲染
const UserCard = memo(function UserCard({ user }) {
  return (
    <div className="card">
      <h3>{user.name}</h3>
      <p>{user.email}</p>
    </div>
  );
});
```

```jsx
// 自定义比较函数（props 复杂时）
const UserCard = memo(
  ({ user }) => <div>{user.name}</div>,
  (prev, next) => prev.user.id === next.user.id, // 返回 true 则跳过渲染
);
```

```text
memo 的适用与注意：
1. 适用 —— props 稳定、渲染昂贵的展示组件
2. 不适用 —— props 每次都新建对象（memo 失效）
3. 浅比较 —— 只比较引用，嵌套对象需自定义比较
4. 配合 useCallback/useMemo 传稳定引用才有效
```

## useMemo

useMemo 缓存计算结果，依赖不变时返回上次结果，避免每次渲染重复计算。适合昂贵的派生数据。

```jsx
import { useMemo } from 'react';

function ProductList({ products, filter }) {
  // 只有 products 或 filter 变化才重新计算
  const filtered = useMemo(
    () => products.filter((p) => p.category === filter).sort((a, b) => b.price - a.price),
    [products, filter],
  );

  return <ul>{filtered.map((p) => <li key={p.id}>{p.name}</li>)}</ul>;
}
```

```text
useMemo 的适用与注意：
1. 适用 —— 昂贵计算（大数组过滤/排序/聚合）
2. 不适用 —— 简单计算，useMemo 本身也有开销
3. 不要为了「看起来优化」滥用，先测量
4. 依赖数组要准确，漏依赖会导致缓存脏数据
```

```jsx
// 缓存复杂对象，避免传给 memo 子组件时引用变化
const config = useMemo(() => ({ theme, locale }), [theme, locale]);
return <UserCard config={config} />;
```

## useCallback

useCallback 缓存函数引用，依赖不变时返回同一个函数，避免子组件因函数引用变化而重渲染。常与 memo 配合使用。

```jsx
import { useCallback, memo } from 'react';

const Button = memo(function Button({ onClick, label }) {
  return <button onClick={onClick}>{label}</button>;
});

function Parent() {
  // 缓存函数，Button 不会因引用变化而重渲染
  const handleClick = useCallback(() => {
    console.log('clicked');
  }, []);

  return <Button onClick={handleClick} label="Submit" />;
}
```

```text
useCallback 的适用与注意：
1. 适用 —— 传给 memo 子组件的回调
2. 适用 —— 作为 useEffect 依赖时保证稳定
3. 不适用 —— 传给普通组件（引用变化不影响重渲染）
4. 闭包陷阱 —— 依赖漏写会拿到旧值
```

```jsx
// 用函数式更新避免依赖 state
const increment = useCallback(() => {
  setCount((c) => c + 1); // 不依赖 count，函数稳定
}, []);
```

## Selector

Selector（选择器）是状态管理库的「按需订阅」机制：组件只订阅自己用到的数据切片，切片不变就不重渲染。Redux 的 useSelector、Zustand 的 selector 都是这个思路。

```jsx
import { useSelector } from 'react-redux';

function UserName() {
  // 只订阅 name，name 不变组件不重渲染
  const name = useSelector((state) => state.user.name);
  return <span>{name}</span>;
}

function UserAge() {
  // 只订阅 age，与其他状态解耦
  const age = useSelector((state) => state.user.age);
  return <span>{age}</span>;
}
```

```jsx
// Zustand 用 selector 精准订阅
import { create } from 'zustand';

const useStore = create((set) => ({
  name: 'Alice',
  age: 30,
  updateAge: (age) => set({ age }),
}));

function Age() {
  const age = useStore((s) => s.age); // 只订阅 age
  return <span>{age}</span>;
}
```

```text
Selector 的要点：
1. 订阅越细，重渲染范围越小
2. 避免在 selector 里返回新对象（引用变化导致重渲染）
3. 多个独立状态拆成多个 selector
4. 复杂派生可用 reselect 缓存 selector 结果
```

## Context Splitting

Context Splitting（上下文拆分）把一个大 Context 拆成多个小 Context，让组件只订阅自己关心的部分，避免「一个值变化导致所有消费者重渲染」。

```jsx
// 坏：一个大 Context 包所有状态，任何变化都全量重渲染
const AppContext = createContext();

// 好：按关注点拆分
const ThemeContext = createContext();
const UserContext = createContext();
const CartContext = createContext();

function App() {
  return (
    <ThemeContext.Provider value={theme}>
      <UserContext.Provider value={user}>
        <CartContext.Provider value={cart}>
          <Main />
        </CartContext.Provider>
      </UserContext.Provider>
    </ThemeContext.Provider>
  );
}
```

```jsx
// 订阅主题的组件不受 user/cart 变化影响
function ThemedButton() {
  const { theme } = useContext(ThemeContext);
  return <button className={theme}>...</button>;
}
```

```text
Context 拆分的策略：
1. 按「变化频率」拆分 —— 高频变化的（cart）与低频（theme）分开
2. 按「关注领域」拆分 —— user、theme、cart 各自独立
3. 用 useMemo 包 Provider value，避免无谓的引用变化
4. 高频更新场景考虑 Zustand 等替代 Context
```

## Virtual List

Virtual List（虚拟列表）只渲染可视区域的行，用 react-window / react-virtualized 等库，把长列表的重渲染和 DOM 数量降到最低。

```jsx
import { FixedSizeList } from 'react-window';
import { memo } from 'react';

const Row = memo(({ index, style, data }) => (
  <div style={style}>{data[index]}</div>
));

export function VirtualList({ items }) {
  return (
    <FixedSizeList
      height={500}
      width="100%"
      itemCount={items.length}
      itemSize={40}
      itemData={items}
    >
      {Row}
    </FixedSizeList>
  );
}
```

```text
虚拟列表的收益：
1. DOM 节点从 10 万降到几十个
2. 首次渲染快，滚动流畅
3. 配合 memo 减少行重渲染
```

## Suspense

Suspense 是 React 的异步渲染边界：包裹懒加载组件或异步数据源，加载期间显示 fallback，加载完成后无缝切换，配合 Lazy 实现代码分割 + 优雅加载态。

```jsx
import { Suspense, lazy } from 'react';

const HeavyChart = lazy(() => import('./HeavyChart'));

function Dashboard() {
  return (
    <Suspense fallback={<div className="skeleton">加载中...</div>}>
      <HeavyChart />
    </Suspense>
  );
}
```

```text
Suspense 的要点：
1. fallback 显示加载占位（骨架屏更好）
2. 可嵌套，控制不同层级的加载态
3. 配合 startTransition 区分紧急/非紧急更新
4. 避免过度拆分导致加载态闪烁
```

## Lazy

React.lazy 配合动态 import 实现组件级代码分割，组件只在首次渲染时才下载，减少首屏 bundle 体积。

```jsx
import { lazy, Suspense } from 'react';

// 路由级懒加载
const Home = lazy(() => import('./pages/Home'));
const Settings = lazy(() => import('./pages/Settings'));

function App() {
  return (
    <Suspense fallback={<div>loading...</div>}>
      <Routes>
        <Route path="/" element={<Home />} />
        <Route path="/settings" element={<Settings />} />
      </Routes>
    </Suspense>
  );
}
```

```text
Lazy 的最佳实践：
1. 路由级懒加载是标配
2. 重组件（图表、编辑器、地图）单独懒加载
3. 懒加载的组件外层必须有 Suspense
4. 预取 —— 空闲时 import 预热即将访问的路由
```

## Profiler

React Profiler 用于测量组件渲染耗时，定位「谁在拖慢渲染」。开发环境用 React DevTools 的 Profiler 面板，代码里也可用 <Profiler> 组件包裹采集。

```jsx
import { Profiler } from 'react';

function onRender(id, phase, actualDuration, baseDuration, startTime, commitTime) {
  console.log(id, phase, actualDuration.toFixed(2), 'ms');
}

<Profiler id="Dashboard" onRender={onRender}>
  <Dashboard />
</Profiler>
```

```text
Profiler 的输出指标：
1. actualDuration —— 本次 commit 的实际渲染耗时
2. baseDuration —— 无优化下的渲染耗时
3. phase —— mount / update
4. 对比两者差距可看出 memo 等的优化效果
```

```text
性能排查流程：
1. React DevTools → Profiler 面板录制
2. 找到耗时高、渲染频繁的组件
3. 针对性加 memo/useMemo/useCallback/selector
4. 复查 Profiler 确认优化生效
```

## 应用场景实战

### 场景一：列表页的完整优化

```jsx
import { memo, useMemo, useCallback } from 'react';
import { FixedSizeList } from 'react-window';

const Row = memo(({ index, style, data, onSelect }) => (
  <div style={style} onClick={() => onSelect(data[index].id)}>
    {data[index].name}
  </div>
));

function ProductList({ products, selectedId, onSelect }) {
  // 昂贵排序用 useMemo 缓存
  const sorted = useMemo(
    () => [...products].sort((a, b) => a.price - b.price),
    [products],
  );

  // 回调用 useCallback 保证传给 memo 子组件的引用稳定
  const handleSelect = useCallback((id) => onSelect(id), [onSelect]);

  return (
    <FixedSizeList
      height={600}
      itemCount={sorted.length}
      itemSize={40}
      width="100%"
      itemData={sorted}
    >
      {(props) => <Row {...props} onSelect={handleSelect} selectedId={selectedId} />}
    </FixedSizeList>
  );
}
```

### 场景二：路由懒加载 + Suspense 骨架屏

```jsx
import { lazy, Suspense } from 'react';

const Dashboard = lazy(() => import('./Dashboard'));
const Reports = lazy(() => import('./Reports'));

function App() {
  return (
    <BrowserRouter>
      <Suspense fallback={<Skeleton />}>
        <Routes>
          <Route path="/" element={<Dashboard />} />
          <Route path="/reports" element={<Reports />} />
        </Routes>
      </Suspense>
    </BrowserRouter>
  );
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. 先 Profiler 定位瓶颈，别凭感觉加优化
2. memo 配合 useCallback/useMemo 传稳定引用，否则失效
3. selector 订阅尽量细，避免返回新对象
4. 大 Context 按变化频率/领域拆分
5. 路由和重组件一律 Lazy + Suspense
6. 长列表用虚拟列表，配合 memo 行组件

### 踩坑记录

```text
坑 1：memo 不生效
结论：子组件还是每次都重渲染。
原因：props 里传了内联对象/函数，引用每次都变。
解法：用 useMemo/useCallback 缓存 props 引用。

坑 2：useCallback 闭包拿到旧 state
结论：回调里读到的 state 是过期值。
原因：依赖数组漏写 state，函数被缓存没更新。
解法：用函数式更新 setState，或补全依赖。

坑 3：selector 返回新对象导致频繁重渲染
结论：store 一更新组件就重渲染。
原因：useSelector((s) => ({ a: s.a, b: s.b })) 每次返回新对象。
解法：拆分 selector 或用 shallowEqual 比较。

坑 4：大 Context 全量重渲染
结论：theme 一变，全应用组件都重渲染。
原因：所有状态塞一个 Context，消费者过多。
解法：按领域/频率拆分 Context，或换 Zustand。

坑 5：滥用 useMemo 反而更慢
结论：简单计算也包 useMemo，性能没提升。
原因：useMemo 本身有比较和缓存开销。
解法：只在昂贵计算（大数组处理）时用，先测量。
```

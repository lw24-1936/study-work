## 概述

Vue 的响应式系统已经做了细粒度的更新优化（只重渲染依赖变化的组件），性能优化重点在于：避免不必要的计算（Computed 缓存）、跳过静态内容（v-once/v-memo）、缓存组件实例（KeepAlive）、按需加载（异步组件）、减少 DOM 节点（虚拟列表）。

```text
Vue 更新机制的特点：
1. 依赖追踪 —— 组件只依赖它用到的响应式数据
2. 细粒度更新 —— 数据变化只触发相关组件重渲染
3. 异步批处理 —— 同一 tick 内的多次修改合并为一次更新
```

```text
优化的总原则：
1. 派生数据用 Computed 缓存，别在模板里重复计算
2. 静态内容用 v-once/v-memo 跳过重复渲染
3. 频繁切换的组件用 KeepAlive 缓存
4. 重组件用异步组件 + Suspense 按需加载
```

## Computed

Computed（计算属性）缓存基于其响应式依赖的计算结果，依赖不变时直接返回缓存值，避免重复计算。适合「从响应式数据派生」的昂贵计算。

```js
import { computed, ref } from 'vue';

const products = ref([...10000 条数据...]);
const category = ref('electronics');

// 依赖不变时，多次访问都返回缓存结果
const filtered = computed(() =>
  products.value
    .filter((p) => p.category === category.value)
    .sort((a, b) => b.price - a.price),
);
```

```text
Computed 的优势：
1. 缓存 —— 依赖不变不重复计算
2. 惰性求值 —— 没人访问就不计算
3. 自动依赖追踪 —— 依赖变了才重新计算
```

```text
Computed vs 方法：
1. 方法 —— 每次渲染都执行，无缓存
2. Computed —— 依赖不变就返回缓存
3. 模板里重复用同一派生数据，用 Computed
```

```js
// 可写的 computed（需要 setter 时）
const fullName = computed({
  get: () => `${firstName.value} ${lastName.value}`,
  set: (v) => {
    [firstName.value, lastName.value] = v.split(' ');
  },
});
```

## Watch

Watch 监听响应式数据变化并执行副作用（请求、DOM 操作、日志）。与 Computed 不同，Watch 不做缓存，也不返回值，而是「数据变化时做点什么」。

```js
import { ref, watch } from 'vue';

const keyword = ref('');

// 监听变化，执行副作用（请求数据）
watch(keyword, async (val) => {
  const res = await fetch(`/api/search?q=${val}`);
  results.value = await res.json();
});
```

```text
Computed vs Watch 的取舍：
1. Computed —— 派生「值」，同步、缓存、可组合
2. Watch —— 处理「副作用」，异步操作、请求
3. 能用 Computed 就别用 Watch 存一份副本
```

```js
// 深度监听 + 立即执行
watch(
  () => form.value,
  (val) => save(val),
  { deep: true, immediate: true },
);
```

```text
Watch 的性能注意：
1. deep: true 会递归遍历，大对象成本高，谨慎使用
2. 精确监听目标路径，避免监听整个大对象
3. 能用 watchEffect 的简单场景用 watchEffect 自动收集依赖
```

## v-once

v-once 让元素/组件只渲染一次，之后即使依赖变化也跳过重新渲染，适合「一次性渲染后不变」的静态内容。

```html
<!-- 静态内容只渲染一次，后续更新跳过 -->
<div v-once>
  <h1>{{ title }}</h1>
  <p>这段静态说明文字永远不会变</p>
</div>
```

```html
<!-- 大段静态列表/配置只渲染一次 -->
<ul v-once>
  <li v-for="item in staticItems" :key="item">{{ item }}</li>
</ul>
```

```text
v-once 的适用场景：
1. 完全静态的文案、说明
2. 一次性初始化的配置列表
3. 性能敏感的大段静态内容
```

```text
v-once 注意点：
1. 内容后续变化不会反映到 DOM（这是它的代价）
2. 别用在会变化的数据上
3. 对整棵子树生效，含子组件
```

## v-memo

v-memo 是 Vue 3.2+ 的「依赖记忆」指令：传入依赖数组，依赖不变时跳过该子树的重渲染。比 v-once 灵活（v-once 是永远不变，v-memo 是条件跳过）。

```html
<!-- 只有 selectedId 变化才重渲染这一项，其他项跳过 -->
<div v-for="item in list" :key="item.id" v-memo="[item.id === selectedId]">
  <ExpensiveRow :item="item" />
</div>
```

```text
v-memo 的语义：
1. 依赖数组每个值都相等 → 跳过重渲染
2. 任一依赖变化 → 重新渲染
3. 空数组 v-memo="[]" 等价于 v-once
```

```text
v-memo 的适用场景：
1. 长列表中只有个别项变化（选中态高亮）
2. 大量静态行的表格
3. 精确控制某棵子树的更新时机
```

```html
<!-- v-memo 配合 v-if 可跳过不必要分支渲染 -->
<div v-memo="[showDetails]">
  <template v-if="showDetails">...</template>
  <template v-else>...</template>
</div>
```

## KeepAlive

KeepAlive 缓存被切换走的组件实例，再次切回时复用（不重新挂载），保留组件状态（滚动位置、表单输入、已加载数据），避免重复渲染和请求。

```html
<!-- 标签页切换：缓存的组件不重新创建 -->
<KeepAlive>
  <component :is="activeTab" />
</KeepAlive>
```

```html
<!-- 配合路由缓存页面 -->
<router-view v-slot="{ Component }">
  <KeepAlive :include="['Home', 'List']" :max="10">
    <component :is="Component" />
  </KeepAlive>
</router-view>
```

```text
KeepAlive 的属性：
1. include/exclude —— 按组件名选择性缓存
2. max —— 最多缓存实例数（LRU 淘汰）
3. 生命周期 —— activated / deactivated 钩子
```

```text
KeepAlive 的适用场景：
1. 标签页/步骤条切换
2. 列表 → 详情 → 返回（保留滚动位置）
3. 频繁切换的重组件
```

```js
// 缓存的组件用 activated/deactivated 处理副作用
export default {
  activated() {
    this.loadData(); // 切回时刷新
  },
  deactivated() {
    // 切走时清理定时器、取消订阅
  },
};
```

## Async Component

异步组件（defineAsyncComponent）让组件在需要时才加载，配合代码分割减少首屏体积，配合 Suspense 提供加载态。

```js
import { defineAsyncComponent } from 'vue';

// 重组件按需加载
const HeavyChart = defineAsyncComponent(() => import('./HeavyChart.vue'));

// 带加载态和错误态的异步组件
const AsyncComp = defineAsyncComponent({
  loader: () => import('./Comp.vue'),
  loadingComponent: Skeleton,
  errorComponent: ErrorTip,
  delay: 200,       // 200ms 后才显示 loading，避免闪烁
  timeout: 10000,   // 超时触发错误态
});
```

```html
<!-- 配合 Suspense 包裹异步组件 -->
<Suspense>
  <template #default>
    <HeavyChart />
  </template>
  <template #fallback>
    <Skeleton />
  </template>
</Suspense>
```

```text
异步组件的适用场景：
1. 路由级懒加载（Vue Router 默认支持）
2. 点击才展开的重组件（图表、编辑器）
3. 大体积第三方组件
```

```js
// 路由懒加载
const routes = [
  { path: '/reports', component: () => import('./Reports.vue') },
];
```

## Virtual List

Virtual List（虚拟列表）只渲染可视区域的行，用 vue-virtual-scroller、vueuc 或自定义实现，把长列表的 DOM 和渲染成本降到最低。

```html
<!-- 用 vue-virtual-scroller 渲染长列表 -->
<template>
  <RecycleScroller
    :items="items"
    :item-size="50"
    key-field="id"
    class="scroller"
  >
    <template #default="{ item }">
      <div class="row">{{ item.name }}</div>
    </template>
  </RecycleScroller>
</template>
```

```text
虚拟列表的要点：
1. 只渲染可视区域 + 缓冲区
2. 用占位撑出总高度保证滚动条
3. 固定行高性能最佳，动态行高用 DynamicScroller
```

```js
// 简易虚拟列表（核心思路）
import { ref, computed } from 'vue';

const scrollTop = ref(0);
const viewHeight = ref(600);
const itemHeight = 50;

const visibleItems = computed(() => {
  const start = Math.floor(scrollTop.value / itemHeight);
  const count = Math.ceil(viewHeight.value / itemHeight) + 2; // 加缓冲区
  return { start, count };
});
```

## 应用场景实战

### 场景一：长列表 + 选中态高亮优化

```html
<template>
  <RecycleScroller :items="items" :item-size="40" key-field="id" class="scroller">
    <template #default="{ item }">
      <!-- 只有选中状态变化才重渲染这一行 -->
      <div v-memo="[item.id === selectedId]" :class="{ active: item.id === selectedId }">
        {{ item.name }}
      </div>
    </template>
  </RecycleScroller>
</template>

<script setup>
import { ref, computed } from 'vue';

const items = ref([...10000 条数据...]);
const selectedId = ref(null);
const keyword = ref('');

// 派生数据用 computed 缓存
const filteredItems = computed(() =>
  items.value.filter((i) => i.name.includes(keyword.value)),
);
</script>
```

### 场景二：标签页 + 缓存 + 异步组件

```html
<template>
  <div class="tabs">
    <button v-for="tab in tabs" :key="tab.name" @click="active = tab.name">
      {{ tab.name }}
    </button>
  </div>

  <!-- KeepAlive 缓存切换的标签页，切回不重建 -->
  <KeepAlive>
    <component :is="activeComponent" />
  </KeepAlive>
</template>

<script setup>
import { computed, defineAsyncComponent, ref, markRaw } from 'vue';

const tabs = [
  { name: 'Dashboard', comp: markRaw(defineAsyncComponent(() => import('./Dashboard.vue'))) },
  { name: 'Reports', comp: markRaw(defineAsyncComponent(() => import('./Reports.vue'))) },
];
const active = ref('Dashboard');
const activeComponent = computed(() => tabs.find((t) => t.name === active.value).comp);
</script>
```

## 最佳实践与踩坑记录

### 最佳实践

1. 派生数据用 computed 缓存，别在模板里写复杂表达式
2. 副作用（请求、存储）用 watch，派生值用 computed
3. 完全静态的内容用 v-once，条件跳过的子树用 v-memo
4. 频繁切换的标签页/路由用 KeepAlive 缓存实例
5. 重组件用 defineAsyncComponent 按需加载
6. 长列表用虚拟列表，配合 v-memo 减少行重渲染

### 踩坑记录

```text
坑 1：把 computed 当 watch 用
结论：computed 里写请求等副作用，触发不可控。
原因：computed 应是无副作用的纯计算。
解法：副作用放 watch 或 watchEffect，computed 只做派生。

坑 2：watch deep: true 监听整个大对象
结论：任何深层字段变化都触发回调，性能差。
原因：deep 会递归遍历所有属性。
解法：精确监听目标字段（() => obj.a.b），避免深度监听。

坑 3：v-once 用在会变化的数据上
结论：数据更新了但界面不刷新。
原因：v-once 只渲染一次，后续变化被跳过。
解法：只对真正不变的内容用 v-once，会变的用 v-memo。

坑 4：KeepAlive 缓存了不该缓存的组件
结论：内存占用上升，状态陈旧。
原因：所有组件都进 KeepAlive，include 没限制。
解法：用 include/max 限制缓存范围，deactivated 里清理副作用。

坑 5：异步组件忘了处理加载态
结论：组件加载慢时页面空白或报错。
原因：没配 loadingComponent/errorComponent 或 Suspense。
解法：defineAsyncComponent 配 loading/error 态，或 Suspense 兜底。
```

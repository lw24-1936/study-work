## 概述

浏览器渲染一条更新链路是「JS → Style（样式计算）→ Layout（布局/回流）→ Paint（绘制/重绘）→ Composite（合成）」。渲染优化就是减少 Reflow（回流）、减少 Repaint（重绘）、合并 DOM 操作、用虚拟化减少节点数，并用 requestAnimationFrame 把更新对齐到刷新帧。

```text
渲染更新链路的代价：
1. Reflow（回流）—— 重新计算布局，最昂贵
2. Repaint（重绘）—— 重新绘制像素，次昂贵
3. Composite（合成）—— 只合成图层，最廉价
```

```text
优化的优先级：
1. 尽量只触发 Composite（transform/opacity）
2. 避免频繁 Reflow（批量读、缓存布局信息）
3. 减少 Repaint（合并视觉变更）
```

## Reduce Reflow

Reflow（回流）是浏览器重新计算元素位置和尺寸的过程。改几何属性（宽高、位置、边距）都会触发，且会级联影响子元素，代价最高。

```text
触发 Reflow 的操作：
1. 修改几何属性 —— width/height/margin/padding/border
2. 读取布局信息 —— offsetWidth/scrollTop/getBoundingClientRect（强制同步布局）
3. 增删/移动 DOM 节点
4. 修改 font、修改窗口尺寸
```

```js
// 坏：每次循环都读写布局，触发多次回流
for (let i = 0; i < items.length; i++) {
  items[i].style.width = `${items[i].offsetWidth + 10}px`; // 读 offsetWidth 又写 width
}
```

```js
// 好：先读后写，或缓存布局信息
const widths = items.map((el) => el.offsetWidth); // 批量读
items.forEach((el, i) => (el.style.width = `${widths[i] + 10}px`)); // 批量写
```

```text
减少回流的技巧：
1. 读写分离 —— 先读后写，避免交错
2. 缓存布局值 —— offsetWidth 等读一次存起来
3. 用 class 替代逐条改 style
4. 动画用 transform，不用 top/left
5. 脱离文档流操作 —— display:none 或 fragment 上改完再挂载
```

## Reduce Repaint

Repaint（重绘）是元素视觉样式改变（颜色、背景、阴影）但不影响布局时的重绘。代价比回流低，但仍应避免频繁触发。

```text
触发 Repaint（不触发 Reflow）的操作：
1. 修改 color、background、box-shadow
2. 修改 visibility、outline
3. 修改不影响布局的视觉属性
```

```text
只触发 Composite 的属性（最廉价）：
1. transform —— 位移、缩放、旋转
2. opacity —— 透明度
3. filter（部分）—— 滤镜
```

```css
/* 动画用 transform + opacity，避免 layout/paint */
.animate {
  transition: transform 0.3s, opacity 0.3s;
}
.animate:hover {
  transform: translateY(-4px);
  opacity: 0.8;
}
```

```text
减少重绘的技巧：
1. 动画只用 transform/opacity，让浏览器走合成器
2. 需要独立图层的元素用 will-change 提升
3. 避免 hover 时频繁切换背景等视觉属性
```

## Batch DOM Updates

Batch DOM Updates（批量更新 DOM）把多次 DOM 操作合并成一次，减少回流/重绘次数。核心手段：文档片段、克隆节点、一次性替换、display:none 批量改。

```js
// 坏：循环里逐个 append，每次都回流
list.forEach((item) => {
  const li = document.createElement('li');
  li.textContent = item;
  ul.appendChild(li); // 100 次回流
});
```

```js
// 好：用 DocumentFragment 批量挂载，只回流一次
const fragment = document.createDocumentFragment();
list.forEach((item) => {
  const li = document.createElement('li');
  li.textContent = item;
  fragment.appendChild(li);
});
ul.appendChild(fragment); // 一次回流
```

```js
// 好：display:none 期间批量改，再显示
box.style.display = 'none';
// ... 大量 DOM 修改 ...
box.style.display = 'block';
```

```text
批量更新的几种方式：
1. DocumentFragment —— 内存中组装完一次性插入
2. display:none —— 隐藏期间修改不触发可见回流
3. 一次性 innerHTML —— 拼接完整字符串后一次写入
4. 克隆节点 —— cloneNode 修改后再替换
```

## Virtualization

Virtualization（虚拟化）只渲染「当前可见」的 DOM 节点，滚出视口的节点被回收，把成千上万的列表节点压缩到几十个，从根本上减少 DOM 数量和渲染压力。

```text
虚拟化的原理：
1. 只渲染可视区域 + 缓冲区的节点
2. 用占位容器撑出总高度（保证滚动条正确）
3. 滚动时按偏移量计算当前应显示的切片
4. 节点复用，避免频繁创建销毁
```

```js
// 简易虚拟列表实现
function createVirtualList(container, items, itemHeight) {
  const totalHeight = items.length * itemHeight;
  container.style.height = '400px';
  container.style.overflowY = 'auto';

  const inner = document.createElement('div');
  inner.style.height = `${totalHeight}px`;
  inner.style.position = 'relative';
  container.appendChild(inner);

  function render() {
    const scrollTop = container.scrollTop;
    const viewH = container.clientHeight;
    const start = Math.floor(scrollTop / itemHeight);
    const end = Math.ceil((scrollTop + viewH) / itemHeight);
    inner.innerHTML = '';
    for (let i = start; i <= end && i < items.length; i++) {
      const el = document.createElement('div');
      el.style.position = 'absolute';
      el.style.top = `${i * itemHeight}px`;
      el.style.height = `${itemHeight}px`;
      el.textContent = items[i];
      inner.appendChild(el);
    }
  }

  container.addEventListener('scroll', () => requestAnimationFrame(render));
  render();
}
```

## Windowing

Windowing（窗口化）与虚拟化同义，指「只渲染窗口内可见的数据」。React/Vue 生态有成熟库（react-window、react-virtualized、vue-virtual-scroller）封装了窗口化逻辑。

```js
// react-window 固定高度列表
import { FixedSizeList } from 'react-window';

function List({ items }) {
  return (
    <FixedSizeList
      height={400}
      width="100%"
      itemCount={items.length}
      itemSize={50}
    >
      {({ index, style }) => (
        <div style={style}>Row {items[index]}</div>
      )}
    </FixedSizeList>
  );
}
```

```text
窗口化的库与适用：
1. react-window —— 轻量，固定/可变高度列表
2. react-virtualized —— 功能全（表格、网格、瀑布流）
3. vue-virtual-scroller —— Vue 生态虚拟滚动
4. 适用 —— 长列表、表格、时间线、聊天记录
```

```text
窗口化的注意点：
1. 行高固定时性能最佳，可变高度需测量
2. 行内不要依赖「元素在 DOM 中」的副作用
3. 配合 memo 减少不必要的行重渲染
```

## requestAnimationFrame

requestAnimationFrame（rAF）让回调在浏览器下一帧绘制前执行，与屏幕刷新率（60fps）同步，是「视觉更新」的最佳节流方式。

```js
// 坏：scroll 事件高频触发，每次都强制更新
window.addEventListener('scroll', () => {
  updateProgress(); // 每秒可能触发上百次
});

// 好：用 rAF 合并到每帧一次
let ticking = false;
window.addEventListener('scroll', () => {
  if (ticking) return;
  ticking = true;
  requestAnimationFrame(() => {
    updateProgress();
    ticking = false;
  });
});
```

```js
// rAF 做动画，比 setTimeout 更平滑
let start;
function step(timestamp) {
  if (!start) start = timestamp;
  const progress = (timestamp - start) / 1000;
  box.style.transform = `translateX(${progress * 100}px)`;
  if (progress < 1) requestAnimationFrame(step);
}
requestAnimationFrame(step);
```

```text
rAF 的优势：
1. 与刷新帧同步 —— 动画更平滑，无撕裂
2. 自动合并 —— 一帧内多次调用只执行一次
3. 后台标签页自动暂停 —— 节省资源
4. 对比 —— setTimeout 约 4ms 最低精度，rAF 对齐 16.7ms
```

```text
rAF 的适用场景：
1. 动画、滚动、拖拽等视觉更新
2. 节流高频事件（配合 ticking 标志）
3. 不适合 —— 非视觉逻辑、需要精确计时的任务
```

## 应用场景实战

### 场景一：万级数据表格虚拟滚动

```js
// 用 react-window 渲染 10 万行表格
import { FixedSizeList } from 'react-window';
import { memo } from 'react';

const Row = memo(({ index, style, data }) => (
  <div style={style} className="row">
    <span>{data[index].id}</span>
    <span>{data[index].name}</span>
    <span>{data[index].amount}</span>
  </div>
));

export function BigTable({ rows }) {
  return (
    <FixedSizeList
      height={600}
      itemCount={rows.length}
      itemSize={40}
      width="100%"
      itemData={rows}
    >
      {Row}
    </FixedSizeList>
  );
}
```

### 场景二：滚动吸顶 + 进度条的 rAF 优化

```js
let ticking = false;
window.addEventListener('scroll', () => {
  if (ticking) return;
  ticking = true;
  requestAnimationFrame(() => {
    const scrolled = window.scrollY / (document.body.scrollHeight - innerHeight);
    progressBar.style.transform = `scaleX(${scrolled})`; // 只改 transform，走合成
    header.classList.toggle('stuck', window.scrollY > 100);
    ticking = false;
  });
});
```

## 最佳实践与踩坑记录

### 最佳实践

1. 动画只用 transform + opacity，避免触发 layout/paint
2. 读写分离，避免循环里交错读写布局属性
3. 批量 DOM 更新用 DocumentFragment 或 display:none
4. 长列表用虚拟化，只渲染可视节点
5. 视觉更新用 requestAnimationFrame 对齐帧率
6. 需要独立图层的动画用 will-change 提升（但别滥用）

### 踩坑记录

```text
坑 1：循环里交错读写布局
结论：100 次循环触发 100 次回流，卡顿明显。
原因：读 offsetWidth 等会强制同步布局，写又触发回流。
解法：先批量读缓存，再批量写。

坑 2：动画用 top/left 而非 transform
结论：动画掉帧、CPU 占用高。
原因：top/left 触发 layout+paint，transform 只走合成。
解法：位移动画改用 transform: translate。

坑 3：will-change 滥用
结论：内存占用飙升，反而更卡。
原因：will-change 会为元素创建独立图层，过多图层耗尽显存。
解法：只对确定要动画的元素临时加，动画结束移除。

坑 4：虚拟列表行高计算错误
结论：滚动条跳动、内容错位。
原因：可变高度行没正确测量，估算偏差累积。
解法：固定行高，或库支持动态测量（react-window 的 VariableSizeList）。

坑 5：rAF 里做重计算
结论：每帧都跑重逻辑，掉帧。
原因：rAF 回调要在 16.7ms 内完成，塞了耗时任务。
解法：rAF 只做轻量视觉更新，重计算移出或降频。
```

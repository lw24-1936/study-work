## 概述

资源优化解决「加载了太多、太早、太大」的问题：代码层面靠拆分（Code Splitting）、剔除（Tree Shaking）、按需加载（Lazy Loading），网络层面靠资源提示（Preload/Prefetch/Preconnect），具体到图片和字体还有专门的优化手段。

```text
资源优化的两个维度：
1. 减少要下载的量 —— 代码分割、Tree Shaking、压缩图片
2. 控制下载的时机 —— 懒加载、Preload/Prefetch 优先级
```

```text
资源优化的核心原则：
1. 首屏只需要首屏资源，其余延迟加载
2. 能少下载就少下载（tree shaking、压缩）
3. 关键资源优先，非关键资源让路
```

## Code Splitting

Code Splitting（代码分割）把一个大 bundle 拆成多个小 chunk，按需加载。入口分割、动态 import、公共代码提取是三种主要方式，打包工具（Webpack/Vite）原生支持。

```js
// 动态 import：按需加载模块，产生独立 chunk
button.addEventListener('click', async () => {
  const { renderChart } = await import('./chart.js'); // 点击时才下载
  renderChart();
});
```

```js
// Vite 手动分包
export default {
  build: {
    rollupOptions: {
      output: {
        manualChunks: {
          vendor: ['react', 'react-dom'],   // 框架单独打 chunk
          charts: ['echarts', 'd3'],        // 图表库单独打 chunk
        },
      },
    },
  },
};
```

```text
Code Splitting 的策略：
1. 路由级分割 —— 每个路由一个 chunk，切换时加载
2. 组件级分割 —— 重组件（图表、编辑器）单独 chunk
3. 第三方库分割 —— vendor chunk，稳定缓存
4. 公共代码提取 —— 被多处引用的模块提成公共 chunk
```

## Tree Shaking

Tree Shaking（摇树优化）在构建时移除「未被使用的导出代码」，只针对 ES Modules 有效。它依赖静态 import/export 语法做死代码分析。

```js
// utils.js
export function used() { return 1; }
export function unused() { return 2; } // 无人引用，会被摇掉
```

```js
// main.js 只引入 used
import { used } from './utils.js';
console.log(used());
// unused 不会出现在最终产物里
```

```text
Tree Shaking 生效的前提：
1. 必须用 ES Modules（import/export），CommonJS 无法摇树
2. 模块无副作用（或正确标记 sideEffects: false）
3. 构建工具开启 production 压缩
```

```json
{
  "sideEffects": false
}
```

```js
// 注意：有副作用的模块别标记 sideEffects: false
// import './polyfill.js' 这类「仅引入即生效」的模块会被误删
```

```text
Tree Shaking 失效的常见原因：
1. 引入整个库而非具名导入（import _ from 'lodash'）
2. 库是 CommonJS 产物
3. 模块有副作用但没标记
4. 用了动态的、无法静态分析的方式引用
```

## Lazy Loading

Lazy Loading（懒加载）把非首屏资源延迟到「真正需要时」才加载。路由懒加载、组件懒加载、图片懒加载是三种典型形态。

```js
// 路由懒加载（React Router）
const About = lazy(() => import('./pages/About'));
const Home = lazy(() => import('./pages/Home'));

<Routes>
  <Route path="/" element={<Home />} />
  <Route path="/about" element={<About />} />
</Routes>
```

```js
// Vue 路由懒加载
const routes = [
  { path: '/about', component: () => import('./pages/About.vue') },
];
```

```html
<!-- 图片懒加载：原生 loading="lazy" -->
<img src="large.jpg" loading="lazy" alt="..." />
```

```text
懒加载的适用对象：
1. 非首屏路由/页面
2. 折叠线以下的图片、组件
3. 点击才展开的重组件（图表、富文本编辑器）
4. 第三方 SDK（埋点、客服、地图）
```

## Preload

Preload 声明「当前页面确定要用、且应该立即下载」的关键资源，让浏览器提前开始下载，优先级高。常用于首屏关键 CSS、LCP 图片、关键字体。

```html
<!-- 预加载关键脚本/样式/图片/字体 -->
<link rel="preload" as="script" href="/js/critical.js" />
<link rel="preload" as="style" href="/css/critical.css" />
<link rel="preload" as="image" href="/hero.jpg" fetchpriority="high" />
<link rel="preload" as="font" href="/font.woff2" type="font/woff2" crossorigin />
```

```text
Preload 的关键属性：
1. as —— 声明资源类型（script/style/image/font/fetch）
2. crossorigin —— 字体和 fetch 类型必须带
3. fetchpriority —— 可进一步提升优先级
```

```text
Preload 与懒加载的配合：
1. Preload —— 关键资源「尽早」加载
2. Lazy Loading —— 非关键资源「延迟」加载
3. 二者是优先级的两端，各管各的资源
```

## Prefetch

Prefetch 声明「未来可能用到」的资源，浏览器在空闲时才下载，优先级低。用于预判用户下一步（下一页、下个路由）会访问的内容。

```html
<!-- 预取下一页资源，空闲时下载 -->
<link rel="prefetch" as="document" href="/next-page.html" />
```

```js
// 路由预取：悬停或空闲时预取目标路由 chunk
link.addEventListener('mouseenter', () => {
  import('./pages/Detail.js'); // 触发预取
});
```

```text
Prefetch 的适用场景：
1. 用户极可能访问的下一页
2. 关键流程的下一步资源
3. 空闲时预热即将用到的 chunk
```

```text
Preload vs Prefetch：
1. Preload —— 当前页需要，优先级高，立即下载
2. Prefetch —— 未来需要，优先级低，空闲下载
3. 别把 Prefetch 资源用 Preload，会浪费带宽
```

## Preconnect

Preconnect 提前与目标域建立完整连接（DNS + TCP + TLS），省去后续请求的连接建立时间。适用于确定会发起请求的第三方域（API、CDN、字体服务）。

```html
<!-- 提前建立到 API 的完整连接 -->
<link rel="preconnect" href="https://api.example.com" crossorigin />
<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin />
```

```text
Preconnect 的使用要点：
1. 只对「确定会请求」的关键域使用
2. crossorigin 用于 CORS 请求（字体、fetch）
3. 连接是宝贵资源，别对每个域都 preconnect
4. 通常 1-2 个关键域即可，多了反而浪费
```

## DNS Prefetch

DNS Prefetch 只提前做域名解析（比 preconnect 轻量，不建 TCP/TLS 连接），适合「可能会用到、但不确定」的第三方域名。

```html
<!-- 提前解析 DNS -->
<link rel="dns-prefetch" href="//third-party.example.com" />
```

```text
DNS Prefetch vs Preconnect：
1. dns-prefetch —— 只做 DNS 解析，成本最低
2. preconnect —— DNS + TCP + TLS，成本更高但更彻底
3. 确定要请求 → preconnect；只是可能 → dns-prefetch
```

```text
资源提示的优先级排序（低到高）：
1. dns-prefetch —— 解析域名
2. preconnect —— 建立连接
3. prefetch —— 空闲下载未来资源
4. preload —— 立即下载当前关键资源
```

## Image Optimization

图片通常是页面体积的大头，优化收益最高：选对格式、压到合适尺寸、响应式适配、懒加载。

```text
图片格式选择：
1. AVIF —— 压缩率最高，新格式，兼容性渐好
2. WebP —— 压缩率高，主流浏览器支持
3. JPEG —— 照片通用，兼容最好
4. PNG —— 需要透明/无损时
5. SVG —— 图标、矢量图形
```

```html
<!-- 响应式图片：不同尺寸加载不同图 -->
<img
  srcset="small.jpg 480w, medium.jpg 800w, large.jpg 1200w"
  sizes="(max-width: 600px) 480px, 800px"
  src="medium.jpg"
  alt="..."
/>
```

```html
<!-- 用 picture 按格式/条件选择 -->
<picture>
  <source type="image/avif" srcset="photo.avif" />
  <source type="image/webp" srcset="photo.webp" />
  <img src="photo.jpg" alt="..." />
</picture>
```

```text
图片优化清单：
1. 选现代格式（AVIF/WebP）
2. 按显示尺寸压缩，别用 4K 大图当缩略图
3. srcset 响应式适配不同 DPR/屏幕
4. 非首屏图片 loading="lazy"
5. 设置 width/height 或 aspect-ratio 防布局偏移
6. 图标用 SVG 或图标字体（雪碧图已过时）
```

## Font Optimization

Web 字体加载会阻塞文本渲染（或引起 FOIT/FOUT）。优化目标是「尽快显示文本、减少字体体积、避免布局偏移」。

```css
/* font-display 控制字体加载期间的显示策略 */
@font-face {
  font-family: 'MyFont';
  src: url('/fonts/myfont.woff2') format('woff2');
  font-display: swap; /* 先用系统字体，加载完再替换 */
  unicode-range: U+0000-00FF; /* 只加载需要的字符集 */
}
```

```html
<!-- 预加载关键字体 -->
<link rel="preload" as="font" href="/fonts/myfont.woff2" type="font/woff2" crossorigin />
```

```text
font-display 的取值：
1. swap —— 立即用系统字体，加载后替换（推荐）
2. block —— 短暂空白后替换（FOIT）
3. optional —— 短时间不加载就放弃（最适合非关键字体）
4. auto —— 浏览器默认
```

```text
字体优化清单：
1. 用 woff2 格式（压缩率最高）
2. 子集化（subsetting）—— 只保留用到的字符
3. font-display: swap 避免文字不可见
4. preload 关键字体
5. 控制字体数量，别加载整套多字重
6. unicode-range 按字符集分片加载
```

## 应用场景实战

### 场景一：Vite 构建的资源优化配置

```js
// vite.config.js
export default {
  build: {
    rollupOptions: {
      output: {
        manualChunks: {
          react: ['react', 'react-dom'],
          charts: ['echarts'],
        },
      },
    },
  },
  plugins: [],
};
```

```js
// 组件级懒加载：重组件动态导入
import { lazy, Suspense } from 'react';

const HeavyChart = lazy(() => import('./HeavyChart'));

export function Dashboard() {
  return (
    <Suspense fallback={<div>loading...</div>}>
      <HeavyChart />
    </Suspense>
  );
}
```

### 场景二：首屏 HTML 的资源提示组合

```html
<head>
  <!-- 连接 API + 字体服务 -->
  <link rel="preconnect" href="https://api.example.com" crossorigin />
  <link rel="preconnect" href="https://fonts.gstatic.com" crossorigin />

  <!-- 预加载 LCP 图片 + 关键字体 -->
  <link rel="preload" as="image" href="/hero.avif" fetchpriority="high" />
  <link rel="preload" as="font" href="/font.woff2" type="font/woff2" crossorigin />

  <!-- 预取下一页 -->
  <link rel="prefetch" as="document" href="/pricing.html" />
</head>
<body>
  <img src="/hero.avif" width="1200" height="800" alt="hero" />
  <img src="/below-fold.jpg" loading="lazy" alt="..." />
</body>
```

## 最佳实践与踩坑记录

### 最佳实践

1. 路由级 + 组件级代码分割，首屏只加载必要 chunk
2. 第三方库用 ESM 版本 + 具名导入，让 tree shaking 生效
3. LCP 图片用 preload + fetchpriority=high，其余图片 lazy
4. 图片优先 AVIF/WebP + srcset 响应式 + 按需压缩
5. 字体用 woff2 + font-display: swap + 子集化
6. 确定要请求的域 preconnect，LCP 资源 preload，下一页 prefetch

### 踩坑记录

```text
坑 1：Tree Shaking 不生效
结论：引入了整个 lodash，bundle 巨大。
原因：用了 import _ from 'lodash' 或库是 CJS 产物。
解法：用 lodash-es + 具名导入，或引入具体子模块。

坑 2：sideEffects: false 误删副作用模块
结论：polyfill、全局样式等「引入即生效」的模块被删。
原因：无脑全量标记 sideEffects: false。
解法：副作用模块单独标记或用正则排除。

坑 3：Preload 资源与实际不匹配
结论：控制台警告，preload 资源没被使用。
原因：preload 的 href 与实际请求不一致（如指纹 hash 变化）。
解法：确保 preload 的 URL 与最终请求完全一致。

坑 4：图片不设尺寸导致 CLS
结论：图片加载后撑开布局，页面跳动。
原因：img 无 width/height 或 aspect-ratio。
解法：显式设置尺寸或 aspect-ratio 预留空间。

坑 5：字体 FOIT 导致文字长时间不可见
结论：字体加载慢，文字一直空白。
原因：font-display 默认 block，加载期不显示文字。
解法：font-display: swap，先显示系统字体再替换。
```

## 概述

JavaScript 在主线程执行，主线程既要跑 JS 又要渲染页面。JS 优化核心是「别让主线程长时间忙」：减少工作量、拆长任务、把重计算移出主线程、节流高频事件，最终提升 INP/TBT 等交互指标。

```text
主线程拥堵的后果：
1. 长任务阻塞渲染 —— 页面卡顿、掉帧
2. 事件响应延迟 —— INP 恶化，交互不跟手
3. 定时器不准 —— setTimeout 被推迟执行
```

```text
JS 优化的几类手段：
1. 减少工作量 —— 代码分割、算法优化、减少重计算
2. 拆分任务 —— 把长任务切小，让出主线程
3. 移出主线程 —— Web Worker 处理重计算
4. 控制频率 —— Debounce/Throttle 节流高频事件
```

## 减少主线程工作

减少主线程工作是最直接的优化：降低脚本执行总量、避免重复计算、减少不必要的 DOM 操作。

```js
// 坏：每次 render 都重新创建大数组
function render() {
  const list = Array.from({ length: 10000 }, (_, i) => i * 2);
  renderList(list);
}

// 好：把不变的纯计算缓存起来
const list = Array.from({ length: 10000 }, (_, i) => i * 2);
function render() {
  renderList(list);
}
```

```text
减少主线程工作的思路：
1. 缓存计算结果（memoization），避免重复计算
2. 用 Set/Map 替代数组线性查找
3. 减少 DOM 读写次数（批量操作）
4. 缩小遍历范围，避免全量处理
5. 用 requestAnimationFrame 合并视觉更新
```

## Long Task

Long Task（长任务）指执行超过 50ms 的任务，它会阻塞渲染和交互响应。TBT 和 INP 都直接由长任务导致。优化目标是「拆长任务」和「减长任务」。

```js
// 用 PerformanceObserver 发现长任务
new PerformanceObserver((list) => {
  for (const entry of list.getEntries()) {
    if (entry.duration > 50) {
      console.log('长任务:', entry.duration, 'ms');
    }
  }
}).observe({ type: 'longtask', buffered: true });
```

```text
长任务的来源：
1. 大数组循环、递归计算
2. 大 JSON 解析/序列化
3. 一次性渲染大量 DOM
4. 复杂正则匹配
5. 第三方脚本（埋点、广告）
```

```js
// 拆分长任务：把大循环切成多个小片
function processChunks(items, chunkSize, callback) {
  let i = 0;
  function next() {
    const end = Math.min(i + chunkSize, items.length);
    for (; i < end; i++) callback(items[i]);
    if (i < items.length) {
      setTimeout(next, 0); // 让出主线程
    }
  }
  next();
}
```

## Debounce

Debounce（防抖）在事件停止触发一段时间后才执行，适用于「输入搜索、窗口 resize、表单校验」等希望最终只执行一次的场景。

```js
function debounce(fn, delay = 300) {
  let timer;
  return function (...args) {
    clearTimeout(timer);
    timer = setTimeout(() => fn.apply(this, args), delay);
  };
}

// 输入停止 300ms 后才发请求
input.addEventListener('input', debounce((e) => {
  search(e.target.value);
}, 300));
```

```text
Debounce 的适用场景：
1. 搜索框输入 —— 停止输入才请求
2. 窗口 resize —— 停止调整才重算布局
3. 表单校验 —— 输入停顿才校验
4. 保存草稿 —— 停止编辑才自动保存
```

```js
// 防抖 + 立即执行（首触发立刻执行一次）
function debounce(fn, delay, immediate = false) {
  let timer;
  return function (...args) {
    const callNow = immediate && !timer;
    clearTimeout(timer);
    timer = setTimeout(() => { timer = null; if (!immediate) fn.apply(this, args); }, delay);
    if (callNow) fn.apply(this, args);
  };
}
```

## Throttle

Throttle（节流）保证函数在固定时间间隔内最多执行一次，适用于「滚动、拖拽、鼠标移动」等持续高频触发的场景。

```js
function throttle(fn, interval = 200) {
  let last = 0;
  return function (...args) {
    const now = Date.now();
    if (now - last >= interval) {
      last = now;
      fn.apply(this, args);
    }
  };
}

// 滚动时每 200ms 最多执行一次
window.addEventListener('scroll', throttle(() => {
  updateScrollProgress();
}, 200));
```

```text
Debounce 与 Throttle 的区别：
1. Debounce —— 停止触发后才执行，只执行最后一次
2. Throttle —— 持续触发时按固定频率执行
3. 搜索用 debounce，滚动/拖拽用 throttle
```

```js
// 用 requestAnimationFrame 做节流，与屏幕刷新同步
function throttleByRaf(fn) {
  let ticking = false;
  return function (...args) {
    if (ticking) return;
    ticking = true;
    requestAnimationFrame(() => {
      fn.apply(this, args);
      ticking = false;
    });
  };
}
```

## Web Worker

Web Worker 在独立线程运行 JS，不阻塞主线程，适合 CPU 密集任务（大数据处理、加密、图像处理、解析）。主线程通过 postMessage 通信。

```js
// worker.js —— 在独立线程里跑重计算
self.onmessage = (e) => {
  const { data } = e;
  const result = heavyCompute(data); // 大循环、加密等
  self.postMessage(result);
};

function heavyCompute(n) {
  let sum = 0;
  for (let i = 0; i < n; i++) sum += Math.sqrt(i);
  return sum;
}
```

```js
// 主线程
const worker = new Worker('/worker.js');
worker.postMessage(10_000_000);
worker.onmessage = (e) => {
  console.log('计算结果:', e.data); // 主线程无卡顿
};
```

```text
Web Worker 的要点：
1. 独立线程 —— 不阻塞主线程渲染
2. 通信靠 postMessage —— 数据会被拷贝（结构化克隆）
3. 不能操作 DOM —— 只能做纯计算
4. 适合 —— 大 JSON 解析、图像处理、加密、排序
5. 注意创建成本 —— 复用 worker，别频繁新建
```

## Worker Pool

Worker Pool（Worker 池）预先创建一组 Worker，任务来时分发到空闲 Worker，避免频繁创建销毁的开销，提升并发处理能力。

```js
// workerPool.js —— 简单 Worker 池
class WorkerPool {
  constructor(url, size = 4) {
    this.workers = [];
    this.queue = [];
    for (let i = 0; i < size; i++) {
      this.workers.push(this.createWorker(url));
    }
  }
  createWorker(url) {
    const w = new Worker(url);
    w.busy = false;
    w.onmessage = () => this.dispatch(w);
    w.onerror = () => this.dispatch(w);
    return w;
  }
  run(task) {
    return new Promise((resolve) => {
      this.queue.push({ task, resolve });
      this.dispatch();
    });
  }
  dispatch() {
    const idle = this.workers.find((w) => !w.busy);
    const job = this.queue.shift();
    if (idle && job) {
      idle.busy = true;
      idle.onmessage = (e) => {
        idle.busy = false;
        job.resolve(e.data);
        this.dispatch();
      };
      idle.postMessage(job.task);
    }
  }
}
```

```js
const pool = new WorkerPool('/worker.js', 4);
const results = await Promise.all([
  pool.run(1_000_000),
  pool.run(2_000_000),
  pool.run(3_000_000),
]);
```

```text
Worker Pool 的价值：
1. 复用 Worker，省去反复创建/销毁的开销
2. 并发处理多个任务，充分利用多核
3. 适合批量任务（多图处理、批量转换）
```

## requestIdleCallback

requestIdleCallback 让任务在浏览器「空闲时」执行，不抢占关键渲染。适合低优先级的非关键任务（预取数据、清理、统计上报）。

```js
requestIdleCallback((deadline) => {
  // deadline.timeRemaining() 返回剩余空闲时间
  while (deadline.timeRemaining() > 0 && tasks.length > 0) {
    const task = tasks.shift();
    task();
  }
}, { timeout: 2000 }); // 超时兜底，避免任务被饿死
```

```text
requestIdleCallback 的适用场景：
1. 低优先级任务 —— 预取、预热缓存
2. 清理工作 —— 删除过期缓存、日志
3. 非紧急上报 —— 统计、埋点
```

```text
requestIdleCallback 注意点：
1. 不要放关键渲染/交互相关任务
2. 用 timeout 兜底，避免任务一直不执行
3. 空闲时间片段短（约 50ms），任务要能分段
4. 不适合需要确定时机的任务（用 rAF 更合适）
```

## Code Splitting

Code Splitting（代码分割）从「总量」上减少主线程工作：只加载当前需要的代码，延迟加载非关键代码，首屏 JS 体积更小、解析执行更快。

```js
// 动态 import：按需加载，减少首屏解析执行
const { Parser } = await import('./heavy-parser.js');

// 路由/组件懒加载
const Settings = lazy(() => import('./Settings'));
```

```text
Code Splitting 对主线程的收益：
1. 首屏 JS 更小 —— 下载、解析、编译、执行都更快
2. 非关键代码延迟 —— 不占用首屏主线程
3. 配合缓存 —— vendor 与业务代码分离，缓存更稳定
```

```js
// 在空闲时预取可能用到的 chunk
requestIdleCallback(() => {
  import('./Settings'); // 空闲预取
});
```

function debounce(fn, delay) {
  let timer;

    timer = setTimeout(() => fn.apply(this, args), delay);

let controller;
const search = debounce(async (keyword) => {
  controller?.abort(); // 取消上一个未完成的请求

## 最佳实践与踩坑记录

### 最佳实践

1. 长任务拆小片，用 setTimeout/rAF 让出主线程
2. 搜索用 debounce，滚动/拖拽用 throttle，rAF 节流视觉更新
3. CPU 密集任务（大计算、解析、加密）移入 Web Worker
4. 复用 Worker，批量任务用 Worker Pool
5. 非关键任务用 requestIdleCallback 空闲执行
6. 代码分割 + 懒加载，减少首屏 JS 总量

### 踩坑记录

```text
坑 1：Worker 传大数据频繁拷贝
结论：postMessage 大对象反而更慢。
原因：结构化克隆会拷贝数据，超大对象拷贝成本高。
解法：用 Transferable（ArrayBuffer 转移所有权）或 SharedArrayBuffer。

坑 2：requestIdleCallback 任务一直不执行
结论：低优先级任务被饿死，永远不跑。
原因：页面一直繁忙，没有空闲时间。
解法：设置 timeout 兜底，或对关键任务改用 rAF/setTimeout。

坑 3：debounce 延迟太长导致交互迟钝
结论：搜索框感觉「慢半拍」。
原因：debounce 时间设置过长。
解法：300ms 左右为宜，可配 immediate 首触发立即执行。

坑 4：Worker 里想操作 DOM 报错
结论：Worker 里访问 document 报 undefined。
原因：Worker 是独立线程，无 DOM 环境。
解法：Worker 只做纯计算，结果 postMessage 回主线程渲染。

坑 5：频繁创建销毁 Worker
结论：性能反而下降，得不偿失。
原因：Worker 创建有成本，每次 new 太浪费。
解法：复用 Worker 或使用 Worker Pool。
```

## 概述

WebGPU 是浏览器访问 GPU 的下一代标准 API：它取代了老旧的 WebGL，为现代 GPU（Vulkan、Metal、DirectX 12 之上）提供统一的抽象，既支持 3D 渲染，也支持通用计算（GPGPU）。相比 WebGL，WebGPU 显式暴露 GPU 的底层概念（设备、队列、管线、绑定组），性能更强、控制更精细，但上手门槛也更高。

```text
WebGPU 的核心概念：
1. Adapter —— 代表一块物理 GPU 适配器
2. Device —— 逻辑设备，创建一切资源
3. Queue —— 提交命令给 GPU 执行的队列
4. Buffer / Texture —— 数据与图像资源
5. Shader —— 跑在 GPU 上的程序（WGSL 编写）
6. Pipeline —— 渲染/计算管线的配置
7. Bind Group —— 把资源绑定给 Shader 的集合
```

## Adapter

Adapter 是 GPU 的「物理入口」：代表系统中一块可用的 GPU 适配器，通过 `navigator.gpu.requestAdapter()` 获得。Adapter 上可以查询 GPU 的能力、特性、限制，然后用它创建逻辑 Device。若系统没有可用 GPU 或浏览器不支持，requestAdapter 返回 null。

```js
// 请求适配器并检查能力
const adapter = await navigator.gpu.requestAdapter({
  powerPreference: 'high-performance', // 优先独显
});
if (!adapter) {
  console.log('当前环境不支持 WebGPU');
}
console.log(adapter.limits.maxBufferSize); // 最大缓冲区字节数
```

## Device

Device 是逻辑设备，也是 WebGPU 编程的「中心对象」：几乎所有资源（Buffer、Texture、Shader、Pipeline）都由 device 创建，命令也由 device 提交。它抽象了与具体物理 GPU 的交互，开发者只需面向 device 编程。Device 创建后一旦丢失（GPU 重置），需要重新创建并重建全部资源。

```js
const device = await adapter.requestDevice();
device.lost.then((info) => {
  console.error('设备丢失，需重建资源', info.message);
});

// device 创建各种资源
const buffer = device.createBuffer({ size: 16, usage: GPUBufferUsage.UNIFORM });
```

## Queue

Queue 是命令提交队列：GPU 命令（拷贝数据、执行管线）先被编码进 CommandEncoder，再通过 `queue.submit()` 提交给 GPU 执行。Queue 还提供 `writeBuffer` / `writeTexture` 等便捷方法，直接向 GPU 上传数据。命令提交是异步的，Queue 保证按提交顺序执行。

```js
// 用 queue 上传数据并提交命令
const encoder = device.createCommandEncoder();
// ... 编码拷贝 / 渲染命令
const commandBuffer = encoder.finish();
device.queue.submit([commandBuffer]);

// 直接写数据到缓冲区
device.queue.writeBuffer(buffer, 0, new Float32Array([1, 2, 3, 4]));
```

## Buffer

Buffer 是 GPU 上的一块线性内存：用于存储顶点数据、索引、uniform 常量、存储缓冲等。创建时需声明 size 和 usage（用途标志），数据通过 queue.writeBuffer 上传。Buffer 是 WebGPU 计算和渲染的数据基础，几乎所有数据都先装进 Buffer。

```js
// 创建 uniform buffer 并上传数据
const uniformBuffer = device.createBuffer({
  size: 64,
  usage: GPUBufferUsage.UNIFORM | GPUBufferUsage.COPY_DST,
});
const matrix = new Float32Array(16); // 4x4 矩阵
device.queue.writeBuffer(uniformBuffer, 0, matrix);
```

## Texture

Texture 是 GPU 上的多维图像数据：用于渲染目标（颜色/深度附件）、采样贴图、以及计算着色器的读写。Texture 有尺寸、格式（如 rgba8unorm、depth32float）、mip 层级和用途标志，通过 TextureView 暴露给管线使用。

```js
// 创建一张渲染目标纹理
const texture = device.createTexture({
  size: { width: 800, height: 600 },
  format: 'bgra8unorm',
  usage: GPUTextureUsage.RENDER_ATTACHMENT | GPUTextureUsage.COPY_SRC,
});
const view = texture.createView();
```

## Shader

Shader 是跑在 GPU 上的程序，用 WGSL（WebGPU Shading Language）编写：顶点着色器变换顶点、片元着色器计算像素颜色、计算着色器做通用并行计算。Shader 代码以字符串形式通过 `device.createShaderModule()` 编译成 ShaderModule，再被 Pipeline 引用。

```js
const shaderModule = device.createShaderModule({
  code: `
    @vertex
    fn vs_main(@builtin(vertex_index) idx: u32) -> @builtin(position) vec4<f32> {
      var pos = array<vec2<f32>, 3>(
        vec2<f32>(0.0, 0.5),
        vec2<f32>(-0.5, -0.5),
        vec2<f32>(0.5, -0.5)
      );
      return vec4<f32>(pos[idx], 0.0, 1.0);
    }

    @fragment
    fn fs_main() -> @location(0) vec4<f32> {
      return vec4<f32>(1.0, 0.0, 0.0, 1.0);
    }
  `,
});
```

## Bind Group

Bind Group 是「资源绑定集合」：把 Buffer、Texture、Sampler 等资源按声明好的布局（Bind Group Layout）组织起来，供 Shader 在某一组（group）的某个槽位（binding）访问。它连接了「CPU 侧的资源」和「GPU 侧的 Shader 变量」，是 WebGPU 资源管理的核心机制。

```js
// 布局：声明 group 0 的 binding 0 是 uniform buffer
const bindGroupLayout = device.createBindGroupLayout({
  entries: [{ binding: 0, visibility: GPUShaderStage.VERTEX, buffer: { type: 'uniform' } }],
});

const bindGroup = device.createBindGroup({
  layout: bindGroupLayout,
  entries: [{ binding: 0, resource: { buffer: uniformBuffer } }],
});
```

## Pipeline

Pipeline 是 GPU 执行程序的「完整配置」：它把 Shader、顶点布局、绑定组布局、渲染状态等打包成一个不可变对象，提交时 GPU 按此配置执行。Pipeline 分两类——RenderPipeline（渲染管线，走顶点→片元）和 ComputePipeline（计算管线，跑计算着色器）。

### Compute Pipeline

Compute Pipeline 执行计算着色器，做通用并行计算：不经过顶点/片元阶段，直接跑 @compute 函数，通过 dispatch 指定工作线程组数。它是 WebGPU 做 GPGPU（AI 推理、物理模拟、图像处理）的基础。

```js
// 计算管线：把输入数组翻倍
const computePipeline = device.createComputePipeline({
  layout: 'auto',
  compute: {
    module: device.createShaderModule({
      code: `
        @group(0) @binding(0) var<storage, read_write> data: array<f32>;
        @compute @workgroup_size(64)
        fn main(@builtin(global_invocation_id) id: vec3<u32>) {
          data[id.x] = data[id.x] * 2.0;
        }
      `,
    }),
    entryPoint: 'main',
  },
});
```

### Render Pipeline

Render Pipeline 执行渲染：顶点着色器处理顶点 → 光栅化 → 片元着色器着色像素，最终写入颜色附件。创建时需指定顶点状态（缓冲布局）、片元状态（输出格式）、以及 primitive、depth-stencil 等状态。

```js
// 渲染管线
const renderPipeline = device.createRenderPipeline({
  layout: 'auto',
  vertex: {
    module: shaderModule,
    entryPoint: 'vs_main',
  },
  fragment: {
    module: shaderModule,
    entryPoint: 'fs_main',
    targets: [{ format: 'bgra8unorm' }],
  },
  primitive: { topology: 'triangle-list' },
});
```

## 应用场景实战

### 场景一：GPU 并行计算（数组求和）

```js
// 用计算着色器并行求数组平方和
const data = new Float32Array([1, 2, 3, 4, 5, 6, 7, 8]);
const buffer = device.createBuffer({
  size: data.byteLength,
  usage: GPUBufferUsage.STORAGE | GPUBufferUsage.COPY_SRC | GPUBufferUsage.COPY_DST,
});
device.queue.writeBuffer(buffer, 0, data);

const pipeline = device.createComputePipeline({
  layout: 'auto',
  compute: {
    module: device.createShaderModule({
      code: `
        @group(0) @binding(0) var<storage, read_write> arr: array<f32>;
        @compute @workgroup_size(64)
        fn main(@builtin(global_invocation_id) id: vec3<u32>) {
          arr[id.x] = arr[id.x] * arr[id.x];
        }
      `,
    }),
    entryPoint: 'main',
  },
});

const bindGroup = device.createBindGroup({
  layout: pipeline.getBindGroupLayout(0),
  entries: [{ binding: 0, resource: { buffer } }],
});

const encoder = device.createCommandEncoder();
const pass = encoder.beginComputePass();
pass.setPipeline(pipeline);
pass.setBindGroup(0, bindGroup);
pass.dispatchWorkgroups(1);
pass.end();
device.queue.submit([encoder.finish()]);
```

### 场景二：渲染一个三角形

```js
// 完整的三角形渲染（含清屏与提交）
const context = canvas.getContext('webgpu');
const format = navigator.gpu.getPreferredCanvasFormat();
context.configure({ device, format });

const encoder = device.createCommandEncoder();
const pass = encoder.beginRenderPass({
  colorAttachments: [{
    view: context.getCurrentTexture().createView(),
    clearValue: { r: 0, g: 0, b: 0, a: 1 },
    loadOp: 'clear',
    storeOp: 'store',
  }],
});
pass.setPipeline(renderPipeline);
pass.draw(3); // 3 个顶点
pass.end();
device.queue.submit([encoder.finish()]);
```

## 最佳实践与踩坑记录

### 最佳实践

1. 入口处先判空 `navigator.gpu`，做好不支持 WebGPU 的降级
2. 用 `layout: 'auto'` 快速起步，性能敏感时再显式声明布局
3. Pipeline 创建昂贵，创建后缓存复用，不要每帧重建
4. 批量提交命令，减少 queue.submit 次数
5. 监听 device.lost，设备丢失时重建资源
6. 数据上传用 queue.writeBuffer，避免每帧 CPU-GPU 拷贝

### 踩坑记录

```text
坑 1：不判空 navigator.gpu
结论：无 GPU 或旧浏览器环境直接抛错白屏。
原因：直接 navigator.gpu.requestAdapter()，没做能力检测。
解法：入口先判 if (!navigator.gpu) 降级到 WASM/CPU 或提示不支持。

坑 2：每帧重建 pipeline
结论：帧率掉到个位数，GPU 时间全耗在管线编译。
原因：pipeline 创建要编译 shader，开销极大，却放在渲染循环里反复建。
解法：pipeline 创建一次后缓存，循环里只换 bind group 和 submit。

坑 3：没监听 device.lost
结论：切换 GPU 或驱动重置后画面永久黑屏。
原因：设备丢失事件没处理，没有重建资源。
解法：device.lost.then 里重建 device 和全部资源。

坑 4：mapAsync 回读阻塞渲染
结论：读回结果时页面明显卡顿。
原因：同步等待 mapAsync 结果，阻塞主线程。
解法：mapAsync 用 await 异步处理，或尽量不回读（结果直接当顶点/存储用）。

坑 5：uniform buffer 没按对齐规则
结论：WGSL 读取 uniform 值错位，数据全错。
原因：WGSL 的 uniform 有对齐要求（如 vec4 16 字节对齐），buffer 没按规则填充。
解法：按 WGSL 对齐规则布局 buffer，或用结构体声明加显式 padding。

坑 6：命令编码器复用或忘记 finish
结论：提交空命令，或复用已结束的编码器报错。
原因：encoder.finish() 后不能再用，或 beginRenderPass 后忘记 end。
解法：每次 submit 前新建 encoder，begin/end 严格配对。
```

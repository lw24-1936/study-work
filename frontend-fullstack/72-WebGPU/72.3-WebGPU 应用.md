## 概述

WebGPU 的通用计算能力让它远超「画图」：GPU 的数千个并行核心既能渲染 3D，也能做矩阵运算、物理模拟、图像处理和科学计算。这一篇聚焦 WebGPU 在「渲染之外」的实战应用——从 AI 推理到粒子物理，展示同一套 API 如何覆盖截然不同的计算负载。

```text
WebGPU 应用的版图：
1. AI 推理 —— 矩阵乘法加速神经网络
2. 图像处理 —— 逐像素并行滤镜与变换
3. 3D 渲染 —— 场景、光照、模型
4. 物理模拟 —— 粒子、刚体、流体
5. 数据可视化 —— 大规模点/线/面的实时渲染
6. 科学计算 —— 矩阵、微分方程、分子模拟
```

## AI Inference

AI Inference（AI 推理）是 WebGPU 最具潜力的应用：神经网络的推理本质是海量矩阵乘法，天然契合 GPU 并行。把模型权重加载到 storage buffer，用计算着色器执行矩阵乘和激活函数，就能在浏览器本地跑推理。上层库（ONNX Runtime Web、Transformers.js）已封装好这些算子。

```js
// 用 ONNX Runtime Web 的 WebGPU 后端做推理
import * as ort from 'onnxruntime-web';

const session = await ort.InferenceSession.create('./model.onnx', {
  executionProviders: ['webgpu', 'wasm'],
});
const input = new ort.Tensor('float32', new Float32Array([1, 2, 3]), [1, 3]);
const results = await session.run({ input });
```

## Image Processing

Image Processing（图像处理）是 WebGPU 的经典应用：图像的每个像素独立处理，天然可并行。把图像加载为 texture，用片元着色器或计算着色器逐像素执行滤镜（模糊、锐化、色调、边缘检测），比 CPU 逐像素循环快几个数量级，且能实时预览。

```wgsl
// 灰度滤镜：计算像素亮度
@group(0) @binding(0) var img: texture_2d<f32>;
@group(0) @binding(1) var samp: sampler;
@group(0) @binding(2) var<storage, read_write> out: array<f32>;

@compute @workgroup_size(8, 8)
fn main(@builtin(global_invocation_id) id: vec3<u32>) {
  let uv = vec2<f32>(f32(id.x), f32(id.y)) / vec2<f32>(512.0, 512.0);
  let color = textureSample(img, samp, uv).rgb;
  let gray = dot(color, vec3<f32>(0.299, 0.587, 0.114));
  out[id.y * 512 + id.x] = gray;
}
```

## 3D

3D 渲染是 WebGPU 的本职工作：通过渲染管线把顶点变换到屏幕、光栅化成片元、着色成像素。WebGPU 相比 WebGL 提供更现代的管线模型（显式绑定组、可编程管线状态），配合 WGSL 能实现 PBR 光照、阴影、后处理等现代渲染效果，也是 Three.js 等引擎未来的底层目标。

```js
// 3D 渲染循环骨架
function frame() {
  const encoder = device.createCommandEncoder();
  const pass = encoder.beginRenderPass({
    colorAttachments: [{
      view: context.getCurrentTexture().createView(),
      clearValue: { r: 0.1, g: 0.1, b: 0.1, a: 1 },
      loadOp: 'clear',
      storeOp: 'store',
    }],
    depthStencilAttachment: {
      view: depthTexture.createView(),
      depthClearValue: 1.0,
      depthLoadOp: 'clear',
      depthStoreOp: 'store',
    },
  });
  pass.setPipeline(renderPipeline);
  pass.setVertexBuffer(0, vertexBuffer);
  pass.setBindGroup(0, bindGroup);
  pass.draw(vertexCount);
  pass.end();
  device.queue.submit([encoder.finish()]);
  requestAnimationFrame(frame);
}
```

## Physics

Physics（物理模拟）用 WebGPU 的并行计算实现粒子、刚体、流体等模拟：每个粒子/质点由一个线程计算，数千上万个对象同时更新，实现远超 CPU 的规模。典型如 N 体问题、布料、烟雾流体，核心是「每帧并行更新状态 → 回读或直接渲染」。

```wgsl
// 粒子运动：重力 + 简单积分
struct Particle {
  pos: vec2<f32>,
  vel: vec2<f32>,
};

@group(0) @binding(0) var<storage, read_write> particles: array<Particle>;

@compute @workgroup_size(64)
fn main(@builtin(global_invocation_id) id: vec3<u32>) {
  var p = particles[id.x];
  p.vel += vec2<f32>(0.0, -0.01); // 重力
  p.pos += p.vel;
  particles[id.x] = p;
}
```

## Data Visualization

Data Visualization（数据可视化）用 WebGPU 渲染大规模数据：当数据点达到十万、百万级时，Canvas 2D 和 DOM 都会卡顿，而 WebGPU 用顶点缓冲一次性提交海量点/线，配合计算着色器做位置计算，实现流畅交互的散点图、轨迹图、网络图。

```js
// 百万级散点：顶点缓冲 + 一次 draw
const positions = new Float32Array(1_000_000 * 2); // 100 万个点
const vertexBuffer = device.createBuffer({
  size: positions.byteLength,
  usage: GPUBufferUsage.VERTEX | GPUBufferUsage.COPY_DST,
});
device.queue.writeBuffer(vertexBuffer, 0, positions);

pass.setVertexBuffer(0, vertexBuffer);
pass.draw(1_000_000); // 一次绘制百万点
```

## Scientific Computing

Scientific Computing（科学计算）利用 WebGPU 做大规模数值计算：矩阵运算、线性方程组、微分方程求解、分子动力学等。这些任务高度并行，GPU 加速明显。WebGPU 的 storage buffer + 计算着色器构成「数据并行」的通用编程模型，可替代部分 CPU 科学计算负载。

```wgsl
// 向量点积：两个数组逐元素乘再归约
@group(0) @binding(0) var<storage, read> a: array<f32>;
@group(0) @binding(1) var<storage, read> b: array<f32>;
@group(0) @binding(2) var<storage, read_write> partial: array<f32>;

@compute @workgroup_size(256)
fn main(@builtin(global_invocation_id) id: vec3<u32>) {
  let idx = id.x;
  // 每线程算一个乘积，后续归约求和
  partial[idx] = a[idx] * b[idx];
}
```

## 应用场景实战

### 场景一：GPU 矩阵乘法（AI 推理基础算子）

```js
// 用计算着色器实现矩阵乘法的调用骨架
const N = 64;
const size = N * N * 4;
const aBuffer = device.createBuffer({ size, usage: GPUBufferUsage.STORAGE | GPUBufferUsage.COPY_DST });
const bBuffer = device.createBuffer({ size, usage: GPUBufferUsage.STORAGE | GPUBufferUsage.COPY_DST });
const cBuffer = device.createBuffer({ size, usage: GPUBufferUsage.STORAGE | GPUBufferUsage.COPY_SRC });

const matmulPipeline = device.createComputePipeline({
  layout: 'auto',
  compute: {
    module: device.createShaderModule({
      code: `
        @group(0) @binding(0) var<storage, read> A: array<f32>;
        @group(0) @binding(1) var<storage, read> B: array<f32>;
        @group(0) @binding(2) var<storage, read_write> C: array<f32>;
        const N: u32 = 64;
        @compute @workgroup_size(8, 8)
        fn main(@builtin(global_invocation_id) id: vec3<u32>) {
          let row = id.y;
          let col = id.x;
          var sum = 0.0;
          for (var k = 0u; k < N; k = k + 1u) {
            sum += A[row * N + k] * B[k * N + col];
          }
          C[row * N + col] = sum;
        }
      `,
    }),
    entryPoint: 'main',
  },
});

const bindGroup = device.createBindGroup({
  layout: matmulPipeline.getBindGroupLayout(0),
  entries: [
    { binding: 0, resource: { buffer: aBuffer } },
    { binding: 1, resource: { buffer: bBuffer } },
    { binding: 2, resource: { buffer: cBuffer } },
  ],
});

const encoder = device.createCommandEncoder();
const pass = encoder.beginComputePass();
pass.setPipeline(matmulPipeline);
pass.setBindGroup(0, bindGroup);
pass.dispatchWorkgroups(N / 8, N / 8);
pass.end();
device.queue.submit([encoder.finish()]);
```

### 场景二：粒子物理模拟 + 渲染联动

```js
// 粒子更新（计算着色器）+ 渲染（把粒子状态当顶点）
const particleCount = 10000;
const particleBuffer = device.createBuffer({
  size: particleCount * 8, // 每粒子 vec2 pos
  usage: GPUBufferUsage.STORAGE | GPUBufferUsage.VERTEX,
});

// 每帧：先 compute 更新粒子，再 render 绘制
function tick() {
  const encoder = device.createCommandEncoder();
  const computePass = encoder.beginComputePass();
  computePass.setPipeline(updatePipeline);
  computePass.setBindGroup(0, particleBindGroup);
  computePass.dispatchWorkgroups(Math.ceil(particleCount / 64));
  computePass.end();

  const renderPass = encoder.beginRenderPass({
    colorAttachments: [{
      view: context.getCurrentTexture().createView(),
      clearValue: { r: 0, g: 0, b: 0, a: 1 },
      loadOp: 'clear',
      storeOp: 'store',
    }],
  });
  renderPass.setPipeline(renderPipeline);
  renderPass.setVertexBuffer(0, particleBuffer);
  renderPass.draw(particleCount);
  renderPass.end();

  device.queue.submit([encoder.finish()]);
  requestAnimationFrame(tick);
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. 数据量大、可并行的任务才值得上 WebGPU，小任务 CPU 反而更快
2. 复用 buffer 和 pipeline，避免每帧重新创建
3. 计算着色器结果直接当顶点用，省一次回读
4. 权重/常量数据一次上传，循环里只更新变化部分
5. 回读结果（mapAsync）会阻塞，尽量少回读或异步处理

### 踩坑记录

```text
坑 1：小任务硬上 WebGPU 反而更慢
结论：几 KB 数据的计算，WebGPU 比 CPU 慢几倍。
原因：GPU 上传/调度/回读有固定开销，数据量小时摊销不掉。
解法：数据量大、可并行才用 WebGPU，小任务直接 CPU 算。

坑 2：频繁 mapAsync 回读结果
结论：每一帧都回读，渲染帧率被拖垮。
原因：GPU 到 CPU 回读要走异步 + 同步点，频繁回读阻塞管线。
解法：结果留在 GPU 端直接消费（当顶点/存储缓冲），减少回读。

坑 3：没做 WebGPU 可用性检测和降级
结论：Safari 老版本或无 GPU 设备上功能直接失效。
原因：只写 WebGPU 路径，没有 WASM/CPU 降级。
解法：能力检测 + 降级链（WebGPU → WASM → CPU）。

坑 4：权重/常量数据每帧重复上传
结论：模型推理每帧都重新传权重，带宽和延迟爆表。
原因：writeBuffer 放在渲染循环里，权重没缓存。
解法：权重/常量只在初始化上传一次，循环里只更新变化的输入。

坑 5：compute shader 的 workgroup 大小设置不当
结论：并行度不够或超出设备限制，性能差甚至报错。
原因：没考虑设备的 maxComputeWorkgroupSize 和线程组织。
解法：根据设备限制设 workgroup，用合理的分块尺寸（如 256）。

坑 6：结果 buffer 没考虑 stride/对齐
结论：读出的数据错位，图像/矩阵全乱。
原因：不同数据类型 stride 不同，buffer 布局没按 WGSL 对齐。
解法：显式声明 stride，buffer 填充按结构体对齐规则。
```

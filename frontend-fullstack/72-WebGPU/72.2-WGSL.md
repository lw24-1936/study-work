## 概述

WGSL（WebGPU Shading Language）是 WebGPU 专用的着色语言：一种静态类型的类 Rust 语法语言，用于编写跑在 GPU 上的顶点着色器、片元着色器和计算着色器。它替代了 WebGL 时代的 GLSL，与 WebGPU 的资源绑定模型（group/binding）和内置变量（builtin）深度整合。

```text
WGSL 的核心特性：
1. 静态类型 —— 显式类型标注（f32、u32、vec3<f32>）
2. 三类入口 —— @vertex、@fragment、@compute
3. 资源绑定 —— @group / @binding 访问 Buffer / Texture
4. 内置变量 —— @builtin(position / vertex_index)
5. 内置函数 —— 数学、纹理采样、原子操作
```

```wgsl
// WGSL 最小结构示例
@compute @workgroup_size(1)
fn main() {
  // 空实现
}
```

## Vertex Shader

Vertex Shader（顶点着色器）负责处理每个顶点：输入顶点属性（位置、法线、UV），输出变换后的顶点位置（clip space 坐标）以及传递给片元着色器的插值数据。它用 `@vertex` 标注入口，通过 `@builtin(vertex_index)` 或 `@location` 读取顶点数据。

```text
顶点着色器的职责：
1. 接收顶点 —— 通过 @location 或 @builtin 输入
2. 坐标变换 —— 模型 → 世界 → 裁剪空间
3. 输出位置 —— @builtin(position) 必填
4. 传递数据 —— 插值属性传给片元着色器
```

```wgsl
// 顶点着色器：位置 + 颜色传递
struct VertexOutput {
  @builtin(position) position: vec4<f32>,
  @location(0) color: vec4<f32>,
};

@vertex
fn vs_main(
  @location(0) pos: vec3<f32>,
  @location(1) color: vec4<f32>
) -> VertexOutput {
  var out: VertexOutput;
  out.position = vec4<f32>(pos, 1.0);
  out.color = color;
  return out;
}
```

## Fragment Shader

Fragment Shader（片元着色器）负责计算每个像素（片元）的颜色：接收顶点着色器插值后的数据，执行光照、纹理采样等计算，输出最终颜色到渲染目标。它用 `@fragment` 标注入口，用 `@location` 声明输出颜色。

```text
片元着色器的职责：
1. 接收插值 —— 顶点着色器传来的插值数据
2. 纹理采样 —— 用 sampler 读取纹理颜色
3. 光照计算 —— 计算漫反射、高光等
4. 输出颜色 —— @location 输出到渲染目标
```

```wgsl
// 片元着色器：接收颜色直接输出
@fragment
fn fs_main(in: VertexOutput) -> @location(0) vec4<f32> {
  return in.color;
}
```

```wgsl
// 片元着色器：纹理采样
@group(0) @binding(0) var tex: texture_2d<f32>;
@group(0) @binding(1) var samp: sampler;

@fragment
fn fs_tex(@location(0) uv: vec2<f32>) -> @location(0) vec4<f32> {
  return textureSample(tex, samp, uv);
}
```

## Compute Shader

Compute Shader（计算着色器）做通用并行计算：不参与渲染，直接在 GPU 上并行处理大量数据。它用 `@compute` 标注入口，通过 `@workgroup_size` 声明每个工作组的大小，用 `@builtin(global_invocation_id)` 获取当前线程的全局索引，从而处理数组中的对应元素。

```text
计算着色器的要点：
1. 通用计算 —— 不经过光栅化，直接并行
2. 工作组 —— @workgroup_size 定义组内线程数
3. 全局索引 —— @builtin(global_invocation_id) 定位元素
4. 存储读写 —— 通过 storage buffer 读写数据
```

```wgsl
// 计算着色器：数组元素翻倍
@group(0) @binding(0) var<storage, read_write> data: array<f32>;

@compute @workgroup_size(64)
fn main(@builtin(global_invocation_id) id: vec3<u32>) {
  data[id.x] = data[id.x] * 2.0;
}
```

## Uniform

Uniform 是一类「只读、对所有线程一致」的缓冲区：用于传递变换矩阵、光照参数、时间等「整个绘制调用共享」的常量。它在 CPU 侧以 uniform buffer 形式上传，在 WGSL 中用 `var<uniform>` 声明，适合小量、高频共享的数据。

```text
Uniform 的特点：
1. 只读 —— 着色器内不能写
2. 共享一致 —— 所有线程读到同一份
3. 小容量 —— 适合矩阵、标量等常量
4. 高频更新 —— 每帧可更新（如相机矩阵）
```

```wgsl
// WGSL 侧声明 uniform
struct Uniforms {
  modelViewProjection: mat4x4<f32>,
  time: f32,
};

@group(0) @binding(0) var<uniform> uniforms: Uniforms;

@vertex
fn vs_main(@location(0) pos: vec3<f32>) -> @builtin(position) vec4<f32> {
  return uniforms.modelViewProjection * vec4<f32>(pos, 1.0);
}
```

```js
// JS 侧：上传 uniform 数据
const uniformBuffer = device.createBuffer({
  size: 80, // mat4x4 (64) + f32 (16)
  usage: GPUBufferUsage.UNIFORM | GPUBufferUsage.COPY_DST,
});
const mvp = new Float32Array(16);
device.queue.writeBuffer(uniformBuffer, 0, mvp);
```

## Storage Buffer

Storage Buffer 是「可读写、可随机访问」的缓冲区：计算着色器通过它读写任意位置的数组数据，是 GPGPU 数据交换的主要通道。相比 uniform，storage buffer 容量更大、支持读写，但访问速度稍慢、需要声明读写权限（read / write / read_write）。

```text
Storage Buffer 的特点：
1. 可读写 —— 支持 read / write / read_write
2. 大容量 —— 远大于 uniform 的限制
3. 随机访问 —— 按索引读写任意元素
4. 计算主力 —— 计算着色器的数据进出通道
```

```wgsl
// 声明只读和可写的 storage buffer
@group(0) @binding(0) var<storage, read> input: array<f32>;
@group(0) @binding(1) var<storage, read_write> output: array<f32>;

@compute @workgroup_size(64)
fn main(@builtin(global_invocation_id) id: vec3<u32>) {
  output[id.x] = input[id.x] * 2.0;
}
```

```js
// JS 侧：创建 storage buffer
const inputBuffer = device.createBuffer({
  size: data.byteLength,
  usage: GPUBufferUsage.STORAGE | GPUBufferUsage.COPY_DST,
});
const outputBuffer = device.createBuffer({
  size: data.byteLength,
  usage: GPUBufferUsage.STORAGE | GPUBufferUsage.COPY_SRC,
});
```

## 应用场景实战

### 场景一：顶点 + 片元完成彩色三角形

```wgsl
// 一个完整可运行的 WGSL 模块（顶点传颜色，片元输出）
struct VSOutput {
  @builtin(position) pos: vec4<f32>,
  @location(0) color: vec4<f32>,
};

@vertex
fn vs_main(@builtin(vertex_index) idx: u32) -> VSOutput {
  var positions = array<vec2<f32>, 3>(
    vec2<f32>(0.0, 0.5),
    vec2<f32>(-0.5, -0.5),
    vec2<f32>(0.5, -0.5)
  );
  var colors = array<vec4<f32>, 3>(
    vec4<f32>(1.0, 0.0, 0.0, 1.0),
    vec4<f32>(0.0, 1.0, 0.0, 1.0),
    vec4<f32>(0.0, 0.0, 1.0, 1.0)
  );
  var out: VSOutput;
  out.pos = vec4<f32>(positions[idx], 0.0, 1.0);
  out.color = colors[idx];
  return out;
}

@fragment
fn fs_main(in: VSOutput) -> @location(0) vec4<f32> {
  return in.color;
}
```

### 场景二：uniform 驱动的动画

```wgsl
// 用 uniform 里的时间做顶点动画（波浪效果）
struct Uniforms {
  time: f32,
};

@group(0) @binding(0) var<uniform> u: Uniforms;

@vertex
fn vs_wave(@location(0) pos: vec3<f32>) -> @builtin(position) vec4<f32> {
  var p = pos;
  p.y += sin(pos.x * 3.0 + u.time) * 0.1;
  return vec4<f32>(p, 1.0);
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. 结构体用 struct 声明，字段类型显式标注
2. uniform 存共享小数据，storage buffer 存大数组
3. 声明正确的 var 权限（read / write / read_write）
4. 计算着色器合理设置 workgroup_size（64 或 256 常见）
5. 矩阵运算注意列主序，与 JS 侧数据对齐

### 踩坑记录

```text
坑 1：uniform 和 storage 用错
结论：数据量大时报 uniform 超限，或数据无法更新。
原因：uniform 有大小上限且只读，却塞了大数组或要求写。
解法：大数组、需读写用 storage buffer，常量用 uniform。

坑 2：矩阵乘法顺序写反
结论：顶点变换结果错误，画面错乱。
原因：WGSL 矩阵列主序，乘法顺序与直觉相反。
解法：统一用 M * v 形式，明确向量是列向量。

坑 3：workgroup_size 与 dispatch 不匹配
结论：数组后半段没被处理。
原因：workgroup 总数乘 workgroup_size 小于数组长度。
解法：dispatch 数 = ceil(元素数 / workgroup_size)。

坑 4：@location 编号冲突
结论：顶点属性错位，颜色/位置对不上。
原因：多个输入用了相同的 @location 编号。
解法：每个输入属性分配唯一的 location，与 JS 顶点布局一致。

坑 5：类型不匹配导致编译失败
结论：shader 模块创建时报编译错误。
原因：WGSL 静态类型严格，隐式转换被拒绝（如 i32 传 f32）。
解法：显式类型标注，需要转换时用 f32()/i32() 等构造器。
```

## 概述

React 是一个用于构建用户界面的声明式 JavaScript 库。它把 UI 拆分成组件，通过「状态驱动视图」的思想：你只描述「状态是什么样」，React 负责「视图该如何渲染」。

```text
React 的核心思想：
1. 声明式 —— 描述「应该是什么」，而非「怎么做」
2. 组件化 —— UI 拆成可复用的组件，每个组件管理自己的状态
3. 单向数据流 —— Props 从父组件流向子组件，数据流可预测
4. JSX —— 在 JavaScript 中书写类 HTML 的语法
5. 虚拟 DOM —— 先算差异再更新真实 DOM
```

```jsx
// 一个最小的 React 组件
function App() {
  return <h1>Hello, React</h1>;
}
```

## JSX

JSX 是 JavaScript 的语法扩展，允许在 JS 中直接书写「像 HTML」的标签，编译后被转换成 `React.createElement` 调用。

```jsx
// JSX 写法
const element = <h1 className="title">Hello</h1>;

// 编译后等价于
const element = React.createElement('h1', { className: 'title' }, 'Hello');
```

```jsx
// 表达式插值：用 {} 嵌入任意 JS 表达式
const name = 'Alice';
const greeting = <p>你好，{name}</p>;

// 属性：class 用 className，绑定变量用 {}
const cls = 'active';
const btn = <button className={cls} disabled={false}>点我</button>;

// 内联样式：对象形式，属性名驼峰
const style = { color: 'red', fontSize: 20 };
const title = <div style={style}>标题</div>;
```

## Component

组件是 React 的最小复用单元，分函数组件与类组件两类，现代 React 以函数组件为主。

```jsx
// 函数组件：接收 props，返回 JSX
function Welcome(props) {
  return <h1>Hello, {props.name}</h1>;
}

// 箭头函数组件
const Welcome = ({ name }) => <h1>Hello, {name}</h1>;

// 类组件（历史写法，理解即可）
class Welcome extends React.Component {
  render() {
    return <h1>Hello, {this.props.name}</h1>;
  }
}
```

```jsx
// 组件命名必须大写，小写会被当作 HTML 标签
function App() {
  return <Welcome name="Alice" />;  // 大写 → 组件
}
```

## Props

Props 是父组件传给子组件的「只读」数据，子组件不可直接修改，只能通过回调通知父组件更新。

```jsx
function UserCard({ name, age, onDelete }) {
  return (
    <div>
      <span>{name}（{age} 岁）</span>
      <button onClick={onDelete}>删除</button>
    </div>
  );
}

// 默认值
function UserCard({ name = '匿名', age = 0 }) {
  return <span>{name} {age}</span>;
}
```

```jsx
// 传递所有 props 的展开写法
const data = { name: 'Bob', age: 18 };
<UserCard {...data} />;
```

## State

State 是组件内部的可变状态，通过 `useState` 管理，更新后 React 自动重新渲染组件。

```jsx
import { useState } from 'react';

function Counter() {
  const [count, setCount] = useState(0);

  return (
    <button onClick={() => setCount(count + 1)}>
      点击了 {count} 次
    </button>
  );
}
```

```jsx
// 状态更新是异步的、批量的；函数式更新避免读到旧值
function Counter() {
  const [count, setCount] = useState(0);
  const addThree = () => {
    setCount(c => c + 1);  // 函数式更新
    setCount(c => c + 1);
    setCount(c => c + 1);
  };
  return <button onClick={addThree}>{count}</button>;  // 一次 +3
}
```

## Event

React 事件用驼峰命名（onClick、onChange），通过合成事件统一跨浏览器差异。

```jsx
function Form() {
  const handleClick = (e) => {
    e.preventDefault();       // 阻止默认行为
    console.log('点击了按钮');
  };
  const handleChange = (e) => {
    console.log(e.target.value);  // 读取输入值
  };

  return (
    <form>
      <input onChange={handleChange} />
      <button onClick={handleClick}>提交</button>
    </form>
  );
}
```

```jsx
// 事件处理中 this 的绑定（类组件）或直接传参（函数组件）
function List({ onSelect }) {
  return (
    <ul>
      <li onClick={() => onSelect('a')}>A</li>
      <li onClick={() => onSelect('b')}>B</li>
    </ul>
  );
}
```

## Conditional Rendering

条件渲染根据状态决定渲染哪个分支，常用三元表达式、逻辑与、短路等。

```jsx
function Greeting({ isLoggedIn }) {
  // 三元表达式
  return isLoggedIn ? <h1>欢迎回来</h1> : <h1>请先登录</h1>;
}

function Notice({ msg }) {
  // 逻辑与：msg 为空时不渲染
  return <div>{msg && <p>{msg}</p>}</div>;
}

function Status({ type }) {
  // 变量存储分支
  let content;
  if (type === 'loading') content = <Spinner />;
  else if (type === 'error') content = <Error />;
  else content = <Data />;
  return <div>{content}</div>;
}
```

## List Rendering

列表渲染用 `map` 遍历数组生成元素，每个元素需要一个稳定的 `key`。

```jsx
function TodoList({ todos }) {
  return (
    <ul>
      {todos.map(todo => (
        <li key={todo.id}>{todo.text}</li>
      ))}
    </ul>
  );
}
```

```jsx
// 过滤 + 排序后渲染
const active = todos.filter(t => !t.done);
const sorted = [...active].sort((a, b) => a.priority - b.priority);
```

## Key

Key 帮助 React 在 Diff 时识别列表项是否变化，决定复用还是重建 DOM。必须使用稳定且唯一的标识。

```jsx
// 正确：用数据的唯一 id
todos.map(t => <li key={t.id}>{t.text}</li>);

// 错误：用数组下标（列表重排/增删时会导致错乱）
todos.map((t, i) => <li key={i}>{t.text}</li>);
```

```text
Key 的作用与规则：
1. 帮助 React 判断哪些元素可复用、哪些需重建
2. 兄弟节点之间必须唯一，不同列表间可重复
3. 优先使用稳定唯一 id，避免用 index
4. key 变化会强制重建组件并丢失内部状态
```

## Composition

组合（Composition）指组件通过 children 或 props 嵌套其他组件，是 React 复用 UI 的主要方式，优先于继承。

```jsx
// children 组合：容器组件包裹任意内容
function Card({ children }) {
  return <div className="card">{children}</div>;
}

function App() {
  return (
    <Card>
      <h2>标题</h2>
      <p>正文内容</p>
    </Card>
  );
}
```

```jsx
// 具名插槽：通过 props 传递多个「槽位」
function Layout({ sidebar, main }) {
  return (
    <div className="layout">
      <aside>{sidebar}</aside>
      <section>{main}</section>
    </div>
  );
}

<Layout
  sidebar={<Nav />}
  main={<Content />}
/>;
```

## 应用场景实战

### 场景一：受控表单

```jsx
import { useState } from 'react';

function LoginForm({ onSubmit }) {
  const [form, setForm] = useState({ user: '', pwd: '' });

  const handleChange = (e) => {
    const { name, value } = e.target;
    setForm(prev => ({ ...prev, [name]: value }));
  };

  const handleSubmit = (e) => {
    e.preventDefault();
    onSubmit(form);
  };

  return (
    <form onSubmit={handleSubmit}>
      <input name="user" value={form.user} onChange={handleChange} />
      <input name="pwd" type="password" value={form.pwd} onChange={handleChange} />
      <button type="submit">登录</button>
    </form>
  );
}
```

### 场景二：可复用的标签页组件（组合 + 状态）

```jsx
import { useState } from 'react';

function Tabs({ tabs }) {
  const [active, setActive] = useState(tabs[0].key);

  return (
    <div>
      <div className="tab-header">
        {tabs.map(tab => (
          <button
            key={tab.key}
            className={active === tab.key ? 'active' : ''}
            onClick={() => setActive(tab.key)}
          >
            {tab.label}
          </button>
        ))}
      </div>
      <div className="tab-body">
        {tabs.find(tab => tab.key === active)?.content}
      </div>
    </div>
  );
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. 组件保持单一职责，小而专注，便于复用与测试
2. State 只存「派生不了」的最小状态，能算出来的别存
3. 列表渲染必须给稳定唯一 key，避免用 index
4. Props 保持只读，需要修改就通过回调上抛
5. 优先使用组合而非继承来复用 UI

### 踩坑记录

```text
坑 1：直接在循环里定义组件
结论：循环中定义组件会导致每次渲染都重新创建，状态丢失。
原因：组件定义位置变化，React 认为是不同组件。
解法：组件定义在循环外，循环里只做渲染调用。

坑 2：用 index 作 key 导致状态错乱
结论：列表增删或重排时，输入框内容/焦点错位。
原因：index 不随数据稳定，React 复用错误的 DOM。
解法：改用数据的唯一 id 作 key。

坑 3：直接修改 state 不触发渲染
结论：改了 state 但界面不更新。
原因：state 必须通过 setState 返回新引用才触发更新。
解法：数组用 map/filter/concat，对象用展开运算符生成新对象。

坑 4：条件渲染返回了 undefined
结论：界面出现空白或报错。
原因：分支没有覆盖，返回 undefined。
解法：确保每个分支都返回合法的 JSX 或 null。

坑 5：事件处理函数立即执行
结论：onClick={handleClick()} 在渲染时就被调用。
原因：写了调用而不是传引用。
解法：传函数引用 onClick={handleClick}，需要参数就用箭头函数包裹。
```

## 概述

React 的生命周期本质上不是「一堆钩子函数」，而是「渲染的两个阶段 + 组件的三个状态」：组件经历挂载（Mount）、更新（Update）、卸载（Unmount），而每次更新又分为渲染阶段（Render Phase）与提交阶段（Commit Phase）。

```text
React 一次更新的完整流程：
触发（setState/props 变化）→ Render Phase（计算新 Fiber、可中断）
→ Commit Phase（应用 DOM 变更、执行副作用、不可中断）
```

```jsx
// 用 useEffect 观察挂载/更新/卸载三个时刻
function Logger({ id }) {
  useEffect(() => {
    console.log(`挂载/更新：${id}`);
    return () => console.log(`清理/卸载：${id}`);
  }, [id]);
  return <div>{id}</div>;
}
```

## Mount

挂载是组件首次插入 DOM 的过程：创建 Fiber、执行函数组件体、提交真实 DOM，并运行挂载副作用。

```text
挂载阶段（函数组件视角）：
1. 创建组件 Fiber 节点
2. 执行函数组件体（Render Phase，计算 JSX）
3. 提交 DOM（Commit Phase，插入真实节点）
4. 运行副作用（useEffect 首次执行）
5. 触发 ref 绑定、DOM 测量可用
```

```jsx
function Profile({ userId }) {
  const [user, setUser] = useState(null);

  // 挂载时拉取数据（空依赖 = 仅挂载执行）
  useEffect(() => {
    let active = true;
    fetch(`/api/user/${userId}`)
      .then(r => r.json())
      .then(data => { if (active) setUser(data); });
    return () => { active = false; };  // 卸载/更新前清理
  }, []);

  return <div>{user?.name}</div>;
}
```

## Update

更新是组件在 props 或 state 变化后的重新渲染：重新执行组件体，Diff 出差异后更新 DOM。

```text
触发更新的三种来源：
1. 父组件传入新的 props
2. 组件内部调用 setState（含 useReducer 的 dispatch）
3. 订阅的 Context 值发生变化
```

```jsx
function Counter() {
  const [count, setCount] = useState(0);

  // 每次 count 变化都重新执行组件体（Update）
  console.log('渲染，count =', count);

  // 依赖变化时运行清理 + 重新执行
  useEffect(() => {
    console.log('count 更新为', count);
    return () => console.log('清理旧的', count);
  }, [count]);

  return <button onClick={() => setCount(c => c + 1)}>{count}</button>;
}
```

## Unmount

卸载是组件从 DOM 移除的过程：执行所有清理函数、解绑 ref，之后组件不再参与渲染。

```text
卸载时发生的事：
1. 运行所有 useEffect 返回的清理函数
2. 解绑 ref（置为 null）
3. 移除真实 DOM 节点
4. 组件状态随之销毁
```

```jsx
function Timer() {
  useEffect(() => {
    const id = setInterval(() => console.log('tick'), 1000);
    return () => {
      clearInterval(id);  // 卸载时清理，避免泄漏
      console.log('Timer 已卸载');
    };
  }, []);
  return <div>计时中</div>;
}

// 条件渲染卸载组件
function App() {
  const [show, setShow] = useState(true);
  return (
    <div>
      <button onClick={() => setShow(!show)}>切换</button>
      {show && <Timer />}
    </div>
  );
}
```

## Render Phase

渲染阶段是 React 计算「新 UI 应该长什么样」的过程：执行组件函数、生成新的 Fiber 树、Diff 出变更。它是**纯计算、可中断、可丢弃**的。

```text
Render Phase 的特点：
1. 纯函数 —— 无副作用，多次执行结果应一致
2. 可中断 —— 并发模式下可暂停、让出主线程
3. 可丢弃 —— 高优先级任务插入时可能被丢弃重来
4. 不操作真实 DOM —— 只产出「变更描述」
```

```jsx
// 组件体（Render Phase）必须是纯函数
function Pure({ num }) {
  const doubled = num * 2;  // 纯计算
  return <div>{doubled}</div>;
  // 错误示范：这里不能发请求、改 ref、改全局变量
}
```

## Commit Phase

提交阶段把渲染阶段计算出的变更应用到真实 DOM，并同步执行 `useLayoutEffect`/`useInsertionEffect`，随后异步执行 `useEffect`。它是**不可中断**的。

```text
Commit Phase 的三个子阶段：
1. Before Mutation —— 读取旧 DOM（getSnapshotBeforeUpdate 时期）
2. Mutation —— 增删改真实 DOM、绑定 ref
3. Layout —— 运行 useLayoutEffect，DOM 已更新但未绘制
随后浏览器绘制，最后异步运行 useEffect。
```

```jsx
import { useLayoutEffect, useEffect } from 'react';

function Measure() {
  const ref = useRef(null);

  // Commit Phase 同步执行：绘制前测量
  useLayoutEffect(() => {
    const h = ref.current.offsetHeight;
    console.log('布局阶段高度', h);
  });

  // 绘制后异步执行
  useEffect(() => {
    console.log('绘制完成后执行');
  });

  return <div ref={ref} style={{ height: 100 }} />;
}
```

## Effect

Effect 指组件与外部系统（网络、定时器、订阅、DOM）的交互，通过 `useEffect` 声明，在提交后异步运行，是「副作用」的统称。

```text
Effect 与生命周期的关系：
1. 声明式 —— 描述「依赖什么、做什么、如何清理」
2. 每次渲染后对比依赖，决定是否重新执行
3. 卸载时执行最后一次清理函数
4. 与 Render Phase 严格分离（副作用不能发生在渲染阶段）
```

```jsx
function Chat({ roomId }) {
  useEffect(() => {
    // 依赖 roomId：进入新房间时订阅，离开旧房间时取消
    const connection = createConnection(roomId);
    connection.connect();
    return () => connection.disconnect();
  }, [roomId]);

  return <div>房间 {roomId}</div>;
}
```

```text
类组件生命周期 → 函数组件 Effect 对照：
componentDidMount → useEffect(..., [])
componentDidUpdate → useEffect(..., [deps])
componentWillUnmount → useEffect 返回的清理函数
（一个 useEffect 同时承担挂载、更新、卸载三种职责）
```

## 应用场景实战

### 场景一：页面访问埋点（挂载 + 卸载）

```jsx
function PageTracker({ pageId }) {
  useEffect(() => {
    track('enter', pageId);          // 进入页面
    return () => track('leave', pageId);  // 离开页面
  }, [pageId]);
  return <div>页面内容</div>;
}
```

### 场景二：监听窗口尺寸（订阅与清理）

```jsx
function useWindowSize() {
  const [size, setSize] = useState({ w: 0, h: 0 });

  useEffect(() => {
    const onResize = () => setSize({
      w: window.innerWidth,
      h: window.innerHeight,
    });
    onResize();
    window.addEventListener('resize', onResize);
    return () => window.removeEventListener('resize', onResize);
  }, []);

  return size;
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. 把 Render Phase 当作纯函数，副作用一律放进 Effect
2. 一个 Effect 只做一件事，相关逻辑可拆成多个 Effect
3. 清理函数与副作用成对出现（订阅/取消、连接/断开）
4. 优先 useEffect，仅测量布局时用 useLayoutEffect
5. 用依赖数组精确控制 Effect 的执行时机

### 踩坑记录

```text
坑 1：在组件体内写副作用
结论：副作用在渲染阶段执行，导致重复请求或状态污染。
原因：组件体在 Render Phase 会被反复执行（含被中断丢弃的）。
解法：副作用统一放入 useEffect 或事件处理器。

坑 2：忘记清理订阅导致内存泄漏
结论：反复挂载卸载后监听器/定时器越来越多。
原因：只订阅没取消，卸载时未清理。
解法：Effect 返回清理函数，成对管理资源。

坑 3：依赖数组写 [] 但内部用了 props
结论：props 变化时 Effect 仍用旧值，出现 bug。
原因：空依赖让 Effect 只在挂载执行一次，闭包锁死旧值。
解法：把用到的值写进依赖数组，或用函数式更新。

坑 4：用 useLayoutEffect 做重计算
结论：阻塞渲染，页面卡顿。
原因：useLayoutEffect 同步执行会推迟绘制。
解法：重计算移入 useEffect 或用 useMemo。

坑 5：误以为 setState 立即生效
结论：连续 setState 后读到旧值。
原因：状态更新是异步批量的，提交阶段才统一生效。
解法：需要基于前值更新时用函数式 setState。
```

## 概述

移动浏览器是移动端 Web 的运行环境，主流为 iOS 的 Mobile Safari 与 Android 的 Chrome Android。与桌面浏览器相比，移动浏览器在视口、安全区、触控事件上有显著差异，是移动端适配的基础。

```text
移动浏览器的独有特性：
1. Viewport —— 布局视口、视觉视口、理想视口之分
2. Safe Area —— 刘海屏/圆角屏的安全区域
3. Touch / Pointer —— 触控事件体系
4. 300ms 延迟 —— 历史点击延迟问题
5. 系统手势 —— 边缘滑动与浏览器手势冲突
```

```html
<!-- 移动端必备 viewport 声明 -->
<meta name="viewport" content="width=device-width, initial-scale=1" />
```

## Mobile Safari

Mobile Safari 是 iOS 的默认浏览器（WebKit 内核），具有独特的特性与限制，是移动端兼容性的重点对象。

```text
Mobile Safari 特性与限制：
1. 内核 —— WebKit（与桌面 Safari 一致）
2. 地址栏 —— 滚动时收缩/展开，影响视口高度
3. 橡皮筋滚动 —— 页面边界弹性滚动
4. 不支持 WebRTC 早期版本、部分 API 较慢
5. 点击 300ms 延迟（现代版本已消除）
6. PWA 支持受限（历史原因，现已改善）
```

```css
/* 关闭橡皮筋滚动（iOS） */
html, body {
  overscroll-behavior: none;
}

/* 关闭点击高亮 */
* {
  -webkit-tap-highlight-color: transparent;
}
```

```js
// 检测 iOS 环境
const isIOS = /iPhone|iPad|iPod/.test(navigator.userAgent);
const isSafari = /Safari/.test(navigator.userAgent) && !/Chrome/.test(navigator.userAgent);
```

## Chrome Android

Chrome Android 是 Android 的默认浏览器（Blink 内核），支持最新的 Web 标准，但在设备碎片化上有独特挑战。

```text
Chrome Android 特性：
1. 内核 —— Blink（与桌面 Chrome 一致）
2. 标准支持 —— 最新 Web API 跟进最快
3. 设备碎片化 —— 分辨率、屏幕尺寸差异巨大
4. 依赖 WebView 的应用内浏览器（混合 App）
5. 后台标签页激进冻结，影响定时器
```

```js
// 检测 Android / Chrome
const isAndroid = /Android/.test(navigator.userAgent);
const isChrome = /Chrome/.test(navigator.userAgent) && !/Edge|OPR/.test(navigator.userAgent);
```

```text
Android 碎片化影响：
1. 屏幕尺寸从 4 寸到 7 寸+，需响应式覆盖
2. 旧 WebView 内核过时，需兼容或提示升级
3. 后台页面定时器被冻结，长任务受影响
4. 字体渲染差异，需设置字体栈
```

## Viewport

Viewport 是移动端布局的核心概念，分为布局视口、视觉视口、理想视口三种，通过 meta viewport 控制。

```text
三种视口：
1. 布局视口（layout viewport）—— CSS 布局依据的宽度，默认约 980px
2. 视觉视口（visual viewport）—— 用户实际看到的区域
3. 理想视口（ideal viewport）—— 设备宽度，width=device-width 时启用
```

```html
<!-- 标准声明：布局视口 = 设备宽度，缩放 1 -->
<meta name="viewport" content="width=device-width, initial-scale=1" />

<!-- 禁止缩放（不推荐，影响无障碍） -->
<meta name="viewport" content="width=device-width, initial-scale=1, user-scalable=no" />
```

```js
// 读取视口尺寸
console.log(window.innerWidth);                 // 视觉视口宽度
console.log(document.documentElement.clientWidth);   // 布局视口宽度

// Visual Viewport API
window.visualViewport.addEventListener('resize', () => {
  console.log('视觉视口：', window.visualViewport.width, window.visualViewport.height);
});
```

```text
viewport 关键参数：
1. width —— 布局视口宽度（device-width 或具体值）
2. initial-scale —— 初始缩放
3. minimum-scale / maximum-scale —— 缩放范围
4. viewport-fit —— cover 时内容延伸到安全区
```

## Safe Area

Safe Area（安全区）是刘海屏、圆角屏、底部横条上可安全显示内容的区域。通过 viewport-fit=cover 与 env() 适配。

```html
<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover" />
```

```css
/* 使用 env() 适配安全区 */
.header {
  padding-top: env(safe-area-inset-top);      /* 顶部安全区 */
}
.footer {
  padding-bottom: env(safe-area-inset-bottom); /* 底部横条 */
}

/* 兼容旧写法（iOS 11.2 之前用 constant()） */
.header {
  padding-top: constant(safe-area-inset-top);
  padding-top: env(safe-area-inset-top);
}
```

```text
安全区四个方向：
1. safe-area-inset-top —— 顶部（刘海）
2. safe-area-inset-bottom —— 底部（Home 横条）
3. safe-area-inset-left / right —— 横屏两侧
```

```js
// JS 读取安全区
const insets = {
  top: parseFloat(getComputedStyle(document.documentElement).getPropertyValue('env(safe-area-inset-top)')),
  bottom: parseFloat(getComputedStyle(document.documentElement).getPropertyValue('env(safe-area-inset-bottom)')),
};
```

## Touch

Touch（触摸事件）是移动端的基础交互，包括 touchstart、touchmove、touchend、touchcancel，支持多点触控。

```text
Touch 事件：
1. touchstart —— 手指按下
2. touchmove —— 手指移动
3. touchend —— 手指抬起
4. touchcancel —— 触摸被系统打断（来电、手势接管）
```

```js
const el = document.querySelector('.box');

el.addEventListener('touchstart', (e) => {
  const touch = e.touches[0];      // 第一个触点
  console.log('按下：', touch.clientX, touch.clientY);
});

el.addEventListener('touchmove', (e) => {
  const touch = e.touches[0];
  // 阻止默认滚动（实现自定义拖拽时）
  e.preventDefault();
  el.style.transform = `translate(${touch.clientX}px, ${touch.clientY}px)`;
});

el.addEventListener('touchend', () => {
  console.log('抬起');
});
```

```text
Touch 对象关键属性：
1. touches —— 屏幕上所有触点
2. targetTouches —— 当前元素上的触点
3. changedTouches —— 本次变化的触点

多点触控：touches 长度 > 1 时处理手势（缩放/旋转）。
```

## Pointer

Pointer（指针事件）是 W3C 的统一输入模型，把鼠标、触摸、触控笔统一为 pointer 事件，推荐用于跨设备交互。

```text
Pointer 事件：
1. pointerdown / pointerup —— 按下/抬起
2. pointermove —— 移动
3. pointerenter / pointerleave —— 进入/离开
4. pointercancel —— 被系统打断

优势：一套代码兼容鼠标 + 触摸 + 笔。
```

```js
const el = document.querySelector('.box');

el.addEventListener('pointerdown', (e) => {
  el.setPointerCapture(e.pointerId);   // 捕获指针，防止移出元素后丢失
  console.log('指针类型：', e.pointerType);  // mouse/touch/pen
});

el.addEventListener('pointermove', (e) => {
  if (e.buttons > 0) {                 // 按下状态
    el.style.transform = `translate(${e.clientX}px, ${e.clientY}px)`;
  }
});

el.addEventListener('pointerup', (e) => {
  el.releasePointerCapture(e.pointerId);
});
```

```text
Pointer vs Touch 选择：
1. 优先 Pointer —— 一套代码兼容所有输入
2. 需要精细多点触控 → 用 Touch
3. Pointer 需注意 pointercancel（触摸被滚动接管时触发）
```

## 应用场景实战

### 场景一：移动端图片轮播（触摸滑动）

```js
const carousel = document.querySelector('.carousel');
let startX = 0, offset = 0;

carousel.addEventListener('touchstart', (e) => {
  startX = e.touches[0].clientX;
});

carousel.addEventListener('touchmove', (e) => {
  const dx = e.touches[0].clientX - startX;
  carousel.style.transform = `translateX(${offset + dx}px)`;
});

carousel.addEventListener('touchend', (e) => {
  const dx = e.changedTouches[0].clientX - startX;
  offset += dx > 50 ? 300 : dx < -50 ? -300 : 0;   // 阈值判定翻页
  carousel.style.transform = `translateX(${offset}px)`;
});
```

### 场景二：安全区适配的底部导航

```css
.bottom-nav {
  position: fixed;
  bottom: 0;
  left: 0;
  right: 0;
  height: 56px;
  /* 底部安全区：iPhone 横条上方留白 */
  padding-bottom: env(safe-area-inset-bottom);
  box-sizing: content-box;
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. 页面首行声明 viewport meta，缺一不可
2. 优先用 Pointer 事件，统一鼠标与触摸
3. 触摸目标不小于 44x44px（iOS 建议）
4. 安全区用 env(safe-area-inset-*) 适配
5. 用 visualViewport 处理地址栏收缩，而非 100vh
6. 移除 -webkit-tap-highlight 的默认高亮

### 踩坑记录

```text
坑 1：100vh 比可见区域高
结论：底部内容被地址栏/横条遮挡。
原因：100vh 是布局视口高度，包含地址栏区域。
解法：用 100dvh，或 JS 读取 visualViewport 高度。

坑 2：点击 300ms 延迟
结论：点击响应明显迟缓。
原因：旧移动浏览器双击缩放导致 300ms 等待。
解法：viewport 加 width=device-width，或用 pointer 事件。

坑 3：touchmove 中 preventDefault 失效
结论：滚动无法阻止，或报错。
原因：addEventListener 未设 passive: false。
解法：el.addEventListener('touchmove', fn, { passive: false })。

坑 4：position: fixed 在聚焦时跳动
结论：输入框聚焦时固定定位元素错位。
原因：软键盘弹出改变视觉视口。
解法：改用 absolute 或监听 visualViewport 调整。

坑 5：pointercancel 未处理导致拖拽卡死
结论：拖拽中元素卡住不动。
原因：触摸被浏览器滚动接管触发 pointercancel。
解法：监听 pointercancel 重置状态。
```

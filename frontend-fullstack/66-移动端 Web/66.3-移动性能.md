## 概述

移动端性能受限于硬件与网络：CPU 弱、内存小、网络慢且不稳定、电量有限。优化需覆盖首屏加载、包体积、网络传输、内存占用、电量消耗、滚动流畅度六个方面。

```text
移动端性能瓶颈：
1. First Load —— 首屏加载慢，用户流失
2. Bundle —— JS 包过大，解析执行耗时
3. Network —— 弱网/高延迟，传输受限
4. Memory —— 内存小，易 OOM 崩溃
5. Battery —— 持续计算/请求耗电
6. Scroll —— 滚动卡顿，体验差
```

## First Load

First Load（首屏加载）是用户感知性能的关键。移动端弱网下首屏速度直接决定留存，需围绕「尽快渲染首屏内容」优化。

```text
首屏加载关键指标：
1. FCP —— 首次内容绘制
2. LCP —— 最大内容绘制（核心内容可见，< 2.5s）
3. TTI —— 可交互时间
4. INP —— 交互响应（< 200ms）
```

```html
<!-- 首屏关键资源预加载 -->
<link rel="preload" href="/critical.css" as="style" />
<link rel="preload" href="/hero-image.webp" as="image" />

<!-- 预连接第三方域名 -->
<link rel="preconnect" href="https://api.example.com" />
<link rel="dns-prefetch" href="https://cdn.example.com" />

<!-- 首屏 CSS 内联，避免阻塞 -->
<style>/* 关键 CSS */</style>
```

```text
首屏优化策略：
1. 关键 CSS 内联，非关键 CSS 延迟加载
2. 首屏图片优先加载，其余懒加载
3. 路由/组件级代码分割，首屏只加载必要代码
4. SSR/预渲染减少白屏时间
5. 预连接关键第三方域名
```

## Bundle

Bundle（包体积）直接影响下载与解析时间。移动端设备解析 JS 慢，包越大，白屏与卡顿越明显。

```text
包体积优化手段：
1. 代码分割 —— 按路由/组件拆包
2. Tree Shaking —— 移除未使用代码
3. 压缩 —— 构建时 minify + gzip/brotli
4. 按需引入 —— 库只引用的部分
5. 依赖精简 —— 替换重依赖
```

```js
// 路由级代码分割（React Router）
import { lazy, Suspense } from 'react';
const HeavyPage = lazy(() => import('./HeavyPage'));

// 按需引入（lodash-es 的具名导入，tree-shakeable）
import { debounce } from 'lodash-es';

// 动态导入：功能用到时才加载
button.addEventListener('click', async () => {
  const { default: download } = await import('./download');
  download();
});
```

```text
体积检查工具：
1. webpack-bundle-analyzer / rollup-plugin-visualizer
2. 关注重复依赖、过大第三方库
3. 目标：移动端首屏 JS 控制在 200KB（gzip）内
```

## Network

Network（网络）在移动端表现为弱网、高延迟、带宽波动。优化核心是「减少请求、减少传输、增强容错」。

```text
网络优化策略：
1. 减少请求数 —— 合并/缓存/HTTP2 多路复用
2. 减小传输量 —— 压缩、图片优化、按需加载
3. 缓存 —— 强缓存 + Service Worker 离线
4. 容错 —— 弱网降级、请求重试、超时处理
```

```js
// 弱网感知与降级
const connection = navigator.connection;
if (connection) {
  const { effectiveType, saveData } = connection;
  if (effectiveType === 'slow-2g' || saveData) {
    enableLowQualityMode();   // 降级：跳过高清图、关闭预取
  }
}
```

```text
图片网络优化：
1. 用 WebP/AVIF 格式
2. 响应式 srcset，按 DPR/尺寸加载
3. 懒加载（loading="lazy"）
4. 弱网降级为占位图/低清图
```

## Memory

Memory（内存）移动端容量小且回收激进，内存泄漏或峰值过高会导致页面崩溃或被杀。需控制峰值、及时释放、避免泄漏。

```text
内存优化要点：
1. 控制内存峰值 —— 避免一次性加载大数据
2. 及时释放 —— 事件监听、定时器、引用清理
3. 虚拟滚动 —— 长列表只渲染可见项
4. 图片内存 —— 大图压缩、及时回收
```

```js
// 及时释放：清理事件与定时器
useEffect(() => {
  const timer = setInterval(tick, 1000);
  window.addEventListener('scroll', onScroll);
  return () => {
    clearInterval(timer);
    window.removeEventListener('scroll', onScroll);
  };
}, []);
```

```js
// 虚拟滚动：只渲染可见项（简化示意）
const itemHeight = 50, viewHeight = 600;
const [scrollTop, setScrollTop] = useState(0);

const start = Math.floor(scrollTop / itemHeight);
const count = Math.ceil(viewHeight / itemHeight) + 2;
const visible = items.slice(start, start + count);
const offsetY = start * itemHeight;
```

```text
内存泄漏常见来源：
1. 未清理的事件监听与定时器
2. 闭包持有大对象引用
3. 全局变量堆积
4. 未释放的 Blob/URL 对象
```

## Battery

Battery（电量）移动端设备电量有限，持续的计算、网络请求、动画、传感器都会加速耗电。

```text
省电优化策略：
1. 减少不必要的网络轮询（用推送替代）
2. 后台标签页停止动画与定时器
3. 动画用 CSS 合成（GPU 而非 CPU）
4. 传感器（定位等）按需开启、及时关闭
5. 尊重省电模式（saveData / Battery API）
```

```js
// 页面可见性检测：后台暂停动画
document.addEventListener('visibilitychange', () => {
  if (document.hidden) {
    cancelAnimationFrame(rafId);     // 停止动画
    stopPolling();                   // 停止轮询
  } else {
    rafId = requestAnimationFrame(loop);
  }
});
```

```text
耗电大户：
1. 高频定时器（setInterval 轮询）
2. 持续动画（rAF 无限循环）
3. GPS 定位持续开启
4. 大量 JS 计算（主线程忙碌）
```

## Scroll Performance

Scroll Performance（滚动性能）移动端用户最敏感，滚动卡顿直接影响体验。核心是让滚动期间避免阻塞主线程的重活。

```text
滚动卡顿原因：
1. scroll 事件里做重计算/DOM 操作
2. 未用 passive 监听，阻塞滚动
3. 滚动触发布局（回流）
```

```js
// 用 rAF 节流 scroll 事件（配合 passive）
let ticking = false;
window.addEventListener('scroll', () => {
  if (!ticking) {
    requestAnimationFrame(() => {
      updatePosition();
      ticking = false;
    });
    ticking = true;
  }
}, { passive: true });
```

```js
// 用 IntersectionObserver 替代 scroll 监听
const observer = new IntersectionObserver((entries) => {
  entries.forEach((entry) => {
    if (entry.isIntersecting) {
      loadImage(entry.target);
      observer.unobserve(entry.target);
    }
  });
});
document.querySelectorAll('img[data-src]').forEach((img) => observer.observe(img));
```

## 应用场景实战

### 场景一：弱网自动降级图片

```js
function smartImage(img) {
  const connection = navigator.connection;
  const isWeak = connection && (connection.effectiveType === '2g' || connection.effectiveType === 'slow-2g');

  if (isWeak || connection?.saveData) {
    img.src = img.dataset.low;      // 弱网加载低清图
  } else {
    img.src = img.dataset.high;
  }
}
```

### 场景二：长列表虚拟滚动（简化）

```js
function VirtualList({ items, itemHeight = 50, viewHeight = 600 }) {
  const [scrollTop, setScrollTop] = useState(0);

  const onScroll = (e) => setScrollTop(e.target.scrollTop);
  const start = Math.floor(scrollTop / itemHeight);
  const count = Math.ceil(viewHeight / itemHeight) + 2;
  const visible = items.slice(start, start + count);

  return (
    <div style={{ height: viewHeight, overflow: 'auto' }} onScroll={onScroll}>
      <div style={{ height: items.length * itemHeight, position: 'relative' }}>
        {visible.map((item, i) => (
          <div key={start + i} style={{ position: 'absolute', top: (start + i) * itemHeight, height: itemHeight }}>
            {item.text}
          </div>
        ))}
      </div>
    </div>
  );
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. 首屏资源优先，非关键资源延迟加载
2. 路由级代码分割，首屏 JS 控制在 200KB（gzip）内
3. 图片用 WebP/AVIF + srcset + 懒加载
4. 长列表用虚拟滚动，控制内存与 DOM 数量
5. 页面隐藏时停止动画、轮询、定时器
6. scroll 监听用 passive + rAF 节流

### 踩坑记录

```text
坑 1：scroll 事件未加 passive 导致卡顿
结论：滚动明显卡顿。
原因：scroll 监听默认非 passive，浏览器需等回调判断是否 preventDefault。
解法：加 { passive: true }，不在 scroll 里 preventDefault。

坑 2：scroll 回调里做重活
结论：滚动掉帧、页面抖动。
原因：高频 scroll 事件触发大量 DOM 操作。
解法：rAF 节流 + 用 IntersectionObserver 替代。

坑 3：内存泄漏导致移动端崩溃
结论：长时间使用后页面卡死或闪退。
原因：监听器/定时器未清理，堆持续上涨。
解法：组件卸载清理副作用，定期监控内存。

坑 4：后台标签页持续耗电
结论：切后台后电量快速下降。
原因：动画/轮询未在 hidden 时暂停。
解法：visibilitychange 时停止动画与定时器。

坑 5：首屏包过大白屏久
结论：移动端打开页面白屏数秒。
原因：JS 包过大，下载+解析+执行都慢。
解法：代码分割 + 关键资源内联 + 减少第三方库。
```

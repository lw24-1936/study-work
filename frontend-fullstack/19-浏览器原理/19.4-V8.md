## 概述

V8 是 Google 开源的 JavaScript 引擎，用于 Chrome 和 Node.js。它的核心是「分代垃圾回收 + JIT 编译」，用 Ignition（解释器）和 TurboFan（优化编译器）实现高性能。

```text
V8 的核心组成：
1. 内存 —— Heap（堆）+ Stack（栈）
2. GC —— 分代垃圾回收（新生代 Scavenge + 老生代 Mark-Sweep）
3. 编译 —— Ignition（解释器）+ TurboFan（优化编译器）
4. 优化 —— 隐藏类 + 内联缓存
```

## Heap 与 Stack 内存模型

V8 的内存分栈和堆：栈存基本类型和引用，堆存对象。

```text
Stack（栈）：
1. 存基本类型（原始值）和对象引用
2. 后进先出，自动管理
3. 函数调用入栈，返回出栈

Heap（堆）：
1. 存对象、数组、函数
2. 由垃圾回收管理
3. 分新生代/老生代
```

```js
// 基本类型在栈，对象在堆
let num = 42;              // 栈（原始值）
let obj = { a: 1 };        // 堆（对象），栈存引用
let arr = [1, 2, 3];       // 堆
```

## New Space 与 Old Space

堆空间划分为新生代（New Space）和老生代（Old Space）。

```text
New Space（新生代，Young Generation）：
1. 存放「新创建」的对象
2. 空间小（约 1-8MB）
3. 回收频繁（Scavenge 算法）
4. 存活对象晋升到老生代

Old Space（老生代，Old Generation）：
1. 存放「存活久」的对象
2. 空间大
3. 回收不频繁（Mark-Sweep/Compact）
```

## Young / Old Generation 分代

分代回收基于「对象存活时间」的假设：大部分对象很快死亡，少数存活久。

```text
分代假设：
1. 大多数对象「朝生暮死」—— 创建后很快不再使用
2. 少数对象存活久 —— 长期使用

策略：
新生代 —— 频繁回收（代价小）
老生代 —— 低频回收（代价大）
```

```js
// 新生代对象：临时变量、短期对象
function temp() {
  const obj = { x: 1 };   // 临时对象，很快回收
  return obj.x;
}

// 老生代对象：全局变量、长期缓存
const globalCache = { data: [] };   // 长期存活
```

## GC 垃圾回收

GC 自动回收不再使用的内存，V8 采用分代回收策略。

```text
GC 的触发与过程：
1. 内存分配触发 GC
2. 标记可达对象（从根开始）
3. 回收不可达对象
4. 可能触发停顿（Stop-The-World）

关键概念：可达性 —— 从根（全局、栈）能访问到的对象存活。
```

```text
GC 的代价：
1. 暂停 —— 回收时主线程停顿（Stop-The-World）
2. 优化 —— 增量、并发回收减少停顿
```

## Mark-Sweep / Mark-Compact / Scavenge

三种回收算法分别用于老生代和新生代。

```text
Scavenge（新生代）：
1. 半空间复制 —— From 空间复制存活对象到 To 空间
2. 只回收存活对象，快
3. 牺牲空间换时间

Mark-Sweep（标记清除，老生代）：
1. 标记 —— 从根标记可达对象
2. 清除 —— 回收未标记对象
3. 产生内存碎片

Mark-Compact（标记整理，老生代）：
1. 标记 + 整理 —— 回收后移动对象，消除碎片
2. 解决内存碎片问题
```

```text
三种算法的选择：
新生代 —— Scavenge（对象少、回收快）
老生代 —— Mark-Sweep（常规）+ Mark-Compact（碎片多时）
```

## Hidden Class 与 Inline Cache

隐藏类（Hidden Class）优化属性访问，内联缓存（Inline Cache）缓存属性查找结果。

```text
Hidden Class（隐藏类）：
1. 相同结构的对象共享同一个隐藏类
2. 属性访问通过隐藏类快速定位
3. 动态增删属性会创建新的隐藏类（影响性能）

Inline Cache（内联缓存）：
1. 缓存「属性在对象中的位置」
2. 相同隐藏类的对象复用缓存
3. 结构变化导致缓存失效
```

```js
// 正例：相同结构，共享隐藏类
const a = { x: 1, y: 2 };
const b = { x: 3, y: 4 };   // 与 a 结构相同，共享隐藏类

// 反例：动态属性，破坏隐藏类
const c = {};
c.x = 1;
c.y = 2;                    // 逐步添加，隐藏类多次变化
```

```js
// 顺序不同，隐藏类不同
const d = { x: 1, y: 2 };
const e = { y: 2, x: 1 };   // 属性顺序不同，隐藏类不同！
```

```text
优化启示：
1. 构造函数中一次性初始化所有属性
2. 保持属性顺序一致
3. 避免动态增删属性
```

## Ignition 与 TurboFan

Ignition 是解释器（执行字节码），TurboFan 是优化编译器（生成机器码）。

```text
Ignition（解释器）：
1. 快速生成字节码并执行
2. 启动快，适合「冷代码」
3. 收集类型反馈

TurboFan（优化编译器）：
1. 编译热点代码为机器码
2. 基于类型反馈深度优化
3. 假设失效时反优化

协作流程：Ignition 执行 → 热点检测 → TurboFan 优化 → 反优化回退。
```

```text
Ignition + TurboFan 的价值：
1. 启动快 —— Ignition 快速执行
2. 峰值快 —— TurboFan 优化热点
3. 内存省 —— 字节码比机器码小
```

## 应用场景实战

### 场景一：避免内存泄漏

```js
// 反例：全局缓存无限增长
const cache = [];
function addToCache(data) {
  cache.push(data);   // 永不清理，内存泄漏
}

// 正例：限制缓存大小
const cache2 = new Map();
function addLimited(key, data) {
  if (cache2.size > 100) {
    const firstKey = cache2.keys().next().value;
    cache2.delete(firstKey);
  }
  cache2.set(key, data);
}
```

### 场景二：优化属性访问

```js
// 正例：构造函数统一初始化
class Point {
  constructor(x, y) {
    this.x = x;
    this.y = y;   // 一次性初始化，隐藏类稳定
  }
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. 对象属性在构造函数中一次性初始化（稳定隐藏类）
2. 保持对象结构一致（属性顺序、类型）
3. 避免动态增删属性
4. 全局缓存要有上限，防内存泄漏
5. 大对象/频繁分配注意 GC 停顿

### 踩坑记录

```text
坑 1：动态增删属性破坏隐藏类
结论：属性访问变慢。
原因：隐藏类频繁变化，内联缓存失效。
解法：构造时初始化，用赋值替代 delete。

坑 2：全局变量内存泄漏
结论：全局缓存/数组无限增长，内存暴涨。
原因：全局对象常驻，GC 不回收。
解法：缓存设上限，及时清理。

坑 3：事件监听器未移除导致泄漏
结论：移除 DOM 后内存不释放。
原因：事件监听器仍引用 DOM 元素。
解法：移除元素时同步移除监听器。

坑 4：闭包持有大对象
结论：闭包引用大对象，内存不释放。
原因：闭包保留词法环境，引用的对象无法回收。
解法：不需要时置空引用。

坑 5：频繁创建对象导致 GC 停顿
结论：大量临时对象导致频繁 GC，卡顿。
原因：新生代频繁回收，触发停顿。
解法：对象复用（对象池）、减少临时对象。
```

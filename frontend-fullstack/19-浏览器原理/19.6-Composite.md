## 概述

Composite（合成）是渲染流水线的最后阶段：把各图层合成为最终画面。合成在**合成线程**上执行，独立于主线程，是性能最优的阶段。

```text
渲染流水线的最后环节：
Layout → Paint → Raster（光栅化）→ Composite（合成）

合成阶段的优势：
1. 在合成线程执行（非主线程）
2. GPU 加速
3. transform/opacity 只触发合成（最优）
```

## Layer 图层

浏览器把页面分成多个图层，每个图层独立光栅化，最后合成。

```text
图层（Layer）的生成条件：
1. 有 3D transform 或 perspective
2. 有 transform 动画
3. 有 will-change 属性
4. video、canvas、iframe 等
5. position: fixed
```

```js
// 提升为独立图层的属性
element.style.transform = 'translateZ(0)';   // 强制提升图层
element.style.willChange = 'transform';      // 提示浏览器将变化
```

```text
图层的价值：
1. 独立渲染 —— 图层变化不影响其他图层
2. GPU 加速 —— 合成在 GPU 执行
3. 高效动画 —— transform 动画只合成，不回流
```

## Compositing 合成

合成是把多个图层按顺序合成为最终画面。

```text
合成过程：
1. 各图层光栅化为位图
2. 合成线程按 z 顺序组合图层
3. 输出最终帧到屏幕

关键：合成在合成线程，不阻塞主线程。
```

```js
// 只触发合成的属性（最优）
element.style.transform = 'translateX(10px)';
element.style.opacity = '0.5';
// 这些变化只在合成线程处理，主线程无负担
```

```text
合成的优势场景：
1. 滚动 —— 合成线程处理，流畅
2. transform/opacity 动画 —— 不触发主线程
3. 大量图层 —— 并行处理
```

## GPU Rasterization GPU 光栅化

光栅化把绘制指令转为位图，GPU 光栅化利用 GPU 并行加速。

```text
光栅化（Rasterization）：
1. 把矢量绘制指令转为像素位图
2. GPU 光栅化 —— 利用 GPU 并行处理，快
3. 各图层独立光栅化

GPU 加速的意义：并行处理大量像素。
```

## Transform Layer 变换图层

有 transform 的元素会提升为变换图层，其 transform 变化只触发合成。

```js
// transform 动画：只在合成线程执行
element.animate(
  [{ transform: 'translateX(0)' }, { transform: 'translateX(100px)' }],
  { duration: 300 },
);
```

```text
transform 只触发合成的原因：
1. transform 不改变布局（几何位置视觉上变，但布局不变）
2. 图层独立，变换在合成线程完成
3. 无需主线程重新布局/绘制
```

## Paint Layer 绘制图层

Paint Layer 是绘制阶段的图层概念，与合成图层（Graphics Layer）不同。

```text
Paint Layer vs Graphics Layer：
Paint Layer —— 绘制阶段的图层（渲染树节点分组）
Graphics Layer —— 合成阶段的图层（真正独立渲染）

触发合成的元素才成为 Graphics Layer，提升到 GPU。
```

```text
图层层级关系：
1. 渲染树节点 → Paint Layer（绘制分组）
2. 满足条件 → Graphics Layer（合成图层）
3. Graphics Layer 才能独立光栅化、GPU 加速
```

## 应用场景实战

### 场景一：流畅的位移动画

```js
// 反例：改 left 触发回流
element.style.left = '100px';

// 正例：transform 只触发合成
element.style.transform = 'translateX(100px)';
```

### 场景二：提前提示图层提升

```css
/* will-change 提示浏览器该元素将变化，提前提升图层 */
.animated {
  will-change: transform;
}
```

```js
// 动态设置 will-change（动画开始前）
element.style.willChange = 'transform';
// 动画结束后移除
element.addEventListener('transitionend', () => {
  element.style.willChange = 'auto';
});
```

## 最佳实践与踩坑记录

### 最佳实践

1. 动画只用 transform/opacity（只触发合成）
2. will-change 适度使用，动画结束移除
3. 避免图层过多（内存占用）
4. 滚动性能依赖合成，避免主线程阻塞
5. 理解 transform 不触发回流的原理

### 踩坑记录

```text
坑 1：误以为所有属性都能 GPU 加速
结论：改 width 也以为走合成，实际触发布局。
原因：只有 transform/opacity 等只触发合成。
解法：动画只改 transform/opacity。

坑 2：滥用 will-change
结论：大量元素设 will-change，内存暴涨。
原因：每个 will-change 都可能提升图层，占用内存。
解法：只在动画元素上使用，动画结束移除。

坑 3：图层过多
结论：页面图层爆炸，内存和合成开销大。
原因：过多元素触发图层提升。
解法：控制图层数量，避免无谓的 transform: translateZ(0)。

坑 4：transform 动画里读布局
结论：transform 动画中读 offsetWidth，又强制同步布局。
原因：读布局属性破坏合成的独立性。
解法：动画期间避免读布局属性。

坑 5：误解 transform 不改变布局
结论：以为 transform 会触发回流。
原因：transform 是视觉变换，不改变文档布局。
解法：理解 transform 只影响渲染，不影响布局。
```

## 概述

Layout（布局）是渲染流水线中计算元素几何信息的阶段。频繁触发布局（回流）和重绘是前端性能问题的常见来源。

```text
三个易混淆概念：
Layout（布局）—— 计算元素位置尺寸
Reflow（回流）—— 布局失效后重新计算（重排）
Repaint（重绘）—— 视觉变化后重新绘制（不改变布局）

代价：Reflow > Repaint > 仅合成（transform/opacity）
```

## Layout 布局

Layout 计算每个可见元素的几何信息（位置、大小），输出布局树。

```text
Layout 阶段：
1. 遍历渲染树
2. 计算每个元素的位置、尺寸
3. 考虑盒模型、浮动、定位
4. 输出布局树（Layout Tree）

首次渲染执行完整 Layout。
```

```js
// 读取布局信息（可能触发 Layout）
element.offsetWidth;
element.offsetHeight;
element.getBoundingClientRect();
```

## Reflow 回流

回流是「布局重新计算」：元素的几何属性变化，导致重新布局。

```text
触发回流的操作：
1. 修改尺寸 —— width、height、padding、margin、border
2. 增删元素 —— 添加/删除 DOM
3. 修改位置 —— top、left、position
4. 修改字体 —— font-size、font-family
5. 读取布局 —— offsetWidth、clientWidth 等（配合写操作时）
```

```js
// 触发回流的属性
element.style.width = '100px';     // 尺寸变化 → 回流
element.style.margin = '10px';     // 边距变化 → 回流
element.style.top = '20px';        // 位置变化 → 回流
document.body.appendChild(el);     // 增删元素 → 回流
```

```text
回流的代价：
1. 可能级联 —— 一个元素变化影响周围元素
2. 代价高 —— 重新计算布局树
3. 频繁回流 → 页面卡顿
```

## Repaint 重绘

重绘是「重新绘制视觉」，不改变布局，只改变外观。

```text
触发重绘（不回流）的属性：
1. 颜色 —— color、background-color
2. 阴影 —— box-shadow
3. 轮廓 —— outline
4. 可见性 —— visibility（不改变布局）

重绘代价低于回流，但仍需重新绘制。
```

```js
// 只触发重绘（不回流）
element.style.color = 'red';
element.style.backgroundColor = 'blue';
element.style.boxShadow = '0 2px 4px rgba(0,0,0,0.2)';
```

```text
回流 vs 重绘：
回流 —— 几何变化，重新布局（通常也伴随重绘）
重绘 —— 仅外观变化，重新绘制

回流必然触发重绘，重绘不一定回流。
```

## Forced Synchronous Layout 强制同步布局

强制同步布局：**读取布局属性**时，若有**待处理的写操作**，浏览器强制先同步布局，导致性能损耗。

```js
// 强制同步布局（反例）
function resize() {
  elements.forEach(el => {
    el.style.width = `${container.offsetWidth}px`;   // 读 offsetWidth 强制布局
    // 每次循环都强制同步布局，代价高
  });
}
```

```text
强制同步布局的产生：
1. 写操作（改样式）→ 标记布局失效
2. 读操作（读布局属性）→ 若布局已失效，强制先布局
3. 交替读写 → 反复强制布局
```

## Layout Thrashing 布局抖动

布局抖动（Layout Thrashing）：循环中**交替读写**布局，导致多次强制同步布局，性能急剧下降。

```js
// 布局抖动（反例）：循环内交替读写
for (let i = 0; i < items.length; i++) {
  const height = items[i].offsetHeight;   // 读（强制布局）
  items[i].style.height = height + 'px';  // 写（布局失效）
  // 下轮循环读又强制布局 → 抖动
}
```

```js
// 优化：批量读、批量写（分离读写）
const heights = items.map(item => item.offsetHeight);   // 批量读
items.forEach((item, i) => {
  item.style.height = heights[i] + 'px';                 // 批量写
});
```

```text
布局抖动的解决：
1. 分离读写 —— 先读完所有，再统一写
2. 缓存布局值 —— 读一次存变量，避免重复读
3. 用 class 批量改 —— 一次改多个样式
```

## 应用场景实战

### 场景一：优化布局抖动

```js
// 反例：读写交替
function badUpdate(items) {
  items.forEach(item => {
    const w = item.offsetWidth;
    item.style.width = `${w + 10}px`;
  });
}

// 正例：分离读写
function goodUpdate(items) {
  const widths = items.map(item => item.offsetWidth);
  items.forEach((item, i) => {
    item.style.width = `${widths[i] + 10}px`;
  });
}
```

### 场景二：用 transform 代替 top/left

```js
// 反例：改 top/left 触发回流
element.style.left = `${x}px`;

// 正例：transform 只触发合成
element.style.transform = `translateX(${x}px)`;
```

## 最佳实践与踩坑记录

### 最佳实践

1. 动画用 transform/opacity（避免回流）
2. 批量读写分离，避免布局抖动
3. 缓存布局值，减少重复读取
4. 用 class 批量修改样式，避免逐个改 style
5. 减少触发回流的属性操作

### 踩坑记录

```text
坑 1：动画用 top/left
结论：动画卡顿、掉帧。
原因：top/left 触发回流，代价高。
解法：动画用 transform。

坑 2：循环里读写布局
结论：布局抖动，性能急剧下降。
原因：交替读写触发强制同步布局。
解法：批量读、批量写分离。

坑 3：误以为颜色变化触发回流
结论：改 color 以为会重排。
原因：颜色只触发重绘，不回流。
解法：理解回流（几何）与重绘（外观）区别。

坑 4：频繁读取 offsetWidth
结论：循环里反复读 offsetWidth，性能差。
原因：读布局属性可能触发强制布局。
解法：读一次缓存，或用 ResizeObserver。

坑 5：visibility:hidden 与 display:none 混淆
结论：误以为 visibility 不占位（实际占位）。
原因：visibility:hidden 占位（在布局中），display:none 不占位。
解法：理解二者布局差异。
```

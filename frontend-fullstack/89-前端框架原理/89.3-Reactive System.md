## 概述

Reactive System（响应式系统）让「状态变了，依赖它的地方自动更新」。它由三大核心机制组成：Effect 记录「谁依赖谁」，Dependency Tracking 在读取时收集依赖关系，Trigger 在写入时通知依赖方重新执行。再配合 Scheduler 和 Batch Update，把多次变更合并成一次高效更新，这是 Vue、MobX 等框架的底层引擎。

```text
响应式系统的运行机制：
1. Effect —— 定义副作用（如更新视图），是响应式的执行单元
2. Dependency Tracking —— 读取响应式数据时，记录「哪个 effect 用了它」
3. Trigger —— 写入数据时，通知所有依赖它的 effect 重新执行
4. Scheduler —— 控制 effect 何时执行、按什么优先级执行
5. Batch Update —— 把同一轮的多次变更合并成一次更新
```

## Dependency Tracking

Dependency Tracking（依赖收集）在读取响应式数据的瞬间，记录「当前正在运行的 effect 依赖了这个数据」。这样当数据变化时，系统才知道该通知谁，实现精确更新而不是全量刷新。

```js
// 依赖收集的核心：全局记录当前 effect，读取时建立依赖关系
let activeEffect = null;
const targetMap = new WeakMap(); // target -> key -> Set<effect>

function track(target, key) {
  if (!activeEffect) return; // 没有正在运行的 effect，不收集
  let depsMap = targetMap.get(target);
  if (!depsMap) targetMap.set(target, (depsMap = new Map()));
  let deps = depsMap.get(key);
  if (!deps) depsMap.set(key, (deps = new Set()));
  deps.add(activeEffect);
}
```

```text
Dependency Tracking 的要点：
1. 时机 —— 在 getter 里收集，读取即记录
2. 全局指针 —— activeEffect 记录当前正在执行的 effect
3. 粒度 —— 精确到 target.key，而非整个对象
4. 清理 —— effect 重跑前清空旧依赖，避免过期依赖
5. 结构 —— WeakMap(target) → Map(key) → Set(effect)
```

## Effect

Effect（副作用函数）是响应式的执行单元，它包装一段会读取响应式数据的函数。执行时被置为 activeEffect，读取的数据会自动收集它；数据变化时它会被重新触发，实现自动更新。

```js
// Effect 的实现
function effect(fn) {
  const effectFn = () => {
    cleanup(effectFn);      // 先清理旧依赖
    activeEffect = effectFn; // 设为当前 effect
    fn();                    // 执行，读取时触发 track
    activeEffect = null;
  };
  effectFn.deps = [];
  effectFn();
  return effectFn;
}

function cleanup(effectFn) {
  effectFn.deps.forEach(dep => dep.delete(effectFn));
  effectFn.deps.length = 0;
}

// 使用
const state = reactive({ count: 0 });
effect(() => {
  console.log('count =', state.count); // 首次执行打印，之后自动更新
});
```

```text
Effect 的要点：
1. 包装副作用 —— 把「读数据 + 做事情」包成可重跑的函数
2. 自动收集 —— 执行期间读取的响应式数据被自动记录
3. 自动重跑 —— 依赖数据变化时被重新执行
4. 清理机制 —— 重跑前清掉旧依赖，防止内存泄漏和误触发
```

## Trigger

Trigger（触发）在写入响应式数据时执行：找到所有依赖该数据的 effect，通知它们重新运行。它和 Dependency Tracking 是一对——track 收集、trigger 通知，构成完整的响应式闭环。

```js
// trigger：写入时通知依赖方
function trigger(target, key) {
  const depsMap = targetMap.get(target);
  if (!depsMap) return;
  const deps = depsMap.get(key);
  if (!deps) return;
  // 用副本遍历，避免 effect 执行时增删依赖导致死循环
  const effects = [...deps];
  effects.forEach(effectFn => {
    if (effectFn !== activeEffect) {
      effectFn.scheduler ? effectFn.scheduler() : effectFn();
    }
  });
}
```

```text
Trigger 的要点：
1. 时机 —— 在 setter 里触发，写入即通知
2. 找依赖 —— 从 targetMap 里查 target.key 对应的 effect 集合
3. 副本遍历 —— 复制后遍历，防止执行中修改集合
4. 递归触发 —— 嵌套对象赋值要递归 trigger 父级 key
5. 调度分支 —— 有 scheduler 走调度，否则直接执行
```

## Scheduler

Scheduler（调度器）控制 effect 的执行时机和顺序，是响应式系统从「立即执行」到「可控执行」的关键。它让框架能在合适的时候（如下一帧、微任务队列）统一执行更新，支持优先级和去重。

```js
// 带 scheduler 的 effect：数据变化时不立即执行，而是交给调度器
function effect(fn, options = {}) {
  const effectFn = () => {
    cleanup(effectFn);
    activeEffect = effectFn;
    fn();
    activeEffect = null;
  };
  effectFn.scheduler = options.scheduler;
  effectFn();
  return effectFn;
}

// 使用：把更新放进微任务队列，去重后统一执行
const jobQueue = new Set();
let flushing = false;
function queueJob(job) {
  jobQueue.add(job);
  if (flushing) return;
  flushing = true;
  Promise.resolve().then(() => {
    jobQueue.forEach(job => job());
    jobQueue.clear();
    flushing = false;
  });
}

effect(() => {
  console.log(state.count);
}, {
  scheduler: (job) => queueJob(job), // 不立即跑，交给队列去重调度
});
```

```text
Scheduler 的要点：
1. 解耦 —— 把「依赖变了」和「何时执行」分开
2. 去重 —— 同一 effect 多次触发合并成一次
3. 异步 —— 放进微任务队列，统一在下一轮执行
4. 优先级 —— 可按任务优先级排序执行
5. 应用 —— Vue 的 nextTick、React 的调度都基于此
```

## Batch Update

Batch Update（批量更新）把同一轮事件循环中的多次状态变更合并成一次更新，避免「改一次数据就渲染一次」的性能浪费。它通常借助微任务队列实现：先收集变更，再在微任务里统一执行。

```js
// 批量更新：多次修改只触发一次渲染
let dirty = false;
let pending = null;

function batchUpdate(fn) {
  dirty = true;
  fn();                      // 执行修改，但不立即渲染
  if (!pending) {
    pending = Promise.resolve().then(() => {
      render();              // 微任务里统一渲染一次
      pending = null;
      dirty = false;
    });
  }
}

// 连续改三次，只渲染一次
batchUpdate(() => {
  state.count = 1;
  state.count = 2;
  state.count = 3;
});
console.log('渲染次数：1');
```

```text
Batch Update 的要点：
1. 合并变更 —— 同一轮的多写合并成一次更新
2. 微任务 —— 借助微任务队列在「本轮结束后」统一执行
3. 去重 —— 同一 effect 只排一次队
4. 用户感知 —— 避免中间状态闪烁，保证一致性
5. 应用 —— Vue 的 nextTick、React 的批处理
```

## 应用场景实战

### 场景一：手写一个迷你响应式系统

```js
// 完整迷你响应式：reactive + effect + 依赖收集
let activeEffect = null;
const targetMap = new WeakMap();

function reactive(obj) {
  return new Proxy(obj, {
    get(target, key) {
      track(target, key);
      return target[key];
    },
    set(target, key, value) {
      target[key] = value;
      trigger(target, key);
      return true;
    },
  });
}

function track(target, key) {
  if (!activeEffect) return;
  let depsMap = targetMap.get(target);
  if (!depsMap) targetMap.set(target, (depsMap = new Map()));
  let deps = depsMap.get(key);
  if (!deps) depsMap.set(key, (deps = new Set()));
  deps.add(activeEffect);
}

function trigger(target, key) {
  const deps = targetMap.get(target)?.get(key);
  deps?.forEach(fn => fn());
}

function effect(fn) {
  const effectFn = () => {
    activeEffect = effectFn;
    fn();
    activeEffect = null;
  };
  effectFn();
}

// 使用
const state = reactive({ count: 0, name: 'vue' });
effect(() => console.log('count:', state.count));
state.count++; // 自动打印 count: 1
```

### 场景二：带批处理调度的响应式更新

```js
// 配合 scheduler 实现批处理：同步改三次，异步渲染一次
const state = reactive({ a: 0, b: 0 });
const queue = new Set();
let flushing = false;

function queueJob(job) {
  queue.add(job);
  if (flushing) return;
  flushing = true;
  Promise.resolve().then(() => {
    queue.forEach(job => job());
    queue.clear();
    flushing = false;
  });
}

let renderCount = 0;
effect(() => {
  // 渲染逻辑，依赖 a 和 b
  void state.a; void state.b;
  renderCount++;
}, { scheduler: queueJob });

state.a = 1;
state.b = 2;
state.a = 3; // 三次修改，scheduler 去重后只渲染一次
setTimeout(() => console.log('渲染次数：', renderCount), 0);
```

## 最佳实践与踩坑记录

### 最佳实践

1. 用 Proxy 实现响应式，能拦截新增属性和数组索引，比 defineProperty 完整
2. 依赖收集要精确到 key 粒度，避免一个属性变了整个对象都更新
3. 批量更新配合微任务队列，把多次同步修改合并成一次渲染
4. effect 重跑前清理旧依赖，防止「依赖变了还收到通知」的误触发
5. 大对象用 shallowReactive，避免深响应式的性能开销

### 踩坑记录

```text
坑 1：defineProperty 拦不到新增属性
结论：给对象加新属性，视图不更新。
原因：defineProperty 只能拦截已存在的属性，新增属性无感知。
解法：用 Proxy 拦截，或对新增属性调用手动 set 通知。

坑 2：effect 不清理依赖导致误触发
结论：条件分支改掉后，不再读取的数据变化仍触发更新。
原因：旧依赖还挂在 effect 上，没在重跑前清理。
解法：每次 effect 执行前清理 deps，执行时重新收集。

坑 3：循环里同步改状态导致多次渲染
结论：for 循环里改 100 次状态，渲染 100 次，页面卡顿。
原因：没做批量更新，每次写入都立即触发渲染。
解法：用批处理/调度器把同轮变更合并成一次更新。

坑 4：深层对象全量递归响应式化
结论：大对象或第三方对象递归代理，初始化慢、内存高。
原因：对不需要响应式的深层结构做了深代理。
解法：用 shallowReactive 只代理顶层，或 markRaw 标记跳过。

坑 5：在 getter 里写副作用
结论：读取数据时意外触发了其他修改，形成隐式循环依赖。
原因：把「读」和「写」混在一起，getter 里调了 setter。
解法：getter 保持纯函数，只读不写，副作用放到 effect 里。
```

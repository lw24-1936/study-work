## 概述

Compiler（编译器）把模板代码（Vue 的 template、JSX）在构建期转换成高效的渲染函数，把运行时的解析开销前移到编译阶段。它遵循经典的「解析 → 变换 → 生成」三段式：Parser 把模板解析成 AST，Transform 做语义分析和优化，Codegen 生成可执行的 JS 代码，最终在 Runtime 里执行。

```text
编译器的完整流水线：
1. Parser —— 模板字符串 → 词法/语法分析 → AST
2. AST —— 抽象语法树，描述模板结构的中间表示
3. Transform —— 对 AST 做优化（静态提升、补丁标记）
4. Codegen —— AST → 渲染函数代码字符串
5. Runtime —— 执行生成的代码，配合响应式产出 VNode
```

## Parser

Parser（解析器）把模板源码字符串转换成 AST。它先做词法分析（把字符流切成 token），再做语法分析（把 token 组装成树结构）。对 Vue 而言，就是解析 `<div>{{msg}}</div>` 这样的模板。

```js
// 极简模板解析：把 <tag>text</tag> 解析成 AST
function parse(template) {
  const ast = [];
  const tagRe = /<(\w+)([^>]*)>([\s\S]*?)<\/\1>/g;
  let match;
  while ((match = tagRe.exec(template))) {
    const [, tag, attrs, inner] = match;
    ast.push({
      type: 'element',
      tag,
      props: parseAttrs(attrs),
      children: parse(inner), // 递归解析子节点
    });
  }
  return ast;
}

function parseAttrs(attrsStr) {
  const props = {};
  const attrRe = /(\w+)="([^"]*)"/g;
  let m;
  while ((m = attrRe.exec(attrsStr))) {
    props[m[1]] = m[2];
  }
  return props;
}

console.log(parse('<div id="app"><span>hi</span></div>'));
// [{ type: 'element', tag: 'div', props: {id:'app'},
//    children: [{ type: 'element', tag: 'span', props: {}, children: [] }] }]
```

```text
Parser 的要点：
1. 词法分析 —— 字符流 → token（标签、属性、文本）
2. 语法分析 —— token → AST 树
3. 递归下降 —— 模板嵌套结构用递归解析
4. 容错 —— 真实解析器要处理非法输入并报错定位
```

## AST

AST（Abstract Syntax Tree，抽象语法树）是源码的结构化中间表示，每个节点描述模板的一个元素/文本/表达式。它是 Parser 的产物、Transform 的输入，也是所有编译优化和代码生成的基础。

```js
// 一段模板对应的 AST
// <div class="box">{{ message }}</div>
const ast = {
  type: 'element',
  tag: 'div',
  props: { class: 'box' },
  children: [
    {
      type: 'interpolation',        // 插值表达式 {{ }}
      content: { type: 'expression', value: 'message' },
    },
  ],
};

// 遍历 AST 的通用 visitor
function walk(node, visitor) {
  visitor(node);
  for (const child of node.children || []) {
    walk(child, visitor);
  }
}
walk(ast, node => console.log(node.type)); // element, interpolation
```

```text
AST 的要点：
1. 中间表示 —— 脱离具体语法，聚焦结构语义
2. 节点类型 —— element / text / interpolation / directive 等
3. 可遍历 —— 用 visitor 模式遍历和改写
4. 可优化 —— Transform 阶段在 AST 上做标记和提升
5. 位置信息 —— 保留行号列号，便于报错定位
```

## Transform

Transform（变换）在 AST 上做语义分析和优化：识别静态节点、标记动态绑定、提升不变内容。它把「运行时才知道怎么更新」的信息提前到编译期算好，让运行时更新更快、更精准。

```js
// 简化 Transform：标记静态节点和动态节点
function transform(ast) {
  const root = {
    type: 'root',
    children: ast,
    helpers: new Set(),
    dynamicChildren: [],
  };
  traverse(ast, node => {
    if (node.type === 'interpolation') {
      root.dynamicChildren.push(node);      // 动态节点
      root.helpers.add('renderInterpolation'); // 记录需要的辅助函数
    } else if (node.type === 'element') {
      if (!hasDynamic(node)) node.isStatic = true; // 静态节点标记
    }
  });
  return root;
}

function hasDynamic(node) {
  return (node.children || []).some(c => c.type === 'interpolation');
}
```

```text
Transform 的要点：
1. 静态提升 —— 不变节点提升到渲染函数外，避免重复创建
2. 动态标记 —— 标记 patchFlag，Diff 时只检查动态部分
3. 收集依赖 —— 记录渲染函数用到的辅助函数
4. 指令展开 —— v-if/v-for 等指令在编译期展开成代码
5. 优化目标 —— 把运行时开销前移到编译期
```

## Codegen

Codegen（代码生成）把优化后的 AST 转成可执行的 JS 代码字符串。对 Vue 而言，就是生成 render 函数（或返回 VNode 的代码），它配合响应式系统在状态变化时高效产出新的 VNode。

```js
// 简化 Codegen：AST → 渲染函数代码字符串
function codegen(ast) {
  if (ast.type === 'element') {
    const props = Object.entries(ast.props || {})
      .map(([k, v]) => `${k}: "${v}"`)
      .join(', ');
    const children = (ast.children || []).map(codegen).join(', ');
    return `h("${ast.tag}", { ${props} }, ${children})`;
  }
  if (ast.type === 'interpolation') {
    return `ctx.${ast.content.value}`;
  }
  if (ast.type === 'text') {
    return `"${ast.content}"`;
  }
  return 'null';
}

// 生成完整的 render 函数
function generate(ast) {
  return `function render(ctx) { return ${codegen(ast)}; }`;
}

const renderFn = generate({
  type: 'element',
  tag: 'div',
  props: { class: 'box' },
  children: [{ type: 'interpolation', content: { value: 'message' } }],
});
console.log(renderFn);
// function render(ctx) { return h("div", { class: "box" }, ctx.message); }
```

```text
Codegen 的要点：
1. AST → 代码字符串 —— 生成可执行的渲染函数
2. 字符串拼接/模板 —— 拼出合法的 JS 源码
3. 配合 Runtime —— 生成的代码依赖 h 等辅助函数
4. 可读性 —— 生成的代码尽量接近手写，便于调试
5. 产物 —— Vue SFC 编译后得到 render 函数，交给运行时执行
```

## Runtime

Runtime（运行时）负责执行编译器生成的代码，配合响应式系统完成渲染和更新。它提供 h（创建 VNode）、patch（更新 DOM）等辅助函数，是「编译产物」真正跑起来的地方。

```js
// 极简 Runtime：h + patch 让生成的 render 函数跑起来
function h(tag, props, ...children) {
  return { tag, props, children: children.flat() };
}

function patch(el, oldVNode, newVNode) {
  if (oldVNode.tag !== newVNode.tag) {
    const newEl = createElement(newVNode);
    el.parentNode.replaceChild(newEl, el);
    return newEl;
  }
  const text = extractText(newVNode);
  if (el.textContent !== text) {
    el.textContent = text; // 简化：只更新文本
  }
  return el;
}

function createElement(vnode) {
  const el = document.createElement(vnode.tag);
  el.textContent = extractText(vnode);
  return el;
}

function extractText(vnode) {
  if (typeof vnode === 'string') return vnode;
  return (vnode.children || []).map(extractText).join('');
}

// 执行编译产物
const render = (ctx) => h('div', { class: 'box' }, ctx.message);
const vnode = render({ message: 'Hello' });
console.log(extractText(vnode)); // Hello
```

```text
Runtime 的要点：
1. 辅助函数 —— 提供 h、patch 等编译产物依赖的 API
2. 执行渲染 —— 调用生成的 render 函数产出 VNode
3. 配合响应式 —— 状态变化时重新执行 render + patch
4. 轻量 —— 编译器做重活，运行时保持精简
```

## 应用场景实战

### 场景一：手写一个模板 → 渲染函数的迷你编译器

```js
// 完整迷你编译器：parse → transform → codegen → runtime
function compile(template) {
  const ast = parse(template)[0];
  const transformed = transform([ast]);
  return generate(transformed.children[0]);
}

const template = '<div id="app">{{ message }}</div>';
const renderFn = compile(template);
// renderFn 形如：function render(ctx){ return h("div", {id:"app"}, ctx.message) }

// 用 eval 执行（仅演示，生产环境绝不用 eval）
const render = eval(`(${renderFn})`);
console.log(render({ message: 'compiled!' }));
```

### 场景二：静态提升优化

```js
// 把不依赖状态的静态节点提升到渲染函数外，避免每次重建
const staticNodes = new Map();

function hoistStatic(ast) {
  if (ast.isStatic) {
    if (!staticNodes.has(ast.tag)) {
      staticNodes.set(ast.tag, h(ast.tag, ast.props)); // 只创建一次
    }
    return staticNodes.get(ast.tag);
  }
  return h(ast.tag, ast.props, ...(ast.children || []).map(hoistStatic));
}
// 这样静态 div 每次渲染复用同一个 VNode，Diff 直接跳过
```

## 最佳实践与踩坑记录

### 最佳实践

1. 把能在编译期确定的计算前移，别留到运行时每次重复做
2. 模板保持简单，复杂逻辑放进 JS 函数，别让编译器猜语义
3. 理解 SFC 的编译产物，调试时看生成的 render 函数
4. 静态内容用静态节点，减少 Diff 和重复创建
5. 避免在模板里写复杂表达式，交给 computed 或方法

### 踩坑记录

```text
坑 1：模板里写复杂表达式，编译产物难读难调
结论：生成的反 render 函数又长又绕，出 bug 很难定位。
原因：把一堆逻辑塞进模板表达式，编译器难以优化。
解法：复杂逻辑抽到 computed/method，模板只做简单绑定。

坑 2：用 eval 执行编译产物
结论：在运行时用 eval 跑生成的代码，有安全和性能隐患。
原因：贪图方便，把编译期生成、运行期执行的边界搞混了。
解法：编译在构建期完成，产物是普通模块，直接 import 使用。

坑 3：忽略编译器的静态提升优化
结论：大量静态节点每次渲染都重新创建，性能浪费。
原因：不了解静态提升机制，把可静态化的内容写成动态。
解法：不依赖状态的模板片段保持静态，让编译器自动提升。

坑 4：手写解析器时正则解析嵌套结构
结论：用正则解析嵌套标签，遇到复杂嵌套就崩溃。
原因：正则无法处理任意深度嵌套，状态机才对。
解法：用递归下降/状态机写解析器，不要用正则硬匹配嵌套。

坑 5：AST 遍历时改了结构没回溯
结论：Transform 阶段改 AST 后，父节点引用断裂。
原因：遍历时修改子节点数组，迭代器状态失效。
解法：先收集要改的节点，遍历完再统一修改。
```

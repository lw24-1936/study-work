## 概述

Virtual DOM（虚拟 DOM）是用 JavaScript 对象描述真实 DOM 结构的轻量表示。状态变化时，框架先在内存里比对「新虚拟 DOM」和「旧虚拟 DOM」的差异，再把最小变更一次性应用到真实 DOM，从而把频繁、昂贵的 DOM 操作变成廉价的 JS 计算和批量更新。

```text
Virtual DOM 的核心流程：
1. 渲染 —— 状态/模板产出 VNode 树（虚拟 DOM）
2. Diff —— 比对新旧两棵 VNode 树，找出差异
3. Patch —— 把差异应用到真实 DOM，最小化操作
4. Reconciliation —— 整个「比对 + 更新」的协调过程
5. Key —— 帮助 Diff 识别节点身份，实现复用
```

## VNode

VNode（虚拟节点）是虚拟 DOM 的基本单元，用一个普通 JS 对象描述一个真实 DOM 节点的类型、属性和子节点。它比真实 DOM 轻得多，创建和比较都快。

```js
// VNode 的最小结构
function h(tag, props, ...children) {
  return {
    tag,        // 标签名：'div'、'ul' 等
    props,      // 属性对象：{ id, class, onClick }
    key: props?.key,  // 唯一标识，Diff 复用依据
    children,   // 子 VNode 数组或文本
  };
}

// 描述 <div id="app"><span>hello</span></div>
const vnode = h('div', { id: 'app' },
  h('span', null, 'hello')
);
console.log(vnode);
// { tag: 'div', props: { id: 'app' }, key: undefined,
//   children: [{ tag: 'span', props: null, children: ['hello'] }] }
```

```text
VNode 的要点：
1. 纯对象 —— 用 tag/props/children 描述 DOM，无 DOM 开销
2. 轻量 —— 创建和比较比真实 DOM 快得多
3. 可序列化 —— 可跨平台（SSR、跨端渲染）
4. 类型 —— 元素节点、文本节点、组件节点、Fragment 等
```

## Diff

Diff 是比对新旧两棵 VNode 树、找出最小变更集的算法。它的关键优化是同层比较（不跨层）和 key 复用，把朴素 O(n³) 的树比较降到 O(n)。

```js
// 简化版子节点 Diff：新旧子列表对比
function diffChildren(oldChildren, newChildren) {
  const patches = [];
  const oldMap = new Map();
  oldChildren.forEach((child, i) => {
    if (child.key != null) oldMap.set(child.key, { child, i });
  });

  let lastIndex = 0;
  newChildren.forEach((newChild, i) => {
    const found = oldMap.get(newChild.key);
    if (found) {
      if (found.i < lastIndex) {
        patches.push({ type: 'move', from: found.i, to: i });
      } else {
        lastIndex = found.i;
      }
    } else {
      patches.push({ type: 'insert', node: newChild, to: i });
    }
  });

  oldChildren.forEach((oldChild, i) => {
    if (!newChildren.some(c => c.key === oldChild.key)) {
      patches.push({ type: 'remove', from: i });
    }
  });
  return patches;
}
```

```text
Diff 的要点：
1. 同层比较 —— 只比同一层级，跨层直接替换
2. 双指针 —— 头尾对撞，减少不必要的移动
3. key 复用 —— 有 key 才能识别「同一个节点」
4. 复杂度 —— 优化后 O(n)，远快于暴力 O(n³)
```

## Patch

Patch 是 Diff 的落地步骤：把 Diff 计算出的差异（patches）应用到真实 DOM 上。它只做「必要的」DOM 操作——增、删、改属性、替换节点，避免全量重建。

```js
// 把 patch 应用到真实 DOM
function applyPatch(container, patch) {
  const { type } = patch;
  switch (type) {
    case 'insert': {
      const el = createElement(patch.node);
      container.insertBefore(el, container.childNodes[patch.to]);
      break;
    }
    case 'remove': {
      container.removeChild(container.childNodes[patch.from]);
      break;
    }
    case 'move': {
      const el = container.childNodes[patch.from];
      const ref = container.childNodes[patch.to];
      container.insertBefore(el, ref);
      break;
    }
    case 'updateProps': {
      const el = container.childNodes[patch.index];
      for (const [key, val] of Object.entries(patch.props)) {
        el.setAttribute(key, val);
      }
      break;
    }
  }
}

function createElement(vnode) {
  if (typeof vnode === 'string') return document.createTextNode(vnode);
  const el = document.createElement(vnode.tag);
  for (const child of vnode.children || []) {
    el.appendChild(createElement(child));
  }
  return el;
}
```

```text
Patch 的要点：
1. 最小操作 —— 只做 Diff 标记的增删改，不做全量重建
2. 批量应用 —— 收集所有差异后统一提交，减少重排
3. 属性更新 —— 只更新变化的属性，不覆盖整个节点
4. 与 Diff 分离 —— Diff 计算、Patch 执行，职责清晰
```

## Reconciliation

Reconciliation（协调）是框架完整的更新机制：状态变化 → 重新渲染出新 VNode 树 → Diff 找出差异 → Patch 更新真实 DOM。它管理着「何时更新、更新哪些节点、如何复用节点」的全过程。

```js
// 简化版协调器：新旧 VNode 树对比并更新
function reconcile(container, oldVNode, newVNode) {
  // 1. 类型不同，直接替换
  if (!isSameNode(oldVNode, newVNode)) {
    container.replaceChild(createElement(newVNode), container.firstChild);
    return newVNode;
  }
  // 2. 更新属性
  updateProps(container.firstChild, oldVNode.props, newVNode.props);
  // 3. 递归协调子节点
  reconcileChildren(container.firstChild, oldVNode.children, newVNode.children);
  return newVNode;
}

function isSameNode(a, b) {
  if (!a || !b) return false;
  return a.tag === b.tag && a.key === b.key;
}

function updateProps(el, oldProps = {}, newProps = {}) {
  for (const key in { ...oldProps, ...newProps }) {
    if (oldProps[key] !== newProps[key]) {
      if (newProps[key] == null) el.removeAttribute(key);
      else el.setAttribute(key, newProps[key]);
    }
  }
}
```

```text
Reconciliation 的要点：
1. 完整流程 —— render → diff → commit 三段式
2. 节点复用 —— 类型和 key 相同才复用，否则重建
3. 可中断 —— React Fiber 把协调拆成可中断单元
4. 统一入口 —— 所有更新都走这一套机制，保证一致
```

## Key

Key 是列表项的稳定唯一标识，Diff 靠它判断「新旧列表中哪些是同一个节点」。正确设置 key 能让框架复用节点、保持组件状态；用错 key（如数组下标）会导致复用错乱和状态串位。

```jsx
// 正确：用业务唯一 id 作 key
<ul>
  {todos.map(todo => (
    <li key={todo.id}>{todo.text}</li>
  ))}
</ul>

// 错误：用数组下标，重排/插入时会复用错乱
<ul>
  {todos.map((todo, index) => (
    <li key={index}>{todo.text}</li>
  ))}
</ul>
```

```text
Key 的要点：
1. 稳定唯一 —— 用业务 id，不用数组下标
2. 兄弟间唯一 —— 同一列表内 key 不重复即可，不必全局唯一
3. 状态保持 —— key 相同则复用组件实例，状态不丢
4. 慎用 index —— 重排、插入、删除时会导致复用错乱
5. 值稳定 —— key 用原始值，避免每次渲染都生成新引用
```

## 应用场景实战

### 场景一：手写一个迷你虚拟 DOM 渲染器

```js
// 极简虚拟 DOM：h 创建 VNode，render 挂载，update 对比更新
function h(tag, props, ...children) {
  return { tag, props, children: children.flat() };
}

function render(vnode, container) {
  const el = typeof vnode === 'string'
    ? document.createTextNode(vnode)
    : createElement(vnode);
  container.appendChild(el);
  return el;
}

function createElement(vnode) {
  const el = document.createElement(vnode.tag);
  for (const [k, v] of Object.entries(vnode.props || {})) {
    el.setAttribute(k, v);
  }
  for (const child of vnode.children) {
    render(child, el);
  }
  return el;
}

const app = document.getElementById('app');
const vnode = h('div', { class: 'box' },
  h('h1', null, 'Hello'),
  h('p', null, 'Virtual DOM')
);
render(vnode, app);
```

### 场景二：带 key 的列表 Diff

```js
// 带 key 的列表 Diff：正确识别新增、删除、移动
const oldList = [
  { key: 1, text: 'a' },
  { key: 2, text: 'b' },
  { key: 3, text: 'c' },
];
const newList = [
  { key: 3, text: 'c' },
  { key: 1, text: 'a' },
  { key: 4, text: 'd' },
];

const oldMap = new Map(oldList.map(item => [item.key, item]));
const patches = [];
newList.forEach(item => {
  if (!oldMap.has(item.key)) patches.push(`新增 ${item.text}`);
  else oldMap.delete(item.key);
});
oldMap.forEach(item => patches.push(`删除 ${item.text}`));
console.log(patches); // ['新增 d', '删除 b']
```

## 最佳实践与踩坑记录

### 最佳实践

1. 列表项一律用业务唯一 id 作 key，杜绝用数组下标
2. 避免在渲染函数里创建新的对象/函数引用，减少无谓 Diff
3. 组件拆分要细，让 Diff 的作用域尽量小
4. 大数据列表配合虚拟列表，别让虚拟 DOM 树过大
5. 理解「同层比较」，跨层移动节点会触发重建，设计时避免频繁跨层

### 踩坑记录

```text
坑 1：用 index 当 key，重排后状态串位
结论：列表插入/删除/重排后，输入框内容、选中态跑到别的行。
原因：index 不是稳定标识，重排后同一 index 指向不同数据。
解法：用业务唯一 id 当 key，Diff 才能正确复用节点。

坑 2：key 用随机数/时间戳
结论：每次渲染 key 都变，列表节点全部重建，性能极差。
原因：key 不稳定，框架认为每个节点都是新的。
解法：key 必须是稳定唯一值，不能每次渲染重新生成。

坑 3：误以为虚拟 DOM 一定比直接操作 DOM 快
结论：简单场景下手动操作 DOM 反而更快，却硬套虚拟 DOM。
原因：虚拟 DOM 的价值在于「声明式 + 最小化更新」，不是绝对性能。
解法：理解它的优势是可维护性和批量更新，而非绝对速度。

坑 4：Diff 后仍然全量重建
结论：每次更新 DOM 节点全部重建，页面闪烁且卡顿。
原因：类型判断写错，key 缺失导致无法复用。
解法：确保 tag + key 都正确，让框架能命中复用路径。

坑 5：跨层移动节点导致频繁重建
结论：把节点从一个父容器移到另一个，触发整棵子树重建。
原因：Diff 只做同层比较，跨层移动被当成删除 + 新建。
解法：设计组件层级时保持稳定，避免频繁跨层移动。
```

## 概述

Scheduler（调度器）决定「哪些任务先做、什么时候做、做多久」，是框架保证流畅体验的核心。它基于任务优先级把更新排队，用微任务/宏任务控制执行时机，用 Yield 和 Time Slice 让长任务可中断、可让位，避免长时间占用主线程导致掉帧。

```text
调度器的核心机制：
1. Priority —— 为任务分级，高优先级先执行
2. Task Queue —— 任务队列，按优先级有序存放待执行任务
3. Microtask —— 微任务，本轮同步代码后立即执行
4. Macrotask —— 宏任务，下一轮事件循环执行
5. Yield —— 主动让出主线程，把控制权交还浏览器
6. Time Slice —— 时间分片，大任务切成小片分批执行
```

## Priority

Priority（优先级）给任务分级，让调度器知道哪些任务该先做。典型分级如「同步/用户交互/普通/空闲」，高优先级的用户交互任务能插队到低优先级任务之前，保证交互及时响应。

```js
// 优先级定义（数字越小优先级越高）
const Priority = {
  IMMEDIATE: 1,     // 同步优先，不可中断
  USER_BLOCKING: 2, // 用户交互，如点击、输入
  NORMAL: 3,        // 普通更新
  LOW: 4,           // 低优先级，可延后
  IDLE: 5,          // 空闲时才做
};

// 按优先级调度
function schedule(priority, fn) {
  const task = { priority, fn };
  taskQueue.push(task);
  taskQueue.sort((a, b) => a.priority - b.priority);
  runNext();
}
```

```text
Priority 的要点：
1. 分级 —— 用户交互 > 普通更新 > 空闲任务
2. 插队 —— 高优任务可以抢占低优任务
3. 饥饿问题 —— 低优任务不能永远饿死，需兜底执行
4. 应用 —— React 的 Lane 模型、浏览器的渲染优先级
```

## Task Queue

Task Queue（任务队列）按优先级存放待执行的任务，调度器从中取出任务执行。它通常是优先队列（堆实现），保证每次取出的是当前最高优先级的任务。

```js
// 基于小顶堆的优先级任务队列
class TaskQueue {
  constructor() {
    this.heap = [];
  }
  push(task) {
    this.heap.push(task);
    let i = this.heap.length - 1;
    while (i > 0) {
      const p = (i - 1) >> 1;
      if (this.heap[p].priority <= this.heap[i].priority) break;
      [this.heap[p], this.heap[i]] = [this.heap[i], this.heap[p]];
      i = p;
    }
  }
  pop() {
    const top = this.heap[0];
    const last = this.heap.pop();
    if (this.heap.length) {
      this.heap[0] = last;
      this._sink(0);
    }
    return top;
  }
  _sink(i) {
    const n = this.heap.length;
    while (true) {
      let min = i;
      const l = i * 2 + 1, r = i * 2 + 2;
      if (l < n && this.heap[l].priority < this.heap[min].priority) min = l;
      if (r < n && this.heap[r].priority < this.heap[min].priority) min = r;
      if (min === i) break;
      [this.heap[i], this.heap[min]] = [this.heap[min], this.heap[i]];
      i = min;
    }
  }
  get size() { return this.heap.length; }
}
```

```text
Task Queue 的要点：
1. 优先队列 —— 用堆实现，取最高优先级 O(log n)
2. 有序 —— 出队顺序由优先级决定，而非入队顺序
3. 去重 —— 相同任务重复入队时合并，避免重复执行
4. 应用 —— React Scheduler 的 taskQueue/timerQueue
```

## Microtask

Microtask（微任务）在「当前同步代码执行完、事件循环进入下一轮之前」执行。Promise.then、queueMicrotask、MutationObserver 都是微任务。它优先级高于宏任务，适合做「尽快但要等同步代码结束」的更新。

```js
// 微任务：同步代码跑完后立即执行
console.log('1 同步');
queueMicrotask(() => console.log('3 微任务'));
Promise.resolve().then(() => console.log('4 微任务'));
console.log('2 同步');
// 输出顺序：1 同步 → 2 同步 → 3 微任务 → 4 微任务
```

```text
Microtask 的要点：
1. 时机 —— 当前同步代码结束后、下一个宏任务前
2. 优先级 —— 高于宏任务，先于渲染前的部分工作
3. 用途 —— 批量更新、nextTick、Promise 回调
4. 陷阱 —— 微任务里再排微任务会饿死宏任务（无限循环）
```

## Macrotask

Macrotask（宏任务）是事件循环的「一轮」主体，setTimeout、setInterval、I/O、消息事件都是宏任务。每个宏任务执行完后，事件循环会清空所有微任务，再进行渲染，然后进入下一个宏任务。

```js
// 宏任务 vs 微任务的执行顺序
console.log('1 同步');
setTimeout(() => console.log('4 宏任务'), 0);
Promise.resolve().then(() => console.log('3 微任务'));
setTimeout(() => console.log('5 宏任务'), 0);
console.log('2 同步');
// 输出：1 → 2 → 3（微任务）→ 4（宏任务）→ 5（宏任务）
```

```text
Macrotask 的要点：
1. 一轮循环 —— 一个宏任务 = 一轮事件循环的主任务
2. 时机 —— 微任务全部清空后才轮到下一个宏任务
3. 用途 —— 定时器、I/O 回调、把任务推迟到下一轮
4. 渲染时机 —— 浏览器常在宏任务之间插入渲染
```

## Yield

Yield（让出）是任务主动把主线程控制权交还给浏览器，让浏览器有机会处理输入、渲染等高优先级工作。它是时间分片和可中断任务的基础，避免长时间同步执行把页面卡死。

```js
// 主动让出：检查是否应该暂停，把控制权还给浏览器
function shouldYield() {
  // 判断当前任务是否已经超过时间片（如 5ms）
  return performance.now() - startTime > 5;
}

let startTime = performance.now();
function workLoop() {
  while (currentTask && !shouldYield()) {
    currentTask();        // 执行一小片
    currentTask = nextTask();
  }
  if (currentTask) {
    // 还有任务，让出主线程，下个宏任务继续
    setTimeout(workLoop, 0);
  }
}
```

```text
Yield 的要点：
1. 主动让位 —— 检查时间预算，超时就暂停
2. 保证响应 —— 让浏览器能及时处理输入和渲染
3. 配合调度 —— 让出后通过宏任务/微任务继续执行
4. 应用 —— React 的可中断渲染、时间切片
```

## Time Slice

Time Slice（时间分片）把一个大任务切成多个小片，每片在限定时间（如 5ms）内执行，超时就让出主线程。这样长任务不会一次阻塞主线程几百毫秒，保证每帧都有机会渲染，避免掉帧。

```js
// 时间分片：把 1 万项渲染任务切成每批 5ms
const tasks = Array.from({ length: 10000 }, (_, i) => () => {
  // 渲染第 i 项
  renderItem(i);
});

const FRAME_TIME = 5; // 每片最多 5ms
function sliceWork() {
  const sliceStart = performance.now();
  while (tasks.length && performance.now() - sliceStart < FRAME_TIME) {
    const task = tasks.shift();
    task();
  }
  if (tasks.length) {
    // 还有剩余，让出主线程，下一轮继续
    requestIdleCallback(sliceWork) || setTimeout(sliceWork, 0);
  }
}
sliceWork();
```

```text
Time Slice 的要点：
1. 切片 —— 大任务拆成小片，单片执行时间可控
2. 时间预算 —— 每片不超过帧预算（通常 5ms 左右）
3. 让位续跑 —— 时间到就让出，用空闲回调/宏任务继续
4. 收益 —— 长任务不再阻塞主线程，保持 60fps
5. 应用 —— 大列表渲染、长计算任务的拆分
```

## 应用场景实战

### 场景一：按优先级调度的任务队列

```js
// 完整示例：优先级队列 + 微任务批量执行
const queue = new TaskQueue();
let flushing = false;

function scheduleTask(priority, fn) {
  queue.push({ priority, fn });
  if (flushing) return;
  flushing = true;
  Promise.resolve().then(() => {
    while (queue.size) {
      const task = queue.pop();
      task.fn();
    }
    flushing = false;
  });
}

scheduleTask(3, () => console.log('低优：日志上报'));
scheduleTask(1, () => console.log('高优：用户交互响应'));
scheduleTask(2, () => console.log('中优：数据更新'));
// 输出顺序：高优 → 中优 → 低优
```

### 场景二：用时间分片渲染大数据列表

```js
// 时间分片：10 万行数据分批渲染，不阻塞主线程
const data = Array.from({ length: 100000 }, (_, i) => i);
const container = document.getElementById('list');
let index = 0;
const BATCH = 200; // 每批渲染 200 行

function renderBatch(deadline) {
  while (index < data.length && (deadline.timeRemaining() > 0 || deadline.didTimeout)) {
    const item = document.createElement('div');
    item.textContent = `第 ${data[index]} 行`;
    container.appendChild(item);
    index++;
  }
  if (index < data.length) {
    requestIdleCallback(renderBatch, { timeout: 100 });
  }
}
requestIdleCallback(renderBatch, { timeout: 100 });
```

## 最佳实践与踩坑记录

### 最佳实践

1. 用户交互任务设高优先级，保证点击/输入即时响应
2. 日志上报、预加载等设低优先级，让出主线程给关键任务
3. 长任务用时间分片，单片控制在 5ms 内，保持 60fps
4. 批量更新用微任务，避免多次渲染；长任务续跑用宏任务或 requestIdleCallback
5. 低优先级任务要有兜底，防止被高优任务饿死

### 踩坑记录

```text
坑 1：微任务里递归排微任务，饿死宏任务
结论：页面卡死，setTimeout、渲染永远得不到执行。
原因：微任务队列里不断生成新微任务，事件循环永远清不完。
解法：微任务里避免无限递归，长任务用宏任务或时间分片让位。

坑 2：长任务不分片，一次阻塞主线程
结论：点击、滚动无响应，页面明显卡顿掉帧。
原因：几百毫秒的同步计算/渲染占满主线程，浏览器无法渲染。
解法：用时间分片，每片 5ms 内让出主线程。

坑 3：优先级设置不当，低优任务饿死
结论：持续的日志上报永远排不上，任务堆积内存上涨。
原因：低优先级任务没有兜底，一直被高优任务插队。
解法：给低优任务设过期时间，到期自动提升优先级执行。

坑 4：用 setTimeout 0 当微任务用
结论：期望「同步代码后立即执行」，结果延迟到下一个宏任务。
原因：混淆了宏任务和微任务的执行时机。
解法：需要尽快执行用 Promise/queueMicrotask，需要推迟用 setTimeout。

坑 5：时间分片用 setTimeout 精度不够
结论：setTimeout(0) 实际延迟 4ms 以上，分片效率低。
原因：浏览器对嵌套定时器有最小延迟限制（约 4ms）。
解法：优先用 requestIdleCallback 或 MessageChannel 让出。
```

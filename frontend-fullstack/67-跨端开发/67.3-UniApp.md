## 概述

UniApp 是 DCloud 推出的跨端框架，基于 Vue 语法编写，一套代码编译到 H5、各小程序（微信/支付宝/百度等）、App（iOS/Android）。对国内多端场景尤其友好。

```text
UniApp 的核心特性：
1. Vue 语法 —— 用 Vue 写页面，前端无缝上手
2. 一套多端 —— 编译到 H5、小程序、App、快应用
3. 条件编译 —— 按平台写差异化代码
4. 生态丰富 —— uni-ui 组件库、插件市场
5. 国内友好 —— 小程序与 App 打包开箱即用
```

```vue
<template>
  <view class="container">
    <text>{{ message }}</text>
    <button @click="handleClick">点击</button>
  </view>
</template>

<script>
export default {
  data() {
    return { message: 'Hello UniApp' };
  },
  methods: {
    handleClick() {
      uni.showToast({ title: '点击成功' });
    },
  },
};
</script>
```

## Vue

UniApp 基于 Vue，语法与 Vue 高度一致，但组件映射到各端。

```text
Vue 语法在 UniApp：
1. 支持 Vue 2 与 Vue 3（新项目建议 Vue 3）
2. 组件 —— view、text、image 等替代 div、span、img
3. 生命周期 —— onLoad、onShow 等页面级生命周期
4. 指令 —— v-if、v-for、v-model 均可用
```

```vue
<script setup>
import { ref } from 'vue';

const count = ref(0);
const items = ref(['a', 'b', 'c']);
</script>

<template>
  <view>
    <text>{{ count }}</text>
    <view v-for="item in items" :key="item">{{ item }}</view>
  </view>
</template>
```

## H5

编译到 H5 时，UniApp 页面渲染为常规网页。

```text
H5 端特点：
1. 渲染为普通 HTML/CSS/JS
2. 支持浏览器全部能力
3. 组件映射为 div 等 DOM 元素
4. 适合做 Web 端与 SEO 场景
```

```json
// manifest.json 配置 H5 路由模式
{
  "h5": {
    "router": {
      "mode": "history",
      "base": "/"
    }
  }
}
```

## Mini Program

小程序是 UniApp 的核心场景，一套代码编译到微信/支付宝/百度等多个小程序平台。

```text
小程序编译：
1. 组件映射 —— view → 小程序 view，button → button
2. 条件编译 —— #ifdef MP-WEIXIN 写微信专属代码
3. 分包 —— 支持主包/分包优化体积
4. 能力对齐 —— uni 的 API 统一各小程序差异
```

```vue
<script>
export default {
  onLoad() {
    // #ifdef MP-WEIXIN
    console.log('仅在微信小程序编译');
    // #endif

    // #ifdef MP-ALIPAY
    console.log('仅在支付宝小程序编译');
    // #endif
  },
};
</script>
```

```text
条件编译指令：
#ifdef —— 仅在某平台包含
#ifndef —— 排除某平台
#ifdef H5 || MP-WEIXIN —— 多平台组合
```

## App

编译到 App 时，UniApp 打包为原生安装包（iOS/Android）。

```text
App 端特点：
1. 打包方式 —— 云打包或本地离线打包
2. 渲染引擎 —— 可选 WebView 或 nvue（原生渲染）
3. 原生能力 —— 通过 plus API 调用摄像头、定位等
4. 热更新 —— 可下发 wgt 资源包
```

```js
// 调用原生能力（App 端 plus API）
export function getLocation() {
  return new Promise((resolve, reject) => {
    plus.geolocation.getCurrentPosition(resolve, reject);
  });
}
```

```text
nvue 与 vue 页面：
vue —— WebView 渲染，跨端兼容好
nvue —— 原生渲染，性能更好，但语法受限
```

## 应用场景实战

### 场景一：多端商城

```vue
<script setup>
import { ref } from 'vue';

const goods = ref([
  { id: 1, name: '商品A', price: 99 },
  { id: 2, name: '商品B', price: 199 },
]);

function buy(item) {
  uni.showModal({
    title: '确认购买',
    content: `${item.name} ¥${item.price}`,
  });
}
</script>

<template>
  <view>
    <view v-for="g in goods" :key="g.id">
      <text>{{ g.name }} - ¥{{ g.price }}</text>
      <button @click="buy(g)">购买</button>
    </view>
  </view>
</template>
```

### 场景二：条件编译分享

```js
function share() {

  // #endif

  // #ifdef APP-PLUS
  plus.share.sendWithSystem({}, '分享内容', null, '');
  // #endif
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. 新项目用 Vue 3 组合式 API
2. 差异代码用条件编译，别在运行时判断平台
3. 大列表用分页/虚拟滚动，避免小程序性能问题
4. 统一用 uni 的 API，别直接用小程序的 wx API
5. 小程序注意主包体积，合理分包

### 踩坑记录

```text
坑 1：用了 Web 专属 API 报错
结论：document、window 在小程序端不存在。
原因：小程序是独立运行环境，没有 DOM。
解法：用 uni 统一 API，或条件编译区分。

坑 2：图片显示不出来
结论：图片在小程序不加载。
原因：域名未在小程序后台配置合法域名。
解法：配置 request/uploadFile/downloadFile 合法域名。

坑 3：样式在 App 与 H5 不一致
结论：同一套样式多端渲染差异大。
原因：小程序 rpx 与 H5 的 px 换算、组件差异。
解法：用 rpx/upx 单位，差异处条件编译。

坑 4：nvue 与 vue 语法不兼容
结论：nvue 页面部分 CSS 不生效。
原因：nvue 原生渲染，只支持 flex 布局。
解法：优先 vue 页面，性能要求高才用 nvue。

坑 5：v-for 没有 key 警告
结论：小程序端列表更新异常。
原因：缺少 key 导致 diff 错误。
解法：v-for 一定加 :key。
```

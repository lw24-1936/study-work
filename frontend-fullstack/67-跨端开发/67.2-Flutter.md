## 概述

Flutter 是 Google 推出的跨端 UI 框架，用 Dart 编写，自绘 UI（Skia/Impeller 渲染引擎），不依赖系统原生控件，一套代码跑 iOS、Android、Web、桌面。

```text
Flutter 的核心特性：
1. 自绘引擎 —— 用 Skia/Impeller 自己绘制，不依赖原生控件
2. 一切皆 Widget —— UI 由 Widget 树组合而成
3. Dart 语言 —— 强类型、AOT/JIT 双模式
4. 高性能 —— 直接编译为原生机器码，接近原生
5. 跨多端 —— 移动端、Web、桌面一套代码
```

```dart
import 'package:flutter/material.dart';

void main() => runApp(const MyApp());

class MyApp extends StatelessWidget {
  const MyApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      home: Scaffold(
        body: Center(child: Text('Hello Flutter')),
      ),
    );
  }
}
```

## Widget

Widget 是 Flutter 的 UI 基本单元，描述界面「应该长什么样」。

```text
Widget 分类：
1. StatelessWidget —— 无状态，输入不变输出不变
2. StatefulWidget —— 有状态，通过 setState 触发重建
3. 组合 —— 通过嵌套 Widget 树构建界面
4. 不可变 —— Widget 本身不可变，变化时重建新的
```

```dart
class Counter extends StatefulWidget {
  const Counter({super.key});

  @override
  State<Counter> createState() => _CounterState();
}

class _CounterState extends State<Counter> {
  int count = 0;

  @override
  Widget build(BuildContext context) {
    return Column(
      children: [
        Text('$count'),
        ElevatedButton(
          onPressed: () => setState(() => count++),
          child: const Text('加一'),
        ),
      ],
    );
  }
}
```

```text
Widget 三棵树：
1. Widget 树 —— 配置（不可变）
2. Element 树 —— 生命周期与状态管理
3. RenderObject 树 —— 真正的布局与绘制
```

## Dart

Dart 是 Flutter 的编程语言，兼具静态类型与灵活语法。

```text
Dart 特点：
1. 强类型 —— 编译期类型检查，减少运行时错误
2. AOT/JIT —— 开发用 JIT 热重载，生产用 AOT 编译
3. 面向对象 —— 类、继承、mixin
4. 异步 —— Future、async/await、Stream
5. 空安全 —— null safety，编译期规避空指针
```

```dart
// 异步与空安全示例
Future<String> fetchName() async {
  final name = await loadFromNetwork();
  return name ?? '匿名';   // null 安全兜底
}

// 集合与函数式
final nums = [1, 2, 3, 4];
final doubled = nums.map((n) => n * 2).toList();  // [2, 4, 6, 8]
```

## Rendering Engine

Flutter 不依赖原生控件，而是用渲染引擎自绘每一帧。

```text
渲染引擎演进：
1. Skia —— 老引擎，跨平台 2D 图形库
2. Impeller —— 新引擎，针对 iOS/Android 优化，减少卡顿
3. 绘制流程 —— Widget → Element → RenderObject → Layer → 引擎绘制
4. 优势 —— UI 三端完全一致，不受系统控件差异影响
```

```text
为什么自绘？
原生控件在不同系统/版本表现不一致，自绘保证像素级一致，
并且 Flutter 可以直接控制每一帧的渲染。
```

## Platform Channel

Platform Channel 是 Dart 与原生（Kotlin/Swift）通信的机制，用于调用系统能力。

```text
Platform Channel 三种：
1. MethodChannel —— 方法调用（Dart 调原生，最常见）
2. EventChannel —— 事件流（原生推送到 Dart）
3. BasicMessageChannel —— 双向消息
```

```dart
import 'package:flutter/services.dart';

const platform = MethodChannel('com.example/battery');

Future<int> getBatteryLevel() async {
  final level = await platform.invokeMethod('getBatteryLevel');
  return level;
}
```

```kotlin
// Android 原生侧（Kotlin）
MethodChannel(flutterEngine.dartExecutor.binaryMessenger, "com.example/battery")
    .setMethodCallHandler { call, result ->
        if (call.method == "getBatteryLevel") {
            result.success(100)
        } else {
            result.notImplemented()
        }
    }
```

## Isolate

Dart 默认单线程（UI 线程），Isolate 是并发执行单元，不共享内存。

```text
Isolate 特点：
1. 独立内存 —— 每个 Isolate 有独立堆，不共享状态
2. 消息通信 —— 通过 SendPort/ReceivePort 传消息
3. 不阻塞 UI —— 耗时任务放独立 Isolate 跑
4. compute 简化 —— 便捷函数快速创建 Isolate
```

```dart
import 'package:flutter/foundation.dart';

// compute 简化 Isolate 用法
int heavyCalc(int n) {
  var sum = 0;
  for (var i = 0; i < n; i++) sum += i;
  return sum;
}

Future<void> run() async {
  final result = await compute(heavyCalc, 100000000);
  print(result);
}
```

```text
注意：
Isolate 之间不共享内存，通信靠消息拷贝，
大对象传递有拷贝开销，需权衡。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 优先用 const 构造 Widget，减少重建开销
2. 大列表用 ListView.builder 懒加载
3. 耗时计算放 Isolate，别卡 UI 线程
4. 状态管理按项目规模选择（setState → Provider/Riverpod/Bloc）
5. Platform Channel 传大数据注意序列化开销

### 踩坑记录

```text
坑 1：setState 后 UI 没更新
结论：修改状态后界面无变化。
原因：直接改了可变对象，引用未变，框架判断无需重建。
解法：创建新对象赋值，或用不可变数据结构。

坑 2：长列表一次性渲染卡顿
结论：用 Column 嵌套 ListView 导致全部构建。
原因：Column 会一次性创建所有子 Widget。
解法：用 ListView.builder 按需构建。

坑 3：耗时任务卡死 UI
结论：同步执行大计算导致界面冻结。
原因：Dart 默认单线程，UI 与逻辑同线程。
解法：用 compute/Isolate 隔离耗时任务。

坑 4：Channel 类型不匹配崩溃
结论：invokeMethod 返回值类型错误。
原因：原生返回类型与 Dart 期望不一致。
解法：统一约定返回类型，做好空安全判断。

坑 5：热重载丢状态
结论：修改代码热重载后状态丢失。
原因：热重载重建 Widget 树，State 可能不保留。
解法：用热重启（hot restart）或保证状态可重建。
```

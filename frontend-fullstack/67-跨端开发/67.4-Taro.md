## 概述

Taro 是京东开源的跨端框架，用 React（也支持 Vue）编写，一套代码编译到小程序、H5、React Native 等多端。核心是「类 React 语法 + 多端编译」。

```text
Taro 的核心特性：
1. React 语法 —— 用 React 组件/JSX 写多端应用
2. 多端编译 —— 编译到微信/支付宝等小程序、H5、RN
3. 运行时适配 —— 提供统一的 API 与组件层
4. 生态成熟 —— 插件、组件库（taro-ui）完善
5. 支持 Vue —— 3.x 起同时支持 React 与 Vue
```

```jsx
import { View, Text, Button } from '@tarojs/components';

export default function Home() {
  return (
    <View>
      <Text>Hello Taro</Text>
      <Button onClick={() => console.log('点击')}>按钮</Button>
    </View>
  );
}
```

## React

Taro 基于 React 组件模型，但组件来自 @tarojs/components，而非 DOM 元素。

```text
Taro 中的 React：
1. 组件 —— 用 View/Text/Image 替代 div/span/img
2. Hooks —— useState、useEffect 等完全可用
3. 事件 —— 用 onClick 等驼峰命名
4. 语法 —— JSX、函数组件、类组件
```

```jsx
import { useState } from 'react';
import { View, Text, Input } from '@tarojs/components';

export default function Counter() {
  const [count, setCount] = useState(0);

  return (
    <View>
      <Text>{count}</Text>
      <Input value={String(count)} />
      <View onClick={() => setCount(count + 1)}>加一</View>
    </View>
  );
}
```

## Mini Program

小程序是 Taro 最核心的编译目标。

```text
小程序编译：
1. React 组件编译为小程序自定义组件
2. 模板 —— JSX 编译为 WXML
3. 样式 —— CSS 编译为 WXSS
4. 分包 —— 支持主包/分包/独立分包
```

```jsx
// 使用小程序专属能力
import Taro from '@tarojs/taro';
import { View } from '@tarojs/components';

export default function Share() {
  const handleShare = () => {
    Taro.showShareMenu({ withShareTicket: true });
  };

  return <View onClick={handleShare}>分享</View>;
}
```

```text
编译产物结构：
src/pages/index/index.jsx  →  编译为
dist/weapp/pages/index/index.js + index.wxml + index.wxss + index.json
```

## H5

Taro 也可编译为 H5 网页。

```text
H5 编译：
1. 组件映射为 DOM 元素
2. 支持 Web 全部能力
3. 路由 —— 用 Taro 路由 API，编译为 Web 路由
4. 适合做 Web 端展示
```

```jsx
import Taro from '@tarojs/taro';
import { View } from '@tarojs/components';

export default function GoDetail() {
  const go = () => {
    Taro.navigateTo({ url: '/pages/detail/index' });
  };

  return <View onClick={go}>跳转详情</View>;
}
```

## Native

Taro 3.x 起支持编译到 React Native，用原生渲染提升性能。

```text
Native 编译：
1. 目标 —— React Native，原生渲染
2. 组件映射 —— Taro 组件映射为 RN 组件
3. 性能 —— 比小程序/H5 更接近原生
4. 场景 —— 对性能要求高的移动应用
```

```jsx
// Taro 编译到 RN，代码保持一致
import { View, Text, ScrollView } from '@tarojs/components';

export default function List() {
  return (
    <ScrollView>
      <View><Text>条目 1</Text></View>
      <View><Text>条目 2</Text></View>
    </ScrollView>
  );
}
```

## 应用场景实战

### 场景一：多端电商小程序

```jsx
import { useState } from 'react';
import { View, Text } from '@tarojs/components';
import Taro from '@tarojs/taro';

export default function Goods() {
  const [list] = useState([
    { id: 1, name: '商品A', price: 99 },
    { id: 2, name: '商品B', price: 199 },
  ]);

  const buy = (item) => {
    Taro.showToast({ title: `已选 ${item.name}` });
  };

  return (
    <View>
      {list.map((g) => (
        <View key={g.id} onClick={() => buy(g)}>
          <Text>{g.name} - ¥{g.price}</Text>
        </View>
      ))}
    </View>
  );
}
```

### 场景二：跨端请求封装

```jsx
import Taro from '@tarojs/taro';

export function request(url, data) {
  return Taro.request({
    url: `${process.env.API_BASE}${url}`,
    data,
    header: { 'Content-Type': 'application/json' },
  }).then((res) => res.data);
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. 组件从 @tarojs/components 引入，别用原生 DOM 标签
2. 平台差异用 process.env.TARO_ENV 判断
3. 样式用 rpx 单位适配多端
4. 请求统一封装，避免每处写域名
5. 小程序注意分包与体积优化

### 踩坑记录

```text
坑 1：用了 HTML 标签编译失败
结论：div/span 等标签在小程序端报错。
原因：小程序没有这些标签，需映射为 View/Text。
解法：统一用 @tarojs/components 的组件。

坑 2：事件名大小写问题
结论：onClick 与 onTap 混淆。
原因：Taro 统一用 onClick，小程序原生是 bindtap。
解法：按 Taro 规范写 onClick，编译时自动转换。

坑 3：图片域名白名单
结论：小程序图片加载失败。
原因：图片域名未配置合法域名。
解法：在小程序后台配置 downloadFile 合法域名。

坑 4：循环渲染缺 key
结论：列表更新错乱、警告。
原因：React diff 依赖 key 定位节点。
解法：map 渲染必须加唯一 key。

坑 5：CSS 选择器兼容
结论：部分 CSS 选择器在小程序不生效。
原因：小程序 WXSS 不支持标签选择器、通配符等。
解法：用类选择器，避免高级选择器。
```

## 概述

Tauri 是用 Rust 构建桌面应用的框架，前端用任意 Web 技术，后端用 Rust，复用系统 WebView 而非打包 Chromium，体积远小于 Electron。

```text
Tauri 的核心特性：
1. 极小体积 —— 复用系统 WebView，安装包几 MB
2. Rust 后端 —— 高性能、内存安全
3. 前端自由 —— React/Vue/Svelte 任意框架
4. 安全 —— 默认最小权限，能力需显式声明
5. 跨平台 —— Windows/macOS/Linux
```

```text
Tauri 对比 Electron：
Electron —— 打包 Chromium + Node，体积大（100MB+），内存占用高
Tauri —— 复用系统 WebView + Rust，体积小（几 MB），内存占用低
```

```rust
// main.rs
fn main() {
    tauri::Builder::default()
        .invoke_handler(tauri::generate_handler![greet])
        .run(tauri::generate_context!())
        .expect("error while running tauri application");
}

#[tauri::command]
fn greet(name: &str) -> String {
    format!("Hello, {}!", name)
}
```

## Rust

Rust 是 Tauri 的后端语言，负责系统级能力与性能敏感逻辑。

```text
Rust 特点：
1. 内存安全 —— 所有权系统，无 GC、无空指针
2. 高性能 —— 编译为原生机器码
3. 强类型 —— 编译期检查，减少运行时错误
4. 跨平台 —— 编译到三大桌面平台
```

```rust
// Rust 基础语法示意
fn main() {
    let mut total = 0;
    for i in 1..=100 {
        total += i;
    }
    println!("total: {}", total);   // 5050
}
```

```text
Rust 在 Tauri 中的角色：
1. 系统命令 —— 文件、网络、进程等操作
2. 性能敏感 —— 加密、压缩、图像处理
3. 内存优化 —— 低内存占用
```

## WebView

Tauri 复用操作系统的 WebView 来渲染前端界面。

```text
WebView 复用：
1. Windows —— WebView2（Edge Chromium）
2. macOS —— WKWebView（Safari）
3. Linux —— WebKitGTK
4. 好处 —— 不打包浏览器内核，体积骤减
```

```text
注意点：
1. 不同系统 WebView 版本差异 → 兼容性问题
2. 依赖系统已安装对应 WebView
3. 前端是标准 Web，无特殊 API
```

## IPC

Tauri 的 IPC 通过 command 实现，前端 invoke 调用 Rust 函数。

```rust
// Rust 定义 command
#[tauri::command]
fn read_file(path: String) -> Result<String, String> {
    std::fs::read_to_string(path).map_err(|e| e.to_string())
}
```

```js
// 前端调用
import { invoke } from '@tauri-apps/api/core';

const content = await invoke('read_file', { path: '/tmp/a.txt' });
console.log(content);
```

```text
IPC 机制：
1. 前端 invoke(name, args) → Rust command
2. 参数与返回值自动序列化（JSON）
3. 返回 Result，错误可捕获
```

## Native API

Tauri 提供丰富的前端 API（插件），访问系统原生能力。

```text
原生能力插件：
1. fs —— 文件系统
2. dialog —— 原生对话框
3. notification —— 系统通知
4. clipboard —— 剪贴板
5. shell —— 执行命令
```

```rust
// 安装插件并在 Builder 注册
fn main() {
    tauri::Builder::default()
        .plugin(tauri_plugin_fs::init())
        .plugin(tauri_plugin_dialog::init())
        .run(tauri::generate_context!())
        .expect("error");
}
```

```js
// 前端使用原生对话框
import { open } from '@tauri-apps/plugin-dialog';

const file = await open({ multiple: false });
console.log(file);
```

## 应用场景实战

### 场景一：本地文件管理器

```rust
#[tauri::command]
fn list_dir(path: String) -> Result<Vec<String>, String> {
    let mut files = Vec::new();
    for entry in std::fs::read_dir(path).map_err(|e| e.to_string())? {
        let entry = entry.map_err(|e| e.to_string())?;
        files.push(entry.file_name().to_string_lossy().to_string());
    }
    Ok(files)
}
```

```js
import { invoke } from '@tauri-apps/api/core';

const files = await invoke('list_dir', { path: '/tmp' });
files.forEach((f) => console.log(f));
```

### 场景二：系统通知

```js
import {
  isPermissionGranted,
  requestPermission,
  sendNotification,
} from '@tauri-apps/plugin-notification';

async function notify() {
  let granted = await isPermissionGranted();
  if (!granted) granted = (await requestPermission()) === 'granted';
  if (granted) sendNotification({ title: '提示', body: '任务完成' });
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. 能力按需声明，最小权限原则
2. 前端框架随意选，逻辑与 UI 分层
3. 性能敏感逻辑下沉到 Rust command
4. command 返回 Result，别直接 panic
5. 大文件读写走流式，别一次性读内存

### 踩坑记录

```text
坑 1：command 未注册
结论：前端 invoke 报 command not found。
原因：command 未加入 generate_handler! 列表。
解法：在 Builder 的 invoke_handler 中注册 command。

坑 2：参数名不匹配
结论：invoke 传参后 Rust 收到默认值或报错。
原因：前端参数名与 Rust 参数名不一致。
解法：invoke 的 args 键名与 command 参数名严格一致。

坑 3：不同系统 WebView 渲染差异
结论：macOS 正常，Windows/Linux 表现不一致。
原因：各系统 WebView 内核版本不同。
解法：做兼容性测试，避免依赖最新 Web 特性。

坑 4：权限未配置
结论：访问文件报权限错误。
原因：fs 插件需在 capability 中声明允许的路径。
解法：在 capabilities 配置文件中声明作用域。

坑 5：体积没想象中小
结论：打包后体积偏大。
原因：引入了大量依赖或未开优化。
解法：开 release 优化，精简依赖，用 strip 减小体积。
```

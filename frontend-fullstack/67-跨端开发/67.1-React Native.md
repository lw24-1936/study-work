## 概述

React Native（RN）是 Meta 推出的跨端框架，用 JavaScript/TypeScript 编写 React 组件，渲染为真正的原生 UI（iOS/Android）。与 WebView 方案不同，RN 调用原生控件，性能和体验接近原生。

```text
React Native 的核心特性：
1. 用 React 写原生 —— 一套 JS 代码，渲染 iOS/Android 原生控件
2. 真正原生 UI —— 不是 WebView，是原生 View/Text/Image
3. 跨端共享 —— 业务逻辑、组件可跨平台复用
4. 架构演进 —— 从 Bridge 到 JSI/Fabric/TurboModules 新架构
5. 热更新 —— 可下发 JS Bundle 动态更新
```

```js
import { View, Text, StyleSheet } from 'react-native';

export default function App() {
  return (
    <View style={styles.container}>
      <Text style={styles.title}>Hello React Native</Text>
    </View>
  );
}

const styles = StyleSheet.create({
  container: { flex: 1, justifyContent: 'center', alignItems: 'center' },
  title: { fontSize: 20, fontWeight: 'bold' },
});
```

## Component

RN 的组件对应原生控件，由 JS 层声明，原生层渲染。

```text
RN 组件体系：
1. 基础组件 —— View、Text、Image、ScrollView、TextInput
2. 组件本质 —— 每个组件映射到对应的原生 View
3. 事件处理 —— 通过 Props 回调（onPress 等）
4. 样式 —— StyleSheet.create，Flexbox 布局
```

```js
import { View, Text, TextInput, Pressable } from 'react-native';

function Form() {
  return (
    <View>
      <TextInput placeholder="输入用户名" />
      <Pressable onPress={() => console.log('提交')}>
        <Text>提交</Text>
      </Pressable>
    </View>
  );
}
```

```text
注意：
1. 没有 div/span，只有 View/Text
2. 文本必须包在 Text 内
3. Flexbox 默认 flexDirection 是 column（Web 是 row）
4. 样式是 JS 对象，不是 CSS
```

## Bridge

Bridge 是 RN 老架构的核心，负责 JS 与原生之间的通信。

```text
Bridge 工作原理：
1. JS 线程与原生线程分离
2. 通信通过「桥」异步传递消息（JSON 序列化）
3. 三类消息 —— 调用原生方法、回调、事件
4. 瓶颈 —— 所有通信走桥，大数据量/高频调用性能差
```

```js
// 老架构下调用原生模块（异步，走 Bridge）
import { NativeModules } from 'react-native';

const { ToastModule } = NativeModules;
// 调用原生方法，跨桥异步
ToastModule.show('Hello', 1000);
```

```text
Bridge 的局限：
1. 异步 —— 无法同步获取结果
2. 序列化开销 —— JSON 序列化/反序列化
3. 单通道 —— 大量消息会排队阻塞
4. 新架构用 JSI 取代 Bridge
```

## JSI

JSI（JavaScript Interface）是新架构的基础，让 JS 直接持有原生对象引用，取代 Bridge 的异步消息。

```text
JSI 核心思想：
1. JS 与原生直接互调 —— 通过 C++ 层直接暴露接口
2. 同步调用 —— 不再依赖异步消息队列
3. 零拷贝 —— 避免 JSON 序列化，共享内存
4. 引擎无关 —— 可替换 JS 引擎（Hermes/V8）
```

```cpp
// JSI 概念示意：原生侧向 JS 暴露函数（伪代码）
// 通过 jsi::Runtime 注册 hostObject
auto hostObject = std::make_shared<MyHostObject>();
runtime.global().setProperty(runtime, "nativeApi",
    jsi::Object::createFromHostObject(runtime, hostObject));
```

```text
JSI 带来的改变：
1. TurboModules 基于 JSI —— 模块懒加载、同步调用
2. Fabric 基于 JSI —— 渲染层直接通信
3. Hermes 基于 JSI —— 引擎可插拔
```

## Fabric

Fabric 是新架构的渲染系统（UI 层），取代老架构的 UI Manager。

```text
Fabric 特点：
1. 新渲染管线 —— 由 C++ 层直接处理 UI 更新
2. 同步渲染 —— 借助 JSI，UI 指令同步下发
3. 优先级调度 —— 支持 React 18 的并发特性
4. 跨平台一致 —— 同一套 C++ 核心跑在 iOS/Android
```

```text
Fabric 对比老架构：
老架构 UI Manager —— JS 通过 Bridge 异步发 UI 指令，延迟明显
Fabric —— 直接通过 JSI 下发，减少跳帧、提升流畅度
```

## TurboModules

TurboModules 是原生模块的新实现，基于 JSI 的懒加载、类型安全的模块系统。

```text
TurboModules 特点：
1. 按需加载 —— 用到才加载原生模块，缩短启动时间
2. 同步调用 —— 通过 JSI 直接调用，不排队
3. 类型安全 —— 用 Codegen 生成类型，减少运行时报错
4. 向后兼容 —— 老 Native Module 仍可工作
```

```js
// 使用 TurboModule（API 与老 NativeModule 基本一致）
import { NativeModules } from 'react-native';

const { DeviceInfo } = NativeModules;
// 新架构下走 JSI 同步调用
const deviceId = DeviceInfo.getDeviceId();
```

## Hermes

Hermes 是 Meta 为 RN 优化的轻量 JS 引擎，提升启动速度和内存占用。

```text
Hermes 特性：
1. 预编译 —— AOT 编译为字节码，减少解析时间
2. 启动快 —— 比 JSC/V8 首屏启动更快
3. 内存小 —— 针对移动端低内存优化
4. 支持 JSI —— 与新架构无缝配合
```

```js
// Android 开启 Hermes（android/app/build.gradle）
// project.ext.react = [
//     enableHermes: true
// ]
```

```text
Hermes 注意点：
1. 调试需开启 source map
2. 老版本对 Proxy/部分 ES 特性支持受限，新版本已补齐
3. 生产环境强烈建议开启
```

## Native Module

Native Module 是 JS 调用原生能力（相机、传感器等）的桥梁，需原生侧实现。

```text
Native Module 开发流程：
1. 原生侧 —— 实现模块（Android 用 Kotlin/Java，iOS 用 ObjC/Swift）
2. 暴露方法 —— 通过注解/宏注册到 RN
3. JS 侧 —— 通过 NativeModules 调用
```

```java
// Android 原生模块（Kotlin）
class ToastModule(reactContext: ReactApplicationContext) :
    ReactContextBaseJavaModule(reactContext) {

    override fun getName() = "ToastModule"

    @ReactMethod
    fun show(message: String, duration: Int) {
        Toast.makeText(reactContext, message, duration).show()
    }
}
```

```js
// JS 侧调用
import { NativeModules } from 'react-native';
const { ToastModule } = NativeModules;
ToastModule.show('保存成功', 1000);
```

## 应用场景实战

### 场景一：跨平台业务 App

```js
// 一套代码同时跑 iOS/Android
import { Platform, StyleSheet } from 'react-native';

const padding = Platform.OS === 'ios' ? 20 : 16;

const styles = StyleSheet.create({
  container: { padding },
});
```

### 场景二：调用设备能力（定位）

```js
import { NativeModules, PermissionsAndroid, Platform } from 'react-native';

async function getLocation() {
  if (Platform.OS === 'android') {
    await PermissionsAndroid.request(
      PermissionsAndroid.PERMISSIONS.ACCESS_FINE_LOCATION,
    );
  }
  return NativeModules.LocationModule.getCurrentPosition();
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. 生产环境开启 Hermes，缩短启动时间
2. 新项目直接采用新架构（Fabric + TurboModules）
3. 高频交互走 JSI 同步调用，避免走老 Bridge
4. 列表用 FlatList/FlashList，不用 ScrollView 渲染大列表
5. 原生模块做类型安全（Codegen），减少运行时报错

### 踩坑记录

```text
坑 1：文本不在 Text 组件内
结论：直接放字符串到 View 报错。
原因：RN 没有裸文本节点，必须用 Text 包裹。
解法：所有文本用 Text 组件包裹。

坑 2：Flexbox 默认方向是 column
结论：横向布局不生效。
原因：RN 的 flexDirection 默认 column，与 Web 的 row 相反。
解法：显式设置 flexDirection: 'row'。

坑 3：Bridge 高频通信卡顿
结论：大量 JS 与原生频繁通信时掉帧。
原因：老 Bridge 异步 + JSON 序列化，消息排队。
解法：升级新架构走 JSI，或减少跨端调用频率。

坑 4：新架构与老库不兼容
结论：部分老原生库在新架构下崩溃。
原因：老库基于 Bridge 实现，未适配 TurboModules。
解法：检查库是否支持新架构，或临时关闭新架构。

坑 5：Hermes 调试时看不到源码
结论：调试时报错指向字节码。
原因：Hermes 预编译，需 source map 还原。
解法：开启 source map，用 Chrome DevTools 调试。
```

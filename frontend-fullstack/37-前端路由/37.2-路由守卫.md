## 概述

路由守卫在导航发生前、中、后执行逻辑，用于身份认证（Authentication）、权限控制（Authorization）、数据预取、页面离开确认等。核心是拦截导航，根据条件决定「放行、重定向、取消」。

```text
路由守卫核心概念：
1. Authentication —— 身份认证：确认「你是谁」
2. Authorization —— 授权：确认「你能做什么」
3. Permission —— 权限：细粒度的功能/数据访问控制
4. Navigation Guard —— 导航守卫：拦截导航的钩子
5. Redirect —— 重定向：引导到登录页/无权页等
```

```js
// 认证 + 权限 + 重定向的典型组合
router.beforeEach((to) => {
  const token = getToken();
  if (to.meta.requiresAuth && !token) {
    return { name: 'login', query: { redirect: to.fullPath } }; // Redirect
  }
  if (to.meta.permission && !hasPermission(to.meta.permission)) {
    return { name: '403' }; // 无权限重定向
  }
  return true; // 放行
});
```

## Authentication

认证（Authentication）确认用户身份，通常基于 token/session。路由守卫中最常见的是「未登录跳转登录页」。

```js
// 认证守卫：未登录重定向到登录页
router.beforeEach((to) => {
  const token = localStorage.getItem('token');
  const isLoginPage = to.name === 'login';

  if (!token && !isLoginPage) {
    return { name: 'login', query: { redirect: to.fullPath } };
  }
  if (token && isLoginPage) {
    return { name: 'home' }; // 已登录访问登录页，跳首页
  }
  return true;
});
```

```js
// React Router 方式（用包装组件）
function RequireAuth({ children }) {
  const token = localStorage.getItem('token');
  const location = useLocation();
  if (!token) {
    return <Navigate to="/login" state={{ from: location }} replace />;
  }
  return children;
}

<Route path="/dashboard" element={<RequireAuth><Dashboard /></RequireAuth>} />
```

```text
认证要点：
1. token 存在性判断，必要时校验有效性/过期
2. 记录来源路径，登录后回跳
3. 已登录访问登录页时重定向到首页
```

## Authorization

授权（Authorization）确认用户是否有权限做某事，比认证更细粒度。通常结合用户角色（role）或权限列表判断。

```js
// 基于角色的授权
router.beforeEach((to) => {
  const user = getUser();
  if (to.meta.roles && !to.meta.roles.includes(user.role)) {
    return { name: '403' }; // 角色不符，无权访问
  }
  return true;
});

// 路由配置
const routes = [
  {
    path: '/admin',
    component: Admin,
    meta: { roles: ['admin'] }, // 仅 admin 角色可访问
  },
];
```

```text
授权模型：
1. 基于角色（RBAC）—— role 判断，简单直观
2. 基于权限点 —— permission 列表判断，更细粒度
3. 前端只做体验控制，真正的安全在后端
```

## Permission

权限（Permission）是比角色更细粒度的控制，控制到「按钮」「菜单」「数据」级别。路由权限控制哪些路由可见可访问，配合动态路由生成菜单。

```js
// 基于权限点的判断
function hasPermission(perm) {
  return user.permissions.includes(perm);
}

router.beforeEach((to) => {
  const required = to.meta.permission;
  if (required && !hasPermission(required)) {
    return { name: '403' };
  }
  return true;
});
```

```js
// 动态路由：根据权限过滤生成路由表
function buildRoutes(allRoutes, permissions) {
  return allRoutes
    .filter((r) => !r.meta?.permission || permissions.includes(r.meta.permission))
    .map((r) => ({ ...r, children: r.children ? buildRoutes(r.children, permissions) : [] }));
}

const routes = buildRoutes(allRoutes, user.permissions);
routes.forEach((r) => router.addRoute(r)); // 动态注册
```

```text
权限控制分层：
1. 路由级 —— 控制页面访问
2. 菜单级 —— 控制可见菜单
3. 按钮级 —— 控制操作（指令/组件包裹）
4. 数据级 —— 后端控制（前端无法保证安全）
```

## Navigation Guard

导航守卫是路由库提供的拦截钩子，分为全局、路由级、组件级，执行顺序有明确约定。

```js
// Vue Router 全局守卫
router.beforeEach((to, from) => {
  // 前置：放行/重定向/取消
  return true; // 放行
  return false; // 取消当前导航
  return { name: 'login' }; // 重定向
});

router.beforeResolve((to) => {
  // 解析守卫，在组件解析后、确认导航前
});

router.afterEach((to, from) => {
  // 后置钩子，不能取消导航
  document.title = to.meta.title;
});
```

```js
// React Router v6 没有原生守卫，用组件实现
function Guard({ children, guard }) {
  const location = useLocation();
  const result = guard();
  if (result === false) return null;
  if (result?.redirect) return <Navigate to={result.redirect} replace />;
  return children;
}
```

```text
Vue 守卫执行顺序：
beforeRouteLeave（离开组件）
→ beforeEach（全局前置）
→ beforeRouteUpdate（复用组件）
→ beforeEnter（路由级）
→ 解析异步组件
→ beforeRouteEnter（进入组件）
→ beforeResolve
→ afterEach
```

## Redirect

重定向（Redirect）把用户导航到另一个路径，用于登录跳转、默认页、旧链接迁移、无权跳转等。

```js
// 路由配置重定向
const routes = [
  { path: '/', redirect: '/home' }, // 默认跳首页
  { path: '/old-path', redirect: '/new-path' }, // 旧链接迁移
  { path: '/admin', redirect: (to) => (hasAuth() ? '/admin/dashboard' : '/login') },
];
```

```js
// 守卫中动态重定向（带回跳参数）
router.beforeEach((to) => {
  if (!isLogin()) {
    return { path: '/login', query: { redirect: to.fullPath } };
  }
  return true;
});

// 登录成功后回跳
const redirect = route.query.redirect || '/';
router.push(redirect);
```

```text
重定向要点：
1. 登录页记录来源，登录后回跳
2. 默认路径重定向到首页
3. 无权访问重定向到 403
4. 避免重定向循环（登录页重定向到登录页）
```

## 应用场景实战

### 场景一：完整的登录鉴权流程

```js
// 守卫：未登录跳登录页并记录来源
router.beforeEach((to) => {
  const token = localStorage.getItem('token');
  if (to.meta.requiresAuth && !token) {
    return { name: 'login', query: { redirect: to.fullPath } };
  }
  return true;
});

// 登录页：登录成功后回跳
async function handleLogin() {
  const res = await api.login(form);
  localStorage.setItem('token', res.token);
  const redirect = route.query.redirect || '/';
  router.push(redirect);
}
```

### 场景二：基于角色的动态路由

```js
async function setupRoutes(user) {
  const accessible = filterRoutesByRole(allRoutes, user.role);
  accessible.forEach((r) => router.addRoute(r));
  router.addRoute({ path: '/:pathMatch(.*)*', component: NotFound });
  // 兜底跳转
  router.replace({ name: 'home' });
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. 认证、授权逻辑集中在全局前置守卫，避免散落
2. 前端权限只做体验控制，安全依赖后端校验
3. 登录重定向记录来源路径，提升体验
4. 动态路由注册后补一个 404 兜底路由
5. 避免重定向循环，登录页等公开页要放行

### 踩坑记录

```text
坑 1：重定向循环
结论：页面无限跳转，浏览器报「重定向次数过多」。
原因：登录页也被守卫拦截，反复重定向。
解法：公开路由（登录页）在守卫中白名单放行。

坑 2：只在前端做权限控制
结论：直接调接口仍能越权操作。
原因：前端权限可被绕过，非安全边界。
解法：后端做真正的鉴权，前端仅优化体验。

坑 3：动态路由未注册 404
结论：刷新或直接访问未注册路由白屏。
原因：动态注册后缺少兜底路由。
解法：注册完成后补通配符 404 路由。

坑 4：afterEach 里尝试取消导航
结论：取消无效。
原因：afterEach 是后置钩子，导航已确认。
解法：取消导航用 beforeEach，afterEach 只做收尾。

坑 5：token 失效未处理
结论：token 过期后请求报 401，但前端仍停留。
原因：只判断 token 存在，未校验有效性。
解法：请求拦截器捕获 401，清理 token 并跳登录。
```

## 概述

SPA（单页应用）路由让页面在不刷新浏览器的情况下切换视图。前端路由有两种实现：Hash 路由（基于 URL 的 # 部分）和 History 路由（基于 History API）。React Router、Vue Router 等库封装了这些能力，通过 Router 管理导航，Route 声明路径与组件的映射。

```text
SPA 路由核心概念：
1. Hash Router —— 基于 URL hash（#/path），无需服务端配置
2. History Router —— 基于 History API，URL 干净，需服务端 fallback
3. BrowserRouter —— React Router 的 History 模式
4. Router —— 路由容器/管理器，提供导航上下文
5. Route —— 路径与组件的映射规则
6. Nested Route —— 嵌套路由，父组件内渲染子路由
7. Dynamic Route —— 动态路由，路径含参数（/user/:id）
```

```js
import { BrowserRouter, Routes, Route } from 'react-router-dom';

function App() {
  return (
    <BrowserRouter>
      <Routes>
        <Route path="/" element={<Home />} />
        <Route path="/about" element={<About />} />
      </Routes>
    </BrowserRouter>
  );
}
```

## Hash Router

Hash 路由把路径写在 URL 的 `#` 后面（如 `/#/user/1`），利用 `hashchange` 事件监听变化。`#` 后内容不会发送给服务端，因此无需服务端配置。

```js
// 原生 hash 路由实现
window.addEventListener('hashchange', () => {
  const path = location.hash.slice(1) || '/';
  render(path);
});

// 跳转
location.hash = '#/about';
```

```js
// React Router 使用 HashRouter
import { HashRouter, Routes, Route } from 'react-router-dom';

<HashRouter>
  <Routes>
    <Route path="/" element={<Home />} />
  </Routes>
</HashRouter>
```

```text
Hash 路由特点：
1. 兼容性好 —— 老浏览器也支持
2. 无需服务端配置 —— # 后不发送到服务端
3. URL 不美观 —— 带 # 符号
4. 不利于 SEO —— 搜索引擎忽略 hash
```

## History Router

History 路由利用 History API（pushState/replaceState + popstate），URL 干净无 #，但刷新时需要服务端把未知路径回退到 index.html。

```js
// 原生 History 路由
window.addEventListener('popstate', () => {
  render(location.pathname);
});

// 跳转
history.pushState({}, '', '/about');
render('/about');
```

```js
// Vue Router 的 History 模式
import { createRouter, createWebHistory } from 'vue-router';

const router = createRouter({
  history: createWebHistory(),
  routes,
});
```

```text
History 路由特点：
1. URL 干净美观，无 #
2. 支持 SEO（配合 SSR）
3. 刷新需服务端 fallback 到 index.html
4. 兼容性较好（IE10+）
```

## BrowserRouter

BrowserRouter 是 React Router 中基于 History API 的路由容器，为应用提供路由上下文，是所有路由组件的外层包裹。

```js
import { BrowserRouter, Routes, Route, Link, useNavigate } from 'react-router-dom';

function App() {
  return (
    <BrowserRouter>
      <nav>
        <Link to="/">首页</Link>
        <Link to="/about">关于</Link>
      </nav>
      <Routes>
        <Route path="/" element={<Home />} />
        <Route path="/about" element={<About />} />
      </Routes>
    </BrowserRouter>
  );
}
```

```js
// 编程式导航
function Home() {
  const navigate = useNavigate();
  return <button onClick={() => navigate('/about')}>跳转</button>;
}
```

```text
BrowserRouter 要点：
1. 必须包裹整个应用（一个应用一个）
2. 提供 useNavigate、useLocation 等 hook 的上下文
3. 生产环境需服务端配置 fallback
```

## Router

Router 是路由管理器，负责维护当前路径状态、匹配路由、驱动视图渲染。不同库有不同形态（React Router 的 BrowserRouter、Vue Router 的 createRouter）。

```js
// Vue Router 创建 router 实例
import { createRouter, createWebHistory } from 'vue-router';

const router = createRouter({
  history: createWebHistory(),
  routes: [
    { path: '/', component: Home },
    { path: '/about', component: About },
  ],
});

// 挂载
app.use(router);

// 导航
router.push('/about');
```

```text
Router 职责：
1. 解析当前 URL
2. 匹配路由表，找到对应组件
3. 管理导航状态与历史栈
4. 暴露导航方法（push/replace/back）
```

## Route

Route 声明「路径 → 组件」的映射。React Router 用 `<Route>` 组件，Vue Router 用路由配置对象。

```js
// React Router
<Routes>
  <Route path="/" element={<Home />} />
  <Route path="/user/:id" element={<UserDetail />} />
  <Route path="*" element={<NotFound />} /> {/* 404 兜底 */}
</Routes>
```

```js
// Vue Router
const routes = [
  { path: '/', component: Home },
  { path: '/user/:id', component: UserDetail },
  { path: '/:pathMatch(.*)*', component: NotFound },
];
```

```text
Route 要点：
1. path 精确匹配（React 默认，可加 * 通配）
2. 404 兜底路由放最后
3. 支持重定向（redirect）、别名（alias）
```

## Nested Route

嵌套路由让子路由渲染在父组件的 `<Outlet>`（React）或 `<router-view>`（Vue）中，形成「布局 + 内容」的结构。

```js
// React Router 嵌套
import { Outlet } from 'react-router-dom';

function Layout() {
  return (
    <div>
      <nav>侧边栏</nav>
      <Outlet /> {/* 渲染子路由 */}
    </div>
  );
}

<Routes>
  <Route path="/dashboard" element={<Layout />}>
    <Route index element={<Overview />} /> {/* 默认子路由 */}
    <Route path="users" element={<Users />} />
    <Route path="settings" element={<Settings />} />
  </Route>
</Routes>
```

```js
// Vue Router 嵌套
const routes = [
  {
    path: '/dashboard',
    component: Layout,
    children: [
      { path: '', component: Overview },
      { path: 'users', component: Users },
    ],
  },
];
```

```text
嵌套路由要点：
1. 父组件放置 Outlet/router-view 出口
2. index 或空 path 表示默认子路由
3. 子路径用相对路径
```

## Dynamic Route

动态路由在路径中使用参数占位符（`:id`），匹配不同 URL 并提取参数，供组件读取。

```js
// React Router
import { useParams } from 'react-router-dom';

function UserDetail() {
  const { id } = useParams(); // 从 /user/123 提取 id = '123'
  return <div>用户 {id}</div>;
}

<Route path="/user/:id" element={<UserDetail />} />
```

```js
// Vue Router
import { useRoute } from 'vue-router';

const route = useRoute();
const id = route.params.id;

// 配置
{ path: '/user/:id', component: UserDetail, props: true }
```

```text
动态路由要点：
1. :id 是必选参数，:id? 是可选参数
2. 参数变化复用组件时需监听参数变化
3. 通配符 * 匹配任意路径
```

## 应用场景实战

### 场景一：后台布局 + 嵌套路由

```js
<BrowserRouter>
  <Routes>
    <Route path="/" element={<PublicLayout />}>
      <Route index element={<Landing />} />
      <Route path="login" element={<Login />} />
    </Route>
    <Route path="/admin" element={<AdminLayout />}>
      <Route index element={<Dashboard />} />
      <Route path="users" element={<UserManage />} />
      <Route path="users/:id" element={<UserEdit />} />
    </Route>
  </Routes>
</BrowserRouter>
```

### 场景二：详情页带参数跳转

```js
function List() {
  const navigate = useNavigate();
  return (
    <ul>
      {items.map((item) => (
        <li key={item.id} onClick={() => navigate(`/users/${item.id}`)}>
          {item.name}
        </li>
      ))}
    </ul>
  );
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. 生产环境 History 模式务必配置服务端 fallback
2. 404 兜底路由放最后，避免吞掉正常路由
3. 嵌套路由子路径用相对路径，不用绝对路径
4. 动态参数变化用 watch/useEffect 监听，而非只依赖 mounted
5. 布局类结构用嵌套路由，减少重复代码

### 踩坑记录

```text
坑 1：History 模式刷新 404
结论：直接访问子路由刷新后报 404。
原因：服务端未把未知路径回退到 index.html。
解法：Nginx 配 try_files，或改用 Hash 模式。

坑 2：动态参数变化组件不更新
结论：/user/1 到 /user/2 组件数据不变。
原因：组件复用，未重新挂载。
解法：useEffect 依赖 params，或 watch 监听参数。

坑 3：嵌套路由子路径用绝对路径
结论：子路由匹配错误，跑到顶层。
原因：以 / 开头是绝对路径。
解法：子路由写相对路径。

坑 4：404 路由放在前面
结论：所有路由都匹配到 404。
原因：通配符 * 提前匹配。
解法：404 兜底路由放最后。

坑 5：忘记 Outlet 出口
结论：子路由配置了但内容不显示。
原因：父组件没有 Outlet/router-view。
解法：父组件添加 Outlet 渲染子路由。
```

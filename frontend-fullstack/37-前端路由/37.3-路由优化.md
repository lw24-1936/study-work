## 概述

路由优化围绕「按需加载」展开：通过路由懒加载把代码按路由拆分（Code Splitting），减小首屏体积；配合 Prefetch/Preload 提前加载即将访问的资源，让路由切换更流畅。三者共同优化加载性能与用户体验。

```text
路由优化核心概念：
1. Route Lazy Loading —— 路由组件按需加载（动态 import）
2. Prefetch —— 空闲时预取即将用到的资源
3. Preload —— 高优先级预加载当前关键资源
4. Code Splitting —— 代码分割，按路由拆 chunk
```

```js
// 懒加载 + 代码分割
const routes = [
  { path: '/', component: () => import('./Home.vue') },
  { path: '/about', component: () => import('./About.vue') },
  { path: '/dashboard', component: () => import('./Dashboard.vue') },
];
```

## Route Lazy Loading

路由懒加载用动态 `import()` 让组件在路由被访问时才加载，而不是打包进首屏。Vue Router 和 React Router 都通过动态 import 实现。

```js
// Vue Router 懒加载
const routes = [
  { path: '/user', component: () => import('./views/User.vue') },
  // 命名 chunk（构建时明确分包名）
  {
    path: '/settings',
    component: () => import(/* webpackChunkName: "settings" */ './views/Settings.vue'),
  },
];
```

```js
// React Router 懒加载（配合 React.lazy + Suspense）
import { lazy, Suspense } from 'react';

const Dashboard = lazy(() => import('./pages/Dashboard'));

function App() {
  return (
    <Suspense fallback={<div>加载中...</div>}>
      <Routes>
        <Route path="/dashboard" element={<Dashboard />} />
      </Routes>
    </Suspense>
  );
}
```

```text
懒加载的价值：
1. 减小首屏 bundle，加快首次加载
2. 未访问的路由不下载
3. 配合 Suspense 显示加载态
```

## Prefetch

Prefetch 是在浏览器空闲时预取「未来可能访问」的资源（如悬停链接、下一路由），降低切换延迟。Vue Router 的 lazy 支持 prefetch，webpack 也有 prefetch 魔法注释。

```js
// webpack prefetch：空闲时预取
import(/* webpackPrefetch: true */ './views/NextPage.vue');
```

```js
// Vite 构建层预取（rollup）
import(/* @vite-ignore */ './views/NextPage.vue');
```

```html
<!-- 原生 prefetch：低优先级预取 -->
<link rel="prefetch" href="/chunks/about.js" as="script" />
```

```text
Prefetch 特点：
1. 低优先级，浏览器空闲时加载
2. 用于「可能」用到的资源
3. 适合下一页、悬停触发的资源
```

## Preload

Preload 是「当前页面」需要的高优先级资源预加载，告诉浏览器「尽快加载这个资源」，用于首屏关键资源。

```html
<!-- 原生 preload：高优先级加载当前页关键资源 -->
<link rel="preload" href="/critical.js" as="script" />
<link rel="preload" href="/font.woff2" as="font" type="font/woff2" crossorigin />
```

```text
Preload vs Prefetch：
Preload —— 当前页需要，高优先级，立即加载
Prefetch —— 未来可能需要，低优先级，空闲加载
首屏关键资源用 preload，下一页资源用 prefetch。
```

```js
// 路由切换前预加载组件数据（React Router loader）
<Route
  path="/dashboard"
  element={<Dashboard />}
  loader={async () => {
    const data = await fetchDashboard();
    return data; // 进入路由前预取数据
  }}
/>
```

## Code Splitting

代码分割（Code Splitting）把应用拆成多个 chunk，按需加载。路由懒加载是代码分割最常见的应用，此外还有 vendor 分包、公共依赖提取等。

```js
// Vite/Rollup 手动分包（vite.config.js）
export default {
  build: {
    rollupOptions: {
      output: {
        manualChunks: {
          // 把第三方库拆成独立 chunk
          vendor: ['react', 'react-dom'],
          antd: ['antd'],
          utils: ['./src/utils'],
        },
      },
    },
  },
};
```

```js
// webpack 提取公共依赖
optimization: {
  splitChunks: {
    chunks: 'all',
    cacheGroups: {
      vendor: {
        test: /[\\/]node_modules[\\/]/,
        name: 'vendors',
        priority: 10,
      },
    },
  },
}
```

```text
代码分割策略：
1. 路由级分割 —— 每个路由一个 chunk（懒加载）
2. 第三方库分包 —— vendor 独立，利于缓存
3. 公共模块提取 —— 复用代码单独成 chunk
4. 动态 import 函数 —— 任意逻辑按需加载
```

## 应用场景实战

### 场景一：路由懒加载 + Suspense 加载态

```js
import { lazy, Suspense } from 'react';
import { Routes, Route } from 'react-router-dom';

const Home = lazy(() => import('./pages/Home'));
const UserList = lazy(() => import('./pages/UserList'));
const UserDetail = lazy(() => import('./pages/UserDetail'));

function App() {
  return (
    <Suspense fallback={<PageLoading />}>
      <Routes>
        <Route path="/" element={<Home />} />
        <Route path="/users" element={<UserList />} />
        <Route path="/users/:id" element={<UserDetail />} />
      </Routes>
    </Suspense>
  );
}
```

### 场景二：悬停预取路由资源

```js
// 鼠标悬停导航链接时预取对应 chunk
function NavLink({ to, children }) {
  const prefetch = () => import(`./pages/${to}.jsx`);
  return (
    <Link to={to} onMouseEnter={prefetch}>
      {children}
    </Link>
  );
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. 路由组件一律懒加载，首屏只加载必要代码
2. 第三方库单独分包，提升缓存命中率
3. 首屏关键资源用 preload，下一页用 prefetch
4. Suspense 提供友好加载态，避免白屏
5. 懒加载粒度适中，过细会导致请求过多

### 踩坑记录

```text
坑 1：懒加载组件未包 Suspense
结论：React 懒加载组件渲染报错/白屏。
原因：React.lazy 需要 Suspense 边界。
解法：用 Suspense 包裹并提供 fallback。

坑 2：所有路由都懒加载导致请求风暴
结论：频繁切换路由时加载延迟明显。
原因：chunk 过碎，每次切换都发请求。
解法：适度合并小路由，重要路由可 preload。

坑 3：vendor 未分包导致缓存失效
结论：业务代码改动后，第三方库也重新下载。
原因：vendor 和业务代码打包在一起。
解法：manualChunks/splitChunks 拆出 vendor。

坑 4：preload 滥用
结论：首屏反而变慢。
原因：preload 优先级高，过多会抢占带宽。
解法：只 preload 真正关键的首屏资源。

坑 5：动态 import 路径写错
结论：构建报错或 chunk 加载 404。
原因：动态 import 路径需静态可分析。
解法：用字面量路径，避免完全动态的变量拼接。
```

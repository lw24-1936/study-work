## 概述

定位和层叠是 CSS 里最「反直觉」的部分——absolute 的基准到底是谁、z-index 为什么设了不生效、弹窗为什么被盖住。这篇笔记深入两个底层概念：包含块（containing block，定位的基准）和层叠上下文（stacking context，z-index 比较的边界），这是解开所有「定位/层叠玄学」的钥匙。

```text
两个核心概念：
containing block（包含块）—— 决定 absolute/fixed 元素相对谁定位
stacking context（层叠上下文）—— 决定 z-index 在什么范围内比较
```

## containing block 包含块

包含块是「定位元素计算位置的基准」，不同定位方式的包含块不同：

```text
定位元素的包含块：
static/relative —— 包含块是「最近的块级祖先」的内容区
absolute —— 包含块是「最近的非 static 定位祖先」的 padding 盒
fixed —— 包含块是「视口」（除非祖先有 transform/filter 等）
sticky —— 包含块是「最近的滚动容器」
```

```text
包含块的确定规则（关键）：
1. 默认（static/relative）—— 最近的块级祖先
2. absolute —— 最近的非 static 定位祖先（position: relative/absolute/fixed/sticky）
3. fixed —— 视口，但祖先有 transform/filter/perspective 时改相对该祖先
4. sticky —— 最近的滚动容器（overflow 非 visible 的祖先）
```

```html
<style>
  .grandparent { position: relative; }
  .parent { /* 没设定位 */ }
  .child { position: absolute; top: 0; }
</style>
<div class="grandparent">
  <div class="parent">
    <div class="child">我相对谁定位？</div>
  </div>
</div>
<!-- child 相对 grandparent 定位（parent 不是定位元素，往上找到 grandparent） -->
```

```text
百分比定位的基准：
top/left 的百分比是相对「包含块的宽高」，
不是相对父元素（除非父元素就是包含块）。
```

```text
transform 对 fixed 的影响（重要坑）：
祖先元素有 transform/filter/perspective/backdrop-filter 时，
fixed 的包含块变成该祖先，而不是视口。
表现为「fixed 元素跟着祖先滚动」。
```

## top、right、bottom、left 偏移

这四个属性控制定位元素的偏移量：

```css
.absolute-box {
  position: absolute;
  top: 0;      /* 距包含块顶部 0 */
  left: 20px;  /* 距包含块左侧 20px */
}
```

```text
偏移属性：
top/right/bottom/left —— 相对包含块的偏移
单位：px、%、vw/vh 等
百分比 —— 相对包含块的宽（left/right）或高（top/bottom）
```

```text
偏移属性的特殊用法：
1. 居中 —— top: 50% + translate(-50%, -50%)
2. 拉伸 —— top: 0 + bottom: 0（不设 height，元素被上下拉伸）
3. 只设一个方向 —— 只设 top 不设 left，水平位置保持
```

```css
/* 拉伸：上下左右都 0，元素铺满包含块 */
.overlay {
  position: absolute;
  top: 0; right: 0; bottom: 0; left: 0;
  background: rgba(0,0,0,0.5);
}
```

## stacking context 层叠上下文

层叠上下文是「z-index 比较的边界」，理解它是解开所有 z-index 问题的关键。

```text
层叠上下文（Stacking Context）：
一个独立的三维层叠空间。元素属于某个层叠上下文，
它的 z-index 只在「当前层叠上下文内」和其他兄弟比较，
不能跨出边界和外部的元素比较。
```

```text
创建层叠上下文的常见方式：
1. 根元素 <html>（最外层上下文）
2. position 非 static + z-index 非 auto
3. position: fixed / sticky
4. flex/grid 子元素 + z-index 非 auto
5. transform / filter / opacity < 1 / will-change
6. isolation: isolate（显式创建）
```

```html
<style>
  .parent { position: relative; z-index: 1; }
  .child { position: absolute; z-index: 9999; }
  .sibling { position: relative; z-index: 2; }
</style>
<div class="parent">
  <div class="child">z-index 9999，但盖不过 sibling</div>
</div>
<div class="sibling">z-index 2，反而在上面</div>
<!-- child 的 9999 只在 parent 内部比较，parent 整体是 1，
     sibling 是 2 > 1，所以 sibling 在上层 -->
```

```text
层叠顺序（同一上下文内的绘制顺序，从下到上）：
1. 背景和边框
2. 负 z-index
3. 块级元素
4. 浮动元素
5. 行内元素
6. z-index: 0 / auto
7. 正 z-index
```

## z-index 深入

z-index 控制层叠顺序，但它的行为受层叠上下文约束。

```text
z-index 生效的条件：
元素必须是定位元素（position 非 static）或 flex/grid 子项。
static 元素的 z-index 无效。
```

```text
z-index 的比较规则：
1. 同层叠上下文内 —— 直接比 z-index 数值，大的在上
2. 不同层叠上下文 —— 比「各自所属上下文」的 z-index
3. 负 z-index —— 在背景之上、正常内容之下
```

```text
z-index 的管理实践：
用「分层」思想，给不同的 UI 层级分配 z-index 区间：
1. 内容层 —— 1~9
2. 下拉/悬浮层 —— 10~99
3. 遮罩层 —— 100~999
4. 弹窗层 —— 1000~9999
5. 全局提示层 —— 10000+

避免随意设 9999 这类魔法数字，用 CSS 变量统一管理。
```

```css
:root {
  --z-dropdown: 10;
  --z-sticky: 100;
  --z-modal: 1000;
  --z-toast: 10000;
}
```

## fixed、sticky、absolute 的层叠行为

三种脱离文档流的定位，在层叠上下文里的行为：

```text
fixed —— 相对视口（或 transform 祖先），自身创建层叠上下文
sticky —— 相对滚动容器，自身创建层叠上下文
absolute —— 相对定位祖先，配 z-index 才创建层叠上下文
```

```text
关键理解：
1. fixed/sticky 自动创建层叠上下文（它们的 z-index 独立生效）
2. absolute 需要 z-index 非 auto 才创建层叠上下文
3. 弹窗（fixed）被盖住，通常是「被低 z-index 的父上下文限制」
```

```text
弹窗 z-index 失效的排查：
1. 弹窗是否被放在一个低 z-index 的祖先里（被「锁」在上下文中）
2. 祖先是否有 transform/opacity（创建了层叠上下文）
3. 解决方案：把弹窗移到 body 层级（React Portal），避免被祖先上下文限制
```

## 应用场景实战

### 场景一：全屏遮罩 + 弹窗

```css
.overlay {
  position: fixed;
  top: 0; right: 0; bottom: 0; left: 0;
  background: rgba(0, 0, 0, 0.5);
  z-index: 999;
}
.modal {
  position: fixed;
  top: 50%;
  left: 50%;
  transform: translate(-50%, -50%);
  z-index: 1000;
}
```

### 场景二：z-index 被祖先锁死的问题

```text
问题：弹窗 z-index 设到 99999 还是被别的元素盖住。

原因分析：
弹窗的祖先元素（如一个 transform 的容器）创建了层叠上下文，
弹窗的 z-index 只能在这个上下文内部比较，
盖不过上下文之外更高 z-index 的元素。

解决：
把弹窗渲染到 body 层级（React 用 createPortal），
脱离有层叠上下文的祖先。
```

```jsx
// React Portal：把弹窗渲染到 body，避开祖先层叠上下文
import { createPortal } from 'react-dom';

function Modal({ children }) {
  return createPortal(
    <div className="modal">{children}</div>,
    document.body  // 渲染到 body，脱离祖先的层叠上下文
  );
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. absolute 明确配定位祖先（父元素 relative）
2. z-index 用 CSS 变量分层管理，不用魔法数字
3. 弹窗用 Portal 渲染到 body，避免被祖先层叠上下文锁住
4. 理解 transform 会改变 fixed 的包含块和创建层叠上下文
5. 排查 z-index 先看「层叠上下文」，再调数值

### 踩坑记录

```text
坑 1：absolute 相对错误元素定位
结论：absolute 元素跑到视口角落，而不是父元素内。
原因：父元素没设定位，absolute 往上找到更远的定位祖先。
解法：给父元素设 position: relative。

坑 2：fixed 元素随祖先滚动
结论：fixed 元素没固定在视口，跟着滚。
原因：祖先有 transform/filter，fixed 改相对该祖先。
解法：把 fixed 元素移出有 transform 的祖先，或改用其他定位。

坑 3：z-index 设到 99999 还是被盖住
结论：弹窗被低 z-index 的元素盖住。
原因：弹窗被锁在低 z-index 祖先的层叠上下文里。
解法：弹窗渲染到 body（Portal），脱离限制。

坑 4：opacity < 1 意外创建层叠上下文
结论：加了 opacity: 0.9 后，子元素的 z-index 行为变了。
原因：opacity < 1 会创建层叠上下文。
解法：理解 opacity/transform/filter 都会创建层叠上下文，注意它们的影响。

坑 5：百分比 top 的基准搞错
结论：top: 50% 不是相对父元素的一半。
原因：百分比 top 相对「包含块」的高度，包含块不一定是父元素。
解法：确认包含块是谁，或改用 transform 居中（相对自身）。
```

## 概述

盒模型（Box Model）是 CSS 布局的基础——每个元素都是一个「盒子」，由内容、内边距、边框、外边距四层组成。理解盒模型，才能准确控制元素尺寸、间距和布局，也才能解释「为什么加了 padding 元素就变宽了」这类问题。

```text
盒模型的四层（从内到外）：
content —— 内容区（文字、图片）
padding —— 内边距（内容到边框）
border  —— 边框
margin  —— 外边距（元素到其他元素）
```

## 盒模型四层：content、padding、border、margin

```css
.box {
  width: 200px;        /* content 宽度 */
  padding: 20px;       /* 内边距 */
  border: 2px solid black;  /* 边框 */
  margin: 10px;        /* 外边距 */
}
```

```text
content（内容区）：
元素的文字、子元素所在区域，由 width/height 决定。

padding（内边距）：
内容到边框之间的空间，背景色会填充 padding 区域。

border（边框）：
元素的边框，可设宽度、样式、颜色。

margin（外边距）：
元素和其他元素之间的空间，透明（不显示背景）。
```

```text
padding 和 margin 的简写（记忆：顺时针上右下左）：
padding: 10px;              /* 四边都是 10px */
padding: 10px 20px;         /* 上下 10，左右 20 */
padding: 10px 20px 30px;    /* 上 10，左右 20，下 30 */
padding: 10px 20px 30px 40px; /* 上 10，右 20，下 30，左 40 */
```

```text
margin 的特殊行为：
1. 外边距合并（margin collapse）—— 相邻元素的上下 margin 会合并取较大值
2. 负 margin —— 让元素反向移动（拉近距离）
3. margin: auto —— 水平居中（左右 auto）
```

## box-sizing 盒模型类型

box-sizing 决定 width/height 是「只含 content」还是「含 padding 和 border」。

```text
box-sizing 的两个取值：
content-box（默认）—— width = content 宽度
                       实际占位 = width + padding + border

border-box —— width = content + padding + border
              实际占位 = width（padding/border 从 width 里扣）
```

```css
.box {
  box-sizing: content-box;  /* 默认 */
  width: 200px;
  padding: 20px;
  /* 实际占位 = 200 + 20*2 = 240px（不含 border） */
}

.box2 {
  box-sizing: border-box;
  width: 200px;
  padding: 20px;
  /* 实际占位 = 200px（content 被压缩到 160px） */
}
```

```text
content-box 的坑：
设 width: 200px + padding: 20px，实际占 240px，
加 padding 元素会「变大」，容易撑破布局。

border-box 的优势：
width 就是最终宽度，加 padding 不改变占位，布局更可控。
```

```css
/* 全局统一 border-box（现代项目的标准做法） */
*,
*::before,
*::after {
  box-sizing: border-box;
}
```

## width、height 与 min/max

width/height 是基础尺寸，min/max 系列限制尺寸范围。

```css
.box {
  width: 100%;        /* 宽度 */
  height: 200px;      /* 高度 */
  min-width: 200px;   /* 最小宽度 */
  max-width: 800px;   /* 最大宽度 */
  min-height: 100px;  /* 最小高度 */
  max-height: 400px;  /* 最大高度 */
}
```

```text
min/max 的用途：
1. max-width 限制元素不会太宽（大屏下文字行太长难读）
2. min-width 保证元素不会太窄（布局不挤坏）
3. 响应式布局常用：width: 100% + max-width: 1200px
```

```css
/* 响应式容器：小屏占满，大屏不超过 1200px */
.container {
  width: 100%;
  max-width: 1200px;
  margin: 0 auto;
}
```

```text
width 的取值：
px —— 固定像素
% —— 相对父元素
vw —— 相对视口宽度
auto —— 自动（块级默认填满，行内按内容）
```

## overflow 溢出

overflow 控制「内容超出元素尺寸」时的表现：

```css
.box {
  overflow: visible;  /* 默认，内容溢出可见 */
  overflow: hidden;   /* 溢出裁剪隐藏 */
  overflow: scroll;   /* 总是显示滚动条 */
  overflow: auto;     /* 溢出时才显示滚动条 */
}
```

```text
overflow 四值：
visible —— 内容溢出可见（默认）
hidden  —— 溢出部分裁剪
scroll  —— 强制滚动条
auto    —— 需要时滚动条
```

```css
/* 单行文字溢出省略号 */
.ellipsis {
  white-space: nowrap;      /* 不换行 */
  overflow: hidden;         /* 裁剪 */
  text-overflow: ellipsis;  /* 省略号 */
}
```

```text
overflow 的副作用：
overflow: hidden 会创建 BFC（块级格式化上下文），
可用于清除浮动、解决 margin 折叠。
```

## 应用场景实战

### 场景一：响应式容器 + 文字省略

```css
/* 响应式容器 */
.container {
  width: 100%;
  max-width: 1200px;
  margin: 0 auto;
  padding: 0 16px;
  box-sizing: border-box;
}

/* 单行省略 */
.title {
  overflow: hidden;
  text-overflow: ellipsis;
  white-space: nowrap;
}

/* 多行省略（2 行） */
.desc {
  display: -webkit-box;
  -webkit-line-clamp: 2;
  -webkit-box-orient: vertical;
  overflow: hidden;
}
```

### 场景二：卡片布局（border-box）

```css
.card {
  box-sizing: border-box;
  width: 300px;
  padding: 20px;
  border: 1px solid #ddd;
  /* 实际占位就是 300px，padding 不撑破布局 */
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. 全局统一 box-sizing: border-box（现代项目标配）
2. 响应式容器用 width: 100% + max-width 限制
3. 文字溢出用 overflow + text-overflow 省略号
4. 水平居中用 margin: 0 auto（块级元素）
5. 理解 margin 合并，避免意外的间距

### 踩坑记录

```text
坑 1：加 padding 元素被撑大
结论：设了 width，加 padding 后元素实际变宽，布局错乱。
原因：默认 content-box，width 不含 padding。
解法：全局 border-box，让 width 含 padding。

坑 2：上下 margin 合并导致间距异常
结论：两个相邻元素的间距比预期小（取了较大值而非相加）。
原因：垂直方向的 margin 会合并（margin collapse）。
解法：用 padding 替代，或触发 BFC（overflow: hidden 等）。

坑 3：height: 100% 不生效
结论：子元素 height: 100% 没有撑满父元素。
原因：百分比高度依赖父元素有明确高度。
解法：父元素设明确 height，或用 flex 布局替代。

坑 4：overflow: hidden 误裁剪了弹窗/下拉
结论：绝对定位的子元素（弹窗）被 overflow: hidden 裁剪。
原因：overflow 裁剪所有溢出内容，包括绝对定位子元素。
解法：弹窗移到 overflow 容器外，或改用其他定位方案。

坑 5：图片底部有空白间隙
结论：图片下方多出几像素空白。
原因：img 是行内元素，默认按基线对齐，下方有行距空间。
解法：img 设 display: block，或 vertical-align: middle。
```

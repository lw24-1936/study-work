## 概述

display 属性决定元素的「显示类型」，是 CSS 最核心的属性之一。它控制元素是块级还是行内、是否参与布局、如何生成盒模型。理解 display 是掌握 CSS 布局的基础。

```text
display 的两大类：
1. 外部显示类型（outer）—— 元素如何参与父元素的布局（block/inline）
2. 内部显示类型（inner）—— 元素内部如何布局（flex/grid）
```

## block 与 inline

### block 块级

```css
div { display: block; }
```

```text
block 的特性：
1. 独占一行（前后换行）
2. 可设 width/height
3. 默认宽度填满父容器
4. 上下 margin/padding 生效

常见 block 元素：div、p、h1-h6、ul、li、section、header
```

### inline 行内

```css
span { display: inline; }
```

```text
inline 的特性：
1. 不换行（多个行内元素排在一行）
2. width/height 不生效（尺寸由内容决定）
3. 上下 margin/padding 不生效（左右生效）
4. 只有水平方向有效

常见 inline 元素：span、a、strong、em、img（特殊的行内替换元素）
```

```text
inline 元素的坑：
1. width/height 设了不生效
2. 上下 padding/margin 不推开间距（视觉重叠）
3. 图片是 inline 但可设宽高（替换元素，特殊）
```

## inline-block

inline-block 结合了块级和行内的特点：

```css
.button { display: inline-block; }
```

```text
inline-block 的特性：
1. 不换行（像 inline，多个排一行）
2. 可设 width/height（像 block）
3. 上下 margin/padding 生效（像 block）

用途：并排的按钮、导航项、卡片（既想排一行又想设尺寸）。
```

```text
inline-block 的坑：
元素间有空白间隙（HTML 里换行/空格被当成一个空格）。
解决：父元素 font-size: 0 再恢复，或用 flex 替代。
```

```text
inline vs inline-block vs block 对比：
| 属性          | inline | inline-block | block |
|---------------|--------|--------------|-------|
| 独占一行      | 否     | 否           | 是    |
| 可设 width    | 否     | 是           | 是    |
| 上下 margin   | 否     | 是           | 是    |
```

## none 隐藏元素

display: none 彻底隐藏元素（不占位）：

```css
.hidden { display: none; }
```

```text
display: none 的特点：
1. 元素完全不渲染，不占空间
2. 从可访问性树移除（屏幕阅读器也读不到）
3. 重新 display 会触发重新渲染

对比其他隐藏方式：
visibility: hidden —— 隐藏但占位（保留空间）
opacity: 0 —— 透明但占位、可交互
```

```text
三种隐藏方式的区别：
| 方式              | 占位 | 可交互 | 读屏器可读 |
|-------------------|------|--------|-----------|
| display: none     | 否   | 否     | 否        |
| visibility:hidden | 是   | 否     | 否        |
| opacity: 0        | 是   | 是     | 是        |
```

## flex 与 grid 布局

display: flex 和 display: grid 是现代的两种布局方式：

```css
.container { display: flex; }   /* 一维布局（行或列） */
.container { display: grid; }   /* 二维布局（行列） */
```

```text
flex vs grid 的选择：
flex —— 一维布局，元素在一行或一列排列（导航栏、按钮组）
grid —— 二维布局，行列网格（页面布局、卡片网格）

详见 05.6-Flex 和 05.7-Grid。
```

## table、flow-root、contents

### table

display: table 让元素表现得像表格（历史遗留，用于老式布局）。

```css
.wrapper { display: table; }
.cell { display: table-cell; }
```

```text
display: table 的用途：
1. 兼容老代码（表格布局的 CSS 版本）
2. 垂直居中（table-cell 配 vertical-align，老技巧）

现代布局用 flex/grid 替代，table 已少用。
```

### flow-root

display: flow-root 创建 BFC（块级格式化上下文），用于清除浮动、解决 margin 合并。

```css
.clearfix { display: flow-root; }
```

```text
flow-root 的作用：
1. 创建新的 BFC
2. 包含内部浮动（子元素 float 后父元素不塌陷）
3. 解决外边距合并

对比老式 clearfix（伪元素 + clear），flow-root 更简洁。
```

### contents

display: contents 让元素「消失」，其子元素直接成为父元素的子元素。

```css
.wrapper { display: contents; }
```

```text
display: contents 的用途：
1. 突破嵌套限制（flex/grid 里，让孙子元素直接参与父布局）
2. 去掉无语义的包裹层（不产生盒模型）

注意：display: contents 的元素自身不渲染盒，可访问性有坑
（部分浏览器早期有 bug，屏幕阅读器读不到）。
```

## 应用场景实战

### 场景一：导航栏（flex 替代 inline-block）

```css
/* 老式：inline-block 导航（有间隙问题） */
.nav-item { display: inline-block; }

/* 现代：flex 导航（无间隙，对齐更方便） */
.nav {
  display: flex;
  gap: 16px;
}
```

### 场景二：清除浮动（flow-root）

```css
/* 父元素包含浮动子元素，不塌陷 */
.container {
  display: flow-root;
}
.container .float-left {
  float: left;
}
```

### 场景三：列表项点击区域扩展

```css
/* 用 display: contents 让子元素直接参与 grid 布局 */
.grid {
  display: grid;
  grid-template-columns: 1fr 1fr;
}
.grid > .row {
  display: contents;  /* row 不产生盒，子元素直接进 grid */
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. 布局用 flex/grid，不用 inline-block 和 table
2. 隐藏元素优先 display: none（彻底不渲染）
3. 清除浮动用 flow-root（替代老式 clearfix）
4. 理解 block/inline 的默认行为，避免「设了 width 不生效」
5. inline-block 的间隙问题用 flex 规避

### 踩坑记录

```text
坑 1：inline 元素设 width/height 不生效
结论：span 设了宽度没反应。
原因：inline 元素尺寸由内容决定，width/height 无效。
解法：需要设尺寸改 display: inline-block 或 block。

坑 2：inline-block 元素间有间隙
结论：并排的元素之间有莫名其妙的空白。
原因：HTML 里换行/空格被渲染成空格字符。
解法：父元素 font-size: 0（子元素恢复），或改用 flex。

坑 3：display: none 和 visibility: hidden 混用
结论：以为隐藏了但元素还占位，或反之。
原因：display:none 不占位，visibility:hidden 占位。
解法：要彻底隐藏用 display:none，要保留占位用 visibility:hidden。

坑 4：display: contents 可访问性 bug
结论：屏幕阅读器读不到 display: contents 元素的内容。
原因：部分浏览器对 display: contents 的可访问性树处理有 bug。
解法：谨慎使用，检查目标浏览器的可访问性支持。

坑 5：浮动导致父元素塌陷
结论：子元素 float 后，父元素高度为 0。
原因：浮动元素脱离文档流，父元素无法包裹。
解法：父元素 display: flow-root（或 overflow: hidden）。
```

## 概述

CSS（Cascading Style Sheets）的「C」是 Cascading（层叠）——这是理解 CSS 一切行为的关键。同一元素可能被多条规则命中，最终用哪条，由「层叠 + 优先级 + 继承」这套规则决定。这篇笔记讲 CSS 的核心机制：语法、层叠、优先级、继承，这些是排查「样式为什么没生效」的基础。

```text
CSS 的三个核心机制：
1. 层叠（Cascade）—— 多条规则冲突时，按来源和顺序决定
2. 优先级（Specificity）—— 选择器越具体，优先级越高
3. 继承（Inheritance）—— 部分属性自动传给子元素
```

## CSS 语法：Syntax、Selector、Declaration、Property、Value

CSS 由规则（Rule）组成，每条规则是「选择器 + 声明块」：

```css
selector {
  property: value;
  /* 选择器 { 属性: 值; } */
}
```

```css
/* 完整示例 */
h1 {
  color: red;
  font-size: 24px;
}
```

```text
CSS 语法的四要素：
Selector（选择器）—— 选中要样式的元素（h1）
Declaration（声明）—— 一条属性设置（color: red）
Property（属性）—— 要设置什么（color）
Value（值）—— 设置成什么（red）
```

```text
声明块的结构：
{
  属性1: 值1;
  属性2: 值2;
}
多条声明用分号分隔，最后一条分号可省略（但建议写）。
```

## Cascade 层叠

层叠是 CSS 解决「多个规则命中同一元素」的机制，按顺序决定「谁赢」。

```text
层叠的优先级顺序（从低到高）：
1. 浏览器默认样式（User Agent）
2. 用户自定义样式
3. 作者样式（你写的 CSS）
4. 作者样式 + !important
5. 用户样式 + !important
6. 浏览器 + !important（过渡值）
```

```text
层叠的关键规则：
1. 来源 —— 作者样式 > 用户样式 > 浏览器默认
2. 重要性 —— !important 提升优先级
3. 层叠层（@layer）—— 后声明的 layer 优先（现代特性）
4. 顺序 —— 同优先级下，后写的覆盖先写的
```

```css
/* 同优先级，后写的赢 */
p { color: red; }
p { color: blue; }  /* 最终蓝色 */
```

```text
@layer 层叠层（现代 CSS）：
可以显式控制样式的层级顺序，解决大型项目的样式冲突。
```

## Specificity 优先级

当层叠来源相同时，用「优先级（Specificity）」比较选择器的「具体程度」。

```text
优先级的计算（四位数，从左到右比较）：
内联样式（style 属性）—— 1,0,0,0
ID 选择器 —— 0,1,0,0
类/属性/伪类 —— 0,0,1,0
元素/伪元素 —— 0,0,0,1

通配符 *、组合器（> + ~）、:where() —— 0（不计入）
```

```css
/* 优先级示例 */
p                       /* 0,0,0,1 */
.title                  /* 0,0,1,0 */
#main .title            /* 0,1,1,0 */
<div style="...">       /* 1,0,0,0 */
```

```text
优先级比较规则：
从左到右逐位比较，第一位大的赢；第一位相同看第二位，依此类推。
```

```text
优先级速记（记忆）：
!important > 内联 > ID > 类/伪类/属性 > 元素/伪元素

特殊：
1. :where() 优先级为 0（设计用来写低优先级的基础样式）
2. :is() / :not() 取「参数里优先级最高」的
3. 内联样式优先于任何选择器（除 !important）
```

## Inheritance 继承

部分 CSS 属性会自动继承给子元素，部分不会。

```text
可继承的属性（大多与「文字」相关）：
color、font-*（font-size/family/weight）、
text-align、line-height、visibility、cursor 等

不可继承的属性（大多与「盒子」相关）：
width/height、margin、padding、border、background、
position、display 等
```

```html
<style>
  body { color: blue; }  /* color 可继承 */
</style>
<body>
  <p>这段文字是蓝色</p>  <!-- 继承了 body 的 color -->
</body>
```

```text
继承的控制：
inherit —— 强制继承（即使本来不继承）
initial —— 设为初始值（不继承）
unset   —— 可继承属性继承，不可继承属性设初始值
```

```css
button {
  /* 按钮默认不继承字体，强制继承 */
  font: inherit;
}
```

```text
继承的坑：
表单控件（input/button/select）默认不继承字体，
要统一字体需显式 font: inherit。
```

## Initial、Unset 与 Revert

这三个关键字用于「重置」属性到某个基准状态：

```text
initial —— 属性在 CSS 规范里的「初始值」
            color 的 initial 是 black，display 的 initial 是 inline

unset   —— 「可继承属性」重置为继承，「不可继承属性」重置为初始值
           （等于 initial 和 inherit 的结合）

revert  —— 回滚到「上一条来源」的值
           作者样式里 revert 会回滚到浏览器默认样式
```

```css
.example {
  color: initial;   /* 黑色（初始值） */
  color: unset;     /* 继承父级（可继承属性） */
  color: revert;    /* 回滚到浏览器默认 */
}
```

```text
三者的区别（记忆）：
initial —— 规范定义的初始值
unset   —— 继承或初始值（自动选择）
revert  —— 回滚到上一条来源（如浏览器默认）
```

## !important

!important 强制提升一条声明的优先级，覆盖其他所有规则（同来源内）。

```css
.error {
  color: red !important;  /* 强制红色，覆盖其他 color 声明 */
}
```

```text
!important 的优先级：
!important 声明的优先级高于普通声明，但多个 !important 之间仍按
「来源 + 优先级」比较。

优先级排序（简化）：
浏览器默认 < 用户 < 作者 < 作者 !important < 用户 !important
```

```text
!important 的正确用法（少用）：
1. 覆盖第三方库的样式（无法改源码时）
2. 工具类（utility class）覆盖（如 Tailwind 的 ! 前缀）
3. 临时救急（后续应重构掉）

滥用 !important 会让样式层级混乱，难以维护。
```

## 应用场景实战

### 场景一：排查「样式不生效」

```text
样式不生效的排查顺序：
1. 选择器是否选中了元素（拼写、结构是否匹配）
2. 是否被更高优先级的规则覆盖（DevTools 里看被划掉的样式）
3. 属性是否可继承/是否被其他来源覆盖
4. 是否有 !important 干扰
5. 浏览器是否支持该属性（兼容性）

用 DevTools 的「Computed」面板看最终生效的样式和来源。
```

### 场景二：统一表单控件字体

```css
/* 表单控件默认不继承字体，统一重置 */
button,
input,
select,
textarea {
  font: inherit;
  color: inherit;
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. 用低优先级选择器（类优先，避免 ID 和深层嵌套）
2. 优先靠「顺序」而非「!important」解决冲突
3. 表单控件显式 font: inherit 统一字体
4. 理解继承和层叠，用 DevTools Computed 面板排查
5. 大型项目用 @layer 管理样式层级

### 踩坑记录

```text
坑 1：滥用 ID 选择器导致优先级过高
结论：类选择器覆盖不了 ID 样式，只能层层加 !important。
原因：ID 优先级（0,1,0,0）远高于类（0,0,1,0）。
解法：优先用类选择器，ID 只用于 JS 定位。

坑 2：用 !important 压 !important 导致层级失控
结论：样式越来越难改，一个样式要配好几个 !important。
原因：!important 互相压，层级彻底混乱。
解法：重构选择器，用更具体的类而非 !important。

坑 3：表单控件字体和页面不一致
结论：input/button 字体和 body 不一样。
原因：表单控件默认不继承 font。
解法：button/input/select/textarea 加 font: inherit。

坑 4：分不清 initial 和 inherit
结论：重置样式结果和预期不符。
原因：initial 是「初始值」，inherit 是「继承值」，两者不同。
解法：要继承用 inherit，要初始值用 initial，要自动用 unset。

坑 5：同优先级靠顺序覆盖却没生效
结论：后写的规则没覆盖前面的。
原因：两条规则优先级不同，顺序只在同优先级时生效。
解法：比较两条规则的具体优先级（DevTools 显示优先级）。
```

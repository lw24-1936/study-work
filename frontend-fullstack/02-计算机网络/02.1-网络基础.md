## 概述

计算机网络解决的是「数据如何在多台机器之间传输」。前端工程师不需要造网络设备，但每个页面请求都跑在网络上——DNS 解析、TCP 连接、IP 路由、MAC 寻址，一环卡住页面就慢。这篇笔记从分层模型讲起，把每层的关键概念（MAC、IP、路由、NAT、DHCP、ICMP）串成一条「数据包从浏览器到服务器的完整旅程」，后续 TCP/HTTP 等篇章都在这个骨架上展开。

```text
一个数据包从浏览器到服务器的旅程（分层视角）：
应用层    —— 浏览器生成 HTTP 请求
传输层    —— TCP 分段，加端口号
网络层    —— IP 寻址，加源/目标 IP
链路层    —— MAC 寻址，加源/目标 MAC
物理层    —— 转成电/光信号发出
```

## 网络分层模型：OSI 与 TCP/IP

分层是为了把复杂的网络通信拆解成独立、可替换的模块。两个主流模型：

```text
OSI 七层模型（理论标准）：
7 应用层    Application   —— 为应用提供网络服务
6 表示层    Presentation  —— 数据格式转换、加密、压缩
5 会话层    Session       —— 建立、管理会话
4 传输层    Transport     —— 端到端传输、可靠性
3 网络层    Network       —— 路由、逻辑寻址
2 数据链路层 Data Link     —— 帧、物理寻址（MAC）
1 物理层    Physical      —— 比特流、电/光信号

TCP/IP 四层模型（实际标准）：
4 应用层    —— 对应 OSI 5/6/7 层（HTTP、DNS、TLS、FTP）
3 传输层    —— 对应 OSI 4 层（TCP、UDP）
2 网络层    —— 对应 OSI 3 层（IP、ICMP）
1 网络接口层 —— 对应 OSI 1/2 层（以太网、ARP）
```

```text
为什么记 OSI 还要记 TCP/IP：
OSI 是教学模型，分层清晰但七层在实际中没完全实现（表示层/会话层被并进应用层）。
TCP/IP 是互联网实际使用的协议栈。面试常问两者对应关系。
```

分层的关键价值：每层只关心自己的职责，向上层提供封装好的服务。比如应用层发 HTTP 请求时完全不用知道底层走的是以太网还是 Wi-Fi。

```text
封装与解封装：
发送时，每层向下加自己的头（HTTP 报文 → TCP 段 → IP 包 → 帧）。
接收时，每层向上剥自己的头，最终还原出 HTTP 报文。
```

## 数据链路层：MAC 与 ARP

### MAC

MAC（Media Access Control）地址是网卡的物理地址，48 位，全球唯一（由厂商烧录），用于**同一局域网内**的设备寻址。

```text
MAC 地址格式：00:1A:2B:3C:4D:5E
前 24 位 —— 厂商标识（OUI）
后 24 位 —— 设备序号
```

```text
IP 地址 vs MAC 地址：
IP  —— 逻辑地址，跨网络路由用，会随网络变化
MAC —— 物理地址，局域网内寻址用，网卡出厂固定

类比：IP 是收货地址（可变的逻辑位置），MAC 是身份证号（固定的物理身份）。
```

### ARP

ARP（Address Resolution Protocol）解决「知道对方 IP，怎么找到对方 MAC」的问题——IP 寻址最终要落到 MAC 才能在同一链路里传输。

```text
ARP 工作流程（同一局域网）：
1. 主机 A 要发数据给 IP 192.168.1.2，但不知道它的 MAC
2. A 广播 ARP 请求：「谁是 192.168.1.2？告诉我你的 MAC」
3. 目标机 B 回复：「我是 192.168.1.2，MAC 是 xx:xx:xx」
4. A 缓存这条映射（ARP 缓存），之后直接发
```

```text
ARP 缓存 —— arp -a 查看。缓存有有效期，避免频繁广播。
ARP 欺骗 —— 攻击者伪装成网关回复 ARP 请求，实现中间人攻击（局域网内）。
```

前端视角：ARP 是局域网内部机制，对跨网络的请求，浏览器侧感知不到，但理解它有助于排查「同一 Wi-Fi 下设备互相访问」的问题。

## 网络层：IP、IPv4 与 IPv6

### IP

IP（Internet Protocol）负责跨网络的逻辑寻址和路由。它是**无连接、尽力而为（best-effort）**的协议——不保证送达、不保证顺序，可靠性交给上层 TCP。

```text
IP 的职责：
1. 寻址 —— 给每台设备一个逻辑地址（IP 地址）
2. 分片 —— 大包拆小以适应链路 MTU
3. 路由 —— 决定包从哪条路径走
```

### IPv4

IPv4 是 32 位地址，点分十进制表示，理论上约 43 亿个地址（已耗尽）。

```text
IPv4 地址：192.168.1.100
每段 8 位，共 4 段，取值范围 0-255
```

IPv4 地址分类（保留网段是内网常客）：

```text
私有地址（内网用，公网不可路由）：
10.0.0.0/8         —— 10.x.x.x
172.16.0.0/12      —— 172.16.x.x ~ 172.31.x.x
192.168.0.0/16     —— 192.168.x.x（家用路由器最常见）

其他特殊地址：
127.0.0.1     —— 回环地址（localhost）
169.254.x.x   —— 链路本地地址（DHCP 失败时自动分配）
```

### IPv6

IPv6 是 128 位地址，解决 IPv4 地址枯竭问题，用冒号十六进制表示。

```text
IPv6 地址：2001:0db8:85a3:0000:0000:8a2e:0370:7334
简化写法：2001:db8:85a3::8a2e:370:7334（前导零省略，连续零用 :: 表示）
```

```text
IPv4 vs IPv6：
地址长度 —— 32 位 vs 128 位
地址数量 —— 43 亿 vs 约 3.4×10^38（基本无限）
表示法   —— 点分十进制 vs 冒号十六进制
NAT      —— IPv4 靠 NAT 续命；IPv6 每设备都有公网地址，不再需要 NAT
```

前端视角：IPv6 对前端的影响主要是「网络环境」，企业内网、云主机、CDN 都逐步支持 IPv6。代码层面遇到 IP 解析（如埋点上报、反爬）要兼容两种格式。

## 子网划分

子网（Subnet）把一个 IP 网络再划分成更小的逻辑网络，配合子网掩码使用。

```text
子网掩码（Subnet Mask）：
255.255.255.0  = /24  —— 前 24 位是网络位，后 8 位是主机位
192.168.1.0/24      —— 网络地址 192.168.1.0，可用主机 192.168.1.1 ~ 192.168.1.254
```

```text
CIDR 表示法：
IP/前缀长度，如 192.168.1.100/24
/24 表示子网掩码前 24 位为 1。
```

```text
子网划分的作用：
1. 隔离广播域 —— 一个子网的广播不会泛滥到另一个子网
2. 安全管理 —— 不同部门/服务放不同子网，用 ACL 隔离
3. 节省地址 —— 按需分配主机位数
```

```text
网络地址 vs 广播地址：
192.168.1.0   —— 网络地址（主机位全 0，标识子网本身）
192.168.1.255 —— 广播地址（主机位全 1，发给子网内所有主机）
这两个不能分配给设备。
```

## 路由

路由（Routing）是「数据包怎么从一个网络到另一个网络」的寻路过程，由路由器完成。

```text
路由的核心是路由表（Routing Table）：
每个路由器维护一张表，记录「目标网络 → 下一跳 → 出口」。
收到包后查表，决定从哪个接口转发出去。
```

```text
路由类型：
默认路由（default route）—— 0.0.0.0/0，匹配所有「不在表里」的目标，指向网关
直连路由 —— 路由器直连的网络
静态路由 —— 手动配置
动态路由 —— 路由协议自动学习（OSPF、BGP）
```

```text
一次跨网络通信的路由过程（浏览器访问公网服务器）：
1. 浏览器（192.168.1.100）判断目标 IP 不在本子网
2. 走默认路由，发给网关（路由器 192.168.1.1）
3. 路由器查路由表，逐跳转发到目标网络
4. 沿途每跳的 MAC 地址都在变，但源/目标 IP 始终不变
```

```text
查看路由：traceroute/tracert 命令能看到包经过的每一跳。
```

## NAT

NAT（Network Address Translation，网络地址转换）把私有地址转换成公网地址，是 IPv4 地址枯竭的「续命」方案，也是家用路由器/企业出口的标配。

```text
NAT 解决的问题：
内网设备用私有 IP（192.168.x.x），要访问公网就必须在出口
把私有 IP 换成公网 IP。多台内网设备共用一个公网 IP。
```

```text
NAT 类型：
静态 NAT —— 一对一映射（一个内网 IP 固定映射一个公网 IP）
动态 NAT —— 地址池动态分配
NAPT/PAT（端口复用）—— 多内网 IP 共用一个公网 IP，靠端口区分（家庭/企业最常见）
```

```text
NAT 对前端的直接影响：
1. 端口转发 —— 想从公网访问内网服务，需在路由器配「公网端口 → 内网 IP:端口」映射
2. NAT 穿透 —— 内网设备没有独立公网 IP，P2P/WebRTC 直连困难，需要 STUN/TURN 辅助
3. 排查「本地能访问，外网访问不了」—— 往往是 NAT/端口转发没配
```

## DHCP

DHCP（Dynamic Host Configuration Protocol）自动给设备分配 IP 地址、子网掩码、网关、DNS。

```text
DHCP 四步握手（DORA）：
Discover —— 客户端广播「我要 IP」
Offer    —— 服务器回复「给你 192.168.1.100」
Request  —— 客户端确认「我就要这个」
ACK      —— 服务器确认，租约生效
```

```text
DHCP 分配的内容：
IP 地址、子网掩码、默认网关、DNS 服务器、租约时间
```

```text
前端相关：
1. DHCP 有租约期，IP 可能变 —— 依赖固定 IP 的服务要配静态 IP 或 DHCP 保留
2. DHCP 失败会拿到 169.254.x.x 链路本地地址 —— 表现为「能连 Wi-Fi 但上不了网」
```

## ICMP

ICMP（Internet Control Message Protocol）是网络层的控制报文协议，用于诊断和错误报告，最著名的应用是 ping 和 traceroute。

```text
ICMP 常见用途：
ping    —— 发 Echo Request，对方回 Echo Reply，测连通性和延迟
traceroute —— 通过 TTL 递增探测路径上的每一跳
错误报告 —— 目标不可达（Destination Unreachable）、超时（Time Exceeded）
```

```text
ping 的工作原理：
1. 发 ICMP Echo Request 到目标
2. 目标回 ICMP Echo Reply
3. 计算往返时间（RTT），判断连通性和网络质量
```

```text
前端排查时的 ICMP 使用：
1. ping 域名/IP —— 判断网络通不通、丢包率
2. 但要注意：很多服务器/防火墙禁 ping（ICMP 被拦），ping 不通不代表服务不可用
3. 前端性能里，RTT 是连接延迟的底层指标，影响 TCP 握手和页面加载
```

## 应用场景实战

### 场景一：排查「浏览器打不开网站」

从网络基础视角分层排查：

```bash
# 1. DNS 是否解析成功（应用层）
nslookup example.com
# 返回 IP 说明 DNS 正常，报错说明 DNS 问题

# 2. 网络是否通（网络层，ICMP）
ping 93.184.216.34
# 通：网络可达；不通：可能防火墙禁 ping 或网络断了

# 3. 端口是否开放（传输层）
curl -v http://93.184.216.34:80
# 能连上端口说明服务可达

# 4. 检查本机 IP 配置（DHCP 是否正常）
ip addr    # Linux / WSL
ipconfig   # Windows
# 拿到 169.254.x.x 说明 DHCP 失败，拿不到有效 IP
```

### 场景二：局域网内让同事访问本机开发服务

```text
问题：你在 192.168.1.100 上跑 dev server（localhost:3000），
同事在 192.168.1.101 上访问 http://192.168.1.100:3000 失败。

排查链路（局域网内，纯链路层 + 传输层）：
1. dev server 是否监听 0.0.0.0 而不是 127.0.0.1（只监听 127.0.0.1 局域网访问不到）
2. 本机防火墙是否放行 3000 端口
3. 两台机器是否在同一子网（都是 192.168.1.x）

解决：
vite --host 0.0.0.0   # 让 dev server 监听所有网卡
```

## 最佳实践与踩坑记录

### 最佳实践

1. 排查网络问题按「分层」从下往上：物理链路 → 链路层（ARP）→ 网络层（IP/路由/ICMP）→ 传输层（端口）→ 应用层（DNS/HTTP）
2. 内网服务监听 0.0.0.0 而非 127.0.0.1，才能被局域网其他设备访问
3. 依赖固定 IP 的服务配 DHCP 保留或静态 IP，避免租约到期 IP 漂移
4. 部署到公网的服务，NAT/端口转发和安全组要同步配置，缺一环就访问不通
5. 理解私有地址段（10/172.16/192.168），排查时先判断目标是内网还是公网

### 踩坑记录

```text
坑 1：ping 不通就断定服务挂了
结论：ping 不通不等于服务不可用，可能只是防火墙禁 ICMP。
原因：ICMP 常被安全策略关闭，HTTP 端口其实是通的。
解法：用 curl 测实际服务端口，ping 只作为网络连通性参考。

坑 2：dev server 只监听 127.0.0.1，局域网访问不了
结论：localhost 能访问，换 IP 就拒绝连接。
原因：127.0.0.1 只绑定回环接口，不监听对外网卡。
解法：启动加 --host 0.0.0.0（vite/webpack-dev-server 都有此参数）。

坑 3：拿到 169.254.x.x 地址上不了网
结论：Wi-Fi 连上了但无法访问任何网站。
原因：DHCP 分配失败，系统回退到链路本地地址（169.254.x.x），没有有效网关。
解法：重启路由器/检查 DHCP 服务，或手动配静态 IP。

坑 4：ARP 缓存污染导致局域网访问异常
结论：局域网内访问某台机器时断时续、或访问到错误设备。
原因：ARP 缓存被欺骗或过期信息未刷新，MAC 映射错误。
解法：清 ARP 缓存（arp -d），排查局域网是否有 ARP 欺骗。

坑 5：内网部署用公网 IP 段导致路由黑洞
结论：服务配了不属于内网的 IP，无法被正确路由。
原因：私网里用了公网地址段，路由表无法处理。
解法：内网服务用私有地址段（10/172.16/192.168），出口靠 NAT。
```

## 概述

CSS 单位决定尺寸的「基准」，分绝对单位（px）和相对单位（%、em、rem、视口单位）。选对单位是响应式布局和可维护性的基础——用 px 写死尺寸，响应式就难做；用相对单位，布局才能灵活伸缩。

```text
单位的分类：
绝对单位 —— px（固定，不随环境变化）
相对单位 —— %（相对父）、em（相对自身字号）、rem（相对根字号）、
            vw/vh（相对视口）、ch/ex（相对字体度量）
```

## 绝对单位：px

px（像素）是最常用的绝对单位，固定尺寸，不随环境变化。

```css
.box {
  width: 200px;  /* 固定 200 像素 */
}
```

```text
px 的特点：
1. 固定 —— 任何设备上都是 200px（逻辑像素）
2. 精确 —— 适合边框、精确尺寸
3. 不灵活 —— 不能随环境缩放（响应式布局里少用）
```

```text
px 的适用场景：
1. 边框、阴影（1px 边框不需要响应式）
2. 图标、装饰的精确尺寸
3. 不适合：布局尺寸、字号（用相对单位更好）
```

```text
逻辑像素 vs 物理像素（理解）：
CSS 的 px 是「逻辑像素」，在 Retina 屏上 1px 可能对应 2 个物理像素。
浏览器自动处理缩放，开发者用逻辑 px 思考即可。
```

## 相对单位：%、em、rem

### % 百分比

% 相对「父元素」的对应属性：

```css
.child {
  width: 50%;  /* 父元素宽度的一半 */
}
```

```text
% 的基准：
width: 50% —— 父元素 width 的一半
height: 50% —— 父元素 height 的一半（父元素要有明确高度）
font-size: 150% —— 父元素 font-size 的 1.5 倍
```

```text
% 的坑：
height 百分比要求父元素有明确高度，否则不生效。
```

### em

em 相对「当前元素」的 font-size：

```css
.parent {
  font-size: 16px;
}
.child {
  font-size: 1.5em;  /* 16 * 1.5 = 24px */
  padding: 1em;      /* 24 * 1 = 24px（相对自身字号） */
}
```

```text
em 的特点：
1. 相对自身 font-size
2. 会「累积」—— 嵌套的 em 逐层相乘（1.5em 里的 1.5em = 2.25 倍）
```

```text
em 的坑：
嵌套元素用 em 会累积放大/缩小，难以预测。
例如 li 里套 li，每层 1.2em 会指数级变化。
```

### rem

rem 相对「根元素（html）」的 font-size：

```css
html {
  font-size: 16px;  /* 根字号，1rem = 16px */
}
.box {
  font-size: 1.5rem;   /* 24px */
  padding: 1rem;       /* 16px */
}
```

```text
rem 的特点：
1. 相对根元素字号（全局统一基准）
2. 不累积 —— 嵌套不影响
3. 适合做全局尺寸（字号、间距）
```

```text
em vs rem 的选择：
em —— 相对自身，适合「组件内部按比例缩放」（如按钮 padding 随字号）
rem —— 相对根，适合「全局统一尺寸」（如整体字号、间距）

实践：全局布局/字号用 rem，组件内部比例用 em。
```

```text
rem 的响应式技巧：
改变 html 的 font-size，所有 rem 尺寸整体缩放。
（配合媒体查询实现整体缩放，但现代更推荐直接写 rem）
```

## 视口单位：vw、vh 及动态变体

视口单位相对「浏览器视口」的尺寸：

```css
.hero {
  width: 100vw;    /* 视口宽度的 100% */
  height: 50vh;    /* 视口高度的 50% */
}
```

```text
视口单位：
vw —— 视口宽度的 1%
vh —— 视口高度的 1%
vmin —— 视口宽高中较小者的 1%
vmax —— 视口宽高中较大者的 1%
```

### svh、lvh、dvh（动态视口单位）

移动端浏览器地址栏收起/展开会改变视口高度，传统 vh 不准确，动态单位解决这个问题：

```text
移动端地址栏的三种状态：
大视口（Large）—— 地址栏收起，视口最大
小视口（Small）—— 地址栏展开，视口最小
动态视口（Dynamic）—— 随地址栏实时变化

对应单位：
svh —— 小视口高度（地址栏展开时）
lvh —— 大视口高度（地址栏收起时）
dvh —— 动态视口高度（实时跟随，推荐）
```

```css
.hero {
  height: 100vh;    /* 老写法：地址栏变化时可能溢出 */
  height: 100dvh;   /* 推荐：随地址栏动态调整 */
}
```

```text
dvh 的使用：
移动端全屏容器用 100dvh，避免地址栏收起/展开导致的高度跳变。
```

## 其他单位：vmin、vmax、ch、ex

### vmin 与 vmax

```css
.square {
  width: 50vmin;  /* 宽高中较小的 50%（保证是正方形） */
}
```

```text
vmin —— 视口宽高较小者的 1%（横屏时是高度）
vmax —— 视口宽高较大者的 1%（横屏时是宽度）
```

### ch 与 ex

ch 和 ex 相对字体的「度量」：

```text
ch —— 「0」字符的宽度
ex —— 「x」字符的高度

用途：ch 常用于限制文本行宽（可读性），
max-width: 60ch 表示一行最多约 60 个字符。
```

```css
.article {
  max-width: 65ch;  /* 一行约 65 个字符，最佳阅读宽度 */
}
```

## 应用场景实战

### 场景一：响应式字号（clamp + rem）

```css
html {
  font-size: 16px;
}
h1 {
  font-size: clamp(1.5rem, 4vw, 3rem);
  /* 最小 1.5rem，随视口，最大 3rem */
}
p {
  font-size: 1rem;
  line-height: 1.6;  /* 无单位，相对自身字号 */
}
```

### 场景二：移动端全屏容器

```css
.hero {
  height: 100vh;    /* 兜底老浏览器 */
  height: 100dvh;   /* 动态视口，地址栏适配 */
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. 全局尺寸（字号、间距）用 rem，组件内部比例用 em
2. 响应式字号用 clamp，布局用 %/fr/vw
3. 移动端全屏容器用 dvh（替代 vh）
4. 文本阅读宽度用 ch（max-width: 65ch）
5. 固定像素只用在小尺寸（边框、图标）

### 踩坑记录

```text
坑 1：em 嵌套累积导致字号失控
结论：嵌套列表字号逐层放大/缩小，越来越离谱。
原因：em 相对自身字号，嵌套时逐层相乘。
解法：全局字号用 rem（不累积），em 只用于组件内部比例。

坑 2：height: 100% 不生效
结论：子元素设 height: 100% 没撑满。
原因：百分比高度要求父元素有明确高度。
解法：父元素设明确高度，或用 flex/grid、vh 替代。

坑 3：移动端 100vh 溢出（地址栏遮挡）
结论：全屏容器在手机上底部被地址栏遮挡。
原因：100vh 是「大视口」高度，地址栏展开时实际可用高度更小。
解法：用 100dvh（动态视口），或 svh。

坑 4：vw 没考虑滚动条导致横向溢出
结论：width: 100vw 出现横向滚动条。
原因：100vw 包含滚动条宽度，比实际内容区宽。
解法：用 100% 替代 100vw（需要视口宽时才用 vw）。

坑 5：line-height 用 em/px 而非无单位值
结论：line-height 继承时比例失衡。
原因：line-height: 1.6em 会固定成像素，子元素字号变化时行高不跟着变。
解法：line-height 用无单位值（1.6），相对自身字号动态计算。
```

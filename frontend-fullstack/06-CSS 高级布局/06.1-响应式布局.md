## 概述

响应式布局让页面在不同设备（手机、平板、桌面）上都呈现合适的布局。核心思想是「一个页面适配所有屏幕」，而不是为每种设备做单独的版本。实现手段从 Media Query（媒体查询）到 Container Query（容器查询），以及流式布局、响应式字体和图片。

```text
响应式布局的三种实现策略：
1. 流式布局（Fluid）—— 用百分比/fr 等相对单位，布局随容器伸缩
2. 断点适配（Media Query）—— 在特定宽度切换布局
3. 容器查询（Container Query）—— 按组件容器（而非视口）适配
```

## Media Query 与 Breakpoint

### Media Query

Media Query 按「视口条件」应用不同样式，是响应式布局的核心工具。

```css
/* 视口宽度小于等于 600px 时应用 */
@media (max-width: 600px) {
  .container {
    flex-direction: column;
  }
}
```

```text
Media Query 的语法：
@media (条件) { 样式 }
@media (条件1) and (条件2) { 样式 }

常用条件：
min-width / max-width —— 视口宽度
orientation —— 横竖屏
prefers-color-scheme —— 深色模式
prefers-reduced-motion —— 减少动画
```

```text
min-width vs max-width（方向区别）：
min-width: 600px —— 宽度 >= 600px 时生效（「从小往上」，配合 Mobile First）
max-width: 600px —— 宽度 <= 600px 时生效（「从大往下」，配合 Desktop First）
```

### Breakpoint 断点

断点是「布局发生切换的临界宽度」，是响应式设计的基准。

```text
常见断点（参考，非绝对）：
< 600px   —— 手机（小屏）
600-960px —— 平板（中屏）
960-1280px —— 桌面（大屏）
> 1280px  —— 大桌面（超大屏）
```

```text
断点的设计原则：
1. 断点由「内容」决定，不是由「设备型号」决定
   （内容在哪个宽度「挤不下」了，就在那里设断点）
2. 断点尽量少（3-4 个），太多难维护
3. 用变量统一管理断点值
```

## Mobile First 与 Desktop First

这是响应式设计的两种「策略方向」：

```text
Mobile First（移动优先）：
先写移动端样式（基础），再用 min-width 断点逐步增强到大屏。

@media (min-width: 768px) { /* 平板增强 */ }
@media (min-width: 1024px) { /* 桌面增强 */ }
```

```text
Desktop First（桌面优先）：
先写桌面端样式（完整），再用 max-width 断点逐步降级到小屏。

@media (max-width: 1024px) { /* 平板降级 */ }
@media (max-width: 768px) { /* 手机降级 */ }
```

```text
Mobile First vs Desktop First：
Mobile First —— 移动优先，现代主流
  优点：移动端加载快（只加载需要的样式）、移动端体验优先
  缺点：桌面端要额外写增强样式

Desktop First —— 桌面优先，老项目常见
  优点：桌面端开发直观
  缺点：移动端要写大量降级样式

现代推荐 Mobile First（移动流量占比高，性能优先）。
```

## Fluid Layout 流式布局

流式布局用「相对单位」让布局随容器伸缩，不依赖固定像素：

```css
.container {
  width: 100%;          /* 占满父容器 */
  max-width: 1200px;    /* 大屏上限 */
  margin: 0 auto;
}

.column {
  width: 33.33%;        /* 百分比，随容器伸缩 */
  /* 或用 flex/grid 的 fr 单位 */
}
```

```text
流式布局的核心：
1. 用 % / fr / auto 等相对单位，不用固定 px
2. 布局随容器宽度自动伸缩
3. 配合 max-width/min-width 限制极端情况
```

```text
流式 vs 断点：
流式 —— 连续伸缩（任何宽度都适配）
断点 —— 离散切换（特定宽度切换布局）

实践：流式为「底」，断点为「补」。布局用流式，特定宽度需要「改结构」
时才用断点。
```

## Responsive Typography 与 Responsive Image

### Responsive Typography 响应式字体

字体大小也随屏幕缩放：

```css
/* 用 clamp 实现流式字号 */
h1 {
  font-size: clamp(1.5rem, 4vw, 3rem);
  /* 最小 1.5rem，随视口 4vw，最大 3rem */
}
```

```text
响应式字体的方案：
1. clamp(min, 理想值, max) —— 流式，推荐
2. Media Query 断点调整字号
3. 用 rem（相对根字号）配合 html 字号调整
```

### Responsive Image 响应式图片

图片按屏幕加载合适尺寸（详见 04.9-图片）：

```html
<img
  src="photo.jpg"
  srcset="photo-400.jpg 400w, photo-800.jpg 800w, photo-1200.jpg 1200w"
  sizes="(max-width: 600px) 100vw, 50vw"
  alt="照片">
```

## Container Query

Container Query（容器查询）按「组件容器」而非「视口」做响应式，是响应式设计的重大进步。

```css
.card-container {
  container-type: inline-size;  /* 声明为查询容器 */
}

@container (min-width: 400px) {
  .card {
    flex-direction: row;  /* 容器宽度 >= 400px 时横排 */
  }
}
```

```text
Container Query vs Media Query：
Media Query —— 按「视口」响应（全局）
Container Query —— 按「组件容器」响应（局部）

价值：组件能「自包含」响应式，同一组件放在不同容器里自动适配，
不用依赖视口宽度。组件库尤其受益。
```

```text
Container Query 的完整内容见 06.6-Container Query。
```

## 应用场景实战

### 场景一：Mobile First 的卡片网格

```css
/* 移动优先：单列 */
.card-grid {
  display: grid;
  gap: 16px;
  grid-template-columns: 1fr;  /* 手机单列 */
}

/* 平板：两列 */
@media (min-width: 600px) {
  .card-grid {
    grid-template-columns: repeat(2, 1fr);
  }
}

/* 桌面：四列 */
@media (min-width: 1024px) {
  .card-grid {
    grid-template-columns: repeat(4, 1fr);
  }
}
```

### 场景二：流式 + 断点的响应式容器

```css
.container {
  width: 100%;
  max-width: 1200px;
  margin: 0 auto;
  padding: 0 16px;
}

/* 导航栏：桌面横排，手机竖排 */
.nav {
  display: flex;
  gap: 16px;
}
@media (max-width: 600px) {
  .nav {
    flex-direction: column;
  }
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. Mobile First 优先（min-width 断点，移动端性能好）
2. 断点由内容决定，不硬套设备型号，数量控制在 3-4 个
3. 布局用流式（% / fr / clamp），断点只用于「结构切换」
4. 响应式字体用 clamp，图片用 srcset/sizes
5. 组件级响应式优先用 Container Query

### 踩坑记录

```text
坑 1：只做 Desktop First 导致移动端臃肿
结论：移动端加载了所有桌面样式，性能差。
原因：Desktop First 先写大屏完整样式，移动端要层层覆盖。
解法：Mobile First 优先，小屏只加载基础样式。

坑 2：断点套用固定设备型号
结论：在 768px/1024px 硬切，中间宽度布局别扭。
原因：断点没按内容「挤不下」的位置设，而是套设备型号。
解法：观察内容在哪些宽度变形，在那里设断点。

坑 3：忽略横竖屏
结论：横屏手机布局错乱。
原因：只按宽度适配，没考虑 orientation。
解法：关键布局加 orientation 断点或流式兜底。

坑 4：响应式只改布局不改字号/图片
结论：布局适配了，但字号太大、图片太重，移动端体验仍差。
原因：响应式不完整，漏了字体和图片。
解法：字号用 clamp，图片用 srcset/sizes 按屏加载。

坑 5：Media Query 断点值用错方向
结论：min-width 和 max-width 搞反，样式在错误范围生效。
原因：min 是「向上」，max 是「向下」，方向混淆。
解法：Mobile First 用 min-width（从小到大），Desktop First 用 max-width。
```

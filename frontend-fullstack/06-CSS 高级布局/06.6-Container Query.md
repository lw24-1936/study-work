## 概述

Container Query（容器查询）按「组件容器」的尺寸做响应式，而非「视口」。它解决了 Media Query 的根本局限：组件在不同页面里，视口可能相同，但组件所在的容器大小不同，Media Query 无法处理这种情况。容器查询让组件「自包含」响应式。

```text
Container Query vs Media Query：
Media Query —— 按视口宽度响应（页面级）
Container Query —— 按容器宽度响应（组件级）

例子：一个卡片组件，放在主内容区（宽 800px）和侧边栏（宽 300px），
视口都是 1200px，Media Query 无法区分，
Container Query 能按「卡片实际所在容器」分别适配。
```

```text
容器查询的核心价值：
1. 组件自包含 —— 组件不依赖页面上下文，放哪都自动适配
2. 组件库友好 —— 复用组件无需关心宿主布局
3. 响应式更精确 —— 按真实可用空间而非视口
```

## container-type 与 container-name

容器查询第一步：用 container-type 声明「哪些元素是查询容器」。

```css
.card-wrapper {
  container-type: inline-size;  /* 声明为「行内尺寸」查询容器 */
}
```

```text
container-type 的取值：
inline-size —— 按容器「行内（宽度）」查询（最常用）
size —— 按容器「宽高」查询（需要显式尺寸）
normal —— 不是查询容器（默认）
```

```text
container-name 命名容器：
container-name: sidebar;  /* 给容器命名 */

@container sidebar (min-width: 400px) { ... }  /* 查询指定容器 */
```

```css
/* container 简写：type / name */
.sidebar {
  container: sidebar / inline-size;
}
```

```text
container-type: inline-size 的副作用（重要）：
声明为查询容器后，容器的大小不再依赖内容（类似 display: flow-root），
需要显式设置尺寸，否则高度可能塌陷。
```

## @container 查询规则

@container 是容器查询的语法，类似 @media：

```css
@container (min-width: 400px) {
  .card {
    flex-direction: row;
  }
}
```

```text
@container 的语法：
@container (条件) { 样式 }
@container 容器名 (条件) { 样式 }  // 查询指定容器

条件：
min-width / max-width —— 容器宽度（配 inline-size）
min-height / max-height —— 容器高度（配 size）
```

```html
<style>
  .card-wrapper {
    container-type: inline-size;
  }
  /* 容器 >= 400px 时，卡片横排 */
  @container (min-width: 400px) {
    .card {
      display: flex;
      flex-direction: row;
    }
  }
  /* 容器 < 400px 时，卡片竖排 */
  @container (max-width: 399px) {
    .card {
      flex-direction: column;
    }
  }
</style>
```

```text
容器查询的规则：
1. @container 里的样式作用于「容器内的元素」
2. 条件基于「最近的查询容器」的尺寸
3. 可以嵌套容器查询（不同层级容器分别适配）
```

## Container Units 容器单位

容器查询配套的「容器单位」，相对容器（而非视口）计算：

```css
.card {
  font-size: 5cqw;  /* 容器宽度的 5% */
}
```

```text
容器单位：
cqw —— 容器宽度的 1%
cqh —— 容器高度的 1%
cqi —— 容器行内尺寸的 1%
cqb —— 容器块尺寸的 1%
cqmin —— 容器宽高较小者的 1%
cqmax —— 容器宽高较大者的 1%
```

```text
容器单位 vs 视口单位：
vw/vh —— 相对视口（全局）
cqw/cqh —— 相对容器（组件级）

价值：组件内的字号、间距随「组件大小」缩放，而非视口。
```

```css
/* 组件内字号随容器缩放 */
.widget {
  container-type: inline-size;
}
.widget-title {
  font-size: clamp(1rem, 8cqw, 2rem);
}
```

## 应用场景实战

### 场景一：自适应的卡片组件

```css
/* 卡片组件：放主区（宽）横排，放侧栏（窄）竖排 */
.card-wrapper {
  container-type: inline-size;
}
.card {
  display: flex;
  flex-direction: column;  /* 默认竖排 */
}
@container (min-width: 500px) {
  .card {
    flex-direction: row;  /* 容器够宽则横排 */
  }
}
```

### 场景二：侧边栏导航的自适应

```css
.sidebar {
  container: sidebar / inline-size;
}
/* 侧边栏窄时只显示图标，宽时显示图标+文字 */
@container sidebar (max-width: 200px) {
  .nav-label { display: none; }
}
@container sidebar (min-width: 201px) {
  .nav-label { display: inline; }
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. 组件级响应式用容器查询，页面级响应式仍用 Media Query
2. container-type: inline-size 后注意容器尺寸（内容不再撑高度）
3. 容器命名用 container-name，查询用 @container 名字 (条件)
4. 组件内字号/间距用容器单位（cqw），随组件缩放
5. 查询容器尽量「靠近」被查询的元素（就近原则）

### 踩坑记录

```text
坑 1：声明 container-type 后容器高度塌陷
结论：容器设了 inline-size 后，高度变成 0 或异常。
原因：inline-size 容器尺寸不依赖内容，需显式设尺寸。
解法：给容器显式设 height，或确认布局能撑起高度。

坑 2：@container 查询到错误的容器
结论：样式基于「更外层」容器而非最近的容器。
原因：查询容器就近匹配，嵌套时可能命中非预期容器。
解法：用 container-name 明确指定查询哪个容器。

坑 3：容器查询条件用视口宽度理解
结论：以为 @container (min-width: 600px) 是视口条件。
原因：容器查询基于容器尺寸，不是视口。
解法：区分 @container（容器）和 @media（视口）。

坑 4：容器单位在非容器上下文里失效
结论：cqw 用在非容器内，值异常。
原因：容器单位需要祖先有 container-type，否则回退到「小视口」。
解法：确保容器单位用在查询容器内部。

坑 5：老浏览器不兼容容器查询
结论：老浏览器里容器查询完全不生效。
原因：容器查询是较新特性（Chrome 105+）。
解法：查 caniuse，提供 Media Query 降级兜底。
```

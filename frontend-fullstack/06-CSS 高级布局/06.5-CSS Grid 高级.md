## 概述

基础 Grid（05.7）讲的是行列定义和定位，这篇讲 Grid 的高级能力：命名线/命名区让布局更直观、自动放置简化布局、Subgrid 解决嵌套对齐、Masonry 实现瀑布流。掌握这些，Grid 就能胜任复杂布局。

```text
Grid 高级特性：
Named Lines —— 给网格线命名，定位更可读
Named Areas —— 用区域名画布局图
Auto Placement —— 自动放置，简化布局
Subgrid —— 子元素继承父网格
Masonry —— 瀑布流布局
```

## Named Lines 命名网格线

网格线可以命名，定位时用名字而非数字：

```css
.container {
  display: grid;
  grid-template-columns: [start] 1fr [middle] 1fr [end];
}

.item {
  grid-column: start / end;  /* 从 start 线到 end 线 */
}
```

```text
命名网格线的语法：
[name] 定义一条命名线（放在轨道尺寸前后）
[start] 1fr [middle] 1fr [end]

一条线可以多个名字：[main-start sidebar-end]
```

```text
命名的价值：
1. 可读性 —— grid-column: start / end 比 1 / 3 好懂
2. 可维护 —— 改轨道顺序不影响名字引用
```

## Named Areas 命名区域

grid-template-areas 用「名字」画布局，是最直观的 Grid 用法（05.7 已简介，这里展开）：

```css
.container {
  display: grid;
  grid-template-areas:
    "header header header"
    "sidebar main  main"
    "footer footer footer";
  grid-template-columns: 200px 1fr 1fr;
  grid-template-rows: auto 1fr auto;
}

.header { grid-area: header; }
.sidebar { grid-area: sidebar; }
.main { grid-area: main; }
.footer { grid-area: footer; }
```

```text
grid-template-areas 的规则：
1. 每一行字符串对应一行轨道，空格分隔列
2. 同名区域自动合并（header 占 3 列）
3. 用 . 表示空单元格
4. 每个区域名必须对应一个 grid-area
```

```text
Named Areas 的优势：
布局图「所见即所得」—— 字符串就是布局的直观表达。
改布局只需改字符串，不用动子元素定位。
```

## Auto Placement 自动放置

Auto Placement 是「不用手动指定每个元素位置，Grid 自动排列」的机制：

```css
.container {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  /* 子元素不写 grid-column/row，自动按顺序放置 */
}
```

```text
自动放置的顺序：
默认 row 方向（先填满第一行，再第二行）。

grid-auto-flow 控制方向：
grid-auto-flow: row;     /* 默认，按行 */
grid-auto-flow: column;  /* 按列 */
grid-auto-flow: dense;   /* 密集填充（填满空洞） */
```

```text
grid-auto-flow: dense 的用途：
当元素尺寸不一（有的跨列），会产生「空洞」，
dense 会让后面的元素回填空洞，布局更紧凑。
```

```css
/* 图片墙：dense 填充避免空洞 */
.gallery {
  display: grid;
  grid-template-columns: repeat(4, 1fr);
  grid-auto-flow: dense;
}
.gallery .large {
  grid-column: span 2;  /* 大图跨 2 列 */
  grid-row: span 2;
}
```

## Subgrid 子网格

Subgrid 让子元素「继承父网格的轨道」，解决嵌套网格的对齐问题：

```css
.grid {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  gap: 16px;
}

.grid-item {
  display: grid;
  grid-template-columns: subgrid;  /* 继承父网格的列 */
  grid-column: span 3;             /* 占满父网格 */
}
```

```text
Subgrid 解决的问题：
普通嵌套网格，子网格的列是「独立」的，和父网格对不齐。
Subgrid 让子网格的轨道「对齐父网格」，实现跨层级的列对齐。

典型场景：卡片列表里，每张卡片的标题/按钮对齐。
```

```text
Subgrid 的用法：
grid-template-columns: subgrid;  // 继承父的列轨道
grid-template-rows: subgrid;     // 继承父的行轨道
```

```text
Subgrid 的兼容性：
较新特性，现代浏览器（Chrome 117+、Safari 16+）已支持，
老浏览器需要降级方案。
```

## Masonry 瀑布流

Masonry（瀑布流）是 Pinterest 式的「不等高卡片紧凑排列」布局：

```css
.masonry {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  grid-template-rows: masonry;  /* 瀑布流行 */
}
```

```text
Masonry 的机制：
不等高的卡片，紧凑地「填充」到最短的列，
避免传统 Grid 里「同行对齐」导致的空白。

现状：masonry 是实验性特性，浏览器支持还不完善，
生产环境常用 CSS Columns 或 JS 库（Masonry.js）实现。
```

```css
/* 兼容方案：CSS Columns 实现瀑布流 */
.masonry {
  columns: 3;
  column-gap: 16px;
}
.masonry .item {
  break-inside: avoid;  /* 防止卡片被拆分到两列 */
  margin-bottom: 16px;
}
```

```text
瀑布流的三种实现：
1. grid-template-rows: masonry —— 原生（实验性，未普及）
2. CSS Columns —— 简单，但顺序是「竖着排」（先填满一列）
3. JS 库（Masonry.js）—— 功能全，但依赖 JS
```

## 应用场景实战

### 场景一：用 Named Areas 搭后台布局

```css
.admin-layout {
  display: grid;
  grid-template-areas:
    "header header"
    "sidebar content"
    "sidebar footer";
  grid-template-columns: 240px 1fr;
  grid-template-rows: auto 1fr auto;
  min-height: 100vh;
}
```

### 场景二：图片墙（dense 填充）

```css
.gallery {
  display: grid;
  grid-template-columns: repeat(4, 1fr);
  grid-auto-flow: dense;
  gap: 8px;
}
.gallery img:nth-child(3n) {
  grid-column: span 2;
  grid-row: span 2;  /* 每 3 张一张大图 */
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. 页面骨架用 grid-template-areas（直观、可维护）
2. 命名网格线提高定位可读性
3. 图片墙/卡片流用 grid-auto-flow: dense 填充空洞
4. 嵌套对齐用 Subgrid（注意兼容性）
5. 瀑布流用 CSS Columns 兜底（原生 masonry 未普及）

### 踩坑记录

```text
坑 1：grid-template-areas 区域名拼错
结论：布局错乱，区域不渲染。
原因：areas 字符串里的名字和 grid-area 对不上。
解法：严格核对区域名，areas 和 grid-area 一致。

坑 2：dense 打乱视觉顺序
结论：dense 填充后，元素视觉顺序和 DOM 顺序不一致。
原因：dense 让后面元素回填空洞，改变视觉顺序。
解法：顺序重要时别用 dense，或权衡紧凑和顺序。

坑 3：Subgrid 兼容性没考虑
结论：老浏览器里子网格不对齐。
原因：Subgrid 是较新特性，老浏览器不支持。
解法：查兼容性，提供降级（或不用 subgrid 的备选布局）。

坑 4：masonry 属性当成已普及使用
结论：grid-template-rows: masonry 在多数浏览器不生效。
原因：masonry 是实验特性，未正式进入标准。
解法：用 CSS Columns 或 JS 库实现瀑布流。

坑 5：命名线重名导致引用歧义
结论：同名网格线在 grid-column 引用时结果不确定。
原因：一条线多个名字没问题，但多条线同名会歧义。
解法：网格线命名保持唯一，或用数字 + 名字组合。
```

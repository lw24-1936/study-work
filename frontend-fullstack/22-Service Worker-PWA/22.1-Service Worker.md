## 概述

Service Worker 是运行在浏览器后台、独立于页面的脚本，可拦截网络请求、管理缓存、实现离线与推送。它是 PWA 的基石，只能在 HTTPS 或 localhost 下注册。

```text
Service Worker 核心特性：
1. 独立线程 —— 与页面并行，不阻塞 UI
2. 可拦截请求 —— 通过 fetch 事件接管网络
3. 可离线 —— 结合 Cache Storage 缓存资源
4. 事件驱动 —— install/activate/fetch/message 等生命周期事件
5. 无 DOM 访问 —— 不能操作页面 DOM，只能通过 postMessage 通信
```

```js
// 注册 Service Worker（在主线程执行）
if ('serviceWorker' in navigator) {
  navigator.serviceWorker.register('/sw.js')
    .then((reg) => console.log('注册成功', reg.scope))
    .catch((err) => console.error('注册失败', err));
}
```

## Lifecycle

Service Worker 有明确的生命周期：注册（register）→ 安装（install）→ 等待（waiting）→ 激活（activate）→ 工作（fetch/message）→ 废弃（redundant）。

```text
生命周期阶段：
parsed      —— 脚本已下载，尚未执行
installing  —— install 事件触发，可预缓存资源
installed   —— 安装完成，等待激活（可能被旧 SW 阻塞）
activating  —— activate 事件触发，可清理旧缓存
activated   —— 已接管页面，开始拦截 fetch
redundant   —— 被新版本替换或注册失败，进入废弃
```

```text
为什么有 waiting 状态：
如果页面仍被旧 SW 控制，新 SW 安装后会进入 waiting，
直到旧 SW 控制的页面全部关闭，或调用 self.skipWaiting() 强制激活。
```

```js
// 关键事件监听
self.addEventListener('install', (e) => { /* 预缓存 */ });
self.addEventListener('activate', (e) => { /* 清理旧缓存 */ });
self.addEventListener('fetch', (e) => { /* 拦截请求 */ });
self.addEventListener('message', (e) => { /* 页面通信 */ });
```

## Scope

Scope 是 Service Worker 的控制范围，由注册时脚本的路径决定。SW 只能拦截其 scope 内的请求。

```text
作用域规则：
1. 默认 scope = SW 脚本所在目录
2. 注册时可显式指定 scope（不能超出脚本目录）
3. 只能控制 scope 内的页面和请求
```

```js
// 默认 scope：/ 下的所有请求
navigator.serviceWorker.register('/sw.js');

// 显式指定 scope（不能超出 /app/ 目录）
navigator.serviceWorker.register('/app/sw.js', { scope: '/app/' });
```

```text
典型应用：
1. 全站 SW → 放根目录 /sw.js，scope 为 /
2. 子应用 SW → 放子目录，只控制该子路径
3. 一个页面只能被一个 SW 控制，多个 SW 按 scope 分工
```

## Install

Install 事件在 SW 首次安装或版本更新时触发，适合预缓存核心资源。用 event.waitUntil 延长安装过程，保证资源缓存完成才算安装成功。

```js
const CACHE_NAME = 'my-app-v1';
const PRECACHE = ['/', '/app.js', '/style.css', '/logo.png'];

self.addEventListener('install', (event) => {
  event.waitUntil(
    caches.open(CACHE_NAME)
      .then((cache) => cache.addAll(PRECACHE))
      .then(() => self.skipWaiting())   // 立即激活，不等旧 SW
  );
});
```

```text
install 注意点：
1. waitUntil 中的 Promise 失败 → 安装失败，SW 不生效
2. 预缓存资源列表要精简，别把大文件全塞进来
3. 更新缓存版本名（v1 → v2）才会触发重新安装
```

## Activate

Activate 事件在 SW 即将接管页面时触发，适合清理旧版本缓存、迁移数据。activate 里调用 clients.claim() 可立即控制所有页面。

```js
self.addEventListener('activate', (event) => {
  const allowed = ['my-app-v2'];
  event.waitUntil(
    caches.keys()
      .then((keys) => Promise.all(
        keys.filter((k) => !allowed.includes(k))
            .map((k) => caches.delete(k))
      ))
      .then(() => self.clients.claim())
  );
});
```

```text
activate 职责：
1. 删除旧版本缓存，避免存储膨胀
2. 数据迁移（如 IndexedDB schema 升级）
3. clients.claim() 让新 SW 立即控制已有页面
```

## Fetch

Fetch 事件在 SW 控制的页面发起网络请求时触发，可拦截并决定返回什么（缓存、网络或自定义响应），是实现离线与缓存策略的核心。

```js
self.addEventListener('fetch', (event) => {
  event.respondWith(
    caches.match(event.request).then((cached) => {
      // 缓存优先
      if (cached) return cached;
      return fetch(event.request);
    })
  );
});
```

```text
fetch 事件要点：
1. event.respondWith() 必须调用，否则请求走默认网络
2. event.request 是 Request 对象，含 url/method/destination 等
3. 可按请求类型区分策略（静态资源 vs 接口）
```

```js
// 按资源类型区分策略
self.addEventListener('fetch', (event) => {
  const { request } = event;
  if (request.mode === 'navigate') {
    // 页面导航：网络优先，失败回退缓存
    event.respondWith(
      fetch(request).catch(() => caches.match('/offline.html'))
    );
  } else if (request.destination === 'image') {
    // 图片：缓存优先
    event.respondWith(
      caches.match(request).then((c) => c || fetch(request))
    );
  }
});
```

## Message

Message 事件用于页面与 Service Worker 之间的双向通信，通过 postMessage 发送数据。适合让页面触发 SW 的特定操作（如跳过等待、更新缓存）。

```js
// 主线程 → SW：发送消息
navigator.serviceWorker.controller?.postMessage({ type: 'SKIP_WAITING' });

// SW 内监听
self.addEventListener('message', (event) => {
  if (event.data.type === 'SKIP_WAITING') {
    self.skipWaiting();
  }
});
```

```js
// SW → 主线程：通过 Client 回消息
self.clients.matchAll().then((clients) => {
  clients.forEach((client) => client.postMessage({ type: 'UPDATED' }));
});

// 主线程监听
navigator.serviceWorker.addEventListener('message', (event) => {
  console.log('收到 SW 消息', event.data);
});
```

```text
MessageChannel 支持：
页面与 SW 也可用 MessageChannel 建立专用双向通道，
用于流式数据传输等高级场景。
```

## Cache

Cache 指 Cache Storage API，是 Service Worker 用来存储请求/响应对的键值存储。通过 caches.open 打开命名缓存，配合 fetch 实现离线。

```js
// 基本操作
const cache = await caches.open('my-cache');
await cache.add('/app.js');               // 请求并缓存
await cache.addAll(['/', '/style.css']);  // 批量缓存
await cache.put('/app.js', response);     // 手动写入
const res = await cache.match('/app.js'); // 查找缓存
await cache.delete('/app.js');            // 删除
```

```text
Cache Storage 特点：
1. 键是 Request，值是 Response
2. 与 HTTP 缓存相互独立，由代码控制
3. 命名空间隔离，可管理多个缓存版本
4. 存储配额有限，需主动清理
```

```js
// 判断请求是否命中缓存
const isCached = await caches.match('/app.js');
console.log(isCached ? '已缓存' : '未缓存');
```

## Update

Update 指 Service Worker 自身的更新机制：浏览器检测到 sw.js 内容变化后，会安装新版本并等待接管。

```text
更新流程：
1. 浏览器定期检查 sw.js 是否有变化（字节级比对）
2. 有变化 → 下载并触发新 install
3. 新 SW 进入 waiting（旧 SW 仍控制页面）
4. 触发条件：skipWaiting() 或旧 SW 控制的页面全部关闭
5. 新 SW activate → 接管
```

```js
// 实现「检测到更新就提示用户刷新」
navigator.serviceWorker.register('/sw.js').then((reg) => {
  reg.addEventListener('updatefound', () => {
    const newWorker = reg.installing;
    newWorker.addEventListener('statechange', () => {
      if (newWorker.state === 'installed' && navigator.serviceWorker.controller) {
        // 有新版本可用，提示用户刷新
        showUpdateBanner();
      }
    });
  });
});
```

```text
更新注意点：
1. sw.js 任何字节变化都会触发更新
2. 缓存名要随之升级（v1 → v2），否则旧缓存不清理
3. 建议配合 skipWaiting + clients.claim 实现「更新即生效」
```

## 应用场景实战

### 场景一：离线可用的静态站点

```js
// sw.js —— 预缓存 + 缓存优先，实现完全离线
const CACHE = 'site-v1';
self.addEventListener('install', (e) => {
  e.waitUntil(
    caches.open(CACHE).then((c) => c.addAll(['/', '/app.js', '/style.css']))
  );
});
self.addEventListener('fetch', (e) => {
  e.respondWith(
    caches.match(e.request).then((c) => c || fetch(e.request))
  );
});
```

### 场景二：后台推送更新提示

```js
// 主线程：检测更新并通知用户
navigator.serviceWorker.register('/sw.js').then((reg) => {
  reg.addEventListener('updatefound', () => {
    const w = reg.installing;
    w.addEventListener('statechange', () => {
      if (w.state === 'installed' && navigator.serviceWorker.controller) {
        if (confirm('有新版本，立即刷新？')) window.location.reload();
      }
    });
  });
});
```

## 最佳实践与踩坑记录

### 最佳实践

1. 缓存名带版本号（v1/v2），activate 时清理旧缓存
2. 预缓存只放核心资源，避免安装过慢
3. 用 skipWaiting + clients.claim 实现更新即时生效
4. 按请求类型区分缓存策略，不要一刀切
5. 只在 HTTPS 或 localhost 下使用（安全要求）

### 踩坑记录

```text
坑 1：改了 sw.js 但页面仍用旧逻辑
结论：更新不生效。
原因：新 SW 停在 waiting，旧 SW 还在控制页面。
解法：install 里调用 self.skipWaiting()，activate 里调用 clients.claim()。

坑 2：缓存名不变导致资源不更新
结论：预缓存列表改了，但用户还是拿到旧资源。
原因：缓存名相同，新 install 不会重新写入同 key 内容。
解法：每次变更升级缓存名（v1 → v2）。

坑 3：SW 作用域限制导致请求拦截失败
结论：有些请求没被 SW 拦截。
原因：请求 URL 不在 SW 的 scope 内。
解法：把 sw.js 放根目录，或用 Service-Worker-Allowed 头扩展 scope。

坑 4：非 HTTPS 下注册失败
结论：生产环境 SW 注册报错。
原因：Service Worker 要求安全上下文（HTTPS 或 localhost）。
解法：部署到 HTTPS，本地开发用 localhost。

坑 5：waitUntil 未包裹异步操作
结论：缓存没写完 SW 就被终止。
原因：install 里的异步没包进 waitUntil，SW 提前结束。
解法：所有关键异步都放进 event.waitUntil()。
```

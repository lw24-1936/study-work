## 概述

PWA（Progressive Web App）用 Web 技术提供接近原生应用的体验：可安装、可离线、可推送。它由 Web App Manifest、Service Worker 和 HTTPS 三块构成。

```text
PWA 三大支柱：
1. Web App Manifest —— 定义应用元信息（名称、图标、启动方式）
2. Service Worker —— 提供离线、缓存、推送、后台同步
3. HTTPS —— 安全上下文，Service Worker 的硬性要求
```

```text
PWA 带来的能力：
1. 可安装 —— 添加到桌面/主屏幕，像原生 App 一样启动
2. 可离线 —— 断网仍能访问已缓存内容
3. 可推送 —— 即使页面关闭也能收到通知
4. 可同步 —— 网络恢复后自动补发请求
```

## Web App Manifest

Web App Manifest 是一个 JSON 文件，描述应用名称、图标、主题色、启动方式等元信息，让浏览器知道如何「像 App 一样」展示和启动。

```html
<link rel="manifest" href="/manifest.webmanifest" />
```

```json
{
  "name": "我的应用",
  "short_name": "应用",
  "start_url": "/",
  "display": "standalone",
  "background_color": "#ffffff",
  "theme_color": "#3f51b5",
  "icons": [
    { "src": "/icon-192.png", "sizes": "192x192", "type": "image/png" },
    { "src": "/icon-512.png", "sizes": "512x512", "type": "image/png" }
  ]
}
```

```text
关键字段：
name / short_name —— 完整名 / 短名（桌面图标下显示短名）
start_url          —— 启动时加载的 URL
display            —— standalone（独立窗口）/ fullscreen / minimal-ui / browser
theme_color        —— 状态栏/工具栏主题色
background_color   —— 启动屏背景色
icons              —— 应用图标，需 192 和 512 两个尺寸
```

## Offline

Offline（离线）能力由 Service Worker + Cache Storage 实现，让应用在断网时依然能打开和使用。

```js
// 离线能力：预缓存 + 网络回退
self.addEventListener('install', (e) => {
  e.waitUntil(
    caches.open('v1').then((c) => c.addAll(['/', '/app.js', '/style.css']))
  );
});

self.addEventListener('fetch', (e) => {
  e.respondWith(
    caches.match(e.request).then((c) => c || fetch(e.request))
  );
});
```

```text
离线体验的三个层次：
1. 离线可打开 —— 预缓存了应用壳（shell）
2. 离线可浏览 —— 已访问过的内容被动态缓存
3. 离线可操作 —— 本地暂存操作，联网后同步
```

```text
注意：
离线不等于缓存一切。应优先保证「能打开」，再按需缓存内容，
否则会消耗大量存储空间。
```

## Installability

Installability（可安装性）指浏览器判定应用满足条件、允许安装。Chrome 等浏览器在满足条件后会自动弹出安装提示或允许用户手动安装。

```text
安装条件（Chrome 标准）：
1. 页面通过 HTTPS 访问
2. 有合法的 Web App Manifest
3. 已注册有效的 Service Worker（含 fetch 处理器）
4. 图标满足要求（至少 192x192 和 512x512）
5. start_url 可访问，display 等字段合法
```

```js
// 监听安装提示（beforeinstallprompt 事件）
let deferredPrompt;
window.addEventListener('beforeinstallprompt', (e) => {
  e.preventDefault();          // 阻止默认提示
  deferredPrompt = e;          // 保存，待用户点击自定义按钮
});

// 用户点击「安装」按钮时
installBtn.addEventListener('click', async () => {
  deferredPrompt.prompt();
  const { outcome } = await deferredPrompt.userChoice;
  console.log(outcome);        // 'accepted' 或 'dismissed'
});
```

```text
注意：Chrome 已逐步限制自动弹窗，
beforeinstallprompt 在部分版本可能不再触发，
应同时提供浏览器菜单的手动安装引导。
```

## Add to Home Screen

Add to Home Screen（添加到主屏幕）是安装 PWA 的用户操作，把应用图标放到桌面或主屏幕，之后可像原生 App 一样独立启动。

```text
添加后的表现（display: standalone）：
1. 独立窗口启动，无浏览器地址栏
2. 出现在桌面/主屏幕，有应用图标
3. 独立任务切换条目，与浏览器分离
```

```text
iOS Safari 的差异：
1. 通过「分享 → 添加到主屏幕」手动添加
2. 用 apple-touch-icon 指定图标
3. 用 apple-mobile-web-app-capable 控制独立模式
```

```html
<!-- iOS 专属配置 -->
<link rel="apple-touch-icon" href="/icon-180.png" />
<meta name="apple-mobile-web-app-capable" content="yes" />
<meta name="apple-mobile-web-app-status-bar-style" content="black" />
```

## Push

Push（推送）让服务端在应用未打开时也能向用户发送通知。它由 Push API（消息投递）和 Notification API（展示通知）配合 Service Worker 实现。

```js
// 1. 请求通知权限
Notification.requestPermission().then((permission) => {
  console.log(permission);  // 'granted' / 'denied' / 'default'
});
```

```js
// 2. 订阅推送
const registration = await navigator.serviceWorker.ready;
const subscription = await registration.pushManager.subscribe({
  userVisibleOnly: true,
  applicationServerKey: urlBase64ToUint8Array(PUBLIC_VAPID_KEY),
});
// 把 subscription 发送到服务端保存
await fetch('/api/subscribe', {
  method: 'POST',
  body: JSON.stringify(subscription),
});
```

```js
// 3. SW 内接收并展示通知
self.addEventListener('push', (event) => {
  const data = event.data.json();
  event.waitUntil(
    self.registration.showNotification(data.title, {
      body: data.body,
      icon: '/icon-192.png',
    })
  );
});
```

```text
推送流程：
1. 用户授权通知权限
2. 浏览器订阅推送服务（拿到 subscription）
3. 服务端保存 subscription
4. 服务端通过推送服务发送消息
5. SW 的 push 事件接收并 showNotification
```

## Background Sync

Background Sync（后台同步）允许应用在网络恢复后自动补发之前失败的操作，即使页面已关闭。适合表单提交、离线操作同步等场景。

```js
// 页面：网络失败时注册后台同步
navigator.serviceWorker.ready.then((reg) => {
  reg.sync.register('sync-posts');
});
```

```js
// SW：监听 sync 事件，网络恢复后重试
self.addEventListener('sync', (event) => {
  if (event.tag === 'sync-posts') {
    event.waitUntil(sendPendingPosts());
  }
});

async function sendPendingPosts() {
  const pending = await getPendingFromDB();   // 从 IndexedDB 取待发数据
  for (const post of pending) {
    await fetch('/api/posts', { method: 'POST', body: JSON.stringify(post) });
  }
  await clearPending();                        // 成功后清理
}
```

```text
Background Sync 特点：
1. 由浏览器调度，网络恢复后触发
2. 页面无需保持打开（SW 在后台执行）
3. 用 tag 区分不同的同步任务
4. 失败会自动重试，但时机由浏览器决定
```

## 应用场景实战

### 场景一：可安装的离线笔记应用

```json
{
  "name": "离线笔记",
  "short_name": "笔记",
  "start_url": "/",
  "display": "standalone",
  "theme_color": "#1a73e8",
  "icons": [
    { "src": "/icon-192.png", "sizes": "192x192", "type": "image/png" },
    { "src": "/icon-512.png", "sizes": "512x512", "type": "image/png" }
  ]
}
```

```js
// sw.js：预缓存应用壳，接口走网络回退
self.addEventListener('install', (e) => {
  e.waitUntil(caches.open('note-v1').then((c) => c.addAll(['/', '/app.js'])));
});
self.addEventListener('fetch', (e) => {
  if (e.request.url.includes('/api/')) {
    e.respondWith(fetch(e.request).catch(() => caches.match(e.request)));
  } else {
    e.respondWith(caches.match(e.request).then((c) => c || fetch(e.request)));
  }
});
```

### 场景二：离线点赞 + 后台同步

```js
// 离线时点赞，先存本地再注册同步
async function like(postId) {
  try {
    await fetch(`/api/posts/${postId}/like`, { method: 'POST' });
  } catch {
    await savePendingLike(postId);              // 存 IndexedDB
    const reg = await navigator.serviceWorker.ready;
    await reg.sync.register('sync-likes');      // 注册后台同步
  }
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. 图标提供 192 和 512 两个尺寸，保证各平台显示正常
2. 离线优先缓存「应用壳」，内容按需动态缓存
3. 推送订阅用 VAPID 密钥，服务端安全保存订阅信息
4. 后台同步只用于非即时操作，避免滥用
5. 监听 beforeinstallprompt 提供自定义安装入口

### 踩坑记录

```text
坑 1：不满足安装条件，没有安装提示
结论：用户无法安装 PWA。
原因：缺 manifest、图标尺寸不足、或 SW 没有 fetch 处理器。
解法：用 Lighthouse 的 PWA 审计逐项排查并补齐条件。

坑 2：iOS 上不显示安装提示
结论：iOS Safari 不支持 beforeinstallprompt。
原因：iOS 走「分享 → 添加到主屏幕」的手动流程。
解法：引导 iOS 用户手动添加，并配置 apple-touch-icon。

坑 3：推送订阅了但收不到通知
结论：服务端推送失败或权限被拒。
原因：权限未授予、VAPID 密钥错误、或订阅已过期。
解法：检查 Notification.permission，校验服务端 VAPID，处理过期订阅。

坑 4：后台同步迟迟不触发
结论：注册了 sync 但一直没执行。
原因：后台同步触发时机由浏览器决定，可能延迟很久。
解法：不要依赖 sync 做即时同步，重要操作给用户明确反馈。

坑 5：display 配置被忽略
结论：安装了但仍在浏览器标签页里打开。
原因：manifest 的 display 字段缺失或浏览器不支持该模式。
解法：显式设置 display: standalone，并检查 manifest 是否被正确加载。
```

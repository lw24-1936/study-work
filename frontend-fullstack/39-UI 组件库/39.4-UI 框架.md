## 概述

UI 框架（组件库）提供一套现成的、风格统一的组件与设计规范，让团队专注于业务逻辑而非重复造轮子。按设计哲学可分为「完整成套」与「无头（headless）+ 可定制」两类。

```text
选型需要考量的维度：
1. 框架生态 —— React / Vue 阵营
2. 设计语言 —— 是否契合产品风格（Material、企业级、简洁）
3. 定制能力 —— 主题、样式覆盖的灵活度
4. 可访问性 —— 无障碍支持是否完善
5. 包体积与性能 —— tree-shaking、按需加载
6. 维护活跃度 —— 社区规模、更新频率
```

```text
两大流派：
成套组件库 —— Ant Design、Material UI、Element Plus、Vuetify
  开箱即用，风格统一，但深度定制成本高
无头/可定制 —— Radix UI、shadcn/ui、Chakra UI
  提供行为与可访问性，样式由你掌控，灵活但需组装
```

## Ant Design

Ant Design（antd）是阿里巴巴出品的企业级 React 组件库，中文生态成熟，是后台管理系统的首选之一。

```jsx
import { Button, Table, ConfigProvider } from 'antd';
import zhCN from 'antd/locale/zh_CN';

function AdminPage() {
  return (
    <ConfigProvider locale={zhCN} theme={{ token: { colorPrimary: '#1677ff' } }}>
      <Button type="primary">主要按钮</Button>
      <Table columns={columns} dataSource={data} />
    </ConfigProvider>
  );
}
```

```text
Ant Design 特点：
1. 企业级组件齐全（表格、表单、树、图表生态）
2. 中文文档完善，国内使用广泛
3. 基于 CSS-in-JS 的 Design Token 主题系统
4. 适合中后台、B 端产品
```

## Material UI

Material UI（MUI）遵循 Google Material Design 规范的 React 组件库，国际生态最成熟，主题系统强大。

```jsx
import { Button, Table, createTheme, ThemeProvider } from '@mui/material';

const theme = createTheme({
  palette: {
    primary: { main: '#1976d2' },
  },
});

function App() {
  return (
    <ThemeProvider theme={theme}>
      <Button variant="contained" color="primary">主要按钮</Button>
    </ThemeProvider>
  );
}
```

```text
Material UI 特点：
1. 遵循 Material Design 设计规范，风格辨识度高
2. 主题系统强大（palette、typography、spacing）
3. 组件与工具丰富，含 MUI X（数据表格、日期）
4. 适合国际化产品、追求 Material 风格的应用
```

## Chakra UI

Chakra UI 是强调「可组合、可访问、开发体验好」的 React 组件库，用 style props 直接控制样式，组件代码更简洁。

```jsx
import { ChakraProvider, Button, Box, extendTheme } from '@chakra-ui/react';

const theme = extendTheme({
  colors: { brand: { 500: '#6B46C1' } },
});

function App() {
  return (
    <ChakraProvider theme={theme}>
      <Box p={4} bg="gray.50">
        <Button colorScheme="brand">主要按钮</Button>
      </Box>
    </ChakraProvider>
  );
}
```

```text
Chakra UI 特点：
1. style props（p、bg、color）让布局内联可读
2. 默认注重可访问性（WAI-ARIA）
3. 主题用 Design Token 高度可定制
4. 适合快速开发、重视 DX 的产品
```

## Radix UI

Radix UI 是「无头（headless）」组件库：只提供交互行为与可访问性，不带任何样式，样式完全由开发者决定。

```jsx
import * as Dialog from '@radix-ui/react-dialog';

function MyDialog() {
  return (
    <Dialog.Root>
      <Dialog.Trigger asChild>
        <button className="btn">打开</button>
      </Dialog.Trigger>
      <Dialog.Portal>
        <Dialog.Overlay className="overlay" />
        <Dialog.Content className="dialog-content">
          <Dialog.Title>标题</Dialog.Title>
          <Dialog.Description>描述内容</Dialog.Description>
          <Dialog.Close>关闭</Dialog.Close>
        </Dialog.Content>
      </Dialog.Portal>
    </Dialog.Root>
  );
}
```

```text
Radix UI 特点：
1. 无头设计 —— 只提供行为，零样式，完全自由定制
2. 可访问性一流 —— 键盘导航、焦点管理、ARIA 开箱即用
3. 细粒度模块 —— 按需引入单个组件（Dialog、Dropdown 等）
4. 常作为其他库（shadcn/ui）的底层
```

## shadcn/ui

shadcn/ui 不是 npm 包，而是「复制源码到你的项目」的组件集合，基于 Radix UI + Tailwind CSS，把控制权完全交给开发者。

```bash
# 不是安装依赖，而是生成源码到你的项目里
npx shadcn@latest init
npx shadcn@latest add button dialog table
```

```jsx
// 生成的组件源码在你的项目里，可随意修改
import { Button } from '@/components/ui/button';
import { Dialog, DialogContent, DialogTrigger } from '@/components/ui/dialog';

function Demo() {
  return (
    <Dialog>
      <DialogTrigger asChild>
        <Button variant="outline">打开对话框</Button>
      </DialogTrigger>
      <DialogContent>
        <p>这是对话框内容</p>
      </DialogContent>
    </Dialog>
  );
}
```

```text
shadcn/ui 特点：
1. 代码归你所有 —— 复制进项目，可自由修改
2. 基于 Tailwind CSS，样式天然统一、易定制
3. 底层是 Radix UI，可访问性有保障
4. 适合 Next.js/Tailwind 技术栈、追求完全掌控的团队
```

## Element Plus

Element Plus 是 Vue 3 的组件库，Element UI 的延续，中文生态好，国内 Vue 中后台主流选择。

```vue
<template>
  <div>
    <el-button type="primary">主要按钮</el-button>
    <el-table :data="rows">
      <el-table-column prop="name" label="姓名" />
      <el-table-column prop="age" label="年龄" />
    </el-table>
  </div>
</template>

<script setup>
import { ref } from 'vue';
const rows = ref([
  { name: 'Alice', age: 28 },
  { name: 'Bob', age: 34 },
]);
</script>
```

```text
Element Plus 特点：
1. Vue 3 生态的标杆组件库
2. 组件齐全，中后台场景覆盖广
3. 中文文档完善，国内使用广泛
4. 基于 CSS 变量主题定制
```

## Naive UI

Naive UI 是社区出品的 Vue 3 组件库，以「可主题定制、TypeScript 友好、tree-shaking 优化」著称。

```vue
<template>
  <n-config-provider :theme-overrides="overrides">
    <n-button type="primary">主要按钮</n-button>
    <n-data-table :columns="columns" :data="rows" />
  </n-config-provider>
</template>

<script setup lang="ts">
import { NConfigProvider, NButton, NDataTable } from 'naive-ui';
const columns = [
  { title: '姓名', key: 'name' },
  { title: '年龄', key: 'age' },
];
const rows = [
  { key: '1', name: 'Alice', age: 28 },
];
</script>
```

```text
Naive UI 特点：
1. 纯 TypeScript 编写，类型体验好
2. 主题系统灵活，支持运行时定制
3. 默认支持 tree-shaking，按需引入体积小
4. 适合重视类型与定制能力的 Vue 3 项目
```

## Vuetify

Vuetify 是 Vue 的 Material Design 组件库，提供大量组件与完整的 Material 风格体系，适合快速搭建 Material 风格应用。

```vue
<template>
  <v-app>
    <v-btn color="primary">主要按钮</v-btn>
    <v-data-table :items="rows" :headers="headers" />
  </v-app>
</template>

<script setup>
const headers = [
  { title: '姓名', key: 'name' },
  { title: '年龄', key: 'age' },
];
const rows = [
  { name: 'Alice', age: 28 },
  { name: 'Bob', age: 34 },
];
</script>
```

```text
Vuetify 特点：
1. Vue 的 Material Design 实现，风格统一
2. 组件数量庞大（80+），覆盖场景广
3. 内置布局系统（v-app、v-container）
4. 适合快速交付 Material 风格的 Vue 项目
```

## 应用场景实战

### 场景一：后台管理系统的组件库选型

```text
需求：企业内部中后台，团队熟悉 React，需要表格/表单/权限管理
推荐：Ant Design
理由：
1. 企业级组件最全（ProTable、ProForm 生态）
2. 中文文档与社区，问题好解决
3. Design Token 可统一品牌色
```

```text
需求：Vue 3 技术栈的后台系统
推荐：Element Plus 或 Naive UI
理由：
1. Element Plus 生态成熟、组件全
2. Naive UI 类型好、体积小、主题灵活
若重视定制与 TS 体验选 Naive UI，重视生态与案例选 Element Plus
```

### 场景二：新品牌 C 端产品的选型

```text
需求：面向消费者的新品牌，要求独特视觉，技术栈 Next.js + Tailwind
推荐：shadcn/ui（基于 Radix UI）
理由：
1. 代码归你，视觉可完全自定义，摆脱「组件库脸」
2. Tailwind 与 Next.js 无缝集成
3. 可访问性由 Radix UI 保证
组合：Radix UI 提供行为，Tailwind 定义样式，shadcn/ui 组织代码
```

```jsx
// shadcn/ui 项目中的典型使用
import { Button } from '@/components/ui/button';
import { Card, CardHeader, CardContent } from '@/components/ui/card';

export function PricingCard({ plan }) {
  return (
    <Card>
      <CardHeader>{plan.name}</CardHeader>
      <CardContent>
        <p>￥{plan.price}/月</p>
        <Button className="w-full">立即订阅</Button>
      </CardContent>
    </Card>
  );
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. 选型先看技术栈（React/Vue）与产品定位（中后台/C 端/国际化）
2. 后台系统优先成套库（antd/Element Plus），省时省力
3. 追求独特视觉用无头方案（Radix + Tailwind 或 shadcn/ui）
4. 深度定制前评估「覆盖主题 vs 源码掌控」的成本
5. 关注可访问性与维护活跃度，避免选择已停滞的库

### 踩坑记录

```text
坑 1：只按流行度选型，忽略设计匹配度
结论：做 Material 风格以外的产品强行用 MUI，定制很痛苦。
原因：成套库的视觉语言已固化，深度改造成本高。
解法：先定产品视觉，再选与之匹配的库。

坑 2：全套引入导致包体积爆炸
结论：首屏加载慢，打包产物巨大。
原因：未做按需加载/tree-shaking，全量 import。
解法：按需引入（babel-plugin-import / unplugin），或选默认 tree-shaking 的库。

坑 3：深度魔改成套组件库
结论：升级库版本时样式/行为大面积破坏。
原因：覆盖了库内部结构，升级成本极高。
解法：优先用官方主题/插槽定制，深度需求改用无头方案。

坑 4：忽略可访问性
结论：键盘无法操作、读屏失效，产品不合规。
原因：选用的库或自定义样式未考虑 a11y。
解法：优先选 Radix/Chakra 等重视 a11y 的库，自定义时补 ARIA。

坑 5：无头库组件不全导致重复造轮子
结论：选了 Radix 却发现要自己组装很多组件。
原因：无头库只提供基础交互，高级组件需自己搭。
解法：无头 + shadcn/ui 补全，或评估成套库与无头库的组合。
```

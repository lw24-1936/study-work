## 概述

反馈组件向用户传达「操作结果、系统状态、加载进度」等信息，分为即时提示（Message、Toast、Notification）、进度反馈（Progress、Spin、Skeleton）、结果页（Result、Empty）、警示（Alert）。

```text
反馈组件的四类：
1. 即时提示 —— Message/Toast（轻量）、Notification（带标题）
2. 进度反馈 —— Progress（明确进度）、Spin/Skeleton（不确定等待）
3. 结果反馈 —— Result（成功/失败结果页）、Empty（空状态）
4. 警示 —— Alert（页面内静态提示）
```

```jsx
// 以 Ant Design 为例的导入
import { Alert, message, notification, Progress,
         Skeleton, Empty, Result, Spin } from 'antd';
```

## Alert

Alert 是页面内嵌的警示条，持续展示，用于重要信息、警告、错误提示，可关闭。

```jsx
import { Alert } from 'antd';

function Notices() {
  return (
    <div>
      <Alert message="操作成功" type="success" showIcon />
      <Alert message="注意" description="这是一条警告信息" type="warning" showIcon />
      <Alert message="错误" description="请求失败，请重试" type="error" closable />
      <Alert message="提示" type="info" showIcon />
    </div>
  );
}
```

```jsx
// 关闭后回调（可用于记录或隐藏横幅）
<Alert
  message="可关闭的提示"
  closable
  onClose={() => console.log('已关闭')}
/>;
```

## Message

Message 是轻量级的全局即时提示，短暂显示后自动消失，适合操作结果反馈（保存成功、删除成功）。

```jsx
import { message } from 'antd';

// 命令式调用
message.success('保存成功');
message.error('保存失败');
message.warning('数据未完整');
message.info('提示信息');
message.loading('加载中…', 2);  // 2 秒后关闭
```

```jsx
// 异步操作后的结果反馈
async function handleSave() {
  const hide = message.loading('保存中…', 0);  // 0 = 不自动关闭
  try {
    await apiSave();
    hide();
    message.success('保存成功');
  } catch (e) {
    hide();
    message.error('保存失败：' + e.message);
  }
}
```

## Notification

Notification 是带标题与内容的通知卡片，比 Message 信息更丰富，常用于需要用户关注的系统通知，可带操作按钮。

```jsx
import { notification } from 'antd';

notification.open({
  message: '新消息',
  description: '你有一条新的评论',
  duration: 4,
});

notification.success({
  message: '提交成功',
  description: '工单 #1234 已创建',
});
```

```jsx
// 带操作按钮的通知
notification.open({
  message: '更新可用',
  description: '有新的版本 v2.0.0',
  btn: <Button size="small" onClick={doUpdate}>立即更新</Button>,
});
```

```text
Message vs Notification 的取舍：
Message —— 轻量、无标题、操作结果（保存/删除成功）
Notification —— 带标题/描述/操作，重要事件（收到通知、更新提示）
```

## Toast

Toast 是移动端/跨平台语境下的轻量提示，与 Message 概念等价：短暂出现、自动消失、不打断操作。不同库命名不同（Ant Design 叫 message，Element Plus 叫 ElMessage，移动端普遍叫 toast）。

```jsx
// 自定义轻量 toast（无组件库时）
function toast(text, type = 'info', duration = 2000) {
  const el = document.createElement('div');
  el.className = `toast toast-${type}`;
  el.textContent = text;
  document.body.appendChild(el);
  setTimeout(() => el.remove(), duration);
}

toast('操作成功', 'success');
```

```jsx
// 各库的等价写法
// Ant Design: message.success('成功')
// Element Plus: ElMessage.success('成功')
// 移动端（antd-mobile）: Toast.show('成功')
```

## Progress

Progress 展示任务的完成进度，支持条形、圆形、仪表盘等多种形态，可配合状态色。

```jsx
import { Progress } from 'antd';

function UploadProgress({ percent }) {
  return (
    <div>
      <Progress percent={percent} />
      <Progress type="circle" percent={75} />
      <Progress type="dashboard" percent={75} />
      <Progress percent={30} status="exception" />  {/* 异常态 */}
      <Progress percent={100} status="success" />    {/* 完成态 */}
    </div>
  );
}
```

```jsx
// 动态进度（配合上传/下载）
function DownloadButton() {
  const [percent, setPercent] = useState(0);
  const download = async () => {
    await downloadWithProgress(setPercent);  // 回调更新进度
  };
  return (
    <div>
      <Button onClick={download}>下载</Button>
      {percent > 0 && <Progress percent={percent} />}
    </div>
  );
}
```

## Skeleton

Skeleton 是骨架屏占位，在数据加载时用灰块模拟内容布局，减少感知上的等待。

```jsx
import { Skeleton } from 'antd';

function LoadingArticle({ loading, data }) {
  if (loading) {
    return (
      <div>
        <Skeleton active paragraph={{ rows: 4 }} />
      </div>
    );
  }
  return <Article data={data} />;
}
```

```jsx
// 模拟真实布局的骨架（头像 + 标题 + 段落）
<Skeleton avatar active title paragraph={{ rows: 3 }} />;
```

```text
Skeleton 与 Spin 的选择：
Skeleton —— 内容区域较大、结构已知，用骨架屏更平滑
Spin —— 局部小区域加载，或整页转圈等待
```

## Empty

Empty 是空状态占位，当列表/表格无数据时展示，可提供自定义插图与操作入口。

```jsx
import { Empty, Button } from 'antd';

function OrderList({ orders }) {
  if (orders.length === 0) {
    return (
      <Empty
        description="暂无订单"
        image={Empty.PRESENTED_IMAGE_SIMPLE}
      >
        <Button type="primary">去下单</Button>
      </Empty>
    );
  }
  return <List dataSource={orders} renderItem={render} />;
}
```

```jsx
// 自定义图片与描述
<Empty
  image="https://example.com/empty.png"
  description={<span>没有找到相关结果</span>}
/>;
```

## Result

Result 是结果页组件，用于反馈「操作完成」的整体结果（成功、失败、403、404 等），常用于流程终点。

```jsx
import { Result, Button } from 'antd';

function SubmitResult({ success }) {
  if (success) {
    return (
      <Result
        status="success"
        title="提交成功"
        subTitle="你的申请已提交，请等待审核。"
        extra={<Button type="primary">返回首页</Button>}
      />
    );
  }
  return (
    <Result
      status="error"
      title="提交失败"
      subTitle="请检查网络后重试。"
      extra={<Button onClick={retry}>重新提交</Button>}
    />
  );
}
```

```jsx
// 404 页面
<Result status="404" title="404" subTitle="页面不存在" extra={<Button>返回</Button>} />;
```

## Spin

Spin 是加载中的转圈指示器，可包裹内容区域，用于局部加载等待。

```jsx
import { Spin } from 'antd';

function LoadingArea({ loading, children }) {
  return (
    <Spin spinning={loading} tip="加载中…">
      {children}
    </Spin>
  );
}
```

```jsx
// 全屏/独立加载
<Spin size="large" />;
<Spin size="small" />;

// 自定义文案
<Spin tip="数据加载中…">
  <div style={{ minHeight: 200 }} />
</Spin>;
```

## 应用场景实战

### 场景一：表单提交的完整反馈流

```jsx
import { useState } from 'react';
import { message, Spin, Result } from 'antd';

function SubmitForm() {
  const [status, setStatus] = useState('idle');  // idle | loading | success | error

  const handleSubmit = async (values) => {
    setStatus('loading');
    try {
      await apiSubmit(values);
      setStatus('success');
      message.success('提交成功');
    } catch (e) {
      setStatus('error');
      message.error('提交失败：' + e.message);
    }
  };

  if (status === 'loading') return <Spin tip="提交中…"><div style={{ minHeight: 200 }} /></Spin>;
  if (status === 'success') {
    return <Result status="success" title="提交成功" extra={<Button onClick={() => setStatus('idle')}>再填一次</Button>} />;
  }
  if (status === 'error') {
    return <Result status="error" title="提交失败" extra={<Button onClick={() => setStatus('idle')}>重试</Button>} />;
  }
  return <Form onFinish={handleSubmit} />;
}
```

### 场景二：列表加载的三态处理

```jsx
import { Skeleton, Empty, List } from 'antd';

function ProductList({ loading, products, error }) {
  if (loading) {
    return (
      <div>
        {[1, 2, 3].map(i => (
          <Skeleton key={i} avatar active paragraph={{ rows: 2 }} style={{ marginBottom: 12 }} />
        ))}
      </div>
    );
  }

  if (error) {
    return <Empty description="加载失败，请刷新重试" />;
  }

  if (products.length === 0) {
    return <Empty description="暂无商品" />;
  }

  return (
    <List
      dataSource={products}
      renderItem={p => <List.Item>{p.name} — ￥{p.price}</List.Item>}
    />
  );
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. 操作结果用 message（轻量），重要通知用 notification（带标题）
2. 列表/内容加载优先用 Skeleton，比整页 Spin 体验更好
3. 空状态用 Empty 并给出下一步操作入口，而非留白
4. 流程终点（提交/支付）用 Result 明确结果与后续动作
5. 明确进度用 Progress，不确定等待用 Spin/Skeleton

### 踩坑记录

```text
坑 1：message 在组件卸载后调用
结论：控制台报错或提示不显示。
原因：message 挂载在全局容器，异步回调在组件卸载后触发。
解法：在回调里判空，或用 App 包裹的 message 实例保证上下文。

坑 2：连续调用 message 造成堆积
结论：快速点击弹出几十条提示，体验差。
原因：每次操作都弹新 message，不限制。
解法：用 message 的 key 复用（message.success({ content, key }))，或防抖。

坑 3：loading 态没有超时兜底
结论：请求卡住时一直转圈。
原因：Spin/Skeleton 只由 loading 状态控制，无超时。
解法：请求加超时/取消，失败时切换到 error 态。

坑 4：空状态与错误状态混为一谈
结论：请求失败却显示「暂无数据」。
原因：没有区分 error 与 empty 两种状态。
解法：三态分别处理 loading / error / empty。

坑 5：Notification 默认不自动关闭导致堆积
结论：通知一直停留，占据屏幕。
原因：漏设 duration，默认 4.5s 但部分场景设为 0。
解法：明确设置 duration，重要通知才设 0（需手动关闭）。
```

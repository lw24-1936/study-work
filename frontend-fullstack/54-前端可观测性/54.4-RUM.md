## 概述

RUM（Real User Monitoring，真实用户监控）是采集真实用户在使用应用时的性能、错误和行为数据，反映真实体验的监控方式。与合成监控（Synthetic）不同，RUM 数据来自每一个真实用户，覆盖真实设备、网络和地域的多样性。

```text
RUM 采集的核心维度：
1. Performance —— 性能（LCP、INP、CLS、加载耗时）
2. Error —— 错误（JS 错误、资源错误、接口错误）
3. Device —— 设备（机型、屏幕、系统）
4. Browser —— 浏览器（类型、版本）
5. Network —— 网络（连接类型、速度）
6. Region —— 地域（用户所在地区）

RUM vs Synthetic（合成监控）：
RUM —— 真实用户真实数据，覆盖广、有真实环境差异，但不可控
Synthetic —— 固定脚本定时跑，可控可对比，但覆盖面窄
```

```js
// RUM 采集的数据结构示例
const rumData = {
  performance: { lcp: 2100, inp: 150, cls: 0.05 },
  error: { jsErrors: 3, apiErrors: 1 },
  device: { model: 'iPhone 15', os: 'iOS 17', screen: '393x852' },
  browser: { name: 'Safari', version: '17.4' },
  network: { type: '4g', effectiveType: '4g', rtt: 80 },
  region: { country: 'CN', city: 'Shanghai' },
  session: { id: 's_123', duration: 320 },
};
```

## Real User Monitoring

Real User Monitoring 的核心理念是"从用户视角看应用"，通过在真实用户浏览器里运行采集脚本，把每个用户的真实体验数据上报汇总。

```js
// RUM 采集脚本的核心逻辑
function initRUM() {
  // 1. 采集性能指标
  collectWebVitals();

  // 2. 采集错误
  collectErrors();

  // 3. 采集设备和环境信息
  collectEnvironment();

  // 4. 采集用户行为（可选）
  collectActions();
}

function collectWebVitals() {
  // 使用 web-vitals 或 PerformanceObserver 采集 LCP/INP/CLS
  const observer = new PerformanceObserver((list) => {
    for (const entry of list.getEntries()) {
      report({
        type: 'performance',
        name: entry.entryType,
        value: entry.startTime,
      });
    }
  });
  observer.observe({ entryTypes: ['largest-contentful-paint', 'layout-shift'] });
}

function collectErrors() {
  window.addEventListener('error', (e) => {
    report({ type: 'error', message: e.message, stack: e.error?.stack });
  });
  window.addEventListener('unhandledrejection', (e) => {
    report({ type: 'error', message: e.reason?.message });
  });
}
```

```text
RUM 的落地方式：
1. 自建 —— 自己写采集脚本 + 后端聚合存储
2. 开源 —— 用 OpenTelemetry + 后端存储方案
3. 商业平台 —— Sentry、Datadog、Dynatrace 等

自建 vs 平台：
自建可控但成本高（采集、存储、查询、可视化都要做），
平台开箱即用但按量收费，中小团队优先选平台。
```

## Performance

Performance 维度采集真实用户的性能数据，核心是 Core Web Vitals（LCP/INP/CLS）以及加载相关的耗时指标。

```js
// 采集真实用户性能数据
import { onLCP, onINP, onCLS, onTTFB, onFCP } from 'web-vitals';

function reportPerformance(metric) {
  report({
    type: 'performance',
    name: metric.name,       // LCP / INP / CLS / TTFB / FCP
    value: metric.value,
    rating: metric.rating,   // good / needs-improvement / poor
  });
}

onLCP(reportPerformance);
onINP(reportPerformance);
onCLS(reportPerformance);
onTTFB(reportPerformance);
onFCP(reportPerformance);
```

```js
// 采集自定义性能指标（如首屏渲染完成时间）
function measureFirstScreen() {
  const start = performance.now();
  // 业务首屏数据渲染完成的标记
  window.addEventListener('load', () => {
    setTimeout(() => {
      const firstScreenTime = performance.now() - start;
      report({ type: 'performance', name: 'first_screen', value: firstScreenTime });
    }, 0);
  });
}
```

```text
Performance 维度的分析：
1. 按评级分布 —— 多少用户 LCP 是 good，多少是 poor
2. 按分位 —— P75/P95，看最差体验的用户
3. 按维度对比 —— 哪些设备/网络/地域性能差

关键价值：
发现"真实用户"的性能问题，而非实验室环境的理想值。
同一页面在低端机和 3G 网络下可能性能极差。
```

## Error

Error 维度采集真实用户遇到的错误，包括 JS 错误、资源加载错误、接口错误，是衡量稳定性的核心数据。

```js
// 采集用户错误
function collectErrors() {
  // JS 运行时错误
  window.addEventListener('error', (e) => {
    if (e.target === window) {
      report({
        type: 'error',
        category: 'js',
        message: e.message,
        stack: e.error?.stack,
        filename: e.filename,
        lineno: e.lineno,
      });
    } else {
      // 资源加载错误
      report({
        type: 'error',
        category: 'resource',
        resource: e.target.tagName,
        url: e.target.src || e.target.href,
      });
    }
  }, true);

  // Promise 拒绝
  window.addEventListener('unhandledrejection', (e) => {
    report({
      type: 'error',
      category: 'promise',
      message: e.reason?.message || String(e.reason),
    });
  });
}
```

```text
Error 维度的分析：
1. 错误率 —— 发生错误的会话占比
2. 错误分布 —— 哪些错误最多、影响面最大
3. 错误趋势 —— 新版本发布后错误是否增加

与错误上报（53.5）的关系：
RUM 的 Error 维度是"聚合视角"（整体错误率、分布），
错误上报是"单条视角"（每次错误的详情），
两者配合：先用 RUM 看整体，再下钻到具体错误详情。
```

## Device

Device 维度采集用户的设备信息（机型、操作系统、屏幕），用于发现特定设备上的性能或兼容性问题。

```js
// 采集设备信息
function collectDevice() {
  const device = {
    type: getDeviceType(),        // mobile / tablet / desktop
    model: getDeviceModel(),      // 机型（从 UA 解析，如 iPhone 15）
    os: getOS(),                  // 操作系统
    osVersion: getOSVersion(),
    screen: `${screen.width}x${screen.height}`,
    devicePixelRatio: window.devicePixelRatio,
    memory: navigator.deviceMemory,   // 设备内存（部分浏览器）
  };

  report({ type: 'device', ...device });
}

function getDeviceType() {
  const ua = navigator.userAgent;
  if (/Mobile|Android|iPhone/.test(ua)) return 'mobile';
  if (/iPad|Tablet/.test(ua)) return 'tablet';
  return 'desktop';
}

function getDeviceModel() {
  const ua = navigator.userAgent;
  // 用 ua-parser-js 等库解析更准确
  const match = ua.match(/iPhone (\d+)/);
  return match ? `iPhone ${match[1]}` : 'Unknown';
}
```

```text
Device 维度的分析价值：
1. 兼容性 —— 某机型/系统上错误率高，定位兼容问题
2. 性能 —— 低端机 LCP 差，针对性优化
3. 适配 —— 屏幕尺寸分布，指导响应式设计

典型发现：
"Android 低端机上 INP 超 500ms" → 针对性减少主线程负载
"iOS 某版本上布局错乱" → 定位系统级兼容问题
```

## Browser

Browser 维度采集浏览器类型和版本，用于发现浏览器兼容性问题。

```js
// 采集浏览器信息
function collectBrowser() {
  const ua = navigator.userAgent;
  const browser = {
    name: getBrowserName(ua),     // Chrome / Safari / Firefox / Edge
    version: getBrowserVersion(ua),
    language: navigator.language,
    cookiesEnabled: navigator.cookieEnabled,
    doNotTrack: navigator.doNotTrack,
  };

  report({ type: 'browser', ...browser });
}

function getBrowserName(ua) {
  if (/Edg\//.test(ua)) return 'Edge';
  if (/Firefox\//.test(ua)) return 'Firefox';
  if (/Chrome\//.test(ua)) return 'Chrome';
  if (/Safari\//.test(ua)) return 'Safari';
  return 'Unknown';
}

function getBrowserVersion(ua) {
  const match = ua.match(/Chrome\/(\d+)/);
  return match ? match[1] : 'Unknown';
}
```

```text
Browser 维度的分析价值：
1. 兼容性 —— 某浏览器版本错误率高，定位兼容 bug
2. 覆盖度 —— 用户浏览器分布，决定支持的优先级
3. 特性支持 —— 新特性是否可安全使用（Feature Detection 参考）

典型发现：
"Firefox 上某功能报错" → 定位到 Firefox 不支持某 API
"Edge 用户占比 2%" → 决定是否投入资源做 Edge 专项兼容
```

## Network

Network 维度采集用户的网络连接类型和速度，用于分析弱网环境下的表现。

```js
// 采集网络信息
function collectNetwork() {
  const conn = navigator.connection;   // Network Information API

  const network = {
    type: conn?.type || 'unknown',           // wifi / 4g / 3g / 2g
    effectiveType: conn?.effectiveType || 'unknown',  // 有效连接类型
    downlink: conn?.downlink,               // 下行速度 Mbps
    rtt: conn?.rtt,                         // 往返时间 ms
    saveData: conn?.saveData || false,      // 是否省流量模式
  };

  report({ type: 'network', ...network });
}
```

```text
Network 维度的分析价值：
1. 弱网体验 —— 3G/2G 用户性能极差，考虑降级方案
2. 优化决策 —— 弱网用户占比高，资源要更轻量化
3. 问题定位 —— 慢请求是网络问题还是服务问题

典型发现：
"2G 用户 LCP 超 10s" → 针对弱网做资源瘦身、骨架屏
"WiFi 用户也慢" → 排除网络因素，定位服务端问题
```

## Region

Region 维度采集用户的地理位置，用于分析不同地域的性能和可用性差异（尤其对 CDN、多机房部署的团队）。

```js
// 采集地域信息
function collectRegion() {
  // 前端拿到的地域信息有限，通常由服务端根据 IP 解析
  // 前端可以采集一些辅助信息
  const region = {
    timezone: Intl.DateTimeFormat().resolvedOptions().timeZone,   // 时区
    locale: navigator.language,       // 语言区域（zh-CN、en-US）
  };

  report({ type: 'region', ...region });

  // 精确的地理位置（国家、城市）由后端根据请求 IP 解析并关联
}
```

```text
Region 维度的分析价值：
1. 地域性能差异 —— 某地区 CDN 覆盖差导致加载慢
2. 可用性 —— 某地域机房故障，错误率突增
3. 合规 —— 数据分布，满足数据本地化要求

前端与后端的配合：
前端采集时区、语言等辅助信息，
精确地理位置（国家/城市）由后端按 IP 解析，
上报时关联到同一会话。
```

## 应用场景实战

### 场景一：搭建 RUM 采集器

```js
// rum.js —— 轻量 RUM 采集器
const RUM = {
  init(endpoint) {
    this.endpoint = endpoint;
    this.sessionId = crypto.randomUUID();
    this.collectPerformance();
    this.collectErrors();
    this.collectEnvironment();
  },

  report(data) {
    const payload = {
      ...data,
      sessionId: this.sessionId,
      url: location.href,
      time: Date.now(),
      release: window.__APP_VERSION__,
    };
    navigator.sendBeacon(this.endpoint, JSON.stringify(payload));
  },

  collectPerformance() {
    new PerformanceObserver((list) => {
      for (const entry of list.getEntries()) {
        if (entry.entryType === 'largest-contentful-paint') {
          this.report({ type: 'perf', name: 'lcp', value: entry.startTime });
        }
      }
    }).observe({ type: 'largest-contentful-paint', buffered: true });
  },

  collectErrors() {
    window.addEventListener('error', (e) => {
      this.report({ type: 'error', message: e.message });
    }, true);
    window.addEventListener('unhandledrejection', (e) => {
      this.report({ type: 'error', message: String(e.reason) });
    });
  },

  collectEnvironment() {
    this.report({
      type: 'env',
      browser: navigator.userAgent,
      device: navigator.userAgent.includes('Mobile') ? 'mobile' : 'desktop',
      network: navigator.connection?.effectiveType,
      timezone: Intl.DateTimeFormat().resolvedOptions().timeZone,
    });
  },
};

RUM.init('/api/rum');
```

## 最佳实践与踩坑记录

### 最佳实践

1. 采集 Web Vitals（LCP/INP/CLS），而非只盯 onload 时间
2. 按设备、浏览器、网络、地域维度下钻分析，发现特定群体的体验问题
3. 错误按会话聚合计算错误率，而非按上报条数
4. RUM 数据采样或聚合上报，控制数据量和成本
5. 用 sendBeacon 上报，避免影响页面性能和丢失数据
6. 结合 RUM（真实数据）和 Synthetic（可控对比）互补监控

### 踩坑记录

```text
坑 1：只测实验室数据不测真实用户
结论：实验室性能满分，真实用户抱怨慢。
原因：只依赖 Lighthouse 等合成测试，忽略真实环境差异。
解法：部署 RUM 采集真实用户数据，覆盖设备和网络多样性。

坑 2：RUM 采集影响页面性能
结论：监控脚本本身拖慢页面。
原因：同步高频上报，阻塞主线程。
解法：异步批量上报，sendBeacon，采样控制频率。

坑 3：按上报条数算错误率
结论：错误率虚高，误报警。
原因：一个错误触发多次上报（多个事件监听）。
解法：按会话聚合，或按 errorId 去重计算。

坑 4：忽略弱网和低端机用户
结论：高端机数据好看，掩盖了长尾用户问题。
原因：只关注平均值和 P50。
解法：看 P95/P99，按设备/网络维度拆解。

坑 5：地域信息前端硬编码
结论：地域分析不准。
原因：前端拿不到准确地理位置，靠时区或语言猜测。
解法：后端按 IP 解析地域，前端只采集时区等辅助信息。
```

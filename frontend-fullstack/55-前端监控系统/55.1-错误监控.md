## 概述

前端错误监控是「可观测性」的第一块拼图。线上代码经过压缩混淆，用户遇到报错时开发者往往一无所知，因此需要在运行时捕获各类异常，附加上下文（用户、页面、网络、版本）后上报到监控平台（Sentry、自建平台等），以便快速定位和回归。

```text
前端错误监控的完整链路：
1. 采集 —— 在运行时捕获五类错误（JS/Promise/Resource/API/Chunk）
2. 聚合 —— 附加用户、页面、版本、网络、堆栈等上下文
3. 上报 —— 采样后通过 sendBeacon/图片/fetch 发送到监控后端
4. 还原 —— 用 Source Map 把压缩堆栈还原为源码位置
5. 告警 —— 按错误率、影响用户数触发告警

五类错误：
1. JS Error —— 同步代码抛出的异常（onerror）
2. Promise Error —— 未处理的 Promise 拒绝（unhandledrejection）
3. Resource Error —— 图片/脚本/样式加载失败（捕获阶段监听）
4. API Error —— 接口请求失败或业务码异常（拦截器）
5. Chunk Load Error —— 懒加载分包加载失败（webpack 运行时错误）
```

## JS Error

JS Error 是同步执行代码抛出的异常，通过 `window.onerror` 或 `addEventListener('error')` 捕获。

```js
// 方式一：window.onerror（只能绑定一个）
window.onerror = function (message, source, lineno, colno, error) {
  report({
    type: 'js',
    message,
    source,
    lineno,
    colno,
    stack: error ? error.stack : '',
  });
  return false; // 返回 true 可阻止浏览器默认报错行为
};

// 方式二：addEventListener（可多个，推荐）
window.addEventListener('error', (event) => {
  const { message, filename, lineno, colno, error } = event;
  report({ type: 'js', message, filename, lineno, colno, stack: error?.stack });
}, true);
```

```js
// 增强：配合 try/catch 捕获带上下文的同步错误
function safeRun(fn, meta = {}) {
  try {
    return fn();
  } catch (err) {
    report({ type: 'js', message: err.message, stack: err.stack, meta });
    throw err;
  }
}
```

## Promise Error

Promise 中被 reject 却没有 `.catch` 处理的错误，不会触发 `onerror`，需要用 `unhandledrejection` 捕获。

```js
window.addEventListener('unhandledrejection', (event) => {
  const reason = event.reason;
  report({
    type: 'promise',
    message: reason?.message || String(reason),
    stack: reason?.stack || '',
  });
  // event.preventDefault() 可阻止控制台默认警告
});

// 触发示例：下面这个 Promise 被 reject 但没人 catch
Promise.reject(new Error('接口数据解析失败'));
```

```js
// 注意：很多 Promise 错误来自 async/await 忘写 try/catch
async function loadUser() {
  const res = await fetch('/api/user'); // 若失败且无 catch，会成为 unhandledrejection
  return res.json();
}
// 正确写法
async function loadUserSafe() {
  try {
    const res = await fetch('/api/user');
    return await res.json();
  } catch (err) {
    report({ type: 'promise', message: err.message });
  }
}
```

## Resource Error

图片、脚本、样式等静态资源加载失败不会冒泡到 `window.onerror`，必须在**捕获阶段**监听 `error` 事件。

```js
// 资源错误：必须用捕获阶段（true），因为资源 error 不冒泡
window.addEventListener('error', (event) => {
  const target = event.target;
  if (!target) return;
  // 资源元素的错误：有 src/href 属性，且没有 error.stack
  const tagName = target.tagName?.toLowerCase();
  if (tagName === 'img' || tagName === 'script' || tagName === 'link') {
    report({
      type: 'resource',
      tagName,
      src: target.src || target.href || '',
    });
  }
}, true); // 捕获阶段关键
```

```html
<!-- 触发场景：图片 404、脚本 CDN 失效、样式跨域被拦 -->
<img src="https://cdn.example.com/banner.png" />
<script src="https://cdn.example.com/app.js"></script>
```

## API Error

API Error 指接口请求失败或返回业务错误，通常在请求库（fetch/axios）的拦截层统一处理。

```js
// 统一封装 fetch，拦截 HTTP 错误与业务码错误
async function request(url, options = {}) {
  let res;
  try {
    res = await fetch(url, options);
  } catch (err) {
    report({ type: 'api', url, stage: 'network', message: err.message });
    throw err;
  }
  if (!res.ok) {
    report({ type: 'api', url, stage: 'http', status: res.status });
    throw new Error(`HTTP ${res.status}`);
  }
  const data = await res.json();
  if (data.code !== 0) {
    report({ type: 'api', url, stage: 'biz', code: data.code, message: data.msg });
    throw new Error(data.msg);
  }
  return data.data;
}
```

```js
// axios 拦截器版
axios.interceptors.response.use(
  (resp) => resp,
  (error) => {
    report({
      type: 'api',
      url: error.config?.url,
      status: error.response?.status,
      message: error.message,
    });
    return Promise.reject(error);
  },
);
```

## Chunk Load Error

Chunk Load Error 是代码分包懒加载时，动态导入的 chunk 文件加载失败（CDN 失效、版本不匹配、网络中断），在 webpack/Vite 生态中非常常见，典型表现为 `Loading chunk xxx failed`。

```js
// webpack 动态导入报错：TypeError: Loading chunk 3 failed.
// 处理：对 dynamic import 做重试与降级
async function lazyLoad(importFn, retries = 3) {
  for (let i = 0; i < retries; i++) {
    try {
      return await importFn();
    } catch (err) {
      const isChunkError = /Loading chunk .* failed/.test(err.message);
      if (!isChunkError) throw err;
      report({ type: 'chunk', message: err.message, retry: i + 1 });
      if (i === retries - 1) {
        // 最终降级：提示用户刷新
        alert('网络异常，请刷新页面重试');
        throw err;
      }
    }
  }
}

// React.lazy 使用示例
const Settings = lazy(() => lazyLoad(() => import('./Settings')));
```

```js
// 兜底：全局监听 chunk 加载失败（覆盖运行时动态加载的脚本）
window.addEventListener('error', (event) => {
  const msg = event.message || '';
  if (/Loading chunk|error loading dynamically imported module/i.test(msg)) {
    report({ type: 'chunk', message: msg });
    // 可选：刷新页面尝试重新加载
  }
}, true);
```

## 应用场景实战

### 场景一：自建轻量错误监控 SDK

```js
// 一个最小可用的错误采集 SDK
const monitor = {
  init({ appId, dsn }) {
    this.appId = appId;
    this.dsn = dsn;
    this._bindGlobal();
  },
  _bindGlobal() {
    window.addEventListener('error', (e) => {
      if (e.target?.src) return this._report('resource', { src: e.target.src });
      this._report('js', { message: e.message, stack: e.error?.stack });
    }, true);
    window.addEventListener('unhandledrejection', (e) => {
      this._report('promise', { message: e.reason?.message });
    });
  },
  _report(type, payload) {
    const body = {
      appId: this.appId,
      type,
      ...payload,
      ua: navigator.userAgent,
      url: location.href,
      time: Date.now(),
    };
    navigator.sendBeacon(this.dsn, JSON.stringify(body));
  },
};

monitor.init({ appId: 'web-shop', dsn: '/api/collect/error' });
```

### 场景二：错误聚合去重

```js
// 同一错误大量重复上报会淹没监控，做指纹去重
function fingerprint(message, stack = '') {
  // 取堆栈首行（源码位置）作为指纹，忽略行号列号的可变性
  const firstFrame = stack.split('\n').slice(1, 4).join('|');
  return `${message}@${firstFrame}`.slice(0, 200);
}

const seen = new Map();
function report(err) {
  const key = fingerprint(err.message, err.stack);
  const prev = seen.get(key);
  const now = Date.now();
  if (prev && now - prev.time < 60_000) {
    prev.count++;
    return; // 一分钟内重复，只计数不上报
  }
  seen.set(key, { time: now, count: 1 });
  send({ ...err, fingerprint: key });
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. 统一封装一个 `report` 函数，所有错误走同一条上报通道
2. JS/Resource 错误用捕获阶段 `addEventListener('error', ..., true)`
3. Promise 错误单独监听 `unhandledrejection`
4. API 错误在请求库拦截层统一处理，区分网络/HTTP/业务码三类
5. 上报时附带版本号、用户 ID、页面 URL，方便定位「哪个版本引入」
6. 做指纹去重与采样，避免高频错误刷爆后端
7. 用 `navigator.sendBeacon` 上报，页面卸载时也不丢数据
8. 敏感数据（token、手机号）在上报前脱敏

### 踩坑记录

```text
坑 1：Resource Error 监听不到
结论：图片/脚本加载失败不触发 onerror。
原因：资源加载错误不冒泡，且 onerror 只处理 JS 运行时错误。
解法：用 window 捕获阶段监听 error，并判断 target 是资源元素。

坑 2：跨域脚本错误只有 Script error.
结论：跨域 JS 报错 message 被浏览器抹成 "Script error."。
原因：浏览器同源策略隐藏跨域脚本细节。
解法：script 标签加 crossorigin="anonymous"，CDN 返回 CORS 头。

坑 3：Promise 错误捕获不到
结论：reject 的 Promise 没有任何上报。
原因：unhandledrejection 未监听，且 onerror 不覆盖 Promise。
解法：监听 unhandledrejection，代码里 async/await 尽量配 try/catch。

坑 4：Chunk Load Error 大量爆发
结论：发版后用户端大量 "Loading chunk failed"。
原因：旧 HTML 引用了已被删除的旧 chunk 文件名（哈希不匹配）。
解法：chunk 文件保留多个历史版本，或捕获后提示刷新重新拉取。

坑 5：sendBeacon 在部分场景失败
结论：上报偶发丢失。
原因：sendBeacon 有 64KB 体积限制，且不支持自定义请求头。
解法：大数据用 fetch keepalive，或拆小包分批上报。
```

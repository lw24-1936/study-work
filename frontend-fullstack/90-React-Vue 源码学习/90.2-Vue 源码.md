## 概述

Vue 3 源码拆成「响应式 + 运行时 + 编译器」三大模块：@vue/reactivity 用 Proxy 做依赖收集与触发，@vue/runtime-core 提供与平台无关的 VNode 与渲染器，@vue/compiler-core 把模板编译成渲染函数，最终由 Scheduler 统一调度更新。读懂 Vue 源码的关键，是抓住「状态变化 → effect 触发 → 组件重新渲染 → patch 更新 DOM」这条主链路。

```text
Vue 3 的模块划分（monorepo packages）：
1. @vue/reactivity   —— 响应式系统：reactive/ref/effect，Proxy + track/trigger
2. @vue/runtime-core —— 运行时核心：VNode、组件实例、渲染器、调度器，平台无关
3. @vue/runtime-dom  —— 运行时 DOM：DOM 渲染器、事件与属性 patch
4. @vue/compiler-core —— 编译器核心：模板 → AST → transform → codegen，平台无关
5. @vue/compiler-dom  —— 编译器 DOM：v-model/v-show/v-html 等 DOM 相关转换
```

```js
// 一条完整链路的简化示意
import { reactive, effect } from '@vue/reactivity';

const state = reactive({ count: 0 });
effect(() => {
  // 读取 count 时收集依赖，count 变化时重新执行
  console.log('count =', state.count);
});
state.count++; // 触发依赖，打印 count = 1
```

## Reactivity

Reactivity 是 Vue 响应式的根基：用 Proxy 拦截对象读写，读取时 track 收集依赖，写入时 trigger 触发依赖。每个响应式对象对应一个 dep（依赖集合），effect 是依赖的最小执行单元。

```js
// 响应式系统的核心：track / trigger（简化）
const targetMap = new WeakMap(); // 对象 → key → dep

function track(target, key) {
  let depsMap = targetMap.get(target);
  if (!depsMap) targetMap.set(target, (depsMap = new Map()));
  let dep = depsMap.get(key);
  if (!dep) depsMap.set(key, (dep = new Set()));
  if (activeEffect) dep.add(activeEffect); // 收集当前正在执行的 effect
}

function trigger(target, key) {
  const dep = targetMap.get(target)?.get(key);
  dep && dep.forEach(effect => effect()); // 触发所有依赖
}

function reactive(obj) {
  return new Proxy(obj, {
    get(target, key, receiver) {
      track(target, key);
      return Reflect.get(target, key, receiver);
    },
    set(target, key, value, receiver) {
      Reflect.set(target, key, value, receiver);
      trigger(target, key);
      return true;
    },
  });
}
```

```text
Reactivity 的要点：
1. Proxy 拦截 —— 比 Object.defineProperty 多了数组下标、新增属性、delete 的拦截
2. 懒收集 —— 只有被读取的 key 才进入依赖，没读过的 key 变化不会触发
3. 依赖清理 —— 每次执行 effect 前清空旧依赖，避免「幽灵依赖」
4. ref —— 内部也是 reactive，只是包了一层 value 访问器
```

## VNode

VNode（虚拟节点）是运行时对真实 DOM 的轻量描述，也是组件、元素、文本、注释的统一抽象。Vue 用 shapeFlag 标记节点类型，用 patchFlag 标记「哪些部分可能变化」，供编译器与 diff 优化使用。

```js
// VNode 结构（简化）
function createVNode(type, props, children) {
  const shapeFlag = typeof type === 'string'
    ? 1 /* ELEMENT */
    : 1 << 2 /* COMPONENT */;
  return {
    type,           // 元素名 或 组件对象
    props,          // 属性 / 事件
    children,       // 子节点（数组 / 文本）
    shapeFlag,      // 节点类型位标记
    patchFlag: 0,   // 编译期打上的「动态标记」
    el: null,       // 对应的真实 DOM（patch 后回填）
    component: null,// 组件实例
  };
}
```

```text
VNode 的两个位标记：
1. shapeFlag —— 描述「这是什么」：元素/组件/文本/注释/Suspense/Teleport
2. patchFlag —— 描述「哪里会变」：TEXT/CLASS/PROPS/FULL_PROPS，编译器静态分析生成
3. patchFlag 的意义 —— 让 diff 只对比可能变化的 props，跳过静态内容
```

## Renderer

Renderer 是渲染器，负责把 VNode 真正变成 DOM，并处理后续的更新（patch）。它通过 createRenderer 传入平台相关的节点/属性操作，实现「核心逻辑与平台解耦」。

```js
// 渲染器骨架（简化）
function createRenderer(options) {
  const { createElement, insert, setElementText, patchProp } = options;

  function patch(n1, n2, container) {
    if (n1 === n2) return;
    if (n1 == null) {
      mountElement(n2, container);        // 首次挂载
    } else if (n1.type !== n2.type) {
      unmount(n1);
      mountElement(n2, container);        // 类型不同，整体替换
    } else {
      patchElement(n1, n2);               // 更新
    }
  }

  function mountElement(vnode, container) {
    const el = (vnode.el = createElement(vnode.type));
    for (const key in vnode.props) patchProp(el, key, null, vnode.props[key]);
    vnode.children && mountChildren(vnode.children, el);
    insert(el, container);
  }

  return { render(vnode, container) { patch(null, vnode, container); } };
}
```

```text
Renderer 的分层：
1. 平台无关 —— 核心 patch 逻辑在 runtime-core，不碰 DOM API
2. 平台相关 —— createElement/insert/patchProp 由 runtime-dom 注入
3. 可移植 —— 同样的核心可驱动 DOM、Canvas、终端（如 vue-server-renderer）
```

## Runtime Core

Runtime Core 是与平台无关的运行时核心：组件实例的创建、setup 的执行、生命周期钩子的调度、渲染函数与响应式的结合都在这一层完成，不依赖任何 DOM API。

```js
// 组件实例与渲染流程（简化）
function mountComponent(vnode, container) {
  const instance = {
    vnode,
    props: vnode.props,
    setupState: null,
    render: null,
    isMounted: false,
  };

  // 1. 执行 setup，拿到响应式状态与渲染函数
  const setupResult = vnode.type.setup?.(vnode.props) || {};
  instance.render = vnode.type.render;
  instance.setupState = setupResult;

  // 2. 用 effect 包住渲染，状态变化自动重渲染
  instance.update = effect(() => {
    const subTree = instance.render.call(instance.setupState);
    patch(instance.subTree, subTree, container); // 旧树 diff 新树
    instance.subTree = subTree;
  });

  instance.update();
}
```

```text
Runtime Core 的关键职责：
1. 组件实例 —— 承载 props/setupState/render/生命周期钩子
2. 渲染 effect —— 把「渲染函数」变成响应式的副作用，状态一变就重渲染
3. 生命周期 —— onMounted/onUpdated 等，通过实例上的钩子数组在恰当时机调用
4. 依赖注入 —— provide/inject 沿组件树向下查找
```

## Runtime DOM

Runtime DOM 是 DOM 平台的运行时实现，给渲染器注入具体的 DOM 操作：创建元素、设置属性、绑定事件、更新文本等，是「渲染器核心」落到浏览器的一层。

```js
// runtime-dom 注入的节点与属性操作（简化）
export const nodeOps = {
  createElement: tag => document.createElement(tag),
  createText: text => document.createTextNode(text),
  insert: (child, parent, anchor) => parent.insertBefore(child, anchor || null),
  remove: child => child.parentNode.removeChild(child),
  setElementText: (el, text) => (el.textContent = text),
};

export function patchProp(el, key, prev, next) {
  if (key.startsWith('on')) {
    // 事件：onClick → click
    const event = key.slice(2).toLowerCase();
    prev && el.removeEventListener(event, prev);
    el.addEventListener(event, next);
  } else if (key === 'class') {
    el.className = next;
  } else if (key === 'style') {
    for (const k in next) el.style[k] = next[k];
  } else if (key in el) {
    el[key] = next; // 如 value、checked 等 DOM 属性
  } else {
    el.setAttribute(key, next);
  }
}
```

```text
Runtime DOM 的要点：
1. 事件绑定 —— 模板里的 @click 编译成 onClick，patchProp 里转成 addEventListener
2. class/style —— 单独处理，支持对象/数组语法
3. DOM property 优先 —— value/checked 用 el[key] 赋值而非 setAttribute
4. 这是 Vue 2 与 3 都有的「平台模块」，但 3 里真正解耦成了独立包
```

## Compiler Core

Compiler Core 是模板编译器的核心：把 template 字符串解析成 AST，再做静态分析（标记动态节点、打 patchFlag），最后生成渲染函数代码。它同样平台无关，只负责字符串到代码。

```js
// 编译管道的三步（简化）
function compile(template) {
  const ast = parse(template);      // 1. 模板 → AST
  transform(ast, nodeTransforms);   // 2. AST 转换 + 静态分析
  const code = generate(ast);       // 3. AST → 渲染函数代码
  return new Function(code);
}
```

```text
Compiler Core 的三阶段：
1. parse —— 模板字符串 → AST，记录每个节点与指令
2. transform —— 遍历 AST，做静态提升、打 patchFlag、标记动态节点
3. generate —— AST → render 函数代码（返回 VNode 的 js 字符串）
4. 核心产物是「更聪明的渲染函数」，静态部分提升、动态部分打标
```

## Compiler DOM

Compiler DOM 是 DOM 平台相关的编译转换，处理只在浏览器里有意义的指令：v-model 拆成 value 绑定 + input 事件，v-show 编译成 display 切换，v-html 编译成 innerHTML 设置。

```js
// v-model 的编译产物（示意）
// 模板：<input v-model="msg">
// 编译后大致等价于：
h('input', {
  value: msg,                          // :value 绑定
  onInput: e => { msg = e.target.value; } // @input 更新
});
```

```text
Compiler DOM 的转换：
1. v-model —— 按元素类型拆分：text → value+input，checkbox → checked+change
2. v-show —— 编译成 style.display 的切换，而非 v-if 的挂载/卸载
3. v-html —— 编译成 innerHTML，需警惕 XSS
4. v-text —— 编译成 textContent
```

## Scheduler

Scheduler 是 Vue 的调度器：同一轮里多次修改状态只触发一次组件重渲染。它把待更新的任务放进队列，用微任务（Promise.then）在下一轮统一执行，从而「去重」并保证更新顺序。

```js
// 调度队列（简化）
const queue = new Set();   // 待更新的组件，Set 去重
let flushing = false;

function queueJob(job) {
  queue.add(job);
  if (!flushing) {
    flushing = true;
    Promise.resolve().then(() => {
      queue.forEach(job => job()); // 微任务里统一执行
      queue.clear();
      flushing = false;
    });
  }
}

// nextTick 的实现：把回调放到本轮队列之后
function nextTick(fn) {
  return Promise.resolve().then(fn);
}
```

```text
Scheduler 的机制：
1. 去重 —— 同一组件多次触发只入队一次
2. 微任务 —— Promise.then 保证在本次宏任务后、渲染前执行
3. 父子顺序 —— 父组件先于子组件更新（按创建顺序）
4. nextTick —— 想在 DOM 更新后做操作，必须等 nextTick
```

## Diff

Diff 是渲染器的核心算法，对比新旧 VNode 子节点数组，用最少的操作更新 DOM。Vue 3 采用「双端比较 + 最长递增子序列」的优化，对可复用节点只做移动而非重建。

```js
// keyed diff 的思路（简化示意）
function patchKeyedChildren(c1, c2, container) {
  // 1. 从头部开始，type/key 相同的直接复用
  let i = 0;
  while (i < c1.length && i < c2.length && isSameVNode(c1[i], c2[i])) {
    patch(c1[i], c2[i], container);
    i++;
  }
  // 2. 中间无法简单对齐的部分，用 key 建立映射
  const keyMap = new Map();
  for (let j = i; j < c1.length; j++) keyMap.set(c1[j].key, j);
  // 3. 找出最长递增子序列，这部分节点不动，其余节点移动
  //    （实际实现更复杂，此处省略 LIS 细节）
}

function isSameVNode(a, b) {
  return a.type === b.type && a.key === b.key;
}
```

```text
Diff 的优化手段：
1. key 复用 —— key 相同的节点视为「同一节点」，只更新不重建
2. 双端比较 —— 头头/尾尾/头尾/尾头 四次快速对齐
3. 最长递增子序列 —— 计算最少移动次数，稳定序列保持不动
4. patchFlag 跳过 —— 静态节点直接跳过，只 patch 动态部分
```

## 应用场景实战

### 场景一：手写一个最小响应式系统

```js
// 极简版 Vue 响应式：能跑通 track/trigger/effect
let activeEffect = null;
const deps = new WeakMap();

function reactive(obj) {
  return new Proxy(obj, {
    get(target, key) {
      if (activeEffect) {
        let map = deps.get(target) || deps.set(target, new Map()).get(target);
        let set = map.get(key) || map.set(key, new Set()).get(key);
        set.add(activeEffect);
      }
      return Reflect.get(target, key);
    },
    set(target, key, value) {
      Reflect.set(target, key, value);
      const set = deps.get(target)?.get(key);
      set && set.forEach(fn => fn());
      return true;
    },
  });
}

function effect(fn) {
  activeEffect = fn;
  fn();          // 首次执行，完成依赖收集
  activeEffect = null;
}

const state = reactive({ a: 1, b: 2 });
effect(() => console.log('a =', state.a)); // 打印 a = 1
state.a = 10;                              // 触发，打印 a = 10
state.b = 20;                              // 没被收集，无输出
```

### 场景二：看懂一次 v-model 的完整链路

```text
<input v-model="msg"> 从模板到 DOM 的链路：
1. Compiler DOM 把 v-model 拆成 :value="msg" + @input
2. Compiler Core 生成 render 函数，value 绑定打上 PROPS patchFlag
3. 组件 effect 首次执行，创建 input，把 msg 渲染成 value
4. 用户输入 → input 事件 → msg = e.target.value → 触发 setter
5. trigger 触发组件 effect → Scheduler 入队 → 微任务统一重渲染
6. patch 阶段发现 value 变化，更新 input.value
```

## 最佳实践与踩坑记录

### 最佳实践

1. 响应式对象用 reactive/ref 包裹，但别对同一个对象混用两种声明
2. 列表渲染始终给稳定 key，key 是 diff 复用的唯一凭据
3. 大对象里不经常变的字段用 shallowRef/shallowReactive 减少代理开销
4. 需要 DOM 更新后再操作时，用 nextTick 而不是 setTimeout
5. 避免在模板里写复杂表达式，静态分析与 patchFlag 都受益于简单结构
6. 读源码先画「数据流图」，再对着 packages 目录逐包击破

### 踩坑记录

```text
坑 1：直接给 reactive 对象整体赋值
结论：state = { count: 0 } 之后响应式失效。
原因：reactive 返回的是 Proxy，整体替换丢掉了代理引用。
解法：用 ref 包住需要整体替换的值，或改属性 state.count = 0。

坑 2：解构 reactive 对象丢失响应式
结论：const { count } = state 后 count 不再响应。
原因：解构是对原始值取值，绕过了 Proxy 的 get 拦截。
解法：用 toRefs(state) 保留响应式，或直接读 state.count。

坑 3：在 nextTick 之外读更新后的 DOM
结论：修改状态后立刻读 DOM 拿到旧值。
原因：Scheduler 用微任务异步更新，DOM 还没变。
解法：await nextTick() 后再读 DOM。

坑 4：v-for 用 index 当 key
结论：列表增删/排序时状态错位。
原因：index 不稳定，diff 把不同数据复用成了同一节点。
解法：用数据稳定的唯一 id 当 key。

坑 5：v-html 直接渲染用户输入
结论：页面被注入恶意脚本，触发 XSS。
原因：v-html 直接把字符串写进 innerHTML。
解法：用户输入用文本插值，确需富文本时先做消毒处理。
```

## 概述

Code Generation（代码生成，简称 Codegen）是编译流水线的最后一站：把 Transform 之后的 AST 序列化成目标代码字符串。它的输出可能是 JS、字节码、机器码，甚至是另一种语言的源码，关键在于「忠实还原 AST 的语义」。

```text
Codegen 在编译流程中的位置：
1. Parser → AST → Transform → AST → Codegen → 目标代码字符串
2. Codegen 是 AST 的「打印器」，按节点类型递归拼接字符串
3. 同时维护位置映射，用于生成 Source Map
```

```js
// 一个极简 Codegen：把 AST 转回 JS 字符串
function generate(node) {
  switch (node.type) {
    case 'Literal': return String(node.value);
    case 'Identifier': return node.name;
    case 'BinaryExpression':
      return `${generate(node.left)} ${node.operator} ${generate(node.right)}`;
    case 'VariableDeclaration':
      return `${node.kind} ${generate(node.id)} = ${generate(node.init)};`;
    default: throw new Error(`未知节点: ${node.type}`);
  }
}
```

## Codegen

Codegen 的本质是「按节点类型递归打印」：每个节点类型对应一段模板字符串，把子节点的生成结果拼进去。真实实现（如 Babel 的 @babel/generator）还会处理缩进、换行、注释保留、括号优先级、字符串转义等细节。

```js
// 带缩进与优先级的 Codegen（简化）
function generate(node, indent = '') {
  switch (node.type) {
    case 'Program':
      return node.body.map(s => generate(s, indent)).join('\n');
    case 'BinaryExpression': {
      // 根据优先级决定是否加括号
      const code = `${generate(node.left)} ${node.operator} ${generate(node.right)}`;
      const needParen = node.parent && node.parent.type === 'BinaryExpression'
        && precedence(node.operator) < precedence(node.parent.operator);
      return needParen ? `(${code})` : code;
    }
    case 'Literal':
      return typeof node.value === 'string' ? `"${node.value}"` : String(node.value);
    default:
      throw new Error(`未实现的节点: ${node.type}`);
  }
}
```

```text
Codegen 的关注点：
1. 字符串拼接 —— 按类型分派，子节点结果递归拼入
2. 优先级与括号 —— 嵌套表达式要按优先级加括号，避免改变语义
3. 缩进与换行 —— 输出可读性，也影响 Source Map 的行列
4. 转义 —— 字符串里的引号、换行、特殊字符要正确转义
5. 注释保留 —— 可选地保留源码注释（如 Babel 的 comments 选项）
```

## Source Map

Source Map 是一份「目标代码 ↔ 源文件」的位置映射，让浏览器在报错、断点时能把「压缩后代码的行列」还原到「原始源码的行列」。它在 Codegen 阶段生成，是前端调试与线上错误定位的基石。

```js
// Source Map 的核心数据结构（VLQ 编码前）
{
  version: 3,
  sources: ['input.js'],       // 源文件列表
  names: ['a', 'b', 'sum'],    // 标识符名列表
  mappings: 'AAAA,SAASA,MAAM', // VLQ 编码的位置映射
}
```

```text
Source Map 的要点：
1. mappings —— 用 VLQ（变长 base64）编码「生成列、源文件、源行、源列、名字」
2. 生成时机 —— Codegen 每次写出一段代码，就记录一次对应位置
3. 两种模式 —— inline（base64 内嵌）/ 独立 .map 文件（配合 sourceMappingURL）
4. 作用 —— dev 定位报错、线上还原堆栈、热更新与覆盖率统计都依赖它
```

## 应用场景实战

### 场景一：给算术 AST 生成 JS 代码

```js
// 输入 AST，输出可执行的 JS 字符串
const ast = {
  type: 'BinaryExpression', operator: '*',
  left: { type: 'BinaryExpression', operator: '+',
          left: { type: 'Literal', value: 1 },
          right: { type: 'Literal', value: 2 } },
  right: { type: 'Literal', value: 3 },
};

function gen(node) {
  if (node.type === 'Literal') return String(node.value);
  const left = gen(node.left);
  const right = gen(node.right);
  const code = `${left} ${node.operator} ${right}`;
  // 子表达式优先级低于当前时加括号
  const wrap = node.left.type === 'BinaryExpression' && node.operator === '*';
  return wrap ? `(${code})` : code;
}

console.log(gen(ast)); // (1 + 2) * 3
```

### 场景二：用 source-map 库还原线上错误位置

```js
const { SourceMapConsumer } = require('source-map');

async function locateError(stackLine) {
  // 从线上 .map 文件加载 consumer
  const raw = await fetch('/dist/app.js.map').then(r => r.text());
  const consumer = await new SourceMapConsumer(raw);
  const pos = consumer.originalPositionFor({
    line: stackLine.line, column: stackLine.column,
  });
  return `${pos.source}:${pos.line}:${pos.column} (${pos.name})`;
}

// 把压缩后报错的 1:2345 还原成 src/index.js:42:10
```

## 最佳实践与踩坑记录

### 最佳实践

1. Codegen 与 Parser 互为逆过程，写完生成器后做「parse(generate(ast))」往返测试
2. 括号处理用优先级表统一判断，别散落在各节点里
3. 生产构建必须产出 Source Map 并上传监控平台，线上报错才能定位
4. Source Map 别暴露到生产公开访问，避免源码泄露，做好访问控制
5. 字符串转义、Unicode、正则字面量要单独测试，是生成器最常见 bug

### 踩坑记录

```text
坑 1：嵌套表达式漏加括号
结论：生成 (1 + 2) * 3 时丢括号变成 1 + 2 * 3，语义错。
原因：只在顶层判断括号，没按子表达式优先级判断。
解法：每个表达式生成时对比父子运算符优先级决定是否加括号。

坑 2：字符串没转义
结论：字符串里含引号或换行，生成的代码直接语法错误。
原因：直接把 value 原样拼进模板，没做转义。
解法：统一走转义函数，处理引号、反斜杠、换行、制表符。

坑 3：Source Map 的 mappings 与代码行不对齐
结论：断点/报错定位偏移几行，误导排查。
原因：Codegen 里拼接换行时没有同步更新行列计数器。
解法：每写一行代码就推进一次行列，严格按写入顺序记录映射。

坑 4：生产环境把 Source Map 也发到了公网
结论：攻击者拿到完整源码，暴露密钥与逻辑。
原因：构建产物连同 .map 一起部署且未做访问控制。
解法：.map 文件只对内部监控系统开放，或改用 hidden-source-map。

坑 5：Codegen 丢失注释导致 license 缺失
结论：打包产物丢了版权头注释，合规风险。
原因：默认丢弃 AST 里的注释节点。
解法：保留注释节点并在生成时输出，或单独注入 banner。
```

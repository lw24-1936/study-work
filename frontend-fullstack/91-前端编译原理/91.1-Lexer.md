## 概述

Lexer（词法分析器）是编译流水线的第一站，负责把一段原始源码字符串切分成一个个有意义的 Token 序列，供后续的 Parser 使用。它不关心语法结构，只做「字符流 → 单词流」的切分与分类。

```text
Lexer 在编译流程中的位置：
1. 源码字符串 → Lexer → Token 序列 → Parser → AST
2. Lexer 只回答「这些字符组成什么词」，不管「这些词怎么组合」
3. 输出是带类型、位置信息的 Token 数组
```

```js
// 一个简单的加法表达式词法分析
const tokens = tokenize('let x = 1 + 2');
// 输出类似：
// [ {type:'keyword', value:'let'},
//   {type:'ident',  value:'x'},
//   {type:'op',     value:'='},
//   {type:'number', value:'1'},
//   {type:'op',     value:'+'},
//   {type:'number', value:'2'} ]
```

## Token

Token 是词法分析的最小产物，代表源码中的一个「词」，通常包含类型、原始值、以及源码中的位置信息（行号、列号），供报错定位与 Source Map 使用。

```js
// Token 的数据结构
{
  type: 'number',   // 词的类型：keyword/ident/number/string/punct/...
  value: '42',      // 词面值
  start: 10,        // 在源码中的起始位置
  end: 12,          // 结束位置
  line: 1,          // 行号（用于报错）
  column: 10,       // 列号
}
```

```text
Token 的常见类型：
1. keyword —— let/const/if/return 等保留字
2. ident   —— 变量名、函数名等标识符
3. number  —— 数字字面量（含小数、指数、十六进制）
4. string  —— 字符串字面量（单/双引号、模板串）
5. punct   —— 标点符号（括号、逗号、运算符）
6. eof     —— 结束标记，Parser 以此判断输入结束
```

## Tokenization

Tokenization（分词）是 Lexer 的核心工作：顺序扫描字符，根据首字符决定这个词的类型，再用状态机/正则把整个词读完，跳过空白与注释，产出 Token 列表。

```js
// 手写一个极简 JS 分词器
function tokenize(input) {
  const tokens = [];
  let i = 0;
  while (i < input.length) {
    const ch = input[i];
    if (/\s/.test(ch)) { i++; continue; }              // 跳过空白

    if (/[a-zA-Z_$]/.test(ch)) {                       // 标识符/关键字
      let j = i;
      while (j < input.length && /[\w$]/.test(input[j])) j++;
      const word = input.slice(i, j);
      const keywords = new Set(['let', 'const', 'if', 'return', 'function']);
      tokens.push({ type: keywords.has(word) ? 'keyword' : 'ident', value: word });
      i = j; continue;
    }

    if (/\d/.test(ch)) {                               // 数字
      let j = i;
      while (j < input.length && /[\d.]/.test(input[j])) j++;
      tokens.push({ type: 'number', value: input.slice(i, j) });
      i = j; continue;
    }

    if ('+-*/=(){};,'.includes(ch)) {                 // 运算符/标点
      tokens.push({ type: 'punct', value: ch });
      i++; continue;
    }

    throw new Error(`无法识别的字符: ${ch} at ${i}`);
  }
  tokens.push({ type: 'eof', value: '' });
  return tokens;
}

console.log(tokenize('let x = 1 + 2'));
```

```text
Tokenization 的要点：
1. 首字符决定类型 —— 看到字母走标识符，看到数字走数字，看到引号走字符串
2. 最长匹配 —— 尽量读完整的词，例如 '>=' 不能只读 '>'
3. 跳过空白与注释 —— 它们不产生 Token，但换行要计入行号
4. 状态机/正则 —— 复杂语言用有限状态机，简单场景正则够用
```

## 应用场景实战

### 场景一：给模板引擎写一个分词器

```js
// 把 'hello {{name}}!' 拆成文本与插值两种 Token
function tokenizeTemplate(str) {
  const tokens = [];
  const re = /\{\{(.+?)\}\}/g;
  let last = 0, m;
  while ((m = re.exec(str))) {
    if (m.index > last) tokens.push({ type: 'text', value: str.slice(last, m.index) });
    tokens.push({ type: 'expr', value: m[1].trim() });
    last = re.lastIndex;
  }
  if (last < str.length) tokens.push({ type: 'text', value: str.slice(last) });
  return tokens;
}

console.log(tokenizeTemplate('hello {{name}}!'));
// [{type:'text',value:'hello '}, {type:'expr',value:'name'}, {type:'text',value:'!'}]
```

### 场景二：识别一个 JSON 字符串的词法结构

```text
输入：{"name":"vue","version":3}
分词结果：
1. {        → punct
2. "name"   → string
3. :        → punct
4. "vue"    → string
5. ,        → punct
6. "version"→ string
7. :        → punct
8. 3        → number
9. }        → punct
10. eof     → eof

Parser 拿到这串 Token 后，就能按 JSON 文法构建对象。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 每个 Token 都带上位置信息，报错与 Source Map 都依赖它
2. 用「首字符分派」而不是整段正则匹配，性能更好也更易读
3. 数字、字符串、模板串的处理要单独写函数，别塞进主循环
4. 最后一定要补 eof Token，让 Parser 有明确的结束信号
5. 字符串里的转义、引号配对要小心处理，是分词器最常见的 bug 源

### 踩坑记录

```text
坑 1：字符串里包含引号导致提前截断
结论：'it\\'s' 被切成了 'it' + s'，后续解析全错。
原因：没有处理转义字符，遇到 \\' 就误判为字符串结束。
解法：读到 \\ 时把下一个字符一起吞掉，不当作结束符。

坑 2：没有跳过注释
结论：// comment 被当成运算符切分，Parser 报语法错误。
原因：注释不是语言语法的一部分，但 Lexer 必须识别并丢弃。
解法：遇到 // 或 /* 时跳到注释结束再继续。

坑 3：>= 被拆成 > 和 =
结论：比较运算被拆成两个运算符，语义完全变了。
原因：按单字符判断，没有做最长匹配。
解法：运算符按「最长匹配」优先，先试两位运算符再试一位。

坑 4：忘了 eof Token
结论：Parser 读到最后以为还有内容，陷入死循环或越界。
原因：缺少明确的输入结束标记。
解法：词法分析结束时显式 push 一个 eof Token。

坑 5：数字与标识符边界不清
结论：3abc 被识别成一个词，语义错误。
原因：读到数字后又继续读字母，混成了一个 Token。
解法：数字只读数字和小数点，遇到字母立即结束。
```

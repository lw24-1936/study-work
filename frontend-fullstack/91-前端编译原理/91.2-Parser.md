## 概述

Parser（语法分析器）把 Lexer 产出的 Token 序列，按语言的文法规则组装成一棵抽象语法树（AST）。它负责回答「这些词怎么组合成合法的结构」，是整个编译流程里对「语法」负责的一环。

```text
Parser 在编译流程中的位置：
1. Token 序列 → Parser → AST → Transform → Codegen → 目标代码
2. Parser 的核心是「文法 + 递归」，把线性 Token 变成树形结构
3. 语法错误在这一步被识别并抛出，附带位置信息
```

```js
// 输入 Token 序列，输出一棵 AST
const ast = parse(tokens);
// 形如：
// { type: 'Program', body: [
//     { type: 'VariableDeclaration',
//       id: { type: 'Identifier', name: 'x' },
//       init: { type: 'BinaryExpression', operator: '+',
//               left: { type: 'Literal', value: 1 },
//               right: { type: 'Literal', value: 2 } } } ] }
```

## AST

AST（抽象语法树）是源码的树形抽象表示，去掉了空格、注释、括号等「语法糖细节」，只保留语义结构。后续的转换、优化、代码生成都围绕这棵树展开。

```js
// AST 节点示例：一个函数声明
{
  type: 'FunctionDeclaration',
  id: { type: 'Identifier', name: 'add' },
  params: [
    { type: 'Identifier', name: 'a' },
    { type: 'Identifier', name: 'b' },
  ],
  body: {
    type: 'BlockStatement',
    body: [
      { type: 'ReturnStatement',
        argument: { type: 'BinaryExpression', operator: '+',
                    left: { type: 'Identifier', name: 'a' },
                    right: { type: 'Identifier', name: 'b' } } },
    ],
  },
}
```

```text
AST 的特点：
1. 树形结构 —— 每个节点有 type 与子节点，天然适合递归遍历
2. 语义优先 —— 括号、分号等「写法细节」被丢弃，只留语义
3. 统一中间表示 —— Babel/TS/esbuild 都用 AST 作为转换的中间层
4. 可序列化 —— 可转成 JSON 存储、比对、甚至手写构造
```

## Recursive Descent

Recursive Descent（递归下降）是最直观的解析算法：为每个文法规则写一个解析函数，函数之间互相递归调用，从顶层规则一路下降到终结符。适合 LL 文法，代码可读性高，是绝大多数前端工具的首选。

```js
// 递归下降解析四则运算（只含 + 与数字，展示思路）
class Parser {
  constructor(tokens) { this.tokens = tokens; this.pos = 0; }

  peek() { return this.tokens[this.pos]; }
  eat(type) {
    const t = this.tokens[this.pos];
    if (t.type !== type) throw new Error(`期望 ${type}，实际 ${t.value}`);
    this.pos++;
    return t;
  }

  // expr := term ('+' term)*
  parseExpr() {
    let left = this.parseTerm();
    while (this.peek().value === '+') {
      this.eat('punct'); // 吃掉 '+'
      const right = this.parseTerm();
      left = { type: 'BinaryExpression', operator: '+', left, right };
    }
    return left;
  }

  // term := number | '(' expr ')'
  parseTerm() {
    const t = this.peek();
    if (t.type === 'number') {
      this.eat('number');
      return { type: 'Literal', value: Number(t.value) };
    }
    if (t.value === '(') {
      this.eat('punct');
      const node = this.parseExpr();
      this.eat('punct'); // 吃掉 ')'
      return node;
    }
    throw new Error(`意外的 Token: ${t.value}`);
  }
}
```

```text
递归下降的要点：
1. 每个规则一个函数 —— 文法与代码一一对应，好写也好读
2. 优先级分层 —— 乘除比加减低一层，先解析高优先级
3. 左递归要改写 —— A := A + b 这类左递归会导致死循环，需转成循环
4. 前瞻 —— 用 peek 看当前 Token 决定走哪个分支
```

## Pratt Parser

Pratt Parser（运算符优先级解析，又称 Top-Down Operator Precedence）用「绑定力（binding power）」统一处理运算符优先级，避免了递归下降中多层优先级带来的函数堆叠。它对中缀、前缀、后缀运算符的处理尤其优雅，适合表达式密集的语言。

```js
// Pratt Parser 的核心：按绑定力解析表达式
const precedence = { '+': 1, '-': 1, '*': 2, '/': 2 };

class PrattParser {
  constructor(tokens) { this.tokens = tokens; this.pos = 0; }

  parseExpr(minPrec = 0) {
    let left = this.parsePrefix();          // 先解析前缀/原子
    while (true) {
      const op = this.peek().value;
      const prec = precedence[op] ?? -1;
      if (prec < minPrec) break;            // 绑定力不够，交回上层
      this.pos++;                            // 吃掉运算符
      const right = this.parseExpr(prec + 1); // 右结合还是左结合由 +1 控制
      left = { type: 'BinaryExpression', operator: op, left, right };
    }
    return left;
  }

  parsePrefix() {
    const t = this.tokens[this.pos++];
    if (t.type === 'number') return { type: 'Literal', value: Number(t.value) };
    throw new Error(`意外的前缀: ${t.value}`);
  }
}
```

```text
Pratt Parser 的优点：
1. 一张优先级表 —— 加新运算符只需在表里加一行，不用新写函数
2. 统一处理 —— 前缀、中缀、后缀共用一套绑定力框架
3. 可读性 —— 代码量远小于等价的递归下降
4. 典型应用 —— Babel 的表达式解析、JS 的运算符解析都借鉴此思想
```

## 应用场景实战

### 场景一：解析一个简单的函数调用

```js
// 目标：解析 add(1, 2) → CallExpression
// 思路：ident '(' expr (',' expr)* ')'
function parseCall() {
  const callee = { type: 'Identifier', name: eat('ident').value };
  eat('punct'); // '('
  const args = [];
  if (peek().value !== ')') {
    args.push(parseExpr());
    while (peek().value === ',') {
      eat('punct');
      args.push(parseExpr());
    }
  }
  eat('punct'); // ')'
  return { type: 'CallExpression', callee, arguments: args };
}
```

### 场景二：给 JSON 写一个完整解析器

```js
// 用递归下降解析 JSON 文本为对象
function parseJSON(tokens) {
  let i = 0;
  const value = () => {
    const t = tokens[i];
    if (t.type === 'number') { i++; return Number(t.value); }
    if (t.type === 'string') { i++; return t.value; }
    if (t.value === '{') return obj();
    if (t.value === '[') return arr();
    throw new Error(`意外的 Token: ${t.value}`);
  };
  const obj = () => {
    i++; // '{'
    const result = {};
    while (tokens[i].value !== '}') {
      const key = tokens[i].value; i += 2; // key 和 ':'
      result[key] = value();
      if (tokens[i].value === ',') i++;
    }
    i++; // '}'
    return result;
  };
  const arr = () => {
    i++; // '['
    const result = [];
    while (tokens[i].value !== ']') {
      result.push(value());
      if (tokens[i].value === ',') i++;
    }
    i++; // ']'
    return result;
  };
  return value();
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. 先写文法再写代码，文法清晰了递归函数自然就出来了
2. 每个 parse 函数只吃它负责的 Token，边界要明确
3. 错误信息带上 Token 的行列号，定位越快越好
4. 表达式用 Pratt Parser，语句和声明用递归下降，各取所长
5. AST 节点加 start/end 位置，后续 Source Map 与报错都靠它

### 踩坑记录

```text
坑 1：左递归导致死循环
结论：parseExpr 里直接调用 parseExpr 导致无限递归、栈溢出。
原因：A := A + b 这类文法直接翻译成代码就是左递归。
解法：把左递归改写成循环（递归下降）或用 Pratt 的绑定力。

坑 2：运算符优先级写错
结论：1 + 2 * 3 被解析成 (1 + 2) * 3，结果错。
原因：加减乘除没有分层，都放在同一层循环里。
解法：优先级分层解析，或引入绑定力表。

坑 3：忘了吃掉闭合括号
结论：解析 '(1+2' 时没有消费 ')'，后续 Token 全错位。
原因：递归返回前漏掉了 eat 闭合符号。
解法：每个左括号对应一个明确的右括号 eat，写单元测试覆盖。

坑 4：不处理 eof 就继续读
结论：读到 Token 数组末尾，访问 undefined 抛异常。
原因：循环条件没判断是否到达 eof。
解法：循环前先判断 peek 是否为 eof 再继续。

坑 5：AST 丢失位置信息
结论：后续代码生成时无法生成 Source Map，报错无法定位。
原因：AST 节点只存了 type 和 value，没存 start/end。
解法：解析时把每个 Token 的位置塞进 AST 节点。
```

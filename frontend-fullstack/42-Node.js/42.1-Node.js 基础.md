## 概述

Node.js 是让 JavaScript 脱离浏览器在服务端运行的运行时环境。它的核心是「单线程事件循环 + 非阻塞 I/O」：用 V8 执行 JS，用 libuv 把耗时 I/O 丢给操作系统线程池异步处理，主线程只负责调度回调。

```text
Node.js 的核心组成：
1. V8 —— JavaScript 引擎，负责编译和执行 JS
2. libuv —— 跨平台异步 I/O 库，提供事件循环和线程池
3. 内置模块 —— fs、http、path 等核心 API
4. 事件循环 —— 单线程调度异步任务的机制
```

```js
// Node 的非阻塞 I/O：异步读文件不阻塞主线程
const fs = require('node:fs');
fs.readFile('a.txt', 'utf-8', (err, data) => {
  if (!err) console.log(data);
});
console.log('我先执行');
```

## Runtime 与 V8 与 libuv

Runtime 是把 JS 引擎、事件循环、系统调用整合起来的环境。V8 负责解析执行 JS（含 JIT 编译），libuv 负责事件循环和异步 I/O（文件、网络、定时器、线程池）。

```text
三者分工：
V8   —— 执行 JS 代码（同步代码都跑在 V8 上）
libuv —— 处理异步 I/O 和事件循环（底层 epoll/kqueue 等机制）
Runtime —— 组合二者 + 提供模块系统 + 绑定系统调用
```

```js
// V8 的一些运行时能力
console.log(process.versions.v8);        // V8 版本
console.log(v8.getHeapStatistics());     // 堆内存统计
```

```text
libuv 的线程池：
1. 默认 4 个线程（UV_THREADPOOL_SIZE 可调）
2. 处理 fs 文件操作、dns.lookup、加密等阻塞任务
3. 网络 I/O 不走线程池，由操作系统 epoll 等机制处理
```

## Event Loop

事件循环是 Node 调度异步回调的机制：每个阶段处理一类回调队列，循环往复。理解阶段顺序才能理解 setTimeout、Promise 的执行顺序。

```text
事件循环的六个阶段：
1. timers —— 执行到期的 setTimeout/setInterval 回调
2. pending callbacks —— 执行系统级回调（如 TCP 错误）
3. idle, prepare —— 内部使用
4. poll —— 检索新的 I/O 事件，执行 I/O 回调
5. check —— 执行 setImmediate 回调
6. close callbacks —— 执行 close 事件回调
```

```js
// 经典执行顺序：微任务先于宏任务
setTimeout(() => console.log('timeout'), 0);
setImmediate(() => console.log('immediate'));
Promise.resolve().then(() => console.log('promise'));
process.nextTick(() => console.log('nextTick'));

// 输出顺序：
// nextTick → promise → timeout/immediate（取决于 poll 阶段时机）
```

```text
微任务 vs 宏任务：
微任务 —— process.nextTick、Promise.then，当前阶段结束后立即执行
宏任务 —— setTimeout、setInterval、setImmediate、I/O 回调
process.nextTick 优先级高于 Promise.then
```

## Process

Process 是全局对象，承载进程信息、环境变量、命令行参数、退出控制等。

```js
// 环境变量与参数
process.env.NODE_ENV;              // 环境变量
process.argv;                      // 命令行参数数组
process.cwd();                     // 当前工作目录

// 进程控制
process.exit(0);                   // 退出进程
process.pid;                       // 进程 ID

// 信号监听
process.on('SIGINT', () => {
  console.log('收到中断信号');
  process.exit(0);
});
```

```js
// 全局异常兜底
process.on('uncaughtException', (err) => {
  console.error('未捕获异常', err);
});
process.on('unhandledRejection', (reason) => {
  console.error('未处理的 Promise 拒绝', reason);
});
```

## Buffer

Buffer 是 Node 处理二进制数据的类，弥补 JS 早期无二进制类型的缺陷。它是一块固定大小的内存，用于文件、网络等字节流操作。

```js
// 创建 Buffer
const buf = Buffer.from('hello', 'utf-8');   // 从字符串
const buf2 = Buffer.alloc(10);               // 分配 10 字节并清零
const buf3 = Buffer.allocUnsafe(10);         // 分配但不初始化（快，可能含旧数据）

buf.toString('utf-8');                        // 转回字符串
buf.length;                                   // 字节长度（不是字符数）
```

```js
// 读写整数（注意字节序）
const b = Buffer.alloc(4);
b.writeUInt32BE(0x12345678, 0);    // 大端写
b.readUInt32BE(0);                 // 读回

// 字符串长度 vs 字节长度（中文 3 字节）
Buffer.from('中').length;           // 3
```

## Stream

Stream 是处理大数据的抽象：把数据切成一块块（chunk）边读边处理，不必一次性加载到内存。Node 的核心模块大多基于 Stream。

```js
const fs = require('node:fs');

// 流式读文件：分块处理，内存占用恒定
const rs = fs.createReadStream('big.txt');
rs.on('data', (chunk) => {
  console.log('读到一个 chunk', chunk.length);
});
rs.on('end', () => console.log('读取完成'));
```

```text
Stream 的价值：
1. 内存恒定 —— 只保留当前 chunk，不整体加载
2. 时间更快 —— 边读边处理，不必等全部读完
3. 可组合 —— pipe 串联多个流，构建管道
```

## EventEmitter

EventEmitter 是 Node 的事件驱动核心：对象发出事件，监听器响应。几乎所有 I/O 对象（Stream、Server、Process）都继承自它。

```js
const { EventEmitter } = require('node:events');

const emitter = new EventEmitter();

// 注册监听器
emitter.on('data', (msg) => console.log('收到', msg));
emitter.once('ready', () => console.log('只触发一次'));

// 触发事件
emitter.emit('data', 'hello');
emitter.emit('ready');
emitter.emit('ready');   // 第二次不触发（once）

// 移除监听
const handler = () => {};
emitter.on('foo', handler);
emitter.off('foo', handler);
```

```js
// 自定义类继承 EventEmitter
class Server extends EventEmitter {
  start() {
    this.emit('started');
  }
}
const s = new Server();
s.on('started', () => console.log('服务已启动'));
s.start();
```

## 应用场景实战

### 场景一：统计大文件行数（流式处理）

```js
const fs = require('node:fs');

function countLines(file) {
  return new Promise((resolve, reject) => {
    let lines = 0;
    let last = '';
    const rs = fs.createReadStream(file, { encoding: 'utf-8' });
    rs.on('data', (chunk) => {
      lines += (last + chunk).split('\n').length - 1;
      last = chunk.slice(chunk.lastIndexOf('\n') + 1);
    });
    rs.on('end', () => resolve(lines));
    rs.on('error', reject);
  });
}

countLines('big.txt').then((n) => console.log('总行数', n));
```

### 场景二：简单事件驱动计数器

```js
const { EventEmitter } = require('node:events');

class Counter extends EventEmitter {
  constructor() {
    super();
    this.count = 0;
  }
  increment() {
    this.count++;
    this.emit('change', this.count);
  }
}

const c = new Counter();
c.on('change', (n) => {
  if (n === 3) console.log('达到 3 次');
});
c.increment();
c.increment();
c.increment();
```

## 最佳实践与踩坑记录

### 最佳实践

1. 优先用 Stream 处理大文件，避免 readFile 一次性加载内存
2. 模块导入统一用 node: 前缀（node:fs），区分内置与第三方
3. process.nextTick 别滥用，过多会阻塞事件循环
4. Buffer 用 alloc 而非 new Buffer()（已废弃）
5. 监听 uncaughtException 只做兜底记录，不能替代业务错误处理

### 踩坑记录

```text
坑 1：CPU 密集任务阻塞事件循环
结论：一个耗时 for 循环导致所有请求卡住。
原因：Node 单线程，同步 CPU 任务占满主线程，事件循环无法周转。
解法：CPU 密集任务拆块（setImmediate 让出）或丢给 worker_threads。

坑 2：用 readFile 读大文件导致 OOM
结论：读 1GB 文件直接内存溢出崩溃。
原因：readFile 把整个文件读进内存再回调。
解法：大文件用 createReadStream 流式处理。

坑 3：混淆 setTimeout 和 setImmediate 的顺序
结论：两者谁先执行不确定，行为不稳定。
原因：顺序取决于 poll 阶段时机（在主模块里取决于系统状态）。
解法：在 I/O 回调里 setImmediate 一定先于 setTimeout，别依赖顶层顺序。

坑 4：Buffer 的 length 误当字符串长度
结论：中文场景算长度出错。
原因：Buffer.length 是字节数，中文 UTF-8 占 3 字节。
解法：先 toString 再取 .length，或明确用字节语义。

坑 5：process.exit 直接退出导致异步任务丢失
结论：进程退出时还有未写完的文件/日志。
原因：process.exit 强制退出，不等事件循环清空。
解法：让进程自然结束，或用 process.exitCode = 0 优雅退出。
```

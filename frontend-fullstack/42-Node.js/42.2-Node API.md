## 概述

Node 内置模块是服务端开发的基础工具集，覆盖文件系统、路径、网络、加密、进程管理等。它们无需安装，通过 `require('node:xxx')` 直接使用。掌握这些模块是后端开发与构建工具（Webpack、Vite）底层理解的前提。

```text
内置模块分类：
1. 文件与系统 —— fs、path、os
2. 网络 —— http、https、net
3. 数据处理 —— url、util、crypto
4. 并发与进程 —— child_process、worker_threads、cluster
```

```js
// 统一使用 node: 前缀引入内置模块
const fs = require('node:fs');
const path = require('node:path');
```

## fs 与 path

fs 是文件系统模块，提供读写、复制、目录操作；path 处理路径拼接、解析、规范化，跨平台消除分隔符差异。

```js
const fs = require('node:fs');
const path = require('node:path');

// 同步 vs 异步 vs Promise
fs.readFileSync('a.txt', 'utf-8');                       // 同步
fs.readFile('a.txt', 'utf-8', (err, data) => {});        // 回调
fs.promises.readFile('a.txt', 'utf-8');                  // Promise

// 写入（不存在则创建）
fs.writeFileSync('b.txt', 'hello');
fs.appendFileSync('b.txt', ' world');

// 目录操作
fs.mkdirSync('dir', { recursive: true });                // 递归创建
fs.readdirSync('dir');                                    // 读目录
fs.rmSync('dir', { recursive: true });                    // 递归删除
```

```js
// path 常用方法
path.join('/a', 'b', 'c');        // '/a/b/c'（处理分隔符）
path.resolve('src', 'index.js');  // 绝对路径
path.basename('/a/b/c.txt');      // 'c.txt'
path.dirname('/a/b/c.txt');       // '/a/b'
path.extname('c.txt');            // '.txt'
path.parse('/a/b/c.txt');         // { root, dir, base, ext, name }
```

## url 与 os

url 模块解析和构造 URL；os 提供操作系统信息（CPU、内存、平台）。

```js
const { URL, URLSearchParams } = require('node:url');

const u = new URL('https://example.com:8080/api/list?page=2&size=10');
u.hostname;        // 'example.com'
u.port;            // '8080'
u.pathname;        // '/api/list'
u.searchParams.get('page');   // '2'

// 构造查询串
const params = new URLSearchParams({ a: 1, b: 'x y' });
params.toString();             // 'a=1&b=x+y'
```

```js
const os = require('node:os');

os.cpus();              // CPU 信息
os.totalmem();          // 总内存
os.freemem();           // 空闲内存
os.platform();          // 'linux' / 'darwin' / 'win32'
os.homedir();           // 用户主目录
os.EOL;                 // 换行符
```

## util 与 crypto

util 提供工具函数（promisify 转 Promise、类型判断）；crypto 提供哈希、加密、随机数等安全能力。

```js
const util = require('node:util');
const fs = require('node:fs');

// promisify：把回调风格函数转成 Promise
const readFile = util.promisify(fs.readFile);
readFile('a.txt', 'utf-8').then(console.log);

util.types.isDate(new Date());       // true
util.format('%s:%s', 'a', 'b');      // 'a:b'
```

```js
const crypto = require('node:crypto');

// 哈希摘要
crypto.createHash('sha256').update('hello').digest('hex');

// HMAC（带密钥的摘要）
crypto.createHmac('sha256', 'secret').update('data').digest('hex');

// 加盐哈希（密码存储）
const salt = crypto.randomBytes(16).toString('hex');
crypto.scryptSync('password', salt, 64).toString('hex');

// 随机数
crypto.randomBytes(16).toString('hex');
crypto.randomUUID();
```

## http 与 https

http/https 是网络服务核心模块，可创建 HTTP 服务端和发起请求。https 在 http 基础上加 TLS 加密。

```js
const http = require('node:http');

const server = http.createServer((req, res) => {
  const { method, url } = req;
  res.writeHead(200, { 'Content-Type': 'application/json' });
  res.end(JSON.stringify({ method, url }));
});

server.listen(3000, () => console.log('监听 3000'));
```

```js
// 发起请求
http.get('http://localhost:3000/api', (res) => {
  let body = '';
  res.on('data', (chunk) => (body += chunk));
  res.on('end', () => console.log(JSON.parse(body)));
});
```

```js
// https：需要证书文件
const https = require('node:https');
const fs = require('node:fs');

const options = {
  key: fs.readFileSync('key.pem'),
  cert: fs.readFileSync('cert.pem'),
};
https.createServer(options, (req, res) => res.end('secure')).listen(443);
```

## net

net 提供底层 TCP 服务，http 就是建立在 net 之上。适合自定义协议、长连接、socket 通信。

```js
const net = require('node:net');

// TCP 服务端
const server = net.createServer((socket) => {
  socket.on('data', (data) => {
    console.log('收到', data.toString());
    socket.write('pong');
  });
});
server.listen(9000);

// TCP 客户端
const client = net.connect(9000, '127.0.0.1', () => {
  client.write('ping');
});
client.on('data', (data) => console.log('响应', data.toString()));
```

## child_process 与 worker_threads 与 cluster

三个模块解决 Node 单线程的并发限制：child_process 起子进程跑外部命令，worker_threads 起工作线程共享内存，cluster 多进程负载均衡。

```js
const { exec, execFile, spawn, fork } = require('node:child_process');

// exec：跑 shell 命令（输出较小）
exec('ls -la', (err, stdout) => console.log(stdout));

// spawn：流式输出（适合大输出、长时间任务）
const child = spawn('node', ['-v']);
child.stdout.on('data', (d) => console.log(d.toString()));

// fork：专门跑 Node 脚本，带 IPC 通信
const worker = fork('./worker.js');
worker.send({ type: 'task', data: 1 });
worker.on('message', (m) => console.log(m));
```

```js
// worker_threads：工作线程，可共享内存
const { Worker, isMainThread, parentPort } = require('node:worker_threads');

if (isMainThread) {
  const w = new Worker(__filename);
  w.on('message', (m) => console.log('结果', m));
} else {
  parentPort.postMessage(42);
}
```

```js
// cluster：多进程监听同端口，主进程分发
const cluster = require('node:cluster');
const os = require('node:os');

if (cluster.isPrimary) {
  for (let i = 0; i < os.cpus().length; i++) cluster.fork();
} else {
  require('node:http').createServer((req, res) => res.end('worker')).listen(3000);
}
```

## 应用场景实战

### 场景一：遍历目录统计文件大小

```js
const fs = require('node:fs');
const path = require('node:path');

function dirSize(dir) {
  let total = 0;
  for (const entry of fs.readdirSync(dir, { withFileTypes: true })) {
    const full = path.join(dir, entry.name);
    if (entry.isDirectory()) total += dirSize(full);
    else total += fs.statSync(full).size;
  }
  return total;
}

console.log('目录大小', dirSize('./src'), '字节');
```

### 场景二：HTTP 服务 + 哈希签名接口

```js
const http = require('node:http');
const crypto = require('node:crypto');
const url = require('node:url');

const SECRET = 'my-secret';

const server = http.createServer((req, res) => {
  const { pathname, searchParams } = new URL(req.url, 'http://localhost');
  if (pathname === '/sign' && req.method === 'GET') {
    const data = searchParams.get('data') ?? '';
    const sign = crypto.createHmac('sha256', SECRET).update(data).digest('hex');
    res.writeHead(200, { 'Content-Type': 'application/json' });
    res.end(JSON.stringify({ data, sign }));
  } else {
    res.writeHead(404).end();
  }
});

server.listen(3000);
```

## 最佳实践与踩坑记录

### 最佳实践

1. 文件操作优先 fs.promises，配合 async/await，避免回调地狱
2. 内置模块统一 node: 前缀，与第三方包区分
3. 密码哈希用 scrypt/bcrypt 加盐，不用裸 sha256
4. 外部命令优先 execFile/spawn（数组参数），避免 exec 的 shell 注入
5. 多核利用优先 cluster（进程级），共享内存场景才用 worker_threads

### 踩坑记录

```text
坑 1：用 exec 拼接用户输入导致命令注入
结论：用户传参被拼进 shell 命令执行任意代码。
原因：exec 走 shell，字符串拼接未转义。
解法：用 execFile/spawn 传数组参数，或严格校验输入。

坑 2：path.join 和 path.resolve 混淆
结论：拼接的路径不是预期的绝对/相对路径。
原因：join 只是拼接，resolve 会基于 cwd 解析成绝对路径。
解法：拼接用 join，取绝对路径用 resolve，明确各自语义。

坑 3：readFileSync 阻塞事件循环
结论：同步读大文件导致服务卡死。
原因：同步 API 占用主线程，期间无法处理其他请求。
解法：服务端路径用异步 API，只有启动时一次性加载才用 Sync。

坑 4：哈希用来存密码且不加盐
结论：相同密码哈希相同，可被彩虹表破解。
原因：直接用 sha256(password) 存储。
解法：加随机盐 + scrypt/bcrypt，慢哈希增加破解成本。

坑 5：cluster 的 IPC 消息序列化开销
结论：worker 间传大对象性能差。
原因：cluster 通过 IPC 走 JSON 序列化，大对象开销大。
解法：共享大量数据用 worker_threads 的 SharedArrayBuffer，而非频繁 IPC。
```

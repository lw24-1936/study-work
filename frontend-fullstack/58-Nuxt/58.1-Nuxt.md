## 概述

Nuxt 是基于 Vue 的全栈框架，在 Vue 之上提供了文件路由、自动导入、服务端渲染、静态生成等能力。它解决的核心问题是「纯 Vue SPA 的 SEO 差、首屏慢」，同时用一套代码覆盖从纯静态站到全栈应用的各种形态。

```text
Nuxt 的核心能力：
1. File Routing —— 基于 pages/ 目录自动生成路由
2. Auto Import —— 组件、组合式函数、工具函数免手动 import
3. SSR —— 服务端渲染，首屏快、SEO 友好
4. SSG —— 构建期预渲染成静态文件，可部署到 CDN
5. Hybrid Rendering —— 通过 routeRules 按路由混合 SSR/SSG/ISR
6. Nitro —— 独立服务端引擎，负责 API、部署与运行时
```

```text
Nuxt 项目结构（典型）：
app.vue            —— 应用根组件（入口）
nuxt.config.ts     —— 框架配置
pages/             —— 页面（自动生成路由）
components/        —— 组件（自动导入）
composables/       —— 组合式函数（自动导入）
server/            —— 服务端代码（由 Nitro 驱动）
public/            —— 静态资源
```

## File Routing

Nuxt 使用「文件即路由」的约定：`pages/` 目录下的每个 Vue 文件自动对应一个 URL，无需手写路由表。

```text
文件 → 路由映射规则：
pages/index.vue           →  /
pages/about.vue           →  /about
pages/users/index.vue     →  /users
pages/users/[id].vue      →  /users/:id        （动态参数）
pages/users/[...slug].vue →  /users/**         （捕获所有）
pages/users/[[slug]].vue  →  可选捕获所有（斜杠可省略）
```

```vue
<!-- pages/users/[id].vue -->
<template>
  <div>
    <h1>用户详情</h1>
    <p>用户 ID：{{ route.params.id }}</p>
    <NuxtLink to="/">返回首页</NuxtLink>
  </div>
</template>

<script setup>
const route = useRoute();           // 自动导入，无需 import
</script>
```

```vue
<!-- app.vue：根组件，负责渲染页面 -->
<template>
  <div>
    <NuxtLayout>
      <NuxtPage />                    <!-- 渲染当前路由对应的页面 -->
    </NuxtLayout>
  </div>
</template>
```

```text
嵌套路由：
pages/parent.vue        与
pages/parent/child.vue  组成嵌套关系。

parent.vue 内需要放置 <NuxtPage /> 来渲染子页面：
/parent        → parent.vue
/parent/child  → parent.vue + child.vue

路由分组（Route Group）：
pages/(admin)/dashboard.vue  →  /dashboard
用括号包裹的目录不参与 URL，仅用于组织文件。
```

```vue
<!-- pages/parent.vue -->
<template>
  <div>
    <h1>父页面</h1>
    <NuxtPage />                       <!-- 子路由渲染在此 -->
  </div>
</template>
```

```ts
// 页面元信息（布局、中间件、标题）
// 在 <script setup> 中定义
definePageMeta({
  layout: 'default',
  middleware: 'auth',
  title: '用户详情'
});
```

## Auto Import

Nuxt 基于 unimport 提供自动导入：组件、组合式函数、工具函数以及 Vue 的 API 都无需手动 `import`，显著减少样板代码。

```text
自动导入的范围：
1. components/ 目录下的组件（含嵌套目录）
2. composables/ 目录下的组合式函数（仅顶层导出）
3. utils/ 目录下的工具函数（Nuxt 3.9+ 默认启用）
4. Vue 核心 API：ref、computed、onMounted 等
5. Nuxt 内置组合式：useFetch、useState、useRuntimeConfig 等
```

```ts
// composables/useCounter.ts —— 顶层 export function 才会被自动导入
export function useCounter() {
  const count = ref(0);              // ref 来自 Vue，自动导入
  const increment = () => count.value++;
  return { count, increment };
}
```

```vue
<!-- components/AppButton.vue —— 自动导入后任意页面直接用 <AppButton> -->
<template>
  <button class="btn" @click="$emit('click')">
    <slot />
  </button>
</template>
```

```vue
<!-- pages/index.vue —— 全部免 import -->
<template>
  <div>
    <AppButton @click="increment">点击 {{ count }}</AppButton>
  </div>
</template>

<script setup>
const { count, increment } = useCounter();  // 自定义 composable 自动导入
const route = useRoute();                    // Nuxt 内置，自动导入
const state = useState('global', () => ({ a: 1 })); // 全局共享状态
</script>
```

```text
如何知道哪些被自动导入？
Nuxt 会生成 .nuxt/types/imports.d.ts 类型声明文件，
编辑器能获得完整的自动补全与类型提示。

也可在 nuxt.config.ts 中自定义：
export default defineNuxtConfig({
  imports: {
    dirs: ['stores']        // 额外添加自动导入目录
  }
});
```

## SSR

SSR（Server-Side Rendering）指服务端把页面渲染成完整 HTML 返回，浏览器先展示内容，随后再「水合」（hydration）接管交互。这是 Nuxt 默认的渲染模式。

```text
SSR 的流程：
1. 请求到达 Nitro 服务端
2. 服务端执行页面的 setup（包括数据获取）
3. 渲染成 HTML 字符串返回
4. 浏览器渲染 HTML（首屏可见）
5. 客户端加载 JS 并水合，接管交互
```

```vue
<!-- pages/posts/[id].vue —— 数据在服务端获取并随 HTML 返回 -->
<template>
  <div>
    <h1>{{ data?.title }}</h1>
    <p>{{ data?.body }}</p>
  </div>
</template>

<script setup>
// useAsyncData / useFetch 在 SSR 阶段执行，数据被序列化进 payload
const { data } = await useFetch(`/api/posts/${useRoute().params.id}`);
</script>
```

```ts
// 使用 useAsyncData 获取非接口数据（如数据库查询、文件读取）
const { data, pending, error, refresh } = await useAsyncData(
  'posts',
  () => $fetch('/api/posts'),
  { lazy: true }                    // lazy: 不阻塞渲染，后台获取
);
```

```text
SSR 的收益与代价：
收益：
1. SEO 友好 —— 搜索引擎可直接抓取完整 HTML
2. 首屏更快 —— 用户更快看到内容（首字节可能更慢）
3. 社交分享 —— Open Graph 抓取到真实内容

代价：
1. 需要服务器运行 Node 运行时
2. 服务端无法使用 window/document 等浏览器 API
3. 水合失败可能导致交互异常
```

```ts
// 关闭 SSR（纯 SPA 模式）
export default defineNuxtConfig({
  ssr: false
});
```

## SSG

SSG（Static Site Generation）在构建期把所有页面预渲染成静态 HTML 文件，部署后无需服务器，直接由 CDN 提供。通过 `nuxi generate` 触发。

```text
SSG 的执行方式：
1. 运行 npm run generate（底层调用 nuxi generate）
2. Nitro 预渲染 crawler 从入口爬取所有链接
3. 每个页面执行 setup，获取数据并固化成 HTML
4. 数据随页面内联，生成纯静态文件到 .output/public
```

```ts
// nuxt.config.ts —— 配置预渲染路由
export default defineNuxtConfig({
  nitro: {
    prerender: {
      routes: ['/', '/about', '/posts/1', '/posts/2']  // 显式指定
      // crawlLinks: true 时，也会自动爬取页面中的 <NuxtLink>
    }
  }
});
```

```text
SSG 适用与限制：
适用：博客、文档站、营销页等「内容不频繁变化」的场景。
限制：内容更新需要重新构建；用户个性化内容无法静态化。
```

## Hybrid Rendering

Hybrid Rendering（混合渲染）是 Nuxt 3 的核心优势：通过 `routeRules` 为不同路由指定不同的渲染策略，在同一个应用内按需混合 SSR、SSG、ISR、SWR。

```ts
// nuxt.config.ts —— 按路由混合渲染
export default defineNuxtConfig({
  routeRules: {
    '/': { prerender: true },              // 首页静态生成
    '/blog/**': { swr: 3600 },             // 博客：缓存 1 小时，过期后后台重建
    '/admin/**': { ssr: false },           // 管理后台：纯 SPA
    '/api/**': { cors: true },             // 接口允许跨域
    '/old-page': { redirect: '/new' }      // 重定向
  }
});
```

```text
routeRules 常用策略：
prerender: true   —— 构建期静态生成（SSG）
ssr: false        —— 客户端渲染（SPA）
swr: 秒数          —— 缓存响应，过期后后台重新生成（Stale-While-Revalidate）
isr: 秒数          —— 增量静态再生成
redirect           —— 重定向
proxy              —— 反向代理到其他服务
headers / cors     —— 自定义响应头
```

## Nitro

Nitro 是 Nuxt 的服务端引擎，负责处理 `server/` 目录的代码、构建产物与多平台部署。它让同一套服务端代码可以零修改部署到 Node、Deno、Cloudflare Workers、Vercel 等不同环境。

```text
Nitro 的职责：
1. 执行 server/ 目录下的 API 路由与中间件
2. 提供 $fetch、useStorage 等服务端工具
3. 通过 Preset 适配不同部署平台
4. 处理 SSR 渲染与数据缓存
```

```ts
// server/api/hello.ts —— 文件即 API 路由
export default defineEventHandler((event) => {
  return { message: 'Hello from Nitro' };
});
```

```text
server/ 目录结构：
server/api/         —— API 路由（GET /api/xxx）
server/routes/      —— 服务端路由（可返回 HTML）
server/middleware/  —— 服务端中间件
server/utils/       —— 服务端工具函数（自动导入）
server/plugins/     —— 服务端插件（Nitro 插件）
```

```text
Nitro 的通用部署：
构建产物 .output/ 是平台无关的。
部署到不同平台只需改 preset：
nitro: { preset: 'node-server' }       —— Node 服务器
nitro: { preset: 'vercel' }            —— Vercel
nitro: { preset: 'cloudflare' }        —— Cloudflare Workers
nitro: { preset: 'deno-deploy' }       —— Deno Deploy
```

## 应用场景实战

### 场景一：博客站（SSG）

```text
需求：技术博客，内容稳定，追求极致加载速度与低成本。
方案：全站 SSG，部署到静态托管/CDN。

nuxt.config.ts:
export default defineNuxtConfig({
  routeRules: {
    '/**': { prerender: true }
  }
});

构建：npm run generate
产物：.output/public 为纯静态文件，可直接上传 CDN。
```

### 场景二：内容 + 后台系统（混合渲染）

```text
需求：一个应用包含对外内容页（要 SEO）与内部后台（要交互）。
方案：Hybrid Rendering 按路由拆分。

routeRules: {
  '/': { prerender: true },          // 营销首页静态化
  '/docs/**': { swr: 600 },          // 文档缓存 10 分钟
  '/dashboard/**': { ssr: false }    // 后台走 SPA
}
```

```vue
<!-- 后台页面中，用 onMounted 保证只在客户端访问浏览器 API -->
<script setup>
const width = ref(0);

onMounted(() => {
  width.value = window.innerWidth;   // SSR 阶段 window 不存在
});
</script>
```

## 最佳实践与踩坑记录

### 最佳实践

1. 数据获取统一用 useFetch/useAsyncData，避免在服务端直接 fetch 导致重复请求
2. 需要 SEO 的页面用 SSR/SSG，纯交互后台用 ssr: false
3. 浏览器专属代码放进 onMounted 或 ClientOnly 组件，避免 SSR 报错
4. 自动导入的 composable 必须顶层导出，且用 use 前缀命名
5. 善用 routeRules 做混合渲染，而非全站统一策略

### 踩坑记录

```text
坑 1：SSR 阶段访问 window 报错
结论：服务端渲染时报 window is not defined。
原因：Node 运行时没有 window/document 等浏览器全局对象。
解法：浏览器 API 放进 onMounted，或用 <ClientOnly> 包裹，或加 import.meta.client 判断。

坑 2：useFetch 数据在客户端重复请求
结论：同一数据 SSR 取一次、客户端又取一次。
原因：没有走 Nuxt 的 payload 传输机制，直接用裸 fetch。
解法：用 useFetch/useAsyncData，数据会随 payload 序列化到客户端复用。

坑 3：自动导入失效
结论：composable 无法自动导入。
原因：非顶层导出、或目录不在默认扫描范围、或文件名不以 use 开头（仅约定习惯）。
解法：确保顶层 export function；自定义目录在 imports.dirs 中注册。

坑 4：动态路由未预渲染导致 404
结论：generate 后 [id] 页面访问 404。
原因：动态路由默认不被 crawler 发现。
解法：在 nitro.prerender.routes 中显式列出所有动态路径。

坑 5：水合不匹配（Hydration Mismatch）
结论：控制台报 hydration mismatch 警告，交互异常。
原因：服务端与客户端渲染结果不一致（如依赖随机数、时间戳、localStorage）。
解法：差异部分用 onMounted 或 <ClientOnly>，保证首帧 HTML 两端一致。
```

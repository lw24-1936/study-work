## 概述

Storybook 是组件开发环境（Component Workshop），让开发者在隔离环境里开发、浏览、测试 UI 组件。每个组件写若干个 Story（故事，即组件的某个状态），就能在浏览器里逐个查看，且能自动生成文档、交互测试和视觉回归测试。

```text
Storybook 解决什么问题：
1. 组件开发需要「看到」状态 —— 不用起整个应用就能渲染单个组件
2. 组件状态多 —— 一个按钮有 primary/default/disabled 等状态
3. 文档与代码同步 —— 文档从 Story 自动生成，不会过期
4. 视觉回归 —— 组件改坏了能截图对比发现
```

```text
Storybook 的核心概念：
1. Story —— 组件的某个具体状态（一个「故事」）
2. Args —— Story 的 props 输入
3. Controls —— 交互式调参面板
4. Actions —— 记录事件回调
5. Docs —— 自动生成的文档页
6. Interaction Test —— 交互流程断言
7. Visual Regression —— 截图对比测试
```

## Story

Story 是组件的「一个状态示例」。一个组件可以有多个 Story，每个 Story 展示组件在某组 props 下的样子。Story 用 CSF（Component Story Format）编写，是一个导出对象。

```tsx
// Button.stories.tsx —— CSF 格式
import type { Meta, StoryObj } from '@storybook/react';
import { Button } from './Button';

const meta: Meta<typeof Button> = {
  title: 'Components/Button',   // 侧边栏分组路径
  component: Button,
};
export default meta;

type Story = StoryObj<typeof Button>;

// 一个 Story = 一个状态
export const Primary: Story = {
  args: { variant: 'primary', children: '提交' },
};

export const Disabled: Story = {
  args: { variant: 'primary', children: '提交', disabled: true },
};
```

```text
CSF 的三个版本：
CSF1 —— storiesOf() 函数式，已废弃
CSF2 —— export const Story + Template 函数
CSF3 —— export const Story + args 对象（当前主流，最简洁）
```

```tsx
// CSF3 也可以用 render 函数自定义渲染
export const WithIcon: Story = {
  args: { children: '搜索' },
  render: (args) => (
    <Button {...args}>
      <SearchIcon />
      {args.children}
    </Button>
  ),
};
```

## Args

Args 是传给 Story 的参数对象，本质就是组件的 props 集合。Story 通过 args 定义组件的输入，Controls 面板据此生成可调节的控件。

```tsx
// 定义 argTypes，声明每个 args 的类型和控件
const meta: Meta<typeof Button> = {
  component: Button,
  argTypes: {
    variant: {
      control: 'select',
      options: ['primary', 'default', 'danger'],
    },
    size: {
      control: 'radio',
      options: ['sm', 'md', 'lg'],
    },
    disabled: { control: 'boolean' },
  },
};
export default meta;
```

```tsx
// 全局 args / 组件级 args —— 多个 Story 共享的默认值
export default {
  component: Button,
  args: {
    size: 'md',
    variant: 'primary',
  },
} satisfies Meta<typeof Button>;

export const Large: Story = {
  args: { size: 'lg' },  // 覆盖默认值，其余继承
};
```

```text
Args 的层级（优先级从高到低）：
Story args > Component args > Global args

同名 key 越靠近 Story 越优先，可用来做「全局默认 + 局部覆盖」。
```

## Controls

Controls 是 Storybook 的交互式调参面板，根据 argTypes 自动生成输入控件（下拉框、单选框、开关、颜色选择器），开发者改控件就能实时看组件变化，无需改代码。

```tsx
// 各种控件类型
const meta: Meta<typeof Card> = {
  component: Card,
  argTypes: {
    title: { control: 'text' },          // 文本框
    count: { control: 'number' },         // 数字输入
    theme: {
      control: 'inline-radio',            // 内联单选
      options: ['light', 'dark'],
    },
    color: { control: 'color' },          // 颜色选择器
    visible: { control: 'boolean' },      // 开关
  },
};
```

```text
常用控件类型：
select / radio / inline-radio —— 枚举单选
boolean —— 开关
text / number / color —— 基础输入
date —— 日期
object / array —— JSON 编辑
range —— 滑杆（配合 min/max/step）

argTypes 不声明时，Storybook 会按 props 的 TS 类型自动推断控件。
```

## Actions

Actions 用于记录组件的回调事件（如 onClick、onChange），在面板里显示事件触发的参数。它验证「组件在正确时机调用了正确的回调，并传了正确的参数」。

```tsx
// 把回调交给 actions 记录
import { fn } from '@storybook/test';

const meta: Meta<typeof Button> = {
  component: Button,
  args: {
    onClick: fn(),       // 自动记录到 Actions 面板
  },
};

// 自定义事件参数名
const meta2: Meta<typeof Select> = {
  component: Select,
  argTypes: {
    onChange: { action: 'changed' },  // 面板里显示为 changed 事件
  },
};
```

```text
Actions 的用途：
1. 确认回调被触发 —— 点了按钮，面板出现 onClick 记录
2. 检查参数 —— onChange 传出的 value 是否正确
3. 交互测试的基础 —— 断言某个 action 被调用过 N 次
```

## Docs

Docs 是 Storybook 自动生成的文档页，从 Story 和组件源码（TS 类型、JSDoc 注释）自动提取，展示每个 Story 的渲染结果、props 表格、源码。

```tsx
// JSDoc 注释会显示在 Docs 的 props 表格里
export interface ButtonProps {
  /** 按钮变体：主按钮/默认/危险 */
  variant?: 'primary' | 'default' | 'danger';
  /** 是否禁用 */
  disabled?: boolean;
  /** 点击回调 */
  onClick?: () => void;
}
```

```tsx
// MDX 混合编写文档 —— 文字说明 + 嵌入 Story
// Button.mdx
import { Meta, Story, Canvas } from '@storybook/blocks';
import * as ButtonStories from './Button.stories';

<Meta of={ButtonStories} />

# 按钮 Button

用于触发操作。有三种变体：

<Canvas of={ButtonStories.Primary} />
```

```text
Docs 自动生成的内容：
1. props 表格 —— 从 TS 类型 + JSDoc 提取
2. Story 画布 —— 每个 Story 的可交互预览
3. 源码展示 —— 组件的实现源码
4. 描述 —— 从 JSDoc / 参数说明提取
```

## Interaction Test

Interaction Test（交互测试）在 Story 里模拟用户操作（点击、输入、键盘）并断言结果，用 `play` 函数编写。它跑在真实的 Storybook 环境里，比单元测试更接近真实使用。

```tsx
// 交互测试 —— 用 @storybook/test 的 play 函数
import { expect, userEvent, within } from '@storybook/test';

export const SubmitFlow: Story = {
  play: async ({ canvasElement }) => {
    const canvas = within(canvasElement);
    const button = canvas.getByRole('button', { name: '提交' });
    await userEvent.click(button);
    await expect(button).toBeDisabled();
  },
};
```

```tsx
// 更复杂的表单交互测试
export const FillForm: Story = {
  play: async ({ canvasElement }) => {
    const canvas = within(canvasElement);
    await userEvent.type(canvas.getByLabelText('用户名'), 'Alice');
    await userEvent.click(canvas.getByRole('button', { name: '登录' }));
    await expect(canvas.getByText('欢迎，Alice')).toBeInTheDocument();
  },
};
```

```text
Interaction Test 的运行方式：
1. 浏览器手动 —— Story 页直接观察 play 执行
2. 自动测试 —— test-runner 在 headless 浏览器批量跑
   npx test-storybook

依赖 @storybook/jest / @storybook/test 的 expect 与 userEvent。
```

## Visual Regression

Visual Regression（视觉回归测试）是「截图对比」—— 拍下每个 Story 的截图，后续改动再拍一次，像素级 diff 出变化。它抓的是「样式回归」，是逻辑测试覆盖不到的。

```text
视觉回归的原理：
1. 基线截图 —— 每个 Story 拍一张基准图
2. 变更截图 —— 改代码后再拍一次
3. 像素 diff —— 两张图对比，标出变化区域
4. 人工确认 —— 变化符合预期则接受（更新基线），否则是回归
```

```bash
# Chromatic（Storybook 官方视觉回归服务）
npx chromatic --project-token=xxx

# 本地也能用 Playwright 截图对比
npx playwright test --update-snapshots
```

```text
视觉回归工具的选型：
1. Chromatic —— Storybook 官方，与 Story 无缝集成（推荐）
2. Percy —— 通用视觉回归，支持任意页面/组件
3. Playwright toHaveScreenshot —— 手动写截图断言
4. Loki / Lost Pixel —— 自托管开源方案

关键点：跨浏览器、跨设备截图，diff 阈值可调。
```

## 应用场景实战

### 场景一：给组件库搭 Storybook 并写全套 Story

```bash
# 初始化
npx storybook@latest init

# 目录结构
src/components/Button/
├── Button.tsx
├── Button.css
└── Button.stories.tsx
```

```tsx
// Button.stories.tsx —— 覆盖所有状态
import type { Meta, StoryObj } from '@storybook/react';
import { fn } from '@storybook/test';
import { Button } from './Button';

const meta: Meta<typeof Button> = {
  title: '通用组件/Button',
  component: Button,
  args: { onClick: fn(), children: '按钮' },
  argTypes: {
    variant: {
      control: 'select',
      options: ['primary', 'default', 'danger'],
    },
  },
};
export default meta;

type Story = StoryObj<typeof Button>;

export const Primary: Story = { args: { variant: 'primary' } };
export const Default: Story = { args: { variant: 'default' } };
export const Danger: Story = { args: { variant: 'danger' } };
export const Disabled: Story = { args: { disabled: true } };
```

### 场景二：交互测试 + 视觉回归接入 CI

```yaml
# .github/workflows/storybook.yml
name: Storybook
on: [pull_request]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: npm ci
      - run: npx test-storybook          # 交互测试
      - run: npx chromatic --project-token=${{ secrets.CHROMATIC_TOKEN }}  # 视觉回归
```

```tsx
// 交互测试用例 —— 登录表单全流程
export const Login: Story = {
  play: async ({ canvasElement }) => {
    const canvas = within(canvasElement);
    await userEvent.type(canvas.getByLabelText('用户名'), 'Alice');
    await userEvent.type(canvas.getByLabelText('密码'), '123456');
    await userEvent.click(canvas.getByRole('button', { name: '登录' }));
    await expect(canvas.getByText('登录成功')).toBeInTheDocument();
  },
};
```

## 最佳实践与踩坑记录

### 最佳实践

1. 每个组件的每个状态都写 Story，Story 是文档也是测试用例
2. 用 CSF3 的 args 对象写法，简洁且便于 Controls 生成
3. 交互测试用 `@storybook/test` 的 userEvent，贴近真实用户操作
4. 视觉回归接 CI，PR 里直接看到 diff 截图
5. 用 JSDoc 注释补充 props 说明，Docs 自动展示
6. Story 命名用「分类/组件」，保持侧边栏分组清晰

### 踩坑记录

```text
坑 1：Story 里组件没被渲染出来
结论：画布空白，报 component 未定义。
原因：Meta 里 component 字段漏写或写错。
解法：确认 meta.component = 组件本身，且 default export 是 meta。

坑 2：交互测试报「element not found」
结论：getByRole 找不到目标元素。
原因：Story 渲染的是组件局部，canvasElement 范围要限定。
解法：用 within(canvasElement) 限定查询范围，别用全局 screen。

坑 3：视觉回归大量「伪变化」
结论：没改样式，截图却全红。
原因：动画/异步加载/字体渲染导致截图不稳定。
解法：视觉回归前禁用动画（waitForFonts、prefers-reduced-motion），
     等待组件稳定再截图。

坑 4：Args 类型推断不出控件
结论：Controls 面板里某 prop 没有控件。
原因：prop 是复杂类型或 union，Storybook 无法推断。
解法：手动在 argTypes 里声明 control 类型和 options。

坑 5：Actions 面板没有记录
结论：点了按钮，onClick 没出现在 Actions 里。
原因：回调没传 fn()，或组件内部没调用传入的 onClick。
解法：args 里 onClick: fn()，确认组件确实调用了该 prop。
```

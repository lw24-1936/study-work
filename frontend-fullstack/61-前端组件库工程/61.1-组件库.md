## 概述

组件库是把可复用的 UI 组件（按钮、表单、表格等）沉淀成一套统一、可维护的工程。它解决「多个项目重复造轮子、样式风格不一致、可访问性无人保障」的问题，是设计系统的代码载体。

```text
组件库的核心目标：
1. 复用 —— 组件一次开发、处处使用，降低重复劳动
2. 一致 —— 统一的视觉、交互、命名，产品体验一致
3. 可维护 —— 集中修 bug、升级，一处改全局生效
4. 规范 —— 内置可访问性、主题、国际化等最佳实践
```

```text
组件库工程的全景（六块拼图）：
1. Component API —— 组件对外接口设计
2. Token —— 设计令牌，颜色/间距/字号的单一事实来源
3. Theme —— 主题系统，暗色/亮色/品牌定制
4. Accessibility —— 可访问性，键盘/读屏器支持
5. Responsive —— 响应式，多端适配
6. Internationalization —— 国际化，多语言支持
```

## Component API

Component API 是组件的对外接口，决定了使用者怎么写代码。好的 API 直观、可组合、可预测，坏的 API 让人想绕开组件自己写。

```text
组件 API 设计原则：
1. props 命名一致 —— 同类组件用同义 prop（value、onChange、disabled）
2. 受控/非受控统一 —— 有 value 就有 defaultValue，有 onChange
3. 组合优先 —— 用 children/slots 组合，而非上百个 props
4. 语义化 —— <Button primary> 优于 <Button type="primary">
5. 默认值合理 —— 零配置即可用，开箱即用
```

```tsx
// 好的组件 API 示例
<Button variant="primary" size="md" onClick={handleClick}>
  提交
</Button>

<Select
  value={value}
  defaultValue="zh"
  onChange={setValue}
  options={[{ label: '中文', value: 'zh' }]}
/>
```

```tsx
// 组合式 API —— 用复合组件替代大量 props
<Tabs>
  <Tabs.List>
    <Tabs.Tab value="a">标签 A</Tabs.Tab>
    <Tabs.Tab value="b">标签 B</Tabs.Tab>
  </Tabs.List>
  <Tabs.Panel value="a">内容 A</Tabs.Panel>
  <Tabs.Panel value="b">内容 B</Tabs.Panel>
</Tabs>
```

```text
API 一致性反例：
Button 用 onClick，Card 用 handleClick —— 不一致
Input 用 value，Select 用 selected —— 不一致
禁用：Button 用 disabled，Table 用 editable=false —— 不一致

一致是组件库的生命线，不一致比没有组件库更糟。
```

## Theme

Theme（主题）是「可切换的整体视觉风格」的抽象，最典型的是暗色/亮色主题，也支持品牌定制（换主色）。主题系统让组件样式与具体颜色解耦，同一组件能渲染出不同风格。

```tsx
// 主题切换：组件不感知具体颜色，只引用语义 token
import { ThemeProvider } from './theme';

<ThemeProvider theme="dark">
  <Button variant="primary">提交</Button>
</ThemeProvider>
```

```text
主题系统的三层结构：
1. 基础色板 —— 原始色值（blue-500、gray-100）
2. 语义 token —— 别名（color-bg、color-text、color-primary）
3. 主题映射 —— 不同主题下语义 token 指向不同色板值

暗色主题的本质：同一个语义 token 在 dark 下指向不同色值，
组件代码零改动。
```

```css
/* 用 CSS 变量实现主题 —— 切换只需换 class */
:root {
  --color-bg: #ffffff;
  --color-text: #1a1a1a;
  --color-primary: #1677ff;
}

[data-theme='dark'] {
  --color-bg: #141414;
  --color-text: #e5e5e5;
  --color-primary: #4096ff;
}

.button {
  background: var(--color-primary);
  color: var(--color-bg);
}
```

## Token

Token（设计令牌）是设计决策（颜色、间距、字号、圆角、阴影）的命名变量，是设计稿与代码之间的契约。它是 Theme 的底层基础，Theme 本质上是「同一套 token 的不同取值」。

```text
Token 的分类：
1. 基础 token —— 原始值（color-blue-500、spacing-4、font-size-md）
2. 语义 token —— 用途别名（color-primary、spacing-padding-lg）
3. 组件 token —— 组件专属（button-height、input-radius）

使用语义 token 而非基础 token —— 换主题时只改映射不改组件。
```

```ts
// tokens.ts —— token 定义
export const tokens = {
  color: {
    blue500: '#1677ff',
    gray900: '#1a1a1a',
    gray100: '#f5f5f5'
  },
  spacing: {
    sm: '4px',
    md: '8px',
    lg: '16px'
  },
  radius: {
    sm: '4px',
    md: '8px',
    round: '9999px'
  }
};

// 语义 token 映射
export const semantic = {
  colorPrimary: tokens.color.blue500,
  colorText: tokens.color.gray900,
  colorBg: tokens.color.gray100,
  paddingMd: tokens.spacing.md
};
```

```json
// Style Dictionary —— token 单源，生成多平台产物
{
  "color": {
    "primary": { "value": "#1677ff" },
    "text": { "value": "#1a1a1a" }
  },
  "spacing": {
    "md": { "value": "8px" }
  }
}
```

## Accessibility

Accessibility（可访问性，a11y）让组件能被所有人使用，包括键盘用户、读屏器（Screen Reader）用户。组件库应当内置可访问性，而不是让使用者自己补。

```text
可访问性的四个关键点：
1. 语义化 —— 用原生元素（button、select）而非 div + onClick
2. 键盘可达 —— Tab 聚焦、方向键操作、Enter/Space 激活
3. ARIA —— aria-label、role、aria-expanded 补充语义
4. 焦点管理 —— 弹层打开聚焦、关闭归还焦点
```

```tsx
// 正确：原生 button + aria 属性
<button
  type="button"
  aria-label="关闭弹窗"
  onClick={onClose}
>
  关闭
</button>

// 错误：div 模拟按钮，键盘和读屏器都无法使用
// <div onClick={onClose}>关闭</div>
```

```text
常见可访问性问题：
1. 图标按钮缺 aria-label —— 读屏器读不出含义
2. 自定义下拉框不可键盘操作
3. 弹窗无焦点陷阱（focus trap），Tab 会跑到背景
4. 颜色对比度不足（正文 < 4.5:1）
5. 仅用颜色表达状态（红/绿），色盲用户无法区分
```

## Responsive

Responsive（响应式）让组件在不同屏幕尺寸下都能正常使用。组件库的响应式主要关注「组件在不同宽度下的布局行为」——栅格、断点、流式尺寸。

```text
响应式组件的实现手段：
1. 断点 —— 按屏幕宽度切换布局（sm/md/lg/xl）
2. 流式 —— 用百分比/auto-fill 自适应，而非固定像素
3. 容器查询 —— 按父容器宽度而非视口宽度响应
```

```tsx
// 栅格系统 —— 按断点分配列宽
<Grid>
  <Grid.Col span={12} md={6} lg={4}>内容</Grid.Col>
</Grid>
```

```css
/* 容器查询 —— 组件宽度自适应父容器 */
.card-container {
  container-type: inline-size;
}

@container (max-width: 400px) {
  .card {
    flex-direction: column;
  }
}
```

```text
断点与容器查询的区别：
断点 —— 响应「视口」宽度（整个窗口）
容器查询 —— 响应「父容器」宽度（组件所在区域）

组件库更应优先容器查询：同一个组件放在侧边栏（窄）和
主内容区（宽）应分别适配，而不是只看整个窗口。
```

## Internationalization

Internationalization（国际化，i18n）让组件库支持多语言，包括组件内置文案（如「确定」「取消」、分页的「共 N 条」）和日期/数字格式化。

```text
组件库国际化的三块内容：
1. 内置文案 —— 弹窗按钮、空状态、分页文案等
2. 数字/日期格式 —— 千分位、日期顺序（不同地区不同）
3. 方向 —— 支持 RTL（从右到左）布局
```

```tsx
// 组件库内置文案的国际化 —— 通过 locale 注入
import { ConfigProvider } from './lib';

<ConfigProvider locale={zhCN}>
  <App />
</ConfigProvider>

// 分页组件内置文案：
// zh-CN: "共 100 条"  en-US: "100 items in total"
```

```text
i18n 与 l10n：
i18n（国际化）—— 开发阶段让产品「可国际化」，架构上支持多语言
l10n（本地化）—— 为特定地区准备翻译与格式的过程

组件库做 i18n，应用层做 l10n，两者分工明确。
```

## 应用场景实战

### 场景一：搭建一套带主题切换的按钮组件

```tsx
// Button.tsx —— 组件只引用语义 token，不写死颜色
type ButtonProps = {
  variant?: 'primary' | 'default';
  children: React.ReactNode;
  onClick?: () => void;
};

export function Button({ variant = 'default', children, onClick }: ButtonProps) {
  return (
    <button
      type="button"
      className={`btn btn-${variant}`}
      onClick={onClick}
    >
      {children}
    </button>
  );
}
```

```css
/* button.css —— 主题变量 + 变体 */
.btn {
  padding: 8px 16px;
  border: none;
  border-radius: var(--radius-md);
  cursor: pointer;
}
.btn-primary {
  background: var(--color-primary);
  color: #fff;
}
.btn-default {
  background: var(--color-bg);
  color: var(--color-text);
  border: 1px solid var(--color-border);
}
```

### 场景二：给图标按钮补可访问性

```tsx
// 图标按钮 —— 只有图标无文字，必须 aria-label
function IconButton({ icon, label, onClick }: {
  icon: React.ReactNode;
  label: string;
  onClick?: () => void;
}) {
  return (
    <button type="button" aria-label={label} onClick={onClick}>
      {icon}
    </button>
  );
}

// 使用：读屏器会读出「删除」
<IconButton icon={<TrashIcon />} label="删除" onClick={remove} />
```

## 最佳实践与踩坑记录

### 最佳实践

1. 组件只引用语义 token，不写死颜色，主题切换零改动
2. 可交互元素用原生元素，语义和键盘支持免费获得
3. 图标按钮必加 aria-label，弹窗做焦点管理
4. 优先容器查询而非媒体查询做组件级响应式
5. 内置文案抽成 locale 配置，不硬编码中文
6. 用 Storybook 沉淀每个组件的用例，兼作文档与测试

### 踩坑记录

```text
坑 1：组件写死颜色导致暗色主题失效
结论：切到暗色主题，某组件还是白底黑字。
原因：组件里硬编码了 #fff / #000 而非语义 token。
解法：全量替换为 var(--color-*)，禁止硬编码色值。

坑 2：div 模拟按钮，键盘无法操作
结论：Tab 键跳过该「按钮」，Enter/Space 无效。
原因：div 无原生交互语义，读屏器也不识别。
解法：改 <button>，或用 role="button" + tabIndex + 键盘监听。

坑 3：Token 命名太「基础」，换主题要改组件
结论：组件引用 blue-500，品牌换色需全局改组件代码。
原因：用了基础 token 而非语义 token。
解法：组件只引用 color-primary 等语义 token，改映射即可换肤。

坑 4：国际化只翻文案，漏了数字/日期格式
结论：英文文案对了，但数字还是 1,234.5 中文格式。
原因：没接 Intl.NumberFormat / 日期格式化。
解法：格式化和文案都走 locale 配置，统一由 i18n 层处理。

坑 5：响应式只做媒体查询，组件放侧边栏崩了
结论：组件在窄容器里仍按视口断点渲染，布局溢出。
原因：媒体查询看视口不看容器。
解法：组件级适配用容器查询（container-type: inline-size）。
```

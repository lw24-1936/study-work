## 概述

共享存储让多台机器访问同一份数据：NFS（Linux 间共享文件，最常用）、Samba（Linux 和 Windows 共享）、iSCSI（块级共享，像本地磁盘）、分布式存储 Ceph/GlusterFS（大规模、高可用）。选型：Linux 间共享用 NFS，跨平台用 Samba，块设备用 iSCSI，大规模集群用 Ceph/GlusterFS。核心是「数据集中、多机访问」。

```text
共享存储选型：
1. NFS —— Linux 间共享文件，最简单常用
2. Samba —— 跨平台（Linux/Windows 共享），SMB 协议
3. iSCSI —— 块级共享（像本地磁盘），数据库/虚拟机
4. Ceph/GlusterFS —— 分布式，大规模高可用
```

## NFS

NFS（Network File System）是 Linux 间共享文件的标准协议：服务器导出目录，客户端挂载后像本地目录一样访问。配置：服务器 /etc/exports 定义导出目录 + 权限，客户端 mount -t nfs 挂载。NFS 适合「多台机器共享同一份文件」（如共享代码、共享数据）。版本 NFSv3（老）/NFSv4（新，支持安全认证）。

```text
# 实测（本机无 NFS 挂载）
$ mount | grep nfs || echo "无 nfs 挂载"
无 nfs 挂载
# 本机没配 NFS，以下为通用配置
```

```shell
# 服务器端：导出目录
echo '/data 192.168.1.0/24(rw,sync,no_root_squash)' >> /etc/exports
exportfs -ra                  # 重新导出
# 客户端：挂载
mount -t nfs 192.168.1.100:/data /mnt/data
# 持久化（fstab）
echo '192.168.1.100:/data /mnt/data nfs defaults 0 0' >> /etc/fstab
```

```text
NFS 要点：
1. 服务器 /etc/exports 导出，客户端 mount 挂载
2. 适合 Linux 间共享文件（代码/数据）
3. NFSv4 支持安全认证，NFSv3 简单但无加密
```

## Samba

Samba 是 Linux 实现 SMB/CIFS 协议的服务，用于「Linux 和 Windows 共享文件」——Windows 访问 Linux 的共享目录（像访问 Windows 共享）。配置 /etc/samba/smb.conf，定义共享 + 用户认证。适合「公司文件服务器」「Windows 和 Linux 混用环境」。

```shell
# 配置共享（/etc/samba/smb.conf）
# [share]
#   path = /data/share
#   browseable = yes
#   read only = no
#   valid users = alice

# 创建 samba 用户
smbpasswd -a alice
# 重启服务
systemctl restart smbd
```

```text
Samba 要点：
1. SMB/CIFS 协议，Linux/Windows 跨平台共享
2. 配置 /etc/samba/smb.conf + smbpasswd 用户
3. 适合文件服务器、跨平台环境
```

## iSCSI

iSCSI 是「块级」共享存储——通过 IP 网络共享「磁盘块」（不是文件），客户端挂载后像本地硬盘一样分区、格式化。适合「数据库、虚拟机」等需要块设备的场景。架构：target（存储服务器）提供块设备，initiator（客户端）连接使用。相比 NFS（文件级），iSCSI 是块级（性能更好、语义更接近本地盘）。

```text
iSCSI vs NFS：
1. iSCSI —— 块级共享，像本地磁盘，适合数据库/虚拟机
2. NFS —— 文件级共享，像共享目录，适合共享文件
3. iSCSI 更底层（能分区格式化），NFS 更简单（直接挂目录）
```

## 分布式存储 Ceph 与 GlusterFS

分布式存储解决「大规模 + 高可用」：Ceph（对象/块/文件三合一，企业级，架构复杂）、GlusterFS（分布式文件系统，简单，适合文件共享）。特点：数据分布在多台机器、自动冗余、横向扩展。相比单机 NFS，分布式存储适合「几十台以上的集群、TB/PB 级数据、高可用要求」。两者都是「把多台机器的磁盘聚合成一个存储池」。

```text
Ceph vs GlusterFS：
1. Ceph —— 对象/块/文件三合一，企业级，架构复杂（OSD/MON/MDS）
2. GlusterFS —— 分布式文件系统，简单，适合文件共享
3. 共同 —— 数据分布多机、自动冗余、横向扩展
```

## 应用场景实战

### 场景一：多台 Web 服务器共享一份代码（NFS）

```shell
# 存储服务器：导出代码目录
echo '/var/www 192.168.1.0/24(rw,sync,no_root_squash)' >> /etc/exports
exportfs -ra
# Web 服务器：挂载共享目录
mount -t nfs 192.168.1.100:/var/www /var/www
# 各 Web 服务器访问同一份代码，保证一致性
```

### 场景二：Linux 文件服务器给 Windows 用（Samba）

```shell
# 1. 装 samba
apt install samba
# 2. 配共享（smb.conf）
# 3. 建用户
smbpasswd -a alice
# 4. Windows 访问 \\192.168.1.100\share
```

## 最佳实践与踩坑记录

### 最佳实践

1. Linux 间共享用 NFS，跨平台用 Samba，块设备用 iSCSI
2. NFS 客户端挂载用 fstab 持久化，避免重启丢失
3. NFS 导出目录限定网段（/etc/exports 里配 IP 段），别导出给所有
4. 数据库/虚拟机用 iSCSI（块级），共享文件用 NFS（文件级）
5. 大规模高可用用 Ceph/GlusterFS，别用单机 NFS 硬撑

### 踩坑记录

```text
坑 1：NFS 客户端重启后挂载丢失
结论：mount 的 NFS 重启后没了。
原因：mount 是临时的，没写 fstab。
解法：写 /etc/fstab 持久化挂载。

坑 2：NFS 挂载卡住，df 命令都卡
结论：NFS 服务器挂了，客户端 df/ls 卡住不动。
原因：NFS 默认 hard 挂载，服务器不可达时客户端无限重试。
解法：用 soft 挂载选项（超时返回错误），或 soft,intr。

坑 3：NFS 导出没限网段，被全网访问
结论：/etc/exports 导出给 *，任何机器都能挂。
原因：没限制网段，权限过宽。
解法：exports 里限定网段（192.168.1.0/24），并配防火墙。

坑 4：NFS 权限问题，客户端 root 没权限
结论：客户端 root 访问 NFS 文件报权限不足。
原因：root_squash（root 被映射成 nobody），默认安全策略。
解法：理解 root_squash，需要 root 权限用 no_root_squash（注意安全）。

坑 5：Samba 和 Windows 版本协议不兼容
结论：Windows 10 连不上老 Samba。
原因：SMB 协议版本不匹配（老 SMB1 被 Windows 禁用）。
解法：Samba 配置启用 SMB2/3（min protocol = SMB2）。
```

## 概述

共享存储让多台机器访问同一份数据，是「数据集中、多机访问」的基础设施。按共享粒度分四类技术：

1. **NFS**：Linux 之间共享文件的最常用方案（内核自带客户端，天然支持）。
2. **Samba（SMB/CIFS）**：Linux 与 Windows 跨平台共享的标准协议。
3. **iSCSI**：块级共享，客户端把远端块设备当成「本地磁盘」使用（数据库、虚拟机）。
4. **分布式文件系统（Ceph / GlusterFS）**：多台机器磁盘聚合为存储池，横向扩展 + 自动冗余，适合大规模集群。

选型一句话：**Linux 间共享文件用 NFS；跨平台（Windows）用 Samba；要裸盘块设备用 iSCSI；几十台以上的大规模高可用集群用 Ceph/GlusterFS**。共享存储不是「越复杂越好」——单机 NFS 能解决的问题不要上分布式，运维成本是选型的关键考量。

```text
共享存储四层选型：
1. NFS        —— 文件级，Linux 间共享，最简单常用（内核原生）
2. Samba      —— 文件级，Linux/Windows 跨平台，SMB 协议
3. iSCSI      —— 块级，像本地磁盘，数据库/虚拟机场景
4. Ceph/GlusterFS —— 文件/块/对象，分布式，大规模高可用
```

## 核心概念

### 1. 文件级共享 vs 块级共享

| 维度 | 文件级共享（NFS/Samba） | 块级共享（iSCSI） |
|---|---|---|
| 共享单位 | 目录（导出目录/共享名） | 裸磁盘块（LUN） |
| 客户端视角 | 挂载成目录，看到的是文件 | 识别成 /dev/sdX 裸盘，自己分区格式化 |
| 适用场景 | 共享文件、代码、文档 | 数据库、虚拟机磁盘、集群文件系统底层 |
| 并发语义 | 文件锁/租约由协议管理 | 多端同时读写需上层（集群 FS/数据库）保证 |
| 性能开销 | 多一层文件系统 + 协议封装 | 接近本地盘（协议开销小） |

**记住**：iSCSI 共享的是「磁盘」，NFS/Samba 共享的是「目录」。数据库、虚拟机要块设备用 iSCSI；团队共享文件用 NFS/Samba。

### 2. NFS（Network File System）

- 服务器在 `/etc/exports` 声明「导出哪个目录、允许哪些网段/主机、什么权限选项」。
- 客户端 `mount -t nfs 服务器:目录 挂载点` 挂载后，像本地目录一样使用。
- 基于 **RPC（远程过程调用）+ XDR（外部数据表示）** 机制，文件操作由内核转发到服务器执行。
- 版本：**NFSv3**（经典，无状态，UDP/TCP 都支持，无内置加密）与 **NFSv4**（有状态、单端口 2049、内置锁与租约、支持 Kerberos 认证，是当前主流）。

### 3. Samba / SMB / CIFS

- **SMB（Server Message Block）** 是微软主导的文件共享协议，CIFS 是其早期版本名，现在一般统称 SMB。
- **Samba** 是 Linux 上 SMB 协议的实现：Linux 机器模拟 Windows 文件服务器，Windows 资源管理器输入 `\\192.168.1.100\share` 即可访问。
- 用户认证独立于系统用户：用 `smbpasswd -a` 建立 Samba 口令（可以复用系统用户名）。
- 协议版本：SMB1（老、有严重漏洞如永恒之蓝，Windows 默认禁用）→ SMB2/3（现代默认）。Samba 侧用 `min protocol = SMB2` 强制。

### 4. iSCSI（Internet Small Computer System Interface）

- 把 **SCSI 命令封装进 TCP/IP** 传输，用普通以太网模拟 SAN（存储区域网络）。
- 角色：**target（目标端，存储服务器）** 提供块设备（LUN）；**initiator（发起端，客户端）** 连接后由内核识别为本地磁盘。
- 管理工具：target 端 `targetcli`/`tgtadm`；initiator 端 `iscsiadm`。
- 用途：数据库、虚拟机镜像、需要「裸盘」的存储场景；比 FC（光纤通道）便宜，是 IP-SAN 的主流。

### 5. 分布式文件系统（Ceph / GlusterFS）

- **Ceph**：数据切成对象，按 **CRUSH 算法**分布到各 OSD 节点，多副本/纠删码保证可靠性；同时提供对象（RADOS GW）、块（RBD）、文件（CephFS）三种接口；组件多（MON/OSD/MDS），架构复杂。
- **GlusterFS**：纯分布式文件系统，文件分布到各 brick（存储节点），支持副本卷、条带卷；配置简单，只提供文件接口。
- 适合：几十台以上集群、TB/PB 级数据、要求无单点的高可用场景。

### 6. 挂载与导出的几个关键名词

- **导出表（export table）**：服务器端「哪些目录、给谁、什么权限」的清单（/etc/exports），`exportfs -v` 查看生效结果。
- **挂载点（mount point）**：客户端把远端目录「接」到本地目录树的位置。
- **nobody / 65534**：匿名映射用户。NFS 默认 `root_squash` 把客户端 root 映射成 nobody（UID 65534），防止越权。
- **stale file handle**：服务端导出的目录被删除/重建后，客户端旧句柄失效产生的「陈旧文件句柄」错误。
- **LUN（Logical Unit Number）**：iSCSI target 导出的块设备单元。

## 工作原理

### 1. NFS 请求的完整链路

```text
客户端应用 open/read/write 文件
   ↓  VFS（虚拟文件系统层）识别为 NFS 挂载点
   ↓  NFS 客户端内核模块把操作封装为 RPC 请求
   ↓  XDR 序列化（跨平台数据表示，解决字节序差异）
   ↓  TCP（NFSv3 可 UDP）发送到服务器 2049 端口
   ↓  服务器 rpc.nfsd 内核线程解包
   ↓  调用服务器本地 VFS 执行真实磁盘 IO
   ↓  结果按原路径返回客户端
```

关键点：

- **RPC（Remote Procedure Call）**：让「远端文件操作」看起来像本地函数调用，客户端内核屏蔽了网络细节。
- **XDR（eXternal Data Representation）**：统一数据编码格式，保证不同字节序（x86 小端 vs SPARC 大端）机器之间数据一致。
- **portmapper（rpcbind）**：NFSv3 时代服务器服务端口不固定（nfsd 2049、mountd 随机高位端口），由 rpcbind（111 端口）登记注册；NFSv4 把服务收敛到单一 2049 端口，简化了防火墙配置。
- **有状态 vs 无状态**：NFSv3 无状态（服务器重启后客户端挂载仍有效，锁靠 lockd 辅助）；NFSv4 有状态（引入会话与租约，锁语义更严格，服务器重启需要客户端重新协商）。

### 2. NFSv3 vs NFSv4 对比

| 维度 | NFSv3 | NFSv4 |
|---|---|---|
| 状态 | 无状态 | 有状态（会话 + 租约） |
| 端口 | 2049 + rpcbind 多端口（mountd 随机） | 单端口 2049（含挂载协议） |
| 传输 | TCP/UDP | TCP（默认），NFSv4.1+ 支持 pNFS 并行 |
| 文件锁 | 独立 lockd 协议 | 内置锁（NLM 不需要） |
| 安全认证 | AUTH_SYS（仅 UID/GID 明文） | 支持 Kerberos（krb5/krb5i/krb5p），AUTH_SYS 仍可用 |
| 挂载协议 | 单独 mount 协议（mountd） | 集成（无 mountd） |
| 用户映射 | 纯数字 UID/GID，跨机器需手动对齐 | 支持 idmapd 名字映射（user@domain） |
| 兼容性 | 老系统、嵌入式支持好 | 现代 Linux/Windows（Client for NFS）主流 |

生产环境默认用 NFSv4；只有老客户端、老内核、特殊嵌入式环境才需要回退 NFSv3。

### 3. Samba 工作原理

```text
Windows 客户端（SMB 客户端）
   ↓  建立 TCP 445 连接（老环境 139/NetBIOS）
   ↓  SMB 协商（版本、特性、加密能力）
   ↓  认证（NTLM/Kerberos，取决于域环境）
   ↓  访问共享 \\server\share
   ↓  Samba（smbd 进程）把 SMB 文件操作翻译为
   ↓  服务器本地 POSIX 文件操作，并做权限/所有权映射
   ↓  （Windows ACL ↔ POSIX 权限的转换）
```

- `smbd`：文件共享与打印服务主进程（445 端口）。
- `nmbd`：NetBIOS 名称解析（老环境 137/138/139，现代环境可关）。
- 用户映射：Windows 用户名（`domain\alice`）↔ Linux 系统用户（`alice`），口令独立存于 `/var/lib/samba/private/passdb.tdb`（smbpasswd 维护）。
- 权限映射：Windows 的 ACL 与 Linux 的 rwx 权限体系不同，Samba 做近似翻译；`force user`、`valid users` 等指令用于控制最终生效身份。

### 4. iSCSI 工作原理

```text
initiator（客户端）                          target（存储服务器）
应用需要磁盘 → 内核 iSCSI 驱动
  ↓  iscsiadm 发现（Discovery，3260 端口）
  ↓  登录（Login，CHAP 认证可选）
  ↓  建立会话，SCSI 命令封装进 TCP 包
  ↓━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━→   targetcli/tgtd 解封装
  ↓                                           调用本地块设备（LUN）执行 IO
  ↓←━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━  返回结果
  ↓
内核把该会话注册为 /dev/sdX（块设备）
  ↓  fdisk 分区 → mkfs 格式化 → mount 使用（与本地盘完全一致）
```

### 5. Ceph / GlusterFS 工作原理简述

- **Ceph**：数据切对象 → CRUSH 算法按集群拓扑（机架/主机/OSD）伪随机分布 → 每个对象多副本（默认 3 副本，写需全部确认）或纠删码。客户端通过 librados 直接与 OSD 通信（去中心化），MON 只负责集群状态（谁在、谁挂了）。
- **GlusterFS**：卷类型决定分布方式——分布式（文件散列到 brick）、复制（每文件多副本）、条带（大文件分块）、或组合。通过 FUSE 挂载到客户端。

## 常用命令与配置

### 服务端（NFS）

```shell
# Ubuntu/Debian 安装
apt install nfs-kernel-server

# 编辑 /etc/exports 导出目录后，重载导出表
exportfs -ra                 # 重新导出全部（-r 重读 exports，-a 导出所有）
exportfs -v                  # 查看当前生效的导出及选项
exportfs -u 192.168.1.0/24:/data   # 撤销某条导出

# 查看服务器自己导出了什么
showmount -e localhost       # 依赖 nfs-common（Ubuntu）/ nfs-utils（RHEL）
showmount -e 192.168.1.100   # 从客户端查看远程服务器导出

# 服务管理
systemctl enable --now nfs-kernel-server   # RHEL 系：nfs-server
```

### 客户端（NFS）

```shell
# Ubuntu/Debian 客户端只需 nfs-common（含 mount.nfs、showmount、nfsstat）
apt install nfs-common

# 挂载（NFSv4 默认）
mount -t nfs 192.168.1.100:/data /mnt/data
mount -t nfs4 192.168.1.100:/data /mnt/data   # 显式 v4
mount -o vers=3 192.168.1.100:/data /mnt/data # 显式 v3

# 常用挂载选项组合
mount -t nfs -o rw,sync,hard,intr,noatime,rsize=1048576,wsize=1048576 \
      192.168.1.100:/data /mnt/data

# 查看挂载信息
mount | grep nfs
df -hT | grep nfs
nfsstat -m                 # 查看 NFS 挂载的详细选项（客户端）
nfsstat -rc                # 客户端 RPC 调用统计（看延迟/重传）
nfsstat -rs                # 服务端 RPC 统计（服务端执行）

# 卸载
umount /mnt/data
umount -f /mnt/data        # 卡死时强制卸载
```

### Samba

```shell
apt install samba smbclient      # RHEL 系：dnf install samba samba-client
systemctl enable --now smbd

smbpasswd -a alice               # 创建/设置 Samba 用户口令（用户需已存在）
smbpasswd -e alice               # 启用用户
pdbedit -L                       # 列出 Samba 用户
testparm                         # 校验 smb.conf 语法（改配置后必跑）

# 客户端命令行访问
smbclient -L //192.168.1.100 -U alice       # 列出共享
smbclient //192.168.1.100/share -U alice    # 交互式访问共享

# Linux 挂载 CIFS 共享
apt install cifs-utils
mount -t cifs //192.168.1.100/share /mnt/win -o username=alice,uid=1000,gid=1000
```

### iSCSI

```shell
# target 端（存储服务器）
apt install targetcli-fb          # RHEL 系：dnf install targetcli
targetcli                         # 交互式管理（创建 backstore/LUN/ACL）

# initiator 端（客户端）
apt install open-iscsi            # RHEL 系：dnf install iscsi-initiator-utils
systemctl enable --now iscsid
iscsiadm -m discovery -t sendtargets -p 192.168.1.100   # 发现 target
iscsiadm -m node -T iqn.2026-08.local.lab:data -p 192.168.1.100 --login  # 登录
lsblk                             # 登录后出现新块设备 /dev/sdX
iscsiadm -m session               # 查看会话
iscsiadm -m node -T iqn... --logout   # 登出
```

## 配置文件解析

### /etc/exports（NFS 导出表）逐行解析

```text
# 格式：导出目录  允许主机(选项1,选项2) [允许主机2(选项...)]
/data       192.168.1.0/24(rw,sync,no_subtree_check) 10.0.0.5(ro)
/home/pub   *(ro,all_squash,anonuid=1000,anongid=1000)
/backup     192.168.1.0/24(rw,sync,no_root_squash,no_subtree_check)
```

| 字段/选项 | 含义 |
|---|---|
| `/data` | 要导出的目录（建议挂载在独立分区/磁盘上） |
| `192.168.1.0/24` | 允许访问的网段；`*` 表示所有主机（慎用）；也可写单个 IP 或主机名 |
| `rw` / `ro` | 读写 / 只读 |
| `sync` | 同步写：服务器落盘后才应答（数据安全，默认推荐） |
| `async` | 异步写：先应答后落盘（性能高，断电可能丢数据） |
| `root_squash` | 客户端 root 映射为 nobody/匿名（默认，安全） |
| `no_root_squash` | 客户端 root 保留 root 权限（危险，仅可信内网） |
| `all_squash` | 所有用户都映射为匿名用户（公共只读目录常用） |
| `anonuid` / `anongid` | 匿名映射到指定 UID/GID（配合 all_squash） |
| `no_subtree_check` | 关闭子树检查（提升性能，现代版本默认推荐） |
| `fsid=0` | 标记 NFSv4 根导出（配合 NFSv4 伪文件系统） |

修改后必须 `exportfs -ra` 重载；删除导出目录条目后，客户端需重新挂载，否则出现 stale file handle。

### /etc/fstab 中的 NFS 持久化挂载

```text
# 设备(服务器:目录)  挂载点  类型  选项              dump pass
192.168.1.100:/data  /mnt/data  nfs  defaults,_netdev,noatime 0 0
```

- `_netdev`：**必须加**，告诉系统「这是网络设备」，开机时等网络就绪后再挂载，否则开机挂载失败。
- `noatime`：不更新访问时间，减少 NFS 网络写请求，性能提升明显。
- 选项之间用逗号分隔，不要有空格。
- 修改 fstab 后 `mount -a` 验证，确认无误再重启，避免开机卡死在挂载。

### /etc/nfs.conf（NFSv4 服务端配置，RHEL 系）

```ini
[nfsd]
# 并发 nfsd 线程数（默认自动按 CPU 数）
threads=16
# 版本支持
vers4=y
vers3=y

[exportfs]
# 客户端 root_squash 策略全局默认（通常不在这里改）
```

Ubuntu 对应文件为 `/etc/default/nfs-kernel-server`（主要配置 `RPCNFSDCOUNT` 线程数）。

### /etc/idmapd.conf（NFSv4 用户映射）

```ini
[General]
# 域名必须与客户端一致，否则名字映射失败，文件属主变成 nobody
Domain = lab.local

[Mapping]
Nobody-User = nobody
Nobody-Group = nogroup
```

NFSv4 用「名字 + 域」而不是数字 UID 传递用户身份，跨机器时 `Domain` 不一致会导致权限错乱（表现为 nobody/65534）。

### /etc/samba/smb.conf 关键段

```ini
[global]
   workgroup = WORKGROUP          # Windows 工作组名
   server string = %h 文件服务器
   security = user                # 用户级认证（默认，最常用）
   map to guest = Bad User        # 允许 guest 访问（按需）
   min protocol = SMB2            # 禁 SMB1，防老协议漏洞
   log file = /var/log/samba/log.%m
   max log size = 1000

[share]                           # 共享名 = Windows 里看到的 \\server\share
   path = /data/share             # 服务器上的真实目录
   browseable = yes
   read only = no
   valid users = alice, bob       # 允许的用户（白名单）
   write list = alice             # 可写用户
   create mask = 0644             # 新建文件默认权限
   directory mask = 0755
   force user = alice             # 所有写入以 alice 身份执行（共享目录场景）
```

改动后用 `testparm` 校验语法，再 `systemctl restart smbd`。

### iSCSI 配置文件简述

- `/etc/iscsi/iscsid.conf`：initiator 端默认参数（自动登录 `node.startup = automatic`、CHAP 用户名密码等）。
- `/etc/iscsi/initiatorname.iscsi`：本机 initiator 的 IQN 名（`InitiatorName=iqn.2026-08.local:client1`），target 端 ACL 按它授权。
- target 端配置保存在 `/etc/target/`（targetcli 管理，`saveconfig` 持久化）。

## 应用场景实战

### 场景一：多台 Web 服务器共享一份代码（NFS）

需求：3 台 Web 服务器读取同一份应用代码，发布一次全网生效。

```shell
# ① 存储服务器（192.168.1.100）
apt install nfs-kernel-server
mkdir -p /var/www

# ② 编辑 /etc/exports，追加：
echo '/var/www 192.168.1.0/24(rw,sync,no_subtree_check,no_root_squash)' >> /etc/exports
exportfs -ra && exportfs -v          # 重载并确认

# ③ 防火墙放行（ufw）
ufw allow from 192.168.1.0/24 to any port 2049 proto tcp
# NFSv4 单端口 2049；若用 NFSv3 还需放行 111、20048（mountd）及 rpc 高位端口

# ④ 各 Web 服务器挂载
apt install nfs-common
mount -t nfs -o rw,noatime,hard 192.168.1.100:/var/www /var/www

# ⑤ 持久化（/etc/fstab 追加）
echo '192.168.1.100:/var/www /var/www nfs defaults,_netdev,noatime 0 0' >> /etc/fstab

# ⑥ 验证
mount | grep nfs
df -hT /var/www
# 任一节点写文件，其他节点立即可见（close-to-open 一致性）
```

注意：代码共享场景一般用 `no_root_squash` 方便发布账号以 root 写入，但**只限可信内网**；对外服务建议保持 `root_squash` 并给发布账号分配专用 UID。

### 场景二：Linux 文件服务器给 Windows 用（Samba）

需求：公司文件服务器（Linux）让 Windows 员工通过资源管理器访问共享目录。

```shell
# ① 安装
apt install samba smbclient

# ② 配置 /etc/samba/smb.conf（见「配置文件解析」），关键段：
# [public]
#    path = /data/share
#    read only = no
#    valid users = alice
#    min protocol = SMB2

# ③ 建系统用户 + Samba 口令
useradd -m alice
smbpasswd -a alice

# ④ 启动并校验
testparm
systemctl enable --now smbd

# ⑤ Windows 侧访问
# 资源管理器地址栏输入：\\192.168.1.100\public
# 输入用户名 alice 和 Samba 口令即可

# ⑥ Linux 客户端挂载验证（可选）
apt install cifs-utils
mount -t cifs //192.168.1.100/public /mnt/win -o username=alice,uid=1000,gid=1000
df -hT /mnt/win
```

安全提醒：Samba 口令与系统口令相互独立（即使系统用户已锁密码也不影响 Samba 登录）；强烈建议 `min protocol = SMB2`，SMB1 存在永恒之蓝（EternalBlue）等严重漏洞。

### 场景三：数据库服务器使用 iSCSI 块存储

需求：数据库（如 MySQL）数据盘放到远端存储阵列，本地无盘、容量可弹性扩展。

```shell
# target 端（存储服务器 192.168.1.200）
apt install targetcli-fb
targetcli <<'EOF'
backstores/block create name=db_lun dev=/dev/sdb        # 用真实磁盘做 backstore
iscsi/ create iqn.2026-08.local.lab:db                   # 创建 target
iscsi/iqn.2026-08.local.lab:db/tpg1/luns create /backstores/block/db_lun
iscsi/iqn.2026-08.local.lab:db/tpg1/acls create iqn.2026-08.local:dbclient   # 只允许指定 initiator
saveconfig
EOF
# 防火墙放行 3260
ufw allow 3260/tcp

# initiator 端（数据库服务器）
apt install open-iscsi
echo 'InitiatorName=iqn.2026-08.local:dbclient' > /etc/iscsi/initiatorname.iscsi
systemctl enable --now iscsid
iscsiadm -m discovery -t sendtargets -p 192.168.1.200   # 发现
iscsiadm -m node -T iqn.2026-08.local.lab:db -p 192.168.1.200 --login  # 登录
lsblk                                  # 出现 /dev/sdb
fdisk /dev/sdb && mkfs.ext4 /dev/sdb1 # 分区格式化（与本地盘一致）
mount /dev/sdb1 /var/lib/mysql         # 数据库数据目录
```

注意：iSCSI 块设备上要建文件系统再给数据库用；多路径（MPIO）、CHAP 认证、独立存储网络是高可用生产环境的标配（见「性能与调优」）。

### 场景四：大规模集群存储选型（Ceph/GlusterFS）

需求：50 节点应用集群，数据量 20TB+，要求无单点、自动冗余。

```shell
# GlusterFS 示例（简单场景：2 副本复制卷）
apt install glusterfs-server
gluster peer probe node2
gluster volume create gv0 replica 2 node1:/data/brick1 node2:/data/brick2 force
gluster volume start gv0
# 客户端挂载
mount -t glusterfs node1:/gv0 /mnt/gfs

# Ceph 示例（对象/块/文件三合一，架构较复杂，生产一般用 cephadm 部署）
# cephadm bootstrap --mon-ip 192.168.1.10
# 部署 OSD/MDS 后：rbd create / ceph-fuse 挂载 CephFS
```

选型：纯文件共享、团队小 → GlusterFS；需要块存储 + 对象存储 + 文件存储三合一、有专门运维 → Ceph；集群规模不大但要求高可用 → 也可以先用 NFS + keepalived/DRBD 方案（见 [[19.2-Keepalived 与 VRRP]] 相关章节）。

### 选型决策表（NFS vs Samba vs iSCSI vs 分布式 FS）

| 维度 | NFS | Samba | iSCSI | Ceph/GlusterFS |
|---|---|---|---|---|
| 共享粒度 | 文件 | 文件 | 块 | 文件/块/对象 |
| 客户端 | Linux/Unix 原生；Windows 可装 Client for NFS | Windows 原生；Linux 装 cifs-utils | Linux/Windows 均可（initiator） | Linux（FUSE/内核）；Windows 需额外客户端 |
| 部署复杂度 | 低 | 低 | 中 | 高（Ceph 尤甚） |
| 性能 | 中（文件级协议） | 中（协议开销较大） | 高（块级、接近本地盘） | 中高（取决于副本/网络） |
| 高可用 | 单点，需上层方案 | 单点 | 需多路径 + 存储侧冗余 | 天然多副本、无单点 |
| 典型场景 | 共享代码/文档/家目录 | Windows 互操作 | 数据库、虚拟机磁盘 | 大规模云平台、PB 级 |

## 性能与调优

1. **读写块大小 rsize/wsize**：NFS 单次读写的数据块大小，默认 1MB（现代内核自动协商），可显式指定 `rsize=1048576,wsize=1048576`。块太小（如 32K）吞吐低；大文件顺序读写调大块收益明显，小文件随机 IO 影响不大。
2. **传输协议选 TCP**：NFSv3 时代 UDP 在局域网有延迟优势，但丢包后无重传保证、容易出「半写」；现代网络一律 TCP，NFSv4 默认仅 TCP。
3. **noatime 挂载选项**：不更新 atime，消除每次读操作带来的属性写回，NFS 场景收益显著（一次读少一次 RPC 往返），Web 服务器、代码目录尤其明显。
4. **async vs sync 权衡**：`sync` 保证服务器落盘后才应答，数据安全但写性能低（尤其机械盘 + 小文件）；`async` 先应答后落盘，写吞吐大幅提升，但**断电/宕机可能丢已应答数据**。生产数据库类数据用 sync；缓存、日志、可重建数据可用 async。也可以服务器端磁盘用带电池保护的 RAID 卡 + sync 折中。
5. **用 nfsstat 观察**：`nfsstat -rc` 看客户端 RPC 次数与重传（重传多 = 网络不稳/服务端慢）；`nfsstat -rs` 看服务端吞吐。结合 `iostat`、`sar -n DEV` 判断瓶颈在网络还是磁盘。
6. **服务端 nfsd 线程数**：RHEL `/etc/nfs.conf` 的 `threads`、Ubuntu `/etc/default/nfs-kernel-server` 的 `RPCNFSDCOUNT`，默认按 CPU 核数，高并发场景调大（如 32）。
7. **网络基础设施**：共享存储走网络，内网千兆起步、生产建议万兆；延迟敏感场景把存储流量与业务流量隔离（独立网卡/VLAN）；支持 jumbo frame（MTU 9000）的交换机开启可降低 CPU 开销与包数。
8. **Samba 性能**：`read raw = yes`、`write raw = yes`（大块传输）、`socket options = TCP_NODELAY` 是老经验；现代 Samba 默认已优化，重点检查网络与磁盘；`aio read size`/`aio write size` 开启异步 IO。
9. **iSCSI 用独立网络**：块 IO 对延迟极敏感，存储流量与业务流量分开（独立网卡/VLAN/交换机）；SSD backstore + 多路径（MPIO，multipath 配置）提升带宽与可用性；客户端 IO 调度器用 none/noop（`echo none > /sys/block/sdX/queue/scheduler`）。
10. **分布式 FS**：副本数（replica 3 vs 2）与性能/容量直接权衡；Ceph 可对冷数据用纠删码（EC）省空间换 CPU；GlusterFS 复制卷写放大明显，写密集场景慎用复制卷。

## 安全与权限

1. **exports 严格限网段**：导出条目写具体网段/主机（`192.168.1.0/24`），**不要用 `*`**；`exportfs -v` 定期审计导出表。公网环境 NFS 暴露 = 灾难。
2. **root_squash 是默认安全策略**：客户端 root 在服务端被映射为 nobody（UID 65534），无法越权读写服务端文件。`no_root_squash` 只在「可信内网 + 明确需要 root 写」时使用，且要配防火墙；`all_squash` + `anonuid/anongid` 用于公共目录把所有人钉死为某个低权限用户。
3. **防火墙端口**：
   - NFSv4：只需 TCP 2049。
   - NFSv3：2049 + rpcbind(111) + mountd(随机/20048) + lockd/nlockmgr 随机端口——用固定端口配置（`/etc/nfs.conf` 里 `mountd-port=20048`、`statd-port=...`）再放行。
   - firewalld（RHEL）：`firewall-cmd --permanent --add-service=nfs --add-service=rpc-bind --add-service=mountd && firewall-cmd --reload`。
   - ufw（Ubuntu）：`ufw allow from 192.168.1.0/24 to any port 2049 proto tcp`。
4. **Kerberos 认证（NFSv4）**：`sec=krb5`（仅认证）/`krb5i`（认证+完整性）/`krb5p`（认证+加密）。需要 KDC + 主机 keytab，配置 `Domain`（idmapd）与 DNS 一致。纯内网普通场景用 AUTH_SYS 足够，涉密/跨机房用 Kerberos。
5. **SELinux（RHEL 必做）**：RHEL 默认 Enforcing，SELinux 会拦 NFS/Samba 的导出与访问：
   ```shell
   setsebool -P nfs_export_all_rw 1      # 允许导出 rw
   setsebool -P samba_export_all_rw 1    # 允许 Samba 导出 rw
   setsebool -P samba_enable_home_dirs 1 # 允许共享用户家目录
   semanage fcontext -a -t public_content_rw_t "/data(/.*)?" && restorecon -R /data
   ```
   改完用 `getsebool -a | grep -E 'nfs|samba'` 验证；SELinux 拦阻查 `/var/log/audit/audit.log`（`ausearch -m avc`）。Ubuntu 用 AppArmor，一般无需配置，但 `nfs-kernel-server` 的 AppArmor profile 若启用需确认不拦导出目录。
6. **Samba 安全**：`security = user` 用户级认证；禁用 SMB1（`min protocol = SMB2`）；口令策略（`pdbedit` 管理）；共享目录权限 + `valid users` 白名单双保险；Samba 口令定期更换；`smbstatus` 查看在线会话与打开文件。
7. **iSCSI CHAP 认证**：target 端启用单向/双向 CHAP（`iscsi/.../tpg1/acls/iqn.../chap auth`），防未授权 initiator 登录；initiator 端在 `/etc/iscsi/iscsid.conf` 配置 CHAP 用户名密码。
8. **权限映射注意**：NFSv3 按数字 UID/GID 判断权限，客户端与服务端用户 UID 不一致会出现「明明有权限却 Permission denied」；NFSv4 用 idmapd 名字映射，Domain 必须两端一致。

## 故障排查

### 案例一：NFS 挂载失败（connection refused / timeout）

```shell
# 症状：mount -t nfs ... 报 connection refused 或 Operation timed out
showmount -e 192.168.1.100          # ① 服务器导出正常吗（不通则查网络/服务）
nc -zv 192.168.1.100 2049           # ② NFSv4 端口通不通
systemctl status nfs-kernel-server  # ③ 服务端服务状态（RHEL：nfs-server）
ss -tlnp | grep 2049                # ④ 服务端 2049 是否监听
ufw status                          # ⑤ 防火墙放行了吗（RHEL：firewall-cmd --list-services）
exportfs -v                         # ⑥ 服务端导出表里有没有这条（权限/网段匹配）
```

排查顺序：**服务活着吗 → 端口通吗 → 防火墙放了吗 → 导出表对吗**。最常踩的是防火墙没放 2049 或 exports 网段写错。

### 案例二：NFS 挂载卡住，df/ls 都卡死（hard 挂载）

```text
症状：NFS 服务器宕机/断网后，客户端 df、ls、任何访问该挂载点的命令
      全部卡住不动（D 状态进程），kill 都杀不掉。
原因：NFS 默认 hard 挂载——服务器不可达时客户端无限重试，进程
      阻塞在内核等待。这是「保证数据一致性」的设计，代价是卡死。
```

```shell
# 排查
mount | grep nfs                    # 看挂载选项是 hard 还是 soft
ps -eo pid,stat,wchan:30,cmd | grep -i nfs   # D 状态 = 等 IO（NFS）
cat /proc/mounts | grep nfs         # 确认选项

# 解决
umount -f /mnt/data                 # 强制卸载（可能仍不成功）
umount -l /mnt/data                 # lazy 卸载（立刻返回，后台清理）
# 预防：挂载加 soft,intr（超时返回错误而非卡死）；
# 数据一致性要求高的场景权衡：hard+intr 比 soft 安全，
# 但 soft 至少不会让整机业务被 NFS 拖死
```

### 案例三：stale file handle（陈旧文件句柄）

```text
症状：客户端访问 NFS 文件报 Stale file handle (os error 116)。
原因：服务端导出目录被删除、重建、或 exportfs 重载后路径变化，
      客户端旧文件句柄指向已不存在的对象。
```

```shell
# 解决
umount /mnt/data
mount -t nfs 192.168.1.100:/data /mnt/data   # 重新挂载即可
# 预防：不要在导出目录上直接 rm -rf 重建；先 umount 客户端再操作
```

### 案例四：权限问题——属主变成 nobody / 65534，或 Permission denied

```text
症状：客户端看到文件属主是 nobody(65534)，root 读写报 Permission denied；
      或客户端用户有权限但服务端拒绝。
原因（按概率排序）：
  1. root_squash 生效：客户端 root 被映射成 nobody——这是正常的，不是故障；
  2. NFSv4 idmapd Domain 两端不一致，名字映射失败退化为 nobody；
  3. 客户端与服务端用户 UID 不一致（NFSv3 纯数字匹配）；
  4. 服务端目录权限本身不允许（chmod/chown 没对齐）。
```

```shell
# 排查
id alice                          # 客户端用户 UID
ssh server id alice               # 服务端用户 UID（两端必须一致）
cat /etc/idmapd.conf | grep Domain  # 两端 Domain 一致吗
exportfs -v                      # 服务端选项：root_squash / all_squash
ls -ln /data                     # 服务端目录真实属主（数字视角）
```

### 案例五：Windows 连不上 Samba 共享

```shell
# 症状：\\192.168.1.100\share 提示找不到网络路径 / 拒绝访问
nc -zv 192.168.1.100 445           # ① 445 端口通吗（防火墙是否放行）
testparm                           # ② smb.conf 语法
systemctl status smbd              # ③ 服务状态
smbstatus                          # ④ 有没有会话/认证失败记录
pdbedit -L | grep alice            # ⑤ 用户存在吗、口令设置了吗
grep -E 'min protocol|security' /etc/samba/smb.conf  # ⑥ 协议与安全模式
# 老 Windows/老 Samba 连不上：SMB1 被禁 → min protocol 调低（不推荐）
# 或 Windows 侧启用 SMB1（更不推荐）；正确做法是升级到 SMB2/3
```

## 常见问题

```text
Q1: NFS 和 Samba 怎么选？
A: Linux 之间共享用 NFS（内核原生、协议开销小、配置简单）；Linux 与
   Windows 跨平台共享用 Samba（SMB 是 Windows 原生协议）。Windows 客户端
   访问 NFS 要装额外组件，体验差；反过来 Linux 挂 CIFS 也要 cifs-utils。

Q2: iSCSI 和 NFS 有什么区别？
A: 粒度不同：iSCSI 是块级，客户端拿到裸盘自己分区格式化，语义接近本地
   磁盘，性能好，适合数据库/虚拟机；NFS 是文件级，共享目录，适合共享
   文件/代码。iSCSI 多端并发写同一文件系统需要上层（集群 FS/数据库）
   保证，NFS 自带文件锁语义。

Q3: NFS 服务器挂了，客户端为什么 df 都卡住？
A: 因为默认 hard 挂载：服务器不可达时客户端在内核里无限重试，阻塞所有
   访问该挂载点的进程。改用 soft 挂载会在超时后返回错误，但可能产生
   不一致的读写结果；折中方案 hard + intr（允许信号中断等待）。

Q4: 什么时候该用 Ceph/GlusterFS 而不是单机 NFS？
A: 集群规模大（几十台以上）、数据量 TB/PB 级、要求无单点故障时。单机
   NFS 是单点：服务器挂了全部客户端不可用。分布式存储多副本自动冗余、
   横向扩展，但运维复杂度也高——小规模不要为了「高级」而上分布式。

Q5: NFSv3 和 NFSv4 该用哪个？
A: 默认 NFSv4：单端口 2049（防火墙简单）、内置锁、支持 Kerberos 认证、
   性能更好。只有老客户端/老内核/特殊嵌入式环境不支持 v4 时才回退 v3。

Q6: root_squash 和 no_root_squash 有什么区别，什么时候用哪个？
A: root_squash（默认）把客户端 root 映射成 nobody，防止客户端 root 越权
   操作服务器文件，安全；no_root_squash 让客户端 root 保留 root 权限，
   方便但危险，只用于可信内网的明确场景（如发布账号需要以 root 写代码
   目录），并配合防火墙限定来源网段。
```

## 面试题

```text
1. 什么是共享存储？NFS、Samba、iSCSI、分布式文件系统各自的特点？
   答：共享存储让多机访问同一份数据。NFS 是 Linux 间文件级共享，内核
   原生、简单；Samba 是 SMB 协议实现，解决 Linux/Windows 跨平台；iSCSI
   是块级共享，客户端拿到裸盘当本地磁盘用，适合数据库/虚拟机；Ceph/
   GlusterFS 是分布式存储，多机聚合、多副本、无单点，适合大规模集群。

2. NFS 的 root_squash 是什么？为什么默认开启？
   答：把客户端的 root 用户映射成匿名用户（nobody/65534），防止客户端
   root 借 NFS 越权读写服务器任意文件。客户端 root 在客户端机器上有完全
   权限，如果不映射，就能以 root 身份操作服务器导出目录，风险极大，所以
   默认开启。需要 root 权限的场景用 no_root_squash（注意安全）。

3. 块级共享和文件级共享有什么区别？
   答：块级（iSCSI）共享裸磁盘块，客户端自己分区格式化建文件系统，协议
   开销小、性能接近本地盘，但多端共享需要上层协调；文件级（NFS/Samba）
   共享目录，客户端看到的就是文件，带文件锁与权限语义，简单但多一层
   协议封装。数据库/虚拟机用块级，共享文件用文件级。

4. NFS 的 hard 和 soft 挂载有什么区别？生产环境选哪个？
   答：hard（默认）在服务器不可达时无限重试，进程卡死但保证最终一致；
   soft 超时返回错误，进程不会卡死但可能读到半截数据。生产环境数据一致
   性要求高一般用 hard（可加 intr 允许中断），对可用性要求高、数据可重建
   的场景用 soft。

5. NFSv3 和 NFSv4 的主要区别？
   答：NFSv3 无状态、多端口（2049 + mountd 随机端口 + rpcbind）、锁依赖
   独立 lockd、认证只有 AUTH_SYS、用户映射按数字 UID；NFSv4 有状态（会话
   租约）、单端口 2049、内置锁、支持 Kerberos（krb5/krb5i/krb5p）、用户
   映射走 idmapd 名字映射。现代环境默认 NFSv4。

6. 一个 Web 集群要共享代码目录，怎么设计？
   答：NFS 是最合适方案：服务器导出 /var/www 限内网网段（rw,sync,
   no_subtree_check），客户端 fstab 持久化挂载（加 _netdev,noatime），
   防火墙只放行 2049（NFSv4）；一致性要求不高时 async 提升性能；要防
   单点可加 DRBD/keepalived 或迁移到 GlusterFS/CephFS。
```

## 最佳实践与踩坑记录

### 最佳实践

1. Linux 间共享文件用 NFS，跨平台用 Samba，数据库/虚拟机块设备用 iSCSI，大规模高可用用 Ceph/GlusterFS——别拿单机 NFS 硬撑大集群。
2. NFS 客户端挂载必须写 fstab 持久化，且**加 `_netdev`**，避免开机网络未就绪导致挂载失败卡开机。
3. `/etc/exports` 一律限定网段（`192.168.1.0/24`），禁止导出给 `*`；修改后 `exportfs -ra` 重载并 `exportfs -v` 复核。
4. 默认保持 `root_squash`；`no_root_squash` 只用于可信内网明确场景。
5. 生产优先 NFSv4（单端口 2049，防火墙好配、支持 Kerberos、内置锁）。
6. Samba 配置强制 `min protocol = SMB2`，禁用 SMB1；改配置后先 `testparm` 再重启。
7. iSCSI 存储流量走独立网络（独立网卡/VLAN），开启 CHAP 认证，ACL 按 initiator IQN 白名单放行。
8. 服务端存储目录放在独立分区/磁盘（LVM/RAID 之上），避免与系统盘争抢 IO；参考 [[06.4-RAID]] 与 [[06.3-逻辑卷管理 LVM]]。
9. 共享存储是「数据集中点」，必须纳入监控：挂载点可用性、磁盘容量、网络延迟、服务进程状态，配合 [[13.3-系统监控]] 告警。
10. 每次架构变更（升级内核、改 exports、迁移目录）先在测试环境验证，再动生产；变更前检查客户端挂载状态。

### 踩坑记录

```text
坑 1：NFS 客户端重启后挂载丢失
结论：mount 的 NFS 目录重启后没了，业务起不来。
原因：mount 是临时挂载，没写 /etc/fstab。
解法：写 /etc/fstab 持久化，且加 _netdev 选项避免开机时网络未就绪
     导致挂载失败卡住开机流程。

坑 2：NFS 挂载卡住，df 命令都卡
结论：NFS 服务器挂了，客户端 df/ls 全部卡死，kill 都杀不掉。
原因：NFS 默认 hard 挂载，服务器不可达时客户端无限重试（D 状态）。
解法：umount -f /mnt/data 或 umount -l 强制卸载；新挂载用
     soft,intr 或 hard,intr，权衡一致性与可用性。

坑 3：NFS 导出没限网段，被全网访问
结论：/etc/exports 写 *(rw)，公司任意机器都能挂载读写。
原因：偷懒用 * 通配，没限制网段。
解法：exports 里限定网段（192.168.1.0/24），exportfs -ra 重载，
     并配防火墙只放行内网来源。

坑 4：客户端 root 访问 NFS 报权限不足
结论：客户端 root 写 NFS 文件 Permission denied，以为配置错了。
原因：root_squash 生效，root 被映射成 nobody——这是默认安全策略，
     不是故障。
解法：理解并确认 root_squash 行为；确实需要 root 写再显式
     配 no_root_squash（限可信内网），否则用普通用户+正确 UID 访问。

坑 5：Samba 和 Windows 版本协议不兼容
结论：Windows 10/11 连不上老版本 Samba，提示找不到网络路径。
原因：SMB 协议版本不匹配：老 Samba 默认 SMB1，Windows 已禁用 SMB1。
解法：Samba 配置 min protocol = SMB2（启用 SMB2/3）；
     老 Windows XP 才需要 SMB1，不要为兼容老系统牺牲安全。

坑 6：NFSv4 文件属主全部变成 nobody
结论：挂载后所有文件属主显示 nobody(65534)，权限全乱。
原因：NFSv4 用户映射走 idmapd，客户端/服务端 /etc/idmapd.conf 的
     Domain 不一致，名字映射失败退化为匿名。
解法：两端 Domain 配成一致（如 lab.local）并重启 rpcidmapd/
     nfs-idmapd 服务；或改用 NFSv3 数字 UID 对齐。

坑 7：改完 /etc/exports 没重载，权限不生效
结论：改了 exports 加权限，客户端还是旧权限，怀疑配置没写对。
原因：改 exports 后忘了 exportfs -ra，导出表还是旧的。
解法：每次修改后 exportfs -ra 重载，exportfs -v 确认生效；
     涉及删除目录的操作要先在客户端 umount。

坑 8：Samba 用户建了但 Windows 登录报错
结论：useradd 建了用户，smbpasswd 也设置了，Windows 还是拒绝访问。
原因：Samba 口令与系统口令独立，可能忘了 smbpasswd -a；或共享段
     valid users 白名单没包含该用户；或共享目录本身权限不够。
解法：pdbedit -L 确认 Samba 用户存在；检查 smb.conf valid users；
     检查共享目录 chmod/chown；testparm + 重启 smbd 后重试。

坑 9：iSCSI 登录成功但看不到磁盘
结论：iscsiadm 登录成功，lsblk 却没有新磁盘。
原因：target 端 LUN 没绑定到 target（luns create 漏了）；或 ACL
     里 initiator IQN 与客户端不一致被拒；或 udev 还没刷新。
解法：targetcli 检查 luns/acls；确认 /etc/iscsi/initiatorname.iscsi
     与 ACL 一致；partprobe / udevadm settle 刷新后再 lsblk。

坑 10：RHEL 上 NFS/Samba 配好还是访问被拒
结论：exports/smb.conf 都对了，客户端还是连不上或没权限。
原因：SELinux Enforcing 拦截了导出与访问（AVC 拒绝）。
解法：setsebool -P nfs_export_all_rw 1、samba_export_all_rw 1 等；
     ausearch -m avc 查审计日志确认，再配 semanage fcontext 目录标签。
```

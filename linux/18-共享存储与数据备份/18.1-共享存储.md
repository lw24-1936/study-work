## 概述

共享存储让多台机器访问同一份数据：NFS（Linux 间共享文件，最常用）、Samba（Linux 和 Windows 共享）、iSCSI（块级共享，像本地磁盘）、分布式存储 Ceph/GlusterFS（大规模、高可用）。选型：Linux 间共享用 NFS，跨平台用 Samba，块设备用 iSCSI，大规模集群用 Ceph/GlusterFS。核心是「数据集中、多机访问」。

```text
# 实测（本机无 NFS 挂载）
$ mount | grep nfs || echo "无 nfs 挂载"
无 nfs 挂载
# 本机没配 NFS，以下为通用配置
```

```text
共享存储选型：
1. NFS —— Linux 间共享文件，最简单常用
2. Samba —— 跨平台（Linux/Windows 共享），SMB 协议
3. iSCSI —— 块级共享（像本地磁盘），数据库/虚拟机
4. Ceph/GlusterFS —— 分布式，大规模高可用
```

## 核心概念

1. **文件级共享 vs 块级共享**：NFS/Samba 是文件级（共享「目录」，客户端挂载目录访问文件）；iSCSI 是块级（共享「磁盘块」，客户端拿到裸盘自己分区格式化）。
2. **NFS（Network File System）**：Linux 间共享文件的标准协议，服务器导出目录，客户端挂载后像本地目录访问。
3. **Samba**：Linux 实现 SMB/CIFS 协议，用于 Linux 和 Windows 跨平台共享。
4. **iSCSI**：通过 IP 网络共享磁盘块，target（存储端）提供块设备，initiator（客户端）连接使用。
5. **Ceph / GlusterFS**：分布式存储，把多台机器磁盘聚合成存储池，自动冗余、横向扩展。

```text
核心概念：
文件级（NFS/Samba 共享目录） vs 块级（iSCSI 共享裸盘）
分布式（Ceph/GlusterFS 聚合多机磁盘、自动冗余）
```

## 工作原理

1. **NFS 工作原理**：服务器在 /etc/exports 声明「导出哪个目录给哪些网段」，客户端 `mount -t nfs` 挂载后，文件操作走 NFS 协议（RPC）转发到服务器执行。版本 NFSv3（老，基于 UDP/TCP，无加密）/ NFSv4（新，支持安全认证、有状态）。
2. **iSCSI 工作原理**：把 SCSI 命令封装进 TCP/IP 传输。initiator 连接 target 后，内核把它识别成一块本地磁盘（/dev/sdX），之后像本地盘一样分区、格式化、挂载。
3. **Ceph 工作原理**：数据被切成对象，按 CRUSH 算法分布到各 OSD 节点，多副本保证高可用；GlusterFS 则按目录/文件分布到各 brick（存储节点）。

```text
NFS：mount 后文件操作走 RPC 转发到服务器（NFSv3 无加密 / NFSv4 支持认证）
iSCSI：SCSI 命令封装进 TCP/IP，initiator 识别为本地磁盘
Ceph：对象 + CRUSH 分布到 OSD，多副本；GlusterFS：文件分布到 brick
```

## 常用命令与配置

```shell
# NFS 服务器端：导出目录
echo '/data 192.168.1.0/24(rw,sync,no_root_squash)' >> /etc/exports
exportfs -ra                  # 重新导出
showmount -e 192.168.1.100    # 看服务器导出了什么

# NFS 客户端：挂载
mount -t nfs 192.168.1.100:/data /mnt/data
echo '192.168.1.100:/data /mnt/data nfs defaults 0 0' >> /etc/fstab   # 持久化

# Samba 配置共享 + 用户
smbpasswd -a alice            # 创建 samba 用户
systemctl restart smbd        # 重启服务
```

```text
NFS 要点：
1. 服务器 /etc/exports 导出，客户端 mount 挂载
2. 适合 Linux 间共享文件（代码/数据）
3. NFSv4 支持安全认证，NFSv3 简单但无加密
```

## 配置文件解析

```text
# /etc/exports 格式
导出目录  允许的网段/主机(选项1,选项2)

选项含义：
rw / ro          —— 读写 / 只读
sync / async     —— 同步写（安全慢）/ 异步写（快，断电可能丢数据）
no_root_squash   —— 客户端 root 保留 root 权限（默认 root_squash 映射成 nobody）
all_squash       —— 所有用户都映射成匿名用户
```

```ini
# /etc/samba/smb.conf 关键段
[share]
   path = /data/share
   browseable = yes
   read only = no
   valid users = alice
   min protocol = SMB2        # 启用 SMB2/3（老 SMB1 被 Windows 禁用）
```

```text
iSCSI 相关：
target（存储端）—— tgtd/targetcli 提供块设备，配置 LUN
initiator（客户端）—— iscsiadm 发现 + 登录 target，识别为本地盘
```

## 应用场景实战

### 场景一：多台 Web 服务器共享一份代码（NFS）

```shell
# 存储服务器：导出代码目录
echo '/var/www 192.168.1.0/24(rw,sync,no_root_squash)' >> /etc/exports
exportfs -ra
# Web 服务器：挂载共享目录
mount -t nfs 192.168.1.100:/var/www /var/www
# 各 Web 服务器访问同一份代码，保证一致性
```

### 场景二：Linux 文件服务器给 Windows 用（Samba）

```shell
# 1. 装 samba
apt install samba
# 2. 配共享（smb.conf）
# 3. 建用户
smbpasswd -a alice
# 4. Windows 访问 \\192.168.1.100\share
```

## 性能与调优

```text
1. NFS 读写块大小 —— mount 选项 rsize/wsize（默认 1MB 左右），大文件传输调大提升吞吐
2. NFS async —— 异步写性能高但断电可能丢数据，对一致性要求低的场景可用
3. 网络 —— NFS 走网络，延迟和带宽是关键，内网千兆/万兆为宜
4. iSCSI 用独立网络 —— 块 IO 对延迟敏感，存储流量和业务流量分开（独立网卡/VLAN）
5. Ceph/GlusterFS —— 副本数（replication）影响性能和安全，性能敏感场景副本数 vs 速度权衡
```

## 安全与权限

```text
1. exports 限定网段 —— /etc/exports 里配 IP 段（192.168.1.0/24），别导出给 *
2. root_squash —— 客户端 root 被映射成 nobody（默认安全策略），防客户端 root 越权写服务器
3. Samba 用户认证 —— 用 smbpasswd 独立认证，min protocol = SMB2 防老协议漏洞
4. NFSv4 + Kerberos —— 需要加密/认证的环境用 NFSv4 + Kerberos（krb5），NFSv3 无加密
5. 防火墙 —— NFS 需要放行 2049 端口（NFSv4）及 rpcbind/挂载相关端口
```

## 故障排查

```shell
# 1. NFS 挂载失败
# 症状：mount -t nfs 报 connection refused / timeout
showmount -e <服务器>          # 服务器导出正常吗
nc -zv <服务器> 2049           # 端口通不通（NFSv4）
systemctl status nfs-server    # 服务器 NFS 服务状态

# 2. NFS 挂载卡住，df/ls 都卡
# 症状：NFS 服务器挂了，客户端 df/ls 卡住不动
mount | grep nfs               # 看挂载类型（hard/soft）
# 解决：soft 挂载超时返回错误，或用 soft,intr 选项

# 3. 客户端 root 访问 NFS 报权限不足
# 症状：客户端 root 读写 NFS 文件失败
grep nfs /etc/exports          # 是否配了 root_squash
```

## 常见问题

```text
Q1: NFS 和 Samba 怎么选？
A: Linux 之间共享用 NFS（原生、简单），Linux/Windows 跨平台用 Samba（SMB 协议）。

Q2: iSCSI 和 NFS 有什么区别？
A: iSCSI 是块级（客户端拿到裸盘自己格式化），NFS 是文件级（共享目录）。数据库/虚拟机用 iSCSI，共享文件用 NFS。

Q3: NFS 服务器挂了，客户端为什么 df 都卡住？
A: NFS 默认 hard 挂载，服务器不可达时客户端无限重试。用 soft 挂载选项超时返回错误。

Q4: 什么时候该用 Ceph/GlusterFS 而不是单机 NFS？
A: 几十台以上集群、TB/PB 级数据、高可用要求时。单机 NFS 是单点，挂了全不可用；分布式存储自动冗余、横向扩展。
```

## 面试题

```text
1. NFS 的 root_squash 是什么？为什么默认开启？
   答：把客户端的 root 映射成 nobody，防止客户端 root 越权读写服务器文件（客户端 root 拿到服务器 root 权限很危险）。需要 root 权限用 no_root_squash（注意安全）。

2. 块级共享和文件级共享有什么区别？
   答：块级（iSCSI）共享裸盘，客户端自己分区格式化，性能好、语义接近本地盘；文件级（NFS/Samba）共享目录，客户端挂载访问文件，简单但多一层协议。

3. NFS 的 hard 和 soft 挂载有什么区别？
   答：hard（默认）服务器不可达时无限重试（客户端卡住），soft 超时返回错误。数据一致性要求高用 hard，避免卡死用 soft。

4. Ceph 和 GlusterFS 怎么选？
   答：Ceph 对象/块/文件三合一、企业级、架构复杂（OSD/MON/MDS）；GlusterFS 纯分布式文件系统、简单。要块存储/对象存储用 Ceph，纯文件共享用 GlusterFS。
```

## 最佳实践与踩坑记录

### 最佳实践

1. Linux 间共享用 NFS，跨平台用 Samba，块设备用 iSCSI
2. NFS 客户端挂载用 fstab 持久化，避免重启丢失
3. NFS 导出目录限定网段（/etc/exports 里配 IP 段），别导出给所有
4. 数据库/虚拟机用 iSCSI（块级），共享文件用 NFS（文件级）
5. 大规模高可用用 Ceph/GlusterFS，别用单机 NFS 硬撑

### 踩坑记录

```text
坑 1：NFS 客户端重启后挂载丢失
结论：mount 的 NFS 重启后没了。
原因：mount 是临时的，没写 fstab。
解法：写 /etc/fstab 持久化挂载。

坑 2：NFS 挂载卡住，df 命令都卡
结论：NFS 服务器挂了，客户端 df/ls 卡住不动。
原因：NFS 默认 hard 挂载，服务器不可达时客户端无限重试。
解法：用 soft 挂载选项（超时返回错误），或 soft,intr。

坑 3：NFS 导出没限网段，被全网访问
结论：/etc/exports 导出给 *，任何机器都能挂。
原因：没限制网段，权限过宽。
解法：exports 里限定网段（192.168.1.0/24），并配防火墙。

坑 4：NFS 权限问题，客户端 root 没权限
结论：客户端 root 访问 NFS 文件报权限不足。
原因：root_squash（root 被映射成 nobody），默认安全策略。
解法：理解 root_squash，需要 root 权限用 no_root_squash（注意安全）。

坑 5：Samba 和 Windows 版本协议不兼容
结论：Windows 10 连不上老 Samba。
原因：SMB 协议版本不匹配（老 SMB1 被 Windows 禁用）。
解法：Samba 配置启用 SMB2/3（min protocol = SMB2）。
```

## 概述

存储管理三件事：性能评估（磁盘够不够快）、容量规划（磁盘够不够用）、老化与替换（磁盘寿命管理）。核心工具：iostat 测性能、df 看容量、smartctl 看健康（SMART 检测磁盘老化）。关键认知：磁盘会老化（尤其 SSD 有写入寿命），要提前规划替换，别等磁盘坏了才处理。

```text
# 实测（本机存储现状）
$ df -h / 
/dev/sda2  915G  62G  807G  8%  /
$ df -i /
/dev/sda2  60981248 inodes  1064499 已用  2%  /
# 空间用 8%、inode 用 2%，存储很充裕
```

## 存储性能评估

存储性能评估用 iostat：吞吐（rkB/s/wkB/s）、IOPS（r/s/w/s）、延迟（await）、繁忙度（%util）。评估「磁盘够不够快」：await 高（>10ms）= IO 慢，%util 接近 100% = 饱和。对比基线（记录常态）判断异常。SSD 的 await 通常 <1ms，HDD 几 ms~几十 ms。压测用 fio（模拟各种 IO 负载）。

```shell
iostat -x 1 5           # 实时看吞吐/延迟/繁忙度
iostat -d sda           # 某块盘的吞吐
fio --name=test --rw=randread --size=1G   # 压测随机读（fio 需装）
```

```text
存储性能指标：
1. 吞吐 rkB/s/wkB/s —— 每秒读写 KB
2. IOPS r/s/w/s —— 每秒读写次数
3. 延迟 await —— 单次 IO 等待（SSD <1ms，HDD 几~几十 ms）
4. 繁忙度 %util —— 接近 100% = 饱和
```

## 容量规划

容量规划：看「当前用量 + 增长率」预测「什么时候满」，提前扩容。关键看「趋势」不是「当前值」——当前 8% 但增长快（如日志每天 +1%），也要提前规划。数据源：df 历史（或用监控系统记录）、业务增长预估。阈值：80% 提醒、90% 告警，别等 100%。注意 inode 也要规划（大量小文件会耗尽 inode）。

```shell
df -h               # 空间用量
df -i               # inode 用量（小文件多时也关注）
du -sh /var/* | sort -rh | head   # 哪个目录增长快
```

```text
容量规划要点：
1. 看趋势（增长率）不是当前值
2. 阈值：80% 提醒、90% 告警
3. inode 也要规划（小文件多）
4. 监控记录历史，预测增长
```

## 磁盘老化与替换

磁盘会老化：HDD 机械部件磨损、SSD 闪存写入寿命耗尽。用 SMART（smartctl）检测磁盘健康：看「重新分配扇区数」「写入寿命」「错误率」等指标，老化前预警替换。流程：定期 smartctl 检查 → 发现老化指标 → 提前替换（迁移数据到新盘）。关键：主动检测 + 提前替换，别等磁盘彻底坏了（数据丢失）。

```shell
smartctl -a /dev/sda          # 查看磁盘健康（SMART 数据）
smartctl -H /dev/sda          # 健康状态（PASSED/FAILED）
smartctl -A /dev/sda          # SMART 属性（看老化指标）
```

```text
SMART 老化指标：
1. Reallocated_Sector_Ct 重新分配扇区（HDD 坏道）
2. Wear_Leveling_Count 写入寿命（SSD）
3. Power_On_Hours 通电时长
4. 指标异常 = 磁盘老化，提前替换
```

```text
磁盘替换流程：
检测老化（smartctl）→ 提前规划 → 备份数据 → 换新盘 → 恢复数据
```

## 应用场景实战

### 场景一：磁盘空间告警，做容量规划

```shell
# 1. 看当前用量和增长
df -h
# 2. 记录历史（每天 df 快照，或监控系统）
# 3. 算增长率，预测满的时间
# 如：当前 60%，每天 +1%，40 天后满 → 提前清理或扩容
# 4. 找增长源头
du -sh /* 2>/dev/null | sort -rh | head
```

### 场景二：定期检查磁盘健康，提前替换

```shell
# 1. 定期 SMART 检查（cron 每周）
smartctl -H /dev/sda
# 2. 看老化指标
smartctl -A /dev/sda | grep -E 'Reallocated|Wear|Power_On'
# 3. 发现老化 → 备份数据 + 换盘
```

## 最佳实践与踩坑记录

### 最佳实践

1. 存储性能看 iostat 的 await 和 %util，别只看吞吐
2. 容量规划看「增长率」，阈值 80% 提醒 90% 告警
3. 定期 smartctl 检查磁盘健康，老化提前替换
4. SSD 关注写入寿命（Wear_Leveling），HDD 关注坏道（Reallocated）
5. 磁盘替换前先备份 + 验证备份可恢复

### 踩坑记录

```text
坑 1：只看空间用量，忽略 inode
结论：df 显示空间够，但创建文件报错。
原因：inode 用满（大量小文件），df -i 能看出。
解法：df -i 也纳入监控，小文件多的场景关注 inode。

坑 2：容量规划只看当前值，忽略增长率
结论：磁盘当前够用，突然就满了。
原因：没看增长率，日志/数据增长快。
解法：记录历史趋势，按增长率预测，提前扩容。

坑 3：磁盘坏了才换，数据丢失
结论：磁盘彻底坏了才处理，数据丢了。
原因：没做 SMART 健康检测，没提前预警。
解法：定期 smartctl 检查，老化指标异常就提前替换。

坑 4：SSD 用满写入寿命还继续写
结论：SSD 写入寿命耗尽，出现坏块/数据丢失。
原因：没关注 SSD 的 Wear_Leveling（写入寿命）指标。
解法：SSD 监控写入量，寿命快尽时提前换盘。

坑 5：替换磁盘时没验证备份
结论：换盘前备份了，恢复时发现备份是坏的。
原因：备份没验证过，以为备份了就行。
解法：备份后验证可恢复（定期恢复演练），再换盘。
```

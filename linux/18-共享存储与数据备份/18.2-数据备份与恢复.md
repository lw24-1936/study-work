## 概述

数据备份是「防止数据丢失的最后防线」——误删、磁盘坏、勒索病毒、灾难，都靠备份兜底。核心：备份策略（3-2-1 原则）、备份工具（rsync 同步、restic/borg 增量备份）、快照与恢复演练（快照做一致性备份、演练验证能恢复）。关键认知：备份的价值 = 能恢复，不能恢复的备份等于没有。

```text
# 实测（本机备份工具）
$ rsync --version | head -1
rsync version 3.2.7
$ command -v restic borg || echo "restic/borg 未装"
restic/borg 未装
# rsync 已装（最常用），restic/borg 需单独装
```

```text
备份三要素：
1. 备份策略 —— 3-2-1 原则（3 份副本、2 种介质、1 份异地）
2. 备份工具 —— rsync（同步）、restic/borg（增量+加密+去重）
3. 快照与演练 —— 快照做一致性备份，演练验证能恢复
```

## 核心概念

1. **3-2-1 原则**：3 份数据副本（原始 + 2 备份）、2 种不同介质（磁盘 + 磁带/不同盘）、1 份异地（防火灾/灾难）。
2. **备份类型**：全量备份（每次全备）、增量备份（只备上次备份后的变化）、差异备份（备上次全量后的变化）。
3. **rsync**：增量同步工具，本地/远程都行，镜像目录、简单直接，无版本历史。
4. **restic / borg**：版本化备份工具，加密 + 去重 + 快照，保留历史快照。
5. **快照（snapshot）**：某一时刻的数据状态（LVM/文件系统/存储快照），备份前打快照保证一致性。

```text
3-2-1 备份原则：
3 份副本 —— 原始 + 2 份备份
2 种介质 —— 不同存储介质（防单一介质故障）
1 份异地 —— 异地备份（防本地灾难）
```

```text
备份类型：
1. 全量备份 —— 每次都备全部（简单但慢、占空间）
2. 增量备份 —— 只备上次备份后的变化（快、省空间）
3. 差异备份 —— 备上次「全量」后的变化（折中）
```

## 工作原理

1. **rsync 增量原理**：对比源和目标的文件（大小 + mtime 快速判断 + 校验和精确判断），只传变化的部分（分块校验 + 差异传输），没变的文件跳过，所以大目录同步很快。
2. **restic 去重原理**：数据切成块（chunk），按内容哈希去重——相同内容的块只存一份。备份多个版本时，没变的数据不重复占用空间。
3. **快照原理**：LVM 快照用 Copy-on-Write（COW）——打快照时只记录元数据，后续写操作把「要覆盖的旧块」先拷到快照区，快照始终指向打快照那一刻的数据状态，不冻结业务。

```text
rsync 增量：大小+mtime 快速判断 + 校验和精确判断，只传变化的块
restic 去重：数据切块 + 内容哈希去重，相同块只存一份
LVM 快照：COW（写时复制），快照保持打快照时的数据状态
```

## 常用命令与配置

```shell
# rsync 备份（增量同步）
rsync -avz /data/ backup:/backup/data/
rsync -avz --delete /data/ backup:/backup/data/   # 同步删除

# restic 备份（版本化+加密+去重）
restic init -r /backup/repo
restic backup -r /backup/repo /data
restic snapshots -r /backup/repo
restic restore -r /backup/repo latest --target /restore
```

```text
rsync vs restic/borg：
1. rsync —— 同步目录（镜像），简单直接，无版本历史
2. restic/borg —— 版本化备份（保留历史快照），加密+去重
3. 选型 —— 同步用 rsync，要版本/加密/去重用 restic/borg
```

## 配置文件解析

```shell
# 备份脚本（rsync 增量 + 删除同步）
cat > /opt/scripts/backup.sh <<'EOF'
#!/bin/bash
rsync -avz --delete /data/ backup:/backup/data/
rsync -avz /etc/ backup:/backup/etc/
EOF

# cron 定时备份
# 0 3 * * * /opt/scripts/backup.sh >> /var/log/backup.log 2>&1
```

```text
restic 仓库相关：
restic init -r /backup/repo   —— 初始化仓库（设置加密密码）
环境变量：
RESTIC_PASSWORD       —— 仓库密码（加密密钥）
RESTIC_REPOSITORY     —— 仓库位置
```

```text
LVM 快照命令：
lvcreate -L 10G -s -n snap /dev/vgdata/lv   —— 建快照（-s 快照，-L 快照区大小）
lvremove /dev/vgdata/snap                   —— 用完删快照
```

## 应用场景实战

### 场景一：用 rsync 做每日增量备份

```shell
# 1. 备份脚本（rsync 增量 + 删除同步）
cat > /opt/scripts/backup.sh <<'EOF'
#!/bin/bash
rsync -avz --delete /data/ backup:/backup/data/
rsync -avz /etc/ backup:/backup/etc/
EOF
# 2. cron 每天凌晨备份
# 0 3 * * * /opt/scripts/backup.sh >> /var/log/backup.log 2>&1
```

### 场景二：数据库备份（快照保证一致性）

```shell
# 1. 打 LVM 快照（冻结数据状态）
lvcreate -L 20G -s -n mysql_snap /dev/vgdata/lv_mysql
# 2. 从快照备份
mount /dev/vgdata/mysql_snap /mnt/snap
mysqldump --databases mydb > /backup/mydb.sql
# 3. 清理快照
umount /mnt/snap && lvremove /dev/vgdata/mysql_snap
```

## 性能与调优

```text
1. 增量优先 —— 优先用增量备份（rsync/restic），全量备份慢且占空间
2. 压缩 vs 速度 —— rsync -z 压缩传输省带宽，但 CPU 开销增加，网络是瓶颈时才用
3. 去重省空间 —— restic/borg 的内容去重，多版本备份省大量空间
4. 备份窗口 —— 大备份安排在业务低峰（凌晨），别和业务抢 IO
5. 带宽限制 —— rsync --bwlimit=1000 限制传输带宽，别打满生产网络
```

## 安全与权限

```text
1. 备份数据加密 —— restic/borg 加密备份，异地/云端备份必须加密
2. 备份仓库密码保管 —— restic 密码丢失 = 备份无法恢复，密码要安全备份
3. 备份权限 —— 备份文件含敏感数据，限制访问权限（chmod 600）
4. 传输加密 —— rsync 远程走 SSH（默认加密），别用明文 rsync 协议
5. 防勒索 —— 备份不能被业务主机「就地删除」，异地 + 离线备份（air-gap）
```

## 故障排查

```shell
# 1. 备份失败（磁盘满/网络断）
tail -f /var/log/backup.log          # 看备份日志
df -h                                # 备份目标磁盘满了吗
ping backup                           # 备份机网络通不通

# 2. 恢复失败（备份损坏/不完整）
restic check -r /backup/repo         # restic 校验仓库完整性
tar tzf /backup/mysql.tar.gz >/dev/null  # 校验 tar 包完整性

# 3. 备份很久没更新（脚本没跑）
grep backup /var/log/cron.log        # cron 执行记录
systemctl list-timers | grep backup  # 检查定时任务状态
```

## 常见问题

```text
Q1: 全量、增量、差异备份怎么选？
A: 数据量小用全量（简单）；数据量大用「定期全量 + 频繁增量」，恢复时全量 + 增量串起来。

Q2: 为什么说「不演练的备份 = 没有备份」？
A: 备份可能损坏/不完整，不演练就不会发现，真出事时发现恢复不了。定期做恢复演练验证。

Q3: 数据库能直接 rsync 备份吗？
A: 不能。运行中的数据库直接备份会拿到不一致的数据（备份时还在写）。先打快照或锁表/停库，再备份。

Q4: rsync 和 restic 怎么选？
A: 只要「镜像同步」用 rsync（简单）；要「历史版本 + 加密 + 去重」用 restic/borg。
```

## 面试题

```text
1. 3-2-1 备份原则是什么？
   答：3 份数据副本、2 种不同介质、1 份异地。核心是冗余 + 多介质 + 异地，防单一故障和本地灾难。

2. 为什么数据库备份前要打快照？
   答：运行中的数据库持续写数据，直接备份会拿到「不一致」的中间状态，恢复时数据损坏。快照冻结某一时刻的数据状态。

3. 增量备份和差异备份有什么区别？
   答：增量备份基于「上次任何备份」（上次增量也算）的变化；差异备份基于「上次全量」的变化。增量更省空间，差异恢复更快。

4. 备份数据被勒索软件加密了怎么办？
   答：靠「异地 + 离线（air-gap）」备份——勒索软件只能加密本机/在线数据，离线异地备份不受影响，用它们恢复。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 备份遵循 3-2-1 原则（3 副本、2 介质、1 异地）
2. 数据库备份前打快照，保证一致性（否则恢复不了）
3. 定期做恢复演练，验证备份真的能恢复
4. 备份自动化（cron）+ 监控（备份失败要告警）
5. 备份数据加密（尤其异地/云端备份）

### 踩坑记录

```text
坑 1：备份了但从来没演练过，真出事恢复不了
结论：备份做了几年，真删库了发现备份是坏的/恢复不了。
原因：没做恢复演练，备份损坏/不完整没被发现。
解法：定期做恢复演练（删库→恢复→验证），验证备份有效。

坑 2：数据库直接备份，数据不一致
结论：数据库运行中直接 tar 备份，恢复后发现数据损坏。
原因：备份时数据库在写，备份的数据不一致。
解法：备份前打快照（LVM 快照）或停库/锁表，保证一致性。

坑 3：rsync 没加 --delete，删除的文件还留在备份
结论：源删了文件，备份里还有（备份越积越大）。
原因：rsync 默认不删目标端多余文件。
解法：加 --delete 同步删除，或接受备份保留历史。

坑 4：备份都在同一块盘/同一机房，一起毁
结论：备份和原始数据在同一块盘，盘坏了全没。
原因：没遵循 3-2-1（异地/多介质）。
解法：备份异地 + 多介质（至少另一块盘/另一台机器）。

坑 5：备份失败没告警，出事才发现备份是空的
结论：备份脚本失败（磁盘满/网络断），一直没人知道。
原因：备份没监控，失败静默。
解法：备份脚本失败要告警（邮件/webhook），定期检查备份日志。
```

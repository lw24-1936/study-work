## 概述

交换空间（swap）是「内存不够时把不常用的内存页临时写到磁盘」的兜底空间。物理内存用满时，内核把冷数据换出到 swap，腾出内存给活跃进程。swap 分两种：swap 分区（独立分区）和 swap 文件（普通文件当 swap，更灵活）。swappiness 参数控制「内核多积极地用 swap」。swap 是「兜底」不是「替代内存」——swap 太多会拖慢系统。

```text
swap 核心概念：
1. 作用 —— 内存不足时把冷内存页换出到磁盘，腾出物理内存
2. 形式 —— swap 分区（独立分区）或 swap 文件（普通文件，灵活）
3. swappiness —— 0-100，控制换出积极度（默认 60，越高越爱用 swap）
4. 定位 —— 兜底，不是内存替代品，大量用 swap 说明内存不足
```

## 核心概念

swap 分区是专门类型（分区类型 82）的分区，swap 文件是普通文件（`dd` 创建 + `mkswap` 格式化 + `swapon` 启用）。现代发行版（Ubuntu）默认用 swap 文件（如 /swap.img），因为文件大小可随时调整、不用重新分区。查看 swap 用 `swapon --show` 或 `cat /proc/swaps`，启用/停用用 swapon/swapoff。

```text
# 实测（本机 swap 是文件不是分区）
$ swapon --show
NAME      TYPE SIZE  USED PRIO
/swap.img file   8G 76.7M   -1
# swap 是 /swap.img 文件，8G，当前用了 76.7M（内存够时基本不用）
```

```shell
# 创建并启用一个 swap 文件
dd if=/dev/zero of=/swapfile bs=1M count=2048   # 建 2G 文件
chmod 600 /swapfile
mkswap /swapfile                                # 格式化为 swap
swapon /swapfile                                # 启用
swapon --show                                   # 确认
# 持久化：写进 fstab，/swapfile none swap sw 0 0
```

### swap 分区 —— 传统方式

是什么：磁盘上一个专门的分区（MBR 分区类型 82，GPT 用 8200），格式化为 swap，独立于文件系统。

为什么：老系统/传统部署用分区，性能略好（少了文件系统层）、不受文件系统碎片影响，但大小固定，扩容要重分区。

怎么用：装机时规划好一块 swap 分区；或用 fdisk 新建一块类型 82 的分区再 mkswap。

边界/易错点：改大小要动分区表，风险高、不灵活；现代部署基本都被 swap 文件取代。分错类型会导致 swapon 报错。

```shell
# 用 fdisk 新建 swap 分区（交互：n 新建 → t 改类型为 82 → w 写入）
fdisk /dev/sdb
mkswap /dev/sdb1
swapon /dev/sdb1
```

### swap 文件 —— 现代方式

是什么：普通文件系统上的一个文件，用 `dd`/`fallocate` 创建固定大小，mkswap 格式化后 swapon。

为什么：大小随时可调（swapoff → 重建 → swapon 就行），不用动分区表；云主机、容器、发行版默认都用它。

怎么用：`dd if=/dev/zero of=/swapfile bs=1M count=N`（或 fallocate）+ chmod 600 + mkswap + swapon。

边界/易错点：`fallocate` 创建的文件在部分文件系统（ext4 支持、但 btrfs 早期版本）上 mkswap 会报「holes」，稳妥用 `dd` 填零；文件必须 chmod 600 否则 swapon 报 insecure permissions；放本地盘别放网络盘。

```shell
# fallocate 快速建 swap 文件（比 dd 快；btrfs 上若不支持就退回 dd）
fallocate -l 4G /swapfile
chmod 600 /swapfile
mkswap /swapfile
swapon /swapfile
```

### swap 的两种「压缩」变体：zram 与 zswap

- zram：内存里开辟的压缩块设备，直接作为 swap 设备（swapon /dev/zram0）。换出的页被压缩存回内存，几乎无磁盘 IO，适合内存小、又要「多出点可用内存」的设备（嵌入式/树莓派/小内存容器）。
- zswap：内核的「压缩 swap 缓存层」。换出时先把页压缩存内存，内存里的压缩缓存满了才写真实 swap；换入时优先从压缩缓存读，减少磁盘 IO。仍需要真实 swap 做后备。

```text
zram vs zswap 一句话区分：
zram  —— 纯内存压缩 swap 设备，不需要真实磁盘 swap
zswap —— 真实 swap 前面的压缩缓存层，需要真实 swap 做后备
```

## 工作原理

swap 的工作机制是「换页（paging）」。物理内存紧张时，内核的页回收机制（kswapd/直接回收）挑选「不常用的匿名页」（进程堆/栈等，不是文件页——文件页可直接丢弃，脏了就回写文件）换出到 swap 分区，腾出物理页给活跃进程。被换出的页再次被访问时触发缺页异常，内核从 swap 读回来（换入）。所以「swap 用得多」说明内存紧张，进程在频繁换入换出，性能下降。

```text
swap 工作原理：
1. 页回收 —— 内存紧张时内核选冷匿名页换出到 swap（文件页可直接丢弃/回写）
2. 换出 swap out —— 冷页写 swap，腾出物理页
3. 换入 swap in —— 访问被换出的页时缺页异常，从 swap 读回
4. 频繁换入换出 = 抖动 thrashing —— 内存严重不足，性能骤降
```

### 匿名页 vs 文件页：为什么只有匿名页进 swap

内存里的页分两类。文件页（mmap 的文件、程序代码）在后备文件里本来就有一份，内存紧张时直接丢弃——干净的丢弃、脏的写回文件即可，不需要 swap。匿名页（进程的堆、栈、malloc 出来的内存）没有后备文件，唯一能「落盘」的地方就是 swap，所以内存紧张时匿名页被换出到 swap。这就是「文件页走回写、匿名页走 swap」的分工。

```text
内存页的两条回收路径：
文件页（mmap 文件/代码）→ 干净页直接丢弃，脏页回写文件，不需要 swap
匿名页（堆/栈/malloc）  → 没有后备文件，换出到 swap 兜底
```

### swap cache 与抖动（thrashing）

swap cache：换出的页被访问、换入内存后，swap 上的副本会暂时保留，形成「内存 + swap 各一份」的状态；如果这页很快又被换出，就不用重新写 swap（省一次 IO）。抖动（thrashing）：内存严重不足时，进程的工作集反复被换出又换入，系统把大量时间花在磁盘 IO 上、真正干活的时间很少，表现为 swap 持续高位、磁盘 IO 打满、系统卡死。这是「内存不够了」的强烈信号。

```shell
# 用 vmstat 观察换入换出（si/so 两列，单位 KB/s）
vmstat 1
# si（swap in）/ so（swap out）持续非零且很大 → 正在抖动
```

## 常用命令与配置

swap 的日常命令：swapon（启用）、swapoff（停用）、mkswap（格式化）、swapon --show（查看）。多个 swap 可以配优先级（priority，swapon -p），优先级高的先用。要调整 swap 大小就是「swapoff 旧的 → 建新的 → swapon」。

```shell
swapon --show              # 查看已启用的 swap
swapon /swapfile           # 启用
swapoff /swapfile          # 停用（内存够时才能停，否则报错）
mkswap /swapfile           # 格式化为 swap
swapon -p 10 /swapfile2    # 启用并设优先级（数字大优先）
cat /proc/swaps            # 内核视角的 swap
```

```shell
# 内存与 swap 的日常观测
free -h                    # 一行看清内存 + swap 用量
vmstat 1                   # si/so 观察换入换出，判断是否抖动
swapon -s                  # 等价 swapon --show
swapoff -a                 # 停用所有 swap
mkswap -f /dev/sdb1        # -f 强制（分区可能带旧签名，强制重建）
```

```text
swap 优先级 priority：
1. 多个 swap 设备/文件可同时启用，priority 数字大的先用
2. 默认 priority = -1，可用 swapon -p N 或 fstab 的 pri=N 指定
3. 场景：SSD 上的 swap 设高优先级、机械盘上的设低优先级，让系统优先用快的
```

## 配置文件解析

swap 的持久化配置在 /etc/fstab：一行 `设备/文件 none swap sw 0 0`。系统开机时按 fstab 启用 swap。另外 /proc/sys/vm/swappiness 控制换出积极度（也是配置项，见性能调优）。

```text
# 实测（本机 /etc/fstab 里的 swap 行）
$ grep swap /etc/fstab
/swap.img none swap sw 0 0
# swap 文件 /swap.img，类型 swap，选项 sw，开机自动启用
```

```shell
# fstab 里加 swap 后验证
swapon -a            # 启用 fstab 里所有 swap
swapon --show        # 确认
```

```text
# /etc/fstab 里 swap 行的完整字段说明
/swapfile none swap sw 0 0
└─设备/文件  └─挂载点(swap 固定用 none)  └─类型 swap  └─选项 sw  └─dump  └─fsck 顺序(0 不检查)

# 带优先级的写法（SSD 上的 swap 设高优先级）
/dev/nvme0n1p2 none swap sw,pri=10 0 0
/dev/sdb2      none swap sw,pri=1  0 0
```

swappiness 的持久化写在 /etc/sysctl.conf（或 /etc/sysctl.d/ 下的文件），也可以用 systemd 的 swap 单元管理 swap 文件（比 fstab 更现代、支持依赖关系）。

```shell
# swappiness 持久化
echo 'vm.swappiness=10' >> /etc/sysctl.conf
sysctl -p               # 立即生效
```

## 应用场景实战

### 场景一：内存不够了，快速加一个 swap 文件应急

```shell
# 1. 建 4G swap 文件并启用
dd if=/dev/zero of=/swapfile2 bs=1M count=4096
chmod 600 /swapfile2
mkswap /swapfile2
swapon /swapfile2
# 2. 确认生效
swapon --show
free -h
# 3. 持久化（避免重启丢失）
echo '/swapfile2 none swap sw 0 0' >> /etc/fstab
```

### 场景二：给数据库服务器调低 swappiness

```shell
# 1. 查看当前值
cat /proc/sys/vm/swappiness
# 2. 调低到 10（优先用物理内存，避免数据库缓存被换出拖慢查询）
sysctl vm.swappiness=10
# 3. 持久化
echo 'vm.swappiness=10' >> /etc/sysctl.conf
sysctl -p
```

### 场景三：定位并处理 swap 抖动（thrashing）

```shell
# 1. 先看整体：内存和 swap 用量
free -h
# 2. 看换入换出是否持续（si/so 两列一直很大就是抖动）
vmstat 1 5
# 3. 看哪个进程占内存最多、swap 最多
top -o %MEM            # 按内存排序
# 4. 处理：杀掉/优化占内存的进程，或加内存，或临时扩大 swap 兜底
```

```text
判断结论：
swap 使用率高 + vmstat 的 si/so 持续非零 → 内存真实不足，正在抖动；
swap 用了一点但 si/so 基本为 0 → 只是冷数据被换出，系统健康，不用管。
前者要加内存/优化程序，后者是 swap 正常兜底的表现。
```

## 性能与调优

swappiness（0-100）控制内核「多积极地换出内存页到 swap」。值越高，内核越早、越积极地把内存换出；值越低，越倾向用满物理内存再说。默认 60（适中）。数据库服务器常调低到 10-20（尽量用物理内存，避免数据库缓存被换出），桌面/内存紧张时保持默认或调高。

```text
# 实测（本机默认 swappiness）
$ cat /proc/sys/vm/swappiness
60
# 默认 60：均衡策略，内存用到一定程度就开始换出
```

```shell
sysctl vm.swappiness=10              # 临时调低（数据库服务器常用）
sysctl -w vm.swappiness=10           # 等价写法
# 持久化：/etc/sysctl.conf 加 vm.swappiness=10
```

```text
swappiness 调优要点：
1. 默认 60 —— 均衡策略
2. 数据库/缓存服务 10-20 —— 优先物理内存，别换出热缓存
3. 内存紧张/桌面 —— 保持默认或调高，让系统尽早换出
4. 0 ≠ 禁用 —— 只是「尽量避免」，内存极度紧张仍会换出
```

### swappiness 取值分段解读

```text
swappiness 取值含义：
0   —— 尽量不换出匿名页（不是禁用 swap），内存极度紧张仍会换出
1   —— 最小换出（老内核里 0/1 接近；较新内核把 0 重定义为「仅避免 OOM 才换出」）
10  —— 数据库服务器常用，优先用物理内存
60  —— 默认，均衡
100 —— 激进换出，尽早把匿名页赶去 swap
```

### zswap / zram 压缩 swap 的启用

```shell
# 启用 zswap（需要内核支持，一般内置）—— 真实 swap 前加压缩缓存
echo 1 > /sys/module/zswap/parameters/enabled

# 启用 zram 作为 swap 设备（内存小机器常用）
modprobe zram
echo lz4 > /sys/block/zram0/comp_algorithm   # 选压缩算法
echo 2G > /sys/block/zram0/disksize          # 设 zram 大小
mkswap /dev/zram0
swapon -p 100 /dev/zram0                     # 高优先级，优先用压缩 swap
```

### 内存回收相关参数（配合 swappiness）

`vm.vfs_cache_pressure` 控制内核「回收目录项/inode 缓存 vs 换出匿名页」的倾向，值越高越积极回收文件系统缓存（间接减少换出匿名页的压力）。

```shell
# 默认 100；调高让内核更积极回收文件缓存（间接影响换页行为）
sysctl -w vm.vfs_cache_pressure=150
```

## 安全与权限

swap 的安全关键是「文件权限」：swap 里存的是换出的内存页（可能含密码、密钥等敏感数据），swap 文件必须 chmod 600（只 root 可读写），否则普通用户能读到换出的内存数据。更严格的做法是对 swap 加密（LUKS 加密 swap，防磁盘被物理盗取后读 swap 数据）。

```text
swap 安全要点：
1. 文件权限 600 —— swap 里可能有敏感内存数据，只 root 可读写
2. 加密 swap —— 敏感环境用 LUKS 加密 swap，防物理盗盘
3. 别放共享目录 —— swap 文件放本地盘，别放网络/共享存储
```

### 加密 swap（LUKS）与休眠

需要「休眠到磁盘」（hibernate）时，休眠镜像通常写到 swap，且应该加密（休眠镜像里是完整内存，含所有进程数据）。加密 swap 用 LUKS：把 swap 做成 LUKS 卷，或（较新内核）直接用 dm-crypt 的随机密钥 swap。休眠还要求 swap 大小 ≥ 内存大小。

```text
加密 swap 两种做法：
1. LUKS 加密 swap 分区 —— 开机用密钥解密后 swapon（要输密码，或密钥存 initramfs）
2. 随机密钥 swap（/dev/mapper 一次性密钥）—— 每次开机随机生成，无法休眠恢复但免交互
休眠 hibernate 要求：swap 大小 ≥ 内存大小，否则休眠镜像写不下
```

## 故障排查

### swapon 报 insecure permissions

```shell
# 1. 看报错
swapon /swapfile   # insecure permissions 0644
# 2. 改权限
chmod 600 /swapfile
# 3. 重试
swapon /swapfile
```

### swapoff 报 memory exhausted

```shell
# 1. swap 用得多时 swapoff 会失败（换回物理内存不够）
# 2. 先看内存和 swap 使用
free -h
# 3. 释放内存后再停（或加内存/临时加大物理可用）
```

### swapon 报 swapfile has holes（fallocate 建的 swap 文件）

```shell
# 1. fallocate 建的 swap 文件在部分文件系统上 mkswap 报 has holes
mkswap /swapfile   # mkswap: /swapfile: warning: don't erase bootbits sectors ... swapfile has holes
# 2. 用 dd 填零重建，消掉空洞
swapoff /swapfile
dd if=/dev/zero of=/swapfile bs=1M count=4096
chmod 600 /swapfile
mkswap /swapfile
swapon /swapfile
```

### 系统卡顿，怀疑是 swap 抖动

```shell
# 1. 看 swap 使用和换入换出
free -h
vmstat 1 5
# 2. 看哪个进程在疯狂换页
top -o %MEM
# 3. 结合 /proc/meminfo 看内存水位
cat /proc/meminfo | grep -E 'MemAvailable|SwapTotal|SwapFree'
```

## 常见问题

```text
Q1: swap 分区和 swap 文件怎么选？
A: 现代发行版默认 swap 文件（大小灵活、不用重分区），传统/老系统用 swap 分区。功能等价。

Q2: swap 要设多大？
A: 内存 ≤2G 用 2 倍，2-8G 用 1 倍，>8G 用 4-8G 兜底即可；要休眠（hibernate）需 ≥ 内存大小。

Q3: swappiness=0 能禁用 swap 吗？
A: 不能，0 只是「尽量避免」，内存极度紧张时仍会换出。真禁用要 swapoff -a 且不写 fstab。

Q4: swap 用得多是不是就要加内存？
A: 是。swap 持续高使用说明内存不足、在频繁换页，应加内存或优化程序内存占用。

Q5: 什么是抖动（thrashing）？
A: 内存严重不足时进程工作集被反复换出换入，系统大量时间耗在磁盘 IO 上，表现为 vmstat 的 si/so 持续高位、系统卡死。

Q6: zram 和 zswap 有什么区别？
A: zram 是纯内存压缩块设备、直接当 swap 用（不需真实 swap）；zswap 是真实 swap 前的压缩缓存层（需真实 swap 后备）。都为了减少磁盘 IO。

Q7: 为什么 swap 文件必须 chmod 600？
A: swap 里是换出的内存页，可能含密码/密钥等敏感数据，权限太宽会让普通用户读到这些内容，系统也会拒绝启用权限不对的 swap。
```

## 面试题

```text
1. swap 的作用是什么？
   答：内存不足时把冷内存页换出到磁盘腾出物理内存，是内存的兜底，不是替代品。

2. swappiness 参数的作用？
   答：0-100 控制内核换页积极度，越高越早换出，越低越倾向用满物理内存；默认 60。

3. swap 分区和 swap 文件的区别？
   答：分区是独立类型 82 的分区，文件是普通文件（dd+mkswap+swapon），功能等价，文件更灵活。

4. 为什么 swap 用多了系统变慢？
   答：磁盘远慢于内存，频繁换入换出（抖动）导致大量磁盘 IO，性能骤降。

5. 匿名页和文件页在内存回收时有什么不同？
   答：文件页有后备文件，干净页直接丢弃、脏页回写文件；匿名页没有后备文件，只能换出到 swap 兜底。

6. swap cache 是什么？
   答：换出的页被换入内存后 swap 上的副本暂时保留，若这页很快又被换出就不用重新写 swap，省一次 IO。

7. 怎么判断系统是否在抖动？
   答：vmstat 1 看 si/so（swap in/out）持续非零且数值大，同时 free -h 显示 swap 高使用、内存吃紧，就是抖动，需加内存或优化程序。
```

## 最佳实践与踩坑记录

### 最佳实践

1. swap 大小：内存 ≤2G 用 2 倍，2-8G 用 1 倍，>8G 用 4-8G 兜底即可
2. 数据库服务器调低 swappiness（10-20），优先用物理内存
3. swap 文件权限设 600，防止被普通用户读取
4. 观察 swap 使用：free -h 或 vmstat，swap 持续高说明内存不足该加内存
5. 需要临时加 swap 用 swap 文件，比重启加分区快得多
6. 多个 swap 设备用 priority 分级：SSD 上的设高优先级优先用，机械盘上的兜底
7. 小内存设备（树莓派/容器）优先考虑 zram 压缩 swap，避免磁盘 IO

### 踩坑记录

```text
坑 1：swap 文件权限太宽
结论：chmod 644 swap 文件，普通用户能读到换出的内存数据。
原因：swap 里可能有敏感数据（密码等内存页），权限 644 会泄露。
解法：swap 文件必须 chmod 600，只 root 可读写。

坑 2：swap 文件 swapon 报 insecure permissions
结论：swapon 提示 insecure permissions 0644，拒绝启用。
原因：swap 文件权限不是 600，系统认为不安全。
解法：chmod 600 /swapfile 后再 swapon。

坑 3：swap 分区没写进 fstab，重启后失效
结论：swapon 启用的 swap 重启后没了。
原因：swapon 是临时的，不写 fstab 不持久化。
解法：写 /etc/fstab（/swapfile none swap sw 0 0），或 systemd swap 单元。

坑 4：swappiness 调成 0 以为禁用 swap
结论：swappiness=0 后系统还是用了 swap。
原因：swappiness=0 只是「尽量避免」，内存极度紧张时仍会换出。
解法：要真正禁用就 swapoff -a，或接受「0 = 尽量不用」。

坑 5：swap 空间过大导致磁盘被占满
结论：配了 64G swap，磁盘被 swap 文件占满。
原因：swap 文件按预设大小直接占磁盘空间。
解法：按内存比例合理设 swap 大小，别盲目设超大值。

坑 6：fallocate 建的 swap 文件 mkswap 报 has holes
结论：fallocate -l 建的 swap 文件 swapon 时报 swapfile has holes。
原因：fallocate 产生稀疏文件，部分文件系统（早期 btrfs）不支持它做 swap。
解法：改用 dd if=/dev/zero 填零重建 swap 文件，消除空洞。

坑 7：swapoff 停不掉，报 memory exhausted
结论：swap 用得多时 swapoff 报 memory exhausted，停不下来。
原因：停用 swap 要把换出的页全部读回物理内存，内存不够就失败。
解法：先释放内存（杀进程/清理缓存）或加内存，再 swapoff。
```

## 概述

文件系统是「分区上怎么组织文件和目录」的规则。Linux 通过 VFS（虚拟文件系统）抽象统一了各种文件系统的操作接口——上层程序不用关心底层是 ext4 还是 XFS。常见文件系统：ext4（默认、稳定）、XFS（大文件高性能）、Btrfs（快照/COW）、ZFS（高级特性）。格式化用 mkfs、挂载用 mount、开机自动挂载配 fstab、用 UUID 标识分区。

```text
文件系统全流程：
1. VFS —— 内核抽象层，统一 ext4/XFS/Btrfs 等不同文件系统的接口
2. 格式化 —— mkfs.ext4 / mkfs.xfs 在分区上建文件系统
3. 挂载 —— mount 把分区挂到目录树上，umount 卸载
4. 自动挂载 —— /etc/fstab 配置开机挂载，用 UUID 标识分区（稳定）
5. 检查 —— fsck 检查修复文件系统错误
```

## 核心概念

### VFS：虚拟文件系统抽象层

VFS（Virtual File System）是内核里的抽象层，为上层提供统一的文件操作接口（open/read/write），底层对接各种具体文件系统（ext4、XFS、Btrfs、NTFS、甚至伪文件系统 /proc /sys）。好处是：程序写文件不用关心磁盘上是哪种文件系统，新加一种文件系统只要实现 VFS 的接口就能被系统识别。这就是「一切皆文件」能成立的基础。

```text
VFS 的作用：
应用程序 → VFS 统一接口 → ext4 / XFS / Btrfs / proc / tmpfs ...
1. 统一接口 —— open/read/write 对所有文件系统一致
2. 可扩展 —— 新文件系统实现 VFS 接口即可接入
3. 伪文件系统也走 VFS —— /proc /sys /tmpfs 都是 VFS 之上的实现
```

VFS 层维护四类核心对象：superblock（超级块，文件系统整体元信息）、inode（索引节点，单个文件的元数据）、dentry（目录项，路径名到 inode 的映射，含目录缓存 dcache）、file（打开的文件，含读写位置）。open 一个文件时，内核沿路径逐个解析 dentry 找到 inode，再建立 file 对象返回 fd，后续 read/write 都通过 file → inode 定位到磁盘块。

```text
VFS 四大对象：
1. superblock —— 挂载的每个文件系统一个，存块大小/总块数/挂载状态
2. inode —— 每个文件一个，存权限/大小/时间戳/数据块指针
3. dentry —— 路径名 → inode 的映射，配合 dcache 加速路径查找
4. file —— 打开的文件实例，存读写偏移/访问模式，对应进程 fd
```

### 四种主流文件系统：ext4 / XFS / Btrfs / ZFS

四种主流文件系统各有定位。ext4 是 Linux 默认，稳定成熟、通用性好；XFS 擅长大文件和高并发写（Red Hat 系默认，适合数据库/大文件）；Btrfs 支持快照、COW、子卷（Ubuntu 可选的下一代）；ZFS 功能最全（快照/校验/压缩/RAID-Z）但许可和内核集成复杂。选型：通用/小文件用 ext4，大文件/高吞吐用 XFS，要快照用 Btrfs/ZFS。

```text
四种文件系统对比：
1. ext4 —— 默认、稳定、通用，日志型，日常首选
2. XFS —— 大文件/高并发写强，Red Hat 系默认，数据库场景
3. Btrfs —— 快照/COW/子卷，Ubuntu 新一代可选
4. ZFS —— 快照/校验/压缩/RAID-Z 全有，但许可复杂
```

- ext4：ext3 的继任者，日志文件系统 + extent（连续块映射，减少大文件元数据）+ 延迟分配（delayed allocation）。单文件最大 16TB、卷最大 1EB，支持在线扩容、向后兼容 ext2/ext3。是绝大多数 Linux 发行版默认的通用文件系统。
- XFS：SGI 出品，64 位日志文件系统，用「分配组（allocation group）」并行化 IO，大文件、高并发写性能强，Red Hat/CentOS 默认。支持在线扩容（xfs_growfs），但**不支持缩容**。
- Btrfs：Oracle 发起，写时复制（COW）+ 快照 + 子卷（subvolume）+ 数据校验和 + 内置压缩 + 内置 RAID。是「下一代」文件系统，Ubuntu 可作为安装选项。
- ZFS：Sun 出品，把「卷管理 + 文件系统」合二为一（pool + dataset 概念），快照/校验/压缩/RAID-Z/自愈全都有，但 CDDL 许可与 GPL 冲突，不能进主线内核，靠 OpenZFS 内核模块（DKMS）运行。

```text
# 实测（本机文件系统类型）
$ df -hT
/dev/sda2  ext4   915G  62G  808G   8%  /
/dev/sda1  vfat   1.1G 6.2M  1.1G   1%  /boot/efi
# 根分区是 ext4，EFI 分区是 vfat（FAT32，UEFI 引导要求）
```

```shell
# 各种文件系统的格式化命令（格式化会清空数据，先确认目标）
mkfs.ext4  /dev/sdb1      # ext4
mkfs.xfs   /dev/sdb1      # XFS（加 -f 可覆盖已有签名）
mkfs.btrfs /dev/sdb1      # Btrfs
mkfs.vfat  /dev/sdb1      # FAT32（UEFI ESP / U 盘兼容场景）
```

```text
选型速查：
1. 通用/系统盘/小文件 —— ext4（稳定成熟）
2. 数据库/大文件/高并发写 —— XFS（分配组并行，吞吐强）
3. 要快照/子卷/内建压缩 —— Btrfs 或 ZFS
4. 跨盘池化/RAID-Z/自愈 —— ZFS（许可复杂，需额外装内核模块）
```

## 工作原理

文件系统的工作分「读写路径」和「一致性保障」两部分。读写路径：进程 write → VFS 统一接口 → 具体文件系统的写方法 → 页缓存（page cache，先写内存，稍后刷盘）→ 磁盘。ext4/XFS 都是「日志文件系统」（journaling）——写数据前先把操作记录到日志（journal），再写数据，这样断电/崩溃时能通过重放日志恢复一致性（避免文件系统损坏）。

```text
文件系统工作原理：
1. 读写路径 —— 进程 → VFS → 具体文件系统 → 页缓存 → 磁盘
2. 页缓存 —— 写先落内存（快），内核后台刷盘（脏页回写）
3. 日志 journaling —— 先写日志再写数据，崩溃后重放日志恢复一致性
4. inode —— 每个文件一个 inode，存元数据（权限/大小/块指针），文件名只是目录里的条目
```

页缓存（page cache）是性能的关键：write 只是把数据拷进内存页并标记为「脏页」，立刻返回；内核后台线程（pdflush/flush）按 dirty_ratio 等阈值把脏页批量刷到磁盘。好处是写快、能合并连续写，坏处是断电时「已返回成功但没落盘」的数据会丢——所以数据库等对持久性敏感的应用要 fsync 强制刷盘。

```text
页缓存与刷盘：
1. write 落内存脏页即返回，内核后台异步刷盘
2. fsync/fdatasync —— 强制刷盘，数据库事务提交前必须调用
3. dirty_ratio / dirty_background_ratio —— 控制刷盘触发阈值（/proc/sys/vm/）
4. 断电丢数据 —— 未刷盘的脏页会丢，所以「写成功 ≠ 已落盘」
```

ext4 的日志有三种模式，由 data= 挂载选项控制：

- data=ordered（默认）：元数据记日志，数据先落盘再提交元数据，兼顾安全与性能。
- data=writeback：只记元数据日志，数据落盘顺序不保证，最快但崩溃可能丢数据。
- data=journal：数据和元数据都记日志，最安全但写放大严重、最慢。

```text
ext4 日志三模式：
1. data=ordered（默认）—— 数据先写、元数据后提交，安全与性能平衡
2. data=writeback —— 只记元数据，最快，崩溃可能丢数据或文件损坏
3. data=journal —— 数据+元数据全记日志，最安全，写放大、最慢
```

## 常用命令与配置

格式化（mkfs）在分区上建文件系统，挂载（mount）把分区接到目录树某个挂载点。`mkfs.ext4 /dev/sdb1` 格式化，`mount /dev/sdb1 /mnt/data` 挂载，`umount /mnt/data` 卸载。格式化会清空分区数据，操作前确认。挂载是临时的，重启失效，要持久化就得写 fstab。

```shell
mkfs.ext4 /dev/sdb1              # 格式化成 ext4
mkfs.xfs  /dev/sdb1              # 格式化成 XFS
mount /dev/sdb1 /mnt/data        # 挂载
df -h /mnt/data                  # 确认挂载
umount /mnt/data                 # 卸载
```

```shell
# 挂载选项（mount -o）
mount -o noatime /dev/sdb1 /mnt/data   # 不更新访问时间（省 IO）
mount -o remount,rw /                   # 重新挂载为读写
findmnt /                               # 查看挂载详情（比 df 详细）
```

```shell
# 挂载选项组合（多个选项逗号分隔）
mount -o noatime,nodiratime,noexec /dev/sdb1 /mnt/data   # 省 IO + 禁执行
mount -o ro /dev/sdb1 /mnt/ro                          # 只读挂载（取证/救援）
mount -t ext4 -o loop /root/disk.img /mnt/img          # 挂载镜像文件（loop 设备）
```

```shell
# ext4 调整工具 tune2fs（改挂载选项之外的参数，无需重新格式化）
tune2fs -l /dev/sdb1                # 查看 ext4 超级块信息
tune2fs -m 1 /dev/sdb1              # 保留块比例调到 1%（默认 5%，大容量盘可调小）
tune2fs -L mydata /dev/sdb1         # 设置卷标（label）
e2label /dev/sdb1                   # 查看卷标
```

```shell
# XFS 专用管理工具（XFS 不能用 tune2fs）
xfs_admin -l /dev/sdb1              # 查看 XFS label 和 UUID
xfs_info /dev/sdb1                  # 查看 XFS 块大小/分配组等几何信息
```

```text
常用命令速查：
1. mkfs.ext4 / mkfs.xfs / mkfs.btrfs —— 格式化（mkfs -t ext4 等价）
2. mount / umount —— 挂载 / 卸载，mount -o 带选项
3. blkid / lsblk -f —— 查 UUID、文件系统类型
4. tune2fs —— ext4 专属调整（保留块/卷标/日志）；XFS 用 xfs_admin
5. findmnt —— 查挂载详情（挂载点、来源、选项、类型）
```

## 配置文件解析

fstab（/etc/fstab）配置开机自动挂载，每行：`设备 挂载点 类型 选项 dump fsck顺序`。用 UUID 而非设备名（/dev/sda1）标识分区——因为设备名可能因磁盘顺序变化而变，UUID 是分区的唯一标识、永远稳定。`blkid` 查 UUID，改完 fstab 用 `mount -a` 测试（能挂上说明配置对）。

```text
# 实测（本机 /etc/fstab）
$ grep -vE '^\s*#|^\s*$' /etc/fstab
/dev/disk/by-uuid/93b40af2-... / ext4 defaults 0 1
/dev/disk/by-uuid/2CA5-0507    /boot/efi vfat defaults 0 1
/swap.img none swap sw 0 0
# 用 UUID 标识分区（by-uuid/xxx），swap 是文件不是分区
```

```shell
blkid                          # 查分区 UUID
mount -a                       # 测试 fstab 配置（不报错即正确）
findmnt /                      # 查看挂载详情
```

```text
fstab 每列含义：
设备(UUID)  挂载点  类型  选项  dump(备份标志)  fsck顺序(0 不检查/1 根/2 其他)
```

fstab 各列详解：

- 第 1 列 设备：写 `/dev/sda1` 或 `UUID=xxx` 或 `LABEL=xxx`，推荐 UUID（稳定）。也可写 `/dev/disk/by-uuid/xxx` 符号链接路径。
- 第 2 列 挂载点：目录路径；swap 写 `none` 或 `swap`。
- 第 3 列 类型：ext4/xfs/vfat/swap 等，`auto` 让内核自动探测。
- 第 4 列 选项：`defaults`（= rw,suid,dev,exec,auto,nouser,async）或自定义，逗号分隔。常用 `nofail`（设备不存在也不卡启动）、`noatime`、`ro`。
- 第 5 列 dump：是否被 dump 备份，0 不备份，1 备份。
- 第 6 列 fsck 顺序：0 不检查，1 根分区（最先），2 其他分区。

```shell
# 一条 fstab 示例（数据盘，nofail 防启动卡住）
# UUID=xxxx-xxxx /data ext4 defaults,nofail 0 2
```

```text
fstab 选项要点：
1. UUID —— 设备列首选 UUID=xxx，设备名会因盘序变化
2. nofail —— 设备缺失（如 U 盘没插）也不阻断启动，可热插拔设备必加
3. fsck 顺序 —— 根分区写 1，其他写 2，0 表示开机不检查
4. 改完 mount -a 测试 —— 有错立刻报，别等重启才发现卡 emergency mode
```

## 应用场景实战

### 场景一：新数据盘格式化并配置开机自动挂载

```shell
# 1. 分区 + 格式化
parted /dev/sdb mklabel gpt
parted /dev/sdb mkpart data ext4 1MiB 100%
mkfs.ext4 /dev/sdb1
# 2. 查 UUID 写入 fstab
blkid /dev/sdb1
echo "UUID=<上一步的UUID> /data ext4 defaults 0 2" >> /etc/fstab
# 3. 建挂载点 + 测试挂载
mkdir /data
mount -a
df -h /data
```

### 场景二：异常关机后检查修复文件系统

```shell
# 1. 看文件系统状态
dmesg | grep -i 'ext4\|xfs' | tail
# 2. 卸载并检查
umount /dev/sdb1
fsck -f /dev/sdb1
# 3. 重新挂载
mount /dev/sdb1 /mnt/data
```

### 场景三：数据库大文件盘格式化成 XFS 并调优挂载

```shell
# 1. 格式化 XFS（数据库/大文件场景，-f 强制覆盖旧签名）
mkfs.xfs -f /dev/sdb1
# 2. 用 noatime 挂载（数据库访问频繁，省去 atime 更新写 IO）
mkdir /data
mount -o noatime /dev/sdb1 /data
# 3. 确认挂载选项生效
findmnt /data
# 4. 写进 fstab 持久化
blkid /dev/sdb1
echo "UUID=<上一步UUID> /data xfs defaults,noatime 0 2" >> /etc/fstab
mount -a
```

```text
场景三要点：
1. XFS 适合大文件/数据库 —— 分配组并行、延迟分配，高并发写吞吐强
2. noatime —— 数据库盘高频读，关 atime 省大量无意义写 IO
3. XFS 不能缩容 —— 规划容量时留足余量，别指望日后缩小
```

## 性能与调优

文件系统性能调优主要是「选对文件系统」和「挂载选项」：数据库/大文件选 XFS（并发写强），通用选 ext4，要快照选 Btrfs/ZFS。挂载选项里 noatime（不更新访问时间）能省大量写 IO；日志模式（data=ordered 默认安全，data=writeback 快但崩溃风险高）。对齐磁盘、留足空间（ext4 空间用满会碎片化、性能下降）也影响性能。

```text
文件系统性能要点：
1. 选型 —— 大文件/高并发写用 XFS，通用用 ext4
2. noatime —— 挂载选项，不更新访问时间，省写 IO
3. 日志模式 —— data=ordered（默认，安全）/ writeback（快，风险高）
4. 别用满 —— ext4 空间接近 100% 会碎片化，性能明显下降
```

```shell
# 关闭 atime（relatime 是 Linux 默认，比 noatime 折中：只在 atime < mtime 时更新）
mount -o noatime /dev/sdb1 /mnt/data
# 查看当前挂载选项
findmnt -o OPTIONS /mnt/data
```

```shell
# ext4 保留块调优：大容量数据盘把默认 5% 保留块调小，释放空间
tune2fs -m 1 /dev/sdb1        # 保留块比例 1%（5% 在 1TB 盘上就是 50G）
```

```text
调优清单：
1. noatime —— 读密集场景省写 IO，数据库/日志盘强烈建议
2. tune2fs -m —— 大容量数据盘调小保留块比例，别让 root 保留块白占空间
3. 日志模式 —— 默认 ordered 别乱改 writeback，除非能接受崩溃丢数据
4. XFS —— 用 mkfs.xfs 时默认参数已针对大文件优化，一般无需手动调
```

## 安全与权限

文件系统层的安全主要靠「挂载选项」和「权限」：nosuid（禁止 SUID 位生效，防提权）、nodev（不识别设备文件）、noexec（禁止执行文件）、ro（只读挂载）。给临时挂载点（如 /tmp、U 盘、共享目录）加这些选项能防攻击。文件系统的普通权限（rwx）和 inode 层面的 ACL 见 05 章。

```text
挂载安全选项：
1. nosuid —— 忽略 SUID/SGID 位，防提权攻击
2. nodev —— 不识别设备文件，防在挂载点创建设备节点
3. noexec —— 禁止执行该文件系统上的二进制
4. ro —— 只读挂载（关键数据/取证场景）
```

```shell
# 强化挂载：U 盘/共享目录等不可信来源
mount -o nosuid,nodev,noexec /dev/sdb1 /mnt/usb
# /tmp 常见加固写法（fstab 里）
# tmpfs /tmp tmpfs nosuid,nodev,noexec 0 0
```

```text
安全加固场景：
1. /tmp、/var/tmp、/dev/shm —— 常被攻击者利用，加 nosuid,nodev,noexec
2. 只读挂载 —— 关键配置/取证时 ro 挂载，防误改
3. 加密 —— 敏感数据在文件系统层之上叠 LUKS（cryptsetup），或选带内建加密的方案
```

## 故障排查

### 挂载失败

```shell
# 1. 看报错类型
mount /dev/sdb1 /mnt/data   # wrong fs type? 没格式化？设备不存在？
# 2. 确认分区存在 + 已格式化
lsblk /dev/sdb1 && blkid /dev/sdb1
# 3. 指定文件系统类型重试
mount -t ext4 /dev/sdb1 /mnt/data
```

### 文件系统损坏检查（fsck）

fsck 检查并修复文件系统错误，通常在系统异常关机、磁盘损坏后使用。检查前必须先卸载分区（umount），否则在挂载状态下检查会损坏数据。根分区检查需要在救援模式或重启时进行（开机自动 fsck）。

```shell
umount /dev/sdb1               # 先卸载
fsck -f /dev/sdb1              # 强制检查
fsck -y /dev/sdb1              # 自动修复错误
# 根分区检查：重启时加 fsck 参数，或进救援模式
```

### 文件系统变只读（remount ro）

```shell
# 症状：写入报 Read-only file system
# 1. 看内核日志找原因（IO 错误/磁盘故障触发内核把文件系统改只读）
dmesg | tail -20
# 2. 确认当前挂载状态
mount | grep ' / '
# 3. 修复底层问题后手动 remount 读写
mount -o remount,rw /
```

### XFS 检查不能用 fsck（fsck.xfs 是空操作）

```shell
# fsck.xfs 默认什么都不做，XFS 要用 xfs_repair
umount /dev/sdb1
xfs_repair /dev/sdb1            # 检查修复 XFS（挂载中会拒绝执行）
xfs_repair -n /dev/sdb1         # 只检查不修复（dry run）
```

```text
XFS 检查注意：
1. fsck.xfs 是空操作 —— XFS 检查修复必须用 xfs_repair
2. xfs_repair 要先 umount —— 挂载中执行会报错拒绝
3. 严重损坏时 xfs_repair -L 清日志（有丢数据风险，最后手段）
```

## 常见问题

```text
Q1: ext4 和 XFS 怎么选？
A: 通用/小文件用 ext4（默认、稳定），大文件/高并发写/数据库用 XFS，要快照用 Btrfs/ZFS。

Q2: mount 报 wrong fs type？
A: 分区没格式化，或文件系统类型和 mount 默认不一致，先 mkfs 或用 mount -t 指定类型。

Q3: umount 报 device is busy？
A: 有进程在用挂载点（cd 进去/文件被打开），用 fuser -m /mnt 找进程 kill，或 umount -l 懒卸载。

Q4: fstab 里设备名和 UUID 用哪个？
A: 用 UUID（by-uuid），设备名会因磁盘顺序变化而变，UUID 永远稳定。

Q5: 为什么 df 显示的空间和 du 对不上？
A: 常见原因：文件被删除但进程还开着（空间没释放，lsof | grep deleted 查）；或 ext4 保留块、日志占用。先找 deleted 文件 kill 进程。

Q6: 文件系统在挂载状态下能 fsck 吗？
A: 不能。挂载中检查会读到不一致数据、可能损坏文件系统，必须先 umount；根分区要在救援模式或重启时检查。
```

## 面试题

```text
1. 什么是 VFS？为什么需要它？
   答：VFS 是内核的虚拟文件系统抽象层，为上层提供统一 open/read/write 接口，屏蔽底层 ext4/XFS 等差异，使「一切皆文件」成立、新文件系统易接入。

2. 日志文件系统为什么能防崩溃损坏？
   答：写数据前先把操作记入 journal 日志，崩溃后重放日志恢复一致性，避免文件系统元数据损坏。

3. mount 和 fstab 的关系？
   答：mount 是临时挂载（重启失效），fstab 配置开机自动挂载，是持久化的依据。

4. 文件系统的 inode 和文件名什么关系？
   答：inode 存文件元数据（权限/大小/块指针），文件名只是目录里「名字 → inode」的条目，所以硬链接可以多个名字指向同一 inode。

5. ext4 的日志三种模式（data=ordered/writeback/journal）区别？
   答：ordered 数据先落盘再提交元数据（默认，安全均衡）；writeback 只记元数据日志、最快但崩溃可能丢数据；journal 数据元数据都记日志、最安全但写放大最慢。

6. 为什么 XFS 不能缩容？
   答：XFS 的分配组和 extent 布局为「只增不减」设计，官方只提供在线扩容（xfs_growfs），没有缩容工具；要缩只能备份数据、重建小卷、恢复数据。
```

## 最佳实践与踩坑记录

### 最佳实践

1. fstab 用 UUID 标识分区，别用设备名（会因磁盘顺序变化而变）
2. 改完 fstab 先 mount -a 测试，能挂上再重启
3. 检查文件系统前先 umount 卸载，挂载中检查会损坏数据
4. 数据库/大文件场景选 XFS，通用选 ext4，要快照选 Btrfs/ZFS
5. 格式化前再三确认目标分区，mkfs 不可逆
6. 数据盘挂载加 noatime，读密集场景省写 IO
7. 可热插拔设备（U 盘/移动盘）fstab 加 nofail，防没插设备卡启动

### 踩坑记录

```text
坑 1：fstab 写错导致系统无法启动
结论：fstab 配错挂载参数，开机卡住进 emergency mode。
原因：fstab 是开机挂载的依据，错一行可能挂载失败卡启动。
解法：改完 mount -a 测试；卡启动时进救援模式注释掉错误行。

坑 2：mount 挂载失败报 wrong fs type
结论：mount /dev/sdb1 报 wrong fs type, bad option。
原因：分区没格式化，或文件系统类型和 mount 默认不一致。
解法：先 mkfs 格式化，或用 mount -t 指定类型。

坑 3：用设备名 /dev/sda1 写 fstab，换盘序后挂载错乱
结论：加了一块盘后 sda 变 sdb，fstab 里 /dev/sda1 挂到了别的盘。
原因：设备名按枚举顺序分配，不固定。
解法：fstab 用 UUID（by-uuid），永久稳定。

坑 4：fsck 检查挂载中的分区
结论：对已挂载分区 fsck，提示 running fsck on mounted filesystem 危险。
原因：挂载中检查会读到不一致的数据，可能破坏文件系统。
解法：先 umount 再 fsck，根分区在救援模式/重启时检查。

坑 5：umount 卸载报 device is busy
结论：umount /mnt 报 target is busy。
原因：有进程正在用该挂载点（cd 进去、文件被打开）。
解法：fuser -m /mnt 找占用进程，kill 后重试，或 umount -l 懒卸载。

坑 6：文件删了空间没释放
结论：rm 删了日志文件，df 看空间没涨。
原因：文件被进程打开着（fd 没关），删除只是断链接，数据块仍被占用。
解法：lsof +L1 或 lsof | grep deleted 找占用进程，重启/kill 后空间释放。

坑 7：XFS 盘用 fsck 检查「什么都没做」
结论：对 XFS 跑 fsck 瞬间返回，实际根本没检查。
原因：fsck.xfs 默认是空操作，XFS 的检查修复靠 xfs_repair。
解法：XFS 用 xfs_repair（先 umount），别指望 fsck。
```

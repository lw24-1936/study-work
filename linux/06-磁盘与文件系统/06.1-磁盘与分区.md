## 概述

磁盘要先「分区」再「格式化」才能存数据。分区表分 MBR（老式，最大 2TB、最多 4 主分区）和 GPT（新式，支持大容量、128 分区、UEFI 标配）两种。分区工具 fdisk（MBR/传统）、gdisk（GPT 版 fdisk）、parted（两者都支持，脚本友好）。理解磁盘结构（扇区/分区表）和分区工具，才能给新磁盘划分区、扩容。

```text
磁盘 → 分区 → 文件系统 三层：
1. 磁盘 —— 物理块设备 /dev/sda、/dev/nvme0n1，由扇区组成
2. 分区 —— 把磁盘切成 /dev/sda1、/dev/sda2 等逻辑块
3. 文件系统 —— 分区上建 ext4/XFS 等，才能存文件
```

## 核心概念

### 磁盘结构：扇区、磁道、柱面与寻址

磁盘（块设备）由扇区组成，每个扇区传统 512 字节（新盘 4K）。分区表记录「这块盘怎么切」，分区是磁盘上的连续区域。Linux 里磁盘叫 /dev/sda、/dev/sdb（SATA），NVMe 叫 /dev/nvme0n1，分区用数字后缀（sda1、nvme0n1p1）。用 lsblk 能看清整机的块设备和分区树。

机械盘按「盘片 → 磁道（track）→ 扇区（sector）」组织数据：多个盘片同半径的磁道组成柱面（cylinder）。寻址方式有两种：

- CHS（柱面/磁头/扇区）：老式三维寻址，受 BIOS 中断 13h 限制，最多寻址 8GB，早已被淘汰。
- LBA（Logical Block Addressing，逻辑块寻址）：把扇区从 0 开始线性编号，现代盘和分区表都用它。

```text
磁盘结构术语：
1. 扇区 sector —— 最小物理读写单元，传统 512 字节，Advanced Format 新盘 4096 字节（4K）
2. 磁道 track —— 盘片上同一半径的一圈，柱面 cylinder —— 多个盘片同半径磁道的集合
3. CHS —— 柱面/磁头/扇区三维寻址，老式，上限约 8GB
4. LBA —— 逻辑块线性寻址，扇区从 0 编号，现代标准
5. 512e / 4Kn —— 512e 是「逻辑 512B 物理 4K」，4Kn 是「逻辑物理都是 4K」，分区要对齐物理扇区
```

```shell
# 查看磁盘扇区大小和物理/逻辑扇区（512e 盘会显示 logical 512 / physical 4096）
fdisk -l /dev/sda | head -5
# 查看块设备几何信息
blockdev --getss --getpbsz /dev/sda     # 逻辑扇区 + 物理扇区大小
```

```text
# 实测（本机 lsblk，省略 snap 的 loop 设备）
NAME   SIZE   TYPE MOUNTPOINTS
sda  931.5G   disk
├─sda1    1G   part /boot/efi
└─sda2 930.5G part /
sdb  119.2G   disk
├─sdb1  650M   part          # ESP 分区
├─sdb3 104.4G  part          # Windows 系统盘（ntfs）
├─sdb5  11.9G  part          # Windows 恢复分区
└─sdb6   1.2G  part          # Dell 支持分区
# 本机是双系统：sda 是 Ubuntu（ext4），sdb 是 Windows（ntfs）
```

### 分区类型：主分区、扩展分区、逻辑分区

MBR 分区表把分区分为「主分区（primary）」和「扩展分区（extended）」：主分区最多 4 个，扩展分区最多 1 个（占用一个主分区名额），扩展分区内部可以再切多个「逻辑分区（logical）」。所以 MBR 要超过 4 个分区，套路是「3 主分区 + 1 扩展分区 → 扩展里再建逻辑分区」。GPT 没有主/扩展/逻辑之分，统一 128 个分区项，简单得多。

```text
MBR 分区类型：
1. 主分区 primary —— 最多 4 个，可直接装系统、直接挂载
2. 扩展分区 extended —— 最多 1 个，占一个主分区名额，自身不能存数据
3. 逻辑分区 logical —— 建在扩展分区里，编号从 5 开始（sda5、sda6...）
4. GPT —— 无主/扩展/逻辑之分，统一 128 个分区项
```

### MBR 与 GPT 分区表

分区表分 MBR 和 GPT 两种：MBR 是老式分区表，存在磁盘第一个扇区（512 字节），最多 4 个主分区（或 3 主 + 1 扩展），单分区最大 2TB。GPT 是新式，UEFI 标配，支持 128 个分区、超 2TB 磁盘，自带备份分区表和校验。判断方法：有 /boot/efi 挂载点就是 GPT+UEFI。

```text
MBR vs GPT：
1. MBR —— 512 字节主引导记录，4 主分区上限，单分区 ≤2TB，老 BIOS 引导
2. GPT —— GUID 分区表，128 分区，支持 >2TB，自带备份表，UEFI 引导标配
3. 判断 —— lsblk 看有没有 /boot/efi（ESP 分区），有就是 GPT+UEFI
```

```text
# 实测（本机是 GPT+UEFI）
$ df -hT | grep efi
/dev/sda1  vfat  1.1G  6.2M  1.1G  1%  /boot/efi
# 有 /boot/efi（EFI 系统分区），说明是 GPT 分区表 + UEFI 引导
```

### 三个分区工具：fdisk / gdisk / parted

- fdisk：util-linux 自带，交互式，MBR 和 GPT 都能处理（新版自动识别分区表类型），日常最常用。
- gdisk：GPT fdisk 项目出品，只处理 GPT，界面命令和 fdisk 几乎一样，是「GPT 专版 fdisk」。
- parted：GNU Parted，支持脚本化（一条命令建分区），适合自动化、批量操作，MBR/GPT 都支持。

```text
三个工具定位：
1. fdisk —— 交互式，MBR/GPT 都支持，日常手动分区首选
2. gdisk —— 交互式，GPT 专用，命令同 fdisk，处理 GPT 细节更顺手
3. parted —— 脚本化，一条命令建分区，适合自动化/批量，MBR/GPT 都支持
```

## 工作原理

分区表是磁盘的「目录」——记录每个分区从哪个扇区开始、到哪结束、是什么类型。MBR 把分区表放在第 0 扇区（512 字节：446 字节引导代码 + 64 字节分区表 + 2 字节结束标志），64 字节只能装 4 个分区项（每项 16 字节），所以最多 4 个主分区。GPT 用 LBA 分区，分区表放在磁盘开头和结尾各一份（冗余备份），每项记录分区的 GUID、起始/结束 LBA、类型，因此支持 128 分区和大容量。

```text
分区表工作原理：
1. MBR —— 第 0 扇区存分区表（446B 引导 + 64B 分区表 + 2B 标志），4 主分区上限
2. GPT —— LBA 分区，开头结尾各一份分区表（冗余），128 分区 + 大容量
3. 内核识别 —— 分区表写盘后需 partprobe 刷新，内核才生成 /dev/sdaN 设备节点
```

MBR 的扩展分区靠「链式 EBR」实现多个逻辑分区：扩展分区里每个逻辑分区前面都有一个 EBR（Extended Boot Record），记录「本逻辑分区的位置 + 下一个 EBR 的位置」，一个个串起来。这也是 MBR 逻辑分区编号从 5 开始的原因——1~4 留给主分区。

GPT 的具体布局：LBA 0 是保护性 MBR（Protective MBR，防止老工具误判为空白盘而破坏），LBA 1 是 GPT 头（含分区表位置、CRC32 校验、备份位置），LBA 2~33 是 128 个分区项（每项 128 字节，含分区类型 GUID、唯一 GUID、起止 LBA、属性），磁盘末尾有备份 GPT 头 + 备份分区表。主表坏了内核能自动用末尾的备份表恢复。

```text
GPT 布局细节：
1. LBA 0 —— 保护性 MBR，防止老工具把 GPT 盘当空白盘破坏
2. LBA 1 —— GPT 头，含 CRC32 校验和、分区表位置、备份表位置
3. LBA 2~33 —— 128 个分区项（每项 128 字节），记录类型 GUID / 唯一 GUID / 起止 LBA
4. 盘尾 —— 备份 GPT 头 + 备份分区表，主表损坏可自动恢复
```

分区工具做的事就是「读写分区表」：新建分区 = 往分区表里加一项，删分区 = 删一项。分区表写好后，内核要重新读（partprobe / kpartx）才会在 /dev 下生成对应的设备节点。

## 常用命令与配置

三个分区工具：fdisk 最常用（交互式，MBR/GPT 都支持）、gdisk 是 fdisk 的 GPT 专版（界面和 fdisk 一样）、parted 支持脚本化（适合自动化）。流程都是：选盘 → 建分区表 → 建分区 → 写盘 → 刷新内核分区表（partprobe）。改分区前先备份数据——分区操作有风险，错一步数据就没了。

```shell
fdisk /dev/sdb        # 交互式分区（n 新建、w 写盘、q 退出）
gdisk /dev/sdb        # GPT 版 fdisk
parted /dev/sdb mklabel gpt   # 脚本化建 GPT 分区表
parted /dev/sdb mkpart primary ext4 1MiB 100GiB
partprobe             # 刷新内核分区表，让新分区立即可见
```

```shell
# 查看分区表（只读，安全）
fdisk -l /dev/sda
lsblk
```

fdisk 交互式建分区：进入后按 m 看帮助，常用 n（新建）、p（打印分区表）、d（删除）、t（改分区类型）、g（新建 GPT 表）、o（新建空 MBR 表）、w（写盘保存）、q（退出不保存）。以下是一个完整交互流程：

```text
$ fdisk /dev/sdb
Command (m for help): g      # 新建空 GPT 分区表
Command (m for help): n      # 新建分区
Partition number (1-128, default 1): 1
First sector (2048-..., default 2048):        # 回车用默认（1MiB 对齐）
Last sector (default ...): +100G             # 分区大小 100G
Command (m for help): p      # 打印确认
Command (m for help): w      # 写盘保存（q 则放弃）
```

gdisk 的交互命令和 fdisk 完全一致（n/p/d/t/w/q），区别是 gdisk 只认 GPT，进入时会自动把空盘初始化成 GPT 表。parted 脚本化建分区一条命令搞定：

```shell
# parted 脚本化：建 GPT 表 + 一个 100G 数据分区
parted /dev/sdb mklabel gpt
parted /dev/sdb mkpart data ext4 1MiB 100GiB
parted /dev/sdb print            # 查看分区表（比 fdisk 输出更紧凑）
parted /dev/sdb rm 1             # 删除 1 号分区
```

```shell
# 删除分区表（wipefs 抹掉 MBR/GPT 签名，常用于「重做分区」前清空）
wipefs -a /dev/sdb
# 抹掉后确认
lsblk /dev/sdb
```

```text
fdisk 交互命令速查：
1. m —— 帮助，p —— 打印分区表，n —— 新建，d —— 删除
2. t —— 改分区类型（GPT 里选 Linux filesystem 等 GUID 类型）
3. g —— 新建空 GPT 表，o —— 新建空 MBR 表（DOS label）
4. w —— 写盘保存，q —— 退出不保存（丢弃所有修改）
```

## 配置文件解析

分区表没有独立的「配置文件」，它的「配置」直接写在磁盘上（MBR 第 0 扇区 / GPT 的 LBA）。但有几个地方能读到分区信息：/proc/partitions（内核识别的分区）、/dev/disk/by-uuid、by-partuuid（分区标识的符号链接）、`sgdisk --backup` 导出的分区表备份。

```shell
cat /proc/partitions          # 内核看到的分区（major/minor + 块数）
ls -l /dev/disk/by-uuid/      # 按 UUID 标识分区
ls -l /dev/disk/by-partuuid/  # 按分区 GUID 标识
sgdisk --backup=/root/parts.bak /dev/sda     # 备份 GPT 分区表
sgdisk --load-backup=/root/parts.bak /dev/sda   # 恢复分区表
```

```text
分区表备份：
1. sgdisk --backup —— 导出分区表（几十字节），误删分区后可恢复
2. /dev/disk/by-partuuid —— GPT 分区的稳定标识（不因盘序变化）
3. /proc/partitions —— 内核当前识别的分区，比 lsblk 更底层
```

除 sgdisk 外，sfdisk 也能导出/导入分区表（MBR/GPT 都行，脚本友好，用逗号分隔的 dump 格式）。fdisk 自身在写盘时会把原分区表备份到磁盘扇区（GPT 自动存末尾备份），sgdisk 的备份文件是「额外的一份保险」。

```shell
# sfdisk 导出分区表（文本格式，可读可改，适合脚本批量复刻分区布局）
sfdisk --dump /dev/sda > /root/sda.part
# sfdisk 导入分区表（把导出的布局应用到新盘，实现「复制磁盘布局」）
sfdisk /dev/sdb < /root/sda.part
```

```text
分区表备份方式对比：
1. sgdisk --backup —— 二进制备份，GPT 专用，恢复最直接
2. sfdisk --dump —— 文本导出，可读可改，适合脚本批量复制布局（MBR/GPT 都支持）
3. GPT 自带 —— 磁盘末尾自动存备份表，主表损坏内核自动恢复
```

## 应用场景实战

### 场景一：给新加的数据盘分区并查看

```shell
# 1. 识别新盘
lsblk
# 2. 建 GPT 分区表 + 一个数据分区
parted /dev/sdc mklabel gpt
parted /dev/sdc mkpart data ext4 1MiB 100%
partprobe
# 3. 确认分区
lsblk /dev/sdc
```

### 场景二：查看现有分区布局排查磁盘问题

```shell
# 看整机磁盘和分区树
lsblk
# 看分区表类型和详情
fdisk -l /dev/sda
# 看每个分区的文件系统类型和 UUID
blkid
```

### 场景三：用 fdisk 交互式给新盘建 MBR 分区（老 BIOS 场景）

```shell
# 老 BIOS 机器需要 MBR 分区表时的完整交互流程
fdisk /dev/sdb
# 交互步骤：
#   o          新建空 MBR 分区表（DOS label）
#   n          新建分区，选 p（主分区），分区号 1，起始用默认，大小 +200G
#   n          再建分区，选 p（主分区），分区号 2，起始用默认，大小用默认（剩余全部）
#   t 1        改 1 号分区类型为 83（Linux filesystem）
#   p          打印确认
#   w          写盘保存
partprobe
lsblk /dev/sdb          # 应看到 sdb1、sdb2
```

```text
场景三要点：
1. MBR 最多 4 主分区 —— 超过 4 个要改成 3 主 + 1 扩展，扩展里建逻辑分区
2. 起始扇区用默认 —— fdisk 新版默认 2048 扇区（1MiB）对齐，别手改
3. 类型 83 —— MBR 里 83 是 Linux 文件系统，82 是 swap，GPT 里改类型用 GUID
```

## 性能与调优

分区层面的性能要点是「分区对齐」：分区起始位置要对齐到磁盘物理扇区/擦除块的边界（传统 512B 扇区、新盘 4K 扇区、SSD 页）。没对齐会导致一次 IO 跨两个物理块，读写放大、性能下降。现代工具（parted/fdisk）默认从 1MiB 对齐，基本不用担心，但老工具或手工指定起始扇区时要注意。SSD 的分区对齐尤其重要（影响写放大和寿命）。

```text
分区性能要点：
1. 4K 对齐 —— 分区起始要对齐物理扇区/页边界，否则 IO 跨块放大
2. 现代工具默认 1MiB 对齐 —— parted/fdisk 新版本自动处理，别手改起始扇区
3. SSD —— 对齐影响写放大和寿命，务必对齐
4. 分区数量 —— 别切太碎，分区多不影响性能（但挂载点多管理麻烦）
```

验证分区是否对齐：起始扇区能被 8（4K 盘 4096/512=8）整除即对齐。fdisk -l 看 Start 列，或 parted 用 unit s print 看起始扇区。

```shell
# 检查分区起始扇区是否 4K 对齐（4096 字节 = 8 个 512 字节扇区）
parted /dev/sda unit s print
# 看每个分区的 Start 扇区值，能被 8 整除即为 4K 对齐（如 2048、2048000）
fdisk -l /dev/sda | grep -E '^/dev'
```

```text
对齐判断：
1. 512B 逻辑 / 4K 物理的盘 —— 分区起始扇区要能被 8 整除（4096/512）
2. 现代工具默认从 2048 扇区（1MiB）起 —— 2048 能被 8 整除，天然对齐
3. 手工 mkpart 起始写成 1MiB 而非裸扇区号 —— parted 会自动对齐到最优边界
```

## 安全与权限

分区操作都是高危操作（写分区表），只有 root 能执行。数据安全靠三件事：操作前备份分区表（sgdisk --backup）、操作前备份数据、操作前用只读命令（fdisk -l / lsblk）确认目标盘没错。生产环境改分区前，先在测试机/虚拟机演练，别直接在线上盘动手。

```text
分区安全要点：
1. 只有 root 能分区 —— 普通用户无权限，防误操作
2. 操作前备份分区表 —— sgdisk --backup，几十字节能救命
3. 操作前确认目标盘 —— lsblk/fdisk -l 只读查看，别把系统盘当数据盘
4. 生产改分区先演练 —— 在测试机/虚机验证过再上生产
```

特别提醒：分区操作写的是分区表本身，但「删除分区」「重建分区」本身不会立刻清零数据（数据还在盘上，只是分区表不再指向它）。所以误删分区后，只要没在盘上继续写新数据，用备份分区表或 testdisk 恢复，数据大概率能救回来。反过来，「重新分区 + 格式化」才会真正破坏数据。

```text
误删分区后的数据恢复窗口：
1. 删分区 ≠ 删数据 —— 分区表不指向了，数据扇区还在
2. 立即停手 —— 别再 mkpart/mkfs，覆盖前都能救
3. sgdisk --load-backup 恢复分区表，或 testdisk 扫描重建
```

## 故障排查

### 分区不识别（新建分区后 /dev 下没设备）

```shell
# 1. 看内核有没有识别
cat /proc/partitions | grep sdc
# 2. 没识别就刷新分区表
partprobe
# 3. 还不行就 kpartx 或重启
```

### 分区表损坏（fdisk -l 报错）

```shell
# 1. 用备份恢复 GPT 分区表
sgdisk --load-backup=/root/parts.bak /dev/sda
# 2. 没有备份用 testdisk 尝试恢复
# 3. 确认恢复结果
fdisk -l /dev/sda
```

### fdisk 打开磁盘报错（No such file / Permission denied）

```shell
# 1. 确认设备名拼对、盘真在
lsblk | grep sd
# 2. Permission denied —— 检查是否 root
sudo fdisk -l /dev/sdb
# 3. No such file —— 设备节点没生成，看内核日志
dmesg | tail -20
```

### GPT 盘被老工具报「PMBR size mismatch」警告

```shell
# 症状：fdisk -l 提示 GPT PMBR size mismatch ... will be corrected
# 1. 用 gdisk 或新版 fdisk 重写保护性 MBR
sgdisk -e /dev/sda          # 修复保护性 MBR
# 2. 确认警告消失
fdisk -l /dev/sda | tail -3
```

```text
PMBR size mismatch 原因：
1. 保护性 MBR 里的「整盘大小」字段和实际不符 —— 常发生在磁盘扩容/克隆后
2. 影响 —— 通常无害，但老工具可能误判，sgdisk -e 一键修复
```

## 常见问题

```text
Q1: MBR 和 GPT 怎么选？
A: 新系统/新盘一律 GPT（UEFI 标配、支持大容量、自带备份），MBR 只在兼容老 BIOS 或特殊需求时用。

Q2: fdisk、gdisk、parted 用哪个？
A: 交互式日常用 fdisk（GPT 也能处理），纯 GPT 操作可用 gdisk，脚本化/自动化用 parted。

Q3: 新建分区后为什么 /dev/sdc1 不存在？
A: 内核没刷新分区表，执行 partprobe 或重启。

Q4: 分区能无损调整大小吗？
A: parted 支持 resize（有数据时风险高），或改用 LVM（在线扩容缩容，见 06.3）。普通分区调整前先备份。

Q5: 为什么 MBR 分区编号从 5 开始（sda5）？
A: 1~4 号留给主分区/扩展分区，逻辑分区建在扩展分区里、编号从 5 开始。GPT 没这个限制。

Q6: 删了分区数据还能恢复吗？
A: 能。删分区只改分区表、不清数据扇区，只要没重新分区/格式化，用备份分区表（sgdisk --load-backup）或 testdisk 扫描即可恢复。
```

## 面试题

```text
1. MBR 和 GPT 的区别？
   答：MBR 512 字节主引导记录，4 主分区、单分区 ≤2TB；GPT 128 分区、支持 >2TB、自带备份分区表、UEFI 标配。

2. 为什么 MBR 最多 4 个主分区？
   答：MBR 分区表只有 64 字节，每个分区项 16 字节，所以最多 4 个；要更多分区用扩展分区（3 主 + 1 扩展）。

3. 分区和文件系统什么关系？
   答：分区是磁盘上的连续区域（先切块），文件系统是分区上的数据组织规则（再格式化），先分区再格式化才能存文件。

4. 新盘上架后怎么分区？
   答：lsblk 识别 → parted mklabel gpt 建分区表 → mkpart 建分区 → partprobe 刷新 → mkfs 格式化 → mount 挂载。

5. 什么是分区对齐（4K 对齐）？为什么重要？
   答：分区起始扇区对齐到物理扇区（4K）边界，起始扇区能被 8 整除。不对齐会导致一次 IO 跨两个物理块、读写放大，SSD 上还加剧写放大、缩短寿命。

6. CHS 和 LBA 寻址的区别？
   答：CHS 用柱面/磁头/扇区三维寻址，受 BIOS 限制只能寻址约 8GB；LBA 把扇区线性编号，现代盘和分区表（MBR 32 位 / GPT 64 位）都用 LBA。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 分区操作前先备份数据，fdisk/parted 误操作不可逆
2. 新系统用 GPT + UEFI，MBR 只在兼容旧 BIOS 时用
3. 分区表操作完执行 partprobe 刷新，否则新分区不识别
4. 数据盘和系统盘分开，系统盘别存业务数据
5. 用 lsblk -f 一次看清分区 + 文件系统 + UUID + 挂载点
6. 分区起始用默认 1MiB 对齐，别手工指定裸扇区号
7. 分区前先 wipefs -a 清旧签名，避免新旧分区表冲突

### 踩坑记录

```text
坑 1：fdisk 改了分区没 w 写盘就退出
结论：分区操作做了，但没按 w 保存，重新看还是原样。
原因：fdisk 是交互式，q 退出不保存，w 才写盘。
解法：确认无误后按 w 写入，别用 q 退出（q 丢弃所有修改）。

坑 2：新建分区后 /dev/sda3 不存在
结论：parted/fdisk 建了分区，但 /dev 下没出现对应设备。
原因：内核没刷新分区表，新分区没被识别。
解法：执行 partprobe 或 kpartx 刷新，或重启。

坑 3：MBR 分区表装不了超 2TB 的盘
结论：2TB 以上磁盘用 MBR 只能用到 2TB。
原因：MBR 用 32 位扇区地址，单分区上限 2TB。
解法：大容量盘用 GPT，别用 MBR。

坑 4：误操作分区导致数据丢失
结论：parted mkpart 选错起始位置，覆盖了原有分区。
原因：分区操作直接写分区表，选错范围就破坏数据。
解法：操作前 fdisk -l 看清现有布局，备份分区表（sgdisk --backup）。

坑 5：给有数据的盘重新分区没卸载
结论：挂载中的分区重新分区，数据损坏。
原因：分区被挂载使用时改动，文件系统不一致。
解法：先 umount 卸载，再分区，分区完重新格式化挂载。

坑 6：在 GPT 盘上误建 MBR 表（或反过来）
结论：o 命令在 GPT 盘上建了 MBR 表，原分区信息全丢。
原因：fdisk 的 o（新建 DOS 表）/ g（新建 GPT 表）会清空现有分区表，方向搞反就毁了布局。
解法：动手前 p 确认当前表类型；清表前先 sgdisk --backup 备份。

坑 7：分区起始扇区手工指定成奇数导致 4K 没对齐
结论：mkpart 手工写起始扇区（如 63），4K 盘上 IO 放大、性能下降。
原因：63 这类老 BIOS 遗留起始值不被 8 整除，没对齐物理 4K 边界。
解法：起始一律用默认（2048）或写 1MiB，用 parted unit s print 核对能被 8 整除。
```

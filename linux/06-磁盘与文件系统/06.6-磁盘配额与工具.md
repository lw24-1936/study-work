## 概述

磁盘相关的运维工具分三类：配额（quota，限制每个用户/组能用多少空间）、查看（df/du/lsblk/blkid，看空间用了多少、设备是什么）、性能（iostat，看 IO 吞吐和延迟）。日常排查「磁盘满了」「谁占的空间」「IO 慢不慢」就靠这些工具。quota 管「防超额」，查看工具管「定位问题」，iostat 管「分析性能」。

```text
工具三分类：
1. quota —— 按用户/组限制磁盘空间和 inode 数，防止单人占满
2. df/du —— df 看分区用量、du 看目录用量，定位「谁占了空间」
3. lsblk/blkid —— lsblk 看设备树、blkid 看 UUID/文件系统类型
4. iostat —— IO 吞吐、延迟、利用率，分析磁盘性能
```

## 核心概念

quota 给每个用户/组设置磁盘空间（block）和文件数（inode）上限，防止单个用户占满整个磁盘（比如共享服务器上某用户狂存文件）。启用步骤：挂载选项加 usrquota/grpquota → quotacheck 建配额库 → edquota 设置配额 → quotaon 启用。分软限制（soft，超了宽限期告警）和硬限制（hard，硬上限）。

```shell
# 1. 挂载时启用 quota（fstab 加 usrquota,grpquota 选项）
mount -o remount,usrquota,grpquota /home
# 2. 初始化配额库
quotacheck -cug /home
# 3. 启用配额
quotaon /home
# 4. 设置用户配额（交互式编辑）
edquota -u alice
# 查看配额使用
repquota /home
```

```text
quota 关键概念：
1. block 配额 —— 限制占用的磁盘空间（KB/MB/GB）
2. inode 配额 —— 限制文件数量（防大量小文件）
3. soft 软限制 —— 超了给宽限期，期限内可恢复
4. hard 硬限制 —— 硬上限，超了无法再写
```

## 工作原理

quota 的原理是「内核统计 + 配额库存储」。启用 quota 后，内核按 uid/gid 统计每个用户的 block 和 inode 用量（写文件时实时计数），和配额库（aquota.user/aquota.group）里的限额比较，超 hard 限制就拒绝写入。df/du 的原理不同：df 读文件系统的超级块（superblock）统计整分区用量，du 遍历目录逐文件累加。iostat 读 /proc/diskstats 内核的 IO 统计。

```text
磁盘工具工作原理：
1. quota —— 内核按 uid/gid 实时计数 block/inode，超 hard 拒写
2. df —— 读 superblock 统计分区整体用量
3. du —— 遍历目录逐文件累加
4. iostat —— 读 /proc/diskstats 内核 IO 统计
```

## 常用命令与配置

df 看「分区级别」的用量（哪个分区满了），du 看「目录级别」的用量（哪个目录占了空间）。排查「磁盘满了」的标准流程：df -h 看哪个分区满 → du -sh 逐层找大目录 → 定位到大文件。df 看挂载点、du 看具体占用，两者配合才能定位到「谁吃了磁盘」。

```text
# 实测（df 看分区级别）
$ df -hT
/dev/sda2  ext4  915G  62G  808G   8%  /
/dev/sda1  vfat  1.1G 6.2M  1.1G   1%  /boot/efi
# 根分区 915G 用了 62G（8%），还健康
```

```shell
df -h                 # 分区用量（人类可读）
du -sh /var/*         # 各目录占用，定位大目录
du -sh /var/* | sort -rh | head    # 按大小排序找 TOP
df -i                 # 看 inode 使用（文件数，不是空间）
```

lsblk 以树状显示块设备和分区（磁盘→分区→挂载点），一眼看清整机磁盘布局；blkid 显示每个设备的 UUID 和文件系统类型。lsblk -f 两者结合，一次输出「设备 + 文件系统 + UUID + 挂载点 + 用量」，是识别磁盘的万能命令。

```text
# 实测（lsblk -f 关键部分）
NAME   FSTYPE  LABEL      MOUNTPOINTS
sda
├─sda1 vfat               /boot/efi
└─sda2 ext4               /
sdb
├─sdb1 vfat    ESP
├─sdb3 ntfs    OS          # Windows 系统盘
├─sdb5 ntfs    Image
└─sdb6 ntfs    DELLSUPPORT
# 一眼看出：sda 是 Ubuntu（ext4），sdb 是 Windows（ntfs，双系统）
```

```shell
lsblk                 # 设备树
lsblk -f              # 设备 + 文件系统 + UUID + 挂载点
blkid                 # UUID 和文件系统类型
blkid /dev/sda2       # 查单个设备的 UUID
```

## 配置文件解析

quota 的配置分三处：挂载选项（/etc/fstab 里分区加 usrquota,grpquota）、配额库文件（aquota.user/aquota.group，存各用户限额）、配额参数（宽限期，tunefs/ext4 用 edquota -t 设置）。df/du/lsblk 无配置文件（读内核信息），iostat 的配置在 /etc/default/sysstat（是否开机收集）。

```shell
# fstab 里启用 quota 的挂载选项
# /dev/sdb1 /home ext4 defaults,usrquota,grpquota 0 2
# 配额库文件（quotacheck 生成）
# /home/aquota.user   /home/aquota.group
edquota -t            # 设置宽限期（soft 超限后能撑多久）
```

```text
quota 配置三处：
1. fstab 挂载选项 —— usrquota/grpquota 启用配额
2. aquota.user/group —— 配额库，存各用户限额
3. 宽限期 —— edquota -t 设置，soft 超限后的缓冲期
```

## 应用场景实战

### 场景一：磁盘满了，定位是哪个目录吃掉的

```shell
# 1. 看哪个分区满
df -h
# 2. 对满的分区逐层找大目录
du -sh /var/* 2>/dev/null | sort -rh | head -10
# 3. 定位大文件
find /var -type f -size +100M -exec ls -lh {} \; 2>/dev/null
```

### 场景二：给共享服务器设磁盘配额防超额

```shell
# 1. 启用配额（fstab 挂载选项加 usrquota）
mount -o remount,usrquota /home
quotacheck -cum /home
quotaon /home
# 2. 给用户设 10G 空间 + 100 万文件配额
setquota -u alice 10G 11G 1000000 1100000 /home
# 3. 查看配额使用
repquota /home
```

## 性能与调优

iostat 报告磁盘 IO 性能：吞吐（KB 读写/秒）、IOPS（每秒 IO 次数）、延迟（await）、利用率（%util）。排查「磁盘慢」就看这些指标——await 高说明 IO 延迟大、%util 接近 100% 说明磁盘饱和。iostat 来自 sysstat 包（`apt install sysstat`），`iostat -x 1` 每秒刷新看实时 IO。

```shell
iostat                 # 概览
iostat -x 1            # 每秒看扩展指标（吞吐/IOPS/await/%util）
iostat -p sda          # 看某块盘的 IO
```

```text
iostat 关键指标：
1. r/s w/s —— 每秒读写 IO 次数（IOPS）
2. rkB/s wkB/s —— 每秒读写吞吐（KB）
3. await —— 平均 IO 等待时间（延迟，高说明慢）
4. %util —— 设备繁忙度（接近 100% 说明磁盘饱和）
```

## 安全与权限

磁盘空间是共享资源，安全核心是「防止滥用」：quota 限制单人占满（共享服务器必须配）；df/du 排查时注意权限（du 统计没权限的目录会报错/遗漏）；磁盘告警阈值要提前设（80% 提醒、90% 告警），别等 100% 才处理。iostat 等监控工具要持续收集才能发现趋势。

```text
磁盘安全要点：
1. quota 防滥用 —— 共享服务器必配，防单人占满
2. du 权限 —— 统计时无权限目录会遗漏，root 跑才准
3. 告警阈值 —— 80% 提醒、90% 告警，别等 100%
4. 持续监控 —— iostat 持续收集，才能发现 IO 趋势
```

## 故障排查

### df 和 du 对不上

```shell
# 1. 对比 df 和 du
df -h / && du -sh /
# 2. 找被删除但没释放的文件（句柄没关）
lsof +L1 | head
# 3. 重启占用进程释放空间
```

### 写文件报 no space 但 df 显示有空间

```shell
# 1. 看 inode 使用
df -i
# 2. inode 用完（大量小文件），找小文件多的目录
find / -xdev -type f | awk -F/ '{print $2}' | sort | uniq -c | sort -rn | head
# 3. 删除海量小文件释放 inode
```

## 常见问题

```text
Q1: df 和 du 为什么对不上？
A: 有文件被删除但仍被进程占用（句柄没释放），df 算它们、du 不算。用 lsof +L1 找。

Q2: 磁盘没满但写文件报 no space？
A: inode 用完了（大量小文件），df -i 能看出，删小文件释放 inode。

Q3: quota 配了为什么不生效？
A: 挂载没加 usrquota 选项，或 quotaon 没启用。确认 fstab/mount 有 usrquota。

Q4: 怎么快速定位谁占了磁盘？
A: df -h 找满的分区 → du -sh 逐层找大目录 → find 找大文件，三步定位。
```

## 面试题

```text
1. df 和 du 的区别？
   答：df 读 superblock 看分区整体用量，du 遍历目录累加看目录用量；有 deleted 文件时两者对不上。

2. 磁盘满和 inode 满有什么区别？
   答：磁盘满是空间用完（df -h 100%），inode 满是文件数用完（df -i 100%），后者多因海量小文件。

3. quota 的 soft 和 hard 限制？
   答：soft 软限制超了给宽限期（可恢复），hard 硬限制超了无法再写。

4. iostat 的 await 和 %util 说明什么？
   答：await 是平均 IO 等待时间（高=延迟大），%util 是设备繁忙度（近 100%=饱和）。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 排查磁盘满：先 df 看分区，再 du 逐层找目录，别瞎猜
2. 共享服务器（多用户）必须配 quota，防止单人占满磁盘
3. 识别设备用 lsblk -f，一次看全设备+文件系统+UUID+挂载点
4. 分析 IO 性能用 iostat -x，重点看 await 和 %util
5. 磁盘告警阈值建议 80% 提醒、90% 告警，别等 100% 才处理

### 踩坑记录

```text
坑 1：du 和 df 显示的用量对不上
结论：df 显示分区用了 80G，du 统计各目录加起来才 60G。
原因：有文件被删除但仍被进程占用（句柄没释放），df 算它们、du 不算。
解法：lsof +L1 找 deleted 文件，重启占用进程释放空间。

坑 2：df 显示磁盘没满但写文件报 no space
结论：df -h 看空间还有，但写文件报 No space left on device。
原因：inode 用完了（大量小文件），df -i 能看出来。
解法：df -i 查 inode 使用，删掉海量小文件释放 inode。

坑 3：quota 配了不生效
结论：edquota 设了配额，用户还是能超额写。
原因：挂载没加 usrquota 选项，或 quotaon 没启用。
解法：确认 fstab/mount 有 usrquota，quotacheck + quotaon 启用。

坑 4：iostat 命令不存在
结论：iostat: command not found。
原因：iostat 在 sysstat 包里，不是默认安装。
解法：apt install sysstat（Debian/Ubuntu）或 dnf install sysstat。

坑 5：只看 du -sh /* 没排除伪文件系统误判
结论：du -sh /* 里 /proc /sys /run 报错或显示 0，干扰判断。
原因：/proc /sys 是伪文件系统，du 统计它们无意义。
解法：du -sh 排除 /proc /sys /dev /run，或用 du -x 不跨文件系统。
```

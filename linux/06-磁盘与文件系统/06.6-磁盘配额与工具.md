## 概述

磁盘相关的运维工具分三类：配额（quota，限制每个用户/组能用多少空间）、查看（df/du/lsblk/blkid，看空间用了多少、设备是什么）、性能（iostat，看 IO 吞吐和延迟）。日常排查「磁盘满了」「谁占的空间」「IO 慢不慢」就靠这些工具。quota 管「防超额」，查看工具管「定位问题」，iostat 管「分析性能」。

```text
工具三分类：
1. quota —— 按用户/组限制磁盘空间和 inode 数，防止单人占满
2. df/du —— df 看分区用量、du 看目录用量，定位「谁占了空间」
3. lsblk/blkid —— lsblk 看设备树、blkid 看 UUID/文件系统类型
4. iostat —— IO 吞吐、延迟、利用率，分析磁盘性能
```

## 核心概念

quota 给每个用户/组设置磁盘空间（block）和文件数（inode）上限，防止单个用户占满整个磁盘（比如共享服务器上某用户狂存文件）。启用步骤：挂载选项加 usrquota/grpquota → quotacheck 建配额库 → edquota 设置配额 → quotaon 启用。分软限制（soft，超了宽限期告警）和硬限制（hard，硬上限）。

```shell
# 1. 挂载时启用 quota（fstab 加 usrquota,grpquota 选项）
mount -o remount,usrquota,grpquota /home
# 2. 初始化配额库
quotacheck -cug /home
# 3. 启用配额
quotaon /home
# 4. 设置用户配额（交互式编辑）
edquota -u alice
# 查看配额使用
repquota /home
```

```text
quota 关键概念：
1. block 配额 —— 限制占用的磁盘空间（KB/MB/GB）
2. inode 配额 —— 限制文件数量（防大量小文件）
3. soft 软限制 —— 超了给宽限期，期限内可恢复
4. hard 硬限制 —— 硬上限，超了无法再写
```

### quota 的四个维度：block / inode × soft / hard

- block（空间）：限制用户能占多少磁盘空间，单位 1K 块（或用 K/M/G 后缀）。
- inode（文件数）：限制用户能建多少个文件，专门防「海量小文件把 inode 耗尽」这种空间没满但写不进去的情况。
- soft（软限制）：超了允许继续写，但进入宽限期（grace period），期限内降到 soft 以下就没事，逾期则按 hard 处理。
- hard（硬限制）：真正的硬上限，一旦达到立即拒绝写入。

```text
soft / hard 的关系：
soft < hard。用户超 soft 但没超 hard 时还能写，靠宽限期缓冲；
超过宽限期（默认 7 天）还没降下来，soft 就升级成 hard，不能再写。
```

### ext4 的 quota 命令族 vs xfs 的 xfs_quota

ext 系列文件系统用传统的 quota 命令族（quotacheck/quotaon/edquota/setquota/repquota/quota）。xfs 文件系统不用这套，改用 `xfs_quota`（挂载选项是 uquota/gquota/pquota，不用 quotacheck 建库）。CentOS/RHEL 7+ 默认根分区是 xfs，所以「在 CentOS 上敲 quotacheck 没反应」是常见踩坑——xfs 要用 xfs_quota。

```text
ext4 vs xfs 配额工具对照：
ext4 —— 挂载 usrquota,grpquota + quotacheck + quotaon + edquota/setquota/repquota
xfs  —— 挂载 uquota,gquota,pquota + xfs_quota -x -c 'limit ...'（无需 quotacheck）
```

### df / du / lsblk / blkid / iostat 各管什么

```text
工具定位速记：
df    —— 分区（文件系统）级别：整块分区用了多少、剩多少
du    —— 目录级别：某个目录/文件占了多大空间
lsblk —— 设备树：磁盘→分区→挂载点 的层级关系
blkid —— 设备身份：UUID、LABEL、文件系统类型
iostat—— 设备 IO 性能：吞吐、IOPS、延迟、利用率
```

## 工作原理

quota 的原理是「内核统计 + 配额库存储」。启用 quota 后，内核按 uid/gid 统计每个用户的 block 和 inode 用量（写文件时实时计数），和配额库（aquota.user/aquota.group）里的限额比较，超 hard 限制就拒绝写入。df/du 的原理不同：df 读文件系统的超级块（superblock）统计整分区用量，du 遍历目录逐文件累加。iostat 读 /proc/diskstats 内核的 IO 统计。

```text
磁盘工具工作原理：
1. quota —— 内核按 uid/gid 实时计数 block/inode，超 hard 拒写
2. df —— 读 superblock 统计分区整体用量
3. du —— 遍历目录逐文件累加
4. iostat —— 读 /proc/diskstats 内核 IO 统计
```

### df 为什么能「秒出」、du 为什么慢

df 只读一次超级块（superblock）——文件系统挂载时就有块位图和 inode 位图的计数，直接报「总块数 - 已用块数」，O(1) 秒出。du 要遍历目录树、对每个文件做 stat 累加大小，文件越多越慢，大目录可能要几十秒。这也是两者性能差异的根源，以及「df 和 du 对不上」的部分原因（见故障排查）。

```text
df vs du 的原理差异：
df —— 读 superblock 的块计数，秒出，看「分区还剩多少」
du —— stat 遍历每个文件累加，慢，看「某个目录实际占多少」
```

### quota 的 project（目录级）配额

传统 quota 按用户/组限，xfs 还支持 project quota（prjquota）——按「项目/目录」限，比如把 /srv/project-a 划成一个 project，限制这个目录整体最多用多少空间，跟「哪个用户写的」无关。适合多租户目录隔离的场景。

```shell
# xfs project quota 简例
# 1. 挂载加 pquota
mount -o prjquota /dev/sdb1 /srv
# 2. 定义 project 和目录映射（/etc/projects + /etc/projid）
echo "100:/srv/project-a" >> /etc/projid
echo "/srv/project-a" >> /etc/projects
# 3. 设 project 限额
xfs_quota -x -c 'project -s 100' -c 'limit -p bhard=50g 100' /srv
```

## 常用命令与配置

df 看「分区级别」的用量（哪个分区满了），du 看「目录级别」的用量（哪个目录占了空间）。排查「磁盘满了」的标准流程：df -h 看哪个分区满 → du -sh 逐层找大目录 → 定位到大文件。df 看挂载点、du 看具体占用，两者配合才能定位到「谁吃了磁盘」。

```text
# 实测（df 看分区级别）
$ df -hT
/dev/sda2  ext4  915G  62G  808G   8%  /
/dev/sda1  vfat  1.1G 6.2M  1.1G   1%  /boot/efi
# 根分区 915G 用了 62G（8%），还健康
```

```shell
df -h                 # 分区用量（人类可读）
du -sh /var/*         # 各目录占用，定位大目录
du -sh /var/* | sort -rh | head    # 按大小排序找 TOP
df -i                 # 看 inode 使用（文件数，不是空间）
```

### df 常用选项

```shell
df -h                 # 人类可读（K/M/G）
df -T                 # 显示文件系统类型
df -i                 # inode 使用情况
df -x tmpfs -x devtmpfs    # 排除伪文件系统，只看真实磁盘
df --total            # 末尾加一行合计
```

### du 常用选项

```shell
du -sh /var           # 目录总大小（summary + human）
du -h --max-depth=1 /var   # 只统计一层子目录，逐层下钻
du -x -sh /           # -x 不跨文件系统（排除挂载点里的其它盘）
du -a /var | sort -rh | head   # 连文件一起排序，找最大的文件
```

lsblk 以树状显示块设备和分区（磁盘→分区→挂载点），一眼看清整机磁盘布局；blkid 显示每个设备的 UUID 和文件系统类型。lsblk -f 两者结合，一次输出「设备 + 文件系统 + UUID + 挂载点 + 用量」，是识别磁盘的万能命令。

```text
# 实测（lsblk -f 关键部分）
NAME   FSTYPE  LABEL      MOUNTPOINTS
sda
├─sda1 vfat               /boot/efi
└─sda2 ext4               /
sdb
├─sdb1 vfat    ESP
├─sdb3 ntfs    OS          # Windows 系统盘
├─sdb5 ntfs    Image
└─sdb6 ntfs    DELLSUPPORT
# 一眼看出：sda 是 Ubuntu（ext4），sdb 是 Windows（ntfs，双系统）
```

```shell
lsblk                 # 设备树
lsblk -f              # 设备 + 文件系统 + UUID + 挂载点
blkid                 # UUID 和文件系统类型
blkid /dev/sda2       # 查单个设备的 UUID
```

### blkid 精确取值

```shell
blkid /dev/sda2                 # 该设备的 UUID、TYPE、LABEL
blkid -s UUID /dev/sda2         # 只看 UUID 这个标签
blkid -o value -s UUID /dev/sda2   # 只输出 UUID 值（写 fstab 时有用）
lsblk -o NAME,SIZE,FSTYPE,UUID,MOUNTPOINT   # 自定义列
```

### quota 命令族

```shell
quotacheck -cug /home     # 建配额库（-c 建 -u 用户 -g 组）
quotaon /home             # 启用配额
quotaoff /home            # 停用配额
edquota -u alice          # 交互式编辑 alice 的配额
edquota -t                # 设置宽限期（grace period）
setquota -u alice 10G 11G 1000000 1100000 /home   # 非交互式设置
repquota /home            # 报告所有用户配额使用
quota -u alice            # 查 alice 的配额使用
```

```text
setquota 参数顺序（容易记混）：
setquota -u 用户 block软 block硬 inode软 inode硬 文件系统
例：setquota -u alice 10G 11G 1000000 1100000 /home
    → 空间软 10G/硬 11G，文件数软 100万/硬 110万
```

### xfs_quota 用法

```shell
# xfs 文件系统用 xfs_quota，交互式或 -c 传命令
xfs_quota -x -c 'report -h' /home        # 报告配额使用
xfs_quota -x -c 'limit bsoft=10g bhard=11g alice' /home   # 设空间配额
xfs_quota -x -c 'limit isoft=1000000 ihard=1100000 alice' /home   # 设文件数配额
xfs_quota -x -c 'timer -b 7days' /home   # 设宽限期
```

### iostat 用法

```shell
iostat                 # 概览（CPU + 设备）
iostat -x 1            # 每秒看扩展指标（吞吐/IOPS/await/%util）
iostat -x 1 5          # 每秒一次、共 5 次
iostat -d              # 只看设备、不看 CPU
iostat -p sda          # 只看 sda 这块盘（含分区）
iostat -m              # 以 MB 为单位（默认 KB）
```

## 配置文件解析

quota 的配置分三处：挂载选项（/etc/fstab 里分区加 usrquota,grpquota）、配额库文件（aquota.user/aquota.group，存各用户限额）、配额参数（宽限期，tunefs/ext4 用 edquota -t 设置）。df/du/lsblk 无配置文件（读内核信息），iostat 的配置在 /etc/default/sysstat（是否开机收集）。

```shell
# fstab 里启用 quota 的挂载选项
# /dev/sdb1 /home ext4 defaults,usrquota,grpquota 0 2
# 配额库文件（quotacheck 生成）
# /home/aquota.user   /home/aquota.group
edquota -t            # 设置宽限期（soft 超限后能撑多久）
```

```text
quota 配置三处：
1. fstab 挂载选项 —— usrquota/grpquota 启用配额
2. aquota.user/group —— 配额库，存各用户限额
3. 宽限期 —— edquota -t 设置，soft 超限后的缓冲期
```

```shell
# iostat（sysstat 包）的开机收集配置（用于历史趋势）
cat /etc/default/sysstat
# ENABLED="true" 表示开机启动数据收集，配合 sar 看历史 IO
```

## 应用场景实战

### 场景一：磁盘满了，定位是哪个目录吃掉的

```shell
# 1. 看哪个分区满
df -h
# 2. 对满的分区逐层找大目录
du -sh /var/* 2>/dev/null | sort -rh | head -10
# 3. 定位大文件
find /var -type f -size +100M -exec ls -lh {} \; 2>/dev/null
```

### 场景二：给共享服务器设磁盘配额防超额

```shell
# 1. 启用配额（fstab 挂载选项加 usrquota）
mount -o remount,usrquota /home
quotacheck -cum /home
quotaon /home
# 2. 给用户设 10G 空间 + 100 万文件配额
setquota -u alice 10G 11G 1000000 1100000 /home
# 3. 查看配额使用
repquota /home
```

### 场景三：用 iostat 定位磁盘 IO 瓶颈

```shell
# 1. 每秒刷新扩展指标，观察读写负载
iostat -x 1 5
# 2. 重点看 await（延迟）和 %util（繁忙度）
#    await 持续 > 20ms 说明 IO 延迟高；%util 接近 100% 说明磁盘饱和
# 3. 定位是哪个设备、哪个分区在扛 IO
iostat -x -p sda 1 5
# 4. 进一步找是哪个进程在猛打 IO
iotop -o
```

```text
排查结论速查：
await 高（>20ms）→ IO 延迟大，可能是磁盘慢或随机 IO 太多
%util ≈ 100%     → 传统机械盘说明饱和（SSD 要结合 await 和队列深度看）
r/s 或 w/s 高     → IOPS 压力大（大量小 IO）
rkB/s/wkB/s 高    → 吞吐压力大（大量顺序大 IO）
```

## 性能与调优

iostat 报告磁盘 IO 性能：吞吐（KB 读写/秒）、IOPS（每秒 IO 次数）、延迟（await）、利用率（%util）。排查「磁盘慢」就看这些指标——await 高说明 IO 延迟大、%util 接近 100% 说明磁盘饱和。iostat 来自 sysstat 包（`apt install sysstat`），`iostat -x 1` 每秒刷新看实时 IO。

```shell
iostat                 # 概览
iostat -x 1            # 每秒看扩展指标（吞吐/IOPS/await/%util）
iostat -p sda          # 看某块盘的 IO
```

```text
iostat 关键指标：
1. r/s w/s —— 每秒读写 IO 次数（IOPS）
2. rkB/s wkB/s —— 每秒读写吞吐（KB）
3. await —— 平均 IO 等待时间（延迟，高说明慢）
4. %util —— 设备繁忙度（接近 100% 说明磁盘饱和）
```

### iostat -x 完整指标逐列解读

```text
iostat -x 关键列含义：
rrqm/s wrqm/s —— 每秒合并的读写请求（合并越多，说明顺序性越好）
r/s w/s       —— 每秒实际读写请求数（IOPS）
rkB/s wkB/s   —— 每秒读写吞吐
r_await w_await —— 读/写平均延迟（ms），await = (r_await + w_await) 加权
aqu-sz        —— 平均队列深度（排队中的 IO 数）
rareq-sz wareq-sz —— 平均请求大小（KB），判断 IO 是顺序大块还是随机小块
%util         —— 设备繁忙时间占比
```

```text
几个容易误读的点：
1. %util=100% 对机械盘 = 饱和；对 SSD/NVMe（多队列并行）%util 高不代表真饱和，要看 await + 队列深度
2. svctm（服务时间）已被内核标记不可靠，别用它判断性能
3. await 高 ≠ 一定磁盘慢，也可能是队列堆叠（太多并发 IO 排队）
```

## 安全与权限

磁盘空间是共享资源，安全核心是「防止滥用」：quota 限制单人占满（共享服务器必须配）；df/du 排查时注意权限（du 统计没权限的目录会报错/遗漏）；磁盘告警阈值要提前设（80% 提醒、90% 告警），别等 100% 才处理。iostat 等监控工具要持续收集才能发现趋势。

```text
磁盘安全要点：
1. quota 防滥用 —— 共享服务器必配，防单人占满
2. du 权限 —— 统计时无权限目录会遗漏，root 跑才准
3. 告警阈值 —— 80% 提醒、90% 告警，别等 100%
4. 持续监控 —— iostat 持续收集，才能发现 IO 趋势
```

## 故障排查

### df 和 du 对不上

```shell
# 1. 对比 df 和 du
df -h / && du -sh /
# 2. 找被删除但没释放的文件（句柄没关）
lsof +L1 | head
# 3. 重启占用进程释放空间
```

### 写文件报 no space 但 df 显示有空间

```shell
# 1. 看 inode 使用
df -i
# 2. inode 用完（大量小文件），找小文件多的目录
find / -xdev -type f | awk -F/ '{print $2}' | sort | uniq -c | sort -rn | head
# 3. 删除海量小文件释放 inode
```

### quota 设了不生效 / 没启用

```shell
# 1. 确认挂载带没带 usrquota
mount | grep usrquota
# 2. 确认配额库存在、quotaon 已启用
ls -l /home/aquota.user
quotaon -p /home        # 打印配额启用状态
# 3. 都正常仍不生效，检查是否是 xfs（要用 xfs_quota）
df -T /home
```

### xfs 上跑 quota 命令没反应

```shell
# 1. 确认文件系统类型
df -T /home    # 显示 xfs
# 2. xfs 用 xfs_quota，不是 quotacheck/quotaon
mount -o remount,uquota /home
xfs_quota -x -c 'report -h' /home
```

## 常见问题

```text
Q1: df 和 du 为什么对不上？
A: 有文件被删除但仍被进程占用（句柄没释放），df 算它们、du 不算。用 lsof +L1 找。

Q2: 磁盘没满但写文件报 no space？
A: inode 用完了（大量小文件），df -i 能看出，删小文件释放 inode。

Q3: quota 配了为什么不生效？
A: 挂载没加 usrquota 选项，或 quotaon 没启用。确认 fstab/mount 有 usrquota。

Q4: 怎么快速定位谁占了磁盘？
A: df -h 找满的分区 → du -sh 逐层找大目录 → find 找大文件，三步定位。

Q5: xfs 文件系统怎么设配额？
A: 用 xfs_quota（挂载加 uquota/gquota），不用 quotacheck/quotaon 那套 ext 命令族。

Q6: iostat 的 %util 到 100% 就一定是磁盘饱和吗？
A: 机械盘基本是；SSD/NVMe 多队列并行，%util 高不代表饱和，要结合 await 和队列深度判断。

Q7: du 统计结果比实际少是怎么回事？
A: 统计的目录里有子目录没权限，du 会跳过并报 Permission denied，用 root 跑才完整准确。
```

## 面试题

```text
1. df 和 du 的区别？
   答：df 读 superblock 看分区整体用量，du 遍历目录累加看目录用量；有 deleted 文件时两者对不上。

2. 磁盘满和 inode 满有什么区别？
   答：磁盘满是空间用完（df -h 100%），inode 满是文件数用完（df -i 100%），后者多因海量小文件。

3. quota 的 soft 和 hard 限制？
   答：soft 软限制超了给宽限期（可恢复），hard 硬限制超了无法再写。

4. iostat 的 await 和 %util 说明什么？
   答：await 是平均 IO 等待时间（高=延迟大），%util 是设备繁忙度（近 100%=饱和）。

5. quota 的 block 和 inode 配额分别限制什么？
   答：block 限制磁盘空间，inode 限制文件数量，后者专门防海量小文件耗尽 inode。

6. 被删除的文件为什么还占空间（df 不降）？
   答：进程还开着文件的句柄，文件被 unlink 但 inode 没释放，df 仍计数；关闭进程或用 lsof +L1 找到后释放。

7. 为什么 du 统计目录比 df 慢很多？
   答：du 要遍历目录树对每个文件 stat 累加，文件多就慢；df 只读一次 superblock 的块计数，秒出。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 排查磁盘满：先 df 看分区，再 du 逐层找目录，别瞎猜
2. 共享服务器（多用户）必须配 quota，防止单人占满磁盘
3. 识别设备用 lsblk -f，一次看全设备+文件系统+UUID+挂载点
4. 分析 IO 性能用 iostat -x，重点看 await 和 %util
5. 磁盘告警阈值建议 80% 提醒、90% 告警，别等 100% 才处理
6. du 排查大目录时加 -x 不跨文件系统，排除挂载点干扰
7. xfs 文件系统用 xfs_quota，别在 xfs 上跑 ext 的 quota 命令族

### 踩坑记录

```text
坑 1：du 和 df 显示的用量对不上
结论：df 显示分区用了 80G，du 统计各目录加起来才 60G。
原因：有文件被删除但仍被进程占用（句柄没释放），df 算它们、du 不算。
解法：lsof +L1 找 deleted 文件，重启占用进程释放空间。

坑 2：df 显示磁盘没满但写文件报 no space
结论：df -h 看空间还有，但写文件报 No space left on device。
原因：inode 用完了（大量小文件），df -i 能看出来。
解法：df -i 查 inode 使用，删掉海量小文件释放 inode。

坑 3：quota 配了不生效
结论：edquota 设了配额，用户还是能超额写。
原因：挂载没加 usrquota 选项，或 quotaon 没启用。
解法：确认 fstab/mount 有 usrquota，quotacheck + quotaon 启用。

坑 4：iostat 命令不存在
结论：iostat: command not found。
原因：iostat 在 sysstat 包里，不是默认安装。
解法：apt install sysstat（Debian/Ubuntu）或 dnf install sysstat。

坑 5：只看 du -sh /* 没排除伪文件系统误判
结论：du -sh /* 里 /proc /sys /run 报错或显示 0，干扰判断。
原因：/proc /sys 是伪文件系统，du 统计它们无意义。
解法：du -sh 排除 /proc /sys /dev /run，或用 du -x 不跨文件系统。

坑 6：在 xfs 文件系统上跑 quotacheck/quotaon 没反应
结论：CentOS 根分区（xfs）上执行 quotaon 报错或配额不生效。
原因：xfs 不用 ext 的 quota 命令族，要用 xfs_quota + uquota/gquota 挂载选项。
解法：mount -o remount,uquota /home，再用 xfs_quota -x -c 'limit ...'。

坑 7：只看 %util=100% 就断定磁盘饱和
结论：NVMe SSD 上 %util 常年接近 100%，但实际延迟很低、远没饱和。
原因：SSD 多队列并行，%util 只反映「有 IO 在跑」的时间占比，不代表打满。
解法：结合 await（延迟）和 aqu-sz（队列深度）判断，别单看 %util。
```

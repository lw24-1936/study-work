## 概述

RAID（Redundant Array of Independent Disks，独立磁盘冗余阵列）把多块盘组合成一个逻辑盘，换取性能或数据冗余。分硬 RAID（硬件 RAID 卡）和软 RAID（软件 mdadm 实现）。核心是理解各 RAID 级别在「性能、容量、冗余」之间的取舍：RAID 0 快但无冗余、RAID 1 镜像、RAID 5/6 奇偶校验、RAID 10 镜像+条带。生产服务器常用 RAID 1 或 RAID 10。

```text
RAID 三要素权衡（性能 / 容量 / 冗余）：
1. RAID 0 条带 —— 性能翻倍，无冗余，一块坏全丢
2. RAID 1 镜像 —— 冗余（镜像），容量减半，读快写慢
3. RAID 5 单奇偶 —— 容忍 1 块坏，容量 N-1
4. RAID 6 双奇偶 —— 容忍 2 块坏，容量 N-2
5. RAID 10 镜像+条带 —— 性能+冗余都好，容量减半
```

## 核心概念

五个级别的核心区别在「数据怎么分布」和「能不能容忍盘坏」：RAID 0 把数据条带化分散到多盘（并行读写快，但无冗余、一块坏全丢）；RAID 1 全量镜像到第二块盘（坏一块数据还在）；RAID 5 用一块盘存奇偶校验（坏一块能从校验恢复）；RAID 6 两块校验（坏两块都能恢复）；RAID 10 先镜像再条带（性能和冗余兼得，但要 4 块盘）。

```text
各 RAID 级别对比（N 块盘）：
级别    最少盘数  可用容量   容错    特点
RAID 0   2        N          0 块    纯性能，无冗余
RAID 1   2        N/2        1 块    镜像，读快
RAID 5   3        N-1        1 块    性价比高
RAID 6   4        N-2        2 块    高容错
RAID 10  4        N/2        1-2 块  性能+冗余
```

硬 RAID vs 软 RAID：硬 RAID 用独立 RAID 卡（带缓存、CPU 不参与、性能好、成本高），软 RAID 用内核 md 模块 + mdadm（成本低、灵活，但占主机 CPU）。中小规模服务器用软 RAID 足够。

## 工作原理

RAID 的核心是「数据分布算法」。条带化（striping，RAID 0/5/6/10 都用）：数据按块（chunk）轮转写到多块盘，实现并行读写。镜像（mirroring，RAID 1/10）：同一份数据写两份。奇偶校验（parity，RAID 5/6）：用 XOR 运算——N 块数据盘 + 1 块校验盘，任意一块坏了能用剩下 N 块 XOR 反推出丢失的数据（RAID 5 单校验 XOR，RAID 6 用 Reed-Solomon 双校验，容两块）。

```text
RAID 数据分布算法：
1. 条带 striping —— 数据按 chunk 轮转写多盘，并行读写（性能来源）
2. 镜像 mirroring —— 同一数据写两份（冗余来源，RAID 1/10）
3. 奇偶校验 parity —— XOR 运算，坏一块用剩余盘反推（RAID 5/6）
4. 写惩罚 —— RAID 5 每次写要读旧数据+旧校验、算新校验再写，多几次 IO
```

## 常用命令与配置

mdadm 是 Linux 软 RAID 的管理工具，用普通磁盘（或分区）做 RAID，不需要硬件 RAID 卡。创建用 `mdadm --create`，查看状态用 `cat /proc/mdstat`，故障盘替换用 `mdadm --fail` + `--remove` + `--add`。

```shell
# 创建 RAID 1（两块盘镜像）
mdadm --create /dev/md0 --level=1 --raid-devices=2 /dev/sdb1 /dev/sdc1
# 格式化 + 挂载
mkfs.ext4 /dev/md0
mount /dev/md0 /data
# 查看 RAID 状态
cat /proc/mdstat
mdadm --detail /dev/md0
```

```shell
# 模拟盘坏并替换（容错演练）
mdadm --manage /dev/md0 --fail /dev/sdb1      # 标记盘坏
mdadm --manage /dev/md0 --remove /dev/sdb1    # 移除坏盘
mdadm --manage /dev/md0 --add /dev/sdd1       # 加新盘重建
cat /proc/mdstat                               # 观察重建进度
```

## 配置文件解析

mdadm 的配置文件是 /etc/mdadm/mdadm.conf：记录阵列（ARRAY 行）和备用盘（spare），开机时 mdadm 按它自动组装阵列。创建阵列后要 `mdadm --detail --scan >> mdadm.conf` 写入配置，并 update-initramfs -u 更新 initramfs，否则重启后阵列不会自动组装（/dev/md0 消失）。

```shell
# 把当前阵列写进配置（开机自动组装的关键）
mdadm --detail --scan >> /etc/mdadm/mdadm.conf
update-initramfs -u          # 更新 initramfs，让内核启动时能识别阵列
```

```text
# /etc/mdadm/mdadm.conf 关键行
ARRAY /dev/md0 metadata=1.2 name=host:0 UUID=xxxx:xxxx:xxxx
# ARRAY 行记录阵列的 UUID 和设备名，开机按它组装
```

## 应用场景实战

### 场景一：给数据库服务器做 RAID 10（性能 + 冗余）

```shell
# 4 块盘做 RAID 10
mdadm --create /dev/md0 --level=10 --raid-devices=4 /dev/sdb1 /dev/sdc1 /dev/sdd1 /dev/sde1
mkfs.xfs /dev/md0
echo "/dev/md0 /data xfs defaults 0 2" >> /etc/fstab
mount -a
cat /proc/mdstat
```

### 场景二：RAID 1 盘坏告警与替换流程

```shell
# 1. 发现盘坏（看 mdstat 或系统告警）
cat /proc/mdstat          # 显示 degraded 或盘标记 (F)
# 2. 移除坏盘、插入新盘重建
mdadm --manage /dev/md0 --remove /dev/sdb1
mdadm --manage /dev/md0 --add /dev/sdd1
# 3. 观察重建
watch cat /proc/mdstat    # 重建进度，完成后恢复正常
```

## 性能与调优

RAID 级别直接决定性能：读性能 RAID 0/10 最强（并行读），写性能 RAID 0/10 好、RAID 5/6 有「写惩罚」（每次写要多读旧数据+算校验）。所以写密集场景选 RAID 10（无写惩罚），读多写少才适合 RAID 5。软 RAID 还可以调 chunk size（条带块大小，大块适合顺序 IO、小块适合随机 IO）。

```text
RAID 性能要点：
1. 读性能 —— RAID 0/10 并行读最强，RAID 1 也能双读
2. 写惩罚 —— RAID 5/6 每次写多几次 IO，写密集别用
3. 选型 —— 写密集用 RAID 10，读多写少可用 RAID 5
4. chunk size —— 条带块大小，顺序 IO 用大块、随机 IO 用小块
```

## 安全与权限

RAID 最容易被误解的一点：RAID 是「冗余」不是「备份」——RAID 挡硬件故障（盘坏），挡不住误删、误改、中勒索病毒（这些操作会同步到所有盘）。安全要点：RAID 之外必须另有备份；mdadm 操作要 root；做 RAID 前确认盘名（--create 会清空数据）；重要阵列配置热备盘（spare）缩短降级窗口。

```text
RAID 安全要点：
1. RAID 不是备份 —— 防硬件故障，不防误删/误改/病毒，必须另有备份
2. 权限 —— mdadm 操作要 root
3. --create 会清空数据 —— 创建前 lsblk 确认盘名
4. 配热备盘 spare —— 坏盘自动顶上重建，缩短降级窗口
```

## 故障排查

### 盘坏降级（degraded）

```shell
# 1. 看阵列状态
cat /proc/mdstat          # [U_] 表示一块盘下线，degraded
mdadm --detail /dev/md0   # 看哪块盘 (F) 或 removed
# 2. 移除坏盘 + 加新盘重建
mdadm --manage /dev/md0 --remove /dev/sdb1
mdadm --manage /dev/md0 --add /dev/sdd1
# 3. 观察重建进度
cat /proc/mdstat
```

### 重启后 /dev/md0 消失

```shell
# 1. 看配置里有没有阵列记录
cat /etc/mdadm/mdadm.conf
# 2. 没记录就补上并更新 initramfs
mdadm --detail --scan >> /etc/mdadm/mdadm.conf
update-initramfs -u
# 3. 手动组装测试
mdadm --assemble --scan
```

## 常见问题

```text
Q1: RAID 5 和 RAID 10 怎么选？
A: 写密集/性能优先用 RAID 10（无写惩罚），读多写少、预算有限用 RAID 5（容量利用率高）。

Q2: RAID 能替代备份吗？
A: 不能。RAID 只防硬件故障，防不住误删、误改、病毒，必须另有备份。

Q3: 软 RAID 和硬 RAID 怎么选？
A: 硬 RAID 性能好（带缓存、不占 CPU）但贵；软 RAID 便宜灵活，中小规模够用，性能略逊。

Q4: RAID 5 坏一块盘还能用吗？
A: 能，降级运行（degraded），但必须尽快换盘重建，重建期间再坏一块就全丢。
```

## 面试题

```text
1. RAID 0、1、5、10 的区别？
   答：0 条带无冗余、1 镜像、5 单奇偶容 1 块、10 镜像+条带。可用容量分别 N、N/2、N-1、N/2。

2. RAID 5 的奇偶校验原理？
   答：用 XOR 运算，N 块数据盘算出一个校验值存校验盘，坏任意一块用剩余 N 块 XOR 反推出数据。

3. 为什么 RAID 5 有写惩罚？
   答：每次写要读旧数据 + 旧校验、算新校验、再写数据和校验，多几次 IO，所以写性能差。

4. RAID 和备份的区别？
   答：RAID 是实时冗余防硬件故障（删除会同步所有盘），备份是历史副本防逻辑错误/灾难，两者互补。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 生产关键数据用 RAID 1 或 RAID 10，别用 RAID 0（无冗余）存重要数据
2. RAID 只是「冗余」不是「备份」——RAID 挡不住误删、误改，必须另做备份
3. 软 RAID 定期 cat /proc/mdstat 检查状态，盘坏要第一时间替换
4. RAID 5 重建时压力大，大容量盘建议 RAID 6 或 RAID 10（防重建时第二块盘也坏）
5. 做 RAID 前先备份分区表和数据，mdadm --create 会清空数据

### 踩坑记录

```text
坑 1：把 RAID 当备份，误删文件后才发现恢复不了
结论：RAID 1 里 rm 删了文件，另一块盘上也没有了。
原因：RAID 是实时冗余，删除操作会同步到所有盘，挡不住逻辑错误。
解法：RAID 之外必须另有备份（异地/快照/离线），RAID 只防硬件故障。

坑 2：RAID 5 重建过程中第二块盘也坏了
结论：RAID 5 坏一块后重建，重建时又坏一块，数据全丢。
原因：重建要读所有盘、压力大，同批次的盘可能集中老化。
解法：大容量盘用 RAID 6（容 2 块）或 RAID 10，降低重建期风险。

坑 3：mdadm --create 用错了盘，数据被清空
结论：建 RAID 时盘名写错，把有数据的盘卷进去。
原因：--create 会初始化盘上的 RAID 元数据，覆盖原有数据。
解法：创建前 lsblk 确认盘名，备份数据，别把系统盘写进去。

坑 4：软 RAID 没配置开机自动组装，重启后 md0 消失
结论：重启后 /dev/md0 没了，挂载失败。
原因：mdadm 元数据没写进 mdadm.conf，开机不自动组装。
解法：mdadm --detail --scan >> /etc/mdadm/mdadm.conf，update-initramfs -u。

坑 5：RAID 5 写惩罚导致写性能差
结论：RAID 5 写入明显比 RAID 0/10 慢。
原因：每次写要读旧数据+旧校验、算新校验、再写，多几次 IO。
解法：对写密集场景选 RAID 10（无写惩罚），RAID 5 适合读多写少。
```

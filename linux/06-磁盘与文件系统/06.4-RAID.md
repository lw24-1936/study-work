## 概述

RAID（Redundant Array of Independent Disks，独立磁盘冗余阵列）把多块盘组合成一个逻辑盘，换取性能或数据冗余。分硬 RAID（硬件 RAID 卡）和软 RAID（软件 mdadm 实现）。核心是理解各 RAID 级别在「性能、容量、冗余」之间的取舍：RAID 0 快但无冗余、RAID 1 镜像、RAID 5/6 奇偶校验、RAID 10 镜像+条带。生产服务器常用 RAID 1 或 RAID 10。

```text
RAID 三要素权衡（性能 / 容量 / 冗余）：
1. RAID 0 条带 —— 性能翻倍，无冗余，一块坏全丢
2. RAID 1 镜像 —— 冗余（镜像），容量减半，读快写慢
3. RAID 5 单奇偶 —— 容忍 1 块坏，容量 N-1
4. RAID 6 双奇偶 —— 容忍 2 块坏，容量 N-2
5. RAID 10 镜像+条带 —— 性能+冗余都好，容量减半
```

## 核心概念

五个级别的核心区别在「数据怎么分布」和「能不能容忍盘坏」：RAID 0 把数据条带化分散到多盘（并行读写快，但无冗余、一块坏全丢）；RAID 1 全量镜像到第二块盘（坏一块数据还在）；RAID 5 用一块盘存奇偶校验（坏一块能从校验恢复）；RAID 6 两块校验（坏两块都能恢复）；RAID 10 先镜像再条带（性能和冗余兼得，但要 4 块盘）。

```text
各 RAID 级别对比（N 块盘）：
级别    最少盘数  可用容量   容错    特点
RAID 0   2        N          0 块    纯性能，无冗余
RAID 1   2        N/2        1 块    镜像，读快
RAID 5   3        N-1        1 块    性价比高
RAID 6   4        N-2        2 块    高容错
RAID 10  4        N/2        1-2 块  性能+冗余
```

硬 RAID vs 软 RAID：硬 RAID 用独立 RAID 卡（带缓存、CPU 不参与、性能好、成本高），软 RAID 用内核 md 模块 + mdadm（成本低、灵活，但占主机 CPU）。中小规模服务器用软 RAID 足够。

### RAID 0 —— 条带化，纯性能

是什么：把数据按 chunk（条带块）切成一段段，轮转写到所有盘上，最少 2 块盘，不做任何冗余。

为什么：读写可以并行打到 N 块盘，顺序带宽和 IOPS 近乎翻倍，是所有级别里性能上限最高的。

怎么用：适合性能优先、数据可重建或可丢失的场景——临时缓存盘、日志盘、视频剪辑的临时工作盘、无状态的数据中转。

边界/易错点：没有任何容错，任意一块盘坏则整个阵列数据全丢（而且丢得彻底，因为没有校验可恢复）。千万别用它存唯一数据。另外「快」主要体现在顺序带宽，随机小 IO 的提升远没想象中大。

```shell
# 创建 RAID 0（2 块盘条带，可用容量 = 2 块盘之和）
mdadm --create /dev/md0 --level=0 --raid-devices=2 /dev/sdb1 /dev/sdc1
```

### RAID 1 —— 镜像，冗余最简

是什么：同一份数据完整写到两块盘（互为镜像），最少 2 块盘，可用容量 = 单盘容量（N/2）。

为什么：坏任意一块盘数据完整无损，是最简单可靠的冗余；读可以同时从两块盘并发读，读性能反而提升。

怎么用：系统盘、数据库、小规模但「绝不能丢」的关键数据。两块盘就能上，成本最低的冗余方案。

边界/易错点：写性能没有提升（甚至略降，因为要写两份）；容量利用率只有 50%，成本高。是「冗余」不是「备份」——误删的文件在两块盘上会一起消失。

```shell
# 创建 RAID 1（2 块盘镜像，坏一块数据仍在）
mdadm --create /dev/md0 --level=1 --raid-devices=2 /dev/sdb1 /dev/sdc1
```

### RAID 5 —— 单奇偶校验，性价比之选

是什么：数据条带化 + 1 块盘存奇偶校验（parity），校验信息轮转分布到所有盘（不是固定一块校验盘），最少 3 块盘，可用容量 N-1。

为什么：用 1 块盘的代价换取「坏任意 1 块盘不丢数据」，在容量利用率和冗余之间性价比最高。

怎么用：读多写少、预算有限的场景——归档、文件服务器、备份存储。

边界/易错点：写有「写惩罚」（见工作原理），写密集场景性能差；坏 1 块后进入降级（degraded）状态，此时必须尽快换盘重建，重建期间再坏 1 块就全丢。大容量盘（≥4T）重建耗时长、期间风险高，更推荐 RAID 6。

```shell
# 创建 RAID 5（3 块盘，可用容量 = 2 块盘之和）
mdadm --create /dev/md0 --level=5 --raid-devices=3 /dev/sdb1 /dev/sdc1 /dev/sdd1
```

### RAID 6 —— 双奇偶校验，高容错

是什么：在 RAID 5 基础上加第二份独立的奇偶校验（P + Q），最少 4 块盘，可用容量 N-2，能同时坏 2 块盘不丢数据。

为什么：解决 RAID 5「重建期间再坏一块就全丢」的痛点——大容量盘重建动辄几十小时，期间再坏一块的概率不低，RAID 6 用 2 块校验盘把这个风险压下去。

怎么用：大容量盘、数据极其重要且不能接受重建期风险的场景——企业级 NAS、备份服务器、对象存储后端。

边界/易错点：写惩罚比 RAID 5 更重（每次写要算 2 份校验）；容量利用率更低（N-2）；重建时间也更长。

```shell
# 创建 RAID 6（4 块盘，可用容量 = 2 块盘之和，容 2 块坏）
mdadm --create /dev/md0 --level=6 --raid-devices=4 /dev/sdb1 /dev/sdc1 /dev/sdd1 /dev/sde1
```

### RAID 10（1+0）—— 镜像 + 条带，生产首选

是什么：先把盘两两做成镜像（RAID 1），再把多组镜像做成条带（RAID 0）。最少 4 块盘（且必须是偶数），可用容量 N/2。

为什么：同时拿到 RAID 0 的性能（条带并行）和 RAID 1 的冗余（镜像），且没有 RAID 5/6 的写惩罚——写密集型生产数据库的标配。

怎么用：数据库、虚拟化宿主机、高频读写的核心业务存储。

边界/易错点：容错能力是「每组镜像坏最多 1 块」，最坏情况下能坏 N/2 块（每组坏一块），但也可能坏在同一组导致数据丢失——所以说是「1-2 块」容错。容量利用率 50%，和 RAID 1 一样成本偏高。

```shell
# 创建 RAID 10（4 块盘，先镜像后条带）
mdadm --create /dev/md0 --level=10 --raid-devices=4 /dev/sdb1 /dev/sdc1 /dev/sdd1 /dev/sde1
```

## 工作原理

RAID 的核心是「数据分布算法」。条带化（striping，RAID 0/5/6/10 都用）：数据按块（chunk）轮转写到多块盘，实现并行读写。镜像（mirroring，RAID 1/10）：同一份数据写两份。奇偶校验（parity，RAID 5/6）：用 XOR 运算——N 块数据盘 + 1 块校验盘，任意一块坏了能用剩下 N 块 XOR 反推出丢失的数据（RAID 5 单校验 XOR，RAID 6 用 Reed-Solomon 双校验，容两块）。

```text
RAID 数据分布算法：
1. 条带 striping —— 数据按 chunk 轮转写多盘，并行读写（性能来源）
2. 镜像 mirroring —— 同一数据写两份（冗余来源，RAID 1/10）
3. 奇偶校验 parity —— XOR 运算，坏一块用剩余盘反推（RAID 5/6）
4. 写惩罚 —— RAID 5 每次写要读旧数据+旧校验、算新校验再写，多几次 IO
```

### 奇偶校验 XOR 反推的具体过程

RAID 5 的冗余本质上是「异或」运算的对称性：`A XOR B = P`，那么 `A = P XOR B`、`B = P XOR A`。任何一块数据盘坏，都能用「校验盘 + 剩下的数据盘」异或反推出来。

```text
RAID 5 奇偶校验 XOR 举例（2 数据盘 + 1 校验盘）：
数据盘 A = 1101，数据盘 B = 1011
校验盘 P = A XOR B = 0110

若 A 盘损坏，从 P 和 B 反推 A：
A = P XOR B = 0110 XOR 1011 = 1101（原数据恢复）
```

RAID 6 用了两份独立的校验（P 和 Q），Q 用 Galois 域上的 Reed-Solomon 编码（不是简单 XOR），所以坏两块也能分别反推。这也是 RAID 6 写惩罚更重的原因——每次写要重算两份校验。

### 写惩罚（write penalty）的 IO 次数

写惩罚只发生在「部分条带写」时（小块随机写，条带没写满）。此时 RAID 5 要先读旧数据和旧校验、算出新校验，再写新数据和新校验，一共 4 次 IO（对比单盘 1 次 IO，放大 4 倍）。整条条带写满（大块顺序写）时可以直接用新数据算出校验，没有惩罚。

```text
RAID 5/6 写惩罚对比（小随机写）：
RAID 5  —— 读旧数据 + 读旧 P + 写新数据 + 写新 P = 4 次 IO（放大 4 倍）
RAID 6  —— 读旧数据 + 读旧 P + 读旧 Q + 写新数据 + 写新 P + 写新 Q = 6 次 IO（放大 6 倍）
RAID 10 —— 镜像写两份 = 2 次 IO，无校验计算，所以写密集场景选它
```

### 重建（rebuild / resync）过程

盘坏后，阵列进入降级状态继续服务（读还能正常、性能下降）。换上新盘后，mdadm 开始重建：对 RAID 1/10 是从健康盘全量拷贝；对 RAID 5/6 是读所有剩余盘、逐条带重新计算校验和数据。重建要读满所有盘、压力极大，这也是「重建期间再坏一块」风险高的原因。软 RAID 可用 write-intent bitmap（写意图位图）在异常重启后跳过「全量重同步」，只补同步脏块，大幅缩短恢复时间。

```shell
# 查看重建进度
cat /proc/mdstat
# 输出里 [UU_] 的 _ 表示正在重建的那块，后面跟着百分比和速度
# 例：md0 : active raid1 sdd1[2] sdc1[1] sdb1[0]
#      1048576 blocks super 1.2 [2/1] [_U]  recovery = 43.2% (453120/1048576) finish=2.1min speed=7890K/sec
```

## 常用命令与配置

mdadm 是 Linux 软 RAID 的管理工具，用普通磁盘（或分区）做 RAID，不需要硬件 RAID 卡。创建用 `mdadm --create`，查看状态用 `cat /proc/mdstat`，故障盘替换用 `mdadm --fail` + `--remove` + `--add`。

```shell
# 创建 RAID 1（两块盘镜像）
mdadm --create /dev/md0 --level=1 --raid-devices=2 /dev/sdb1 /dev/sdc1
# 格式化 + 挂载
mkfs.ext4 /dev/md0
mount /dev/md0 /data
# 查看 RAID 状态
cat /proc/mdstat
mdadm --detail /dev/md0
```

```shell
# 模拟盘坏并替换（容错演练）
mdadm --manage /dev/md0 --fail /dev/sdb1      # 标记盘坏
mdadm --manage /dev/md0 --remove /dev/sdb1    # 移除坏盘
mdadm --manage /dev/md0 --add /dev/sdd1       # 加新盘重建
cat /proc/mdstat                               # 观察重建进度
```

### 创建阵列的完整参数

```shell
# 创建时常用选项
mdadm --create /dev/md0 \
  --level=10 \                 # RAID 级别：0/1/5/6/10
  --raid-devices=4 \           # 数据盘数量
  --spare-devices=1 \          # 热备盘数量（坏盘自动顶上）
  --chunk=512K \               # 条带块大小（默认 512K）
  --bitmap=internal \          # 写意图位图，异常重启后快速重同步
  /dev/sdb1 /dev/sdc1 /dev/sdd1 /dev/sde1 /dev/sdf1
```

```shell
# 查看与维护
mdadm --detail /dev/md0           # 阵列详细信息（盘状态、重建进度）
mdadm --examine /dev/sdb1         # 看单块盘上的 RAID 超级块（superblock）
mdadm --assemble --scan           # 按配置文件重新组装阵列
mdadm --stop /dev/md0             # 停止阵列（停用前先卸载挂载）
mdadm --zero-superblock /dev/sdb1 # 擦除盘上的 RAID 元数据（拆阵列后清理）
```

```shell
# 扩容（grow/reshape）：加盘把 RAID 5 从 3 盘扩到 4 盘
mdadm --add /dev/md0 /dev/sde1            # 先加为新盘
mdadm --grow --raid-devices=4 /dev/md0    # 再重塑阵列到 4 盘
# 之后还要扩展文件系统才能真正用上新增容量：
# resize2fs /dev/md0（ext4）或 xfs_growfs /mountpoint（xfs）
```

## 配置文件解析

mdadm 的配置文件是 /etc/mdadm/mdadm.conf：记录阵列（ARRAY 行）和备用盘（spare），开机时 mdadm 按它自动组装阵列。创建阵列后要 `mdadm --detail --scan >> mdadm.conf` 写入配置，并 update-initramfs -u 更新 initramfs，否则重启后阵列不会自动组装（/dev/md0 消失）。

```shell
# 把当前阵列写进配置（开机自动组装的关键）
mdadm --detail --scan >> /etc/mdadm/mdadm.conf
update-initramfs -u          # 更新 initramfs，让内核启动时能识别阵列
```

```text
# /etc/mdadm/mdadm.conf 关键行
DEVICE /dev/sd[b-e]1
# DEVICE 限定扫描哪些设备（默认扫描所有分区）
ARRAY /dev/md0 metadata=1.2 name=host:0 UUID=xxxx:xxxx:xxxx
# ARRAY 行记录阵列的 UUID 和设备名，开机按它组装
MAILADDR root
# 阵列异常时发邮件告警到 root（配合 mdadm 的 monitor 模式）
```

metadata 版本决定超级块的存放位置和阵列命名：

```text
mdadm 元数据（superblock）版本：
0.90 —— 老格式，超级块放盘末尾，设备名固定 /dev/md0，用于 /boot 老引导兼容
1.0 —— 超级块放盘末尾（兼容 0.90 位置），1.1 放盘开头，1.2（默认）放盘开头后 4K
1.x —— 阵列名出现在 /dev/md/ 下（如 /dev/md/host:0 或 /dev/md0）
```

## 应用场景实战

### 场景一：给数据库服务器做 RAID 10（性能 + 冗余）

```shell
# 4 块盘做 RAID 10
mdadm --create /dev/md0 --level=10 --raid-devices=4 /dev/sdb1 /dev/sdc1 /dev/sdd1 /dev/sde1
mkfs.xfs /dev/md0
echo "/dev/md0 /data xfs defaults 0 2" >> /etc/fstab
mount -a
cat /proc/mdstat
```

```text
选 RAID 10 而非 RAID 5 的原因：数据库是写密集 + 随机小块 IO，
RAID 5 的写惩罚会拖垮写入，RAID 10 镜像写两份无校验计算，写性能最好。
```

### 场景二：RAID 1 盘坏告警与替换流程

```shell
# 1. 发现盘坏（看 mdstat 或系统告警）
cat /proc/mdstat          # 显示 degraded 或盘标记 (F)
# 2. 移除坏盘、插入新盘重建
mdadm --manage /dev/md0 --remove /dev/sdb1
mdadm --manage /dev/md0 --add /dev/sdd1
# 3. 观察重建
watch cat /proc/mdstat    # 重建进度，完成后恢复正常
```

### 场景三：用 3 块盘搭 RAID 5 文件服务器 + 热备盘

```shell
# 3 块数据盘 + 1 块热备盘做 RAID 5
mdadm --create /dev/md0 --level=5 --raid-devices=3 \
  --spare-devices=1 /dev/sdb1 /dev/sdc1 /dev/sdd1 /dev/sde1
mkfs.ext4 /dev/md0
mkdir -p /srv/files
mount /dev/md0 /srv/files

# 持久化：写 mdadm.conf + fstab，重启后自动组装挂载
mdadm --detail --scan >> /etc/mdadm/mdadm.conf
update-initramfs -u
echo "/dev/md0 /srv/files ext4 defaults 0 2" >> /etc/fstab
```

```text
热备盘（spare）的作用：任一数据盘坏，mdadm 自动用 spare 顶替并开始重建，
把「降级窗口」缩到最短，运维不用半夜爬起来手动换盘。
```

## 性能与调优

RAID 级别直接决定性能：读性能 RAID 0/10 最强（并行读），写性能 RAID 0/10 好、RAID 5/6 有「写惩罚」（每次写要多读旧数据+算校验）。所以写密集场景选 RAID 10（无写惩罚），读多写少才适合 RAID 5。软 RAID 还可以调 chunk size（条带块大小，大块适合顺序 IO、小块适合随机 IO）。

```text
RAID 性能要点：
1. 读性能 —— RAID 0/10 并行读最强，RAID 1 也能双读
2. 写惩罚 —— RAID 5/6 每次写多几次 IO，写密集别用
3. 选型 —— 写密集用 RAID 10，读多写少可用 RAID 5
4. chunk size —— 条带块大小，顺序 IO 用大块、随机 IO 用小块
```

### chunk size 调优

chunk（条带块）是「一次连续写到单块盘的数据量」。顺序大 IO 用大 chunk（512K~1M）让每次 IO 尽量铺满单盘、减少跨盘寻址；随机小 IO 用小 chunk（64K~256K）让并发 IO 分散到更多盘、提高并行度。chunk 大小在建阵列时用 `--chunk` 定死，后期改要重塑（reshape）。

```shell
# 建阵列时指定 chunk（顺序大文件场景用 1M）
mdadm --create /dev/md0 --level=0 --raid-devices=2 --chunk=1M /dev/sdb1 /dev/sdc1
```

### 写意图位图（write-intent bitmap）与重建速度

write-intent bitmap 在阵列上记录「哪些块是脏的（写过没同步完）」。异常断电重启后，普通阵列要全量重同步（读满所有盘，几小时），有 bitmap 的阵列只补同步脏块（几分钟）。代价是正常运行时有轻微性能开销。

```shell
# 给已建阵列加写意图位图
mdadm --grow --bitmap=internal /dev/md0
# 去掉（省掉正常运行时的开销）
mdadm --grow --bitmap=none /dev/md0
```

重建/重同步速度可以用内核参数限速，避免重建把生产 IO 抢光：

```shell
# 重建速度下限/上限（KB/s），限制重建别打满磁盘
sysctl -w dev.raid.speed_limit_min=10000
sysctl -w dev.raid.speed_limit_max=100000
```

## 安全与权限

RAID 最容易被误解的一点：RAID 是「冗余」不是「备份」——RAID 挡硬件故障（盘坏），挡不住误删、误改、中勒索病毒（这些操作会同步到所有盘）。安全要点：RAID 之外必须另有备份；mdadm 操作要 root；做 RAID 前确认盘名（--create 会清空数据）；重要阵列配置热备盘（spare）缩短降级窗口。

```text
RAID 安全要点：
1. RAID 不是备份 —— 防硬件故障，不防误删/误改/病毒，必须另有备份
2. 权限 —— mdadm 操作要 root
3. --create 会清空数据 —— 创建前 lsblk 确认盘名
4. 配热备盘 spare —— 坏盘自动顶上重建，缩短降级窗口
```

### 阵列监控与告警

软 RAID 不会自动「大喊大叫」提醒你盘坏了，需要主动监控。常用手段：mdadm 的 monitor 模式（后台轮询，异常发邮件）、配合 MAILADDR 配置、或接入 Prometheus/监控系统的 node_exporter 采集 `/proc/mdstat`。生产上「盘坏了自己不知道，直到第二块也坏」是最常见的事故。

```shell
# mdadm monitor 模式：后台监控阵列，异常按 mdadm.conf 的 MAILADDR 发邮件
mdadm --monitor --daemonise --scan --syslog
# 立即手工检查所有阵列
cat /proc/mdstat
mdadm --detail --scan
```

## 故障排查

### 盘坏降级（degraded）

```shell
# 1. 看阵列状态
cat /proc/mdstat          # [U_] 表示一块盘下线，degraded
mdadm --detail /dev/md0   # 看哪块盘 (F) 或 removed
# 2. 移除坏盘 + 加新盘重建
mdadm --manage /dev/md0 --remove /dev/sdb1
mdadm --manage /dev/md0 --add /dev/sdd1
# 3. 观察重建进度
cat /proc/mdstat
```

### 重启后 /dev/md0 消失

```shell
# 1. 看配置里有没有阵列记录
cat /etc/mdadm/mdadm.conf
# 2. 没记录就补上并更新 initramfs
mdadm --detail --scan >> /etc/mdadm/mdadm.conf
update-initramfs -u
# 3. 手动组装测试
mdadm --assemble --scan
```

### 阵列组装失败（superblock 冲突 / 盘名漂移）

```shell
# 1. 报错信息常见：no superblock found / devices have different metadata
# 2. 逐块盘看超级块信息，确认 metadata 版本一致
mdadm --examine /dev/sdb1 /dev/sdc1
# 3. 指定盘和 metadata 版本强制组装（版本要跟 examine 结果一致）
mdadm --assemble /dev/md0 /dev/sdb1 /dev/sdc1 --metadata=1.2
# 4. 盘名漂移（sdb 变 sdc）用 UUID 组装更稳
mdadm --assemble /dev/md0 --uuid=xxxx:xxxx:xxxx:xxxx
```

### 重建慢或卡住

```shell
# 1. 看当前重建速度和进度
cat /proc/mdstat
# 2. 检查是否被 speed_limit 限速了
cat /proc/sys/dev/raid/speed_limit_min /proc/sys/dev/raid/speed_limit_max
# 3. 重建 IO 会打满磁盘，必要时避开业务高峰，或临时调高上限加速
```

## 常见问题

```text
Q1: RAID 5 和 RAID 10 怎么选？
A: 写密集/性能优先用 RAID 10（无写惩罚），读多写少、预算有限用 RAID 5（容量利用率高）。

Q2: RAID 能替代备份吗？
A: 不能。RAID 只防硬件故障，防不住误删、误改、病毒，必须另有备份。

Q3: 软 RAID 和硬 RAID 怎么选？
A: 硬 RAID 性能好（带缓存、不占 CPU）但贵；软 RAID 便宜灵活，中小规模够用，性能略逊。

Q4: RAID 5 坏一块盘还能用吗？
A: 能，降级运行（degraded），但必须尽快换盘重建，重建期间再坏一块就全丢。

Q5: RAID 10 到底能坏几块盘？
A: 每组镜像（两两一组）最多坏 1 块。最坏情况每组坏一块能扛 N/2 块，但同组坏两块就丢数据，所以说「1-2 块」容错，别理解成「随便坏两块都行」。

Q6: chunk size 该设多大？
A: 顺序大 IO（视频、备份）用大 chunk（512K~1M），随机小 IO（数据库）用小 chunk（64K~256K）。建阵列时定死，改要大动干戈。

Q7: 软 RAID 的 write-intent bitmap 有什么用？
A: 记录脏块，异常断电重启后只重同步脏块（几分钟）而不是全量重同步（几小时），代价是正常运行时轻微性能开销。
```

## 面试题

```text
1. RAID 0、1、5、6、10 的区别？
   答：0 条带无冗余、1 镜像、5 单奇偶容 1 块、6 双奇偶容 2 块、10 镜像+条带。可用容量分别 N、N/2、N-1、N-2、N/2。

2. RAID 5 的奇偶校验原理？
   答：用 XOR 运算，N 块数据盘算出一个校验值存校验盘，坏任意一块用剩余 N 块 XOR 反推出数据。

3. 为什么 RAID 5 有写惩罚？
   答：每次写要读旧数据 + 旧校验、算新校验、再写数据和校验，多几次 IO，所以写性能差。

4. RAID 和备份的区别？
   答：RAID 是实时冗余防硬件故障（删除会同步所有盘），备份是历史副本防逻辑错误/灾难，两者互补。

5. RAID 5 和 RAID 6 的核心差异是什么？
   答：校验份数不同——RAID 5 一份校验容 1 块坏，RAID 6 两份独立校验（P+Q，Reed-Solomon）容 2 块坏；RAID 6 写惩罚更重、容量利用率更低，但重建期更安全。

6. 重建（rebuild）期间的风险是什么？
   答：重建要读满所有剩余盘、压力大且耗时长；RAID 5 重建期间再坏一块数据全丢，所以大容量盘推荐 RAID 6 或 RAID 10。

7. mdadm 里 --spare-devices 是干什么的？
   答：配热备盘，任一数据盘坏时自动顶替并开始重建，缩短降级窗口，减少人工干预。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 生产关键数据用 RAID 1 或 RAID 10，别用 RAID 0（无冗余）存重要数据
2. RAID 只是「冗余」不是「备份」——RAID 挡不住误删、误改，必须另做备份
3. 软 RAID 定期 cat /proc/mdstat 检查状态，盘坏要第一时间替换
4. RAID 5 重建时压力大，大容量盘建议 RAID 6 或 RAID 10（防重建时第二块盘也坏）
5. 做 RAID 前先备份分区表和数据，mdadm --create 会清空数据
6. 重要阵列配热备盘（spare）+ write-intent bitmap，缩降级窗口、缩短异常恢复时间
7. 创建完阵列务必写 mdadm.conf + update-initramfs，否则重启阵列不自动组装

### 踩坑记录

```text
坑 1：把 RAID 当备份，误删文件后才发现恢复不了
结论：RAID 1 里 rm 删了文件，另一块盘上也没有了。
原因：RAID 是实时冗余，删除操作会同步到所有盘，挡不住逻辑错误。
解法：RAID 之外必须另有备份（异地/快照/离线），RAID 只防硬件故障。

坑 2：RAID 5 重建过程中第二块盘也坏了
结论：RAID 5 坏一块后重建，重建时又坏一块，数据全丢。
原因：重建要读所有盘、压力大，同批次的盘可能集中老化。
解法：大容量盘用 RAID 6（容 2 块）或 RAID 10，降低重建期风险。

坑 3：mdadm --create 用错了盘，数据被清空
结论：建 RAID 时盘名写错，把有数据的盘卷进去。
原因：--create 会初始化盘上的 RAID 元数据，覆盖原有数据。
解法：创建前 lsblk 确认盘名，备份数据，别把系统盘写进去。

坑 4：软 RAID 没配置开机自动组装，重启后 md0 消失
结论：重启后 /dev/md0 没了，挂载失败。
原因：mdadm 元数据没写进 mdadm.conf，开机不自动组装。
解法：mdadm --detail --scan >> /etc/mdadm/mdadm.conf，update-initramfs -u。

坑 5：RAID 5 写惩罚导致写性能差
结论：RAID 5 写入明显比 RAID 0/10 慢。
原因：每次写要读旧数据+旧校验、算新校验、再写，多几次 IO。
解法：对写密集场景选 RAID 10（无写惩罚），RAID 5 适合读多写少。

坑 6：把 RAID 10 当成「随便坏两块都安全」
结论：两块盘同时坏，但恰好是同一组镜像的两块，数据全丢。
原因：RAID 10 每组镜像最多容 1 块，同组坏两块没有冗余可恢复。
解法：理解 RAID 10 的容错是「每组最多坏 1 块」，关键数据仍要另做备份。

坑 7：盘坏了自己不知道，直到第二块也坏
结论：阵列降级运行了很久没人发现，第二块盘坏才暴露，数据丢失。
原因：软 RAID 不会主动告警，没配监控，cat /proc/mdstat 也没人看。
解法：配 mdadm --monitor + MAILADDR 告警，或接入监控系统采集 mdstat，盘坏立刻知道。
```

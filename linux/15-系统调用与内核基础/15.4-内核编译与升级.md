## 概述

内核是操作系统的核心，升级/编译内核属于「高级操作」。日常升级内核用包管理器（apt/dnf/yum，最安全），源码编译内核只在「需要定制功能（打补丁、裁剪模块、开启新特性、调试）」时做。核心知识点：内核源码获取（kernel.org 或发行版源码包）、版本命名与 LTS、配置（.config / make menuconfig）、编译安装（make -jN → modules_install → install → update-grub）、多内核并存与回滚（GRUB 菜单）、升级后第三方驱动重编（DKMS）。注意：编译内核耗时长（几十分钟到数小时）、风险高（配置错误可能起不来），非必要别折腾。

```text
内核编译 vs 升级：
1. 升级 —— 包管理器（apt/dnf/yum）装预编译内核包，安全简单，日常用这个
2. 编译 —— 从源码定制（裁剪/打补丁/新特性/学习），耗时长、风险高
3. 回滚 —— 多内核并存（/boot/vmlinuz-*），GRUB 菜单选旧内核启动
```

```text
什么时候必须源码编译：
1. 需要内核源码级补丁（厂商驱动、安全修复、性能 patch）
2. 发行版内核没开启你需要的功能（如特定文件系统、调度器选项）
3. 裁剪内核（嵌入式/最小化系统，减小体积和攻击面）
4. 学习内核：读源码、加调试输出、做实验
其余场景一律用包管理器升级
```

## 核心概念

### 内核源码与版本命名

Linux 内核版本号三段式：`主版本.次版本.修订号`，如 6.8.7。

```text
6 . 8 . 7
主   次   修订
主版本：大版本演进（5.x → 6.x）
次版本：功能演进；偶数（6.8）是稳定版线，奇数（6.9）是开发版线
修订号：bugfix / 安全修复
后缀：-rc1/-rc2 预发布候选，-stable 稳定分支
```

**LTS（Long Term Support）**：长期维护版本，官方维护数年（如 5.15、6.1、6.6、6.8、6.12），生产环境选 LTS；非 LTS 版本只维护约 3 个月。发行版内核另带发行版后缀：Ubuntu 的 `7.0.0-28-generic`（`-generic` 是 Ubuntu 的通用配置 flavor，还有 `-lowlatency`、`-realtime` 等 flavor），RHEL 的 `5.14.0-284.el9.x86_64`。

```text
# 实测（本机内核版本）
$ uname -r
7.0.0-28-generic
$ uname -a
Linux lw-Vostro-7580 7.0.0-28-generic #28~24.04.1-Ubuntu SMP PREEMPT_DYNAMIC
Wed Jul  1 15:50:57 UTC 2 x86_64 x86_64 x86_64 GNU/Linux
```

### 内核配置：.config 与 CONFIG_*

编译内核前必须配置：每个功能三个选项——编进内核（y）、编译成模块（m）、不要（n）。配置结果存在源码根目录的 `.config` 文件里：

```text
CONFIG_EXT4_FS=y         # 编进内核镜像（vmlinuz 里，开机即用）
CONFIG_NFS_FS=m          # 编译成模块（.ko 文件，需要时 modprobe 加载）
# CONFIG_QUOTA is not set   # 注释掉 = 该功能不编译
```

y 和 m 的取舍：**开机必须要用的（磁盘/根文件系统驱动、内存管理、调度器）编进内核 y**；可选功能（网络文件系统、杂项驱动）做成模块 m 减小内核镜像；用不到的 n。模块化的问题：模块在 initramfs 阶段也要能被加载，否则根文件系统挂不上（经典启动失败原因）。

### 多内核并存与 GRUB

每个安装的内核在 /boot 下有自己的 vmlinuz-<版本>、initrd.img-<版本>、System.map-<版本>、config-<版本>。GRUB 启动菜单列出所有内核，默认启动最新安装的，可手动选旧内核——这就是回滚的机制。**升级内核永远不会「替换」旧内核，而是「新增」一个**，旧内核保留到手动清理。

```text
# 实测（本机 /boot 两个内核并存，可随时回滚）
$ ls -l /boot/vmlinuz-*
-rw------- 1 root root 16742472  6月 23 23:11 /boot/vmlinuz-6.17.0-40-generic   # 旧
-rw------- 1 root root 17000840  7月  1 21:32 /boot/vmlinuz-7.0.0-28-generic    # 当前
```

### DKMS：动态内核模块支持

第三方驱动（NVIDIA、VirtualBox、ZFS、WireGuard 老版本等）是**针对特定内核版本编译的 .ko**，内核升级后旧模块不兼容（modprobe 报 invalid module format / Unknown symbol）。DKMS（Dynamic Kernel Module Support）解决这个问题：内核安装时触发 DKMS 钩子，自动为新内核重编译已注册的驱动模块。

```text
DKMS 工作流：
1. 安装驱动时用 dkms add/add 注册源码（如 dkms add -m nvidia -v 550.xx）
2. dkms install 编译并安装到 /lib/modules/<版本>/updates/dkms/
3. 之后每次安装新内核，postinst 钩子自动 dkms autoinstall 为新内核重编
```

### Red Hat 系差异速览

```text
Ubuntu/Debian（本机）                Red Hat 系（RHEL/CentOS/Rocky/Fedora）
apt update && apt upgrade           yum update kernel（只升内核） / dnf upgrade
linux-image-<版本> 包                kernel-<版本>.x86_64.rpm
update-grub                         grub2-mkconfig -o /boot/grub2/grub.cfg
/usr/lib/update-notifier            内核升级后重启提示（needs-restarting）
linux-modules-extra-* 包            kernel-modules-extra 包
apt source linux / apt-get source   yumdownloader --source kernel
dkms 包同名 dkms                    dkms 包同名（epel 里）
```

RHEL 系 `yum update kernel` **只升级内核不升级其他包**；装好后 grub2-mkconfig 重新生成引导菜单（有些版本 yum 自动执行，手动跑一遍更保险）。

## 工作原理

### 编译流水线：配置 → 编译 → 安装

```text
内核编译三步：
1. 配置：make menuconfig / olddefconfig / localmodconfig → 生成 .config
2. 编译：make -jN → 产出 vmlinuz（内核镜像）+ 一堆 .ko（模块）
3. 安装：make modules_install（模块 → /lib/modules/<版本>/）
        + make install（镜像/initrd/System.map → /boot + 更新 GRUB）
```

编译产出物：

```text
arch/x86/boot/bzImage      内核镜像（装到 /boot/vmlinuz-<版本>）
System.map                内核符号表（调试/解析 oops 用，运行时内核不读它）
.config                   本次编译配置（装到 /boot/config-<版本>）
/lib/modules/<版本>/      模块树（kernel/ 下按子系统分目录的 .ko）
Module.symvers            模块符号版本（编译外部模块时用）
```

### 从 .config 到镜像

Kbuild 系统读取 .config，把「y 项」编译进内核镜像（链接成 bzImage），把「m 项」编译成独立 .ko 模块文件。模块与内核存在**版本绑定**：.ko 里有 vermagic 字符串（版本号 + SMP/PREEMPT 等特性标记），加载时与运行内核比对，不一致拒绝加载——这就是「升级内核后旧模块全部失效」的机制来源，也是 DKMS 存在的意义。

### initramfs 与引导

内核镜像只包含 y 项功能。根文件系统所在的磁盘驱动、文件系统模块等如果是 m，内核启动早期根本没法挂根——所以有 initramfs（initrd）：一个包含「挂根所需最小模块和工具」的临时根文件系统，由 update-initramfs 根据 /etc/initramfs-tools/ 和模块树生成。启动顺序：

```text
BIOS/UEFI → GRUB（读 /boot/grub/grub.cfg）→ 加载 vmlinuz + initrd.img
→ 内核解压启动 → 挂 initramfs → 加载挂根所需模块 → 切换到真实根文件系统
→ 执行 /sbin/init（systemd）→ 开机流程继续
```

升级内核后 initramfs 重新生成（update-initramfs -c），如果 initramfs 生成失败或缺少模块，新内核就会「卡在挂根」。

### GRUB 多内核菜单机制

GRUB 扫描 /boot 下的 vmlinuz-*，为每个内核生成一个菜单项（Ubuntu 还按「发行版子菜单」收纳）。`update-grub`（Debian 系，= grub-mkconfig 的封装）读取 /etc/default/grub + /etc/grub.d/ 脚本重新生成 /boot/grub/grub.cfg。**修改 /etc/default/grub 后必须重新 update-grub 才生效**。

```text
# 实测（本机 /etc/default/grub 关键行）
GRUB_DEFAULT=0                    # 默认启动第一个菜单项（通常=最新内核）
GRUB_TIMEOUT_STYLE=hidden
GRUB_TIMEOUT=0                    # 菜单等待 0 秒（看不到菜单，回滚时开机按住 Shift/Esc）
GRUB_CMDLINE_LINUX_DEFAULT="quiet splash"   # 追加到所有内核的启动参数
# 实测（本机内核实际启动参数）
$ cat /proc/cmdline
BOOT_IMAGE=/boot/vmlinuz-7.0.0-28-generic root=UUID=93b40af2-6f5d-40e1-b057-593b6b7c7428
ro quiet splash vt.handoff=7
```

## 常用命令与配置

### 包管理器升级（日常路径）

```shell
# Ubuntu / Debian
apt update
apt list --upgradable | grep linux   # 看有没有内核更新
apt upgrade                           # 全部升级（含内核），或
apt install linux-image-generic       # 只升级内核到发行版最新
# 装完后 reboot，新内核自动成为 GRUB 默认项

# Red Hat 系
yum update kernel                     # 只更新内核包（RHEL 7/8）
dnf upgrade kernel                    # RHEL 9 / Fedora
grub2-mkconfig -o /boot/grub2/grub.cfg   # 重新生成引导菜单（保险起见）
reboot
```

### 查看与回滚相关命令

```shell
uname -r                  # 当前运行的内核版本
ls /boot/vmlinuz-*        # 已安装内核（多版本并存）
dpkg -l | grep linux-image    # Ubuntu 已装内核包
rpm -qa | grep ^kernel        # RHEL 已装内核包
apt remove linux-image-<版本> # 卸载旧内核（Ubuntu）
yum remove kernel-<版本>      # 卸载旧内核（RHEL）
update-grub                   # Debian 系重新生成 GRUB 菜单
grub2-mkconfig -o /boot/grub2/grub.cfg   # RHEL 系
```

### 源码编译完整命令链

```shell
# 1. 安装编译依赖（Ubuntu 24.04）
apt install build-essential libncurses-dev bison flex libssl-dev libelf-dev dwarves bc
# Red Hat 系：yum groupinstall "Development Tools" && yum install ncurses-devel
#            bison flex openssl-devel elfutils-libelf-devel bc dwarves

# 2. 获取源码（kernel.org 或发行版源码包）
wget https://cdn.kernel.org/pub/linux/kernel/v6.x/linux-6.8.12.tar.xz
tar xJf linux-6.8.12.tar.xz && cd linux-6.8.12
# 或 Debian 系发行版源码：apt source linux（需 deb-src 源）

# 3. 配置
make olddefconfig          # 基于当前内核配置生成（推荐起点）
make menuconfig            # 图形化微调（文本菜单界面）

# 4. 编译安装
make -j$(nproc)            # 并行编译（本机 8 核）
make modules_install       # 安装模块到 /lib/modules/<版本>/
make install               # 安装 vmlinuz/initrd/System.map 到 /boot 并更新 GRUB
reboot
```

```text
# 实测（本机编译环境）
$ nproc
8
$ gcc --version | head -1
gcc (Ubuntu 13.3.0-6ubuntu2~24.04.1) 13.3.0
$ make --version | head -1
GNU Make 4.3
$ dpkg -l build-essential | grep ^ii
build-essential 12.10ubuntu1
# 注意：libncurses-dev / bison / flex / libssl-dev / libelf-dev 本机未装
# —— 直接编译内核前必须先 apt install 补全（menuconfig 依赖 libncurses-dev）
```

## 配置文件解析

### .config：内核编译的「唯一真相」

配置结果保存在 .config，决定编译什么。配置文件逐项解析：

```text
# .config 片段（以文件系统为例）
CONFIG_EXT4_FS=y           # y = 编进内核（根文件系统用 ext4 必须 y）
CONFIG_BTRFS_FS=m          # m = 编译成模块（btrfs 需要时 modprobe）
# CONFIG_XFS_FS is not set # 注释 = 不启用（对应 n）
CONFIG_LOCALVERSION="-custom"   # 自定义版本后缀（uname -r 会显示 6.8.12-custom）
```

### 配置生成方式对比

```text
make defconfig        发行版/架构默认配置，通用但臃肿（不推荐当起点）
make olddefconfig     复用当前内核配置（/proc/config.gz 或已装内核 config-*），
                     新选项取默认值 —— 升级内核版本时的推荐起点
make oldconfig        同 olddefconfig，但新选项逐个交互询问
make localmodconfig   根据「当前加载的模块」裁剪配置：
                     只保留当前硬件/使用的功能，体积最小，但换硬件可能缺驱动
make menuconfig       图形化文本菜单（依赖 libncurses-dev），交互微调
make nconfig          更现代的 ncurses 界面
make xconfig / gconfig   Qt / GTK 图形界面（需装开发库，服务器一般不装）
```

**olddefconfig vs localmodconfig 的选择**：要「跟上新版本又不想重新配」用 olddefconfig（保真、稳妥）；要「裁剪到最小」用 localmodconfig（激进，机器上没有的硬件驱动全不要，换机器/加硬件会缺驱动）。生产服务器裁剪前想清楚：这台机器以后会不会加网卡/磁盘阵列。

### /boot 下的文件

```text
/boot/vmlinuz-<版本>        内核镜像（bzImage）
/boot/initrd.img-<版本>      initramfs（挂根所需的模块和工具）
/boot/System.map-<版本>      内核符号表（调试 oops 用）
/boot/config-<版本>          该内核的编译配置（排查功能缺失第一站）
/boot/grub/grub.cfg           GRUB 启动菜单（update-grub 生成，别手改）
```

```text
# 实测（本机 /boot 完整内容）
$ ls /boot/
config-6.17.0-40-generic   config-7.0.0-28-generic   efi   grub
initrd.img   initrd.img-6.17.0-14-generic   initrd.img-6.17.0-40-generic
initrd.img-7.0.0-28-generic   initrd.img.old   memtest86+ia32.bin
memtest86+ia32.efi   memtest86+x64.bin   memtest86+x64.efi
System.map-6.17.0-40-generic   System.map-7.0.0-28-generic
vmlinuz   vmlinuz-6.17.0-40-generic   vmlinuz-7.0.0-28-generic   vmlinuz.old
# vmlinuz / initrd.img / vmlinuz.old 是无版本号的符号链接，指向当前/上一个内核
```

### /etc/default/grub

```text
# /etc/default/grub（内核选择相关选项）
GRUB_DEFAULT=0            # 默认启动项：0 第一个（通常最新）；也可写 saved / 菜单标题
GRUB_DEFAULT=saved        # 记住上次选择（GRUB_SAVEDEFAULT=true 配合）
GRUB_TIMEOUT=5            # 菜单等待秒数（回滚操作需要 >0，否则看不到菜单）
GRUB_TIMEOUT_STYLE=menu   # hidden = 默认不显示菜单，按键才显示
GRUB_CMDLINE_LINUX_DEFAULT="quiet splash"  # 追加到所有内核的启动参数
# 改完必须 update-grub（Debian 系）/ grub2-mkconfig（RHEL 系）才生效
```

### Red Hat 系配置差异

```text
RHEL 的 grub2 配置文件：
/boot/grub2/grub.cfg        （BIOS 启动）
/boot/efi/EFI/redhat/grub.cfg （UEFI 启动）
/etc/default/grub           同左，但生成命令是 grub2-mkconfig -o /boot/grub2/grub.cfg
grub2-set-default 0         设置默认启动项
grubby --info=ALL           查看内核菜单项；grubby --set-default 内核路径 切默认内核
RHEL 9 的 /boot 下还有 loader/entries/（bls 风格菜单条目，grub2-mkconfig 自动生成）
```

## 应用场景实战

### 场景一：升级内核后回滚到旧内核

```shell
# 1. 升级前确认旧内核在（有退路）
ls /boot/vmlinuz-*
# 2. 升级内核（Ubuntu）
apt update && apt install linux-image-generic
reboot
# 3. 升级后验证新内核
uname -r
dmesg | grep -iE 'error|fail'      # 看新内核有无报错
# 4. 出问题回滚：重启 → GRUB 菜单（开机按住 Shift/Esc）
#    → 「Advanced options for Ubuntu」→ 选旧内核版本启动
uname -r                            # 确认已回滚
# 5. 稳定后清理有问题的内核
apt remove linux-image-<新版本> --purge
update-grub
```

### 场景二：源码定制编译（localmodconfig 精简内核）

以「当前硬件最小可用」为目标编译定制内核：

```shell
# 1. 依赖 + 源码
apt install build-essential libncurses-dev bison flex libssl-dev libelf-dev dwarves bc
wget https://cdn.kernel.org/pub/linux/kernel/v6.x/linux-6.8.12.tar.xz
tar xJf linux-6.8.12.tar.xz && cd linux-6.8.12
# 2. 配置：先 olddefconfig 保底，再 localmodconfig 裁剪
make olddefconfig
make localmodconfig        # 按当前加载模块裁剪，会交互确认未知项
make menuconfig            # 最后人工确认：磁盘/网卡驱动必须 y 或 m
# 3. 编译安装
make -j$(nproc)
make modules_install
make install
reboot
# 4. 验证
uname -r                   # 应显示新版本
ls /lib/modules/$(uname -r)/
```

### 场景三：升级内核后重编第三方驱动（DKMS）

```shell
# 场景：升级内核后 NVIDIA 驱动 / VirtualBox 内核模块加载失败
# 1. 确认驱动是否走 DKMS
dkms status
# 2. 手动触发重编（若系统没自动跑）
dkms autoinstall
# 或指定模块重编：
dkms build -m nvidia -v 550.120
dkms install -m nvidia -v 550.120
# 3. 验证模块与当前内核匹配
modinfo nvidia | head -5        # 看 vermagic 与 uname -r 是否一致
modprobe nvidia                 # 加载测试
# 4. 没走 DKMS 的老驱动：重装驱动包（apt install --reinstall xxx）
#    或重新执行官方驱动安装脚本（会为新内核重编）
```

### 场景四：清理旧内核（释放 /boot 空间）

```shell
# 1. 先确认当前内核，别删正在用的
uname -r
# 2. 列出已装内核包（Ubuntu）
dpkg -l | grep linux-image
# 3. 删掉不需要的旧内核（保留最近 1-2 个做回滚）
apt remove linux-image-6.17.0-40-generic linux-headers-6.17.0-40-generic
# 4. 重新生成 GRUB 菜单
update-grub
# 5. 确认 /boot 空间
df -h /boot
# RHEL 系：yum remove kernel-6.1.0-1.el9 或 dnf remove kernel-*
```

## 性能与调优

### 编译并行度与加速

```text
make -j$(nproc)          用满全部核（本机 8 核）；内存小（<8GB）用 -j4 防 OOM
make -j8 2>&1 | tee build.log   后台看进度（进度百分比在每行开头）
make -j8 V=1             显示完整编译命令（排查报错用）
ccache 缓存编译产物：export CC="ccache gcc"，重复编译/调试内核提速数倍
   （apt install ccache，/usr/lib/ccache 已在 PATH 时自动生效）
```

完整编译一个通用 x86_64 内核：8 核机器约 20-60 分钟（视配置），单核要 3-8 小时；localmodconfig 裁剪后能快很多。内存建议 ≥8GB，磁盘编译期占用 20-50GB（含模块树）。

### 内核运行参数优化（编译期选项）

```text
CONFIG_PREEMPT=y          抢占式内核（桌面/实时场景，延迟低）
CONFIG_PREEMPT_VOLUNTARY  自愿抢占（服务器默认，吞吐优先）
CONFIG_HZ_1000            时钟频率 1000Hz（交互/延迟敏感）
CONFIG_HZ_250             250Hz（服务器省电）
CONFIG_NO_HZ_FULL         全无时钟 tick（低延迟计算场景）
CONFIG_LOCALVERSION="-custom"  标识自定义内核
CONFIG_DEBUG_INFO=n       关 debug 符号减小体积（需要调试才开）
CONFIG_IKCONFIG_PROC=y    把配置导出到 /proc/config.gz（排查功能缺失）
```

选型建议：桌面/工作站用发行版内核（已针对交互优化）；服务器保持发行版默认配置；需要低延迟（音频、交易）考虑 -lowlatency/-realtime flavor 或 PREEMPT_FULL。

### 生产环境内核升级选型

```text
1. 生产选发行版官方内核（稳定 + 厂商补丁 + 安全更新及时），不追主线
2. 跳版本升级前查发行版生命周期：Ubuntu LTS 内核（hwe/ga）、RHEL 9.x 小版本
3. 先在测试环境复现业务，跑 3-7 天再上生产
4. 分批灰度：先升级低峰业务机器，再全量
5. 升级窗口留足回滚时间，回滚预案写在变更单里
```

## 安全与权限

### 源码与包来源

```text
1. 内核源码只从 kernel.org 官方或发行版官方源获取，校验 sha256 签名
2. 内核包只从发行版官方仓库装（apt/dnf），第三方源的内核包慎用
3. 内核是系统最敏感组件 —— 被植入后门等于整个系统沦陷
4. 生产环境启用 UEFI Secure Boot + 内核模块签名校验，防加载未签名恶意模块
```

### Secure Boot 与模块签名

```text
Secure Boot 开启时：
1. 内核镜像必须由受信密钥签名（发行版内核已签，可正常启动）
2. 自编译内核需要：自己生成密钥 → 用 sbsign 签名 bzImage，
   并把公钥注册进 MOK（mokutil --import）→ 重启 enroll
3. 第三方/自编模块同理：sign-file 用 MOK 密钥签名 .ko，
   否则加载报 "Required key not available"（module_sig_enforced）
4. Ubuntu 用 shim + MokManager；RHEL 类似（shimx64.efi）
```

```shell
# 检查 Secure Boot 状态
mokutil --sb-state            # SecureBoot enabled / disabled
# 检查内核是否强制模块签名
cat /proc/sys/kernel/modules_disabled   # 0 = 模块可用
dmesg | grep -i 'module verification'
```

### 权限与最小化

```text
1. 编译/安装内核必须 root —— 内核是最敏感组件，别用 sudo 跑来源不明的编译脚本
2. 生产环境只装需要的模块（localmodconfig/模块黑名单），减小攻击面
3. 卸载不用的内核版本（每个旧内核都是潜在漏洞面）
4. 升级后及时安装安全更新；内核安全修复（CVE）通常只能靠升级内核解决
5. 禁止生产环境直接源码编译主线内核（无发行版安全支持）
```

## 故障排查

### 案例一：升级内核后系统起不来（回滚流程）

```shell
# 现象：重启后卡在黑屏/内核 panic/无法挂载根文件系统
# 1. 重启进 GRUB（开机按住 Shift/Esc 调出菜单，或改 GRUB_TIMEOUT>0）
#    → Advanced options → 选旧内核启动
# 2. 旧内核里查新内核失败原因
journalctl -b -1 | grep -iE 'panic|fail|error'    # 看上一次启动日志
# 3. 如果能进新内核但报错，看 dmesg
dmesg | grep -iE 'panic|error|failed'
# 4. 确认是模块/驱动问题：initramfs 里缺模块
lsinitramfs /boot/initrd.img-<新版本> | grep -E 'ext4|xfs'   # 检查挂根模块
# 5. 重新生成 initramfs 后重试
update-initramfs -c -k <新版本>
# 6. 稳定后卸载问题内核
apt remove linux-image-<新版本> --purge && update-grub
```

### 案例二：编译报错（缺依赖/语法错误）

```shell
# 现象：make 中途报错，常见：
#   "No rule to make target" / 缺头文件 / "flex: command not found" / openssl 报错
# 1. 确认工具链完整（Ubuntu 全家桶）
apt install build-essential libncurses-dev bison flex libssl-dev libelf-dev dwarves bc
# RHEL 系：yum groupinstall "Development Tools" && yum install ncurses-devel bison flex
#          openssl-devel elfutils-libelf-devel bc dwarves
# 2. 确认磁盘空间（编译产物 20-50GB）
df -h
# 3. 确认源码完整（tar.xz 校验、解压没中断）
# 4. 增量修复：make clean 后重新 make（别在坏一半的产物上继续）
# 5. 看具体报错位置
make -j8 V=1 2>&1 | tail -50
```

### 案例三：initramfs 生成失败 / 挂根失败

```text
现象：安装新内核时 update-initramfs 报错，或启动卡在
     "Begin: Running /scripts/init-bottom" / 直接 kernel panic: VFS: Unable to mount root fs
原因：
1. initramfs 生成时缺工具/模块（update-initramfs 失败）
2. 自编译内核把磁盘驱动（SATA/NVMe）配成 m 但 initramfs 里没包含
3. root=UUID 与真实设备不符（换盘/克隆系统后常见）
4. /boot 空间不足，initrd.img 写不完整
排查：
lsinitramfs /boot/initrd.img-<版本> | grep -E 'ahci|nvme|ext4'   # 模块在不在
cat /proc/cmdline                          # 看 root= 参数
blkid | grep UUID                          # 对照 root UUID
df -h /boot                                # 空间是否够
解法：
update-initramfs -c -k <版本>              # 重新生成
# 配置把磁盘驱动改 y（编进内核）后重编译
# /boot 腾空间（清理旧内核）后重新生成 initramfs
```

### 案例四：升级后模块不匹配（modprobe 失败）

```shell
# 现象：升级内核后 dmesg 报 "disagrees about version of symbol" /
#       "Invalid module format" / "Required key not available"
# 1. 确认模块是给哪个内核编的
modinfo <模块名> | grep vermagic
uname -r
# 2. 版本不匹配 → 重装/重编驱动
#    DKMS 驱动：dkms status && dkms autoinstall
#    发行版驱动包：apt install --reinstall <驱动包>
# 3. 签名问题（Secure Boot）：用 MOK 密钥签模块，或 enroll 驱动厂商密钥
# 4. 内核模块目录里确认有没有对应版本
ls /lib/modules/$(uname -r)/kernel/drivers/
```

## 常见问题

```text
Q1: 升级内核后删了旧内核，新内核起不来没法回滚？
A: 升级后先验证新内核稳定（uname -r + dmesg + 业务跑几天），再清理旧内核。
   始终保留至少一个已知可用的旧内核，回滚是最后退路。

Q2: 编译内核要多大磁盘空间？多久？
A: 通用 x86_64 内核编译产物 20-50GB（源码 1.3GB + 构建产物 + 模块树）。
   时间：8 核约 20-60 分钟，单核 3-8 小时。编译前 df -h，/boot 也要留
   几百 MB（每个内核 vmlinuz+initrd 约 100-200MB）。

Q3: make menuconfig 配置错了导致内核起不来？
A: 别从零配：用 olddefconfig（基于当前内核配置）起步，只微调你要改的项。
   磁盘/根文件系统驱动（SATA/NVMe/ext4/xfs）必须 y 或确保进 initramfs。
   localmodconfig 裁剪后一定要人工确认网卡/磁盘驱动还在。

Q4: 升级内核后显卡/NVIDIA 驱动失效？
A: 驱动模块绑定内核版本。走 DKMS 的驱动会自动重编（dkms autoinstall）；
   不走的重新安装驱动包或官方安装脚本。装完确认 modinfo 的 vermagic
   和 uname -r 一致。

Q5: Secure Boot 开启时自编译内核起不来/模块加载失败？
A: 自编译内核需要签名：生成密钥对 → sbsign 签 bzImage → mokutil --import
   公钥 → 重启 enroll MOK。模块同样要 sign-file 签名，否则
   "Required key not available"。嫌麻烦可在 BIOS 关 Secure Boot（生产谨慎）。

Q6: /boot 空间不足怎么办？
A: 每个内核约 100-200MB，/boot 独立分区（500MB-1GB）容易满。
   清理：apt autoremove --purge 删旧内核 + 旧 headers，update-grub。
   根治：/boot 不独立分区（和 / 一起），或扩大分区。

Q7: 源码编译的内核能收到安全更新吗？
A: 不能。自编译内核没有发行版安全支持，CVE 修复要自己跟进（订阅
   linux-stable 邮件列表/公告）。生产环境想要安全更新就用发行版内核。

Q8: 编译时 make -jN 和内存有什么关系？
A: 每个编译任务吃几百 MB 内存，-j$(nproc) 在内存 <8GB 的机器上容易 OOM
   （编译进程被 kill）。内存小用 -j4/-j2，或加 swap。报
   "internal compiler error: Killed" 基本就是内存不够。

Q9: 升级内核需要更新 grub 吗？
A: Debian 系装内核包时 postinst 钩子会自动跑 update-initramfs 和
   update-grub；但手动改了 /etc/default/grub 或手动拷贝内核文件时
   要手动 update-grub / grub2-mkconfig。RHEL 系 yum 装完自动跑
   grub2-mkconfig，手动操作时记得跑。

Q10: 怎么让 GRUB 默认启动旧内核（临时切回）？
A: 单次：GRUB 菜单里选。永久：改 /etc/default/grub 的 GRUB_DEFAULT
   为菜单项序号或标题，update-grub。RHEL 用 grubby --set-default。
   建议用 GRUB_DEFAULT=saved + GRUB_SAVEDEFAULT=true，用 grub2-set-default
   动态控制默认项。
```

## 面试题

```text
1. 内核升级有哪些方式？各自适用场景？
   答：①包管理器（apt/dnf/yum）装发行版预编译内核 —— 安全简单、有安全支持，
   日常升级用它；②源码编译 —— 需要定制功能（打补丁、裁剪、新特性、学习），
   风险高、无安全支持；③订阅实时内核/第三方仓库（如 Ubuntu Pro 实时内核），
   特殊场景。生产默认走①。

2. 内核版本号怎么读？什么是 LTS？
   答：主.次.修订三段（如 6.8.12）：主版本大演进，次版本偶数稳定/奇数开发，
   修订号修 bug。LTS = 长期维护版本（如 5.15、6.1、6.6、6.8），官方维护
   数年以上，生产环境优先选；非 LTS 只维护约 3 个月。

3. 内核回滚是怎么实现的？
   答：多内核并存机制 —— 升级是「新增」不是「替换」，/boot 下每个内核有
   独立的 vmlinuz/initrd/System.map，GRUB 菜单列出所有内核；出问题在菜单
   选旧内核启动即可回滚。所以升级后别急着删旧内核。

4. 源码编译内核的完整流程？
   答：①装依赖（build-essential/libncurses-dev/bison/flex/libssl-dev/libelf-dev）；
   ②获取源码（kernel.org，校验签名）；③配置（make olddefconfig 起步 →
   make menuconfig 微调，生成 .config）；④编译 make -j$(nproc)；
   ⑤make modules_install 装模块；⑥make install 装镜像并更新 GRUB；
   ⑦reboot 验证。注意磁盘空间（20-50GB）和 /boot 空间。

5. 内核配置里的 y、m、n 有什么区别？怎么选？
   答：y = 编进内核镜像（开机即用，无需加载）；m = 编译成模块 .ko（需要时
   modprobe，可卸载）；n = 不编译。开机必须的（磁盘/根文件系统驱动、内存管理）
   选 y；可选功能选 m 减小镜像；用不到的选 n。磁盘驱动配错（m 但 initramfs
   没含）会导致挂根失败。

6. 升级内核后第三方驱动（NVIDIA 等）失效，怎么解决？
   答：驱动模块绑定内核版本（vermagic 校验），升级后旧 .ko 不兼容。
   用 DKMS 注册的驱动会在内核安装时自动为新内核重编（dkms autoinstall）；
   没走 DKMS 的重新安装驱动包/官方脚本。验证：modinfo 模块的 vermagic
   与 uname -r 一致。

7. localmodconfig 和 olddefconfig 有什么区别？
   答：olddefconfig 基于当前内核配置生成（保留原配置，新选项取默认），
   升级版本时的稳妥起点；localmodconfig 根据当前加载的模块裁剪配置，
   只保留本机使用的功能，体积最小但换硬件可能缺驱动。要稳用 olddefconfig，
   要小用 localmodconfig（之后人工确认磁盘/网卡驱动）。

8. Secure Boot 对自编译内核有什么影响？
   答：Secure Boot 开启时只启动受信签名内核。自编译内核需自签：生成密钥 →
   sbsign 签 bzImage → mokutil --import 注册公钥 → 重启 enroll MOK；
   第三方模块也要用同一密钥 sign-file 签名，否则报 "Required key not
   available"。发行版内核已签名，可直接启动。

9. initramfs 是干什么的？为什么升级内核要重新生成？
   答：initramfs 是临时根文件系统，包含挂载真实根文件系统所需的最小模块
   （磁盘驱动、文件系统）和工具。内核启动早期用它挂根，再切换到真实根。
   新内核模块树不同，initramfs 必须重新生成（update-initramfs -c），
   否则启动卡在挂根。升级后 update-initramfs 失败要立刻处理。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 日常升级内核用包管理器，别源码编译（编译慢、无安全支持、风险高）
2. 升级后保留旧内核至少 1-2 个版本，稳定运行几天再清理
3. 源码编译从 make olddefconfig 起步，别从零配置，关键驱动（磁盘/网卡）别关
4. 编译前确认磁盘（20-50GB）、/boot 空间和内存（≥8GB），缺依赖先补齐
5. 生产环境先在测试机验证新内核（跑业务 3-7 天），再灰度上线
6. 升级窗口留足回滚时间，回滚步骤写进变更单，先在测试机演练一遍
7. 第三方驱动优先用 DKMS 版（自动适配新内核），别手动拷 .ko
8. Secure Boot 环境提前规划签名（MOK），别等装完才发现模块加载不了
9. 自编译内核要自己跟进安全更新（订阅 stable 公告），生产慎用
10. 卸载旧内核前 uname -r 确认不是当前内核，删完 update-grub 验证菜单
11. 编译加日志（make -j8 2>&1 | tee build.log），报错有据可查
12. 内核升级后检查 dmesg 和 journalctl，确认无驱动报错再交回生产

### 踩坑记录

```text
坑 1：升级内核后删了旧内核，新内核起不来没法回滚
结论：升级 + 清理旧内核，新内核 panic 进不去系统，又没有旧内核可回滚。
原因：删了唯一的回滚退路，GRUB 菜单只剩坏内核。
解法：升级后验证新内核稳定（至少几天）再清理；始终保留最近 1-2 个旧内核。

坑 2：编译内核磁盘空间不够，编到一半报错
结论：make 到一半报磁盘满 / "No space left on device"。
原因：内核编译产物巨大（源码 1.3GB + 构建 + 模块树，总共 20-50GB），/boot 独立分区也容易满。
解法：编译前 df -h 确认空间，/boot 留 1GB 以上；清理旧内核腾空间；编译目录别放 /tmp（tmpfs 重启清空）。

坑 3：make menuconfig 裁剪太狠，编译出的内核起不来
结论：新内核启动直接 panic: Unable to mount root fs。
原因：menuconfig/localmodconfig 关掉了磁盘或根文件系统驱动，或驱动做成 m 但 initramfs 里没包含。
解法：olddefconfig 起步只微调；磁盘（ahci/nvme）、根文件系统（ext4/xfs）必须 y；localmodconfig 后人工确认驱动；必要时 update-initramfs -c。

坑 4：升级内核后 NVIDIA/网卡驱动模块失效
结论：升级后 dmesg 报 "disagrees about version of symbol" / "Invalid module format"，显卡/网卡不可用。
原因：驱动 .ko 绑定内核版本（vermagic 校验），旧模块进不了新内核。
解法：用 DKMS 驱动（dkms autoinstall 自动重编）；非 DKMS 驱动重装驱动包；验证 modinfo 的 vermagic 与 uname -r 一致。

坑 5：源码编译时间太长，编到一半被 OOM 杀掉
结论：make 报 "internal compiler error: Killed"，编译中断。
原因：-j$(nproc) 并行任务太多，内存（<8GB）被吃满，编译进程被杀。
解法：内存小用 make -j4/-j2；加 swap；或减并行度 + ccache。

坑 6：升级后 /boot 空间不足，update-initramfs 失败
结论：升级内核时报 update-initramfs failed，新内核没有完整 initrd.img。
原因：/boot 独立分区被多个旧内核占满（每个 100-200MB）。
解法：apt autoremove --purge 清理旧内核 + headers，update-grub；之后 monitor /boot 使用率，或不再独立分区 /boot。

坑 7：手动改了 /etc/default/grub 忘了 update-grub
结论：改了 GRUB_TIMEOUT / GRUB_DEFAULT，重启后不生效。
原因：grub.cfg 是 update-grub 生成的快照，改 default/grub 不会自动生效。
解法：Debian 系 update-grub；RHEL 系 grub2-mkconfig -o /boot/grub2/grub.cfg（或 /boot/efi/EFI/redhat/grub.cfg）；RHEL9 检查 loader/entries/。

坑 8：GRUB_TIMEOUT=0 看不到菜单，回滚时进不了 GRUB
结论：新内核起不来，开机却直接进 recovery/黑屏，按 Shift 没反应。
原因：GRUB_TIMEOUT=0 + hidden 时菜单一闪而过，键盘来不及。
解法：开机连按 Shift/Esc（BIOS 用 Shift，UEFI 用 Esc 或连按）；或提前在 /etc/default/grub 设 GRUB_TIMEOUT=5 方便回滚；极端情况用 Live USB 挂载 chroot 改配置。

坑 9：Secure Boot 开启，自编译内核/模块加载失败
结论：自编译内核无法启动，或模块报 "Required key not available"。
原因：Secure Boot 只加载受信签名内核/模块，自编译的没签名。
解法：生成密钥 → sbsign 签 bzImage → mokutil --import → 重启 enroll MOK；模块用 sign-file 签同一密钥；或 BIOS 关 Secure Boot（生产谨慎评估）。

坑 10：apt 卸载内核时把当前内核一起删了
结论：apt remove 手滑删了正在运行的内核，系统失去当前内核包。
原因：没先 uname -r 确认，或依赖关系导致 kernel 元包被连带删除。
解法：删前 uname -r + dpkg -l | grep linux-image 双确认；误删后马上 apt install 对应版本；运行中内核被删重启就可能起不来。

坑 11：localmodconfig 换机器后缺驱动
结论：定制内核在另一台机器（新网卡/新磁盘阵列）起不来或没网。
原因：localmodconfig 按「当前机器加载的模块」裁剪，新硬件驱动被裁掉了。
解法：裁剪前列出可能硬件（网卡/RAID/虚拟化），确认对应 CONFIG_* 保留；裁剪内核只用于固定硬件环境，通用部署用发行版内核。

坑 12：自编译内核没有安全更新，出了 CVE 没人管
结论：线上跑着自编译内核，爆出内核 CVE 才发现没有补丁来源。
原因：自编译内核脱离发行版安全支持体系。
解法：生产用发行版内核（apt/dnf 自动安全更新）；自编译只用于实验/特殊定制环境，并订阅 linux-stable 安全公告手动跟进。
```

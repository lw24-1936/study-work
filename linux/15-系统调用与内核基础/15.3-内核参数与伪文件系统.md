## 概述

内核参数和伪文件系统是「和内核交互的接口」：sysctl 读写内核运行参数（不用重启内核就能调优），/proc 和 /sys 是内核暴露的伪文件系统（虚拟文件，反映和控制系统状态）。内核调优（TCP 参数、内存水位、转发开关、文件句柄上限）都通过 sysctl 或直接写 /proc/sys 完成。理解这些接口，才能「改内核行为」而不重新编译内核。

用户态访问内核有三层接口：

```text
内核接口三件套：
1. 系统调用（syscall） —— 编程接口，程序调用的（open/read/write…）
2. sysctl 内核参数     —— 运行时配置接口，sysctl -w 改、sysctl -a 看
3. 伪文件系统          —— 数据接口：/proc（进程与系统信息）、/sys（设备与内核对象）
```

三者关系：sysctl 只是 /proc/sys 的封装（点号路径 ↔ 目录层级），/proc 和 /sys 是内核向用户态暴露状态和配置的「窗口」。运维调优的大头（网络栈、内存水位、转发开关）几乎全落在 sysctl 参数上，而排查问题（CPU、内存、进程、设备）主要靠读 /proc 和 /sys。

```text
# 实测（本机 Ubuntu 24.04，内核 7.0.0-28-generic）
$ sysctl kernel.hostname kernel.ostype kernel.osrelease
kernel.hostname = lw-Vostro-7580
kernel.ostype = Linux
kernel.osrelease = 7.0.0-28-generic
$ sysctl -a | wc -l
3302
# 本机有 3302 个内核参数可调（内核版本不同，参数数量不同）
```

## 核心概念

### sysctl 与内核参数

sysctl 是读写内核运行参数的接口：`sysctl -a` 查看全部，`sysctl 参数名` 查看单个，`sysctl -w 参数=值` 临时修改（立即生效、重启失效），写入配置文件后 `sysctl -p` / `sysctl --system` 加载实现持久化。参数按「点分层级」组织，底层就是 /proc/sys 目录树。

```text
sysctl 参数五大类（顶层命名空间）：
kernel.*   内核行为（hostname、pid_max、panic、sysrq）
vm.*       虚拟内存（swappiness、overcommit、dirty 水位）
net.*      网络栈（core、ipv4、ipv6、bridge）
fs.*       文件系统（file-max、aio-max-nr、inotify）
dev.*      设备（cdrom、scsi 等）
```

### /proc 伪文件系统（procfs）

/proc 挂载在内存中的伪文件系统（无对应磁盘），文件内容由内核「按需生成」。两类内容：一是系统信息（/proc/cpuinfo、/proc/meminfo、/proc/loadavg、/proc/uptime、/proc/version、/proc/filesystems、/proc/mounts、/proc/cmdline、/proc/sys 内核参数），二是每个进程一个目录 /proc/<PID>/（status、cmdline、environ、fd、maps、stat、io、limits、cwd、exe 等）。文件大小几乎都为 0，`cat` 时才动态生成内容。

```text
# 实测（本机 /proc 根目录）
$ ls /proc/ | head
1  10  100  1007441  1007465  1007507  ...   # 每个数字 = 一个进程的目录（PID）
# 非数字项是系统信息文件：cpuinfo meminfo loadavg uptime version mounts ...
```

### /sys 伪文件系统（sysfs）

/sys（sysfs）由内核 2.6 引入，基于设备模型（kobject）暴露「设备与内核对象」：/sys/block 块设备、/sys/class 按功能分类的设备（net、block、thermal、power 等）、/sys/devices 设备树、/sys/module 已加载模块、/sys/kernel 内核对象、/sys/firmware 固件信息。与 /proc 的区别：/proc 偏「进程和系统运行状态」，/sys 偏「设备和内核对象」；/sys 的目录层级是真实设备模型的投影（如 /sys/class/net/eth0/ 下是 address、speed、operstate、mtu 等设备属性文件）。

```text
# 实测（本机 /sys 顶层）
$ ls /sys/
block  bus  class  dev  devices  firmware  fs  hypervisor  kernel  module  power
```

### 参数持久化与生效方式

内核参数的三种生效方式：

```text
1. 临时生效：sysctl -w 参数=值  或  echo 值 > /proc/sys/路径 —— 立即生效，重启丢失
2. 持久生效：写 /etc/sysctl.conf 或 /etc/sysctl.d/*.conf，再 sysctl -p 加载 —— 重启保留
3. 启动参数：内核 cmdline（/etc/default/grub 的 GRUB_CMDLINE_LINUX），
   部分参数（如 kernel.panic、quiet）可走启动参数，开机即生效
```

经验法则：先 `sysctl -w` 临时改并观察验证，确认无误再写入配置文件持久化。

### Red Hat 系差异速览

```text
Ubuntu/Debian（本机）          Red Hat 系（RHEL/CentOS/Rocky/Fedora）
/etc/sysctl.conf              /etc/sysctl.conf（同样存在）
/etc/sysctl.d/*.conf          同左，另多一层 /usr/lib/sysctl.d/（发行版默认值）
sysctl -p                     同左
update-grub                   用 grub2-mkconfig -o /boot/grub2/grub.cfg
sysctl 命令包 procps           包 procps-ng
```

Red Hat 系加载顺序（systemd-sysctl 按字典序）：/usr/lib/sysctl.d/（发行版默认）→ /etc/sysctl.d/（管理员）→ /etc/sysctl.conf，**后面的覆盖前面的（最后写入生效）**。Ubuntu/Debian 没有 /usr/lib/sysctl.d/ 这一层（systemd 包里虽有目录但基本为空），规则同理：/etc/sysctl.d/*.conf 覆盖 /etc/sysctl.conf。

## 工作原理

### sysctl 与 /proc/sys 的映射

sysctl 参数名中的点号就是 /proc/sys 下的目录层级：`net.ipv4.ip_forward` 对应 `/proc/sys/net/ipv4/ip_forward` 这个文件。sysctl 命令只是把这个路径翻译成「点分命名」并自动处理格式（读时去空格、写时加换行）。两者完全等价：

```text
sysctl net.ipv4.ip_forward        ≡   cat /proc/sys/net/ipv4/ip_forward
sysctl -w net.ipv4.ip_forward=1   ≡   echo 1 > /proc/sys/net/ipv4/ip_forward
点号（net.ipv4.ip_forward） ↔ 目录层级（net/ipv4/ip_forward）
```

```text
# 实测（本机两个入口读同一个参数，结果一致）
$ sysctl net.ipv4.ip_forward
net.ipv4.ip_forward = 1
$ cat /proc/sys/net/ipv4/ip_forward
1
```

### procfs：读取时动态生成

/proc 是伪文件系统，文件元数据（大小）为 0，inode 不占磁盘。每次 open/read 都会调用内核中对应的回调函数（proc_ops），由内核现场生成内容。因此：

- `cat /proc/meminfo` 两次看到的内存数字不同（内存实时变化）；
- /proc 下的文件不是「存档」，读到的永远是当前状态；
- 写入 /proc/sys/xxx 时，内核解析值并立即修改对应内核变量，不需要任何守护进程参与。

### sysfs：设备模型的投影

/sys 是内核设备模型的用户态视图。内核里每个设备/驱动/总线都对应一个 kobject，注册进 sysfs 后在 /sys 下生成目录；属性文件（attribute）对应 kobject 的 show/store 方法。例：/sys/class/net/enp59s0/speed 的 show 回调实时返回网卡协商速率，往 /sys/class/net/.../ 某些可写属性写值则调用 store 回调修改设备配置（如 /sys/class/backlight/*/brightness 调屏幕亮度）。**/sys 的目录结构是设备模型的「真实投影」，不是随便造的目录**。

```text
# 实测（本机 /sys/class/net/ 的网卡属性，lo 没有 device 链接 —— 虚拟设备无物理设备）
$ ls /sys/class/net/
br-3b8a83784ecf  br-426e2d2c7b6e  docker0  enp59s0  lo  tailscale0  veth053fb36 ...
$ cat /sys/class/net/enp59s0/speed /sys/class/net/enp59s0/operstate
-1                 # speed -1 = 未协商（接口 down）
down
$ cat /sys/class/net/enp59s0/address
54:bf:64:06:4d:7b  # MAC 地址
```

### 开机加载顺序：systemd-sysctl

现代发行版（Ubuntu 16.04+ / RHEL 7+）由 systemd 的 systemd-sysctl.service 在开机时按字典序加载配置：

```text
1. /usr/lib/sysctl.d/*.conf   （发行版/软件包默认值，RHEL 系存在）
2. /etc/sysctl.d/*.conf       （管理员配置，目录按文件名排序，如 10-*.conf < 99-*.conf）
3. /etc/sysctl.conf           （传统单文件，最后加载）
后面读取的值覆盖前面 —— 「最后写入生效」
```

这也解释了为什么网上的教程喜欢用 `99-*.conf` 命名：数字最大，加载最晚，优先级最高。

## 常用命令与配置

### sysctl 命令速查

```shell
sysctl -a                          # 列出全部参数（本机 3302 个）
sysctl -a | grep tcp               # 按关键字过滤
sysctl net.ipv4.ip_forward         # 查看单个参数
sysctl -w net.ipv4.ip_forward=1    # 临时修改（立即生效，重启丢失）
sysctl -w net.ipv4.ip_local_port_range="1024 65000"   # 多值参数用引号包空格
sysctl -p                          # 加载 /etc/sysctl.conf
sysctl -p /etc/sysctl.d/99-tune.conf   # 加载指定文件
sysctl --system                    # 按优先级加载全部（/etc/sysctl.d/ + conf）
sysctl -q 参数名                   # 静默模式（配合脚本判断参数是否存在）
```

### 查看 /proc 与 /sys

```shell
cat /proc/cpuinfo | head           # CPU 型号/核数/缓存
cat /proc/meminfo | head           # 内存总量/可用/缓存
cat /proc/loadavg                  # 1/5/15 分钟负载
cat /proc/uptime                   # 开机时长 + 空闲时长
cat /proc/version                  # 内核版本 + 编译工具链
cat /proc/filesystems              # 内核支持的文件系统
cat /proc/mounts                   # 当前挂载表
cat /proc/cmdline                  # 内核启动参数
cat /proc/sys/net/ipv4/ip_forward  # 内核参数（= sysctl net.ipv4.ip_forward）
ls /proc/1/                        # 看 PID 1 的进程信息目录
ls /sys/block/                     # 块设备（sda/sdb…）
ls /sys/class/net/                 # 网络设备
ls /sys/module/                    # 已加载的内核模块
```

```text
# 实测（本机 /proc 与挂载信息）
$ cat /proc/loadavg /proc/uptime
2.03 1.40 1.60 1/2580 3110036     # 1/5/15 分钟负载 + 当前运行/总线程数 + 最近 PID
1987102.70 15277795.00            # 开机 1987102 秒，累计空闲 15277795 秒
$ mount | grep proc
proc on /proc type proc (rw,nosuid,nodev,noexec,relatime)
$ df -h /proc
文件系统        大小  已用  可用 已用% 挂载点
proc               0     0     0     - /proc
# 伪文件系统占用 0 磁盘 —— 内容不在磁盘上
```

## 配置文件解析

### /etc/sysctl.conf

传统持久化配置文件（Ubuntu/Debian 和 RHEL 都有），逐行 `参数名=值`，`#` 注释。Ubuntu 24.04 中它只是个壳，实际内容都 include 到 /etc/sysctl.d/ 里（`/etc/sysctl.conf -> ../usr/lib/sysctl.d/50-default.conf` 的 symlink 结构视发行版而异），但手写配置放这里仍然有效。

### /etc/sysctl.d/*.conf

按文件名排序的片段目录，应用软件包（systemd、内核包、docker 等）和管理员各自放一个文件互不干扰。命名惯例：`NN-描述.conf`（两位数字前缀控制加载顺序）。

```text
# /etc/sysctl.d/99-tune.conf  —— 管理员自定义调优（数字最大，最后加载）
net.ipv4.ip_forward=1
net.ipv4.tcp_tw_reuse=1
net.ipv4.ip_local_port_range=1024 65000
net.core.somaxconn=4096
net.core.rmem_max=16777216
net.core.wmem_max=16777216
vm.swappiness=10
vm.dirty_ratio=10
fs.file-max=2097152
kernel.pid_max=4194304
```

```text
配置规则：
1. 每行 参数名=值（点分层级，net.ipv4.ip_forward）
2. 多值参数用空格分隔（net.ipv4.ip_local_port_range=1024 65000）
3. 值不能带引号、不能带单位（swappiness=10 不是 "10" 或 10%）
4. 修改后 sysctl -p（单文件）或 sysctl --system（全部）立即生效
5. 优先级：/etc/sysctl.d/99-*.conf > /etc/sysctl.d/10-*.conf > /etc/sysctl.conf
   （数字大的后加载，后加载覆盖先加载）
```

| 分类 | 参数 | 典型值 | 作用 |

### Red Hat 系差异

```text
RHEL/CentOS/Rocky：
1. 额外一层 /usr/lib/sysctl.d/（发行版默认参数放这里，别手改，会被更新覆盖）
2. 加载顺序：/usr/lib/sysctl.d/ → /etc/sysctl.d/ → /etc/sysctl.conf，后加载覆盖先加载

4. 查看实际生效值：sysctl 参数名（只看配置可能被覆盖）
5. 内核参数包：procps-ng（yum install procps-ng）
```

## 应用场景实战

### 场景一：开启 IP 转发（做网关 / Docker 容器网络）

Docker 桥接网络、VPN 网关、路由器角色都需要 ip_forward=1。

```shell
# 1. 查看当前值
sysctl net.ipv4.ip_forward
# 2. 临时开启（立即生效，重启丢失）
sysctl -w net.ipv4.ip_forward=1
# 3. 持久化（写入配置，重启保留）
echo 'net.ipv4.ip_forward=1' | tee /etc/sysctl.d/99-ip-forward.conf
sysctl --system
# 4. 验证
cat /proc/sys/net/ipv4/ip_forward   # 输出 1
```

### 场景二：高并发 Web/网关连接参数组

Nginx + 大量短连接（或 API 网关），出现 TIME_WAIT 堆积、端口耗尽、accept 队列溢出时按组调整：

```shell
# 查看现状
sysctl net.ipv4.tcp_tw_reuse net.ipv4.ip_local_port_range net.core.somaxconn net.core.netdev_max_backlog
# 一组调优（先临时改验证）
sysctl -w net.ipv4.tcp_tw_reuse=1
sysctl -w net.ipv4.ip_local_port_range="1024 65000"
sysctl -w net.core.somaxconn=4096
sysctl -w net.core.netdev_max_backlog=10000
# 持久化
cat > /etc/sysctl.d/99-web-tune.conf <<'EOF'
net.ipv4.tcp_tw_reuse=1
net.ipv4.ip_local_port_range=1024 65000
net.core.somaxconn=4096
net.core.netdev_max_backlog=10000
EOF
sysctl --system
# 应用侧配套：Nginx 的 listen backlog 也要调（默认 511，Linux 上限受 somaxconn 限制）
```

### 场景三：文件句柄不足（Too many open files）

高并发应用（Java/Node/Redis）报 `Too many open files` 时，除了改 ulimit（进程级软硬限制），还要确认系统级上限 fs.file-max 和 inode 数量：

```shell
# 1. 看全局句柄使用情况（file-nr：已分配/未用/上限）
cat /proc/sys/fs/file-nr
# 2. 看进程级限制
cat /proc/<PID>/limits | grep -i 'open files'
ulimit -n
# 3. 提升系统级上限
sysctl -w fs.file-max=2097152
echo 'fs.file-max=2097152' > /etc/sysctl.d/99-file-max.conf
sysctl --system
# 4. 进程级限制（/etc/security/limits.conf 或 systemd unit 的 LimitNOFILE）
```

注意：fs.file-max 是**系统全局**上限，应用进程的句柄数还受 ulimit/limits.conf/Unit 的 LimitNOFILE 约束，两层都要调（参见 [[05.6-资源限制]]）。

### 场景四：数据库服务器 swappiness 调优

数据库（MySQL/PostgreSQL）大量使用 page cache，swap 积极度太高会导致「内存里的热数据被换出到 swap，查询变慢」。建议把 swappiness 调低：

```shell
# 查看当前值（Ubuntu 默认 60）
sysctl vm.swappiness
# 调低（10 表示非必要不 swap，保留给紧急情况）
sysctl -w vm.swappiness=10
echo 'vm.swappiness=10' > /etc/sysctl.d/99-db-tune.conf
sysctl --system
# 验证内存真实使用（看 Swap 列是否持续增长）
free -h
```

## 性能与调优

### 调优思路

内核参数调优不是「抄一份优化清单」，而是「先量化问题，再针对瓶颈调参，最后验证收益」：

```text
调优四步：
1. 监控定位瓶颈（ss -s 看连接状态、vmstat 看内存、iostat 看 IO、sar 看网络）
2. 找到对应参数（瓶颈类型 → 参数分类：网络栈/内存/文件系统/调度）
3. 一次只改一个参数，sysctl -w 临时验证
4. 确认收益后写配置文件持久化，并记录改动
```

### 网络栈参数组

```text
高并发服务端（对外提供服务）：
net.core.somaxconn=4096           # 提高 accept 队列
net.core.netdev_max_backlog=10000 # 网卡收包队列
net.ipv4.tcp_max_syn_backlog=8192 # SYN 队列
net.ipv4.tcp_syncookies=1         # 防 SYN Flood
net.ipv4.tcp_fin_timeout=30       # 快速回收 FIN_WAIT_2
net.ipv4.tcp_tw_reuse=1           # 复用 TIME_WAIT（Linux 5.16+ 已默认启用部分逻辑）

高并发客户端/爬虫（大量出站连接）：
net.ipv4.ip_local_port_range=1024 65000   # 扩大可用端口
net.ipv4.tcp_tw_reuse=1                   # 端口快速复用

大流量传输（下载/CDN/备份）：
net.core.rmem_max=16777216        # 接收缓冲上限 16MB
net.core.wmem_max=16777216        # 发送缓冲上限 16MB
net.ipv4.tcp_rmem=4096 87380 16777216
net.ipv4.tcp_wmem=4096 16384 16777216
```

### 内存参数组

```text
vm.swappiness=10                   # 数据库/缓存服务：减少 swap 换出
vm.overcommit_memory=0            # 保持默认启发式；特殊场景用 2（严格模式）
vm.dirty_ratio=10                 # 脏页上限（写密集业务调低，防写入尖峰）
vm.dirty_background_ratio=5       # 后台回写阈值
vm.vfs_cache_pressure=100         # 保持默认；内存大且 cache 命中高可调低
```

```shell
# 1. 读回确认（sysctl 和 /proc/sys 两个入口都验证）
sysctl net.ipv4.ip_forward

# 2. 运行时观测实际效果
```

## 安全与权限

### 写权限：root 专属

/proc/sys 和 /sys 下的大多数文件权限是 `-rw-r--r--`：**读对所有人开放，写仅 root**。普通用户执行 `sysctl -w` 会报 Permission denied，直接 `echo 1 > /proc/sys/...` 也一样。服务端加固时注意：能 sudo 的账户等于能改内核行为，sudoers 授权要谨慎（见 [[05.4-提权与 sudo]]）。

```text
# 实测（本机 ip_forward 文件权限）
$ ls -l /proc/sys/net/ipv4/ip_forward
-rw-r--r-- 1 root root 0  7月 27 13:04 /proc/sys/net/ipv4/ip_forward
```

### hidepid：隐藏其他用户的进程

/proc 默认允许任何用户查看所有进程的目录（含 cmdline、environ、cwd —— 会泄露其他用户的命令行参数和环境变量）。需要加固时用 hidepid 挂载选项：

```shell
# /etc/fstab 里给 /proc 加 hidepid=2（最严格：连目录都不可见）
proc  /proc  proc  defaults,hidepid=2  0 0
# 或 systemd 挂载参数（/etc/systemd/system/proc.mount.d/override.conf 之类）
mount -o remount,hidepid=2 /proc   # 临时重挂载
```

hidepid 有三个级别：0 默认（可见所有进程）、1（不可见其他用户进程的 cmdline/environ）、2（其他用户进程目录完全不可见）。注意 hidepid=2 会破坏 ps/top 等工具对多用户进程的可见性，需在「可见性 vs 安全」之间权衡。

### 危险参数清单

```text
改错可能直接「搞挂系统」或「打开安全口子」的参数：
kernel.panic=0          panic 后不重启 —— 服务器建议设 10（10 秒后自动重启）
kernel.sysrq=1          SysRq 魔术键（生产环境谨慎，远程可触发内核操作）
vm.overcommit_memory=1  无脑超售内存 —— malloc 成功但 OOM 时被杀的是你自己
net.ipv4.ip_forward=1   开启转发 —— 非网关机器别开，等于给网络开了一扇门
net.ipv4.conf.all.rp_filter=0   关闭反向路径过滤 —— 防 IP 欺骗的最后防线
fs.protected_hardlinks=0        关闭硬链接保护 —— 攻击者可利用 /tmp 提权
kernel.kptr_restrict=0          /proc/kallsyms 对所有人可见 —— 泄露内核符号地址
```

### 安全相关参数（建议默认开启）

```text

net.ipv4.conf.all.rp_filter=1              # 反向路径过滤，防 IP 欺骗（默认开）
net.ipv4.conf.all.accept_redirects=0       # 不接收 ICMP 重定向（防路由劫持）
net.ipv4.conf.all.send_redirects=0         # 非路由器不发送重定向
```

## 故障排查

### 案例一：改了参数，重启后又变回去

```shell
# 现象：sysctl -w 设置后当时生效，重启后恢复默认
# 排查步骤：
# 1. 确认当前值
sysctl net.ipv4.ip_forward
# 2. 确认配置文件里有没有（grep 两个位置）
grep -r ip_forward /etc/sysctl.conf /etc/sysctl.d/
# 3. 确认没有被其他文件覆盖（优先级：后加载的赢）
ls /etc/sysctl.d/ && sysctl --system
# 4. 持久化 + 验证
echo 'net.ipv4.ip_forward=1' > /etc/sysctl.d/99-ip-forward.conf
sysctl --system && sysctl net.ipv4.ip_forward
```

### 案例二：sysctl -p 报 unknown key

```shell
# 现象：sysctl -p 报 "sysctl: cannot stat /proc/sys/...: No such file or directory"
# 1. 先确认正确参数名（关键字搜索）
sysctl -a | grep 关键词
# 2. 确认内核是否编译了该功能（参数不存在 = 功能没编进内核/没加载模块）
ls /proc/sys/net/ipv4/ | grep 关键词
# 3. 检查拼写：点分层级错一个就是另一个路径
sysctl net.ipv4.tcp_tw_reuse      # 正确
sysctl net.ipv4.tcp_tw_reuse=1    # 值写成文件名都会报错
```

注意：同一个参数在 RHEL 旧版和 Ubuntu 新版的名字可能不同（如 tcp_tw_reuse 在 5.16+ 部分逻辑已内建，参数仍在但语义变化），跨发行版抄配置前先 `sysctl -a | grep` 确认。

### 案例三：配置写了，但参数没生效（被覆盖）

```shell
# 现象：/etc/sysctl.conf 里写了 vm.swappiness=10，重启后还是 60
# 1. 看实际生效值
sysctl vm.swappiness
# 2. 全量找哪个文件写了 swappiness（可能是 docker/系统包配置覆盖）
grep -r swappiness /etc/sysctl.conf /etc/sysctl.d/ /usr/lib/sysctl.d/
# 3. 用高优先级文件（数字最大）覆盖
cat /etc/sysctl.d/99-tune.conf    # 确认已有
echo 'vm.swappiness=10' >> /etc/sysctl.d/99-tune.conf
sysctl --system
sysctl vm.swappiness              # 现在应为 10
```

### 案例四：普通用户改参数报 Permission denied

```shell
# 现象：非 root 执行 sysctl -w 或 echo > /proc/sys 报权限错误
# 原因：/proc/sys 文件 root 可写，普通用户只读（-rw-r--r-- root root）
# 解法：
sudo sysctl -w net.ipv4.ip_forward=1        # 用 sudo
# 应用需要改参数时（如 Docker 服务）走 systemd 的
# systemd-sysctl.service，而非给应用授权写 /proc/sys
```

## 常见问题

```text
Q1: sysctl -w 改了，重启又变回去？
A: sysctl -w 只改内存中的值（临时生效）。要持久化：写 /etc/sysctl.conf 或
   /etc/sysctl.d/ 下配置文件，然后 sysctl -p（单文件）或 sysctl --system（全部）加载。

Q2: 直接 echo 值 > /proc/sys/xxx 和 sysctl -w 有什么区别？
A: 效果等价（sysctl 底层就是读写 /proc/sys）。区别在格式处理：sysctl 自动处理
   多值参数的空格、结尾换行，echo 需要自己拼对格式。日常操作优先 sysctl -w。

Q3: 写了 sysctl.conf 但参数没生效？
A: 两个可能：①改完没执行 sysctl -p / --system 加载；②参数被后加载的文件覆盖
   （优先级数字大的赢）。用 sysctl 参数名 看实际值，grep 排查所有配置文件。

Q4: 网上抄的「内核优化参数」该不该用？
A: 谨慎。参数有场景（Web 服务 vs 数据库 vs 客户端差异巨大）、有内核版本差异
   （如 tcp_tw_reuse 在新内核语义变化）、有的还是安全负优化（如 tcp_tw_recycle
   已在新内核移除）。理解每个参数含义，按自己瓶颈调，一次改一个并对比验证。

Q5: /proc 和 /sys 里有些文件读出来是空的或 0？
A: 正常。伪文件系统内容由内核动态生成：权限受限（如 /proc/kcore 需 root）、
   设备不存在（如 /sys/class/net/xxx/speed 显示 -1 表示未协商）、或值确实为 0
   （如 uptime 里的空闲时间可能极大但 loadavg 在正常范围）。

Q6: 参数改了之后系统出问题，怎么回滚？
A: ①把值改回之前的（改动前先 sysctl 参数名 记录旧值）；
   ②从配置文件删掉该行后 sysctl --system 重载；
   ③严重到进不了系统：开机 GRUB 加内核参数（如 sysctl.vm.swappiness=60）
   或进 recovery 模式改配置。所以调优前先记录旧值、一次只改一个参数。

Q7: 容器里看到的 /proc 是宿主机的吗？
A: 部分隔离。容器通过挂载 namespace 看到自己的 /proc，但内核参数
   /proc/sys 默认共享宿主机内核（改容器里 /proc/sys 就是改宿主机！）。
   Docker 默认 /proc/sys 只读挂载，防止容器改宿主机内核参数。

Q8: sysctl 参数和 /sys 里的属性有什么区别？
A: sysctl（/proc/sys）管「内核全局运行参数」；/sys 管「设备/对象属性」
   （网卡速率、设备状态、模块参数）。也有交叉：模块加载参数可以通过
   /sys/module/<模块>/parameters/ 在运行时改（等价 modprobe 时的 module.param=）。
```

## 面试题

```text
1. sysctl 和 /proc/sys 是什么关系？
   答：同一回事的两种表达。sysctl net.ipv4.ip_forward 底层就是读/写
   /proc/sys/net/ipv4/ip_forward，点号对应目录层级。sysctl 是更方便的命令行封装，
   自动处理格式；直接写文件也行，二者完全等价。

2. /proc 和 /sys 两个伪文件系统的区别？
   答：/proc（procfs）提供进程和系统运行信息：/proc/<PID>/（status/cmdline/fd）、
   /proc/meminfo、/proc/cpuinfo、/proc/sys（内核参数）；/sys（sysfs）基于设备模型
   暴露设备和内核对象：/sys/class/net 网卡、/sys/class/block 块设备、/sys/module
   已加载模块。粗分：/proc 是「进程+系统状态」，/sys 是「设备+内核对象」。

3. 怎么让内核参数永久生效？优先级是怎样的？
   答：写 /etc/sysctl.conf 或 /etc/sysctl.d/*.conf，然后 sysctl -p 或 --system 加载。
   优先级：按字典序后加载覆盖先加载，/etc/sysctl.d/ 里的数字大的文件覆盖数字小的，
   /etc/sysctl.conf 最后加载兜底；RHEL 系还有 /usr/lib/sysctl.d/（发行版默认）在最前。
   一句话：最后写入生效。

4. 什么是伪文件系统？和普通文件系统有什么不同？
   答：伪文件系统（procfs/sysfs/tmpfs）内容不落磁盘，文件大小常为 0，读取时由内核
   实时生成内容，写入时内核解析并改变内核状态；普通文件系统（ext4/xfs）数据存磁盘、
   断电不丢。df 看 /proc 大小为 0，重启后 /proc /sys 内容「重新长出来」。

5. 高并发下 TIME_WAIT 太多、端口不够用，怎么调？
   答：区分角色：服务端大量 TIME_WAIT 可用 tcp_tw_reuse（配合时间戳）复用连接；
   客户端大量出站连接把 ip_local_port_range 从 32768-60999 扩大到 1024-65000；
   同时确认 net.ipv4.tcp_fin_timeout 不必过长。注意 tcp_tw_recycle 已在新内核
   移除（NAT 场景有坑），别照抄旧博客。

6. 进程打开文件数上限（Too many open files）受哪些因素影响？
   答：三层：①系统全局 fs.file-max（/proc/sys/fs/file-max）；②进程级 rlimit
   （ulimit -n，soft/hard 两层，limits.conf 或 systemd LimitNOFILE 设置）；
   ③inode 数量（fs.inode-max，通常随内存自动增长）。排查看
   cat /proc/sys/fs/file-nr（已分配/未用/上限）判断卡在哪层。

7. /proc/<PID>/ 里有哪些关键文件？各有什么用？
   答：status 进程状态/身份（Name/Pid/Uid/VmRSS…）；cmdline 启动命令行（以 \0 分隔）；
   environ 环境变量；cwd 当前工作目录符号链接；exe 可执行文件符号链接；
   fd/ 打开的文件描述符（软链到真实文件）；maps/smaps 内存映射；stat/statm 状态与
   内存统计；io 磁盘 IO 统计；limits 资源限制；oom_score 被杀优先级；
   net/ 该进程网络命名空间视角。

8. hidepid 是干什么的？
   答：/proc 挂载选项，限制用户查看其他用户进程的信息，防信息泄露
   （cmdline/environ 会暴露别人的命令参数和密钥）。hidepid=2 最严格：
   其他用户的进程目录不可见。多租户/安全加固场景常用。

9. /sys/module/<模块名>/parameters/ 是什么？
   答：模块加载参数的用户态入口，对应 modprobe 时的 module.param=value。
   若模块允许（参数带写权限）可运行时修改，部分参数改后立即生效，
   但很多模块参数只在加载时读取一次，运行时改无效。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 内核参数先临时改（sysctl -w）验证，确认无误再写配置文件持久化
2. 调优一次只改一个参数，改完记录旧值 —— 出问题能定位能回滚
3. 持久化放 /etc/sysctl.d/99-xxx.conf（数字最大优先级最高），别挤在 /etc/sysctl.conf
4. 改完必须 sysctl --system（或 -p）加载并读回验证，别只改文件
5. 用 sysctl -a | grep 确认参数名存在，跨发行版先验证再抄配置
6. 文件句柄问题要查三层：fs.file-max（全局）、ulimit/limits.conf（进程）、inode
7. 生产环境参数变更走配置管理（Ansible sysctl 模块）统一下发，避免机器漂移
8. 读 /proc 和 /sys 排查问题时注意权限：/proc/kcore、/proc/<他人PID> 等受限
9. 容器里别动 /proc/sys —— 共享宿主机内核，改了就是改宿主机
10. 安全参数（rp_filter、syncookies、kptr_restrict）保持发行版默认开启，别为性能关掉

### 踩坑记录

```text
坑 1：sysctl -w 改了，重启又变回去
结论：以为改好了，重启后参数恢复默认，业务表现又变差。
原因：sysctl -w 只改内存值，不写任何配置文件，重启自然丢失。
解法：验证通过后写 /etc/sysctl.d/99-xxx.conf 并 sysctl --system 加载。

坑 2：echo 值 > /proc/sys 写不进去或格式不对
结论：echo 1 > /proc/sys/net/ipv4/ip_forward 有效，但多值参数写了无效甚至报错。
原因：参数格式特殊（多值要空格分隔，如 ip_local_port_range="1024 65000"），echo 默认带换行，部分参数解析严格。
解法：优先 sysctl -w（自动处理格式），或先 cat 该文件看格式再写。

坑 3：照抄网上的「内核优化清单」，系统反而不稳
结论：抄了一堆 sysctl 参数，出现网络异常、OOM 增多。
原因：参数与场景/内核版本强相关（tcp_tw_recycle 在 NAT 下害人、overcommit_memory=1 无脑超售），旧博客参数在新内核可能已移除或语义变了。
解法：理解每个参数含义，按瓶颈针对性调，一次一个，验证后再保留。

坑 4：参数名写错，sysctl -p 报 unknown key
结论：sysctl -p 报 cannot stat /proc/sys/...: No such file or directory。
原因：点分层级写错或拼写错（如 net.ipv4.tcp_tw_reuse 写成 tcp_tw_reuse=1 丢前缀）。
解法：sysctl -a | grep 关键词 找正确参数名，确认内核编译了该功能。

坑 5：改了 sysctl.conf 忘了 sysctl -p 加载
结论：配置写了，但参数当时没生效，线上问题没解决还找不到原因。
原因：配置文件只在加载时才读，改文件本身不会动内核。
解法：改完立即 sysctl --system（或 -p）并读回验证，养成习惯。

坑 6：参数被别的文件覆盖，改了等于没改
结论：sysctl.conf 里写了 swappiness=10，实际值还是 60。
原因：docker/系统包在 /etc/sysctl.d/ 或 /usr/lib/sysctl.d/ 里写了同参数，加载顺序靠后，覆盖了你的配置。
解法：grep -r 参数名 /etc/sysctl.d/ /usr/lib/sysctl.d/ /etc/sysctl.conf全量排查，把自定义值放到数字最大的 99-*.conf。

坑 7：普通用户执行 sysctl -w 报 Permission denied
结论：脚本里 sysctl -w 直接失败，误以为参数没生效。
原因：/proc/sys 文件 root 可写、普通用户只读（-rw-r--r--）。
解法：用 sudo，或把参数写进配置让 systemd-sysctl 开机加载；应用进程别授权写 /proc/sys。

坑 8：容器里改了 /proc/sys，宿主机跟着变
结论：在容器里 echo 1 > /proc/sys/xxx 成功，宿主机全局参数被改了。
原因：内核参数属于内核全局/网络命名空间（部分 net.* 参数在容器内是独立 netns 才隔离），默认共享宿主机内核。
解法：容器里别改内核参数；需要改走宿主机配置；确认参数是否 per-netns 隔离。

坑 9：把 kernel.panic 设成 0，服务器 panic 后挂死
结论：服务器内核 panic 后无响应，必须人工干预重启。
原因：kernel.panic=0 表示 panic 后不自动重启（默认值）。
解法：生产服务器设 kernel.panic=10（panic 10 秒后自动重启），配合看门狗（watchdog）双保险。

坑 10：调了 swappiness 没效果，还以为是参数没生效
结论：swappiness 调成 10，free -h 看 Swap 还在涨，以为设置失败。
原因：swappiness 是「倾向」不是「开关」，已有换出页面回收需要时间；且进程已分配的内存不会自动搬回。
解法：配合 vm.vfs_cache_pressure、观察 swap 增长趋势（vmstat 1 5），确认 sysctl vm.swappiness 值已生效即可，别指望立竿见影。
```

## 概述

内核参数和伪文件系统是「和内核交互的接口」：sysctl 读写内核运行参数（不用重启内核就调优），/proc 和 /sys 是内核暴露的伪文件系统（虚拟文件，反映和控制系统状态）。内核调优（TCP 参数、内存水位、转发开关）都通过 sysctl 或直接写 /proc/sys。理解这些接口，才能「改内核行为」而不重新编译内核。

```text
内核接口三件套：
1. sysctl —— 读写内核参数（sysctl -w 改、sysctl -a 看）
2. /proc —— 伪文件系统，进程和系统信息（/proc/cpuinfo、/proc/sys）
3. /sys —— 伪文件系统，设备和内核对象（/sys/block、/sys/class）
```

## 核心概念

1. **sysctl**：读写内核运行参数的工具，`sysctl -a` 看所有、`sysctl -w 参数=值` 临时改，持久化写 /etc/sysctl.conf。
2. **/proc**：伪文件系统，提供「进程 + 系统信息」——/proc/cpuinfo、/proc/meminfo、/proc/<pid>/、/proc/sys。
3. **/sys**：伪文件系统（sysfs），提供「设备和内核对象」——/sys/block、/sys/class、/sys/kernel。
4. **内核调优参数**：影响系统行为的开关（IP 转发、swap 积极度、TIME_WAIT 复用、文件句柄上限）。

```text
# 实测（本机 sysctl 参数）
$ sysctl kernel.hostname kernel.ostype kernel.osrelease
kernel.hostname = lw-Vostro-7580
kernel.ostype = Linux
kernel.osrelease = 7.0.0-28-generic
$ sysctl -a | wc -l
3264
# 本机有 3264 个内核参数可调
```

## 工作原理

/proc 和 /sys 是「伪文件系统」——文件内容不存在于磁盘，而是在读取时由内核实时生成，写入时由内核解析并改变内核状态。/proc/sys 是 sysctl 的底层：`sysctl net.ipv4.ip_forward` 实际读的是 /proc/sys/net/ipv4/ip_forward 文件。sysctl 只是把这个文件路径用「点」分隔表达（net.ipv4.ip_forward ↔ /proc/sys/net/ipv4/ip_forward）。

```text
sysctl 与 /proc/sys 的关系：
sysctl net.ipv4.ip_forward  ↔  读/写 /proc/sys/net/ipv4/ip_forward
点号（net.ipv4.ip_forward）对应目录层级（net/ipv4/ip_forward）
```

## 常用命令与配置

```shell
sysctl -a                      # 看所有参数
sysctl net.ipv4.ip_forward     # 看单个
sysctl -w net.ipv4.ip_forward=1   # 临时改
echo 'net.ipv4.ip_forward=1' >> /etc/sysctl.conf   # 持久化
sysctl -p                      # 重新加载配置
cat /proc/cpuinfo | head       # CPU 信息
cat /proc/meminfo | head       # 内存信息
cat /proc/sys/net/ipv4/ip_forward   # 内核参数（= sysctl net.ipv4.ip_forward）
ls /sys/block/                 # 块设备（sda/sdb 等）
```

```text
# 实测（本机 /proc /sys 结构）
$ ls /proc/ | head
1  10  100  1007441  ...   # 每个数字是一个进程的目录（PID）
$ ls /sys/
block  bus  class  dev  devices  firmware  fs  kernel  module
# /proc 以进程为主，/sys 以设备/内核对象为主
```

## 配置文件解析

sysctl 持久化配置在 /etc/sysctl.conf 和 /etc/sysctl.d/*.conf：

```text
# /etc/sysctl.conf 或 /etc/sysctl.d/99-tune.conf
net.ipv4.ip_forward=1
vm.swappiness=10
net.ipv4.tcp_tw_reuse=1
fs.file-max=65535
vm.dirty_ratio=10
```

```text
配置规则：
1. 参数名=值（点分层，net.ipv4.ip_forward）
2. 多值参数用空格分隔（net.ipv4.ip_local_port_range=1024 65000）
3. 修改后 sysctl -p（单文件）或 sysctl --system（全部）生效
4. 优先级：/etc/sysctl.d/*.conf > /etc/sysctl.conf
```

## 应用场景实战

### 场景一：开启 IP 转发（做网关/Docker）

```shell
# 1. 看当前值
sysctl net.ipv4.ip_forward
# 2. 临时开启
sysctl -w net.ipv4.ip_forward=1
# 3. 持久化
echo 'net.ipv4.ip_forward=1' >> /etc/sysctl.conf
sysctl -p
```

### 场景二：调优 TCP 参数（高并发 Web）

```shell
# 1. 查看当前 TCP 参数
sysctl net.ipv4.tcp_tw_reuse net.ipv4.ip_local_port_range
# 2. 调优（TIME_WAIT 复用 + 扩大端口范围）
sysctl -w net.ipv4.tcp_tw_reuse=1
sysctl -w net.ipv4.ip_local_port_range="1024 65000"
# 3. 持久化
echo -e 'net.ipv4.tcp_tw_reuse=1\nnet.ipv4.ip_local_port_range=1024 65000' >> /etc/sysctl.conf
```

## 性能与调优

```text
常见内核调优参数：
net.ipv4.ip_forward=1        IP 转发（网关/Docker 需要）
vm.swappiness=10             swap 积极度（数据库调低）
net.ipv4.tcp_tw_reuse=1      TIME_WAIT 复用（短连接场景）
fs.file-max=65535            文件句柄上限
vm.dirty_ratio=10            脏页比例（写密集调低）
```

## 安全与权限

```text
1. 写权限 —— /proc/sys 和 /sys 的写需要 root，普通用户只能读
2. hidepid —— /proc 挂载 hidepid 选项，限制进程目录对其他用户的可见性
3. 参数影响 —— 改内核参数直接影响系统安全（如 ip_forward 开启转发），谨慎
4. 审计 —— 内核参数改动应记录，便于回溯谁改了什么
```

## 故障排查

### 改了参数重启又变回去

```shell
# 1. 确认是否只临时改（sysctl -w 不持久化）
sysctl net.ipv4.ip_forward
# 2. 检查配置文件
grep -r ip_forward /etc/sysctl.conf /etc/sysctl.d/
# 3. 持久化 + 加载
echo 'net.ipv4.ip_forward=1' >> /etc/sysctl.d/99-tune.conf
sysctl --system
```

### sysctl -p 报 unknown key

```shell
# 参数名写错，先查正确名字
sysctl -a | grep 关键词
# 确认参数名拼写和层级
```

## 常见问题

```text
Q1: sysctl -w 改了重启又变回去？
A: sysctl -w 是临时改。写 /etc/sysctl.conf 或 /etc/sysctl.d/，sysctl -p 加载。

Q2: 改了 /proc/sys 的文件但格式不对？
A: 有些参数格式特殊（多值要空格分隔），写错格式不生效。优先用 sysctl -w。

Q3: 网上抄的内核优化参数导致问题？
A: 那些参数可能不适合你的场景。理解每个参数含义，按需调，别盲目照抄。

Q4: 写了 sysctl.conf 但参数没生效？
A: 改了文件没 sysctl -p 重新加载。改完执行 sysctl -p（或 --system）。
```

## 面试题

```text
1. sysctl 和 /proc/sys 的关系？
   答：同一回事。sysctl net.ipv4.ip_forward 底层读/写 /proc/sys/net/ipv4/ip_forward，点号对应目录层级。

2. /proc 和 /sys 的区别？
   答：/proc 提供进程和系统信息（cpuinfo/meminfo/pid），/sys（sysfs）提供设备和内核对象（block/class）。

3. 怎么让内核参数永久生效？
   答：写 /etc/sysctl.conf 或 /etc/sysctl.d/*.conf，然后 sysctl -p（或 --system）加载。

4. 什么是伪文件系统？
   答：文件内容不存在于磁盘，读取时内核实时生成，写入时内核解析并改变状态。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 内核参数临时改（sysctl -w）验证，再持久化（sysctl.conf）
2. 调优一次改一个参数，别一次改一堆（出问题难定位）
3. 改前记录旧值，方便回滚
4. /proc/sys 和 sysctl 是同一回事，sysctl 更友好
5. 调优参数前理解含义，网上抄的「优化参数」不一定适合你的场景

### 踩坑记录

```text
坑 1：sysctl -w 改了重启又变回去
结论：sysctl -w 改的参数重启后恢复默认。
原因：sysctl -w 是临时改，不持久化。
解法：写 /etc/sysctl.conf 或 /etc/sysctl.d/，sysctl -p 加载。

坑 2：改了 /proc/sys 的文件但格式不对
结论：echo 1 > /proc/sys/net/ipv4/ip_forward 生效，但别的参数写了无效。
原因：有些参数格式特殊（如多值参数要空格分隔），写错格式不生效。
解法：优先用 sysctl -w（自动处理格式），或先读看格式再写。

坑 3：网上抄的「内核优化参数」导致问题
结论：照抄一堆 sysctl 参数，系统反而出问题。
原因：那些参数可能不适合你的场景（内存/网络差异大）。
解法：理解每个参数含义，按需调，别盲目照抄。

坑 4：sysctl 参数名写错，sysctl -p 报错
结论：sysctl -p 报 unknown key。
原因：参数名写错（点分层写错、拼写错）。
解法：sysctl -a | grep 关键词 找正确参数名。

坑 5：忘了 sysctl -p 加载新配置
结论：写了 sysctl.conf，但参数没生效。
原因：改了文件没 sysctl -p 重新加载。
解法：改完 sysctl.conf 执行 sysctl -p（或 --system）。
```

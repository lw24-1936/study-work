## 概述

内核模块是「可动态加载的内核功能」——驱动、文件系统、网络协议等都能做成模块，需要时加载（modprobe）、不用时卸载（rmmod），不用重新编译内核。这样内核保持精简、功能按需加载。核心：lsmod（看已加载模块）、modprobe（加载/卸载，自动处理依赖）、insmod（直接加载，不管依赖）、/lib/modules（模块存放位置）。

```text
内核模块三要素：
1. 加载/卸载 —— modprobe 加载、rmmod 卸载，动态增减内核功能
2. 依赖 —— 模块之间有依赖，modprobe 自动加载依赖模块
3. 存放 —— /lib/modules/<内核版本>/ 下，每个内核版本一套
```

## 核心概念

1. **lsmod**：查看已加载模块（+ Used by 依赖关系）。
2. **modprobe**：加载/卸载模块，自动解析依赖（读 modules.dep），是推荐用法。
3. **insmod**：直接加载指定 .ko 文件，不处理依赖（易出错），只在加载特定路径模块时用。
4. **模块依赖**：模块之间互相依赖（如 nvidia_drm 依赖 nvidia_modeset），modprobe 自动加载依赖链。

```text
命令分工：
lsmod     查看已加载模块（+ Used by 依赖）
modprobe  加载/卸载（自动处理依赖，推荐）
insmod    直接加载 .ko（不管依赖，易错）
rmmod     卸载
modinfo   看模块信息（依赖/参数/描述）
```

## 工作原理

内核模块以 .ko 文件（kernel object）存放在 /lib/modules/<内核版本>/ 下。加载模块时，modprobe 先读 modules.dep（依赖关系文件），按依赖顺序逐个 insmod 加载；卸载时反向卸载。模块在内核空间运行，和内核共享地址空间——所以模块代码出错（如空指针）会导致整个内核崩溃。lsmod 的 Used by 列显示「谁在用这个模块」，由内核维护引用计数。

```text
模块加载原理：
modprobe 读 modules.dep → 按依赖顺序 insmod 加载 → 内核执行模块 init 函数 → 注册功能
卸载反向：rmmod → 检查引用计数（Used by 非 0 拒绝）→ 执行 exit 函数 → 释放
```

## 常用命令与配置

```shell
lsmod                 # 查看已加载模块（+ 依赖）
modprobe nvidia       # 加载模块（自动处理依赖）
modprobe -r nvidia    # 卸载模块
insmod /path/to/xxx.ko   # 直接加载 .ko 文件（不管依赖）
rmmod xxx             # 卸载
modinfo nvidia        # 看模块信息（依赖/参数/描述）
modinfo -F depends nvidia   # 只看依赖
modprobe --show-depends nvidia_drm   # 看会加载哪些依赖模块
```

```text
# 实测（本机已加载模块，nvidia 驱动占大头）
$ lsmod | head
Module          Size     Used by
nvidia_uvm    2080768   0
nvidia_drm     139264   1  nvidia_drm
nvidia_modeset 1683456   1  nvidia_drm
nvidia       105349120   3  nvidia_uvm,nvidia_drm,nvidia_modeset
btrfs         2269184   0
# nvidia 驱动 105MB，是最大的模块；Used by 列显示依赖关系
```

## 配置文件解析

模块配置文件在 /etc/modprobe.d/，关键配置：

```text
# /etc/modprobe.d/blacklist.conf（禁用模块）
blacklist nouveau         # 禁用开源 nvidia 驱动，避免和闭源驱动冲突

# /etc/modprobe.d/options.conf（模块参数）
options nvidia NVreg_DynamicPowerManagement=0x02

# /etc/modules（开机加载的模块，Debian/Ubuntu）
nvidia
```

```text
/lib/modules/<内核版本>/ 目录结构：
kernel/        模块文件（.ko，按 drivers/fs/net 分类）
modules.dep    依赖关系文件（modprobe 读它）
modules.alias  别名映射（设备 ID → 模块名）
```

```text
# 实测（本机 /lib/modules，4 个内核版本）
$ ls /lib/modules/
6.17.0-29-generic
6.17.0-35-generic
6.17.0-40-generic
7.0.0-28-generic
# 4 个内核各有一套模块，当前内核 7.0.0-28 用对应的模块目录
```

## 应用场景实战

### 场景一：加载/卸载一个驱动模块

```shell
# 1. 看模块是否已加载
lsmod | grep nvidia
# 2. 加载模块（自动处理依赖）
modprobe nvidia
# 3. 看模块信息
modinfo nvidia
# 4. 卸载模块（如果不再需要）
modprobe -r nvidia
```

### 场景二：排查模块加载失败

```shell
# 1. 加载失败
modprobe xxx
# 报错如：modprobe: FATAL: Module xxx not found
# 2. 看模块在不在
find /lib/modules/$(uname -r) -name 'xxx*'
# 3. 看内核日志里的加载错误
dmesg | tail -20
```

## 性能与调优

```text
1. 按需加载 —— 内核保持精简，模块按需加载，减少常驻内存
2. 禁用无用模块 —— blacklist 掉不用的驱动，减少启动时间和内存占用
3. 模块参数调优 —— options 调驱动行为（如网卡中断合并、显卡功耗）
4. 驱动选择 —— 有多个驱动时（如 nouveau vs nvidia），blacklist 掉冲突的
```

## 安全与权限

```text
1. 模块加载权限 —— 加载/卸载模块要 root（内核态操作，权限极高）
2. 模块签名 —— 内核可开启模块签名校验，只加载可信模块（防恶意模块）
3. 模块是内核代码 —— 恶意/有 bug 的模块能直接破坏内核，只加载可信来源
4. 黑名单 —— 禁用不必要的模块，缩小攻击面
```

## 故障排查

### 模块加载失败

```shell
# 1. 看报错信息
modprobe xxx 2>&1
# 2. 看内核日志里的详细错误
dmesg | tail -30
# 3. 确认模块存在且属于当前内核
find /lib/modules/$(uname -r) -name 'xxx*'
# 4. 看依赖是否满足
modinfo -F depends xxx
```

### 模块加载了但设备没工作

```shell
# 1. 确认模块加载成功
lsmod | grep xxx
# 2. 看内核日志的初始化输出
dmesg | grep -i xxx
# 3. 看设备是否被识别
ls -l /dev/ | grep 设备名
```

## 常见问题

```text
Q1: insmod 加载模块报 Unknown symbol？
A: 模块有依赖，insmod 不处理依赖。用 modprobe（自动加载依赖）。

Q2: modprobe 报 Module not found？
A: 模块不在当前内核的 /lib/modules 目录（内核版本不对/模块没装）。确认模块属于当前内核。

Q3: 卸载正在使用的模块会怎样？
A: 系统崩溃或功能异常。lsmod 看 Used by 非 0 说明被用，先卸依赖它的模块。

Q4: 升级内核后驱动模块失效？
A: 驱动模块编译给旧内核，新内核不兼容。用 dkms 版驱动（自动为新内核编译）。
```

## 面试题

```text
1. 内核模块是什么？
   答：可动态加载的内核功能（驱动/文件系统/网络协议），按需加载/卸载，不用重编译内核。

2. modprobe 和 insmod 的区别？
   答：modprobe 自动解析依赖（读 modules.dep）并加载依赖链；insmod 只加载指定 .ko，不处理依赖。

3. lsmod 的 Used by 列是什么意思？
   答：显示「谁在用这个模块」的依赖关系，Used by 非 0 说明被其他模块使用，不能直接卸载。

4. 升级内核后驱动失效怎么办？
   答：用 dkms 版驱动（自动为新内核重新编译模块），或等驱动厂商适配新内核。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 加载/卸载模块用 modprobe（自动处理依赖），别用 insmod
2. 查模块依赖用 modinfo -F depends，理解依赖链
3. 模块加载失败先看 dmesg 内核日志，报错在里面
4. 每个内核版本一套模块，升级内核后模块目录也变
5. 别手动卸载正在用的模块（lsmod Used by 非 0），会导致崩溃

### 踩坑记录

```text
坑 1：insmod 加载模块报 Unknown symbol
结论：insmod 加载模块报未知符号错误。
原因：模块有依赖，insmod 不处理依赖，依赖模块没加载。
解法：用 modprobe（自动加载依赖），别用 insmod。

坑 2：modprobe 报 Module not found
结论：modprobe 加载模块报找不到。
原因：模块不在当前内核的 /lib/modules 目录（内核版本不对/模块没装）。
解法：确认模块属于当前内核，或 modprobe -r + 重新加载，或装对应内核的模块包。

坑 3：卸载正在使用的模块导致崩溃
结论：rmmod 正在用的模块，系统崩溃或功能异常。
原因：模块被使用（Used by 非 0），强卸会出问题。
解法：lsmod 看 Used by，先卸载依赖它的模块，或别卸正在用的。

坑 4：升级内核后模块加载失败
结论：升级内核后，某些驱动模块加载不了。
原因：新内核的模块目录没有对应的 .ko（驱动没适配新内核）。
解法：确认驱动支持新内核，装 dkms 版本（自动为新内核编译模块）。

坑 5：黑名单模块没生效
结论：想禁用某模块，改了 blacklist 还是加载了。
原因：blacklist 配置没写对位置，或没更新 initramfs。
解法：/etc/modprobe.d/blacklist.conf 写 blacklist xxx，然后 update-initramfs -u。
```

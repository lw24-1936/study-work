## 概述

进程是「正在运行的程序」，是 Linux 资源分配和调度的基本单位。每个进程有 PID（唯一标识）和 PPID（父进程 PID），有运行状态（运行/睡眠/僵尸等），进程的诞生靠 fork（复制）+ exec（替换）两个系统调用。理解进程的父子关系、状态、创建机制，是后面进程管理、信号、守护进程的基础。

```text
进程四要素：
1. 进程/线程 —— 进程是资源分配单位，线程是调度单位，一个进程可多线程
2. PID/PPID —— PID 唯一标识进程，PPID 是父进程，进程树从 PID 1（systemd）开始
3. 状态 —— R 运行 / S 睡眠 / D 不可中断 / Z 僵尸 / T 停止 / I 空闲
4. fork/exec —— fork 复制出子进程，exec 用新程序替换进程映像
```

## 进程与线程与任务

进程是「运行中的程序」，拥有独立的地址空间、文件描述符、资源；线程是进程内的执行流，共享进程的地址空间、更轻量。Linux 里线程和进程在调度上统一叫「任务」（task），都用 task_struct 描述，所以 ps 能看到线程。一个进程（如 nginx）可以有多个线程，但日常运维把「进程」当一个整体看，线程细节用 top -H 看。

```text
进程 vs 线程：
1. 进程 —— 独立地址空间、独立资源，隔离性好、创建开销大
2. 线程 —— 共享进程地址空间，轻量、切换快，但一个崩可能影响同进程其它线程
3. 任务 —— Linux 内核统一把进程/线程当 task 调度
```

## PID 与 PPID

每个进程有唯一 PID（进程号），PPID 是它的父进程 PID。所有进程构成一棵树：根是 PID 1（systemd），它 fork 出所有其他进程，所以 PPID=0 的只有 systemd 和内核线程。查看用 `ps -ef`（含 PPID）或读 /proc/<pid>/status。理解父子关系才能解释「父进程死了子进程变孤儿」「僵尸进程要父进程回收」。

```text
# 实测（进程树根）
$ ps -ef | head -5
UID   PID  PPID  CMD
root    1     0  /usr/lib/systemd/systemd ...
root    2     0  [kthreadd]
root    3     2  [pool_workqueue_release]
# PID 1 是 systemd（PPID 0，树的根），PID 2 是内核线程 kthreadd
```

```text
# 实测（/proc/self/status 看自己的进程信息）
$ head -8 /proc/self/status
Name:   head
State:  R (running)
Pid:    1081279
PPid:   1081226
# 每个进程在 /proc/<pid>/ 下都有自己的目录，status 里是进程元信息
```

## 进程状态

进程有六种主要状态（ps 的 STAT 列）：R 运行中/就绪、S 可中断睡眠（最常见，等事件）、D 不可中断睡眠（等 IO，kill 不掉）、Z 僵尸（已退出但父进程没回收）、T 停止（被信号暂停）、I 空闲内核线程。`ps -eo pid,stat,comm` 看状态，STAT 后缀还有额外信息（s=会话领导、< =高优先级、+=前台进程组）。

```text
# 实测（进程状态）
$ ps -eo pid,ppid,stat,comm | head -6
PID   PPID STAT COMMAND
  1      0 Ss   systemd       # S 睡眠 + s 会话领导
  2      0 S    kthreadd      # S 睡眠（内核线程）
  4      2 I<   kworker/...   # I 空闲内核线程 + < 高优先级
```

```text
进程状态速查（STAT 首字符）：
R 运行/就绪 | S 可中断睡眠 | D 不可中断睡眠 | Z 僵尸 | T 停止 | I 空闲
```

## fork 与 exec

进程的诞生靠两个系统调用：fork 复制当前进程（得到一个几乎一样的子进程），exec 用新程序替换当前进程的内存映像（PID 不变、程序变了）。shell 执行一条命令就是「fork 一个子进程 + 子进程 exec 该命令」。理解 fork/exec 能解释「为什么 shell 里执行命令后 shell 还在」——shell fork 出子进程去 exec 命令，自己等待子进程结束。

```text
fork / exec 机制：
1. fork —— 复制当前进程，父进程得到子进程 PID，子进程从 fork 处继续执行
2. exec —— 用新程序替换当前进程，PID 不变，内存映像全新
3. 组合 —— shell 跑命令 = fork 子进程 + 子进程 exec 命令 + 父进程 wait
```

```shell
# 观察 fork：一个进程 fork 出子进程
bash -c 'echo "父进程 $$"; (sleep 1; echo "子进程完成") & wait'
```

## 应用场景实战

### 场景一：查看进程树，理解父子关系

```shell
# 1. 看完整进程树（含父子关系）
ps -ef --forest | head -20
# 2. 或按树显示某个服务的进程
pstree -p nginx
# 3. 查看某进程的父进程
ps -o pid,ppid,cmd -p <PID>
```

### 场景二：排查僵尸进程

```shell
# 1. 找僵尸进程（STAT 是 Z）
ps -eo pid,ppid,stat,comm | grep ' Z '
# 2. 找到僵尸的父进程，让它回收
# 僵尸进程无法 kill，要父进程 wait 回收或父进程退出
ps -o ppid= -p <僵尸PID>
```

## 最佳实践与踩坑记录

### 最佳实践

1. 看进程用 ps -ef（含 PPID 和完整命令）或 ps aux（含资源占用）
2. 理解进程树：从 PID 1 往下找父子关系，别孤立地看单个进程
3. 僵尸进程要看父进程——子进程死了父进程不回收才变僵尸
4. 查进程详情读 /proc/<pid>/ 目录，比 ps 更全（status/fd/cmdline/environ）
5. D 状态进程是等 IO，kill 不掉别硬杀，先查 IO 瓶颈

### 踩坑记录

```text
坑 1：僵尸进程 kill 不掉
结论：kill -9 僵尸进程无效，它还在 ps 里。
原因：僵尸进程已退出，只是等父进程回收，不响应任何信号。
解法：找到父进程（PPID），让父进程 wait 回收或重启父进程。

坑 2：D 状态进程杀不掉还拖累系统
结论：进程卡在 D 状态，kill -9 无效。
原因：D 是不可中断睡眠，进程在等 IO（磁盘/网络），信号被挂起。
原因：先查 IO 瓶颈（iostat），解决 IO 问题进程自然恢复。

坑 3：误以为 PID 1 可以随便 kill
结论：kill PID 1（systemd）会导致系统崩溃。
原因：PID 1 是所有进程的祖先、内核特殊对待，杀了它系统就挂了。
解法：永远别对 PID 1 动手，重启系统用 reboot。

坑 4：fork 出的子进程继承了父进程的资源导致泄漏
结论：子进程继承了父进程的文件描述符、锁，父进程退出后资源没释放。
原因：fork 会复制父进程的资源句柄，子进程不关就泄漏。
解法：子进程用完的资源及时关闭，或用 exec 替换（exec 会重置）。

坑 5：用 ps 只看到进程名看不到完整命令，定位不到
结论：ps 默认截断长命令，看不到完整参数。
原因：终端宽度或 ps 默认格式截断了 COMMAND 列。
解法：ps auxww（w 重复取消截断）或 ps -ef --width 200。
```

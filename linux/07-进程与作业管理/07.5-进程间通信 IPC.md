## 概述

IPC（Inter-Process Communication，进程间通信）是进程之间交换数据的机制。六种主要方式：管道（匿名，父子进程）、命名管道（FIFO，无亲缘进程）、信号量（同步互斥）、共享内存（最快）、消息队列（结构化消息）、socket（网络/本地）。它们各有适用场景：管道适合流水线、共享内存适合大数据量、socket 适合跨机通信。查看当前系统的 IPC 用 ipcs。

```text
六种 IPC 对比：
1. 管道 |          —— 匿名单向，父子进程，shell 流水线
2. 命名管道 mkfifo —— 有名字的管道文件，无亲缘关系进程
3. 信号量           —— 同步互斥、计数，防止竞争
4. 共享内存         —— 映射同一块物理内存，速度最快
5. 消息队列         —— 结构化消息，按类型收发
6. socket          —— 网络通信，跨主机/本地
```

```text
# 实测（本机当前无在用 IPC）
$ ipcs
--------- 消息队列 -----------
（空）
------------ 共享内存段 --------------
（空）
--------- 信号量数组 -----------
（空）
# 系统里没进程在用 System V IPC（消息队列/共享内存/信号量），属正常
```

## 核心概念

### 管道与命名管道

管道分两种：匿名管道（shell 的 `|`，连接父子进程，单向、随进程结束消失）和命名管道（FIFO，mkfifo 创建的文件，有名字、可被无亲缘关系的进程读写）。匿名管道是 shell 流水线的基础，命名管道让「不相关的两个进程」也能通过文件路径通信。命名管道的读写会阻塞——没写入方读会等，没读方写会等。

```shell
# 匿名管道（父子进程，单向）
ls -l | wc -l

# 命名管道（FIFO，无亲缘进程）
mkfifo /tmp/myfifo
# 终端 A 写入
echo "hello" > /tmp/myfifo
# 终端 B 读取
cat /tmp/myfifo      # 输出 hello
rm /tmp/myfifo
```

```text
匿名管道 vs 命名管道：
1. 匿名管道 | —— 父子进程间，单向，进程结束即消失
2. 命名管道 FIFO —— 有文件名，无亲缘进程可通信，读写阻塞等待对方
```

### 信号量

信号量（semaphore）用于进程间的「同步和互斥」——本质是一个计数器，控制「同时最多几个进程访问某资源」。它不传输数据，只协调顺序、防止竞争（比如两个进程同时写一个文件）。信号量的经典应用是「互斥锁」和「限制并发数」。System V 信号量用 semget/semop 操作，POSIX 信号量用 sem_open/sem_wait。

```text
信号量要点：
1. 本质 —— 计数器，P 操作减一（获取）、V 操作加一（释放）
2. 用途 —— 互斥（二进制信号量=锁）、限制并发（计数信号量）
3. 不传数据 —— 只协调，配合共享内存一起用
```

### 共享内存

共享内存是最快的 IPC——多个进程把同一块物理内存映射到各自的地址空间，直接读写、不经过内核拷贝（相比管道/socket 要拷贝数据）。适合大数据量、高频通信（如数据库进程共享缓存）。缺点是要自己处理同步（配合信号量防竞争）。System V 用 shmget/shmat，POSIX 用 shm_open/mmap。查看用 ipcs -m。

```text
共享内存要点：
1. 最快 —— 直接映射同一物理内存，无内核拷贝
2. 场景 —— 大数据量、高频通信（进程共享缓存）
3. 缺点 —— 需自己同步（配合信号量），管理复杂
```

### 消息队列

消息队列是「有结构的消息传递」——进程把一条条有类型、有边界的消息放进队列，另一个进程按类型取。和管道（字节流、无边界）不同，消息队列是「一条条消息」的，天然有边界。适合「生产者-消费者」模式。System V 用 msgget/msgsnd/msgrcv，POSIX 用 mq_open/mq_send。

```text
消息队列 vs 管道：
1. 消息队列 —— 结构化、有边界、按类型收发，可多对多
2. 管道 —— 字节流、无边界、单向，一对多需配合
```

### socket

socket 是最通用的 IPC——既能本地进程通信（Unix domain socket，如 /run/mysqld.sock），也能跨主机网络通信（TCP/UDP）。它是网络编程的基础，几乎所有服务间通信（HTTP、MySQL、Redis、微服务 RPC）都基于 socket。本地 socket 比网络 socket 快（不走网络栈），同一台机器上的进程间通信用 Unix socket 更高效。

```shell
# 查看本机的 socket（本地 + 网络）
ss -lntup | head
# 本地 Unix domain socket
ss -xl | head
```

```text
socket 两种类型：
1. Unix domain socket —— 本地进程通信，路径形如 /run/xxx.sock，快
2. 网络 socket —— TCP/UDP，跨主机，IP:端口
```

## 工作原理

六种 IPC 的底层数据流分两类：「数据拷贝型」和「直接映射型」：

1. **数据拷贝型**（管道/消息队列/socket）：数据从发送方用户态 → 内核缓冲区 → 接收方用户态，至少一次内核拷贝，安全但慢。
2. **直接映射型**（共享内存）：多个进程把同一块物理页映射进各自地址空间，直接读写、零拷贝，最快但要自己同步。

信号量是特例——它不传数据，只维护一个内核计数器，靠原子加减实现互斥和限流。

```text
IPC 数据流对比：
管道/socket/消息队列：发送方 → 内核缓冲区 → 接收方（有拷贝，慢但安全）
共享内存：           双方直接映射同一物理页（零拷贝，最快）
信号量：             内核计数器 P/V 操作（不传数据，只协调）
```

## 常用命令与配置

```shell
ipcs                    # 查看所有 System V IPC（消息队列/共享内存/信号量）
ipcs -m                 # 只看共享内存
ipcs -q                 # 只看消息队列
ipcs -s                 # 只看信号量
ipcrm -m <shmid>        # 删除共享内存段
ipcrm -q <msgid>        # 删除消息队列
ipcrm -s <semid>        # 删除信号量
mkfifo /tmp/pipe        # 创建命名管道
ss -xl                  # 查看 Unix domain socket
```

```text
System V IPC 标识：每种对象有唯一的 key 和 id，ipcs 能查、ipcrm 能删
POSIX IPC 则用文件路径（shm_open/mq_open）标识，不体现在 ipcs 里
```

## 配置文件解析

System V IPC 的资源上限由内核参数控制（/proc/sys/kernel/），可在 /etc/sysctl.conf 调整：

```text
# /etc/sysctl.conf —— System V IPC 内核参数
kernel.shmmax = 68719476736      # 单个共享内存段最大字节数（默认 32G）
kernel.shmall = 16777216         # 系统共享内存总页数上限
kernel.shmmni = 4096             # 系统最大共享内存段数
kernel.msgmax = 8192             # 单条消息最大字节数
kernel.msgmnb = 16384            # 单个消息队列最大字节数
kernel.sem = 250 32000 32 128    # 信号量：数组数/总量/单次操作/最大信号量
```

```shell
sysctl -w kernel.shmmax=68719476736   # 临时调整（重启失效）
sysctl -p                              # 从 /etc/sysctl.conf 加载
```

## 应用场景实战

### 场景一：用命名管道做两个独立脚本间的数据传递

```shell
# 1. 建命名管道
mkfifo /tmp/data_pipe
# 2. 生产脚本写入（后台）
(while true; do date; sleep 1; done) > /tmp/data_pipe &
# 3. 消费脚本读取
cat /tmp/data_pipe | head -3
# 4. 清理
rm /tmp/data_pipe
```

### 场景二：查看数据库的本地 socket 通信

```shell
# MySQL/Redis 等本地连接走 Unix socket（比 TCP 快）
ss -xl | grep -E 'mysql|redis|docker'
ls -l /var/run/mysqld/mysqld.sock 2>/dev/null
```

## 性能与调优

```text
1. 同机通信用 Unix domain socket —— 比 TCP 网络栈少一层，快
2. 大数据量高频通信用共享内存 —— 零拷贝，但要配信号量同步
3. 调整 shmmax/shmall —— 数据库（PostgreSQL 共享缓存）需要大共享内存，默认太小要调
4. 管道适合流式小数据 —— 大文件传输别硬走管道，考虑共享内存或文件
5. 消息队列注意消息大小 —— msgmax 默认 8K，大消息要调大参数
```

## 安全与权限

```text
1. IPC 对象有权限位 —— 共享内存/消息队列/信号量有自己的 owner/group/mode（ipcs 的权限列）
2. 命名管道/socket 文件权限 —— 权限设错（其它用户可读写）会泄露数据
3. Unix socket 路径长度限制 —— 约 108 字节，太深路径会失败，放 /run/ 短路径
4. 残留 IPC 对象 —— 进程异常退出不清理，用 ipcrm 及时回收，防止占满 shmmni
5. 共享内存是「裸内存」 —— 无内核保护，进程越界写会踩其他进程数据，务必严格同步
```

## 故障排查

### IPC 对象残留 / 连接失败

```shell
# 1. 查看残留的 System V IPC 对象
ipcs
# 2. 确认属主和权限
ipcs -m -i <shmid>
# 3. 清理残留对象
ipcrm -m <shmid>
```

### Unix socket 连不上

```shell
# 1. 看 socket 文件是否存在
ls -l /run/xxx.sock
# 2. 看权限（服务进程要有读写权限）
stat /run/xxx.sock
# 3. 看服务是否监听该 socket
ss -xl | grep xxx
```

## 常见问题

```text
Q1: 共享内存为什么最快？
A: 多个进程直接映射同一块物理内存，读写不经内核拷贝（管道/socket 都要从用户态拷贝到内核缓冲区）。

Q2: 信号量传数据吗？
A: 不传。信号量只是计数器，负责同步互斥、限制并发，数据要配合共享内存或其它方式传递。

Q3: Unix domain socket 和 TCP socket 选哪个？
A: 同机进程通信用 Unix socket（快、路径寻址）；跨主机用 TCP socket。数据库本地连接默认走 Unix socket。

Q4: ipcs 和 ss 看的 IPC 一样吗？
A: 不一样。ipcs 看 System V IPC（共享内存/消息队列/信号量），ss 看 socket（Unix domain + 网络）。
```

## 面试题

```text
1. 六种 IPC 方式分别是什么？各自适用场景？
   答：管道（父子流水线）、命名管道（无亲缘进程）、信号量（同步互斥）、共享内存（大数据量最快）、消息队列（结构化消息）、socket（跨机/本地）。

2. 共享内存为什么需要信号量配合？
   答：共享内存本身不同步，多进程并发写同一块内存会竞争、数据错乱，需要信号量做互斥保护临界区。

3. 消息队列和管道有什么区别？
   答：消息队列是结构化的「一条条消息」、有边界、可按类型收发；管道是字节流、无边界、单向。

4. 进程异常退出后 IPC 对象会怎样？
   答：System V IPC（共享内存/消息队列/信号量）不随进程退出自动释放，会残留，需 ipcrm 清理；管道/socket 随进程退出释放。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 同机进程通信用 Unix socket，比走 TCP 网络栈快
2. 共享内存是最快但最难管的，只在性能关键场景用（配信号量同步）
3. 命名管道注意「读写阻塞」——没对端会卡住，用超时或非阻塞
4. 消息队列适合生产者-消费者，天然有消息边界
5. 跨机通信一律 socket（TCP/UDP），别用本地 IPC 方式硬套

### 踩坑记录

```text
坑 1：命名管道读写没对端导致阻塞
结论：cat fifo 没写入方，命令卡住不动。
原因：FIFO 读写是阻塞的，没对端就等。
解法：用超时（timeout 5 cat fifo），或打开时加 O_NONBLOCK 非阻塞。

坑 2：共享内存没配信号量导致数据竞争
结论：两进程同时写共享内存，数据错乱。
原因：共享内存本身不同步，并发写会竞争。
解法：配信号量或互斥锁保护临界区。

坑 3：消息队列和管道混淆，按字节流读消息队列
结论：把消息队列当字节流读，消息边界丢了。
原因：消息队列是「一条条消息」，按消息收发，不是字节流。
解法：理解消息队列的 msgrcv 按类型收，别当管道用。

坑 4：ipcs 看到大量残留的共享内存/信号量
结论：ipcs 一堆进程退出了却没清理的 IPC 对象。
原因：进程异常退出没释放 IPC 资源，残留占用。
解法：ipcrm -m/-s/-q 手动清理残留对象。

坑 5：Unix socket 路径太长或权限不对导致连接失败
结论：socket 文件路径过长（超 108 字节）或权限错，连不上。
原因：Unix socket 路径有长度限制，且 socket 文件权限要放行。
解法：socket 放 /run/ 或短路径，权限设对（属主属组匹配服务）。
```

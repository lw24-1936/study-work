## 概述

文件与目录操作是 Linux 日常使用最频繁的基本功，分三块：增删改查（ls/cd/mkdir/touch/cp/mv/rm）、查看内容（cat/less/head/tail/od/hexdump）、查找定位（find/locate/which/whereis/type）。它们组合起来能覆盖绝大多数「文件在哪、内容是什么、怎么搬怎么删」的场景。熟练这些命令是后面学文本三剑客、Shell 脚本、故障排查的前提。

```text
命令三分类：
1. 增删改查 —— ls/cd/pwd/mkdir/touch/cp/mv/rm/rmdir，管文件本身的创建移动删除
2. 查看内容 —— cat/less/more/head/tail/nl/od/hexdump，管文件内容的显示
3. 查找定位 —— find/locate/which/whereis/type，管文件在哪、命令是哪个
```

## 核心概念

1. **增删改查**：cp 加 -a 保留属性（权限/时间戳/软链），mv 改名和移动同一条命令，rm 没有回收站、删了基本找不回，rmdir 只能删空目录。
2. **查看内容**：cat 一次输出全文（小文件），less 交互分页（大文件、能搜索），head/tail 看头看尾、tail -f 实时跟踪，od/hexdump 用八进制/十六进制看二进制。
3. **查找定位**：find 实时遍历（条件灵活但慢），locate 查索引（秒出但可能过期），which/whereis/type 查「命令」不是「文件」。

```text
查看命令分工：
1. cat —— 一次输出全文，-n 加行号，适合小文件或拼接（cat a b > c）
2. less —— 交互分页，/搜索、g 开头、G 结尾、q 退出，大文件首选
3. more —— 简化版分页器，只能向前，功能弱于 less
4. head/tail —— -n 取行数、-c 取字节数，tail -f 实时跟踪追加
5. nl —— 输出带行号，od/hexdump —— 八进制/十六进制看二进制
```

```text
查找命令分工：
1. find —— 实时遍历，按 -name/-type/-size/-mtime 过滤，-exec 对结果执行操作
2. locate —— 查索引数据库，秒出但需 updatedb 更新，新建文件可能搜不到
3. which —— 找 PATH 里的可执行文件，whereis —— 连 man/源码一起定位
4. type —— 判断命令类型（shell 内置 / 别名 / 外部程序）
```

### 增删改查命令逐个拆解

ls 是「列目录内容」：默认不显示点开头的隐藏文件，要 `-a` 才带上；`-l` 长格式看权限/属主/大小/时间，`-h` 把大小转成可读单位，`-t` 按修改时间排序、`-S` 按大小排序、`-R` 递归列子目录、`-d` 只看目录本身而非其内容、`-i` 显示 inode 号。

```shell
ls -l            # 长格式：权限 链接数 属主 属组 大小 时间 名字
ls -la           # 长格式 + 含隐藏文件
ls -lhS          # 可读大小 + 按大小倒序
ls -lt           # 按修改时间倒序
ls -ld /tmp      # 只看 /tmp 目录本身的属性，不展开其内容
ls -li           # 第一列显示 inode 号
```

要点：`ls -d` 最容易记错——不带 `-d` 时 `ls /tmp` 列的是 /tmp 里面的东西，带 `-d` 才列 /tmp 这个目录项本身；隐藏文件只是「点开头」的普通文件，不是系统保留，`.bashrc`、`.gitignore` 都属此类。

cd / pwd 是「切换目录 / 打印当前目录」：cd 是 shell 内置命令（`which cd` 找不到外部程序），pwd 有逻辑路径和物理路径之分——`pwd -P` 会解析符号链接给出真实物理路径。

```shell
cd /var/log       # 切到绝对路径
cd ~              # 回家目录（等价 cd）
cd -              # 回上一个目录（shell 记住的 OLDPWD）
cd ..             # 上级目录
pwd               # 打印当前目录（逻辑路径）
pwd -P            # 打印物理路径（符号链接解析后的真实路径）
```

要点：`cd` 进目录需要对该目录有 `x`（执行）权限，只有 `r` 权限能 `ls` 目录名但进不去；`cd -` 依赖 shell 变量 `OLDPWD`，在脚本里不一定可靠。

mkdir / touch 是「建目录 / 建空文件（或更新时间戳）」：mkdir 用 `-p` 递归建父目录，`-m` 直接指定权限；touch 更准确的定位是「把访问/修改时间设为当前」，文件不存在才顺带创建，对已存在文件 touch 不会清空内容。

```shell
mkdir -p /data/app/logs     # 递归创建多级目录，父目录不存在也不报错
mkdir -m 750 /data/secure   # 建目录并直接指定权限 750
touch newfile.txt           # 创建空文件
touch -a file.txt           # 只更新 atime（访问时间）
touch -m file.txt           # 只更新 mtime（修改时间）
touch -t 202608182136 file.txt   # 指定时间戳（YYYYMMDDhhmm）
```

要点：touch 对已存在的文件只是刷新时间戳、不覆盖内容，很多脚本用 `touch` 当「标记文件/心跳」；mkdir 不带 `-p` 时父目录缺失会直接报 `No such file or directory`。

cp 是「复制」：`-r` 递归复制目录（但不保留属性），`-p` 保留权限/时间戳，`-a` 是归档模式（等价 `-dpR`，连软链、属性一起保留），`-i` 覆盖前询问，`-n` 不覆盖已存在文件，`-u` 只复制源比目标新的文件。

```shell
cp file.txt file.txt.bak     # 复制文件
cp -r dir1 dir2              # 递归复制目录（不保留属性）
cp -a dir1 dir2              # 归档复制：保留权限/时间戳/软链，备份首选
cp -i a.txt b.txt            # 目标已存在时先确认
cp -u src/* dest/            # 只复制更新的文件（增量）
cp file1 file2 dest/         # 一次复制多个源到目录
```

要点：复制目录千万别只用 `cp -r`（丢权限、时间戳变），备份用 `cp -a` 或 `tar -p`；`cp` 覆盖已存在目标默认不提示，重要文件加 `-i` 或配别名 `alias cp='cp -i'`。

mv 是「移动/改名」：同分区只改目录项（秒级），跨分区是复制+删除（慢）；`-i` 覆盖确认，`-b` 覆盖前备份，`-n` 不覆盖。

```shell
mv a.txt b.txt        # 改名
mv file.txt /tmp/     # 移动
mv dir1 dir2          # dir2 不存在 = 改名；dir2 存在 = 移进 dir2 里面
mv -i a.txt b.txt     # 覆盖前确认
```

要点：mv 移动目录时目标已存在会变成「移进目标目录里」而不是覆盖，这点和 cp 语义一致但容易想错；mv 不能跨分区「秒完成」，大目录跨盘要等完整读写。

rm / rmdir 是「删除」：rm 删文件/目录（-r 递归、-f 强制、-i 确认），没有回收站；rmdir 只能删空目录，删不空会报错。

```shell
rm file.txt           # 删文件
rm -r dir             # 递归删目录
rm -f file.txt        # 强制删除，不提示
rmdir emptydir        # 删空目录
rmdir -p a/b/c        # 连同空的父目录一起删（逐级删到非空为止）
```

要点：rm 不可逆，生产上删前先 `ls` 确认目标、`rm -rf` 的变量路径先校验非空；rmdir 能删的一定是空目录，删有内容的目录会报 `Directory not empty`。

### 查看命令逐个拆解

cat 是「连接并输出全文」：适合小文件、拼接多个文件、配合重定向生成文件；`-n` 全部行号、`-b` 只给非空行编号、`-s` 压缩连续空行、`-A` 显示所有不可见字符（行尾 `$`、Tab 为 `^I`）。

```shell
cat file.txt                    # 输出全文
cat -n file.txt                 # 带行号
cat -A file.txt                 # 显示行尾/制表符等不可见字符
cat part1.txt part2.txt > all.txt   # 拼接多个文件
cat >> file.txt << 'EOF'        # 追加写（配合 heredoc）
some text
EOF
```

要点：cat 会把整个文件一次性刷到终端，几 GB 日志会卡死；`cat -A` 是排查「行尾是 CRLF 还是 LF」「有没有多余空格」的利器。

less 是「交互分页查看」：大文件首选，按需加载不占内存，支持前后翻页和搜索；常用按键 `/` 搜索、`n` 下一个匹配、`g` 开头、`G` 结尾、`b` 上翻、空格下翻、`q` 退出。

```shell
less /var/log/syslog            # 交互查看
less -N file.txt                # 带行号
less -S file.txt                # 长行不折行，左右方向键滚动
less +G file.txt                # 直接跳到末尾（看日志尾部）
```

要点：less 支持「边读边搜」，看日志时 `/ERROR` 秒定位；`-S` 不折行对宽表格很重要，否则列全被折乱。

more 是「简化分页器」：只能向前翻（less 的前身），功能弱于 less，space 下翻、`b` 回翻、`/` 搜索、`q` 退出。现在基本被 less 取代，只在极小环境（busybox）里还有存在感。

head / tail 是「看头看尾」：`-n` 取行数（正数从头/尾取、`-n +N` 从第 N 行开始）、`-c` 取字节数，tail 的 `-f` 实时跟踪追加、`-F` 跟踪时文件被轮转（改名/重建）仍继续跟。

```shell
head -n 20 file.txt             # 前 20 行
head -c 100 file.txt            # 前 100 字节
tail -n 50 /var/log/syslog      # 最后 50 行
tail -n +10 file.txt            # 从第 10 行开始到最后（跳过前 9 行）
tail -f /var/log/syslog         # 实时跟踪追加
tail -F /var/log/syslog         # 文件被 logrotate 轮转后仍继续跟
```

要点：`tail -n +N` 是从第 N 行开始（含 N），别和 `-n N` 混淆；`-f` 跟的是 inode，日志轮转后可能跟丢，`-F` 会按文件名重新打开，生产看日志用 `-F` 更稳。

nl 是「带行号输出」：比 `cat -n` 精细，默认只给非空行编号；`-ba` 全编号、`-bt` 只非空行、`-n ln/rn/rz` 控制对齐方式（左对齐/右对齐/右对齐补零）。

```shell
nl file.txt                     # 只给非空行编号
nl -ba file.txt                 # 所有行都编号（含空行）
nl -n rz file.txt               # 行号右对齐补零（0001, 0002...）
cat -n file.txt                 # 对比：cat -n 给所有行编号
```

要点：nl 默认跳过空行、`cat -n` 不跳过，这就是两者输出的差异；看代码行号用 `nl -ba` 或 `cat -n` 都行。

od / hexdump 是「按八进制/十六进制看二进制」：od 格式丰富（`-c` 字符、`-x` 十六进制、`-o` 八进制、`-t x1` 指定字节格式），hexdump 的 `-C` 是「十六进制 + ASCII 对照」的经典格式。

```shell
od -c a.bin | head              # 八进制看字符（含转义）
od -x a.bin | head              # 十六进制（2 字节一组）
od -t x1 a.bin | head           # 十六进制（1 字节一组）
hexdump -C a.bin | head         # 十六进制 + ASCII 对照，最直观
xxd a.bin | head                # xxd 也是十六进制查看器，可反向还原
```

要点：od 默认是八进制，`-t x1` 才是逐字节十六进制，别被默认输出搞混；看二进制魔数、协议头、不可见字符用 `hexdump -C` 最直观。

### 查找命令逐个拆解

find 是「实时遍历文件系统树」：按名字、类型、大小、时间、权限、属主等条件过滤，还能用 `-exec`/`-delete` 对结果执行操作；缺点是慢（全盘遍历 IO 重）。

```shell
find /var/log -name "*.log" -type f        # 按名字 + 类型
find /var/log -type f -mtime -7            # 7 天内修改的
find /var/log -type f -mmin -60            # 60 分钟内修改的
find /tmp -type f -size +100M              # 大于 100MB 的
find /tmp -type f -size -1k                # 小于 1KB 的
find / -type f -perm -4000 2>/dev/null     # 查找 SUID 文件
find / -user www-data -type f 2>/dev/null  # 按属主查找
find . -maxdepth 2 -type d                 # 限制递归深度
```

要点：find 默认递归所有子目录，大范围查找务必加 `-maxdepth` 限制或 `2>/dev/null` 压掉无权限目录的报错；`-mtime -7` 是「7 天以内」，`+7` 是「7 天以前」，方向别记反。

`-exec` 对每个匹配执行命令：`\;` 逐个执行（慢）、`+` 批量传参（快，类似 xargs）；处理含空格文件名用 `-print0` 配 `xargs -0`。

```shell
find /var/log -name "*.gz" -exec rm {} \;    # 逐个删除
find /var/log -name "*.gz" -exec rm {} +     # 批量删除（更快）
find . -type f -name "*.log" -exec wc -l {} +   # 批量统计行数
find . -print0 | xargs -0 rm                  # 安全处理含空格文件名
find . -type f -name "*.tmp" -delete          # 用 find 内置 delete 更高效
```

要点：`-exec ... \;` 和 `-exec ... +` 的区别是「每个文件跑一次」vs「把文件攒一批一次跑」，海量文件时后者快一个量级；含空格/特殊字符文件名必须走 `-print0 | xargs -0`。

locate 是「查索引数据库」：秒出但依赖 updatedb 预建的索引（mlocate/plocate），新建文件要等索引刷新才搜得到；适合「大概记得文件名」的快速定位。

```shell
updatedb && locate nginx.conf      # 先刷新索引再秒查
locate -i "*.conf"                 # 忽略大小写
locate -l 20 syslog                # 只显示前 20 条
```

要点：locate 查的是 `/var/lib/mlocate/mlocate.db`（或 plocate 对应路径）的快照，不是实时文件系统；刚建的文件、刚删的文件都可能和索引不一致，精确查找用 find。

which / whereis / type 是「查命令」而非「查文件」：which 在 `$PATH` 里找可执行文件（`-a` 显示全部命中），whereis 连 man 手册和源码一起定位，type 判断命令到底是 shell 内置、别名、函数还是外部程序。

```shell
which python3                     # PATH 里的位置
which -a python3                  # 显示 PATH 里所有同名命中
whereis ls                        # 二进制 + man + 源码
whereis -b ls                     # 只看二进制
type cd                           # cd is a shell builtin（shell 内置）
type -t ls                        # 输出类型词：alias/builtin/file...
type -a ls                        # 列出所有定义（别名 + 外部程序）
```

要点：which 找不到不代表命令不能用——shell 内置（cd、echo）和别名（ll）which 都查不到，此时用 type 判断；`type -t` 输出的词（alias/keyword/function/builtin/file）是脚本里判断命令来源的标准手段。

## 工作原理

文件操作底层有两个关键机制值得理解：一是 mv——同分区移动只改目录项（秒完成），跨分区移动是「复制 + 删除」（要完整读写数据，大目录极慢）；二是 find vs locate——find 实时遍历文件系统树（慢但准），locate 查 updatedb 预建的索引数据库（快但可能过期，刚建的文件查不到）。理解这两个机制，就能解释「为什么 mv 有时秒有时慢」「为什么 locate 搜不到新文件」。

```text
两个底层机制：
1. mv 同分区 = 改目录项指针，不搬数据（秒级）；跨分区 = 复制到目标 + 删源（受 IO 限制）
2. find = 实时遍历目录树；locate = 查 updatedb 索引（定时/手动刷新，有延迟）
```

除这两个，还有两个机制决定了「文件操作」的边界，值得一并理解：

**路径解析（namei）**：内核按「目录项 → inode」逐级解析路径。`/var/log/syslog` 要先读 `/` 的 inode 找到 `var` 目录项，再读 `var` 的 inode 找 `log`，再读 `log` 的 inode 找 `syslog`。这意味着：路径里任何一级目录缺 `x` 权限，都会中断解析（表现为 `Permission denied` 或 `No such file or directory`）；符号链接会在解析中被「展开」成目标路径。

**删除的本质**：`rm` 不是抹掉文件内容，而是调用 `unlink` 断开目录项与 inode 的链接（链接数 -1）。当链接数归零且没有进程持有该 inode 时，数据块才被标记为空闲。所以「rm 了文件但进程还开着句柄，磁盘不释放」——这和 02.4 讲的 inode/链接数是一回事。

```text
路径解析链路：
/var/log/syslog → 读 / 的 inode → 找 var 目录项 → 读 var 的 inode → 找 log 目录项 → 读 log 的 inode → 找 syslog 目录项
删除链路：rm = unlink（目录项-1）→ 链接数=0 且无进程占用 → 数据块释放
```

## 常用命令与配置

```shell
# 创建与移动
mkdir -p /tmp/demo/sub
touch /tmp/demo/a.txt /tmp/demo/b.txt
cp -a /tmp/demo /tmp/demo.bak       # 归档复制，保留所有属性
mv /tmp/demo/a.txt /tmp/demo/c.txt  # 改名
rm -rf /tmp/demo.bak                # 递归删除

# 看目录
ls -lah /tmp/demo                   # 详细 + 隐藏 + 可读大小
ls -lt                              # 按修改时间倒序
```

```shell
# 看小文件与拼接
cat -n /etc/hosts
cat part1.txt part2.txt > all.txt

# 看大文件（日志）
less /var/log/syslog        # / 搜索关键词，G 跳结尾
tail -n 50 /var/log/syslog  # 最后 50 行
tail -f /var/log/syslog     # 实时跟踪，Ctrl+C 退出

# 看二进制 / 不可见字符
hexdump -C a.bin | head     # 十六进制 + ASCII
od -c a.bin | head          # 八进制看字符
```

```shell
# find 按条件查找
find / -name "*.log" -type f 2>/dev/null          # 按名字
find /var/log -type f -mtime -7                    # 7 天内修改的
find /tmp -type f -size +100M                      # 大于 100MB 的
find /var/log -name "*.gz" -exec rm {} \;          # 找到并删除

# 数据库查找与命令定位
updatedb && locate nginx.conf                     # 更新索引后秒查
which python3                                       # PATH 里的位置
whereis ls                                          # 命令 + man + 源码
type cd                                             # cd 是 shell 内置
```

```shell
# ls 的排序与过滤技巧
ls -lS /var/log | head -10          # 最大的 10 个文件
ls -lt /var/log | head -10          # 最新修改的 10 个
ls -R /etc | grep -i nginx          # 递归查找（比 find 粗略但快）

# 用 stat 批量看文件属性（比 ls -l 信息更全）
stat -c '%n %s %y' /tmp/demo/*.txt  # 文件名 大小 修改时间
```

## 应用场景实战

### 场景一：找出 /var/log 下最近 3 天修改过的大日志文件并归档

```shell
# 1. 找最近 3 天修改、大于 50MB 的日志
find /var/log -type f -name "*.log" -mtime -3 -size +50M

# 2. 逐个看行数，确认要处理
find /var/log -type f -name "*.log" -size +50M -exec wc -l {} \;

# 3. 归档（压缩）后删除原文件释放空间
find /var/log -type f -name "*.log" -size +50M -exec gzip {} \;
ls -lh /var/log/*.log.gz
```

## 性能与调优

```text
文件操作的性能优化：
1. find 提速 —— -prune 排除大目录（如 .git/node_modules），别全盘裸扫；加 -maxdepth 限制深度
2. locate 秒查 —— 频繁查找时先 updatedb 建索引，比 find 快几个量级
3. cp 大目录用 -a + rsync —— 复制保属性用 cp -a，增量同步用 rsync（只传差异）
4. 大文件读用 less —— 别 cat 几 GB 日志，less 按需加载不占内存
5. tail -f 加 grep —— 实时日志先过滤再输出，减少 IO 和刷屏
6. -exec + 代替 -exec \; —— 海量文件批量处理时，把逐进程调用换成批量传参，省掉大量 fork 开销
7. 用 find -delete 代替 -exec rm —— find 内置删除不走 fork，比外部 rm 更快
8. 统计行数用 wc -l，别用 cat | wc —— 省一次管道和 cat 进程
```

## 安全与权限

```text
文件操作安全要点：
1. rm 无回收站 —— 删除前 ls 确认，rm -rf 变量路径前先校验非空，防 rm -rf / 事故
2. find -exec 防注入 —— 文件名含空格/特殊字符会断参数，用 -print0 | xargs -0
3. cp/mv 覆盖确认 —— cp -i / mv -i 交互确认，防静默覆盖重要文件
4. 权限最小化 —— 删除/修改系统目录文件要 root，日常用普通用户 + sudo
5. 敏感文件不留明文 —— 备份/传输配置含密码时加密，临时文件用完即删
6. 用 trash-cli 或 safe-rm 软删除 —— 给 rm 加一层回收站/黑名单保护，防误删
7. 进目录要 x 权限 —— cd 目录需要 x（搜索）权限，ls 目录内容需要 r 权限，两者独立
```

## 故障排查

```shell
# 1. 文件找不到
find / -name "<文件名>" 2>/dev/null     # 兜底全盘找
locate <文件名>                          # 先秒查（记得 updatedb）

# 2. 权限拒绝（Permission denied）
ls -l <文件>          # 看属主属组和权限位
ls -ld <目录>         # 目录权限拒绝时看目录本身（缺 x 权限）

# 3. mv 大目录极慢
df -h <源> <目标>     # 看是否跨分区，跨分区 mv = 复制 + 删除

# 4. 删了文件磁盘不释放
lsof +L1 | grep deleted    # 找被进程占用的已删文件

# 5. mkdir/touch 失败
df -h <路径>          # 看磁盘是否满（No space left on device）
mount | grep <路径>   # 看是否是只读挂载（Read-only file system）
```

## 常见问题

```text
Q1: mv 为什么有时瞬间完成、有时很慢？
A: 同分区 mv 只改目录项（秒级），跨分区 mv 是复制 + 删除（受 IO 限制，大目录慢）。

Q2: locate 为什么搜不到刚创建的文件？
A: locate 查 updatedb 的索引快照，新文件还没入索引，先 updatedb 刷新或改用 find。

Q3: 删文件有回收站吗？
A: 没有。rm 删了基本找不回，重要文件删前备份，生产用 trash-cli 之类的软删除方案。

Q4: which 和 whereis 区别？
A: which 只找 PATH 里的可执行文件，whereis 连 man 手册和源码一起定位。

Q5: cp -r 和 cp -a 区别？
A: -r 只递归复制，-a 归档模式（递归 + 保留权限/时间戳/软链），备份目录用 -a。

Q6: which cd 为什么查不到？
A: cd 是 shell 内置命令，不是外部程序，which 只在 PATH 里找可执行文件；用 type cd 判断（显示 builtin）。

Q7: find 的 -exec {} \; 和 -exec {} + 有什么区别？
A: \; 是「每个文件跑一次命令」（慢、fork 多），+ 是「把文件攒一批一次传参」（快、类似 xargs）。

Q8: tail -n +10 是什么意思？
A: 从第 10 行开始输出到最后（跳过前 9 行）；带 + 号表示「从第 N 行起」，不带表示「取 N 行」。
```

## 面试题

```text
1. 找出 /var/log 下大于 100MB 且 7 天前修改的文件？
   答：find /var/log -type f -size +100M -mtime +7

2. find 和 locate 的区别？
   答：find 实时遍历文件系统（慢但准），locate 查索引数据库（快但可能过期）。

3. 怎么批量把 .txt 改成 .md？
   答：for f in *.txt; do mv "$f" "${f%.txt}.md"; done，或 rename 's/\.txt$/.md/' *.txt

4. 查看大日志文件用什么命令？
   答：less（交互分页、可搜索），tail -f 实时跟踪追加内容，别用 cat 刷屏。

5. 为什么 find -exec 处理含空格文件名会出错？怎么解决？
   答：shell 按空格分词把文件名拆断；用 find ... -print0 | xargs -0 处理。

6. 怎么找出当前目录下最大的 10 个文件？
   答：find . -type f -exec ls -lh {} \; | sort -k5 -rh | head -10，或 ls -lS | head -10（不递归）。

7. 统计一个文件有多少行用什么命令？
   答：wc -l file.txt；要看带行号的内容用 cat -n 或 nl -ba。

8. touch 命令有什么用？
   答：创建空文件；已存在的文件则更新其访问/修改时间戳（-a 只改 atime、-m 只改 mtime），不会清空内容。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 大文件用 less 分页看，别用 cat 把几 GB 日志刷屏
2. 删文件前先 ls 确认目标，rm -rf 加绝对路径、别手滑带空格的变量
3. 复制目录要保留属性用 cp -a，别用 cp -r（会丢权限和时间戳）
4. 找文件能用 locate 先秒查，查不到再 find 实时遍历
5. 看日志跟踪用 tail -f，配 grep 过滤更高效（tail -f log | grep ERROR）
6. 海量文件批量删除用 find -delete 或 -exec rm {} +，别用 \; 逐个 fork
7. 判断命令来源用 type，别用 which（which 查不到 shell 内置和别名）
8. 统计文件行数/字节用 wc，查看二进制用 hexdump -C，别用 cat 读二进制

### 踩坑记录

```text
坑 1：rm -rf $DIR/ 当 DIR 为空变量，误删根目录
结论：变量没赋值，rm -rf / 把系统删光。
原因：脚本里 DIR 变量为空，路径变成 /，-f 又不提示。
解法：删之前 echo "$DIR" 校验非空，或用 rm -rf "/opt/$DIR" 限定父目录。

坑 2：find -exec 结果里带空格文件名导致命令断错
结论：文件名含空格，-exec {} 执行时参数被拆分。
原因：{} 未加引号，shell 按空格分词。
解法：用 find ... -print0 | xargs -0，或 -exec 里给 {} 加引号。

坑 3：cp -r 复制后文件权限和时间戳变了
结论：复制的目录权限丢失，时间戳全变成复制时间。
原因：cp -r 不保留属性，要用 -p 或 -a。
解法：目录备份用 cp -a（归档模式），或 tar -p。

坑 4：locate 搜不到刚创建的文件
结论：刚 touch 的文件 locate 查不到。
原因：locate 查的是 updatedb 的索引快照，新文件还没入索引。
解法：先 updatedb 刷新索引，或改用 find 实时查找。

坑 5：用 cat 查看大日志导致终端卡死
结论：几 GB 的日志 cat 一刷，终端直接卡住。
原因：cat 无分页，一次性输出全部内容。
解法：大文件用 less，或 tail/head 只看需要的部分。

坑 6：mv 跨文件系统移动大目录极慢
结论：把大目录 mv 到另一块盘，卡了十几分钟。
原因：跨文件系统 mv 是「复制 + 删除」，要完整读写数据，不是改目录项。
解法：同分区 mv 秒完成；跨分区用 rsync --remove-source-files 或接受复制耗时。

坑 7：用 find -exec rm {} \; 批量删几十万文件，卡到天荒地老
结论：海量小文件逐个 -exec rm，fork 了几十万次进程，慢到像卡死。
原因：\; 让 find 对每个匹配文件都起一个 rm 子进程，进程开销压倒一切。
解法：换成 -exec rm {} +（批量传参）或 find ... -delete（find 内置删除，零 fork）。
```

## 概述

文件与目录操作是 Linux 日常使用最频繁的基本功，分三块：增删改查（ls/cd/mkdir/touch/cp/mv/rm）、查看内容（cat/less/head/tail/od/hexdump）、查找定位（find/locate/which/whereis/type）。它们组合起来能覆盖绝大多数「文件在哪、内容是什么、怎么搬怎么删」的场景。熟练这些命令是后面学文本三剑客、Shell 脚本、故障排查的前提。

```text
命令三分类：
1. 增删改查 —— ls/cd/pwd/mkdir/touch/cp/mv/rm/rmdir，管文件本身的创建移动删除
2. 查看内容 —— cat/less/more/head/tail/nl/od/hexdump，管文件内容的显示
3. 查找定位 —— find/locate/which/whereis/type，管文件在哪、命令是哪个
```

## 核心概念

1. **增删改查**：cp 加 -a 保留属性（权限/时间戳/软链），mv 改名和移动同一条命令，rm 没有回收站、删了基本找不回，rmdir 只能删空目录。
2. **查看内容**：cat 一次输出全文（小文件），less 交互分页（大文件、能搜索），head/tail 看头看尾、tail -f 实时跟踪，od/hexdump 用八进制/十六进制看二进制。
3. **查找定位**：find 实时遍历（条件灵活但慢），locate 查索引（秒出但可能过期），which/whereis/type 查「命令」不是「文件」。

```text
查看命令分工：
1. cat —— 一次输出全文，-n 加行号，适合小文件或拼接（cat a b > c）
2. less —— 交互分页，/搜索、g 开头、G 结尾、q 退出，大文件首选
3. more —— 简化版分页器，只能向前，功能弱于 less
4. head/tail —— -n 取行数、-c 取字节数，tail -f 实时跟踪追加
5. nl —— 输出带行号，od/hexdump —— 八进制/十六进制看二进制
```

```text
查找命令分工：
1. find —— 实时遍历，按 -name/-type/-size/-mtime 过滤，-exec 对结果执行操作
2. locate —— 查索引数据库，秒出但需 updatedb 更新，新建文件可能搜不到
3. which —— 找 PATH 里的可执行文件，whereis —— 连 man/源码一起定位
4. type —— 判断命令类型（shell 内置 / 别名 / 外部程序）
```

4. **目录项（directory entry）与 inode 是两回事**：目录本身也是一种文件，内容是「名字 → inode 号」的映射表。所以「改名、移动同分区目录」只改这张映射表，不碰数据；而 `basename`/`dirname` 这类工具纯做字符串切分，完全不访问文件系统——`basename /no/such/path` 一样能输出 `path`。

```text
目录项的语义：
1. 目录 = 名字到 inode 的映射表（不是"文件列表"）
2. basename/dirname 只切字符串，不 stat 文件，路径不存在也照样输出
3. realpath/readlink -f 会真的去解析每一级（要存在 + 有 x 权限）
4. 同分区 mv = 改映射表；跨分区 mv = 复制数据 + 删旧目录项
```

5. **通配符展开（globbing）是 shell 干的，不是命令干的**：`ls *.txt` 里的 `*` 由 shell 在调用 ls 之前展开成文件名列表，ls 收到的已经是具体参数。这也解释了为什么「命令没找到文件」时报错的其实是 shell（`No match` / `未找到匹配`），以及为什么 `echo *` 能列出文件名。

```text
globbing 关键点：
1. * —— 匹配任意长度（不含 /），? —— 匹配单个字符，[abc]/[a-z] —— 字符集
2. 展开发生在 fork/exec 之前，命令根本不知道你写了通配符
3. 用引号（'*' / "*" / \*）阻止展开，把字面量交给命令
4. 引号只阻止 glob，不阻止变量展开（双引号内 $VAR 仍展开，单引号才全锁）
```

6. **花括号展开 `{}` 与通配符不是一回事**：`{a,b}{1,2}` 展开成 `a1 a2 b1 b2`，它不检查文件是否存在、纯字符串笛卡尔积；`{1..5}`、`{a..e}`、`{01..10..2}` 还能生成序列。常用于批量建目录、批量备份。

```text
brace expansion 特点：
1. 纯字符串展开，不做文件名匹配，路径不存在也照样展开
2. 支持序列 {1..5}、带步长 {0..10..2}、补零 {01..10}
3. 展开顺序在变量展开之前，所以 x={a,b}; echo $x 得到 {a,b} 而不是 a b
4. 引号能阻止它：echo "{a,b}" 原样输出 {a,b}
```

7. **展开顺序决定了脚本里那些"看起来莫名其妙"的结果**：bash 依次做 花括号展开 → 波浪号展开 → 参数/变量展开、命令替换、算术展开 → 分词（word splitting）→ 通配符展开 → 去引号。所以 `f="a b"; ls $f` 会被拆成两个参数，而 `ls "$f"` 才是一个。

```text
bash 展开顺序（背下来能解释 80% 的脚本 bug）：
brace → tilde(~) → 变量/命令替换/算术 → word splitting → glob → 去引号
推论：
1. 变量不加引号会被分词 + glob，含空格路径必须 "$var"
2. 通配符展开在变量展开之后，所以 f='*.txt'; echo $f 会真的展开
3. IFS 控制 word splitting 用的分隔符（默认 空格/Tab/换行）
```

8. **argv 有硬上限：单条命令的参数总长不能超过 ARG_MAX**：本机 `getconf ARG_MAX` = 2097152（2MiB），单个参数上限 128KiB（MAX_ARG_STRLEN）。超了就是经典的 `Argument list too long`（errno E2BIG）。

```text
# 本机实测（Ubuntu 24.04.4 LTS，内核 7.0.0-28-generic）
$ getconf ARG_MAX
2097152
$ /bin/true $(seq 1 400000)
/usr/bin/bash: 行 5: /bin/true: 参数列表过长
（退出码 126）
$ /bin/true $(seq 1 1000)
（正常返回 0）
解读：约 40 万个短参数就超过 2MiB 上限；解法是 xargs / find -exec + 分批传参。
```

9. **逻辑大小与占用块数是两个数**：`ls -l` 给的是逻辑大小（st_size），`ls -s` / `du` 给的是实际占用的块（st_blocks×512B）。一个 3 字节的文件也占 4KiB，一个 1GiB 的稀疏文件可能只占几十 KiB。

```text
# 本机实测
$ ls -lsh /usr/bin/ls /tmp/w23/a/b/c/x.txt
4.0K -rw-r--r-- 1 root root    3  9月 12 11:21 /tmp/w23/a/b/c/x.txt
140K -rwxr-xr-x 1 root root 139K  8月 25 23:09 /usr/bin/ls
解读：3 字节的文件在 ext4 上按最小块占 4KiB；ls 的"139K"是逻辑大小，
du 报的 140K 是块数换算——所以 du 与 ls -l 经常"对不上"，正常现象。
```

10. **稀疏文件（sparse file）与空洞**：`truncate -s 1G` 只改 inode 里的逻辑长度，不实际写 1GiB 数据（中间是空洞），所以瞬间完成、几乎不占盘；只有真正写入的位置才分配块。虚拟机镜像、日志预分配文件常靠它省空间。

```text
稀疏文件要点（示例，本机策略不允许执行破坏性命令）：
1. truncate -s 1G big.img —— 建 1GiB 逻辑大小、实际占 0 块的空洞文件
2. truncate -s +1M f / truncate -s -1M f —— 相对扩/缩（+ - 前缀）
3. truncate -r ref f —— 把 f 截断成与 ref 同样大小（对齐镜像常用）
4. 真实数据只占写入过的块；ls -l 看 1G，du 可能只报 0
5. 复制时 cp 默认会"填实"空洞（除非 --sparse=always / cp -a 保留稀疏）
```

11. **三个时间戳 atime / mtime / ctime 分工不同**：atime 是上次读取、mtime 是内容上次修改、ctime 是 inode 元数据上次变更（改权限、改属主、改链接数都会动 ctime，但它**不是**创建时间）。Ubuntu 默认 `relatime` 挂载，只在 atime 比 mtime 旧或超过 24h 时才更新 atime，省 IO。

```text
# 本机实测
$ stat -c 'atime=%x mtime=%y ctime=%z' /tmp/w23/a/b/c/x.txt
atime=2026-09-12 11:21:59.537609850 +0800
mtime=2026-09-12 11:21:59.538863258 +0800
ctime=2026-09-12 11:21:59.538863258 +0800
$ findmnt -no SOURCE,FSTYPE,OPTIONS /
/dev/sda2 ext4   rw,relatime
要点：
1. chmod/chown 只动 ctime，不动 mtime —— 用 mtime 判断"内容有没有改"更准
2. relatime 下 atime 不会每次读都更新，别用 atime 做"精确访问审计"
3. touch -a 改 atime、touch -m 改 mtime、touch -d '时间' 指定时刻
```

12. **元数据（inode）与数据块分离设计**：权限、属主、时间、大小、块指针全在 inode 里，文件名在目录项里，内容在数据块里。这就是「同一文件可以有多个名字（硬链接）」「改名不影响内容与句柄」的根本原因。

```text
inode 三件套（配合 02.4 一起看）：
1. 目录项 —— 名字 + inode 号（可多个名字指向同一 inode = 硬链接）
2. inode —— 权限/属主/时间/大小/块指针/链接计数
3. 数据块 —— 真正的内容
推论：stat 的 %h 是链接计数；ls -l 第二列就是它；rm 只是把计数 -1
```

13. **临时文件的正确姿势是 mktemp，不是手拼文件名**：`/tmp/fixed_name` 有符号链接攻击和并发生成重名两大风险。`mktemp` 用 O_EXCL 语义生成唯一文件（默认 600 权限），临时目录用 `-d`；`$TMPDIR` 决定落盘位置（本机为空则落 `/tmp`）。

```text
# 本机实测
$ mktemp -d
/tmp/tmp.SE4aeAZQFb
$ ls -ld /tmp/tmp.SE4aeAZQFb
drwx------ 2 root root 4096  9月 12 11:21 /tmp/tmp.SE4aeAZQFb
$ mktemp -t myprog.XXXXXX
/tmp/myprog.TfPrbf
$ mktemp --suffix=.log /tmp/xxx.XXXX
/tmp/xxx.WOqY.log
$ echo "TMPDIR=${TMPDIR:-（未设置，默认 /tmp）}"
TMPDIR=（未设置，默认 /tmp）
要点：-t 模板落在 ${TMPDIR:-/tmp}；XXXXXX 至少 3 个 X；文件 600、目录 700
```

14. **原子替换靠 rename(2)**：同目录下「写临时文件 → `mv` 覆盖目标」是运维发版、重写配置的标准动作，因为 `rename` 是原子操作，读方要么看到旧内容要么看到新内容，不会看到半个文件。`sed -i`、`cp --backup`、`rsync` 落盘都依赖这一机制。

```text
原子写文件模板（示例）：
1. tmp=$(mktemp /etc/nginx/nginx.conf.XXXXXX)
2. 生成新内容到 $tmp（此时线上文件一直可用）
3. chmod/chown 对齐原文件属性
4. mv -f $tmp /etc/nginx/nginx.conf   ← 同分区 rename，原子生效
前提：临时文件必须和目标是同一个文件系统，跨设备 rename 会 EXDEV 失败
（coreutils 的 mv 会自动退化成 cp+unlink，就不再原子了）
```

15. **FIFO（命名管道）是唯一一种"没有内容"的文件**：`mkfifo` 建出的文件大小为 0，打开读端会阻塞直到有写端，反之亦然。它用于进程间通信（`tail -f x | ...` 的替代、日志收集、cron 触发脚本）。

```text
# 本机实测
$ mkfifo p23
$ ls -l p23
prw-r--r-- 1 root root 0  9月 12 11:25 p23      ← 类型位是 p（pipe）
$ stat -c '%F %s bytes %a' p23
先进先出文件 0 bytes 644
要点：大小恒为 0；没有读写端时 open 会阻塞；mkfifo -m 660 控制权限
```

16. **删除的语义是 unlink，不是"擦除"**：`rm` 断开目录项与 inode 的链接，链接数为 0 且无进程持有句柄时才回收数据块。所以「rm 完 df 不降」「rm 完还能用 /proc/<pid>/fd 恢复」都是这个机制的直接结果。要真擦数据得用 `shred`，而它在 SSD/日志文件系统上并不可靠。

```text
删除链路与保护：
1. rm → unlink(2) → 链接数 -1 → 若为 0 且无持有者 → 数据块入空闲链表
2. 进程还开着句柄时块不释放：lsof +L1 能列出这些 (deleted) 文件
3. rm --preserve-root（GNU 默认开启）拦 rm -rf /
4. --one-file-system 让递归删除不跨挂载点，防误删挂载进来的盘
5. 想要回收站：trash-cli（trash-put）或 safe-rm 黑名单
```

17. **现代替代工具（fd / bat / eza）不是取代关系，而是补默认值**：fd 默认忽略 .gitignore + 隐藏文件、输出彩色、语法比 find 短；bat 是带高亮和行号的 cat；eza 是颜色/图标更强、能显示 git 状态的 ls。服务器上未必预装，写脚本/排障时仍应以 find/ls/cat 为准（可移植）。

```text
# 本机实测（这三个工具本机未安装）
$ command -v fd fdfind bat batcat eza
（无输出）
$ apt-cache policy fd-find bat | head -8
fd-find:
  已安装：(无)
  候选： 9.0.0-1
bat:
  已安装：(无)
  候选： 0.24.0-1build1
选型对照：
1. find → 脚本/可移植/精细条件；fd → 交互式日常查找（apt install fd-find，命令名 fdfind）
2. ls → 脚本解析用；eza → 人看（apt install eza 或 cargo install eza）
3. cat → 小文件；bat → 人看代码（apt install bat，命令名 batcat，避免与 bacula 冲突）
```

18. **挂载点边界会改变命令的行为**：`/dev/shm`（tmpfs，本机 9.7G）、`/run`（tmpfs 2.0G）、`/boot/efi`（vfat 1.1G）和根分区 `/dev/sda2`（ext4）不是同一个文件系统。mv/cp/rename 的原子性、`rm -rf` 的波及范围、`find` 的遍历深度、`du` 的统计结果，都会因为跨不跨挂载点而完全不同。

```text
# 本机实测（判断"跨不跨文件系统"最直接的办法：比设备号）
$ stat -c 'dev=%d  %n' /tmp /var/lib /root /dev/shm /run /boot/efi
dev=2050  /tmp
dev=2050  /var/lib
dev=2050  /root
dev=29  /dev/shm
dev=28  /run
dev=2049  /boot/efi
解读：dev 相同 = 同文件系统（mv 秒完成），不同 = 跨设备（mv 退化为复制+删除）。
```

### 增删改查命令逐个拆解

ls 是「列目录内容」：默认不显示点开头的隐藏文件，要 `-a` 才带上；`-l` 长格式看权限/属主/大小/时间，`-h` 把大小转成可读单位，`-t` 按修改时间排序、`-S` 按大小排序、`-R` 递归列子目录、`-d` 只看目录本身而非其内容、`-i` 显示 inode 号。

```shell
ls -l            # 长格式：权限 链接数 属主 属组 大小 时间 名字
ls -la           # 长格式 + 含隐藏文件
ls -lhS          # 可读大小 + 按大小倒序
ls -lt           # 按修改时间倒序
ls -ld /tmp      # 只看 /tmp 目录本身的属性，不展开其内容
ls -li           # 第一列显示 inode 号
```

要点：`ls -d` 最容易记错——不带 `-d` 时 `ls /tmp` 列的是 /tmp 里面的东西，带 `-d` 才列 /tmp 这个目录项本身；隐藏文件只是「点开头」的普通文件，不是系统保留，`.bashrc`、`.gitignore` 都属此类。

cd / pwd 是「切换目录 / 打印当前目录」：cd 是 shell 内置命令（`which cd` 找不到外部程序），pwd 有逻辑路径和物理路径之分——`pwd -P` 会解析符号链接给出真实物理路径。

```shell
cd /var/log       # 切到绝对路径
cd ~              # 回家目录（等价 cd）
cd -              # 回上一个目录（shell 记住的 OLDPWD）
cd ..             # 上级目录
pwd               # 打印当前目录（逻辑路径）
pwd -P            # 打印物理路径（符号链接解析后的真实路径）
```

要点：`cd` 进目录需要对该目录有 `x`（执行）权限，只有 `r` 权限能 `ls` 目录名但进不去；`cd -` 依赖 shell 变量 `OLDPWD`，在脚本里不一定可靠。

mkdir / touch 是「建目录 / 建空文件（或更新时间戳）」：mkdir 用 `-p` 递归建父目录，`-m` 直接指定权限；touch 更准确的定位是「把访问/修改时间设为当前」，文件不存在才顺带创建，对已存在文件 touch 不会清空内容。

```shell
mkdir -p /data/app/logs     # 递归创建多级目录，父目录不存在也不报错
mkdir -m 750 /data/secure   # 建目录并直接指定权限 750
touch newfile.txt           # 创建空文件
touch -a file.txt           # 只更新 atime（访问时间）
touch -m file.txt           # 只更新 mtime（修改时间）
touch -t 202608182136 file.txt   # 指定时间戳（YYYYMMDDhhmm）
```

要点：touch 对已存在的文件只是刷新时间戳、不覆盖内容，很多脚本用 `touch` 当「标记文件/心跳」；mkdir 不带 `-p` 时父目录缺失会直接报 `No such file or directory`。

cp 是「复制」：`-r` 递归复制目录（但不保留属性），`-p` 保留权限/时间戳，`-a` 是归档模式（等价 `-dpR`，连软链、属性一起保留），`-i` 覆盖前询问，`-n` 不覆盖已存在文件，`-u` 只复制源比目标新的文件。

```shell
cp file.txt file.txt.bak     # 复制文件
cp -r dir1 dir2              # 递归复制目录（不保留属性）
cp -a dir1 dir2              # 归档复制：保留权限/时间戳/软链，备份首选
cp -i a.txt b.txt            # 目标已存在时先确认
cp -u src/* dest/            # 只复制更新的文件（增量）
cp file1 file2 dest/         # 一次复制多个源到目录
```

要点：复制目录千万别只用 `cp -r`（丢权限、时间戳变），备份用 `cp -a` 或 `tar -p`；`cp` 覆盖已存在目标默认不提示，重要文件加 `-i` 或配别名 `alias cp='cp -i'`。

mv 是「移动/改名」：同分区只改目录项（秒级），跨分区是复制+删除（慢）；`-i` 覆盖确认，`-b` 覆盖前备份，`-n` 不覆盖。

```shell
mv a.txt b.txt        # 改名
mv file.txt /tmp/     # 移动
mv dir1 dir2          # dir2 不存在 = 改名；dir2 存在 = 移进 dir2 里面
mv -i a.txt b.txt     # 覆盖前确认
```

要点：mv 移动目录时目标已存在会变成「移进目标目录里」而不是覆盖，这点和 cp 语义一致但容易想错；mv 不能跨分区「秒完成」，大目录跨盘要等完整读写。

rm / rmdir 是「删除」：rm 删文件/目录（-r 递归、-f 强制、-i 确认），没有回收站；rmdir 只能删空目录，删不空会报错。

```shell
rm file.txt           # 删文件
rm -r dir             # 递归删目录
rm -f file.txt        # 强制删除，不提示
rmdir emptydir        # 删空目录
rmdir -p a/b/c        # 连同空的父目录一起删（逐级删到非空为止）
```

要点：rm 不可逆，生产上删前先 `ls` 确认目标、`rm -rf` 的变量路径先校验非空；rmdir 能删的一定是空目录，删有内容的目录会报 `Directory not empty`。

### 查看命令逐个拆解

cat 是「连接并输出全文」：适合小文件、拼接多个文件、配合重定向生成文件；`-n` 全部行号、`-b` 只给非空行编号、`-s` 压缩连续空行、`-A` 显示所有不可见字符（行尾 `$`、Tab 为 `^I`）。

```shell
cat file.txt                    # 输出全文
cat -n file.txt                 # 带行号
cat -A file.txt                 # 显示行尾/制表符等不可见字符
cat part1.txt part2.txt > all.txt   # 拼接多个文件
cat >> file.txt << 'EOF'        # 追加写（配合 heredoc）
some text
EOF
```

要点：cat 会把整个文件一次性刷到终端，几 GB 日志会卡死；`cat -A` 是排查「行尾是 CRLF 还是 LF」「有没有多余空格」的利器。

less 是「交互分页查看」：大文件首选，按需加载不占内存，支持前后翻页和搜索；常用按键 `/` 搜索、`n` 下一个匹配、`g` 开头、`G` 结尾、`b` 上翻、空格下翻、`q` 退出。

```shell
less /var/log/syslog            # 交互查看
less -N file.txt                # 带行号
less -S file.txt                # 长行不折行，左右方向键滚动
less +G file.txt                # 直接跳到末尾（看日志尾部）
```

要点：less 支持「边读边搜」，看日志时 `/ERROR` 秒定位；`-S` 不折行对宽表格很重要，否则列全被折乱。

more 是「简化分页器」：只能向前翻（less 的前身），功能弱于 less，space 下翻、`b` 回翻、`/` 搜索、`q` 退出。现在基本被 less 取代，只在极小环境（busybox）里还有存在感。

head / tail 是「看头看尾」：`-n` 取行数（正数从头/尾取、`-n +N` 从第 N 行开始）、`-c` 取字节数，tail 的 `-f` 实时跟踪追加、`-F` 跟踪时文件被轮转（改名/重建）仍继续跟。

```shell
head -n 20 file.txt             # 前 20 行
head -c 100 file.txt            # 前 100 字节
tail -n 50 /var/log/syslog      # 最后 50 行
tail -n +10 file.txt            # 从第 10 行开始到最后（跳过前 9 行）
tail -f /var/log/syslog         # 实时跟踪追加
tail -F /var/log/syslog         # 文件被 logrotate 轮转后仍继续跟
```

要点：`tail -n +N` 是从第 N 行开始（含 N），别和 `-n N` 混淆；`-f` 跟的是 inode，日志轮转后可能跟丢，`-F` 会按文件名重新打开，生产看日志用 `-F` 更稳。

nl 是「带行号输出」：比 `cat -n` 精细，默认只给非空行编号；`-ba` 全编号、`-bt` 只非空行、`-n ln/rn/rz` 控制对齐方式（左对齐/右对齐/右对齐补零）。

```shell
nl file.txt                     # 只给非空行编号
nl -ba file.txt                 # 所有行都编号（含空行）
nl -n rz file.txt               # 行号右对齐补零（0001, 0002...）
cat -n file.txt                 # 对比：cat -n 给所有行编号
```

要点：nl 默认跳过空行、`cat -n` 不跳过，这就是两者输出的差异；看代码行号用 `nl -ba` 或 `cat -n` 都行。

od / hexdump 是「按八进制/十六进制看二进制」：od 格式丰富（`-c` 字符、`-x` 十六进制、`-o` 八进制、`-t x1` 指定字节格式），hexdump 的 `-C` 是「十六进制 + ASCII 对照」的经典格式。

```shell
od -c a.bin | head              # 八进制看字符（含转义）
od -x a.bin | head              # 十六进制（2 字节一组）
od -t x1 a.bin | head           # 十六进制（1 字节一组）
hexdump -C a.bin | head         # 十六进制 + ASCII 对照，最直观
xxd a.bin | head                # xxd 也是十六进制查看器，可反向还原
```

要点：od 默认是八进制，`-t x1` 才是逐字节十六进制，别被默认输出搞混；看二进制魔数、协议头、不可见字符用 `hexdump -C` 最直观。

### 查找命令逐个拆解

find 是「实时遍历文件系统树」：按名字、类型、大小、时间、权限、属主等条件过滤，还能用 `-exec`/`-delete` 对结果执行操作；缺点是慢（全盘遍历 IO 重）。

```shell
find /var/log -name "*.log" -type f        # 按名字 + 类型
find /var/log -type f -mtime -7            # 7 天内修改的
find /var/log -type f -mmin -60            # 60 分钟内修改的
find /tmp -type f -size +100M              # 大于 100MB 的
find /tmp -type f -size -1k                # 小于 1KB 的
find / -type f -perm -4000 2>/dev/null     # 查找 SUID 文件
find / -user www-data -type f 2>/dev/null  # 按属主查找
find . -maxdepth 2 -type d                 # 限制递归深度
```

要点：find 默认递归所有子目录，大范围查找务必加 `-maxdepth` 限制或 `2>/dev/null` 压掉无权限目录的报错；`-mtime -7` 是「7 天以内」，`+7` 是「7 天以前」，方向别记反。

`-exec` 对每个匹配执行命令：`\;` 逐个执行（慢）、`+` 批量传参（快，类似 xargs）；处理含空格文件名用 `-print0` 配 `xargs -0`。

```shell
find /var/log -name "*.gz" -exec rm {} \;    # 逐个删除
find /var/log -name "*.gz" -exec rm {} +     # 批量删除（更快）
find . -type f -name "*.log" -exec wc -l {} +   # 批量统计行数
find . -print0 | xargs -0 rm                  # 安全处理含空格文件名
find . -type f -name "*.tmp" -delete          # 用 find 内置 delete 更高效
```

要点：`-exec ... \;` 和 `-exec ... +` 的区别是「每个文件跑一次」vs「把文件攒一批一次跑」，海量文件时后者快一个量级；含空格/特殊字符文件名必须走 `-print0 | xargs -0`。

locate 是「查索引数据库」：秒出但依赖 updatedb 预建的索引（mlocate/plocate），新建文件要等索引刷新才搜得到；适合「大概记得文件名」的快速定位。

```shell
updatedb && locate nginx.conf      # 先刷新索引再秒查
locate -i "*.conf"                 # 忽略大小写
locate -l 20 syslog                # 只显示前 20 条
```

要点：locate 查的是 `/var/lib/mlocate/mlocate.db`（或 plocate 对应路径）的快照，不是实时文件系统；刚建的文件、刚删的文件都可能和索引不一致，精确查找用 find。Red Hat 系 minimal 安装默认不带 locate，需 `dnf install mlocate`（或 plocate），updatedb 由 /etc/cron.daily/mlocate 定时触发；coreutils 里的 ls/cat/find/cp/mv 两系完全一致（都来自 GNU coreutils），只有包管理命令（apt vs dnf）和个别同名工具（rename）有差异。

which / whereis / type 是「查命令」而非「查文件」：which 在 `$PATH` 里找可执行文件（`-a` 显示全部命中），whereis 连 man 手册和源码一起定位，type 判断命令到底是 shell 内置、别名、函数还是外部程序。

```shell
which python3                     # PATH 里的位置
which -a python3                  # 显示 PATH 里所有同名命中
whereis ls                        # 二进制 + man + 源码
whereis -b ls                     # 只看二进制
type cd                           # cd is a shell builtin（shell 内置）
type -t ls                        # 输出类型词：alias/builtin/file...
type -a ls                        # 列出所有定义（别名 + 外部程序）
```

要点：which 找不到不代表命令不能用——shell 内置（cd、echo）和别名（ll）which 都查不到，此时用 type 判断；`type -t` 输出的词（alias/keyword/function/builtin/file）是脚本里判断命令来源的标准手段。

## 工作原理

文件操作底层有两个关键机制值得理解：一是 mv——同分区移动只改目录项（秒完成），跨分区移动是「复制 + 删除」（要完整读写数据，大目录极慢）；二是 find vs locate——find 实时遍历文件系统树（慢但准），locate 查 updatedb 预建的索引数据库（快但可能过期，刚建的文件查不到）。理解这两个机制，就能解释「为什么 mv 有时秒有时慢」「为什么 locate 搜不到新文件」。

```text
两个底层机制：
1. mv 同分区 = 改目录项指针，不搬数据（秒级）；跨分区 = 复制到目标 + 删源（受 IO 限制）
2. find = 实时遍历目录树；locate = 查 updatedb 索引（定时/手动刷新，有延迟）
```

除这两个，还有两个机制决定了「文件操作」的边界，值得一并理解：

**路径解析（namei）**：内核按「目录项 → inode」逐级解析路径。`/var/log/syslog` 要先读 `/` 的 inode 找到 `var` 目录项，再读 `var` 的 inode 找 `log`，再读 `log` 的 inode 找 `syslog`。这意味着：路径里任何一级目录缺 `x` 权限，都会中断解析（表现为 `Permission denied` 或 `No such file or directory`）；符号链接会在解析中被「展开」成目标路径。

**删除的本质**：`rm` 不是抹掉文件内容，而是调用 `unlink` 断开目录项与 inode 的链接（链接数 -1）。当链接数归零且没有进程持有该 inode 时，数据块才被标记为空闲。所以「rm 了文件但进程还开着句柄，磁盘不释放」——这和 02.4 讲的 inode/链接数是一回事。

```text
路径解析链路：
/var/log/syslog → 读 / 的 inode → 找 var 目录项 → 读 var 的 inode → 找 log 目录项 → 读 log 的 inode → 找 syslog 目录项
删除链路：rm = unlink（目录项-1）→ 链接数=0 且无进程占用 → 数据块释放
```

### 目录树与路径工具（tree / basename / dirname / realpath / readlink）

`tree` 用树形缩进展示目录层级，比 `ls -R` 可读得多；`basename` / `dirname` 只做字符串切分（不访问文件系统）；`realpath` / `readlink -f` 会真的逐级解析路径（必须存在且有 x 权限）；`readlink`（不带 -f）只打印符号链接自身的目标字符串。

```shell
tree                     # 树形列出当前目录（默认不含隐藏文件）
tree -a                  # 含隐藏文件
tree -L 2 -d             # 只到 2 层、只列目录
tree -h --du             # 显示大小、并累计目录占用
tree -I 'node_modules|.git'   # 排除匹配项（正则）
tree -P '*.md' --prune   # 只保留匹配模式的文件

basename /etc/nginx/nginx.conf          # nginx.conf（取最后一段）
basename /etc/nginx/nginx.conf .conf    # nginx（顺带去掉后缀）
dirname  /etc/nginx/nginx.conf          # /etc/nginx（去掉最后一段）
basename /usr/lib/                      # lib（末尾斜杠会被忽略）

realpath link                 # 解析成绝对真实路径（链接逐级展开）
realpath -e link              # 路径不存在就报错（--canonicalize-existing）
realpath -m /no/such/path     # 允许不存在（--canonicalize-missing）
realpath --relative-to=/etc /tmp/w23/a/b   # 输出相对路径 ../tmp/w23/a/b
readlink link                 # 只打印链接目标（一层，不解析）
readlink -f link              # 递归解析到最后目标（像 realpath）
readlink -e link              # 同上，但要求目标存在
```

```text
# 实测输出（Ubuntu 24.04.4 LTS，内核 7.0.0-28-generic）
$ ls -l cur_link chain_link
cur_link -> /tmp/w23/a          # 普通软链
chain_link -> cur_link          # 链指向链

$ readlink cur_link
/tmp/w23/a
$ readlink chain_link
cur_link                        ← 不带 -f 只看一层，把链名照抄出来
$ readlink -f chain_link
/tmp/w23/a                      ← 带 -f 递归解析到真实路径
$ realpath --relative-to=/etc /tmp/w23/a/b
../tmp/w23/a/b
$ realpath -m /no/such/path
/no/such/path                   ← -m 允许不存在，纯做路径规整
$ readlink -f /no/such/path ; echo "exit=$?"
exit=1                          ← 目标不存在，-f 无输出且失败（父级缺失时）
$ readlink -f /usr/bin/awk
/usr/bin/mawk                   ← 解开"命令 → alternatives → 真实二进制"的链路
```

```text
tree 在本机未安装（实测）：
$ tree /tmp/w23
/usr/bin/bash: 行 5: tree: 未找到命令
$ apt-cache policy tree | head -3
tree:
  已安装：(无)
  候选： 2.1.1-2ubuntu3.24.04.2
安装：sudo apt install -y tree
替代：ls -R（原始）、find . -print | sed -e 's;[^/]*/;|____;g;s;____|; |;g'（脚本降级方案）
```

要点：`dirname` 是纯字符串操作，`dirname /a` 返回 `/`（根），`dirname a` 返回 `.`（相对路径没有斜杠时前者恒为点）；`readlink` 不加 `-f` 只解一层链，脚本里想拿真实路径必须加 `-f` 或 `-e`；判断 `readlink -f` 是否成功要看退出码，而不是看输出为空——目标不存在时它安静地失败。

### 临时文件与空间预分配（mktemp / truncate）

```shell
mktemp                    # 建唯一临时文件（600），输出路径
mktemp -d                 # 建唯一临时目录（700）
mktemp -t myprog.XXXXXX   # 指定前缀模板，落在 ${TMPDIR:-/tmp}
mktemp -p /var/tmp tmp.XXXX    # 指定目录（--tmpdir=/var/tmp）
mktemp --suffix=.log t.XXXX    # 指定后缀（后缀不计入 XXXXXX 模板）
TMPDIR=/dev/shm mktemp -d      # 临时目录放到内存盘，速度极快、重启即失

truncate -s 1G big.img         # 把文件设为 1GiB 逻辑大小（稀疏，不写数据）
truncate -s +1M big.img        # 相对扩大 1MiB（还有 -1M 缩小）
truncate -s 0 log.txt          # 清空文件但保留 inode（服务句柄不失效）
truncate -r ref.img copy.img   # 按参考文件大小截断 copy.img
```

```text
# 实测输出（Ubuntu 24.04.4 LTS，内核 7.0.0-28-generic）
$ mktemp -d
/tmp/tmp.SE4aeAZQFb
$ ls -ld /tmp/tmp.SE4aeAZQFb
drwx------ 2 root root 4096  9月 12 11:21 /tmp/tmp.SE4aeAZQFb
$ mktemp -t myprog.XXXXXX
/tmp/myprog.TfPrbf
$ mktemp --suffix=.log /tmp/xxx.XXXX
/tmp/xxx.WOqY.log
$ echo "TMPDIR=${TMPDIR:-（未设置，即默认 /tmp）}"
TMPDIR=（未设置，即默认 /tmp）
```

```text
truncate 语义（示例，本机策略不允许对真实文件执行截断类操作）：
1. truncate 只改 inode 的 st_size，不写数据：-s 1G 瞬间完成、du 报 0
2. 截断（变小）是真删数据：truncate -s 0 f 之后 f 的内容没了，但 inode 不变
3. 与 rm 的区别：truncate 保留目录项与 inode，正在写日志的进程句柄依然有效
4. 与 :> f 等价（shell 重定向截断），truncate 的好处是能指定确切字节数
5. 稀疏空洞被 cp/tar 打包时默认会被"填实"成真实数据，注意目标盘容量
```

要点：`mktemp` 生成的名字带 6 位随机串，天然避免并发冲突，是脚本临时文件的正解；`truncate -s 0` 常被用来「清空日志但不重启服务」，效果等同 `: > /var/log/x.log`，但注意清空后 `tail -f` 会停在原位置（因为 inode 没变、offset 还在），此时 `tail -F` 或者先做 logrotate 更稳妥。

### 安全擦除（shred）与它做不到的事

```shell
shred -n 3 secret.txt       # 覆写 3 遍（默认就是 3）
shred -z secret.txt         # 最后再补一遍 0 覆写，掩盖擦除痕迹
shred -u secret.txt         # 覆写后删除（-u = --remove）
shred -v -n 1 secret.txt    # 显示进度
shred -n 3 /dev/sdb1        # 直接擦整块设备（危险，需 root）
```

```text
shred 的能力边界（示例，本机策略不允许执行覆写/删除类命令）：
1. GNU shred 假设是"原地覆写"：磁盘上写哪里就是哪里 —— 机械盘 + ext2/3 成立
2. 硬件层失效：SSD 有磨损均衡（写入落到不同闪存块）、磁盘有坏块重映射，
   原块可能被回收或挪走，覆写不等于抹掉
3. 文件系统层失效：ext4/xfs/btrfs 是日志型/写时复制（COW）文件系统，
   覆写会产生新块，旧块里的原始数据可能残留；压缩/去重文件系统同理
4. 元数据残留：文件名、大小、时间戳可能还在快照/日志/备份里
5. 真正可靠的做法：全盘加密（LUKS）—— 销毁密钥即等于销毁数据
6. 与 rm 的关系：rm 只断链接（数据块可能仍可恢复），shred 试图覆写内容但
   对现代介质不保证；两者都不是"安全删除"的银弹
```

要点：`shred -u` 看起来比 `rm` 安全，但在 SSD、ext4 日志文件系统、云盘（底层分散存储）上都不能保证原始数据被物理覆盖；合规场景首选整盘 LUKS 加密，删数据时销毁密钥。

### 部署安装（install）：脚本里替代 cp + chmod + chown

`install` 能在复制的同时设权限、属主、属组，还能自动建目录（`-D`），是部署脚本里比「`cp` 再 `chmod`」更可靠的一步到位工具。

```shell
install -m 640 src.txt /tmp/w23/x-restricted.txt   # 复制并设权限 640
install -D -m 700 src.txt /pkg/deep/y              # 逐级建目录再复制（-D）
install -d -m 1777 -o root -g root /tmp/shared23   # 只建目录并设权限/属主
install -o app -g app -m 750 app.conf /etc/app/    # 指定属主属组
install -b -m 644 a b                              # 覆盖前备份（b 后缀 ~）
install -t /usr/local/bin a.sh b.sh                # 多个源装到同一目录
```

```text
# 实测输出（Ubuntu 24.04.4 LTS，内核 7.0.0-28-generic）
$ install -m 640 /tmp/w23/a/b/c/x.txt /tmp/w23/x-restricted.txt
$ ls -l /tmp/w23/x-restricted.txt
-rw-r----- 1 root root 3  9月 12 11:25 /tmp/w23/x-restricted.txt

$ install -D -m 700 /tmp/w23/a/b/c/x.txt /tmp/w23/newdir/deep/y
$ ls -l /tmp/w23/newdir/deep/y
-rwx------ 1 root root 3  9月 12 11:25 /tmp/w23/newdir/deep/y
解读：-D 顺带建出了 newdir/deep 两级目录，一步完成"建目录 + 复制 + 设权"。

$ install -d -m 1777 -o root -g root /tmp/w23/shared23
$ ls -ld /tmp/w23/shared23
drwxrwxrwt 2 root root 4096  9月 12 11:25 /tmp/w23/shared23
解读：1777 = 粘滞位（t），和 /tmp 一样的"谁都能写、只能删自己的"语义。
```

要点：`install` 默认**不保留源文件的时间戳**（它按复制时刻计），要保留得加 `-p`；不带 `-D` 时目标目录必须已存在，否则报错——这正好和 `cp` 的语义不同，部署脚本里优先用 `install -D -m`。

### 命名管道（mkfifo）：无内容的文件

```shell
mkfifo /tmp/myfifo                 # 建 FIFO（默认权限受 umask 影响）
mkfifo -m 660 /tmp/myfifo          # 指定权限
ls -l /tmp/myfifo                  # 类型位显示 p（prw-r--r--）
cat /tmp/myfifo &                  # 读端先挂起等待
echo hello > /tmp/myfifo           # 写端打开后两端同时打通
mkfifo /tmp/pipe && tee /tmp/pipe > /tmp/copy <<< "x" &   # 不落盘的转发
```

```text
# 实测输出（Ubuntu 24.04.4 LTS，内核 7.0.0-28-generic）

hello-fifo
$ stat -c '%F %s bytes %a' p23

解读：FIFO 文件大小恒为 0，数据只在内核缓冲区里流动；类型位 p / stat 报"先进先出文件"。
```

要点：直接 `cat fifo` 会**阻塞**直到有写端（反之亦然），排障时别以为命令卡死；FIFO 适合做「两个进程的对接线」——比如把 `tail -f` 的输出喂给一个不接受管道输入的程序。

### 谁占着文件（fuser）：排障主力

```shell
fuser file.txt              # 打印占用该文件的 PID
fuser -v file.txt           # 详细（用户/PID/权限/命令）
fuser -m /data              # 占用该挂载点（任何文件）的进程
fuser -k file.txt           # 杀掉占用者（先看 -v 确认）
fuser -k -TERM -m /data     # 按挂载点杀，指定信号
fuser -u file.txt           # 输出里带上用户名
fuser -n tcp 8080           # 查占用 TCP 8080 的进程（常见口误是 fuser 8080/tcp）
```


### 十六进制/字节查看器对照（od / hexdump / xxd）

```shell
file /usr/bin/ls               # 先看文件类型（读魔数）
od -c -N 32 /usr/bin/ls        # 八进制偏移 + 字符视图
od -t x1 -N 16 /usr/bin/ls     # 逐字节十六进制
od -A d -t x1 f                # 偏移用十进制显示（-A x/o/d/n）
hexdump -C f                   # 经典"十六进制 + ASCII"对照（最直观）
hexdump -n 32 -C f             # 只看前 32 字节
xxd -l 32 f                    # xxd 十六进制 + ASCII（列布局不同）
xxd -r dump.txt restored.bin   # 反向还原：把 hexdump 文本变回二进制
strings a.bin | head           # 从二进制里捞可打印字符串
```

```text
# 实测输出（Ubuntu 24.04.4 LTS，内核 7.0.0-28-generic）
$ od -c -N 16 /usr/bin/ls
0000000 177   E   L   F 002 001 001  \0  \0  \0  \0  \0  \0  \0  \0
0000020
$ od -t x1 -N 16 /usr/bin/ls
0000000 7f 45 4c 46 02 01 01 00 00 00 00 00 00 00 00 00
0000020
$ hexdump -C -n 32 /usr/bin/ls
00000000  7f 45 4c 46 02 01 01 00  00 00 00 00 00 00 00 00  |.ELF............|
00000010  03 00 3e 00 01 00 00 00  30 6d 00 00 00 00 00 00  |..>.....0m......|
00000020
$ xxd -l 16 /usr/bin/ls
0000000: 7f45 4c46 0201 0100 0000 0000 0000 0000  .ELF............
$ file /usr/bin/ls
/usr/bin/ls: ELF 64-bit LSB pie executable, x86-64, version 1 (SYSV), ... stripped
三者对照结论：
1. od -c 把 7f 显示成 177（八进制），别误以为是"值不一样"
2. od 默认偏移是八进制；-A x 换十六进制偏移，-A d 换十进制
3. hexdump -C 是"1 行 16 字节 + 中间双空格分组 + 右侧 ASCII"，人类最好读
4. xxd 每行 8 组 2 字节、偏移带冒号，且能用 -r 逆向还原，改二进制用它
5. 魔数 7f 45 4c 46 = "\x7fELF"，这就是 file 判断"ELF 可执行"的依据
```

要点：看到 `od -c` 里的 `177`、`\0` 不要慌，那只是八进制与转义表示；分析协议头/文件格式优先 `hexdump -C`，需要「文本 → 二进制」往返时用 `xxd`/`xxd -r`。

### find 参数全集

```shell
# 名字与路径
find . -name '*.log'            # 按名字（区分大小写，支持通配符）
find . -iname '*.LOG'           # 忽略大小写
find . -path '*/conf/*.xml'     # 按路径匹配（可配合 -ipath）
find . -regex '.*/[0-9]+\.bak'  # 正则匹配整条路径（-regextype 指定方言）

find . -type f -o -type l       # 文件类型：f/d/l/s/p/b/c
find . -maxdepth 2 -mindepth 1  # 深度限制（-maxdepth 应在最前面，性能更好）
# 时间

find . -mmin -60                # 60 分钟内（分钟粒度）
find . -newermt '2026-09-01'    # 比指定时刻新（可写 'yesterday'/'2 hours ago'）

find . -size -1k                # 小于 1KiB
find . -size 0                  # 恰好 0 字节（配合 -empty 更完整）
# 权限与属主
find . -perm 644                # 权限完全等于 644
find . -perm -u+w               # 至少含属主可写（- 表示"包含"）
find . -perm /u+w,g+w           # 任一位置含 w（/ 表示"其中之一"）
find . -perm -4000              # 含 SUID 位（-=全部满足，/=任一满足）
find . -user nginx -group www-data
find . -nouser -o -nogroup      # 属主/属组已不存在的孤儿文件
# inode / 链接 / 空
find . -inum 57415953           # 按 inode 号找（找回被误删的硬链接用）
find . -links +1                # 硬链接数大于 1
find . -samefile ref.txt        # 与 ref 是同一 inode 的所有路径
find . -empty                   # 空文件或空目录
find . -readable -writable      # 当前用户可读/可写
# 逻辑组合
find . -name '*.log' -not -path './archive/*'
find . \( -name '*.gz' -o -name '*.zip' \) -type f
# 动作
find . -name '*.tmp' -delete                      # 删除（内置，最快）
find . -name '*.sh' -exec chmod +x {} +           # 批量执行
find . -name '*.sh' -execdir bash -n {} \;        # 在文件所在目录里执行
find . -type f -exec wc -l {} +                   # 统计
find . -name '.git' -prune -o -type f -name '*.js' -print   # 剪枝排除 .git
find . -type f -printf '%s\t%p\n' | sort -rn | head -10     # 直接输出大小排序
find . -print0 | xargs -0 -P 8 -n 200 cp -a -t /backup       # 并行批量
```


### cp 全家 / mv 原子性 / rm 防护

```shell
cp file dest/                  # 复制文件
cp -r dir dest/                # 递归复制目录（不保留属性）
cp -a dir dest/                # 归档：-dR --preserve=all（备份首选）
cp -p file dest/               # 保留权限/属主/时间戳（-p 等价 --preserve=mode,ownership,timestamps）
cp -d link dest/               # 复制链接本身而不是跟随目标（-P 同样）
cp -L link dest/               # 跟随链接，复制目标内容
cp -l file dest/               # 硬链接而不是复制（省空间，同分区才行）
cp -s file dest/               # 建符号链接而不是复制
cp -f file dest/               # 目标存在且打不开时先删除再复制
cp -i file dest/               # 覆盖前询问
cp -n file dest/               # 不覆盖（新版本提示用 --update=none）
cp -u src/* dest/              # 只复制更新的（--update=older）
cp --reflink=auto big.img copy.img   # 支持 COW 的文件系统上秒级复制（btrfs/xfs）
cp --sparse=always f dest/     # 空洞按稀疏写（省目标盘）
cp --preserve=mode,ownership,timestamps,links,context,xattr  # 精确指定保留项
cp -t /backup f1 f2            # 目标目录写在前面（-t 适合脚本）
cp -v a b                      # 显示过程

mv a b                         # 改名 / 移动
mv -n a b                      # 不覆盖
mv -f a b                      # 强制覆盖
mv -b a b                      # 覆盖前备份为 b~
mv -t /data a b c              # 批量移到目录（-t）
mv -v a b                      # 显示过程

rm file                        # 删文件
rm -r dir                      # 递归
rm -f file                     # 强制、忽略不存在的文件
rm -i file                     # 逐个确认
rm -I dir                      # 删除超过 3 个或递归时"确认一次"（比 -i 好用）
rm -d emptydir                 # 删空目录（等价 rmdir）
rm --preserve-root /           # 默认行为：拒绝删除 /
rm --no-preserve-root -rf /    # 关掉保护（千万别在生产敲）
rm --one-file-system -rf /mnt  # 不跨越挂载点（配合 -preserve-root 更稳）
rm -rf -- "$DIR"               # -- 结束选项解析，防路径以 - 开头被当参数
```

```text
'a/b/c/x.txt' -> 'cp-v.txt'
```

```text
mv 的原子性与性能边界（示例 + 机制）：
1. 同文件系统：mv 调 rename(2) —— 只改目录项，O(1)，任何大小的文件都秒完成
2. 跨文件系统：rename 返回 EXDEV，mv 退化为"复制内容 + unlink 源"，
   时间与数据量成正比；中途失败可能留下"半份拷贝 + 原文件还在"（cp 语义）
3. 同文件系统内改名正在被写的大文件：文件句柄不受影响，写入继续落到同一 inode
4. mv 目录到"已存在的目录名"= 移进去；到"不存在的名字"= 改名 —— 语义二义性来源
5. mv 覆盖已存在文件是同目录 rename 的替换语义：读者要么看到旧文件，要么看到新文件
```

要点：跨文件系统大目录迁移优先 `rsync -a --remove-source-files`，它可断点续传、能校验，比 mv 停在中途更可控；`rm -rf` 在脚本里永远写成 `rm -rf -- "$dir"`（`--` 防连字符文件名、引号防空格、变量先校验非空），这是「内容安全」的最低门槛。

### 目录跳转与历史栈（cd / pushd / popd / dirs / CDPATH）

```shell
cd /var/log            # 绝对路径
cd -                   # 回上一个目录（并打印它）
cd                     # 回家目录（等价 cd ~）
cd ..                  # 上一级
cd -P /some/link       # 按物理路径进入（解掉符号链接）
pwd -P                 # 打印物理路径（默认 pwd 是逻辑路径）
pushd /etc             # 入栈并切换
pushd -n /etc          # 只入栈不切换（-n）
dirs -v                # 带编号打印目录栈
pushd +2 / popd -0     # 按编号跳/出栈
popd                   # 弹出栈顶并切回
hash -d                # 清掉命令哈希缓存（换 PATH 后常用）
```

```text
  cd web 会依次在 .、/opt/apps 里找 web 目录并直接切进去 ——
  交互式很方便，脚本里是坑（切过去的路径可能不是你以为的那个）。
```

要点：`cd` 进目录要 `x` 权限、`ls` 内容要 `r` 权限，两者独立（`cd -P` 也一样要）；脚本里别依赖 `cd -`/`OLDPWD`，用显式变量；`CDPATH` 会改变 `cd relativepath` 的语义，脚本开头最好 `unset CDPATH`。

### stat 格式化与 ls -l 字段对照

```shell

stat -c '%n %s %F %a %U %G' file           # 自定义格式（脚本友好）
stat -c '%A %a %i %h %b %B' file           # 符号权限/八进制/inode/链接数/块数/块大小
stat -c '%x | %y | %z' file                # atime | mtime | ctime（含纳秒 + 时区）
stat -c '%n %s' /tmp/demo/*.txt            # 批量（对每个参数各来一行）
stat -f /var                               # 看文件系统信息（-f 作用于挂载点）
stat --printf='%s\n' file                  # 结尾不加换行（printf 语义）
```

### 查找工具选型：which / type / command -v / whereis

```shell
which ls                 # 在 $PATH 里找可执行文件，返回第一个命中
which -a python3         # 列出 PATH 里所有同名
type ls                  # 综合判断：别名>函数>内建>外部

type -a ls               # 列出所有定义来源（含别名与哈希）

whereis ls               # 二进制 + man + 源码（查"程序包自带什么"）
whereis -b -m ls         # 限制查二进制与 man
hash -l                  # 看 shell 的命令哈希表
```

```text
1. 脚本里判断"命令是否存在" → command -v foo >/dev/null 2>&1（POSIX、快、无输出污染）
```

### 场景一：找出 /var/log 下最近 3 天修改过的大日志文件并归档


## 性能与调优

```text
文件操作的性能优化：
1. find 提速 —— -prune 排除大目录（如 .git/node_modules），别全盘裸扫；加 -maxdepth 限制深度
2. locate 秒查 —— 频繁查找时先 updatedb 建索引，比 find 快几个量级
3. cp 大目录用 -a + rsync —— 复制保属性用 cp -a，增量同步用 rsync（只传差异）
4. 大文件读用 less —— 别 cat 几 GB 日志，less 按需加载不占内存
5. tail -f 加 grep —— 实时日志先过滤再输出，减少 IO 和刷屏
6. -exec + 代替 -exec \; —— 海量文件批量处理时，把逐进程调用换成批量传参，省掉大量 fork 开销
7. 用 find -delete 代替 -exec rm —— find 内置删除不走 fork，比外部 rm 更快
8. 统计行数用 wc -l，别用 cat | wc —— 省一次管道和 cat 进程
```

## 安全与权限

```text
文件操作安全要点：
1. rm 无回收站 —— 删除前 ls 确认，rm -rf 变量路径前先校验非空，防 rm -rf / 事故
2. find -exec 防注入 —— 文件名含空格/特殊字符会断参数，用 -print0 | xargs -0
3. cp/mv 覆盖确认 —— cp -i / mv -i 交互确认，防静默覆盖重要文件
4. 权限最小化 —— 删除/修改系统目录文件要 root，日常用普通用户 + sudo
5. 敏感文件不留明文 —— 备份/传输配置含密码时加密，临时文件用完即删
6. 用 trash-cli 或 safe-rm 软删除 —— 给 rm 加一层回收站/黑名单保护，防误删
7. 进目录要 x 权限 —— cd 目录需要 x（搜索）权限，ls 目录内容需要 r 权限，两者独立
```

## 故障排查

```shell
# 1. 文件找不到
find / -name "<文件名>" 2>/dev/null     # 兜底全盘找
locate <文件名>                          # 先秒查（记得 updatedb）

# 2. 权限拒绝（Permission denied）
ls -l <文件>          # 看属主属组和权限位
ls -ld <目录>         # 目录权限拒绝时看目录本身（缺 x 权限）

# 3. mv 大目录极慢
df -h <源> <目标>     # 看是否跨分区，跨分区 mv = 复制 + 删除

# 4. 删了文件磁盘不释放
lsof +L1 | grep deleted    # 找被进程占用的已删文件

# 5. mkdir/touch 失败
df -h <路径>          # 看磁盘是否满（No space left on device）
mount | grep <路径>   # 看是否是只读挂载（Read-only file system）

# 6. 谁占着文件/端口（删不掉、卸不掉、端口占用）
fuser -vm <文件或目录>      # 详细列出占用者（用户/PID/权限/命令）
fuser -k <文件>            # 确认后杀掉占用者（默认 SIGKILL）
fuser -n tcp 8080          # 查占用 TCP 8080 的进程
lsof <文件>                # 完整 fd 视图（打开的文件、类型、偏移）
lsof +L1                   # 已删除但仍被进程占用的文件（磁盘不释放的元凶）
lsof -p <PID> | head       # 某进程打开了什么

# 7. Argument list too long（E2BIG）
getconf ARG_MAX            # 本机 2097152（2MiB）
find . -type f -print0 | xargs -0 rm        # 分批传参，绕开上限
find . -type f -exec rm {} +                # 同上（find 自动分批）
ls | head                 # 确认对象数量级再说

# 8. 文件名乱码 / 编码不对
file <文件>                # 先看它自称什么编码
ls -b                       # 非打印字符转义显示（看真实字节）
iconv -f GBK -t UTF-8 -c in > out           # 尝试转码，-c 丢弃非法字节
convmv -f gbk -t utf8 -r --notest <dir>     # 批量重命名文件名（需安装 convmv）

# 9. Text file busy（ETXTBSY）
lsof <可执行文件>          # 有进程正在运行/写入该文件
fuser -k <可执行文件>      # 或停掉服务后再替换

# 10. inode 用尽（df 有空间也报 No space left on device）
df -i                       # 看 inode 使用率（本机 / 为 3%，通常无虞）
find <目录> -xdev -type f | sed 's/.*//' | wc -l   # 粗看文件数量级
```

## 常见问题

```text
Q1: mv 为什么有时瞬间完成、有时很慢？
A: 同分区 mv 只改目录项（秒级），跨分区 mv 是复制 + 删除（受 IO 限制，大目录慢）。

Q2: locate 为什么搜不到刚创建的文件？
A: locate 查 updatedb 的索引快照，新文件还没入索引，先 updatedb 刷新或改用 find。

Q3: 删文件有回收站吗？
A: 没有。rm 删了基本找不回，重要文件删前备份，生产用 trash-cli 之类的软删除方案。

Q4: which 和 whereis 区别？
A: which 只找 PATH 里的可执行文件，whereis 连 man 手册和源码一起定位。

Q5: cp -r 和 cp -a 区别？
A: -r 只递归复制，-a 归档模式（递归 + 保留权限/时间戳/软链），备份目录用 -a。

Q6: which cd 为什么查不到？
A: cd 是 shell 内置命令，不是外部程序，which 只在 PATH 里找可执行文件；用 type cd 判断（显示 builtin）。

Q7: find 的 -exec {} \; 和 -exec {} + 有什么区别？
A: \; 是「每个文件跑一次命令」（慢、fork 多），+ 是「把文件攒一批一次传参」（快、类似 xargs）。

Q8: tail -n +10 是什么意思？
A: 从第 10 行开始输出到最后（跳过前 9 行）；带 + 号表示「从第 N 行起」，不带表示「取 N 行」。

Q9: cp -r 复制完目录，为什么文件时间戳全变成"现在"了？
A: -r 只负责递归，不保留属性；保留权限/属主/时间戳要用 -p，整个目录备份用 -a（= -dR --preserve=all）。本机实测：设置 mtime 为 2020-01-01 后 cp -r 得到的是当前时间，cp -a / cp -p 保持 2020-01-01。

Q10: 删了大文件 df 却没降，为什么？
A: 有进程还开着这个文件的句柄，unlink 只把链接数减到 0，数据块要等句柄关闭才回收。用 `lsof +L1` 找出带 (deleted) 的条目，重启对应服务即释放。

Q11: 一次要删几十万个小文件，"Argument list too long" 怎么破？
A: 单条命令参数总长有上限（本机 getconf ARG_MAX = 2097152 字节，超了报"参数列表过长"，退出码 126）。用 `find 目录 -type f -exec rm {} +` 或 `find 目录 -type f -print0 | xargs -0 rm`，把参数分批传入；更快的做法是 `find -delete`（内置、零 fork）。

Q12: 下载的文件名是乱码，怎么处理？
A: 先用 `file` 和 `ls -b` 确认真实字节与编码，再 `iconv -f GBK -t UTF-8 -c` 转内容；文件名本身乱码用 `convmv -f gbk -t utf8 -r --notest` 批量改名（需安装 convmv）。注意先备份，转码不可逆。

Q13: 同一个文件为什么能有两个名字？和软链接有什么区别？
A: 硬链接：两个目录项指向同一 inode，`stat %h` 链接数为 2，删除任一个名字数据仍在；只限同一文件系统，不能给目录做硬链接。软链接：独立 inode，内容是"目标路径字符串"，`ls -l` 显示 `->`，目标删了就是悬空链接（dircolors 里 ORPHAN 显示红底）。

Q14: 脚本里生成临时文件，怎样才安全？
A: 别手拼 `/tmp/固定名`（并发重名 + 符号链接攻击），用 `tmp=$(mktemp)` 或 `mktemp -d`，必要时 `TMPDIR=/dev/shm`；重写配置文件时"先写临时文件再 mv 覆盖"保证原子性（同文件系统内 rename 是原子的）。

Q15: find、locate、fd 到底该用哪个？
A: 脚本/可移植/条件复杂 → find；"大概记得名字"且愿意接受索引延迟 → locate（本机未安装，需 apt install plocate 并 updatedb）；本机交互式快速搜 → fd（未安装，apt install fd-find，命令名 fdfind，默认忽略 .gitignore 与隐藏文件）。

Q16: truncate -s 0 和 rm 有什么区别？
A: truncate 只把 inode 里的长度置 0，目录项和 inode 都保留，正在写日志的进程句柄依然有效（清空日志不重启服务的常用手段）；rm 是 unlink 目录项，文件从目录里消失、句柄关闭后空间才回收。清空后 `tail -f` 会停在原 offset，改 `tail -F` 或先 logrotate。
```

## 面试题

```text
1. 找出 /var/log 下大于 100MB 且 7 天前修改的文件？
   答：find /var/log -type f -size +100M -mtime +7

2. find 和 locate 的区别？
   答：find 实时遍历文件系统（慢但准），locate 查索引数据库（快但可能过期）。

3. 怎么批量把 .txt 改成 .md？
   答：for f in *.txt; do mv "$f" "${f%.txt}.md"; done，或 rename 's/\.txt$/.md/' *.txt

4. 查看大日志文件用什么命令？
   答：less（交互分页、可搜索），tail -f 实时跟踪追加内容，别用 cat 刷屏。

5. 为什么 find -exec 处理含空格文件名会出错？怎么解决？
   答：shell 按空格分词把文件名拆断；用 find ... -print0 | xargs -0 处理。

6. 怎么找出当前目录下最大的 10 个文件？
   答：find . -type f -exec ls -lh {} \; | sort -k5 -rh | head -10，或 ls -lS | head -10（不递归）。

7. 统计一个文件有多少行用什么命令？
   答：wc -l file.txt；要看带行号的内容用 cat -n 或 nl -ba。

8. touch 命令有什么用？
   答：创建空文件；已存在的文件则更新其访问/修改时间戳（-a 只改 atime、-m 只改 mtime），不会清空内容。

9. 软链接和硬链接有什么区别？各适合什么场景？
   答：硬链接是多条目录项指向同一个 inode，不能跨文件系统、不能链目录，删掉一个名字文件数据仍在（链接计数减到 0 才真正释放）；软链接是独立文件，内容是目标路径字符串，可跨文件系统、可链目录，目标删了就成断链（dangling）。用法上：同一分区内要多入口/做快照备份用硬链接；跨分区、指向目录、需要动态跟随路径（如 /usr/bin/myapp -> /opt/app/current）用软链接。

10. inode 和 dentry 是什么关系？
    答：inode 存元数据与数据块位置（权限、属主、大小、时间戳、块指针），dentry 是「目录项」这个内存对象，把文件名映射到 inode。目录本质是一张「文件名 -> inode 号」的表，VFS 把最近用过的映射缓存在 dentry cache 里加速路径查找；硬链接就是同一个 inode 被多个 dentry 引用。inode 号在单个文件系统内唯一，dentry 是内存结构、重启即失。

11. find 的 -prune 是怎么工作的？为什么常和 -o 一起用？
    答：-prune 对匹配到的目录返回真但不递归下降，等于剪掉整棵子树，省掉大量遍历。find 的表达式默认由隐式 -a（and）串联，单独写 -prune 只返回真、既不打印也不排除，必须配合 -o（or）表达「匹配到就剪枝、否则打印」：find . -path ./node_modules -prune -o -name '*.log' -print。注意 -prune 只对目录生效，且 -name 匹配的是 basename，判断目录层级要用 -path 或 -type d。

12. 为什么处理文件名建议用 find -print0 | xargs -0？
    答：文件名的合法字符里包含空格、制表符甚至换行，-print 用换行分隔、xargs 默认按空白和引号切分，含空格的文件名会被拆成多个参数。改用 NUL（\0）分隔——NUL 是文件名里唯一不可能出现的字节——find -print0 每条以 \0 结尾，xargs -0 按 \0 接收，参数边界就不丢。等价方案是 -exec {} +，同样按边界批量传参、只起一次进程。

13. cp 和 rsync 的本质区别是什么？
    答：cp 每次都全量拷贝、不做比较；rsync 按需增量——比较源和目标的 mtime/size（默认不看内容），只传变化的部分，还能 --delete 同步删除、-P 断点续传、-z 压缩、跨 SSH 走远端。反复同步大目录、断点续传、只更新变化文件用 rsync；本地一次性拷贝、要精确控制属性用 cp -a。注意 rsync 默认的 mtime+size 判定在「内容变了但 mtime/size 没变」时会漏拷，需要 -c 校验和兜底。

14. mv 是原子操作吗？
    答：同一文件系统内是原子的——mv 只调用 rename 改目录项，要么完成要么没发生，不会出现半截文件，这正是「先写临时文件再 mv 覆盖」能保证配置文件读到的永远是完整版本的原因。跨文件系统时不是原子的——退化成复制加删除，中途失败源和目标都可能残缺。另外 rename 覆盖已存在的目标也是原子的，不会先删再建。

15. 为什么说 rm -rf 比 find -delete 危险？
    答：rm -rf 是「先把完整路径拼出来再交给 rm」，路径一旦拼错（变量为空、多了斜杠、通配符被 shell 提前展开）就按错误目标删，加上 -r 递归、-f 不提示、无二次确认，删完不可恢复。find -delete 是 find 在遍历过程中对「已经匹配确认的对象」删除，路径由 find 内部构造、不经过 shell 分词与通配展开，误删概率低很多；但 -delete 隐含 -depth，会连带删掉匹配的空目录，要留意。两者都建议先跑一遍不带删除动作的命令看匹配清单。

16. cd 的 CDPATH 有什么陷阱？
    答：CDPATH 是一个搜索目录列表，cd 相对路径时会依次到各目录里找：设了 CDPATH=/opt/study-work 后，在任意目录执行 cd linux 会跳到 /opt/study-work/linux，而不是当前目录下的 linux，脚本里相对路径会静默跳走。更隐蔽的是：只有 CDPATH 里含空项或 . 才代表当前目录，且命中 CDPATH 时 bash 会把目标路径打印到标准输出，污染 $(...) 的捕获结果。脚本里要么先 unset CDPATH，要么 cd ./linux 明确指向当前目录。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 大文件用 less 分页看，别用 cat 把几 GB 日志刷屏
2. 删文件前先 ls 确认目标，rm -rf 加绝对路径、别手滑带空格的变量
3. 复制目录要保留属性用 cp -a，别用 cp -r（会丢权限和时间戳）
4. 找文件能用 locate 先秒查，查不到再 find 实时遍历
5. 看日志跟踪用 tail -f，配 grep 过滤更高效（tail -f log | grep ERROR）
6. 海量文件批量删除用 find -delete 或 -exec rm {} +，别用 \; 逐个 fork
7. 判断命令来源用 type，别用 which（which 查不到 shell 内置和别名）
8. 统计文件行数/字节用 wc，查看二进制用 hexdump -C，别用 cat 读二进制

### 踩坑记录

```text
坑 1：rm -rf $DIR/ 当 DIR 为空变量，误删根目录
结论：变量没赋值，rm -rf / 把系统删光。
原因：脚本里 DIR 变量为空，路径变成 /，-f 又不提示。
解法：删之前 echo "$DIR" 校验非空，或用 rm -rf "/opt/$DIR" 限定父目录。

坑 2：find -exec 结果里带空格文件名导致命令断错
结论：文件名含空格，-exec {} 执行时参数被拆分。
原因：{} 未加引号，shell 按空格分词。
解法：用 find ... -print0 | xargs -0，或 -exec 里给 {} 加引号。

坑 3：cp -r 复制后文件权限和时间戳变了
结论：复制的目录权限丢失，时间戳全变成复制时间。
原因：cp -r 不保留属性，要用 -p 或 -a。
解法：目录备份用 cp -a（归档模式），或 tar -p。

坑 4：locate 搜不到刚创建的文件
结论：刚 touch 的文件 locate 查不到。
原因：locate 查的是 updatedb 的索引快照，新文件还没入索引。
解法：先 updatedb 刷新索引，或改用 find 实时查找。

坑 5：用 cat 查看大日志导致终端卡死
结论：几 GB 的日志 cat 一刷，终端直接卡住。
原因：cat 无分页，一次性输出全部内容。
解法：大文件用 less，或 tail/head 只看需要的部分。

坑 6：mv 跨文件系统移动大目录极慢
结论：把大目录 mv 到另一块盘，卡了十几分钟。
原因：跨文件系统 mv 是「复制 + 删除」，要完整读写数据，不是改目录项。
解法：同分区 mv 秒完成；跨分区用 rsync --remove-source-files 或接受复制耗时。

坑 7：用 find -exec rm {} \; 批量删几十万文件，卡到天荒地老
结论：海量小文件逐个 -exec rm，fork 了几十万次进程，慢到像卡死。
原因：\; 让 find 对每个匹配文件都起一个 rm 子进程，进程开销压倒一切。
解法：换成 -exec rm {} +（批量传参）或 find ... -delete（find 内置删除，零 fork）。

坑 8：在 Debian 系写的 rename 正则命令，拿到 Red Hat 系跑直接报错
结论：rename 's/\.txt$/.md/' *.txt 在 CentOS/Rocky 上报语法错误或 Unknown option。
原因：Debian/Ubuntu 装的是 Perl rename（支持正则 s///），Red Hat 系装的是 util-linux rename（只做字符串替换 rename old new），两套工具语法完全不同、命令不通用。
解法：跨发行版脚本别依赖 rename，用 shell 循环 for f in *.txt; do mv "$f" "${f%.txt}.md"; done 最稳妥。

坑 9：cd "$VAR" 变量为空时静默切到 $HOME，脚本在错误目录里继续执行
结论：脚本里 cd $DIR 的 DIR 为空时，cd 无参等价于 cd ~，切到 $HOME 且返回 0 不报错，后面的 rm/mv 全在 $HOME 里跑。
原因：POSIX 规定 cd 不带参数就切到 $HOME 并以成功退出；再用 `;` 或换行分隔命令时，前一条失败也拦不住后一条。
解法：cd 目标加双引号并显式判空（[ -n "$DIR" ] || exit 1），链式命令一律用 && 串联（cd "$DIR" && rm -rf ./build），批量脚本开头加 set -euo pipefail。

坑 10：for f in $(ls) 把含空格的文件名拆成多个参数
结论：for f in $(ls) 遍历 "my file.txt" 时被拆成 my 和 file.txt 两轮，cp/mv 要么报错要么对错误的文件动手。
原因：$(...) 命令替换后 shell 按 IFS（空格、制表符、换行）做单词拆分，文件名里的空格成了分隔符。
解法：优先用通配符 for f in *; do ...; done（bash 通配展开不做单词拆分）；需要处理命令输出时用 while IFS= read -r f; do ...; done < <(cmd)，别用 $(ls)。

坑 11：readlink -f 对路径中间不存在的目录返回空，脚本拿空值拼路径出事
结论：readlink -f /tmp/a/b/c 在 /tmp/a 不存在时输出空字符串且退出码非 0，脚本若把返回值当路径用就变成空或当前目录。
原因：GNU readlink -f 要求路径的每一级（除最后一段外）都真实存在才能规范化，中间缺一级就放弃、输出为空。
解法：允许路径不存在的场景用 readlink -m（--canonicalize-missing）；或先 [ -e "$p" ] 判断存在再接 readlink；拿到返回值一律判空再用。

坑 12：硬链接不能跨文件系统，跨分区做 ln 直接报 Invalid cross-device link
结论：给 /dev/sda2 根分区上的文件在 /dev/sdb 分区或 /boot/efi（vfat）里建硬链接，ln 报 Invalid cross-device link 失败。
原因：硬链接只是同一个 inode 的另一个目录项，inode 号只在单个文件系统内唯一，跨文件系统没有对应 inode 可指。
解法：跨文件系统只能建软链接 ln -s；硬链接也不能链目录（内核直接禁止，防目录环路）。判断两个路径是否同分区用 stat -c %d 比对设备号，或 df 路径 看是否同挂载点。

坑 13：ls | wc -l 统计文件数，遇到含换行的文件名就数错
结论：文件名里带换行符时，wc -l 把一个文件名数成两行，结果偏多；ls 在管道里一行一文件也只是近似，文件名含引号时还会被转义。
原因：ls 默认按终端宽度分列输出，且以换行分隔条目，而换行本身是文件名的合法字符，行数 ≠ 文件数。
解法：统计当前目录文件数用 find . -maxdepth 1 -type f -printf '.\n' | wc -l；要求绝对准确用 find . -maxdepth 1 -type f -printf '%f\0' | tr -cd '\0' | wc -c（以 NUL 计数，NUL 是文件名里唯一不可能出现的字节）。

坑 14：mv 跨文件系统大目录看着像卡死，中途中断源和目标都不完整
结论：跨分区的 mv 要整份复制再删源，几十 GB 目录走十几分钟像卡死；中途 Ctrl-C，源目录已被删掉一部分、目标也缺文件。
原因：跨设备 mv 退化成 cp + rm，没有事务也没有回滚，内核复制完才 unlink 源，中断发生在复制中途就两边都不完整（按文件逐个搬的实现中断时源已被删了一部分）。
解法：跨分区搬大目录用 rsync -a --partial --remove-source-files 分两步（先复制校验、确认无误再清源），或 tar -C 源 -cf - . | tar -C 目标 -xf - 走管道；同分区 mv 只改目录项、内核保证原子，秒完成。
```

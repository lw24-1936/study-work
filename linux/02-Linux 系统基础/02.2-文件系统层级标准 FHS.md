## 概述

FHS（Filesystem Hierarchy Standard，文件系统层级标准）规定了 Linux 根目录下每个目录该放什么，让不同发行版、不同程序的作者都能按约定找到文件。它的核心是「按用途分区，而不是按程序分区」——配置文件统一进 /etc、可变数据统一进 /var、可执行文件统一进 /usr。记住这张目录地图，排查「文件找不到、磁盘满了、程序装哪了」时就有了方向。

```text
FHS 三大分区逻辑：
1. 静态 vs 可变 —— /usr 存静态程序、/var 存运行时变化的数据（日志/缓存）
2. 共享 vs 独立 —— /usr 可跨机共享、/etc /var 是每台机器独立的本机配置
3. 真实 vs 虚拟 —— 普通目录落磁盘，/proc /sys /dev /run 是内核生成的内存文件系统
```

## 核心概念

1. **根目录职责**：/bin /sbin /lib 存基础命令和库（已合并到 /usr），/etc 存配置，/usr 存程序，/var 存可变数据（日志/缓存/数据库/队列），/home 存用户数据，/opt 存第三方独立软件，/boot 存内核引导文件。
2. **usr merge**：现代发行版把 /bin、/sbin、/lib 软链合并到 /usr 下，写脚本时 /usr/bin/xxx 和 /bin/xxx 等价。
3. **四个伪文件系统**：/proc /sys /dev /run 是内核在内存里动态生成的，不占磁盘、不能当普通文件编辑，但读它们能拿到 CPU/内存/进程/设备的一切运行信息。
4. **/etc 的定位**：系统级与软件级的配置都住这里（nginx、ssh、systemd），改配置先备份——它是「还原一台机器」最关键的目录之一。
5. **/usr 的定位**：只读的程序与共享数据，分 /usr/bin（命令）、/usr/lib（库）、/usr/share（架构无关数据）、/usr/local（手工编译安装）。生产/容器常只读挂载。
6. **/var 的定位**：可变数据聚集地——/var/log 日志、/var/cache 缓存、/var/lib 数据库、/var/spool 队列。磁盘告警第一眼先看它。
7. **/dev 的设备节点**：不是普通文件，是「设备入口」，每个节点由主设备号（major）和次设备号（minor）标识，内核靠这对数字路由到对应驱动。
8. **/run 与 /var/run**：/run 是 tmpfs（内存文件系统），放 PID 文件、socket、锁文件，重启自动清空；/var/run 在多数发行版是 /run 的软链。

```text
根目录职责表：
1. /bin  —— 基本命令（ls/cp/mv），已合并到 /usr/bin
2. /sbin —— 系统管理命令（fdisk/ifconfig），已合并到 /usr/sbin
3. /etc  —— 系统与软件的配置文件（/etc/nginx、/etc/ssh）
4. /usr  —— 用户程序与只读数据（/usr/bin、/usr/lib、/usr/share、/usr/local 手工安装）
5. /var  —— 可变数据（/var/log 日志、/var/cache 缓存、/var/lib 数据库、/var/spool 队列）
6. /home —— 普通用户主目录，/root 是 root 用户主目录
7. /tmp  —— 临时文件，所有人可写，重启可能被清空
8. /opt  —— 第三方独立软件（/opt/xxx 整个应用装一个目录）
9. /lib  —— 共享库（libc 等），已合并到 /usr/lib
10. /boot —— 内核与引导文件（vmlinuz、initramfs、grub）
11. /mnt /media —— 临时挂载点 / 可移动介质挂载点
```

```text
四个伪文件系统：
1. /proc —— 进程与内核信息，/proc/cpuinfo 内存 cpuinfo、/proc/meminfo 内存、/proc/<pid>/ 每个进程的目录
2. /sys  —— 内核对象模型（sysfs），设备/驱动/总线/电源，/sys/class/net 看网卡
3. /dev  —— 设备文件入口，/dev/sda 磁盘、/dev/null 黑洞、/dev/zero、/dev/random
4. /run  —— 运行时数据（tmpfs，重启清空），PID 文件、socket 文件、/run/lock
```

```text
目录该放什么不该放什么（易错边界）：
1. /usr —— 只放「包管理器管的程序」，手工编译放 /usr/local，别污染包管理器领地
2. /var —— 只放「运行时变化的数据」，程序本体别放这（要放 /usr 或 /opt）
3. /tmp —— 只放「临时文件」，重要数据别放（可能被清）；持久化数据放 /home 或 /var
4. /opt —— 只放「自包含的第三方整包应用」，配置/日志仍建议外放 /etc、/var/log 遵守 FHS
5. /etc —— 只放「配置」，别放可执行文件和数据
```

```text
设备节点的主次设备号（/dev 的工作原理）：
$ ls -l /dev/sda /dev/null
brw-rw---- 1 root disk 8, 0   /dev/sda    # b=块设备，8,0 = 主设备号,次设备号
crw-rw-rw- 1 root root 1, 3   /dev/null   # c=字符设备
major（主设备号）→ 内核路由到哪个驱动；minor（次设备号）→ 驱动区分是哪个具体设备
设备节点本身只是「入口标记」，真正读写由内核按这对数字转交驱动，所以 /dev 里其实没有真实数据。
```

```text
关键目录的默认权限（理解为什么普通用户能/不能写）：
/ 755、/etc 755、/usr 755 —— 系统目录，普通用户只读
/tmp 1777、/var/tmp 1777    —— 所有人可写 + sticky bit，防互删
/home/用户 700、/root 700   —— 用户主目录默认只自己可进
/var/log 755（内部文件多为 640）—— 日志只 root/adm 组可读
权限是 FHS 约定之外的另一层约束：目录「该放什么」+ 权限「谁能动」共同决定文件安全边界。
```

```text
FHS 里的其它目录（补全地图，别只知道前 11 个）：
1. /srv —— 服务数据（service data），如 /srv/www、/srv/ftp，放服务对外提供的数据
2. /mnt —— 管理员手动挂载的临时挂载点（mount /dev/sdb1 /mnt/data）
3. /media —— 系统自动挂载的可移动介质（U 盘/光盘），如 /media/user/USB
4. /lost+found —— fsck 修复后找回的孤儿文件碎片，每个 ext 文件系统根目录一个
5. /var/run → /run 软链 —— 运行时数据的兼容路径，老脚本写 /var/run 也指向 /run
```

## 工作原理

FHS 靠「按用途分区」让所有程序遵循同一套位置约定：程序本体只读、放 /usr（可被多台机器共享挂载）；运行时的日志/缓存/数据库/锁文件会变化，放 /var 和 /run；每台机器不同的配置放 /etc。这种「静态数据与可变数据分离」是它跟 Windows「程序 + 数据 + 配置堆一个目录」最本质的区别，也决定了备份策略（备份 /etc 和 /var 就能还原这台机器的配置和业务数据）。

```text
为什么这样分（设计意图）：
1. /usr 只读共享 —— 同一份程序镜像可挂给多台机器，升级只动一处
2. /etc + /var 本机独立 —— 配置和数据是每台机器自己的，备份它们即可还原
3. /tmp /run 易失 —— 临时和运行时数据放内存/临时盘，重启自动清、不留垃圾
```

伪文件系统的工作原理是「内核即时生成，不落磁盘」：/proc 和 /sys 是内核暴露自身状态的接口——读 /proc/meminfo 时，内核当场计算当前内存使用情况返回，文件本身不存在于磁盘上（大小显示为 0）；/dev 里的设备节点则是指向驱动的入口，读 /dev/null 就是丢弃、读 /dev/random 就是取随机数；/run 是 tmpfs，数据存在内存里，掉电即失。理解这一点，就不会犯「往 /proc 里写配置当永久存储」的错误。

```text
伪文件系统三大特性（为什么「不能当普通文件编辑」）：
1. 不占磁盘 —— df -h 看 /proc /sys /dev 大小是 0，数据由内核实时生成
2. 内容动态 —— 读一次变一次（如 /proc/meminfo），不能缓存、不能备份
3. 写入受限 —— 少量文件可写但需特定格式（echo 特定值），改错影响内核，优先用 sysctl
```

## 常用命令与配置

```shell
# 查看根目录一级结构 + 确认 usr merge
ls -la /
ls -ld /bin /sbin /lib      # 软链指向 /usr/bin 等

# 看各目录占用（磁盘满时定位用）
du -sh /var /usr /home /tmp 2>/dev/null
```

```shell
# 读 /proc 拿系统信息
cat /proc/cpuinfo | grep 'model name' | head -1   # CPU 型号
cat /proc/meminfo | head -3                        # 内存信息
ls /proc/$$                                        # 当前 shell 进程目录

# 读 /sys 拿设备信息
cat /sys/class/net/eth0/address                    # 网卡 MAC
cat /sys/class/thermal/thermal_zone0/temp          # CPU 温度（毫摄氏度）

# /dev 特殊设备
echo hello > /dev/null        # 丢弃输出
dd if=/dev/zero of=/dev/null bs=1M count=100   # 制造 100MB 写入
```

```shell
# 查已安装软件的文件分布（FHS 实战）
dpkg -L nginx                 # Debian 系：包的所有文件落在哪些 FHS 目录
rpm -ql nginx                 # Red Hat 系
dpkg -S /etc/nginx/nginx.conf # 反查文件属于哪个包（Debian）
rpm -qf /etc/nginx/nginx.conf # 反查（Red Hat）
```

```shell
# 确认伪文件系统挂载类型（为什么它们不占磁盘）
findmnt /proc /sys /dev /run    # 看挂载类型：proc/sysfs/devtmpfs/tmpfs
df -h /proc /sys /dev /run      # 大小全是 0 或内存盘
file /proc/meminfo /dev/null    # 识别文件类型（proc 显示空、dev 显示设备节点）
```

```shell
# 看 usr merge 的软链 + 设备节点的主次号
readlink -f /bin /sbin /lib     # 全部解析到 /usr/bin /usr/sbin /usr/lib
ls -l /dev/sda /dev/null /dev/zero   # b=块设备 c=字符设备，major,minor
stat -c '%n -> %F' /bin /etc /tmp    # 看文件/目录/软链类型
```

```shell
# /proc 更多常用入口（读系统状态的高频字段）
cat /proc/uptime              # 系统运行时长（秒 空闲秒）
cat /proc/loadavg             # 1/5/15 分钟负载均值
cat /proc/version             # 内核版本 + 编译信息
cat /proc/mounts              # 当前实际挂载表（/etc/fstab 的生效结果）
head /proc/net/tcp            # TCP 连接表（配合 /proc/net/dev 看网卡流量）
```

## 配置文件解析

```text
/etc —— 系统与软件配置的家（FHS 里最核心的配置目录）：
/etc/fstab          # 文件系统挂载表（开机自动挂载）
/etc/passwd /etc/shadow   # 用户账号与密码哈希
/etc/ssh/sshd_config      # SSH 服务配置
/etc/nginx/nginx.conf     # nginx 配置
/etc/cron.d/              # 定时任务配置片段
```

```text
/etc/profile 与 /etc/environment —— 全局环境配置：
/etc/profile       # 登录 shell 全局初始化（PATH、umask），各发行版再 include /etc/profile.d/*.sh
/etc/environment   # 系统级环境变量（PAM 读它，不区分 shell）
```

```text
/var 下的关键子目录（磁盘告警时按这个顺序查）：
/var/log      # 日志（access.log、syslog、journal），最常撑爆磁盘
/var/cache    # 缓存（apt 缓存、包缓存），可安全清理
/var/lib      # 程序数据（mysql、docker、postgresql 数据目录都在这）
/var/spool    # 队列（邮件队列、打印队列、cron 的 at 队列）
/var/tmp      # 比 /tmp 更「持久」的临时文件（重启不清，但仍有清理策略）
```

## 应用场景实战

### 场景一：磁盘满了，快速定位是哪个目录吃掉的

```shell
# 1. 先看哪个分区满了
df -h

# 2. 对满的分区逐层找大目录（/ 满了通常查 /var /usr /home /tmp）
du -sh /var/* 2>/dev/null | sort -rh | head -10

# 3. 常见元凶：日志（/var/log）、缓存（/var/cache）、数据库（/var/lib）、临时文件（/tmp）
ls -lhS /var/log | head
ls -lhS /tmp | head
```

```text
# 实测输出（本机真实分布）
$ du -sh /var /usr /home /tmp 2>/dev/null
36G     /var
8.8G    /usr
5.1G    /home
469M    /tmp
# /var 独占 36G，远超其它目录——典型的企业服务器形态：日志+数据库+容器数据都压在 /var
# 所以磁盘告警时第一眼就该看 /var 下的 /var/lib（数据库）、/var/log（日志）、/var/lib/docker（容器）。
```

### 场景二：装一个第三方软件到 /opt，并按 FHS 约定组织配置和日志

```shell
# 1. 软件本体装到 /opt/myapp
mkdir -p /opt/myapp/bin
cp ./myapp /opt/myapp/bin/

# 2. 配置文件放 /etc（系统级配置约定位置）
mkdir -p /etc/myapp
cp ./myapp.conf /etc/myapp/

# 3. 运行时数据放 /var（日志、PID 文件）
mkdir -p /var/log/myapp /run/myapp

# 4. 给用户加个 PATH，用软链暴露可执行文件
ln -s /opt/myapp/bin/myapp /usr/local/bin/myapp
```

### 场景三：查一个已安装软件的文件分布（FHS 实战）

```shell
# Debian 系：看 nginx 装的所有文件分别落在哪些 FHS 目录
dpkg -L nginx

# Red Hat 系：看 rpm 包的文件清单
rpm -ql nginx

# 反查：某个文件属于哪个包（丢了文件知道补哪个包）
dpkg -S /etc/nginx/nginx.conf      # Debian
rpm -qf /etc/nginx/nginx.conf      # Red Hat
```

```text
# 实测：nginx 包的文件严格按 FHS 分布（本机真实输出，Ubuntu 24.04）
$ dpkg -L nginx | grep -E '/(etc|usr|var)/' | head -20
/etc/nginx/nginx.conf          # 配置进 /etc
/usr/sbin/nginx                # 可执行进 /usr/sbin
/usr/lib/nginx/                # 模块与库进 /usr/lib
/var/log/nginx/                # 日志进 /var/log
/run/nginx.pid                 # PID 文件进 /run
# 一个包的文件精确落位到五个 FHS 目录——这正是「按用途分区」在真实软件里的体现。
```

## 性能与调优

```text
FHS 相关的性能/容量优化：
1. /var 单独分区 —— 日志/数据库/容器都写 /var，单独分区避免它写满拖垮根分区
2. /tmp 挂 tmpfs —— 临时文件落内存，读写快且重启自动清；代价是占内存、大文件别放
3. 挂载 noatime —— 关掉 atime 更新，减少读文件时的磁盘写（日志/数据库场景收益明显）
4. /usr 只读 + 共享挂载 —— 只读挂载 + 共享镜像，容器/无盘场景省空间、提启动速度
5. 日志放 /var/log 并做轮转 —— 避免日志无限增长占满 /var（配合 logrotate）
6. 清理 /var/cache —— apt 缓存、包缓存可安全清（apt clean / dnf clean all），省出几个 G
```

## 安全与权限

```text
FHS 安全要点：
1. /tmp 必须有 sticky bit —— 所有人可写但只能删自己的文件（drwxrwxrwt），防互相删文件
2. /var/log 收紧权限 —— 日志含敏感信息，目录 750、文件 640，只 root 和 adm 组可读
3. /proc /sys 只读保护 —— 伪文件系统多只读，写错会影响内核，改参数用 sysctl
4. /usr 只读挂载 —— 生产/容器场景把 /usr 只读，防被入侵后篡改程序文件
5. 别把敏感数据放 /tmp /var/tmp —— 世界可读的临时目录，密钥/凭据绝不落这里
6. /dev 设备节点权限 —— 磁盘设备（/dev/sda）默认 root:disk 660，防普通用户直接读写裸设备绕过文件权限
```

## 故障排查

```shell
# 1. 文件找不到：确认该程序按 FHS 装在哪
dpkg -S <文件名>        # Debian 反查所属包
find / -name "<文件名>" 2>/dev/null   # 兜底全盘找

# 2. 磁盘满：按 FHS 逐层定位
df -h
du -sh /var/* 2>/dev/null | sort -rh | head

# 3. Read-only file system：/usr 或根被只读挂载了
mount | grep -E 'ro,|,ro '
mount -o remount,rw /    # 重新读写挂载（根分区）

# 4. /tmp 文件被清：确认 systemd-tmpfiles 清理策略
systemctl status systemd-tmpfiles-clean.timer

# 5. 程序报「找不到 PID 文件/socket」：查 /run 是否被清空（重启后正常现象）
ls -la /run/myapp
# /run 是 tmpfs，重启即清；程序要有能力在启动时重建这些文件

# 6. 磁盘显示有空间但报 No space left on device：inode 用完了
df -h /          # 空间还有
df -i /          # 但 inode 用完（大量小文件把 inode 占满）
find / -xdev -type f | wc -l   # 数文件总量，定位是哪个目录塞了几十万小文件
```

## 常见问题

```text
Q1: /bin 和 /usr/bin 有什么区别？
A: 现在没区别。usr merge 后 /bin 是 /usr/bin 的软链，两个路径等价。

Q2: 为什么磁盘告警先看 /var？
A: /var 是日志(/var/log)+数据库(/var/lib)+容器(/var/lib/docker)的聚集地，是企业服务器占空间的大头。

Q3: 手工装的软件放哪？
A: 第三方独立软件放 /opt/<app>（整个应用一个目录），自己编译的放 /usr/local，别污染包管理器领地。

Q4: /proc /sys 里的文件能改吗？
A: 多数只读，少量可写但要用正确格式（echo 特定值），改错可能影响系统，优先用 sysctl 命令。

Q5: /tmp 的文件能放重要数据吗？
A: 不能。它可能被 tmpfiles 定期清理、重启清空，重要数据放 /home 或 /var。

Q6: /run 和 /var/run 什么关系？
A: /run 是内存文件系统（tmpfs）放 PID/socket/锁文件，重启清空；/var/run 在多数发行版是 /run 的软链，两者等价。

Q7: /dev 里的文件是真文件吗？
A: 不是。是设备节点，只存主次设备号（major/minor），读写时内核按这对数字转交驱动，所以 ls -l 看到的是 b/c 开头而非 -（普通文件）。

Q8: /srv、/opt、/usr/local 都放第三方东西，怎么区分？
A: /opt 放自包含的整包商业/第三方软件；/usr/local 放手工源码编译的程序（按 /usr 的结构组织）；/srv 放服务对外提供的数据（网站根、FTP 目录）。数据放 /srv，程序放 /opt 或 /usr/local。
```

## 面试题

```text
1. FHS 的核心思想是什么？
   答：按用途分区而非按程序分区——配置进 /etc、可变数据进 /var、程序进 /usr，静态与可变数据分离。

2. /var 和 /tmp 放什么、区别是什么？
   答：/var 放持久化的可变数据（日志/缓存/数据库）；/tmp 放临时文件，可能重启清空、不持久。

3. /proc 是什么？占磁盘吗？
   答：内核生成的内存文件系统（procfs），暴露进程和内核状态，不占磁盘，随内核动态生成。

4. 为什么 /usr 可以只读挂载？
   答：/usr 只放静态程序文件，运行时不写，可只读挂载 + 跨机共享，提升安全和可维护性。

5. 备份一台服务器的配置和业务数据，最小要备哪些目录？
   答：/etc（配置）、/var（业务数据/日志）、/home（用户数据），配合软件清单即可还原。

6. /dev/sda 里的 8,0 是什么意思？
   答：主设备号 8 和次设备号 0。主设备号路由到磁盘驱动，次设备号区分具体磁盘。设备节点本身不存数据，只是驱动入口。

7. 为什么 /tmp 要有 sticky bit？
   答：/tmp 所有人可写（1777 权限），sticky bit 保证「只有文件属主和 root 能删除」，否则任何用户都能删别人的临时文件。

8. /proc 和 /sys 都暴露内核信息，区别是什么？
   答：/proc（procfs）偏「进程与内核运行状态」，是历史悠久的只读信息接口；/sys（sysfs）偏「内核对象模型」，按设备/驱动/总线结构化、可写（配合 udev 做设备管理）。读状态看 /proc，操作设备属性看 /sys。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 手工编译安装的软件放 /usr/local 或 /opt，别污染 /usr 的包管理器领地
2. 排查磁盘满按 FHS 定位：日志 /var/log、缓存 /var/cache、数据 /var/lib、临时 /tmp
3. 脚本里写临时文件用 /tmp，写 PID 文件和 socket 用 /run（重启自动清空，不留垃圾）
4. 读系统状态优先 /proc /sys，比装一堆监控工具更快更准
5. 改 /etc 下的配置前先备份，这个目录是所有软件配置的家
6. 给服务器分区时 /var 单独挂（或至少预留足够空间），日志和数据库都靠它
7. 数据目录（MySQL/PG/Docker）统一放 /var/lib，配合持久化磁盘和备份策略

### 踩坑记录

```text
坑 1：把 /tmp 当成永久存储，重启后文件没了
结论：放 /tmp 的文件重启后丢失，或长时间不用被 systemd-tmpfiles 清理。
原因：/tmp 是临时目录，部分发行版用 tmpfiles 定时清空旧文件。
解法：要长期保留的文件放 /home 或 /var，别放 /tmp。

坑 2：往 /proc 里写数据「成功」了但没效果甚至报错
结论：以为能像普通文件一样编辑 /proc 下的内容。
原因：/proc /sys 是内核生成的内存文件系统，多数只读或需要特定格式写入。
解法：用专门的命令（sysctl、echo 特定值到特定文件）修改，别当普通文件编辑。

坑 3：直接 rm /bin 里的文件导致命令全挂
结论：删了系统命令，连 ls 都跑不了。
原因：/bin 是基础命令所在，删错导致系统无法操作。
解法：基础命令目录别乱动；误删后用 busybox 或救援模式恢复。

坑 4：装软件把文件散得到处都是，卸载时删不干净
结论：手工安装的软件可执行文件、库、配置、日志分散，卸载找不到。
原因：没按 FHS 约定归类，直接解压到根目录。
解法：第三方软件统一装 /opt/<app>，配置 /etc/<app>，日志 /var/log/<app>，卸载删整个目录即可。

坑 5：把数据库数据目录放在 /tmp 或内存盘，重启丢数据
结论：MySQL/PG 数据目录放错位置，重启后数据全丢。
原因：数据目录放在 tmpfs 或 /tmp 这类易失目录。
解法：持久化数据统一放 /var/lib（如 /var/lib/mysql），并挂到持久化磁盘。

坑 6：把程序日志写到 /usr 或程序目录，只读文件系统写失败
结论：程序在 /usr 下写日志报 Read-only file system。
原因：/usr 按 FHS 约定是只读共享目录，容器/只读根场景下不可写。
解法：运行时可变数据（日志/缓存/PID 文件）一律放 /var 和 /run。

坑 7：/var/log 占满根分区导致服务起不来
结论：日志把 /var 写满，mysql/nginx 等服务报「磁盘空间不足」启动失败。
原因：日志没有轮转（logrotate 未配或失效），持续增长直到占满分区。
解法：先 truncate -s 0 或 rm 掉大日志恢复服务，再配 logrotate 做轮转压缩，/var 单独分区隔离风险。
```

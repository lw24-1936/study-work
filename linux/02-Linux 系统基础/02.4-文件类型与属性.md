## 概述

Linux 里「一切皆文件」：普通文件、目录、设备、管道、socket 都是文件，用同一套接口操作。每个文件的核心是 inode——它存着文件的元数据（权限、属主、大小、时间戳、数据块指针），而文件名只是目录项（dentry）里的一个标签，指向 inode。理解「文件名 → 目录项 → inode → 数据块」这条链，硬链接、符号链接、时间戳这些概念就都通了。

```text
文件的三层结构：
1. 文件名 —— 只是目录项里的一个名字，不是文件的本质
2. inode —— 文件的元数据（权限/属主/大小/时间戳/数据块指针），一个文件一个 inode
3. 数据块 —— 文件真正的内容，inode 里的指针指向它
关键推论：多个文件名可以指向同一个 inode（硬链接），删除文件 = 断开目录项链接
```

## 核心概念

1. **七种文件类型**：ls -l 首字符标识——`-` 普通文件、`d` 目录、`l` 软链、`c` 字符设备、`b` 块设备、`p` 管道、`s` socket。file 命令识别内容类型比扩展名可靠。
2. **inode 与目录项**：inode 存元数据和数据块指针、不存文件名；目录项是「文件名 → inode 号」映射。删除 = 断开链接，链接数归零且无进程占用才释放数据块。
3. **硬链接 vs 软链**：硬链接是同一 inode 的多个名字（删一个不影响、不能跨分区、不能链目录）；软链是存路径的独立文件（可跨分区、可链目录、目标删了断链）。
4. **三个时间戳**：atime 访问时间、mtime 内容修改时间、ctime inode 元数据变更时间（chmod/chown 也变）。

```text
七种文件类型（ls -l 首字符）：
1. - 普通文件 —— 文本、二进制、数据，最常规的文件
2. d 目录 —— 目录也是一种文件，内容是目录项列表
3. l 符号链接 —— 软链，存目标路径，可跨文件系统、可指向目录
4. c 字符设备 —— 按字节流访问的设备（键盘 /dev/tty、终端）
5. b 块设备 —— 按块访问的设备（磁盘 /dev/sda，可随机读写）
6. p 管道 FIFO —— 命名管道，进程间单向数据流
7. s socket —— 本地进程间通信的 socket 文件（如 /run/mysqld/mysqld.sock）
```

```text
inode 关键点：
1. inode 存什么 —— 权限、属主属组、大小、时间戳、链接数、数据块指针，不存文件名
2. 目录项存什么 —— 文件名 ↔ inode 号的映射，目录文件的内容就是一张表
3. 链接数 —— inode 被几个目录项引用，ls -l 第二列；归零才可释放
4. 打开计数 —— 进程 open 的文件即使删除，进程还持有 inode，空间不释放
```

```text
硬链接 vs 符号链接：
1. 硬链接 —— 同一 inode 的多个名字，删原文件不影响（链接数>1），不能跨分区、不能链目录
2. 符号链接 —— 存路径的独立文件，可跨分区、可链目录，目标删除即断链
3. 判断 —— 硬链接 ls -i 看 inode 号相同；软链 ls -l 首字符是 l
4. 选型 —— 备份/别名多用软链，需要「同一文件多个入口」且不依赖路径时用硬链
```

## 工作原理

文件访问的完整链路是「文件名 → 目录项 → inode → 数据块」：程序用路径找文件时，内核先在目录项里查文件名对应的 inode 号，再读 inode 拿到权限、大小和数据块指针，最后按指针读数据块。「删除文件」只是把目录项里这条映射删掉（链接数 -1），当链接数为 0 且没有进程持有该 inode 时，数据块才被标记为空闲。这就是「rm 了文件但进程还开着句柄，磁盘不释放」的底层原因。

```text
访问链路与删除本质：
文件名 → 目录项（dentry 表）→ inode（元数据 + 数据块指针）→ 数据块（真实内容）
删除 = 断开目录项链接（链接数-1）；链接数=0 且无进程占用 → 数据块真正释放
```

## 常用命令与配置

```shell
# 看文件类型 + 内容类型
ls -l /etc/passwd /tmp /dev/sda /dev/null
file /etc/passwd
file /bin/ls

# 看 inode 号与链接数
ls -li /etc/passwd      # 第一列 inode 号，第三列链接数
stat -c '%i %h %n' /etc/passwd

# stat 完整元数据 + 格式串提取
stat /etc/passwd
stat -c 'inode=%i links=%h size=%s mode=%a' /etc/passwd
stat -c '%U %G %y' /etc/passwd     # 属主 属组 修改时间
```

```shell
# 建硬链接与软链
echo hello > a.txt
ln a.txt a.hard          # 硬链接：a.txt 和 a.hard 同一 inode
ln -s a.txt a.soft       # 软链：a.soft 存 "a.txt" 这个路径
ls -li a.txt a.hard a.soft

# 删除原文件验证
rm a.txt
cat a.hard               # 还在（链接数>1）
cat a.soft               # No such file or directory（断链）
```

```text
# 实测（/tmp 下真实执行）
$ echo hello > demo.txt && ln demo.txt demo.hard && ln -s demo.txt demo.soft
$ ls -li demo.txt demo.hard demo.soft
57415528 -rw-r--r-- 2 root root 6  8月 18 21:36 demo.hard
57415530 lrwxrwxrwx 1 root root 8  8月 18 21:36 demo.soft -> demo.txt
57415528 -rw-r--r-- 2 root root 6  8月 18 21:36 demo.txt
# 关键两点：demo.hard 和 demo.txt 的 inode 都是 57415528（同一文件，链接数=2）
# demo.soft 是独立 inode 57415530，首字符 l，内容是指向 demo.txt 的路径。
```

```shell
# 观察三个时间戳
echo a > f.txt
stat -c '%x %y %z' f.txt     # atime mtime ctime
cat f.txt                    # 读一次，atime 变
chmod 600 f.txt              # 改权限，ctime 变，mtime 不变
echo b >> f.txt              # 改内容，mtime 和 ctime 都变
ls -lu f.txt                 # atime；ls -l 看 mtime；ls -lc 看 ctime

# 定位「删了文件但磁盘不释放」
lsof +L1
```

## 配置文件解析

```text
/etc/magic —— file 命令的魔数数据库：
# 记录各文件格式的「魔数」（文件头特征字节），file 靠它识别内容类型而非扩展名
# 例：PDF 文件头是 %PDF-，ELF 可执行文件头是 \x7fELF
# 自定义魔数规则可追加到 /etc/magic 或 ~/.magic
```

```text
/proc/sys/fs —— 文件系统相关的内核参数（与 inode 相关的运行时配置）：
/proc/sys/fs/inode-max        # 系统 inode 上限（只读）
/proc/sys/fs/file-max         # 系统打开文件句柄上限
# 用户级限制看 /etc/security/limits.conf 的 nofile
```

## 应用场景实战

### 场景一：排查「文件删了但磁盘空间没释放」

```shell
# 1. 磁盘满，先看占用
df -h /

# 2. 找「已删除但仍被进程占用」的文件（lsof 显示 deleted）
lsof +L1 | grep deleted

# 3. 找到占用进程后，重启或 kill 该进程释放空间
# 例：nginx 的日志被删了但进程还开着文件句柄
systemctl restart nginx
df -h /    # 空间回来了
```

### 场景二：给可执行程序建软链并校验时间戳属性

```shell
# 1. 程序装在 /opt/app，建软链到 PATH
ln -s /opt/app/bin/tool /usr/local/bin/tool
which tool

# 2. 验证软链指向与目标
ls -l /usr/local/bin/tool        # l 开头，箭头指向真实路径
readlink -f /usr/local/bin/tool  # 解析出最终真实路径

# 3. 用 stat 核对属性（权限/时间戳/类型）
stat -c '%F %a %U %y' /opt/app/bin/tool
```

## 性能与调优

```text
inode / 时间戳相关性能优化：
1. 挂载 noatime —— 关闭 atime 更新，读文件不再产生磁盘写（日志/数据库收益大）
2. 防 inode 耗尽 —— 海量小文件场景 inode 比容量先耗尽，df -i 监控 inode 使用率
3. 稀疏文件省空间 —— 逻辑大小大、实际占用小（Blocks < Size），备份用 tar -S 保留稀疏
4. 少用全盘 find —— 全盘遍历 IO 重，优先 locate 索引或用 -prune 排除大目录
5. 硬链接省空间 —— 需要多份相同大文件时用硬链接，只占一份磁盘（如容器镜像分层）
```

## 安全与权限

```text
文件类型与属性安全要点：
1. 软链攻击（symlink race）—— 高权限程序操作可被换掉的软链目标，注意 TOCTOU 竞态
2. SUID 文件风险 —— 属主是 root 且带 SUID 的程序是提权面，定期审查（find / -perm -4000）
3. 断链检查 —— 软链目标被删后脚本静默失效，用 readlink -f 校验
4. socket 文件权限 —— /run 下的 socket 靠文件权限控制谁能连（如 mysql.sock 660）
5. /tmp sticky bit —— 防其他用户删你的文件，检查 drwxrwxrwt
```

## 故障排查

```shell
# 1. 断链：软链目标不存在
ls -l <软链>        # 红色闪烁 / 箭头指向不存在的路径
readlink <软链>      # 看它存的路径

# 2. inode 耗尽（No space left on device 但 df -h 还有空间）
df -i /              # 看 inode 使用率是不是 100%

# 3. 磁盘不释放
lsof +L1 | grep deleted    # 找被进程占用的已删文件

# 4. file 识别错误
file <文件>          # 没识别对就查 /etc/magic 有没有对应魔数
```

## 常见问题

```text
Q1: 硬链接和软链怎么选？
A: 需要「同一文件多个入口、不依赖路径」用硬链接；需要跨分区、指向目录、跟随路径用软链。

Q2: 为什么删了文件磁盘没释放？
A: 进程还持有被删文件的 inode，链接数归零但打开计数>0，数据块没释放。lsof +L1 找、重启进程。

Q3: atime、mtime、ctime 分别什么时候变？
A: atime 读内容时变，mtime 改内容时变，ctime 改内容/权限/属主（inode 元数据）都变。

Q4: chmod 改了权限，为什么 mtime 没变但 ctime 变了？
A: mtime 只记录内容修改，chmod 改的是 inode 元数据、归 ctime 管。

Q5: 为什么目录不能建硬链接？
A: 内核禁止（防目录环），目录共享用软链或 bind mount。
```

## 面试题

```text
1. inode 里存什么、不存什么？
   答：存权限、属主属组、大小、时间戳、链接数、数据块指针；不存文件名（文件名在目录项里）。

2. 硬链接和软链的本质区别？
   答：硬链接是同一 inode 的多个目录项（删一个不影响、不能跨分区/链目录）；软链是存路径的独立文件（目标删了断链）。

3. 删除文件的本质是什么？
   答：断开目录项与 inode 的链接（链接数-1），链接数归零且无进程占用时数据块才释放。

4. 为什么「rm 大日志后磁盘没释放」？
   答：进程还持有文件句柄（打开计数>0），数据块未释放。lsof +L1 找 deleted 文件、重启进程。

5. 三个时间戳的区别？
   答：atime 访问时间、mtime 内容修改时间、ctime inode 元数据变更时间（chmod/chown 也变 ctime）。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 判断文件内容类型用 file 命令，别信扩展名（Linux 不靠扩展名）
2. 给程序建别名用软链（ln -s），跨分区、指向目录都行
3. 备份工具按 mtime 增量判断，改权限导致 ctime 变化不会误触发 mtime 备份
4. 排查磁盘不释放先 lsof +L1 找 deleted 文件，重启占用进程
5. 软链要检查目标存在性，避免「断链」在脚本里静默失效

### 踩坑记录

```text
坑 1：删了日志文件磁盘空间没回来
结论：rm 掉大日志，df 看磁盘还是满的。
原因：进程还持有被删文件的 inode（文件句柄），数据块没释放。
解法：lsof +L1 找 deleted 文件，重启或 kill 占用进程。

坑 2：把硬链接当软链用，以为删原文件软链还在
结论：ln a.txt b.txt 建的是硬链接，删除 a.txt 后 b.txt 内容居然还在。
原因：硬链接指向同一 inode，链接数>1 数据不释放。
解法：明确区分 ln（硬链接）和 ln -s（软链），需要「跟随路径」的用 -s。

坑 3：软链指向被删，脚本静默失败
结论：软链目标删了，脚本读软链拿到空/报错但没显式报。
原因：软链断链后操作目标文件时静默失败。
解法：脚本里先 readlink -f 校验目标存在，或加 set -e 让错误显性。

坑 4：chmod 后备份工具做了全量备份
结论：只改了权限，备份却把文件全量重传。
原因：备份工具用 ctime 判断变化，chmod/chown 都会更新 ctime。
解法：了解备份工具的判据（mtime 还是 ctime），权限变更后手动触发或接受全量。

坑 5：给目录建硬链接失败
结论：ln /data /backup 报 Operation not permitted。
原因：目录不能建硬链接（内核禁止，防环）。
解法：目录共享用软链或 bind mount，别用硬链接。
```

## 概述

Linux 里「一切皆文件」：普通文件、目录、设备、管道、socket 都是文件，用同一套接口操作。每个文件的核心是 inode——它存着文件的元数据（权限、属主、大小、时间戳、数据块指针），而文件名只是目录项（dentry）里的一个标签，指向 inode。理解「文件名 → 目录项 → inode → 数据块」这条链，硬链接、符号链接、时间戳这些概念就都通了。

```text
文件的三层结构：
1. 文件名 —— 只是目录项里的一个名字，不是文件的本质
2. inode —— 文件的元数据（权限/属主/大小/时间戳/数据块指针），一个文件一个 inode
3. 数据块 —— 文件真正的内容，inode 里的指针指向它
关键推论：多个文件名可以指向同一个 inode（硬链接），删除文件 = 断开目录项链接
```

## 七种文件类型

`ls -l` 输出的第一个字符标识文件类型。七种类型里，普通文件、目录、符号链接是日常接触最多的；字符设备、块设备是硬件接口；管道（FIFO）和 socket 是进程间通信的通道。用 `file` 命令能识别文件的具体内容类型，比看扩展名可靠（Linux 不靠扩展名判断文件类型）。

```text
七种文件类型（ls -l 首字符）：
1. - 普通文件 —— 文本、二进制、数据，最常规的文件
2. d 目录 —— 目录也是一种文件，内容是目录项列表
3. l 符号链接 —— 软链，存目标路径，可跨文件系统、可指向目录
4. c 字符设备 —— 按字节流访问的设备（键盘 /dev/tty、终端）
5. b 块设备 —— 按块访问的设备（磁盘 /dev/sda，可随机读写）
6. p 管道 FIFO —— 命名管道，进程间单向数据流
7. s socket —— 本地进程间通信的 socket 文件（如 /run/mysqld/mysqld.sock）
```

```shell
# 看文件类型
ls -l /etc/passwd /tmp /dev/sda /dev/null
# -rw-r--r-- 普通文件，drwxr-xr-x 目录，brw-rw---- 块设备，crw-rw-rw- 字符设备

# 用 file 识别内容类型（比扩展名可靠）
file /etc/passwd
file /bin/ls
file a.log.gz

# 看一个目录文件里的内容（目录项）
ls -i /tmp          # -i 显示 inode 号
```

## inode 与目录项

inode 存文件的元数据和数据块指针，唯独不存文件名。文件名存在目录项（dentry）里，目录项是「文件名 → inode 号」的映射表。所以「删除文件」的本质是断开目录项和 inode 的链接，当 inode 的链接数为 0 且没有进程打开它时，数据块才真正释放。这也是为什么「删了文件但进程还占着，磁盘不释放」——链接数归零但进程还持有 inode。

```text
inode 关键点：
1. inode 存什么 —— 权限、属主属组、大小、时间戳、链接数、数据块指针，不存文件名
2. 目录项存什么 —— 文件名 ↔ inode 号的映射，目录文件的内容就是一张表
3. 链接数 —— inode 被几个目录项引用，ls -l 第二列；归零才可释放
4. 打开计数 —— 进程 open 的文件即使删除，进程还持有 inode，空间不释放
```

```shell
# 看 inode 号与链接数
ls -li /etc/passwd      # 第一列 inode 号，第三列链接数
stat -c '%i %h %n' /etc/passwd   # inode 号、链接数、文件名

# 定位「删了文件但磁盘不释放」：找被删除但仍被进程占用的文件
lsof +L1
```

## stat

stat 命令一次性展示一个文件 inode 里的所有元数据：inode 号、类型、权限、链接数、属主、大小、三个时间戳、数据块信息。它比 ls -l 更全（ls 只显示 mtime 和部分字段）。stat 的 -c 参数可以按格式串提取任意字段，写脚本时特别有用。

```text
stat 展示的字段：
1. 基础 —— inode 号、文件类型、权限、硬链接数、属主属组
2. 大小 —— 逻辑大小 Size 与实际占用 Blocks（可能不一致，稀疏文件）
3. 时间戳 —— Access 访问时间、Modify 修改时间、Change 变更时间
4. 设备 —— 所在设备与 inode 所在设备（跨文件系统判断）
```

```shell
# 完整查看一个文件的元数据
stat /etc/passwd

# 按格式串提取字段（脚本常用）
stat -c 'inode=%i links=%h size=%s mode=%a' /etc/passwd
stat -c '%U %G %y' /etc/passwd     # 属主 属组 修改时间
```

## 硬链接与符号链接

硬链接和符号链接是两种不同的「别名」机制。硬链接是目录项直接指向同一个 inode——删除任意一个链接，数据还在（只要链接数 ≥1），但不能跨文件系统、不能给目录建硬链接。符号链接是一个独立的文件，内容存的是目标路径——可以跨文件系统、可以指向目录，但目标删了它就变成「断链」。日常用 ln -s 建软链、ln 建硬链接。

```text
硬链接 vs 符号链接：
1. 硬链接 —— 同一 inode 的多个名字，删原文件不影响（链接数>1），不能跨分区、不能链目录
2. 符号链接 —— 存路径的独立文件，可跨分区、可链目录，目标删除即断链
3. 判断 —— 硬链接 ls -i 看 inode 号相同；软链 ls -l 首字符是 l
4. 选型 —— 备份/别名多用软链，需要「同一文件多个入口」且不依赖路径时用硬链
```

```shell
# 建硬链接与软链
echo hello > a.txt
ln a.txt a.hard          # 硬链接：a.txt 和 a.hard 同一 inode
ln -s a.txt a.soft       # 软链：a.soft 存 "a.txt" 这个路径

ls -li a.txt a.hard a.soft    # 看 inode：hard 相同，soft 是 l 且 inode 不同
```

```text
# 实测（/tmp 下真实执行）
$ echo hello > demo.txt && ln demo.txt demo.hard && ln -s demo.txt demo.soft
$ ls -li demo.txt demo.hard demo.soft
57415528 -rw-r--r-- 2 root root 6  8月 18 21:36 demo.hard
57415530 lrwxrwxrwx 1 root root 8  8月 18 21:36 demo.soft -> demo.txt
57415528 -rw-r--r-- 2 root root 6  8月 18 21:36 demo.txt
# 关键两点：demo.hard 和 demo.txt 的 inode 都是 57415528（同一文件，链接数=2）
# demo.soft 是独立 inode 57415530，首字符 l，内容是指向 demo.txt 的路径。
```

```shell
# 验证硬链接：删除原文件，硬链接内容还在，软链断掉
rm a.txt
cat a.hard               # 还在
cat a.soft               # No such file or directory
```

## 时间戳

Linux 每个文件有三个时间戳：atime（access time，最近读取时间）、mtime（modify time，内容最近修改时间）、ctime（change time，inode 元数据最近变更时间，如 chmod/chown 也会变）。ls -l 默认显示 mtime，ls -lu 显示 atime，ls -lc 显示 ctime。备份工具常按 mtime 判断文件是否变化，所以理解三者区别才能解释「我没改文件，为什么备份又全量传了」。

```text
三个时间戳：
1. atime 访问时间 —— 读文件内容时更新，ls -lu 查看
2. mtime 修改时间 —— 文件内容变化时更新，ls -l 默认显示
3. ctime 变更时间 —— inode 元数据变化时更新（改内容/改权限/改属主都会），ls -lc 查看
注意：chmod/chown 会更新 ctime 但不更新 mtime（内容没变）
```

```shell
# 观察三个时间戳
echo a > f.txt
stat -c '%x %y %z' f.txt     # atime mtime ctime

cat f.txt                    # 读一次，atime 变
chmod 600 f.txt              # 改权限，ctime 变，mtime 不变
echo b >> f.txt              # 改内容，mtime 和 ctime 都变

ls -lu f.txt                 # atime
ls -l  f.txt                 # mtime
ls -lc f.txt                 # ctime
```

## 应用场景实战

### 场景一：排查「文件删了但磁盘空间没释放」

```shell
# 1. 磁盘满，先看占用
df -h /

# 2. 找「已删除但仍被进程占用」的文件（lsof 显示 deleted）
lsof +L1 | grep deleted

# 3. 找到占用进程后，重启或 kill 该进程释放空间
# 例：nginx 的日志被删了但进程还开着文件句柄
systemctl restart nginx
df -h /    # 空间回来了
```

### 场景二：给可执行程序建软链并校验时间戳属性

```shell
# 1. 程序装在 /opt/app，建软链到 PATH
ln -s /opt/app/bin/tool /usr/local/bin/tool
which tool

# 2. 验证软链指向与目标
ls -l /usr/local/bin/tool        # l 开头，箭头指向真实路径
readlink -f /usr/local/bin/tool  # 解析出最终真实路径

# 3. 用 stat 核对属性（权限/时间戳/类型）
stat -c '%F %a %U %y' /opt/app/bin/tool
```

## 最佳实践与踩坑记录

### 最佳实践

1. 判断文件内容类型用 file 命令，别信扩展名（Linux 不靠扩展名）
2. 给程序建别名用软链（ln -s），跨分区、指向目录都行
3. 备份工具按 mtime 增量判断，改权限导致 ctime 变化不会误触发 mtime 备份
4. 排查磁盘不释放先 lsof +L1 找 deleted 文件，重启占用进程
5. 软链要检查目标存在性，避免「断链」在脚本里静默失效

### 踩坑记录

```text
坑 1：删了日志文件磁盘空间没回来
结论：rm 掉大日志，df 看磁盘还是满的。
原因：进程还持有被删文件的 inode（文件句柄），数据块没释放。
解法：lsof +L1 找 deleted 文件，重启或 kill 占用进程。

坑 2：把硬链接当软链用，以为删原文件软链还在
结论：ln a.txt b.txt 建的是硬链接，删除 a.txt 后 b.txt 内容居然还在。
原因：硬链接指向同一 inode，链接数>1 数据不释放。
解法：明确区分 ln（硬链接）和 ln -s（软链），需要「跟随路径」的用 -s。

坑 3：软链指向被删，脚本静默失败
结论：软链目标删了，脚本读软链拿到空/报错但没显式报。
原因：软链断链后操作目标文件时静默失败。
解法：脚本里先 readlink -f 校验目标存在，或加 set -e 让错误显性。

坑 4：chmod 后备份工具做了全量备份
结论：只改了权限，备份却把文件全量重传。
原因：备份工具用 ctime 判断变化，chmod/chown 都会更新 ctime。
解法：了解备份工具的判据（mtime 还是 ctime），权限变更后手动触发或接受全量。

坑 5：给目录建硬链接失败
结论：ln /data /backup 报 Operation not permitted。
原因：目录不能建硬链接（内核禁止，防环）。
解法：目录共享用软链或 bind mount，别用硬链接。
```

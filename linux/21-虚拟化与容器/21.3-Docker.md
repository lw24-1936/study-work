## 概述

Docker 是目前最主流的容器化工具，把「应用 + 依赖 + 运行环境」打包成可移植的镜像，在任何装了 Docker 的机器上都能一致地跑起来，解决「我本地能跑、你环境不行」的问题。核心是三大对象：镜像（Image，只读模板）、容器（Container，镜像的运行实例）、仓库（Registry，镜像的存储/分发中心，如 Docker Hub）。它建立在上一节的 namespace/cgroups 之上，本质是对 Linux 容器能力的工程化封装。

```text
Docker 三对象：
镜像 Image     只读的分层模板（构建产物，类比「类」）
容器 Container 镜像的运行实例（类比「对象」），可写层在其上
仓库 Registry  镜像的存储/分发（Docker Hub / 私有 registry）
```

## 核心概念

### 镜像（Image）

镜像是容器的只读模板，由 Dockerfile 构建，由多个分层（layer）叠加而成，含应用代码、运行时、依赖库、环境变量、启动命令。镜像按「仓库:标签」命名（如 `nginx:1.25`，`nginx` 是仓库名，`1.25` 是 tag，缺省 tag 为 `latest`）。镜像是不可变的——改镜像只能重新 build 出新镜像。

```shell
docker pull nginx:1.25          # 从 Docker Hub 拉取镜像
docker images                   # 列出本地镜像（含 REPOSITORY/TAG/SIZE）
docker image history nginx:1.25 # 看镜像的分层结构
docker rmi nginx:1.25           # 删除镜像
docker tag nginx:1.25 myrepo/nginx:v1   # 打标签
docker push myrepo/nginx:v1     # 推送到仓库
```

### 容器（Container）

容器是镜像的运行实例，在镜像的只读层之上加一层可写层。容器有独立生命周期：创建（create）→ 启动（start）→ 运行 → 停止（stop）→ 删除（rm）。`docker run` 是 create + start 的合体，是最高频命令。

```shell
docker run -d --name web -p 8080:80 nginx:1.25    # 后台启动并映射端口
docker ps                        # 列出运行中的容器
docker ps -a                     # 含已停止的容器
docker exec -it web bash         # 进入运行中容器执行命令
docker logs -f web               # 看容器日志
docker stop web && docker rm web # 停止并删除
docker rm -f web                 # 强制删除（运行中也删）
```

### 网络（Network）

Docker 为容器提供隔离的网络，默认几种驱动：

- **bridge**：默认，每个容器接到 `docker0` 网桥，通过 NAT 出外网，容器间可互通
- **host**：容器直接用宿主网络栈，无隔离但性能最好
- **none**：无网络，完全隔离
- **overlay**：跨多台宿主机组网（Swarm/K8s）
- **macvlan**：容器直接拿物理网段的 IP，像一台真实主机

端口映射 `-p 宿主端口:容器端口` 把容器服务暴露到宿主，是对外访问的标准方式。

```shell
docker network ls                  # 列出网络
docker network create mynet         # 创建自定义 bridge 网络
docker run -d --network mynet --name app myapp   # 容器接入 mynet
docker run -d --network host nginx               # 用宿主网络栈
docker network inspect mynet        # 看网络详情（含接入容器与 IP）
docker network rm mynet             # 删除网络
```

### 存储（Volume）

容器可写层随容器删除而丢失，持久数据要用「挂载」落到容器外，三种方式：

- **volume**：Docker 管理的卷，存 `/var/lib/docker/volumes/`，最推荐（可命名、可共享、备份方便）
- **bind mount**：挂载宿主任意目录到容器，灵活但依赖宿主路径
- **tmpfs**：挂到内存，重启即失，用于临时/敏感数据

```shell
docker volume create mydata      # 创建命名卷
docker run -d -v mydata:/data --name db mysql:8    # 挂载命名卷到容器 /data
docker run -d -v /host/path:/data --name app myapp # bind mount 宿主机目录
docker run -d --tmpfs /tmp:rw,size=64m nginx       # tmpfs 挂内存
docker volume ls                 # 列出卷
docker volume inspect mydata     # 看卷的宿主实际路径
```

### Dockerfile

Dockerfile 是镜像的构建脚本，逐条指令定义镜像内容。常用指令：`FROM`（基础镜像）、`RUN`（构建时执行命令）、`COPY`/`ADD`（拷贝文件）、`ENV`（环境变量）、`WORKDIR`（工作目录）、`EXPOSE`（声明端口）、`CMD`/`ENTRYPOINT`（启动命令）。每条指令生成一层，层可缓存，所以「变更少的指令放前面」能加速构建。

```dockerfile
# Dockerfile：Python Web 应用（多阶段构建，最终镜像只带运行依赖）
# 阶段一：构建依赖（大，用完即弃）
FROM python:3.12-slim AS builder
WORKDIR /app
COPY requirements.txt .
RUN pip install --prefix=/install -r requirements.txt

# 阶段二：运行镜像（小）
FROM python:3.12-slim
WORKDIR /app
COPY --from=builder /install /usr/local
COPY app.py .
ENV PORT=8080
EXPOSE 8080
CMD ["python", "app.py"]
```

```shell
docker build -t myapp:v1 .     # 用当前目录 Dockerfile 构建，打 tag
docker build --no-cache -t myapp:v1 .   # 忽略缓存强制重建
```

### Compose

Docker Compose 用 YAML 文件定义并启动「一组」相互关联的容器（如 web + db + redis），一条命令拉起整个应用栈。它是单机多容器编排的标准工具，也是 K8s 之外最简单的多容器方案。

```yaml
# docker-compose.yml：一个 web + redis 的典型栈
services:
  web:
    image: myapp:v1
    build: .
    ports:
      - "8080:8080"
    environment:
      - REDIS_URL=redis://redis:6379
    depends_on:
      - redis
  redis:
    image: redis:7
    volumes:
      - redis-data:/data
volumes:
  redis-data:
```

```shell
docker compose up -d       # 后台启动整个栈
docker compose ps          # 看栈内容器状态
docker compose logs -f web # 看某个服务日志
docker compose down        # 停止并移除整个栈（加 -v 连卷一起删）
```

## 工作原理

Docker 是 C/S 架构，客户端命令发给守护进程执行：

1. **docker CLI**（客户端）→ 通过 Unix socket（`/var/run/docker.sock`）或 TCP 发给 **dockerd**（守护进程）。
2. **dockerd** 负责镜像管理、网络、存储卷、容器生命周期编排。
3. **dockerd** 调 **containerd**（高层运行时）管理容器生命周期和镜像。
4. **containerd** 调 **runc**（低层运行时）真正创建 namespace/cgroup、切根文件系统跑起进程。

镜像拉取流程：`docker pull` → dockerd 找本地镜像 → 没有则从 Registry 分层下载（每层一个 tar）→ 存到本地 `/var/lib/docker/` → 运行时用 OverlayFS 联合挂载成分层文件系统。

```text
Docker 架构调用链：
docker CLI → dockerd（守护进程）→ containerd（高层运行时）→ runc（低层运行时）→ namespace/cgroup
镜像：Registry 分层下载 → 本地存储 → OverlayFS 联合挂载 → 容器可写层（COW）
```

## 常用命令与配置

```shell
# 镜像
docker pull <image>              # 拉取
docker build -t name:tag .       # 构建
docker images / docker rmi       # 列出 / 删除
docker push <image>              # 推送
docker save -o img.tar <image>   # 导出为 tar（离线迁移）
docker load -i img.tar           # 从 tar 导入

# 容器
docker run -d --name c -p 8080:80 -v data:/data -e KEY=val --restart unless-stopped <image>
docker ps -a / stop / start / restart / rm / logs -f / exec -it / inspect

# 网络与存储
docker network ls / create / inspect / rm
docker volume ls / create / inspect / rm

# 系统与资源
docker system df                 # 看镜像/容器/卷占用空间
docker system prune -a           # 清理未使用的镜像/容器/网络（慎用）
docker stats                     # 看运行中容器的实时资源占用
docker top <container>           # 看容器内进程
```

```text
docker run 关键参数：
-d 后台  -p 端口映射  -v 挂载  -e 环境变量  --name 命名
--restart unless-stopped 开机自启（异常退出自动拉起）
--memory/--cpus 资源限额
```

## 配置文件解析

### Dockerfile 指令

```dockerfile
FROM ubuntu:24.04              # 基础镜像（每层起点）
RUN apt update && apt install -y curl   # 构建时执行（生成一层）
COPY ./app /app                # 拷贝本地文件进镜像
ADD ./app.tar.gz /app          # COPY + 自动解压 tar
WORKDIR /app                   # 设置工作目录（后续指令相对它）
ENV APP_ENV=production         # 环境变量（构建+运行都生效）
EXPOSE 8080                    # 声明端口（文档性，真正映射靠 -p）
CMD ["/app/start.sh"]          # 容器默认启动命令（可被 docker run 覆盖）
ENTRYPOINT ["/app/start.sh"]   # 固定入口命令（不易被覆盖）
```

```text
指令要点：
CMD vs ENTRYPOINT  CMD 是默认命令可被覆盖，ENTRYPOINT 是固定入口，常组合 ENTRYPOINT + CMD 传默认参数
COPY vs ADD        COPY 纯拷贝（推荐），ADD 多一个自动解压 tar/远程 URL（有坑，少用）
层缓存            每指令一层，前面层没变则复用缓存；COPY 的文件变了后面全重建
```

### docker-compose.yml

```yaml
version: "3.8"                  # Compose 文件版本（新版可省略）
services:
  web:
    build: ./web                # 从 ./web/Dockerfile 构建
    image: myapp:latest         # 构建产物打 tag
    ports: ["8080:80"]          # 端口映射
    environment:                # 环境变量（列表或 map）
      NODE_ENV: production
    volumes:                    # 挂载
      - ./web:/app
    depends_on:                 # 依赖（先启动 redis 再启动 web）
      - redis
    restart: unless-stopped
  redis:
    image: redis:7
volumes: {}                     # 顶层声明命名卷
networks: {}                    # 顶层声明自定义网络
```

```text
Compose 要点：
services   定义容器集合，每个服务 = 一个容器（可横向 scale）
depends_on 只控制启动顺序，不保证服务就绪（要就绪检查用 healthcheck）
docker compose up -d 自动创建默认网络，服务间用服务名互访（如 redis:6379）
```

### daemon.json（Docker 守护进程配置）

```json
{
  "registry-mirrors": ["https://mirror.example.com"],
  "data-root": "/var/lib/docker",
  "log-driver": "json-file",
  "log-opts": { "max-size": "10m", "max-file": "3" },
  "storage-driver": "overlay2"
}
```

```text
registry-mirrors 国内加速镜像源
data-root        数据存储路径（默认 /var/lib/docker）
log-opts         日志轮转（防容器日志撑爆磁盘）
storage-driver   存储驱动（默认 overlay2）
改完 systemctl restart docker 生效
```

## 应用场景实战

### 场景一：把一个 Python Web 应用容器化并跑起来

从代码到可访问的容器服务，完整走一遍：

```shell
# 1. 应用代码 app.py（最小 Flask 应用，监听 8080）
# 2. Dockerfile（见上文「核心概念 - Dockerfile」）

# 3. 构建镜像
docker build -t myapp:v1 .

# 4. 运行容器并映射端口
docker run -d --name myapp -p 8080:8080 myapp:v1

# 5. 验证
curl http://localhost:8080     # 返回应用响应
docker logs -f myapp           # 看运行日志
docker ps                      # 确认容器 running
```

```text
流程：写代码 → 写 Dockerfile → docker build 出镜像 → docker run 起容器 → curl 验证
docker build 的层缓存：代码没变时重建秒级完成，只改代码则只重跑 COPY 之后的层
```

### 场景二：用 Compose 一键起「Web + Redis」栈

单机多容器应用用 Compose 编排，一条命令拉起整套依赖：

```yaml
# docker-compose.yml
services:
  web:
    build: .
    ports: ["8080:8080"]
    environment:
      REDIS_URL: redis://redis:6379
    depends_on:
      - redis
  redis:
    image: redis:7-alpine
    volumes:
      - redis-data:/data
volumes:
  redis-data:
```

```shell
docker compose up -d            # 后台启动 web + redis
docker compose ps               # 看两个容器状态
curl http://localhost:8080      # web 可访问，且能连上 redis（服务名 redis 解析）
docker compose logs -f web      # 跟日志
docker compose down -v          # 停止并删除容器和卷
```

```text
Compose 的价值：把「多个容器 + 网络 + 卷」的启动关系写进一个 YAML，一条 up 拉起整栈
服务间用服务名互访（web 里连 redis:6379），Compose 自动建网络并做 DNS 解析
```

## 性能与调优

```text
1. 镜像瘦身 —— 多阶段构建 + alpine/slim 基础镜像，减层减体积，加速拉取与分发
2. 合理利用层缓存 —— 依赖安装（pip/npm）单独一层、代码拷贝放最后，重建只跑变更层
3. 日志轮转 —— 配 log-opts 的 max-size/max-file，防容器 stdout 撑爆磁盘
4. 资源限额 —— 生产容器必设 --memory/--cpus，避免争抢与 OOM
5. 存储用 overlay2 + 数据落 volume —— 避免写可写层（COW 慢）
6. 定期 docker system prune —— 清理悬空镜像/停止容器，回收 inode 和磁盘
```

## 安全与权限

```text
1. 非 root 运行 —— Dockerfile 里建普通用户 + USER 指令，别用 root 跑业务进程
2. 用官方/可信镜像 —— 拉镜像固定 tag（别用 latest 漂移），私有仓库用 HTTPS + 认证
3. 少用 --privileged 与 --cap-add —— 默认已裁剪能力，别把 SYS_ADMIN 等危险能力放出去
4. 镜像扫描 —— 用 trivy / docker scan 扫漏洞，基础镜像及时更新
5. 守护进程 socket 保护 —— /var/run/docker.sock 是 root 等价物，别挂进容器、别裸暴露 TCP
6. 密钥不进镜像 —— 用 secret（--secret / compose secrets）或运行时注入，别写进 Dockerfile 层
```

## 故障排查

### 容器启动后立刻退出

```shell
# 1. 看退出原因和日志
docker ps -a                # 看 STATUS 和退出码
docker logs <container>     # 看最后输出（启动失败最常见的排查入口）
# 2. 前台启动排查
docker run -it --rm <image> sh   # 覆盖 CMD 手动进 shell 看环境
# 3. 检查启动命令/路径
docker inspect <container> | grep -A5 Cmd   # 看实际执行的 Cmd/Entrypoint
```

### 端口访问不通

```shell
# 1. 确认端口映射是否正确
docker ps                   # 看 PORTS 列，如 0.0.0.0:8080->80/tcp
# 2. 确认容器内服务在监听
docker exec <container> ss -tlnp   # 看容器内监听端口
# 3. 确认宿主防火墙放行
sudo ss -tlnp | grep 8080         # 宿主侧是否有监听
# 4. 排查容器网络（bridge 模式 NAT 转发）
docker network inspect bridge     # 看容器 IP 与网关
```

### 磁盘空间爆掉

```shell
docker system df             # 看镜像/容器/卷各占多少
docker system prune -a       # 清理未使用的镜像和容器（先确认无在用）
docker images | grep '<none>'  # 找悬空镜像
# 日志文件过大的容器
docker inspect -f '{{.LogPath}}' <container>   # 定位日志文件，检查大小
```

## 常见问题

```text
Q1: docker run 和 docker create 区别？
A: create 只创建容器不启动，run = create + start 一步到位。需要「先建后配再启」用 create，日常直接 run。

Q2: CMD 和 ENTRYPOINT 区别？
A: CMD 是默认启动命令，docker run 后面跟命令可覆盖它；ENTRYPOINT 是固定入口，不易被覆盖。常见组合 ENTRYPOINT 定义入口 + CMD 传默认参数。

Q3: volume 和 bind mount 怎么选？
A: volume 由 Docker 管理（路径不依赖宿主、易备份共享、推荐）；bind mount 挂宿主任意目录（灵活但和宿主强耦合）。持久数据优先 volume。

Q4: 容器里进程退出容器为什么也停了？
A: 容器主进程（PID 1）退出，容器生命周期就结束（除非 --restart 拉起）。所以容器启动命令要前台运行，别 daemonize。

Q5: bridge 和 host 网络怎么选？
A: bridge 隔离好、可端口映射（默认，推荐）；host 性能最好但和宿主共享网络栈、易端口冲突，适合高性能网络场景或调试。
```

## 面试题

```text
1. Docker 镜像、容器、仓库关系？
   答：镜像（只读模板）→ run 出容器（可写实例），镜像从仓库拉取/推送。类比：镜像是类，容器是对象，仓库是制品库。

2. Docker 启动容器背后做了什么？
   答：docker CLI 发请求给 dockerd，dockerd 调 containerd，containerd 调 runc 创建 namespace/cgroup、切根文件系统跑起进程；镜像是 OverlayFS 分层挂载。

3. 怎么优化镜像体积和构建速度？
   答：多阶段构建 + 精简基础镜像（alpine/slim）、合并 RUN 指令减层、依赖安装单独一层利用缓存、COPY 放最后。

4. 数据为什么要挂卷，不写容器里？
   答：容器可写层随容器删除丢失，且写时复制有性能开销。volume 持久、独立于容器生命周期、可共享和备份。

5. Docker 网络有几种模式？各自用途？
   答：bridge（默认隔离 + NAT）、host（共享宿主网络栈、高性能）、none（无网络）、overlay（跨主机）、macvlan（容器拿物理网段 IP）。单机常用 bridge，跨主机用 overlay。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 一个容器一个进程，进程前台运行（PID 1 就是业务进程）
2. 镜像固定 tag（别用 latest），构建产物进私有仓库统一分发
3. 数据、日志、配置都走 volume，容器本身可随时删了重建（无状态）
4. Dockerfile 用多阶段构建 + 非 root 用户运行，镜像瘦身又降权
5. 生产容器必设 --memory/--cpus 限额和日志轮转
6. 多容器用 Compose 编排，别手写一长串 docker run 脚本

### 踩坑记录

```text
坑 1：latest 标签漂移，生产突然变了镜像
结论：重新 pull 后服务行为变化，难回滚。
原因：latest 是「最新」的浮动标签，同名镜像内容会变。
解法：构建/部署固定版本 tag（v1.2.3），回滚改 tag 即可。

坑 2：容器日志写爆磁盘
结论：宿主磁盘 100%，服务受影响。
原因：容器 stdout 写进 json 日志文件，默认无轮转，长时间运行无限增长。
解法：daemon.json 配 log-opts 的 max-size/max-file，或改用日志驱动。

坑 3：CMD 写错导致容器秒退
结论：docker run 后容器立即 Exited。
原因：启动命令 daemonize 或立即返回，PID 1 退出容器就停。
解法：启动命令前台运行；排查用 docker logs + docker run -it 手动进 shell 看。

坑 4：把 docker.sock 挂进容器，等于送 root
结论：容器内可操作宿主全部容器，逃逸风险极高。
原因：/var/run/docker.sock 是 Docker API 入口，有它就是宿主的 root 权限。
解法：别挂 socket 进容器；需要时用受限的远程 API + TLS 认证。

坑 5：--restart 和手动 stop 打架，容器删不掉
结论：docker stop 后容器又自动起来，rm 报错。
原因：配了 --restart always/unless-stopped，守护进程不停拉起。
解法：先 docker update --restart=no 再 stop/rm，或 rm -f 强删。

坑 6：Compose 里 depends_on 不管「服务就绪」
结论：web 先启动，连数据库时数据库还没就绪报错。
原因：depends_on 只保证启动顺序，不等待依赖服务真正 ready。
解法：加 healthcheck + depends_on 的 condition: service_healthy，或应用内重试。
```

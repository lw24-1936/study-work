## 概述

虚拟化（Virtualization）是把一台物理机的 CPU、内存、磁盘、网络等资源抽象成多个互相隔离的逻辑实例（虚拟机，VM），每个 VM 跑一个独立的 Guest OS。核心价值：提高硬件利用率（一台物理机跑几十个 VM）、强隔离（一个 VM 挂了不影响其它）、可迁移（VM 本质是磁盘文件，可整体搬走）。在 Linux 上，KVM（内核模块做 CPU/内存虚拟化）+ QEMU（用户态做设备模拟）+ libvirt（统一管理 API）是最主流的开源虚拟化栈。

```text
Linux 虚拟化栈三件套：
KVM     内核模块，把 Linux 内核变成 hypervisor（CPU/内存虚拟化，/dev/kvm）
QEMU    用户态程序，设备模拟（磁盘/网卡/显卡）+ 内存管理，配合 KVM 加速
libvirt 统一管理守护进程（libvirtd），virsh 命令行 + XML 配置，一套 API 管 KVM/Xen/LXC
```

## 核心概念

### 虚拟化类型（全虚拟化 / 半虚拟化 / 硬件辅助）

按「Guest OS 是否需要感知虚拟化环境」分三种：

- **全虚拟化（Full Virtualization）**：Guest OS 完全不知道自己在虚拟化环境里，hypervisor 用二进制翻译（Binary Translation，BT）动态拦截并翻译 Guest 的特权指令。代表是早期的 VMware Workstation、VirtualBox（纯软件模拟模式）。优点：Guest 内核零修改；缺点：每条特权指令都要翻译，性能损失明显。
- **半虚拟化（Paravirtualization，PV）**：Guest OS 被修改过，知道自己跑在 hypervisor 上，通过 hypercall（类似系统调用的超调用）直接请求 hypervisor 服务，不再走特权指令翻译。代表是 Xen PV。优点：性能接近裸机；缺点：要改 Guest 内核，Windows 等闭源系统用不了。
- **硬件辅助虚拟化（Hardware-assisted）**：Intel VT-x / AMD-V 在 CPU 里加了新的执行模式（root / non-root），Guest 直接在硬件上跑，特权指令触发 VM Exit 切回 hypervisor 处理。既不用改 Guest 内核、又没有二进制翻译的开销，是现代默认方案，KVM 就是基于它。

```shell
# 检查 CPU 是否支持硬件辅助虚拟化（vmx=Intel VT-x，svm=AMD-V）
grep -cE 'vmx|svm' /proc/cpuinfo
# 输出 > 0 表示支持；为 0 则无法使用 KVM 加速，只能纯软件模拟（极慢）
```

```text
三种虚拟化对比：
全虚拟化   Guest 无感知，二进制翻译特权指令，性能差，无需改内核
半虚拟化   Guest 有感知，hypercall 直调，性能好，需改 Guest 内核
硬件辅助   VT-x/AMD-V 新增 CPU 模式，性能好且不改内核，现代默认
```

### Hypervisor 类型（Type 1 / Type 2）

- **Type 1（裸机型 / Bare-metal）**：hypervisor 直接跑在硬件上，不依赖宿主 OS。代表：Xen、VMware ESXi、微软 Hyper-V。KVM 也通常归为 Type 1——它以内核模块形式让 Linux 内核直接充当 hypervisor。
- **Type 2（宿主型 / Hosted）**：hypervisor 是宿主 OS 上的一个程序。代表：VirtualBox、VMware Workstation。性能比 Type 1 差（多一层宿主 OS 调度）。

```text
Type 1（裸机）：hypervisor 直接管硬件，Xen / ESXi / KVM
Type 2（宿主）：hypervisor 是宿主 OS 里的程序，VirtualBox / VMware Workstation
```

### KVM

KVM（Kernel-based Virtual Machine）是 Linux 内核的虚拟化模块（`kvm.ko` + 平台模块 `kvm-intel.ko` / `kvm-amd.ko`）。加载后 Linux 内核变成一个 hypervisor，向用户态暴露 `/dev/kvm` 设备。KVM 只负责两件事：CPU 虚拟化（VT-x/AMD-V）和内存虚拟化（EPT/NPT 二级页表），不包含任何设备模拟——设备模拟交给 QEMU。

```shell
# 加载 KVM 模块并确认
sudo modprobe kvm_intel   # Intel；AMD 用 kvm_amd
lsmod | grep kvm
# 示例输出：
# kvm_intel             311296  0
# kvm                  1081344  1 kvm_intel
ls -l /dev/kvm
# crw-rw---- 1 root kvm 10, 232 ... /dev/kvm
```

### QEMU

QEMU（Quick EMUlator）是用户态虚拟化程序，负责 VM 的「外围设备」：虚拟磁盘、网卡、显卡、USB、声卡，以及内存布局、启动引导。QEMU 单独使用是纯软件模拟（TCG 二进制翻译，慢）；配合 KVM 时，CPU 指令直接交给硬件执行，QEMU 只管设备 IO，这就是 `qemu-kvm` 的模式。KVM + QEMU = 一个完整可用的虚拟机。

```shell
# 用 QEMU 直接启动一个虚拟机（KVM 加速）
qemu-system-x86_64 \
  -enable-kvm \
  -m 2048 \
  -smp 2 \
  -drive file=/var/lib/libvirt/images/test.qcow2,format=qcow2 \
  -netdev user,id=n0 -device virtio-net-pci,netdev=n0 \
  -vnc :1
# -enable-kvm 走硬件加速；去掉它则纯软件模拟（慢一个数量级）
```

### libvirt

libvirt 是一套「虚拟化统一管理」API 和守护进程（`libvirtd`），屏蔽 KVM/Xen/LXC/QEMU 的差异，用同一套 XML 描述虚拟机、同一个 `virsh` 命令管理。它是 OpenStack、oVirt 等云平台的底层管理组件。

```shell
# virsh 是 libvirt 的命令行客户端
virsh list --all        # 列出所有虚拟机（含关机状态）
virsh list              # 只看运行中的
# Id   Name      State
# --------------------------
# 1    test      running
```

### virt-manager

virt-manager 是 libvirt 的图形化前端（GUI），在桌面环境里点鼠标就能创建/启动/连接虚拟机，底层仍然调 libvirt API。生产环境用 `virsh` + `virt-install` 脚本化，桌面环境用 virt-manager 直观操作。

```shell
# 安装桌面管理工具
sudo apt install -y virt-manager
# 启动 GUI（需要桌面环境 / X11 转发）
virt-manager
# 命令行等价物（脚本化创建虚拟机）
sudo virt-install --name test --memory 2048 --vcpus 2 \
  --disk size=20 --cdrom /path/to/ubuntu.iso --os-variant ubuntu24.04
```

## 工作原理

KVM 虚拟化的核心是「CPU 模式切换 + 内存二级映射 + virtio 设备 IO」三段：

1. **CPU 虚拟化**：VT-x 引入 VMX root / non-root 两种模式。Guest OS 的代码在 non-root 模式直接跑在物理 CPU 上（接近裸机速度），一旦执行特权指令（如改页表、读时钟、IO 指令），CPU 触发 **VM Exit**，把控制权交回 hypervisor（KVM）处理，处理完再 VM Entry 回到 Guest。QEMU 通过 `/dev/kvm` 的 ioctl（`KVM_RUN`、`KVM_CREATE_VCPU` 等）驱动这套流程。

2. **内存虚拟化**：Guest 看到的是「Guest 物理地址」，还要再映射到「宿主物理地址」。EPT（Intel）/ NPT（AMD）二级页表由 CPU 硬件完成这层转换，避免纯软件影子页表的开销，这是 KVM 内存性能好的关键。

3. **设备 IO**：分两种——全模拟（QEMU 用软件模拟真实网卡 e1000 / IDE 磁盘，慢但兼容性最好）和 virtio 半虚拟化（Guest 里装 virtio 驱动，直接和 QEMU 的后端共享内存队列，性能接近直通）。

```text
KVM 执行流程：
Guest 跑特权指令 → VM Exit → KVM 内核处理 → 需要设备 IO 则交给 QEMU → VM Entry 回 Guest
内存：Guest 物理地址 --EPT/NPT 硬件二级映射--> 宿主物理地址
设备：全模拟（e1000/IDE，慢） vs virtio 半虚拟化（virtio-net/virtio-blk，快）
```

## 常用命令与配置

```shell
# 查看虚拟化环境
virsh list --all              # 所有虚拟机
virsh nodeinfo                # 宿主 CPU/内存信息
virsh capabilities            # 宿主支持能力（含 CPU 型号、虚拟化特性）

# 虚拟机生命周期
virsh start test              # 启动（开机）
virsh shutdown test           # 正常关机（发 ACPI 信号）
virsh destroy test            # 强制断电
virsh reboot test             # 重启
virsh autostart test          # 设置开机自启（随 libvirtd）
virsh autostart --disable test

# 连接控制台
virsh console test            # 文本控制台（需 Guest 配好串口）
virt-viewer test              # 图形控制台

# 快照与克隆
virsh snapshot-create-as test snap1 "首次快照"    # 建快照
virsh snapshot-list test                          # 列快照
virsh snapshot-revert test snap1                  # 回滚快照
virt-clone --original test --name test2 --auto-clone  # 克隆

# 网络与存储
virsh net-list --all          # 虚拟网络
virsh pool-list --all         # 存储池
virsh vol-list default        # 默认池里的卷（磁盘镜像）
```

```text
常用组合：
virsh list --all   查看状态 → virsh start/shutdown 开关机 → virsh console 进控制台
virt-install       命令行创建 VM（脚本化）  virt-clone 克隆
```

## 配置文件解析

libvirt 的虚拟机定义是 XML，默认放 `/etc/libvirt/qemu/*.xml`，网络定义在 `/etc/libvirt/qemu/networks/`。改完 XML 要 `virsh define` 重新加载。

```xml
<!-- /etc/libvirt/qemu/test.xml 关键字段 -->
<domain type='kvm'>                    <!-- 虚拟化类型：kvm 硬件加速 / qemu 纯软件 -->
  <name>test</name>
  <memory unit='KiB'>2097152</memory>  <!-- 内存 2G -->
  <vcpu placement='static'>2</vcpu>    <!-- 2 个 vCPU -->
  <os>
    <type arch='x86_64' machine='q35'>hvm</type>
    <boot dev='hd'/>                   <!-- 从磁盘启动 -->
  </os>
  <devices>
    <disk type='file' device='disk'>
      <driver name='qemu' type='qcow2'/>
      <source file='/var/lib/libvirt/images/test.qcow2'/>
      <target dev='vda' bus='virtio'/> <!-- virtio 磁盘 -->
    </disk>
    <interface type='network'>
      <source network='default'/>      <!-- 接 default 网络（NAT） -->
      <model type='virtio'/>           <!-- virtio 网卡 -->
    </interface>
    <graphics type='vnc' port='5901'/> <!-- VNC 图形控制台 -->
  </devices>
</domain>
```

```text
字段含义：
type='kvm'         硬件加速；改成 'qemu' 退化为纯软件模拟（慢）
memory/vcpu        内存与 CPU 配额，可热调整
disk  bus='virtio' 半虚拟化磁盘（快）；bus='ide' 全模拟（慢但兼容）
interface model    virtio 网卡（快） vs e1000 全模拟
graphics           VNC/SPICE 图形控制台端口
```

## 应用场景实战

### 场景一：命令行创建一台可用的 Ubuntu 虚拟机

从零用 virt-install 创建一台虚拟机（脚本化，适合批量交付测试环境）：

```shell
# 1. 下载 ISO（以 Ubuntu Server 为例）
wget -O /tmp/ubuntu.iso https://releases.ubuntu.com/24.04/ubuntu-24.04-live-server-amd64.iso

# 2. 创建 20G 磁盘镜像 + 安装虚拟机
qemu-img create -f qcow2 /var/lib/libvirt/images/test.qcow2 20G
sudo virt-install \
  --name test \
  --memory 4096 \
  --vcpus 4 \
  --disk /var/lib/libvirt/images/test.qcow2,format=qcow2,bus=virtio \
  --network network=default,model=virtio \
  --cdrom /tmp/ubuntu.iso \
  --os-variant ubuntu24.04 \
  --graphics vnc \
  --noautoconsole

# 3. 安装过程中用图形控制台连上去操作
virt-viewer test

# 4. 装完开机、进控制台、关机
virsh start test
virsh console test
virsh shutdown test
```

```text
流程：下载 ISO → qemu-img 建磁盘 → virt-install 装系统 → virt-viewer 完成安装 → virsh 管理生命周期
qcow2 是 QEMU 的写时复制磁盘格式（稀疏分配 + 快照支持），比 raw 省空间
```

### 场景二：用 libvirt 默认 NAT 网络给多台 VM 组内网

libvirt 自带一个 `default` NAT 网络，VM 接上去自动拿到 192.168.122.0/24 的地址、经宿主 NAT 出外网，多台 VM 之间可互通——适合搭一个互相通信的测试集群。

```shell
# 1. 确认默认网络存在并启用
virsh net-list --all
# Name      State    Autostart
# default   active   yes
virsh net-dumpxml default | grep -E 'ip address'
# <ip address='192.168.122.1' netmask='255.255.255.0'>

# 2. 两台 VM 都接 default 网络（virt-install 里 --network network=default）
# 3. 各自进控制台查 IP，验证互通
virsh console test
ip addr show    # 拿到 192.168.122.x
ping 192.168.122.1   # ping 通宿主的虚拟网桥（virbr0），即证明网络通
```

```text
default 网络 = virbr0 网桥 + dnsmasq（DHCP 分配 192.168.122.0/24）+ iptables NAT 出外网
多 VM 接同一 network，即可在 NAT 网段内互通，模拟一个局域网
```

## 性能与调优

```text
1. 磁盘用 virtio —— Guest 装 virtio 驱动，virtio-blk 比 IDE 全模拟快数倍
2. 磁盘镜像用 qcow2 的 cache=none 或 cache=writeback，配 iodepth 提升 IO
3. CPU 绑定 —— 用 cpuset/vcpu pinning 把 vCPU 绑到物理核，减少调度抖动（延迟敏感型）
4. 大页内存 —— 配 hugepages，减少 TLB miss，数据库类负载提升明显
5. 网络用 virtio + vhost-net —— 数据面绕过 QEMU 直接在宿主机内核处理，吞吐翻倍
6. 半虚拟化时钟 kvm-clock，避免 Guest 时钟漂移（否则 NTP 频繁修正）
```

## 安全与权限

```text
1. libvirt 访问控制 —— 默认 polkit 认证，非 root 用户要加入 libvirt/libvirt-qemu 组
2. 资源配额 —— 内存/CPU 设上限，防止单个 VM 抢占宿主全部资源
3. 网络隔离 —— 敏感 VM 用隔离网络（isolated），不接 NAT/桥接出外网
4. 磁盘镜像权限 —— qcow2 文件属主 qemu 用户，防普通用户篡改 VM 磁盘
5. 虚拟化逃逸 —— 及时更新 QEMU/KVM 补丁（历史上有 VM 逃逸漏洞），生产 VM 不跑不可信代码
```

## 故障排查

### KVM 加速不可用（VM 起不来 / 极慢）

```shell
# 1. 确认 CPU 支持硬件虚拟化
grep -cE 'vmx|svm' /proc/cpuinfo        # 为 0 则不支持
# 2. 确认 KVM 模块已加载
lsmod | grep kvm                         # 没有则 modprobe kvm_intel
# 3. 确认 /dev/kvm 权限
ls -l /dev/kvm
# 4. 确认 BIOS 没关虚拟化（云主机常见：要在控制台开 VT-x）
# 5. 如果只能纯软件跑，说明 qemu 没接上 KVM，检查 XML 里 type='kvm'
```

### 虚拟机无法启动 / 卡在启动

```shell
# 查看 libvirt 日志
sudo tail -f /var/log/libvirt/qemu/test.log
# 查看守护进程日志
journalctl -u libvirtd -n 50
# 磁盘镜像损坏检查
qemu-img check /var/lib/libvirt/images/test.qcow2
# 存储池/磁盘空间不足
df -h /var/lib/libvirt/images
```

## 常见问题

```text
Q1: KVM 和 QEMU 到底什么关系？
A: KVM 只做 CPU/内存虚拟化（内核模块，/dev/kvm），QEMU 做设备模拟（磁盘/网卡/显卡）。两者配合才是完整虚拟机；QEMU 单用是纯软件模拟。

Q2: 为什么我的虚拟机很慢？
A: 先查有没有 -enable-kvm / XML type='kvm'——没走硬件加速就是纯软件模拟。其次磁盘/网卡是否用了 virtio，全模拟的 e1000/IDE 是性能瓶颈。

Q3: 全虚拟化和硬件辅助虚拟化区别？
A: 全虚拟化靠 hypervisor 二进制翻译特权指令（软件层），硬件辅助靠 CPU 的 VT-x/AMD-V 直接执行（硬件层）。后者快得多，是 KVM 的基础。

Q4: virt-manager 和 virsh 用哪个？
A: 桌面环境/偶尔管理用 virt-manager（图形直观），批量/脚本/无桌面服务器用 virsh + virt-install（可脚本化）。两者都调 libvirt，管理的是同一批 VM。

Q5: 容器和虚拟机怎么选？
A: 需要跑完整独立内核、强隔离、不同 OS 用虚拟机；只隔离应用进程、要启动快密度高用容器。详见 [[21.2-容器原理]]。
```

## 面试题

```text
1. 简述 KVM 虚拟化的原理？
   答：KVM 是内核模块，用 CPU 的 VT-x/AMD-V 让 Guest 在 non-root 模式直接跑，特权指令触发 VM Exit 交回内核处理；内存用 EPT/NPT 二级页表；设备 IO 由 QEMU 模拟（或 virtio 半虚拟化）。

2. 全虚拟化、半虚拟化、硬件辅助虚拟化区别？
   答：全虚拟化二进制翻译特权指令、无需改 Guest 但慢；半虚拟化改 Guest 内核用 hypercall 直调、快但只适用开源 OS；硬件辅助靠 CPU 扩展（VT-x/AMD-V）直接执行，又快又不用改内核。

3. 为什么 KVM 需要 QEMU？
   答：KVM 只虚拟化 CPU 和内存，不含任何设备。QEMU 负责磁盘/网卡/显卡等设备模拟和内存布局，两者协作（QEMU 调 /dev/kvm 加速 CPU，自己模拟 IO）才构成完整虚拟机。

4. 什么是 virtio？有什么好处？
   答：virtio 是半虚拟化 IO 框架，Guest 装 virtio 驱动后通过共享内存队列和 QEMU 后端通信，绕过全模拟设备的逐指令翻译，磁盘/网络性能接近原生。

5. libvirt 的作用？
   答：统一的虚拟化管理 API + 守护进程，屏蔽 KVM/Xen/LXC 差异，用 XML 描述 VM、virsh 统一管理，是 OpenStack 等云平台的底层。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 磁盘用 qcow2 格式 + virtio 总线，支持稀疏分配和快照
2. 网络默认用 virtio + default NAT 网络，隔离且省事
3. 虚拟机定义用 XML 版本管理（virsh dumpxml > 备份），改前先备份
4. 内存/CPU 设合理上限，避免单 VM 拖垮宿主
5. 定期 qemu-img check 检查磁盘镜像，重要 VM 做快照
6. 用 virt-install + shell 脚本批量建 VM，而不是逐台点 GUI

### 踩坑记录

```text
坑 1：VM 慢得离谱，发现是纯软件模拟
结论：虚拟机能跑但 CPU 性能极差。
原因：XML 里 type='qemu' 或启动没加 -enable-kvm，QEMU 走了 TCG 二进制翻译。
解法：确认 CPU 支持 vmx/svm + kvm 模块加载，XML 改 type='kvm'。

坑 2：BIOS 关了虚拟化，KVM 起不来
结论：/dev/kvm 不存在，virsh start 报错。
原因：物理机 BIOS 里 Intel VT-x/AMD-V 被禁用，CPU 不支持硬件虚拟化。
解法：进 BIOS 开 VT-x；云主机在控制台开（部分云厂商默认关闭需手动开）。

坑 3：磁盘用了 raw 格式又频繁快照，空间爆掉
结论：磁盘镜像占满宿主存储。
原因：raw 是满额预分配，qcow2 才是稀疏 + 写时复制，适合快照和瘦分配。
解法：建盘用 qcow2；已用 raw 的可 qemu-img convert 转换。

坑 4：virtio 驱动没装，Guest 认不出磁盘/网卡
结论：安装阶段 Guest 找不到磁盘。
原因：XML 里用了 virtio 总线，但 Guest 没装 virtio 驱动（老系统/精简镜像）。
解法：装系统时先加载 virtio 驱动，或用 IDE/e1000 装完再换 virtio。

坑 5：改完 XML 直接 virsh start 不生效
结论：改了 XML 但虚拟机还是旧配置。
原因：直接改 /etc/libvirt/qemu/*.xml 文件后没重新 define，libvirt 没加载新定义。
解法：改完执行 virsh define /etc/libvirt/qemu/test.xml 再启动。
```

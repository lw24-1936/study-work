## 概述

Linux 开机是五个阶段的接力：BIOS/UEFI（硬件自检、找到引导）→ GRUB2（引导加载器、选内核）→ 内核加载（解压、初始化硬件）→ initramfs（临时根文件系统、加载磁盘驱动）→ systemd（PID 1，拉起所有服务）。理解这个流程，才能定位「启动卡在哪一步」——是引导问题、内核问题还是服务启动慢。`systemd-analyze` 能看各阶段耗时。

```text
开机五阶段接力：
BIOS/UEFI → GRUB2 → 内核加载 → initramfs → systemd
1. BIOS/UEFI —— 硬件自检，找到并执行引导加载器
2. GRUB2 —— 引导菜单，加载内核和 initramfs 到内存
3. 内核加载 —— 解压内核、初始化硬件、挂载根文件系统
4. initramfs —— 临时内存根文件系统，提供磁盘驱动让根分区可挂载
5. systemd —— PID 1 进程，按 target 顺序拉起所有服务
```

整个流程可以按「谁在控制」分成两段：前两阶段（BIOS/UEFI + GRUB2）运行在「裸机 + 引导环境」里，代码是固件和引导加载器；后三阶段（内核 + initramfs + systemd）控制权已经交到 Linux 内核手里。排查启动问题时先分清卡在哪一段，手段完全不同：引导段靠 BIOS/UEFI 设置和 GRUB 救援模式，内核段靠 `dmesg` 和 initramfs 急救 shell，服务段靠 `journalctl`。

## 核心概念

1. **固件（firmware）**：BIOS（老式，从 MBR 读引导代码）或 UEFI（新式，从 EFI 系统分区 ESP 读 .efi 文件）。UEFI 支持 GPT、Secure Boot、更快启动。
2. **引导加载器（boot loader）**：GRUB2，显示引导菜单、加载内核和 initramfs 到内存。
3. **内核镜像（vmlinuz）**：压缩的内核，`/boot/vmlinuz-*`，GRUB 加载它。
4. **initramfs（initrd.img）**：临时根文件系统镜像，提供磁盘驱动，解决「鸡生蛋」问题。
5. **PID 1（systemd）**：内核启动的第一个进程，负责拉起整个用户空间。

```text
核心概念速查：
固件       BIOS（MBR）/ UEFI（ESP + GPT + Secure Boot）
引导加载器  GRUB2，选内核、加载 vmlinuz + initrd
内核镜像   vmlinuz-*，/boot 下，压缩内核
initramfs  initrd.img-*，临时根，带磁盘驱动
PID 1      systemd，拉起所有服务
```

下面按「是什么 → 为什么 → 怎么用 → 边界/易错点」把每个核心概念展开。

### BIOS 与 UEFI（固件）

- **是什么**：主板上的固件程序，开机第一个执行的代码。BIOS 是 1980 年代遗留的 16 位实模式固件，从磁盘开头 512 字节的 MBR 读引导代码；UEFI 是现代统一可扩展固件接口，从 FAT 格式的 EFI 系统分区（ESP）里读 `.efi` 引导程序。
- **为什么**：固件负责把硬件初始化到「足够引导」的程度，并找到下一阶段的引导代码。BIOS 受限于 16 位实模式和 MBR 的 2TB 磁盘上限；UEFI 用 64 位、支持 GPT 分区表（超大磁盘）、Secure Boot 和更快的启动。
- **怎么用**：开机按 F2/Del 进固件设置，设启动顺序、开关 Secure Boot。`efibootmgr` 管理 UEFI 启动项。

```shell
# 判断机器是 UEFI 还是 BIOS 启动
ls /sys/firmware/efi        # 有输出 = UEFI，无该目录 = 传统 BIOS/Legacy
# 查看 UEFI 启动项列表
efibootmgr -v
# 查看固件信息（BIOS 版本/厂商）
dmidecode -t bios | head -20
# 查看系统固件类型（bootctl 是 systemd 自带）
bootctl status | head -5
```

- **边界/易错点**：BIOS 只能从 MBR 引导，MBR 分区表最多 4 个主分区、单盘最大 2TB；UEFI 必须配合 GPT + ESP 分区，如果 ESP 分区被删/损坏，系统直接起不来。改启动模式（Legacy ↔ UEFI）后要重装 GRUB（`grub-install`），否则引导不匹配。

### GRUB2（引导加载器）

- **是什么**：GNU GRUB 第二代，Linux 最常用的引导加载器，分两个阶段：`boot.img`（MBR/ESP 里的一小段，负责找 `core.img`）和 `core.img`（加载 `/boot/grub/` 下的模块，读 `grub.cfg` 显示菜单）。
- **为什么**：固件只知道「执行某段引导代码」，GRUB2 负责读文件系统、找到内核文件（vmlinuz）和 initramfs、给内核传启动参数，把两者加载进内存后跳转。
- **怎么用**：改配置改 `/etc/default/grub`，然后 `update-grub` 重新生成 `grub.cfg`。开机时按 Shift/Esc 进菜单，`e` 编辑本次启动参数，`c` 进 GRUB 命令行。

```shell
update-grub                              # 重新生成 /boot/grub/grub.cfg
grub-install /dev/sda                    # 把 GRUB 装到磁盘（UEFI 会自动装到 ESP）
grub-mkconfig -o /boot/grub/grub.cfg     # 手动生成（update-grub 的底层）
# 进 GRUB 命令行（开机菜单按 c）后的常用命令
#   set root=(hd0,msdos1)   # 指定内核所在分区
#   linux /vmlinuz-xxx root=/dev/sda1   # 指定内核 + 根分区
#   initrd /initrd.img-xxx   # 指定 initramfs
#   boot                     # 启动
```

- **边界/易错点**：`grub.cfg` 是自动生成的，手改会被下次 `update-grub` 覆盖（要改就改 `/etc/default/grub`）。内核参数（`root=`、`quiet`、`splash`）是通过 `GRUB_CMDLINE_LINUX_DEFAULT` 传给内核的，改完必须 `update-grub` 才生效。

### 内核加载（vmlinuz）

- **是什么**：`vmlinuz` 是压缩后的内核镜像（`vmlinux` 用 gzip/xz 等压缩得到）。GRUB 把它和 initramfs 一起加载进内存，跳转到内核入口。
- **为什么**：内核镜像要先解压再执行，解压到内存里运行；内核一旦接管，就初始化 CPU/内存/中断、探测硬件、挂载根文件系统，最后 exec PID 1。
- **怎么用**：`uname -r` 看当前内核版本，`ls /boot/vmlinuz-*` 看已装内核。内核启动参数用 `cat /proc/cmdline` 查看。

```shell
uname -r                    # 当前运行的内核版本
uname -a                    # 完整内核信息
ls /boot/vmlinuz-*          # 所有已安装的内核镜像
cat /proc/cmdline           # 本次启动内核参数（GRUB 传入）
dmesg | head -30            # 内核启动日志开头（硬件初始化）
```

- **边界/易错点**：`vmlinuz` 必须和对应的 `initrd.img`、`/lib/modules/<版本>/` 模块目录配套，删内核时要连模块一起删，否则残留。内核 panic 通常表现为黑屏或大写锁定键闪烁，说明内核段挂了，跟 systemd 服务无关。

### initramfs（initrd.img）

- **是什么**：一个压缩的 cpio 归档（`initrd.img-*`），里面是临时根文件系统 + init 脚本 + 必要的内核模块（磁盘/RAID/LVM/加密驱动）。内核启动时先把它解压到内存当临时根。
- **为什么**：解决「鸡生蛋」——根文件系统在磁盘上，读磁盘需要驱动，驱动又在根文件系统里。initramfs 自带驱动，内核先用它把根分区挂起来，再 `switch_root` 切到真实根。
- **怎么用**：`lsinitramfs` 看里面有什么，`update-initramfs -u` 重建（改磁盘/LVM/加密/驱动配置后必须做）。

```shell
lsinitramfs /boot/initrd.img-$(uname -r) | head -30   # 看 initramfs 内容
update-initramfs -u                                    # 更新当前内核的 initramfs
update-initramfs -u -k all                             # 更新所有内核的 initramfs
dracut -f                                              # RHEL 系重建 initramfs（Debian 用 update-initramfs）
```

- **边界/易错点**：改完 `/etc/fstab`、LVM 卷、LUKS 加密盘、或把根分区驱动从内核内置改成模块后，如果不重建 initramfs，重启可能挂不上根分区、掉进 initramfs 急救 shell（`(initramfs)` 提示符）。initramfs 里的 `/etc/fstab` 是打包时快照，跟真实根分区的 `fstab` 是两回事。

### systemd（PID 1）

- **是什么**：内核挂好根文件系统后 exec 的第一个用户态进程（PID 1），现代 Linux 的初始化系统 + 服务管理器。
- **为什么**：PID 1 特殊——内核把「孤儿进程托管」「信号转发」「系统关闭」都交给它。systemd 读所有 unit 文件构建依赖图，并行拉起服务到默认 target，比老的 SysV init 串行快。
- **怎么用**：`systemctl get-default` 看默认 target，`systemctl set-default` 改，`systemd-analyze` 看启动耗时。详细管理见 [[10.2-systemd]]。

```shell
systemctl get-default           # 看默认 target（如 graphical.target / multi-user.target）
systemctl set-default multi-user.target   # 改成无桌面的多用户模式
systemd-analyze                 # 分阶段启动耗时
ps -p 1 -o comm=                # 确认 PID 1 是 systemd
```

- **边界/易错点**：PID 1 只能有一个，容器里（如 Docker）常用 `/sbin/init` 或直接跑业务进程当 PID 1，systemd 不是必需的。systemd 是「服务层」问题，如果机器根本进不了用户态（内核都没起来），systemd 无从谈起——别把内核 panic 误判成服务问题。

## 工作原理

五阶段的接力细节：

1. **BIOS/UEFI**：通电 → 固件自检（POST）→ 按启动顺序找引导设备 → 执行引导代码（MBR 或 ESP 里的 .efi）。
2. **GRUB2**：读 `/boot/grub/grub.cfg` → 显示菜单 → 把内核（vmlinuz）和 initramfs（initrd.img）加载进内存 → 跳转到内核入口。
3. **内核加载**：内核自解压 → 初始化 CPU/内存/中断 → 挂载 initramfs 为临时根 → 加载磁盘驱动。
4. **initramfs**：内核执行 initramfs 里的 init → 加载 LVM/RAID/加密模块 → 挂载真正的根分区 → switch_root 切换到真实根。
5. **systemd**：内核 exec 第一个进程 systemd（PID 1）→ 按 /etc/fstab 挂载文件系统 → 到达默认 target，系统就绪。

```text
关键点：initramfs 解决「鸡生蛋」
根文件系统在磁盘上 → 读磁盘要驱动 → 驱动在根文件系统里
initramfs 自带驱动，内核先用它读根分区，再切到真实根
```

```text
# 实测（本机 /boot 下的内核和引导文件）
$ ls /boot/vmlinuz-* /boot/initrd.img-*
/boot/vmlinuz-6.17.0-40-generic
/boot/vmlinuz-7.0.0-28-generic      # 当前内核
/boot/initrd.img-6.17.0-40-generic
/boot/initrd.img-7.0.0-28-generic
# vmlinuz 是内核、initrd.img 是 initramfs，多内核并存，GRUB 菜单选择
```

每一阶段的「控制权交接」和「可观测点」如下：

```text
阶段        谁在跑          卡住时的现象          排查手段
BIOS/UEFI  固件            黑屏/停在厂商 LOGO    固件设置、启动顺序、Secure Boot
GRUB2       引导加载器      grub> 或 grub rescue>  GRUB 命令行、重装 GRUB
内核加载    内核(早期)      panic/大写键闪烁       dmesg、启动参数、去掉 quiet
initramfs   init 脚本       (initramfs) 急救 shell 重建 initramfs、检查 fstab/驱动
systemd     PID 1           停在某个服务           journalctl -b、systemctl status
```

## 常用命令与配置

```shell
update-grub                 # 重新生成 grub.cfg（装新内核后自动调）
grub-install /dev/sda       # 重装 GRUB 到磁盘
cat /proc/cmdline           # 内核启动参数（GRUB 传的）
uname -r                    # 当前内核版本
dmesg | head -30            # 看内核启动日志
lsinitramfs /boot/initrd.img-$(uname -r) | head   # 看 initramfs 里有什么
update-initramfs -u         # 更新 initramfs（改磁盘/驱动配置后）
systemctl get-default       # 看默认 target
```

按阶段分组的命令：

```shell
# 固件/引导类型相关
ls /sys/firmware/efi          # 判断 UEFI
efibootmgr -v                 # UEFI 启动项
dmidecode -t bios             # BIOS 信息
bootctl status                # systemd-boot 引导状态（也显示固件类型）

# 引导加载器相关
grub-mkconfig -o /boot/grub/grub.cfg    # 生成 grub.cfg
grub-install --target=x86_64-efi --efi-directory=/boot/efi   # 显式装 UEFI 版 GRUB
grep '^menuentry' /boot/grub/grub.cfg   # 列出引导菜单项

# 内核/initramfs 相关
uname -r                      # 当前内核
ls /boot/                     # 看内核 + initramfs + grub
update-initramfs -u           # 重建 initramfs
lsmod | head                  # 已加载的内核模块
dmesg | grep -iE 'error|panic|fail' | head   # 内核启动错误

# systemd/服务相关
systemd-analyze               # 启动耗时
systemd-analyze blame         # 服务耗时排行
systemctl list-units --type=target   # 列出所有 target
```

## 配置文件解析

```text
引导相关文件：
/boot/vmlinuz-*          内核镜像（压缩内核）
/boot/initrd.img-*       initramfs 镜像
/boot/grub/grub.cfg      引导配置（update-grub 生成，别手改）
/etc/default/grub        GRUB 配置源（改这里再 update-grub）
/boot/efi/               EFI 系统分区挂载点（UEFI 引导文件）
/etc/fstab               开机挂载的文件系统表
```

```text
# /etc/default/grub 关键项（改完要 update-grub）
GRUB_DEFAULT=0               # 默认启动第几个内核/菜单项
GRUB_TIMEOUT=5               # 菜单等待秒数
GRUB_CMDLINE_LINUX_DEFAULT="quiet splash"   # 内核启动参数
```

`/etc/default/grub` 完整的关键项解释：

```ini
# GRUB_DEFAULT 可写 0（第一个菜单项）、菜单标题、或 saved（记住上次选择）
GRUB_DEFAULT=0
# GRUB_TIMEOUT=0 跳过菜单，=-1 无限等待用户选择
GRUB_TIMEOUT=5
# 传给内核的默认启动参数（正常启动都带）
GRUB_CMDLINE_LINUX_DEFAULT="quiet splash"
# 传给内核的额外参数（救援模式也带，常放 console=/root 相关）
GRUB_CMDLINE_LINUX=""
# 是否显示 GRUB 启动画面（无图形卡的环境关掉，改 console）
GRUB_TERMINAL=console
```

内核启动参数（`/proc/cmdline`）里的常用项：

```text
root=/dev/sda1         指定根分区（UEFI 常写 root=UUID=xxxx）
ro                     先以只读挂载根分区，fsck 后 remount 为读写
quiet                  少打印启动信息
splash                 显示启动画面
single / 1             进单用户模式（救援）
init=/bin/bash         指定 init 程序（调试用，跳过 systemd）
rd.break               在 initramfs 阶段进入急救 shell（RHEL 系）
```

## 应用场景实战

### 场景一：看开机各阶段耗时，定位启动慢

```shell
# 1. 总启动耗时（分阶段）
systemd-analyze
# 2. 哪个服务拖慢了启动
systemd-analyze blame | head
```

```text
# 实测（本机，注意 userspace 耗时异常长）
$ systemd-analyze
Startup finished in 7.199s (firmware) + 10.391s (loader) + 4.579s (kernel) + 4min 33.545s (userspace)
# firmware/loader/kernel 都正常，userspace 4 分 33 秒——说明是服务启动慢拖的
$ systemd-analyze blame | head -3
2min 33.159s docker.service
2min 6.774s fwupd-refresh.service
46.127s containerd.service
# 定位到 docker.service 拖了 2 分 33 秒，是开机慢的元凶
```

### 场景二：查看内核启动参数和引导配置

```shell
# 1. 内核启动参数
cat /proc/cmdline
# 2. GRUB 默认启动项
grep -E '^menuentry|^set default' /boot/grub/grub.cfg | head
# 3. 当前内核和已装内核
uname -r
ls /boot/vmlinuz-*
```

### 场景三：升级内核并配置回滚

新内核装好后，别急着删旧内核——先重启验证新内核稳定，出问题在 GRUB 菜单里回滚。完整流程：

```shell
# 1. 安装新内核（以 Debian/Ubuntu 为例，RHEL 用 dnf install kernel）
apt install linux-image-generic

# 2. 装完后 update-grub 会自动生成新菜单项，确认新内核进了菜单
grep '^menuentry' /boot/grub/grub.cfg | head

# 3. 查看当前默认启动项（0 = 第一个，通常是最新内核）
grep -E '^set default|GRUB_DEFAULT' /boot/grub/grub.cfg /etc/default/grub

# 4. 想固定用旧内核，改 /etc/default/grub 指定菜单项标题，再 update-grub
#    GRUB_DEFAULT="Advanced options for Ubuntu>Ubuntu, with Linux 6.17.0-40-generic"
update-grub

# 5. 重启验证，确认新内核稳定后再删旧内核
uname -r
apt remove linux-image-6.17.0-40-generic   # 确认稳定后才删
```

## 性能与调优

```text
1. 缩短固件自检 —— BIOS 关掉不必要的硬件自检、设启动顺序，UEFI 开 Fast Boot
2. 减少 GRUB 等待 —— /etc/default/grub 的 GRUB_TIMEOUT 调小（改完 update-grub）
3. 内核启动 —— 去掉不必要的内核参数，精简 initramfs 里的模块
4. 服务启动 —— systemd 并行启动，systemd-analyze blame 定位慢服务，能延迟的延迟
5. 禁用不用的服务 —— systemctl disable 关掉开机不必要的服务（蓝牙、打印等）
```

```shell
systemd-analyze critical-chain   # 看启动关键路径（哪一环最慢）
systemctl list-unit-files --state=enabled   # 看所有自启服务，精简
```

更多调优手段：

```text
1. 固件层：开启 Fast Boot / 快速启动，关闭无用的板载设备（串口、软驱控制器），设好启动顺序避免空等
2. GRUB 层：GRUB_TIMEOUT 设为 1~3 秒；去掉 splash 省图形初始化时间（服务器无桌面场景）
3. 内核层：用 make localmodconfig 裁剪不用的模块（嵌入式/定制内核），精简 initramfs（MODULES=dep 只留必需）
4. 服务层：systemd-analyze critical-chain 找关键路径；非关键服务改用 timer 延迟（见 [[14.2-systemd timer]]）
5. 并行度：systemd 默认并行，但服务自己互相阻塞（如等 DNS/网络）会拖慢，配好 After=network-online.target 而非 network.target
```

## 安全与权限

```text
1. Secure Boot —— UEFI 校验引导链（固件→GRUB→内核）签名，防 bootkit，生产机可开
2. 内核命令行可见 —— /proc/cmdline 可能暴露敏感参数，注意别在启动参数里放密码
3. GRUB 密码 —— 给 GRUB 菜单设密码，防止有人进救援模式改 root 密码
4. initramfs 完整性 —— initramfs 被篡改可注入恶意驱动，Secure Boot 覆盖此风险
5. 磁盘加密 —— LUKS 加密根分区，initramfs 里放解密模块，开机输入密码解锁
```

GRUB 密码设置（防止单用户模式被绕过改 root 密码）：

```shell
# 1. 生成密码哈希（用 grub-mkpasswd-pbkdf2，交互输入两次密码）
grub-mkpasswd-pbkdf2

# 2. 编辑 /etc/default/grub，加超级用户和密码
#    GRUB_PASSWORD=grub.pbkdf2.sha512.10000.<上一步输出的哈希>
# 3. 重新生成配置
update-grub
```

```text
GRUB 密码的作用：
限制谁能编辑引导菜单/进命令行/进单用户模式
不设的话，任何能物理接触机器的人都能在 GRUB 里加 init=/bin/bash 直接拿 root
设了之后，进单用户/救援模式要输密码
```

## 故障排查

### 启动卡住，先判断卡在哪一阶段

```shell
# 1. 卡在 GRUB 界面/grub rescue> —— 引导问题
# 2. 卡在内核加载（黑屏/panic）—— 内核或 initramfs 问题
dmesg | tail -50          # 看内核最后输出
# 3. 卡在登录前（服务起不来）—— systemd 服务/fstab 问题
systemctl --failed        # 看失败的服务
journalctl -b -1          # 看上次启动日志
```

### 内核 panic 或根分区挂不上

```shell
# 1. 进救援模式，检查 initramfs 是否该更新
lsinitramfs /boot/initrd.img-$(uname -r) | grep -i <驱动/模块>
update-initramfs -u
# 2. 检查 fstab 是否正确
cat /etc/fstab
blkid                      # 核对 UUID
```

### 卡在 grub rescue>（引导文件丢失/损坏）

```text
现象：开机不显示菜单，直接进 grub rescue> 提示符
原因：/boot/grub 被删、分区 UUID 变了（重装/克隆磁盘后）、MBR/ESP 引导代码损坏
```

```shell
# 在 grub rescue> 提示符下，先找内核所在分区
ls                        # 列出所有磁盘和分区，如 (hd0,msdos1)
ls (hd0,msdos1)/          # 看哪个分区下有 boot/ 或 vmlinuz
# 手动引导
set root=(hd0,msdos1)
set prefix=(hd0,msdos1)/boot/grub
insmod normal
normal                    # 进正常 GRUB 菜单
# 进系统后重装 GRUB 修复
grub-install /dev/sda
update-grub
```

### 卡在 initramfs 急救 shell

```shell
# 在 (initramfs) 提示符下，检查根分区能否挂载
blkid
# 手动挂载根分区看报什么错
mount /dev/sda1 /root
# 常见原因：fstab UUID 写错、LVM 卷没激活、LUKS 没解密、驱动缺了
# 修复后重建 initramfs
update-initramfs -u
```

## 常见问题

```text
Q1: 怎么判断机器是 BIOS 还是 UEFI 启动？
A: 看有没有 /boot/efi 挂载点（或 ls /sys/firmware/efi 目录存在），有就是 UEFI。

Q2: 升级内核后怎么回滚？
A: GRUB 菜单（Advanced options）里选旧内核启动，稳定后再删新内核。别急着删旧内核。

Q3: 开机慢，怎么快速定位？
A: systemd-analyze 看总耗时分阶段，systemd-analyze blame 定位慢服务，再决定优化或延迟启动。

Q4: 改了 /etc/default/grub 为什么不生效？
A: 它是配置源，改完要 update-grub 重新生成 grub.cfg 才生效。

Q5: 卡在 grub rescue> 怎么办？
A: 用 ls 找内核所在分区，set root/prefix 后 insmod normal 进正常菜单，进系统后 grub-install + update-grub 修复。

Q6: 卡在 (initramfs) 急救 shell 是什么原因？
A: 根分区挂载失败——通常是 fstab UUID 写错、改过磁盘/LVM/加密没重建 initramfs、或驱动缺失。手动 mount 根分区看报错，修复后 update-initramfs -u。

Q7: 内核 panic 和服务启动失败怎么区分？
A: panic 是内核阶段挂了（黑屏/大写键闪烁，dmesg 有 kernel panic 字样），服务失败是 systemd 阶段（能看到登录提示符，systemctl --failed 和 journalctl 可查）。
```

## 面试题

```text
1. Linux 开机的完整流程？
   答：BIOS/UEFI 固件自检 → GRUB2 加载内核和 initramfs → 内核自解压初始化 → initramfs 提供驱动挂载根分区 → systemd（PID 1）拉起服务到达默认 target。

2. initramfs 是干嘛的？为什么需要它？
   答：临时根文件系统，解决「鸡生蛋」——根分区在磁盘上、读磁盘要驱动、驱动在根分区里。initramfs 自带驱动，内核先用它读根分区再切换。

3. BIOS 和 UEFI 的区别？
   答：BIOS 老式，从 MBR 读引导代码；UEFI 新式，从 ESP 读 .efi，支持 GPT、Secure Boot、更快启动。

4. 为什么升级内核后要保留旧内核？
   答：新内核可能不兼容（驱动/panic），保留旧内核可在 GRUB 菜单回滚，删了旧内核就没退路。

5. initrd 和 initramfs 是一回事吗？
   答：原理相同（临时根文件系统），实现不同——initrd 是老式的块设备镜像（ramdisk，需要额外 mount），initramfs 是 cpio 归档直接解到 tmpfs（内核 2.6 后默认）。现代内核都用 initramfs，文件名仍习惯叫 initrd.img。

6. MBR 和 GPT 的区别？
   答：MBR 老式，最多 4 个主分区、单盘 2TB 上限，配合 BIOS；GPT 新式，支持 128 个分区、超大磁盘、带备份分区表和 CRC 校验，配合 UEFI（也兼容 BIOS 引导，通过保护性 MBR）。

7. 为什么 PID 1 一定要是 systemd（或 init）？它挂了会怎样？
   答：PID 1 是内核启动的第一个用户态进程，内核把孤儿进程托管、信号转发、系统关闭都交给它。PID 1 挂了（exit）会导致内核 panic，系统直接死机，所以 systemd 会捕获各种信号避免意外退出。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 开机慢先用 systemd-analyze blame 定位慢服务，别乱猜
2. 多内核并存，升级内核后保留旧内核，出问题 GRUB 里回滚
3. 别手改 grub.cfg，用 update-grub 生成，改配置改 /etc/default/grub
4. 改磁盘/LVM/加密配置后记得 update-initramfs -u，否则可能起不来
5. 生产服务器默认 target 用 multi-user（无桌面），省资源
6. 物理可接触的机器给 GRUB 设密码，防止单用户模式绕过改 root
7. 克隆/迁移磁盘后检查 fstab 和 GRUB 里的 UUID 是否对得上，必要时 blkid 核对

### 踩坑记录

```text
坑 1：改 /boot/grub/grub.cfg 被 update-grub 覆盖
结论：手改了 grub.cfg，下次升级内核 update-grub 把你的改动冲掉了。
原因：grub.cfg 是自动生成的，别手改。
解法：改 /etc/default/grub（配置文件），再 update-grub 生成。

坑 2：删了旧内核后新内核起不来没法回滚
结论：升级内核后删了旧内核，新内核 panic 进不去系统。
原因：删了回滚用的旧内核，GRUB 里没得选。
解法：升级内核后验证新内核稳定，再手动删旧内核（apt remove）。

坑 3：改了 LVM/加密盘配置没更新 initramfs
结论：改了磁盘配置重启后卡在 initramfs，根分区挂不上。
原因：initramfs 里还是旧配置，不知道新磁盘布局。
解法：改磁盘/LVM/加密配置后 update-initramfs -u，再重启。

坑 4：fstab 配错导致启动卡 emergency mode
结论：fstab 写了错的挂载，开机进 emergency mode。
原因：fstab 是开机挂载依据，错一行挂载失败卡启动。
解法：emergency mode 下改回 fstab，或救援模式修。

坑 5：开机慢以为是硬件问题，其实是服务拖的
结论：开机几分钟，以为硬盘/硬件坏了。
原因：其实是某个服务（docker 等）启动慢拖的。
解法：systemd-analyze blame 定位慢服务，优化或延迟启动。

坑 6：克隆/迁移磁盘后 UUID 变了导致起不来
结论：把系统盘 dd/克隆到新盘，重启卡 grub rescue 或挂不上根分区。
原因：新盘分区的 UUID 跟 fstab、grub.cfg 里记的不一致。
解法：用 blkid 查新 UUID，同步改 /etc/fstab 和 GRUB，再 update-grub + update-initramfs。

坑 7：Legacy 和 UEFI 模式切换后不重装 GRUB
结论：BIOS 里把启动模式从 Legacy 改成 UEFI（或反之），重启进不了系统。
原因：两种模式的引导代码装的位置不同（MBR vs ESP），切换后原引导代码不匹配。
解法：切模式后 grub-install 重装对应版本的 GRUB（UEFI 装到 ESP）。
```

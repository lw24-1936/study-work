## 概述

系统起不来（或启动卡住）时的排错三板斧：单用户模式（rescue，改密码/修配置）、grub 修复（重装引导加载器）、急救模式（emergency，最坏情况）。核心思路：先判断「卡在哪一步」——是 GRUB 引导问题、内核问题、还是服务启动问题，再对症下药。`systemctl --failed` 看失败的服务、`systemd-analyze` 看启动耗时、journalctl -b 看本次启动日志。

```text
启动排错三板斧：
1. 单用户模式 rescue —— 挂文件系统 + root shell，改密码、修配置
2. grub 修复 —— grub-install 重装引导、update-grub 重新生成配置
3. 急救模式 emergency —— 最精简环境，兜底修复
```

```text
# 实测（本机当前无启动失败的服务）
$ systemctl --failed
0 loaded units listed.
```

## 单用户模式

单用户模式（rescue.target）是「挂载文件系统、启动基础服务、给 root shell」的排障环境。典型用途：忘了 root 密码（进去重设）、改坏了配置导致起不来（进去改回）。进入方法：开机在 GRUB 菜单按 e 编辑启动项，在内核命令行加 `systemd.unit=rescue.target`（或 `single`），Ctrl+X 启动。进去后根分区可能是只读的，要先 `mount -o remount,rw /` 才能改。

```shell
# 进入单用户模式后
mount -o remount,rw /      # 根分区改读写（默认只读）
passwd root                # 重设 root 密码
# 或修复改坏的配置
vi /etc/fstab
reboot
```

```text
单用户模式适用场景：
1. 忘 root 密码 —— 进去 passwd 重置
2. 改坏配置（fstab/网络/服务）—— 进去改回
3. 文件系统错误 —— 进去 fsck 修复
```

## grub 修复

GRUB 是引导加载器，坏了就进不了系统（显示 grub rescue> 或直接黑屏）。修复分两种情况：grub.cfg 配置损坏（update-grub 重新生成即可，能进系统/救援模式）和 GRUB 完全损坏（grub-install 重装到磁盘，要从 Live 系统或 chroot）。常见场景：双系统装 Windows 覆盖了 GRUB、删分区破坏了引导。

```shell
# 情况一：grub.cfg 损坏（能进救援模式）
update-grub                   # 重新生成配置
grub-install /dev/sda         # 重装到磁盘 MBR/GPT

# 情况二：GRUB 完全损坏（从 Live USB 启动后 chroot）
mount /dev/sda2 /mnt
mount /dev/sda1 /mnt/boot/efi
chroot /mnt
grub-install /dev/sda
update-grub
exit && reboot
```

```text
GRUB 损坏的两种情况和修复：
1. grub.cfg 损坏 —— update-grub 重新生成（救援模式里就能做）
2. GRUB 引导程序损坏 —— grub-install 重装（需 chroot 或 Live 系统）
```

## 急救模式

急救模式（emergency.target）是最精简的排障环境——几乎只挂载根文件系统、给一个 shell，网络、服务都不起。它是「最坏情况」的兜底：连救援模式都进不去（文件系统挂载失败、关键服务崩）时用。区别救援模式：emergency 更精简（根文件系统可能都只读、没网络）。进入方法同单用户模式，加 `systemd.unit=emergency.target` 或 `emergency`。

```text
rescue vs emergency（再次对比）：
1. rescue —— 挂文件系统 + 基础服务，环境较完整，优先用
2. emergency —— 只挂根文件系统，最精简，rescue 进不去时的兜底
```

```shell
# emergency 模式下（根分区只读时）
mount -o remount,rw /       # 改读写
# 查看启动日志定位问题
journalctl -xb
# 检查 fstab 和磁盘
cat /etc/fstab
blkid
```

## 应用场景实战

### 场景一：忘了 root 密码，单用户模式重置

```shell
# 1. 开机 GRUB 菜单按 e，linux 行末尾加 systemd.unit=rescue.target
# 2. Ctrl+X 启动，进入单用户模式
# 3. 根分区改读写 + 重置密码
mount -o remount,rw /
passwd root
# 4. 重启
reboot
```

### 场景二：改坏 fstab 导致启动卡住

```shell
# 1. 启动卡在 emergency mode，按提示输入 root 密码进入
# 2. 根分区改读写
mount -o remount,rw /
# 3. 检查并修复 fstab
cat /etc/fstab
vi /etc/fstab        # 注释掉错误的挂载行
# 4. 重启验证
reboot
```

## 最佳实践与踩坑记录

### 最佳实践

1. 系统起不来先判断卡在哪步：GRUB 界面 → grub 问题；内核加载中 → 内核/initramfs；登录前 → 服务/fstab
2. 忘密码/改坏配置进单用户模式修，比重装系统快得多
3. 改 fstab/磁盘配置后，先用 mount -a 测试再重启
4. 双系统装 Windows 会覆盖 GRUB，装前备份引导
5. 定期用 systemctl --failed 检查有没有失败的服务，别等起不来才查

### 踩坑记录

```text
坑 1：单用户模式里根分区只读，改不动东西
结论：进了 rescue，passwd/vi 都报只读文件系统。
原因：rescue 挂载的根分区默认只读，要先 remount。
解法：mount -o remount,rw / 改读写，再操作。

坑 2：改 fstab 前没 mount -a 测试，重启起不来
结论：fstab 写错直接重启，开机卡 emergency。
原因：fstab 错误导致挂载失败，系统进不了正常状态。
解法：改完 fstab 先 mount -a 测试，能挂上再重启。

坑 3：grub rescue> 提示符下不知道怎么办
结论：开机显示 grub rescue>，进不了系统。
原因：GRUB 找不到引导配置/分区（分区变了或配置损坏）。
解法：rescue 里 ls 找分区、set root/prefix、insmod normal、normal 手动引导。

坑 4：双系统装 Windows 后 GRUB 没了
结论：装了 Windows，开机直接进 Windows，Linux 进不去。
原因：Windows 覆盖了 MBR/引导，GRUB 被冲掉。
解法：Live USB 启动 chroot，grub-install + update-grub 重装 GRUB。

坑 5：journalctl -b 看错启动日志
结论：排查启动问题，journalctl 看到的是当前这次还是上次的日志分不清。
原因：journalctl -b 默认当前启动，-b -1 才是上次启动。
解法：排查启动失败用 journalctl -b -1（上次启动的日志），看失败原因。
```

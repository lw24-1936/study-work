## 概述

「运行级别」（runlevel）是老 SysV init 的概念（0-6 七个级别），systemd 用「target」取代了它——target 是「一组服务的集合」，代表系统的某种运行状态。常见 target：multi-user.target（多用户命令行，服务器）、graphical.target（图形界面）、rescue.target（救援/单用户）、emergency.target（紧急模式）。切换 target 用 `systemctl isolate`，默认 target 用 `systemctl set-default`。

```text
运行级别 → target 对照：
SysV runlevel    systemd target        说明
0               poweroff.target        关机
1               rescue.target          救援（单用户）
3               multi-user.target      多用户命令行
5               graphical.target       图形界面
6               reboot.target          重启
```

```text
# 实测（本机默认 target）
$ systemctl get-default
graphical.target
# 本机是桌面系统（graphical），服务器通常是 multi-user.target
```

## multi-user.target

multi-user.target 是「多用户命令行」状态——网络、服务都起来，但没有图形界面。这是服务器的标准运行级别（省资源、无桌面）。服务器默认 target 就该是 multi-user.target。切换过去用 `systemctl isolate multi-user.target`（从图形切到命令行），设成默认用 `systemctl set-default multi-user.target`。

```shell
systemctl isolate multi-user.target     # 切换到多用户（命令行）
systemctl set-default multi-user.target # 设为默认（服务器推荐）
systemctl get-default                   # 看当前默认
```

```text
multi-user.target 特点：
1. 多用户、有网络、有服务，无图形界面
2. 服务器标准运行级别，省资源
3. 对应老 SysV 的 runlevel 3
```

## graphical.target

graphical.target 是「图形界面」状态——在 multi-user 的基础上多启动图形界面（显示管理器、桌面环境）。桌面系统默认是这个。它依赖 multi-user.target（先起服务再起图形）。服务器不需要图形界面，别设成 graphical.target（浪费资源）。

```text
graphical.target 特点：
1. 多用户 + 图形界面（桌面）
2. 依赖 multi-user.target（先起服务再起图形）
3. 桌面系统默认，服务器不推荐
```

```shell
systemctl isolate graphical.target      # 切换到图形（需装了桌面）
systemctl set-default graphical.target  # 设为默认（桌面系统）
```

## rescue 与 emergency

两个「排障模式」target：rescue.target（救援模式，挂载文件系统、启动基础服务、给 root shell——常用于改 root 密码、修配置）和 emergency.target（紧急模式，最小化环境、几乎只挂载根文件系统、单个 shell——最坏情况用）。区别：rescue 环境更完整（有网络/基础服务），emergency 最精简（只有根文件系统和 shell）。进这两个模式通常在 GRUB 菜单加参数（systemd.unit=rescue.target 或 emergency）。

```text
rescue vs emergency：
1. rescue.target —— 救援模式，挂载文件系统 + 基础服务，root shell，改密码/修配置
2. emergency.target —— 紧急模式，最小化（几乎只挂根分区），单个 shell，最坏情况
```

```shell
# 临时进入救援模式（下次重启）
systemctl rescue
# 或重启时在 GRUB 加内核参数
# systemd.unit=rescue.target
# systemd.unit=emergency.target
```

## 应用场景实战

### 场景一：服务器设成命令行模式（省资源）

```shell
# 1. 设为 multi-user（命令行）默认
systemctl set-default multi-user.target
# 2. 立即切换过去
systemctl isolate multi-user.target
# 3. 验证
systemctl get-default
```

### 场景二：忘了 root 密码，进救援模式重置

```shell
# 1. 开机在 GRUB 菜单按 e 编辑启动项
# 2. 在 linux 那行末尾加 systemd.unit=rescue.target
# 3. Ctrl+X 启动进救援模式
# 4. 救援模式里重置密码
passwd root
# 5. 重启
reboot
```

## 最佳实践与踩坑记录

### 最佳实践

1. 服务器默认 target 用 multi-user.target，别留 graphical（省资源）
2. 忘 root 密码/改坏配置，进 rescue.target 修，比重装系统快
3. emergency.target 是最坏情况的兜底，环境最精简，别当常规用
4. 切换 target 用 isolate，设默认用 set-default，别搞混
5. 改默认 target 前确认系统有没有对应组件（如无桌面就别设 graphical）

### 踩坑记录

```text
坑 1：服务器设了 graphical.target，白吃资源
结论：没桌面的服务器默认 target 是 graphical，启动慢、吃内存。
原因：graphical 会起一堆图形组件，服务器用不上。
解法：systemctl set-default multi-user.target，切回命令行。

坑 2：isolate 和 set-default 搞混
结论：以为 isolate 是「永久切换」，重启后又回到默认。
原因：isolate 是「临时切换当前状态」，set-default 才是「改默认」。
解法：要临时切换用 isolate，要永久改默认用 set-default。

坑 3：进 rescue 模式后根分区只读，改不了密码
结论：救援模式里 passwd 报只读文件系统。
原因：rescue 挂载的根分区是只读的，要先重新挂载为读写。
解法：mount -o remount,rw / 重新挂载为读写，再改密码。

坑 4：emergency 模式几乎什么都干不了
结论：进了 emergency，发现大部分命令/服务都没有。
原因：emergency 只挂根文件系统，环境极简。
解法：emergency 只是兜底，能进 rescue 就进 rescue（环境更完整）。

坑 5：改默认 target 到不存在的 target 导致起不来
结论：set-default 写了个错误 target，开机找不到。
原因：target 名写错或没装对应组件。
解法：set-default 前 systemctl list-unit-files --type=target 确认存在。
```

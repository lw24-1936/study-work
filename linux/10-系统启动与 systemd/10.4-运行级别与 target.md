## 概述

「运行级别」（runlevel）是老 SysV init 的概念（0-6 七个级别），systemd 用「target」取代了它——target 是「一组服务的集合」，代表系统的某种运行状态。常见 target：multi-user.target（多用户命令行，服务器）、graphical.target（图形界面）、rescue.target（救援/单用户）、emergency.target（紧急模式）。切换 target 用 `systemctl isolate`，默认 target 用 `systemctl set-default`。

装完服务器第一件事就该确认默认 target：桌面发行版默认 graphical.target（起图形），但服务器用不上图形界面，应改成 multi-user.target。理解 runlevel 与 target 的对应关系，是运维和面试都绕不开的基础。

```text
运行级别 → target 对照：
SysV runlevel    systemd target        说明
0               poweroff.target        关机
1               rescue.target          救援（单用户）
2               multi-user.target      多用户（无 NFS，Debian 旧默认）
3               multi-user.target      多用户命令行
4               multi-user.target      保留/自定义（默认未使用）
5               graphical.target       图形界面
6               reboot.target          重启
```

```text
# 实测（本机默认 target）
$ systemctl get-default
graphical.target
# 本机是桌面系统（graphical），服务器通常是 multi-user.target
```

```text
理解 target 的三个关键：
1. target 是「状态」不是「进程」——它聚合其他 unit，本身不干具体活
2. 一个时刻只有一个「激活的 target 集合」——isolate 切换是「停一组、起一组」
3. runlevel 只是「历史名字」——systemd 内部全用 target，runlevel 命令只是兼容层
```

## 核心概念

1. **target**：一组服务的集合，代表系统运行状态。它本身不干具体活，而是「聚合」其他 unit（Wants/Requires）。
2. **multi-user.target**：多用户命令行状态——网络、服务都起，无图形界面，服务器标准。
3. **graphical.target**：在 multi-user 基础上加图形界面（桌面），桌面系统默认。
4. **rescue.target**：救援模式，挂文件系统 + 基础服务 + root shell，改密码/修配置。
5. **emergency.target**：紧急模式，最小化环境（几乎只挂根分区），最坏情况兜底。

```text
target 关系：
graphical.target 依赖 multi-user.target（先起服务再起图形）
multi-user.target 依赖 basic.target（基础系统）
rescue.target / emergency.target 是排障专用，越往下环境越精简
```

### multi-user.target

是什么：多用户命令行运行状态，网络、ssh、数据库、Web 服务都正常拉起，只是没有图形界面（显示管理器、桌面环境）。

为什么：服务器跑的是服务不是桌面，图形组件纯属浪费资源还增加攻击面，所以服务器标准就是 multi-user。

怎么用：`systemctl set-default multi-user.target` 设默认，`systemctl isolate multi-user.target` 临时切换。

边界/易错点：multi-user 只保证「多用户服务」起来，不等于「所有服务都起来」——某个具体服务（如 nginx）还要自己 enable 才会自启。别以为切到 multi-user 服务就齐了。

### graphical.target

是什么：在 multi-user.target 之上叠加图形栈（display-manager.service + 桌面环境），是桌面系统的运行状态。

为什么：桌面用户要图形界面，graphical 把「服务 + 桌面」串起来一次到位。

怎么用：`systemctl set-default graphical.target` 设默认，`systemctl isolate graphical.target` 切换。

边界/易错点：graphical 依赖 multi-user，所以切到 graphical 之前服务已经起来了；反过来，没装显示管理器/桌面却设 graphical，会切不过去或直接黑屏。

### rescue.target

是什么：救援/单用户模式，挂载本地文件系统、启动最基础的服务，给一个 root shell（需要 root 密码）。

为什么：系统改坏配置（fstab、网络、密码）起不来时，需要一个「能进文件系统改东西」的入口。

怎么用：开机 GRUB 内核命令行加 `systemd.unit=rescue.target`，或运行中 `systemctl rescue`。

边界/易错点：rescue 挂载的根分区默认只读，改东西前要 `mount -o remount,rw /`；网络默认不启，要联网得手动拉起对应网络服务。

### emergency.target

是什么：紧急模式，几乎只挂根分区（只读）给一个 shell，连基础服务都不起，是 rescue 都进不去时的兜底。

为什么：连 rescue 依赖的基础服务都起不来（fstab 损坏、sysinit 坏）时，需要一个最小到极致的环境。

怎么用：开机内核命令行加 `systemd.unit=emergency.target`，或运行中 `systemctl emergency`。

边界/易错点：emergency 的 shell 通常不要求密码（比 rescue 更危险），且环境极简——很多命令、挂载、设备都不可用，只适合「把改坏的配置改回去」这种最小操作。

## 工作原理

systemd 的启动是「目标驱动」：从默认 target 出发，按依赖关系（Wants/Requires/After）层层拉起服务。

1. **默认 target**：`systemctl set-default` 设置，本质是创建一个指向某 target 的符号链接（default.target）。
2. **isolate 切换**：`systemctl isolate X.target` 停掉不在 X 依赖链里的服务，拉起 X 依赖链的服务，实现「切换运行状态」。
3. **救援/紧急**：rescue.target 挂载文件系统 + 启动基础服务给 root shell；emergency.target 只挂根分区给单 shell，环境最精简。

```text
启动目标链：
default.target（graphical/multi-user）
  → basic.target（基础系统就绪）
    → 各服务（nginx/mysql/...，按依赖并行）
```

```text
完整依赖链（从最上层到最底层）：
graphical.target → multi-user.target → basic.target
  → sysinit.target → local-fs.target / swap.target
    → 各挂载单元（fstab 生成）/ 各服务单元

关键点：target 之间用 Requires= / After= 串起顺序，
「隔离」隔离的是「不在目标依赖链里的 unit」。
```

```text
isolate 的实际动作（三件事）：
1. 找出目标 target 及其依赖链上的所有 unit（「要保留的集合」）
2. stop 掉所有「不在这个集合里」的 unit（含没被依赖的服务）
3. start 目标 target 依赖链里还没起来的 unit
```

## 常用命令与配置

```shell
systemctl get-default                   # 看默认 target
systemctl set-default multi-user.target # 设默认（服务器推荐）
systemctl isolate multi-user.target     # 临时切换到多用户
systemctl isolate graphical.target      # 临时切换到图形
systemctl list-units --type=target --all  # 看所有 target（含激活状态）
systemctl list-unit-files --type=target   # 看所有 target 单元文件
systemctl cat multi-user.target         # 看 target 单元文件内容
systemctl rescue                        # 进入救援模式（等价 isolate rescue.target）
systemctl emergency                     # 进入紧急模式（等价 isolate emergency.target）
```

```text
兼容层命令（runlevel 老命令，systemd 下仍能用）：
runlevel      # 打印上一次和当前的运行级别（N 3 之类）
who -r        # 等价，看当前运行级别
telinit 3     # 老式切换运行级别（systemd 里映射到 isolate multi-user.target）
```

```text
set-default vs isolate（再强调一次）：
set-default   永久改默认 target（重启后生效，本质改 default.target 符号链接）
isolate       临时切换当前运行状态（重启后回到默认 target）
```

## 配置文件解析

```text
target 文件位置：
/usr/lib/systemd/system/*.target    软件包自带（默认）
/etc/systemd/system/*.target        管理员覆盖（优先级更高）

默认 target 的实现：
/etc/systemd/system/default.target → 符号链接 → graphical.target（或 multi-user.target）
systemctl set-default 就是改这个链接指向
```

```ini
# multi-user.target 示例（聚合其他 unit）
[Unit]
Description=Multi-User System
Requires=basic.target
Conflicts=rescue.service rescue.target
After=basic.target rescue.service rescue.target
AllowIsolate=yes
```

```ini
# graphical.target 示例（在 multi-user 之上叠加图形）
[Unit]
Description=Graphical Interface
Requires=multi-user.target
Wants=display-manager.service
Conflicts=rescue.service rescue.target
After=multi-user.target rescue.service rescue.target display-manager.service
AllowIsolate=yes
```

```ini
# rescue.target 示例（单用户救援）
[Unit]
Description=Rescue Mode
Requires=sysinit.target rescue.service
After=sysinit.target rescue.service
AllowIsolate=yes
```

```text
AllowIsolate=yes 的作用：
只有声明了 AllowIsolate=yes 的 target 才能被 systemctl isolate 切换过去。
没这个字段的 target，isolate 会报错。
rescue/emergency/multi-user/graphical 都带了这个字段。
```

```text
runlevel 兼容机制的实现：
/usr/lib/systemd/system/ 下有 runlevel0.target ~ runlevel6.target 符号链接
runlevel0 → poweroff、runlevel1 → rescue、runlevel3 → multi-user、runlevel5 → graphical
老命令 runlevel / telinit 靠这套链接把数字翻译成 target
```

## 应用场景实战

### 场景一：服务器设成命令行模式（省资源）

```shell
# 1. 设为 multi-user（命令行）默认
systemctl set-default multi-user.target
# 2. 立即切换过去
systemctl isolate multi-user.target
# 3. 验证
systemctl get-default
```

### 场景二：忘了 root 密码，进救援模式重置

```shell
# 1. 开机在 GRUB 菜单按 e 编辑启动项
# 2. 在 linux 那行末尾加 systemd.unit=rescue.target
# 3. Ctrl+X 启动进救援模式
# 4. 救援模式里重置密码
mount -o remount,rw /
passwd root
# 5. 重启
reboot
```

### 场景三：新机器上架，确认默认 target 并按需切换

```shell
# 1. 看当前默认 target 和激活的 target
systemctl get-default
systemctl list-units --type=target --state=active
# 2. 服务器：改成 multi-user
systemctl set-default multi-user.target
# 3. 不重启立即切过去（确认能正常切）
systemctl isolate multi-user.target
# 4. 确认关键服务还在（切 target 不应误杀 sshd）
systemctl is-active sshd
# 5. 桌面机需要图形时再切回 graphical
systemctl set-default graphical.target
```

```text
场景三要点：
1. 上架先 get-default 确认，别想当然——有的镜像默认 graphical
2. 切完 target 用 is-active 确认 sshd 等关键服务没被误停
3. 在远程 ssh 上 isolate 要小心：切到不含网络/ssh 的 target 会断开连接
```

## 性能与调优

```text
1. 服务器用 multi-user.target —— 不起图形界面，省内存和启动时间
2. 精简 graphical —— 桌面系统去掉不需要的图形组件，加快登录
3. isolate 慎用 —— 会停掉目标链之外的服务，生产环境切换前确认影响
4. 启动耗时 —— systemd-analyze critical-chain 看从 default.target 到各服务的路径
5. 减少自启服务 —— systemctl list-unit-files --state=enabled 清理不必要的自启项，加速到达 target
```

```shell
systemd-analyze critical-chain          # 看启动关键路径（默认 target 到各服务）
systemd-analyze blame | head            # 各服务启动耗时排行
systemctl list-unit-files --type=target # 看有哪些 target 可用
```

## 安全与权限

```text
1. 救援模式是「绕开登录」的入口 —— 物理访问机器的人能进 rescue 改 root 密码
2. GRUB 设密码 —— 防止未授权者进救援/紧急模式，物理安全靠机房门禁 + GRUB 密码
3. 服务器别设 graphical —— 图形组件增加攻击面（显示管理器等）
4. emergency 环境极简 —— 能进 rescue 别进 emergency，rescue 有基础工具更安全可控
5. rescue 需要 root 密码、emergency 常免密 —— emergency 更危险，务必锁好物理访问和 GRUB
6. 远程 isolate 别切到断网 target —— 切到 rescue/emergency 会断开 ssh，人不在机房就「失联」了
```

## 故障排查

### 进救援模式改配置后还是起不来

```shell
# 1. 看失败的服务
systemctl --failed
# 2. 看启动日志
journalctl -xb | tail -50
# 3. 检查默认 target 是否指向了不存在的 target
systemctl get-default
ls -l /etc/systemd/system/default.target
```

### 切到 graphical 后黑屏

```shell
# 1. 切回 multi-user（命令行）
systemctl isolate multi-user.target
# 2. 检查显示管理器/桌面是否装了
systemctl status gdm3
# 3. 看图形启动日志
journalctl -u gdm3 -n 50
```

### isolate 切换失败或报错

```shell
# 1. 确认目标 target 存在且允许 isolate
systemctl list-unit-files --type=target | grep multi-user
systemctl cat multi-user.target | grep AllowIsolate
# 2. 看切换失败原因
journalctl -xe | tail -50
# 3. 关键服务被误停后重新拉起
systemctl start sshd
```

## 常见问题

```text
Q1: isolate 和 set-default 的区别？
A: isolate 临时切换当前运行状态（重启后回到默认），set-default 永久改默认 target（本质改 default.target 符号链接）。

Q2: 服务器该用哪个 target？
A: multi-user.target（命令行多用户），无图形、省资源，对应老 runlevel 3。

Q3: 救援模式里根分区只读改不了东西？
A: rescue 挂载的根分区默认只读，先 mount -o remount,rw / 再操作。

Q4: 怎么进 rescue/emergency 模式？
A: 开机 GRUB 菜单按 e，内核命令行加 systemd.unit=rescue.target 或 emergency.target，Ctrl+X 启动；运行中也可 systemctl rescue / emergency。

Q5: runlevel 命令在 systemd 下还能用吗？输出是什么？
A: 能用，是兼容层。输出如「N 3」表示上次 N（无）、当前 3；systemd 内部把 runlevel 数字映射到 target（3→multi-user、5→graphical）。

Q6: graphical.target 和 multi-user.target 到底差在哪？
A: graphical = multi-user + 显示管理器 + 桌面。网络/ssh/数据库等服务两边都一样起，差别只在有没有图形栈。

Q7: isolate 到 rescue 会断开我的 ssh 吗？
A: 会。rescue.target 不在 sshd 的依赖链里，isolate 过去会停掉 sshd。远程机器别 isolate 到 rescue/emergency，会失联。

Q8: systemctl rescue 和 systemctl isolate rescue.target 有区别吗？
A: 没区别。systemctl rescue 就是 isolate rescue.target 的快捷方式，底层执行同一个切换动作。
```

## 面试题

```text
1. 运行级别和 target 的对应关系？
   答：runlevel 0=poweroff、1=rescue、2/3/4=multi-user、5=graphical、6=reboot。systemd 用 target 取代了 runlevel。

2. graphical.target 和 multi-user.target 的关系？
   答：graphical 依赖 multi-user——先起多用户服务再起图形界面，graphical 是多用户 + 桌面的超集。

3. isolate 的原理？
   答：停掉目标 target 依赖链之外的服务，拉起目标依赖链内的服务，实现运行状态切换。只有 AllowIsolate=yes 的 target 能被 isolate。

4. rescue 和 emergency 的区别？
   答：rescue 挂文件系统 + 基础服务，环境较完整；emergency 几乎只挂根分区，最精简，是 rescue 进不去时的兜底。rescue 要 root 密码，emergency 常免密。

5. default.target 是什么？set-default 背后做了什么？
   答：default.target 是 /etc/systemd/system/ 下的一个符号链接，指向真正要用的 target（multi-user/graphical）。set-default 就是重建这个链接。

6. target 和 service 的关系？
   答：target 聚合 service（通过 Requires/Wants），代表「系统状态」；service 是具体干活的单元。一个 target 依赖链上挂着几十上百个 service。

7. 为什么服务器默认 target 不该是 graphical？
   答：graphical 会起显示管理器、桌面等一堆用不上的图形组件，浪费内存、拖慢启动、还增加攻击面。服务器应设 multi-user.target。

8. systemctl isolate 和 systemctl start 一个 target 的区别？
   答：start 只是「把 target 及其依赖拉起来」，不停止别的服务；isolate 会先停掉链外服务再拉起目标，实现运行状态「切换」。start 不能真正切换运行级别。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 服务器默认 target 用 multi-user.target，别留 graphical（省资源）
2. 忘 root 密码/改坏配置，进 rescue.target 修，比重装系统快
3. emergency.target 是最坏情况的兜底，环境最精简，别当常规用
4. 切换 target 用 isolate，设默认用 set-default，别搞混
5. 改默认 target 前确认系统有没有对应组件（如无桌面就别设 graphical）
6. 远程机器切换 target 前先确认会不会断开 ssh（别 isolate 到 rescue/emergency）
7. 切完 target 用 systemctl is-active 确认关键服务（sshd）还在

### 踩坑记录

```text
坑 1：服务器设了 graphical.target，白吃资源
结论：没桌面的服务器默认 target 是 graphical，启动慢、吃内存。
原因：graphical 会起一堆图形组件，服务器用不上。
解法：systemctl set-default multi-user.target，切回命令行。

坑 2：isolate 和 set-default 搞混
结论：以为 isolate 是「永久切换」，重启后又回到默认。
原因：isolate 是「临时切换当前状态」，set-default 才是「改默认」。
解法：要临时切换用 isolate，要永久改默认用 set-default。

坑 3：进 rescue 模式后根分区只读，改不了密码
结论：救援模式里 passwd 报只读文件系统。
原因：rescue 挂载的根分区是只读的，要先重新挂载为读写。
解法：mount -o remount,rw / 重新挂载为读写，再改密码。

坑 4：emergency 模式几乎什么都干不了
结论：进了 emergency，发现大部分命令/服务都没有。
原因：emergency 只挂根文件系统，环境极简。
解法：emergency 只是兜底，能进 rescue 就进 rescue（环境更完整）。

坑 5：改默认 target 到不存在的 target 导致起不来
结论：set-default 写了个错误 target，开机找不到。
原因：target 名写错或没装对应组件。
解法：set-default 前 systemctl list-unit-files --type=target 确认存在。

坑 6：远程 isolate 到 rescue/emergency，ssh 直接断了
结论：在远程机器上 isolate 切到救援模式，人还在机房外，机器失联。
原因：rescue/emergency 依赖链里没有 sshd，isolate 会停掉它。
解法：远程机器别 isolate 到 rescue/emergency；真要切，确保有带外管理（IPMI/console）。

坑 7：切到 graphical 黑屏，以为是系统坏了
结论：set-default graphical 后重启黑屏，其实系统正常、只是没图形组件。
原因：没装显示管理器/桌面，graphical.target 依赖的 display-manager 起不来。
解法：切回 multi-user（isolate multi-user.target），确认要图形先装桌面组件再设 graphical。
```

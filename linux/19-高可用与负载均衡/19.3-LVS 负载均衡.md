## 概述

LVS（Linux Virtual Server）是 Linux 内核级的四层（传输层）负载均衡器，性能极高（跑在内核态，吞吐可达百万级连接）。它工作在 TCP/UDP 层（只看 IP 和端口，不看 HTTP 内容），有三种转发模式：NAT（网络地址转换）、DR（直接路由，最常用）、TUN（IP 隧道）。配合 Keepalived 做高可用，是经典的高性能负载均衡方案。

```text
LVS 定位：
内核级四层负载均衡，只转发（不看 HTTP 内容），性能极高，
负责「把流量分发到后端多台服务器」。七层逻辑（HTTP 路由）交给 Nginx/HAProxy。
```

## 核心概念

1. **VS（Virtual Server）**：虚拟服务，对外暴露的 VIP + 端口（客户端访问这个）。
2. **RS（Real Server）**：真实服务器，后端实际处理请求的机器。
3. **Director**：调度器，运行 LVS 的机器，负责把流量转发到 RS。
4. **三种模式**：NAT（改 IP 转发）、DR（改 MAC 直接路由，最常用）、TUN（IP 隧道封装）。
5. **调度算法**：决定「请求分给哪个 RS」——rr（轮询）、wrr（加权轮询）、lc（最少连接）、wlc（加权最少连接）、sh（源地址哈希）。

```text
核心术语：
VS 虚拟服务（VIP:端口）→ Director 调度器 → RS 真实服务器
```

## 工作原理

三种转发模式的区别在「数据包怎么转发」：

1. **NAT 模式**：Director 改写数据包的目标 IP（VIP→RS 的 IP），RS 回包经 Director 改回源 IP。所有流量（进和出）都经过 Director，Director 是瓶颈，但 RS 不需要特殊配置。
2. **DR 模式（最常用）**：Director 不改 IP，只改目标 MAC 地址（把包转给 RS 的 MAC），RS 回包直接回给客户端（不经过 Director）。因为「请求经 Director，响应不经」，Director 压力小，吞吐高。要求 RS 和 Director 在同一物理网段，且 RS 要配 VIP（lo 接口）。
3. **TUN 模式**：Director 把包用 IP 隧道封装发给 RS，RS 解封装后回包直连客户端。适合「RS 在不同网段/跨机房」，但有隧道开销。

```text
三模式对比：
NAT  —— 进出都经 Director，Director 是瓶颈，RS 无需特殊配置
DR   —— 进经 Director、出直连，性能最高，要求同网段 + RS 配 VIP
TUN  —— 隧道封装，适合跨网段，有封装开销
```

```text
调度算法：
rr/wrr     轮询/加权轮询（按顺序轮流）
lc/wlc     最少连接/加权最少连接（发给连接最少的 RS）
sh         源地址哈希（同源 IP 固定到同 RS，会话保持）
```

## 常用命令与配置

```shell
# 安装（本机未装，示例）
apt install ipvsadm          # Debian/Ubuntu
dnf install ipvsadm          # CentOS/RHEL

# 配置虚拟服务 + 后端（DR 模式）
ipvsadm -A -t 192.168.1.100:80 -s rr        # 加 VS，rr 算法
ipvsadm -a -t 192.168.1.100:80 -r 192.168.1.11 -g   # 加 RS（-g = DR）
ipvsadm -a -t 192.168.1.100:80 -r 192.168.1.12 -g

# 查看
ipvsadm -L -n                # 查看规则
ipvsadm -L -n --stats        # 查看统计（连接数/流量）
ipvsadm -L -n -c             # 查看当前连接

# 保存/恢复
ipvsadm-save > /etc/ipvsadm.rules
ipvsadm-restore < /etc/ipvsadm.rules
```

```text
ipvsadm 选项：
-A  添加虚拟服务（VS）
-a  添加真实服务器（RS）
-t  TCP 服务（-u 是 UDP）
-s  调度算法（rr/wrr/lc/wlc/sh）
-g  DR 模式（-m 是 NAT，-i 是 TUN）
```

## 配置文件解析

LVS 用 ipvsadm 命令配置（无独立配置文件），但 RS 端（DR 模式）需要特殊配置——在 lo 接口上配 VIP：

```bash
# RS 端（DR 模式）配置 VIP 到 lo 接口
# 这样 RS 能接收「目标地址是 VIP」的包，且回包用 VIP 源地址
ip addr add 192.168.1.100/32 dev lo
# 抑制 lo 接口对 VIP 的 ARP 响应（避免 RS 和 Director 抢 ARP）
echo 1 > /proc/sys/net/ipv4/conf/lo/arp_ignore
echo 2 > /proc/sys/net/ipv4/conf/lo/arp_announce
echo 1 > /proc/sys/net/ipv4/conf/all/arp_ignore
echo 2 > /proc/sys/net/ipv4/conf/all/arp_announce
```

```text
DR 模式 RS 的关键配置：
1. lo 配 VIP —— RS 能接收 VIP 包、回包源地址是 VIP
2. 抑制 ARP —— 只让 Director 响应 VIP 的 ARP，RS 不响应（防抢）
```

## 应用场景实战

### 场景一：DR 模式负载均衡（最常用）

```text
架构：
客户端 → VIP 192.168.1.100:80（Director 的 LVS）
        → RS1 192.168.1.11（Web1，lo 配 VIP）
        → RS2 192.168.1.12（Web2，lo 配 VIP）

配置：
1. Director：ipvsadm 配 VS + 两个 RS（-g DR 模式）
2. RS1/RS2：lo 配 VIP + 抑制 ARP
3. 客户端访问 VIP，流量分发到两台 Web
4. RS 回包直连客户端（不经 Director），性能高
```

### 场景二：LVS + Keepalived 高可用

```text
架构：两个 Director + Keepalived 做 VIP 漂移
Director1（主）+ Director2（备）── 共享 VIP
任一 Director 挂，VIP 漂移到另一个，负载均衡不中断
```

## 性能与调优

```text
1. 选对模式 —— 同网段用 DR（性能最高），跨网段用 TUN，简单场景用 NAT
2. 调度算法 —— 连接时长不均用 wlc（最少连接），要会话保持用 sh
3. 连接跟踪 —— LVS 本身极快，瓶颈通常在 RS 和后端应用
4. 持久化连接 —— 配 -p 超时（如 -p 300），同源 IP 固定到同 RS（会话保持）
```

## 安全与权限

```text
1. DR 模式 ARP —— RS 要正确抑制 ARP，否则 RS 抢 VIP 的 ARP 导致流量混乱
2. 防火墙 —— Director 放行 VIP 端口，RS 放行真实端口
3. 权限 —— ipvsadm 需 root
4. 防 DDoS —— LVS 可抗一定攻击（内核态快速转发），但后端 RS 仍是瓶颈
```

## 故障排查

### 流量分发不到 RS

```shell
# 1. 看 LVS 规则和统计
ipvsadm -L -n --stats
# 2. 看是否有连接进入（InActConn/ActiveConn）
ipvsadm -L -n -c
# 3. 抓包看流量（Director 上）
tcpdump -i eth0 port 80
# 4. 检查 RS 的 VIP 配置和 ARP 抑制
ip addr show lo && cat /proc/sys/net/ipv4/conf/lo/arp_ignore
```

## 常见问题

```text
Q1: DR 模式 RS 收不到包？
A: 检查 RS 的 lo 是否配了 VIP，ARP 抑制是否正确（否则包到不了 RS）。

Q2: 回包不走 Director（DR 模式）会不会有问题？
A: 不会，DR 模式就是「进经 Director、出直连」，回包直接回客户端是设计目标。

Q3: 会话保持怎么做？
A: 用 sh 调度算法（源哈希）或 -p 持久化连接（同源 IP 固定到同 RS）。

Q4: LVS 和 Nginx 负载均衡区别？
A: LVS 是四层（IP:端口，性能高），Nginx 是七层（HTTP 内容，功能丰富）。常用 LVS 做入口四层分发，Nginx 做七层路由。
```

## 面试题

```text
1. LVS 三种模式的区别？
   答：NAT 进出都经 Director（瓶颈）；DR 进经 Director、出直连（性能最高，同网段）；TUN 隧道封装（跨网段）。

2. DR 模式为什么 RS 要配 VIP 和抑制 ARP？
   答：配 VIP 让 RS 能收「目标=VIP」的包、回包源=VIP；抑制 ARP 防止 RS 和 Director 抢 VIP 的 ARP 响应。

3. 调度算法怎么选？
   答：连接时长均匀用 rr/wrr，时长不均用 lc/wlc（发给连接少的），要会话保持用 sh。

4. LVS 为什么性能高？
   答：跑在内核态（ipvs 模块），只做四层转发（不看 HTTP 内容），DR 模式回包不经 Director，吞吐极高。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 同网段用 DR 模式（性能最高），跨网段才用 TUN
2. RS 正确配 lo 的 VIP + ARP 抑制（DR 模式关键）
3. 会话保持用 sh 算法或 -p 持久化连接
4. 配合 Keepalived 做 Director 高可用
5. 规则用 ipvsadm-save 持久化，重启不丢

### 踩坑记录

```text
坑 1：DR 模式 RS 没抑制 ARP，抢 VIP
结论：RS 和 Director 都响应 VIP 的 ARP，流量混乱。
原因：RS 配了 lo VIP 但没设 arp_ignore/arp_announce，RS 也响应 ARP。
解法：RS 上设 arp_ignore=1、arp_announce=2，只让 Director 响应 VIP 的 ARP。

坑 2：DR 模式 RS 没配 lo VIP，收不到包
结论：流量到不了 RS，RS 上抓包看不到请求。
原因：RS 没在 lo 配 VIP，无法接收「目标地址=VIP」的包。
解法：RS 的 lo 接口配 VIP（/32），才能接收 VIP 包。

坑 3：NAT 模式下 Director 成为瓶颈
结论：NAT 模式吞吐上不去，Director 的 CPU/带宽打满。
原因：NAT 模式进出流量都经 Director，Director 是瓶颈。
解法：同网段改用 DR 模式（回包直连，不经 Director）。

坑 4：调度算法选错导致负载不均
结论：用了 rr 轮询，但后端请求时长差异大，有的 RS 忙死有的闲死。
原因：rr 只看顺序不看负载，长请求会让某 RS 堆积。
解法：时长不均用 wlc（加权最少连接），发给连接最少的 RS。

坑 5：规则没持久化，重启后 LVS 失效
结论：重启后 ipvsadm -L 空，负载均衡没了。
原因：ipvsadm 规则是内核态临时的，没 save 持久化。
解法：ipvsadm-save > /etc/ipvsadm.rules + 开机 restore。
```

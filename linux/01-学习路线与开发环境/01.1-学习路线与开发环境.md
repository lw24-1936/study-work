## 概述

Linux 运维 / SRE / 平台工程师的成长，本质是把「命令行基础 + Shell 脚本 + 系统原理 + 网络 + 自动化运维」串成一条可落地的学习路径，并配一套能随时跑起来的实验环境。本主题回答两个问题：该按什么顺序学、用什么工具链练。核心思路是「先搭环境、边学边做、以项目驱动」——环境是前提，具体知识点在本知识库的后续篇章展开。

```text
学习路线的三条主线：
1. 命令行与系统基础 —— 文件系统、权限、进程、内存、软件包、systemd（地基）
2. 脚本与文本处理 —— Shell 脚本、正则、grep/sed/awk 三剑客（日常效率核心）
3. 网络与运维进阶 —— TCP/IP、防火墙、日志监控、自动化、高可用、容器与内核（进阶）
```

## Linux 运维 / SRE / 平台工程师能力模型

这三个岗位共享同一套 Linux 内核知识底座，区别在侧重：运维工程师偏「系统的安装、部署、维护与故障处理」，SRE 偏「用工程手段保证系统的可靠性（SLO、容量、变更、可观测性）」，平台工程师偏「把底层能力抽象成内部平台（CICD、容器、监控、基础设施即代码）」。面试和晋升考察的往往是「系统原理 + 排障经验」的深度，而非某个命令的记忆。

```text
能力模型四象限：
1. 系统底层 —— 文件系统、进程、内存、权限、内核参数、系统调用
2. 网络与安全 —— TCP/IP、路由、防火墙、DNS、SSH/TLS 加固
3. 运维工程 —— 日志、监控、定时任务、备份、高可用、自动化（Ansible/Terraform）
4. 容器与可观测 —— Docker/K8s、Prometheus/Grafana、eBPF 性能分析
```

## 学习阶段与先修关系

学习有清晰的先修依赖，跳级会事倍功半。阶段一打地基（命令行 + 文件系统 + 权限 + 进程），阶段二学脚本（Shell + 三剑客 + 文本处理），阶段三进系统核心（网络 + systemd + 存储 + 内存），阶段四做运维进阶（监控 + 自动化 + 高可用 + 容器），阶段五冲内核与综合项目。每阶段都要配对应的可运行实验，而不是只看书。

```text
五阶段与先修关系：
阶段一 基础 —— 命令行与文件操作(02) + 用户权限(05) + 进程(07) —— 无先修，入口
阶段二 脚本 —— 文本三剑客(03) + Shell 编程(04) —— 依赖阶段一
阶段三 系统核心 —— 磁盘文件系统(06) + 内存(08) + 软件包(09) + systemd(10) + 网络(11) + 防火墙(12)
阶段四 运维 —— 日志监控(13) + 定时任务(14) + 性能调优(16) + 故障排查(17) + 高可用(19) + 网络服务(20)
阶段五 进阶 —— 系统调用与内核(15) + 存储(18) + 虚拟化容器(21) + 自动化(22) + 安全(23) + eBPF(24)

先修示例：学 Shell 前先懂命令行与管道；学防火墙前先懂 TCP/IP；学性能调优前先懂进程与内存。
```

## 发行版选择

Linux 发行版分三大系：Debian 系（apt）、Red Hat 系（dnf/yum）、Arch 系（pacman）。生产环境主流是 Debian 系和 Red Hat 系——Ubuntu 适合个人开发与学习，Debian 适合追求稳定的服务器，CentOS Stream / Rocky / AlmaLinux 是 Red Hat 系的企业替代品（CentOS 8 停维护后 Rocky 与 AlmaLinux 承接了其社区定位），openSUSE 在 SUSE 生态、Alpine 以极简体积成为容器镜像首选。学习阶段选一个用熟即可，包管理器的差异不影响系统原理的学习。

```text
发行版选型：
1. Ubuntu —— 文档最多、上手最快，个人开发与学习首选，LTS 每两年一版
2. Debian —— 稳定保守，服务器长期运行首选，软件版本偏旧但可靠
3. CentOS Stream —— Red Hat 的上游滚动版，定位介于 Fedora 与 RHEL 之间
4. Rocky / AlmaLinux —— CentOS 8 停维护后的社区承接者，1:1 兼容 RHEL
5. openSUSE —— SUSE 系，YaST 配置工具 + zypper 包管理，企业 SUSE 的社区版
6. Alpine —— musl libc + busybox 极简，容器基础镜像首选（几 MB 体积）
```

```shell
# 查看发行版信息（任何发行版通用）
cat /etc/os-release

# Debian 系与 Red Hat 系包管理器对照
apt update && apt install -y nginx      # Debian/Ubuntu
dnf install -y nginx                    # Rocky/AlmaLinux/CentOS Stream
apk add nginx                           # Alpine
```

## 虚拟机 / 双系统 / 云主机 / 裸金属

练手环境的四种载体各有取舍：虚拟机（VirtualBox/VMware）最安全、可快照回滚，适合初学和做破坏性实验；双系统性能最好但要重启切换、有数据风险；云主机（按量付费）最接近真实生产、有公网 IP，适合学部署和网络；裸金属就是物理服务器，成本最高、权限最大。推荐路径：虚拟机入门 → 云主机做真实部署 → 裸金属/集群做高可用实验。

```text
四种环境载体：
1. 虚拟机 —— 快照/克隆/回滚，随便折腾不心疼，初学与故障演练首选
2. 双系统 —— 原生性能，但要重启切换、引导和磁盘分区有风险
3. 云主机 —— 有公网 IP、最像生产，适合学网络/部署/安全，按量计费便宜
4. 裸金属 —— 物理机/独服，权限最大，适合压测、高可用、内核调优实验
```

```shell
# Multipass 快速起一台 Ubuntu 虚拟机（比 VirtualBox 更轻）
multipass launch --name dev --cpus 2 --memory 4G --disk 20G
multipass shell dev
multipass stop dev && multipass delete dev && multipass purge
```

## WSL2 / Multipass / Vagrant / Packer

这四种工具解决「在 Windows/macOS 上快速获得 Linux 环境」和「批量构建可复现的环境镜像」两类问题：WSL2 让 Windows 原生跑 Linux 内核、文件互通；Multipass 一键管理轻量 Ubuntu 虚拟机；Vagrant 用代码声明式定义虚拟机（Vagrantfile）；Packer 构建可复用的虚拟机镜像（供 Vagrant/云平台使用）。前两者是「个人练手」，后两者是「环境即代码」的工程化手段。

```text
工具分工：
1. WSL2 —— Windows 内嵌 Linux 内核，VSCode Remote 无缝衔接，开发体验最好
2. Multipass —— Canonical 出品，单命令启停 Ubuntu 实例，适合快速实验
3. Vagrant —— Vagrantfile 声明式定义多虚拟机拓扑，团队统一环境
4. Packer —— 构建标准化镜像，供 Vagrant/云主机/AWS AMI 复用
```

```ruby
# Vagrantfile：声明式定义一个 Ubuntu 22.04 虚拟机
Vagrant.configure("2") do |config|
  config.vm.box = "ubuntu/jammy64"
  config.vm.network "private_network", ip: "192.168.56.10"
  config.vm.provider "virtualbox" do |vb|
    vb.memory = "2048"
    vb.cpus = 2
  end
  config.vm.provision "shell", inline: "apt update && apt install -y nginx"
end
```

```shell
# Vagrant 生命周期
vagrant up && vagrant ssh
vagrant halt && vagrant destroy -f
```

## SSH 远程连接、密钥认证与免密登录

SSH 是 Linux 远程运维的默认入口。密码认证简单但每次要输密码、易被爆破；密钥认证用「公钥放服务器、私钥留本地」的非对称方式实现免密登录，是生产环境的标准做法。核心命令 ssh 连接、ssh-keygen 生成密钥、ssh-copy-id 部署公钥、scp/rsync 传文件。

```text
SSH 要点：
1. 密钥认证 —— 私钥在客户端、公钥追加到服务器 ~/.ssh/authorized_keys，非对称加密验证身份
2. 免密登录 —— ssh-copy-id 一条命令把公钥部署到目标机，之后 ssh 不再要密码
3. 权限敏感 —— 私钥文件必须 600、.ssh 目录必须 700，否则 sshd 拒绝
4. 安全加固 —— 改端口、禁用 root 密码登录、禁密码只留密钥（详见 12.4 安全通信）
```

```shell
# 生成密钥对（默认 Ed25519，比 RSA 更快更短）
ssh-keygen -t ed25519 -C "your_email@example.com"

# 部署公钥到服务器，实现免密登录
ssh-copy-id -i ~/.ssh/id_ed25519.pub user@192.168.1.10

# 免密登录与传文件
ssh user@192.168.1.10
scp ./app.tar.gz user@192.168.1.10:/opt/
rsync -avz ./dist/ user@192.168.1.10:/var/www/html/
```

## Shell 环境与配置文件与别名

Shell 是用户与内核之间的命令解释器，bash 是默认、zsh 交互体验好（补全/主题）、fish 开箱即用但语法不兼容 POSIX。登录 shell 读取 ~/.bash_profile（或 ~/.profile），交互 shell 读取 ~/.bashrc——两者加载时机不同，别把环境变量和别名写错位置。别名 alias 把长命令缩成短命令，是效率利器。

```text
Shell 与配置要点：
1. bash —— Linux 默认 shell，脚本兼容性最好，学 Shell 从 bash 开始
2. zsh —— 交互体验强（oh-my-zsh 补全/主题/插件），兼容 bash 脚本
3. fish —— 开箱即用、语法糖多，但不兼容 POSIX sh，脚本慎用
4. 配置文件 —— 登录 shell 读 .bash_profile，交互 shell 读 .bashrc，别名和环境变量各归其位
```

```shell
# ~/.bashrc 里加别名和环境变量
alias ll='ls -alF'
alias gs='git status'
alias k='kubectl'
export PATH="$HOME/bin:$PATH"

# 改默认 shell（bash -> zsh）
chsh -s /bin/zsh
```

## 终端多路复用

tmux 和 screen 把单个 SSH 会话切分成多个窗口/面板，核心价值是「会话常驻」——断开 SSH 后后台任务继续跑、重新连接后能恢复现场。tmux 是现代主流（窗口/面板/会话三层模型 + 可配置），screen 更老、功能较弱但几乎每台机器都有。远程跑长任务、多人协作、保留现场都靠它。

```text
tmux 三层模型：
1. session（会话）—— 常驻服务端，断线不丢，attach 恢复
2. window（窗口）—— 一个 session 里的多个全屏标签页
3. pane（面板）—— 一个窗口里水平/垂直分割的多个终端
```

```shell
tmux new -s dev          # 新建会话
tmux attach -t dev       # 重新连接会话（断线后恢复现场）
tmux ls                  # 列出会话
# 会话内快捷键（默认前缀 Ctrl+b）：
# Ctrl+b c  新建窗口    Ctrl+b "  水平分割面板    Ctrl+b %  垂直分割面板
# Ctrl+b d  脱离会话（后台继续跑）    Ctrl+b x  关闭面板
```

```text
# 实测：tmux 并非所有发行版默认自带
$ command -v tmux || echo "tmux 未安装"
tmux 未安装
$ apt install -y tmux    # Debian/Ubuntu 一行装上
```

## 编辑器

终端编辑器是远程运维的基本功，因为生产服务器上往往只有它。Vim/Neovim 是模态编辑器、学习曲线陡但效率极高，几乎所有 Linux 发行版自带；nano 简单直观、适合临时改个配置。远程运维至少要掌握 Vim 的基础操作（三种模式、移动、编辑、保存退出、查找替换），否则改个配置文件都费劲。

```text
编辑器选型：
1. Vim —— 模态编辑（普通/插入/命令模式），系统自带，远程运维标配
2. Neovim —— Vim 的现代重写，LSP 原生支持，插件生态（Lua）更现代
3. nano —— 无模式、简单直观，适合不熟 Vim 时临时改配置
```

```shell
vim /etc/hosts
# 基础操作：i 进入插入模式，Esc 回普通模式
# :w 保存，:q 退出，:wq 保存退出，:q! 强制退出不保存
# /pattern 查找，n 下一个，:s/old/new/g 整行替换
```

## 编译工具链

从源码编译软件需要一套工具链：GCC/Clang 是编译器（把源码编成目标文件），Make 根据 Makefile 的规则驱动编译，CMake 是跨平台的构建系统生成器（生成 Makefile/Ninja），autotools 是老的构建体系（configure + make + make install）。源码编译的典型三步走是 `./configure && make && make install`，在软件包管理那篇（09.3）会详细展开。

```text
工具链分工：
1. GCC / Clang —— 编译器，GCC 是 Linux 默认，Clang 编译更快、报错信息更友好
2. Make —— 读 Makefile，按依赖关系增量编译，只重编改动的部分
3. CMake —— 生成器，从 CMakeLists.txt 生成 Makefile 或 Ninja，跨平台首选
4. autotools —— 老式构建体系，configure 脚本探测环境后生成 Makefile
```

```shell
# 经典源码编译三步走
./configure --prefix=/usr/local
make -j$(nproc)          # 并行编译，用满 CPU 核数
sudo make install

# CMake 构建
cmake -S . -B build && cmake --build build -j$(nproc)
```

## 网络下载与请求

curl、wget、scp、rsync 是运维日常的传输四件套：curl 发 HTTP 请求、调试接口（最强大），wget 批量下载、断点续传，scp 基于 SSH 的加密文件拷贝，rsync 增量同步、只传差异。curl 和 wget 管「互联网下载」，scp 和 rsync 管「机器之间同步文件」，职责不同别混用。

```text
传输工具分工：
1. curl —— 发任意 HTTP 请求（GET/POST/自定义头），调试 API 首选
2. wget —— 递归/断点续传下载，批量拉文件强
3. scp —— 基于 SSH 的加密拷贝，简单场景够用
4. rsync —— 增量同步（只传差异块），目录镜像/备份首选
```

```shell
# curl 调试接口
curl -s -X POST http://localhost:8080/api/login \
  -H 'Content-Type: application/json' \
  -d '{"user":"admin","pass":"secret"}'

# wget 断点续传下载
wget -c https://example.com/large.tar.gz

# rsync 增量同步目录到远程
rsync -avz --delete ./web/ user@server:/var/www/web/
```

## 帮助与手册

遇到命令不会用，第一反应是查文档而不是搜搜索引擎。man 是离线手册（man ls），info 是 GNU 的带链接文档，apropos 按关键词反查命令（忘了命令名用它），tldr 是社区维护的精简示例手册（比 man 短、直奔例子），help 看 shell 内置命令的帮助。man 手册分 9 个 section（1 用户命令、5 配置文件格式、8 系统管理命令）。

```text
帮助体系：
1. man —— 完整手册，分 section，man 5 sshd_config 查配置、man 8 mount 查管理命令
2. info —— GNU 文档，带超链接，比 man 更详尽但交互略复杂
3. apropos —— 按关键词反查，apropos partition 找到 fdisk/parted
4. tldr —— 精简实例手册，tldr tar 直接给常用例子，新手友好
5. help —— 内置命令帮助，help cd、help for（外部命令要用 man）
```

```shell
man ls                  # 查 ls 手册，q 退出，/ 搜索
man 5 sshd_config       # 查配置文件格式
apropos -a create partition   # 反查「创建分区」相关命令
tldr tar                # 需要先 pip install tldr
help cd                 # shell 内置命令
```

## 环境与实验：容器化练习环境与故障演练

学习 Linux 最有效的方式是「在容器里做实验、在故障里学排查」。Docker 容器几秒拉起一个干净环境、随手销毁，适合练习命令、搭服务、复现问题；故障演练则是主动制造故障（删文件、占满磁盘、杀掉进程、断网）来练习排查和恢复。安全的学习环境 + 刻意的故障演练，比被动排障成长快得多。

```text
实验环境三原则：
1. 用容器隔离 —— 每个实验一个 docker run，坏了 rm 重来，不污染宿主机
2. 随手造故障 —— 主动 dd 塞满磁盘、kill -9 杀进程、iptables 断网，再练排查
3. 保留可复现 —— 实验步骤写成脚本，复盘和分享都用它
```

```shell
# 起一个干净的 Ubuntu 容器做实验
docker run -it --rm ubuntu:22.04 bash

# 起一个带 systemd 的容器练 systemd/服务管理
docker run -it --rm --privileged \
  -v /sys/fs/cgroup:/sys/fs/cgroup:rw \
  ubuntu:22.04 bash

# 故障演练：塞满磁盘再练习排查
dd if=/dev/zero of=/tmp/bigfile bs=1M count=2048
df -h
# 排查：df -h 看哪个分区满了，du -sh /* 找大目录，lsof +L1 找被删除仍占用的文件
```

## 应用场景实战

### 场景一：从零配一台远程开发机（发行版 + SSH 免密 + 基础工具）

```shell
# 1. 用 Multipass 或云主机起一台 Ubuntu 22.04，然后 SSH 进去
ssh root@<server-ip>

# 2. 换国内软件源并更新（加快下载速度）
sed -i 's/archive.ubuntu.com/mirrors.aliyun.com/g' /etc/apt/sources.list
apt update && apt full-upgrade -y

# 3. 装基础工具链：编辑器 + 传输 + 复用 + 帮助
apt install -y vim curl wget rsync tmux tldr htop git

# 4. 建一个普通用户并配置密钥免密登录（别用 root 直接操作）
adduser deploy
usermod -aG sudo deploy
mkdir -p /home/deploy/.ssh && chmod 700 /home/deploy/.ssh
cp ~/.ssh/authorized_keys /home/deploy/.ssh/authorized_keys
chown -R deploy:deploy /home/deploy/.ssh
```

```shell
# 5. 从本地验证免密登录 + 传文件
ssh-copy-id deploy@<server-ip>     # 本地执行，部署公钥
ssh deploy@<server-ip>             # 免密登录成功
rsync -avz ./project/ deploy@<server-ip>:~/project/
```

### 场景二：搭一个容器化实验环境并做一次故障演练

```shell
# 1. 用容器起实验环境（练习命令不污染宿主机）
```

## 最佳实践与踩坑记录

### 最佳实践

1. 环境先行：先花一天把虚拟机/容器跑通，再开始学，边学边跑
2. 学习以项目驱动，每个知识点配一个最小可运行命令，不只看书
3. 优先学一套发行版（Ubuntu）吃透原理，再横向对比 Red Hat 系差异
4. SSH 一律用密钥认证并禁用 root 密码登录，养成生产安全习惯
5. 实验一律进容器或虚拟机，随手造故障练排查，别在唯一的生产机上试
6. 遇到命令先 man/tldr 查文档，再搜搜索引擎，培养离线排障能力
7. 把常用操作沉淀成别名和脚本，重复劳动自动化

### 踩坑记录

```text
坑 1：在 Windows 上用 WSL2 学 Linux，结果和服务器环境行为不一致
结论：本地跑通、服务器报错，排查半天发现是环境差异。
原因：WSL2 是精简内核 + 特殊文件系统，与真实发行版（systemd、网络栈）有差异。
解法：练系统原理用虚拟机或容器，WSL2 只当轻量开发环境用。

坑 2：SSH 免密登录配好了却一直要密码
结论：ssh-copy-id 执行成功，连接时仍提示输密码。
原因：~/.ssh 目录或 authorized_keys 权限不对（目录非 700、文件非 600），sshd 拒绝信任。
解法：chmod 700 ~/.ssh && chmod 600 ~/.ssh/authorized_keys，再检查 sshd 的 StrictModes。

坑 3：把环境变量写在 ~/.bashrc 里导致 ssh 执行命令找不到
结论：ssh host 'mycmd' 报 command not found，但交互登录有。
原因：非交互式 ssh 不读 .bashrc（读 .bash_profile 或直接不读），环境变量没加载。
解法：环境变量写进 ~/.bash_profile 或 ~/.profile，或在命令里显式 source。

坑 4：rsync 同步目录越同步越乱
结论：目标目录出现残留文件，删了的文件又出现。
原因：没用 --delete 参数，rsync 默认只增不删，源端删除的文件目标端还留着。
解法：做镜像同步用 rsync -avz --delete，确认源是权威再删。

坑 5：直接用 root 在服务器上做实验，误删系统文件
结论：一条 rm -rf 打错路径，系统起不来。
原因：root 权限无边界，实验和运维混在同一个账户。
解法：日常用普通用户 + sudo，实验进容器/虚拟机，生产操作前先备份。
```

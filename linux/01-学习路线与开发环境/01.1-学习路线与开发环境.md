## 概述

Linux 运维 / SRE / 平台工程师的成长，本质是把「命令行基础 + Shell 脚本 + 系统原理 + 网络 + 自动化运维」串成一条可落地的学习路径，并配一套能随时跑起来的实验环境。本主题回答两个问题：该按什么顺序学、用什么工具链练。核心思路是「先搭环境、边学边做、以项目驱动」——环境是前提，具体知识点在本知识库的后续篇章展开。

```text
学习路线的三条主线：
1. 命令行与系统基础 —— 文件系统、权限、进程、内存、软件包、systemd（地基）
2. 脚本与文本处理 —— Shell 脚本、正则、grep/sed/awk 三剑客（日常效率核心）
3. 网络与运维进阶 —— TCP/IP、防火墙、日志监控、自动化、高可用、容器与内核（进阶）
```

## 核心概念

1. **能力模型**：运维 / SRE / 平台工程师共享同一套 Linux 内核知识底座，区别在侧重——运维偏安装部署与故障处理，SRE 偏工程化保证可靠性（SLO/容量/变更/可观测性），平台工程师偏把底层能力抽象成内部平台（CICD/容器/监控/IaC）。面试考察的是「系统原理 + 排障经验」的深度，不是命令记忆。
2. **学习阶段与先修**：阶段一打地基（命令行/文件系统/权限/进程）→ 阶段二学脚本（Shell + 三剑客）→ 阶段三进系统核心（网络/systemd/存储/内存）→ 阶段四做运维进阶（监控/自动化/高可用/容器）→ 阶段五冲内核与综合项目。跳级事倍功半。
3. **发行版选型**：三大系 Debian（apt）/ Red Hat（dnf）/ Arch（pacman）。Ubuntu 上手快、文档多，Debian 稳定保守，Rocky/AlmaLinux 承接 CentOS 8 停维护后的企业定位，Alpine 极简做容器基础镜像。
4. **环境载体**：虚拟机（快照回滚、随便折腾）、双系统（原生性能、有风险）、云主机（公网 IP、最像生产）、裸金属（权限最大）。
5. **工具链分工**：WSL2/Multipass/Vagrant/Packer 解决「快速获得 Linux 环境 + 可复现镜像」；SSH 是远程运维入口；Vim 是终端编辑标配；curl/wget/scp/rsync 是传输四件套；man/tldr 是离线查文档。

```text
能力模型四象限：
1. 系统底层 —— 文件系统、进程、内存、权限、内核参数、系统调用
2. 网络与安全 —— TCP/IP、路由、防火墙、DNS、SSH/TLS 加固
3. 运维工程 —— 日志、监控、定时任务、备份、高可用、自动化（Ansible/Terraform）
4. 容器与可观测 —— Docker/K8s、Prometheus/Grafana、eBPF 性能分析
```

```text
五阶段与先修关系：
阶段一 基础 —— 命令行与文件操作(02) + 用户权限(05) + 进程(07) —— 无先修，入口
阶段二 脚本 —— 文本三剑客(03) + Shell 编程(04) —— 依赖阶段一
阶段三 系统核心 —— 磁盘文件系统(06) + 内存(08) + 软件包(09) + systemd(10) + 网络(11) + 防火墙(12)
阶段四 运维 —— 日志监控(13) + 定时任务(14) + 性能调优(16) + 故障排查(17) + 高可用(19) + 网络服务(20)
阶段五 进阶 —— 系统调用与内核(15) + 存储(18) + 虚拟化容器(21) + 自动化(22) + 安全(23) + eBPF(24)
```

```text
发行版选型：
1. Ubuntu —— 文档最多、上手最快，个人开发与学习首选，LTS 每两年一版
2. Debian —— 稳定保守，服务器长期运行首选，软件版本偏旧但可靠
3. CentOS Stream —— Red Hat 的上游滚动版，定位介于 Fedora 与 RHEL 之间
4. Rocky / AlmaLinux —— CentOS 8 停维护后的社区承接者，1:1 兼容 RHEL
5. openSUSE —— SUSE 系，YaST 配置工具 + zypper 包管理
6. Alpine —— musl libc + busybox 极简，容器基础镜像首选（几 MB 体积）
```

## 工作原理

学习路径按「先修依赖驱动」运转：每个阶段的技能都建立在前一阶段之上，跳级会出现「会敲命令但不懂原理」的空心化。落地方式是「环境先行 + 项目驱动」——先在虚拟机/容器里搭好可反复折腾的环境，再用最小可运行命令验证每个知识点，最后用故障演练把知识变成排障能力。

```text
学习路径工作原理：
先修依赖 → 阶段递进 → 环境先行 → 项目驱动 → 故障演练
先修示例：学 Shell 前先懂命令行与管道；学防火墙前先懂 TCP/IP；学性能调优前先懂进程与内存。
```

## 配置文件解析

```shell
# ~/.bashrc：交互 shell 配置（别名 + 环境变量）
alias ll='ls -alF'
alias gs='git status'
alias k='kubectl'
export PATH="$HOME/bin:$PATH"

# 改默认 shell（bash -> zsh）
chsh -s /bin/zsh
```

```text
Shell 配置加载时机（关键，别写错位置）：
登录 shell（ssh 登录/开机）  → 读 ~/.bash_profile（Debian 常用 ~/.profile）
交互 shell（开新终端）      → 读 ~/.bashrc
非交互 shell（ssh host 'cmd'） → 通常两者都不读，环境变量要显式 source 或写 .profile
```

## 应用场景实战

### 场景一：从零配一台远程开发机（发行版 + SSH 免密 + 基础工具）

```shell
# 1. 用 Multipass 或云主机起一台 Ubuntu 22.04，然后 SSH 进去
ssh root@<server-ip>

# 2. 换国内软件源并更新（加快下载速度）
sed -i 's/archive.ubuntu.com/mirrors.aliyun.com/g' /etc/apt/sources.list
apt update && apt full-upgrade -y

# 3. 装基础工具链：编辑器 + 传输 + 复用 + 帮助
apt install -y vim curl wget rsync tmux tldr htop git

# 4. 建一个普通用户并配置密钥免密登录（别用 root 直接操作）
adduser deploy
usermod -aG sudo deploy
mkdir -p /home/deploy/.ssh && chmod 700 /home/deploy/.ssh
cp ~/.ssh/authorized_keys /home/deploy/.ssh/authorized_keys
chown -R deploy:deploy /home/deploy/.ssh
```

```shell
# 5. 从本地验证免密登录 + 传文件
ssh-copy-id deploy@<server-ip>     # 本地执行，部署公钥
ssh deploy@<server-ip>             # 免密登录成功
rsync -avz ./project/ deploy@<server-ip>:~/project/
```

### 场景二：搭一个容器化实验环境并做一次故障演练

```shell
# 1. 用容器起实验环境（练习命令不污染宿主机）
docker run -itd --name lab ubuntu:22.04 bash
docker exec -it lab bash

# 2. 容器内装工具并观察系统
apt update && apt install -y htop procps util-linux
df -h && free -h && ps aux

# 3. 主动制造「磁盘满」故障
dd if=/dev/zero of=/bigfile bs=1M count=1024
df -h /     # 观察容量变化

# 4. 练习排查：定位大文件 + 清理
du -sh /bigfile
rm -f /bigfile && df -h /   # 恢复

# 5. 演练结束后销毁容器（环境随手即弃）
docker rm -f lab
```

## 性能与调优

```text
开发环境效率调优（不是系统性能调优，是「让你干活更快」）：
1. 编译并行 —— make -j$(nproc) 用满 CPU 核数，源码编译快几倍
2. 软件源加速 —— 换国内镜像（aliyun/tuna），apt/dnf 下载从分钟级到秒级
3. 别名压缩高频操作 —— alias ll/gs/k，长命令敲一次就够
4. rsync 增量同步 —— 只传差异块，大目录镜像比 scp 全量快一个量级
5. 用 tldr 替代 man —— 直奔例子，查命令时间从 1 分钟缩到 10 秒
```

## 安全与权限

```text
开发环境安全要点：
1. SSH 密钥权限 —— 私钥 600、.ssh 目录 700，否则 sshd 拒绝信任（StrictModes）
2. 禁用 root 密码登录 —— PasswordAuthentication no + PermitRootLogin prohibit-password
3. 日常用普通用户 + sudo —— 别用 root 直接做实验，rm -rf 打错路径就起不来了
4. 实验进容器/虚拟机 —— 破坏性操作不碰生产机和唯一工作机
5. 私钥不落地多台 —— 每台机器/每个用途一把私钥，泄露可单独吊销
```

## 故障排查

```shell
# 1. SSH 连不上：先看网络通不通，再看 sshd 状态
ping <server-ip>
ss -tlnp | grep :22
systemctl status ssh

# 2. 免密登录配了还输密码：查权限
ls -ld ~/.ssh ~/.ssh/authorized_keys
# 目录要 700、文件要 600，不对就 chmod 修正

# 3. ssh host 'cmd' 报 command not found（交互登录却正常）
ssh user@host 'echo $PATH'
# 非交互不读 .bashrc，环境变量写到 .profile 或显式 source

# 4. 容器起不来 / 退出：看日志
docker logs lab
docker inspect lab | grep -i error
```

## 常见问题

```text
Q1: 该选哪个发行版开始学？
A: Ubuntu（文档多、上手快、apt 生态）。原理吃透后再横向对比 Red Hat 系（dnf/firewalld/SELinux）差异。

Q2: WSL2 和虚拟机学 Linux 哪个好？
A: 练系统原理（systemd/内核/网络）用虚拟机或容器，WSL2 只当轻量开发环境——它内核和文件系统与真实发行版有差异。

Q3: SSH 免密登录为什么还输密码？
A: 九成是权限问题——~/.ssh 要 700、authorized_keys 要 600，另一成是 sshd StrictModes 或公钥没追加对。

Q4: 环境变量写哪里才对？
A: 交互用写 .bashrc，登录用写 .bash_profile/.profile，非交互 ssh 执行命令两边都不读、要显式 source。

Q5: 实验环境用虚拟机还是容器？
A: 学 systemd/内核/网络用虚拟机（完整系统），练命令/服务/故障用容器（秒起秒毁、隔离干净）。
```

## 面试题

```text
1. 运维、SRE、平台工程师有什么区别？
   答：共享同一套 Linux 知识底座。运维偏部署维护与故障处理，SRE 用工程手段保证可靠性（SLO/容量/变更），平台工程师把底层能力抽象成内部平台（CICD/容器/监控/IaC）。

2. 学习 Linux 的合理路径是什么？
   答：命令行与系统基础 → Shell 与三剑客 → 系统核心（网络/存储/内存/systemd）→ 运维进阶（监控/自动化/高可用/容器）→ 内核与综合项目，每阶段配可运行实验。

3. 为什么生产服务器 SSH 要禁用 root 密码登录？
   答：密码可被爆破，root 权限无边界；改密钥认证 + 禁 root 密码 + 普通用户 sudo，缩小攻击面和误操作风险。

4. Ubuntu 和 CentOS/Rocky 的核心差异？
   答：包管理 apt/dpkg vs dnf/rpm，防火墙 ufw vs firewalld，安全模块 AppArmor vs SELinux，默认文件系统 ext4 vs XFS；命令层面 95% 相同。

5. 源码编译的典型三步走？
   答：./configure（探测环境生成 Makefile）→ make（编译）→ make install（安装），并行用 make -j$(nproc)。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 环境先行：先花一天把虚拟机/容器跑通，再开始学，边学边跑
2. 学习以项目驱动，每个知识点配一个最小可运行命令，不只看书
3. 优先学一套发行版（Ubuntu）吃透原理，再横向对比 Red Hat 系差异
4. SSH 一律用密钥认证并禁用 root 密码登录，养成生产安全习惯
5. 实验一律进容器或虚拟机，随手造故障练排查，别在唯一的生产机上试
6. 遇到命令先 man/tldr 查文档，再搜搜索引擎，培养离线排障能力
7. 把常用操作沉淀成别名和脚本，重复劳动自动化

### 踩坑记录

```text
坑 1：在 Windows 上用 WSL2 学 Linux，结果和服务器环境行为不一致
结论：本地跑通、服务器报错，排查半天发现是环境差异。
原因：WSL2 是精简内核 + 特殊文件系统，与真实发行版（systemd、网络栈）有差异。
解法：练系统原理用虚拟机或容器，WSL2 只当轻量开发环境用。

坑 2：SSH 免密登录配好了却一直要密码
结论：ssh-copy-id 执行成功，连接时仍提示输密码。
原因：~/.ssh 目录或 authorized_keys 权限不对（目录非 700、文件非 600），sshd 拒绝信任。
解法：chmod 700 ~/.ssh && chmod 600 ~/.ssh/authorized_keys，再检查 sshd 的 StrictModes。

坑 3：把环境变量写在 ~/.bashrc 里导致 ssh 执行命令找不到
结论：ssh host 'mycmd' 报 command not found，但交互登录有。
原因：非交互式 ssh 不读 .bashrc（读 .bash_profile 或直接不读），环境变量没加载。
解法：环境变量写进 ~/.bash_profile 或 ~/.profile，或在命令里显式 source。

坑 4：rsync 同步目录越同步越乱
结论：目标目录出现残留文件，删了的文件又出现。
原因：没用 --delete 参数，rsync 默认只增不删，源端删除的文件目标端还留着。
解法：做镜像同步用 rsync -avz --delete，确认源是权威再删。

坑 5：直接用 root 在服务器上做实验，误删系统文件
结论：一条 rm -rf 打错路径，系统起不来。
原因：root 权限无边界，实验和运维混在同一个账户。
解法：日常用普通用户 + sudo，实验进容器/虚拟机，生产操作前先备份。
```

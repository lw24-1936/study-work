## 概述

TCP/IP 协议栈是互联网的基础，Linux 网络的一切都建立在这套分层模型上：应用层（HTTP/SSH/DNS）→ 传输层（TCP/UDP）→ 网络层（IP/ICMP/ARP）→ 链路层（以太网）。理解这四层 + IP 地址与子网 + 路由 + ARP + ICMP，才能看懂 `ip addr`、`ip route`、`ping`、`ss` 这些命令背后的网络原理，排查「网络不通」时知道该从哪一层查起。

```text
TCP/IP 四层模型：
应用层   HTTP / SSH / DNS / FTP          （进程间通信、数据格式）
传输层   TCP / UDP                        （端口、连接、可靠/不可靠）
网络层   IP / ICMP / ARP                  （IP 地址、路由、寻址）
链路层   以太网 / WiFi / ARP              （MAC 地址、物理传输）
```

## 核心概念

1. **分层模型**：TCP/IP 四层（应用/传输/网络/链路），对应 OSI 七层的简化，逐层封装/解封装。
2. **IP 地址与子网**：网络层寻址标识，IPv4 32 位 / IPv6 128 位，子网掩码划分网络+主机部分。
3. **路由**：决定数据包往哪发，同网段直连、跨网段走默认网关，最长前缀匹配选路。
4. **ARP**：地址解析协议，链路层把 IP 映射到 MAC，只工作在广播域内。
5. **ICMP**：网络层控制消息协议，错误报告 + 诊断（ping/traceroute）。

```text
核心概念速查：
分层模型   应用/传输/网络/链路四层，逐层封装
IP + 子网  寻址 + 划网段，/24 掩码 255.255.255.0
路由       决定往哪发，同网段直连、跨网段走网关
ARP        IP → MAC，链路层广播解析
ICMP       控制消息，ping/traceroute 的基础
```

## 工作原理

数据发送的完整封装过程（自顶向下）：应用层数据 → 传输层加 TCP/UDP 头（含端口）→ 网络层加 IP 头（含源/目的 IP）→ 链路层加帧头（含源/目的 MAC），物理发送。接收时反向解封装。

跨网段通信需要 ARP + 路由配合：本机查路由表确定下一跳 → 下一跳在同一链路就用 ARP 解析下一跳的 MAC → 发帧。同网段直接 ARP 解析目标 MAC；跨网段则 ARP 解析网关 MAC，由网关转发。

```text
封装流程（发送）：
应用数据 → TCP/UDP 头 → IP 头 → 帧头（MAC）→ 物理发送

跨网段通信：
查路由表定下一跳 → ARP 解析下一跳 MAC → 发帧 → 网关转发
```

```text
# 实测（本机 IP 地址）
$ ip -4 addr show
lo          inet 127.0.0.1/8              # 回环，本机通信
wlp0s20f3   inet 192.168.1.167/24         # WiFi 网卡，/24 掩码
docker0     inet 172.17.0.1/16            # Docker 网桥
tailscale0  inet 100.71.112.119/32        # Tailscale VPN（/32 单机）
```

## 常用命令与配置

```shell
ip -4 addr show              # 看 IP 地址
ip route show                # 看路由表
ip neigh                     # 看 ARP 表（IP → MAC）
ping -c 4 8.8.8.8            # ICMP 测连通
traceroute 8.8.8.8           # 探测路径
ss -tlnp                     # 看传输层监听端口
ip link show                 # 看链路层网卡状态
```

## 配置文件解析

```text
网络相关配置文件：
/etc/hosts           本地域名 → IP 静态映射（应用层解析优先查）
/etc/resolv.conf     DNS 服务器（应用层域名解析）
/etc/nsswitch.conf   名字解析顺序（hosts: files dns）
/etc/sysctl.conf     内核网络参数（转发、调优）
/proc/sys/net/ipv4/ip_forward   IP 转发开关
```

```text
# 本机路由表（网络层）

172.17.0.0/16 dev docker0                # Docker 网络
```

## 应用场景实战

### 场景一：本机 IP 和网段排查

```shell
# 1. 看所有 IP 和掩码
ip -4 addr show
# 2. 看路由表（默认网关、直连网段）
ip route show
# 3. 看 ARP 表（同网段的 MAC 映射）
ip neigh
```

### 场景二：判断「网络不通」出在哪一层

```shell
# 1. 链路层：网卡有没有起来
ip link show
# 2. 网络层：IP 配了没、通不通
ip addr show && ping -c 2 192.168.1.1
# 3. 传输层：端口通不通
nc -zv 192.168.1.10 22
# 逐层排查：链路 → IP → 端口，定位到具体那一层
```

## 性能与调优

```text
1. MTU —— 链路层最大传输单元，调对避免分片（1500 以太网标准，隧道环境要调小）
2. 路由缓存 —— 内核路由缓存加速转发，一般不用手动管
3. ARP 表 —— 大二层网络 ARP 表项多，注意 ip neigh 清理无效表项
4. 网卡 offload —— 关闭不必要的 offload（tso/gro）排查疑难网络问题
5. 内核参数 —— sysctl 调 net.core/ipv4 参数（详见 16.5-网络性能）
```

```shell
ip link show wlp0s20f3       # 看 MTU
sysctl net.ipv4.ip_forward   # 看转发开关
sysctl net.ipv4.tcp_congestion_control   # 看拥塞算法
```

## 安全与权限

```text
1. ARP 欺骗 —— 伪造 ARP 应答劫持流量，内网用静态 ARP/交换机端口安全防护
2. ICMP 暴露 —— 禁 ping 隐藏主机，但也妨碍排障，权衡配置
3. 私有地址 —— 内网用私有段（192.168/10/172.16-31），NAT 后才上公网
4. IP 欺骗 —— 源 IP 可伪造，反制靠防火墙 + 反向路径过滤（rp_filter）
5. 分片攻击 —— 恶意分片绕过检测，防火墙要重组后再过滤
```

## 故障排查

### 网络不通的逐层排查

```shell
# 1. 链路层：网卡状态
ip link show | grep -E 'state|UP'
# 2. 网络层：IP 和路由
ip addr show && ip route show
# 3. 连通性：ping 网关
ping -c 2 192.168.1.1
# 4. 传输层：端口
ss -tlnp
# 5. 抓包深挖
tcpdump -i any -n icmp
```

## 常见问题

```text
Q1: ping 不通就是网络坏了吗？
A: 不一定，目标可能禁了 ICMP。用 nc -zv 测端口、curl 测服务，别只看 ping。

Q2: 同网段通、跨网段不通？
A: 路由问题——默认网关没配或配错，ip route 查默认路由。

Q3: ARP 表里的 MAC 不对怎么办？
A: ip neigh flush 清缓存，让内核重新 ARP 学习。

Q4: 子网掩码配错有什么后果？
A: 划错网络/主机边界，路由判断错误，导致部分 IP 通信异常。
```

## 面试题

```text
1. OSI 七层和 TCP/IP 四层怎么对应？
   答：TCP/IP 应用层 ≈ OSI 应用+表示+会话，传输层=传输层，网络层=网络层，链路层=数据链路+物理。

2. 数据包从应用层到网线经历了什么？
   答：逐层封装——应用数据加 TCP/UDP 头（端口）→ 加 IP 头（源/目的 IP）→ 加帧头（MAC），物理发送。

3. ARP 是干嘛的？跨网段通信用 ARP 吗？
   答：ARP 把 IP 解析成 MAC，只工作在链路层同网段。跨网段时 ARP 解析的是网关的 MAC，由网关转发。

4. 私有地址段有哪些？为什么内网用私有地址？
   答：192.168.x、10.x、172.16-31.x。内网用私有地址 + NAT 上公网，解决公网 IPv4 地址不足。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 网络不通按「链路 → IP → 路由 → 端口」自下而上排查，别乱猜
2. 看 IP/路由/ARP 统一用 ip 命令（ip addr/route/neigh），别用老的 ifconfig/route
3. 同网段通、跨网段不通，多半是路由/网关问题
4. ping 不通不代表网络不通——可能对方禁了 ICMP，用 nc 测端口
5. 理解私有地址段，内网服务别直接暴露公网 IP

### 踩坑记录

```text
坑 1：ping 不通就判断网络坏了
结论：ping 不通，但服务其实正常。
原因：目标禁了 ICMP（防火墙挡 ping），或 ICMP 被丢弃。
解法：用 nc -zv 测端口、curl 测 HTTP，别只看 ping。

坑 2：ifconfig 命令不存在
结论：新系统敲 ifconfig 报 command not found。
原因：ifconfig 已被 ip 命令取代，新发行版默认不装 net-tools。
解法：用 ip addr / ip link，或 apt install net-tools 装回老工具。

坑 3：同网段通、跨网段不通，排查错了方向
结论：能 ping 通同网段机器，ping 不通外网。
原因：路由问题——默认网关没配或配错。
解法：ip route 查默认路由，确认 default via 网关正确。

坑 4：ARP 表里的 MAC 不对导致通信异常
结论：某台机器突然连不上，ARP 表里 MAC 是错的。
原因：ARP 缓存了旧的错误映射（换网卡/IP 冲突）。
解法：ip neigh flush 清 ARP 缓存，重新学习。

坑 5：子网掩码配错导致部分机器不通
结论：掩码配错（如 /16 配成 /24），部分 IP 通信异常。
原因：掩码划错网络/主机边界，路由判断错误。
解法：确认掩码正确，同网段掩码必须一致。
```

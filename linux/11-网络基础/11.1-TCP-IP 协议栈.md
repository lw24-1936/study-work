## 概述

TCP/IP 协议栈是互联网的基础，Linux 网络的一切都建立在这套分层模型上：应用层（HTTP/SSH/DNS）→ 传输层（TCP/UDP）→ 网络层（IP/ICMP/ARP）→ 链路层（以太网）。理解这四层 + IP 地址与子网 + 路由 + ARP + ICMP，才能看懂 `ip addr`、`ip route`、`ping`、`ss` 这些命令背后的网络原理，排查「网络不通」时知道该从哪一层查起。

```text
TCP/IP 四层模型：
应用层   HTTP / SSH / DNS / FTP          （进程间通信、数据格式）
传输层   TCP / UDP                        （端口、连接、可靠/不可靠）
网络层   IP / ICMP / ARP                  （IP 地址、路由、寻址）
链路层   以太网 / WiFi / ARP              （MAC 地址、物理传输）
```

## OSI 与 TCP/IP 模型

OSI 是七层参考模型（理论框架），TCP/IP 是四层实际模型（互联网事实标准）。两者对应关系：TCP/IP 的应用层≈OSI 的应用+表示+会话层，传输层=传输层，网络层=网络层，链路层=数据链路+物理层。日常排查按「自下而上」——先看链路（网线/网卡）再看 IP（地址/路由）再看端口（服务），逐层排除。

```text
OSI 七层 vs TCP/IP 四层：
OSI                  TCP/IP
应用层   ┐
表示层   ├─ 应用层    应用层（HTTP/SSH/DNS）
会话层   ┘
传输层   ─────────   传输层（TCP/UDP）
网络层   ─────────   网络层（IP/ICMP/ARP）
数据链路层 ┐
物理层   ┘────────   链路层（以太网/WiFi）
```

## IP 地址与子网

IP 地址是网络层的寻址标识，分 IPv4（32 位，如 192.168.1.167）和 IPv6（128 位）。子网掩码（如 /24）划分「网络部分」和「主机部分」——同一子网的设备能直接通信，不同子网要经过路由器。私有地址段（192.168.x、10.x、172.16-31.x）用于内网，公网地址用于互联网。`ip addr` 查看本机 IP 和掩码。

```text
# 实测（本机 IP 地址）
$ ip -4 addr show
lo          inet 127.0.0.1/8              # 回环，本机通信
wlp0s20f3   inet 192.168.1.167/24         # WiFi 网卡，/24 掩码
docker0     inet 172.17.0.1/16            # Docker 网桥
tailscale0  inet 100.71.112.119/32        # Tailscale VPN（/32 单机）
```

```text
IP 地址要点：
1. IPv4 32 位 / IPv6 128 位，子网掩码划网络+主机
2. /24 = 掩码 255.255.255.0，同网段直接通，跨网段走路由
3. 私有段 192.168/10/172.16-31 用于内网，公网地址全局唯一
```

## 路由

路由决定「数据包往哪发」：同网段直接发，跨网段发到默认网关（路由器）。每台机器有路由表（`ip route`），按「最长前缀匹配」选路——更具体的路由优先。默认路由（default via 网关）是「不知道往哪发就发网关」。Linux 还能当路由器（IP 转发），转发其他机器的数据包。

```text
# 实测（本机路由表）
$ ip route show
default via 192.168.1.1 dev wlp0s20f3    # 默认网关（出外网走这里）
192.168.1.0/24 dev wlp0s20f3             # 本网段直连
172.17.0.0/16 dev docker0                # Docker 网络
172.18.0.0/16 dev br-49cfcba0160f        # Docker 网络
```

## ARP

ARP（地址解析协议）解决「知道 IP、不知道 MAC」的问题——同一链路内，设备用 MAC 地址通信，ARP 把 IP 映射到 MAC。发数据前查 ARP 表（`ip neigh`），查不到就广播「谁的 IP 是 X？」，目标机应答后缓存。ARP 表缓存了 IP→MAC 的映射，用 `ip neigh` 查看。ARP 只工作在链路层（同网段），跨网段交给路由。

```shell
ip neigh                    # 查看 ARP 表（IP → MAC 映射）
ip neigh show 192.168.1.1   # 查网关的 MAC
arp -a                      # 老命令，等价 ip neigh
```

## ICMP

ICMP 是网络层的「控制消息」协议，用于错误报告和诊断——ping 用的就是 ICMP Echo 请求/应答，traceroute 用 ICMP（或 UDP）探测路径。ICMP 还报告「目标不可达」「超时」等错误。理解 ICMP 才能看懂 ping 的「request timeout」和 traceroute 的每一跳。注意：有些服务器/防火墙禁 ICMP（禁 ping），所以 ping 不通不一定网络不通。

```shell
ping -c 4 192.168.1.1       # ICMP Echo 测试连通性
ping -c 4 8.8.8.8           # 测外网连通
traceroute 8.8.8.8          # ICMP/UDP 探测路径
```

```text
ICMP 常见用途：
1. ping —— ICMP Echo 请求/应答，测连通和延迟
2. traceroute —— 探测数据包经过的每一跳
3. 错误报告 —— 目标不可达、超时、重定向
```

## 应用场景实战

### 场景一：本机 IP 和网段排查

```shell
# 1. 看所有 IP 和掩码
ip -4 addr show
# 2. 看路由表（默认网关、直连网段）
ip route show
# 3. 看 ARP 表（同网段的 MAC 映射）
ip neigh
```

### 场景二：判断「网络不通」出在哪一层

```shell
# 1. 链路层：网卡有没有起来
ip link show
# 2. 网络层：IP 配了没、通不通
ip addr show && ping -c 2 192.168.1.1
# 3. 传输层：端口通不通
nc -zv 192.168.1.10 22
# 逐层排查：链路 → IP → 端口，定位到具体那一层
```

## 最佳实践与踩坑记录

### 最佳实践

1. 网络不通按「链路 → IP → 路由 → 端口」自下而上排查，别乱猜
2. 看 IP/路由/ARP 统一用 ip 命令（ip addr/route/neigh），别用老的 ifconfig/route
3. 同网段通、跨网段不通，多半是路由/网关问题
4. ping 不通不代表网络不通——可能对方禁了 ICMP，用 nc 测端口
5. 理解私有地址段，内网服务别直接暴露公网 IP

### 踩坑记录

```text
坑 1：ping 不通就判断网络坏了
结论：ping 不通，但服务其实正常。
原因：目标禁了 ICMP（防火墙挡 ping），或 ICMP 被丢弃。
解法：用 nc -zv 测端口、curl 测 HTTP，别只看 ping。

坑 2：ifconfig 命令不存在
结论：新系统敲 ifconfig 报 command not found。
原因：ifconfig 已被 ip 命令取代，新发行版默认不装 net-tools。
解法：用 ip addr / ip link，或 apt install net-tools 装回老工具。

坑 3：同网段通、跨网段不通，排查错了方向
结论：能 ping 通同网段机器，ping 不通外网。
原因：路由问题——默认网关没配或配错。
解法：ip route 查默认路由，确认 default via 网关正确。

坑 4：ARP 表里的 MAC 不对导致通信异常
结论：某台机器突然连不上，ARP 表里 MAC 是错的。
原因：ARP 缓存了旧的错误映射（换网卡/IP 冲突）。
解法：ip neigh flush 清 ARP 缓存，重新学习。

坑 5：子网掩码配错导致部分机器不通
结论：掩码配错（如 /16 配成 /24），部分 IP 通信异常。
原因：掩码划错网络/主机边界，路由判断错误。
解法：确认掩码正确，同网段掩码必须一致。
```

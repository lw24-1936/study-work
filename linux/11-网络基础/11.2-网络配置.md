## 概述

网络配置回答「网卡怎么配 IP、怎么上网」：用 `ip` 命令临时配（立即生效、重启失效），或写网卡配置文件持久化（netplan / NetworkManager / systemd-networkd）。地址来源分静态 IP（手动指定，服务器用）和 DHCP（自动获取，客户端用）。

现代 Linux 的网络配置被三个层次的管理工具覆盖：**iproute2**（`ip` 命令，直接操作内核）、**NetworkManager**（守护进程式自动管理，桌面/通用默认）、**systemd-networkd**（轻量声明式，服务器/容器默认）。Ubuntu 用 **netplan** 作为「声明式入口」，netplan 自己不碰内核，而是把 YAML 翻译给后端（NetworkManager 或 systemd-networkd）执行。Red Hat 系用 NetworkManager（nmcli/nmtui）+ ifcfg 配置文件。

理解「配置 → 后端 → 内核」这条生效链，才能解决「改了 IP 不生效」「重启配置就丢」这类经典问题：配置写在哪一层、有没有 apply、后端有没有接管这张网卡，三个问题一次定位。

```text
网络配置层级：
1. ip 命令          临时配置（立即生效，重启失效）
2. 网卡配置文件      持久化（netplan / NetworkManager / ifcfg）
3. 静态 IP          手动指定，服务器常用
4. DHCP             自动获取，客户端/临时环境常用
5. 网络管理器        后端执行者（NetworkManager / systemd-networkd）
```

本机环境：Ubuntu 24.04.4 LTS，netplan renderer 为 NetworkManager，WiFi 网卡 wlp0s20f3 由 DHCP 获取 192.168.1.167/24（网关 192.168.1.1），另有 docker0（172.17.0.1/16）、多个 br-* 网桥、tailscale0（100.71.112.119/32）等虚拟网卡。全篇实测输出均来自该机器。

## 核心概念

1. **网卡（interface）**：网络接口，是内核里可配地址/路由的对象。命名有规律：`en`=有线以太网、`wl`=无线、`lo`=回环、`docker0`/`br-*`=网桥（Docker 创建）、`veth*`=虚拟以太网对、`tailscale0`=VPN 隧道。predictable naming（enp59s0 这种带总线位置的）取代了老的 eth0。
2. **ip 命令体系**：iproute2 的工具，`ip addr`（地址）、`ip link`（链路）、`ip route`（路由）、`ip neigh`（邻居/ARP）。配置**临时生效**，重启丢失。
3. **静态 IP vs DHCP**：静态 IP 四要素（地址/掩码/网关/DNS）手动指定，地址固定，服务器必备；DHCP 自动获取（含租约续期），即插即用，客户端环境默认。
4. **netplan**：Ubuntu 的声明式网络配置层（YAML），本身不执行，把配置翻译给 NetworkManager 或 systemd-networkd。
5. **NetworkManager / systemd-networkd**：真正的后端执行者。NM 功能全（WiFi 漫游、VPN、多连接切换、DBus 接口），桌面默认；networkd 轻量、无状态、声明式，服务器/容器默认。
6. **主机名与 hosts**：`hostnamectl` 设置主机名；`/etc/hosts` 是本地静态域名映射，解析优先级高于 DNS。
7. **DNS 解析链**：`/etc/nsswitch.conf` 决定顺序（files → dns），`/etc/resolv.conf` 指向上游（Ubuntu 上是 systemd-resolved 的 stub 127.0.0.53）。
8. **bond / VLAN / 策略路由**：多网卡绑定（冗余/带宽）、VLAN 子接口（一个物理口多个逻辑网段）、多路由表按规则选路。

```text
静态 IP 四要素：
1. IP 地址   192.168.1.100
2. 子网掩码  /24（255.255.255.0）
3. 默认网关  192.168.1.1
4. DNS       8.8.8.8（可多个，逗号分隔）
```

```text
配置工具对照表：
工具/体系        作用            生效方式          适用发行版
ip 命令          直接改内核      立即、不持久     所有
netplan          声明式 YAML      apply 时生效      Ubuntu
NetworkManager    守护进程管理    即时 + 持久化     通用（桌面默认）
systemd-networkd  声明式 .network 重启服务生效    服务器/容器
nmcli/nmtui       NM 的命令行/TUI 即时 + 持久化    Red Hat 系默认
ifcfg 文件        传统配置文件     重启网络生效     RHEL/CentOS 7 及以前
```


## 工作原理

### 配置生效路径

```text
ip 命令 ──────────────→ 内核 netlink（临时，重启丢）
netplan YAML ──apply──→ 后端（NM / networkd）──→ 内核（持久化）
nmcli/ifcfg ──────────→ NetworkManager ────────→ 内核（持久化）
DHCP：网卡 ──广播──→ DHCP 服务器（租约写入 /var/lib/dhcp/ 或 journald）
```

1. **ip 命令**：直接通过 netlink 套接字调内核接口，改地址/路由/网卡状态，不写任何配置文件——所以重启后 NetworkManager/networkd 按自己的配置重新设置，临时改动被覆盖。
2. **netplan**：Ubuntu 的声明式层。`netplan apply` 时读取 `/etc/netplan/*.yaml`，生成后端（NetworkManager 或 networkd）的配置并让其重新加载。renderer 字段决定翻译给谁。
3. **NetworkManager**：守护进程持续监听网卡事件（插线、WiFi 信号），自动激活/切换连接；每个「连接」是一套完整配置（地址/DNS/路由），nmcli 管理。
4. **DHCP（DORA 四步）**：Discover（客户端广播找服务器）→ Offer（服务器广播/单播提供租约）→ Request（客户端广播确认要哪份租约）→ ACK（服务器确认）。之后进入租约期，到期前约一半时间开始续租（单播 Renew）。

```text
DHCP 四步：
Discover  客户端广播：谁有 IP 分我？
Offer     服务器：我出 192.168.1.167/24，网关 .1，DNS .1，租期 86400s
Request   客户端广播：我要 Offer 里那个
ACK       服务器：确认，租约生效
```

### DNS 解析链（Ubuntu systemd-resolved）

```text
应用进程 → getaddrinfo()
  → nsswitch.conf 的 hosts 行：files mdns4_minimal [NOTFOUND=return] dns
  → ① /etc/hosts（files）命中就用，不查 DNS
  → ② 查不到再走 DNS：/etc/resolv.conf（stub 127.0.0.53）
  → ③ systemd-resolved 按网卡查上游（本机：192.168.1.1，来自 DHCP）
```

`/etc/resolv.conf` 在 Ubuntu 上是指向 `/run/systemd/resolve/stub-resolv.conf` 的符号链接，里面只有 `nameserver 127.0.0.53`——真正上游由 systemd-resolved 按「哪个网卡有 DefaultRoute」动态决定（`resolvectl status` 可看）。手改 /etc/resolv.conf 会被覆盖，正确姿势是改 netplan 的 nameservers 或 `resolvectl dns`。

### 策略路由原理

普通路由表一张（main）不够用（双网卡双网关、VPN 分流）时，用**多路由表 + ip rule 规则**：内核按 `ip rule` 的优先级从高到低逐条匹配（source 地址/fwmark/tos 等），命中后去指定的路由表（main/table 100/...）查路由。

```text
# 实测（本机）——ip rule show：注意优先级数字，小优先
$ ip rule show
0:      from all lookup local        # 最高优先级，local 表（本机地址）
5210:   from all fwmark 0x80000/0xff0000 lookup main
5230:   from all fwmark 0x80000/0xff0000 lookup default
5250:   from all fwmark 0x80000/0xff0000 unreachable
5270:   from all lookup 52           # Tailscale 的策略路由规则（按来源分流）
32766:  from all lookup main         # 常规路由表
32767:  from all lookup default
# 优先级 0-32767，数字小的先匹配；fwmark 是打标记分流（防火墙配合）
```

### IPv6 配置：SLAAC vs DHCPv6

- **SLAAC（无状态）**：路由器周期发 Router Advertisement（RA，含前缀/网关），主机自己用 EUI-64/隐私扩展生成地址，无需 DHCP 服务器。默认开启（netplan `accept-ra: true` / NetworkManager 默认）。
- **DHCPv6（有状态）**：类似 IPv4 DHCP，服务器分配地址，常用于企业（要记录地址分配）。
- 两者可共存：RA 通告前缀 + DHCPv6 下发 DNS 等附加信息。

```text
# 实测（本机）——ip -br addr：wlp0s20f3 上 IPv4/IPv6 共存
$ ip -br addr
lo               UNKNOWN  127.0.0.1/8 ::1/128
enp59s0          DOWN
wlp0s20f3        UP       192.168.1.167/24 2408:8226:5a11:890:6e66:a1b4:ec81:39cb/64 ...
tailscale0       UNKNOWN  100.71.112.119/32 fd7a:115c:a1e0::cc37:7078/128 ...
# 一个网卡多个地址：IPv4 一个 + IPv6 多个（SLAAC 隐私地址会生成多个，轮换保护隐私）
```

## 常用命令与配置

```shell
# ip 命令体系（临时配置）
ip addr                            # 看所有 IP
ip -br addr                        # 简洁版（一行一个网卡）
ip link                            # 看网卡状态
ip link set wlp0s20f3 down         # 停用网卡
ip link set wlp0s20f3 up           # 启用网卡
ip addr add 192.168.1.200/24 dev enp59s0    # 临时加 IP
ip addr del 192.168.1.200/24 dev enp59s0    # 删 IP
ip route add default via 192.168.1.1 dev enp59s0   # 临时加默认路由
ip route del default                            # 删默认路由

# NetworkManager（nmcli）
nmcli device status                 # 看设备状态
nmcli connection show               # 看连接配置
nmcli device wifi list              # 看 WiFi 信号
nmcli connection up <name>          # 启用连接
nmcli connection modify <name> ipv4.method manual ipv4.addresses 192.168.1.100/24
nmcli connection modify <name> ipv4.gateway 192.168.1.1 ipv4.dns 8.8.8.8
nmcli connection down <name> && nmcli connection up <name>   # 应用修改

# netplan（Ubuntu）
netplan apply                      # 应用配置（语法错误会回滚/报错）
netplan try                        # 试用配置，超时自动回滚（远程操作神器）
netplan generate                   # 只生成后端配置不应用

# 主机名 / DNS
hostnamectl set-hostname my-server # 设置主机名（持久化）
resolvectl status                  # 看 systemd-resolved 状态
resolvectl dns                      # 看各网卡上游 DNS
resolvectl flush-caches             # 清 DNS 缓存
```

Red Hat 系差异对照：

| 操作 | Ubuntu（netplan） | CentOS/RHEL（NetworkManager + ifcfg） |
|---|---|---|
| 静态 IP | netplan YAML + `netplan apply` | `nmcli connection modify` 或改 ifcfg 文件 + `nmcli con up` |
| 查看配置 | `cat /etc/netplan/*.yaml` | `nmcli connection show <name>` |
| 重启网络 | `netplan apply` | `systemctl restart NetworkManager` / `nmcli con reload` |
| 防火墙 | ufw（`ufw allow 22`） | firewalld（`firewall-cmd --add-port=22/tcp --permanent`） |
| 包管理 | apt | yum/dnf |

## 配置文件解析

### netplan YAML（Ubuntu）详解

netplan 配置在 `/etc/netplan/*.yaml`（多个文件按字母序合并），核心字段：

| 字段 | 作用 | 示例 |
|---|---|---|
| `network.version` | 固定 2 | `version: 2` |
| `network.renderer` | 后端：networkd / NetworkManager | `renderer: NetworkManager` |
| `ethernets/wifis/bridges` | 网卡类型分组，键是网卡名或 match | `ethernets: {enp59s0: {...}}` |
| `dhcp4/dhcp6` | 是否 DHCP | `dhcp4: true` |
| `addresses` | 静态 IP 列表（可多个，含 IPv6） | `addresses: [192.168.1.100/24]` |
| `routes` | 静态路由 | `routes: [{to: default, via: 192.168.1.1}]` |
| `nameservers` | DNS 与搜索域 | `nameservers: {addresses: [8.8.8.8], search: [example.com]}` |
| `mtu` | 网卡 MTU | `mtu: 1400` |
| `match` | 按属性匹配网卡（不用固定名） | `match: {macaddress: "34:41:5d:f2:6a:52"}` |

```yaml
# netplan 静态 IP 配置示例（/etc/netplan/01-static.yaml）
network:
  version: 2
  renderer: networkd          # 服务器用 networkd，桌面用 NetworkManager
  ethernets:
    enp59s0:
      dhcp4: no               # 关掉 DHCP
      addresses: [192.168.1.100/24]
      routes:
        - to: default
          via: 192.168.1.1
      nameservers:
        addresses: [8.8.8.8, 114.114.114.114]
        search: [example.com]
      mtu: 1500
```

```text

```

### Red Hat 系：ifcfg 文件（传统）


## 应用场景实战

### 场景一：临时给网卡加 IP（立即生效、重启失效）

适合测试、多 IP 场景（同网卡绑多个 IP 跑多个服务）：

```shell
# 1. 临时加 IP
ip addr add 192.168.1.200/24 dev enp59s0
# 2. 验证（能看到新 IP 和原来的共存）
ip -br addr show enp59s0
# 3. 测试服务监听新地址
ss -tlnp | grep 192.168.1.200
# 4. 用完删除（重启也会自动消失）
ip addr del 192.168.1.200/24 dev enp59s0
# 注意：加 IP 后内核会自动生成一条直连路由（192.168.1.0/24），删 IP 时一并消失
```

### 场景二：Ubuntu netplan 配置静态 IP（服务器）

```shell
# 1. 先确认后端：桌面 NetworkManager，服务器 networkd
cat /etc/netplan/*.yaml | grep renderer
# 2. 备份并写配置（见上文 01-static.yaml 示例）
sudo cp /etc/netplan/01-network-manager-all.yaml /etc/netplan/01-network-manager-all.yaml.bak
sudo vim /etc/netplan/01-static.yaml
# 3. 先 try 再 apply（远程操作必用 try，失败自动回滚）
sudo netplan try
# 4. 确认生效
ip -4 addr show && ip route show
# 5. 持久化验证：重启后地址还在（systemctl reboot 或 ip link set down/up 测试）
```

### 场景三：Red Hat 系用 nmcli 配置静态 IP

```shell
# 1. 查看现有连接名（默认一般是网卡名）
nmcli connection show
# 2. 改成静态 IP（modify 只改配置，需要 up 重新激活）
sudo nmcli connection modify enp59s0 \
  ipv4.method manual \
  ipv4.addresses 192.168.1.100/24 \
  ipv4.gateway 192.168.1.1 \
  ipv4.dns "8.8.8.8 114.114.114.114" \
  connection.autoconnect yes
# 3. 重新激活（先 down 再 up，注意远程操作会断连）
sudo nmcli connection down enp59s0 && sudo nmcli connection up enp59s0
# 4. 验证
ip -4 addr show enp59s0
```

### 场景四：多网卡双网关——策略路由

场景：服务器两张网卡，eth0 上办公网（网关 .1），eth1 上业务网（网关 10.0.0.1），要求「来源是 10.0.0.x 的流量走 eth1，其他走 eth0」：

```shell
# 1. 建独立路由表（编辑 /etc/iproute2/rt_tables，加一行）
echo "100 business" | sudo tee -a /etc/iproute2/rt_tables
# 2. 往 business 表写路由
sudo ip route add default via 10.0.0.1 dev eth1 table 100
# 3. 加规则：来源 10.0.0.0/24 的流量查 business 表
sudo ip rule add from 10.0.0.0/24 table 100
# 4. 验证
ip route show table 100
ip rule show
# 5. 持久化：写进 netplan（routes/ routing-policy）或 NM 连接配置
```

```yaml
# netplan 持久化版本（多网卡 + 策略路由）
network:
  version: 2
  renderer: networkd
  ethernets:
    eth0:
      dhcp4: true
    eth1:
      addresses: [10.0.0.2/24]
      routes:
        - to: default
          via: 10.0.0.1
          table: 100
      routing-policy:
        - from: 10.0.0.0/24
          table: 100
```

### 场景五：VLAN 子接口配置

场景：一个物理口接交换机 trunk，要同时走 VLAN 10（办公）和 VLAN 20（服务器）：

```shell
# Ubuntu 需要先装 vlan 支持
sudo apt install vlan && sudo modprobe 8021q
# 临时创建 VLAN 子接口（命名 网卡.VID）
ip link add link enp59s0 name enp59s0.10 type vlan id 10
ip addr add 192.168.10.2/24 dev enp59s0.10
ip link set enp59s0.10 up
# 验证
ip -br addr | grep enp59s0
```

```yaml
# netplan 持久化版本
network:
  version: 2
  renderer: networkd
  ethernets:
    enp59s0: {}
  vlans:
    enp59s0.10:
      id: 10
      link: enp59s0
      addresses: [192.168.10.2/24]
```

Red Hat 系：`nmcli connection add type vlan con-name vlan10 dev enp59s0 id 10 ipv4.method manual ipv4.addresses 192.168.10.2/24`，或 ifcfg-enp59s0.10（`VLAN=yes`）。

### 场景六：网卡 bonding（链路聚合）

场景：两块千兆网卡绑成 bond0，交换机支持 LACP 就 802.3ad，不支持就 active-backup：

```yaml
# netplan 持久化版本（mode 4 = 802.3ad 动态聚合）
network:
  version: 2
  renderer: networkd
  ethernets:
    enp59s0: {}
    enp60s0: {}
  bonds:
    bond0:
      interfaces: [enp59s0, enp60s0]
      addresses: [192.168.1.100/24]
      parameters:
        mode: 802.3ad        # 或 active-backup
        mii-monitor-interval: 100
        lacp-rate: fast
      routes:
        - to: default
          via: 192.168.1.1
```

```shell
# Red Hat 系 nmcli 版
nmcli connection add type bond con-name bond0 ifname bond0 mode 802.3ad \
  ipv4.method manual ipv4.addresses 192.168.1.100/24 ipv4.gateway 192.168.1.1
nmcli connection add type ethernet con-name bond0-port1 ifname enp59s0 master bond0
nmcli connection add type ethernet con-name bond0-port2 ifname enp60s0 master bond0
nmcli connection up bond0
# 验证：cat /proc/net/bonding/bond0 看 active slave 与模式
```

bond 模式对比（常用 4 种）：

| 模式 | 名称 | 特点 | 适用 |
|---|---|---|---|
| mode 1 | active-backup | 一主一备，故障切换 | 只求冗余，交换机无要求 |
| mode 4 | 802.3ad (LACP) | 动态聚合，带宽叠加 | 交换机支持 LACP，双千兆变约 2G |
| mode 0 | balance-rr | 轮询逐包分发 | 交换机需支持，兼容性差 |
| mode 6 | balance-alb | 自适应负载均衡 | 无需交换机支持，但开销大 |

## 性能与调优

1. **MTU 与巨型帧**：机房内部存储/备份网络整链路支持时用 MTU 9000，大块传输吞吐提升明显（减少分片与帧头开销）；上外网/隧道一律 1500 或更低（WireGuard 建议 1280-1420）。netplan 里 `mtu: 9000` 直接配。
2. **offload 卸载**：默认开启 TSO/GRO 等，省 CPU；抓包排查疑难问题时 `ethtool -K enp59s0 tso off gro off` 关闭对比（见 [[11.5-网络诊断工具]]）。
3. **bonding**：高吞吐/高可用场景用 802.3ad（交换机配合），只求冗余用 active-backup；mode 0（rr）在部分交换机上会乱序，慎用。
4. **DNS 就近**：配置延迟低、距离近的 DNS（`dig @8.8.8.8 example.com` 对比时延），缓存策略（systemd-resolved 默认缓存，`resolvectl statistics` 看命中率）。
5. **双栈注意**：IPv4/IPv6 都配（本机 wlp0s20f3 同时有 192.168.1.167/24 和 2408:8226:.../64），只配一个会导致依赖另一栈的服务连不上（比如某些应用默认走 IPv6 但没配）。
6. **内核缓冲**：高并发服务器调 `net.core.somaxconn`、`net.core.rmem_max/wmem_max`、`net.ipv4.tcp_fin_timeout` 等（详见 [[15.3-内核参数与伪文件系统]] 和 [[16.5-网络性能]]）。
7. **路由表规模**：多网卡/多租户场景用独立路由表（rt_tables）隔离，避免 main 表互相覆盖。

## 安全与权限

1. **远程改 IP 风险**：改错 IP/网关会立刻断连且 SSH 无响应。正确姿势：① 用 `netplan try`（超时自动回滚）；② 或「临时加新 IP + 测试 + 删旧 IP」；③ 有带外管理（console/IPMI）兜底。
2. **只用一个管理器**：NetworkManager 和 systemd-networkd 同时管同一张网卡会互相覆盖配置，必须二选一（netplan 的 renderer 就是指定这个）。
3. **DHCP 信任**：内网出现恶意/误配 DHCP 服务器可下发恶意网关/DNS（中间人）。防护：交换机 DHCP Snooping（只信任指定端口）、生产网用静态 IP 或受控 DHCP。
4. **配置权限**：网卡配置文件必须 root 属主（netplan/ifcfg 默认 644 root），普通用户不能改网络配置（改 /etc/hosts 也需要 root）；`ip` 命令改配置需要 CAP_NET_ADMIN。
5. **IPv6 按需启用**：不需要 IPv6 的环境可关闭（`net.ipv6.conf.all.disable_ipv6=1` 或 netplan 不配 IPv6），减少 RA/NDP 相关攻击面；但关闭前确认业务不依赖 IPv6。
6. **WiFi 安全**：生产 WiFi 用 WPA2/WPA3 企业认证（802.1X），别用 WEP/共享密码；netplan 配置文件里有明文 WiFi 密码，注意文件权限与备份安全。
7. **防火墙联动**：改完网络配置后检查防火墙（ufw/firewalld）规则是否与新网段匹配，避免「网络通了但防火墙挡了」。

## 故障排查

### 案例一：改了配置不生效 / 断网

```shell
# 1. 确认谁在管这张网卡（关键！两个后端会打架）
systemctl is-active NetworkManager systemd-networkd
nmcli device status                    # NM 视角
# 2. 看当前生效的地址与后端认为的地址是否一致
ip addr show
nmcli connection show
# 3. netplan 语法检查（先 try 再 apply）
sudo netplan try                       # 语法错误会提示并回滚
sudo netplan apply
# 4. 看后端日志
journalctl -u NetworkManager -n 50
journalctl -u systemd-networkd -n 50
# 5. 终极检查：配置写对了但网卡被别的服务接管？
#    检查 /run/systemd/network/ 下有没有 networkd 生成的配置，NM 是否 ignore 了网卡
```

### 案例二：DHCP 获取不到 IP

```shell
# 1. 网卡状态：没 up 就不可能拿到地址
ip link show enp59s0
# 2. 手动触发一次 DHCP 看报错
sudo dhclient -v enp59s0              # 老工具，看 Debug 输出
# 3. 抓包看 DORA 卡在哪一步
sudo tcpdump -i enp59s0 -n port 67 or port 68
#   只看到 Discover 没 Offer：DHCP 服务器不在/被隔离/VLAN 不通
#   有 Offer 没 Request：客户端不认（网卡被别的服务占用）
# 4. 看租约记录
cat /var/lib/dhcp/dhclient.leases     # 或 journalctl | grep -i dhcp
# 5. systemd-networkd 环境看 journalctl -u systemd-networkd
```

### 案例三：DNS 解析失败

```shell
# 1. 分清是「网络不通」还是「DNS 不通」：ping IP 通、ping 域名不通 = DNS 问题
ping -c 2 192.168.1.1
ping -c 2 github.com                  # 域名解析失败会报 unknown host
# 2. 用 dig 直接问上游（绕过系统缓存）
dig @8.8.8.8 github.com               # 通：上游 OK，问题在本地解析链
dig @192.168.1.1 github.com           # 不通：本地 DNS 服务器问题
# 3. 查本地解析链
resolvectl status                     # 看当前上游是谁
resolvectl query github.com           # 问 systemd-resolved
# 4. 看 /etc/hosts 是否被污染/写错（files 优先级高于 DNS！）
cat /etc/hosts
# 5. 缓存问题就 flush
sudo resolvectl flush-caches
```

### 案例四：多网卡路由冲突

```shell
# 现象：双网卡后外网突然不通，或访问内网走错网卡
ip route show                         # 看有没有多条 default
# 两条 default（metric 不同）：小的生效，检查是否写错
# 直连路由被覆盖：两个网卡网段重叠会互相顶
# 解法：给次要网卡加 metric，或用策略路由（见场景四）
ip route add default via 192.168.1.1 dev wlp0s20f3 metric 100
# 或 netplan 里 routes 写 metric 字段；NM 里 connection.autoconnect 优先级
```

### 案例五：网卡名变了导致配置失效

```shell
# 现象：重启后 IP 没了，因为网卡名从 eth0 变成 enp59s0
# 原因：predictable naming 按硬件位置命名，插槽/PCI 变化名字就变
# 解法1：netplan 用 match macaddress 而不是网卡名
# 解法2：改 udev 规则固定名（/etc/udev/rules.d/70-persistent-net.rules）
# 解法3：RHEL 系内核参数 net.ifnames=0 biosdevname=0 回到 eth0 命名
ip link                                  # 先确认现在的名字
cat /sys/class/net/*/address             # 用 MAC 找物理网卡
```

## 常见问题

```text
Q1: ip addr 配的 IP 重启后没了？
A: 正常。ip 命令是临时配置，只改内核不改文件。持久化要写
   netplan（Ubuntu）/nmcli 或 ifcfg（Red Hat），并确保网络服务在开机时应用。

Q2: 改 netplan 不生效？
A: 三个检查点：① 有没有 netplan apply（改了不 apply 等于没改）；
   ② renderer 与实际后端是否一致（netplan 只翻译给 renderer 指定的后端）；
   ③ 网卡是否被别的管理器接管（NetworkManager 和 networkd 同时管一张卡会打架）。

Q3: 远程改 IP 断连了怎么办？
A: 改错 IP/网关导致。预防优先：netplan try（超时自动回滚）、临时加新 IP 测试后删旧 IP、
   带外管理（IPMI/console）。真断了只能去机房/带外恢复，或等 DHCP 租约过期重新获取。

Q4: 静态 IP 和 DHCP 怎么选？
A: 服务器/固定服务用静态 IP（地址不变，防火墙、DNS 记录、监控都依赖固定地址）；
   客户端、临时环境、笔记本用 DHCP（即插即用）。企业环境可用 DHCP 静态绑定（按 MAC
   固定分配），兼具两者优点。

Q5: 为什么我改了 /etc/resolv.conf 重启就还原？
A: Ubuntu 上 /etc/resolv.conf 是指向 systemd-resolved stub 的符号链接，被动态管理。
   正确做法：改 netplan 的 nameservers 后 netplan apply；或 resolvectl dns <网卡> <IP>；
   或换掉符号链接改用静态 resolv.conf（systemd-resolved 的 modes 决定）。

Q6: 网卡名怎么是 enp59s0 这种怪名字？能改回 eth0 吗？
A: 这是 predictable naming（按 PCI 总线位置命名，便于多网卡识别稳定），新系统默认。
   能改回 eth0（内核参数 net.ifnames=0），但不建议——多网卡服务器会因枚举顺序
   不确定导致配置错乱。用 MAC match 或 udev 固定规则更靠谱。

Q7: IPv6 要不要配/要不要关？
A: 需要 IPv6 业务就配（本机 SLAAC 自动就有）；不需要就明确关闭
   （net.ipv6.conf.all.disable_ipv6=1），别留半吊子状态。关闭前确认没有依赖
   IPv6 的服务（有些 DNS 只返回 AAAA 记录时应用会卡）。

Q8: 网卡能同时有多个 IP 吗？
A: 能，一张网卡可以绑多个 IPv4/IPv6 地址（ip addr add 多次，或 netplan addresses 列表），
   内核为每个地址自动生成直连路由。多 IP 常用于：一个网卡跑多个虚拟主机、平滑切换 IP。
```

## 面试题

```text
1. 静态 IP 要配哪四个东西？
   答：IP 地址、子网掩码（网络前缀）、默认网关、DNS 服务器。
   少配网关只能同网段通信；少配 DNS 域名解析失败；掩码错会导致网段判断错乱。

2. ip 命令和 ifconfig 的区别？
   答：ip 是 iproute2 的现代工具，功能全（addr/link/route/neigh 统一语法）、
   支持 IPv6 原生、输出可读性好；ifconfig 是老的 net-tools，已废弃，
   新系统默认不装，不支持路由表/策略路由等新特性。

3. NetworkManager 和 systemd-networkd 的区别？
   答：NM 功能全：自动检测插线/WiFi 漫游、多连接切换、DBus/图形界面/nmcli 管理、
   桌面默认；networkd 轻量、声明式（.network 文件）、无状态、启动快，
   服务器/容器环境默认。两者不能同时管同一张网卡。

4. DHCP 获取 IP 的完整流程？
   答：DORA 四步：Discover（客户端广播找服务器）→ Offer（服务器提供租约：
   地址/网关/DNS/租期）→ Request（客户端广播确认）→ ACK（服务器确认生效）。
   之后租期过半开始续租（Renew），续租失败到期 IP 被回收。

5. netplan 的工作原理？为什么叫「声明式」？
   答：netplan 不直接操作内核，它读取 /etc/netplan/*.yaml 的声明式配置，
   netplan apply 时翻译成后端（NetworkManager 或 systemd-networkd）的配置并应用。
   「声明式」= 只描述「最终想要的状态」（哪个网卡什么 IP），
   不用管具体执行步骤，执行由 renderer 指定的后端完成。

6. 怎么实现「双网卡双网关，不同来源走不同出口」？
   答：策略路由：在 /etc/iproute2/rt_tables 定义独立路由表（如 table 100），
   把第二个网关的路由写进 table 100，再用 ip rule add from <网段> table 100
   按来源地址分流。netplan 里用 routes.table + routing-policy 持久化。

7. bond 有哪些常用模式？各什么场景？
   答：mode 1 active-backup（一主一备，只求冗余，交换机无要求）；
   mode 4 802.3ad（LACP 动态聚合，带宽叠加，需交换机支持）；
   mode 0 balance-rr（轮询分发，兼容性差）；mode 6 balance-alb（无需交换机支持）。
   生产常用 1 或 4。

8. 域名解析的完整顺序是什么？
   答：应用调 getaddrinfo → nsswitch.conf 的 hosts 行决定顺序
   （Ubuntu 默认 files mdns4_minimal [NOTFOUND=return] dns）→
   先查 /etc/hosts（files），命中直接用；没命中查 mDNS（.local 域名）；
   再没命中走 DNS：/etc/resolv.conf 指定的服务器（Ubuntu 是 systemd-resolved
   stub 127.0.0.53，由它转发给上游）。所以 /etc/hosts 能「覆盖」DNS。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 服务器配静态 IP，客户端/临时环境用 DHCP；企业服务器可 DHCP 静态绑定。
2. 用 ip 命令（现代），别用 ifconfig；脚本里也别写 ifconfig/route（新系统没有）。
3. 改配置后必须应用：netplan apply / nmcli connection up / systemctl restart NetworkManager。
4. 远程改 IP 三步走：netplan try 或「临时加新 IP + 测试 + 删旧 IP」，永远留退路。
5. 改之前备份：`sudo cp /etc/netplan/*.yaml /tmp/`、`nmcli connection export`。
6. 先确认「谁在管这张网卡」再动手（NetworkManager vs networkd 二选一）。
7. DNS 的持久化改法：netplan nameservers 或 resolvectl，别直接改 /etc/resolv.conf（会被还原）。
8. 多网卡服务器用策略路由 + 独立路由表，别在 main 表里硬塞冲突路由。
9. WiFi 密码在 netplan 明文存储，注意文件权限（600）与备份安全。

### 踩坑记录

```text
坑 1：ip addr 配了 IP 重启就没了
结论：ip addr add 配的 IP，重启后消失，服务起不来。
原因：ip 命令是临时配置，只改内核不写文件。
解法：持久化要写 netplan（Ubuntu）或 nmcli/ifcfg（Red Hat），并确认网络服务自启。

坑 2：改 netplan 没 apply，配置不生效
结论：改了 netplan 文件，ip addr 看还是老 IP。
原因：netplan 是声明式配置，必须 apply 才翻译给后端执行。
解法：sudo netplan apply（语法错误会报错不应用）；远程操作用 netplan try 自动回滚。

坑 3：远程服务器改 IP 把自己改断连了
结论：改静态 IP 后 SSH 断了，连不上了。
原因：IP 改错、掩码/网关配错，或网卡 down 后没 up，网络不通。
解法：预防为主——netplan try / 临时加新 IP 测试后删旧 IP / 带外管理。
      已断只能机房或 IPMI 恢复，或等 DHCP 租约重新获取。

坑 4：ifconfig 找不到，老脚本跑不了
结论：老脚本用 ifconfig，新系统报 command not found。
原因：ifconfig 在 net-tools 包，新发行版不装。
解法：apt install net-tools（临时兼容），长期应把脚本迁移到 ip 命令。

坑 5：NetworkManager 和 systemd-networkd 同时管，配置冲突
结论：两个管理器都启动，网卡配置打架，改了 A 被 B 覆盖。
原因：两个守护进程同时管理同一网卡，优先级混乱，互相覆盖。
解法：只用一个管理器（另一个 systemctl disable），netplan renderer 指定后端。

坑 6：ifcfg 文件写了 ONBOOT=no（或忘写），重启网卡不生效
结论：Red Hat 系重启后 IP 没了，nmcli 看连接是 disabled。
原因：ifcfg 里 ONBOOT=no 或没写，NetworkManager 不自动激活该连接。
解法：ONBOOT=yes + nmcli connection reload/up；用 nmcli 创建连接默认 autoconnect。

坑 7：手改 /etc/resolv.conf 被还原
结论：改了 /etc/resolv.conf 写自己的 DNS，重启/重新连接后又变回 127.0.0.53。
原因：Ubuntu 的 resolv.conf 是 systemd-resolved stub 的符号链接，动态管理。
解法：改 netplan 的 nameservers 或 resolvectl dns <网卡> <IP>；
      真要静态 resolv.conf 需改 systemd-resolved 模式或换掉符号链接。

坑 8：网卡名变了导致配置全部失效
结论：服务器重启后 IP 没了，发现网卡从 eth0 变成 enp59s0。
原因：predictable naming 按 PCI 槽位命名，硬件变动后名字改变，旧配置匹配不上。
解法：netplan 用 match macaddress 匹配网卡；或 udev 规则固定名称；别依赖 eth0。

坑 9：双网卡配了双默认网关，外网时通时不通
结论：两张网卡都写了 default 路由，外网流量随机走，时通时断。
原因：main 表两条 default（metric 相同），内核选路不确定。
解法：只留一条 default（或用 metric 区分主备），次要网卡走策略路由独立表。

坑 10：WiFi 配置在 netplan 里密码明文，备份泄露
结论：netplan 的 access-points 里 password 是明文，配置备份/截图泄露风险。
原因：netplan 本身不加密 WiFi 凭据。
解法：控制文件权限；桌面环境让 NetworkManager 存凭据（nm-secret-agent）；
      敏感环境用企业 802.1X 认证替代共享密码。
```

## 概述

网络配置回答「网卡怎么配 IP、怎么上网」：用 ip 命令临时配（重启失效），或写网卡配置文件持久化（netplan/NetworkManager/systemd-networkd）。分静态 IP（手动指定）和 DHCP（自动获取）。现代 Linux 网络配置被 NetworkManager（桌面/通用）和 systemd-networkd（服务器）管理，Ubuntu 桌面用 netplan + NetworkManager。理解配置层级，才能「改了 IP 不生效」时知道去哪查。

```text
网络配置层级：
1. ip 命令 —— 临时配置（立即生效，重启失效）
2. 网卡配置文件 —— 持久化（netplan/NetworkManager/systemd-networkd）
3. 静态 IP —— 手动指定，服务器常用
4. DHCP —— 自动获取，客户端/临时环境常用
```

## 核心概念

1. **网卡（interface）**：网络接口，命名规则 en=以太网、wl=无线、docker0/br-* 虚拟网卡。
2. **ip 命令**：现代网络配置工具（iproute2），替代 ifconfig，配置是临时的。
3. **静态 IP**：手动指定 IP/掩码/网关/DNS，稳定，服务器用。
4. **DHCP**：自动从 DHCP 服务器获取（IP/网关/DNS 都自动），客户端用。
5. **网络管理器**：NetworkManager（功能全，桌面默认）和 systemd-networkd（轻量，服务器默认）。

```text
静态 IP 四要素：
1. IP 地址   192.168.1.100
2. 子网掩码  /24（255.255.255.0）
3. 默认网关  192.168.1.1
4. DNS       8.8.8.8
```

```text
# 实测（本机网卡）
$ ip -br link
lo               UNKNOWN  00:00:00:00:00:00   # 回环
enp59s0          DOWN     ...                  # 有线网卡（没插线）
wlp0s20f3        UP       ...                  # WiFi 网卡（在用）
docker0          UP       ...                  # Docker 网桥
tailscale0       UNKNOWN  ...                  # Tailscale VPN
# 网卡命名：en=有线、wl=无线，docker0/br-* 是 Docker 虚拟网卡
```

## 工作原理

网络配置的生效路径：配置工具（nmcli/netplan/systemd-networkd）→ 网络管理器守护进程 → 写内核（网卡 IP、路由表）。

1. **ip 命令**：直接调内核 netlink 接口，临时改网卡 IP/状态，重启失效（因为没写配置文件）。
2. **netplan**：声明式 YAML 配置，`netplan apply` 时把配置翻译给后端（NetworkManager 或 systemd-networkd）。
3. **NetworkManager**：守护进程自动管理连接（有线/无线），nmcli 操作，桌面/通用系统默认。
4. **DHCP**：网卡广播 DHCP Discover → 服务器 Offer 分配 → 客户端 Request 确认 → 拿到 IP/网关/DNS。

```text
配置生效路径：
ip 命令 → 内核（临时）
netplan YAML → 后端（NM/networkd）→ 内核（持久化）
DHCP 四步：Discover → Offer → Request → ACK
```

## 常用命令与配置

```shell
ip addr                        # 看所有 IP
ip link                        # 看网卡状态
ip link set wlp0s20f3 down     # 停用网卡
ip link set wlp0s20f3 up       # 启用网卡
ip -br addr                    # 简洁版 IP 列表
ip addr add 192.168.1.200/24 dev enp59s0   # 临时加 IP
ip addr del 192.168.1.200/24 dev enp59s0   # 删 IP

# NetworkManager
nmcli device status            # 看设备
nmcli connection show          # 看连接配置
nmcli device wifi list         # 看 WiFi
nmcli connection up <name>     # 启用连接

# netplan
netplan apply                  # 应用配置
netplan try                    # 试用配置（超时自动回滚）
```

## 配置文件解析

```text
各发行版网卡配置位置：
Ubuntu（netplan）       /etc/netplan/*.yaml
Red Hat（NetworkManager） /etc/NetworkManager/system-connections/ 或 /etc/sysconfig/network-scripts/
systemd-networkd        /etc/systemd/network/*.network
```

```yaml
# netplan 静态 IP 配置示例（/etc/netplan/01-static.yaml）
network:
  version: 2
  renderer: networkd
  ethernets:
    enp59s0:
      dhcp4: no
      addresses: [192.168.1.100/24]
      routes:
        - to: default
          via: 192.168.1.1
      nameservers:
        addresses: [8.8.8.8, 114.114.114.114]
```

```shell
sudo netplan apply      # 应用 netplan 配置
```

## 应用场景实战

### 场景一：临时给网卡加一个 IP

```shell
# 1. 临时加 IP（重启失效）
ip addr add 192.168.1.200/24 dev enp59s0
# 2. 验证
ip addr show enp59s0
# 3. 临时删除
ip addr del 192.168.1.200/24 dev enp59s0
```

### 场景二：配置静态 IP（netplan，Ubuntu）

```shell
# 1. 写 netplan 配置
sudo vim /etc/netplan/01-static.yaml
# 2. 应用配置
sudo netplan apply
# 3. 验证
ip addr show && ip route show
```

## 性能与调优

```text
1. 网卡 offload —— 开启 tso/gro 减少 CPU 开销（默认开启，疑难问题可关）
2. 链路聚合 bonding —— 多网卡绑定提升带宽/冗余，高吞吐服务器用
3. MTU —— 巨型帧（9000）提升大流量传输效率，需全链路支持
4. DNS 就近 —— 配置延迟低的 DNS，减少域名解析时间
5. 双栈 —— IPv4/IPv6 共存，别只配一个导致部分服务连不上
```

## 安全与权限

```text
1. 远程改 IP 风险 —— 改错会断连，用「临时加新 IP + 测试 + 删旧 IP」的方式
2. 只用一个管理器 —— NetworkManager 和 systemd-networkd 别同时管同一网卡
3. DHCP 信任 —— 内网 DHCP 服务器被攻破可下发恶意网关/DNS，生产网用受控 DHCP
4. 配置权限 —— 网卡配置文件属 root，修改需 sudo，防普通用户篡改网络
5. 禁用 IPv6 按需 —— 不需要 IPv6 的环境可禁用，减少攻击面
```

## 故障排查

### 改了配置不生效 / 断网

```shell
# 1. 确认用了哪个管理器
systemctl is-active NetworkManager systemd-networkd
# 2. 看当前生效的 IP
ip addr show
# 3. netplan 配置是否有语法错误
netplan try           # 试用，报错会指出
# 4. 看网络管理器日志
journalctl -u NetworkManager -n 50
```

## 常见问题

```text
Q1: ip addr 配的 IP 重启后没了？
A: ip 命令是临时配置，持久化要写 netplan/NetworkManager 配置文件。

Q2: 改 netplan 不生效？
A: netplan 要 apply 才生效，且确认 renderer 和实际管理器一致。

Q3: 远程改 IP 断连了怎么办？
A: 改错 IP/网关导致。远程改 IP 用临时加新 IP + 测试 + 删旧 IP 的方式，或配个带外管理（console/IPMI）。

Q4: 静态 IP 和 DHCP 怎么选？
A: 服务器用静态 IP（地址固定），客户端/临时环境用 DHCP（自动获取）。
```

## 面试题

```text
1. 静态 IP 要配哪四个东西？
   答：IP 地址、子网掩码、默认网关、DNS 服务器。

2. ip 命令和 ifconfig 的区别？
   答：ip 是 iproute2 的现代工具，功能全、语法统一；ifconfig 是老的 net-tools，已废弃、新系统默认不装。

3. NetworkManager 和 systemd-networkd 的区别？
   答：NM 功能全、自动管理、桌面默认；networkd 轻量、声明式配置、服务器/容器默认。

4. DHCP 获取 IP 的流程？
   答：Discover（广播发现）→ Offer（服务器分配）→ Request（客户端确认）→ ACK（服务器确认），拿到 IP/网关/DNS。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 服务器配静态 IP，客户端/临时环境用 DHCP
2. 用 ip 命令（现代），别用 ifconfig（已废弃）
3. 改配置后记得应用（netplan apply / nmcli / systemctl restart）
4. 远程改 IP 要小心——改错会断连，先确认再应用
5. 网卡配置位置因发行版而异，先确认用哪个管理器再改

### 踩坑记录

```text
坑 1：ip addr 配了 IP 重启就没了
结论：ip addr add 配的 IP，重启后消失。
原因：ip 命令是临时配置，不持久化。
解法：持久化要写 netplan/NetworkManager 配置文件。

坑 2：改 netplan 没 apply，配置不生效
结论：改了 netplan 文件，重启/查看还是老 IP。
原因：netplan 要 apply 才生效，没 apply 改了白改。
解法：sudo netplan apply，或重启网络服务。

坑 3：远程服务器改 IP 把自己改断连了
结论：改静态 IP 后 SSH 断了，连不上了。
原因：IP 改错或网关/掩码配错，网络不通。
解法：远程改 IP 用「临时加新 IP + 测试 + 删旧 IP」的方式，别直接改。

坑 4：ifconfig 找不到，脚本跑不了
结论：老脚本用 ifconfig，新系统报 command not found。
原因：ifconfig 在 net-tools 包，新系统不装。
解法：apt install net-tools，或把脚本改成 ip 命令。

坑 5：NetworkManager 和 systemd-networkd 同时管，配置冲突
结论：两个管理器都启动，网卡配置打架。
原因：两个守护进程同时管理网络，优先级混乱。
解法：只用一个管理器，另一个 disable 掉。
```

## 概述

网络诊断工具回答「通不通、谁在连、连不上为什么、流量长啥样」：ping/traceroute 测连通、ss/netstat 看连接、nc 测端口、tcpdump 抓包分析、mtr 综合诊断、ethtool 看网卡。排查网络问题先「ping 测连通 → ss 看端口 → nc 测具体端口 → tcpdump 抓包深挖」。这些工具各有分工，配合起来能定位绝大多数网络问题。

```text
网络诊断工具分工：
1. 连通性 —— ping（测通）、traceroute（测路径）
2. 连接查看 —— ss / netstat（看连接和监听端口）
3. 端口测试 —— nc（测某端口通不通）
4. 抓包分析 —— tcpdump（看流量内容）
5. 综合诊断 —— mtr（ping+traceroute 结合）
6. 网卡信息 —— ethtool（速度/双工/驱动）
```

## 核心概念

六个工具分三组：连通性（ping/traceroute）、连接查看（ss/netstat）、深挖（nc/tcpdump/mtr/ethtool）。下面逐一展开。

### ping 与 traceroute 连通性

ping 用 ICMP 测「通不通 + 延迟」，是最基础的连通性测试。traceroute 显示数据包到目标经过的「每一跳」，定位「断在哪一跳」。ping 不通不一定网络不通（可能禁 ICMP），traceroute 能看清路径。注意：traceroute 部分系统默认不装（要 tracepath 或单独装）。

```text
# 实测（本机工具可用性）
$ for t in ping traceroute dig nc tcpdump mtr ethtool netstat; do
>   command -v $t >/dev/null && echo "$t: 有" || echo "$t: 无"; done
ping: 有   traceroute: 无   dig: 有   nc: 有
tcpdump: 有   mtr: 有   ethtool: 有   netstat: 有
# 本机 traceroute 未装，可用 tracepath 或 mtr 替代
```

```shell
ping -c 4 8.8.8.8            # 测外网连通 + 延迟
ping -c 4 192.168.1.1        # 测网关连通
tracepath 8.8.8.8            # 替代 traceroute（内置）
mtr 8.8.8.8                  # 动态 traceroute
```

### ss 与 netstat 连接查看

ss 是现代的连接查看工具（替代 netstat），看「谁在监听、谁在连接」。关键用法：`ss -tlnp` 看监听端口（t=tcp、l=listen、n=数字、p=进程）、`ss -tan` 看所有连接及状态。netstat 是老命令（net-tools 包），功能等价。排查「服务起来了没」「端口被谁占了」「连接状态异常」都用 ss。

```text
# 实测（本机监听端口）
$ ss -tlnp | head
LISTEN 0.0.0.0:22     sshd        # SSH
LISTEN 0.0.0.0:80     nginx       # Web
LISTEN 0.0.0.0:8082   nginx       # Web（另一站点）
LISTEN 0.0.0.0:3306   docker-proxy  # MySQL 容器
LISTEN 0.0.0.0:2379   docker-proxy  # etcd 容器
LISTEN 0.0.0.0:3000   node        # Node 服务
LISTEN 0.0.0.0:19530  docker-proxy  # Milvus 向量库
```

```shell
ss -tlnp              # 看监听端口 + 进程
ss -tan               # 看所有 TCP 连接 + 状态
ss -s                 # 连接统计
ss -tlnp | grep :80   # 看 80 端口被谁监听
netstat -tlnp         # 等价（老命令）
```

### nc 端口测试

nc（netcat）是「网络瑞士军刀」——测端口通不通（nc -zv）、收发数据、做简易服务器/客户端。测端口是最常用场景：`nc -zv 主机 端口` 测试某端口是否开放。比 telnet 更通用（telnet 很多系统不装）。还可用 nc 传文件、测 UDP、做端口转发。

```shell
nc -zv 192.168.1.10 22        # 测 22 端口通不通
nc -zv 127.0.0.1 80           # 测本机 80 端口
nc -zv -u 127.0.0.1 53        # 测 UDP 端口
echo "test" | nc 127.0.0.1 80  # 发数据测试
```

### tcpdump 抓包

tcpdump 是命令行抓包工具——抓取经过网卡的网络包，分析流量内容。排查「请求发没发出去」「握手在哪失败」「协议异常」时用。关键：`tcpdump -i 网卡` 指定网卡、`port 80` 过滤端口、`host 1.2.3.4` 过滤主机、`-w 文件` 存包（用 Wireshark 分析）。抓包要 root 权限。

```shell
tcpdump -i wlp0s20f3 port 80          # 抓 80 端口流量
tcpdump -i any host 192.168.1.10      # 抓某主机的流量
tcpdump -i any tcp port 22 -w ssh.pcap # 抓包存文件
tcpdump -i any -n icmp                # 抓 ICMP（ping）
```

```text
tcpdump 常用过滤：
1. port 80 —— 指定端口
2. host 1.2.3.4 —— 指定主机
3. tcp / udp / icmp —— 指定协议
4. -w 文件 —— 存包，用 Wireshark 分析
```

### mtr 与 ethtool

mtr 是 ping + traceroute 的结合体——动态显示每一跳的丢包率和延迟，持续观察网络质量（比单次 traceroute 更直观，能看出「哪一跳在丢包」）。ethtool 看网卡硬件信息（速度、双工、驱动、是否支持千兆）。排查「网速慢」「丢包」「网卡跑在半双工」用这俩。

```shell
mtr 8.8.8.8               # 动态 traceroute，看每跳丢包
mtr -r -c 10 8.8.8.8      # 报告模式（10 个包）
ethtool wlp0s20f3         # 看网卡信息
ethtool -S wlp0s20f3      # 看网卡统计
```

## 工作原理

这些工具各自从内核不同位置取数据：ping 发 ICMP echo 请求、按回包算 RTT；traceroute 靠递增 IP 头的 TTL（每跳路由器减一，减到 0 回 ICMP time exceeded）逐跳探测；ss 从内核的 netlink socket 直接读连接表（比 netstat 读 /proc/net 更快更全）；tcpdump 用 libpcap + BPF 过滤器在内核抓包拷贝到用户态。

```text
各工具数据来源：
ping         主动发 ICMP，测 RTT 与丢包
traceroute   递增 TTL，收集每跳 ICMP time exceeded，定位路径
ss           读内核 netlink socket 连接表（快、全）
netstat      读 /proc/net/tcp 等文件（老实现，可能截断）
tcpdump      内核 BPF 过滤器 + libpcap 抓包拷贝
ethtool      ioctl/ethtool 协议读网卡寄存器（速度/双工/驱动）
```

## 常用命令与配置

```shell
# 连通性
ping -c 4 8.8.8.8           # 4 个包测通
tracepath 8.8.8.8           # 内置 traceroute
# 连接
ss -tlnp                    # 监听端口
ss -tan state established   # 只看已建立连接
# 端口
nc -zv 1.2.3.4 80           # 测 TCP 端口
nc -zvu 1.2.3.4 53          # 测 UDP 端口
# 抓包
tcpdump -i any -nn port 80  # 抓包（-nn 不解析域名/服务名）
# 网卡
ethtool eth0                # 网卡速度/双工
ethtool -S eth0             # 网卡统计
```

## 配置文件解析

网络诊断工具本身不读配置，但排查时要理解这几个网络配置文件，它们决定了「解析到哪、转发到哪、内核怎么处理」。

```text
网络诊断相关配置文件：
/etc/resolv.conf     DNS 服务器（nameserver 行），dig/nslookup 查它
/etc/hosts          本地静态映射，优先于 DNS
/etc/nsswitch.conf  解析顺序（hosts: files dns）
/etc/sysctl.conf    内核网络参数（net.ipv4.ip_forward、tcp 调优等）

说明：
1. 域名解析异常先看 /etc/resolv.conf 和 /etc/hosts
2. 转发/路由异常看 net.ipv4.ip_forward（sysctl）
3. TCP 连接状态异常（TIME_WAIT 堆积）看 /etc/sysctl.conf 的 tcp 参数
```

## 应用场景实战

### 场景一：服务端口不通，逐层排查

```shell
# 1. 看服务有没有监听端口
ss -tlnp | grep <端口>
# 2. 本地测端口
nc -zv 127.0.0.1 <端口>
# 3. 远程测端口
nc -zv <目标IP> <端口>
# 4. 抓包看请求到没到
tcpdump -i any port <端口>
```

### 场景二：网络慢、丢包，定位问题段

```shell
# 1. mtr 看每一跳的丢包率（定位丢包段）
mtr 8.8.8.8
# 2. 看网卡是否跑在半双工/低速
ethtool wlp0s20f3 | grep -E 'Speed|Duplex'
# 3. 看连接状态是否异常堆积
ss -s && ss -tan | awk 'NR>1{print $1}' | sort | uniq -c
```

## 性能与调优

```text
1. 抓包量大时用 -w 存文件离线分析，别 -i any 全量刷终端
2. tcpdump 加过滤（port/host/protocol）缩小抓取范围，降低 CPU 和丢包
3. ss 比 netstat 快（直接读 netlink），高频监控用 ss
4. mtr 持续观察能看出「抖动/间歇性丢包」，比单次 traceroute 更能定位性能问题
5. ethtool 查网卡是否协商到低速/半双工，这是网速慢的常见根因
```

## 安全与权限

```text
1. tcpdump 抓包要 root（或 CAP_NET_RAW），抓到的明文内容含敏感数据，别外发
2. 抓包文件（.pcap）可能含密码/token/内网拓扑，脱敏后再共享
3. nc 可做端口转发/反弹 shell，是攻击常用工具——服务器上非必要不装、装了限制使用
4. ping/ICMP 常被防火墙禁，别因为 ping 不通就武断判「服务挂了」
5. 对外诊断暴露内网信息（traceroute 的每跳 IP），报障时注意脱敏
```

## 故障排查

### 连不上服务：从端口到抓包逐层定位

```shell
# 1. 本机监听确认
ss -tlnp | grep <端口>          # 没输出 = 服务没起来或没监听
# 2. 本机回环测
nc -zv 127.0.0.1 <端口>         # 失败 = 服务没监听
# 3. 跨机测
nc -zv <目标IP> <端口>          # 失败 = 防火墙/路由挡了
# 4. 抓包确认请求到没到
tcpdump -i any host <目标IP> and port <端口> -nn
```

### 网速慢 / 丢包定位

```shell
# 1. 网卡协商速率/双工
ethtool eth0 | grep -E 'Speed|Duplex'
# 2. 每跳丢包
mtr -r -c 20 8.8.8.8
# 3. 连接状态堆积
ss -s
```

## 常见问题

```text
Q1: ping 不通但服务能访问？
A: 目标禁了 ICMP（防火墙挡 ping），但 TCP 服务正常。用 nc -zv 测端口、curl 测服务。

Q2: traceroute 中间全是 * 是不是断了？
A: 不是。中间路由器不响应 ICMP（星号不代表断），只要最后一跳能到就行。

Q3: ss 和 netstat 数字对不上？
A: 以 ss 为准。ss 直接读内核 netlink，netstat 读 /proc 且可能截断。

Q4: tcpdump 报 permission denied？
A: 抓包要 root 权限，加 sudo 或给用户 CAP_NET_RAW 能力。

Q5: 为什么 netstat 报 command not found？
A: netstat 在 net-tools 包，新系统默认不装，用 ss 替代或 apt install net-tools。
```

## 面试题

```text
1. ss 和 netstat 的区别？
   答：ss 直接读内核 netlink socket，更快更全；netstat 读 /proc/net 文件（老实现）。现代系统用 ss。

2. traceroute 的原理？
   答：递增 IP 头的 TTL，每跳路由器 TTL 减一，减到 0 回 ICMP time exceeded，据此探测每跳 IP。

3. tcpdump 的过滤是在哪做的？
   答：内核态用 BPF 过滤器，只把匹配的包拷贝到用户态，避免全量拷贝开销大。

4. ping 为什么不能完全代表服务可用？
   答：ping 只测 ICMP 通不通，服务端口通不通、应用层正不正常要 nc/curl 测。

5. 怎么判断网络慢是「链路丢包」还是「网卡协商问题」？
   答：mtr 看每跳丢包率定位链路；ethtool 看 Speed/Duplex 确认网卡是否跑在低速/半双工。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 看连接/端口统一用 ss（现代），netstat 是老命令别依赖
2. 测端口用 nc -zv，比 telnet 通用（telnet 很多系统不装）
3. 抓包用 tcpdump -i any + 过滤条件，别抓全量（量太大）
4. 排查丢包用 mtr 看每一跳，比单次 traceroute 直观
5. 网速异常查 ethtool 看网卡是不是跑在半双工/低速

### 踩坑记录

```text
坑 1：ss 和 netstat 混用，结果对不上
结论：ss 和 netstat 显示的数量不一致。
原因：ss 读内核直接，netstat 读 /proc，且 netstat 可能截断。
解法：统一用 ss，结果以 ss 为准。

坑 2：tcpdump 抓包量大，把自己卡死
结论：tcpdump -i any 没过滤，抓包把终端刷爆。
原因：全量抓包量大，输出/存文件爆炸。
解法：加过滤（port/host/protocol），或 -w 存文件离线分析。

坑 3：ping 不通就判断服务挂了
结论：ping 目标不通，但服务其实正常（能 curl 通）。
原因：目标禁 ICMP，ping 被防火墙挡了。
解法：用 nc -zv 测端口、curl 测服务，别只看 ping。

坑 4：netstat 命令不存在
结论：敲 netstat 报 command not found。
原因：netstat 在 net-tools 包，新系统不默认装。
解法：用 ss 替代，或 apt install net-tools。

坑 5：traceroute 显示 * * * 以为断了
结论：traceroute 中间几跳全是 *，以为网络断。
原因：中间路由器不响应 ICMP（星号不代表断，目标能到就行）。
解法：看最后一跳能不能到，中间 * 是正常的。
```

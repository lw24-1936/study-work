## 概述

DNS 把「域名」解析成「IP 地址」（如 www.example.com → 1.2.3.4）。Linux 的解析流程：先查 /etc/hosts（本地静态映射），再查 DNS 服务器（/etc/resolv.conf 指定）。主机名（hostname）是机器的名字，用 hostnamectl 管理。dig/nslookup/host 是 DNS 查询工具（dig 最强大）。理解解析流程和这几个配置文件，才能排查「域名解析不了」。

```text
DNS 解析流程：
应用请求域名 → 查 /etc/hosts（本地）→ 查 DNS 服务器（resolv.conf）
1. /etc/hosts —— 本地静态映射，优先于 DNS
2. /etc/resolv.conf —— 指定 DNS 服务器地址
3. 缓存 —— systemd-resolved / nscd 缓存解析结果
```

## 核心概念

1. **域名解析**：域名 → IP 的过程，分本地解析（/etc/hosts）和远程解析（DNS 服务器）。
2. **/etc/hosts**：本地静态映射表，优先级最高，改它立即生效。
3. **/etc/resolv.conf**：指定 DNS 服务器，现代系统由 systemd-resolved 管理。
4. **systemd-resolved**：本地 DNS 缓存/转发服务，resolv.conf 指向它的 stub（127.0.0.53）。
5. **主机名（hostname）**：机器标识，static（静态）/transient（临时）/pretty（显示名）三种。

```text
# 实测（本机 /etc/hosts）
$ grep -vE '^\s*#|^\s*$' /etc/hosts
127.0.0.1 localhost
127.0.1.1 lw-Vostro-7580
140.82.112.3 github.com
140.82.113.5 api.github.com
::1 ip6-localhost ip6-loopback
# 前两行是本地主机名，后两行手动把 github.com 指到正确 IP（DNS 修复）
```

## 工作原理

DNS 解析是「逐级递归/迭代查询」：本地先查 /etc/hosts（命中直接返回）→ 没命中查 /etc/resolv.conf 指定的 DNS 服务器 → DNS 服务器递归查询根服务器 → 顶级域 → 权威服务器 → 返回 A 记录。

解析顺序由 /etc/nsswitch.conf 的 hosts 行控制（files 在前表示先查 hosts）。systemd-resolved 作为本地缓存/转发层：应用查 127.0.0.53（stub），resolved 再转发给上游 DNS 并缓存结果。

```text
解析链路：
应用 → /etc/hosts（files）→ systemd-resolved stub（127.0.0.53）→ 上游 DNS → 根/顶级/权威

nsswitch.conf 控制顺序：
hosts: files dns   # 先 /etc/hosts，再 DNS
```

## 常用命令与配置

```shell
# DNS 查询
dig example.com              # 完整解析（A 记录 + 权威 + 耗时）
dig example.com +short       # 只要结果（IP）
dig @8.8.8.8 example.com     # 指定 DNS 服务器查询
nslookup example.com         # 交互式查询
host example.com             # 简洁查询

# systemd-resolved
resolvectl status            # 看上游 DNS 服务器
resolvectl query example.com # 用 systemd-resolved 解析
resolvectl flush-caches      # 清 DNS 缓存

# 主机名
hostnamectl                  # 查看主机名详情
hostnamectl set-hostname web01   # 设置主机名（永久）
hostname                     # 快速看主机名
```

## 配置文件解析

```text
DNS 相关配置文件：
/etc/hosts          本地静态映射（优先级最高）
/etc/resolv.conf    DNS 服务器（nameserver 行）
/etc/nsswitch.conf  解析顺序（hosts: files dns）
/etc/hostname       静态主机名
```

```text
# 实测（本机 resolv.conf，由 systemd-resolved 管理）
$ cat /etc/resolv.conf
nameserver 127.0.0.53
options edns0 trust-ad
search tailc6bb9f.ts.net
# 127.0.0.53 是 systemd-resolved 的 stub，真正上游 DNS 用 resolvectl status 看
```

```text

      Machine ID: f33d9c6e946b440893fe3b5b6afbc29c
```

## 应用场景实战

### 场景一：域名解析不了，排查 DNS

```shell
# 1. 用 dig 看解析过程
dig example.com
# 2. 指定 DNS 服务器测试（绕过本地 DNS）
dig @8.8.8.8 example.com
# 3. 看本地 DNS 配置
cat /etc/resolv.conf
resolvectl status
# 4. 看 /etc/hosts 有没有错误映射
cat /etc/hosts
```

### 场景二：测试环境把域名指向测试服务器

```shell
# 1. 编辑 hosts，把测试域名指到测试服务器
echo "10.0.0.5 api.test.example.com" | sudo tee -a /etc/hosts
# 2. 验证解析
getent hosts api.test.example.com
# 3. 测试完删除（避免影响他人）
sudo sed -i '/api.test.example.com/d' /etc/hosts
```

## 性能与调优

```text
1. 本地缓存 —— systemd-resolved/nscd/dnsmasq 缓存解析结果，减少重复远程查询
2. 就近 DNS —— 配延迟低的 DNS（ISP 或就近的公共 DNS），减少解析耗时
3. 预取/并行 —— 应用层做 DNS 预解析、多记录并行查询
4. TTL 权衡 —— 缓存 TTL 短则解析新但查询多，长则省查询但更新慢
5. search 域 —— resolv.conf 的 search 域太长会导致补全域名额外查询，精简
```

## 安全与权限

```text
1. DNS 污染/劫持 —— 上游 DNS 被污染会解析到恶意 IP，用可信 DNS + DNSSEC 校验
2. /etc/hosts 篡改 —— hosts 优先级最高，被篡改可把域名劫持到钓鱼 IP，注意文件权限
3. 加密 DNS —— DoH/DoT 加密 DNS 查询，防中间人窃听解析内容
4. 主机名泄露 —— 主机名会出现在日志/SSH/网络里，别在主机名里放敏感信息
5. 权限 —— /etc/hosts、/etc/resolv.conf 属 root，普通用户不能改
```

## 故障排查

### 域名解析失败 / 解析到错误 IP

```shell
# 1. 直接查，看报什么错
dig example.com
# 2. 绕过本地 DNS 直接查公共 DNS（判断是不是本地 DNS 问题）
dig @8.8.8.8 example.com
# 3. 检查 hosts 有没有错误映射（优先级最高）
grep example.com /etc/hosts
# 4. 检查解析顺序和 DNS 配置
cat /etc/nsswitch.conf | grep hosts
resolvectl status
```

## 常见问题

```text
Q1: 改了 resolv.conf 为什么被覆盖？
A: resolv.conf 由 systemd-resolved 生成，手动改会被覆盖。用 resolvectl/nmcli 改 DNS。

Q2: 域名解析到错误 IP？
A: 先查 /etc/hosts 有没有错误映射（优先级最高），再查 DNS 缓存，最后查上游 DNS。

Q3: dig 和 nslookup 结果不一致？
A: nslookup 可能走不同解析路径（缓存/搜索域）。以 dig 为准，对比 dig @8.8.8.8 排除本地干扰。

Q4: 改了主机名但有些服务还显示旧名字？
A: /etc/hosts 里的旧主机名映射没同步。改主机名后同步 /etc/hosts 的 127.0.1.1 映射。
```

## 面试题

```text
1. Linux 解析域名的完整流程？
   答：先查 /etc/hosts（本地静态映射），没命中再查 /etc/resolv.conf 指定的 DNS 服务器（经 systemd-resolved 缓存/转发），DNS 服务器递归查询返回结果。

2. /etc/hosts 和 DNS 的优先级？
   答：/etc/hosts 优先级高于 DNS（nsswitch.conf 的 hosts: files dns，files 在前）。改 hosts 立即生效、覆盖 DNS 结果。

3. systemd-resolved 的 stub（127.0.0.53）是什么？
   答：本地 DNS 缓存/转发服务的入口，resolv.conf 指向它，真正上游 DNS 由 resolvectl 管理，实现本地缓存 + 动态切换上游。

4. dig 相比 nslookup 的优势？
   答：dig 输出更详细（完整解析过程、权威服务器、耗时），支持 +short、@指定服务器，是 DNS 排错的首选工具。
```

## 最佳实践与踩坑记录

### 最佳实践

1. DNS 排错用 dig（最详细），看「解析流程 + 哪个环节出错」
2. /etc/hosts 优先级高于 DNS，改 hosts 能快速覆盖解析结果
3. 测试环境改 hosts 指到测试服务器，用完记得删
4. 主机名改完同步 /etc/hosts，避免旧名字残留
5. 理解 systemd-resolved 的 stub（127.0.0.53），真上游 DNS 用 resolvectl 看

### 踩坑记录

```text
坑 1：改了 resolv.conf 被 systemd-resolved 覆盖
结论：直接改 /etc/resolv.conf 的 nameserver，重启后又被改回。
原因：resolv.conf 是 systemd-resolved 生成的，手动改会被覆盖。
解法：用 resolvectl 或 nmcli 改 DNS，别直接改 resolv.conf。

坑 2：/etc/hosts 里有错误映射导致解析到错误 IP
结论：域名解析到错误的 IP，排查半天发现是 hosts 写错了。
原因：hosts 优先级最高，有映射就先用它，不查 DNS。
解法：getent hosts 域名 看走的是 hosts 还是 DNS，检查 hosts 内容。

坑 3：改了主机名但 /etc/hosts 没同步
结论：hostnamectl set-hostname 后，有些服务还显示旧主机名。
原因：/etc/hosts 里的旧主机名映射没更新。
解法：改主机名后同步 /etc/hosts 里的 127.0.1.1 映射。

坑 4：dig 和 nslookup 结果不一致
结论：dig 查的 IP 和 nslookup 查的不一样。
原因：nslookup 可能走不同的解析路径（缓存/搜索域）。
解法：以 dig 为准（最直接），对比 dig @8.8.8.8 排除本地 DNS 干扰。

坑 5：DNS 查询慢，忘了用本地缓存
结论：每次解析都远程查询，慢。
原因：没配 DNS 缓存（systemd-resolved/nscd/dnsmasq）。
解法：启用 systemd-resolved 缓存，或本地搭 dnsmasq 缓存。
```

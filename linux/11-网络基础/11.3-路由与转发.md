## 概述

路由决定「数据包从哪个网卡发出去、发到哪」。核心三件事：路由表（存所有转发规则）、默认网关（兜底路由，出外网走它）、IP 转发（让 Linux 当路由器转发别人的包）。日常「上不了网」多半是默认网关问题，「跨网段不通」看路由表，「Linux 当网关/NAT」要开 IP 转发。策略路由（policy routing）是进阶——按源地址/标记等条件走不同路由。

```text
路由三要素：
1. 路由表 —— 所有路由规则，ip route 查看，按最长前缀匹配
2. 默认网关 —— default 路由，出外网的兜底
3. IP 转发 —— /proc/sys/net/ipv4/ip_forward，开启才能转发
```

## 核心概念

1. **路由表**：「目标网段 → 出口网卡/下一跳」的规则表，`ip route` 查看，最长前缀匹配选路。
2. **默认网关**：default 路由，不知道往哪发就发网关，出外网的兜底。
3. **IP 转发**：内核转发「不是发给本机的包」，让 Linux 当路由器，做网关/NAT/容器网络。
4. **策略路由**：按源地址/端口/标记等多条件选路，用多路由表 + ip rule 实现，比普通路由（只看目标地址）灵活。
5. **NAT**：地址转换，配合 IP 转发让内网机器共享一个公网出口。

```text
# 实测（本机路由表）
$ ip route show
default via 192.168.1.1 dev wlp0s20f3 proto dhcp src 192.168.1.167 metric 600
192.168.1.0/24 dev wlp0s20f3 proto kernel scope link src 192.168.1.167
172.17.0.0/16 dev docker0 proto kernel scope link src 172.17.0.1
172.18.0.0/16 dev br-49cfcba0160f proto kernel scope link src 172.18.0.1
# default=默认网关，192.168.1.0/24=本网段直连，172.x=Docker 虚拟网络
```

## 工作原理

路由决策的核心是「最长前缀匹配」：内核拿到一个目标 IP，在路由表里找「能匹配目标网段、且前缀最长（最具体）」的路由，用它决定出口网卡和下一跳。

转发流程（当路由器时）：收到不是发给本机的包 → 查路由表决定下一跳 → 改包（TTL 减一）→ 从出口网卡发出。ip_forward=1 才转发，否则丢弃。

```text
最长前缀匹配：
目标 10.0.0.5
  default（0.0.0.0/0）     匹配，但前缀最短
  10.0.0.0/8 via A         匹配，前缀更长 → 选这条
  10.0.0.0/16 via B        匹配，前缀最长 → 最终选这条

转发流程：
收包（非本机）→ 查路由表 → 改 TTL → 出口网卡发出（需 ip_forward=1）
```

## 常用命令与配置

```shell
ip route                        # 查看路由表
ip route show default           # 看默认网关
ip route add 10.0.0.0/8 via 192.168.1.254    # 加路由
ip route del 10.0.0.0/8                       # 删路由
ip route add default via 192.168.1.1          # 加默认路由
ip route get 8.8.8.8            # 看某个 IP 会走哪条路由

# IP 转发
echo 1 > /proc/sys/net/ipv4/ip_forward    # 临时开启
sysctl -w net.ipv4.ip_forward=1           # 等价

# 策略路由
ip rule show                    # 看路由策略
ip route show table 100         # 看自定义路由表
ip rule add from 192.168.1.100 table 100  # 源 IP 走 table 100
```

## 配置文件解析

```text
路由相关配置：
/proc/sys/net/ipv4/ip_forward   IP 转发开关（1=开）
/etc/sysctl.conf                持久化内核参数
/etc/iproute2/rt_tables         自定义路由表名定义

静态路由持久化（因发行版而异）：
Ubuntu netplan     /etc/netplan/*.yaml 的 routes:
Red Hat            /etc/sysconfig/network-scripts/route-<iface>
systemd-networkd   /etc/systemd/network/*.network 的 [Route] 段
```

```yaml
# netplan 静态路由示例
network:
  version: 2
  ethernets:
    enp59s0:
      addresses: [192.168.1.100/24]
      routes:
        - to: default
          via: 192.168.1.1
        - to: 10.0.0.0/8
          via: 192.168.1.254
```

```text
# 实测（本机 IP 转发已开启，因为跑 Docker）
$ cat /proc/sys/net/ipv4/ip_forward
1
# Docker 的容器网络需要主机转发数据包，所以 ip_forward=1
```

## 应用场景实战

### 场景一：排查「能上内网不能上外网」

```shell
# 1. 看默认网关有没有
ip route show default
# 2. 测网关连通
ping -c 2 192.168.1.1
# 3. 测外网（网关通、外网不通 = 网关/上游问题）
ping -c 2 8.8.8.8
```

### 场景二：让 Linux 当 NAT 网关（开启转发）

```shell
# 1. 开启 IP 转发
echo 1 > /proc/sys/net/ipv4/ip_forward
# 2. 配 NAT（iptables MASQUERADE）
iptables -t nat -A POSTROUTING -s 10.0.0.0/8 -o enp59s0 -j MASQUERADE
# 3. 持久化转发
echo 'net.ipv4.ip_forward=1' >> /etc/sysctl.conf && sysctl -p
```

## 性能与调优

```text
1. 路由缓存 —— 内核维护路由缓存加速转发，大流量网关场景关注其命中率
2. 转发性能 —— 网关/NAT 机器关掉不必要的服务，让 CPU 专注转发
3. conntrack —— NAT 依赖连接跟踪，高并发调大 net.netfilter.nf_conntrack_max
4. 网卡多队列 —— 转发吞吐大时用多队列网卡 + 中断亲和，分散 CPU
5. 策略路由开销 —— 规则太多影响选路性能，规则要精简有序
```

```shell
sysctl net.netfilter.nf_conntrack_max   # 看连接跟踪上限
sysctl -w net.netfilter.nf_conntrack_max=1048576   # 调大
```

## 安全与权限

```text
1. 默认网关是信任边界 —— 恶意网关可劫持所有出外网流量，别乱指
2. NAT 暴露面 —— 转发内网流量时注意别把内网服务误暴露到公网
3. 反向路径过滤 rp_filter —— 丢弃源地址伪造的包，防 IP 欺骗
4. 策略路由防泄漏 —— 多网卡分流时确保敏感流量走加密通道（VPN），别漏到公网
5. 转发权限 —— 只有 root 能改 ip_forward 和路由表
```

```shell
sysctl net.ipv4.conf.all.rp_filter    # 看反向路径过滤（1=开）
sysctl -w net.ipv4.conf.all.rp_filter=1
```

### 跨网段不通 / 上不了外网

```shell
# 1. 看目标网段有没有路由
ip route get 10.0.0.5
# 2. 看默认网关
ip route show default
# 3. 测网关连通

# 4. 如果本机当网关，查转发开关

```

## 常见问题

```text
Q1: 能上内网不能上外网？
A: 默认网关没配或配错。ip route show default 确认，加 default via 网关。

Q2: 加了静态路由重启后没了？
A: ip route add 是临时的。持久化写 netplan/NetworkManager 配置或启动脚本。

Q3: 容器网络不通？
A: 主机 ip_forward=0，内核不转发容器数据包。sysctl 开转发并持久化。

Q4: 两个默认网关导致网络时好时坏？
A: 多个 default 路由内核按 metric 选，可能选错。只留一个默认网关，或用 metric 区分。
```

## 面试题

```text
1. 路由选择的原则是什么？
   答：最长前缀匹配——在能匹配目标网段的路由里，选前缀最长（最具体）的一条。

2. 默认网关的作用？
   答：default 路由，访问非本网段（外网）时兜底走它。没配默认网关只能访问本网段。

3. IP 转发是干嘛的？什么时候要开？
   答：让内核转发「不是发给本机」的数据包，即当路由器。做网关/NAT/软路由/容器网络（Docker）时要开。

4. 策略路由和普通路由的区别？
   答：普通路由只看目标地址，一套路由表；策略路由按源地址/端口/标记等多条件匹配，用多路由表 + ip rule 分流（双网卡、多出口）。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 上不了外网先查默认网关，再查 IP 转发（如果本机当网关）
2. 加静态路由用 ip route add，临时有效，持久化写配置
3. 容器网络依赖 IP 转发，跑 Docker 的机器 ip_forward 必须是 1
4. 策略路由用 ip rule + 多路由表，先画清分流规则再配
5. 排查跨网段不通，先 ip route 看目标网段有没有路由

### 踩坑记录

```text
坑 1：能上内网不能上外网，默认网关没配
结论：ping 本网段通，ping 8.8.8.8 不通。
原因：没有默认路由，外网包不知道往哪发。
解法：ip route add default via 网关，或配静态 IP 时设网关。

坑 2：ip route add 的路由重启后消失
结论：加了静态路由，重启没了。
原因：ip route add 是临时的，不持久化。
解法：持久化写 netplan/NetworkManager 或启动脚本。

坑 3：容器网络不通，忘了开 IP 转发
结论：Docker 容器能启动但访问不了外网。
原因：主机 ip_forward=0，内核不转发容器数据包。
解法：sysctl net.ipv4.ip_forward=1，写 sysctl.conf 持久化。

坑 4：两条默认路由导致路由混乱
结论：配了两个默认网关，网络时好时坏。
原因：多个 default 路由，内核按 metric 选，可能选错。
解法：只留一个默认网关，或用 metric 区分优先级。

坑 5：策略路由配了不生效
结论：ip rule 加了规则，流量还是走默认路由。
原因：规则匹配顺序/条件不对，或没配套的路由表。
解法：ip rule 确认规则匹配，ip route show table 确认表里有路由。
```

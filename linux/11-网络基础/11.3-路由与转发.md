## 概述

路由决定「数据包从哪个网卡发出去、发到哪」。核心三件事：路由表（存所有转发规则）、默认网关（兜底路由，出外网走它）、IP 转发（让 Linux 当路由器转发别人的包）。日常「上不了网」多半是默认网关问题，「跨网段不通」看路由表，「Linux 当网关/NAT」要开 IP 转发。策略路由（policy routing）是进阶——按源地址/标记等条件走不同路由。

```text
路由三要素：
1. 路由表 —— 所有路由规则，ip route 查看，按最长前缀匹配
2. 默认网关 —— default 路由，出外网的兜底
3. IP 转发 —— /proc/sys/net/ipv4/ip_forward，开启才能转发
```

本机是一台 Ubuntu 24.04 笔记本（有线网卡 DOWN、Wi-Fi 上网、跑着 Docker 和 Tailscale），路由表非常典型：一条 DHCP 下发的默认路由、一条本网段直连路由、若干条 Docker 虚拟网桥路由，`ip rule` 里还能看到 Tailscale 注入的 fwmark 策略规则——正好用来讲解多路由表和策略路由。

## 核心概念

1. **路由表**：「目标网段 → 出口网卡/下一跳」的规则表，`ip route` 查看，最长前缀匹配选路。
2. **默认网关**：default 路由，不知道往哪发就发网关，出外网的兜底。
3. **IP 转发**：内核转发「不是发给本机的包」，让 Linux 当路由器，做网关/NAT/容器网络。
4. **策略路由**：按源地址/端口/标记等多条件选路，用多路由表 + ip rule 实现，比普通路由（只看目标地址）灵活。
5. **NAT**：地址转换，配合 IP 转发让内网机器共享一个公网出口。
6. **多路由表**：内核按 priority 依次查 local → main → default（及用户自定义表），实现按条件分流。

下面按「是什么 → 为什么 → 怎么用 → 边界/易错点」展开核心概念。

### 路由条目（route entry）

- **是什么**：路由表里一行就是一个路由条目，经典字段为 destination / gateway / genmask / flags / metric / iface（`route -n` 的显示风格），现代 `ip route` 用 CIDR 写法。常用字段：
  - `destination`：目标网段（如 `192.168.1.0/24`，`default` 等价于 `0.0.0.0/0`）；
  - `via`（gateway）：下一跳 IP，必须与出口网卡在同一网段；
  - `dev`（iface）：出口网卡；
  - `proto`：路由来源（`kernel` 内核自动生成、`dhcp` DHCP 下发、`static` 手动配置、`boot` 启动时配置）；
  - `scope`：路由作用域（`link` 直连、`global` 可转发到其他网段）；
  - `metric`：优先级，越小越优先（同目标网段时比较）；
  - `src`：源地址选择提示（发往该网段时优先用这个源 IP）；
  - `linkdown`：出口网卡链路状态为 down 的标志。
- **为什么**：内核转发每个包都要查这张表，字段设计让「选路」这件事精确且可调试。
- **怎么用**：`ip route show` 查看、`ip route get <ip>` 模拟查表、`route -n` 看传统格式。

### 默认路由与直连路由

- **是什么**：`default via 192.168.1.1 dev wlp0s20f3` 是默认路由（目标 `0.0.0.0/0`，前缀长度 0，任何地址都能匹配，兜底用）；`192.168.1.0/24 dev wlp0s20f3 scope link` 是直连路由（网卡配了 IP 后内核自动生成，目标在本网段，直接二层发出，不需要网关）。
- **为什么**：直连路由保证本网段互通，默认路由保证外网可达——两者缺一不可。
- **怎么用**：`ip route add default via <网关>` 临时加默认路由；直连路由一般由内核自动维护，手动删了会导致本网段也不通。
- **边界/易错点**：默认路由的 `via` 必须和本机某个网卡同网段；配静态 IP 时如果忘了写网关，就没有默认路由，表现为「能上内网不能上外网」。

### IP 转发（ip_forward）

- **是什么**：内核参数 `net.ipv4.ip_forward`（1=开启）。决定内核是否转发「目标地址不是本机」的 IP 包。
- **为什么**：普通主机只收发本机流量；路由器/NAT 网关/容器网络需要把包从一张网卡转到另一张网卡，必须开转发。
- **怎么用**：`sysctl -w net.ipv4.ip_forward=1` 临时开；写 `/etc/sysctl.conf`（或 `/etc/sysctl.d/*.conf`）持久化；`cat /proc/sys/net/ipv4/ip_forward` 查看。
- **边界/易错点**：转发开只是「允许」，实际转发还受 iptables FORWARD 链约束（默认策略可能是 DROP）；Docker 会自动开转发并改 FORWARD 链策略。

### 策略路由（policy routing）与多路由表

- **是什么**：普通路由只看「目标地址」一张表；策略路由用 `ip rule` 定义一组规则（按源地址、目标、tos、fwmark、接口等条件），命中哪条规则就走哪张路由表，实现「不同的包走不同的路」。
- **为什么**：多出口/双线接入、VPN 分流、按源 IP 走不同线路等场景，单表无法表达「同一个目标，来源不同走法不同」。
- **怎么用**：先在 `/etc/iproute2/rt_tables` 定义表名，`ip route add ... table 100` 往表里灌路由，`ip rule add from 192.168.1.100 table 100` 把匹配条件绑到表上。
- **边界/易错点**：`ip rule` 按 priority 从小到大依次匹配，先到先得；规则顺序错了（如宽泛规则排在精确规则前面）会导致分流不生效。

### NAT（地址转换）

- **是什么**：网络地址转换，改写包的源/目标 IP。SNAT（源地址转换，出方向改源 IP）、DNAT（目标地址转换，入方向改目标 IP）、MASQUERADE（动态源地址转换，出口 IP 不固定时用）。
- **为什么**：内网私网地址（RFC 1918：10/8、172.16/12、192.168/16）不能在公网路由，需要 NAT 网关把内网流量伪装成公网 IP 出去，回程流量再转换回来。
- **怎么用**：iptables/nftables 的 `nat` 表，`POSTROUTING` 链做 SNAT/MASQUERADE，`PREROUTING` 链做 DNAT。依赖 conntrack 连接跟踪。
- **边界/易错点**：NAT 只改 IP/端口，不改应用层内容（FTP 等协议需要额外模块）；NAT 会话记录在 conntrack 里，conntrack 满会导致新连接失败。

```text
# 实测（本机路由表）
$ ip route show
default via 192.168.1.1 dev wlp0s20f3 proto dhcp src 192.168.1.167 metric 600 
172.17.0.0/16 dev docker0 proto kernel scope link src 172.17.0.1 
172.18.0.0/16 dev br-49cfcba0160f proto kernel scope link src 172.18.0.1 
172.19.0.0/16 dev br-3b8a83784ecf proto kernel scope link src 172.19.0.1 linkdown 
172.20.0.0/16 dev br-426e2d2c7b6e proto kernel scope link src 172.20.0.1 linkdown 
172.22.0.0/16 dev br-c61daaf2859b proto kernel scope link src 172.22.0.1 
192.168.1.0/24 dev wlp0s20f3 proto kernel scope link src 192.168.1.167 metric 600 
# default=DHCP 下发的默认网关；192.168.1.0/24=Wi-Fi 网段直连；
# 172.17.0.0/16、172.18.0.0/16 等=Docker 虚拟网桥（br-*），带 linkdown 的是没容器在用的桥
```

## 工作原理

### 路由决策的完整流程

内核收包/发包时做「路由查找（fib lookup）」，不是只查一张表，而是按 `ip rule` 的 priority 顺序依次尝试：

```text
1. priority 0   ：查 local 表（255）——本机地址、广播、组播等
                  （命中说明包是发给本机的，直接送上层协议栈，不转发）
2. priority N   ：用户自定义规则（ip rule add 的规则，如 fwmark/源地址分流）
3. priority 32766：查 main 表（254）——日常 ip route 看到的路由都在这里
4. priority 32767：查 default 表（253）——通常为空，留给特殊用途
```

**关键点**：`local` 表存本机地址路由（`ip route show table local` 能看到 `local 192.168.1.167 dev wlp0s20f3`），所以「发给本机自己 IP 的包」永远不会被转发出去——这就是「查 local → main」顺序的意义。

### 最长前缀匹配（Longest Prefix Match, LPM）

路由表里可能有多个条目都能「匹配」一个目标 IP，内核选**前缀最长（最具体）**的那条。前缀一样长时再比 metric（越小越优先）；metric 相同再比 scope（link < global）。

```text
最长前缀匹配：
目标 10.0.0.5
  default（0.0.0.0/0）     匹配，但前缀最短（0 位）
  10.0.0.0/8 via A         匹配，前缀 8 位 → 比 default 更具体
  10.0.0.0/16 via B        匹配，前缀 16 位 → 最具体，最终选这条

前缀长度优先于 metric：
  10.0.0.0/8  metric 100     ← 前缀 8 位，metric 大
  10.0.0.0/16 metric 200     ← 前缀 16 位，metric 也大
  目标 10.0.0.5 → 选 /16（前缀优先，metric 只在前缀相同时才比较）
```

### 转发流程（Linux 当路由器时）

```text
收包（目标不是本机）→ rp_filter 反向路径检查（可选）→ 查路由表定下一跳
→ TTL 减 1（TTL 为 0 则丢弃并回 ICMP Time Exceeded）→ 重写二层 MAC（下一跳/出口）
→ 从出口网卡发出（前提：ip_forward=1 且 FORWARD 链放行）
```

### 多路径路由（ECMP）与路由缓存

- 同一目标网段可以配多条 `nexthop`，形成等价多路径（Equal-Cost Multi-Path），内核按 hash（源/目标 IP 等）在多条链路上分摊流量，`ip route add default nexthop via A dev eth0 nexthop via B dev eth1`。
- 路由查找结果会进 FIB 缓存（`ip route get` 输出末尾的 `cache` 就是命中缓存），大流量转发场景关注缓存命中。

### 黑洞路由（blackhole / unreachable / prohibit）

- `ip route add blackhole 10.0.0.0/8`：匹配的包直接丢弃（不回复 ICMP）；
- `ip route add unreachable 10.0.0.0/8`：丢弃并回 ICMP Network Unreachable；
- `ip route add prohibit 10.0.0.0/8`：丢弃并回 ICMP Administratively Prohibited。
- 用途：屏蔽恶意网段、防环路、路由收敛前兜底、测试故障注入。

## 常用命令与配置

```shell
ip route                              # 查看主路由表（main）
ip route show table all               # 查看所有路由表
ip route show table local             # 本机地址路由表
ip route show default                 # 看默认网关
ip route show table 100               # 看自定义路由表
ip route get 8.8.8.8                  # 模拟查表：某个 IP 会走哪条路由（最常用排错命令）
ip route get 8.8.8.8 from 192.168.1.100  # 指定源地址查表（排策略路由用）

# 增删改（临时生效，重启丢失）
ip route add 10.0.0.0/8 via 192.168.1.254           # 加静态路由
ip route add 10.0.0.0/8 dev enp59s0                 # 直连式静态路由（不走网关）
ip route add default via 192.168.1.1                # 加默认路由
ip route add default via 192.168.1.1 metric 100     # 带 metric 的默认路由
ip route del 10.0.0.0/8                             # 删路由
ip route replace 10.0.0.0/8 via 192.168.1.253       # 存在则改、不存在则加
ip route flush table 100                            # 清空某张表
ip route change 10.0.0.0/8 via 192.168.1.252        # 改现有条目属性

# 多路径 ECMP
ip route add default nexthop via 192.168.1.1 dev wlp0s20f3 \
                          nexthop via 192.168.2.1 dev enp59s0

# 黑洞/精确路由
ip route add blackhole 10.0.0.0/8                   # 丢弃匹配包
ip route add unreachable 10.0.0.0/8                 # 丢弃 + ICMP unreachable

# IP 转发开关
cat /proc/sys/net/ipv4/ip_forward                   # 查看（1=开）
echo 1 > /proc/sys/net/ipv4/ip_forward              # 临时开启
sysctl -w net.ipv4.ip_forward=1                     # 等价写法
sysctl -p                                           # 从配置文件重载

# 策略路由
ip rule show                                        # 看路由策略（按 priority 排序）
ip rule add from 192.168.1.100 table 100            # 源 IP 走 table 100
ip rule add fwmark 0x1 table 100                    # 打标记的包走 table 100
ip rule add from 10.0.0.0/8 lookup 100 priority 100 # 指定优先级（越小越先匹配）
ip rule del from 192.168.1.100 table 100            # 删规则
ip route add default via 192.168.1.1 table 100      # 往自定义表里灌路由

# 传统命令（route/netstat）
route -n                                            # 经典格式查看路由表
route add -net 10.0.0.0/8 gw 192.168.1.254          # 老式添加（不推荐，用 ip route）
```

```text
# 实测（本机 ip rule，能看到 Tailscale 注入的策略规则）
$ ip rule show
0:	from all lookup local
5210:	from all fwmark 0x80000/0xff0000 lookup main
5230:	from all fwmark 0x80000/0xff0000 lookup default
5250:	from all fwmark 0x80000/0xff0000 unreachable
5270:	from all lookup 52
32766:	from all lookup main
32767:	from all lookup default
# priority 0 查 local 表；5210~5270 是 Tailscale 注入的规则（fwmark 0x80000 是
# Tailscale 的流量标记，table 52 是 Tailscale 自己的路由表）；
# 32766/32767 是内核内置的 main/default 兜底。
```

```text

$ ip route get 8.8.8.8
```

## 配置文件解析


## 应用场景实战

### 场景一：排查「能上内网不能上外网」

```shell
# 1. 看默认网关有没有
ip route show default
# 2. 测网关连通
ping -c 2 192.168.1.1
# 3. 测外网（网关通、外网不通 = 网关/上游问题）
ping -c 2 8.8.8.8
# 4. 确认 DNS 没问题（解析不出 IP 也可能表现为「上不了网」）
getent hosts baidu.com

# 排查结论表：
# 本网段通 + 网关不通        → 二层/网关问题（AP、交换机、网关宕机）
# 网关通 + 8.8.8.8 不通      → 网关的上游链路/运营商问题
# 8.8.8.8 通 + 域名不通      → DNS 问题，不是路由问题
# 都通但网页打不开          → 应用层/防火墙问题
```

### 场景二：让 Linux 当 NAT 网关（开启转发）

把一台双网卡 Linux 变成内网机器的出口网关：内网口 eth1（192.168.10.1/24）接内网，外网口 enp59s0 接公网。

```shell
# 1. 开启 IP 转发（临时 + 持久化）
sysctl -w net.ipv4.ip_forward=1
echo 'net.ipv4.ip_forward=1' > /etc/sysctl.d/99-forward.conf && sysctl -p

# 2. 配 NAT（MASQUERADE：出口 IP 动态，适合拨号/家用宽带）
iptables -t nat -A POSTROUTING -s 192.168.10.0/24 -o enp59s0 -j MASQUERADE

# 3. 放行 FORWARD（很多发行版默认 DROP）
iptables -A FORWARD -i eth1 -o enp59s0 -j ACCEPT
iptables -A FORWARD -i enp59s0 -o eth1 -m state --state RELATED,ESTABLISHED -j ACCEPT

# 4. 内网机器把网关指到 192.168.10.1 即可上网
# 固定出口 IP 用 SNAT 更明确：
iptables -t nat -A POSTROUTING -s 192.168.10.0/24 -o enp59s0 -j SNAT --to-source 1.2.3.4

# 5. 持久化 iptables（Ubuntu）
apt install iptables-persistent && netfilter-persistent save
```

### 场景三：策略路由实现双线/多出口分流

公司有两条出口：电信线 eth0（默认）、联通线 eth1；要求研发网段 192.168.20.0/24 走联通，其他走电信。

```shell
# 1. 定义路由表名
echo "100 unicom" >> /etc/iproute2/rt_tables

# 2. 往联通表里灌路由（默认路由 + 回程网段）
ip route add default via 192.168.2.1 dev eth1 table unicom
ip route add 192.168.20.0/24 dev eth1 scope link table unicom

# 3. 加策略规则：源地址匹配走联通表
ip rule add from 192.168.20.0/24 lookup unicom

# 4. 验证：指定源地址查表
ip route get 8.8.8.8 from 192.168.20.5
# 8.8.8.8 via 192.168.2.1 dev eth1 ...   ← 走了联通线

# 注意：还要配 SNAT/MASQUERADE，让 192.168.20.0/24 的包以 eth1 的 IP 出去
iptables -t nat -A POSTROUTING -s 192.168.20.0/24 -o eth1 -j MASQUERADE
# 如果开了 rp_filter 严格模式，双向都要有对应路由，否则回包被丢
```

```shell
# fwmark 标记分流（按应用打标记，适合「指定进程走代理/VPN」）
iptables -t mangle -A OUTPUT -m owner --uid-owner 1000 -j MARK --set-mark 0x1
ip rule add fwmark 0x1 lookup 200
ip route add default via 192.168.3.1 dev eth2 table 200
# Tailscale/WireGuard 就是这么干的：所有隧道流量打 fwmark，走独立路由表
```

### 场景五：黑洞路由屏蔽恶意/抢占网段

## 性能与调优

```text
1. 路由查找 —— 内核用 LPM trie 查表，普通规模路由表查找是 O(1) 级，
   但 ip rule 规则过多会退化成线性扫描，规则要精简有序
2. 转发性能 —— 网关/NAT 机器关掉不必要的服务，让 CPU 专注转发；
   ip_forward 开启后大流量转发建议看软中断分布（mpstat）
3. conntrack —— NAT 依赖连接跟踪，高并发调大 net.netfilter.nf_conntrack_max，
   并监控 conntrack 使用率（满了会丢新连接）
4. 网卡多队列 —— 转发吞吐大时用多队列网卡 + 中断亲和（irqbalance），分散 CPU
5. 多路径哈希 —— 多出口 ECMP 时调 fib_multipath_hash_policy，让同一连接固定走同一条
   （policy 0 按目的 IP，policy 1 按源+目的 IP，避免跨线路连接错乱）
6. rp_filter 代价 —— 严格模式每个转发包多一次反向查表，内网可信环境可保持 loose(2)
```

```shell
sysctl net.netfilter.nf_conntrack_max                      # 看连接跟踪上限
sysctl net.netfilter.nf_conntrack_count                    # 看当前连接数
sysctl -w net.netfilter.nf_conntrack_max=1048576           # 调大（临时）
echo 'net.netfilter.nf_conntrack_max=1048576' > /etc/sysctl.d/99-nat.conf
sysctl net.ipv4.fib_multipath_hash_policy                  # ECMP 哈希策略
sysctl -w net.ipv4.fib_multipath_hash_policy=1
```

```text
# 实测（本机 rp_filter 默认值）
$ sysctl net.ipv4.conf.all.rp_filter
net.ipv4.conf.all.rp_filter = 2
# 2 = loose 松散模式（Ubuntu 默认），1 = strict 严格模式
# 严格模式要求「包的入接口 == 回包路由的出口」，多网卡环境容易误杀，
# 双线负载/多出口环境建议保持 2 或 0，并靠防火墙做源地址校验
```

## 安全与权限

```text
1. 默认网关是信任边界 —— 恶意网关可劫持所有出外网流量（改默认网关=中间人），别乱指
2. NAT 暴露面 —— 转发内网流量时注意别把内网服务误暴露到公网；
   DNAT 只映射需要的端口，FORWARD 链默认 DROP 白名单放行
3. 反向路径过滤 rp_filter —— 丢弃源地址伪造的包，防 IP 欺骗
4. 策略路由防泄漏 —— 多网卡分流时确保敏感流量走加密通道（VPN），别漏到公网；
   Tailscale/WireGuard 用 fwmark + 独立路由表 + unreachable 兜底防泄漏（见本机 ip rule）
5. ICMP redirect 攻击 —— 伪造的 ICMP Redirect 可篡改路由，服务器上建议
   net.ipv4.conf.all.accept_redirects=0
6. 转发权限 —— 只有 root 能改 ip_forward 和路由表；改路由表要 sudo
7. 路由协议 —— 生产环境跑动态路由（OSPF/BGP）用独立设备或专用 daemon，
   注意认证（OSPF MD5、BGP MD5/TCP-AO）防路由注入
```

```shell
sysctl net.ipv4.conf.all.rp_filter                 # 看反向路径过滤（1=严格/2=松散）
sysctl -w net.ipv4.conf.all.rp_filter=1            # 临时开严格模式
echo 'net.ipv4.conf.all.accept_redirects=0' > /etc/sysctl.d/99-sec.conf
sysctl -p
```

## 故障排查

### 子案例一：跨网段不通（ip route get 定位法）

```shell
# 1. 看目标网段有没有路由、会走哪条
ip route get 10.0.0.5
# 输出 "unreachable" → 没有匹配路由（没配静态路由，也没有默认路由兜底）
# 2. 看默认网关
ip route show default
# 3. 测网关连通
ping -c 2 <网关>
# 4. 有路由但 ping 不通 → 逐跳排查（traceroute 看包丢在哪一跳）
traceroute -n 10.0.0.5
```

### 子案例二：能上内网不能上外网

```shell
# 1. 确认默认路由存在
ip route show default
# 2. 确认网关通
ping -c 2 192.168.1.1
# 3. 网关通但外网不通 → 问题在网关上游/运营商/防火墙
ping -c 2 8.8.8.8
# 4. 也可能是 DNS：8.8.8.8 通但域名不通 → getent hosts 排查 DNS
# 5. 本机是网关的话，再查转发开关和 FORWARD 链
cat /proc/sys/net/ipv4/ip_forward
iptables -L FORWARD -n -v          # 看 FORWARD 默认策略和计数
```

### 子案例三：Linux 网关/容器转发不生效

```shell
# 症状：内网机器/容器访问外网不通
# 1. 转发开关
cat /proc/sys/net/ipv4/ip_forward        # 必须是 1
# 2. FORWARD 链是否放行（Docker 会插自己的规则，自定义网关注意默认策略）
iptables -L FORWARD -n -v | head
# 3. NAT 规则是否存在（少了 MASQUERADE/SNAT，回包不会回来）
iptables -t nat -L POSTROUTING -n -v
# 4. rp_filter 是否误杀（多网卡时严格模式常见）
sysctl net.ipv4.conf.all.rp_filter
# 5. conntrack 是否打满
sysctl net.netfilter.nf_conntrack_count net.netfilter.nf_conntrack_max
# 6. 抓包对比：内网口有 SYN、外网口没有 → 路由/转发问题；
#    外网口有 SYN 无 SYN-ACK → NAT 或上游问题
tcpdump -i eth1 -n 'tcp port 80'
tcpdump -i enp59s0 -n 'tcp port 80'
```

### 子案例四：策略路由不生效

```shell
# 症状：ip rule 加了规则，流量还是走默认路由
# 1. 确认规则存在且顺序正确（priority 越小越先匹配，精确规则别排在宽泛规则后面）
ip rule show
# 2. 确认目标表里有路由（表空 = 规则命中也白搭）
ip route show table 100
# 3. 指定源地址模拟查表（-o 看走哪条）
ip route get 8.8.8.8 from 192.168.1.100
# 4. 确认应用真的用了那个源地址（有些应用绑定特定源 IP，多出口环境常见）
ip route get 8.8.8.8 from 192.168.1.167
# 5. 检查 rp_filter：分流后回包从别的接口进来，严格模式会丢
```

### 子案例五：路由环路与 TTL

```shell
# 症状：ping 外网报 "Time to live exceeded"
# 1. 环路一定发生在某两台设备互相指对方为下一跳，traceroute 看包在哪两跳间打转
traceroute -n 8.8.8.8
# 2. 检查本机有没有指向错误网关的路由（比如把默认网关指到了路由器内部地址）
ip route show default
# 3. TTL 是防环路的最后手段：每转发一跳 TTL-1，减到 0 丢弃并回 ICMP，
#    环路最多打转 255 跳就会被 TTL 掐死，不会无限循环
# 4. 临时缓解：黑洞路由兜住环路的网段
ip route add blackhole 10.0.0.0/8
```

## 常见问题

```text
Q1: 能上内网不能上外网？
A: 默认网关没配或配错。ip route show default 确认，ip route add default via 网关 补上；
   网关通但外网不通则是网关上游/运营商的问题。

Q2: 加了静态路由重启后没了？
A: ip route add 是临时的，不落盘。持久化写 netplan 的 routes: 段、
   NetworkManager（nmcli connection modify +ipv4.routes）或 route-<iface> 文件。

Q3: 容器网络不通？
A: 主机 ip_forward=0，内核不转发容器数据包。sysctl -w net.ipv4.ip_forward=1 开转发并
   写入 /etc/sysctl.d/ 持久化；再确认 FORWARD 链放行。

Q4: 两个默认网关导致网络时好时坏？
A: 多个 default 路由内核按 metric 选（相等时随机/哈希），可能选错。只留一个默认网关，
   或用 metric 明确优先级，或用 ip rule 按源地址分流。

Q5: ip route add 报 "Nexthop has invalid gateway"？
A: 下一跳必须与本机某网卡同网段。比如本机 192.168.1.167/24，下一跳写 10.0.0.1
   就会报这个错——先保证网卡上配了对应网段的 IP，或改走 dev 直连式路由。

Q6: 多网卡机器某些网段丢包/不通，rp_filter 严格模式误杀？
A: 严格模式要求包的入接口与回包路由出口一致，多出口环境容易误判。
   改为 loose(2) 或关掉(0)，或在 ip rule 里为回程流量补路由。

Q7: NAT 网关下内网机器访问不了网关自身映射的公网服务（NAT 回流）？
A: 内网机器访问公网 IP 的 DNAT 服务时，回包路由走内网接口，NAT 会话对不上。
   解法：加 hairpin NAT（内网访问也做 SNAT），或让内网直接用内网 IP 访问。

Q8: Docker 重启后自定义 iptables/路由丢失？
A: Docker 启动时会重写 iptables 并管理自身路由，手改的规则会被覆盖。
   自定义规则写到 iptables-persistent / docker-compose 的 iptables 配置里，
   别和 Docker 的规则混在一起手改。
```

## 面试题

```text
1. 路由选择的原则是什么？
   答：最长前缀匹配（LPM）——在能匹配目标网段的路由里，选前缀最长（最具体）的一条；
   前缀相同时比 metric（越小越优先），再比 scope。

2. 默认网关的作用？没有默认网关会怎样？
   答：default 路由（0.0.0.0/0）是兜底，访问非本网段（外网）时走它。
   没配默认网关只能访问本网段（直连路由覆盖的网段），外网包无路由可查被丢弃。

3. IP 转发是干嘛的？什么时候要开？
   答：让内核转发「不是发给本机」的数据包，即让 Linux 当路由器。
   做网关/NAT/软路由/容器网络（Docker、K8s node）时要开 net.ipv4.ip_forward=1。

4. 策略路由和普通路由的区别？
   答：普通路由只看目标地址，一套路由表；策略路由按源地址/端口/tos/fwmark 等多条件
   匹配，用 ip rule + 多路由表（main/自定义表）分流，适合双线、VPN 分流、多出口场景。

5. metric 和前缀长度，哪个优先？
   答：前缀长度优先。metric 只在目标网段完全相同时才比较；前缀更长意味着更精确的匹配。

6. SNAT 和 MASQUERADE 的区别？
   答：SNAT 指定固定出口 IP（--to-source 1.2.3.4），适合出口 IP 固定的机房环境；
   MASQUERADE 动态取出口网卡当前 IP（-o 指定接口即可），适合拨号/动态 IP，
   代价是每次都要查出口 IP，性能略低。

7. 路由环路是怎么产生的？怎么防？
   答：两台设备互相把对方指为下一跳（或网关配置错误），包在环里打转。
   防：TTL 每跳减一、减到 0 丢弃（这是最终兜底）；排查用 traceroute 找打转的跳数；
   管理上规范网关配置、动态路由协议防环机制（OSPF 区域设计、BGP AS 路径）。

8. 黑洞路由有什么用？
   答：把某网段路由指向 blackhole/unreachable，匹配的包直接丢弃，用于屏蔽恶意流量、
   路由收敛前兜底、防环路。比 iptables DROP 更早拦截（在路由层就丢弃）。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 上不了外网先查默认网关，再查 IP 转发（如果本机当网关）
2. 排路由问题先 `ip route get <目标IP>` —— 一步看出「有没有路由、走哪、源地址是谁」
3. 加静态路由用 `ip route add` 临时验证，确认有效后立刻持久化（netplan/NM/route-文件）
4. 容器网络依赖 IP 转发，跑 Docker/K8s 的机器 ip_forward 必须是 1
5. 策略路由先画清分流矩阵（条件 → 表 → 路由 → NAT），再动手配 ip rule
6. 多出口/NAT 环境注意 rp_filter 用 loose 模式，配好回程路由，避免玄学丢包
7. 修改系统路由前备份：`ip route show > /tmp/route-backup.txt`，出问题秒级恢复
8. 生产环境的默认路由、静态路由变更走变更记录，别在高峰期裸改

### 踩坑记录

```text
坑 1：能上内网不能上外网，默认网关没配
结论：ping 本网段通，ping 8.8.8.8 不通。
原因：没有默认路由，外网包不知道往哪发。
解法：ip route add default via 网关，或配静态 IP 时设网关（netplan gateway4/routes）。

坑 2：ip route add 的路由重启后消失
结论：加了静态路由，重启没了。
原因：ip route add 是临时的，不持久化。
解法：持久化写 netplan/NetworkManager/route-<iface>，验证命令只用于测试。

坑 3：容器网络不通，忘了开 IP 转发
结论：Docker 容器能启动但访问不了外网。
原因：主机 ip_forward=0，内核不转发容器数据包。
解法：sysctl net.ipv4.ip_forward=1，写 /etc/sysctl.d/99-forward.conf 持久化。

坑 4：两条默认路由导致路由混乱
结论：配了两个默认网关，网络时好时坏。
原因：多个 default 路由，内核按 metric 选，metric 相同时可能随机选。
解法：只留一个默认网关，或用 metric 区分优先级，或用 ip rule 分流。

坑 5：策略路由配了不生效
结论：ip rule 加了规则，流量还是走默认路由。
原因：规则匹配顺序/条件不对（精确规则排在宽泛规则后面），或目标路由表是空的。
解法：ip rule show 确认规则顺序，ip route show table 确认表里有路由，
      ip route get <ip> from <源IP> 模拟查表验证。

坑 6：下一跳不在直连网段，路由加不上
结论：ip route add 报 "Nexthop has invalid gateway"。
原因：via 的下一跳必须和本机某网卡同网段，否则内核无法二层寻址。
解法：先给网卡配对应网段的 IP，或改用 dev 直连式路由（不指定 via）。

坑 7：rp_filter 严格模式误杀多网卡/多出口流量
结论：多网卡机器某些网段 ping 不通，抓包发现包发出去了但没回包。
原因：strict 模式要求入接口与回包路由出口一致，分流环境回包从别的口进，被丢。
解法：sysctl net.ipv4.conf.all.rp_filter=2（loose）或 0，靠防火墙做源校验。

坑 8：NAT 网关内网访问不了自己映射的服务（NAT 回流/hairpin）
结论：公网访问正常，内网访问网关映射的公网 IP 不通。
原因：内网请求经 DNAT 后回包路由走了内网接口，conntrack 会话对不上。
解法：加 hairpin 规则（内网访问也 SNAT），或内网直接用内网 IP 访问。

坑 9：Docker 重启覆盖了自定义 iptables 规则
结论：手动加的 NAT/FORWARD 规则在 docker restart 后消失。
原因：Docker 启动时重建自己的 iptables 链和规则，覆盖手工修改。
解法：规则写入 iptables-persistent（netfilter-persistent save），
      或纳入 docker-compose/编排管理，避免手工改 Docker 管理的链。

坑 10：改路由表忘记备份，出问题回滚困难
结论：误删/误改路由后网络中断，手忙脚乱。
原因：路由操作即时生效且不提示。
解法：操作前 ip route show > 备份文件；远程操作务必留一个带外通道或
      定时任务兜底恢复（如 crontab 每 5 分钟检查默认路由存在性）。
```

## 概述

firewalld 和 ufw 是「iptables/nftables 的高层封装」——用更简单的概念（区域/服务）管理防火墙，底层还是 iptables/nftables。firewalld 是 Red Hat 系默认（CentOS/RHEL/Fedora），用「区域 zone」管理；ufw 是 Ubuntu 的简化前端，用「放行/拒绝端口」管理。两者都降低了直接用 iptables 的复杂度。

```text
# 实测（本机两者都没用）
$ ufw status
状态：不活动
$ command -v firewall-cmd || echo "firewalld 未安装"
firewalld 未安装
# 本机直接用 iptables/nftables（Docker/tailscale/1Panel 管理），没启用高层封装
```

```text
firewalld vs ufw：
1. firewalld —— Red Hat 系默认，区域 zone + 服务 service 概念
2. ufw —— Ubuntu 简化前端，放行/拒绝端口，命令极简
3. 共同点 —— 都是 iptables/nftables 的封装，底层一样
```

## 核心概念

1. **区域 zone（firewalld）**：一组规则的集合（public、home、internal、dmz、trusted 等）。网卡绑定到某个 zone，就应用该 zone 的规则。默认 zone 是 public（只放行 SSH 等）。
2. **服务 service（firewalld）**：预定义的端口组合（ssh=22、http=80、https=443），放行一个服务等于放行它对应的端口。
3. **ufw 的极简模型**：默认「拒绝入站、放行出站」，用 `ufw allow 端口/服务` 放行。命令直白，适合简单场景。
4. **富规则 rich rule（firewalld）**：用更细的条件（源地址 + 端口 + 动作）写规则，比 service/port 灵活。
5. **直接规则 direct rule（firewalld）**：透传 iptables 规则，用于 firewalld 表达不了的场景（最后的逃生舱）。

```text
firewalld 三层规则：
1. service/port —— 简单（放行服务或端口）
2. 富规则 rich rule —— 灵活（源 + 端口 + 动作组合）
3. 直接规则 direct —— 透传 iptables，最后手段
```

## 工作原理

firewalld 和 ufw 本质是「规则翻译器」——把高层概念（zone/service/端口）翻译成底层 iptables/nftables 规则：

1. **firewalld**：zone 定义一组规则，网卡绑 zone 后，firewalld 把该 zone 的规则写入 iptables/nftables 的对应链。firewalld 自己管理 iptables 规则（这就是为什么手动改 iptables 会跟它冲突）。`--permanent` 写入配置文件（/etc/firewalld/zones/），`--reload` 重新加载到运行时。
2. **ufw**：把「allow/deny 端口」翻译成 iptables 规则，写入 /etc/ufw/user.rules。`ufw enable` 时加载这些规则并设默认策略。
3. 两者都是「前台」——真正的包过滤还是内核 netfilter 干的，用 `iptables -L` 或 `nft list ruleset` 能看到它们生成的底层规则。

```text
封装层级：
firewalld / ufw（高层概念：zone/service/端口）
        ↓ 翻译成
iptables / nftables（规则：匹配 + 动作）
        ↓ 写入
netfilter（内核包过滤框架）
```

## 常用命令与配置

firewalld（Red Hat 系）：

```shell
firewall-cmd --state                     # 状态
firewall-cmd --get-default-zone          # 默认区域
firewall-cmd --list-all                  # 看当前区域规则
firewall-cmd --add-service=http --permanent   # 放行 http 服务
firewall-cmd --add-port=8080/tcp --permanent  # 放行端口
firewall-cmd --reload                    # 重载生效
firewall-cmd --get-active-zones          # 看哪些网卡绑了哪些 zone
```

ufw（Ubuntu）：

```shell
ufw status                  # 状态（inactive 未启用）
ufw status verbose          # 详细状态（含默认策略）
ufw enable                  # 启用（默认拒绝入站）
ufw allow 22                # 放行 SSH
ufw allow 80,443/tcp        # 放行 Web
ufw allow from 192.168.1.0/24   # 放行某网段
ufw delete allow 22         # 删除规则
ufw disable                 # 停用
```

```text
富规则 / 直接规则（firewalld 高级）：
# 富规则：允许 192.168.1.100 访问 3306 端口
firewall-cmd --add-rich-rule='rule family="ipv4" source address="192.168.1.100" port protocol="tcp" port="3306" accept' --permanent
# 直接规则：透传 iptables
firewall-cmd --direct --add-rule ipv4 filter INPUT 0 -p tcp --dport 8443 -j ACCEPT
```

## 配置文件解析

firewalld 配置在 /etc/firewalld/（zone 用 XML），ufw 在 /etc/ufw/（规则用文本）。

```xml
<!-- /etc/firewalld/zones/public.xml（默认 zone） -->
<?xml version="1.0" encoding="utf-8"?>
<zone>
  <short>Public</short>
  <description>For use in public areas.</description>
  <service name="ssh"/>        <!-- 放行的服务 -->
  <port port="80" protocol="tcp"/>   <!-- 放行的端口 -->
</zone>
```

```text
# /etc/ufw/ 目录结构
ufw.conf          # ufw 主配置（ENABLED=yes 表示启用）
user.rules        # 用户规则（ufw allow 生成，翻译成 iptables）
user6.rules       # IPv6 规则
```

```text
firewalld 配置要点：
1. /etc/firewalld/zones/*.xml  每个 zone 一个 XML 文件
2. --permanent 写入 XML，--reload 从 XML 加载到运行时
3. ufw 的 user.rules 是 ufw allow 生成的底层规则
```

## 应用场景实战

### 场景一：CentOS 用 firewalld 放行 Web 和 SSH

```shell
# 1. 启用并放行服务
systemctl enable --now firewalld
firewall-cmd --add-service=ssh --permanent
firewall-cmd --add-service=http --permanent
firewall-cmd --add-service=https --permanent
firewall-cmd --reload
# 2. 验证
firewall-cmd --list-all
```

### 场景二：Ubuntu 用 ufw 放行服务端口

```shell
# 1. 启用（默认拒绝入站）
ufw enable
# 2. 放行 SSH 和 Web
ufw allow 22
ufw allow 80,443/tcp
# 3. 验证
ufw status verbose
```

## 性能与调优

```text
1. 规则数量 —— firewalld/ufw 生成的规则最终落在 iptables/nftables，规则少则匹配快
2. 避免重复 zone —— 同一网卡只绑一个 zone，多个 zone 规则会叠加
3. ufw 简单场景 —— 只放行必要端口，别堆一堆规则
4. firewalld 高并发 —— 底层是 nftables 后端时性能更好（RHEL8+/CentOS8+）
5. 直接规则慎用 —— direct 规则绕过 firewalld 管理，多了难维护，能不用就不用
```

## 安全与权限

```text
1. 默认策略 —— firewalld 默认 zone（public）只放行 ssh，ufw 默认拒绝入站（最小权限）
2. 远程操作 —— 启用前先放行 SSH（ufw allow 22 再 enable），否则锁自己
3. 绑定网卡 —— firewalld 按网卡绑 zone，公网网卡绑 public（严）、内网绑 internal/trusted（松）
4. 富规则限源 —— 敏感端口（数据库 3306）用富规则限定来源 IP，别全网放行
5. 别绕过封装 —— 统一用 firewalld/ufw 管理，手动改 iptables 会跟它冲突
```

## 故障排查

### firewalld 规则不生效

```shell
# 1. 看服务状态
systemctl status firewalld
# 2. 看当前生效规则（--permanent 但没 --reload 则不生效）
firewall-cmd --list-all
# 3. 看网卡绑的 zone 对不对
firewall-cmd --get-active-zones
```

### ufw 启用后 SSH 断了

```shell
# 1. 确认 ufw 状态和规则
ufw status verbose
# 2. 看 SSH 端口是否放行
ufw status | grep 22
# 3. 没放行则补（控制台或救援模式）
ufw allow 22
```

## 常见问题

```text
Q1: firewalld 改了规则为什么不生效？
A: 没加 --permanent（规则是临时的），或加了 --permanent 但没 --reload。要 --permanent + --reload 才能持久化并生效。

Q2: ufw 和 firewalld 能同时用吗？
A: 不建议。两者都管理底层 iptables，会冲突。选一个用（Ubuntu 用 ufw，CentOS 用 firewalld）。

Q3: ufw 能配复杂规则（NAT/端口转发）吗？
A: 不能，ufw 只做简单的放行/拒绝。复杂规则（NAT/端口转发）要用 iptables/nftables 或 firewalld 的直接规则。

Q4: firewalld 和 iptables 手动规则为什么打架？
A: firewalld 自己管理 iptables 规则，手动改 iptables 会和 firewalld 的规则冲突。统一用 firewalld 管理。
```

## 面试题

```text
1. firewalld 和 ufw 的本质是什么？
   答：都是 iptables/nftables 的高层封装，把 zone/service/端口 等概念翻译成底层 iptables/nftables 规则，内核 netfilter 才真正过滤。

2. firewalld 的 zone 是什么？
   答：zone 是一组规则的集合，网卡绑定到某个 zone 就应用该 zone 的规则。默认 public zone 只放行 SSH 等基本服务。

3. firewalld 的 --permanent 和 --reload 有什么作用？
   答：--permanent 把规则写入配置文件（持久化，但不立即生效），--reload 从配置文件重新加载到运行时。要两者配合。

4. ufw 的默认策略是什么？
   答：拒绝入站、放行出站。启用后外部连不进来，需要 ufw allow 放行具体端口。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 简单场景用 ufw（Ubuntu）/firewalld（CentOS），复杂规则直接 iptables/nftables
2. firewalld 改规则用 --permanent + --reload，否则重启丢失
3. 远程改防火墙先放行 SSH 再启用，否则把自己锁外面
4. 默认区域（public）只放行必要服务，别全放
5. 理解 firewalld/ufw 都是 iptables 封装，底层规则用 iptables -L 能看到

### 踩坑记录

```text
坑 1：firewalld 改规则没 --permanent，重启后丢失
结论：firewall-cmd --add-port 后重启，端口又没了。
原因：没加 --permanent，规则是临时的（运行时）。
解法：加 --permanent 持久化，再 --reload 生效。

坑 2：ufw enable 后 SSH 断了
结论：启用 ufw 后远程 SSH 连不上。
原因：ufw 默认拒绝入站，没先放行 22 端口。
解法：先 ufw allow 22，再 ufw enable。

坑 3：firewalld 和 iptables 手动规则混用冲突
结论：手动 iptables 规则和 firewalld 规则打架。
原因：firewalld 自己管理 iptables，手动改会和它冲突。
解法：统一用 firewalld 管理，别绕过它手动改 iptables。

坑 4：ufw 和 Docker 冲突
结论：启用 ufw 后 Docker 容器网络异常。
原因：ufw 和 Docker 都管 iptables，规则可能互相干扰。
解法：理解 Docker 的 iptables 行为，或用 DOCKER-USER 链自定义。

坑 5：firewalld --reload 把运行时规则清了
结论：--reload 后没加 --permanent 的运行时规则没了。
原因：--reload 重新加载永久规则，运行时临时规则丢失。
解法：所有要保留的规则都加 --permanent。
```

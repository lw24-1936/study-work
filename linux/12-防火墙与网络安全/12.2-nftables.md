## 概述

nftables 是 netfilter 框架的新一代用户态工具，取代 iptables/ip6tables/arptables/ebtables 四件套，用一套语法统一管理 IPv4/IPv6/ARP/桥接的过滤。nft 命令语法更简洁、性能更好（内核级一次匹配）。现代系统（Ubuntu 20.04+、CentOS 8+）默认用 nftables 作为 iptables 的后端（iptables 命令实际翻译成 nft 规则）。理解 nft 才能看懂新系统的防火墙。

```text
# 实测（本机 nftables 规则，Ubuntu 用 nft 作为 iptables 后端）
$ nft list ruleset | head
table ip filter {
    chain INPUT {
        type filter hook input priority filter; policy accept;
        counter packets 13512001 bytes 5768215729 jump ts-input
    }
    ...
}
# iptables 规则底层就是 nft，nft list ruleset 能看到真实规则
```

## 核心概念

1. **表 table**：按地址族（family）划分，常用 ip（仅 IPv4）、ip6（仅 IPv6）、inet（同时管 IPv4+IPv6）、bridge（桥接）。表可以自由命名（不像 iptables 只有固定 5 张表）。
2. **链 chain**：有 type + hook 定义「在哪个关卡处理」（如 type filter hook input = 进本机时过滤），priority 决定同 hook 下的执行顺序。链分「基链」（挂在 hook 上）和「常规链」（被 jump 调用，相当于 iptables 的自定义链）。
3. **规则 rule**：匹配条件（ip saddr、tcp dport）+ 动作（accept/drop/counter/jump）。用 handle 唯一标识，删规则按 handle 不按行号。
4. **与传统 iptables 对比**：nftables 语法统一（一套管 IPv4/IPv6/ARP/桥接）、性能更好（内核一次匹配）、更灵活（表可自定义）。

```text
# 实测（nft 的 Docker 链规则，比 iptables 更可读）
$ nft list ruleset | grep -A2 'chain DOCKER'
chain DOCKER {
    ip daddr 172.18.0.6 ... tcp dport 3306 ... accept   # MySQL
    ip daddr 172.18.0.4 ... tcp dport 5432 ... accept   # PostgreSQL
    ip daddr 172.18.0.7 ... tcp dport 5672 ... accept   # RabbitMQ
}
```

```text
nftables 三要素：
1. 表 table —— 按地址族（ip/ip6/inet），inet 同时管 IPv4+IPv6
2. 链 chain —— type + hook（input/forward/output）+ priority
3. 规则 rule —— 匹配（ip daddr/tcp dport）+ 动作（accept/drop）
```

## 工作原理

nftables 复用 netfilter 内核框架，但把四套工具（iptables/ip6tables/ebtables/arptables）的规则统一到一套内核表达：

1. **内核一次匹配**：nft 把规则编译成字节码，内核用虚拟机的匹配引擎一次性解释，规则多时比 iptables 的逐规则遍历更快。
2. **hook 与 priority**：链通过 hook（input/forward/output/prerouting/postrouting）挂到 netfilter 的关卡上，priority 决定同一关卡多条链的先后顺序（如 -100 先于 0 先于 100）。
3. **iptables 兼容层**：新系统的 iptables 命令实际是「iptables-nft」后端——iptables 语法被翻译成 nft 规则存进内核，所以 `nft list ruleset` 能看到 iptables 配的规则。

```text
nftables vs iptables：
1. 语法 —— nft 统一一套，iptables 分 iptables/ip6tables/ebtables 四套
2. 性能 —— nft 内核一次匹配更快，规则多时优势明显
3. 可读性 —— nft 用 ip daddr/tcp dport，比 iptables -s/--dport 清晰
4. 兼容 —— 新系统 iptables 命令是 nft 后端，规则底层是 nft
```

## 常用命令与配置

```shell
nft list ruleset              # 查看全部规则
nft -a list ruleset           # 带 handle（删规则用）
nft add table ip filter       # 建表
nft add chain ip filter INPUT '{ type filter hook input priority 0; policy accept; }'
nft add rule ip filter INPUT tcp dport 22 accept   # 放行 SSH
nft delete rule ip filter INPUT handle 3           # 删规则（按 handle）
nft flush ruleset             # 清空所有规则
nft list table inet myfilter  # 只看某张表
```

```shell
# 等价对比
iptables -A INPUT -p tcp --dport 22 -j ACCEPT
nft add rule ip filter INPUT tcp dport 22 accept
```

```text
nft 语法要点：
1. add/delete/list 三动作，操作对象是 表/链/规则
2. 匹配用 ip saddr / tcp dport / ct state，动作用 accept/drop/counter
3. 删规则用 handle（nft -a 查看），不是行号
```

## 配置文件解析

nftables 规则用 `nft list ruleset` 导出，保存到 /etc/nftables.conf，由 nftables 服务开机加载。配置文件就是 `nft` 脚本语法，可直接手写。

```text
# /etc/nftables.conf 结构
#!/usr/sbin/nft -f          # 用 nft -f 执行本文件
flush ruleset               # 先清空，保证幂等

table inet filter {
    chain input {
        type filter hook input priority 0; policy drop;
        ct state established,related accept
        iif lo accept
        tcp dport 22 accept
        tcp dport {80, 443} accept
    }
    chain forward {
        type filter hook forward priority 0; policy drop;
    }
    chain output {
        type filter hook output priority 0; policy accept;
    }
}
```

```text
字段含义：
flush ruleset   清空现有规则（避免重复叠加）
table inet      inet 族表，同时管 IPv4+IPv6
type ... hook   chain 挂到哪个 netfilter 关卡
policy drop     链的默认策略（未匹配的包怎么处理）
{80, 443}       集合语法，一条规则匹配多个端口
```

```shell
nft list ruleset > /etc/nftables.conf    # 导出规则持久化
nft -f /etc/nftables.conf                # 加载配置文件
systemctl enable --now nftables          # 开机自动加载
```

## 应用场景实战

### 场景一：用 nft 配基础防火墙（只放行 SSH/Web）

```shell
# 1. 建表和链
nft add table inet myfilter
nft add chain inet myfilter input '{ type filter hook input priority 0; policy drop; }'
# 2. 放行已建立连接和回环
nft add rule inet myfilter input ct state established,related accept
nft add rule inet myfilter input iif lo accept
# 3. 放行 SSH/Web
nft add rule inet myfilter input tcp dport 22 accept
nft add rule inet myfilter input tcp dport {80, 443} accept
```

### 场景二：查看和清空规则

```shell
# 1. 查看全部规则
nft list ruleset
# 2. 只看某张表
nft list table inet myfilter
# 3. 清空（慎用，会删所有规则）
nft flush ruleset
```

## 性能与调优

```text
1. 规则分组 —— 命中率高的规则放前面（如 ct state established 放最前）
2. 用集合 set —— 多个端口/IP 放一个 set 里，一条规则匹配（比多条规则快）
3. 用 inet 族 —— 一套规则管 IPv4+IPv6，省一半规则量
4. 避免冗余规则 —— nft 规则少时性能差异小，关键是别堆几十上百条无用规则
5. 计数器开销 —— counter 有统计开销，纯过滤场景可省略
```

```shell
# 用 set 批量匹配（比逐条 add rule 高效）
nft add set inet myfilter allowed_ports '{ type inet_service; }'
nft add element inet myfilter allowed_ports '{ 22, 80, 443, 8080 }'
nft add rule inet myfilter input tcp dport @allowed_ports accept
```

## 安全与权限

```text
1. 默认策略 —— 链 policy drop，只放行必要端口（最小权限）
2. 连接跟踪 —— ct state established,related 放行已建立连接，新连接才走规则
3. 限速防爆破 —— limit rate 限制连接速率，防 SSH 爆破
4. 规则持久化 —— 保存到 /etc/nftables.conf + 服务开机加载，重启不丢
5. 与 Docker 共存 —— Docker 也生成 nft 规则，手动改前先理解它的链
```

```shell
# 限速示例（每 IP 每秒最多 5 个新连接）
nft add rule inet myfilter input tcp dport 22 ct state new limit rate 5/second accept
```

## 故障排查

### 规则不生效

```shell
# 1. 看规则是否在、顺序对不对
nft list ruleset
# 2. 看计数（确认流量命中哪条规则）
nft list ruleset -a
# 3. 看地址族对不对（IPv6 流量要 inet/ip6 族，ip 族只匹配 IPv4）
nft list table inet myfilter
```

### 规则误删 / 清空导致网络异常

```shell
# 1. flush 前先备份当前规则
nft list ruleset > /root/nft-backup.conf
# 2. 误删后恢复
nft -f /root/nft-backup.conf
# 3. Docker 规则被清空，重启 Docker 重建
systemctl restart docker
```

## 常见问题

```text
Q1: iptables 和 nft 命令混用会怎样？
A: 两者都是 netfilter 前端，混用容易重复/冲突。选一个统一用（新系统用 nft），别混用。

Q2: nft 删规则为什么用 handle 不用行号？
A: nft 规则用 handle 唯一标识，行号会随插入/删除变化，handle 稳定。nft -a list ruleset 看 handle。

Q3: inet 族和 ip 族有什么区别？
A: ip 族只匹配 IPv4，ip6 只匹配 IPv6，inet 同时匹配两者。统一用 inet 族省事。

Q4: flush ruleset 会清掉 Docker 的规则吗？
A: 会。flush 清空所有规则（包括 Docker 自动生成的）。flush 前备份，或精确 delete 特定规则。
```

## 面试题

```text
1. nftables 相比 iptables 有哪些优势？
   答：语法统一（一套管 IPv4/IPv6/ARP/桥接，不用四套工具）、性能更好（内核字节码一次匹配）、更灵活（表可自定义、支持 set/映射）。

2. nftables 的表和 iptables 的表有什么不同？
   答：iptables 是固定 5 张表（filter/nat/mangle/raw/security），nftables 的表按地址族（ip/ip6/inet/bridge）划分、名字可自定义。

3. 为什么新系统的 iptables 命令还能用？
   答：新系统用 iptables-nft 后端，iptables 语法被翻译成 nft 规则存进内核，nft list ruleset 能看到这些规则。

4. nft 规则的 priority 是什么作用？
   答：priority 决定同一 hook 下多条链的执行顺序，数值小的先执行（如 -100 先于 0 先于 100）。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 新系统优先用 nftables，iptables 是兼容接口
2. 用 inet 族一套规则管 IPv4+IPv6，不用配两遍
3. 改规则前先 nft list ruleset 看现状，避免误删
4. nft 规则持久化用 /etc/nftables.conf + systemctl enable nftables
5. Docker 也生成 nft 规则，手动改前先理解它的链

### 踩坑记录

```text
坑 1：iptables 和 nft 命令混用，规则冲突
结论：一会儿 iptables 一会儿 nft，规则乱套。
原因：两者都是 netfilter 前端，混用容易重复/冲突。
解法：选一个统一用（新系统用 nft），别混用。

坑 2：nft flush ruleset 把 Docker 规则也清了
结论：flush ruleset 后容器网络挂了。
原因：flush 清空所有规则，包括 Docker 自动生成的。
解法：flush 前确认影响，或用更精确的 delete 删特定规则。

坑 3：nft 规则没持久化，重启后消失
结论：nft add 的规则重启后没了。
原因：nft 命令是临时的，没写 /etc/nftables.conf。
解法：nft list ruleset > /etc/nftables.conf + systemctl enable nftables。

坑 4：删规则用行号删错（nft 用 handle 不用行号）
结论：nft delete 用 iptables 的行号思路，删错了规则。
原因：nft 用 handle 标识规则，不是行号。
解法：nft -a list ruleset 看 handle，按 handle 删。

坑 5：inet 族和 ip 族搞混，规则没生效
结论：建的规则在 ip 族，流量是 IPv6，没匹配到。
原因：ip 族只管 IPv4，IPv6 要 inet 或 ip6 族。
解法：统一用 inet 族（同时管 IPv4+IPv6）。
```

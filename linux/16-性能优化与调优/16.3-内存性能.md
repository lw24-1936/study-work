## 概述

内存性能分析回答「内存够不够、谁在吃、有没有泄漏、为什么换出」：页缓存（文件缓存，可回收）、内存水位（触发回收的阈值）、swap（换出到磁盘）、内存分配（进程怎么分内存）。核心指标：available（真实可用）、si/so（换出）、匿名页（进程占用）。内存问题通常是「不够 → 换出 → 变慢」或「泄漏 → 耗尽 → OOM」。

```text
内存性能四要素：
1. 页缓存 —— 文件缓存，可回收，占满正常
2. 内存水位 —— min/low/high 阈值，触发回收
3. swap —— 换出到磁盘，si/so 持续高 = 内存不够
4. 内存分配 —— 进程 malloc/匿名页，泄漏看 RSS 趋势
```

## 核心概念

1. **页缓存 page cache**：文件内容的缓存，尽量占满空闲内存（加速磁盘 IO）。可回收——内存紧张时内核回收页缓存，所以 available（含可回收页缓存）才是真实可用。
2. **内存水位 watermark**：内核回收内存的阈值——min/low/high 三个水位，低于 low 后台回收，低于 min 直接回收（同步，可能阻塞）。
3. **swap**：内存不够时把冷匿名页换出到磁盘。si/so 持续高 = 内存真不够、系统在抖动（thrashing）。
4. **匿名页 anonymous page**：进程 malloc/堆分配的内存，没有文件对应，不能回收只能换出（swap）。
5. **RSS**：进程实际占用的物理内存，内存泄漏看 RSS 趋势（单调增长 = 泄漏）。

```text
# 实测（本机 free，参考 08 章数据）
$ free -h
              total   used   free  buff/cache  available
内存：         19Gi   10Gi   329Mi   9.5Gi      8.7Gi
# available=8.7Gi 才是真实可用（含可回收的 9.5Gi 页缓存）
```

## 工作原理

1. **页缓存回收**：页缓存是「借」空闲内存用的，进程需要内存时内核回收页缓存（脏页先写回磁盘再回收，干净页直接回收）。所以「页缓存占满」不是问题，是设计行为。
2. **水位触发**：内存低于 low 水位 → kswapd 后台异步回收；低于 min 水位 → 分配内存时同步直接回收（进程阻塞）。min 水位太低会导致「内存一紧张就卡」。
3. **swap 换出**：内存不足时内核把冷匿名页换出到 swap 分区/文件，需要时再换入。换入换出都走磁盘（慢），频繁换出（si/so 高）说明内存真不够，系统抖动。

```text
内存回收链：
进程要内存 → 回收页缓存（快，干净页直接回收）
          → 不够 → 换出匿名页到 swap（慢）
          → 还不够 → 直接回收（同步阻塞）→ OOM Killer 杀进程
```

## 常用命令与配置

```shell
free -h                 # available 是关键
cat /proc/meminfo | grep -E 'MemAvailable|Cached|Buffers'
vmstat 1 5              # si/so 列：换入/换出，持续高 = 内存不够
ps aux --sort=-%mem | head      # 内存大户
pidstat -r 1                    # 每个进程内存
```

```text
swap 性能判断：
si/so = 0      正常（没在换出）
si/so 持续高   内存不够，系统抖动，加内存或找大户
swappiness     换出积极度（调低避免缓存被换出）
```

```shell
cat /proc/sys/vm/swappiness       # 换出积极度
vmstat 1 5                        # si/so 换入换出
free -h                           # swap 使用量
```

## 配置文件解析

内存调优参数在 /proc/sys/vm/ 下：

```text
/proc/sys/vm/swappiness      换出积极度（0-100，越小越倾向保留页缓存）
                             数据库服务器调 10-20，避免缓存被换出拖慢查询
/proc/sys/vm/min_free_kbytes min 水位（保留给紧急情况，过大浪费内存）
/proc/sys/vm/dirty_ratio     脏页占比阈值（达到后强制写回）
/proc/sys/vm/dirty_background_ratio  后台写回阈值
```

```shell
cat /proc/sys/vm/min_free_kbytes   # min 水位
cat /proc/zoneinfo | grep -A5 'pages free'   # 看各 zone 水位
sysctl -w vm.swappiness=10         # 临时调低（持久化写 /etc/sysctl.conf）
```

```text
三水位线：
min  —— 低于它直接回收（同步，可能阻塞分配）
low  —— 低于它后台回收（kswapd 异步）
high —— 高于它停止回收
```

## 应用场景实战

### 场景一：内存不够，定位是「真不够」还是「缓存占满」

```shell
# 1. 看 available（真实可用）
free -h
# 2. 看是否在换出
vmstat 1 5
# si/so=0 → 只是缓存占满（正常），available 够用
# si/so 持续高 → 真不够，继续查
# 3. 找内存大户
ps aux --sort=-%mem | head
```

### 场景二：排查内存泄漏

```shell
# 1. 找可疑进程（内存持续涨）
top -o %MEM
# 2. 持续观察 RSS 是否单调增长
pidstat -r -p <PID> 5
# 3. Java 进程看堆
jstat -gcutil <PID> 1000
```

## 性能与调优

```text
1. 数据库 swappiness —— 调低（10-20），避免页缓存被换出拖慢查询
2. 页缓存 —— 占满正常，别清缓存（清理反而变慢，下次读回源磁盘）
3. 及时回收 —— min_free_kbytes 别设太小，否则内存一紧张就卡
4. 大页 hugepage —— 数据库/大内存应用开透明大页（THP）或显式大页，减少 TLB 缺失
5. 内存泄漏 —— 监控 RSS 趋势，泄漏早发现早处理
```

## 安全与权限

```text
1. sysctl 权限 —— 改 /proc/sys/vm/* 要 root，改错（如 swappiness 极端值）影响全系统
2. 内存敏感信息 —— 进程内存含密钥/凭证，core dump 和 /proc/PID/mem 要限制访问
3. OOM 保护 —— 关键进程调 oom_score_adj 负值，降低被 OOM Killer 杀的概率
4. cgroup 限额 —— 用 cgroup 限制进程内存，防止单进程吃满整机
```

## 故障排查

### 内存不够导致变慢/抖动

```shell
# 1. 看 available 和 swap
free -h
# 2. 看换出情况
vmstat 1 5     # si/so 持续高 = 抖动
# 3. 找大户
ps aux --sort=-%mem | head
# 4. 看是否 OOM 过
dmesg | grep -i 'out of memory'
```

### 进程被 OOM Killer 杀

```shell
# 1. 确认 OOM
dmesg | grep -i oom
# 2. 看 OOM 时谁被杀、当时内存状况
journalctl -k | grep -i oom
# 3. 找内存大户
ps aux --sort=-%mem | head
```

## 常见问题

```text
Q1: free 显示 free 很少，是不是内存不够？
A: 不是。free 列不含可回收页缓存，要看 available（含可回收缓存）才是真实可用。页缓存占满空闲内存是正常行为。

Q2: 页缓存越涨越高，是内存泄漏吗？
A: 不是。页缓存尽量占满空闲内存，是设计行为（可回收）。真正的泄漏看进程 RSS 是否单调增长。

Q3: swappiness=0 能完全禁用 swap 吗？
A: 不能。0 只是「尽量避免」，内存极端紧张时仍会换出。真正禁用用 swapoff，或接受「0=尽量不用」。

Q4: 什么时候该加内存？
A: available 长期很低 + si/so 持续高（系统在抖动）时。如果只是页缓存占满、available 充足，不用加。
```

## 面试题

```text
1. available 和 free 有什么区别？
   答：free 是「完全空闲」的内存，available 是「可分配给新进程」的内存（含可回收的页缓存）。判断内存够不够看 available。

2. 页缓存是什么？为什么占满内存是正常的？
   答：页缓存是文件内容的缓存，加速磁盘 IO。空闲内存本就该被缓存用（不用白不用），进程需要时内核会回收页缓存，所以占满不是问题。

3. swap 和 thrashing（抖动）是什么关系？
   答：swap 是内存不够时的缓冲（换出冷页），但频繁换入换出（si/so 持续高）就是抖动，说明内存严重不足，内核反复换页导致系统极慢。

4. 内存泄漏怎么判断？
   答：看进程 RSS 趋势——持续单调增长不回落 = 疑似泄漏（合理缓存会涨到上限后稳定）。Java 用 jstat 看堆，C 用 valgrind。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 判断内存够不够看 available + si/so，不是 free 或 used
2. 页缓存占满是正常的（空闲内存本就该被缓存用）
3. swap 持续换出（si/so 高）= 真不够，加内存或找大户
4. 数据库服务器 swappiness 调低（10-20）
5. 内存泄漏早期发现：RSS 单调增长，用监控趋势

### 踩坑记录

```text
坑 1：看 free 列判断内存不够，误判
结论：free 只有 300M 就以为内存爆了。
原因：free 列不含可回收页缓存，available 才是真实可用。
解法：看 available（free -h），或看 si/so 是否在换出。

坑 2：页缓存占满以为是内存泄漏
结论：buff/cache 越涨越高，以为是泄漏。
原因：页缓存尽量占满空闲内存，是设计行为。
解法：看进程 RSS 是否增长，缓存涨是正常的（可回收）。

坑 3：swappiness 调成 0 以为禁用 swap
结论：swappiness=0 后还是用了 swap。
原因：0 只是「尽量避免」，内存极端紧张时仍换出。
解法：真正禁用用 swapoff，或接受「0=尽量不用」。

坑 4：内存泄漏和合理缓存分不清
结论：进程 RSS 一直涨，分不清是泄漏还是缓存。
原因：JVM 堆、连接池会涨到上限后稳定，真泄漏无限涨。
解法：看 RSS 是「涨到顶稳定」还是「单调无限涨」。

坑 5：内存抖动（thrashing）没及时发现
结论：系统响应极慢，si/so 持续高。
原因：内存不够 + swap 也满，内核反复换入换出。
解法：监控 si/so + available，加内存或限制内存大户。
```

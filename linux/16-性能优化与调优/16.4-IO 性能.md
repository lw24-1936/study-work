## 概述

IO 性能分析回答「磁盘快不快、IO 瓶颈在哪」：IO 调度器（内核怎么排序 IO 请求）、磁盘吞吐与延迟（iostat 的 rkB/s 和 await）、块设备调优（队列深度、调度器选择）。磁盘是系统最慢的部件之一，IO 瓶颈会拖垮一切。核心指标：await（IO 延迟）、%util（设备繁忙度）、r/s w/s（IOPS）。

```text
IO 性能三要素：
1. IO 调度器 —— 内核排序 IO 请求的策略（mq-deadline/none/bfq）
2. 吞吐与延迟 —— iostat 的 rkB/s（吞吐）、await（延迟）
3. 块设备调优 —— 调度器选择、队列深度、预读
```

## 核心概念

1. **IO 调度器 scheduler**：决定「内核怎么排序发给磁盘的 IO 请求」——合并相邻请求、排序减少机械盘寻道。mq-deadline（默认）、none（不调度，适合 SSD/NVMe）、bfq（公平调度）、kyber（低延迟）。
2. **吞吐 throughput**：每秒读写的 KB/MB（rkB/s/wkB/s）。衡量「传了多少数据」。
3. **IOPS**：每秒读写次数（r/s w/s）。衡量「处理了多少次请求」，小 IO 场景（数据库随机读写）更看重 IOPS。
4. **延迟 await**：单次 IO 的平均等待时间。SSD <1ms，HDD 几 ms~几十 ms。await 高 = IO 慢。
5. **繁忙度 %util**：设备忙于处理 IO 的时间比例，接近 100% = 设备饱和。

```text
iostat -x 关键指标：
r/s w/s     IOPS（每秒读写次数）
rkB/s wkB/s 吞吐（每秒读写 KB）
await       平均延迟（高 = IO 慢，SSD <1ms，HDD 几~几十 ms）
%util       设备繁忙度（接近 100% = 饱和）
```

## 工作原理

1. **IO 调度**：内核把应用的 IO 请求放进队列，调度器决定「先发哪个」。机械盘有寻道时间，调度器排序请求（合并相邻、按磁道排序）减少寻道；SSD/NVMe 随机访问快、无寻道，调度反而浪费（用 none 直发）。
2. **请求路径**：应用 read/write → 页缓存（读命中缓存不碰盘）→ 块层（调度器排序）→ 设备队列 → 磁盘。iostat 的 await 反映「请求在队列 + 设备里的等待时间」。
3. **队列深度**：nr_requests 决定「设备队列里能排多少请求」。队列深（大）能提高吞吐（更多请求并行），但延迟可能升高。

```text
# 实测（本机 IO 调度器）
$ cat /sys/block/sda/queue/scheduler
none [mq-deadline]
# 当前用 mq-deadline，none 可选（NVMe/SSD 推荐 none）
```

```text
调度器选择：
mq-deadline  默认，兼顾延迟和吞吐，HDD 适用
none         不调度，SSD/NVMe 适用（随机访问快，调度浪费）
bfq          公平调度，桌面/多任务适用
kyber        低延迟，适合对延迟敏感的场景
```

## 常用命令与配置

```shell
iostat -x 1 5           # 扩展指标（吞吐/延迟/繁忙度）
iostat -d sda 1         # 看某块盘的吞吐
pidstat -d 1            # 看每个进程的 IO
iotop                   # 实时看 IO 大户（需装）
fio --name=test --rw=randread --size=1G   # 压测随机读（fio 需装）
```

```shell
cat /sys/block/sda/queue/scheduler    # 看调度器
echo none > /sys/block/sda/queue/scheduler   # 切换（SSD 用 none）
```

```text
块设备调优参数（/sys/block/<设备>/queue/）：
scheduler       调度器（none/mq-deadline/bfq/kyber）
nr_requests     队列深度（大 = 高吞吐，小 = 低延迟）
read_ahead_kb   预读大小（顺序读调大，随机读调小）
rotational      是否机械盘（1=HDD，0=SSD）
```

## 配置文件解析

块设备的调优参数直接在 /sys/block/<设备>/queue/ 下（伪文件系统，可 echo 修改）：

```shell
# 看块设备参数
cat /sys/block/sda/queue/scheduler      # 调度器
cat /sys/block/sda/queue/nr_requests    # 队列深度
cat /sys/block/sda/queue/read_ahead_kb  # 预读大小
cat /sys/block/sda/queue/rotational     # 1=机械盘 0=SSD

# 调优示例：SSD 设 none + 大队列
echo none > /sys/block/sda/queue/scheduler
echo 1024 > /sys/block/sda/queue/nr_requests
```

```text
持久化注意：
echo 修改 /sys/block 是临时的（重启丢失），持久化要配：
1. udev 规则（/etc/udev/rules.d/）—— 设备插入时自动应用
2. systemd tmpfiles / rc.local —— 开机执行
```

## 应用场景实战

### 场景一：磁盘 IO 慢，定位瓶颈

```shell
# 1. iostat 看磁盘延迟和繁忙度
iostat -x 1 5
# await 高 + %util 100% = 磁盘饱和
# 2. 找是哪个进程在狂读写
pidstat -d 1
# 3. 看磁盘类型（SSD 还是 HDD）
cat /sys/block/sda/queue/rotational
```

### 场景二：SSD 上把调度器切成 none 提升性能

```shell
# 1. 确认是 SSD（rotational=0）
cat /sys/block/sda/queue/rotational
# 2. 切换调度器
echo none > /sys/block/sda/queue/scheduler
# 3. 验证
cat /sys/block/sda/queue/scheduler
# 4. 持久化（udev 规则或启动脚本）
```

## 性能与调优

```text
1. 调度器按盘类型 —— SSD/NVMe 用 none，HDD 用 mq-deadline
2. 队列深度 —— 高吞吐场景调大 nr_requests，低延迟场景调小
3. 预读 —— 顺序读调大 read_ahead_kb，随机读调小（预读浪费）
4. 数据库 IO —— 随机小 IO 多，看 IOPS 和 await，用 SSD + none
5. 文件系统选择 —— 高并发小文件用适合的文件系统（XFS/ext4），配合 noatime 减少写
```

## 安全与权限

```text
1. 调度器修改权限 —— echo 到 /sys/block 要 root，改错调度器影响全盘性能
2. iotop 权限 —— 看其他进程 IO 要 root（或 CAP_NET_ADMIN）
3. fio 压测 —— 生产环境别直接压测（会打满磁盘影响业务），用测试盘
4. 预读/队列参数 —— 改了会影响所有用到该盘的服务，改前评估影响
```

## 故障排查

### 磁盘 IO 慢（await 高）

```shell
# 1. 看延迟和繁忙度
iostat -x 1 5
# 2. 找 IO 大户
pidstat -d 1   # 或 iotop
# 3. 看磁盘类型和调度器
cat /sys/block/sda/queue/rotational
cat /sys/block/sda/queue/scheduler
# 4. 看是否机械盘坏道/老化
smartctl -A /dev/sda
```

### 磁盘饱和（%util 100%）

```shell
# 1. 确认饱和
iostat -x 1 5   # %util 接近 100%
# 2. 看是读多还是写多
iostat -d sda 1
# 3. 找是谁在狂读写
pidstat -d 1
```

## 常见问题

```text
Q1: await 高是什么原因？
A: await 是单次 IO 的平均等待时间，高说明 IO 慢——可能是机械盘寻道、队列排队、磁盘老化坏道、或设备饱和。

Q2: SSD 为什么用 none 调度器？
A: SSD/NVMe 随机访问快、没有寻道时间，调度器排序反而增加延迟。none 直发请求最快。

Q3: IOPS 和吞吐有什么区别？
A: IOPS 是每秒请求次数（小 IO 场景重要，如数据库随机读写），吞吐是每秒数据量（大 IO 场景重要，如视频传输）。小 IO 看 IOPS，大 IO 看吞吐。

Q4: %util 100% 就是磁盘坏了吗？
A: 不是。%util 接近 100% 只说明设备饱和（有 IO 排队），可能是负载高、调度/队列问题，不是磁盘坏了。结合 await 和 smartctl 判断。
```

## 面试题

```text
1. IO 调度器是干什么的？有哪些常见类型？
   答：调度器决定内核怎么排序发给磁盘的 IO 请求。mq-deadline（默认，兼顾延迟吞吐）、none（不调度，SSD/NVMe）、bfq（公平调度）、kyber（低延迟）。

2. await 和 %util 分别衡量什么？
   答：await 是单次 IO 的平均等待时间（延迟），%util 是设备忙于处理 IO 的时间比例（繁忙度）。await 高 = IO 慢，%util 接近 100% = 饱和。

3. SSD 和 HDD 调优有什么区别？
   答：SSD 随机访问快、无寻道，用 none 调度器 + 大队列深度；HDD 有寻道时间，用 mq-deadline 排序减少寻道 + 适当预读。

4. 怎么定位磁盘 IO 瓶颈？
   答：iostat -x 看 await/%util 判断是否慢/饱和 → pidstat -d 或 iotop 找 IO 大户 → 看盘类型和调度器 → 针对性调优（切调度器/调队列/加 SSD）。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 判断 IO 性能用 iostat -x，看 await 和 %util
2. SSD/NVMe 用 none 调度器，HDD 用 mq-deadline
3. 先确认盘类型（rotational）再调调度器
4. 找 IO 大户用 pidstat -d 或 iotop
5. 数据库磁盘调大预读（read_ahead_kb），顺序读多时有效

### 踩坑记录

```text
坑 1：只看吞吐不看延迟
结论：磁盘吞吐还行，但 await 很高（几十 ms）。
原因：延迟高说明 IO 慢（寻道/排队），吞吐高不代表体验好。
解法：iostat -x 看 await，延迟高查原因（机械盘/队列/坏道）。

坑 2：SSD 还用 mq-deadline，没切 none
结论：SSD 性能没发挥，还在用 HDD 的调度器。
原因：没根据盘类型切调度器，SSD 用 none 更快。
解法：确认 rotational=0，echo none > scheduler。

坑 3：%util 100% 就判断磁盘坏了
结论：%util 100% 就换盘，其实还有优化空间。
原因：%util 接近 100% 只说明有 IO 排队，可能是调度/队列问题。
解法：结合 await 和 IOPS 判断，先调调度器/队列。

坑 4：改了调度器重启又变回去
结论：echo none > scheduler 重启后恢复 mq-deadline。
原因：直接 echo 是临时的，不持久化。
解法：udev 规则或 rc.local 持久化调度器设置。

坑 5：预读调太大反而变慢
结论：read_ahead_kb 调很大，随机读场景反而慢。
原因：预读适合顺序读，随机读时预读浪费（读了不用）。
解法：按负载类型调预读，顺序读调大、随机读调小。
```

## 概述

网络性能分析回答「网络快不快、瓶颈在哪」：吞吐（每秒传多少数据）、延迟（RTT，往返时间）、TCP 调优（缓冲、连接参数）、网卡多队列（多核并行处理收包）。核心指标：带宽利用率、丢包率、RTT。网络瓶颈通常在「带宽打满」或「TCP 参数没调优」或「单核处理收包」。

```text
网络性能四要素：
1. 吞吐 —— 每秒传输量（带宽打满 = 瓶颈）
2. 延迟 —— RTT（往返时间），高延迟影响交互
3. TCP 调优 —— 缓冲、连接参数（影响吞吐和连接数）
4. 网卡多队列 —— 多核并行收包（单核收包是瓶颈）
```

## 网络吞吐与延迟

吞吐是「每秒传多少数据」（带宽），延迟是「数据往返时间」（RTT）。两者关系：高带宽高延迟（如跨国链路）常见，TCP 的吞吐受「带宽×延迟积」限制（BDP）。测吞吐用 iperf，测延迟用 ping（RTT）。判断网络瓶颈：带宽打满（吞吐到上限）、丢包、RTT 高。

```shell
iperf3 -s               # 服务器端
iperf3 -c 服务器IP      # 客户端测吞吐
ping -c 10 目标         # 测 RTT（延迟）
ss -i                   # 看 TCP 连接的 RTT/吞吐
```

```text
吞吐 vs 延迟：
1. 吞吐 —— 每秒传输量（带宽），iperf 测
2. 延迟 —— RTT 往返时间，ping 测
3. BDP —— 带宽×延迟积，TCP 缓冲要配够才能跑满带宽
```

## TCP 调优

TCP 调优提升网络性能，核心参数：缓冲区（tcp_rmem/tcp_wmem，读写缓冲，BDP 大要调大）、连接队列（tcp_max_syn_backlog、somaxconn，高并发连接）、TIME_WAIT 复用（tcp_tw_reuse，短连接场景）、拥塞算法（bbr，高吞吐场景）。调优方向：高并发 Web 调大 backlog + tw_reuse，大带宽长延迟调大缓冲 + bbr。

```shell
# 查看 TCP 参数
sysctl net.ipv4.tcp_rmem net.ipv4.tcp_wmem
sysctl net.core.somaxconn net.ipv4.tcp_max_syn_backlog
# 调优示例
sysctl -w net.core.somaxconn=1024
sysctl -w net.ipv4.tcp_tw_reuse=1
sysctl -w net.ipv4.tcp_congestion_control=bbr
```

```text
TCP 调优参数：
tcp_rmem/tcp_wmem    读写缓冲区（BDP 大调大）
somaxconn            监听队列（高并发调大）
tcp_max_syn_backlog  SYN 队列（防 SYN flood）
tcp_tw_reuse         TIME_WAIT 复用（短连接）
tcp_congestion_control  拥塞算法（bbr 高吞吐）
```

## 网卡多队列

网卡多队列（multi-queue）让网卡有多个收发队列，对应多核 CPU 并行处理——解决「单核收包成为瓶颈」。现代网卡都支持多队列（RSS 把流量分发到不同队列），配合中断亲和性（把队列中断绑到不同核）。查看：`ethtool -l`（队列数）、/proc/interrupts（中断分布）。高吞吐场景单核收包是常见瓶颈，多队列 + 中断亲和性能显著提升。

```shell
ethtool -l eth0          # 看网卡队列数
ethtool -S eth0 | grep queue   # 看每队列统计
cat /proc/interrupts | grep <网卡>   # 中断分布
```

```text
网卡多队列要点：
1. 多队列 —— 网卡多个收发队列，多核并行处理
2. RSS —— 把流量哈希分发到不同队列
3. 中断亲和性 —— 队列中断绑到不同核，避免单核瓶颈
```

## 应用场景实战

### 场景一：测网络吞吐，定位带宽瓶颈

```shell
# 1. 服务器端起 iperf
iperf3 -s
# 2. 客户端测吞吐
iperf3 -c <服务器IP>
# 3. 测延迟
ping -c 10 <服务器IP>
# 吞吐接近带宽上限 = 带宽瓶颈；RTT 高 = 延迟问题
```

### 场景二：高并发 Web 调优 TCP 参数

```shell
# 1. 调大连接队列
sysctl -w net.core.somaxconn=4096
sysctl -w net.ipv4.tcp_max_syn_backlog=4096
# 2. TIME_WAIT 复用（短连接）
sysctl -w net.ipv4.tcp_tw_reuse=1
# 3. 持久化
echo -e 'net.core.somaxconn=4096\nnet.ipv4.tcp_tw_reuse=1' >> /etc/sysctl.conf
sysctl -p
```

## 最佳实践与踩坑记录

### 最佳实践

1. 测网络性能用 iperf（吞吐）+ ping（延迟），别只看一个
2. 高并发 Web 调大 somaxconn + backlog + tw_reuse
3. 大带宽长延迟（跨国）调大 TCP 缓冲 + bbr
4. 高吞吐场景看网卡多队列，单核收包是常见瓶颈
5. 网络调优一次改一个参数，改前记录旧值

### 踩坑记录

```text
坑 1：只测 ping 不测吞吐，判断不出带宽瓶颈
结论：ping 正常就以为网络没问题，其实带宽打满。
原因：ping 只测延迟，不测吞吐。
解法：iperf 测吞吐，看是否接近带宽上限。

坑 2：TCP 缓冲没调大，大带宽跑不满
结论：千兆/万兆带宽，实际传输只有几百兆。
原因：TCP 缓冲太小，受 BDP（带宽×延迟）限制跑不满。
解法：调大 tcp_rmem/tcp_wmem，配合 bbr。

坑 3：高并发连接被拒，somaxconn 太小
结论：并发高时新连接失败（SYN 被丢）。
原因：监听队列 somaxconn 太小，连接来不及处理被丢。
解法：调大 net.core.somaxconn + 应用的 backlog。

坑 4：单核 CPU 高但整体不高，网卡收包瓶颈
结论：网络吞吐上不去，某个 CPU 核 100%。
原因：网卡单队列，收包集中在一个核处理。
解法：网卡多队列（RSS）+ 中断亲和性（irqbalance）。

坑 5：bbr 切了没评估就上生产
结论：切 bbr 后某些场景反而变差。
原因：bbr 适合长肥管道（高带宽长延迟），不是万能。
解法：测试环境压测对比，再决定。
```

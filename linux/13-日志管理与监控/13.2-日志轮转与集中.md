## 概述

日志会无限增长，不管理会把磁盘占满。解决方案：logrotate 轮转（定期切割、压缩、删除旧日志）、日志归档（长期保存）、集中管理（rsyslog 远程转发、ELK/Loki 集中收集分析）。单机靠 logrotate，多机靠集中收集。核心思想：日志要「轮转防占满 + 集中便于查 + 归档留证据」。

```text
日志管理三板斧：
1. 轮转 logrotate —— 定期切割/压缩/删除，防占满磁盘
2. 归档 —— 压缩存历史，留审计证据
3. 集中 —— rsyslog 远程转发 / ELK / Loki，多机统一收集
```

## 核心概念

1. **logrotate**：日志轮转工具，按「大小或时间」切割日志，保留 N 份历史（.1、.2.gz），旧的压缩或删除。配置文件 /etc/logrotate.conf（全局）+ /etc/logrotate.d/*（每个服务一份）。
2. **日志归档**：把历史日志压缩保存、留证据——logrotate 的 compress 就是把轮转后的旧日志压成 .gz 归档，兼顾审计、合规、节省空间。
3. **rsyslog 远程转发**：客户端把日志发到日志服务器（UDP/TCP），服务器统一收集，实现多机日志集中。
4. **ELK 与 Loki**：现代日志集中方案。ELK（Elasticsearch+Logstash+Kibana）成熟但重，Loki（Grafana 出品）轻量、按标签索引，配合 Grafana 查询。

```text
ELK vs Loki：
1. ELK —— Elasticsearch+Logstash+Kibana，成熟强大但重
2. Loki —— Grafana 出品，轻量、按标签索引、配 Grafana 查询
3. 共同 —— 收集 agent → 集中存储 → 查询可视化
```

## 工作原理

logrotate 轮转的流程：轮转触发（每天/日志超大小）→ 把当前日志改名成 .1（旧 .1 变 .2，依次后移）→ 按配置压缩/删除最旧的一份 → 通知服务重开日志文件（或 copytruncate 复制后清空）。保留 rotate N 份，超出 N 的最旧日志被删掉。

日志集中原理：各服务器的日志 agent（Filebeat/Promtail 或 rsyslog）把日志发到集中存储（Elasticsearch/Loki），查询端（Kibana/Grafana）统一检索。这样多机日志「一处查、不随机器丢失、便于审计」。

```text
logrotate 轮转流程：
触发（daily/size）→ 改名后移（log → .1 → .2.gz）→ 压缩/删除最旧 → 通知服务重开或 copytruncate

日志集中架构：
各服务器日志 → Filebeat/Promtail（agent 收集）→ Elasticsearch/Loki（存储）→ Kibana/Grafana（查询）
```

## 常用命令与配置

```shell
logrotate -d /etc/logrotate.conf    # 调试模式（不实际执行）
logrotate -f /etc/logrotate.conf    # 强制轮转
logrotate /etc/logrotate.d/nginx    # 轮转某服务的日志
gzip /var/log/old.log               # 手动压缩归档
zcat /var/log/auth.log.2.gz | head  # 查看压缩的归档日志
systemctl restart rsyslog           # 改 rsyslog 配置后重启
```

```text
# 实测（本机 logrotate 版本和配置）
$ logrotate --version | head -1
logrotate 3.21.0
$ ls /etc/logrotate.d/
alternatives  apport  apt  bootlog  nginx  rsyslog  ...
# 每个服务一份轮转配置，nginx/rsyslog 都有自己的
```

## 配置文件解析

logrotate 的服务配置示例（/etc/logrotate.d/nginx）：

```text
# /etc/logrotate.d/nginx
/var/log/nginx/*.log {
    daily           # 每天轮转
    rotate 14       # 保留 14 份历史
    compress        # 压缩旧日志
    delaycompress   # 延迟压缩（留一份不压缩）
    missingok       # 日志不存在不报错
    notifempty      # 空日志不轮转
}
```

```text
关键参数：
daily/weekly/monthly   轮转周期
rotate N               保留 N 份历史
compress               压缩旧日志
size 100M              按大小轮转（超过即转）
copytruncate           复制后清空原文件（适合正在写的日志）
postrotate/endscript   轮转后执行的脚本（如给服务发 SIGHUP）
```

rsyslog 远程转发的客户端配置：

```text
# 客户端转发配置（/etc/rsyslog.d/remote.conf）
*.* @192.168.1.100:514        # 所有日志发到日志服务器（UDP）
# *.* @@192.168.1.100:514     # 用 TCP（更可靠）
```

## 应用场景实战

### 场景一：给 nginx 日志配轮转防占满磁盘

```shell
# 1. 看现有轮转配置
cat /etc/logrotate.d/nginx
# 2. 调整保留份数和压缩
# rotate 14 → rotate 30（保留 30 天）
sudo vi /etc/logrotate.d/nginx
# 3. 测试轮转配置
sudo logrotate -d /etc/logrotate.d/nginx
# 4. 强制轮转一次
sudo logrotate -f /etc/logrotate.d/nginx
```

### 场景二：把多台服务器日志集中到一台

```shell
# 客户端（每台服务器）
echo '*.* @192.168.1.100:514' | sudo tee /etc/rsyslog.d/remote.conf
sudo systemctl restart rsyslog
# 服务器（日志中心）
# 开 rsyslog UDP 接收，日志落到 /var/log/remote/ 下
```

## 性能与调优

```text
1. 轮转周期 —— 日志量大改 size 触发（如 size 100M），别只靠 daily
2. 压缩开销 —— compress 用 gzip 默认，量大可换更快算法或 delaycompress 缓冲
3. 集中传输 —— 日志量大用 TCP（可靠）或 Kafka 缓冲，别直接打爆日志服务器
4. 存储清理 —— ELK/Loki 设保留期（如 7 天）和降采样，防存储爆炸
```

## 安全与权限

```text
1. 归档权限 —— 压缩日志含敏感信息（登录/请求），归档文件权限要收紧
2. 传输加密 —— rsyslog 远程转发默认明文，跨公网用 TLS（imrelp/tls）
3. 日志服务器安全 —— 日志中心是审计证据集中地，单独部署、限制访问
4. 归档保留期 —— 按合规要求定（金融 6 个月起），到期安全删除
```

## 故障排查

### 轮转不生效，日志还在涨

```shell
# 1. 调试模式看轮转计划（不实际执行）
logrotate -d /etc/logrotate.d/服务名
# 2. 确认日志路径和配置匹配
cat /etc/logrotate.d/服务名
# 3. 手动强制轮转验证
logrotate -f /etc/logrotate.d/服务名
```

### 轮转后服务还写旧文件

```shell
# 看服务持有的日志文件句柄
lsof | grep '/var/log/服务名'
# 如果还指向 .1 旧文件，说明服务没重开日志 → copytruncate 或发 SIGHUP
```

## 常见问题

```text
Q1: logrotate 轮转后服务继续写旧文件？
A: 服务持有旧文件句柄，轮转移动文件后服务不知道。用 copytruncate（复制后清空），或让服务支持重开日志（postrotate 发 SIGHUP）。

Q2: rsyslog 远程转发丢日志？
A: UDP 不可靠（网络抖动会丢），重要日志用 TCP（@@ 前缀）。

Q3: ELK 和 Loki 怎么选？
A: 大规模日志检索分析用 ELK（成熟强大但重），中小规模/和 Grafana 整合用 Loki（轻量按标签索引）。

Q4: rotate 保留几份合适？
A: 按「审计要求 + 磁盘空间」权衡，rotate 14~30 常见。
```

## 面试题

```text
1. logrotate 的 copytruncate 是做什么的？
   答：复制日志后清空原文件，解决「服务持有文件句柄、轮转后还写旧文件」的问题，适合不支持重开日志的服务。

2. 日志集中有哪些方案？
   答：传统 rsyslog 远程转发（UDP/TCP）；现代 ELK（Elasticsearch+Logstash+Kibana）、Loki（Grafana 出品）。

3. 为什么集中日志建议用 TCP 而不是 UDP？
   答：UDP 不可靠、网络抖动会丢日志；TCP 保证送达，重要日志/审计场景用 TCP。

4. 日志无限增长怎么防？
   答：logrotate 配 rotate N + compress 轮转，ELK/Loki 设保留期和降采样。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 所有写日志的服务都要配 logrotate，别让日志无限增长
2. 轮转保留份数按「审计要求 + 磁盘空间」权衡，rotate 14~30 常见
3. 多机日志集中（rsyslog 转发或 Loki/ELK），别一台台登上去查
4. 归档日志压缩 + 定期清理，防磁盘占满
5. 集中日志要配检索（Loki/ELK），否则集中了也查不动

### 踩坑记录

```text
坑 1：日志没配轮转，磁盘被占满
结论：某服务日志一直涨，磁盘满了。
原因：没配 logrotate，日志无限增长。
解法：给服务加 logrotate 配置，rotate N + compress。

坑 2：copytruncate 没用导致日志继续写旧文件
结论：轮转后服务还写旧文件，新日志文件是空的。
原因：服务持有日志文件句柄，轮转移动文件后服务不知道。
解法：用 copytruncate（复制后清空原文件），或让服务支持重开日志（SIGHUP）。

坑 3：rsyslog 远程转发用 UDP 丢日志
结论：日志集中后发现有丢失。
原因：UDP 不可靠，网络抖动会丢。
解法：重要日志用 TCP（@@），或接受 UDP 的「可能丢」。

坑 4：ELK/Loki 没配日志清理，存储爆炸
结论：集中日志后存储快速占满。
原因：日志量巨大，没配保留期限/压缩。
解法：设日志保留期（如 7 天），按需降采样或压缩。

坑 5：logrotate 配置语法错，轮转静默失败
结论：轮转没生效，日志还在涨。
原因：logrotate 配置语法错，或路径写错。
解法：logrotate -d 调试模式看报错，确认路径正确。
```

## 概述

日志会无限增长，不管理会把磁盘占满。解决方案：logrotate 轮转（定期切割、压缩、删除旧日志）、日志归档（长期保存）、集中管理（rsyslog 远程转发、ELK/Loki 集中收集分析）。单机靠 logrotate，多机靠集中收集。核心思想：日志要「轮转防占满 + 集中便于查 + 归档留证据」。

```text
日志管理三板斧：
1. 轮转 logrotate —— 定期切割/压缩/删除，防占满磁盘
2. 归档 —— 压缩存历史，留审计证据
3. 集中 —— rsyslog 远程转发 / ELK / Loki，多机统一收集
```

## 核心概念

### logrotate 与日志轮转

logrotate 是 Linux 事实标准的日志轮转工具，由 cron / systemd timer 每天触发，按「大小或时间」切割日志，保留 N 份历史（.1、.2.gz），旧的压缩或删除。配置文件 /etc/logrotate.conf（全局默认）+ /etc/logrotate.d/*（每个应用一份，include 进来）。

```text
轮转的直观效果（本机 /var/log/nginx 实测）：
access.log      <- 当前正在写
access.log.1    <- 昨天整天的
access.log.2.gz <- 前天，已压缩
access.log.3.gz <- 大前天，已压缩
rotate 14 表示最多留 14 份，第 15 份被删
```

### 轮转周期、保留份数与压缩

三个核心参数决定「多久转、留几份、压不压」：

```text
daily / weekly / monthly   按时间轮转（最常见的触发方式）
size 100M                  超过 100M 就轮转（大日志服务用这个兜底）
rotate N                   保留 N 份历史，超出的最旧档案被删除
compress                   轮转后的旧档 gzip 压缩成 .gz
delaycompress              延迟压缩：最新一份 .1 先不压，下次轮转时再压
```

「按大小还是按时间」取决于业务：访问量平稳的服务用 daily；日志量波动大的用 size；两者都想要用 maxsize（时间到或超大小，先到先转）。

### create 与 copytruncate

轮转的两种「切文件」方式，解决同一个问题：日志文件被改名后，正在写它的进程怎么办。

```text
create     默认方式：把 access.log 改名为 access.log.1，再新建一个空的
           access.log，靠 postrotate 通知进程重开文件（nginx -s reopen / SIGHUP）
copytruncate 把 access.log 复制一份为 access.log.1，然后 truncate 清空原文件，
           进程句柄始终指向同一个 inode，不用通知进程
```

create 适合支持重开日志的进程（nginx、rsyslog、syslog 系全家）；copytruncate 适合无法重开日志的进程（老程序、不知名二进制），代价是复制期间可能丢几行日志、多一次全量读盘 IO。

### 集中日志：rsyslog 远程转发

多台服务器各自有日志，排查问题一台台登上去太慢。rsyslog 原生支持远程转发：客户端把日志经网络发给日志服务器（UDP/TCP/RELP/TLS），服务器用模板落盘到 /var/log/remote/<主机名>/ 下。UDP 快但不可靠，TCP 可靠，RELP 带应用层确认防丢，跨公网加 TLS。

```text
客户端: *.* @192.168.1.100:514     （@ 一个 = UDP，@@ 两个 = TCP）
服务器: module(load="imtcp") + input(type="imtcp" port="514")
```

### journald 自身的清理与导出

journald 不归 logrotate 管，它自己按 SystemMaxUse 限额滚动和清理二进制文件。但 journald 日志要长期归档/集中，需要导出：`journalctl --output=export` 导出可重放格式，`journalctl --output=json` 导出结构化文本给采集器（Filebeat/Promtail 都支持读 journald 或导出的文本）。

### ELK 与 Loki

现代日志集中方案（更重的场景）：

```text
ELK（Elastic Stack）：
Filebeat（采集）→ Logstash（解析/清洗）→ Elasticsearch（存储/索引）→ Kibana（查询可视化）
优点：全文检索强、生态成熟、支持复杂 pipeline
缺点：重，ES 集群吃内存，运维成本高

Loki（Grafana 出品）：
Promtail（采集）→ Loki（存储，只索引标签不索引全文）→ Grafana（查询）
优点：轻量、成本低、和 Prometheus/Grafana 天然一体
缺点：全文检索能力弱，复杂查询要 LogQL
```

### 日志保留策略

保留多久 = 合规要求 × 磁盘预算 × 检索需求。设计时先定「审计必须留多久」（金融/等保常要求 6 个月到数年），再算每日日志量，反推磁盘容量和压缩比，最后落到 logrotate rotate N / journald MaxRetentionSec / ES 索引生命周期（ILM）上。

```text
容量估算公式：
每日日志量 × 保留天数 × 压缩系数(0.1~0.3) = 需要的归档空间
例：每天 2GB、留 90 天、gzip 压到 20% → 2 × 90 × 0.2 = 36GB 归档空间
```

## 工作原理

### logrotate 轮转时序

Ubuntu 上 logrotate 由 logrotate.timer（systemd timer，每天 00:00）触发，非 systemd 系统由 /etc/cron.daily/logrotate 触发。实测本机：

```text
$ systemctl list-timers | grep -i log
Thu 2026-08-20 00:00:00 CST  12h ago  logrotate.timer  logrotate.service

logrotate.timer（每天 00:00）
  → logrotate.service
    → logrotate /etc/logrotate.conf
      → include /etc/logrotate.d/*  读所有应用配置
      → 逐条对比 state 文件 /var/lib/logrotate/status（上次轮转时间）
      → 满足条件（周期到 / 超 size）则执行轮转
```

单条日志的轮转动作序列：

```text
1. 触发：daily 到期 或 文件超过 size
2. 改名后移：access.log → access.log.1，旧的 .1 → .2，依次后移
3. 新建空文件 access.log（create 方式），权限属主按配置
4. 压缩：compress 时把 .1 压成 .1.gz；delaycompress 时下次轮转才压
5. 清理：超过 rotate N 份的最旧档案直接删除
6. 通知：postrotate 脚本执行（如 nginx -s reopen、rsyslog-rotate）
7. 记录：把轮转时间写进 state 文件，防止同一周期重复轮转
```

### create 与 copytruncate 两种方式的原理

```text
create（默认）：
  进程 fd → inode A（access.log）
  轮转：rename(access.log → access.log.1)，create 新 inode B（access.log）
  postrotate：nginx -s reopen → 进程关闭 fd(A) 打开 fd(B)
  风险：postrotate 没执行/进程不支持 reopen，进程继续写 inode A = 日志全进 .1

copytruncate：
  进程 fd → inode A（access.log）
  轮转：copy(A → access.log.1)，truncate(A) 清空
  进程 fd 始终指向 inode A，无感知，继续写
  代价：复制期间新日志可能丢几行；大文件复制 IO 高
```

### 集中日志传输原理

```text
客户端 rsyslogd（imuxsock 收本地日志）
  → 规则 *.* @192.168.1.100:514
  → UDP/TCP 报文（RFC 3164 格式，每行一条）
  → 服务器 rsyslogd（imtcp/imudp 模块监听 514）
  → 模板匹配 → /var/log/remote/<HOSTNAME>/messages.log
```

服务器侧的关键是「按来源主机分目录」（模板里用 %HOSTNAME%），否则所有机器的日志混在一个文件里没法看。TCP 有连接管理，断线重连后补发缓冲里的日志（rsyslog 的 TCP 队列默认会缓存）。

### journald 与 logrotate 的关系

两者互不干涉：

```text
journald 二进制日志（/var/log/journal/）：
  自己滚动：journal 文件到 8M/32M 等阈值自动切新文件
  自己清理：总量超 SystemMaxUse 删最旧
  不用 logrotate，配了也没意义（二进制，logrotate 不懂）

文本日志（/var/log/*.log，含 rsyslog 写的）：
  归 logrotate 管
```

### ELK 采集链路简述

```text
Filebeat（每台机器上的采集 agent）
  → 读文件 / journald / syslog，逐行发到 Logstash
  → Logstash 按 grok 正则解析出字段（时间/级别/来源/消息）
  → 写入 Elasticsearch（按天索引 logstash-2026.08.19）
  → Kibana 检索/可视化/告警
  → ILM 策略：热 7 天 → 温 30 天 → 冷/删除
```

## 常用命令与配置

### logrotate 命令

```shell
logrotate /etc/logrotate.conf          # 正常执行（一般由 timer/cron 调）
logrotate -d /etc/logrotate.conf       # debug 模式：只打印会做什么，不实际执行
logrotate -f /etc/logrotate.conf       # force：无视 state 强制轮转
logrotate -v /etc/logrotate.conf       # verbose：打印执行细节
logrotate -s /path/status.conf ...     # 指定 state 文件
logrotate /etc/logrotate.d/nginx       # 只轮转某应用（注意会读全局默认）
```

### 压缩与查看归档

```shell
gzip /var/log/old.log                  # 手动压缩归档
zcat /var/log/auth.log.2.gz | head     # 查看压缩归档（不解压落盘）
zgrep 'Failed password' /var/log/auth.log.2.gz
zless /var/log/auth.log.2.gz           # 分页查看
```

### 集中日志相关命令

```shell
systemctl restart rsyslog              # 改 rsyslog 配置后重启
rsyslogd -N1                           # 配置语法检查
ss -tlnp | grep 514                    # 服务器确认 514 在监听
tail -f /var/log/remote/主机名/*.log   # 服务器看客户端日志是否到达
```

## 配置文件解析

### /etc/logrotate.conf 全局配置逐行解析

本机完整内容（Ubuntu 默认）：

```text
# /etc/logrotate.conf —— 全局默认，/etc/logrotate.d/* 里的配置覆盖它
weekly                  # 默认轮转周期：每周
su root adm             # 轮转后新建文件用 root:adm（/var/log 的属组是 adm）
rotate 4                # 默认保留 4 份历史
create                  # 默认轮转后新建空文件（create 方式）
#dateext                # 用日期后缀命名（默认关；开了则 .1 变成 .20260819）
#compress               # 默认不压缩（各应用配置里各自开）
include /etc/logrotate.d  # 核心：把分应用配置全部包含进来
```

要点：/etc/logrotate.d/ 里的每个文件是一组「路径 + 指令块」，未写的指令继承全局默认。rsyslog 自己的轮转配置就在 /etc/logrotate.d/rsyslog，nginx 的包安装时自带 /etc/logrotate.d/nginx。

### /etc/logrotate.d/rsyslog 逐行解析

```text
# /etc/logrotate.d/rsyslog —— 系统文本日志的轮转
/var/log/syslog
/var/log/mail.log
/var/log/kern.log
/var/log/auth.log
/var/log/user.log
/var/log/cron.log
{
    rotate 4            # 保留 4 份（4 周）
    weekly              # 每周轮转
    missingok           # 文件不存在不报错（如 cron.log 默认没开）
    notifempty          # 空文件不轮转
    compress            # 旧档压缩
    delaycompress       # 最新一份 .1 先不压，给排查留明文
    sharedscripts       # 多个文件只执行一次 postrotate
    postrotate
        /usr/lib/rsyslog/rsyslog-rotate   # 通知 rsyslog 重开所有日志文件
    endscript
}
```

```text
postrotate 的作用：logrotate 把 syslog 改名成 syslog.1 后，rsyslogd 的文件句柄
还指向旧的 inode，不重开会继续写 .1。rsyslog-rotate 脚本让 rsyslogd 重新打开
新文件。任何「自己写日志的守护进程」都要有对应的 postrotate 通知。
```

### /etc/logrotate.d/nginx 逐行解析

```text
# /etc/logrotate.d/nginx —— 本机实际内容
/var/log/nginx/*.log {
    daily                       # 每天轮转（日志量大，比 weekly 勤）
    missingok                   # 日志不存在不报错
    rotate 14                   # 保留 14 份（14 天）
    compress                    # 压缩旧档
    delaycompress               # 最新一份 .1 不压
    notifempty                  # 空日志不轮转（避免半夜生成一堆空档）
    create 0640 www-data adm    # 新文件权限 0640、属主 www-data:adm
    sharedscripts               # 所有 .log 共享一次 postrotate
    prerotate
        if [ -d /etc/logrotate.d/httpd-prerotate ]; then \
            run-parts /etc/logrotate.d/httpd-prerotate; \
        fi \
    endscript
    postrotate
        invoke-rc.d nginx rotate >/dev/null 2>&1   # 通知 nginx 重开日志
    endscript
}
```

### /etc/logrotate.d/apt 与 wtmp

```text
# /etc/logrotate.d/apt —— 按大小+月度组合
/var/log/apt/term.log {
  rotate 12
  monthly
  compress
  missingok
  notifempty
}
/var/log/apt/history.log { ... 同上 ... }

# /etc/logrotate.d/wtmp —— minsize：月轮转 + 至少 1M 才转
/var/log/wtmp {
    missingok
    monthly
    create 0664 root utmp
    minsize 1M
    rotate 1
}
```

### logrotate 指令速查表

| 指令 | 作用 |
|---|---|
| daily / weekly / monthly / yearly | 按时间周期轮转 |
| size 100M | 超过该大小就轮转（K/M/G 后缀） |
| maxsize 100M | 周期到或超大小，先到先转 |
| minsize 100M | 大小+时间都要满足才转 |
| rotate N | 保留 N 份，超出删除；0 = 不保留直接删 |
| compress / nocompress | 轮转后压缩（默认 gzip） |
| delaycompress | 最新一份延迟到下次轮转再压 |
| compresscmd / compressext | 换压缩程序（如 zstd、.zst） |
| missingok / nomissingok | 文件不存在是否报错 |
| notifempty / ifempty | 空文件是否轮转 |
| create [mode owner group] | 轮转后新建空文件及权限属主 |
| copytruncate | 复制后清空原文件（句柄不动） |
| postrotate ... endscript | 轮转后执行的脚本 |
| prerotate ... endscript | 轮转前执行的脚本 |
| sharedscripts | 多文件只跑一次脚本（配合上面两个） |
| dateext / dateformat | 归档用日期后缀（.20260819 而非 .1） |
| su user group | 以指定用户执行轮转（避免权限问题） |
| olddir /dir | 归档移到指定目录 |
| mail addr | 删除的日志邮件发出去 |
| tabooext | 忽略指定后缀的文件 |

### rsyslog 集中日志配置

客户端（每台被采集机）：

```text
# /etc/rsyslog.d/remote.conf
*.* @192.168.1.100:514        # UDP 转发（快，可能丢）
#*.* @@192.168.1.100:514      # TCP 转发（可靠，推荐）
```

服务器（日志中心）：

```text
# /etc/rsyslog.conf 打开接收模块
module(load="imtcp")
input(type="imtcp" port="514")

# /etc/rsyslog.d/remote-server.conf 定义模板和落盘规则
$template RemoteLogs,"/var/log/remote/%HOSTNAME%/%PROGRAMNAME%.log"
*.* ?RemoteLogs
```

```text
%HOSTNAME% 按来源主机分目录，%PROGRAMNAME% 按程序分文件；
收下来后 /var/log/remote/web1/sshd.log、web1/nginx.log、web2/sshd.log ...
```

Red Hat 系差异：RHEL/CentOS 的 logrotate 包布局完全一致（/etc/logrotate.conf + /etc/logrotate.d/），默认配置也近同；差异在 rsyslog 默认规则文件把系统日志写 /var/log/messages（对应 Ubuntu 的 syslog）和 /var/log/secure（对应 auth.log）——给集中日志服务器配模板时，RHEL 客户端的日志会以 messages 名义到达，模板里按 %HOSTNAME% 分目录即可不受影响。

## 应用场景实战

### 场景一：nginx 日志轮转实战

```shell
# 1. 看现有轮转配置
cat /etc/logrotate.d/nginx
# 2. 调整保留份数（日志多就加大 rotate，磁盘紧就缩小）
sudo vi /etc/logrotate.d/nginx   # rotate 14 → rotate 30（留 30 天）
# 3. 先调试模式验证（不实际执行，看报错）
sudo logrotate -d /etc/logrotate.d/nginx
# 4. 强制轮转一次验证效果
sudo logrotate -f /etc/logrotate.d/nginx
ls -la /var/log/nginx/
# 5. 验证 postrotate 生效：nginx 在写新文件，旧文件没再增长
tail -f /var/log/nginx/access.log
```

```text
验证要点：
- access.log 时间戳应刷新为当前时刻
- access.log.1 是刚才整天的旧日志
- nginx 仍在写新 access.log（postrotate 生效），而不是继续写 .1
```

### 场景二：把多台服务器日志集中到一台 rsyslog 服务器

```shell
# 客户端（每台服务器，192.168.1.100 是日志服务器）
echo '*.* @192.168.1.100:514' | sudo tee /etc/rsyslog.d/remote.conf
sudo systemctl restart rsyslog
# 服务端（日志中心）验证
ss -tlnp | grep 514          # 514 在监听（imtcp 已开）
tail -f /var/log/remote/web1/sshd.log   # 客户端日志按主机到达
# 服务器自己也要留日志：加一条规则让收到的日志同时写本地
```

```text
安全注意：514 是特权端口，rsyslog 需要 root 才能监听；客户端来源没做认证，
公网环境务必配 TLS + 访问控制（见「安全与权限」）。
```

### 场景三：journald 日志导出与归档

journald 日志不落文本，要长期保留或集中，先导出：

```shell
# 1. 导出二进制格式（可重放，最保真）
journalctl --output=export --since "2026-08-01" > journal-export.bin
# 2. 导出 JSON（给 Filebeat/脚本采集）
journalctl -o json --since "1 hour ago" | head -5
# 3. 按服务导出文本归档
journalctl -u nginx --since "2026-08-01" > nginx-202608.log
# 4. 清理：设上限后手动瘦身
journalctl --vacuum-size=500M
```

### 场景四：磁盘容量规划与压缩估算

```shell
# 1. 摸清每天日志量（看昨天的轮转文件大小）
ls -lh /var/log/syslog.1 /var/log/nginx/access.log.1
# 2. 看压缩收益（对比 .1 明文和 .2.gz 压缩后）
ls -lh /var/log/syslog.1 /var/log/syslog.2.gz
# 3. 估算：每日 20M × 90 天 × 压缩 20% ≈ 360M 归档空间
# 4. 落配置：rotate 90 + compress，磁盘紧张就 rotate 30
sudo vi /etc/logrotate.d/rsyslog   # rotate 4 → rotate 30
```

```text
实测压缩收益（本机 syslog 系列）：
syslog.1 明文 19M，syslog.2.gz 压缩后 1.7M，压缩比约 9:1
日志文本重复度高（时间戳、重复行），gzip 收益很大
```

## 性能与调优

```text
1. 轮转周期 —— 日志量大改 size 触发（如 size 100M），别只靠 daily；
   一天几个 G 的服务 daily 都太晚，要 hourly + size 双触发
2. 压缩开销 —— gzip 是默认，CPU 占用低；海量日志可换 zstd（compresscmd /usr/bin/zstd
   compressext .zst），压缩快且压缩比更好；delaycompress 把压缩挪到深夜
3. copytruncate 代价 —— 大文件复制吃 IO，几 G 的日志别用 copytruncate，
   优先 create + postrotate
4. 集中传输 —— 日志量大用 TCP（可靠）或 Kafka 缓冲，别直接打爆日志服务器；
   服务器侧开多线程（rsyslog 的 processqueue）或上 ELK
5. 存储清理 —— ELK/Loki 设保留期（如 7 天）和降采样，防存储爆炸；
   ES 用 ILM 自动冷热分层
6. 轮转本身的开销 —— logrotate 只在每天 00:00 跑一次，处理几千个文件也就几秒；
   手动 -f 全量强制轮转才明显耗时
```

## 安全与权限

```text
1. 归档权限 —— 压缩日志含敏感信息（登录/请求/命令），.gz 权限和明文一致收紧；
   nginx 配置 create 0640 www-data adm 就是为了不让普通用户读请求日志
2. 传输加密 —— rsyslog 远程转发默认明文，跨公网用 TLS：
   module(load="imtcp" StreamDriver.Name="gtls" StreamDriver.Mode="1" ...)
   或 RELP + 证书；最低限度也要放内网 VLAN 里
3. 日志服务器安全 —— 日志中心是审计证据集中地，单独部署、限制访问、
   定期备份，别和业务混在一台
4. 归档保留期 —— 按合规要求定（等保/金融常见 6 个月起），到期安全删除
5. 注入防护 —— 日志内容可能被伪造（用户输入进日志），解析端要防
   Log4Shell 式注入，落盘时过滤控制字符
6. 514 端口 —— 特权端口只能 root 监听，客户端无认证，公网暴露 514
   等于给别人塞日志/占磁盘，必须限制来源（防火墙 + TLS）
```

## 故障排查

### 案例一：轮转不生效，日志还在涨

```shell
# 1. 调试模式看轮转计划（不实际执行，直接报配置错误）
logrotate -d /etc/logrotate.d/服务名
# 2. 确认日志路径和配置匹配（通配符覆盖到文件了吗）
cat /etc/logrotate.d/服务名
ls -l /var/log/服务名*.log
# 3. 看 state 文件里上次轮转时间（没到周期属正常）
grep 服务名 /var/lib/logrotate/status
# 4. 手动强制轮转验证
logrotate -f /etc/logrotate.d/服务名
```

```text
高频原因：state 文件里刚轮转过（周期没到）；路径通配符不匹配；
配置语法错（logrotate -d 会直接报）；timer/cron 没跑（systemctl list-timers）。
```

### 案例二：轮转后服务还写旧文件

```shell
# 1. 看服务持有的日志文件句柄指向谁
lsof | grep '/var/log/服务名'
# 如果还指向 .1 旧文件（inode 没变），说明服务没重开日志
# 2. 立即止血：给服务发信号重开文件
kill -USR1 $(pgrep 服务名)     # nginx/rsyslog 系用 USR1 重开日志
# 3. 根治：create 方式必须配 postrotate；或改用 copytruncate
```

```text
判定技巧：lsof 输出里 NAME 列显示 /var/log/服务名.log.1 就是旧句柄；
inode 数字对比（ls -i 与 lsof）最准确。
```

### 案例三：远程转发丢日志

```shell
# 1. 服务器确认 514 在监听、防火墙放行
ss -tlnp | grep 514
# 2. 客户端测试单条转发
logger -t test-remote "hello remote"
# 3. 服务器看是否到达
tail -f /var/log/remote/客户端主机名/test-remote.log
# 4. UDP 丢包看不到痕迹，改用 TCP
# 客户端：*.* @@192.168.1.100:514
# 5. 服务器加队列缓冲
# global(processInternalMessages="on")
```

### 案例四：轮转后文件属主/权限不对

```shell
# 现象：轮转后 access.log 变成 root:root，nginx 写不进去
# 原因：配置里没写 create 的属主，新建文件用了默认
# 解法：logrotate 配置加 create 0640 www-data adm；
# 或全局 /etc/logrotate.conf 的 su root adm 保证执行权限
ls -l /var/log/nginx/access.log
```

## 常见问题

```text
Q1: logrotate 轮转后服务继续写旧文件？
A: 服务持有旧文件句柄，轮转移动文件后服务不知道。用 copytruncate（复制后清空），
   或让服务支持重开日志（postrotate 发 USR1/reopen）。lsof 查句柄确认。

Q2: rsyslog 远程转发丢日志？
A: UDP 不可靠（网络抖动会丢），重要日志用 TCP（@@ 前缀）或 RELP。

Q3: ELK 和 Loki 怎么选？
A: 大规模日志全文检索分析用 ELK（成熟强大但重）；中小规模/和 Grafana 整合用 Loki
   （轻量按标签索引，不索引全文）。

Q4: rotate 保留几份合适？
A: 按「审计要求 + 磁盘空间」权衡，rotate 14~30 常见；日志量大且磁盘紧就少留，
   合规要求长保留就把归档搬到冷存储/对象存储。

Q5: copytruncate 和 create 什么区别？
A: create 改名后新建文件，需要 postrotate 通知进程重开；copytruncate 复制后清空
   原文件，进程无感知，适合不支持下重开日志的程序，但可能丢几行且大文件复制吃 IO。

Q6: logrotate 的 dateext 有什么用？
A: 归档名用日期（access.log.20260819）代替序号（access.log.1），跨年好辨认、
   不容易和序号混淆；配 dateformat -%Y%m%d 自定义格式。

Q7: 为什么 logrotate 到点没执行？
A: 先确认触发机制：systemd 系统看 logrotate.timer（systemctl list-timers），
   老系统看 /etc/cron.daily/logrotate；再看 state 文件是否已记录本次轮转。

Q8: journald 的日志要 logrotate 吗？
A: 不用，journald 自己按 SystemMaxUse 滚动清理；logrotate 只管 /var/log 文本。
   journald 日志归档用 journalctl --output=export 导出。

Q9: 轮转频率和日志量怎么匹配？
A: 日增量 < 100M 用 daily；百 M 到 G 级用 size 100M+；大日志考虑 hourly timer +
   maxsize 双触发，别让单个轮转周期内日志涨到几 G。
```

## 面试题

```text
1. logrotate 的 copytruncate 是做什么的？
   答：复制日志后清空原文件，解决「服务持有文件句柄、轮转后还写旧文件」的问题，
       适合不支持重开日志的服务；代价是复制期间可能丢几行、大文件复制吃 IO。

2. 日志集中有哪些方案？
   答：传统 rsyslog 远程转发（UDP/TCP/RELP/TLS）；现代 ELK
       （Filebeat+Logstash+Elasticsearch+Kibana）、Loki（Grafana 出品）。

3. 为什么集中日志建议用 TCP 而不是 UDP？
   答：UDP 不可靠、网络抖动会丢日志；TCP 保证送达，重要日志/审计场景用 TCP。

4. 日志无限增长怎么防？
   答：文本日志配 logrotate 轮转（rotate N + compress）；journald 设 SystemMaxUse；
       ELK/Loki 设保留期和降采样。

5. 轮转后 nginx 还在写旧文件是怎么回事？
   答：nginx 的文件句柄还指向被改名的 inode，postrotate 没生效或没配；
       解法：配置里 postrotate 调 nginx -s reopen（或 USR1），或改用 copytruncate。

6. logrotate 的 delaycompress 解决什么问题？
   答：轮转后最新一份 .1 先不压缩，等下次轮转再压；排查问题时 .1 是明文可直接
       grep，不用先解压，也避免轮转瞬间压缩占 CPU。

7. 怎么设计日志保留策略？
   答：先定合规要求（留多久），再算每日日志量和压缩比，反推磁盘容量；
       logrotate rotate N、journald MaxRetentionSec、ES ILM 分层落盘。

8. 集中日志服务器怎么按来源分目录？
   答：rsyslog 服务器用模板 $template RemoteLogs,"/var/log/remote/%HOSTNAME%/%PROGRAMNAME%.log"
       落盘，客户端日志按主机名分目录，避免混在一起。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 所有写日志的服务都要配 logrotate，别让日志无限增长
2. 轮转保留份数按「审计要求 + 磁盘空间」权衡，rotate 14~30 常见
3. 守护进程写日志必须有 postrotate 通知重开文件，没有就 copytruncate
4. 多机日志集中（rsyslog 转发或 Loki/ELK），别一台台登上去查
5. 归档日志压缩 + 定期清理，防磁盘占满
6. 集中日志要配检索（Loki/ELK），否则集中了也查不动
7. 改完 logrotate 配置先 -d 调试再 -f 强制验证，别直接等明天
8. 日志文件权限收紧（640），压缩归档同样收紧
9. journald 设 SystemMaxUse 上限，防止二进制日志无限增长
10. 容量规划按「每日量 × 天数 × 压缩比」估算，给磁盘留 20% 余量

### 踩坑记录

```text
坑 1：日志没配轮转，磁盘被占满
结论：某服务日志一直涨，磁盘满了，业务挂掉。
原因：没配 logrotate，日志无限增长。
解法：给服务加 logrotate 配置，rotate N + compress；journald 设 SystemMaxUse。

坑 2：copytruncate 没用导致日志继续写旧文件
结论：轮转后服务还写旧文件，新日志文件是空的。
原因：服务持有日志文件句柄，轮转移动文件后服务不知道。
解法：用 copytruncate（复制后清空原文件），或让服务支持重开日志（SIGHUP/USR1）。

坑 3：rsyslog 远程转发用 UDP 丢日志
结论：日志集中后发现有丢失，还找不到规律。
原因：UDP 不可靠，网络抖动会丢。
解法：重要日志用 TCP（@@ 双 @），或 RELP 带确认，别用 UDP 传审计日志。

坑 4：ELK/Loki 没配日志清理，存储爆炸
结论：集中日志后存储快速占满。
原因：日志量巨大，没配保留期限/压缩。
解法：设日志保留期（如 7 天），按需降采样或压缩，ES 用 ILM。

坑 5：logrotate 配置语法错，轮转静默失败
结论：轮转没生效，日志还在涨，cron 里报错也不看。
原因：logrotate 配置语法错，或路径写错，错误只在 cron 邮件里。
解法：logrotate -d 调试模式看报错，确认路径正确后再 -f 验证。

坑 6：postrotate 忘配 sharedscripts，reload 被执行 N 次
结论：nginx 配置里多个 .log 文件，轮转后 nginx reload 了 4 次。
原因：没有 sharedscripts，每个文件轮转后都执行一次 postrotate。
解法：多文件共用一个脚本时加 sharedscripts，脚本只执行一次。

坑 7：delaycompress 忘配，排查时旧日志全是 .gz
结论：要查昨天的日志，发现 .1 已是 .gz，每次都要 zcat。
原因：compress 直接压缩了最新旧档，没有延迟。
解法：配 delaycompress，最新一份留明文；配合 rotate N 保证有明文可查。

坑 8：轮转后新文件属主 root，服务写不进去
结论：nginx 轮转后 access.log 变 root:root，权限报错。
原因：配置没写 create 的属主，或全局 su root adm 没生效。
解法：nginx 配置 create 0640 www-data adm，明确新建文件的属主权限。

坑 9：journald 和 logrotate 各管各的，磁盘还是满
结论：/var/log 清了，磁盘还是满的。
原因：journald 二进制日志在 /var/log/journal，logrotate 管不了它。
解法：journald.conf 设 SystemMaxUse，journalctl --vacuum-size 立即清理。
```

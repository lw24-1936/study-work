## 概述

系统监控工具回答「系统现在什么状态、谁在吃资源」：top/htop 看总览（CPU/内存/进程），vmstat 看内存与 CPU 动态，iostat 看磁盘 IO，mpstat 看每个 CPU 核心，sar 看历史（后台采集），pidstat 看单进程的 CPU/内存/IO。这些工具分工明确，配合起来能定位「CPU 飙高」「内存不够」「IO 慢」等绝大多数性能问题。

```text
# 实测（本机监控工具可用性）
$ for t in top htop vmstat iostat mpstat sar pidstat; do
>   command -v $t >/dev/null && echo "$t: 有" || echo "$t: 无"; done
top: 有   htop: 无   vmstat: 有   iostat: 有   mpstat: 有   sar: 有   pidstat: 有
# 本机 sysstat 系列（iostat/mpstat/sar/pidstat）齐全，htop 未装
```

## 核心概念

1. **top / htop**：实时总览。top 顶部是系统汇总（load average、CPU、内存），下面是进程列表（按 CPU 排序）；htop 是增强版（彩色、鼠标、树状）。
2. **vmstat**：报告内存、CPU、IO、系统（进程/中断/上下文切换）的动态，是「快速看系统整体健康」的工具。
3. **iostat / mpstat**：iostat 看磁盘 IO（吞吐、IOPS、延迟 await、利用率 %util）；mpstat 看每个 CPU 核心的利用率（-P ALL）。
4. **sar / pidstat**：sar 是历史监控（后台定时采集，查历史时段）；pidstat 是进程级监控（单进程的 CPU/内存/IO）。

```text
工具分工：
top/htop 总览 → vmstat 整体动态 → iostat 磁盘 → mpstat 每核 → sar 历史 → pidstat 进程级
```

## 工作原理

这些监控工具本质是「读取内核维护的计数器」——CPU 时间片、内存页、磁盘 IO、网络字节数都记录在 /proc 和 /sys 里，工具定时采样并计算差值，得出「每秒的 CPU 使用率/IO 量/网络流量」。

top 是实时采样（默认每 3 秒刷新一次）；sar 是后台采样（sysstat 服务通过 cron 定时采集，存到 /var/log/sysstat/ 历史文件），所以能「事后看当时」。pidstat 直接读 /proc/<pid>/ 下的进程计数器。

```text
监控原理：
内核计数器（/proc、/sys）→ 工具定时采样 → 计算差值 → 得出每秒使用率/IO量
top 实时采样，sar 后台采样存历史，pidstat 读进程计数器
```

## 常用命令与配置

```shell
top                    # 实时总览
top -u alice           # 只看某用户
top -p 1234            # 只看某进程
top -H -p 1234         # 看某进程的线程
vmstat 1 5             # 每秒采样 5 次
vmstat -s              # 汇总统计
vmstat -d              # 磁盘统计
iostat -x 1 3          # 磁盘 IO 扩展指标（await/%util 关键）
iostat -p sda          # 看某块盘
mpstat -P ALL 1 3      # 每核 CPU
mpstat 1 3             # 总体 CPU
sar -u 1 5             # CPU 历史/实时
sar -r                 # 内存
sar -d                 # 磁盘 IO
pidstat 1 5            # 所有进程的 CPU
pidstat -p 1234 1      # 某进程的 CPU/内存/IO
pidstat -d             # 进程磁盘 IO
```

```text
# 实测（本机 vmstat）
$ vmstat 1 2
 r b  free   buff   cache   si so  bi bo  us sy id wa
 0 1  198460 1427756 8663680  0  0   8 101  1  0 97  2
 0 0  192076 1427756 8663684  0  0   0  24  8  1 87  4
# r=0（无排队）、si/so=0（无换出）、id=97（CPU 空闲），系统空闲健康
```

## 配置文件解析

sar 的历史采集由 sysstat 服务控制，配置文件在 /etc/default/sysstat（Debian/Ubuntu）或 /etc/sysconfig/sysstat（RHEL）：

```text
# /etc/default/sysstat（Debian/Ubuntu）
ENABLED="true"          # 开启后台采集（false 则 sar 无历史数据）
```

```text
# /etc/cron.d/sysstat 采集周期
5-55/10 * * * * root command -v debian-sa1 > /dev/null && debian-sa1 1 1   # 每 10 分钟采一次
```

```text
top 配置（~/.toprc）：
保存的交互设置（排序键、显示列）。按键 W 可把当前配置写入 ~/.toprc，下次生效
```

## 应用场景实战

### 场景一：CPU 飙高，定位到进程和核心

```shell
# 1. top 看哪个进程吃 CPU
top
# 2. mpstat 看是不是单核飙高
mpstat -P ALL 1 3
# 3. pidstat 看进程的 CPU 细节
pidstat -p <PID> 1
# 4. 看进程的线程（哪个线程在飙）
top -H -p <PID>
```

### 场景二：磁盘慢，用 iostat 分析

```shell
# 1. iostat 看磁盘 IO
iostat -x 1 5
# 2. 关注 await（延迟）和 %util（繁忙度）
# 3. 找是哪个进程在狂读写磁盘
pidstat -d 1
# 4. 或用 iotop（需装）
```

## 性能与调优

```text
1. 采样间隔 —— 别太密（1 秒足够看趋势），太密本身消耗 CPU
2. sar 历史 —— 开启 sysstat 后台采集，事后才能回溯「当时系统状态」
3. 关注点 —— CPU 看 load+us/sy/wa，内存看 si/so，磁盘看 await+%util
4. 长监控 —— 用 sar -o 输出到文件，事后分析，别靠屏幕刷屏
```

## 安全与权限

```text
1. top 信息泄露 —— top/ps 会暴露其他用户的进程命令行（可能含密码），普通用户默认看不到别人的进程
2. pidstat 权限 —— 看其他用户的进程需要 root，/proc 的 hidepid 可进一步限制
3. sar 历史敏感 —— /var/log/sysstat 含系统状态，权限默认 root 可读
4. 监控数据外发 —— 别把监控数据（含进程/用户信息）随意发到外部
```

## 故障排查

### load average 高但 CPU 不高

```shell
# 1. 看 CPU 分布（wa 高 = 等 IO，不是 CPU 忙）
vmstat 1 5
# 2. 看不可中断进程（D 状态 = 等 IO）
top -b -n 1 | awk '$8=="D"'
# 3. 定位 IO 瓶颈
iostat -x 1 3
```

### sar 查不到历史数据

```shell
# 1. 确认 sysstat 服务已启用
systemctl status sysstat
# 2. 确认采集配置开启
grep ENABLED /etc/default/sysstat
# 3. 看历史文件是否存在
ls /var/log/sysstat/
```

## 常见问题

```text
Q1: htop 命令不存在？
A: htop 不是默认安装，apt install htop，或直接用 top。

Q2: load average 高就一定是 CPU 不够？
A: 不一定。load 包含「等待 IO/不可中断」的进程，wa 高说明是 IO 瓶颈不是 CPU。

Q3: sar 查不到历史数据？
A: sysstat 服务没开（不采集就没历史），systemctl enable --now sysstat。

Q4: iostat 的 %util 100% 就是磁盘瓶颈？
A: 不一定。%util 高只说明有 IO 在排队，要结合 await（延迟）和 IOPS 综合判断。
```

## 面试题

```text
1. load average 和 CPU 使用率的区别？
   答：load 是运行队列长度（含等 IO 的不可中断进程），CPU 使用率是 CPU 忙的比例。load 高可能不是 CPU 瓶颈，而是 IO 瓶颈。

2. 怎么定位「单核飙高、多核空闲」？
   答：mpstat -P ALL 看每核，或 top 按 1 看每核；进程没做并行/亲和性导致单核跑满。

3. iostat 的 await 和 %util 分别指什么？
   答：await 是平均 IO 延迟（高 = 磁盘慢），%util 是设备繁忙度（接近 100% = 饱和）。

4. sar 和 pidstat 的区别？
   答：sar 是历史监控（后台采集、事后分析），pidstat 是进程级（定位哪个进程吃资源）。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 先 top 看总览定位方向，再用专项工具（iostat/mpstat/pidstat）深入
2. 看磁盘性能用 iostat -x，重点看 await 和 %util
3. 单核飙高用 mpstat -P ALL，负载不均可能是进程没做亲和性
4. 事后分析用 sar（历史数据），定位进程用 pidstat
5. sysstat 包（iostat/mpstat/sar/pidstat）装一下，排查性能必备

### 踩坑记录

```text
坑 1：htop 命令不存在
结论：敲 htop 报 command not found。
原因：htop 不是默认安装，要单独装。
解法：apt install htop，或直接用 top。

坑 2：load average 高就以为 CPU 不够
结论：load 高，但 CPU 使用率不高。
原因：load 包含「等待 IO/不可中断」的进程，load 高可能是 IO 瓶颈不是 CPU。
解法：看 vmstat 的 wa（等 IO）列，wa 高说明是 IO 问题。

坑 3：只看 top 的 %CPU 忽略单核飙高
结论：多核机器某进程 %CPU 100%，但整体 CPU 不高。
原因：单核跑满，其他核空闲，进程没做并行/亲和性。
解法：mpstat -P ALL 看每核，top 按 1 看每核负载。

坑 4：iostat 的 %util 100% 就判断磁盘慢
结论：%util 100% 就换磁盘，其实还有优化空间。
原因：%util 接近 100% 只说明「有 IO 在排队」，不一定是硬件瓶颈。
解法：结合 await（延迟）和 r/s w/s（IOPS）综合判断。

坑 5：sar 查不到历史数据
结论：sar 命令有，但查历史没数据。
原因：sysstat 服务没开（不采集就没历史）。
解法：systemctl enable --now sysstat，确保定时采集。
```

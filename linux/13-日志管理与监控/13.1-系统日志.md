## 概述

系统日志记录「系统发生了什么」，是排查问题的第一手资料。Linux 有两套日志系统并存：rsyslog（传统，写 /var/log/ 下的文本文件，如 /var/log/auth.log）和 journald（systemd 自带，二进制日志，journalctl 查看）。日志有「级别」（debug/info/warning/error 等）和「设施」（auth/kern/mail 等来源分类）。排查问题先看日志，`journalctl` 是核心工具。

```text
两套日志系统：
1. rsyslog —— 传统 syslog，写 /var/log/ 文本文件（auth.log、syslog）
2. journald —— systemd 自带，二进制日志，journalctl 查看
3. 级别 facility —— 严重程度（debug~emerg）+ 来源分类（auth/kern/mail）
```

## 核心概念

系统日志围绕几个核心概念展开：

1. **syslog 与 rsyslog**：syslog 是日志协议/标准，rsyslog 是它的实现（守护进程），把系统和服务产生的日志写到 /var/log/ 下的文本文件。配置文件 /etc/rsyslog.conf（+ /etc/rsyslog.d/），定义「什么设施什么级别写到哪个文件」。
2. **journald**：systemd 自带的日志系统，收集所有 systemd 服务和内核日志，存成二进制格式，用 journalctl 查看。优势是按服务/时间过滤、带结构化元数据。
3. **日志级别（severity）**：严重程度，从低到高 debug、info、notice、warning、err、crit、alert、emerg，用来按严重程度过滤。
4. **日志设施（facility）**：标识日志来源——auth（认证）、kern（内核）、mail（邮件）、daemon（守护进程）、user（用户进程）。

```text
日志级别（从低到高）：
debug < info < notice < warning < err < crit < alert < emerg

常见设施（facility）：
auth 认证 | kern 内核 | mail 邮件 | daemon 守护进程 | user 用户进程
```

## 工作原理

日志从产生到落盘是一条流水线：

1. **产生**：内核（kmsg）和用户进程（syslog 接口）产生日志。
2. **接收**：rsyslog 通过 /dev/log（本地 socket）接收用户进程日志，通过 kmsg 接收内核日志；journald 直接接管 systemd 服务的 stdout/stderr 和内核日志。
3. **写入**：rsyslog 按「设施.级别 → 目标文件」规则写到 /var/log/*；journald 写二进制日志（/var/log/journal/）。
4. **轮转**：logrotate 定期切割/压缩/删除旧日志，防止占满磁盘。

两套系统并存：rsyslog 可用 imjournal 模块读取 journald 日志，journald 也可 ForwardToSyslog 转给 rsyslog，保证两边都能查到。

```text
日志流水线：
产生（内核 kmsg / 进程 syslog）→ 接收（rsyslog / journald）→ 写入（文本文件 / 二进制）→ 轮转（logrotate）
```

## 常用命令与配置

```shell
tail -f /var/log/syslog       # 实时看系统日志
tail -f /var/log/auth.log     # 实时看认证日志（登录/SSH）
journalctl                    # journald 全部日志
journalctl -u nginx           # 某服务的日志
journalctl -u nginx -f        # 实时跟踪
journalctl -b                 # 本次启动的日志
journalctl -b -1              # 上次启动的日志
journalctl -p err             # 只看 error 及以上
journalctl --since "1 hour ago"   # 按时间
systemctl status rsyslog      # rsyslog 服务状态
```

```text
# 实测（journalctl 最近日志）
$ journalctl -n 3 --no-pager
8月18 23:20:17 lw-Vostro-7580 systemd[1]: Starting sysstat-collect.service...
8月18 23:20:17 lw-Vostro-7580 systemd[1]: sysstat-collect.service: Deactivated successfully.
8月18 23:20:58 lw-Vostro-7580 tailscaled[3281909]: magicsock: closing connection to derp-26 (idle)
# 每条日志有：时间 + 主机名 + 进程[PID] + 消息
```

## 配置文件解析

rsyslog 主配置 /etc/rsyslog.conf 用「选择器 + 动作」格式定义日志写入规则：

```text
# /etc/rsyslog.conf 片段（选择器 + 动作）
auth,authpriv.*                 /var/log/auth.log    # 认证日志
*.*;auth,authpriv.none          -/var/log/syslog     # 系统主日志（- 表示异步写）
kern.*                          -/var/log/kern.log   # 内核日志
mail.*                          -/var/log/mail.log   # 邮件日志
*.emerg                         :omusrmsg:*          # 紧急日志广播给所有用户
```

```text
字段含义：
选择器 = 设施.级别（* 表示全部，none 表示排除）
动作   = 文件路径 / 远程转发 / 终端 / 用户
- 前缀  = 异步写（不立即 fsync，性能好）
```

```text
# 实测（本机 /var/log 关键日志文件）
$ ls /var/log/ | head
auth.log          # 认证日志（登录/提权）
auth.log.1        # 轮转后的旧日志
auth.log.2.gz     # 压缩归档的旧日志
boot.log          # 启动日志
syslog            # 系统主日志
# .1/.2.gz 后缀 = logrotate 轮转+压缩的归档
```

journald 的配置在 /etc/systemd/journald.conf，关键字段：

```text
# /etc/systemd/journald.conf 关键项
Storage=persistent      # 持久化（auto/volatile/persistent/none）
SystemMaxUse=1G         # 日志总上限，防止占满磁盘
SystemKeepFree=1G       # 给磁盘保留的空间
MaxRetentionSec=1month  # 最长保留时间
```

## 应用场景实战

### 场景一：服务起不来，查日志定位原因

```shell
# 1. 看服务的日志
journalctl -u nginx -n 50
# 2. 实时跟踪（配合重启服务复现）
journalctl -u nginx -f
# 3. 按级别过滤错误
journalctl -u nginx -p err
```

### 场景二：排查登录失败/暴力破解

```shell
# 1. 看认证日志
tail -f /var/log/auth.log
# 2. 统计失败登录
grep 'Failed password' /var/log/auth.log | wc -l
# 3. 看失败来源 IP
grep 'Failed password' /var/log/auth.log | awk '{print $(NF-3)}' | sort | uniq -c | sort -rn
```

## 性能与调优

```text
1. 异步写 —— rsyslog 动作前加 -（如 -/var/log/syslog），不立即 fsync，减少 IO
2. 日志上限 —— journald 设 SystemMaxUse，避免日志无限增长
3. 级别过滤 —— 生产环境日志级别别开太低（debug），减少日志量
4. 磁盘 IO —— 日志写密集的服务考虑把日志放到独立磁盘/SSD
```

## 安全与权限

```text
1. 日志文件权限 —— /var/log/auth.log 通常 640，只 root/adm 可读，防泄露登录信息
2. 日志防篡改 —— 日志是审计证据，集中转发到日志服务器（脱离被入侵机器）
3. journald 访问 —— journalctl 需要 adm/systemd-journal 组权限，普通用户默认看不了全部
4. 敏感信息 —— 日志里别记密码/令牌，必要时脱敏
```

## 故障排查

### 日志文件没更新 / 服务没打日志

```shell
# 1. 确认 rsyslog 服务在跑
systemctl status rsyslog
# 2. 看日志文件最后修改时间
ls -l /var/log/syslog
# 3. 确认服务自己的日志写到哪（不是所有服务都走 syslog）
journalctl -u 服务名 -n 20
```

### 日志占满磁盘

```shell
# 1. 找最大的日志文件
du -sh /var/log/* | sort -rh | head
# 2. 找被删除但仍占空间的日志文件
lsof +L1 | grep deleted
```

## 常见问题

```text
Q1: journalctl 和 /var/log 里的日志对不上？
A: rsyslog 和 journald 是两套系统，rsyslog 需配置 imjournal 模块转发 journald 日志，否则 journald 有而 /var/log 没有。

Q2: journalctl -b 看的是哪次启动？
A: 默认当前启动（-b），上次启动要 -b -1，更早用 -b -2。

Q3: 日志级别 warning 和 err 谁更严重？
A: err 更严重，顺序 debug<info<notice<warning<err<crit<alert<emerg。

Q4: 服务自己写日志文件，journalctl 查不到怎么办？
A: 服务没经过 systemd/syslog，直接看它自己写的 /var/log/xxx.log。
```

## 面试题

```text
1. rsyslog 和 journald 的区别？
   答：rsyslog 是传统 syslog 实现，写 /var/log 文本文件；journald 是 systemd 自带，二进制日志，按服务/时间结构化过滤。

2. 日志的「级别」和「设施」分别指什么？
   答：级别（severity）是严重程度（debug~emerg），设施（facility）是来源分类（auth/kern/mail）。

3. 日志无限增长怎么办？
   答：logrotate 轮转（切割/压缩/删除）+ journald 设 SystemMaxUse 上限。

4. 排查一次登录失败/暴力破解看什么日志？
   答：/var/log/auth.log（或 journalctl -u ssh），grep 'Failed password' 统计失败来源 IP。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 排查问题先看日志（journalctl -u 服务名），别瞎猜
2. 实时跟踪用 -f，复现问题时边操作边看日志
3. 日志按级别过滤（-p err）快速定位错误
4. 登录/安全问题查 /var/log/auth.log
5. journalctl 和 rsyslog 并存，服务日志用 journalctl、系统日志看 /var/log

### 踩坑记录

```text
坑 1：journalctl 和 /var/log 里的日志对不上
结论：journalctl 有日志，但 /var/log/syslog 里没有。
原因：rsyslog 和 journald 是两套，rsyslog 可能没转发 journald 的日志。
解法：确认 rsyslog 配置（imjournal 模块）转发 journald 日志。

坑 2：journalctl -b 看错启动的日志
结论：排查启动问题，journalctl -b 看的是本次，问题在上次启动。
原因：-b 默认当前启动，上次启动要 -b -1。
解法：排查启动失败用 journalctl -b -1。

坑 3：日志把磁盘占满
结论：/var/log 或 journald 日志无限增长，磁盘满了。
原因：没配日志轮转/上限，日志无限累积。
解法：配 logrotate 轮转，journald 设 SystemMaxUse 上限。

坑 4：journalctl 按服务查不到日志
结论：journalctl -u 服务名 没输出，但服务在跑。
原因：服务自己写日志文件（不经过 systemd），或用了 syslog 不是 journald。
解法：看服务自己写的日志文件（/var/log/xxx.log），别只查 journalctl。

坑 5：日志级别搞反，err 和 warning 分不清
结论：以为 warning 比 err 严重，过滤错了。
原因：级别顺序记反（warning 比 err 低）。
解法：记 debug<info<notice<warning<err<crit<alert<emerg。
```

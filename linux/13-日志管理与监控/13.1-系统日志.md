## 概述

系统日志记录「系统发生了什么」，是排查问题的第一手资料。Linux 有两套日志系统并存：rsyslog（传统，写 /var/log/ 下的文本文件，如 /var/log/auth.log）和 journald（systemd 自带，二进制日志，journalctl 查看）。日志有「级别」（debug/info/warning/error 等）和「设施」（auth/kern/mail 等来源分类）。排查问题先看日志，`journalctl` 是核心工具。

```text
两套日志系统：
1. rsyslog —— 传统 syslog，写 /var/log/ 文本文件（auth.log、syslog）
2. journald —— systemd 自带，二进制日志，journalctl 查看
3. 级别 facility —— 严重程度（debug~emerg）+ 来源分类（auth/kern/mail）
4. 内核日志 —— printk → ring buffer → dmesg/kmsg，rsyslog 与 journald 都能收
5. 轮转 —— logrotate 定期切割/压缩/删除，防止日志占满磁盘（详见 13.2）
```

## 核心概念

### syslog 与 rsyslog

syslog 是日志协议/标准（RFC 3164 旧版、RFC 5424 新版），规定了「一条日志由哪些字段组成、怎么传输」。rsyslog 是它的主流实现（守护进程 rsyslogd），把系统和服务的日志写到 /var/log/ 下的文本文件。配置文件 /etc/rsyslog.conf（+ /etc/rsyslog.d/），定义「什么设施什么级别写到哪个文件」。

rsyslog 相比老 syslogd 的增强：支持模块化（imuxsock 本地 socket、imklog 内核、imjournal 读 journald、imudp/imtcp 网络收发）、模板（template）定制落盘格式、队列缓冲、TLS 加密、高性能异步写。

```text
一条 syslog 消息的标准字段：
时间戳 + 主机名 + 程序名[PID] + 消息内容
例：8月 19 12:34:50 lw-Vostro-7580 tailscaled[3281909]: monitor: RTM_NEWROUTE: ...
```

### journald

journald（systemd-journald）是 systemd 自带的日志系统，收集所有 systemd 服务、内核、以及任何写 syslog 接口的进程的日志，存成二进制格式（带结构化元数据），用 journalctl 查看。优势：按服务/时间/级别/字段过滤、日志与元数据一起存（PID、UID、SELinux 上下文、引导 ID）、自动轮转清理。

### 日志级别（severity）

严重程度从低到高共 8 级，数字越小越严重：

| 值 | 级别 | 含义 | 常见场景 |
|---|---|---|---|
| 0 | emerg | 系统不可用 | 内核 panic |
| 1 | alert | 必须立即处理 | 数据库损坏、磁盘满 |
| 2 | crit | 严重 | 硬件故障 |
| 3 | err | 错误 | 服务启动失败 |
| 4 | warning | 警告 | 配置异常但不致命 |
| 5 | notice | 正常但重要 | 服务重启 |
| 6 | info | 信息 | 常规状态记录 |
| 7 | debug | 调试 | 开发期排错用 |

```text
级别顺序：debug < info < notice < warning < err < crit < alert < emerg
过滤时 -p err 表示「err 及以上（数字 <= 3）」，即 err/crit/alert/emerg 全包含
```

### 日志设施（facility）

标识日志来源的分类（RFC 5424 标准 0-23）：

| 值 | facility | 含义 |
|---|---|---|
| 0 | kern | 内核消息 |
| 1 | user | 用户进程 |
| 2 | mail | 邮件系统 |
| 3 | daemon | 系统守护进程 |
| 4 | auth | 安全/认证（已废弃，用 authpriv 替代） |
| 5 | syslog | syslog 内部 |
| 6 | lpr | 打印服务 |
| 7 | news | 新闻组 |
| 8 | uucp | UUCP 传输 |
| 9 | cron | 定时任务 |
| 10 | authpriv | 安全/认证（私有，登录/提权） |
| 11 | ftp | FTP 服务 |
| 16-23 | local0~local7 | 本地自定义（应用常用） |

```text
常见设施：auth 认证 | kern 内核 | mail 邮件 | daemon 守护进程 | user 用户进程 | cron 定时任务
规则写法：设施.级别，如 auth.* 表示 auth 设施的全部级别
```

### /var/log 目录与常见日志文件

| 文件 | 用途 |
|---|---|
| /var/log/syslog | 系统主日志（Debian/Ubuntu，除 auth 外几乎所有日志） |
| /var/log/auth.log | 认证日志（SSH 登录、sudo 提权、su） |
| /var/log/kern.log | 内核日志 |
| /var/log/dmesg | 本次启动的内核 ring buffer 导出 |
| /var/log/boot.log | 开机启动过程输出 |
| /var/log/dpkg.log | dpkg 包安装/升级记录 |
| /var/log/apt/ | apt 操作（history.log 命令记录、term.log 终端输出） |
| /var/log/wtmp、btmp | 成功/失败登录记录（last、lastb 读取） |
| /var/log/lastlog | 每个用户最近一次登录时间 |
| /var/log/journal/ | journald 二进制日志目录 |
| /var/log/nginx/access.log 等 | 应用自身日志（nginx、mysql、redis 各自目录） |

```text
轮转后缀约定：.1（最新旧档）→ .2 → .3，.gz 表示已压缩
例：auth.log → auth.log.1 → auth.log.2.gz → auth.log.3.gz
```

### 内核日志与 ring buffer

内核用 printk() 输出日志，写入内核内存中的环形缓冲区（ring buffer，默认 128KB 左右，可用 dmesg 查看）。ring buffer 满后新日志覆盖旧日志，所以开机太久 dmesg 里早期内容可能被冲掉。内核日志通过 /dev/kmsg 暴露给用户态，rsyslog 用 imklog 模块读取、journald 直接接收，两条通道都能拿到。

```text
printk() → ring buffer（内存） → /dev/kmsg → imklog/journald → /var/log/kern.log / journal
dmesg 查看 ring buffer；rsyslog 落盘的 kern.log 是历史归档，两者内容可能不同步
```

### 用户登录日志（wtmp/btmp/lastlog）

登录相关的三个二进制文件，不是文本，要用专用命令读：

```text
/var/log/wtmp    成功登录/登出记录 → last、who
/var/log/btmp    失败登录记录       → lastb
/var/log/lastlog 各用户最后登录时间 → lastlog
```

### 时间戳、时区与精度

- journald 日志存储时带 UTC 时间（__REALTIME_TIMESTAMP，微秒精度），显示时按本机时区渲染。本机时区 Asia/Shanghai（CST，UTC+8），所以 journalctl 显示 CST，`-o short-iso` 显示 `2026-08-19T12:37:52+08:00`。
- 内核 dmesg 时间戳是「开机以来第几秒」，格式 `[10.613805]`，不是日历时间。
- syslog 文本文件的传统时间戳只有分钟精度，journald 二进制日志是微秒精度。
- 排查「日志时间对不上」先看时区（`timedatectl`），再看是哪个时钟（系统时钟 vs RTC）。

## 工作原理

### 日志从产生到落盘的流水线

```text
产生（内核 kmsg / 进程 syslog 接口 / 服务 stdout）→ 收集（journald / rsyslog）→ 写入（二进制 / 文本）→ 轮转（logrotate）
```

### 内核日志路径

内核日志有两条独立路径到达用户态：一条是 rsyslog 的 imklog 模块读 /dev/kmsg 后按规则写 kern.log；一条是 journald 直接从内核读。两条路径并行，互不依赖。

### rsyslog 的工作模型

rsyslogd 启动后加载 /etc/rsyslog.conf 和 /etc/rsyslog.d/*.conf，配置分三部分：MODULES（加载输入模块）、GLOBAL DIRECTIVES（全局参数）、规则（选择器 + 动作）。运行时通过 /dev/log（unix socket）接收本地进程 syslog 消息，按规则逐条匹配「设施.级别」选择器，命中后执行动作（写文件/转发/终端/忽略）。带 `-` 前缀的动作异步写，不等待 fsync。

```text
进程 → write(/dev/log) → rsyslogd → 规则匹配（selector）→ 动作（/var/log/xxx.log）
规则不命中的日志被丢弃（默认），所以「没进 syslog 文件」不等于「没产生日志」
```

### journald 的工作模型

systemd 服务单元把 stdout/stderr 接到 journald（StandardOutput=journal），服务不打日志文件也能被 journald 捕获；进程调用 syslog() 的日志也进 journald。日志以二进制 journal 文件存储：/run/log/journal/（内存盘，重启丢）或 /var/log/journal/（持久化）。文件达到阈值自动滚动新文件，总量超过 SystemMaxUse 自动清理最旧。

```text
服务 stdout/stderr ─┐
syslog() 调用 ──────┼─► journald ─► /var/log/journal/<machine-id>/ 二进制文件
内核 /dev/kmsg ─────┘
```

### journald 与 rsyslog 的双通道协作

两套系统并存，默认各自收一份：rsyslog 从 /dev/log 和 /dev/kmsg 收，journald 从 native 协议、stdout 接管、内核收。为了让两边内容一致，可以开两条桥：

- journald → rsyslog：/etc/systemd/journald.conf 设 `ForwardToSyslog=yes`（默认开启），journald 把收到的日志再转发给 rsyslog 落文本。
- rsyslog → journald：rsyslog 加载 imjournal 模块读 journald 日志（RHEL 默认配置这么干）。

```text
                 ┌──────────────────────────────┐
内核/进程/服务 ──►│ journald → /var/log/journal/ │
                 └──────────────┬───────────────┘
                                │ ForwardToSyslog=yes（默认开）
                                v
                 ┌──────────────────────────────┐
                 │ rsyslog → /var/log/*.log     │
                 │ （imuxsock/imklog/imjournal） │
                 └──────────────────────────────┘
```

实际效果：大部分日志两边都有，但两边各自独立轮转、独立清理，内容会有时间差和数量差，属正常。

### 日志轮转（logrotate）预告

文本日志无限增长会占满磁盘，logrotate 定期把日志改名归档（.1/.2.gz）、压缩、删除超龄档案，并在轮转后通知服务重开文件。journald 则自己管自己（按 SystemMaxUse 清理）。细节在 13.2 展开，这里只要记住「文本日志靠 logrotate，journald 靠自身清理」。


## 配置文件解析

### /etc/rsyslog.conf 逐段解析

Ubuntu 的 rsyslog 主配置分三部分：MODULES（模块）、GLOBAL DIRECTIVES（全局参数）、IncludeConfig（包含分片）。实测本机完整内容：

```text
# /etc/rsyslog.conf（Ubuntu 默认）
#################
#### MODULES ####
#################
module(load="imuxsock")          # 本地 unix socket 收进程日志（/dev/log）
#module(load="immark")           # 定时 --MARK-- 消息（默认关）
#module(load="imudp")            # UDP 网络接收（集中日志服务器才开）
#input(type="imudp" port="514")
#module(load="imtcp")            # TCP 网络接收
#input(type="imtcp" port="514")
module(load="imklog" permitnonkernelfacility="on")   # 内核日志
###########################
#### GLOBAL DIRECTIVES ####
###########################
$RepeatedMsgReduction on        # 重复消息合并
$FileOwner syslog               # 日志文件属主
$FileGroup adm
$FileCreateMode 0640            # 新建日志文件权限 640
$DirCreateMode 0755
$Umask 0022
$PrivDropToUser syslog          # 降权运行（不用 root）
$PrivDropToGroup syslog
$WorkDirectory /var/spool/rsyslog
# 包含 /etc/rsyslog.d/*.conf（真正写规则的地方）
$IncludeConfig /etc/rsyslog.d/*.conf
```

要点：rsyslogd 降权成 syslog 用户运行（PrivDropToUser），所以 /var/log 下的日志属主大多是 syslog:adm；网络接收模块默认全注释，做集中日志服务器时才打开。

### /etc/rsyslog.d/50-default.conf 规则逐条解析

```text
# 认证日志：auth 和 authpriv 两个设施的全部级别 → auth.log
auth,authpriv.*                 /var/log/auth.log
# 系统主日志：全部设施全部级别，排除 auth 系列（避免重复），- 前缀 = 异步写
*.*;auth,authpriv.none          -/var/log/syslog
# 内核日志
kern.*                          -/var/log/kern.log
# 邮件日志
mail.*                          -/var/log/mail.log
# 紧急消息广播给所有在线用户（写终端，不落盘）
*.emerg                         :omusrmsg:*
```

```text
字段含义：
选择器 = 设施.级别（* 表示全部，none 表示排除，多个用 , 分隔；多个选择器用 ; 分隔）
动作   = 文件路径 / @远程UDP / @@远程TCP / 终端 / :omusrmsg:用户
- 前缀 = 异步写（不立即 fsync，性能好，断电可能丢少量日志）
```

### 选择器（selector）语法详解

```text
格式：设施.级别      匹配「该设施该级别及以上」
     设施.=级别      精确匹配该级别（kern.=err 只匹配 err，不含 crit）
     设施.!级别      该级别以下（不含该级别）
     *.info          所有设施 info 及以上
     mail.none       排除 mail 设施（常与其他选择器组合）
     auth,authpriv.* 多个设施并列
     *.*;auth.none   全部排除 auth（分号连接多个选择器）
优先级比较按数字：err(3) 比 warning(4) 高，*.warning 不含 err
```

Red Hat 系差异：RHEL/CentOS 的规则写在 /etc/rsyslog.conf 主文件（和 /etc/rsyslog.d/ 分片并存），默认落盘目标不同——系统主日志写 /var/log/messages（对应 Ubuntu 的 /var/log/syslog），认证日志写 /var/log/secure（对应 auth.log），另设 cron、maillog、spooler 等文件。迁移脚本或排查时按「文件用途」找，别按文件名套。

### journald 配置 /etc/systemd/journald.conf

本机是 Ubuntu 默认（文件里只有 `[Journal]` 空段，全部走内置默认值），关键项：

```text
# /etc/systemd/journald.conf 关键项（默认值）
Storage=auto             # auto/volatile/persistent/none
                         # auto：/var/log/journal 存在才持久化，否则内存盘 /run/log/journal
                         # persistent：总是持久化到 /var/log/journal
SystemMaxUse=            # 日志总上限，默认磁盘 10%，防止占满
SystemKeepFree=          # 给其他用途保留的空间（默认 15%）
MaxRetentionSec=         # 最长保留时间（默认不限，按空间清理）
Compress=yes             # 旧 journal 文件压缩
ForwardToSyslog=yes      # 转发给 rsyslog（默认开）
ForwardToConsole=no      # 转发到控制台
RateLimitIntervalSec=30s # 限速窗口（默认 30 秒）
RateLimitBurst=10000     # 窗口内最多条数（默认 10000）
```

改完 `systemctl restart systemd-journald` 生效。注意 Ubuntu 默认 Storage=auto 且安装时创建了 /var/log/journal，所以本机是持久化的（`journalctl --disk-usage` 有 637.9M 在磁盘）。

Red Hat 系差异：RHEL 7+ 默认持久化（Storage 默认 auto 但系统预建 /var/log/journal）；Debian/Ubuntu 的 systemd 版本较新，同样默认 auto，只要 /var/log/journal 目录存在就持久化——目录删掉立刻回到内存模式。

## 应用场景实战

### 场景一：服务起不来，查日志定位原因

```shell
# 1. 先看服务状态，拿到失败信息
systemctl status nginx
# 2. 看该服务最近 50 条日志
journalctl -u nginx -n 50
# 3. 只看错误级别
journalctl -u nginx -p err
# 4. 复现问题：边重启边实时跟踪
journalctl -u nginx -f
systemctl restart nginx
# 5. 若 journald 里没有，多半服务自己写文件了
tail -f /var/log/nginx/error.log
```

### 场景二：排查 SSH 暴力破解

```shell
# 1. 实时盯认证日志
tail -f /var/log/auth.log
# 2. 统计失败登录总数
grep 'Failed password' /var/log/auth.log | wc -l
# 3. 按来源 IP 排序（auth.log 中 IP 在第 11 列）
grep 'Failed password' /var/log/auth.log | awk '{print $(NF-3)}' | sort | uniq -c | sort -rn
# 4. journald 角度：看 sshd 的认证失败事件
journalctl -u ssh | grep -i 'failed'
# 5. 失败登录记录文件
lastb | head
```

```text
实测：本机 auth.log 里 Failed password 为 0 条（grep -c 返回 0），说明没有暴力破解，
属于正常值；公网服务器这个数字通常每天几百到上万。
```

### 场景三：应用日志接入 journald

应用不想自己管理日志文件时，三种方式把日志送进 journald：

```shell
# 方式一：logger 命令（脚本最常用），-p 指定设施.级别，-t 指定程序名
logger -p local0.info -t myapp "job finished"
# 方式二：systemd-cat 包装命令，stdout/stderr 全部进 journald
systemd-cat -t myapp python3 /opt/app/run.py
# 方式三：service 单元把 stdout 交给 journald（systemd 默认行为）
# [Service] StandardOutput=journal  StandardError=journal
```

```text
应用日志进 journald 后：
journalctl -t myapp              # 按程序名查
journalctl -t myapp -f           # 实时跟踪
journalctl -t myapp --since "10 min ago"
```

### 场景四：内核与硬件问题用 dmesg

```shell
# 1. 看内核 ring buffer 里的硬件报错
dmesg | grep -iE 'error|fail|usb|xhci' | tail
# 2. 持久化内核日志（rsyslog 已把内核日志写 kern.log）
grep -i error /var/log/kern.log | tail
# 3. 网卡断连/磁盘异常都能在这里看到
dmesg -T   # -T 把秒数时间戳转成可读时间
```

```text
实测：本机 dmesg 有 xhci_hcd USB 控制器报错（HC died; cleaning up），
journalctl -p err 里 kernel 条目就是同一来源，两条通道内容一致。
```

## 性能与调优

```text
1. 异步写 —— rsyslog 动作前加 -（如 -/var/log/syslog），不立即 fsync，减少 IO
2. 日志上限 —— journald 设 SystemMaxUse，避免日志无限增长占满磁盘
3. 级别过滤 —— 生产环境日志级别别开太低（debug），日志量会放大几十倍
4. 磁盘 IO —— 日志写密集的服务把 /var/log 放独立磁盘/SSD，避免和数据盘抢 IO
5. 限速 —— 防日志洪水：rsyslog 的 $SystemLogRateLimitInterval，
   journald 的 RateLimitIntervalSec/RateLimitBurst
6. 压缩 —— journald 的 Compress=yes 对旧文件 gzip 压缩，实测占用可减半以上
7. 及时清理 —— journalctl --vacuum-size / --vacuum-time 手动瘦身
```

journald 日志占用过大的处理（本机实测占用 637.9M）：

```shell
journalctl --disk-usage                    # 先看占多少
journalctl --vacuum-size=200M              # 清到 200M 以内
journalctl --vacuum-time=7d                # 只留最近 7 天
journalctl --vacuum-files=5                # 只留最近 5 个文件
# 想长期限制：/etc/systemd/journald.conf 设 SystemMaxUse=500M 后重启
```

## 安全与权限

```text
1. 文件权限 —— /var/log/auth.log 属主 syslog:adm、权限 640，只有 root 和 adm 组可读，
   防止登录信息泄露；改规则时别把权限放宽成 644 全局可读
2. 日志防篡改 —— 日志是审计证据，单机日志可被入侵者删除/修改；
   重要日志集中转发到日志服务器（脱离被入侵机器），甚至做 WORM 存储
3. journald 访问 —— journalctl 普通用户只能看本用户进程的日志；
   看系统全部日志需要 root 或 adm/systemd-journal 组（usermod -aG adm 用户名）
4. 敏感信息 —— 日志里别记密码/令牌/密钥；应用日志脱敏（打码、不落请求体）
5. dmesg 限制 —— kernel.dmesg_restrict=1 时普通用户不能看 dmesg（内核日志可能含硬件序列号等）
6. 内核日志可能泄露 —— printk 会把 UID 等写进日志，多用户机器注意
```

## 故障排查

### 案例一：日志文件没更新 / 服务没打日志

```shell
# 1. 确认 rsyslog 服务在跑
systemctl status rsyslog
# 2. 看日志文件最后修改时间
ls -l /var/log/syslog
# 3. 确认服务自己的日志写到哪（不是所有服务都走 syslog）
journalctl -u 服务名 -n 20
# 4. 规则被改坏时用语法检查
rsyslogd -N1
```

### 案例二：日志占满磁盘

```shell
# 1. 找最大的日志文件
du -sh /var/log/* | sort -rh | head
# 2. 找被删除但仍占空间的日志文件（服务还握着旧句柄）
lsof +L1 | grep deleted
# 3. journald 占用
journalctl --disk-usage
journalctl --vacuum-size=200M
# 4. 找到元凶后配 logrotate 或 journald 上限（见 13.2）
```

### 案例三：journalctl 查不到服务的日志

```shell
# 1. 确认服务真的在跑
systemctl status 服务名
# 2. 该服务可能不经过 systemd（手动 nohup 起的）或自己写文件
journalctl -u 服务名 -n 10
ls -l /var/log/服务名*.log
# 3. 按程序名试试（-u 匹配 unit 名，-t 匹配程序名）
journalctl -t 程序名 -n 10
# 4. 内存模式重启丢日志：确认 /var/log/journal 存在
ls -ld /var/log/journal
```

### 案例四：日志时间戳与时区对不上

```shell
# 1. 看系统时区/时间是否同步
timedatectl
# 2. 看 journal 内部存储的时间（UTC 微秒）
journalctl -o verbose -n 1 | grep -E 'REALTIME|_SOURCE'
# 3. 内核 dmesg 是开机秒数，不是日历时间，别混着比
dmesg | head -1
# 4. 容器场景注意：容器内时区独立，挂载 /etc/localtime 或设 TZ
```

## 常见问题

```text
Q1: journalctl 和 /var/log 里的日志对不上？
A: rsyslog 和 journald 是两套系统，rsyslog 靠 ForwardToSyslog 收 journald 转发的日志、
   imjournal 模块反向读取，两者各自独立轮转清理，内容有差属正常；
   完全对不上时检查 journald.conf 的 ForwardToSyslog 和 rsyslog 的 imjournal 配置。

Q2: journalctl -b 看的是哪次启动？
A: 默认当前启动（-b），上次启动用 -b -1，更早用 -b -2；
   journalctl --list-boots 列出全部启动记录。

Q3: 日志级别 warning 和 err 谁更严重？
A: err 更严重，数字更小：debug(7) < info(6) < notice(5) < warning(4) < err(3) < crit(2) < alert(1) < emerg(0)。

Q4: 服务自己写日志文件，journalctl 查不到怎么办？
A: 服务没经过 systemd/syslog（如 nohup 手动启动、或程序直接 fopen 写文件），
   直接看它自己写的 /var/log/xxx.log；想统一管理就让服务写 syslog 或用 systemd-cat 包装。

Q5: journald 日志占用太大怎么办？
A: journalctl --vacuum-size=200M 立即清理；长期在 journald.conf 设 SystemMaxUse 上限。

Q6: /var/log/syslog 是空的但 journalctl 有日志？
A: rsyslog 的规则没匹配到（默认规则在 /etc/rsyslog.d/50-default.conf），
   或 ForwardToSyslog=no；先 rsyslogd -N1 检查配置，再看 50-default.conf 的 *.* 规则。

Q7: 日志时间差 8 小时？
A: 多半是时区：显示时按本机时区（CST=UTC+8），存储是 UTC；
   timedatectl 看时区，journalctl -o short-iso 看带偏移的时间。

Q8: 普通用户能看所有日志吗？
A: 不能，默认只能看自己进程的；加入 adm 或 systemd-journal 组后可见系统日志。

Q9: dmesg 权限不够？
A: 内核限制了普通用户读 ring buffer（kernel.dmesg_restrict=1），
   root 或 sysctl kernel.dmesg_restrict=0 才能读。
```

## 面试题

```text
1. rsyslog 和 journald 的区别？
   答：rsyslog 是传统 syslog 实现，按规则写 /var/log 文本文件，支持远程转发；
       journald 是 systemd 自带，二进制日志带结构化元数据，按服务/时间/级别过滤，
       自动限量和清理；生产环境常两者并存，journald 查明细、rsyslog 落文本和转发。

2. 日志的「级别」和「设施」分别指什么？
   答：级别（severity/priority）是严重程度，8 级从 debug 到 emerg；
       设施（facility）是来源分类，auth/kern/mail/daemon/user/cron/local0-7 等；
       规则用「设施.级别」选择器匹配。

3. 日志无限增长怎么办？
   答：文本日志配 logrotate 轮转（切割/压缩/删除旧档）；
       journald 设 SystemMaxUse 上限，超限自动清理最旧。

4. 排查一次登录失败/暴力破解看什么日志？
   答：/var/log/auth.log（或 journalctl -u ssh），grep 'Failed password'
       统计失败来源 IP；lastb 看失败登录记录。

5. journalctl 相比 tail /var/log/syslog 强在哪？
   答：结构化元数据（PID/UID/boot ID/程序名），可按 unit、级别、时间区间、
       字段过滤，-o json 输出机器可读格式，还能跨重启查（-b -1）。

6. 内核日志是怎么产生的？
   答：内核 printk() 写入内存 ring buffer，通过 /dev/kmsg 暴露；
       dmesg 读 ring buffer，rsyslog 的 imklog 和 journald 都从 /dev/kmsg 收。

7. journald 和 rsyslog 怎么协作？
   答：journald.conf 的 ForwardToSyslog=yes 把日志转发给 rsyslog 落文本；
       rsyslog 的 imjournal 模块反向读 journald 日志（RHEL 默认配置）；
       两通道独立，内容会略有差异。

8. 日志文件权限为什么是 640 root:adm？
   答：日志含敏感信息（登录 IP、命令、路径），640 保证 root 和 adm 组可读、
       其他用户不可读；rsyslog 用 syslog 用户降权写文件。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 排查问题先看日志（journalctl -u 服务名），别瞎猜
2. 实时跟踪用 -f，复现问题时边操作边看日志
3. 日志按级别过滤（-p err）快速定位错误，再逐级放宽
4. 登录/安全问题查 /var/log/auth.log，结合 last/lastb
5. journalctl 和 rsyslog 并存，服务日志用 journalctl、系统日志看 /var/log
6. 生产环境 journald 设 SystemMaxUse，防止日志撑爆磁盘
7. 重要日志集中转发到日志服务器，防单机被入侵后日志被抹掉
8. 应用日志统一走 syslog/journald，别让每个应用自己管理文件（除非有特殊格式需求）

### 踩坑记录

```text
坑 1：journalctl 和 /var/log 里的日志对不上
结论：journalctl 有日志，但 /var/log/syslog 里没有。
原因：rsyslog 和 journald 是两套，rsyslog 可能没转发 journald 的日志。
解法：确认 journald.conf 的 ForwardToSyslog=yes，rsyslog 配置（imjournal 模块）转发。

坑 2：journalctl -b 看错启动的日志
结论：排查启动问题，journalctl -b 看的是本次，问题在上次启动。
原因：-b 默认当前启动，上次启动要 -b -1。
解法：排查启动失败用 journalctl -b -1，先 --list-boots 确认启动序号。

坑 3：日志把磁盘占满
结论：/var/log 或 journald 日志无限增长，磁盘满了。
原因：没配日志轮转/上限，日志无限累积。
解法：配 logrotate 轮转，journald 设 SystemMaxUse 上限，必要时 vacuum 立即清。

坑 4：journalctl 按服务查不到日志
结论：journalctl -u 服务名 没输出，但服务在跑。
原因：服务自己写日志文件（不经过 systemd），或手动 nohup 启动不归 systemd 管。
解法：看服务自己写的日志文件（/var/log/xxx.log），或用 -t 程序名、systemd-cat 包装。

坑 5：日志级别搞反，err 和 warning 分不清
结论：以为 warning 比 err 严重，过滤错了。
原因：级别顺序记反（warning 比 err 低）。
解法：记 debug<info<notice<warning<err<crit<alert<emerg，数字越小越严重。

坑 6：journald 日志重启后丢失
结论：重启后 journalctl 只剩本次启动的日志。
原因：/var/log/journal 目录不存在，journald 跑在内存模式（/run/log/journal）。
解法：mkdir -p /var/log/journal 并重启 journald，或 journald.conf 设 Storage=persistent。

坑 7：日志时间差 8 小时
结论：日志显示时间和实际对不上，差 8 小时。
原因：时区没对齐，存储是 UTC 显示按本地时区；或容器内时区没挂载。
解法：timedatectl 确认时区，容器挂载 /etc/localtime 或设置 TZ 环境变量。

坑 8：普通用户看不了日志报 Permission denied
结论：非 root 用户 tail /var/log/auth.log 没权限。
原因：auth.log 权限 640，属主 syslog:adm，普通用户不在 adm 组。
解法：usermod -aG adm 用户名 后重新登录；或统一用 journalctl（加 systemd-journal 组）。

坑 9：服务起不来但 journalctl -u 服务名 没日志
结论：systemctl start 失败，日志里却什么都没有。
原因：服务单元在 ExecStartPre 阶段就挂了，或 unit 根本不存在/没加载。
解法：systemctl status 看失败阶段，查 systemctl --failed，journalctl -b -1 查启动期。
```

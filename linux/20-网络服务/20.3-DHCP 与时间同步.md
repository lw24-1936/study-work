## 概述

DHCP（动态主机配置协议）自动给设备分配 IP 地址（IP/网关/DNS），省去手动配置。时间同步（NTP/chrony）让多台机器时钟一致，是「分布式系统/日志/证书」的基础。DHCP 服务用 dnsmasq（轻量，DHCP+DNS）或 isc-dhcp（专用）；时间同步用 systemd-timesyncd（默认，简单）、chrony（现代推荐，精度高）、ntpd（老牌）。时区管理用 timedatectl。

```text
# 实测（本机时间同步状态）
$ timedatectl
Local time: 二 2026-08-18 23:50:08 CST
Time zone: Asia/Shanghai (CST, +0800)
System clock synchronized: yes     # 时间已同步
NTP service: active                # NTP 服务运行中（systemd-timesyncd）
# 本机用 systemd-timesyncd（chrony/ntpd 未装）
```

## 核心概念

1. **DHCP**：客户端广播请求 → 服务器分配 IP/网关/DNS，租约（lease）有期限，到期续租。
2. **NTP**：网络时间协议，客户端向时间服务器同步时钟，精度可达毫秒级。
3. **chrony vs ntpd vs timesyncd**：chrony（现代推荐，精度高、网络抖动适应好）、ntpd（老牌，全功能）、systemd-timesyncd（轻量，桌面/简单场景默认）。
4. **时区**：机器的时区设置（Asia/Shanghai 等），用 timedatectl 管理，和「时间同步」是两回事（同步的是 UTC 精确时间，时区是显示偏移）。

```text
核心概念：
DHCP（自动分配 IP）+ NTP/chrony（时间同步）+ 时区（timedatectl 管理）
chrony 精度高（服务器推荐），timesyncd 轻量（默认），ntpd 老牌
```

## 工作原理

**DHCP 四步握手（DORA）**：
1. Discover：客户端广播「谁有 IP 给我」
2. Offer：服务器回应「我可以给你 192.168.1.100」
3. Request：客户端请求「我就要这个」
4. Ack：服务器确认「给你了，租约 24 小时」

**NTP 同步原理**：
客户端向时间服务器发请求，服务器返回「我的时间」，客户端计算网络延迟（RTT）补偿，校准本地时钟。分层（stratum）：stratum 0（原子钟）→ 1（直接连原子钟）→ 2、3…（逐级同步）。chrony 会持续微调时钟（slew，平滑调整），避免时钟跳变。

```text
DHCP DORA：Discover → Offer → Request → Ack（分配 + 租约）
NTP：请求服务器时间 → 计算 RTT 补偿 → 平滑校准本地时钟（分层 stratum）
```

## 常用命令与配置

```shell
# DHCP 服务（dnsmasq）
apt install dnsmasq
systemctl status dnsmasq

# 时间同步（chrony）
apt install chrony
systemctl status chronyd
chronyc tracking              # 同步状态（服务器/偏差/精度）
chronyc sources               # 时间源列表
chronyc sources -v            # 详细（含每源状态）

# 时区管理
timedatectl                   # 查看时间和时区
timedatectl set-timezone Asia/Shanghai   # 设置时区
timedatectl list-timezones | grep -i shanghai
timedatectl set-ntp true      # 开启 NTP 同步
```

## 配置文件解析

dnsmasq DHCP 配置（/etc/dnsmasq.conf）：

```ini
# DHCP 配置
dhcp-range=192.168.1.100,192.168.1.200,12h   # 分配范围 + 租约 12 小时
dhcp-option=3,192.168.1.1                     # 网关（option 3）
dhcp-option=6,8.8.8.8,114.114.114.114         # DNS（option 6）
dhcp-host=AA:BB:CC:DD:EE:FF,192.168.1.50      # 静态绑定（固定 IP）
```

chrony 配置（/etc/chrony/chrony.conf）：

```ini
# 时间源（国内 NTP 服务器）
server ntp.aliyun.com iburst
server ntp.tencent.com iburst
pool pool.ntp.org iburst

# 允许内网机器同步（本机作时间服务器）
allow 192.168.1.0/24

# 本地时钟兜底（无网络时仍可作时间源）
local stratum 10
```

```text
dnsmasq DHCP：
dhcp-range 分配范围+租约，dhcp-option 3=网关 6=DNS，dhcp-host 静态绑定
chrony：
server 时间源（iburst 快速同步），allow 允许内网同步
```

## 应用场景实战

### 场景一：内网 DHCP 服务器（dnsmasq）

```shell
# 1. 配置 dhcp-range + 网关 + DNS
# 2. 重启 dnsmasq
systemctl restart dnsmasq
# 3. 内网机器自动获取 IP（不用手动配）
# 客户端验证：ip addr 看是否拿到 dhcp-range 里的 IP
```

### 场景二：内网时间同步（chrony 作时间服务器）

```shell
# 1. 服务器配时间源 + allow 内网
# 2. 客户端指向这台时间服务器
# /etc/chrony/chrony.conf: server 192.168.1.10 iburst
# 3. 验证同步
chronyc tracking
# 4. 所有机器时间一致（日志/证书/分布式系统都依赖）
```

## 性能与调优

```text
1. DHCP 租约 —— 租约太长（IP 浪费/回收慢）、太短（续租频繁）；12~24 小时平衡
2. NTP 时间源 —— 配多个时间源 + iburst（启动快速同步），选延迟低的
3. chrony 精度 —— 局域网时间服务器用本地时钟兜底（local stratum），离线也能同步
4. 平滑调整 —— chrony 用 slew（微调）不用 step（跳变），避免影响依赖时间的应用
```

## 安全与权限

```text
1. DHCP 防 rogue —— 内网防「非法 DHCP 服务器」乱发 IP（只能靠交换机 DHCP snooping）
2. DHCP 静态绑定 —— 关键设备（服务器）用 dhcp-host 固定 IP，别让 IP 乱漂
3. NTP 认证 —— 重要场景 NTP 配认证（防时间被篡改），普通内网可简化
4. 时区统一 —— 服务器统一 UTC 或统一业务时区，日志时间才一致
5. 时间同步失败告警 —— 时间不同步会导致证书校验失败、分布式脑裂，要监控
```

## 故障排查

### 客户端拿不到 IP

```shell
# 1. 看客户端是否发出 DHCP 请求（抓包）
tcpdump -i eth0 port 67 or port 68
# 2. 看 dnsmasq 日志
journalctl -u dnsmasq -n 50
# 3. 确认 dhcp-range 范围没耗尽
grep dhcp-range /etc/dnsmasq.conf
```

### 时间不同步

```shell
# 1. 看同步状态
chronyc tracking
timedatectl
# 2. 看时间源是否可达
chronyc sources -v
# 3. 测 NTP 端口
nc -zvu <时间服务器> 123
```

## 常见问题

```text
Q1: 时间同步和时区是一回事吗？
A: 不是。时间同步校准 UTC 精确时间，时区是「本地显示偏移」。同步后 + 设对时区，本地时间才正确。

Q2: chrony、ntpd、timesyncd 怎么选？
A: 服务器推荐 chrony（精度高、适应网络抖动），桌面/简单用 timesyncd（默认够用），老系统用 ntpd。

Q3: DHCP 租约到期会怎样？
A: 客户端自动续租（租约一半时请求续期），续不上则租约到期释放 IP、重新申请。

Q4: 为什么分布式系统要时间同步？
A: 日志时间戳、证书有效期校验、分布式事务/锁、数据一致性判断都依赖一致的时间。
```

## 面试题

```text
1. DHCP 的四步握手？
   答：Discover（发现）→ Offer（提供）→ Request（请求）→ Ack（确认），即 DORA。

2. NTP 和 chrony 的区别？
   答：都是时间同步，chrony 更现代（精度高、网络抖动适应好、启动快），ntpd 老牌全功能。

3. 为什么时间不同步会导致证书校验失败？
   答：证书有有效期，本地时间错（如快了几年）会导致「证书未生效/已过期」误判。

4. DHCP 分配 IP 的租约机制？
   答：分配带租约期，客户端租约一半时续租，到期未续则释放，避免 IP 被永久占用。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 服务器时间同步用 chrony（精度高），桌面默认 timesyncd 够用
2. 内网建时间服务器，所有机器指向它（时间统一）
3. 服务器时区统一（UTC 或业务时区），日志时间才一致
4. 关键设备 DHCP 静态绑定（dhcp-host），IP 不漂移
5. 时间同步失败要告警（影响证书/分布式）

### 踩坑记录

```text
坑 1：时间同步和时区搞混
结论：设了 NTP 同步，但时间还是不对（差 8 小时）。
原因：同步的是 UTC，时区没设对（显示偏移错）。
解法：timedatectl set-timezone Asia/Shanghai 设对时区。

坑 2：时间源用境外服务器，同步慢/失败
结论：NTP 用 pool.ntp.org，国内同步慢或失败。
原因：境外 NTP 延迟高、可能被墙。
解法：换国内时间源（ntp.aliyun.com / ntp.tencent.com）。

坑 3：DHCP 范围耗尽，新设备拿不到 IP
结论：新设备连不上网，dhcp-range 用完了。
原因：分配范围太小，租约太长回收慢。
解法：扩大 dhcp-range，或缩短租约。

坑 4：内网有 rogue DHCP 服务器
结论：设备拿到错误 IP（不是自己 DHCP 发的）。
原因：内网有人接了路由器/非法 DHCP。
解法：交换机开 DHCP snooping，只信任合法 DHCP 端口。

坑 5：时间不同步导致证书/日志异常
结论：服务报证书错误、日志时间错乱。
原因：本地时钟漂移，时间不同步。
解法：配 chrony 同步 + 监控时间偏差告警。
```

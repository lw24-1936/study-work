## 概述

本章覆盖网络服务两大基础件：**DHCP**（动态主机配置协议，自动分配 IP/网关/DNS）与**时间同步**（NTP 体系，让全网机器时钟一致）。DHCP 解决「手动配 IP 易错、易冲突、运维成本高」的问题；时间同步解决「日志时间线错乱、证书校验失败、分布式系统不一致」的问题。两者都是「一次配置、全网受益」的典型基础服务。

DHCP 服务端实现：**ISC DHCP 服务器**（专用、功能全，Ubuntu 包 `isc-dhcp-server` / Red Hat 包 `dhcp-server`）、**dnsmasq**（轻量，DHCP+DNS+TFTP 一体化，适合小网络）。时间同步实现：**systemd-timesyncd**（Ubuntu 默认，仅客户端、极简）、**chrony**（现代推荐，精度高、抗网络抖动，RHEL 8+ 默认）、**ntpd**（老牌全功能）。时区管理统一用 **timedatectl**。

## 核心概念

1. **DHCP 作用域（scope）**：一个子网一段「可分配 IP 的管辖范围」，DHCP 服务器按网段（subnet）划分作用域，每个作用域内配地址池。
2. **地址池（pool/range）**：作用域内真正拿出来分配的 IP 区间，如 `range 192.168.1.100 192.168.1.200;`。池大小决定同时在线设备数上限。
3. **租约（lease）**：IP 不是永久给设备，而是「借」一段时间（如 24 小时），到期前自动续租。租约记录在租约文件里，服务器重启也不丢。
4. **保留地址（reservation）**：按 MAC 地址把某个 IP「锁给」特定设备（如打印机、服务器），保证 IP 永远不变，DHCP 与静态配置双轨兼容。
5. **option 选项**：DHCP 不只给 IP，还下发配置：option 3（网关）、option 6（DNS）、option 15（域名）、option 51（租约时长）、option 53（报文类型）、option 54（服务器标识）、option 66/67（PXE 启动服务器/引导文件）。
6. **DHCP 中继（relay）**：客户端广播到不了别的网段，中继代理（dhcrelay）把广播转成单播转发给远端 DHCP 服务器，实现「一个服务器管多个网段」。
7. **NTP 分层（stratum）**：stratum 0（原子钟/GPS）→ stratum 1（直接连原子钟的国家授时中心）→ stratum 2、3…（逐级同步）。数值越小越权威，stratum 16 表示「未同步」。
8. **offset / delay / jitter**：offset 是本地时钟与服务器时钟的偏差（要消除的量）；delay 是网络往返延迟（RTT）；jitter 是 offset 的波动程度（网络抖动），三者是衡量同步质量的核心指标。
9. **slew vs step**：slew 是「微调」——把时钟频率调快/调慢一点，平滑追平偏差（不跳变）；step 是「跳变」——直接改时间（大偏移时才用）。平滑调整不影响依赖时间连续性的应用（如日志、数据库 WAL）。
10. **时区与时间同步是两回事**：时间同步校准的是 UTC 精确时间；时区只是「显示偏移量」（+0800）。同步了但时区配错，本地时间照样差 8 小时。

```text
一句话记忆：
DHCP  = 作用域(scope) + 地址池(range) + 租约(lease) + 保留(reservation) + 选项(option)
NTP   = stratum 层级 + offset/delay/jitter 三个指标 + slew 平滑调整
服务  = timesyncd(轻量默认) / chrony(精度高) / ntpd(老牌)
```

## 工作原理

### DHCP 的 DORA 四步握手

客户端无 IP 时通过 UDP 广播完成四次报文交互（客户端端口 68，服务器端口 67）：

```text
客户端                                          DHCP 服务器
  │ ① DHCPDISCOVER                                │
  │  src=0.0.0.0:68  dst=255.255.255.255:67       │  广播「谁有 IP 给我」
  │──────────────────────────────────────────────▶│  服务器收到后从池中预选一个 IP
  │                                               │
  │ ② DHCPOFFER                                   │
  │  src=服务器:67 → 广播/单播:68                  │  回应「我可以给你 192.168.1.100，
  │◀──────────────────────────────────────────────│  网关/DNS/租约时长如下…」携带 option 54 服务器标识
  │                                               │
  │ ③ DHCPREQUEST                                │
  │  src=0.0.0.0:68  dst=255.255.255.255:67       │  广播「我就要 192.168.1.100 这个」
  │──────────────────────────────────────────────▶│  （广播是为了让其他 Offer 的服务器回收预留）
  │                                               │  服务器把该 IP 标记为已租出，写租约文件
  │ ④ DHCPACK                                    │
  │  src=服务器:67 → 广播/单播:68                  │  「成交，租约 86400 秒」
  │◀──────────────────────────────────────────────│
  │  客户端配置 IP/掩码/网关/DNS，完成上线
```

关键细节：**OFFER 是「预留」不是「分配」**，只有收到 REQUEST 才真正扣减地址池；**REQUEST 必须广播**（而不是单播给选定服务器），否则其他发过 OFFER 的服务器会一直占着预留地址；服务器如果拒绝（如 IP 已被占用）会回 **DHCPNAK**，客户端收到 NAK 后重新走 Discover。

### 租约生命周期（T1/T2 续租）

```text
租约期（如 24h）
├── 0% ───────────────── 获得租约（ACK）
├── 50% (T1=12h) ─────── 单播 REQUEST 给原服务器续租（续约成功则重置计时）
├── 87.5% (T2=21h) ───── T1 续租失败，改为广播 REQUEST（任何服务器都可回应）
└── 100% ─────────────── 仍失败 → 租约到期 → 停止使用 IP → 重新 DISCOVER
```

客户端还有两种主动报文：**DHCPRELEASE**（关机/主动释放，服务器立即回收）、**DHCPDECLINE**（客户端 ARP 探测发现地址冲突，拒绝使用并告知服务器）。**DHCPINFORM** 用于已有静态 IP 的机器只向服务器要「其他配置」（DNS 等）。

### NTP 同步原理

客户端与服务器交换四个时间戳计算偏差：

```text
客户端                    服务器
  │ t1 发送请求 ──────────▶│ t2 收到请求
  │◀─────── 响应 ─────────│ t3 发出响应
  │ t4 收到响应
偏移 offset = ((t2 − t1) + (t3 − t4)) / 2      # 本地时钟要加减的量
延迟 delay  = (t4 − t1) − (t3 − t2)            # 网络往返时间
```

单次测量有网络抖动，NTP 客户端会**连续采样 + 过滤 + 选择 + 合并**：过滤掉异常的样本（选择算法丢弃 outlier），在多个时间源中选「最可信的组合」（Marzullo 算法取交集），最后对本地时钟做**频率校正**（不只校一次时间，而是校准「时钟走得快还是慢」——即频率漂移，写入 drift 文件，下次启动直接套用）。

**chrony 与 ntpd 的核心差异**：ntpd 按固定周期轮询（默认 64s，指数退避最大 1024s）；chrony 采用**自适应轮询**，网络好时加密采样频率、网络差时自动降频，同时支持「短时间高精度测量」模式，因此在**虚拟化环境、网络抖动大、笔记本频繁休眠唤醒**等场景精度明显更好，且启动后几十秒就能达到毫秒级。

### 三种时间同步软件对比

| 软件 | 定位 | 服务名 | 可否做服务器 | 精度 | 适用场景 |
| --- | --- | --- | --- | --- | --- |
| systemd-timesyncd | SNTP 客户端（极简） | systemd-timesyncd | 否 | 秒~百毫秒级 | Ubuntu 桌面/单机默认 |
| chrony | 现代 NTP 实现 | chronyd | 是 | 亚毫秒~毫秒级 | RHEL 8+ 默认、服务器、虚拟化 |
| ntpd | 经典 NTP 实现 | ntpd | 是 | 毫秒级 | 老系统、需要传统 ntpq 生态 |

```text
DHCP 排错抓包口诀：tcpdump -i eth0 port 67 or port 68
NTP 同步验证口诀：chronyc tracking（同步状态）+ chronyc sources -v（时间源明细）
```

## 常用命令与配置

```shell
# ---------- DHCP 服务器（ISC DHCP，Ubuntu） ----------
apt install isc-dhcp-server          # Red Hat 系：yum/dnf install dhcp-server
dhcpd -t -cf /etc/dhcp/dhcpd.conf    # 语法检查（修改后必做，出错会拒绝启动）
dhcpd -d -f -cf /etc/dhcp/dhcpd.conf # 前台调试模式（带日志直接打屏，排错利器）
systemctl restart isc-dhcp-server    # Red Hat 系服务名：dhcpd
systemctl status isc-dhcp-server
journalctl -u isc-dhcp-server -n 50  # DHCP 服务器日志

# ---------- DHCP 中继 ----------
apt install isc-dhcp-relay           # Red Hat 系：dhcp-relay
dhcrelay -i eth0 -i eth1 192.168.1.10   # 把 eth0/eth1 的 DHCP 广播转发给 192.168.1.10

# ---------- dnsmasq（DHCP+DNS 一体化） ----------
apt install dnsmasq                  # dnsmasq-base 已装时只需装主包
systemctl restart dnsmasq
journalctl -u dnsmasq -n 30

# ---------- 客户端侧 ----------
ip addr                               # 看是否拿到 DHCP 分配的 IP
dhclient -v eth0                      # 手动请求一次（老客户端工具）
# Ubuntu 24.04 默认走 systemd-networkd / NetworkManager，dhclient 仅按需安装

# ---------- 时间同步（chrony，服务端/客户端通用） ----------
apt install chrony                    # Red Hat 系：dnf install chrony（默认已装）
systemctl restart chronyd             # 服务名两边都是 chronyd
chronyc tracking                      # 同步状态（参考 ID/stratum/offset）
chronyc sources -v                    # 时间源明细（* 当前生效源）
chronyc makestep                      # 立即强制步进一次（大偏移时手动校时）
chronyc clients                       # 谁在向本机同步（本机作服务器时）

# ---------- 时间同步（systemd-timesyncd，Ubuntu 默认） ----------
timedatectl set-ntp true              # 开启 NTP 同步
timedatectl set-ntp false             # 关闭（改手动时间前先关，否则会被拉回去）
systemctl status systemd-timesyncd
timedatectl show-timesync             # 同步详情（服务器/轮询间隔/stratum）

# ---------- 老牌 ntpd ----------
apt install ntp                       # Red Hat 系：dnf install ntp（已弃用）
ntpq -p                               # 查看同步源（* 当前生效源）
ntpdate -u ntp.aliyun.com             # 一次性校时（老工具，仅应急）

# ---------- 时区管理（timedatectl 全家桶） ----------
timedatectl                           # 查看时间/时区/同步状态
timedatectl list-timezones | grep -i shanghai
timedatectl set-timezone Asia/Shanghai
timedatectl set-local-rtc true        # 硬件时钟按本地时间保存（默认 false=UTC，别乱改）
hwclock --systohc                     # 把系统时钟写入硬件时钟（RTC）
```

## 配置文件解析

### ISC DHCP：/etc/dhcp/dhcpd.conf（逐行解析）

```text
# 全局默认租约（客户端未特别要求时）
default-lease-time 86400;          # 默认租约 24 小时（秒）
max-lease-time 172800;             # 客户端能申请到的最大租约 48 小时

# 全局 option（每个作用域可覆盖）
option domain-name "example.com";                  # option 15：搜索域
option domain-name-servers 8.8.8.8, 114.114.114.114;  # option 6：DNS 列表
option ntp-servers 192.168.1.10;                   # option 42：NTP 服务器（可选下发）

# 作用域：192.168.1.0/24 网段
subnet 192.168.1.0 netmask 255.255.255.0 {
    range 192.168.1.100 192.168.1.200;   # 地址池：100~200 共 101 个地址
    option routers 192.168.1.1;          # option 3：网关（作用域级覆盖全局）
    option domain-name-servers 192.168.1.1, 8.8.8.8;  # 作用域级 DNS
    default-lease-time 43200;            # 本作用域默认租约 12 小时
}

# 保留地址：打印机固定 192.168.1.50（按 MAC 锁定）
host printer {
    hardware ethernet AA:BB:CC:DD:EE:FF;  # 客户端网卡 MAC（冒号分隔，小写）
    fixed-address 192.168.1.50;          # 固定 IP（必须在池外，避免冲突）
}

# 固定 IP 另一种写法：与 range 同网段但不在池内即可；
# 若 fixed-address 落在 range 内，DHCP 会把该地址从池中剔除（dhcpd 自动处理）
```

语法注意：每个语句**以分号结尾**，花括号后**无分号**；`subnet` 的 IP 必须与掩码严格匹配（`subnet 192.168.1.0 netmask 255.255.255.0`，写成 192.168.1.1 会报错）。修改后必须 `dhcpd -t` 通过再重启。

### 租约文件：/var/lib/dhcp/dhcpd.leases

```text
lease 192.168.1.100 {
    starts 6 2026/08/19 05:50:26;          # 租约开始时间
    ends 7 2026/08/20 05:50:26;            # 租约到期时间
    cltt 6 2026/08/19 05:50:26;            # 最近一次续租时间（client last transaction time）
    binding state active;                  # 状态：active/free/backup
    next binding state free;
    hardware ethernet 00:11:22:33:44:55;   # 持有者 MAC
    client-hostname "alice-laptop";        # 客户端主机名
}
# 排查「谁占了这个 IP」直接查此文件；服务器异常断电时 lease 文件可能损坏，
# 会用 .~ 备份（dhcpd.leases~）恢复，也可删除后重启（会失去租约记录，慎用）。
```

### dnsmasq：/etc/dnsmasq.conf（DHCP 相关段）

```ini
# 只启用 DHCP（DNS 部分默认也开着，可两者都用）
dhcp-range=192.168.1.100,192.168.1.200,12h   # 地址池 + 租约 12 小时
dhcp-option=option:router,192.168.1.1         # 网关（option 3）
dhcp-option=option:dns-server,8.8.8.8,114.114.114.114   # DNS（option 6）
dhcp-option=option:ntp-server,192.168.1.10    # 下发 NTP 服务器（option 42）
dhcp-host=AA:BB:CC:DD:EE:FF,192.168.1.50      # MAC 静态绑定
dhcp-host=AA:BB:CC:DD:EE:FF,printer           # 也可绑定主机名（配合 DNS）
dhcp-boot=pxelinux.0,192.168.1.10             # PXE 网络启动（option 66/67）
```

### chrony：/etc/chrony/chrony.conf（逐行解析）

```ini
# ---- 时间源：server 精确指定 / pool 表示一组服务器（自动负载均衡） ----
server ntp.aliyun.com iburst          # iburst：启动时快速连续采样 4 次，几秒内完成首次同步
server ntp.tencent.com iburst
pool pool.ntp.org iburst              # 池：从池中随机选 4 台（新版语法，推荐）

# ---- 访问控制：本机同时当内网时间服务器 ----
allow 192.168.1.0/24                  # 允许内网网段同步（白名单，可多条）
# deny all                            # 显式拒绝其余来源（默认即拒绝，可不写）
bindcmdaddress 127.0.0.1              # chronyc 命令通道只绑本机（安全）
bindcmdaddress ::1

# ---- 大偏移处理：前 3 次更新允许最多 1 秒的 step，之后只 slew ----
makestep 1 3                          # RHEL 系默认值；阈值秒数, 前 N 次更新内允许

# ---- 本地时钟兜底：无外网时仍可给内网提供时间（stratum 10） ----
local stratum 10

# ---- 其它常用 ----
driftfile /var/lib/chrony/drift       # 频率漂移记录（重启沿用，加快收敛）
rtcsync                               # 定期把系统时间写回硬件时钟（RTC）
logdir /var/log/chrony                # 日志目录
maxslewrate 1000                      # slew 最大速率（ppm），防极端微调
```

### systemd-timesyncd：/etc/systemd/timesyncd.conf

```ini
[Time]
```

## 性能与调优

```text
1. 租约时长权衡
   长租约（7 天）：续租报文少、DHCP 服务器压力小，但 IP 回收慢、地址池易耗尽；
   短租约（30 分钟）：IP 周转快（适合无线/访客网络），但续租报文多。
   常规办公网 12~24h 是平衡点；访客网/高流动场景 30min~2h。
2. 地址池规划
   服务器/打印机用 host 保留（池外固定 IP），池只给动态设备；
   池大小 = 峰值并发设备数 × 1.2 冗余；别把保留 IP 放进 range。
3. DHCP 服务器性能
   dhcpd 单进程即可支撑数千客户端（协议简单）；压力点通常在日志 IO 与
   租约文件写入；dnsmasq 适合 <500 终端，更大规模用 ISC DHCP 或多台 failover。
4. chrony 采样调优
   server 加 iburst：启动后 3~4 次快速采样，冷启动几十秒即收敛（无 iburst 要等 1~2 轮询周期）；
   网络抖动大时可配 maxpoll 6（64s）/ minpoll 4（16s）提高采样密度；
   多个 server 同时配（≥3 个），chrony 自动选择/合并，抵抗单点故障。
5. makestep 策略
   首次开机偏差巨大（RTC 漂移）时靠 step 快速归位：makestep 1 3（前 3 次更新允许
   1 秒以上跳变），之后只 slew，兼顾「快速收敛」与「不影响应用时间连续性」。
6. 频率漂移复用
   driftfile 记录晶振漂移率，重启后直接套用，收敛时间从分钟级降到秒级；
   虚拟化环境漂移率变化大，driftfile 尤为重要。
7. 网络抖动与精度
   精度上限由网络 RTT 抖动决定（jitter 几十 ms 时别指望亚毫秒精度）；
   局域网内自建时间服务器（stratum 2）+ 客户端直连，抖动最小、精度最高。
```

## 安全与权限

```text
1. DHCP 防 rogue 服务器
   非法 DHCP（员工私接路由器/恶意设备）会广播 Offer 劫持客户端，导致拿错 IP/网关。
   唯一根治手段是交换机开启 DHCP snooping：只信任「上联口」能发 Offer，
   其它端口收到的 DHCPOFFER 直接丢弃（与 DAI 联动还能防 ARP 欺骗）。
2. DHCP 静态绑定关键设备
   服务器/打印机/网络设备用 host 保留（MAC→IP 绑定），IP 不漂移；
   防火墙白名单、监控告警、备份策略都依赖固定 IP，漂移一次排查半天。
3. 地址池与中继的安全
   不要配置「池外子网广播」意外放行；dhcrelay 只对指定服务器单播转发；
   DHCP 报文无认证（无内置加密），涉密网络要配合接入认证（802.1X）管控入口。
4. NTP 访问控制
   chrony：allow 白名单 + 默认拒绝 + bindcmdaddress 127.0.0.1（chronyc 管理通道不外露）；
   别把时间服务器暴露公网（UDP 123 曾是放大攻击反射源，现代版本已缓解，但没必要开放）。
5. NTP 认证（高安全场景）
   chrony 支持对称密钥认证（key 文件）与 NTS（RFC 8915，chrony 4.x/RHEL 9）；
   防「中间人篡改时间」——篡改时间可导致证书误判、票据失效、审计失真，比停摆更隐蔽。
6. 防火墙放行清单
   时间服务器：放行 123/udp（入向）；客户端：出向 123/udp；
   DHCP 服务器：放行 67/udp；客户端：68/udp 出向；
   Red Hat 系：firewall-cmd --add-service=ntp / --add-service=dhcp（firewalld 预定义服务）。
7. 时区与日志审计
   全公司服务器统一 UTC（或统一业务时区），日志/审计时间戳才可比对；
   时间同步状态纳入监控：timedatectl 的 System clock synchronized: no 要告警。
```

## 故障排查

### 案例一：客户端拿不到 IP

```shell
# 1. 客户端先自检：网卡是否 up、是否发了请求（抓包）
ip link set eth0 up && ip addr flush dev eth0
tcpdump -i eth0 port 67 or port 68 -n -vv
#   看到 DISCOVER 发出但没有 OFFER 回来 → 服务器没收到/没响应
#   什么都没抓到 → 客户端网卡/链路问题（先 ping 网关确认二层通）

# 2. 服务器侧查日志
journalctl -u isc-dhcp-server -n 50        # 或 dnsmasq：journalctl -u dnsmasq
#   常见日志：No free leases（池耗尽）、no subnet declaration（客户端网段没配作用域）

# 3. 常见根因清单
grep -E 'range|subnet' /etc/dhcp/dhcpd.conf   # 地址池是否耗尽/作用域是否覆盖该网段
ss -ulnp | grep -E ':(67|68)\b'               # 服务器是否监听 67/udp（防火墙挡了？）
dhcpd -t -cf /etc/dhcp/dhcpd.conf             # 配置是否语法错误（错误会拒绝启动）
# 4. 跨网段场景：确认 dhcrelay 在跑、且 relay 到服务器的路由/防火墙通
```

### 案例二：时间不同步

```shell
# 1. 看同步状态
timedatectl                     # System clock synchronized: no 就是没同步上
chronyc tracking                # 报 "Unable to connect to chronyd" 说明 chronyd 没起
# 2. 看时间源是否可达
chronyc sources -v              # 每行首字符：* 生效源 / + 候选 / ? 不可达 / x 时钟不同步
#   全是 ?  → DNS 解析或网络不通
#   有 * 但 offset 很大 → 上游本身漂移或本机频率漂移未收敛（看 driftfile）
# 3. 测 UDP 123 端口连通性
nc -zvu <时间服务器IP> 123       # 没有输出 = UDP 通（UDP 无 ACK，nc -u 显示 open 即通）
# 4. 检查防火墙与 DNS
systemctl status chronyd         # 服务是否 active
# Red Hat 系：firewall-cmd --list-services 确认 ntp 服务已放行（防火墙默认拒绝会静默丢 UDP）
# 5. timesyncd 场景：确认没被 chrony/ntpd 抢服务（三者互斥，装 chrony 会停用 timesyncd）
systemctl status systemd-timesyncd
```

### 案例三：IP 地址冲突（两台机器同 IP）

```shell
# 现象：设备间歇性断网，arp 表里同一 IP 对应多个 MAC
# 1. 抓 ARP 冲突证据
tcpdump -i eth0 arp -n
#   同一 IP 出现两个不同 MAC 的回答 → 确认冲突
# 2. 找出占用者
arp -a | grep <冲突IP>
ip neigh show | grep <冲突IP>
# 3. 查 DHCP 租约归属
grep -B2 -A6 '<冲突IP>' /var/lib/dhcp/dhcpd.leases
#   若冲突 IP 是静态配置的（不在池内）→ 手工改静态机的 IP；
#   若在池内 → 可能是客户端 DHCPDECLINE 未生效/有人手动配了池内地址
# 4. 预防：把常用设备全部 host 保留 + 交换机 DHCP snooping 收口
```

### 案例四：装了 chrony 后 timedatectl 显示 NTP inactive

```shell
# 现象：apt install chrony 之后，timedatectl 显示 NTP service: inactive
# 原因：Ubuntu 的 chrony 包声明 Conflicts: systemd-timesyncd，
#       安装时自动停用并屏蔽 timesyncd（避免两个 NTP 客户端打架）
# 验证：
systemctl status chronyd          # chronyd 在跑，时间同步实际由 chrony 接管
timedatectl                       # NTP service: inactive 是「timesyncd 没跑」，不代表没同步
# 解法：以 chronyd 为准（chronyc tracking 正常即可）；想换回 timesyncd：
apt remove chrony && systemctl enable --now systemd-timesyncd
```

## 常见问题

```text
Q1: 时间同步和时区是一回事吗？
A: 不是。时间同步校准 UTC 精确时间（与服务器比对），时区只是「本地显示偏移」。
   只同步不设时区，显示差 8 小时；只设时区不同步，会越漂越远。两者都要做。

Q2: chrony、ntpd、systemd-timesyncd 怎么选？
A: 服务器/虚拟化/高精度场景用 chrony（RHEL 8+ 默认，精度高、抗抖动、启动快）；
   桌面单机、要求极简用 systemd-timesyncd（Ubuntu 默认，够用）；
   老系统或依赖传统 ntpq 生态才用 ntpd。chrony 与 timesyncd 互斥，别同时装。

Q3: DHCP 租约到期会怎样？
A: 租约到 50%（T1）时单播续租，失败则在 87.5%（T2）广播续租；
   仍失败则到期释放 IP、重新走 DORA 申请。续租失败一般伴随网络故障，需排查链路。

Q4: 为什么分布式系统必须时间同步？
A: 日志/审计时间戳排序、TLS 证书有效期校验、Kerberos 票据、分布式事务超时判断、
   数据库 binlog 与主从复制、定时任务触发都依赖一致可信的时间；时间错乱会导致
   证书误判、脑裂、数据竞争等「看起来毫无关联」的诡异故障。

Q5: chronyc sources -v 输出里的 * 和 ? 是什么？
A: 每行首字符是源状态：* 当前选中的同步源、+ 可用的候选源、- 被合并算法排除、
   ? 最近采样不可达、x 时钟不同步、~ 时间戳抖动过大。正常应至少有一个 *。

Q6: DHCP 服务器能跨网段分配 IP 吗？
A: 不能直接跨（广播到不了别的网段），需要 DHCP 中继 dhcrelay：客户端广播 →
   relay 转发为单播给服务器 → 服务器按 relay 上报的 giaddr（网关地址）判断
   客户端所在网段，从对应作用域分配。

Q7: 手动改了系统时间，为什么一会儿又变回去了？
A: NTP 同步开着（timedatectl set-ntp true），客户端会周期性把时钟拉回服务器时间。
   手动校时前先 timedatectl set-ntp false，或用 chronyc makestep 让服务器校准。

Q8: dhcpd.leases 文件能删吗？
A: 能删（服务器会自动重建），但会丢失所有已分配租约的「记忆」：已在线客户端
   续租时可能拿不到原 IP（原地址被当空闲分给别人），造成短暂冲突。
   正常运维不删；异常损坏时用备份 dhcpd.leases~ 恢复。
```

## 面试题

```text
1. 请完整描述 DHCP 的 DORA 四步过程。
   答：Discover——客户端无 IP，广播 DHCPDISCOVER（源 0.0.0.0:68，目的 255.255.255.255:67）
       询问谁提供 IP；Offer——服务器广播/单播 DHCPOFFER，预选一个 IP 并携带网关/DNS/租约
       等选项（预留但未分配）；Request——客户端广播 DHCPREQUEST 确认要这个 IP（广播是为让
       其它 Offer 服务器回收预留）；Ack——服务器广播 DHCPACK 确认分配并写租约文件，客户端
       配置 IP 后完成上线。若服务器拒绝则回 DHCPNAK，客户端重新 Discover。

2. NTP 如何计算时钟偏移？什么是 stratum？
   答：客户端与服务器交换四个时间戳 t1/t2/t3/t4，offset = ((t2-t1)+(t3-t4))/2，
       delay = (t4-t1)-(t3-t2)，再经过滤/选择/合并算法剔除异常样本、综合多源结果，
       并校准时钟频率漂移。stratum 是时间源的层级：0 为原子钟/GPS，1 为直接连接
       授时中心，逐级递增，16 表示未同步；层级越小的源越权威。

3. chrony 相比 ntpd 的优势？
   答：① 自适应轮询，网络好时采样更密、精度更高，抖动大时自动降频；
      ② 启动后几十秒即达毫秒级（iburst 快速采样），ntpd 需要多次轮询周期；
      ③ 虚拟化/休眠唤醒/网络波动环境下表现更稳（现代实现，RHEL 8+ 默认采用）；
      ④ 支持 NTS 加密认证（chrony 4.x），更安全。

4. 什么情况下 NTP 会 step（跳变）而不是 slew（微调）？
   答：offset 超过配置阈值时（如 makestep 1 3：前 3 次更新允许最多 1 秒的跳变，
       之后只 slew）。大偏移用 slew 需要极长时间追平，且漂移校正本身不可靠；
       但 step 会破坏时间连续性（日志空洞、数据库时间戳异常），所以只在开机
       初期或偏移巨大时允许，正常运行期只用 slew。

5. 什么是 DHCP 中继？为什么需要它？
   答：DHCP 请求是广播，无法跨网段；中继（dhcrelay）监听客户端广播，加上
       giaddr（客户端所在网段地址）后单播转发给远端 DHCP 服务器，服务器据此
       选择对应作用域分配 IP。实现「一个 DHCP 服务器管理多个网段」。

6. DHCP 租约的 T1/T2 续租机制？
   答：租约 50% 时（T1）客户端单播 REQUEST 向原服务器续租；失败则在 87.5%（T2）
       改为广播 REQUEST，任何可达服务器都可回应；仍失败则租约到期释放 IP，
       重新开始 DORA。T1/T2 机制保证续租平滑、IP 不浪费。

7. 如何防止内网出现 rogue DHCP 服务器？
   答：交换机开启 DHCP snooping，指定信任端口（上联口）之外的端口丢弃
       所有 DHCPOFFER 报文；配合 DAI 防 ARP 欺骗、802.1X 接入认证管控入口；
       关键设备用 host 保留固定 IP，并监控 dhcpd 日志中的异常分配。
```

```text
坑 1：时间同步和时区搞混
结论：设了 NTP 同步，但本地时间还是不对（差 8 小时）。
原因：NTP 同步的是 UTC 精确时间，时区没设对（显示偏移错）。
解法：timedatectl set-timezone Asia/Shanghai 设对时区；检查 timedatectl 的
      Time zone 字段，而不是只看 synchronized。

坑 2：时间源用境外服务器，同步慢/失败
结论：配置 pool.ntp.org，内网机器 chronyc sources 全是 ?，同步失败。
原因：境外 NTP 池延迟高、跨海链路抖动大、部分环境出网受限。
解法：换国内时间源（ntp.aliyun.com / ntp.tencent.com，加 iburst），
      或内网自建时间服务器统一出网。

坑 3：DHCP 地址池耗尽，新设备拿不到 IP
结论：新设备一直获取不到地址，日志报 No free leases。
原因：range 太小 + 租约太长（IP 回收慢），或大量设备长期在线。
解法：扩大 range（注意池外保留区）、缩短租约、清理租约文件里的僵尸租约
      （grep binding state active 核对），必要时加一台 DHCP 服务器做 failover。

坑 4：内网有 rogue DHCP 服务器，设备拿错 IP
结论：部分设备拿到 192.168.168.x 的诡异地址，网关不通。
原因：有人私接路由器/无线路由默认开了 DHCP，抢答 Offer。
解法：交换机开 DHCP snooping 只信任上联口；找到并移除非法设备；
      事后把合法 DHCP 服务器 MAC 加入 snooping 信任白名单。

坑 5：时间不同步导致证书/日志异常
结论：服务偶发报证书错误、日志时间戳倒序、分布式任务错乱。
原因：本地时钟漂移大（RTC 没同步或 NTP 停摆），证书有效期判断错乱。
解法：配 chrony 同步 + 监控 timedatectl/chronyc tracking 的 offset 阈值告警；
      服务器换电池（CMOS 电池老化是 RTC 漂移元凶）。

坑 6：chrony 和 systemd-timesyncd 同时装，服务互相打架
结论：装完 chrony 后 timedatectl 显示 NTP service: inactive，以为没同步。
原因：两个 NTP 客户端互斥（chrony 包 Conflicts systemd-timesyncd，
      安装时自动停用 timesyncd），inactive 只是 timesyncd 没跑。
解法：以 chronyc tracking 为准判断同步状态；想换回 timesyncd 就先卸载 chrony。

坑 7：手动改时间后被 NTP 拉回去/改不动
结论：timedatectl set-time 设置失败或设完马上变回。
原因：NTP 同步开着（set-ntp true），客户端周期性覆盖本地时间。
解法：先 timedatectl set-ntp false 再改时间；或直接 chronyc makestep
      让服务器校准，不要手动 set-time。

坑 8：dhcpd.conf 少写分号，服务起不来
结论：重启 isc-dhcp-server 失败，journalctl 报 syntax error。
原因：dhcpd.conf 语句必须分号结尾，花括号后不能加分号，漏写/多写都会拒绝启动。
解法：改完先 dhcpd -t -cf /etc/dhcp/dhcpd.conf 语法检查，通过再重启；
      改之前备份原配置。

坑 9：跨网段 DHCP 不生效
结论：配置了 relay 但远端网段拿不到 IP，日志里没有该网段的租约。
原因：dhcrelay 没指定对网卡/没指定服务器地址，或服务器没配对应网段的 subnet。
解法：dhcrelay -i 客户端网卡 -i 服务器网卡 <服务器IP> 明确指定；
      服务器 dhcpd.conf 必须为每个网段配 subnet 作用域（含 range）。
```

## 概述

文件共享服务让「多台机器/用户」访问同一份文件，五种方式：Samba（Linux/Windows 跨平台，SMB 协议）、NFS（Linux 间共享，文件级）、FTP（传统文件传输，明文不安全）、SFTP（SSH 加密的文件传输，替代 FTP）、rsync（增量同步，备份/同步场景）。选型：Linux 间共享用 NFS，跨平台用 Samba，传输文件用 SFTP（别用 FTP），同步/备份用 rsync。

```text
# 实测（本机 rsync 已装，NFS/Samba 未配置）
$ rsync --version | head -1
rsync version 3.2.7
$ mount | grep -E 'nfs|cifs' || echo "无 nfs/samba 挂载"
无 nfs/samba 挂载
```

## 核心概念

1. **Samba**：实现 SMB/CIFS 协议，Linux 和 Windows 互访文件（文件服务器常用）。
2. **NFS**：Linux 间共享文件（导出目录 → 客户端挂载），文件级共享。
3. **FTP**：传统文件传输协议（21 端口），明文密码、不安全，已被 SFTP 取代。
4. **SFTP**：基于 SSH 的文件传输（22 端口），加密、安全，是 FTP 的现代替代。
5. **rsync**：增量同步工具（只传变化），适合备份/同步，不是「挂载共享」而是「复制同步」。

```text
五种方式对比：
Samba  跨平台（Linux↔Windows），文件服务器
NFS    Linux 间文件共享，挂载即用
FTP    老式文件传输，明文不安全（弃用）
SFTP   SSH 加密传输，FTP 的现代替代
rsync  增量同步，备份/同步场景
```

## 工作原理

**NFS**：服务器 /etc/exports 导出目录 → 客户端 mount 挂载 → 客户端像访问本地目录一样访问（读写经 RPC 协议走网络）。挂载后「看到的就是共享目录」。

**Samba**：SMB 协议，客户端（尤其 Windows）通过「网络共享」访问 Linux 目录，带用户认证。

**SFTP**：走 SSH 通道，`sftp 用户@主机` 登录后用类似 FTP 的命令（get/put）传文件，全程加密。

**rsync**：对比源和目标，只传「变化的文件」（按大小/时间/校验和判断），增量同步。

```text
NFS：导出目录 → 客户端挂载 → 像本地目录访问（RPC）
Samba：SMB 协议，Windows 网络共享访问 Linux 目录
SFTP：SSH 通道加密传文件（get/put）
rsync：对比差异，只传变化（增量同步）
```

## 常用命令与配置

```shell
# NFS 服务端
echo '/data 192.168.1.0/24(rw,sync,no_root_squash)' >> /etc/exports
exportfs -ra                  # 重新导出
# NFS 客户端
mount -t nfs 服务器:/data /mnt/data

# Samba
smbpasswd -a alice            # 建 samba 用户
systemctl restart smbd

# SFTP（就是 SSH）
sftp user@host
> get 远程文件                # 下载
> put 本地文件                # 上传

# rsync
rsync -avz /data/ backup:/backup/data/
```

## 配置文件解析

NFS 导出配置（/etc/exports）：

```text
# 格式：导出目录 客户端(选项)
/data    192.168.1.0/24(rw,sync,no_root_squash)
/backup  *.example.com(ro,sync)

选项：
rw/ro        读写/只读
sync         同步写（数据安全，性能略低）
no_root_squash  客户端 root 保留 root 权限（默认 root_squash 降为 nobody）
```

Samba 配置（/etc/samba/smb.conf）：

```ini
[share]
    path = /data/share         # 共享目录
    browseable = yes
    read only = no             # 可写
    valid users = alice,bob    # 允许的用户
    create mask = 0664
```

```text
NFS exports：导出目录 + 客户端网段 + 权限选项（rw/sync/root_squash）
Samba smb.conf：共享名 + path + 用户权限
```

## 应用场景实战

### 场景一：多台 Linux 共享数据目录（NFS）

```shell
# 服务端
echo '/data 192.168.1.0/24(rw,sync)' >> /etc/exports
exportfs -ra
# 客户端（每台）
mount -t nfs 192.168.1.100:/data /mnt/data
echo '192.168.1.100:/data /mnt/data nfs defaults 0 0' >> /etc/fstab
# 多台机器访问同一份 /data，数据一致
```

### 场景二：Windows 访问 Linux 文件（Samba）

```shell
# 1. 装 samba + 配共享 + 建用户
# 2. Windows 资源管理器输入 \\192.168.1.100\share
# 3. 输入 samba 用户密码，即可访问
```

### 场景三：安全传文件（SFTP 替代 FTP）

```shell
# 用 SFTP（SSH 加密），别用 FTP（明文）
sftp deploy@192.168.1.100
> put app.jar          # 上传
> get logs/app.log     # 下载
```

## 性能与调优

```text
1. NFS 版本 —— NFSv4 性能/安全性优于 v3，尽量用 v4
2. NFS rsize/wsize —— 读写块大小，大文件传输调大（如 1MB）
3. NFS sync vs async —— async 性能好但可能丢数据，安全优先用 sync
4. rsync 压缩 —— 网络传输加 -z 压缩，大文件加 -P（断点续传）
5. Samba 协议版本 —— 用 SMB2/3（快），禁用 SMB1（慢且有漏洞）
```

## 安全与权限

```text
1. 别用 FTP —— 明文密码，用 SFTP 替代
2. NFS 限定网段 —— exports 里限客户端网段，别导出给所有人
3. NFS root_squash —— 默认开启（客户端 root 降权），别轻易 no_root_squash
4. Samba 用户认证 —— 用 smbpasswd 建独立用户，别用系统用户直接登
5. 传输加密 —— 跨公网用 SFTP/rsync over SSH，别用明文 NFS/Samba 裸跑公网
```

## 故障排查

### NFS 挂载失败

```shell
# 1. 看服务端 NFS 服务状态
systemctl status nfs-server
# 2. 看导出列表
showmount -e 服务器IP
# 3. 看客户端挂载报错
mount -t nfs -v 服务器:/data /mnt/data
# 4. 看 RPC 端口
rpcinfo -p 服务器IP
```

### 权限问题（挂载成功但没权限）

```shell
# NFS 权限：exports 选项 + 目录本身权限
ls -ld /data          # 服务端目录权限
# Samba 权限：共享配置 + Linux 文件权限 + samba 用户
```

## 常见问题

```text
Q1: FTP 和 SFTP 用哪个？
A: SFTP（SSH 加密、安全），FTP 明文已弃用。SFTP 就是 SSH，无需额外装 FTP 服务。

Q2: NFS 和 Samba 怎么选？
A: 纯 Linux 环境用 NFS（简单高效），跨 Windows 用 Samba。

Q3: NFS 挂载卡住（服务器挂了）怎么办？
A: 用 soft 挂载选项（超时返回错误），别用默认 hard（无限重试）。

Q4: rsync 是「共享」还是「同步」？
A: rsync 是同步（复制到本地/远程），不是挂载共享。NFS/Samba 是「挂载访问」，rsync 是「增量复制」。
```

## 面试题

```text
1. NFS 和 Samba 的区别？
   答：NFS 是 Linux 间文件共享（NFS 协议），Samba 是跨平台（SMB/CIFS 协议，兼容 Windows）。

2. 为什么用 SFTP 不用 FTP？
   答：FTP 明文传输（密码可被窃听），SFTP 走 SSH 加密通道，安全。

3. NFS 的 root_squash 是什么？
   答：客户端 root 访问时降权为 nobody（防止客户端 root 在服务端有 root 权限），安全机制。

4. rsync 增量同步的原理？
   答：对比源和目标的文件（大小/时间/校验和），只传变化的文件，不重传未变的。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 传文件用 SFTP/rsync（加密），别用 FTP（明文）
2. NFS 限定网段 + root_squash，别导出给所有人
3. Linux 间共享用 NFS，跨 Windows 用 Samba
4. 大文件 rsync 加 -P（断点续传）+ -z（压缩）
5. NFS 挂载写 fstab 持久化，避免重启丢失

### 踩坑记录

```text
坑 1：NFS 服务器挂了，客户端 df/ls 全卡住
结论：NFS 服务器不可达，客户端访问挂载点卡死。
原因：默认 hard 挂载，服务器不可达时无限重试。
解法：挂载用 soft,intr 选项，超时返回错误不卡死。

坑 2：NFS 客户端 root 访问权限不足
结论：客户端 root 访问 NFS 文件报 Permission denied。
原因：root_squash 把客户端 root 降为 nobody，没权限。
解法：需要 root 权限时服务端配 no_root_squash（注意安全）。

坑 3：FTP 明文密码被窃听
结论：FTP 传文件密码泄露。
原因：FTP 明文传输，中间人可窃听密码和文件。
解法：改用 SFTP（SSH 加密），彻底弃用 FTP。

坑 4：Samba 老协议 SMB1 连不上/有漏洞
结论：Windows 10+ 连不上老 Samba，或安全扫描报 SMB1 漏洞。
原因：SMB1 已被 Windows 禁用（有 WannaCry 等漏洞）。
解法：Samba 配 min protocol = SMB2，禁用 SMB1。

坑 5：NFS 重启后客户端挂载丢失
结论：NFS 客户端重启后挂载点没了。
原因：mount 是临时的，没写 fstab。
解法：写 /etc/fstab 持久化，或用 autofs 自动挂载。
```

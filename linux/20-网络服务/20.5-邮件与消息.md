## 概述

邮件服务让系统「发信」——应用通知、告警、cron 任务报告都靠邮件。Postfix 是 Linux 最主流的邮件服务器（MTA，替代老牌 Sendmail）。核心：SMTP（发信协议）、POP3/IMAP（收信协议）。生产环境自建完整邮件服务器很复杂（反垃圾、认证、TLS），所以常见做法是「Postfix 只做发信（中继到第三方 SMTP），收信用第三方」。基础邮件服务（发信 + 本地投递）是运维必备。

```text
# 实测（本机未装邮件服务）
$ command -v postfix sendmail exim || echo "邮件服务未装"
邮件服务未装
# 邮件服务需单独安装（apt install postfix）
```

## 核心概念

1. **MTA（邮件传输代理）**：负责邮件的传输/路由（Postfix、Sendmail、Exim），「发信」的核心。
2. **SMTP**：简单邮件传输协议，用于「发信」和「服务器间转发」（25 端口，加密 465/587）。
3. **POP3 / IMAP**：收信协议。POP3（下载到本地，110 端口）、IMAP（服务器端管理，143 端口，现代多用）。
4. **MDA / MUA**：MDA（投递代理，把邮件投到用户邮箱）、MUA（邮件客户端，如 Outlook、Foxmail）。
5. **中继 relay**：把邮件转发到别的服务器（如中继到企业邮箱/第三方 SMTP）。

```text
核心概念：
MTA（Postfix 发信核心）+ SMTP（发信协议）+ POP3/IMAP（收信协议）
中继 relay（转发到第三方 SMTP，自建发信的常见做法）
```

## 工作原理

邮件收发流程：

1. **发信**：发件人的 MUA（客户端）→ 通过 SMTP 提交给发件人的 MTA（Postfix）→ MTA 查 DNS 的 MX 记录找到收件域名的邮件服务器 → SMTP 投递过去。
2. **收信**：收件人的 MTA 收到邮件 → MDA 投递到用户邮箱（本地存储）→ 收件人用 MUA 通过 POP3/IMAP 取信。

自建发信（Postfix 中继）的简化流程：应用/系统 → Postfix → 中继到第三方 SMTP（企业邮箱/Gmail）→ 对方收件人。这样不用自己处理「反垃圾、反向解析、域名信誉」这些复杂问题。

```text
发信：MUA → MTA(Postfix) → 查 MX 记录 → 对方 MTA → 投递
收信：对方 MTA → MDA → 邮箱 → MUA(POP3/IMAP) 取信
自建发信：Postfix 中继到第三方 SMTP（避免自建完整邮件服务器的复杂度）
```

## 常用命令与配置

```shell
# 安装（本机未装，示例）
apt install postfix mailutils    # Debian/Ubuntu
dnf install postfix mailx        # CentOS/RHEL

# 发送邮件
echo "内容" | mail -s "主题" user@example.com
echo "内容" | mailx -s "主题" -a 附件 user@example.com

# 查看邮件队列
mailq / postqueue -p             # 队列里的邮件（待发/卡住）
postqueue -f                     # 强制冲刷队列（重发）
postsuper -d ALL                 # 清空队列

# 服务管理
systemctl status postfix
journalctl -u postfix -n 50      # 邮件日志
```

## 配置文件解析

Postfix 主配置（/etc/postfix/main.cf，发信中继到第三方 SMTP）：

```ini
# 主机名和域名
myhostname = mail.example.com
mydomain = example.com
myorigin = $mydomain

# 中继到第三方 SMTP（如企业邮箱/QQ/163）
relayhost = [smtp.example.com]:587
smtp_sasl_auth_enable = yes            # 开启 SMTP 认证
smtp_sasl_password_maps = hash:/etc/postfix/sasl_passwd
smtp_sasl_security_options = noanonymous
smtp_tls_security_level = encrypt      # TLS 加密
```

认证密码文件（/etc/postfix/sasl_passwd）：

```text
[smtp.example.com]:587  user@example.com:密码
# 改完执行 postmap /etc/postfix/sasl_passwd 生成 hash
```

```text
关键配置：
relayhost              中继目标（第三方 SMTP）
smtp_sasl_auth_enable  认证开关
smtp_sasl_password_maps 认证密码文件
smtp_tls_security_level TLS 加密
```

## 应用场景实战

### 场景一：配置 Postfix 发信（中继到第三方 SMTP）

```shell
# 1. 装 postfix
apt install postfix mailutils
# 2. 配 main.cf（relayhost + 认证 + TLS）
# 3. 配认证密码
echo '[smtp.qq.com]:587 user@qq.com:授权码' > /etc/postfix/sasl_passwd
postmap /etc/postfix/sasl_passwd
# 4. 重启 + 测试发信
systemctl restart postfix
echo "测试" | mail -s "test" admin@example.com
```

### 场景二：cron 任务失败发邮件告警

```shell
# 1. 配置好 Postfix 发信
# 2. cron 里设 MAILTO（任务输出自动发邮件）
# crontab 顶部：MAILTO=admin@example.com
# 3. 任务失败时，输出自动邮件通知
```

## 性能与调优

```text
1. 队列管理 —— 大量邮件时队列堆积，postqueue -f 冲刷，配并发投递
2. 批量发信 —— 营销/通知邮件用专门的发送服务（第三方 SMTP 有频率限制），别用自建 Postfix 群发
3. 队列重试 —— 失败邮件自动重试（默认间隔递增），卡住的用 postqueue -f 手动重发
4. 连接复用 —— 中继到同一 SMTP 复用连接，减少握手
```

## 安全与权限

```text
1. 别做开放中继 —— 配好 relay 限制，否则被垃圾邮件滥用（open relay）
2. TLS 加密 —— 中继和提交都开 TLS（smtp_tls_security_level=encrypt）
3. 认证密码文件 —— sasl_passwd 权限 600，别泄露
4. SPF/DKIM —— 发信域名配 SPF/DKIM 记录，否则被对方判垃圾邮件
5. 反向解析 —— 发信 IP 要有 PTR 反向解析，否则被拒
```

## 故障排查

### 邮件发不出去

```shell
# 1. 看邮件队列（卡住的邮件）
mailq
# 2. 看 postfix 日志
journalctl -u postfix -n 50
tail -f /var/log/mail.log
# 3. 看卡住邮件的原因（队列详情）
postcat -q <队列ID>
# 4. 手动重发
postqueue -f
```

### 邮件被对方拒收

```shell
# 常见原因：无反向解析、无 SPF/DKIM、被列黑名单
# 1. 查反向解析
dig -x <发信IP>
# 2. 查 SPF 记录
dig TXT example.com | grep spf
```

## 常见问题

```text
Q1: 自建邮件服务器还是用第三方？
A: 完整自建（收+发+反垃圾）很复杂，通常「Postfix 发信（中继第三方）+ 第三方收信」够用。

Q2: SMTP、POP3、IMAP 区别？
A: SMTP 发信，POP3 收信（下载到本地），IMAP 收信（服务器管理，多设备同步）。

Q3: 邮件进垃圾箱怎么回事？
A: 域名没配 SPF/DKIM、发信 IP 没反向解析、IP 信誉差。配 SPF/DKIM + 正向信誉。

Q4: mailq 里邮件卡住怎么办？
A: postcat 看卡住原因，postqueue -f 重发，postsuper -d 删除死信。
```

## 面试题

```text
1. MTA、MUA、MDA 分别是什么？
   答：MTA 传输代理（Postfix 发信路由）、MUA 邮件客户端（Outlook）、MDA 投递代理（投递到邮箱）。

2. SMTP 和 POP3/IMAP 的区别？
   答：SMTP 发信，POP3/IMAP 收信。POP3 下载本地，IMAP 服务器端管理（多设备同步）。

3. 什么是 open relay？为什么危险？
   答：开放中继（任何人都能经你的服务器发信），被垃圾邮件滥用，IP 被拉黑。

4. 邮件被拒收的常见原因？
   答：无 SPF/DKIM、无反向解析、IP 信誉差、被列黑名单、内容触发垃圾过滤。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 发信用 Postfix 中继第三方 SMTP，别自建完整邮件服务器
2. 发信域名配 SPF/DKIM，否则进垃圾箱
3. 认证密码文件权限 600，TLS 加密
4. 别配成 open relay（限制中继来源）
5. cron/告警用邮件通知，但配置好发信（否则收不到）

### 踩坑记录

```text
坑 1：配成 open relay 被垃圾邮件滥用
结论：服务器被利用群发垃圾邮件，IP 被拉黑。
原因：没限制中继来源，任何人都能经你发信。
解法：限制中继（mynetworks + 认证），别开放中继。

坑 2：邮件进了垃圾箱，查不出原因
结论：发信成功但对方收不到（在垃圾箱）。
原因：没配 SPF/DKIM，或发信 IP 信誉差。
解法：配 SPF/DKIM 记录 + 反向解析，提升域名信誉。

坑 3：cron 设了 MAILTO 但收不到
结论：cron 任务失败，邮件没收到。
原因：没装/没配邮件服务（Postfix），本地投递都失败。
解法：先装 postfix 配好发信，再设 MAILTO。

坑 4：中继第三方 SMTP 认证失败
结论：Postfix 中继报认证错误（535）。
原因：密码/授权码错，或没 postmap 生成 hash。
解法：确认授权码正确，改 sasl_passwd 后 postmap 生成 hash。

坑 5：邮件卡在队列，一直重发
结论：mailq 里邮件堆积，反复重试发不出去。
原因：中继服务器不可达/认证失败，邮件无限重试。
解法：postcat 看卡住原因，postqueue -f 重发或 postsuper -d 删死信。
```

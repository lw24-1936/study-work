## 概述

系统加固（System Hardening）是指通过收紧配置、裁剪不必要的组件、限制权限，把系统的「攻击面」降到最小。攻击者入侵靠的是漏洞和误配置，加固就是主动消除这两类风险：装的东西越少、权限越细、服务越精简、内核越收紧，被攻破的概率越低。它是一条持续动作，不是一次性操作——上线前做基线加固，上线后持续审计和补丁。

```text
系统加固四大抓手：
最小化安装    只装必需的包，减少可被利用的组件
用户与权限    禁用 root 直连、细粒度授权、收紧密码与文件权限
服务裁剪      停用无关服务、关掉多余监听端口
内核加固参数  用 sysctl 收紧内核安全开关（ASLR / syncookies / 反向路径过滤等）
```

## 核心概念

### 最小化安装

最小化安装指「按需装包」，只保留业务真正需要的软件，原则是「装得越少，可被攻击的组件越少」。实践上从 minimal ISO 起步，装包用 `--no-install-recommends`（Debian）或 `dnf install --setopt=install_weak_deps=False`（RHEL）避免拖进一车推荐依赖，再逐项核对已装清单，卸载编译器、调试工具、多余客户端这类「入侵者顺手就用的工具」。

```shell
# RHEL 系：最小化安装 + 不装弱依赖
dnf install --setopt=install_weak_deps=False <pkg>

# Debian 系：不装推荐依赖
apt install --no-install-recommends <pkg>

# 查看已安装的软件包数量（感受"瘦身"空间）
rpm -qa | wc -l          # RHEL 系
dpkg -l | grep '^ii' | wc -l   # Debian 系

# 找出常见"多余"工具，确认不需要就卸载
rpm -qa | grep -Ei 'gcc|make|debug|nc|tcpdump|telnet'
```

```text
最小化安装要点：
1. 从 minimal 基础镜像/ISO 起步，不要"全功能"安装
2. 装包关掉推荐/弱依赖，避免连带装进无关组件
3. 卸载编译器（gcc/make）、抓包、调试工具等入侵者常用工具
4. 定期 rpm -qa / dpkg -l 清点，确认每个包都有"存在理由"
```

### 用户与权限

用户与权限是加固的第二道防线，核心是「最小权限」：默认账户禁用 root 远程登录、业务进程跑普通用户、授权走 sudo 而非直接给 root、收紧密码有效期和文件默认权限。三个层次：账户层（谁、什么口令、有效期）、认证层（如何登录：密钥/密码、失败锁定）、文件层（谁能读写执行）。

```shell
# 1. 账户层：密码有效期策略（/etc/login.defs）
grep -E 'PASS_MAX_DAYS|PASS_MIN_DAYS|PASS_MIN_LEN' /etc/login.defs
chage -l root                # 看某账户密码策略
chage -M 90 -m 7 -W 7 <user>  # 最长 90 天、最短 7 天、提前 7 天提醒

# 2. 认证层：禁用 root 通过 SSH 登录（改 sshd_config 后重启）
#    PermitRootLogin no   PasswordAuthentication no
systemctl restart sshd

# 3. 文件层：收紧默认权限
umask 027                    # 新建文件默认 750（组可读不可写，其他人无权限）
find / -xdev -perm -4000 -type f 2>/dev/null   # 找 SUID 文件，核对是否必要
chmod u-s /usr/bin/passwd    # 去掉不必要的 SUID（注意：passwd 需要 SUID 才能改 shadow，慎改）

# 4. 授权层：sudo 最小授权，避免 sudo ALL=(ALL) ALL
visudo                       # 编辑 /etc/sudoers，给用户只授必要命令
```

```text
用户与权限加固要点：
1. 禁用 root 直接 SSH，日常用普通用户 + sudo，审计"谁在何时用了 sudo"
2. 密码有效期 + 复杂度 + 失败锁定（pam_faillock）三件套
3. umask 设 027（更严格可 077），新建文件默认不对外开放
4. 定期扫 SUID/SGID 文件，去掉不必要的高权限位
```

### 服务裁剪

服务裁剪指关掉系统里用不到的服务，让「开着且能对外说话」的进程越少越好。每个对外监听端口都是一个潜在入口，裁剪的步骤是：列出已启用服务 → 列出监听端口 → 对照业务需求，能 disable 的 disable、能 mask 的 mask、能卸载的卸载。判断标准：说不清这个服务为什么开着的，就该关。

```shell
# 1. 列出所有"开机自启"的服务
systemctl list-unit-files --type=service --state=enabled

# 2. 列出所有正在监听的 TCP/UDP 端口
ss -tulnp

# 3. 关掉不需要的服务（disable 只是取消自启，mask 连手动启动都禁止）
systemctl disable --now <service>   # 停止并取消自启
systemctl mask <service>            # 彻底屏蔽，防止被依赖间接拉起

# 4. 确认裁剪后端口变少
ss -tulnp
```

```text
服务裁剪要点：
1. 原则：每个监听端口都必须能说出"被谁用、为什么开"
2. disable 取消自启，mask 彻底屏蔽（防被其它 unit 依赖拉起）
3. 常见可裁剪：telnet、rsh、ftp、nfs、rpcbind、cups、avahi-daemon
4. 裁完用 ss -tulnp 复核，只留业务必需的端口
```

### 内核加固参数

内核加固参数通过 `/proc/sys/`（sysctl）收紧内核的安全行为，覆盖内存、网络、进程三大类：内存侧开 ASLR（地址空间随机化）让漏洞利用难定位地址；网络侧开 syncookies 防 SYN 洪水、关源路由和 ICMP 重定向、开反向路径过滤（rp_filter）防 IP 欺骗；进程侧关 core dump 防泄露敏感信息、限制 dmesg 和 /proc 指针地址的暴露、开 Yama 限制 ptrace。这些是「不改代码、只改开关」就能显著提升对抗能力的低成本手段。

```shell
# 查看/临时设置（立即生效，重启失效）
sysctl kernel.randomize_va_space
sysctl -w kernel.randomize_va_space=2

# 查看所有可调参数
sysctl -a | grep -E 'randomize|syncookies|rp_filter'

# 持久化：写进 /etc/sysctl.d/*.conf 后加载
cat > /etc/sysctl.d/99-hardening.conf <<'EOF'
# 内存
kernel.randomize_va_space = 2        # ASLR 全开
fs.suid_dumpable = 0                 # 禁止 SUID 程序 core dump
kernel.dmesg_restrict = 1            # 限制 dmesg 泄露内核地址
kernel.kptr_restrict = 2             # 限制 /proc 泄露内核指针
kernel.yama.ptrace_scope = 1         # 限制 ptrace（仅同父进程）
# 网络
net.ipv4.tcp_syncookies = 1          # 防 SYN flood
net.ipv4.conf.all.accept_redirects = 0   # 忽略 ICMP 重定向
net.ipv4.conf.all.send_redirects = 0     # 不发 ICMP 重定向（非路由节点）
net.ipv4.conf.all.accept_source_route = 0 # 禁止源路由
net.ipv4.conf.all.rp_filter = 1      # 反向路径过滤，防 IP 欺骗
net.ipv4.icmp_echo_ignore_broadcasts = 1 # 忽略广播 ping
EOF
sysctl -p /etc/sysctl.d/99-hardening.conf   # 立即加载
```

```text
内核加固参数要点：
kernel.randomize_va_space=2  ASLR 全开（0 关 / 1 部分 / 2 全开）
net.ipv4.tcp_syncookies=1    防 SYN 洪水（半连接队列满时仍能响应）
net.ipv4.conf.all.rp_filter=1 反向路径过滤，丢弃源地址伪造的包
fs.suid_dumpable=0            禁止 SUID 程序 core dump（防泄露）
kernel.dmesg_restrict=1       非 root 不能读 dmesg（防内核地址泄露）
kernel.yama.ptrace_scope=1    限制进程间 ptrace（防内存注入/窃取）
```

## 工作原理

系统加固的底层逻辑是「缩小攻击面 + 提高利用门槛」两条腿：

1. **缩小攻击面**：攻击者要入侵，先得找到一个「入口」——一个监听端口、一个有漏洞的服务、一个可登录的账户、一个可写的目录。最小化安装、服务裁剪、用户收紧，本质上都是减少这些入口的数量。入口越少，被发现和利用的概率越低。
2. **提高利用门槛**：入口还在的情况下，让漏洞「难被利用」。内核参数就是典型——ASLR 让堆栈地址随机，缓冲区溢出攻击拿不到稳定地址；rp_filter 让伪造源地址的包进不来；dmesg/kptr 限制让攻击者读不到内核地址做下一步计算。这层不减少入口，但让每个入口都更难打穿。

两者是乘法关系：攻击面缩小一半、利用难度翻一倍，整体风险降到四分之一。所以加固要「广度 + 深度」一起做，只做其一效果有限。

```text
加固两条腿：
缩小攻击面 → 减少入口（少装包 / 少开服务 / 少开账户 / 少开端口）
提高利用门槛 → 增加难度（ASLR / 权限限制 / 内核收紧 / 补丁更新）

关系：乘法。攻击面 × 利用难度 = 总体风险，两边都要做
```

## 常用命令与配置

```shell
# === 账户与密码 ===
```

## 配置文件解析

### /etc/sysctl.conf 与 /etc/sysctl.d/*.conf

内核参数的持久化配置文件。`/etc/sysctl.d/` 下的 `.conf` 按文件名排序覆盖 `sysctl.conf`，所以自定义参数通常放 `99-*.conf` 保证优先级最高。

```ini
# /etc/sysctl.d/99-hardening.conf
kernel.randomize_va_space = 2          # ASLR：0 关 / 1 部分 / 2 全开
kernel.core_uses_pid = 1               # core 文件名带 PID
fs.suid_dumpable = 0                   # SUID 程序不产生 core dump
kernel.dmesg_restrict = 1              # 限制 dmesg
kernel.kptr_restrict = 2               # 限制内核指针暴露
net.ipv4.tcp_syncookies = 1            # SYN cookie 防护
net.ipv4.conf.all.rp_filter = 1        # 反向路径过滤
net.ipv4.conf.all.accept_redirects = 0 # 忽略 ICMP 重定向
net.ipv4.conf.all.log_martians = 1     # 记录"火星包"（源地址不合法的包）
net.ipv4.ip_forward = 0                # 非路由节点关闭转发
```

```text
字段要点：
值类型        0/1 布尔开关，2 表示"更高档"（如 ASLR 全开）
加载方式      sysctl -p <file> 立即生效；sysctl --system 加载全部
优先级        /etc/sysctl.d/ 按文件名字典序覆盖 /etc/sysctl.conf
```

### /etc/ssh/sshd_config（SSH 服务加固）

SSH 是最常被扫描爆破的入口，加固它的配置集中在认证方式和 root 直连控制。

```ini
# /etc/ssh/sshd_config 关键项
PermitRootLogin no                  # 禁止 root 直接登录（用普通用户 + sudo）
PasswordAuthentication no           # 禁止口令登录（只用密钥）
PubkeyAuthentication yes            # 允许密钥登录
PermitEmptyPasswords no             # 禁止空口令
MaxAuthTries 3                      # 单连接最多尝试次数（防爆破）
ClientAliveInterval 300             # 空闲 300 秒探测，防死连接
ClientAliveCountMax 0               # 探测 0 次就断开
AllowUsers alice bob                # 白名单：只允许这些用户登录（推荐）
Protocol 2                          # 只用 SSH 协议 v2
```

```text
SSH 加固要点：
1. PermitRootLogin no + PasswordAuthentication no = 只留密钥登录的普通用户
2. AllowUsers/AllowGroups 白名单，比"黑名单"更严
3. 改完 systemctl restart sshd，另开一个会话验证能登录再关旧会话
4. 配合 fail2ban 自动封禁爆破 IP
```

### /etc/login.defs 与 /etc/security/limits.conf

`login.defs` 定义新建账户的默认密码策略，`limits.conf` 定义进程级资源上限（防资源耗尽）。

```ini
# /etc/login.defs（新建用户默认值）
PASS_MAX_DAYS   90     # 密码最长有效期（天）
PASS_MIN_DAYS   7      # 两次改密码最短间隔
PASS_MIN_LEN    12     # 最小密码长度
PASS_WARN_AGE   7      # 过期前 7 天提醒
CREATE_HOME     yes
UMASK           077    # 新用户默认 umask
```

```ini
# /etc/security/limits.conf（资源限制，防单用户/单进程耗尽资源）
*               hard    core            0        # 禁 core dump
*               hard    nproc           4096     # 最大进程数
*               hard    nofile          65535    # 最大打开文件数
```

```text
字段要点：
login.defs 只影响"之后新建"的用户，存量用户用 chage 改
limits.conf soft/hard：soft 是当前上限（可自行提高），hard 是硬顶（只有 root 能提）
```

## 应用场景实战

### 场景一：新服务器上线前的加固脚本

把常见加固动作写成脚本，新机器上线时跑一遍，保证「基线一致」。脚本幂等（重复跑不报错），跑完用 ss 和 sysctl 复核。

```shell
#!/bin/bash
# harden.sh —— 新服务器上线加固（示例，按业务裁剪）
set -e

echo "[1/5] 设置 umask 027"
echo "umask 027" >> /etc/profile

echo "[2/5] 内核加固参数"
cat > /etc/sysctl.d/99-hardening.conf <<'EOF'
kernel.randomize_va_space = 2
fs.suid_dumpable = 0
kernel.dmesg_restrict = 1
net.ipv4.tcp_syncookies = 1
net.ipv4.conf.all.rp_filter = 1
net.ipv4.conf.all.accept_redirects = 0
net.ipv4.conf.all.accept_source_route = 0
net.ipv4.icmp_echo_ignore_broadcasts = 1
EOF
sysctl --system > /dev/null

echo "[3/5] SSH 加固"
sed -i 's/^#\?PermitRootLogin.*/PermitRootLogin no/' /etc/ssh/sshd_config
sed -i 's/^#\?PasswordAuthentication.*/PasswordAuthentication no/' /etc/ssh/sshd_config
sed -i 's/^#\?PermitEmptyPasswords.*/PermitEmptyPasswords no/' /etc/ssh/sshd_config
systemctl restart sshd

echo "[4/5] 关闭常见多余服务"
for svc in telnet.socket rsh.socket ftp.service cups.service avahi-daemon.service; do
  systemctl disable --now "$svc" 2>/dev/null || true
done

echo "[5/5] 复核"
ss -tulnp
sysctl kernel.randomize_va_space net.ipv4.tcp_syncookies
```

```text
流程：设 umask → 内核参数 → SSH 收紧 → 裁服务 → 复核
关键：改 SSH 前先确认有可用的密钥登录，否则会把自己锁在门外
```

### 场景二：SSH 登录加固 + 失败锁定（防爆破）

SSH 爆破是最常见的自动化攻击。加固组合拳：密钥登录 + 禁 root + 失败锁定（pam_faillock）+ fail2ban 封 IP。

```shell
# 1. 生成密钥对（客户端执行），把公钥放进服务器 authorized_keys
ssh-keygen -t ed25519 -C "admin@host"
ssh-copy-id alice@server

# 2. 服务端 /etc/ssh/sshd_config
#    PermitRootLogin no
#    PasswordAuthentication no
#    AllowUsers alice
systemctl restart sshd

# 3. 失败锁定：/etc/security/faillock.conf（RHEL9，pam_faillock）
cat >> /etc/security/faillock.conf <<'EOF'
deny = 5
unlock_time = 600
EOF
# 并在 /etc/pam.d/sshd 启用 pam_faillock（auth 段加两行，视发行版而定）

# 4. fail2ban 自动封爆破 IP
dnf install fail2ban -y
systemctl enable --now fail2ban
fail2ban-client status sshd   # 查看封禁情况
```

```text
组合拳层次：
第一层 密钥登录（密码都进不来，爆破无从谈起）
第二层 失败锁定（pam_faillock：错 5 次锁 10 分钟）
第三层 fail2ban（按 IP 封禁，阻断批量扫描）
```

## 性能与调优

加固通常对性能影响很小（多为开关型参数），但有两处要留意：

```text
1. tcp_syncookies —— 只在 SYN 半连接队列满时才触发，正常流量下无感；极端高并发下可微调 backlog
2. rp_filter —— 反向路径过滤对"非对称路由/多网卡"场景会误丢包；多网卡或路由复杂时设 0 或 2（宽松模式）
3. umask 收紧 —— 无性能影响，但可能影响共享协作（组内不可写），按团队协作模型选 027/022
4. core dump 关闭 —— 反而省磁盘，但排查崩溃会缺现场，dev 环境可保留
5. 服务裁剪 —— 直接省内存和 CPU（少跑进程），是"免费的性能优化"
```

```text
调优原则：先保证安全基线，再按业务实测微调网络类参数（rp_filter/syncookies），别为了极致性能关掉安全开关
```

## 安全与权限

```text
1. 加固配置本身要防篡改 —— sysctl.conf / sshd_config / sudoers 属 root，权限 600/644，改动走审计（23.3）
2. sudoers 用 visudo 编辑（带语法校验），避免写坏导致无法提权
3. SUID 位是双刃剑 —— passwd/su/sudo 需要它，但要定期核对，防止被塞进恶意 SUID 二进制
4. 内核参数别只"临时 set" —— 重启就丢，务必落盘到 /etc/sysctl.d/ 并验证 sysctl --system 生效
5. 加固 ≠ 一次做完 —— 新装的包/新开的服务会重新引入风险，配合定期基线扫描（OpenSCAP）
```

## 故障排查

### 加固后 SSH 连不上（最常见）

```shell
# 1. 从控制台（或已有的旧会话）确认 sshd 是否在跑
systemctl status sshd

# 2. 看 sshd 日志，定位拒绝原因
journalctl -u sshd -n 50
#    常见：Permission denied (publickey) → 密码登录被关但没配密钥
#    Connection closed by ... → PermitRootLogin no 但你在用 root 连

# 3. 校验配置语法（改错会起不来）
sshd -t

# 4. 用 -v 从客户端看认证过程（卡在哪一步）
ssh -v alice@server
```

```text
SSH 连不上排查顺序：sshd 是否在跑 → sshd -t 语法 → journalctl 日志 → 客户端 ssh -v
最稳做法：改 SSH 配置后另开一个终端验证能登录，再关旧会话（防锁死自己）
```

### sysctl 参数「设置不生效」

```shell
# 1. 确认当前生效值
sysctl <key>                 # 如 sysctl kernel.randomize_va_space

# 2. 确认文件里写对了（注意 .conf 文件名排序覆盖）
cat /etc/sysctl.d/99-hardening.conf

# 3. 强制重新加载全部并回读
sysctl --system
sysctl <key>

# 4. 若仍不对，看是否有更高优先级的文件覆盖（字典序靠后覆盖靠前）
ls /etc/sysctl.d/
```

```text
sysctl 不生效常见原因：
1. 只 sysctl -w 临时设了，没落盘 → 重启丢失
2. 写进 sysctl.conf 但被 /etc/sysctl.d/ 下文件名更靠后的 .conf 覆盖
3. 语法错（等号两侧空格、拼写错）→ sysctl -p 会报 unknown key
```

## 常见问题

```text
Q1: 加固和「打补丁」是什么关系？
A: 打补丁（更新软件）修已知漏洞，加固收紧配置降低攻击面，两者互补。加固不替代补丁，补丁也不替代加固。生产系统两者都要做。

Q2: PermitRootLogin no 后，怎么临时需要 root 操作？
A: 普通用户 sudo 提权，或 sudo -i 进入 root shell。sudo 有审计记录，比直接 root 登录更安全可控。

Q3: umask 设 027 会影响什么？
A: 新建文件默认 640、目录 750——同组可读、其他用户不可见。适合团队协作。若需求是「组内可写」，用 002；「完全私密」用 077。

Q4: 内核参数加固会不会影响正常业务？
A: 大部分不会（ASLR、syncookies、dmesg 限制都是「防攻击」开关）。唯一要留意的是 rp_filter（多网卡/非对称路由）和 ip_forward（本机要做路由/容器网络时需要开）。改前记录原值，出问题能回滚。

Q5: 服务裁剪裁错了导致功能异常怎么办？
A: disable 是可逆的——systemctl enable <service> 恢复自启；mask 要 systemctl unmask 才能恢复。裁剪前先记录「关了哪些、为什么」，便于回滚和审计。
```

## 面试题

```text
1. 系统加固通常做哪些事？
   答：最小化安装（只装必需包）、账户与权限收紧（禁 root 直连、sudo 最小授权、密码策略）、服务裁剪（关无关服务/端口）、内核参数加固（ASLR、syncookies、rp_filter）、补丁更新、基线扫描（CIS/STIG）。

2. 什么是 ASLR？为什么要开？
   答：Address Space Layout Randomization，地址空间布局随机化。堆、栈、库的加载地址每次随机，让缓冲区溢出等漏洞攻击无法预测目标地址，大幅提高利用难度。kernel.randomize_va_space=2 全开。

3. rp_filter 是什么？什么时候要关？
   答：反向路径过滤，校验入站包的源地址是否来自「该地址应来自的网卡」，防 IP 欺骗。多网卡/非对称路由/做负载均衡或路由器的场景下会误丢合法包，此时设 0（关）或 2（宽松模式）。

4. 怎么判断一个服务该不该关？
   答：看它是否「对外监听 + 是否业务必需」。用 ss -tulnp 列监听端口，逐项核对用途；说不清为什么开着的就关。裁剪原则：默认关闭，按需开启。

5. SSH 加固的核心措施？
   答：PermitRootLogin no（禁 root 直连）、PasswordAuthentication no（只用密钥）、AllowUsers 白名单、失败锁定（pam_faillock）、fail2ban 封爆破 IP、改默认端口（可选）。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 从 minimal 安装起步，装包用 `--no-install-recommends` / 关弱依赖，定期清点包清单
2. 禁 root SSH 直连 + 密钥登录，日常走普通用户 + sudo，授权用最小命令白名单
3. 用 `ss -tulnp` 逐端口核对，能 mask 的服务一律 mask，只留业务必需
4. 内核参数落盘到 `/etc/sysctl.d/99-*.conf` 并 `sysctl --system` 验证，别只临时 `sysctl -w`
5. 加固脚本化 + 幂等，新机器跑一遍保证基线一致，配合 OpenSCAP 做 CIS 基线自动核查
6. 每次加固改动前记录原值/原状态，可回滚；改动后另开会话验证登录与服务正常

### 踩坑记录

```text
坑 1：改完 sshd_config 把自己锁在门外
结论：SSH 断连后无法再登录，只能走控制台/带外管理。
原因：先关了密码登录又没配好密钥，或 AllowUsers 没包含自己。
解法：改前先 ssh-copy-id 配好密钥，改后另开会话验证，确认能登再关旧会话。

坑 2：sysctl 参数重启后失效
结论：临时 sysctl -w 设置，重启回到默认值。
原因：只改了运行时 /proc/sys，没写进 /etc/sysctl.d/。
解法：落盘到 /etc/sysctl.d/99-*.conf，sysctl --system 加载并回读验证。

坑 3：rp_filter=1 把多网卡机器的合法流量丢了
结论：多网卡/非对称路由场景下业务偶发丢包、连接异常。
原因：反向路径过滤把「从非预期网卡进来的合法包」当成欺骗包丢弃。
解法：该场景设 net.ipv4.conf.all.rp_filter=2（宽松）或按网卡单独设 0。

坑 4：剪服务时顺手关了 NFS 相关服务，导致共享存储挂不上
结论：业务服务启动失败，日志报 mount 超时。
原因：rpcbind/nfs 是共享存储依赖，未核对依赖就 disable。
解法：裁剪前用 systemctl list-dependencies 查依赖关系，逐个核对再关。

坑 5：只做了一次加固，之后再也不管
结论：系统随时间推移重新积累风险（新装包、新开服务、新账户）。
原因：把加固当一次性动作，没有持续审计。
解法：加固进 CI/上线流程，定期跑 OpenSCAP 基线和端口/账户/SUID 盘点。
```

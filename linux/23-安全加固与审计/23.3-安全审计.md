## 概述

安全审计（Security Auditing）是通过内核级审计框架（auditd）记录系统中的敏感操作——谁在什么时间、对什么文件、执行了什么系统调用、结果如何——为事后取证、合规核查、入侵分析提供不可抵赖的记录。它与普通日志（syslog/journald）的区别在于：审计记录由内核在系统调用层直接产生，粒度细到「进程 open 了哪个文件、执行了哪个命令」，且可以针对特定文件、特定系统调用做定向监控。这是等保/合规的硬性要求，也是入侵后「谁干的、怎么进来的」的唯一可靠答案。

```text
安全审计三要素：
auditd       用户态守护进程 + 内核审计子系统，负责收集和落盘审计记录
审计规则     决定"记录什么"：文件监视（-w）、系统调用（-a syscall）、控制规则
日志分析     audit.log 记录 + ausearch 查询 + aureport 汇总报表
```

## 核心概念

### auditd（Linux 审计框架）

Linux 审计框架分两部分：内核侧的审计子系统（在系统调用路径上挂钩子，按规则生成审计记录）和用户侧的 `auditd` 守护进程（从内核接收记录，写进 `/var/log/audit/audit.log`）。配套工具链：`auditctl`（运行时管理规则）、`ausearch`（查询记录）、`aureport`（生成汇总报表）、`auditd`/`augenrules`（加载规则和配置）。审计规则可以「即时」用 auditctl 设置，也可以「持久」写进 `/etc/audit/rules.d/*.rules`。

```shell
# 查看审计服务状态
systemctl status auditd
auditctl -s                      # 看审计子系统状态（启用/规则数/backlog）

# 查看当前生效的审计规则
auditctl -l

# 查看审计日志文件
ls -l /var/log/audit/
```

```text
auditd 要点：
内核侧  系统调用路径上的钩子，按规则生成记录（不依赖应用日志）
用户侧  auditd 守护进程接收内核记录，写 /var/log/audit/audit.log
工具链  auditctl（管规则）/ ausearch（查记录）/ aureport（出报表）
```

### 审计规则

审计规则决定「记录什么」，三类：

- **控制规则**（`-a control` / 直接改配置）：控制审计子系统本身，如 backlog 上限、速率、是否审计失败。审计子系统通常要求「不可变」（`-e 2` 锁定规则，只有重启才能改），防入侵者关掉审计。
- **文件监视规则**（`-w`）：监视文件/目录，记录对其的访问（读/写/执行/属性变更）。
- **系统调用规则**（`-a syscall`）：按系统调用号/名称记录，可按 UID、成功/失败过滤。

```shell
# 文件监视：监控 /etc/passwd 的写与属性变更
auditctl -w /etc/passwd -p wa -k passwd_changes

# 文件监视：监控目录（递归）里的所有变更
auditctl -w /etc/ -p wa -k etc_changes

# 系统调用：记录所有用户的 execve（执行命令），键名 cmd_log
auditctl -a always,exit -F arch=b64 -S execve -k cmd_log

# 系统调用：记录特定用户对文件的写入
auditctl -a always,exit -F arch=b64 -S open -F uid=1000 -F success=1 -k user_open

# 查看规则 / 删除规则
auditctl -l
auditctl -d always,exit -F arch=b64 -S execve -k cmd_log

# 锁定规则（-e 2 不可变，重启才能解锁）
auditctl -e 2
```

```text
规则三要素记忆：
-w path -p <权限> -k <键>            文件监视（r 读 w 写 x 执行 a 属性）
-a always,exit -S <syscall> -F <过滤> -k <键>   系统调用（-F 过滤 uid/arch/success）
-e 0|1|2                             控制规则（0 关 / 1 开 / 2 锁定不可变）
键 -k 用于分组，ausearch -k 按组检索
```

### 日志分析

审计记录写在 `/var/log/audit/audit.log`，每条记录由若干 `type=...` 字段组成，一个事件常对应多条 type（如 `SYSCALL` + `PATH` + `CWD` + `EXECVE`）。分析三工具：

- **ausearch**：按时间、键、用户、类型、事件 ID 精确查询
- **aureport**：生成汇总报表（登录、失败、文件访问、异常等维度）
- **直接看 raw 日志**：理解底层格式，`type=` 是关键字段

```shell
# 看最近 10 条审计记录
tail -n 10 /var/log/audit/audit.log

# ausearch：按键、按用户、按类型查询
ausearch -k passwd_changes          # 查键为 passwd_changes 的记录
ausearch -ua alice                  # 查 alice 用户相关（uid）
ausearch -m USER_LOGIN              # 查登录事件（type/message 类型）
ausearch -ts today                  # 查今天（-ts 起始时间）

# aureport：汇总报表
aureport -l                         # 登录报表
aureport -f                         # 文件访问报表
aureport -x                         # 命令执行报表
aureport -au                        # 认证事件报表
aureport --failed                   # 失败事件汇总
```

```text
日志分析要点：
type 字段  SYSCALL（系统调用）/ PATH（文件路径）/ EXECVE（命令参数）/ USER_LOGIN（登录）/ AVC（SELinux 拒绝）
ausearch   精确查（-k 键 / -ua 用户 / -m 类型 / -ts 时间）
aureport   汇总报（-l 登录 / -x 命令 / -f 文件 / --failed 失败）
同一事件 多条 type 记录共享同一个审计事件 ID，用 -a <event_id> 关联查看
```

## 工作原理

审计框架的链路是「规则 → 内核钩子 → 记录 → 用户态落盘」：

1. **加载规则**：`auditctl`（或 `/etc/audit/rules.d/*.rules` 经 `augenrules` 合并）把规则下发给内核审计子系统。
2. **内核判定**：进程每次触发被规则命中的系统调用（如 `open`、`execve`、`write`），内核在系统调用返回点（`always,exit`）生成审计记录——含进程上下文（PID/UID/GID）、系统调用参数、文件路径、返回值（成功/失败）。
3. **入队传递**：内核把记录放进审计队列（backlog），通过 netlink 发给用户态 `auditd`。
4. **落盘**：`auditd` 把记录写入 `/var/log/audit/audit.log`（可配轮转），按 `auditd.conf` 的 flush 策略刷盘。

关键设计：审计在内核层产生、root 也不可直接关闭（`-e 2` 锁定后规则不可变），保证「记录本身可信、不可抵赖」，这是它区别于应用层日志的根本。

```text
审计链路：
规则下发（auditctl / augenrules）→ 内核系统调用钩子命中 → 生成记录（进程/参数/路径/结果）
→ netlink 传入用户态 auditd → 写 /var/log/audit/audit.log

设计要点：内核层产生、root 不可绕过、-e 2 锁定规则防入侵者关闭审计
```

## 常用命令与配置

```shell
# === 规则管理（运行时） ===
auditctl -l                          # 列出当前规则
auditctl -w /etc/shadow -p wa -k shadow_chg    # 加文件监视
auditctl -a always,exit -F arch=b64 -S execve -k cmd        # 加系统调用监视
auditctl -D                          # 删除全部规则（慎用）
auditctl -e 2                        # 锁定（不可变，重启才解锁）

# === 持久化规则 ===
# 规则写 /etc/audit/rules.d/*.rules，用 augenrules 合并生成 /etc/audit/audit.rules
augenrules --load                    # 合并并加载所有 .rules
systemctl restart auditd             # 重启 auditd（会自动加载 audit.rules）

# === 查询与分析 ===
ausearch -k <键>                     # 按键查
ausearch -m <类型>                   # 按类型查（USER_LOGIN/AVC/SYSCALL）
ausearch -ts today -te now           # 按时间范围
ausearch -a <event_id>               # 按事件 ID 查完整关联记录
aureport -l / -x / -f / --failed     # 汇总报表

# === 状态 ===
auditctl -s                          # 看状态（enabled / backlog / 规则数）
systemctl status auditd
```

```text
命令分组记忆：
规则    auditctl -w / -a / -D / -e，持久化走 rules.d + augenrules
查询    ausearch（-k 键 / -m 类型 / -ts 时间 / -a 事件）
报表    aureport（-l 登录 / -x 命令 / -f 文件 / --failed 失败）
```

## 配置文件解析

### /etc/audit/auditd.conf（auditd 守护进程配置）

```ini
# /etc/audit/auditd.conf 关键项
log_file = /var/log/audit/audit.log   # 日志文件路径
log_format = ENRICHED                  # RAW / ENRICHED（含 UID/登录名等可读字段）
log_group = root                       # 日志文件属组
max_log_file = 8                       # 单文件最大 MB，触发轮转
num_logs = 5                           # 保留几个轮转文件
flush = INCREMENTAL_ASYNC              # 刷盘策略：NONE/INCREMENTAL/SYNC/INCREMENTAL_ASYNC
freq = 50                              # INCREMENTAL 模式下每 50 条刷一次
space_left = 75                        # 磁盘剩余 75MB 时告警
space_left_action = SYSLOG             # 触发 syslog 告警
admin_space_left = 50                  # 剩余 50MB 时执行 admin 动作
admin_space_left_action = SUSPEND      # 暂停审计（防止日志写爆磁盘）
disk_full_action = SUSPEND             # 磁盘满时暂停审计
disk_error_action = SUSPEND            # 磁盘错误时暂停审计
```

```text
字段要点：
flush    刷盘策略：SYNC 每条落盘最安全但慢，INCREMENTAL_ASYNC 性能/安全平衡（默认）
max_log_file + num_logs 控制日志大小与轮转，防磁盘写满
space_left_action / disk_full_action 磁盘告警与满盘时的动作（SUSPEND 暂停审计）
ENRICHED 格式 每条记录附带 uid/auid 对应的登录名等可读信息，排查更直观
```

### /etc/audit/rules.d/audit.rules（审计规则，持久化）

规则文件放 `/etc/audit/rules.d/`，`augenrules` 把它们合并成 `/etc/audit/audit.rules` 供 auditd 加载。

```text
# /etc/audit/rules.d/audit.rules
# 删除旧规则（加载时先清空，避免重复累积）
-D

# 加大 backlog，防止高负载下丢事件
-b 8192

# 失败时 panic（高安全环境，审计不可用则停机，防"关了审计再入侵"）
-f 2

# 文件监视：核心系统文件
-w /etc/passwd -p wa -k identity
-w /etc/shadow -p wa -k identity
-w /etc/sudoers -p wa -k sudoers_change
-w /var/log/audit/ -p wa -k audit_log

# 系统调用：记录所有命令执行
-a always,exit -F arch=b64 -S execve -k cmd_log

# 系统调用：记录 root 权限变更（setuid/setgid）
-a always,exit -F arch=b64 -S setuid -S setgid -F success=1 -k priv_escalation

# 锁定规则（不可变，重启才能改）
-e 2
```

```text
规则文件要点：
-D      清空已有规则（放文件开头，避免累积重复）
-b      设置 backlog 队列大小（-b 8192）
-f 2    审计失败时 panic（0 忽略 / 1 printk / 2 panic）
-w/-a   文件监视 / 系统调用规则，-k 打键便于检索
-e 2    锁定，规则不可变（生产建议，防入侵者停审计）
加载    augenrules --load 合并加载；systemctl restart auditd 会自动加载
```

## 应用场景实战

### 场景一：监控敏感文件被访问/篡改

监控 `/etc/passwd`、`/etc/shadow` 等核心文件，任何写操作都留下记录，谁改的一目了然。

```shell
# 1. 加文件监视规则（读写 + 属性变更都记）
auditctl -w /etc/passwd -p wa -k identity
auditctl -w /etc/shadow -p wa -k identity

# 2. 模拟一次修改（测试规则是否生效）
useradd -m testuser       # 会写 /etc/passwd 和 /etc/shadow

# 3. 查询这次修改
ausearch -k identity -ts recent
# 示例输出（关键字段）：
# type=SYSCALL ... syscall=open ... comm="useradd" exe="/usr/sbin/useradd"
# type=PATH ... name="/etc/passwd" ...
# 记录了进程 useradd、系统调用 open、目标路径 /etc/passwd

# 4. 汇总：哪些程序/用户改过 identity 文件
ausearch -k identity --format text | grep -E 'comm=|name=|uid='
```

```text
场景要点：-w 加 -p wa 覆盖"写 + 属性变更"，-k 打键便于成组检索
记录内容：进程名（comm）、程序路径（exe）、系统调用、目标路径（name）、用户（uid/auid）
```

### 场景二：审计用户登录与命令执行

记录「谁登录了」和「登录后执行了哪些命令」，用于合规审计和入侵溯源。

```shell
# 1. 记录所有 execve（命令执行）
auditctl -a always,exit -F arch=b64 -S execve -k cmd_log

# 2. 看登录事件
aureport -l
# 示例输出：
# Login Report
# =========================================
# # date time auid host term exe success event
# 1. 08/19/26 10:00:00 alice 192.168.1.50 ssh /usr/sbin/sshd yes 1001

# 3. 查某用户执行的命令（先拿 uid，再按 uid 查 execve）
ausearch -ua alice -k cmd_log --format text | grep -E 'exe=|comm=|proctitle='

# 4. 失败登录/认证失败汇总（抓爆破）
aureport --failed
ausearch -m USER_LOGIN -sv no      # 查登录失败记录
```

```text
场景要点：execve 记录"执行了什么"，USER_LOGIN 记录"谁登录"，--failed 抓失败/爆破
溯源路径：登录报表定位"谁从哪进来" → execve 记录定位"进来后干了什么"
```

## 性能与调优

```text
1. 规则越少越精准越好 —— 别 -S all 全量审计，高负载系统会产生海量记录拖慢系统、塞满磁盘
2. 只审计必需 —— 用 -F uid=/success= 过滤，缩小记录范围；文件监视只盯真正敏感的文件
3. backlog 调大 —— -b 8192 或更高，高并发下避免审计队列溢出丢事件（丢事件是审计事故）
4. flush 选 INCREMENTAL_ASYNC —— 每条 SYNC 落盘最安全但显著拖慢高频系统调用；默认 INCREMENTAL_ASYNC 是性能/安全平衡点
5. 日志轮转 + 集中 —— max_log_file/num_logs 控大小，配 rsyslog 转发到集中日志平台（13.2）
6. 监控审计自身开销 —— 用 aureport 看事件速率，必要时收敛规则，别让审计本身成为瓶颈
```

```text
调优原则：审计要"够用但不过量"。规则精准、backlog 充足、刷盘平衡、日志轮转，四件事都做到
```

## 安全与权限

```text
1. 审计日志防篡改 —— /var/log/audit/ 目录权限收紧（root:root），日志是取证核心证据，被改就没意义
2. -e 2 锁定规则 —— 生产启用不可变规则，防止入侵者 auditctl -D 清掉规则再作案
3. 日志外发 —— 本机日志可被入侵者删，配 rsyslog 实时转发到独立日志服务器（或只读介质）
4. 规则文件防篡改 —— /etc/audit/rules.d/ 属 root，改规则本身也会被审计（-w 监视该目录）
5. 权限分离 —— 只给审计管理员读审计日志的权限，普通用户无权限翻 audit.log
6. 审计失败即告警 —— -f 2（失败 panic）或 space_left_action 配告警，审计失效要能第一时间发现
```

## 故障排查

### auditd 起不来

```shell
# 1. 看服务状态与报错
systemctl status auditd
journalctl -u auditd -n 50

# 2. 常见原因：规则文件语法错误
auditctl -l                       # 看已加载规则是否报错
augenrules --check                # 检查 rules.d 规则语法（部分发行版支持）
cat /etc/audit/rules.d/audit.rules  # 人工检查规则拼写

# 3. 常见原因：auditd.conf 配置错误
# 检查 log_file 路径是否存在、磁盘是否满
df -h /var/log/audit
```

```text
auditd 起不来常见原因：
1. 规则文件语法错（arch= 写成 arch =、键名拼错）
2. auditd.conf 里 log_file 目录不存在 / 磁盘满
3. 内核审计子模块未启用（极少见，检查内核配置 CONFIG_AUDIT）
```

### 审计日志把磁盘写满

```shell
# 1. 确认磁盘占用
df -h /var/log/audit
du -sh /var/log/audit/*

# 2. 看谁在疯狂产生事件
aureport --summary           # 各类型事件数量汇总
ausearch -ts today --format text | head

# 3. 收敛规则（找到高产生量的规则，删掉或加过滤）
auditctl -l

# 4. 配轮转（auditd.conf）
# max_log_file = 8   num_logs = 5
```

```text
磁盘写满的根因通常是：规则太宽（如 -S all 或 -w / 根目录）+ 高频访问
解法：收敛规则 + 加 -F 过滤 + 配 max_log_file/num_logs 轮转 + 日志外发
```

### 审计记录丢失（backlog 溢出）

```shell
# 1. 看内核审计状态，backlog 是否溢出
auditctl -s
# 输出含 backlog=... backlog_wait_time=...，以及 lost 计数

# 2. 加大 backlog 队列
auditctl -b 16384
# 持久化：在 rules.d 文件里加 -b 16384
```

```text
backlog 溢出 = 审计子系统在高并发下丢事件，属于审计事故
解法：-b 调大队列 + 精简规则减少事件量 + flush 调成 INCREMENTAL_ASYNC
```

## 常见问题

```text
Q1: 审计和 syslog/journald 日志有什么区别？
A: 审计由内核在系统调用层直接产生，粒度到"进程 + 系统调用 + 文件路径 + 结果"，可定向监控特定文件/调用，且规则可锁定防篡改；syslog 是应用自己写的高层日志，依赖应用自觉、易被入侵者删除。两者互补。

Q2: auditctl 加的规则重启就没了？
A: auditctl 是运行时规则，重启丢失。持久化要写 /etc/audit/rules.d/*.rules，用 augenrules --load 合并加载，systemctl restart auditd 会自动加载合并后的 /etc/audit/audit.rules。

Q3: -e 2 锁定规则后想改规则怎么办？
A: -e 2 不可变，运行时无法改，必须重启系统（或重载审计子系统的特殊流程）后才能改规则文件。这是故意设计——防入侵者停掉审计。所以规则要提前想清楚再锁。

Q4: 为什么建议把审计日志转发到别的机器？
A: 本机日志可被入侵者删除/篡改，取证就不可信。实时转发到独立日志服务器（或只读介质）保证日志的完整性和不可抵赖性，是等保/合规的常见要求。

Q5: 审计会拖慢系统吗？怎么控制？
A: 规则太宽（全量系统调用审计）会显著拖慢高频操作。控制手段：规则精准、加 -F 过滤、flush 用 INCREMENTAL_ASYNC、backlog 调大。正常精准审计的开销可控制在个位数百分比。

Q6: ausearch 结果里一个事件怎么有好几条记录？
A: 一个审计事件（如一次 open）会生成多条 type 记录：SYSCALL（调用本身）+ PATH（路径）+ CWD（工作目录）+ PROCTITLE（命令行）等，共享同一个事件 ID。用 ausearch -a <event_id> 把同一事件的记录关联起来看。
```

## 面试题

```text
1. Linux 审计框架由哪些部分组成？
   答：内核审计子系统（系统调用钩子，按规则生成记录）+ 用户态 auditd 守护进程（接收并写 /var/log/audit/audit.log）+ 工具链 auditctl（管规则）/ausearch（查记录）/aureport（出报表）。

2. 审计规则有哪几类？
   答：控制规则（backlog、速率、-e 锁定不可变）、文件监视规则（-w path -p wa）、系统调用规则（-a always,exit -S syscall -F 过滤）。用 -k 打键便于分组检索。

3. 怎么审计"某个用户执行了哪些命令"？
   答：加规则 auditctl -a always,exit -F arch=b64 -S execve -k cmd_log，再 ausearch -ua <用户> -k cmd_log 查询，或 aureport -x 出命令执行报表。

4. 为什么要用 -e 2 锁定审计规则？
   答：防止入侵者用 auditctl -D 清空规则、停掉审计再作案。锁定后规则不可变，只有重启才能改，保证审计记录可信、不可抵赖。

5. audit.log 写满磁盘怎么办？
   答：事前配 max_log_file/num_logs 轮转 + 空间告警（space_left_action）；根因是规则太宽产生海量记录，收敛规则 + 加过滤；同时把日志转发到集中平台，避免单机堆积。

6. 审计记录丢失（backlog 溢出）说明什么？怎么处理？
   答：高并发下审计队列溢出导致丢事件，是审计事故。处理：-b 调大 backlog、精简规则、flush 调 INCREMENTAL_ASYNC，并监控审计状态（auditctl -s）。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 规则精准不贪多——只审计真正敏感的文件和系统调用，别 -S all 全量审计拖垮系统
2. 用 -k 给规则打语义化键名，ausearch -k 一键成组检索
3. 生产启用 -e 2 锁定规则，防入侵者停审计；规则想清楚再锁
4. 审计日志实时转发到独立日志服务器，保证取证可信、不可抵赖
5. 配好 max_log_file/num_logs 轮转 + 空间告警，别让审计日志写爆磁盘
6. 定期 aureport 出报表（登录/失败/命令/文件），异常登录和爆破要能及时发现并告警

### 踩坑记录

```text
坑 1：规则配成 -S all 全量审计，系统变慢、日志爆炸
结论：CPU 和 IO 飙升，audit.log 迅速写满磁盘。
原因：全量审计每个系统调用，高频操作（读文件等）产生海量记录。
解法：删掉宽泛规则，改精准规则 + -F 过滤（uid/arch/success），只审计必需项。

坑 2：auditctl 加了规则，重启后消失
结论：重启后审计规则没了，监控失效。
原因：auditctl 是运行时规则，未持久化到 /etc/audit/rules.d/。
解法：写 rules.d/*.rules + augenrules --load，重启自动加载。

坑 3：审计日志被入侵者删除，事后无法取证
结论：入侵发生后 audit.log 被清空，查不到入侵痕迹。
原因：日志只存本机，且未锁定规则/未限制日志访问权限。
解法：-e 2 锁定规则 + 日志实时外发到独立服务器 + 收紧 /var/log/audit 权限。

坑 4：backlog 默认太小，高并发下丢事件
结论：审计记录丢失，合规核查不通过。
原因：审计队列溢出，内核静默丢弃记录。
解法：-b 8192（或更高）加大队列，auditctl -s 监控 backlog 和 lost 计数。

坑 5：磁盘满触发 SUSPEND，审计静默停摆
结论：审计服务暂停而不自知，违规操作无人记录。
原因：disk_full_action=SUSPEND 时磁盘满会暂停审计，但没告警到位。
解法：space_left_action 配告警提前预警 + 日志轮转 + 外发，监控磁盘余量。

坑 6：只审计不分析，日志成了摆设
结论：记录了一大堆，但没人看，入侵发生了也不知道。
原因：没有把审计日志接入分析/告警，缺少定期报表。
解法：rsyslog 接入集中平台 + 告警规则（失败登录、敏感文件变更），定期 aureport 出报表。
```

## 概述

传统包格式（deb/rpm）和发行版绑定，同一个软件要为不同发行版各打一个包。通用包格式（Snap/Flatpak/AppImage）解决「一次打包、到处运行」——把软件和依赖一起打包，跨发行版通用。三者区别：Snap（Canonical 出品，Ubuntu 主推，沙盒+自动更新）、Flatpak（社区主导，桌面应用为主，沙盒）、AppImage（单文件、免安装、直接运行）。三者都自带依赖，解决「依赖地狱」。

```text
三种通用包格式：
1. Snap —— Canonical 出品，沙盒隔离 + 自动更新，Ubuntu 主推
2. Flatpak —— 社区主导，桌面应用为主，沙盒 + 运行时
3. AppImage —— 单文件、免安装、双击即运行，便携
共同点：自带依赖、跨发行版、解决依赖冲突
```

```text
# 实测（本机）
$ command -v snap
/usr/bin/snap
$ command -v flatpak || echo "flatpak 未安装"
flatpak 未安装
# Ubuntu 默认带 snap（snap 装的软件在 lsblk 里是一堆 loop 设备），flatpak 需单独装
```

## Snap

Snap 是 Canonical 的通用包格式：软件连同依赖打包成一个 snap，装在沙盒里、自动更新。Ubuntu 默认集成（snap 命令，Ubuntu 商店的软件很多是 snap）。snap 的安装会在 /dev 下产生 loop 设备（每个 snap 挂载成一个只读镜像），所以 `lsblk` 能看到一堆 loop。管理：`snap install/remove/list/refresh`。

```shell
snap install firefox          # 安装
snap list                     # 列出已装
snap refresh                  # 更新所有 snap
snap remove firefox           # 卸载
snap find nginx               # 搜索
```

```text
Snap 特点：
1. 沙盒 —— 隔离运行，安全性好，但权限受限（文件访问要授权）
2. 自动更新 —— 后台自动更新，无需手动管
3. loop 设备 —— 每个 snap 挂载成只读镜像，lsblk 看到一堆 loop
```

## Flatpak

Flatpak 是社区主导的通用包格式，主打桌面应用（GUI 软件），沙盒运行 + 共享运行时。Fedora 默认集成，其他发行版要装 flatpak 包。Flatpak 依赖「运行时」（runtime，基础库）和「沙盒」，应用从 Flathub 仓库安装。管理：`flatpak install/run/list/uninstall`。

```shell
# 安装 flatpak（Debian/Ubuntu）
apt install flatpak
flatpak remote-add --if-not-exists flathub https://flathub.org/repo/flathub.flatpakrepo
# 安装应用
flatpak install flathub org.gimp.GIMP
flatpak run org.gimp.GIMP
flatpak list
```

```text
Flatpak 特点：
1. 桌面应用为主 —— GUI 软件打包分发的主力
2. 运行时 runtime —— 共享基础库，减少重复
3. Flathub —— 官方应用仓库
```

## AppImage

AppImage 是最简单的通用格式：整个应用打包成一个文件，免安装、加执行权限直接运行、删文件即卸载。便携性强（适合 U 盘携带、临时用某软件），但没有沙盒、没有自动更新、没有集中管理。适合「下一个文件直接跑」的场景，不适合作为系统级软件分发方式。

```shell
# AppImage 用法：下载 → 加执行权限 → 直接运行
chmod +x ./App.AppImage
./App.AppImage
# 可选：集成到桌面
./App.AppImage --appimage-extract-and-run
```

```text
AppImage 特点：
1. 单文件 —— 一个 .AppImage 文件，免安装
2. 便携 —— 加执行权限直接跑，删文件即卸载
3. 局限 —— 无沙盒、无自动更新、无集中管理
```

## 应用场景实战

### 场景一：在 Ubuntu 上装一个商店应用（snap）

```shell
# 1. 搜索
snap find vlc
# 2. 安装
snap install vlc
# 3. 查看已装的 snap
snap list
# 4. 更新
snap refresh vlc
```

### 场景二：临时用某软件，下载 AppImage 直接跑

```shell
# 1. 下载 AppImage
curl -LO https://example.com/app.AppImage
# 2. 加执行权限
chmod +x app.AppImage
# 3. 直接运行（不污染系统）
./app.AppImage
# 4. 用完删文件即卸载
rm app.AppImage
```

## 最佳实践与踩坑记录

### 最佳实践

1. 通用包适合「跨发行版分发」和「隔离依赖」，但体积大、启动慢，别滥用
2. 服务器/命令行工具优先用系统包管理器（apt/dnf），别用 snap/flatpak
3. 桌面 GUI 应用用 Flatpak（Fedora）或 Snap（Ubuntu），生态成熟
4. 临时用某软件用 AppImage，免安装、用完即删
5. 通用包和系统包可能重复安装同名软件，注意别混着用

### 踩坑记录

```text
坑 1：snap 装的软件和系统包同名，命令执行的是 snap 版
结论：装了 snap 版 docker 和 apt 版 docker，命令行为不一致。
原因：snap 和 apt 的二进制可能都在 PATH 里，执行到哪个取决于顺序。
解法：同一软件只用一个来源装，检查 which 命令确认执行的是哪个。

坑 2：snap 软件的沙盒导致访问不到宿主机文件
结论：snap 装的编辑器打不开 /home 外的文件。
原因：snap 沙盒默认限制文件访问，只允许用户目录等特定路径。
解法：snap connect 授予接口权限，或改用非 snap 版。

坑 3：AppImage 报 FUSE 错误无法运行
结论：AppImage 报 dlopen libfuse.so.2 失败。
原因：AppImage 依赖 FUSE 挂载，系统没装 libfuse2。
解法：apt install libfuse2，或用 --appimage-extract 解包运行。

坑 4：Flatpak 应用启动慢、体积大
结论：Flatpak 装个软件要拉几百 MB 运行时，启动也慢。
原因：Flatpak 要下载共享 runtime + 应用本身，沙盒启动有开销。
解法：接受这个代价，或用系统包管理器装轻量替代。

坑 5：通用包导致 /var/lib 或磁盘被 snap 占满
结论：snap 装多了，磁盘被 snap 镜像占满。
原因：每个 snap 都挂载成 loop 镜像，旧版本还留着。
解法：snap list 看占用，snap remove 清理不用的，设 snap 自动清理旧版本。
```

## 概述

Red Hat 系（RHEL/CentOS Stream/Rocky/AlmaLinux/Fedora）用 rpm + dnf/yum 管理软件包。rpm 是底层工具（装/卸 .rpm 包，不处理依赖，对应 Debian 的 dpkg），yum 是老上层工具，dnf 是新一代上层工具（Fedora 22 起取代 yum，更快、依赖解析更好）。日常用 dnf（`dnf install/remove/update`），老系统（CentOS 7）用 yum。理解 rpm/dnf 的分工，和 Debian 的 dpkg/apt 完全对应。

```text
Red Hat 系包管理分层（对应 Debian 系）：
1. rpm —— 底层，直接装/卸 .rpm 包（对应 dpkg）
2. dnf/yum —— 上层，解析依赖、从仓库下载（对应 apt）
3. dnf 是新一代 —— 取代 yum，用 libsolv/hawkey 库，依赖解析更快更准
4. 仓库 —— /etc/yum.repos.d/*.repo 定义软件源
```

Red Hat 系的包管理核心概念和 Debian 系同构，只是换了一套名字：rpm 对应 dpkg、dnf 对应 apt、仓库（repo）对应软件源、.rpm 对应 .deb。此外 Red Hat 系有个 Debian 没有的概念——**模块流（Module Streams）**，RHEL 8+/CentOS 8+ 的 AppStream 仓库用 module 管理同一软件的不同版本流（如 nodejs:14 / nodejs:18 / nodejs:20），这是它区别于 Debian 系的最大特色。

## 核心概念

### rpm 底层工具

**是什么**：rpm 是 Red Hat 系的底层包管理工具，直接操作 .rpm 包和本地的 rpm 数据库（/var/lib/rpm），不处理依赖。

**为什么**：rpm 和 dpkg 一样，只负责「把包里的文件放到系统 + 记录到数据库」，不负责「缺依赖怎么办」。需要查「某个文件属于哪个包」「某包装了哪些文件」「校验包是否被篡改」时，rpm 是最快最直接的入口。

**怎么用**：`rpm -ivh 包.rpm`（安装，v=verbose、h=hash 进度）、`rpm -e`（卸载）、`rpm -qa`（查已装）、`rpm -ql`（查文件清单）、`rpm -qf`（反查归属）、`rpm -V`（校验文件完整性）。

**边界/易错点**：`rpm -ivh` 装本地包不处理依赖，缺依赖会直接报 failed dependencies，装完要用 dnf 补；`rpm -Uvh` 是升级（upgrade，装不上就当新装），`rpm -Fvh` 是只升级已装的（freshen，未装则跳过）；`rpm -qa` 要 grep 时注意别用 `rpm -qa | grep` 去匹配通配符，rpm 自己支持 `rpm -qa 'nginx*'` 通配。

```shell
# rpm 底层操作
rpm -ivh nginx.rpm          # 安装本地包（不处理依赖）
rpm -Uvh nginx.rpm          # 升级（未装则当新装）
rpm -Fvh nginx.rpm          # 只升级已装的（未装跳过）
rpm -e nginx                # 卸载
rpm -qa | grep nginx        # 查已装包
rpm -qa 'nginx*'            # 通配符查（rpm 原生支持，别用 grep）
rpm -ql nginx               # 包的文件清单
rpm -qf /usr/sbin/nginx     # 文件属于哪个包
rpm -qi nginx               # 包信息（版本/描述）
rpm -qc nginx               # 包的配置文件
rpm -V nginx                # 校验包文件是否被篡改（无输出=正常）
rpm -q --requires nginx     # 包依赖什么
rpm -q --provides nginx     # 包提供什么
```

```text
rpm 命令记忆：
-i 安装、-U 升级、-F 刷新（只升级已装）、-e 卸载
-q 查询 + a（全部）/ l（文件清单）/ f（归属）/ i（信息）/ c（配置）/ requires（依赖）
-v verbose、-h hash 进度条（组合成 -ivh）
-V 校验（verification），输出 5 个位置标记表示文件被改过
```

### yum 与 dnf 上层工具

**是什么**：三代工具：rpm 是底层，yum 是老上层（CentOS 7 及更早默认），dnf 是新上层（Fedora 22+、CentOS 8+ 默认，命令和 yum 基本兼容）。

**为什么**：dnf 相比 yum 的优势：依赖解析更快（libsolv 求解器）、内存占用低、支持更丰富的仓库操作。RHEL 8+/CentOS 8+ 已默认 dnf（yum 命令仍然可用，是 dnf 的别名）。yum 的依赖解析用 Python 实现、慢且内存高，大规模仓库（EPEL + 多源）时差距明显。

**怎么用**：日常用 dnf 的子命令（install/remove/update/search/info），CentOS 7 用 yum（语法几乎一致）。dnf 的 `history`（事务历史 + 回滚）、`module`（模块流）、`repoquery`（仓库查询）是比 yum 强的地方。

**边界/易错点**：dnf 系统里 `yum` 是 `dnf` 的软链接/别名，两者命令互通但底层都是 dnf，别以为「yum 和 dnf 是两套独立状态」；dnf 的 `update` 和 `upgrade` 在 dnf 里是等价的（upgrade 是 update 的别名），和 apt 的「update=刷索引、upgrade=升级」语义完全不同，别按 Debian 习惯理解。

```text
三代工具分工：
1. rpm —— 底层，装/卸 .rpm，不处理依赖（rpm -ivh/-e/-qa/-ql/-qf）
2. yum —— 老上层，CentOS 7 默认，自动解析依赖
3. dnf —— 新上层，Fedora 22+/CentOS 8+ 默认，yum 的现代化重写
```

```shell
# dnf/yum 上层操作（语法基本一致，CentOS 7 把 dnf 换成 yum）
dnf install nginx          # 安装
dnf remove nginx           # 卸载
dnf update                 # 升级所有包（注意：不是刷索引）
dnf makecache              # 刷新仓库缓存（对应 apt update）
dnf search nginx           # 搜索
dnf info nginx             # 详情
```

### 仓库管理

**是什么**：Red Hat 系的软件源叫「仓库」（repo），配置在 /etc/yum.repos.d/*.repo（INI 格式），每个 repo 定义名字、baseurl（或 mirrorlist）、enabled（是否启用）、gpgcheck（是否校验签名）。

**为什么**：和 apt 的 sources.list 一样，dnf 靠 repo 里的元数据（repodata/）知道有哪些包。管理仓库 = 决定「从哪下载、信任哪些源、装哪些组件」。BaseOS（基础系统）、AppStream（应用流）、EPEL（社区额外包）是 RHEL 系最常用的几个仓库。

**怎么用**：`dnf repolist`（列启用的仓库）、`dnf repolist all`（含禁用）、`dnf config-manager --add-repo <url>`（加仓库）、`--set-enabled/--set-disabled`（启停）、`dnf makecache`（刷新元数据缓存）。

**边界/易错点**：baseurl 和 mirrorlist 二选一，别同时写（mirrorlist 是镜像列表 URL，baseurl 是固定地址）；国内镜像通常把 mirrorlist 注释掉、改用固定 baseurl 指向阿里云/清华；`enabled=0` 的仓库不会参与解析，装包前确认目标仓库已启用；EPEL 是 Fedora 社区维护、兼容 RHEL，但要和系统版本匹配（epel-release 装对应版本）。

```text
.repo 文件字段：
[name]   仓库标识（唯一，dnf repolist 显示的名字）
name=    人类可读的描述
baseurl  仓库地址（固定 URL）—— 和 mirrorlist 二选一
mirrorlist 镜像列表 URL（自动选镜像）
enabled  是否启用（1/0）
gpgcheck 是否校验签名（1/0）
gpgkey   签名公钥路径（file:// 或 https://）
```

```shell
dnf repolist                  # 列出所有启用的仓库
dnf repolist all              # 含禁用的仓库
dnf repolist -v               # 详细（含 baseurl、包数量）
dnf config-manager --add-repo <url>     # 添加仓库
dnf config-manager --set-enabled epel   # 启用某仓库
dnf config-manager --set-disabled epel  # 禁用某仓库
dnf makecache                 # 刷新仓库缓存（对应 apt update）
```

## 工作原理

dnf 的依赖解析原理：.rpm 包的依赖关系（Requires/Provides）由 dnf 用 libsolv（SAT 求解器）计算，比 yum 的 Python 实现更快更准。dnf 维护一个事务（transaction）——安装/升级/卸载都记录成事务，可回滚（dnf history undo）。仓库元数据（repodata）缓存在本地（/var/cache/dnf），makecache 刷新。

```text
dnf 工作原理：
1. libsolv 求解器 —— 解析 .rpm 的 Requires/Provides，算出完整安装集合
2. 事务 —— dnf 每步操作记成事务，dnf history undo 可回滚
3. repodata 缓存 —— 仓库元数据缓存 /var/cache/dnf，makecache 刷新
4. 比 yum 快 —— libsolv 是 C 实现，yum 是 Python 实现
```

完整执行链：`dnf makecache` 从各 repo 下载元数据（repodata/*.xml，含包名、版本、依赖、文件列表）缓存到本地 → `dnf install pkg` 用 libsolv 在缓存元数据里解依赖 → 下载 .rpm 到缓存 → 调用 rpm 安装 → 记录一条事务。libsolv 用 C 重写了 yum 的依赖解析核心（hawkey/libdnf 是它的封装），所以依赖解析快。dnf history 的每条事务记录「装了/卸了/升级了哪些包、从哪个版本到哪个版本」，`dnf history undo <ID>` 反向执行那次操作。

```text
dnf 执行链：
dnf makecache（下载 repodata 元数据）
  → libsolv 解 Requires/Provides 依赖
  → 下载 .rpm 到 /var/cache/dnf
  → rpm 安装 + 记录 history 事务
```

```text
rpm 依赖字段（对应 .deb 的依赖字段）：
Requires    本包依赖什么（对应 Depends）
Provides    本包提供什么能力（对应 Provides）
Conflicts   与谁互斥（对应 Conflicts）
Obsoletes   本包取代哪个包（升级换名时用，Debian 用 Replaces）
```

## 常用命令与配置

dnf 的日常操作和 apt 一一对应：`dnf install`（安装）、`dnf remove`（卸载）、`dnf update`（升级）、`dnf search`（搜索）、`dnf info`（详情）、`dnf history`（事务历史，可回滚）。区别记忆点：apt 用 update 刷新索引 + upgrade 升级，dnf 用 makecache 刷新 + update 升级（dnf 的 update 既是升级也是刷新）。卸载残留依赖用 `dnf autoremove`。

```shell
dnf makecache                # 刷新仓库缓存
dnf install nginx            # 安装
dnf update -y                # 升级所有包
dnf remove nginx             # 卸载
dnf search nginx             # 搜索
dnf info nginx               # 包详情
dnf autoremove               # 清理无用依赖
dnf history                  # 查看事务历史
dnf history undo <ID>        # 回滚某次事务
```

```shell
# dnf 进阶操作
dnf list installed           # 列出已装包
dnf list available           # 列出可装包
dnf list --upgrades          # 列出可升级包
dnf provides <文件或命令>    # 查某文件/命令由哪个包提供（对应 apt-file / dpkg -S）
dnf repoquery --requires nginx      # 查包依赖（对应 apt-cache depends）
dnf repoquery --whatprovides <cap>  # 反查哪个包提供某能力
dnf group list               # 软件组（如 "Development Tools"）
dnf group install "Development Tools"   # 组安装
dnf module list              # 模块流列表（RHEL 8+）
dnf module install nodejs:18 # 装指定模块流
dnf download nginx           # 只下载 .rpm 不安装（需 dnf-plugins-core）
dnf install --downloadonly nginx    # 只下载
```

```text
dnf vs apt 命令对照：
apt update          ↔  dnf makecache        # 刷新索引
apt install xxx     ↔  dnf install xxx      # 安装
apt remove xxx      ↔  dnf remove xxx       # 卸载
apt upgrade         ↔  dnf update           # 升级
apt-cache search    ↔  dnf search           # 搜索
apt-cache show      ↔  dnf info             # 详情
apt-cache depends   ↔  dnf repoquery --requires  # 依赖
dpkg -S 文件        ↔  dnf provides 文件    # 反查归属
apt autoremove      ↔  dnf autoremove       # 清理依赖
```

## 配置文件解析

Red Hat 系的软件源叫「仓库」（repo），配置在 /etc/yum.repos.d/*.repo 文件里（INI 格式）。每个 repo 定义：名字、baseurl（或 mirrorlist）、是否启用（enabled）、是否校验（gpgcheck）。常用仓库：BaseOS（基础系统）、AppStream（应用流）、EPEL（Extra Packages，社区维护的额外包）。全局配置在 /etc/dnf/dnf.conf。

```text
# /etc/yum.repos.d/xxx.repo 结构（示例）
[epel]
name=Extra Packages for Enterprise Linux
baseurl=https://mirrors.aliyun.com/epel/8/Everything/$basearch
enabled=1
gpgcheck=1
gpgkey=file:///etc/pki/rpm-gpg/RPM-GPG-KEY-EPEL-8
```

```shell
dnf repolist                  # 列出所有仓库
dnf repolist all              # 含禁用的仓库
dnf config-manager --add-repo <url>    # 添加仓库
dnf config-manager --set-enabled epel  # 启用某仓库
dnf makecache                 # 刷新仓库缓存（对应 apt update）
```

```text
.repo 文件字段：
[name]   仓库标识（唯一）
baseurl  仓库地址（或 mirrorlist 镜像列表）
enabled  是否启用（1/0）
gpgcheck 是否校验签名（1/0）
gpgkey   签名公钥路径
```

```text
.repo 里的变量：
$basearch   架构（x86_64/aarch64）
$releasever 系统版本（8/9）
$stream     CentOS Stream 的 stream 标识

# /etc/dnf/dnf.conf 全局配置
[main]
gpgcheck=1                  # 全局默认校验签名
installonly_limit=3         # 保留几个内核版本
max_parallel_downloads=10   # 并发下载数（dnf 支持）
fastestmirror=True          # 自动选最快镜像（老 yum 插件）
```

## 应用场景实战

### 场景一：CentOS 新机器初始化软件源 + 装基础工具

```shell
# 1. 换阿里云/清华镜像源（加快下载）
sed -i 's/mirrorlist/#mirrorlist/g' /etc/yum.repos.d/CentOS-*.repo
sed -i 's|#baseurl=http://mirror.centos.org|baseurl=http://mirrors.aliyun.com|g' /etc/yum.repos.d/CentOS-*.repo
# 2. 装 EPEL（额外包仓库）
dnf install -y epel-release
# 3. 刷新缓存 + 装基础工具
dnf makecache
dnf install -y vim curl wget htop git
```

### 场景二：用 dnf history 回滚一次误操作

```shell
# 1. 误装了某包，查历史
dnf history
# 2. 回滚那次安装
dnf history undo <上一步的ID>
# 3. 确认回滚结果
dnf history
```

### 场景三：查「某个命令/文件由哪个包提供」并安装（AppStream 模块流）

```shell
# 1. 某命令找不到，反查由哪个包提供
dnf provides */nginx        # 或 dnf provides /usr/sbin/nginx
# 2. 看该包在哪些模块流里（RHEL 8+ 用 module 管理多版本）
dnf module list | grep -i nodejs
# 3. 装指定版本的模块流
dnf module install nodejs:18
# 4. 只下载不安装（内网/离线分发）
dnf install --downloadonly --downloaddir=/tmp/rpms nginx
```

```text
module（模块流）概念：
AppStream 仓库用 module 管理同一软件的多版本流，如 nodejs:14/16/18/20
dnf module list 看所有模块流
dnf module install nodejs:18 装指定流（默认流 dnf install nodejs 即可）
这是 RHEL 8+ 区别于 Debian 系（apt 只有单一版本）的重要特性
```

## 性能与调优

dnf 的性能调优：换镜像源（国内阿里云/清华，下载快）、开 fastestmirror（自动选最快镜像）、清理缓存（dnf clean all）。dnf 本身比 yum 快（libsolv 求解器 C 实现、内存占用低），但仓库多时 makecache 仍会慢，可以精简不需要的仓库。

```text
dnf 性能要点：
1. 换镜像源 —— 国内用阿里云/清华镜像
2. fastestmirror —— 自动选最快镜像（老 yum 有，dnf 依赖缓存）
3. 清理缓存 —— dnf clean all 释放空间
4. 精简仓库 —— 别启用用不到的仓库，makecache 更快
```

```shell
# 并发下载（/etc/dnf/dnf.conf 的 [main] 段）
# max_parallel_downloads=10     # 提高下载并发
# 清理缓存
dnf clean all
# 只清理元数据缓存（保留已下载 rpm）
dnf clean metadata
```

## 安全与权限

Red Hat 系安全核心是「gpgcheck」：仓库默认 gpgcheck=1，用 gpgkey 校验包签名，防止包被篡改。加第三方源（如 EPEL）要导入对应公钥（rpm --import）。别为省事把 gpgcheck=0（关闭校验有供应链风险）。权限上 rpm/dnf 要 root。

```text
Red Hat 系安全要点：
1. gpgcheck=1 —— 校验包签名，防篡改
2. rpm --import —— 导入第三方源公钥（建立信任）
3. 别关 gpgcheck —— 关闭校验有供应链风险
4. 权限 —— rpm/dnf 要 root/sudo
```

```shell
# 导入第三方源公钥
rpm --import https://dl.fedoraproject.org/pub/epel/RPM-GPG-KEY-EPEL-8
# 查看已导入的公钥
rpm -qa gpg-pubkey*
# 校验某个已装包的文件完整性（被改过会输出标记）
rpm -V nginx
```

```text
rpm -V 输出解读（8 位标记 + 文件名）：
S 大小变、M 权限变、5 摘要变（内容被改）、L 符号链接变、
U 属主变、G 属组变、T mtime 变、P 能力变
输出为空 = 包文件完好；有标记 = 该文件被改动过（排查入侵/误改）
```

## 故障排查

### 仓库不可用（404 / 连接失败）

```shell
# 1. 看是哪个仓库的问题
dnf repolist -v
# 2. 测试仓库地址连通
curl -I <baseurl>
# 3. 换镜像源或禁用坏仓库
dnf config-manager --set-disabled <repo>
```

### 依赖冲突

```shell
# 1. 看具体冲突
dnf install <pkg>   # 报 conflicts
# 2. 用 --nobest 或跳过冲突包
dnf install --nobest <pkg>
# 3. 清理缓存重试
dnf clean all && dnf makecache
```

### 数据库损坏（rpmdb 报错 / 无法读写 rpm 数据库）

```shell
# 1. 重建 rpm 数据库
rpm --rebuilddb
# 2. 若数据库彻底损坏，备份后重建
mv /var/lib/rpm /var/lib/rpm.bak
rpm --initdb
rpm --rebuilddb
```

## 常见问题

```text
Q1: yum 和 dnf 用哪个？
A: CentOS 7 用 yum，CentOS 8+/RHEL 8+/Fedora 用 dnf（新、快）。dnf 系统里 yum 是 dnf 别名。

Q2: rpm 和 dnf 的分工？
A: rpm 底层装/卸 .rpm 不处理依赖，dnf 上层解析依赖、从仓库下载，对应 Debian 的 dpkg/apt。

Q3: 装本地 .rpm 包用什么？
A: 用 dnf install ./xxx.rpm（自动处理依赖），别用 rpm -ivh（不处理依赖）。

Q4: dnf update 和 upgrade 区别？
A: 在 dnf 里基本等价（dnf upgrade 是 update 的别名），都是升级所有包。

Q5: dnf makecache 是干什么的？
A: 下载各仓库的元数据（repodata）缓存到本地，对应 apt update。改了 .repo 后要 makecache 才生效。

Q6: 怎么查某个命令由哪个包提供？
A: dnf provides <命令或文件>（如 dnf provides */nginx），或 rpm -qf <已存在的文件路径>。

Q7: 怎么安装指定版本的包？
A: dnf install <包名>-<版本>（如 dnf install nginx-1.20.1），或用 dnf module install <模块>:<流> 装模块流的指定版本。

Q8: dnf 报 rpmdb 错误（无法读写 rpm 数据库）怎么办？
A: 先 rpm --rebuilddb 重建数据库，还不行就备份 /var/lib/rpm 后 rpm --initdb + --rebuilddb。
```

## 面试题

```text
1. rpm、yum、dnf 三者的关系？
   答：rpm 底层装/卸 .rpm 不处理依赖；yum 老上层（CentOS 7）；dnf 新上层（CentOS 8+，libsolv 求解器更快），yum 在 dnf 系统里是别名。

2. dnf 比 yum 快在哪？
   答：dnf 用 libsolv/hawkey（C 实现）做依赖解析，yum 是 Python 实现，dnf 更快、内存占用更低。

3. .repo 文件的 gpgcheck 作用？
   答：开启后校验包 GPG 签名，防止包被篡改，是供应链安全的关键配置。

4. dnf history 有什么用？
   答：记录每次事务（装/卸/升级），可以 dnf history undo <ID> 回滚误操作。

5. dnf update 和 apt update 语义一样吗？
   答：不一样。dnf update 是升级所有包（对应 apt upgrade），刷新索引在 dnf 里是 makecache（对应 apt update）。

6. rpm -ivh、-Uvh、-Fvh 的区别？
   答：-i 安装（已装会报错）、-U 升级（未装则当新装）、-F 刷新（只升级已装的，未装跳过）。

7. Red Hat 系的 AppStream 和 BaseOS 仓库分别放什么？
   答：BaseOS 放基础系统核心包，AppStream 放应用软件（并用 module 模块流管理多版本），EPEL 是社区维护的额外包仓库。

8. 如何查一个 .rpm 包依赖什么、提供什么？
   答：rpm -q --requires <包> 查依赖，rpm -q --provides <包> 查提供能力；dnf repoquery --requires <包> 也能查。
```

## 最佳实践与踩坑记录

### 最佳实践

1. CentOS 8+/RHEL 8+ 优先用 dnf（新、快），CentOS 7 用 yum
2. 装 EPEL 仓库获取官方源之外的常用软件（epel-release）
3. 国内服务器换阿里云/清华镜像源，下载快很多
4. 用 dnf history 做事务管理和回滚，误操作可撤销
5. rpm -ivh 装本地包不处理依赖，优先用 dnf install ./xxx.rpm
6. 用 dnf provides / dnf repoquery 查依赖和归属，别靠猜包名

### 踩坑记录

```text
坑 1：CentOS 7 上没有 dnf 命令
结论：CentOS 7 敲 dnf 报 command not found。
原因：dnf 是 Fedora 22+/CentOS 8+ 才默认，CentOS 7 用 yum。
解法：CentOS 7 用 yum，或先 yum install epel-release 再装 dnf。

坑 2：dnf 命令和 yum 混用导致元数据不一致
结论：一会儿 dnf 一会儿 yum，包状态混乱。
原因：两者维护各自的元数据缓存，混用可能冲突。
解法：选一个统一用（新系统用 dnf），别交替用。

坑 3：仓库没配 gpgcheck，装了被篡改的包
结论：仓库 gpgcheck=0，第三方包没验签名就装。
原因：关闭签名校验，包可能被中间人替换。
解法：保持 gpgcheck=1，并导入正确的 gpgkey。

坑 4：dnf update 升级了内核导致服务异常
结论：全量 update 后，内核/服务版本变化引发问题。
原因：update 会升级所有包，包括内核、关键库。
解法：生产环境按需升级（dnf update <包名>），内核升级单独做并保留回滚。

坑 5：dnf autoremove 误删依赖
结论：autoremove 删了还在用的库，程序报缺库。
原因：dnf 按依赖判断「不再需要」，判断可能不准。
解法：autoremove 前 --dry-run 预览，或 dnf autoremove --nobest。

坑 6：改了 .repo 后没 makecache，装包还是找不到
结论：加了新仓库或改了源，install 还是报 No match。
原因：没刷新仓库元数据缓存，dnf 不知道新仓库里有什么。
解法：dnf makecache 刷新缓存后再 install（对应 apt update）。

坑 7：把 baseurl 和 mirrorlist 同时写进 .repo
结论：仓库下载时行为异常或报错。
原因：baseurl（固定地址）和 mirrorlist（镜像列表）二选一，同时写会冲突。
解法：只保留一个——国内镜像通常注释掉 mirrorlist、写死 baseurl 指向镜像站。
```

## 概述

Linux 是多用户系统，用户和组是权限管理的基础。系统用四个文件存账号信息：/etc/passwd（用户基本信息）、/etc/shadow（密码哈希，仅 root 可读）、/etc/group（组信息）、/etc/gshadow（组密码）。管理命令是 useradd/usermod/userdel（用户）和 groupadd/groupmod/groupdel（组）。理解这四个文件的结构，才能看懂「用户怎么存、密码在哪、属于哪些组」。

```text
四个账号文件：
1. /etc/passwd —— 用户基本信息（用户名/UID/GID/家目录/shell），所有人可读
2. /etc/shadow —— 密码哈希与过期策略，仅 root 可读（安全）
3. /etc/group —— 组信息（组名/GID/组成员）
4. /etc/gshadow —— 组密码，仅 root 可读
```

## 核心概念

用户与组的核心概念围绕四个账号文件、用户管理命令、组管理命令展开，下面逐一说明。

### 四个账号文件

/etc/passwd 每行 7 个冒号分隔字段：`用户名:密码占位:UID:GID:描述:家目录:登录shell`。密码字段现在都是 x（占位），真实哈希移到 /etc/shadow 里（shadow = 更安全，因为 passwd 要对所有用户可读）。/etc/shadow 每行：`用户名:哈希:上次改密天数:最小天数:最大天数:警告天数:...`。UID 0 是 root，系统账号（daemon/bin）的 shell 是 /usr/sbin/nologin（禁止登录）。

```text
# /etc/passwd 字段拆解
root:x:0:0:root:/root:/bin/bash
│    │ │ │ │     │      └─ 登录 shell
│    │ │ │ │     └─ 家目录
│    │ │ │ └─ 描述（GECOS）
│    │ │ └─ 主组 GID
│    │ └─ UID（0=root）
│    └─ 密码占位（真实哈希在 shadow）
└─ 用户名
```

```text
# 实测（本机 /etc/passwd 前 3 行）
root:x:0:0:root:/root:/bin/bash
daemon:x:1:1:daemon:/usr/sbin:/usr/sbin/nologin
bin:x:2:2:bin:/bin:/usr/sbin/nologin
# root 的 shell 是 /bin/bash；daemon、bin 是系统账号，shell 是 nologin（禁止登录）
```

```text
# /etc/shadow 字段（哈希已脱敏）
root:$y$...（哈希）:20592:0:99999:7:::
# 20592 是「上次改密码距 1970 的天数」，99999 是密码最大有效天数
```

四个文件为什么要分开存：/etc/passwd 必须对所有人可读（ls、ps 等无数程序要把它当「用户名 ↔ UID」的映射表查），如果把密码哈希也放 passwd 里，等于把哈希公开给所有用户拿去离线爆破。/etc/shadow 独立成文件后，权限收紧到 600 或 000（仅 root 及带 SUID 的认证程序可读写），普通用户既看不到也改不了别人的哈希。/etc/group 与 /etc/gshadow 的关系同理：group 存组名/GID/成员（可读），gshadow 存组密码（通常用 ! 禁用，仅 root 可读）。

/etc/group 每行 4 字段：`组名:组密码占位:GID:成员列表`。/etc/gshadow 每行 4 字段：`组名:组密码:组管理员:成员列表`。组密码在现代发行版里基本废弃（用 gpasswd/sudo 管理组更安全），所以 group 的密码字段是 x、gshadow 的密码字段是 !。

```text
# /etc/group 字段拆解
dev:x:1002:alice,bob
│   │ │    └─ 成员列表（逗号分隔，这些是「附加组」成员）
│   │ └─ GID
│   └─ 组密码占位（真实在 gshadow）
└─ 组名

# /etc/gshadow 字段拆解
dev:!:alice:alice,bob
│   │ │      └─ 成员列表
│   │ └─ 组管理员（可代管成员，冒号分隔）
│   └─ 组密码（! = 未设置/禁用）
└─ 组名
```

边界与易错点：四个文件都是冒号分隔的定长字段，字段里不能出现冒号（用户名/组名规则）。**不要用编辑器直接改这四个文件**——useradd/usermod/gpasswd 会同时维护多个文件（改家目录还要建目录、拷 /etc/skel），手改一个文件会让 passwd 和 shadow、group 和 gshadow 失配。确实要手改时用 vipw / vigr（带锁，改完校验一致性）。

```text
四个账号文件速记：
passwd  7 字段：用户名:密码占位(x):UID:GID:GECOS:家目录:shell
shadow  9 字段：用户名:哈希:上次改密天数:最小天数:最大天数:警告天数:宽限:过期:保留
group   4 字段：组名:组密码占位(x):GID:成员列表
gshadow 4 字段：组名:组密码(!):组管理员:成员列表
```

### 用户管理命令

useradd 创建用户（-m 建家目录、-s 指定 shell、-g 主组、-G 附加组），usermod 修改（-aG 追加附加组、-l 改名、-L/-U 锁定/解锁），userdel 删除（-r 连家目录一起删）。创建用户后记得设密码（passwd 用户名），否则无法登录。查看用户身份用 id 命令。

```shell
useradd -m -s /bin/bash testuser    # 建用户 + 家目录 + bash
passwd testuser                      # 设密码
id testuser                          # 查看 uid/gid/组
usermod -aG sudo testuser            # 追加到 sudo 组
userdel -r testuser                  # 删除用户及家目录
```

```text
# 实测
$ useradd -m -s /bin/bash testuser
$ id testuser
uid=1001(testuser) gid=1001(testuser) 组=1001(testuser)
# 新用户 UID 从 1000 起自动分配，主组同名
```

useradd 的「默认行为」不是凭空来的，它读两个配置文件：/etc/default/useradd（-s 默认 shell、家目录基准路径、是否建家目录等）和 /etc/login.defs（UID_MIN/GID_MIN、密码策略、是否默认建家目录 CREATE_HOME）。所以同一个 useradd 命令在不同发行版/不同配置下行为可能不同——最典型的是「要不要 -m」：Red Hat 系默认建家目录，Debian/Ubuntu 的 useradd 默认**不**建家目录（Debian 上「建家目录 + 交互式设密码」的是 adduser 这个封装脚本）。写脚本时显式写 -m 别依赖默认。

常用选项一览：

```shell
useradd -m -s /bin/bash -g dev -G sudo alice   # 建用户 + 家目录 + 主组 dev + 附加组 sudo
useradd -u 2000 -d /opt/alice alice            # 指定 UID、家目录
useradd -c "Alice Wang" -e 2026-12-31 alice    # 描述 + 账号过期日期
useradd -M -s /usr/sbin/nologin appuser        # 不建家目录 + 禁登录（服务账号）
useradd -r appuser                             # 建系统账号（UID 落在 SYS_UID_MIN 区间）
useradd -k /etc/customskel -m alice            # 用自定义骨架目录建家目录
```

usermod 的易错点集中在 -g / -G / -aG 三个参数：-g 改**主组**（只有一个），-G 是「设置」附加组（覆盖原有），-aG 才是「追加」附加组。改主组时如果新主组不在用户附加组里，原来主组的权限会丢。另一个常见操作是「搬家家目录」：

```shell
usermod -d /home/newdir -m alice   # 改家目录并 -m 把旧目录内容搬过去
usermod -l newname oldname         # 改登录名（-l），家目录名要另用 -d -m 同步改
usermod -e 2026-12-31 alice        # 设账号过期日期
usermod -L / -U alice              # 锁定/解锁账号（shadow 哈希前加/去 !）
```

边界与易错点：userdel 默认只删账号不删家目录（残留孤儿文件）；userdel -r 会连家目录和 mail spool 一起删，但**不会**删用户在其他地方创建的文件——那些文件会变成无主文件（ls -l 显示 UID 数字），用 find -nouser 找。

### 组管理命令

组是把用户分类、批量授权的手段。groupadd 建组、groupmod 改组、groupdel 删组、gpasswd 管理组成员。用户有「主组」（/etc/passwd 里 GID 字段）和「附加组」（/etc/group 里列出）——主组一个，附加组可以有多个。usermod -aG 追加附加组时一定要加 -a，否则会覆盖原有的附加组。

```shell
groupadd dev                        # 建组
usermod -aG dev testuser            # 追加用户到 dev 组（-a 追加不覆盖）
id testuser                         # 验证组
groupdel dev                        # 删组
```

```text
# 实测（追加组后）
$ usermod -aG testgroup testuser
$ id testuser
uid=1001(testuser) gid=1001(testuser) 组=1001(testuser),1002(testgroup)
# 组字段变成了两个：主组 testuser + 附加组 testgroup
```

gpasswd 是管理组成员的专用命令，比直接改 /etc/group 安全（会同步 gshadow）：

```shell
gpasswd -a alice dev      # 把 alice 加入 dev 组（等价 usermod -aG dev alice）
gpasswd -d alice dev      # 把 alice 移出 dev 组
gpasswd -M alice,bob dev  # 一次性设置 dev 组成员列表（覆盖，非追加）
gpasswd -A alice dev      # 设 alice 为 dev 组管理员（可代管成员）
```

groupmod 改组属性：

```shell
groupmod -n develop dev   # 改组名 dev → develop
groupmod -g 2000 dev      # 改 GID
```

边界与易错点：groupdel 只能删「没有用户把它当主组」的组——如果某个用户的 /etc/passwd 主组 GID 指向这个组，groupdel 会报错拒绝删除，得先把这些用户的主组改掉。另外 -G 覆盖 vs -aG 追加是最高频的坑（见踩坑 1）。

## 工作原理

用户和组的工作原理是「登录时查 passwd 定位身份 → 认证时查 shadow 校验密码 → 授权时查 group 决定权限」三步：

1. **定位身份**：登录时内核把「登录名」映射到 UID（查 /etc/passwd），系统内部只认 UID 不认名字，进程携带 UID 运行。
2. **校验密码**：认证时拿 /etc/shadow 里的哈希比对，只有 root 或认证程序（passwd 带 SUID）能读写 shadow。
3. **决定权限**：进程的「主组 + 附加组」决定它能访问哪些文件。/etc/group 把 GID 映射到组名和成员列表，附加组由 /etc/group 的成员字段决定。

```text
登录流程：用户名 → 查 passwd 得 UID/GID → 查 shadow 校验密码 → 进程携带 UID/GID 运行 → 权限按 UID/组判定
关键点：系统只认 UID/GID（数字），passwd/group 只是「名字 ↔ 数字」的映射表
```

「查 passwd/shadow」这个动作在用户态是由 glibc 的 NSS（Name Service Switch）完成的，不是直接 read 文件。NSS 让账号来源可插拔：/etc/nsswitch.conf 里 `passwd: files systemd` 表示「先查本地 /etc/passwd，再查 systemd 的动态用户」；改成 `passwd: files ldap` 就能接 LDAP 集中认证。getent 命令走的就是 NSS，所以「本地文件里没有、但 getent 能查到」通常是 NSS 配了 ldap/sssd 后端。

```text
NSS 分工（账号查询） vs PAM 分工（认证决策）：
NSS（/etc/nsswitch.conf）—— getpwnam/getgrnam 查「用户/组是谁」，来源可插拔（files/ldap/sssd/systemd）
PAM（/etc/pam.d/*）—— 认证「密码对不对、会话怎么开」，详见 05.5
两者独立：NSS 负责查询，PAM 负责认证，登录时先 NSS 查到账号再 PAM 校验密码
```

## 常用命令与配置

用户与组管理的常用命令一览：

```shell
# 用户
useradd -m -s /bin/bash alice      # 建用户（家目录 + bash）
passwd alice                        # 设/改密码
usermod -aG wheel alice             # 追加附加组
usermod -L alice                    # 锁定账号（shadow 哈希前加 !）
usermod -U alice                    # 解锁
userdel -r alice                    # 删除用户 + 家目录

# 组
groupadd dev                        # 建组
groupmod -n develop dev             # 改组名 dev → develop
gpasswd -a alice dev                # 把 alice 加入 dev 组
gpasswd -d alice dev                # 把 alice 移出 dev 组
groupdel dev                        # 删组

# 查看
id alice                            # 看 uid/gid/所属组
whoami                              # 当前用户名
groups alice                        # 列出 alice 的所有组
getent passwd alice                 # 查 passwd（含 LDAP 等 nss 源）
getent group dev                    # 查 group
```

```text
命令归类：
- 建/改/删用户：useradd / usermod / userdel
- 建/改/删组：groupadd / groupmod / groupdel
- 密码与账号状态：passwd / chage（过期策略）/ usermod -L/-U（锁定）
- 查询：id / whoami / groups / getent
```

密码与账号状态是独立的一组，运维常用：

```shell
passwd -S alice            # 查账号状态（P=正常 L=锁定 NP=无密码）
passwd -l / -u alice       # 锁定/解锁（等价 usermod -L/-U）
passwd -e alice            # 强制下次登录改密码（shadow 上次改密天数清零）
passwd -d alice            # 删除密码（变空密码，慎用）

chage -l alice             # 查密码过期策略详情
chage -M 90 -W 7 -I 14 alice   # 密码 90 天过期、提前 7 天警告、过期后 14 天宽限
chage -E 2026-12-31 alice      # 账号到期日期
useradd -D                 # 查看 useradd 默认值（来自 /etc/default/useradd）
```

## 配置文件解析

用户与组相关的真实配置文件：

```text
/etc/passwd（7 字段，冒号分隔）：
用户名 : 密码占位(x) : UID : GID : 描述(GECOS) : 家目录 : 登录shell
root   : x           : 0   : 0   : root       : /root   : /bin/bash

/etc/shadow（9 字段，冒号分隔）：
用户名 : 哈希 : 上次改密天数 : 最小天数 : 最大天数 : 警告天数 : 宽限 : 过期 : 保留
哈希为 ! 或 * 表示账号被锁定（未设密码或已 -L）

/etc/group（4 字段，冒号分隔）：
组名 : 组密码占位(x) : GID : 成员列表(逗号分隔)
dev  : x            : 1002: alice,bob

/etc/login.defs 关键字段：
UID_MIN 1000      # 普通用户 UID 起点（<1000 留给系统账号）
GID_MIN 1000
CREATE_HOME yes   # useradd 默认建家目录
UMASK 022         # 新建文件默认权限掩码
PASS_MAX_DAYS 99999  # 密码最大有效天数
```

```shell
# 查看字段
getent passwd root     # 输出 passwd 一行
getent group dev       # 输出 group 一行
grep -E '^(UID_MIN|GID_MIN|UMASK|CREATE_HOME)' /etc/login.defs
```

除 login.defs 外，useradd 的默认行为还来自 /etc/default/useradd，家目录初始内容来自 /etc/skel：

```text
/etc/default/useradd 关键字段：
GROUP=100       # 默认主组（有的发行版用「用户私有组」UPG，值会不同）
HOME=/home      # 家目录基准路径
SHELL=/bin/sh   # 默认 shell
INACTIVE=-1     # 密码过期后宽限天数（-1=不锁定）
EXPIRE=         # 账号默认到期日期（空=永不过期）
SKEL=/etc/skel  # 家目录骨架（useradd -m 时拷贝其中内容）

/etc/skel —— 新建用户家目录的模板目录：
放进去的文件（.bashrc/.profile/README 等）在 useradd -m 时自动拷到每个新用户家目录
适合给全公司新员工统一预置初始化脚本、欢迎文件
```

```shell
# 查看 useradd 默认值
useradd -D
# 查看家目录骨架内容
ls -la /etc/skel
```

## 应用场景实战

### 场景一：给新入职同事建账号并分配权限

```shell
# 建用户 + 设密码 + 加入开发组 + 授权 sudo
useradd -m -s /bin/bash zhangsan
passwd zhangsan
groupadd dev
usermod -aG dev zhangsan
usermod -aG sudo zhangsan       # 需要提权时
id zhangsan
```

### 场景二：排查「为什么这个用户登录不了」

```shell
# 1. 看用户是否存在、shell 是否被禁
grep '^用户名' /etc/passwd
# 2. 看密码是否锁定（shadow 里哈希前有 ! 就是锁定）
grep '^用户名' /etc/shadow
# 3. 看账号是否过期
chage -l 用户名
```

### 场景三：批量创建账号并统一设初始密码与过期策略

入职一批人时逐个 useradd 效率低且易漏，写个小脚本批量建、统一设密码策略：

```shell
# 用户名清单放文件里，每行一个
cat users.txt
# alice
# bob
# carol

while read -r user; do
  useradd -m -s /bin/bash -g dev "$user"
  echo "InitP@ss-2026" | passwd --stdin "$user"   # Red Hat 系；Debian 系用 chpasswd
  chage -d 0 "$user"                               # 强制首次登录改密码
done < users.txt

# 验证
for user in alice bob carol; do id "$user"; done
```

```shell
# Debian/Ubuntu 的 passwd 没有 --stdin，用 chpasswd 批量设密码
cat users.txt | while read -r user; do
  echo "$user:InitP@ss-2026" | chpasswd
  chage -d 0 "$user"
done
```

## 性能与调优

用户与组本身开销很小，调优重点在「账号查询」和「批量操作」：

```text
1. 本地账号多时（几万+），getent/passwd 查询可走 nscd 缓存，减少反复读文件
2. 大量用户/组（LDAP 集中管理）走 sssd/nslcd 缓存，避免每次认证都打后端
3. usermod -aG 批量加组时，注意 /etc/group 成员字段别超行长度上限
4. 定期清理僵尸账号（离职员工），减少账号表膨胀和无主文件（find -nouser）
5. chage 批量设过期策略用脚本循环，别逐个手工敲
```

## 安全与权限

```text
1. 四个账号文件权限：/etc/passwd 644、/etc/group 644，/etc/shadow 和 /etc/gshadow 必须 600 或 000（仅 root 可读）
2. 系统账号 shell 用 /usr/sbin/nologin，禁止直接登录，只跑服务
3. 禁用 root 直接 SSH 登录（PermitRootLogin no），提权走 sudo
4. 密码哈希存 shadow 而不是 passwd——passwd 必须所有人可读，哈希放这里等于泄露
5. 定期审计异常账号：awk -F: '$3==0 {print}' /etc/passwd 查 UID=0 的账号（正常只应有 root）
6. 空密码或哈希为空的账号及时处理，passwd -d 删密码要慎用
7. 用户家目录权限默认别给 777——家目录可被别人读写，等于把 .ssh/.bashrc 都暴露出去
8. 用 PAM 密码策略（pam_pwquality）强制复杂度，配合 chage 设过期，别只靠「口头要求强密码」
```

## 故障排查

```shell
# 1. 用户登录不了：先看账号状态
grep '^用户名' /etc/passwd /etc/shadow     # 是否存在、哈希前有没有 !
chage -l 用户名                            # 看过期/改密策略

# 2. 用户权限不对：看组
id 用户名                                  # 主组 + 附加组
groups 用户名

# 3. 新加的组不生效（当前 shell 还认旧组）
# 重新登录，或临时用 newgrp 切组
newgrp dev

# 4. 找不到用户但 getent 能查到：NSS 顺序问题
grep -E '^(passwd|group):' /etc/nsswitch.conf   # files 应在前面
```

```shell
# 5. useradd 建的用户没有家目录
ls -ld /home/用户名        # 目录不存在 → 建时没加 -m
mkhomedir_helper 用户名     # 补建家目录（或 useradd -m 重来）

# 6. 删用户后出现无主文件（ls -l 显示 UID 数字而非名字）
find / -xdev -nouser 2>/dev/null    # 全盘找无主文件
```

## 常见问题

```text
Q1: 为什么 /etc/passwd 的密码字段都是 x？
A: 真实密码哈希已移到 /etc/shadow（仅 root 可读），passwd 里的 x 是占位符——因为 passwd 必须对所有人可读，哈希放这等于公开。

Q2: 主组和附加组的区别？
A: 主组一个（passwd 的 GID 字段，新建文件的默认属组），附加组可多个（/etc/group 成员列表，决定额外访问权限）。

Q3: usermod -G 和 -aG 的区别？
A: -G 是「设置」附加组（覆盖原有），-aG 是「追加」（保留原有）。追加组必须用 -aG，否则丢组。

Q4: 删除用户后为什么还有他的文件？
A: userdel 默认只删账号不删家目录，文件属主会变成无主（显示 UID 数字）。用 userdel -r 连家目录删，或用 find -nouser 找残留文件。

Q5: 锁定账号（usermod -L）和删除账号（userdel）区别？
A: -L 只是给 shadow 哈希前加 ! 禁用登录，账号和数据都在，可 -U 解锁恢复；userdel 才是真正删除。

Q6: useradd 和 adduser 有什么区别？
A: useradd 是底层命令，行为由 /etc/default/useradd 和 /etc/login.defs 决定；adduser 是发行版（Debian/Ubuntu）提供的封装脚本，会交互式建家目录、设密码、填 GECOS。脚本里用 useradd，手动操作用 adduser 更省事。

Q7: 新加用户进组后，为什么当前终端还是看不到新组？
A: 当前 shell 的组信息在登录时已固化，usermod -aG 改了 /etc/group 但已运行的 shell 不重新加载。重新登录生效，或临时 newgrp 组名 切换。
```

## 面试题

```text
1. /etc/passwd 和 /etc/shadow 各存什么？为什么分开？
   答：passwd 存用户名/UID/GID/家目录/shell（所有人可读），shadow 存密码哈希与过期策略（仅 root 可读）。分开是因为 passwd 必须可读，哈希放这里会泄露，shadow 用独立权限保护密码。

2. UID 0 是什么？如何排查异常的 UID 0 账号？
   答：UID 0 是 root，拥有最高权限。awk -F: '$3==0 {print}' /etc/passwd 列出所有 UID=0 账号，正常只应有 root。

3. usermod -aG 的 -a 起什么作用？
   答：-a 表示 append（追加），配合 -G 把用户追加到附加组；不加 -a 会覆盖原有附加组。

4. 新建用户的 UID 从多少开始？为什么系统账号 UID 都小？
   答：普通用户默认 UID_MIN=1000 起；<1000 留给系统服务账号（daemon/bin），避免和真实用户冲突。

5. 怎么查一个用户属于哪些组？
   答：id 用户名 或 groups 用户名，列出主组 + 所有附加组。

6. /etc/skel 是干什么的？
   答：新建用户家目录的骨架模板目录。useradd -m 时会把 /etc/skel 里的文件（.bashrc/.profile 等）拷到新用户家目录，用于统一预置初始化文件。

7. groupdel 删组时报「cannot remove the primary group」是什么原因？
   答：有用户把该组当主组（/etc/passwd 的 GID 字段指向它），groupdel 拒绝删除。先 usermod -g 新主组 把这些用户的主组改掉，再删。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 系统账号 shell 用 /usr/sbin/nologin，禁止直接登录，只跑服务
2. usermod -aG 追加附加组必须加 -a，否则覆盖原组导致权限丢失
3. 删用户前先确认没在跑进程、没占资源（ps -u 用户名），再 userdel
4. 密码设强密码并定期过期（chage），禁用 root 直接 SSH 登录
5. 生产环境用统一 UID/GID 规范（如 1000 起用户、特定范围服务账号）
6. 用 id/getent 确认账号结果，别手改 /etc/passwd 文件
7. 批量建账号用脚本 + chpasswd/chage，别逐个手工敲；初始密码强制首登修改

### 踩坑记录

```text
坑 1：usermod -G 没加 -a 覆盖了附加组
结论：usermod -G sudo user 把用户原有的 dev 组覆盖掉了。
原因：-G 是「设置」附加组（覆盖），-aG 才是「追加」。
解法：追加组永远用 -aG，改主组用 -g。

坑 2：userdel 不带 -r 留下孤儿家目录
结论：删了用户但 /home/用户名 还在，占空间且残留敏感文件。
原因：userdel 默认只删账号，不删家目录。
解法：确定要彻底删就用 userdel -r，或删前先备份家目录。

坑 3：改 /etc/passwd 直接用编辑器改错格式
结论：手改 passwd 字段错位，用户登录异常。
原因：passwd 是冒号分隔的固定 7 字段，手改易错。
解法：用 useradd/usermod/userdel 管理，别直接编辑；密码用 passwd 命令改。

坑 4：密码锁定了却以为删了用户
结论：usermod -L 锁定后用户登录不了，但账号还在。
原因：-L 只是给 shadow 哈希前加 ! 锁定，不是删除。
解法：区分「锁定」（-L/-U）和「删除」（userdel），锁定可解锁恢复。

坑 5：忘了给新用户设密码导致登录不了
结论：useradd 后直接 SSH 登录被拒。
原因：新用户密码字段是 !（锁定），没设密码无法认证。
解法：useradd 后必须 passwd 用户名 设密码，或 useradd -p 预置哈希。

坑 6：新加的组当前 shell 不生效
结论：usermod -aG 加了组，但 id 看不到新组。
原因：当前登录会话缓存了旧的组信息，重新登录才生效。
解法：重新登录，或临时 newgrp dev 切换；写脚本判组时用 getent group 确认。

坑 7：Debian 系 useradd 没加 -m，用户登录后没有家目录
结论：Ubuntu/Debian 上 useradd alice 后 SSH 登录报「Could not chdir to home directory」。
原因：Debian 系 useradd 默认不建家目录（CREATE_HOME 未设或为 no），Red Hat 系才默认建。
解法：建用户显式加 -m；已建的可 mkhomedir_helper 用户名 补建，或 useradd -m -d /home/用户名 重建。
```

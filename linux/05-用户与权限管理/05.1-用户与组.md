## 概述

Linux 是多用户系统，用户和组是权限管理的基础。系统用四个文件存账号信息：/etc/passwd（用户基本信息）、/etc/shadow（密码哈希，仅 root 可读）、/etc/group（组信息）、/etc/gshadow（组密码）。管理命令是 useradd/usermod/userdel（用户）和 groupadd/groupmod/groupdel（组）。理解这四个文件的结构，才能看懂「用户怎么存、密码在哪、属于哪些组」。

```text
四个账号文件：
1. /etc/passwd —— 用户基本信息（用户名/UID/GID/家目录/shell），所有人可读
2. /etc/shadow —— 密码哈希与过期策略，仅 root 可读（安全）
3. /etc/group —— 组信息（组名/GID/组成员）
4. /etc/gshadow —— 组密码，仅 root 可读
```

## 四个账号文件

/etc/passwd 每行 7 个冒号分隔字段：`用户名:密码占位:UID:GID:描述:家目录:登录shell`。密码字段现在都是 x（占位），真实哈希移到 /etc/shadow 里（shadow = 更安全，因为 passwd 要对所有用户可读）。/etc/shadow 每行：`用户名:哈希:上次改密天数:最小天数:最大天数:警告天数:...`。UID 0 是 root，系统账号（daemon/bin）的 shell 是 /usr/sbin/nologin（禁止登录）。

```text
# /etc/passwd 字段拆解
root:x:0:0:root:/root:/bin/bash
│    │ │ │ │     │      └─ 登录 shell
│    │ │ │ │     └─ 家目录
│    │ │ │ └─ 描述（GECOS）
│    │ │ └─ 主组 GID
│    │ └─ UID（0=root）
│    └─ 密码占位（真实哈希在 shadow）
└─ 用户名
```

```text
# 实测（本机 /etc/passwd 前 3 行）
root:x:0:0:root:/root:/bin/bash
daemon:x:1:1:daemon:/usr/sbin:/usr/sbin/nologin
bin:x:2:2:bin:/bin:/usr/sbin/nologin
# root 的 shell 是 /bin/bash；daemon、bin 是系统账号，shell 是 nologin（禁止登录）
```

```text
# /etc/shadow 字段（哈希已脱敏）
root:$y$...（哈希）:20592:0:99999:7:::
# 20592 是「上次改密码距 1970 的天数」，99999 是密码最大有效天数
```

## 用户管理命令

useradd 创建用户（-m 建家目录、-s 指定 shell、-g 主组、-G 附加组），usermod 修改（-aG 追加附加组、-l 改名、-L/-U 锁定/解锁），userdel 删除（-r 连家目录一起删）。创建用户后记得设密码（passwd 用户名），否则无法登录。查看用户身份用 id 命令。

```shell
useradd -m -s /bin/bash testuser    # 建用户 + 家目录 + bash
passwd testuser                      # 设密码
id testuser                          # 查看 uid/gid/组
usermod -aG sudo testuser            # 追加到 sudo 组
userdel -r testuser                  # 删除用户及家目录
```

```text
# 实测
$ useradd -m -s /bin/bash testuser
$ id testuser
uid=1001(testuser) gid=1001(testuser) 组=1001(testuser)
# 新用户 UID 从 1000 起自动分配，主组同名
```

## 组管理命令

组是把用户分类、批量授权的手段。groupadd 建组、groupmod 改组、groupdel 删组、gpasswd 管理组成员。用户有「主组」（/etc/passwd 里 GID 字段）和「附加组」（/etc/group 里列出）——主组一个，附加组可以有多个。usermod -aG 追加附加组时一定要加 -a，否则会覆盖原有的附加组。

```shell
groupadd dev                        # 建组
usermod -aG dev testuser            # 追加用户到 dev 组（-a 追加不覆盖）
id testuser                         # 验证组
groupdel dev                        # 删组
```

```text
# 实测（追加组后）
$ usermod -aG testgroup testuser
$ id testuser
uid=1001(testuser) gid=1001(testuser) 组=1001(testuser),1002(testgroup)
# 组字段变成了两个：主组 testuser + 附加组 testgroup
```

## 应用场景实战

### 场景一：给新入职同事建账号并分配权限

```shell
# 建用户 + 设密码 + 加入开发组 + 授权 sudo
useradd -m -s /bin/bash zhangsan
passwd zhangsan
groupadd dev
usermod -aG dev zhangsan
usermod -aG sudo zhangsan       # 需要提权时
id zhangsan
```

### 场景二：排查「为什么这个用户登录不了」

```shell
# 1. 看用户是否存在、shell 是否被禁
grep '^用户名' /etc/passwd
# 2. 看密码是否锁定（shadow 里哈希前有 ! 就是锁定）
grep '^用户名' /etc/shadow
# 3. 看账号是否过期
chage -l 用户名
```

## 最佳实践与踩坑记录

### 最佳实践

1. 系统账号 shell 用 /usr/sbin/nologin，禁止直接登录，只跑服务
2. usermod -aG 追加附加组必须加 -a，否则覆盖原组导致权限丢失
3. 删用户前先确认没在跑进程、没占资源（ps -u 用户名），再 userdel
4. 密码设强密码并定期过期（chage），禁用 root 直接 SSH 登录
5. 生产环境用统一 UID/GID 规范（如 1000 起用户、特定范围服务账号）

### 踩坑记录

```text
坑 1：usermod -G 没加 -a 覆盖了附加组
结论：usermod -G sudo user 把用户原有的 dev 组覆盖掉了。
原因：-G 是「设置」附加组（覆盖），-aG 才是「追加」。
解法：追加组永远用 -aG，改主组用 -g。

坑 2：userdel 不带 -r 留下孤儿家目录
结论：删了用户但 /home/用户名 还在，占空间且残留敏感文件。
原因：userdel 默认只删账号，不删家目录。
解法：确定要彻底删就用 userdel -r，或删前先备份家目录。

坑 3：改 /etc/passwd 直接用编辑器改错格式
结论：手改 passwd 字段错位，用户登录异常。
原因：passwd 是冒号分隔的固定 7 字段，手改易错。
解法：用 useradd/usermod/userdel 管理，别直接编辑；密码用 passwd 命令改。

坑 4：密码锁定了却以为删了用户
结论：usermod -L 锁定后用户登录不了，但账号还在。
原因：-L 只是给 shadow 哈希前加 ! 锁定，不是删除。
解法：区分「锁定」（-L/-U）和「删除」（userdel），锁定可解锁恢复。

坑 5：忘了给新用户设密码导致登录不了
结论：useradd 后直接 SSH 登录被拒。
原因：新用户密码字段是 !（锁定），没设密码无法认证。
解法：useradd 后必须 passwd 用户名 设密码，或 useradd -p 预置哈希。
```

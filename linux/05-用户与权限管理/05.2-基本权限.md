## 概述

Linux 用 rwx 三元组控制文件访问：r 读、w 写、x 执行，分别作用于「属主（owner）、属组（group）、其他人（others）」三类。改权限用 chmod，改属主属组用 chown/chgrp，默认权限由 umask 决定。权限是 Linux 安全的第一道门，理解「谁（owner/group/others）能对文件做什么（rwx）」是运维基本功。

```text
权限模型：
1. 三元组 —— rwx 分别 = 读/写/执行，数字 4/2/1 表示
2. 三类主体 —— 属主 owner、属组 group、其他人 others
3. 修改 —— chmod 改权限、chown 改属主、chgrp 改属组
4. 默认 —— umask 决定新建文件的默认权限
```

## 核心概念

基本权限围绕 rwx 权限、chmod、chown/chgrp、umask 四个概念展开，下面逐一说明。

### rwx 权限

每个文件三组 rwx 权限，对应属主/属组/其他人。rwx 对文件和目录含义不同：文件的 r=读内容、w=改内容、x=执行；目录的 r=列目录、w=增删文件、x=进入目录。数字表示：r=4、w=2、x=1，权限数字是三者相加（如 rwx=7、rw=6、r-x=5）。`ls -l` 输出的 `-rw-r--r--` 就是三组 rwx。

```text
rwx 对文件/目录的含义：
1. 文件 —— r 读内容 / w 改内容 / x 执行
2. 目录 —— r 列目录项 / w 增删目录内文件 / x 进入目录
3. 数字 —— r=4 w=2 x=1，权限 = 三者相加（755 = rwxr-xr-x）
```

```text
# 实测
$ ls -l /etc/hostname
-rw-r--r-- 1 root root 15  5月 17 11:29 /etc/hostname
# 拆解：-（普通文件） rw-（属主可读写） r--（属组可读） r--（其他人可读）
```

### chmod 修改权限

chmod 改权限，支持两种写法：数字法（chmod 755）和符号法（chmod u+x、chmod g-w、chmod o=r）。数字法一次性设全三组，符号法只改指定主体的指定权限。常用：chmod 755（脚本可执行）、chmod 644（普通文件）、chmod 600（私密文件）。递归改目录用 -R。

```shell
chmod 755 script.sh        # 数字法：属主 rwx，组/其他 r-x
chmod u+x script.sh        # 符号法：给属主加执行
chmod 600 id_rsa           # 私钥：仅属主可读写
chmod -R 755 /var/www      # 递归改目录
```

### chown 与 chgrp

chown 改属主（可同时改属组，用 `属主:属组` 或 `属主.属组`），chgrp 只改属组。部署服务时经常要 chown 给运行用户（如 nginx 文件归 www-data、web 目录归部署用户），否则服务进程没权限读写自己的文件。改属主通常要 root 权限。

```shell
chown deploy:deploy app.jar          # 改属主和属组
chown -R www-data:www-data /var/www  # 递归改
chgrp dev /opt/shared                # 只改属组
```

### umask 与默认权限

umask 是「权限掩码」，决定新建文件/目录的默认权限：新文件默认 666 - umask，新目录默认 777 - umask。常见 umask 022（默认权限文件 644、目录 755）、002（共享组场景，文件 664）。所以新建文件默认没有 x 权限（执行位被 umask 剥掉），这是安全默认。当前 umask 用 `umask` 查看，`umask 022` 修改。

```shell
umask            # 查看当前 umask
umask 0022       # 设置为 022
```

```text
# 实测（本机默认）
$ umask
0022
# 所以新建文件默认 644（666-022）、新建目录默认 755（777-022）
```

## 工作原理

权限检查是内核在每次 open/read/write/exec 时按固定顺序做的：

1. **属主匹配**：进程的 euid（有效 UID）等于文件属主 → 用属主权限位（前三字符）。
2. **属组匹配**：进程属组（或附加组）等于文件属组 → 用属组权限位（中间三字符）。
3. **其他**：都不匹配 → 用其他人权限位（后三字符）。注意是「先命中谁用谁」，不会叠加——属主匹配后不再看属组。

umask 的工作原理：进程 open/creat 创建文件时，内核用 `mode & ~umask` 得到最终权限，即在调用方请求的权限上「剥掉」umask 里为 1 的位。所以 umask 只能减少权限、不能增加，且新文件默认不含执行位（open 的 mode 通常不含 x）。

```text
权限检查顺序（先命中即返回）：
euid == 属主 → 用 owner 位
否则（egid 或附加组 == 属组）→ 用 group 位
否则 → 用 other 位

umask：最终权限 = 请求权限 & ~umask（只减不增）
```

## 常用命令与配置

```shell
# 查权限
ls -l file                # 符号 + 属主/属组
stat file                 # 含八进制权限、属主 UID/GID

# 改权限
chmod 755 file            # 数字法
chmod u+x,g-w,o=r file    # 符号法（可逗号组合）
chmod -R 755 dir          # 递归

# 改属主/属组
chown user file
chown user:group file
chown -R user:group dir
chgrp group file

# 默认权限
umask                     # 查看
umask 022                 # 设置（当前 shell 生效）
```

```text
常用权限速记：
755 = rwxr-xr-x（可执行脚本/目录）
644 = rw-r--r--（普通文件）
600 = rw-------（私密文件：私钥/密码配置）
750 = rwxr-x---（属主可读写执行，同组可读执行，其他人无）
```

## 配置文件解析

权限的默认值和持久化配置：

```text
权限位表示（ls -l 十位 + 八进制）：
-rwxr-xr-x  →  0755
第 1 位类型：- 普通文件 / d 目录 / l 链接
后 9 位：三组 rwx，对应 owner/group/other

umask 配置位置（按登录方式生效）：
/etc/login.defs  UMASK 022   # useradd 新建用户家目录的默认 umask
/etc/profile      umask 022  # 交互式登录 shell 全局默认
/etc/bash.bashrc  umask 022  # 交互式非登录 shell（部分发行版）
~/.bashrc         umask 027  # 用户级覆盖，优先级最高
```

```shell
# 查看各配置里的 umask 设置
grep -i umask /etc/login.defs /etc/profile /etc/bash.bashrc
```

## 应用场景实战

### 场景一：部署 Web 服务并设置正确权限

```shell
# 网站文件归 www-data（nginx 运行用户），目录 755 文件 644
chown -R www-data:www-data /var/www/mysite
find /var/www/mysite -type d -exec chmod 755 {} \;
find /var/www/mysite -type f -exec chmod 644 {} \;
# 敏感配置只给属主
chmod 600 /var/www/mysite/.env
```

### 场景二：共享目录给团队协作

```shell
# 建共享目录，同组成员可读写
mkdir /opt/shared
chgrp dev /opt/shared
chmod 2775 /opt/shared        # 2775 含 SGID，组内新建文件自动归组
```

## 性能与调优

权限检查本身是内核常量时间操作，性能影响极小，调优重点在「递归操作」和「大量文件」：

```text
1. chmod -R / chown -R 递归改大目录会遍历所有 inode，用 find 按类型分治更可控
2. 大量文件批量改权限：find ... -exec chmod ... + 比 \; 少 fork 进程（一次处理多文件）
3. 权限检查不涉及磁盘 IO，无需为「权限」优化文件访问路径
4. 目录权限过宽（777）主要是安全隐患，性能影响可忽略
```

## 安全与权限

```text
1. 最小权限原则：能 644/755 就不 777，能 600 就不 644
2. 私钥/含密码配置一律 600，.ssh 目录 700
3. 服务进程别以 root 跑，文件 chown 给最小权限的运行用户
4. 目录 w 权限要警惕：有 w 就能增删文件，配合 sticky bit 防互删
5. 定期审计异常权限：find / -perm -4000（SUID）、find / -perm -0002（全局可写）
6. 敏感文件检查：find / -xdev -type f -perm -004（其他人可读的敏感文件）
```

## 故障排查

```shell
# 1. 权限不足：看属主/属组/权限
ls -l 文件

# 2. 我是属主但没权限？看 ACL 是否覆盖了基本权限
getfacl 文件

# 3. 目录进不去：目录缺 x 权限
ls -ld 目录            # 看目录本身的权限

# 4. 改了权限不生效：看挂载选项（noexec/nosuid/只读挂载）
mount | grep 挂载点

# 5. chmod 后还是不能执行：文件系统以 noexec 挂载，或脚本本身语法错误
bash -n 脚本           # 校验脚本语法
```

## 常见问题

```text
Q1: 目录 r 和 x 的区别？
A: r 只能列出目录里的文件名，x 才能进入目录、访问目录内文件。目录通常 r 和 x 成对给（755/750）。

Q2: chmod 755 的 755 是什么意思？
A: 八进制三组：7=属主 rwx，5=属组 r-x，5=其他人 r-x。数字是 r=4+w=2+x=1 相加。

Q3: chown 和 chgrp 区别？
A: chown 改属主（可同时改属组 user:group），chgrp 只改属组。改属主通常要 root。

Q4: 为什么新建文件总是没有执行权限？
A: 默认权限 = 666 - umask，umask 把执行位剥掉了（安全默认），所以新文件不会自动可执行。

Q5: umask 022 和 002 有什么区别？
A: 022 让新建文件 644（组/其他人不可写），002 让组可写（文件 664），适合共享组协作场景。
```

## 面试题

```text
1. rwx 对文件和目录分别代表什么？
   答：文件 r=读内容/w=改内容/x=执行；目录 r=列目录/w=增删文件/x=进入目录。

2. 权限检查的顺序？
   答：先看属主（euid==owner 用 owner 位），再看属组（egid/附加组==group 用 group 位），最后 others，先命中即返回、不叠加。

3. umask 是什么？为什么新建文件默认 644？
   答：umask 是权限掩码，新文件权限 = 666 - umask。umask 022 时 666-022=644，且执行位被剥掉。

4. chmod 644 和 chmod u=rw,go=r 等价吗？
   答：等价，都是属主 rw、属组 r、其他人 r。数字法一次设全，符号法可部分修改。

5. 目录没有 w 权限，但属主是它，能删目录里的文件吗？
   答：能。删文件看「目录的 w 权限」而非文件本身权限，属主有目录 w 就能删目录里的任意文件（除非目录有 sticky bit）。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 普通文件 644、可执行脚本 755、私密文件（密钥/密码）600，这是约定俗成的默认
2. 改权限用数字法一次设全，符号法只做增量修改
3. 部署服务时把文件 chown 给运行用户，别让服务以 root 跑
4. 敏感文件（私钥、含密码配置）一律 600，别 777
5. 目录要 x 权限才能进去，只给 r 不给 x 的目录列不出内容也进不去

### 踩坑记录

```text
坑 1：chmod 777 滥用导致安全风险
结论：为图省事给目录 777，任何用户都能改。
原因：777 放开所有权限，等于权限形同虚设。
解法：按最小权限原则，需要谁给谁，能 755/644 就不 777。

坑 2：目录只给 r 不给 x，进不去也列不出
结论：chmod 444 目录后，ls 报权限不足。
原因：目录的 r 只能列名字，x 才能进入和访问内容。
解法：目录要访问就给 r-x（755/750），r 和 x 通常成对出现。

坑 3：chown 后服务进程还是没权限
结论：改了文件属主，服务还是读写失败。
原因：服务运行用户和文件属主不匹配，或 SELinux 上下文没改。
解法：确认服务的运行用户（systemctl 看 User=），chown 给对用户。

坑 4：SSH 私钥权限太松被拒绝
结论：chmod 644 id_rsa 后 SSH 报 Permissions 0644 too open。
原因：SSH 要求私钥仅属主可读（600），权限太松会拒。
解法：私钥一律 chmod 600，.ssh 目录 chmod 700。

坑 5：umask 设成 000 导致新文件全可写
结论：改 umask 000 后新建文件 666，人人可改。
原因：umask 000 不剥任何权限，默认权限过宽。
解法：umask 保持 022（或 027 更严），别图方便设 000。

坑 6：chmod -R 递归改到不该改的文件
结论：chmod -R 777 / 把系统文件权限全改了，系统异常。
原因：-R 递归会波及目录下所有文件，包括本不该改的。
解法：递归改用 find 按类型精确筛（-type f / -type d 分开改），别对根目录乱 -R。
```

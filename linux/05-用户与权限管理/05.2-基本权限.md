## 概述

Linux 用 rwx 三元组控制文件访问：r 读、w 写、x 执行，分别作用于「属主（owner）、属组（group）、其他人（others）」三类。改权限用 chmod，改属主属组用 chown/chgrp，默认权限由 umask 决定。权限是 Linux 安全的第一道门，理解「谁（owner/group/others）能对文件做什么（rwx）」是运维基本功。

```text
权限模型：
1. 三元组 —— rwx 分别 = 读/写/执行，数字 4/2/1 表示
2. 三类主体 —— 属主 owner、属组 group、其他人 others
3. 修改 —— chmod 改权限、chown 改属主、chgrp 改属组
4. 默认 —— umask 决定新建文件的默认权限
```

## rwx 权限

每个文件三组 rwx 权限，对应属主/属组/其他人。rwx 对文件和目录含义不同：文件的 r=读内容、w=改内容、x=执行；目录的 r=列目录、w=增删文件、x=进入目录。数字表示：r=4、w=2、x=1，权限数字是三者相加（如 rwx=7、rw=6、r-x=5）。`ls -l` 输出的 `-rw-r--r--` 就是三组 rwx。

```text
rwx 对文件/目录的含义：
1. 文件 —— r 读内容 / w 改内容 / x 执行
2. 目录 —— r 列目录项 / w 增删目录内文件 / x 进入目录
3. 数字 —— r=4 w=2 x=1，权限 = 三者相加（755 = rwxr-xr-x）
```

```text
# 实测
$ ls -l /etc/hostname
-rw-r--r-- 1 root root 15  5月 17 11:29 /etc/hostname
# 拆解：-（普通文件） rw-（属主可读写） r--（属组可读） r--（其他人可读）
```

## chmod 修改权限

chmod 改权限，支持两种写法：数字法（chmod 755）和符号法（chmod u+x、chmod g-w、chmod o=r）。数字法一次性设全三组，符号法只改指定主体的指定权限。常用：chmod 755（脚本可执行）、chmod 644（普通文件）、chmod 600（私密文件）。递归改目录用 -R。

```shell
chmod 755 script.sh        # 数字法：属主 rwx，组/其他 r-x
chmod u+x script.sh        # 符号法：给属主加执行
chmod 600 id_rsa           # 私钥：仅属主可读写
chmod -R 755 /var/www      # 递归改目录
```

## chown 与 chgrp

chown 改属主（可同时改属组，用 `属主:属组` 或 `属主.属组`），chgrp 只改属组。部署服务时经常要 chown 给运行用户（如 nginx 文件归 www-data、web 目录归部署用户），否则服务进程没权限读写自己的文件。改属主通常要 root 权限。

```shell
chown deploy:deploy app.jar          # 改属主和属组
chown -R www-data:www-data /var/www  # 递归改
chgrp dev /opt/shared                # 只改属组
```

## umask 与默认权限

umask 是「权限掩码」，决定新建文件/目录的默认权限：新文件默认 666 - umask，新目录默认 777 - umask。常见 umask 022（默认权限文件 644、目录 755）、002（共享组场景，文件 664）。所以新建文件默认没有 x 权限（执行位被 umask 剥掉），这是安全默认。当前 umask 用 `umask` 查看，`umask 022` 修改。

```shell
umask            # 查看当前 umask
umask 0022       # 设置为 022
```

```text
# 实测（本机默认）
$ umask
0022
# 所以新建文件默认 644（666-022）、新建目录默认 755（777-022）
```

## 应用场景实战

### 场景一：部署 Web 服务并设置正确权限

```shell
# 网站文件归 www-data（nginx 运行用户），目录 755 文件 644
chown -R www-data:www-data /var/www/mysite
find /var/www/mysite -type d -exec chmod 755 {} \;
find /var/www/mysite -type f -exec chmod 644 {} \;
# 敏感配置只给属主
chmod 600 /var/www/mysite/.env
```

### 场景二：共享目录给团队协作

```shell
# 建共享目录，同组成员可读写
mkdir /opt/shared
chgrp dev /opt/shared
chmod 2775 /opt/shared        # 2775 含 SGID，组内新建文件自动归组
```

## 最佳实践与踩坑记录

### 最佳实践

1. 普通文件 644、可执行脚本 755、私密文件（密钥/密码）600，这是约定俗成的默认
2. 改权限用数字法一次设全，符号法只做增量修改
3. 部署服务时把文件 chown 给运行用户，别让服务以 root 跑
4. 敏感文件（私钥、含密码配置）一律 600，别 777
5. 目录要 x 权限才能进去，只给 r 不给 x 的目录列不出内容也进不去

### 踩坑记录

```text
坑 1：chmod 777 滥用导致安全风险
结论：为图省事给目录 777，任何用户都能改。
原因：777 放开所有权限，等于权限形同虚设。
解法：按最小权限原则，需要谁给谁，能 755/644 就不 777。

坑 2：目录只给 r 不给 x，进不去也列不出
结论：chmod 444 目录后，ls 报权限不足。
原因：目录的 r 只能列名字，x 才能进入和访问内容。
解法：目录要访问就给 r-x（755/750），r 和 x 通常成对出现。

坑 3：chown 后服务进程还是没权限
结论：改了文件属主，服务还是读写失败。
原因：服务运行用户和文件属主不匹配，或 SELinux 上下文没改。
解法：确认服务的运行用户（systemctl 看 User=），chown 给对用户。

坑 4：SSH 私钥权限太松被拒绝
结论：chmod 644 id_rsa 后 SSH 报 Permissions 0644 too open。
原因：SSH 要求私钥仅属主可读（600），权限太松会拒。
解法：私钥一律 chmod 600，.ssh 目录 chmod 700。

坑 5：umask 设成 000 导致新文件全可写
结论：改 umask 000 后新建文件 666，人人可改。
原因：umask 000 不剥任何权限，默认权限过宽。
解法：umask 保持 022（或 027 更严），别图方便设 000。
```

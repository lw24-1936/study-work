## 概述

本项目目标：在 26.1 搭好的基础环境上，把一台服务器从「能用」提升到「通过安全基线审计、可上生产」的水准。安全加固是攻防对抗里防守方的系统工程——攻击者只要找到一个入口就能得手，防守方必须堵住所有入口。所以加固的核心思路是**减少攻击面 + 默认拒绝 + 持续审计**。

本项目覆盖四个环节：系统加固（最小化、账户口令、内核参数、文件权限）、防火墙策略（iptables/firewalld 白名单）、SELinux（强制访问控制）、CIS 基线检查（用 Lynis/CIS-CAT 打分并整改）。

技术栈：Ubuntu Server 22.04（UFW/AppArmor）与 Rocky Linux 9（firewalld/SELinux）双主线；工具用 iptables/firewalld、SELinux 工具链（semanage/audit2why）、Lynis、auditd。

前置条件：已完成 26.1 基础环境（sudo 账户、密钥登录、基础分区），有一台可反复折腾的测试机（**先在测试机验证，别直接在生产上开 enforcing**）。

```text
交付物：一台通过 CIS 基线检查、防火墙白名单、SELinux enforcing、审计开启、可安全投入生产并可通过合规审计的服务器
```

## 核心概念

本项目涉及的技术点：

1. **系统加固（system hardening）**：通过最小化安装、删除无用软件、收紧账户口令策略、加固内核参数、收紧文件权限，系统性减少攻击面。攻击面 = 攻击者可接触的入口（服务、端口、账户、可写文件），加固就是逐项关小这些入口。
2. **防火墙策略**：默认拒绝入站、按白名单放行必要服务，把攻击者挡在服务层之外。Linux 防火墙基于 netfilter 框架，上层工具分 iptables（老牌、规则链式）和 firewalld（zone 抽象、动态管理）。
3. **SELinux（强制访问控制 MAC）**：DAC（自主访问控制，即文件权限）之外的又一层——即使进程以 root 跑、文件权限是 777，SELinux 仍可按策略拒绝访问。进程和文件都被打上安全上下文（context），访问时先过 DAC 再过 MAC，任一拒绝即拒绝。
4. **CIS 基线检查**：CIS（Center for Internet Security）发布的 Benchmarks 是业界公认的加固基线，逐条列出「该关的服务、该设的参数、该收紧的权限」。用 Lynis（开源）或 CIS-CAT（官方工具）自动对照打分，分数越高越接近基线，未过项逐条整改。

```text
加固主线：
系统加固（最小化+账户+内核+权限）→ 防火墙（默认拒绝+白名单）→ SELinux（MAC 兜底）→ CIS 基线检查（量化验收）
```

## 工作原理

四个环节的底层机制：

1. **系统加固**：核心是「关掉用不到的，收紧必须用的」。最小化安装砍掉多余组件；账户口令策略靠 PAM（可插拔认证模块）在认证时强制强度校验；内核参数靠 sysctl 直接改 `/proc/sys` 下的运行态开关（如关闭 ICMP 重定向、开启 SYN cookie）。
2. **防火墙（netfilter 四表五链）**：数据包经过内核网络栈时，netfilter 在 5 个挂载点（PREROUTING/INPUT/FORWARD/OUTPUT/POSTROUTING）触发钩子，按规则链逐条匹配，命中即按 ACCEPT/DROP/REJECT 处理。iptables 直接操作这些链；firewalld 在它之上做 zone（区域）+ service（服务）的抽象，最终也翻译成 netfilter 规则。
3. **SELinux（类型强制 Type Enforcement）**：每个主体（进程）和客体（文件/端口/设备）都有安全上下文 `user:role:type`，其中 `type` 是核心。策略定义了「哪个 type 的进程能访问哪个 type 的客体、用什么权限」。访问时 SELinux 在 AVC（Access Vector Cache）里查决策，拒绝则记日志 `avc: denied`，可用 `audit2why` 解释原因。
4. **CIS 基线检查**：Lynis 内置几百个测试项，逐个对照 CIS/发行版最佳实践——检查文件权限、内核参数、服务状态、补丁版本、密码策略等，输出硬化指数（hardening index）和建议清单。它只「检查 + 给建议」，不自动修复（`lynis hardening` 可交互式部分修复）。

```text
防护层次（纵深防御）：
网络边界（防火墙白名单）→ 服务层（最小化+SSH 加固）→ 系统层（内核参数+权限+审计）→ 内核层（SELinux MAC 兜底）→ 验证层（CIS 基线打分）
任何一层被绕过，下一层仍然拦截
```

## 常用命令与配置

```shell
# 系统加固：账户与口令
chage -l admin                       # 查看账户口令策略（过期/最短/最长）
chage -M 90 -m 1 -W 7 admin          # 口令最长 90 天、最短 1 天、过期前 7 天提醒
passwd -l guest                      # 锁定账户（禁登录）
userdel -r guest                     # 删除账户及其家目录
faillock --user admin --reset        # 解锁登录失败被锁定的账户

# 系统加固：文件权限与 SUID 排查
find / -perm -4000 -type f 2>/dev/null   # 找出所有 SUID 文件（常见提权点）
find / -perm -2 -type f 2>/dev/null      # 找出所有全局可写文件
find / -nouser -o -nogroup 2>/dev/null   # 找出无主文件（删除账户后遗留）

# 防火墙：firewalld（RHEL 系）
firewall-cmd --get-default-zone         # 当前默认 zone
firewall-cmd --list-all                 # 看 zone 全部规则
firewall-cmd --permanent --add-service=http   # 永久放行 http 服务
firewall-cmd --permanent --add-port=8080/tcp  # 永久放行 8080 端口
firewall-cmd --permanent --remove-service=dhcpv6-client   # 移除不需要的服务
firewall-cmd --reload                   # 重载使永久规则生效
firewall-cmd --runtime-to-permanent     # 把运行态临时规则固化

# 防火墙：iptables（通用/老系统）
iptables -L -n -v                       # 看规则链（含计数）
iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT   # 放行已建立连接
iptables -A INPUT -i lo -j ACCEPT       # 放行回环
iptables -A INPUT -p tcp --dport 22 -m limit --limit 5/min -j ACCEPT   # 限速放行 SSH
iptables -P INPUT DROP                  # 默认拒绝入站

# SELinux
getenforce                             # 当前模式（Enforcing/Permissive/Disabled）
setenforce 1                           # 临时切到 Enforcing（0=Permissive）
sestatus                               # SELinux 状态摘要
getsebool -a | grep httpd              # 看 httpd 相关布尔开关
setsebool -P httpd_can_network_connect on   # 永久开启某布尔开关
semanage fcontext -a -t httpd_sys_content_t "/web(/.*)?"   # 定义目录的默认上下文
restorecon -Rv /web                    # 按策略恢复目录上下文
ls -Z /web                             # 查看文件安全上下文
ausearch -m avc -ts recent             # 查最近的 AVC 拒绝日志
audit2why < /var/log/audit/audit.log   # 解释为什么被拒绝

# CIS 基线检查：Lynis
lynis audit system                     # 完整系统审计
lynis show suggestions                 # 只显示建议清单
lynis show details FILE-6310           # 看某个测试项详情
```

```text
工具分工：
iptables     老牌、脚本化、兼容性好，规则链式管理，适合写死的基础规则
firewalld    zone+service 抽象、可动态增删规则不中断连接，RHEL 系默认
SELinux      MAC 强制访问控制，DAC 之外的兜底，生产建议 enforcing
Lynis        开源合规检查，几百个测试项 + 硬化指数 + 建议清单
CIS-CAT      官方合规评估工具，输出标准 CIS 报告，可对接审计
```

## 配置文件解析

### /etc/selinux/config（SELinux 模式）

```text
SELINUX=enforcing        # enforcing 强制 / permissive 只记日志不拦 / disabled 关闭
SELINUXTYPE=targeted     # targeted 只约束关键服务 / mls 多级安全（极少用）
```

关键点：`disabled` 改成 `enforcing` 后必须 `touch /.autorelabel` 再重启，让系统重打全盘安全标签，否则大量文件标签缺失、服务起不来。

### /etc/sysctl.d/99-hardening.conf（内核加固参数）

```text
# 网络层加固
net.ipv4.conf.all.rp_filter = 1              # 反向路径过滤，防 IP 欺骗
net.ipv4.conf.all.accept_redirects = 0       # 拒绝 ICMP 重定向（防路由劫持）
net.ipv4.conf.all.send_redirects = 0         # 不发送 ICMP 重定向
net.ipv4.conf.all.accept_source_route = 0    # 拒绝源路由（防绕过路由策略）
net.ipv4.icmp_echo_ignore_broadcasts = 1     # 忽略广播 ping（防 Smurf 放大攻击）
net.ipv4.tcp_syncookies = 1                  # 开启 SYN cookie（防 SYN 洪水）
net.ipv4.conf.all.log_martians = 1           # 记录可疑源地址包

# 进程与内存
kernel.randomize_va_space = 2                # ASLR 地址随机化（2=全随机）
fs.suid_dumpable = 0                         # SUID 进程 core dump 不落地（防泄露）
kernel.sysrq = 0                             # 关闭 Magic SysRq（防物理/串口提权）
```

### /etc/security/pwquality.conf（口令强度，Debian/Ubuntu）

```text
minlen = 12          # 最小长度
dcredit = -1         # 至少 1 个数字（负数=强制）
ucredit = -1         # 至少 1 个大写
lcredit = -1         # 至少 1 个小写
ocredit = -1         # 至少 1 个特殊字符
maxrepeat = 3        # 同字符最多连续 3 次
difok = 5            # 新口令与旧口令至少 5 个字符不同
```

### /etc/security/faillock.conf（登录失败锁定，RHEL 8+）

```text
deny = 5             # 连续失败 5 次锁定
unlock_time = 600    # 锁定 600 秒
fail_interval = 900  # 失败计数窗口 900 秒
```

### /etc/audit/rules.d/audit.rules（审计规则）

```text
-w /etc/passwd -p wa -k identity        # 监控 /etc/passwd 写/属性变更，标记 identity
-w /etc/shadow -p wa -k identity
-w /etc/sudoers -p wa -k sudoers
-w /var/log/auth.log -p wa -k authlog   # Debian/Ubuntu 认证日志
-a always,exit -F arch=b64 -S execve -k exec   # 记录所有 execve 系统调用
```

## 应用场景实战

目标服务器：Rocky Linux 9，IP `203.0.113.11`，已按 26.1 完成基础环境（admin 账户、密钥登录、firewalld 只放行 2222）。从「能用」加固到「过基线」，共 8 步。

### 步骤一：环境侦察与最小化

加固前先摸清现状——装了什么、跑着什么、开着哪些端口：

```shell
# 1. 系统与内核版本
cat /etc/os-release | head -n 2
uname -r
# 2. 已安装的软件包数量（越多攻击面越大）
rpm -qa | wc -l
# 3. 正在监听的端口
ss -tulnp
# 4. 开机自启的服务
systemctl list-unit-files --type=service --state=enabled
# 5. 可登录的账户（有 shell 的才是潜在登录入口）
awk -F: '$7 ~ /\/bash|\/sh/ {print $1}' /etc/passwd
```

解释：`ss -tulnp` 列出所有监听端口，没必要的服务就是攻击面；`systemctl list-unit-files --state=enabled` 找开机自启的服务，逐个问「这个一定要跑吗」；`awk` 从 `/etc/passwd` 筛出带登录 shell 的账户。

最小化动作——卸载无用服务、停掉不用的：

```shell
# 卸载图形界面相关（服务器用不上）
dnf groupremove "Server with GUI" -y
# 停掉并禁用不用的服务（示例：cups 打印、avahi 零配置发现）
systemctl disable --now cups avahi-daemon 2>/dev/null
# 删掉无主账户、游戏账户
userdel -r games 2>/dev/null; userdel -r ftp 2>/dev/null
```

验证：

```shell
ss -tulnp
systemctl list-unit-files --type=service --state=enabled
```

示例输出（加固后应只剩 sshd 和必要的服务）：

```text
tcp   LISTEN 0  128  0.0.0.0:2222  0.0.0.0:*  users:(("sshd",pid=812,fd=3))
```

### 步骤二：账户与口令策略加固

```shell
# 1. 收紧所有交互账户的口令策略
chage -M 90 -m 1 -W 7 admin
# 2. 锁定无登录需求的账户
passwd -l guest 2>/dev/null
# 3. 收紧全局 umask 到 027（新建文件默认 640，其他用户不可读）
sed -i 's/^UMASK.*/UMASK 027/' /etc/login.defs
# 4. 配置口令强度（pwquality）与失败锁定（faillock）
# RHEL 9 用 authselect 启用带 pwquality 的配置：
authselect select sssd with-faillock with-pamaccess --force
# 编辑 /etc/security/pwquality.conf 设强度（见配置文件解析节）
# 编辑 /etc/security/faillock.conf：deny=5 unlock_time=600
```

解释：`chage -M 90` 强制口令 90 天轮换，降低口令泄露窗口期；`passwd -l` 锁账户保留数据；`authselect` 是 RHEL 8+ 统一管理 PAM 配置的入口，`with-faillock` 自动挂上失败锁定，比手工改 PAM 文件安全。

验证：

```shell
chage -l admin
authselect check
```

示例输出：

```text
Last password change            : Aug 19, 2026
Password expires                : Nov 17, 2026
Password inactive               : never
Account expires                 : never
Minimum number of days between password change     : 1
Maximum number of days between password change     : 90
```

### 步骤三：SSH 进阶加固

26.1 已做了密钥登录 + 禁 root + 改端口，这里补上进阶项（防爆破、限尝试、禁弱算法）：

```shell
# 编辑 /etc/ssh/sshd_config 追加
# LoginGraceTime 30            # 登录宽限 30 秒，超时断开（拖慢爆破）
# MaxAuthTries 3               # 最多 3 次认证尝试
# MaxSessions 3                # 单连接最多 3 个会话
# AllowUsers admin             # 白名单，只允许 admin 登录
# PermitEmptyPasswords no      # 禁止空口令
# X11Forwarding no             # 关闭 X11 转发
# AllowTcpForwarding no        # 关闭 TCP 转发（防内网穿透跳板）

# 校验并重启
sshd -t && systemctl restart sshd
```

解释：`MaxAuthTries 3` 配合 faillock 双层防爆破；`AllowTcpForwarding no` 很关键——否则攻破一台边缘机就能把它当跳板转发进内网；`AllowUsers` 白名单是最强的一道闸，不在名单里的账户连密钥都过不了。

验证（用不在白名单的账户尝试登录，应被直接拒绝）：

```shell
ssh -p 2222 other@203.0.113.11
```

示例输出：

```text
other@203.0.113.11: Permission denied (publickey).
```

### 步骤四：内核参数与网络加固

把内核加固参数写入 sysctl 配置文件并生效：

```shell
# 写入 /etc/sysctl.d/99-hardening.conf（内容见配置文件解析节）
# 立即生效
sysctl --system
# 抽查几个关键项
sysctl net.ipv4.conf.all.rp_filter
sysctl net.ipv4.tcp_syncookies
sysctl kernel.randomize_va_space
```

解释：`sysctl --system` 按 `/etc/sysctl.d/`、`/etc/sysctl.conf` 顺序加载所有参数立即生效；`rp_filter` 反 IP 欺骗、`tcp_syncookies` 防 SYN 洪水、`randomize_va_space=2` 开 ASLR 让缓冲区溢出利用更难。

验证：

```shell
sysctl net.ipv4.tcp_syncookies
```

示例输出：

```text
net.ipv4.tcp_syncookies = 1
```

### 步骤五：防火墙策略（默认拒绝 + 白名单）

firewalld 把默认 zone 收紧为「只放行白名单」：

```shell
# 1. 确认默认 zone 和当前规则
firewall-cmd --list-all
# 2. 移除默认开放但用不上的服务（dhcpv6-client、cockpit 等）
firewall-cmd --permanent --remove-service=dhcpv6-client
firewall-cmd --permanent --remove-service=cockpit
# 3. 只放行必要的：SSH 新端口 + Web
firewall-cmd --permanent --add-port=2222/tcp
firewall-cmd --permanent --add-service=http
firewall-cmd --permanent --add-service=https
# 4. 重载生效
firewall-cmd --reload
# 5. 查看最终规则
firewall-cmd --list-all
```

解释：firewalld 默认 zone（public）默认放行 ssh、dhcpv6-client、cockpit 等服务，这些都要按实际需求砍掉；`--permanent` 写永久规则、`--reload` 重载生效（不影响现有连接）；最终效果是「除 2222/http/https 外全部拒绝」。

等价的 iptables 写法（脚本化、无 firewalld 的老系统）：

```shell
iptables -F                          # 清空规则（先确保有 console 访问）
iptables -P INPUT DROP               # 默认拒绝入站
iptables -P FORWARD DROP             # 默认拒绝转发
iptables -P OUTPUT ACCEPT            # 出站放行
iptables -A INPUT -i lo -j ACCEPT                          # 回环
iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT   # 已建立连接
iptables -A INPUT -p tcp --dport 2222 -m limit --limit 5/min -j ACCEPT  # SSH 限速
iptables -A INPUT -p tcp --dport 80 -j ACCEPT              # HTTP
iptables -A INPUT -p tcp --dport 443 -j ACCEPT             # HTTPS
iptables-save > /etc/iptables/rules.v4                     # 持久化
```

解释：`-m limit --limit 5/min` 给 SSH 端口限速，同一来源每分钟最多 5 个新连接，把暴力爆破拖到几乎不可行；`-m state --state ESTABLISHED,RELATED` 放行已建立的连接，保证出站请求的响应能回来。

验证：

```shell
firewall-cmd --list-all
```

示例输出：

```text
public (active)
  target: default
  services: http https
  ports: 2222/tcp
  ...
```

### 步骤六：SELinux 开启与策略管理

Rocky/RHEL 默认已启用 SELinux，但很多「图省事」的教程会让人关掉它。这一步把它开回 enforcing 并学会排错：

```shell
# 1. 确认当前状态
getenforce
sestatus
# 2. 若显示 Disabled，改配置 + 触发重打标签后重启
sed -i 's/^SELINUX=disabled/SELINUX=enforcing/' /etc/selinux/config
touch /.autorelabel
reboot
# 3. 临时切换（不开配置、只切运行态，重启失效）
setenforce 1
```

解释：`Disabled` 到 `enforcing` 必须重启 + `/.autorelabel` 重打全盘标签，否则之前关闭期间创建的文件没有安全上下文，进程访问会报 AVC 拒绝。

部署服务时按需开 SELinux 策略（以把 Web 根改到 `/web` 为例）：

```shell
# 4. 定义 /web 目录默认上下文
semanage fcontext -a -t httpd_sys_content_t "/web(/.*)?"
# 5. 恢复目录上下文
restorecon -Rv /web
# 6. 若 Web 要连数据库（默认被 SELinux 禁止网络连接）
setsebool -P httpd_can_network_connect_db on
# 7. 若 Web 用非标准端口 8080
semanage port -a -t http_port_t -p tcp 8080
```

解释：`semanage fcontext` 是「定义某个路径默认该是什么类型」；`restorecon` 把文件标签恢复成策略定义的类型；`setsebool -P` 开布尔开关（`-P` 永久）；`semanage port` 把 8080 划入 http 端口类型。这套「改路径/改端口 → 同步 SELinux 策略」是 SELinux 环境部署服务的基本功。

验证：

```shell
ls -Z /web
sestatus
```

示例输出：

```text
unconfined_u:object_r:httpd_sys_content_t:s0 /web/index.html
SELinux status:                 enabled
Current mode:                   enforcing
```

### 步骤七：文件系统权限与审计加固

```shell
# 1. /tmp 挂 noexec,nosuid,nodev（防脚本注入执行）
# 编辑 /etc/fstab，/tmp 行选项加 noexec,nosuid,nodev，然后：
mount -o remount /tmp
# 2. 排查 SUID/SGID 文件（常见提权点，逐个确认是否必要）
find / -perm -4000 -type f 2>/dev/null
# 3. 排查全局可写文件
find / -perm -2 -type f 2>/dev/null
# 4. 开启审计：监控关键文件 + execve
# 编辑 /etc/audit/rules.d/audit.rules（内容见配置文件解析节）
augenrules --load
systemctl enable --now auditd
# 5. 查审计日志
ausearch -k identity | tail -n 20
```

解释：`/tmp` 是攻击者落地脚本的首选位置，`noexec` 让它无法执行；SUID 文件（如 `passwd`、`sudo`）以属主权限运行，多一个就多一个提权面，逐个核对；auditd 把关键文件变更和系统调用记入 `/var/log/audit/audit.log`，出事能回溯。

验证：

```shell
mount | grep /tmp
auditctl -l
```

示例输出：

```text
/tmp on /dev/mapper/rl-tmp type xfs (rw,nosuid,nodev,noexec,relatime,seclabel)
-w /etc/passwd -p wa -k identity
-w /etc/shadow -p wa -k identity
```

## 性能与调优

```text
1. 审计有 IO 开销 —— 全量 execve 审计在高并发系统上会拖慢性能，生产按需只审计敏感文件，别无脑全开
2. 防火墙规则顺序影响性能 —— 高频规则（ESTABLISHED）放最前，别把限速规则放第一条（每个包都要过 limit 匹配）
3. SELinux 本身开销极小 —— AVC 决策有缓存，enforcing 对性能影响通常 <5%，别拿「性能」当关闭 SELinux 的借口
4. sysctl syncookies 在正常流量下无开销 —— 只在 SYN 队列满时才启用，开了不亏
5. /tmp 用 tmpfs（内存盘）+ noexec —— 快且重启清空，代价是占内存，小内存机器权衡
```

```shell
# 查看审计是否拖慢系统（audit 进程 CPU 占用）
top -bn1 | grep auditd
# 查看当前连接状态分布（TIME_WAIT 过多说明短连接多）
ss -s
```

## 安全与权限

```text
1. SELinux 上下文 —— 文件被移到新目录后标签会丢（mv 保留标签、cp 继承目标目录默认标签），服务起不来先查 restorecon
2. SUID 提权面 —— find / -perm -4000 的结果逐个核对，非必要的去掉 SUID 位（chmod u-s）
3. 审计日志防篡改 —— auditd 日志目录 /var/log/audit 权限收紧，且规则里加 audit 自身的保护（-w /etc/audit/ -p wa）
4. 最小权限 —— 服务用专用低权限账户跑（如 nginx 用 nginx 用户），不共用 root
5. 防火墙规则变更要留痕 —— 用审计监控 /etc/firewalld 和 iptables 配置变更
```

```shell
# 去掉某个文件的 SUID 位（如确认某程序不需要 setuid）
chmod u-s /usr/bin/example
# 收紧审计日志目录权限
chmod 700 /var/log/audit
```

## 故障排查

### SELinux 拦截导致服务起不来

```shell
# 症状：服务启动失败/访问被拒，日志无业务错误
# 1. 查 AVC 拒绝日志
ausearch -m avc -ts recent
# 2. 解释原因（直接读 audit.log）
audit2why < /var/log/audit/audit.log
# 3. 若确认是策略太严，临时切 permissive 验证
setenforce 0
# 服务正常 → 确认是 SELinux 拦截
# 4. 生成放行模块或开对应布尔开关（别永久关 SELinux）
audit2allow -a -M mymodule && semodule -i mymodule.pp
```

解释：`audit2why` 直接告诉你「哪个进程因为缺哪个布尔开关被拒」；`audit2allow -a` 把 AVC 日志转成放行规则、`semodule -i` 加载自定义模块——这是「开 permissive 验证 + 定向放行」的标准排错路径，而不是一拒就关 SELinux。

### 防火墙误拦合法流量

```shell
# 症状：服务正常但外部连不上
# 1. 确认端口在监听
ss -tulnp | grep <port>
# 2. 确认防火墙放行
firewall-cmd --list-all | grep <port>
# 3. 看防火墙日志（firewalld 丢弃的包）
journalctl -u firewalld -n 50
# 4. 临时放行验证
firewall-cmd --add-port=<port>/tcp
```

### 加固后 SSH 连不上

```shell
# 症状：改完 sshd_config 或防火墙后新连接进不去
# 关键：旧连接别断开
sshd -t                          # 查 SSH 配置语法
firewall-cmd --list-all          # 查端口是否放行
systemctl status sshd            # 查服务状态
# 常见原因：AllowUsers 没把自己加进去 / 端口改了防火墙没同步 / MaxAuthTries 太低
```

### 审计日志写满磁盘

```shell
# 症状：磁盘告警，/var/log/audit 暴涨
du -sh /var/log/audit
# 1. 看审计规则是否过宽（全量 execve 最易爆）
auditctl -l
# 2. 收紧规则，去掉不必要的高频监控
# 3. 日志轮转
cat /etc/audit/auditd.conf | grep -E 'max_log_file|num_logs'
```

## 常见问题

```text
Q1: SELinux 和防火墙是不是重复的防护？
A: 不重复，是两层。防火墙拦的是「进不来的流量」（网络层），SELinux 拦的是「进程能碰什么」（系统层）。即使防火墙放行了 80 端口、nginx 被攻破，SELinux 仍能限制 nginx 进程只能读该读的文件，防它碰 /etc/shadow。

Q2: 加固之后会不会影响业务？
A: 会的，这正是要先在测试机验证的原因。最常见的三类影响：SELinux 拦截（改端口/改路径后要同步策略）、防火墙拦端口（新服务忘了放行）、口令策略太严（用户不满）。逐层灰度、留好回退。

Q3: permissive 和 enforcing 有什么区别？什么时候用 permissive？
A: permissive 只记 AVC 日志不真正拦截，enforcing 才拦。排错时切 permissive 判断「是不是 SELinux 的问题」，定位后开对应布尔开关/加放行模块，再切回 enforcing。生产别长期留 permissive——那等于没开。

Q4: Lynis 硬化指数多少分算合格？
A: 没有统一分数线，看审计要求。一般 90+ 算良好、95+ 算严格合规。重点是逐条看 SUGGESTION 里「Critical/High」级别的项，比总分更有意义。

Q5: 为什么不能直接关闭 SELinux 省事？
A: SELinux 是纵深防御的最后一道、也是关键一道——它防的是「服务被攻破后的横向移动」。零日漏洞、Web 漏洞拿到的往往就是服务进程权限，SELinux 能把它圈在最小权限里。关了它，DAC 一旦被绕过就裸奔。
```

## 面试题

```text
1. 说说 SELinux 的三种工作模式，以及它的上下文由哪几部分组成？
   答：Enforcing（强制拦截）、Permissive（只记日志不拦）、Disabled（关闭）。安全上下文由 user:role:type:level 组成，其中 type（类型）是类型强制 TE 的核心，策略定义「某 type 进程能访问某 type 客体」。

2. iptables 的四表五链是什么？一个访问本机 80 端口的数据包走哪条链？
   答：四表 = filter（过滤）、nat（地址转换）、mangle（包修改）、raw（连接跟踪豁免）；五链 = PREROUTING/INPUT/FORWARD/OUTPUT/POSTROUTING。访问本机 80 端口走 PREROUTING → INPUT，filter 表的 INPUT 链负责放行/拒绝。

3. 如何让一台新上线的服务同时通过防火墙和 SELinux 两道关？
   答：防火墙用 firewall-cmd --permanent --add-port=<port>/tcp 放行端口；SELinux 若用非标准端口要 semanage port -a -t <type>_port_t，若改文件路径要 semanage fcontext + restorecon，涉及网络/数据库要开对应 seboolean。

4. 服务器被爆破 SSH，你会怎么加固？
   答：密钥登录 + 禁 root + 禁密码、AllowUsers 白名单、MaxAuthTries 降低、改默认端口、firewalld/iptables 对 22/SSH 端口限速、fail2ban 自动封禁、faillock 账户锁定。

5. 怎么量化一台服务器「加固得怎么样」？
   答：用 CIS 基线工具（Lynis/CIS-CAT）对照 CIS Benchmark 自动打分，看硬化指数和 Critical/High 未过项，逐条整改后重跑，直到达到审计要求的分数。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 加固顺序固定：先做账户+密钥+防火墙（保命层），再动 SELinux（最易误伤），最后跑基线检查验收
2. 任何加固先在测试机验证，生产灰度分批执行，别一次性全上
3. 防火墙用「默认拒绝 + 白名单」，高频规则（ESTABLISHED）放最前
4. SELinux 生产保持 enforcing，出问题用 audit2why/audit2allow 定向放行，别整体关
5. 用 Lynis/CIS-CAT 定期跑基线检查，整改后重跑量化验收
6. 审计只监控必要的敏感文件和关键系统调用，别全量 execve
7. 加固变更全部记入变更日志，能回退、可审计

### 踩坑记录

```text
坑 1：disabled 直接改 enforcing 没 relabel，重启后服务全挂
结论：SELinux 切 enforcing 后一堆服务报 AVC 拒绝、起不来。
原因：关闭期间创建的文件没有安全上下文，直接 enforcing 全部被拦。
解法：改配置后 touch /.autorelabel 再重启，让系统重打全盘标签。

坑 2：改端口改路径却不同步 SELinux 策略
结论：服务部署到 /web 或改用 8080 端口后被 SELinux 拦截。
原因：SELinux 按策略定义的 type 约束路径和端口，改路径/端口后旧策略不匹配。
解法：semanage fcontext -a + restorecon 定义新路径上下文，semanage port -a 定义新端口类型。

坑 3：加固防火墙把自己锁在外面
结论：iptables -P INPUT DROP 或清空规则后，SSH 直接断连。
原因：默认拒绝/清空规则前没先放行 SSH 和 ESTABLISHED 连接。
解法：先加 ACCEPT 规则（SSH + 已建立连接）再设默认 DROP，且保持一个 console/旧会话不断。

坑 4：AllowUsers 白名单没把自己加进去
结论：改完 sshd_config 重启后，自己也登不进去。
原因：AllowUsers 只列了别人，或拼错用户名。
解法：改配置前 sshd -t 校验，白名单确认包含自己，保持旧连接验证后再关。

坑 5：以为 SELinux 拦了就永久 setenforce 0
结论：服务是能跑了，但 SELinux 形同虚设，审计一看就是合规不合格项。
原因：用关闭/降级代替「定向放行」，治标不治本。
解法：permissive 只用于定位问题，用 audit2allow/audit2why/sebool 定向放行后切回 enforcing。

坑 6：审计全量 execve 把磁盘写满
结论：/var/log/audit 几小时涨满，拖垮系统。
原因：-a always,exit -S execve 记录每次系统调用，高并发下海量日志。
解法：只审计敏感文件（-w /etc/passwd -p wa）和关键调用，配合 auditd 轮转。
```

## 概述

本项目目标：在 26.1 搭好的服务器（`server01`）上，用 Nginx 部署一个「多站点 + 反向代理 + HTTPS + 静态资源缓存」的完整 Web 环境。前端静态站和 API 后端分离，统一由 Nginx 对外服务。

技术栈：Nginx（反向代理 + 静态服务）、Let's Encrypt/certbot（免费 TLS 证书）、一个示例后端服务（Python Flask 监听 `127.0.0.1:8080`）。

前置条件：已完成 26.1 的基础环境（nginx 已装、防火墙已配、admin 账户可 sudo）；两个域名 `www.example.com`、`api.example.com` 已解析到服务器 IP。

```text
交付物：Nginx 反向代理多站点，静态站走缓存 + gzip，API 走 HTTPS + 反向代理，证书自动续期
```

## 核心概念

本项目涉及的技术点：

1. **Nginx 反向代理**：客户端请求 Nginx，Nginx 转发到后端（`proxy_pass`），后端只监听内网地址，隐藏真实服务。
2. **多站点（虚拟主机）**：一台机器按 `server_name`（域名）分发到不同站点，一个 Nginx 实例跑多个网站。
3. **TLS 证书**：HTTPS 的加密与身份认证，Let's Encrypt 免费签发，certbot 自动完成 ACME 验证 + 续期。
4. **静态资源与缓存**：静态文件（CSS/JS/图片）直接由 Nginx 返回，配 `expires` 缓存头让浏览器缓存；`proxy_cache` 缓存后端响应，减轻后端压力。

```text
核心概念：
反向代理（proxy_pass 转发）→ 多站点（server_name 分发）→ TLS（certbot 签证书）→ 静态资源 + 缓存（expires / proxy_cache / gzip）
```

## 工作原理

1. **请求处理流程**：请求到达 → Nginx 按 `listen` + `server_name` 匹配 server 块 → 按 URL 路径匹配 `location` → 静态路径直接读盘返回，动态路径 `proxy_pass` 转发后端。
2. **反向代理**：Nginx 作为服务端代理，收到请求后新建到后端的连接转发，拿到响应再回给客户端；通过 `proxy_set_header` 把真实客户端 IP 传给后端。
3. **TLS 握手**：客户端发起 TLS 握手 → Nginx 返回证书链 → 客户端校验证书 + 协商对称密钥 → 建立加密通道。certbot 用 HTTP-01 验证：往站点放一个随机 token 文件，CA 通过 HTTP 访问验证域名控制权，通过后签发证书。
4. **缓存**：静态资源带 `Cache-Control: max-age` 让浏览器本地缓存；`proxy_cache` 在 Nginx 层缓存后端响应，命中缓存直接返回，不再打后端。

```text
请求流程：listen+server_name 匹配 → location 匹配 → 静态读盘 / 动态 proxy_pass
TLS 验证：certbot HTTP-01 → CA 访问 token 文件验证域名 → 签发证书 → 自动续期
缓存两级：浏览器缓存（expires/Cache-Control）+ Nginx 缓存（proxy_cache）
```

## 常用命令与配置

```shell
nginx -t                      # 测试配置语法（改配置后必跑）
systemctl reload nginx        # 平滑重载配置（不中断连接）
systemctl restart nginx       # 重启（会短暂中断）
nginx -T                      # 查看完整生效配置（含 include）
curl -I https://example.com   # 看响应头（验证缓存/证书）

# certbot 证书
certbot --nginx -d example.com -d www.example.com   # 自动改 nginx 配置 + 签证书
certbot renew --dry-run       # 测试续期流程
certbot certificates          # 查看已签证书

# 排查
tail -f /var/log/nginx/error.log     # 错误日志
tail -f /var/log/nginx/access.log    # 访问日志
ss -tlnp | grep -E ':80|:443'        # 看端口占用
```

```text
配置要点：
1. 改配置先 nginx -t，通过再 reload
2. 后端只监听 127.0.0.1，靠 Nginx 对外，别直接暴露后端端口
3. 静态资源配长缓存头，动态接口不缓存
```

## 配置文件解析

### /etc/nginx/nginx.conf（主配置）

```nginx
user www-data;                          # worker 运行用户
worker_processes auto;                  # worker 数 = CPU 核数
error_log /var/log/nginx/error.log warn;
pid /run/nginx.pid;

events {
    worker_connections 1024;            # 每个 worker 最大连接数
}

http {
    include /etc/nginx/mime.types;      # MIME 类型映射
    default_type application/octet-stream;
    sendfile on;                        # 零拷贝发静态文件
    tcp_nopush on;
    keepalive_timeout 65;
    include /etc/nginx/conf.d/*.conf;          # 通用片段
    include /etc/nginx/sites-enabled/*;        # 站点配置
}
```

### 反向代理站点（含 header 传递）

```nginx
server {
    listen 80;
    server_name api.example.com;

    location / {
        proxy_pass http://127.0.0.1:8080;      # 转发到后端
        proxy_set_header Host $host;           # 透传原始域名
        proxy_set_header X-Real-IP $remote_addr;         # 真实客户端 IP
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;      # 原始协议（http/https）
    }
}
```

### TLS 站点（certbot 生成）

```nginx
server {
    listen 443 ssl;
    server_name www.example.com;

    ssl_certificate /etc/letsencrypt/live/example.com/fullchain.pem;  # 证书链
    ssl_certificate_key /etc/letsencrypt/live/example.com/privkey.pem; # 私钥
    include /etc/letsencrypt/options-ssl-nginx.conf;   # TLS 协议套件
    ssl_dhparam /etc/letsencrypt/ssl-dhparams.pem;

    root /var/www/www.example.com;
    index index.html;
}
```

### 静态缓存片段

```nginx
# 静态资源：长缓存 + gzip 预置
location ~* \.(css|js|png|jpg|jpeg|gif|svg|woff2?|ico)$ {
    root /var/www/www.example.com;
    expires 30d;                       # 浏览器缓存 30 天
    add_header Cache-Control "public, immutable";
    access_log off;                    # 静态资源不记访问日志
}
```

```text
关键字段：
proxy_pass            反向代理目标
proxy_set_header      向后端透传的头（真实 IP / 原始协议）
server_name           虚拟主机域名
ssl_certificate       证书链 + 私钥
expires               浏览器缓存时长
```

## 应用场景实战

目标：`www.example.com` 静态站（HTML + CSS/JS），`api.example.com` 反代到 Flask 后端，两个都上 HTTPS，静态资源走缓存 + gzip。共 8 步。

### 步骤一：准备后端服务（Flask 监听 127.0.0.1:8080）

先做一个最小后端，让 Nginx 有东西可代理：

```shell
# 安装 Python 虚拟环境工具（Debian/Ubuntu 需先装 python3-venv）
sudo apt install -y python3-venv
mkdir -p /opt/app && cd /opt/app
python3 -m venv venv
./venv/bin/pip install flask
```

写后端应用 `/opt/app/app.py`：

```python
from flask import Flask, request

app = Flask(__name__)

@app.route("/")
def index():
    return {"service": "api", "client_ip": request.headers.get("X-Real-IP")}

@app.route("/hello")
def hello():
    return {"message": "hello from backend"}

if __name__ == "__main__":
    # 只监听内网回环地址，不对外暴露
    app.run(host="127.0.0.1", port=8080)
```

写 systemd unit `/etc/systemd/system/api.service`：

```ini
[Unit]
Description=Example API backend
After=network.target

[Service]
User=www-data
WorkingDirectory=/opt/app
ExecStart=/opt/app/venv/bin/python /opt/app/app.py
Restart=always

[Install]
WantedBy=multi-user.target
```

```shell
sudo systemctl daemon-reload
sudo systemctl enable --now api
# 验证后端本地可达
curl -s http://127.0.0.1:8080/hello
```

示例输出：

```text
{"message":"hello from backend"}
```

解释：后端只绑 `127.0.0.1`，外部无法直接访问，必须走 Nginx 反代；用 systemd 托管，进程挂了自动拉起（`Restart=always`）。

### 步骤二：确认 Nginx 环境

```shell
nginx -v
nginx -t
sudo systemctl status nginx --no-pager | head -n 5
```

解释：确认 nginx 已装、配置语法正常、服务在跑。Ubuntu 的站点配置目录是 `/etc/nginx/sites-available/` + `sites-enabled/` 软链；RHEL 系直接用 `/etc/nginx/conf.d/`，本次以 Ubuntu 为例，RHEL 系把站点文件直接放进 `conf.d/` 即可。

### 步骤三：部署静态站点（www.example.com）

```shell
# 建站点目录和首页
sudo mkdir -p /var/www/www.example.com
echo '<h1>Hello from static site</h1>' | sudo tee /var/www/www.example.com/index.html > /dev/null
sudo chown -R www-data:www-data /var/www/www.example.com
```

写站点配置 `/etc/nginx/sites-available/www.example.com`：

```nginx
server {
    listen 80;
    server_name www.example.com;

    root /var/www/www.example.com;
    index index.html;

    # 静态资源缓存 + gzip 由后续步骤的片段接管
    location / {
        try_files $uri $uri/ =404;     # 找不到就 404，不暴露目录结构
    }
}
```

```shell
sudo ln -s /etc/nginx/sites-available/www.example.com /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
curl -s -H 'Host: www.example.com' http://127.0.0.1/
```

示例输出：

```text
<h1>Hello from static site</h1>
```

解释：`sites-available` 放配置、`sites-enabled` 软链启用（Ubuntu 惯例）；`try_files` 按顺序找文件，找不到返回 404 而非暴露目录；`curl -H 'Host:'` 在本地模拟域名访问（域名还没解析到本机时用）。

### 步骤四：配置反向代理（api.example.com）

写 `/etc/nginx/sites-available/api.example.com`：

```nginx
server {
    listen 80;
    server_name api.example.com;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_connect_timeout 5s;      # 连接后端超时
        proxy_read_timeout 30s;        # 读后端响应超时
    }
}
```

```shell
sudo ln -s /etc/nginx/sites-available/api.example.com /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
curl -s -H 'Host: api.example.com' http://127.0.0.1/hello
```

示例输出：

```text
{"message":"hello from backend"}
```

解释：`proxy_pass http://127.0.0.1:8080` 把请求转发给后端；四个 `proxy_set_header` 让后端能拿到原始域名、真实客户端 IP 和原始协议（后端据此记录日志、判断 http/https）；两个 timeout 防止后端挂死时连接长期占用。

### 步骤五：多站点并存与默认站点

现在两个 server 块都监听 80，Nginx 按请求的 Host 头分发：

```shell
# 看当前启用的站点
ls -l /etc/nginx/sites-enabled/
# 测试不同域名命中不同站点
curl -s -H 'Host: www.example.com' http://127.0.0.1/ | head -n 1
curl -s -H 'Host: api.example.com'  http://127.0.0.1/hello
# 未匹配的 Host 会落到 default 站点，禁掉默认站点防域名劫持
sudo rm -f /etc/nginx/sites-enabled/default
```

解释：`server_name` 匹配请求的 Host 头，一台机器跑多站点；Ubuntu 默认有个 `default` 站点，请求的 Host 不匹配任何站点时落到它——生产环境删掉默认站点，避免「任意域名都能访问到某个站点」。

验证：

```shell
sudo nginx -t && sudo systemctl reload nginx
curl -s -o /dev/null -w '%{http_code}\n' -H 'Host: unknown.example.com' http://127.0.0.1/
```

示例输出：

```text
404
```

### 步骤六：签发 TLS 证书（certbot + Let's Encrypt）

```shell
# 安装 certbot 的 nginx 插件
sudo apt install -y certbot python3-certbot-nginx
# RHEL 系：sudo dnf install -y certbot python3-certbot-nginx

# 自动签证书并改写 nginx 配置（域名必须已解析到本机，且 80 端口对外开放）
sudo certbot --nginx -d www.example.com -d api.example.com
```

解释：`certbot --nginx` 用 HTTP-01 验证——certbot 在站点放一个 token 文件，Let's Encrypt 通过 HTTP 访问验证域名归属，验证通过即签发证书，并自动往 nginx 配置加 `listen 443 ssl` 和证书路径，顺手加 HTTP→HTTPS 跳转。这一步要求 80 端口能从公网访问，且防火墙放行了 80/443。

验证：

```shell
curl -sI https://www.example.com | head -n 1
sudo certbot certificates
```

示例输出：

```text
HTTP/1.1 200 OK

Found the following certs:
  Certificate Name: www.example.com
    Domains: www.example.com api.example.com
    Expiry Date: 2026-11-17 02:30:00+00:00 (VALID: 89 days)
```

### 步骤七：静态资源与缓存

给静态站补上缓存和 gzip。写 `/etc/nginx/sites-available/www.example.com` 追加内容：

```nginx
server {
    listen 80;
    server_name www.example.com;
    root /var/www/www.example.com;
    index index.html;

    # gzip 压缩（文本类资源体积大，压缩收益高）
    gzip on;
    gzip_types text/plain text/css application/javascript application/json image/svg+xml;
    gzip_min_length 1024;

    # 静态资源：长缓存
    location ~* \.(css|js|png|jpg|jpeg|gif|svg|woff2?|ico)$ {
        expires 30d;
        add_header Cache-Control "public, immutable";
        access_log off;
    }

    # HTML 页面：不缓存，保证更新及时生效
    location / {
        try_files $uri $uri/ =404;
        add_header Cache-Control "no-cache";
    }
}
```

```shell
sudo nginx -t && sudo systemctl reload nginx
# 验证缓存头
curl -sI -H 'Host: www.example.com' http://127.0.0.1/static/app.js
```

示例输出：

```text
HTTP/1.1 200 OK
Cache-Control: public, immutable
Expires: Thu, 17 Sep 2026 02:30:00 GMT
```

解释：静态资源（带版本 hash 的 CSS/JS/图片）配 30 天长缓存，浏览器二次访问直接读本地；HTML 页面配 `no-cache` 让浏览器每次回源确认，避免更新不生效；gzip 把文本资源压到原体积的 1/5 左右，省带宽提速度。

### 步骤八：后端响应缓存（proxy_cache）与整体验证

在 nginx.conf 的 `http` 块里加缓存定义，再给 API 站点加缓存规则（只缓存 GET 请求）：

```nginx
# http 块内
proxy_cache_path /var/cache/nginx levels=1:2 keys_zone=api_cache:10m max_size=1g inactive=60m use_temp_path=off;
```

API 站点加：

```nginx
location / {
    proxy_pass http://127.0.0.1:8080;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;

    proxy_cache api_cache;
    proxy_cache_key "$scheme$request_method$host$request_uri";  # 缓存键
    proxy_cache_valid 200 1m;          # 200 响应缓存 1 分钟
    proxy_cache_bypass $cookie_nocache; # 有 nocache cookie 则绕过缓存
}
```

```shell
sudo nginx -t && sudo systemctl reload nginx
# 验证：连续请求两次，第二次命中缓存（X-Cache-Status 变 HIT）
curl -s -o /dev/null -w '%{http_code}\n' -H 'Host: api.example.com' http://127.0.0.1/hello
```

解释：`proxy_cache_path` 定义缓存存储（目录 + 内存索引 keys_zone）；`proxy_cache_key` 决定哪些请求算同一条缓存；`proxy_cache_valid` 只缓存 200 且只缓存 1 分钟，动态接口不适合长缓存。缓存命中后 Nginx 直接返回，不再打后端。

整体验证清单：

```shell
# 1. 静态站：200 + gzip + 缓存头
curl -sI https://www.example.com | grep -iE 'HTTP|content-encoding|cache-control'
# 2. API：HTTPS 反代 + 后端拿到真实 IP
curl -s https://api.example.com/
# 3. 配置无语法错误
sudo nginx -t
# 4. 证书有效期
sudo certbot certificates | grep -E 'Expiry'
```

## 性能与调优

```text
1. gzip 压缩 —— 文本资源压缩到 1/5，省带宽提速度（CPU 换带宽）
2. 静态资源长缓存（expires 30d + immutable）—— 浏览器不再重复请求
3. proxy_cache —— 缓存后端响应，减轻后端压力（只缓存幂等的 GET）
4. HTTP/2 —— listen 443 ssl http2，多路复用减少连接开销
5. worker_processes = CPU 核数，worker_connections 调大提升并发
6. 后端 keepalive —— upstream 里 keepalive 复用后端连接，省 TCP 握手
```

```nginx
# HTTP/2 + 后端连接复用示例
upstream backend {
    server 127.0.0.1:8080;
    keepalive 32;                    # 保持 32 条到后端的空闲连接
}
server {
    listen 443 ssl http2;            # 开启 HTTP/2
    server_name api.example.com;
    location / {
        proxy_pass http://backend;
        proxy_http_version 1.1;
        proxy_set_header Connection "";   # 复用连接必须清掉该头
    }
}
```

## 安全与权限

```text
1. 后端只监听 127.0.0.1，不对外暴露端口
2. TLS 只留新协议 —— ssl_protocols TLSv1.2 TLSv1.3，禁老版本
3. 隐藏版本号 —— server_tokens off，别暴露 nginx 版本
4. 限请求体大小 —— client_max_body_size 10m，防超大上传打爆磁盘
5. 限流 —— limit_req_zone 限制单 IP 请求频率，防 CC 攻击
6. 覆盖 X-Forwarded-For 而非追加 —— 反向代理时要能识别/丢弃伪造的 XFF 头
```

```nginx
# 限流示例
limit_req_zone $binary_remote_addr zone=api_limit:10m rate=10r/s;
server {
    location / {
        limit_req zone=api_limit burst=20 nodelay;
        proxy_pass http://127.0.0.1:8080;
    }
}
```

## 故障排查

### 502 Bad Gateway

```shell
# 502 = 后端无响应（挂了/端口不对/没起）
systemctl status api                     # 后端服务是否在跑
curl -s http://127.0.0.1:8080/hello      # 本地直连后端是否通
tail -f /var/log/nginx/error.log         # 看 connect() failed 细节
```

### 504 Gateway Timeout

```shell
# 504 = 后端处理超时（超过 proxy_read_timeout）
# 排查：后端是否卡住、慢查询
tail -f /var/log/nginx/error.log | grep -i timeout
# 解决：临时调大 proxy_read_timeout，或优化后端性能
```

### 证书签发失败

```shell
# certbot 报 connection refused / timeout
```

## 常见问题

```text
Q1: 反向代理和正向代理区别？
A: 反向代理代理服务端（客户端不知道后端是谁），正向代理代理客户端（服务端不知道客户端是谁）。Nginx 做的是反向代理。

Q2: proxy_pass 结尾加 / 和不加 / 有区别吗？
A: 有。proxy_pass http://backend（无结尾 /）会把 location 匹配到的路径原样拼上；proxy_pass http://backend/（有结尾 /）会用 / 替换匹配到的路径前缀。写错会导致转发路径不对。

Q3: 静态资源和动态接口的缓存策略为什么不同？
A: 静态资源内容不变、体积大，适合长缓存（浏览器本地缓存）；动态接口结果随时变，长缓存会让用户看到旧数据，所以只短缓存或配 no-cache，甚至只缓存幂等的 GET。

Q4: certbot 签的证书多久到期？会自动续期吗？
A: Let's Encrypt 证书 90 天有效期。certbot 安装时会建 systemd timer（certbot.timer），每天自动检查、到期前自动续期。可跑 certbot renew --dry-run 验证续期链路正常。

Q5: 为什么后端要绑 127.0.0.1 而不是 0.0.0.0？
A: 绑 127.0.0.1 后外部无法绕过 Nginx 直连后端，减少暴露面；所有流量统一走 Nginx 的日志、限流、TLS 终结。
```

## 面试题

```text
1. Nginx 反向代理怎么把真实客户端 IP 传给后端？
   答：用 proxy_set_header X-Real-IP $remote_addr 和 X-Forwarded-For $proxy_add_x_forwarded_for，后端从这些头里读真实 IP；注意反向代理侧要能识别/覆盖伪造的 XFF，避免被客户端伪造。

2. 一台 Nginx 怎么跑多个站点？
   答：虚拟主机。多个 server 块，按 listen（端口）+ server_name（请求的 Host 头）匹配分发，一台机器一个 Nginx 实例跑多个域名。

3. HTTPS 证书的验证流程（HTTP-01）是怎样的？
   答：certbot 在站点根目录放一个随机 token 文件，CA 通过 http://域名/.well-known/acme-challenge/<token> 访问，能读到正确 token 即证明域名控制权，通过后签发证书。

4. 浏览器缓存（expires）和 Nginx 缓存（proxy_cache）区别？
   答：expires 是让「浏览器」本地缓存静态资源，Nginx 返回缓存头、后续请求浏览器不发；proxy_cache 是 Nginx 自己缓存「后端响应」，后端压力减轻。一个在客户端、一个在服务端。

5. 502 和 504 分别代表什么？
   答：502 后端无响应（服务挂了、端口不对、连接被拒）；504 后端处理超时（超过 proxy_read_timeout，慢查询/卡死导致）。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 改配置先 `nginx -t`，通过再 `reload`（不中断服务）
2. 后端只监听 127.0.0.1，统一走 Nginx 对外 + TLS 终结
3. 静态资源带版本 hash + 长缓存，HTML 页面配 no-cache
4. TLS 在 Nginx 层终结，后端走内网 HTTP，减少后端加解密开销
5. 打开 gzip + HTTP/2，文本压缩 + 多路复用
6. proxy_cache 只缓存幂等的 GET 请求，动态写接口别缓存
7. 用 `nginx -T` 看「实际生效的完整配置」（含所有 include）

### 踩坑记录

```text
坑 1：改了配置没 nginx -t 直接 reload，起不来
结论：配置语法错误导致 reload 失败，服务中断。
原因：没先测语法就加载了错误配置。
解法：改完先 nginx -t，通过再 reload；报错会指出具体行号。

坑 2：proxy_pass 结尾的 / 写错，转发路径不对
结论：后端收到错误路径，接口 404。
原因：proxy_pass 有无结尾 / 决定是否拼接 location 匹配的路径。
解法：理清规则——无 / 拼接完整路径，有 / 用 / 替换匹配前缀，按需选择。

坑 3：静态资源配了长缓存但没带版本 hash
结论：更新了 CSS/JS 但用户浏览器还读旧缓存。
原因：文件名不变 + 长缓存，浏览器一直用本地旧文件。
解法：静态资源文件名带 hash（app.a1b2c3.js），更新时文件名变、缓存自然失效；HTML 配 no-cache。

坑 4：HTTPS 证书签了但浏览器还报不安全
结论：证书错误提示。
原因：证书域名和访问域名不匹配、证书过期、或访问用的是 IP 而非域名。
解法：确认证书 SAN 覆盖访问域名、未过期、生产用正规 CA（Let's Encrypt）而非自签。

坑 5：proxy_cache 把登录态/写接口也缓存了
结论：不同用户看到相同的缓存内容，数据串号。
原因：缓存键没区分用户，或缓存了非幂等请求。
解法：缓存键加用户标识；只缓存 GET，写请求和带认证头的请求用 proxy_cache_bypass / proxy_no_cache 跳过。

坑 6：gzip 配了但响应没压缩
结论：响应头没有 Content-Encoding: gzip。
原因：gzip_types 没包含目标 MIME 类型，或文件小于 gzip_min_length 阈值。
解法：确认 gzip_types 覆盖 text/css、application/javascript 等；确认文件超过 min_length。
```

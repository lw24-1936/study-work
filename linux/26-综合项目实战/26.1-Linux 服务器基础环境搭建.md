## 概述

本项目目标：把一台全新的裸机/云主机从「刚装好系统」整理成「可安全投入生产的基础环境」，作为后续所有服务（Web、数据库、监控）的地基。完整覆盖五个环节：系统安装、分区规划、用户与权限、SSH 加固、基础软件部署。

技术栈：Ubuntu Server 22.04 LTS（Debian 系）与 Rocky Linux 9（RHEL 系）双主线，工具用 LVM（逻辑卷）、OpenSSH、UFW/firewalld、chrony、fail2ban。

前置条件：一台可装机的服务器（物理机或云主机）、有 root 或可提权账户、能连到软件源镜像。

```text
交付物：一台分区合理、账户规范、仅允许密钥登录、防火墙只放行必要端口、基础软件就绪的生产服务器
```

## 核心概念

本项目涉及的技术点：

1. **系统安装**：从 ISO 启动引导 → 选择安装介质 → 最小化安装（minimal），只装基础组件，减少攻击面和维护量。云主机直接选发行版镜像，跳过引导环节。
2. **分区规划**：用 LVM 把磁盘切成独立逻辑卷，`/var`、`/tmp`、`/home` 与 `/` 分离，防止日志/临时文件写满磁盘拖垮整个系统。
3. **用户与权限**：禁用 root 直接登录，创建普通管理账户走 sudo 提权；用 umask 收紧默认文件权限。
4. **SSH 加固**：密钥认证替代密码、禁止 root 登录、改默认端口、限制来源 IP，降低暴力破解风险。
5. **基础软件部署**：常用工具链（vim/curl/git/htop）+ 时间同步（chrony）+ Web 服务（nginx）+ 防火墙，全部用包管理器安装并交给 systemd 管理。

```text
核心概念：
系统安装（最小化）→ 分区规划（LVM 隔离）→ 用户与权限（sudo + umask）→ SSH 加固（密钥登录）→ 基础软件（systemd 托管）
```

## 工作原理

五个环节串联成一条「从裸机到可用」的流水线，前后有依赖关系：

1. **系统安装**：引导程序（GRUB）加载内核 → initramfs 挂载临时根 → 安装程序把软件包解压到目标分区 → 写引导 + 生成 initramfs → 重启进系统。
2. **分区规划（LVM 分层）**：物理卷 PV（整块分区）→ 卷组 VG（多个 PV 组成池）→ 逻辑卷 LV（从 VG 里切出的一块可挂载卷）。LV 可在线扩容，比传统分区灵活。
3. **用户与权限**：登录时 PAM 依次校验账号、密码/密钥；成功后在 `/etc/passwd` 里确定 UID，按 `/etc/group` 归属确定组；提权时 sudo 读 `/etc/sudoers` 判断是否有授权。
4. **SSH 加固**：客户端发起连接 → 服务端发主机公钥 → 客户端校验指纹 → 走密钥认证（客户端用私钥签名，服务端用 authorized_keys 里的公钥验签）→ 建立加密通道。禁用密码认证后，没有私钥的爆破流量直接在此步被拒。
5. **基础软件部署**：包管理器从镜像源下载 `.deb`/`.rpm` → 解包 + 执行安装脚本 → 生成 systemd unit → `systemctl enable` 注册开机自启。

```text
流水线依赖：
系统安装 → 分区规划（装完即定，后期难改）→ 用户与权限（先建账户再禁用 root，别把自己锁外面）→ SSH 加固 → 基础软件部署
```

## 常用命令与配置

```shell
# 系统与硬件信息
lsblk                      # 查看磁盘和分区结构
free -h                    # 内存
lscpu                      # CPU 信息
hostnamectl                # 主机名与系统信息

# 分区与 LVM
fdisk /dev/sda             # 交互式分区
pvcreate /dev/sda2         # 创建物理卷
vgcreate vg_system /dev/sda2   # 创建卷组
lvcreate -L 30G -n lv_root vg_system   # 创建逻辑卷
mkfs.ext4 /dev/vg_system/lv_root       # 格式化
mount /dev/vg_system/lv_root /mnt      # 挂载

# 用户与权限
useradd -m -s /bin/bash admin          # 建用户
usermod -aG sudo admin                 # 加入 sudo 组（Debian/Ubuntu）
usermod -aG wheel admin                # 加入 wheel 组（RHEL 系）
visudo                                  # 编辑 sudoers

# SSH
ssh-keygen -t ed25519 -C "admin@server01"   # 生成密钥
ssh-copy-id -i ~/.ssh/id_ed25519.pub admin@SERVER_IP   # 复制公钥
systemctl restart ssh                   # 重启 SSH（Debian/Ubuntu）
systemctl restart sshd                  # 重启 SSH（RHEL 系）

# 基础软件
apt update && apt install -y vim curl wget git htop net-tools chrony nginx   # Debian 系
dnf install -y vim curl wget git htop net-tools chrony nginx                 # RHEL 系
systemctl enable --now chrony           # 时间同步开机自启
```

```text
配置要点：
1. 分区用 LVM，别用传统固定分区（后期扩容麻烦）
2. 先建好 admin 账户 + 配好密钥，再禁用 root 和密码登录
3. 防火墙默认拒绝入站，只放行 SSH 端口和业务端口
```

## 配置文件解析

### /etc/ssh/sshd_config（SSH 加固核心）

```text
# 关键加固项
Port 2222                    # 改默认 22 端口（降低扫描命中率）
PermitRootLogin no           # 禁止 root 直接登录
PasswordAuthentication no    # 禁用密码认证，只允许密钥
PubkeyAuthentication yes     # 开启密钥认证
AuthorizedKeysFile .ssh/authorized_keys   # 公钥存放位置
AllowUsers admin             # 白名单，只允许 admin 登录
ClientAliveInterval 300      # 每 300 秒探测一次客户端
ClientAliveCountMax 3        # 探测 3 次无响应断开（清掉挂死的连接）
```

### /etc/sudoers（提权规则）

```text
# 通过 visudo 编辑（有语法校验，写错会锁死 sudo）
root    ALL=(ALL:ALL) ALL    # root 全权限
%sudo   ALL=(ALL:ALL) ALL    # Debian/Ubuntu：sudo 组全权限
%wheel  ALL=(ALL:ALL) ALL    # RHEL 系：wheel 组全权限
admin   ALL=(ALL) NOPASSWD: /usr/bin/systemctl   # 单用户免密跑指定命令
```

### /etc/fstab（开机挂载）

```text
# <设备>                      <挂载点>  <类型>  <选项>                  <dump> <pass>
/dev/vg_system/lv_root        /         ext4    defaults,noatime        0      1
/dev/vg_system/lv_var         /var      ext4    defaults,noatime        0      2
/dev/vg_system/lv_tmp         /tmp      ext4    defaults,noexec,nosuid,nodev  0  2
/dev/vg_system/lv_swap        none      swap    sw                      0      0
```

```text
关键选项：
noatime      不记录文件访问时间，减少写放大（适合生产）
noexec       分区内禁止执行二进制（/tmp 标配，防脚本注入执行）
nosuid,nodev 禁止 setuid 和块/字符设备（/tmp 标配）
```

## 应用场景实战

目标服务器：`server01`，IP `203.0.113.10`，系统盘 `/dev/sda` 40G，装 Ubuntu Server 22.04 LTS。从零搭建到可交付，共 8 步。

### 步骤一：系统安装（最小化）

用 UEFI 从 Ubuntu Server 22.04 LTS ISO 引导，进入安装向导：

```shell
# 关键选择（安装向导里逐项确认）
# 1. Language: English
# 2. Installation type: Ubuntu Server (minimized)  最小化安装，不装桌面
# 3. Storage: 选择整盘，勾选 Set up this disk as an LVM group
# 4. Profile: 主机名 server01，创建用户 admin（安装程序会自动加进 sudo 组）
# 5. SSH: 勾选 Install OpenSSH server（提前装好，别等进系统再补）
# 6. Featured snaps: 全部不选
```

解释：最小化安装只带基础组件，减少攻击面和后续补丁量；安装程序内建 LVM 选项，先在这里搭好基础，分区细节在步骤二调整；提前勾选 OpenSSH 可避免「装完进不去再跑一趟」的尴尬。

验证：

```shell
# 装机完成后第一件事：确认能登录
ssh admin@203.0.113.10
hostnamectl
```

示例输出：

```text
   Static hostname: server01
         Icon name: computer-vm
  Operating System: Ubuntu 22.04.3 LTS
            Kernel: Linux 5.15.0-91-generic
```

### 步骤二：分区规划（LVM 扩展调整）

安装程序默认只分一个大的 `/`，生产环境要拆开。用 LVM 命令扩出独立逻辑卷：

```shell
# 1. 看当前磁盘与 LVM 结构
lsblk
pvs && vgs && lvs

# 2. 在卷组里切出独立逻辑卷（假设卷组名 ubuntu-vg）
lvcreate -L 4G  -n lv_swap ubuntu-vg
lvcreate -L 10G -n lv_var  ubuntu-vg
lvcreate -L 5G  -n lv_home ubuntu-vg
lvcreate -L 2G  -n lv_tmp  ubuntu-vg

# 3. 格式化
mkswap /dev/ubuntu-vg/lv_swap
mkfs.ext4 /dev/ubuntu-vg/lv_var
mkfs.ext4 /dev/ubuntu-vg/lv_home
mkfs.ext4 /dev/ubuntu-vg/lv_tmp
```

解释：`lvcreate -L <大小> -n <名字> <卷组>` 从卷组剩余空间切出逻辑卷；`swap` 用 `mkswap` 初始化，普通卷用 `mkfs.ext4`。RHEL 系卷组默认叫 `rhel` 或 `rl`，命令完全一致，只换卷组名。

写入 `/etc/fstab` 并挂载：

```text
/dev/ubuntu-vg/lv_var     /var   ext4   defaults,noatime           0  2
/dev/ubuntu-vg/lv_home    /home  ext4   defaults,noatime           0  2
/dev/ubuntu-vg/lv_tmp     /tmp   ext4   defaults,noexec,nosuid,nodev  0  2
/dev/ubuntu-vg/lv_swap    none   swap   sw                         0  0
```

```shell
# 挂载新分区并启用 swap
mount -a
swapon -a
# 验证
df -h
```

示例输出：

```text
/dev/mapper/ubuntu--vg-lv_root   27G  4.1G   22G  16% /
/dev/mapper/ubuntu--vg-lv_var    9.8G  320M  9.0G   4% /var
/dev/mapper/ubuntu--vg-lv_home   4.9G   28K  4.6G   1% /home
/dev/mapper/ubuntu--vg-lv_tmp    1.9G   24K  1.8G   1% /tmp
```

解释：`mount -a` 按 fstab 挂载所有未挂载项，`swapon -a` 启用 swap；`df -h` 能看到每个逻辑卷独立占用，日志写满 `/var` 也不会撑爆 `/`。

### 步骤三：网络、主机名、时区、时间同步

```shell
# 时区（国内服务器）
timedatectl set-timezone Asia/Shanghai
# 主机名
hostnamectl set-hostname server01
# 时间同步（Ubuntu 22.04 默认 chrony；RHEL 9 默认 chrony）
systemctl enable --now chrony
chronyc sources -v          # 查看时间源
timedatectl                 # 确认 NTP service: active
```

解释：时区不对会导致日志时间错乱、排查困难；chrony 开机自启后持续从 NTP 源校准时钟，证书验证、日志时间戳、数据库都依赖准确时间。

验证：

```shell
timedatectl
```

示例输出：

```text
               Local time: Wed 2026-08-19 10:30:00 CST
           Universal time: Wed 2026-08-19 02:30:00 UTC
                 RTC time: Wed 2026-08-19 02:30:00
                Time zone: Asia/Shanghai (CST, +0800)
System clock synchronized: yes
              NTP service: active
```

### 步骤四：创建管理用户与权限

安装向导已建 admin，这里规范权限：确认 sudo 组、收紧 umask。

```shell
# 确认 admin 在 sudo 组
id admin
# 收紧全局 umask（默认 022，改成 027 让新建文件默认不给其他用户读）
# 编辑 /etc/login.defs，把 UMASK 行改成 027
sudo sed -i 's/^UMASK.*/UMASK 027/' /etc/login.defs
# 同时改 /etc/profile 里的 umask（交互登录 shell 生效）
sudo sed -i 's/^umask 022/umask 027/' /etc/profile
```

解释：`id admin` 显示用户所属组；umask 决定新建文件/目录的默认权限，`027` 表示新建文件默认 `640`（组可读、其他无权限），比默认 `022` 更安全。`sed -i` 直接原地替换两处配置。

验证：

```shell
id admin
umask
```

示例输出：

```text
uid=1000(admin) gid=1000(admin) groups=1000(admin),27(sudo)
0027
```

### 步骤五：SSH 加固（密钥登录 + 关密码 + 关 root + 改端口）

先在本机（管理员电脑）生成密钥并复制公钥，再改配置：

```shell
# 1. 本机生成 ed25519 密钥对（比 RSA 更短更快更安全）
ssh-keygen -t ed25519 -C "admin@server01"
# 2. 把公钥复制到服务器（此时还允许密码登录，会提示输入密码）
ssh-copy-id -i ~/.ssh/id_ed25519.pub admin@203.0.113.10
# 3. 测试密钥登录（应该不再要密码）
ssh -i ~/.ssh/id_ed25519 admin@203.0.113.10
```

解释：`ssh-keygen -t ed25519` 生成 Ed25519 密钥对；`ssh-copy-id` 把公钥追加到服务器的 `~/.ssh/authorized_keys`。先配好密钥再关密码，避免把自己锁在门外。

改 `/etc/ssh/sshd_config`：

```text
Port 2222
PermitRootLogin no
PasswordAuthentication no
PubkeyAuthentication yes
AllowUsers admin
```

```shell
# 4. 测试配置语法，再重启（RHEL 系服务名是 sshd）
sudo sshd -t
sudo systemctl restart ssh
```

解释：`sshd -t` 先校验配置语法，通过再重启，防止写错配置把 SSH 服务搞挂（此时你已经断开就无法远程修）。四个参数分别：改端口、禁 root、禁密码、只放行 admin。

验证（新开一个终端，旧连接保持不断）：

```shell
ssh -i ~/.ssh/id_ed25519 -p 2222 admin@203.0.113.10
# 确认 root 登录被拒
ssh -p 2222 root@203.0.113.10
```

示例输出：

```text
root@203.0.113.10: Permission denied (publickey).
```

### 步骤六：防火墙（只放行必要端口）

```shell
# Ubuntu：UFW
sudo ufw allow 2222/tcp
sudo ufw enable
sudo ufw status

# RHEL 系：firewalld
sudo firewall-cmd --permanent --add-port=2222/tcp
sudo firewall-cmd --permanent --remove-service=ssh
sudo firewall-cmd --reload
sudo firewall-cmd --list-all
```

解释：UFW 默认拒绝入站、放行出站，`allow 2222/tcp` 只开 SSH 新端口；firewalld 需 `--permanent` 写持久规则再 `--reload` 生效，顺手把默认的 `ssh`（22 端口）服务移除，避免旧端口还敞着。

验证：

```shell
sudo ufw status
```

示例输出：

```text
Status: active

To                         Action      From
--                         ------      ----
2222/tcp                   ALLOW       Anywhere
```

### 步骤七：基础软件部署

```shell
# 1. 更新源并升级现有包
sudo apt update && sudo apt upgrade -y
# RHEL 系：sudo dnf update -y

# 2. 安装常用工具链 + nginx + 时间同步（Ubuntu 已装 chrony 可跳过）

# RHEL 系：sudo dnf install -y vim curl wget git htop net-tools fail2ban nginx

# 3. nginx 开机自启并启动
sudo systemctl enable --now nginx
sudo systemctl status nginx --no-pager
```

解释：`apt update` 刷新软件源索引、`apt upgrade` 升级已装包；工具链里 `fail2ban` 会自动扫描登录日志、封禁暴力破解 IP，是 SSH 加固的配套件；nginx 作为后续 Web/反代的基础，先装好并交给 systemd 管理。

验证：

```shell
systemctl is-enabled nginx
curl -s -I http://127.0.0.1 | head -n 1
```

示例输出：

```text
enabled
HTTP/1.1 200 OK
```

## 性能与调优

```text
1. 分区挂载加 noatime —— 少记录访问时间，减少磁盘写放大
2. swap 大小按内存定 —— 内存 ≤4G 时 swap=2×内存，大内存机器 swap 可小（生产建议至少 4G 兜底）
3. 软件源换国内镜像 —— 阿里/清华镜像，更新下载快几个量级
4. /tmp 用 tmpfs（内存盘）—— 临时文件走内存，快且重启自动清空（代价是占内存）
5. 内核参数 vm.swappiness 调低到 10 —— 减少不必要的 swap 换页，优先用内存
```

```shell
# 调低 swappiness（立即生效 + 永久写入）
sudo sysctl vm.swappiness=10
echo 'vm.swappiness=10' | sudo tee /etc/sysctl.d/99-swappiness.conf
```

## 安全与权限

```text
1. 最小权限 —— admin 日常用普通权限，需要时 sudo 提权，不长期用 root
2. 禁用 root 远程登录 + 禁用密码认证，只留密钥
3. umask 027 —— 新建文件默认 640，其他用户不可读
4. /tmp 挂 noexec,nosuid,nodev —— 防脚本注入执行和 setuid 提权
5. 防火墙默认拒绝入站，只开白名单端口
6. fail2ban 自动封禁暴力破解 IP
```

```shell
# 查看 fail2ban 的 sshd 监狱状态（若已安装并启用）
sudo fail2ban-client status sshd
```

## 故障排查

### SSH 改完配置连不上

```shell
# 场景：改了 sshd_config 重启后，新连接进不去
# 关键：旧连接别断开，在旧会话里排查
sudo sshd -t                     # 先查语法
sudo tail -f /var/log/auth.log   # Debian/Ubuntu 看认证日志
sudo tail -f /var/log/secure     # RHEL 系看认证日志
# 常见原因：端口没在防火墙放行 / 公钥权限太松（~/.ssh 要 700，authorized_keys 要 600）
```

### 分区挂载失败进不了系统

```shell
# 场景：改坏 /etc/fstab，开机挂载失败进 emergency mode
# 进入紧急模式后：
mount -o remount,rw /            # 重新以读写挂载根分区
vim /etc/fstab                   # 修正错误行
reboot
# 预防：改完 fstab 先 mount -a 验证，报错立刻改回
```

### sudo 不生效

```shell
# 场景：usermod -aG sudo 后提示不在 sudoers 文件里
# 原因：组变更要重新登录才生效
id admin                         # 看是否已显示 sudo 组
# 解决：重新登录一次；若还不行，visudo 检查 /etc/sudoers 语法
sudo visudo
```

## 常见问题

```text
Q1: 为什么先建 admin 再禁用 root，而不是一开始就禁 root？
A: 禁用 root 登录后，没有别的账户就彻底进不去了。顺序必须是「建账户 + 配密钥」先完成并验证，再关 root 和密码。

Q2: 密钥登录和密码登录哪个安全？
A: 密钥登录。密码可被暴力破解或撞库；私钥只在客户端、公钥验签，且 ed25519 私钥极难暴力破解。生产环境应禁用密码登录。

Q3: LVM 分区和传统分区区别？
A: 传统分区大小固定、扩容要重分区；LVM 从卷组切逻辑卷，可在线扩容、跨盘扩展卷组，运维灵活得多。

Q4: 改 SSH 端口有意义吗？
A: 对「防暴力破解」有帮助——大量扫描脚本只打 22 端口，改端口能挡掉大部分无差别扫描；但不是安全措施本身，真正的安全靠密钥认证 + 防火墙 + fail2ban。

Q5: /tmp 为什么要 noexec？
A: 攻击者常把脚本/可执行文件写到 /tmp 再执行，noexec 让 /tmp 里的二进制无法执行，堵住这条利用链。
```

## 面试题

```text
1. 一台新服务器上线，你会做哪些基础配置？
   答：最小化安装 → LVM 分区（/var /tmp 分离、/tmp 加 noexec）→ 建 sudo 管理账户 → 密钥登录 + 禁 root + 禁密码 + 改端口 → 防火墙白名单 → 时间同步 + 常用工具 + fail2ban。

2. LVM 的三个层次是什么？各起什么作用？
   答：PV（物理卷，磁盘/分区）、VG（卷组，多个 PV 组成存储池）、LV（逻辑卷，从 VG 切出的可挂载卷）。好处是可在线扩容、跨盘扩展。

3. 如何让一台服务器只允许指定用户通过密钥登录？
   答：sshd_config 设 PermitRootLogin no、PasswordAuthentication no、AllowUsers 白名单，把公钥写入对应用户的 ~/.ssh/authorized_keys。

4. umask 022 和 027 的区别？
   答：022 新建文件默认 644（其他用户可读）、目录 755；027 新建文件默认 640（其他用户不可读）、目录 750。生产建议 027 收紧权限。

5. 改坏 sshd_config 导致连不上怎么办？
   答：若旧连接还在，用旧会话 sshd -t 查语法、修正配置后 reload；若已全断，只能走控制台/带外管理恢复。预防：改配置前先 sshd -t，且保持一个旧连接不断。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 最小化安装，不装桌面和多余组件，减少攻击面
2. 分区用 LVM，`/var`、`/tmp`、`/home` 独立，`/tmp` 加 noexec,nosuid,nodev
3. 先建 sudo 账户 + 配密钥并验证，再禁 root 和密码登录
4. 改 sshd_config 前先 `sshd -t`，且保持一个旧连接不断
5. 防火墙默认拒绝入站，只放行白名单端口
6. 时间同步（chrony）开机自启，日志和证书都依赖准确时间
7. 交付前跑一遍完整验证清单，别靠「感觉配置好了」

### 踩坑记录

```text
坑 1：先禁 root 再建账户，把自己锁在门外
结论：服务器彻底进不去，只能走控制台。
原因：PermitRootLogin no 之后，没有可用账户登录。
解法：顺序固定——先建 admin + 配密钥并验证能登录，再关 root 和密码。

坑 2：改 sshd_config 没先 sshd -t，重启后 SSH 挂了
结论：配置语法错误，sshd 起不来，远程全部断连。
原因：直接 restart 加载了错误配置。
解法：改完先 sudo sshd -t 校验，通过再 reload；改配置时保持一个旧会话不断。

坑 3：改 fstab 没先 mount -a 验证，开机进 emergency mode
结论：重启后挂载失败，系统进紧急模式。
原因：fstab 写错（设备名/选项拼错），开机挂载直接失败。
解法：改完 fstab 先 mount -a 验证，报错立刻改回再重启。

坑 4：usermod -aG sudo 后 sudo 还是不认
结论：提示用户不在 sudoers 文件里。
原因：组变更要重新登录才生效，当前会话还是旧组信息。
解法：重新登录一次，或 su - admin 切新会话再 sudo。

坑 5：改 SSH 端口但防火墙没放行，重启后连不上
结论：SSH 端口改了、防火墙还只放行 22，新连接被墙。
原因：改了 sshd_config 的 Port，忘了同步防火墙规则。
解法：改端口时同步更新防火墙（ufw allow 2222/tcp / firewall-cmd --add-port）。

坑 6：authorized_keys 权限太松，密钥登录被拒
结论：密钥登录报 Permission denied (publickey)。
原因：~/.ssh 或 authorized_keys 权限过松（group/other 可写），sshd 默认拒绝使用。
解法：chmod 700 ~/.ssh && chmod 600 ~/.ssh/authorized_keys。
```

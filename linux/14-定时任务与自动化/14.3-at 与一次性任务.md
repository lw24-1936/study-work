## 概述

cron 是「周期任务」，at 是「一次性任务」——在指定时间执行一次，执行完就没了。at 适合「定时执行一次」的场景（如「30 分钟后重启服务」「今晚 11 点跑一次迁移」）。batch 是 at 的变体（系统空闲时执行）。anacron 是「补跑错过的周期任务」（机器关机没跑的任务，开机后补）。三者补全了 cron 的定时任务体系。

```text
三种任务类型：
1. cron —— 周期任务（每天/每小时重复）
2. at —— 一次性任务（指定时间执行一次）
3. anacron —— 补跑错过的周期任务（关机期间没跑的任务）
```

```text
# 实测（本机 at 未安装）
$ command -v at || echo "at 未安装"
at 未安装
# at 不是默认安装，用前 apt install at
```

## 核心概念

1. **at**：在指定时间执行一次命令，`at 时间` 进入交互（或管道传命令），到点执行，执行完任务就从队列消失。
2. **batch**：at 的变体，不指定时间，在「系统负载低时」执行，适合不紧急的耗时任务。
3. **anacron**：解决 cron 的缺陷——机器关机错过了任务不补跑。anacron 记录上次执行时间，开机时检查并补跑错过的任务。
4. **atd 守护进程**：at 的后台服务，负责调度 at/batch 队列里的任务。

```text
at 时间格式：
now + 30 minutes   30 分钟后
23:00              今晚 23 点
tomorrow           明天
02:00 08/20        8 月 20 号 2 点
```

## 工作原理

at 的任务队列由 atd 守护进程维护：提交 at 任务后，命令被序列化存到 /var/spool/at/ 的队列文件里，atd 每分钟检查一次队列，把「到点」的任务取出来执行（执行环境和提交时一致），执行完删除队列文件。

anacron 则是「补跑」机制：它不追求精确时间，而是记录每个任务上次执行的时间戳（/var/spool/anacron/）。开机时 anacron 检查「哪些任务距离上次执行已超过周期」，超过就补跑。因此 anacron 只支持「每天/每周/每月」粒度（分钟级没意义，因为只开机时检查）。

```text
at 工作流程：
提交 at 任务 → 存 /var/spool/at/ 队列 → atd 每分钟检查 → 到点执行 → 删除队列

anacron 补跑流程：
开机 → 对比上次执行时间戳 → 超过周期的任务补跑 → 更新时间戳
```

## 常用命令与配置

```shell
at now + 30 minutes          # 30 分钟后执行（进入交互输入命令）
at 23:00                    # 今晚 23 点执行
echo "reboot" | at 02:00    # 凌晨 2 点重启（管道传命令）
atq                         # 看任务队列
atrm 3                      # 删 3 号任务
batch                        # 系统空闲时执行（进入交互）
systemctl status atd        # 确认 atd 服务在跑
```

```text
# 实测（本机有 anacron）
$ ls /etc/cron.d/anacron
/etc/cron.d/anacron
# 本机装了 anacron，负责补跑 cron.daily/weekly/monthly 错过的任务
```

## 配置文件解析

anacron 的配置在 /etc/anacrontab：

```text
# /etc/anacrontab 格式（周期 延迟 任务名 命令）
7    10    cron.daily    run-parts --report /etc/cron.daily
30   15    cron.weekly   run-parts --report /etc/cron.weekly
@monthly 45 cron.monthly run-parts --report /etc/cron.monthly
```

```text
字段含义：
周期（天）   超过这个天数没跑就补跑（7 = 7 天）
延迟（分钟） 开机后延迟多久执行（避免开机瞬间集中跑）
任务名      时间戳文件名（/var/spool/anacron/任务名）
命令        执行什么（通常 run-parts 跑目录下脚本）
```

at 的任务队列文件在 /var/spool/at/，每个任务一个文件，内容是序列化的命令 + 环境。

## 应用场景实战

### 场景一：定时一次性执行（30 分钟后重启服务）

```shell
# 1. 30 分钟后重启 nginx
echo "systemctl restart nginx" | at now + 30 minutes
# 2. 看任务队列
atq
# 3. 取消（如果改主意了）
atrm <任务号>
```

### 场景二：给 anacron 加一个「保证每天执行」的任务

```shell
# 1. 写脚本
cat > /opt/scripts/daily-sync.sh <<'EOF'
#!/bin/bash
rsync -av /data/ /backup/data/
EOF
chmod +x /opt/scripts/daily-sync.sh
# 2. 放到 /etc/cron.daily/（anacron 会保证它每天执行，错过补跑）
cp /opt/scripts/daily-sync.sh /etc/cron.daily/
```

## 性能与调优

```text
1. 延迟执行 —— anacron 的「延迟」字段让任务错开开机瞬间，避免集中跑打爆 IO
2. batch 择机 —— 耗时不紧急的任务用 batch，系统空闲时再跑，不抢业务资源
3. 队列清理 —— at 队列文件执行完自动删，无需手动维护
4. 任务合并 —— 多个一次性任务别拆太碎，能合并成一个脚本一次执行
```

## 安全与权限

```text
1. at.allow/at.deny —— 控制谁能用 at（/etc/at.allow 白名单优先）
2. 执行身份 —— at 任务以提交时的用户身份执行，别用 root 提交不必要任务
3. 队列文件权限 —— /var/spool/at/ 只有 atd 可读，任务内容防泄露
4. 敏感命令 —— at 提交的命令会序列化存储，别放明文密码
```

## 故障排查

### at 任务没执行

```shell
# 1. 确认 atd 服务在跑
systemctl status atd
# 2. 看任务是否在队列
atq
# 3. 看 atd 日志
journalctl -u atd -n 50
```

### at 任务执行了但看不到结果

```shell
# 1. at 输出默认发邮件（可能没配），改重定向到日志
echo "cmd > /var/log/at.log 2>&1" | at now + 5 minutes
# 2. 确认任务是否已执行（队列消失）
atq
```

## 常见问题

```text
Q1: at 命令不存在？
A: at 不是默认安装，apt install at，并确认 atd 服务启动。

Q2: at 任务执行了但看不到结果？
A: at 输出默认发邮件（可能没配邮件）。命令里重定向输出到日志（> /var/log/at.log 2>&1）。

Q3: 笔记本关机错过 cron 任务，开机后没补跑？
A: cron 不补跑错过的任务，用 anacron（/etc/cron.daily/ 等）或 systemd timer 的 Persistent=true。

Q4: anacron 能配分钟级任务吗？
A: 不能。anacron 只支持每天/每周/每月粒度，分钟级用 cron 或 systemd timer。
```

## 面试题

```text
1. at 和 cron 的区别？
   答：cron 是周期任务（重复执行），at 是一次性任务（指定时间执行一次）。

2. anacron 解决什么问题？
   答：机器关机错过 cron 周期任务不补跑的问题，开机后检查并补跑错过的任务。

3. batch 和 at 的区别？
   答：batch 是 at 变体，不指定具体时间，在系统负载低时执行，适合不紧急的耗时任务。

4. at 任务的执行结果默认去哪？
   答：默认通过邮件发给提交用户，没配邮件则丢失，所以通常重定向到日志。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 「执行一次」用 at，「周期执行」用 cron，「保证执行」用 anacron
2. at 不是默认安装，用前 apt install at
3. at 命令用管道传比交互式更适合脚本化
4. 桌面/笔记本（常关机）用 anacron 保证周期任务补跑
5. at 任务的输出会发邮件（或重定向到日志）

### 踩坑记录

```text
坑 1：at 命令不存在
结论：敲 at 报 command not found。
原因：at 不是默认安装。
解法：apt install at，并确认 atd 服务启动。

坑 2：at 任务执行了但看不到结果
结论：at 到点执行了，但不知道成功还是失败。
原因：at 的输出默认发邮件（可能没配邮件），看不到。
解法：at 命令里重定向输出到日志（> /var/log/at.log 2>&1）。

坑 3：cron 任务在笔记本关机时错过，以为会补跑
结论：笔记本关机错过 cron 任务，开机后没补跑。
原因：cron 不补跑错过的任务（这是 anacron 的职责）。
解法：用 anacron（/etc/cron.daily/ 等），或 systemd timer 的 Persistent=true。

坑 4：anacron 不支持分钟级任务
结论：想在 anacron 里配「每 5 分钟」任务，不生效。
原因：anacron 只支持每天/每周/每月粒度。
解法：分钟级任务用 cron 或 systemd timer。

坑 5：at 时间写错，任务没执行
结论：at 时间格式写错，任务没跑。
原因：at 的时间解析有规则，写错会拒绝或执行时间不对。
解法：atq 看队列确认，at 时间格式多试或看 man at。
```

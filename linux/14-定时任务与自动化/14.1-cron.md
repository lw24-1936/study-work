## 概述

cron 是 Linux 的定时任务系统，按时间表周期执行命令（如每天备份、每小时清理、每分钟心跳）。配置分两种：用户级（crontab -e，每个用户自己的任务）和系统级（/etc/crontab、/etc/cron.d/、/etc/cron.daily/ 等）。crontab 语法是「五段式时间 + 命令」，特殊字符串（@daily/@reboot）是快捷写法。注意 cron 的环境变量精简，脚本里要写全路径。

```text
cron 定时任务系统：
1. 用户级 —— crontab -e 编辑自己的任务，crontab -l 查看
2. 系统级 —— /etc/crontab、/etc/cron.d/*、/etc/cron.daily/
3. 语法 —— 分 时 日 月 周 + 命令（五段式）
4. 特殊字符串 —— @daily/@hourly/@reboot 快捷写法
```

## 核心概念

1. **crontab 五段式语法**：每一行是「分（0-59）时（0-23）日（1-31）月（1-12）周（0-7）+ 命令」，`*` 任意、`*/N` 每 N、`1,3,5` 列举、`1-5` 范围。
2. **用户级与系统级**：用户级（crontab -e，存 /var/spool/cron/，以该用户身份执行）；系统级（/etc/crontab、/etc/cron.d/、/etc/cron.daily/，可指定执行用户）。
3. **特殊字符串**：@reboot（开机）、@daily（每天）、@hourly、@weekly、@monthly、@yearly，是五段式的快捷别名。
4. **环境变量**：cron 执行时环境极简（PATH 不含 /usr/local/bin、不读 .bashrc），脚本要用绝对路径。

```text
crontab 五段式：
分 时 日 月 周
0  3  *  *  *     每天 3:00
*/5 * * * *      每 5 分钟
0  9  *  *  1-5   工作日 9:00
30 2  1  *  *     每月 1 号 2:30

符号：
*      任意
*/N    每 N（如 */5 = 每 5）
1,3,5  列举
1-5    范围
```

## 工作原理

cron 由守护进程 crond 驱动：crond 每分钟醒来一次，检查所有 crontab（用户级 /var/spool/cron/* + 系统级 /etc/crontab、/etc/cron.d/*），把「当前分钟匹配」的任务取出来，fork 子进程执行。执行环境是最小化的 shell（sh），不加载用户的 .bashrc/.profile，所以 PATH 等环境变量精简。任务输出默认通过邮件发给任务属主（没配 MTA 就丢弃）。

```text
cron 工作流程：
crond 每分钟醒来 → 检查所有 crontab → 匹配当前分钟的任务 → fork 子进程执行（最小化环境）
```

## 常用命令与配置

```shell
crontab -e            # 编辑当前用户的定时任务
crontab -l            # 查看当前用户的定时任务
crontab -r            # 删除所有定时任务（慎用）
crontab -u alice -l   # 看某用户的任务（root）
systemctl status cron # 确认 crond 服务在跑
```

```text
# 实测（本机系统级 cron）
$ ls /etc/cron.d/
anacron  dsh-cert-renew  e2scrub_all  sysstat
$ ls /etc/cron.daily/
0anacron  apport  apt-compat  dpkg  logrotate  man-db  sysstat
# /etc/cron.d/ 是系统级任务（含 dsh-cert-renew 证书续期），
# /etc/cron.daily/ 是每天执行的脚本（logrotate/sysstat 等）
```

## 配置文件解析

系统级 crontab /etc/crontab 比用户级多一列「执行用户」：

```text
# /etc/crontab 格式（多一列用户名）
分 时 日 月 周 用户 命令
17 *    * * *   root  cd / && run-parts --report /etc/cron.hourly
25 6    * * *   root  test -x /usr/sbin/anacron || run-parts /etc/cron.daily
47 6    * * 7   root  test -x /usr/sbin/anacron || run-parts /etc/cron.weekly
52 6    1 * *   root  test -x /usr/sbin/anacron || run-parts /etc/cron.monthly
```

```text
字段含义：
五段式时间（分 时 日 月 周）+ 执行用户 + 命令
run-parts —— 依次执行目录下的所有脚本（/etc/cron.daily 等）
```

用户级 crontab 存在 /var/spool/cron/crontabs/（Debian）或 /var/spool/cron/（RHEL），格式是五段式 + 命令（无用户列）。

## 应用场景实战

### 场景一：每天凌晨 3 点备份数据库

```shell
# 1. 写备份脚本（绝对路径）
cat > /opt/scripts/db-backup.sh <<'EOF'
#!/bin/bash
/usr/bin/mysqldump -uroot mydb | /usr/bin/gzip > /backup/mydb-$(date +%F).sql.gz
EOF
chmod +x /opt/scripts/db-backup.sh
# 2. 加 crontab
crontab -e
# 加：0 3 * * * /opt/scripts/db-backup.sh
# 3. 验证
crontab -l
```

### 场景二：cron 任务手动能跑、定时不跑，排查环境

```shell
# 1. 看 cron 的报错（发到邮件或日志）
grep CRON /var/log/syslog | tail
# 2. 检查是不是 PATH 问题
# 手动 which 命令，对比 cron 环境
# 3. 脚本里写全路径 + 重定向日志
0 3 * * * /opt/scripts/backup.sh >> /var/log/backup.log 2>&1
```

## 性能与调优

```text
1. 触发密度 —— 别设 */1 * * * * 的高频任务做重活，合理规划触发间隔
2. 错峰执行 —— 多个任务别都堆在同一分钟，用不同分钟错开，避免瞬间负载
3. 日志重定向 —— 输出重定向到文件，避免邮件积压/每次 fork 邮件进程
4. 轻量任务 —— 每分钟跑的任务要极轻量（健康检查/心跳），重活放到低频
```

## 安全与权限

```text
1. cron.allow/cron.deny —— 控制谁能用 crontab（/etc/cron.allow 白名单优先）
2. 用户级任务以该用户身份执行 —— 别用 root 跑不必要的任务，最小权限
3. 脚本权限 —— cron 脚本只 root/属主可写，防被篡改注入恶意命令
4. 敏感信息 —— 脚本里别硬编码密码（用环境变量/密钥文件）
```

## 故障排查

### 任务没执行

```shell
# 1. 确认 crond 服务在跑
systemctl status cron
# 2. 看 cron 日志
grep CRON /var/log/syslog | tail
# 3. 确认 crontab 语法和路径
crontab -l
```

### 任务执行了但结果不对

```shell
# 1. 手动执行脚本对比
/opt/scripts/backup.sh
# 2. 看重定向的日志
tail /var/log/backup.log
# 3. 检查环境变量差异（PATH/依赖）
```

## 常见问题

```text
Q1: cron 任务手动能跑，定时不跑？
A: cron 环境变量精简（PATH 不含 /usr/local/bin、不读 .bashrc），脚本用绝对路径或 crontab 显式设 PATH。

Q2: cron 任务失败看不到报错？
A: 输出没重定向，报错丢了。命令后加 >> /var/log/xxx.log 2>&1。

Q3: 周字段 0 和 7 什么区别？
A: 都表示周日，0 和 7 等价。五段式顺序是「分 时 日 月 周」。

Q4: crontab -r 把任务全删了怎么办？
A: -r 是删除所有任务。平时 crontab -l > backup 备份，别误用 -r。
```

## 面试题

```text
1. crontab 五段式分别代表什么？
   答：分（0-59）时（0-23）日（1-31）月（1-12）周（0-7，0 和 7 都是周日）。

2. cron 任务为什么手动能跑、定时不跑？
   答：cron 用最小化环境（PATH 精简、不读 .bashrc），命令/依赖找不到。用绝对路径或显式设 PATH。

3. 用户级和系统级 crontab 的区别？
   答：用户级 crontab -e（存 /var/spool/cron/，以该用户身份跑）；系统级 /etc/crontab、/etc/cron.d/（多一列执行用户，系统维护）。

4. @reboot 任务依赖服务没起来怎么办？
   答：脚本里加「等依赖就绪」逻辑（sleep + 检测），或改用 systemd service 的 After= 声明依赖。
```

## 最佳实践与踩坑记录

### 最佳实践

1. cron 脚本用绝对路径，别依赖登录 shell 的环境变量
2. 任务输出重定向到日志（>> log 2>&1），否则看不到报错
3. 备份/清理类任务放凌晨（避开业务高峰）
4. 系统级任务放 /etc/cron.d/（可指定用户），个人任务用 crontab -e
5. 改完 crontab 用 crontab -l 确认，测试任务可以先设成 */1 分钟验证

### 踩坑记录

```text
坑 1：cron 任务手动能跑，定时不跑
结论：脚本手动执行正常，cron 定时执行失败。
原因：cron 环境变量精简（PATH 不含 /usr/local/bin 等），找不到命令/依赖。
解法：脚本用绝对路径，或 crontab 显式设 PATH。

坑 2：cron 任务没输出，报错看不到
结论：任务失败但不知道原因。
原因：cron 的 stdout/stderr 没重定向，报错丢了（或发到没人看的邮件）。
解法：命令后加 >> /var/log/xxx.log 2>&1 重定向。

坑 3：crontab 语法写错（周和日的 0/7）
结论：任务没按预期执行。
原因：周字段 0 和 7 都是周日，或五段式位置写错。
解法：确认五段式顺序（分时日月周），周 0=7=周日。

坑 4：crontab -r 误删所有任务
结论：crontab -r 把所有定时任务删了。
原因：-r 是删除（remove），-l 才是查看，手滑敲成 -r。
解法：crontab -l > backup 定期备份，别乱用 -r。

坑 5：@reboot 任务在开机时依赖的服务还没起
结论：@reboot 脚本执行失败，因为依赖的数据库/网络还没起来。
原因：@reboot 开机就执行，但依赖服务可能还没就绪。
解法：脚本里加「等依赖服务就绪」的逻辑（sleep + 检测），或用 systemd 的 After=。
```

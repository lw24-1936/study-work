## 概述

systemd timer 是 systemd 的定时任务机制，替代 cron 的现代化方案。原理：一个 .timer 单元 + 一个 .service 单元，timer 定义「什么时候触发」，service 定义「执行什么」。比 cron 的优势：集成 systemd（日志进 journald、可看状态、失败可重试）、时间表达式更灵活、按服务管理。现代系统推荐用 timer 做系统级定时任务。

```text
systemd timer 原理：
1. .timer 单元 —— 定义触发时间（OnCalendar/OnBootSec）
2. .service 单元 —— 定义执行的任务
3. 配合 —— timer 触发时激活同名 service
```

```text
# 实测（本机 systemd timer）
$ systemctl list-timers --all | head
NEXT                          UNIT                  ACTIVATES
Tue 23:30:00 CST   sysstat-collect.timer      sysstat-collect.service
Tue 23:32:32 CST   anacron.timer              anacron.service
Wed 00:00:00 CST   logrotate.timer            logrotate.service
Wed 00:00:00 CST   dpkg-db-backup.timer       dpkg-db-backup.service
# 系统里已有一堆 timer：sysstat 采集、logrotate 轮转、anacron 等
```

## 核心概念

1. **timer unit**：定义「什么时候触发」，两种触发方式——单调时间（OnBootSec 开机后 N 秒、OnUnitActiveSec 上次激活后 N 秒）和墙钟时间（OnCalendar 日历时间）。
2. **service 配对**：timer 文件放 /etc/systemd/system/，和同名 service 配对（foo.timer 激活 foo.service）。
3. **OnCalendar**：日历时间表达式，比 cron 五段式更灵活可读，格式 `星期 年-月-日 时:分:秒`。
4. **Persistent**：错过的时间（如关机期间）开机后补跑。

```text
触发方式：
单调时间 —— OnBootSec（开机后 N 秒）、OnUnitActiveSec（上次激活后 N 秒）
墙钟时间 —— OnCalendar（日历时间，如 daily、Mon..Fri 09:00）
```

## 工作原理

timer 单元注册到 timers.target 后，systemd 在内存里维护每个 timer 的下次触发时间点。到点时，systemd 激活同名的 .service 单元执行任务，执行结果记录在 journald 里（journalctl -u 服务名 可查）。若配了 Persistent=true，timer 会记录「上次应触发但没触发」的时间，开机后补跑。相比 cron 每分钟轮询，timer 是「到点精确唤醒」，更省资源、更精确。

```text
timer 工作流程：
timer 注册到 timers.target → systemd 维护下次触发时间 → 到点激活同名 service → 日志进 journald
```

## 常用命令与配置

```shell
systemctl list-timers                 # 查看所有 timer
systemctl list-timers --all           # 含禁用的
systemctl enable --now mytask.timer   # 启用 timer
systemctl status mytask.timer         # 看状态和下次触发时间
systemctl daemon-reload               # 改 timer 文件后重载
systemd-analyze calendar "Mon..Fri 09:00"   # 验证 OnCalendar 表达式
```

## 配置文件解析

timer 单元文件结构：

```ini
# /etc/systemd/system/mytask.timer
[Unit]
Description=Run mytask daily

[Timer]
OnCalendar=daily
Persistent=true          # 错过的时间补跑

[Install]
WantedBy=timers.target
```

```text
关键字段：
[Timer] OnCalendar     日历触发表达式（daily、Mon..Fri 09:00）
[Timer] OnBootSec      开机后 N 秒触发
[Timer] OnUnitActiveSec  上次激活后 N 秒触发
[Timer] Persistent     true 则错过的时间补跑
[Install] WantedBy     timers.target（让 timer 随系统启用）
```

对应的 service 单元：

```ini
# /etc/systemd/system/mytask.service
[Unit]
Description=Run mytask

[Service]
Type=oneshot              # 执行完即退出（定时任务常用）
ExecStart=/opt/scripts/mytask.sh
```

## 应用场景实战

### 场景一：用 timer 做每天定时备份

```ini
# 1. /etc/systemd/system/backup.service
[Unit]
Description=Daily Backup
[Service]
Type=oneshot
ExecStart=/opt/scripts/backup.sh

# 2. /etc/systemd/system/backup.timer
[Unit]
Description=Run backup daily
[Timer]
OnCalendar=*-*-* 03:00:00
Persistent=true
[Install]
WantedBy=timers.target
```

```shell
# 3. 启用
systemctl daemon-reload
systemctl enable --now backup.timer
# 4. 验证
systemctl list-timers backup.timer
journalctl -u backup.service
```

### 场景二：查看系统里所有定时任务

```shell
# 1. 看所有 timer
systemctl list-timers --all
# 2. 看某个 timer 的详情（下次触发时间）
systemctl status logrotate.timer
# 3. 看 timer 对应的 service 执行日志
journalctl -u logrotate.service
```

## 性能与调优

```text
1. 精确唤醒 —— timer 到点精确触发，比 cron 每分钟轮询更省资源
2. 触发间隔 —— 别设过密（如每 1 秒）的 timer，systemd 也要调度开销
3. 日志 —— journalctl -u 服务名 自动留痕，比 cron 手动重定向省事
4. oneshot 类型 —— 定时任务用 Type=oneshot，执行完即退不常驻
```

## 安全与权限

```text
1. 单元文件权限 —— /etc/systemd/system/*.timer 要 root 可写，防被篡改
2. 执行用户 —— service 里 User=/Group= 指定执行身份，别默认 root
3. 环境隔离 —— ExecStart 用绝对路径，避免依赖登录环境
4. 敏感信息 —— 用 EnvironmentFile= 引密钥文件，别硬编码
```

## 故障排查

### timer 改了不生效

```shell
# 1. 重载 systemd 配置
systemctl daemon-reload
# 2. 确认下次触发时间
systemctl status mytask.timer
# 3. 验证表达式
systemd-analyze calendar "Mon..Fri 09:00"
```

### timer 触发失败（service 报错）

```shell
# 1. 看 service 执行日志
journalctl -u mytask.service -n 50
# 2. 确认 service 和 timer 同名配对
ls /etc/systemd/system/mytask.*
# 3. 手动跑一次 service 验证脚本本身
systemctl start mytask.service
```

## 常见问题

```text
Q1: 改了 timer 文件为什么不生效？
A: systemd 缓存旧文件，改完要 systemctl daemon-reload。

Q2: timer 触发了但报 unit not found？
A: timer 和 service 要同名配对（foo.timer → foo.service），确认 service 存在。

Q3: 关机错过触发时间，开机后没补跑？
A: 默认 Persistent=false。加 Persistent=true，错过的时间开机后补跑。

Q4: Type=oneshot 的 service 状态显示 dead，是失败了吗？
A: oneshot 执行完就退出，状态不是 active 是正常的，看 journalctl 日志确认结果。
```

## 面试题

```text
1. systemd timer 和 cron 的区别？
   答：timer 集成 systemd（日志进 journald、状态可查、失败可重试、依赖管理），表达式更灵活；cron 更简单、生态成熟。系统级任务用 timer。

2. timer 的两种触发方式？
   答：单调时间（OnBootSec/OnUnitActiveSec）和墙钟时间（OnCalendar）。

3. Persistent=true 的作用？
   答：错过触发时间（如关机期间）开机后补跑，保证任务不丢。

4. timer 和 service 怎么配合？
   答：同名配对，foo.timer 定义触发时间，到点激活 foo.service 执行任务。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 系统级/服务级定时任务优先用 timer（集成 systemd）
2. 配 Persistent=true，错过的时间（如关机期间）补跑
3. timer 的日志自动进 journald，journalctl -u 服务名 查看
4. 改 timer 文件后 systemctl daemon-reload
5. timer 和 cron 可共存，按场景选

### 踩坑记录

```text
坑 1：改了 timer 文件没 daemon-reload，不生效
结论：改了 OnCalendar，触发时间还是老的。
原因：systemd 缓存了旧 timer 文件。
解法：改完 systemctl daemon-reload。

坑 2：timer 配了但 service 没写，触发失败
结论：timer 触发了，但报 unit not found。
原因：timer 和 service 要同名配对（foo.timer → foo.service），缺 service。
解法：确认同名 service 存在。

坑 3：没配 Persistent，关机期间的任务没补跑
结论：机器关机错过了触发时间，开机后任务没补执行。
原因：默认 Persistent=false，错过就错过。
解法：加 Persistent=true，错过的时间开机后补跑。

坑 4：OnCalendar 语法写错，触发时间不对
结论：OnCalendar 表达式写错，任务没在预期时间跑。
原因：OnCalendar 格式和 cron 不同，容易写错。
解法：systemd-analyze calendar "表达式" 验证，看下次触发时间。

坑 5：Type=oneshot 的 service 反复触发，状态不对
结论：oneshot 服务在 timer 触发后状态显示 failed/dead，以为失败。
原因：oneshot 执行完就退出，状态不是 active，是正常的。
解法：理解 oneshot 语义（执行完即退），看 journalctl 日志确认执行成功。
```

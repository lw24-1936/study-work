## 概述

sed 是「流编辑器」（stream editor），按行读入、处理、输出，默认不修改原文件（除非用 -i）。它最擅长三件事：替换（s/旧/新/）、删除（/模式/d）、按地址范围操作（sed -n '2,5p'）。和 grep 只过滤不同，sed 能真正改内容，所以常用来做批量替换、删行、提取片段。它的执行模型是「模式空间 + 保持空间」两个缓冲区，理解这一点才能看懂高级用法。

```text
sed 三件核心能力：
1. 替换 —— s/旧/新/标志，g 全局、i 忽略大小写、\1 & 引用捕获
2. 删除 —— /模式/d 删匹配行、地址范围删段落
3. 地址范围 —— 行号/模式/组合，指定命令作用于哪些行
```

除这三件外，sed 还能**插入/追加行**（i/a）、**修改整行**（c）、以及用**保持空间**做跨行操作。脚本语法是「地址 + 命令」：地址决定「对哪些行」，命令决定「做什么」，中间的分号 `;` 分隔多条命令。

## 核心概念

sed 的核心概念是「替换、删除、增行、地址范围」四类操作。

### 替换

替换是 sed 最常用的功能，语法 `s/旧/新/标志`。分隔符 `/` 可换成别的字符（处理含 `/` 的路径时用 `s|/a/b|/c/d|`）。标志 `g` 是全局替换（默认只替换每行第一个）、`i` 忽略大小写、`p` 同时打印。替换里 `\1 \2` 引用捕获组、`&` 引用整个匹配内容，能做「把 user=alice 改成 用户=alice」这类结构变换。

```shell
# 默认只替换每行第一个匹配
sed 's/INFO/信息/' /tmp/demo.txt | head -1
# 全局替换 + 捕获组：把 action=xxx 换成 动作=xxx
sed -E 's/action=(\w+)/动作=\1/g' /tmp/demo.txt | head -2
```

```text
# 实测
$ sed 's/INFO/信息/' /tmp/demo.txt | head -1
2026-08-18 10:00:01 信息  user=alice action=login  ip=10.0.0.1
$ sed -E 's/action=(\w+)/动作=\1/g' /tmp/demo.txt | head -2
2026-08-18 10:00:01 INFO  user=alice 动作=login  ip=10.0.0.1
2026-08-18 10:00:05 ERROR user=bob   动作=query  ip=10.0.0.2
```

```text
替换标志速查：
g   全局替换（默认只替换每行第一个）
i   忽略大小写
p   同时打印被替换的行（配合 -n 只看改动行）
数字  只替换每行第 N 处匹配（如 s/a/b/2 换第 2 个 a）
w 文件  把被替换的行写入指定文件
e   （GNU）把替换结果当 shell 命令执行，慎用
```

```shell
# 替换里引用 & 和捕获组：给日期加括号
echo '2026-08-18' | sed -E 's/^([0-9]{4})-([0-9]{2})-([0-9]{2})/\1年\2月\3日/'
# 输出：2026年08月18日
```

```shell
# 数字标志：只替换每行第 2 个 a
echo 'aa bb aa' | sed 's/a/A/2'
# 输出：aA bb aa（第 1 个 a 没动，第 2 个变 A）
```

```text
替换易错点：
- & 在替换串里代表整个匹配，字面 & 要写成 \&
- 分隔符 / 与内容里的 / 冲突时换分隔符 s|a|b| 或 s#a#b#
- 捕获组在 BRE 下要转义 \(...\)，ERE（-E）直接写 (...)
- 大小写转换 \U \L \u \l 是 GNU 扩展，BSD sed 不支持
```

### 删除

`/模式/d` 删除匹配的行，`sed -n 'N, M d'` 删除地址范围。删除常用于「去掉日志里的干扰行」——比如分析前先把 DEBUG 级别、已知无害的行删掉，剩下的就是有效信息。注意 d 删除的是模式空间里的整行，删除后不输出、直接读下一行。

```shell
# 删除所有 ERROR 行
sed '/ERROR/d' /tmp/demo.txt
```

```text
# 实测（6 行删掉 3 行 ERROR，只剩 INFO/WARN）
2026-08-18 10:00:01 INFO  user=alice action=login  ip=10.0.0.1
2026-08-18 10:01:00 WARN  user=carol action=login  ip=10.0.0.3
2026-08-18 10:02:00 INFO  user=dave  action=logout ip=10.0.0.4
```

```shell
# 删除空行
sed '/^$/d' 文件
# 删除 3 到 5 行（地址范围）
sed '3,5d' 文件
# 删除从 START 到 END 之间的所有行（含两边界）
sed '/START/,/END/d' 文件
```

```text
删除易错点：
- d 删除的是「整行」，不是行内某段文字——删文字要用 s/旧/空/
- 多条件删除用 ; 或 -e 串联：sed '/^#/d; /^$/d' 删注释行和空行
- 地址范围 /START/,/END/ 若 END 从未出现，会一直删到文件末尾
```

### 插入与追加

`i\` 在匹配行之前插入一行（insert），`a\` 在匹配行之后追加一行（append）。它们和替换、删除的区别是「增行」而非「改行」。典型用途是批量给配置文件的某个段落前后加注释标记、给日志分段加分隔线。命令里 `\` 后的内容是插入的文本。

```shell
# 在第 2 行之后追加一行
sed '2a\---- 追加行 ----' /tmp/demo.txt | head -3
```

```text
# 实测
2026-08-18 10:00:01 INFO  user=alice action=login  ip=10.0.0.1
2026-08-18 10:00:05 ERROR user=bob   action=query  ip=10.0.0.2
---- 追加行 ----
```

```shell
# i 在第 2 行之前插入
sed '2i\---- 插入行 ----' /tmp/demo.txt | head -3
# 按模式追加：在每行 ERROR 之后加一条分隔线
sed '/ERROR/a\==== 以上是错误 ====' /tmp/demo.txt | head -4
```

```text
插入/追加易错点：
- i\ 和 a\ 后面的 \ 是命令的一部分，插入文本直接跟在后面
- 插入多行内容用 \n 或反斜杠续行（不同版本写法略有差异）
- 想替换整行（而非前后加行）用 c 命令：sed '2c\新内容'
- a 命令在每行后追加时，可以用 r 命令从文件读入内容代替
```

### 地址范围

sed 的「地址」指定命令作用于哪些行，可以是行号、模式，或两者的范围组合。`sed -n '2,4p'` 打印 2~4 行，`sed '/开始/,/结束/d'` 删除从「开始」到「结束」之间的所有行（常用于删掉日志里某段报错块）。地址范围让 sed 从「逐行处理」升级到「按段落处理」。

```shell
# 只打印第 2~4 行
sed -n '2,4p' /tmp/demo.txt
```

```text
# 实测
2026-08-18 10:00:05 ERROR user=bob   action=query  ip=10.0.0.2
2026-08-18 10:01:00 WARN  user=carol action=login  ip=10.0.0.3
2026-08-18 10:01:10 ERROR user=alice action=upload ip=10.0.0.1
```

```text
地址的六种形式：
1. 行号     2p、3d（第 2 行、第 3 行）
2. 末行     $p（最后一行）
3. 正则     /ERROR/p（匹配 ERROR 的行）
4. 范围     2,5 或 /a/,/b/（区间，含两端）
5. 取反     2!p（除第 2 行外全部）
6. 步长     （GNU）1~2p（从第 1 行起每隔 2 行）
```

```shell
# 末行、取反、步长组合演示
sed -n '$p' /tmp/demo.txt                    # 最后一行
sed -n '2!p' /tmp/demo.txt | head -2         # 除第 2 行外
sed -n '2~2p' /tmp/demo.txt                  # 第 2、4、6 行（每隔 2 行）
```

```shell
# 相对地址：从第 2 行起连续 3 行（含第 2 行）
printf '1\n2\n3\n4\n5\n6\n' | sed -n '2,+2p'
```

```text
# 实测
2
3
4
```

```shell
# 0,/re/：从文件头到第一个匹配（GNU 扩展，区别于 1,/re/ 从第 1 行算起）
printf 'a\nb\na\n' | sed -n '0,/a/p'
# 正则地址忽略大小写（GNU 的 I 标志）
printf 'A\nb\na\n' | sed -n '/a/Ip'
```

```text
# 实测
a
A
a
```

```text
地址进阶补充：
- 相对范围 addr,+N：从 addr 起连续 N 行（含 addr），如 2,+2 作用于 2~4 行
- 0,/re/（GNU）：把「第 0 行」当起始，作用域覆盖文件头到第一个匹配；1,/re/ 若第 1 行就匹配，只会作用于第 1 行
- /re/I（GNU）：正则地址忽略大小写
- 步长 first~step：从 first 行起每隔 step 行；0~2 会匹配所有偶数行（GNU 扩展，BSD sed 不支持）
```

### 模式空间与保持空间

sed 每处理一行都用到两个缓冲区：**模式空间**（当前行的工作区）和**保持空间**（跨行暂存区）。平时只操作模式空间，一旦要「跨行拼内容」（反转行序、合并相邻行、段落重组），就得在两者之间搬运数据。

```text
保持空间命令：
h  模式空间 → 保持空间（覆盖）
H  模式空间 → 保持空间（追加，加换行）
g  保持空间 → 模式空间（覆盖）
G  保持空间 → 模式空间（追加，加换行）
x  两者交换
N  读入下一行并追加到模式空间（跨行操作的另一个入口）
```

```shell
# 经典用法：反转文件行序（每行先把之前的积累追加到自己后面，最后一行整体输出）
sed -n '1!G;h;$p' /tmp/demo.txt
```

```text
# 输出（顺序倒置，最后一行跑到最前）
2026-08-18 10:02:30 ERROR user=eve   action=login  ip=10.0.0.5
2026-08-18 10:02:00 INFO  user=dave  action=logout ip=10.0.0.4
2026-08-18 10:01:10 ERROR user=alice action=upload ip=10.0.0.1
2026-08-18 10:01:00 WARN  user=carol action=login  ip=10.0.0.3
2026-08-18 10:00:05 ERROR user=bob   action=query  ip=10.0.0.2
2026-08-18 10:00:01 INFO  user=alice action=login  ip=10.0.0.1
```

```shell
# N 命令：把下一行读到模式空间，配合 s 做跨行替换
# 把「foo\nbar」两行合并成一行（用逗号连接）
printf 'foo\nbar\nbaz\n' | sed 'N;s/\n/,/'
# 输出：foo,bar 和 baz（两两合并）
```

```text
保持空间易错点：
- h/H/g/G 的「覆盖 vs 追加」容易记混：大写 = 追加（加换行），小写 = 覆盖
- N 读完文件末尾后没有下一行时会直接终止（不输出最后一行），跨行脚本要处理边界
- 这些是 sed 里最抽象的部分，能用 awk 表达清楚的跨行逻辑就别硬上 sed
```

N 之外还有三个跨行命令常被忽略，但对「窗口滑动」「延迟一行输出」这类需求很关键：

```shell
# D：删除模式空间中第一个换行之前的部分，剩余部分继续处理（不读新行）
# 经典滑动窗口 N;D：始终只保留「最后读到的一行」，最终输出最后一行
printf 'a\nb\nc\nd\ne\n' | sed 'N;D'
```

```text
# 实测（输出最后一行）
e
```

```shell
# P：打印模式空间中第一个换行之前的部分；D 只删到第一个换行
# N;P;D：两行一批读入，逐行打印，等价于把整个文件原样输出
printf 'a\nb\nc\nd\ne\n' | sed 'N;P;D'
# 单独 D：每行都删光，什么都不输出
printf 'a\nb\nc\n' | sed 'D'
```

```text
# 实测
a
b
c
d
e
（第二条 D 命令无输出）
```

```text
多行命令速查（在模式空间内按「换行」切分行）：
N  读入下一行并追加到模式空间末尾（加换行）
P  打印模式空间第一个换行之前的部分（「第一行」）
D  删除模式空间第一个换行之前的部分，剩余部分继续执行（不读新行）
d  删除整个模式空间，然后读下一行（与 D 的关键区别）
h/H/g/G/x  保持空间搬运（覆盖 / 追加 / 交换）
```

```text
N/P/D 易错点：
- N 在文件末尾取不到下一行时，会输出当前模式空间后终止——所以 N;D 能打印出最后一行
- D 删除第一行后若模式空间还有内容，会继续执行命令而不读新输入，这是滑动窗口的机制
- D 与 d 不要混：d 删整行后读下一行；D 只删到第一个换行，剩下的继续跑
- 能改用 awk 表达的跨行逻辑（尤其多字段、多条件）优先 awk，sed 的多行命令可读性差
```

### 分支与测试（b / t / :标签）

sed 的脚本不只是顺序执行，还支持跳转，能做「条件分支」和「循环」：

```text
b 标签   无条件跳到 :标签 处（不传标签则跳到脚本末尾，结束本行处理）
t 标签   若本轮循环里上一次 s/// 替换成功，则跳到 :标签；否则继续（不传标签则跳到末尾）
:标签    定义跳转目标（标签名任意字母数字）
```

```shell
# b 分支：匹配到 line2 就跳到脚本末尾（跳过后续命令），其余行照常替换
printf 'line1\nline2\nline3\n' | sed 's/line/LINE/; /LINE2/b; s/LINE3/END/'
```

```text
# 实测
LINE1
LINE2
END
```

```shell
# t 测试：只有 s 替换成功才跳转，做「替换过就不再处理」的短路逻辑
printf 'apple\nbanana\ncherry\n' | sed 's/apple/APPLE/; t found; b end; :found; s/.*/命中替换/; :end'
```

```text
# 实测
命中替换
banana
cherry
```

```text
b/t 易错点：
- 标签定义用 :名称，跳转用 b 名称 / t 名称，名字要一致
- b 不带标签 = 结束本行处理（等价于直接读下一行）；t 不带标签 = 若替换过就结束本行
- t 判断的是「上一次替换是否成功」，不是「是否命中某地址」，多分支逻辑容易写错
- 复杂分支建议直接换 awk（有 if/else/for/while），sed 的标签跳转可读性差
```

## 工作原理

sed 的执行模型是「逐行读入 → 执行命令 → 输出」的循环，核心在「模式空间」和「保持空间」两个缓冲区：

1. **模式空间（pattern space）**：sed 每次读入一行放到模式空间，对模式空间依次执行脚本里的命令（s/d/p/a/i...），然后输出模式空间内容，读下一行。这就是「流编辑」——一行进、一行出。
2. **保持空间（hold space）**：另一个辅助缓冲区，用于跨行操作。相关命令：`h` 把模式空间复制到保持空间、`H` 追加、`g` 把保持空间复制回模式空间、`G` 追加、`x` 两者交换。

最经典的应用是「反转文件行序」：`sed -n '1!G;h;$p'` —— 每行先读入、把之前积累的内容追加到它后面，最后一行时全部输出，就实现了倒序。这个技巧是理解 sed 双缓冲区的钥匙。

```shell
# 用保持空间反转行序
sed -n '1!G;h;$p' /tmp/demo.txt
```

```text
# 实测（输出顺序倒过来了，最后一行跑到最前）
2026-08-18 10:02:30 ERROR user=eve   action=login  ip=10.0.0.5
2026-08-18 10:02:00 INFO  user=dave  action=logout ip=10.0.0.4
2026-08-18 10:01:10 ERROR user=alice action=upload ip=10.0.0.1
2026-08-18 10:01:00 WARN  user=carol action=login  ip=10.0.0.3
2026-08-18 10:00:05 ERROR user=bob   action=query  ip=10.0.0.2
2026-08-18 10:00:01 INFO  user=alice action=login  ip=10.0.0.1
# 拆解：1!G（非首行时把保持空间追加到模式空间后）、h（当前行存入保持空间）、$p（最后一行打印）
```

```text
逐行执行模型（每行完整跑一遍脚本）：
读一行 → 模式空间 → 依次执行脚本命令 → 默认输出模式空间 → 读下一行
-a/i 的输出不经过模式空间，直接进输出流
-d 终止本行后续命令，直接读下一行
-N 额外读入下一行到模式空间，跨行操作靠它
```

## 常用命令与配置

sed 的高频命令与选项速查：

```shell
sed 's/旧/新/' file        # 替换每行第一个
sed 's/旧/新/g' file       # 全局替换
sed '/模式/d' file         # 删除匹配行
sed -n '2,5p' file         # 只打印 2~5 行（-n 抑制默认输出）
sed '2a\文本' file          # 第 2 行后追加
sed '2i\文本' file          # 第 2 行前插入
sed '2c\文本' file          # 第 2 行整行替换
sed -i 's/旧/新/' file     # 直接写回文件
sed -i.bak 's/旧/新/' file # 写回并留 .bak 备份
sed -E 's/(a)=(b)/\1x\2/' file  # -E 扩展正则 + 捕获组
sed -e 's/a/A/' -e '/B/d' file  # 多条命令串联
sed -f rules.sed file      # 从脚本文件读命令
```

```text
选项分工：
-n 抑制默认输出（配合 p 只打印选中行）
-i 原地写回（危险，配合 .bak 留备份）
-E/-r 扩展正则（捕获组不用转义）
-f 从脚本文件读 sed 命令（可复用）
-e 多条命令串联（等价于用 ; 分隔）
```

还有四个 GNU sed 选项，处理「特殊分隔 / 多文件 / 实时输出 / 调试」时用得上：

```shell
# -z：以 NUL（\0）而不是换行作为「行」分隔，处理含换行的整块内容
printf 'a\x00b\x00c\x00' | sed -z 's/a/A/; s/c/C/' | od -c
```

```text
# 实测（\0 分隔的块被当「行」处理，替换后仍保留 \0）
0000000   A  \0   b  \0   C  \0
0000006
```

```shell
# -s：把每个输入文件当作独立流处理，$ 变成「每个文件各自的最后一行」
printf 'x\ny\n' > /tmp/f_a.txt
printf 'x\ny\n' > /tmp/f_b.txt
sed -n '$p' /tmp/f_a.txt /tmp/f_b.txt      # 不加 -s：只匹配整体最后一行
sed -s -n '$p' /tmp/f_a.txt /tmp/f_b.txt   # 加 -s：每个文件的最后一行都打印
```

```text
# 实测

y
y          （加 -s，两个文件各自末尾都打印）
```

# -u：无缓冲输出，边读边写（默认 sed 对大输出有块缓冲，配合管道实时看进度用）

选项边界：
- -z 是 GNU 扩展，BSD/macOS 的 sed 不支持；配合 find -print0 / xargs -0 处理带空格或换行的文件名
- -s 常用于「对一批文件分别做同一替换但 $ / 首行语义要按文件算」的场景，配合 -i 多文件原地替换

## 配置文件解析

sed 没有独立配置文件，但它的命令可以组织成可复用的「sed 脚本文件」：

```text
1. 把多条 sed 命令写进 .sed 文件，用 sed -f script.sed 加载执行，
   相当于「sed 的配置」——复杂编辑规则集中管理、可复用
2. 脚本文件里每条命令一行，注释用 #（部分 sed 版本支持）
3. 示例 rules.sed 内容：
   /^#/d              # 删注释行
   s/ +$//            # 去行尾空格
   s/ERROR/错误/g     # 全局替换
   用法：sed -f rules.sed 输入文件
```

```text
GNU sed 与 BSD（macOS）sed 的关键差异：
- -E：GNU 和 BSD 都支持；-r 只有 GNU 支持（BSD 会报错）
- -i：GNU 可裸写 -i；BSD 必须带后缀 sed -i '' 或 sed -i .bak
- \s、\+：GNU 扩展；BSD 用 [[:space:]]、\+ 的写法也略有差异
- 跨平台脚本优先写 -E、[[:space:]]、sed -i.bak 这类两边通用的写法
```

```text
Red Hat / CentOS / RHEL 系的差异（红帽系默认也是 GNU sed，与 Ubuntu 一致）：
- 上面说的 GNU 扩展（-E、-i 裸写、\\U\\L、b/t 标签、-z、-s）在红帽系同样可用，
  不需要像 macOS 那样做「去 GNU 化」处理
- 版本差异才是坑：RHEL 7 / CentOS 7 自带的 sed 是 4.2.2（2012），比较老——
  不支持 -E（GNU sed 4.3 才加入，老版本只有 -r）、也没有 --debug（4.9 才加入）
- RHEL 8 是 sed 4.5、RHEL 9 是 sed 4.8，都支持 -E 和 -z
- 给 CentOS 7 写脚本时用 -r 而不是 -E 才兼容；-z 在 4.2.2 已有
- 结论：跨平台脚本分两档——只覆盖 Linux（含红帽系）可用 GNU 扩展；要覆盖 macOS
  必须按上面「GNU vs BSD」那条做裁剪（-E、-i 带后缀、避开 \\s/\\+/-z/-s）
```

## 应用场景实战

### 场景一：批量修改配置文件里的监听端口

```shell
# 把 nginx 配置里的 80 端口改成 8080（-i 直接写回，先备份）
sed -i.bak 's/listen 80;/listen 8080;/g' /etc/nginx/sites-available/default
# 确认改动
grep -n 'listen' /etc/nginx/sites-available/default
```

### 场景二：从日志里抽取一段报错上下文

```shell
# 打印从第一个 ERROR 到下一个 INFO 之间的行（报错块）
sed -n '/ERROR/,/INFO/p' /tmp/demo.txt | head
```

```text
# 输出（ERROR 到 INFO 之间的一整段）
2026-08-18 10:00:05 ERROR user=bob   action=query  ip=10.0.0.2
2026-08-18 10:01:00 WARN  user=carol action=login  ip=10.0.0.3
2026-08-18 10:01:10 ERROR user=alice action=upload ip=10.0.0.1
2026-08-18 10:02:00 INFO  user=dave  action=logout ip=10.0.0.4
```

### 场景三：清理配置文件的注释行、空行与行尾空格

```shell
# 删 # 开头注释、删空行、去行尾空格，输出干净配置
sed -e '/^#/d' -e '/^[[:space:]]*$/d' -e 's/[[:space:]]*$//' /etc/nginx/nginx.conf | head
```

```text
# 说明
- /^#/d            删除以 # 开头的注释行
- /^[[:space:]]*$/d  删除空行（含只有空白字符的行）
- s/[[:space:]]*$// 去掉每行末尾的空白字符
# 这是「拿配置去 diff / 归档」前的标准清洗动作，三步一条命令完成
```

```text
生产注意：清理用管道输出到屏幕先看效果，确认无误再 -i 写回。
清洗动作对配置文件是「有损」的——删掉的注释可能带着重要说明，先备份再动。
```

### 场景四：批量把 Windows 换行（CRLF）转成 Unix 换行（LF）

Windows 编辑过的文件带回车换行 `\r\n`，在 Linux 上会导致脚本报 `\r` 相关错误、`file` 显示 "with CRLF line terminators"。本机没装 dos2unix 时，用 sed 一行等价替代，且 `-i` 一次能处理多个文件：

```shell
# 先确认是 CRLF
printf 'a\r\nb\r\n' > /tmp/crlf1.txt
printf 'c\r\nd\r\n' > /tmp/crlf2.txt
file /tmp/crlf1.txt
# 多文件一次性去掉行尾 \r，并留 .bak 备份
sed -i.bak 's/\r$//' /tmp/crlf1.txt /tmp/crlf2.txt
od -c /tmp/crlf1.txt | head -1
ls /tmp/crlf*.bak
```

```text
# 实测
/tmp/crlf1.txt: ASCII text, with CRLF line terminators
0000000   a  \n   b  \n
/tmp/crlf1.txt.bak
/tmp/crlf2.txt.bak
```

```text
说明：
- s/\r$// 匹配行尾的回车符并删除；\n 是行分隔符不在模式空间里，所以只需处理 \r
- sed -i 支持一次传多个文件（GNU 的 -i 可带文件列表），批量转码很方便
- 等价替代：tr -d '\r' < 旧 > 新 或 perl -pi -e 's/\r\n/\n/g'，都无需 dos2unix
- 反向（LF 转 CRLF）用 sed 's/$/\r/'，注意 \r 是 GNU 扩展，BSD sed 不认
```

## 性能与调优

```text
1. sed 是单行流式处理，比 awk 轻，简单替换/删除优先用 sed
2. 用地址范围限定处理行，避免对无关行执行替换
3. -i 写回会新建临时文件再改名，大文件操作时注意磁盘空间
4. 复杂跨行/多字段逻辑用 awk，别在 sed 里硬塞
5. 多个 sed 串成管道时合并成一条 sed -e '...' -e '...'，少起进程
6. 只提取不修改时加 -n + p，抑制默认输出，减少不必要的 I/O
```

实测量级（本机 200 万行、15MB 的 /tmp/big.txt，同一次替换/计数任务下 sed / awk / grep 对比）：

```shell
seq 1 2000000 > /tmp/big.txt   # 200 万行
time sed 's/1999/X/g' /tmp/big.txt > /dev/null
time awk '{gsub(/1999/,"X"); print}' /tmp/big.txt > /dev/null
time grep -c '1999' /tmp/big.txt
```

```text
# 实测（三次 time 的 real 时间）
sed 全局替换:  real 0m0.176s   user 0m0.174s
awk gsub:     real 0m0.210s   user 0m0.205s
grep -c 计数: real 0m0.014s   （结果 1600）
```

```text
选型结论：
- 只做「匹配/计数/过滤」选 grep：纯读 + 不输出内容，比 sed/awk 都快一个量级
- 单行「替换/删除」选 sed：比 awk 略快、写法更短
- 多字段、按列计算、多条件组合选 awk：gsub 后还要 print 每个字段，开销更高，但这是 sed 做不了的
- 需要递归搜代码 + 高亮 + 忽略 .gitignore 时用 rg（本机 ripgrep 14.1.0），但它是「搜索」不是「替换」，sed 的批量替换无法被 rg 替代
- sed -i 的额外成本：写回 = 写临时文件 + rename，比纯输出多一次完整 I/O，大文件批量替换优先「管道输出到新文件再 mv」而非反复 -i
```

## 安全与权限

```text
1. -i 原地写回是破坏性操作，改系统配置前必留 .bak 备份
2. sed -i 对符号链接会「替换链接本身」而非目标文件，改配置时要确认目标
3. 用 sed 处理含敏感信息的文件时，别把中间结果输出到日志
4. 批量替换脚本里的替换串若来自用户输入，注意元字符转义
5. 替换串里的 &、\1 是元字符，用户输入要按字面处理时先转义 & 和 \
```

两条高危点要单独拎出来说：

```text
命令注入（真 RCE 风险）：GNU sed 的 e 标志会把替换结果当 shell 命令执行
- echo 'echo hello' | sed 's/.*/&/e'  → 实际执行了 echo hello，输出 hello
- 若替换内容来自用户输入，e 标志等于给了对方一个 shell，绝对不能对未清洗输入用 e
- 生产里禁用 e；真需要「把文本当命令执行」用 xargs 或显式 shell，别藏在 sed 里
```

```shell
# 变量未转义 & 会「吃掉」整个匹配（不是注入，但结果错）
v='A&B'; echo 'x y' | sed "s/y/$v/"     # 输出 x AyB（& 被展开成匹配内容 y）
v2='A\&B'; echo 'x y' | sed "s/y/$v2/"  # 输出 x A&B（转义后才是字面 &）
```

```text
# 实测
x AyB
x A&B
```

```text
转义与注入小结：
- 替换串来自变量时，把 & 换成 \&、\ 换成 \\、分隔符 / 换成其它字符或用 s|...|...|
- 更稳的做法：不用 sed 的变量拼接，改用 awk -v（变量当值传，不参与脚本语法解析）
- sed 脚本要放在单引号里（'s/.../.../'），避免 shell 先展开 $、反引号、$(...) 导致意外命令替换
```

```text
ReDoS 不存在于 sed：
- sed 的 s/// 用的是 POSIX BRE/ERE，引擎是线性 DFA（GNU sed 用 glibc regcomp 的 DFA 路径），
  没有回溯，不会出现「灾难性回溯」——这是 sed 正则相对 PCRE 的一个安全优势
- ReDoS（a*a*a... 类指数级回溯）只出现在 PCRE 类回溯引擎（grep -P、Python re、JS 正则）
- 所以用 sed 做正则替换不用担心构造恶意模式拖垮 CPU；但恶意输入仍可能匹配极慢的
  「超长行 + 复杂 ERE」，量级有限、不是 ReDoS
```

```text
权限相关：
- sed -i 写 /etc 下配置需要 root，普通用户会 Permission denied；sudo 时临时文件在目标
  目录旁生成，目录不可写会失败
- sed -i 内部是「写临时文件 + rename」，会改变文件 inode、破坏硬链接和符号链接指向
  ——对用硬链接去重、或 /etc/alternatives 这类符号链接管理的文件，别用 -i，用「输出到新文件 + 手动替换」
```

## 故障排查

```text
「替换不生效」排查顺序：
1. 忘了 -i —— 默认只输出到屏幕不改文件，加 -i 才写回
2. 忘了 g —— 只替换了每行第一个，加 g 全局
3. 分隔符冲突 —— 替换内容含 / 时报错，换分隔符 s|...|...|
4. 地址范围不对 —— 先 sed -n '...p' 预览选中的行，确认范围
5. 正则方言 —— 捕获组 \1 在 BRE 下要转义 \(...\)，或用 -E

「范围删多了/删少了」：
- /a/,/b/ 若 b 从未出现会删到文件末尾；先用 sed -n '/a/,/b/p' 预览再执行

「macOS 上报 unknown option -- r / 乱码」：
- BSD sed 不支持 -r，改用 -E；-i 要带后缀 sed -i '' 或 -i.bak
```

常见报错原文与对应排查（本机 GNU sed 4.9 实测）：

```shell
# 1. 命令码写错
echo 'abc' | sed 'Z'
# 2. s 命令分隔符不配对（少写一个 /）
echo 'abc' | sed 's/abc'
```

```text
# 实测
sed: -e 表达式 #1, 字符 1: 未知的命令：“Z”
sed: -e 表达式 #1, 字符 5: 未终止的“s”命令
```

```text
报错对照：
- 「未知的命令」= 脚本里出现了 sed 不认的命令码（Z/X 等），检查是否拼错、或用错方言
- 「未终止的 s 命令」= s/// 三个分隔符没凑齐，替换串里有裸 / 时最容易触发，换分隔符 s|..|..|
- 「invalid option -- r」= BSD/macOS sed 不支持 -r，改 -E
- 「unknown option -- i」= BSD sed 的 -i 必须跟后缀，写成 sed -i.bak 或 sed -i ''
```

```text
「argument list too long」（处理海量文件）：
- sed -i 's/x/y/' *.log 在目录里有几万个 .log 时，shell 展开 *.log 超过 ARG_MAX 会报
  bash: /usr/bin/sed: Argument list too long
- 解法：find . -name '*.log' -exec sed -i 's/x/y/' {} + （+ 会分批，不超限），
  或 find ... -print0 | xargs -0 sed -i 's/x/y/'
```

```text
「中文/多字节字符被按字节处理」：
- 默认 zh_CN.UTF-8 下 sed 按「字符」处理；LC_ALL=C 下按「字节」处理，
  多字节汉字会被拆成字节逐个替换，结果数量翻倍
- 实测：printf '你好\n' | sed 's/./X/g'        → XX（2 个字符）
        printf '你好\n' | LC_ALL=C sed 's/./X/g' → XXXXXX（6 个字节）
- 处理中文要保证 LC_ALL 是 UTF-8（默认就是），别在脚本里随手 export LC_ALL=C
  （除非你就是想按字节处理，如转码、删控制字节）
```

## 常见问题

```text
Q1: sed -i 和先输出到临时文件再 mv 有什么区别？
A: -i 内部就是「写临时文件 + 改名」，但会破坏符号链接和硬链接，且不留备份时无法回滚。改重要文件用 -i.bak。

Q2: 为什么 s/旧/新/ 只替换了每行第一个？
A: 默认只替换第一个匹配，加 g 标志才全局替换。

Q3: 怎么删除文件中所有空行？
A: sed '/^$/d' file。

Q4: 替换内容里有 & 或 / 怎么办？
A: & 要写成 \&（字面量），/ 换成别的分隔符如 s|a|b|。

Q5: 怎么只替换每行的第 N 处匹配？
A: 用数字标志：s/旧/新/2 只替换每行第 2 个；s/旧/新/2g 从第 2 个起全替换。

Q6: sed -E 和 sed -r 有什么区别？
A: 作用一样（扩展正则），-r 是 GNU 老写法，-E 是 POSIX/BSD 通用写法。跨平台（含 macOS）脚本用 -E。

Q7: sed 怎么在匹配行前/后插入多行内容？
A: i\ 和 a\ 后面跟插入文本，多行用 \n 或反斜杠续行；内容很多时用 r 命令从文件读入：sed '/pattern/r 文件'。

Q8: sed -i 和「输出到临时文件再 mv」到底差在哪？
A: -i 内部就是「写临时文件 + rename」，会改变 inode、破坏硬链接和符号链接指向；手动输出到新文件可以控制覆盖时机、先 diff 再决定。对符号链接管理的文件（如 /etc/alternatives）别用 -i。

Q9: sed 怎么做大小写转换？
A: GNU sed 用 \U（转大写）、\L（转小写）、\u（首字母大写）、\l（首字母小写），如 sed 's/.*/\U&/' 全行转大写。这些是 GNU 扩展，BSD sed 不支持，跨平台要用 tr 或 awk。

Q10: 怎么把相邻两行合并成一行？
A: 用 N 读入下一行再替换换行：sed 'N;s/\n/ /' 把两行合成一行（空格连接）。注意 N 到文件末尾会终止，行数奇数时最后一行会丢，用 $!N 规避。

Q11: sed 的 b / t / 标签是干嘛的，什么时候用？
A: b 是无条件跳转、t 是「上次替换成功才跳转」，配合 :标签 能做条件分支和循环。适合「替换成功就跳过后续命令」这类短路逻辑；复杂分支（if/else/循环）建议直接换 awk，sed 的标签可读性差。

Q12: -z 和 -s 选项分别解决什么问题？
A: -z 用 NUL（\0）代替换行当「行」分隔，处理含换行的整块数据（配合 find -print0/xargs -0）；-s 把每个输入文件当独立流，$ 变成「每个文件各自的最后一行」，配合 -i 批量处理多文件时按文件算语义。两者都是 GNU 扩展。
```

## 面试题

```text
1. sed 和 grep 的本质区别？
   答：grep 只过滤（输出匹配行），sed 能编辑（替换/删除/增行）。sed 默认输出所有行，grep 只输出匹配行。

2. sed 的模式空间和保持空间是什么？
   答：模式空间是每行处理的工作区，保持空间是跨行操作的临时缓冲区，靠 h/H/g/G/x 命令在两者间搬运数据。

3. 怎么用 sed 只替换第 3 行的内容？
   答：sed '3s/旧/新/' file，地址 3 限定只作用于第 3 行。

4. sed -i 有什么风险？
   答：原地写回不可逆，改错无备份就丢数据；且会破坏符号链接。应加 .bak 后缀留备份。

5. sed 的地址可以有哪些形式？
   答：行号（2）、末行（$）、正则（/re/）、范围（2,5 或 /a/,/b/）、取反（2!）、步长（GNU 的 1~2）。地址决定命令作用于哪些行。

6. 怎么用 sed 反转文件行序？
   答：sed -n '1!G;h;$p' file。靠保持空间：每行把之前的积累追加到自己后面，最后一行整体输出。

7. sed -i 和 sed -i.bak 差别，生产里为什么重要？
   答：-i 直接覆盖无备份，-i.bak 覆盖前留 .bak 副本。改系统配置或批量替换一旦写错，有备份才能回滚，所以生产环境写回必带后缀。

8. sed 的 N 和 D 命令分别做什么？组合起来有什么经典用法？
   答：N 读入下一行并追加到模式空间（跨行操作入口）；D 删除模式空间中第一个换行之前的部分、剩余内容继续处理（不读新行）。经典组合 N;D 是滑动窗口，最终只输出最后一行。

9. 怎么删除文件的第 2 到第 5 行？
   答：sed '2,5d' file。地址范围 2,5 限定命令作用于第 2~5 行，d 删除整行。想反着来（只保留 2~5 行）用 sed -n '2,5p' file。

10. sed 的 b 和 t 命令有什么区别？
   答：b 是无条件跳转到标签；t 是「本轮循环里上一次 s/// 替换成功才跳转」，否则顺序继续。t 常用于「替换成功后跳过后续处理」的短路逻辑。

11. sed 替换时怎么引用捕获组和整个匹配内容？
   答：替换串里 \1 \2... 引用第 1、2... 个捕获组（BRE 下要 \(...\) 转义，-E 下直接 (...)），& 引用整个匹配。例：echo abc123 | sed -E 's/([a-z]+)([0-9]+)/\2-\1/' 得 123-abc。

12. 为什么 sed 脚本要写在单引号里？
   答：防止 shell 先展开脚本里的 $、反引号、$(...)、! 等。双引号里 $1 会被 shell 展开成位置参数、! 触发历史扩展，导致脚本不是预期的样子。单引号内一切按字面传给 sed。

13. sed 的 e 标志（GNU）有什么风险？
   答：e 会把替换结果当 shell 命令执行，若替换内容来自用户输入就是命令注入 RCE。生产里禁用 e；需要「把文本当命令执行」应显式用 xargs 或 shell。

14. 怎么用 sed 只打印匹配某模式的行（类似 grep）？
   答：sed -n '/模式/p' file。-n 抑制默认输出，p 只打印匹配的行，效果等同 grep '模式' file。反过来「打印不匹配的行」用 sed -n '/模式/!p'。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 默认不带 -i，先在屏幕确认结果，再 -i 写回
2. 用 -i 改重要文件时加后缀备份（-i.bak），出错了能回滚
3. 处理含 / 的路径换分隔符 s|/a|/b|，别用一堆 \/ 转义
4. 全局替换记得加 g，否则只换每行第一个
5. 跨多行/复杂变换优先用 awk，sed 适合单行内的增删改
6. 多条编辑命令合并成一条 sed -e '...' -e '...'，少起进程
7. 跨平台脚本用 -E 而非 -r，-i 带后缀，避免 BSD/macOS 差异

### 踩坑记录

```text
坑 1：忘了加 g 只替换了每行第一个
结论：一行多个目标词只换了第一个，剩下的没动。
原因：s/旧/新/ 默认只替换每行第一个匹配。
解法：要全换加 g 标志：s/旧/新/g。

坑 2：替换内容里的 & 和 \1 被特殊处理
结论：想把文本里的 & 字面量替换进去，结果 & 变成了整个匹配内容。
原因：替换串里 & 代表整个匹配、\1 代表捕获组，是元字符。
解法：字面 & 要写成 \&，或改用 awk 的 sub/gsub。

坑 3：sed -i 直接改坏了原文件没备份
结论：批量替换写错，原文件被覆盖。
原因：-i 直接写回文件，没有留底。
解法：用 sed -i.bak 留备份，或先输出到临时文件对比后再覆盖。

坑 4：地址范围 /开始/,/结束/ 匹配不到预期
结论：范围选择的行比预期多或少。
原因：范围是「第一个开始到第一个结束」，重复模式时容易错位。
解法：先用 sed -n '...p' 打印预览范围，确认后再执行操作。

坑 5：分隔符 / 与路径冲突导致语法错误
结论：sed 's//usr//opt/' 报错或行为错乱。
原因：替换含 / 的路径时，/ 分隔符和路径里的 / 混在一起。
解法：换分隔符 sed 's|/usr|/opt|'，或转义每个 /。

坑 6：macOS 上报错 unknown option 或 -i 行为不同
结论：同一脚本在 Linux 正常、macOS 报 sed: illegal option -- r 或 -i 出错。
原因：BSD sed 不支持 -r，且 -i 必须带后缀（sed -i ''）。
解法：跨平台统一用 -E、sed -i.bak，别裸写 -r 和 -i。

坑 7：范围 /a/,/b/ 在 b 不出现时删到文件末尾
结论：sed '/START/,/END/d' 结果把 END 之后的内容也删光了。
原因：范围的结束模式 END 从未匹配到时，范围会一直延伸到文件末尾。
解法：先 sed -n '/START/,/END/p' 预览确认 END 确实存在，再执行删除。

坑 8：替换串里的变量没转义 &，结果被替换成匹配内容
结论：v='A&B' 时 sed "s/y/$v/" 得到 x AyB，而不是 x A&B。
原因：替换串里 & 是元字符，代表整个匹配内容。
解法：变量进替换串前把 & 转成 \&（\ 转成 \\、分隔符换掉），或改用 awk -v 传变量避开元字符。

坑 9：替换含 / 的路径时报「未终止的 s 命令」
结论：sed 's//usr//opt/' 报错或行为错乱。
原因：路径里的 / 和 s/// 的分隔符混在一起，sed 分不清哪个是分隔符。
解法：换分隔符 sed 's|/usr|/opt|' 或 sed 's#/usr#/opt#'，或逐个转义 \/。

坑 10：N 命令处理奇数行文件时丢最后一行
结论：两行合并用 sed 'N;s/\n/ /'，最后一行（奇数时）没输出。
原因：N 在文件末尾取不到下一行会终止整个 sed，最后一行不进入输出。
解法：用 sed '$!N;s/\n/ /' 跳过末行，或处理完再单独补最后一行。

坑 11：LC_ALL=C 下处理中文，多字节字符被按字节替换
结论：printf '你好' | LC_ALL=C sed 's/./X/g' 输出 XXXXXX（6 个 X），而不是 XX。
原因：C locale 下 sed 按字节处理，一个 UTF-8 汉字 3 字节被当成 3 个「字符」。
解法：处理中文保持 LC_ALL=zh_CN.UTF-8（默认就是），别在脚本里随手 export LC_ALL=C。

坑 12：sed -i 破坏了符号链接/硬链接
结论：对 /etc/alternatives 这类符号链接用 -i，链接本身被替换成普通文件，目标没被改。
原因：-i 内部是「写临时文件 + rename」，会换掉 inode，链接关系随之丢失。
解法：对符号链接/硬链接管理的文件，用「输出到新文件 + 手动替换」，别用 -i。

坑 13：把 GNU 扩展当通用，在老 RHEL 7 或 macOS 上报错
结论：CentOS 7 上 sed -E 报 invalid option，macOS 上 sed 's/$/\r/' 报错。
原因：-E 是 GNU sed 4.3 才加入（RHEL 7 的 4.2.2 只有 -r）；\r、\s、-z 等是 GNU 扩展，BSD sed 不认。
解法：老红帽用 -r；跨平台（含 macOS）用 -E + -i.bak + [[:space:]]，避开 \r/\s/-z/-s 等 GNU 扩展。
```

## 概述

sed 是「流编辑器」（stream editor），按行读入、处理、输出，默认不修改原文件（除非用 -i）。它最擅长三件事：替换（s/旧/新/）、删除（/模式/d）、按地址范围操作（sed -n '2,5p'）。和 grep 只过滤不同，sed 能真正改内容，所以常用来做批量替换、删行、提取片段。它的执行模型是「模式空间 + 保持空间」两个缓冲区，理解这一点才能看懂高级用法。

```text
sed 执行模型：
1. 逐行读入到「模式空间」（pattern space），对模式空间执行命令，输出，读下一行
2. 「保持空间」（hold space）是另一个辅助缓冲区，用于跨行操作
3. 常用命令 —— s 替换 / d 删除 / p 打印 / a 追加 / i 插入 / n 下一行
```

## 替换

替换是 sed 最常用的功能，语法 `s/旧/新/标志`。分隔符 `/` 可换成别的字符（处理含 `/` 的路径时用 `s|/a/b|/c/d|`）。标志 `g` 是全局替换（默认只替换每行第一个）、`i` 忽略大小写、`p` 同时打印。替换里 `\1 \2` 引用捕获组、`&` 引用整个匹配内容，能做「把 user=alice 改成 用户=alice」这类结构变换。

```shell
# 默认只替换每行第一个匹配
sed 's/INFO/信息/' /tmp/demo.txt | head -1
# 全局替换 + 捕获组：把 action=xxx 换成 动作=xxx
sed -E 's/action=(\w+)/动作=\1/g' /tmp/demo.txt | head -2
```

```text
# 实测
$ sed 's/INFO/信息/' /tmp/demo.txt | head -1
2026-08-18 10:00:01 信息  user=alice action=login  ip=10.0.0.1
$ sed -E 's/action=(\w+)/动作=\1/g' /tmp/demo.txt | head -2
2026-08-18 10:00:01 INFO  user=alice 动作=login  ip=10.0.0.1
2026-08-18 10:00:05 ERROR user=bob   动作=query  ip=10.0.0.2
```

## 删除

`/模式/d` 删除匹配的行，`sed -n 'N, M d'` 删除地址范围。删除常用于「去掉日志里的干扰行」——比如分析前先把 DEBUG 级别、已知无害的行删掉，剩下的就是有效信息。注意 d 删除的是模式空间里的整行，删除后不输出、直接读下一行。

```shell
# 删除所有 ERROR 行
sed '/ERROR/d' /tmp/demo.txt
```

```text
# 实测（6 行删掉 3 行 ERROR，只剩 INFO/WARN）
2026-08-18 10:00:01 INFO  user=alice action=login  ip=10.0.0.1
2026-08-18 10:01:00 WARN  user=carol action=login  ip=10.0.0.3
2026-08-18 10:02:00 INFO  user=dave  action=logout ip=10.0.0.4
```

## 插入与追加

`i\` 在匹配行之前插入一行（insert），`a\` 在匹配行之后追加一行（append）。它们和替换、删除的区别是「增行」而非「改行」。典型用途是批量给配置文件的某个段落前后加注释标记、给日志分段加分隔线。命令里 `\` 后的内容是插入的文本。

```shell
# 在第 2 行之后追加一行
sed '2a\---- 追加行 ----' /tmp/demo.txt | head -3
```

```text
# 实测
2026-08-18 10:00:01 INFO  user=alice action=login  ip=10.0.0.1
2026-08-18 10:00:05 ERROR user=bob   action=query  ip=10.0.0.2
---- 追加行 ----
```

## 地址范围

sed 的「地址」指定命令作用于哪些行，可以是行号、模式，或两者的范围组合。`sed -n '2,4p'` 打印 2~4 行，`sed '/开始/,/结束/d'` 删除从「开始」到「结束」之间的所有行（常用于删掉日志里某段报错块）。地址范围让 sed 从「逐行处理」升级到「按段落处理」。

```shell
# 只打印第 2~4 行
sed -n '2,4p' /tmp/demo.txt
```

```text
# 实测
2026-08-18 10:00:05 ERROR user=bob   action=query  ip=10.0.0.2
2026-08-18 10:01:00 WARN  user=carol action=login  ip=10.0.0.3
2026-08-18 10:01:10 ERROR user=alice action=upload ip=10.0.0.1
```

## 模式空间与保持空间

sed 每次处理一行放进「模式空间」，而「保持空间」是跨行操作的临时仓库。相关命令：`h` 把模式空间复制到保持空间、`H` 追加、`g` 把保持空间复制回模式空间、`G` 追加、`x` 两者交换。最经典的应用是「反转文件行序」：`sed -n '1!G;h;$p'` —— 每行先读入、把之前积累的内容追加到它后面，最后一行时全部输出，就实现了倒序。这个技巧是理解 sed 双缓冲区的钥匙。

```shell
# 用保持空间反转行序
sed -n '1!G;h;$p' /tmp/demo.txt
```

```text
# 实测（输出顺序倒过来了，最后一行跑到最前）
2026-08-18 10:02:30 ERROR user=eve   action=login  ip=10.0.0.5
2026-08-18 10:02:00 INFO  user=dave  action=logout ip=10.0.0.4
2026-08-18 10:01:10 ERROR user=alice action=upload ip=10.0.0.1
2026-08-18 10:01:00 WARN  user=carol action=login  ip=10.0.0.3
2026-08-18 10:00:05 ERROR user=bob   action=query  ip=10.0.0.2
2026-08-18 10:00:01 INFO  user=alice action=login  ip=10.0.0.1
# 拆解：1!G（非首行时把保持空间追加到模式空间后）、h（当前行存入保持空间）、$p（最后一行打印）
```

## 应用场景实战

### 场景一：批量修改配置文件里的监听端口

```shell
# 把 nginx 配置里的 80 端口改成 8080（-i 直接写回，先备份）
sed -i.bak 's/listen 80;/listen 8080;/g' /etc/nginx/sites-available/default
# 确认改动
grep -n 'listen' /etc/nginx/sites-available/default
```

### 场景二：从日志里抽取一段报错上下文

```shell
# 打印从第一个 ERROR 到下一个 INFO 之间的行（报错块）
sed -n '/ERROR/,/INFO/p' /tmp/demo.txt | head
```

## 最佳实践与踩坑记录

### 最佳实践

1. 默认不带 -i，先在屏幕确认结果，再 -i 写回
2. 用 -i 改重要文件时加后缀备份（-i.bak），出错了能回滚
3. 处理含 / 的路径换分隔符 s|/a|/b|，别用一堆 \/ 转义
4. 全局替换记得加 g，否则只换每行第一个
5. 跨多行/复杂变换优先用 awk，sed 适合单行内的增删改

### 踩坑记录

```text
坑 1：忘了加 g 只替换了每行第一个
结论：一行多个目标词只换了第一个，剩下的没动。
原因：s/旧/新/ 默认只替换每行第一个匹配。
解法：要全换加 g 标志：s/旧/新/g。

坑 2：替换内容里的 & 和 \1 被特殊处理
结论：想把文本里的 & 字面量替换进去，结果 & 变成了整个匹配内容。
原因：替换串里 & 代表整个匹配、\1 代表捕获组，是元字符。
解法：字面 & 要写成 \&，或改用 awk 的 sub/gsub。

坑 3：sed -i 直接改坏了原文件没备份
结论：批量替换写错，原文件被覆盖。
原因：-i 直接写回文件，没有留底。
解法：用 sed -i.bak 留备份，或先输出到临时文件对比后再覆盖。

坑 4：地址范围 /开始/,/结束/ 匹配不到预期
结论：范围选择的行比预期多或少。
原因：范围是「第一个开始到第一个结束」，重复模式时容易错位。
解法：先用 sed -n '...p' 打印预览范围，确认后再执行操作。

坑 5：分隔符 / 与路径冲突导致语法错误
结论：sed 's//usr//opt/' 报错或行为错乱。
原因：替换含 / 的路径时，/ 分隔符和路径里的 / 混在一起。
解法：换分隔符 sed 's|/usr|/opt|'，或转义每个 /。
```

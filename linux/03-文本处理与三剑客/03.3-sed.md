## 概述

sed 是「流编辑器」（stream editor），按行读入、处理、输出，默认不修改原文件（除非用 -i）。它最擅长三件事：替换（s/旧/新/）、删除（/模式/d）、按地址范围操作（sed -n '2,5p'）。和 grep 只过滤不同，sed 能真正改内容，所以常用来做批量替换、删行、提取片段。它的执行模型是「模式空间 + 保持空间」两个缓冲区，理解这一点才能看懂高级用法。

```text
sed 三件核心能力：
1. 替换 —— s/旧/新/标志，g 全局、i 忽略大小写、\1 & 引用捕获
2. 删除 —— /模式/d 删匹配行、地址范围删段落
3. 地址范围 —— 行号/模式/组合，指定命令作用于哪些行
```

除这三件外，sed 还能**插入/追加行**（i/a）、**修改整行**（c）、以及用**保持空间**做跨行操作。脚本语法是「地址 + 命令」：地址决定「对哪些行」，命令决定「做什么」，中间的分号 `;` 分隔多条命令。

## 核心概念

sed 的核心概念是「替换、删除、增行、地址范围」四类操作。

### 替换

替换是 sed 最常用的功能，语法 `s/旧/新/标志`。分隔符 `/` 可换成别的字符（处理含 `/` 的路径时用 `s|/a/b|/c/d|`）。标志 `g` 是全局替换（默认只替换每行第一个）、`i` 忽略大小写、`p` 同时打印。替换里 `\1 \2` 引用捕获组、`&` 引用整个匹配内容，能做「把 user=alice 改成 用户=alice」这类结构变换。

```shell
# 默认只替换每行第一个匹配
sed 's/INFO/信息/' /tmp/demo.txt | head -1
# 全局替换 + 捕获组：把 action=xxx 换成 动作=xxx
sed -E 's/action=(\w+)/动作=\1/g' /tmp/demo.txt | head -2
```

```text
# 实测
$ sed 's/INFO/信息/' /tmp/demo.txt | head -1
2026-08-18 10:00:01 信息  user=alice action=login  ip=10.0.0.1
$ sed -E 's/action=(\w+)/动作=\1/g' /tmp/demo.txt | head -2
2026-08-18 10:00:01 INFO  user=alice 动作=login  ip=10.0.0.1
2026-08-18 10:00:05 ERROR user=bob   动作=query  ip=10.0.0.2
```

```text
替换标志速查：
g   全局替换（默认只替换每行第一个）
i   忽略大小写
p   同时打印被替换的行（配合 -n 只看改动行）
数字  只替换每行第 N 处匹配（如 s/a/b/2 换第 2 个 a）
w 文件  把被替换的行写入指定文件
e   （GNU）把替换结果当 shell 命令执行，慎用
```

```shell
# 替换里引用 & 和捕获组：给日期加括号
echo '2026-08-18' | sed -E 's/^([0-9]{4})-([0-9]{2})-([0-9]{2})/\1年\2月\3日/'
# 输出：2026年08月18日
```

```shell
# 数字标志：只替换每行第 2 个 a
echo 'aa bb aa' | sed 's/a/A/2'
# 输出：aA bb aa（第 1 个 a 没动，第 2 个变 A）
```

```text
替换易错点：
- & 在替换串里代表整个匹配，字面 & 要写成 \&
- 分隔符 / 与内容里的 / 冲突时换分隔符 s|a|b| 或 s#a#b#
- 捕获组在 BRE 下要转义 \(...\)，ERE（-E）直接写 (...)
- 大小写转换 \U \L \u \l 是 GNU 扩展，BSD sed 不支持
```

### 删除

`/模式/d` 删除匹配的行，`sed -n 'N, M d'` 删除地址范围。删除常用于「去掉日志里的干扰行」——比如分析前先把 DEBUG 级别、已知无害的行删掉，剩下的就是有效信息。注意 d 删除的是模式空间里的整行，删除后不输出、直接读下一行。

```shell
# 删除所有 ERROR 行
sed '/ERROR/d' /tmp/demo.txt
```

```text
# 实测（6 行删掉 3 行 ERROR，只剩 INFO/WARN）
2026-08-18 10:00:01 INFO  user=alice action=login  ip=10.0.0.1
2026-08-18 10:01:00 WARN  user=carol action=login  ip=10.0.0.3
2026-08-18 10:02:00 INFO  user=dave  action=logout ip=10.0.0.4
```

```shell
# 删除空行
sed '/^$/d' 文件
# 删除 3 到 5 行（地址范围）
sed '3,5d' 文件
# 删除从 START 到 END 之间的所有行（含两边界）
sed '/START/,/END/d' 文件
```

```text
删除易错点：
- d 删除的是「整行」，不是行内某段文字——删文字要用 s/旧/空/
- 多条件删除用 ; 或 -e 串联：sed '/^#/d; /^$/d' 删注释行和空行
- 地址范围 /START/,/END/ 若 END 从未出现，会一直删到文件末尾
```

### 插入与追加

`i\` 在匹配行之前插入一行（insert），`a\` 在匹配行之后追加一行（append）。它们和替换、删除的区别是「增行」而非「改行」。典型用途是批量给配置文件的某个段落前后加注释标记、给日志分段加分隔线。命令里 `\` 后的内容是插入的文本。

```shell
# 在第 2 行之后追加一行
sed '2a\---- 追加行 ----' /tmp/demo.txt | head -3
```

```text
# 实测
2026-08-18 10:00:01 INFO  user=alice action=login  ip=10.0.0.1
2026-08-18 10:00:05 ERROR user=bob   action=query  ip=10.0.0.2
---- 追加行 ----
```

```shell
# i 在第 2 行之前插入
sed '2i\---- 插入行 ----' /tmp/demo.txt | head -3
# 按模式追加：在每行 ERROR 之后加一条分隔线
sed '/ERROR/a\==== 以上是错误 ====' /tmp/demo.txt | head -4
```

```text
插入/追加易错点：
- i\ 和 a\ 后面的 \ 是命令的一部分，插入文本直接跟在后面
- 插入多行内容用 \n 或反斜杠续行（不同版本写法略有差异）
- 想替换整行（而非前后加行）用 c 命令：sed '2c\新内容'
- a 命令在每行后追加时，可以用 r 命令从文件读入内容代替
```

### 地址范围

sed 的「地址」指定命令作用于哪些行，可以是行号、模式，或两者的范围组合。`sed -n '2,4p'` 打印 2~4 行，`sed '/开始/,/结束/d'` 删除从「开始」到「结束」之间的所有行（常用于删掉日志里某段报错块）。地址范围让 sed 从「逐行处理」升级到「按段落处理」。

```shell
# 只打印第 2~4 行
sed -n '2,4p' /tmp/demo.txt
```

```text
# 实测
2026-08-18 10:00:05 ERROR user=bob   action=query  ip=10.0.0.2
2026-08-18 10:01:00 WARN  user=carol action=login  ip=10.0.0.3
2026-08-18 10:01:10 ERROR user=alice action=upload ip=10.0.0.1
```

```text
地址的六种形式：
1. 行号     2p、3d（第 2 行、第 3 行）
2. 末行     $p（最后一行）
3. 正则     /ERROR/p（匹配 ERROR 的行）
4. 范围     2,5 或 /a/,/b/（区间，含两端）
5. 取反     2!p（除第 2 行外全部）
6. 步长     （GNU）1~2p（从第 1 行起每隔 2 行）
```

```shell
# 末行、取反、步长组合演示
sed -n '$p' /tmp/demo.txt                    # 最后一行
sed -n '2!p' /tmp/demo.txt | head -2         # 除第 2 行外
sed -n '2~2p' /tmp/demo.txt                  # 第 2、4、6 行（每隔 2 行）
```

### 模式空间与保持空间

sed 每处理一行都用到两个缓冲区：**模式空间**（当前行的工作区）和**保持空间**（跨行暂存区）。平时只操作模式空间，一旦要「跨行拼内容」（反转行序、合并相邻行、段落重组），就得在两者之间搬运数据。

```text
保持空间命令：
h  模式空间 → 保持空间（覆盖）
H  模式空间 → 保持空间（追加，加换行）
g  保持空间 → 模式空间（覆盖）
G  保持空间 → 模式空间（追加，加换行）
x  两者交换
N  读入下一行并追加到模式空间（跨行操作的另一个入口）
```

```shell
# 经典用法：反转文件行序（每行先把之前的积累追加到自己后面，最后一行整体输出）
sed -n '1!G;h;$p' /tmp/demo.txt
```

```text
# 输出（顺序倒置，最后一行跑到最前）
2026-08-18 10:02:30 ERROR user=eve   action=login  ip=10.0.0.5
2026-08-18 10:02:00 INFO  user=dave  action=logout ip=10.0.0.4
2026-08-18 10:01:10 ERROR user=alice action=upload ip=10.0.0.1
2026-08-18 10:01:00 WARN  user=carol action=login  ip=10.0.0.3
2026-08-18 10:00:05 ERROR user=bob   action=query  ip=10.0.0.2
2026-08-18 10:00:01 INFO  user=alice action=login  ip=10.0.0.1
```

```shell
# N 命令：把下一行读到模式空间，配合 s 做跨行替换
# 把「foo\nbar」两行合并成一行（用逗号连接）
printf 'foo\nbar\nbaz\n' | sed 'N;s/\n/,/'
# 输出：foo,bar 和 baz（两两合并）
```

```text
保持空间易错点：
- h/H/g/G 的「覆盖 vs 追加」容易记混：大写 = 追加（加换行），小写 = 覆盖
- N 读完文件末尾后没有下一行时会直接终止（不输出最后一行），跨行脚本要处理边界
- 这些是 sed 里最抽象的部分，能用 awk 表达清楚的跨行逻辑就别硬上 sed
```

## 工作原理

sed 的执行模型是「逐行读入 → 执行命令 → 输出」的循环，核心在「模式空间」和「保持空间」两个缓冲区：

1. **模式空间（pattern space）**：sed 每次读入一行放到模式空间，对模式空间依次执行脚本里的命令（s/d/p/a/i...），然后输出模式空间内容，读下一行。这就是「流编辑」——一行进、一行出。
2. **保持空间（hold space）**：另一个辅助缓冲区，用于跨行操作。相关命令：`h` 把模式空间复制到保持空间、`H` 追加、`g` 把保持空间复制回模式空间、`G` 追加、`x` 两者交换。

最经典的应用是「反转文件行序」：`sed -n '1!G;h;$p'` —— 每行先读入、把之前积累的内容追加到它后面，最后一行时全部输出，就实现了倒序。这个技巧是理解 sed 双缓冲区的钥匙。

```shell
# 用保持空间反转行序
sed -n '1!G;h;$p' /tmp/demo.txt
```

```text
# 实测（输出顺序倒过来了，最后一行跑到最前）
2026-08-18 10:02:30 ERROR user=eve   action=login  ip=10.0.0.5
2026-08-18 10:02:00 INFO  user=dave  action=logout ip=10.0.0.4
2026-08-18 10:01:10 ERROR user=alice action=upload ip=10.0.0.1
2026-08-18 10:01:00 WARN  user=carol action=login  ip=10.0.0.3
2026-08-18 10:00:05 ERROR user=bob   action=query  ip=10.0.0.2
2026-08-18 10:00:01 INFO  user=alice action=login  ip=10.0.0.1
# 拆解：1!G（非首行时把保持空间追加到模式空间后）、h（当前行存入保持空间）、$p（最后一行打印）
```

```text
逐行执行模型（每行完整跑一遍脚本）：
读一行 → 模式空间 → 依次执行脚本命令 → 默认输出模式空间 → 读下一行
-a/i 的输出不经过模式空间，直接进输出流
-d 终止本行后续命令，直接读下一行
-N 额外读入下一行到模式空间，跨行操作靠它
```

## 常用命令与配置

sed 的高频命令与选项速查：

```shell
sed 's/旧/新/' file        # 替换每行第一个
sed 's/旧/新/g' file       # 全局替换
sed '/模式/d' file         # 删除匹配行
sed -n '2,5p' file         # 只打印 2~5 行（-n 抑制默认输出）
sed '2a\文本' file          # 第 2 行后追加
sed '2i\文本' file          # 第 2 行前插入
sed '2c\文本' file          # 第 2 行整行替换
sed -i 's/旧/新/' file     # 直接写回文件
sed -i.bak 's/旧/新/' file # 写回并留 .bak 备份
sed -E 's/(a)=(b)/\1x\2/' file  # -E 扩展正则 + 捕获组
sed -e 's/a/A/' -e '/B/d' file  # 多条命令串联
sed -f rules.sed file      # 从脚本文件读命令
```

```text
选项分工：
-n 抑制默认输出（配合 p 只打印选中行）
-i 原地写回（危险，配合 .bak 留备份）
-E/-r 扩展正则（捕获组不用转义）
-f 从脚本文件读 sed 命令（可复用）
-e 多条命令串联（等价于用 ; 分隔）
```

## 配置文件解析

sed 没有独立配置文件，但它的命令可以组织成可复用的「sed 脚本文件」：

```text
1. 把多条 sed 命令写进 .sed 文件，用 sed -f script.sed 加载执行，
   相当于「sed 的配置」——复杂编辑规则集中管理、可复用
2. 脚本文件里每条命令一行，注释用 #（部分 sed 版本支持）
3. 示例 rules.sed 内容：
   /^#/d              # 删注释行
   s/ +$//            # 去行尾空格
   s/ERROR/错误/g     # 全局替换
   用法：sed -f rules.sed 输入文件
```

```text
GNU sed 与 BSD（macOS）sed 的关键差异：
- -E：GNU 和 BSD 都支持；-r 只有 GNU 支持（BSD 会报错）
- -i：GNU 可裸写 -i；BSD 必须带后缀 sed -i '' 或 sed -i .bak
- \s、\+：GNU 扩展；BSD 用 [[:space:]]、\+ 的写法也略有差异
- 跨平台脚本优先写 -E、[[:space:]]、sed -i.bak 这类两边通用的写法
```

## 应用场景实战

### 场景一：批量修改配置文件里的监听端口

```shell
# 把 nginx 配置里的 80 端口改成 8080（-i 直接写回，先备份）
sed -i.bak 's/listen 80;/listen 8080;/g' /etc/nginx/sites-available/default
# 确认改动
grep -n 'listen' /etc/nginx/sites-available/default
```

### 场景二：从日志里抽取一段报错上下文

```shell
# 打印从第一个 ERROR 到下一个 INFO 之间的行（报错块）
sed -n '/ERROR/,/INFO/p' /tmp/demo.txt | head
```

```text
# 输出（ERROR 到 INFO 之间的一整段）
2026-08-18 10:00:05 ERROR user=bob   action=query  ip=10.0.0.2
2026-08-18 10:01:00 WARN  user=carol action=login  ip=10.0.0.3
2026-08-18 10:01:10 ERROR user=alice action=upload ip=10.0.0.1
2026-08-18 10:02:00 INFO  user=dave  action=logout ip=10.0.0.4
```

### 场景三：清理配置文件的注释行、空行与行尾空格

```shell
# 删 # 开头注释、删空行、去行尾空格，输出干净配置
sed -e '/^#/d' -e '/^[[:space:]]*$/d' -e 's/[[:space:]]*$//' /etc/nginx/nginx.conf | head
```

```text
# 说明
- /^#/d            删除以 # 开头的注释行
- /^[[:space:]]*$/d  删除空行（含只有空白字符的行）
- s/[[:space:]]*$// 去掉每行末尾的空白字符
# 这是「拿配置去 diff / 归档」前的标准清洗动作，三步一条命令完成
```

```text
生产注意：清理用管道输出到屏幕先看效果，确认无误再 -i 写回。
清洗动作对配置文件是「有损」的——删掉的注释可能带着重要说明，先备份再动。
```

## 性能与调优

```text
1. sed 是单行流式处理，比 awk 轻，简单替换/删除优先用 sed
2. 用地址范围限定处理行，避免对无关行执行替换
3. -i 写回会新建临时文件再改名，大文件操作时注意磁盘空间
4. 复杂跨行/多字段逻辑用 awk，别在 sed 里硬塞
5. 多个 sed 串成管道时合并成一条 sed -e '...' -e '...'，少起进程
6. 只提取不修改时加 -n + p，抑制默认输出，减少不必要的 I/O
```

## 安全与权限

```text
1. -i 原地写回是破坏性操作，改系统配置前必留 .bak 备份
2. sed -i 对符号链接会「替换链接本身」而非目标文件，改配置时要确认目标
3. 用 sed 处理含敏感信息的文件时，别把中间结果输出到日志
4. 批量替换脚本里的替换串若来自用户输入，注意元字符转义
5. 替换串里的 &、\1 是元字符，用户输入要按字面处理时先转义 & 和 \
```

## 故障排查

```text
「替换不生效」排查顺序：
1. 忘了 -i —— 默认只输出到屏幕不改文件，加 -i 才写回
2. 忘了 g —— 只替换了每行第一个，加 g 全局
3. 分隔符冲突 —— 替换内容含 / 时报错，换分隔符 s|...|...|
4. 地址范围不对 —— 先 sed -n '...p' 预览选中的行，确认范围
5. 正则方言 —— 捕获组 \1 在 BRE 下要转义 \(...\)，或用 -E

「范围删多了/删少了」：
- /a/,/b/ 若 b 从未出现会删到文件末尾；先用 sed -n '/a/,/b/p' 预览再执行

「macOS 上报 unknown option -- r / 乱码」：
- BSD sed 不支持 -r，改用 -E；-i 要带后缀 sed -i '' 或 -i.bak
```

## 常见问题

```text
Q1: sed -i 和先输出到临时文件再 mv 有什么区别？
A: -i 内部就是「写临时文件 + 改名」，但会破坏符号链接和硬链接，且不留备份时无法回滚。改重要文件用 -i.bak。

Q2: 为什么 s/旧/新/ 只替换了每行第一个？
A: 默认只替换第一个匹配，加 g 标志才全局替换。

Q3: 怎么删除文件中所有空行？
A: sed '/^$/d' file。

Q4: 替换内容里有 & 或 / 怎么办？
A: & 要写成 \&（字面量），/ 换成别的分隔符如 s|a|b|。

Q5: 怎么只替换每行的第 N 处匹配？
A: 用数字标志：s/旧/新/2 只替换每行第 2 个；s/旧/新/2g 从第 2 个起全替换。

Q6: sed -E 和 sed -r 有什么区别？
A: 作用一样（扩展正则），-r 是 GNU 老写法，-E 是 POSIX/BSD 通用写法。跨平台（含 macOS）脚本用 -E。

Q7: sed 怎么在匹配行前/后插入多行内容？
A: i\ 和 a\ 后面跟插入文本，多行用 \n 或反斜杠续行；内容很多时用 r 命令从文件读入：sed '/pattern/r 文件'。
```

## 面试题

```text
1. sed 和 grep 的本质区别？
   答：grep 只过滤（输出匹配行），sed 能编辑（替换/删除/增行）。sed 默认输出所有行，grep 只输出匹配行。

2. sed 的模式空间和保持空间是什么？
   答：模式空间是每行处理的工作区，保持空间是跨行操作的临时缓冲区，靠 h/H/g/G/x 命令在两者间搬运数据。

3. 怎么用 sed 只替换第 3 行的内容？
   答：sed '3s/旧/新/' file，地址 3 限定只作用于第 3 行。

4. sed -i 有什么风险？
   答：原地写回不可逆，改错无备份就丢数据；且会破坏符号链接。应加 .bak 后缀留备份。

5. sed 的地址可以有哪些形式？
   答：行号（2）、末行（$）、正则（/re/）、范围（2,5 或 /a/,/b/）、取反（2!）、步长（GNU 的 1~2）。地址决定命令作用于哪些行。

6. 怎么用 sed 反转文件行序？
   答：sed -n '1!G;h;$p' file。靠保持空间：每行把之前的积累追加到自己后面，最后一行整体输出。

7. sed -i 和 sed -i.bak 差别，生产里为什么重要？
   答：-i 直接覆盖无备份，-i.bak 覆盖前留 .bak 副本。改系统配置或批量替换一旦写错，有备份才能回滚，所以生产环境写回必带后缀。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 默认不带 -i，先在屏幕确认结果，再 -i 写回
2. 用 -i 改重要文件时加后缀备份（-i.bak），出错了能回滚
3. 处理含 / 的路径换分隔符 s|/a|/b|，别用一堆 \/ 转义
4. 全局替换记得加 g，否则只换每行第一个
5. 跨多行/复杂变换优先用 awk，sed 适合单行内的增删改
6. 多条编辑命令合并成一条 sed -e '...' -e '...'，少起进程
7. 跨平台脚本用 -E 而非 -r，-i 带后缀，避免 BSD/macOS 差异

### 踩坑记录

```text
坑 1：忘了加 g 只替换了每行第一个
结论：一行多个目标词只换了第一个，剩下的没动。
原因：s/旧/新/ 默认只替换每行第一个匹配。
解法：要全换加 g 标志：s/旧/新/g。

坑 2：替换内容里的 & 和 \1 被特殊处理
结论：想把文本里的 & 字面量替换进去，结果 & 变成了整个匹配内容。
原因：替换串里 & 代表整个匹配、\1 代表捕获组，是元字符。
解法：字面 & 要写成 \&，或改用 awk 的 sub/gsub。

坑 3：sed -i 直接改坏了原文件没备份
结论：批量替换写错，原文件被覆盖。
原因：-i 直接写回文件，没有留底。
解法：用 sed -i.bak 留备份，或先输出到临时文件对比后再覆盖。

坑 4：地址范围 /开始/,/结束/ 匹配不到预期
结论：范围选择的行比预期多或少。
原因：范围是「第一个开始到第一个结束」，重复模式时容易错位。
解法：先用 sed -n '...p' 打印预览范围，确认后再执行操作。

坑 5：分隔符 / 与路径冲突导致语法错误
结论：sed 's//usr//opt/' 报错或行为错乱。
原因：替换含 / 的路径时，/ 分隔符和路径里的 / 混在一起。
解法：换分隔符 sed 's|/usr|/opt|'，或转义每个 /。

坑 6：macOS 上报错 unknown option 或 -i 行为不同
结论：同一脚本在 Linux 正常、macOS 报 sed: illegal option -- r 或 -i 出错。
原因：BSD sed 不支持 -r，且 -i 必须带后缀（sed -i ''）。
解法：跨平台统一用 -E、sed -i.bak，别裸写 -r 和 -i。

坑 7：范围 /a/,/b/ 在 b 不出现时删到文件末尾
结论：sed '/START/,/END/d' 结果把 END 之后的内容也删光了。
原因：范围的结束模式 END 从未匹配到时，范围会一直延伸到文件末尾。
解法：先 sed -n '/START/,/END/p' 预览确认 END 确实存在，再执行删除。
```

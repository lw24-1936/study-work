## 概述

这一篇把正则、grep、sed、awk、sort/uniq 串起来，用三个真实场景演示「三剑客组合拳」怎么落地：日志统计分析、CSV 与配置文件处理、批量改名。核心思路都一样——先看清数据格式、再用管道把各工具串成流水线、最后用真实结果验证。每个案例都基于本机真实数据跑过，可以直接照搬改路径复用。

```text
三剑客组合套路：
1. 日志统计 —— grep 过滤 → awk 提取字段 → sort | uniq -c 计数 → sort -rn 排序 → head 取前 N
2. 表格处理 —— cut/awk 切列 → 条件过滤 → 数值汇总
3. 批量操作 —— find/ls 生成清单 → xargs/循环 → sed/awk 逐个改名或改内容
```

```text
红帽系 vs Debian 系默认工具差异（直接影响命令怎么写）：
1. 默认 awk：Red Hat/CentOS/RHEL/Fedora 预装 gawk（支持 gensub/asort/IGNORECASE/FPAT 等扩展）；
   Ubuntu/Debian 默认是 mawk，这些扩展直接报 "function xxx never defined"。
   本机（Ubuntu 24.04）awk 是 mawk 1.3.4，下文 awk 示例全部按 mawk 可跑的写法给，gawk 专有写法会单独标注。
2. grep：本机 GNU grep 3.11；grep -P（PCRE）两边都依赖 libpcre2，BSD/busybox 的 grep 常没有 -P。
3. sed -i：GNU sed 的 -i 可不带后缀；macOS/BSD 的 sed -i 必须带后缀（sed -i '' 's///'）。
   Red Hat/CentOS 与 Debian 都用 GNU sed，行为一致；跨平台脚本写 sed -i.bak 最稳。
4. sort 中文排序：结果随 LC_COLLATE 变化（本机 zh_CN.UTF-8 与 LC_ALL=C 结果不同）；
   Red Hat/CentOS 服务器常是 en_US.UTF-8 或 C，同一脚本换机器跑结果可能不同，脚本里显式 LC_ALL=C。
```

## 核心概念

组合拳的本质是「单一职责 + 管道拼接」：每个工具只做一件事，用管道把输出接到下一个工具的输入。

### 日志统计流水线

日志统计是最高频的组合。标准套路：grep 过滤掉噪音 → awk 提取关心的字段 → sort | uniq -c 分组计数 → sort -rn 按次数倒序 → head 取 TOP N。这条链每一步输出都清晰可验证，中间卡住就拆开逐段排查。

```text
grep 过滤 → awk 提取 → sort | uniq -c 计数 → sort -rn 倒序 → head 取前 N
```

每一步对应的具体命令，单独跑都能看到中间结果：

```shell
# 1. 只看 ERROR 行（缩小范围）
grep ERROR /var/log/app.log | head -5

# 2. 提取第 7 列（请求路径）
awk '{print $7}' /var/log/nginx/access.log | head -5

# 3. 分组计数（先 sort 聚相邻、再 uniq -c 计数）
awk '{print $7}' /var/log/nginx/access.log | sort | uniq -c

# 4. 按次数倒序 + 取前 5
awk '{print $7}' /var/log/nginx/access.log | sort | uniq -c | sort -rn | head -5
```

```text
要点：
1. grep 先过滤缩小范围，awk 提取字段，sort|uniq 分组计数，sort -rn 倒序，head 截断
2. 每步输出都是「干净的一列/一计数」，可直接喂给下一步
3. 拆段调试：去掉后面的管道就能看当前阶段的中间输出
4. 边界：uniq -c 前必须 sort；大日志关联数组憋内存，改用 sort|uniq 外部排序
```

### 表格处理流水线

CSV、冒号分隔的配置文件（/etc/passwd）这类「结构化数据」，用 awk 切列 + 条件 + 数值汇总。核心是「awk -F分隔符 切列 + NR>1 跳表头 + 条件过滤 + 数值计算」四件套，比 cut 更稳（默认按空白切、能算数值）。

```text
awk -F, 切列 → NR>1 跳表头 → 条件过滤 → 分组/求和/求平均
```

四件套对应的具体命令：

```shell
# 1. 切列：逗号分隔，取第 2、4 列
awk -F, '{print $2, $4}' /tmp/users.csv

# 2. 跳表头：NR>1 跳过第一行
awk -F, 'NR>1 {print $2, $4}' /tmp/users.csv

# 3. 条件过滤：工资 >= 15000
awk -F, 'NR>1 && $4>=15000 {print $2, $4}' /tmp/users.csv

# 4. 数值汇总：按部门分组计数 + 求平均工资
awk -F, 'NR>1 {cnt[$3]++; sum[$3]+=$4} END {for (d in cnt) print d, cnt[d], sum[d]/cnt[d]}' /tmp/users.csv
```

```text
要点：
1. -F 指定分隔符，NR>1 跳过表头是处理 CSV 的两个固定动作
2. awk 能直接做数值计算（求和/平均/最大），cut 只能切列不能算
3. 冒号分隔的 /etc/passwd、键值对的 .env 同理，只是换 -F 分隔符
4. 边界：字段含分隔符（CSV 引号转义）时 awk 会切错，复杂 CSV 用 csvkit/Python
```

### 批量操作流水线

批量改名、批量改内容的核心是「生成清单 → 逐个处理」。清单用 find/ls 生成，逐个处理用 shell 循环或 xargs，改名/改内容用参数扩展或 sed。关键纪律：先只打印清单确认，再真正执行。

```text
find/ls 生成清单 → xargs/循环 → sed/参数扩展 逐个改名或改内容
```

批量改名的三种实现，从简单到通用：

```shell
# 生成清单：先看要处理哪些文件
ls /tmp/renametest/*.txt

# 方案一：循环 + 参数扩展（.txt → .md）
for f in /tmp/renametest/*.txt; do echo "mv $f ${f%.txt}.md"; done   # 先打印
for f in /tmp/renametest/*.txt; do mv "$f" "${f%.txt}.md"; done      # 确认后执行

# 方案二：rename 命令（正则替换）
rename -n 's/\.txt$/.md/' /tmp/renametest/*.txt    # -n 只打印不执行
rename 's/\.txt$/.md/' /tmp/renametest/*.txt

# 方案三：find + 循环（处理子目录里的所有文件，文件名含空格也安全）
find /tmp/project -type f -name '*.txt' -print0 | while IFS= read -r -d '' f; do
    mv "$f" "${f%.txt}.md"
done
```

```text
要点：
1. 纪律：先打印清单（echo 或 rename -n）确认，再真正执行，防误改误删
2. 参数扩展：${f%.txt} 去尾部、${f##*/} 去目录、${f/旧/新} 替换首个
3. 文件名含空格：循环里给 "$f" 加引号，或用 find -print0 + read -d ''
4. 边界：mv 默认覆盖已存在的目标文件，改名前 [ -e "$new" ] 检查或用 mv -n
```

### 数据清洗与格式转换流水线

日志/数据文件常带脏数据：CRLF 换行、多余空白、编码问题（GBK 转 UTF-8）、不可见字符。清洗套路是「tr/iconv/sed 规范格式 → awk 提取 → sort/uniq 去重」。这一步做好了，后续统计才不会因为换行符、全角空格这类脏数据出诡异结果。

```text
iconv 转码 / tr 去 \r 与压缩空白 / sed 去尾部空白 → awk 提取 → sort | uniq 去重
```

```shell
# 1. 查看文件是否有 CRLF 换行（Windows 文件常见）
file /tmp/win.txt

# 2. 去 CRLF：sed 去行尾 \r（等价 dos2unix，本机未装 dos2unix 时用这个）
sed 's/\r$//' /tmp/win.txt > /tmp/clean.txt

# 3. 压缩连续空白为一个空格（日志里对齐用的多余空格）
tr -s '[:space:]' ' ' < /tmp/clean.txt

# 4. 去重（先 sort 再 uniq，或直接 sort -u）
sort -u /tmp/clean.txt
```

```text
要点：
1. CRLF 判定：file 命令看 "with CRLF line terminators"；od -c 看 \r \n 字节
2. dos2unix 本机未装，等价替代：sed 's/\r$//' 或 tr -d '\r' 或 perl -pi -e 's/\r\n/\n/g'
3. tr -s 压缩重复字符，tr -d 删除字符；[:space:] 是 POSIX 字符类
4. sort -u 等于 sort | uniq（去重），但一条命令更省
5. 编码转换：iconv -f GBK -t UTF-8 处理 Windows 中文文件，别用 sed 硬转编码
```

### 实测：三剑客组合拳真跑输出

下面命令都在本机（Ubuntu 24.04，mawk 1.3.4，GNU grep 3.11，GNU sed 4.9）真跑过，测试数据是 /tmp/acc.log（10 行模拟 nginx 日志）、/tmp/users.csv（含表头），输出原样贴出，可当「命令对不对」的对照：

```text
$ awk '{cnt[$9]++} END {for (k in cnt) print k, cnt[k]}' /tmp/acc.log | sort -k2 -rn
200 6
500 2
403 1
401 1

$ awk '{print $7}' /tmp/acc.log | sort | uniq -c | sort -rn
      5 /api/user
      3 /api/order
      2 /api/login

$ awk '{print $1}' /tmp/acc.log | sort | uniq -c | sort -rn
      4 1.2.3.4
      3 9.9.9.9
      3 5.6.7.8

$ awk -F, 'NR>1 {cnt[$3]++} END {for (d in cnt) print d, cnt[d]}' /tmp/users.csv | sort
dev 3
ops 1
sales 2

$ awk -F, 'NR>1 {sum+=$4} END {print "平均工资:", sum/(NR-1)}' /tmp/users.csv
平均工资: 16166.7
```

```text
读输出要点：
1. uniq -c 输出的计数前有空格（右对齐），awk 处理它时字段会错位，要用 $1 取计数、$2 取键
2. awk 关联数组 for (k in cnt) 的遍历顺序未定义（mawk 实测按内部哈希序），要稳定顺序必须管道给 sort
3. 状态码分布里 200 有 6 条、500 有 2 条，直接对上「谁在报错」——先看分布再看明细
```

### 实测：边界行为对照（cut vs awk、sort 排序、mawk 缺 gawk 扩展）

几个「看起来应该一样、实际结果不同」的边界，用本机真跑输出对照，写组合命令时能少踩坑：

```text
# 1. cut -d' ' 按「单个空格」切，连续空格产生空字段；awk 默认「连续空白」一个分隔符
$ printf 'a  b\tc\n' | cut -d' ' -f2
（输出为空行：a 后面的两个空格之间拆出一个空字段）
$ printf 'a  b\tc\n' | awk '{for(i=1;i<=NF;i++) printf "["$i"]"; print ""}'
[a][b][c]

# 2. sort 默认字典序 vs -n 数值序 vs -V 版本序
$ printf '9\n10\n100\n' | sort
10
100
9
$ printf '9\n10\n100\n' | sort -n
9
10
100
$ printf 'a1\na10\na2\n' | sort -V
a1
a2
a10

# 3. 中文排序随 LC_COLLATE 变化
$ printf '张三\n李四\n赵六\n王五\n' > /tmp/f3.txt
$ sort /tmp/f3.txt
李四
王五
张三
赵六
$ LC_ALL=C sort /tmp/f3.txt
张三
李四
王五
赵六

# 4. mawk 缺 gawk 扩展，报错原文
$ awk 'BEGIN{print gensub(/a/,"b","g","aaa")}'
awk: line 2: function gensub never defined
$ awk 'BEGIN{a[1]=3;a[2]=1;n=asort(a);print n}'
awk: line 2: function asort never defined
```

```text
对照结论：
1. 字段对齐的数据用 awk（连续空白分隔），cut -d' ' 只适合「严格单空格」的文件
2. 数值列排序一定加 -n；版本号（v1.10 vs v1.9）用 -V；两者不能互相替代
3. 中文排序无「正确」答案，取决于 locale；脚本要稳定就 LC_ALL=C
4. Ubuntu 默认 mawk，gawk 扩展直接报 "function xxx never defined"，跨平台脚本只用 POSIX 语法
```

## 工作原理

整条流水线是「流式管道」，每个工具都是过滤器：读上一级的 stdout、处理后写自己的 stdout，交给下一级。数据从左往右流动，任何一级只关心自己的输入格式和输出格式：

1. **字段定位**：先摸清数据格式（nginx 日志 $1=IP、$7=路径、$9=状态码），这是后续所有统计的前提。
2. **逐步缩小**：grep 缩小范围 → awk 提取字段 → sort/uniq 聚合并计数，每一步都在减少数据量。
3. **可验证性**：管道可以任意拆断——去掉 `| head` 就能看中间结果，逐段调试，这正是组合拳比「写一个大脚本」好排查的原因。

```text
数据流：原始文件 → grep 过滤 → awk 提取 → sort 聚合 → uniq -c 计数 → sort -rn 排序 → head 截断
每一步可拆开验证：删掉后面的管道就能看当前阶段的输出
```

```text
组合拳 vs 大脚本的取舍：
1. 管道组合：每步可独立验证、易调试、适合一次性分析和探索
2. 大脚本（awk -f / shell script）：适合固定报表、要复用、逻辑复杂时
3. 经验：先管道探索出正确逻辑，再固化成脚本；别一上来就写大脚本
```

```text
平台差异对流水线的影响：
1. awk 方言：同样的 awk 脚本在 Ubuntu（mawk）和 CentOS（gawk）都能跑（POSIX 子集）；
   反过来用 gawk 扩展（gensub/asort/FPAT）写的脚本在 mawk 上直接报错。
   跨平台只用 POSIX 语法；需要 gawk 扩展时注释「需 gawk，CentOS 自带、Ubuntu 需 apt install gawk」。
2. locale：awk 的 tolower/toupper 对多字节字符、sort 的中文排序都随 LC_COLLATE/LANG 变；
   CentOS 7 默认 LANG 常是 en_US.UTF-8、最小化安装可能是 C，和 Ubuntu 桌面 zh_CN.UTF-8 不同。
3. 分隔符：awk 默认 FS 是「连续空白」，与平台无关（mawk/gawk 一致）；
   但 cut -d' ' 按单个空格切，连续空格产生空字段——这是 cut 和 awk 行为差异，别混用。
```

## 常用命令与配置

三个场景的高频命令汇总：

```shell
# 日志统计
wc -l < access.log                                  # 总行数
awk '{cnt[$9]++} END {for (k in cnt) print k, cnt[k]}' access.log | sort -k2 -rn   # 状态码分布
awk '{print $7}' access.log | sort | uniq -c | sort -rn | head -5                  # 路径 TOP5
awk '{print $1}' access.log | sort | uniq -c | sort -rn                           # 来源 IP

# 表格处理
awk -F, 'NR>1 {cnt[$3]++} END {for (d in cnt) print d, cnt[d]}' users.csv          # 分组计数
awk -F, 'NR>1 {sum+=$4} END {print sum/(NR-1)}' users.csv                          # 求平均
awk -F: '$7 ~ /bash|sh$/ {print $1, $7}' /etc/passwd                               # 切 passwd

# 批量改名
for f in *.txt; do mv "$f" "${f%.txt}.md"; done                                    # 循环 + 参数扩展
rename 's/\.txt$/.md/' *.txt                                                       # rename 命令
```

按「分析 → 提取 → 统计 → 排序」四步拆分的完整日志分析命令集：

```shell
# 分析：先看规模和样本
wc -l < access.log                        # 总行数
head -3 access.log                        # 看样本摸字段

# 提取：awk 切出关心的字段
awk '{print $1, $7, $9}' access.log       # IP、路径、状态码

# 统计：分组计数
awk '{cnt[$9]++} END {for (k in cnt) print k, cnt[k]}' access.log    # 状态码分布
awk '{print $1}' access.log | sort | uniq -c                          # 各 IP 次数

# 排序：按次数/数值倒序取 TOP
awk '{print $7}' access.log | sort | uniq -c | sort -rn | head -10   # 路径 TOP10
```

```text
通用配置要点：
1. 分析对象决定分隔符：nginx 日志默认空白、CSV 逗号、/etc/passwd 冒号
2. 统计套路固定：awk 提取 → sort | uniq -c → sort -rn → head
3. 批量操作先 echo 打印清单，确认后再 mv/sed 真正执行
```

补充几条高频组合（时间窗口、方法统计、字节汇总），仍按「提取 → 统计 → 排序」拆：

```shell
# 时间窗口聚合：nginx 日志 $4 是 [date:time]，按小时统计请求数
awk '{split($4, t, ":"); h=t[2]; cnt[h]++} END {for (k in cnt) print k, cnt[k]}' access.log | sort

# HTTP 方法分布（$6 是 "GET" 带引号，sed 去引号再统计）
awk '{print $6}' access.log | sed 's/"//g' | sort | uniq -c | sort -rn

# 流量汇总：$10 是响应字节数
awk '{sum+=$10} END {print "总字节:", sum}' access.log

# 应用日志按分钟统计 ERROR（$1 日期、$2 时间、$3 级别）
awk '$3=="ERROR" {split($2, t, ":"); cnt[t[1]":"t[2]]++} END {for (k in cnt) print k, cnt[k]}' app.log | sort
```

```text
实测（本机 /tmp/acc.log、/tmp/app.log）：
$ awk '{split($4, t, ":"); h=t[2]; cnt[h]++} END {for (k in cnt) print k, cnt[k]}' /tmp/acc.log | sort
10 10
$ awk '{print $6}' /tmp/acc.log | sed 's/"//g' | sort | uniq -c | sort -rn
      8 GET
      1 POST
      1 DELETE
$ awk '{sum+=$10} END {print "总字节:", sum}' /tmp/acc.log
总字节: 4512
$ awk '$3=="ERROR" {split($2, t, ":"); cnt[t[1]":"t[2]]++} END {for (k in cnt) print k, cnt[k]}' /tmp/app.log | sort
10:00 3
```

```text
红帽系差异注意：
1. CentOS/RHEL 的 nginx 日志默认也走 combined 格式，字段顺序和本机一致；
   但 systemd 发行版日志进 journald 后，要看日志走 journalctl，别直接 grep /var/log/messages
   （CentOS 7 还有 messages，RHEL 8+ 已迁 journald）。
2. sort -rn 的 -r/-n 是 POSIX 选项，两边一致；sort -h/-V 也是 GNU sort 通用，Red Hat 与 Debian 都支持。
```

## 配置文件解析

文本处理的「配置」主要体现在**数据格式的定义**上——格式决定字段位置，字段位置决定 awk 怎么写：

```text
1. nginx 日志格式由 nginx.conf 里的 log_format 定义，
   默认 combined 格式按空白切分后：$1=IP、$7=路径、$9=状态码、$10=字节
2. 自定义 log_format 会改变字段顺序，分析前先看日志样本确认 $N 对应什么
3. /etc/passwd 是冒号分隔的固定 7 字段，awk -F: 切列前先确认字段含义
4. 分析任何「按列」的数据，第一步永远是 head 看样本 + 摸清分隔符和字段
```

```text
常见日志格式对照（分析前先对齐字段）：
1. nginx combined：$1 IP / $4 时间 / $6 方法 / $7 路径 / $9 状态码 / $10 字节
2. Apache combined 与 nginx 字段顺序一致，可直接套用
3. 自定义 log_format 加入 $http_x_forwarded_for 后，IP 列会前移，统计前必须重核对
4. /etc/passwd 7 字段：用户名:密码占位:UID:GID:描述:家目录:shell（用 $1 $3 $4 $7）
```

```text
红帽/CentOS 的日志位置与格式差异：
1. nginx 日志默认路径：Debian/Ubuntu 是 /var/log/nginx/access.log；
   Red Hat/CentOS 装 nginx（epel）后也是 /var/log/nginx/access.log，路径一致。
2. Apache：Debian 是 /var/log/apache2/access.log，Red Hat/CentOS 是 /var/log/httpd/access_log，
   文件名和目录都不同，跨平台统计脚本要先探测路径。
3. 系统日志：CentOS 7 及以前是 /var/log/messages + /var/log/secure；RHEL 8/CentOS 8+ 默认走 systemd-journald，
   /var/log/messages 不再默认存在，先 journalctl -u 服务名 提取再喂给三剑客。
4. 自定义 log_format 后字段顺序变了，写死的 $7/$9 会错位——先 head 看样本再写，这条两边通用。
```

## 应用场景实战

### 场景一：Nginx 与应用日志统计分析

访问日志是最常见的分析对象，标准 nginx 格式按空白切分后字段固定：$1 客户端 IP、$7 请求路径、$9 状态码、$10 响应字节。分析套路三步走：先看整体规模、再按维度分组统计、最后定位异常。下面这套命令能回答「谁在访问、访问什么、报错没有、哪个接口最热」四个问题。

```shell
# 1. 总请求数
wc -l < /var/log/nginx/access.log
# 2. 状态码分布（健康度一目了然）
awk '{cnt[$9]++} END {for (k in cnt) print k, cnt[k]}' /var/log/nginx/access.log | sort -k2 -rn
# 3. 请求路径 TOP 榜（哪个接口最热）
awk '{print $7}' /var/log/nginx/access.log | sort | uniq -c | sort -rn | head -5
# 4. 客户端 IP 来源（谁在访问）
awk '{print $1}' /var/log/nginx/access.log | sort | uniq -c | sort -rn | head
```

```text
# 实测（本机真实 nginx 日志）
$ wc -l < /var/log/nginx/access.log
824
$ awk '{cnt[$9]++} END {for (k in cnt) print k, cnt[k]}' /var/log/nginx/access.log | sort -k2 -rn
401 527
200 279
101 18
$ awk '{print $7}' /var/log/nginx/access.log | sort | uniq -c | sort -rn | head -5
    527 /api/pair/heartbeat
     81 /api/pet/state
     18 /aionui-panel/list
     10 /api/subagent.list
     10 /api/dynamicCordisRunner/inventory
# 真实结论：/api/pair/heartbeat 被请求 527 次、全部返回 401（未授权）——
# 心跳接口鉴权失败导致客户端反复重试。这就是「用日志看出生产问题」的完整示范。
```

补充两个「应用日志」常用统计——按时间段聚合同样是组合拳的延伸：

```shell
# 按分钟统计 ERROR 出现次数（应用日志时间戳在 $1 日期、$2 时间）
awk '$3=="ERROR" {split($2, t, ":"); cnt[t[1]":"t[2]]++} END {for (k in cnt) print k, cnt[k]}' /var/log/app.log

# 统计 5xx 错误并列出具体接口
awk '$9>=500 {print $7}' /var/log/nginx/access.log | sort | uniq -c | sort -rn
```

### 场景二：CSV 与配置文件处理

CSV 和键值配置文件是运维经常要处理的结构化数据。CSV 用 `-F,` 切列、`NR>1` 跳过表头，就能做过滤、分组、数值汇总；配置文件（冒号分隔的 /etc/passwd、键值对的 .env）同理，只是换分隔符。核心是「awk 切列 + 条件 + 汇总」三段式。

```shell
# CSV：统计各部门人数、算平均工资、过滤高薪员工
awk -F, 'NR>1 {cnt[$3]++} END {for (d in cnt) print d, cnt[d]}' /tmp/users.csv
awk -F, 'NR>1 {sum+=$4} END {print "平均工资:", sum/(NR-1)}' /tmp/users.csv
awk -F, '$4>=15000 {print $2, $4}' /tmp/users.csv

# 冒号分隔的 /etc/passwd：列出所有可登录用户的用户名和 shell
awk -F: '$7 ~ /bash|sh$/ {print $1, $7}' /etc/passwd | head
```

```text
# 实测（CSV 部分）
$ awk -F, 'NR>1 {cnt[$3]++} END {for (d in cnt) print d, cnt[d]}' /tmp/users.csv
dev 3
ops 1
sales 1
$ awk -F, 'NR>1 {sum+=$4} END {print "平均工资:", sum/(NR-1)}' /tmp/users.csv
平均工资: 14200
$ awk -F, '$4>=15000 {print $2, $4}' /tmp/users.csv
alice 15000
carol 18000
eve 16000
```

键值配置文件（.env）和统计 UID 分布的例子：

```shell
# .env 键值配置：去掉注释和空行，只留 KEY=VALUE
grep -v '^#' /app/.env | grep -v '^$'

# 统计 /etc/passwd 里各 shell 的用户数
awk -F: '{cnt[$7]++} END {for (s in cnt) print s, cnt[s]}' /etc/passwd | sort -k2 -rn

# 统计各 UID 区间的用户数（UID>=1000 通常是普通用户）
awk -F: '$3>=1000 {cnt[$7]++} END {for (s in cnt) print s, cnt[s]}' /etc/passwd
```

### 场景三：批量改名

批量改名的核心是「循环 + 参数扩展」或 rename 命令。`${f%.txt}` 去掉文件名尾部的 .txt，`${f%%.*}` 去掉第一个点之后的所有内容，`${f/旧/新}` 替换第一个匹配。复杂规则用 sed 生成新名字再 mv。注意批量操作前先「只打印不执行」，确认清单无误再真正改名。

```shell
# 方案一：shell 循环 + 参数扩展
cd /tmp/renametest
for f in *.txt; do mv "$f" "${f%.txt}.md"; done
ls

# 方案二：rename 命令（正则批量替换扩展名）
rename 's/\.txt$/.md/' *.txt
```

```text
# 实测（改名前 → 改名后）
$ ls
file1.txt  file2.txt  file3.txt
$ for f in *.txt; do mv "$f" "${f%.txt}.md"; done
$ ls
file1.md  file2.md  file3.md
```

批量改「文件内容」同样用 sed 循环，和改名一个套路：

```shell
# 批量把目录下所有 .conf 里的旧域名换成新域名（先打印确认）
grep -rl 'old.example.com' /etc/app/*.conf    # 先看哪些文件含旧值
sed -i 's/old\.example\.com/new.example.com/g' /etc/app/*.conf   # 确认后替换

# 批量给所有 .sh 加可执行权限
find /opt/scripts -name '*.sh' -exec chmod +x {} \;
```

```text
说明：
1. 改名：${f%.txt} 去尾部扩展名，${f/旧/新} 替换首个匹配，rename 用正则
2. 改内容：sed -i 原地替换，grep -rl 先定位哪些文件含目标
3. 纪律：先打印清单/用 -n 预演，确认后再真正执行，防误改
```

### 场景四：数据清洗与时间窗口聚合

生产日志常不干净：Windows 上传的文件带 CRLF、字段混了多余空白、时间戳要按小时聚合。这个场景演示「清洗 → 时间窗口聚合 → 关联」一条龙，全部基于本机真实数据跑过。

```shell
# 准备：模拟 Windows 上传的 CRLF 日志
printf 'a\r\nb\r\na\r\nc\r\n' > /tmp/win.txt

# 1. 确认是 CRLF
file /tmp/win.txt

# 2. 去 CRLF 后再统计（不先去 \r，awk 的 $1 会带 \r，比较/去重全错）
sed 's/\r$//' /tmp/win.txt | sort | uniq -c

# 3. 时间窗口聚合：把「小时」作为维度统计请求数
awk '{split($4, t, ":"); h=t[2]; cnt[h]++} END {for (k in cnt) print k, cnt[k]}' /tmp/acc.log | sort

# 4. 关联两个文件：join 按共同字段合并（两边先 sort；<( ) 是 bash 进程替换）
join <(sort /tmp/a.txt) <(sort /tmp/b.txt)
```

```text
# 实测
$ printf 'a\r\nb\r\na\r\nc\r\n' > /tmp/win.txt
$ file /tmp/win.txt
/tmp/win.txt: ASCII text, with CRLF line terminators
$ sed 's/\r$//' /tmp/win.txt | sort | uniq -c
      2 a
      1 b
      1 c

$ awk '{split($4, t, ":"); h=t[2]; cnt[h]++} END {for (k in cnt) print k, cnt[k]}' /tmp/acc.log | sort
10 10

# join 示例（/tmp/a.txt = 1 alice / 2 bob / 3 carol，/tmp/b.txt = 1 dev / 2 ops / 4 sales）
$ join <(sort /tmp/a.txt) <(sort /tmp/b.txt)
1 alice dev
2 bob ops
```

```text
要点：
1. CRLF 不先去干净，awk 字段里残留 \r，sort/uniq 把 "a" 和 "a\r" 当两条不同记录——Windows 日志统计最隐蔽的坑
2. join 按第一个字段关联，两边必须先 sort；comm 比较的是「整行」是否相同，join 才是「按键关联」，别混
3. 时间聚合用 split($4, t, ":") 把 "10:00:01" 拆成 t[1]=10 t[2]=00 t[3]=01，t[1] 是小时、t[1]":"t[2] 是分钟
4. bash 进程替换 <(...) 不是 POSIX，sh 脚本里改用临时文件，否则 join <(sort a) <(sort b) 会失败
5. 红帽系注意：RHEL 8+ 日志在 journald，先 journalctl -u 服务名 --since today 导出成文本，再跑上面的 awk 聚合
```

### 场景五：多文件关联与合并（join / comm / paste / column）

运维常要合并多个来源的数据：两张表按 ID 关联（类似 SQL JOIN）、两份清单找交集/差集、把字段拼成一行。join 按共同字段关联、comm 比较整行、paste 按行并排、column 对齐成表。全部本机真跑：

```shell
# 数据：/tmp/a.txt（ID 姓名）、/tmp/b.txt（ID 部门）
# a.txt: 1 alice / 2 bob / 3 carol；b.txt: 1 dev / 2 ops / 4 sales

# 1. join 按第一列关联（两边先 sort）
join <(sort /tmp/a.txt) <(sort /tmp/b.txt)

# 2. paste 按行并排（不关联，只对齐行号）
paste /tmp/a.txt /tmp/b.txt

# 3. column 把空格分隔输出对齐成表
printf '1 alice dev\n2 bob ops\n3 carol sales\n' | column -t

# 4. 统计 /etc/passwd 里 UID 最大的三个账号（sort -n 数值排序）
awk -F: '{print $3, $1}' /etc/passwd | sort -n | tail -3
```

```text
# 实测
$ join <(sort /tmp/a.txt) <(sort /tmp/b.txt)
1 alice dev
2 bob ops

$ paste /tmp/a.txt /tmp/b.txt
1 alice  1 dev
2 bob    2 ops
3 carol  4 sales

$ printf '1 alice dev\n2 bob ops\n3 carol sales\n' | column -t
1  alice  dev
2  bob    ops
3  carol  sales

$ awk -F: '{print $3, $1}' /etc/passwd | sort -n | tail -3
999 dnsmasq
1000 lw
65534 nobody
```

```text
要点：
1. join 只输出两边都有的键（内连接）；想保留单边用 join -a 1 或 -a 2（左/右外连接）
2. comm 比较的是整行是否逐字相同，join 才是按键关联——两份「看起来相关」但字段不同的文件，comm 给空、join 给结果
3. paste 不按键关联，只把第 N 行拼第 N 行，行数不同时短的补空
4. column -t 只做展示对齐、不改变数据，适合临时看结果，别把它当数据清洗
5. 红帽/CentOS 的 /etc/passwd 字段结构和 Debian 一致（7 字段冒号分隔），UID 500/1000 起是普通用户的分界线两边也一致
```

## 性能与调优

```text
1. 大日志先 wc -l 看规模，再决定全量还是抽样分析
2. 几十 GB 日志别用 awk 关联数组憋在内存，改用 sort | uniq -c 流式外部排序
3. sort 加 LC_ALL=C 提速，加 -T 指定临时目录防磁盘满
4. 管道尽量让 awk 先做字段提取、缩小数据量，再交给 sort 排序
5. 组合命令写成脚本存档，改个路径就能复用，别每次现拼
```

```text
进阶调优：
1. 抽样分析：大日志用 head/tail 取片段先验证命令，再跑全量
2. 多维度统计一次 awk 做完（一个数组存一个维度），别为每个维度重扫一遍文件
3. grep -E 一次匹配多关键词，别写多个 grep 串起来
4. 结果复用：中间结果存 /tmp 文件，避免反复重跑同一条耗时管道
5. sort --parallel=N 多核排序，大文件提速明显
```

```text
实测量级（本机 200 万行、12MB 的 /tmp/big.txt，SSD 本地）：
$ seq 1 2000000 > /tmp/big.txt
$ time grep -c '1999999' /tmp/big.txt
1
real    0m0.010s  user 0m0.004s  sys 0m0.006s
$ time rg -c '1999999' /tmp/big.txt
1
real    0m0.005s  user 0m0.003s  sys 0m0.002s
# 结论：单模式计数 grep 和 rg 都在毫秒级；rg 更快主要靠多线程并行 + 默认跳过二进制/隐藏文件。
```

```text
工具选型与红帽差异：
1. 大文件首选 rg（ripgrep 14.1 本机已装）；没 rg 用 grep，先加 LC_ALL=C（回避 UTF-8 解码，提速明显）
2. 关联数组内存：awk '{cnt[$k]++}' 在 END 前把唯一键全攒内存；几十 GB 日志改 sort | uniq -c 外部排序
3. sort 提速三件套：LC_ALL=C + -T /path（临时目录放快盘）+ --parallel=N
4. 红帽/CentOS 服务器 CPU 核多，sort --parallel 和 rg -j 收益比笔记本大；按核数调
5. 别在管道里反复重扫同一文件：一次 awk 多建几个数组，比 grep X | awk、grep Y | awk 各扫一遍省 I/O
```

```text
管道里排序是主要耗时点（本机 200 万行 /tmp/big.txt 实测）：
$ time sort -u big.txt | wc -l
2000000
real    0m0.959s  user 0m3.868s  sys 0m0.163s
$ time awk '{print $1}' big.txt > /dev/null
real    0m0.153s  user 0m0.151s  sys 0m0.002s
$ time grep -c '^1999999$' big.txt
1
real    0m0.008s  user 0m0.006s  sys 0m0.002s
# 量级差：grep 过滤（0.01s）< awk 提取（0.15s）<< sort（1s）。
# 结论：先 grep 缩范围、再 awk 提取、最后才 sort，排序放最后且数据量越小越好。
```

```text
提速经验：
1. 排序是 O(n log n) 且要写临时文件，是管道里最贵的操作，先用 grep/awk 裁到最小数据量再 sort
2. sort -u 比 sort | uniq 少一次进程 + 少一次全量读，去重优先 sort -u
3. 多列排序用 sort -k2,2 -n 明确字段边界（-k2 会从第 2 列排到行尾，-k2,2 只排第 2 列）
4. 大文件 sort 用 -T /dev/shm 或快盘做临时目录 + --parallel=$(nproc)，比默认 /tmp 快
5. Red Hat/CentOS 服务器磁盘阵列 + 大内存，sort 的 -S 参数（指定内存缓冲）可以调大，Debian/Ubuntu 同理按机器调
```

## 安全与权限

```text
1. 分析日志提取的敏感字段（token/密码/用户隐私）别原样输出或外发
2. 批量改名/删除前先打印清单确认，防止误删误改
3. 处理 /etc/passwd、/etc/shadow 等敏感文件时，结果别重定向到可被他人读的位置
4. 用 xargs 批量操作时注意文件名含空格/特殊字符，用 -0 或引号保护
5. sed -i 原地修改前先备份（sed -i.bak 或 cp 一份），改坏能回滚
6. 日志里 IP/用户名属隐私数据，外部分享统计结果前先脱敏（sed 打码或只发聚合结果）
7. 未加引号的变量拼进 sed/awk 是注入点：变量内容会被当作命令解释
```

```text
实测（变量内容覆盖 sed 脚本）：
$ var='s/.*/INJECTED/'
$ echo 'hello' | sed "$var"
INJECTED
# var 本身就是 sed 脚本，输出被它改写；若 var 来自用户输入（文件名/日志内容），
# 恶意内容可执行任意 sed 替换、甚至配合 -i 改文件。正确做法：变量只作为数据，用 awk -v 传值并转义。
```

```text
8. ReDoS（正则灾难性回溯）只在 grep -P（PCRE 回溯引擎）存在；grep -E/-F 用 DFA/BM 线性算法不回溯。
   对不可信输入跑 grep -P 时正则写不好可能 CPU 打满；默认 BRE/ERE 无此问题。
9. sed -i 改生产配置前先备份（sed -i.bak）；Red Hat/CentOS 的 SELinux 可能拦 sed 改 /etc 下文件，
   报 "Permission denied" 时看 audit.log 定位，别盲改。
```

## 故障排查

```text
「统计结果对不上」排查顺序：
1. 字段错位 —— 先 awk '{print NR, NF, $1, $2, $3}' 摸清每列
2. 分隔符 —— CSV 忘了 -F,，或空格/tab 混用
3. 表头混入 —— 忘了 NR>1 跳过表头，统计多出奇怪键
4. 数值 vs 字符串 —— 排序比较忘加 -n 或 $n+0 数值化

「管道中间结果异常」排查：
- 把管道逐段拆开（去掉后面的 | 看当前输出），定位是哪一段出了问题

「批量改名后文件名不对」排查：
- 参数扩展写错：${f%.txt} 是去尾部 .txt，${f%%.txt} 是贪婪去第一个 . 之后全部
- 目标文件已存在被覆盖：改名前 [ -e "$new" ] 检查，或 mv -n

「sed -i 改坏文件」排查：
- 正则没锚定（\b 边界），误替换了不该换的内容
- 没备份无法回滚：养成 sed -i.bak 或先 cp 备份的习惯
「grep 报 Binary file matches」排查：
- grep 检测到二进制内容（NUL 字节），默认只提示不输出匹配行
- 确认是文本就加 -a（--text）强制当文本处理；确认是二进制就别 grep，用 strings 或 file 先看类型

「grep 报 argument list too long」排查：
- 通配符展开的文件太多，超过 execve 参数上限（单次 argv 总长）
- 改 find ... -exec grep ... {} + 或 find ... -print0 | xargs -0 grep ...，分批处理

「中文乱码 / locale 警告」排查：
- 文件是 GBK 编码、LANG 是 UTF-8，grep/sed 输出乱码 → 先 iconv -f GBK -t UTF-8 转码
- 报 "warning: setlocale: LC_ALL: cannot change locale (en_US.UTF-8)" → 该 locale 未生成，
  用 locale -a 看有哪些可用，改设 C.UTF-8 或 zh_CN.UTF-8
- 排序结果和预期不符 → LC_COLLATE 影响，脚本里显式 LC_ALL=C

「sed 报 invalid command code」排查：
- 脚本里有未转义的特殊字符（如替换内容里的 / & \），或命令拼错
- 用 # 或 | 做 s 命令分隔符避免 / 冲突：sed 's#/path#/newpath#g'
```

## 常见问题

```text
Q1: 为什么分析日志要先看字段格式？
A: nginx 日志字段位置由 log_format 定义，不同格式字段位置不同。先 head 看样本 + 摸清分隔符，否则 awk 统计全错。

Q2: 大日志 awk 统计内存暴涨怎么办？
A: 关联数组在 END 前一直累积。改 sort | uniq -c 流式统计（外部排序），或抽样分析。

Q3: 批量改名怎么防止误操作？
A: 先 for f in ...; do echo "mv $f ..."; done 只打印清单，确认后再真正 mv。

Q4: 组合命令为什么比写一个大脚本好排查？
A: 管道每一步可拆开验证，删掉后面的 | 就能看中间输出，逐段定位问题。

Q5: CSV 字段里含逗号怎么处理？
A: awk/cut 只按字符切、不解析引号转义，含逗号的字段会被拆错。简单场景可先用 csvkit 的 csvcut/csvgrep，复杂场景用 Python 的 csv 模块。

Q6: 批量改文件内容（不是改名）怎么做？
A: grep -rl '旧值' 目录 先定位含目标的文件，再 sed -i 's/旧/新/g' 文件列表 原地替换。改前先备份（sed -i.bak）防改坏。

Q7: 怎么统计某个接口的响应时间分布？
A: 先确认日志格式里有响应时间字段（如 $request_time），再 awk '{print $n}' 提取该列，用 sort -n 排序看分位数，或 awk 分组统计区间分布。

Q8: 日志字段里残留 \r（CRLF）导致统计错乱怎么办？
A: 先用 file 确认 "CRLF line terminators"，再 sed 's/\r$//' 或 tr -d '\r' 清洗，之后再做统计。本机没装 dos2unix，sed/tr/perl 是等价替代。

Q9: 为什么 sort | uniq -c 的输出计数对不齐、awk 再处理会错位？
A: uniq -c 的计数列是右对齐的（前面补空格），awk 直接处理时字段会错位。要用 awk '{print $1}' 取计数、$2 取键，或 uniq -c 前先 awk 输出干净字段。

Q10: awk 关联数组遍历顺序不稳定，想要确定顺序怎么办？
A: for (k in arr) 的遍历顺序是未定义的（mawk 按内部哈希序）。要稳定就 END 里把结果打印成「键 值」再管道给 sort。

Q11: 同一个 awk 脚本在 Ubuntu 能跑、到 CentOS 报 "function gensub never defined"？
A: 用了 gawk 扩展。Ubuntu 默认 awk 是 mawk、CentOS 默认是 gawk。跨平台只用 POSIX 语法；必须用 gawk 扩展时，CentOS 直接用、Ubuntu 先 sudo apt install gawk 再显式调用 gawk。

Q12: 分析系统日志时发现 /var/log/messages 不存在？
A: RHEL 8/CentOS 8+ 默认走 systemd-journald，不再有 messages 文件。用 journalctl -u 服务名 --since today 导出文本，再喂给三剑客处理；CentOS 7 及以前才直接 grep /var/log/messages。
```

## 面试题

```text
1. 一条命令统计日志里每个 IP 的访问次数并倒序？
   答：awk '{print $1}' access.log | sort | uniq -c | sort -rn。

2. 怎么从日志里找出访问最多的前 5 个接口？
   答：awk '{print $7}' access.log | sort | uniq -c | sort -rn | head -5。

3. CSV 文件统计各部门人数怎么写？
   答：awk -F, 'NR>1 {cnt[$3]++} END {for (d in cnt) print d, cnt[d]}' users.csv。

4. 批量把 .txt 改成 .md 有哪些方法？
   答：for 循环 + 参数扩展 ${f%.txt}.md，或 rename 命令 rename 's/\.txt$/.md/' *.txt。

5. 一条命令统计日志里 5xx 错误的接口和次数？
   答：awk '$9>=500 {print $7}' access.log | sort | uniq -c | sort -rn，先用 awk 过滤状态码、再分组计数。

6. 为什么日志统计要「sort 两次」（sort | uniq -c | sort -rn）？
   答：第一次 sort 把相同行聚到一起（uniq 只合并相邻行），第二次 sort -rn 按计数结果倒序，把最多的排前面。两次 sort 目的不同。

7. 大日志（几十 GB）怎么做分组统计？
   答：别用 awk 关联数组（内存累积），改用 awk 提取字段后 sort | uniq -c 外部排序流式统计，或抽样分析。sort 加 -T 指定临时目录、LC_ALL=C 提速。

8. awk 默认分隔符和 cut -d' ' 有什么区别？
   答：awk 默认 FS 是「连续空白」（空格/tab 任意组合都当一个分隔符），cut -d' ' 是按「单个空格」切，连续空格会产生空字段。所以字段对齐的数据用 awk 比 cut 稳。

9. 怎么把两个文件按共同字段关联（类似 SQL JOIN）？
   答：join 命令，两边先 sort，join file1 file2 按第一列关联；comm 比较的是整行是否相同，不是按键关联，别混用。bash 里可用 join <(sort a) <(sort b) 免临时文件。

10. grep 报 "Binary file matches" 不输出内容怎么办？
   答：文件含 NUL 字节被 grep 判定为二进制。确认是文本就加 -a 强制当文本；真二进制用 strings 先提取可读串，或 file 先看类型。

11. 为什么 grep -P 的正则要小心 ReDoS？
   答：-P 走 PCRE 回溯引擎，构造不当的正则对恶意输入可能指数级回溯、CPU 打满；默认 BRE/ERE 是线性 DFA/BM 不回溯，无此风险。不可信输入优先用 -E。

12. 中文日志排序结果和预期不一样？
   答：sort 按 LC_COLLATE 排，zh_CN.UTF-8 和 C 的结果不同。要稳定字节序就 LC_ALL=C sort；要拼音序需要 locale 支持。脚本里显式设 LC_ALL 避免换机器结果漂移。

13. sed 替换内容里带 / 或 & 怎么写？
   答：换分隔符 sed 's#/a/b#/x/y#g'，或用转义 \/ \&。& 在替换串里代表「整个匹配」，要字面 & 写成 \&。

14. 批量改文件内容（不是改名）怎么做才安全？
   答：先 grep -rl '旧值' 目录 定位文件，确认清单后 sed -i.bak 's/旧/新/g' 文件列表，.bak 保留备份可回滚。生产环境改前再核对一遍 grep 命中的行。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 分析日志先摸清字段格式（$1 是什么），再写统计，别猜字段
2. 统计套路固定：awk 提取 → sort | uniq -c → sort -rn → head
3. CSV 处理统一 awk -F, + NR>1，比 cut 更稳（默认按空白切、能算数值）
4. 批量改名/删除前先「只打印清单」，确认后再真正执行
5. 复杂文本处理写成脚本存档，下次改个路径就能复用
6. 大日志抽样分析：先 head/tail 取片段验证命令，再跑全量
7. sed -i 改文件前先备份（-i.bak），改坏能回滚

### 踩坑记录

```text
坑 1：日志字段错位导致统计结果牛头不对马嘴
结论：awk '{print $9}' 统计出来的「状态码」根本不是状态码。
原因：日志格式和默认 nginx 格式不同，或含特殊分隔符导致字段错位。
解法：先 awk '{print NR, NF, $1, $2...}' 摸清每列，再写统计。

坑 2：批量改名时文件名含空格被拆断
结论：for f in *.txt 遇到 "my file.txt" 循环变量被拆成两个。
原因：shell 分词把空格当成参数分隔符。
解法：循环里给 "$f" 加引号，或用 find -print0 | xargs -0。

坑 3：mv 批量改名时目标文件已存在被覆盖
结论：a.txt 改成 a.md 时 a.md 已存在，原文件被覆盖。
原因：mv 默认覆盖目标文件，没做存在性检查。
解法：改名前 [ -e "$new" ] 检查，或用 mv -n 不覆盖。

坑 4：awk 统计 401 却漏了带引号或空格的状态码
结论：日志里状态码列偶尔带别的字符，统计出来多出奇怪的键。
原因：日志格式不统一，某列混入了非预期内容。
解法：统计前用 awk 校验字段类型，或 grep 先过滤出格式正常的行。

坑 5：处理大日志时 awk 把所有结果憋在内存里
结论：几十 GB 日志 awk '{cnt[$k]++} END{...}' 内存暴涨。
原因：关联数组在 END 前一直累积，大文件下内存占用高。
解法：大日志用 sort | uniq -c 流式统计（外部排序），或抽样分析。

坑 6：sed -i 正则没锚定，误替换了不该换的内容
结论：sed -i 's/foo/bar/g' 把 foobar、food 里的 foo 也一起替换了。
原因：正则没加边界（\b）或锚定（^ $），子串匹配命中超出预期。
解法：用 \bfoo\b 限定单词边界，或先 grep 预览会被替换的行再 sed。

坑 7：处理日志时把含敏感字段的中间结果重定向到公共目录
结论：把提取出的 token/密码/用户信息写到 /tmp 下 644 权限的文件，别人可读。
原因：没注意中间结果文件的权限和内容敏感性。
解法：敏感字段先脱敏（sed 打码），中间结果写受限目录并设 600 权限，用完即删。

坑 8：CSV 忘了 NR>1，表头被当成一条数据混进统计
结论：awk -F, '$4>=15000' 把表头 "name salary" 也打印出来。
原因：表头行 "salary" 不是数字，awk 对字符串和数字比较走字符串比较，"salary" > "15000" 成立，表头漏过过滤。
解法：过滤/统计前先 NR>1 跳过表头；数值列用 $4+0 强制数值化再比较。

坑 9：uniq -c 输出右对齐，awk 再处理时字段错位
结论：sort | uniq -c 的输出再喂给 awk '{print $2}' 取到的是空格不是键。
原因：uniq -c 的计数列前补空格右对齐（宽度随最大计数变化），awk 默认按连续空白切，字段位置漂移。
解法：取 uniq -c 输出时用 awk '{print $1, $2}' 明确第 1 第 2 列，或 sort | uniq -c | sort -rn 后直接 head 不再切列。

坑 10：Windows 日志的 CRLF 导致去重/统计全错
结论：同样的行 a 和 a\r 被 sort/uniq 当成两条不同记录。
原因：\r 残留在行尾，sort 比较时 \r 参与比较，导致「看起来一样」的行其实不同。
解法：先 sed 's/\r$//' 或 tr -d '\r' 清洗，或 file 确认后统一转 LF 再统计。

坑 11：awk 关联数组遍历顺序每次跑可能不同
结论：for (k in cnt) 打印的键顺序不稳定，直接当报表输出顺序乱跳。
原因：关联数组内部是哈希表，遍历顺序未定义（mawk/gawk 实现不同、同实现也可能随插入变化）。
解法：END 里打印「键 值」后管道给 sort；要按值排 sort -k2 -rn、要按键排 sort。

坑 12：sed -i 跨平台脚本没带备份后缀，macOS 上直接报错
结论：sed -i 's/a/b/' 在 GNU sed 正常，在 macOS/BSD sed 报 "invalid option -- i" 或把 's/a/b/' 当后缀。
原因：BSD sed 的 -i 必须紧跟一个后缀参数（可为空字符串 sed -i ''），GNU sed 的后缀可省略。
解法：跨平台脚本统一 sed -i.bak 's/.../'（两边都生成 .bak，行为一致）；Red Hat/CentOS 用 GNU sed 与 Debian 一致，只有 macOS/BSD 需注意。
```

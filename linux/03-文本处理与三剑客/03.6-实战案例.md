## 概述

这一篇把正则、grep、sed、awk、sort/uniq 串起来，用三个真实场景演示「三剑客组合拳」怎么落地：日志统计分析、CSV 与配置文件处理、批量改名。核心思路都一样——先看清数据格式、再用管道把各工具串成流水线、最后用真实结果验证。每个案例都基于本机真实数据跑过，可以直接照搬改路径复用。

```text
三剑客组合套路：
1. 日志统计 —— grep 过滤 → awk 提取字段 → sort | uniq -c 计数 → sort -rn 排序 → head 取前 N
2. 表格处理 —— cut/awk 切列 → 条件过滤 → 数值汇总
3. 批量操作 —— find/ls 生成清单 → xargs/循环 → sed/awk 逐个改名或改内容
```

## 核心概念

组合拳的本质是「单一职责 + 管道拼接」：每个工具只做一件事，用管道把输出接到下一个工具的输入。

### 日志统计流水线

日志统计是最高频的组合。标准套路：grep 过滤掉噪音 → awk 提取关心的字段 → sort | uniq -c 分组计数 → sort -rn 按次数倒序 → head 取 TOP N。这条链每一步输出都清晰可验证，中间卡住就拆开逐段排查。

```text
grep 过滤 → awk 提取 → sort | uniq -c 计数 → sort -rn 倒序 → head 取前 N
```

### 表格处理流水线

CSV、冒号分隔的配置文件（/etc/passwd）这类「结构化数据」，用 awk 切列 + 条件 + 数值汇总。核心是「awk -F分隔符 切列 + NR>1 跳表头 + 条件过滤 + 数值计算」四件套，比 cut 更稳（默认按空白切、能算数值）。

```text
awk -F, 切列 → NR>1 跳表头 → 条件过滤 → 分组/求和/求平均
```

### 批量操作流水线

批量改名、批量改内容的核心是「生成清单 → 逐个处理」。清单用 find/ls 生成，逐个处理用 shell 循环或 xargs，改名/改内容用参数扩展或 sed。关键纪律：先只打印清单确认，再真正执行。

```text
find/ls 生成清单 → xargs/循环 → sed/参数扩展 逐个改名或改内容
```

## 工作原理

整条流水线是「流式管道」，每个工具都是过滤器：读上一级的 stdout、处理后写自己的 stdout，交给下一级。数据从左往右流动，任何一级只关心自己的输入格式和输出格式：

1. **字段定位**：先摸清数据格式（nginx 日志 $1=IP、$7=路径、$9=状态码），这是后续所有统计的前提。
2. **逐步缩小**：grep 缩小范围 → awk 提取字段 → sort/uniq 聚合并计数，每一步都在减少数据量。
3. **可验证性**：管道可以任意拆断——去掉 `| head` 就能看中间结果，逐段调试，这正是组合拳比「写一个大脚本」好排查的原因。

```text
数据流：原始文件 → grep 过滤 → awk 提取 → sort 聚合 → uniq -c 计数 → sort -rn 排序 → head 截断
每一步可拆开验证：删掉后面的管道就能看当前阶段的输出
```

## 常用命令与配置

三个场景的高频命令汇总：

```shell
# 日志统计
wc -l < access.log                                  # 总行数
awk '{cnt[$9]++} END {for (k in cnt) print k, cnt[k]}' access.log | sort -k2 -rn   # 状态码分布
awk '{print $7}' access.log | sort | uniq -c | sort -rn | head -5                  # 路径 TOP5
awk '{print $1}' access.log | sort | uniq -c | sort -rn                           # 来源 IP

# 表格处理
awk -F, 'NR>1 {cnt[$3]++} END {for (d in cnt) print d, cnt[d]}' users.csv          # 分组计数
awk -F, 'NR>1 {sum+=$4} END {print sum/(NR-1)}' users.csv                          # 求平均
awk -F: '$7 ~ /bash|sh$/ {print $1, $7}' /etc/passwd                               # 切 passwd

# 批量改名
for f in *.txt; do mv "$f" "${f%.txt}.md"; done                                    # 循环 + 参数扩展
rename 's/\.txt$/.md/' *.txt                                                       # rename 命令
```

## 配置文件解析

文本处理的「配置」主要体现在**数据格式的定义**上——格式决定字段位置，字段位置决定 awk 怎么写：

```text
1. nginx 日志格式由 nginx.conf 里的 log_format 定义，
   默认 combined 格式按空白切分后：$1=IP、$7=路径、$9=状态码、$10=字节
2. 自定义 log_format 会改变字段顺序，分析前先看日志样本确认 $N 对应什么
3. /etc/passwd 是冒号分隔的固定 7 字段，awk -F: 切列前先确认字段含义
4. 分析任何「按列」的数据，第一步永远是 head 看样本 + 摸清分隔符和字段
```

## 应用场景实战

### 场景一：Nginx 与应用日志统计分析

访问日志是最常见的分析对象，标准 nginx 格式按空白切分后字段固定：$1 客户端 IP、$7 请求路径、$9 状态码、$10 响应字节。分析套路三步走：先看整体规模、再按维度分组统计、最后定位异常。下面这套命令能回答「谁在访问、访问什么、报错没有、哪个接口最热」四个问题。

```shell
# 1. 总请求数
wc -l < /var/log/nginx/access.log
# 2. 状态码分布（健康度一目了然）
awk '{cnt[$9]++} END {for (k in cnt) print k, cnt[k]}' /var/log/nginx/access.log | sort -k2 -rn
# 3. 请求路径 TOP 榜（哪个接口最热）
awk '{print $7}' /var/log/nginx/access.log | sort | uniq -c | sort -rn | head -5
# 4. 客户端 IP 来源（谁在访问）
awk '{print $1}' /var/log/nginx/access.log | sort | uniq -c | sort -rn | head
```

```text
# 实测（本机真实 nginx 日志）
$ wc -l < /var/log/nginx/access.log
824
$ awk '{cnt[$9]++} END {for (k in cnt) print k, cnt[k]}' /var/log/nginx/access.log | sort -k2 -rn
401 527
200 279
101 18
$ awk '{print $7}' /var/log/nginx/access.log | sort | uniq -c | sort -rn | head -5
    527 /api/pair/heartbeat
     81 /api/pet/state
     18 /aionui-panel/list
     10 /api/subagent.list
     10 /api/dynamicCordisRunner/inventory
# 真实结论：/api/pair/heartbeat 被请求 527 次、全部返回 401（未授权）——
# 心跳接口鉴权失败导致客户端反复重试。这就是「用日志看出生产问题」的完整示范。
```

### 场景二：CSV 与配置文件处理

CSV 和键值配置文件是运维经常要处理的结构化数据。CSV 用 `-F,` 切列、`NR>1` 跳过表头，就能做过滤、分组、数值汇总；配置文件（冒号分隔的 /etc/passwd、键值对的 .env）同理，只是换分隔符。核心是「awk 切列 + 条件 + 汇总」三段式。

```shell
# CSV：统计各部门人数、算平均工资、过滤高薪员工
awk -F, 'NR>1 {cnt[$3]++} END {for (d in cnt) print d, cnt[d]}' /tmp/users.csv
awk -F, 'NR>1 {sum+=$4} END {print "平均工资:", sum/(NR-1)}' /tmp/users.csv
awk -F, '$4>=15000 {print $2, $4}' /tmp/users.csv

# 冒号分隔的 /etc/passwd：列出所有可登录用户的用户名和 shell
awk -F: '$7 ~ /bash|sh$/ {print $1, $7}' /etc/passwd | head
```

```text
# 实测（CSV 部分）
$ awk -F, 'NR>1 {cnt[$3]++} END {for (d in cnt) print d, cnt[d]}' /tmp/users.csv
dev 3
ops 1
sales 1
$ awk -F, 'NR>1 {sum+=$4} END {print "平均工资:", sum/(NR-1)}' /tmp/users.csv
平均工资: 14200
$ awk -F, '$4>=15000 {print $2, $4}' /tmp/users.csv
alice 15000
carol 18000
eve 16000
```

### 场景三：批量改名

批量改名的核心是「循环 + 参数扩展」或 rename 命令。`${f%.txt}` 去掉文件名尾部的 .txt，`${f%%.*}` 去掉第一个点之后的所有内容，`${f/旧/新}` 替换第一个匹配。复杂规则用 sed 生成新名字再 mv。注意批量操作前先「只打印不执行」，确认清单无误再真正改名。

```shell
# 方案一：shell 循环 + 参数扩展
cd /tmp/renametest
for f in *.txt; do mv "$f" "${f%.txt}.md"; done
ls

# 方案二：rename 命令（正则批量替换扩展名）
rename 's/\.txt$/.md/' *.txt
```

```text
# 实测（改名前 → 改名后）
$ ls
file1.txt  file2.txt  file3.txt
$ for f in *.txt; do mv "$f" "${f%.txt}.md"; done
$ ls
file1.md  file2.md  file3.md
```

## 性能与调优

```text
1. 大日志先 wc -l 看规模，再决定全量还是抽样分析
2. 几十 GB 日志别用 awk 关联数组憋在内存，改用 sort | uniq -c 流式外部排序
3. sort 加 LC_ALL=C 提速，加 -T 指定临时目录防磁盘满
4. 管道尽量让 awk 先做字段提取、缩小数据量，再交给 sort 排序
5. 组合命令写成脚本存档，改个路径就能复用，别每次现拼
```

## 安全与权限

```text
1. 分析日志提取的敏感字段（token/密码/用户隐私）别原样输出或外发
2. 批量改名/删除前先打印清单确认，防止误删误改
3. 处理 /etc/passwd、/etc/shadow 等敏感文件时，结果别重定向到可被他人读的位置
4. 用 xargs 批量操作时注意文件名含空格/特殊字符，用 -0 或引号保护
```

## 故障排查

```text
「统计结果对不上」排查顺序：
1. 字段错位 —— 先 awk '{print NR, NF, $1, $2, $3}' 摸清每列
2. 分隔符 —— CSV 忘了 -F,，或空格/tab 混用
3. 表头混入 —— 忘了 NR>1 跳过表头，统计多出奇怪键
4. 数值 vs 字符串 —— 排序比较忘加 -n 或 $n+0 数值化

「管道中间结果异常」排查：
- 把管道逐段拆开（去掉后面的 | 看当前输出），定位是哪一段出了问题
```

## 常见问题

```text
Q1: 为什么分析日志要先看字段格式？
A: nginx 日志字段位置由 log_format 定义，不同格式字段位置不同。先 head 看样本 + 摸清分隔符，否则 awk 统计全错。

Q2: 大日志 awk 统计内存暴涨怎么办？
A: 关联数组在 END 前一直累积。改 sort | uniq -c 流式统计（外部排序），或抽样分析。

Q3: 批量改名怎么防止误操作？
A: 先 for f in ...; do echo "mv $f ..."; done 只打印清单，确认后再真正 mv。

Q4: 组合命令为什么比写一个大脚本好排查？
A: 管道每一步可拆开验证，删掉后面的 | 就能看中间输出，逐段定位问题。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 分析日志先摸清字段格式（$1 是什么），再写统计，别猜字段
2. 统计套路固定：awk 提取 → sort | uniq -c → sort -rn → head
3. CSV 处理统一 awk -F, + NR>1，比 cut 更稳（默认按空白切、能算数值）
4. 批量改名/删除前先「只打印清单」，确认后再真正执行
5. 复杂文本处理写成脚本存档，下次改个路径就能复用

### 踩坑记录

```text
坑 1：日志字段错位导致统计结果牛头不对马嘴
结论：awk '{print $9}' 统计出来的「状态码」根本不是状态码。
原因：日志格式和默认 nginx 格式不同，或含特殊分隔符导致字段错位。
解法：先 awk '{print NR, NF, $1, $2...}' 摸清每列，再写统计。

坑 2：批量改名时文件名含空格被拆断
结论：for f in *.txt 遇到 "my file.txt" 循环变量被拆成两个。
原因：shell 分词把空格当成参数分隔符。
解法：循环里给 "$f" 加引号，或用 find -print0 | xargs -0。

坑 3：mv 批量改名时目标文件已存在被覆盖
结论：a.txt 改成 a.md 时 a.md 已存在，原文件被覆盖。
原因：mv 默认覆盖目标文件，没做存在性检查。
解法：改名前 [ -e "$new" ] 检查，或用 mv -n 不覆盖。

坑 4：awk 统计 401 却漏了带引号或空格的状态码
结论：日志里状态码列偶尔带别的字符，统计出来多出奇怪的键。
原因：日志格式不统一，某列混入了非预期内容。
解法：统计前用 awk 校验字段类型，或 grep 先过滤出格式正常的行。

坑 5：处理大日志时 awk 把所有结果憋在内存里
结论：几十 GB 日志 awk '{cnt[$k]++} END{...}' 内存暴涨。
原因：关联数组在 END 前一直累积，大文件下内存占用高。
解法：大日志用 sort | uniq -c 流式统计（外部排序），或抽样分析。
```

## 概述

三剑客之外，还有一批「小而精」的文本工具，各自解决一类问题：sort 排序、uniq 去重计数、tr 字符替换、cut 按列截取、paste 按列合并、join 按键连接、comm 比较、diff 找差异、patch 打补丁、wc 统计。它们通常不单独出现，而是串在三剑客的管道里——`grep 过滤 → awk 提取 → sort | uniq -c 统计 → sort -rn 排序`，这一条链就是日志分析的标准流水线。

```text
工具分工表：
1. sort / uniq —— 排序、去重、计数（uniq -c 需先 sort）
2. tr / cut —— 字符级替换、按列截取
3. paste / join —— 按列合并、按键连接两个文件
4. comm / diff / patch —— 文件比较、找差异、生成并应用补丁
5. wc —— 数行数、单词数、字节数
```

## 核心概念

这批工具按「排序去重 / 字符列操作 / 合并连接 / 比较打补丁 / 统计」五组来理解。

### sort 与 uniq

sort 排序，uniq 去重。它们几乎总是成对出现——uniq 只能合并「相邻」的重复行，所以去重前必须先 sort。sort 关键选项：`-n` 按数值排序（默认字典序）、`-r` 倒序、`-k` 指定列、`-t` 指定分隔符、`-u` 排序同时去重。uniq 关键选项：`-c` 计数、`-d` 只显示重复行、`-u` 只显示不重复行。`sort | uniq -c | sort -rn` 就是「统计 + 按次数倒序」的标准套路。

```shell
# 统计各部门人数
awk -F, 'NR>1 {print $3}' /tmp/users.csv | sort | uniq -c
```

```text
# 实测
      3 dev
      1 ops
      1 sales
# 注意 uniq -c 必须先 sort，否则不连续的行不会被合并去重
```

sort 的 `-k` 按列排序、`-t` 指定分隔符、`-h`/`-V` 处理人类可读数字和版本号；uniq 的 `-d`/`-u` 各看「重复的」和「不重复的」：

```shell
# 按第 2 列数值排序（逗号分隔）
sort -t, -k2 -n /tmp/users.csv

# 按数值倒序
sort -rn /tmp/nums.txt

# 多列排序：先按第 2 列、再按第 1 列
sort -k2,2 -k1,1 /tmp/data.txt

# -h 人类可读数字排序（10K < 2M < 1G）
du -h | sort -h | tail -3

# 找出重复行 / 不重复行
sort /tmp/nums.txt | uniq -d
sort /tmp/nums.txt | uniq -u
```

```text
要点：
1. sort 默认字典序，数字排序必须 -n；-k 指定「从哪列到哪列」，-t 指定分隔符
2. sort -u 等价 sort | uniq，一步排序+去重，少一个进程
3. uniq 只合并相邻重复行，-c 计数、-d 只显重复、-u 只显不重复
4. 边界：uniq 比较的是整行，想忽略前导空白或只比部分字段用 -f/-s/-w
5. 易错点：-k2 是「从第 2 列到行尾」，要只按第 2 列须写 -k2,2，否则后续列影响排序
```

### tr 与 cut

tr 做字符级替换/删除（不是按行），cut 按列截取。tr 最常用于大小写转换、压缩重复字符、删除某类字符；cut 用 `-d` 指定分隔符、`-f` 选列，从表格数据里「切竖条」。两者定位不同：tr 操作「字符」，cut 操作「列」。CSV、冒号分隔的配置文件（如 /etc/passwd），用 cut 切列最直接。

```shell
# tr 大小写转换
echo "Hello World" | tr 'a-z' 'A-Z'
# cut 切 CSV 的第 2、4 列
cut -d, -f2,4 /tmp/users.csv
```

```text
# 实测
$ echo "Hello World" | tr 'a-z' 'A-Z'
HELLO WORLD
$ cut -d, -f2,4 /tmp/users.csv
name,salary
alice,15000
bob,12000
carol,18000
dave,10000
eve,16000
```

tr 的删除 `-d`、压缩 `-s`、取补集 `-c`；cut 的按字符 `-c`、按字节 `-b`：

```shell
# tr -d 删除数字
echo "abc123def" | tr -d '0-9'

# tr -s 压缩连续空格
echo "a   b    c" | tr -s ' '

# tr -c 取补集：保留数字，其余换成换行
echo "a1b2c3" | tr -c '0-9' '\n'

# cut -c 按字符位置截取（第 1~4 个字符）
echo "2026-08-18" | cut -c1-4

# cut 切 /etc/passwd 的用户名和 shell
cut -d: -f1,7 /etc/passwd | head -3
```

```text
要点：
1. tr 是「字符级」映射：tr SET1 SET2 逐字符替换，SET1/SET2 长度不同按末字符补
2. tr -d 删除字符、-s 压缩连续重复、-c 取补集；tr 支持 [:lower:] [:digit:] 字符类
3. cut -d 按分隔符切列、-c 按字符位置、-b 按字节；-f2,4 选第 2、4 列
4. 边界：cut 不能重排列顺序（-f4,2 仍按 2,4 输出），重排用 awk
5. 易错点：cut 默认分隔符是 tab，切空格分隔数据要 -d' ' 或改用 awk（默认按空白切）
```

### paste 与 join

paste 把两个文件的每行「横向拼接」成多列，join 按共同字段「连接」两个文件（类似 SQL JOIN）。paste 简单粗暴——按行对齐合并，不管内容；join 要两个文件先按连接字段排序，只输出两边都匹配的行。想把两列数据并排看用 paste，想按 ID 关联两个表用 join。

```shell
# paste 横向拼接：名字 + 部门
paste -d: /tmp/names.txt /tmp/depts.txt
# join 按键连接（两边都先按第1列排序）
join /tmp/j1.txt /tmp/j2.txt
```

```text
# 实测
$ paste -d: /tmp/names.txt /tmp/depts.txt
name:dept
alice:dev
bob:ops
carol:dev
dave:sales
eve:dev
$ join /tmp/j1.txt /tmp/j2.txt
1 alice dev
2 bob ops
# join 只输出两边都有共同键(1、2)的行；j1 的 3、j2 的 4 无匹配被丢弃
```

paste 的 `-s` 把多行拼成一行；join 的 `-1`/`-2` 指定连接列、`-a` 做外连接、`-e`/`-o` 控制空值和输出格式：

```shell
# paste -s 把整个文件的列串成一行（冒号分隔）
paste -s -d: /tmp/nums.txt

# join 指定左表第 1 列、右表第 1 列连接（默认就是第 1 列）
join -1 1 -2 1 /tmp/j1.txt /tmp/j2.txt

# 左外连接：保留 j1 所有行，j2 没匹配的填空值
join -a1 -e 'NULL' -o '0,1.2,2.2' /tmp/j1.txt /tmp/j2.txt
```

```text
要点：
1. paste 按行号对齐合并，不管内容是否相关；-s 转置（行变列）
2. join 类似 SQL INNER JOIN，两边必须先按连接字段排序，否则结果错乱
3. -1 n 指定左表第 n 列、-2 n 指定右表第 n 列、-t 指定分隔符
4. -a1/-a2 做左/右外连接，-e 填充空值，-o 自定义输出格式
5. 易错点：join 输入未排序会漏匹配或乱序，连接前先 sort -k 对应列
```

### comm 与 diff 与 patch

三个「比较」工具，粒度递增。comm 比较两个已排序文件的「行集合」，输出三列（只在文件1、只在文件2、两边都有）；diff 逐行找差异，`-u` 输出统一格式的补丁；patch 应用 diff 生成的补丁。comm 看「集合差异」，diff/patch 是代码/配置变更管理的基础——Git 的 patch 就是这个格式。

```shell
# comm：三列分别 = 只在f1、只在f2、两边都有
comm /tmp/f1.txt /tmp/f2.txt
# diff -u 生成统一格式补丁
diff -u /tmp/demo.txt /tmp/demo2.txt
```

```text
# 实测
$ comm /tmp/f1.txt /tmp/f2.txt
a
b
		c
		d
	e
	f
# 无缩进=只在 f1(a,b)，一个 tab=只在 f2(e,f)，两个 tab=两边都有(c,d)

$ diff -u /tmp/demo.txt /tmp/demo2.txt
--- /tmp/demo.txt
+++ /tmp/demo2.txt
@@ -1,6 +1,6 @@
-2026-08-18 10:00:01 INFO  user=alice action=login  ip=10.0.0.1
+2026-08-18 10:00:01 DEBUG  user=alice action=login  ip=10.0.0.1
 2026-08-18 10:00:05 ERROR user=bob   action=query  ip=10.0.0.2
# - 行是旧文件内容，+ 行是新文件内容，@@ 标记变更位置
```

comm 的 `-1/-2/-3` 屏蔽某列、`-12` 只取交集、`-23` 只取「仅在文件1」；diff/patch 的完整打补丁流程：

```shell
# comm -12 只输出两边都有的行（交集）
comm -12 /tmp/f1.txt /tmp/f2.txt

# comm -23 只输出「仅在文件1」的行（f1 比 f2 多的）
comm -23 /tmp/f1.txt /tmp/f2.txt

# diff 生成补丁文件
diff -u /tmp/demo.txt /tmp/demo2.txt > /tmp/change.patch

# patch 应用补丁（把 demo.txt 变成 demo2.txt）
patch /tmp/demo.txt < /tmp/change.patch

# patch 预演（只检查能否应用，不改文件）
patch --dry-run /tmp/demo.txt < /tmp/change.patch

# patch 撤销（反向应用补丁）
patch -R /tmp/demo.txt < /tmp/change.patch
```

```text
要点：
1. comm 是「集合」比较，要求两个输入都已排序；三列对应 只在f1/只在f2/两边都有
2. -12 交集、-23 仅在f1、-13 仅在f2；-3 屏蔽共同列
3. diff -u 输出统一格式（- 旧 + 新 @@ 位置），是 patch 的输入格式
4. patch 应用补丁前先 --dry-run 预演；-R 反向撤销；-pN 剥离路径前缀层数
5. 易错点：comm 输入未排序结果不可靠；patch 补丁上下文不匹配会拒绝应用并生成 .rej 文件
```

### wc

wc 统计行数、单词数、字节数（或字符数）。`wc -l` 数行、`wc -w` 数单词、`wc -c` 数字节、`wc -m` 数字符。最常用的 `wc -l` 出现在各种管道末尾——「匹配到多少行」「有多少个文件」。注意 wc 输出的顺序是 行 单词 字节，多个文件时最后还有合计行。

```shell
# 数行数和字节数
wc -l -c /tmp/demo.txt
```

```text
# 实测
6 378 /tmp/demo.txt
# 6 行，378 字节
```

`-w` 数单词、`-m` 数字符（和 `-c` 数字节在多字节编码下不同）、`-L` 最长行：

```shell
# 数单词、字符、最长行
echo "hello world" | wc -w
printf "新\n" | wc -c        # 字节数：UTF-8 中文一个字符占 3 字节
printf "新\n" | wc -m        # 字符数：1 个字符 + 1 个换行
wc -L /tmp/demo.txt          # 最长行的长度（字符数）
```

```text
要点：
1. wc 输出顺序固定：行 单词 字节（-l -w -c），多文件时最后有 total 合计行
2. -c 数字节、-m 数字符，多字节编码（UTF-8 中文）下两者不同，按需选
3. wc -l 数是换行符个数，末行无换行符时少算一行；空行也算一行
4. 管道末尾高频用法：grep 匹配数、find | wc -l 数文件
5. 易错点：wc -l 对空文件报 0、但含空行的文件「物理行数」含空行，要「非空行数」用 grep -c .
```

## 工作原理

这些工具串成管道时，核心是「流式处理 + 排序去重」两条线：

1. **流式单遍工具**：tr/cut/wc/paste 都是读一行处理一行，内存占用恒定，可以接在任意管道里处理无限流。
2. **排序去重线**：`sort | uniq -c | sort -rn` 是日志统计的标准链。uniq 只合并「相邻」重复行，所以必须先 sort 把相同的行聚到一起；`-c` 给每组合计次数；最后再 `sort -rn` 按次数倒序，把「最热的」排最前。
3. **比较类**：comm 要求两个输入都已排序（它逐行比对集合），diff 则无所谓顺序、逐行找最小差异（最长公共子序列思想）。

```text
流式工具（tr/cut/wc/paste）：单遍、内存恒定，可处理无限流
排序去重（sort | uniq -c | sort -rn）：先聚合相同行，再计数，最后按次数倒序
比较（comm 需已排序 / diff 无需排序）：集合差异 vs 逐行最小差异
```

```text
内部实现补充：
1. sort 是外部排序：内存不够时自动切块落盘、归并，所以超大文件也稳定，但依赖临时目录空间
2. sort 比较规则由 locale（LC_COLLATE）决定，字节级 vs 字典序结果不同
3. uniq 是纯流式：只记住「上一行」，所以只能合并相邻重复
4. diff 基于最长公共子序列（LCS）找最小编辑集，-u 统一格式输出变更上下文
5. join 是「双指针归并」：两边都已排序时各走一个指针，相等就输出
```

## 常用命令与配置

```shell
sort -n file              # 数值排序
sort -rn file             # 数值倒序
sort -k2 -t, file         # 按第 2 列、逗号分隔排序
sort -u file              # 排序并去重
uniq -c file              # 计数（需先 sort）
tr 'a-z' 'A-Z' < file     # 小写转大写
cut -d: -f1,7 /etc/passwd # 切 passwd 的 1、7 列
paste -d: a.txt b.txt     # 横向拼接两文件
join f1 f2                # 按键连接（需已排序）
comm f1 f2                # 比较两个已排序文件
diff -u old new           # 统一格式差异
wc -l file                # 数行
```

更多高频命令（按用途分组）：

```shell
# 排序
sort -h file              # 人类可读数字排序（10K < 2M < 1G）
sort -V file              # 版本号排序（v1.9 < v1.10）
sort -s file              # 稳定排序（相等元素保持原顺序）
sort -k2,2nr -k1,1 file   # 先按第2列数值倒序、再按第1列

# 去重计数
sort file | uniq -c       # 计数
sort file | uniq -d       # 只显重复行
sort file | uniq -u       # 只显不重复行

# 字符/列
tr -d '0-9' < file        # 删除数字
tr -s ' ' < file          # 压缩连续空格
tr '[:lower:]' '[:upper:]' < file   # 小写转大写（字符类写法）
cut -c1-10 file           # 按字符位置截取
cut -d, -f1,3 file        # 按逗号切，取第 1、3 列

# 合并/连接
paste -s -d: file         # 多行串成一行
join -1 2 -2 1 a b        # 左表第2列连右表第1列
join -a1 -e '-' a b       # 左外连接，空值填充 -

# 比较/补丁
comm -12 f1 f2            # 交集
comm -23 f1 f2            # 仅在 f1
diff -u old new > p.patch # 生成补丁
patch -p1 < p.patch       # 应用补丁
patch --dry-run < p.patch # 预演
patch -R < p.patch        # 撤销

# 统计
wc -l file                # 行数
wc -w file                # 单词数
wc -c file                # 字节数
wc -m file                # 字符数
wc -L file                # 最长行长度
```

## 配置文件解析

这些工具本身不读配置文件，但排序/比较行为受 locale 影响：

```text
1. LC_ALL / LC_COLLATE —— 决定 sort、comm 的排序规则。
   默认 C locale 按字节值排序，en_US.UTF-8 按字典序（大小写、变音符号规则不同）。
2. 需要稳定的字节级排序（脚本里结果一致）时，显式 LC_ALL=C sort ...，
   避免不同机器 locale 导致排序结果不一致。
3. diff/patch 无 locale 依赖，但 patch 的应用结果取决于补丁格式是否匹配。
```

```text
locale 影响实例：
1. LC_ALL=C sort 下，大小写按 ASCII 码值排（A-Z 在 a-z 前）
2. en_US.UTF-8 下，排序忽略大小写差异、按字母顺序（a 和 A 视为同级）
3. sort -n 数值排序不受 locale 影响，但默认字典序受
4. 脚本里要「确定性」输出时统一 LC_ALL=C，避免不同机器结果漂移
```

## 应用场景实战

### 场景一：日志关键词排行（组合 sort/uniq/cut）

```shell
# 提取 nginx 请求路径 → 统计次数 → 按次数倒序 → 取前 5
awk '{print $7}' /var/log/nginx/access.log | sort | uniq -c | sort -rn | head -5
```

```text
# 实测（本机真实日志）
    527 /api/pair/heartbeat
     81 /api/pet/state
     18 /aionui-panel/list
     10 /api/subagent.list
     10 /api/dynamicCordisRunner/inventory
```

### 场景二：对比两台机器同一份配置文件找差异

```shell
# 把两处配置分别排序后比较，找出不一致项
sort /tmp/node1.conf > /tmp/node1.sorted
sort /tmp/node2.conf > /tmp/node2.sorted
comm -3 /tmp/node1.sorted /tmp/node2.sorted   # 只看两边不同的行
```

### 场景三：用 diff + patch 管理配置文件的变更

运维里「先改一份配置文件验证、再批量应用到其它机器」的标准做法：diff 生成补丁、patch 把补丁打到其它机器。

```shell
# 1. 先改 node1 的配置，改完生成补丁
diff -u /etc/app/config.old /etc/app/config.new > /tmp/config.patch

# 2. 预演：确认补丁能干净地应用到 node2 的配置
patch --dry-run /etc/app/config.node2 < /tmp/config.patch

# 3. 实际应用
patch /etc/app/config.node2 < /tmp/config.patch

# 4. 出问题就反向撤销
patch -R /etc/app/config.node2 < /tmp/config.patch
```

```text
# config.patch 内容示例（diff -u 统一格式）
--- /etc/app/config.old
+++ /etc/app/config.new
@@ -3,7 +3,7 @@
 max_connections 100
-timeout 30
+timeout 60
 log_level info
```

```text
说明：
1. diff -u 生成统一格式补丁，patch 能据此把旧文件变成新文件
2. --dry-run 先预演，避免补丁上下文不匹配时把文件改坏
3. -R 反向应用可撤销；这是 Git「patch 工作流」的底层原语
```

## 性能与调优

```text
1. sort 大文件时加 -S 指定内存、-T 指定临时目录，避免磁盘满
2. 设 LC_ALL=C 让 sort 走字节比较，显著快于 UTF-8 字典序
3. sort 默认外部排序（内存不够自动落盘），超大文件也稳定，但注意临时目录空间
4. 能 sort -u 一步去重就别 sort | uniq（少一个进程）
5. 管道里尽量让 awk 先做字段提取、缩小数据量，再交给 sort
```

```text
进阶调优：
1. sort --parallel=N 用多核并行排序，大文件提速明显
2. sort -S 1G 把可用内存调到 1G，减少落盘次数（默认按总内存比例估）
3. 只需要前 N 条时，awk 提取后先 sort -rn | head -N，别全量 uniq 再截断（顺序是 sort|uniq|sort，head 放最后）
4. tr 是纯字符流、无缓冲，处理 GB 级流也恒定内存，适合大文件字符清洗
5. wc -l 大文件也快（只数换行符），但 wc -m 要解码字符、略慢
```

## 安全与权限

```text
1. diff 输出可能含敏感配置差异，别把生产机器配置差异外发
2. patch 应用补丁前先 patch --dry-run 预演，防补丁格式错导致文件损坏
3. comm/sort 处理含密码的文件时，中间结果（.sorted 临时文件）注意权限
4. 批量改名/删除用这些工具生成清单时，先打印确认再执行
5. sort 的临时文件默认写 /tmp，处理敏感数据时用 -T 指定受限目录并设权限
6. patch 补丁文件里可能嵌路径，应用来自不可信来源的补丁前先人工审内容
```

## 故障排查

```text
「sort 排序不对」排查：
1. 数字排成 1 10 2 —— 默认字典序，加 -n 数值排序
2. 结果因机器而异 —— locale 不同，显式 LC_ALL=C sort
3. 中文排序乱 —— 字节序 vs 字典序，按需设 locale
4. 按列排序结果乱 —— -k2 是「第2列到行尾」，要 -k2,2 限定单列

「uniq 去重不干净」排查：
- uniq 只合并相邻行，先 sort 再 uniq，或 sort -u 一步到位
- 想忽略字段前后空白差异，uniq 加 -f 跳过字段数或 -w 限定比较宽度

「join 结果漏行/乱序」排查：
- join 要求两边都按连接字段排序，先 sort -k 对应列再 join
- 想保留单边独有的行，加 -a1 或 -a2 做外连接

「patch 应用失败」排查：
- 补丁上下文（@@ 附近的行）和目标文件不一致，--dry-run 先预演
- 补丁路径层级不对，用 -pN 剥离前缀；失败会生成 .rej 文件提示冲突位置
```

## 常见问题

```text
Q1: uniq -c 前为什么必须先 sort？
A: uniq 只合并相邻重复行，不相邻的重复不去。先 sort 把相同行聚到一起才能正确计数。

Q2: sort -n 和默认排序差在哪？
A: 默认字典序 "10" < "2"（按字符串），-n 按数值 2 < 10。数字排序必须加 -n。

Q3: comm 和 diff 什么区别？
A: comm 比较两个已排序文件的「行集合」（三列输出），diff 逐行找最小差异（生成补丁）。用途不同。

Q4: cut 切不了空格分隔的数据？
A: cut 默认按 tab 切，空格分隔要 -d' ' 或改用 awk（默认按空白切，更省心）。

Q5: sort -k2 和 sort -k2,2 有什么区别？
A: -k2 是从第 2 列排序到行尾，后续列也参与比较；-k2,2 只按第 2 列排。多列排序时要用 -k 起止范围精确控制。

Q6: wc -c 和 wc -m 什么区别？
A: -c 数字节、-m 数字符。UTF-8 里一个中文占 3 字节，所以含中文时两者不同：数「占多少字节」用 -c，数「几个字符」用 -m。

Q7: patch 应用失败怎么排查？
A: 先 patch --dry-run 预演看报错，常见是补丁上下文和目标文件不一致（文件被改过），或路径层级不对需要 -pN 剥离前缀。失败会生成 .rej 文件，看它定位冲突位置。
```

## 面试题

```text
1. 怎么统计日志里每个 IP 出现的次数并排序？
   答：awk '{print $1}' log | sort | uniq -c | sort -rn，提取字段后「排序-计数-倒序」。

2. sort 的数值排序和字典序排序区别？
   答：字典序按字符串比较（"10" < "2"），数值排序 -n 按数值比较（2 < 10）。数字排序忘加 -n 是最常见的错误。

3. diff 和 patch 是什么关系？
   答：diff 生成差异补丁（-u 统一格式），patch 应用补丁把旧文件变成新文件。Git 的 patch 就是这个格式。

4. 为什么说 uniq 去重前必须 sort？
   答：uniq 只合并相邻的重复行，不 sort 时不相邻的重复不会被去重，导致去重不干净。

5. cut 和 awk 切列的区别？
   答：cut 轻量、只能按单字符分隔符切列、不能重排列顺序；awk 功能更强——默认按空白切、能做条件过滤和数值计算、能重排字段。字段含分隔符转义或要计算时用 awk。

6. join 和 paste 的区别？
   答：join 按共同字段做类似 SQL 的连接（要求两边排序、只输出匹配行），paste 按行号横向拼接（不管内容是否相关）。想按 ID 关联用 join，想把两列并排看用 paste。

7. comm 和 diff 分别用于什么场景？
   答：comm 比较两个已排序文件的「集合差异」（哪些只在 A、哪些只在 B、哪些都有），diff 逐行找「内容差异」并生成补丁。前者看集合，后者看内容变更。
```

## 最佳实践与踩坑记录

### 最佳实践

1. uniq -c 前必须先 sort，否则不连续重复行不会被合并
2. 排序用 sort -n 才是数值排序，默认字典序会让 10 排在 9 前面
3. 切 CSV 列用 cut -d, -f，但字段含逗号时换 awk -F,
4. 比较文件差异用 diff -u，可读性好、还能直接给 patch 用
5. 数文件个数用 `ls | wc -l` 或 find -type f | wc -l，别用 wc 统计空行
6. 脚本里要确定性排序统一 LC_ALL=C，避免不同机器 locale 漂移
7. 大文件排序给 sort 加 -S 内存和 -T 临时目录，防磁盘满

### 踩坑记录

```text
坑 1：uniq 没配 sort，去重不干净
结论：a a b a 去重后还是 a b a，中间隔着 b 的重复 a 没去掉。
原因：uniq 只合并相邻行，不相邻的重复不去。
解法：先 sort 再 uniq，或 sort -u 一步到位。

坑 2：sort 默认字典序导致数值排序错乱
结论：1 10 2 9 排成 1 10 2 9，不是 1 2 9 10。
原因：默认按字符串比较，"10" < "2"。
解法：加 -n 按数值排序，负数/小数也适用。

坑 3：cut 用默认 tab 分隔符切空格分隔的数据
结论：cut -f2 切空格分隔的文件切不出想要的列。
原因：cut 默认按 tab 切，不认连续空格。
解法：加 -d' ' 指定空格，或改用 awk（默认按空白切，更省心）。

坑 4：wc -l 把空文件算成 0 行但含空行的文件行数包含空行
结论：统计「有效内容行数」和「物理行数」混淆。
原因：wc -l 数的是换行符个数，空行也算一行。
解法：有效行数用 grep -c '^[^[:space:]]*$' 或 grep -vc '^$'。

坑 5：diff 比较含中文/编码差异的文件报「二进制不同」
结论：两个文本文件 diff 却提示 binary files differ。
原因：文件含非 UTF-8 字节或 BOM，diff 误判为二进制。
解法：加 -a 强制按文本比较，或先 file 确认编码。

坑 6：sort -k2 没限定到单列，排序结果和预期不符
结论：按第 2 列排，结果第 2 列相同的行顺序却乱了。
原因：-k2 实际是「从第 2 列排到行尾」，后续列也参与比较。
解法：只按第 2 列排要写 -k2,2；多列排序用 -k2,2 -k1,1 精确控制每段。

坑 7：join 输入没排序导致结果漏行
结论：join 两个文件结果少了很多匹配行，或顺序错乱。
原因：join 要求两边都按连接字段排序，未排序时双指针归并会漏匹配。
解法：连接前分别 sort -k 连接列，再 join；或改用 awk 关联数组做连接（不受排序限制）。
```

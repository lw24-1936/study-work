## 概述

grep 是按行搜索文本的工具，从文件或管道里挑出匹配模式的行。它和 sed、awk 并称「文本三剑客」，但 grep 只做一件事——过滤，不修改。日常用法几乎都长这样：`grep 关键词 文件` 找匹配行，`grep -E 正则` 用扩展正则，`grep -v` 反向过滤，`grep -r` 递归搜目录。排查日志、找配置、过滤输出，grep 都是第一个上场的工具。

```text
grep 核心能力：
1. 按行匹配 —— 匹配到模式的行整行输出，不修改原文件
2. 正则引擎 —— 默认 BRE，-E 切 ERE，-P 切 PCRE
3. 组合过滤 —— -v 取反、-i 忽略大小写、-c 计数、-n 行号、-o 只出匹配部分
```

除过滤外，grep 还承担脚本里的「条件判断」角色：退出码 0/1/2 分别表示「有匹配 / 无匹配 / 出错」，`if grep -q ...` 是 shell 里最常用的存在性判断写法。

## 核心概念

grep 的核心概念是「正则方言 + 一组过滤选项」。

### 基本与扩展正则

grep 默认用 BRE，`+ ? | ( ) { }` 要转义；加 `-E` 切到 ERE 后这些直接写。两者的差别在写正则时最容易踩坑——同一个模式，`grep 'a\+'`（BRE）和 `grep -E 'a+'`（ERE）才等价。`grep -P` 进 PCRE，支持 `\d \w \s` 简写。实战里 `grep -E` 最常用，因为不用背转义规则。

```shell
# BRE：量词要转义
grep '10\.0\.0\.[0-9]' /tmp/demo.txt | head -1
# ERE：量词直接写
grep -E '10\.0\.0\.[0-9]{1}' /tmp/demo.txt | head -1
```

```text
# 实测（两条命令都匹配到同一行，但写法不同）
2026-08-18 10:00:01 INFO  user=alice action=login  ip=10.0.0.1
```

```text
三种方言 + 固定字符串：
- grep（BRE）   默认，+ ? | ( ) { } 要转义
- grep -E（ERE）元字符直接写，日常首选
- grep -P（PCRE）支持 \d \w \s、前瞻后瞻
- grep -F        固定字符串，不解释任何元字符，最快
```

```shell
# -F 固定字符串：. 就是字面点号，不是任意字符
echo '1.2.3' | grep -F '1.2.3'     # 命中
echo '1x2y3' | grep -F '1.2.3'     # 不命中（没有字面 .）
```

```text
四种模式引擎对比：

| 方言 | 元字符写法 | 额外能力 | 引擎/速度 | 适用场景 |
|---|---|---|---|---|
| 默认（BRE） | + ? \| ( ) { } 要转义 | 无 | 线性时间 DFA | 简单固定模式 |
| -E（ERE） | 直接写，不转义 | 无 | 线性时间 DFA | 日常正则，首选 |
| -P（PCRE2） | 直接写，另有 \d \w \s | 前瞻/后瞻/非贪婪 | 回溯，有上限兜底 | 复杂提取 |
| -F（固定字符串） | 全部按字面 | 无 | Boyer-Moore，最快 | 搜字面量、用户输入 |
```

```text
选型原则：能 -F 不用正则，能 -E 不用 -P。BRE 转义规则容易写错，日常写 -E 最稳；-P 只在需要 \d \w \s 简写、前瞻后瞻、非贪婪时才上，且要接受「跨平台缺 -P」和「回溯上限」两个代价。
```

### 常用选项

grep 的选项是它的灵魂，几个高频选项背下来能覆盖 90% 的场景：`-i` 忽略大小写、`-v` 反向匹配、`-c` 计数、`-n` 显示行号、`-o` 只输出匹配的部分、`-l` 只列文件名。其中 `-c` 和 `-i` 配合排查日志特别有用——「这个错误出现多少次」「大小写混着写都算」。

```shell
grep -c 'error' /tmp/demo.txt      # 小写 error：0 次
grep -ci 'error' /tmp/demo.txt     # 忽略大小写：3 次（ERROR）
grep -v 'ERROR' /tmp/demo.txt      # 反向：排除 ERROR 行
```

```text
# 实测
$ grep -c 'error' /tmp/demo.txt
0
$ grep -ci 'error' /tmp/demo.txt
3
$ grep -v 'ERROR' /tmp/demo.txt
2026-08-18 10:00:01 INFO  user=alice action=login  ip=10.0.0.1
2026-08-18 10:01:00 WARN  user=carol action=login  ip=10.0.0.3
2026-08-18 10:02:00 INFO  user=dave  action=logout ip=10.0.0.4
# 注意 -c 数的是「行数」不是「出现次数」，一行多个匹配也只算 1
```

```text
其余高频选项：
-w  整词匹配（等价 \<模式\>），grep 'cat' 会匹配 catalog，-w 不会
-x  整行匹配，要求整行完全等于模式
-m n  最多输出 n 个匹配行后停止
-q  静默模式，只返回退出码不输出，用于脚本判断
-L  反向 -l，列出「不含」模式的文件名
-H  始终带文件名前缀（默认多文件时自动带）
```

```shell
# -w 整词匹配：排除 catalog 这类包含 cat 的干扰
echo -e 'cat\ncatalog\nconcatenate' | grep -w 'cat'
# 输出：只有 cat
echo -e 'cat\ncatalog\nconcatenate' | grep 'cat'
# 输出：三行全命中（cat 是 catalog/concatenate 的子串）
```

```shell
# -m 只取前 2 个 ERROR，-q 静默判断「有没有」
grep -m2 'ERROR' /tmp/demo.txt
grep -q 'FATAL' /tmp/demo.txt && echo "有 FATAL" || echo "无 FATAL"
```

### 提取与定位（-n / -o / -H / -h 组合）

```text
grep 的「提取」和「定位」靠 -o、-n、-H、-h 四个选项组合：

- -o 只输出匹配片段，每匹配一次输出一行（配合 -E 正则就是字段提取器）
- -n 在输出前加「行号:」，定位到文件里的具体行
- -H 强制带文件名前缀（多文件时默认就带），-h 强制去掉文件名前缀（单文件时默认不带）
- -no 组合：行号 + 匹配片段，一个匹配一行
```

```shell
# -no 组合：每个匹配单独一行，带行号和片段
printf 'error here, another error\n' | grep -no 'error'
```

```text
# 实测
$ printf 'error here, another error\n' | grep -no 'error'
1:error
1:error
```

```shell
# -oE 提取日志里的 IP（行首）和三位状态码
grep -oE '^[0-9.]+|[0-9]{3}' /tmp/access.log | head
# -H/-h：多文件搜时控制要不要文件名前缀
grep -Hn 'secret' /tmp/proj/src/y.js    # -H 强制带文件名（单文件默认不带）
grep -hn 'secret' /tmp/proj/src/*.js    # -h 强制不带文件名（多文件默认带）
```

```text
# 实测（-oE 提取 IP 和状态码，注意 -o 让每个匹配独占一行）
$ grep -oE '^[0-9.]+|[0-9]{3}' /tmp/access.log | head
10.0.0.1
200
10.0.0.2
200
```

### 递归搜索

`grep -r` 递归搜索整个目录，`-l` 只列命中的文件名、`-H` 显示文件名。在一堆配置文件里找「哪个文件配置了 server_name」、在代码库找「谁引用了这个函数」，都是 `grep -r` 的典型场景。生产服务器改配置前，先 `grep -r` 摸清影响面，避免漏改。

```shell
# 在 nginx 配置目录递归找 server_name
grep -rl 'server_name' /etc/nginx/ 2>/dev/null
```

```text
# 实测（本机 nginx 配置里包含 server_name 的文件）
/etc/nginx/sites-available/default
/etc/nginx/uwsgi_params
/etc/nginx/scgi_params
/etc/nginx/nginx.conf
/etc/nginx/fastcgi_params
/etc/nginx/conf.d/deepseek-harness.conf
/etc/nginx/conf.d/new-admin.conf
```

```text
递归搜索的过滤选项：
--include='*.conf'    只搜匹配 glob 的文件
--exclude='*.log'     跳过匹配 glob 的文件
--exclude-dir=node_modules  跳过目录（可写多个 --exclude-dir）
-I                    跳过二进制文件（不报 binary file matches）
-r                    不跟随符号链接；-R 跟随（可能死循环）
```

```shell
# 只搜 .conf 文件、跳过二进制，带行号
grep -rn --include='*.conf' -I 'server_name' /etc/nginx/ 2>/dev/null | head -3
```

### 上下文

看日志时往往不只想要匹配行，还想看它前后几行发生了什么。`-A n` 显示匹配行后 n 行（After）、`-B n` 显示前 n 行（Before）、`-C n` 前后各 n 行（Context）。排查报错时 `grep -C 3 ERROR` 一下就能看到报错前后的调用链，比只看报错行高效得多。

```shell
# WARN 前后各 1 行
grep -C1 'WARN' /tmp/demo.txt
```

```text
# 实测
2026-08-18 10:00:05 ERROR user=bob   action=query  ip=10.0.0.2
2026-08-18 10:01:00 WARN  user=carol action=login  ip=10.0.0.3
2026-08-18 10:01:10 ERROR user=alice action=upload ip=10.0.0.1
```

```text
上下文选项细节：
-A n  匹配行之后 n 行（After）
-B n  匹配行之前 n 行（Before）
-C n  前后各 n 行（Context）
多段匹配之间用 -- 分隔，可用 --group-separator=字符串 自定义分隔符
```

```shell
# 报错后 2 行、前 1 行一起看调用链
grep -B1 -A2 'ERROR' /tmp/demo.txt | head -6
```

### 多模式

要一次匹配多个关键词，用 `-e 模式1 -e 模式2`（多个 -e）或 `-E '模式1|模式2'`（ERE 交替），或者 `-f 文件` 从文件读取模式列表。`-f` 适合「关键词很多、维护在一个文件里」的场景，比如监控脚本里维护一份「需要告警的错误关键词」清单。

```shell
# 三种多模式写法
grep -E 'ERROR|WARN' /tmp/demo.txt
grep -e ERROR -e WARN /tmp/demo.txt
printf 'ERROR\nWARN\n' > /tmp/patterns.txt
grep -f /tmp/patterns.txt /tmp/demo.txt
```

```text
# 实测（grep -f 模式文件，匹配 ERROR 或 WARN 的行）
2026-08-18 10:00:05 ERROR user=bob   action=query  ip=10.0.0.2
2026-08-18 10:01:00 WARN  user=carol action=login  ip=10.0.0.3
2026-08-18 10:01:10 ERROR user=alice action=upload ip=10.0.0.1
2026-08-18 10:02:30 ERROR user=eve   action=login  ip=10.0.0.5
```

```text
多模式写法取舍：
- 模式少（2~3 个）→ -E 'a|b|c' 或 -e a -e b -e c
- 模式多、需长期维护 → -f 模式文件（每行一个模式，空行和 # 注释行会被忽略）
- 模式是纯字面量（含 . * 等）→ -F -f 文件，避免元字符被解释
```

### PCRE（-P）与平台差异

```text
grep -P 切到 PCRE2（libpcre2）引擎，支持 \d \w \s 简写、非贪婪量词、前瞻后瞻断言——这些 ERE 都没有。-P 不是 POSIX，是 GNU grep 的扩展，能否用取决于编译时是否链接了 libpcre2。
```

```shell
# 前瞻断言：只匹配后面紧跟数字的 foo
printf 'foo123\nfoobar\nfoo45\n' | grep -P 'foo(?=\d)'
# 非贪婪量词：? 让 * 尽量少匹配，逐个抓出 <div>...</div>
echo 'a<div>b</div>c<div>d</div>' | grep -oP '<div>.*?</div>'
```

```text
# 实测
$ printf 'foo123\nfoobar\nfoo45\n' | grep -P 'foo(?=\d)'
foo123
foo45
$ echo 'a<div>b</div>c<div>d</div>' | grep -oP '<div>.*?</div>'
<div>b</div>
<div>d</div>
$ printf 'foo123\n' | grep -E 'foo(?=\d)'    # ERE 不认识前瞻
grep: 警告：表达式以 ? 开头
```

```text
平台差异：
- GNU grep（Debian/Ubuntu、Red Hat/CentOS/RHEL、Arch）：编译带 libpcre2 时 -P 可用，主流发行版默认可用
- macOS 自带 BSD grep：无 -P（brew install grep 得到 ggrep）
- busybox grep（Alpine、部分精简容器镜像）：无 -P、无 -z、无 --include
- 写要跨平台跑的脚本时优先 BRE/ERE，PCRE 单独标注依赖
```

### 二进制文件判定

```text
grep 读入时发现 NUL 字节或无效 UTF-8 等二进制特征，默认不输出内容、只打印一行提示（英文 locale 下是 binary file matches，中文 locale 下是「匹配到二进制文件」），返回退出码 0（表示「有匹配」）。这是防乱码刷屏的保护，但搜混合了文本和二进制数据的日志文件时反而把匹配行吞掉，是高频坑。相关选项：-a/--text 把二进制当文本处理、-I 直接跳过二进制文件、--binary-files=binary 把有匹配的二进制文件按文件名列出。
```

```shell
# 造一个含二进制字节的文件
printf '\x89PNG\x00\x01\n' > /tmp/img.bin
grep  'PNG' /tmp/img.bin     # 默认：只提示，不输出
grep -a 'PNG' /tmp/img.bin   # -a：当文本，强制输出
grep -I 'PNG' /tmp/img.bin   # -I：直接跳过，退出码 1（当作无匹配）
```

```text
# 实测（本机 GNU grep 3.11，zh_CN.UTF-8 下提示文案是中文）
$ printf '\x89PNG\x00\x01\n' > /tmp/img.bin
$ grep 'PNG' /tmp/img.bin
grep: /tmp/img.bin: 匹配到二进制文件
$ echo $?
0
$ grep -a 'PNG' /tmp/img.bin
PNG
$ grep -I 'PNG' /tmp/img.bin
$ echo $?
1
```

```text
注意：grep 的二进制判定不只看 NUL 字节，无效 UTF-8 序列、大量控制字符也会触发；一旦判定为二进制，即使加 -n -o 也不输出内容。要「当文本强制搜」用 -a，要「彻底跳过」用 -I，两者语义相反别混用。
```

### -z 与 -Z（NUL 分隔）

```text
grep 默认以换行 \n 为记录分隔符，一条记录就是一行。加 -z（--null-data）把 NUL 字节当作记录分隔符，换行降级为普通字符——配合 find -print0、grep -lZ 这类 NUL 分隔的输出，能安全处理文件名里带空格、换行的情况。输出侧对应 -Z（--null）：匹配的文件名之间用 NUL 而不是换行分隔，供 xargs -0 消费。
```

```shell
# 文件名里带空格：换行分隔会拆错，NUL 分隔才安全
find /tmp -name '*.txt' -print0 | grep -z 'fruit' | tr '\0' '\n'
# -lZ：输出匹配文件的文件名，用 NUL 分隔
grep -lZ 'apple' /tmp/fruit.txt /tmp/t.txt | od -c | head -1
```

```text
# 实测（-lZ 输出的文件名后面是 \0 而不是 \n）
$ grep -lZ 'apple' /tmp/fruit.txt /tmp/t.txt | od -c | head -1
0000000   /   t   m   p   /   f   r   u   i   t   .   t   x   t  \0
```

```text
-z 的语义细节：一条「记录」变成「到下一个 NUL 为止」的整段内容，可以跨多个换行；此时 ^ 和 $ 锚定的是 NUL 边界，$ 匹配的是记录末尾（NUL 之前），而不是换行。busybox grep 没有 -z / -Z。
```

### 跨发行版差异（Red Hat/CentOS/RHEL vs Debian/Ubuntu）

```text
grep 本体在两大发行版系里都是 GNU grep，选项和正则行为基本一致，真正的差异集中在三处：

1. 版本新旧：RHEL/CentOS 7 自带 GNU grep 2.20（较老，-P 依赖 pcre2 包、--include 的 glob 展开有边界差异），RHEL 8/9 与 Ubuntu 24.04 已到 3.x（本机实测 3.11）。老版本写脚本时要避免依赖 3.x 才稳定的选项（如 --group-separator 的细节）。
2. 包名与安装：两系包名都是 grep，Ubuntu/Debian 用 apt install grep，Red Hat 系用 dnf install grep；pcre2 支持由发行版默认打包，一般无需额外装。
3. locale 默认值：Red Hat 系 minimal 安装常默认 LANG=C（或 en_US），Ubuntu 桌面默认 zh_CN.UTF-8 这类本地化 locale——grep -i 的大小写折叠、. 对多字节字符的匹配随 locale 变化（见下「性能与调优」的实测），同一脚本在两台机器上可能行为不同，脚本里要稳定就显式 LC_ALL=C。
4. 容器环境：Alpine、busybox 镜像里的 grep 是 busybox 实现（无 -P / -z / --include / -I），与发行版无关但与 Docker 场景强相关——容器内排查时别想当然用 GNU 选项。

注：RHEL 具体版本号未在本机实测（本机是 Ubuntu 24.04），以上版本差异为编写时参考，写脚本前以目标机器 grep --version 为准。
```

## 工作原理

grep 的处理模型是「逐行读入 → 正则匹配 → 命中输出」，本身不修改数据：

1. **逐行处理**：grep 按行读入（以 `\n` 为记录分隔符），对每一行单独跑正则匹配，命中就把整行输出。所以 grep 是「行级」工具，跨行的模式默认匹配不到。
2. **退出码语义**：找到匹配返回 0、没找到返回 1、出错（文件不存在等）返回 2。这是脚本里 `if grep -q ...` 判断的依据，和其它命令「0=成功」的语义略有不同。
3. **二进制检测**：grep 读入时若发现 NUL 字节或非文本内容，默认只打印 `binary file matches` 而不输出内容（防乱码刷屏），需要强制当文本处理加 `-a`。

```text
grep 执行流程：打开输入 → 逐行读入 → 正则匹配该行 → 命中则输出（-o 只输出匹配片段）→ 读完退出
退出码：0 有匹配 / 1 无匹配 / 2 出错
```

```shell
# 退出码在脚本里的用法：区分「没找到」和「出错」
grep -q 'FATAL' /tmp/demo.txt
case $? in
  0) echo "找到 FATAL" ;;
  1) echo "没有 FATAL" ;;
  2) echo "命令出错（文件不存在等）" ;;
esac
```

```text
补充两个处理模型细节：

4. 流式处理与缓冲：grep 从管道读入时边读边匹配，但输出默认走块缓冲——tail -f log | grep 'ERROR' 在日志量小时可能迟迟不刷出结果。加 --line-buffered 让每命中一行立即输出（tail -f 场景必备）；--color=always 强制上色时 grep 也会自动切到行缓冲。

5. -q 短路：grep -q 命中第一行即返回 0，不再读后续内容。大文件只判断「有没有」时用它，比 grep ... | head -1 快得多（后者仍可能多读内容才退出）。
```

```text
# 实测：退出码 0/1/2 三种情况
$ grep -q 'apple' /tmp/fruit.txt;    echo $?   # 有匹配
0
```

## 常用命令与配置

grep 的高频选项速查，覆盖排查日志 90% 的用法：

```shell
grep -n   'ERROR' app.log     # 带行号找错误
grep -ci  'error' app.log     # 忽略大小写计数
grep -v   'DEBUG' app.log     # 排除 DEBUG 噪音
grep -oE  '[0-9]+\.[0-9]+\.[0-9]+\.[0-9]+' access.log   # 只提取 IP
grep -C3  'ERROR' app.log     # 错误上下文各 3 行
grep -rl  'server_name' /etc/nginx/    # 递归找含关键词的文件名
grep -f   patterns.txt log    # 从文件读多个模式
grep -a   'keyword' mixed.bin # 把二进制当文本搜
grep -w   'cat' words.txt     # 整词匹配，排除 catalog
grep -m5  'ERROR' app.log     # 只要前 5 个匹配行
grep -L   'ERROR' *.log       # 列出不含 ERROR 的文件
```

```text
选项分工：
-i 忽略大小写 / -v 反向 / -c 计数 / -n 行号 / -o 只出匹配片段
-r 递归 / -l 只列文件名 / -A -B -C 上下文 / -e -f 多模式 / -a 二进制当文本
-w 整词 / -x 整行 / -m 限量 / -q 静默 / -L 反向列文件 / -I 跳过二进制
```

```shell
# 模式以 - 开头时，grep 会把 -foo 当成选项解析，报错或行为错乱
grep '-foo' /tmp/dash.txt        # 错误：把 -f 当选项，oo 当参数
grep -e '-foo' /tmp/dash.txt     # 正确：-e 显式声明这是模式
grep -- '-foo' /tmp/dash.txt     # 正确：-- 之后全是操作数
```

```text
# 实测（-foo 被当成 -f 选项，oo 被当成模式文件）
$ grep '-foo' /tmp/dash.txt
grep: oo: 没有那个文件或目录
$ grep -e '-foo' /tmp/dash.txt
-foo
$ grep -- '-foo' /tmp/dash.txt
-foo
```

```text
-- 规则：-- 之后的所有参数都当操作数（文件名/模式位置），不再当选项。模式以 - 开头、文件名以 - 开头时都要靠它或 -e 兜底。
```

## 配置文件解析

grep 本身不读配置文件，但它的行为受环境变量和 shell 别名影响：

```text
1. GREP_COLORS —— 控制匹配高亮的颜色（mt= 匹配文本颜色），默认在多数发行版开启
2. GREP_OPTIONS —— 旧版用于设默认选项，新版 grep 已废弃，别依赖
3. shell 别名 —— 很多发行版默认 alias grep='grep --color=auto'，
   这也是「交互式能高亮、脚本里没有」差异的来源
4. --exclude / --exclude-dir —— 递归搜索的过滤规则，等价于「配置哪些文件不搜」
5. --color=auto/always/never —— 控制高亮；管道或重定向时 auto 会自动关闭颜色
```

```shell
grep -rl -I --exclude-dir=node_modules 'secret' /tmp/proj
```

```text
-I 与 --exclude-dir 组合是「搜源码、躲开依赖目录和二进制」的标准姿势；-l 只看「哪个文件命中」，把结果压缩成文件名清单，避免大文件命中时刷屏。
```

### 场景六：tail -f 实时监控报错并即时刷出

```shell
# tail -f 持续输出新日志，grep --line-buffered 保证每条 ERROR 立即打印，不攒缓冲
tail -f /var/log/app.log | grep --line-buffered 'ERROR'
# 生产上常用：同时监控多个关键字，命中即触发告警
tail -f /var/log/app.log | grep --line-buffered -E 'FATAL|ERROR' | while read line; do
  curl -s -X POST https://alert.example.com/webhook -d "msg=$line"
done
```

```text
为什么必须 --line-buffered：grep 输出默认块缓冲（4KB 或 8KB 刷一次），日志量小时 tail -f 喂进来的行会停在缓冲里不显示。--line-buffered 让每命中一行就 flush 一次，交互式 tail 和实时告警都依赖它。注意 tail -f 本身不缓冲，缓冲发生在 grep 这层。
```

## 性能与调优

```text
1. 固定字符串搜索用 grep -F，跳过正则引擎，速度更快
2. 递归搜索加 --exclude-dir=node_modules --exclude='*.log'，别搜进大目录
3. 设 LC_ALL=C 可以加快多字节 locale 下的匹配速度
4. 大文件先 grep 缩小范围，再交给 awk/sed 精细处理，别让 awk 直接吃全量
5. 只关心「有没有」用 grep -q，命中即返回，不扫完整个文件
6. 递归搜索加 -I 跳过二进制文件，避免逐个探测二进制内容的开销
```

```text
# 实测：grep vs rg vs grep -F（500 万行 / 38.9MB 文件，命中行在文件末尾附近）
$ wc -lc /tmp/big5.txt
 5000000 38888896 /tmp/big5.txt
$ time grep  -c '4999999' /tmp/big5.txt
1
real 0m0.022s  user 0m0.016s  sys 0m0.006s
$ time rg    -c '4999999' /tmp/big5.txt
1
real 0m0.009s  user 0m0.004s  sys 0m0.004s
$ time grep -Fc '4999999' /tmp/big5.txt
1
real 0m0.021s  user 0m0.018s  sys 0m0.003s
```

```text
量级参考与选型：
- 单文件、固定字符串：grep -F 已经够快，GNU grep 内置 Boyer-Moore 类算法，不需要换 rg
- 递归扫大仓库、要尊重 .gitignore、要彩色结构化输出：用 rg（本机 ripgrep 14.1.0）
- 复杂正则（回溯多）时 -P 反而可能慢，能用 -F 就别上 -P；写 ^ 前缀锚定能帮引擎快速跳过不匹配行
- 500 万行单模式计数在 0.02s 量级，grep 本身不是瓶颈，真正慢的是「读磁盘」和「递归遍历文件树」
```

```text
# 实测：LC_ALL=C 对 -i 大小写折叠的影响（多字节字符）
$ printf 'Äpfel\näpfel\n' > /tmp/uml.txt
$ grep -i 'äpfel' /tmp/uml.txt           # zh_CN.UTF-8：Unicode 大小写折叠，两个都命中
Äpfel
äpfel
$ LC_ALL=C grep -i 'äpfel' /tmp/uml.txt  # C locale：按字节比较，只有小写命中
äpfel
```

```text
# 实测：. 在 UTF-8 locale 匹配整个字符，在 C locale 匹配单个字节
$ printf '张三\n' > /tmp/cn.txt
$ grep -o '.' /tmp/cn.txt           # zh_CN.UTF-8：两个完整字符
张
三
$ LC_ALL=C grep -o '.' /tmp/cn.txt  # C locale：6 个字节（每个汉字 3 字节），显示为乱码
```

```text
结论：LC_ALL=C 让 grep 按字节处理，跳过 Unicode 大小写表和字符分类，单字节比较更快；副作用是 . 不再匹配完整多字节字符、-i 的大小写折叠失效（Ä 不再匹配 ä）。脚本要稳定结果就显式 LC_ALL=C，要正确匹配多语言文本就保持 UTF-8 locale。
```

## 安全与权限

```text
1. 别用 grep 把含密码/私钥的文件内容输出到日志或终端（如 grep -r 'password' /etc/ 可能泄露）
2. 递归搜索系统目录（/etc /home）时注意权限，只读操作别误带写
3. grep 匹配结果里若含敏感字段（token/密钥），进一步处理时先脱敏
4. 排查日志时避免把 access.log 里的用户 token 整行外发到第三方
5. 用户输入直接拼进 grep 模式时，用 grep -F 或先转义元字符，避免正则注入
6. 正则注入细节：用户输入里若含 . * [ 等元字符会被解释，轻则匹配错，重则被构造恶意模式。防御用 grep -F 固定字符串，或把输入写进模式文件后用 grep -f - 从 stdin 读，避开元字符解释。
7. 灾难性回溯（ReDoS）：grep 默认的 BRE/ERE 引擎是线性时间（DFA 类），不会回溯爆炸；但 -P 走 PCRE2 回溯引擎，遇到 (a+)+$ 这类嵌套量词模式会被恶意输入触发回溯爆炸，PCRE2 靠内置回溯上限兜底（报「超过 PCRE 的回溯限制」），而不是无限挂死。
8. 权限与信息泄露：grep -r 扫 /etc /home 时命中 shadow、私钥、密码文件会整行回显到终端，排查时先想清楚搜的范围，避免把结果贴到工单/群聊外泄。
```

```text
# 实测：同一输入，-E（线性）与 -P（回溯）的天壤之别
$ printf 'aaaaaaaaaaaaaaaaaaaaaaaaaaaab\n' > /tmp/redos.txt   # 29 个 a + 结尾 b
$ grep -E '^(a+)+$' /tmp/redos.txt      # BRE/ERE 引擎：线性时间，瞬间返回无匹配
$ echo $?
1
$ grep -P '^(a+)+$' /tmp/redos.txt      # PCRE2 引擎：嵌套量词回溯爆炸，被上限拦下
grep: /tmp/redos.txt: 超过 PCRE 的回溯限制
$ echo $?
2
```

```text
结论：grep 的 ReDoS 风险只存在于 -P 模式（PCRE2 回溯）。默认 grep / grep -E 用线性时间引擎，写 (a+)+$ 这类病态模式也不会挂死；但 -P 时要避免嵌套量词，或信任 PCRE2 的回溯上限兜底（默认报错退出而不是 CPU 打满）。
```

## 故障排查

```text
「grep 搜不到」排查顺序：
1. 大小写 —— 用 -i 再试，或确认大小写
2. 正则转义 —— . * [ 等元字符被当特殊字符，改用 grep -F 固定字符串
3. 方言 —— + ? | ( ) 在 BRE 里是字面量，换 grep -E 再试
4. 文件编码/二进制 —— 报 binary file matches 用 grep -a

「交互式有结果、脚本里没有」：
- 大概率是 shell 别名（--color 不影响结果，但 --exclude 或自定义 alias 可能），
  脚本里用 command grep 或绝对路径 /usr/bin/grep 规避

「匹配到了但不是我想要的子串」：
- 比如 grep 'cat' 匹配到 catalog，加 -w 整词匹配，或写 \<cat\>

「grep: 参数列表过长（Argument list too long）」：
- 用 grep '关键词' $(find ...) 或 grep '关键词' /大目录/* 时，shell 展开的参数总长超过 execve 上限
- 本机实测 getconf ARG_MAX = 2097152（约 2MB），几十万个文件名就够触发
- 解法：find ... -exec grep ... {} + 或 find ... -print0 | xargs -0 grep ...，让 xargs 分批传参

「grep: xxx: 匹配到二进制文件（Binary file matches）」：
- 文件里混了 NUL 或无效 UTF-8，grep 判定为二进制后不输出内容（但退出码是 0）
- 解法：要内容用 -a，要跳过用 -I，要按文件名列出用 --binary-files=binary

「中文乱码 / 匹配不到中文」：
- 文件是 GBK 编码而终端是 UTF-8，grep 按字节匹配自然对不上；或 locale 不是 UTF-8 时 . 按字节匹配把多字节汉字截断
- 解法：iconv -f GBK -t UTF-8 转码后再 grep；确认 LC_ALL/LANG 是 UTF-8（locale -a 里有没有 zh_CN.utf8）

「locale 警告（grep: warning: environment variable LC_ALL ...）」：
- 设了系统里没生成的 locale（如 en_US.UTF-8 未生成时 LANG=en_US.UTF-8），glibc 落到 C 语义并告警
- 解法：locale -a 确认可用 locale，改设 C.UTF-8 或已生成的 locale
```

## 常见问题

```text
Q1: grep -c 数的是什么？
A: 匹配的「行数」，不是出现次数。一行里出现多个关键词也只算 1。要数次数用 grep -o 关键词 | wc -l。

Q2: grep 搜二进制文件只报 binary file matches？
A: grep 检测到二进制字节后默认只提示不输出。加 -a 把文件当文本强制输出。

Q3: 递归搜索太慢怎么办？
A: 加 --exclude-dir 排除大目录、--include 限定文件类型，别在 / 根目录裸跑 grep -r。

Q4: grep 的退出码为什么不是 0/1 那么简单？
A: 0 有匹配、1 无匹配、2 出错。脚本里判断要区分「没找到」和「出错」。

Q5: grep 'cat' 匹配到了 catalog，怎么只匹配 cat？
A: 加 -w 整词匹配（等价 grep '\<cat\>'）。-w 给整个模式加词边界，避免子串误命中。

Q6: grep -r 和 -R 有什么区别？
A: -r 不跟随符号链接，-R（等价 --dereference-recursive）会跟随，遇到循环链接可能死循环。默认用 -r 更安全。

Q7: 递归搜索怎么跳过二进制文件？
A: 加 -I（等价 --binary-files=without-match），二进制文件直接跳过，而不是报 binary file matches 刷屏。

Q8: grep -o 有什么用？
A: 只输出匹配到的片段而不是整行。统计出现次数（grep -o 词 | wc -l）、从日志提取 IP/状态码/时间戳（grep -oE '正则'）都靠它。

Q9: grep -E 和 egrep 是一回事吗？
A: 是。egrep 是历史命令，等价于 grep -E；同样 fgrep 等价于 grep -F。新脚本直接用 grep -E / grep -F，别依赖 egrep/fgrep 这些遗留别名。

Q10: 怎么在 grep 里搜「以 - 开头的模式」？
A: 用 grep -e '-foo' 或 grep -- '-foo'，否则 -foo 被当选项解析（实测会报「grep: oo: 没有那个文件或目录」）。

Q11: grep 的结果为什么有时带颜色有时不带？
A: 多数发行版默认 alias grep='grep --color=auto'，输出到 tty 时上色，管道/重定向时 auto 自动关色。脚本里要稳定就显式 --color=never，要强制带色（如给 tail -f 用）就 --color=always。

Q12: 怎么一次搜多个关键词？
A: grep -E 'a|b|c'、grep -e a -e b -e c、或把关键词逐行写进文件后 grep -f patterns.txt。模式多且要长期维护时用 -f。

Q13: grep 搜中文为什么有时搜不到？
A: 多半是文件编码不是 UTF-8（GBK 等），或 locale 不是 UTF-8 导致按字节匹配。iconv 转码、确认 locale -a 里有 UTF-8 locale 再搜。
```

## 面试题

```text
1. grep 和 sed、awk 的分工是什么？
   答：grep 只过滤（按行挑出匹配行），sed 做流式替换/删除，awk 做字段级处理和统计。三者常串在管道里配合。

2. grep -E 和 grep 默认的 BRE 有什么区别？
   答：BRE 下 + ? | ( ) { } 是字面量要转义，-E 切 ERE 后这些直接是元字符。写正则时方言不同结果不同。

3. 怎么统计一个日志文件里 ERROR 出现的总次数（不是行数）？
   答：grep -o 'ERROR' file | wc -l。因为 -c 只数行，-o 把每个匹配单独输出一行，再用 wc -l 数个数。

4. grep -r 递归搜索有什么坑？
   答：会搜进大日志、二进制、node_modules 等无用目录导致极慢，应配合 --exclude-dir / --include 过滤。

5. grep -F 和 grep -E 什么时候用哪个？
   答：搜固定字符串（含 . * 等字面字符）用 -F，不解释元字符、速度最快；需要正则表达式才用 -E。用户输入当模式时应优先 -F。

6. 怎么高效地在大型代码库递归搜索？
   答：grep -rn --include='*.js' --exclude-dir=node_modules -I '关键词' 目录——限定文件类型、排除大目录、跳过二进制，再带 -n 定位行号。

7. grep 的退出码在 shell 脚本里怎么用？
   答：0 有匹配 / 1 无匹配 / 2 出错。用 if grep -q 'pattern' file; then ... 做存在性判断，并区分 1（没找到）和 2（出错）。

8. grep -o 和 grep -c 的区别？
   答：-c 数「匹配的行数」，-o 只输出匹配片段（每匹配一次输出一行）。统计关键词总出现次数要用 grep -o 词 | wc -l。

9. 为什么 grep 搜二进制文件只显示「binary file matches」？
   答：grep 检测到 NUL 字节或无效 UTF-8 等二进制特征后，默认只提示不输出（防乱码刷屏），退出码仍为 0。加 -a 强制当文本、-I 跳过、--binary-files=binary 只列文件名。

10. grep -P 和 grep -E 有什么本质区别？
    答：-E 是 ERE（POSIX 扩展正则），grep 用线性时间 DFA 引擎、无回溯爆炸风险；-P 是 PCRE2，支持 \d \w \s、非贪婪、前瞻后瞻，但走回溯引擎，嵌套量词模式可能触发回溯上限报错。跨平台时 -P 依赖 libpcre2，非 GNU 平台常没有。

11. grep 里怎么匹配「以 - 开头的模式」？
    答：grep -e '-foo' 或 grep -- '-foo'。裸写 grep '-foo' 会把 -foo 当选项解析（实测报「grep: oo: 没有那个文件或目录」）。

12. 递归搜索时 -r 和 -R 有什么区别？
    答：-r 不跟随符号链接，-R（--dereference-recursive）会跟随，遇到循环链接可能死循环。默认用 -r。

13. grep 的 --line-buffered 是干什么的？
    答：让输出按行缓冲（命中即 flush）。配合 tail -f 实时过滤日志时，不加它结果会积在 4KB/8KB 块缓冲里迟迟不显示。

14. grep 的大小写匹配受什么影响？
    答：受 locale 影响。-i 在 UTF-8 locale 下做 Unicode 大小写折叠（Ä 匹配 ä），在 LC_ALL=C 下按字节比较（Ä 不匹配 ä）。脚本要稳定结果显式 LC_ALL=C，要正确匹配多语言文本保持 UTF-8 locale。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 默认用 grep -E，元字符不用转义、少踩坑
2. 排查日志先 grep -c 数规模，再看 -C 上下文定位
3. 找配置/引用用 grep -r 递归，配合 -l 只列文件名
4. 多关键词用 grep -f 模式文件，维护方便
5. 大文件/二进制文件 grep 加 -a 或 --binary-files=text，避免「binary file matches」吞结果
6. 搜词而非搜子串时加 -w，避免 grep 'cat' 误命中 catalog
7. 递归搜索必加 --include / --exclude-dir / -I，别裸跑 grep -r
8. 模式或文件名以 - 开头时用 -- 或 -e 兜底，避免被当选项解析
9. 要稳定跨机器行为就显式 LC_ALL=C（同时清楚它对 -i 大小写折叠和 . 匹配的副作用）

### 踩坑记录

```text
坑 1：grep -c 数的是行数不是次数
结论：一行里出现多个关键词，-c 只算 1。
原因：grep 按行匹配，一行命中即计 1。
解法：要数出现次数用 grep -o 关键词 | wc -l。

坑 2：搜二进制文件报 binary file matches 看不到内容
结论：grep 日志或混合文件时只报 binary file matches，不输出行。
原因：grep 检测到二进制字节，默认只提示不输出。
解法：加 -a（把文件当文本）或 --text 强制输出。

坑 3：grep 模式里忘了转义 .
结论：grep '1.2.3' 能匹配 1x2y3 这种本不想匹配的行。
原因：. 是元字符，匹配任意字符。
解法：匹配字面点号要 grep '1\.2\.3' 或用 grep -F 固定字符串。

坑 4：grep -r 搜到大目录极慢
结论：在 / 或大仓库 grep -r 半天出不来。
原因：递归遍历所有文件，包括大日志、二进制、node_modules。
解法：加 --exclude/--exclude-dir 过滤，或用 grep -r --include='*.conf' 限定类型。

坑 5：管道里 grep 配合 set -o pipefail 时退出码误导
结论：grep 无匹配返回 1，脚本里 if grep ... 判断反了。
原因：grep 找到匹配返回 0、找不到返回 1，和其它命令语义不同。
解法：明确用 grep -q 做判断，或加 || true 避免脚本中断。

坑 6：搜子串时没加 -w 误命中
结论：grep 'cat' 把 catalog、concatenate 这类行也匹配进来。
原因：默认是「包含子串」匹配，不是整词匹配。
解法：加 -w 或写 \<cat\>，要求词边界。

坑 7：递归搜索跟随符号链接导致死循环或重复结果
结论：用 -R 或 --dereference-recursive 在含循环链接的目录里跑不出结果。
原因：-R 会跟随符号链接，遇到指向父目录的链接就循环遍历。
解法：默认用 -r（不跟链接），确需跟链接时加 --exclude-dir 排除链接目录。

坑 8：模式以 - 开头被当选项
结论：grep '-foo' 文件 报「grep: oo: 没有那个文件或目录」。
原因：-foo 被解析成 -f 选项 + 参数 oo。
解法：grep -e '-foo' 或 grep -- '-foo'。

坑 9：LC_ALL=C 下 -i 匹配不到 Ä 这类非 ASCII 大写
结论：UTF-8 下 -i 能匹配 Äpfel，设了 LC_ALL=C 后只匹配小写 äpfel。
原因：C locale 按字节比较，不做 Unicode 大小写折叠。
解法：需要多语言大小写折叠时保持 UTF-8 locale；纯 ASCII 提速才用 LC_ALL=C。

坑 10：. 在 C locale 下按字节匹配把汉字拆乱
结论：LC_ALL=C 下 grep -o '.' 对「张三」输出 6 个字节乱码。
原因：C locale 下一个 . 匹配一个字节，UTF-8 汉字是 3 字节。
解法：匹配中文保持 UTF-8 locale，或用 grep -P '\p{Han}' 显式匹配汉字（需 -P）。

坑 11：grep -P 嵌套量词触发回溯上限
结论：grep -P '^(a+)+$' 对「29 个 a + b」报「超过 PCRE 的回溯限制」。
原因：PCRE2 回溯引擎，嵌套量词是病态模式，输入不匹配时回溯指数爆炸。
解法：-P 时避免 (a+)+ 这类嵌套量词，改成可线性匹配的等价写法；或信任回溯上限兜底。

坑 12：参数列表过长（Argument list too long）
结论：grep 关键词 $(find /大目录) 报「参数列表过长」。
原因：shell 展开的参数总长超过 execve 上限（本机 ARG_MAX=2097152）。
解法：find ... -exec grep ... {} + 或 find ... -print0 | xargs -0 grep ...。

坑 13：tail -f 管道里 grep 结果迟迟不刷出
结论：tail -f log | grep 'ERROR' 长时间看不到新错误行。
原因：grep 输出默认块缓冲，日志量小时凑不满缓冲不 flush。
解法：加 --line-buffered，命中即刷出。
```

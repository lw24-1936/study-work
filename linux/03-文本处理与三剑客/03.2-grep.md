## 概述

grep 是按行搜索文本的工具，从文件或管道里挑出匹配模式的行。它和 sed、awk 并称「文本三剑客」，但 grep 只做一件事——过滤，不修改。日常用法几乎都长这样：`grep 关键词 文件` 找匹配行，`grep -E 正则` 用扩展正则，`grep -v` 反向过滤，`grep -r` 递归搜目录。排查日志、找配置、过滤输出，grep 都是第一个上场的工具。

```text
grep 核心能力：
1. 按行匹配 —— 匹配到模式的行整行输出，不修改原文件
2. 正则引擎 —— 默认 BRE，-E 切 ERE，-P 切 PCRE
3. 组合过滤 —— -v 取反、-i 忽略大小写、-c 计数、-n 行号、-o 只出匹配部分
```

## 核心概念

grep 的核心概念是「正则方言 + 一组过滤选项」。

### 基本与扩展正则

grep 默认用 BRE，`+ ? | ( ) { }` 要转义；加 `-E` 切到 ERE 后这些直接写。两者的差别在写正则时最容易踩坑——同一个模式，`grep 'a\+'`（BRE）和 `grep -E 'a+'`（ERE）才等价。`grep -P` 进 PCRE，支持 `\d \w \s` 简写。实战里 `grep -E` 最常用，因为不用背转义规则。

```shell
# BRE：量词要转义
grep '10\.0\.0\.[0-9]' /tmp/demo.txt | head -1
# ERE：量词直接写
grep -E '10\.0\.0\.[0-9]{1}' /tmp/demo.txt | head -1
```

```text
# 实测（两条命令都匹配到同一行，但写法不同）
2026-08-18 10:00:01 INFO  user=alice action=login  ip=10.0.0.1
```

### 常用选项

grep 的选项是它的灵魂，几个高频选项背下来能覆盖 90% 的场景：`-i` 忽略大小写、`-v` 反向匹配、`-c` 计数、`-n` 显示行号、`-o` 只输出匹配的部分、`-l` 只列文件名。其中 `-c` 和 `-i` 配合排查日志特别有用——「这个错误出现多少次」「大小写混着写都算」。

```shell
grep -c 'error' /tmp/demo.txt      # 小写 error：0 次
grep -ci 'error' /tmp/demo.txt     # 忽略大小写：3 次（ERROR）
grep -v 'ERROR' /tmp/demo.txt      # 反向：排除 ERROR 行
```

```text
# 实测
$ grep -c 'error' /tmp/demo.txt
0
$ grep -ci 'error' /tmp/demo.txt
3
$ grep -v 'ERROR' /tmp/demo.txt
2026-08-18 10:00:01 INFO  user=alice action=login  ip=10.0.0.1
2026-08-18 10:01:00 WARN  user=carol action=login  ip=10.0.0.3
2026-08-18 10:02:00 INFO  user=dave  action=logout ip=10.0.0.4
# 注意 -c 数的是「行数」不是「出现次数」，一行多个匹配也只算 1
```

### 递归搜索

`grep -r` 递归搜索整个目录，`-l` 只列命中的文件名、`-H` 显示文件名。在一堆配置文件里找「哪个文件配置了 server_name」、在代码库找「谁引用了这个函数」，都是 `grep -r` 的典型场景。生产服务器改配置前，先 `grep -r` 摸清影响面，避免漏改。

```shell
# 在 nginx 配置目录递归找 server_name
grep -rl 'server_name' /etc/nginx/ 2>/dev/null
```

```text
# 实测（本机 nginx 配置里包含 server_name 的文件）
/etc/nginx/sites-available/default
/etc/nginx/uwsgi_params
/etc/nginx/scgi_params
/etc/nginx/nginx.conf
/etc/nginx/fastcgi_params
/etc/nginx/conf.d/deepseek-harness.conf
/etc/nginx/conf.d/new-admin.conf
```

### 上下文

看日志时往往不只想要匹配行，还想看它前后几行发生了什么。`-A n` 显示匹配行后 n 行（After）、`-B n` 显示前 n 行（Before）、`-C n` 前后各 n 行（Context）。排查报错时 `grep -C 3 ERROR` 一下就能看到报错前后的调用链，比只看报错行高效得多。

```shell
# WARN 前后各 1 行
grep -C1 'WARN' /tmp/demo.txt
```

```text
# 实测
2026-08-18 10:00:05 ERROR user=bob   action=query  ip=10.0.0.2
2026-08-18 10:01:00 WARN  user=carol action=login  ip=10.0.0.3
2026-08-18 10:01:10 ERROR user=alice action=upload ip=10.0.0.1
```

### 多模式

要一次匹配多个关键词，用 `-e 模式1 -e 模式2`（多个 -e）或 `-E '模式1|模式2'`（ERE 交替），或者 `-f 文件` 从文件读取模式列表。`-f` 适合「关键词很多、维护在一个文件里」的场景，比如监控脚本里维护一份「需要告警的错误关键词」清单。

```shell
# 三种多模式写法
grep -E 'ERROR|WARN' /tmp/demo.txt
grep -e ERROR -e WARN /tmp/demo.txt
printf 'ERROR\nWARN\n' > /tmp/patterns.txt
grep -f /tmp/patterns.txt /tmp/demo.txt
```

```text
# 实测（grep -f 模式文件，匹配 ERROR 或 WARN 的行）
2026-08-18 10:00:05 ERROR user=bob   action=query  ip=10.0.0.2
2026-08-18 10:01:00 WARN  user=carol action=login  ip=10.0.0.3
2026-08-18 10:01:10 ERROR user=alice action=upload ip=10.0.0.1
2026-08-18 10:02:30 ERROR user=eve   action=login  ip=10.0.0.5
```

## 工作原理

grep 的处理模型是「逐行读入 → 正则匹配 → 命中输出」，本身不修改数据：

1. **逐行处理**：grep 按行读入（以 `\n` 为记录分隔符），对每一行单独跑正则匹配，命中就把整行输出。所以 grep 是「行级」工具，跨行的模式默认匹配不到。
2. **退出码语义**：找到匹配返回 0、没找到返回 1、出错（文件不存在等）返回 2。这是脚本里 `if grep -q ...` 判断的依据，和其它命令「0=成功」的语义略有不同。
3. **二进制检测**：grep 读入时若发现 NUL 字节或非文本内容，默认只打印 `binary file matches` 而不输出内容（防乱码刷屏），需要强制当文本处理加 `-a`。

```text
grep 执行流程：打开输入 → 逐行读入 → 正则匹配该行 → 命中则输出（-o 只输出匹配片段）→ 读完退出
退出码：0 有匹配 / 1 无匹配 / 2 出错
```

## 常用命令与配置

grep 的高频选项速查，覆盖排查日志 90% 的用法：

```shell
grep -n   'ERROR' app.log     # 带行号找错误
grep -ci  'error' app.log     # 忽略大小写计数
grep -v   'DEBUG' app.log     # 排除 DEBUG 噪音
grep -oE  '[0-9]+\.[0-9]+\.[0-9]+\.[0-9]+' access.log   # 只提取 IP
grep -C3  'ERROR' app.log     # 错误上下文各 3 行
grep -rl  'server_name' /etc/nginx/    # 递归找含关键词的文件名
grep -f   patterns.txt log    # 从文件读多个模式
grep -a   'keyword' mixed.bin # 把二进制当文本搜
```

```text
选项分工：
-i 忽略大小写 / -v 反向 / -c 计数 / -n 行号 / -o 只出匹配片段
-r 递归 / -l 只列文件名 / -A -B -C 上下文 / -e -f 多模式 / -a 二进制当文本
```

## 配置文件解析

grep 本身不读配置文件，但它的行为受环境变量和 shell 别名影响：

```text
1. GREP_COLORS —— 控制匹配高亮的颜色（mt= 匹配文本颜色），默认在多数发行版开启
2. GREP_OPTIONS —— 旧版用于设默认选项，新版 grep 已废弃，别依赖
3. shell 别名 —— 很多发行版默认 alias grep='grep --color=auto'，
   这也是「交互式能高亮、脚本里没有」差异的来源
4. --exclude / --exclude-dir —— 递归搜索的过滤规则，等价于「配置哪些文件不搜」
```

# 只看出错行、排除已知的无害告警，并带上行号

## 性能与调优

```text
1. 固定字符串搜索用 grep -F，跳过正则引擎，速度更快
2. 递归搜索加 --exclude-dir=node_modules --exclude='*.log'，别搜进大目录
3. 设 LC_ALL=C 可以加快多字节 locale 下的匹配速度
4. 大文件先 grep 缩小范围，再交给 awk/sed 精细处理，别让 awk 直接吃全量
5. 只关心「有没有」用 grep -q，命中即返回，不扫完整个文件
```

## 安全与权限

```text
1. 别用 grep 把含密码/私钥的文件内容输出到日志或终端（如 grep -r 'password' /etc/ 可能泄露）
2. 递归搜索系统目录（/etc /home）时注意权限，只读操作别误带写
3. grep 匹配结果里若含敏感字段（token/密钥），进一步处理时先脱敏
4. 排查日志时避免把 access.log 里的用户 token 整行外发到第三方
```

## 故障排查

```text
「grep 搜不到」排查顺序：
1. 大小写 —— 用 -i 再试，或确认大小写
2. 正则转义 —— . * [ 等元字符被当特殊字符，改用 grep -F 固定字符串
3. 方言 —— + ? | ( ) 在 BRE 里是字面量，换 grep -E 再试
4. 文件编码/二进制 —— 报 binary file matches 用 grep -a

「交互式有结果、脚本里没有」：
- 大概率是 shell 别名（--color 不影响结果，但 --exclude 或自定义 alias 可能），
  脚本里用 command grep 或绝对路径 /usr/bin/grep 规避
```

## 常见问题

```text
Q1: grep -c 数的是什么？
A: 匹配的「行数」，不是出现次数。一行里出现多个关键词也只算 1。要数次数用 grep -o 关键词 | wc -l。

Q2: grep 搜二进制文件只报 binary file matches？
A: grep 检测到二进制字节后默认只提示不输出。加 -a 把文件当文本强制输出。

Q3: 递归搜索太慢怎么办？
A: 加 --exclude-dir 排除大目录、--include 限定文件类型，别在 / 根目录裸跑 grep -r。

Q4: grep 的退出码为什么不是 0/1 那么简单？
A: 0 有匹配、1 无匹配、2 出错。脚本里判断要区分「没找到」和「出错」。
```

## 面试题

```text
1. grep 和 sed、awk 的分工是什么？
   答：grep 只过滤（按行挑出匹配行），sed 做流式替换/删除，awk 做字段级处理和统计。三者常串在管道里配合。

2. grep -E 和 grep 默认的 BRE 有什么区别？
   答：BRE 下 + ? | ( ) { } 是字面量要转义，-E 切 ERE 后这些直接是元字符。写正则时方言不同结果不同。

3. 怎么统计一个日志文件里 ERROR 出现的总次数（不是行数）？
   答：grep -o 'ERROR' file | wc -l。因为 -c 只数行，-o 把每个匹配单独输出一行，再用 wc -l 数个数。

4. grep -r 递归搜索有什么坑？
   答：会搜进大日志、二进制、node_modules 等无用目录导致极慢，应配合 --exclude-dir / --include 过滤。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 默认用 grep -E，元字符不用转义、少踩坑
2. 排查日志先 grep -c 数规模，再看 -C 上下文定位
3. 找配置/引用用 grep -r 递归，配合 -l 只列文件名
4. 多关键词用 grep -f 模式文件，维护方便
5. 大文件/二进制文件 grep 加 -a 或 --binary-files=text，避免「binary file matches」吞结果

### 踩坑记录

```text
坑 1：grep -c 数的是行数不是次数
结论：一行里出现多个关键词，-c 只算 1。
原因：grep 按行匹配，一行命中即计 1。
解法：要数出现次数用 grep -o 关键词 | wc -l。

坑 2：搜二进制文件报 binary file matches 看不到内容
结论：grep 日志或混合文件时只报 binary file matches，不输出行。
原因：grep 检测到二进制字节，默认只提示不输出。
解法：加 -a（把文件当文本）或 --text 强制输出。

坑 3：grep 模式里忘了转义 .
结论：grep '1.2.3' 能匹配 1x2y3 这种本不想匹配的行。
原因：. 是元字符，匹配任意字符。
解法：匹配字面点号要 grep '1\.2\.3' 或用 grep -F 固定字符串。

坑 4：grep -r 搜到大目录极慢
结论：在 / 或大仓库 grep -r 半天出不来。
原因：递归遍历所有文件，包括大日志、二进制、node_modules。
解法：加 --exclude/--exclude-dir 过滤，或用 grep -r --include='*.conf' 限定类型。

坑 5：管道里 grep 配合 set -o pipefail 时退出码误导
结论：grep 无匹配返回 1，脚本里 if grep ... 判断反了。
原因：grep 找到匹配返回 0、找不到返回 1，和其它命令语义不同。
解法：明确用 grep -q 做判断，或加 || true 避免脚本中断。
```

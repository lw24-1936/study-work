## 概述

awk 是三剑客里唯一带「编程语言」属性的工具——它能按字段处理、做条件判断、循环、数组统计、数值计算。核心模型是「模式 + 动作」：对每一行，匹配到模式就执行动作。默认按空白切字段（$1 $2 ...），所以分析「按列」的数据（日志、CSV、命令输出）特别顺手。日志统计分析、报表计算、字段提取，awk 是主力。

```text
awk 核心模型：
1. 结构 —— awk '模式 {动作}' 文件，逐行读入、匹配模式、执行动作
2. 字段 —— 默认按空白切分，$1 $2 ... 是字段，$0 是整行，NF 是字段数
3. 能力 —— 内置变量 + 条件 + 循环 + 数组 + 函数，本质是个小型解释器
```

## 字段与记录

awk 把每行叫一条「记录」（record），按分隔符切成「字段」（field）。默认分隔符是空白（空格/制表符），`-F` 指定其它分隔符（CSV 用 `-F,`）。`$1 $2 ...` 引用字段，`$0` 是整行，`$NF` 是最后一个字段。分析日志时「IP 是 $1、状态码是 $9」这种对应关系一旦摸清，后面全是顺手的事。

```shell
# nginx 日志：$1 IP、$7 路径、$9 状态码、$10 字节数
awk '{print $1, $9, $10, $7}' /var/log/nginx/access.log | head -3
```

```text
# 实测（本机真实 nginx 日志）
100.115.7.80 200 2849 /
100.115.7.80 200 29709 /assets/vendor-CjyC-hUb.css
100.115.7.80 200 279 /manifest.webmanifest
# nginx 默认日志格式按空白切分后，$1=客户端IP、$7=请求路径、$9=状态码、$10=响应字节
```

## 内置变量

awk 内置变量省去大量手工计数。`NR` 是当前记录号（跨文件累计）、`FNR` 是当前文件内的记录号、`NF` 是当前行字段数、`FS` 是输入分隔符、`OFS` 是输出分隔符、`RS` 是记录分隔符。最常用的是 NR（行号）和 NF（字段数）——`awk 'NR>1'` 跳过表头、`awk '{print NF}'` 看每行几列。

```shell
# NR 行号 + NF 字段数 + 部分字段
awk '{print NR, NF, $1, $4}' /tmp/demo.txt
```

```text
# 实测
1 6 2026-08-18 user=alice
2 6 2026-08-18 user=bob
3 6 2026-08-18 user=carol
4 6 2026-08-18 user=alice
5 6 2026-08-18 user=dave
6 6 2026-08-18 user=eve
# 每行 6 个字段：$1=日期 $2=时间 $3=级别 $4=user $5=action $6=ip
```

## 模式与动作

awk 的「模式」可以是正则、条件表达式、或行号范围；「动作」是花括号里的语句。`awk '/ERROR/ {print}'` 匹配含 ERROR 的行、`awk '$3=="ERROR"'` 是条件、`awk 'NR==1,NR==3'` 是行号范围。模式省略时默认对所有行执行动作，动作省略时默认打印整行（等价 grep）。

```shell
# 正则模式：匹配含 ERROR 的行（等价 grep ERROR）
awk '/ERROR/' /tmp/demo.txt | head -2
```

```text
# 实测
2026-08-18 10:00:05 ERROR user=bob   action=query  ip=10.0.0.2
2026-08-18 10:01:10 ERROR user=alice action=upload ip=10.0.0.1
```

## 条件

awk 的条件判断用 `if`，或直接写「条件 {动作}」这种模式形式。支持 `== != < > <= >= && || !` 全套逻辑运算。条件让 awk 能做「过滤 + 计算」二合一——比如「统计状态码大于等于 500 的行数」「找出工资超 15000 的人」。字段是数字就按数值比较，是字符串就按字典序比较。

```shell
# 只处理 ERROR 级别的行，打印时间+动作
awk '$3=="ERROR" {print $1, $2, $5}' /tmp/demo.txt
```

```text
# 实测
2026-08-18 10:00:05 action=query
2026-08-18 10:01:10 action=upload
2026-08-18 10:02:30 action=login
```

## 循环

awk 支持 for / while 循环，常用来遍历一行内的所有字段。典型场景：「一行里不确定哪个字段含目标，遍历找出来」——比如日志里 ip= 字段位置不固定时，用 `for (i=1; i<=NF; i++)` 逐个字段判断。这是 awk 比 grep/sed 强的地方：它能在字段级别做逻辑。

```shell
# 遍历所有字段，提取 ip= 开头的那个
awk '{for (i=1; i<=NF; i++) if ($i ~ /^ip=/) print $i}' /tmp/demo.txt
```

```text
# 实测
ip=10.0.0.1
ip=10.0.0.2
ip=10.0.0.3
ip=10.0.0.1
ip=10.0.0.4
ip=10.0.0.5
```

## 数组

awk 的数组是关联数组（下标可以是任意字符串），天然适合做「分组计数」。最经典的统计范式：`awk '{cnt[$k]++} END {for (x in cnt) print x, cnt[x]}'`——按某个字段分组、累加、最后输出。日志里统计「各状态码数量」「各 IP 访问次数」「各接口调用量」，全是这个套路。数组在 END 块里统一输出（因为要等所有行读完）。

```shell
# 按级别分组计数
awk '{cnt[$3]++} END {for (k in cnt) print k, cnt[k]}' /tmp/demo.txt
```

```text
# 实测
INFO 2
ERROR 3
WARN 1
```

## 字符串与数值函数

awk 内置函数分字符串和数值两类。字符串：`length()` 长度、`substr(s,m,n)` 截取、`index(s,t)` 查找、`split(s,arr,sep)` 拆分、`tolower()/toupper()` 大小写。数值：`int()` 取整、`sqrt()` 平方根、`rand()` 随机。正则相关 `match()`、`sub()/gsub()` 做替换。数值运算 awk 直接支持 `+ - * / %`，做 CSV 汇总、求平均、求和都很直接。

```shell
# 数值运算：过滤工资>=15000 的，求全体平均工资
awk -F, '$4>=15000 {print $2, $4}' /tmp/users.csv
awk -F, 'NR>1 {sum+=$4} END {print "平均工资:", sum/(NR-1)}' /tmp/users.csv
```

```text
# 实测
name salary
alice 15000
carol 18000
eve 16000
平均工资: 14200
# NR>1 跳过表头（第一行是 name,salary）；sum/(NR-1) 除以有效数据行数
```

## BEGIN 与 END

BEGIN 块在读取任何输入之前执行（初始化、打印表头），END 块在所有输入处理完后执行（汇总、打印结果）。「BEGIN 设分隔符 + 主体逐行处理 + END 汇总」是 awk 脚本的标准三段式。做报表时 BEGIN 打印列名、END 打印合计行，结构清晰。

```shell
# 三段式：BEGIN 表头 → 主体统计 → END 输出
awk 'BEGIN {print "级别统计:"} {cnt[$3]++} END {for (k in cnt) print k, cnt[k]}' /tmp/demo.txt
```

```text
# 实测
级别统计:
INFO 2
ERROR 3
WARN 1
```

## 应用场景实战

### 场景一：统计 nginx 日志的状态码分布和请求路径 TOP 榜

```shell
# 状态码分布
awk '{cnt[$9]++} END {for (k in cnt) print k, cnt[k]}' /var/log/nginx/access.log | sort -k2 -rn
# 请求路径 TOP5
awk '{print $7}' /var/log/nginx/access.log | sort | uniq -c | sort -rn | head -5
```

```text
# 实测（本机真实日志，一条就看出问题在哪）
$ awk '{cnt[$9]++} END {for (k in cnt) print k, cnt[k]}' /var/log/nginx/access.log | sort -k2 -rn
401 527
200 279
101 18
$ awk '{print $7}' /var/log/nginx/access.log | sort | uniq -c | sort -rn | head -5
    527 /api/pair/heartbeat
     81 /api/pet/state
     18 /aionui-panel/list
     10 /api/subagent.list
     10 /api/dynamicCordisRunner/inventory
# 真实发现：/api/pair/heartbeat 被请求 527 次且全返回 401（未授权）——心跳接口鉴权失败，
# 客户端在反复重试。这就是企业里用 awk 从日志里「看出问题」的标准动作。
```

### 场景二：CSV 数据汇总（分组求和、求平均）

```shell
# 按部门统计人数
awk -F, 'NR>1 {cnt[$3]++} END {for (d in cnt) print d, cnt[d]}' /tmp/users.csv
```

```text
# 实测
dev 3
ops 1
sales 1
```

## 最佳实践与踩坑记录

### 最佳实践

1. 分析日志先摸清字段位置（$1 是什么、$9 是什么），再写统计
2. 分组计数用关联数组 + END 输出，这是 awk 最高频的范式
3. CSV 处理记得 -F, 和 NR>1 跳过表头
4. 复杂统计写成 .awk 脚本文件，别堆在命令行里
5. awk 做不了的（跨行、复杂逻辑）才考虑 Python，能 awk 就 awk

### 踩坑记录

```text
坑 1：字段编号搞错，统计结果全错
结论：本以为是 $4 是级别，结果统计出来牛头不对马嘴。
原因：多空格/分隔符没摸清，字段错位。
解法：先 awk '{print NR, NF, $1, $2, $3...}' 看清每列是什么，再写统计。

坑 2：CSV 里字段本身含分隔符导致错位
结论：-F, 切分含逗号的字段（如 "a,b"）被拆成两列。
原因：awk 不解析 CSV 的引号转义，只按字符切。
解法：简单 CSV 用 awk，复杂 CSV 用 csvkit 或 Python 的 csv 模块。

坑 3：数值字段当字符串比较，排序/判断出错
结论：awk 'NR>1 && $4>15000' 对 10000 和 20000 比较结果反了。
原因：字段默认是字符串，字符串比较按字典序 "10000" > "15000" 为假但 "20000" > "15000" 为真，边界值会错。
解法：显式数值化 $4+0 > 15000，或确保字段无前导字符。

坑 4：END 块里数组遍历顺序不确定
结论：for (k in arr) 输出的顺序每次可能不同。
原因：awk 关联数组不保证遍历顺序，和插入顺序无关。
解法：需要排序输出时，把结果 pipe 给 sort，或 gawk 用 PROCINFO["sorted_in"]。

坑 5：awk 里单引号转义地狱
结论：awk '{print "'"'"'"}' 这类嵌套引号写错。
原因：shell 单引号内不能直接放单引号。
解法：awk 脚本存成文件 awk -f script.awk，或改用双引号包裹并用反斜杠转义。
```

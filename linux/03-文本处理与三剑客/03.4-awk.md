## 概述

awk 是三剑客里唯一带「编程语言」属性的工具——它能按字段处理、做条件判断、循环、数组统计、数值计算。核心模型是「模式 + 动作」：对每一行，匹配到模式就执行动作。默认按空白切字段（$1 $2 ...），所以分析「按列」的数据（日志、CSV、命令输出）特别顺手。日志统计分析、报表计算、字段提取，awk 是主力。

```text
awk 核心模型：
1. 结构 —— awk '模式 {动作}' 文件，逐行读入、匹配模式、执行动作
2. 字段 —— 默认按空白切分，$1 $2 ... 是字段，$0 是整行，NF 是字段数
3. 能力 —— 内置变量 + 条件 + 循环 + 数组 + 函数，本质是个小型解释器
```

### 一个必须先说清的前提：Ubuntu 的 awk 是 mawk，不是 gawk

「awk」首先是**一份语言规范**（POSIX 定义了 awk 的语法与语义），不是某一个具体的程序。同一个叫 `awk` 的命令名，在不同发行版背后可能是完全不同的实现，扩展能力差别很大：

| 运行环境 | `/usr/bin/awk` 实际是什么 | 备注 |
|---|---|---|
| Debian / Ubuntu | **mawk**（`mawk` 包，默认装） | gawk 不在默认安装里，要手动 `apt install gawk` |
| Red Hat / CentOS / RHEL / Fedora | **gawk**（GNU awk，默认预装） | `gensub/asort/IGNORECASE/FPAT` 等扩展开箱可用 |
| Alpine / 容器最小镜像 | **busybox awk** | 功能最弱，很多 POSIX 细节都缺 |
| macOS / 部分 BSD | **BWK awk**（one true awk） | 无 `gensub/asort`，无 `--version` |

```text
# 实测（本机 Ubuntu 24.04.4 LTS，用户 lw-Vostro-7580）
$ awk --version
mawk 1.3.4 20240123
Copyright 2008-2023,2024, Thomas E. Dickey
Copyright 1991-1996,2014, Michael D. Brennan

random-funcs:       arc4random_stir/arc4random
regex-funcs:        internal

compiled limits:
sprintf buffer      8192
maximum-integer     9223372036854775808

$ command -v gawk          # gawk 根本没装
（无输出）

$ dpkg -l | grep -E '^ii +(gawk|mawk) '
ii  mawk   1.3.4.20240123-1build1   amd64   Pattern scanning and text processing language
```

记住这条结论，本篇后面所有示例都建立在它之上：

1. **本机默认 `awk` 是 mawk 1.3.4**，POSIX 部分功能完整，但 **gawk 的专有扩展一个都没有**。
2. 网上绝大多数 awk 教程默认读者用的是 gawk，照抄会直接报 `function xxx never defined`。
3. 本文示例**默认只用 mawk 能吃下的语法**；凡涉及 gawk 专有特性，一律显式标注「需要 gawk」，并同时给出 mawk 下的等价替代写法。
4. 红帽系（RHEL/CentOS）默认 `awk` 就是 gawk —— 同一个脚本「Ubuntu 上报错、CentOS 上正常」，根源通常就在这里。反过来，如果你只为 gawk 写脚本并把机器换成 Ubuntu，会全线崩。

一段可以在任何机器上先跑的两行探针（本机实测输出如下）：

```shell
# 探针 1：看版本横幅（gawk 打印 "GNU Awk 5.x"，mawk 打印 "mawk 1.3.4"）
awk --version 2>/dev/null | head -1

# 探针 2：不看版本，直接探测 gawk 专有变量 PROCINFO 是否非空
awk 'BEGIN{print (PROCINFO["version"] != "" ? "gawk" : "非 gawk（mawk/busybox/BSD）")}'
```

```text
# 实测
$ awk --version 2>/dev/null | head -1
mawk 1.3.4 20240123
$ awk 'BEGIN{print (PROCINFO["version"] != "" ? "gawk" : "非 gawk（mawk/busybox/BSD）")}'
非 gawk（mawk/busybox/BSD）
# 注意：mawk 读未定义变量 PROCINFO["version"] 不报错、只返回空串，所以这个探针是「静默可判」的
```

```text
# 在 RHEL / CentOS / Fedora 上跑同样的探针（对照，非本机实测，写脚本时以目标机实测为准）
$ awk --version | head -1
GNU Awk 5.1.0, API: 3.0 (GNU MPFR 4.1.0, GNU MP 6.2.0)
$ awk 'BEGIN{print (PROCINFO["version"] != "" ? "gawk" : "非 gawk")}'
gawk
```

## 核心概念

awk 的核心概念是「字段模型 + 编程语言要素」两大部分。

### 字段与记录

awk 把每行叫一条「记录」（record），按分隔符切成「字段」（field）。默认分隔符是空白（空格/制表符），`-F` 指定其它分隔符（CSV 用 `-F,`）。`$1 $2 ...` 引用字段，`$0` 是整行，`$NF` 是最后一个字段。分析日志时「IP 是 $1、状态码是 $9」这种对应关系一旦摸清，后面全是顺手的事。

```shell
# nginx 日志：$1 IP、$7 路径、$9 状态码、$10 字节数
awk '{print $1, $9, $10, $7}' /var/log/nginx/access.log | head -3
```

```text
# 实测（本机真实 nginx 日志）
100.115.7.80 200 2849 /
100.115.7.80 200 29709 /assets/vendor-CjyC-hUb.css
100.115.7.80 200 279 /manifest.webmanifest
# nginx 默认日志格式按空白切分后，$1=客户端IP、$7=请求路径、$9=状态码、$10=响应字节
```

`$NF` 是最后一个字段、`$(NF-1)` 是倒数第二个，这两个在「列数不固定」时最实用——不用数一共有几列，直接取尾部字段。`-F` 接的是正则，所以能写多字符分隔符：

```shell
# 取最后两个字段（$NF 最后一个、$(NF-1) 倒数第二个）
awk '{print $1, $(NF-1), $NF}' /tmp/demo.txt | head -2

# -F 多字符分隔符（正则）：逗号或分号都算分隔
echo "a,b;c" | awk -F'[,;]' '{print $2}'

# 输出用 OFS 控制字段间分隔符（默认空格）
awk 'BEGIN{OFS=" | "} {print $1, $2, $3}' /tmp/demo.txt | head -2
```

```text
要点：
1. 记录 = 一行，字段 = 按 FS 切出来的一段；默认 FS 是「连续空白」，多个空格/制表符当一个分隔
2. $0 是整行、$NF 是最后一个字段、$(NF-1) 是倒数第二个——列数不固定时优先用它们
3. -F 接正则：-F'[,;]' 表示逗号或分号都算分隔，-F'[ ,]' 表示空格或逗号
4. 边界：awk 不解析引号转义，CSV 字段里含逗号会被拆错，复杂 CSV 用 csvkit 或 Python csv
5. 易错点：FS 为单个空格（-F' ' 或默认）是「连续空白」特例；要按「字面单个空格」切须写 -F'[ ]'
```

### 内置变量

awk 内置变量省去大量手工计数。`NR` 是当前记录号（跨文件累计）、`FNR` 是当前文件内的记录号、`NF` 是当前行字段数、`FS` 是输入分隔符、`OFS` 是输出分隔符、`RS` 是记录分隔符。最常用的是 NR（行号）和 NF（字段数）——`awk 'NR>1'` 跳过表头、`awk '{print NF}'` 看每行几列。

```shell
# NR 行号 + NF 字段数 + 部分字段
awk '{print NR, NF, $1, $4}' /tmp/demo.txt
```

```text
# 实测
1 6 2026-08-18 user=alice
2 6 2026-08-18 user=bob
3 6 2026-08-18 user=carol
4 6 2026-08-18 user=alice
5 6 2026-08-18 user=dave
6 6 2026-08-18 user=eve
# 每行 6 个字段：$1=日期 $2=时间 $3=级别 $4=user $5=action $6=ip
```

FS/OFS/RS 三个变量控制「怎么切」和「怎么拼」；FNR 在处理多文件时区分「当前文件里的行号」：

```shell
# FS 输入按冒号切、OFS 输出用逗号拼回
awk 'BEGIN{FS=":"; OFS=","} {print $1, $3}' /etc/passwd | head -3

# RS 改成空串：按「段落」处理（空行分隔的块算一条记录）
awk 'BEGIN{RS=""} {print NR, NF}' /tmp/para.txt

# FNR vs NR：处理多个文件时 FNR 每个文件重新从 1 数
awk '{print FILENAME, FNR, NR}' /tmp/a.txt /tmp/b.txt
```

```text
要点：
1. NR 跨文件累计、FNR 每个文件重新计数；配合 FILENAME 能定位「第几个文件的第几行」
2. NF 是字段数，$NF 因此天然是最后一个字段；NR 常用于 NR>1 跳过表头
3. FS/OFS 成对：FS 管输入切分、OFS 管输出拼接；RS 改记录分隔符可跨行/按段落处理
4. 易错点：OFS 只在「逗号分隔多个输出项」时生效，print $1 $2 之间没有逗号则不分隔
5. 易错点：$0 整行不受 OFS 影响；对 $0 重新赋值后要 $1=$1 强制重算才会按 OFS 重排
```

### 模式与动作

awk 的「模式」可以是正则、条件表达式、或行号范围；「动作」是花括号里的语句。`awk '/ERROR/ {print}'` 匹配含 ERROR 的行、`awk '$3=="ERROR"'` 是条件、`awk 'NR==1,NR==3'` 是行号范围。模式省略时默认对所有行执行动作，动作省略时默认打印整行（等价 grep）。

```shell
# 正则模式：匹配含 ERROR 的行（等价 grep ERROR）
awk '/ERROR/' /tmp/demo.txt | head -2
```

```text
# 实测
2026-08-18 10:00:05 ERROR user=bob   action=query  ip=10.0.0.2
2026-08-18 10:01:10 ERROR user=alice action=upload ip=10.0.0.1
```

模式还可以是「正则匹配某个字段」（用 `~` / `!~`），或「行号范围」，甚至可以写多个「模式 {动作}」串成一个脚本：

```shell
# 字段级正则：第 5 个字段以 action=query 结尾的行
awk '$5 ~ /action=query$/' /tmp/demo.txt | head -2

# 取反：第 3 个字段不是 INFO 的行
awk '$3 !~ /INFO/' /tmp/demo.txt | head -2

# 行号范围：只打印第 2 到第 3 行
awk 'NR==2, NR==3' /tmp/demo.txt

# 多个模式串成脚本：先筛 ERROR，再筛含 alice 的
awk '/ERROR/ && /alice/' /tmp/demo.txt
```

```text
要点：
1. 模式类型：正则（/re/）、字段正则（$n ~ /re/）、条件（$3=="ERROR"）、行号范围（NR==a,NR==b）
2. 模式省略 = 所有行都执行动作；动作省略 = 默认 print $0（等价 grep）
3. 多个「模式 {动作}」按书写顺序对同一行依次求值，命中哪个执行哪个
4. 易错点：/ERROR/ 是「整行包含」，$3 ~ /ERROR/ 才是「第 3 字段包含」；要精确匹配用 $3=="ERROR"
5. 易错点：范围模式 NR==a,NR==b 是「开关式」——从 a 开始到 b 结束，会跨越连续区间
```

### 条件

awk 的条件判断用 `if`，或直接写「条件 {动作}」这种模式形式。支持 `== != < > <= >= && || !` 全套逻辑运算。条件让 awk 能做「过滤 + 计算」二合一——比如「统计状态码大于等于 500 的行数」「找出工资超 15000 的人」。字段是数字就按数值比较，是字符串就按字典序比较。

```shell
# 只处理 ERROR 级别的行，打印时间+动作
awk '$3=="ERROR" {print $1, $2, $5}' /tmp/demo.txt
```

```text
# 实测
2026-08-18 10:00:05 action=query
2026-08-18 10:01:10 action=upload
2026-08-18 10:02:30 action=login
```

`if/else` 语句和三目运算符写分支逻辑；`&&`/`||` 组合多个条件：

```shell
# if/else 分支：ERROR 标红心、其它标横线
awk '{if ($3=="ERROR") print "E", $0; else print "-", $0}' /tmp/demo.txt | head -3

# 三目运算符：一行内完成条件赋值
awk '{print ($3=="ERROR" ? "严重" : "正常"), $2}' /tmp/demo.txt | head -3

# 组合条件：INFO 级别且含 alice 的行
awk '$3=="INFO" && /alice/' /tmp/demo.txt
```

```text
要点：
1. 条件判断 = 关系运算（== != < > <= >=）+ 逻辑运算（&& || !）
2. 两种写法等价：awk '条件 {动作}' 和 awk '{if (条件) 动作}'
3. 三目 x ? y : z 适合一行内给变量赋值或输出分支结果
4. 易错点：字段默认是字符串，"10" > "9" 按字典序为假；数值比较要 $n+0 或 -v 传数字
5. 易错点：字符串比较用 ==，正则匹配用 ~；把 == 写成 = 是赋值、恒为真
```

### 循环

awk 支持 for / while 循环，常用来遍历一行内的所有字段。典型场景：「一行里不确定哪个字段含目标，遍历找出来」——比如日志里 ip= 字段位置不固定时，用 `for (i=1; i<=NF; i++)` 逐个字段判断。这是 awk 比 grep/sed 强的地方：它能在字段级别做逻辑。

```shell
# 遍历所有字段，提取 ip= 开头的那个
awk '{for (i=1; i<=NF; i++) if ($i ~ /^ip=/) print $i}' /tmp/demo.txt
```

```text
# 实测
ip=10.0.0.1
ip=10.0.0.2
ip=10.0.0.3
ip=10.0.0.1
ip=10.0.0.4
ip=10.0.0.5
```

`while` 适合「不知道次数、满足条件就继续」的场景，`break` 提前退出、`continue` 跳过本次、`next` 直接跳到下一条记录：

```shell
# while 循环：从第 2 个字段开始找第一个含 = 的字段
awk '{i=2; while (i<=NF && $i !~ /=/) i++; print $i}' /tmp/demo.txt | head -2

# next：跳过第一行（表头），后续行照常处理
awk 'NR==1 {next} {print NR, $1}' /tmp/demo.txt | head -2

# break：遍历字段，找到目标就停止（避免继续无谓比较）
awk '{for (i=1; i<=NF; i++) if ($i ~ /^ip=/) {print $i; break}}' /tmp/demo.txt | head -2
```

```text
要点：
1. for 用于「已知边界」的遍历（i=1; i<=NF; i++），while 用于「条件驱动」的循环
2. break 跳出当前循环、continue 跳过本次迭代、next 跳到下一条记录（不执行后续动作）
3. 遍历字段是 awk 区别于 grep/sed 的核心能力——字段位置不固定时逐个找
4. 易错点：for 循环里改 $i 不影响 $0，要写回整行需显式 $0=$0 重算
5. 易错点：next 会跳过当前行后续所有「模式 {动作}」，别放在统计逻辑之前误跳行
```

### 数组

awk 的数组是关联数组（下标可以是任意字符串），天然适合做「分组计数」。最经典的统计范式：`awk '{cnt[$k]++} END {for (x in cnt) print x, cnt[x]}'`——按某个字段分组、累加、最后输出。日志里统计「各状态码数量」「各 IP 访问次数」「各接口调用量」，全是这个套路。数组在 END 块里统一输出（因为要等所有行读完）。

```shell
# 按级别分组计数
awk '{cnt[$3]++} END {for (k in cnt) print k, cnt[k]}' /tmp/demo.txt
```

```text
# 实测
INFO 2
ERROR 3
WARN 1
```

数组还支持「成员判断」「删除元素」「求长度」，多维场景用下标拼接模拟：

```shell
# 统计每个 IP 每个级别的次数（二维分组，下标用逗号拼成键）
awk '{cnt[$6" "$3]++} END {for (k in cnt) print k, cnt[k]}' /tmp/demo.txt

# 判断键是否存在 + 数组长度
awk '{seen[$3]=1} END {print "级别数:", length(seen); if ("ERROR" in seen) print "有 ERROR"}' /tmp/demo.txt

# 删除元素：统计时排除掉某个键
awk '{cnt[$3]++} END {delete cnt["INFO"]; for (k in cnt) print k, cnt[k]}' /tmp/demo.txt
```

```text
要点：
1. 关联数组下标是字符串，cnt[$3]++ 天然做分组计数，无需预声明
2. 输出放 END：所有行读完后数组才完整，遍历用 for (k in arr)
3. `k in arr` 判断键是否存在、delete arr[k] 删元素、length(arr) 求元素个数
4. 多维：用下标拼接模拟（cnt[$a SUBSEP $b] 或 cnt[$a","$b]），awk 本身无真正二维数组
5. 易错点：for (k in arr) 遍历顺序不确定，要排序输出 pipe 给 sort；`PROCINFO["sorted_in"]` 是 gawk 专有，Ubuntu 默认的 mawk 下**静默失效**（不报错，就是没排序），跨发行版别依赖它（见「核心概念」的方言对照表）
```

### 字符串与数值函数

awk 内置函数分字符串和数值两类。字符串：`length()` 长度、`substr(s,m,n)` 截取、`index(s,t)` 查找、`split(s,arr,sep)` 拆分、`tolower()/toupper()` 大小写。数值：`int()` 取整、`sqrt()` 平方根、`rand()` 随机。正则相关 `match()`、`sub()/gsub()` 做替换。数值运算 awk 直接支持 `+ - * / %`，做 CSV 汇总、求平均、求和都很直接。

```shell
# 数值运算：过滤工资>=15000 的，求全体平均工资
awk -F, '$4>=15000 {print $2, $4}' /tmp/users.csv
awk -F, 'NR>1 {sum+=$4} END {print "平均工资:", sum/(NR-1)}' /tmp/users.csv
```

```text
# 实测
name salary
alice 15000
carol 18000
eve 16000
平均工资: 14200
# NR>1 跳过表头（第一行是 name,salary）；sum/(NR-1) 除以有效数据行数
```

常用函数的典型用法：

```shell
# 字符串：截取、长度、查找、拆分
echo "2026-08-18" | awk '{print substr($1,1,4), substr($1,6,2), length($1)}'
awk '{print index($4, "=")}' /tmp/demo.txt | head -1
awk '{n=split($0, a, " "); print "字段数:", n, "首字段:", a[1]}' /tmp/demo.txt | head -1

# 替换：sub 替换第一个、gsub 替换全部
awk '{gsub(/user=/, "", $4); print $4}' /tmp/demo.txt | head -2

# 大小写 + 格式化 + 取整
echo "Hello" | awk '{print tolower($1), toupper($1)}'
awk 'BEGIN{printf "%.2f\n", 10/3}'
awk 'BEGIN{print int(3.9), sqrt(16)}'
```

```text
要点：
1. 字符串：length/substr/index/split/tolower/toupper；正则替换 sub（首个）/gsub（全部）/match（定位）
2. 数值：int 截断取整（非四舍五入）、sqrt 开方、rand 随机（配 srand(种子) 才可复现）
3. split(s, arr, sep) 把字符串拆进数组，返回拆出的段数——和字段切分互补
4. sprintf/printf 格式化输出，做报表对齐列宽时用它
5. 易错点：int() 是截断不是四舍五入（int(3.9)=3）；rand() 默认每次种子相同，要 srand() 才随机
```

#### 补充：mawk 的字符串是「字节串」，不是「字符」

这是 mawk 和 gawk 的又一处分歧，而且**经常在中文/UTF-8 数据上悄悄出错**。mawk 是字节导向的实现，`length()` / `substr()` / `index()` / `split(s, a, "")` 全部按**字节**计算；gawk 在 UTF-8 locale 下会按**字符**算。本机实测（文件名 `/tmp/awkt/cn.txt`，内容就是 `张三` 加一个换行）：

```shell
# 文件内容：两个 UTF-8 汉字（张、三）+ 换行，共 2 字符 = 6 字节
printf '张三\n' > cn.txt

# length 到底数的是字节还是字符？
awk '{print length($0)}' cn.txt
LC_ALL=C awk '{print length($0)}' cn.txt
LC_ALL=C.UTF-8 awk '{print length($0)}' cn.txt

# substr 取“第一个字符”，看切出来是什么
awk '{print substr($0,1,1)}' cn.txt | od -An -tx1

# split 按空串逐“字符”切，看切成几段
awk '{n=split($0,a,""); print n}' cn.txt
```

```text
# 实测
$ printf '张三\n' > cn.txt
$ awk '{print length($0)}' cn.txt
6
$ LC_ALL=C awk '{print length($0)}' cn.txt
6
$ LC_ALL=C.UTF-8 awk '{print length($0)}' cn.txt
6

$ awk '{print substr($0,1,1)}' cn.txt | od -An -tx1
e5 0a

$ awk '{n=split($0,a,""); print n}' cn.txt
6

# 结论：三个 locale 下 length 都是 6 —— 因为「张三」是 2 个字符 × 3 字节 = 6 字节，
#       mawk 数的是字节，根本不看 locale；substr($0,1,1) 只切出第一个字节 0xe5，
#       这不是一个合法的 UTF-8 字符，打印出来就是乱码，这正是中文被「切坏」的根因。
#       gawk 在 UTF-8 locale 下同一份数据 length 会是 2，substr($0,1,1) 得到完整的「张」。
```

因此有一条很实用的纪律：**要用 awk 截断含中文的字段（尤其是按长度截断），在 Ubuntu 默认 mawk 下不要用 `substr()`，改用 `cut -c`、`${var:0:n}`（bash 里按字符）或直接用 Python**；如果非要 awk，就得先 `sudo apt install gawk` 再显式用 `gawk`，并且 `export LC_ALL=C.UTF-8`。

同一批实测里还暴露了另外几个容易踩的点：

```shell
# toupper/tolower 只处理 ASCII，非 ASCII 字母原样不动
awk 'BEGIN{print toupper("héllo"), toupper("中文")}'

# index 找不到时返回 0（不是 -1，也不是空）
awk 'BEGIN{s="hello"; print index(s,"ll"), index(s,"zz")}'

# substr(s, m) 两参数形式 = 从 m 到结尾
awk 'BEGIN{s="hello"; print substr(s,2)}'

# length 不带参数 = length($0)；length 不加括号也行
printf 'hello\n' | awk '{print length(), length}'

# printf 支持的格式符（本机实测）
awk 'BEGIN{printf "%d %5.2f %e %x %o %c\n", 42, 3.14159, 12345.678, 255, 8, 65}'

# 浮点打印精度：默认 %g 六位有效数字
awk 'BEGIN{print 10/3; printf "%.2f\n", 10/3}'

# 大整数会被浮点截断（超过 2^53 后不再精确）
awk 'BEGIN{print 9007199254740992 + 1}'
```

```text

$ awk 'BEGIN{s="hello"; print index(s,"ll"), index(s,"zz")}'

$ awk 'BEGIN{s="hello"; print substr(s,2)}'

$ printf 'hello\n' | awk '{print length(), length}'

$ awk 'BEGIN{printf "%d %5.2f %e %x %o %c\n", 42, 3.14159, 12345.678, 255, 8, 65}'

$ awk 'BEGIN{print 10/3; printf "%.2f\n", 10/3}'

$ awk 'BEGIN{print 9007199254740992 + 1}'

# 超过 2^53 = 9007199254740992 之后加 1 已经无法表示 —— 大整数 ID 不要用 awk 做算术
```

```text
要点：
1. mawk 字符串按「字节」：length/substr/index/split 都数字节，和 locale 无关；截断中文必须换工具或换 gawk
2. toupper/tolower 只翻 ASCII 字母，非 ASCII 原样返回
3. index() 找不到返回 0；substr(s,m) 是「从 m 到结尾」；length() 不带参数就是 length($0)
4. printf 格式符 %d %f %e %x %o %c 齐全；print 默认按 %g 输出 6 位有效数字
5. awk 的数值是双精度浮点，超过 2^53 的整数不精确，ID/时间戳级别的精确算术别交给 awk
```

### BEGIN 与 END

BEGIN 块在读取任何输入之前执行（初始化、打印表头），END 块在所有输入处理完后执行（汇总、打印结果）。「BEGIN 设分隔符 + 主体逐行处理 + END 汇总」是 awk 脚本的标准三段式。做报表时 BEGIN 打印列名、END 打印合计行，结构清晰。

```shell
# 三段式：BEGIN 表头 → 主体统计 → END 输出
awk 'BEGIN {print "级别统计:"} {cnt[$3]++} END {for (k in cnt) print k, cnt[k]}' /tmp/demo.txt
```

```text
# 实测
级别统计:
INFO 2
ERROR 3
WARN 1
```

BEGIN 里设 FS/OFS、END 里打印合计行；两个块都能写多个，按顺序执行：

```shell
# BEGIN 设分隔符 + 打印表头；END 打印数据行数
awk 'BEGIN{FS=","; print "姓名,工资"} NR>1{sum+=$4} END{print "平均:", sum/(NR-1)}' /tmp/users.csv

# 多文件时 END 只在全部处理完后执行一次
awk 'BEGIN{n=0} {n+=NF} END{print "总字段数:", n}' /tmp/demo.txt
```

```text
要点：
1. BEGIN 读数据前执行一次（初始化变量/设 FS/OFS/打表头），END 处理完执行一次（汇总/合计）
2. 主体对每条记录执行一次；三段式是 awk 报表脚本的标准骨架
3. BEGIN/END 可写多个，按出现顺序执行；无输入文件时也能只靠 BEGIN 输出（如纯计算）
4. 易错点：字段 $1 只在主体有效，BEGIN 里还没有字段、END 里是最后一条记录的字段残留
5. 易错点：END 里 NR 是总行数，适合算平均（sum/NR），但注意跳过表头后要除以 (NR-1)
```

### awk 方言对照：gawk 专有特性在 mawk 下有两种下场

这是本篇最重要的一张表。**gawk 专有特性落到 mawk 上，要么「报错」，要么更危险的「静默失效」**——后者不报错、不退出，只是给你一个错的结果，比报错难查得多：

|---|---|---|---|
| `gensub(re, repl, how, s)` | 支持 | 报错 `function gensub never defined` | `sub()`（首个）/ `gsub()`（全部）；只要替换第一个匹配就用 `sub` |

| `-i inplace` | 5.1+ 支持 | 报错 `awk: not an option: -i` | 输出到临时文件再 `mv`；或改用 GNU `sed -i` |

## 工作原理

awk 的执行模型是「三段式 + 逐记录循环」：

1. **BEGIN 阶段**：读入任何数据之前执行一次，用于初始化变量、设 FS/OFS、打印表头。
2. **主体循环**：按记录分隔符 RS（默认换行）逐条读入，每读一条先按 FS 切成字段、更新 NR/NF，然后**按顺序**对每个「模式 {动作}」求值——模式命中就执行对应动作。
3. **END 阶段**：所有记录处理完后执行一次，用于输出汇总结果。

关键点：字段切分发生在「每条记录读入时」，所以 `$1` 等字段只在主体循环里有效；关联数组要等到 END 里遍历输出，因为那时所有记录才处理完。理解这个「读一条 → 过一遍所有模式 → 下一条」的循环，就理解了 awk 为什么是日志统计的标准工具。

```text
awk 执行流程：
BEGIN（一次）→ 逐记录循环 { 切字段 → 更新 NR/NF → 按序匹配模式执行动作 } → END（一次）
```

```text
逐记录循环的细节：
1. 每条记录先按 RS 读入、再按 FS 切字段、更新 NR/NF/FNR
2. 然后按脚本书写顺序依次对每个「模式 {动作}」求值，命中即执行
3. 一个动作里 next 会立即跳到下一条记录，跳过当前行剩余的其它模式
4. 内存模型：变量和关联数组跨记录存活，这是分组统计能累积的原因
```

### 字段切分的时机（为什么改 FS 有时「不生效」）

awk 规范允许字段**惰性切分**：一条记录读进来后，`$0` 已经有了，但 `$1 $2 ...` 要等你**第一次引用字段或 NF** 时才按当前的 FS 切。这带来一个非常常见的困惑：在主体动作里改 `FS`，对「当前这条记录」通常不起作用，只影响后面的记录。本机实测：

```shell
# 在第 1 行（而非 BEGIN）里改 FS
printf 'a:b\nc:d\n' | awk 'NR==1{FS=":"} {print NR, "NF="NF, "$1="$1}'

# 正确做法：在 BEGIN 里设，或者用 -F（等价于读数据前设好）
printf 'a:b\nc:d\n' | awk -F: '{print NR, "NF="NF, "$1="$1}'
```

```text
# 实测
$ printf 'a:b\nc:d\n' | awk 'NR==1{FS=":"} {print NR, "NF="NF, "$1="$1}'
1 NF=1 $1=a:b          <-- 第 1 行没被切，整行当成一个字段
2 NF=2 $1=c            <-- 第 2 行才按 ":" 切开

$ printf 'a:b\nc:d\n' | awk -F: '{print NR, "NF="NF, "$1="$1}'
1 NF=2 $1=a
2 NF=2 $1=c
```

同一个「惰性」机制也解释了另外两个高频现象：

1. **改了字段不会自动重排 `$0`**：`$0` 是「原始输入 + 手工修改」的拼接结果，改 `$1` 后 awk 会用 OFS 重建 `$0`，但**对 `$0` 本身做 `gsub` 不会反推字段**，必须显式写 `$0=$0` 或 `$1=$1` 触发重切。
2. **`sub/gsub` 直接作用于 `$n` 会重建整行**，作用于 `$0` 则字段保持旧值——两种写法结果不同，见下面的实测。

```shell
# 改字段：awk 自动用 OFS 重建 $0
echo "a b c" | awk 'BEGIN{OFS="-"}{$1=$1; print}'

# 对 $0 做替换：字段不会跟着变，必须 $0=$0 强制重切
echo "a b c" | awk '{gsub(/ /,"-"); print $1}'
echo "a b c" | awk '{gsub(/ /,"-"); $0=$0; print $1}'

# 对 $1 做替换：整行会被重建（空格仍是默认 OFS）
echo "a b" | awk '{gsub(/a/,"X",$1); print $0}'
```

```text
# 实测
$ echo "a b c" | awk 'BEGIN{OFS="-"}{$1=$1; print}'
a-b-c

$ echo "a b c" | awk '{gsub(/ /,"-"); print $1}'
a b c          <-- $1 还是原来的 "a"（字段没重切）

$ echo "a b c" | awk '{gsub(/ /,"-"); $0=$0; print $1}'
a-b-c          <-- $0=$0 强制重切，现在整行成了 1 个字段

$ echo "a b" | awk '{gsub(/a/,"X",$1); print $0}'
X b            <-- gsub 作用于 $1，awk 自动重建 $0
```

### 记录分隔符 RS 的工作细节

RS 决定「什么算一条记录」。默认是换行符 `\n`；改成别的值可以按任意串切，改成空串则进入「段落模式」（空行分隔的块算一条记录）。这段全部本机实测：

```shell
# 多字符 RS：按 "XX" 切记录
printf 'aXXbXXc' | awk 'BEGIN{RS="XX"} {print NR, $0}'

# RS="" 段落模式：连续空行分隔的块算一条记录，块内换行保留
printf 'l1\nl2\n\nl3\n' | awk 'BEGIN{RS=""} {print "rec"NR": ["$0"]"}'

# 段落模式下：换行也会被当作字段分隔（POSIX 规定：RS="" 时 FS 也把 \n 当分隔符）
printf 'a b\nc d\n' | awk 'BEGIN{RS=""} {print NF, $1, $3}'

# ORS 改「输出」记录分隔符（默认 \n）
printf '1\n2\n' | awk 'BEGIN{ORS="|"} {print}'
```

```text
# 实测
$ printf 'aXXbXXc' | awk 'BEGIN{RS="XX"} {print NR, $0}'
1 a
2 b
3 c

$ printf 'l1\nl2\n\nl3\n' | awk 'BEGIN{RS=""} {print "rec"NR": ["$0"]"}'
rec1: [l1
l2]
rec2: [l3]

$ printf 'a b\nc d\n' | awk 'BEGIN{RS=""} {print NF, $1, $3}'
4 a c          <-- 段落模式下 a b\nc d 被切成 4 个字段（换行也分隔）

$ printf '1\n2\n' | awk 'BEGIN{ORS="|"} {print}'
1|2|           <-- 记录之间用 | 而不是换行
```

```text
要点：
1. 字段是「惰性切分」的：引用 $n / NF 才按当时的 FS 切，所以在主体里改 FS 对当前行常常无效
2. 设置 FS 的正确位置是 BEGIN，或命令行 -F（读数据前就生效）
3. 改 $n 会自动用 OFS 重建 $0；只改 $0 不会反推字段，要 $0=$0 或 $1=$1 强制重切
4. RS 默认 \n；RS="XX" 按任意串切记录；RS="" 是段落模式，且此时 FS 也把换行当分隔符
5. ORS 是「输出」端的分隔符，和 RS 对称：RS 管怎么读、ORS 管怎么写
```

## 常用命令与配置

awk 的常用参数与高频单行命令：

```shell
awk -F, '{print $1}' file            # 指定分隔符为逗号
awk -v threshold=100 '$2 > threshold' file   # 外部传变量
awk -f script.awk file               # 从脚本文件加载程序
awk 'NR>1 {print}' file              # 跳过第一行（表头）
awk '{cnt[$1]++} END {for (k in cnt) print k, cnt[k]}' file   # 分组计数
awk '{sum+=$2} END {print sum/NR}' file                        # 求平均
```

```text
参数分工：
-F 输入分隔符 / -v 传变量 / -f 脚本文件 / -F'[ ,]' 多字符分隔符
```

更多高频单行命令（按用途分组）：

```shell
# 字段提取
awk '{print $1, $NF}' file                                   # 首字段 + 末字段
awk -F: '{print $1, $3, $7}' /etc/passwd                     # 切 passwd

# 过滤
awk '$3=="ERROR"' file                                       # 精确匹配字段
awk '$2 > 100' file                                          # 数值过滤
awk 'NR>=10 && NR<=20' file                                  # 行号区间

# 统计
awk '{cnt[$1]++} END {for (k in cnt) print k, cnt[k]}' file  # 分组计数
awk '{sum+=$2; if ($2>max) max=$2} END {print "和:", sum, "最大:", max}' file  # 求和+最大值
awk 'NR>1 {s+=$2} END {printf "平均: %.2f\n", s/(NR-1)}' file              # 求平均

# 改写字段顺序 / 格式化输出
awk '{print $3, $1, $2}' file                               # 重排字段
awk '{printf "%-10s %5d\n", $1, $2}' file                   # 对齐输出
```

```text
实用技巧：
1. -v 传变量避免在单引号里拼 shell 变量（引号地狱），还能传数值做比较
2. 复杂脚本写 .awk 文件用 -f 加载，可复用、可加注释、可版本管理
3. 单行命令优先「提取/过滤/统计」三类，覆盖 90% 日志分析需求
```

### 选项层面的方言差异（本机实测）

awk 的**命令行选项**同样是分方言的。Ubuntu 默认 mawk 只认 POSIX 选项加自己的 `-W` 系列，gawk 的长选项（`--csv`、`-i inplace`、`-e`、`--dump-variables`）它一律拒绝：

```shell
# 本机 mawk 实测：这些 gawk 选项全部不可用
awk -i inplace '{print}' f.txt      # awk: not an option: -i
awk --csv '{print $1}' f.txt        # awk: not an option: --csv
awk -e 'BEGIN{print "a"}' -e 'BEGIN{print "b"}'   # awk: not an option: -e

# mawk 自己的一套 -W 选项是可用的
awk -W version                      # 打印版本横幅
awk -W dump 'BEGIN{x=1; print x}'   # 把编译后的字节码 dump 出来（调试用）

# 多段脚本：gawk 用 -e 或 @include，mawk 只能靠多个 -f 依次拼接
printf 'BEGIN{print "A"}\n' > a1.awk
printf 'BEGIN{print "B"}\n' > a2.awk
awk -f a1.awk -f a2.awk             # 输出 A 然后 B

# 从标准输入读脚本：-f - （mawk 支持）
printf 'BEGIN{print "ok"}\n' | awk -f -
```

### 一组可以直接背下来的经典单行惯用法（全部本机实测）

```shell
# 1) 去重且保持「首次出现」的顺序（比 sort -u 保序）
printf 'a\nb\na\nc\nb\n' > dup.txt
awk '!a[$0]++' dup.txt

# 2) 只打印重复出现的行
awk 'a[$0]++' dup.txt

# 3) 删除空行（NF==0 即空行/纯空白行）
printf 'x\n\ny\n' | awk 'NF'

# 4) 取最后 3 行（tail -n 3 的 awk 版，需先缓存——最坏 O(n) 内存）
printf '1\n2\n3\n4\n5\n' | awk '{a[NR]=$0} END{for(i=NR-2;i<=NR;i++) print a[i]}'

# 5) 反转行序（tac 的 awk 版）
printf '1\n2\n3\n' | awk '{a[NR]=$0} END{for(i=NR;i>=1;i--) print a[i]}'

# 6) 多列分别求和（一次遍历出所有列的合计）
printf '1 2\n3 4\n' | awk '{for(i=1;i<=NF;i++) s[i]+=$i} END{for(i=1;i<=NF;i++) print "列"i": "s[i]}'

# 7) 每行字符数（注意：mawk 数的是字节，见「核心概念」）
printf 'ab\ncde\n' | awk '{print NR": "length($0)}'
```

```text

c

$ awk 'a[$0]++' dup.txt

b

$ printf 'x\n\ny\n' | awk 'NF'

y

$ printf '1\n2\n3\n4\n5\n' | awk '{a[NR]=$0} END{for(i=NR-2;i<=NR;i++) print a[i]}'

$ printf 'ab\ncde\n' | awk '{print NR": "length($0)}'

```

```text
要点：
1. mawk 只认 POSIX 选项 + -W 系列；gawk 的 --csv / -i inplace / -e / --dump-variables / @include 在 mawk 上直接报 "not an option"
2. 多段脚本：mawk 用多个 -f 拼接；-f - 可从标准输入读脚本（两边都支持）
3. 惯用法四件套：!a[$0]++（保序去重）、a[$0]++（只列重复）、NF（删空行）、{a[NR]=$0} END{...}（tail/tac 的 awk 版）
4. -- 放在「程序文本之前」才表示选项结束；写在程序文本之后会被当成文件名（mawk 实测）
5. 跨平台脚本里如果出现 --csv / -i inplace，等于给 Ubuntu 埋了一个必炸的雷
```

## 配置文件解析

awk 没有独立配置文件，但它的程序可以通过脚本文件和变量「配置化」：

```text
1. 把复杂 awk 程序写进 .awk 文件，用 awk -f script.awk 加载——可复用、可版本管理
2. -v 传变量相当于「运行时配置」，把阈值/分隔符等参数化
3. ENVIRON 数组 —— awk 程序内可直接读环境变量（ENVIRON["HOME"]），
   把外部环境当配置来源
4. 脚本文件结构：
   BEGIN { FS=","; OFS="," }     # 配置段
   { ... }                        # 主逻辑
   END { ... }                    # 汇总
```

脚本文件示例（`report.awk`，与 nginx 日志配套）：

```awk
# report.awk —— 统计 nginx 日志状态码分布
BEGIN {
    FS = " "                 # 配置段：输入分隔符
    OFS = "\t"               # 输出用 tab 对齐
    print "状态码", "数量"    # 表头
}
{
    cnt[$9]++                # 主逻辑：$9 是状态码
}
END {
    for (k in cnt)           # 汇总段：输出结果
        print k, cnt[k]
}
```

```text
用法：awk -f report.awk /var/log/nginx/access.log | sort -k2 -rn
要点：
1. 脚本文件让 awk 程序脱离 shell 引号转义，写复杂逻辑更清晰
2. ENVIRON["NAME"] 读环境变量，可把阈值/目录等做成配置
3. -v 传变量优先级高于脚本内的赋值，适合做「运行时参数」
```

### 用环境变量做配置（ENVIRON）—— 本机实测

awk 没有配置文件，但 `ENVIRON` 数组把进程环境直接暴露给脚本，这是最「无侵入」的配置入口：调用方用环境变量传参数，脚本里读 `ENVIRON["KEY"]`，不用改脚本、也不用拼 `-v`。

```shell
# 脚本里读环境变量，不存在的键返回空串（不报错）
THRESH=100 awk 'BEGIN{t = ENVIRON["THRESH"] + 0; print "阈值:", t}'

# 不设也能跑，只是值为 0 —— 可以借此给默认值
awk 'BEGIN{t = (ENVIRON["THRESH"] != "" ? ENVIRON["THRESH"] : 50) + 0; print "阈值:", t}'
```

```text
# 实测
$ THRESH=100 awk 'BEGIN{t = ENVIRON["THRESH"] + 0; print "阈值:", t}'
阈值: 100

$ awk 'BEGIN{t = (ENVIRON["THRESH"] != "" ? ENVIRON["THRESH"] : 50) + 0; print "阈值:", t}'
阈值: 50
```

### 脚本库复用：`@include` 是 gawk 专有

想把公共函数（比如自定义的十六进制转换、时间格式化）拆到一个 `lib.awk` 里复用，gawk 提供了 `@include`，**mawk 不认识这个语法**，直接语法报错：

```shell
# lib.awk 里写 @include —— mawk 直接崩
echo '@include "nonexistent.awk"' > inc.awk
awk -f inc.awk /etc/hostname
```

```text
# 实测
$ awk -f inc.awk /etc/hostname
awk: 1: unexpected character '@'
```

mawk 下的替代方案就是把公共脚本当成「另一段程序」，用多个 `-f` 依次加载（等价于把文件内容拼起来）：

```shell
# lib.awk 放函数，main.awk 放逻辑，命令行上按顺序拼
printf 'function hi(){ return "hello" }\n' > lib.awk
printf 'BEGIN{ print hi() }\n' > main.awk
awk -f lib.awk -f main.awk
```

```text
# 实测
$ awk -f lib.awk -f main.awk
hello
```

### 把 awk 脚本做成可执行命令（shebang 的正确写法）

要让 `./report.awk access.log` 直接跑，脚本头部必须写成**绝对路径的 `awk`**（shebang 不走 PATH）：

```awk
#!/usr/bin/awk -f
# report.awk —— 统计状态码分布；第一行 shebang 里的 -f 不能省
BEGIN { FS = " "; OFS = "\t"; print "状态码", "数量" }
      { cnt[$9]++ }
END   { for (k in cnt) print k, cnt[k] }
```

```shell
chmod +x report.awk
./report.awk /var/log/nginx/access.log
```

```text
要点（配置文件解析的补充）：
1. ENVIRON["KEY"] 是最轻量的「配置」入口；键不存在返回空串、值为字符串，做数值比较前要 +0
2. @include 是 gawk 专有，mawk 报 "unexpected character '@'"；mawk 用多个 -f 拼接实现同样的「脚本库」效果
3. 想让脚本可执行，shebang 必须是 #!/usr/bin/awk -f（绝对路径 + 带 -f），不能写 #!/usr/bin/env awk
4. 注意 shebang 固定调用 awk 会随发行版换实现（Ubuntu=mawk、RHEL=gawk）—— 要锁死行为就写 gawk 并在注释里说明依赖
5. 配置化的三个层次：-v（运行时参数）→ ENVIRON（环境约定）→ .awk 脚本文件（可版本管理的固定配置）
```

完整报表：BEGIN 打印表头、主体按部门统计人数和工资总和、END 打印合计行。这是 awk 做「日报/周报」的标准三段式。

### 场景四：把「gawk 专有」的脚本改写成 mawk 能跑（迁移实战）

这是 Ubuntu 上最高频的一次性任务：从网上/别的机器抄来一段 awk，本机一跑就报 `function gensub never defined`。下面给一份典型脚本，先看它在 mawk 下的真实报错，再逐步换成等价写法。

```shell
# 目标：把 "name=alice;role=admin" 里 role= 后的值取出来并大写，只处理第一条记录
# 原始写法（gawk 专有：用了 gensub）
echo 'name=alice;role=admin' | awk '{print toupper(gensub(/.*role=([^;]+).*/, "\\1", "g", $0))}'
```

```text
# 实测（mawk 下直接炸）
$ echo 'name=alice;role=admin' | awk '{print toupper(gensub(/.*role=([^;]+).*/, "\\1", "g", $0))}'
awk: line 2: function gensub never defined
```

mawk 下有三条替换路线，按复杂度递增：

```shell
# 路线 A：用 match + RSTART/RLENGTH 手工抠（最通用，POSIX 全支持）
echo 'name=alice;role=admin' | awk '{if (match($0, /role=[^;]+/)) {v = substr($0, RSTART+5, RLENGTH-5); print toupper(v)}}'

# 路线 B：用 sub 就地删掉前后缀（不需要分组捕获时最简洁）
echo 'name=alice;role=admin' | awk '{sub(/.*role=/, ""); sub(/;.*/, ""); print toupper($0)}'

# 路线 C：用 split / FS 直接切（结构规整时最快）
echo 'name=alice;role=admin' | awk -F'[;=]' '{print toupper($4)}'
```

```text
# 实测
$ echo 'name=alice;role=admin' | awk '{if (match($0, /role=[^;]+/)) {v = substr($0, RSTART+5, RLENGTH-5); print toupper(v)}}'
ADMIN
$ echo 'name=alice;role=admin' | awk '{sub(/.*role=/, ""); sub(/;.*/, ""); print toupper($0)}'
ADMIN
$ echo 'name=alice;role=admin' | awk -F'[;=]' '{print toupper($4)}'
ADMIN
```

换成 `asort` 的迁移同样简单——`asort` 只是「把数组排序」，交回给 `sort` 即可：

```shell
# gawk：asort 按值排序（数组内部排）
# mawk：把结果打到管道，交给 sort（外部排，功能等价且更好调参）
awk '{cnt[$3]++} END{for (k in cnt) print cnt[k], k}' /tmp/demo.txt | sort -rn
```

```text
# 实测
3 ERROR
2 INFO
1 WARN
```

```text
迁移套路总结（gawk → mawk）：
1. gensub(/re/, "\\1", "g", s) → sub/gsub（无分组）或 match + RSTART/RLENGTH（要分组）
2. asort/asorti(arr) → 把 arr 打到 stdout，用 sort / sort -rn / sort -k2 排
3. IGNORECASE=1 → 匹配前对两边做 tolower()
4. FPAT → while (match(...)) 循环抠
5. -i inplace → 写临时文件再 mv；或改用 sed -i
6. 你无法在本机验证 gawk 行为时，就别在脚本里留 gawk 特性——宁可用更啰嗦的 POSIX 写法
```

### 场景五：系统账户审计（/etc/passwd + /etc/group）

awk 天生适合处理 `/etc/passwd` 这种固定字段的冒号分隔文件（7 个字段：用户名:密码占位:UID:GID:注释:HOME:SHELL）。以下全部是本机真实执行结果。

```shell
# 先看规模
wc -l /etc/passwd /etc/group

# 1) UID 分布：root / 系统账户 / 普通用户
awk -F: '{c[($3==0 ? "root(UID=0)" : ($3>=1000 ? "普通用户(UID>=1000)" : "系统账户(1-999)"))]++}
         END{for(k in c) printf "%-24s %d\n", k, c[k]}' /etc/passwd | sort

# 2) 能登录的 shell 分布（/usr/sbin/nologin 和 /bin/false 表示不可登录）
awk -F: '{c[$7]++} END{for(k in c) printf "%-28s %d\n", k, c[k]}' /etc/passwd | sort -k2 -rn

# 3) 密码字段为空（能无密码登录，安全隐患）的账户数
awk -F: '$2=="" {n++} END{print n+0}' /etc/passwd

# 4) 头 3 个账户的「名 UID SHELL」
awk -F: 'NR<=3 {print $1, $3, $7}' /etc/passwd
```

```text
/bin/sync                    1

$ awk -F: '$2=="" {n++} END{print n+0}' /etc/passwd
0

$ awk -F: 'NR<=3 {print $1, $3, $7}' /etc/passwd
root 0 /bin/bash
daemon 1 /usr/sbin/nologin
bin 2 /usr/sbin/nologin
```

审计结论（这一步才是 awk 的价值所在）：52 个账户里只有 2 个是 UID ≥ 1000 的真人用户，其余 49 个都是系统账户；**只有 2 个账户的 shell 是 `/bin/bash`，却有 42 个是 `/usr/sbin/nologin`** —— 这是标准做法，不需要登录的服务账户都把 shell 设成 nologin。`/bin/false`、`/bin/sync` 同样不可登录。密码字段为空的账户数为 0，也符合预期（现代发行版密码都在 `/etc/shadow`，passwd 里是 `x`）。

```text
红帽系差异（RHEL / CentOS / Fedora）：
1. /etc/passwd 的字段结构（7 字段冒号分隔）在红帽系与 Debian/Ubuntu 完全一致，上面 4 条命令两边都能直接跑
2. UID 分界线不同：RHEL 系 UID 500 起是普通用户（CentOS 6 及更早）／1000 起（CentOS 7+ 起），
   本机 Ubuntu 是 1000 起 —— 写审计脚本时把阈值写成变量、用 -v 传入，别硬编码
3. 红帽系的 /etc/passwd 里系统账户数量通常比 Ubuntu 桌面版更多（多了 nfsnobody/tss/sshd 等）
4. 若机器启用了 SSSD/LDAP，/etc/passwd 只是本地账户，真实账户要 getent passwd 才全 ——
   两种情况下 awk -F: 的写法一样，只是输入来源从文件换成 getent passwd 的管道输出
```

### 场景六：多文件关联聚合（awk 版 join：补字段 + 反连接）

awk 用 `NR==FNR` 这个惯用法可以模拟 SQL 的 JOIN：**第一个文件读完建映射，之后读第二个文件时查表**。原理是 `NR` 跨文件累计而 `FNR` 每个文件重置，所以 `NR==FNR` 只有在读第一个文件时为真。

```shell
# 准备数据：部门代码 → 中文名
printf 'dev,研发部\nops,运维部\nsales,销售部\n' > dept.csv

# 1) 关联：给 users.csv 每行补上部门中文名
awk -F, 'NR==FNR {d[$1]=$2; next}          # 第一阶段：读 dept.csv 建映射，next 掉
         FNR==1 {next}                      # 跳过 users.csv 表头
         {print $2, "("$3") 部门:", d[$3], "工资:", $4}' dept.csv /tmp/users.csv

# 2) 分组聚合：按部门求人数、总额、人均
awk -F, 'NR==FNR {d[$1]=$2; next}
         FNR>1 {sum[d[$3]]+=$4; n[d[$3]]++}
         END{for (k in sum) printf "%-10s 人数=%d 总额=%d 人均=%.0f\n", k, n[k], sum[k], sum[k]/n[k]}' dept.csv /tmp/users.csv | sort

# 3) 反连接：找出在 users.csv 里但 dept.csv 没有映射的行（数据质量问题）
awk -F, 'NR==FNR {d[$1]=1; next}
         FNR>1 && !($3 in d) {print "无部门映射:", $0}' dept.csv /tmp/users.csv
```

## 性能与调优

```text
1. awk 单遍扫描就能完成过滤+统计，比 grep|sort|uniq 多进程管道更快
2. 关联数组在大文件下内存累积，几十 GB 日志别把所有键憋在内存里，改用 sort|uniq -c 流式统计
3. 字段切分是主要开销，字段越多越慢，必要时用单字符分隔符
4. 复杂逻辑写成 .awk 文件用 -f 加载，比命令行堆一长串更易维护
5. 数值比较注意字段类型，避免字符串比较导致的重复扫描和错误结果
```

```text
进阶调优：
1. 用 gawk（GNU awk）时，需要稳定输出顺序可设 PROCINFO["sorted_in"]="@val_num_desc"，
   省掉尾部 sort 进程
2. 大文件优先 awk 过滤再交给其它工具，先缩小数据量是管道优化的第一原则
3. 字符串连接（s = s $0）在 gawk 里是 O(1) 摊还，但 mawk 等实现可能是 O(n^2)，
   大量拼接用数组 + join 思路更稳
4. 避免在每行里重复调用 system()（每调用 fork 一次进程，极慢），能用内置函数就别起子进程
```

### 实测基准数据（200 万行 / 约 14 MB，本机 mawk 1.3.4）

性能结论不能靠感觉。下面这些数字全部是本机实跑 `time` 得到的，测试文件用 `seq 1 2000000` 生成：

```shell
seq 1 2000000 > /tmp/big.txt        # 约 14 MB，200 万行
wc -l /tmp/big.txt

# A) 正则匹配计数
time awk '/1999/{n++} END{print "matched:", n}' /tmp/big.txt
time grep -c '1999' /tmp/big.txt    # 对照组

# B) 只数行、不碰任何字段（不触发字段切分）
time awk '{n++} END{print n}' /tmp/big.txt

# C) 引用 $1 求和（触发字段切分）
time awk '{s+=$1} END{print s}' /tmp/big.txt

# D) 关联数组分组（按字段长度分组）
time awk '{c[length($1)]++} END{n=0; for(k in c) n++; print "组数:", n}' /tmp/big.txt
```


从这组数字能直接读出三条结论：

1. **字段切分确实是主要开销**：同样扫 200 万行，只用 `n++` 是 0.046s，一旦引用 `$1` 触发字段切分就涨到 0.203s —— 约 **4.4 倍**。所以「只提取需要的字段」「能不用 `$n` 就不用」是真实的优化手段，不是空话。
2. **纯计数用 grep 比 awk 快**（0.014s vs 0.074s，约 5 倍）—— grep 是专门为字符串匹配优化的，awk 要先逐行建记录、跑自己的 regex 引擎。**只需要「某模式出现多少次」这种任务，别用 awk 硬扛，用 `grep -c`。**
3. **awk 的优势在「一趟搞定复合逻辑」**：如果你本来要跑 `grep | sort | uniq -c | sort -rn` 四道管道（4 个进程 + 中间数据落内存），一个 awk 就能一次遍历出结果 —— 这时 awk 的绝对速度慢一点，但少了三次进程切换和三份中间数据。

### 字符串拼接的复杂度：mawk 上是二次方增长（实测数据）

原文档提到「mawk 的字符串拼接可能是 O(n^2)」。这条在本机得到了验证——同一段脚本，只改拼接次数，耗时增长远快于线性：

```shell
time awk 'BEGIN{for(i=0;i<20000;i++)  s = s "x"; print length(s)}'
time awk 'BEGIN{for(i=0;i<60000;i++)  s = s "x"; print length(s)}'
time awk 'BEGIN{for(i=0;i<200000;i++) s = s "x"; print length(s)}'
```

```text
# 实测
$ time awk 'BEGIN{for(i=0;i<20000;i++) s = s "x"; print length(s)}'
20000
real	0m0.005s

$ time awk 'BEGIN{for(i=0;i<60000;i++) s = s "x"; print length(s)}'
60000
real	0m0.044s

$ time awk 'BEGIN{for(i=0;i<200000;i++) s = s "x"; print length(s)}'
200000
real	0m1.057s
```

拼接次数从 2 万涨到 20 万（**10 倍**），耗时从 0.005s 涨到 1.057s（**约 211 倍**）—— 典型的二次方（O(n²)）特征。原因是 mawk 每次拼接都会重新分配并整体拷贝字符串。

**规整结论**：在 mawk 下要「攒很多行再输出」，**不要用 `s = s $0`**，改用数组下标追加、`END` 里再遍历输出；或者干脆别攒，用管道交给 `sort`/`uniq` 流式处理。

```shell
# 反例：二次方拼接（1 万行还行，一百万行会慢到不可忍）
# awk '{ s = s $0 "\n" } END { printf "%s", s }' big.txt

# 正例：先过滤再交管道，全程流式，内存恒定
awk '/ERROR/ {print $1}' big.txt | sort | uniq -c | sort -rn | head
```

### 大文件下的内存与输出缓冲

```text
1. 关联数组是内存大户：存的键越多内存越大。几十 GB 的日志如果按 IP 分组，上千万个键会把 awk 吃成几个 GB ——
   这种规模改用 sort | uniq -c（GNU sort 会落盘做外部归并），或者先过滤再分组
2. awk 的输出到终端是行缓冲、到管道/文件是块缓冲。要「即时看到输出」（长任务进度），在 print 后调 fflush()
3. 输入侧也一样：awk 逐条读，本身就是流式的；真正吃内存的只有「你主动缓存进数组」的那些数据
4. 多核机器上 awk 是单线程的 —— 要并行就切成多个文件分片喂给多个 awk，或在管道前置 xargs -P（比如按行号区间切）
5. RHEL/CentOS 的 gawk 在数值计算上通常比 mawk 略慢（gawk 功能多、检查多），
   但两者都远快于 Python 逐行读；选型时「先看方言兼容性，再看速度」
```

## 安全与权限

```text
1. awk 的 system() 会执行 shell 命令，脚本里拼接未校验输入时存在命令注入风险，尽量别用
2. 用 awk 处理日志提取的敏感字段（token/密码）别原样写入输出或日志
3. awk 脚本文件若有可执行权限且带 shebang，注意其被意外调用的权限边界
4. 处理 /etc/shadow、私钥等敏感文件时，awk 结果别重定向到可被他人读的位置
5. 从外部输入（文件名、-v 变量）拼进 system() 前先校验，或改用 awk 内置能力替代
6. 处理用户可控的输入文件时，警惕 getline 从文件读入导致的路径/内容注入，尽量别用 getline
```

### 命令注入的现场演示（本机实测，只跑无害命令）

上面第 1 条和第 5 条是**真实且高发**的漏洞，值得看一眼现场。`system()` 把字符串交给 `/bin/sh -c` 执行，只要字符串里有一处 `;`、`|`、`$()`、反引号，就能追加任意命令：

```shell
# 反面教材：外部传入的 user 直接拼进 system()
awk -v user='alice; whoami' 'BEGIN{system("echo 用户: " user)}'

# 正确做法：能用 print 就别用 system()
awk -v user='alice; whoami' 'BEGIN{print "用户: " user}'
```

```text
# 实测
$ awk -v user='alice; whoami' 'BEGIN{system("echo 用户: " user)}'
用户: alice
root                       <-- whoami 被真的执行了！输入里的 ";" 就是注入点

$ awk -v user='alice; whoami' 'BEGIN{print "用户: " user}'
用户: alice; whoami        <-- print 把整串当数据，不解释，安全
```

**安全纪律**：awk 脚本里凡是把「来自文件 / 来自 `-v` / 来自环境变量」的内容拼进 `system()`，都等于把 shell 交给外部输入。要么不用 `system()`，要么用单引号包裹并用 `sprintf` 里做严格白名单校验（只允许 `[A-Za-z0-9_.-]`），绝不直接拼接。

### system() 的性能与权限代价

`system()` 每调用一次都会 `fork` 一个子进程再 `exec` 一个 shell，代价比内置运算高约四个数量级——这也是「安全」之外的第二个理由：

```shell
# 50 次 system("true")：起了 50 个 shell 进程
time awk 'BEGIN{for(i=0;i<50;i++) system("true")}'

# 50000 次内置运算
time awk 'BEGIN{for(i=0;i<50000;i++) x=i+1; print x}'
```

```text
# 实测
$ time awk 'BEGIN{for(i=0;i<50;i++) system("true")}'
real	0m0.026s          # 50 次 system ≈ 26ms，约 0.52ms/次

$ time awk 'BEGIN{for(i=0;i<50000;i++) x=i+1; print x}'
50000
real	0m0.003s          # 5 万次内置运算 3ms，约 0.06µs/次

# 折算下来：system() 比内置运算慢约 8000~9000 倍（≈4 个数量级）
```

```text
安全与权限补充要点：
1. system() 是 awk 的注入面：任何外部输入直接拼接都能追加命令（实测 "; whoami" 成功执行）
2. 能用 print/printf 表达的就别用 system()；确需执行外部命令时，输入必须过白名单校验
3. system() 每次 fork+exec，比内置运算慢约 4 个数量级；循环里调 system() 是性能杀手
4. awk 脚本注意 shebang 的调用路径：/usr/bin/awk 是 alternatives 软链，Ubuntu 指向 mawk、RHEL 指向 gawk，
   行为可能随发行版变化；对安全性敏感的脚本要写死实现路径
5. awk 不做权限检查，它继承调用者的权限读文件 —— 处理 /etc/shadow 这类文件时的授权来自 sudo/文件 mode，
   awk 自己不是安全边界；别用「awk 读不到」当访问控制
6. RHEL/CentOS 上若开启 SELinux，脚本写系统目录还可能被策略拦（用 ausearch -m avc 排查），
   Ubuntu 桌面默认走 AppArmor，两者都不改变「awk 本身不做访问控制」这一事实
```

## 故障排查

```text
「统计结果不对」排查顺序：
1. 字段错位 —— 先 awk '{print NR, NF, $1, $2, $3}' 看清每列是什么
2. 分隔符 —— 默认按空白切，CSV 要 -F,，多空格/特殊分隔符要核对
3. 数值 vs 字符串 —— 字段默认字符串，比较排序要 $n+0 数值化
4. 表头混入 —— 忘了 NR>1 跳过表头，统计多出奇怪键
5. 数组遍历顺序 —— for(k in arr) 无序，要排序 pipe 给 sort
```

```text
「命令报语法错误」排查：
1. 单引号内再放单引号 —— awk '{print "it'"'"'s"}' 这类转义写错，改用 -v 或脚本文件
2. 括号/花括号不匹配 —— 复杂脚本先存文件再 awk -f，编辑器里能看清配对
3. -F 分隔符里的特殊正则字符 —— -F'.' 会把点当「任意字符」，要 -F'\\.'
4. gawk 与 mawk 差异 —— 某些扩展（如 PROCINFO/gensub/asort）只在 gawk 可用，Ubuntu 默认 awk 是 mawk，
   见下面「报错解码表」和「核心概念」的方言对照表
```

### 报错解码表：看到这些信息就知道问题在哪

awk 的报错信息普遍很短，下面是本机实测过的原文与对应的根因、修法：

| 报错原文 | 根因 | 修法 |
|---|---|---|
| `awk: line 2: function gensub never defined` | 用了 gawk 专有函数（gensub/asort/asorti/strtonum/and/or/xor…） | 换等价 POSIX 写法，或 `sudo apt install gawk` 后显式调 `gawk` |
| `awk: not an option: -i` | `-i inplace` 是 gawk 5.1+ 的选项 | 写临时文件再 `mv`；或改用 `sed -i` |
| `awk: not an option: --csv` | `--csv` 是 gawk 5.3+ 的选项 | 用 `-F,`；带引号的 CSV 交给 Python/csvkit |
| `awk: line 1: syntax error at or near ,` | 十有八九是 `match(s, re, arr)` 的第三参数（gawk 专有） | 用 `RSTART` / `RLENGTH` + `substr` |
| `awk: line 1: syntax error at or near {` | `switch/case`（gawk 专有） | 写 `if / else if` 链 |
| `awk: line 1: syntax error at or near *` | 写了 `**` 幂运算符（gawk 专有） | 改成 `^` |
| `awk: 1: unexpected character '@'` | 写了 `@include` / `@load`（gawk 专有） | 多个 `-f` 拼接脚本 |
| `awk: run time error: not enough arguments passed to printf("...")` | printf 格式符个数多于实参（mawk 直接报错退出，gawk 只警告） | 补齐参数或删掉多余格式符 |
| `awk: cannot open "--" (No such file or directory)` | `--` 写在了程序文本之后，被当成文件名 | 把 `--` 放到程序文本之前：`awk -- 'prog' file` |

### 「结果不对但没报错」的排查顺序

这类问题最费时间，按下面的顺序排查命中率最高：

```text
1. 先确认字段长什么样：awk '{print NR": NF="NF" ["$0"]"}' file | head -3
   —— 90% 的「统计结果不对」是字段错位（分隔符不是想象中的那个）
2. 再确认当前 awk 是哪个实现：awk --version | head -1
   —— 若是 mawk，检查脚本里有没有 IGNORECASE/FPAT/PROCINFO/BEGINFILE/ARGIND/RT（静默失效类）
3. 确认分隔符：默认是「连续空白」不是「单个空格」；CSV 要 -F,；字面单空格要 -F'[ ]'
4. 确认数值/字符串语义：字段是 strnum（纯数字按数值比较），-v 传入的也是；
   但拼接过的字符串（$1"" ）会变回字典序比较
5. 确认数组遍历顺序：for (k in arr) 无序，结果要稳定就管道 sort
6. 确认 locale：中文/length/substr 在 mawk 下按字节算；跨机器结果不同时先试 LC_ALL=C 复现
```

```text
红帽系对照：同样一份脚本，在 CentOS/RHEL（gawk）上第 2 步的结论会不同 ——
gawk 会让 IGNORECASE/FPAT/PROCINFO 真正生效，所以「Ubuntu 结果不对、CentOS 结果对」
或者反过来，都是方言差异导致的，不是数据问题。排查时先固定住 awk 实现（写死 gawk 或写死 mawk）。
```

## 常见问题

```text
Q1: awk 和 sed 怎么选？
A: 单行内的替换/删除用 sed，字段级提取、分组统计、数值计算用 awk。awk 是完整语言，sed 是流编辑器。

Q2: 为什么统计结果里字段编号总是对不上？
A: 多空格、分隔符、日志格式和默认 nginx 格式不同都会错位。先 awk '{print NR, NF, $1...}' 摸清字段。

Q3: CSV 字段里含逗号怎么办？
A: awk 不解析引号转义，只按字符切。复杂 CSV 用 csvkit 或 Python 的 csv 模块。

Q4: awk 能跨行处理吗？
A: 默认按记录（行）处理，跨行要靠 RS 改记录分隔符或状态变量，复杂场景不如 Python。

Q5: NR 和 FNR 到底差在哪？
A: NR 是「已经读过的总记录数」，跨文件累计；FNR 是「当前文件内的记录号」，每换一个文件重新从 1 数。处理多个文件要区分行号时用 FNR，要全局行号用 NR。

Q6: 怎么把 shell 变量传进 awk？
A: 用 -v 传：awk -v key="$var" '$1==key' file。别在单引号里直接拼 $var（shell 不会展开单引号内的变量），也避免引号转义地狱。

Q7: for (k in arr) 输出顺序乱怎么办？
A: 关联数组不保证遍历顺序。要排序就 pipe 给 sort，或 gawk 里设 PROCINFO["sorted_in"]="@val_num_desc"（按值倒序）/@ind_str_asc（按键升序）。注意 PROCINFO["sorted_in"] 是 gawk 专有，Ubuntu 默认的 mawk 下不报错但完全不生效（静默失效），跨发行版一律用管道 sort。

Q8: 为什么我的 gensub 一跑就报 function gensub never defined？
A: gensub 是 gawk 专有函数，Ubuntu/Debian 默认的 awk 是 mawk，没有它。三种处理：改用 sub/gsub（不需要分组捕获时）、改用 match + RSTART/RLENGTH + substr（需要分组时）、或 sudo apt install gawk 后把命令里的 awk 改成 gawk（不要依赖 awk 这个名字）。

Q9: 怎么知道自己机器上的 awk 到底是 mawk 还是 gawk？
A: awk --version | head -1 看横幅（mawk 打印 "mawk 1.3.4 ..."，gawk 打印 "GNU Awk 5.x"）；或者 awk 'BEGIN{print (PROCINFO["version"] != "" ? "gawk" : "非 gawk")}'，PROCINFO 是 gawk 专有变量，mawk 下它返回空串且不报错。生产脚本里建议把实现判定写进注释或启动检查。

Q10: IGNORECASE=1 写了没用，还是不区分大小写匹配失败？
A: IGNORECASE 是 gawk 专有，mawk 会忽略它（不报错），匹配仍然区分大小写。mawk 下用 tolower($0) ~ /pattern/ 或 tolower($0) == tolower(target) 实现大小写不敏感。

Q11: 中文为什么被 substr 切坏、length 数出来是字数的 3 倍？
A: Ubuntu 默认的 mawk 是字节导向实现，length/substr/index/split 都按字节算，和 locale 无关（本机实测「张三」length 恒为 6）。要按字符处理中文，用 cut -c、bash 的 ${var:0:n} 或 Python；非要用 awk 就先装 gawk 并设 LC_ALL=C.UTF-8，用 gawk 而不是 awk。

Q12: 同一个 awk 脚本在 Ubuntu 能跑、到 CentOS 报 function xxx never defined，为什么？
A: 典型原因是脚本用了 gawk 扩展：CentOS/RHEL 默认 gawk 能跑，Ubuntu 默认 mawk 报 "function xxx never defined"。修法：只用 POSIX 语法；必须用扩展时，在 CentOS 直接调 gawk，在 Ubuntu 先 sudo apt install gawk 再显式调 gawk，并把依赖写进脚本注释。

Q13: awk 能像 sed -i 一样原地改文件吗？
A: mawk 不能（无 -i inplace，报 awk: not an option: -i）。gawk 5.1+ 支持 gawk -i inplace，但跨发行版不安全。通用做法是写临时文件再原子替换：awk '...' f > f.tmp && mv f.tmp f（mv 是原子的，比直接重定向回原文件更安全）。纯文本替换类任务直接用 GNU sed -i 或 sed -i.bak。

Q14: awk 处理带引号的 CSV 为什么总是错位？
A: awk 只按字符/正则切分，不解析 CSV 的引号转义规则——字段里的逗号、字段内的换行都会切错。简单无引号 CSV 用 -F,；带引号的 CSV 用 Python 的 csv 模块或 csvkit；gawk 5.3+ 的 --csv 能处理，但 Ubuntu 默认的 mawk 没有这个选项（报 awk: not an option: --csv）。

Q15: print 出来的浮点数怎么控制精度？
A: print 默认按 OFMT（默认 %.6g）输出，所以 10/3 打印 3.33333。要固定小数位用 printf "%.2f\n", x；要改 print 的默认格式就设 OFMT="%.3f"（注意 OFMT 只影响数字，CONVFMT 影响数字转字符串的场合）。报表对齐统一用 printf。

Q16: awk 一次能处理多个文件吗？怎么区分是哪个文件的第几行？
A: 能，直接 awk '...' f1 f2。NR 跨文件累计、FNR 每个文件重新从 1 数、FILENAME 是当前文件名。常用套路 NR==FNR 判断「是否在读第一个文件」，这是 awk 模拟 JOIN 的标准写法（见场景六）。

Q17: for 循环里能不能改 $1 来改写整行？
A: 改 $n 会触发 awk 用 OFS 重建 $0（所以 $1=$1; print 是按 OFS 重排字段的标准写法）；但改完不会自动重切字段。反过来，对 $0 做 gsub 不会自动更新字段，要 $0=$0 或 $1=$1 强制重切。这两条方向不同的规则很容易混，见「工作原理」的实测。

Q18: awk 里怎么调试？（没有断点也没有 gdb 的话）
A: 三个土办法：1) 在脚本里插 print 到 stderr（print "DBG:", $0 > "/dev/stderr"），不影响 stdout 的数据管道；2) 用 awk -W dump 'prog' 看字节码（mawk 专有，较底层）；3) gawk 上用 gawk --dump-variables=/dev/stdout 'prog' 打印所有全局变量终值，或用 gawk -D 交互式调试器（mawk 都不支持）。
```

## 面试题

```text
1. awk 的 BEGIN、主体、END 分别什么时候执行？
   答：BEGIN 读数据前执行一次（初始化/表头），主体每条记录执行一次（逐行处理），END 数据处理完后执行一次（汇总）。

2. 用 awk 统计日志里每个状态码的数量？
   答：awk '{cnt[$9]++} END {for (k in cnt) print k, cnt[k]}' access.log，用关联数组做分组计数。

3. NR 和 FNR 的区别？
   答：NR 是跨文件累计的记录号，FNR 是当前文件内的记录号。处理多文件时 FNR 每个文件重新计数。

4. awk 的字段默认怎么切分？怎么指定分隔符？
   答：默认按空白（空格/制表符）切分，-F 指定其它分隔符（-F, 或 -F'[ ,]' 多字符）。

5. awk 里 $0、$1、$NF、NF 分别是什么？
   答：$0 是整行、$1 是第一个字段、$NF 是最后一个字段、NF 是字段总数。$(NF-1) 是倒数第二个字段。

6. 用 awk 求一个 CSV 文件某列的平均值怎么写？
   答：awk -F, 'NR>1 {sum+=$4; n++} END {print sum/n}' file.csv，NR>1 跳过表头，累加后除以有效行数。

7. awk 和 grep/sed 比强在哪？
   答：awk 是完整的小型语言——能做字段级提取、条件判断、循环、关联数组分组统计、数值计算，这是 grep（行级匹配）和 sed（流式替换）做不到的。字段级分组统计是它的杀手锏。

8. Ubuntu 默认的 awk 是什么实现？它和 gawk 有什么本质区别？
   答：Ubuntu/Debian 默认 awk 是 mawk 1.3.4（本机实测：awk --version 输出 "mawk 1.3.4 20240123"，gawk 未安装）；RHEL/CentOS/Fedora 默认是 gawk。两者都实现了 POSIX 的 awk 语言，但 gawk 提供大量扩展（gensub/asort/IGNORECASE/FPAT/PROCINFO/--csv/-i inplace/@include/switch/位运算函数等），mawk 没有。区别分两类后果：报错类（function xxx never defined、not an option）和更危险的静默失效类（IGNORECASE/FPAT/PROCINFO/BEGINFILE/ARGIND/RT 不生效但不报错）。

9. 举出至少三种「gawk 有、mawk 没有」的特性，并给出 mawk 下的替代方案。
   答：1) gensub() 替换 → 用 sub/gsub（无分组）或 match + RSTART/RLENGTH + substr（要分组）；2) asort()/asorti() 数组排序 → 把结果打到管道交给 sort；3) IGNORECASE 大小写不敏感 → 匹配前对两边做 tolower()；4) FPAT → while(match()) 循环抠；5) -i inplace → 临时文件 + mv 原子替换。

10. awk 的 $0、$1、NF、NR、FNR、FS、OFS、RS、ORS 各是什么？
    答：$0 整行、$1 第一个字段、NF 字段数（因此 $NF 是最后一个字段）、NR 累计记录号（跨文件）、FNR 当前文件内记录号、FS 输入字段分隔符（默认连续空白）、OFS 输出字段分隔符（默认空格）、RS 记录分隔符（默认换行）、ORS 输出记录分隔符（默认换行）。

11. awk 里「字段是惰性切分」是什么意思？由此产生什么坑？
    答：读入一条记录时只拿到 $0，直到第一次引用 $n 或 NF 才按当时的 FS 切字段。坑在于「在主体动作里改 FS 对当前这条记录无效」，只影响后面的记录——本机实测：printf 'a:b\nc:d\n' | awk 'NR==1{FS=":"}{print NR,NF,$1}' 第 1 行输出 NF=1（没切），第 2 行才 NF=2。正确做法是在 BEGIN 里设 FS，或用命令行 -F。

12. awk 里怎么把两个文件按某个 key 关联起来（模拟 JOIN）？
    答：用 NR==FNR 惯用法：awk -F, 'NR==FNR{d[$1]=$2; next} {print $0, d[$3]}' dept.csv users.csv。原理是 NR 跨文件累计、FNR 每文件重置，所以 NR==FNR 只在读第一个文件时为真；第一阶段建映射并用 next 跳过后续规则，第二阶段查表。反连接就是 !($3 in d) 只打印找不到映射的行。

13. awk 统计一组数据的「分组计数」标准写法是什么？为什么输出要放 END？
    答：awk '{cnt[$1]++} END{for (k in cnt) print k, cnt[k]}' file。放 END 是因为关联数组要等所有记录读完后才完整，中途遍历只能看到部分结果。输出顺序不稳定，要稳定就管道 sort（mawk 没有 PROCINFO["sorted_in"]）。

14. awk 里数值和字符串是怎么比较的？10 和 9 谁大？
    答：规则分三种情况。来自输入的字段、来自 -v 的赋值，如果内容整体是一个合法数字，就带 strnum 属性——按数值比较（所以本机实测字段 "10" > "9" 为真）。普通字符串变量按字典序比较（"10" < "9"）。用拼接把它变成纯字符串（$1""）也会退回字典序。要强制数值比较用 $n+0。

15. awk 处理中文/UTF-8 有什么坑？为什么 mawk 下 length("张三") 等于 6？
    答：Ubuntu 默认的 mawk 是字节导向实现，length/substr/index/split(s,a,"") 全部按字节算，且不受 locale 影响（本机实测：默认 locale、LC_ALL=C、LC_ALL=C.UTF-8 三种情况下 length("张三") 都是 6 = 2 字符 × 3 字节）。后果是 substr($0,1,1) 只能切出第一个字节 0xe5，打印出来是乱码。gawk 在 UTF-8 locale 下按字符算，同一数据 length 是 2。要按字符处理中文，用 cut -c、bash 参数扩展或 Python。

16. awk 适合处理什么规模的数据？它的性能瓶颈在哪？
    答：单机文本处理、几百万行级别非常合适（本机实测：200 万行 / 14 MB，纯行数 0.046s、引用 $1 求和 0.203s、正则计数 0.074s）。主要瓶颈有三个：字段切分（引用 $n 会让耗时涨约 4 倍）、关联数组的内存占用（键数量决定内存，几十 GB 日志别把上千万键憋在主内存里）、以及字符串拼接（mawk 上是 O(n²)，本机实测拼接次数 10 倍、耗时 211 倍，所以不要用 s=s$0 攒大量文本）。

17. awk 的 system() 有什么安全问题？
    答：system() 把字符串交给 shell（/bin/sh -c）执行，外部可控的输入拼进去就能注入命令。本机实测：awk -v user='alice; whoami' 'BEGIN{system("echo 用户: " user)}' 会真的执行 whoami 并输出 root。此外 system() 每次 fork+exec，比内置运算慢约四个数量级（实测 50 次 system ≈ 26ms，5 万次内置运算 ≈ 3ms）。原则：能用 print 就别用 system()，必须用时对外部输入做白名单校验。

18. 写出一个「既能在 Ubuntu 的 mawk 跑、也能在 CentOS 的 gawk 跑」的 awk 脚本，要注意什么？
    答：1) 只用 POSIX 语法：不用 gensub/asort/IGNORECASE/FPAT/PROCINFO/@include/switch/**/--csv/-i inplace/位运算函数；2) 需要排序就管道 sort；3) 大小写不敏感用 tolower()；4) 不依赖数组遍历顺序；5) 处理中文别用 substr 按字符截断；6) 如果非要用 gawk 扩展，脚本里显式调用 gawk 并在注释里写「Ubuntu 需 sudo apt install gawk」，同时把 awk 实现的版本判定写进启动检查（awk --version）。

19. awk 脚本怎么做成可执行命令？shebang 要注意什么？
    答：第一行写 #!/usr/bin/awk -f（必须是解释器的绝对路径，且要带 -f 表示「把脚本文件当程序」），chmod +x 后即可 ./script.awk file。不能写 #!/usr/bin/env awk——shebang 只接受一个参数，env 形式会让 -f 丢失。另外 /usr/bin/awk 通常是 alternatives 软链，Ubuntu 指向 mawk、RHEL 指向 gawk，行为可能随发行版变化，要锁定实现就写 gawk 的绝对路径。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 分析日志先摸清字段位置（$1 是什么、$9 是什么），再写统计
2. 分组计数用关联数组 + END 输出，这是 awk 最高频的范式
3. CSV 处理记得 -F, 和 NR>1 跳过表头
4. 复杂统计写成 .awk 脚本文件，别堆在命令行里
5. awk 做不了的（跨行、复杂逻辑）才考虑 Python，能 awk 就 awk
6. 需要稳定排序输出时 pipe 给 sort，或 gawk 用 PROCINFO["sorted_in"]
7. 提取尾部字段用 $NF / $(NF-1)，别去数一共几列
8. **写脚本前先跑 `awk --version` 确认方言**：Ubuntu 默认 mawk、RHEL 默认 gawk；把这句话写进脚本注释，能省掉一半的「在我机器上是好的」
9. **只用 POSIX 语法就能覆盖 95% 的日常需求**：分组计数、字段提取、条件过滤、求和求平均，都不需要 gawk 扩展
10. 需要排序输出时一律管道 `sort`（而不是 PROCINFO["sorted_in"]），这样 mawk/gawk 行为一致、还能调 -k/-n/-r
11. 大小写不敏感匹配统一用 `tolower()`，别用 IGNORECASE（mawk 静默失效）
12. 多文件关联用 `NR==FNR` 惯用法，它是最通用、最可移植的 awk JOIN 写法
13. 需要改文件内容时别指望 `awk -i inplace`（mawk 没有）：输出到临时文件再 `mv` 覆盖，或交给 GNU `sed -i.bak`
14. 处理含中文的数据时，避免用 `substr` 按长度截断（mawk 按字节），优先 `cut -c` / bash 参数扩展 / Python
15. **不要用 `s = s $0` 攒大量文本**（mawk 上是 O(n²)），要缓存就用数组 + END 输出，或者干脆交给管道流式处理
16. 脚本里别调 `system()`：既有命令注入风险（外部输入可追加命令），又比内置运算慢约 4 个数量级
17. 把 awk 程序写进 `.awk` 文件并用 `-f` 加载（可注释、可复用、可版本管理）；要共享函数就用多个 `-f`（`@include` 是 gawk 专有）
18. 大文件先过滤再聚合：`awk '/条件/' big | awk '...'` 的两段式比一次性在 awk 里憋住所有 key 更省内存

### 踩坑记录

```text
坑 1：字段编号搞错，统计结果全错
结论：本以为是 $4 是级别，结果统计出来牛头不对马嘴。
原因：多空格/分隔符没摸清，字段错位。
解法：先 awk '{print NR, NF, $1, $2, $3...}' 看清每列是什么，再写统计。

坑 2：CSV 里字段本身含分隔符导致错位
结论：-F, 切分含逗号的字段（如 "a,b"）被拆成两列。
原因：awk 不解析 CSV 的引号转义，只按字符切。
解法：简单 CSV 用 awk，复杂 CSV 用 csvkit 或 Python 的 csv 模块。

坑 3：数值字段当字符串比较，排序/判断出错
结论：awk 'NR>1 && $4>15000' 对 10000 和 20000 比较结果反了。
原因：字段默认是字符串，字符串比较按字典序 "10000" > "15000" 为假但 "20000" > "15000" 为真，边界值会错。
解法：显式数值化 $4+0 > 15000，或确保字段无前导字符。

坑 4：END 块里数组遍历顺序不确定
结论：for (k in arr) 输出的顺序每次可能不同。
原因：awk 关联数组不保证遍历顺序，和插入顺序无关。
解法：需要排序输出时，把结果 pipe 给 sort，或 gawk 用 PROCINFO["sorted_in"]。

坑 5：awk 里单引号转义地狱
结论：awk '{print "'"'"'"}' 这类嵌套引号写错。
原因：shell 单引号内不能直接放单引号。
解法：awk 脚本存成文件 awk -f script.awk，或改用双引号包裹并用反斜杠转义。

坑 6：FS 设成单个空格却想按「字面空格」切分
结论：以为 -F' ' 是按单个空格切，结果连续多个空格被当成一个分隔符。
原因：awk 里 FS 为单个空格（含默认值）是「连续空白」特例，等价于按空白切分。
解法：要按字面单个空格切须写 -F'[ ]'；要按「一个或多个空格」切写 -F'[ ]+'。

坑 7：忘了 int() 是截断取整，四舍五入结果不符预期
结论：awk 'BEGIN{print int(2.6)}' 输出 2，以为会得到 3。
原因：awk 的 int() 是向下截断，不是四舍五入。
解法：四舍五入用 int(x+0.5)，或 printf "%.0f\n" x（printf 才按四舍五入格式化）。

坑 8：抄来的 awk 脚本一跑就报 function gensub never defined
结论：网上教程里的 gensub(/re/, "\\1", "g", s) 在本机直接报错退出，脚本根本跑不起来。
原因：gensub 是 gawk 专有函数；Ubuntu/Debian 默认的 awk 是 mawk 1.3.4（本机实测 awk --version 输出 mawk 1.3.4 20240123），gawk 根本没装。
解法：1) 不需要分组捕获就用 sub/gsub；2) 需要分组用 match() + RSTART/RLENGTH + substr；3) 实在要用 gawk，sudo apt install gawk 后把命令里的 awk 改成 gawk（别依赖 awk 这个名字）。同类还有 asort/asorti/strtonum/and/or/xor，报错格式都是 function xxx never defined。

坑 9：IGNORECASE=1 写了，匹配还是区分大小写（而且没有报错）
结论：echo 'ABC' | awk 'BEGIN{IGNORECASE=1} /abc/{print "matched"}' 完全没有输出，退出码还是 0。
原因：IGNORECASE 是 gawk 专有变量，mawk 只是把它当普通变量赋值，不会改变正则匹配行为——属于「静默失效」，比报错更难发现。
解法：改成 echo 'ABC' | awk '{if (tolower($0) ~ /abc/) print "matched"}'（本机实测输出 matched）。凡是看到 IGNORECASE，一律换成 tolower()。

坑 10：FPAT 设了却不生效，字段还是按空白切
结论：echo 'x' | awk 'BEGIN{FPAT="[0-9]+"} {print NF}' 输出 1，而不是期望的 0（按数字串切应该切不出字段）。
原因：FPAT（按字段内容切分）是 gawk 扩展，mawk 静默忽略它，仍然用 FS 切。
解法：改用 while (match(s, /[0-9]+/)) 循环，每次用 substr(s, RSTART, RLENGTH) 取出一个匹配并推进 s；本机实测对 'a1b22c333' 依次输出 1、22、333。

坑 11：awk -i inplace 改文件报 not an option
结论：awk -i inplace '{print "X"$0}' ip.txt 报 awk: not an option: -i，压根没执行。
原因：-i inplace 是 gawk 5.1+ 的选项，mawk 不支持。
解法：写成 awk '...' f > f.tmp && mv f.tmp f（mv 原子替换，比直接重定向回原文件安全）；纯替换类任务用 GNU sed -i 或 sed -i.bak。

坑 12：中文被 substr 切成了乱码，length 数出来是字数的 3 倍
结论：对内容「张三」的文件执行 awk '{print length($0)}' 得到 6（期望 2）；awk '{print substr($0,1,1)}' 输出的字节是 e5（单字节），终端里显示为乱码。
原因：mawk 是字节导向实现，length/substr/index/split 全部按字节算，且不看 locale——本机实测默认 locale、LC_ALL=C、LC_ALL=C.UTF-8 三种情况下 length 都是 6。gawk 在 UTF-8 locale 下按字符算（同一份数据是 2）。
解法：不要用 awk 的 substr 按长度截断中文，改用 cut -c、bash 的 ${var:0:n} 或 Python；确需 awk 就先装 gawk 且用 gawk 而不是 awk，并设 LC_ALL=C.UTF-8。

坑 13：用 s = s $0 攒几十万行文本，脚本慢到跑不完
结论：同一个拼接循环，2 万次 0.005s、6 万次 0.044s、20 万次 1.057s——数据量只涨 10 倍，耗时涨了约 211 倍。
原因：mawk 每次字符串拼接都会重新分配并整体拷贝，复杂度是 O(n²)。
解法：不要在 awk 里攒大字符串。要缓存行就用数组（a[NR]=$0 在 END 里遍历），要统计就直接交给 sort | uniq -c 流式处理。

坑 14：在主体动作里改 FS，当前这行却没被切开
结论：printf 'a:b\nc:d\n' | awk 'NR==1{FS=":"} {print NR, NF, $1}' 第 1 行输出 NF=1、$1=a:b（没切），第 2 行才按 ":" 切成 NF=2。
原因：awk 的字段是惰性切分的——记录读入时只准备 $0，直到第一次引用 $n / NF 才按「当时的 FS」切。第 1 行的字段在第 1 行动作执行前已经按旧 FS 切好（引用 NF 时用的是旧值）。
解法：FS 一律在 BEGIN 里设，或直接用命令行 -F:；不要在主体里改 FS 后指望当前行重新切。同理，对 $0 做替换后要 $0=$0 才会重切字段。

坑 15：把外部输入拼进 system()，被人追加了命令
结论：awk -v user='alice; whoami' 'BEGIN{system("echo 用户: " user)}' 先打印「用户: alice」，紧接着打印「root」——whoami 被真的执行了。
原因：system() 把字符串交给 /bin/sh -c 执行，输入里的 ; | $() 反引号都是命令分隔符。另外 system() 每次 fork+exec，比内置运算慢约 4 个数量级（实测 50 次 system 约 26ms，5 万次内置运算约 3ms）。
解法：能用 print/printf 表达就别用 system()；确需执行命令时对外部输入做白名单校验（只允许 [A-Za-z0-9_.-]），绝不直接拼接。

坑 16：match(s, re, arr) 第三参数让脚本报语法错误
结论：awk 'BEGIN{if (match("abc",/b/,m)) print m[1]}' 报 awk: line 1: syntax error at or near ,。
原因：match() 的第三参数（把捕获分组存进数组）是 gawk 扩展，mawk 不支持。同类语法错误还有 switch/case（syntax error at or near {）、2**10 幂运算（syntax error at or near *）、@include（unexpected character '@'）。
解法：用 RSTART/RLENGTH + substr 手工抠分组；switch 改成 if/else if 链；** 改成 ^；@include 改成多个 -f 拼接。

坑 17：printf 的参数给少了，mawk 直接报错中断
结论：awk 'BEGIN{printf "%s|%s\n", "only"}' 报 awk: run time error: not enough arguments passed to printf("%s|%s\n") 并终止，输出只有半行 only|。
原因：mawk 对 printf 参数不足是致命错误；gawk 只打印警告并继续。写跨发行版脚本时按最严格的实现来。
解法：核对格式符个数与实参个数；拼接输出时宁可分多次 printf，别一次堆一长串格式符。

坑 18：以为默认分隔符是「一个空格」，结果和 cut -d' ' 结果对不上
结论：对同一份 'a   b\tc' 的数据，awk '{print NF}' 得到 3，而 cut -d' ' -f1,2,3 得到的是按字面单空格切的 3 段（内容完全不同）；用 awk -F'[ ]' 才得到 4 个字段。
原因：awk 的 FS 为单个空格（含默认值）时是特例——表示「连续空白（空格/制表符/换行）都算一个分隔符」，和 cut 的「字面一个空格」语义不同。另外 -F' ' 也是这个特例，只有 -F'[ ]' 才是字面单空格。
解法：分析空白分隔的日志用默认 FS（或 -F'[ \t]+'）；真要按字面单空格切就用 -F'[ ]'；从 cut 迁移到 awk 时注意这个语义差。
```

## 附：跨发行版速查（Ubuntu mawk vs RHEL/CentOS gawk）

这一节把本篇所有方言差异收拢成两张表，方便放到脚本注释或团队 wiki 里。

### 默认工具的差别

| 项目 | Debian / Ubuntu | Red Hat / CentOS / RHEL / Fedora |
|---|---|---|
| `/usr/bin/awk` 指向 | mawk（`mawk` 包，默认装） | gawk（`gawk` 包，默认装） |
| 本机/参照版本 | mawk 1.3.4 20240123（本机实测） | GNU Awk 5.x（以目标机 `awk --version` 为准） |
| 安装另一种 | `sudo apt install gawk` | `sudo dnf install mawk`（一般没必要） |
| 判定命令 | `awk --version` / `awk 'BEGIN{print (PROCINFO["version"]!=""?"gawk":"非 gawk")}'` | 同上 |

```text
# 两条命令，在任何发行版上都能判定（本机 Ubuntu 实测输出见括号）
$ awk --version | head -1
mawk 1.3.4 20240123

$ awk 'BEGIN{print (PROCINFO["version"] != "" ? "gawk" : "非 gawk（mawk/busybox/BSD）")}'
非 gawk（mawk/busybox/BSD）
```

### 特性可用性对照（本篇重点）

| 特性 | Ubuntu（mawk） | RHEL/CentOS（gawk） | 跨发行版建议 |
|---|---|---|---|
| POSIX 核心（字段/模式/BEGIN-END/数组/sub/gsub/sprintf/getline/printf） | 可用 | 可用 | 直接写，是跨平台的基本盘 |
| `nextfile`、`systime()`、`strftime()` | 可用（mawk 1.3.4） | 可用 | 可用，但仍建议判定后使用 |
| `gensub()` | 不可用（报 never defined） | 可用 | 用 sub/gsub 或 match+substr 替代 |
| `asort()` / `asorti()` | 不可用 | 可用 | 管道 `sort` |
| `IGNORECASE` | 静默失效 | 可用 | `tolower()` |
| `FPAT` | 静默失效 | 可用 | `while(match())` |
| `PROCINFO["sorted_in"]` | 静默失效 | 可用 | 管道 `sort` |
| `BEGINFILE` / `ENDFILE` | 静默失效 | 可用 | 主体里判 `FNR==1` |
| `ARGIND` | 静默失效 | 可用 | 用 `ARGV[]` / `FILENAME` |
| `RT` | 静默失效 | 可用 | 自己从 `$0` 推 |
| `-i inplace` | 报 `not an option` | gawk 5.1+ 可用 | 临时文件 + `mv`，或 `sed -i` |
| `--csv` | 报 `not an option` | gawk 5.3+ 可用 | `-F,`；复杂 CSV 交 Python/csvkit |
| `match(s,re,arr)` | 报 syntax error | 可用 | `RSTART/RLENGTH` + `substr` |
| `@include` / `@load` | 报 unexpected character '@' | 可用 | 多个 `-f` 拼接 |
| `switch/case`、`**`、位运算函数 | 报 syntax error / never defined | 可用 | `if/else if`、`^`、手写或换 Python |
| 字符串语义 | 按字节（length/substr/index） | UTF-8 locale 下按字符 | 中文处理别用 awk substr |
| 字符串拼接复杂度 | O(n²)（实测：10 倍数据 → 211 倍耗时） | 摊还 O(1) | 别用 `s=s$0` 攒文本 |

```text
# 依赖：仅 POSIX awk（Ubuntu 默认 mawk 1.3.4 / RHEL 默认 gawk 均可运行）

#   RHEL/CentOS：默认 awk 即 gawk，可直接用 gawk 命令
```

```text
红帽系差异总结（本文相关）：
```

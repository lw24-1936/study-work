## 概述

脚本里「进程」层面的操作：子 shell（括号里独立环境跑一段）、命令替换（$( ) 捕获命令输出）、后台任务（& 并行执行）、作业控制（jobs/fg/bg）、信号处理（trap 捕获信号）。这些是脚本「并行」「异步」「优雅退出」的基础——写定时任务、并行处理、带清理逻辑的脚本都离不开。

```text
五个进程机制：
1. 子 shell ( ... ) —— 括号里独立子进程执行，变量改动不外泄
2. 命令替换 $( ... ) —— 捕获命令输出赋给变量
3. 后台任务 cmd & —— 并行执行，$! 拿 PID，wait 等待
4. 作业控制 jobs / fg / bg —— 管理前后台任务
5. trap —— 捕获信号执行清理，实现优雅退出
```

## 核心概念

脚本里的进程操作围绕五个机制展开：子 shell、命令替换、后台任务、作业控制、信号处理。下面逐一展开。

### 子 shell

用括号 `( ... )` 包起来的命令在「子 shell」里执行——独立的子进程，有自己的变量环境。子 shell 里对变量的修改不影响父 shell（反过来父 shell 的变量子 shell 能读到）。所以「想在隔离环境跑一段、又不污染当前环境」就用子 shell。管道里的每一段、命令替换也都是子 shell。

```shell
x=outer
( x=inner; echo "子shell内 x=$x" )
echo "子shell外 x=$x"
```

```text
# 实测
子shell内 x=inner
子shell外 x=outer
# 子 shell 里的赋值不影响外部——这就是隔离
```

子 shell 的「是什么→为什么→怎么用→边界」：它是 fork 出的子进程，环境是父 shell 的副本。为什么要它——隔离变量改动、切换工作目录不污染主流程、把一组命令当原子单元。边界是「变量改不动父 shell、但文件/进程等系统资源是共享的」。

典型用法：临时切目录、隔离环境变量、把整段逻辑放进子进程。

```shell
# 1. 临时切目录不影响父 shell
pwd
(cd /tmp && pwd)
pwd                 # 还是原目录

# 2. 隔离环境变量
PATH=/custom/bin
(PATH=/tmp/bin; echo "子shell PATH=$PATH")
echo "父shell PATH=$PATH"   # 不受影响

# 3. 整段后台跑，不阻塞
( echo 开始; sleep 1; echo 结束 ) &
echo "父 shell 继续跑"
wait
```

```text
# 示例输出
/root
/tmp
/root
子shell PATH=/tmp/bin
父shell PATH=/custom/bin
父 shell 继续跑
开始
结束
```

要点：子 shell 继承变量副本、继承 fd、共享文件系统；`( cmd & )` 让整段进后台；管道 `a | b` 的每一段都是子 shell，这是「管道里改变量不生效」的根源。

### 命令替换

命令替换 `$(命令)` 把命令的输出捕获成字符串，赋给变量或嵌入命令。`$( )` 是推荐写法（老式反引号 `` ` ` `` 易和引号混淆、嵌套难）。典型场景：`now=$(date)`、`result=$(计算)`、`count=$(grep -c ...)`。注意命令替换会去掉输出末尾的换行符。

```shell
echo "当前时间: $(date +%H:%M:%S)  当前用户: $(whoami)"
echo "进程数: $(ps -e --no-headers | wc -l)"
```

```text
# 实测
当前时间: 22:21:51  当前用户: root
进程数: 404
```

命令替换的「是什么→为什么→怎么用→边界」：它在子 shell 里执行命令、把 stdout 捕获成字符串返回。为什么用它——把命令结果接进变量、拼进别的命令参数。边界是「只捕获 stdout、丢弃 stderr、去末尾换行、大输出会整块吃进内存」。

```shell
# 1. 只捕获 stdout，stderr 仍在终端
out=$(ls /root 2>/dev/null)          # stderr 丢弃
out_all=$(ls /root 2>&1)             # stderr 也并进变量

# 2. 捕获多行结果
lines=$(seq 3)
echo "捕获结果: $lines"              # 多行被压成一行（换行变空格）
echo "--- 用引号保留换行 ---"
echo "$lines"

# 3. 嵌套：命令替换里再嵌命令替换
echo "日期: $(date +%F) 主机: $(hostname)"
```

```text
# 示例输出
捕获结果: 1 2 3
--- 用引号保留换行 ---
1
2
3
日期: 2026-08-19 主机: <主机名>
```

要点：`$( )` 可嵌套、引号好处理，反引号难嵌套；要保留末尾换行用 readarray 或进程替换；要保留内部换行就 `echo "$var"` 加引号。

### 后台任务

命令后加 `&` 让它后台并行执行，`$!` 拿后台进程 PID，`wait` 等待后台任务完成。后台任务让脚本能「并行跑多个耗时任务」——比如同时向多台机器部署、并行下载多个文件。`wait` 等所有后台任务完成再继续，是并行后汇聚的关键。

```bash
sleep 2 &
pid=$!
echo "后台 PID: $pid"
wait $pid
echo "后台任务完成"
```

```text
# 实测
后台 PID: 1017207
后台任务完成
```

后台任务的「是什么→为什么→怎么用→边界」：`&` 让命令 fork 后立即返回，shell 不阻塞。为什么要它——把串行的 N 个耗时任务改成并行，总耗时从「累加」变「取最大」。边界是「脚本退出时后台任务可能收到 SIGHUP 被杀」「并行任务写共享资源要加锁」。

```bash
# 并行跑 3 个任务，记录每个 PID，逐个 wait 并检查退出码
pids=()
for i in 1 2 3; do
    ( sleep $((i)); echo "任务 $i 完成" ) &
    pids+=("$!")
done

# 逐个等待并检查
for pid in "${pids[@]}"; do
    if wait "$pid"; then
        echo "PID $pid 成功"
    else
        echo "PID $pid 失败"
    fi
done
echo "全部后台任务结束"
```

```text
# 示例输出
任务 1 完成
PID 1052679 成功
任务 2 完成
PID 1052680 成功
任务 3 完成
PID 1052681 成功
全部后台任务结束
```

要点：`$!` 只记「最近一个」后台 PID，多个后台任务要自己收进数组；`wait` 无参等所有后台任务、`wait $pid` 等指定；逐个 wait 能拿到每个的退出码，比一次 wait 全等更可靠。

### 作业控制

作业控制管理前后台任务：`jobs` 列出当前 shell 的作业、`fg %n` 把后台作业调回前台、`bg %n` 让暂停的作业到后台跑、Ctrl+Z 暂停前台任务。交互式 shell 里用得多，脚本里主要用 `&` + `wait`。理解作业控制能解释「为什么 Ctrl+C 只能中断前台任务」。

```text
作业控制命令：
1. jobs —— 列出当前 shell 的所有作业（带编号 %1 %2 ...）
2. fg %1 —— 把 1 号作业调到前台
3. bg %1 —— 让暂停的 1 号作业在后台继续
4. Ctrl+Z —— 暂停前台任务，Ctrl+C —— 中断前台任务
```

作业控制只在「交互式 shell」里有意义，脚本里因为不是交互式、默认关闭作业控制。它的机制：一个终端会话是一个「进程组」，前后台是「哪个进程组占用终端」的切换。

```shell
# 交互式 shell 里的典型操作序列（演示，非脚本）
sleep 100 &        # 后台作业，jobs 显示 [1] PID
jobs               # 列出：[1]+ Running sleep 100 &
fg %1              # 调回前台（此时 Ctrl+Z 可暂停）
bg %1              # 暂停的作业继续后台跑
kill %1            # 按作业号杀掉
```

```text
要点：
- 作业号 %n 是 shell 内部的编号，和 PID 是两回事；jobs -l 能看到 PID
- Ctrl+Z 发 SIGTSTP 暂停，Ctrl+C 发 SIGINT 中断，只作用于前台进程组
- 脚本里一般不用 jobs/fg/bg，直接 & + $! + wait 更可控
```

### 信号处理 trap

trap 捕获信号并执行指定命令，实现「优雅退出」——脚本收到 SIGINT（Ctrl+C）、SIGTERM（kill 默认信号）时，先清理临时文件、释放资源，再退出。最常用的是 `trap '清理逻辑' EXIT`（脚本退出时自动执行）和 `trap '...' INT TERM`（收到中断/终止信号时执行）。写临时文件的脚本一定要 trap 清理，否则异常退出留一堆垃圾文件。

```bash
trap 'echo "捕获到 EXIT 信号，执行收尾清理"' EXIT
echo "主逻辑执行"
```

```text
# 实测
主逻辑执行
捕获到 EXIT 信号，执行收尾清理
# EXIT 陷阱在脚本退出时自动触发，无论正常还是异常退出
```

trap 的「是什么→为什么→怎么用→边界」：它给信号注册一个处理函数。为什么要它——脚本收到 Ctrl+C/kill 时默认「直接死」，临时文件、锁、数据库连接都没清理；trap 让你在退出前跑一段清理。边界是「EXIT 伪信号不是真信号」「trap 里单引号延迟展开、双引号立即展开」。

```bash
# 完整示例：临时文件 + 锁的清理
tmpfile=$(mktemp)
lockfile=/tmp/app.lock

cleanup() {
    echo "清理中..."
    rm -f "$tmpfile" "$lockfile"
    echo "清理完成"
}
trap cleanup EXIT INT TERM

# 模拟工作
echo "PID $$ 开始工作"
echo "data" > "$tmpfile"
touch "$lockfile"
sleep 1
# 收到 Ctrl+C 或 kill 时，cleanup 会先跑再退出
```

```text
# 示例输出（正常结束）
PID 1052679 开始工作
清理中...
清理完成
```

```shell
# 查看/清空 trap
trap -p            # 列出当前所有 trap
trap - EXIT        # 清除 EXIT 陷阱
trap -l            # 列出所有信号名
```

要点：trap 支持多信号并列 `trap cmd INT TERM HUP`；`trap '...' EXIT` 覆盖了「任何退出路径」；EXIT 陷阱里再 exit 不会递归触发；信号处理函数执行期间同信号默认被屏蔽。

## 工作原理

子 shell 的本质是 fork 出子进程：bash 遇到 `( ... )`、管道 `|`、命令替换 `$( )` 时，fork 一个子进程执行，子进程继承父进程的变量副本（写时复制），所以子 shell 改变量不影响父 shell。后台任务 `&` 也是 fork + 异步执行。trap 依赖信号机制——bash 收到信号后先执行 trap 指定的命令，再决定退出还是继续。

```text
子 shell 产生的三种场景：
1. ( ... ) 圆括号 —— 显式子 shell
2. 管道 a | b —— 每段都跑在子 shell（所以管道里改变量不生效）
3. 命令替换 $( ... ) —— 在子 shell 里执行

后台任务 cmd & —— bash fork 子进程后立即返回，不阻塞，$! 记下 PID
trap —— bash 注册信号处理器，收到信号先跑 trap 命令再决定退出/继续
```

深入一层，几个关键机制的底层：

```text
1. fork：子 shell / 管道 / 命令替换 / 后台任务都靠 fork() 创建子进程，父子共享「写时复制」内存
2. 写时复制（COW）：子 shell 读父变量零拷贝；一旦赋值，才复制那一页——所以隔离不是「完全独立」
3. 进程组/会话：后台任务、作业控制靠进程组区分前后台；nohup 靠忽略 SIGHUP 让任务脱离会话
4. 信号：trap 注册的信号处理器是「用户态回调」，bash 收到信号后挂起当前命令、跑 trap 逻辑
```

```shell
# 验证「管道每段都是子 shell」：管道里的 $BASHPID 和外面不同
echo "外层 PID: $BASHPID"
echo "管道内 PID: $(echo $BASHPID) | $$" 2>/dev/null
echo hello | { read x; echo "管道子shell PID: $BASHPID"; }
```

```text
# 示例输出
外层 PID: 1052679
hello | 1052679
管道子shell PID: 1052682
# 管道里的 BASHPID（1052682）和外层（1052679）不同——每段是独立子进程
```

## 常用命令与配置

```shell
( cmd1; cmd2 )             # 子 shell 执行一段命令
var=$(cmd)                 # 命令替换捕获输出
cmd &                      # 后台执行
echo $!                    # 后台进程 PID
wait $pid                  # 等待指定后台任务
jobs / fg %1 / bg %1       # 作业控制
trap 'cmd' EXIT INT TERM   # 捕获信号执行清理
trap -p                    # 列出当前所有 trap
disown                     # 让后台任务脱离当前 shell
nohup cmd &                # 忽略 SIGHUP 的后台执行
```

```text
补充命令：
- wait           无参数等所有后台任务；wait $pid 等指定；wait -n 等任意一个完成
- disown %1      把作业从作业表移除，shell 退出时不再给它发 SIGHUP
- setsid cmd     让命令脱离当前会话（新会话 + 新进程组）
- $BASHPID       当前 bash 进程的真实 PID（$$ 在子 shell 里保持不变）
```

## 配置文件解析

子 shell 和后台任务都继承当前 shell 的环境，但「非交互式脚本」不会自动读 bash 启动文件——脚本里的变量、PATH、别名要自己在脚本内定义，别指望登录时配好的环境。

```text
bash 启动文件（进程/子 shell 相关）：
~/.bashrc          交互式 shell 每次启动都读，放别名/函数/PATH
~/.bash_profile    登录 shell 读一次，通常 source ~/.bashrc
/etc/profile       系统级登录 shell 配置（所有用户）
/etc/bash.bashrc   系统级交互式 shell 配置（Debian/Ubuntu）

注意：
1. 脚本 #!/bin/bash 启动的是非交互式 shell，不读 ~/.bashrc —— 靠它配的别名在脚本里失效
2. 子 shell ( ... ) 继承父 shell 的环境变量，但继承的是副本，改动不外泄
3. 后台任务 & 继承当前 shell 的变量，但脚本退出时可能收到 SIGHUP 被终止
```

配置对进程操作的影响，具体到三个例子：

```shell
# 1. 脚本里的别名不生效（非交互式 shell 不读 ~/.bashrc）
cat > /tmp/test_alias.sh <<'EOF'
#!/bin/bash
alias ll='ls -l'
ll
EOF
bash /tmp/test_alias.sh          # 会报 ll: 未找到命令

# 2. 脚本要独立环境：自己定义 PATH，别依赖登录环境
#!/usr/bin/env bash
export PATH=/usr/local/bin:/usr/bin:/bin
echo "脚本内 PATH=$PATH"
```

```text
要点：
- 非交互式 shell 不读 ~/.bashrc，除非脚本里显式 source ~/.bashrc（不推荐，破坏可移植性）
- 子 shell 继承的是「已 export」的变量；未 export 的普通变量在 ( ... ) 里也能读到（bash 继承全部），但改动不外泄
- 后台任务继承变量副本，但环境变量改动（export）会在 fork 时一起复制过去
```

## 应用场景实战

### 场景一：并行向多台服务器部署

```bash
#!/usr/bin/env bash
# 并行部署到多台机器，全部完成后汇总
servers=(web1 web2 web3)
for host in "${servers[@]}"; do
    ssh "$host" 'systemctl restart nginx' &
    pids+=("$!")
done
# 等所有后台任务完成
for pid in "${pids[@]}"; do
    wait "$pid" || echo "部署失败 PID=$pid"
done
echo "全部部署完成"
```

### 场景二：带清理逻辑的临时文件脚本

```bash
#!/usr/bin/env bash
tmpfile=$(mktemp)
# 无论脚本怎么退出，都清理临时文件
trap 'rm -f "$tmpfile"; echo "已清理临时文件"' EXIT

# 处理逻辑...
echo "生成的数据" > "$tmpfile"
cat "$tmpfile"
```

### 场景三：用信号量控制并发数的并行下载

```bash
#!/usr/bin/env bash
# 最多同时跑 2 个下载任务，其余排队
max_jobs=2
active=0

urls=("url1" "url2" "url3" "url4" "url5")

for url in "${urls[@]}"; do
    # 达到并发上限就等一个任务完成
    while (( active >= max_jobs )); do
        wait -n      # 等任意一个后台任务完成
        ((active--))
    done
    (
        echo "下载 $url 开始"
        sleep 1      # 模拟下载耗时
        echo "下载 $url 完成"
    ) &
    ((active++))
done
wait                 # 等剩余任务全部结束
echo "全部下载完成"
```

```text
这个场景用「计数器 + wait -n」实现信号量：active 记录在跑数量，达到 max_jobs 就 wait -n
等任意一个完成再放行下一个。这是并行任务控制并发的通用模板，避免一次拉起几十个后台任务打爆资源。
```

## 性能与调优

```text
1. 并行任务用 & 替代串行，总耗时从「累加」变「取最大」，但别一次拉太多（受 CPU/网络/文件描述符限制）
2. 命令替换启动子进程有开销，循环里频繁 $( ) 慢——把能一次算完的提到循环外
3. 管道每段一个子进程，长管道（a|b|c|d）进程多，必要时合并
4. 后台任务数量用「信号量」控制并发，避免打爆资源
5. wait 逐个等，可提前发现单个任务失败，别只等最后一个
6. 命令替换输出很大时（如整文件），用 readarray -t lines < <(cmd) 比 var=$(cmd) 再拆更省内存
```

## 安全与权限

```text
1. 命令替换 $( ) 里拼接用户输入要加引号，防命令注入（$(rm -rf ...) 之类的注入）
2. 后台任务并行写共享文件要加锁，避免并行写坏文件
3. trap 清理临时文件用变量/绝对路径，别在 trap 里执行不可信命令
4. nohup/disown 让任务脱离终端继续跑，输出要重定向到文件，否则占住终端
5. 命令替换捕获外部命令输出赋变量时，别直接把内容 eval/执行——内容是数据不是代码
6. 后台任务用 root 跑时注意权限，别把特权操作扔后台无人监管
```

## 故障排查

```shell
# 后台任务「莫名消失」：查是不是脚本退出时被 SIGHUP 杀了
jobs -l
# 脚本退出后后台任务没跑完：看有没有 wait / nohup
ps -ef | grep <任务名>
# trap 没生效：确认 trap 写在脚本靠前、信号名正确
trap -p
# 管道里变量改了不生效：确认是不是在子 shell 里改的
echo $var
```

```text
排错思路：
1. 后台任务没跑完就没了 → 脚本退出发了 SIGHUP；加 wait 或 nohup/setsid
2. 变量在管道里改了不生效 → 管道每段是子 shell，改 done < <(cmd) 进程替换
3. trap 不触发 → 信号名写对没（EXIT/INT/TERM）；trap 是不是在脚本很靠后才定义
4. 命令替换拿到空值 → 命令是否只输出了 stderr（stdout 为空）；加 2>&1 试试
5. 并行任务互相覆盖文件 → 检查有没有写共享文件没加锁；给每任务独立输出文件
6. wait 没等到任务 → 确认 wait 的 PID 是 $! 记录的，且后台任务真的启动成功
```

## 常见问题

```text
Q1: 子 shell 里 cd 为什么不影响父 shell？
A: 子 shell 是独立子进程，cd 只改子进程工作目录，父 shell 不变。

Q2: 管道里赋值为什么丢失？
A: a | b 每段都是子 shell，赋值发生在子进程里，父 shell 读不到。

Q3: 后台任务脚本退出后也被杀？
A: 脚本退出时后台子进程收到 SIGHUP，用 wait 等待或 nohup/disown 脱离。

Q4: trap EXIT 什么时候触发？
A: 脚本任何路径退出（正常/异常/收到信号）都触发，适合放清理逻辑。

Q5: 命令替换的输出为什么少了换行？
A: $( ) 会去掉输出末尾的所有换行，需要保留时用进程替换或 readarray。

Q6: $! 和 $$ 和 $BASHPID 有什么区别？
A: $! 是最近一个后台任务 PID；$$ 是当前 shell 的 PID（子 shell 里不变）；$BASHPID 是当前 bash 进程真实 PID（子 shell 里会变）。

Q7: 怎么并行跑任务又限制并发数？
A: 用计数器 + wait -n 实现信号量，或 xargs -P N 并行执行。

Q8: nohup 和 disown 有什么区别？
A: nohup 启动时就让命令忽略 SIGHUP；disown 是把已在后台的任务从作业表移除，shell 退出时不发 SIGHUP。
```

## 面试题

```text
1. 子 shell 和子进程的区别？
   答：子 shell 就是 fork 出的子进程，用 ( ) 显式创建；管道、命令替换也隐式创建子 shell。

2. 命令替换 $( ) 和反引号 `` 的区别？
   答：功能等价，$( ) 可嵌套、易读、引号处理简单，反引号难嵌套易混淆。

3. 后台任务如何拿到 PID 并等待？
   答：cmd & 后 $! 是 PID，wait $pid 等待完成。

4. trap 能捕获哪些信号？
   答：EXIT（脚本退出）、INT（Ctrl+C）、TERM（kill 默认）等，trap -l 列出全部信号。

5. 为什么管道里的变量修改不生效？
   答：管道每段跑在子 shell，变量改动隔离在子进程里。

6. 脚本退出后它的后台任务会怎样？
   答：后台任务可能收到 SIGHUP 被终止；用 wait 等待、nohup 忽略 SIGHUP、disown 移除作业表可避免。

7. 命令替换为什么丢掉末尾换行？
   答：$( ) 设计上会 strip 输出末尾所有换行，保留内部换行；要保留末尾换行用 readarray 或进程替换。

8. $$ 和 $BASHPID 的区别？什么时候用哪个？
   答：$$ 是 shell 主进程 PID、子 shell 里不变；$BASHPID 是当前 bash 进程真实 PID、子 shell 里会变——区分进程时用 $BASHPID。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 命令替换用 $( )，别用反引号（易错、难嵌套）
2. 写临时文件的脚本必须 trap 'rm -f ...' EXIT 清理
3. 并行任务用 & + $! + wait，先启动后统一 wait 汇聚
4. 要隔离变量改动用子 shell ( ... )，别在函数里改全局
5. 优雅退出 trap EXIT 放脚本靠前位置，保证任何路径退出都触发
6. 并行任务限制并发数用信号量（计数器 + wait -n），别一次全拉起来
7. 管道里要改变量就别用管道，改 done < <(cmd) 进程替换

### 踩坑记录

```text
坑 1：子 shell 里 cd 不影响父 shell
结论：(cd /tmp; ls) 执行完，父 shell 的目录没变。
原因：子 shell 的 cd 只改子进程的工作目录。
解法：要在当前 shell 改目录就别用括号，或用 cd /tmp && 命令。

坑 2：命令替换去掉了末尾换行
结论：x=$(printf "a\nb\n") 后 $x 是 "a\nb" 少了个换行。
原因：命令替换会 strip 掉输出末尾的所有换行。
解法：需要保留换行时用进程替换或 readarray，或接受这个行为。

坑 3：后台任务没 wait 就退出，任务被终止
结论：脚本退出后，它启动的后台任务也被 kill。
原因：脚本结束时 shell 退出，后台子进程收到 SIGHUP 被终止。
解法：用 wait 等后台任务完成，或 nohup/disown 脱离会话。

坑 4：trap 里用单引号导致变量当时不展开
结论：trap 'echo $PID' EXIT 打印的是退出时的 PID，不是定义时的。
原因：单引号延迟展开，trap 触发时才解析变量。
解法：要定义时展开用双引号 trap "echo $PID" EXIT，要实时值用单引号。

坑 5：wait 返回的是最后一个作业的退出码
结论：wait 多个后台任务后，$? 只反映最后一个的成败。
原因：wait 无参数返回最后一个结束作业的状态。
解法：逐个 wait "$pid" 并检查每个的退出码，别用一次 wait 判断全部。

坑 6：命令替换里 stderr 没被捕获，变量拿到空值
结论：var=$(ls /nonexist) 后 var 为空，但报错信息刷屏。
原因：$( ) 只捕获 stdout，stderr 仍走终端。
解法：需要一并捕获用 var=$(ls /nonexist 2>&1)，或 2>/dev/null 丢弃。

坑 7：在管道里给变量赋值，循环结束后变量是空的
结论：echo a | while read x; do y=$x; done; echo $y 输出空。
原因：管道让 while 循环跑在子 shell，赋值不外泄。
解法：用 while read ... done < file 或 done < <(cmd) 进程替换，让循环留在当前 shell。
```

## 概述

脚本里「进程」层面的操作：子 shell（括号里独立环境跑一段）、命令替换（$( ) 捕获命令输出）、后台任务（& 并行执行）、作业控制（jobs/fg/bg）、信号处理（trap 捕获信号）。这些是脚本「并行」「异步」「优雅退出」的基础——写定时任务、并行处理、带清理逻辑的脚本都离不开。

```text
五个进程机制：
1. 子 shell ( ... ) —— 括号里独立子进程执行，变量改动不外泄
2. 命令替换 $( ... ) —— 捕获命令输出赋给变量
3. 后台任务 cmd & —— 并行执行，$! 拿 PID，wait 等待
4. 作业控制 jobs / fg / bg —— 管理前后台任务
5. trap —— 捕获信号执行清理，实现优雅退出
```

## 核心概念

脚本里的进程操作围绕五个机制展开：子 shell、命令替换、后台任务、作业控制、信号处理。下面逐一展开。

### 子 shell

用括号 `( ... )` 包起来的命令在「子 shell」里执行——独立的子进程，有自己的变量环境。子 shell 里对变量的修改不影响父 shell（反过来父 shell 的变量子 shell 能读到）。所以「想在隔离环境跑一段、又不污染当前环境」就用子 shell。管道里的每一段、命令替换也都是子 shell。

```shell
x=outer
( x=inner; echo "子shell内 x=$x" )
echo "子shell外 x=$x"
```

```text
# 实测
子shell内 x=inner
子shell外 x=outer
# 子 shell 里的赋值不影响外部——这就是隔离
```

### 命令替换

命令替换 `$(命令)` 把命令的输出捕获成字符串，赋给变量或嵌入命令。`$( )` 是推荐写法（老式反引号 `` ` ` `` 易和引号混淆、嵌套难）。典型场景：`now=$(date)`、`result=$(计算)`、`count=$(grep -c ...)`。注意命令替换会去掉输出末尾的换行符。

```shell
echo "当前时间: $(date +%H:%M:%S)  当前用户: $(whoami)"
echo "进程数: $(ps -e --no-headers | wc -l)"
```

```text
# 实测
当前时间: 22:21:51  当前用户: root
进程数: 404
```

### 后台任务

命令后加 `&` 让它后台并行执行，`$!` 拿后台进程 PID，`wait` 等待后台任务完成。后台任务让脚本能「并行跑多个耗时任务」——比如同时向多台机器部署、并行下载多个文件。`wait` 等所有后台任务完成再继续，是并行后汇聚的关键。

```bash
sleep 2 &
pid=$!
echo "后台 PID: $pid"
wait $pid
echo "后台任务完成"
```

```text
# 实测
后台 PID: 1017207
后台任务完成
```

### 作业控制

作业控制管理前后台任务：`jobs` 列出当前 shell 的作业、`fg %n` 把后台作业调回前台、`bg %n` 让暂停的作业到后台跑、Ctrl+Z 暂停前台任务。交互式 shell 里用得多，脚本里主要用 `&` + `wait`。理解作业控制能解释「为什么 Ctrl+C 只能中断前台任务」。

```text
作业控制命令：
1. jobs —— 列出当前 shell 的所有作业（带编号 %1 %2 ...）
2. fg %1 —— 把 1 号作业调到前台
3. bg %1 —— 让暂停的 1 号作业在后台继续
4. Ctrl+Z —— 暂停前台任务，Ctrl+C —— 中断前台任务
```

### 信号处理 trap

trap 捕获信号并执行指定命令，实现「优雅退出」——脚本收到 SIGINT（Ctrl+C）、SIGTERM（kill 默认信号）时，先清理临时文件、释放资源，再退出。最常用的是 `trap '清理逻辑' EXIT`（脚本退出时自动执行）和 `trap '...' INT TERM`（收到中断/终止信号时执行）。写临时文件的脚本一定要 trap 清理，否则异常退出留一堆垃圾文件。

```bash
trap 'echo "捕获到 EXIT 信号，执行收尾清理"' EXIT
echo "主逻辑执行"
```

```text
# 实测
主逻辑执行
捕获到 EXIT 信号，执行收尾清理
# EXIT 陷阱在脚本退出时自动触发，无论正常还是异常退出
```

## 工作原理

子 shell 的本质是 fork 出子进程：bash 遇到 `( ... )`、管道 `|`、命令替换 `$( )` 时，fork 一个子进程执行，子进程继承父进程的变量副本（写时复制），所以子 shell 改变量不影响父 shell。后台任务 `&` 也是 fork + 异步执行。trap 依赖信号机制——bash 收到信号后先执行 trap 指定的命令，再决定退出还是继续。

```text
子 shell 产生的三种场景：
1. ( ... ) 圆括号 —— 显式子 shell
2. 管道 a | b —— 每段都跑在子 shell（所以管道里改变量不生效）
3. 命令替换 $( ... ) —— 在子 shell 里执行

后台任务 cmd & —— bash fork 子进程后立即返回，不阻塞，$! 记下 PID
trap —— bash 注册信号处理器，收到信号先跑 trap 命令再决定退出/继续
```

## 常用命令与配置

```shell
( cmd1; cmd2 )             # 子 shell 执行一段命令
var=$(cmd)                 # 命令替换捕获输出
cmd &                      # 后台执行
echo $!                    # 后台进程 PID
wait $pid                  # 等待指定后台任务
jobs / fg %1 / bg %1       # 作业控制
trap 'cmd' EXIT INT TERM   # 捕获信号执行清理
trap -p                    # 列出当前所有 trap
disown                     # 让后台任务脱离当前 shell
nohup cmd &                # 忽略 SIGHUP 的后台执行
```

## 配置文件解析

子 shell 和后台任务都继承当前 shell 的环境，但「非交互式脚本」不会自动读 bash 启动文件——脚本里的变量、PATH、别名要自己在脚本内定义，别指望登录时配好的环境。

```text
bash 启动文件（进程/子 shell 相关）：
~/.bashrc          交互式 shell 每次启动都读，放别名/函数/PATH
~/.bash_profile    登录 shell 读一次，通常 source ~/.bashrc
/etc/profile       系统级登录 shell 配置（所有用户）
/etc/bash.bashrc   系统级交互式 shell 配置（Debian/Ubuntu）

注意：
1. 脚本 #!/bin/bash 启动的是非交互式 shell，不读 ~/.bashrc —— 靠它配的别名在脚本里失效
2. 子 shell ( ... ) 继承父 shell 的环境变量，但继承的是副本，改动不外泄
3. 后台任务 & 继承当前 shell 的变量，但脚本退出时可能收到 SIGHUP 被终止
```

## 应用场景实战

### 场景一：并行向多台服务器部署

```bash
#!/usr/bin/env bash
# 并行部署到多台机器，全部完成后汇总
servers=(web1 web2 web3)
for host in "${servers[@]}"; do
    ssh "$host" 'systemctl restart nginx' &
    pids+=("$!")
done
# 等所有后台任务完成
for pid in "${pids[@]}"; do
    wait "$pid" || echo "部署失败 PID=$pid"
done
echo "全部部署完成"
```

### 场景二：带清理逻辑的临时文件脚本

```bash
#!/usr/bin/env bash
tmpfile=$(mktemp)
# 无论脚本怎么退出，都清理临时文件
trap 'rm -f "$tmpfile"; echo "已清理临时文件"' EXIT

# 处理逻辑...
echo "生成的数据" > "$tmpfile"
cat "$tmpfile"
```

## 性能与调优

```text
1. 并行任务用 & 替代串行，总耗时从「累加」变「取最大」，但别一次拉太多（受 CPU/网络/文件描述符限制）
2. 命令替换启动子进程有开销，循环里频繁 $( ) 慢——把能一次算完的提到循环外
3. 管道每段一个子进程，长管道（a|b|c|d）进程多，必要时合并
4. 后台任务数量用「信号量」控制并发，避免打爆资源
5. wait 逐个等，可提前发现单个任务失败，别只等最后一个
```

## 安全与权限

```text
1. 命令替换 $( ) 里拼接用户输入要加引号，防命令注入（$(rm -rf ...) 之类的注入）
2. 后台任务并行写共享文件要加锁，避免并行写坏文件
3. trap 清理临时文件用变量/绝对路径，别在 trap 里执行不可信命令
4. nohup/disown 让任务脱离终端继续跑，输出要重定向到文件，否则占住终端
```

## 故障排查

```shell
# 后台任务「莫名消失」：查是不是脚本退出时被 SIGHUP 杀了
jobs -l
# 脚本退出后后台任务没跑完：看有没有 wait / nohup
ps -ef | grep <任务名>
# trap 没生效：确认 trap 写在脚本靠前、信号名正确
trap -p
# 管道里变量改了不生效：确认是不是在子 shell 里改的
echo $var
```

## 常见问题

```text
Q1: 子 shell 里 cd 为什么不影响父 shell？
A: 子 shell 是独立子进程，cd 只改子进程工作目录，父 shell 不变。

Q2: 管道里赋值为什么丢失？
A: a | b 每段都是子 shell，赋值发生在子进程里，父 shell 读不到。

Q3: 后台任务脚本退出后也被杀？
A: 脚本退出时后台子进程收到 SIGHUP，用 wait 等待或 nohup/disown 脱离。

Q4: trap EXIT 什么时候触发？
A: 脚本任何路径退出（正常/异常/收到信号）都触发，适合放清理逻辑。

Q5: 命令替换的输出为什么少了换行？
A: $( ) 会去掉输出末尾的所有换行，需要保留时用进程替换或 readarray。
```

## 面试题

```text
1. 子 shell 和子进程的区别？
   答：子 shell 就是 fork 出的子进程，用 ( ) 显式创建；管道、命令替换也隐式创建子 shell。

2. 命令替换 $( ) 和反引号 `` 的区别？
   答：功能等价，$( ) 可嵌套、易读、引号处理简单，反引号难嵌套易混淆。

3. 后台任务如何拿到 PID 并等待？
   答：cmd & 后 $! 是 PID，wait $pid 等待完成。

4. trap 能捕获哪些信号？
   答：EXIT（脚本退出）、INT（Ctrl+C）、TERM（kill 默认）等，trap -l 列出全部信号。

5. 为什么管道里的变量修改不生效？
   答：管道每段跑在子 shell，变量改动隔离在子进程里。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 命令替换用 $( )，别用反引号（易错、难嵌套）
2. 写临时文件的脚本必须 trap 'rm -f ...' EXIT 清理
3. 并行任务用 & + $! + wait，先启动后统一 wait 汇聚
4. 要隔离变量改动用子 shell ( ... )，别在函数里改全局
5. 优雅退出 trap EXIT 放脚本靠前位置，保证任何路径退出都触发

### 踩坑记录

```text
坑 1：子 shell 里 cd 不影响父 shell
结论：(cd /tmp; ls) 执行完，父 shell 的目录没变。
原因：子 shell 的 cd 只改子进程的工作目录。
解法：要在当前 shell 改目录就别用括号，或用 cd /tmp && 命令。

坑 2：命令替换去掉了末尾换行
结论：x=$(printf "a\nb\n") 后 $x 是 "a\nb" 少了个换行。
原因：命令替换会 strip 掉输出末尾的所有换行。
解法：需要保留换行时用进程替换或 readarray，或接受这个行为。

坑 3：后台任务没 wait 就退出，任务被终止
结论：脚本退出后，它启动的后台任务也被 kill。
原因：脚本结束时 shell 退出，后台子进程收到 SIGHUP 被终止。
解法：用 wait 等后台任务完成，或 nohup/disown 脱离会话。

坑 4：trap 里用单引号导致变量当时不展开
结论：trap 'echo $PID' EXIT 打印的是退出时的 PID，不是定义时的。
原因：单引号延迟展开，trap 触发时才解析变量。
解法：要定义时展开用双引号 trap "echo $PID" EXIT，要实时值用单引号。

坑 5：wait 返回的是最后一个作业的退出码
结论：wait 多个后台任务后，$? 只反映最后一个的成败。
原因：wait 无参数返回最后一个结束作业的状态。
解法：逐个 wait "$pid" 并检查每个的退出码，别用一次 wait 判断全部。
```

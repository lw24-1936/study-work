## 概述

Bash 脚本是 Linux 运维自动化的基础——把一串命令写进文件、加上逻辑、一次性执行。本篇讲脚本的结构与执行方式、变量与作用域、环境变量、位置参数、特殊变量这五个地基概念。理解了变量怎么存、怎么传、怎么读，后面写流程控制和函数才有根基。

```text
Bash 脚本五要素：
1. Shebang —— 第一行 #!/usr/bin/env bash 声明解释器
2. 变量 —— name=value 赋值、$name 引用、${name} 精确边界
3. 环境变量 —— export 导出后子进程可见（HOME/PATH/USER 等）
4. 位置参数 —— $1 $2 ... 脚本接收的命令行参数
5. 特殊变量 —— $# 参数个数、$? 退出码、$! 后台 PID、$$ 自身 PID
```

## 核心概念

Bash 脚本的地基概念：脚本怎么组织、变量怎么存、怎么传、怎么读。下面五个小节逐一展开。

### 脚本结构与执行方式

脚本就是一个以 shebang 开头的文本文件，shebang 声明用哪个解释器执行。执行方式分两种：`bash script.sh`（用 bash 解释，不需可执行权限）和 `./script.sh`（直接执行，需要 chmod +x 加可执行权限）。写完脚本先 `bash -n script.sh` 检查语法，再执行。

```bash
#!/usr/bin/env bash
name="world"
echo "hello, $name"
echo "当前用户: $(whoami)"
echo "当前目录: $(pwd)"
```

```text
# 实测（chmod +x 后直接执行）
$ ./hello.sh
hello, world
当前用户: root
当前目录: /tmp
```

### 变量与作用域

变量赋值 `name=value`，注意等号两边不能有空格（有空格会被当成命令）。引用用 `$name`，需要区分边界时用 `${name}`——比如 `${name}s` 是「name 的值拼 s」，而 `$names` 会去找一个叫 names 的变量。变量默认是全局的，函数里想局部化要用 `local`（见 04.3 函数）。

```shell
name="alice"
echo "hello $name"       # hello alice
echo "hello ${name}s"    # hello alices（花括号区分边界）
```

```text
# 实测
hello alice
hello alices
```

### 环境变量

环境变量是「会传递给子进程」的变量，用 `export 变量=值` 导出。系统预设了一堆环境变量：HOME 家目录、PATH 命令搜索路径、USER 当前用户、SHELL 当前 shell。环境变量和普通变量的区别在于是否对子进程可见——脚本里 export 的变量，脚本启动的子命令能读到，不 export 的读不到。

```shell
echo "HOME=$HOME SHELL=$SHELL USER=$USER"
export MY_APP_ENV=production   # 导出后子进程可见
```

```text
# 实测
HOME=/root SHELL=/bin/bash USER=root
```

### 位置参数

位置参数是脚本从命令行接收的参数：`$1` 第一个、`$2` 第二个、`$0` 是脚本名本身、`$#` 是参数个数、`$@` 和 `$*` 是全部参数。写「接收参数做通用处理」的脚本（比如批量处理指定文件、传目标目录）都靠位置参数。

```bash
#!/usr/bin/env bash
echo "脚本名 \$0: $0"
echo "参数个数 \$#: $#"
echo "第一个参数 \$1: $1"
echo "所有参数 \$@: $@"
```

```text
# 实测（传 3 个参数）
$ ./args.sh foo bar baz
脚本名 $0: /tmp/args.sh
参数个数 $#: 3
第一个参数 $1: foo
所有参数 $@: foo bar baz
```

### 特殊变量

特殊变量是 shell 自动维护的状态变量，脚本里高频使用：`$?` 上一条命令的退出码（0 成功、非 0 失败）、`$!` 最后一个后台进程的 PID、`$$` 当前脚本的 PID、`$#` 参数个数。其中 `$?` 最重要——判断命令是否成功全靠它，写「失败就退出」的逻辑必须读退出码。

```text
特殊变量速查：
1. $? 上一条命令退出码（0=成功，非0=失败）
2. $! 最后一个后台进程 PID
3. $$ 当前 shell/脚本的 PID
4. $# 位置参数个数、$@ 全部参数（每个独立）、$* 全部参数（拼成串）
```

```shell
ls /nonexistent
echo "退出码: $?"          # 非 0，命令失败
ls /etc/hostname > /dev/null
echo "退出码: $?"          # 0，命令成功
```

## 工作原理

Bash 执行脚本时先读 shebang 确定解释器，再 fork 出一个子进程，逐行读取脚本、做变量展开和命令替换，最后交给内核执行命令。变量存在进程的「环境表」里，export 会把变量复制进子进程的环境，普通变量则只留在当前进程——这是「环境变量对子进程可见、普通变量不可见」的底层原因。

```text
脚本执行流程：
读取 shebang（#!）→ fork 子进程 → 逐行解析（变量展开/命令替换）→ 执行命令
变量存储：进程环境表；export 复制给子进程，普通变量不复制
```

## 常用命令与配置

```shell
bash -n script.sh      # 只查语法不执行
bash -x script.sh      # 逐条打印命令（调试用）
bash -c '命令'         # 用 bash 执行一段字符串命令
source file            # 当前 shell 执行（不 fork 子进程）
export VAR=val         # 导出环境变量
env                    # 查看当前环境变量列表
```

## 配置文件解析

Bash 启动时按「登录 shell / 非登录 shell」加载不同配置：登录 shell 依次读 /etc/profile、~/.bash_profile，后者通常再 source ~/.bashrc；非登录 shell（脚本、ssh 执行单命令）只读 ~/.bashrc。全局配置放 /etc/profile、/etc/bash.bashrc，个人配置放 ~/.bashrc、~/.bash_profile。

```text
登录 shell：/etc/profile → ~/.bash_profile → ~/.bashrc
非登录 shell：只读 ~/.bashrc
改完 source ~/.bashrc 立即生效
```

## 应用场景实战

### 场景一：写一个接收参数的部署脚本骨架

```bash
#!/usr/bin/env bash
# 用法：./deploy.sh <环境> <版本号>
set -e

ENV=${1:?用法: deploy.sh <环境> <版本号>}
VERSION=${2:?缺少版本号}

echo "开始部署: 环境=$ENV 版本=$VERSION"
echo "部署脚本 PID: $$"
# 部署逻辑：拉包、解压、重启服务 ...
echo "部署完成"
```

### 场景二：检查命令是否成功并据此分支

```bash
#!/usr/bin/env bash
if systemctl is-active --quiet nginx; then
  echo "nginx 运行中"
else
  echo "nginx 未运行，退出码 $?"
  systemctl start nginx
fi
```

## 性能与调优

```text
1. 减少外部命令调用 —— 用参数扩展/内置命令替代 sed/awk/expr
2. 循环里避免开子进程 —— 命令替换 $( ) 和管道都会 fork，大循环慎用
3. 用 [[ ]] 替代 [ ] —— 内置测试，比外部 test 快且更安全
4. 大文件逐行读用 while read，别用 for $(cat file)（一次性展开耗内存）
```

## 安全与权限

```text
1. 别硬编码密码/密钥，用环境变量或独立配置文件传入
2. 含敏感信息的脚本 chmod 700，别让其他人可读
3. 变量引用加双引号，防止值含空格/分号导致命令注入
4. 慎用 eval，别执行未经验证的用户输入
```

## 故障排查

```shell
bash -n script.sh     # 语法错误定位到具体行
bash -x script.sh     # 追踪执行到哪条命令卡住/出错
echo $?               # 查看上一条命令退出码定位失败点
```

## 常见问题

```text
Q1: 脚本报 Permission denied？
A: 没可执行权限，chmod +x script.sh，或直接 bash script.sh 执行。

Q2: 变量输出为空？
A: 检查是否赋值、是否拼错变量名、是否在子 shell 里改的变量没传出来。

Q3: bash 和 sh 执行结果不同？
A: sh 常是 dash（POSIX），不支持 [[ ]]、数组等 bash 扩展，脚本声明 #!/usr/bin/env bash。

Q4: 脚本里 export 的变量，退出脚本后终端读不到？
A: 脚本跑在子进程里，环境变量不外泄；要在当前 shell 生效用 source 执行。
```

## 面试题

```text
1. Shebang 的作用？
   答：声明脚本用哪个解释器执行；#!/usr/bin/env bash 比写死 /bin/bash 可移植。

2. export 和普通赋值区别？
   答：export 的变量会传给子进程，普通变量只在当前 shell 可见。

3. "$@" 和 "$*" 的区别？
   答：加引号后 "$@" 每个参数独立保留，$* 合并成一个串；遍历参数用 "$@"。

4. 单引号和双引号区别？
   答：双引号内 $var、$(cmd) 会展开，单引号内一律原样输出。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 脚本第一行固定 `#!/usr/bin/env bash`，比写死 `/bin/bash` 可移植
2. 写脚本先 `bash -n script.sh` 查语法，再执行
3. 变量引用加双引号 `"$var"`，防止值为空或含空格时被拆断
4. 需要区分边界用 `${var}`，别偷懒写 `$vars` 引入歧义
5. 脚本里判断命令成功用 `$?`，别用命令输出判断

### 踩坑记录

```text
坑 1：变量赋值等号两边加了空格
结论：name = alice 报 command not found。
原因：等号两边有空格时，shell 把 name 当成命令执行。
解法：赋值必须 name=alice 紧贴等号，两边不留空格。

坑 2：引用变量没加引号，空值/空格导致参数错位
结论：rm -rf $DIR 当 DIR 为空时变成 rm -rf。
原因：未加引号的空变量被展开成空，参数丢失或错位。
解法：始终用 "$DIR" 加引号引用，或用 ${DIR:?} 强制非空。

坑 3：环境变量没 export 子进程读不到
结论：脚本里 VAR=xxx 后调用的子脚本读不到 $VAR。
原因：普通变量不传递给子进程，要 export 才可见。
解法：需要跨进程就用 export VAR=xxx，或 VAR=xxx command 形式。

坑 4：$@ 和 $* 不加引号时行为相同，加引号后不同
结论：含空格的参数被拆断或合并，遍历参数结果不对。
原因："$@" 每个参数独立保留，$* 和 "$*" 会合并成一个串。
解法：遍历参数统一用 for x in "$@"，别用 $*。

坑 5：脚本执行方式不同导致 $0 不同
结论：bash script.sh 和 ./script.sh 里 $0 输出不同。
原因：$0 是「怎么被调用的」——bash script.sh 是 script.sh，./script.sh 是 ./script.sh。
解法：依赖 $0 判断路径时用 dirname 规范化，别直接拿 $0 当绝对路径用。
```

## 概述

Bash 脚本是 Linux 运维自动化的基础——把一串命令写进文件、加上逻辑、一次性执行。本篇讲脚本的结构与执行方式、变量与作用域、环境变量、位置参数、特殊变量这五个地基概念。理解了变量怎么存、怎么传、怎么读，后面写流程控制和函数才有根基。

```text
Bash 脚本五要素：
1. Shebang —— 第一行 #!/usr/bin/env bash 声明解释器
2. 变量 —— name=value 赋值、$name 引用、${name} 精确边界
3. 环境变量 —— export 导出后子进程可见（HOME/PATH/USER 等）
4. 位置参数 —— $1 $2 ... 脚本接收的命令行参数
5. 特殊变量 —— $# 参数个数、$? 退出码、$! 后台 PID、$$ 自身 PID
```

## 核心概念

Bash 脚本的地基概念：脚本怎么组织、变量怎么存、怎么传、怎么读。下面五个小节逐一展开，每节按「是什么 → 为什么 → 怎么用 → 边界/易错点」讲。

### 脚本结构与执行方式

**是什么**：脚本就是一个以 shebang 开头的文本文件，shebang 声明用哪个解释器执行。第一行 `#!/usr/bin/env bash` 比写死 `#!/bin/bash` 可移植——它通过 `env` 在 PATH 里找 bash，不依赖 bash 的绝对路径。

**为什么**：没有 shebang 时，直接 `./script.sh` 执行会用当前 shell 解释（可能是 dash），语法和 bash 有差异；有 shebang 则内核读取它确定解释器，行为确定。

**怎么用**：执行方式分两种——`bash script.sh`（用 bash 解释，不需可执行权限，适合调试）和 `./script.sh`（直接执行，需要 `chmod +x` 加可执行权限）。写完脚本先 `bash -n script.sh` 检查语法，再执行。

```bash
#!/usr/bin/env bash
name="world"
echo "hello, $name"
echo "当前用户: $(whoami)"
echo "当前目录: $(pwd)"
```

```text
# 实测（chmod +x 后直接执行）
$ ./hello.sh
hello, world
当前用户: root
当前目录: /tmp
```

**边界/易错点**：

- shebang 必须严格第一行，前面不能有空行或空格，否则内核不认。
- Windows 上编辑的脚本带 CRLF 换行（`\r\n`），`./script.sh` 会报「解释器找不到」或 `$'\r': command not found`，用 `dos2unix` 或 `sed -i 's/\r$//'` 修。
- `./script.sh` 需要可执行权限，`bash script.sh` 不需要；两者 `$0` 的值不同（见位置参数）。

```text
脚本头部常用开关（set 命令）：
set -e   —— 任一命令失败立即退出，避免带着错误继续跑
set -u   —— 引用未定义变量报错，抓拼写错误
set -x   —— 每条命令执行前打印，调试用
set -o pipefail —— 管道中任一命令失败都算失败（配合 set -e 用）
```

### 变量与作用域

**是什么**：变量是「名字 → 值」的存储单元。赋值 `name=value`，引用 `$name`，需要区分边界时用 `${name}`。

**为什么**：脚本要靠变量记住状态——配置、中间结果、用户输入都存变量里，后续逻辑反复引用。作用域决定变量在哪些地方可见，不搞清楚就会「改了没生效」或「莫名被覆盖」。

**怎么用**：等号两边不能有空格（有空格会被当成命令）。`${name}s` 是「name 的值拼 s」，而 `$names` 会去找一个叫 names 的变量。变量默认是全局的，函数里想局部化要用 `local`（见 04.3 函数）。

```shell
name="alice"
echo "hello $name"       # hello alice
echo "hello ${name}s"    # hello alices（花括号区分边界）
```

```text
# 实测
hello alice
hello alices
```

**命令替换**：把命令的输出存进变量用 `$(命令)` 或反引号，推荐 `$( )`——嵌套清晰、易读。

```shell
now=$(date +%H:%M:%S)
files=$(ls /etc | wc -l)
echo "当前时间: $now，/etc 下条目数: $files"
```

**引号三态**：双引号内 `$var`、`$(cmd)` 会展开；单引号内一律原样输出；不加引号按空白分词（值含空格会被拆断）。

```shell
v="hello world"
echo "$v"      # hello world（一个整体）
echo '$v'      # $v（原样，不展开）
echo $v        # hello world（会被拆成两个词，管道/循环里要小心）
```

**参数扩展默认值**：变量可能为空时给兜底值，四种写法。

```shell
echo "环境: ${APP_ENV:-dev}"      # 空或未定义时用 dev，不改变原变量
echo "环境: ${APP_ENV:=prod}"     # 空时用 prod 并写回原变量
echo "必须传: ${APP_ENV:?缺少环境变量}"  # 空时打印错误并退出
echo "提示: ${APP_ENV:+已设置}"    # 非空时替换成「已设置」
```

**只读与删除**：

```shell
readonly HOST="web-01"
# HOST="db-01"    # 报错：readonly variable
unset name        # 删除变量
```

**边界/易错点**：

- 赋值 `name = alice`（带空格）会报 command not found，shell 把 name 当成命令。
- 变量名只能由字母、数字、下划线组成，且不能以数字开头（`1var=1` 报错）。
- 在子 shell（管道、`$( )`、括号）里改的变量不传回当前 shell，作用域不跨进程。

### 环境变量

**是什么**：环境变量是「会传递给子进程」的变量，用 `export 变量=值` 导出。它是普通变量加上「复制进子进程环境表」这一层标记。

**为什么**：脚本要靠环境变量拿到运行上下文——HOME、PATH、USER 决定了命令去哪找、往哪写、以谁的身份跑。普通变量只活在当前进程，子进程读不到，所以需要 export 显式声明「这个变量要给子进程用」。

**怎么用**：系统预设了一堆环境变量——HOME 家目录、PATH 命令搜索路径、USER 当前用户、SHELL 当前 shell、PWD 当前目录、OLDPWD 上一个目录。脚本里 `export MY_APP_ENV=production` 后，脚本启动的子命令能读到。

```shell
echo "HOME=$HOME SHELL=$SHELL USER=$USER"
export MY_APP_ENV=production   # 导出后子进程可见
bash -c 'echo "子进程读到: $MY_APP_ENV"'   # 子进程能读到 production
```

```text
# 实测
HOME=/root SHELL=/bin/bash USER=root
```

**查看环境变量**：`env` 看所有导出变量、`printenv 变量名` 看单个、`set` 看包括非导出的全部变量和函数。

**一次性传递**：不想永久 export、只想让某条命令临时读到，用 `VAR=xxx command` 前缀形式。

```shell
APP_ENV=staging bash -c 'echo "$APP_ENV"'   # staging，仅此命令可见
echo "${APP_ENV:-未导出}"                    # 未导出（当前 shell 读不到）
```

**PATH 的重要性**：PATH 决定命令搜索顺序，脚本里临时加路径别覆盖，用追加。

```shell
export PATH="$HOME/bin:$PATH"   # 追加，保留原有路径
```

**边界/易错点**：

- 不 export 的普通变量子进程读不到；这是「脚本里 VAR=xxx 后调用的子脚本读不到」的根因。
- 子 shell 里 export 的变量也传不回父 shell——环境变量复制是单向的（父 → 子）。
- export 一个已存在的变量再改值，子进程读到的是导出那一刻的值，之后父 shell 再改不影响已 fork 的子进程。

### 位置参数

**是什么**：位置参数是脚本从命令行接收的参数——`$1` 第一个、`$2` 第二个……`$0` 是脚本名本身，`$#` 是参数个数，`$@`/`$*` 是全部参数。

**为什么**：写「接收参数做通用处理」的脚本（批量处理指定文件、传目标目录、传环境名和版本号）全靠位置参数，否则脚本只能写死路径，换个目标就得改代码。

**怎么用**：

```bash
#!/usr/bin/env bash
echo "脚本名 \$0: $0"
echo "参数个数 \$#: $#"
echo "第一个参数 \$1: $1"
echo "所有参数 \$@: $@"
```

```text
# 实测（传 3 个参数）
$ ./args.sh foo bar baz
脚本名 $0: /tmp/args.sh
参数个数 $#: 3
第一个参数 $1: foo
所有参数 $@: foo bar baz
```

**超过 9 个参数**：`$1` 到 `$9` 之后要用花括号 `${10}`、`${11}`，否则 `$10` 会被当成 `$1` 后面拼个 0。

```shell
echo "${10}"   # 第 10 个参数
```

**shift 移位**：`shift` 把参数整体左移一位（`$2` 变 `$1`），循环处理不定个数的参数用它。

```shell
while [ $# -gt 0 ]; do
    echo "处理参数: $1"
    shift
done
```

**`$@` 与 `$*` 的区别（关键）**：加引号后 `"$@"` 每个参数独立保留（含空格参数不拆），`"$*"` 把所有参数拼成一个串。遍历参数必须用 `"$@"`。

**边界/易错点**：

- 第 10 个参数起必须写 `${10}`，`$10` 语义错误。
- `$0` 是「怎么被调用的」，`bash script.sh` 是 `script.sh`，`./script.sh` 是 `./script.sh`，依赖它取路径要用 `dirname` 规范化。
- 位置参数和函数参数是两套空间（函数里的 `$1` 是函数参数，见 04.3）。

### 特殊变量

**是什么**：特殊变量是 shell 自动维护的状态变量，脚本里高频使用，不能手工赋值。

**为什么**：脚本要靠它们读状态做判断——上一条命令成没成功、后台进程的 PID、自己的 PID，这些信息 shell 已经记好了，直接读就行。

**怎么用**：

```text
特殊变量速查：
1. $? 上一条命令退出码（0=成功，非0=失败）
2. $! 最后一个后台进程 PID
3. $$ 当前 shell/脚本的 PID
4. $# 位置参数个数、$@ 全部参数（每个独立）、$* 全部参数（拼成串）
5. $- 当前 shell 的选项标志（如 -e -u -x）
6. $_ 上一条命令的最后一个参数
```

```shell
ls /nonexistent
echo "退出码: $?"          # 非 0，命令失败
ls /etc/hostname > /dev/null
echo "退出码: $?"          # 0，命令成功

sleep 30 &                # 后台启动
echo "后台进程 PID: $!"
echo "当前脚本 PID: $$"
```

**退出码的范围与含义**：`$?` 是 0-255 的整数。0 表示成功，非 0 表示失败；不同程序用不同非 0 码区分错误类型（如 grep 的 1 是「没匹配到」、2 是「出错」）。

**边界/易错点**：

- `$?` 只能读一次——它保存的永远是「上一条」命令的退出码，中间插任何命令（包括 `echo`）都会把它覆盖。要用就先存起来：`rc=$?`。
- `$?` 读的是「最后一条管道命令」的退出码，除非开了 `set -o pipefail`。

```shell
false
rc=$?                 # 立刻存起来
echo "命令退出码: $rc"   # 这里 $? 已经被 echo 覆盖，读 rc 才准
```

## 工作原理

Bash 执行脚本时先读 shebang 确定解释器，再 fork 出一个子进程，逐行读取脚本、做变量展开和命令替换，最后交给内核执行命令。变量存在进程的「环境表」里，export 会把变量复制进子进程的环境，普通变量则只留在当前进程——这是「环境变量对子进程可见、普通变量不可见」的底层原因。

```text
脚本执行流程：
读取 shebang（#!）→ fork 子进程 → 逐行解析（变量展开/命令替换）→ 执行命令
变量存储：进程环境表；export 复制给子进程，普通变量不复制
```

变量展开发生在命令执行前：shell 先把 `$name`、`$(cmd)`、`$((算术))` 替换成实际值，再交给命令。展开有固定顺序（花括号 → 波浪号 → 参数/命令/算术 → 分词 → 路径通配），理解顺序能解释很多「为什么这里要加引号」的问题。

```text
展开顺序（简化）：
1. 花括号展开 {a,b,c}
2. 波浪号展开 ~ → /root
3. 参数/命令/算术展开 $var、$(cmd)、$((...))
4. 单词拆分（按 IFS 分词）—— 不加引号时发生
5. 路径通配 *.txt、[abc]、?  —— 不加引号时发生
```

## 常用命令与配置

```shell
bash -n script.sh      # 只查语法不执行
bash -x script.sh      # 逐条打印命令（调试用）
bash -c '命令'         # 用 bash 执行一段字符串命令

export VAR=val         # 导出环境变量
env                    # 查看当前环境变量列表

unset VAR              # 删除变量
readonly VAR=val       # 声明只读变量
shift [n]              # 位置参数左移 n 位
```

## 配置文件解析

Bash 启动时按「登录 shell / 非登录 shell」加载不同配置：登录 shell 依次读 /etc/profile、~/.bash_profile，后者通常再 source ~/.bashrc；非登录 shell（脚本、ssh 执行单命令）只读 ~/.bashrc。全局配置放 /etc/profile、/etc/bash.bashrc，个人配置放 ~/.bashrc、~/.bash_profile。

```text
登录 shell：/etc/profile → ~/.bash_profile → ~/.bashrc
非登录 shell：只读 ~/.bashrc
交互 shell：有提示符、读配置；非交互脚本：通常不读 ~/.bashrc（取决于调用方式）
改完 source ~/.bashrc 立即生效
```

配置文件的典型内容——定义环境变量、别名、函数、PS1 提示符：

```shell
# ~/.bashrc 常见片段
export PATH="$HOME/.local/bin:$PATH"
export EDITOR=vim
alias ll='ls -alF'
alias gs='git status'
```

注意脚本（非交互非登录）一般不会自动读 ~/.bashrc，所以「在 .bashrc 里 export 的变量，脚本里读不到」是正常的——要共享就写成独立配置、在脚本里 source。

## 应用场景实战

### 场景一：写一个接收参数的部署脚本骨架

```bash
#!/usr/bin/env bash
# 用法：./deploy.sh <环境> <版本号>
set -e

ENV=${1:?用法: deploy.sh <环境> <版本号>}
VERSION=${2:?缺少版本号}

echo "开始部署: 环境=$ENV 版本=$VERSION"
echo "部署脚本 PID: $$"
# 部署逻辑：拉包、解压、重启服务 ...
echo "部署完成"
```

### 场景二：检查命令是否成功并据此分支

```bash
#!/usr/bin/env bash
if systemctl is-active --quiet nginx; then
  echo "nginx 运行中"
else
  echo "nginx 未运行，退出码 $?"
  systemctl start nginx
fi
```

### 场景三：环境变量驱动的多环境配置脚本

同一套脚本，靠环境变量切换测试/生产配置，不改代码。

```bash
#!/usr/bin/env bash
set -euo pipefail

# 读环境变量，给默认值兜底
APP_ENV=${APP_ENV:-dev}
DB_HOST=${DB_HOST:-127.0.0.1}
DB_PORT=${DB_PORT:-3306}

case "$APP_ENV" in
  prod)  LOG_LEVEL=warn  ;;
  staging) LOG_LEVEL=info ;;
  *)     LOG_LEVEL=debug ;;
esac

echo "启动应用: 环境=$APP_ENV 日志级别=$LOG_LEVEL"
echo "连接数据库: $DB_HOST:$DB_PORT"

# 生产环境做额外检查
if [ "$APP_ENV" = "prod" ] && [ "$DB_HOST" = "127.0.0.1" ]; then
  echo "错误：生产环境不允许连本机数据库" >&2
  exit 1
fi
```

## 性能与调优

```text
1. 减少外部命令调用 —— 用参数扩展/内置命令替代 sed/awk/expr
2. 循环里避免开子进程 —— 命令替换 $( ) 和管道都会 fork，大循环慎用
3. 用 [[ ]] 替代 [ ] —— 内置测试，比外部 test 快且更安全
4. 大文件逐行读用 while read，别用 for $(cat file)（一次性展开耗内存）
5. 算术用 $(( ))，别调外部 expr（省一次子进程）
```

## 安全与权限

```text
1. 别硬编码密码/密钥，用环境变量或独立配置文件传入
2. 含敏感信息的脚本 chmod 700，别让其他人可读
3. 变量引用加双引号，防止值含空格/分号导致命令注入
4. 慎用 eval，别执行未经验证的用户输入
5. 外部输入（用户参数、环境变量）进命令前先校验，别直接拼进 rm/curl/eval
```

## 故障排查

```shell
bash -n script.sh     # 语法错误定位到具体行
bash -x script.sh     # 追踪执行到哪条命令卡住/出错
echo $?               # 查看上一条命令退出码定位失败点
set -u                # 抓未定义变量（拼写错误的变量名）
```

```text
常见故障速查：
脚本报 Permission denied → chmod +x 或用 bash script.sh 执行
脚本报 $'\r': command not found → 文件带 CRLF 换行，dos2unix 转一下
变量输出为空 → 检查是否赋值、是否拼错、是否在子 shell 里改的没传出来
```

## 常见问题

```text
Q1: 脚本报 Permission denied？
A: 没可执行权限，chmod +x script.sh，或直接 bash script.sh 执行。

Q2: 变量输出为空？
A: 检查是否赋值、是否拼错变量名、是否在子 shell 里改的变量没传出来。

Q3: bash 和 sh 执行结果不同？
A: sh 常是 dash（POSIX），不支持 [[ ]]、数组等 bash 扩展，脚本声明 #!/usr/bin/env bash。

Q4: 脚本里 export 的变量，退出脚本后终端读不到？
A: 脚本跑在子进程里，环境变量不外泄；要在当前 shell 生效用 source 执行。

Q5: 变量名能包含哪些字符？
A: 字母、数字、下划线，且不能以数字开头；等号两边不能有空格，否则 name 被当成命令。

Q6: $(命令) 和反引号 `命令` 有什么区别？
A: 都能做命令替换，$( ) 嵌套清晰、可读性好，是推荐写法；反引号里嵌套要转义、易错。

Q7: 怎么给变量设默认值？
A: ${var:-默认}（只返回默认不写回）、${var:=默认}（写回原变量）、${var:?提示}（空则报错退出）。

Q8: 脚本里为什么读不到 .bashrc 里 export 的变量？
A: 非交互脚本通常不读 .bashrc；把共享配置写进独立文件、在脚本里 source 引入。
```

## 面试题

```text
1. Shebang 的作用？
   答：声明脚本用哪个解释器执行；#!/usr/bin/env bash 比写死 /bin/bash 可移植。

2. export 和普通赋值区别？
   答：export 的变量会传给子进程，普通变量只在当前 shell 可见。

3. "$@" 和 "$*" 的区别？
   答：加引号后 "$@" 每个参数独立保留，$* 合并成一个串；遍历参数用 "$@"。

4. 单引号和双引号区别？
   答：双引号内 $var、$(cmd) 会展开，单引号内一律原样输出。

5. 如何让变量对子进程可见？
   答：export VAR=val 导出；或 VAR=val command 一次性传给某条命令；子 shell 里改的传不回父 shell。

6. $?、$!、$$、$# 分别表示什么？
   答：$? 上一条命令退出码、$! 最后后台进程 PID、$$ 当前进程 PID、$# 位置参数个数。

7. ${var:-default} 和 ${var:=default} 的区别？
   答：前者只在展开时返回 default、不改原变量；后者在 var 为空时把 default 写回 var 再返回。

8. bash script.sh 和 ./script.sh 的区别？
   答：前者用 bash 解释、不需可执行权限；后者直接执行、需 chmod +x；两者 $0 的值也不同。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 脚本第一行固定 `#!/usr/bin/env bash`，比写死 `/bin/bash` 可移植
2. 写脚本先 `bash -n script.sh` 查语法，再执行
3. 变量引用加双引号 `"$var"`，防止值为空或含空格时被拆断
4. 需要区分边界用 `${var}`，别偷懒写 `$vars` 引入歧义
5. 脚本里判断命令成功用 `$?`，别用命令输出判断
6. 关键脚本开头加 `set -euo pipefail`，命令失败即退出、未定义变量即报错
7. 用默认值参数扩展 `${var:-default}` 给变量兜底，别写一堆 if 判断空

### 踩坑记录

```text
坑 1：变量赋值等号两边加了空格
结论：name = alice 报 command not found。
原因：等号两边有空格时，shell 把 name 当成命令执行。
解法：赋值必须 name=alice 紧贴等号，两边不留空格。

坑 2：引用变量没加引号，空值/空格导致参数错位
结论：rm -rf $DIR 当 DIR 为空时变成 rm -rf。
原因：未加引号的空变量被展开成空，参数丢失或错位。
解法：始终用 "$DIR" 加引号引用，或用 ${DIR:?} 强制非空。

坑 3：环境变量没 export 子进程读不到
结论：脚本里 VAR=xxx 后调用的子脚本读不到 $VAR。
原因：普通变量不传递给子进程，要 export 才可见。
解法：需要跨进程就用 export VAR=xxx，或 VAR=xxx command 形式。

坑 4：$@ 和 $* 不加引号时行为相同，加引号后不同
结论：含空格的参数被拆断或合并，遍历参数结果不对。
原因："$@" 每个参数独立保留，$* 和 "$*" 会合并成一个串。
解法：遍历参数统一用 for x in "$@"，别用 $*。

坑 5：脚本执行方式不同导致 $0 不同
结论：bash script.sh 和 ./script.sh 里 $0 输出不同。
原因：$0 是「怎么被调用的」——bash script.sh 是 script.sh，./script.sh 是 ./script.sh。
解法：依赖 $0 判断路径时用 dirname 规范化，别直接拿 $0 当绝对路径用。

坑 6：Windows 编辑的脚本带 CRLF 换行
结论：脚本报 $'\r': command not found 或 /usr/bin/env: 'bash\r': No such file。
原因：Windows 换行是 \r\n，Linux 只认 \n，\r 被当成命令名的一部分。
解法：dos2unix script.sh，或 sed -i 's/\r$//' script.sh。

坑 7：$? 用得太晚，中间命令把它覆盖了
结论：echo "退出码 $?" 打印的其实是上一条 echo 的退出码，不是目标命令的。
原因：$? 永远保存「上一条」命令的退出码，任何中间命令都会覆盖它。
解法：命令执行完立刻 rc=$? 存下来，后面读 $rc。
```

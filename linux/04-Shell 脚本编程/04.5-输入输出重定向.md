## 概述

这一篇讲重定向的进阶用法：文件描述符、Here Document、Here String、进程替换。前面 02.6 讲过基础的 `>` `>>` `|`，这里讲脚本里更灵活的重定向手段——用 Here Document 喂多行输入、用 Here String 把字符串当 stdin、用进程替换把命令输出当文件。这些在写「需要传多行配置、临时文件」的脚本时特别有用。

```text
四个进阶重定向：
1. 文件描述符 —— fd 0/1/2 标准流，可自定义 fd 3 同时读写多个文件
2. Here Document <<EOF —— 把多行文本原样喂给命令的 stdin
3. Here String <<< —— 把单个字符串当 stdin，免 echo 管道
4. 进程替换 <(...) —— 把命令输出伪装成文件，省去临时文件
```

## 核心概念

四个进阶重定向手段：文件描述符、Here Document、Here String、进程替换。下面逐一展开。

### 文件描述符

每个进程默认三个文件描述符：0 标准输入、1 标准输出、2 标准错误。重定向就是把这些 fd 指向文件，还能自定义 fd（如 `3>file` 打开第三个流）。脚本里常见技巧：`exec 3>log.txt` 把 fd 3 绑定到日志文件，之后 `echo ... >&3` 写日志，避免和正常输出混在一起。

```shell
# 三个标准流
echo "正常输出"              # fd 1 stdout
echo "错误输出" >&2          # fd 2 stderr

# 自定义 fd 3 绑定文件
exec 3>/tmp/log.txt
echo "写进日志" >&3
exec 3>&-                   # 关闭 fd 3
cat /tmp/log.txt
```

文件描述符的「是什么→为什么→怎么用」：fd 是内核给每个进程维护的「打开文件」的编号，0/1/2 是默认三件套。重定向的本质是「改 fd 指向的目标」。为什么需要自定义 fd——因为有时候要同时读两个文件、同时写两个文件（一个日志、一个错误），只靠 1/2 不够用，就临时开 fd 3、4。

补充三个关键操作：复制 fd、从 fd 读、fd 与文件的双向读写。

```shell
# 1. 复制 fd：3>&1 把 fd 3 指向 fd 1 现在指的地方（先记住 stdout）
exec 3>&1                 # 保存原始 stdout 到 fd 3
exec 1>/tmp/out.txt       # stdout 改指向文件
echo "这行进文件"
exec 1>&3                 # 恢复 stdout
exec 3>&-                 # 关闭 fd 3
echo "这行回终端"

# 2. 从 fd 读：3<file 打开文件供读取，<&3 读取
exec 3</etc/hostname
read -r line <&3
echo "hostname 第一行: $line"
exec 3<&-
```

```text
# 示例输出
这行回终端
hostname 第一行: <主机名>
```

```shell
# 3. 同时读写一个 fd：<>file 读写模式打开（不截断）
exec 3<>/tmp/counter.txt
echo "1" >&3          # 写
exec 3>&-             # 关闭
```

要点：`exec 3>file` 打开写、`exec 3<file` 打开读、`exec 3<>file` 打开读写、`exec 3>&-`/`exec 3<&-` 关闭、`3>&1`/`3<&0` 复制。这些 exec 形式的 fd 操作是「脚本级」重定向，比每条命令后跟 `>file` 更灵活。

### Here Document

Here Document（`<<EOF ... EOF`）把多行文本原样喂给命令的 stdin，适合给命令传多行配置、写临时文件、批量 SQL。关键点：`<<EOF`（不带引号）会对内容做变量展开，`<<'EOF'`（引号）则原样输出不展开——写包含 `$` 的内容时一定要用引号版，否则 `$var` 会被意外展开。

```shell
# 原样输出（引号 EOF 不展开变量）
cat <<'EOF'
多行文本原样输出
变量 $HOME 不展开
EOF
```

```text
# 实测
多行文本原样输出
变量 $HOME 不展开（用了引号 EOF）
```

Here Document 的完整形态比 `<<EOF ... EOF` 多几个细节：结束标记可以缩进、内容可以做「引用抑制一部分展开」、还能把 here doc 接到管道后。

```shell
# 1. <<-EOF：结束标记前允许 tab 缩进（脚本里嵌 here doc 时对齐用）
cat <<-'EOF'
	这行前面有 tab
	结束标记 EOF 前也有 tab
	EOF

# 2. 不带引号的 <<EOF：内容里的变量、命令替换会被展开
name="alice"
cat <<EOF
你好 $name，家目录是 $HOME
EOF

# 3. here doc 接到管道后，作为后续命令的 stdin
cat <<'EOF' | tr 'a-z' 'A-Z'
hello world
EOF
```

```text
# 示例输出（第 2 段）
你好 alice，家目录是 /root
```

要点：`<<-EOF` 只能忽略前导 **tab**（不是空格），且只对结束标记生效；`<<EOF` 展开变量和命令替换，`<<'EOF'` 或 `<<"EOF"` 完全抑制展开，`<<\EOF` 也能抑制（转义标记）。

### Here String

Here String（`<<<`）把单个字符串直接当命令的 stdin，省去 `echo ... | cmd` 的管道。适合「把一行字符串喂给读 stdin 的命令」——`wc -w <<< "..."` 数单词、`read x <<< "..."` 读值、`grep x <<< "$var"` 搜变量内容。比 echo 管道少一个子进程、写法更干净。

```shell
wc -w <<< "hello world from here string"
```

```text
# 实测
5
# 等价于 echo "hello world from here string" | wc -w，但少一层管道
```

Here String 的边界：它只喂「一行」字符串（bash 会在末尾补一个换行），多词会被 read 按 IFS 拆成多个变量。典型用法有读值、拆分、给 grep 喂变量、喂数组。

```shell
# 1. read 读值
read -r first second <<< "hello world"
echo "first=$first second=$second"

# 2. 喂数组
read -ra arr <<< "a b c"
echo "数组: ${arr[@]}  长度: ${#arr[@]}"

# 3. grep 搜变量内容
line="error: disk full at 14:32"
grep -o 'error' <<< "$line" && echo "含 error"
```

```text
# 示例输出
first=hello second=world
数组: a b c  长度: 3
error
含 error
```

要点：`<<<` 会做变量展开（和 `<<` 带引号不同，它总展开），末尾自动补换行；`read -a` 把整串按 IFS 拆进数组，是「字符串转数组」的快捷方式。

### 进程替换

进程替换 `<(...)` 把命令的输出伪装成一个临时文件，供「只接受文件参数」的命令使用；`>(...)` 反过来把命令的输入伪装成文件。典型场景：diff 两个命令的输出、把命令结果喂给 while read、比较两个进程列表——都不用先落临时文件。

```shell
# diff 两个命令的输出（无需临时文件）
diff <(echo aaa) <(echo bbb)
```

```text
# 实测
1c1
< aaa
---
> bbb
```

进程替换的两个方向都要掌握：`<(...)` 当「读的文件」用（输出侧）、`>(...)` 当「写的文件」用（输入侧）。

```shell
# 1. <(...) 输出侧：diff、comm、sort、while read 都吃
comm -12 <(echo -e "a\nb\nc" | sort) <(echo -e "b\nc\nd" | sort)

# 2. >(...) 输入侧：把命令输出同时写进「进程」和文件
echo "data" | tee >(md5sum) > /tmp/saved.txt

# 3. 喂给 while read（不用管道避免子 shell 变量丢失）
while read -r line; do
    echo "读到: $line"
done < <(seq 3)
```

```text
# 示例输出
b
c
d41d8cd98f00b204e9800998ecf8427e  -
读到: 1
读到: 2
读到: 3
```

要点：`<(...)` 实际返回一个形如 `/dev/fd/63` 的路径，命令拿它当普通文件读；`done < <(cmd)` 是 while 循环喂进程替换的固定写法（注意 `< <` 之间有空格）；`>(...)` 里命令的 stdin 接到外部命令的输出。

## 工作原理

重定向的本质是「改文件描述符指向」：每个进程默认 fd 0/1/2 指向终端，`>` 把 fd 1 指向文件，`2>` 把 fd 2 指向文件。Here Document/Here String 是「把一段文本喂给 fd 0」的语法糖，进程替换 `<(...)` 则是「把命令输出挂到 /dev/fd/N」伪装成文件。

```text
重定向原理：修改进程文件描述符（fd）的指向
fd 0=stdin 1=stdout 2=stderr，> 重定向 1，2> 重定向 2
进程替换 <(...) 把命令输出挂到 /dev/fd/N，伪装成文件
```

展开讲，四个机制的底层实现各不相同：

```text
1. 重定向 >/>>/< ：fork 子进程后，在 exec 前把 fd 指向文件——dup2 系统调用把 fd 1 复制成目标文件的 fd
2. Here Document <<EOF：bash 把 EOF 之间的内容写进一个临时文件（或管道），再当 stdin 喂给命令
3. Here String <<<：bash 把字符串写进临时文件/管道，末尾补换行，喂给命令 stdin
4. 进程替换 <(...)：bash 用命名管道（FIFO，/dev/fd/N）把子命令输出接到一个 fd，命令拿这个 fd 当文件读
```

```shell
# 验证进程替换返回的是 /dev/fd/N 路径
echo <(echo hello)
```

```text
# 示例输出
/dev/fd/63
```

## 常用命令与配置

```shell
cmd > file        # stdout 覆盖写入
cmd >> file       # stdout 追加
cmd 2> err        # stderr 重定向
cmd > file 2>&1   # stdout+stderr 都进 file
cmd &> file       # 同上（bash 简写）
cmd <<'EOF'       # Here Document 原样输入
cmd <<< "str"     # Here String 输入
cmd < <(cmd2)     # 进程替换喂 stdin
exec 3>file       # 打开 fd 3 写文件
exec 3>&-         # 关闭 fd 3
exec 3>&1         # 复制 fd 1 到 fd 3
```

```text
重定向顺序记忆：
- > file 2>&1 先让 stdout 进文件，再把 stderr 并进 stdout（正确）
- 2>&1 > file 先让 stderr 并进旧 stdout（终端），再让 stdout 进文件（stderr 没进去，错误）
- &> file 是 bash 的 stdout+stderr 一起重定向简写，等价 > file 2>&1
```

## 配置文件解析

Here Document 常用于「生成配置文件」——把整段配置原样写进文件。用 `<<'EOF'`（引号）避免配置里的 $ 变量被展开。这是脚本自动化部署（生成 systemd unit、nginx 配置）的主力手段。

```text
生成配置模板：
cat <<'EOF' > /etc/app.conf
key=$not_expanded   # 引号 EOF，$ 不展开
value=literal
EOF
```

下面是一个「用变量生成配置、又能保留字面 $」的完整示例——两种 EOF 一起用：

```bash
#!/usr/bin/env bash
# 生成 nginx 站点配置：端口用变量、location 里的 $ 保留字面
port=${1:-8080}

cat > /etc/nginx/conf.d/app.conf <<EOF
server {
    listen ${port};          # 这里要展开端口变量
    location / {
        proxy_pass http://127.0.0.1:\$backend_port;
        # 上面的 \$backend_port 转义，保留字面 \$，交给 nginx 运行时解析
    }
}
EOF
```

```text
技巧：同一段 heredoc 里「想展开的」正常写，「想保留字面 $ 的」加反斜杠转义 \$
——比整体用引号 EOF 更细粒度，适合「大部分展开、小部分保留」的配置模板。
```

## 应用场景实战

### 场景一：用 Here Document 批量写配置文件

```bash
#!/usr/bin/env bash
# 生成一个 systemd 服务文件
cat <<'EOF' > /etc/systemd/system/myapp.service
[Unit]
Description=My App
After=network.target

[Service]
ExecStart=/opt/myapp/bin/myapp
Restart=always

[Install]
WantedBy=multi-user.target
EOF
echo "服务文件已生成"
```

### 场景二：用进程替换统计两个时间点的进程差异

```bash
#!/usr/bin/env bash
# 记录进程快照，对比变化
ps -e -o comm --no-headers | sort > /tmp/procs.txt
# ... 过一会 ...
comm -13 <(sort /tmp/procs.txt) <(ps -e -o comm --no-headers | sort)
echo "以上是新出现的进程"
```

### 场景三：脚本同时输出「屏幕 + 日志」，错误单独落文件

```bash
#!/usr/bin/env bash
# 常规信息进屏幕和日志，错误单独进 err.log
exec 3>&1                                     # 保存 stdout
exec > >(tee -a /var/log/app.log) 2>&1        # stdout+stderr 走 tee（屏幕+日志）

echo "正常信息：开始处理"
echo "警告信息" >&2
echo "错误信息：磁盘满了" >&2

# 恢复 stdout（可选，脚本到这里通常直接结束）
exec 1>&3
echo "这条只在终端，不进日志"
```

```text
这个场景用 >(tee -a log) 让 stdout 同时到屏幕和日志，再 2>&1 把 stderr 也并进去。
exec 3>&1 提前保存原始 stdout，需要时 exec 1>&3 恢复。
```

## 性能与调优

```text
1. <<< 比 echo | cmd 少一个子进程和管道
2. 进程替换比落临时文件快（省磁盘 IO），但要注意 fd 上限
3. 大量日志写入用 exec 3>log 复用 fd，别反复开关文件
4. 重定向到 /dev/null 丢弃输出，省磁盘
5. 循环里别每次重定向打开同一个文件（>file 每次截断+重开），用 exec 3>>file 一次打开复用
6. tee 有缓冲，高频写入时注意「缓冲不落盘」——需要实时看日志用 stdbuf -oL 或直接 >file
```

## 安全与权限

```text
1. 重定向写文件时注意权限，别把敏感内容写进 644 文件
2. Here Document 生成含密钥的配置，用 umask 077 或写完 chmod 600
3. 日志和错误信息分离（>&2），避免误把错误当数据
4. Here Document 里 `$(...)` 和反引号会被展开执行——用引号 EOF 抑制，否则外部输入会命令注入
5. 进程替换 >(...) 里命令以当前用户权限跑，别把不可信数据重定向进特权命令
6. 写系统配置文件（/etc 下）用 Here Document 前确认有权限，失败会半写文件（先写临时文件再 mv）
```

## 故障排查

```shell
# 常见：2>&1 顺序错误、结束标记 EOF 前有空格
cmd > file 2>&1      # 正确顺序，2>&1 在 > 之后
# 排查 fd 占用
ls -l /proc/$$/fd    # 看当前进程打开的文件描述符
```

```text
排错思路：
1. stderr 没进文件 → 检查 2>&1 是不是写在 > 之前；用 &> 或 > file 2>&1
2. here doc 不结束 → 结束标记前面有空格/tab；顶格写，或改用 <<-EOF
3. here doc 里变量被展开了 → 换 <<'EOF'（引号）
4. 进程替换报语法错 → 脚本是不是 sh 在解释（shebang 写错）；进程替换是 bash 特性
5. fd 不够用报 too many open files → ls -l /proc/$$/fd 看开了多少，脚本里 exec 3>&- 及时关
6. 重定向后屏幕没输出 → 检查是不是把 stdout 也重定向走了，忘了 tee 或 fd 复制
```

## 常见问题

```text
Q1: 2>&1 放在 > 前面为什么不对？
A: 重定向从左到右，2>&1 在 > file 前会先把 stderr 指向旧 stdout。

Q2: Here Document 内容里的变量被展开了？
A: 用 <<'EOF'（引号）禁止展开，<<EOF 才展开。

Q3: <(...) 在 sh 脚本报语法错误？
A: 进程替换是 bash 特性，脚本用 #!/usr/bin/env bash。

Q4: 想同时看到输出又写进文件？
A: cmd | tee file，输出既到屏幕也进文件。

Q5: <<EOF 和 <<-EOF 区别？
A: <<-EOF 允许结束标记前有 tab 缩进（会被忽略），方便脚本里对齐；只能忽略 tab 不能忽略空格。

Q6: Here String <<< 和 Here Document << 的区别？
A: <<< 喂单个字符串（末尾自动补换行），<< 喂多行文本块。

Q7: 怎么只丢弃 stderr 保留 stdout？
A: cmd 2>/dev/null；两个都丢 cmd >/dev/null 2>&1。
```

## 面试题

```text
1. 0 1 2 三个文件描述符代表什么？
   答：0 标准输入、1 标准输出、2 标准错误。

2. > file 2>&1 和 &> file 的区别？
   答：等价，都是 stdout+stderr 重定向到 file；2>&1 是 POSIX 通用写法。

3. Here Document 和 Here String 区别？
   答：<<EOF 喂多行文本，<<< 喂单个字符串。

4. 进程替换的用途？
   答：把命令输出伪装成文件，给只接受文件参数的命令（diff/while read）用，省临时文件。

5. 2>&1 >file 和 >file 2>&1 有什么区别？
   答：前者 stderr 先并到旧 stdout（终端）、stdout 再进文件，stderr 没进文件；后者才是 stdout+stderr 都进文件。

6. Here Document 怎么抑制变量展开？
   答：结束标记加引号 <<'EOF'，或用 <<\EOF 转义标记。

7. exec 3>file 是干什么的？
   答：打开自定义文件描述符 3 指向文件，之后 echo ... >&3 写入；exec 3>&- 关闭。

8. 进程替换底层用了什么机制？
   答：命名管道（FIFO）或 /dev/fd/N，把命令输出挂成一个可读的 fd 伪装成文件。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 写含 $ 的多行内容用 <<'EOF'（引号），避免变量被意外展开
2. 单个字符串喂 stdin 用 <<<，比 echo | cmd 干净且少个子进程
3. 比较两个命令输出用 <(...)，省去临时文件
4. 日志输出走 stderr（>&2），正常结果走 stdout，分离后可分别重定向
5. 自定义 fd 用 exec 3>file 打开、用完 exec 3>&- 关闭
6. 同时要屏幕+文件用 tee，配合 >(tee log) 进程替换可连 stdout 一起接
7. 需要保留 stdout 又临时重定向时，先 exec 3>&1 保存、用完 exec 1>&3 恢复

### 踩坑记录

```text
坑 1：Here Document 里变量被意外展开
结论：<<EOF 内容里的 $var 被展开成变量值，想保留字面 $ 却变了。
原因：不带引号的 EOF 会对内容做变量和命令展开。
解法：要原样输出用 <<'EOF'（引号），要展开才用 <<EOF。

坑 2：Here Document 结束标记 EOF 前有空格不生效
结论：结束标记前有缩进，heredoc 不结束、报错。
原因：结束标记必须顶格写，前面不能有空格/tab。
解法：结束标记顶格写；需要缩进用 <<-EOF（自动忽略前导 tab）。

坑 3：进程替换 <(...) 在 POSIX sh 里不兼容
结论：#!/bin/sh 的脚本里 <(...) 报语法错误。
原因：进程替换是 bash 特性，sh/dash 不支持。
解法：用 bash 脚本（#!/usr/bin/env bash），或改临时文件方案。

坑 4：重定向顺序错误导致结果不符预期
结论：2>&1 放在 > 前面，stderr 没合并进去。
原因：重定向从左到右生效，2>&1 必须在 > file 之后。
解法：正确顺序 cmd > file 2>&1，或 cmd &> file。

坑 5：Here String 多词被当成一个参数还是多个
结论：read a b <<< "x y" 和预期不同。
原因：<<< 是「整串当 stdin」，read 按 IFS 拆分成多个变量。
解法：明确 read 的拆分行为，或用数组 read -a arr <<< "..."。

坑 6：while read 用管道喂导致循环里的变量丢失
结论：cat file | while read x; do y=$x; done; echo $y 出来是空。
原因：管道让 while 循环跑在子 shell，循环里的赋值不外泄。
解法：用 done < file 或 done < <(cmd) 进程替换，让循环留在当前 shell。

坑 7：exec 3>file 忘了关闭导致 fd 泄漏
结论：脚本里反复 exec 3>file 打开文件，fd 越开越多，最后 too many open files。
原因：自定义 fd 不会自动关闭，重复打开会累积。
解法：用完 exec 3>&- 关闭；或用子 shell ( ... ) 把 fd 操作包起来自动回收。
```

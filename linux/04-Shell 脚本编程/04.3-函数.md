## 概述

函数把重复的逻辑封装成可复用的单元。脚本越写越长，重复代码越来越多，就该抽函数了——定义一次、到处调用。函数的关键概念：定义、参数传递（函数有自己独立的 $1 $2）、返回值（return 退出码 vs echo 输出）、局部变量（local）、函数库（source 复用）。掌握这五个，脚本就能模块化。

```text
函数五要素：
1. 定义 —— name() { ... } 或 function name { ... }
2. 参数 —— 函数内的 $1 $2 是函数参数，不是脚本参数
3. 返回 —— return 返回退出码（0-255），echo 返回数据（用 $(fun) 捕获）
4. 局部变量 —— local 声明，只在函数内可见
5. 函数库 —— 把函数写进单独文件，source 引入复用
```

## 核心概念

函数的五个核心概念：定义、参数、返回、局部变量、函数库。下面逐一展开，每节按「是什么 → 为什么 → 怎么用 → 边界/易错点」讲。

### 函数定义

**是什么**：函数定义两种写法——`name() { ... }`（推荐，POSIX 兼容）和 `function name { ... }`（bash 关键字）。定义后像命令一样调用。

**为什么**：重复出现两次以上的逻辑就该抽函数，避免复制粘贴——改一处逻辑，所有调用点同步更新，减少漏改。

**怎么用**：

```bash
greet() {
    echo "hello, $1"
}
greet "alice"
greet "bob"
```

```text
# 实测
hello, alice
hello, bob
```

**查看与重定义**：`type` 看函数定义、`declare -f` 列出所有函数；同名函数后定义覆盖先定义。

```shell
type greet          # 显示 greet 是函数及其定义
declare -F          # 列出所有函数名
declare -f greet    # 显示 greet 的完整定义
```

**边界/易错点**：

- 函数必须在调用前定义（shell 顺序执行），函数库文件都放脚本开头 source。
- `function name { ... }` 是 bash 扩展，`name() { ... }` 是 POSIX 兼容写法，写库文件用后者更通用。
- 函数名别和系统命令重名（如定义 `ls()` 会遮蔽 /bin/ls），排查时 `type ls` 能看到遮蔽。

### 参数传递

**是什么**：函数有自己独立的参数空间——函数内的 `$1 $2 $# $@` 指的是传给函数的参数，不是传给脚本的。脚本的 `$1` 和函数里的 `$1` 互不影响。

**为什么**：参数让同一个函数能处理不同输入，这是函数复用性的来源——`add 3 5`、`add 10 20` 共用一套逻辑。

**怎么用**：调用时 `函数名 参数1 参数2`，函数内用 `$1 $2` 接收。

```bash
add() {
    echo $(( $1 + $2 ))
}
result=$(add 3 5)
echo "3+5=$result"
```

```text
# 实测
3+5=8
```

**函数内读取脚本参数**：函数内 `$1` 是函数参数，脚本参数要先在函数外存进变量，或调用时显式传入。

```bash
#!/usr/bin/env bash
process() {
    echo "处理文件: $1"
}
# 把脚本参数显式传给函数
process "$1"
```

**可变参数与 shift**：函数内同样能用 `$@`、`$#`、`shift` 处理不定个数参数。

```bash
sum() {
    local total=0
    for n in "$@"; do
        total=$((total + n))
    done
    echo $total
}
echo "总和: $(sum 1 2 3 4 5)"
```

**边界/易错点**：

- 函数里直接用 `$1` 想拿脚本参数会拿错——函数 `$1` 是函数自己的参数，脚本参数要用变量中转。
- 函数参数同样受「第 10 个起要 `${10}`」约束。
- 函数无法直接传「数组」整体，要么传数组元素展开，要么传数组名（bash 4.3+ 用 nameref）。

### 返回值

**是什么**：函数有两种「返回」——`return` 返回退出码（0-255 的整数，用 `$?` 读），`echo` 返回数据（用 `$(函数)` 捕获输出）。

**为什么**：区分两种返回很重要——`return` 只能返回 0-255 的整数（表示成功/失败），要返回字符串、数字结果就得用 `echo` + 命令替换。把两者混用，`$(fun)` 会把 return 的值也当输出。

```text
返回值的两种方式：
1. return N —— 返回退出码，调用方用 $? 判断成功/失败（N 范围 0-255）
2. echo 数据 —— 返回字符串/数值，调用方用 result=$(fun) 捕获
```

**怎么用**：

```bash
check_file() {
    if [ -f "$1" ]; then
        return 0    # 成功
    else
        return 1    # 失败
    fi
}
check_file /etc/hostname && echo "文件存在"
```

```bash
# echo 返回数据
get_upper() {
    echo "${1^^}"
}
name=$(get_upper "alice")
echo "大写: $name"
```

**输出分流（关键）**：`$(fun)` 捕获的是 stdout，函数里的调试信息、日志要写到 stderr（`>&2`），否则会混进返回值。

```bash
fetch() {
    echo "开始请求..." >&2      # 调试信息走 stderr，不进返回值
    echo "请求结果数据"          # 真正的返回值走 stdout
}
data=$(fetch)
echo "捕获到: $data"
```

**边界/易错点**：

- `return 300` 会被对 256 取模，`$?` 读出来是 44；返回大数值用 echo。
- 函数不写 return 时，返回的是函数里最后一条命令的退出码。
- 想返回多个值没有原生语法，常用「echo 多行 + 逐行 read」或「全局变量」兜底（后者要谨慎）。

### 局部变量

**是什么**：函数里默认的变量是全局的，会污染外部作用域；用 `local` 声明局部变量，只在函数内有效。

**为什么**：函数里忘了 local，变量名和外部撞了，脚本行为就诡异——外部变量被意外覆盖，或函数读到了外部的同名变量。这是写函数最容易踩的坑。

**怎么用**：

```bash
greet() {
    local who=$1        # 局部变量，不影响外部
    echo "hello, $who"
}
greet "alice"
# 外部没有 who 变量
echo "外部 who 为空: ${who:-未定义}"
```

```bash
# 对比：不加 local 会污染全局
name="外部"
set_name() {
    name="被函数改了"     # 没加 local，改的是全局 name
}
set_name
echo "name=$name"       # 被函数改了
```

**local 的组合用法**：`local var=$(cmd)` 注意——命令替换的退出码会被 local 吞掉；要保留退出码分开写。

```bash
# 不推荐：local rc=$(false) 后 $? 是 0（local 命令成功）
# 推荐：分开写
some_cmd() { false; }
local rc
some_cmd
rc=$?
```

**边界/易错点**：

- 规则：函数内部的临时变量一律加 local，除非明确要改全局。
- bash 是「动态作用域」——函数能读到调用者的局部变量（`$1` 参数本质上就是这种机制），这跟多数编程语言的「词法作用域」不同。
- `local` 只能用在函数体内，函数外使用会报错。

### 函数库

**是什么**：把常用函数收集到一个文件里，用 `source 文件`（或 `. 文件`）引入，就做成了函数库。

**为什么**：团队里常用的日志函数、错误处理函数、工具函数，放一个 lib.sh 里，各脚本 source 复用，避免每个脚本复制粘贴一份——改 bug 只改一处。

**怎么用**：函数库文件通常只定义不执行。

```bash
# lib.sh —— 函数库
log_info() { echo "[INFO] $(date '+%H:%M:%S') $*"; }
log_error() { echo "[ERROR] $(date '+%H:%M:%S') $*" >&2; }
```

```bash
# 主脚本里 source 引入
source ./lib.sh
log_info "开始部署"
log_error "连接失败"
```

**函数库的约定**：函数名统一前缀避免冲突，只定义不执行（没有顶层语句）。

```bash
# lib.sh 顶部注释说明用途，函数统一 lib_ 前缀
lib_die() { echo "[FATAL] $*" >&2; exit 1; }
lib_confirm() { read -r -p "$* (y/N) " ans; [[ $ans =~ ^[yY]$ ]]; }
```

**边界/易错点**：

- `source` 是「在当前 shell 执行」，lib.sh 的顶层语句会真的执行、全局变量直接进主脚本作用域——所以函数库只放函数定义，不放顶层可执行语句。
- source 不可信脚本等于执行它，有安全风险；函数库来源要可控。
- 函数库路径别写死，用脚本自身目录相对定位：`source "$(dirname "$0")/lib.sh"`。

## 工作原理

函数在 shell 里不是独立的「程序」，而是「当前 shell 里的一段命名代码块」——调用时在当前 shell 执行（不 fork 子进程），所以函数能改全局变量（除非 local）。函数有自己的参数空间（$1 $2 是函数参数），调用结束返回退出码。这与「脚本调用外部命令（fork 子进程）」本质不同。

```text
函数 = 当前 shell 内命名代码块，调用不 fork 子进程
参数：函数内 $1 $2 是函数参数，与脚本参数独立
返回值：return 退出码（$? 读），echo 数据（$(fun) 捕获）
```

bash 的变量作用域是「动态作用域」：函数执行时能看到调用者作用域里的变量（不只是全局变量）。所以函数里能读到调用者 `local` 的变量，这种「向下可见」是 bash 特有，和 Python/Java 的「词法作用域」（只向上找定义处）相反。

```text
动态作用域示意：
a() { local x=1; b; }    # b 里能读到 x=1
b() { echo "x=$x"; }     # 因为 b 在 a 的作用域里被调用
# 若 a 没定义 x，b 会读到全局的 x（如果有）
```

## 常用命令与配置

```shell
myfunc() { ... }         # 定义函数（POSIX 兼容）
function myfunc { ... }  # 另一种定义
myfunc arg1 arg2         # 调用并传参
local var=val            # 声明局部变量
source lib.sh            # 引入函数库
type myfunc              # 查看函数定义
declare -F               # 列出所有函数名
unset -f myfunc          # 删除函数
```

## 配置文件解析

函数本身没有配置文件，函数库是「用 .sh 文件承载的代码复用」——lib.sh 里放纯函数定义，主脚本 source 引入。约定函数库只定义不执行（没有顶层语句），且函数名统一前缀避免冲突。

```text
lib.sh 结构：
# 顶部注释说明用途
log_info() { ... }    # 函数定义
log_error() { ... }
# 不写顶层可执行语句，只在被 source 后提供函数
```

函数库和「配置文件」的边界：配置是键值数据（用 . /etc/os-release 或 source config.sh 读入变量），函数库是逻辑（可执行代码）。两者常一起用——config 存环境、lib 存逻辑、主脚本 source 两者后编排。

```shell
# config.sh —— 数据配置
APP_PORT=8080
APP_ENV=production
```

```shell
# 主脚本：先读配置，再引入函数库，最后编排
source ./config.sh
source ./lib.sh
log_info "以 $APP_ENV 环境启动，端口 $APP_PORT"
```

## 应用场景实战

### 场景一：封装一个带重试的下载函数

```bash
#!/usr/bin/env bash
download() {
    local url=$1 dest=$2 max_retry=${3:-3}
    local attempt=0
    while [ $attempt -lt $max_retry ]; do
        if curl -fsSL "$url" -o "$dest"; then
            echo "下载成功: $dest"
            return 0
        fi
        attempt=$((attempt + 1))
        echo "第 $attempt 次重试..." >&2
        sleep 2
    done
    echo "下载失败: $url" >&2
    return 1
}

download "https://example.com/app.tar.gz" "/tmp/app.tar.gz" 3
```

### 场景二：函数库 + 主脚本分离的巡检框架

```bash
#!/usr/bin/env bash
# 主脚本：巡检框架
source ./lib.sh

check_disk() {
    local usage=$(df / | awk 'NR==2 {print $5}' | tr -d '%')
    [ "$usage" -ge 80 ] && log_error "磁盘使用率 $usage%" || log_info "磁盘正常 $usage%"
}
check_disk
```

### 场景三：递归统计目录大小的函数

递归是函数的进阶用法——函数内部调用自身，靠「终止条件 + 子问题」两段控制，处理树形结构（目录、菜单）最自然。

```bash
#!/usr/bin/env bash
# 递归累加目录（含子目录）里所有文件的大小，单位 KB
dir_size() {
    local d=$1 total=0
    local f
    for f in "$d"/*; do
        if [ -d "$f" ]; then
            # 子目录递归累加
            local sub=$(dir_size "$f")
            total=$((total + sub))
        elif [ -f "$f" ]; then
            total=$((total + $(du -k "$f" | cut -f1)))
        fi
    done
    echo $total
}

echo "目录总大小: $(dir_size /etc) KB"
```

```text
递归三要素：
1. 终止条件 —— 目录里没有子目录时不再递归（for 循环自然结束）
2. 子问题 —— 子目录大小 = 递归调用 dir_size 子目录
3. 返回值 —— 每层用 echo 返回本层大小，上层用 $( ) 捕获累加
```

## 性能与调优

```text
1. 函数调用几乎零开销（不 fork），放心拆小函数
2. 避免在函数里反复调外部命令，能内置就内置
3. 递归要设终止条件，shell 递归深了易爆栈
4. 函数输出用 printf 比多次 echo 拼更快（少开几次写）
5. 高频调用的函数里，把命令替换结果算好存变量，别每次进函数都重新算
```

## 安全与权限

```text
1. 函数库 source 前确认来源可信，别 source 不可信脚本（等于执行它）
2. 函数名别和系统命令重名，否则遮蔽命令
3. 返回值用 return 表示成败，别用 echo 返回状态（会被 $(fun) 捕获污染）
4. 函数里别直接 eval 未验证参数，参数进 eval/rm 前先校验
5. 递归函数要设深度上限，防止恶意输入导致无限递归耗尽资源
```

## 故障排查

```shell
bash -x script.sh      # 追踪函数进入/返回、变量值
# 常见：函数未定义就调用（定义顺序）、local 放错位置
set -u                 # 抓函数里拼错的变量名
declare -f myfunc      # 查看函数实际定义，确认没被覆盖
```

```text
常见故障速查：
函数报 command not found → 定义在调用之后，或函数库没 source
函数改了变量外面也变 → 函数内变量默认全局，用 local 声明
$(fun) 捕获到调试信息 → 调试 echo 应写到 stderr（>&2）
函数返回值超出 255 → return 对 256 取模，大数值用 echo
```

## 常见问题

```text
Q1: 函数报 command not found？
A: 函数定义在调用之后（shell 顺序执行），或函数库没 source。

Q2: 函数里改的变量，外面也变了？
A: 函数内变量默认全局，要局部用 local 声明。

Q3: return 300 为什么 $? 是 44？
A: return 退出码范围 0-255，超出对 256 取模；返回大数值用 echo。

Q4: $(fun) 捕获到了调试信息？
A: 命令替换捕获 stdout，调试 echo 应写到 stderr（>&2）。

Q5: 函数里怎么读脚本的参数？
A: 函数内 $1 是函数参数；脚本参数要在函数外存进变量，或调用时显式传入。

Q6: 函数怎么返回多个值？
A: 没有原生语法；常用 echo 多行输出后逐行 read，或用全局变量（要谨慎、明确注释）。

Q7: local var=$(cmd) 有什么坑？
A: 命令替换的退出码会被 local 吞掉，$? 变成 local 命令的退出码（0）；要保留退出码就分开写。

Q8: source 函数库和直接执行函数库脚本有什么区别？
A: source 在当前 shell 执行，函数和变量留下来可用；直接执行会 fork 子进程，函数不会留在当前 shell。
```

## 面试题

```text
1. 函数返回值的两种方式？
   答：return 返回退出码（0-255，$? 读），echo 返回数据（$(fun) 捕获）。

2. 为什么函数内要 local？
   答：默认变量全局，local 限定函数作用域，防止污染外部同名变量。

3. source 和执行脚本的区别？
   答：source 在当前 shell 执行（函数/变量留下来），执行脚本 fork 子进程（不留在当前）。

4. 函数参数和脚本参数怎么区分？
   答：函数内 $1 $2 是函数参数；脚本参数在函数外读取，或调用前存到变量里。

5. 函数不写 return 时返回什么？
   答：返回函数里最后一条命令的退出码。

6. bash 的变量作用域是词法还是动态？
   答：动态作用域——函数能读到调用者的局部变量，与 Python/Java 的词法作用域相反。

7. return 的退出码范围是多少？超出会怎样？
   答：0-255，超出对 256 取模（return 300 实际 $? 是 44）；返回大数值用 echo。

8. $(fun) 为什么会捕获到不该有的内容？
   答：命令替换捕获函数所有 stdout，调试/日志 echo 应写 stderr（>&2），stdout 只留真正的返回值。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 函数内部临时变量一律加 local，防止污染全局
2. 要返回数据用 echo + $(fun) 捕获，要返回状态用 return + $? 判断
3. 重复出现两次以上的逻辑就抽函数，三次以上必须抽
4. 常用函数收进 lib.sh，用 source 复用，别到处复制粘贴
5. 函数命名用下划线小写（log_info、check_disk），别用短而无意义的名字
6. 调试/日志输出统一走 stderr（>&2），stdout 只留函数真正的返回值
7. 函数库用统一前缀（lib_）避免和主脚本、其他库函数冲突

### 踩坑记录

```text
坑 1：函数里改了全局变量，外面跟着变
结论：函数里 x=1 赋值后，函数外 $x 也变成了 1。
原因：函数内不加 local 的变量是全局的，赋值影响整个脚本。
解法：函数内部变量一律 local，除非明确要改全局。

坑 2：return 返回了超过 255 的值被截断
结论：return 300 后 $? 读出来是 44（300 对 256 取模）。
原因：return 的退出码范围是 0-255，超出会截断。
解法：返回大数值用 echo + $(fun) 捕获，return 只用来表示成功/失败。

坑 3：$(fun) 捕获了函数里所有 echo 输出
结论：函数里 echo 调试信息也进了 $(fun) 的捕获结果。
原因：命令替换捕获函数的所有 stdout，包括调试 echo。
解法：调试信息 echo 到 stderr（>&2），stdout 只输出真正要返回的数据。

坑 4：函数没定义就调用报 command not found
结论：调用函数报 command not found。
原因：函数定义在调用之后（shell 顺序执行），或函数库没 source。
解法：函数定义放调用前，函数库用 source 引入且放脚本开头。

坑 5：source 引入的函数库和主脚本变量冲突
结论：lib.sh 里的变量和主脚本变量互相覆盖。
原因：source 是「在当前 shell 执行」，lib.sh 的全局变量直接进主脚本作用域。
解法：函数库里变量用 local 或命名加前缀（如 LIB_xxx）避免冲突。

坑 6：函数里直接拿 $1 想读脚本参数却读到函数参数
结论：函数里 echo $1 输出的是函数参数，不是脚本的第一个参数。
原因：函数有独立的参数空间，函数内 $1 是函数自己的参数。
解法：脚本参数在函数外存进变量，或调用函数时显式传入（myfunc "$1"）。

坑 7：local var=$(cmd) 丢失了命令的退出码
结论：local rc=$(false) 之后 $? 是 0，误判命令成功。
原因：命令替换的结果先算，但 local 命令本身成功、把 $? 覆盖成 0。
解法：分开写——local rc; rc=$(cmd)（或先赋值临时变量，再 local 声明）。
```

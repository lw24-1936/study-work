## 概述

函数把重复的逻辑封装成可复用的单元。脚本越写越长，重复代码越来越多，就该抽函数了——定义一次、到处调用。函数的关键概念：定义、参数传递（函数有自己独立的 $1 $2）、返回值（return 退出码 vs echo 输出）、局部变量（local）、函数库（source 复用）。掌握这五个，脚本就能模块化。

```text
函数五要素：
1. 定义 —— name() { ... } 或 function name { ... }
2. 参数 —— 函数内的 $1 $2 是函数参数，不是脚本参数
3. 返回 —— return 返回退出码（0-255），echo 返回数据（用 $(fun) 捕获）
4. 局部变量 —— local 声明，只在函数内可见
5. 函数库 —— 把函数写进单独文件，source 引入复用
```

## 核心概念

函数的五个核心概念：定义、参数、返回、局部变量、函数库。下面逐一展开。

### 函数定义

函数定义两种写法：`name() { ... }`（推荐，POSIX 兼容）和 `function name { ... }`。定义后像命令一样调用。函数体里写任何 shell 语句。函数必须在调用前定义（shell 是顺序执行的），所以函数库文件都放脚本开头 source。

```bash
greet() {
    echo "hello, $1"
}
greet "alice"
greet "bob"
```

```text
# 实测
hello, alice
hello, bob
```

### 参数传递

函数有自己独立的参数空间：函数内的 `$1 $2 $# $@` 指的是传给函数的参数，不是传给脚本的。脚本的 `$1` 和函数里的 `$1` 互不影响。调用时 `函数名 参数1 参数2`，函数内用 `$1 $2` 接收。这是函数复用性的来源——同一个函数能处理不同的输入。

```bash
add() {
    echo $(( $1 + $2 ))
}
result=$(add 3 5)
echo "3+5=$result"
```

```text
# 实测
3+5=8
```

### 返回值

函数有两种「返回」：`return` 返回退出码（0-255 的整数，用 `$?` 读），`echo` 返回数据（用 `$(函数)` 捕获输出）。区分很重要——`return` 只能返回 0-255 的整数（表示成功/失败），要返回字符串、数字结果就得用 `echo` + 命令替换。别把两者混用，否则 `$(fun)` 会把 return 的值也当输出。

```text
返回值的两种方式：
1. return N —— 返回退出码，调用方用 $? 判断成功/失败（N 范围 0-255）
2. echo 数据 —— 返回字符串/数值，调用方用 result=$(fun) 捕获
```

```bash
check_file() {
    if [ -f "$1" ]; then
        return 0    # 成功
    else
        return 1    # 失败
    fi
}
check_file /etc/hostname && echo "文件存在"
```

### 局部变量

函数里默认的变量是全局的，会污染外部作用域；用 `local` 声明局部变量，只在函数内有效。这是写函数最容易踩的坑——函数里忘了 local，变量名和外部撞了，脚本行为就诡异。规则：函数内部的临时变量一律加 local。

```bash
greet() {
    local who=$1        # 局部变量，不影响外部
    echo "hello, $who"
}
greet "alice"
# 外部没有 who 变量
echo "外部 who 为空: ${who:-未定义}"
```

### 函数库

把常用函数收集到一个文件里，用 `source 文件`（或 `. 文件`）引入，就做成了函数库。团队里常用的日志函数、错误处理函数、工具函数，放一个 lib.sh 里，各脚本 source 复用，避免每个脚本复制粘贴一份。函数库文件通常只定义不执行。

```bash
# lib.sh —— 函数库
log_info() { echo "[INFO] $(date '+%H:%M:%S') $*"; }
log_error() { echo "[ERROR] $(date '+%H:%M:%S') $*" >&2; }
```

```bash
# 主脚本里 source 引入
source ./lib.sh
log_info "开始部署"
log_error "连接失败"
```

## 工作原理

函数在 shell 里不是独立的「程序」，而是「当前 shell 里的一段命名代码块」——调用时在当前 shell 执行（不 fork 子进程），所以函数能改全局变量（除非 local）。函数有自己的参数空间（$1 $2 是函数参数），调用结束返回退出码。这与「脚本调用外部命令（fork 子进程）」本质不同。

```text
函数 = 当前 shell 内命名代码块，调用不 fork 子进程
参数：函数内 $1 $2 是函数参数，与脚本参数独立
返回值：return 退出码（$? 读），echo 数据（$(fun) 捕获）
```

## 常用命令与配置

```shell
myfunc() { ... }         # 定义函数（POSIX 兼容）
function myfunc { ... }  # 另一种定义
myfunc arg1 arg2         # 调用并传参
local var=val            # 声明局部变量
source lib.sh            # 引入函数库
```

## 配置文件解析

函数本身没有配置文件，函数库是「用 .sh 文件承载的代码复用」——lib.sh 里放纯函数定义，主脚本 source 引入。约定函数库只定义不执行（没有顶层语句），且函数名统一前缀避免冲突。

```text
lib.sh 结构：
# 顶部注释说明用途
log_info() { ... }    # 函数定义
log_error() { ... }
# 不写顶层可执行语句，只在被 source 后提供函数
```

## 应用场景实战

### 场景一：封装一个带重试的下载函数

```bash
#!/usr/bin/env bash
download() {
    local url=$1 dest=$2 max_retry=${3:-3}
    local attempt=0
    while [ $attempt -lt $max_retry ]; do
        if curl -fsSL "$url" -o "$dest"; then
            echo "下载成功: $dest"
            return 0
        fi
        attempt=$((attempt + 1))
        echo "第 $attempt 次重试..."
        sleep 2
    done
    echo "下载失败: $url" >&2
    return 1
}

download "https://example.com/app.tar.gz" "/tmp/app.tar.gz" 3
```

### 场景二：函数库 + 主脚本分离的巡检框架

```bash
#!/usr/bin/env bash
# 主脚本：巡检框架
source ./lib.sh

check_disk() {
    local usage=$(df / | awk 'NR==2 {print $5}' | tr -d '%')
    [ "$usage" -ge 80 ] && log_error "磁盘使用率 $usage%" || log_info "磁盘正常 $usage%"
}
check_disk
```

## 性能与调优

```text
1. 函数调用几乎零开销（不 fork），放心拆小函数
2. 避免在函数里反复调外部命令，能内置就内置
3. 递归要设终止条件，shell 递归深了易爆栈
4. 函数输出用 printf 比多次 echo 拼更快（少开几次写）
```

## 安全与权限

```text
1. 函数库 source 前确认来源可信，别 source 不可信脚本（等于执行它）
2. 函数名别和系统命令重名，否则遮蔽命令
3. 返回值用 return 表示成败，别用 echo 返回状态（会被 $(fun) 捕获污染）
```

## 故障排查

```shell
bash -x script.sh      # 追踪函数进入/返回、变量值
# 常见：函数未定义就调用（定义顺序）、local 放错位置
set -u                 # 抓函数里拼错的变量名
```

## 常见问题

```text
Q1: 函数报 command not found？
A: 函数定义在调用之后（shell 顺序执行），或函数库没 source。

Q2: 函数里改的变量，外面也变了？
A: 函数内变量默认全局，要局部用 local 声明。

Q3: return 300 为什么 $? 是 44？
A: return 退出码范围 0-255，超出对 256 取模；返回大数值用 echo。

Q4: $(fun) 捕获到了调试信息？
A: 命令替换捕获 stdout，调试 echo 应写到 stderr（>&2）。
```

## 面试题

```text
1. 函数返回值的两种方式？
   答：return 返回退出码（0-255，$? 读），echo 返回数据（$(fun) 捕获）。

2. 为什么函数内要 local？
   答：默认变量全局，local 限定函数作用域，防止污染外部同名变量。

3. source 和执行脚本的区别？
   答：source 在当前 shell 执行（函数/变量留下来），执行脚本 fork 子进程（不留在当前）。

4. 函数参数和脚本参数怎么区分？
   答：函数内 $1 $2 是函数参数；脚本参数在函数外读取，或调用前存到变量里。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 函数内部临时变量一律加 local，防止污染全局
2. 要返回数据用 echo + $(fun) 捕获，要返回状态用 return + $? 判断
3. 重复出现两次以上的逻辑就抽函数，三次以上必须抽
4. 常用函数收进 lib.sh，用 source 复用，别到处复制粘贴
5. 函数命名用下划线小写（log_info、check_disk），别用短而无意义的名字

### 踩坑记录

```text
坑 1：函数里改了全局变量，外面跟着变
结论：函数里 x=1 赋值后，函数外 $x 也变成了 1。
原因：函数内不加 local 的变量是全局的，赋值影响整个脚本。
解法：函数内部变量一律 local，除非明确要改全局。

坑 2：return 返回了超过 255 的值被截断
结论：return 300 后 $? 读出来是 44（300 对 256 取模）。
原因：return 的退出码范围是 0-255，超出会截断。
解法：返回大数值用 echo + $(fun) 捕获，return 只用来表示成功/失败。

坑 3：$(fun) 捕获了函数里所有 echo 输出
结论：函数里 echo 调试信息也进了 $(fun) 的捕获结果。
原因：命令替换捕获函数的所有 stdout，包括调试 echo。
解法：调试信息 echo 到 stderr（>&2），stdout 只输出真正要返回的数据。

坑 4：函数没定义就调用报 command not found
结论：调用函数报 command not found。
原因：函数定义在调用之后（shell 顺序执行），或函数库没 source。
解法：函数定义放调用前，函数库用 source 引入且放脚本开头。

坑 5：source 引入的函数库和主脚本变量冲突
结论：lib.sh 里的变量和主脚本变量互相覆盖。
原因：source 是「在当前 shell 执行」，lib.sh 的全局变量直接进主脚本作用域。
解法：函数库里变量用 local 或命名加前缀（如 LIB_xxx）避免冲突。
```

## 概述

数组和字符串处理是脚本处理「一批数据」和「文本变换」的核心。数组分一维数组（下标数字）和关联数组（下标字符串，类似字典）；字符串处理靠「参数扩展」——bash 内置的一整套 `${var...}` 语法，能做截取、去前后缀、替换、默认值、大小写转换。这些语法不用调用外部命令（sed/awk），脚本里就地完成、速度快。

```text
三类核心能力：
1. 一维数组 —— arr=(a b c)，${arr[0]} 取值、${arr[@]} 全部、${#arr[@]} 长度
2. 关联数组 —— declare -A map，map[key]=val，${map[key]} 取值
3. 参数扩展 —— ${s:pos:len} 截取、${s#prefix} 去前缀、${s%suffix} 去后缀、${s/old/new} 替换
```

## 核心概念

三类核心能力：一维/关联数组、字符串截取替换、参数扩展。下面三个小节逐一展开。

### 一维与关联数组

一维数组用 `arr=(元素...)` 定义，下标从 0 开始，`${arr[0]}` 取第一个、`${arr[@]}` 取全部、`${#arr[@]}` 取长度。关联数组要先 `declare -A` 声明，下标是字符串，`map[key]=value` 赋值、`${map[key]}` 取值——适合做「名字到值」的映射，比如配置项、计数器。关联数组是 bash 4+ 特性，老系统注意兼容。

```bash
arr=(apple banana cherry)
echo "一维数组全部: ${arr[@]}"
echo "第1个元素: ${arr[0]}   数组长度: ${#arr[@]}"

declare -A map
map[name]=alice
map[age]=30
echo "关联数组: name=${map[name]} age=${map[age]}"
```

```text
# 实测
一维数组全部: apple banana cherry
第1个元素: apple   数组长度: 3
关联数组: name=alice age=30
```

为什么要用数组而不是一堆独立变量：数组能「一批处理」——循环遍历、批量追加、一次取长度。一维数组的下标是整数，元素按顺序排；关联数组的下标是任意字符串，适合「按名字找值」。两者的共同边界是「元素里含空格必须加引号」，否则 `arr=(a b)` 会拆成两个元素。

一维数组还有几个高频操作：追加、切片、删除元素、取下标集合。

```bash
arr=(a b c)
arr+=(d e)                      # 追加两个元素
echo "追加后: ${arr[@]}  长度: ${#arr[@]}"
echo "切片 第2个起取2个: ${arr[@]:1:2}"
echo "所有下标: ${!arr[@]}"
unset 'arr[0]'                  # 删除第 0 个元素（留空洞）
echo "删第0个后: ${arr[@]}  下标变成: ${!arr[@]}"
```

```text
# 示例输出
追加后: a b c d e  长度: 5
切片 第2个起取2个: b c
所有下标: 0 1 2 3 4
删第0个后: b c d e  下标变成: 1 2 3 4
```

关联数组的关键操作是「遍历所有 key」「判断 key 是否存在」：

```bash
declare -A map
map[name]=alice
map[age]=30
map[city]=beijing
echo "所有 key: ${!map[@]}"
echo "所有 value: ${map[@]}"
echo "key 数量: ${#map[@]}"
# 判断 key 是否存在（bash 4.2+）
[[ -v map[name] ]] && echo "name 存在" || echo "name 不存在"
[[ -v map[email] ]] && echo "email 存在" || echo "email 不存在"
```

```text
# 示例输出
所有 key: city name age
所有 value: beijing alice 30
key 数量: 3
name 存在
email 不存在
```

要点：关联数组的 key 遍历顺序不保证（哈希表），需要有序遍历时先把 key 排序再取。`${!map[@]}` 拿 key、`${map[@]}` 拿 value，二者下标一一对应。

### 字符串截取与替换

字符串处理全靠参数扩展语法：`${s:pos:len}` 从 pos 起截 len 个字符、`${s:pos}` 从 pos 到末尾、`${#s}` 长度、`${s#prefix}` 去掉最短前缀、`${s##prefix}` 去掉最长前缀、`${s%suffix}` 去掉最短后缀、`${s%%suffix}` 去掉最长后缀、`${s/old/new}` 替换第一个、`${s//old/new}` 替换全部。这套语法是脚本里处理路径、文件名、字符串的主力。

```bash
s="hello world"
echo "截取前5个: ${s:0:5}   从第6个起: ${s:6}   总长度: ${#s}"
echo "去前缀: ${s#hello }   去后缀: ${s% world}   替换: ${s/world/linux}"
```

```text
# 实测
截取前5个: hello   从第6个起: world   总长度: 11
去前缀: world   去后缀: hello   替换: hello linux
```

为什么用参数扩展而不是 sed/awk：它在当前 shell 内完成，不 fork 子进程、不用管道，处理路径和文件名这种高频小操作时快一个量级。边界是「pattern 用通配符语义而非正则」——`${s#*_}` 里的 `*` 是 glob 通配符，不是正则 `.*`。

补充几个高频但容易漏的用法：负偏移截取、按通配符去前后缀、锚定首尾的替换、大小写转换。

```bash
s="hello world"
echo "从倒数第5个起: ${s: -5}"        # 负偏移，注意冒号后要留空格
echo "去最长前缀: ${s##*.}"           # 贪婪去前缀（配合路径用）
echo "去最长后缀: ${s%%.*}"           # 贪婪去后缀
echo "全部替换: ${s//o/0}"
echo "只替换开头: ${s/#hello/HI}   只替换结尾: ${s/%world/END}"
echo "全大写: ${s^^}   全小写: ${s,,}"
```

```text
# 示例输出
从倒数第5个起: world
去最长前缀: hello world
去最长后缀: hello world
全部替换: hell0 w0rld
只替换开头: HI world   只替换结尾: hello END
全大写: HELLO WORLD   全小写: hello world
```

要点：`${s: -5}` 负偏移的冒号和负号之间必须有空格（否则被当成 `${s:-5}` 默认值语法）；`${s^^}`/`${s,,}` 是 bash 4+ 特性；`${s/#pat/}` 和 `${s/%pat/}` 用 `#`/`%` 前缀锚定字符串首尾，是「只改头/只改尾」的常用手段。

### 参数扩展

参数扩展提供「变量默认值」类的能力：`${var:-默认}` 变量为空/未定义时用默认值（不改 var）、`${var:=默认}` 为空时赋默认值并返回（会改 var）、`${var:?错误信息}` 为空时报错退出、`${var:+替代}` 非空时返回替代值。这些语法让脚本在「变量可能没设置」的场景下健壮——尤其 `${1:?用法}` 强制参数非空，是写脚本的常用 guard。

```bash
unset x
echo "默认值: ${x:-default}"      # 返回 default，x 仍是空
echo "仍为空: ${x:-empty}"
```

```text
# 实测
默认值: default
仍为空: empty
# ${x:-default} 只返回默认值不赋值；${x:=default} 会真正给 x 赋值
```

为什么需要这套语法：脚本里大量变量「可能没设置」（用户没传参数、环境变量没 export、命令输出为空），直接 `$var` 在 `set -u` 下会报错、不报错则拿到空值继续跑。默认值语法把「兜底」写进一行，是写健壮脚本的基本功。

完整梳理四个默认值变体和间接引用：

```bash
unset a
echo ":- (空/未定义兜底): ${a:-DEFAULT}"       # 返回 DEFAULT，不改 a
echo ":= (兜底并赋值):   ${a:=SET}"            # 返回 SET，并把 a 赋成 SET
echo "现在 a = ${a:-空}"
unset b
echo ":? (空即报错): ${b:?变量 b 未设置}"        # 报错退出，这里会中断脚本
```

```text
# 示例输出（注意 :? 那行会报错中断，这里单独演示）
:- (空/未定义兜底): DEFAULT
:= (兜底并赋值):   SET
现在 a = SET
bash: b: 变量 b 未设置
```

`${var:+替代}` 是反向的——var 非空才返回「替代」，常用来做「有值才追加前缀」：

```bash
prefix="prod"
echo "环境: ${prefix:+[$prefix]}环境"
unset prefix
echo "环境: ${prefix:+[$prefix]}环境"     # prefix 空，什么都不追加
```

```text
# 示例输出
环境: [prod]环境
环境: 环境
```

间接引用 `${!name}` 是「变量名存变量里，再取该变量的值」，配置文件解析和动态变量名场景会用到：

```bash
var_name="HOME"
echo "间接引用 HOME: ${!var_name}"       # 取 $var_name 指向的变量的值
```

```text
# 示例输出
间接引用 HOME: /root
```

## 工作原理

参数扩展 `${...}` 是 bash 内置的「字符串求值器」——不调外部命令，直接在当前 shell 里完成截取/替换/默认值，所以快。数组在 bash 里是「带数字/字符串下标的变量集合」，关联数组（declare -A）底层是哈希表，下标是字符串。这些操作都在 shell 内部完成，不 fork。

```text
参数扩展 = 内置字符串求值，不调外部命令（快）
${s:pos:len} 截取 / ${s#p} 去前缀 / ${s/old/new} 替换 / ${var:-d} 默认值
一维数组 arr=(...) 数字下标；关联数组 declare -A 字符串下标（哈希）
```

参数扩展的解析顺序是固定的：先做 `{}` 内的操作符匹配（`:-` `:=` `:?` `:+` `#` `##` `%` `%%` `/`），再按操作符语义对变量值做变换，最后把结果展开回命令。这套流程全在 bash 内部完成，不产生子进程——这是它比 `sed`/`awk`/`basename` 快的原因。

```text
几个「内部实现」细节：
1. 数组下标「无空洞」时连续 0..n-1；unset 某个元素后留空洞，${!arr[@]} 能看出真实下标
2. 关联数组是哈希表，遍历 ${!map[@]} 的顺序不保证，和插入顺序无关
3. ${s: -n} 负偏移是「从末尾倒数」，${s:pos:len} 里 pos/len 都支持算术表达式（${s:$((i+1)):2}）
4. ${#s} 取的是「字符数」不是字节数，中文等多字节字符按字符算
```

```bash
# 算术下标 + 字符数按字符算的验证
s="abc你好"
echo "字符数(应为5): ${#s}"
i=1
echo "算术切片(第2个起取2): ${s:$((i+1)):2}"
```

```text
# 示例输出
字符数(应为5): 5
算术切片(第2个起取2): c你
```

## 常用命令与配置

```shell
arr=(a b c)            # 定义一维数组
arr+=(d)               # 追加元素
declare -A map         # 定义关联数组
echo "${arr[@]}"       # 全部元素
echo "${#arr[@]}"      # 数组长度
echo "${!arr[@]}"      # 所有下标（一维）/ 所有 key（关联）
echo "${s:0:5}"        # 截取
echo "${s#prefix}"     # 去最短前缀
echo "${s##prefix}"    # 去最长前缀
echo "${s%suffix}"     # 去最短后缀
echo "${s/old/new}"    # 替换第一个
echo "${s//old/new}"   # 替换全部
echo "${s^^}"          # 全大写
echo "${s,,}"          # 全小写
echo "${var:-默认}"     # 空/未定义时兜底
echo "${var:?报错}"     # 空/未定义时报错退出
echo "${!name}"        # 间接引用
```

```text
常用命令速记：
- 取元素 ${arr[i]}，取全部 ${arr[@]}，取长度 ${#arr[@]}，取下标 ${!arr[@]}
- 截取 ${s:pos:len}，长度 ${#s}，去前后缀 ${s#p}/${s%p}，替换 ${s/old/new}
- 默认值 ${var:-d}/${var:=d}，报错 ${var:?msg}，反向 ${var:+alt}，间接 ${!name}
```

## 配置文件解析

数组/字符串处理不直接对应配置文件，但常用来解析配置——用 while read 逐行读配置文件，用参数扩展拆分 KEY=VALUE、去注释、去空白。

```text
解析 KEY=VALUE 配置：
while IFS='=' read -r k v; do
  k=${k%% *}            # 去尾部空白
  case $k in \#*) continue;; esac   # 跳过注释
  config["$k"]=$v       # 存进关联数组
done < config.ini
```

下面是完整可运行的「解析 .ini 风格配置」示例，覆盖去注释、去空白、存关联数组、按 key 取值：

```bash
#!/usr/bin/env bash
# 解析 KEY=VALUE 配置到关联数组
declare -A config

parse_config() {
    local file=$1
    while IFS='=' read -r key value; do
        # 去首尾空白
        key=${key// /}
        value=${value// /}
        # 跳过空行和注释行
        [[ -z "$key" || "$key" == \#* ]] && continue
        # 去掉行内注释（# 之后的部分）
        value=${value%%\#*}
        config["$key"]="$value"
    done < "$file"
}

cat > /tmp/app.conf <<'EOF'
# 应用配置
name = myapp
port = 8080
debug = true
EOF

parse_config /tmp/app.conf
echo "name = ${config[name]}"
echo "port = ${config[port]}"
echo "debug = ${config[debug]}"
```

```text
# 示例输出
name = myapp
port = 8080
debug = true
```

## 应用场景实战

### 场景一：批量处理文件时用数组收集结果

```bash
#!/usr/bin/env bash
# 找出大文件，用数组收集后统一处理
big_files=()
while IFS= read -r f; do
    big_files+=("$f")
done < <(find /var/log -type f -size +50M 2>/dev/null)

echo "找到 ${#big_files[@]} 个大文件："
for f in "${big_files[@]}"; do
    echo "  $f"
done
```

### 场景二：解析路径和文件名

```bash
#!/usr/bin/env bash
path="/var/log/nginx/access.log"
echo "目录: ${path%/*}"           # /var/log/nginx（去最短后缀，即文件名）
echo "文件名: ${path##*/}"        # access.log（去最长前缀，即目录）
echo "扩展名: ${path##*.}"        # log
echo "去扩展名: ${path%.*}"       # /var/log/nginx/access
```

### 场景三：用关联数组统计日志里的状态码计数

```bash
#!/usr/bin/env bash
# 统计 access.log 里每个 HTTP 状态码出现次数
declare -A status_count

log_file=${1:-/var/log/nginx/access.log}
while read -r _ _ _ _ _ _ _ _ code _; do
    status_count["$code"]=$(( ${status_count["$code"]:-0} + 1 ))
done < "$log_file"

# 按状态码排序输出
echo "状态码统计（从高到低）："
for code in "${!status_count[@]}"; do
    echo "${status_count[$code]} $code"
done | sort -rn
```

```text
这个场景用关联数组做计数器：${status_count["$code"]:-0} 在首次遇到某状态码时兜底为 0，
再 +1 累计。最后 sort -rn 按次数降序排，一眼看出哪个状态码最多。
```

## 性能与调优

```text
1. 字符串处理用参数扩展，比 sed/awk 少开子进程
2. 关联数组 O(1) 查找，适合做「键值查找/计数」，别用线性遍历
3. 大数组追加 arr+=(x) 比 arr=("${arr[@]}" x) 快
4. 循环里重复 ${#s} 长度不变时可先存变量
5. 字符串拼接循环里用 s+="..." 追加，比每次 s="$s..." 新建字符串快（bash 就地扩展）
6. 遍历关联数组前先 sort 拿稳定顺序，避免哈希序导致输出抖动
```

## 安全与权限

```text
1. 关联数组 key 来自外部输入时，注意 key 含特殊字符（空格/换行）
2. 用 ${var:?} 强制变量非空，避免空值拼进路径
3. 处理用户输入文件名时用参数扩展去路径（防路径穿越）
4. 数组/变量存敏感信息（token/密码）时，用完后 unset 清除，别留在环境里
5. 解析外部配置文件到关联数组时，value 里可能含命令替换 $() 或反引号——存值不执行，但后续 eval 时要注意
6. set -u 下访问可能不存在的关联数组 key，用 ${map[key]:-} 兜底，别裸 ${map[key]}
```

## 故障排查

```shell
declare -p arr         # 查看数组完整内容（调试）
declare -p map         # 查看关联数组完整内容
# 常见：关联数组没 declare -A、数组下标越界返回空不报错
set -u                 # 让未定义变量报错
```

```text
排错思路：
1. 数组值不对 → declare -p arr 看实际存了什么（含下标是否有空洞）
2. 关联数组取不到值 → 先确认 declare -A 了没有；再 echo "${!map[@]}" 看 key 是否真是你写的样子
3. 字符串截取结果不对 → 用 echo "${s#x}" 逐个试 pattern，注意是 glob 不是正则
4. 变量展开成空 → set -u 打开看是不是变量名拼错；${var:-默认} 是不是误用了单冒号
5. 遍历数组被拆断 → 看遍历时加没加引号 "${arr[@]}"
```

## 常见问题

```text
Q1: 关联数组 map[key]=v 报错？
A: 没 declare -A map，先声明关联数组。

Q2: ${arr[@]} 遍历元素被拆断？
A: 加引号 "${arr[@]}"，否则含空格元素被拆。

Q3: ${var:-默认} 不改变量？
A: - 只返回默认值，要「返回并赋值」用 ${var:=默认}。

Q4: ${s#p} 去前缀没去干净？
A: 单 # 去最短匹配，贪婪用双 ##（${s##p}）。

Q5: 怎么取数组的「全部下标」或关联数组的「全部 key」？
A: ${!arr[@]} 取一维数组所有下标，${!map[@]} 取关联数组所有 key。

Q6: 数组元素含空格怎么定义？
A: 元素加引号 arr=("a b" "c d")，遍历时也必须 "${arr[@]}"。

Q7: ${s: -3} 和 ${s:-3} 有什么区别？
A: 前者是「从倒数第 3 个字符截到末尾」（负偏移，冒号后必须空格），后者是「s 为空时返回默认值 -3」。

Q8: 怎么判断关联数组里某个 key 是否存在？
A: [[ -v map[key] ]]（bash 4.2+），或 [[ -n ${map[key]+_} ]]（兼容老版本）。
```

## 面试题

```text
1. 一维数组和关联数组的区别？
   答：一维数组数字下标，关联数组（declare -A）字符串下标，bash 4+ 支持。

2. ${var:-x} 和 ${var:=x} 的区别？
   答：- 只返回默认值不改 var，= 返回并赋值给 var。

3. 怎么去掉字符串的前后缀？
   答：${s#prefix} 去最短前缀、${s##prefix} 去最长前缀、${s%suffix} 去最短后缀、${s%%suffix} 去最长后缀。

4. 遍历数组为什么加引号？
   答："${arr[@]}" 每个元素独立保留，不加引号按空白拆分。

5. ${s//old/new} 和 ${s/old/new} 的区别？
   答：双斜杠替换所有匹配，单斜杠只替换第一个。

6. 怎么取字符串长度？中文字符怎么算？
   答：${#s} 取长度，按「字符」算不按字节——中文等多字节字符算 1 个字符。

7. ${s#pattern} 里的 pattern 是正则还是通配符？
   答：是 glob 通配符（* ? [...]），不是正则表达式。

8. 间接引用 ${!name} 是什么？什么时候用？
   答：name 变量里存另一个变量名，${!name} 取那个变量的值；配置解析、动态变量名场景用。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 遍历数组用 for f in "${arr[@]}"，加引号防元素含空格被拆
2. 解析路径/文件名用参数扩展（${path##*/}），比 basename/dirname 快且不用子进程
3. 关联数组用 declare -A，适合「键值映射」，但注意 bash 4+ 才有
4. 变量可能为空时用 ${var:-默认} 给兜底，强制非空用 ${var:?错误}
5. 字符串处理优先参数扩展，sed/awk 留给复杂场景
6. 追加数组用 arr+=(x)，删除元素用 unset 'arr[i]'
7. 关联数组做计数器时用 ${map[k]:-0} 兜底再 +1，避免首次访问报空

### 踩坑记录

```text
坑 1：遍历数组用 ${arr[@]} 不加引号，元素含空格被拆
结论：arr=("a b" "c d") 遍历时被拆成 a、b、c、d 四个。
原因：${arr[@]} 不加引号会按空白重新分词。
解法：始终用 "${arr[@]}" 加引号遍历。

坑 2：关联数组没 declare -A 声明
结论：map[key]=val 当普通数组用，key 被当成下标 0。
原因：不 declare -A 就是普通数组，字符串下标不生效。
解法：关联数组必须先 declare -A map。

坑 3：${s#prefix} 和 ${s##prefix} 混淆
结论：想贪婪去前缀却用了单 #，结果没去干净。
原因：单 # 去掉「最短」匹配，双 ## 去掉「最长」匹配。
解法：路径去目录用 ${path##*/}（最长前缀），去文件名用 ${path%/*}（最短后缀）。

坑 4：数组下标越界不报错返回空
结论：${arr[100]} 越界不报错，静默返回空字符串。
原因：bash 数组越界访问不报错，返回空。
解法：先判断下标 < ${#arr[@]}，或用 set -u 让未设置变量报错。

坑 5：${var:-默认} 和 ${var:=默认} 混淆
结论：以为 ${var:-默认} 会给 var 赋值，结果后续用 $var 还是空。
原因：- 只返回默认值不改变量，= 才真正赋值。
解法：要「返回且赋值」用 :=，只「临时兜底」用 :-。

坑 6：${s: -3} 冒号后没空格，被当成默认值语法
结论：想取「末尾 3 个字符」写 ${s:-3}，结果 s 非空时返回整个 s。
原因：${s:-3} 是「s 为空返回 3」，不是负偏移截取。
解法：负偏移必须写成 ${s: -3}（冒号和负号之间留空格）。

坑 7：unset 'arr[i]' 后数组留下空洞，${#arr[@]} 与下标不对应
结论：删了中间元素后，遍历 ${arr[@]} 元素少了但下标跳号，${arr[0]} 可能取不到第 1 个。
原因：unset 数组元素留空洞，后续下标不重排。
解法：要么接受空洞用 ${!arr[@]} 遍历下标，要么重建数组 arr=("${arr[@]}" ) 消除空洞。
```

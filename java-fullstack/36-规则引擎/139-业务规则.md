## 概述

业务规则是企业的业务决策逻辑（优惠、风控、定价），业务规则管理让规则可配置、可动态修改、可版本化。

```text
业务规则管理解决：
1. 规则硬编码 —— 规则在代码里，改规则要改代码发版
2. 规则不透明 —— 业务人员不知道规则是什么
3. 规则难维护 —— 规则散落在各处
```

```text
业务规则管理的目标：
1. 规则可视化 —— 规则在管理后台可见
2. 动态修改 —— 改规则不重启
3. 版本管理 —— 规则变更可追溯、可回滚
4. 灰度发布 —— 规则逐步放量
```

## 规则管理

规则管理是规则的增删改查和分类组织。

### 规则的存储

```text
1. 数据库 —— 规则存数据库，后台管理
2. 规则文件 —— 规则存 .drl/.xlsx 文件，版本管理
3. 规则平台 —— 专用规则平台（Drools Workbench）
```

### 规则表设计

```sql
CREATE TABLE biz_rule (
    id BIGINT PRIMARY KEY,
    rule_code VARCHAR(64),       -- 规则编码
    rule_name VARCHAR(128),      -- 规则名称
    rule_type VARCHAR(32),       -- 规则类型（优惠/风控/定价）
    rule_content TEXT,           -- 规则内容（DRL/JSON）
    status VARCHAR(16),          -- 状态（草稿/已发布/已下线）
    version INT,                 -- 版本号
    create_time DATETIME,
    update_time DATETIME
);
```

### 规则管理功能

```text
1. 规则列表 —— 查询、筛选
2. 规则编辑 —— 新增、修改、删除
3. 规则分类 —— 按业务类型分组
4. 规则状态 —— 草稿、发布、下线
```

## 动态规则

动态规则是运行时加载规则，改规则不重启应用。

### 动态规则的价值

```text
静态规则：规则打包在 jar 里，改规则要发版重启
动态规则：规则存数据库/配置中心，运行时加载，改规则即时生效
```

### 动态加载实现

```java
@Service
public class DynamicRuleService {

    @Autowired
    private RuleRepository ruleRepository;

    private volatile KieBase kieBase;   // 当前生效的规则库

    // 从数据库加载规则，构建 KieBase
    public void reloadRules() {
        List<BizRule> rules = ruleRepository.findByStatus("PUBLISHED");
        String drl = rules.stream()
            .map(BizRule::getRuleContent)
            .collect(Collectors.joining("\n"));

        KieHelper helper = new KieHelper();
        helper.addContent(drl, ResourceType.DRL);
        kieBase = helper.build();   // 替换规则库
    }

    // 执行规则
    public void execute(Object fact) {
        KieSession session = kieBase.newKieSession();
        session.insert(fact);
        session.fireAllRules();
        session.dispose();
    }
}
```

### 规则变更通知

```java
// 规则变更后触发重载
// 1. 手动触发：调用 reloadRules()
// 2. 定时刷新：定时拉取最新规则
// 3. 消息通知：规则变更发消息，各实例重载
```

```java
// 定时刷新规则（简单方案）
@Scheduled(fixedDelay = 60000)   // 每分钟刷新
public void refreshRules() {
    dynamicRuleService.reloadRules();
}
```

## 规则版本

规则版本管理规则的变更历史，支持回滚。

### 版本管理

```text
1. 每次修改生成新版本（version + 1）
2. 保留历史版本
3. 支持回滚到指定版本
```

```sql
-- 规则版本表
CREATE TABLE biz_rule_version (
    id BIGINT PRIMARY KEY,
    rule_id BIGINT,          -- 规则 ID
    version INT,             -- 版本号
    rule_content TEXT,       -- 该版本的规则内容
    change_log VARCHAR(255), -- 变更说明
    create_time DATETIME
);
```

### 版本对比与回滚

```text
1. 版本对比 —— 查看两个版本的差异
2. 回滚 —— 恢复到历史版本
3. 审计 —— 谁改了什么，何时改的
```

## 规则发布

规则发布是规则从草稿到生效的过程，支持灰度。

### 发布流程

```text
1. 规则编辑（草稿）
2. 规则审核（测试）
3. 规则发布（生效）
4. 规则下线（停用）
```

### 灰度发布

```text
灰度：新规则只对部分流量生效，验证后全量
```

```java
// 灰度规则：按用户 ID 灰度
public boolean shouldUseNewRule(Long userId) {
    // 灰度用户（如 user_id % 100 < 10，10% 流量）
    return userId % 100 < grayPercent;
}
```

```java
// 执行时按灰度判断用哪个规则版本
public void executeRule(Object fact, Long userId) {
    if (shouldUseNewRule(userId)) {
        newRuleKieSession.execute(fact);    // 新规则
    } else {
        oldRuleKieSession.execute(fact);    // 旧规则
    }
}
```

## 规则执行

规则执行是把事实送入规则引擎，得到结果。

### 执行方式

```text
1. 同步执行 —— 请求内执行规则
2. 异步执行 —— 规则复杂时异步
3. 批量执行 —— 批量数据处理
```

### 执行监控

```text
1. 执行日志 —— 记录命中的规则
2. 执行统计 —— 规则命中率、耗时
3. 结果记录 —— 规则执行结果
```

```java
// 执行 + 记录日志
public Result executeWithLog(Object fact) {
    long start = System.currentTimeMillis();

    // 执行规则（记录命中的规则）
    List<String> firedRules = new ArrayList<>();
    KieSession session = kieBase.newKieSession();
    session.setGlobal("firedRules", firedRules);
    session.insert(fact);
    session.fireAllRules();

    long cost = System.currentTimeMillis() - start;
    log.info("规则执行：命中 {} 条，耗时 {}ms", firedRules.size(), cost);
    session.dispose();

    return new Result(fact, firedRules, cost);
}
```

## 应用场景实战

### 场景 1：动态优惠规则系统

```java
@Service
public class PromotionService {

    @Autowired
    private DynamicRuleService ruleService;

    public Order applyPromotion(Order order) {
        // 执行动态规则（优惠规则从数据库加载，可动态修改）
        ruleService.execute(order);
        return order;   // order.discount 已被规则修改
    }
}

// 管理后台修改规则 → 规则生效（不重启）
// 规则：满 100 减 10 → 改为满 200 减 30
```

### 场景 2：规则版本 + 灰度

```java
@Service
public class RuleEngine {

    private final Map<Integer, KieBase> versionCache = new ConcurrentHashMap<>();

    // 灰度执行（新版本规则只对 10% 用户生效）
    public void executeWithGray(Object fact, Long userId, int newVersion) {
        KieBase ruleBase;
        if (userId % 100 < 10) {
            ruleBase = getVersion(newVersion);      // 新版本（灰度）
        } else {
            ruleBase = getVersion(newVersion - 1);  // 旧版本（稳定）
        }

        KieSession session = ruleBase.newKieSession();
        session.insert(fact);
        session.fireAllRules();
        session.dispose();
    }
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. **规则存数据库，动态加载**。改规则不重启，即时生效。

2. **规则版本化**。每次变更生成版本，支持回滚。

3. **规则变更要审核**。规则影响业务，发布前要测试审核。

4. **灰度发布规则**。新规则小流量验证，再全量。

5. **规则执行要监控**。记录命中率、耗时、结果。

### 踩坑记录

**坑 1：规则热加载线程安全**

```java
private KieBase kieBase;   // 多线程读写，可能拿到半初始化的规则库
```

用 volatile + 不可变对象，或用 AtomicReference 保证可见性。

**坑 2：规则变更无审核直接上线**

```text
规则改错了直接生效，导致业务损失（如优惠规则写错）
```

规则变更要审核、测试、灰度。

**坑 3：规则版本混乱**

```text
多个实例加载的规则版本不一致（有的新有的旧）
```

规则版本统一管理，变更通知所有实例同步。

**坑 4：规则执行性能差**

```text
每次执行都重新构建 KieBase（昂贵），性能差
```

KieBase 缓存复用，只重建 KieSession。

**坑 5：规则内容无校验**

```text
规则 DRL 语法错误，加载失败，导致规则不生效
```

规则保存前校验语法，加载失败告警。

**坑 6：灰度规则比例失控**

```text
灰度比例配置错误（100%），新规则全量生效
```

灰度比例要可配置、可回退，异常时快速回滚。

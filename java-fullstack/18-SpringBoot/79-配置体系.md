## 概述

Spring Boot 的配置体系让应用可以通过多种外部来源注入配置，无需重新打包即可改变行为。配置的核心是 `application.properties` 或 `application.yml`，配合 Profile 实现多环境切换。

```text
配置来源（优先级从高到低）：
命令行参数 > JVM 系统属性 > 环境变量 > application-{profile}.yml
> application.yml > @PropertySource > 默认值
```

## application.properties 与 application.yml

### properties 格式

```properties
# 扁平结构，用 . 分隔层级
server.port=8080
server.address=127.0.0.1
spring.datasource.url=jdbc:mysql://localhost:3306/mydb
spring.datasource.username=root
spring.datasource.password=secret
spring.datasource.driver-class-name=com.mysql.cj.jdbc.Driver
```

### yml 格式

```yaml
# 树形结构，用缩进表达层级
server:
  port: 8080
  address: 127.0.0.1

spring:
  datasource:
    url: jdbc:mysql://localhost:3306/mydb
    username: root
    password: secret
    driver-class-name: com.mysql.cj.jdbc.Driver
```

### 两者对比

| 维度 | properties | yml |
|------|-----------|-----|
| 层级表达 | 用 . 分隔（扁平） | 用缩进（树形） |
| 可读性 | 配置多时较乱 | 层级清晰，适合复杂配置 |
| 集合表达 | 用索引 [0]、[1] | 用 - 列表 |
| 类型 | 全是字符串 | 支持类型推断（数字、布尔） |
| 使用场景 | 简单配置 | 复杂配置、多环境 |

### 复杂结构对比

properties 表达集合和嵌套：

```properties
# 列表
app.servers[0]=server1.example.com
app.servers[1]=server2.example.com

# Map
app.mail.host=smtp.example.com
app.mail.port=587

# 嵌套对象
app.security.enabled=true
app.security.secret-key=abc123
```

yml 表达集合和嵌套：

```yaml
app:
  servers:
    - server1.example.com
    - server2.example.com
  mail:
    host: smtp.example.com
    port: 587
  security:
    enabled: true
    secret-key: abc123
```

yml 对复杂结构的表达更自然，因此现代 Spring Boot 项目默认推荐 yml。

### yml 的特殊语法

```yaml
# 多文档（一个文件配置多个环境）
spring:
  profiles: dev
server:
  port: 8081
---
spring:
  profiles: prod
server:
  port: 80
```

```yaml
# 占位符引用其他配置
app:
  name: my-app
  description: ${app.name} 是一个应用    # 引用 app.name

# 带默认值的占位符
app:
  timeout: ${app.custom-timeout:30000}   # 若无则用 30000
```

```yaml
# 字符串特殊字符
app:
  path: ${user.home}/logs                 # 引用系统属性
  literal: '含:和{的字符串需要引号'
```

## Profile 多环境配置

Profile 是 Spring Boot 多环境切换的核心机制。

### 配置文件命名

```text
application.yml              —— 公共配置（所有环境共享）
application-dev.yml          —— 开发环境
application-test.yml         —— 测试环境
application-prod.yml         —— 生产环境
```

### 激活 Profile

```yaml
# application.yml 中指定
spring:
  profiles:
    active: dev
```

```bash
# 命令行指定（优先级更高）
java -jar app.jar --spring.profiles.active=prod

# 环境变量指定
SPRING_PROFILES_ACTIVE=prod java -jar app.jar
```

### Profile 配置合并

```yaml
# application.yml（公共）
spring:
  application:
    name: my-app
server:
  port: 8080

---
# application-dev.yml（开发，覆盖公共配置）
server:
  port: 8081
logging:
  level:
    root: DEBUG

---
# application-prod.yml（生产）
server:
  port: 80
logging:
  level:
    root: WARN
```

激活 dev 时，最终配置 = 公共配置 + dev 覆盖。

### @Profile 注解

```java
@Configuration
@Profile("dev")
public class DevConfig {
    // 只在 dev 环境生效
    @Bean
    public DataSource devDataSource() { ... }
}

@Configuration
@Profile("prod")
public class ProdConfig {
    // 只在 prod 环境生效
    @Bean
    public DataSource prodDataSource() { ... }
}
```

```java
// 组合条件：dev 或 test
@Profile({"dev", "test"})

// 取反：非 prod
@Profile("!prod")
```

## 外部配置

外部配置让应用在**不改代码、不打新包**的情况下改变行为，是云原生部署的基础。

### 配置来源完整清单

| 来源 | 示例 | 说明 |
|------|------|------|
| 命令行参数 | --server.port=8080 | 最高优先级 |
| JVM 系统属性 | -Dserver.port=8080 | System.getProperties() |
| 环境变量 | SERVER_PORT=8080 | 系统环境变量 |
| 配置文件 | application.yml | 最常用 |
| 外部配置文件 | --spring.config.location | 指定外部路径 |
| @PropertySource | @PropertySource("...") | 自定义属性源 |

### 环境变量映射规则

环境变量通过"大写 + 下划线"映射到配置项：

```text
server.port          → SERVER_PORT
spring.datasource.url → SPRING_DATASOURCE_URL
app.api.key          → APP_API_KEY

规则：
1. 全大写
2. . 替换为 _
3. - 替换为 _
```

```bash
# Docker 部署时通过环境变量注入配置
docker run -e SERVER_PORT=8080 -e SPRING_DATASOURCE_URL=jdbc:mysql://db:3306/mydb myapp
```

### spring.config.location 指定外部配置

```bash
# 指定外部配置文件（优先级高于 jar 内的 application.yml）
java -jar app.jar --spring.config.location=/opt/config/application.yml

# 指定目录（加载目录下所有配置文件）
java -jar app.jar --spring.config.location=/opt/config/

# 多个位置
java -jar app.jar --spring.config.location=classpath:/,file:/opt/config/
```

### spring.config.import 导入其他配置

```yaml
# 导入其他配置文件
spring:
  config:
    import: classpath:additional.yml

# 导入配置中心（Spring Cloud Config）
spring:
  config:
    import: configserver:http://config-server:8888
```

### 命令行参数

```bash
java -jar app.jar --server.port=8080 --spring.profiles.active=prod
java -jar app.jar --app.name=myapp --app.timeout=5000
```

命令行参数是最高优先级，常用于临时覆盖某个配置。

## 配置优先级

Spring Boot 完整的配置优先级（从高到低）：

```text
1. 命令行参数（--server.port=8080）
2. Java 系统属性（-Dserver.port=8080）
3. 操作系统环境变量（SERVER_PORT=8080）
4. 随机数属性（random.*）
5. 外部 application-{profile}.yml（jar 外的 profile 配置）
6. 内部 application-{profile}.yml（jar 内的 profile 配置）
7. 外部 application.yml（jar 外）
8. 内部 application.yml（jar 内）
9. @PropertySource 注解
10. 默认属性
```

记忆口诀：**命令行 > 系统属性 > 环境变量 > profile 专用 > 默认配置**，外部的优先于内部的。

```bash
# 验证优先级：即使 application.yml 里配了 8080，命令行 9090 会覆盖
java -jar app.jar --server.port=9090
# 实际监听 9090
```

## 配置绑定

Spring Boot 提供两种配置绑定方式：`@Value` 和 `@ConfigurationProperties`。

### @Value —— 单个值注入

```java
@Component
public class AppConfig {

    @Value("${app.name}")
    private String appName;

    @Value("${app.timeout:30000}")  // 默认值
    private long timeout;

    @Value("${app.ratio:0.8}")
    private double ratio;

    @Value("${app.enabled:true}")
    private boolean enabled;
}
```

`@Value` 适合注入少量、简单的配置值。

### @ConfigurationProperties —— 类型安全绑定

```java
@Component
@ConfigurationProperties(prefix = "app")
public class AppProperties {
    private String name;
    private String version;
    private int maxConnections;
    private List<String> allowedOrigins;
    private Map<String, String> mail;
    private Security security = new Security();

    // 必须提供 getter/setter
    public static class Security {
        private boolean enabled;
        private String secretKey;
        // getter/setter
    }
    // getter/setter
}
```

```yaml
app:
  name: my-app
  version: "2.0"
  max-connections: 50
  allowed-origins:
    - http://localhost:3000
    - http://example.com
  mail:
    host: smtp.example.com
    port: 587
  security:
    enabled: true
    secret-key: abc123
```

### 启用 @ConfigurationProperties

```java
// 方式 1：@Component 直接注册
@Component
@ConfigurationProperties(prefix = "app")
public class AppProperties { }

// 方式 2：@EnableConfigurationProperties（推荐，用于第三方/分组）
@Configuration
@EnableConfigurationProperties(AppProperties.class)
public class AppConfig { }

// 方式 3：@ConfigurationPropertiesScan 扫描
@SpringBootApplication
@ConfigurationPropertiesScan("com.example.config")
public class Application { }
```

### @ConfigurationProperties 校验

```java
@ConfigurationProperties(prefix = "app")
@Validated  // 开启校验
public class AppProperties {

    @NotBlank
    private String name;      // 不能为空

    @Min(1)
    @Max(1000)
    private int maxConnections;  // 1-1000 之间

    @Email
    private String adminEmail;
}
```

### @Value vs @ConfigurationProperties

| 维度 | @Value | @ConfigurationProperties |
|------|--------|-------------------------|
| 绑定方式 | 逐个字段 | 前缀 + 整组字段 |
| 类型安全 | 弱（需手动转换） | 强（自动类型转换） |
| 复杂结构 | 不支持（List/Map 麻烦） | 支持嵌套、List、Map |
| 校验 | 不支持 JSR-303 | 支持 @Validated |
| 松散绑定 | 不支持 | 支持 |
| 适用场景 | 少量简单配置 | 一组相关配置 |

推荐：一组相关配置用 `@ConfigurationProperties`，单个简单值用 `@Value`。

## 松散绑定

`@ConfigurationProperties` 支持松散绑定（Relaxed Binding），属性名可以有多种写法：

```java
@ConfigurationProperties(prefix = "app.security")
public class SecurityProperties {
    private String secretKey;    // 字段：secretKey
    private boolean enabled;
}
```

以下配置写法都等价：

```yaml
app:
  security:
    secret-key: abc        # kebab-case（短横线）
    enabled: true

app:
  security:
    secretKey: abc         # camelCase（驼峰）
    enabled: true

app:
  security:
    SECRET_KEY: abc        # uppercase（大写+下划线）
    ENABLED: true
```

松散绑定规则：

```text
Java 字段名           可接受的配置写法
secretKey       →    secret-key / secretKey / SECRET_KEY
maxConnections  →    max-connections / maxConnections / MAX_CONNECTIONS
```

**注意**：`@Value` 不支持松散绑定——`@Value("${app.secret-key}")` 必须精确匹配配置名。这就是为什么复杂配置推荐 `@ConfigurationProperties`。

## 配置加密与敏感信息

### 敏感配置的处理

```yaml
# 不推荐：明文密码
spring:
  datasource:
    password: mySecretPassword123

# 推荐：用环境变量注入
spring:
  datasource:
    password: ${DB_PASSWORD}   # 从环境变量读取，配置文件中不留明文
```

### 随机值

```yaml
# Spring Boot 内置的随机值占位符
my:
  secret: ${random.value}        # 随机字符串
  number: ${random.int}          # 随机整数
  less-than-ten: ${random.int(10)}   # 0-10 随机整数
  range: ${random.int[1024,65536]}   # 范围内随机整数
  long: ${random.long}           # 随机 long
  uuid: ${random.uuid}           # 随机 UUID
```

### 场景 3：动态读取配置

```java
@Service
public class ConfigService {

    @Autowired
    private Environment environment;

    public String getDynamicConfig(String key) {
        // 运行时动态读取配置
        return environment.getProperty(key, "default-value");
    }

    public boolean isProdEnv() {
        String[] profiles = environment.getActiveProfiles();
        return Arrays.asList(profiles).contains("prod");
    }
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. **公共配置和差异配置分离**。application.yml 放公共配置，application-{profile}.yml 放各环境差异。

2. **敏感信息用环境变量，不用明文**。密码、密钥通过 `${ENV_VAR}` 注入，配置文件不落明文。

3. **复杂配置用 @ConfigurationProperties**。一组相关配置（数据库、支付、缓存）定义专门的配置类，类型安全 + 校验 + 松散绑定。

4. **默认激活 dev，生产显式指定**。`spring.profiles.active` 在 application.yml 中默认 dev，生产通过命令行/环境变量覆盖。

5. **配置项命名用 kebab-case**。`max-connections` 优于 `maxConnections`，符合 Spring Boot 惯例和松散绑定规则。

### 踩坑记录

**坑 1：yml 缩进用 Tab 报错**

```yaml
# 错误：Tab 缩进
server:
	port: 8080    # 这里用了 Tab，解析报错

# 正确：空格缩进（2 或 4 空格，统一）
server:
  port: 8080
```

yml 严格区分空格和 Tab，混用会导致解析失败。

**坑 2：@Value 不支持松散绑定**

```java
@Value("${app.max-connections}")  // 配置是 app.max-connections
private int maxConnections;        // 精确匹配 OK

// 但如果配置写成 app.maxConnections，这里就注入失败
```

`@Value` 的 `${}` 是精确匹配，不享受松散绑定。要松散绑定用 `@ConfigurationProperties`。

**坑 3：@ConfigurationProperties 没有 getter/setter**

```java
@ConfigurationProperties(prefix = "app")
public class AppProperties {
    private String name;  // 没有 getter/setter
    // Spring Boot 通过 getter/setter 绑定，字段会被忽略！
}
```

`@ConfigurationProperties` 依赖 getter/setter 绑定（除非用构造器绑定）。缺 getter/setter 的字段不会被注入。

**坑 4：配置文件位置不对**

```text
配置文件必须在 src/main/resources 下（classpath 根），
不是 src/main/java 下
```

**坑 5：环境变量名映射错误**

```bash
# 环境变量 SPRING_DATASOURCE_URL 映射 spring.datasource.url
# 但如果变量名写错（如 SPRING_DATASOURCE_URL_XXX），不会映射成功
```

环境变量映射是"大写 + 下划线"精确对应，多一个字符都不行。

**坑 6：profile 配置不生效**

```yaml
spring:
  profiles:
    active: dev    # 写成 active: [dev] 或 profile: dev 都不对
```

`spring.profiles.active` 的 key 必须精确。旧版本 Spring Boot（1.x）用的是 `spring.profiles.active`，但 `spring.profiles` 分组是 2.4+ 的新特性，注意版本差异。

## 项目背景

实时协作白板（Real-time Collaborative Whiteboard）解决的是「多人同时在一块画布上绘制、编辑、讨论」的问题：远程会议画架构图、在线课堂写板书、设计评审圈重点。这类场景的难点不是「画」本身，而是「并发的一致性」——两个人同时拖同一个图形、同时删同一个图形、一个断开重连后别人画的内容怎么补回来。业界有两种思路：中心化的 OT（Operational Transformation，操作转换）需要中心服务器对操作排序并做转换，实现复杂；去中心化的 CRDT（Conflict-free Replicated Data Type，无冲突复制数据类型）让每个端对并发操作按确定性规则合并，最终必然收敛到一致状态，天然支持乱序到达、断线重连、历史重放。本项目采用 CRDT（OR-Set 加 LWW 寄存器）实现图形集合的无冲突合并，WebSocket 做实时通道，快照 + 操作日志做历史版本与回放。它是理解分布式一致性与实时协作的最佳实战载体。

业务痛点：

```text
1. 异地沟通画不清：远程会议/线上授课想画架构图、讲思路，没有共享画板，只能截图发来发去
2. 并发操作互相覆盖：多人同时画图，后写的覆盖先写的，A 拖走的图形在 B 那边又跳回来
3. 无法回看过程：画到一半想回退到十分钟前的状态，没有历史版本，只能手动重画
4. 同步延迟高：用轮询拉取别人画了什么，实时性差、浪费带宽，光标完全不可用
5. 权限失控：链接一分享所有人都能改，没有查看/编辑的角色区分
6. 断线重连丢操作：网络抖动重连后，期间别人画的内容丢失，状态对不上
```

目标用户与核心诉求：

```text
1. 研发/产品团队：远程设计评审，多人同时画架构图、泳道图，边画边讨论
2. 在线教育老师：白板授课，学生可看不可改（或分组协作），课后可回放板书
3. 会议主持人：控制白板权限（谁可编辑）、查看历史版本、恢复误删内容
```

项目要解决的核心问题一句话概括：构建一个多人实时协作白板——WebSocket 实时广播操作、CRDT 保证并发操作无冲突合并（所有端最终一致）、光标实时同步、快照 + 操作日志实现历史版本回放与断线增量补齐。

## 功能介绍

功能按角色与模块拆分：白板管理（入口端）、图形绘制（编辑端）、实时协作（通道端）、历史版本（回放端）。

```text
一、白板管理（入口端）
1. 创建白板 —— 创建画布，生成分享链接与邀请码
2. 分享与邀请 —— 邀请码/链接指定角色（查看/编辑），过期时间与使用次数限制
3. 权限控制 —— owner/editor/viewer 三种角色，viewer 的操作在服务端被拒绝
4. 白板列表 —— 我创建的/我参与的，按最近编辑排序

二、图形绘制（编辑端）
1. 图形工具 —— 矩形/圆/线/文本/箭头/自由画笔
2. 图形编辑 —— 移动/缩放/改色/线宽/填充/文字修改
3. 图形属性 —— 颜色、线宽、填充色、字号等属性面板
4. 撤销重做 —— 基于操作日志的 undo/redo（按操作回退，不破坏 CRDT 状态）

三、多人实时协作（通道端）
1. 操作广播 —— 增删改图形的操作通过 WebSocket 广播给同板在线成员
2. CRDT 合并 —— 并发操作按 OR-Set（add-wins）+ LWW 寄存器规则合并，无冲突、最终一致
3. 光标同步 —— 实时看到其他人的光标位置与昵称
4. 在线成员 —— 进出白板实时提示，成员列表展示在线状态
5. 断线重连 —— 重连后按 opId 拉取缺失操作增量补齐

四、历史版本（回放端）
1. 自动快照 —— 每 N 个操作或每 5 分钟生成一次画布快照
2. 版本回放 —— 从任意快照回放到当前（快照 + 后续操作重放）
3. 版本恢复 —— 一键恢复到历史版本（广播全量状态替换操作）
4. 操作追溯 —— 每个图形可查是谁、什么时间创建的
```

## 技术选型

| 组件 | 选型 | 理由 |
|------|------|------|
| 开发框架 | Spring Boot 2.7/3.x | 生态成熟 |
| 实时通信 | Spring WebSocket（TextWebSocketHandler） | 全双工双向通道，操作级实时性 |
| CRDT | 自研 OR-Set（add-wins）+ LWW Register | 形状级粒度，无冲突合并 |
| 逻辑时钟 | HLC（客户端 id + 计数器 + 物理时间戳） | 事件排序与 LWW 冲突裁决 |
| 持久层 | MyBatis-Plus | 操作日志/快照/成员 |
| 数据库 | MySQL 8.0 | 操作日志、快照、白板元数据 |
| 缓存 | Redis | 光标热数据、在线状态、会话注册 |
| 前端 | Vue 3 + Canvas 渲染 | 图形绘制与交互 |
| 构建 | Maven | 标准工具 |

选型说明：

```text
1. CRDT 选 OR-Set（add-wins）+ LWW：图形集合天然是「元素级」数据结构，元素增删用 OR-Set（并发 add 与 remove 时 add 赢，图形不会莫名消失）；同一图形的属性修改用 LWW 寄存器（时间戳大者胜），冲突裁决规则简单可解释
2. 不用中心化 OT：OT 需要中心服务器排序与转换，CRDT 天然支持乱序、离线、重放，实现成本低，契合白板「操作即消息」的模型
3. 操作日志全量落库：每笔操作以 opId 唯一标识持久化，既是历史回放的素材，也是断线重连增量同步的源头
4. 快照定期生成：快照 + 增量重放控制回放成本，避免从零重放十万条操作；快照同时是版本恢复的基线
5. 光标走 Redis + 限频广播：光标高频变化（鼠标移动），Redis 存最新位置，客户端限频上报（约 20Hz），服务端合并后广播，只保留最新值
```

```text
│      MySQL        │   │  Redis   │   │      ——               │
```

一次协作操作的完整链路：

```text
1. 用户 A 在白板拖出一个矩形，客户端生成本地 opId（clientId:seq），立即渲染（乐观更新）
2. 客户端通过 WebSocket 发送 {opId, boardId, type:addShape, payload, clock}
3. WS 处理器解析消息，调用操作服务：按 boardId 校验成员权限（editor 及以上）
4. 操作服务按 opId 幂等去重（board_id + op_id 唯一索引，重连重发直接丢弃）
5. CRDT 合并器把操作合并进服务端状态（add-wins 集合 + LWW 字段裁决）
6. 操作落库（board_op_log），返回 ack 给 A
7. 操作进入广播队列，50ms 批量窗口合并后推送给同白板其他在线成员
8. 用户 B 的客户端收到操作应用到本地画布，两端状态一致
9. 期间 B 也画了个圆（并发操作）：两端按 CRDT 规则合并，最终一致（两个图形都在）
10. 若 A 断线重连：按 opId 增量拉取缺失操作补齐本地状态
```

## 核心实现

### 1. 白板服务：创建、邀请与权限

```java
@Service
public class BoardService {

    @Autowired
    private BoardMapper boardMapper;
    @Autowired
    private BoardMemberMapper memberMapper;
    @Autowired
    private BoardInviteMapper inviteMapper;
    @Autowired
    private BoardAccessLogMapper accessLogMapper;

    /** 创建白板：创建人自动成为 owner */
    @Transactional(rollbackFor = Exception.class)
    public Long createBoard(Long userId, String boardName) {
        Board board = new Board();
        board.setBoardCode("b_" + UUID.randomUUID().toString().replace("-", "").substring(0, 12));
        board.setBoardName(boardName);
        board.setOwnerId(userId);
        boardMapper.insert(board);

        BoardMember member = new BoardMember();
        member.setBoardId(board.getId());
        member.setUserId(userId);
        member.setRole("owner");
        memberMapper.insert(member);
        return board.getId();
    }

    /** 生成邀请：指定角色与有效期 */
    public String createInvite(Long boardId, String role, LocalDateTime expireTime) {
        checkOwner(boardId);
        BoardInvite invite = new BoardInvite();
        invite.setBoardId(boardId);
        invite.setInviteCode(UUID.randomUUID().toString().replace("-", "").substring(0, 8));
        invite.setGrantRole(role);
        invite.setExpireTime(expireTime);
        inviteMapper.insert(invite);
        return invite.getInviteCode();
    }

    /** 通过邀请加入：校验有效期与次数，按邀请角色授予权限 */
    public void joinByInvite(Long userId, String inviteCode) {
        BoardInvite invite = inviteMapper.selectByCode(inviteCode);
        if (invite == null) {
            throw new BizException("邀请码不存在");
        }
        if (invite.getExpireTime() != null && invite.getExpireTime().isBefore(LocalDateTime.now())) {
            throw new BizException("邀请已过期");
        }
        if (invite.getUseCount() >= invite.getUseLimit()) {
            throw new BizException("邀请次数已用完");
        }
        if (memberMapper.selectByBoardUser(invite.getBoardId(), userId) != null) {
            return;   // 已是成员
        }
        BoardMember member = new BoardMember();
        member.setBoardId(invite.getBoardId());
        member.setUserId(userId);
        member.setRole(invite.getGrantRole());
        memberMapper.insert(member);
        inviteMapper.incrUseCount(invite.getId());
        accessLogMapper.insert(invite.getBoardId(), userId, "join", "邀请加入");
    }

    /** 权限校验：查看者执行写操作直接拒绝（服务端强制，不依赖前端） */
    public void checkPermission(Long boardId, Long userId, String requiredRole) {
        BoardMember member = memberMapper.selectByBoardUser(boardId, userId);
        if (member == null) {
            throw new BizException("无权访问该白板");
        }
        if ("editor".equals(requiredRole)
                && "viewer".equals(member.getRole())) {
            throw new BizException("当前角色为查看者，无法编辑");
        }
    }
}
```

### 2. WebSocket 处理器：连接鉴权、消息路由与广播

```java
@Component
public class BoardWebSocketHandler extends TextWebSocketHandler {

    @Autowired
    private CrdtOpService crdtOpService;
    @Autowired
    private CursorSyncService cursorSyncService;
    @Autowired
    private BoardSessionRegistry sessionRegistry;

    @Override
    public void afterConnectionEstablished(WebSocketSession session) {
        // 连接参数：ws://host/ws/board?boardId=1&token=xxx
        String boardId = (String) session.getAttributes().get("boardId");
        Long userId = (Long) session.getAttributes().get("userId");
        sessionRegistry.register(boardId, session);
        // 通知其他成员：有人上线
        sessionRegistry.broadcast(boardId, jsonMessage("memberJoin",
                "{\"userId\":" + userId + "}"), session.getId());
    }

    @Override
    protected void handleTextMessage(WebSocketSession session, TextMessage message) {
        String boardId = (String) session.getAttributes().get("boardId");
        Long userId = (Long) session.getAttributes().get("userId");
        try {
            JsonNode msg = objectMapper.readTree(message.getPayload());
            String type = msg.path("type").asText();
            switch (type) {
                case "op" -> crdtOpService.applyOp(boardId, userId, msg.path("data"));
                case "cursor" -> cursorSyncService.onCursor(boardId, userId, msg.path("data"));
                case "ping" -> session.sendMessage(new TextMessage("{\"type\":\"pong\"}"));
                default -> { /* 忽略未知类型 */ }
            }
        } catch (Exception e) {
            sendError(session, e.getMessage());
        }
    }

    @Override
    public void afterConnectionClosed(WebSocketSession session, CloseStatus status) {
        String boardId = (String) session.getAttributes().get("boardId");
        Long userId = (Long) session.getAttributes().get("userId");
        sessionRegistry.unregister(boardId, session.getId());
        // 通知其他成员：有人下线
```

### 3. 操作服务：幂等去重、落库与入队广播

```java
@Service
public class CrdtOpService {

    @Autowired
    private BoardOpLogMapper opLogMapper;
    @Autowired
    private BoardService boardService;
    @Autowired
    private CrdtStateManager stateManager;
    @Autowired
    private BoardSessionRegistry sessionRegistry;
    @Autowired
    private StringRedisTemplate redisTemplate;

    /**
     * 应用一笔操作：权限校验 -> 幂等去重 -> CRDT 合并 -> 落库 -> 入广播队列
     * 幂等三保险：Redis SETNX + 数据库唯一索引（board_id, op_id）+ 内存 seen 集合
     */
    public void applyOp(String boardId, Long userId, JsonNode data) {
        String opId = data.path("opId").asText();
        String opType = data.path("opType").asText();
        // 写操作才做权限校验（cursor 是轻量消息，只校验成员资格）
        if (!"cursor".equals(opType)) {
            boardService.checkPermission(Long.parseLong(boardId), userId, "editor");
        }
        // 幂等去重：重连重发/重复广播直接丢弃
        String dedupKey = "board:op:seen:" + boardId + ":" + opId;
        Boolean first = redisTemplate.opsForValue()
                .setIfAbsent(dedupKey, "1", 24, TimeUnit.HOURS);
        if (!Boolean.TRUE.equals(first)) {
            return;   // 已处理过
        }
        // CRDT 合并进服务端状态（内存，广播与快照用）
        stateManager.apply(Long.parseLong(boardId), opId, opType, data);

        // 落库（唯一索引兜底去重）
        BoardOpLog log = new BoardOpLog();
        log.setBoardId(Long.parseLong(boardId));
        log.setOpId(opId);
        log.setClientId(data.path("clientId").asText());
        log.setOpType(opType);
        log.setShapeId(data.path("shapeId").asText(null));
        log.setPayload(data.path("payload").toString());
        log.setClockSeq(data.path("clock").path("seq").asLong());
        log.setClockTs(data.path("clock").path("ts").asLong());
        log.setUserId(userId);
        try {
            opLogMapper.insert(log);
        } catch (DuplicateKeyException e) {
            return;   // 并发重复插入，已存在
        }
        // 入广播队列（批量窗口合并发送）
        sessionRegistry.enqueueBroadcast(boardId,
                "{\"type\":\"op\",\"data\":" + data.toString() + "}");
    }

    /** 断线重连增量同步：返回 lastOpId 之后的所有操作 */
    public List<BoardOpLog> syncOps(Long boardId, String lastOpId) {
        if (lastOpId == null || lastOpId.isEmpty()) {
            return opLogMapper.selectByBoard(boardId, 5000);   // 首次进入最多 5000 条
        }
        Long lastId = opLogMapper.selectIdByOpId(boardId, lastOpId);
        return lastId == null ? List.of() : opLogMapper.selectAfterId(boardId, lastId, 5000);
    }
}
```

### 4. CRDT 状态管理器：OR-Set（add-wins）+ LWW 合并

```java
@Component
public class CrdtStateManager {

    // 每块白板一个 CRDT 状态（内存态，快照定期落库，重启从快照+日志重建）
    private final ConcurrentHashMap<Long, BoardCrdtState> states = new ConcurrentHashMap<>();

    public BoardCrdtState get(Long boardId) {
        return states.computeIfAbsent(boardId, k -> new BoardCrdtState());
    }

    /** 合并一笔操作到状态：图形级 OR-Set + LWW 裁决 */
    public void apply(Long boardId, String opId, String opType, JsonNode data) {
        BoardCrdtState state = get(boardId);
        String shapeId = data.path("shapeId").asText();
        long ts = data.path("clock").path("ts").asLong();
        long seq = data.path("clock").path("seq").asLong();
        switch (opType) {
            case "addShape" -> state.addShape(shapeId,
                    data.path("payload").toString(), ts, seq);
            case "removeShape" -> state.removeShape(shapeId, ts, seq);
            case "updateShape" -> state.updateShape(shapeId,
                    data.path("payload").toString(), ts, seq);
            default -> { /* cursor 不进 CRDT 状态 */ }
        }
    }

    /** 白板 CRDT 状态：add-wins OR-Set + 图形属性 LWW */
    public static class BoardCrdtState {
        // shapeId -> 图形数据 + 最后修改时钟
        private final ConcurrentHashMap<String, ShapeEntry> shapes = new ConcurrentHashMap<>();
        // shapeId -> 删除时钟（remove 只记录墓碑，不立即物理删除）
        private final ConcurrentHashMap<String, Clock> tombstones = new ConcurrentHashMap<>();

        public void addShape(String shapeId, String payload, long ts, long seq) {
            Clock addClock = new Clock(ts, seq);
            Clock removed = tombstones.get(shapeId);
            // add-wins：并发 add 与 remove 时，若 add 时钟更新则复活图形
            if (removed != null && removed.compareTo(addClock) > 0) {
                return;   // remove 后于 add，保持删除
            }
            shapes.compute(shapeId, (k, old) -> {
                if (old == null || old.clock.compareTo(addClock) < 0) {
                    return new ShapeEntry(payload, addClock);
                }
                return old;
            });
        }

        public void removeShape(String shapeId, long ts, long seq) {
            Clock removeClock = new Clock(ts, seq);
            tombstones.put(shapeId, removeClock);
            ShapeEntry entry = shapes.get(shapeId);
            // 只有 remove 时钟晚于 add 时钟才真正移除（add-wins 语义）
            if (entry != null && entry.clock.compareTo(removeClock) < 0) {
                shapes.remove(shapeId);
            }
        }

        public void updateShape(String shapeId, String payload, long ts, long seq) {
            Clock updateClock = new Clock(ts, seq);
            shapes.computeIfPresent(shapeId, (k, old) ->
                    old.clock.compareTo(updateClock) < 0
                            ? new ShapeEntry(payload, updateClock)   // LWW：新时钟覆盖
                            : old);
        }

        /** 序列化为快照 JSON */
        public String toJson() {
            // {"shapes": {"shapeId": {"payload": ..., "clock": {...}}}}
            Map<String, Object> out = new HashMap<>();
            shapes.forEach((id, entry) -> out.put(id, entry.payload));
            return toJsonString(out);
        }
    }

    // 混合逻辑时钟：物理时间戳 + 客户端计数器，避免时间戳相同无法裁决
    public static class Clock implements Comparable<Clock> {
        long ts;
        long seq;

        Clock(long ts, long seq) {
            this.ts = ts;
            this.seq = seq;
        }

        @Override
        public int compareTo(Clock o) {
            int c = Long.compare(this.ts, o.ts);
            return c != 0 ? c : Long.compare(this.seq, o.seq);
        }
    }

    // ShapeEntry / toJsonString 等工具省略（序列化用 Jackson）
}
```

### 6. 广播风暴控制：会话注册表 + 批量合并发送

```java
@Component
public class BoardSessionRegistry {

    // boardId -> 在线会话集合（线程安全）
    private final ConcurrentHashMap<String, ConcurrentHashMap<String, WebSocketSession>> boards
            = new ConcurrentHashMap<>();
    // boardId -> 广播队列（批量窗口合并）
    private final ConcurrentHashMap<String, ConcurrentLinkedQueue<String>> queues
            = new ConcurrentHashMap<>();
    private final ScheduledExecutorService flusher = Executors.newScheduledThreadPool(2);

    public BoardSessionRegistry() {
        // 每 50ms 冲刷一次广播队列：合并光标（保留最新），批量发送操作
        flusher.scheduleWithFixedDelay(this::flushAll, 50, 50, TimeUnit.MILLISECONDS);
    }

    public void register(String boardId, WebSocketSession session) {
        boards.computeIfAbsent(boardId, k -> new ConcurrentHashMap<>())
                .put(session.getId(), session);
    }

    public void unregister(String boardId, String sessionId) {
        ConcurrentHashMap<String, WebSocketSession> sessions = boards.get(boardId);
        if (sessions != null) {
            sessions.remove(sessionId);
        }
    }

    /** 入队广播：光标类消息只保留最新一条（覆盖旧值） */
    public void enqueueBroadcast(String boardId, String message) {
        ConcurrentLinkedQueue<String> queue =
                queues.computeIfAbsent(boardId, k -> new ConcurrentLinkedQueue<>());
        if (message.contains("\"cursor\"")) {
            // 光标消息：丢弃同类型旧消息，只保留最新（合并）
            queue.removeIf(m -> m.contains("\"cursor\""));
        }
        queue.offer(message);
        // 队列上限保护：超过 500 条丢最旧的光标消息，保操作消息
        while (queue.size() > 500) {
            queue.poll();
        }
    }

    /** 批量发送：合并后逐会话异步发送，失败即关闭会话（客户端会重连） */
    private void flushAll() {
        queues.forEach((boardId, queue) -> {
            if (queue.isEmpty()) {
                return;
            }
            List<String> batch = new ArrayList<>();
            while (!queue.isEmpty()) {
                batch.add(queue.poll());
            }
            ConcurrentHashMap<String, WebSocketSession> sessions = boards.get(boardId);
            if (sessions == null) {
                return;
            }
            sessions.values().forEach(session -> {
                try {
                    // 批量合并成一条消息：["op1","op2",...]
                    String payload = "{\"type\":\"batch\",\"data\":"
                            + toJsonArray(batch) + "}";
                    session.sendMessage(new TextMessage(payload));
                } catch (Exception e) {
                    closeQuietly(session);   // 发送失败：关闭，客户端重连补同步
                }
            });
        });
    }

    /** 立即广播（成员上下线等低频消息用） */
    public void broadcast(String boardId, String message, String excludeSessionId) {
        ConcurrentHashMap<String, WebSocketSession> sessions = boards.get(boardId);
        if (sessions == null) {
            return;
        }
        sessions.forEach((sid, session) -> {
            if (sid.equals(excludeSessionId)) {
                return;
            }
            try {
                session.sendMessage(new TextMessage(message));
            } catch (Exception e) {
                closeQuietly(session);
            }
        });
    }

    private String toJsonArray(List<String> messages) {
        return "[" + String.join(",", messages) + "]";
    }

    private void closeQuietly(WebSocketSession session) {
        try {
            session.close(CloseStatus.SERVER_ERROR);
        } catch (Exception ignored) {
            // 关闭失败忽略
        }
    }
}
```

### 7. 历史回放服务：快照生成、回放与版本恢复

```java
@Service
public class BoardHistoryService {

    @Autowired
    private BoardMapper boardMapper;
    @Autowired
    private BoardSnapshotMapper snapshotMapper;
    @Autowired
    private BoardOpLogMapper opLogMapper;
    @Autowired
    private CrdtStateManager stateManager;
    @Autowired
    private BoardSessionRegistry sessionRegistry;

    /** 定时/阈值触发快照：操作数达到阈值（如 200）或每 5 分钟 */
    @Scheduled(fixedRate = 5 * 60 * 1000)
    public void autoSnapshot() {
        for (Board board : boardMapper.selectActive()) {
            makeSnapshot(board.getId());
        }
    }

    /** 生成快照：当前 CRDT 状态序列化 + 记录对应操作日志最大 id */
    @Transactional(rollbackFor = Exception.class)
    public void makeSnapshot(Long boardId) {
        Board board = boardMapper.selectById(boardId);
        CrdtStateManager.BoardCrdtState state = stateManager.get(boardId);
        BoardSnapshot snapshot = new BoardSnapshot();
        snapshot.setBoardId(boardId);
        snapshot.setSnapshotNo(board.getLastSnapshotNo() + 1);
        snapshot.setSnapshotJson(state.toJson());
        snapshot.setOpSeq(opLogMapper.maxId(boardId));
        snapshotMapper.insert(snapshot);
        board.setLastSnapshotNo(snapshot.getSnapshotNo());
        boardMapper.updateById(board);
    }

    /**
     * 回放到指定快照：快照基线 + 该快照之后的增量操作重放
     * 返回重放后的完整画布状态 JSON（供前端渲染或导出）
     */
    public String replay(Long boardId, int snapshotNo) {
        BoardSnapshot snapshot = snapshotMapper.selectByNo(boardId, snapshotNo);
        if (snapshot == null) {
            throw new BizException("快照不存在");
        }
        // 用独立状态实例重放，不影响在线实时状态
        CrdtStateManager.BoardCrdtState state = new CrdtStateManager.BoardCrdtState();
        state.loadFromJson(snapshot.getSnapshotJson());
        // 重放增量操作（op_seq 之后的全部操作，按 id 顺序）
        List<BoardOpLog> ops = opLogMapper.selectAfterId(boardId, snapshot.getOpSeq(), 100000);
        for (BoardOpLog op : ops) {
            stateManager.replayInto(state, op);   // 按同一 CRDT 规则重放
        }
        return state.toJson();
    }

    /** 版本恢复：把历史状态广播给所有在线成员（全量替换操作） */
    public void restore(Long boardId, int snapshotNo, Long operatorId) {
        String stateJson = replay(boardId, snapshotNo);
        // 广播全量替换消息：各端清空画布后加载恢复状态
        sessionRegistry.broadcast(boardId,
                "{\"type\":\"fullState\",\"data\":" + stateJson + "}", null);
        accessLogMapper.insert(boardId, operatorId, "restore", "恢复到快照 " + snapshotNo);
    }
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. opId 全局唯一 + 幂等三保险：opId 用 clientId:seq 生成，Redis SETNX + 数据库唯一索引（board_id, op_id）+ 内存 seen 集合，重连重发/重复广播任意场景都不会产生重复操作
2. 乐观更新 + 服务端仲裁：客户端本地先渲染（零延迟），服务端 CRDT 合并结果为准，冲突按 HLC 时钟裁决，两端最终收敛一致
3. 快照 + 增量重放：定期快照（操作数阈值 + 时间双触发），回放成本 = 快照 + 增量操作，永远不做全量重放；快照同时是版本恢复的基线
4. 广播分优先级：图形操作必达（批量窗口 + 可靠发送，失败关连接触发重连补同步），光标可丢（只保留最新值覆盖旧值），队列超限丢光标保操作
5. 光标限频合并：客户端 20Hz 上报 + 服务端 50ms 批量窗口内同类型消息只保留最新，光标消息占比从 90% 降到可接受水平
6. 心跳保活与断线增量同步：30 秒 ping/pong 保活，断线重连后按 lastOpId 增量拉取，无需全量重传
7. 权限在服务端强制：viewer 只是前端隐藏编辑按钮，服务端对非 editor 的操作直接拒绝，绕不过去

### 踩坑记录

```text
坑 1：并发操作互相覆盖
结论：两人同时拖同一个图形，后到的消息把先到的覆盖，图形来回跳。
原因：用「全量状态覆盖」同步，没有元素级合并。
解法：改为 CRDT 元素级合并——图形增删用 OR-Set（add-wins），属性修改用 LWW（时间戳大者胜），并发操作按确定性规则收敛。

坑 2：重连重发产生重复图形
结论：断线重连后客户端重发操作，同一个矩形出现两个。
原因：操作没有全局唯一 id，服务端无法识别重复消息。
解法：opId 用 clientId:seq 生成且全局唯一，服务端按 opId 幂等去重（Redis + 数据库唯一索引双保险）。

坑 3：广播风暴打爆连接
结论：20 人同时快速拖动图形，服务端消息量每秒上万条，带宽与 CPU 飙升。
原因：每笔操作立即逐会话发送，没有批量与合并。
解法：50ms 批量窗口合并发送（一批消息合成一条 batch），队列上限保护，光标类消息同窗口只保留最新。

坑 4：光标消息淹没操作消息
结论：鼠标移动消息占消息总量 90%，真正有价值的图形操作被挤占。
原因：光标与操作同一优先级、同样频率广播。
解法：光标限频（客户端 20Hz + 服务端 50ms 合并），队列超限时优先丢弃光标消息，保证操作消息不丢。

坑 5：回放从零开始太慢
结论：画了 5 万笔操作的白板，回放要几分钟，页面卡死。
原因：每次回放都从空状态重放全部操作日志。
解法：定期快照 + 增量重放：回放 = 目标快照 + 快照之后的少量操作；快照触发用「操作数阈值 + 时间」双条件。

坑 6：时钟回拨导致 LWW 误判
结论：某客户端系统时间被 NTP 校准回拨，它发的操作时间戳更小，被旧操作覆盖。
原因：LWW 只比较物理时间戳，客户端时钟不可靠。
解法：用 HLC（混合逻辑时钟）：物理时间戳 + 客户端计数器，同时间戳按计数器裁决；客户端时间落后时本地时钟追赶服务端时钟再发操作。

坑 7：查看者绕过前端直接发操作
结论：viewer 用户用脚本直接向 WebSocket 发 addShape 消息，画布被乱涂。
原因：前端隐藏了编辑按钮，但服务端没有权限校验。
解法：服务端对写操作强制校验成员角色（editor 及以上），viewer 的写操作直接拒绝并记录审计日志。
```

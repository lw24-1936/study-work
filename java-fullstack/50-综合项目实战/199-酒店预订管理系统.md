## 项目背景

酒店预订管理系统（PMS，Property Management System）是酒店行业的核心业务系统，一头连着 C 端预订渠道（官网、小程序、OTA 平台），一头连着酒店前台的入住办理、房态管理和财务结算。它比普通的电商订单系统多两个棘手问题：一是「库存」不是单一商品，而是「房型 x 日期」的二维组合（同一房型同一日期不能超卖，跨多晚的订单要逐晚锁房），二是订单状态跨多个物理动作（预订、支付、入住、退房、取消），状态流转必须严格受控。再加上房价随日期浮动（节假日上浮、连住优惠）、超时未支付自动取消、收益统计等业务，是练习「并发控制 + 状态机 + 缓存一致性」的完整战场。

业务痛点：

```text
1. 超售：同一房型同一日期被重复卖出，客人到店无房，投诉与赔偿不断
2. 房态不实时：前台只能靠 Excel 或口头问询判断可售房，渠道信息滞后
3. 订单状态混乱：预订/入住/离店/取消全靠人工登记，退房后房间迟迟不释放
4. 超时订单不清理：客人订了不付钱，房间被占着卖不出去
5. 房价管理粗放：旺季淡季一个价，节假日定价靠拍脑袋，收益流失
6. 收益统计靠手工：房费收入、入住率、平均房价（ADR）对不上账，财务月底加班
```

目标用户与核心诉求：

```text
1. 宾客：在线查房态、预订下单、支付、取消，到店快速办理入住
2. 前台：办理预订/入住/退房、换房、处理取消，房态一目了然
3. 酒店运营：房型/房价管理、房态日历维护、渠道库存分配、收益分析
4. 财务：收入对账、订单审计、按日/按房型的收益报表
```

项目要解决的核心问题一句话概括：用「房型 x 日期」的库存模型管住每一间夜，用状态机管住订单的每一次流转，让房态实时准确、订单可追溯、收益算得清。

## 功能介绍

功能按角色拆成三个端：宾客端（预订）、前台端（到店办理）、运营端（房态与收益）。

```text
一、宾客端
1. 房型浏览 —— 房型列表（图片/面积/床型/可住人数/设施）、价格日历
2. 房态日历 —— 查看某房型未来 30 天每晚可售状态与房价
3. 预订下单 —— 选房型 + 入住/离店日期 + 间数，锁房并生成订单（待支付）
4. 支付 —— 在线支付（对接支付网关），支付后订单确认
5. 取消 —— 按取消政策取消订单（入住前可免费取消，部分预付单不可取消）
6. 我的订单 —— 订单列表/详情、电子凭证、发票申请

二、前台端
1. 预订办理 —— 电话/到店订单录入（来源=前台），代客下单
2. 入住办理 —— 校验订单与证件，分配具体房间号，房态占用
3. 退房办理 —— 结算房费与杂费（加床/迷你吧），释放房间
4. 换房/续住 —— 房型升级差价补收，续住延长房态占用
5. 当日房态板 —— 在住/待入住/已退/脏房/维修房五态看板

三、运营端
1. 房型管理 —— 房型增删改查、房间总数、基础配置（床型/面积/设施）
2. 房价管理 —— 基础房价 + 日期覆盖价（节假日上调、淡季促销）+ 连住折扣
3. 房态日历管理 —— 整房/维修房设置、限售数量设置
4. 订单管理 —— 全量订单查询、超时订单手动处理、异常订单介入
5. 收益统计 —— 每日营收、入住率（OCC）、平均房价（ADR）、每间可售房收入（RevPAR）
```

## 技术选型

| 组件 | 选型 | 理由 |
|------|------|------|
| 开发框架 | Spring Boot 2.7/3.x | 生态成熟，起步快 |
| 持久层 | MyBatis-Plus | 房型/房间/房价/订单单表 CRUD，统计聚合走自定义 SQL |
| 数据库 | MySQL 8.0 | 订单、房态快照、房价落库，事务保证状态变更原子性 |
| 缓存 | Redis | 房态日历缓存、间夜锁房计数（Lua）、防重标记 |
| 分布式锁 | Redisson | 超时取消、对账等跨实例互斥动作 |
| 消息队列 | RabbitMQ（可选） | 订单事件（下单/支付/取消）异步通知渠道与报表 |
| 定时任务 | XXL-Job / Spring @Scheduled | 超时未支付自动取消、房态对账、收益日结 |
| 前端 | Vue 3 + Element Plus | 后台管理 + 预订 H5 |
| 鉴权 | Spring Security + JWT | 宾客/前台/运营三角色 |
| 报表 | ECharts | 收益趋势、入住率图表 |

选型说明：

```text
1. 间夜库存用 Redis 计数：key = hotel:sold:{roomTypeId}:{date}，值 = 该房型该日期已售间夜数；Lua 脚本一次校验多晚日期，任一天不足整单回滚，杜绝「前几晚锁了后几晚超卖」
2. 房价分层：基础房价（room_type 表）+ 日期覆盖价（room_rate 表），查询时按日期优先取覆盖价，节假日调价不需要动基础数据
3. 订单状态机管理：已预订/已支付/已入住/已离店/已取消五态，每个流转动作（支付/入住/退房/取消）先过状态机校验再落库
4. 超时取消用定时任务 + 分布式锁：每分钟扫描待支付超 30 分钟的订单，逐单加锁处理，避免与用户支付动作并发打架
```

请求链路示例（宾客预订下单）：

```text
1. 前端 POST /api/booking/order，JWT 校验宾客身份
2. Service 校验：入住日期 < 离店日期、房型存在且可售、间数不超过房型总数
3. 计算总价：逐晚查房价（覆盖价优先），累加间数 x 每晚价
4. 构造入住期间每一天的房态 key，Lua 脚本原子校验并锁定间夜
5. 任一天库存不足：整单回滚，返回「所选日期房间不足」
6. 锁房成功创建订单（状态=已预订/待支付），返回订单号
7. 30 分钟未支付：定时任务扫描取消订单并回滚房态；支付成功则订单确认
```

入住/退房链路：

```text
1. 前台办理入住：校验订单状态=已支付，分配具体房间号（到店选房，不锁具体房号）
2. 房间状态置为占用，订单状态流转 已支付 -> 已入住
3. 退房：结算房费与杂费，订单状态流转 已入住 -> 已离店
4. 房间状态置为脏房（待保洁），保洁完成后置为空净房
5. 已离店订单计入收益统计，按离店日期归账
```

## 核心实现

### 1. 锁房：Lua 脚本批量扣减间夜（防超卖）

```java
@Component
public class RoomLockScript {

    /**
     * Lua 脚本：逐日校验库存，任一天不足则回滚已扣日期，整单失败
     * KEYS = 每晚的已售计数 key（hotel:sold:{roomTypeId}:{date}）
     * ARGV[1] = 预订间数，ARGV[2] = 该房型房间总数
     */
    public static final String SCRIPT =
            "for i = 1, #KEYS do " ..
            "    local sold = tonumber(redis.call('GET', KEYS[i]) or '0') " ..
            "    if sold + tonumber(ARGV[1]) > tonumber(ARGV[2]) then " ..
            "        for j = 1, i - 1 do " ..
            "            redis.call('DECR', KEYS[j]) " ..   // 回滚已扣日期
            "        end " ..
            "        return -1 " ..
            "    end " ..
            "end " ..
            "for i = 1, #KEYS do " ..
            "    redis.call('INCR', KEYS[i]) " ..
            "end " ..
            "return 1";

    public static final DefaultRedisScript<Long> INSTANCE = new DefaultRedisScript<>(SCRIPT, Long.class);
}
```

### 2. 预订下单：锁房 + 算价 + 建单

```java
@Service
public class BookingService {

    private static final String SOLD_KEY = "hotel:sold:";
    private static final String DONE_KEY = "hotel:done:";

    @Autowired
    private StringRedisTemplate redisTemplate;
    @Autowired
    private BookingOrderMapper orderMapper;
    @Autowired
    private RoomTypeMapper roomTypeMapper;
    @Autowired
    private RoomRateMapper roomRateMapper;
    @Autowired
    private OrderRoomDetailMapper detailMapper;

    /**
     * 预订下单：校验 -> 算价 -> Lua 锁房 -> 建单（待支付）
     */
    public Long createOrder(BookingDTO dto) {
        // 1. 基础校验：日期合法、间数合理
        if (!dto.getCheckIn().isBefore(dto.getCheckOut())) {
            throw new BizException("入住日期必须早于离店日期");
        }
        RoomType roomType = roomTypeMapper.selectById(dto.getRoomTypeId());
        if (roomType == null || roomType.getStatus() == 0) {
            throw new BizException("房型不存在或已停售");
        }
        if (dto.getRoomCount() > roomType.getRoomTotal()) {
            throw new BizException("预订间数超过房型总量");
        }
        // 2. 防重：同用户 30 秒内重复提交拦截（先于锁房，失败要释放）
        String doneKey = DONE_KEY + dto.getUserId() + ":" + dto.getCheckIn() + ":" + dto.getRoomTypeId();
        Boolean first = redisTemplate.opsForValue().setIfAbsent(doneKey, "1", 30, TimeUnit.SECONDS);
        if (!Boolean.TRUE.equals(first)) {
            throw new BizException("请勿重复提交");
        }
        // 3. 计算总价：逐晚取房价（覆盖价优先于基础价），间数 x 每晚价累加
        long totalAmount = calcAmount(roomType, dto.getCheckIn(), dto.getCheckOut(), dto.getRoomCount());
        // 4. 构造每晚房态 key，Lua 原子锁房
        List<String> keys = new ArrayList<>();
        for (LocalDate d = dto.getCheckIn(); d.isBefore(dto.getCheckOut()); d = d.plusDays(1)) {
            keys.add(SOLD_KEY + dto.getRoomTypeId() + ":" + d);
        }
        Long result = redisTemplate.execute(RoomLockScript.INSTANCE, keys,
                String.valueOf(dto.getRoomCount()),
                String.valueOf(roomType.getRoomTotal()));
        if (result == null || result < 0) {
            redisTemplate.delete(doneKey);
            throw new BizException("所选日期房间不足，请调整日期或房型");
        }
        // 5. 创建订单，状态=0 已预订（待支付）
        BookingOrder order = new BookingOrder();
        order.setOrderNo(OrderNoGenerator.next("HTL"));
        order.setUserId(dto.getUserId());
        order.setRoomTypeId(dto.getRoomTypeId());
        order.setRoomCount(dto.getRoomCount());
        order.setCheckIn(dto.getCheckIn());
        order.setCheckOut(dto.getCheckOut());
        order.setTotalAmount(BigDecimal.valueOf(totalAmount));
        order.setStatus(0);
        orderMapper.insert(order);
        // 6. 写间夜明细（对账基准），每晚一条
        for (LocalDate d = dto.getCheckIn(); d.isBefore(dto.getCheckOut()); d = d.plusDays(1)) {
            OrderRoomDetail detail = new OrderRoomDetail();
            detail.setOrderId(order.getId());
            detail.setRoomTypeId(dto.getRoomTypeId());
            detail.setStayDate(d);
            detail.setPrice(priceOf(roomType, d));
            detailMapper.insert(detail);
        }
        return order.getId();
    }

    /**
     * 算价：逐晚取覆盖价，无覆盖价用基础价；间数 x 每晚价累加
     * 扩展点：连住 3 晚以上 9 折在此处叠加
     */
    private long calcAmount(RoomType roomType, LocalDate checkIn, LocalDate checkOut, int count) {
        long total = 0;
        for (LocalDate d = checkIn; d.isBefore(checkOut); d = d.plusDays(1)) {
            total += priceOf(roomType, d) * count;
        }
        return total;
    }

    /**
     * 单晚房价：room_rate 覆盖价优先，否则基础价（单位：分，避免浮点误差）
     */
    private long priceOf(RoomType roomType, LocalDate date) {
        RoomRate rate = roomRateMapper.selectByTypeAndDate(roomType.getId(), date);
        return rate != null ? rate.getPriceCents() : roomType.getBasePriceCents();
    }
}
```

### 3. 订单状态机

```java
@Component
public class OrderStatusMachine {

    /**
     * 订单状态机：
     *   0已预订 -> 1已支付（支付成功） / 4已取消（超时未付/用户取消）
     *   1已支付 -> 2已入住（到店办理） / 4已取消（入住前退款取消）
     *   2已入住 -> 3已离店（退房结算）
     *   3已离店 / 4已取消 为终态
     * 所有状态变更入口必须先调用 transit 校验，非法流转直接抛异常
     */
    private static final Map<Integer, Set<Integer>> TRANSITIONS = Map.of(
            0, Set.of(1, 4),
            1, Set.of(2, 4),
            2, Set.of(3),
            3, Set.of(),
            4, Set.of()
    );

    public void transit(int from, int to) {
        Set<Integer> allowed = TRANSITIONS.getOrDefault(from, Set.of());
        if (!allowed.contains(to)) {
            throw new BizException("非法的订单状态流转：" + from + " -> " + to);
        }
    }
}
```

### 4. 超时未支付自动取消

```java
@Component
public class AutoCancelTask {

    private static final long PAY_TIMEOUT_MINUTES = 30;

    @Autowired
    private BookingOrderMapper orderMapper;
    @Autowired
    private OrderRoomDetailMapper detailMapper;
    @Autowired
    private RedissonClient redissonClient;
    @Autowired
    private StringRedisTemplate redisTemplate;
    @Autowired
    private OrderStatusMachine statusMachine;

    /**
     * 每分钟扫描：已预订(0) 且创建超过 30 分钟的订单，自动取消并回滚房态
     * 逐单加分布式锁，防止与「用户正在支付」的流程并发冲突
     */
    @Scheduled(fixedDelay = 60 * 1000)
    public void cancelTimeoutOrders() {
        Date deadline = new Date(System.currentTimeMillis() - PAY_TIMEOUT_MINUTES * 60_000L);
        List<BookingOrder> expired = orderMapper.selectByStatusBefore(0, deadline);
        for (BookingOrder order : expired) {
            RLock lock = redissonClient.getLock("hotel:cancel:" + order.getId());
            if (!lock.tryLock()) {
                continue; // 该单正被其他流程处理（如支付回调）
            }
            try {
                // 二次校验：可能刚被用户支付成功，状态已变
                BookingOrder latest = orderMapper.selectById(order.getId());
                if (latest.getStatus() != 0) {
                    continue;
                }
                // 状态机校验 + 落库
                statusMachine.transit(latest.getStatus(), 4);
                latest.setStatus(4);
                latest.setCancelReason("超时未支付自动取消");
                orderMapper.updateById(latest);
                // 回滚房态：释放每晚会占用的间夜（Redis + MySQL 快照）
                releaseNightStock(latest);
            } finally {
                lock.unlock();
            }
        }
    }

    /**
     * 回滚间夜：Redis 已售计数 -1（负数兜底归零），明细标记已释放
     */
    private void releaseNightStock(BookingOrder order) {
        for (LocalDate d = order.getCheckIn(); d.isBefore(order.getCheckOut()); d = d.plusDays(1)) {
            String key = "hotel:sold:" + order.getRoomTypeId() + ":" + d;
            Long sold = redisTemplate.opsForValue().decrement(key);
            if (sold != null && sold < 0) {
                redisTemplate.opsForValue().set(key, "0");
            }
            detailMapper.releaseByOrderAndDate(order.getId(), d);
        }
    }
}
```

### 5. 入住 / 退房办理

```java
@Service
public class CheckInOutService {

    @Autowired
    private BookingOrderMapper orderMapper;
    @Autowired
    private RoomMapper roomMapper;
    @Autowired
    private OrderStatusMachine statusMachine;

    /**
     * 入住办理：校验订单状态 -> 分配具体房间号 -> 状态 1 -> 2
     * 预订阶段只锁房型库存不锁具体房号，到店由前台选房，灵活应对换房
     */
    public void checkIn(Long orderId, List<Long> roomIds) {
        BookingOrder order = orderMapper.selectById(orderId);
        if (order == null) {
            throw new BizException("订单不存在");
        }
        // 1. 状态机校验：只有 已支付(1) 能入住
        statusMachine.transit(order.getStatus(), 2);
        // 2. 校验房间：属于订单房型、当前空闲、数量与订单一致
        if (roomIds.size() != order.getRoomCount()) {
            throw new BizException("分配房间数量与订单不符");
        }
        for (Long roomId : roomIds) {
            Room room = roomMapper.selectById(roomId);
            if (room == null || !room.getRoomTypeId().equals(order.getRoomTypeId())
                    || room.getStatus() != 0) {
                throw new BizException("房间不可用：" + roomId);
            }
        }
        // 3. 批量占房 + 状态流转
        roomMapper.batchOccupy(roomIds);
        order.setStatus(2);
        order.setCheckInTime(new Date());
        orderMapper.updateById(order);
    }

    /**
     * 退房办理：状态 2 -> 3，释放房间，订单计入收益统计
     * 杂费（加床/迷你吧）在前台账单中单独结算，不改变订单总额
     */
    public void checkOut(Long orderId) {
        BookingOrder order = orderMapper.selectById(orderId);
        if (order == null) {
            throw new BizException("订单不存在");
        }
        statusMachine.transit(order.getStatus(), 3);
        // 释放订单占用的房间（置为脏房，待保洁后恢复空净房）
        roomMapper.releaseByOrder(orderId);
        order.setStatus(3);
        order.setCheckOutTime(new Date());
        orderMapper.updateById(order);
    }
}
```

### 6. 房态日历与收益统计

```java
@Service
public class RoomStatusService {

    private static final String SOLD_KEY = "hotel:sold:";

    @Autowired
    private StringRedisTemplate redisTemplate;
    @Autowired
    private RoomTypeMapper roomTypeMapper;
    @Autowired
    private RoomStatusMapper roomStatusMapper;

    /**
     * 房态日历：返回某房型未来 N 天每晚的可售间夜数
     * 可售 = 房间总数 - 已售计数（Redis），未初始化日期按 0 处理
     */
    public Map<String, Integer> calendar(Long roomTypeId, LocalDate start, int days) {
        RoomType roomType = roomTypeMapper.selectById(roomTypeId);
        Map<String, Integer> result = new LinkedHashMap<>();
        for (int i = 0; i < days; i++) {
            LocalDate date = start.plusDays(i);
            String key = SOLD_KEY + roomTypeId + ":" + date;
            String sold = redisTemplate.opsForValue().get(key);
            int soldCount = sold == null ? 0 : Integer.parseInt(sold);
            result.put(date.toString(), Math.max(roomType.getRoomTotal() - soldCount, 0));
        }
        return result;
    }

    /**
     * 每小时对账：Redis 已售计数与 MySQL room_status 快照核对
     * Redis 重启丢失计数时，以 MySQL 快照重建（Redis 是主，MySQL 是恢复依据）
     */
    @Scheduled(cron = "0 30 * * * ?")
    public void reconcile() {
        List<RoomStatus> snapshots = roomStatusMapper.selectRecent(30);
        for (RoomStatus s : snapshots) {
            String key = SOLD_KEY + s.getRoomTypeId() + ":" + s.getStatusDate();
            String sold = redisTemplate.opsForValue().get(key);
            if (sold == null) {
                // Redis 无值：用 MySQL 快照重建
                redisTemplate.opsForValue().set(key, String.valueOf(s.getSoldCount()));
            }
        }
    }
}
```

```java
public class RevenueStatService {

    private static final String REV_KEY = "hotel:revenue:";

    @Autowired
    private BookingOrderMapper orderMapper;
    @Autowired
    private StringRedisTemplate redisTemplate;

    /**
     * 收益统计：按日/按房型聚合已入住与已离店订单的房费
     * 核心指标：营收、入住率 OCC（售出间夜/可售间夜）、平均房价 ADR（营收/售出间夜）
     * 结果缓存 5 分钟，统计接口不反复跑大 SQL
     */
    public RevenueVO statRevenue(LocalDate start, LocalDate end) {
        String cacheKey = REV_KEY + start + ":" + end;
        String cached = redisTemplate.opsForValue().get(cacheKey);
        if (cached != null) {
            return JSON.parseObject(cached, RevenueVO.class);
        }
        // SQL 聚合：按 check_out_time 归账，只统计 status IN (2,3) 的真实住店订单
        // SELECT DATE(check_out_time) day, room_type_id,
        //        SUM(total_amount) revenue, COUNT(DISTINCT order_id) orders
        //   FROM booking_order
        //  WHERE status IN (2,3) AND check_out_time BETWEEN ...
        //  GROUP BY day, room_type_id
        RevenueVO vo = orderMapper.statRevenue(start, end);
        // 入住率与 ADR 在 Java 层计算，避免 SQL 里写死业务口径
        vo.calcOccAdr();
        redisTemplate.opsForValue().set(cacheKey, JSON.toJSONString(vo), 5, TimeUnit.MINUTES);
        return vo;
    }
```

### 场景一：连锁酒店官网 + OTA 渠道预订

某连锁酒店集团 20 家门店上线自有预订平台，同时对接携程/美团等 OTA，超卖是最大风险：

```text
1. 集团在运营后台维护 6 种标准房型，每家门店配置房间总数与基础房价
2. 节假日调价：运营在房价管理里为五一/国庆三天设置覆盖价，基础价不动
3. 宾客在官网预订「大床房 5 月 1 日-3 日 2 间」：Lua 脚本逐晚校验 2 间库存，任一天不足整单拒绝
4. OTA 渠道订单走同一套接口：渠道间夜与官网共享同一 Redis 计数，天然防超卖
5. 宾客 30 分钟未支付，定时任务自动取消并回滚房态，房间回到可售池
6. 到店办理入住分配具体房号；退房后房间置脏房，保洁完成恢复可售
7. 财务看每日收益报表：营收、入住率、ADR 自动归账，月底对账半小时完成
```

### 场景二：单体民宿/精品酒店前台办理

小型民宿没有独立 PMS，前台用本系统管理 15 间客房，重点是房态准确与订单留痕：

```text
4. 客人到店：核对证件后办理入住，分配具体房号，订单状态自动流转
5. 提前离店：退房时按实际住店晚数结算，多收的房费原路退回
6. 淡季促销：运营把未来 30 天工作日的覆盖价调低，收益统计里能看到促销效果
```

### 场景三：会议型酒店团房预订

会议型酒店旺季接团队房（50 间连住 3 天），团房与散客房共享库存，锁房粒度要一致：

## 最佳实践与踩坑记录

### 最佳实践

1. 间夜库存模型（房型 x 日期）统一用 Redis 计数：key 设计成 hotel:sold:{roomTypeId}:{date}，锁房/释放/查询都基于它，所有渠道共享同一计数天然防超卖
2. 多晚订单必须整单原子校验：Lua 脚本逐日检查，任一天不足回滚已扣日期，杜绝「前几晚锁了后几晚超卖」的中间态
3. 状态机集中管理流转：订单五态流转表用 Map 定义，所有状态变更入口统一调用 transit 校验，新增状态流转只改一处
4. 超时取消要「扫描 + 加锁 + 二次校验」三件套：先查出候选，逐单加 Redisson 锁，处理前再查一次最新状态，避免与支付回调并发打架
5. 房价「基础价 + 日期覆盖价」分层：调价只插 room_rate 覆盖记录，不修改基础数据，历史订单价格可追溯
6. 预订只锁房型库存不锁具体房号：到店分配房间，前台可灵活换房；具体房号被占用时只需改房间状态，不影响库存计数
7. Redis 与 MySQL 双写靠对账兜底：Redis 是房态主数据（扛并发），MySQL room_status 快照是恢复依据，每小时对账重建丢失的计数

### 踩坑记录

```text
坑 1：同一房型同日期超卖
结论：两个订单锁到同一晚最后一间房。
原因：先 GET 已售数判断再 INCR 两步操作有竞态窗口。
解法：改 Lua 脚本原子「校验-扣减-回滚」；脚本内完成全部判断，Redis 单线程执行。

坑 2：多晚订单部分成功
结论：3 晚订单只锁上前 2 晚，第 3 晚超卖。
原因：逐晚独立扣减，没有整单校验。
解法：Lua 脚本先遍历全部日期校验，任一天不足回滚已扣的日期再返回失败。

坑 3：超时取消与用户支付并发
结论：用户刚支付成功，订单却被定时任务取消，房间回滚。
原因：取消任务读到旧状态（待支付），没做二次校验就取消。
解法：逐单加分布式锁 + 锁内重新查库二次校验状态；支付回调同样先抢锁再改状态。

坑 4：取消后房态不释放
结论：订单取消了，房间还是显示不可售。
原因：只改了订单状态，忘了回滚 Redis 已售计数与明细。
解法：取消/退房流程统一走 releaseNightStock：Redis DECR（负数兜底归零）+ 明细标记释放 + MySQL 快照同步，三处一起做。

坑 5：Redis 重启后房态计数丢失
结论：重启后所有日期显示满房（计数变 0 但订单还在）。
原因：已售计数只存在 Redis 内存，没有恢复机制。
解法：room_status 快照表定期落库 + 每小时对账任务重建；Redis 开 AOF 持久化。

坑 6：金额用浮点运算出现 0.1 误差
结论：三晚房价 99.9 与 100 对不上账。
原因：double 累加浮点误差。
解法：金额统一用「分」存储（long），Java 侧 BigDecimal 运算，展示时再转元。
```

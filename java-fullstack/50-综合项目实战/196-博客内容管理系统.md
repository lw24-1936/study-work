## 项目背景

博客内容管理系统（CMS）是内容创作领域最基础也最通用的业务系统，几乎所有内容型产品（技术社区、企业官网、新媒体平台、内部知识库）都离不开一套「写文章、管分类、做搜索、看统计」的后台。选择它作为综合实战项目，是因为它麻雀虽小五脏俱全：既有普通的 CRUD，又有全文检索、缓存、浏览量统计、评论互动等真实业务里高频出现的技术点，能完整覆盖「Spring Boot + 持久层 + 缓存 + 搜索」这条主流技术线。

业务痛点：

```text
1. 手写 HTML 维护文章：改一处样式要动全站，内容与样式耦合严重
2. 无分类无标签：文章多了之后检索困难，读者找不到想看的内容
3. 搜索靠数据库 LIKE：数据量过万后 LIKE '%关键词%' 全表扫描，慢且无法按相关度排序
4. 浏览量、点赞数每次查库：热点文章频繁更新同一行，锁竞争严重
5. 作者与管理员权限不分：任何人都能改任何文章，缺乏角色隔离
6. 无评论审核：垃圾广告评论直接展示，影响内容质量
```

目标用户与核心诉求：

```text
1. 作者：写文章、管理自己的草稿与发布状态、看自己文章的阅读数据
2. 管理员：审核评论、管理全站分类标签、置顶推荐、封禁违规账号
3. 读者：按分类/标签浏览、全文搜索、评论互动、收藏文章
```

项目要解决的核心问题一句话概括：让非技术人员也能通过可视化后台管理内容，让读者能快速找到并消费内容，让运营能掌握内容数据。

## 功能介绍

功能按角色拆成三个端：前台展示端（读者）、作者后台（写作者）、管理后台（管理员）。

```text
一、前台展示端（读者视角）
1. 首页 —— 最新文章列表 + 置顶推荐 + 热门文章榜
2. 文章详情 —— Markdown 渲染、浏览量/点赞/收藏、评论区
3. 分类与标签 —— 按分类浏览、按标签聚合
4. 全文搜索 —— 关键词搜索标题+正文+摘要，按相关度排序
5. 作者主页 —— 某个作者发布的全部文章

二、作者后台（写作者视角）
1. 文章管理 —— 新建/编辑/删除文章，草稿与发布状态切换
2. Markdown 编辑器 —— 实时预览、图片上传（存本地/OSS）
3. 分类标签管理 —— 为文章设置分类与多个标签
4. 数据看板 —— 自己文章的浏览量、点赞数、评论数统计

三、管理后台（管理员视角）
1. 用户管理 —— 作者/读者账号管理，角色分配，封禁/解封
2. 分类管理 —— 分类的增删改查与排序
3. 标签管理 —— 标签合并、清理无文章引用的孤儿标签
4. 评论审核 —— 待审核/已通过/已驳回三态流转
5. 置顶与推荐 —— 文章置顶、首页推荐位管理
6. 全站统计 —— 总文章数、总用户数、总浏览量、近 7 日发文趋势
```

## 技术选型

| 组件 | 选型 | 理由 |
|------|------|------|
| 开发框架 | Spring Boot 2.7/3.x | 生态成熟，起步快，社区资料多 |
| 持久层 | MyBatis-Plus | 单表 CRUD 零 SQL，复杂查询走 XML，兼顾效率与灵活 |
| 数据库 | MySQL 8.0 | 业务数据落库，支持事务与复杂关联查询 |
| 缓存 | Redis | 文章详情缓存、浏览量计数器、热门榜 ZSet |
| 全文检索 | Elasticsearch 8.x | 标题+正文全文搜索，中文分词（IK 分词器） |
| 前端 | Vue 3 + Element Plus（后台）/ Thymeleaf（前台可选） | 后台管理用前后端分离，前台可 SSR 或静态化 |
| 鉴权 | Spring Security + JWT | 无状态认证，前后端分离标配 |
| 文件存储 | 本地磁盘 / MinIO | 图片上传，小项目本地，生产用 MinIO |
| 构建 | Maven | 依赖管理标准工具 |

选型说明：

```text
1. MyBatis-Plus 而非纯 MyBatis：文章/评论/标签都是标准单表 CRUD，MP 的 BaseMapper 直接省掉大量样板代码
2. ES 而非 MySQL LIKE：搜索要按相关度排序、支持中文分词、数据量大不退化，LIKE 做不到
3. Redis 承担三件事：热点文章缓存（读多写少）、浏览量计数器（高频写）、热门榜（ZSet 排序）
4. 浏览量不用 MySQL 实时更新：每次 +1 都 UPDATE 会锁行，先写 Redis，定时批量刷库
```

## 架构设计

系统分层与请求链路：

```text
┌─────────────────────────────────────────────────────────┐
│                     客户端（浏览器）                       │
│  前台页面（Thymeleaf/Vue）   作者后台（Vue3）  管理后台     │
└──────────────────────────────┬──────────────────────────┘
                               │ HTTP / JSON
┌──────────────────────────────▼──────────────────────────┐
│                   Spring Boot 应用层                      │
│  ┌─────────┐ ┌─────────┐ ┌─────────┐ ┌──────────────┐   │
│  │Controller│ │ Service │ │  Mapper  │ │ Security/JWT │   │
│  └─────────┘ └─────────┘ └─────────┘ └──────────────┘   │
└──────┬──────────────────┬──────────────────┬─────────────┘
       │                  │                  │
┌──────▼──────┐   ┌───────▼───────┐   ┌──────▼──────────┐
│   MySQL     │   │    Redis      │   │ Elasticsearch   │
│ 文章/评论/   │   │ 文章缓存/计数  │   │ 文章索引（搜索） │
│ 用户/分类表  │   │ 热门榜/验证码  │   │ 标题+正文+摘要   │
└─────────────┘   └───────────────┘   └─────────────────┘
```

请求链路示例（读者打开一篇文章）：

```text
1. 前端 GET /api/articles/{id}
2. Controller 收到请求，JWT 过滤器校验（公开接口放行）
3. Service 先查 Redis：key = article:detail:{id}
4. Redis 命中 → 直接返回缓存 JSON（浏览量 +1 走独立计数器 key）
5. Redis 未命中 → 查 MySQL（文章表 + 作者信息 + 分类 + 标签）
6. 组装完整 VO 后写回 Redis（TTL 30 分钟），下次命中
7. 浏览量计数器：Redis INCR article:view:{id}，定时任务每 5 分钟批量刷回 MySQL
```

搜索链路（读者搜索「Spring 事务」）：

```text
1. 前端 GET /api/search?kw=Spring 事务
2. Service 调用 ES：multi_match 查询 title^3 + summary^2 + content 字段
3. IK 分词器把「Spring 事务」切成「spring」「事务」
4. ES 按 BM25 相关度排序返回 top 20 文档 id
5. 用 id 回 MySQL 查最新文章详情（ES 只存索引字段，详情以 MySQL 为准）
6. 高亮片段：ES 返回 highlight 片段，前端标红展示
```

## 核心实现

### 1. 文章详情：Redis 缓存 + 缓存穿透防护

```java
@Service
public class ArticleService {

    private static final String DETAIL_KEY = "article:detail:";
    private static final String VIEW_KEY = "article:view:";

    @Autowired
    private ArticleMapper articleMapper;
    @Autowired
    private RedisTemplate<String, Object> redisTemplate;

    /**
     * 文章详情（缓存优先，防止缓存穿透）
     * 穿透防护：查不到时写入空值缓存（TTL 60s），避免恶意请求反复打库
     */
    public ArticleVO getDetail(Long id) {
        String key = DETAIL_KEY + id;
        // 1. 查缓存
        Object cached = redisTemplate.opsForValue().get(key);
        if (cached != null) {
            // 空值占位：防止缓存穿透
            if ("EMPTY".equals(cached)) {
                return null;
            }
            return (ArticleVO) cached;
        }
        // 2. 缓存未命中，查库（关联作者、分类、标签）
        ArticleVO vo = articleMapper.selectDetailById(id);
        if (vo == null) {
            redisTemplate.opsForValue().set(key, "EMPTY", 60, TimeUnit.SECONDS);
            return null;
        }
        // 3. 写缓存，TTL 30 分钟（文章变更时主动删缓存）
        redisTemplate.opsForValue().set(key, vo, 30, TimeUnit.MINUTES);
        return vo;
    }

    /**
     * 浏览量 +1：先写 Redis 计数器，定时批量刷库
     * 用 Hash 结构避免大量独立 key 难管理：hash key = article:views，field = 文章id
     */
    public void incrView(Long id) {
        redisTemplate.opsForHash().increment("article:views", String.valueOf(id), 1);
    }
}
```

### 2. 浏览量定时批量刷库

```java
@Component
public class ViewCountSyncTask {

    @Autowired
    private RedisTemplate<String, Object> redisTemplate;
    @Autowired
    private ArticleMapper articleMapper;

    /**
     * 每 5 分钟把 Redis 中的浏览量增量刷回 MySQL
     * 刷完删除 Hash 中已处理字段，避免重复累加
     */
    @Scheduled(fixedDelay = 5 * 60 * 1000)
    public void syncViewCount() {
        String hashKey = "article:views";
        Map<Object, Object> views = redisTemplate.opsForHash().entries(hashKey);
        if (views.isEmpty()) {
            return;
        }
        views.forEach((articleId, count) -> {
            Long id = Long.valueOf(articleId.toString());
            Long incr = Long.valueOf(count.toString());
            articleMapper.incrViewCount(id, incr);
            // 刷库成功后删除对应字段（用 delete 而非整体删除，保证增量语义）
            redisTemplate.opsForHash().delete(hashKey, articleId);
        });
    }
}
```

### 3. 全文搜索（ES + IK 分词）

```java
@Service
public class SearchService {

    @Autowired
    private RestHighLevelClient esClient;

    /**
     * 关键词搜索：标题权重最高，摘要次之，正文最低
     * 返回文章 id 列表 + 高亮片段
     */
    public List<SearchHitVO> search(String keyword, int page, int size) {
        SearchSourceBuilder source = new SearchSourceBuilder();
        // multi_match：title^3 表示标题命中权重是正文的 3 倍
        source.query(QueryBuilders.multiMatchQuery(keyword)
                .field("title", 3.0f)
                .field("summary", 2.0f)
                .field("content")
                .analyzer("ik_max_word"));
        // 高亮：命中词用 <em> 包裹，前端渲染标红
        HighlightBuilder highlight = new HighlightBuilder()
                .field("title").field("summary")
                .preTags("<em class='hl'>").postTags("</em>");
        source.highlighter(highlight);
        source.from((page - 1) * size).size(size);

        SearchRequest request = new SearchRequest("article_index");
        request.source(source);
        try {
            SearchResponse response = esClient.search(request, RequestOptions.DEFAULT);
            // 解析 hits，组装 SearchHitVO（id + 高亮标题 + 高亮摘要）
            List<SearchHitVO> result = new ArrayList<>();
            for (SearchHit hit : response.getHits().getHits()) {
                Map<String, Object> fields = hit.getSourceAsMap();
                SearchHitVO vo = new SearchHitVO();
                vo.setId(Long.valueOf(hit.getId()));
                // 优先取高亮字段，没有高亮则取原文
                Map<String, HighlightField> hl = hit.getHighlightFields();
                vo.setTitle(hl.containsKey("title")
                        ? hl.get("title").fragments()[0].string()
                        : String.valueOf(fields.get("title")));
                result.add(vo);
            }
            return result;
        } catch (IOException e) {
            throw new RuntimeException("ES 搜索失败", e);
        }
    }
}
```

### 4. 文章发布同步索引（MySQL 与 ES 一致性）

```java
@Service
public class ArticleIndexSync {

    @Autowired
    private RestHighLevelClient esClient;

    /**
     * 文章发布/更新时同步到 ES
     * 只索引搜索需要的字段：id、title、summary、content、publishTime
     * 删除文章时同步删除索引，保证搜索不到已删除内容
     */
    public void indexArticle(Article article) {
        Map<String, Object> doc = new HashMap<>();
        doc.put("title", article.getTitle());
        doc.put("summary", article.getSummary());
        doc.put("content", article.getContent());
        doc.put("publishTime", article.getPublishTime());

        IndexRequest request = new IndexRequest("article_index")
                .id(String.valueOf(article.getId()))
                .source(doc, XContentType.JSON);
        try {
            esClient.index(request, RequestOptions.DEFAULT);
        } catch (IOException e) {
            // 生产环境：记日志 + 发 MQ 重试，保证最终一致
            log.error("文章索引同步失败, id={}", article.getId(), e);
        }
    }

    public void deleteIndex(Long articleId) {
        DeleteRequest request = new DeleteRequest("article_index")
                .id(String.valueOf(articleId));
        try {
            esClient.delete(request, RequestOptions.DEFAULT);
        } catch (IOException e) {
            log.error("文章索引删除失败, id={}", articleId, e);
        }
    }
}
```

### 5. 热门文章榜（Redis ZSet）

```java
@Service
public class HotRankService {

    private static final String HOT_RANK_KEY = "article:hot:rank";

    @Autowired
    private RedisTemplate<String, Object> redisTemplate;

    /**
     * 发布文章时初始化 ZSet 成员（score = 浏览量 + 点赞数*5 + 评论数*10）
     * 定时任务每小时用浏览量增量更新 score
     */
    public void refreshHotRank() {
        // 1. 从 MySQL 取近 7 天文章，计算热度分
        List<Article> articles = articleMapper.selectRecentArticles(7);
        ZSetOperations<String, Object> zset = redisTemplate.opsForZSet();
        for (Article a : articles) {
            long score = a.getViewCount()
                    + a.getLikeCount() * 5L
                    + commentCount(a.getId()) * 10L;
            zset.add(HOT_RANK_KEY, String.valueOf(a.getId()), score);
        }
        // 2. 只保留前 50，防止 ZSet 无限膨胀
        zset.removeRange(HOT_RANK_KEY, 50, -1);
    }

    /**
     * 读者点「热门榜」：取 ZSet 倒序前 N 条
     */
    public List<Long> topN(int n) {
        Set<Object> ids = redisTemplate.opsForZSet()
                .reverseRange(HOT_RANK_KEY, 0, n - 1);
        return ids.stream().map(o -> Long.valueOf(o.toString())).toList();
    }
}
```

## 实际应用场景

### 场景一：技术社区的技术博客模块

某技术社区要上线「技术博客」板块，作者写文章、读者搜索阅读。用本系统的完整能力：

```text
1. 作者登录后台（JWT 认证），写 Markdown 文章，选分类「Java」「架构」加标签「Spring」「Redis」
2. 点「发布」：status 置为 1，publish_time 写入，同步索引到 ES
3. 读者在首页看到最新列表；搜「Redis 缓存」时 ES 按相关度返回，标题高亮
4. 读者打开文章：Redis 命中详情缓存秒开，浏览量计数走 Redis 异步累加
5. 运营看管理后台：热门榜前 50 自动生成，把爆文置顶、推荐到首页
6. 恶意评论被评论审核拦住，管理员驳回后读者不可见
```

### 场景二：企业内部知识库

公司内部 Wiki 化改造，员工写技术方案、运维手册，部门间共享：

```text
1. 管理员建分类：「运维手册」「研发规范」「项目文档」，建账号时按角色分配
```

## 最佳实践与踩坑记录

### 最佳实践

1. 浏览量/点赞这类高频写操作先进 Redis，定时批量刷库，别直接 UPDATE MySQL
2. 文章详情缓存必须考虑一致性：更新文章时主动删缓存（先更库再删缓存），而不是等 TTL 过期
3. 缓存穿透要防空值缓存 + 布隆过滤器两道防线（高并发场景布隆过滤器更彻底）
4. 搜索索引与 MySQL 的一致性用「先更库、后同步 ES、失败进 MQ 重试」保证最终一致
5. 列表页永远不要 SELECT 正文 content 字段，MEDIUMTEXT 会拖垮查询
6. 置顶 + 分页的组合：列表查询 ORDER BY is_top DESC, publish_time DESC，置顶文章永远在最前
7. 评论表加 parent_id 支持楼中楼，但前端展示限制两层，避免无限嵌套

### 踩坑记录

```text
坑 1：浏览量计数重复累加
结论：Redis 增量刷库时重复统计。
原因：刷库后没删 Hash 字段，下次 entries() 又取到旧值。
解法：刷库成功立即 hdel 对应 field；用 Lua 脚本保证「读取-删除」原子性。

坑 2：文章更新后搜索还是旧内容
结论：改了标题搜不到新标题。
原因：只更新了 MySQL，没同步 ES 索引。
解法：发布/更新/删除统一走 Service 方法，在方法内同步索引；或监听 binlog 同步。

坑 3：Redis 缓存与数据库不一致
结论：先更库再删缓存，极端情况下短暂读到旧数据。
原因：缓存 TTL 30 分钟，直接依赖过期必然不一致。
解法：更新时主动 del 缓存；对一致性要求高的场景（如金额）不缓存或加版本号。

坑 4：ES 索引里有已删除文章
结论：搜索能搜到已删除的文章。
原因：删除文章时只删了 MySQL。
解法：删除走统一 Service 方法，方法内同步 deleteIndex；孤儿数据用定时任务对账清理。

坑 5：列表查询慢
结论：文章列表接口超时。
原因：列表 SQL 联查了 content 字段，数据量大后 IO 暴涨。
解法：列表查询用 ArticleListVO（不含 content），详情页单独查 content。

坑 6：中文搜索分词效果差
结论：搜「Spring事务」搜不到「Spring 事务」。
原因：ES 默认 standard 分词器不识别中文。
解法：装 IK 分词器，索引 mapping 的 analyzer 指定 ik_max_word，查询用 ik_smart。
```

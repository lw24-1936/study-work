## 项目背景

会员积分与营销系统是电商、银行、航空、餐饮、游戏等几乎所有 To C 业务的标配：通过「消费得积分、签到打卡、做任务赚积分、积分兑换商品」形成用户激励闭环，提升留存与复购。积分本质上是企业的「数字负债」，账必须算得清：每一笔积分从哪来、到哪去、余额对不对、会不会被并发薅羊毛、过期怎么清理。这个项目把「事务一致性、幂等防重、并发扣减、Redis 排行榜、定时任务」串成一个完整业务闭环，是学习「钱相关系统」如何保证正确性的最佳实战载体。

业务痛点：

```text
1. 积分发放靠 Excel 手工登记：漏发、错发、对不上账，运营每天在补账
2. 无流水明细：会员问「我的积分怎么少的」，客服查不到任何记录，信任崩塌
3. 无防重机制：签到、活动奖励可以重复领取，羊毛党批量薅积分
4. 积分永不失效：老积分沉淀成长期负债，财务成本逐年膨胀
5. 余额与流水脱节：入账和扣减不在同一事务，账实不符无从对账
6. 排行榜靠人工统计：运营每周手工拉数算排名，没有实时激励效果
```

目标用户与核心诉求：

```text
1. 会员用户：签到打卡、做任务攒积分，在积分商城兑换实物或优惠券
2. 运营人员：配置积分规则、上架商品、发营销活动，看排行榜做激励
3. 财务/审计：每一笔积分变动可查可追溯，余额与流水严格一致
```

项目要解决的核心问题一句话概括：让积分「给得合规、扣得安全、记得清楚、防得住薅」，并用签到、排行榜、营销活动形成持续的用户激励闭环。

## 功能介绍

功能按角色与模块拆分：会员端（赚积分/花积分）、运营端（规则/商品/活动）、系统端（定时任务/对账）。

```text
一、会员端（用户视角）
1. 签到日历 —— 每日签到领积分，连续签到天数越多奖励越高（如第 N 天 N*10 分）
2. 任务中心 —— 完善资料、每日登录、分享邀请等任务，完成后自动发积分
3. 消费积分 —— 下单消费按比例返积分，订单支付成功后自动入账
4. 积分明细 —— 全部积分流水分页查询：入账/扣减/余额快照，一清二楚
5. 积分商城 —— 商品列表、积分兑换、兑换订单查询与物流状态
6. 积分排行榜 —— 本月/累计积分榜，展示排名与我的名次

二、运营端（运营视角）
1. 积分规则配置 —— 各业务场景积分值、每日上限、启用状态
2. 商品管理 —— 积分商品上架/下架、库存调整、兑换所需积分设置
3. 兑换订单处理 —— 待发货/已发货状态流转，取消订单自动退积分
4. 营销活动 —— 创建限时活动（如「双倍积分日」「新人礼包」），配置奖励与名额
5. 手动调整 —— 人工补发/追扣积分（需审批流），全程留流水
6. 数据看板 —— 积分发放/消耗趋势、签到率、兑换排行

三、系统端（系统能力）
1. 过期清理 —— 定时任务扫描过期积分，自动扣减并记录过期流水
2. 排行榜快照 —— 定时重建 Redis ZSet 排行榜，避免热 key 压力
3. 防重复领取 —— Redis 预检 + 数据库唯一键双保险
4. 对账任务 —— 流水余额与会员余额定期核对，不一致告警
```

## 技术选型

| 组件 | 选型 | 理由 |
|------|------|------|
| 开发框架 | Spring Boot 2.7/3.x | 生态成熟，事务与定时任务开箱即用 |
| 持久层 | MyBatis-Plus | 流水/订单/商品标准 CRUD，复杂统计走 XML |
| 数据库 | MySQL 8.0 | 积分流水与余额落库，事务与唯一索引保证账目正确 |
| 缓存 | Redis | 签到防重（SETNX）、排行榜（ZSet）、热点数据缓存、分布式锁 |
| 定时任务 | Spring Task（生产可换 XXL-Job） | 过期清理、排行榜重建、对账 |
| 分布式锁 | Redis SETNX / Redisson | 定时任务多实例互斥、并发扣减保护 |
| 前端 | Vue 3 + Element Plus | 会员端 H5 页面 + 运营后台 |
| 构建 | Maven | 依赖管理标准工具 |

选型说明：

```text
1. 余额冗余在 member 表 + 流水表双写，且必须在同一事务：保证余额与流水强一致
2. 防重用「Redis 预检 + DB 唯一索引兜底」两层：Redis 挡流量，唯一索引保正确
3. 排行榜用 Redis ZSet：天然支持按分数排序与排名查询，读写都是毫秒级
4. 并发扣减用条件 UPDATE（balance >= points 才更新）：一行 SQL 原子完成校验与扣减，不超扣
5. 定时任务用分布式锁防多实例重复执行：过期清理跑两遍会把积分扣两次
```

请求链路示例（会员签到领积分）：

```text
1. 会员点「签到」，前端 POST /api/sign-in
2. 签到 Service 先用 Redis SETNX 预检：今天已签到直接拒绝（key 24h 过期）
3. 查询昨天签到记录，计算连续签到天数：昨天签过则 +1，否则重新从 1 开始
4. sign_in_record 落库（唯一键 member_id + sign_date 兜底防重）
5. 调用统一入账方法 grantPoints：写流水 + 更新余额，同一事务
6. 流水唯一键 (member_id, biz_type, biz_id) 保证同一天只入账一次
7. 事务提交，返回「连续签到第 N 天，获得 N*10 积分」给前端
8. 签到日历刷新：本月签到记录渲染成日历格子
```

请求链路示例（积分商城兑换商品）：

```text
1. 会员在商城点「立即兑换」，前端 POST /api/exchange
2. 兑换 Service 先 SELECT ... FOR UPDATE 锁住商品行，防止并发超卖
3. 校验商品状态与库存，条件 UPDATE 扣库存，影响行数为 0 说明库存不足
4. 计算所需积分，调用统一扣减方法 deductPoints：条件 UPDATE 余额（不超扣）
5. 生成兑换订单（order_no 全局唯一），状态待发货
6. 以上全部在同一事务：库存、余额、订单要么全成功要么全回滚
7. 会员在订单列表看到新订单，运营后台发货后状态流转为已发货
```

定时任务链路（积分过期清理）：

```text
1. 每天凌晨 3 点触发过期清理任务
2. 先抢分布式锁（SETNX points:expire:lock，10 分钟过期），防止多实例重复执行
3. 查询所有入账超过 365 天且未过期的积分流水，按会员分组求和
4. 对每个会员：条件 UPDATE 扣减余额（只扣到 0），写入 EXPIRED 类型流水
5. 标记旧流水已过期，下次扫描不再重复处理
6. 记录清理日志：本日清理会员数、总积分，供财务核对
```

设计要点：

```text
1. member.points_balance 是冗余字段，与 points_flow 的求和必须一致，靠同一事务保证
2. points_flow 唯一键 (member_id, biz_type, biz_id)：同一业务单号只能入账一次，幂等防重的最终防线
3. sign_in_record 唯一键 (member_id, sign_date)：防止并发签到领双份
4. reward_record 唯一键 (member_id, campaign_id)：防止同一活动重复领取
5. balance_after 快照：对账任务核对「流水余额与 member 余额」是否一致
```

## 核心实现

### 1. 积分入账：流水 + 余额同事务 + 幂等防重

所有积分增加（消费返积分、签到、任务、活动）统一走这一个方法，保证账目口径一致。防重靠两层：先查流水（快速返回），再靠唯一索引兜底（并发时抛 DuplicateKeyException）。

```java
package com.example.points.service;

/**
 * 积分核心服务：入账与扣减的统一入口
 */
@Service
public class PointsService {

    @Autowired
    private PointsFlowMapper flowMapper;
    @Autowired
    private MemberMapper memberMapper;

    /**
     * 积分入账：写流水 + 更新余额，同一事务
     *
     * @param memberId 会员 id
     * @param bizType  业务类型（CONSUME/SIGN_IN/TASK/CAMPAIGN）
     * @param bizId    业务单号（幂等键，如订单号、签到日期）
     * @param points   入账积分数（正数）
     */
    @Transactional
    public PointsFlow grantPoints(Long memberId, String bizType, String bizId,
                                  int points, String remark) {
        // 1. 幂等防重：同一业务单号已入账过则直接返回，不重复发
        PointsFlow exist = flowMapper.selectByMemberBiz(memberId, bizType, bizId);
        if (exist != null) {
            return exist;
        }
        // 2. 写流水（唯一索引兜底：并发重复请求会在这里抛 DuplicateKeyException）
        PointsFlow flow = new PointsFlow();
        flow.setMemberId(memberId);
        flow.setBizType(bizType);
        flow.setBizId(bizId);
        flow.setPoints(points);
        flow.setRemark(remark);
        flowMapper.insert(flow);
        // 3. 更新余额与累计积分（同一事务，要么都成功要么都回滚）
        memberMapper.incrPoints(memberId, points);
        // 4. 回填余额快照，便于对账
        Member member = memberMapper.selectById(memberId);
        flowMapper.updateBalanceAfter(flow.getId(), member.getPointsBalance());
        return flow;
    }
}
```

### 2. 积分扣减：条件 UPDATE 防超扣

并发扣减是「钱相关系统」最经典的坑：两个请求同时扣，各自读到余额 100，各扣 80，结果余额变成 -60。解法是让「校验余额充足」和「扣减」变成一条原子 SQL。

```java
package com.example.points.service;

/**
 * 积分扣减：并发安全，永不超扣
 */
@Service
public class PointsServiceDeduct {

    @Autowired
    private PointsFlowMapper flowMapper;
    @Autowired
    private MemberMapper memberMapper;

    /**
     * 积分扣减：条件 UPDATE 原子完成「校验余额 + 扣减」
     *
     * @param memberId 会员 id
     * @param bizType  业务类型（EXCHANGE/EXPIRE/ADJUST）
     * @param bizId    业务单号（幂等键）
     * @param points   扣减积分数（正数）
     */
    @Transactional
    public PointsFlow deductPoints(Long memberId, String bizType, String bizId,
                                   int points, String remark) {
        // 1. 余额校验 + 扣减一条 SQL 完成：余额不足则影响行数为 0
        int rows = memberMapper.deductPointsIfEnough(memberId, points);
        if (rows == 0) {
            throw new BizException("积分余额不足");
        }
        // 2. 写扣减流水（points 记负数）
        PointsFlow flow = new PointsFlow();
        flow.setMemberId(memberId);
        flow.setBizType(bizType);
        flow.setBizId(bizId);
        flow.setPoints(-points);
        flow.setRemark(remark);
        Member member = memberMapper.selectById(memberId);
        flow.setBalanceAfter(member.getPointsBalance());
        flowMapper.insert(flow);
        return flow;
    }
}
```

对应 Mapper 的原子扣减 SQL（不超扣的关键）：

```sql
-- 只有余额充足才更新成功，行锁保护同一会员的并发扣减
UPDATE member
SET points_balance = points_balance - #{points}
WHERE id = #{memberId} AND points_balance >= #{points}
```

### 3. 签到服务：连续天数计算 + 防重复签到

签到是最高频的积分入口，也是最容易被刷的功能。双层防重：Redis SETNX 快速拦截（流量层），DB 唯一键兜底（正确性层）。

```java
package com.example.points.service;

/**
 * 签到服务：连续签到激励 + 防重复
 */
@Service
public class SignInService {

    @Autowired
    private SignInRecordMapper recordMapper;
    @Autowired
    private PointsService pointsService;
    @Autowired
    private RedisTemplate<String, Object> redisTemplate;

    /**
     * 每日签到
     * 奖励规则：连续第 N 天奖励 N*10 积分，封顶 100
     */
    @Transactional
    public SignInResult signIn(Long memberId) {
        LocalDate today = LocalDate.now();
        // 1. Redis 预检：今天已签到则拒绝（key 当天有效）
        String signKey = "sign:today:" + memberId;
        Boolean first = redisTemplate.opsForValue()
                .setIfAbsent(signKey, "1", 24, TimeUnit.HOURS);
        if (Boolean.FALSE.equals(first)) {
            throw new BizException("今天已经签到过了");
        }
        try {
            // 2. 计算连续天数：昨天签到了则 +1，否则从 1 重新开始
            SignInRecord yesterday = recordMapper.selectByMemberAndDate(
                    memberId, today.minusDays(1));
            int continuous = (yesterday == null) ? 1 : yesterday.getContinuousDays() + 1;
            int reward = Math.min(continuous * 10, 100);
            // 3. 签到记录落库（唯一键 member_id + sign_date 兜底防重）
            SignInRecord record = new SignInRecord();
            record.setMemberId(memberId);
            record.setSignDate(today);
            record.setContinuousDays(continuous);
            record.setPoints(reward);
            recordMapper.insert(record);
            // 4. 统一走积分入账（biz_id = 日期，天然幂等）
            pointsService.grantPoints(memberId, "SIGN_IN",
                    today.toString(), reward, "连续签到第 " + continuous + " 天");
            return new SignInResult(continuous, reward);
        } catch (DuplicateKeyException e) {
            // DB 唯一键兜底命中：说明 Redis 标记丢失，实际已签到
            throw new BizException("今天已经签到过了");
        }
    }

    /**
     * 签到日历：查某月全部签到记录，前端渲染日历
     */
    public List<SignInRecord> monthRecords(Long memberId, String month) {
        return recordMapper.selectByMonth(memberId, month);
    }
}
```

### 4. 积分商城兑换：库存 + 积分双扣一致性

兑换涉及三个数据变更：扣库存、扣积分、生成订单。任何一个失败都不能留半截，必须同一事务。扣库存用「行锁 + 条件更新」防超卖。

```java
package com.example.points.service;

/**
 * 积分商城：兑换商品
 */
@Service
public class ExchangeService {

    @Autowired
    private PointsGoodsMapper goodsMapper;
    @Autowired
    private ExchangeOrderMapper orderMapper;
    @Autowired
    private PointsServiceDeduct pointsService;

    /**
     * 兑换商品：扣库存 + 扣积分 + 生成订单，同一事务
     */
    @Transactional
    public ExchangeOrder exchange(Long memberId, Long goodsId, int quantity) {
        // 1. 行锁锁定商品：SELECT ... FOR UPDATE，串行化同一商品的并发兑换
        PointsGoods goods = goodsMapper.selectByIdForUpdate(goodsId);
        if (goods == null || goods.getStatus() != 1) {
            throw new BizException("商品已下架");
        }
        // 2. 条件更新扣库存：影响行数为 0 说明库存不足
        int rows = goodsMapper.deductStock(goodsId, quantity);
        if (rows == 0) {
            throw new BizException("库存不足");
        }
        // 3. 计算所需积分并扣减（复用统一扣减，不超扣）
        int needPoints = goods.getPointsPrice() * quantity;
        pointsService.deductPoints(memberId, "EXCHANGE",
                "EX_" + System.currentTimeMillis(), needPoints,
                "兑换商品：" + goods.getName() + " x" + quantity);
        // 4. 生成兑换订单
        ExchangeOrder order = new ExchangeOrder();
        order.setOrderNo(generateOrderNo());
        order.setMemberId(memberId);
        order.setGoodsId(goodsId);
        order.setQuantity(quantity);
        order.setPoints(needPoints);
        order.setStatus(0); // 待发货
        orderMapper.insert(order);
        return order;
    }

    /**
     * 订单号：时间戳 + 随机数，全局唯一
     */
    private String generateOrderNo() {
        return "EX" + System.currentTimeMillis()
                + String.format("%04d", ThreadLocalRandom.current().nextInt(10000));
    }
}
```

### 5. 积分排行榜：Redis ZSet

排行榜用 ZSet 实现：member 存会员 id，score 存积分值。ZREVRANGE 取倒序榜单，ZREVRANK 查我的名次，全部 O(logN) 复杂度。定时全量重建，保证与 MySQL 数据一致。

```java
package com.example.points.service;

/**
 * 积分排行榜：Redis ZSet 实现
 */
@Service
public class PointsRankService {

    private static final String RANK_KEY = "points:rank:total";

    @Autowired
    private RedisTemplate<String, Object> redisTemplate;
    @Autowired
    private MemberMapper memberMapper;

    /**
     * 每日凌晨 2 点全量重建排行榜
     * 数据量不大时简单可靠；量大后可改为增量更新 score
     */
    @Scheduled(cron = "0 0 2 * * ?")
    public void rebuildRank() {
        // 1. 从 MySQL 取全部会员的累计积分，写入 ZSet
        List<Member> members = memberMapper.selectAll();
        ZSetOperations<String, Object> zset = redisTemplate.opsForZSet();
        for (Member m : members) {
            zset.add(RANK_KEY, String.valueOf(m.getId()), m.getTotalPoints());
        }
        // 2. 只保留前 1000 名，防止 ZSet 无限膨胀
        zset.removeRange(RANK_KEY, 1000, -1);
    }

    /**
     * 取榜单前 N 名：ZREVRANGE 按分数倒序
     */
    public List<RankItemVO> topN(int n) {
        Set<Object> members = redisTemplate.opsForZSet()
                .reverseRange(RANK_KEY, 0, n - 1);
        if (members == null) {
            return List.of();
        }
        List<RankItemVO> result = new ArrayList<>();
        int rank = 1;
        for (Object memberId : members) {
            Double score = redisTemplate.opsForZSet().score(RANK_KEY, memberId);
            result.add(new RankItemVO(Long.valueOf(memberId.toString()),
                    score == null ? 0 : score.longValue(), rank++));
        }
        return result;
    }

    /**
     * 我的排名：ZREVRANK 返回从 0 开始的下标，+1 即名次
     */
    public long myRank(Long memberId) {
        Long rank = redisTemplate.opsForZSet()
                .reverseRank(RANK_KEY, String.valueOf(memberId));
        return rank == null ? -1 : rank + 1; // -1 表示未上榜
    }
}
```

### 6. 过期清理定时任务

积分过期是财务刚需：入账满 365 天未使用的积分自动作废。关键点：多实例部署时只能有一个实例执行（分布式锁），且扣减必须走「不超扣」逻辑。

```java
package com.example.points.task;

/**
 * 积分过期清理：入账满 365 天未使用的积分作废
 */
@Component
public class PointsExpireTask {

    @Autowired
    private PointsFlowMapper flowMapper;
    @Autowired
    private MemberMapper memberMapper;
    @Autowired
    private RedisTemplate<String, Object> redisTemplate;

    /**
     * 每天凌晨 3:30 执行，分布式锁防多实例重复执行
     */
    @Scheduled(cron = "0 30 3 * * ?")
    public void expirePoints() {
        String lockKey = "points:expire:lock";
        Boolean locked = redisTemplate.opsForValue()
                .setIfAbsent(lockKey, "1", 10, TimeUnit.MINUTES);
        if (Boolean.FALSE.equals(locked)) {
            // 其他实例正在执行，本实例直接跳过
            return;
        }
        try {
            // 1. 查出每个会员的过期未用积分（按入账时间超过 365 天且未标记过期的流水求和）
            List<MemberExpireVO> list = flowMapper.selectExpiredUnusedPoints();
            for (MemberExpireVO vo : list) {
                expireOneMember(vo);
            }
        } finally {
            redisTemplate.delete(lockKey);
        }
    }

    /**
     * 单个会员的过期处理：扣余额 + 记过期流水 + 标记旧流水
     */
    @Transactional
    public void expireOneMember(MemberExpireVO vo) {
        if (vo.getExpirePoints() <= 0) {
            return;
        }
        // 1. 条件 UPDATE 扣减：只扣到 0，绝不超扣
        int rows = memberMapper.deductPointsIfEnough(vo.getMemberId(), vo.getExpirePoints());
        if (rows == 0) {
            return; // 余额不足（期间被消费），跳过
        }
        // 2. 写过期流水（负数，余额快照）
        Member member = memberMapper.selectById(vo.getMemberId());
        PointsFlow flow = new PointsFlow();
        flow.setMemberId(vo.getMemberId());
        flow.setBizType("EXPIRE");
        flow.setBizId("EXPIRE_" + vo.getMemberId() + "_" + LocalDate.now());
        flow.setPoints(-vo.getExpirePoints());
        flow.setBalanceAfter(member.getPointsBalance());
        flow.setRemark("积分过期清理");
        flowMapper.insert(flow);
        // 3. 标记旧流水已过期，下次扫描不再重复处理
        flowMapper.markExpired(vo.getMemberId());
    }
}
```

### 7. 营销活动防重复领取

营销活动的核心风险是羊毛党批量刷：同一个人重复领取、并发请求抢同一个名额。解法同样是「Redis 预检 + DB 唯一键兜底」双层防线，外加名额条件扣减。

```java
package com.example.points.service;

/**
 * 营销活动：限时任务领取奖励，防重复领取
 */
@Service
public class RewardService {

    @Autowired
    private CampaignMapper campaignMapper;
    @Autowired
    private RewardRecordMapper recordMapper;
    @Autowired
    private PointsService pointsService;
    @Autowired
    private RedisTemplate<String, Object> redisTemplate;

    /**
     * 领取活动奖励：Redis 预检 + DB 唯一键兜底 + 名额条件扣减
     */
    @Transactional
    public void claimReward(Long memberId, Long campaignId) {
        // 1. Redis 预检：同一会员同一活动只能领一次（key 保留 7 天覆盖活动周期）
        String claimKey = "campaign:claim:" + campaignId + ":" + memberId;
        Boolean first = redisTemplate.opsForValue()
                .setIfAbsent(claimKey, "1", 7, TimeUnit.DAYS);
        if (Boolean.FALSE.equals(first)) {
            throw new BizException("你已领取过该活动奖励");
        }
        try {
            // 2. 校验活动状态：未开始/已结束都拒绝
            Campaign campaign = campaignMapper.selectById(campaignId);
            if (campaign == null || campaign.getEndTime().before(new Date())) {
                throw new BizException("活动已结束");
            }
            // 3. 名额扣减：条件更新防超领（剩余名额不足则影响行数为 0）
            int rows = campaignMapper.decrRemain(campaignId);
            if (rows == 0) {
                throw new BizException("手慢了，名额已抢完");
            }
            // 4. 领取记录落库（唯一键 member_id + campaign_id 兜底防重）
            RewardRecord record = new RewardRecord();
            record.setMemberId(memberId);
            record.setCampaignId(campaignId);
            record.setRewardPoints(campaign.getRewardPoints());
            recordMapper.insert(record);
            // 5. 发放积分（统一入账，biz_id = campaignId，幂等）
            pointsService.grantPoints(memberId, "CAMPAIGN",
                    String.valueOf(campaignId), campaign.getRewardPoints(),
                    "活动奖励：" + campaign.getName());
        } catch (DuplicateKeyException e) {
            // DB 唯一键兜底命中：Redis 标记可能因异常丢失
            throw new BizException("你已领取过该活动奖励");
        } catch (Exception e) {
            // 事务回滚时清理 Redis 预检标记，允许用户重试
            redisTemplate.delete(claimKey);
            throw e;
        }
    }
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. 所有积分变动统一走 grantPoints/deductPoints 两个入口：口径统一，审计方便，杜绝各处散写 UPDATE
2. 流水与余额必须同一事务：先写流水再更新余额（或先扣余额再写流水），任何一步失败整体回滚
3. 幂等防重三层：业务前置判断（查流水）-> Redis 预检（挡流量）-> DB 唯一索引（保正确），缺一不可
4. 并发扣减用条件 UPDATE（WHERE balance >= points）：一行 SQL 原子完成校验 + 扣减，绝不超扣
5. 定时任务加分布式锁：过期清理、排行榜重建等任务多实例部署时只能执行一次
6. 排行榜用 ZSet + 定时快照重建：实时读 Redis，定期从 MySQL 全量重建保证一致
7. 余额是「可读快照」，对账任务定期用流水重算余额校验冗余字段，账实不符立即告警

### 踩坑记录

```text
坑 1：并发签到领双份积分
结论：同一会员同一毫秒发两个签到请求，积分入账两次。
原因：先查再插的「检查-插入」模式有竞态窗口，两个请求都查到未签到。
解法：sign_in_record 加唯一键 (member_id, sign_date)，重复插入抛 DuplicateKeyException；外层 Redis SETNX 先拦流量。

坑 2：并发扣减超扣
结论：两个兑换请求同时扣同一会员积分，余额被扣成负数。
原因：先 SELECT 余额再 UPDATE 扣减，两个请求读到相同余额，都通过校验。
解法：改为单条条件 UPDATE（balance >= points 才更新），校验与扣减原子完成；影响行数为 0 即余额不足。

坑 3：兑换时库存扣了积分没扣
结论：扣库存成功但扣积分失败，订单也没生成，库存神秘消失。
原因：扣库存与扣积分在两个事务里，或者扣库存方法没有标注事务注解。
解法：兑换流程统一 @Transactional，库存扣减、积分扣减、订单生成在同一事务；注意自调用不走代理，事务注解要写在被 Spring 直接调用的方法上。

坑 4：余额与流水对不上
结论：member.points_balance 与流水求和差了一大截。
原因：历史版本里余额更新和流水写入不在同一事务；或并发入账时余额回填快照错位。
解法：入账/扣减统一走同一事务的两个写操作；加对账定时任务：按会员重算流水求和与余额比对，不一致告警并自动修正。

坑 5：定时任务重复执行扣两次积分
结论：过期清理任务跑完后积分被扣了两遍。
原因：多实例部署后每个实例都执行了 @Scheduled 任务。
解法：任务内先抢 Redis 分布式锁（SETNX + 过期时间），抢不到直接跳过；同时用「标记已过期」字段保证同一批流水只处理一次。

坑 6：ZSet 排行榜成员重复与精度问题
结论：榜单出现重复会员或分数不准。
原因：member 用昵称导致同名合并；score 用 double 累加大数丢失精度。
解法：ZSet 的 member 一律用 member_id（唯一标识），score 用 long 积分值转 double（千万级以内无精度问题）；重建时全量覆盖而非增量累加。
```

## 项目背景

在线考试系统解决的是线下考试全流程的组织成本问题：出题、印刷、运输、考场安排、监考、阅卷、成绩统计，每个环节都要人力物力，且考试周期被拉得很长。教育机构、企业培训、职业认证、政府技能鉴定这几类场景对「随时考、异地考、自动判分」的需求非常刚性，在线考试系统因此成为综合项目实战里的经典题目。它麻雀虽小五脏俱全：题库管理是典型 CRUD，随机组卷涉及复杂查询与算法，在线答题涉及会话与限时，自动判分涉及规则引擎式的比对逻辑，防作弊又牵扯 Redis 计数与前端埋点——一条链路把 Spring Boot + MySQL + Redis 的主流玩法全走了一遍。

业务痛点：

```text
1. 纸质试卷印刷、运输、保管成本高，泄题风险大，一场考试从出题到考完要两周
2. 人工阅卷效率低，百人规模的选择题试卷要判一整天，且判分标准不统一
3. 考场安排受场地限制，异地考生、在职学员无法参加统一时间的线下考试
4. 考生作弊手段多（传纸条、抄邻座），监考人力覆盖不过来
5. 试卷难度不可控：组卷全凭老师经验，每次考试难度波动大，成绩可比性差
6. 成绩统计靠手工 Excel，及格率、分数段、知识点正确率等分析做不出来
```

目标用户与核心诉求：

```text
1. 考生：随时随地上网考试，交卷即出分（客观题），成绩可查可下载
2. 教师：题库沉淀复用、一键随机组卷、客观题自动判分、成绩与正确率分析
3. 管理员/教务：考试场次管理、考生名单导入、防作弊监控、考试数据导出
4. 机构决策层：跨场次对比各知识点掌握情况，指导教学调整
```

项目要解决的核心问题一句话概括：把「出题-组卷-考试-判分-统计」整条链路搬到线上，用 Redis 扛住考试高峰并发，用规则与定时任务替代人工监考和阅卷。

## 功能介绍

功能按角色拆成三个端：考生端（答题）、教师端（出题组卷阅卷）、管理端（考试与防作弊管控）。

```text
一、考生端
1. 考试列表 —— 查看已报名的考试场次、考试时间、时长、总分
2. 进入考试 —— 校验考试时间窗口，创建答题会话，随机题序后开始倒计时
3. 在线答题 —— 单选/多选/判断/简答，逐题作答，题号导航可标记存疑题
4. 切屏检测 —— 浏览器失焦/切换标签页自动上报，超阈值强制交卷
5. 交卷与成绩 —— 手动交卷/超时自动交卷，客观题即时出分，主观题阅卷后出总分

二、教师端
1. 题库管理 —— 题目 CRUD，按题型（单选/多选/判断/简答）、难度（1-5 级）、知识点分类
2. 手动组卷 —— 从题库勾选题目，逐题设置分值
3. 随机组卷 —— 按「题型+难度+知识点+题数+每题分值」规则自动抽题，可多次重新生成
4. 考试发布 —— 设置考试时间窗口、时长、总分、及格分、防作弊开关（切屏阈值）
5. 主观题阅卷 —— 简答题逐份批改打分，给出评语
6. 成绩分析 —— 分数段分布、平均分、及格率、每题正确率、知识点掌握度

三、管理端
1. 用户管理 —— 教师/考生账号、班级/机构组织架构
2. 考试管理 —— 场次创建、考生名单导入（批量）、考试启停
3. 防作弊监控 —— 实时查看各考生切屏次数，异常考生强制交卷/成绩作废
4. 数据统计 —— 跨场次汇总、导出 Excel 成绩单
```

## 技术选型

| 组件 | 选型 | 理由 |
|------|------|------|
| 开发框架 | Spring Boot 2.7/3.x | 生态成熟，起步快，定时任务 @Scheduled 开箱即用 |
| 持久层 | MyBatis-Plus | 题库/考试/成绩单表 CRUD 零 SQL，随机抽题走自定义 SQL |
| 数据库 | MySQL 8.0 | 题目、试卷、考试记录落库，支持事务（交卷-判分原子性） |
| 缓存 | Redis | 题目缓存（读多写少）、答题会话（限时倒计时）、切屏计数、防重提交 |
| 定时任务 | Spring @Scheduled | 考试开放提醒、超时强制交卷兜底；量大可换 XXL-Job |
| 前端 | Vue 3 + Element Plus | 后台管理 + 答题页，前后端分离 |
| 鉴权 | Spring Security + JWT | 考生/教师/管理员三角色，无状态认证 |
| 构建 | Maven | 依赖管理标准工具 |

选型说明：

```text
1. MyBatis-Plus 而非纯 MyBatis：题库、考试、记录都是标准单表 CRUD，BaseMapper 直接省掉样板代码；随机抽题这种复杂 SQL 走自定义方法
2. Redis 承担四件事：题目缓存（避免考试高峰打爆数据库）、答题会话（剩余时间秒级倒计时）、切屏计数（高频 INCR）、防重复交卷（setIfAbsent）
3. 判分逻辑不依赖数据库存储过程：客观题判分在 Java 层做规则比对，规则可扩展（如多选漏选给半分）
4. 定时任务做兜底而非主路径：前端倒计时可能被绕过，服务端定时扫描强制交卷才是最终保障
```

请求链路示例（考生进入考试并开始答题）：

```text
1. 前端 GET /api/exam/{examId}/start，JWT 过滤器校验考生身份
2. Service 校验考试时间窗口：未开始/已结束直接拒绝
3. 幂等处理：查 exam_record 是否有进行中的记录，有则直接续考（防重复开考）
4. 无记录则新建考试记录（状态=考试中），把该试卷题目 id 列表洗牌后写入 Redis 会话
5. 考生逐题作答：POST /api/exam/answer 写 exam_answer 明细（Redis 会话校验未超时）
6. 交卷：状态置为已交卷，判分服务遍历答题明细，客观题自动判分、主观题标记待阅卷
7. 定时任务兜底：每分钟扫描考试中且超过结束时间的记录，强制交卷并判分
```

## 核心实现

### 1. 题库管理：题目 CRUD + Redis 缓存（防穿透）

```java
@Service
public class QuestionService {

    private static final String QUESTION_KEY = "exam:question:";

    @Autowired
    private QuestionMapper questionMapper;
    @Autowired
    private RedisTemplate<String, Object> redisTemplate;

    /**
     * 题目详情：缓存优先，防缓存穿透
     * 考试高峰期上千考生并发读同一批题目，命中缓存可把数据库压力降一个数量级
     */
    public QuestionVO getQuestion(Long id) {
        String key = QUESTION_KEY + id;
        Object cached = redisTemplate.opsForValue().get(key);
        if (cached != null) {
            // 空值占位：缓存穿透防护
            if ("EMPTY".equals(cached)) {
                return null;
            }
            return (QuestionVO) cached;
        }
        QuestionVO vo = questionMapper.selectQuestionVO(id);
        if (vo == null) {
            // 查不到的 id 写空值缓存 60 秒，防止恶意遍历打库
            redisTemplate.opsForValue().set(key, "EMPTY", 60, TimeUnit.SECONDS);
            return null;
        }
        // TTL 对齐考试周期：考试进行中题目不可修改，12 小时后缓存自然失效
        redisTemplate.opsForValue().set(key, vo, 12, TimeUnit.HOURS);
        return vo;
    }

    /**
     * 新增/修改题目：写库后主动删缓存，保证下次读取拿到新数据
     */
    public void saveQuestion(Question question) {
        if (question.getId() == null) {
            questionMapper.insert(question);
        } else {
            questionMapper.updateById(question);
            redisTemplate.delete(QUESTION_KEY + question.getId());
        }
    }
}
```

### 2. 随机组卷：按题型+难度+知识点抽题

```java
@Service
public class ExamPaperService {

    @Autowired
    private QuestionMapper questionMapper;
    @Autowired
    private ExamQuestionMapper examQuestionMapper;
    @Autowired
    private ExamMapper examMapper;

    /**
     * 随机组卷：按规则逐条抽题并生成试卷快照
     * rules 示例：[{"type":1,"difficulty":2,"knowledgePoint":"Redis","count":10,"score":3}]
     */
    public void buildPaper(Long examId, List<PaperRule> rules) {
        // 1. 先清旧试卷，保证重复组卷幂等
        examQuestionMapper.deleteByExamId(examId);
        // 2. 逐规则抽题
        int seq = 1;
        int totalScore = 0;
        for (PaperRule rule : rules) {
            List<Question> questions = questionMapper.randomSelect(
                    rule.getType(), rule.getDifficulty(),
                    rule.getKnowledgePoint(), rule.getCount());
            if (questions.size() < rule.getCount()) {
                throw new BizException("题库数量不足：题型" + rule.getType()
                        + " 难度" + rule.getDifficulty() + " 仅剩 " + questions.size() + " 题");
            }
            for (Question q : questions) {
                ExamQuestion eq = new ExamQuestion();
                eq.setExamId(examId);
                eq.setQuestionId(q.getId());
                eq.setSeq(seq++);
                eq.setScore(rule.getScore());
                eq.setShuffleFlag(rule.getShuffle() ? 1 : 0);
                examQuestionMapper.insert(eq);
                totalScore += rule.getScore();
            }
        }
        // 3. 回写总分与及格分校验
        examMapper.updateTotalScore(examId, totalScore);
    }
}
```

```xml
<!-- QuestionMapper.xml：随机抽题，ORDER BY RAND() 只适合中小题库，题量大时换随机主键区间 -->
<select id="randomSelect" resultType="Question">
    SELECT * FROM question
    WHERE type = #{type}
      AND difficulty = #{difficulty}
      AND status = 1
      <if test="knowledgePoint != null and knowledgePoint != ''">
          AND knowledge_point = #{knowledgePoint}
      </if>
    ORDER BY RAND()
    LIMIT #{count}
</select>
```

### 3. 开始考试：答题会话 + 随机题序 + 限时

```java
@Service
public class ExamSessionService {

    private static final String SESSION_KEY = "exam:session:";
    private static final String REMAIN_KEY = "exam:remain:";

    @Autowired
    private ExamRecordMapper examRecordMapper;
    @Autowired
    private ExamQuestionMapper examQuestionMapper;
    @Autowired
    private ExamMapper examMapper;
    @Autowired
    private RedisTemplate<String, Object> redisTemplate;

    /**
     * 开始考试：创建考试记录 + 生成限时会话 + 随机题序
     * 同考生重复进入直接续考，保证断网重连不丢进度
     */
    public ExamStartVO start(Long examId, Long studentId) {
        Exam exam = examMapper.selectById(examId);
        // 1. 时间窗口校验：未开始或已结束都不允许进入
        Date now = new Date();
        if (now.before(exam.getStartTime()) || now.after(exam.getEndTime())) {
            throw new BizException("不在考试时间窗口内");
        }
        // 2. 幂等：已有进行中的记录直接续考
        ExamRecord exist = examRecordMapper.selectActive(examId, studentId);
        if (exist != null) {
            return buildStartVO(exist);
        }
        // 3. 创建考试记录，状态=考试中
        ExamRecord record = new ExamRecord();
        record.setExamId(examId);
        record.setStudentId(studentId);
        record.setStatus(1);
        record.setStartTime(now);
        examRecordMapper.insert(record);

        // 4. 随机题序：试卷快照的 seq 是出题顺序，此处按考生洗牌
        //    只洗 shuffle_flag=1 的题，问答题等固定顺序的题保持原序
        List<Long> questionIds = examQuestionMapper.selectShuffleIds(examId);
        Collections.shuffle(questionIds);

        // 5. 会话入 Redis：题目顺序 + 剩余秒数，TTL 即考试时长
        long seconds = exam.getDuration() * 60L;
        String sessionKey = SESSION_KEY + record.getId();
        redisTemplate.opsForValue().set(sessionKey, questionIds, seconds, TimeUnit.SECONDS);
        redisTemplate.opsForValue().set(REMAIN_KEY + record.getId(),
                seconds, seconds, TimeUnit.SECONDS);

        return buildStartVO(record);
    }

    /**
     * 剩余时间：前端每秒拉一次（或首次进入拉一次后本地倒计时）
     * 以 Redis TTL 为准，防止前端改本地时间作弊
     */
    public long remainSeconds(Long recordId) {
        Long remain = redisTemplate.getExpire(REMAIN_KEY + recordId, TimeUnit.SECONDS);
        return remain == null ? 0 : remain;
    }
}
```

### 4. 防作弊：切屏检测

```java
@Service
public class AntiCheatService {

    private static final String BLUR_KEY = "exam:blur:";

    @Autowired
    private RedisTemplate<String, Object> redisTemplate;
    @Autowired
    private ExamRecordMapper examRecordMapper;
    @Autowired
    private ExamMapper examMapper;

    /**
     * 切屏上报：浏览器失焦/切换标签页时前端调此接口
     * Redis INCR 计数，达到阈值标记异常并强制交卷
     */
    public int reportBlur(Long recordId, Long studentId) {
        ExamRecord record = examRecordMapper.selectById(recordId);
        Exam exam = examMapper.selectById(record.getExamId());
        if (exam.getAntiCheat() == 0) {
            return -1; // 该考试未开启防作弊
        }
        String key = BLUR_KEY + recordId;
        Long count = redisTemplate.opsForValue().increment(key);
        // 首次切屏设置 TTL，保证计数随考试周期重置
        if (count != null && count == 1) {
            redisTemplate.expire(key, exam.getDuration() * 60L, TimeUnit.SECONDS);
        }
        if (count != null && count >= exam.getMaxBlurCount()) {
            // 超过阈值：状态置为 3（异常强制交卷），成绩按已答部分计算
            examRecordMapper.forceSubmit(recordId, studentId, 3, count.intValue());
            redisTemplate.delete("exam:session:" + recordId);
        }
        // 返回剩余可切屏次数，前端做警告提示
        return exam.getMaxBlurCount() - count.intValue();
    }
}
```

### 5. 自动判分：客观题规则比对 + 主观题待人工

```java
@Service
public class GradingService {

    @Autowired
    private ExamAnswerMapper examAnswerMapper;
    @Autowired
    private QuestionMapper questionMapper;
    @Autowired
    private ExamRecordMapper examRecordMapper;

    /**
     * 判分入口：交卷时调用（手动交卷与定时强制交卷都走这里）
     * 客观题（单选/多选/判断）自动比对，简答题标记待人工阅卷
     */
    public void grade(Long recordId) {
        List<ExamAnswer> answers = examAnswerMapper.selectByRecordId(recordId);
        int objectiveScore = 0;
        int pendingCount = 0;
        for (ExamAnswer answer : answers) {
            if (answer.getQuestionType() == 4) {
                // 简答题：标记待人工阅卷，不参与自动判分
                answer.setStatus(2);
                pendingCount++;
            } else {
                Question q = questionMapper.selectById(answer.getQuestionId());
                boolean correct = checkAnswer(q, answer.getAnswer());
                answer.setStatus(correct ? 3 : 4);
                if (correct) {
                    answer.setScore(q.getScore());
                    objectiveScore += q.getScore();
                }
            }
            examAnswerMapper.updateById(answer);
        }
        // 回写记录：客观题得分先落库，主观题阅卷完成后累加总分
        examRecordMapper.updateObjectiveScore(recordId, objectiveScore, pendingCount);
    }

    /**
     * 答案比对：单选/判断精确匹配；多选要求与标准答案集合完全一致
     * 扩展点：多选漏选可改为给半分，规则收敛在此方法内
     */
    private boolean checkAnswer(Question q, String studentAnswer) {
        if (studentAnswer == null || studentAnswer.isBlank()) {
            return false; // 未作答算错
        }
        String standard = q.getAnswer().replace(" ", "");
        String mine = studentAnswer.replace(" ", "");
        if (q.getType() == 2) {
            // 多选题：按集合比较，顺序无关
            Set<String> std = new HashSet<>(Arrays.asList(standard.split(",")));
            Set<String> ans = new HashSet<>(Arrays.asList(mine.split(",")));
            return std.equals(ans);
        }
        return standard.equalsIgnoreCase(mine);
    }
}
```

### 6. 定时任务：超时强制交卷 + 考试开放提醒

```java
@Component
public class ExamTask {

    @Autowired
    private ExamRecordMapper examRecordMapper;
    @Autowired
    private GradingService gradingService;
    @Autowired
    private RedisTemplate<String, Object> redisTemplate;

    /**
     * 每分钟扫描：考试中但已超过考试结束时间的记录，强制交卷并判分
     * 兜底场景：考生断网、前端倒计时被绕过（改本地时间）、页面被关闭
     */
    @Scheduled(cron = "0 * * * * ?")
    public void forceSubmitExpired() {
        // 查出所有 status=1（考试中）且已过 end_time 的考试记录
        List<ExamRecord> expired = examRecordMapper.selectExpired(new Date());
        for (ExamRecord record : expired) {
            // 分布式环境下加锁，防止多实例重复处理同一记录
            String lockKey = "exam:submit:lock:" + record.getId();
            Boolean locked = redisTemplate.opsForValue()
                    .setIfAbsent(lockKey, "1", 30, TimeUnit.SECONDS);
            if (!Boolean.TRUE.equals(locked)) {
                continue; // 其他实例正在处理
            }
            try {
                // 二次校验：状态可能刚被手动交卷流程改掉
                ExamRecord latest = examRecordMapper.selectById(record.getId());
                if (latest.getStatus() != 1) {
                    continue;
                }
                latest.setStatus(2);
                latest.setSubmitTime(new Date());
                examRecordMapper.updateById(latest);
                // 判分 + 清理会话
                gradingService.grade(latest.getId());
                redisTemplate.delete("exam:session:" + latest.getId());
                redisTemplate.delete("exam:remain:" + latest.getId());
            } finally {
                redisTemplate.delete(lockKey);
            }
        }
    }

    /**
     * 每 30 分钟扫描：未来 30 分钟内开考的考试，给已报名考生发提醒
     * 生产环境改造：发 MQ 消息由通知服务推送站内信/短信
     */
    @Scheduled(cron = "0 0/30 * * * ?")
    public void remindUpcoming() {
        Date start = new Date();
        Date end = new Date(System.currentTimeMillis() + 30 * 60 * 1000L);
        List<Exam> upcoming = examMapper.selectByStartRange(start, end);
        for (Exam exam : upcoming) {
            List<Long> studentIds = examRecordMapper.selectStudentIds(exam.getId());
            // 此处省略：逐考生发送提醒（站内信/短信），发送失败记录日志不阻塞
        }
    }
}
```

## 实际应用场景

### 场景一：高校期末线上考试

某高校公共课（如大学英语）2000 名考生线上期末考，机房容量不足、跨校区考生多，改用本系统：

```text
1. 教务处建考试：时长 90 分钟，总分 100，及格 60，开启防作弊（切屏阈值 3 次）
2. 教师导入题库：客观题 300 道 + 简答 20 道，按「单选 30 题 ×2 分 + 多选 10 题 ×2 分 + 判断 10 题 ×1 分 + 简答 2 题 ×10 分」随机组卷
3. 考试当天 2000 人同时进入：题目命中 Redis 缓存，数据库零压力；每题答案写入明细表
4. 有考生切屏 4 次：AntiCheatService 标记异常强制交卷，成绩按已答部分计算并留痕
5. 考试结束：定时任务兜底扫描，断网考生被强制交卷，客观题自动判分完成
6. 教师登录后台批改 4000 份简答题，批完即出总分
7. 教务导出成绩 Excel，按班级/分数段统计及格率，挂科名单一键生成
```

### 场景二：企业入职与晋升在线测评

某互联网公司对候选人做技术能力测评、对在职员工做晋升考试，题目要求保密、防作弊要求高：

```text
1. HR 建测评场次，导入候选人名单（手机号+邮箱），系统发考试通知
2. 题库按「Java 基础/Redis/MySQL/架构」知识点分区，每场按岗位随机抽题，两次考试题目不重复

4. 客观题即时出分，简答题由技术负责人分组批改，评语随成绩一起回传候选人
5. 晋升考试的成绩存档，关联人才盘点数据，作为晋升依据
```


## 最佳实践与踩坑记录

### 最佳实践

1. 判分入口收敛成唯一方法：手动交卷、超时强制交卷、异常强制交卷都调 gradingService.grade()，判分规则只维护一处
2. 考试会话全部放 Redis 并设置 TTL：题目顺序、剩余时间、切屏计数都有自然过期时间，考试结束自动清理，不留垃圾数据
3. 定时任务做「扫描 + 加锁 + 二次校验」三件套：先查出候选，setIfAbsent 加锁防多实例重复处理，处理前再查一次最新状态防竞态
4. 试卷用快照表（exam_question）而非实时关联题库：考试开始后题目修改不影响进行中的考试，成绩可追溯
5. 客观题判分在 Java 层做，规则可扩展；多选「漏选给半分」这类策略调整只改 checkAnswer 一处
6. 答题明细冗余 question_type 字段：判分时避免批量回查题目表，考试高峰能省一次大查询
7. 前端倒计时只做展示，服务端 Redis TTL 才是权威；前端本地时间可被修改，一切限时判断以服务端为准

### 踩坑记录

```text
坑 1：考生断网重连后进度丢失
结论：重进考试从第一题开始，已答答案全丢。
原因：只在前端内存里保存答题状态，没落库也没建会话。
解法：每答一题立即写 exam_answer 明细；开始考试接口做幂等，有进行中记录直接续考。

坑 2：切屏计数被绕过
结论：考生在无痕窗口/多标签页间切换，blur 事件不触发。
原因：浏览器 blur 事件只在窗口失焦时触发，标签页内跳转不触发。
解法：前端同时上报 visibilitychange 与 blur；后端结合答题间隔（相邻两题作答时间 < 2 秒视为异常）做辅助判定。

坑 3：考试高峰数据库被打爆
结论：2000 人同时开考，题目接口全部打到 MySQL，连接池耗尽。
原因：题目没做缓存，每次进入考试都按题查询。
解法：题目详情加 Redis 缓存 + 空值防穿透；试卷题目一次性查询组装后整体进会话缓存。

坑 4：ORDER BY RAND() 组卷越来越慢
结论：题库到 5 万题后组卷接口耗时 3 秒以上。
原因：ORDER BY RAND() 对全表排序，数据量线性增长。
解法：小题库（万级以内）可接受；大题库改为「随机主键区间 + 偏移取数」或按 id 取模分片抽样。

坑 5：多实例部署后强制交卷重复执行
结论：同一个考生被强制交卷两次，简答题被判两次分。
原因：定时任务在多实例上同时跑，没有互斥。
解法：每单 setIfAbsent 加锁；处理前二次校验状态；判分改为幂等（已判分的题跳过）。

坑 6：考试结束瞬间交卷失败
结论：23:59:50 交卷报「考试已结束」，考生成绩丢失。
原因：前端倒计时与服务端时间有偏差，临界点交卷请求被时间窗口校验拒绝。
解法：交卷接口放宽 30 秒缓冲（end_time + 30s 内允许交卷）；判分以 record 的 submit_time 为准，而不是请求到达时间。
```

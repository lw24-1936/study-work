## 项目背景

电商后台管理系统是电商业务最核心的中枢系统：前台负责卖，后台负责管。商品怎么上架、库存怎么进出、订单怎么流转、促销怎么设置、会员怎么运营、数据怎么看，全部由后台系统承载。选择它作为综合实战项目，是因为电商后台几乎覆盖了 Java 后端最常见的全部技术点：复杂商品模型建模、库存与订单的事务联动、缓存与锁的使用、定时统计与报表，是把「Spring Boot + MyBatis-Plus + MySQL + Redis」这条技术线打穿的最佳练兵场。

业务痛点：

```text
1. 商品规格混乱：一个商品多个颜色尺码，用「一行一个商品」的扁平表根本撑不住
2. 库存对不上：前台显示有货，下单后仓库说没货，超卖问题频发
3. 分类层级浅：分类只能一级，无法支撑「服装 > 男装 > T恤 > 圆领」这种多级树
4. 订单靠手工：发货、售后全靠人工登记，状态混乱，找不到单
5. 促销全靠改价：优惠券、满减靠运营手动改价格，风控与结算一塌糊涂
6. 数据靠导出：销售统计靠运营导出 Excel 手工算，实时性差、口径不统一
7. 会员无沉淀：用户买了什么、偏好是什么完全没记录，复购无从下手
```

目标用户与核心诉求：

```text
1. 运营人员：商品上下架、设置促销、查看销售数据，操作要简单直观
2. 仓储人员：入库、出库、盘点要快，库存预警要提前提醒
3. 客服人员：订单查询、发货操作、售后处理要在一个界面完成
4. 管理层：实时看销售额、订单量、库存健康度，辅助经营决策
5. 财务人员：核对订单金额、退款金额，促销成本要算得清
```

项目要解决的核心问题一句话概括：用 SPU/SKU 模型管住商品与库存，用事务和锁保证库存与订单联动不错乱，用统一后台让运营、仓储、客服各司其职、数据可视。

## 功能介绍

功能按业务模块拆分，共六大模块：商品管理、库存管理、订单管理、会员管理、促销管理、数据统计。

```text
一、商品管理
1. 分类管理 —— 多级分类树（无限层级），分类的增删改查、排序、上下架控制
2. SPU 管理 —— 商品基础信息（名称、品牌、主图、详情、属性列表）
3. SKU 管理 —— 规格组合（颜色/尺码等），每个 SKU 独立价格、库存、编码
4. 商品上下架 —— 上架/下架/售罄状态流转，上下架实时同步前台
5. 商品审核 —— 可选流程：运营提交、管理员审核后上架

二、库存管理
1. 入库管理 —— 采购入库/退货入库，生成入库单与库存流水
2. 出库管理 —— 销售出库/调拨出库，与订单发货联动
3. 库存查询 —— 按 SPU/SKU/仓库查询可用库存、锁定库存
4. 库存预警 —— 低于预警阈值自动提醒，生成预警清单
5. 盘点管理 —— 盘点单录入，盘盈盘亏自动生成调整流水

三、订单管理
1. 订单列表 —— 多条件查询（订单号/会员/状态/时间区间），支持导出
2. 订单详情 —— 商品明细、收货信息、支付信息、操作日志时间线
3. 发货管理 —— 填写物流公司/运单号，发货后状态流转
4. 售后管理 —— 退款/退货申请审核，退款原路退回
5. 订单取消 —— 未支付订单超时自动取消，取消后释放库存

四、会员管理
1. 会员档案 —— 注册信息、等级、积分、消费累计
2. 会员等级 —— 普通/银卡/金卡，按消费金额自动升级
3. 积分管理 —— 消费得积分、积分抵现，规则可配置
4. 会员营销 —— 按人群发优惠券（新客/沉睡/高价值）

五、促销管理
1. 优惠券 —— 满减券/折扣券/无门槛券，限量领取，可叠加规则控制
2. 满减活动 —— 满 X 减 Y，按全场/分类/商品维度设置
3. 秒杀活动 —— 限时限量低价，独立库存池（可选扩展）
4. 促销日历 —— 活动排期，生效时间精确到秒

六、数据统计
1. 销售总览 —— 今日/昨日/近 7 日销售额、订单量、客单价
2. 商品排行 —— 按销量/销售额排行的 Top 榜
3. 库存健康度 —— 库存周转、预警 SKU 数、滞销商品清单
4. 会员分析 —— 新增会员数、复购率、消费分布
5. 报表导出 —— 销售日报/月报导出 Excel（对接 EasyExcel）
```

## 技术选型

| 组件 | 选型 | 理由 |
|------|------|------|
| 开发框架 | Spring Boot 2.7/3.x | 生态成熟，起步快，社区资料多 |
| 持久层 | MyBatis-Plus | 单表 CRUD 零 SQL，分页/条件构造器开箱即用，复杂查询走 XML |
| 数据库 | MySQL 8.0 | 业务数据落库，事务与关联查询可靠 |
| 缓存 | Redis | 商品详情缓存、购物车、分布式锁、统计数据缓存 |
| 前端 | Vue 3 + Element Plus | 后台管理系统标配，表格/表单组件齐全 |
| 鉴权 | Spring Security + JWT | 无状态认证，前后端分离标配 |
| 定时任务 | Spring Task / XXL-Job | 订单超时关闭、统计聚合、库存预警扫描 |
| 报表导出 | EasyExcel | 大数据量 Excel 导出，内存占用低 |
| 构建 | Maven | 依赖管理标准工具 |

选型说明：

```text
1. MyBatis-Plus 而非纯 MyBatis：商品/订单/会员都是标准单表 CRUD，MP 的 BaseMapper 和 LambdaQueryWrapper 省掉大量样板代码
2. SPU/SKU 关系查询手写 XML：spu 关联 sku、分类、属性需要多表 join，XML 里写清楚比 MP 链式调用更可控
3. Redis 承担四件事：商品详情缓存（读多写少）、购物车（高频读写）、分布式锁（下单防超卖）、统计缓存（聚合结果）
4. 库存与订单联动必须走 MySQL 事务 + 行锁，不能依赖 Redis 的最终一致，金额与库存宁可慢不能错
```

系统分层与请求链路：

```text
┌─────────────────────────────────────────────────────────┐
│                    客户端（浏览器）                        │
│     运营后台（Vue3 + Element Plus）   仓储/客服工作台       │
└──────────────────────────────┬──────────────────────────┘
                               │ HTTP / JSON
┌──────────────────────────────▼──────────────────────────┐
│                   Spring Boot 应用层                      │
│  ┌─────────┐ ┌─────────┐ ┌─────────┐ ┌──────────────┐   │
│  │Controller│ │ Service │ │  Mapper │ │ Security/JWT │   │
│  └─────────┘ └─────────┘ └─────────┘ └──────────────┘   │
│  ┌──────────────────────────────────────────────────┐    │
│  │ 领域服务：商品/库存/订单/会员/促销/统计            │    │
│  └──────────────────────────────────────────────────┘    │
└──────┬──────────────────┬──────────────────┬─────────────┘
       │                  │                  │
┌──────▼──────┐   ┌───────▼───────┐   ┌──────▼──────────┐
│   MySQL     │   │    Redis      │   │   定时任务       │
│ 商品/库存/   │   │ 商品缓存/购物车 │   │ 订单超时/统计    │
│ 订单/会员表  │   │ 锁/统计缓存    │   │ 聚合/库存预警    │
└─────────────┘   └───────────────┘   └─────────────────┘
```

下单请求链路（前台用户下单 → 后台库存联动）：

```text
1. 用户提交订单：携带 skuId + 数量 + 收货地址 + 优惠券
2. 网关层鉴权（JWT），路由到订单服务
3. OrderService 加分布式锁：lock:order:{userId}，防止同一用户并发下单
4. 事务内操作：查询 SKU 价格与可用库存，校验库存充足
5. 扣减库存：UPDATE sku SET stock = stock - n WHERE id = ? AND stock >= n
   （条件更新即行锁，扣减失败说明库存不足，抛异常回滚）
6. 生成订单主表 + 订单明细表，写入库存流水表（出库记录）
7. 事务提交后释放锁，Redis 删商品详情缓存（先更库后删缓存）
8. 返回订单号，前端跳转支付；支付回调后再触发真正的库存出库
```

Redis Key 设计：

```text
1. product:spu:{id}           商品详情缓存（SPU+SKU 组装好的 VO），TTL 30 分钟，变更即删
2. product:spu:list:{page}    商品列表页缓存，TTL 5 分钟
3. cart:{memberId}            Hash 结构购物车，field = skuId，value = 数量
4. lock:order:{memberId}      下单分布式锁，防止同一用户并发重复下单
5. coupon:stock:{couponId}    优惠券剩余量计数器（发行量 - 领取量），INCR 原子扣减
6. stat:sale:{yyyyMMdd}       当日销售额/订单量实时计数器，定时聚合刷 MySQL
7. token:{jti}                JWT 会话缓存，支持强制下线
8. lock:stat:sync             统计聚合任务分布式锁，防止多实例重复执行
```

## 核心实现

### 1. 多级分类树（递归组装 + 缓存）

```java
@Service
public class CategoryService {

    private static final String CACHE_KEY = "product:category:tree";

    @Autowired
    private CategoryMapper categoryMapper;
    @Autowired
    private RedisTemplate<String, Object> redisTemplate;

    /**
     * 查询整棵分类树（缓存优先）
     * 递归组装：顶级分类 -> 子分类 -> 孙分类，支持无限层级
     */
    @SuppressWarnings("unchecked")
    public List<CategoryVO> getTree() {
        Object cached = redisTemplate.opsForValue().get(CACHE_KEY);
        if (cached != null) {
            return (List<CategoryVO>) cached;
        }
        // 1. 一次查出全部分类（后台量级小，全量加载）
        List<Category> all = categoryMapper.selectList(
                new LambdaQueryWrapper<Category>()
                        .eq(Category::getStatus, 1)
                        .orderByDesc(Category::getSort));
        // 2. 按 parentId 分组
        Map<Long, List<Category>> byParent = all.stream()
                .collect(Collectors.groupingBy(Category::getParentId));
        // 3. 递归构建树
        List<CategoryVO> tree = buildChildren(0L, byParent);
        redisTemplate.opsForValue().set(CACHE_KEY, tree, 30, TimeUnit.MINUTES);
        return tree;
    }

    private List<CategoryVO> buildChildren(Long parentId,
                                           Map<Long, List<Category>> byParent) {
        List<Category> children = byParent.getOrDefault(parentId, Collections.emptyList());
        List<CategoryVO> vos = new ArrayList<>();
        for (Category c : children) {
            CategoryVO vo = new CategoryVO();
            vo.setId(c.getId());
            vo.setName(c.getName());
            vo.setChildren(buildChildren(c.getId(), byParent));
            vos.add(vo);
        }
        return vos;
    }

    /** 分类变更（新增/修改/删除/排序）后删除缓存 */
    public void clearCache() {
        redisTemplate.delete(CACHE_KEY);
    }
}
```

```java
     * 入库操作（采购/退货入库）

    @Transactional(rollbackFor = Exception.class)
    public void inbound(Long skuId, int qty, String bizNo, String operator) {

            throw new BusinessException("入库数量必须大于 0");
        }
        // 1. 行锁查询当前库存（for update 悲观锁，串行化同一 SKU 的库存操作）

        // 2. 更新库存
        Sku update = new Sku();
        update.setId(skuId);
        update.setStock(before + qty);
        skuMapper.updateById(update);
        // 3. 写流水
        insertLog(skuId, 1, qty, before, before + qty, bizNo, operator, "入库");
    }

    public List<Sku> warnList() {
```

### 4. 下单：库存与订单联动（核心难点）

```java
@Service
public class OrderService {

    @Autowired
    private SkuMapper skuMapper;
    @Autowired
    private OrderMapper orderMapper;
    @Autowired
    private OrderItemMapper orderItemMapper;
    @Autowired
    private StringRedisTemplate stringRedisTemplate;

    private static final String LOCK_PREFIX = "lock:order:";

    /**
     * 创建订单（核心：扣库存 + 建订单必须在同一事务）
     * 超卖防护三层：
     * 1. 分布式锁防止同一用户并发
     * 2. UPDATE ... WHERE stock >= ? 条件更新，数据库层面保证不超卖
     * 3. 锁库存（locked_stock）避免「已下单未支付」的货被再卖
     */
    @Transactional(rollbackFor = Exception.class)
    public Long createOrder(OrderCreateDTO dto) {
        String lockKey = LOCK_PREFIX + dto.getMemberId();
        // 1. 获取分布式锁（SET NX EX，失败说明用户正在下单，直接返回）
        Boolean locked = stringRedisTemplate.opsForValue()
                .setIfAbsent(lockKey, "1", Duration.ofSeconds(10));
        if (!Boolean.TRUE.equals(locked)) {
            throw new BusinessException("操作太频繁，请稍后再试");
        }
        try {
            // 2. 预校验 + 计算金额
            BigDecimal total = BigDecimal.ZERO;
            List<OrderItem> items = new ArrayList<>();
            for (OrderItemDTO itemDTO : dto.getItems()) {
                Sku sku = skuMapper.selectById(itemDTO.getSkuId());
                if (sku == null || sku.getStatus() != 1) {
                    throw new BusinessException("商品已下架: " + itemDTO.getSkuId());
                }
                // 3. 原子扣减可用库存：stock >= n 是条件，防止并发超卖
                int rows = skuMapper.deductStock(itemDTO.getSkuId(), itemDTO.getQuantity());
                if (rows == 0) {
                    throw new BusinessException("库存不足: " + sku.getSkuNo());
                }
                // 4. 同步增加锁定库存（下单未支付期间占用）
                skuMapper.addLockedStock(itemDTO.getSkuId(), itemDTO.getQuantity());

                total = total.add(sku.getPrice().multiply(
                        BigDecimal.valueOf(itemDTO.getQuantity())));
                items.add(buildItem(sku, itemDTO));
            }
            // 5. 计算优惠（优惠券/满减，此处简化）
            BigDecimal discount = calcDiscount(dto, total);
            BigDecimal payAmount = total.subtract(discount);

            // 6. 创建订单主表 + 明细
            Orders order = new Orders();
            order.setOrderNo(genOrderNo());
            order.setMemberId(dto.getMemberId());
            order.setTotalAmount(total);
            order.setDiscountAmount(discount);
            order.setPayAmount(payAmount);
            order.setStatus(0);   // 待支付
            order.setReceiverName(dto.getReceiverName());
            order.setReceiverPhone(dto.getReceiverPhone());
            order.setReceiverAddr(dto.getReceiverAddr());
            orderMapper.insert(order);
            items.forEach(i -> i.setOrderId(order.getId()));
            items.forEach(orderItemMapper::insert);

            // 7. 写库存流水（销售锁定记录）
            for (OrderItemDTO itemDTO : dto.getItems()) {
                stockLogMapper.insert(buildLockLog(itemDTO, order.getOrderNo()));
            }
            return order.getId();
        } finally {
            // 8. 释放分布式锁
            stringRedisTemplate.delete(lockKey);
        }
    }

    /** 超时未支付自动取消：释放锁定库存 */
    @Transactional(rollbackFor = Exception.class)
    public void cancelExpiredOrders() {
        // 定时任务调用：查出创建超过 30 分钟仍待支付的订单
        List<Orders> expired = orderMapper.selectExpiredPending(30);
        for (Orders order : expired) {
            // 逐单取消：回补库存、释放锁定、改状态（此处省略明细遍历）
            orderMapper.updateStatus(order.getId(), 4, 0);
            releaseLockedStock(order.getId());
        }
    }
}
```

### 5. 优惠券领取与核销（Redis 计数 + 事务）

```java
@Service
public class CouponService {

    @Autowired
    private CouponMapper couponMapper;
    @Autowired
    private StringRedisTemplate stringRedisTemplate;

    private static final String STOCK_KEY = "coupon:stock:";
    private static final String RECEIVE_LOCK = "lock:coupon:receive:";

    /**
     * 领取优惠券：Redis 原子扣减发行余量，DB 落领取记录
     * 先扣 Redis 再写库，防并发超发；写库失败则回补计数
     */
    @Transactional(rollbackFor = Exception.class)
    public void receive(Long couponId, Long memberId) {
        // 1. 幂等校验：一人限领一张（Redis 记录已领）
        Boolean first = stringRedisTemplate.opsForValue()
                .setIfAbsent(RECEIVE_LOCK + couponId + ":" + memberId,
                        "1", Duration.ofMinutes(1));
        if (!Boolean.TRUE.equals(first)) {
            throw new BusinessException("请勿重复领取");
        }
        // 2. 原子扣减剩余量（负数说明已领完）
        Long remain = stringRedisTemplate.opsForValue()
                .decrement(STOCK_KEY + couponId);
        if (remain == null || remain < 0) {
            stringRedisTemplate.opsForValue().increment(STOCK_KEY + couponId);
            throw new BusinessException("优惠券已领完");
        }
        // 3. 落库（user_coupon 表 insert，此处简化为直接计数）
        couponMapper.incrReceiveCount(couponId);
        // 4. 发送「领取成功」消息（异步，可对接 MQ）
    }

    /**
     * 下单时校验优惠券是否可用并计算抵扣
     * threshold 为门槛：满 X 才可用
     */
    public BigDecimal calcDiscount(Coupon coupon, BigDecimal orderAmount) {
        if (coupon.getThreshold() != null
                && orderAmount.compareTo(coupon.getThreshold()) < 0) {
            throw new BusinessException("未满足使用门槛");
        }
        if (coupon.getType() == 1) {          // 满减券
            return coupon.getAmount().min(orderAmount);
        } else if (coupon.getType() == 3) {   // 无门槛券
            return coupon.getAmount();
        }
        return BigDecimal.ZERO;
    }
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. SPU/SKU 分层是电商商品建模的标配：公共信息放 SPU，价格/库存/规格放 SKU，库存永远挂在 SKU 上，绝不放 SPU
2. 库存扣减必须用「条件更新」UPDATE ... SET stock = stock - n WHERE stock >= n，这是防超卖的根本手段，应用层锁只是辅助
3. 库存变动一律写流水表（stock_log），「库存值」可修正，「流水账」不可篡改，对账全靠它
4. 订单与库存联动必须单事务：扣库存、建订单、写流水任何一个失败都要整体回滚，绝不能先扣库存后建订单
5. 下单用「锁库存（locked_stock）」而非直接扣库存：未支付订单占用的库存要看得见、可释放
6. 金额计算全程用 BigDecimal，绝不用 double/float，比较用 compareTo
7. 商品详情缓存一致性用「先更库、后删缓存」；列表页缓存 TTL 设短（5 分钟内），详情页可长（30 分钟）

### 踩坑记录

```text
坑 1：超卖事故
结论：活动期间库存卖成负数。
原因：先 SELECT 查库存再 UPDATE 扣减，两条语句之间并发下单都读到同一个库存值。
解法：改为单条条件更新 UPDATE sku SET stock = stock - n WHERE id = ? AND stock >= n，
     受影响行数为 0 即库存不足；对账脚本每日检查 stock + locked 与流水是否一致。

坑 2：MySQL 事务里用了 Redis 锁导致死锁/长事务
结论：下单接口偶发超时。
原因：分布式锁（Redis）与数据库行锁同时使用，锁释放逻辑异常时事务一直挂着，
     行锁不释放，后续请求全部排队。
解法：锁只保护「同一用户的并发下单」这一层，库存扣减本身靠数据库条件更新；
     锁 TTL 设短（10 秒），finally 中释放；严禁在事务内做 Redis 网络 IO 重试。

坑 3：SKU 规格相同但能重复保存
结论：后台商品管理出现两个一模一样的黑色 XL。
原因：保存 SKU 时没校验规格 JSON 是否重复，数据库也没有唯一索引约束。
解法：应用层 Set 去重 + 数据库加唯一索引 uk(sku_no)；规格用规范化 JSON（key 排序）后再比较。

坑 4：分类树删了父分类，子分类变成孤儿
结论：商品详情页分类显示为空。
原因：删除分类时没有检查子分类和挂载商品。
解法：删除前校验子分类数与商品数，有引用则禁止删除或强制先迁移；加 level 字段便于
     层级约束（只能删叶子分类）。

坑 5：取消订单没释放锁定库存
结论：大量订单取消后，仓库实际有货但前台显示无货。
原因：超时取消任务只改了订单状态，忘了回补 locked_stock 和 stock。
解法：取消/关闭订单统一走一个方法，事务内完成「状态更新 + 库存回补 + 流水」；
     增加对账任务：锁定库存超 24 小时未支付的订单强制扫描处理。

坑 6：统计数字对不上财务账
结论：看板销售额与财务系统差了 2 万。
原因：看板统计的是「下单金额」包含未支付订单，财务统计的是「支付成功金额」。
解法：明确指标口径：销售额 = 已支付订单实付金额，下单金额单独命名；
```

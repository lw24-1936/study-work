## 项目背景

会议室是公司最抢手的公共资源，传统管理方式（行政台账登记、前台口头询问、微信群接龙）在百人以上规模的公司里必然出乱子：会议室被重复预订、订了不来、设备缺失、会议撞车。会议室预约系统的本质是一个「资源 + 时间段」的排他性预订系统，与酒店房态、医院号源、机房机位同构，但多了审批流、邀请、签到、纪要等办公协同能力，是学习「时间段冲突检测 + 并发资源抢占」最合适的实战项目。

业务痛点：

```text
1. 口头/台账预约：信息不同步，A 部门订了 B 部门不知道，现场撞车
2. 无冲突检测：同一会议室同一时段被重复预订，全靠行政人工核对
3. 无审批控制：重要会议室（总裁办、董事会）谁都能订，无权限分层
4. 订了不来：无人签到、无爽约记录，稀缺资源被无效占用
5. 设备不可控：投影仪、视频会议设备没有单独预约，开会才发现设备被借走
6. 无提醒机制：会议开始前无人提醒，参会人迟到，会议纪要散落在个人电脑
```

目标用户与核心诉求：

```text
1. 普通员工：查会议室空闲时段、发起预约、收到审批结果与开会提醒、扫码签到
2. 部门助理/行政：管理会议室与设备、人工审批重要会议室、查看使用统计
3. 管理员：会议室增删改（容量/位置/开放时间）、设备维护状态、全局预约规则
4. 参会人：收到会议邀请、确认参会、会后查看纪要
```

项目要解决的核心问题一句话概括：让会议室资源像高铁票一样被「时间片」精确管理，冲突可检测、抢占有锁、过程可追溯。

## 功能介绍

功能按角色拆成四个模块：会议室资源管理、预约与审批、会议协同、统计与提醒。

```text
一、会议室资源管理（管理员视角）
1. 会议室管理 —— 增删改查：名称/位置/容量/开放时间（如 08:00-22:00）/状态（可用/停用）
2. 设备管理 —— 会议室绑定设备（投影仪/白板/电视/视频会议终端），设备维修中可标记
3. 设备预约 —— 设备随会议预约或单独预约（如借用投影仪），同样做时段冲突检测

二、预约与审批（员工 + 审批人视角）
1. 空闲查询 —— 按日期/时段/容量/设备筛选可用会议室，日历视图展示
2. 发起预约 —— 选会议室 + 时间段 + 主题 + 参会人，系统自动检测时段冲突
3. 冲突检测 —— 同一时段同一会议室只允许一个有效预约，重叠即拦截
4. 审批流程 —— 普通会议室自动审批（无冲突即通过）；重要会议室转人工审批
5. 我的预约 —— 待审批/已通过/已驳回/已取消四态列表，可取消未开始的预约
6. 会议状态流转 —— 待审批→已通过→进行中→已结束，超时未开会自动释放

三、会议协同（发起人 + 参会人视角）
1. 会议邀请 —— 预约通过后自动通知参会人，可接受/拒绝
2. 提醒 —— 会议开始前 30 分钟站内信 + 邮件提醒，发送记录可查
3. 签到 —— 会议开始前后扫码签到，记录签到时间
4. 会议纪要 —— 会后上传纪要（Markdown），关联待办事项
5. 签到统计 —— 应到/实到/迟到/爽约，会议室使用率统计

四、日历视图（全员视角）
1. 日视图 —— 选中日期，按小时轴展示各会议室占用情况
2. 周视图 —— 一周内各会议室预约块状图，空闲时段一目了然
3. 冲突高亮 —— 同一会议室重叠的预约红色标记（历史遗留数据也能暴露）
```

## 技术选型

| 组件 | 选型 | 理由 |
|------|------|------|
| 开发框架 | Spring Boot 2.7/3.x | 生态成熟，起步快 |
| 持久层 | MyBatis-Plus | 单表 CRUD 零 SQL，冲突检测/日历查询走自定义 XML |
| 数据库 | MySQL 8.0 | 预约数据落库，事务保证一致性 |
| 缓存 | Redis | 日历视图缓存、签到码、提醒去重标记 |
| 分布式锁 | Redisson | 并发预约同一会议室的场景，保证「检查-插入」原子性 |
| 定时任务 | Spring @Scheduled + Quartz（可选） | 会议提醒、超时自动释放、会议状态归档 |
| 鉴权 | Spring Security + JWT | 员工账号体系，预约/审批按角色鉴权 |
| 前端 | Vue 3 + Element Plus + FullCalendar | 日历视图用 FullCalendar 二次开发，后台用 Element Plus |

选型说明：

```text
1. 冲突检测必须用「数据库条件 UPDATE / SELECT ... FOR UPDATE」而不是应用层判断：先查后插存在竞态窗口，两个请求同时查到空闲都会插入成功
2. 并发预约同一会议室用 Redisson 分布式锁串行化：锁内做冲突检测 + 插入，锁粒度是 roomId 而不是全局锁，不同会议室互不阻塞
3. 日历视图是读多写少：缓存整天的预约块，预约变更时按 roomId+date 删除缓存
4. 定时任务管三类事：会议前 30 分钟提醒、会议结束状态归档、超时未开始自动释放
```

预约创建链路（员工提交预约）：

```text
1. 前端 POST /api/reservation，携带 roomId、startTime、endTime、参会人列表
2. Service 校验：时间段合法（开始 < 结束、在会议室开放时间内、非过去时间）
3. 获取 Redisson 分布式锁 meeting:lock:room:{roomId}（等待 3 秒）
4. 锁内做冲突检测：查该会议室时间重叠的有效预约，有冲突直接拒绝
5. 无冲突：插入预约记录（状态=待审批）+ 批量插入参会人邀请
6. 判断审批模式：普通会议室自动审批（更新为已通过 + 写审批记录），重要会议室保持待审批并通知审批人
7. 释放锁，删除该会议室当天日历缓存，返回预约结果
```

日历视图链路（员工查看某天会议室占用）：

```text
1. 前端 GET /api/calendar?date=2026-08-20&roomId=3
2. Service 查 Redis：key = meeting:calendar:{roomId}:{date}
3. 命中 → 直接返回当天预约块列表
4. 未命中 → SQL 查该会议室当天所有有效预约（状态=已通过/待审批）
5. 组装日历 VO（开始/结束/标题/审批状态/是否本人），写缓存 TTL 10 分钟
6. 前端 FullCalendar 渲染时间轴，空闲时段绿色、占用红色
```

## 核心实现

### 1. 时间段重叠冲突检测 SQL

冲突检测的本质：两个时间段 `[a1, a2)` 与 `[b1, b2)` 重叠当且仅当 `a1 < b2 AND a2 > b1`。SQL 中只统计「有效」状态（已通过/待审批），已取消、已驳回、已结束的预约不参与占用。

```java
@Mapper
public interface ReservationMapper extends BaseMapper<MeetingReservation> {

    /**
     * 统计指定会议室在 [startTime, endTime) 内重叠的有效预约数
     * 重叠条件：已存在预约的 start_time < 新结束时间 AND end_time > 新开始时间
     * 状态过滤：只有待审批(0)和已通过(1)才占用时段
     */
    @Select("""
            SELECT COUNT(*) FROM meeting_reservation
            WHERE room_id = #{roomId}
              AND status IN (0, 1)
              AND start_time < #{endTime}
              AND end_time > #{startTime}
            """)
    long countConflict(@Param("roomId") Long roomId,
                       @Param("startTime") LocalDateTime startTime,
                       @Param("endTime") LocalDateTime endTime);

    /**
     * 设备冲突检测：同一设备同一时段只能被一个有效预约占用
     */
    @Select("""
            SELECT COUNT(*) FROM device_reservation
            WHERE device_id = #{deviceId}
              AND status = 1
              AND start_time < #{endTime}
              AND end_time > #{startTime}
            """)
    long countDeviceConflict(@Param("deviceId") Long deviceId,
                             @Param("startTime") LocalDateTime startTime,
                             @Param("endTime") LocalDateTime endTime);

    /**
     * 日历视图：查某会议室某天的全部有效预约
     */
    @Select("""
            SELECT * FROM meeting_reservation
            WHERE room_id = #{roomId}
              AND status IN (0, 1)
              AND start_time < DATE_ADD(#{date}, INTERVAL 1 DAY)
              AND end_time > #{date}
            ORDER BY start_time
            """)
    List<MeetingReservation> selectByDay(@Param("roomId") Long roomId,
                                         @Param("date") LocalDate date);
}
```

### 2. 预约申请：分布式锁 + 冲突检测

并发预约同一会议室时，「查冲突 + 插入」必须原子。用 Redisson 锁把同一会议室的创建串行化，锁内再做冲突检测，从根上消除竞态。

```java
@Service
public class ReservationService {

    @Autowired
    private RedissonClient redissonClient;
    @Autowired
    private ReservationMapper reservationMapper;
    @Autowired
    private InviteeMapper inviteeMapper;
    @Autowired
    private ApprovalService approvalService;
    @Autowired
    private RedisTemplate<String, Object> redisTemplate;

    /**
     * 创建预约：分布式锁内完成冲突检测与插入
     */
    @Transactional
    public Long create(ReservationRequest req) {
        // 1. 基础校验：时间段合法性
        validateTimeRange(req);
        // 2. 加锁：锁粒度是会议室，不同会议室并发互不影响
        String lockKey = "meeting:lock:room:" + req.getRoomId();
        RLock lock = redissonClient.getLock(lockKey);
        boolean locked = false;
        try {
            // 等锁 3 秒：同一会议室的并发请求在此排队
            locked = lock.tryLock(3, 10, TimeUnit.SECONDS);
            if (!locked) {
                throw new BizException("当前会议室预约繁忙，请稍后重试");
            }
            // 3. 锁内冲突检测
            long conflict = reservationMapper.countConflict(
                    req.getRoomId(), req.getStartTime(), req.getEndTime());
            if (conflict > 0) {
                throw new BizException("该时段会议室已被预约，请选择其他时间");
            }
            // 4. 插入预约
            MeetingReservation resv = new MeetingReservation();
            resv.setRoomId(req.getRoomId());
            resv.setApplicantId(req.getApplicantId());
            resv.setTitle(req.getTitle());
            resv.setStartTime(req.getStartTime());
            resv.setEndTime(req.getEndTime());
            resv.setRemark(req.getRemark());
            resv.setStatus(ReservationStatus.PENDING.getCode());
            reservationMapper.insert(resv);
            // 5. 批量插入参会人（唯一键防重复）
            for (Long userId : req.getInviteeIds()) {
                Invitee invitee = new Invitee();
                invitee.setReservationId(resv.getId());
                invitee.setUserId(userId);
                inviteeMapper.insert(invitee);
            }
            // 6. 审批分支：自动审批直接通过，人工审批保持待审批
            approvalService.dispatch(resv);
            // 7. 删除日历缓存，让新预约立即可见
            redisTemplate.delete(calendarKey(req.getRoomId(), req.getStartTime().toLocalDate()));
            return resv.getId();
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
            throw new BizException("预约取消失败，请重试");
        } finally {
            if (locked && lock.isHeldByCurrentThread()) {
                lock.unlock();
            }
        }
    }

    /**
     * 取消预约：乐观更新防止把「已结束/已开始」的会议取消
     */
    @Transactional
    public void cancel(Long reservationId, Long operatorId) {
        MeetingReservation resv = reservationMapper.selectById(reservationId);
        if (!resv.getApplicantId().equals(operatorId)) {
            throw new BizException("只能取消自己的预约");
        }
        // 条件更新：只有待审批/已通过才能取消，其他状态不生效
        int rows = reservationMapper.updateStatusIfIn(
                reservationId, ReservationStatus.CANCELLED.getCode(),
                List.of(ReservationStatus.PENDING.getCode(), ReservationStatus.APPROVED.getCode()));
        if (rows == 0) {
            throw new BizException("当前状态不可取消");
        }
        redisTemplate.delete(calendarKey(resv.getRoomId(), resv.getStartTime().toLocalDate()));
    }

    private String calendarKey(Long roomId, LocalDate date) {
        return "meeting:calendar:" + roomId + ":" + date;
    }
}
```

### 3. 审批流程：自动审批 + 人工审批

预约创建后统一走 dispatch：普通会议室自动通过并留审批记录；需人工审批的会议室保持待审批，推送审批任务给管理员。

```java
@Service
public class ApprovalService {

    @Autowired
    private ReservationMapper reservationMapper;
    @Autowired
    private ApprovalMapper approvalMapper;
    @Autowired
    private RoomMapper roomMapper;
    @Autowired
    private NotifyService notifyService;

    /**
     * 审批分发：按会议室 need_approval 决定自动还是人工
     */
    @Transactional
    public void dispatch(MeetingReservation resv) {
        MeetingRoom room = roomMapper.selectById(resv.getRoomId());
        if (room.getNeedApproval().equals(0)) {
            // 自动审批：状态直接置为已通过
            autoApprove(resv, room);
        } else {
            // 人工审批：保持待审批，通知审批人
            resv.setApprovalMode(1);
            reservationMapper.updateById(resv);
            notifyService.notifyApprovers(resv, room);
        }
    }

    /**
     * 自动审批：写审批记录（approve_type=1，审批人为空），通知申请人
     */
    private void autoApprove(MeetingReservation resv, MeetingRoom room) {
        resv.setStatus(ReservationStatus.APPROVED.getCode());
        reservationMapper.updateById(resv);

        Approval approval = new Approval();
        approval.setReservationId(resv.getId());
        approval.setResult(1);
        approval.setApproveType(1);
        approval.setReason("自动审批：时段无冲突");
        approvalMapper.insert(approval);
        notifyService.notifyApplicant(resv, "预约已自动通过");
    }

    /**
     * 人工审批：管理员通过/驳回，写审批记录，通知申请人
     */
    @Transactional
    public void manualApprove(Long reservationId, Long approverId, boolean pass, String reason) {
        MeetingReservation resv = reservationMapper.selectById(reservationId);
        // 乐观更新：只有待审批才能被审批，防重复审批
        int rows = reservationMapper.updateStatusIfIn(
                reservationId,
                pass ? ReservationStatus.APPROVED.getCode() : ReservationStatus.REJECTED.getCode(),
                List.of(ReservationStatus.PENDING.getCode()));
        if (rows == 0) {
            throw new BizException("该预约已被处理");
        }
        Approval approval = new Approval();
        approval.setReservationId(reservationId);
        approval.setApproverId(approverId);
        approval.setResult(pass ? 1 : 2);
        approval.setApproveType(2);
        approval.setReason(reason);
        approvalMapper.insert(approval);

        String msg = pass ? "预约审批通过" : "预约被驳回：" + reason;
        notifyService.notifyApplicant(resv, msg);
    }
}
```

### 4. 会议提醒：定时任务 + 去重

会议开始前 30 分钟发站内信/邮件。定时任务每分钟扫一次「即将开始」的会议，Redis SETNX 保证每场会议只提醒一次（多实例部署也不重复发）。

```java
@Component
public class MeetingRemindTask {

    @Autowired
    private ReservationMapper reservationMapper;
    @Autowired
    private InviteeMapper inviteeMapper;
    @Autowired
    private NotifyService notifyService;
    @Autowired
    private RedisTemplate<String, Object> redisTemplate;

    /**
     * 每分钟执行：找出 30 分钟后开始的已通过会议，逐个提醒
     */
    @Scheduled(fixedDelay = 60 * 1000)
    public void remindUpcoming() {
        LocalDateTime start = LocalDateTime.now().plusMinutes(30);
        LocalDateTime end = start.plusMinutes(1);
        // 扫 [30分钟, 31分钟) 窗口内开始的会议
        List<MeetingReservation> list = reservationMapper
                .selectByStartWindow(start, end, ReservationStatus.APPROVED.getCode());
        for (MeetingReservation resv : list) {
            remindOnce(resv);
        }
    }

    private void remindOnce(MeetingReservation resv) {
        // SETNX 去重：提醒过的会议不再提醒
        String key = "meeting:remind:done:" + resv.getId();
        Boolean first = redisTemplate.opsForValue()
                .setIfAbsent(key, "1", Duration.ofDays(1));
        if (Boolean.FALSE.equals(first)) {
            return;
        }
        List<Invitee> invitees = inviteeMapper.selectByReservation(resv.getId());
        for (Invitee invitee : invitees) {
            notifyService.sendMessage(invitee.getUserId(),
                    "会议提醒：" + resv.getTitle() + " 将于 " + resv.getStartTime() + " 开始，"
                            + "地点会议室 " + resv.getRoomId());
        }
    }
}
```

### 5. 签到与签到统计

签到码在会议开始前由定时任务生成，员工扫码输入签到码完成签到；统计模块汇总应到/实到/迟到/爽约。

```java
@Service
public class CheckinService {

    @Autowired
    private InviteeMapper inviteeMapper;
    @Autowired
    private ReservationMapper reservationMapper;
    @Autowired
    private RedisTemplate<String, Object> redisTemplate;

    /**
     * 会议开始前生成签到码（随机 6 位数字），写入 Redis，过期自动消失
     */
    public String generateCode(Long reservationId) {
        String code = String.valueOf(ThreadLocalRandom.current().nextInt(100000, 1000000));
        redisTemplate.opsForValue().set("meeting:sign:code:" + reservationId,
                code, Duration.ofHours(3));
        return code;
    }

    /**
     * 员工签到：校验签到码 + 必须是该会议参会人
     */
    @Transactional
    public void checkin(Long reservationId, Long userId, String code) {
        // 1. 校验签到码
        String expected = (String) redisTemplate.opsForValue()
                .get("meeting:sign:code:" + reservationId);
        if (expected == null || !expected.equals(code)) {
            throw new BizException("签到码错误或已过期");
        }
        // 2. 更新参会人签到状态（条件更新保证只签一次）
        int rows = inviteeMapper.updateSignStatus(
                reservationId, userId, 1, LocalDateTime.now());
        if (rows == 0) {
            throw new BizException("您不在本次会议参会名单中或已签到");
        }
        // 3. 写入 Redis 集合，供实时统计
        redisTemplate.opsForSet().add("meeting:sign:set:" + reservationId, userId);
    }

    /**
     * 签到统计：应到/实到/迟到/爽约，迟到=签到时间晚于会议开始时间
     */
    public CheckinStatVO stat(Long reservationId) {
        MeetingReservation resv = reservationMapper.selectById(reservationId);
        List<Invitee> invitees = inviteeMapper.selectByReservation(reservationId);
        CheckinStatVO vo = new CheckinStatVO();
        vo.setExpected(invitees.size());
        vo.setSigned((int) invitees.stream().filter(i -> i.getSignStatus() == 1).count());
        // 迟到判定：sign_time 晚于会议 start_time
        vo.setLate((int) invitees.stream()
                .filter(i -> i.getSignStatus() == 1
                        && i.getSignTime() != null
                        && i.getSignTime().isAfter(resv.getStartTime()))
                .count());
        vo.setAbsent(vo.getExpected() - vo.getSigned());
        return vo;
    }
}
```

### 6. 日历视图数据组装

日历接口把「会议室 X 时间轴」的预约块组装成前端可直接渲染的结构，缓存命中则免查库。

```java
@Service
public class CalendarService {

    @Autowired
    private ReservationMapper reservationMapper;
    @Autowired
    private RoomMapper roomMapper;
    @Autowired
    private RedisTemplate<String, Object> redisTemplate;

    /**
     * 日视图：某会议室某天的预约块列表（含空闲时间推导）
     */
    public DayViewVO dayView(Long roomId, LocalDate date) {
        String key = "meeting:calendar:" + roomId + ":" + date;
        Object cached = redisTemplate.opsForValue().get(key);
        if (cached != null) {
            return (DayViewVO) cached;
        }
        MeetingRoom room = roomMapper.selectById(roomId);
        List<MeetingReservation> list = reservationMapper.selectByDay(roomId, date);
        // 组装预约块：只暴露前端需要字段，不泄露内部状态码
        List<ReservationBlock> blocks = list.stream().map(r -> {
            ReservationBlock b = new ReservationBlock();
            b.setReservationId(r.getId());
            b.setTitle(r.getTitle());
            b.setStartTime(r.getStartTime());
            b.setEndTime(r.getEndTime());
            b.setStatus(r.getStatus()); // 待审批灰色，已通过绿色
            return b;
        }).toList();
        DayViewVO vo = new DayViewVO();
        vo.setRoomId(roomId);
        vo.setRoomName(room.getName());
        vo.setDate(date);
        vo.setBlocks(blocks);
        // 按「预约块之间」推导空闲时段（会议室开放时间范围内）
        vo.setFreeSlots(deriveFreeSlots(room, blocks));
        redisTemplate.opsForValue().set(key, vo, 10, TimeUnit.MINUTES);
        return vo;
    }

    /**
     * 空闲时段推导：开放时间区间减去已预约块，得到可预订窗口
     */
    private List<FreeSlot> deriveFreeSlots(MeetingRoom room, List<ReservationBlock> blocks) {
        LocalTime open = LocalTime.parse(room.getOpenTime());
        LocalTime close = LocalTime.parse(room.getCloseTime());
        List<FreeSlot> slots = new ArrayList<>();
        LocalDateTime cursor = LocalDateTime.now().toLocalDate().atTime(open);
        LocalDateTime closeTime = LocalDateTime.now().toLocalDate().atTime(close);
        for (ReservationBlock b : blocks) {
            if (b.getStartTime().isAfter(cursor)) {
                slots.add(new FreeSlot(cursor, b.getStartTime()));
            }
            cursor = b.getEndTime().isAfter(cursor) ? b.getEndTime() : cursor;
        }
        if (cursor.isBefore(closeTime)) {
            slots.add(new FreeSlot(cursor, closeTime));
        }
        return slots;
    }
}
```

### 7. 会议状态归档：定时任务

会议结束后把状态置为「已结束」并释放设备占用；超过开始时间 15 分钟未开始的预约自动取消（爽约释放资源）。

```java
@Component
public class MeetingArchiveTask {

    @Autowired
    private ReservationMapper reservationMapper;
    @Autowired
    private DeviceReservationMapper deviceReservationMapper;

     */
    @Scheduled(fixedDelay = 5 * 60 * 1000)
    public void archiveFinished() {

        reservationMapper.archiveFinished(ReservationStatus.FINISHED.getCode(), now);

    @Scheduled(fixedDelay = 5 * 60 * 1000)
    public void cancelNoShow() {
        LocalDateTime deadline = LocalDateTime.now().minusMinutes(15);
        reservationMapper.cancelNoShow(ReservationStatus.CANCELLED.getCode(), deadline);
    }
}
```

某 300 人公司有 12 间会议室，以前靠行政手工登记，一天撞车 3 次：

```text
1. 行政初始化：录入 12 间会议室（容量/位置/开放时间），绑定投影仪、白板等设备
2. 普通小会议室 need_approval=0，自动审批；大会议室（容纳 30 人）need_approval=1 需行政审批
3. 员工在日历视图看到空闲时段，选 14:00-15:00 发起预约，自动通过并通知参会人
4. 两个部门同时抢 14:00 大会议室：Redisson 锁串行化，后到者收到「时段冲突」提示
5. 会议前 30 分钟全员收到提醒，扫码签到，行政看签到统计发现爽约率 20%
6. 行政设置爽约规则：超时 15 分钟未开始的会议自动取消，资源释放给其他人
7. 月底导出使用率统计，行政把使用率低的会议室改造成电话间
```

## 最佳实践与踩坑记录

### 最佳实践

1. 冲突检测用一条 SQL 的区间重叠条件（start < newEnd AND end > newStart），而不是应用层循环判断，省一次查询且无竞态
2. 并发预约同一资源必须加分布式锁：锁粒度精确到会议室/设备，锁内做「查冲突 + 插入」，不同资源并发互不阻塞
3. 状态流转全部用条件 UPDATE（UPDATE ... SET status=? WHERE id=? AND status IN (...)），影响行数为 0 即状态已变，天然幂等防重复操作
4. 日历视图是典型读多写少：缓存按「roomId + 日期」做 key，预约/取消/审批时精确删除对应 key，不用全局清缓存
5. 提醒类定时任务必须去重：Redis SETNX + TTL 保证每场会议只提醒一次，多实例部署也不重复
6. 设备与会议室解耦：设备单独成表、单独预约、单独冲突检测，会议室状态不被设备维修拖累
7. 时间段校验前置：开始 < 结束、在开放时间内、非过去时间，在入参校验层就拦住，别让脏数据进库

### 踩坑记录

```text
坑 1：并发预约同一会议室双双成功
结论：两个人同时提交同一时段预约，都显示成功。
原因：先查冲突再插入的「检查-插入」两步之间存在竞态窗口。
解法：Redisson 锁（锁粒度 roomId）串行化同一会议室的创建，锁内查+插；数据库再加唯一约束兜底（可用 room_id+start_time 冗余字段做唯一键）。

坑 2：冲突检测把已取消的预约也算进去了
结论：会议室明明空了，却提示「时段已被预约」。
原因：冲突 SQL 没过滤状态，已取消/已驳回的预约也参与区间重叠判断。
解法：冲突条件加 status IN (待审批, 已通过)，取消和驳回即时释放时段。

坑 3：提醒重复发送
结论：同一场会议参会人收到 3 条提醒。
原因：定时任务每 1 分钟扫一次窗口，同一会议在窗口内被扫到多次；多实例部署时更严重。
解法：Redis SETNX meeting:remind:done:{id} 去重，TTL 1 天；已提醒的会议直接跳过。

坑 4：审批把已取消的预约通过了
结论：申请人取消了预约，管理员后审批还是显示「已通过」。
原因：审批只按 id 更新状态，没校验当前状态。
解法：审批用条件更新（WHERE status=待审批），影响行数为 0 时提示「该预约已被处理」。

坑 5：日历缓存不及时刷新
结论：新预约成功后，日历视图还是旧的，看不到刚订的时段。
原因：只写了缓存、没在预约变更时删缓存，等 TTL 10 分钟。
解法：预约创建/取消/审批的统一收尾动作里删 meeting:calendar:{roomId}:{date}。

坑 6：跨天预约的冲突检测漏检
结论：22:00-次日 01:00 的预约与当天其他预约重叠却检测不到。
原因：日历查询按单日过滤（start_time < 次日），跨天会议被截断。
解法：冲突检测 SQL 用绝对时间比较，天然支持跨天；日历视图按「区间相交」而不是「当天开始」过滤。

坑 7：会议未开始就被归档成已结束
结论：会议还没开，状态变成已结束。
原因：归档任务按 end_time < now 判断，把「已通过但未开始」的会议也算进去了。
解法：归档条件加 status=已通过 且 start_time < now 且 end_time < now；未开始的会议走爽约取消逻辑。
```

## 项目背景

共享充电宝系统（Shared Power Bank System）是共享经济领域的典型项目：平台在城市各处铺设充电柜，用户扫码租借充电宝，用完归还到任意同品牌柜机，系统按使用时长自动计费。业务核心是「一借一还」两个动作加上背后的设备管理、计费结算、押金流转。与网约车不同，充电宝业务的「归还」是开放的——用户可能把宝还到任何一台柜机，这就要求设备状态（柜格占用、电量）必须实时可信，且订单结算必须发生在归还那一刻。这个项目覆盖了 IoT 设备模拟、订单状态机、按时间计费、押金生命周期、消息补偿重试等核心机制，是理解「线上订单与线下设备状态一致性」的最佳实战项目。

业务痛点：

```text
1. 设备状态不可信：柜机离线、柜格卡宝、电量上报延迟，线上显示有宝实际没有，用户体验差
2. 计费规则复杂：按时间计费 + 每日封顶 + 免费时长 + 不同品牌不同价，归还瞬间要算清
3. 归还即结算：用户还到任意柜机，订单必须在归还事件到达的几秒内完成计费与扣款
4. 押金流程重：免押评估、押金冻结、归还后退还，资金流转出错会引发投诉与监管风险
5. 设备离线断点：柜机断网时租借/归还事件丢失，订单状态与实物不一致，需要补偿对账
6. 低电量资产损失：没人回收低电量宝，充电宝闲置在柜机里，资产周转率低
```

目标用户与核心诉求：

```text
1. 用户：扫码 5 秒内借到宝，归还后立即收到账单，押金退还到账快，费用透明
2. 运维人员：实时查看设备在线率、柜格状态、低电量宝分布，一键下发回收指令
3. 平台运营：配置计费规则与封顶策略，处理异常订单（卡宝/丢宝/误扣），保障资金安全
4. 财务：每日订单结算、押金流水对账、平台收入统计
```

项目要解决的核心问题一句话概括：让「扫码借宝 - 使用 - 归还 - 计费 - 押金流转」这条链路在设备随时可能离线的情况下保持线上订单状态与线下实物状态的一致，并在归还瞬间完成准确计费。

## 功能介绍

功能按角色与模块拆分：用户端（租借）、设备端（IoT 柜机）、订单计费（核心）、资产管理（调度）、平台治理（规则与异常）。

```text
一、用户端（C 端用户）
1. 扫码租借 —— 扫柜机二维码，查看柜格电量分布，选择租借（自动分配电量最高的宝）
2. 免押评估 —— 芝麻信用分/微信支付分达标免押金，未达标冻结押金
3. 订单中心 —— 租借中订单：已用时长、实时费用、免费时长剩余、附近可还网点
4. 归还结算 —— 扫码归还到柜，柜格确认锁宝后自动结算账单，扣款并推送支付结果
5. 押金退还 —— 租借中的押金在归还结算时自动解冻，异常场景（丢宝）走押金赔付

二、设备端（IoT 柜机模拟）
1. 心跳上报 —— 每 30 秒上报设备在线状态、柜格占用情况
2. 电量上报 —— 柜内每格充电宝上报电量百分比，低电量标记待回收
3. 指令执行 —— 接收平台下发指令：开锁（借出/归还锁宝）、柜格状态变更确认
4. 离线缓冲 —— 断网期间本地记录操作事件，恢复后批量补传（带时间戳）

三、订单计费（核心模块）
1. 租借开单 —— 开锁成功后生成租借订单，记录借出时间与柜机信息
2. 实时计费 —— 租借中按分钟累计费用（前端展示用，以归还结算为准）
3. 归还结算 —— 归还时按规则算费：基础时长费 + 超时费，扣除免费时长，封顶保护
4. 支付闭环 —— 结算后自动扣款（余额/免密代扣），生成支付流水，失败进入补扣队列

四、押金管理
1. 免押评估 —— 信用分达标免押，未达标按充电宝价值冻结押金
2. 押金冻结 —— 租借成功时冻结，防止用户欠费跑路
3. 押金退还 —— 归还结算且无欠费后自动解冻，实时退回原支付渠道
4. 押金赔付 —— 逾期未还/丢宝场景，按规则扣罚押金，剩余部分退还

五、资产管理（设备调度）
1. 设备台账 —— 柜机/充电宝全生命周期管理（投放/维修/报废）
2. 电量监控 —— 全城低电量宝分布，运维按片区下发回收任务
3. 回收调度 —— 低电量宝标记待回收，运维取走充电，充满后重新投放
4. 库存看板 —— 每个柜机在线宝数/可用宝数/占用宝数实时统计

六、平台治理（异常与规则）
1. 异常订单处理 —— 卡宝（开锁未取出）/错还（还错柜）/丢宝（超期未还）自动识别与人工介入
2. 计费规则配置 —— 不同品牌/城市的基础价、每小时单价、每日封顶、免费时长
3. 消息补偿 —— 设备离线期间事件补传后的对账重放，幂等处理
4. 数据统计 —— 租借量、归还率、营收、设备在线率日报
```

## 技术选型

| 组件 | 选型 | 理由 |
|------|------|------|
| 开发框架 | Spring Boot 2.7/3.x | 生态成熟，快速搭建业务服务 |
| 持久层 | MyBatis-Plus | 单表 CRUD 零 SQL，复杂对账查询走 XML |
| 数据库 | MySQL 8.0 | 用户/设备/订单/押金流水等核心数据 |
| 缓存 | Redis（String/Hash/SETNX） | 设备实时状态、柜格状态、分布式锁 |
| 消息队列 | RabbitMQ | 设备事件异步处理、离线补偿重试、延迟消息 |
| 设备接入 | Netty TCP / HTTP 长连接（模拟） | 柜机心跳与指令下发通道 |
| 支付 | 微信/支付宝免密代扣 API | 租借冻结、归还自动扣款、押金退款 |
| 信用评估 | 芝麻信用/微信支付分 API | 免押判定 |
| 定时任务 | Spring @Scheduled / XXL-Job | 逾期订单扫描、设备离线检测、对账任务 |
| 构建 | Maven | 依赖管理标准工具 |

选型说明：

```text
1. 设备事件全部走 MQ 异步化：开锁结果、归还结果、心跳都是高频事件，直接同步处理会拖垮主链路，MQ 削峰 + 消费者幂等处理
2. 实时状态用 Redis、账务数据用 MySQL：柜格占用、宝电量是瞬时状态放 Redis 快速读写；订单、流水、押金是账务数据必须落库
3. 归还结算放在归还事件到达时：归还 = 最终状态，结算只发生一次，通过订单状态机保证「一单一结」
4. 离线补偿用 MQ 重试 + 幂等消费：设备补传的事件可能重复，消费者按事件 ID 幂等去重
5. 押金冻结与退还走统一流水：所有押金变动都有流水记录，财务对账有据可查
```

用户扫码租借的完整链路：

```text
1. 用户扫柜机二维码，前端拿到 cabinetId 与柜机公钥，请求租借接口
2. 后端校验柜机在线、柜格有可用宝，按信用分评估免押或冻结押金
3. 校验通过后向柜机下发开锁指令（Netty/TCP），同时用 Redis 锁锁住目标柜格
4. 柜机开锁成功回传事件（MQ），消费者把柜格状态置为「待取」，生成租借订单
5. 用户取出充电宝，柜机上报「宝已取出」+ 电量，订单状态变为租借中
6. 租借中每 5 分钟计算一次展示费用（Redis 缓存，非权威）
7. 用户到任意柜机扫码归还，柜机检测空柜格，平台下发锁宝指令
8. 柜机确认锁宝成功回传归还事件，结算服务按规则算费、扣款、解冻押金
9. 订单状态变为已完成，用户收到账单推送，柜格状态更新为占用（宝在充电）
```

Redis Key 设计：

```text
cabinet:status:{cabinetId}      柜机在线状态（String：1在线 0离线，心跳续期 TTL 90 秒）
cabinet:slot:{cabinetId}        柜格状态（Hash：slotNo -> bankId/empty，实时占用）
bank:status:{bankId}            充电宝实时状态（Hash：battery/status/cabinetId/slotNo）
lock:cabinet:{cabinetId}        柜机操作锁（SETNX，防并发开宝/归还同一柜格）
order:rent:{orderNo}            租借订单缓存（Hash：status/borrowTime/bankId，结算提速）
rent:lock:{orderNo}             订单结算锁（SETNX，防归还事件重复结算）
pay:retry:{orderNo}             支付重试计数（INCR，代扣失败补偿）
deposit:lock:{userId}           押金操作锁（SETNX，防冻结/退还并发冲突）
recycle:queue:low-battery        低电量待回收任务队列（LIST，运维领取）
```

### 1. 设备服务：柜机心跳与状态维护

```java
@Service
public class CabinetService {

    @Autowired
    private StringRedisTemplate redisTemplate;
    @Autowired
    private CabinetMapper cabinetMapper;

    private static final long HEARTBEAT_TTL_SECONDS = 90;

    /**
     * 处理柜机心跳：更新在线状态 + 柜格占用快照
     * 心跳每 30 秒一次，TTL 90 秒，超过未上报自动判定离线
     */
    public void handleHeartbeat(Long cabinetId, Map<Integer, Long> slotBanks) {
        // 1. 在线状态（TTL 续期即在线）
        redisTemplate.opsForValue().set("cabinet:status:" + cabinetId,
                "1", HEARTBEAT_TTL_SECONDS, TimeUnit.SECONDS);

        // 2. 柜格占用快照：slotNo -> bankId（空柜格存 EMPTY）
        String slotKey = "cabinet:slot:" + cabinetId;
        Map<String, String> slotMap = new HashMap<>();
        slotBanks.forEach((slot, bankId) ->
                slotMap.put(String.valueOf(slot),
                        bankId == null ? "EMPTY" : String.valueOf(bankId)));
        redisTemplate.opsForHash().putAll(slotKey, slotMap);
        redisTemplate.expire(slotKey, 2, TimeUnit.HOURS);

        // 3. 心跳落库（低频，供在线率统计）
        Cabinet cabinet = cabinetMapper.selectById(cabinetId);
        if (cabinet != null && cabinet.getOnlineStatus() != 1) {
            cabinetMapper.updateOnlineStatus(cabinetId, 1);
        }
    }

    /**
     * 设备离线检测：心跳 TTL 过期即离线
     * 定时任务每 60 秒扫一遍 Redis 中在线的柜机，与数据库状态比对
     */
    @Scheduled(fixedDelay = 60_000)
    public void detectOfflineCabinets() {
        List<Cabinet> online = cabinetMapper.selectByOnlineStatus(1);
        for (Cabinet cabinet : online) {
            String key = "cabinet:status:" + cabinet.getId();
            if (!Boolean.TRUE.equals(redisTemplate.hasKey(key))) {
                // 心跳超时：置离线，同时把该柜机的在借宝标记为异常（无法归还）
                cabinetMapper.updateOnlineStatus(cabinet.getId(), 0);
                log.warn("柜机心跳超时离线: {}", cabinet.getCabinetNo());
                // 通知运维：该柜机上的租借订单引导用户去其他网点归还
                notifyOps(cabinet.getId(), "柜机离线");
            }
        }
    }

    /** 柜格操作分布式锁：开宝/归还前获取，防止并发操作同一柜格 */
    public boolean tryLockSlot(Long cabinetId, int slotNo, long timeoutMs) {
        String lockKey = "lock:cabinet:" + cabinetId;
        Boolean ok = redisTemplate.opsForValue()
                .setIfAbsent(lockKey, String.valueOf(slotNo), timeoutMs, TimeUnit.MILLISECONDS);
        return Boolean.TRUE.equals(ok);
    }

    public void unlockSlot(Long cabinetId) {
        redisTemplate.delete("lock:cabinet:" + cabinetId);
    }
}
```

### 2. 租借服务：扫码开宝与订单创建（状态机入口）

```java
@Service
public class RentService {

    @Autowired
    private CabinetService cabinetService;
    @Autowired
    private RentOrderMapper rentOrderMapper;
    @Autowired
    private PowerBankMapper powerBankMapper;
    @Autowired
    private StringRedisTemplate redisTemplate;

    /**
     * 扫码租借：校验柜机/柜格 -> 免押判定 -> 下发开锁指令
     * 开锁结果由设备回传事件异步确认（见事件消费者）
     */
    public RentResult rent(Long userId, Long cabinetId) {
        // 1. 柜机在线校验
        String online = redisTemplate.opsForValue().get("cabinet:status:" + cabinetId);
        if (!"1".equals(online)) {
            throw new BizException("该柜机离线，请更换网点");
        }
        // 2. 找电量最高的可用宝（从柜格 Hash 反查）
        String slotKey = "cabinet:slot:" + cabinetId;
        Map<Object, Object> slots = redisTemplate.opsForHash().entries(slotKey);
        Long bestBankId = null;
        int bestBattery = -1;
        for (Object v : slots.values()) {
            if ("EMPTY".equals(v)) continue;
            Long bankId = Long.valueOf(String.valueOf(v));
            Integer battery = getBattery(bankId);
            if (battery != null && battery > bestBattery) {
                bestBattery = battery;
                bestBankId = bankId;
            }
        }
        if (bestBankId == null) {
            throw new BizException("该柜机暂无可用充电宝");
        }
        // 3. 柜格锁（开锁期间禁止其他操作）
        int slotNo = findSlotNo(slots, bestBankId);
        if (!cabinetService.tryLockSlot(cabinetId, slotNo, 30_000)) {
            throw new BizException("柜格操作中，请稍后再试");
        }
        try {
            // 4. 免押判定：信用分 >= 550 免押，否则冻结押金
            User user = userMapper.selectById(userId);
            boolean depositFree = user.getCreditScore() != null
                    && user.getCreditScore() >= 550;
            if (!depositFree) {
                depositService.freeze(userId, chargeRule.getDeposit(), "租借押金");
            }
            // 5. 下发开锁指令（Netty 通道，省略底层）
            boolean sent = IotChannel.sendOpenCommand(cabinetId, slotNo, bestBankId);
            if (!sent) {
                cabinetService.unlockSlot(cabinetId);
                throw new BizException("开锁指令下发失败");
            }
            // 6. 预创建订单（状态=租借中，等设备确认取出后正式生效）
            RentOrder order = new RentOrder();
            order.setOrderNo(genOrderNo());
            order.setUserId(userId);
            order.setBankId(bestBankId);
            order.setBorrowCabinetId(cabinetId);
            order.setBorrowTime(new Date());
            order.setStatus(0); // 租借中
            rentOrderMapper.insert(order);
            // 缓存订单上下文，设备回传事件按 orderNo 找到订单
            cacheOrderContext(order);
            return new RentResult(order.getOrderNo(), slotNo, depositFree);
        } catch (Exception e) {
            cabinetService.unlockSlot(cabinetId);
            throw e;
        }
    }

    /** 设备回传「宝已取出」：确认订单生效，更新宝状态为租借中 */
    public void confirmTaken(String orderNo, Long bankId) {
        RentOrder order = rentOrderMapper.selectByOrderNo(orderNo);
        if (order == null || order.getStatus() != 0) {
            return; // 幂等：已确认过直接忽略
        }
        // 更新充电宝状态：在柜可借 -> 租借中
        powerBankMapper.casUpdateStatus(bankId, 1, 2);
        redisTemplate.opsForHash().put("bank:status:" + bankId, "status", "2");
        // 柜格置空
        cabinetService.markSlotEmpty(order.getBorrowCabinetId(), order.getSlotNo());
    }
}
```

### 3. 归还结算服务：归还时算费（核心）

```java
@Service
public class ReturnSettleService {

    @Autowired
    private RentOrderMapper rentOrderMapper;
    @Autowired
    private ChargeRuleMapper chargeRuleMapper;
    @Autowired
    private StringRedisTemplate redisTemplate;

    /**
     * 归还结算：柜机确认锁宝后触发，只结算一次
     * 计费公式：max(0, 使用分钟 - 免费分钟) / 60 * 单价，再与封顶取小
     */
    @Transactional(rollbackFor = Exception.class)
    public SettleResult settle(String orderNo, Long returnCabinetId,
                               Long bankId, LocalDateTime returnTime) {
        // 结算锁：归还事件可能重复到达（设备补传），保证一单一结
        String lockKey = "rent:lock:" + orderNo;
        Boolean locked = redisTemplate.opsForValue()
                .setIfAbsent(lockKey, "1", 60, TimeUnit.SECONDS);
        if (!Boolean.TRUE.equals(locked)) {
            throw new BizException("订单结算中，请稍后");
        }
        try {
            RentOrder order = rentOrderMapper.selectByOrderNo(orderNo);
            // 幂等：已结算过的订单直接返回原结果
            if (order.getStatus() == 2) {
                return SettleResult.alreadySettled(order.getActualPay());
            }
            // 1. 计算使用时长（分钟，向上取整到分钟）
            long minutes = Duration.between(
                    order.getBorrowTime().toLocalDateTime(), returnTime).toMinutes();
            minutes = Math.max(1, minutes); // 不足 1 分钟按 1 分钟
            order.setReturnTime(Timestamp.valueOf(returnTime));
            order.setReturnCabinetId(returnCabinetId);
            order.setTotalMinutes((int) minutes);

            // 2. 按规则算费：免费时长扣除 + 封顶
            ChargeRule rule = chargeRuleMapper.selectByCityAndBrand(
                    order.getCityCode(), order.getBrand());
            int billableMinutes = Math.max(0, (int) minutes - rule.getFreeMinutes());
            BigDecimal hours = BigDecimal.valueOf(billableMinutes)
                    .divide(BigDecimal.valueOf(60), 2, RoundingMode.CEILING);
            BigDecimal amount = hours.multiply(rule.getUnitPrice());
            // 封顶保护：按自然日封顶，跨天累加（此处简化为单次封顶）
            amount = amount.min(rule.getDailyCap()).setScale(2, RoundingMode.HALF_UP);
            order.setAmount(amount);
            order.setActualPay(amount);
            order.setStatus(1); // 已归还待支付

            // 3. 状态机推进 + 落库（CAS 防并发）
            int updated = rentOrderMapper.casSettle(orderNo, amount, returnTime,
                    returnCabinetId, (int) minutes);
            if (updated != 1) {
                throw new BizException("订单状态异常，请联系客服");
            }
            // 4. 自动扣款（免密代扣），失败进入补扣队列
            boolean payOk = payService.deduct(order.getUserId(), orderNo, amount);
            if (payOk) {
                rentOrderMapper.updateStatus(orderNo, 2); // 已支付
            } else {
                mqSender.sendDelay("pay.retry", orderNo, 5, TimeUnit.MINUTES);
            }
            // 5. 更新宝状态：租借中 -> 在柜可借，柜格占用
            powerBankMapper.casUpdateStatus(bankId, 2, 1);
            cabinetService.markSlotOccupied(returnCabinetId, bankId, order.getSlotNo());
            return SettleResult.success(amount);
        } finally {
            redisTemplate.delete(lockKey);
        }
    }
}
```

```java
        Map<Object, Object> ctx = redisTemplate.opsForHash().entries(cacheKey);

                order.getCityCode(), order.getBrand());

        BigDecimal amount = BigDecimal.valueOf(billable)

                .min(rule.getDailyCap());
```

### 5. 押金服务：冻结与退还

```java
@Service
public class DepositService {

    @Autowired
    private DepositRecordMapper depositRecordMapper;
    @Autowired
    private UserMapper userMapper;
    @Autowired
    private StringRedisTemplate redisTemplate;

    /**
     * 冻结押金：租借开宝时调用
     * 押金操作加用户级锁，防止并发订单同时动押金
     */
    @Transactional(rollbackFor = Exception.class)
    public void freeze(Long userId, BigDecimal amount, String orderNo) {
        String lockKey = "deposit:lock:" + userId;
        Boolean locked = redisTemplate.opsForValue()
                .setIfAbsent(lockKey, "1", 10, TimeUnit.SECONDS);
        if (!Boolean.TRUE.equals(locked)) {
            throw new BizException("押金操作中，请稍后再试");
        }
        try {
            User user = userMapper.selectById(userId);
            if (user.getDepositFree() == 1) {
                return; // 免押用户不冻结
            }
            // 冻结：从支付渠道扣款到平台押金账户（此处简化为余额扣减 + 流水）
            int updated = userMapper.deductBalance(userId, amount);
            if (updated != 1) {
                throw new BizException("余额不足，无法冻结押金");
            }
            DepositRecord record = new DepositRecord();
            record.setUserId(userId);
            record.setOrderNo(orderNo);
            record.setBizType("freeze");
            record.setAmount(amount.negate());
            record.setRemark("租借押金冻结");
            depositRecordMapper.insert(record);
        } finally {
            redisTemplate.delete(lockKey);
        }
    }

    /**
     * 退还押金：归还结算成功后自动触发
     * 有欠费/赔付时先扣减再退还余额
     */
    @Transactional(rollbackFor = Exception.class)
    public void refund(Long userId, String orderNo, BigDecimal deductAmount) {
        String lockKey = "deposit:lock:" + userId;
        Boolean locked = redisTemplate.opsForValue()
                .setIfAbsent(lockKey, "1", 10, TimeUnit.SECONDS);
        if (!Boolean.TRUE.equals(locked)) {
            throw new BizException("押金操作中，请稍后再试");
        }
        try {
            // 1. 查该用户押金余额（未退还的冻结总额）
            BigDecimal frozen = depositRecordMapper.sumByType(userId, "freeze")
                    .subtract(depositRecordMapper.sumByType(userId, "refund"))
                    .subtract(depositRecordMapper.sumByType(userId, "deduct"));
            if (frozen.compareTo(BigDecimal.ZERO) <= 0) {
                return; // 无押金可退
            }
            // 2. 有赔付扣减：先记扣罚流水，再退余额
            if (deductAmount != null && deductAmount.compareTo(BigDecimal.ZERO) > 0) {
                DepositRecord deduct = new DepositRecord();
                deduct.setUserId(userId);
                deduct.setOrderNo(orderNo);
                deduct.setBizType("deduct");
                deduct.setAmount(deductAmount.negate());
                deduct.setRemark("逾期/丢宝扣罚");
                depositRecordMapper.insert(deduct);
                frozen = frozen.subtract(deductAmount);
            }
            if (frozen.compareTo(BigDecimal.ZERO) <= 0) {
                return;
            }
            // 3. 原路退回（此处简化为余额加回 + 流水）
            userMapper.addBalance(userId, frozen);
            DepositRecord record = new DepositRecord();
            record.setUserId(userId);
            record.setOrderNo(orderNo);
            record.setBizType("refund");
            record.setAmount(frozen);
            record.setRemark("押金退还");
            depositRecordMapper.insert(record);
            log.info("押金退还成功 userId={} amount={}", userId, frozen);
        } finally {
            redisTemplate.delete(lockKey);
        }
    }
}
```

```java
@Component
public class DeviceEventConsumer {

    @Autowired
    private RentService rentService;
    @Autowired
    private ReturnSettleService returnSettleService;
    @Autowired
    private CabinetService cabinetService;
    @Autowired
    private StringRedisTemplate redisTemplate;

    /**
     * 消费设备事件（开锁结果/取出确认/归还确认）
     * 设备离线补传会产生重复事件，按事件 ID 幂等去重
     */
    @RabbitListener(queues = "device.event")
    public void onDeviceEvent(DeviceEvent event) {
        // 1. 幂等去重：同一事件 ID 只处理一次（SETNX，TTL 24h）
        String dedupKey = "device:event:" + event.getEventId();
        Boolean first = redisTemplate.opsForValue()
                .setIfAbsent(dedupKey, "1", 24, TimeUnit.HOURS);
        if (!Boolean.TRUE.equals(first)) {
            log.info("重复事件忽略: {}", event.getEventId());
            return;
        }
        switch (event.getType()) {
            case "TAKEN":      // 宝已取出：订单正式生效
                rentService.confirmTaken(event.getOrderNo(), event.getBankId());
                break;
            case "RETURNED":   // 归还锁宝成功：触发结算
                returnSettleService.settle(event.getOrderNo(),
                        event.getCabinetId(), event.getBankId(), event.getEventTime());
                break;
            case "HEARTBEAT":  // 心跳
                cabinetService.handleHeartbeat(event.getCabinetId(), event.getSlotBanks());
                break;
            default:
                log.warn("未知事件类型: {}", event.getType());
        }
    }

    /**
     * 归还事件消费失败重试：失败消息进入延迟队列，5 分钟后重试
     * 超过 3 次仍失败转人工工单
     */
    @RabbitListener(queues = "device.event.retry")
    public void onRetry(DeviceEvent event) {
        String countKey = "retry:count:" + event.getEventId();
        Long count = redisTemplate.opsForValue().increment(countKey);
        if (count != null && count <= 3) {
            try {
                onDeviceEvent(event);
            } catch (Exception e) {
                log.error("重试仍失败: {}", event.getEventId(), e);
            }
        } else {
            // 超过 3 次：转人工工单，运维线下核实柜格状态
            createManualTicket(event, "设备事件多次处理失败");
        }
    }
}
```

```java
@Service
public class RecycleScheduler {

    @Autowired
    private PowerBankMapper powerBankMapper;
    @Autowired
    private RentOrderMapper rentOrderMapper;
    @Autowired
    private StringRedisTemplate redisTemplate;

    /**
     * 低电量回收：扫描电量低于 20% 的在柜宝，生成回收任务
     * 运维领取任务后取走充电，充满后重新投放
     */
    @Scheduled(fixedDelay = 10 * 60_000)
    public void scanLowBattery() {
        List<PowerBank> lowBanks = powerBankMapper.selectByBatteryLessThan(20);
        for (PowerBank bank : lowBanks) {
            if (bank.getStatus() != 1) {
                continue; // 只回收在柜可借的宝
            }
            // 状态：在柜可借 -> 待回收
            int updated = powerBankMapper.casUpdateStatus(bank.getId(), 1, 3);
            if (updated == 1) {
                // 入回收队列，运维 App 领取
                String task = bank.getId() + ":" + bank.getCabinetId() + ":" + bank.getSlotNo();
                redisTemplate.opsForList()
                        .rightPush("recycle:queue:low-battery", task);
                log.info("低电量宝入回收队列 bankId={} battery={}%", bank.getId(), bank.getBattery());
            }
        }
    }

    /**
     * 逾期扫描：租借超过免费时长 N 天未归还，判定丢宝
     * 逾期订单：按押金赔付 + 订单置为丢宝状态
     */
    @Scheduled(cron = "0 30 2 * * ?") // 每天凌晨 2:30
    public void scanOverdueOrders() {
        // 逾期阈值：租借中且超过 3 天未归还
        LocalDateTime threshold = LocalDateTime.now().minusDays(3);
        List<RentOrder> overdue = rentOrderMapper.selectOverdue(threshold);
        for (RentOrder order : overdue) {
            // 1. 订单状态：租借中 -> 丢宝赔付
            rentOrderMapper.casUpdateStatus(order.getOrderNo(), 0, 4);
            // 2. 扣罚押金（全扣），剩余退还
            ChargeRule rule = chargeRuleMapper.selectByCityAndBrand(
                    order.getCityCode(), order.getBrand());
            depositService.refund(order.getUserId(), order.getOrderNo(), rule.getDeposit());
            // 3. 通知用户：补缴费用或归还后申请恢复
            notifyUser(order.getUserId(), "充电宝逾期未归还，已按丢宝处理");
        }
    }
}
```

## 实际应用场景

### 场景一：商场扫码租借全流程

用户在商场借充电宝的完整链路：

```text
1. 用户扫柜机二维码，前端请求租借接口，携带 cabinetId
2. 后端校验柜机在线（Redis 心跳标记），从柜格 Hash 选出电量最高的宝（87%）
3. 信用分 620 免押，跳过押金冻结；开锁指令下发柜机，柜格加锁
4. 柜机开锁成功回传 TAKEN 事件，MQ 消费者确认订单生效，订单状态=租借中
5. 用户取走充电宝，柜机上报电量与取出状态，柜格置空
6. 用户手机端看到订单：已用 35 分钟，实时费用 1.5 元（免费时长 5 分钟已扣）
7. 2 小时后用户到另一商场扫码归还，柜机检测空柜格，平台下发锁宝指令
8. 柜机确认锁宝回传 RETURNED 事件，结算服务算费：115 分钟 - 5 免费 = 110 分钟，1.83 小时 * 3 元 = 5.5 元（未超封顶）
9. 自动扣款成功，订单状态=已支付，账单推送用户，柜格状态更新为占用（宝在充电）
```

### 场景二：柜机离线导致的事件补偿

柜机断网后恢复，事件补传的一致性保障：

```text
1. 柜机 A 断网 20 分钟，期间用户扫码借走一个宝（柜机本地记录事件）
2. 平台设备离线检测任务发现柜机 A 心跳超时，置为离线，通知运维
3. 用户无法在该柜机归还，引导页展示附近 500 米内其他在线柜机
4. 柜机 A 网络恢复，心跳续期重新上线，同时补传断网期间 3 条事件
5. 补传事件进入 MQ，消费者按事件 ID 幂等去重，逐条处理
6. 其中「宝已取出」事件补确认了租借订单，订单计费从真实取出时间起算
7. 归还事件正常消费，结算正确，用户账单无异常
8. 对账任务核对设备事件与订单记录，全部对上，无脏数据
```

### 场景三：低电量回收与丢宝赔付

资产周转与异常订单处理：

```text
1. 定时任务每 10 分钟扫描电量 < 20% 的在柜宝，共发现 15 台
2. 15 台宝状态置为待回收，进入回收队列，运维 App 显示任务列表
3. 运维领取任务，到柜机取出低电量宝，充满后重新投放（状态回在柜可借）
4. 用户小李的宝借出 5 天未归还，逾期扫描任务命中该订单
5. 订单状态置为丢宝赔付，押金 99 元全额扣罚，流水记录扣罚明细
6. 剩余押金 0 元无需退还，通知用户补缴费用或归还宝后申请恢复
7. 若押金 99 元、应付费用 60 元：扣罚后剩余 39 元原路退还
8. 财务每日对账：押金流水 = 冻结 - 退还 - 扣罚，账实相符
```

## 最佳实践与踩坑记录

### 最佳实践

1. 归还结算只发生在归还事件到达时：归还即终态，通过订单结算锁 + 状态 CAS 保证「一单一结」，设备重复上报事件被幂等拦截
2. 设备事件全走 MQ + 事件 ID 幂等：心跳/开锁/归还都是高频异步事件，消费者按事件 ID SETNX 去重，设备离线补传的重复事件不会造成重复结算
3. 实时状态与账务数据分离：柜格占用、电量放 Redis 支撑高频读写；订单、押金流水放 MySQL 保证账务可靠，两者用事件驱动保持一致
4. 押金操作全部走流水 + 用户级锁：冻结/退还/扣罚都有 deposit_record 留痕，用户级分布式锁防止并发订单同时动押金
5. 离线检测靠心跳 TTL 而非显式下线：柜机 30 秒心跳 + 90 秒 TTL，超时自动判定离线，比依赖设备主动下线通知可靠得多
6. 封顶与免费时长参数化：计费规则按城市/品牌入库配置，运营可调；实时展示费用标注「仅供参考」，权威金额只在归还结算时生成
7. 扣款失败走延迟重试队列：代扣失败后进 MQ 延迟队列（5 分钟后重试），超 3 次转人工，避免静默丢单
8. 低电量回收与逾期扫描做成独立定时任务：资产运营与风险控制不阻塞主交易链路，扫描结果进队列由运维人工闭环

### 踩坑记录

```text
坑 1：归还事件重复消费导致重复扣款
结论：柜机网络抖动补传归还事件，用户被扣了两次钱。
原因：消费者没有幂等处理，同一事件被处理两遍。
解法：事件带全局唯一 eventId，消费前 SETNX 去重；订单结算加 Redis 锁 + 状态 CAS，已结算订单直接返回原结果。

坑 2：开锁成功但用户没取宝
结论：柜格显示占用，实际柜门开着没人拿，宝被下一位用户取走。
原因：开锁指令与取出确认之间没有超时处理。
解法：开锁后 60 秒未收到 TAKEN 事件自动关单，柜格恢复可借；取出确认与开锁事件做关联校验。

坑 3：设备离线期间订单状态与实物不一致
结论：柜机断网时用户还了宝，但线上订单一直显示租借中，用户被持续计费。
原因：归还事件丢失，没有补偿机制。
解法：心跳 TTL 判定离线 + 断网期间事件本地缓存恢复后补传；补传事件幂等重放，计费按真实归还时间（设备时钟）起算。

坑 4：计费与封顶跨天理解错误
结论：用户租了 3 天，按「单次封顶」只收 20 元，平台亏了。
原因：每日封顶被实现成整单封顶。
解法：封顶按自然日分段计算，跨天订单每天单独封顶再累加；规则配置里明确 daily_cap 的统计口径。

坑 5：押金退还与欠费扣款并发
结论：用户同时还了 A 单（有欠费）和 B 单（押金退还），押金被退了两次。
原因：押金退还没有用户级锁，两个订单并发操作同一押金余额。
解法：押金操作加用户级分布式锁（deposit:lock:{userId}），冻结/退还/扣罚串行执行，全部留流水。

坑 6：电量上报频率过高打爆接口
结论：柜机每 5 秒上报一次电量，高峰 10 万台设备把接入层压垮。
原因：实时电量不需要这么高的频率。
解法：电量上报合并进 30 秒心跳，Redis 内存态实时更新，落库节流到 5 分钟一次。

坑 7：柜格并发操作（两人同时扫码同一柜格）
结论：两个用户同时扫同一个柜格，都收到开锁成功，宝被抢。
原因：柜格操作没有互斥。
解法：开锁前对柜机加分布式锁（lock:cabinet:{cabinetId}），锁内完成选格-下发-预占，超时自动释放。

坑 8：支付回调与归还结算顺序颠倒
结论：支付回调先到，订单还是待支付状态，回调被当成无效请求丢弃，用户钱扣了订单却没更新。
原因：异步回调与本地结算无顺序保证。
解法：支付回调做成「事件驱动最终一致」：回调只更新支付状态并记录流水，订单状态由结算流程统一推进，两边按 orderNo 对账兜底。
```

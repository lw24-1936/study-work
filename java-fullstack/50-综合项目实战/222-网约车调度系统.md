## 项目背景

网约车调度系统（Ride-Hailing Dispatch System）是出行行业的核心业务系统：乘客发起叫车请求后，系统要在几秒内从成千上万个在线司机中找到合适的车（就近、评分高、负载均衡），通知司机接单，再全程跟踪行程状态直至支付完成。调度的本质是「匹配」——把乘客的即时出行需求与司机的供给能力在时空维度上快速撮合。传统出租车靠电话叫车、路边招手，供需信息完全割裂；网约车把「人找车」变成「系统派车」，靠实时位置（Redis GEO）与订单匹配算法把空驶率降到最低。这个项目覆盖了实时位置计算、订单状态机、动态计价、实时推送（WebSocket）四大硬核模块，是学习高并发实时业务的最佳载体之一。

业务痛点：

```text
1. 供需匹配慢：乘客叫车后靠人工派单或司机盲抢，响应要几分钟，乘客大量流失
2. 位置数据分散：司机位置散落在各端上报，没有统一的地理索引，查最近司机要全表扫描
3. 派单不公平：派单只看距离，高分司机接不到单、低分司机抢走好单，司机满意度低
4. 计价混乱：高峰期/恶劣天气没有调价机制，运力流失，乘客打不到车
5. 行程状态靠人工：接驾/到达/支付全靠电话确认，状态错乱，纠纷无据可查
6. 实时性差：乘客看不到司机位置、司机收不到新单提醒，体验割裂
```

目标用户与核心诉求：

```text
1. 乘客：发起叫车后 3-5 秒内收到应答，实时看到司机位置与预计到达时间，行程透明
2. 司机：注册审核通过后上线接单，系统公平派单，计价规则清楚，收入可查
3. 平台运营：监控城市运力分布，设置动态调价策略，处理司乘纠纷（依据完整行程轨迹）
```

项目要解决的核心问题一句话概括：基于实时位置数据，在毫秒级完成「乘客需求 - 在线司机」的最优匹配，并用可靠的订单状态机与动态计价保证整个行程从叫车到支付的全流程闭环。

## 功能介绍

功能按角色与模块拆分：乘客端（叫车）、司机端（接单）、调度引擎（匹配）、订单履约（行程）、平台治理（规则与评价）。

```text
一、乘客端（C 端用户）
1. 一键叫车 —— 选择起点终点（地图选点/常用地址），预估价格与等待时间
2. 实时追踪 —— 行程中实时查看司机位置、预计到达时间（WebSocket 推送）
3. 行程支付 —— 到达后自动结算，支持余额/微信/支付宝，行程单明细可查
4. 司乘互评 —— 行程结束后对司机打分（服务/驾驶/车内环境），可追加文字评价
5. 行程管理 —— 历史行程、发票申请、紧急求助（行程分享给紧急联系人）

二、司机端（供给方）
1. 入驻注册 —— 提交身份证/驾驶证/行驶证/车辆信息，等待平台审核
2. 在线接单 —— 一键上线/下线，上线后位置实时上报（GPS + 基站兜底）
3. 接单方式 —— 平台派单（强制接单/可拒绝）+ 抢单大厅（订单广播，先到先得）
4. 行程操作 —— 接驾/到达上车点/开始行程/到达目的地，全程按钮驱动
5. 收入中心 —— 订单流水、计价明细（里程费/时长费/动态调价溢价）、提现

三、调度引擎（平台核心）
1. 就近匹配 —— Redis GEO 在司机位置集合中检索起点周边 N 公里内的在线司机
2. 派单策略 —— 距离权重 + 司机评分权重 + 负载均衡（当日单量/拒单率），综合打分选最优
3. 抢单广播 —— 订单进入候选司机可见池，先到先得，Redis 锁保证原子性
4. 动态调价 —— 按供需比（周边订单数/在线司机数）计算动态溢价系数
5. 运力监控 —— 城市/区域在线司机热力图，供运营干预派单

四、订单履约（行程状态机）
1. 状态流转 —— 待接单 -> 已派单 -> 司机接驾 -> 已到达 -> 行程中 -> 待支付 -> 已完成/已取消
2. 超时机制 —— 派单超时自动扩大范围重派，司机接驾超时自动取消并赔付
3. 位置追踪 —— 行程中司机位置每 3-5 秒上报，Redis GEO 存储 + WebSocket 推给乘客
4. 支付结算 —— 行程结束按计价规则算费，生成账单，司机端展示分成明细

五、平台治理（运营/管理端）
1. 司机审核 —— 资料人工/OCR 审核，准入名单管理，黑名单封禁
2. 计价规则配置 —— 基础价/里程单价/时长单价/夜间加价/动态调价上下限
3. 评价体系 —— 评分聚合（近 100 单均值），低分司机降权（派单权重下调）
4. 纠纷仲裁 —— 完整行程轨迹回放（轨迹点+时间线），作为客诉判定依据
```

## 技术选型

| 组件 | 选型 | 理由 |
|------|------|------|
| 开发框架 | Spring Boot 2.7/3.x | 生态成熟，微服务友好，快速搭建 |
| 持久层 | MyBatis-Plus | 单表 CRUD 零 SQL，订单复杂查询走 XML |
| 数据库 | MySQL 8.0 | 司机/乘客/订单/评价等核心业务数据 |
| 位置索引 | Redis 6.2+（GEO） | GEOSEARCH 毫秒级就近检索，替代 MySQL 经纬度全表扫描 |
| 缓存/锁 | Redis（String/Hash/SETNX） | 在线状态、派单锁、订单上下文缓存 |
| 地图服务 | 高德地图 Web 服务 API / 腾讯位置服务 | 路线规划、距离矩阵、逆地理编码、POI 搜索 |
| 实时推送 | Spring WebSocket / Netty | 司机位置推送、新订单提醒、状态变更通知 |
| 认证鉴权 | JWT | 乘客端/司机端无状态鉴权，网关统一校验 |
| 定时任务 | Spring @Scheduled / XXL-Job | 派单超时扫描、离线司机清理、每日结算 |
| 构建 | Maven | 依赖管理标准工具 |

选型说明：

```text
1. 位置索引用 Redis GEO 而非 MySQL：司机位置每秒级更新，MySQL 经纬度索引在千万级点位上查询是秒级，Redis GEOADD + GEOSEARCH 是毫秒级，且天然支持半径检索与距离排序
2. 位置上报只写 Redis，不落库：实时位置是「瞬时状态」，持久化用低频快照（每 30 秒批量写 driver_location 表）做轨迹回放，避免高频写库
3. 地图服务走服务端 API：前端只传坐标，路线规划/距离矩阵/ETA 计算全部由后端调用高德/腾讯 Web 服务 API 完成，防止 Key 泄露
4. 派单的原子性靠 Redis 锁：多实例部署下同一订单可能被并发派给多个司机，用订单级 SETNX 锁保证「一单一司机」
5. 实时推送用 WebSocket：司机位置变化、订单状态变化都是服务端主动事件，HTTP 轮询延迟高且浪费资源
```

乘客叫车到接单的完整链路：

```text
1. 乘客 App 选起点终点，前端调高德 JS API 选点，向后端发起叫车请求（含起终点坐标）
2. 后端生成订单（状态=待派单），调地图服务估算里程与时长，按计价规则算预估价格
3. 调度引擎以起点坐标为中心，GEOSEARCH 检索周边 5 公里内「在线且可接单」的司机
4. 候选司机按「距离权重 + 评分权重 + 当日单量」综合打分排序，取前 N 名进入派单池
5. 派单：向得分最高的司机推送新单通知（WebSocket），司机 15 秒内未响应则顺延下一名
6. 司机点击接单，Redis 派单锁校验订单仍未被接，成功后订单状态变为已派单
7. 司机按导航接驾，到达上车点点击「已到达」，乘客上车后司机点「开始行程」
8. 行程中司机位置每 3 秒上报 Redis GEO，WebSocket 实时推送给乘客地图
9. 到达目的地，司机点「到达」，系统按计价规则结算生成账单，乘客支付
10. 支付完成后双方互评，订单结束，调度引擎把司机重新放入可接单池
```

## 数据库设计

核心表设计（7 张表）：

```sql
-- 司机表（注册信息 + 审核状态 + 服务状态）
CREATE TABLE `driver` (
  `id`           BIGINT       NOT NULL AUTO_INCREMENT,
  `phone`        VARCHAR(20)  NOT NULL COMMENT '手机号（登录账号）',
  `name`         VARCHAR(50)  NOT NULL COMMENT '司机姓名',
  `id_card_no`   VARCHAR(30)  DEFAULT NULL COMMENT '身份证号（脱敏存储）',
  `license_no`   VARCHAR(30)  DEFAULT NULL COMMENT '驾驶证号',
  `vehicle_no`   VARCHAR(20)  DEFAULT NULL COMMENT '车牌号',
  `vehicle_type` VARCHAR(20)  DEFAULT NULL COMMENT '车型：快车/专车/顺风车',
  `audit_status` TINYINT      NOT NULL DEFAULT 0 COMMENT '审核状态：0待审核 1通过 2驳回 3封禁',
  `online_status` TINYINT     NOT NULL DEFAULT 0 COMMENT '在线状态：0离线 1在线 2接单中 3休息',
  `score`        DECIMAL(3,2) NOT NULL DEFAULT 5.00 COMMENT '服务评分（0-5，近100单均值）',
  `total_orders` INT          NOT NULL DEFAULT 0 COMMENT '累计完成订单数',
  `today_orders` INT          NOT NULL DEFAULT 0 COMMENT '当日已完成订单数（负载均衡用）',
  `reject_count` INT          NOT NULL DEFAULT 0 COMMENT '当日拒单次数',
  `city_code`    VARCHAR(10)  NOT NULL COMMENT '服务城市编码',
  `create_time`  DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `update_time`  DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_phone` (`phone`),
  KEY `idx_city_status` (`city_code`, `online_status`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='司机表';

-- 乘客表
CREATE TABLE `passenger` (
  `id`           BIGINT       NOT NULL AUTO_INCREMENT,
  `phone`        VARCHAR(20)  NOT NULL COMMENT '手机号（登录账号）',
  `nickname`     VARCHAR(50)  DEFAULT NULL COMMENT '昵称',
  `score`        DECIMAL(3,2) NOT NULL DEFAULT 5.00 COMMENT '乘客评分',
  `total_orders` INT          NOT NULL DEFAULT 0 COMMENT '累计下单数',
  `status`       TINYINT      NOT NULL DEFAULT 1 COMMENT '账号状态：1正常 0冻结',
  `create_time`  DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_phone` (`phone`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='乘客表';

-- 订单表（行程全生命周期）
CREATE TABLE `trip_order` (
  `id`             BIGINT       NOT NULL AUTO_INCREMENT,
  `order_no`       VARCHAR(32)  NOT NULL COMMENT '订单号（业务唯一）',
  `passenger_id`   BIGINT       NOT NULL COMMENT '乘客 id',
  `driver_id`      BIGINT       DEFAULT NULL COMMENT '司机 id（派单后写入）',
  `start_lng`      DECIMAL(10,6) NOT NULL COMMENT '起点经度',
  `start_lat`      DECIMAL(10,6) NOT NULL COMMENT '起点纬度',
  `start_addr`     VARCHAR(200) DEFAULT NULL COMMENT '起点地址描述',
  `end_lng`        DECIMAL(10,6) NOT NULL COMMENT '终点经度',
  `end_lat`        DECIMAL(10,6) NOT NULL COMMENT '终点纬度',
  `end_addr`       VARCHAR(200) DEFAULT NULL COMMENT '终点地址描述',
  `estimate_amount` DECIMAL(10,2) DEFAULT NULL COMMENT '预估金额',
  `actual_amount`  DECIMAL(10,2) DEFAULT NULL COMMENT '实际金额（行程结束结算）',
  `price_factor`   DECIMAL(3,2) NOT NULL DEFAULT 1.00 COMMENT '动态调价系数（下单时快照）',
  `distance_km`    DECIMAL(6,2) DEFAULT NULL COMMENT '实际里程（公里）',
  `duration_min`   INT          DEFAULT NULL COMMENT '实际时长（分钟）',
  `status`         TINYINT      NOT NULL DEFAULT 0 COMMENT '状态：0待派单 1已派单 2接驾中 3已到达 4行程中 5待支付 6已完成 7已取消',
  `cancel_reason`  VARCHAR(200) DEFAULT NULL COMMENT '取消原因',
  `pay_time`       DATETIME     DEFAULT NULL COMMENT '支付时间',
  `create_time`    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `update_time`    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_order_no` (`order_no`),
  KEY `idx_passenger` (`passenger_id`, `create_time`),
  KEY `idx_driver` (`driver_id`, `create_time`),
  KEY `idx_status_time` (`status`, `create_time`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='行程订单表';

-- 司机位置快照表（低频落库，轨迹回放用）
CREATE TABLE `driver_location` (
  `id`          BIGINT        NOT NULL AUTO_INCREMENT,
  `driver_id`   BIGINT        NOT NULL COMMENT '司机 id',
  `lng`         DECIMAL(10,6) NOT NULL COMMENT '经度',
  `lat`         DECIMAL(10,6) NOT NULL COMMENT '纬度',
  `speed`       DECIMAL(5,1)  DEFAULT NULL COMMENT '速度（km/h）',
  `report_time` DATETIME      NOT NULL COMMENT '上报时间',
  PRIMARY KEY (`id`),
  KEY `idx_driver_time` (`driver_id`, `report_time`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='司机位置快照表';

-- 计价规则表（城市 + 车型维度）
CREATE TABLE `price_rule` (
  `id`             BIGINT       NOT NULL AUTO_INCREMENT,
  `city_code`      VARCHAR(10)  NOT NULL COMMENT '城市编码',
  `vehicle_type`   VARCHAR(20)  NOT NULL COMMENT '车型：快车/专车',
  `base_price`     DECIMAL(6,2) NOT NULL COMMENT '起步价',
  `base_distance`  DECIMAL(4,1) NOT NULL DEFAULT 3.0 COMMENT '起步里程（公里）',
  `per_km_price`   DECIMAL(6,2) NOT NULL COMMENT '每公里单价',
  `per_min_price`  DECIMAL(6,2) NOT NULL COMMENT '每分钟时长费',
  `night_surcharge` DECIMAL(3,2) NOT NULL DEFAULT 1.00 COMMENT '夜间加价系数（23-5点）',
  `factor_min`     DECIMAL(3,2) NOT NULL DEFAULT 1.00 COMMENT '动态调价下限',
  `factor_max`     DECIMAL(3,2) NOT NULL DEFAULT 2.50 COMMENT '动态调价上限',
  `status`         TINYINT      NOT NULL DEFAULT 1 COMMENT '1生效 0停用',
  `create_time`    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_city_type` (`city_code`, `vehicle_type`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='计价规则表';

-- 司乘互评表
CREATE TABLE `review` (
  `id`           BIGINT       NOT NULL AUTO_INCREMENT,
  `order_no`     VARCHAR(32)  NOT NULL COMMENT '订单号',
  `from_type`    TINYINT      NOT NULL COMMENT '评价方：1乘客 2司机',
  `from_id`      BIGINT       NOT NULL COMMENT '评价人 id',
  `to_id`        BIGINT       NOT NULL COMMENT '被评人 id',
  `score`        TINYINT      NOT NULL COMMENT '评分 1-5',
  `tags`         VARCHAR(200) DEFAULT NULL COMMENT '标签（态度好/准时/车内整洁）',
  `content`      VARCHAR(500) DEFAULT NULL COMMENT '文字评价',
  `create_time`  DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_order_from` (`order_no`, `from_type`),
  KEY `idx_to` (`to_id`, `create_time`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='司乘互评表';

-- 订单状态流转日志表（纠纷仲裁依据）
CREATE TABLE `order_event` (
  `id`          BIGINT       NOT NULL AUTO_INCREMENT,
  `order_no`    VARCHAR(32)  NOT NULL COMMENT '订单号',
  `from_status` TINYINT      DEFAULT NULL COMMENT '原状态',
  `to_status`   TINYINT      NOT NULL COMMENT '新状态',
  `operator`    VARCHAR(50)  DEFAULT NULL COMMENT '操作方：passenger/driver/system',
  `remark`      VARCHAR(200) DEFAULT NULL COMMENT '备注（如：派单超时重派）',

  KEY `idx_order` (`order_no`, `create_time`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='订单状态流转日志表';
```

Redis Key 设计：

```text
geo:driver:{cityCode}          司机实时位置 GEO 集合（GEOADD 上报，GEOSEARCH 就近检索）
driver:online:{driverId}       司机在线状态（String：1在线 0离线，TTL 30 秒续期）
driver:loc:{driverId}          司机最新位置快照（Hash：lng/lat/speed/ts，兜底查询）
order:ctx:{orderNo}            订单派单上下文（Hash：status/candidateList/expireTime/round）
order:dispatch:lock:{orderNo}  订单派单锁（SETNX，防多实例重复派单，TTL 30 秒）
dispatch:candidate:{orderNo}   候选司机列表（ZSET，按综合得分排序）
driver:load:{driverId}         司机当日负载（INCR 当日单量，负载均衡因子）
surge:ratio:{cityCode}:{areaKey}  区域供需比与动态调价系数（定时计算缓存）
```

### 1. 位置服务：司机位置上报与 GEO 就近检索

```java
@Service
public class GeoLocationService {

    @Autowired
    private StringRedisTemplate redisTemplate;
    @Autowired
    private DriverLocationMapper locationMapper;

    private static final double SEARCH_RADIUS_KM = 5.0;

    /**
     * 司机位置上报：写入 GEO + 快照 Hash
     * 上报频率 3-5 秒一次，只写 Redis，每 30 秒异步落库一次做轨迹
     */
    public void reportDriverLocation(Long driverId, double lng, double lat,
                                     double speed, String cityCode) {
        // 1. 写入 GEO 集合（key 按城市分片，控制单集合规模）
        String geoKey = "geo:driver:" + cityCode;
        redisTemplate.opsForGeo().add(geoKey,
                new Point(lng, lat), String.valueOf(driverId));

        // 2. 写入位置快照 Hash（供订单详情/客服查最新位置）
        String locKey = "driver:loc:" + driverId;
        Map<String, String> loc = new HashMap<>();
        loc.put("lng", String.valueOf(lng));
        loc.put("lat", String.valueOf(lat));
        loc.put("speed", String.valueOf(speed));
        loc.put("ts", String.valueOf(System.currentTimeMillis()));
        redisTemplate.opsForHash().putAll(locKey, loc);
        redisTemplate.expire(locKey, 10, TimeUnit.MINUTES);

        // 3. 每 30 秒落库一次（按秒取整做节流，轨迹回放用）
        long second = System.currentTimeMillis() / 1000;
        if (second % 30 == 0) {
            DriverLocation locEntity = new DriverLocation();
            locEntity.setDriverId(driverId);
            locEntity.setLng(new BigDecimal(String.valueOf(lng)));
            locEntity.setLat(new BigDecimal(String.valueOf(lat)));
            locEntity.setSpeed(new BigDecimal(String.valueOf(speed)));
            locEntity.setReportTime(new Date());
            locationMapper.insert(locEntity);
        }
    }

    /**
     * 就近检索：返回起点周边 radius 公里内的在线司机，按距离升序
     * 返回 List<DriverDistance>（driverId + 距离米数）
     */
    public List<DriverDistance> searchNearbyDrivers(double lng, double lat,
                                                    double radiusKm, String cityCode) {
        String geoKey = "geo:driver:" + cityCode;
        // GEOSEARCH 按圆心检索，WITHCOORD 可同时取坐标
        GeoResults<RedisGeoCommands.GeoLocation<String>> results =
                redisTemplate.opsForGeo().search(geoKey,
                        new Circle(new Point(lng, lat),
                                new Distance(radiusKm, RedisGeoCommands.DistanceUnit.KILOMETERS)),
                        RedisGeoCommands.GeoSearchCommandArgs.newGeoSearchArgs()
                                .includeDistance().sortAscending());

        List<DriverDistance> list = new ArrayList<>();
        if (results != null) {
            for (GeoResult<RedisGeoCommands.GeoLocation<String>> r : results.getContent()) {
                String driverId = r.getContent().getName();
                // 过滤掉「接单中/休息」的司机，只留在线可接单
                String online = redisTemplate.opsForValue().get("driver:online:" + driverId);
                if ("1".equals(online)) {
                    double meters = r.getDistance() != null ? r.getDistance().getValue() : 0;
                    list.add(new DriverDistance(Long.valueOf(driverId), meters));
                }
            }
        }
        return list;
    }

    /** 司机下线：从 GEO 删除位置，清除在线状态 */
    public void offline(Long driverId, String cityCode) {
        redisTemplate.opsForGeo().remove("geo:driver:" + cityCode, String.valueOf(driverId));
        redisTemplate.delete("driver:online:" + driverId);
    }

    /** 距离结果内部类 */
    @Data
    public static class DriverDistance {
        private final Long driverId;
        private final double distanceMeters;

        public DriverDistance(Long driverId, double distanceMeters) {
            this.driverId = driverId;
            this.distanceMeters = distanceMeters;
        }
    }
}
```

### 2. 调度引擎：就近匹配 + 综合评分派单

```java
@Service
public class DispatchService {

    @Autowired
    private GeoLocationService geoLocationService;
    @Autowired
    private DriverMapper driverMapper;
    @Autowired
    private StringRedisTemplate redisTemplate;

    private static final double BASE_RADIUS_KM = 3.0;   // 首轮派单半径
    private static final double MAX_RADIUS_KM = 8.0;    // 最大扩围半径
    private static final long DISPATCH_EXPIRE_MS = 30000; // 司机响应窗口 30 秒

    /**
     * 派单入口：就近匹配 + 综合打分 + 顺序派发
     * 1. 从小半径开始 GEOSEARCH 找候选
     * 2. 距离 + 评分 + 负载 加权打分
     * 3. 按得分逐个推送，司机响应窗口内未接则顺延下一名
     */
    public boolean dispatch(Long orderId, String orderNo, double lng, double lat,
                            String cityCode) {
        // 派单锁：防止多实例重复派单
        String lockKey = "order:dispatch:lock:" + orderNo;
        Boolean locked = redisTemplate.opsForValue()
                .setIfAbsent(lockKey, String.valueOf(orderId), 30, TimeUnit.SECONDS);
        if (!Boolean.TRUE.equals(locked)) {
            return false; // 其他实例正在派单
        }
        try {
            double radius = BASE_RADIUS_KM;
            while (radius <= MAX_RADIUS_KM) {
                // 1. GEO 就近检索候选司机
                List<GeoLocationService.DriverDistance> nearby =
                        geoLocationService.searchNearbyDrivers(lng, lat, radius, cityCode);
                if (nearby.isEmpty()) {
                    radius += 2.0; // 无候选则扩大范围
                    continue;
                }
                // 2. 综合打分：距离分 60% + 评分分 30% + 负载分 10%
                List<ScoredDriver> scored = scoreDrivers(nearby, cityCode);
                scored.sort(Comparator.comparingDouble(ScoredDriver::getScore).reversed());

                // 3. 顺序派发：每人 30 秒响应窗口，超时顺延下一名
                for (ScoredDriver driver : scored) {
                    if (pushOrderToDriver(orderNo, driver.getDriverId())) {
                        return true; // 司机已接单
                    }
                }
                radius += 2.0;
            }
            return false; // 全部司机无响应，订单转抢单池
        } finally {
            redisTemplate.delete(lockKey);
        }
    }

    /** 综合打分：距离越近分越高，评分越高分越高，当日单量越少分越高 */
    private List<ScoredDriver> scoreDrivers(
            List<GeoLocationService.DriverDistance> nearby, String cityCode) {
        List<ScoredDriver> result = new ArrayList<>();
        for (GeoLocationService.DriverDistance d : nearby) {
            Driver driver = driverMapper.selectById(d.getDriverId());
            if (driver == null || driver.getAuditStatus() != 1) {
                continue; // 审核未通过直接跳过
            }
            // 距离分：1 公里内 100 分，每远 1 公里扣 10 分
            double distanceScore = Math.max(0, 100 - d.getDistanceMeters() / 1000 * 10);
            // 评分分：4.8 分以上满分，每低 0.1 扣 5 分
            double scorePart = Math.max(0, (driver.getScore().doubleValue() - 3.0) / 2.0 * 100);
            // 负载分：当日 0 单 100 分，每多 1 单扣 5 分，最多扣到 0
            double loadScore = Math.max(0, 100 - driver.getTodayOrders() * 5);
            double total = distanceScore * 0.6 + scorePart * 0.3 + loadScore * 0.1;
            result.add(new ScoredDriver(driver.getId(), total));
        }
        return result;
    }

    /**
     * 推送订单给司机：WebSocket 下发新单通知，司机点接单后回调 confirmOrder
     * 这里只负责「尝试派发」，实际接单成功由 confirmOrder 确认
     */
    private boolean pushOrderToDriver(String orderNo, Long driverId) {
        // WebSocket 推送（省略连接管理细节），推送失败视为不可达
        boolean pushed = OrderWsPush.pushNewOrder(driverId, orderNo);
        if (!pushed) {
            return false;
        }
        // 等待司机响应：订单上下文里记录司机已收到，接单回调会 CAS 状态
        String ctxKey = "order:ctx:" + orderNo;
        redisTemplate.opsForHash().put(ctxKey, "currentDriver", String.valueOf(driverId));
        redisTemplate.expire(ctxKey, DISPATCH_EXPIRE_MS, TimeUnit.MILLISECONDS);
        return false; // 是否接单成功由 confirmOrder 返回
    }

    /** 司机确认接单：CAS 校验订单仍处于待派单，成功则锁定司机 */
    public boolean confirmOrder(Long driverId, String orderNo) {
        String ctxKey = "order:ctx:" + orderNo;
        String current = (String) redisTemplate.opsForHash().get(ctxKey, "currentDriver");
        if (current == null || !current.equals(String.valueOf(driverId))) {
            return false; // 不是当前候选或已过期
        }
        // 用 SETNX 保证只有一个司机能成功接单
        String acceptKey = "order:accept:" + orderNo;
        Boolean ok = redisTemplate.opsForValue()
                .setIfAbsent(acceptKey, String.valueOf(driverId), 10, TimeUnit.MINUTES);
        if (!Boolean.TRUE.equals(ok)) {
            return false; // 已被其他司机接走
        }
        // 更新数据库订单状态：待派单 -> 已派单，绑定司机
        orderService.acceptOrder(orderNo, driverId);
        return true;
    }
}
```

### 3. 计价服务：里程 + 时长 + 动态调价

```java
@Service
public class PriceService {

    @Autowired
    private PriceRuleMapper priceRuleMapper;
    @Autowired
    private StringRedisTemplate redisTemplate;

    private static final BigDecimal NIGHT_START = new BigDecimal("23");
    private static final BigDecimal NIGHT_END = new BigDecimal("5");

    /**
     * 预估价格：地图 API 给出里程与时长，套用计价规则
     * 公式：max(起步价, 里程费 + 时长费) * 调价系数 + 夜间加价
     */
    public BigDecimal estimate(Long orderNo, String cityCode, String vehicleType,
                               double distanceKm, int durationMin, LocalDateTime time) {
        PriceRule rule = priceRuleMapper.selectByCityAndType(cityCode, vehicleType);
        if (rule == null) {
            throw new BizException("该城市暂未开通" + vehicleType);
        }
        // 1. 里程费与时长费
        BigDecimal distanceFee = BigDecimal.valueOf(distanceKm)
                .multiply(rule.getPerKmPrice());
        BigDecimal durationFee = BigDecimal.valueOf(durationMin)
                .multiply(rule.getPerMinPrice());
        BigDecimal amount = distanceFee.add(durationFee);

        // 2. 与起步价取大
        if (BigDecimal.valueOf(distanceKm).compareTo(rule.getBaseDistance()) <= 0) {
            amount = amount.max(rule.getBasePrice());
        }

        // 3. 夜间加价（23:00 - 05:00）
        BigDecimal hour = new BigDecimal(time.getHour());
        boolean isNight = hour.compareTo(NIGHT_START) >= 0
                || hour.compareTo(NIGHT_END) < 0;
        if (isNight) {
            amount = amount.multiply(rule.getNightSurcharge());
        }

        // 4. 动态调价系数（下单时快照，写入订单，结算不再变动）
        BigDecimal factor = getSurgeFactor(cityCode, vehicleType);
        amount = amount.multiply(factor).setScale(2, RoundingMode.HALF_UP);
        return amount;
    }

    /**
     * 动态调价：供需比 = 周边待派订单数 / 周边在线司机数
     * ratio > 1 供不应求，系数上调；ratio < 0.5 供过于求，系数回落
     */
    public BigDecimal getSurgeFactor(String cityCode, String vehicleType) {
        String cacheKey = "surge:ratio:" + cityCode + ":" + vehicleType;
        String cached = redisTemplate.opsForValue().get(cacheKey);
        if (cached != null) {
            return new BigDecimal(cached);
        }
        PriceRule rule = priceRuleMapper.selectByCityAndType(cityCode, vehicleType);
        // 周边订单数（待派单订单队列长度）与在线司机数（GEO 集合大小）
        long pendingOrders = redisTemplate.opsForList()
                .size("order:queue:" + cityCode);
        long onlineDrivers = redisTemplate.opsForGeo()
                .size("geo:driver:" + cityCode);
        double ratio = onlineDrivers == 0 ? 2.0
                : (double) pendingOrders / onlineDrivers;

        // 线性映射：ratio 1.0 -> factor 1.0，ratio 每 +0.5 -> factor +0.2
        BigDecimal factor = BigDecimal.ONE
                .add(BigDecimal.valueOf((ratio - 1.0) * 0.4))
                .setScale(2, RoundingMode.HALF_UP);
        // 收敛到配置区间 [factor_min, factor_max]
        factor = factor.max(rule.getFactorMin()).min(rule.getFactorMax());

        redisTemplate.opsForValue().set(cacheKey, factor.toPlainString(),
                5, TimeUnit.MINUTES); // 5 分钟刷新一次
        return factor;
    }

    /**
     * 行程结束结算：按实际里程/时长重新计算，并生成账单
     * 里程超预估 20% 以上时二次确认（防绕路）
     */
    public BigDecimal settle(TripOrder order, double actualKm, int actualMin) {
        BigDecimal amount = estimate(order.getOrderNo(), order.getCityCode(),
                order.getVehicleType(), actualKm, actualMin, order.getEndTime());
        // 防绕路校验：实际金额超过预估 30% 时标记异常，人工复核
        BigDecimal estimate = order.getEstimateAmount();
        if (estimate != null
                && amount.compareTo(estimate.multiply(new BigDecimal("1.3"))) > 0) {
            orderService.markAbnormal(order.getOrderNo(), "费用超预估30%");
        }
        return amount;
    }
}
```

### 4. 订单服务：行程状态机

```java
@Service
public class OrderService {

    public static final int STATUS_WAIT_DISPATCH = 0;  // 待派单
    public static final int STATUS_DISPATCHED = 1;     // 已派单
    public static final int STATUS_PICKING = 2;        // 接驾中
    public static final int STATUS_ARRIVED = 3;        // 已到达上车点
    public static final int STATUS_TRIP = 4;           // 行程中
    public static final int STATUS_WAIT_PAY = 5;       // 待支付
    public static final int STATUS_FINISHED = 6;       // 已完成
    public static final int STATUS_CANCELED = 7;       // 已取消

    @Autowired
    private TripOrderMapper orderMapper;
    @Autowired
    private OrderEventMapper eventMapper;
    @Autowired
    private StringRedisTemplate redisTemplate;

    /**
     * 状态机统一流转入口：校验合法迁移，落库 + 记事件日志 + 更新缓存
     * 合法迁移表：0->1/7, 1->2/7, 2->3/7, 3->4/7, 4->5/7, 5->6
     */
    @Transactional(rollbackFor = Exception.class)
    public boolean transition(String orderNo, int from, int to, String operator,
                              String remark) {
        if (!isValidTransition(from, to)) {
            throw new BizException("非法状态流转: " + from + " -> " + to);
        }
        // CAS 更新：WHERE status = from，防止并发乱序
        int updated = orderMapper.casUpdateStatus(orderNo, from, to, remark);
        if (updated != 1) {
            throw new BizException("订单状态已变更，请刷新后重试");
        }
        // 记录事件日志（纠纷仲裁时间线）
        OrderEvent event = new OrderEvent();
        event.setOrderNo(orderNo);
        event.setFromStatus(from);
        event.setToStatus(to);
        event.setOperator(operator);
        event.setRemark(remark);
        eventMapper.insert(event);
        // 通知乘客/司机端状态变化（WebSocket）
        OrderWsPush.pushStatusChanged(orderNo, to);
        return true;
    }

    /** 合法迁移校验 */
    private boolean isValidTransition(int from, int to) {
        switch (from) {
            case STATUS_WAIT_DISPATCH:
                return to == STATUS_DISPATCHED || to == STATUS_CANCELED;
            case STATUS_DISPATCHED:
                return to == STATUS_PICKING || to == STATUS_CANCELED;
            case STATUS_PICKING:
                return to == STATUS_ARRIVED || to == STATUS_CANCELED;
            case STATUS_ARRIVED:
                return to == STATUS_TRIP || to == STATUS_CANCELED;
            case STATUS_TRIP:
                return to == STATUS_WAIT_PAY || to == STATUS_CANCELED;
            case STATUS_WAIT_PAY:
                return to == STATUS_FINISHED;
            default:
                return false;
        }
    }

    /** 派单超时扫描：超过 60 秒仍待派单的订单转入抢单池或自动取消 */
    @Scheduled(fixedDelay = 10_000)
    public void scanTimeoutOrders() {
        List<TripOrder> pending = orderMapper.selectByStatus(STATUS_WAIT_DISPATCH);
        for (TripOrder order : pending) {
            long waitMs = System.currentTimeMillis() - order.getCreateTime().getTime();
            if (waitMs > 60_000) {
                // 转抢单池：广播给候选司机，先到先得
                redisTemplate.opsForList()
                        .leftPush("order:queue:" + order.getCityCode(), order.getOrderNo());
                transition(order.getOrderNo(), STATUS_WAIT_DISPATCH, STATUS_DISPATCHED,
                        "system", "派单超时转抢单池");
            }
        }
    }
}
```

```java
@Service
public class GrabOrderService {

    @Autowired
    private StringRedisTemplate redisTemplate;
    @Autowired
    private OrderService orderService;

    /**
     * 司机抢单：订单号 + 司机 id，Redis 原子抢占
     * 广播队列里同一订单可能被多个司机同时抢，SETNX 保证只有一人成功
     */
    public boolean grab(String orderNo, Long driverId) {
        // 1. 校验司机在线且未被封禁（省略校验细节）
        // 2. 原子抢占：同一订单只允许一个司机抢到
        String grabKey = "order:grab:" + orderNo;
        Boolean ok = redisTemplate.opsForValue()
                .setIfAbsent(grabKey, String.valueOf(driverId), 60, TimeUnit.SECONDS);
        if (!Boolean.TRUE.equals(ok)) {
            return false; // 手慢了，已被抢走
        }
        try {
            // 3. 校验订单仍处于可抢状态（待派单/已派单未接）
            TripOrder order = orderMapper.selectByOrderNo(orderNo);
            if (order == null || order.getStatus() != OrderService.STATUS_WAIT_DISPATCH) {
                return false;
            }
            // 4. 状态流转：待派单 -> 已派单，绑定司机
            orderService.transition(orderNo, OrderService.STATUS_WAIT_DISPATCH,
                    OrderService.STATUS_DISPATCHED, "driver:" + driverId, "抢单成功");
            return true;
        } catch (Exception e) {
            redisTemplate.delete(grabKey); // 失败释放抢占，其他人还能抢
            throw e;
        }
    }

    /** 司机端轮询抢单大厅：拉取当前城市可抢订单列表 */
    public List<String> grabPool(String cityCode) {
        Long size = redisTemplate.opsForList().size("order:queue:" + cityCode);
        if (size == null || size == 0) {
            return Collections.emptyList();
        }
        return redisTemplate.opsForList()
                .range("order:queue:" + cityCode, 0, Math.min(size, 20) - 1);
    }
}
```

### 6. 地图服务封装：路线规划与距离矩阵

```java
@Service
public class MapApiService {

    // 高德 Web 服务 API（服务端 Key，绝不下发到客户端）
    private static final String AMAP_KEY = "your-amap-server-key";
    private static final String AMAP_DIRECTION_URL =
            "https://restapi.amap.com/v3/direction/driving";
    private static final String AMAP_DISTANCE_URL =
            "https://restapi.amap.com/v3/distance";

    @Autowired
    private RestTemplate restTemplate;

    /**
     * 路线规划：返回里程（米）与预计时长（秒）
     * 用于叫车时预估价格、行程中 ETA 刷新
     */
    public RouteInfo planRoute(double fromLng, double fromLat,
                               double toLng, double toLat) {
        String url = AMAP_DIRECTION_URL + "?key=" + AMAP_KEY
                + "&origin=" + fromLng + "," + fromLat
                + "&destination=" + toLng + "," + toLat
                + "&extensions=base";
        Map<String, Object> resp = restTemplate.getForObject(url, Map.class);
        if (resp == null || !"1".equals(String.valueOf(resp.get("status")))) {
            throw new BizException("路线规划失败");
        }
        List<?> paths = (List<?>) ((Map<?, ?>) resp.get("route")).get("paths");
        if (paths == null || paths.isEmpty()) {
            throw new BizException("起终点之间无可用路线");
        }
        Map<?, ?> path = (Map<?, ?>) paths.get(0);
        RouteInfo info = new RouteInfo();
        info.setDistanceMeters(Double.parseDouble(String.valueOf(path.get("distance"))));
        info.setDurationSeconds(Long.parseLong(String.valueOf(path.get("duration"))));
        return info;
    }

    /**
     * 批量距离矩阵：计算起点到多个司机位置的距离（批量接口，一次最多 100 对）
     * 用于派单时对 GEO 候选做更精确的道路距离校准
     */
    public Map<Long, Double> batchDistance(double fromLng, double fromLat,
                                           List<Long> driverIds) {
        // 拼接目标点：lng,lat|lng,lat|...
        String origins = fromLng + "," + fromLat;
        String destinations = driverIds.stream()
                .map(id -> redisTemplate.opsForHash()
                        .entries("driver:loc:" + id))
                .map(m -> m.get("lng") + "," + m.get("lat"))
                .collect(Collectors.joining("|"));
        String url = AMAP_DISTANCE_URL + "?key=" + AMAP_KEY
                + "&origins=" + origins + "&destinations=" + destinations + "&type=1";
        Map<String, Object> resp = restTemplate.getForObject(url, Map.class);
        Map<Long, Double> result = new HashMap<>();
        if (resp != null && "1".equals(String.valueOf(resp.get("status")))) {
            List<?> results = (List<?>) resp.get("results");
            for (int i = 0; i < results.size() && i < driverIds.size(); i++) {
                Map<?, ?> item = (Map<?, ?>) results.get(i);
                result.put(driverIds.get(i),
                        Double.parseDouble(String.valueOf(item.get("distance"))));
            }
        }
        return result;
    }

    @Data
    public static class RouteInfo {
        private double distanceMeters;
        private long durationSeconds;
    }
}
```

### 7. WebSocket 推送：司机位置实时追踪

```java
@Component
public class OrderWsPush {

    // 连接会话管理：userId -> session（乘客端/司机端各一个连接）
    private static final ConcurrentHashMap<Long, WebSocketSession> SESSIONS =
            new ConcurrentHashMap<>();

    @Autowired
    private GeoLocationService geoLocationService;

    /**
     * 行程中位置追踪：每 3 秒由位置上报服务触发
     * 把司机最新位置推送给关联乘客，乘客地图实时移动
     */
    public void pushDriverLocation(String orderNo, Long passengerId,
                                   Long driverId, String cityCode) {
        WebSocketSession session = SESSIONS.get(passengerId);
        if (session == null || !session.isOpen()) {
            return; // 乘客不在线，跳过（下次上报再推）
        }
        // 取司机最新位置快照
        Map<Object, Object> loc = redisTemplate.opsForHash()
                .entries("driver:loc:" + driverId);
        if (loc.isEmpty()) {
            return;
        }
        // 组装推送消息：订单号 + 位置 + 剩余距离/时间
        Map<String, Object> msg = new HashMap<>();
        msg.put("type", "LOCATION");
        msg.put("orderNo", orderNo);
        msg.put("lng", Double.parseDouble(String.valueOf(loc.get("lng"))));
        msg.put("lat", Double.parseDouble(String.valueOf(loc.get("lat"))));
        msg.put("speed", String.valueOf(loc.get("speed")));
        msg.put("ts", System.currentTimeMillis());
        try {
            session.sendMessage(new TextMessage(objectMapper.writeValueAsString(msg)));
        } catch (Exception e) {
            // 推送失败：连接可能断开，移除会话，客户端重连后恢复
            SESSIONS.remove(passengerId);
        }
    }

    /** 连接建立时注册会话 */
    public static void register(Long userId, WebSocketSession session) {
        SESSIONS.put(userId, session);
    }

    /** 连接断开时清理 */
    public static void unregister(Long userId) {
        SESSIONS.remove(userId);
    }
}
```

## 实际应用场景

### 场景一：早晚高峰叫车（就近派单 + 动态调价）

高峰时段订单量是平峰的 3-5 倍，司机供给不足，系统需要既快又公平地撮合：

```text
1. 乘客 8:30 在地铁站发起叫车，起点坐标 (116.397, 39.908)，系统生成待派单订单
2. 调地图 API 算得里程 6.2 公里、预计 25 分钟，按计价规则预估 28.5 元
3. 调度引擎 GEOSEARCH 检索起点 3 公里内在线司机：共 42 名
4. 综合打分：距离 1.2 公里、评分 4.9、当日已接 5 单的司机 A 得分最高
5. 供需比计算：该区域待派订单 18 个、在线司机 42 名，ratio=0.43，系数维持 1.00
6. 订单推送给司机 A，8 秒后确认接单，订单状态变为已派单
7. 司机按导航接驾，乘客上车后点击开始行程，位置每 3 秒上报推送
8. 23:30 夜间接单：夜间系数 1.2 生效，乘客看到价格上浮提示后确认叫车
```

### 场景二：偏远区域叫车（派单超时 + 抢单兜底）

郊区订单附近司机稀少，派单策略要自动扩围并兜底：

```text
1. 乘客在开发区叫车，3 公里内仅 2 名在线司机
2. 首轮派单推给司机 A，30 秒响应窗口内未接单（司机正在接其他乘客）
3. 调度引擎自动扩围到 5 公里，新增 3 名候选司机，依次推送仍无人接
4. 扩围到 8 公里后依旧无响应，订单标记「派单超时」
5. 定时任务扫描发现订单等待超 60 秒，将订单推入该城市抢单池
6. 8.5 公里外的司机 B 看到抢单大厅广播，点击抢单，SETNX 抢占成功
7. 订单绑定司机 B，乘客端显示司机距离 8.5 公里、预计 18 分钟到达
8. 平台运营在运力监控看到该区域供给不足，推送消息引导附近司机上线
```

### 场景三：行程中实时追踪与安全监控

行程中的位置推送与异常检测：

```text
1. 行程开始后司机位置每 3 秒上报一次，写入 Redis GEO 与位置快照
2. 位置服务每 30 秒批量落库一次 driver_location 快照表
3. WebSocket 把司机实时位置推给乘客端，地图上车辆图标平滑移动
4. 后端同步比对订单路线：实际轨迹偏离规划路线超过 500 米，触发绕路预警
5. 系统每 10 分钟向乘客推送 ETA 刷新（调地图 API 计算剩余时间）
6. 乘客点击「紧急求助」，系统将实时位置与行程快照发送给紧急联系人
7. 行程结束生成账单，如费用超预估 30% 自动标记异常单进入人工复核
8. 司机与乘客互评后订单归档，轨迹数据保留 90 天供纠纷仲裁
```

## 最佳实践与踩坑记录

### 最佳实践

1. 位置索引用 Redis GEO、持久化用低频快照：实时位置只写 Redis（毫秒级读写），每 30 秒落库一次快照，既满足实时性又不打爆数据库
2. 按城市分片 GEO Key：`geo:driver:{cityCode}` 单城市一个集合，避免全国司机挤在同一个 ZSET 导致检索变慢，也方便城市级运维
3. 派单原子性用 SETNX 锁 + CAS 状态更新：多实例并发派单时「一单一司机」靠 Redis 锁保证，订单状态迁移用 `UPDATE ... WHERE status = from` 防乱序
4. 计价规则参数化：起步价/单价/夜间系数/调价上下限全部入库配置，运营可调，绝不硬编码；动态调价系数在下单时快照进订单，结算不再变动
5. 状态机集中管理：所有状态流转走统一 transition 方法，合法性校验 + 事件日志一步到位，杜绝业务代码里到处直接改 status
6. 地图服务 Key 只在服务端：路线规划/距离矩阵全部后端调用 Web 服务 API，客户端只拿坐标，防止 Key 泄露被刷
7. 推送失败静默降级：WebSocket 断连时移除会话、不重试堆消息，客户端重连后拉一次全量状态即可，避免消息积压
8. 司机在线状态用「心跳续期」：位置上报时同步续期 online 标记（TTL 30 秒），超过 60 秒没上报自动视为离线，比显式下线更可靠

### 踩坑记录

```text
坑 1：用 MySQL 经纬度索引做就近检索
结论：司机量到 10 万级后，距离查询要 1-2 秒，派单直接超时。
原因：MySQL 的经纬度范围扫描 + 距离排序无法利用 B+ 树索引高效完成半径检索。
解法：改用 Redis GEO，GEOADD 写入 + GEOSEARCH 半径检索，单次查询毫秒级；MySQL 只做低频轨迹归档。

坑 2：司机位置全量落库
结论：3 秒一次的上报把 MySQL 写炸了，binlog 膨胀，主从延迟飙升。
原因：实时位置是瞬时状态，高频写库完全没有必要。
解法：实时位置只写 Redis，每 30 秒节流落库一次快照表，轨迹回放按快照点线性插值即可。

坑 3：多实例重复派单
结论：订单同时推给两个司机，两个司机都点了接单，乘客被两辆车接。
原因：应用多实例部署后，两个实例同时执行派单逻辑，没有互斥。
解法：订单级 SETNX 派单锁 + 接单时 CAS 校验订单状态，双重保障一单一司机。

坑 4：派单只按距离
结论：距离最近的司机永远是同一批人，高分司机接不到单，投诉率上升。
原因：派单因子单一，没有考虑司机评分与负载。
解法：综合打分 = 距离 60% + 评分 30% + 当日单量 10%，低分/高负载司机自动降权，派单更公平。

坑 5：动态调价系数结算时才算
结论：乘客下单时显示 25 元，行程结束变成 35 元，大量客诉。
原因：动态调价系数在结算时重新计算，供需变化导致价格跳变。
解法：调价系数在下单时快照写入订单表，结算沿用快照值，价格对乘客全程可见。

坑 6：WebSocket 连接不经网关统一管理
结论：服务重启后所有司机端断连，新订单推送全部丢失，只能靠轮询兜底。
原因：连接绑定在单个实例内存里，实例重启会话即失。
解法：网关层做连接粘滞 + 断线重连后全量状态同步（拉取当前订单/在线状态），推送失败不堆消息直接降级。

坑 7：司机直接改数据库状态字段
结论：接驾/到达等操作绕过状态机直接 UPDATE，出现「已到达却还没接驾」的脏状态。
原因：没有统一状态流转入口，各业务代码自己改 status。
解法：收敛为 transition 状态机方法，校验合法迁移 + 记录事件日志，非法流转直接抛异常。

坑 8：位置上报与订单状态并发错乱
结论：司机点了「开始行程」，但乘客端还显示「接驾中」。
原因：WebSocket 推送与状态更新不是原子的，乘客先收到旧状态推送。
解法：状态变更先落库再推送，推送消息带订单版本号，客户端按版本号丢弃过期消息。
```

## 项目背景

电子合同签署系统（Electronic Contract Signing System）解决传统纸质合同「打印、快递、盖章、扫描、归档」的漫长流程问题：一份劳动合同异地签署来回快递要 5-10 天，采购合同盖章后还要担心被篡改、丢失。本系统把合同从「模板 → 变量填充 → 签署 → 存证 → 归档 → 验真」全流程数字化：模板管理、PDF 自动生成、多方顺序/并行签署、数字签名（RSA/SM2）、时间戳存证、哈希链防篡改、在线验真。本项目的落地方案是「模拟实现」：不依赖真实 CA 数字证书与权威时间戳机构（TSA），用 RSA 签名 + 系统自建时间戳服务 + 哈希链即可完整演示签署与验真闭环，生产环境可平滑替换为 CA 证书与国密 SM2 体系。

业务痛点：

```text
1. 签署周期长：纸质合同跨城快递往返 5-10 天，业务被合同卡脖子
2. 盖章成本高：印章管理混乱，萝卜章、盗盖事件频发，风控难做
3. 篡改难发现：纸质合同涂改后肉眼难辨，纠纷时举证困难
4. 归档成本大：海量纸质档案需要库房存放，检索一份合同要翻半天
5. 多方签署难：三方以上合同要逐个快递传递，顺序错乱就作废重来
6. 法律效力存疑：无数字签名、无时间戳的电子文档，司法采信度低
```

目标用户与核心诉求：

```text
1. 企业合同管理员（HR/采购/销售）：维护合同模板，批量发起签署，跟踪签署进度
2. 合同发起人：选择模板填变量生成合同，配置签署人顺序与签署方式
3. 签署方（员工/客户/供应商）：接收签署通知，短信验证码认证意愿，手写签名或证书签名
4. 法务/风控人员：合同归档管理、在线验真、出具验真报告用于司法举证
5. 平台管理员：模板与印章管理、签署日志审计、时间戳服务配置
```

项目要解决的核心问题一句话概括：把「合同签署」抽象成「模板变量填充 + 签署流程状态机 + 数字签名与哈希链存证」，让任何合同从起草到司法可举证的电子归档全流程线上化，且无 CA 也能完整演示可信签署闭环。

## 功能介绍

功能按角色与模块拆分：合同模板管理、合同创建、签署流程、电子签名、签署意愿认证、时间戳存证、归档验真、防篡改校验。

```text
一、合同模板管理（合同管理员使用）
1. 模板上传 —— 上传 PDF 版合同模板（含占位变量），系统解析变量清单
2. 变量配置 —— 为模板配置变量坐标（变量名/页号/X/Y/字号/最大宽度），保存为模板定义
3. 模板版本 —— 每次编辑 version +1，已发起合同锁定模板版本，不受后续修改影响
4. 模板启停 —— 停用后不可用于新建合同，存量合同不受影响

二、合同创建（发起人使用）
1. 选择模板 —— 按分类/关键词检索可用模板
2. 变量填充 —— 在线表单填写变量（如员工姓名、岗位、薪资），前端即时校验必填与格式
3. 生成合同 —— 系统按变量坐标写入 PDF 生成合同文件（未签版），计算初始哈希
4. 配置签署 —— 添加签署方（姓名/手机号），选择签署模式（顺序/并行）与签署方式（手写/证书）
5. 发起签署 —— 生成签署任务，向签署方发送短信通知（模拟）

三、签署流程（签署方使用）
1. 签署通知 —— 短信携带签署链接，链接短期有效
2. 意愿认证 —— 签署前输入短信验证码，确认本人操作（防代签、防抵赖）
3. 查看合同 —— 在线预览合同全文，确认条款
4. 手写签名 —— 前端 canvas 手写签名生成 PNG 图片
5. 证书签名 —— 模拟数字证书签名（演示环境内置密钥对，生产对接 CA/USBKey）
6. 签名定位 —— 签署人在合同指定签署区（红框标注）确认位置，系统按坐标落章
7. 拒签处理 —— 签署方可拒签并填写原因，流程回到发起人处理（修改后重新发起）

四、时间戳与存证（系统自动）
1. 时间戳签发 —— 每次签署完成，时间戳服务对「内容哈希 + 时间」签发 ts_token（TSA 私钥签名）
2. 哈希链维护 —— 每条签署记录串联成哈希链，任何篡改都会导致链断裂
3. 存证记录 —— 签署人、算法、哈希、时间戳、签名值全量落库可审计

五、合同归档与验真（法务使用）
1. 合同归档 —— 签署完成后自动归档（含签署后 PDF 与全部签署记录），按合同号检索
2. 在线验真 —— 上传 PDF 或输入合同号，系统重算哈希、逐节点验签、校验哈希链、验证时间戳
3. 验真报告 —— 输出验真结论（真/伪/被篡改）与各签署人签署明细，可导出 PDF 报告
4. 防篡改校验 —— 任意篡改合同文件（哪怕一个字节），哈希链校验立即失败并定位到签署节点

六、平台管理（管理员使用）
1. 印章管理 —— 上传企业电子印章图片，绑定使用权限（谁可用/哪些合同可用）
2. 密钥管理 —— 演示环境密钥对/TSA 密钥对的生成与轮换
3. 审计日志 —— 合同创建、签署、归档、验真全操作留痕
```

## 技术选型

| 组件 | 选型 | 理由 |
|------|------|------|
| 开发框架 | Spring Boot 2.7/3.x | 生态成熟，快速搭建 REST 服务 |
| 持久层 | MyBatis-Plus | 单表 CRUD 零 SQL，复杂查询走 XML |
| 数据库 | MySQL 8.0 | 合同、签署记录、存证等结构化数据 |
| 缓存 | Redis | 短信验证码、签署并发锁、会话 |
| PDF 处理 | iText 7（或 OpenPDF） | 模板变量填充、坐标签章、PDF 合成 |
| 数字签名 | JDK 内置 RSA（SHA256withRSA） | 无需额外依赖，演示环境可运行 |
| 国密算法 | BouncyCastle（可选扩展 SM2） | 生产环境替换 RSA，代码接口一致 |
| 哈希 | JDK MessageDigest SHA-256 | 哈希链与文件指纹计算 |
| 印章/签名图片 | 前端 Canvas 生成 PNG | 手写签名采集与印章图片管理 |
| 短信服务 | 模拟实现（Redis 存验证码） | 演示环境不依赖真实短信通道，可替换阿里云/腾讯云 SMS |
| 文件存储 | MinIO / 本地磁盘 | 合同 PDF、签名图片、印章图片 |
| 前端 | Vue 3 + Element Plus + pdf.js | 合同预览、签署区定位、手写签名板 |

选型说明：

```text
1. 数字签名用 JDK 内置 RSA：SHA256withRSA 是 JCE 自带算法，零依赖即可演示「签名-验签」闭环；接口抽象成 CryptoProvider，生产可无缝切换 BouncyCastle SM2（国密合规）
2. 时间戳模拟自建：系统内置 TSA 密钥对，对「内容哈希 + 时间」签名生成 ts_token，行为与真实时间戳机构一致；生产替换为权威 TSA 接口即可
3. PDF 签章用「坐标 + 图片叠加」：模板变量与印章都按坐标定位写入 PDF，避免依赖复杂的 PDF 表单域解析，逻辑直观、可运行
4. 哈希链贯穿全生命周期：合同初始哈希 → 每个签署节点哈希 → 归档哈希，环环相扣，验真时从头重算对比
5. 意愿认证用短信验证码：签署前必须通过验证码确认，这是《电子签名法》对可靠电子签名「签署人身份 + 签署意愿」要求的低成本实现
```

合同签署完整链路（顺序签署示例）：

```text
1. HR 上传劳动合同模板 PDF，配置变量坐标（员工姓名/岗位/薪资/签署日期）
2. HR 发起合同：选模板 → 填变量 → 生成未签 PDF → 配置签署人（员工，顺序模式）
3. 系统创建合同（状态 DRAFT）→ 创建签署任务（状态 WAITING）→ 生成初始哈希 rootHash → 状态置 SIGNING
4. 第一个签署任务解锁（WAITING → READY），向员工发送签署短信（模拟）
5. 员工打开链接 → 输入短信验证码（Redis 校验）→ 预览合同 → 手写签名生成 PNG
6. 系统定位签署区坐标 → 合成签章 PDF → 计算 contentHash → 用员工私钥签名 → TSA 签发时间戳
7. 计算 nodeHash 写入签署记录 → 流程推进（任务 SIGNED，下一任务解锁）
8. 全部签署完成：合同状态 COMPLETED，自动归档（合同 + 全部签署记录 + 哈希链）
9. 法务验真：上传 PDF → 重算哈希 → 逐节点验签 + 校验哈希链 + 验证时间戳 → 输出验真报告
```

哈希链结构示意：

```text
rootHash = SHA256(合同原始文件字节)                     ← 发起时生成
nodeHash[1] = SHA256(rootHash + contentHash1 + 签署人A + ts_token1 + signature1)
nodeHash[2] = SHA256(nodeHash[1] + contentHash2 + 签署人B + ts_token2 + signature2)
nodeHash[n] = SHA256(nodeHash[n-1] + contentHashN + 签署人N + ts_tokenN + signatureN)

验真：从 rootHash 逐节点重算 nodeHash，与库里记录对比；
任一节点不匹配 → 该节点之后的记录被篡改；contentHash 不匹配 → 合同文件被改动
```

## 数据库设计

核心表设计（7 张表）：

```sql
-- 合同模板表
CREATE TABLE `contract_template` (
  `id`            BIGINT       NOT NULL AUTO_INCREMENT,
  `tpl_name`      VARCHAR(200) NOT NULL COMMENT '模板名称',
  `tpl_type`      VARCHAR(50)  NOT NULL COMMENT '分类：labor/purchase/sale/lease 等',
  `file_path`     VARCHAR(500) NOT NULL COMMENT '模板 PDF 文件路径',
  `var_config`    MEDIUMTEXT   NOT NULL COMMENT '变量坐标配置 JSON（key/x/y/page/fontSize）',
  `version`       INT          NOT NULL DEFAULT 1 COMMENT '版本号（每次编辑 +1）',
  `status`        TINYINT      NOT NULL DEFAULT 1 COMMENT '状态：0停用 1启用',
  `owner_id`      BIGINT       DEFAULT NULL COMMENT '创建人',
  `create_time`   DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `update_time`   DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  KEY `idx_type` (`tpl_type`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='合同模板表';

-- 合同主表
CREATE TABLE `contract` (
  `id`            BIGINT       NOT NULL AUTO_INCREMENT,
  `contract_no`   VARCHAR(64)  NOT NULL COMMENT '合同编号（业务唯一）',
  `title`         VARCHAR(300) NOT NULL COMMENT '合同标题',
  `tpl_id`        BIGINT       NOT NULL COMMENT '模板 id（锁定版本）',
  `tpl_version`   INT          NOT NULL COMMENT '发起时模板版本（快照）',
  `var_data`      MEDIUMTEXT   NOT NULL COMMENT '变量数据 JSON',
  `file_path`     VARCHAR(500) NOT NULL COMMENT '当前合同 PDF 路径（每次签署后更新）',
  `root_hash`     CHAR(64)     NOT NULL COMMENT '合同初始哈希（SHA-256，防篡改链首）',
  `sign_mode`     VARCHAR(20)  NOT NULL DEFAULT 'SEQUENTIAL' COMMENT '签署模式：SEQUENTIAL顺序 PARALLEL并行',
  `status`        VARCHAR(20)  NOT NULL DEFAULT 'DRAFT' COMMENT '状态：DRAFT/SIGNING/COMPLETED/CANCELLED/ARCHIVED',
  `initiator_id`  BIGINT       DEFAULT NULL COMMENT '发起人',
  `create_time`   DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `update_time`   DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_contract_no` (`contract_no`),
  KEY `idx_status` (`status`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='合同主表';

-- 签署任务表（每个签署方一个任务）
CREATE TABLE `sign_task` (
  `id`            BIGINT       NOT NULL AUTO_INCREMENT,
  `contract_id`   BIGINT       NOT NULL COMMENT '合同 id',
  `signer_name`   VARCHAR(100) NOT NULL COMMENT '签署人姓名',
  `signer_phone`  VARCHAR(20)  NOT NULL COMMENT '签署人手机号',
  `seq`           INT          NOT NULL COMMENT '签署顺序（并行模式都为 1）',
  `sign_type`     VARCHAR(20)  NOT NULL DEFAULT 'HANDWRITE' COMMENT '签署方式：HANDWRITE手写 CERT证书',
  `stamp_path`    VARCHAR(500) DEFAULT NULL COMMENT '签名/印章图片路径（签署后写入）',
  `status`        VARCHAR(20)  NOT NULL DEFAULT 'WAITING' COMMENT '状态：WAITING/READY/SIGNED/REJECTED/EXPIRED',
  `reject_reason` VARCHAR(500) DEFAULT NULL COMMENT '拒签原因',
  `auth_status`   VARCHAR(20)  NOT NULL DEFAULT 'UNAUTH' COMMENT '意愿认证状态：UNAUTH/AUTHED',
  `sign_time`     DATETIME     DEFAULT NULL COMMENT '签署时间',
  `create_time`   DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  KEY `idx_contract` (`contract_id`),
  KEY `idx_phone` (`signer_phone`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='签署任务表';

-- 签署记录表（哈希链节点）
CREATE TABLE `sign_record` (
  `id`            BIGINT       NOT NULL AUTO_INCREMENT,
  `contract_id`   BIGINT       NOT NULL COMMENT '合同 id',
  `task_id`       BIGINT       NOT NULL COMMENT '签署任务 id',
  `signer_name`   VARCHAR(100) NOT NULL COMMENT '签署人',
  `signer_pubkey` TEXT         NOT NULL COMMENT '签署人公钥（验签用）',
  `algorithm`     VARCHAR(50)  NOT NULL DEFAULT 'SHA256withRSA' COMMENT '签名算法',
  `content_hash`  CHAR(64)     NOT NULL COMMENT '签署时合同文件哈希（SHA-256）',
  `signature`     TEXT         NOT NULL COMMENT '对 contentHash 的签名（Base64）',
  `ts_token`      VARCHAR(100) NOT NULL COMMENT '时间戳存证 token',
  `prev_hash`     CHAR(64)     NOT NULL COMMENT '前一节点哈希（rootHash 或上一 nodeHash）',
  `node_hash`     CHAR(64)     NOT NULL COMMENT '本节点哈希（哈希链节点）',
  `stamp_pos`     VARCHAR(200) DEFAULT NULL COMMENT '签章坐标 JSON（page/x/y/w/h）',
  `sign_time`     DATETIME     NOT NULL COMMENT '签署时间',
  `create_time`   DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_task` (`task_id`),
  KEY `idx_contract` (`contract_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='签署记录表（哈希链）';

-- 时间戳存证表
CREATE TABLE `timestamp_cert` (
  `id`            BIGINT       NOT NULL AUTO_INCREMENT,
  `ts_token`      VARCHAR(100) NOT NULL COMMENT '时间戳 token（唯一）',
  `content_hash`  CHAR(64)     NOT NULL COMMENT '被存证的内容哈希',
  `ts_time`       DATETIME     NOT NULL COMMENT '可信时间（TSA 签发时间）',
  `ts_signature`  TEXT         NOT NULL COMMENT 'TSA 对(时间+哈希)的签名（Base64）',
  `tsa_key_id`    VARCHAR(50)  NOT NULL COMMENT 'TSA 密钥标识（验签定位公钥）',
  `create_time`   DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_ts_token` (`ts_token`),
  KEY `idx_hash` (`content_hash`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='时间戳存证表';

-- 合同归档表
CREATE TABLE `contract_archive` (
  `id`            BIGINT       NOT NULL AUTO_INCREMENT,
  `contract_id`   BIGINT       NOT NULL COMMENT '合同 id',
  `final_file`    VARCHAR(500) NOT NULL COMMENT '最终签署版 PDF 路径',
  `chain_json`    MEDIUMTEXT   NOT NULL COMMENT '哈希链全量快照 JSON（验真依据）',
  `archive_no`    VARCHAR(64)  NOT NULL COMMENT '归档编号',
```

### 1. 密码学工具类：RSA 签名、验签与哈希

```java
package com.demo.contract.crypto;

import java.security.*;
import java.security.spec.PKCS8EncodedKeySpec;
import java.security.spec.X509EncodedKeySpec;
import java.util.Base64;

/**
 * 数字签名与哈希工具类（演示环境用 JDK 内置 RSA）
 * 生产环境可替换为 BouncyCastle SM2：接口保持不变，换算法实现即可
 */
public class CryptoUtil {

    private static final String ALG_SIGN = "SHA256withRSA";
    private static final String ALG_KEY  = "RSA";

    /** 生成 RSA 密钥对（演示用；生产由 CA/USBKey 签发证书） */
    public static KeyPair generateKeyPair() throws Exception {
        KeyPairGenerator generator = KeyPairGenerator.getInstance(ALG_KEY);
        generator.initialize(2048);
        return generator.generateKeyPair();
    }

    /** 用私钥对内容签名，返回 Base64 签名值 */
    public static String sign(String content, PrivateKey privateKey) throws Exception {
        Signature signature = Signature.getInstance(ALG_SIGN);
        signature.initSign(privateKey);
        signature.update(content.getBytes("UTF-8"));
        return Base64.getEncoder().encodeToString(signature.sign());
    }

    /** 用公钥验签，返回是否通过 */
    public static boolean verify(String content, String signatureBase64, PublicKey publicKey)
            throws Exception {
        Signature signature = Signature.getInstance(ALG_SIGN);
        signature.initVerify(publicKey);
        signature.update(content.getBytes("UTF-8"));
        return signature.verify(Base64.getDecoder().decode(signatureBase64));
    }

    /** SHA-256 哈希，返回 64 位十六进制字符串（哈希链与文件指纹统一用此方法） */
    public static String sha256(String content) throws Exception {
        MessageDigest digest = MessageDigest.getInstance("SHA-256");
        byte[] bytes = digest.digest(content.getBytes("UTF-8"));
        StringBuilder sb = new StringBuilder();
        for (byte b : bytes) {
            sb.append(String.format("%02x", b));
        }
        return sb.toString();
    }

    /** 对文件字节计算 SHA-256（合同 PDF 指纹） */
    public static String sha256File(byte[] fileBytes) throws Exception {
        MessageDigest digest = MessageDigest.getInstance("SHA-256");
        byte[] bytes = digest.digest(fileBytes);
        StringBuilder sb = new StringBuilder();
        for (byte b : bytes) {
            sb.append(String.format("%02x", b));
        }
        return sb.toString();
    }

    /** Base64 编码公钥（存库用） */
    public static String encodePublicKey(PublicKey publicKey) {
        return Base64.getEncoder().encodeToString(publicKey.getEncoded());
    }

    /** 从 Base64 还原公钥 */
    public static PublicKey decodePublicKey(String base64) throws Exception {
        byte[] bytes = Base64.getDecoder().decode(base64);
        return KeyFactory.getInstance(ALG_KEY).generatePublic(new X509EncodedKeySpec(bytes));
    }

    /** 从 Base64 还原私钥 */
    public static PrivateKey decodePrivateKey(String base64) throws Exception {
        byte[] bytes = Base64.getDecoder().decode(base64);
        return KeyFactory.getInstance(ALG_KEY).generatePrivate(new PKCS8EncodedKeySpec(bytes));
    }
}
```

### 2. 时间戳服务：可信时间签发（模拟 TSA）

```java
package com.demo.contract.tsa;

import com.demo.contract.crypto.CryptoUtil;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.stereotype.Service;

import java.security.KeyPair;
import java.security.PrivateKey;
import java.security.PublicKey;
import java.text.SimpleDateFormat;
import java.util.Date;
import java.util.UUID;

/**
 * 时间戳服务（模拟权威 TSA）
 * 对「内容哈希 + 可信时间」做签名，生成 ts_token；
 * 生产环境替换为对接真实时间戳机构（RFC 3161），调用方接口不变
 */
@Service
public class TimestampService {

    // 演示环境内置 TSA 密钥对（启动时生成一次并持久化到配置目录）
    private KeyPair tsaKeyPair;
    private String tsaKeyId = "TSA-DEMO-001";

    public TimestampService() {
        try {
            this.tsaKeyPair = CryptoUtil.generateKeyPair();
        } catch (Exception e) {
            throw new IllegalStateException("TSA 密钥对初始化失败", e);
        }
    }

    /**
     * 签发时间戳：对 contentHash 签上可信时间并签名
     * @return ts_token（后续用 token 取存证详情验签）
     */
    public TimestampCert issueTimestamp(String contentHash) throws Exception {
        String tsTime = new SimpleDateFormat("yyyy-MM-dd HH:mm:ss.SSS").format(new Date());
        // 待签名原文：内容哈希 + 可信时间
        String raw = contentHash + "|" + tsTime;
        String signature = CryptoUtil.sign(raw, tsaKeyPair.getPrivate());
        String token = UUID.randomUUID().toString().replace("-", "");
        return new TimestampCert(token, contentHash, tsTime, signature, tsaKeyId);
    }

    /** 验签：用 TSA 公钥验证时间戳签名，返回是否可信 */
    public boolean verifyTimestamp(TimestampCert cert) throws Exception {
        String raw = cert.getContentHash() + "|" + cert.getTsTime();
        return CryptoUtil.verify(raw, cert.getTsSignature(), tsaKeyPair.getPublic());
    }

    public PublicKey getTsaPublicKey() {
        return tsaKeyPair.getPublic();
    }

    /** 时间戳存证实体（对应 timestamp_cert 表） */
    public static class TimestampCert {
        private String tsToken;
        private String contentHash;
        private String tsTime;
        private String tsSignature;
        private String tsaKeyId;

        public TimestampCert(String tsToken, String contentHash, String tsTime,
                             String tsSignature, String tsaKeyId) {
            this.tsToken = tsToken;
            this.contentHash = contentHash;
            this.tsTime = tsTime;
            this.tsSignature = tsSignature;
            this.tsaKeyId = tsaKeyId;
        }
        // getter/setter 省略
        public String getTsToken() { return tsToken; }
        public String getContentHash() { return contentHash; }
        public String getTsTime() { return tsTime; }
        public String getTsSignature() { return tsSignature; }
        public String getTsaKeyId() { return tsaKeyId; }
    }
}
```

### 3. PDF 服务：模板变量填充与坐标签章

```java
package com.demo.contract.pdf;

import com.itextpdf.io.image.ImageDataFactory;
import com.itextpdf.kernel.font.PdfFont;
import com.itextpdf.kernel.font.PdfFontFactory;
import com.itextpdf.kernel.geom.Rectangle;
import com.itextpdf.kernel.pdf.PdfDocument;
import com.itextpdf.kernel.pdf.PdfReader;
import com.itextpdf.kernel.pdf.PdfWriter;
import com.itextpdf.kernel.pdf.canvas.PdfCanvas;
import com.itextpdf.kernel.pdf.xobject.PdfImageXObject;
import com.fasterxml.jackson.databind.JsonNode;
import com.fasterxml.jackson.databind.ObjectMapper;
import org.springframework.stereotype.Service;

import java.io.File;
import java.io.FileOutputStream;
import java.util.Map;

/**
 * PDF 处理服务：模板变量填充 + 坐标签章
 * 思路：模板 PDF + 变量坐标配置（x/y/page/fontSize），在指定坐标写入文本；
 *       签章 = 把印章/手写签名 PNG 图片按坐标叠加到 PDF 指定页
 */
@Service
public class PdfService {

    private final ObjectMapper objectMapper = new ObjectMapper();

    /**
     * 模板变量填充：读取模板 PDF，按 varConfig 坐标写入变量值，输出新 PDF
     * @param templatePath 模板 PDF 路径
     * @param varConfigJson 变量坐标配置 JSON
     * @param data 变量值（key -> value）
     * @param outPath 输出 PDF 路径
     */
    public void fillTemplate(String templatePath, String varConfigJson,
                             Map<String, String> data, String outPath) throws Exception {
        PdfDocument pdfDoc = new PdfDocument(
                new PdfReader(templatePath), new PdfWriter(new FileOutputStream(outPath)));
        PdfFont font = PdfFontFactory.createFont("STSong-Light", "UniGB-UCS2-H",
                PdfFontFactory.EmbeddingStrategy.PREFER_EMBEDDED);

        JsonNode root = objectMapper.readTree(varConfigJson);
        for (JsonNode v : root.path("variables")) {
            String key = v.path("key").asText();
            String value = data.get(key);
            if (value == null || value.isEmpty()) {
                continue; // 未填变量跳过
            }
            int page = v.path("page").asInt(1);
            float x = (float) v.path("x").asDouble();
            float y = (float) v.path("y").asDouble();
            float fontSize = (float) v.path("fontSize").asDouble(12);
            if (fontSize <= 0) {
                continue; // fontSize=0 表示签章位，由签章流程处理
            }
            // 在指定坐标写文本（PDF 坐标系原点在左下角）
            PdfCanvas canvas = new PdfCanvas(pdfDoc.getPage(page));
            canvas.beginText()
                  .setFontAndSize(font, fontSize)
                  .moveText(x, y)
                  .showText(truncate(value, (int) v.path("maxWidth").asDouble(200), fontSize))
                  .endText();
        }
        pdfDoc.close();
    }

    /** 文本超宽截断（按最大宽度估算字符数） */
    private String truncate(String value, int maxWidth, float fontSize) {
        // 中文约等于字号宽度，简单按比例截断，避免溢出签署区
        int maxChars = (int) (maxWidth / fontSize);
        return value.length() > maxChars ? value.substring(0, maxChars) : value;
    }

    /**
     * 坐标签章：把印章/手写签名 PNG 按坐标叠加到 PDF 指定页
     * @param srcPath 签署前 PDF
     * @param imagePath 印章或手写签名 PNG
     * @param page 目标页（1 起）
     * @param x y 落章坐标（左下角原点）
     * @param width height 印章显示尺寸
     * @param outPath 签署后 PDF
     */
    public void stampImage(String srcPath, String imagePath, int page,
                           float x, float y, float width, float height,
                           String outPath) throws Exception {
        PdfDocument pdfDoc = new PdfDocument(
                new PdfReader(srcPath), new PdfWriter(new FileOutputStream(outPath)));
        PdfCanvas canvas = new PdfCanvas(pdfDoc.getPage(page));
        PdfImageXObject image = new PdfImageXObject(ImageDataFactory.create(imagePath));
        canvas.addXObjectFittedIntoRectangle(image, new Rectangle(x, y, width, height));
        pdfDoc.close();
    }

    /** 读取 PDF 文件字节（计算哈希用） */
    public byte[] readBytes(String filePath) throws Exception {
        return java.nio.file.Files.readAllBytes(new File(filePath).toPath());
    }
}
```

### 4. 签署流程状态机：顺序/并行推进

```java
package com.demo.contract.flow;

import com.demo.contract.entity.Contract;
import com.demo.contract.entity.SignTask;
import com.demo.contract.mapper.ContractMapper;
import com.demo.contract.mapper.SignTaskMapper;
import com.demo.contract.util.BizException;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

import java.util.List;

/**
 * 签署流程状态机
 *
 * 合同状态：DRAFT(草稿) -> SIGNING(签署中) -> COMPLETED(已完成) -> ARCHIVED(已归档)
 *          任意阶段可 CANCELLED(取消)
 * 任务状态：WAITING(等待前序) -> READY(可签) -> SIGNED(已签) / REJECTED(拒签)
 *
 * 顺序模式：只有前序任务 SIGNED 后，下一任务才 WAITING -> READY
 * 并行模式：发起时所有任务直接 READY，全部 SIGNED 即完成
 */
@Service
public class SignFlowService {

    @Autowired
    private ContractMapper contractMapper;
    @Autowired
    private SignTaskMapper signTaskMapper;

    /** 发起签署：合同 DRAFT -> SIGNING，按模式初始化任务状态 */
    @Transactional(rollbackFor = Exception.class)
    public void startSigning(Long contractId) {
        Contract contract = contractMapper.selectById(contractId);
        List<SignTask> tasks = signTaskMapper.selectByContract(contractId);
        if (tasks.isEmpty()) {
            throw new BizException("合同没有签署人，无法发起");
        }
        // 顺序模式：第一任务 READY，其余 WAITING；并行模式：全部 READY
        boolean parallel = "PARALLEL".equals(contract.getSignMode());
        for (int i = 0; i < tasks.size(); i++) {
            SignTask task = tasks.get(i);
            task.setStatus((parallel || i == 0) ? "READY" : "WAITING");
            signTaskMapper.updateById(task);
        }
        contract.setStatus("SIGNING");
        contractMapper.updateById(contract);
    }

    /** 判断指定任务当前是否可签（状态机核心判定） */
    public boolean canSign(Long contractId, Long taskId) {
        Contract contract = contractMapper.selectById(contractId);
        if (contract == null || !"SIGNING".equals(contract.getStatus())) {
            return false;
        }
        SignTask task = signTaskMapper.selectById(taskId);
        return task != null && "READY".equals(task.getStatus());
    }

    /** 任务签署成功后的流程推进 */
    @Transactional(rollbackFor = Exception.class)
    public void onTaskSigned(Long contractId, Long taskId) {
        Contract contract = contractMapper.selectById(contractId);
        List<SignTask> tasks = signTaskMapper.selectByContract(contractId);

        // 全部签署完成 -> 合同 COMPLETED
        boolean allSigned = tasks.stream()
                .allMatch(t -> "SIGNED".equals(t.getStatus()));
        if (allSigned) {
            contract.setStatus("COMPLETED");
            contractMapper.updateById(contract);
            return;
        }
        // 顺序模式：解锁下一个 WAITING 任务
        if ("SEQUENTIAL".equals(contract.getSignMode())) {
            tasks.stream()
                    .filter(t -> "WAITING".equals(t.getStatus()))
                    .findFirst()
                    .ifPresent(next -> {
                        next.setStatus("READY");
                        signTaskMapper.updateById(next);
                    });
        }
    }

    /** 拒签处理：记录原因，流程状态保持，等待发起人处理 */
    @Transactional(rollbackFor = Exception.class)
    public void onTaskRejected(Long contractId, Long taskId, String reason) {
        SignTask task = signTaskMapper.selectById(taskId);
        task.setStatus("REJECTED");
        task.setRejectReason(reason);
        signTaskMapper.updateById(task);
        // 合同状态保持 SIGNING；发起人可在后台取消或调整后重新发起
    }
}
```

### 5. 签署执行：意愿认证 + 数字签名 + 时间戳 + 签章

```java
package com.demo.contract.sign;

import com.demo.contract.crypto.CryptoUtil;
import com.demo.contract.entity.Contract;
import com.demo.contract.entity.SignRecord;
import com.demo.contract.entity.SignTask;
import com.demo.contract.flow.SignFlowService;
import com.demo.contract.mapper.ContractMapper;
import com.demo.contract.mapper.SignRecordMapper;
import com.demo.contract.mapper.SignTaskMapper;
import com.demo.contract.pdf.PdfService;
import com.demo.contract.tsa.TimestampService;
import com.demo.contract.util.BizException;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.data.redis.core.StringRedisTemplate;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

import java.security.KeyPair;
import java.util.Date;
import java.util.concurrent.TimeUnit;

/**
 * 签署执行服务：一次签署 = 意愿认证 -> 内容哈希 -> RSA 签名 -> 时间戳 -> 签章合成 -> 哈希链入链
 */
@Service
public class SignTaskService {

    @Autowired
    private SignTaskMapper signTaskMapper;
    @Autowired
    private SignRecordMapper signRecordMapper;
    @Autowired
    private ContractMapper contractMapper;
    @Autowired
    private SignFlowService signFlowService;
    @Autowired
    private PdfService pdfService;
    @Autowired
    private TimestampService timestampService;
    @Autowired
    private StringRedisTemplate redisTemplate;

    /**
     * 发送签署意愿认证短信验证码（模拟发送，真实场景对接短信服务商）
     */
    public void sendVerifyCode(String phone) {
        // 频控：60s 内只能发一次
        Boolean ok = redisTemplate.opsForValue()
                .setIfAbsent("sms:limit:" + phone + ":sign", "1", 60, TimeUnit.SECONDS);
        if (!Boolean.TRUE.equals(ok)) {
            throw new BizException("发送太频繁，请 60 秒后再试");
        }
        String code = String.format("%06d", (int) (Math.random() * 1000000));
        redisTemplate.opsForValue().set("sms:code:" + phone + ":sign", code, 300, TimeUnit.SECONDS);
        // 模拟发送：真实环境调用 SMS 服务商接口
        System.out.println("[模拟短信] 签署验证码：" + code);
    }

    /**
     * 执行签署
     * @param contractId 合同 id
     * @param taskId 签署任务 id
     * @param smsCode 短信验证码（意愿认证）
     * @param signImagePath 手写签名 PNG 或印章图片路径
     * @param stampPos 签章坐标 JSON（page/x/y/w/h）
     * @param privateKeyBase64 签署人私钥（演示环境传入；生产由 CA/USBKey 提供）
     */
    @Transactional(rollbackFor = Exception.class)
    public SignRecord sign(Long contractId, Long taskId, String smsCode,
                           String signImagePath, String stampPos,
                           String privateKeyBase64, String publicKeyBase64) throws Exception {
        // 1. 状态机校验：任务必须处于 READY 且合同处于 SIGNING
        if (!signFlowService.canSign(contractId, taskId)) {
            throw new BizException("当前任务不可签署（顺序未到或合同状态异常）");
        }
        // 2. 并发防重：同一任务加锁，防止重复签署
        Boolean lock = redisTemplate.opsForValue()
                .setIfAbsent("sign:task:" + taskId + ":lock", "1", 30, TimeUnit.SECONDS);
        if (!Boolean.TRUE.equals(lock)) {
            throw new BizException("该签署任务正在处理中，请勿重复操作");
        }

        SignTask task = signTaskMapper.selectById(taskId);
        // 3. 意愿认证：比对短信验证码（比对后删除，验证码一次性）
        String cached = redisTemplate.opsForValue().get("sms:code:" + task.getSignerPhone() + ":sign");
        if (cached == null || !cached.equals(smsCode)) {
            throw new BizException("验证码错误或已过期");
        }
        redisTemplate.delete("sms:code:" + task.getSignerPhone() + ":sign");
        task.setAuthStatus("AUTHED");

        Contract contract = contractMapper.selectById(contractId);
        // 4. 计算签署时合同文件哈希（指纹）
        byte[] fileBytes = pdfService.readBytes(contract.getFilePath());
        String contentHash = CryptoUtil.sha256File(fileBytes);

        // 5. 数字签名：签署人对内容哈希签名
        java.security.PrivateKey privateKey = CryptoUtil.decodePrivateKey(privateKeyBase64);
        String signature = CryptoUtil.sign(contentHash, privateKey);

        // 6. 时间戳存证：TSA 对内容哈希签发可信时间
        TimestampService.TimestampCert tsCert = timestampService.issueTimestamp(contentHash);

        // 7. 签章合成：签名图片按坐标叠加到 PDF，生成新版本合同文件
        String newFilePath = contract.getFilePath().replace(".pdf", "_signed_" + taskId + ".pdf");
        java.util.Map<String, Object> pos = parseStampPos(stampPos);
        pdfService.stampImage(contract.getFilePath(), signImagePath,
                (int) pos.get("page"), (float) pos.get("x"), (float) pos.get("y"),
                (float) pos.get("w"), (float) pos.get("h"), newFilePath);
        contract.setFilePath(newFilePath);
        contractMapper.updateById(contract);

        // 8. 哈希链：读取前一节点哈希，计算本节点哈希
        String prevHash = contract.getRootHash(); // 链首为合同初始哈希
        SignRecord lastRecord = signRecordMapper.selectLastByContract(contractId);
        if (lastRecord != null) {
            prevHash = lastRecord.getNodeHash(); // 后续节点串接
        }
        String nodeRaw = prevHash + contentHash + task.getSignerName()
                + tsCert.getTsToken() + signature;
        String nodeHash = CryptoUtil.sha256(nodeRaw);

        // 9. 落库：签署记录 + 任务状态推进
        SignRecord record = new SignRecord();
        record.setContractId(contractId);
        record.setTaskId(taskId);
        record.setSignerName(task.getSignerName());
        record.setSignerPubkey(publicKeyBase64); // 签署人公钥（生产从 CA 证书提取）
        record.setAlgorithm("SHA256withRSA");
        record.setContentHash(contentHash);
        record.setSignature(signature);
        record.setTsToken(tsCert.getTsToken());
        record.setPrevHash(prevHash);
        record.setNodeHash(nodeHash);
        record.setStampPos(stampPos);
        record.setSignTime(new Date());
        // 注意：生产环境签署人公钥从证书中提取，此处由调用方传入 publicKeyBase64
        signRecordMapper.insert(record);

        task.setStatus("SIGNED");
        task.setStampPath(signImagePath);
        task.setSignTime(new Date());
        signTaskMapper.updateById(task);

        // 10. 流程推进（解锁下一任务或完成合同）
        signFlowService.onTaskSigned(contractId, taskId);
        return record;
    }

    private java.util.Map<String, Object> parseStampPos(String json) {
        try {
            return new com.fasterxml.jackson.databind.ObjectMapper()
                    .readValue(json, java.util.Map.class);
        } catch (Exception e) {
            throw new BizException("签章坐标格式错误");
        }
    }
}
```

### 6. 哈希链验真服务：防篡改校验与验真报告

```java
package com.demo.contract.verify;

import com.demo.contract.crypto.CryptoUtil;
import com.demo.contract.entity.Contract;
import com.demo.contract.entity.SignRecord;
import com.demo.contract.mapper.ContractMapper;
import com.demo.contract.mapper.SignRecordMapper;
import com.demo.contract.pdf.PdfService;
import com.demo.contract.tsa.TimestampService;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Service;

import java.util.ArrayList;
import java.util.List;

/**
 * 合同验真服务：文件哈希比对 + 哈希链连续性 + 逐节点 RSA 验签 + 时间戳验签
 * 验真结论：PASS(真实可信) / TAMPERED(文件被篡改) / CHAIN_BROKEN(记录被篡改)
 */
@Service
public class VerifyService {

    @Autowired
    private ContractMapper contractMapper;
    @Autowired
    private SignRecordMapper signRecordMapper;
    @Autowired
    private PdfService pdfService;
    @Autowired
    private TimestampService timestampService;

    /**
     * 上传 PDF 验真：文件与链上记录的 contentHash 比对
     */
    public VerifyReport verifyByFile(String contractNo, String filePath) throws Exception {
        Contract contract = contractMapper.selectByNo(contractNo);
        if (contract == null) {
            return VerifyReport.fail("合同不存在: " + contractNo);
        }
        byte[] fileBytes = pdfService.readBytes(filePath);
        String fileHash = CryptoUtil.sha256File(fileBytes);
        return verifyChain(contract, fileHash);
    }

    /**
     * 按合同号验真：以链上记录的 contentHash 为准（文件未变动场景）
     */
    public VerifyReport verifyByContractNo(String contractNo) throws Exception {
        Contract contract = contractMapper.selectByNo(contractNo);
        if (contract == null) {
            return VerifyReport.fail("合同不存在: " + contractNo);
        }
        return verifyChain(contract, null);
    }

    private VerifyReport verifyChain(Contract contract, String fileHash) throws Exception {
        List<String> messages = new ArrayList<>();
        List<SignRecord> records = signRecordMapper.selectByContract(contract.getId());

        // 1. 哈希链连续性：从 rootHash 逐节点重算
        String expectPrev = contract.getRootHash();
        for (SignRecord r : records) {
            if (!expectPrev.equals(r.getPrevHash())) {
                return VerifyReport.fail("哈希链断裂于签署人[" + r.getSignerName()
                        + "]：前一节点哈希不匹配，记录可能被篡改");
            }
            String nodeRaw = r.getPrevHash() + r.getContentHash() + r.getSignerName()
                    + r.getTsToken() + r.getSignature();
            String calcNode = CryptoUtil.sha256(nodeRaw);
            if (!calcNode.equals(r.getNodeHash())) {
                return VerifyReport.fail("哈希链断裂于签署人[" + r.getSignerName()
                        + "]：本节点哈希不匹配，签名或记录被篡改");
            }
            expectPrev = r.getNodeHash();
            messages.add("节点[" + r.getSignerName() + "]哈希链校验通过");
        }

        // 2. 文件一致性：上传文件哈希必须与某个签署节点一致（签署时的文件快照）
        if (fileHash != null) {
            boolean match = records.stream()
                    .anyMatch(r -> r.getContentHash().equals(fileHash));
            if (!match) {
                return VerifyReport.fail("合同文件与所有签署记录哈希均不匹配，文件被篡改");
            }
            messages.add("文件哈希校验通过（与签署时快照一致）");
        }

        // 3. 逐节点 RSA 验签：签署人公钥验 contentHash 的签名
        for (SignRecord r : records) {
            boolean ok = CryptoUtil.verify(r.getContentHash(), r.getSignature(),
                    CryptoUtil.decodePublicKey(r.getSignerPubkey()));
            if (!ok) {
                return VerifyReport.fail("签署人[" + r.getSignerName() + "]的数字签名验签失败");
            }
            messages.add("签署人[" + r.getSignerName() + "]数字签名验签通过");
        }

        // 4. 时间戳验签（本演示用自建 TSA 公钥；生产用权威 TSA 根证书）
        for (SignRecord r : records) {
            // 从存证表取时间戳详情验签（此处简化为用 TSA 公钥重算原始串）
            TimestampService.TimestampCert cert = timestampService
                    .findByToken(r.getTsToken());
            if (cert == null || !timestampService.verifyTimestamp(cert)) {
                return VerifyReport.fail("签署人[" + r.getSignerName() + "]的时间戳验签失败");
            }
            messages.add("签署人[" + r.getSignerName() + "]时间戳验签通过，可信时间=" + cert.getTsTime());
        }

        return VerifyReport.pass(messages);
    }

    /** 验真报告实体 */
    public static class VerifyReport {
        private boolean pass;
        private List<String> messages;
        public static VerifyReport pass(List<String> messages) {
            VerifyReport r = new VerifyReport();
            r.pass = true;
            r.messages = messages;
            return r;
        }
        public static VerifyReport fail(String msg) {
            VerifyReport r = new VerifyReport();
            r.pass = false;
            r.messages = List.of(msg);
            return r;
        }
        // getter 省略
        public boolean isPass() { return pass; }
        public List<String> getMessages() { return messages; }
    }
}
```

```java
package com.demo.contract.web;

 * 合同签署对外接口：模板 -> 创建 -> 发起 -> 签署 -> 验真 全流程编排
 */
@RestController
@RequestMapping("/api/contract")
public class ContractController {

    @Autowired
    private ContractMapper contractMapper;
    @Autowired
    private PdfService pdfService;
    @Autowired
    private SignFlowService signFlowService;
    @Autowired
    private SignTaskService signTaskService;
    @Autowired
    private VerifyService verifyService;

    /**
     * 创建合同：选择模板 + 填变量 -> 生成 PDF -> 建合同记录（DRAFT）
     */
    @PostMapping("/create")
    public Map<String, Object> createContract(@RequestBody CreateContractReq req) throws Exception {
        // 1. 模板变量填充生成未签 PDF（模板与坐标配置由 req 携带，简化示例）
        String outPath = "/data/contracts/" + System.currentTimeMillis() + "_draft.pdf";
        pdfService.fillTemplate(req.getTemplatePath(), req.getVarConfig(),
                req.getVarData(), outPath);

        // 2. 计算初始哈希（哈希链链首）
        byte[] bytes = pdfService.readBytes(outPath);
        String rootHash = CryptoUtil.sha256File(bytes);

        // 3. 落库（contract 记录 + sign_task 列表由事务批量写入，此处省略 mapper 细节）
        Contract contract = new Contract();
        contract.setContractNo("HT" + System.currentTimeMillis());
        contract.setTitle(req.getTitle());
        contract.setFilePath(outPath);
        contract.setRootHash(rootHash);
        contract.setSignMode(req.getSignMode());
        contract.setStatus("DRAFT");
        contractMapper.insert(contract);

        Map<String, Object> result = new HashMap<>();
        result.put("contractNo", contract.getContractNo());
        result.put("contractId", contract.getId());
        result.put("rootHash", rootHash);
        return result;
    }

    /**
     * 发起签署：DRAFT -> SIGNING，按模式初始化任务
     */
    @PostMapping("/{contractId}/start")

        signFlowService.startSigning(contractId);
    }

     * 发送意愿认证验证码
     */
    @PostMapping("/sms-code")

        signTaskService.sendVerifyCode(phone);

    /**
     * 执行签署（演示：私钥/公钥由演示环境生成后传入，生产从 CA 证书提取）

    @PostMapping("/{contractId}/tasks/{taskId}/sign")

                .encodeToString(keyPair.getPrivate().getEncoded());
        String publicKey = java.util.Base64.getEncoder()
                .encodeToString(keyPair.getPublic().getEncoded());
        signTaskService.sign(contractId, taskId, req.getSmsCode(),
                req.getSignImagePath(), req.getStampPos(), privateKey, publicKey);
    }

        public String signMode;
    }

        public String smsCode;
        public String signImagePath;
        public String stampPos;
    }
}
```

## 实际应用场景

### 场景一：HR 劳动合同批量签署（顺序签署）

新员工入职当天要完成劳动合同签署，合同需要「公司先盖章、员工后签名」的顺序流程：

```text
1. HR 上传劳动合同模板 PDF，配置变量坐标：员工姓名/岗位/薪资/合同期限/签署区
2. HR 在系统发起合同：选模板 → 填变量（王小明/Java 工程师/25K/三年）→ 生成未签 PDF
3. 配置签署顺序：公司（证书签名，顺序 1）→ 员工（手写签名，顺序 2），模式 SEQUENTIAL
4. 系统创建合同 DRAFT，生成 rootHash；发起后转 SIGNING，公司任务置 READY
5. 公司侧自动完成印章签署（印章图片 + 企业私钥签名 + 时间戳），流程解锁员工任务
6. 员工收到签署短信，打开链接 → 输入验证码 → 预览合同 → canvas 手写签名
7. 员工签名合成到 PDF 签署区，记录哈希链节点，合同 COMPLETED 自动归档
8. 三个月后员工争议薪资：法务上传归档 PDF 验真，输出 PASS 报告（含双方签名与时间戳），司法举证完成
```

### 场景二：采购合同多方并行签署（并行签署）

三方采购合同（采购方、供应商、担保方）互相不依赖，可以同时签：

```text
1. 采购发起合同，配置三个签署人，模式 PARALLEL，三个任务同时置 READY
2. 三方同时收到短信，各自登录签署（互不等待，缩短签署周期）
3. 每方签署：验证码意愿认证 → 预览合同 → 手写签名/证书签名 → 时间戳存证
4. 三方签署记录依次写入哈希链（顺序以实际签署时间为准）
5. 最后一方签署完成时合同状态置 COMPLETED，自动触发归档
6. 任何一方在签署中拒签：流程保持 SIGNING，发起人收到拒签原因后调整重新发起
7. 对比纸质流程：原来三地快递轮流签要 2 周，现在 1 天完成
```

### 场景三：合同验真与司法存证

发生合同纠纷时，双方各执一份合同文件，需要判断哪份是原件、是否被篡改：

```text
1. 原告上传自己手里的合同 PDF，输入合同编号
2. 系统重算文件 SHA-256，与哈希链上各签署节点的 contentHash 比对
3. 发现文件哈希与签署时快照一致 → 文件未被篡改；不一致 → 定位到被改动的签署节点
4. 系统从 rootHash 起逐节点重算哈希链，验证记录连续性（防数据库记录被改）
5. 逐节点 RSA 验签：每份签名必须能由对应签署人公钥验证通过
6. 逐节点时间戳验签：确认签署时间可信且未被回溯修改
7. 输出验真报告：真/伪/篡改结论 + 每节点明细（签署人/时间/算法），导出 PDF 作为举证材料
```

## 最佳实践与踩坑记录

### 最佳实践

1. 哈希链锚定合同原文：链首 rootHash 是「合同初始文件字节」的哈希，后续每个节点都串接前一节点哈希，任何一处改动（文件或记录）都会导致链条断裂——这是防篡改的根本设计
2. 签署文件不可变：每次签署生成新版本 PDF（路径带 taskId），绝不原地修改已签署文件，旧版本保留可追溯
3. 意愿认证前置：短信验证码校验通过才允许签名，且验证码一次性（比对后删除），杜绝代签与抵赖
4. 状态机集中控制：合同状态与任务状态的流转全部收敛在 SignFlowService，任何签署接口必须先过 canSign 判定，防止绕过流程直接调签名接口
5. 签名算法接口化：CryptoUtil 封装签名/验签/哈希，国密 SM2 替换时只改工具类实现，业务层零改动
6. 时间戳与签名解耦：时间戳由独立 TSA 服务签发并单独存表（timestamp_cert），验真时分别验证签名与时间戳，职责清晰
7. 模板版本快照：发起合同时锁定模板版本（tpl_version），后续模板修改不影响已发起合同的变量坐标
8. 并发防重：同一签署任务用 Redis SETNX 加锁，配合数据库唯一键（uk_task），双保险防重复签署

### 踩坑记录

```text
坑 1：PDF 坐标定位不准，变量填到错误位置
结论：合同模板生成后变量文字错位、超出签署区。
原因：PDF 坐标系原点在左下角（y 向上），前端预览坐标系原点在左上角（y 向下），两套坐标直接混用。
解法：统一约定后端 PDF 坐标（左下角原点，单位 pt），前端预览时做 y 轴翻转换算；模板上线前用「坐标可视化校准」页面逐变量确认。

坑 2：中文文本写入 PDF 乱码
结论：iText 写入中文变量变成方框或乱码。
原因：默认 Helvetica 字体不含中文字形，未注册中文字体。
解法：使用 STSong-Light + UniGB-UCS2-H 内置 CID 字体（或注册系统黑体/宋体 TTF），并设置 PREFER_EMBEDDED 嵌入字体保证跨端渲染一致。

坑 3：签名私钥放服务端内存，安全风险
结论：演示环境为每个签署人生成密钥对并下发私钥，被质疑私钥泄露风险。
原因：为跑通流程简化实现，把私钥当普通参数传来传去。
解法：演示代码中明确注释「生产必须由 CA 证书或 USBKey/手机盾提供私钥，服务端只收签名结果不收私钥」；正式方案对接 CA 签名服务（如 eSeal）由服务端代签或客户端 H5 盾签。

坑 4：哈希链节点数据没算全，验真时链对不上
结论：升级代码后验真全部失败，哈希链全断。
原因：nodeHash 计算串里字段顺序与验真时不一致（少拼了 tsToken 或换了字段顺序），字符串拼接顺序必须完全一致。
解法：把「节点原文拼接规则」抽成唯一方法（HashChainService.computeNodeHash），签署与验真都调它，杜绝两处手写拼接不一致。

坑 5：验证码并发重放
结论：同一验证码被两次签署使用，产生两条签署记录。
原因：校验验证码和删除验证码不是原子操作，两次请求并发都读到验证码。
解法：校验与删除合并为 Redis 原子操作（Lua 脚本：GET 比对一致才 DEL），或先 DEL 拿到返回值再判断；再加任务级 SETNX 锁兜底。

坑 6：签署后文件被覆盖
结论：第二个人签署后，第一个人的签署记录验真失败。
原因：签章合成时直接覆盖了 contract.file_path 指向的文件，且记录里没存每个节点的文件快照。
解法：每次签署生成带 taskId 的新文件，sign_record 记录签署时的 contentHash（文件指纹），验真时逐节点比对，而不是只比对「当前文件」。

坑 7：并行签署时最后一方完成判定竞态
结论：三方并行签署，最后两方同时完成，合同状态没置为 COMPLETED。
原因：onTaskSigned 里「查全部任务 → 判断全 SIGNED → 更新合同」不是原子的，两个并发事务互相读到对方未提交的状态。
解法：状态推进方法加 @Transactional 并配合行锁（select ... for update 锁合同行），或用「更新计数」方式：每次签署原子 INCR 签署计数，计数等于任务总数时置 COMPLETED。
```

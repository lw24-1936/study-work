## 项目背景

物流配送管理系统是电商履约的「最后一环」：用户在电商下单后，货从仓库出发，经过揽收、干线运输、中转、派送、签收，最终到用户手里，中间还可能发生退回、改址、滞留等异常。这个系统管理的不只是「一张运单」，而是一条「从揽收到签收的状态机 + 每一步的时间与位置轨迹链 + 按区域与承运商的路由决策」。选择它作为综合实战项目，是因为它把状态机建模、轨迹时间线、策略路由这些后端设计模式用到了极致，同时天然依赖 Redis（运单缓存、轨迹热点、任务队列）与 MySQL（运单主数据、轨迹流水）的分工协作。

业务痛点：

```text
1. 状态混乱：运单没有统一状态模型，各环节各写各的，客服查不到真实进度
2. 轨迹断裂：只有「已发货」和「已签收」，中间环节全靠人工电话确认
3. 路由靠经验：承运商、线路选择靠老员工拍脑袋，成本高且不稳定
4. 异常无流程：退回、改址、滞留全靠微信群里喊，处理超时无追踪
5. 运费算不清：不同区域不同计费规则，手工算错账，与承运商对账困难
6. 单号散落：电商订单、仓库出库单、物流运单之间没有关联关系
7. 客服压力大：用户查件全打客服电话，没有自助查询入口
```

目标用户与核心诉求：

```text
1. 仓储发货员：快速建单、批量打印面单、交接给承运商
2. 运输调度：按区域/承运商/时效路由分派，异常运输监控
3. 派送员：接单、扫描、签收/异常上报，移动端操作
4. 客服人员：运单全链路轨迹可查，异常件处理进度可见
5. 财务人员：运费按规则自动计算，与承运商月度对账
6. 终端用户：实时查看包裹轨迹，异常时了解处理进展
```

项目要解决的核心问题一句话概括：用状态机把运单生命周期管起来，用轨迹链记录每一步节点与时间，用路由规则把运单分派给最合适的承运商，让每一件货「状态清晰、轨迹可查、异常可控、费用可算」。

## 功能介绍

功能按业务阶段拆分：运单管理、状态流转、轨迹查询、路由分派、异常件处理、运费与统计。

```text
一、运单管理
1. 运单创建 —— 手动建单 / 对接电商订单批量建单，生成唯一运单号
2. 运单查询 —— 按运单号/电商订单号/手机号/收件人多维检索
3. 面单打印 —— 电子面单生成与打印（对接快递电子面单模板）
4. 运单作废 —— 未揽收的运单可作废，已揽收需走异常流程

二、状态机流转
1. 状态定义 —— 待揽收/已揽收/运输中/已到达/派送中/已签收/异常
2. 流转控制 —— 非法状态跳转拦截（如未揽收不能直接签收）
3. 自动流转 —— 扫描枪/司机 App 上报节点自动推进状态
4. 状态回退 —— 特殊场景人工回退（如派送失败退回网点），全程留痕

三、轨迹记录
1. 节点上报 —— 各环节上报节点+时间+地点+操作人，形成轨迹链
2. 轨迹查询 —— 用户端/客服端按时间倒序查看完整轨迹
3. 轨迹快照 —— 首条与最后一条轨迹进入运单主表（揽收/签收时间）
4. 轨迹补录 —— 漏扫场景人工补录，标注补录标记

四、路由分派
1. 区域规则 —— 按收件省市区匹配承运商与线路
2. 承运商管理 —— 承运商档案、覆盖区域、时效承诺、价格表
3. 分派策略 —— 默认策略（区域优先）/成本优先/时效优先可配置
4. 人工改派 —— 自动分派结果可人工干预，记录改派原因

五、异常件处理
1. 异常上报 —— 退回/改址/滞留/破损/拒收五类异常登记
2. 异常流程 —— 退回（原路退回）/改址（新地址重新派送）/滞留（催派）
3. 超时预警 —— 异常件 24 小时未处理自动升级提醒
4. 异常统计 —— 各环节异常率、原因分布报表

六、运费与统计
1. 运费计算 —— 按区域+重量+首续重规则自动计算
2. 运费对账 —— 与承运商账单核对，差异标记
3. 物流时效 —— 各线路平均时效、准时率统计
4. 发货量看板 —— 按日/承运商/区域统计发货量
```

## 技术选型

| 组件 | 选型 | 理由 |
|------|------|------|
| 开发框架 | Spring Boot 2.7/3.x | 生态成熟，Web 服务与定时任务支持完善 |
| 持久层 | MyBatis-Plus | 运单/轨迹/规则表标准 CRUD，条件构造器查询方便 |
| 数据库 | MySQL 8.0 | 运单主数据与轨迹流水落库，事务保证状态一致性 |
| 缓存 | Redis | 运单热点缓存、轨迹队列、状态机流转防重、任务锁 |
| 状态机 | 自研状态机组件（Map 驱动） | 轻量可控，无额外框架依赖；也可选 Spring StateMachine |
| 前端 | Vue 3 + Element Plus（管理端）/ 小程序（派送员端） | 管理后台与移动作业双端 |
| 消息 | RabbitMQ（可选） | 节点上报异步解耦、轨迹通知推送 |
| 定时任务 | XXL-Job | 异常件超时升级、运单状态兜底扫描 |
| 构建 | Maven | 依赖管理标准工具 |

选型说明：

```text
1. 状态机自研而非引入框架：物流状态流转规则简单直接（十来个状态、二十来条流转），
   Map 驱动的事件表足够清晰，出问题好排查；真要扩展再上 Spring StateMachine
2. 轨迹用「写流水、读聚合」：轨迹上报高频写 MySQL 流水表，首尾快照冗余进运单主表，
   查询列表页不需要 join 轨迹表
3. Redis 承担四件事：运单详情缓存（客服高频查）、轨迹热点（用户端查件）、
   节点上报幂等（防重复扫描）、路由规则缓存
4. 状态变更必须走 Service 统一方法：禁止 Mapper 直接改状态，保证流转校验不绕路
```

```text
└──────────────────┘   └───────────────┘   └─────────────────┘
```

节点上报请求链路（派送员扫描「派送中」）：

```text
1. 派送员 App 扫描运单条码，上报节点码（如 ARRIVE_CITY / DELIVERING）+ 位置
2. 网关鉴权（派送员账号），路由到轨迹上报接口
3. 幂等校验：Redis SET NX trace:{waybillNo}:{nodeCode}，防止重复扫描
4. 状态机引擎校验流转合法性：当前状态「已到达」-> 目标状态「派送中」允许
5. 事务内：更新运单状态 + 写轨迹流水（节点+时间+地点+操作人）
6. 更新运单主表快照字段（last_trace），删除运单 Redis 缓存（先更库后删缓存）
7. 异步通知：向用户推送轨迹消息（MQ 解耦，可选）
8. 返回成功，App 展示下一节点可扫的提示
```

Redis Key 设计：

```text
1. waybill:detail:{waybillNo}     运单详情缓存（客服高频查询），TTL 30 分钟，状态变更即删
2. waybill:trace:hot:{waybillNo}  最近 3 条轨迹热点缓存，TTL 5 分钟（用户端查件）
3. trace:dedup:{waybillNo}:{node} 节点上报幂等标记（SET NX EX 24h），防重复扫描
4. route:rule:cache               路由规则全量缓存（Hash），规则变更即删
5. lock:waybill:status:{waybillNo} 运单状态变更分布式锁，防并发流转
6. abnormal:escalate             异常件超时升级 ZSet（score=创建时间），定时扫描
7. stat:ship:{yyyyMMdd}           当日发货量/各承运商发货量计数器，定时聚合刷库
```

## 核心实现

### 1. 运单创建（批量建单 + 路由预分派）

```java
@Service
public class WaybillService {

    @Autowired
    private WaybillMapper waybillMapper;
    @Autowired
    private RouteDispatchService routeDispatchService;
    @Autowired
    private FreightService freightService;

    /**
     * 创建运单（支持批量）
     * 流程：校验地址 -> 生成运单号 -> 路由分派承运商 -> 计算运费 -> 落库
     */
    @Transactional(rollbackFor = Exception.class)
    public String createWaybill(WaybillCreateDTO dto) {
        Waybill wb = new Waybill();
        wb.setWaybillNo(genWaybillNo());   // WB + 年月日 + 随机序号
        wb.setBizOrderNo(dto.getBizOrderNo());
        wb.setSenderName(dto.getSenderName());
        wb.setSenderPhone(dto.getSenderPhone());
        wb.setSenderAddr(dto.getSenderAddr());
        wb.setReceiverName(dto.getReceiverName());
        wb.setReceiverPhone(dto.getReceiverPhone());
        wb.setReceiverAddr(dto.getReceiverAddr());
        // 收件地址拆出省市区分词，路由分派与运费计算都靠它
        wb.setReceiverProvince(dto.getReceiverProvince());
        wb.setReceiverCity(dto.getReceiverCity());
        wb.setReceiverDistrict(dto.getReceiverDistrict());
        wb.setWeight(dto.getWeight());
        wb.setStatus(0);   // 待揽收
        // 1. 路由分派：按收件区域匹配承运商
        Long carrierId = routeDispatchService.dispatch(wb);
        wb.setCarrierId(carrierId);
        // 2. 运费计算：按承运商与区域规则
        wb.setFreight(freightService.calc(dto.getWeight(),
                dto.getReceiverProvince(), dto.getReceiverCity(), carrierId));
        waybillMapper.insert(wb);
        // 3. 写首条轨迹：待揽收（部分系统在分派后写）
        traceService.append(wb.getWaybillNo(), "CREATED", "已创建待揽收",
                dto.getSenderAddr(), "系统", null);
        return wb.getWaybillNo();
    }

    /** 批量建单：电商订单批量导入 */
    public List<String> batchCreate(List<WaybillCreateDTO> list) {
        List<String> nos = new ArrayList<>();
        for (WaybillCreateDTO dto : list) {
            nos.add(createWaybill(dto));   // 每单独立事务，单笔失败不影响其余
        }
        return nos;
    }

    /** 运单详情（Redis 缓存优先） */
    public WaybillDetailVO detail(String waybillNo) {
        String key = "waybill:detail:" + waybillNo;
        Object cached = redisTemplate.opsForValue().get(key);
        if (cached != null) {
            return (WaybillDetailVO) cached;
        }
        Waybill wb = waybillMapper.selectOne(
                new LambdaQueryWrapper<Waybill>().eq(Waybill::getWaybillNo, waybillNo));
        if (wb == null) {
            return null;
        }
        // 组装：运单 + 承运商名称 + 最近轨迹
        WaybillDetailVO vo = assemble(wb);
        redisTemplate.opsForValue().set(key, vo, 30, TimeUnit.MINUTES);
        return vo;
    }
}
```

### 2. 状态机引擎（Map 驱动，核心难点）

```java
@Component
public class WaybillStateMachine {

    /** 状态常量 */
    public static final int PENDING   = 0;   // 待揽收
    public static final int PICKED    = 1;   // 已揽收
    public static final int TRANSIT   = 2;   // 运输中
    public static final int ARRIVED   = 3;   // 已到达
    public static final int DELIVERING = 4;  // 派送中
    public static final int SIGNED    = 5;   // 已签收
    public static final int ABNORMAL  = 6;   // 异常

    /** 合法流转表：key = 当前状态，value = 允许跳转的目标状态集合 */
    private static final Map<Integer, Set<Integer>> TRANSITIONS = new HashMap<>();

    static {
        TRANSITIONS.put(PENDING,    Set.of(PICKED, ABNORMAL));
        TRANSITIONS.put(PICKED,     Set.of(TRANSIT, ABNORMAL));
        TRANSITIONS.put(TRANSIT,    Set.of(ARRIVED, ABNORMAL));
        TRANSITIONS.put(ARRIVED,    Set.of(DELIVERING, ABNORMAL));
        TRANSITIONS.put(DELIVERING, Set.of(SIGNED, ABNORMAL));
        TRANSITIONS.put(ABNORMAL,   Set.of(PICKED, TRANSIT, ARRIVED, DELIVERING, SIGNED));
        // 异常态可回到正常链路（退回重揽、改址重新派送等）
    }

    /**
     * 状态流转核心：校验 + 变更 + 留痕
     * 返回 false 表示非法流转
     */
    public boolean fire(Waybill wb, int targetStatus, String operator) {
        int current = wb.getStatus();
        // 1. 同状态幂等返回（重复扫描不报错）
        if (current == targetStatus) {
            return true;
        }
        // 2. 校验流转合法性
        Set<Integer> allowed = TRANSITIONS.getOrDefault(current, Collections.emptySet());
        if (!allowed.contains(targetStatus)) {
            log.warn("非法状态流转: {} -> {}, 运单={}",
                    current, targetStatus, wb.getWaybillNo());
            return false;
        }
        // 3. 状态落库（条件更新：当前状态必须还是 current，防并发覆盖）
        int rows = waybillMapper.updateStatusIf(
                wb.getWaybillNo(), current, targetStatus);
        if (rows == 0) {
            return false;   // 并发下状态已被其他请求变更
        }
        // 4. 写轨迹（由调用方在事务内统一处理）
        return true;
    }
}
```

```xml
  SET status = #{target}
```

### 3. 轨迹服务（节点上报 + 轨迹链查询）

```java
@Service
public class TraceService {

    @Autowired
    private WaybillTraceMapper traceMapper;
    @Autowired
    private WaybillMapper waybillMapper;
    @Autowired
    private WaybillStateMachine stateMachine;
    @Autowired
    private StringRedisTemplate stringRedisTemplate;

    /**
     * 节点上报统一入口（派送员 App / 仓库扫描枪 / 司机端）
     * 流程：幂等去重 -> 状态机校验 -> 事务内更新状态 + 写轨迹 + 刷缓存
     */
    @Transactional(rollbackFor = Exception.class)
    public boolean reportNode(String waybillNo, String nodeCode, String nodeName,
                              String location, String operator, String remark) {
        // 1. 幂等：同一运单同一节点只处理一次（防重复扫描）
        String dedupKey = "trace:dedup:" + waybillNo + ":" + nodeCode;
        Boolean first = stringRedisTemplate.opsForValue()
                .setIfAbsent(dedupKey, "1", Duration.ofHours(24));
        if (!Boolean.TRUE.equals(first)) {
            return true;   // 重复上报，幂等返回
        }
        // 2. 查运单，映射节点 -> 目标状态
        Waybill wb = waybillMapper.selectOne(
                new LambdaQueryWrapper<Waybill>().eq(Waybill::getWaybillNo, waybillNo));
        if (wb == null) {
            return false;
        }
        int targetStatus = mapNodeToStatus(nodeCode);   // PICKED_UP->1, IN_TRANSIT->2 ...
        // 3. 状态机校验并流转（同状态返回 true，非法返回 false）
        if (!stateMachine.fire(wb, targetStatus, operator)) {
            throw new BusinessException("节点上报与当前运单状态冲突");
        }
        // 4. 写轨迹流水（节点 + 时间 + 地点 + 操作人）
        WaybillTrace trace = new WaybillTrace();
        trace.setWaybillNo(waybillNo);
        trace.setNodeCode(nodeCode);
        trace.setNodeName(nodeName);
        trace.setLocation(location);
        trace.setOperator(operator);
        trace.setRemark(remark);
        trace.setTraceTime(LocalDateTime.now());
        traceMapper.insert(trace);
        // 5. 签收时回填签收时间快照
        if (targetStatus == WaybillStateMachine.SIGNED) {
            waybillMapper.updateReceiveTime(waybillNo, trace.getTraceTime());
        }
        // 6. 删运单缓存（先更库后删缓存）
        redisTemplate.delete("waybill:detail:" + waybillNo);
        redisTemplate.delete("waybill:trace:hot:" + waybillNo);
        return true;
    }

    /**
     * 轨迹链查询：时间倒序返回全部节点
     * 用户端取最近 3 条走热点缓存，客服端查全量走 MySQL
     */
    public List<WaybillTrace> traceList(String waybillNo) {
        return traceMapper.selectList(new LambdaQueryWrapper<WaybillTrace>()
                .eq(WaybillTrace::getWaybillNo, waybillNo)
                .orderByDesc(WaybillTrace::getTraceTime));
    }

    /**
     * 轨迹补录：漏扫场景人工补录，必须带补录标记，时间可指定
     */
    @Transactional(rollbackFor = Exception.class)
    public void backfillTrace(String waybillNo, String nodeCode, String nodeName,
                              String location, String operator, LocalDateTime traceTime) {
        WaybillTrace trace = new WaybillTrace();
        trace.setWaybillNo(waybillNo);
        trace.setNodeCode(nodeCode);
        trace.setNodeName(nodeName);
        trace.setLocation(location);
        trace.setOperator(operator);
        trace.setRemark("人工补录");
        trace.setTraceTime(traceTime);
        traceMapper.insert(trace);
    }
}
```

### 4. 路由分派（区域规则匹配）

```java
@Service
public class RouteDispatchService {

    @Autowired
    private RouteRuleMapper routeRuleMapper;
    @Autowired
    private CarrierMapper carrierMapper;

    /**
     * 路由分派：按收件省/市匹配路由规则，选权重最高的承运商
     * 匹配优先级：省+市 精确 > 省级 > 全国兜底
     */
    public Long dispatch(Waybill wb) {
        List<RouteRule> rules = routeRuleMapper.selectList(
                new LambdaQueryWrapper<RouteRule>().eq(RouteRule::getEnable, 1));
        // 1. 三级匹配：先市、再省、最后全国
        RouteRule best = rules.stream()
                .filter(r -> wb.getReceiverCity().equals(r.getCity()))
                .max(Comparator.comparingInt(RouteRule::getWeight))
                .orElse(null);
        if (best == null) {
            best = rules.stream()
                    .filter(r -> r.getCity() == null
                            && wb.getReceiverProvince().equals(r.getProvince()))
                    .max(Comparator.comparingInt(RouteRule::getWeight))
                    .orElse(null);
        }
        if (best == null) {
            best = rules.stream()
                    .filter(r -> r.getProvince() == null && r.getCity() == null)
                    .max(Comparator.comparingInt(RouteRule::getWeight))
                    .orElse(null);
        }
        if (best == null) {
            throw new BusinessException("收件区域 " + wb.getReceiverCity() + " 暂无可用承运商");
        }
        // 2. 校验承运商状态与覆盖区域
        Carrier carrier = carrierMapper.selectById(best.getCarrierId());
        if (carrier == null || carrier.getStatus() != 1) {
            throw new BusinessException("匹配到的承运商已停用: " + best.getCarrierId());
        }
        return carrier.getId();
    }

    /**
     * 人工改派：记录改派日志（此处简化为直接更新运单承运商）
     * 已揽收的运单改派必须走异常流程，防止「货已交给 A 承运商却显示 B 承运商」
     */
    @Transactional(rollbackFor = Exception.class)
    public void reassign(String waybillNo, Long newCarrierId, String operator, String reason) {
        Waybill wb = waybillMapper.selectOne(
                new LambdaQueryWrapper<Waybill>().eq(Waybill::getWaybillNo, waybillNo));
        if (wb == null) {
            throw new BusinessException("运单不存在");
        }
        if (wb.getStatus() != WaybillStateMachine.PENDING) {
            throw new BusinessException("运单已揽收，改派需先登记异常退回");
        }
        Waybill update = new Waybill();
        update.setId(wb.getId());
        update.setCarrierId(newCarrierId);
        waybillMapper.updateById(update);
        traceService.append(waybillNo, "REASSIGN", "承运商改派",
                reason, operator, "由" + wb.getCarrierId() + "改为" + newCarrierId);
    }
}
```

### 5. 异常件处理（退回 / 改址 / 滞留）

```java
@Service
public class AbnormalService {

    @Autowired
    private AbnormalWaybillMapper abnormalMapper;
    @Autowired
    private WaybillMapper waybillMapper;
    @Autowired
    private TraceService traceService;

    /**
     * 异常登记：异常类型 + 描述，运单状态置为异常（6）
     * 一个运单可叠加多个异常（如先滞留后改址）
     */
    @Transactional(rollbackFor = Exception.class)
    public Long register(String waybillNo, int abnormalType,
                         String description, String operator) {
        Waybill wb = waybillMapper.selectOne(
                new LambdaQueryWrapper<Waybill>().eq(Waybill::getWaybillNo, waybillNo));
        if (wb == null) {
            throw new BusinessException("运单不存在");
        }
        // 1. 登记异常记录（待处理）
        AbnormalWaybill abnormal = new AbnormalWaybill();
        abnormal.setWaybillNo(waybillNo);
        abnormal.setAbnormalType(abnormalType);
        abnormal.setDescription(description);
        abnormal.setStatus(0);
        abnormalMapper.insert(abnormal);
        // 2. 运单标记异常 + 状态机流转到异常态
        Waybill update = new Waybill();
        update.setId(wb.getId());
        update.setIsAbnormal(1);
        update.setStatus(WaybillStateMachine.ABNORMAL);
        waybillMapper.updateById(update);
        // 3. 写异常轨迹
        traceService.append(waybillNo, "ABNORMAL", "异常件登记",
                description, operator, abnormalTypeDesc(abnormalType));
        return abnormal.getId();
    }

    /**
     * 退回处理：原路退回，运单回到待揽收之前的反向流程
     * 简化模型：退回即走「派送中 -> 退回中 -> 已退回」反向状态（此处标记处理完成）
     */
    @Transactional(rollbackFor = Exception.class)
    public void handleReturn(Long abnormalId, String handler) {
        AbnormalWaybill abnormal = abnormalMapper.selectById(abnormalId);
        if (abnormal == null || abnormal.getStatus() != 0) {
            throw new BusinessException("异常记录不存在或已处理");
        }
        // 更新异常处理状态
        AbnormalWaybill update = new AbnormalWaybill();
        update.setId(abnormalId);
        update.setStatus(2);
        update.setHandler(handler);
        update.setHandleTime(LocalDateTime.now());
        update.setHandleResult("已发起原路退回");
        abnormalMapper.updateById(update);
        // 写轨迹：退回中
        traceService.append(abnormal.getWaybillNo(), "RETURNING", "退回中",
                "原路退回", handler, null);
    }

    /**
     * 改址处理：登记新地址，重新进入派送环节
     */
    @Transactional(rollbackFor = Exception.class)
    public void handleAddressChange(Long abnormalId, String newAddress, String handler) {
        AbnormalWaybill abnormal = abnormalMapper.selectById(abnormalId);
        // 更新异常记录：改址类型填新地址
        AbnormalWaybill update = new AbnormalWaybill();
        update.setId(abnormalId);
        update.setNewAddress(newAddress);
        update.setStatus(2);
        update.setHandler(handler);
        update.setHandleTime(LocalDateTime.now());
        update.setHandleResult("已改址: " + newAddress);
        abnormalMapper.updateById(update);
        // 写轨迹：改址后重新派送
        traceService.append(abnormal.getWaybillNo(), "ADDRESS_CHANGED", "收件地址变更",
                newAddress, handler, null);
        // 运单状态回到派送中，重新派送（省略状态机回退细节）
    }

    /**
     * 异常超时升级：异常登记 24 小时未处理的自动升级提醒
     * 定时任务调用，返回超时清单
     */
    public List<AbnormalWaybill> escalateTimeout() {
        return abnormalMapper.selectList(new LambdaQueryWrapper<AbnormalWaybill>()
                .eq(AbnormalWaybill::getStatus, 0)
                .lt(AbnormalWaybill::getCreateTime, LocalDateTime.now().minusHours(24)));
    }
```

### 6. 运费计算（首重续重规则）

```java
@Service
public class FreightService {

    @Autowired
    private FreightRuleMapper freightRuleMapper;

    /**
     * 运费计算：按「寄达省/市」匹配运费规则，首重 + 续重计价
     * 例：规则 首重1kg=8元 续重2元/kg，3.5kg 包裹 = 8 + ceil(2.5)*2 = 14 元
     */
    public BigDecimal calc(BigDecimal weight, String province,
                           String city, Long carrierId) {
        // 1. 匹配规则：市精确 > 省 > 全国兜底
        FreightRule rule = freightRuleMapper.selectOne(
                new LambdaQueryWrapper<FreightRule>()
                        .eq(FreightRule::getCity, city)
                        .eq(FreightRule::getStatus, 1));
        if (rule == null) {
            rule = freightRuleMapper.selectOne(
                    new LambdaQueryWrapper<FreightRule>()
                            .eq(FreightRule::getProvince, province)
                            .isNull(FreightRule::getCity)
                            .eq(FreightRule::getStatus, 1));
        }
        if (rule == null) {
            rule = freightRuleMapper.selectOne(
                    new LambdaQueryWrapper<FreightRule>()
                            .isNull(FreightRule::getProvince)
                            .isNull(FreightRule::getCity)
                            .eq(FreightRule::getStatus, 1));
        }
        if (rule == null) {
            throw new BusinessException("寄达区域 " + city + " 未配置运费规则");
        }
        // 2. 计算：首重 + 续重（不足 1kg 按 1kg 计）
        BigDecimal extra = weight.subtract(rule.getFirstWeight());
        BigDecimal extraFee = BigDecimal.ZERO;
        if (extra.compareTo(BigDecimal.ZERO) > 0) {
            // 向上取整续重公斤数
            BigDecimal extraKg = extra.setScale(0, RoundingMode.CEILING);
            extraFee = extraKg.multiply(rule.getExtraPrice());
        }
        return rule.getFirstPrice().add(extraFee);
    }
}
```

## 实际应用场景

### 场景一：电商自建物流（区域仓配一体）

某电商平台自建仓储与配送网络，系统负责全国发货：

```text
1. 用户下单后 ERP 生成出库单，系统批量创建运单并自动匹配承运商（区域规则：华东走自家车队，偏远地区走顺丰）

5. 派送员上门，上报「派送中」，用户 App 实时看到包裹位置与预计送达时间
6. 用户签收，状态流转「已签收」，签收时间快照回填，运费按规则自动计算
```

快递 SaaS 平台聚合多家承运商，为中小商家提供统一发货入口：

```text
1. 商家导入订单，系统按收件区域在承运商 A/B/C 之间自动路由（权重与价格系数可配）

5. 派送失败（拒收/地址错误）登记异常件，超 24 小时未处理自动升级到平台客服
6. 月度与各承运商对账：运费按平台计算值与承运商账单核对，差异单逐笔核实
7. 平台看板按承运商维度统计发货量、签收时效、异常率，作为次年合同谈判依据
```

### 场景三：同城即时配送（时效敏感型）

生鲜电商同城配送，对时效要求极高，状态机与轨迹粒度更细：

## 最佳实践与踩坑记录

### 最佳实践

1. 状态机用「流转表」集中定义：所有合法流转写在一张 Map 里，状态变更必须走状态机引擎，Mapper 不允许直接改 status
2. 状态落库用条件更新（WHERE status = 期望值）：并发场景下只有第一个请求生效，杜绝状态被覆盖
3. 轨迹「写流水、留快照」：轨迹表只 append 不 update，首尾节点冗余到运单主表，列表页与详情页不 join 轨迹表
4. 节点上报必须幂等：同一运单同一节点重复扫描要能容忍（SET NX + 同状态幂等返回），扫描枪抖动是常态
5. 路由规则三级兜底：市精确 > 省 > 全国，缺失任何一级都能落到兜底承运商，宁慢不能断
6. 改派已揽收运单必须走异常流程：货已经在 A 承运商手里，直接改派会造成「系统显示 B 承运商、实际货在 A」的错乱
7. 运费计算统一走规则引擎：首重续重规则表驱动，禁止代码里写死价格，改价只改表不发布

### 踩坑记录

```text
坑 1：状态被绕过直接改库
结论：运单显示已签收，但没有任何揽收轨迹。
原因：排障时开发直接 UPDATE waybill SET status = 5，绕过了状态机。
解法：状态变更收敛到状态机引擎单一入口，数据库层加状态流转触发器兜底；
     code review 禁止直接写 status 字段的 SQL。

坑 2：重复扫描导致轨迹重复
结论：用户看到两条一模一样的「已签收」轨迹。
原因：扫描枪网络重试，同一节点上报两次，没有幂等。
解法：节点上报前 SET NX 幂等标记 + 状态机同状态幂等返回；
     轨迹表加唯一索引 uk(waybill_no, node_code, trace_time 分钟级)，双保险。

坑 3：并发流转状态覆盖
结论：运单明明已签收，又被后到的「派送中」覆盖回 4。
原因：两个请求并发读同一状态，后写覆盖先写，无条件的 UPDATE 全量覆盖。
解法：状态落库改成条件更新 UPDATE ... WHERE status = #{expect}，
     受影响行数为 0 说明状态已变，丢弃本次流转。

坑 4：路由匹配到停用承运商
结论：运单分给了一家已停止合作的承运商，货物滞留。
原因：路由规则表里规则没停用，只停用了承运商档案。
解法：分派时校验承运商状态；路由规则与承运商档案双状态校验；
     承运商停用时级联停用其全部路由规则。

坑 5：运费对不上承运商账单
结论：系统算出 14 元，承运商账单 16 元。
原因：续重按「向上取整」还是「按 0.5kg 进位」口径不一致，双方各算各的。
解法：运费规则增加进位方式字段（ceil / half_up），与承运商合同口径一致；
     对账时差异单按重量与规则逐笔重算，标注差异原因。

坑 6：异常件没有超时闭环
结论：退回件在网点躺了一周没人处理。
原因：异常登记后没有超时升级机制，全靠人工盯群。
解法：异常件登记时写入 Redis ZSet（score=创建时间），定时任务扫描超 24 小时
     未处理记录升级提醒；升级后仍未处理再次升级并抄送管理层。

坑 7：用户端轨迹查询拖垮数据库
结论：大促期间查件接口超时，数据库连接打满。
原因：用户反复刷新查全量轨迹，每次都查 MySQL 轨迹流水表。
解法：用户端只查最近 3 条走 Redis 热点缓存（TTL 5 分钟），全量轨迹仅客服端
     与详情页按需查询；轨迹表按运单号分表或归档三个月以上历史数据。
```

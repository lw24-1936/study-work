## 项目背景

问卷调查是企业做用户研究、市场调研、内部满意度评估、课程反馈最常用的手段，但传统的纸质问卷 + 手工录入 + Excel 统计模式效率极低，市场上通用问卷平台又难以满足企业内部定制化需求（数据私有、题型定制、与内部账号体系打通）。本系统定位为「企业自建问卷平台」，覆盖问卷设计、发布回收、答卷收集、自动统计、Excel 导出全链路，是典型的「动态表单 + 数据统计」类业务系统。

业务痛点：

```text
1. 纸质问卷：发放回收周期长，录入 Excel 靠人工，错录漏录严重
2. 题型单一：只能用 Word 排单选多选，矩阵题、评分题、跳转逻辑做不了
3. 重复提交：同一个人刷 N 份问卷，数据失真，运营无法识别
4. 统计靠手工：每题选项分布用透视表逐个拉，交叉分析基本做不了
5. 模板不可复用：每次做问卷从零开始排版，相同题目反复录入
6. 数据不私有：用第三方问卷平台，答卷数据存在别人服务器上，涉密问卷不敢发
```

目标用户与核心诉求：

```text
1. 问卷设计者（运营/HR/产品）：可视化拖拽设计问卷、多题型支持、一键发布与回收、模板复用
2. 答卷者（员工/用户）：微信/H5 打开即答、防重复提交、作答进度可续
3. 数据分析者（运营/管理）：各题选项分布、评分均值、矩阵热力、交叉分析、一键导出 Excel
4. 管理员：问卷状态流转（草稿/发布中/已回收）、答卷数据导出备份、模板库管理
```

项目要解决的核心问题一句话概括：让非技术人员 5 分钟做出专业问卷，让答卷数据自动变成可用的统计报表。

## 功能介绍

功能按角色拆成三个端：问卷设计端（设计者）、答卷端（答卷者）、统计管理端（分析者/管理员）。

```text
一、问卷设计端（设计者视角）
1. 问卷管理 —— 新建/编辑/删除问卷，草稿与发布状态切换，复制问卷
2. 题型设计 —— 单选/多选/填空/评分/矩阵五种题型，必答设置，题目排序
3. 矩阵题设计 —— 自定义行（评价对象）与列（评价等级），如「对各部门满意度打分」
4. 问卷设置 —— 问卷说明、匿名开关、截止时间、是否允许重复提交
5. 模板套用 —— 从模板库一键生成问卷骨架，再微调题目
6. 发布与回收 —— 一键发布生成答卷链接/二维码，到期自动回收，也可手动提前回收

二、答卷端（答卷者视角）
1. 打开答卷 —— 通过链接/二维码进入，校验问卷状态（发布中且未截止）
2. 逐题作答 —— 按题型渲染控件：单选/多选/下拉/文本/星级/矩阵表格
3. 必答校验 —— 未答必答题提交时拦截并提示
4. 防重复提交 —— 同一账号/同一 IP 只能交一份（按问卷配置）
5. 提交成功反馈 —— 显示感谢页，记录提交时间

三、统计管理端（分析者/管理员视角）
1. 回收概况 —— 总答卷数、回收率、每日提交趋势
2. 单题统计 —— 单选/多选选项分布（数量+占比）、填空词频、评分均值、矩阵行均值
3. 交叉分析 —— 任意两题交叉（如「年龄 X 满意度」），生成交叉表
4. 答卷明细 —— 逐份查看答卷原始数据，可按提交时间筛选
5. Excel 导出 —— 导出答卷明细（每题一列）与统计汇总，EasyExcel 生成
6. 模板库管理 —— 沉淀高频问卷为模板，统计模板被套用次数
```

## 技术选型

| 组件 | 选型 | 理由 |
|------|------|------|
| 开发框架 | Spring Boot 2.7/3.x | 生态成熟，起步快，社区资料多 |
| 持久层 | MyBatis-Plus | 单表 CRUD 零 SQL，统计聚合走自定义 XML |
| 数据库 | MySQL 8.0 | 业务数据落库，支持事务与 JSON 函数 |
| 缓存 | Redis | 问卷结构缓存、防重复标记、答卷计数、统计缓存 |
| 定时任务 | Spring @Scheduled | 到期自动回收、计数刷库、统计缓存刷新，单机足够 |
| Excel 导出 | EasyExcel | 大答卷量（万级）下比 POI 省内存，注解式导出 |
| 鉴权 | Spring Security + JWT | 设计端/管理端需登录，答卷端可匿名（按问卷配置） |
| 前端 | Vue 3 + Element Plus | 设计端拖拽表单、统计图表（ECharts） |

选型说明：

```text
1. 动态题型不建「每题一列」的表：题目结构存 question 表 + 选项表，矩阵行列存 extra_json，答卷答案整体存 JSON，天然支持任意题型扩展
2. Redis 承担三件事：问卷结构缓存（答卷高并发读取）、防重复标记（SETNX 快速拦截）、答卷计数（INCR 高频写）
3. 统计不走实时计算：答卷提交后写统计缓存，定时任务 + 手动触发刷新，避免每次看报表都全量聚合
4. 定时任务用 Spring @Scheduled 而非 Quartz：本系统无分布式部署诉求，@Scheduled + 注解即可，部署多实例时用 Redis 锁保证只跑一个
```

## 架构设计

系统分层与请求链路：

```text
┌───────────────────────────────────────────────────────────────┐
│                        客户端（浏览器）                          │
│   问卷设计端（Vue3）    答卷端（H5/PC）     统计看板（Vue3）      │
└───────────────────────────────┬───────────────────────────────┘
                                │ HTTP / JSON（JWT 或匿名）
┌───────────────────────────────▼───────────────────────────────┐
│                      Spring Boot 应用层                         │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────────────┐   │
│  │Controller│ │ Service  │ │  Mapper  │ │ 定时任务（回收/刷库）│   │
│  └──────────┘ └──────────┘ └──────────┘ └──────────────────┘   │
│   问卷设计  发布回收  答卷提交  统计聚合  Excel 导出  模板管理     │
└───────────────┬──────────────────────────────┬────────────────┘
                │                              │
┌───────────────▼──────────────┐  ┌────────────▼────────────────┐
│            MySQL              │  │           Redis              │
│ survey/question/option/       │  │ 问卷结构缓存/防重复标记/     │
│ answer/answer_detail/template │  │ 答卷计数/统计缓存/互斥锁      │
└───────────────────────────────┘  └─────────────────────────────┘
```

答卷提交链路（答卷者点「提交」）：

```text
1. 前端 POST /api/survey/answer，带 surveyId + 整份答案 JSON
2. Controller 解析 token（匿名问卷跳过登录校验），组装提交请求
3. Service 校验问卷状态：必须是「发布中」且当前时间未过 end_time，否则拒绝
4. 防重复检查：Redis SETNX survey:answered:{surveyId}:{userId}，已存在直接返回「已提交过」
5. 答案格式校验：逐题校验题型匹配、必答题非空、多选数量上限
6. 事务写入：insert survey_answer（整份 JSON）+ 批量 insert survey_answer_detail（每题一行）
7. 收尾：Redis INCR 答卷计数、删除该问卷统计缓存、返回提交成功
```

统计查看链路（分析者打开单题分布）：

```text
1. 前端 GET /api/survey/{id}/stat
2. Service 查 Redis：key = survey:stat:{surveyId}
3. 命中 → 直接返回统计 VO（分布/均值/矩阵热力）
4. 未命中 → 查 MySQL 聚合（GROUP BY 明细表），Java 解析 answer_json 计算
5. 写回统计缓存（TTL 30 分钟），下次命中
6. 答卷新增或问卷被编辑时主动删除统计缓存，保证新鲜度
```

## 数据库设计

核心表设计（7 张表）：问卷、题目、选项、答卷主表、答卷明细、模板、发布日志。

```sql

CREATE TABLE `survey` (
  `id`            BIGINT        NOT NULL AUTO_INCREMENT COMMENT '问卷ID',
  `title`         VARCHAR(200)  NOT NULL COMMENT '问卷标题',
  `description`   VARCHAR(1000) DEFAULT NULL COMMENT '问卷说明（首页展示）',
  `creator_id`    BIGINT        NOT NULL COMMENT '创建人 user.id',

  `is_anonymous`  TINYINT       NOT NULL DEFAULT 0 COMMENT '是否匿名：0实名 1匿名',

  `collect_count` INT           NOT NULL DEFAULT 0 COMMENT '已回收答卷数（计数器定期刷入）',
```

答案 JSON 格式约定（明细表与主表共用）：

```json
{
  "1":  {"type": 1, "optionId": 3},
  "2":  {"type": 2, "optionIds": [8, 9]},
  "3":  {"type": 3, "text": "希望增加夜间配送"},
  "4":  {"type": 4, "score": 4},
  "5":  {"type": 5, "matrix": {"功能完整性": "非常满意", "易用性": "满意"}}
}
```

```text
1. 单选 type=1：answer_json 存 optionId（int）
2. 多选 type=2：answer_json 存 optionIds（int 数组）
3. 填空 type=3：answer_json 存 text（字符串）
4. 评分 type=4：answer_json 存 score（1-5 或按 extra_json 配置的满分）
5. 矩阵 type=5：answer_json 存 matrix（行标签 -> 列标签映射）
6. 主表 answer_json 以题目 id 为 key 汇总全卷，明细表拆成每题一行，两者字段格式一致
```

Redis Key 设计：

```text
survey:info:{surveyId}                 String  问卷详情缓存（题目+选项+矩阵定义），发布时写入、编辑时删除，TTL=24h
survey:answered:{surveyId}:{userId}    String  实名防重复标记，SETNX 写入，TTL=问卷截止时间
survey:answered:ip:{surveyId}:{ip}     String  匿名答卷按 IP 限频标记，TTL=24h
survey:collect:{surveyId}              String  答卷数计数器，INCR 累加，定时任务刷回 collect_count
survey:stat:{surveyId}                 String  统计结果缓存（分布/均值/交叉），答卷提交或问卷编辑时删除，TTL=30min
survey:stat:lock:{surveyId}            String  统计重算互斥锁（SETNX），防止多个实例并发重算
```

## 核心实现

### 1. 动态题型数据模型：问卷设计保存

题目用「类型 + 扩展 JSON」建模：单选/多选挂选项表，矩阵题的行列定义放 extra_json，未来加新题型（下拉、排序、NPS）只需新增类型枚举，不改表结构。

```java
@Service
public class SurveyDesignService {

    @Autowired
    private SurveyMapper surveyMapper;
    @Autowired
    private QuestionMapper questionMapper;
    @Autowired
    private OptionMapper optionMapper;
    @Autowired
    private RedisTemplate<String, Object> redisTemplate;

    /**
     * 保存问卷及全部题目选项（设计器整单提交）
     * 策略：先删旧题再插新题，题目/选项整体重写，简单可靠
     */
    @Transactional
    public Long saveSurvey(SurveyDraftVO draft) {
        Survey survey = new Survey();
        survey.setId(draft.getSurveyId());
        survey.setTitle(draft.getTitle());
        survey.setDescription(draft.getDescription());
        survey.setIsAnonymous(draft.getIsAnonymous());
        survey.setIsRepeatable(draft.getIsRepeatable());
        survey.setStatus(SurveyStatus.DRAFT.getCode());
        // 新增或更新问卷主体
        if (survey.getId() == null) {
            survey.setCreatorId(draft.getCreatorId());
            surveyMapper.insert(survey);
        } else {
            surveyMapper.updateById(survey);
        }
        // 删除旧题目（级联删除选项），保证整单重写
        questionMapper.deleteBySurveyId(survey.getId());
        // 逐题插入
        for (QuestionDraftVO q : draft.getQuestions()) {
            Question question = new Question();
            question.setSurveyId(survey.getId());
            question.setTitle(q.getTitle());
            question.setQuestionType(q.getQuestionType());
            question.setIsRequired(q.getIsRequired());
            question.setSort(q.getSort());
            // 矩阵题的行列定义、评分满分等扩展信息
            if (q.getExtra() != null) {
                question.setExtraJson(JSON.toJSONString(q.getExtra()));
            }
            questionMapper.insert(question);
            // 单选/多选才有选项列表
            if (q.getQuestionType() == QuestionType.SINGLE.getCode()
                    || q.getQuestionType() == QuestionType.MULTIPLE.getCode()) {
                for (OptionDraftVO o : q.getOptions()) {
                    Option option = new Option();
                    option.setQuestionId(question.getId());
                    option.setOptionText(o.getText());
                    option.setSort(o.getSort());
                    optionMapper.insert(option);
                }
            }
        }
        // 问卷结构变更，删除旧缓存
        redisTemplate.delete("survey:info:" + survey.getId());
        return survey.getId();
    }

    /**
     * 读取问卷完整结构（题目+选项+矩阵定义），答卷页与设计页共用
     */
    public SurveyDetailVO getSurveyDetail(Long surveyId) {
        String key = "survey:info:" + surveyId;
        Object cached = redisTemplate.opsForValue().get(key);
        if (cached != null) {
            return (SurveyDetailVO) cached;
        }
        SurveyDetailVO vo = new SurveyDetailVO();
        vo.setSurvey(surveyMapper.selectById(surveyId));
        vo.setQuestions(questionMapper.selectBySurveyId(surveyId));
        for (QuestionDetailVO q : vo.getQuestions()) {
            // 矩阵题行列从 extra_json 还原
            q.setExtra(JSON.parseObject(q.getExtraJson()));
            if (q.getQuestionType() == QuestionType.SINGLE.getCode()
                    || q.getQuestionType() == QuestionType.MULTIPLE.getCode()) {
                q.setOptions(optionMapper.selectByQuestionId(q.getId()));
            }
        }
        redisTemplate.opsForValue().set(key, vo, 24, TimeUnit.HOURS);
        return vo;
    }
}
```

### 2. 发布回收：定时任务自动回收

发布时写入发布日志并生成答卷链接；每 5 分钟扫描一次已过期问卷，自动从「发布中」流转为「已结束」，实现到点自动回收。

```java
@Service
public class SurveyPublishService {

    @Autowired
    private SurveyMapper surveyMapper;
    @Autowired
    private PublishLogMapper publishLogMapper;

    /**
     * 发布问卷：状态置为发布中，记录发布时间与截止时间
     */
    @Transactional
    public void publish(Long surveyId, Long operatorId, LocalDateTime endTime) {
        Survey survey = surveyMapper.selectById(surveyId);
        // 草稿或已回收的问卷才允许再次发布
        if (survey.getStatus() != SurveyStatus.DRAFT.getCode()
                && survey.getStatus() != SurveyStatus.RECYCLED.getCode()) {
            throw new BizException("当前状态不可发布");
        }
        survey.setStatus(SurveyStatus.PUBLISHING.getCode());
        survey.setPublishTime(LocalDateTime.now());
        survey.setEndTime(endTime);
        surveyMapper.updateById(survey);

        PublishLog log = new PublishLog();
        log.setSurveyId(surveyId);
        log.setOperatorId(operatorId);
        log.setAction(1);
        log.setPublishTime(survey.getPublishTime());
        log.setEndTime(endTime);
        publishLogMapper.insert(log);
    }

    /**
     * 手动回收：状态置为已回收，答卷链接立即失效
     */
    @Transactional
    public void recycle(Long surveyId, Long operatorId) {
        Survey survey = surveyMapper.selectById(surveyId);
        survey.setStatus(SurveyStatus.RECYCLED.getCode());
        surveyMapper.updateById(survey);

        PublishLog log = new PublishLog();
        log.setSurveyId(surveyId);
        log.setOperatorId(operatorId);
        log.setAction(2);
        publishLogMapper.insert(log);
    }
}

@Component
public class SurveyRecycleTask {

    @Autowired
    private SurveyMapper surveyMapper;

    /**
     * 每 5 分钟扫描：发布中且已过截止时间的问卷自动置为已结束
     */
    @Scheduled(fixedDelay = 5 * 60 * 1000)
    public void autoRecycleExpired() {
        LocalDateTime now = LocalDateTime.now();
        // UPDATE ... WHERE 条件更新，天然幂等，重复执行无副作用
        surveyMapper.updateStatusByExpired(SurveyStatus.ENDED.getCode(), now);
```

### 3. 答卷提交：防重复 + JSON 存储

防重复采用「Redis SETNX 预检 + 数据库唯一键兜底」双保险：Redis 拦截绝大多数重复点击，唯一键挡住并发穿透的最后一发。

```java
@Service
public class SurveyAnswerService {

    @Autowired
    private SurveyMapper surveyMapper;
    @Autowired
    private AnswerMapper answerMapper;
    @Autowired
    private AnswerDetailMapper detailMapper;
    @Autowired
    private QuestionMapper questionMapper;
    @Autowired
    private RedisTemplate<String, Object> redisTemplate;

    /**
     * 提交答卷
     * 防重复：Redis SETNX 先拦截，DB 唯一键 (survey_id, user_id) 兜底
     */
    @Transactional
    public Long submit(SurveyAnswerRequest req) {
        Survey survey = surveyMapper.selectById(req.getSurveyId());
        // 1. 状态校验：发布中且未截止
        if (survey.getStatus() != SurveyStatus.PUBLISHING.getCode()) {
            throw new BizException("问卷不在收集期");
        }
        if (survey.getEndTime() != null && survey.getEndTime().isBefore(LocalDateTime.now())) {
            throw new BizException("问卷已截止");
        }
        // 2. 实名答卷：SETNX 防重复标记
        Long userId = req.getUserId();
        if (!survey.getIsRepeatable().equals(1) && userId != null) {
            String flagKey = "survey:answered:" + survey.getId() + ":" + userId;
            Boolean first = redisTemplate.opsForValue()
                    .setIfAbsent(flagKey, "1", Duration.ofHours(24));
            if (Boolean.FALSE.equals(first)) {
                throw new BizException("您已提交过该问卷");
            }
        }
        // 3. 答案格式校验：逐题校验题型与必答
        List<Question> questions = questionMapper.selectBySurveyId(survey.getId());
        validateAnswers(questions, req.getAnswers());
        // 4. 插入答卷主表（整份 JSON）+ 明细表（每题一行）
        SurveyAnswer answer = new SurveyAnswer();
        answer.setSurveyId(survey.getId());
        answer.setUserId(userId);
        answer.setIp(req.getIp());
        answer.setSubmitTime(LocalDateTime.now());
        answer.setAnswerJson(JSON.toJSONString(req.getAnswers()));
        answerMapper.insert(answer);

        for (Map.Entry<Long, AnswerItem> entry : req.getAnswers().entrySet()) {
            AnswerDetail detail = new AnswerDetail();
            detail.setAnswerId(answer.getId());
            detail.setSurveyId(survey.getId());
            detail.setQuestionId(entry.getKey());
            detail.setAnswerJson(JSON.toJSONString(entry.getValue()));
            detailMapper.insert(detail);
        }
        // 5. 计数 + 失效统计缓存
        redisTemplate.opsForValue()
                .increment("survey:collect:" + survey.getId());
        redisTemplate.delete("survey:stat:" + survey.getId());
        return answer.getId();
    }

    private void validateAnswers(List<Question> questions, Map<Long, AnswerItem> answers) {
        for (Question q : questions) {
            AnswerItem item = answers.get(q.getId());
            if (q.getIsRequired().equals(1) && item == null) {
                throw new BizException("必答题未作答：" + q.getTitle());
            }
            if (item == null) {
                continue;
            }
            // 题型匹配校验：单选题只允许一个 optionId 等
            if (q.getQuestionType() == QuestionType.SINGLE.getCode() && item.getOptionId() == null) {
                throw new BizException("单选题答案格式错误");
            }
            if (q.getQuestionType() == QuestionType.MULTIPLE.getCode()
                    && (item.getOptionIds() == null || item.getOptionIds().isEmpty())) {
                throw new BizException("多选题答案格式错误");
            }
        }
    }
}
```

数据库兜底：`uk_survey_user (survey_id, user_id)` 唯一索引，两个请求同时穿透 Redis 时，后插入的事务抛 DuplicateKeyException，被全局异常处理器转为「您已提交过该问卷」。

### 4. 数据统计：分布 / 均值 / 交叉分析

统计聚合从明细表读数据，Java 端解析 answer_json 计算。答卷量小时全量内存聚合足够；答卷量大时先按题目分组后逐题聚合，避免一次载入全表。

```java
@Service
public class SurveyStatService {

    @Autowired
    private AnswerDetailMapper detailMapper;
    @Autowired
    private QuestionMapper questionMapper;
    @Autowired
    private RedisTemplate<String, Object> redisTemplate;

    private static final String STAT_KEY = "survey:stat:";

    /**
     * 单题统计：单选/多选返回选项分布，评分返回均值，矩阵返回各行均值
     */
    public QuestionStatVO statQuestion(Long surveyId, Long questionId) {
        Question q = questionMapper.selectById(questionId);
        List<AnswerDetail> details = detailMapper.selectBySurveyAndQuestion(surveyId, questionId);

        QuestionStatVO vo = new QuestionStatVO();
        vo.setQuestionId(questionId);
        vo.setTotal(details.size());
        switch (QuestionType.of(q.getQuestionType())) {
            case SINGLE: {
                // 单选：统计每个 optionId 的出现次数
                Map<Integer, Long> counter = details.stream()
                        .collect(Collectors.groupingBy(
                                d -> JSON.parseObject(d.getAnswerJson()).getInteger("optionId"),
                                Collectors.counting()));
                vo.setOptionDist(counter);
                break;
            }
            case MULTIPLE: {
                // 多选：一个答案可能属于多个选项，先扁平化再计数
                Map<Integer, Long> counter = new HashMap<>();
                for (AnswerDetail d : details) {
                    List<Integer> ids = JSON.parseObject(d.getAnswerJson())
                            .getJSONArray("optionIds").toJavaList(Integer.class);
                    for (Integer id : ids) {
                        counter.merge(id, 1L, Long::sum);
                    }
                }
                vo.setOptionDist(counter);
                break;
            }
            case SCORE: {
                // 评分：求均值，保留一位小数
                double avg = details.stream()
                        .mapToInt(d -> JSON.parseObject(d.getAnswerJson()).getInteger("score"))
                        .average().orElse(0);
                vo.setAvgScore(BigDecimal.valueOf(avg).setScale(1, RoundingMode.HALF_UP));
                break;
            }
            case MATRIX: {
                // 矩阵：按行聚合，统计每行落在各列的次数
                Map<String, Map<String, Long>> matrix = new LinkedHashMap<>();
                for (AnswerDetail d : details) {
                    JSONObject m = JSON.parseObject(d.getAnswerJson()).getJSONObject("matrix");
                    for (String row : m.keySet()) {
                        String col = m.getString(row);
                        matrix.computeIfAbsent(row, k -> new HashMap<>())
                                .merge(col, 1L, Long::sum);
                    }
                }
                vo.setMatrixDist(matrix);
                break;
            }
            default:
                break;
        }
        return vo;
    }

    /**
     * 交叉分析：题目 A 的每个选项 X 题目 B 的分布
     * 实现：同一份答卷内按用户关联两题答案，构建「A答案 -> B答案计数」映射
     */
    public CrossStatVO crossAnalysis(Long surveyId, Long questionA, Long questionB) {
        // 一次查出两题的明细，按 answer_id 关联
        List<AnswerDetail> aList = detailMapper.selectBySurveyAndQuestion(surveyId, questionA);
        List<AnswerDetail> bList = detailMapper.selectBySurveyAndQuestion(surveyId, questionB);
        Map<Long, Integer> aMap = aList.stream().collect(Collectors.toMap(
                AnswerDetail::getAnswerId,
                d -> JSON.parseObject(d.getAnswerJson()).getInteger("optionId")));
        Map<Long, String> bMap = bList.stream().collect(Collectors.toMap(
                AnswerDetail::getAnswerId,
                d -> String.valueOf(JSON.parseObject(d.getAnswerJson()).getInteger("optionId"))));

        // key = A选项id + ":" + B选项id，统计共现次数
        Map<String, Long> cross = new HashMap<>();
        for (Long answerId : aMap.keySet()) {
            if (!bMap.containsKey(answerId)) {
                continue; // 该答卷没答 B 题，跳过
            }
            cross.merge(aMap.get(answerId) + ":" + bMap.get(answerId), 1L, Long::sum);
        }
        // 组装成 行=A选项、列=B选项 的二维表，交给前端 ECharts 渲染热力图
        return buildCrossTable(cross, questionA, questionB);
    }

    /**
     * 统计看板入口：优先读缓存，未命中重算
     */
    public SurveyStatVO getSurveyStat(Long surveyId) {
        String key = STAT_KEY + surveyId;
        Object cached = redisTemplate.opsForValue().get(key);
        if (cached != null) {
            return (SurveyStatVO) cached;
        }
        SurveyStatVO stat = new SurveyStatVO();
        stat.setCollectCount(detailMapper.countBySurvey(surveyId));
        // 逐题统计（题目多时可并行，这里保持串行简单清晰）
        List<Question> questions = questionMapper.selectBySurveyId(surveyId);
        stat.setQuestions(questions.stream()
                .map(q -> statQuestion(surveyId, q.getId()))
                .toList());
        redisTemplate.opsForValue().set(key, stat, 30, TimeUnit.MINUTES);
        return stat;
    }
}
```

### 5. 答卷导出 Excel（EasyExcel）

导出采用「一次查一批、写一批」的流式写法，万级答卷不 OOM；每题答案 JSON 解析后拍平成一行一列。

```java
@Service
public class SurveyExportService {

    @Autowired
    private AnswerMapper answerMapper;
    @Autowired
    private QuestionMapper questionMapper;

    /**
     * 导出答卷明细：每行一份答卷，每列一题，EasyExcel 流式写出
     */
    public void exportAnswers(Long surveyId, HttpServletResponse response) {
        List<Question> questions = questionMapper.selectBySurveyId(surveyId);
        // 动态表头：提交人、提交时间 + 每道题一列（用题目 id 做列 key）
        List<List<String>> head = new ArrayList<>();
        head.add(List.of("提交人ID"));
        head.add(List.of("提交时间"));
        for (Question q : questions) {
            head.add(List.of(q.getTitle()));
        }
        ExcelWriter writer = EasyExcel.write(response.getOutputStream())
                .head(head).build();
        WriteSheet sheet = EasyExcel.writerSheet("答卷明细").build();

        // 分页流式读取，每页 1000 条，写完即释放
        int page = 1, size = 1000;
        while (true) {
            List<SurveyAnswer> answers = answerMapper.selectPageBySurvey(
                    surveyId, (page - 1) * size, size);
            if (answers.isEmpty()) {
                break;
            }
            List<List<Object>> rows = new ArrayList<>();
            for (SurveyAnswer a : answers) {
                List<Object> row = new ArrayList<>();
                row.add(a.getUserId());
                row.add(a.getSubmitTime());
                JSONObject answersJson = JSON.parseObject(a.getAnswerJson());
                for (Question q : questions) {
                    row.add(flatten(answersJson.getJSONObject(String.valueOf(q.getId()))));
                }
                rows.add(row);
            }
            writer.write(rows, sheet);
            page++;
        }
        writer.finish();
    }

    /**
     * 把单题答案 JSON 拍平成可读字符串（多选转顿号分隔，矩阵转 行:列; 形式）
     */
    private String flatten(JSONObject item) {
        if (item == null) {
            return "";
        }
        if (item.containsKey("optionIds")) {
            return item.getJSONArray("optionIds").stream()
                    .map(String::valueOf).collect(Collectors.joining("、"));
        }
        if (item.containsKey("text")) {
            return item.getString("text");
        }
        if (item.containsKey("score")) {
            return String.valueOf(item.getInteger("score"));
        }
        if (item.containsKey("matrix")) {
            StringBuilder sb = new StringBuilder();
            item.getJSONObject("matrix").forEach((k, v) -> sb.append(k).append(":").append(v).append("; "));
            return sb.toString();
        }
        return String.valueOf(item.getInteger("optionId"));
    }
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. 动态题型用「题目表 + 选项表 + extra_json + 答案 JSON」四件套建模，新增题型只改枚举和渲染器，不动表结构
2. 防重复必须双层：Redis SETNX 挡第一层（毫秒级拦截），DB 唯一键 (survey_id, user_id) 挡第二层（并发穿透兜底），单靠哪一层都有漏洞
3. 答卷主表存整份 JSON 用于「还原现场」，明细表拆行用于「统计聚合」，两表互补而不是互相替代
4. 统计结果缓存要主动失效：答卷提交、问卷编辑时删 survey:stat:{id}，不要依赖 TTL 过期，否则报表滞后
5. Excel 导出用 EasyExcel 流式写 + 分页查，杜绝一次性把全部答卷载入内存
6. 定时任务（自动回收、计数刷库）用「条件 UPDATE」保证幂等，多实例部署时用 Redis 锁保证同一时刻只跑一个
7. 问卷结构缓存以「发布时写入、编辑时删除」为原则，草稿阶段不缓存，避免改了不生效

### 踩坑记录

```text
坑 1：必答题漏校验，脏数据进统计
结论：问卷出现了「未答必答题」的答卷。
原因：提交接口只校验了问卷状态，没逐题校验必答与题型格式。
解法：提交前加载题目列表逐题校验（必答非空 + 题型匹配 + 多选上限），不合法整体拒绝。

坑 2：同一用户重复提交两份答卷
结论：并发双击 + 网络重试导致一人两卷。
原因：只做了 Redis SETNX 预检，两个请求同时通过检查后都执行了 insert。
解法：DB 加唯一键 uk_survey_user 兜底，insert 抛 DuplicateKeyException 时转成友好提示。

坑 3：统计结果一直不变，运营以为数据丢了
结论：新答卷提交后报表数字不涨。
原因：统计接口只读缓存，而提交链路忘了删 survey:stat 缓存，TTL 30 分钟才刷新。
解法：提交成功与问卷编辑的统一收尾动作里 delete 统计缓存。

坑 4：导出 Excel 万级答卷 OOM
结论：导出 2 万份答卷时内存溢出。
原因：一次 SELECT 全量答卷再转 List 组装，POI 全量写内存。
解法：分页查询 + EasyExcel 流式写，每批 1000 条写出后释放。

坑 5：多选分布百分比合计超过 100%
结论：多选统计按「选项出现次数/答卷总数」算占比，合计超 100%。
原因：多选一道题可多选，各选项占比自然可超 100%，但报表没标注口径。
解法：多选题占比口径改为「出现次数/该题有效答卷数」，页面注明「多选题占比合计可能超过 100%」。

坑 6：自动回收后还能提交答卷
结论：截止时间过了，还有答卷进来。
原因：定时任务每 5 分钟跑一次，回收前有 5 分钟窗口；且提交接口没查 end_time。
解法：提交接口实时校验 end_time（硬校验），定时回收只是兜底状态展示，两处都要有。

结论：矩阵题统计接口 500。
原因：早期矩阵答案存的是数组，后来改成 行->列 映射，历史数据格式不一致。
解法：解析时兼容两种格式（识别 JSONArray/JSONObject 分支处理），并写数据修复脚本统一历史数据。
```

## 项目背景

企业网盘是企业内部的文件存储与协作中枢，替代「U 盘拷贝 + 微信传文件 + 邮件发附件」的原始工作方式。选它做综合实战项目，是因为它天然覆盖了文件传输领域最硬核的三个技术点：分片上传、秒传（MD5 查重）、预签名 URL，同时还有树形结构、权限模型、容量统计这些高频业务设计。技术栈上「Spring Boot + MinIO + MySQL + Redis」四件套是中小团队做文件类产品最标准的组合，可迁移到 OSS/COS 等任何 S3 兼容存储。

业务痛点：

```text
1. 文件散落在员工电脑、微信、邮件里，版本混乱，关键文档找不到最终版
2. 硬盘损坏、电脑丢失即数据永久丢失，本地备份不可靠
3. 大文件（设计稿、视频、安装包）超过邮件/微信大小限制，传输靠人肉拷贝
4. 网络波动时大文件上传失败就要从头再来，浪费带宽和时间
5. 部门间共享靠 U 盘和公共盘，无权限管控，机密文档容易泄露
6. 存储容量无统计无配额，个人无限占用，扩容采购没有依据
```

目标用户与核心诉求：

```text
1. 普通员工：上传下载快、目录管理清晰、断点续传、误删可恢复
2. 部门负责人：部门共享空间、成员权限控制、对外分享要可控（提取码+有效期）
3. 管理员：容量配额、全站统计、回收站管理、离职账号文件交接
```

项目要解决的核心问题一句话概括：让文件上传下载又快又稳又安全，让文件按组织架构可控地流动，让存储成本清晰可管理。

## 功能介绍

功能按模块拆成四块：个人文件管理、分享与外发、权限与协作、管理后台。

```text
一、个人文件管理（员工视角）
1. 文件上传 —— 分片上传（大文件切块并行传）、断点续传（失败续传）、秒传（MD5 查重跳过上传）
2. 文件夹管理 —— 新建/重命名/移动/删除，树形目录无限层级
3. 文件操作 —— 重命名、移动、复制、下载、在线预览（图片/PDF/视频）
4. 回收站 —— 删除进回收站，30 天内可恢复，超期自动清理

二、分享与外发
1. 分享链接 —— 选中文件/文件夹生成链接，可设置提取码与有效期（1 天/7 天/30 天/永久）
2. 权限控制 —— 分享链接可设置只读 / 可下载两级权限
3. 我的分享 —— 查看/取消已发分享，复制链接，查看访问次数

三、权限与协作
1. 部门空间 —— 按部门自动生成的共享目录，部门成员可见
2. 个人共享 —— 将文件/文件夹共享给指定用户或部门
3. 权限模型 —— 所有者/可编辑/只读 三级权限，继承父目录权限

四、管理后台（管理员视角）
1. 组织管理 —— 部门树维护、员工账号开通与禁用、离职文件交接
2. 容量管理 —— 每人容量配额设置，超配额自动拒绝上传
3. 统计报表 —— 全站已用容量、Top 占用排行、部门容量分布
4. 安全审计 —— 分享链接清单、下载行为日志、回收站全局管理
```

## 技术选型

| 组件 | 选型 | 理由 |
|------|------|------|
| 开发框架 | Spring Boot 2.7/3.x | 生态成熟，文件上传、定时任务等场景资料丰富 |
| 对象存储 | MinIO | S3 协议兼容、开源可私有化部署，原生支持分片与预签名 URL |
| 数据库 | MySQL 8.0 | 文件元数据、部门、分享、回收站等结构化数据落库 |
| 缓存 | Redis | 秒传 MD5 索引、分片上传状态、断点信息、提取码缓存 |
| 鉴权 | Spring Security + JWT | 无状态认证，前后端分离标配 |
| 前端 | Vue 3 + Element Plus | 文件管理界面成熟组件多，上传组件可做分片切片 |
| 构建 | Maven | 依赖管理标准工具 |

选型说明：

```text
1. 对象存储选 MinIO 而非自建文件服务器：自建方案要自己管扩容、备份、防盗链，MinIO 直接给分片合并、预签名 URL、生命周期策略
2. 元数据与数据分离：文件内容进 MinIO，文件名/目录/权限/分享进 MySQL，两边各司其职，容量统计只算元数据即可
3. Redis 承担四件事：秒传 MD5 索引（防重复上传）、分片上传状态（断点续传依据）、提取码缓存、访问计数
4. 预签名 URL 是下载链路的核心：应用服务器只签发 URL，文件字节流直连 MinIO，大文件下载不占用应用服务器带宽
```

## 架构设计

系统分层与请求链路：

```text
┌──────────────────────────────────────────────────────────────┐
│                       客户端（浏览器）                          │
│    Vue3 文件管理界面（上传组件：分片/断点续传/秒传）               │
└──────────────┬───────────────────────────────┬───────────────┘
               │ HTTP / JSON（业务接口）        │ 预签名 URL 直连
┌──────────────▼───────────────────────────────▼───────────────┐
│                      Spring Boot 应用层                       │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌────────────────┐   │
│  │Controller│ │ Service  │ │  Mapper  │ │ Security/JWT   │   │
│  └──────────┘ └──────────┘ └──────────┘ └────────────────┘   │
└───────┬──────────────────┬──────────────────┬────────────────┘
        │                  │                  │
┌───────▼───────┐  ┌───────▼────────┐  ┌──────▼──────────────┐
│     MySQL     │  │     Redis      │  │       MinIO         │
│ 元数据/部门/   │  │ 秒传MD5/分片状态/ │  │ 对象存储（文件数据）  │
│ 分享/回收站   │  │ 断点信息/提取码  │  │ 预签名URL直传直下    │
└───────────────┘  └────────────────┘  └─────────────────────┘
```

大文件分片上传链路（以 2GB 视频为例）：

```text
1. 前端计算整个文件 MD5，调 GET /api/upload/check?md5=xxx 查重
2. 命中（服务器已有相同文件）：MinIO copyObject 复制对象，直接建元数据，秒传完成
3. 未命中：调 POST /api/upload/init 初始化，MinIO 返回 uploadId，Redis 记录状态
4. 前端按 5MB 切片，逐片调 POST /api/upload/chunk（携带 uploadId + 分片号），
   每片上传到 MinIO 并记录 etag 到 Redis Hash
5. 传完后调 POST /api/upload/complete：服务端 completeMultipartUpload 在 MinIO 服务端合并
6. 合并完成写 file_meta 元数据、更新容量占用，清理 Redis 分片状态
7. 断点续传：中断后前端调 GET /api/upload/progress 拿到已传分片号，只补传缺失分片
```

下载链路（大文件不经过应用服务器）：

```text
1. 前端 GET /api/file/{id}/download
2. 服务端校验登录态 + 文件权限（所有者/共享/分享链接）
3. 服务端调用 MinIO 生成预签名 GET URL（有效期 5 分钟）
4. 前端拿到 URL 直连 MinIO 下载，应用服务器零字节转发
5. 下载行为写审计日志；URL 过期后即使泄露也无法使用
```

## 核心实现

### 1. 上传服务：分片上传 + 断点续传 + 秒传

```java
@Service
public class UploadService {

    @Autowired
    private MinioService minioService;
    @Autowired
    private FileMetaMapper fileMetaMapper;
    @Autowired
    private UserMapper userMapper;
    @Autowired
    private RedisTemplate<String, Object> redisTemplate;

    private static final String UPLOAD_ID_KEY = "upload:uploadId:";
    private static final String CHUNK_KEY = "upload:chunks:";
    private static final long MAX_PART_SIZE = 100 * 1024 * 1024;  // 单片上限 100M

    /**
     * 秒传检查：MD5 命中直接复制对象并建元数据
     * Redis 缓存 md5 -> objectName 加速，未命中查 MySQL
     */
    public SecUploadResult checkMd5(Long userId, String md5, String name, Long parentId, Long size) {
        String cacheKey = "file:md5:" + md5;
        Object cached = redisTemplate.opsForValue().get(cacheKey);
        String existObject = cached == null ? null : cached.toString();
        if (existObject == null) {
            FileMeta exist = fileMetaMapper.selectOne(new LambdaQueryWrapper<FileMeta>()
                    .eq(FileMeta::getMd5, md5)
                    .eq(FileMeta::getIsDir, 0)
                    .last("limit 1"));
            if (exist != null) {
                existObject = exist.getObjectName();
                // 缓存 24 小时，避免每次秒传都查库
                redisTemplate.opsForValue().set(cacheKey, existObject, 24, TimeUnit.HOURS);
            }
        }
        if (existObject == null) {
            return SecUploadResult.needUpload();  // 无相同文件，走真实上传
        }
        // 命中：MinIO 复制对象到新 objectName，与源文件互不影响
        String newObject = ObjectNameUtil.gen();
        minioService.copyObject(existObject, newObject);
        FileMeta meta = new FileMeta();
        meta.setUserId(userId);
        meta.setParentId(parentId);
        meta.setName(name);
        meta.setIsDir(0);
        meta.setSize(size);
        meta.setObjectName(newObject);
        meta.setMd5(md5);
        fileMetaMapper.insert(meta);
        userMapper.incrUsedBytes(userId, size);  // 事务内更新容量
        return SecUploadResult.success(meta.getId());
    }

    /**
     * 初始化分片上传：向 MinIO 申请 uploadId 并记入 Redis
     */
    public String initUpload(Long userId, String objectName) {
        String uploadId = minioService.createMultipartUpload(objectName);
        // uploadId 是后续所有分片操作的凭证，TTL 24 小时防泄漏残留
        redisTemplate.opsForValue().set(UPLOAD_ID_KEY + uploadId, userId, 24, TimeUnit.HOURS);
        return uploadId;
    }

    /**
     * 上传单个分片：校验大小后交 MinIO，etag 记入 Redis Hash
     */
    public Part uploadChunk(String uploadId, int partNumber, MultipartFile file) throws IOException {
        if (file.getSize() > MAX_PART_SIZE) {
            throw new BizException("分片超过大小上限");
        }
        Part part = minioService.uploadPart(uploadId, partNumber,
                file.getInputStream(), file.getSize());
        // 断点续传的依据：已传分片号 -> etag
        redisTemplate.opsForHash().put(CHUNK_KEY + uploadId,
                String.valueOf(partNumber), part.etag());
        return part;
    }

    /**
     * 断点续传：返回已上传的分片号，前端跳过这些分片
     */
    public List<Integer> uploadedParts(String uploadId) {
        Map<Object, Object> chunks = redisTemplate.opsForHash().entries(CHUNK_KEY + uploadId);
        return chunks.keySet().stream()
                .map(k -> Integer.parseInt(k.toString()))
                .sorted().collect(Collectors.toList());
    }

    /**
     * 合并分片：completeMultipartUpload 在 MinIO 服务端合并
     * 合并完成后写元数据、更新容量、清理 Redis 状态
     */
    @Transactional
    public FileMeta complete(String uploadId, String objectName, String name,
                             Long userId, Long parentId, Long size, String md5) {
        Map<Object, Object> chunks = redisTemplate.opsForHash().entries(CHUNK_KEY + uploadId);
        Part[] parts = new Part[chunks.size()];
        chunks.forEach((k, v) -> {
            int num = Integer.parseInt(k.toString());
            parts[num - 1] = new Part(num, v.toString());  // 按分片号排位
        });
        minioService.completeMultipartUpload(objectName, uploadId, parts);
        // 写元数据
        FileMeta meta = new FileMeta();
        meta.setUserId(userId);
        meta.setParentId(parentId);
        meta.setName(name);
        meta.setIsDir(0);
        meta.setSize(size);
        meta.setMd5(md5);
        meta.setObjectName(objectName);
        fileMetaMapper.insert(meta);
        userMapper.incrUsedBytes(userId, size);
        // 清理 Redis 分片状态
        redisTemplate.delete(UPLOAD_ID_KEY + uploadId);
        redisTemplate.delete(CHUNK_KEY + uploadId);
        return meta;
    }
}
```

### 2. MinIO 封装：预签名 URL 与分片操作

```java
@Service
public class MinioService {

    private MinioClient client;

    @Value("${minio.endpoint}")
    private String endpoint;
    @Value("${minio.access-key}")
    private String accessKey;
    @Value("${minio.secret-key}")
    private String secretKey;
    @Value("${minio.bucket}")
    private String bucket;

    @PostConstruct
    public void init() {
        client = MinioClient.builder()
                .endpoint(endpoint)
                .credentials(accessKey, secretKey)
                .build();
        try {
            // 桶不存在则自动创建
            if (!client.bucketExists(BucketExistsArgs.builder().bucket(bucket).build())) {
                client.makeBucket(MakeBucketArgs.builder().bucket(bucket).build());
            }
        } catch (Exception e) {
            throw new RuntimeException("MinIO 初始化失败", e);
        }
    }

    /** 申请分片上传，返回 uploadId */
    public String createMultipartUpload(String objectName) throws Exception {
        CreateMultipartUploadResponse resp = client.createMultipartUpload(
                bucket, null, objectName, null, null);
        return resp.uploadId();
    }

    /** 上传单个分片，返回 Part（分片号 + etag） */
    public Part uploadPart(String uploadId, int partNumber, InputStream data, long size) throws Exception {
        UploadPartResponse resp = client.uploadPart(bucket, null,
                objectName, data, size, partNumber, uploadId);
        return new Part(partNumber, resp.etag());
    }

    /** 合并分片（MinIO 服务端合并） */
    public void completeMultipartUpload(String objectName, String uploadId, Part[] parts) throws Exception {
        client.completeMultipartUpload(bucket, null, objectName, uploadId, parts);
    }

    /** 下载预签名 URL：默认 5 分钟有效，过期即失效 */
    public String presignedGetUrl(String objectName, int expiresSeconds) throws Exception {
        return client.getPresignedObjectUrl(GetPresignedObjectUrlArgs.builder()
                .method(Method.GET)
                .bucket(bucket)
                .object(objectName)
                .expiry(expiresSeconds)
                .build());
    }

    /** 上传预签名 URL：前端直传 MinIO，文件流不经过应用服务器 */
    public String presignedPutUrl(String objectName, int expiresSeconds) throws Exception {
        return client.getPresignedObjectUrl(GetPresignedObjectUrlArgs.builder()
                .method(Method.PUT)
                .bucket(bucket)
                .object(objectName)
                .expiry(expiresSeconds)
                .build());
    }

    /** 复制对象（秒传复用） */
    public void copyObject(String srcObject, String destObject) throws Exception {
        client.copyObject(CopyObjectArgs.builder()
                .bucket(bucket).object(destObject)
                .source(CopySource.builder().bucket(bucket).object(srcObject).build())
                .build());
    }

    /** 删除对象（回收站彻底清理） */
    public void removeObject(String objectName) throws Exception {
        client.removeObject(RemoveObjectArgs.builder().bucket(bucket).object(objectName).build());
    }
}
```

### 3. 文件服务：树形目录与移动

```java
@Service
public class FileService {

    /**
     * 构建目录树：一次查出全部目录，内存组装父子关系
     * 避免递归查库（N 次查询），万级目录内存组装完全够用
     */
    public List<FolderVO> tree(Long userId) {
        List<FileMeta> dirs = fileMetaMapper.selectList(new LambdaQueryWrapper<FileMeta>()
                .eq(FileMeta::getUserId, userId)
                .eq(FileMeta::getIsDir, 1)
                .eq(FileMeta::getStatus, 1)
                .orderByAsc(FileMeta::getName));
        Map<Long, FolderVO> map = new HashMap<>();
        List<FolderVO> roots = new ArrayList<>();
        for (FileMeta d : dirs) {
            map.put(d.getId(), new FolderVO(d));
        }
        for (FileMeta d : dirs) {
            FolderVO vo = map.get(d.getId());
            FolderVO parent = map.get(d.getParentId());
            if (parent == null) {
                roots.add(vo);          // 顶层目录
            } else {
                parent.getChildren().add(vo);
            }
        }
        return roots;
    }

    /**
     * 移动文件/文件夹：校验目标目录归属、重名、防环
     */
    public void move(Long fileId, Long targetParentId, Long userId) {
        FileMeta file = fileMetaMapper.selectById(fileId);
        if (!file.getUserId().equals(userId)) {
            throw new BizException("无权操作他人文件");
        }
        // 校验目标目录存在且属于本人
        if (targetParentId != 0) {
            FileMeta target = fileMetaMapper.selectById(targetParentId);
            if (target == null || !target.getUserId().equals(userId) || target.getIsDir() != 1) {
                throw new BizException("目标目录不存在");
            }
        }
        // 防环：不能把目录移进自己的子孙目录
        if (isAncestor(fileId, targetParentId)) {
            throw new BizException("不能移动到自身或其子目录下");
        }
        // 同目录重名校验
        long count = fileMetaMapper.selectCount(new LambdaQueryWrapper<FileMeta>()
                .eq(FileMeta::getUserId, userId)
                .eq(FileMeta::getParentId, targetParentId)
                .eq(FileMeta::getName, file.getName())
                .ne(FileMeta::getId, fileId)
                .eq(FileMeta::getStatus, 1));
        if (count > 0) {
            throw new BizException("目标目录已存在同名文件");
        }
        FileMeta update = new FileMeta();
        update.setId(fileId);
        update.setParentId(targetParentId);
        fileMetaMapper.updateById(update);
    }

    /** 判断 ancestorId 是否是 nodeId 的祖先（沿 parent_id 向上找） */
    private boolean isAncestor(Long nodeId, Long targetId) {
        Long cur = targetId;
        Set<Long> visited = new HashSet<>();
        while (cur != null && cur != 0 && visited.add(cur)) {
            if (cur.equals(nodeId)) {
                return true;
            }
            FileMeta node = fileMetaMapper.selectById(cur);
            cur = node == null ? null : node.getParentId();
        }
        return false;
    }
}
```

### 4. 分享服务：提取码 + 有效期

```java
@Service
public class ShareService {

    /**
     * 创建分享：生成提取码与 token，Redis 缓存加速校验
     */
    @Transactional
    public ShareLink create(Long userId, Long fileId, String code, Date expireTime, Integer perm) {
        ShareLink link = new ShareLink();
        link.setFileId(fileId);
        link.setUserId(userId);
        link.setCode(code == null ? RandomUtil.randomNumbers(8) : code);
        link.setToken(RandomUtil.randomString(64));
        link.setExpireTime(expireTime);
        link.setPerm(perm);
        shareLinkMapper.insert(link);
        redisTemplate.opsForValue().set("share:code:" + link.getCode(),
                link.getId(), 7, TimeUnit.DAYS);
        return link;
    }

    /**
     * 提取分享文件：三重校验（token 有效性 + 有效期 + 提取码）
     * 校验通过返回预签名下载 URL，5 分钟有效
     */
    public ShareFileVO access(String token, String code) {
        ShareLink link = shareLinkMapper.selectOne(
                new LambdaQueryWrapper<ShareLink>().eq(ShareLink::getToken, token));
        if (link == null || link.getStatus() == 0) {
            throw new BizException("分享不存在或已取消");
        }
        if (link.getExpireTime() != null && link.getExpireTime().before(new Date())) {
            throw new BizException("分享已过期");
        }
        if (!link.getCode().equals(code)) {
            throw new BizException("提取码错误");
        }
        shareLinkMapper.incrVisit(link.getId());  // 访问计数
        FileMeta file = fileMetaMapper.selectById(link.getFileId());
        String url = minioService.presignedGetUrl(file.getObjectName(), 300);
        return ShareFileVO.of(file, url, link.getPerm());
    }

    /** 取消分享：状态置 0 并清 Redis 缓存 */
    public void cancel(Long userId, Long shareId) {
        ShareLink link = shareLinkMapper.selectById(shareId);
        if (!link.getUserId().equals(userId)) {
            throw new BizException("无权取消他人分享");
        }
        link.setStatus(0);
        shareLinkMapper.updateById(link);
        redisTemplate.delete("share:code:" + link.getCode());
    }
}
```

### 5. 回收站服务：软删除与定时清理

```java
@Service
public class RecycleBinService {

    /**
     * 删除（进回收站）：只标记状态，不删 MinIO 对象，恢复零成本
     */
    @Transactional
    public void recycle(Long userId, Long fileId) {
        FileMeta file = fileMetaMapper.selectById(fileId);
        if (!file.getUserId().equals(userId)) {
            throw new BizException("无权删除他人文件");
        }
        file.setStatus(0);
        fileMetaMapper.updateById(file);
        RecycleBin rb = new RecycleBin();
        rb.setFileId(fileId);
        rb.setUserId(userId);
        rb.setExpireTime(DateUtils.addDays(new Date(), 30));
        recycleBinMapper.insert(rb);
    }

    /** 恢复：状态置回 1，删除回收站记录 */
    public void restore(Long userId, Long fileId) {
        RecycleBin rb = recycleBinMapper.selectOne(
                new LambdaQueryWrapper<RecycleBin>().eq(RecycleBin::getFileId, fileId));
        if (rb == null || !rb.getUserId().equals(userId)) {
            throw new BizException("回收站记录不存在");
        }
        FileMeta file = fileMetaMapper.selectById(fileId);
        file.setStatus(1);
        fileMetaMapper.updateById(file);
        recycleBinMapper.deleteById(rb.getId());
    }

    /**
     * 彻底删除：删除 MinIO 对象与元数据，扣减容量
     * 由定时任务每日扫描过期记录调用
     */
    public void purge(Long fileId) {
        FileMeta file = fileMetaMapper.selectById(fileId);
        if (file != null && file.getIsDir() == 0) {
            minioService.removeObject(file.getObjectName());
        }
        fileMetaMapper.deleteById(fileId);
        recycleBinMapper.delete(new LambdaQueryWrapper<RecycleBin>()
                .eq(RecycleBin::getFileId, fileId));
        userMapper.decrUsedBytes(file.getUserId(), file.getSize());
    }
}
```

### 6. 容量统计服务：配额校验与部门汇总

```java
@Service
public class QuotaService {

    /**
     * 个人容量：实时值走 MySQL used_bytes（上传/删除时事务内增减）
     */
    public QuotaVO userQuota(Long userId) {
        User user = userMapper.selectById(userId);
        QuotaVO vo = new QuotaVO();
        vo.setQuotaBytes(user.getQuotaBytes());
        vo.setUsedBytes(user.getUsedBytes());
        vo.setPercent(user.getQuotaBytes() == 0
                ? 0 : user.getUsedBytes() * 100 / user.getQuotaBytes());
        return vo;
    }

    /**
     * 部门统计：汇总本部门及子部门所有成员的用量
     */
    public DeptQuotaVO deptQuota(Long deptId) {
        List<Long> deptIds = deptService.selfAndChildren(deptId);
        List<User> users = userMapper.selectList(
                new LambdaQueryWrapper<User>().in(User::getDeptId, deptIds));
        DeptQuotaVO vo = new DeptQuotaVO();
        vo.setDeptId(deptId);
        vo.setUserCount(users.size());
        vo.setUsedBytes(users.stream().mapToLong(User::getUsedBytes).sum());
        vo.setQuotaBytes(users.stream().mapToLong(User::getQuotaBytes).sum());
        return vo;
    }

    /**
     * 上传前校验容量：超配额直接拒绝，前端上传前也预检一次
     */
    public void checkQuota(Long userId, long needBytes) {
        User user = userMapper.selectById(userId);
        if (user.getUsedBytes() + needBytes > user.getQuotaBytes()) {
            long remainMb = (user.getQuotaBytes() - user.getUsedBytes()) / 1024 / 1024;
            throw new BizException("个人容量不足，剩余 " + remainMb + " MB");
        }
    }
}
```

## 实际应用场景

### 场景一：设计公司的素材库

设计团队每天产出大量 PSD、视频样片，动辄几百 MB 到几 GB：

```text
1. 设计师拖入 3GB 视频素材：前端算 MD5 未命中，发起分片上传，10 个分片并发传
2. 中途网络中断，重新上传时服务端返回已传分片号，只补传剩余 2 片，秒级续传
3. 同组另一设计师上传同一份素材，MD5 命中秒传，几毫秒完成
4. 素材按项目建目录树：「2026 春装/棚拍原片/精修」层级管理
5. 给甲方生成分享链接：设 7 天有效期 + 提取码，只读权限，甲方直接拿预签名 URL 下载
6. 管理员看统计：设计部已用 2.3TB / 配额 5TB，为扩容采购提供依据
```

### 场景二：企业内部文档中心

公司制度、合同、技术文档集中管理，替代公共盘：

```text
1. 管理员建部门树：行政部、研发部、财务部，各部门有独立共享目录
2. 研发部目录共享给研发全员（file_auth 按部门授权），新员工入职自动获得权限
3. 机密合同只共享给财务总监（个人共享 + 只读），下载行为进审计日志
4. 员工误删项目文档，从回收站 30 天内一键恢复
5. 离职员工账号禁用后，其名下文件交接给部门负责人
6. 财务总监电脑硬盘损坏，公司文档从网盘恢复，数据零丢失
```

### 场景三：SaaS 产品内置网盘模块

面向中小企业的 SaaS 系统（如项目管理系统）内置文件模块：

```text
1. 每个企业租户一个 MinIO bucket 前缀隔离，元数据按 tenant_id 分区
2. 项目附件走分片上传，50MB 以上的图纸、PDF 上传不卡顿
3. 预签名 URL 直传直下：文件流量走对象存储，应用服务器带宽成本大降
4. 对外交付文件用分享链接：可设密码、可设到期时间，到期自动失效
5. 用量统计按企业维度出账单，超配额触发付费升级引导
6. 秒传让协作场景（多人传同一份部署包）几乎零流量成本
```

## 最佳实践与踩坑记录

### 最佳实践

1. 元数据与数据分离：文件内容进 MinIO，目录/权限/分享/容量进 MySQL，查询统计只碰元数据
2. 秒传三步走：前端算 MD5 -> Redis 查缓存 -> MySQL 兜底，命中后 copyObject 而非复用同一对象，避免删一个文件影响另一个
3. 分片大小取 5-10MB 折中：太小分片数爆炸（MinIO 上限 10000 片），太大失去断点续传意义
4. 预签名 URL 有效期尽量短（下载 5 分钟），权限校验放应用层，URL 泄露的窗口越小越好
5. 断点续传状态放 Redis 而不是 MySQL：高频读写、可过期（TTL 24h），避免脏数据堆积
6. 容量统计用冗余字段（used_bytes 事务内增减），不要实时 SUM(file_meta.size)，大目录树全表扫描会拖垮接口
7. 回收站用软删除 + 定时任务两级清理：先标记后恢复零成本，30 天后批量 purge 真正释放对象存储

### 踩坑记录

```text
坑 1：分片合并后文件损坏
结论：合并出的文件打不开，MD5 对不上。
原因：分片 etag 记录不全或顺序错乱，completeMultipartUpload 要求 parts 按分片号升序。
解法：Redis Hash 按分片号存 etag，合并前先排序再组装 Part[]；每片上传后立即校验 etag 是否已记录。

坑 2：秒传误判
结论：不同文件 MD5 相同被当成同一文件秒传。
原因：MD5 是摘要不是唯一标识，理论上有碰撞概率。
解法：秒传命中后再比对 size；要求更高的场景换 SHA-256 或先上传头部几 KB 做二次校验。

坑 3：预签名 URL 泄露
结论：分享链接被转发后一直能下载。
原因：URL 有效期设成永久，或提取码为空。
解法：有效期默认 5 分钟以内；分享链接强制提取码 + 到期时间；下载走审计日志。

坑 4：断点续传失效
结论：刷新页面后已传分片全部重传。
原因：uploadId 存在 Redis 但 TTL 太短，或前端没保存 uploadId。
解法：uploadId TTL 设 24 小时；前端把 uploadId 存 localStorage，续传前先查已传分片。

坑 5：回收站恢复后文件丢失
结论：恢复文件后 MinIO 对象已不存在。
原因：purge 定时任务扫描到了未过期记录，或删除时误删了对象。
解法：purge 只处理 expire_time 已过的记录；回收站记录与元数据状态在事务内一起变更。

坑 6：并发上传同一目录重名
结论：两个用户同时上传同名文件，一个覆盖了另一个的元数据。
原因：秒传/重命名/移动只查重未加锁。
解法：上传走「先建临时目录后改名」或对 parent_id + name 加唯一索引；秒传与建元数据放同一事务。
```

## 项目背景

企业即时通讯（IM）是团队协作的地基：工作沟通、项目拉群、通知触达都依赖它。选它做综合实战项目，是因为它逼着你解决 CRUD 之外的硬问题：长连接管理、消息不丢不重、离线补拉、在线状态、已读回执——这些都是分布式系统里「可靠性」话题的缩影。技术栈上以 Spring Boot + WebSocket 为主干，Netty 作为大规模连接场景的可选升级路径，Redis 承担在线状态与未读数，MySQL 落消息记录。

业务痛点：

```text
1. 工作沟通散落在个人微信/QQ，公私不分，信息无法沉淀归档
2. 消息没有已读回执，发了消息不知道对方看没看，关键指令靠口头确认
3. 网络切换或刷新页面后消息丢失，离线期间的消息无从补拉
4. 群聊消息重复：重连后既推送又拉取，消息出现重复
5. 在线状态不可信：显示在线实际不在，或反过来
6. 公司通知（公告、审批提醒）没有统一触达通道，靠邮件层层转发
```

目标用户与核心诉求：

```text
1. 普通员工：单聊/群聊流畅、离线消息不丢、已读回执明确、@ 提醒不错过
2. 群主/管理员：建群拉人、踢人、全员通知、群文件与图片消息
3. 管理员：消息记录可查（合规审计）、在线状态统计、会话列表管理
```

项目要解决的核心问题一句话概括：让消息在弱网、离线、多端场景下都能不丢不重地送达，并让「谁在线、谁已读」清晰可信。

## 功能介绍

功能按模块拆成五块：单聊群聊、消息收发、会话管理、状态与回执、系统能力。

```text
一、单聊与群聊
1. 单聊 —— 一对一私信，支持文本/图片/文件消息
2. 群聊 —— 建群、拉人、退群、踢人、群公告、群名与头像设置
3. 群成员管理 —— 成员列表、群主转让、成员禁言（可选）

二、消息收发
1. 实时收发 —— WebSocket 长连接推送，毫秒级到达
2. 离线消息 —— 离线期间的消息落库，上线后自动补拉
3. 消息类型 —— 文本/图片/文件/@提醒/系统消息，统一 JSON 协议
4. 消息可靠性 —— 客户端生成 client_msg_id，服务端幂等去重；客户端 ack 确认

三、会话管理
1. 会话列表 —— 按最后消息时间排序，置顶会话
2. 未读数 —— 每个会话独立未读角标，点开清零
3. 消息记录 —— 历史消息分页查询，本地不落盘也能翻旧账

四、状态与回执
1. 在线状态 —— 在线/离线/离开三态，Redis 心跳续期
2. 已读回执 —— 单聊显示「已读/未读」，群聊显示已读人数
3. @提醒 —— 群聊 @ 某人，被 @ 者收到系统消息与未读高亮

五、系统能力
1. 登录认证 —— JWT 握手鉴权，非法连接直接拒绝
2. 文件/图片消息 —— 图片走对象存储（MinIO/OSS），消息里只存 URL
3. 通知通道 —— 离线时重要消息可降级为站内信/邮件（可选）
```

## 技术选型

| 组件 | 选型 | 理由 |
|------|------|------|
| 开发框架 | Spring Boot 2.7/3.x | 内置 WebSocket 支持，起步快 |
| 实时通信 | Spring WebSocket（TextWebSocketHandler） | 与 Spring 生态无缝集成，Bean 注入方便，中小规模够用 |
| 高性能通道（可选） | Netty | 连接数万级、需要自定义协议栈时升级，IM 大厂标配 |
| 数据库 | MySQL 8.0 | 消息、会话、群组、已读回执持久化 |
| 缓存 | Redis | 在线状态、未读数、离线消息计数、心跳续期 |
| 鉴权 | Spring Security + JWT | WebSocket 握手阶段校验 token |
| 序列化 | Jackson / Fastjson2 | 消息统一 JSON 协议 |
| 前端 | Vue 3 + 原生 WebSocket | 浏览器原生长连接，无需额外依赖 |

选型说明：

```text
1. Spring WebSocket 与 Netty 的关系：业务起步用 Spring WebSocket，Handler 是 Spring Bean 可自由注入 Service；
   连接数过万、要精细控制粘包拆包与内存池时，再平滑迁移到 Netty，消息协议与业务层不用动
2. Redis 承担在线状态：IM 在线状态是典型「高频读写、可短暂不一致」场景，Redis String + TTL 心跳最合适
3. 消息可靠性靠 MySQL 唯一索引而非消息队列：单机 IM 场景消息量可控，唯一索引去重比 MQ 简单可靠
4. 未读数实时走 Redis，定期刷回 MySQL：会话列表页每次只读 Redis Hash，不压数据库
```

## 架构设计

系统分层与消息链路：

```text
┌──────────────────────────────────────────────────────────────┐
│                       客户端（浏览器/App）                      │
│    登录（JWT）   WebSocket 长连接（/ws/chat）   REST 接口        │
└───────────────┬──────────────────────────────┬───────────────┘
                │ 握手携带 token 鉴权           │ HTTP/JSON
┌───────────────▼──────────────────────────────▼───────────────┐
│                       Spring Boot 应用层                      │
│  ┌────────────┐ ┌────────────┐ ┌────────────┐ ┌───────────┐  │
│  │ WS Handler │ │ MessageSvc │ │Conversation│ │ Security/ │  │
│  │(连接管理)   │ │(发送/幂等)  │ │  Service   │ │  JWT      │  │
│  └────────────┘ └────────────┘ └────────────┘ └───────────┘  │
└───────┬──────────────────────┬────────────────────┬──────────┘
        │                      │                    │
┌───────▼────────┐   ┌─────────▼────────┐   ┌───────▼─────────┐
│     MySQL      │   │      Redis       │   │   Netty（可选）  │
│ 消息/会话/成员/  │   │ 在线状态/未读数/  │   │ 大规模连接场景   │
│ 群组/已读回执   │   │ 离线消息计数/心跳  │   │ 替代内置 WS     │
└────────────────┘   └──────────────────┘   └─────────────────┘
```

消息发送链路（A 发消息给 B）：

```text
1. A 端生成 client_msg_id（UUID），通过 WebSocket 发送 JSON 消息
2. ChatWebSocketHandler 反序列化，调 MessageService.send
3. 幂等校验：sender_id + client_msg_id 唯一索引，重复投递直接返回已发送结果
4. 消息落库（事务），成功后推送
5. 遍历会话成员：在线成员走 WebSocket 直接推送，离线成员未读数 +1（Redis Hash）
6. B 端收到消息后回 ack（消息 id），服务端标记送达；超时未 ack 由客户端重发
7. 群聊含 @ 时，解析 @ 用户列表，额外生成系统提醒消息
```

离线补拉链路（B 上线）：

```text
1. B 登录后建立 WebSocket 连接，握手成功
2. 服务端从 Redis 取各会话未读数，返回会话列表（带未读角标）
3. B 端对每个会话调 GET /api/message/pull?convId=xx&lastMsgId=yy
4. 服务端查 MySQL 中 lastMsgId 之后的消息，分页返回
5. B 端渲染完最后一条后上报已读，服务端更新 last_read_msg_id 并清未读数
6. 单聊场景向 A 广播「B 已读」回执
```

设计要点：消息用 `client_msg_id` 唯一索引做幂等，这是「不重」的根基；未读数双写（Redis 实时 + MySQL 冗余）保证缓存丢失后可恢复；单聊会话用 `(type, owner_id, peer_id)` 唯一索引保证两人只会有一条会话。

## 核心实现

### 1. WebSocket 配置与握手鉴权

```java
@Configuration
@EnableWebSocket
public class WebSocketConfig implements WebSocketConfigurer {

    @Autowired
    private ChatWebSocketHandler chatWebSocketHandler;
    @Autowired
    private AuthHandshakeInterceptor authHandshakeInterceptor;

    /**
     * 注册 /ws/chat 端点，握手前先过 JWT 鉴权拦截器
     */
    @Override
    public void registerWebSocketHandlers(WebSocketHandlerRegistry registry) {
        registry.addHandler(chatWebSocketHandler, "/ws/chat")
                .addInterceptors(authHandshakeInterceptor)
                .setAllowedOrigins("*");  // 生产按域名收紧
    }
}

@Component
public class AuthHandshakeInterceptor implements HandshakeInterceptor {

    @Autowired
    private JwtUtil jwtUtil;

    /**
     * 握手阶段校验 token：合法则把 userId 放入 attributes 传给 Handler
     * 校验失败返回 false 拒绝建立连接
     */
    @Override
    public boolean beforeHandshake(ServerHttpRequest request, ServerHttpResponse response,
                                   WebSocketHandler wsHandler, Map<String, Object> attributes) {
        String token = ((ServletServerHttpRequest) request)
                .getServletRequest().getParameter("token");
        Long userId = jwtUtil.parseUserId(token);
        if (userId == null) {
            return false;  // 拒绝握手
        }
        attributes.put("userId", userId);
        return true;
    }

    @Override
    public void afterHandshake(ServerHttpRequest request, ServerHttpResponse response,
                               WebSocketHandler wsHandler, Exception exception) {
        // 握手后的回调，一般无需处理
    }
}
```

### 2. 连接管理：用户-连接映射

```java
@Component
public class ChatWebSocketHandler extends TextWebSocketHandler {

    // 用户 id -> 连接（单机版内存映射；集群版改为 Redis pub/sub 或 MQ 广播）
    private static final ConcurrentHashMap<Long, WebSocketSession> ONLINE = new ConcurrentHashMap<>();

    @Autowired
    private MessageService messageService;
    @Autowired
    private OfflineMessageService offlineMessageService;
    @Autowired
    private RedisTemplate<String, Object> redisTemplate;

    /** 上线：登记连接、写在线状态、返回未读数 */
    @Override
    public void afterConnectionEstablished(WebSocketSession session) {
        Long userId = (Long) session.getAttributes().get("userId");
        // 同一用户重复登录：踢掉旧连接，保证一个用户一条活跃连接
        WebSocketSession old = ONLINE.put(userId, session);
        if (old != null && old.isOpen()) {
            try {
                old.close(CloseStatus.NORMAL);
            } catch (IOException ignored) {
            }
        }
        // 在线状态写 Redis，TTL 90 秒，心跳每 30 秒续期
        redisTemplate.opsForValue().set("im:online:" + userId, "online", 90, TimeUnit.SECONDS);
        // 推送未读概览（各会话未读数）
        offlineMessageService.pushUnreadOverview(userId);
    }

    /** 收到客户端消息：心跳、聊天、已读上报统一入口 */
    @Override
    protected void handleTextMessage(WebSocketSession session, TextMessage message) {
        Long userId = (Long) session.getAttributes().get("userId");
        JSONObject body = JSON.parseObject(message.getPayload());
        String type = body.getString("type");
        switch (type) {
            case "heartbeat":
                // 心跳续期，同时把状态从「离开」切回「在线」
                redisTemplate.opsForValue().set("im:online:" + userId,
                        "online", 90, TimeUnit.SECONDS);
                break;
            case "chat":
                messageService.send(userId, body);
                break;
            case "read":
                messageService.markRead(userId, body.getLong("conversationId"),
                        body.getLong("lastMsgId"));
                break;
            default:
                log.warn("未知消息类型: {}", type);
        }
    }

    /** 下线：移除连接，状态置离线 */
    @Override
    public void afterConnectionClosed(WebSocketSession session, CloseStatus status) {
        Long userId = (Long) session.getAttributes().get("userId");
        ONLINE.remove(userId);
        redisTemplate.delete("im:online:" + userId);
    }

    /** 判断用户是否在线 */
    public static boolean isOnline(Long userId) {
        WebSocketSession session = ONLINE.get(userId);
        return session != null && session.isOpen();
    }

    /** 向在线用户推送消息，失败返回 false（调用方走离线补拉） */
    public static boolean push(Long userId, String payload) {
        WebSocketSession session = ONLINE.get(userId);
        if (session == null || !session.isOpen()) {
            return false;
        }
        synchronized (session) {  // 同一连接并发写需加锁
            try {
                session.sendMessage(new TextMessage(payload));
                return true;
            } catch (Exception e) {
                log.error("推送失败 userId={}", userId, e);
                return false;
            }
        }
    }
}
```

### 3. 消息服务：幂等 + 落库 + 分发

```java
@Service
public class MessageService {

    @Autowired
    private MessageMapper messageMapper;
    @Autowired
    private ConversationMapper conversationMapper;
    @Autowired
    private ConversationMemberMapper conversationMemberMapper;
    @Autowired
    private RedisTemplate<String, Object> redisTemplate;

    /**
     * 发送消息：幂等去重 -> 落库 -> 推在线 -> 离线计数
     * 消息先落库再推送：推送失败也能靠补拉找回，保证不丢
     */
    public SendResult send(Long senderId, JSONObject body) {
        String clientMsgId = body.getString("clientMsgId");
        Long conversationId = body.getLong("conversationId");
        // 1. 幂等：重复投递直接返回原消息，客户端不会收到重复内容
        Message exist = messageMapper.selectByClientMsgId(senderId, clientMsgId);
        if (exist != null) {
            return SendResult.duplicate(exist);
        }
        // 2. 校验发送人是否在会话里
        if (conversationMemberMapper.count(conversationId, senderId) == 0) {
            throw new BizException("不在该会话中，无法发送");
        }
        // 3. 落库
        Message msg = new Message();
        msg.setConversationId(conversationId);
        msg.setSenderId(senderId);
        msg.setMsgType(body.getIntValue("msgType", 1));
        msg.setContent(body.getString("content"));
        msg.setAtUserIds(body.getString("atUserIds"));
        msg.setClientMsgId(clientMsgId);
        messageMapper.insert(msg);
        // 4. 更新会话最后消息
        conversationMapper.updateLastMsg(conversationId, msg.getId());
        // 5. 分发：在线推送，离线未读数 +1
        List<Long> memberIds = conversationMemberMapper.memberIds(conversationId);
        for (Long uid : memberIds) {
            if (uid.equals(senderId)) {
                continue;  // 自己发的自己前端已回显
            }
            if (!ChatWebSocketHandler.push(uid, JSON.toJSONString(msg))) {
                // 离线：Redis 未读数 +1（Hash 按会话维度）
                redisTemplate.opsForHash().increment("im:unread:" + uid,
                        String.valueOf(conversationId), 1);
            }
        }
        // 6. @ 提醒：给被 @ 者额外发系统消息
        if (StringUtils.hasText(msg.getAtUserIds())) {
            sendAtRemind(msg);
        }
        return SendResult.ok(msg);
    }

    /** @ 提醒：被 @ 者未读高亮 + 系统消息 */
    private void sendAtRemind(Message msg) {
        for (String uid : msg.getAtUserIds().split(",")) {
            Long targetId = Long.valueOf(uid.trim());
            JSONObject remind = new JSONObject();
            remind.put("type", "at");
            remind.put("from", msg.getSenderId());
            remind.put("conversationId", msg.getConversationId());
            remind.put("messageId", msg.getId());
            if (!ChatWebSocketHandler.push(targetId, remind.toJSONString())) {
                redisTemplate.opsForHash().increment("im:at:" + targetId,
                        String.valueOf(msg.getConversationId()), 1);
            }
        }
    }
}
```

### 4. 离线消息：补拉与未读数

```java
@Service
public class OfflineMessageService {

    @Autowired
    private MessageMapper messageMapper;
    @Autowired
    private ConversationMemberMapper conversationMemberMapper;
    @Autowired
    private RedisTemplate<String, Object> redisTemplate;

    /**
     * 离线补拉：取 lastMsgId 之后的消息，分页返回
     * 客户端逐页拉完再上报已读，未读角标随之清零
     */
    public List<Message> pull(Long userId, Long conversationId, Long lastMsgId, int limit) {
        if (conversationMemberMapper.count(conversationId, userId) == 0) {
            throw new BizException("不在该会话中");
        }
        return messageMapper.selectAfter(conversationId, lastMsgId, limit);
    }

    /**
     * 上线推送未读概览：Redis Hash 各会话未读数 -> JSON 推给客户端
     */
    public void pushUnreadOverview(Long userId) {
        Map<Object, Object> unread = redisTemplate.opsForHash()
                .entries("im:unread:" + userId);
        JSONObject overview = new JSONObject();
        overview.put("type", "unread");
        overview.put("data", unread);
        ChatWebSocketHandler.push(userId, overview.toJSONString());
    }

    /**
     * 已读上报：更新 last_read_msg_id，清 Redis 未读数
     * 单聊场景向对方广播「已读」回执
     */
    public void markRead(Long userId, Long conversationId, Long lastMsgId) {
        conversationMemberMapper.updateLastRead(conversationId, userId, lastMsgId);
        redisTemplate.opsForHash().delete("im:unread:" + userId,
                String.valueOf(conversationId));
        // 查单聊对方，推送已读回执
        Long peerId = conversationMapper.singlePeerId(conversationId, userId);
        if (peerId != null) {
            JSONObject receipt = new JSONObject();
            receipt.put("type", "readReceipt");
            receipt.put("conversationId", conversationId);
            receipt.put("readerId", userId);
            receipt.put("lastMsgId", lastMsgId);
            ChatWebSocketHandler.push(peerId, receipt.toJSONString());
        }
    }
}
```

### 5. 会话服务：单聊定位与会话列表

```java
@Service
public class ConversationService {

    /**
     * 单聊定位：两人共用一条会话，owner/peer 按 id 大小排序保证唯一性
     * 不存在则创建，并给双方插入成员记录
     */
    @Transactional
    public Long ensureSingleConversation(Long u1, Long u2) {
        Long min = Math.min(u1, u2);
        Long max = Math.max(u1, u2);
        Conversation c = conversationMapper.selectOne(
                new LambdaQueryWrapper<Conversation>()
                        .eq(Conversation::getType, 1)
                        .eq(Conversation::getOwnerId, min)
                        .eq(Conversation::getPeerId, max));
        if (c != null) {
            return c.getId();
        }
        Conversation conv = new Conversation();
        conv.setType(1);
        conv.setOwnerId(min);
        conv.setPeerId(max);
        conversationMapper.insert(conv);
        conversationMemberMapper.insert(conv.getId(), u1);
        conversationMemberMapper.insert(conv.getId(), u2);
        return conv.getId();
    }

    /**
     * 会话列表：按最后消息时间倒序，带未读数与最后一条消息预览
     * 未读数从 Redis 取，避免每次查库
     */
    public List<ConversationVO> list(Long userId) {
        List<ConversationVO> list = conversationMapper.selectByUser(userId);
        Map<Object, Object> unread = redisTemplate.opsForHash()
                .entries("im:unread:" + userId);
        for (ConversationVO vo : list) {
            Object n = unread.get(String.valueOf(vo.getId()));
            vo.setUnreadCount(n == null ? 0 : Integer.parseInt(n.toString()));
            vo.setOnline(ChatWebSocketHandler.isOnline(vo.getPeerId()));  // 单聊显示对方在线状态
        }
        list.sort(Comparator.comparing(ConversationVO::getLastMsgTime).reversed());
        return list;
    }
}
```

### 6. 在线状态与心跳

```java
@Service
public class PresenceService {

    /**
     * 在线状态三态：在线 / 离线 / 离开
     * Redis key：im:online:{userId}，value 为状态，TTL 90 秒
     * 心跳每 30 秒续期；离开状态由客户端主动上报（如切后台）
     */
    public String getStatus(Long userId) {
        Object v = redisTemplate.opsForValue().get("im:online:" + userId);
        if (v == null) {
            return "offline";
        }
        return v.toString();  // online / away
    }

    /** 客户端上报离开（切后台、锁屏） */
    public void markAway(Long userId) {
        redisTemplate.opsForValue().set("im:online:" + userId, "away", 90, TimeUnit.SECONDS);
    }

    /** 批量查询好友在线状态（会话列表、通讯录用） */
    public Map<Long, String> batchStatus(List<Long> userIds) {
        Map<Long, String> result = new HashMap<>();
        for (Long uid : userIds) {
            result.put(uid, getStatus(uid));
        }
        return result;
    }
}
```

### 7. Netty 版服务端（可选升级路径）

```java
/**
 * Netty 版服务端（可选）：连接数万级、需要精细控制协议时使用
 * 与 Spring WebSocket 共用 MessageService 业务层，协议解析复用
 */
@Component
public class NettyChatServer {

    private final EventLoopGroup boss = new NioEventLoopGroup(1);
    private final EventLoopGroup worker = new NioEventLoopGroup();

    @PostConstruct
    public void start() throws InterruptedException {
        ServerBootstrap bootstrap = new ServerBootstrap();
        bootstrap.group(boss, worker)
                .channel(NioServerSocketChannel.class)
                .childHandler(new ChannelInitializer<SocketChannel>() {
                    @Override
                    protected void initChannel(SocketChannel ch) {
                        ch.pipeline()
                                .addLast(new HttpServerCodec())
                                .addLast(new HttpObjectAggregator(65536))
                                .addLast(new WebSocketServerProtocolHandler("/ws"))
                                .addLast(new NettyChatHandler());  // 业务处理，内部调 MessageService
                    }
                });
        bootstrap.bind(8088).sync();
        log.info("Netty 聊天服务已启动，端口 8088");
    }

    @PreDestroy
    public void stop() {
        boss.shutdownGracefully();
        worker.shutdownGracefully();
    }
}
```

## 实际应用场景

### 场景一：公司全员 IM 替代个人微信

500 人规模的公司用内部 IM 替代工作群：

```text
1. 员工登录网页端/客户端，JWT 握手后建立 WebSocket 长连接
2. 研发部拉「发布群」，发版公告 @全员，被 @ 者收到系统提醒
3. 网络波动导致连接断开，重连后服务端返回各会话未读数，逐个会话补拉离线消息
4. 领导发关键指令，单聊显示「已读」，未读时同事主动跟进，不再靠口头确认
5. 群内发图片/文件消息，内容走 MinIO，消息里只存 URL，聊天记录不膨胀
6. 员工下班切后台，状态显示「离开」；30 秒心跳停止后自动转「离线」
7. 管理员按需导出消息记录做合规审计（消息落库的天然优势）
```


SaaS 产品把 IM 能力封装成站内通知通道：


## 最佳实践与踩坑记录

### 最佳实践

1. 消息先落库再推送：推送失败的消息可以靠补拉找回，保证「不丢」；先推后存则推送成功但落库失败会造成逻辑缺失
2. 幂等是「不重」的根基：客户端生成 client_msg_id，服务端唯一索引去重，重发/重连都不会重复入库
3. 一个用户只保留一条活跃连接：重复登录时踢掉旧连接，避免消息推送到陈旧连接上
4. 未读数实时走 Redis、定期刷 MySQL：Redis Hash 按会话计数，会话列表零数据库压力；缓存丢失可从 last_read_msg_id 重算
5. 在线状态用「TTL + 心跳续期」而不是显式下线：断网时 TCP 关闭事件不可靠，TTL 过期自动判离线最稳妥
6. 同一连接并发推送要加锁：多个线程同时 sendMessage 会抛异常，按 session 加 synchronized
7. 消息协议统一 JSON + type 字段：chat/read/heartbeat/at 全部走一条长连接，减少握手次数；协议升级靠新增 type 兼容旧端

### 踩坑记录

```text
坑 1：消息重复
结论：客户端重连后同一消息出现两次。
原因：发送成功但 ack 丢失，客户端超时重发，服务端没有去重。
解法：client_msg_id 唯一索引幂等；重发返回原消息 id，客户端按 id 去重渲染。

坑 2：消息丢失
结论：断网瞬间发送的消息没了。
原因：消息先推送后落库，或推送时客户端已断开但未计数离线。
解法：先落库后推送；推送失败必须走离线未读数 +1，上线补拉兜底。

坑 3：连接池泄漏
结论：长期运行后内存暴涨，连接数只增不减。
原因：客户端异常退出（杀进程、断网）时 afterConnectionClosed 不触发，ONLINE 里堆积死连接。
解法：Redis TTL 心跳兜底 + 定时任务清理过期连接；服务端定期 ping 探测。

坑 4：并发推送报错
结论：高并发下 sendMessage 抛 IllegalStateException。
原因：同一 WebSocketSession 被多线程同时写。
解法：按 session 加 synchronized 或引入写队列，串行化发送。

坑 5：单聊出现两条会话
结论：A 先发 B 后发，出现两条会话，消息分流。
原因：ensureSingleConversation 并发下重复创建，唯一索引没覆盖到。
解法：owner/peer 按 id 排序保证 (type, owner_id, peer_id) 唯一；并发创建冲突时捕获 DuplicateKey 再查一次。

坑 6：离线补拉后未读角标不准
结论：补拉完角标还是旧的。
原因：补拉和已读上报不是原子操作，拉取期间又有新消息进来。
解法：已读上报带 lastMsgId 幂等；角标以「最后消息 id > last_read_msg_id」实时计算为准。
```

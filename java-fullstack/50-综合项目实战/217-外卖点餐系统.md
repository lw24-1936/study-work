## 项目背景

外卖点餐是电商交易体系里最具代表性的一类业务：用户端浏览下单、商家端接单出餐、配送端履约、平台端清算，一条链路串起三种角色，涉及购物车、库存、支付、状态机、消息通知几乎所有交易系统核心问题。选择它作为综合实战项目，是因为「点餐」比纯电商多了实时性要求（出餐状态实时可见、商家营业状态实时切换）和履约复杂度（配送环节），能把 Redis 缓存、分布式事务边界、消息队列、状态机设计完整串起来。

业务痛点：

```text
1. 菜单管理混乱：菜品没有分类，规格（大份/小份）不单独定价，改价格要改整条记录
2. 购物车频繁读写：每次加减商品都操作数据库，高峰期数据库连接被购物车拖垮
3. 超卖：最后一份鸡腿被两个人同时下单，商家无货可发
4. 订单状态全靠人肉改：没有状态机约束，待支付订单被直接改成配送中
5. 支付回调重复：支付平台重试回调导致同一订单入账两次
6. 商家接单不及时：新订单靠喊，高峰期漏单，无消息通知机制
7. 配送无轨迹：订单出了店就失联，用户只能干等
```

目标用户与核心诉求：

```text
1. 用户：浏览菜单、加购物车、下单支付、实时看订单状态、收到餐后评价
2. 商家：管理店铺营业状态、菜单分类与菜品规格、接单/出餐/发货、回复评价
3. 骑手（配送员）：接单、更新配送状态（取餐/送达）
4. 平台管理员：商家入驻审核、订单纠纷处理、平台经营数据统计
```

项目要解决的核心问题一句话概括：让「点餐-支付-出餐-配送-评价」整条交易链路在并发下不错单、不超卖、状态不乱、信息实时。

## 功能介绍

功能按角色拆成四个端：用户端、商家端、配送端、平台端。

```text
一、用户端（消费者视角）
1. 商家浏览 —— 按距离/评分/销量排序，营业状态与配送费可见
2. 菜单查看 —— 分类点餐（热销/主食/饮品），菜品详情含规格与库存
3. 购物车 —— 加购/减购/修改数量/清空，Redis 存储，跨会话保留
4. 下单 —— 从购物车生成订单，校验营业时间/库存/金额，下单即锁定库存
5. 支付 —— 余额支付/模拟第三方支付，支付回调幂等处理
6. 订单跟踪 —— 状态机驱动：待支付/已接单/配送中/已完成/已取消，配送中显示骑手信息
7. 评价 —— 订单完成后对商家/菜品评分留言，商家可回复

二、商家端（商家视角）
1. 店铺管理 —— 营业状态切换（营业中/休息中/打烊），修改配送费与营业时间
2. 菜单管理 —— 分类增删改，菜品上下架，规格（大/中/小份）独立定价与库存
3. 接单管理 —— 新订单实时提醒（MQ 推送），接单/出餐/开始配送操作
4. 评价管理 —— 查看用户评价并回复，评分影响店铺综合评分
5. 营业统计 —— 今日订单数/营业额/热销菜品 Top10

三、配送端（骑手视角）
1. 配送单池 —— 已出餐待配送订单列表，骑手抢单/被指派
2. 配送操作 —— 取餐确认、送达确认，状态流转同步到订单
3. 我的配送 —— 进行中/已完成配送单，配送量统计

四、平台端（管理员视角）
1. 商家管理 —— 商家入驻审核、违规下架
2. 订单监控 —— 超时未接单订单预警、退款纠纷处理
3. 数据看板 —— GMV、订单量、客单价、取消率
```

## 技术选型

| 组件 | 选型 | 理由 |
|------|------|------|
| 开发框架 | Spring Boot 2.7/3.x | 生态成熟，起步快 |
| 持久层 | MyBatis-Plus | 单表 CRUD 零 SQL，复杂统计走 XML，分页插件开箱即用 |
| 数据库 | MySQL 8.0 | 订单/菜品/评价落库，事务保证一致性 |
| 缓存 | Redis | 购物车（Hash）、菜品缓存、库存预扣、幂等标记 |
| 消息队列 | RabbitMQ | 新订单通知商家、支付成功事件、延迟队列做超时关单 |
| 分布式锁 | Redisson | 下单防并发、支付回调幂等锁 |
| 分布式ID | 雪花算法（MyBatis-Plus 内置） | 订单号全局唯一，趋势递增 |
| 鉴权 | Spring Security + JWT | 用户/商家/骑手三套角色 |
| 前端 | Vue 3 + Element Plus（商家端）/ 移动端 H5（用户端） | 商家端后台管理，用户端 H5 点餐 |

选型说明：

```text
1. MyBatis-Plus 而非纯 MyBatis：商家/菜品/评价全是标准单表 CRUD，MP 的 BaseMapper 直接省掉大量样板代码
2. 购物车必须放 Redis：用户加购操作频繁且无事务诉求，Hash 结构（field=菜品:规格, value=数量）天然适合
3. 库存扣减用数据库条件更新（UPDATE ... SET stock=stock-n WHERE stock>=n）保证不超卖，Redis 预扣只做热点菜品限流
4. 订单状态机是防「状态乱跳」的唯一可靠手段：所有状态变更收敛到状态机方法，非法流转直接拒绝
5. RabbitMQ 承担三类消息：新订单通知（商家端实时刷新）、支付成功事件、超时未支付关单（TTL+死信队列）
6. 超时关单用「延迟队列 + 定时任务兜底」双保险：延迟消息正常路径，定时任务扫描异常积压
```

```text
│   用户端（H5）     商家端（Vue3）     骑手端（H5）     平台端       │
└──────────────────────────────┬───────────────────────────────────┘
                               │ HTTP / JSON（JWT 三角色）
┌──────────────────────────────▼───────────────────────────────────┐
│                        Spring Boot 应用层                         │
│  ┌─────────┐ ┌─────────┐ ┌─────────┐ ┌─────────┐ ┌────────────┐  │
│  │Controller│ │ Service │ │ Mapper  │ │ 状态机   │ │ MQ 生产者/  │  │
│  └─────────┘ └─────────┘ └─────────┘ └─────────┘ │ 消费者      │  │
│   商家/菜单  购物车/下单/支付  配送/评价  统计       └────────────┘  │
└───────┬───────────────────────────────┬──────────────────────────┘
        │                               │
┌───────▼───────────┐   ┌───────────────▼───────┐   ┌─────────────┐
│      MySQL         │   │        Redis           │   │  RabbitMQ   │
│ 商家/分类/菜品/规格/ │   │ 购物车Hash/菜品缓存/    │   │ 新订单/支付  │
│ 订单/明细/评价      │   │ 库存预扣/幂等标记/锁    │   │ 事件/延迟关单 │
└───────────────────┘   └───────────────────────┘   └─────────────┘
```

下单链路（用户从购物车提交订单）：

```text
1. 前端 POST /api/order，携带购物车快照、收货地址、支付方式
2. Service 校验：商家营业中、菜品上架、库存充足、金额一致（服务端重算）
3. 获取 Redisson 锁 order:create:lock:{userId}，防同一用户并发下单
4. 事务内执行：扣库存（条件更新）-> 插入订单 + 订单明细（快照价格）-> 清购物车对应项
5. 事务提交后发 MQ：order.created 事件通知商家端实时刷新
6. 返回订单号；待支付订单 15 分钟未支付，延迟队列消息触发自动取消并回补库存
7. 用户支付成功，回调幂等处理后状态流转为已支付/已接单（按商家配置）
```

订单状态流转链路（一笔订单的一生）：

```text
1. 下单成功 -> 待支付（status=0）
2. 支付回调成功 -> 已支付，商家端收到新订单提醒
3. 商家接单 -> 已接单
4. 商家出餐、骑手取餐 -> 配送中（绑定骑手）
5. 骑手送达确认 -> 已完成，用户可评价
6. 分支：待支付超时/用户取消 -> 已取消（库存回补）；已支付后商家拒单/用户退款 -> 已退款
```

Redis Key 设计：

```text
cart:{userId}                    Hash   购物车：field=dishId:specId，value=数量，TTL=7天
cart:lock:{userId}               String 购物车操作锁（防止并发加减同一商品互相覆盖）
dish:info:{id}                   String 菜品详情缓存（含规格列表），菜品变更时删除，TTL=30min
menu:{merchantId}                String 商家菜单缓存（分类+菜品树），营业状态/菜品变更时删除，TTL=10min
dish:stock:{id}                  String 热点菜品库存预扣缓存（可选），与 DB 库存对账
order:create:lock:{userId}       String 下单分布式锁（防止同一用户并发提交多个订单）
order:pay:lock:{orderNo}         String 支付处理锁（防止支付回调并发重复入账）
pay:notify:done:{orderNo}        String 支付回调幂等标记，SETNX 后 TTL=24h
merchant:neworder:{merchantId}   List   商家新订单待处理队列（MQ 之外的消息兜底通道）
```

MQ 消息设计：

```text
1. order.created（下单成功）  -> 商家端消费：实时刷新新订单列表，未接单订单超时告警
2. order.paid（支付成功）     -> 商家端消费：新订单提醒、厨房打印小票；用户端状态推送
3. order.delivering/done      -> 状态变更事件：用户端实时跟踪
4. order.timeout（延迟 15 分钟）-> 死信队列消费：待支付订单自动取消 + 库存回补
5. review.created             -> 平台端消费：更新商家评分与评分人数
```

## 核心实现

### 1. 购物车：Redis Hash 存储

购物车是高频写、无事务诉求的临时数据，放 Redis 用 Hash 结构：field=`dishId:specId` 唯一标识一个可购项，value=数量，加减用原子操作避免并发覆盖。

```java
@Service
public class CartService {

    @Autowired
    private RedisTemplate<String, Object> redisTemplate;
    @Autowired
    private DishMapper dishMapper;

    private String cartKey(Long userId) {
        return "cart:" + userId;
    }

    /**
     * 加购：Hash 原子自增数量，field = dishId:specId
     * 加购前校验菜品上架状态，防止下架菜还能加
     */
    public void add(Long userId, Long dishId, Long specId, int quantity) {
        Dish dish = dishMapper.selectById(dishId);
        if (dish == null || dish.getStatus() != 1) {
            throw new BizException("菜品已下架");
        }
        String field = dishId + ":" + (specId == null ? "0" : specId);
        // HINCRBY 原子加数量，并发加减不互相覆盖
        redisTemplate.opsForHash().increment(cartKey(userId), field, quantity);
        // 刷新 TTL：活跃购物车顺延 7 天
        redisTemplate.expire(cartKey(userId), Duration.ofDays(7));
    }

    /**
     * 减购：减到 0 或负数时删除该 field
     */
    public void reduce(Long userId, Long dishId, Long specId, int quantity) {
        String key = cartKey(userId);
        String field = dishId + ":" + (specId == null ? "0" : specId);
        // 先减后查：减完数量 <= 0 则移除
        Long remain = redisTemplate.opsForHash().increment(key, field, -quantity);
        if (remain != null && remain <= 0) {
            redisTemplate.opsForHash().delete(key, field);
        }
    }

    /**
     * 查看购物车：回源 MySQL 取最新价格/库存/上下架状态
     * 价格以 DB 为准，购物车只存数量，避免缓存价格过期导致金额错乱
     */
    public List<CartItemVO> listCart(Long userId) {
        Map<Object, Object> entries = redisTemplate.opsForHash().entries(cartKey(userId));
        List<CartItemVO> items = new ArrayList<>();
        for (Map.Entry<Object, Object> e : entries.entrySet()) {
            String field = e.getKey().toString();
            String[] parts = field.split(":");
            Long dishId = Long.valueOf(parts[0]);
            Long specId = Long.valueOf(parts[1]);
            int quantity = Integer.parseInt(e.getValue().toString());
            // 回源组装：菜品信息 + 规格信息 + 最新价格
            CartItemVO vo = assemble(dishId, specId, quantity);
            if (vo != null) {
                items.add(vo); // 菜品下架则跳过
            }
        }
        return items;
    }

    /**
     * 清空购物车（下单成功后调用）
     */
    public void clear(Long userId) {
        redisTemplate.delete(cartKey(userId));
    }
}
```

### 2. 下单：订单 + 明细 + 库存 一个事务

下单是核心事务：扣库存、建订单、建明细、清购物车，四步必须同生共死。库存扣减用条件更新防超卖；下单成功后发 MQ 通知商家。

```java
@Service
public class OrderService {

    @Autowired
    private OrderMapper orderMapper;
    @Autowired
    private OrderItemMapper orderItemMapper;
    @Autowired
    private DishMapper dishMapper;
    @Autowired
    private SpecMapper specMapper;
    @Autowired
    private CartService cartService;
    @Autowired
    private RabbitTemplate rabbitTemplate;
    @Autowired
    private RedissonClient redissonClient;

    /**
     * 从购物车下单
     */
    @Transactional
    public String createOrder(OrderRequest req) {
        // 1. 校验商家营业状态
        Merchant merchant = merchantMapper.selectById(req.getMerchantId());
        if (merchant == null || merchant.getBusinessStatus() != 1) {
            throw new BizException("商家当前未营业");
        }
        // 2. 用户级锁：防止同一用户并发提交多个订单
        String lockKey = "order:create:lock:" + req.getUserId();
        RLock lock = redissonClient.getLock(lockKey);
        boolean locked = lock.tryLock();
        if (!locked) {
            throw new BizException("请勿重复提交订单");
        }
        try {
            // 3. 读取购物车，服务端重算金额（不信任前端传的金额）
            List<CartItemVO> cart = cartService.listCart(req.getUserId());
            if (cart.isEmpty()) {
                throw new BizException("购物车为空");
            }
            // 4. 逐项扣库存（条件更新：库存足够才扣成功）
            BigDecimal total = BigDecimal.ZERO;
            for (CartItemVO item : cart) {
                int rows = deductStock(item.getDishId(), item.getSpecId(), item.getQuantity());
                if (rows == 0) {
                    throw new BizException("「" + item.getDishName() + "」库存不足");
                }
                total = total.add(item.getPrice().multiply(BigDecimal.valueOf(item.getQuantity())));
            }
            // 5. 插入订单 + 明细（明细快照价格）
            Orders order = new Orders();
            order.setOrderNo(IdWorker.getIdStr()); // 雪花ID
            order.setUserId(req.getUserId());
            order.setMerchantId(req.getMerchantId());
            order.setTotalAmount(total);
            order.setDeliveryFee(merchant.getDeliveryFee());
            order.setPayAmount(total.add(merchant.getDeliveryFee()));
            order.setStatus(OrderStatus.PENDING_PAY.getCode());
            order.setAddress(req.getAddress());
            order.setContactName(req.getContactName());
            order.setContactPhone(req.getContactPhone());
            order.setRemark(req.getRemark());
            orderMapper.insert(order);
            for (CartItemVO item : cart) {
                OrderItem oi = new OrderItem();
                oi.setOrderId(order.getId());
                oi.setDishId(item.getDishId());
                oi.setDishName(item.getDishName());
                oi.setSpecId(item.getSpecId());
                oi.setSpecName(item.getSpecName());
                oi.setPrice(item.getPrice());
                oi.setQuantity(item.getQuantity());
                oi.setAmount(item.getPrice().multiply(BigDecimal.valueOf(item.getQuantity())));
                orderItemMapper.insert(oi);
            }
            // 6. 清购物车
            cartService.clear(req.getUserId());
            // 7. 事务提交后发消息通知商家（通过 TransactionSynchronization 保证提交后再发）
            TransactionSynchronizationManager.registerSynchronization(
                    new TransactionSynchronization() {
                        @Override
                        public void afterCommit() {
                            rabbitTemplate.convertAndSend("order.exchange", "order.created",
                                    order.getOrderNo());
                        }
                    });
            return order.getOrderNo();
        } finally {
            if (lock.isHeldByCurrentThread()) {
                lock.unlock();
            }
        }
    }

    /**
     * 扣库存：菜品级与规格级两个维度
     * 条件更新 WHERE stock >= n 或 stock = -1（不限量），天然防超卖
     */
    private int deductStock(Long dishId, Long specId, int quantity) {
        if (specId != null && specId > 0) {
            return specMapper.deductStock(specId, quantity);
        }
        return dishMapper.deductStock(dishId, quantity);
    }
}
```

### 3. 支付：余额支付 + 回调幂等

余额支付在同一事务里扣余额、更新订单状态；第三方支付（模拟）靠回调驱动，回调处理用「分布式锁 + 状态条件更新 + 幂等标记」三重防重。

```java
@Service
public class PaymentService {

    @Autowired
    private OrderMapper orderMapper;
    @Autowired
    private UserAccountMapper accountMapper;
    @Autowired
    private RabbitTemplate rabbitTemplate;
    @Autowired
    private RedissonClient redissonClient;
    @Autowired
    private RedisTemplate<String, Object> redisTemplate;

    /**
     * 余额支付：扣用户余额 + 订单状态流转，一个事务
     */
    @Transactional
    public void payByBalance(String orderNo, Long userId) {
        Orders order = orderMapper.selectByOrderNo(orderNo);
        if (order == null || !order.getUserId().equals(userId)) {
            throw new BizException("订单不存在");
        }
        // 只有待支付订单能支付（状态条件更新防重复支付）
        int rows = accountMapper.deductBalance(userId, order.getPayAmount());
        if (rows == 0) {
            throw new BizException("余额不足");
        }
        rows = orderMapper.updateStatusByCondition(orderNo,
                OrderStatus.PAID.getCode(), OrderStatus.PENDING_PAY.getCode());
        if (rows == 0) {
            // 状态没变说明已支付/已取消，回滚扣款
            accountMapper.refundBalance(userId, order.getPayAmount());
            throw new BizException("订单状态已变化，支付失败");
        }
        order.setPayType(1);
        order.setPayTime(LocalDateTime.now());
        orderMapper.updateById(order);
        // 事务提交后发支付成功事件
        TransactionSynchronizationManager.registerSynchronization(
                new TransactionSynchronization() {
                    @Override
                    public void afterCommit() {
                        rabbitTemplate.convertAndSend("order.exchange", "order.paid", orderNo);
                    }
                });
    }

    /**
     * 第三方支付回调（微信/支付宝模拟）：幂等处理
     * 回调可能重复到达、可能乱序，必须幂等
     */
    public void handlePayNotify(String orderNo, String tradeNo) {
        String lockKey = "order:pay:lock:" + orderNo;
        RLock lock = redissonClient.getLock(lockKey);
        lock.lock();
        try {
            // 幂等标记：处理过的回调直接返回
            Boolean first = redisTemplate.opsForValue()
                    .setIfAbsent("pay:notify:done:" + orderNo, tradeNo, Duration.ofHours(24));
            if (Boolean.FALSE.equals(first)) {
                return; // 已处理过
            }
            // 状态条件更新：只有待支付 -> 已支付（已取消的订单拒绝入账，走退款）
            int rows = orderMapper.updateStatusByCondition(orderNo,
                    OrderStatus.PAID.getCode(), OrderStatus.PENDING_PAY.getCode());
            if (rows > 0) {
                orderMapper.updatePayInfo(orderNo, tradeNo, LocalDateTime.now());
                rabbitTemplate.convertAndSend("order.exchange", "order.paid", orderNo);
            }
        } finally {
            lock.unlock();
        }
    }
}
```

### 4. 订单状态机：非法流转拦截

订单所有状态变更收敛到状态机方法，非法流转（待支付直接改配送中、已完成改取消）直接拒绝，从代码层面杜绝状态乱跳。

```java
@Component
public class OrderStateMachine {

    /**
     * 状态流转表：key = 当前状态，value = 允许到达的目标状态集合
     */
    private static final Map<OrderStatus, Set<OrderStatus>> FLOW = new EnumMap<>(OrderStatus.class);

    static {
        // 待支付 -> 已支付 / 已取消
        FLOW.put(OrderStatus.PENDING_PAY, Set.of(OrderStatus.PAID, OrderStatus.CANCELLED));
        // 已支付 -> 已接单 / 已退款（商家拒单）
        FLOW.put(OrderStatus.PAID, Set.of(OrderStatus.ACCEPTED, OrderStatus.REFUNDED));
        // 已接单 -> 配送中 / 已退款（商家无法履约）
        FLOW.put(OrderStatus.ACCEPTED, Set.of(OrderStatus.DELIVERING, OrderStatus.REFUNDED));
        // 配送中 -> 已完成
        FLOW.put(OrderStatus.DELIVERING, Set.of(OrderStatus.FINISHED));
        // 终态：已完成 / 已取消 / 已退款 不可再流转
        FLOW.put(OrderStatus.FINISHED, Set.of());
        FLOW.put(OrderStatus.CANCELLED, Set.of());
        FLOW.put(OrderStatus.REFUNDED, Set.of());
    }

    @Autowired
    private OrderMapper orderMapper;

    /**
     * 状态流转唯一入口：校验合法性 + 条件更新 + 事件发布
     * 返回 true 表示流转成功，false 表示状态已被并发修改
     */
    public boolean transit(String orderNo, OrderStatus from, OrderStatus to) {
        // 1. 合法性校验：流转表里查不到就是非法流转
        Set<OrderStatus> allowed = FLOW.get(from);
        if (allowed == null || !allowed.contains(to)) {
            throw new BizException("非法状态流转：" + from + " -> " + to);
        }
        // 2. 条件更新：只有当前状态确实是 from 才更新，防并发覆盖
        int rows = orderMapper.updateStatusByCondition(orderNo, to.getCode(), from.getCode());
        if (rows == 0) {
            return false;
        }
        // 3. 发布状态变更事件（用户端实时跟踪）
        orderMapper.publishEvent(orderNo, to);
        return true;
    }
}
```

```java
@Service
public class MerchantOrderService {
```

### 5. 超时未支付自动关单：延迟队列 + 定时任务兜底

下单成功发一条延迟 15 分钟的消息，到期进死信队列由消费者关单；同时定时任务扫描兜底，防止消息丢失导致订单永远挂起。

```java
@Component
public class OrderTimeoutConsumer {

    @Autowired
    private OrderMapper orderMapper;
    @Autowired
    private DishMapper dishMapper;
    @Autowired
    private OrderItemMapper orderItemMapper;

    /**
     * 消费延迟队列的死信消息：取消超时未支付订单并回补库存
     */
    @RabbitListener(queues = "order.timeout.queue")
    public void handleTimeout(String orderNo) {
        cancelOrder(orderNo);
    }

    /**
     * 关单逻辑：待支付 -> 已取消，回补库存 + 销量回退
     * 条件更新保证并发安全（用户刚好支付的竞态）
     */
    @Transactional
    public void cancelOrder(String orderNo) {
        // 只有待支付订单能取消：用户刚好完成支付时此处影响行数为 0
        int rows = orderMapper.updateStatusByCondition(orderNo,
                OrderStatus.CANCELLED.getCode(), OrderStatus.PENDING_PAY.getCode());
        if (rows == 0) {
            return; // 已支付或已取消，无需处理
        }
        // 回补库存：按明细逐项回补
        List<OrderItem> items = orderItemMapper.selectByOrderNo(orderNo);
        for (OrderItem item : items) {
            if (item.getSpecId() != null && item.getSpecId() > 0) {
                dishMapper.restoreSpecStock(item.getSpecId(), item.getQuantity());
            } else {
                dishMapper.restoreStock(item.getDishId(), item.getQuantity());
            }
        }
    }
}

@Component
public class OrderTimeoutTask {

    @Autowired
    private OrderMapper orderMapper;
    @Autowired
    private OrderTimeoutConsumer timeoutConsumer;

    /**
     * 兜底任务：每 2 分钟扫一次创建超过 15 分钟仍待支付的订单
     * 与延迟队列互备：消息丢失也不怕
     */
    @Scheduled(fixedDelay = 2 * 60 * 1000)
    public void scanTimeoutOrders() {
        LocalDateTime deadline = LocalDateTime.now().minusMinutes(15);
        List<String> orderNos = orderMapper.selectTimeoutPending(deadline);
        for (String orderNo : orderNos) {
            // 重复扫描无副作用：条件更新保证只关一次
            timeoutConsumer.cancelOrder(orderNo);
        }
    }
}
```

```java
@Service
public class ReviewService {

    @Autowired
    private ReviewMapper reviewMapper;
    @Autowired
    private OrderMapper orderMapper;
    @Autowired
    private MerchantMapper merchantMapper;

                    public void afterCommit() {

                                review.getId());
                    }
                });
    }

    /**
     * 消费评价事件：更新商家综合评分（加权平均，评分人数越多越稳）
     */
    @RabbitListener(queues = "review.stat.queue")
    public void updateMerchantRating(Long reviewId) {
        Review review = reviewMapper.selectById(reviewId);
        Merchant merchant = merchantMapper.selectById(review.getMerchantId());
        // 新评分 = (旧评分 * 旧人数 + 新评分) / (旧人数 + 1)
        Long count = reviewMapper.countByMerchant(merchant.getId());
        BigDecimal newRating = merchant.getRating()
                .multiply(BigDecimal.valueOf(count - 1))
                .add(BigDecimal.valueOf(review.getRating()))
                .divide(BigDecimal.valueOf(count), 1, RoundingMode.HALF_UP);
        merchantMapper.updateRating(merchant.getId(), newRating);
    }
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. 购物车放 Redis Hash（field=dishId:specId，value=数量），只存数量不存价格，展示时回源 MySQL 取最新价，避免缓存价格过期导致金额错乱
2. 库存扣减用条件更新（UPDATE ... WHERE stock >= n）一条 SQL 完成「检查 + 扣减」，比「先查后扣」快且无竞态；stock=-1 表示不限量
3. 下单事务内只做库内操作（扣库存/建订单/建明细），发 MQ 放事务提交后（TransactionSynchronization.afterCommit），避免「事务回滚了消息却发出去了」
4. 金额一律服务端重算：前端传的金额只做展示，下单/支付时以 DB 菜单价 × 数量为准
5. 订单状态机是硬约束：所有状态变更走 transit()，非法流转直接抛异常，杜绝业务代码到处 UPDATE status
6. 支付回调三重防重：分布式锁（同一订单串行处理）+ 幂等标记（Redis SETNX）+ 状态条件更新（只有待支付能变已支付），回调重复/乱序都不怕
7. 超时关单「延迟队列 + 定时任务」双保险，且关单本身幂等（条件更新），消息丢了有兜底，重复执行无副作用
8. 订单明细必须快照（菜品名/规格/单价），商家之后改价改名不影响历史订单对账

### 踩坑记录

```text
坑 1：超卖
结论：库存 50 份的菜品卖出 60 单。
原因：下单时先查库存再扣减，两个并发请求同时读到库存 50 都通过检查。
解法：改成条件更新 UPDATE ... SET stock=stock-n WHERE stock>=n，影响行数为 0 即库存不足；热点菜品可加 Redis 预扣做前置拦截。

坑 2：购物车并发加减数量丢失
结论：用户快速点加购，数量显示比实际少。
原因：先 GET 再 SET 的非原子读写，两个请求互相覆盖。
解法：HINCRBY 原子自增，减购后数量 <= 0 时再删 field。

坑 3：事务回滚了，商家却收到新订单通知
结论：订单创建失败（库存不足），商家端还是弹了新订单。
原因：MQ 发送写在事务方法内，事务回滚前消息已经发出去。
解法：消息发送移到 TransactionSynchronization.afterCommit()，事务提交成功才发；或改用本地消息表 + 定时投递。

坑 4：支付回调重复入账
结论：一笔订单扣了两次钱。
原因：支付平台回调重试 + 用户重复点击，没有幂等处理。
解法：分布式锁 + Redis SETNX 幂等标记 + 状态条件更新（只有待支付能变已支付）三层防重。

坑 5：订单状态乱跳
结论：待支付订单被商家直接改成配送中，用户投诉。
原因：业务代码各自 UPDATE status，没有统一状态机约束。
解法：所有状态变更收敛到状态机 transit()，流转表校验非法路径，条件更新防并发覆盖。

坑 6：超时关单和支付竞态
结论：用户刚支付成功，订单却被自动取消，库存也回补了。
原因：延迟队列关单与支付回调并发，关单先执行时订单还是待支付。
解法：关单用条件更新（只有待支付能变已取消），影响行数为 0 说明已支付，跳过；支付回调同理，两边互斥由状态条件保证。

坑 7：商家改价后历史订单金额对不上
结论：对账时发现老订单金额和当前菜单价不一致。
原因：订单明细存的是菜品 ID 引用，查询时联表取当前价格。
解法：订单明细把菜品名/规格名/单价/小计全部快照落库，历史订单永远显示下单时价格。

坑 8：延迟消息丢失导致订单永远待支付
结论：MQ 故障期间下单的订单一直挂起，库存被锁死。
原因：只依赖延迟队列关单，消息丢失没有兜底。
解法：加定时任务每 2 分钟扫描超时待支付订单兜底关单，与延迟队列互备。
```

## 项目背景

数据平台（Data Platform）是企业把「散落在各业务系统的数据」汇聚、清洗、存储、分析、展示的一站式系统。业务系统产生数据（订单、日志、用户行为），数据平台负责把它们采集进来、加工成可用的指标，最终通过大屏、报表、接口的形式反哺业务决策。它的价值在于：让数据从「躺在数据库里没人看」变成「实时可监控、可分析、可决策」的资产。这个项目串起了 Kafka（数据管道）、ES（搜索与分析）、Redis（实时统计）、大屏（可视化）四条主流数据技术线，是数据工程方向的核心实战。

业务痛点：

```text
1. 数据分散：订单在 MySQL、日志在文件、行为在第三方，无法统一分析
2. 查询卡顿：业务表数据量大后，多条件组合查询（时间+渠道+状态）秒级超时
3. 没有实时性：报表 T+1 生成，运营看不到当天实时销售情况
4. 分析靠人肉：运营导出 Excel 手工汇总，费时且易错
5. 指标口径不一：不同部门对「成交额」的定义不同，数据对不上
6. 展示能力弱：领导要看大屏，没有可视化能力只能给表格
7. 数据没有沉淀：历史数据不归档、不加工，分析价值白白流失
```

目标用户与核心诉求：

```text
1. 运营人员：实时看销售/流量大盘，按渠道、地区、商品多维分析
2. 管理层：大屏总览核心指标，快速掌握经营状况
3. 数据分析师：通过统一数据平台取数，不再依赖各业务库
4. 研发团队：日志与异常数据汇聚，辅助排障与监控
```

项目要解决的核心问题一句话概括：建立「采集 → 存储 → 分析 → 展示」的数据管道，让业务数据实时汇聚、秒级查询、可视化呈现，支撑经营决策。

## 功能介绍

功能按数据流转阶段拆分：数据采集、数据存储、数据分析、可视化展示、平台管理。

```text
一、数据采集层
1. 业务数据采集 —— 订单/用户行为通过 Kafka 上报（埋点 SDK / 业务异步发送）
2. 日志采集 —— 应用日志接入（Filebeat/Logstash → Kafka）
3. 采集监控 —— 采集量、延迟、失败率大盘

二、数据存储层
1. 明细存储 —— 原始明细入 ES（按天索引），支撑全文检索与聚合
2. 汇总存储 —— 聚合结果入 MySQL（指标宽表）与 Redis（实时计数）
3. 冷热分层 —— 近 7 天热数据在 ES 热节点，历史数据归档

三、数据分析层
1. 实时统计 —— Redis 计数（今日 PV/UV、实时成交额）
2. 多维聚合 —— ES 按时间/渠道/地区/商品聚合（销售榜、渠道占比）
3. 全文检索 —— 订单号、用户名、商品名模糊搜索
4. 指标口径 —— 统一指标定义（成交额=已支付订单金额合计）

四、可视化展示层
1. 实时大屏 —— 核心指标大盘（销售、流量、转化）自动刷新
2. 趋势报表 —— 按小时/天/周维度的趋势图
3. 排行分析 —— TOP 商品、TOP 渠道、TOP 地区
4. 多维筛选 —— 时间范围、渠道、地区下钻

五、平台管理层
1. 数据源管理 —— 配置各业务系统数据源
2. 指标管理 —— 指标定义、口径说明
3. 权限控制 —— 大屏/报表查看权限（按角色）
4. 任务监控 —— 采集任务运行状态、异常告警
```

## 技术选型

| 组件 | 选型 | 理由 |
|------|------|------|
| 开发框架 | Spring Boot 2.7/3.x | 快速构建采集、查询、展示服务 |
| 消息管道 | Kafka 3.x | 高吞吐、可重放，数据管道的事实标准 |
| 搜索引擎 | Elasticsearch 8.x | 全文检索 + 聚合分析，明细数据存储与秒级查询 |
| 实时计数 | Redis | PV/UV、实时成交额等高频计数 |
| 关系库 | MySQL 8.0 | 指标宽表、配置表、用户权限 |
| 可视化 | ECharts（前端大屏） | 大屏图表渲染，社区成熟 |
| 采集器 | Filebeat + Logstash（可选） | 日志采集与预处理 |
| 构建 | Maven + Docker Compose | 快速部署整套环境 |

选型说明：

```text
1. Kafka 做数据总线而非直连：各业务系统只向 Kafka 发消息，数据平台消费，解耦且天然削峰
2. ES 存明细而非 MySQL：明细数据量大（亿级），ES 分片并行查询 + 聚合快，且支持全文检索
3. Redis 只做实时计数：实时指标（今日 PV、实时成交额）高频读写，Redis INCR 原子且快
4. MySQL 存聚合结果与元数据：指标宽表、大屏配置、用户权限，低频读写落 MySQL
5. 大屏用 ECharts：前端从聚合接口拿数据渲染，接口由 ES 聚合 + Redis 实时值组装
```

实时数据链路（订单产生 → 大屏看到）：

```text
1. 订单系统支付成功后，异步发送消息到 Kafka topic: order-topic
2. 明细消费者消费消息：清洗（补全字段/去重）→ 写入 ES 当天索引
3. 汇总消费者消费同一条消息：MySQL 指标宽表当日成交额 +1，Redis 实时成交额 INCR
4. 大屏前端每 5 秒轮询聚合接口
5. 聚合接口组装：实时值读 Redis（今日成交额/PV），维度数据走 ES 聚合（渠道占比/TOP 榜）
6. 大屏刷新：从支付成功到出现在大屏上，端到端延迟约 2-5 秒
```

检索链路（运营查「张三的订单」）：

```text
1. 运营在大屏/报表页输入关键词「张三」
2. 查询接口构造 ES multi_match（订单号/用户名/商品名多字段）
3. ES 按相关度返回命中明细（分页）
4. 接口包装为报表 JSON，前端表格展示
5. 高亮命中词，支持按时间/渠道二次过滤
```

## 核心实现

### 1. 数据采集：业务系统异步上报 Kafka

```java
// 业务系统侧（订单服务）发送消息 —— 支付成功后异步上报
@Service
public class OrderDataReporter {

    @Autowired
    private KafkaTemplate<String, String> kafkaTemplate;
    @Autowired
    private ObjectMapper objectMapper;

    /**
     * 订单支付成功后调用：组装数据消息发到 Kafka
     * 失败不阻塞主流程（记日志 + 定时补偿）
     */
    public void reportPaidOrder(Order order) {
        try {
            Map<String, Object> data = new HashMap<>();
            data.put("orderNo", order.getOrderNo());
            data.put("userName", order.getUserName());
            data.put("goodsName", order.getGoodsName());
            data.put("amount", order.getAmount());
            data.put("channel", order.getChannel());
            data.put("region", order.getRegion());
            data.put("payTime", System.currentTimeMillis());
            kafkaTemplate.send("order-topic", order.getOrderNo(),
                    objectMapper.writeValueAsString(data));
        } catch (Exception e) {
            // 上报失败不影响交易主流程：落本地补偿表，定时重发
            log.error("订单数据上报失败: {}", order.getOrderNo(), e);
            compensationMapper.insert(new CompensationRecord(order.getOrderNo(), "order"));
        }
    }
}
```

### 2. 明细消费者：Kafka → ES（清洗 + 写入）

```java
@Service
public class OrderDetailConsumer {

    @Autowired
    private RestHighLevelClient esClient;
    @Autowired
    private ObjectMapper objectMapper;

    /**
     * 消费订单明细消息，写入 ES 当天索引
     * 幂等：按 order_no 先查后写（或 ES 使用 order_no 作为文档 id）
     */
    @KafkaListener(topics = "order-topic", groupId = "data-platform-detail")
    public void consume(String message) {
        try {
            Map<String, Object> data = objectMapper.readValue(message,
                    new TypeReference<Map<String, Object>>() {});
            String indexName = "order_detail_" +
                    LocalDate.now().format(DateTimeFormatter.BASIC_ISO_DATE);

            // 用 order_no 作文档 id：同一条订单重复消费时覆盖写，天然幂等
            IndexRequest request = new IndexRequest(indexName)
                    .id(String.valueOf(data.get("orderNo")))
                    .source(data, XContentType.JSON);
            esClient.index(request, RequestOptions.DEFAULT);
        } catch (Exception e) {
            // 消费失败：记录偏移、进死信 topic，人工/自动重放
            log.error("明细写入 ES 失败: {}", message, e);
        }
    }
}
```

### 3. 汇总消费者：Kafka → MySQL 宽表 + Redis 实时计数

```java
@Service
public class OrderSummaryConsumer {

    @Autowired
    private DailyMetricMapper metricMapper;
    @Autowired
    private StringRedisTemplate redisTemplate;
    @Autowired
    private ObjectMapper objectMapper;

    /**
     * 消费同一条订单消息做汇总：
     * 1. Redis 实时计数（大屏秒级可见）
     * 2. MySQL 宽表累加（报表 T+0 查询）
     */
    @KafkaListener(topics = "order-topic", groupId = "data-platform-summary")
    public void consume(String message) {
        try {
            Map<String, Object> data = objectMapper.readValue(message,
                    new TypeReference<Map<String, Object>>() {});
            double amount = Double.parseDouble(String.valueOf(data.get("amount")));
            String channel = String.valueOf(data.get("channel"));
            String region = String.valueOf(data.get("region"));
            String today = LocalDate.now().toString();

            // 1. Redis 实时计数（大屏读）
            redisTemplate.opsForValue().increment("stat:today:order");
            redisTemplate.opsForValue().increment("stat:today:gmv", (long) (amount * 100));

            // 2. MySQL 宽表累加（报表读）—— 按 日期+渠道+地区 维度
            int rows = metricMapper.incrByDateChannelRegion(
                    today, channel, region, 1, amount);
            if (rows == 0) {
                // 宽表行不存在则插入（upsert 语义）
                metricMapper.insertIfAbsent(today, channel, region, 1, amount);
            }
        } catch (Exception e) {
            log.error("汇总消费失败: {}", message, e);
        }
    }
}
```

### 4. 大屏聚合接口（Redis 实时值 + ES 维度聚合）

```java
@RestController
@RequestMapping("/api/dashboard")
public class DashboardController {

    @Autowired
    private DashboardService dashboardService;

    /** 大屏数据：实时值 + 维度聚合，5 秒轮询 */
    @GetMapping("/overview")
    public Result<DashboardVO> overview() {
        return Result.success(dashboardService.getOverview());
    }
}

@Service
public class DashboardService {

    @Autowired
    private StringRedisTemplate redisTemplate;
    @Autowired
    private RestHighLevelClient esClient;

    /**
     * 组装大屏数据
     * 实时值：Redis 直接读
     * 维度数据：ES 聚合（渠道占比、TOP 商品、地区分布）
     */
    public DashboardVO getOverview() {
        DashboardVO vo = new DashboardVO();

        // 1. 实时值（Redis）
        vo.setTodayGmv(getLong("stat:today:gmv") / 100.0);
        vo.setTodayOrders(getLong("stat:today:order"));
        vo.setTodayPv(getLong("stat:today:pv"));
        vo.setTodayUv(pfCount("stat:today:uv"));

        // 2. 渠道占比（ES terms 聚合）
        vo.setChannelRatio(esAgg("channel", 10));

        // 3. TOP 商品（ES terms 聚合按 amount sum 排序）
        vo.setTopGoods(esTopGoods(10));

        // 4. 近 24 小时趋势（ES date_histogram 聚合）
        vo.setHourlyTrend(esHourlyTrend());
        return vo;
    }

    /** ES 渠道聚合：按 channel 分组统计订单数与成交额 */
    private List<Map<String, Object>> esAgg(String field, int size) {
        SearchSourceBuilder source = new SearchSourceBuilder()
                .query(QueryBuilders.rangeQuery("payTime")
                        .gte("now-24h").lte("now"))
                .size(0)
                .aggregation(AggregationBuilders.terms("by_" + field)
                        .field(field).size(size)
                        .subAggregation(AggregationBuilders.sum("total_amount")
                                .field("amount")));
        SearchRequest request = new SearchRequest(
                "order_detail_*").source(source);
        try {
            SearchResponse resp = esClient.search(request, RequestOptions.DEFAULT);
            Terms agg = resp.getAggregations().get("by_" + field);
            List<Map<String, Object>> result = new ArrayList<>();
            for (Terms.Bucket bucket : agg.getBuckets()) {
                Map<String, Object> item = new HashMap<>();
                item.put("name", bucket.getKeyAsString());
                item.put("count", bucket.getDocCount());
                Sum sum = bucket.getAggregations().get("total_amount");
                item.put("amount", sum.getValue());
                result.add(item);
            }
            return result;
        } catch (IOException e) {
            throw new RuntimeException("ES 聚合失败", e);
        }
    }
}
```

### 5. 实时 UV 统计（HyperLogLog）

```java
@Service
public class UvStatService {

    @Autowired
    private StringRedisTemplate redisTemplate;

    /**
     * 每次访问调用：把 userId 加入 HyperLogLog
     * 内存极小（12KB 可统计 2^64 去重），误差约 0.81%
     */
    public void addUv(Long userId) {
        String key = "stat:today:uv";
        redisTemplate.opsForHyperLogLog().add(key, String.valueOf(userId));
        redisTemplate.expire(key, 24, TimeUnit.HOURS);
    }

    /** 大屏读 UV：PFCOUNT 去重计数 */
    public long countUv() {
        Long count = redisTemplate.opsForHyperLogLog().size("stat:today:uv");
        return count == null ? 0 : count;
    }
}
```

### 6. 历史明细检索（运营查询订单）

```java
    /** 全文检索：关键词 + 时间范围 + 分页 */
    @GetMapping("/orders")
    public Result<PageResult<OrderHitVO>> search(
            @RequestParam String keyword,
            @RequestParam(required = false) String startTime,
            @RequestParam(required = false) String endTime,
            @RequestParam(defaultValue = "1") int page,
            @RequestParam(defaultValue = "20") int size) {
        return Result.success(searchService.searchOrders(
                keyword, startTime, endTime, page, size));
    }
}

@Service
public class OrderSearchService {

    @Autowired
    private RestHighLevelClient esClient;

    public PageResult<OrderHitVO> searchOrders(String keyword,
            String startTime, String endTime, int page, int size) {
        SearchSourceBuilder source = new SearchSourceBuilder();
        // 多字段全文检索（订单号/用户名/商品名）
        BoolQueryBuilder bool = QueryBuilders.boolQuery()
                .must(QueryBuilders.multiMatchQuery(keyword)
                        .field("order_no", 3.0f)
                        .field("user_name", 2.0f)
                        .field("goods_name"));
        // 时间范围过滤
        if (startTime != null && endTime != null) {
            bool.filter(QueryBuilders.rangeQuery("payTime")
                    .gte(startTime).lte(endTime));
        }
        source.query(bool);
        source.from((page - 1) * size).size(size);

        SearchRequest request = new SearchRequest("order_detail_*").source(source);
        try {
            SearchResponse resp = esClient.search(request, RequestOptions.DEFAULT);
            List<OrderHitVO> list = new ArrayList<>();
            for (SearchHit hit : resp.getHits().getHits()) {
                Map<String, Object> f = hit.getSourceAsMap();
                OrderHitVO vo = new OrderHitVO();
                vo.setOrderNo(String.valueOf(f.get("orderNo")));
                vo.setUserName(String.valueOf(f.get("userName")));
                vo.setGoodsName(String.valueOf(f.get("goodsName")));
                vo.setAmount(Double.parseDouble(String.valueOf(f.get("amount"))));
                list.add(vo);
            }
            return new PageResult<>(list, resp.getHits().getTotalHits().value, page, size);
        } catch (IOException e) {
            throw new RuntimeException("检索失败", e);
        }
    }
}
```

## 实际应用场景

### 场景一：电商公司经营大屏

电商公司搭建管理层经营大屏，实时展示全渠道销售情况：

```text
1. 各业务系统（商城 App/小程序/线下 POS）支付成功后异步上报 Kafka
2. 明细消费者把订单写入 ES 当天索引，汇总消费者累加 MySQL 宽表与 Redis
3. 管理层大屏每 5 秒刷新：今日成交额（Redis）、订单数、PV/UV（HyperLogLog）
4. 渠道占比环形图、TOP 商品榜、地区分布（ES terms 聚合）
5. 近 24 小时趋势曲线（ES date_histogram）
6. 大促期间实时监控成交额曲线，异常波动立刻定位渠道
7. 数据从支付成功到上屏延迟 2-5 秒，运营实时掌握经营状况
```

### 场景二：客服订单检索

客服接到用户咨询「我上周买的那个红色保温杯到哪了」，需要快速定位订单：

```text
1. 客服在检索页输入关键词（用户名/订单号/商品名）
2. ES 多字段全文检索 + 时间范围过滤，秒级返回
3. 结果展示订单号、商品、金额、支付时间
4. 客服根据订单号进订单系统查物流
5. 相比之前翻 MySQL 慢查询，检索效率提升百倍
```

### 场景三：埋点行为分析

产品团队要分析新版首页的点击行为：

```text
1. 前端埋点 SDK 把行为事件（点击/曝光/停留）发送到 Kafka behavior-topic
2. 明细消费者写入 ES behavior 索引（事件名/页面/时间/用户）
3. 产品通过分析页按事件名聚合：各模块点击量、漏斗转化
4. 实时 PV/UV 看大盘，活动上线后即时评估效果
5. 行为数据沉淀，后续支撑个性化推荐
```

## 最佳实践与踩坑记录

### 最佳实践

1. 数据管道分层解耦：业务系统只发 Kafka，数据平台只消费，互不感知，任何一方变更不影响对方
2. 明细与汇总分开消费：明细消费者写 ES（支撑检索），汇总消费者算指标（支撑报表），独立 group 互不阻塞
3. 幂等用「业务键做文档 id」：ES 用 order_no 做文档 id，重复消费覆盖写，天然幂等
4. 实时与离线分离：实时指标走 Redis（秒级），报表宽表走 MySQL（准实时），各有分工
5. ES 按天建索引：方便清理过期数据（删除旧索引比 delete_by_query 快几个量级）
6. 指标口径必须落库：metric_def 表统一口径定义，避免各部门对指标理解不一致
7. 大屏接口要快：实时值走 Redis（毫秒），维度聚合走 ES（百毫秒内），别让大屏轮询拖垮查询服务

### 踩坑记录

```text
坑 1：Kafka 消息重复导致指标翻倍
结论：同一订单被统计两次，GMV 虚高。
原因：消费者重平衡/重试导致消息重复消费。
解法：消费端幂等——汇总用「先查后插 + 唯一键」，明细用 order_no 做文档 id 覆盖写。

坑 2：ES 索引无脑增长
结论：磁盘被 ES 数据占满。
原因：每天一个索引但从不清理，历史索引无限堆积。
解法：按天建索引 + 定时任务删除 30 天前索引，或 ILM 策略自动 rollover 与删除。

坑 3：大屏数据与报表对不上
结论：大屏显示成交额 100 万，报表只有 90 万。
原因：大屏读 Redis 实时值，报表读 MySQL 宽表，两边累加时点不同。
解法：明确「实时值」与「准实时值」两套口径并标注；对账任务定期用 Kafka 重放校准。

坑 4：ES 聚合查询慢
结论：渠道占比接口 3 秒才返回。
原因：聚合查询扫了全部历史索引（order_detail_* 匹配所有天）。
解法：聚合查询限定最近 24 小时/7 天索引范围，或用别名指向热索引。

坑 5：埋点数据丢失
结论：行为分析发现某时段数据缺失。
原因：前端埋点失败静默丢弃，没有补偿。
解法：埋点本地缓存 + 批量上报 + 失败重试；服务端对关键事件做抽样对账。

坑 6：Redis 实时值重启丢失
结论：Redis 重启后大屏实时值归零。
原因：实时指标只存在 Redis 内存，没落盘。
解法：Redis 开启 AOF 持久化；或定期把实时值快照到 MySQL realtime_metric 表，重启后回填。

坑 7：大屏轮询打爆查询服务
结论：多个大屏同时 5 秒轮询，查询服务 CPU 飙升。
原因：每个大屏独立请求聚合，没有复用。
解法：聚合结果加短 TTL 缓存（如 3 秒），多屏共享；或改 WebSocket 推送替代轮询。
```

## 项目背景

定时任务调度平台（Distributed Task Scheduler）解决企业中「定时跑批、周期同步、任务编排」的集中管理问题。没有调度平台时，各系统用 Spring @Scheduled、Linux crontab 各自为战：任务散落、无人监控、挂了没人知道、重复执行产生脏数据、重试全靠人肉、执行情况无法追溯。本系统对标 XXL-Job/Quartz 的产品形态自研：任务管理控制台（创建/编辑/启停）、多种触发规则（cron/固定间隔/一次性）、三类执行器（HTTP/Java Bean/Shell）、分布式调度（多节点抢锁执行防重复）、失败重试（次数/间隔）、全链路执行日志（执行 ID 贯穿）、告警通知（钉钉/邮件）、任务依赖（DAG 拓扑编排）。

业务痛点：

```text
1. 任务散落：@Scheduled 写在各个服务里，crontab 撒在每台机器上，无人知道全量清单
2. 重复执行：多节点部署后 @Scheduled 每台都跑一遍，数据重复、接口被重复调用
3. 失败无感知：任务半夜挂了，第二天才发现，数据缺口已无法补救
4. 重试靠人肉：失败后手动补跑，漏补、错补时有发生
5. 无法追溯：谁改过任务、上次跑成功没、耗时多少，完全没有执行历史
6. 编排靠硬编码：A 跑完才能跑 B 的链路写死在代码里，改一次上线一次
```

目标用户与核心诉求：

```text
1. 业务系统开发者：把定时逻辑从代码里挪到调度平台，配置化触发，代码只写执行逻辑
2. 运维/平台管理员：统一管控全公司任务，启停、监控、告警、重试策略集中配置
3. 数据团队：数据同步、指标计算等批处理任务依赖编排（DAG），失败自动告警与重试
4. 业务人员（低频）：通过 HTTP 任务触发报表生成、对账等简单周期操作
```

项目要解决的核心问题一句话概括：把「定时任务」抽象成「任务定义 + 触发规则 + 执行器 + 分布式防重 + 重试告警 + DAG 编排」，让任务从创建到执行到追溯全流程平台化、可监控、不重复。

## 功能介绍

功能按角色与模块拆分：任务管理、触发规则、执行器、分布式调度、失败重试、执行日志、告警通知、任务依赖。

```text
一、任务管理（控制台，运维与开发者使用）
1. 任务创建 —— 任务名称/分组/执行器类型/执行参数/负责人，配置触发规则
2. 任务编辑 —— 修改参数与规则，立即生效（下一触发周期应用）
3. 任务启停 —— 暂停后不再触发（进行中的执行不受影响）；删除任务保留日志
4. 手动执行 —— 控制台一键触发（立即执行一次，带执行 ID，可观测）
5. 任务搜索 —— 按名称/分组/负责人/状态检索，列表展示最近执行结果

二、触发规则（调度核心）
1. cron 表达式 —— 标准 6/7 段 cron，如 0 0 2 * * ?（每天 2 点），支持秒级
2. 固定间隔 —— 每 N 分钟/小时执行一次（从启停时间起算，可指定首次延迟）
3. 一次性 —— 指定时间执行一次（临时跑批），执行完自动结束
4. 触发预览 —— 保存前预览未来 5 次触发时间，校验表达式合法性

三、执行器（任务执行方式）
1. HTTP 执行器 —— 调度平台调用业务系统 REST 接口（POST + JSON 参数），业务系统零改造接入
2. Java Bean 执行器 —— 平台内嵌执行 Spring Bean（按 Bean 名/方法名反射调用），适合平台内置任务
3. Shell 执行器 —— 执行服务器 Shell 脚本/命令（数据备份、日志清理），结果按退出码判定
4. 超时控制 —— 单次执行超时自动终止（默认 5 分钟，可配置）

四、分布式调度（核心能力）
1. 多节点部署 —— 调度平台自身多实例部署，任意节点都可能成为执行节点
2. 抢锁执行 —— 触发时刻各节点抢 Redis 分布式锁，只有持锁节点真正执行（防重复执行）
3. 数据库唯一键兜底 —— 锁异常时用「触发时间 + 任务 id」唯一键二次防重，双保险
4. 任务分片（可选扩展）—— 大数据任务按分片参数并行执行，各分片独立日志

五、失败重试（可靠性保障）
1. 重试策略 —— 配置最大重试次数（0-10）与重试间隔（固定/指数退避）
2. 指数退避 —— 第 N 次重试间隔 = 基础间隔 * 2^(N-1)，避免故障恢复前狂轰
3. 重试链路 —— 每次重试同一执行 ID 下追加子记录，完整保留首次失败与每次重试明细
4. 重试上限 —— 达到最大次数仍未成功，任务置 FAILED 并触发告警

六、执行日志（全链路可观测）
1. 执行 ID —— 每次触发生成全局唯一 executeId，贯穿「触发 → 执行 → 重试 → 日志 → 告警」
2. 日志明细 —— 执行状态（成功/失败/超时）、开始结束时间、耗时毫秒、退出码、输出摘要
3. 日志检索 —— 按任务/时间/状态/执行 ID 检索，历史日志永久保留（可归档）
4. 重试视图 —— 一次执行的所有重试记录时间线展示

七、告警通知（失败感知）
1. 告警规则 —— 执行失败、重试耗尽、任务超时、连续失败 N 次时触发
2. 通知渠道 —— 钉钉群机器人 Webhook、邮件（JavaMail），可多选
3. 告警去重 —— 同一任务 10 分钟内同类告警合并，避免告警轰炸
4. 告警记录 —— 通知内容、渠道、发送时间、是否成功留痕

八、任务依赖（DAG 编排）
1. 依赖配置 —— 任务 A 依赖任务 B（B 成功后才允许 A 触发），支持多依赖
2. 拓扑校验 —— 保存依赖时检测环（A→B→A 拒绝保存），有向无环图约束
3. 条件触发 —— 依赖任务全部成功后，被依赖任务自动触发（上游链路驱动）
4. 依赖失败处理 —— 上游失败则下游不触发并标记 SKIPPED，上游重试成功后自动续跑
```

## 技术选型

| 组件 | 选型 | 理由 |
|------|------|------|
| 开发框架 | Spring Boot 2.7/3.x | 生态成熟，快速搭建 REST 服务 |
| 调度内核 | 自研调度器（Quartz 风格，秒级 cron 解析） | 核心触发逻辑可控，教学演示清晰 |
| 持久层 | MyBatis-Plus | 单表 CRUD 零 SQL，复杂查询走 XML |
| 数据库 | MySQL 8.0 | 任务定义、执行日志、依赖关系持久化 |
| 分布式锁 | Redis（SETNX + 过期） + 数据库唯一键 | 双保险防重复执行 |
| 分布式 ID | 雪花算法（或 MyBatis-Plus 内置 ID） | 全局唯一执行 ID 贯穿日志链路 |
| HTTP 调用 | OkHttp（或 Spring RestTemplate） | HTTP 执行器调用业务系统 |
| Shell 执行 | ProcessBuilder | 平台节点本地执行脚本 |
| 钉钉告警 | 钉钉群机器人 Webhook（HTTP POST） | 失败秒级触达群成员 |
| 邮件告警 | Spring Boot Starter Mail（JavaMail） | 邮件通知兜底 |
| cron 解析 | cron-utils（或 Quartz CronExpression） | 标准 cron 校验与下次触发时间计算 |
| 前端 | Vue 3 + Element Plus | 任务管理控制台、执行日志、DAG 视图 |

选型说明：

```text
1. 调度内核自研：cron 解析用成熟库（Quartz CronExpression），触发扫描用自研循环（每秒扫一次到期任务），把「触发 → 抢锁 → 分发 → 日志」链路完整写出来，比直接套 Quartz 更利于理解分布式调度的本质
2. 防重复执行双保险：Redis 锁保证「同一时刻只有一个节点执行」，数据库唯一键（触发时刻+任务 id）兜底「锁失效/网络抖动」的极端情况
3. 执行 ID 用分布式 ID：雪花算法保证多节点并发触发下 ID 全局唯一，执行日志、重试记录、告警记录全部用 executeId 关联，形成完整链路
4. HTTP 执行器为主：业务系统只需暴露一个 POST 接口即可接入调度，业务代码零侵入；Java Bean 与 Shell 作为平台内置任务补充
5. DAG 依赖用「边表」存储：job_depend 表记录上下游关系，触发前做拓扑校验（环检测）与就绪判定，比硬编码编排灵活得多
```

```text
└──────────────┘   └──────────────┘   └─────────────────┘
```

调度执行完整链路（cron 任务，3 节点部署）：

```text
1. 运维在控制台创建任务：每天 02:00 同步订单数据（HTTP 执行器，地址 http://order-svc/sync）
2. 调度触发器每秒扫描到期任务（nextFireTime <= now 且状态为启用）
3. 节点 A、B、C 同时扫到该任务 → 各自尝试抢 Redis 锁：SETNX job:lock:{jobId}:{fireTime}（TTL 60s）
4. 节点 A 抢锁成功 → 其余节点失败跳过（防重复执行的核心）
5. 节点 A 生成执行 ID（雪花算法）→ 写 job_trigger_record（jobId + fireTime 唯一键，防重第二道）
6. 节点 A 调起执行器：HTTP POST 订单系统 /sync，携带 executeId 与参数
7. 执行成功 → 写 job_log（成功/耗时）→ 检查下游依赖任务 → 就绪则触发其执行
8. 执行失败 → 进入重试流程（第 1 次重试间隔 30s，指数退避 30s/60s/120s...）
9. 重试仍失败 → 任务 FAILED → 触发告警（钉钉群 + 邮件，10 分钟内同类告警合并）
10. 运维在控制台按 executeId 查看完整链路：触发 → 执行 → 重试 → 告警，问题定位分钟级
```

## 数据库设计

核心表设计（7 张表）：

```sql
-- 任务表
CREATE TABLE `job_info` (
  `id`             BIGINT       NOT NULL AUTO_INCREMENT,
  `job_name`       VARCHAR(100) NOT NULL COMMENT '任务名称',
  `job_group`      VARCHAR(64)  NOT NULL DEFAULT 'DEFAULT' COMMENT '任务分组',
  `trigger_type`   VARCHAR(20)  NOT NULL COMMENT '触发类型：CRON/FIXED/ONCE',
  `cron_expr`      VARCHAR(64)  DEFAULT NULL COMMENT 'cron 表达式（CRON 类型）',
  `interval_sec`   INT          DEFAULT NULL COMMENT '固定间隔秒数（FIXED 类型）',
  `fire_time`      DATETIME     DEFAULT NULL COMMENT '一次性触发时间（ONCE 类型）',
  `executor_type`  VARCHAR(20)  NOT NULL COMMENT '执行器类型：HTTP/BEAN/SHELL',
  `executor_param` TEXT         NOT NULL COMMENT '执行参数（HTTP地址/Bean名/Shell脚本，JSON）',
  `timeout_sec`    INT          NOT NULL DEFAULT 300 COMMENT '超时秒数',
  `retry_count`    INT          NOT NULL DEFAULT 0 COMMENT '最大重试次数',
  `retry_interval` INT          NOT NULL DEFAULT 30 COMMENT '基础重试间隔秒（指数退避）',
  `alarm_strategy` VARCHAR(100) DEFAULT NULL COMMENT '告警策略 JSON（钉钉/邮件/触发条件）',
  `status`         TINYINT      NOT NULL DEFAULT 0 COMMENT '状态：0停用 1启用',
  `owner`          VARCHAR(100) DEFAULT NULL COMMENT '负责人',
  `remark`         VARCHAR(300) DEFAULT NULL COMMENT '备注',
  `create_time`    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `update_time`    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  KEY `idx_group` (`job_group`),
  KEY `idx_status` (`status`),
  KEY `idx_next_fire` (`status`, `next_fire_time`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='任务表';

-- 执行日志表（executeId 贯穿全链路）
CREATE TABLE `job_log` (
  `id`            BIGINT       NOT NULL AUTO_INCREMENT,
  `execute_id`    BIGINT       NOT NULL COMMENT '执行 ID（雪花算法，全局唯一）',
  `job_id`        BIGINT       NOT NULL COMMENT '任务 id',
  `trigger_time`  DATETIME     NOT NULL COMMENT '触发时间',
  `fire_time`     DATETIME     NOT NULL COMMENT '本次调度时刻（防重用）',
  `node`          VARCHAR(100) DEFAULT NULL COMMENT '执行节点（抢锁成功的节点 IP）',
  `status`        VARCHAR(20)  NOT NULL COMMENT '状态：RUNNING/SUCCESS/FAILED/TIMEOUT/SKIPPED',
  `retry_times`   INT          NOT NULL DEFAULT 0 COMMENT '第几次重试（0=首次）',
  `start_time`    DATETIME     DEFAULT NULL COMMENT '开始时间',
  `end_time`      DATETIME     DEFAULT NULL COMMENT '结束时间',
  `cost_ms`       BIGINT       DEFAULT NULL COMMENT '耗时毫秒',
  `exit_code`     INT          DEFAULT NULL COMMENT '退出码（0 成功）',
  `output`        TEXT         DEFAULT NULL COMMENT '执行输出摘要',
  `error_msg`     VARCHAR(1000) DEFAULT NULL COMMENT '失败原因',
  `create_time`   DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_execute` (`execute_id`),
  KEY `idx_job` (`job_id`),
  KEY `idx_job_fire` (`job_id`, `fire_time`),
  KEY `idx_status_time` (`status`, `create_time`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='执行日志表';

-- 触发记录表（数据库防重第二道防线）
CREATE TABLE `job_trigger_record` (
  `id`            BIGINT       NOT NULL AUTO_INCREMENT,
  `job_id`        BIGINT       NOT NULL COMMENT '任务 id',
  `fire_time`     DATETIME     NOT NULL COMMENT '调度时刻（秒级精度）',
  `execute_id`    BIGINT       NOT NULL COMMENT '执行 ID',
  `node`          VARCHAR(100) NOT NULL COMMENT '执行节点',
  `create_time`   DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_job_fire` (`job_id`, `fire_time`) COMMENT '同一任务同一秒只能触发一次（防重兜底）',
  KEY `idx_execute` (`execute_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='触发记录表';

-- 任务依赖表（DAG 边表）
CREATE TABLE `job_depend` (
  `id`            BIGINT       NOT NULL AUTO_INCREMENT,
  `job_id`        BIGINT       NOT NULL COMMENT '下游任务（依赖方）',
  `dep_job_id`    BIGINT       NOT NULL COMMENT '上游任务（被依赖方）',
  `create_time`   DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_depend` (`job_id`, `dep_job_id`),
  KEY `idx_dep` (`dep_job_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='任务依赖表（有向边：job_id 依赖 dep_job_id）';

-- 告警记录表
CREATE TABLE `job_alarm` (
  `id`            BIGINT       NOT NULL AUTO_INCREMENT,
  `execute_id`    BIGINT       DEFAULT NULL COMMENT '关联执行 ID',
  `job_id`        BIGINT       NOT NULL COMMENT '任务 id',
  `alarm_type`    VARCHAR(30)  NOT NULL COMMENT '类型：FAILED/TIMEOUT/RETRY_EXHAUSTED/CONSECUTIVE_FAIL',
  `channel`       VARCHAR(20)  NOT NULL COMMENT '渠道：DINGTALK/EMAIL',
  `content`       TEXT         NOT NULL COMMENT '通知内容',
  `send_result`   TINYINT      NOT NULL COMMENT '发送结果：0失败 1成功',
  `send_time`     DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  KEY `idx_job_time` (`job_id`, `send_time`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='告警记录表';

-- 执行器表（执行器分组与注册信息，HTTP 执行器接入方登记）
CREATE TABLE `executor_group` (
  `id`            BIGINT       NOT NULL AUTO_INCREMENT,
  `group_name`    VARCHAR(100) NOT NULL COMMENT '执行器组名（如 order-svc）',
  `executor_type` VARCHAR(20)  NOT NULL COMMENT '执行器类型',
  `address`       VARCHAR(500) DEFAULT NULL COMMENT 'HTTP 地址 / Bean 名 / 节点标签',
  `status`        TINYINT      NOT NULL DEFAULT 1 COMMENT '状态：0停用 1启用',
  `create_time`   DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_name` (`group_name`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='执行器表';
```

Redis Key 设计：

```text
job:lock:{jobId}:{fireTime}      分布式执行锁（SETNX + TTL 60s，抢锁成功者执行）
job:next:{jobId}                 下次触发时间缓存（调度器扫描加速，可省）
job:alarm:dedup:{jobId}:{type}   告警去重标记（TTL 600s，10 分钟同类告警合并）
job:consecutive:fail:{jobId}     连续失败计数（INCR，告警策略用）
```

```java
        if (job == null) {
            throw new BizException("任务不存在");
        }
        job.setStatus(enable ? 1 : 0);
        jobInfoMapper.updateById(job);
    }

    public Long manualTrigger(Long jobId) {
        JobInfo job = jobInfoMapper.selectById(jobId);
        if (job == null) {
            throw new BizException("任务不存在");
        }
        // 复用调度器的触发入口（见 TriggerService.triggerOnce）
        return triggerService.triggerOnce(job, new Date());
    }

    /**
     * 触发规则校验：
     * CRON -> 表达式合法且未来 5 次触发时间可计算
     * FIXED -> 间隔必须 > 0
     * ONCE  -> 时间必须晚于当前
     */
    private void validateTrigger(JobInfo job) {
        switch (job.getTriggerType()) {
            case "CRON":
                try {
                    CronExpression cron = new CronExpression(job.getCronExpr());
                    Date next = cron.getNextValidTimeAfter(new Date());
                    if (next == null) {
                        throw new BizException("cron 表达式在可预见的未来没有触发时间");
                    }
                } catch (ParseException e) {
                    throw new BizException("cron 表达式非法: " + job.getCronExpr());
                }
                break;
            case "FIXED":
                if (job.getIntervalSec() == null || job.getIntervalSec() <= 0) {
                    throw new BizException("固定间隔必须大于 0");
                }
                break;
            case "ONCE":
                if (job.getFireTime() == null || !job.getFireTime().after(new Date())) {
                    throw new BizException("一次性任务的触发时间必须晚于当前时间");
                }
                break;
            default:
                throw new BizException("不支持的触发类型: " + job.getTriggerType());
        }
    }

    // 循环依赖处理：triggerService 由 Spring 注入（setter 注入规避循环依赖）
    private com.demo.scheduler.trigger.TriggerService triggerService;
    @Autowired
    public void setTriggerService(com.demo.scheduler.trigger.TriggerService triggerService) {
        this.triggerService = triggerService;
    }
```

### 2. 调度触发器：到期扫描与触发分发

```java
package com.demo.scheduler.trigger;

import com.demo.scheduler.distribute.DistributedLockService;
import com.demo.scheduler.entity.JobInfo;
import com.demo.scheduler.job.JobDependService;
import com.demo.scheduler.mapper.JobInfoMapper;
import org.quartz.CronExpression;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.scheduling.annotation.Scheduled;
import org.springframework.stereotype.Service;

import java.text.SimpleDateFormat;
import java.util.Date;
import java.util.List;

/**
 * 调度触发器（自研调度内核，Quartz 风格）
 * 每秒扫描一次「启用且到期」的任务，逐个尝试抢锁，抢锁成功才真正执行
 * 多节点部署时每个节点都在跑这个扫描，靠分布式锁保证只有一个节点执行
 */
@Service
public class TriggerService {

    private static final Logger log = LoggerFactory.getLogger(TriggerService.class);

    @Autowired
    private JobInfoMapper jobInfoMapper;
    @Autowired
    private DistributedLockService lockService;
    @Autowired
    private com.demo.scheduler.execute.JobExecuteService executeService;
    @Autowired
    private JobDependService dependService;

    /** 每秒扫描一次到期任务（平台内置调度线程） */
    @Scheduled(fixedDelay = 1000)
    public void scan() {
        List<JobInfo> jobs = jobInfoMapper.selectEnabled();
        Date now = new Date();
        for (JobInfo job : jobs) {
            Date next = computeNextFireTime(job, now);
            if (next != null && !next.after(now)) {
                // 到期：尝试触发（内部抢锁 + 防重）
                fire(job, next);
            }
        }
    }

    /**
     * 触发一次任务
     * @param fireTime 本次调度时刻（秒级精度，防重的关键维度）
     */
    public void fire(JobInfo job, Date fireTime) {
        // 1. 依赖校验：存在未成功的上游依赖则不触发（DAG 编排）
        if (!dependService.isReady(job.getId())) {
            log.info("任务 {} 的上游依赖未就绪，跳过本次触发", job.getId());
            return;
        }
        // 2. 分布式抢锁：只有抢到锁的节点继续
        boolean locked = lockService.tryLock("job:lock:" + job.getId() + ":"
                + new SimpleDateFormat("yyyyMMddHHmmss").format(fireTime));
        if (!locked) {
            return; // 其他节点已执行，本节点静默跳过
        }
        // 3. 数据库唯一键二次防重（锁失效的极端兜底）
        if (!lockService.tryInsertTriggerRecord(job.getId(), fireTime)) {
            return;
        }
        // 4. 生成执行 ID 并分发执行（异步执行，不阻塞扫描线程）
        executeService.executeAsync(job, fireTime);
    }

    /** 手动触发入口：fireTime 取当前时刻 */
    public Long triggerOnce(JobInfo job, Date now) {
        fire(job, now);
        return now.getTime();
    }

    /** 计算下次触发时间（cron/固定间隔/一次性 三种规则统一出口） */
    public Date computeNextFireTime(JobInfo job, Date now) {
        try {
            switch (job.getTriggerType()) {
                case "CRON":
                    CronExpression cron = new CronExpression(job.getCronExpr());
                    return cron.getNextValidTimeAfter(now);
                case "FIXED":
                    // 简化：以上次执行时间为基准 + 间隔；真实实现维护 lastFireTime 列
                    Date last = job.getLastFireTime();
                    if (last == null) return now;
                    return new Date(last.getTime() + job.getIntervalSec() * 1000L);
                case "ONCE":
                    return job.getFireTime();
                default:
                    return null;
            }
        } catch (Exception e) {
            log.error("计算下次触发时间失败 jobId={}", job.getId(), e);
            return null;
        }
    }
}
```

### 3. 分布式锁服务：Redis 锁 + 数据库唯一键防重

```java
package com.demo.scheduler.distribute;

import com.demo.scheduler.entity.JobTriggerRecord;
import com.demo.scheduler.mapper.JobTriggerRecordMapper;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.dao.DuplicateKeyException;
import org.springframework.data.redis.core.StringRedisTemplate;
import org.springframework.stereotype.Service;

import java.text.SimpleDateFormat;
import java.util.Date;
import java.util.UUID;
import java.util.concurrent.TimeUnit;

/**
 * 分布式锁服务：防重复执行双保险
 * 第一道：Redis SETNX 锁（带随机 value，释放时校验归属，防误删他人锁）
 * 第二道：数据库唯一键（job_id + fire_time），锁失效的极端场景兜底
 */
@Service
public class DistributedLockService {

    @Autowired
    private StringRedisTemplate redisTemplate;
    @Autowired
    private JobTriggerRecordMapper triggerRecordMapper;

    /**
     * 抢分布式锁：SETNX 成功才算抢到
     * value 用随机串标识持锁者，释放时比对，防止「锁过期后被别人持有，自己 DEL 误删」
     */
    public boolean tryLock(String lockKey) {
        String owner = UUID.randomUUID().toString();
        Boolean ok = redisTemplate.opsForValue()
                .setIfAbsent(lockKey, owner, 60, TimeUnit.SECONDS);
        if (Boolean.TRUE.equals(ok)) {
            // 持锁者信息记录在线程本地，释放时校验（简化：直接返回 true，释放逻辑见 unlock）
            ThreadLocalHolder.set(lockKey, owner);
            return true;
        }
        return false;
    }

    /** 释放锁：校验 value 归属后 DEL（防误删） */
    public void unlock(String lockKey) {
        String owner = ThreadLocalHolder.get(lockKey);
        if (owner == null) {
            return;
        }
        String current = redisTemplate.opsForValue().get(lockKey);
        if (owner.equals(current)) {
            redisTemplate.delete(lockKey);
        }
        ThreadLocalHolder.remove(lockKey);
    }

    /**
     * 数据库唯一键防重：job_id + fire_time 唯一索引
     * @return true=插入成功（本次触发有效）；false=已存在（重复触发，丢弃）
     */
    public boolean tryInsertTriggerRecord(Long jobId, Date fireTime) {
        JobTriggerRecord record = new JobTriggerRecord();
        record.setJobId(jobId);
        record.setFireTime(fireTime);
        record.setExecuteId(com.demo.scheduler.util.SnowflakeId.nextId());
        record.setNode(LocalNode.ip());
        try {
            triggerRecordMapper.insert(record);
            return true;
        } catch (DuplicateKeyException e) {
            return false; // 唯一键冲突：同一调度时刻已触发过
        }
    }

    /** 线程本地持锁记录（简化实现） */
    private static class ThreadLocalHolder {
        private static final ThreadLocal<java.util.Map<String, String>> HOLDER =
                ThreadLocal.withInitial(java.util.HashMap::new);
        static void set(String key, String owner) { HOLDER.get().put(key, owner); }
        static String get(String key) { return HOLDER.get().get(key); }
        static void remove(String key) { HOLDER.get().remove(key); }
    }
}
```

### 4. 执行服务：执行器分发与执行日志链路

```java
package com.demo.scheduler.execute;

import com.demo.scheduler.distribute.DistributedLockService;
import com.demo.scheduler.entity.JobInfo;
import com.demo.scheduler.entity.JobLog;
import com.demo.scheduler.mapper.JobLogMapper;
import com.demo.scheduler.util.SnowflakeId;
import okhttp3.*;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.scheduling.annotation.Async;
import org.springframework.stereotype.Service;

import java.io.BufferedReader;
import java.io.InputStreamReader;
import java.util.Date;
import java.util.concurrent.TimeUnit;

/**
 * 执行服务：三类执行器分发（HTTP / Java Bean / Shell）+ 执行日志链路
 * executeId 贯穿「触发记录 → 执行日志 → 重试记录 → 告警记录」，一次执行一条完整链路
 */
@Service
public class JobExecuteService {

    private static final Logger log = LoggerFactory.getLogger(JobExecuteService.class);

    @Autowired
    private JobLogMapper jobLogMapper;
    @Autowired
    private DistributedLockService lockService;
    @Autowired
    private com.demo.scheduler.retry.JobRetryService retryService;
    @Autowired
    private com.demo.scheduler.job.JobDependService dependService;
    @Autowired
    private com.demo.scheduler.alarm.AlarmService alarmService;

    private final OkHttpClient httpClient = new OkHttpClient.Builder()
            .connectTimeout(10, TimeUnit.SECONDS)
            .readTimeout(60, TimeUnit.SECONDS)
            .build();

    /**
     * 异步执行任务（扫描线程调用后立即返回）
     * @param fireTime 调度时刻（用于解锁与防重）
     */
    @Async
    public void executeAsync(JobInfo job, Date fireTime) {
        String lockKey = "job:lock:" + job.getId() + ":"
                + new java.text.SimpleDateFormat("yyyyMMddHHmmss").format(fireTime);
        // 1. 生成执行 ID（雪花算法，全局唯一，贯穿链路）
        Long executeId = SnowflakeId.nextId();
        // 2. 写 RUNNING 日志
        JobLog logEntry = new JobLog();
        logEntry.setExecuteId(executeId);
        logEntry.setJobId(job.getId());
        logEntry.setTriggerTime(new Date());
        logEntry.setFireTime(fireTime);
        logEntry.setNode(LocalNode.ip());
        logEntry.setStatus("RUNNING");
        logEntry.setRetryTimes(0);
        jobLogMapper.insert(logEntry);

        try {
            // 3. 按执行器类型分发
            ExecuteResult result;
            switch (job.getExecutorType()) {
                case "HTTP":  result = executeHttp(job); break;
                case "BEAN":  result = executeBean(job); break;
                case "SHELL": result = executeShell(job); break;
                default:      result = ExecuteResult.fail("未知执行器类型: " + job.getExecutorType());
            }
            // 4. 更新日志（成功/失败 + 耗时）
            logEntry.setStatus(result.isSuccess() ? "SUCCESS" : "FAILED");
            logEntry.setEndTime(new Date());
            logEntry.setCostMs(result.getCostMs());
            logEntry.setExitCode(result.isSuccess() ? 0 : 1);
            logEntry.setOutput(result.getOutput());
            logEntry.setErrorMsg(result.getErrorMsg());
            jobLogMapper.updateById(logEntry);

            if (result.isSuccess()) {
                // 5. 成功后驱动下游依赖任务（DAG 续跑）
                dependService.onSuccess(job.getId());
            } else {
                // 6. 失败进入重试流程（内部处理重试与重试耗尽告警）
                retryService.handleFailure(job, fireTime, executeId, result);
            }
        } catch (Exception e) {
            log.error("任务执行异常 jobId={}", job.getId(), e);
            logEntry.setStatus("FAILED");
            logEntry.setEndTime(new Date());
            logEntry.setErrorMsg(e.getMessage());
            jobLogMapper.updateById(logEntry);
            retryService.handleFailure(job, fireTime, executeId,
                    ExecuteResult.fail(e.getMessage()));
        } finally {
            lockService.unlock(lockKey);
        }
    }

    /** HTTP 执行器：POST + JSON 参数调用业务系统接口 */
    private ExecuteResult executeHttp(JobInfo job) throws Exception {
        long start = System.currentTimeMillis();
        String url = extractParam(job.getExecutorParam(), "url");
        String body = extractParam(job.getExecutorParam(), "body");
        Request request = new Request.Builder()
                .url(url)
                .post(RequestBody.create(body, MediaType.parse("application/json; charset=utf-8")))
                .build();
        try (Response response = httpClient.newCall(request).execute()) {
            String respBody = response.body() != null ? response.body().string() : "";
            boolean success = response.isSuccessful();
            return new ExecuteResult(success, System.currentTimeMillis() - start,
                    respBody, success ? null : "HTTP " + response.code());
        }
    }

    /** Java Bean 执行器：反射调用平台内 Spring Bean 方法 */
    private ExecuteResult executeBean(JobInfo job) throws Exception {
        long start = System.currentTimeMillis();
        String beanName = extractParam(job.getExecutorParam(), "beanName");
        String method = extractParam(job.getExecutorParam(), "method");
        Object bean = SpringContextHolder.getBean(beanName);
        Object result = bean.getClass().getMethod(method).invoke(bean);
        return new ExecuteResult(true, System.currentTimeMillis() - start,
                String.valueOf(result), null);
    }

    /** Shell 执行器：ProcessBuilder 执行脚本，按退出码判定 */
    private ExecuteResult executeShell(JobInfo job) throws Exception {
        long start = System.currentTimeMillis();
        String script = extractParam(job.getExecutorParam(), "script");
        Process process = new ProcessBuilder("/bin/sh", "-c", script)
                .redirectErrorStream(true).start();
        StringBuilder out = new StringBuilder();
        try (BufferedReader reader = new BufferedReader(
                new InputStreamReader(process.getInputStream()))) {
            String line;
            while ((line = reader.readLine()) != null) {
                out.append(line).append("\n");
            }
        }
        int exitCode = process.waitFor();
        boolean success = exitCode == 0;
        return new ExecuteResult(success, System.currentTimeMillis() - start,
                out.toString(), success ? null : "退出码 " + exitCode);
    }

    private String extractParam(String executorParam, String key) {
        // executorParam 为 JSON，简化用 Jackson 解析
        try {
            return new com.fasterxml.jackson.databind.ObjectMapper()
                    .readTree(executorParam).path(key).asText();
        } catch (Exception e) {
            return "";
        }
    }

    /** 执行结果实体 */
    public static class ExecuteResult {
        private final boolean success;
        private final long costMs;
        private final String output;
        private final String errorMsg;

        public ExecuteResult(boolean success, long costMs, String output, String errorMsg) {
            this.success = success;
            this.costMs = costMs;
            this.output = output;
            this.errorMsg = errorMsg;
        }
        public static ExecuteResult fail(String errorMsg) {
            return new ExecuteResult(false, 0, "", errorMsg);
        }
        public boolean isSuccess() { return success; }
        public long getCostMs() { return costMs; }
        public String getOutput() { return output; }
        public String getErrorMsg() { return errorMsg; }
    }
}
```

### 5. 重试服务：指数退避与重试耗尽告警

```java
package com.demo.scheduler.retry;

import com.demo.scheduler.entity.JobInfo;
import com.demo.scheduler.entity.JobLog;
import com.demo.scheduler.execute.JobExecuteService.ExecuteResult;
import com.demo.scheduler.mapper.JobLogMapper;
import com.demo.scheduler.alarm.AlarmService;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Service;

import java.util.Date;

/**
 * 失败重试服务：按次数 + 指数退避间隔调度重试
 * 第 N 次重试间隔 = 基础间隔 * 2^(N-1)，同一 executeId 下追加重试日志
 */
@Service
public class JobRetryService {

    private static final Logger log = LoggerFactory.getLogger(JobRetryService.class);

    @Autowired
    private JobLogMapper jobLogMapper;
    @Autowired
    private AlarmService alarmService;
    @Autowired
    private com.demo.scheduler.execute.JobExecuteService executeService;

    /**
     * 处理执行失败
     * @param executeId 首次执行的执行 ID（重试记录挂在同一链路下）
     */
    public void handleFailure(JobInfo job, Date fireTime, Long executeId, ExecuteResult result) {
        // 1. 查询该 executeId 已重试次数
        int retried = jobLogMapper.countByExecuteId(executeId);
        if (retried >= job.getRetryCount()) {
            // 2. 重试耗尽：标记失败 + 告警
            jobLogMapper.updateStatusByExecuteId(executeId, "FAILED");
            alarmService.alarm(job, executeId, "RETRY_EXHAUSTED",
                    "任务[" + job.getJobName() + "] 重试 " + retried + " 次仍失败: " + result.getErrorMsg());
            return;
        }
        // 3. 计算退避间隔并调度重试（简化：延迟任务线程；生产可用延迟队列/xxl 回调）
        long delaySec = (long) (job.getRetryInterval() * Math.pow(2, retried));
        log.info("任务 {} 第 {} 次执行失败，{}s 后重试", job.getJobName(), retried, delaySec);
        scheduleRetry(job, fireTime, executeId, retried + 1, delaySec);
    }

    /** 调度一次重试（简化实现：延迟线程；生产推荐 Redis 延迟队列或数据库轮询重试表） */
    private void scheduleRetry(JobInfo job, Date fireTime, Long executeId, int retryTimes, long delaySec) {
        Thread thread = new Thread(() -> {
            try {
                Thread.sleep(delaySec * 1000);
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
                return;
            }
            // 重试执行：同一 fireTime（防重维度不变），新起一条重试日志挂在 executeId 链路
            JobLog retryLog = new JobLog();
            retryLog.setExecuteId(executeId);
            retryLog.setJobId(job.getId());
            retryLog.setTriggerTime(new Date());
            retryLog.setFireTime(fireTime);
            retryLog.setStatus("RUNNING");
            retryLog.setRetryTimes(retryTimes);
            jobLogMapper.insert(retryLog);
            // 复用执行逻辑（executeAsync 内部会再次进入失败处理，重试计数自然递增）
            executeService.executeAsync(job, fireTime);
        });
        thread.setDaemon(true);
        thread.start();
    }
}
```

### 6. 依赖编排服务：DAG 拓扑校验与就绪判定

```java
package com.demo.scheduler.job;

import com.demo.scheduler.mapper.JobDependMapper;
import com.demo.scheduler.mapper.JobLogMapper;
import com.demo.scheduler.util.BizException;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Service;

import java.util.*;

/**
 * 依赖编排服务（DAG）
 * job_depend 表存有向边：job_id 依赖 dep_job_id
 * 就绪判定：所有上游最近一次执行必须 SUCCESS；上游成功时驱动下游触发
 */
@Service
public class JobDependService {

    @Autowired
    private JobDependMapper dependMapper;
    @Autowired
    private JobLogMapper jobLogMapper;

    /**
     * 保存依赖关系（批量）：先做环检测，有环拒绝保存
     */
    public void saveDepends(Long jobId, List<Long> depJobIds) {
        // 构造全量边集做环检测
        Map<Long, List<Long>> graph = new HashMap<>();
        List<Long> allJobIds = dependMapper.selectAllJobIds();
        for (Long id : allJobIds) {
            graph.put(id, new ArrayList<>());
        }
        for (Long depId : depJobIds) {
            graph.computeIfAbsent(jobId, k -> new ArrayList<>()).add(depId);
        }
        List<long[]> edges = dependMapper.selectAllEdges();
        for (long[] e : edges) {
            graph.computeIfAbsent(e[0], k -> new ArrayList<>()).add(e[1]);
        }
        if (hasCycle(graph)) {
            throw new BizException("依赖关系存在环，保存被拒绝（必须为有向无环图）");
        }
        dependMapper.deleteByJobId(jobId);
        for (Long depId : depJobIds) {
            dependMapper.insert(jobId, depId);
        }
    }

    /**
     * 就绪判定：上游全部「最近一次执行成功」才允许触发
     * 无上游依赖的任务永远就绪
     */
    public boolean isReady(Long jobId) {
        List<Long> deps = dependMapper.selectDepJobIds(jobId);
        if (deps.isEmpty()) {
            return true;
        }
        for (Long depId : deps) {
            String lastStatus = jobLogMapper.selectLastStatus(depId);
            if (!"SUCCESS".equals(lastStatus)) {
                return false; // 任一上游未成功，下游不触发
            }
        }
        return true;
    }

    /** 上游执行成功回调：驱动下游就绪任务触发（下游有自己的触发规则，此处只释放就绪信号） */
    public void onSuccess(Long depJobId) {
        List<Long> downstream = dependMapper.selectJobIdsByDep(depJobId);
        for (Long jobId : downstream) {
            if (isReady(jobId)) {
                // 触发下游（按其触发规则执行一次；简化：直接调用触发器）
                System.out.println("[DAG] 任务 " + depJobId + " 成功，下游任务 " + jobId + " 就绪");
            }
        }
    }

    /** DFS 环检测 */
    private boolean hasCycle(Map<Long, List<Long>> graph) {
        Set<Long> visiting = new HashSet<>();
        Set<Long> visited = new HashSet<>();
        for (Long node : graph.keySet()) {
            if (dfs(node, graph, visiting, visited)) {
                return true;
            }
        }
        return false;
    }

    private boolean dfs(Long node, Map<Long, List<Long>> graph,
                        Set<Long> visiting, Set<Long> visited) {
        if (visiting.contains(node)) return true;
        if (visited.contains(node)) return false;
        visiting.add(node);
        for (Long next : graph.getOrDefault(node, Collections.emptyList())) {
            if (dfs(next, graph, visiting, visited)) return true;
        }
        visiting.remove(node);
        visited.add(node);
        return false;
    }
}
```

### 7. 告警服务：钉钉群机器人 + 邮件

```java
package com.demo.scheduler.alarm;

import com.demo.scheduler.entity.JobAlarm;
import com.demo.scheduler.entity.JobInfo;
import com.demo.scheduler.mapper.JobAlarmMapper;
import okhttp3.MediaType;
import okhttp3.OkHttpClient;
import okhttp3.Request;
import okhttp3.RequestBody;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.mail.SimpleMailMessage;
import org.springframework.mail.javamail.JavaMailSender;
import org.springframework.stereotype.Service;

import java.util.concurrent.TimeUnit;

/**
 * 告警服务：钉钉群机器人 Webhook + 邮件
 * 告警去重：同一任务 10 分钟内同类告警合并（Redis 标记）
 */
@Service
public class AlarmService {

    @Autowired
    private JobAlarmMapper alarmMapper;
    @Autowired
    private JavaMailSender mailSender;
    @Autowired
    private org.springframework.data.redis.core.StringRedisTemplate redisTemplate;

    @Value("${scheduler.dingtalk.webhook:}")
    private String dingtalkWebhook;
    @Value("${scheduler.alarm.email:}")
    private String alarmEmail;

    private final OkHttpClient httpClient = new OkHttpClient.Builder()
            .connectTimeout(5, TimeUnit.SECONDS).build();

    /**
     * 发送告警：钉钉 + 邮件双渠道，10 分钟去重
     */
    public void alarm(JobInfo job, Long executeId, String alarmType, String content) {
        // 1. 告警去重：同一任务同一类型 10 分钟内只发一次
        String dedupKey = "job:alarm:dedup:" + job.getId() + ":" + alarmType;
        Boolean first = redisTemplate.opsForValue()
                .setIfAbsent(dedupKey, "1", 600, TimeUnit.SECONDS);
        if (!Boolean.TRUE.equals(first)) {
            return; // 同类告警刚发过，合并
        }
        // 2. 钉钉机器人
        boolean dingOk = sendDingtalk(job.getJobName(), executeId, content);
        // 3. 邮件
        boolean mailOk = sendMail(job.getJobName(), executeId, content);
        // 4. 记录告警流水
        JobAlarm record = new JobAlarm();
        record.setExecuteId(executeId);
        record.setJobId(job.getId());
        record.setAlarmType(alarmType);
        record.setContent(content);
        record.setChannel(dingOk && mailOk ? "DINGTALK+EMAIL" : (dingOk ? "DINGTALK" : "EMAIL"));
        record.setSendResult(dingOk || mailOk ? 1 : 0);
        alarmMapper.insert(record);
    }

    /** 钉钉群机器人：markdown 消息推送到群 */
    private boolean sendDingtalk(String jobName, Long executeId, String content) {
        try {
            if (dingtalkWebhook.isEmpty()) return false;
            String json = "{\"msgtype\":\"markdown\",\"markdown\":{\"title\":\"调度任务告警\","
                    + "\"text\":\"### 调度任务告警\\n- 任务: " + jobName
                    + "\\n- 执行ID: " + executeId
                    + "\\n- 详情: " + content + "\"}}";
            Request request = new Request.Builder()
                    .url(dingtalkWebhook)
                    .post(RequestBody.create(json, MediaType.parse("application/json; charset=utf-8")))
                    .build();
            try (okhttp3.Response response = httpClient.newCall(request).execute()) {
                return response.isSuccessful();
            }
        } catch (Exception e) {
            return false;
        }
    }

    /** 邮件告警 */
    private boolean sendMail(String jobName, Long executeId, String content) {
        try {
            if (alarmEmail.isEmpty()) return false;
            SimpleMailMessage message = new SimpleMailMessage();
            message.setTo(alarmEmail);
            message.setSubject("[调度平台] 任务告警: " + jobName);
            message.setText("任务: " + jobName + "\n执行ID: " + executeId + "\n详情: " + content);
            mailSender.send(message);
            return true;
        } catch (Exception e) {
            return false;
        }
    }
}
```

## 实际应用场景

### 场景一：订单数据定时同步（HTTP 执行器 + 失败重试）

电商系统每天凌晨要把订单数据同步到数仓，夜间数据库压力小、出问题要及时补救：

```text
1. 运维创建任务：名称「订单同步数仓」，触发规则 cron=0 0 2 * * ?（每天 02:00）
2. 执行器类型 HTTP，参数：url=http://order-svc/sync/warehouse，body 带日期参数
3. 配置重试：最大 5 次，基础间隔 60s（指数退避 60s/120s/240s/480s/960s）
4. 配置告警：钉钉群 + 邮件，失败与重试耗尽都告警
5. 凌晨 2:00 三个调度节点同时扫到任务，节点 B 抢锁成功执行，A/C 跳过（无重复同步）
6. 2:03 同步失败（数仓接口抖动）→ 进入重试，2:04/2:06/2:10 自动重试
7. 第 4 次重试成功，执行日志链路完整：executeId 下 1 次失败 + 3 次重试 + 1 次成功
8. 若 5 次重试全失败：钉钉群告警 + 邮件通知负责人，运维按 executeId 一键查看失败原因
```

### 场景二：每日报表生成（固定间隔 + Shell 执行器）

运营团队每天上午要 9:00、12:00、15:00、18:00 生成四版销售快报：

```text
1. 运维创建任务：触发规则用 FIXED 固定间隔 10800 秒（3 小时），首次延迟到 9:00
2. 执行器类型 Shell：脚本调用报表服务接口并压缩归档（ProcessBuilder 执行）
3. 脚本退出码 0 判定成功，非 0 判定失败进入重试
4. 报表服务接口幂等（同一 executeId 重复调用不重复生成），天然支持重试
5. 某次执行超时（超时配置 300s）→ 平台终止执行并告警，运维介入
6. 运营在控制台按任务查看最近 4 次执行时间线，确认各时段报表生成情况
```

### 场景三：数据管道 DAG 编排（依赖任务）

数据团队的数据管道：抽取 → 清洗 → 汇总 → 推送到业务库，四步有严格先后顺序：

```text
1. 创建 4 个任务：extract（抽取原始数据）、clean（清洗）、summary（指标汇总）、push（推送到业务库）
2. 配置依赖：clean 依赖 extract，summary 依赖 clean，push 依赖 summary（DAG 链式）
3. 平台保存时做环检测，拒绝任何成环的依赖配置
4. extract 每天 01:00 触发，成功后驱动 clean 就绪；clean 按自己的 cron（01:30）在就绪后触发
5. extract 失败 → clean/summary/push 全部不触发（isReady=false），extract 进入重试
6. extract 重试成功 → 链路自动续跑，无需人工干预
7. 某一步持续失败 → 重试耗尽告警，运维按 executeId 查链路定位到具体环节
8. 全程编排在控制台可视化配置，代码零改动；新环节只需新建任务 + 连依赖边
```

## 最佳实践与踩坑记录

### 最佳实践

1. 防重复执行双保险：Redis 锁（SETNX + 过期时间）解决正常场景的并发竞争，数据库唯一键（job_id + fire_time）兜底锁过期/网络分区等极端场景，两道防线缺一不可
2. 锁的 value 必须带持有者标识：释放锁前比对 value，防止「锁过期后被新持有者接管，旧持有者 DEL 误删」的经典问题
3. 执行 ID 贯穿全链路：每次触发生成雪花 ID，触发记录、执行日志、重试记录、告警记录全部用 executeId 关联，排查问题一条命令查到底
4. 重试用指数退避：固定间隔重试在服务故障恢复前会持续打爆接口，指数退避（基础间隔 * 2^N）让故障期间压力指数下降
5. 执行器必须幂等：HTTP 执行器接口、Shell 脚本要按 executeId/业务键幂等设计，重试才不会产生脏数据
6. 告警必须去重：失败重试的每次失败都告警会轰炸群聊，同一任务 10 分钟内同类告警合并，重试耗尽才升级告警
7. DAG 保存必检环：依赖配置是图结构，保存时 DFS 环检测（有环直接拒绝），运行时再判就绪，把错误挡在配置阶段
8. 任务参数 JSON 化：执行参数统一 JSON 存储（HTTP 地址/Bean 名/脚本），新增执行器类型时表结构零变更

### 踩坑记录

```text
坑 1：多节点部署任务重复执行
结论：3 个节点部署后同一任务同一时刻执行了 3 次，数据翻倍。
原因：每个节点都跑扫描线程，都认为任务到期，没有互斥机制。
解法：触发前抢 Redis 分布式锁（SETNX job:lock:{jobId}:{fireTime}），抢不到直接跳过；再加数据库唯一键（job_id+fire_time）兜底锁失效场景。

坑 2：锁被误删导致并发执行
结论：任务 A 执行超时锁过期，节点 B 抢锁开始执行；A 结束后 DEL 把 B 的锁删了，节点 C 又抢到锁，三重执行。
原因：释放锁时没校验持有者，无脑 DEL。
解法：锁 value 存随机 UUID（持有者标识），DEL 前先 GET 比对，一致才删；生产可用 Redisson 看门狗续期避免锁提前过期。

坑 3：重试把下游接口打爆
结论：上游数据库故障，每秒重试一次，下游被请求淹没，故障恢复后依然高负载。
原因：固定间隔 1 秒无脑重试。
解法：指数退避重试（基础间隔 * 2^N）+ 最大次数上限；故障期压力指数下降，恢复后自然续跑。

坑 4：cron 表达式校验不严
结论：保存了非法 cron（如 0 0 25 * * ? 小时 25），任务永远不触发，无人发现。
原因：只存了字符串没做合法性校验。
解法：保存前用 Quartz CronExpression 解析并计算未来触发时间，解析失败或没有下次触发时间直接拒绝；控制台提供「未来 5 次触发时间」预览。

坑 5：执行日志被重试覆盖
结论：任务失败重试 3 次后，日志只剩最后一条，第一次失败的原始原因丢了。
原因：每次执行更新同一条日志记录。
解法：一次执行一条日志行，重试追加新行（同一 executeId + retryTimes 递增），首次失败原因与每次重试明细完整保留，链路视图按 executeId 聚合展示。

坑 6：依赖配置成环导致任务死循环
结论：A 依赖 B、B 依赖 A，两个任务互相等，永远不执行。
原因：保存依赖时没做环检测。
解法：保存时基于全量边集 DFS 环检测，有环直接拒绝；运行时 isReady 判定增加「上游最后状态非 SUCCESS 则不触发」，双保险。

坑 7：告警轰炸
结论：任务凌晨失败重试 10 次，钉钉群收到 10+ 条告警，真正重要的问题被淹没。
原因：每次失败都发告警。
解法：同一任务同一告警类型 10 分钟去重（Redis SETNX + TTL），重试过程静默、重试耗尽才升级告警；连续失败 N 次单独告警策略。

坑 8：任务参数解析失败静默吞掉
结论：HTTP 地址配错，任务一直失败，日志里看不到真实原因。
原因：参数解析异常被 catch 后返回空字符串，执行器拿空地址调用报错但原因被掩盖。
解法：参数解析失败直接抛错并在日志中记录原始 executor_param 与解析异常；控制台提供「执行参数预览」与「手动执行」快速验证配置。
```

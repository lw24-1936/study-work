## 项目背景

统一认证中心（SSO，Single Sign-On）是企业多个业务系统（OA、ERP、CRM、项目管理系统、合同系统）共用的「一个账号、一套密码、一次登录处处登录」的认证底座。没有 SSO 之前，每个系统各自维护账号密码，员工要记住七八套口令，改密码要改七八个系统，权限分配散落各处，安全审计无从下手。本系统以 OAuth2 授权码模式为核心：业务系统通过「注册应用 → 引导用户到认证中心登录 → 授权码换 Token → 携带 Token 访问」完成接入；认证中心负责统一登录、JWT Token 签发与吊销、全局会话与局部会话同步（一处登录处处登录、一处退出处处退出）、用户中心（账号/密码/第三方绑定）与权限下发。

业务痛点：

```text
1. 账号泛滥：每个系统一套账号密码，员工记忆负担重，弱密码随手用
2. 改密噩梦：员工离职或密码泄露，要挨个系统改密码，漏一个就留后门
3. 权限分散：角色权限在各自系统里定义，同一个人不同系统权限不一致，审计困难
4. 登录割裂：在 OA 登录后进 ERP 还要再登一次，体验割裂、效率低
5. 安全失控：无法统一管控登录策略（失败锁定、异地登录、会话吊销），出了事无法全局处置
6. 三方账号无法统一：微信/钉钉/企业微信账号与内部账号各管各的，无法打通
```

目标用户与核心诉求：

```text
1. 业务系统开发者：按 OAuth2 标准接入认证中心（注册应用 + 回调地址），无需自建登录体系
2. 终端员工：一次登录，所有接入系统免登录进入；退出一个系统，全部系统退出
3. 系统管理员：统一管理应用接入、用户账号、角色权限、登录日志与安全策略
4. 安全/审计人员：全局登录流水可查，任意用户可一键踢下线（Token 吊销）
```

项目要解决的核心问题一句话概括：用 OAuth2 授权码模式 + JWT + Redis 会话，把分散在各系统的登录与权限收拢到认证中心，实现「一次认证、处处通行、统一管控」。

## 功能介绍

功能按角色与模块拆分：应用管理、统一登录、OAuth2 授权码流程、Token 管理、用户中心、权限下发、多应用会话同步。

```text
一、应用管理（系统管理员/应用开发者使用）
1. 应用注册 —— 填写应用名称、图标、回调地址（redirect_uri）、应用类型（Web/移动端），生成 client_id/client_secret
2. 回调地址管控 —— 可配置多个回调地址（精确匹配或域名前缀匹配），杜绝回调劫持
3. 应用启停 —— 停用应用后其登录与换 Token 请求被拒绝
4. 密钥重置 —— client_secret 泄露可一键重置，不影响存量 Token

二、统一登录（终端用户使用）
1. 账号密码登录 —— 用户名 + 密码（BCrypt 存储），登录成功建立全局会话
2. 第三方登录 —— 微信/钉钉/企业微信扫码或授权登录（绑定后免密）
3. 登录安全 —— 连续失败锁定、异地登录提示（可选）、登录日志
4. 全局会话 —— 登录态存认证中心（sso 域 cookie + Redis），有效期内任意应用免登录

三、OAuth2 授权码流程（核心协议）
1. 授权端点 —— /oauth/authorize：校验应用与回调地址，未登录先登录，已登录直接发码
2. 授权码签发 —— 一次性授权码（绑定 client_id + redirect_uri + 用户，10 分钟有效）
3. 令牌端点 —— /oauth/token：应用后端用授权码 + client_secret 换取 Token（授权码模式）
4. 状态参数 —— state 透传防 CSRF（应用生成随机 state，回调时校验）
5. 用户信息端点 —— /userinfo：应用凭 Access Token 获取用户信息与权限

四、Token 管理（认证中心核心能力）
1. Access Token —— JWT 短效（默认 2 小时），携带用户 id、角色、权限，应用无状态校验
2. Refresh Token —— 长效（默认 7 天）存 Redis，过期自动续期，支持轮换
3. 黑名单吊销 —— 登出/踢下线将 Access Token 的 jti 加入 Redis 黑名单，未到期也立即失效
4. 刷新续期 —— Access Token 过期后凭 Refresh Token 换新，无需重新登录
5. 一键踢下线 —— 管理员可将指定用户的所有会话全部吊销

五、用户中心（管理员与用户使用）
1. 账号管理 —— 创建/停用/重置密码（BCrypt 加密存储）
2. 角色权限 —— 角色 CRUD，角色绑定权限点集合，用户绑定角色
3. 第三方绑定 —— 绑定/解绑微信、钉钉账号，支持绑定后一键登录
4. 个人中心 —— 修改密码、查看登录设备与登录历史

六、权限下发（接入应用使用）
1. 登录即带权 —— 换 Token 与 /userinfo 时返回用户角色与权限点集合
2. 应用侧缓存 —— 应用缓存权限并按权限控制菜单与接口，认证中心变更角色后按 TTL 失效
3. 权限变更通知 —— 可选：用户角色变更时广播，应用实时刷新权限缓存

七、多应用会话同步（SSO 核心体验）
1. 一处登录处处登录 —— 登录 appA 后再进 appB，认证中心识别全局会话，直接发码完成登录（无感）
2. 一处退出处处退出 —— appA 登出 → 认证中心删除全局会话 → Redis Pub/Sub 广播 → 各应用删除局部会话
3. 跨域登录态 —— 授权码模式通过「浏览器 302 回跳 + 应用后端换 Token」天然支持跨域，不依赖 cookie 跨域
```

## 技术选型

| 组件 | 选型 | 理由 |
|------|------|------|
| 开发框架 | Spring Boot 2.7/3.x | 生态成熟，快速搭建 REST 服务 |
| 安全框架 | Spring Security（仅用密码加密与过滤链） | BCrypt 密码哈希、安全过滤链 |
| OAuth2 | 自研实现授权码模式（不引入 spring-authorization-server） | 核心逻辑可控，教学演示清晰 |
| Token | JWT（jjwt 0.11.x） | 无状态校验，应用侧零存储 |
| 会话存储 | Redis | 全局会话、授权码、Refresh Token、黑名单、Pub/Sub |
| 数据库 | MySQL 8.0 | 应用、用户、角色、绑定关系等持久化数据 |
| 密码加密 | Spring Security BCryptPasswordEncoder | 加盐哈希，抗彩虹表 |
| 前端 | Vue 3 + Element Plus | 登录页、授权确认页、管理后台 |
| 构建 | Maven | 依赖管理标准工具 |

选型说明：

```text
1. OAuth2 授权码模式自研：不依赖 spring-authorization-server，把「发码、换 Token、验回调」每一步都写出来，是理解 SSO 协议的最佳方式；接口语义与标准 OAuth2 完全一致，生产可平滑迁移
2. JWT 做 Access Token：应用侧只校验签名不过查库，无状态水平扩容；短时效 + 黑名单机制弥补 JWT「无法主动失效」的短板
3. Refresh Token 存 Redis：可吊销、可轮换、可统计，比纯 JWT refresh 更可控
4. 全局会话用「sso 域 cookie + Redis」：cookie 只在认证中心域名下，跨应用传递靠授权码回跳，避开跨域 cookie 限制
5. 会话同步用 Redis Pub/Sub：一处退出广播到所有应用实例，比轮询快、比消息队列轻
```

## 架构设计

系统分层与请求链路：

```text
┌──────────────────────────────────────────────────────────────┐
│               浏览器（终端用户） / 各业务系统后端              │
│   业务系统 A（oa.example.com）  业务系统 B（crm.example.com） │
│   前端应用（Vue3） + 应用后端（Spring Boot 接入方）           │

┌───────────────▼───────────────────────────────▼──────────────┐
│                   统一认证中心（sso.example.com）             │
│   ┌────────────┐ ┌────────────┐ ┌─────────────────────────┐  │
│   │ 应用管理服务 │ │ 授权码服务  │ │ 令牌服务（JWT签发/校验） │  │
│   │ 注册/回调校验│ │ 签发/消费   │ │ 黑名单/刷新/吊销        │  │

│   ┌────────────┐ ┌────────────┐ ┌─────────────────────────┐  │
│   │ 统一登录服务 │ │ 会话同步服务 │ │ 用户中心服务            │  │
│   │ 全局会话    │ │ Pub/Sub广播 │ │ 账号/角色/三方绑定       │  │
│   └────────────┘ └────────────┘ └─────────────────────────┘  │
└───────┬─────────────────┬─────────────────┬──────────────────┘
        │                 │                 │
┌───────▼───────┐   ┌──────▼───────┐   ┌──────▼──────────┐
│    MySQL      │   │    Redis     │   │   各业务系统      │
│ 应用/用户/角色 │   │ 会话/授权码/  │   │ 局部会话 + 权限   │
│ 绑定/登录日志  │   │ 黑名单/PubSub │   │ 缓存（接入方）    │
└───────────────┘   └──────────────┘   └─────────────────┘
```

首次登录（授权码模式）完整链路：

```text
1. 用户访问业务系统 A 的受保护页面，应用后端发现未登录 → 302 跳转认证中心：
   https://sso.example.com/oauth/authorize?response_type=code&client_id=app_a&redirect_uri=https://oa.example.com/callback&state=xyz123
2. 认证中心校验 client_id 与 redirect_uri 匹配 → 用户未登录 → 302 跳登录页
3. 用户输入账号密码提交 → 认证中心校验通过 → 建立全局会话（sso 域种 cookie + Redis 存 ticket）
4. 认证中心生成一次性授权码 code（Redis，绑定 client_id + redirect_uri + userId，TTL 10 分钟）
5. 302 回跳应用回调地址：https://oa.example.com/callback?code=abc123&state=xyz123（应用校验 state 防 CSRF）
6. 应用后端携 code + client_secret 调用认证中心令牌端点：
   POST /oauth/token?grant_type=authorization_code&code=abc123&redirect_uri=...&client_id=app_a&client_secret=...
7. 认证中心消费授权码（校验 client_id/redirect_uri 匹配，一次性删除）→ 签发 JWT Access Token + Refresh Token
8. 应用后端建立局部会话（自己的 session/Token），跳回业务页面 —— 登录完成
9. 用户再访问业务系统 B：同样 302 到认证中心，此时全局会话已存在 → 直接发码 → B 无感登录（SSO 效果）
```

一处退出链路：

```text
1. 用户在业务系统 A 点击退出 → 应用后端调用认证中心 /logout 接口（带 Access Token）
2. 认证中心吊销该用户会话：jti 入黑名单 + 删除 Refresh Token + 删除全局会话 ticket
3. 认证中心向 Redis 频道 sso:logout:channel 发布 userId
4. 所有接入应用（各自实例）订阅该频道 → 收到 userId → 删除本地局部会话与权限缓存
5. 浏览器被 302 到认证中心退出确认页 —— 全系统退出完成
```

Redis Key 设计：

```text
sso:session:{ticket}          全局会话（value=userId，TTL 12h，访问时滑动续期）
sso:code:{code}               授权码（value=userId|clientId|redirectUri，TTL 600s，消费后删除）
sso:refresh:{userId}:{jti}    Refresh Token 状态（value=1，TTL 7d，吊销时删除）
sso:blacklist:{jti}           Access Token 黑名单（value=1，TTL=Token 剩余有效期）
sso:app:{clientId}            应用信息缓存（TTL 1h，回调校验加速）
sso:fail:lock:{username}      连续失败锁定（5 次失败锁 30 分钟）
sso:logout:channel            Redis Pub/Sub 频道（一处退出广播 userId）
```

## 核心实现

### 1. 应用管理：注册与回调地址校验

```java
package com.demo.sso.app;

import com.demo.sso.entity.OAuthApp;
import com.demo.sso.mapper.OAuthAppMapper;
import com.demo.sso.util.BizException;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.security.crypto.bcrypt.BCryptPasswordEncoder;
import org.springframework.stereotype.Service;

import java.util.Arrays;
import java.util.List;
import java.util.UUID;

/**
 * 应用管理服务：注册应用、回调地址校验、密钥重置
 * 回调地址校验是 OAuth2 安全的第一道防线，必须精确管控
 */
@Service
public class OAuthAppService {

    @Autowired
    private OAuthAppMapper appMapper;
    private final BCryptPasswordEncoder encoder = new BCryptPasswordEncoder();

    /** 注册应用：生成 client_id / client_secret（secret 加密存储） */
    public OAuthApp register(String appName, List<String> redirectUris, String owner) {
        OAuthApp app = new OAuthApp();
        app.setAppName(appName);
        app.setClientId("app_" + UUID.randomUUID().toString().replace("-", ""));
        String secret = UUID.randomUUID().toString().replace("-", "") + UUID.randomUUID().toString().replace("-", "");
        app.setClientSecret(encoder.encode(secret)); // 只存密文，明文只返回一次
        app.setRedirectUris(String.join(",", redirectUris));
        app.setStatus(1);
        app.setOwner(owner);
        appMapper.insert(app);
        // 返回明文 secret 供接入方保存（只此一次）
        app.setClientSecret(secret);
        return app;
    }

    /**
     * 校验回调地址：精确匹配或域名前缀匹配
     * 例如注册 https://oa.example.com/callback 与 https://*.example.com/callback
     */
    public void validateRedirectUri(String clientId, String redirectUri) {
        OAuthApp app = appMapper.selectByClientId(clientId);
        if (app == null || app.getStatus() != 1) {
            throw new BizException("应用不存在或已停用");
        }
        List<String> uris = Arrays.asList(app.getRedirectUris().split(","));
        boolean match = uris.stream().anyMatch(reg -> matchUri(reg.trim(), redirectUri));
        if (!match) {
            throw new BizException("回调地址不在白名单内: " + redirectUri);
        }
    }

    /** 精确匹配或通配匹配（* 只允许出现在域名段） */
    private boolean matchUri(String registered, String actual) {
        if (registered.equals(actual)) {
            return true;
        }
        if (registered.contains("*")) {
            String pattern = registered.replace(".", "\\.").replace("*", "[^/]*");
            return actual.matches(pattern);
        }
        return false;
    }

    /** 校验 client_secret（换 Token 时使用） */
    public boolean checkSecret(String clientId, String rawSecret) {
        OAuthApp app = appMapper.selectByClientId(clientId);
        return app != null && encoder.matches(rawSecret, app.getClientSecret());
    }
}
```

```java
 * 授权码服务
 * 授权码是授权码模式的核心凭证：短时效、一次性、必须与 client_id + redirect_uri + userId 绑定
 */
@Service
public class AuthCodeService {

    @Autowired
    private StringRedisTemplate redisTemplate;

    /**
     * 签发授权码
     * @return code（已绑定 clientId/redirectUri/userId 存入 Redis）
     */
    public String issueCode(String clientId, String redirectUri, Long userId) {
        String code = UUID.randomUUID().toString().replace("-", "");
        String value = userId + "|" + clientId + "|" + redirectUri;
        redisTemplate.opsForValue().set("sso:code:" + code, value, 10, TimeUnit.MINUTES);
        return code;
    }

    /**
     * 消费授权码：校验绑定关系 + 原子删除（一次性）
     * @return 授权用户 id
     */
    public Long consumeCode(String code, String clientId, String redirectUri) {
        String key = "sso:code:" + code;
        String value = redisTemplate.opsForValue().get(key);
        if (value == null) {
            throw new BizException("授权码不存在或已过期");
        }
        String[] parts = value.split("\\|");
        Long userId = Long.valueOf(parts[0]);
        String boundClient = parts[1];
        String boundUri = parts[2];
        // 校验绑定关系：code 只能被申请它的应用在申请时的回调地址使用
        if (!clientId.equals(boundClient) || !redirectUri.equals(boundUri)) {
            throw new BizException("授权码与应用/回调地址不匹配");
        }
        // 原子删除：先删再返回，保证一次性（并发第二次拿不到）
        redisTemplate.delete(key);
        return userId;
    }
}
```

```java
 * 任一应用跳转登录时，凭 ticket 判定「已登录」，直接发授权码完成无感登录

@Service
public class SsoLoginService {

    @Autowired
    private StringRedisTemplate redisTemplate;

    private static final long SESSION_TTL_HOURS = 12;

    /** 登录成功：创建全局会话，返回 ticket（种到 sso 域 cookie） */
    public String createGlobalSession(Long userId) {
        String ticket = UUID.randomUUID().toString().replace("-", "");
        redisTemplate.opsForValue().set("sso:session:" + ticket,
                String.valueOf(userId), SESSION_TTL_HOURS, TimeUnit.HOURS);
        return ticket;
    }

    /** 校验全局会话：凭 ticket 返回 userId；未登录返回 null */
    public Long checkGlobalSession(String ticket) {
        if (ticket == null || ticket.isEmpty()) {
            return null;

        if (value == null) {
            return null;
        }
        // 滑动续期：每次访问刷新 TTL，用户持续活跃则不掉线
        redisTemplate.expire("sso:session:" + ticket, SESSION_TTL_HOURS, TimeUnit.HOURS);
        return Long.valueOf(value);
    }

    /** 删除全局会话（登出/踢下线时调用） */
    public void destroyGlobalSession(String ticket) {
        if (ticket != null) {
            redisTemplate.delete("sso:session:" + ticket);
        }
    }
```

### 4. 令牌服务：JWT 签发、校验、刷新与黑名单

```java
package com.demo.sso.token;

import com.demo.sso.util.BizException;
import io.jsonwebtoken.Claims;
import io.jsonwebtoken.Jwts;
import io.jsonwebtoken.SignatureAlgorithm;
import io.jsonwebtoken.security.Keys;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.data.redis.core.StringRedisTemplate;
import org.springframework.stereotype.Service;

import javax.crypto.SecretKey;
import java.nio.charset.StandardCharsets;
import java.util.Date;
import java.util.List;
import java.util.UUID;
import java.util.concurrent.TimeUnit;

/**
 * 令牌服务：JWT 签发/校验/刷新 + Redis 黑名单
 * Access Token 无状态（应用侧验签即用），黑名单兜底实现「立即失效」
 */
@Service
public class TokenService {

    // 演示密钥：生产必须从配置中心加载并定期轮换
    private static final SecretKey KEY = Keys.hmacShaKeyFor(
            "sso-demo-secret-key-please-change-in-production-2026".getBytes(StandardCharsets.UTF_8));

    @Autowired
    private StringRedisTemplate redisTemplate;

    private static final long ACCESS_TTL_MINUTES = 120;   // Access Token 2 小时
    private static final long REFRESH_TTL_DAYS = 7;       // Refresh Token 7 天

    /** 签发 Token 对（Access + Refresh） */
    public TokenPair issueToken(Long userId, String username, List<String> roles) {
        String jti = UUID.randomUUID().toString().replace("-", "");
        Date now = new Date();
        // Access Token：sub=userId，携带角色与权限，应用侧校验
        String accessToken = Jwts.builder()
                .setId(jti)
                .setSubject(String.valueOf(userId))
                .claim("username", username)
                .claim("roles", roles)
                .setIssuedAt(now)
                .setExpiration(new Date(now.getTime() + ACCESS_TTL_MINUTES * 60_000))
                .signWith(KEY, SignatureAlgorithm.HS256)
                .compact();
        // Refresh Token：随机串存 Redis，可吊销可轮换
        String refreshToken = UUID.randomUUID().toString().replace("-", "")
                + UUID.randomUUID().toString().replace("-", "");
        redisTemplate.opsForValue().set("sso:refresh:" + userId + ":" + refreshToken,
                jti, REFRESH_TTL_DAYS, TimeUnit.DAYS);
        return new TokenPair(accessToken, refreshToken, ACCESS_TTL_MINUTES);
    }

    /** 校验 Access Token：签名 + 过期 + 黑名单，返回 Claims */
    public Claims parseAccessToken(String accessToken) {
        try {
            Claims claims = Jwts.parserBuilder().setSigningKey(KEY).build()
                    .parseClaimsJws(accessToken).getBody();
            // 黑名单校验：jti 在黑名单说明已被吊销
            Boolean blocked = redisTemplate.hasKey("sso:blacklist:" + claims.getId());
            if (Boolean.TRUE.equals(blocked)) {
                throw new BizException("Token 已被吊销");
            }
            return claims;
        } catch (BizException e) {
            throw e;
        } catch (Exception e) {
            throw new BizException("Token 无效或已过期");
        }
    }

    /** 刷新：Refresh Token 换新 Access Token（轮换策略，旧 refresh 作废） */
    public TokenPair refresh(Long userId, String refreshToken) {
        String key = "sso:refresh:" + userId + ":" + refreshToken;
        String jti = redisTemplate.opsForValue().get(key);
        if (jti == null) {
            throw new BizException("Refresh Token 无效或已过期，请重新登录");
        }
        // 轮换：删旧 refresh（防重放），签新 Token 对
        redisTemplate.delete(key);
        return issueToken(userId, "user", List.of());
    }

    /** 吊销：Access Token jti 入黑名单 + 删除 Refresh Token（登出/踢下线） */
    public void revoke(String accessToken, Long userId, String refreshToken) {
        try {
            Claims claims = Jwts.parserBuilder().setSigningKey(KEY).build()
                    .parseClaimsJws(accessToken).getBody();
            long remainMs = claims.getExpiration().getTime() - System.currentTimeMillis();
            if (remainMs > 0) {
                redisTemplate.opsForValue().set("sso:blacklist:" + claims.getId(),
                        "1", remainMs, TimeUnit.MILLISECONDS);
            }
        } catch (Exception ignored) {
            // Token 已过期无需入黑名单
        }
        if (refreshToken != null) {
            redisTemplate.delete("sso:refresh:" + userId + ":" + refreshToken);
        }
    }

    /** Token 对实体 */
    public static class TokenPair {
        private String accessToken;
        private String refreshToken;
        private long expiresIn;

        public TokenPair(String accessToken, String refreshToken, long expiresIn) {
            this.accessToken = accessToken;
            this.refreshToken = refreshToken;
            this.expiresIn = expiresIn;
        }
        public String getAccessToken() { return accessToken; }
        public String getRefreshToken() { return refreshToken; }
        public long getExpiresIn() { return expiresIn; }
    }
}
```

```java
/**
 * SSO 对外端点：授权码模式完整实现
 * /oauth/authorize 浏览器授权端点 | /login 登录提交 | /oauth/token 令牌端点

@RestController
public class SsoController {

    @Autowired
    private OAuthAppService appService;
    @Autowired
    private AuthCodeService authCodeService;
    @Autowired
    private SsoLoginService ssoLoginService;
    @Autowired
    private TokenService tokenService;

    private UserCenterService userCenterService;

    /**
     * 授权端点（浏览器 302 进入）：
     * 校验应用与回调 → 未登录跳登录页 → 已登录发授权码回跳
     */
    @GetMapping("/oauth/authorize")
    public void authorize(@RequestParam String response_type,
                          @RequestParam String client_id,
                          @RequestParam String redirect_uri,
                          @RequestParam(required = false) String state,
                          HttpServletRequest request,
                          HttpServletResponse response) throws Exception {
        // 1. 协议校验：只支持 code 模式
        if (!"code".equals(response_type)) {
            throw new BizException("不支持的 response_type: " + response_type);
        }
        // 2. 回调地址白名单校验（安全第一道防线）
        appService.validateRedirectUri(client_id, redirect_uri);
        // 3. 全局会话判定：已登录直接发码，未登录跳登录页
        Long userId = ssoLoginService.checkGlobalSession(readTicket(request));
        if (userId == null) {
            // 带上原参数跳登录页，登录成功后原路继续
            String back = "/oauth/authorize?response_type=code&client_id=" + client_id
                    + "&redirect_uri=" + redirect_uri + "&state=" + state;
            response.sendRedirect("/login?back=" + java.net.URLEncoder.encode(back, "UTF-8"));
            return;
        }
        // 4. 已登录：签发授权码并 302 回跳
        String code = authCodeService.issueCode(client_id, redirect_uri, userId);
        String redirect = redirect_uri + (redirect_uri.contains("?") ? "&" : "?")
                + "code=" + code + "&state=" + state;
        response.sendRedirect(redirect);
    }

    /** 登录提交：校验账号密码 → 建全局会话 → 发授权码回跳 */
    @PostMapping("/login")
    public void login(@RequestParam String username,
                      @RequestParam String password,
                      @RequestParam String back,
                      HttpServletResponse response) throws Exception {
        SysUser user = userCenterService.login(username, password);
        // 建立全局会话（种 sso 域 cookie）
        String ticket = ssoLoginService.createGlobalSession(user.getId());
        Cookie cookie = new Cookie("SSO_TICKET", ticket);
        cookie.setPath("/");
        cookie.setHttpOnly(true);
        cookie.setMaxAge(12 * 3600);
        response.addCookie(cookie);
        response.sendRedirect(back);
    }

    /**
     * 令牌端点（应用后端调用）：
     * 授权码换 Token，校验 code 绑定关系 + client_secret
     */
    @PostMapping("/oauth/token")
    public Map<String, Object> token(@RequestParam String grant_type,
                                     @RequestParam String code,
                                     @RequestParam String redirect_uri,
                                     @RequestParam String client_id,
                                     @RequestParam String client_secret) {
        if (!"authorization_code".equals(grant_type)) {
            throw new BizException("不支持的 grant_type: " + grant_type);
        }
        // 1. 应用密钥校验
        if (!appService.checkSecret(client_id, client_secret)) {
            throw new BizException("应用密钥错误");
        }
        // 2. 消费授权码（绑定关系校验 + 一次性）
        Long userId = authCodeService.consumeCode(code, client_id, redirect_uri);
        // 3. 权限组装 + 签发 Token（权限下发：登录即带角色权限）
        List<String> permissions = userCenterService.getUserPermissions(userId);
        SysUser user = userCenterService.getById(userId);
        TokenService.TokenPair pair = tokenService.issueToken(userId, user.getUsername(), permissions);
        return Map.of(
                "access_token", pair.getAccessToken(),
                "refresh_token", pair.getRefreshToken(),
                "expires_in", pair.getExpiresIn(),
                "token_type", "Bearer",
                "permissions", permissions);
    }

    /** 登出：吊销 Token + 删全局会话 + 广播全应用退出 */
    @PostMapping("/logout")
    public void logout(@RequestHeader("Authorization") String authorization,
                       @RequestParam(required = false) String refreshToken,
                       @RequestParam(required = false) String ticket) {
        String accessToken = authorization.replace("Bearer ", "");
        Long userId = Long.valueOf(tokenService.parseAccessToken(accessToken).getSubject());
        tokenService.revoke(accessToken, userId, refreshToken);
        ssoLoginService.destroyGlobalSession(ticket);
        // 广播：各接入应用删除局部会话（一处退出处处退出）
        sessionSyncService.publishLogout(userId);
    }

    /** 用户信息端点：应用凭 Access Token 获取用户与权限 */
    @GetMapping("/userinfo")
    public Map<String, Object> userinfo(@RequestHeader("Authorization") String authorization) {
        String accessToken = authorization.replace("Bearer ", "");
        io.jsonwebtoken.Claims claims = tokenService.parseAccessToken(accessToken);
        Long userId = Long.valueOf(claims.getSubject());
        return Map.of(
                "userId", userId,
                "username", claims.get("username"),
                "roles", claims.get("roles"),
                "permissions", userCenterService.getUserPermissions(userId));
    }

    private String readTicket(HttpServletRequest request) {
        Cookie[] cookies = request.getCookies();
        if (cookies == null) return null;
        for (Cookie c : cookies) {
            if ("SSO_TICKET".equals(c.getName())) {
                return c.getValue();
            }
        }
        return null;
    }
}
```

```java
            user.setLoginFailCnt(user.getLoginFailCnt() + 1);

        List<String> roleCodes = userRoleMapper.selectRoleCodesByUserId(userId);
        List<String> permissions = new ArrayList<>();
        for (String roleCode : roleCodes) {
            String perms = roleMapper.selectPermissionsByCode(roleCode);
            if (perms != null) {
                for (String p : perms.split(",")) {
                    if (!p.trim().isEmpty() && !permissions.contains(p.trim())) {
                        permissions.add(p.trim());
                    }
                }
            }
        }
        return permissions;
    }

    public SysUser getById(Long userId) {
        return userMapper.selectById(userId);
    }
}
```

## 实际应用场景

### 场景一：企业多系统 SSO 接入（OA、ERP、CRM）

公司有 OA、ERP、CRM 三个系统，希望员工一次登录全部免登：

```text
1. 管理员在认证中心注册三个应用，配置各自回调地址（oa.example.com/callback 等），生成 client_id/client_secret
2. 三个系统后端各自实现「OAuth2 客户端」：未登录跳授权端点、回调换 Token、携带 Token 调 /userinfo
3. 员工访问 OA 未登录 → 302 到认证中心登录页 → 输入账号密码 → 全局会话建立
4. 认证中心发授权码回跳 OA → OA 后端换 Token 建局部会话 → 员工进入 OA
5. 员工切到 ERP：302 到认证中心 → 全局会话有效 → 直接发码 → ERP 无感登录（免输密码）
6. 员工下班点击任一系统「退出」→ 认证中心吊销 Token + 删全局会话 + 广播
7. ERP、CRM 收到广播删除局部会话 —— 一处退出，处处退出，安全收口
```

### 场景二：第三方应用授权登录（开放平台）

外部合作方开发的 SaaS 应用要接入企业账号体系，但企业不想暴露密码：

```text
1. 合作方应用在认证中心注册，获取 client_id/client_secret（回调地址受管控）
2. 用户点击「使用企业账号登录」→ 跳认证中心 → 登录 → 授权确认页（展示应用名称与申请的权限）
3. 用户点击「同意授权」→ 认证中心发授权码回跳合作方应用
4. 合作方后端凭授权码 + client_secret 换 Token，获取用户基本信息与角色
5. 用户密码永远不经过合作方 —— 企业账号体系零泄露
6. 企业风控发现合作方异常 → 管理员一键停用应用或吊销用户 Token，立即生效
```

### 场景三：账号安全治理与一键踢下线

安全团队发现某员工账号在异地登录，需要立即处置：

```text
1. 管理员在认证中心后台检索该用户，查看登录日志（时间/IP/设备/方式）
2. 确认异常后执行「踢下线」：吊销该用户全部 Access Token（jti 入黑名单）+ 删 Refresh Token + 删全局会话
3. 广播登出事件，各应用删除该用户局部会话
4. 该用户所有系统的会话立即失效，即使 Token 未过期也无法访问
5. 同时触发密码重置流程，要求用户改密后重新登录
6. 全程 1 分钟完成，审计日志留痕（谁在什么时间踢了谁）
```

## 最佳实践与踩坑记录

### 最佳实践

1. 回调地址白名单是第一道安全防线：所有授权请求必须先过 validateRedirectUri，杜绝「攻击者把 redirect_uri 指向自己服务器骗取授权码」的经典攻击
2. 授权码三绑定：code 必须绑定 client_id + redirect_uri + userId，换 Token 时逐项比对，防授权码被偷用
3. 授权码一次性：消费时「先删 Redis 再返回」，并发重放第二次必然失败
4. Access Token 短效 + 黑名单兜底：JWT 无法主动失效，必须配合 jti 黑名单实现「登出立即失效」，黑名单 TTL 设为 Token 剩余有效期避免无限膨胀
5. Refresh Token 轮换：每次刷新生成新 refresh 并删除旧的，防重放；Refresh Token 存 Redis 可全局吊销
6. 全局会话滑动续期：用户活跃期间持续刷新 TTL，避免「用着用着突然要重新登录」的体验问题
7. state 参数必须校验：授权请求带应用生成的随机 state，回调时比对，防登录 CSRF
8. 密码只存 BCrypt 哈希：明文永不落库、永不进日志；client_secret 同样加密存储，明文只返回注册当次

### 踩坑记录

```text
坑 1：回调地址没做白名单，授权码被劫持
结论：攻击者构造恶意 redirect_uri 拿到授权码，登录态被窃取。
原因：授权端点只校验了 client_id，没有校验回调地址。
解法：所有授权请求先过回调白名单校验（精确 + 域名通配），不在白名单直接拒绝；回调白名单变更需管理员审批。

坑 2：授权码可重复使用
结论：同一授权码被换两次 Token，产生两个有效会话。
原因：消费授权码时只读了值没删除，校验通过后也没有标记已用。
解法：Redis 先 DEL 再校验返回值（原子一次性），数据库方案用「UPDATE ... SET used=1 WHERE used=0」条件更新判断影响行数。

坑 3：JWT 登出后仍然有效
结论：用户点了退出，拿旧 Token 还能访问接口。
原因：JWT 无状态，服务端没有吊销机制。
解法：登出时把 jti 写入 Redis 黑名单，校验 Token 时先查黑名单；黑名单 TTL = Token 剩余有效期，到期自动清理。

坑 4：一处退出只删了当前应用会话
结论：在 OA 退出，ERP 的会话还活着，安全事件扩大。
原因：登出逻辑只处理了认证中心 Token，没有通知其他应用。
解法：认证中心登出后向 Redis Pub/Sub 频道广播 userId，各应用实例订阅后统一清理本地局部会话与权限缓存。

坑 5：全局会话续期导致永久在线
结论：员工长期挂机，会话永不失效，离职后账号仍可用。
原因：滑动续期只延长不过期，没有最大空闲上限。
解法：双层 TTL——活跃续期到 12h，但累计超过 7 天强制重新登录（存 lastLoginAt 判定）；离职用户由管理员一键踢下线兜底。

坑 6：refresh 重放攻击
结论：泄露的 Refresh Token 被反复使用，攻击者长期保持登录。
原因：刷新接口只校验 refresh 存在，不轮换。
解法：刷新即轮换——每次刷新删除旧 refresh 签新 refresh，旧值重放直接被拒绝；同时 refresh 绑定 userId，跨用户使用直接拒绝并告警。

坑 7：权限下发后应用侧缓存不更新
结论：用户角色被降级，旧权限缓存 24 小时不失效，仍能访问已无权接口。
原因：权限缓存 TTL 过长且无失效机制。
解法：权限缓存 TTL 缩短到 5-10 分钟；角色变更时认证中心发布权限变更事件（复用 Pub/Sub 频道），应用实时清缓存；敏感权限接口应用侧二次鉴权兜底。
```

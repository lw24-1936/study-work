## 项目背景

任务协作看板系统（Kanban）以「看板 - 列表 - 卡片」三级模型组织任务：一个项目一张看板，看板里按流程分列（待办/进行中/测试/完成），任务以卡片形式在列间拖拽流转。它是敏捷开发（Scrum/Kanban 方法论）、跨部门协作、远程办公场景里最常见的协作工具形态，Trello、Jira、禅道、Teambition 都是这个模型。作为实战项目，它把 REST 接口、WebSocket 实时推送、RBAC 权限控制、乐观锁并发控制、操作历史审计这几个后端高频主题全部串了起来，是「协作类系统」的最佳学习载体。

业务痛点：

```text
1. 任务靠口头和微信群传达：安排出去的任务没有记录，跟进全靠问，漏任务家常便饭
2. Excel 管任务：多人同时编辑互相覆盖，状态更新不及时，永远不知道最新进度
3. 状态不透明：任务卡在谁手里、卡了多久没人知道，管理者只能挨个问
4. 协作信息不同步：远程/跨部门团队各看各的，A 改完 B 看不到，信息孤岛
5. 并发编辑覆盖：两个人同时改同一张卡片，后保存的默默覆盖先保存的内容
6. 权限混乱：任何人都能改任何项目，成员误删、误改后无从追溯
```

目标用户与核心诉求：

```text
1. 研发团队：Sprint 迭代任务管理，拖拽流转状态，进度一目了然
2. 产品/运营：需求池、排期、上线跟进，跨角色协作
3. 项目经理/管理者：全局看进度、看阻塞、看人效，操作历史可审计
```

项目要解决的核心问题一句话概括：把任务变成看得见、拖得动、改得清（有历史）、抢不坏（并发安全）的看板卡片，并且让所有协作者实时看到同一个状态。

## 功能介绍

功能按角色与模块拆分：工作台（个人视角）、看板视图（团队协作）、卡片详情（任务本体）、成员协作、权限管理、系统能力。

```text
一、工作台（个人视角）
1. 我的任务 —— 分配给我的、我创建的、我关注的卡片聚合列表
2. 我的看板 —— 我参与的所有项目与看板入口
3. 最近动态 —— 我关注卡片的操作历史时间线

二、看板视图（团队协作核心）
1. 项目/看板管理 —— 创建项目，项目下建看板，看板内建列表
2. 三级模型 —— 看板（Board）-> 列表（List）-> 卡片（Card）
3. 拖拽移动 —— 卡片跨列表拖拽（状态流转）、列表内拖拽（排序）
4. 筛选过滤 —— 按分配人/优先级/截止日期过滤卡片
5. 实时同步 —— 他人操作通过 WebSocket 实时刷新到所有在线端

三、卡片详情（任务本体）
1. 卡片信息 —— 标题、描述（Markdown）、优先级、截止日期
2. 分配人 —— 指定负责人，变更时通知被分配人
3. 关注人 —— 关注卡片动态，评论/移动/完成时收到通知
4. 评论 —— 卡片内讨论，@ 成员可触发通知
5. 附件 —— 上传图片/文档（本地磁盘或 MinIO）

四、权限管理（RBAC）
1. 项目成员 —— 成员与角色管理：项目管理员/成员/访客
2. 操作权限 —— 访客只读、成员可编辑卡片、管理员可管理项目与成员
3. 权限校验 —— 后端 Service 层统一校验，前端隐藏入口

五、系统能力
1. 操作历史 —— 创建/移动/分配/评论等关键操作全量留痕
2. 实时通知 —— 卡片被分配、被评论、被移动时推送站内消息
3. 操作冲突提示 —— 乐观锁冲突时友好提示刷新重试
```

## 技术选型

| 组件 | 选型 | 理由 |
|------|------|------|
| 开发框架 | Spring Boot 2.7/3.x | 生态成熟，WebSocket 与 Security 集成完善 |
| 持久层 | MyBatis-Plus | 项目/看板/卡片标准 CRUD，复杂聚合查询走 XML |
| 数据库 | MySQL 8.0 | 业务数据落库，事务保证拖拽移动的原子性 |
| 实时通信 | Spring WebSocket + STOMP | 原生集成，支持主题订阅与点对点推送，SockJS 降级 |
| 鉴权授权 | Spring Security + JWT | 无状态认证 + RBAC 角色权限模型 |
| 缓存 | Redis | 在线状态、WebSocket 会话管理、推送幂等去重 |
| 前端 | Vue 3 + Element Plus + vuedraggable | 看板 UI 与拖拽交互，前后端分离 |
| 构建 | Maven | 依赖管理标准工具 |

选型说明：

```text
1. WebSocket 选 STOMP 协议而非裸 WebSocket：天然支持 /topic 广播、/queue 点对点、订阅管理
2. RBAC 用「项目成员表 + 角色字段」实现：角色粒度在项目级，比全局角色更贴合协作场景
3. 并发控制用乐观锁（version 字段）而非悲观锁：拖拽操作高频、冲突概率低，乐观锁成本更小
4. 权限校验下沉到 Service 层而非只做前端隐藏：任何接口都可被绕过，后端校验才是安全底线
```

## 架构设计

系统分层与请求链路：

```text
┌───────────────────────────────────────────────────────────┐
│                      客户端（浏览器）                        │
│   看板视图（Vue3 + vuedraggable）     WebSocket 实时连接      │
└───────────────┬──────────────────────────────┬────────────┘
                │ REST / JSON                   │ WS (STOMP)
┌───────────────▼──────────────────────────────▼────────────┐
│                    Spring Boot 应用层                       │
│  ┌────────────┐ ┌────────────┐ ┌────────────┐ ┌─────────┐ │
│  │ 看板 Controller │ │ 卡片 Service │ │ 权限 Service │ │ 推送服务  │ │
│  └────────────┘ └────────────┘ └────────────┘ └─────────┘ │
│  ┌────────────┐ ┌────────────┐ ┌───────────────────────┐  │
│  │ 操作历史 AOP │ │ WebSocket Handler │ │ 乐观锁/状态机/排序算法  │  │
│  └────────────┘ └────────────┘ └───────────────────────┘  │
└───────┬──────────────────────────────┬───────────────────┘
        │                              │
┌───────▼──────────┐         ┌─────────▼──────────┐
│      MySQL       │         │       Redis        │
│ 项目/看板/列表/卡片│         │ 在线状态/会话管理    │
│ 评论/附件/操作历史│         │ 推送幂等去重         │
└──────────────────┘         └─────────────────────┘
```

请求链路示例（卡片拖拽移动）：

```text
1. 用户在 A 列表把卡片拖到 B 列表第 3 个位置
2. vuedraggable 触发 drop 事件，前端 PUT /api/cards/{id}/move
3. Controller -> CardDragService.moveCard，先校验目标列表归属同一看板
4. 乐观锁更新：UPDATE card SET list_id=?, position=? WHERE id=? AND version=?
5. 更新失败（version 不匹配）：返回 409 冲突，前端提示「卡片已被他人修改」
6. 更新成功：同列表内顺移被挤开的卡片 position
7. 事务提交后：记录操作历史 + WebSocket 广播 CARD_MOVED 事件
8. 其他在线成员收到推送，前端本地更新卡片位置，无需刷新页面
```

WebSocket 实时推送链路：

```text
1. 前端连接 ws://host/ws?token=xxx（浏览器 WebSocket 不能自定义 header，token 走 query）
2. 握手拦截器解析 JWT，校验通过后把用户信息放入会话属性
3. 客户端订阅 /topic/project/{projectId}，加入项目实时频道
4. 任意成员操作卡片后，服务端 convertAndSend 广播到该主题
5. 消息带 eventId（UUID），客户端按 eventId 去重，防止重复渲染
6. 连接断开：前端监听 onclose 自动重连，重连成功后全量拉取看板数据兜底
```

设计要点：

```text
1. card 冗余 project_id/board_id：跨项目操作校验与 WebSocket 推送定位都不用回查列表表
2. 卡片没有 status 字段：状态由「所在列表」决定，拖拽移动列表即状态流转，天然形成状态机
3. version 乐观锁字段是所有更新操作的并发防线：拖拽、编辑、分配都带 version 条件更新
4. 列表 position 与卡片 position 分别排序：列内排序互不干扰，拖拽算法只处理目标列表
```

## 核心实现

### 1. 看板三级数据聚合查询

打开看板页需要一次加载「看板 -> 列表 -> 卡片」三级树，用 SQL 联查后在内存组装，避免 N+1 查询。

```java
package com.example.kanban.service;

/**
 * 看板查询：一次聚合三级模型数据
 */
@Service
public class BoardQueryService {

    @Autowired
    private BoardMapper boardMapper;
    @Autowired
    private BoardListMapper listMapper;
    @Autowired
    private CardMapper cardMapper;
    @Autowired
    private CardWatcherMapper watcherMapper;

    /**
     * 加载整个看板：board -> lists -> cards 三级树
     */
    public BoardVO loadBoard(Long boardId, Long currentUserId) {
        Board board = boardMapper.selectById(boardId);
        if (board == null) {
            throw new BizException("看板不存在");
        }
        BoardVO vo = new BoardVO();
        vo.setId(board.getId());
        vo.setName(board.getName());
        // 1. 查该看板下所有列表，按 position 排序（从左到右）
        List<BoardList> lists = listMapper.selectByBoardIdOrderByPosition(boardId);
        for (BoardList list : lists) {
            ListVO listVO = new ListVO();
            listVO.setId(list.getId());
            listVO.setName(list.getName());
            // 2. 查列表下所有卡片，按 position 排序（从上到下）
            List<Card> cards = cardMapper.selectByListIdOrderByPosition(list.getId());
            // 3. 组装展示 VO：分配人昵称、关注人列表、评论数
            listVO.setCards(buildCardVOs(cards, currentUserId));
            vo.getLists().add(listVO);
        }
        return vo;
    }

    /**
     * 卡片展示信息组装：分配人 + 是否被当前用户关注 + 评论数
     */
    private List<CardVO> buildCardVOs(List<Card> cards, Long currentUserId) {
        List<CardVO> result = new ArrayList<>();
        for (Card card : cards) {
            CardVO cv = new CardVO();
            cv.setId(card.getId());
            cv.setTitle(card.getTitle());
            cv.setPriority(card.getPriority());
            cv.setDueDate(card.getDueDate());
            cv.setPosition(card.getPosition());
            cv.setVersion(card.getVersion());
            cv.setAssigneeId(card.getAssigneeId());
            // 关注标记：当前用户是否关注了这张卡片
            cv.setWatched(watcherMapper.exists(card.getId(), currentUserId) != null);
            cv.setCommentCount(commentMapper.countByCardId(card.getId()));
            result.add(cv);
        }
        return result;
    }
}
```

### 2. 卡片拖拽移动：状态机 + 乐观锁

拖拽是本系统的核心难点：卡片状态由所在列表决定，跨列表拖拽就是状态流转；同列表拖拽是排序调整。并发场景下必须用乐观锁防止两个用户同时拖同一张卡片互相覆盖。

```java
package com.example.kanban.service;

/**
 * 卡片拖拽：状态流转 + 乐观锁防并发覆盖
 */
@Service
public class CardDragService {

    @Autowired
    private CardMapper cardMapper;
    @Autowired
    private BoardListMapper listMapper;
    @Autowired
    private ProjectNotifyService notifyService;
    @Autowired
    private OperationLogService logService;

    /**
     * 移动卡片：可跨列表（状态流转），也可同列表内排序
     * 状态机规则：卡片状态 = 所在列表，移动即状态变更
     */
    @Transactional
    public void moveCard(MoveCardRequest req, Long operatorId) {
        // 1. 校验目标列表存在，且与卡片当前列表属于同一看板
        BoardList targetList = listMapper.selectById(req.getTargetListId());
        if (targetList == null) {
            throw new BizException("目标列表不存在");
        }
        Card card = cardMapper.selectById(req.getCardId());
        if (card == null) {
            throw new BizException("卡片不存在");
        }
        if (!card.getBoardId().equals(targetList.getBoardId())) {
            throw new BizException("不能跨看板移动卡片");
        }
        // 2. 乐观锁更新：version 不匹配说明已被他人修改
        int rows = cardMapper.updateListAndPosition(
                card.getId(), req.getTargetListId(), req.getTargetPosition(), card.getVersion());
        if (rows == 0) {
            // 返回 409，前端提示冲突并刷新
            throw new BizException("卡片已被他人修改，请刷新后重试", 409);
        }
        // 3. 源列表重排：把被移走卡片后面的卡片 position 前移补位
        if (!card.getListId().equals(req.getTargetListId())) {
            listMapper.compactPositions(card.getListId(), card.getPosition());
        }
        // 4. 目标列表顺移：给新卡片腾出位置（同列表拖拽时也要处理）
        shiftTargetList(req.getTargetListId(), req.getTargetPosition(), card.getId());
        // 5. 记录操作历史
        logService.record("MOVE_CARD", card.getProjectId(), card.getId(),
                operatorId, card.getListId() + " -> " + req.getTargetListId());
        // 6. WebSocket 广播给项目内所有在线成员
        notifyService.notifyProject(card.getProjectId(), "CARD_MOVED",
                Map.of("cardId", card.getId(), "targetListId", req.getTargetListId(),
                        "position", req.getTargetPosition(), "version", card.getVersion() + 1));
    }

    /**
     * 目标列表顺移：position >= 目标位置的卡片全部 +1
     * 保证插入位置不被占用，排序不重叠
     */
    private void shiftTargetList(Long listId, int position, Long exceptCardId) {
        cardMapper.shiftPositions(listId, position, exceptCardId);
    }
}
```

对应 Mapper 的乐观锁 SQL：

```sql
-- 乐观锁更新：version 必须匹配，更新成功后 version + 1
UPDATE card
SET list_id = #{targetListId}, position = #{targetPosition}, version = version + 1
WHERE id = #{cardId} AND version = #{version}

-- 目标列表顺移：把 position >= 目标位置的卡片往后挪一位
UPDATE card
SET position = position + 1
WHERE list_id = #{listId} AND position >= #{position} AND id != #{exceptCardId}
```

```java
package com.example.kanban.config;

/**
 * 握手拦截器：从 query 参数解析 JWT，校验通过才放行连接
 */
@Component
public class JwtChannelInterceptor implements ChannelInterceptor {

    @Autowired
    private JwtUtil jwtUtil;

    @Override
    public Message<?> preSend(Message<?> message, MessageChannel channel) {
        StompHeaderAccessor accessor = MessageHeaderAccessor
                .getAccessor(message, StompHeaderAccessor.class);
        // 只在 CONNECT 阶段做认证
        if (accessor != null && StompCommand.CONNECT.equals(accessor.getCommand())) {
            // 浏览器 WebSocket 不能自定义 header，token 放在 query 参数里
            String token = accessor.getFirstNativeHeader("token");
            Long userId = jwtUtil.parseUserId(token);
            if (userId == null) {
                throw new MessageDeliveryException("WebSocket 认证失败");
            }
            // 用户信息放入会话，后续消息处理可读取
            accessor.setUser(new StompPrincipal(userId));
        }
        return message;
    }
}
```

### 4. RBAC 权限校验

角色模型：项目管理员（管项目与成员）> 成员（编辑卡片）> 访客（只读）。所有写操作在 Service 层统一走权限校验，防止绕过前端直接调接口。

```java
package com.example.kanban.security;

/**
 * 项目权限服务：项目级 RBAC 校验
 */
@Service
public class PermissionService {

    // 角色常量：数值越小权限越高
    public static final int ROLE_ADMIN = 1;
    public static final int ROLE_MEMBER = 2;
    public static final int ROLE_GUEST = 3;

    @Autowired
    private ProjectMemberMapper memberMapper;
    @Autowired
    private CardMapper cardMapper;

    /**
     * 校验用户对项目的角色是否满足最低要求
     * minRole 传 ROLE_MEMBER 表示至少是成员
     */
    public void checkProjectRole(Long projectId, Long userId, int minRole) {
        ProjectMember member = memberMapper.selectByProjectAndUser(projectId, userId);
        if (member == null) {
            throw new BizException("你不是该项目成员", 403);
        }
        if (member.getRole() > minRole) {
            throw new BizException("权限不足", 403);
        }
    }

    /**
     * 校验用户对卡片的操作权限
     * 先定位卡片所属项目，再走项目角色校验，防止跨项目操作
     */
    public void checkCardPermission(Long cardId, Long userId, int minRole) {
        Card card = cardMapper.selectById(cardId);
        if (card == null) {
            throw new BizException("卡片不存在");
        }
        checkProjectRole(card.getProjectId(), userId, minRole);
    }

    /**
     * 访客能否读某张卡片
     */
    public void checkCardReadable(Long cardId, Long userId) {
        checkCardPermission(cardId, userId, ROLE_GUEST);
    }
}
```

```java
     * 创建卡片：默认插入列表末尾

        notifyService.notifyProject(req.getProjectId(), "CARD_CREATED", card.getId());

    }

     * 分配负责人：变更后通知被分配人
     */
    public void assign(Long cardId, Long assigneeId, Long operatorId) {
        Card card = cardMapper.selectById(cardId);
        if (card == null) {
            throw new BizException("卡片不存在");
        }
        cardMapper.updateAssignee(cardId, assigneeId);
        logService.record("ASSIGN", card.getProjectId(), cardId,
                operatorId, "分配给了用户 " + assigneeId);
        // 点对点通知被分配人
        notifyService.notifyMember(assigneeId, "CARD_ASSIGNED",
                Map.of("cardId", cardId, "title", card.getTitle()));
    }

    /**
     * 关注/取消关注卡片
     * insertIgnore：唯一键 (card_id, user_id) 兜底，重复关注自动忽略
     */
    public void watch(Long cardId, Long userId, boolean watch) {
        if (watch) {
            watcherMapper.insertIgnore(cardId, userId);
        } else {
            watcherMapper.deleteByCardAndUser(cardId, userId);
        }
    }
}
```

### 7. 操作历史：AOP 统一记录

操作历史不能靠每个业务方法手动写日志（容易漏），用 AOP 统一拦截带注解的方法自动落库。

```java
package com.example.kanban.log;

/**
 * 操作历史注解：标注的方法执行成功后自动记录
 */
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
public @interface LogOperation {
    // 动作类型：CREATE/MOVE/ASSIGN/COMMENT/UPDATE
    String value();
}
```

```java
package com.example.kanban.log;

/**
 * 操作历史切面：方法成功返回后异步落库
 */
@Aspect
@Component
public class OperationLogAspect {

    @Autowired
    private OperationLogMapper logMapper;

    @AfterReturning("@annotation(logOperation)")
    public void afterSuccess(JoinPoint joinPoint, LogOperation logOperation) {
        MethodSignature signature = (MethodSignature) joinPoint.getSignature();
        Object[] args = joinPoint.getArgs();
        OperationLog log = new OperationLog();
        log.setAction(logOperation.value());
        log.setOperatorId(OperatorContext.getUserId());
        // 约定：方法参数里第一个 Long 是 projectId（简化示例）
        for (Object arg : args) {
            if (arg instanceof Long projectId) {
                log.setProjectId(projectId);
                break;
            }
        }
        log.setDetail(buildDetail(signature.getName(), args));
        // 异步落库，不阻塞业务
        CompletableFuture.runAsync(() -> logMapper.insert(log));
    }

    private String buildDetail(String methodName, Object[] args) {
        // 生产环境可用 JSON 序列化参数，这里简化展示
        return methodName + " 参数个数: " + args.length;
    }
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. 卡片排序用 position 整数 + 「插入时顺移」算法：新卡片 position 设为目标位置，被挤开的卡片统一 +1，保证排序不重叠
2. 乐观锁（version 字段）是并发协作的底线：所有更新 SQL 都带 version 条件，冲突返回 409 让前端刷新重试
3. WebSocket 消息必须带 eventId：客户端按 eventId 去重，防止重连/重复推送导致重复渲染
4. 断线重连 + 全量拉取兜底：WebSocket 推送可能丢失，重连成功后必须重新拉取看板全量数据
5. 权限校验下沉 Service 层：前端隐藏按钮只是体验优化，后端统一校验才是安全底线
6. 操作历史异步落库：不阻塞业务主流程，用 AOP 统一记录避免漏记
7. 创建看板时初始化默认列表（待办/进行中/完成），减少用户上手成本

### 踩坑记录

```text
坑 1：并发拖拽互相覆盖
结论：两个用户同时拖同一张卡片，后保存的覆盖先保存的，任务状态丢失。
原因：UPDATE 不带版本条件，最后一次写入直接覆盖。
解法：card 表加 version 字段，UPDATE ... WHERE version = ?；影响行数为 0 时返回 409，前端提示刷新。

坑 2：WebSocket 推送丢失导致状态不一致
结论：成员 A 断线期间别人拖了卡片，A 重连后看到的还是旧状态。
原因：WebSocket 消息是瞬时的，连接断开期间的消息不会补发。
解法：前端监听 onclose 自动重连，重连成功后调用全量拉取接口；关键操作以全量数据为准。

坑 3：position 冲突导致排序错乱
结论：多张卡片 position 相同，拖拽后列表顺序随机跳动。
原因：插入新位置时没有顺移后面的卡片，position 重叠后 ORDER BY position 不稳定。
解法：插入时把目标位置及之后的卡片 position +1（UPDATE ... SET position = position + 1 WHERE position >= ?），保证 position 全局唯一。

坑 4：越权访问
结论：普通成员通过拼接口地址能修改别的项目的卡片。
原因：只在前端做了权限控制，后端接口没有校验项目归属与角色。
解法：所有写操作在 Service 层调用 PermissionService.checkCardPermission，先定位卡片项目再校验角色；card 冗余 project_id 便于校验。

坑 5：广播风暴
结论：项目成员很多时，全项目广播所有事件，无关注关系的人也收到大量推送。
原因：所有事件都走 /topic/project/{id} 全局广播。
解法：区分事件类型：列表级变化（拖拽、新建）走项目广播；个人级事件（被分配、被评论、被关注）走 /queue/user/{id} 点对点推送。

坑 6：JWT 在 WebSocket 握手时取不到
结论：前端 SockJS 连接 ws 时报认证失败。
原因：浏览器 WebSocket 握手不能自定义 header，Authorization header 丢失。
解法：token 放在连接 URL 的 query 参数（ws://host/ws?token=xxx），在 ChannelInterceptor 的 CONNECT 阶段从 native header 或 query 中解析校验。
```

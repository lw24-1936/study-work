## 项目背景

可视化流程编排引擎（Visual Workflow Orchestration Engine）解决的问题是：把「多个服务按步骤串联、条件分支、定时/事件触发、失败重试」这类胶水逻辑从业务代码中抽离出来，用 JSON 定义流程、用拖拽设计器可视化编辑、用统一的执行引擎驱动。业务系统里大量存在这类「流程」：订单超时未支付要自动关闭并退款、审批通过后要调用结算/通知/归档多个下游系统、对账异常要进入人工复核分支。这些流程如果写死在代码里，每次改动都要发版，流程走到哪一步、失败在哪一步完全不可见。注意本引擎是轻量自研方案：流程用 JSON 定义 + 自研执行器，只支持 DAG（有向无环图）与有限的节点类型，不引入 Flowable 这类完整 BPMN 规范的重型引擎——没有 BPMN 文件解析、没有泳道/消息/补偿等重型概念，适合内部服务编排场景，几十行配置就能跑通一条链路。

业务痛点：

```text
1. 流程逻辑散落代码：订单超时关闭、审批后多系统同步等逻辑写死在业务方法里，改动一次发版一次
2. 串行步骤耦合深：一条链路 5-10 个步骤（查库存→扣库存→发消息→记账），代码层层嵌套难维护
3. 不可视化：流程长什么样只有研发知道，业务与运维完全无法参与理解
4. 无执行记录：跑到哪一步、失败在哪一步没有日志，出问题只能翻代码打点
5. 触发方式单一：定时/事件驱动的批量操作只能靠写死 @Scheduled 或硬编码回调，无法配置化
6. 编排能力无法复用：每个项目都重复实现一遍「串服务、做分支、带重试」的样板代码
```

目标用户与核心诉求：

```text
1. 后端研发：用 JSON + 设计器定义流程，把「串联多个服务」的胶水代码从业务代码中抽离，新流程不改代码即可上线
2. 业务运维：查看流程实例执行状态、节点日志，对失败节点手动重试，无需研发介入
3. 架构师：统一编排层，沉淀跨系统调用规范（超时/重试/幂等/日志），形成团队级的服务编排标准
```

项目要解决的核心问题一句话概括：把「多个服务按 DAG 串联 + 条件分支 + 定时/事件触发 + 执行日志与重试」封装成轻量自研编排引擎，流程用 JSON 定义、设计器可视化编辑、执行引擎统一驱动，流程的修改与运维不再依赖发版。

## 功能介绍

功能按角色与模块拆分：流程设计器（配置端）、触发机制（入口端）、执行引擎（运行时）、日志与运维（治理端）。

```text
一、流程设计器（配置端，研发与业务使用）
1. 节点拖拽 —— 从节点面板拖入画布：开始/任务/条件判断/延时/HTTP 调用/子流程/结束
2. 连线绘制 —— 从节点出端口拖到另一节点入端口生成连线，可配置条件表达式
3. 节点配置 —— 选中节点配置参数：任务节点配执行处理器（Spring Bean 名）、HTTP 节点配 URL/方法/超时/重试次数、延时节点配时长、子流程节点配子流程编码
4. 条件编辑 —— 连线条件用 DSL 表达式（amount > 1000 && status == 'APPROVED'），预览求值结果
5. 校验与发布 —— 保存时校验 DAG 合法性（无环、单起点、单终点、节点类型白名单、条件表达式可编译），发布生成新版本

二、触发机制（入口端）
1. 手动触发 —— 运维/研发在页面或通过 API 手动发起一次执行（带业务参数与 bizKey）
2. 定时触发 —— 流程配置 cron 表达式（如 0 0 2 * * ? 每天凌晨 2 点），到点自动发起
3. 事件触发 —— 业务系统发布事件（订单支付成功/退款完成），订阅该事件的流程自动执行

三、执行引擎（运行时）
1. 串行执行 —— 单入单出节点按拓扑顺序逐个推进
2. 并行分支 —— 一个节点多条无条件出边时，多个分支并行执行，全部完成后再向后推进（汇合）
3. 条件分支 —— 出边带条件表达式，满足条件的分支才执行，互斥条件走单一分支
4. 节点执行器 —— 开始/任务/条件/延时/HTTP/子流程/结束各类节点执行器，策略模式注册
5. 幂等与重试 —— 实例按 bizKey 幂等（同一业务键只执行一次），节点失败按配置自动重试（指数退避）

四、执行日志与运维（治理端）
1. 实例列表 —— 流程实例执行状态（运行中/成功/失败/终止）、触发方式、耗时
2. 节点日志 —— 每个节点的输入输出、错误信息、重试次数，可下钻查看
3. 手动重试 —— 失败实例一键重试，从失败节点续跑（不重复执行已成功的节点）
4. 版本管理 —— 历史版本列表、版本差异对比、回滚到历史版本
```

## 技术选型

| 组件 | 选型 | 理由 |
|------|------|------|
| 开发框架 | Spring Boot 2.7/3.x | 生态成熟，快速搭建 |
| 持久层 | MyBatis-Plus | 单表 CRUD 零 SQL，复杂查询走 XML |
| 数据库 | MySQL 8.0 | 流程定义/实例/节点记录/日志 |
| 缓存 | Redis | 实例互斥锁、事件去重、定时防重 |
| 表达式引擎 | SpEL（Spring 自带） | 条件表达式求值，无需引入第三方 |
| 流程定义 | JSON（自研 DSL） | nodes + edges 即可表达 DAG，易读易生成 |
| 定时调度 | Spring @Scheduled + 数据库轮询 | 流程定义量级几千以内够用，轻量无依赖 |
| 事件触发 | RabbitMQ / Kafka | 事件生产方与流程解耦，失败可重投 |
| 前端 | Vue 3 + Element Plus + 自研画布 | 拖拽设计器与运维面板 |
| 构建 | Maven | 依赖管理标准工具 |

选型说明：

```text
1. 流程定义用 JSON 而非 BPMN：轻量引擎只关心「节点 + 连线 + 条件」三个要素，BPMN 的泳道、消息、补偿等重型概念用不到，JSON 直接可读、可由设计器生成、可做版本 diff
2. 条件表达式用 SpEL：Spring 自带，支持比较/逻辑/括号/变量引用，用白名单模式（只允许访问上下文 Map），避免引入第三方表达式引擎的维护成本与安全风险
3. 定时触发用数据库轮询 + cron 解析：每秒扫一次 flow_def 中 trigger_type=cron 且到点的流程，配合 Redis 锁防重复触发，几千个流程定义量级完全够用，不引入调度中心
4. 事件触发走 MQ：事件生产方只发消息，引擎消费后匹配订阅的流程创建实例，消费失败可重投，配合事件唯一 id 幂等
5. 自研执行器策略模式：每个节点类型一个执行器类（NodeExecutor 接口），通过 Map<type, executor> 注册，扩展新节点类型只需新增一个执行器类，不触碰引擎核心
```

一次手动触发的完整链路：

```text
1. 运维在页面选择流程「订单结算流程」，填入业务参数（orderNo、amount），点手动触发
2. 触发服务校验流程已发布，按 flow_code + bizKey 生成唯一实例，实例状态置为运行中
3. 执行引擎加载该流程版本 graph_json，解析出 DAG：开始 → 金额判断 → HTTP 调用结算 → 结束
4. 从开始节点出发执行：开始节点成功，沿无条件出边推进到「金额判断」条件节点
5. 条件节点求值：amount=1500，出边表达式 amount > 1000 命中，走「大额」分支到 HTTP 节点
6. HTTP 调用节点执行：调用下游结算系统返回 200，响应体写入节点输出并合并进上下文
7. 到达结束节点，实例状态置为成功，记录总耗时与各节点耗时
8. 若第 6 步超时：按配置自动重试 2 次（指数退避），仍失败则实例置失败并记录错误
9. 运维在运维端看到失败实例，点「重试」，引擎定位失败节点，从该节点续跑
```

Redis Key 设计：

```text
flow:instance:lock:{instanceNo}     实例执行互斥锁（SETNX，执行期间持锁，防止重复调度）
flow:event:dedup:{eventId}          事件去重标记（SETNX，TTL 24h，MQ 重投防重复建实例）
flow:cron:lock:{flowCode}           定时触发防重锁（同一周期只触发一次）
```

## 核心实现

### 1. 流程定义服务：保存、DAG 校验、发布与版本管理

```java
@Service
public class FlowDefService {

    @Autowired
    private FlowDefMapper flowDefMapper;
    @Autowired
    private FlowVersionMapper versionMapper;
    @Autowired
    private RedisTemplate<String, Object> redisTemplate;
    @Autowired
    private ObjectMapper objectMapper;

    /** 保存流程定义（草稿），保存前做 DAG 合法性校验 */
    @Transactional(rollbackFor = Exception.class)
    public Long saveFlow(FlowDef flow) {
        validateGraph(flow.getGraphJson());
        if (flow.getId() == null) {
            flow.setVersion(1);
            flow.setStatus(0);
            flowDefMapper.insert(flow);
        } else {
            FlowDef old = flowDefMapper.selectById(flow.getId());
            flow.setVersion(old.getVersion() + 1);
            flow.setStatus(0);   // 编辑后置回草稿，需重新发布
            flowDefMapper.updateById(flow);
        }
        return flow.getId();
    }

    /** 发布：写入版本快照表，更新定义状态与缓存 */
    @Transactional(rollbackFor = Exception.class)
    public Long publish(Long flowId, String operator, String remark) {
        FlowDef flow = flowDefMapper.selectById(flowId);
        if (flow == null) {
            throw new BizException("流程不存在");
        }
        validateGraph(flow.getGraphJson());
        int newVersion = flow.getVersion() + 1;
        flow.setVersion(newVersion);
        flow.setStatus(1);
        flowDefMapper.updateById(flow);

        // 版本快照：历史可回滚
        FlowVersion v = new FlowVersion();
        v.setFlowId(flowId);
        v.setVersion(newVersion);
        v.setGraphJson(flow.getGraphJson());
        v.setRemark(remark);
        v.setOperator(operator);
        versionMapper.insert(v);

        // 写图定义缓存，执行引擎热加载
        redisTemplate.opsForValue().set(
                "flow:graph:" + flowId + ":" + newVersion,
                flow.getGraphJson(), 12, TimeUnit.HOURS);
        return newVersion;
    }

    /** DAG 校验：节点类型白名单、边引用存在、单起点单终点、无环（拓扑排序） */
    private void validateGraph(String graphJson) {
        try {
            JsonNode root = objectMapper.readTree(graphJson);
            Map<String, JsonNode> nodes = new HashMap<>();
            Set<String> types = Set.of("start", "task", "condition",
                    "delay", "http", "subflow", "end");
            for (JsonNode node : root.path("nodes")) {
                String id = node.path("id").asText();
                String type = node.path("type").asText();
                if (!types.contains(type)) {
                    throw new BizException("非法节点类型: " + type);
                }
                nodes.put(id, node);
            }
            if (!nodes.containsKey("start") || !nodes.containsKey("end")) {
                throw new BizException("流程必须包含开始与结束节点");
            }
            Map<String, List<String>> adj = new HashMap<>();
            Map<String, Integer> inDegree = new HashMap<>();
            nodes.keySet().forEach(n -> { adj.put(n, new ArrayList<>());
                                          inDegree.put(n, 0); });
            for (JsonNode edge : root.path("edges")) {
                String source = edge.path("source").asText();
                String target = edge.path("target").asText();
                if (!nodes.containsKey(source) || !nodes.containsKey(target)) {
                    throw new BizException("边引用了不存在的节点: " + source + "->" + target);
                }
                // 条件表达式预编译，写错在保存时暴露
                String expr = edge.path("expression").asText();
                if (!expr.isEmpty()) {
                    new SpelExpressionParser().parseExpression(expr);
                }
                adj.get(source).add(target);
                inDegree.merge(target, 1, Integer::sum);
            }
            // 拓扑排序判环
            Queue<String> queue = new LinkedList<>();
            inDegree.forEach((n, d) -> { if (d == 0) queue.offer(n); });
            int visited = 0;
            while (!queue.isEmpty()) {
                String n = queue.poll();
                visited++;
                for (String next : adj.get(n)) {
                    if (inDegree.merge(next, -1, Integer::sum) == 0) {
                        queue.offer(next);
                    }
                }
            }
            if (visited != nodes.size()) {
                throw new BizException("流程存在环，非法 DAG");
            }
        } catch (BizException e) {
            throw e;
        } catch (Exception e) {
            throw new BizException("图定义格式错误: " + e.getMessage());
        }
    }
}
```

### 3. 执行引擎：DAG 解析、条件分支与并行分支

```java
@Service
public class FlowEngineService {

    @Autowired
    private FlowInstanceMapper instanceMapper;
    @Autowired
    private FlowNodeInstMapper nodeInstMapper;
    @Autowired
    private FlowLogService logService;
    @Autowired
    private NodeExecutorRegistry executorRegistry;
    @Autowired
    private ConditionEvaluator conditionEvaluator;
    @Autowired
    private RedisTemplate<String, Object> redisTemplate;
    @Autowired
    private ObjectMapper objectMapper;

    // 实例级执行线程池（共享，串行节点自然串行，并行分支由池并发执行）
    private final ExecutorService pool = Executors.newFixedThreadPool(16);

    /** 执行一个流程实例：BFS 推进 + 入边满足计数，天然支持串行/并行/条件分支 */
    public void execute(Long instanceId) {
        FlowInstance inst = instanceMapper.selectById(instanceId);
        if (inst == null) {
            return;
        }
        // 实例互斥锁：防止同实例被重复调度（手动重试与定时撞车）
        Boolean locked = redisTemplate.opsForValue()
                .setIfAbsent("flow:instance:lock:" + inst.getInstanceNo(),
                        "1", 30, TimeUnit.MINUTES);
        if (!Boolean.TRUE.equals(locked)) {
            return;
        }
        Graph graph = parseGraph(loadGraph(inst.getFlowId(), inst.getFlowVersion()));
        Map<String, Object> context = new ConcurrentHashMap<>(parseParams(inst.getParamsJson()));

        // 每个节点的「已满足入边数」计数：全部入边满足才执行（并行汇合语义）
        Map<String, AtomicInteger> satisfied = new ConcurrentHashMap<>();
        AtomicReference<Throwable> failure = new AtomicReference<>();
        CountDownLatch done = new CountDownLatch(1);

        // 从开始节点发起
        runNode(graph, graph.getStartId(), inst, context, satisfied, failure, done);

        try {
            done.await(1, TimeUnit.HOURS);   // 单实例最长 1 小时
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
            failure.compareAndSet(null, new RuntimeException("执行被中断"));
        }

        if (failure.get() != null) {
            inst.setStatus(2);
            inst.setErrorMsg(failure.get().getMessage());
            logService.append(instanceId, null, "ERROR", "实例失败: " + failure.get().getMessage());
        } else {
            inst.setStatus(1);
            logService.append(instanceId, null, "INFO", "实例执行成功");
        }
        inst.setEndTime(new Date());
        instanceMapper.updateById(inst);
        redisTemplate.delete("flow:instance:lock:" + inst.getInstanceNo());
    }

    /** 执行单个节点：执行器运行 -> 输出入上下文 -> 激活满足条件的出边 */
    private void runNode(Graph graph, String nodeId, FlowInstance inst,
                         Map<String, Object> context,
                         Map<String, AtomicInteger> satisfied,
                         AtomicReference<Throwable> failure, CountDownLatch done) {
        GraphNode node = graph.getNode(nodeId);
        if ("end".equals(node.getType())) {
            logService.append(inst.getId(), nodeId, "INFO", "到达结束节点");
            done.countDown();
            return;
        }
        pool.submit(() -> {
            try {
                if (failure.get() != null) {
                    return;   // 已有节点失败，停止推进
                }
                // 记录节点执行实例（含重试，先查再插保持幂等）
                FlowNodeInst nodeInst = nodeInstMapper.selectByInstanceAndNode(
                        inst.getId(), nodeId);
                if (nodeInst == null) {
                    nodeInst = new FlowNodeInst();
                    nodeInst.setInstanceId(inst.getId());
                    nodeInst.setNodeId(nodeId);
                    nodeInst.setNodeName(node.getName());
                    nodeInst.setNodeType(node.getType());
                    nodeInst.setStatus(0);
                    nodeInstMapper.insert(nodeInst);
                }
                if (nodeInst.getStatus() == 1) {
                    // 已成功（重试续跑场景），直接向后激活
                    activateOutgoing(graph, node, inst, context, satisfied, failure, done);
                    return;
                }

                logService.append(inst.getId(), nodeId, "INFO", "开始执行: " + node.getName());
                nodeInst.setInputJson(toJson(context));
                Object output = executorRegistry.get(node.getType()).execute(node, context);
                nodeInst.setOutputJson(toJson(output));
                nodeInst.setStatus(1);
                nodeInst.setEndTime(new Date());
                nodeInstMapper.updateById(nodeInst);
                if (output != null) {
                    context.put(nodeId, output);   // 节点输出并入上下文，供后续节点/条件使用
                }
                logService.append(inst.getId(), nodeId, "INFO", "执行成功");
                activateOutgoing(graph, node, inst, context, satisfied, failure, done);
            } catch (Exception e) {
                failure.compareAndSet(null, e);
                logService.append(inst.getId(), nodeId, "ERROR", "执行失败: " + e.getMessage());
                done.countDown();
            }
        });
    }

    /** 激活出边：无条件边直接激活，条件边求值命中才激活；目标节点入边全满足才执行 */
    private void activateOutgoing(Graph graph, GraphNode node, FlowInstance inst,
                                  Map<String, Object> context,
                                  Map<String, AtomicInteger> satisfied,
                                  AtomicReference<Throwable> failure, CountDownLatch done) {
        for (GraphEdge edge : graph.getOutgoing(node.getId())) {
            boolean pass = edge.getExpression().isEmpty()
                    || conditionEvaluator.evaluate(edge.getExpression(), context);
            if (!pass) {
                continue;   // 条件不满足的分支跳过
            }
            AtomicInteger cnt = satisfied.computeIfAbsent(edge.getTarget(),
                    k -> new AtomicInteger(0));
            if (cnt.incrementAndGet() == graph.getInDegree(edge.getTarget())) {
                runNode(graph, edge.getTarget(), inst, context, satisfied, failure, done);
            }
        }
        // 没有可推进的出边且未结束：实例终止（分支无路可走）
        if (graph.getOutgoing(node.getId()).isEmpty() && !"end".equals(node.getType())
                && failure.get() == null) {
            failure.compareAndSet(null, new RuntimeException("流程无后继节点，终止执行"));
            done.countDown();
        }
    }

    // 图解析工具：Graph/GraphNode/GraphEdge 为内存模型（省略 getter）
    private Graph parseGraph(String graphJson) {
        try {
            JsonNode root = objectMapper.readTree(graphJson);
            return new Graph(root);
        } catch (Exception e) {
            throw new RuntimeException("图解析失败", e);
        }
    }

    private String loadGraph(Long flowId, Integer version) {
        Object cached = redisTemplate.opsForValue().get("flow:graph:" + flowId + ":" + version);
        if (cached != null) {
            return String.valueOf(cached);
        }
        return flowDefMapper.selectById(flowId).getGraphJson();
    }

    private Map<String, Object> parseParams(String json) {
        if (json == null || json.isEmpty()) {
            return new HashMap<>();
        }
        try {
            return objectMapper.readValue(json,
                    new TypeReference<Map<String, Object>>() {});
        } catch (Exception e) {
            return new HashMap<>();
        }
    }

    private String toJson(Object obj) {
        try {
            return objectMapper.writeValueAsString(obj);
        } catch (Exception e) {
            return null;
        }
    }
}
```

### 4. 条件表达式求值：SpEL 封装（白名单 + 缓存）

```java
@Component
public class ConditionEvaluator {

    // 编译后的表达式缓存（表达式数量有限，常驻内存）
    private final ConcurrentHashMap<String, Expression> cache = new ConcurrentHashMap<>();
    private final SpelExpressionParser parser = new SpelExpressionParser();

    /** 对上下文 Map 求值条件表达式，返回是否命中 */
    public boolean evaluate(String expression, Map<String, Object> context) {
        if (expression == null || expression.isBlank()) {
            return true;   // 空表达式 = 无条件通过
        }
        Expression exp = cache.computeIfAbsent(expression, parser::parseExpression);
        StandardEvaluationContext ctx = new StandardEvaluationContext();
        // 白名单：只允许访问上下文 Map，禁止反射/类型引用/bean 调用
        ctx.setVariables(context);
        Boolean result = exp.getValue(ctx, Boolean.class);
        return Boolean.TRUE.equals(result);
    }
}
```

```java
@Component
public class HttpNodeExecutor implements NodeExecutor {

    private final RestTemplate restTemplate;

    public HttpNodeExecutor() {
        SimpleClientHttpRequestFactory factory = new SimpleClientHttpRequestFactory();
        factory.setConnectTimeout(3000);
        factory.setReadTimeout(3000);
        this.restTemplate = new RestTemplate(factory);
    }

    @Override
    public String type() {
        return "http";
    }

    @Override
    public Object execute(GraphNode node, Map<String, Object> context) {
        String url = node.getConfig().getString("url");
        String method = node.getConfig().getString("method", "POST");
        String body = renderTemplate(node.getConfig().getString("body", "{}"), context);
        HttpHeaders headers = new HttpHeaders();
        headers.setContentType(MediaType.APPLICATION_JSON);
        // 幂等键：下游据此去重，重试不会产生重复副作用
        headers.set("X-Idempotency-Key",
                String.valueOf(context.get("__instanceNo")) + ":" + node.getId());
        HttpEntity<String> entity = new HttpEntity<>(body, headers);
        ResponseEntity<String> resp = "GET".equals(method)
                ? restTemplate.exchange(url, HttpMethod.GET, entity, String.class)
                : restTemplate.exchange(url, HttpMethod.POST, entity, String.class);
        if (!resp.getStatusCode().is2xxSuccessful()) {
            throw new RuntimeException("HTTP 调用失败: " + resp.getStatusCode());
        }
        return resp.getBody();
    }

    /** 简单模板渲染：${key} 从上下文取值替换 */
    private String renderTemplate(String template, Map<String, Object> context) {
        String result = template;
        for (Map.Entry<String, Object> entry : context.entrySet()) {
            result = result.replace("${" + entry.getKey() + "}",
                    String.valueOf(entry.getValue()));
        }
        return result;
    }
}
```

```java
@Service
public class FlowRetryService {

    @Autowired
    private FlowInstanceMapper instanceMapper;
    @Autowired
    private FlowNodeInstMapper nodeInstMapper;
    @Autowired
    private FlowEngineService engineService;
    @Autowired
    private FlowLogService logService;

    /**
     * 失败实例手动重试：引擎按「节点已成功则跳过」的规则从失败节点续跑
     * 已成功节点的 output 保留在实例表中，续跑不会产生重复副作用
     */
    public void retryInstance(Long instanceId) {
        FlowInstance inst = instanceMapper.selectById(instanceId);
        if (inst == null || inst.getStatus() != 2) {
            throw new BizException("仅失败实例可重试");
        }
        inst.setStatus(0);
        inst.setErrorMsg(null);
        inst.setStartTime(new Date());
        inst.setEndTime(null);
        instanceMapper.updateById(inst);
        logService.append(instanceId, null, "WARN", "触发手动重试");
        // 引擎重新执行：已成功节点 status=1 直接跳过并向后激活
        engineService.execute(instanceId);
    }

    /**
     * 单节点重试（带指数退避）：HTTP 5xx/超时等可重试错误自动调用
     * 由 HttpNodeExecutor 外层切面或引擎在节点失败时按 retryMax 调度
     */
    public void retryNodeWithBackoff(Long nodeInstId, int retryMax) {
        FlowNodeInst nodeInst = nodeInstMapper.selectById(nodeInstId);
        for (int i = 1; i <= retryMax; i++) {
            long backoff = (long) (Math.pow(2, i) * 500);   // 0.5s 1s 2s...
            try {
                Thread.sleep(backoff);
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
                return;
            }
            nodeInst.setRetryCount(i);
            nodeInst.setStatus(0);
            nodeInstMapper.updateById(nodeInst);
            logService.append(nodeInst.getInstanceId(), nodeInst.getNodeId(),
                    "WARN", "第 " + i + " 次重试");
            // 重试执行由引擎的续跑能力承载（status=0 的节点会被重新执行）
            engineService.execute(nodeInst.getInstanceId());
            FlowInstance inst = instanceMapper.selectById(nodeInst.getInstanceId());
            if (inst.getStatus() == 1) {
                return;   // 重试成功
            }
        }
    }
}
```

## 实际应用场景

### 场景一：订单超时未支付自动关闭

电商订单超过 30 分钟未支付要自动关闭并释放库存，用「定时触发 + 延时节点 + HTTP 调用」编排：

```text
1. 设计流程「订单超时处理」：开始 → 延时 30 分钟 → HTTP 调订单服务查状态 → 条件判断 → 结束
2. 配置定时触发：cron 0 0/1 * * * ? 每分钟扫描一次，bizKey 为「当前分钟 + 订单批次」
3. 流程入参带批次订单列表，延时节点等待 30 分钟后 HTTP 查询订单状态
4. 条件判断：status == 'UNPAID' 走「关闭订单」分支，否则走「已支付跳过」分支
5. 关闭订单分支 HTTP 调用订单服务关闭接口（带幂等键，重试不重复关闭）
6. 全部订单处理完到达结束节点，实例成功，日志记录处理数量
7. 若某订单关闭接口超时：自动重试 2 次，仍失败则该批次实例置失败，运维手动重试续跑
```

### 场景二：审批通过后的多系统数据同步

审批通过后要把数据同步到结算、CRM、归档三个系统，用「事件触发 + 并行分支」编排：

```text
1. 设计流程「审批通过同步」：开始 → 并行分支（结算同步 / CRM 同步 / 归档同步）→ 汇合 → 结束
2. 审批系统在审批通过时发事件 approve.passed（事件 id 为审批单号），流程订阅该事件
3. 事件消费后创建实例，三个分支并行执行（共享线程池），互不阻塞
4. 每个分支是独立的 HTTP 调用节点，带各自的超时与重试配置
5. 三个分支全部完成后汇合到结束节点，实例成功
6. 若 CRM 分支失败：其余分支已完成不重复执行，运维重试后引擎从 CRM 节点续跑
7. 事件重投时按事件 id 去重，不会生成第二个实例
```

### 场景三：日终对账异常处理

每日对账发现差异后进入人工复核流程，用「手动触发 + 条件分支 + 子流程」编排：

```text
1. 设计流程「对账差异处理」：开始 → 条件判断（差异金额）→ 小金额自动调账 / 大金额子流程复核
2. 对账任务发现差异后调用手动触发 API，bizKey 为对账批次号，入参含差异明细
3. 条件判断：amount <= 1000 走「自动调账」分支（HTTP 调用调账服务）
4. amount > 1000 走「子流程复核」分支：子流程为「人工复核流程」（延时 24 小时 + 定时提醒）
5. 子流程执行结果返回主流程，主流程记录复核结论后结束
6. 每次对账批次执行有独立实例与日志，财务可追溯每一步
7. 调账接口失败自动重试，重试仍失败则实例置失败，财务在运维端一键重试
```

## 最佳实践与踩坑记录

### 最佳实践

1. 发布即快照：执行永远读「发布时固化」的版本 graph_json，编辑中的草稿不影响线上执行，回滚只需切换版本号
2. DAG 校验前置：保存/发布时做拓扑排序判环、单起点单终点校验、节点类型白名单、边引用存在性、条件表达式预编译，坏图进不了库
3. 实例幂等三件套：flow_id + biz_key 唯一索引 + Redis 实例锁 + 事件 id 去重，定时触发与 MQ 重投都不会产生重复实例
4. 节点输入输出全落库：每个节点的 input_json / output_json 持久化，既是排查日志，也是重试续跑时「已成功节点跳过」的依据
5. 区分可重试与不可重试错误：HTTP 5xx、超时、网络异常可重试；业务校验失败（参数错、4xx）重试无意义，直接失败终止
6. HTTP 调用带幂等键：重试前给下游传 X-Idempotency-Key，下游去重，避免重试造成重复扣款/重复发券等副作用
7. 上下文只传可序列化数据：节点间传参统一 Map + JSON，禁止传对象引用，保证实例可重放、可迁移、可审计

### 踩坑记录

```text
坑 1：有环流程死循环
结论：设计器允许画回边，某流程执行到深夜都不结束，实例堆积。
原因：保存时没做无环校验，自环/回边导致引擎在环上无限推进。
解法：保存与发布前用拓扑排序判环，有环直接拒绝保存；执行引擎再加最大节点数保护（超过 100 节点强制终止）。

坑 2：发布后修改影响了线上执行
结论：线上实例跑到一半，图定义被后续编辑覆盖，执行错乱。
原因：执行时直接读 flow_def.graph_json 的「当前值」，没有版本快照。
解法：发布时把 graph_json 复制进 flow_version，执行引擎永远按实例上的 flow_version 加载对应版本。

坑 3：定时触发重复执行
结论：同一分钟同一流程被触发多次，产生多个重复实例。
原因：多个应用实例同时扫描 cron 流程，或调度器与手动触发撞车。
解法：Redis SETNX 防重锁（流程编码 + 分钟粒度）+ flow_id + biz_key 唯一索引兜底，重复插入直接抛异常丢弃。

坑 4：条件表达式写错静默走错分支
结论：amount <= 1000 的分支把大额订单也处理了，造成资损。
原因：表达式写错或变量名与上下文不一致，求值异常时返回了默认 true。
解法：求值异常必须抛错而非返回默认值；保存时预编译表达式；上线前用设计器「模拟运行」功能预览分支走向。

坑 5：重试导致下游重复扣款
结论：HTTP 调用超时但下游实际已成功，重试又扣了一次款。
原因：重试机制没有幂等设计，下游收到两次相同请求都正常处理了。
解法：每次 HTTP 调用带 X-Idempotency-Key（实例号 + 节点 id），下游按幂等键去重；同时明确「超时后重试」与「收到 5xx 重试」的语义区别。

坑 6：并行分支死等
结论：某并行分支的 HTTP 调用一直没有返回，实例卡在运行中。
原因：并行分支用线程池执行，等待逻辑没有超时，节点也没有超时配置。
解法：节点配置 timeoutMs（HTTP 读取超时）；引擎对单实例总执行时长设上限（1 小时），超时强制终止并告警。

坑 7：事件重复投递产生多个实例
结论：MQ 消费失败重投后，同一事件建了两个实例，重复执行。
原因：消费逻辑没有按事件 id 幂等。
解法：事件记录表（event_type + event_id 唯一索引）+ Redis SETNX 双保险，重复事件直接丢弃；已处理的事件在 flow_event 中可追溯。
```

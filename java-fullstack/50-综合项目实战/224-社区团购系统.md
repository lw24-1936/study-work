## 项目背景

社区团购系统（Community Group Buying System）是生鲜电商的重要形态：平台招募社区团长，团长在小区建立自提点，平台每日上架团购商品，居民在团长群里下单，达到成团条件（人数/时间）后统一采购发货，商品送到自提点由团长分发给用户。与传统电商「一单一发」不同，社区团购是「预售 + 集单」模式——先收单再采购，靠规模压低采购价。业务的核心是「成团判定」：订单先处于拼团中的冻结态，只有成团后才真正进入履约，未成团要自动退款。这个项目覆盖了拼团模型、库存预占、佣金分账、定时任务批量处理等机制，是理解「预售制交易 + 多方分账」的最佳实战项目。

业务痛点：

```text
1. 成团判定复杂：有人数成团也有时间截止，成团瞬间要把冻结订单批量转正式订单
2. 拼团与普通订单差异大：普通订单下单即履约，拼团订单要等成团，状态流转完全不同
3. 库存难管理：预售模式是预占库存，成团失败要回补库存，超卖与积压并存
4. 佣金分账易错：团长佣金、平台抽成、供应商货款三方分账，手动算必出错
5. 未成团退款慢：用户退款体验差，退款流程与库存回补、佣金撤销要联动
6. 统计口径混乱：成团率、GMV、佣金成本各说各话，财务对不上账
```

目标用户与核心诉求：

```text
1. 社区居民：下单后能看到成团进度，成团了按时取货，未成团自动退款到账
2. 团长：管理自提点与群用户，佣金规则透明，结算准时，数据看板清晰
3. 平台运营：配置每日团品与成团条件，监控各团成团率，及时补团或关团
4. 财务：分账自动化（团长佣金/平台抽成/供应商结算），账实相符可审计
```

项目要解决的核心问题一句话概括：让「开团 - 参团 - 成团/未成团 - 履约 - 分账」这条预售链路自动化运转，成团判定、库存回补、自动退款、佣金分账全部由系统按规则精确完成。

## 功能介绍

功能按角色与模块拆分：用户端（参团）、团长端（开团与自提点）、运营端（团品与活动）、交易核心（成团与订单）、结算中心（分账）。

```text
一、用户端（社区居民）
1. 浏览团购 —— 按小区/自提点查看当日团品，团品带拼团进度（已参团 X/满 Y 人）
2. 下单参团 —— 选择团品与数量，支付后订单进入「拼团中」冻结态
3. 成团进度 —— 实时查看所在团剩余名额与截止时间，成团后收到通知
4. 到店自提 —— 凭取货码到团长自提点取货，团长核销
5. 退款售后 —— 未成团自动退款，成团后支持售后申请（退款退货）

二、团长端（社区合伙人）
1. 入驻申请 —— 提交小区信息/身份资料，等待平台审核，审核通过建立自提点
2. 开团管理 —— 每天从平台选品开团，设置成团人数与截止时间
3. 自提点运营 —— 到货确认、核销取货码、处理用户售后
4. 佣金中心 —— 佣金明细（按订单/按商品类目），申请提现
5. 数据看板 —— 本团当日订单数、GMV、成团率、佣金预估

三、运营端（平台）
1. 团长审核 —— 入驻资质审核，团长等级与佣金比例配置
2. 团品管理 —— 每日团品上下架、售价/成本价/库存设置、限购规则
3. 活动管理 —— 创建团购活动（团品 + 成团人数 + 截止时间 + 起售时间）
4. 成团干预 —— 手动成团（临近截止差几人）、手动关团（商品质量问题）
5. 统计报表 —— 成团率、区域销售、团长业绩排行

四、交易核心（订单与成团）
1. 下单支付 —— 参团下单扣库存（预占），支付后订单冻结为拼团中
2. 成团判定 —— 人数达成即时成团；时间截止时按规则成团/解散
3. 订单拆分 —— 成团后按团长/自提点批量生成履约单与拣货单
4. 库存回补 —— 未成团订单释放预占库存，供后续参团使用
5. 自动退款 —— 未成团订单全额原路退回，退款状态可查

五、结算中心（分账）
1. 佣金计算 —— 按团长佣金比例 × 成团订单实付金额计算
2. 平台抽成 —— 平台服务费 = 实付金额 - 佣金 - 供应商货款
3. 分账流水 —— 每笔成团订单生成分账明细（用户/团长/平台/供应商四方）
4. 结算任务 —— 每日/每周批量生成结算单，团长可申请提现
```

## 技术选型

| 组件 | 选型 | 理由 |
|------|------|------|
| 开发框架 | Spring Boot 2.7/3.x | 生态成熟，快速搭建 |
| 持久层 | MyBatis-Plus | 单表 CRUD 零 SQL，分账统计走 XML |
| 数据库 | MySQL 8.0 | 团长/商品/活动/订单/分账等核心数据 |
| 缓存 | Redis（String/Hash/SETNX） | 库存预占、参团计数、防重复下单 |
| 分布式锁 | Redis SETNX | 成团判定并发控制、库存扣减原子性 |
| 定时任务 | Spring @Scheduled + XXL-Job | 成团截止扫描、未成团退款、结算生成 |
| 消息队列 | RabbitMQ（可选） | 成团事件通知、退款异步处理 |
| 支付 | 微信支付（JSAPI/小程序） | 参团支付、退款原路退回 |
| 前端 | Vue 3 + 小程序 | 用户端/团长端/运营端三端 |
| 构建 | Maven | 依赖管理标准工具 |

选型说明：

```text
1. 拼团计数与成团进度用 Redis：每个团一个计数 key（INCR），成团进度实时展示，避免每次查询都 COUNT 数据库
2. 库存预占用 Redis 原子扣减：参团先扣 Redis 库存（DECR 原子），成团后落库，未成团回补，防止并发超卖
3. 成团判定是「事件 + 定时」双通道：人数到齐即时成团（Redis 计数触发），时间截止兜底（定时任务扫描）
4. 拼团订单与普通订单共用订单主表：用 order_type 字段区分，拼团订单多一个「关联团活动」字段，避免两套订单体系
5. 分账用独立明细表：每笔成团订单写一条分账记录（四方金额），财务按明细对账，不做「事后汇总估算」
```

一次参团到成团履约的完整链路：

```text
1. 团长每晚 20:00 从平台选品开团：鸡蛋 30 枚装，成团 20 人，截止明晚 22:00
2. 用户在团页面看到进度（已参 8/20 人），下单 2 份并支付
3. 下单服务 DECR 预占库存，Redis 团计数 INCR 到 9，订单进入拼团中状态
4. 后续 11 人陆续参团，计数到 20 时触发成团事件
5. 成团服务加分布式锁，批量把该团所有拼团中订单置为已成团
6. 成团后按团长/自提点拆分生成拣货单，通知供应商备货
7. 次日凌晨商品送达自提点，团长确认到货，用户收到取货通知
8. 用户凭取货码到店取货，团长核销，订单状态变为已完成
9. 结算任务按成团订单计算分账：用户实付 - 团长佣金 - 供应商货款 = 平台抽成
10. 若明晚 22:00 未满 20 人：定时任务解散该团，全部订单自动原路退款，库存回补
```

Redis Key 设计：

```text
group:join:{activityId}         团参团人数计数（INCR，成团进度实时展示）
group:joined:{activityId}       已参团用户集合（SET，防同一用户刷参团计数）
stock:group:{activityId}        活动库存（DECR 预占，成团后扣正式库存）
group:status:{activityId}       团状态缓存（String：0进行中 1已成团 2解散，TTL 截止时间）
order:lock:{orderNo}            订单操作锁（SETNX，退款/核销防并发）
group:lock:{activityId}         成团判定锁（SETNX，防多实例重复成团）
settle:lock:{activityId}        结算锁（SETNX，防重复分账）
refund:retry:{refundNo}         退款重试计数（INCR，退款失败补偿）
```

```java
@Service
public class GroupService {

    @Autowired
    private GroupActivityMapper activityMapper;
    @Autowired
    private GroupGoodsMapper goodsMapper;
    @Autowired
    private StringRedisTemplate redisTemplate;

    /**
     * 团长开团：从团品库选品创建活动
     * 活动限量默认取团品库存的一部分，开团时锁定售价快照
     */
    @Transactional(rollbackFor = Exception.class)
    public Long createActivity(Long leaderId, Long goodsId, int targetCount,
                               int limitStock, LocalDateTime endTime) {
        // 1. 团长审核状态校验
        GroupLeader leader = leaderMapper.selectById(leaderId);
        if (leader == null || leader.getAuditStatus() != 1) {
            throw new BizException("团长未通过审核，无法开团");
        }
        // 2. 创建活动：售价/品名快照，防止团品改价影响历史团
        GroupGoods goods = goodsMapper.selectById(goodsId);
        GroupActivity activity = new GroupActivity();
        activity.setActivityNo("GA" + System.currentTimeMillis());
        activity.setLeaderId(leaderId);
        activity.setGoodsId(goodsId);
        activity.setGoodsName(goods.getGoodsName());
        activity.setSalePrice(goods.getSalePrice());
        activity.setTargetCount(targetCount);
        activity.setLimitStock(limitStock);
        activity.setStartTime(LocalDateTime.now());
        activity.setEndTime(endTime);
        activity.setStatus(0); // 进行中
        activityMapper.insert(activity);

        // 3. 活动库存写入 Redis（预占扣减用）
        redisTemplate.opsForValue()
                .set("stock:group:" + activity.getId(),
                        String.valueOf(limitStock), 7, TimeUnit.DAYS);
        return activity.getId();
    }

    /**
     * 用户参团：原子扣库存 + 计数 + 防重复参团
     * 返回该团最新参团人数
     */
    @Transactional(rollbackFor = Exception.class)
    public int join(Long userId, Long activityId, int quantity) {
        // 1. 防重复参团（同一用户同一团只计一次人头，可加购）
        String joinedKey = "group:joined:" + activityId;
        Boolean first = redisTemplate.opsForValue()
                .setIfAbsent(joinedKey + ":user:" + userId, "1", 7, TimeUnit.DAYS);
        if (Boolean.TRUE.equals(first)) {
            redisTemplate.opsForValue().increment("group:join:" + activityId);
        }
        // 2. 原子扣库存（DECR，负数即超卖，回滚）
        String stockKey = "stock:group:" + activityId;
        Long remain = redisTemplate.opsForValue().decrement(stockKey, quantity);
        if (remain == null || remain < 0) {
            redisTemplate.opsForValue().increment(stockKey, quantity); // 回补
            throw new BizException("库存不足");
        }
        // 3. 同步更新活动已售件数与参团人数（落库）
        activityMapper.incrSold(activityId, quantity);
        return activityMapper.incrJoined(activityId);
    }

    /** 查询成团进度：Redis 计数优先，DB 兜底 */
    public JoinProgress progress(Long activityId) {
        GroupActivity activity = activityMapper.selectById(activityId);
        String joined = redisTemplate.opsForValue().get("group:join:" + activityId);
        int joinedCount = joined == null
                ? activity.getJoinedCount() : Integer.parseInt(joined);
        return new JoinProgress(joinedCount, activity.getTargetCount(),
                activity.getEndTime());
    }
}
```

### 2. 成团判定服务：人数即时成团 + 时间截止兜底

```java
@Service
public class GroupSettleService {

    public static final int STATUS_ACTIVE = 0;     // 进行中
    public static final int STATUS_SUCCESS = 1;    // 已成团
    public static final int STATUS_FAILED = 2;     // 未成团解散
    public static final int STATUS_CLOSED = 3;     // 手动关闭

    @Autowired
    private GroupActivityMapper activityMapper;
    @Autowired
    private GroupOrderMapper orderMapper;
    @Autowired
    private StringRedisTemplate redisTemplate;

    /**
     * 成团判定统一入口（人数到齐时调用，定时任务截止时也调用）
     * 成团锁保证同一团只判定一次
     */
    public boolean judge(Long activityId) {
        // 成团锁：多实例/多通道并发判定时只允许一次生效
        String lockKey = "group:lock:" + activityId;
        Boolean locked = redisTemplate.opsForValue()
                .setIfAbsent(lockKey, "1", 60, TimeUnit.SECONDS);
        if (!Boolean.TRUE.equals(locked)) {
            return false; // 其他线程正在判定
        }
        try {
            GroupActivity activity = activityMapper.selectById(activityId);
            if (activity == null || activity.getStatus() != STATUS_ACTIVE) {
                return false; // 已判定过，幂等返回
            }
            // 1. 人数判定：参团人数 >= 成团人数
            int joined = getJoinedCount(activityId);
            boolean success = joined >= activity.getTargetCount();
            // 2. 时间判定：已过截止时间且差人数 <= 3 时可手动成团（此处简化为到点即成/即散）
            boolean expired = activity.getEndTime().isBefore(LocalDateTime.now());

            if (success || expired) {
                if (success) {
                    // 成团：批量更新该团所有拼团中订单
                    doSuccess(activity, joined);
                } else {
                    // 未成团：解散 + 自动退款 + 库存回补
                    doFail(activity, joined);
                }
                return true;
            }
            return false; // 未到人数也未到时间
        } finally {
            redisTemplate.delete(lockKey);
        }
    }

    /** 成团处理：订单批量转待发货 + 生成分账明细 */
    @Transactional(rollbackFor = Exception.class)
    public void doSuccess(GroupActivity activity, int joined) {
        // 1. 活动状态：进行中 -> 已成团
        activityMapper.casUpdateStatus(activity.getId(), STATUS_ACTIVE, STATUS_SUCCESS);
        // 2. 批量更新订单：拼团中 -> 已成团待发货（只更新仍处于拼团中的订单）
        orderMapper.batchUpdateByActivity(activity.getId(),
                OrderStatus.PENDING_GROUP, OrderStatus.GROUPED);
        // 3. 为每笔订单生成分账明细（佣金/成本/平台抽成）
        settlementService.generateDetails(activity.getId());
        // 4. 通知团长：可发起采购/备货
        notifyLeader(activity.getLeaderId(), "你的团已成功成团");
    }

    /** 未成团处理：解散 + 自动退款 + 库存回补 */
    @Transactional(rollbackFor = Exception.class)
    public void doFail(GroupActivity activity, int joined) {
        // 1. 活动状态：进行中 -> 未成团解散
        activityMapper.casUpdateStatus(activity.getId(), STATUS_ACTIVE, STATUS_FAILED);
        // 2. 该团所有拼团中订单：置为已退款，并发起自动退款
        List<GroupOrder> orders = orderMapper.selectByActivityAndStatus(
                activity.getId(), OrderStatus.PENDING_GROUP);
        for (GroupOrder order : orders) {
            refundService.autoRefund(order, "未成团自动退款");
        }
        // 3. 库存回补：活动库存剩余回补到团品总库存
        String stockKey = "stock:group:" + activity.getId();
        String remain = redisTemplate.opsForValue().get(stockKey);
        if (remain != null && Integer.parseInt(remain) > 0) {
            goodsMapper.incrStock(activity.getGoodsId(), Integer.parseInt(remain));
        }
        // 4. 通知用户：团未成团，款项原路退回
        notifyUsers(activity.getId(), "团购未成团，已自动退款");
    }

    /** 定时任务兜底：扫描截止时间已到但未判定的团 */
    @Scheduled(fixedDelay = 60_000)
    public void scanExpiredActivities() {
        List<GroupActivity> expired = activityMapper
                .selectExpiredActive(LocalDateTime.now());
        for (GroupActivity activity : expired) {
            judge(activity.getId());
        }
    }
}
```

```java
@Service
public class GroupOrderService {

    @Autowired
    private GroupService groupService;
    @Autowired
    private GroupOrderMapper orderMapper;
    @Autowired
    private StringRedisTemplate redisTemplate;

    /**
     * 参团下单：校验 -> 预占库存 -> 创建订单（拼团中）-> 发起支付
     * 与普通订单的核心差异：下单后不直接履约，等待成团
     */
    @Transactional(rollbackFor = Exception.class)
    public String placeGroupOrder(Long userId, Long activityId, int quantity) {
        // 1. 团活动状态校验（进行中 + 未截止）
        GroupActivity activity = activityMapper.selectById(activityId);
        if (activity == null || activity.getStatus() != 0) {
            throw new BizException("该团已结束");
        }
        if (activity.getEndTime().isBefore(LocalDateTime.now())) {
            throw new BizException("该团已截止");
        }
        // 2. 限购校验
        Integer bought = orderMapper.sumQuantityByUserAndActivity(userId, activityId);
        if (bought != null && bought + quantity > 5) {
            throw new BizException("超出限购数量");
        }
        // 3. 预占库存（Redis 原子扣减）
        groupService.join(userId, activityId, quantity);

        // 4. 创建订单：order_type=1 拼团订单，状态=拼团中
        GroupOrder order = new GroupOrder();
        order.setOrderNo(genOrderNo());
        order.setUserId(userId);
        order.setLeaderId(activity.getLeaderId());
        order.setActivityId(activityId);
        order.setOrderType(1);
        order.setGoodsId(activity.getGoodsId());
        order.setGoodsName(activity.getGoodsName());
        order.setUnitPrice(activity.getSalePrice());
        order.setQuantity(quantity);
        order.setAmount(activity.getSalePrice()
                .multiply(BigDecimal.valueOf(quantity)));
        order.setOrderStatus(0); // 拼团中
        orderMapper.insert(order);

        // 5. 发起支付（省略支付网关细节），支付成功回调后更新 pay_status
        payService.pay(order.getOrderNo(), order.getAmount());
        return order.getOrderNo();
    }

    /**
     * 普通订单下单（非拼团，如现货直购）
     * 下单即扣正式库存，直接进入待发货，与拼团订单流程分离
     */
    @Transactional(rollbackFor = Exception.class)
    public String placeNormalOrder(Long userId, Long leaderId,
                                   Long goodsId, int quantity) {
        // 1. 扣正式库存（MySQL 乐观锁，防止超卖）
        int updated = goodsMapper.deductStock(goodsId, quantity);
        if (updated != 1) {
            throw new BizException("库存不足");
        }
        // 2. 创建普通订单：直接待发货
        GroupGoods goods = goodsMapper.selectById(goodsId);
        GroupOrder order = new GroupOrder();
        order.setOrderNo(genOrderNo());
        order.setUserId(userId);
        order.setLeaderId(leaderId);
        order.setOrderType(2);
        order.setGoodsId(goodsId);
        order.setGoodsName(goods.getGoodsName());
        order.setUnitPrice(goods.getSalePrice());
        order.setQuantity(quantity);
        order.setAmount(goods.getSalePrice()
                .multiply(BigDecimal.valueOf(quantity)));
        order.setOrderStatus(1); // 已成团待发货（普通单无拼团阶段）
        orderMapper.insert(order);
        payService.pay(order.getOrderNo(), order.getAmount());
        return order.getOrderNo();
    }

    /** 到货核销：到货后生成取货码，用户取货核销 */
    public void pickup(String orderNo, String pickupCode) {

        int updated = orderMapper.casPickup(orderNo, pickupCode);
        if (updated != 1) {
            throw new BizException("取货码无效或已核销");
        }
    }
```

```java
@Service
public class RefundService {

    @Autowired
    private OrderRefundMapper refundMapper;
    @Autowired
    private GroupOrderMapper orderMapper;
    @Autowired
    private StringRedisTemplate redisTemplate;

    /**
     * 自动退款：未成团/手动关团时批量触发
     * 幂等：同一订单只允许生成一张退款单
     */
    @Transactional(rollbackFor = Exception.class)
    public String autoRefund(GroupOrder order, String reason) {
        // 1. 幂等：订单已退款直接返回
        if (order.getOrderStatus() == 5 || order.getPayStatus() == 2) {
            return null;
        }
        // 2. 生成退款单
        OrderRefund refund = new OrderRefund();
        refund.setRefundNo("RF" + System.currentTimeMillis());
        refund.setOrderNo(order.getOrderNo());
        refund.setUserId(order.getUserId());
        refund.setAmount(order.getAmount());
        refund.setRefundType(1); // 未成团自动退款
        refund.setStatus(0);     // 处理中
        refundMapper.insert(refund);

        // 3. 调用支付渠道原路退回（此处模拟），成功则更新状态
        boolean ok = payService.refund(order.getOrderNo(), order.getAmount());
        if (ok) {
            refundMapper.updateStatus(refund.getRefundNo(), 1);
            refund.setStatus(1);
            refund.setFinishTime(LocalDateTime.now());
            // 4. 订单状态联动：拼团中 -> 已退款，pay_status -> 已退款
            orderMapper.casRefund(order.getOrderNo());
            // 5. 释放该订单预占的库存（回补活动库存）
            redisTemplate.opsForValue()
                    .increment("stock:group:" + order.getActivityId(),
                            order.getQuantity());
            return refund.getRefundNo();
        }
        // 4b. 退款失败：入重试队列（延迟 5 分钟），超 3 次转人工
        String retryKey = "refund:retry:" + refund.getRefundNo();
        Long times = redisTemplate.opsForValue().increment(retryKey);
        if (times != null && times <= 3) {
            mqSender.sendDelay("refund.retry", refund.getRefundNo(),
                    5, TimeUnit.MINUTES);
        } else {
            log.error("退款多次失败转人工: {}", refund.getRefundNo());
        }
        return refund.getRefundNo();
    }

    /** 退款重试消费者（延迟队列） */
    @RabbitListener(queues = "refund.retry")
    public void retryRefund(String refundNo) {
        OrderRefund refund = refundMapper.selectByRefundNo(refundNo);
        if (refund == null || refund.getStatus() == 1) {
            return; // 已成功，幂等
        }
        GroupOrder order = orderMapper.selectByOrderNo(refund.getOrderNo());
        if (order != null) {
            autoRefund(order, "退款重试");
        }
    }
}
```

### 5. 结算服务：佣金分账计算

```java
@Service
public class SettlementService {

    @Autowired
    private SettlementDetailMapper detailMapper;
    @Autowired
    private GroupOrderMapper orderMapper;
    @Autowired
    private GroupLeaderMapper leaderMapper;
    @Autowired
    private StringRedisTemplate redisTemplate;

    /**
     * 成团后为每笔订单生成分账明细
     * 四方金额：用户实付 = 团长佣金 + 供应商成本 + 平台抽成
     */
    @Transactional(rollbackFor = Exception.class)
    public void generateDetails(Long activityId) {
        List<GroupOrder> orders = orderMapper.selectByActivityAndStatus(
                activityId, OrderStatus.GROUPED);
        for (GroupOrder order : orders) {
            // 幂等：同一订单只生成一条分账明细
            if (detailMapper.selectByOrderNo(order.getOrderNo()) != null) {
                continue;
            }
            // 1. 团长佣金 = 实付金额 * 佣金比例
            GroupLeader leader = leaderMapper.selectById(order.getLeaderId());
            BigDecimal commission = order.getAmount()
                    .multiply(BigDecimal.valueOf(leader.getCommissionRate()))
                    .divide(BigDecimal.valueOf(100), 2, RoundingMode.HALF_UP);
            // 2. 供应商成本 = 成本价 * 数量（成本价取团品快照）
            GroupGoods goods = goodsMapper.selectById(order.getGoodsId());
            BigDecimal supplierCost = goods.getCostPrice()
                    .multiply(BigDecimal.valueOf(order.getQuantity()));
            // 3. 平台抽成 = 实付 - 佣金 - 成本
            BigDecimal platformIncome = order.getAmount()
                    .subtract(commission).subtract(supplierCost)
                    .max(BigDecimal.ZERO); // 成本倒挂时平台不抽成

            // 4. 写分账明细
            SettlementDetail detail = new SettlementDetail();
            detail.setOrderNo(order.getOrderNo());
            detail.setActivityId(activityId);
            detail.setLeaderId(order.getLeaderId());
            detail.setUserPay(order.getAmount());
            detail.setLeaderCommission(commission);
            detail.setSupplierCost(supplierCost);
            detail.setPlatformIncome(platformIncome);
            detailMapper.insert(detail);

            // 5. 累加团长待结算佣金
            leaderMapper.incrPendingCommission(order.getLeaderId(), commission);
        }
    }

    /**
     * 结算任务：每日凌晨把「已成团满 24 小时」活动的待结算佣金转已结算
     * 防止用户售后导致佣金错发，给退款留出窗口期
     */
    @Scheduled(cron = "0 30 3 * * ?")
    public void dailySettle() {
        // 1. 找到结算窗口到期的活动（成团时间距今超过 24 小时且未结算）
        LocalDateTime threshold = LocalDateTime.now().minusDays(1);
        List<GroupActivity> activities = activityMapper
                .selectSettledReady(threshold);
        for (GroupActivity activity : activities) {
            String lockKey = "settle:lock:" + activity.getId();
            Boolean locked = redisTemplate.opsForValue()
                    .setIfAbsent(lockKey, "1", 60, TimeUnit.SECONDS);
            if (!Boolean.TRUE.equals(locked)) {
                continue;
            }
            try {
                // 2. 分账明细标记已结算
                detailMapper.batchSettleByActivity(activity.getId());
                // 3. 团长佣金：待结算 -> 已结算
                List<SettlementDetail> details = detailMapper
                        .selectByActivity(activity.getId());
                for (SettlementDetail d : details) {
                    leaderMapper.settleCommission(d.getLeaderId(),
                            d.getLeaderCommission());
                }
                // 4. 活动结算状态置为已结算
                activityMapper.updateSettleStatus(activity.getId(), 1);
            } finally {
                redisTemplate.delete(lockKey);
            }
        }
    }

    /** 团长提现：校验待结算佣金余额，生成提现单 */
    @Transactional(rollbackFor = Exception.class)
    public String withdraw(Long leaderId, BigDecimal amount) {
        GroupLeader leader = leaderMapper.selectById(leaderId);
        if (leader.getPendingCommission().compareTo(amount) < 0) {
            throw new BizException("可提现佣金不足");
        }
        leaderMapper.deductPendingCommission(leaderId, amount);
        CommissionWithdraw wd = new CommissionWithdraw();
        wd.setWithdrawNo("WD" + System.currentTimeMillis());
        wd.setLeaderId(leaderId);
        wd.setAmount(amount);
        wd.setStatus(0);
        withdrawMapper.insert(wd);
        return wd.getWithdrawNo();
    }
}
```

```java
    private GroupOrderMapper orderMapper;
    @Autowired
    private SettlementDetailMapper detailMapper;

    /**
     * 单团统计：参团人数、售出件数、成团进度
     */
    public ActivityStat statActivity(Long activityId) {
        GroupActivity activity = activityMapper.selectById(activityId);
        ActivityStat stat = new ActivityStat();
        stat.setActivityNo(activity.getActivityNo());
        stat.setGoodsName(activity.getGoodsName());
        stat.setJoinedCount(activity.getJoinedCount());
        stat.setTargetCount(activity.getTargetCount());
        stat.setSoldQuantity(activity.getSoldQuantity());
        // 成团进度百分比（Redis 计数为准，DB 兜底）
        stat.setProgress(activity.getJoinedCount() * 100
                / Math.max(1, activity.getTargetCount()));
        return stat;
    }

    /**
     * 平台日报：开团数、成团率、GMV、佣金成本
     */
    public DailyReport dailyReport(LocalDate date) {
        DailyReport report = new DailyReport();
        // 1. 开团数与成团数
        report.setTotalActivities(activityMapper.countByDate(date));
        report.setSuccessActivities(activityMapper
                .countByDateAndStatus(date, 1));
        report.setSuccessRate(report.getTotalActivities() == 0 ? 0
                : report.getSuccessActivities() * 100.0
                        / report.getTotalActivities());
        // 2. GMV：当日已支付订单金额合计
        report.setGmv(orderMapper.sumPaidAmountByDate(date));
        // 3. 佣金成本与平台收入
        report.setCommissionCost(detailMapper.sumCommissionByDate(date));
        report.setPlatformIncome(detailMapper.sumPlatformIncomeByDate(date));
        return report;
    }
}
```

## 实际应用场景

### 场景一：团长开团到成团履约

一个小区团购活动的完整生命周期：

```text
1. 团长王姐通过审核，在小区的自提点上线，平台分配默认佣金比例 10%
2. 王姐晚 20:00 从团品库选「土鸡蛋 30 枚装 19.9 元」开团：成团 20 人，截止明晚 22:00，限量 60 份
3. 活动库存写入 Redis，王姐把团链接发到小区微信群
4. 邻居小李下单 2 份并支付：库存 DECR 到 58，参团计数 +1，订单进入拼团中
5. 当晚 21:30 参团人数到 20，参团计数触发成团事件
6. 成团服务加锁判定成功：活动状态转已成团，该团 20 笔订单批量转待发货
7. 系统为每笔订单生成分账明细（佣金/成本/平台抽成），王姐收到成团通知开始备货
8. 次日凌晨 5 点商品送达自提点，王姐确认到货，用户收到取货通知与取货码
9. 用户凭取货码取货，王姐核销，订单完成；次日凌晨结算任务把佣金转入王姐待结算余额
```

### 场景二：未成团自动退款

成团人数不足时的自动解散流程：

```text
1. 张团长开「进口牛奶 12 盒 45 元」的团：成团 15 人，截止今晚 22:00
2. 截止前 1 小时只有 11 人参团，群里有人观望，进度停在 11/15
3. 22:00 定时任务扫描到该团截止且未成团，调用成团判定（人数不足）
4. 判定为未成团：活动状态转解散，锁定该团所有拼团中订单（11 笔）
5. 逐笔生成退款单，调用微信支付原路退回，退款成功订单状态转已退款
6. 活动剩余库存（49 份）回补到团品总库存，供下次开团使用
7. 用户收到「团未成团，款项已原路退回」的站内信与小程序通知
8. 张团长收到提醒：建议下次降低成团人数或延长截止时间，提升成团率
9. 平台日报显示今日成团率 82%，该团被记为未成团样本
```

### 场景三：结算周期与团长提现

佣金分账与提现的财务闭环：

```text
1. 成团后每笔订单立即生成分账明细：用户实付 19.9 = 佣金 1.99 + 成本 15.5 + 平台 2.41
2. 佣金先计入团长「待结算佣金」，暂不可提现（防售后退款导致佣金错发）
3. 用户取货后 24 小时无售后，每日 3:30 结算任务把窗口期到期的佣金转「已结算」
4. 王姐在团长端看到待结算佣金 326.5 元，点击申请提现 300 元
5. 系统校验待结算余额充足，生成提现单，财务审核通过后打款
6. 提现完成后待结算余额扣减，提现流水可查
7. 月末平台统计：本月佣金成本 2.8 万、平台抽成 6.1 万，与财务账核对一致
8. 若某笔订单发生售后退款：分账明细标记冲正，已结算佣金从下次结算中扣回
```

## 最佳实践与踩坑记录

### 最佳实践

1. 成团判定用「Redis 计数即时触发 + 定时任务截止兜底」双通道：人数到齐秒级成团提升体验，时间截止由定时任务扫描保证不漏团
2. 成团/结算/退款全部加分布式锁：成团锁、结算锁保证同一团同一订单只处理一次，幂等性靠锁 + 状态 CAS 双重保障
3. 拼团订单与普通订单共用订单表：order_type 区分 + activity_id 关联，避免维护两套订单体系，退款/核销逻辑统一
4. 价格快照进订单和活动：开团时锁定售价，下单时快照单价，团品改价不影响历史订单，对账口径稳定
5. 佣金分账逐笔明细化：每笔成团订单生成一条 settlement_detail，四方金额关系「实付 = 佣金 + 成本 + 抽成」恒成立，财务可审计
6. 佣金结算留售后窗口期：成团后满 24 小时无售后才转已结算，售后冲正从后续结算扣回，避免佣金错发
7. 库存双轨：Redis 预占库存管并发（DECR 原子），MySQL 正式库存管账实，成团后扣正式库存、未成团回补
8. 退款异步化 + 重试队列：退款走 MQ 延迟重试，超 3 次转人工，退款单幂等设计保证重试不重复退

### 踩坑记录

```text
坑 1：参团人数超卖成团
结论：显示 18/20 人，实际已卖 25 人，超卖 5 单。
原因：库存扣减和人数计数不是原子的，并发下单时两个操作之间插入其他请求。
解法：库存预占用 Redis DECR 原子扣减，负数即拒绝；计数与库存在同一事务内先扣后计。

坑 2：重复成团（成团事件被触发两次）
结论：同一团订单被重复转待发货，分账明细重复生成。
原因：人数到齐的即时成团与定时任务截止成团并发触发，没有互斥。
解法：成团判定统一走 judge 方法，Redis 成团锁 + 活动状态 CAS（进行中 -> 已成团），已判定的团幂等返回。

坑 3：团长改佣金比例导致历史订单分账错乱
结论：团长佣金比例从 10% 调到 15%，历史成团订单全部按新比例算了佣金，平台多付。
原因：分账时实时读团长表的佣金比例，没有快照。
解法：开团时把佣金比例快照进活动表，分账用快照值；调佣只影响新团。

坑 4：退款后库存没有回补
结论：团解散后库存数据对不上，越卖越少。
原因：退款流程只退了钱，没有释放预占库存。
解法：退款成功时把该订单数量回补到活动库存；活动解散时剩余库存统一回补团品总库存。

坑 5：定时任务多实例重复执行
结论：凌晨结算任务跑了两遍，佣金重复入账。
原因：应用多实例部署，@Scheduled 在每个实例上都执行。
解法：改用 XXL-Job 单机执行或加 settle:lock:{activityId} 分布式锁；明细表 order_no 唯一索引兜底防重。

坑 6：支付回调先于订单创建到达
结论：用户支付成功回调先到，订单还没落库，回调被丢弃，用户钱扣了没订单。
原因：支付回调与下单是两条异步链路，无顺序保证。
解法：回调按 orderNo 查不到订单时进延迟队列等订单落库后再处理，最终一致。

坑 7：统计口径不统一
结论：运营看 GMV 是 10 万，财务算出来 9.2 万，对不上账。
原因：有的统计含未成团订单，有的只含已支付，口径混乱。
解法：统一定义：GMV 只统计已支付且已成团订单；退款单单独计数；报表 SQL 统一口径并注释。

坑 8：售后退款导致佣金多发
结论：用户退货退款后，团长佣金已经发了，平台倒贴。
原因：佣金在成团当天就结算了，没有留售后窗口期。
解法：佣金先入「待结算」，成团满 24 小时无售后才转「已结算」；售后订单分账明细冲正，已发佣金从后续结算扣回。
```

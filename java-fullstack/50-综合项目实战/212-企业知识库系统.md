## 项目背景

企业知识库系统（Enterprise Knowledge Base / Wiki）是把公司分散在个人电脑、聊天记录、网盘里的文档沉淀成「结构化、可搜索、有权限、有版本」的集中知识资产。选择它作为综合实战项目，是因为它同时踩中三条技术主线：全文检索（Elasticsearch 中文分词）、版本管理（快照与差异对比）、复杂树形结构（目录树的增删移）。这三个点都是面试和真实业务里的高频考点，做完这个项目等于把「内容型系统」的通用能力都打通了。

业务痛点：

```text
1. 文档散落各处：员工文档在自己电脑、微信群文件、网盘里各存一份，找东西靠问人
2. 没有全文搜索：想找「上次那个部署文档」，只能逐个文件夹翻，效率极低
3. 版本混乱：同一份《接口规范》被 10 个人各改一版，文件名从 v1 排到 v9 最终版
4. 改错了无法回滚：文档被误改覆盖，没有历史版本，数据直接丢失
5. 权限一刀切：要么全部可见要么全部隐藏，敏感文档（薪酬制度、技术架构）没有分级控制
6. 知识没有审批：技术方案随便发布没人评审，错误内容全公司传播，后期返工成本高
```

目标用户与核心诉求：

```text
1. 普通员工：浏览/搜索文档、收藏点赞、编辑自己部门文档，需要一个好用的知识消费入口
2. 文档作者：用 Markdown 写文档、管理版本、提交审批发布，需要顺手不打断的编辑体验
3. 部门管理员：管理本部门目录树、审核文档发布、控制部门文档可见范围
4. 系统管理员：维护部门结构、标签体系、全库统计与权限策略
```

项目要解决的核心问题一句话概括：把企业里的文档从「个人文件」变成「可搜索、有版本、有权限、有审批的组织资产」。

## 功能介绍

功能按角色拆成四个端：浏览端（全员）、编辑端（作者）、审批端（管理员）、管理端（系统管理员）。

```text
一、浏览端（全员视角）
1. 文档树 —— 左侧树形目录浏览全部可见文档，支持折叠展开
2. 全文搜索 —— 关键词搜索标题+正文，按相关度排序，命中高亮
3. 文档阅读 —— Markdown 渲染阅读、目录锚点、历史版本查看
4. 收藏与点赞 —— 收藏到个人列表，点赞表达认可，热门文档排行
5. 标签浏览 —— 按标签聚合文档，快速定位同类内容

二、编辑端（作者视角）
1. Markdown 编辑器 —— 分屏实时预览、图片粘贴上传、代码块高亮
2. 文档管理 —— 新建/编辑/删除文档，在目录树中移动文档或目录
3. 版本管理 —— 每次保存生成版本快照，历史版本对比、一键回滚
4. 草稿与发布 —— 保存草稿，提交审批后由管理员审核发布
5. 标签管理 —— 为文档设置多个标签，标签自动归集

三、审批端（部门管理员视角）
1. 审批中心 —— 待审文档列表（提交人/变更摘要/差异对比）
2. 审批操作 —— 通过发布 / 驳回并附原因，审批记录留痕
3. 部门目录管理 —— 本部门目录树的增删改与排序

四、管理端（系统管理员视角）
1. 部门管理 —— 部门增删改，部门树维护
2. 权限审计 —— 查看文档可见范围设置，处理越权申诉
3. 全库统计 —— 文档总数、版本数、活跃作者、热门标签 Top10
4. 索引管理 —— ES 索引重建、同步失败重试队列查看
```

## 技术选型

| 组件 | 选型 | 理由 |
|------|------|------|
| 开发框架 | Spring Boot 2.7/3.x | 生态成熟，起步快，社区资料多 |
| 持久层 | MyBatis-Plus | 单表 CRUD 零 SQL，树形查询与统计走 XML |
| 数据库 | MySQL 8.0 | 文档、版本、权限、审批等业务数据落库 |
| 全文检索 | Elasticsearch 8.x + IK 分词器 | 标题+正文中文全文检索，BM25 相关度排序 |
| 缓存 | Redis | 文档树缓存、点赞计数、审批幂等、热门榜 |
| 鉴权 | Spring Security + JWT | 无状态认证，权限校验与数据权限结合 |
| 前端 | Vue 3 + Element Plus | 后台管理类系统的成熟组合 |
| 构建 | Maven | 依赖管理标准工具 |

选型说明：

```text
1. ES 而非 MySQL LIKE：知识库的核心价值就是「搜得到」，中文分词 + 相关度排序 + 高亮，LIKE 完全做不到
2. 版本管理用「快照 + 差异」双轨：保存版本时存全文快照（回滚安全），对比时用 diff 算法算差异（展示友好）
3. 文档树缓存用 Redis：树形结构读多写少，全量缓存 + 变更时按路径失效，避免每次递归查库
4. 权限模型用「公开/部门/个人」三级：不过度设计 RBAC 细粒度授权，业务上够用且实现清晰
5. MySQL 与 ES 一致性用「先更库、再同步、失败重试」：同步走统一 Service 方法，失败进重试表定时补推
```

请求链路示例（作者编辑保存文档，触发版本 + 索引同步）：

```text
1. 前端 PUT /api/docs/{id}，body 为 Markdown 正文
2. Controller 校验 JWT，DocService 校验该用户对文档有编辑权限（部门管理员或作者本人）
3. 事务内：更新 doc 表 content + 版本号 +1，插入 doc_version 快照记录（含 diff 摘要）
4. 事务提交后：同步调 IndexSyncService 把新内容写入 ES（标题+正文+标签）
5. ES 同步失败：写入 sync_fail 重试表，定时任务每 5 分钟补推
6. 变更文档树缓存：删除该文档的父目录路径缓存（doc:tree:{parentId}）
7. 返回新版本号与更新时间，前端提示保存成功
```

搜索链路（员工搜索「部署 环境搭建」）：

```text
1. 前端 GET /api/search?kw=部署 环境搭建
2. SearchService 用 multi_match 查 ES：title^3 + content，analyzer 指定 ik_max_word
3. ES 按 BM25 返回 top 20 文档 id + 高亮片段
4. 用 id 回 MySQL 查最新文档元数据（标题/作者/更新时间），ES 只存索引字段
5. 权限过滤：对每个文档做可见性校验（公开/部门/个人），过滤掉无权限的结果
6. 组装搜索结果返回，前端展示高亮标题与摘要
```

## 核心实现

### 1. 树形目录：递归查询 + 缓存 + 移动校验

```java
@Service
public class DocTreeService {

    private static final String TREE_KEY_PREFIX = "doc:tree:";

    @Autowired
    private DocMapper docMapper;
    @Autowired
    private StringRedisTemplate redis;
    @Autowired
    private ObjectMapper objectMapper;

    /**
     * 查询某个父节点下的子树（平铺结构，前端组装成树）
     * 缓存优先：子节点列表缓存 30 分钟，变更操作主动失效
     */
    public List<DocNode> listTree(Long parentId) {
        String key = TREE_KEY_PREFIX + parentId;
        // 1. 查缓存
        String cached = redis.opsForValue().get(key);
        if (cached != null) {
            try {
                return objectMapper.readValue(cached,
                        new TypeReference<List<DocNode>>() {});
            } catch (Exception e) {
                log.warn("文档树缓存解析失败, key={}", key);
            }
        }
        // 2. 缓存未命中，查库（只查一层子节点，前端按需展开）
        List<DocNode> nodes = docMapper.selectList(new LambdaQueryWrapper<Doc>()
                .eq(Doc::getParentId, parentId)
                .orderByAsc(Doc::getType).orderByAsc(Doc::getId))
                .stream().map(DocNode::from).toList();
        // 3. 写缓存
        try {
            redis.opsForValue().set(key, objectMapper.writeValueAsString(nodes),
                    30, TimeUnit.MINUTES);
        } catch (Exception e) {
            log.warn("文档树缓存写入失败, key={}", key);
        }
        return nodes;
    }

    /**
     * 移动文档/目录：校验目标父节点不能是自己的子孙（防环）
     * 防环原理：从目标父节点向上找祖先链，若链上出现被移动节点则非法
     */
    public void move(Long docId, Long newParentId) {
        Doc doc = docMapper.selectById(docId);
        if (doc == null) {
            throw new BusinessException("节点不存在");
        }
        // 1. 目标父节点必须存在且是目录
        Doc parent = docMapper.selectById(newParentId);
        if (parent == null || parent.getType() != 1) {
            throw new BusinessException("目标父节点不存在或不是目录");
        }
        // 2. 防环校验：newParentId 向上找祖先，遇到 docId 则成环
        Long cursor = newParentId;
        while (cursor != null && cursor != 0) {
            if (cursor.equals(docId)) {
                throw new BusinessException("不能移动到自己的子目录下");
            }
            Doc p = docMapper.selectById(cursor);
            cursor = p == null ? null : p.getParentId();
        }
        // 3. 更新父节点并失效相关缓存
        Doc update = new Doc();
        update.setId(docId);
        update.setParentId(newParentId);
        docMapper.updateById(update);
        redis.delete(TREE_KEY_PREFIX + doc.getParentId());
        redis.delete(TREE_KEY_PREFIX + newParentId);
    }
}
```

### 2. 文档保存与版本快照

```java
@Service
public class DocService {

    @Autowired
    private DocMapper docMapper;
    @Autowired
    private DocVersionMapper docVersionMapper;
    @Autowired
    private IndexSyncService indexSyncService;
    @Autowired
    private StringRedisTemplate redis;

    /**
     * 保存文档（草稿态）：事务内更新内容 + 生成版本快照
     * 每次保存都留快照，版本号从 1 递增，供历史对比与回滚
     */
    @Transactional
    public Long saveContent(Long docId, Long operatorId, String content) {
        Doc doc = docMapper.selectById(docId);
        if (doc == null || doc.getType() != 2) {
            throw new BusinessException("文档不存在");
        }
        // 1. 更新正文（草稿状态下更新，已发布文档先进入草稿分支）
        Doc update = new Doc();
        update.setId(docId);
        update.setContent(content);
        update.setVersion(doc.getVersion() + 1);
        docMapper.updateById(update);
        // 2. 写版本快照，diff_summary 用简单行数统计（生产可用 java-diff-utils 算行级差异）
        DocVersion version = new DocVersion();
        version.setDocId(docId);
        version.setVersion(doc.getVersion() + 1);
        version.setContent(content);
        version.setOperatorId(operatorId);
        version.setDiffSummary("新增 " + countLines(content) + " 行");
        docVersionMapper.insert(version);
        return version.getVersion();
    }

    /**
     * 版本对比：取两个版本的全文做行级 diff
     * 用 java-diff-utils 的 Myers 算法，返回增删行列表
     */
    public List<DiffRow> diffVersions(Long docId, int v1, int v2) {
        DocVersion a = getVersion(docId, v1);
        DocVersion b = getVersion(docId, v2);
        if (a == null || b == null) {
            throw new BusinessException("版本不存在");
        }
        List<String> lines1 = Arrays.asList(a.getContent().split("\n"));
        List<String> lines2 = Arrays.asList(b.getContent().split("\n"));
        // DiffUtils.diff 返回行级差异；生产环境用 PatchUtils 生成统一 diff 文本
        DiffResult<String> result = DiffUtils.diff(lines1, lines2);
        return result.getDeltas().stream().map(delta -> {
            DiffRow row = new DiffRow();
            row.setType(delta.getType().name()); // CHANGE/DELETE/INSERT
            row.setOldLine(delta.getSource().getLines().stream().findFirst().orElse(""));
            row.setNewLine(delta.getTarget().getLines().stream().findFirst().orElse(""));
            return row;
        }).toList();
    }

    /**
     * 版本回滚：把指定历史版本的内容恢复为当前内容，并生成新版本
     * 回滚也是「新增版本」而不是覆盖，保证操作可追溯
     */
    @Transactional
    public Long rollback(Long docId, int targetVersion, Long operatorId) {
        DocVersion target = getVersion(docId, targetVersion);
        if (target == null) {
            throw new BusinessException("目标版本不存在");
        }
        Doc doc = docMapper.selectById(docId);
        // 回滚 = 用旧内容保存一个新版本
        Doc update = new Doc();
        update.setId(docId);
        update.setContent(target.getContent());
        update.setVersion(doc.getVersion() + 1);
        docMapper.updateById(update);

        DocVersion version = new DocVersion();
        version.setDocId(docId);
        version.setVersion(doc.getVersion() + 1);
        version.setContent(target.getContent());
        version.setOperatorId(operatorId);
        version.setDiffSummary("回滚至 v" + targetVersion);
        docVersionMapper.insert(version);
        // 已发布文档回滚后同步 ES 索引
        if (doc.getStatus() == 2) {
            indexSyncService.syncDoc(docId);
        }
        return version.getVersion();
    }
}
```

```java
@Service
public class SearchService {

    @Autowired
    private RestHighLevelClient esClient;
    @Autowired
    private DocMapper docMapper;

    /**
     * 关键词搜索：title^3 权重最高，正文次之，标签参与匹配
     * 返回带高亮的结果，随后按可见权限过滤
     */
    public PageResult<DocVO> search(String keyword, Long userId, int page, int size) {
        SearchSourceBuilder source = new SearchSourceBuilder();
        source.query(QueryBuilders.multiMatchQuery(keyword)
                .field("title", 3.0f)
                .field("content")
                .field("tag_str", 2.0f)
                .analyzer("ik_max_word"));
        HighlightBuilder highlight = new HighlightBuilder()
                .field("title").field("content")
                .preTags("<em class='hl'>").postTags("</em>");
        source.highlighter(highlight);
        source.from((page - 1) * size).size(size);

        SearchRequest request = new SearchRequest("doc_index");
        request.source(source);
        List<Long> docIds = new ArrayList<>();
        try {
            SearchResponse response = esClient.search(request, RequestOptions.DEFAULT);
            for (SearchHit hit : response.getHits().getHits()) {
                docIds.add(Long.valueOf(hit.getId()));
            }
        } catch (IOException e) {
            throw new RuntimeException("ES 搜索失败", e);
        }
        if (docIds.isEmpty()) {
            return PageResult.empty();
        }
        // 回 MySQL 查详情并按权限过滤（ES 只存索引字段，不存权限信息）
        List<Doc> docs = docMapper.selectBatchIds(docIds);
        List<DocVO> result = docs.stream()
                .filter(doc -> PermissionService.canRead(doc, userId))
                .map(DocVO::from).toList();
        return PageResult.of(result, result.size());
    }
}
```

### 4. 权限校验：公开 / 部门 / 个人

```java
@Component
public class PermissionService {

    @Autowired
    private UserMapper userMapper;

    /**
     * 读取权限校验：
     * 1. 公开文档全员可读
     * 2. 部门文档要求读者与文档同部门（含子部门）
     * 3. 指定人文档只允许文档归属人读取
     * 4. 系统管理员与部门管理员对本部门文档全量可读
     */
    public static boolean canRead(Doc doc, Long userId) {
        if (doc.getVisibility() == 1) {
            return true; // 公开
        }
        if (doc.getVisibility() == 2) {
            // 部门文档：读者所属部门 == 文档部门（简化版不展开子部门）
            User reader = userMapper.selectById(userId);
            return reader != null && reader.getDeptId() != null
                    && reader.getDeptId().equals(doc.getDeptId());
        }
        // 指定人：仅创建人本人可读（生产可扩展为白名单表）
        return doc.getCreatorId().equals(userId);
    }

    /**
     * 编辑权限校验：作者本人、部门管理员、系统管理员
     * 在 Controller 入口用 AOP 或拦截器统一调用
     */
    public boolean canEdit(Doc doc, User user) {
        if (user.getRole() == 1) {
            return true; // 系统管理员
        }
        if (doc.getCreatorId().equals(user.getId())) {
            return true; // 作者本人
        }
        // 部门管理员：文档归属本部门
        return user.getRole() == 2
                && doc.getDeptId() != null
                && doc.getDeptId().equals(user.getDeptId());
    }
}
```

### 5. 审批发布：状态机 + 幂等

```java
@Service
public class ApprovalService {

    private static final String APPROVAL_LOCK = "approval:lock:";

    @Autowired
    private ApprovalMapper approvalMapper;
    @Autowired
    private DocMapper docMapper;
    @Autowired
    private IndexSyncService indexSyncService;
    @Autowired
    private StringRedisTemplate redis;

    /**
     * 提交审批：草稿文档 -> 待审批
     * 一个文档同一时间只允许一条待审批记录（幂等控制）
     */
    public Long submit(Long docId, Long submitterId) {
        // 1. 幂等锁：防止重复提交
        String lockKey = APPROVAL_LOCK + docId;
        Boolean locked = redis.opsForValue().setIfAbsent(lockKey, "1", 10, TimeUnit.SECONDS);
        if (!Boolean.TRUE.equals(locked)) {
            throw new BusinessException("请勿重复提交审批");
        }
        try {
            // 2. 校验已有待审批记录
            Long pending = approvalMapper.selectCount(new LambdaQueryWrapper<Approval>()
                    .eq(Approval::getDocId, docId)
                    .eq(Approval::getStatus, 0));
            if (pending > 0) {
                throw new BusinessException("该文档已有待审批的申请");
            }
            Doc doc = docMapper.selectById(docId);
            if (doc == null || doc.getType() != 2) {
                throw new BusinessException("文档不存在");
            }
            // 3. 插入审批记录，文档状态 -> 待审批
            Approval approval = new Approval();
            approval.setDocId(docId);
            approval.setSubmitVersion(doc.getVersion());
            approval.setSubmitterId(submitterId);
            approval.setStatus(0);
            approvalMapper.insert(approval);

            Doc update = new Doc();
            update.setId(docId);
            update.setStatus(1);
            docMapper.updateById(update);
            return approval.getId();
        } finally {
            redis.delete(lockKey);
        }
    }

    /**
     * 审批：通过 -> 发布并同步 ES；驳回 -> 退回草稿并记录意见
     * 审批时锁定版本：只允许审批「提交时的版本」
     */
    @Transactional
    public void approve(Long approvalId, Long approverId, boolean pass, String comment) {
        Approval approval = approvalMapper.selectById(approvalId);
        if (approval == null || approval.getStatus() != 0) {
            throw new BusinessException("审批记录不存在或已处理");
        }
        // 并发防重：UPDATE ... WHERE status=0 影响行数为 0 说明已被处理
        int rows = approvalMapper.casUpdateStatus(approvalId, approverId, comment,
                pass ? 1 : 2);
        if (rows == 0) {
            throw new BusinessException("审批已被处理，请刷新");
        }
        Doc doc = docMapper.selectById(approval.getDocId());
        Doc update = new Doc();
        update.setId(doc.getId());
        if (pass) {
            update.setStatus(2); // 已发布
            docMapper.updateById(update);
            // 发布成功同步 ES 索引；失败进重试队列由定时任务补推
            indexSyncService.syncDoc(doc.getId());
        } else {
            update.setStatus(3); // 已驳回
            docMapper.updateById(update);
        }
    }
}
```

### 6. 点赞与收藏：Redis 计数 + 定时刷库

```java
@Service
public class LikeFavoriteService {

    private static final String LIKE_KEY = "doc:like:";
    private static final String LIKE_USER_KEY = "doc:like:user:";
    private static final String FAV_KEY = "doc:favorite:";
    private static final String HOT_RANK = "doc:hot:rank";

    @Autowired
    private LikeRecordMapper likeRecordMapper;
    @Autowired
    private FavoriteMapper favoriteMapper;
    @Autowired
    private DocMapper docMapper;
    @Autowired
    private StringRedisTemplate redis;

    /**
     * 点赞/取消点赞：Redis 计数 + MySQL 记录
     * 幂等：Redis Set 记录已赞用户，MySQL 唯一索引 uk_user_doc 兜底
     */
    public void like(Long docId, Long userId, boolean liked) {
        String countKey = LIKE_KEY + docId;
        String userKey = LIKE_USER_KEY + docId;
        // 1. 更新 Redis 计数与用户集合
        if (liked) {
            Long added = redis.opsForSet().add(userKey, String.valueOf(userId));
            if (added != null && added > 0) {
                redis.opsForValue().increment(countKey);
            }
        } else {
            Long removed = redis.opsForSet().remove(userKey, String.valueOf(userId));
            if (removed != null && removed > 0) {
                redis.opsForValue().decrement(countKey);
            }
        }
        // 2. MySQL 落记录（先删后插，保持幂等）
        likeRecordMapper.delete(new LambdaQueryWrapper<LikeRecord>()
                .eq(LikeRecord::getDocId, docId)
                .eq(LikeRecord::getUserId, userId));
        if (liked) {
            LikeRecord record = new LikeRecord();
            record.setDocId(docId);
            record.setUserId(userId);
            likeRecordMapper.insert(record);
        }
    }

    /**
     * 定时任务：每 5 分钟把 Redis 点赞/收藏计数批量刷回 MySQL
     * 用 Scan 遍历 doc:like:* 前缀的 key，避免 keys 阻塞
     */
    @Scheduled(fixedDelay = 5 * 60 * 1000)
    public void syncCountToDb() {
        Set<String> likeKeys = redis.keys(LIKE_KEY + "*");
        if (likeKeys != null) {
            for (String key : likeKeys) {
                Long docId = Long.valueOf(key.substring(LIKE_KEY.length()));
                String count = redis.opsForValue().get(key);
                Doc update = new Doc();
                update.setId(docId);
                update.setLikeCount(Integer.parseInt(count));
                docMapper.updateById(update);
            }
        }
        // 热门榜：点赞+收藏+浏览加权后写入 ZSet，保留前 50
        List<Doc> docs = docMapper.selectList(new LambdaQueryWrapper<Doc>()
                .eq(Doc::getStatus, 2));
        for (Doc d : docs) {
            double score = d.getLikeCount() * 3.0
                    + d.getFavoriteCount() * 2.0 + d.getViewCount() * 0.1;
            redis.opsForZSet().add(HOT_RANK, String.valueOf(d.getId()), score);
        }
        redis.opsForZSet().removeRange(HOT_RANK, 50, -1);
    }
}
```

### 7. ES 索引同步与失败重试

```java
@Service
public class IndexSyncService {

    @Autowired
    private RestHighLevelClient esClient;
    @Autowired
    private DocMapper docMapper;
    @Autowired
    private SyncFailMapper syncFailMapper;

    /**
     * 文档发布/更新后同步 ES 索引
     * 只索引搜索所需字段；生产环境可改为发 MQ 异步消费
     */
    public void syncDoc(Long docId) {
        Doc doc = docMapper.selectById(docId);
        if (doc == null || doc.getStatus() != 2) {
            return; // 非发布状态不同步
        }
        Map<String, Object> sourceMap = new HashMap<>();
        sourceMap.put("title", doc.getName());
        sourceMap.put("content", doc.getContent());
        sourceMap.put("tag_str", doc.getTagStr());
        sourceMap.put("creator_id", doc.getCreatorId());
        sourceMap.put("update_time", doc.getUpdateTime());
        IndexRequest request = new IndexRequest("doc_index")
                .id(String.valueOf(doc.getId()))
                .source(sourceMap, XContentType.JSON);
        try {
            esClient.index(request, RequestOptions.DEFAULT);
        } catch (IOException e) {
            log.error("文档索引同步失败, docId={}", docId, e);
            // 写入失败重试表，定时任务补推
            SyncFail fail = new SyncFail();
            fail.setDocId(docId);
            fail.setRetryCount(0);
            fail.setStatus(0);
            syncFailMapper.insert(fail);
        }
    }

    /**
     * 定时任务：扫描同步失败记录，重试补推，超过 5 次告警
     */
    @Scheduled(fixedDelay = 5 * 60 * 1000)
    public void retrySync() {
        List<SyncFail> fails = syncFailMapper.selectList(new LambdaQueryWrapper<SyncFail>()
                .eq(SyncFail::getStatus, 0)
                .lt(SyncFail::getRetryCount, 5)
                .last("LIMIT 100"));
        for (SyncFail fail : fails) {
            try {
                syncDoc(fail.getDocId());
                fail.setStatus(1); // 成功
                syncFailMapper.updateById(fail);
            } catch (Exception e) {
                fail.setRetryCount(fail.getRetryCount() + 1);
                syncFailMapper.updateById(fail);
            }
        }
    }
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. 版本管理坚持「只增不改」：回滚也是新增一个版本，而不是覆盖旧版本，保证任何操作可追溯
2. 目录与文档统一建模：一张 doc 表用 type 区分，parent_id 组织树，比「目录表 + 文档表」两张表简单得多，移动/删除逻辑统一
3. 树操作防环是硬校验：移动目录前向上遍历祖先链，遇到自身即拒绝，否则会出现死循环树
4. 点赞/收藏这类高频小写入先进 Redis，定时批量刷库，别让 MySQL 扛每秒钟几千次的 UPDATE
5. ES 与 MySQL 一致性：先更库、后同步索引、失败进重试表定时补推，不依赖强一致
6. 全文搜索的权限过滤放在 MySQL 侧：ES 只存索引字段，搜索结果回查 MySQL 时按可见范围过滤，避免索引里塞权限信息导致权限变更不同步
7. 审批用「UPDATE ... WHERE status=0 影响行数」做乐观并发控制，比先查后改更可靠

### 踩坑记录

```text
坑 1：目录移动到自己的子孙节点下
结论：目录树出现环，前端展开直接死循环。
原因：移动时只校验了目标父节点存在，没校验「目标是否是自己的后代」。
解法：移动前从目标父节点向上遍历祖先链，遇到被移动节点即抛异常拒绝。

坑 2：文档树缓存不失效
结论：新建文档后左侧树刷新不出来。
原因：只删了「当前父节点」的缓存 key，没删「父节点的父节点」链路上的缓存。
解法：失效缓存沿祖先链一路删（循环向上取 parent_id）；或树缓存只存一层，按需展开。

坑 3：回滚后版本号错乱
结论：回滚到 v3 后，新版本号从 3 开始覆盖了旧版本。
原因：回滚逻辑直接 update 版本号 = 目标版本号，而不是在最大版本号上 +1。
解法：回滚 = 用旧内容 insert 一条新版本（version = 当前 max + 1），主键唯一索引 uk_doc_version 保证不冲突。

坑 4：ES 索引与数据库不一致
结论：文档已发布但搜索搜不到，或删除了还能搜到。
原因：只改了 MySQL，同步 ES 的代码漏执行或同步失败没人重试。
解法：发布/更新/删除统一走 Service 方法内同步索引；失败写入重试表，定时任务补推；必要时提供「重建索引」管理入口。

坑 5：部门文档权限泄漏
结论：B 部门员工能搜到 A 部门的内部文档。
原因：ES 搜索结果没做权限过滤，权限只在文档详情接口校验。
解法：搜索链路回查 MySQL 时统一走 PermissionService.canRead 过滤；权限变更（转部门）后对旧索引文档同样生效，因为过滤在查询侧。

坑 6：全文搜索中文分词效果差
结论：搜「知识库」搜不到「知识 库」，搜「部署」命中大量无关文档。
原因：默认 standard 分词器按空格切词，中文被整体当成一个词。
解法：安装 IK 分词器，索引 analyzer 用 ik_max_word（最大切分），查询用 ik_smart（智能切分）；停用词表过滤「的/了/在」等无意义词。

坑 7：点赞计数与记录不一致
结论：Redis 计数是 100，MySQL 点赞记录只有 80 条。
原因：Redis 计数成功但 MySQL 插入失败，或用户取消失败时计数与记录不同步。
解法：以 MySQL 记录表为事实源，定时任务用「MySQL 实际记录数」校准 Redis 计数；Redis 只做展示加速，不做最终依据。
```

## 概述

线程池是并发编程的核心基础设施——它管理一组工作线程，复用它们执行任务。相比每次 `new Thread()`，线程池的优点：

- **降低资源消耗**：复用线程，避免频繁创建/销毁
- **控制并发度**：限制最大线程数，防止资源耗尽
- **管理任务队列**：超出处理能力的任务排队等待
- **统一管理**：监控、关闭、异常处理集中化

## Executor 框架

Java 线程池基于 Executor 框架（JDK 5）：

```
Executor ← 顶层接口，execute(Runnable)
    │
ExecutorService ← 扩展接口，支持 Callable + 生命周期管理
    │
ThreadPoolExecutor ← 核心实现
    │
ScheduledThreadPoolExecutor ← 支持定时/周期任务
```

```java
// Executor —— 任务提交和执行解耦
Executor executor = command -> new Thread(command).start();

// ExecutorService —— 支持 Callable（有返回值）+ Future + 关闭
ExecutorService pool = Executors.newFixedThreadPool(4);

// 提交 Runnable（无返回值）
Future<?> f1 = pool.submit(() -> System.out.println("task"));

// 提交 Callable（有返回值）
Future<String> f2 = pool.submit(() -> {
    Thread.sleep(1000);
    return "result";
});

// 关闭
pool.shutdown();           // 不再接受新任务，等待现有任务完成
// pool.shutdownNow();     // 立即停止（中断正在执行的任务）
pool.awaitTermination(10, TimeUnit.SECONDS);  // 等待 10 秒
```

## ThreadPoolExecutor 核心参数

```java
ThreadPoolExecutor pool = new ThreadPoolExecutor(
    2,                    // corePoolSize  核心线程数
    4,                    // maximumPoolSize 最大线程数
    60, TimeUnit.SECONDS, // keepAliveTime 空闲线程存活时间
    new LinkedBlockingQueue<>(100),  // workQueue 任务队列
    new ThreadPoolExecutor.AbortPolicy()  // handler 拒绝策略
);
```

| 参数 | 含义 | 建议 |
|------|------|------|
| corePoolSize | 核心线程数（常驻，不回收） | CPU 密集型：CPU 核数 + 1；IO 密集型：核数 × 2 |
| maximumPoolSize | 最大线程数 | 略大于 corePoolSize，为上限定 |
| keepAliveTime | 非核心线程空闲多久回收 | 根据任务频率设定，通常 60s |
| workQueue | 任务缓冲队列 | `LinkedBlockingQueue`（无界慎用）、`ArrayBlockingQueue`（推荐） |
| threadFactory | 线程创建工厂 | **必须自定义**——设置线程名称、daemon、异常处理器 |
| handler | 拒绝策略 | 队列满 + 线程满时触发 |

## 四种内置线程池（Executors）

Executors 提供四种便捷创建方法——**但《阿里巴巴开发手册》禁止直接使用**（参数不当容易 OOM）：

```java
// 1. FixedThreadPool —— 固定线程数
// core = max = n，无界 LinkedBlockingQueue
// 风险：队列无界，任务积压可能导致 OOM
ExecutorService fixed = Executors.newFixedThreadPool(4);

// 2. CachedThreadPool —— 弹性线程
// core=0，max=Integer.MAX_VALUE，SynchronousQueue
// 风险：线程数无上限，高并发下创建海量线程导致 OOM
ExecutorService cached = Executors.newCachedThreadPool();

// 3. SingleThreadExecutor —— 单线程
// core=max=1，无界 LinkedBlockingQueue
// 风险：同 Fixed，队列无界
ExecutorService single = Executors.newSingleThreadExecutor();

// 4. ScheduledThreadPool —— 支持定时/周期任务
ScheduledExecutorService scheduled = Executors.newScheduledThreadPool(2);
```

## 线程池工作流程

```
提交任务 submit(task)
    │
    ├── 当前线程数 < corePoolSize？
    │   └── 是 → 创建新线程执行（即使有空闲线程）
    │
    ├── 队列没满？
    │   └── 是 → 放入 workQueue 排队
    │
    ├── 当前线程数 < maximumPoolSize？
    │   └── 是 → 创建新线程执行
    │
    └── 不满足以上 → 执行拒绝策略
```

关于核心线程的补充：JDK 6+ 后，线程池不是"先核心线程再队列再最大线程"的严格顺序——核心线程创建后就进入队列等待，当队列满了才扩到最大线程。

## 拒绝策略

四种内置 + 可自定义：

```java
// AbortPolicy（默认）—— 抛异常
new ThreadPoolExecutor.AbortPolicy()
// 抛出 RejectedExecutionException

// CallerRunsPolicy —— 调用者线程执行
new ThreadPoolExecutor.CallerRunsPolicy()
// 提交任务的线程自己执行，减缓提交速度

// DiscardPolicy —— 静默丢弃
new ThreadPoolExecutor.DiscardPolicy()
// 什么都不做，任务默默消失（危险！）

// DiscardOldestPolicy —— 丢弃最老的任务
new ThreadPoolExecutor.DiscardOldestPolicy()
// 丢弃队首（等待最久的），重试提交当前任务

// 自定义
new RejectedExecutionHandler() {
    @Override
    public void rejectedExecution(Runnable r, ThreadPoolExecutor e) {
        // 记录日志、持久化任务、发送告警...
    }
}
```

| 策略 | 行为 | 适用 |
|------|------|------|
| AbortPolicy | 抛异常 | 默认推荐 |
| CallerRunsPolicy | 提交者执行 | 需要反压的降级场景 |
| DiscardPolicy | 丢弃 | 允许丢失的非关键任务 |
| DiscardOldestPolicy | 丢弃最旧的 | 优先处理新任务 |

## Future 与 FutureTask

```java
// Future 接口 —— 异步计算结果
Future<String> future = pool.submit(() -> {
    Thread.sleep(2000);
    return "完成";
});

// 检查状态
boolean done = future.isDone();        // 是否完成
boolean cancelled = future.isCancelled(); // 是否取消

// 获取结果
String result = future.get();                // 阻塞等待
String result2 = future.get(1, TimeUnit.SECONDS);  // 最多等 1 秒，超时抛 TimeoutException

// 取消任务
future.cancel(true);  // true=可中断正在执行的任务

// FutureTask —— 既是 Runnable 又是 Future
FutureTask<Integer> task = new FutureTask<>(() -> 42);
pool.submit(task);                   // 作为 Runnable 提交
Integer ret = task.get();            // 作为 Future 取结果
```

## ScheduledExecutorService

```java
ScheduledExecutorService scheduler = Executors.newScheduledThreadPool(2);

// 延迟执行
scheduler.schedule(() -> System.out.println("3秒后执行"),
    3, TimeUnit.SECONDS);

// 固定频率执行（任务开始间隔 = period）
scheduler.scheduleAtFixedRate(
    () -> System.out.println("每 2 秒执行"),
    0,                   // 初始延迟
    2, TimeUnit.SECONDS   // 周期（任务开始到下一个任务开始的间隔）
);

// 固定延迟执行（任务结束到下一个开始间隔 = delay）
scheduler.scheduleWithFixedDelay(
    () -> System.out.println("上一个任务结束 3 秒后执行"),
    0,
    3, TimeUnit.SECONDS
);
```

## CompletionService

`CompletionService` 解耦任务提交和结果获取——哪个先完成就先处理哪个：

```java
ExecutorService pool = Executors.newFixedThreadPool(4);
CompletionService<String> cs = new ExecutorCompletionService<>(pool);

// 提交多个任务
List<Callable<String>> tasks = List.of(
    () -> { Thread.sleep(3000); return "慢任务"; },
    () -> { Thread.sleep(500);  return "快任务"; },
    () -> { Thread.sleep(2000); return "中等任务"; }
);

for (Callable<String> task : tasks) {
    cs.submit(task);
}

// 按完成顺序获取结果
for (int i = 0; i < tasks.size(); i++) {
    Future<String> future = cs.take();  // 阻塞等待下一个完成的任务
    String result = future.get();
    System.out.println("完成: " + result);
}
// 输出顺序：快任务 → 中等任务 → 慢任务
```

## 线程池监控与调优

```java
// ThreadPoolExecutor 的监控方法
ThreadPoolExecutor pool = (ThreadPoolExecutor) executor;

int activeCount = pool.getActiveCount();       // 当前活跃线程数
long completed = pool.getCompletedTaskCount();  // 已完成任务数
long taskCount = pool.getTaskCount();           // 总任务数
int queueSize = pool.getQueue().size();         // 队列中等待的任务数
int corePoolSize = pool.getCorePoolSize();      // 核心线程数
int maxPoolSize = pool.getMaximumPoolSize();    // 最大线程数

// 动态调整
pool.setCorePoolSize(8);                       // 调整核心线程数
pool.setMaximumPoolSize(16);                   // 调整最大线程数
```

### 线程池大小公式

```
CPU 密集型（计算为主）：
  线程数 = CPU 核数 + 1

IO 密集型（等待为主）：
  线程数 = CPU 核数 × 2  （粗略）
  线程数 = CPU 核数 × (1 + 平均等待时间 / 平均计算时间)  （精确）

混合型：
  拆成两个线程池分别处理 CPU 密集和 IO 密集任务
```

## 应用场景实战

### 场景一：生产环境线程池配置

```java
public class ThreadPoolFactory {
    public static ThreadPoolExecutor create(String poolName, 
                                             int coreSize, int maxSize,
                                             int queueCapacity) {
        return new ThreadPoolExecutor(
            coreSize,
            maxSize,
            60L, TimeUnit.SECONDS,
            new ArrayBlockingQueue<>(queueCapacity),  // 有界队列！
            new ThreadFactory() {
                private final AtomicInteger counter = new AtomicInteger(1);
                @Override
                public Thread newThread(Runnable r) {
                    Thread t = new Thread(r, poolName + "-" + counter.getAndIncrement());
                    t.setDaemon(false);
                    t.setUncaughtExceptionHandler((thread, ex) -> 
                        log.error("线程池 {} 异常: {}", poolName, ex));
                    return t;
                }
            },
            new ThreadPoolExecutor.CallerRunsPolicy()  // 拒绝时让调用者执行
        );
    }
}
```

### 场景二：动态线程池参数

```java
// 线程池参数需要随业务负载调整
// 关键：有界队列 + 明确的拒绝策略 + 监控

ThreadPoolExecutor pool = ThreadPoolFactory.create(
    "order-processor",
    Runtime.getRuntime().availableProcessors(),
    Runtime.getRuntime().availableProcessors() * 2,
    1000  // 队列容量
);

// 监控告警
ScheduledExecutorService monitor = Executors.newSingleThreadScheduledExecutor();
monitor.scheduleAtFixedRate(() -> {
    int queueSize = pool.getQueue().size();
    if (queueSize > pool.getQueue().remainingCapacity() * 0.8) {
        log.warn("线程池队列使用率 > 80%: {}/{}", 
                 queueSize, pool.getQueue().remainingCapacity() + queueSize);
    }
}, 0, 5, TimeUnit.SECONDS);
```

### 场景三：优雅关闭

```java
public static void shutdownGracefully(ExecutorService pool, long timeout, TimeUnit unit) {
    pool.shutdown();  // 不再接受新任务
    try {
        if (!pool.awaitTermination(timeout, unit)) {
            pool.shutdownNow();  // 超时——强制停止
            if (!pool.awaitTermination(5, TimeUnit.SECONDS)) {
                log.error("线程池无法终止");
            }
        }
    } catch (InterruptedException e) {
        pool.shutdownNow();
        Thread.currentThread().interrupt();
    }
}
```

## 最佳实践与踩坑记录

### 常见问题表

| 问题 | 原因 | 修复 |
|------|------|------|
| OOM | 用了无界队列 `LinkedBlockingQueue<>()` | 用 `ArrayBlockingQueue` 指定容量 |
| OOM（线程太多） | `CachedThreadPool` 无上限 | 用自定义 `ThreadPoolExecutor` |
| 任务"丢失" | 用了 `DiscardPolicy` | 用 `CallerRunsPolicy` 或记录日志 |
| `Future.get()` 永远阻塞 | 任务被丢弃或异常未处理 | 捕获异常 + 超时等待 |
| `shutdown` 后线程不退出 | 线程中用了阻塞操作 | `shutdownNow` + 中断支持 |

### 自定义线程池检查清单

```
[ ] 使用有界队列（ArrayBlockingQueue）
[ ] 自定义 ThreadFactory（线程名 + 异常处理器）
[ ] 明确的拒绝策略（建议 CallerRunsPolicy）
[ ] 核心参数可配置（配置文件或配置中心）
[ ] 加入监控（队列大小、活跃线程数、拒绝次数）
[ ] 优雅关闭（shutdown + awaitTermination）
```

## 总结

- Executor 框架：`Executor` → `ExecutorService` → `ThreadPoolExecutor`
- 线程池工作流程：核心线程 → 队列 → 最大线程 → 拒绝策略
- 绝对不要用 `Executors.xxx()` 创建线程池——无界队列或无界线程数随时 OOM
- 关键配置：有界队列 + 自定义 ThreadFactory + CallerRunsPolicy + 监控
- `CompletionService` 按完成顺序取结果，适合批量异步任务
- 线程数公式：CPU 密集型 = 核数+1；IO 密集型 = 核数×2
- 动态参数：`setCorePoolSize` / `setMaximumPoolSize`，但队列容量一旦创建不可改

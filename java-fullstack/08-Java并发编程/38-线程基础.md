## 概述

线程（Thread）是操作系统调度的最小单位——一个进程可以包含多个线程，它们共享进程的堆和方法区，但各自拥有独立的栈和程序计数器。

Java 从语言级别内置了多线程支持：`Thread` 类和 `Runnable` 接口是 JDK 1.0 就存在的，`Callable` + `Future` 是 JDK 5 加入的。

## 进程 vs 线程

| 维度 | 进程 (Process) | 线程 (Thread) |
|------|---------------|---------------|
| 资源 | 独立的地址空间和系统资源 | 共享进程的内存（堆、方法区） |
| 通信 | IPC（管道、Socket、共享内存），开销大 | 共享内存，开销小 |
| 创建开销 | 大（需要分配独立地址空间） | 小（只需分配栈和寄存器） |
| 崩溃影响 | 一个进程崩溃不影响其他进程 | 一个线程崩溃可能导致整个进程退出 |
| 调度 | 操作系统调度进程 | 进程内调度线程 |

Java 中每个线程对应一个 OS 线程（JDK 21 虚拟线程之前）。

## 创建线程的四种方式

### 方式一：继承 Thread

```java
class MyThread extends Thread {
    @Override
    public void run() {
        System.out.println(Thread.currentThread().getName() + " 正在执行");
    }
}

MyThread t = new MyThread();
t.start();  // 启动线程，JVM 调用 run()
```

不推荐——Java 是单继承，继承了 Thread 就不能再继承别的类。

### 方式二：实现 Runnable（推荐）

```java
class MyTask implements Runnable {
    @Override
    public void run() {
        System.out.println(Thread.currentThread().getName() + " 正在执行");
    }
}

Thread t = new Thread(new MyTask());
t.start();

// Lambda 简化
Thread t2 = new Thread(() -> System.out.println("执行中..."));
t2.start();
```

任务和线程分离，更灵活——任务可以提交给线程池。

### 方式三：实现 Callable + FutureTask

```java
import java.util.concurrent.Callable;
import java.util.concurrent.FutureTask;

Callable<Integer> task = () -> {
    Thread.sleep(1000);
    return 42;
};

FutureTask<Integer> futureTask = new FutureTask<>(task);
Thread t = new Thread(futureTask);
t.start();
Integer result = futureTask.get();  // 阻塞等待结果，返回 42
```

与 Runnable 的区别：Callable 有返回值，可以抛出 checked exception。

### 方式四：线程池（推荐用于生产）

```java
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;

ExecutorService executor = Executors.newFixedThreadPool(4);
executor.submit(() -> System.out.println("任务执行"));
executor.submit(() -> 42);  // Callable 有返回值

executor.shutdown();  // 不再接受新任务，等待已有任务完成
```

## 线程生命周期与状态

Java 线程有 6 种状态（`Thread.State` 枚举）：

```
         NEW
          │  start()
          ▼
       RUNNABLE ←──────┐
       │      │        │
       │   (cpu调度)    │
       ▼      ▼        │
  BLOCKED  WAITING ────┘
  (等锁)   TIMED_WAITING
              │
              ▼
          TERMINATED
```

| 状态 | 说明 | 进入条件 |
|------|------|----------|
| NEW | 线程对象已创建，还没 start | `new Thread()` |
| RUNNABLE | 可运行（含正在运行和等待 CPU） | `start()` 调用后 |
| BLOCKED | 阻塞，等待获取锁 | `synchronized` 竞争失败 |
| WAITING | 无限等待，直到被唤醒 | `wait()`、`join()`、`LockSupport.park()` |
| TIMED_WAITING | 限时等待 | `sleep(ms)`、`wait(ms)`、`join(ms)` |
| TERMINATED | 线程已结束 | run() 执行完毕或异常退出 |

```java
Thread t = new Thread(() -> {
    try { Thread.sleep(2000); } catch (InterruptedException e) { }
});
System.out.println(t.getState());  // NEW

t.start();
System.out.println(t.getState());  // RUNNABLE

Thread.sleep(500);
System.out.println(t.getState());  // TIMED_WAITING

t.join();
System.out.println(t.getState());  // TERMINATED
```

## start vs run

这是个面试高频题——也是生产环境常见 bug：

```java
Thread t = new Thread(() -> System.out.println("执行"));
t.run();    // 错误！只是在当前线程调用 run()，没有启动新线程
t.start();  // 正确！JVM 创建新线程并调用 run()
```

`start()` 只能调用一次——重复调用抛 `IllegalThreadStateException`。

## sleep 与 interrupt

```java
// sleep —— 让当前线程暂停指定毫秒数
Thread.sleep(1000);  // 暂停 1 秒

// interrupt —— 中断线程（协作式中断，不是强制停止）
Thread t = new Thread(() -> {
    while (!Thread.currentThread().isInterrupted()) {
        // 工作...
        try {
            Thread.sleep(100);
        } catch (InterruptedException e) {
            // sleep 期间被 interrupt 会抛 InterruptedException
            // 并且中断标志被清除！
            Thread.currentThread().interrupt();  // 重新设置中断标志
            break;
        }
    }
});
t.start();
t.interrupt();  // 发送中断信号
```

关键规则：
1. `interrupt()` 不会强制停止线程——只是设置一个中断标志
2. `sleep()`/`wait()`/`join()` 被中断时会抛 `InterruptedException` 并**清除**中断标志
3. 捕获 `InterruptedException` 后如果要保留中断状态，必须调用 `Thread.currentThread().interrupt()`

## join —— 等待线程完成

```java
Thread t1 = new Thread(() -> {
    try { Thread.sleep(1000); } catch (InterruptedException e) { }
    System.out.println("t1 完成");
});
t1.start();

t1.join();  // 当前线程阻塞，等待 t1 执行完毕
System.out.println("主线程继续");

// join(timeout) —— 最多等多少毫秒
t1.join(500);  // 最多等 500ms，超时不再等
```

## daemon 守护线程

守护线程在后台运行，当所有非守护线程结束时 JVM 自动退出，不管守护线程是否执行完：

```java
Thread daemon = new Thread(() -> {
    while (true) {
        System.out.println("守护线程工作中...");
        try { Thread.sleep(1000); } catch (InterruptedException e) { break; }
    }
});
daemon.setDaemon(true);  // 必须在 start() 前设置
daemon.start();

Thread.sleep(3000);
System.out.println("主线程结束——守护线程也会跟着退出");
```

典型用途：GC 线程、自动保存线程、心跳检测线程。注意：守护线程的 `finally` 块可能不会执行——JVM 退出时不等待它们。

## 线程优先级

```java
Thread t = new Thread(...);
t.setPriority(Thread.MAX_PRIORITY);  // 10（最高）
t.setPriority(Thread.NORM_PRIORITY); // 5（默认）
t.setPriority(Thread.MIN_PRIORITY);  // 1（最低）
```

优先级是**建议**——最终由 OS 调度器决定，不同平台行为不一致。不要依赖优先级来保证程序的正确性。

## 应用场景实战

### 场景一：异步发送通知

```java
public class NotificationService {
    public void sendAsync(String userId, String message) {
        new Thread(() -> {
            try {
                pushNotification(userId, message);
            } catch (Exception e) {
                log.error("通知发送失败", e);
            }
        }, "notification-" + userId).start();
    }
}
```

### 场景二：并行计算耗时操作

```java
public class ParallelProcessor {
    public static int sum(List<Integer> numbers) throws Exception {
        List<Callable<Integer>> tasks = new ArrayList<>();
        int mid = numbers.size() / 2;
        
        tasks.add(() -> numbers.subList(0, mid).stream().mapToInt(Integer::intValue).sum());
        tasks.add(() -> numbers.subList(mid, numbers.size()).stream().mapToInt(Integer::intValue).sum());
        
        ExecutorService executor = Executors.newFixedThreadPool(2);
        int total = 0;
        for (Future<Integer> future : executor.invokeAll(tasks)) {
            total += future.get();
        }
        executor.shutdown();
        return total;
    }
}
```

### 场景三：超时控制

```java
public static <T> T executeWithTimeout(Callable<T> task, long timeout, TimeUnit unit) 
        throws Exception {
    ExecutorService executor = Executors.newSingleThreadExecutor();
    Future<T> future = executor.submit(task);
    try {
        return future.get(timeout, unit);
    } catch (TimeoutException e) {
        future.cancel(true);
        throw new RuntimeException("任务超时");
    } finally {
        executor.shutdownNow();
    }
}
```

## 最佳实践与踩坑记录

### 常见问题表

| 问题 | 原因 | 修复 |
|------|------|------|
| `start()` 两次抛异常 | 线程只能启动一次 | 检查状态或用线程池 |
| 调用 `run()` 而不是 `start()` | 误解 API | 用 `start()` 启动新线程 |
| 捕获 `InterruptedException` 后标志丢失 | sleep 会清除中断标志 | 重新调 `Thread.currentThread().interrupt()` |
| 守护线程 finally 不执行 | JVM 退出时不等待守护线程 | 核心逻辑不用守护线程 |
| `Thread.stop()` 造成数据不一致 | 强制停止释放所有锁中途状态 | 永远不用 stop()——用 interrupt 协作停止 |

### 线程命名

```java
// 正确：给线程起有意义的名字
Thread t = new Thread(task, "order-processor-1");

// 线程池自定义线程工厂
ThreadFactory factory = r -> {
    Thread t = new Thread(r, "worker-" + counter.getAndIncrement());
    t.setDaemon(false);
    return t;
};
// 生产事故排查时第一个看的就是线程名
```

## 总结

- `Runnable` 是任务抽象（无返回值），`Callable` 有返回值+可抛异常
- 推荐用实现 `Runnable` + 线程池的方式创建线程
- 线程 6 种状态：NEW → RUNNABLE → 各种 WAITING/BLOCKED → TERMINATED
- `start()` 启动新线程，`run()` 只是普通方法调用
- `interrupt()` 是协作式中断，配合 `isInterrupted()` + `sleep` 的 `InterruptedException` 使用
- `join()` 让当前线程等待目标线程结束
- 守护线程在非守护线程全部结束后自动退出，`finally` 可能不执行

## 概述

并发集合（`java.util.concurrent`）是线程安全的数据结构——比用 `synchronized` 包装普通集合高效得多。它们不是简单地给每个方法加锁，而是通过细粒度锁、CAS、写时复制等技术实现高并发。

```
并发集合体系：
├── Map
│   ├── ConcurrentHashMap           —— 分段/桶锁（最常用）
│   └── ConcurrentSkipListMap       —— 跳表（排序+并发）
├── List / Set
│   ├── CopyOnWriteArrayList        —— 写时复制（读多写极少）
│   └── CopyOnWriteArraySet         —— 基于 CopyOnWriteArrayList
├── Queue / Deque
│   ├── ConcurrentLinkedQueue       —— CAS 无界队列
│   ├── ConcurrentLinkedDeque       —— CAS 双端队列
│   ├── ArrayBlockingQueue          —— 有界阻塞队列
│   ├── LinkedBlockingQueue         —— 可选有界阻塞队列
│   ├── PriorityBlockingQueue       —— 优先级阻塞队列
│   ├── SynchronousQueue            —— 无容量传递队列
│   └── DelayQueue                  —— 延迟队列
└── Set
    └── ConcurrentSkipListSet       —— 基于 ConcurrentSkipListMap
```

## 并发集合 vs 同步包装器

```java
// 错误方式：Collections.synchronizedXxx —— 方法级锁，并发度低
Map<String, String> syncMap = Collections.synchronizedMap(new HashMap<>());
// 每个方法都加了 synchronized，所有操作互斥

// 正确方式：并发集合 —— 细粒度锁，并发度高
ConcurrentHashMap<String, String> map = new ConcurrentHashMap<>();
// 桶级别锁，不同桶的操作可以并发
```

| 维度 | synchronized 包装器 | 并发集合 |
|------|---------------------|----------|
| 锁粒度 | 整个集合 | 桶/分段/无锁 |
| 并发度 | 1（所有操作互斥） | 高（不同桶可并发） |
| 迭代器 | Fail-Fast（抛 CME） | Fail-Safe（弱一致性） |
| 复合操作 | 需要外部同步 | 提供原子复合操作 |
| 性能 | 高竞争下很差 | 高竞争下优秀 |

## ConcurrentHashMap

ConcurrentHashMap 已在 24-Map 和 26-集合底层原理 中详细介绍，这里只做并发相关的补充：

```java
ConcurrentHashMap<String, Integer> map = new ConcurrentHashMap<>();

// 原子复合操作 —— 不需要外部同步
map.putIfAbsent("a", 1);                          // key 不存在才放
map.remove("a", 1);                               // key-value 匹配才删
map.replace("a", 1, 2);                           // old=1 才替换为 2
map.replace("a", 2);                              // key 存在就替换

// 原子计算
map.computeIfAbsent("counter", k -> new AtomicInteger()).incrementAndGet();
map.compute("key", (k, v) -> v == null ? 1 : v + 1);
map.merge("count", 1, Integer::sum);

// 批量操作
map.forEachKey(10, k -> System.out.println(k));   // 并行遍历（阈值 10）
map.search(10, (k, v) -> v > 100 ? k : null);     // 并行搜索

// 视图 —— 返回 ConcurrentHashMap 的新实例，不是 ConcurrentHashMap
ConcurrentHashMap.KeySetView<String, Integer> keys = map.keySet();
// keys.add("newKey") 等同于 map.put("newKey", null) 的逻辑
```

## CopyOnWriteArrayList / CopyOnWriteArraySet

写时复制——写操作加锁 + 复制整个数组，读操作无锁：

```java
CopyOnWriteArrayList<String> list = new CopyOnWriteArrayList<>();
list.add("a");
list.add("b");

// 读操作——无锁，直接读数组
String s = list.get(0);
boolean has = list.contains("a");

// 写操作——加 ReentrantLock，复制数组，追加，替换引用
list.add("c");          // 拿到锁 → Arrays.copyOf → 追加 → 替换引用 → 释放锁
list.remove("a");       // 同上
list.set(1, "updated"); // 同上

// 迭代器是"快照"——遍历期间其他线程的写不影响当前迭代
for (String item : list) {
    list.add("new");    // 不影响本次迭代！
}
```

适用：**读多写极少**——黑名单、监听器列表、配置列表。不适用：写频繁（每次写复制全数组）。

## BlockingQueue

BlockingQueue 已在 25-Queue 中详细介绍，这里做并发方面的补充：

```java
// ArrayBlockingQueue —— 有界，数组，单锁
BlockingQueue<String> abq = new ArrayBlockingQueue<>(100);

// LinkedBlockingQueue —— 可选有界，双锁（putLock + takeLock）
BlockingQueue<String> lbq = new LinkedBlockingQueue<>(1000);

// PriorityBlockingQueue —— 无界，按优先级
// SynchronousQueue —— 容量 0，直接传递
// DelayQueue —— 延迟到期才能取出
```

BlockingQueue 的核心价值：生产者-消费者模型的并发安全实现，`put/take` 自动处理阻塞和唤醒。

## ConcurrentLinkedQueue / ConcurrentLinkedDeque

基于 CAS 的无锁并发队列——非阻塞，适用于"不需要阻塞等待"的场景：

```java
ConcurrentLinkedQueue<String> queue = new ConcurrentLinkedQueue<>();

// offer / poll —— 非阻塞
queue.offer("a");         // CAS 入队
queue.offer("b");
String item = queue.poll(); // CAS 出队 → "a"

// peek —— 查看队列头
String head = queue.peek();

// size() —— 不精确！遍历计数，开销 O(n)
int approxSize = queue.size();  // 并发场景下只是近似值
```

适用：消息传递、事件分发——不需要阻塞等待，需要高吞吐。

## ConcurrentSkipListMap / ConcurrentSkipListSet

基于**跳表**（Skip List）的并发有序 Map/Set——TreeMap/TreeSet 的并发替代：

```java
ConcurrentSkipListMap<String, Integer> map = new ConcurrentSkipListMap<>();
map.put("c", 3);
map.put("a", 1);
map.put("b", 2);
// 自动排序：{a=1, b=2, c=3}

// 支持范围操作（并发安全）
map.headMap("c");
map.tailMap("b");
map.subMap("a", "c");

// ConcurrentSkipListSet
ConcurrentSkipListSet<String> set = new ConcurrentSkipListSet<>();
set.add("c");
set.add("a");
// 自动排序：[a, c]
```

## 应用场景实战

### 场景一：ConcurrentHashMap 实现本地缓存

```java
public class LocalCache<K, V> {
    private final ConcurrentHashMap<K, V> cache = new ConcurrentHashMap<>();

    public V get(K key, Function<K, V> loader) {
        return cache.computeIfAbsent(key, loader);  // 原子惰性加载
    }

    public void put(K key, V value) {
        cache.put(key, value);
    }

    public void invalidate(K key) {
        cache.remove(key);
    }

    public void clear() {
        cache.clear();
    }
}
```

### 场景二：BlockingQueue 实现任务调度

```java
public class TaskDispatcher {
    private final BlockingQueue<Task> queue = new LinkedBlockingQueue<>(100);

    public void startWorkers(int n) {
        for (int i = 0; i < n; i++) {
            new Thread(() -> {
                while (true) {
                    try {
                        Task task = queue.take();  // 阻塞等待
                        task.execute();
                    } catch (InterruptedException e) {
                        Thread.currentThread().interrupt();
                        break;
                    }
                }
            }, "worker-" + i).start();
        }
    }

    public boolean submit(Task task) {
        return queue.offer(task);  // 队列满返回 false
    }
}
```

### 场景三：CopyOnWriteArrayList 监听器管理

```java
public class EventSource {
    private final List<EventListener> listeners = new CopyOnWriteArrayList<>();

    public void addListener(EventListener listener) {
        listeners.add(listener);  // 写——很少调用
    }

    public void fireEvent(Event event) {
        for (EventListener listener : listeners) {  // 读——频繁调用
            listener.onEvent(event);
        }
    }
}
```

## 最佳实践与选型指南

### 选型体系

```
需要什么样的线程安全集合？

Map?
├── 不需要排序 → ConcurrentHashMap
└── 需要排序 → ConcurrentSkipListMap

List?
├── 读多写极少 → CopyOnWriteArrayList
└── 读写都有 → Collections.synchronizedList 或外部加锁

Set?
├── 基于 Map → ConcurrentHashMap.newKeySet()
├── 读多写极少 → CopyOnWriteArraySet
└── 需要排序 → ConcurrentSkipListSet

Queue?
├── 需要阻塞等待 → BlockingQueue
│   ├── 有界/数组 → ArrayBlockingQueue
│   ├── 有界/链表 → LinkedBlockingQueue
│   └── 优先级 → PriorityBlockingQueue
├── 不需要阻塞 → ConcurrentLinkedQueue
└── 延迟任务 → DelayQueue
```

### 常见问题表

| 问题 | 原因 | 修复 |
|------|------|------|
| `ConcurrentHashMap.size()` 不精确 | 并发环境下的近似值 | 需要精确值的场景外部同步 |
| `CopyOnWriteArrayList` 写太多导致 OOM | 每次写入复制全数组 | 换 `Collections.synchronizedList` |
| `ConcurrentLinkedQueue.size()` 慢 | 需要遍历整个链表 O(n) | 避免频繁调用 size() |
| BlockingQueue 死锁 | 满或空时阻塞+互相等待 | 用 `offer/poll` 超时版本 |

## 总结

- 并发集合 > 同步包装器——锁粒度细、支持原子复合操作、Fail-Safe 迭代
- `ConcurrentHashMap` 是并发场景的默认 Map——桶锁、原子 compute/merge、批量操作
- `CopyOnWriteArrayList` 读无锁写复制——只适合读多写极少的场景
- `BlockingQueue` 是生产者消费者模式的基石——`put/take` 阻塞等待
- `ConcurrentLinkedQueue` 基于 CAS——高吞吐、不需要阻塞时使用
- `ConcurrentSkipListMap` 跳表实现——TreeMap 的并发替代

## 概述

原子类（`java.util.concurrent.atomic`）是无锁线程安全的利器——基于 CAS（Compare-And-Swap）指令，不依赖 synchronized/Lock，性能极高。适合计数器、标志位、引用更新等简单状态管理。

四大家族：

| 类别 | 类 | 用途 |
|------|-----|------|
| 基本类型 | `AtomicInteger`、`AtomicLong`、`AtomicBoolean` | 整数/布尔值的原子更新 |
| 引用类型 | `AtomicReference`、`AtomicStampedReference`、`AtomicMarkableReference` | 对象引用的原子更新 |
| 数组 | `AtomicIntegerArray`、`AtomicLongArray`、`AtomicReferenceArray` | 数组元素的原子更新 |
| 累加器 | `LongAdder`、`DoubleAdder`、`LongAccumulator`、`DoubleAccumulator` | 高并发累加（分散热点） |

## CAS 原理

CAS 是原子类的基石——一条 CPU 指令完成"比较并交换"：

```
CAS(V, expected, newValue)

伪代码：
if (V == expected) {
    V = newValue;
    return true;
} else {
    return false;
}

整个过程是原子的——CPU 通过总线锁定（或缓存锁定）保证
```

```java
// AtomicInteger.incrementAndGet() 的简化逻辑
public final int incrementAndGet() {
    for (;;) {                         // 自旋
        int current = get();           // 读取当前值
        int next = current + 1;        // 计算新值
        if (compareAndSet(current, next)) {  // CAS
            return next;               // 成功返回
        }
        // 失败 → 重试（自旋）
    }
}
```

关键特征：
- **无锁**：不阻塞线程，失败自旋重试
- **性能高**：无上下文切换，适合低竞争场景
- **ABA 问题**：值从 A→B→A，CAS 检测不到变化（后面会讲）

## AtomicInteger / AtomicLong / AtomicBoolean

```java
import java.util.concurrent.atomic.AtomicInteger;

AtomicInteger counter = new AtomicInteger(0);
AtomicInteger init10  = new AtomicInteger(10);

// 基本操作
int v = counter.get();               // 获取当前值
counter.set(100);                    // 设置新值
int old = counter.getAndSet(200);    // 设置新值并返回旧值

// 原子递增/递减
counter.incrementAndGet();           // ++counter
counter.getAndIncrement();           // counter++
counter.decrementAndGet();           // --counter
counter.getAndDecrement();           // counter--

// 原子加减
counter.addAndGet(5);                // counter += 5
counter.getAndAdd(5);                // 返回旧值，counter += 5

// CAS 操作
boolean success = counter.compareAndSet(100, 200);  // 如果是 100 就改成 200

// 函数式更新（JDK 8+）
counter.updateAndGet(x -> x * 2);    // 原子翻倍
counter.getAndUpdate(x -> x + 1);    // 返回旧值 + 原子更新
counter.accumulateAndGet(3, (x, y) -> x + y);  // 原子累加

// AtomicBoolean
AtomicBoolean flag = new AtomicBoolean(false);
flag.set(true);
boolean old = flag.getAndSet(false);  // 设为 false 并返回旧值 true
```

## AtomicReference

```java
import java.util.concurrent.atomic.AtomicReference;

AtomicReference<User> ref = new AtomicReference<>(new User("张三"));

// 原子更新引用
User newUser = new User("李四");
ref.set(newUser);
User old = ref.getAndSet(new User("王五"));

// CAS 更新
ref.compareAndSet(oldUser, newUser);

// 函数式更新（JDK 8+）
ref.updateAndGet(u -> new User(u.getName().toUpperCase()));
```

典型场景：无锁栈顶更新、配置热更新。

## LongAdder 与 LongAccumulator

JDK 8 引入——高并发累加场景下性能远超 `AtomicLong`：

```java
import java.util.concurrent.atomic.LongAdder;
import java.util.concurrent.atomic.LongAccumulator;

// LongAdder —— 分散热点
LongAdder adder = new LongAdder();
adder.add(1);
adder.add(10);
adder.increment();           // +1
long sum = adder.sum();      // 获取总和
adder.reset();               // 重置为 0

// LongAccumulator —— 自定义累加函数
LongAccumulator maxAccum = new LongAccumulator(Long::max, Long.MIN_VALUE);
maxAccum.accumulate(10);
maxAccum.accumulate(5);
maxAccum.accumulate(30);
long max = maxAccum.get();   // 30 —— 最大值
```

LongAdder 的原理——**分散热点**：

```
AtomicLong：所有线程竞争同一个变量
  Thread 1 ──┐
  Thread 2 ──┼── CAS ──→ count
  Thread 3 ──┘

LongAdder：每个线程写到自己的 Cell，最后求和
  Thread 1 → Cell[0] = 100
  Thread 2 → Cell[2] = 300    sum() → 100 + 300 + 200 = 600
  Thread 3 → Cell[1] = 200

  cells 数组在竞争加剧时动态扩展
```

性能对比（多线程并发累加）：LongAdder >> AtomicLong，尤其在核心数多的机器上。

## ABA 问题与 AtomicStampedReference

```java
// ABA 问题场景：
// 1. 线程 A 读到值 = A
// 2. 线程 B 把 A → B → A
// 3. 线程 A 用 CAS：期望值 A，实际值 A —— CAS 成功！
// 但 A 不知道值曾经变成了 B

// 解决：AtomicStampedReference —— 加版本号
import java.util.concurrent.atomic.AtomicStampedReference;

AtomicStampedReference<String> ref = new AtomicStampedReference<>("A", 0);

int[] stamp = new int[1];
String value = ref.get(stamp);         // 获取值和版本号

boolean ok = ref.compareAndSet(
    "A", "B",                           // 期望值 → 新值
    stamp[0], stamp[0] + 1              // 期望版本 → 新版本
);

// AtomicMarkableReference —— 简化版，只有一个 boolean 标记
```

## 应用场景实战

### 场景一：全局请求计数

```java
public class MetricsCollector {
    private final LongAdder totalRequests = new LongAdder();
    private final LongAdder errorRequests = new LongAdder();

    public void recordRequest(boolean success) {
        totalRequests.increment();
        if (!success) errorRequests.increment();
    }

    public long getTotal() { return totalRequests.sum(); }
    public long getErrorRate() {
        long total = totalRequests.sum();
        return total == 0 ? 0 : errorRequests.sum() * 100 / total;
    }
}
```

### 场景二：无锁对象池

```java
public class LockFreeStack<T> {
    private static class Node<T> {
        final T value;
        Node<T> next;
        Node(T value) { this.value = value; }
    }

    private final AtomicReference<Node<T>> top = new AtomicReference<>();

    public void push(T value) {
        Node<T> newNode = new Node<>(value);
        Node<T> oldTop;
        do {
            oldTop = top.get();
            newNode.next = oldTop;
        } while (!top.compareAndSet(oldTop, newNode));  // 自旋 CAS
    }

    public T pop() {
        Node<T> oldTop;
        Node<T> newTop;
        do {
            oldTop = top.get();
            if (oldTop == null) return null;
            newTop = oldTop.next;
        } while (!top.compareAndSet(oldTop, newTop));
        return oldTop.value;
    }
}
```

### 场景三：序列号生成器

```java
public class SequenceGenerator {
    private final AtomicLong sequence = new AtomicLong(0);

    public long next() {
        return sequence.incrementAndGet();
    }

    public long[] nextBatch(int n) {
        long start = sequence.getAndAdd(n);
        long[] ids = new long[n];
        for (int i = 0; i < n; i++) {
            ids[i] = start + i + 1;
        }
        return ids;
    }
}
```

### 场景四：配置热更新

```java
public class ConfigManager {
    private final AtomicReference<Config> configRef = new AtomicReference<>(new Config());

    public Config getConfig() {
        return configRef.get();  // 无锁读取最新配置
    }

    public void update(Function<Config, Config> updater) {
        configRef.updateAndGet(updater);  // 原子更新
    }
}
```

## 最佳实践与踩坑记录

### 选型指南

| 场景 | 推荐 |
|------|------|
| 简单计数器（低竞争） | `AtomicInteger` / `AtomicLong` |
| 高并发累加（统计） | `LongAdder` |
| 对象引用 CAS | `AtomicReference` |
| 带版本号的 CAS（防 ABA） | `AtomicStampedReference` |
| 数组元素 CAS | `AtomicIntegerArray` 等 |
| 条件标记 | `AtomicBoolean` |

### 常见问题表

| 问题 | 原因 | 修复 |
|------|------|------|
| `incrementAndGet()` 在高竞争下变慢 | CAS 自旋消耗 CPU | 换成 `LongAdder` |
| AtomicReference ABA 导致逻辑错 | 值被改回原值 | `AtomicStampedReference` 加版本号 |
| `LongAdder.sum()` 不是原子快照 | sum 遍历 cells 时可能被更新 | 如果必须精确，用 `AtomicLong` |
| 误用 `LongAdder.reset()` 丢失数据 | reset 不返回旧值 | 用 `sumThenReset()` |

### 性能考量

```
低竞争（< 4 线程）：AtomicLong ≈ LongAdder
中竞争（4-8）：LongAdder 快 2-3 倍
高竞争（> 8）：LongAdder 快 10 倍以上

CAS 失败自旋的代价：
- 竞争激烈时 CPU 空转
- 不适合长时间持有"锁"的复杂操作
- 简单的读写操作（计数器、标志位）是最佳场景
```

## 总结

- CAS = Compare-And-Swap，一条原子 CPU 指令，无锁并发的基础
- 原子类分四类：基本类型、引用、数组、累加器
- `LongAdder` 用分散热点解决高并发累加瓶颈，性能远超 `AtomicLong`
- `AtomicStampedReference` 用版本号解决 ABA 问题
- 原子类适合简单状态操作（计数、标记、引用更新），复杂逻辑仍需锁
- 无锁 ≠ 无条件最优——竞争激烈时 CAS 自旋消耗 CPU，不如锁+阻塞

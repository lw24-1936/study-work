## 概述

Web 安全防范各类攻击，是每个后端开发者的基本素养。

```text
OWASP Top 10（常见 Web 风险）：
1. 注入（SQL 注入等）
2. 失效的认证
3. 敏感数据泄露
4. XXE
5. 失效的访问控制
6. 安全配置错误
7. XSS
8. 不安全的反序列化
9. 使用有漏洞的组件
10. 日志记录不足
```

## XSS 跨站脚本

XSS（Cross-Site Scripting）是攻击者注入恶意脚本，在受害者浏览器执行。

### XSS 类型

```text
1. 反射型 —— 脚本在 URL 参数，反射回页面
2. 存储型 —— 脚本存到数据库，展示时执行
3. DOM 型 —— 前端 JS 处理导致
```

### XSS 攻击示例

```html
<!-- 攻击者提交评论（存储型 XSS） -->
<script>document.cookie 发给攻击者服务器</script>

<!-- 其他用户查看评论时，脚本执行，cookie 被盗 -->
```

### XSS 防护

```text
1. 输出转义 —— 展示用户输入时转义 HTML
2. 输入过滤 —— 过滤危险标签
3. HttpOnly Cookie —— JS 无法读取 cookie
```

```java
// 转义 HTML（输出时）
public String escapeHtml(String input) {
    return input.replace("&", "&amp;")
        .replace("<", "&lt;")
        .replace(">", "&gt;")
        .replace("\"", "&quot;");
}
```

```text
Spring 防护：
1. Thymeleaf 默认转义（th:text 自动转义）
2. 手动转义用 HtmlUtils.htmlEscape()
3. 配置 HttpOnly Cookie
```

## CSRF 跨站请求伪造

CSRF（Cross-Site Request Forgery）是攻击者诱导用户执行非本意的操作。

### CSRF 攻击原理

```text
1. 用户登录了银行网站（有 cookie）
2. 用户访问恶意网站
3. 恶意网站伪造请求（转账），浏览器自动带 cookie
4. 银行以为是用户操作，执行转账
```

### CSRF 防护

```text
1. Token —— 请求带随机 token，服务端校验
2. SameSite Cookie —— 跨站不带 cookie
3. Referer 校验 —— 检查请求来源
```

```java
// Spring Security 的 CSRF 防护（默认开启）
// 表单带 CSRF token
http.csrf().csrfTokenRepository(...);
```

```text
注意：前后端分离 + JWT（token 在 header）天然防 CSRF
（攻击者无法伪造 Authorization header）
```

## SQL Injection SQL 注入

SQL 注入是攻击者注入恶意 SQL，执行非预期操作。

### SQL 注入示例

```java
// 危险的拼接
String sql = "SELECT * FROM users WHERE name = '" + name + "'";
// name = "' OR '1'='1"，变成：
// SELECT * FROM users WHERE name = '' OR '1'='1'  → 查出所有用户
```

### SQL 注入防护

```text
1. 参数化查询（PreparedStatement）—— 核心防护
2. 框架的 #{} —— MyBatis 的 #{} 是参数化
3. 输入校验 —— 校验输入格式
```

```java
// PreparedStatement 参数化（安全）
String sql = "SELECT * FROM users WHERE name = ?";
PreparedStatement ps = conn.prepareStatement(sql);
ps.setString(1, name);   // 参数绑定，不是拼接
```

```java
// MyBatis：#{} 安全（参数化），${} 危险（拼接）
// 安全
SELECT * FROM users WHERE name = #{name}

// 危险（${} 直接拼接，会有 SQL 注入）
SELECT * FROM users WHERE name = '${name}'
```

## SSRF 与 XXE

### SSRF 服务端请求伪造

```text
SSRF：攻击者诱导服务端请求内网地址，探测内网、读取敏感信息
```

```java
// 危险：URL 由用户控制，可能请求内网
String url = request.getParameter("url");
String result = httpClient.get(url);   // 可能请求 http://内网/敏感接口
```

```text
SSRF 防护：
1. 白名单 —— 只允许请求白名单域名
2. 禁止内网地址 —— 过滤 127.0.0.1、10.x、192.168.x
3. 限制协议 —— 只允许 http/https
```

### XXE XML 外部实体注入

```text
XXE：解析 XML 时引入外部实体，读取文件、发起请求
```

```xml
<!-- 恶意 XML -->
<!DOCTYPE foo [<!ENTITY xxe SYSTEM "file:///etc/passwd">]>
<foo>&xxe;</foo>
```

```text
XXE 防护：
1. 禁用外部实体（DocumentBuilderFactory 设置）
```

```java
DocumentBuilderFactory factory = DocumentBuilderFactory.newInstance();
factory.setFeature("http://apache.org/xml/features/disallow-doctype-decl", true);
factory.setFeature("http://xml.org/sax/features/external-general-entities", false);
```

## 文件上传与路径遍历

### 文件上传漏洞

```text
攻击者上传恶意文件（如 .jsp 木马），执行恶意代码
```

```text
防护：
1. 校验文件类型（扩展名 + 内容）
2. 限制文件大小
3. 文件重命名（随机名）
4. 存储到独立目录（不执行）
```

```java
// 文件上传防护
public void upload(MultipartFile file) {
    // 1. 校验扩展名
    String ext = getExtension(file.getOriginalFilename());
    if (!allowedExtensions.contains(ext)) {
        throw new IllegalArgumentException("不允许的文件类型");
    }

    // 2. 限制大小
    if (file.getSize() > MAX_SIZE) {
        throw new IllegalArgumentException("文件过大");
    }

    // 3. 随机文件名（防路径遍历 + 防覆盖）
    String newName = UUID.randomUUID() + "." + ext;
    file.transferTo(new File(uploadDir, newName));
}
```

### 路径遍历

```text
路径遍历：通过 ../ 访问任意文件
```

```java
// 危险：文件名直接拼接路径
String name = request.getParameter("name");   // name = "../../../etc/passwd"
File file = new File(baseDir, name);   // 可能访问任意文件

// 安全：规范化路径 + 校验在基础目录内
Path base = Paths.get(baseDir).normalize();
Path target = base.resolve(name).normalize();
if (!target.startsWith(base)) {
    throw new IllegalArgumentException("非法路径");
}
```

## 命令注入

命令注入是攻击者注入系统命令。

```java
// 危险：命令拼接用户输入
String cmd = "ping " + host;   // host = "8.8.8.8; rm -rf /"
Runtime.getRuntime().exec(cmd);
```

```text
防护：
1. 避免用 Runtime.exec 执行用户输入
2. 参数用 ProcessBuilder 的数组形式（不经过 shell）
3. 输入校验（白名单）
```

## 安全防护总结

| 攻击 | 核心防护 |
|------|---------|
| XSS | 输出转义、HttpOnly |
| CSRF | Token、SameSite |
| SQL 注入 | 参数化查询（#{}） |
| SSRF | 白名单、禁内网 |
| XXE | 禁用外部实体 |
| 文件上传 | 类型校验、重命名 |
| 路径遍历 | 规范化 + 校验 |
| 命令注入 | 避免 exec、参数化 |

```text
通用安全原则：
1. 不信任用户输入 —— 所有输入都要校验、过滤
2. 参数化 —— SQL/命令用参数化
3. 输出转义 —— 展示用户输入时转义
4. 最小权限 —— 限制文件和接口权限
5. 安全配置 —— 禁用危险功能（外部实体）
```

## 最佳实践与踩坑记录

### 最佳实践

1. **SQL 用参数化查询**。MyBatis 用 #{}，不用 ${}。

2. **输出转义**。展示用户输入时转义 HTML。

3. **文件上传要校验**。类型、大小、重命名。

4. **路径要规范化校验**。防止路径遍历。

5. **定期安全扫描**。用工具（如 OWASP ZAP）扫描。

### 踩坑记录

**坑 1：MyBatis 用 ${} 拼接**

```xml
SELECT * FROM users WHERE name = '${name}'   -- SQL 注入
```

用 #{} 参数化，${} 只用于表名/列名（且要白名单）。

**坑 2：只在前端校验**

```text
前端校验文件类型，后端不校验，可绕过
```

前端校验是体验，后端校验是安全（必须后端校验）。

**坑 3：路径拼接不做校验**

```java
new File(baseDir, filename)   // filename 含 ../，路径遍历
```

规范化路径 + 校验在基础目录内。

**坑 4：XML 解析不关外部实体**

```text
默认 XML 解析可能开启外部实体，XXE 攻击
```

显式禁用外部实体。

**坑 5：Cookie 没设 HttpOnly**

```text
Cookie 没 HttpOnly，XSS 能读取 cookie
```

Cookie 设 HttpOnly（+ Secure）。

**坑 6：URL 请求不校验（SSRF）**

```text
用户传 URL 直接请求，可能探测内网
```

白名单 + 禁内网地址。

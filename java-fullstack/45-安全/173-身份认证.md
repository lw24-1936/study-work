## 概述

身份认证是确认"你是谁"的过程，是系统安全的第一道门。

```text
认证（Authentication）vs 授权（Authorization）：
认证 —— 你是谁（登录验证身份）
授权 —— 你能做什么（权限控制）
```

```text
常见认证方案：
1. Session + Cookie —— 传统方案
2. JWT —— 无状态 token
3. OAuth2 —— 第三方授权
4. SSO —— 单点登录
5. MFA —— 多因素认证
```

## Session 与 Cookie

Session + Cookie 是传统认证方案，服务端存会话状态。

### 认证流程

```text
1. 用户登录，服务端验证密码
2. 服务端创建 Session（存用户信息），返回 SessionId
3. 客户端存 SessionId 到 Cookie
4. 后续请求带 Cookie，服务端根据 SessionId 找到 Session
```

```java
// 登录
@PostMapping("/login")
public void login(HttpSession session, String username, String password) {
    if (authService.verify(username, password)) {
        session.setAttribute("user", username);   // 存 Session
    }
}

// 获取当前用户
@GetMapping("/me")
public String me(HttpSession session) {
    return (String) session.getAttribute("user");
}
```

### Session 的优缺点

```text
优点：
1. 服务端可控 —— 可主动注销（踢下线）
2. 简单 —— 框架内置支持

缺点：
1. 有状态 —— 服务端存 Session，分布式要共享（Redis）
2. 扩展性差 —— 水平扩展需要 Session 共享
3. 跨域问题 —— Cookie 受同源限制
```

## JWT 认证

JWT 是无状态 token，用户信息在 token 里（详见 83-JWT）。

### 认证流程

```text
1. 用户登录，服务端签发 JWT
2. 客户端存 JWT（header 携带）
3. 后续请求带 JWT，服务端校验签名
```

```java
// 登录签发 JWT
@PostMapping("/login")
public String login(String username, String password) {
    if (authService.verify(username, password)) {
        return jwtUtil.generateToken(username);   // 签发 JWT
    }
    throw new AuthException("用户名或密码错误");
}
```

### JWT vs Session

| 维度 | Session | JWT |
|------|---------|-----|
| 状态 | 服务端存（有状态） | 无状态 |
| 存储 | 服务端 | 客户端 |
| 扩展 | 需 Session 共享 | 天然支持 |
| 注销 | 简单（删 Session） | 难（需黑名单） |
| 跨域 | 受限（Cookie） | 支持（Header） |
| 适用 | 传统 Web | 前后端分离、微服务 |

## OAuth2 与 OpenID Connect

### OAuth2 授权

OAuth2 是授权协议，让第三方应用访问用户资源（详见 84-OAuth2）。

```text
OAuth2 的场景：
"用微信登录" —— 网站（第三方）请求微信授权，获取用户信息
```

### OpenID Connect（OIDC）

```text
OIDC = OAuth2 + 身份认证层

OAuth2 只解决授权（访问资源），
OIDC 在 OAuth2 基础上加了身份认证（你是谁）
```

```text
OAuth2 vs OIDC：
OAuth2 —— 授权（能访问什么）
OIDC —— 认证（你是谁）+ 授权

OIDC 返回 id_token（用户身份信息），OAuth2 只有 access_token
```

## SSO 单点登录

SSO（Single Sign-On）一次登录，访问多个系统。

### SSO 的原理

```text
1. 用户登录统一认证中心（CAS/Keycloak）
2. 认证中心签发票据（ticket/token）
3. 访问其他系统时，系统验证票据
4. 验证通过，无需重复登录
```

```text
SSO 的实现：
1. CAS —— 经典单点登录协议
2. OAuth2/OIDC —— 现代方案（Keycloak）
3. JWT —— token 共享
```

### SSO 的价值

```text
1. 用户体验 —— 一次登录，处处可用
2. 统一管理 —— 集中认证、授权
3. 安全 —— 统一密码策略、审计
```

## MFA 多因素认证

MFA（Multi-Factor Authentication）用多个因素验证身份。

### 认证因素

```text
1. 你知道的 —— 密码、PIN
2. 你拥有的 —— 手机、硬件令牌
3. 你是什么 —— 指纹、人脸（生物特征）
```

### MFA 的实现

```text
双因素认证（2FA）：
1. 密码（你知道的）
2. 短信验证码 / TOTP（你拥有的）

登录流程：密码验证 → 发送验证码 → 验证码验证 → 登录成功
```

```java
// TOTP（时间戳一次性密码，如 Google Authenticator）
// 手机 App 生成 6 位动态码，服务端校验
```

### MFA 的价值

```text
1. 增强安全 —— 密码泄露了还有第二道防线
2. 防撞库 —— 攻击者没有第二因素
3. 关键操作 —— 支付、改密等关键操作加 MFA
```

## 认证方案选型

| 方案 | 适用 | 特点 |
|------|------|------|
| Session | 传统 Web | 简单、有状态 |
| JWT | 前后端分离、微服务 | 无状态、可扩展 |
| OAuth2 | 第三方授权 | 授权协议 |
| OIDC | 统一认证 | 认证 + 授权 |
| SSO | 多系统 | 一次登录 |
| MFA | 高安全 | 多因素 |

```text
选型建议：
1. 简单 Web 应用 → Session
2. 前后端分离 / 微服务 → JWT
3. 第三方接入 → OAuth2/OIDC
4. 多系统 → SSO（OIDC/Keycloak）
5. 敏感系统 → JWT + MFA
```

## 最佳实践与踩坑记录

### 最佳实践

1. **密码用 BCrypt 哈希**。绝不存明文。

2. **JWT 设置合理过期时间**。短期 + 刷新 token。

3. **敏感操作加 MFA**。支付、改密、改手机号。

4. **HTTPS 传输**。token、密码必须加密传输。

5. **登录失败限制**。防暴力破解（锁定、验证码）。

### 踩坑记录

**坑 1：密码明文存储**

```text
密码明文存数据库，泄露后所有用户密码暴露
```

用 BCrypt 哈希存储。

**坑 2：JWT 过期时间过长**

```text
JWT 有效期 1 年，泄露后长期有效
```

短期（15 分钟）+ 刷新 token。

**坑 3：JWT 无法主动注销**

```text
JWT 无状态，服务端无法主动失效（用户改密码后旧 token 仍有效）
```

用 Redis 黑名单，或短期 token。

**坑 4：Session 不共享导致分布式失效**

```text
多个实例 Session 各自存，负载均衡后登录状态丢失
```

Session 存 Redis（Spring Session）。

**坑 5：Cookie 没设 HttpOnly/Secure**

```text
Cookie 可被 JS 读取（XSS）、明文传输（HTTP）
```

Cookie 设 HttpOnly + Secure。

**坑 6：登录接口无限试错**

```text
登录接口没限流/锁定，暴力破解密码
```

登录失败限制（次数锁定、验证码、限流）。

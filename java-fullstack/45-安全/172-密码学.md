## 概述

密码学是信息安全的基石，理解哈希、加密、签名是做好安全的基础。

```text
密码学三大类：
1. 哈希（Hash）—— 单向，不可逆（MD5、SHA）
2. 对称加密 —— 同一密钥加解密（AES）
3. 非对称加密 —— 公钥加密私钥解密（RSA）
```

```text
常见混淆：
Base64 是编码，不是加密（可逆，无密钥）
哈希是摘要，不是加密（不可逆）
```

## 哈希算法（MD5/SHA）

哈希算法把任意长度数据映射为固定长度摘要，单向不可逆。

### MD5 与 SHA

```text
MD5 —— 128 位摘要（已不安全，有碰撞攻击）
SHA-1 —— 160 位（已不安全）
SHA-256 —— 256 位（安全）
SHA-512 —— 512 位（安全）
```

```java
// SHA-256 哈希
MessageDigest digest = MessageDigest.getInstance("SHA-256");
byte[] hash = digest.digest(data.getBytes());
String hex = HexFormat.of().formatHex(hash);
```

### 哈希的用途

```text
1. 密码存储 —— 密码哈希后存储（配合加盐）
2. 数据完整性 —— 校验文件是否被篡改
3. 数字签名 —— 签名前先哈希
```

### 密码存储（加盐哈希）

```java
// 密码加盐哈希（防彩虹表）
public String hashPassword(String password, String salt) {
    MessageDigest digest = MessageDigest.getInstance("SHA-256");
    byte[] hash = digest.digest((password + salt).getBytes());
    return HexFormat.of().formatHex(hash);
}

// 更推荐：用 BCrypt（自带盐 + 慢哈希）
BCryptPasswordEncoder encoder = new BCryptPasswordEncoder();
String hashed = encoder.encode(password);   // 每次结果不同（盐随机）
boolean match = encoder.matches(password, hashed);
```

```text
密码存储的演进：
明文（危险）→ MD5（可彩虹表破解）→ MD5+盐（可暴力破解）→ BCrypt（慢哈希，推荐）
```

## HMAC 消息认证码

HMAC 是带密钥的哈希，用于验证消息完整性和真实性。

### HMAC 是什么

```text
HMAC = 哈希 + 密钥（对方伪造不了，因为不知道密钥）
```

```java
// HMAC-SHA256
Mac mac = Mac.getInstance("HmacSHA256");
mac.init(new SecretKeySpec(secret.getBytes(), "HmacSHA256"));
byte[] result = mac.doFinal(data.getBytes());
```

### HMAC vs 普通哈希

```text
普通哈希（SHA-256）—— 只验证完整性（谁都能算）
HMAC —— 验证完整性 + 真实性（只有知道密钥的才能算）

用于 API 签名、JWT 签名
```

## 对称加密（AES/DES）

对称加密用同一密钥加解密。

### AES 与 DES

```text
DES —— 56 位密钥（已不安全，太短）
3DES —— 112 位（较慢）
AES —— 128/192/256 位（安全，推荐）
```

### AES 加密

```java
// AES 加密
public String encrypt(String data, String key) throws Exception {
    SecretKeySpec keySpec = new SecretKeySpec(key.getBytes(), "AES");
    Cipher cipher = Cipher.getInstance("AES/GCM/NoPadding");
    cipher.init(Cipher.ENCRYPT_MODE, keySpec);
    byte[] encrypted = cipher.doFinal(data.getBytes());
    return Base64.getEncoder().encodeToString(encrypted);
}

// AES 解密
public String decrypt(String encrypted, String key) throws Exception {
    SecretKeySpec keySpec = new SecretKeySpec(key.getBytes(), "AES");
    Cipher cipher = Cipher.getInstance("AES/GCM/NoPadding");
    cipher.init(Cipher.DECRYPT_MODE, keySpec);
    byte[] decrypted = cipher.doFinal(Base64.getDecoder().decode(encrypted));
    return new String(decrypted);
}
```

### 对称加密的特点

```text
1. 快 —— 加解密速度快
2. 密钥管理难 —— 双方共享密钥，密钥分发是问题
3. 用于 —— 数据加密（大量数据）
```

## 非对称加密（RSA/ECC）

非对称加密用公钥加密，私钥解密。

### RSA 与 ECC

```text
RSA —— 大数分解（成熟，密钥长）
ECC —— 椭圆曲线（密钥短，同等强度更快）
```

### RSA 加密

```java
KeyPairGenerator generator = KeyPairGenerator.getInstance("RSA");
generator.initialize(2048);
KeyPair keyPair = generator.generateKeyPair();

// 公钥加密
Cipher cipher = Cipher.getInstance("RSA");
cipher.init(Cipher.ENCRYPT_MODE, keyPair.getPublic());
byte[] encrypted = cipher.doFinal(data.getBytes());

// 私钥解密
cipher.init(Cipher.DECRYPT_MODE, keyPair.getPrivate());
byte[] decrypted = cipher.doFinal(encrypted);
```

### 非对称加密的特点

```text
1. 慢 —— 比对称加密慢几百倍
2. 安全 —— 公钥公开，私钥保密
3. 用于 —— 密钥交换、数字签名、加密少量数据
```

### 对称 vs 非对称

```text
实际应用：混合加密
1. 用非对称加密（RSA）交换对称密钥（AES）
2. 用对称加密（AES）加密数据

HTTPS 就是这样：RSA 握手交换密钥，AES 加密数据
```

## Base64 编码

Base64 是编码（不是加密），把二进制转成文本。

### Base64 的用途

```text
1. 传输二进制 —— 把二进制转成文本传输（JSON 里的图片）
2. 数据展示 —— 二进制数据可读化
```

```java
String encoded = Base64.getEncoder().encodeToString(data.getBytes());
byte[] decoded = Base64.getDecoder().decode(encoded);
```

```text
重要：Base64 是编码不是加密
1. 可逆（任何人都能解码）
2. 无密钥
3. 不能用于保护敏感数据
```

## 数字签名与数字证书

### 数字签名

数字签名用私钥签名，公钥验证，确认身份和完整性。

```text
数字签名 = 私钥加密哈希（验证者用公钥解密比对）
```

```java
// 签名
Signature signature = Signature.getInstance("SHA256withRSA");
signature.initSign(privateKey);
signature.update(data.getBytes());
byte[] signed = signature.sign();

// 验证
signature.initVerify(publicKey);
signature.update(data.getBytes());
boolean valid = signature.verify(signed);
```

### 数字签名的作用

```text
1. 身份验证 —— 确认消息来自声称的人
2. 完整性 —— 消息没被篡改
3. 不可否认 —— 签名者不能否认
```

### 数字证书

数字证书是权威机构（CA）签发的公钥，证明"公钥属于谁"。

```text
数字证书 = CA 签名的公钥 + 身份信息

HTTPS 流程：
1. 服务器提供证书（含公钥）
2. 客户端用 CA 公钥验证证书
3. 确认服务器身份，交换密钥
```

## 应用场景实战

### 场景 1：密码存储（BCrypt）

```java
@Autowired
private PasswordEncoder passwordEncoder;

public void register(String username, String password) {
    String hashed = passwordEncoder.encode(password);   // BCrypt 哈希
    userMapper.insert(username, hashed);
}

public boolean login(String username, String password) {
    String hashed = userMapper.getPassword(username);
    return passwordEncoder.matches(password, hashed);   // 验证
}
```

### 场景 2：API 签名（HMAC）

```java
// 客户端用密钥签名，服务端验证（详见 132）
String signature = hmacSHA256(secret, method + path + timestamp + body);
```

### 场景 3：敏感数据加密（AES）

```java
// 数据库敏感字段加密存储
String encryptedPhone = aesEncrypt(phone, secretKey);
// 存储 encryptedPhone，读取时解密
```

## 最佳实践与踩坑记录

### 最佳实践

1. **密码用 BCrypt/Argon2**。慢哈希 + 盐，抗暴力破解。

2. **对称加密用 AES-GCM**。认证加密，防篡改。

3. **密钥用密钥管理服务**。密钥不硬编码。

4. **非对称用 RSA 2048+ 或 ECC**。保证强度。

5. **哈希用 SHA-256+**。MD5/SHA-1 已不安全。

### 踩坑记录

**坑 1：把 Base64 当加密**

```text
用 Base64 编码敏感数据，以为加密了（Base64 可逆无密钥）
```

Base64 是编码，敏感数据用 AES 等加密。

**坑 2：密码用 MD5**

```text
密码 MD5 哈希，可彩虹表破解
```

用 BCrypt（慢哈希 + 盐）。

**坑 3：AES 用 ECB 模式**

```java
Cipher.getInstance("AES/ECB/PKCS5Padding");   // ECB 不安全（模式可预测）
```

用 AES/GCM（认证加密）或 CBC + IV。

**坑 4：密钥硬编码**

```java
String key = "my-secret-key";   // 硬编码，泄露
```

密钥用环境变量/密钥管理服务（KMS）。

**坑 5：SHA-1 用于签名**

```text
SHA-1 已不安全（碰撞攻击）
```

用 SHA-256+。

**坑 6：RSA 密钥太短**

```text
RSA 1024 位已被破解
```

RSA 2048+ 或 ECC（P-256+）。

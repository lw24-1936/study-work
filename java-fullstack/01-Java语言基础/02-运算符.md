## 算术运算符

```java
int a = 10, b = 3;

int sum = a + b;      // 13  加
int diff = a - b;     // 7   减
int prod = a * b;     // 30  乘
int quot = a / b;     // 3   除（整数除法，截断）
int rem = a % b;      // 1   取余
```

整数除法直接截断，不四舍五入：

```java
System.out.println(10 / 3);   // 3
System.out.println(10 / 3.0); // 3.3333333333333335
```

`%` 取余的结果符号和被除数一致：

```java
System.out.println(10 % 3);   // 1
System.out.println(10 % -3);  // 1
System.out.println(-10 % 3);  // -1
```

## 关系运算符

结果永远是 `boolean` 类型：

```java
int a = 5, b = 10;

a == b    // false  等于
a != b    // true   不等于
a > b     // false  大于
a < b     // true   小于
a >= b    // false  大于等于
a <= b    // true   小于等于
```

比较引用类型时，`==` 比较的是**引用地址**，不是内容：

```java
String s1 = new String("hello");
String s2 = new String("hello");
System.out.println(s1 == s2);      // false，不同对象
System.out.println(s1.equals(s2)); // true，内容相同
```

## 逻辑运算符

操作数和结果都是 `boolean`：

```java
boolean a = true, b = false;

a && b    // false  AND（短路）
a || b    // true   OR（短路）
!a        // false  NOT
a & b     // false  AND（非短路）
a | b     // true   OR（非短路）
a ^ b     // true   XOR（两个不同为 true）
```

`&&` 和 `&` 的区别：`&&` 如果左操作数为 false 就跳过右边；`&` 无论如何两边都执行。绝大多数情况用 `&&`——效率更高，且能避免右操作数的副作用。

## 位运算符

直接操作二进制位，只适用于整数类型（byte/short/int/long）：

```java
int a = 0b1100;    // 12
int b = 0b1010;    // 10

a & b    // 0b1000 = 8  按位与：两位都是 1 才为 1
a | b    // 0b1110 = 14 按位或：至少一位是 1 就为 1
a ^ b    // 0b0110 = 6  按位异或：不同为 1
~a       // 按位取反：0 变 1，1 变 0
```

位移运算：

```java
int x = 0b0011;      // 3

x << 2                // 0b1100 = 12   左移，低位补 0，等同于乘 2^n
x >> 2                // 0b0000 = 0    算术右移，高位补符号位
x >>> 2               // 0b0000 = 0    逻辑右移，高位补 0（无符号右移）
```

负数右移的区别：

```java
int n = -8;          // 二进制：11111111 11111111 11111111 11111000
n >> 2;              // 算术右移：高位补 1，结果 = -2
n >>> 2;             // 逻辑右移：高位补 0，结果 = 1073741822
```

> 位运算在日常业务代码中少见，但在底层（网络协议解析）、高性能计算（位标记集）、面试（判断奇偶：`n & 1`）中高频出现。

## 赋值运算符

```java
int a = 10;           // 基本赋值
a += 5;               // a = a + 5 → 15
a -= 3;               // a = a - 3 → 12
a *= 2;               // a = a * 2 → 24
a /= 4;               // a = a / 4 → 6
a %= 4;               // a = a % 4 → 2
```

复合赋值自带隐式强转：

```java
byte b = 10;
b = b + 1;            // 编译错误：b+1 是 int，不能赋值给 byte
b += 1;               // 编译通过，等同 b = (byte)(b + 1)
```

## 三元运算符

唯一的三目运算符，`if-else` 的表达式版：

```java
// 条件 ? 为真时的值 : 为假时的值
int max = a > b ? a : b;

String status = score >= 60 ? "及格" : "不及格";
```

类型不一致时，结果类型按提升规则：

```java
// double 和 int 混合，结果提升为 double
double result = flag ? 1.0 : 2;    // 2 提升为 2.0

// 可以嵌套，但超过两层可读性急剧下降
String grade = score >= 90 ? "A" : score >= 80 ? "B" : "C";
```

## 自增自减

```java
int i = 5;

int a = i++;    // a=5, i=6  后置：先赋值，再自增
int b = ++i;    // b=7, i=7  前置：先自增，再赋值
```

典型踩坑：

```java
int i = 0;
i = i++;         // 结果 i=0，不是 1
// 原因：i++ 先把 0 压栈，然后 i 变成 1，然后栈里的 0 赋值给 i——覆盖了
```

面试常考，但生产代码中尽量避免在表达式里混用自增自减——可读性差。

## instanceof

判断对象是否是某个类（或子类）的实例：

```java
Object obj = "hello";

boolean b1 = obj instanceof String;     // true
boolean b2 = obj instanceof Object;     // true（String 是 Object 的子类）
boolean b3 = obj instanceof Integer;    // false
```

Java 16 引入了模式匹配的 instanceof：

```java
// 老写法
if (obj instanceof String) {
    String s = (String) obj;
    System.out.println(s.length());
}

// Java 16+ 新写法
if (obj instanceof String s) {
    System.out.println(s.length());  // s 直接可用，不需要强转
}
```

## 运算符优先级

从高到低：

| 优先级 | 运算符 |
|--------|--------|
| 1 | `()` `[]` `.` |
| 2 | `!` `~` `++` `--`（一元） |
| 3 | `*` `/` `%` |
| 4 | `+` `-` |
| 5 | `<<` `>>` `>>>` |
| 6 | `<` `<=` `>` `>=` `instanceof` |
| 7 | `==` `!=` |
| 8 | `&` |
| 9 | `^` |
| 10 | `\|` |
| 11 | `&&` |
| 12 | `\|\|` |
| 13 | `?:`（三元） |
| 14 | `=` `+=` `-=` 等赋值 |

记不住优先级很正常——用括号明确意图。`a + b * c` 和 `(a + b) * c`，后者不给阅读者留任何歧义空间。

## 短路求值

`&&` 和 `||` 是短路运算符：一旦结果可以确定，剩余操作数不再求值。

```java
// 利用短路避免空指针
if (obj != null && obj.getValue() > 0) {
    // obj 为 null 时，第二个条件不执行，不会 NPE
}

// 利用短路做默认值
String name = inputName != null && !inputName.isEmpty()
    ? inputName : "默认名称";
```

短路求值也意味着带副作用的表达式可能不执行：

```java
int i = 0;
boolean result = false && (++i > 0);
// i 还是 0，因为 && 短路了，++i 根本没执行
```

`&` 和 `|` 不短路——两边都算。这个特性在某些场景中是故意用的（确保两个方法都执行），但常规逻辑判断中很少需要。

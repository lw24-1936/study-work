## 概述

集成测试验证多个组件协同工作的正确性，介于单元测试和端到端测试之间。

```text
集成测试 vs 单元测试：
单元测试 —— 单个方法/类（mock 依赖）
集成测试 —— 多个组件协同（真实依赖）
```

```text
集成测试的内容：
1. Testcontainers —— 真实中间件（数据库、Redis、MQ）
2. WireMock —— 模拟外部 HTTP 服务
3. Embedded Database —— 内嵌数据库
4. API Test —— 接口测试
```

## Testcontainers 容器化测试

Testcontainers 用 Docker 容器提供真实的中间件（MySQL、Redis、Kafka），测试最接近生产。

### 依赖

```xml
<dependency>
    <groupId>org.testcontainers</groupId>
    <artifactId>testcontainers</artifactId>
    <scope>test</scope>
</dependency>
<dependency>
    <groupId>org.testcontainers</groupId>
    <artifactId>mysql</artifactId>
    <scope>test</scope>
</dependency>
<dependency>
    <groupId>org.testcontainers</groupId>
    <artifactId>junit-jupiter</artifactId>
    <scope>test</scope>
</dependency>
```

### MySQL 容器测试

```java
@Testcontainers
@SpringBootTest
class UserRepositoryTest {

    @Container
    static MySQLContainer<?> mysql = new MySQLContainer<>("mysql:8.0")
        .withDatabaseName("testdb")
        .withUsername("test")
        .withPassword("test");

    @DynamicPropertySource   // 动态注入容器地址
    static void configure(DynamicPropertyRegistry registry) {
        registry.add("spring.datasource.url", mysql::getJdbcUrl);
        registry.add("spring.datasource.username", mysql::getUsername);
        registry.add("spring.datasource.password", mysql::getPassword);
    }

    @Autowired
    private UserRepository repository;

    @Test
    void testSaveAndFind() {
        repository.save(new User(null, "张三"));
        assertThat(repository.findByName("张三")).isPresent();
    }
}
```

### Redis 容器测试

```java
@Testcontainers
class RedisTest {

    @Container
    static GenericContainer<?> redis = new GenericContainer<>("redis:7")
        .withExposedPorts(6379);

    @Test
    void testRedis() {
        String host = redis.getHost();
        Integer port = redis.getFirstMappedPort();
        // 连接真实 Redis 测试
    }
}
```

### Testcontainers 的价值

```text
1. 真实环境 —— 真实 MySQL/Redis，不是 H2 模拟
2. 隔离 —— 每次测试独立容器，互不影响
3. 一致性 —— 开发/测试/生产用同一版本
4. 可复用 —— 官方提供各种容器模块
```

### 为什么不用 H2

```text
H2 vs Testcontainers（真实 MySQL）：
H2 —— 模拟，可能和 MySQL 行为不一致（SQL 语法差异）
Testcontainers —— 真实 MySQL，行为一致

关键：H2 测试通过不代表 MySQL 上能跑
```

## WireMock 外部服务模拟

WireMock 模拟外部 HTTP 服务，测试依赖外部 API 的场景。

### 依赖

```xml
<dependency>
    <groupId>org.wiremock</groupId>
    <artifactId>wiremock-standalone</artifactId>
    <scope>test</scope>
</dependency>
```

### 基本用法

```java
class ExternalServiceTest {

    WireMockServer wireMockServer;

    @BeforeEach
    void setup() {
        wireMockServer = new WireMockServer(8089);
        wireMockServer.start();
    }

    @AfterEach
    void teardown() {
        wireMockServer.stop();
    }

    @Test
    void testCallExternalApi() {
        // 模拟外部服务响应
        wireMockServer.stubFor(get(urlEqualTo("/api/user/1"))
            .willReturn(aResponse()
                .withStatus(200)
                .withHeader("Content-Type", "application/json")
                .withBody("{\"id\":1,\"name\":\"张三\"}")));

        // 调用业务代码（内部会调用外部 API）
        User user = userClient.getUser(1L);

        assertThat(user.getName()).isEqualTo("张三");

        // 验证外部 API 被调用
        wireMockServer.verify(getRequestedFor(urlEqualTo("/api/user/1")));
    }
}
```

### WireMock 的用途

```text
1. 模拟外部 API —— 测试依赖第三方服务的代码
2. 模拟故障 —— 模拟超时、500、限流
3. 契约测试 —— 验证请求格式
```

```java
// 模拟故障（超时、500）
wireMockServer.stubFor(get(urlEqualTo("/api/user/1"))
    .willReturn(aResponse().withStatus(500)));

wireMockServer.stubFor(get(urlEqualTo("/api/user/1"))
    .willReturn(aResponse().withFixedDelay(5000)));  // 5 秒延迟
```

## Embedded Database 内嵌数据库

内嵌数据库（H2）测试数据层，无需外部数据库，快速。

### H2 配置

```xml
<dependency>
    <groupId>com.h2database</groupId>
    <artifactId>h2</artifactId>
    <scope>test</scope>
</dependency>
```

```yaml
# application-test.yml
spring:
  datasource:
    url: jdbc:h2:mem:testdb
    driver-class-name: org.h2.Driver
    username: sa
    password:
  jpa:
    hibernate:
      ddl-auto: create-drop   # 测试时自动建表
```

### H2 测试

```java
@SpringBootTest
@ActiveProfiles("test")   # 使用 test 配置
class UserRepositoryTest {

    @Autowired
    private UserRepository repository;

    @Test
    void testSaveAndFind() {
        repository.save(new User(null, "张三"));
        assertThat(repository.findByName("张三")).isPresent();
    }
}
```

### H2 vs Testcontainers

| 维度 | H2 | Testcontainers |
|------|-----|----------------|
| 速度 | 快（无容器） | 慢（启动容器） |
| 真实性 | 模拟（SQL 差异） | 真实 MySQL |
| 依赖 | 无（纯内存） | 需要 Docker |
| 适用 | 快速冒烟 | 关键集成测试 |

```text
策略：
1. 日常开发用 H2（快）
2. 关键集成测试用 Testcontainers（真实）
```

## API Test 接口测试

API 测试验证接口的正确性（Controller 层），结合 MockMvc 或真实请求。

### MockMvc 接口测试

```java
@WebMvcTest(UserController.class)
class UserApiTest {

    @Autowired
    private MockMvc mockMvc;

    @MockBean
    private UserService userService;

    @Test
    void testGetUserApi() throws Exception {
        when(userService.getUser(1L)).thenReturn(new User(1L, "张三"));

        mockMvc.perform(get("/api/users/1")
                .header("Authorization", "Bearer token"))
            .andExpect(status().isOk())
            .andExpect(jsonPath("$.name").value("张三"))
            .andExpect(jsonPath("$.id").value(1));
    }

    @Test
    void testCreateUserApi() throws Exception {
        mockMvc.perform(post("/api/users")
                .contentType(MediaType.APPLICATION_JSON)
                .content("{\"name\":\"李四\",\"age\":25}"))
            .andExpect(status().isCreated());
    }
}
```

### REST Assured（真实请求）

```xml
<dependency>
    <groupId>io.rest-assured</groupId>
    <artifactId>rest-assured</artifactId>
    <scope>test</scope>
</dependency>
```

```java
@SpringBootTest(webEnvironment = WebEnvironment.RANDOM_PORT)
class UserApiTest {

    @LocalServerPort
    private int port;

    @Test
    void testGetUserApi() {
        given()
            .port(port)
            .when()
            .get("/api/users/1")
            .then()
            .statusCode(200)
            .body("name", equalTo("张三"));
    }
}
```

## 应用场景实战

### 场景 1：完整集成测试（Testcontainers + Spring Boot）

```java
@Testcontainers
@SpringBootTest
class OrderServiceIntegrationTest {

    @Container
    static MySQLContainer<?> mysql = new MySQLContainer<>("mysql:8.0")
        .withDatabaseName("testdb");

    @Container
    static GenericContainer<?> redis = new GenericContainer<>("redis:7")
        .withExposedPorts(6379);

    @DynamicPropertySource
    static void configure(DynamicPropertyRegistry registry) {
        registry.add("spring.datasource.url", mysql::getJdbcUrl);
        registry.add("spring.data.redis.host", redis::getHost);
        registry.add("spring.data.redis.port", () -> redis.getFirstMappedPort());
    }

    @Autowired
    private OrderService orderService;

    @Test
    void testCreateOrderWithInventory() {
        // 真实数据库 + 真实 Redis，完整流程测试
        Order order = orderService.createOrder(1L, 100L, 2);
        assertThat(order.getStatus()).isEqualTo("CREATED");
    }
}
```

### 场景 2：模拟外部支付服务（WireMock）

```java
class PaymentServiceTest {

    WireMockServer wireMockServer;

    @BeforeEach
    void setup() {
        wireMockServer = new WireMockServer(8089);
        wireMockServer.start();
    }

    @Test
    void testPaySuccess() {
        // 模拟支付网关成功响应
        wireMockServer.stubFor(post(urlEqualTo("/pay"))
            .willReturn(aResponse()
                .withStatus(200)
                .withBody("{\"code\":0,\"msg\":\"success\"}")));

        boolean result = paymentService.pay(new PaymentRequest());

        assertThat(result).isTrue();
    }

    @Test
    void testPayFailWhenGatewayDown() {
        // 模拟支付网关 500
        wireMockServer.stubFor(post(urlEqualTo("/pay"))
            .willReturn(aResponse().withStatus(500)));

        boolean result = paymentService.pay(new PaymentRequest());

        assertThat(result).isFalse();   // 降级返回 false
    }
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. **关键集成测试用 Testcontainers**。真实中间件，避免 H2 与生产行为差异。

2. **外部依赖用 WireMock 模拟**。不依赖真实第三方服务（不稳定、有成本）。

3. **测试环境隔离**。集成测试用独立的测试库/容器，不污染开发环境。

4. **容器启动慢，合理组织**。用 @Testcontainers + 静态容器，复用容器。

5. **集成测试标记分组**。用 @Tag("integration") 标记，CI 中单独执行。

### 踩坑记录

**坑 1：H2 测试通过但 MySQL 失败**

```text
H2 和 MySQL 的 SQL 语法有差异（如分页、函数），
H2 通过不代表 MySQL 能跑
```

关键 SQL 用 Testcontainers（真实 MySQL）验证。

**坑 2：Testcontainers 需要 Docker**

```text
CI 环境没装 Docker，Testcontainers 测试失败
```

CI 环境配置 Docker，或用 H2 作为降级方案。

**坑 3：容器启动慢导致测试超时**

```text
每个测试类都启动新容器，测试极慢
```

用静态容器（@Container static），多个测试类复用同一容器。

**坑 4：WireMock 端口冲突**

```java
new WireMockServer(8089)   // 固定端口，可能被占用
```

用动态端口：`new WireMockServer(options().dynamicPort())`。

**坑 5：集成测试污染生产数据**

```text
测试连了生产/开发数据库，测试数据污染
```

测试用独立数据库/容器，配置隔离（@ActiveProfiles("test")）。

**坑 6：测试依赖外部服务不稳定**

```text
测试调用真实第三方 API，服务不稳定导致测试随机失败
```

外部服务用 WireMock 模拟，保证测试稳定可重复。

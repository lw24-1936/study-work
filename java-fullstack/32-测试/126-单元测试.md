## 概述

单元测试是测试最小的代码单元（方法），验证其行为正确，是质量保障的第一道防线。

```text
为什么写单元测试：
1. 快速验证 —— 修改代码后立即验证正确性
2. 防止回归 —— 重构时发现破坏
3. 文档作用 —— 测试即文档，展示用法
4. 提升质量 —— 测试驱动开发（TDD）
```

```text
测试金字塔：
        E2E（少量）
      /       \
    集成测试（适量）
  /             \
单元测试（大量，最快，最多）
```

## JUnit 5

JUnit 5 是 Java 单元测试的标准框架。

### 依赖

```xml
<dependency>
    <groupId>org.junit.jupiter</groupId>
    <artifactId>junit-jupiter</artifactId>
    <scope>test</scope>
</dependency>
```

### 基本注解

```java
import org.junit.jupiter.api.*;

class CalculatorTest {

    @BeforeAll      // 所有测试前执行一次（静态方法）
    static void initAll() { }

    @BeforeEach     // 每个测试前执行
    void init() { }

    @Test           // 测试方法
    void testAdd() {
        assertEquals(3, calculator.add(1, 2));
    }

    @AfterEach      // 每个测试后执行
    void tearDown() { }

    @AfterAll       // 所有测试后执行一次
    static void tearDownAll() { }
}
```

### 常用断言

```java
assertEquals(expected, actual);          // 相等
assertNotEquals(unexpected, actual);     // 不等
assertTrue(condition);                   // 为真
assertFalse(condition);                  // 为假
assertNull(obj);                         // 为 null
assertNotNull(obj);                      // 非 null
assertThrows(Exception.class, () -> ...) // 抛异常
assertTimeout(Duration.ofSeconds(1), () -> ...)  // 超时
```

### 参数化测试

```java
@ParameterizedTest
@ValueSource(ints = {1, 2, 3})
void testIsPositive(int num) {
    assertTrue(num > 0);
}

@ParameterizedTest
@CsvSource({
    "1, 1, 2",
    "2, 3, 5",
    "10, 20, 30"
})
void testAdd(int a, int b, int expected) {
    assertEquals(expected, calculator.add(a, b));
}
```

### 生命周期顺序

```text
@BeforeAll → (@BeforeEach → @Test → @AfterEach) × N → @AfterAll
```

## AssertJ 断言

AssertJ 是流式断言库，比 JUnit 原生断言更强大、更易读。

### 依赖

```xml
<dependency>
    <groupId>org.assertj</groupId>
    <artifactId>assertj-core</artifactId>
    <scope>test</scope>
</dependency>
```

### 流式断言

```java
import static org.assertj.core.api.Assertions.*;

// 对象断言
assertThat(user.getName()).isEqualTo("张三");
assertThat(user.getAge()).isGreaterThan(18);
assertThat(user.getEmail()).contains("@");

// 集合断言
assertThat(list)
    .hasSize(3)
    .contains("apple")
    .doesNotContain("banana");

// 链式断言
assertThat(user)
    .isNotNull()
    .hasFieldOrPropertyWithValue("name", "张三");

// 异常断言
assertThatThrownBy(() -> service.getUser(-1))
    .isInstanceOf(IllegalArgumentException.class)
    .hasMessageContaining("id 不能为负");
```

### JUnit vs AssertJ

```text
JUnit 原生：assertEquals(3, result)
AssertJ：assertThat(result).isEqualTo(3)

AssertJ 优势：
1. 流式 API —— 链式调用，可读性强
2. 丰富断言 —— 集合、字符串、异常
3. 错误信息清晰 —— 自动生成对比信息
```

## Mockito 基础

Mockito 是 Java 最流行的 mock 框架，模拟依赖对象。

### 依赖

```xml
<dependency>
    <groupId>org.mockito</groupId>
    <artifactId>mockito-core</artifactId>
    <scope>test</scope>
</dependency>
<dependency>
    <groupId>org.mockito</groupId>
    <artifactId>mockito-junit-jupiter</artifactId>
    <scope>test</scope>
</dependency>
```

### 基本用法

```java
@ExtendWith(MockitoExtension.class)
class OrderServiceTest {

    @Mock                    // 创建 mock 对象
    private OrderRepository repository;

    @InjectMocks             // 注入 mock 到被测对象
    private OrderService service;

    @Test
    void testCreateOrder() {
        // 模拟行为（stub）
        when(repository.save(any(Order.class)))
            .thenReturn(new Order(1L));

        Order result = service.createOrder(new Order());

        // 验证结果
        assertThat(result.getId()).isEqualTo(1L);

        // 验证调用（verify）
        verify(repository).save(any(Order.class));
    }
}
```

### 模拟行为（Stubbing）

```java
// 返回固定值
when(repo.findById(1L)).thenReturn(Optional.of(user));

// 抛异常
when(repo.findById(1L)).thenThrow(new RuntimeException());

// 连续调用返回不同值
when(repo.nextId())
    .thenReturn(1L)
    .thenReturn(2L)
    .thenReturn(3L);

// 参数匹配
when(repo.findByName(anyString())).thenReturn(user);
when(repo.findByName(startsWith("张"))).thenReturn(user);
```

### 验证调用（Verification）

```java
verify(repo).save(order);                    // 调用一次
verify(repo, times(2)).save(order);          // 调用两次
verify(repo, never()).delete(anyLong());     // 从未调用
verify(repo, atLeastOnce()).findAll();       // 至少一次
verifyNoMoreInteractions(repo);              // 没有其他调用
```

## Mock vs Stub vs Spy

三个概念容易混淆，核心区别：

### Stub（桩）

```text
Stub：预定义返回值的假对象（只关心返回值）
```

```java
// Stub：直接返回固定值
UserRepository stub = id -> new User(1L, "测试用户");
```

### Mock（模拟）

```text
Mock：模拟对象（记录调用 + 预定义行为 + 验证调用）
```

```java
// Mock：预定义行为 + 验证调用
@Mock
UserRepository mock;
when(mock.findById(1L)).thenReturn(Optional.of(user));
// ... 调用后
verify(mock).findById(1L);   // 验证是否被调用
```

### Spy（间谍）

```text
Spy：真实对象的部分模拟（真实方法 + 部分 mock）
```

```java
// Spy：包装真实对象，可部分覆盖行为
@Spy
UserService spyService = new UserService();

// 真实调用（默认）
spyService.realMethod();

// 部分 mock（覆盖某个方法）
doReturn(fakeResult).when(spyService).expensiveMethod();
```

### 三者对比

| 概念 | 行为 | 验证 | 场景 |
|------|------|------|------|
| Stub | 返回固定值 | 不验证 | 简单依赖 |
| Mock | 预定义 + 记录调用 | 验证调用 | 复杂依赖 |
| Spy | 真实 + 部分 mock | 可验证 | 部分覆盖 |

```text
使用原则：
1. 优先用 Mock（清晰、可控）
2. 简单依赖用 Stub
3. 需要保留真实行为才用 Spy（少用）
```

## 应用场景实战

### 场景 1：Service 层测试（Mock 依赖）

```java
@ExtendWith(MockitoExtension.class)
class UserServiceTest {

    @Mock
    private UserRepository userRepository;

    @InjectMocks
    private UserService userService;

    @Test
    void shouldReturnUserWhenExists() {
        // 准备（Arrange）
        User user = new User(1L, "张三");
        when(userRepository.findById(1L)).thenReturn(Optional.of(user));

        // 执行（Act）
        User result = userService.getUser(1L);

        // 断言（Assert）
        assertThat(result.getName()).isEqualTo("张三");
    }

    @Test
    void shouldThrowWhenUserNotExists() {
        when(userRepository.findById(99L)).thenReturn(Optional.empty());

        assertThatThrownBy(() -> userService.getUser(99L))
            .isInstanceOf(UserNotFoundException.class);
    }
}
```

### 场景 2：验证方法调用

```java
@Test
void shouldSaveOrderAndNotify() {
    // 准备
    Order order = new Order();
    when(orderRepository.save(order)).thenReturn(order);

    // 执行
    orderService.createOrder(order);

    // 验证：保存了订单 + 发送了通知
    verify(orderRepository).save(order);
    verify(notificationService).notifyOrderCreated(order);
    verifyNoMoreInteractions(notificationService);
}
```

### 场景 3：异常场景测试

```java
@Test
void shouldRetryWhenRepositoryFails() {
    // 前两次失败，第三次成功
    when(repository.save(any()))
        .thenThrow(new RuntimeException("连接超时"))
        .thenThrow(new RuntimeException("连接超时"))
        .thenReturn(new Order(1L));

    Order result = orderService.saveWithRetry(new Order());

    assertThat(result.getId()).isEqualTo(1L);
    verify(repository, times(3)).save(any());
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. **AAA 模式**。Arrange（准备）/ Act（执行）/ Assert（断言），结构清晰。

2. **一个测试测一件事**。测试方法单一职责，便于定位问题。

3. **测试方法名要描述行为**。`shouldReturnUserWhenExists` 而非 `test1`。

4. **用 AssertJ 流式断言**。比 JUnit 原生断言更可读。

5. **只 mock 外部依赖，不 mock 被测对象**。被测逻辑要真实执行。

### 踩坑记录

**坑 1：测试依赖执行顺序**

```java
@Test
void testA() { counter++; }   // 修改共享状态

@Test
void testB() { assertThat(counter).isEqualTo(1); }  // 依赖 testA 先执行
// 测试顺序不保证，testB 可能失败
```

测试要独立，不依赖执行顺序，共享状态在 @BeforeEach 重置。

**坑 2：mock 了被测对象本身**

```java
@Mock
UserService userService;   // 被测对象被 mock，测试没意义
```

mock 外部依赖（Repository），被测对象（Service）用真实实例。

**坑 3：when 用在 void 方法**

```java
when(repo.delete(1L)).thenReturn(...);   // delete 是 void，编译错误
```

void 方法用 `doNothing()` 或 `doThrow()`：
`doThrow(new RuntimeException()).when(repo).delete(1L);`

**坑 4：测试没断言**

```java
@Test
void testMethod() {
    service.doSomething();   // 没断言，测试永远通过（假绿）
}
```

测试必须有断言（assertThat/verify），否则是假测试。

**坑 5：spy 的 when 调用真实方法**

```java
@Spy
UserService spyService;
when(spyService.method()).thenReturn(...);   // when 会真实调用 method！
```

spy 用 `doReturn(...).when(spy).method()` 避免真实调用。

**坑 6：测试依赖外部环境**

```java
@Test
void test() {
    // 依赖数据库、Redis、外部 API，测试不稳定
    User user = jdbcTemplate.queryForObject(...);
}
```

单元测试要隔离外部依赖（mock），依赖外部的放集成测试。

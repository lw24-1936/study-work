## 概述

Git 是分布式版本控制系统，是现代软件开发的基石，管理代码的版本、分支、协作。

```text
Git 的核心概念：
1. Repository（仓库）—— 代码的存储（本地 + 远程）
2. Commit（提交）—— 一次代码变更的快照
3. Branch（分支）—— 独立的开发线
4. 工作区/暂存区/本地仓库/远程仓库
```

```text
Git 的四个区域：
工作区（Working Directory）→ 暂存区（Staging）→ 本地仓库（Local Repo）→ 远程仓库（Remote）
    git add                  git commit            git push
```

## 基本工作流

### 日常开发流程

```bash
git clone <url>              # 克隆仓库
git status                   # 查看状态
git add file.txt             # 添加到暂存区
git add .                    # 添加所有改动
git commit -m "feat: 添加用户模块"   # 提交
git push                     # 推送到远程
git pull                     # 拉取远程更新
```

### 查看历史

```bash
git log                      # 提交历史
git log --oneline            # 简洁历史
git log --graph              # 图形化（分支图）
git log --author=zhangsan    # 按作者过滤
git diff                     # 查看未暂存的改动
git diff --staged            # 查看已暂存的改动
git show <commit>            # 查看某次提交
```

### 撤销操作

```bash
git checkout -- file.txt     # 撤销工作区改动
git reset HEAD file.txt      # 撤销暂存（回工作区）
git reset --soft HEAD~1      # 撤销 commit（保留改动）
git reset --hard HEAD~1      # 撤销 commit（丢弃改动，危险！）
git revert <commit>          # 撤销某次提交（生成新提交，安全）
```

## Branch 分支

分支是 Git 的核心，用于并行开发和功能隔离。

### 分支操作

```bash
git branch                   # 查看本地分支
git branch -a                # 查看所有分支（含远程）
git branch feature-login     # 创建分支
git checkout feature-login   # 切换分支
git checkout -b feature-login  # 创建并切换
git branch -d feature-login  # 删除分支
git push origin feature-login  # 推送分支到远程
```

### 分支合并

```bash
git checkout main            # 切到主分支
git merge feature-login      # 合并功能分支
git push origin main         # 推送合并结果
```

### 远程分支

```bash
git fetch                    # 拉取远程分支（不合并）
git pull                     # 拉取并合并（fetch + merge）
git branch -r                # 查看远程分支
git checkout -b local origin/remote  # 基于远程分支创建本地分支
```

## Merge 与 Rebase

Merge 和 Rebase 是两种整合分支的方式，各有适用场景。

### Merge（合并）

```text
Merge：创建合并提交，保留分支历史
```

```bash
git checkout main
git merge feature-login
# 生成一个 merge commit，保留 feature-login 的完整历史
```

```text
merge 的结果：
main:    A---B---C---M（合并提交）
              \     /
feature:       D---E
```

### Rebase（变基）

```text
Rebase：将分支的提交"移动"到目标分支之上，线性历史
```

```bash
git checkout feature-login
git rebase main
# feature-login 的提交移到 main 之上，历史线性
```

```text
rebase 的结果：
main:    A---B---C
                  \
feature:           D'---E'（重新应用）
```

### Merge vs Rebase

| 维度 | Merge | Rebase |
|------|-------|--------|
| 历史 | 保留分支结构 | 线性历史 |
| 提交 | 多一个 merge commit | 无额外提交 |
| 冲突 | 一次解决 | 可能多次解决 |
| 安全 | 安全 | 改历史（危险） |

```text
使用原则：
1. 公共分支（main）用 merge（不改历史）
2. 个人分支用 rebase（保持整洁）
3. 不要 rebase 已推送的公共分支
```

## Tag 标签

Tag 标记重要的版本节点（发布版本）。

### 标签操作

```bash
git tag                      # 查看标签
git tag v1.0.0               # 创建轻量标签
git tag -a v1.0.0 -m "发布 1.0.0"   # 创建附注标签
git tag v1.0.0 <commit>      # 给历史提交打标签
git push origin v1.0.0       # 推送标签
git push origin --tags       # 推送所有标签
git checkout v1.0.0          # 切到标签（分离头状态）
```

### Tag 的用途

```text
1. 版本发布标记 —— v1.0.0、v2.0.0
2. 回滚参考点 —— 快速定位历史版本
3. 语义化版本 —— 主版本.次版本.修订号
```

## Cherry-pick 与 Stash

### Cherry-pick（挑选提交）

```text
Cherry-pick：把某个分支的某个提交，应用到当前分支
```

```bash
git cherry-pick <commit>     # 挑选单个提交
git cherry-pick <c1> <c2>    # 挑选多个提交
```

```text
场景：
1. 只把某个 bug 修复合并到发布分支
2. 把 hotfix 应用到多个分支
```

### Stash（暂存改动）

```text
Stash：暂时保存未提交的改动，切换分支处理其他事情
```

```bash
git stash                    # 暂存当前改动
git stash list               # 查看暂存列表
git stash pop                # 恢复并删除暂存
git stash apply              # 恢复（不删除）
git stash drop               # 删除暂存
```

```text
场景：
1. 开发到一半，要切分支修 bug
2. 暂存改动，拉取远程更新
```

## Git Flow 分支模型

Git Flow 是经典的分支管理模型，适合有版本发布周期的项目。

### Git Flow 分支结构

```text
main（生产分支）—— 稳定，可发布
  │
develop（开发分支）—— 集成开发
  │
feature/*（功能分支）—— 新功能开发
  │
release/*（发布分支）—— 发布准备
  │
hotfix/*（热修复分支）—— 生产 bug 修复
```

### 各分支职责

| 分支 | 来源 | 合并到 | 说明 |
|------|------|--------|------|
| main | - | - | 生产代码 |
| develop | main | main | 开发集成 |
| feature/* | develop | develop | 新功能 |
| release/* | develop | main + develop | 发布准备 |
| hotfix/* | main | main + develop | 生产修复 |

### 简化模型（GitHub Flow）

```text
main + feature 分支（更简单，适合持续部署）：

main —— 主分支（随时可部署）
feature/* —— 功能分支（PR 合并到 main）
```

```text
Git Flow vs GitHub Flow：
Git Flow —— 复杂，适合有版本发布的传统项目
GitHub Flow —— 简单，适合持续部署的互联网项目
```

## 应用场景实战

### 场景 1：功能开发流程

```bash
# 1. 从 main 创建功能分支
git checkout main
git pull
git checkout -b feature-user-module

# 2. 开发 + 提交
git add .
git commit -m "feat: 实现用户模块"

# 3. 推送并创建 PR
git push origin feature-user-module
# 在 GitHub/GitLab 创建 Pull Request，code review 后合并

# 4. 合并后删除本地分支
git checkout main
git pull
git branch -d feature-user-module
```

### 场景 2：修复生产 bug（hotfix）

```bash
# 1. 从 main 创建 hotfix 分支
git checkout main
git checkout -b hotfix-login-bug

# 2. 修复并提交
git add .
git commit -m "fix: 修复登录 bug"

# 3. 合并到 main 和 develop
git checkout main
git merge hotfix-login-bug
git checkout develop
git merge hotfix-login-bug

# 4. 打标签
git tag v1.0.1
```

### 场景 3：冲突解决

```bash
# 合并时冲突
git merge feature-login
# CONFLICT: 冲突

# 1. 查看冲突文件
git status

# 2. 手动解决冲突（编辑冲突文件）
# <<<<<<< HEAD
# 你的改动
# =======
# 对方的改动
# >>>>>>> feature-login

# 3. 标记解决并提交
git add .
git commit -m "merge: 解决冲突"
```

## 最佳实践与踩坑记录

### 最佳实践

1. **提交信息规范**。用约定式提交（feat/fix/docs/refactor），信息清晰。

2. **小步提交**。一次提交做一件事，便于回滚和 review。

3. **功能分支开发**。不在 main 直接开发，用 feature 分支 + PR。

4. **公共分支用 merge，个人分支用 rebase**。不改公共分支历史。

5. **经常 pull**。保持和远程同步，减少冲突。

### 踩坑记录

**坑 1：reset --hard 误删改动**

```bash
git reset --hard HEAD~1   # 丢弃最近提交的改动，无法恢复
```

reset --hard 危险，用 revert（安全）或确认有备份。

**坑 2：rebase 公共分支**

```bash
git checkout main
git rebase feature   # rebase 了公共分支，改写历史
# 其他人拉取时会冲突
```

不要 rebase 已推送的公共分支。

**坑 3：提交了敏感信息**

```text
提交了密码、密钥到仓库，删掉提交也还在历史里
```

敏感信息用 git filter-branch 清理历史，或立即改密码。

**坑 4：忘记 git add 就 commit**

```bash
git commit -m "xxx"   # 没 add，改动没提交
```

commit 前先 git add，或用 git commit -am（已跟踪文件）。

**坑 5：大文件提交到仓库**

```text
提交了 jar 包、日志等大文件，仓库膨胀
```

用 .gitignore 排除，大文件用 Git LFS。

**坑 6：detached HEAD 状态**

```bash
git checkout v1.0.0   # 切到 tag，进入分离头状态
# 此时提交的 commit 不属于任何分支，可能丢失
```

在 tag 上开发要新建分支：git checkout -b branch v1.0.0。

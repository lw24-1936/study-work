## 概述

Spring Cache 是 Spring 的缓存抽象，通过注解（@Cacheable 等）透明地给方法加缓存，业务代码无需关心缓存的实现细节。

```text
Spring Cache 核心价值：
1. 声明式缓存 —— 注解即缓存，不侵入业务代码
2. 抽象统一 —— 换缓存实现（Redis/Caffeine/EhCache）不改业务代码
3. 开箱即用 —— 只需加注解 + 配置 CacheManager
```

```text
核心组件：
Cache          —— 缓存接口（get/put/evict）
CacheManager   —— 缓存管理器（按名称管理多个 Cache）
@Cacheable     —— 查询缓存（有则返回，无则执行方法并缓存）
@CachePut      —— 更新缓存（总是执行方法并更新缓存）
@CacheEvict    —— 清除缓存
```

## Cache 与 CacheManager

### Cache 接口

```java
public interface Cache {
    String getName();                          // 缓存名称
    Object get(Object key);                    // 获取
    <T> T get(Object key, Class<T> type);      // 获取（带类型）
    void put(Object key, Object value);        // 放入
    void evict(Object key);                    // 清除单个
    void clear();                              // 清空所有
}
```

### CacheManager 接口

```java
public interface CacheManager {
    Cache getCache(String name);               // 按名称获取缓存
    Collection<String> getCacheNames();        // 所有缓存名称
}
```

### 常见 CacheManager 实现

| 实现 | 缓存存储 | 适用场景 |
|------|---------|---------|
| ConcurrentMapCacheManager | JVM 内存 | 开发/测试 |
| CaffeineCacheManager | JVM 内存（高性能） | 本地缓存 |
| RedisCacheManager | Redis | 分布式缓存 |
| EhCacheCacheManager | 内存/磁盘 | 本地缓存 |

### 启用缓存

```java
@Configuration
@EnableCaching  // 启用注解驱动缓存
public class CacheConfig { }
```

## @Cacheable 缓存查询

@Cacheable 是最常用的缓存注解，方法执行前查缓存，命中则返回，未命中则执行方法并缓存结果。

### 基本用法

```java
@Service
public class UserService {

    @Cacheable(value = "users", key = "#id")
    public User getUserById(Long id) {
        // 首次调用执行方法，结果缓存到 "users" 缓存
        // 之后相同 id 直接返回缓存
        return userMapper.findById(id);
    }
}
```

### 属性详解

```java
@Cacheable(
    value = "users",           // 缓存名称（必填）
    key = "#id",               // 缓存 key（SpEL）
    condition = "#id > 0",     // 条件（满足才缓存）
    unless = "#result == null", // 排除条件（满足不缓存）
    cacheManager = "cacheManager",  // 指定管理器
    sync = true                // 同步（防止缓存击穿）
)
public User getUser(Long id) { ... }
```

### condition 与 unless 的区别

```java
// condition：方法执行前判断，满足才查/写缓存
@Cacheable(value = "users", key = "#id", condition = "#id > 0")
public User getUser(Long id) { ... }

// unless：方法执行后判断，满足则不缓存结果
@Cacheable(value = "users", key = "#id", unless = "#result == null")
public User getUser(Long id) { ... }  // 结果 null 不缓存，避免缓存 null
```

```text
condition 在方法调用前求值（决定是否用缓存）
unless 在方法调用后求值（决定是否存缓存）

常用 unless = "#result == null"，防止缓存空值
```

## @CachePut 缓存更新

@CachePut 总是执行方法，并把结果更新到缓存（不查缓存）。

```java
@Service
public class UserService {

    // 更新用户时，同步更新缓存
    @CachePut(value = "users", key = "#user.id")
    public User updateUser(User user) {
        userMapper.update(user);
        return user;  // 返回值更新到缓存
    }

    // 新增用户时，放入缓存
    @CachePut(value = "users", key = "#result.id")
    public User createUser(User user) {
        userMapper.insert(user);
        return user;  // 用 #result.id 作为 key
    }
}
```

## @CacheEvict 缓存清除

@CacheEvict 用于清除缓存，常用于删除/更新操作后。

```java
@Service
public class UserService {

    // 删除用户时清除缓存
    @CacheEvict(value = "users", key = "#id")
    public void deleteUser(Long id) {
        userMapper.delete(id);
    }

    // 清空整个缓存
    @CacheEvict(value = "users", allEntries = true)
    public void clearAllUsers() { ... }

    // 方法执行前清除（beforeInvocation）
    @CacheEvict(value = "users", key = "#id", beforeInvocation = true)
    public void updateUser(Long id) { ... }
}
```

### 组合注解 @Caching

```java
// 一次操作多个缓存
@Caching(
    evict = {
        @CacheEvict(value = "users", key = "#user.id"),
        @CacheEvict(value = "userList", allEntries = true)
    }
)
public User updateUser(User user) { ... }
```

### 类级别配置 @CacheConfig

```java
@Service
@CacheConfig(cacheNames = "users")  // 类内所有注解的默认缓存名
public class UserService {

    @Cacheable(key = "#id")         // 省略 value，用类级别 cacheNames
    public User getUser(Long id) { ... }

    @CacheEvict(key = "#id")
    public void delete(Long id) { ... }
}
```

## 缓存 Key 策略

### 默认 Key 策略

```java
// 不指定 key 时，默认使用所有参数组合
@Cacheable(value = "users")
public User getUser(Long id, String type) {
    // 默认 key = SimpleKey(id, type)
}
```

### 自定义 Key（SpEL）

```java
@Cacheable(value = "users", key = "#id")                    // 单个参数
@Cacheable(value = "users", key = "#user.id")               // 对象属性
@Cacheable(value = "users", key = "#type + ':' + #id")      // 组合 key
@Cacheable(value = "users", key = "#root.methodName")       // 方法名
@Cacheable(value = "users", key = "#root.targetClass")      // 目标类
@Cacheable(value = "users", key = "#p0")                    // 第一个参数（p0/p1）
@Cacheable(value = "users", key = "#a0 + #a1")              // 参数别名
```

### Key 生成器

```java
@Bean
public KeyGenerator customKeyGenerator() {
    return (target, method, params) -> {
        StringBuilder sb = new StringBuilder();
        sb.append(target.getClass().getSimpleName());
        sb.append(":").append(method.getName());
        for (Object param : params) {
            sb.append(":").append(param);
        }
        return sb.toString();
    };
}

// 使用自定义 KeyGenerator
@Cacheable(value = "users", keyGenerator = "customKeyGenerator")
public User getUser(Long id) { ... }
```

## Redis Cache

Redis 是最常用的分布式缓存实现。

### 引入依赖与配置

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-data-redis</artifactId>
</dependency>
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-cache</artifactId>
</dependency>
```

```yaml
spring:
  cache:
    type: redis          # 指定缓存类型
    redis:
      time-to-live: 3600000    # 默认过期时间（毫秒）
      cache-null-values: false # 是否缓存 null 值
      key-prefix: "cache:"     # key 前缀
      use-key-prefix: true
  data:
    redis:
      host: localhost
      port: 6379
```

### 自定义 RedisCacheManager

```java
@Configuration
@EnableCaching
public class RedisCacheConfig {

    @Bean
    public RedisCacheManager cacheManager(RedisConnectionFactory factory) {
        // JSON 序列化
        RedisSerializer<Object> jsonSerializer =
            RedisSerializer.json();

        RedisCacheConfiguration config = RedisCacheConfiguration.defaultCacheConfig()
            .entryTtl(Duration.ofMinutes(30))                    // 默认 30 分钟
            .serializeKeysWith(RedisSerializationContext.SerializationPair
                .fromSerializer(new StringRedisSerializer()))
            .serializeValuesWith(RedisSerializationContext.SerializationPair
                .fromSerializer(jsonSerializer))
            .prefixCacheNameWith("cache:")                        // key 前缀
            .disableCachingNullValues();                          // 不缓存 null

        // 为不同缓存名设置不同 TTL
        Map<String, RedisCacheConfiguration> configs = new HashMap<>();
        configs.put("users", config.entryTtl(Duration.ofHours(1)));   // users 1 小时
        configs.put("hotData", config.entryTtl(Duration.ofMinutes(5))); // 热数据 5 分钟

        return RedisCacheManager.builder(factory)
            .cacheDefaults(config)
            .withInitialCacheConfigurations(configs)
            .build();
    }
}
```

## Caffeine 本地缓存

Caffeine 是高性能的本地缓存（JVM 内存），比 Guava Cache 更优。

### 引入依赖

```xml
<dependency>
    <groupId>com.github.ben-manes.caffeine</groupId>
    <artifactId>caffeine</artifactId>
</dependency>
```

### 配置 CaffeineCacheManager

```java
@Configuration
@EnableCaching
public class CaffeineCacheConfig {

    @Bean
    public CacheManager cacheManager() {
        CaffeineCacheManager manager = new CaffeineCacheManager();
        manager.setCaffeine(Caffeine.newBuilder()
            .maximumSize(10_000)               // 最大条目数
            .expireAfterWrite(10, TimeUnit.MINUTES)  // 写入后过期
            .expireAfterAccess(5, TimeUnit.MINUTES)  // 访问后过期
            .recordStats());                   // 记录统计信息
        return manager;
    }
}
```

### Caffeine 特性

```text
1. 基于 W-TinyLFU 淘汰算法（接近最优）
2. 支持自动加载、异步刷新
3. 提供命中率统计
4. 支持弱引用、软引用
```

## 多级缓存

多级缓存：本地缓存（Caffeine）+ 分布式缓存（Redis）组合，兼顾性能和一致性。

```text
请求 → Caffeine（L1，本地内存，纳秒级）→ Redis（L2，分布式，毫秒级）→ 数据库
```

### 手动实现多级缓存

```java
@Service
public class MultiLevelCacheService {

    @Autowired
    private StringRedisTemplate redisTemplate;

    private final Cache<String, Object> localCache = Caffeine.newBuilder()
        .maximumSize(1000)
        .expireAfterWrite(1, TimeUnit.MINUTES)
        .build();

    public User getUser(Long id) {
        String key = "user:" + id;

        // L1：本地缓存
        Object local = localCache.getIfPresent(key);
        if (local != null) {
            return (User) local;
        }

        // L2：Redis
        String json = redisTemplate.opsForValue().get(key);
        if (json != null) {
            User user = JSON.parseObject(json, User.class);
            localCache.put(key, user);  // 回填本地缓存
            return user;
        }

        // L3：数据库
        User user = userMapper.findById(id);
        if (user != null) {
            redisTemplate.opsForValue().set(key, JSON.toJSONString(user), 30, TimeUnit.MINUTES);
            localCache.put(key, user);
        }
        return user;
    }
}
```

### 多级缓存的一致性挑战

```text
本地缓存的一致性问题：
- 多实例部署时，某实例更新了 Redis，其他实例的本地缓存还是旧值
- 解法：本地缓存 TTL 设短（1 分钟），或通过消息广播失效
```

## 缓存一致性

缓存一致性是缓存使用中最核心的问题。

### Cache Aside 模式（最常用）

```text
读：先读缓存，命中返回；未命中读库，写缓存
写：先更新数据库，再删除缓存
```

```java
// 读
@Cacheable(value = "users", key = "#id")
public User getUser(Long id) {
    return userMapper.findById(id);
}

// 写：先更新库，再删缓存（Cache Aside）
public User updateUser(User user) {
    userMapper.update(user);          // 1. 先更新数据库
    cacheManager.getCache("users").evict(user.getId());  // 2. 再删除缓存
    return user;
}
```

### 为什么"先更新库，再删缓存"

```text
方案 A：先删缓存，再更新库
问题：删缓存后、更新库前，有请求读到旧数据写回缓存，造成脏数据

方案 B：先更新库，再删缓存（推荐）
问题：更新库后、删缓存前，有请求读到旧缓存（短暂不一致）
但窗口极小，且删缓存失败可重试

结论：方案 B 更优
```

### 延迟双删

```java
// 极端情况下的延迟双删
public void updateUser(User user) {
    cacheManager.getCache("users").evict(user.getId());  // 1. 先删一次
    userMapper.update(user);                              // 2. 更新库
    // 3. 延迟再删一次（防止并发读写回旧值）
    scheduledExecutor.schedule(() ->
        cacheManager.getCache("users").evict(user.getId()),
        500, TimeUnit.MILLISECONDS);
}
```

## 缓存三大问题

### 1. 缓存穿透

```text
问题：查询不存在的 key，每次都穿透缓存查数据库
场景：恶意请求大量不存在的 id
```

```java
// 解法 1：缓存空值
@Cacheable(value = "users", key = "#id", unless = "#result == null")
// 改为：缓存 null 值（设置短 TTL）

// 解法 2：布隆过滤器
// 查询前先用布隆过滤器判断 key 是否可能存在
if (!bloomFilter.mightContain(id)) {
    return null;  // 一定不存在，直接返回
}
```

### 2. 缓存击穿

```text
问题：热点 key 过期瞬间，大量请求同时穿透到数据库
场景：某个热 key 过期，正好有大量并发请求
```

```java
// 解法 1：互斥锁（只让一个请求查库）
@Cacheable(value = "hot", key = "#id", sync = true)  // sync 加锁
public HotData getHotData(Long id) { ... }

// 解法 2：热点 key 永不过期（或逻辑过期）
```

### 3. 缓存雪崩

```text
问题：大量 key 同时过期，瞬间流量打到数据库
场景：缓存集中过期（如定时批量设置相同 TTL）
```

```java
// 解法 1：过期时间加随机值
long ttl = 30 * 60 + new Random().nextInt(5 * 60);  // 30 分钟 + 随机 0-5 分钟

// 解法 2：多级缓存兜底
// 解法 3：限流降级
```

## 应用场景实战

### 场景 1：用户信息缓存（Redis）

```java
@Service
public class UserCacheService {

    @Cacheable(value = "users", key = "#id", unless = "#result == null")
    public User getUser(Long id) {
        return userMapper.findById(id);
    }

    @CachePut(value = "users", key = "#user.id")
    public User update(User user) {
        userMapper.update(user);
        return user;
    }

    @CacheEvict(value = "users", key = "#id")
    public void delete(Long id) {
        userMapper.delete(id);
    }
}
```

### 场景 2：热点数据本地缓存 + 分布式缓存

```java
@Service
public class HotDataService {

    @Autowired
    private StringRedisTemplate redisTemplate;

    private final Cache<String, HotData> localCache = Caffeine.newBuilder()
        .maximumSize(100)
        .expireAfterWrite(1, TimeUnit.MINUTES)
        .build();

    public HotData getHotData(String key) {
        // 本地缓存（最快）
        HotData local = localCache.getIfPresent(key);
        if (local != null) return local;

        // Redis（分布式）
        String json = redisTemplate.opsForValue().get(key);
        if (json != null) {
            HotData data = JSON.parseObject(json, HotData.class);
            localCache.put(key, data);
            return data;
        }

        // 数据库（兜底）
        HotData data = loadFromDb(key);
        if (data != null) {
            redisTemplate.opsForValue().set(key, JSON.toJSONString(data), 5, TimeUnit.MINUTES);
            localCache.put(key, data);
        }
        return data;
    }
}
```

### 场景 3：带随机过期时间的缓存（防雪崩）

```java
@Service
public class ProductService {

    @Autowired
    private RedisTemplate<String, Object> redisTemplate;

    public Product getProduct(Long id) {
        String key = "product:" + id;
        Product product = (Product) redisTemplate.opsForValue().get(key);
        if (product != null) return product;

        product = productMapper.findById(id);
        if (product != null) {
            // 随机过期时间，防止雪崩
            long ttl = 30 * 60 + new Random().nextInt(5 * 60);
            redisTemplate.opsForValue().set(key, product, ttl, TimeUnit.SECONDS);
        }
        return product;
    }
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. **缓存 null 要谨慎**。unless="#result == null" 不缓存 null，防止缓存穿透要用布隆过滤器或短 TTL 空值缓存。

2. **写操作用 Cache Aside**。先更新数据库，再删除缓存，不要用 @CachePut 更新（避免并发脏数据）。

3. **热点 key 单独处理**。热 key 用 sync=true 或逻辑过期，防止击穿。

4. **过期时间加随机值**。防止缓存雪崩。

5. **缓存只缓存查询结果，不缓存业务逻辑**。缓存的是方法返回值，不是副作用。

### 踩坑记录

**坑 1：@Cacheable 在类内部自调用不生效**

```java
@Service
public class UserService {
    public User getUser(Long id) {
        return this.getUserInternal(id);  // 自调用，缓存不生效！
    }

    @Cacheable(value = "users", key = "#id")
    public User getUserInternal(Long id) {
        return userMapper.findById(id);
    }
}
```

缓存通过 AOP 代理实现，自调用绕过代理。解法：注入自己或拆分类。

**坑 2：@Cacheable 标注的方法返回 void**

```java
@Cacheable(value = "users", key = "#id")
public void getUser(Long id) { ... }  // 返回 void，缓存的是 null，无意义
```

@Cacheable 缓存的是返回值，void 方法没有缓存价值。

**坑 3：默认序列化导致缓存不可读**

```java
// Redis 缓存用默认 JDK 序列化，redis-cli 看到乱码
// 且缓存对象必须实现 Serializable
```

配置 JSON 序列化，避免 JDK 序列化。

**坑 4：key 冲突**

```java
@Cacheable(value = "users", key = "#id")
public User getUser(Long id) { ... }

@Cacheable(value = "users", key = "#id")
public User getById(String id) { ... }  // key 都是 #id，可能冲突
// Long 1 和 String "1" 的 key 可能相同
```

key 设计要带上类型或方法信息，避免不同类型参数 key 冲突。

**坑 5：缓存大对象导致内存压力**

```java
@Cacheable(value = "reports", key = "#id")
public Report getReport(Long id) { ... }  // Report 几十 MB，缓存几万条
```

大对象不要全量缓存，缓存摘要或分片。

**坑 6：@CacheEvict 的 allEntries 滥用**

```java
@CacheEvict(value = "users", allEntries = true)  // 每次更新清空整个缓存
public void update(User user) { ... }
// 频繁更新导致缓存命中率极低
```

allEntries=true 只在必要时用（如批量操作），单个更新用 key 精确清除。

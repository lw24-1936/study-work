## 概述

Java 是面向对象语言，但八种基本类型（`int`、`double` 等）不是对象。为了让基本类型也能参与面向对象的操作——放进集合、参与泛型、调用方法——Java 给每种基本类型都配了一个对应的**包装类（Wrapper Class）**。

包装类把基本类型"包"成对象，同时提供了大量工具方法（进制转换、类型判断、字符串解析等）。

| 对比维度 | 基本类型 | 包装类型 |
|----------|----------|----------|
| 本质 | 值，存于栈 | 对象，存于堆 |
| 默认值 | `0` / `false` | `null` |
| 能否放进集合 | 不能 | 能 |
| 能否参与泛型 | 不能 | 能 |
| 运算效率 | 高 | 低（拆装箱有开销） |
| 占用内存 | 小 | 大（对象头 + 值） |

## 八种包装类速览

| 基本类型 | 包装类 | 缓存范围 |
|----------|--------|----------|
| `byte` | `Byte` | -128 ~ 127（全缓存） |
| `short` | `Short` | -128 ~ 127 |
| `int` | `Integer` | -128 ~ 127（可调） |
| `long` | `Long` | -128 ~ 127 |
| `float` | `Float` | 无缓存 |
| `double` | `Double` | 无缓存 |
| `char` | `Character` | 0 ~ 127 |
| `boolean` | `Boolean` | `true` / `false` 全缓存 |

所有包装类都不可变（`final class`），和 `String` 一样——一旦创建，内部值就不能变。

## 装箱与拆箱

**装箱（Boxing）**：基本类型 → 包装对象。
**拆箱（Unboxing）**：包装对象 → 基本类型。

JDK 5 之后编译器自动完成装箱拆箱，不需要手动 `new Integer(10)`：

```java
// 自动装箱
Integer a = 10;          // 编译器替你做：Integer.valueOf(10)
List<Integer> list = new ArrayList<>();
list.add(42);            // 自动装箱

// 自动拆箱
int b = a;               // 编译器替你做：a.intValue()
int sum = a + 5;         // 先拆箱，再运算

// 手动装箱（JDK 9+ 不推荐用 new，用 valueOf）
Integer c = Integer.valueOf(100);
// 手动拆箱
int d = c.intValue();
```

自动装箱的原理是编译器在字节码中插入 `Integer.valueOf()` 和 `intValue()` 调用。字节码里不存在"自动"这件事——就是普通的方法调用。

### null 拆箱的危险

这是一个生产环境高频踩坑点：

```java
Integer count = null;         // 可能来自数据库查询
int n = count;                // NullPointerException！拆箱调用 count.intValue()
```

```java
// 安全写法
Integer count = getCountFromDB();    // 可能返回 null
if (count != null) {
    int n = count;
}

// 或者用默认值
int safeCount = count != null ? count : 0;
```

## 基本类型与包装类型的区别

除了底层的存储位置和默认值差异，日常开发中最关键的是这三个区别：

1. **包装类型可以是 `null`**：这是双刃剑。好处是能表示"没有值"的语义（数据库字段可能为空）；坏处是忘了判空就 NPE。
2. **`==` 比较的是引用，不是值**：包装类型用 `==` 只比较内存地址，两个值相等的 Integer 可能 `==` 为 false。
3. **包装类型占用更多内存**：一个 `Integer`（16 字节对象头 + 4 字节 int + 对齐 = 24 字节），是一个 `int`（4 字节）的 6 倍。热路径上大量包装类会带来 GC 压力。

```java
// == vs equals 的经典场景
Integer x = 128;
Integer y = 128;
System.out.println(x == y);        // false —— 引用不同
System.out.println(x.equals(y));   // true  —— 值相同
```

## Integer 缓存机制

`Integer.valueOf(int)` 对 -128 ~ 127 范围内的值使用缓存——多次调用返回**同一个对象**。这个行为是 JLS（Java Language Specification）规定的。

```java
Integer a = 127;
Integer b = 127;
System.out.println(a == b);    // true  —— 缓存命中，同一个对象

Integer c = 128;
Integer d = 128;
System.out.println(c == d);    // false —— 超出缓存范围，两个对象
```

缓存上限可以通过 JVM 参数调整：

```sh
java -Djava.lang.Integer.IntegerCache.high=1024
```

下限（-128）不可调，上限调到 1024 意味着 0 ~ 1024 也被缓存。这个参数只影响 `valueOf` 和自动装箱——`new Integer(n)` 永远不缓存，但 JDK 9 已经把构造方法标记为 `@Deprecated`，建议用 `valueOf`。

## valueOf 与 parseXXX

这两个方法长得像，用途完全不同：

| 方法 | 返回类型 | 用途 |
|------|----------|------|
| `Integer.valueOf("123")` | `Integer`（对象） | 字符串转包装对象，可用缓存 |
| `Integer.parseInt("123")` | `int`（基本类型） | 字符串转基本类型，性能更好 |

```java
// 推荐：不需要对象时直接用 parseInt，避免无谓的装箱
int n = Integer.parseInt("255");              // 十进制
int hex = Integer.parseInt("FF", 16);         // 十六进制 → 255
int bin = Integer.parseInt("1010", 2);        // 二进制 → 10

// 转换失败抛 NumberFormatException
// Integer.parseInt("abc");   // NumberFormatException

// 进制转换
String binary = Integer.toBinaryString(10);   // "1010"
String hexStr = Integer.toHexString(255);     // "ff"
String octal = Integer.toOctalString(64);     // "100"

// valueOf 用缓存，适合需要对象的场景（放进集合等）
Integer obj = Integer.valueOf(100);
```

## 包装类型的比较陷阱

```java
// 陷阱 1：== 只在缓存范围内可靠
Integer a = 100, b = 100;
System.out.println(a == b);       // true —— 缓存命中

Integer c = 200, d = 200;
System.out.println(c == d);       // false —— 超出缓存
System.out.println(c.equals(d));  // true —— 正确比较方式

// 陷阱 2：混合类型比较 —— 编译器会拆箱
Integer e = 100;
int f = 100;
System.out.println(e == f);       // true —— 拆箱后比较 int 值

// 陷阱 3：Float/Double 无缓存
Float g = 1.0f, h = 1.0f;
System.out.println(g == h);       // false —— 每次都 new
```

## Number 抽象类

`Number` 是所有数值包装类的父类，提供统一的值提取方法：

```java
public abstract class Number {
    public abstract int intValue();
    public abstract long longValue();
    public abstract float floatValue();
    public abstract double doubleValue();
    public byte byteValue();
    public short shortValue();
}

// 多态用法：处理未知数值类型
public static double toDouble(Number num) {
    return num.doubleValue();
}

System.out.println(toDouble(42));           // 42.0
System.out.println(toDouble(3.14f));        // 3.140000104904175
System.out.println(toDouble(100L));         // 100.0
```

## 应用场景实战

### 场景一：集合与泛型

```java
// 基本类型不能作为泛型参数
// List<int> list = new ArrayList<>();   // 编译错误！

List<Integer> scores = new ArrayList<>();
scores.add(95);       // 自动装箱
scores.add(88);

// 取最大值
int max = Collections.max(scores);   // 自动拆箱
```

### 场景二：数据库字段映射

```java
// 实体类——用包装类型表示可为空的字段
public class User {
    private Long id;           // 用 Long 而不是 long，因为数据库可能为 null
    private String name;
    private Integer age;       // 年龄可能未填
    private Double salary;     // 薪资可能不在查询范围
    private Boolean active;    // 激活状态可能未知

    // getter/setter 省略
}
```

### 场景三：配置解析

```java
// 从配置文件读取数值
Properties props = new Properties();
props.load(new FileReader("app.properties"));

// parseInt 更高效 —— 直接得到基本类型
int port = Integer.parseInt(props.getProperty("server.port", "8080"));
int timeout = Integer.parseInt(props.getProperty("timeout", "30"));

// 如果不是数字，抛 NumberFormatException 而不是返回 null
// 这符合 fail-fast 原则
```

### 场景四：统计计算中的空值处理

```java
public class OrderStats {
    // 计算平均金额，跳过空值
    public static double average(List<Double> amounts) {
        double sum = 0;
        int count = 0;
        for (Double amt : amounts) {
            if (amt != null) {          // 必须判空，否则拆箱 NPE
                sum += amt;             // 自动拆箱
                count++;
            }
        }
        return count == 0 ? 0 : sum / count;
    }
}
```

## 最佳实践与常见问题

### 选择原则

| 场景 | 推荐 |
|------|------|
| 方法的局部变量、循环计数 | `int` / `double`（基本类型） |
| 实体类属性（数据库映射） | `Integer` / `Long` / `Double`（可 null） |
| 集合元素 | 包装类型 |
| 泛型参数 | 包装类型（别无选择） |
| 大量计算（科学计算、图像处理） | 基本类型 |
| Optional 包装值 | 包装类型 |

### 常见问题表

| 问题 | 原因 | 修复 |
|------|------|------|
| NPE："intValue()" | 对 null 包装类拆箱 | 拆箱前判空或用 `Optional.ofNullable(val).orElse(0)` |
| `==` 比较结果不稳定 | Integer 缓存只到 127 | 统一用 `equals()` 或拆箱到 int 再 `==` |
| `List<Integer>` 和 `int[]` 互转慢 | 无直接的批量转换 | 用 `IntStream` 或 `Arrays.stream` |
| 泛型方法不接受 `int[]` | 基本类型数组是引用类型但不是包装类数组 | 用 `Integer[]` 或用 Stream |

### 性能建议

```java
// 热路径上避免无谓的装箱拆箱
// 不推荐：int → Integer → int
Integer sum = 0;
for (int i = 0; i < 1000000; i++) {
    sum += i;    // 每次循环：拆箱、相加、装箱
}

// 推荐：全程基本类型
int sum = 0;
for (int i = 0; i < 1000000; i++) {
    sum += i;
}
```

## 总结

- 八种基本类型各有对应包装类，包装类是不可变对象，可放进集合和泛型
- 自动装箱拆箱由编译器完成（`valueOf` / `intValue`），null 拆箱直接 NPE
- `==` 比较包装类引用不可靠——用 `equals()`，或者先拆箱到基本类型
- `valueOf` 会缓存 -128 ~ 127 的 Integer，`parseInt` 返回基本类型更高效
- 实体类属性用包装类型（可表示 null），局部变量和计算用基本类型

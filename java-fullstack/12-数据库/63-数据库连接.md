## 概述

Java 通过 JDBC（Java Database Connectivity）与数据库交互。JDBC 定义了一套标准接口，各数据库厂商提供对应的驱动实现。直接使用 JDBC 需要手动管理连接，生产环境通过连接池（HikariCP、Druid）复用连接。

本章不重复第 64 章 JDBC 的完整内容，重点放在数据库连接的管理和连接池——这些是生产环境的核心关注点。

## JDBC 架构

```
┌─────────────────────────────────────────────┐
│         Java 应用代码                         │
│  (Spring JDBC / MyBatis / Hibernate / JPA)  │
├─────────────────────────────────────────────┤
│              JDBC API                        │
│  (java.sql / javax.sql 接口)                │
├─────────────────────────────────────────────┤
│           JDBC Driver Manager                │
│  (加载驱动、建立连接)                          │
├─────────────────────────────────────────────┤
│    MySQL Driver │ PostgreSQL Driver │ ...   │
│  (mysql-connector-j)                        │
├─────────────────────────────────────────────┤
│          MySQL / PostgreSQL / Oracle         │
└─────────────────────────────────────────────┘
```

四种 JDBC 驱动类型：

**Type 1（JDBC-ODBC Bridge）**：已从 JDK 8 中移除。桥接 ODBC 驱动，依赖本地 ODBC 配置。

**Type 2（Native-API Driver）**：Java 调用本地数据库客户端库（C/C++），需安装客户端。

**Type 3（Network Protocol Driver）**：三层架构，JDBC 调用 → 中间件 → 数据库。灵活但复杂。

**Type 4（Thin Driver / Direct-to-Database）**：纯 Java 实现，直接通过 Socket 与数据库通信。最常用——MySQL 的 `mysql-connector-j` 就是 Type 4。

## JDBC 核心接口

### Driver —— 驱动注册

```java
// JDBC 4.0+ 通过 SPI 自动注册（META-INF/services/java.sql.Driver）
// 无需手动 Class.forName()
Class.forName("com.mysql.cj.jdbc.Driver");  // 旧写法，现在不需要
```

### Connection —— 数据库连接

```java
// 方式一：DriverManager（简单应用）
String url = "jdbc:mysql://localhost:3306/mydb?useSSL=false&serverTimezone=Asia/Shanghai";
Connection conn = DriverManager.getConnection(url, "root", "password");

// 方式二：DataSource（生产环境，配合连接池）
DataSource ds = new HikariDataSource(config);
Connection conn = ds.getConnection();
```

MySQL 连接 URL 常用参数：

```
jdbc:mysql://host:port/database?参数1=值1&参数2=值2

useSSL=false / true              是否使用 SSL
serverTimezone=Asia/Shanghai     时区（8.0+ 驱动必须设置）
characterEncoding=utf8           字符编码
useUnicode=true                  使用 Unicode
rewriteBatchedStatements=true    重写批量插入（提升批量性能）
allowPublicKeyRetrieval=true     允许获取公钥（SSL 模式下）
useServerPrepStmts=true          使用服务端预编译
cachePrepStmts=true              缓存预编译语句
```

### 完整 JDBC 示例

```java
public class JdbcDemo {
    public static void main(String[] args) {
        String url = "jdbc:mysql://localhost:3306/mydb";
        String user = "root";
        String password = "password";

        // try-with-resources 自动关闭资源（Java 7+）
        try (Connection conn = DriverManager.getConnection(url, user, password)) {

            // 查询
            try (PreparedStatement ps = conn.prepareStatement(
                    "SELECT id, name, salary FROM employee WHERE dept_id = ?")) {
                ps.setInt(1, 1);
                try (ResultSet rs = ps.executeQuery()) {
                    while (rs.next()) {
                        long id = rs.getLong("id");
                        String name = rs.getString("name");
                        BigDecimal salary = rs.getBigDecimal("salary");
                        System.out.printf("id=%d, name=%s, salary=%s%n", id, name, salary);
                    }
                }
            }

            // 更新
            try (PreparedStatement ps = conn.prepareStatement(
                    "UPDATE employee SET salary = ? WHERE id = ?")) {
                ps.setBigDecimal(1, new BigDecimal("18000"));
                ps.setLong(2, 1);
                int rows = ps.executeUpdate();
                System.out.println("更新行数: " + rows);
            }
        } catch (SQLException e) {
            e.printStackTrace();
        }
    }
}
```

## PreparedStatement —— 预编译语句

PreparedStatement 是 JDBC 中最重要的接口之一，完成两件事：防止 SQL 注入和提升性能。

### 防止 SQL 注入

```java
// 危险写法：拼接 SQL → SQL 注入
String name = request.getParameter("name");  // 用户输入: ' OR '1'='1
String sql = "SELECT * FROM user WHERE name = '" + name + "'";
// 实际执行: SELECT * FROM user WHERE name = '' OR '1'='1' → 返回全部用户

// 正确写法：PreparedStatement 参数化
String sql = "SELECT * FROM user WHERE name = ?";
PreparedStatement ps = conn.prepareStatement(sql);
ps.setString(1, name);  // 参数转义，' OR '1'='1 被当作普通字符串
```

### 预编译提升性能

MySQL 预编译流程：

```
1. 发送 SQL 模板 + 参数 → 数据库解析、优化、生成执行计划
2. 后续同模板的调用只需发送参数 → 直接执行（跳过解析优化）
```

```java
// JDBC URL 开启服务端预编译
// jdbc:mysql://localhost:3306/db?useServerPrepStmts=true&cachePrepStmts=true

String sql = "INSERT INTO user (name, email) VALUES (?, ?)";
try (PreparedStatement ps = conn.prepareStatement(sql)) {
    for (User u : users) {
        ps.setString(1, u.getName());
        ps.setString(2, u.getEmail());
        ps.addBatch();   // 加入批处理
    }
    ps.executeBatch();   // 一次发送所有
}
```

### Statement vs PreparedStatement

| | Statement | PreparedStatement |
|--|-----------|-------------------|
| SQL 注入 | 危险 | 安全 |
| 预编译 | 不支持 | 支持 |
| 二进制数据 | 困难 | 支持（setBlob/setBinaryStream） |
| 性能 | 每次解析 | 一次解析多次执行 |
| 可读性 | 拼接混乱 | 参数化清晰 |

## ResultSet —— 结果集处理

```java
try (ResultSet rs = ps.executeQuery()) {
    // 按列名获取（推荐：列名明确，不受 SELECT 顺序影响）
    long id = rs.getLong("id");
    String name = rs.getString("name");

    // 按列索引获取（从 1 开始）
    long id2 = rs.getLong(1);
    String name2 = rs.getString(2);

    // NULL 处理
    String email = rs.getString("email");
    if (rs.wasNull()) {
        email = "未设置";
    }
    // 或者直接用包装类型接收
    // Integer age = (Integer) rs.getObject("age"); // 可能 null

    // ResultSetMetaData —— 获取列信息
    ResultSetMetaData meta = rs.getMetaData();
    int colCount = meta.getColumnCount();
    for (int i = 1; i <= colCount; i++) {
        String colName = meta.getColumnName(i);
        String colType = meta.getColumnTypeName(i);
    }
}
```

### 可滚动 ResultSet

```java
// 创建可滚动、可更新的 Statement
Statement stmt = conn.createStatement(
    ResultSet.TYPE_SCROLL_INSENSITIVE,  // 可滚动，不感知外部修改
    ResultSet.CONCUR_READ_ONLY          // 只读
);

ResultSet rs = stmt.executeQuery("SELECT * FROM employee");

rs.absolute(5);     // 跳到第 5 行
rs.relative(-2);    // 向前移 2 行
rs.first();         // 第一行
rs.last();          // 最后一行
rs.previous();      // 上一行
```

`TYPE_SCROLL_INSENSITIVE` 会把所有结果加载到内存，大数据集不要用。

## Batch 批处理

逐条 INSERT 10000 条数据需要 10000 次网络往返。Batch 将这 10000 条打包成一批发送。

```java
String sql = "INSERT INTO log (user_id, action, created_at) VALUES (?, ?, ?)";
try (PreparedStatement ps = conn.prepareStatement(sql)) {
    for (int i = 0; i < 10000; i++) {
        ps.setLong(1, i);
        ps.setString(2, "LOGIN");
        ps.setTimestamp(3, Timestamp.valueOf(LocalDateTime.now()));
        ps.addBatch();

        // 每 1000 条执行一批
        if (i % 1000 == 0) {
            ps.executeBatch();
            ps.clearBatch();
        }
    }
    ps.executeBatch();  // 最后一批
}
```

性能对比（10000 条插入）：

| 方式 | 时间（约） | 网络往返 |
|------|-----------|----------|
| 逐条 executeUpdate | 30-60s | 10000 次 |
| Batch（每 1000 条） | 1-3s | 10 次 |
| Batch + rewriteBatchedStatements | <1s | 1 次（合并成单条多 VALUES） |

`rewriteBatchedStatements=true` 会将批量 INSERT 重写为单条：

```sql
-- 原来：多条 INSERT
INSERT INTO t VALUES (1, 'a');
INSERT INTO t VALUES (2, 'b');
INSERT INTO t VALUES (3, 'c');

-- 重写后：单条多 VALUES
INSERT INTO t VALUES (1, 'a'), (2, 'b'), (3, 'c');
```

## 事务处理

```java
Connection conn = null;
try {
    conn = ds.getConnection();
    conn.setAutoCommit(false);  // 关闭自动提交

    try (PreparedStatement ps1 = conn.prepareStatement(
            "UPDATE account SET balance = balance - ? WHERE id = ?")) {
        ps1.setBigDecimal(1, amount);
        ps1.setLong(2, fromId);
        ps1.executeUpdate();
    }

    try (PreparedStatement ps2 = conn.prepareStatement(
            "UPDATE account SET balance = balance + ? WHERE id = ?")) {
        ps2.setBigDecimal(1, amount);
        ps2.setLong(2, toId);
        ps2.executeUpdate();
    }

    conn.commit();     // 提交

} catch (SQLException e) {
    if (conn != null) {
        try { conn.rollback(); } catch (SQLException ex) { ex.printStackTrace(); }
    }
    throw e;
} finally {
    if (conn != null) {
        try { conn.setAutoCommit(true); conn.close(); } catch (SQLException e) { }
    }
}
```

### 隔离级别设置

```java
// JDBC 层面
conn.setTransactionIsolation(Connection.TRANSACTION_READ_COMMITTED);

// 隔离级别常量：
// TRANSACTION_READ_UNCOMMITTED  = 1
// TRANSACTION_READ_COMMITTED    = 2
// TRANSACTION_REPEATABLE_READ   = 4
// TRANSACTION_SERIALIZABLE      = 8
```

Spring 中由 `@Transactional(isolation = Isolation.READ_COMMITTED)` 管理。

### Savepoint 部分回滚

```java
conn.setAutoCommit(false);
Savepoint sp1 = conn.setSavepoint("sp1");

ps.executeUpdate("UPDATE account SET balance = balance - 100 WHERE id = 1");
Savepoint sp2 = conn.setSavepoint("sp2");

try {
    ps.executeUpdate("UPDATE account SET balance = balance + 100 WHERE id = 99999");
    // id=99999 不存在 → 受影响 0 行
} catch (SQLException e) {
    conn.rollback(sp2);  // 只回滚第二条 UPDATE
}

conn.commit();  // 第一条 UPDATE 生效
```

## 连接池概述

### 为什么需要连接池

每次创建 TCP 连接 + MySQL 认证握手 = 约 20-50ms。高并发下频繁创建/销毁连接会严重拖慢系统。连接池预创建一批连接并复用。

```
没有连接池：
请求1 → 创建连接(20ms) → 执行SQL(1ms) → 关闭连接 → 释放
请求2 → 创建连接(20ms) → 执行SQL(1ms) → 关闭连接 → 释放
CPU 和网络开销全在创建连接上

有连接池：
启动时 → 预创建 10 个连接 → 放入池中
请求1 → 借一个连接 → 执行SQL(1ms) → 归还 → 池中
请求2 → 借一个连接 → 执行SQL(1ms) → 归还 → 池中
```

### 连接池的核心参数

| 参数 | 说明 | 建议值 |
|------|------|--------|
| minimumIdle | 最小空闲连接数 | 等于 maximumPoolSize |
| maximumPoolSize | 最大连接数 | 按 QPS 和 RT 计算 |
| connectionTimeout | 获取连接超时 | 30000ms |
| idleTimeout | 空闲连接最大存活时间 | 600000ms |
| maxLifetime | 连接最大存活时间 | 1800000ms（比数据库 wait_timeout 短） |

**连接数计算公式**：

```
连接数 = ((核心数 * 2) + 有效磁盘数)

实际公式（来自 HikariCP 文档）：
connections = ((core_count * 2) + effective_spindle_count)

effective_spindle_count 是硬盘主轴数，SSD 约等于 1

4 核 SSD 服务器：connections = (4*2) + 1 = 9
```

实际值需要根据压测调整。并发请求多而连接数太少会积压等待；连接数太多会加重数据库负担。

### 连接验证

连接池中的空闲连接可能已被数据库断开（MySQL 默认 wait_timeout=8h），使用前需要验证：

```sql
-- 验证 SQL
SELECT 1   -- 最轻量，只返回 1

-- 或在连接 URL 中配置自动重连
autoReconnect=true   -- 不推荐（生产环境可能雪崩）
```

## HikariCP

HikariCP 是 Spring Boot 2.x 的默认连接池，以"快"著称。字节码级优化，连接代理不生成大量垃圾对象。

### Maven 依赖

```xml
<dependency>
    <groupId>com.zaxxer</groupId>
    <artifactId>HikariCP</artifactId>
</dependency>
<!-- Spring Boot 自动包含，无需额外引入 -->
```

### Spring Boot 配置

```yaml
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/mydb?useSSL=false&serverTimezone=Asia/Shanghai&rewriteBatchedStatements=true
    username: root
    password: password
    driver-class-name: com.mysql.cj.jdbc.Driver
    hikari:
      minimum-idle: 10
      maximum-pool-size: 20
      connection-timeout: 30000
      idle-timeout: 600000
      max-lifetime: 1800000
      connection-test-query: SELECT 1
      pool-name: MyPool
```

### 代码配置（不使用 Spring Boot）

```java
HikariConfig config = new HikariConfig();
config.setJdbcUrl("jdbc:mysql://localhost:3306/mydb");
config.setUsername("root");
config.setPassword("password");
config.setMinimumIdle(10);
config.setMaximumPoolSize(20);
config.setConnectionTimeout(30000);
config.setIdleTimeout(600000);
config.setMaxLifetime(1800000);
config.setConnectionTestQuery("SELECT 1");

HikariDataSource ds = new HikariDataSource(config);
```

### HikariCP 为什么快

1. **字节码精简**：编译后的类文件极小，JIT 友好
2. **FastList 替代 ArrayList**：无范围检查，remove 不从头扫描
3. **ConcurrentBag**：无锁设计，用 ThreadLocal + CAS 管理连接
4. **Proxy 生成优化**：Javassist 直接生成字节码而非反射代理

### 连接泄漏检测

```yaml
spring:
  datasource:
    hikari:
      leak-detection-threshold: 10000   # 超过 10s 未归还的连接到 WARN 日志
```

日志输出：

```
[HikariPool-1 housekeeper] WARN  c.z.h.p.ProxyLeakTask
  - Connection leak detection triggered for conn1, stack trace follows
java.lang.Exception: Apparent connection leak detected
  at com.example.MyService.slowMethod(MyService.java:42)
```

## Druid

Druid 是阿里开源的连接池，除了连接池功能还内置 SQL 监控、Web 控制台、防火墙。

### Maven 依赖

```xml
<dependency>
    <groupId>com.alibaba</groupId>
    <artifactId>druid-spring-boot-starter</artifactId>
    <version>1.2.20</version>
</dependency>
```

### Spring Boot 配置

```yaml
spring:
  datasource:
    druid:
      url: jdbc:mysql://localhost:3306/mydb?useSSL=false&serverTimezone=Asia/Shanghai
      username: root
      password: password
      driver-class-name: com.mysql.cj.jdbc.Driver

      # 连接池
      initial-size: 5
      min-idle: 10
      max-active: 20
      max-wait: 30000

      # 检测
      test-while-idle: true
      test-on-borrow: false
      test-on-return: false
      validation-query: SELECT 1
      time-between-eviction-runs-millis: 60000

      # 监控
      stat-view-servlet:
        enabled: true
        url-pattern: /druid/*
        login-username: admin
        login-password: admin123

      # 过滤器
      filters: stat,wall,slf4j

      # 防火墙
      filter:
        wall:
          enabled: true
          config:
            drop-table-allow: false   # 禁止 DROP TABLE

      # Web 监控
      web-stat-filter:
        enabled: true
        url-pattern: /*
        exclusions: "*.js,*.gif,*.jpg,*.png,*.css,*.ico,/druid/*"
```

### Druid 监控能力

访问 `http://localhost:8080/druid` 查看：
- 数据源状态（活跃连接数、等待数）
- SQL 执行统计（执行次数、耗时、并发）
- SQL 防火墙（拦截记录）
- URI 监控（各接口的 SQL 调用情况）

### HikariCP vs Druid

| 特性 | HikariCP | Druid |
|------|----------|-------|
| 性能 | 最高 | 略低（监控开销） |
| SQL 监控 | 无（需第三方） | 内置 |
| Web 控制台 | 无 | 内置 |
| SQL 防火墙 | 无 | 内置 |
| 社区 | 全球活跃 | 国内活跃 |
| Spring Boot 默认 | 是（2.x） | 否 |
| 适用场景 | 性能优先 | 运维监控优先 |

通用规则：性能优先选 HikariCP；团队需要 SQL 监控选 Druid。两者可以共存。

## 应用场景实战

### 场景一：Spring Boot + HikariCP 配置（生产级）

```yaml
spring:
  datasource:
    url: jdbc:mysql://192.168.1.100:3306/mydb?useSSL=false&serverTimezone=Asia/Shanghai&characterEncoding=utf8&rewriteBatchedStatements=true&cachePrepStmts=true&useServerPrepStmts=true
    username: app
    password: ${DB_PASSWORD}    # 环境变量，不硬编码
    hikari:
      pool-name: BizDBPool
      minimum-idle: 10
      maximum-pool-size: 20
      connection-timeout: 5000
      idle-timeout: 300000
      max-lifetime: 1200000
      leak-detection-threshold: 15000
      connection-test-query: SELECT 1
```

关键决策：
- `maximum-pool-size=20`：根据压测确定，不要让数据库连接数超过 `max_connections` / 服务实例数
- `connection-timeout=5000`：获取连接超时 5 秒，比默认 30 秒更激进——宁可快速失败让调用方重试
- `leak-detection-threshold=15000`：超过 15 秒未归还打印警告栈，方便排查连接泄漏
- `max-lifetime=1200000`（20 分钟）：必须小于 MySQL `wait_timeout`（默认 8 小时），比 idle-timeout 大，确保连接在被 MySQL 断开前就由连接池主动回收

### 场景二：Druid 多数据源

### 场景三：连接池监控指标

HikariCP 提供 Micrometer 指标，接入 Prometheus + Grafana：

```java
// HikariCP 自动注册 Micrometer 指标（需引入 micrometer-core）
// 可监控：
// hikaricp_connections_active    活跃连接
// hikaricp_connections_idle       空闲连接
// hikaricp_connections_pending    等待获取连接的线程数
// hikaricp_connections_timeout    超时次数
// hikaricp_connections_creation_seconds  创建连接耗时
```

告警规则：
- `hikaricp_connections_pending > 0` 持续 1 分钟 → 连接池不够用
- `hikaricp_connections_timeout > 0` → 有线程获取连接超时
- `hikaricp_connections_active / maximumPoolSize > 0.8` → 接近上限

## 最佳实践与踩坑记录

**实践 1：连接池大小设置**

不要盲目设置过大。每个数据库连接的 MySQL 线程约占用 256KB-512KB 内存。1000 个连接就是 256MB-512MB——而且是两边都占（应用 + 数据库）。

公式作为起点，压测后确定最终值。监控 `connections_pending`，如果持续 > 0，说明池太小。

**实践 2：始终使用 try-with-resources**

```java
// 正确：自动关闭
try (Connection conn = ds.getConnection();
     PreparedStatement ps = conn.prepareStatement(sql);
     ResultSet rs = ps.executeQuery()) {
    // ...
}

// 错误：可能泄漏连接
Connection conn = ds.getConnection();
PreparedStatement ps = conn.prepareStatement(sql);
ResultSet rs = ps.executeQuery();
// 忘记 close() → 连接泄漏
```

**实践 3：maxLifetime 设置**

必须小于 MySQL `wait_timeout`。连接池在连接到达 maxLifetime 时主动关闭并创建新连接。如果 maxLifetime 大于 wait_timeout，连接被 MySQL 断开而连接池不知道，下次使用时报 `CommunicationsException`。

```sql
-- 查看 MySQL wait_timeout
SHOW VARIABLES LIKE 'wait_timeout';  -- 默认 28800（8 小时）
```

HikariCP 默认 maxLifetime=1800000（30 分钟），安全。Druid 不设 maxLifetime 也相对安全（有 keepAlive 机制）。

**实践 4：不要在循环内获取连接**

```java
// 错误：每次循环借一次连接
for (Item item : items) {
    try (Connection conn = ds.getConnection()) {
        // ...
    }
}

// 正确：复用连接
try (Connection conn = ds.getConnection()) {
    for (Item item : items) {
        // ...
    }
}
```

**踩坑 1**：ResultSet 未关闭导致连接无法归还。用 try-with-resources 解决。

**踩坑 2**：MySQL 8.x 驱动需要指定时区 `serverTimezone`，否则报 `The server time zone value 'xxx' is unrecognized`。

**踩坑 3**：`rewriteBatchedStatements=true` 存在限制——INSERT 语句中不能有 `ON DUPLICATE KEY UPDATE`、`INSERT IGNORE` 等修饰。需要时跳过 rewrite。

**踩坑 4**：Druid 的 `test-while-idle` 默认 true 但 `time-between-eviction-runs-millis` 默认不设置，导致空闲检测不生效。确保同时配置。

**踩坑 5**：Spring Boot 3.x 中 `spring.datasource.url` 不再需要 `driver-class-name`（自动推断）。但多数据源时仍需显式指定。

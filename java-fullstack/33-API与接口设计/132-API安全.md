## 概述

API 安全保护接口不被滥用，核心是认证（你是谁）、授权（能做什么）、防护（防攻击）。

```text
API 安全的三大问题：
1. 认证（Authentication）—— 确认调用方身份
2. 授权（Authorization）—— 控制访问权限
3. 防护（Protection）—— 防攻击（限流、防重放）
```

```text
常见攻击：
1. 未认证访问 —— 接口裸奔
2. 重放攻击 —— 截取请求重发
3. 篡改 —— 修改请求内容
4. 刷接口 —— 恶意高频调用
```

## 认证方式对比

### 四种认证方式

| 方式 | 原理 | 适用场景 |
|------|------|---------|
| JWT | 无状态 token | 前后端分离、微服务 |
| OAuth2 | 授权协议 | 第三方授权 |
| API Key | 简单密钥 | 开放平台、机器间调用 |
| Signature | 签名（HMAC） | 支付、高安全场景 |

### 选型建议

```text
1. 内部系统、前后端分离 → JWT
2. 第三方接入 → OAuth2 或 API Key
3. 支付、金融 → 签名（HMAC）
4. 开放平台 → API Key + 签名
```

## JWT 认证

JWT 是无状态认证，token 包含用户信息（详见 83-JWT）。

### 认证流程

```text
1. 登录 → 服务端签发 JWT
2. 客户端携带 JWT（Authorization: Bearer xxx）
3. 服务端校验 JWT 签名和有效期
4. 解析用户信息，处理请求
```

### Spring Security + JWT

```java
// JWT 过滤器
@Component
public class JwtAuthFilter extends OncePerRequestFilter {

    @Override
    protected void doFilterInternal(HttpServletRequest request,
            HttpServletResponse response, FilterChain chain) {
        String token = extractToken(request);
        if (token != null && jwtUtil.isValid(token)) {
            String username = jwtUtil.getUsername(token);
            // 设置认证信息
            UsernamePasswordAuthenticationToken auth =
                new UsernamePasswordAuthenticationToken(username, null, authorities);
            SecurityContextHolder.getContext().setAuthentication(auth);
        }
        chain.doFilter(request, response);
    }
}
```

## API Key 认证

API Key 是简单的密钥认证，客户端携带密钥访问。

### 使用方式

```text
客户端请求携带 API Key：
1. Header：X-API-Key: abc123
2. Query：?api_key=abc123
```

```java
// API Key 校验
@Component
public class ApiKeyFilter extends OncePerRequestFilter {

    @Override
    protected void doFilterInternal(HttpServletRequest request,
            HttpServletResponse response, FilterChain chain) {
        String apiKey = request.getHeader("X-API-Key");
        if (apiKey == null || !apiKeyService.isValid(apiKey)) {
            response.setStatus(HttpStatus.UNAUTHORIZED.value());
            return;
        }
        chain.doFilter(request, response);
    }
}
```

### API Key 的局限

```text
1. 简单 —— 一个字符串，易泄露
2. 无法认证用户 —— 只能认证"应用"
3. 适合机器间调用、开放平台
```

## 签名认证（HMAC）

签名认证用密钥对请求做摘要，防止篡改和重放，适合高安全场景。

### HMAC 签名原理

```text
1. 客户端和服务端共享密钥（secret）
2. 客户端用 secret 对请求参数做 HMAC 摘要
3. 请求携带签名（signature）+ 时间戳 + 随机数
4. 服务端用同样的 secret 计算签名，比对
```

### 签名流程

```text
签名 = HMAC-SHA256(secret, method + path + timestamp + nonce + body)

请求：
X-App-Id: app1
X-Timestamp: 1704067200
X-Nonce: abc123
X-Signature: 5f3a...
```

### 签名验证（Java）

```java
public class SignatureUtil {

    // 生成签名
    public static String sign(String secret, String method, String path,
                              long timestamp, String nonce, String body) {
        String data = method + "\n" + path + "\n" + timestamp + "\n" + nonce + "\n" + body;
        try {
            Mac mac = Mac.getInstance("HmacSHA256");
            mac.init(new SecretKeySpec(secret.getBytes(), "HmacSHA256"));
            byte[] bytes = mac.doFinal(data.getBytes());
            return Base64.getEncoder().encodeToString(bytes);
        } catch (Exception e) {
            throw new RuntimeException(e);
        }
    }

    // 验证签名
    public static boolean verify(String secret, String signature, String method,
                                 String path, long timestamp, String nonce, String body) {
        // 1. 检查时间戳（防重放，5 分钟内有效）
        if (Math.abs(System.currentTimeMillis() - timestamp) > 5 * 60 * 1000) {
            return false;
        }
        // 2. 计算并比对签名
        String expected = sign(secret, method, path, timestamp, nonce, body);
        return MessageDigest.isEqual(
            expected.getBytes(), signature.getBytes());  // 恒时比较防时序攻击
    }
}
```

### 签名的安全要素

```text
1. 时间戳 —— 防重放（过期请求无效）
2. nonce（随机数）—— 防重放（同时间戳的重复请求）
3. HMAC —— 防篡改（内容改了签名不匹配）
4. 恒时比较 —— 防时序攻击
```

## 限流与幂等

### 限流（Rate Limit）

```text
限流防止接口被刷，保护系统（详见 103-高并发）
```

```java
// 接口限流注解
@RateLimiter(name = "api-limiter", fallbackMethod = "rateLimitFallback")
public Result process() { ... }

public Result rateLimitFallback(Throwable t) {
    return Result.error(429, "请求过于频繁");
}
```

### 幂等（Idempotency）

```text
幂等：重复请求不产生副作用（防重复提交、防重放）
```

```text
幂等的实现：
1. 幂等键 —— 请求带 Idempotency-Key，服务端去重
2. 唯一索引 —— 数据库唯一约束兜底
3. 分布式锁 —— 同一请求加锁
```

```java
// 幂等实现（幂等键 + Redis 去重）
public Result createOrder(OrderDTO dto) {
    String idempotencyKey = dto.getIdempotencyKey();

    // Redis 去重
    Boolean first = redisTemplate.opsForValue()
        .setIfAbsent("idempotent:" + idempotencyKey, "1", 24, TimeUnit.HOURS);
    if (!Boolean.TRUE.equals(first)) {
        return Result.error("重复请求");   // 已处理过
    }

    // 处理业务
    return orderService.create(dto);
}
```

## 应用场景实战

### 场景 1：签名认证完整实现

```java
// 客户端请求（带签名）
public void callApi() {
    String appId = "app1";
    String secret = "shared-secret";
    String method = "POST";
    String path = "/api/orders";
    long timestamp = System.currentTimeMillis();
    String nonce = UUID.randomUUID().toString();
    String body = "{\"userId\":1}";

    String signature = SignatureUtil.sign(secret, method, path, timestamp, nonce, body);

    // 发送请求，携带签名信息
    httpClient.post("/api/orders")
        .header("X-App-Id", appId)
        .header("X-Timestamp", String.valueOf(timestamp))
        .header("X-Nonce", nonce)
        .header("X-Signature", signature)
        .body(body);
}
```

### 场景 2：接口安全组合

```text
完整的 API 安全方案：
1. 认证 —— JWT（用户身份）
2. 传输 —— HTTPS（加密传输）
3. 限流 —— 防止刷接口
4. 幂等 —— 防止重复提交
5. 参数校验 —— 防止注入
```

## 最佳实践与踩坑记录

### 最佳实践

1. **传输用 HTTPS**。明文 HTTP 传输 token/密钥会被截获。

2. **密钥放服务端**。secret 不能下发到客户端（前端）。

3. **签名加时间戳和 nonce**。防重放攻击。

4. **密钥轮换**。定期更换密钥，泄露及时作废。

5. **敏感接口加限流**。登录、支付等接口单独限流。

### 踩坑记录

**坑 1：secret 硬编码在前端**

```javascript
// 前端代码里的 secret，等于公开
const secret = "my-secret-key";
```

secret 只能放服务端，前端用 JWT（无 secret）。

**坑 2：签名不校验时间戳**

```java
// 只校验签名，不校验时间戳，重放攻击有效
```

签名必须配合时间戳（过期失效）和 nonce（防重放）。

**坑 3：HTTP 明文传输 token**

```text
HTTP 明文传输 JWT，token 被截获，冒充用户
```

生产环境必须 HTTPS。

**坑 4：恒时比较缺失**

```java
// 普通字符串比较，存在时序攻击风险
if (expected.equals(actual)) { ... }
```

签名比较用 MessageDigest.isEqual（恒时比较）。

**坑 5：JWT 不校验有效期**

```java
jwtUtil.isValid(token);   // 只校验签名，不校验过期
// 过期 token 仍有效
```

JWT 校验要包括签名 + 过期时间。

**坑 6：幂等键不持久化**

```text
幂等键只存内存，服务重启后丢失，重复请求又生效
```

幂等键存 Redis/数据库，设置合理的过期时间。

## 概述

API 文档是接口的使用说明书，好的文档让前后端协作高效、接口可发现、可测试。

```text
API 文档的价值：
1. 协作 —— 前后端并行开发，接口对齐
2. 测试 —— 文档界面可在线调试
3. 维护 —— 接口变更同步文档
4. 发现 —— 接口一目了然
```

```text
主流方案：
1. Swagger/OpenAPI —— 注解自动生成（最流行）
2. Knife4j —— Swagger 增强（国内流行）
3. Spring REST Docs —— 测试驱动文档
```

## OpenAPI 规范

OpenAPI（原 Swagger）是 API 文档的标准规范，描述接口的结构。

### OpenAPI 是什么

```text
OpenAPI = API 描述规范（类似 WSDL）
用 JSON/YAML 描述接口的路径、参数、响应
```

```yaml
# OpenAPI 3.0 示例
openapi: 3.0.0
info:
  title: 用户服务 API
  version: 1.0.0
paths:
  /api/users/{id}:
    get:
      summary: 获取用户
      parameters:
        - name: id
          in: path
          required: true
          schema:
            type: integer
      responses:
        '200':
          description: 成功
          content:
            application/json:
              schema:
                $ref: '#/components/schemas/User'
```

## Swagger 集成

Swagger 是 OpenAPI 的实现，通过注解自动生成 API 文档。

### 依赖（springdoc-openapi）

```xml
<dependency>
    <groupId>org.springdoc</groupId>
    <artifactId>springdoc-openapi-starter-webmvc-ui</artifactId>
    <version>2.3.0</version>
</dependency>
```

### 注解使用

```java
@RestController
@RequestMapping("/api/users")
@Tag(name = "用户管理", description = "用户相关接口")   // 类描述
public class UserController {

    @Operation(summary = "获取用户", description = "根据 ID 查询用户详情")  // 方法描述
    @GetMapping("/{id}")
    public User getUser(
            @Parameter(description = "用户 ID")   // 参数描述
            @PathVariable Long id) {
        return userService.get(id);
    }
}
```

### 实体注解

```java
@Schema(description = "用户实体")
public class User {
    @Schema(description = "用户 ID")
    private Long id;

    @Schema(description = "用户名", example = "张三")
    private String name;

    @Schema(description = "年龄", example = "20")
    private Integer age;
}
```

### 访问文档

```text
Swagger UI：http://localhost:8080/swagger-ui.html
OpenAPI JSON：http://localhost:8080/v3/api-docs
```

### 常用注解

| 注解 | 作用 | 位置 |
|------|------|------|
| @Tag | 类/接口描述 | Controller |
| @Operation | 方法描述 | 方法 |
| @Parameter | 参数描述 | 参数 |
| @Schema | 实体描述 | 实体类/字段 |
| @ApiResponse | 响应描述 | 方法 |

### 自定义配置

```java
@Configuration
public class OpenApiConfig {

    @Bean
    public OpenAPI openAPI() {
        return new OpenAPI()
            .info(new Info()
                .title("用户服务 API")
                .description("用户服务接口文档")
                .version("1.0.0"))
            .addSecurityItem(new SecurityRequirement().addList("bearerAuth"))
            .components(new Components()
                .addSecuritySchemes("bearerAuth",
                    new SecurityScheme()
                        .type(SecurityScheme.Type.HTTP)
                        .scheme("bearer")
                        .bearerFormat("JWT")));
    }
}
```

## Knife4j 增强

Knife4j 是 Swagger 的增强版（国内流行），界面更友好，功能更丰富。

### 依赖

```xml
<dependency>
    <groupId>com.github.xiaoymin</groupId>
    <artifactId>knife4j-openapi3-jakarta-spring-boot-starter</artifactId>
    <version>4.4.0</version>
</dependency>
```

### 访问

```text
Knife4j UI：http://localhost:8080/doc.html
```

### Knife4j 的特点

```text
1. 界面友好 —— 比原生 Swagger UI 更好看
2. 离线文档 —— 支持导出 Markdown/HTML
3. 全局参数 —— 配置全局认证头
4. 接口排序 —— 自定义接口顺序
```

### Knife4j vs Swagger

| 维度 | Swagger UI | Knife4j |
|------|-----------|---------|
| 界面 | 简洁 | 更友好 |
| 导出 | 有限 | 支持 Markdown/HTML |
| 中文 | 一般 | 完善 |
| 生态 | 国际标准 | 国内流行 |

## Spring REST Docs

Spring REST Docs 是测试驱动的文档，文档从测试生成，保证文档和代码一致。

### 依赖

```xml
<dependency>
    <groupId>org.springframework.restdocs</groupId>
    <artifactId>spring-restdocs-mockmvc</artifactId>
    <scope>test</scope>
</dependency>
```

### 测试生成文档

```java
@WebMvcTest(UserController.class)
class UserDocumentationTest {

    @Autowired
    private MockMvc mockMvc;

    @Test
    void documentGetUser() throws Exception {
        mockMvc.perform(get("/api/users/1"))
            .andExpect(status().isOk())
            .andDo(document("get-user",      // 文档片段名
                pathParameters(
                    parameterWithName("id").description("用户 ID")
                ),
                responseFields(
                    fieldWithPath("id").description("用户 ID"),
                    fieldWithPath("name").description("用户名")
                )));
    }
}
```

### Spring REST Docs 的特点

```text
1. 测试驱动 —— 文档和代码一致性保证（测试失败文档不生成）
2. 精确 —— 手动描述每个字段
3. 片段化 —— 生成 Asciidoc 片段，拼装成文档

vs Swagger：
Swagger —— 注解驱动，自动但可能不精确
REST Docs —— 测试驱动，精确但繁琐
```

## 应用场景实战

### 场景 1：完整 Swagger 配置

```java
@RestController
@RequestMapping("/api/users")
@Tag(name = "用户管理")
public class UserController {

    @Operation(summary = "创建用户")
    @ApiResponses({
        @ApiResponse(responseCode = "201", description = "创建成功"),
        @ApiResponse(responseCode = "400", description = "参数错误")
    })
    @PostMapping
    @ResponseStatus(HttpStatus.CREATED)
    public User create(@Valid @RequestBody UserDTO dto) {
        return userService.create(dto);
    }
}
```

### 场景 2：文档分组（多模块）

```java
@Bean
public GroupedOpenApi userApi() {
    return GroupedOpenApi.builder()
        .group("用户服务")
        .pathsToMatch("/api/users/**")
        .build();
}

@Bean
public GroupedOpenApi orderApi() {
    return GroupedOpenApi.builder()
        .group("订单服务")
        .pathsToMatch("/api/orders/**")
        .build();
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. **注解要完整**。@Tag、@Operation、@Parameter 描述清楚。

2. **生产环境关闭文档**。文档暴露接口信息，生产环境关闭或加权限。

3. **文档和代码同步**。接口变更同步更新注解。

4. **用 Knife4j 导出离线文档**。给前端/第三方交付离线文档。

5. **配置认证**。文档界面支持 token 认证，方便调试。

### 踩坑记录

**坑 1：生产环境暴露文档**

```yaml
# 生产环境没关闭文档，暴露接口信息
springdoc:
  api-docs:
    enabled: true   # 生产应该 false
```

生产环境关闭文档或加访问控制。

**坑 2：注解没写导致文档空**

```java
@GetMapping("/{id}")
public User get(@PathVariable Long id) { ... }
// 没加 @Operation/@Tag，文档只有路径没描述
```

Controller 和方法都要加注解描述。

**坑 3：Swagger 版本冲突**

```text
springfox（旧）和 springdoc（新）同时引入，冲突
Spring Boot 3 用 springdoc，springfox 已不维护
```

Spring Boot 3 + springdoc-openapi，不要用 springfox。

**坑 4：DTO 字段没注解**

```java
public class UserDTO {
    private String name;   // 没 @Schema，文档里字段无描述
}
```

实体和 DTO 的字段加 @Schema 描述。

**坑 5：文档和实际接口不一致**

```text
代码改了，注解没改，文档还是旧的，误导调用方
```

接口变更同步更新文档注解。

**坑 6：忽略响应示例**

```text
文档没有响应示例，调用方不知道返回结构
```

@Schema 加 example，或 @Operation 里描述响应结构。

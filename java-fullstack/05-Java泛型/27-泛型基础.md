## 概述

泛型（Generics）是 JDK 5 引入的编译期类型检查机制——本质是**参数化类型**：把类型当作参数传递，让同一个类/接口/方法适配多种数据类型，同时保证编译时类型安全。

Java 泛型的核心价值：

| 价值 | 说明 |
|------|------|
| **编译期类型检查** | 把 `ClassCastException` 从运行时提前到编译时 |
| **消除强制转型** | 取元素时不需要 `(String) list.get(0)` |
| **代码复用** | 一套代码适配多种类型（容器、算法） |
| **自文档化** | `List<User>` 比 `List` 清晰得多 |

Java 泛型的实现方式是**类型擦除**（Type Erasure）——泛型信息只在编译期存在，编译后全部擦除。这不是 bug，是有意为之的设计选择：保证与 JDK 1.4 及之前的字节码兼容。

## 为什么需要泛型

没有泛型之前，集合只能存 `Object`：

```java
// JDK 1.4 时代（无泛型）
List list = new ArrayList();
list.add("hello");
list.add(42);               // 可以混入 Integer
list.add(new Date());       // 什么都能装

// 取出来必须强转
String s = (String) list.get(0);  // 必须手动强转
// String s2 = (String) list.get(1); // 编译通过但运行时 ClassCastException！
```

有三个致命问题：
1. **类型不安全**：什么都能往里放，取出来才发现类型不对
2. **强制转型麻烦**：每次取元素都要写 `(Type)`，代码臃肿
3. **bug 延迟到运行时**：编译器帮不了你，上线才炸

有了泛型后：

```java
List<String> list = new ArrayList<>();
list.add("hello");
// list.add(42);            // 编译错误！int 不是 String
// list.add(new Date());    // 编译错误！

String s = list.get(0);     // 不需要强转，编译器知道类型
```

## 泛型类

泛型类在类名后声明类型参数——可以有一个或多个：

```java
// 单个类型参数
public class Box<T> {
    private T content;

    public void put(T content) {
        this.content = content;
    }

    public T get() {
        return content;
    }
}

// 使用
Box<String> stringBox = new Box<>();
stringBox.put("hello");
String s = stringBox.get();     // 不需要强转

Box<Integer> intBox = new Box<>();
intBox.put(42);
int value = intBox.get();       // 自动拆箱
```

多个类型参数：

```java
// 两个类型参数：键值对
public class Pair<K, V> {
    private K key;
    private V value;

    public Pair(K key, V value) {
        this.key = key;
        this.value = value;
    }

    public K getKey() { return key; }
    public V getValue() { return value; }
    public void setValue(V value) { this.value = value; }
}

// 使用
Pair<String, Integer> pair = new Pair<>("age", 25);
String key = pair.getKey();
Integer val = pair.getValue();
```

类型参数可以有边界（bound），限制可传入的类型：

```java
// T 必须是 Number 或其子类
public class NumericBox<T extends Number> {
    private T number;

    public NumericBox(T number) {
        this.number = number;
    }

    public double doubleValue() {
        return number.doubleValue();  // 安全：Number 有 doubleValue()
    }
}

// NumberBox<Integer> ok = new NumberBox<>(42);     // OK
// NumberBox<String> bad = new NumberBox<>("hi");  // 编译错误！String 不是 Number
```

多个边界用 `&` 连接（类放第一个）：

```java
// T 必须继承 Comparable 且实现 Serializable
public class SortedBox<T extends Comparable<T> & Serializable> {
    // ...
}
```

边界可以是一个类 + 多个接口，但 Java 不支持多继承，所以类最多一个。

## 泛型接口

接口的类型参数由实现类确定或继续传递：

```java
// 泛型接口
public interface Repository<T, ID> {
    T findById(ID id);
    void save(T entity);
    void delete(ID id);
}

// 实现时指定具体类型
public class UserRepository implements Repository<User, Long> {
    @Override
    public User findById(Long id) { ... }

    @Override
    public void save(User entity) { ... }

    @Override
    public void delete(Long id) { ... }
}

// 实现时继续保留泛型
public class GenericRepository<T, ID> implements Repository<T, ID> {
    @Override
    public T findById(ID id) { ... }

    @Override
    public void save(T entity) { ... }

    @Override
    public void delete(ID id) { ... }
}
```

Java 标准库中的泛型接口：

```java
// Comparable —— 给自己定义自然顺序
public class User implements Comparable<User> {
    private int age;

    @Override
    public int compareTo(User other) {
        return Integer.compare(this.age, other.age);
    }
}

// Iterable —— 支持增强 for 循环
public class MyList<T> implements Iterable<T> {
    @Override
    public Iterator<T> iterator() { ... }
}
```

## 泛型方法

泛型方法在返回值前声明自己的类型参数——即使所在类不是泛型类也可以：

```java
// 非泛型类中的泛型方法
public class ArrayUtils {

    // <T> 声明这是泛型方法，T 只在本方法内有效
    public static <T> T getMiddle(T[] array) {
        return array[array.length / 2];
    }

    // 多个类型参数
    public static <K, V> Map<K, V> singletonMap(K key, V value) {
        Map<K, V> map = new HashMap<>();
        map.put(key, value);
        return map;
    }
}

// 调用
String[] arr = {"a", "b", "c"};
String middle = ArrayUtils.<String>getMiddle(arr);  // 显式指定
String middle2 = ArrayUtils.getMiddle(arr);          // 类型推断（通常省略）

Map<String, Integer> map = ArrayUtils.singletonMap("age", 25);
```

有类型边界的泛型方法：

```java
// T 必须实现 Comparable，用于比较两个元素
public static <T extends Comparable<T>> T max(T a, T b) {
    return a.compareTo(b) > 0 ? a : b;
}

String maxStr = max("hello", "world");  // "world"
Integer maxInt = max(10, 20);          // 20
// max(new Object(), new Object());    // 编译错误！Object 没实现 Comparable
```

泛型方法和泛型类的类型参数相互独立：

```java
public class Container<E> {
    private E element;

    // 这是一个泛型方法，<T> 和类的 <E> 是两个不同的类型参数
    // 如果它们恰好同名，方法级的 T 会遮蔽类级的 E
    public <T> void process(T input) {
        System.out.println(input);
    }
}
```

## 泛型构造器

构造器也可以有自己的类型参数（极少使用，但存在）：

```java
public class Pair<K, V> {
    private K key;
    private V value;

    // 普通构造器（使用类的类型参数）
    public Pair(K key, V value) {
        this.key = key;
        this.value = value;
    }

    // 泛型构造器——有自己的类型参数
    public <U extends K> Pair(Pair<U, ? extends V> other) {
        this.key = other.getKey();       // U 可以安全地赋给 K
        this.value = other.getValue();
    }
}
```

构造器的类型参数由编译器推断，调用时不需要手动指定：

```java
Pair<Number, Number> p1 = new Pair<>(1, 2.0);
Pair<Number, Number> p2 = new Pair<>(p1);  // 泛型构造器，U 被推断为 Integer
```

## 类型参数命名约定

Java 社区对类型参数有一致的命名习惯：

| 字母 | 含义 | 典型场景 |
|------|------|----------|
| `E` | Element | 集合元素（`List<E>`） |
| `K` | Key | 键（`Map<K,V>`） |
| `V` | Value | 值（`Map<K,V>`） |
| `T` | Type | 通用类型（最常见） |
| `S`, `U`, `V` | 第 2、3、4 个类型参数 | 多参数场景 |
| `N` | Number | 数值类型 |
| `R` | Return | 返回值类型 |

遵守这个约定能显著提高代码可读性——看到 `<T>` 就知道是通用类型，看到 `<K, V>` 就知道是键值对。

## 原始类型与泛型实例

原始类型（Raw Type）是指不带类型参数的泛型类——为了向后兼容 JDK 1.4：

```java
// 泛型版本（正确）
List<String> list = new ArrayList<>();

// 原始类型（遗留代码中常见）
List rawList = new ArrayList();        // 编译器会警告：unchecked
rawList.add("hello");
rawList.add(42);                       // 不报错！类型安全性完全丧失

// 混合使用会破坏类型安全
List<String> safeList = new ArrayList<>();
List rawRef = safeList;                // 可以赋值给原始类型
rawRef.add(42);                        // 塞入了 Integer！
// String s = safeList.get(0);          // 运行时 ClassCastException
```

**规则**：永远不要使用原始类型。`List` 只存在于和 JDK 1.4 代码互操作时。

## 泛型与数组

Java 禁止创建泛型数组——因为类型擦除和数组的协变冲突：

```java
// 这些全部编译错误！
// List<String>[] lists = new List<String>[10];      // 错误！
// T[] array = new T[10];                             // 错误！
// Pair<String, Integer>[] pairs = new Pair<String, Integer>[10]; // 错误！
```

原因：泛型数组会破坏类型安全：

```java
// 假设允许创建泛型数组
// List<String>[] lists = new List<String>[1];   // 假设可以
// Object[] objects = lists;                      // 数组协变
// objects[0] = new ArrayList<Integer>();         // 放入 List<Integer>
// String s = lists[0].get(0);                    // ClassCastException！拿出来的其实是 Integer
```

如果需要泛型数组的场景，有两种替代方案：

```java
// 方案一：用 ArrayList（推荐）
List<List<String>> listOfLists = new ArrayList<>();

// 方案二：创建原始数组然后强转（加 @SuppressWarnings）
@SuppressWarnings("unchecked")
List<String>[] lists = (List<String>[]) new List[10];
```

## 应用场景实战

### 场景一：通用缓存工具

```java
public class SimpleCache<K, V> {
    private final Map<K, V> cache = new ConcurrentHashMap<>();

    public V get(K key, Supplier<V> loader) {
        return cache.computeIfAbsent(key, k -> loader.get());
    }

    public void put(K key, V value) {
        cache.put(key, value);
    }

    public V getIfPresent(K key) {
        return cache.get(key);
    }

    public void invalidate(K key) {
        cache.remove(key);
    }
}

// 用法
SimpleCache<Long, User> userCache = new SimpleCache<>();
User user = userCache.get(1L, () -> userRepository.findById(1L));
```

### 场景二：通用数据转换器

```java
public interface Converter<S, T> {
    T convert(S source);
}

// 多个转换器组合
public class ConverterChain<S, M, T> implements Converter<S, T> {
    private final Converter<S, M> first;
    private final Converter<M, T> second;

    public ConverterChain(Converter<S, M> first, Converter<M, T> second) {
        this.first = first;
        this.second = second;
    }

    @Override
    public T convert(S source) {
        return second.convert(first.convert(source));
    }
}

// 用法
Converter<User, UserDTO> toDTO = user -> new UserDTO(user.getName());
Converter<UserDTO, UserVO> toVO = dto -> new UserVO(dto.getName(), "extra");
Converter<User, UserVO> chain = new ConverterChain<>(toDTO, toVO);
```

### 场景三：Result 封装

```java
public class Result<T> {
    private final T data;
    private final String error;
    private final boolean success;

    private Result(T data, String error, boolean success) {
        this.data = data;
        this.error = error;
        this.success = success;
    }

    public static <T> Result<T> success(T data) {
        return new Result<>(data, null, true);
    }

    public static <T> Result<T> failure(String error) {
        return new Result<>(null, error, false);
    }

    public T getData() {
        if (!success) throw new IllegalStateException("操作失败: " + error);
        return data;
    }

    public boolean isSuccess() { return success; }
    public String getError() { return error; }
}
```

### 场景四：树节点

```java
public class TreeNode<T> {
    private T value;
    private List<TreeNode<T>> children = new ArrayList<>();

    public TreeNode(T value) {
        this.value = value;
    }

    public TreeNode<T> addChild(T childValue) {
        TreeNode<T> child = new TreeNode<>(childValue);
        children.add(child);
        return child;
    }

    public List<T> flatten() {
        List<T> result = new ArrayList<>();
        result.add(value);
        for (TreeNode<T> child : children) {
            result.addAll(child.flatten());
        }
        return result;
    }
}
```

## 最佳实践与踩坑记录

### 常见问题表

| 问题 | 原因 | 修复 |
|------|------|------|
| `ArrayList<int>` 编译错误 | 泛型类型参数不能是基本类型 | 用 `ArrayList<Integer>` |
| `instanceof` 检查泛型 | 类型擦除后泛型信息丢失 | 不能用 `list instanceof List<String>`，只能 `list instanceof List` |
| 静态方法不能使用类的类型参数 | 静态方法属于类，不属于实例 | 把静态方法声明为泛型方法 `<T> static ...` |
| 原始类型混用破坏安全 | 向 `List`（无泛型）放入不同类型 | 始终指定类型参数 |
| 不能 new 类型参数 | 类型擦除后 `new T()` 没有意义 | 传 `Supplier<T>` 或 `Class<T>` |

### 编写规范

```java
// 正确：类型参数尽量单字母 + 有意义
public class Cache<K, V> { }

// 错误：类型参数不清晰
public class Cache<A, B> { }

// 正确：有边界时用更明确的命名
public class NumericOps<T extends Number> { }

// 注意：泛型的类型推断
Map<String, List<String>> map = new HashMap<>();  // JDK 7+ 菱形语法，右边省略
```

## 总结

- 泛型把类型检查从运行时提前到编译期，消除强制转型和 ClassCastException
- 泛型类在类名后声明 `<T>`，泛型方法在返回值前声明 `<T>`
- 类型参数用有意义的单字母：`E`（元素）、`K`/`V`（键值）、`T`（通用）
- 类型边界 `<T extends Number>` 限制可传类型，并提供方法访问能力
- Java 泛型通过类型擦除实现——运行时没有泛型信息（高级篇会展开）
- 不要用原始类型，不要尝试创建泛型数组

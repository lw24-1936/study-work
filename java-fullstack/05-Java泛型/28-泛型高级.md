## 概述

泛型基础篇讲了怎么用泛型——本篇讲泛型**为什么是这样**。类型擦除、通配符、PECS 原则是 Java 泛型中面试最密集、也最令人困惑的部分。理解这些不光是为了面试，更是看懂框架源码的前提。

## 类型擦除

Java 泛型通过**类型擦除**实现——编译器在编译时去掉所有泛型信息，把类型参数替换为边界（或 Object），必要时插入强制转型。

### 擦除规则

```
规则一：无边界类型参数 → 擦除为 Object
规则二：有边界类型参数 → 擦除为边界类型
规则三：插入必要的类型转换
```

### 规则一：无边界 → Object

```java
// 源码
public class Box<T> {
    private T value;
    public T get() { return value; }
    public void put(T value) { this.value = value; }
}

// 擦除后（等价于）
public class Box {
    private Object value;
    public Object get() { return value; }
    public void put(Object value) { this.value = value; }
}
```

### 规则二：有边界 → 边界类型

```java
// 源码
public class NumericBox<T extends Number> {
    private T value;
    public T get() { return value; }
}

// 擦除后（等价于）
public class NumericBox {
    private Number value;   // T 被 Number 替换
    public Number get() { return value; }
}
```

### 规则三：插入强制转型

```java
// 源码
Box<String> box = new Box<>();
box.put("hello");
String s = box.get();

// 编译后等价于
Box box = new Box();
box.put("hello");
String s = (String) box.get();  // 编译器自动插入
```

这就是为什么 `get()` 时不需要手动转型——编译器偷偷帮你加了。

### 擦除的证据

```java
// 泛型信息在运行时完全消失
List<String> strList = new ArrayList<>();
List<Integer> intList = new ArrayList<>();

// 两个 List 的 Class 对象相同
System.out.println(strList.getClass() == intList.getClass());  // true
System.out.println(strList.getClass());   // class java.util.ArrayList

// 无法通过 instanceof 检查泛型
// if (list instanceof List<String>) { }  // 编译错误！
if (list instanceof List) { }             // 只能这样
```

### 类型擦除的后果

```java
// 1. 不能重载只有泛型参数不同的方法
// 编译错误——擦除后两个方法签名相同！
class Processor {
    // void process(List<String> list) { }   // 擦除后: process(List)
    // void process(List<Integer> list) { }  // 擦除后: process(List) ← 冲突！
}

// 2. 不能在静态上下文中使用类的类型参数
class Box<T> {
    // static T defaultItem;    // 编译错误！T 依赖实例
    // static T create() { }    // 编译错误！
    
    static <U> U create(U item) { return item; }  // OK——泛型方法可以
}

// 3. 不能 new 类型参数
class Factory<T> {
    // T create() { return new T(); }  // 编译错误！擦除后是 new Object()？
    
    // 解决方案：传 Class 或 Supplier
    T create(Class<T> clazz) throws Exception {
        return clazz.getDeclaredConstructor().newInstance();
    }
}
```

## 泛型继承

泛型类可以继承泛型类——子类可以保留、指定或扩展父类的类型参数：

```java
// 情况一：子类也泛型，传递类型参数
class BaseDao<T, ID> {
    public T findById(ID id) { return null; }
}

class UserDao<T> extends BaseDao<T, Long> { }
// UserDao<String> → BaseDao<String, Long>

// 情况二：子类指定具体类型
class UserDao extends BaseDao<User, Long> { }
// UserDao 不再是泛型类，明确知道操作的是 User

// 情况三：子类增加新的类型参数
class AuditableDao<T, ID, U> extends BaseDao<T, ID> {
    private U auditor;
}
```

重要：不同泛型参数的泛型类**没有继承关系**：

```java
List<String> strList = new ArrayList<>();
// List<Object> objList = strList;   // 编译错误！List<String> 不是 List<Object> 的子类型

// 这是合理的：
// 如果允许，就可以往 List<Object> 中放入 Integer，然后 strList.get(0) 拿到 Integer
```

但 **原始类型的继承关系保留**：

```java
// ArrayList<String> 是 List<String> 的子类型
List<String> list = new ArrayList<>();  // OK

// ArrayList<String> 是 ArrayList 的子类型
ArrayList<String> al = new ArrayList<>();
ArrayList raw = al;  // OK（虽然不安全）
```

## 通配符 ?

`?` 代表"未知类型"——当你不关心具体类型，或者需要灵活接受多种泛型参数时使用：

```java
// 只能接受 List<?> 的方法
public static void printList(List<?> list) {
    for (Object item : list) {
        System.out.println(item);  // 作为 Object 读取
    }
    // list.add("hello");          // 编译错误！不知道 ? 是什么，不能 add
    // list.add(null);             // 只有 null 可以（null 是所有类型的子类型）
}

List<String> strList = List.of("a", "b");
List<Integer> intList = List.of(1, 2, 3);
printList(strList);   // OK
printList(intList);   // OK
```

`?` 和 `Object` 的区别：

```java
// List<Object> 只能接受 List<Object>
public static void onlyObject(List<Object> list) { }

// List<?> 可以接受任何类型的 List
public static void anyType(List<?> list) { }

List<Object> objList = new ArrayList<>();
List<String> strList = new ArrayList<>();

onlyObject(objList);     // OK
// onlyObject(strList);  // 编译错误！List<String> 不是 List<Object>
anyType(objList);        // OK
anyType(strList);        // OK
```

## 上界通配符 extends

`? extends T` 表示"T 或 T 的任意子类"——可以安全地**读取**，不能写入（除了 null）：

```java
// 接受 Number 及其子类的 List
public static double sumNumbers(List<? extends Number> numbers) {
    double sum = 0;
    for (Number n : numbers) {  // 安全：都是 Number
        sum += n.doubleValue();
    }
    // numbers.add(42);    // 编译错误！可能是 List<Double>，不能放 Integer
    // numbers.add(new Integer(10));  // 编译错误！同理
    return sum;
}

List<Integer> ints = List.of(1, 2, 3);
List<Double> doubles = List.of(1.5, 2.5, 3.5);
System.out.println(sumNumbers(ints));     // 6.0
System.out.println(sumNumbers(doubles));  // 7.5
```

记忆口诀：**`? extends T` = 生产者，只能读不能写**。你拿到的是 T 或其子类，最小公约数是 T，所以按 T 读是安全的。但写的时候你不知道实际是 Integer 还是 Double，写了就破坏类型安全。

## 下界通配符 super

`? super T` 表示"T 或 T 的任意父类"——可以安全地**写入** T，但读取只能到 Object：

```java
// 可以向其中放入 Integer 的集合
public static void addNumbers(List<? super Integer> list) {
    list.add(1);
    list.add(2);
    list.add(3);
    // Integer value = list.get(0);   // 编译错误！get 返回的是 Object
    Object obj = list.get(0);          // 只能取到 Object
}

List<Number> numbers = new ArrayList<>();
List<Integer> ints = new ArrayList<>();
List<Object> objects = new ArrayList<>();

addNumbers(numbers);   // OK — Integer 是 Number 的子类
addNumbers(ints);      // OK — Integer 是 Integer
addNumbers(objects);   // OK — Integer 是 Object 的子类
```

记忆口诀：**`? super T` = 消费者，只能写不能读（有用信息）**。放入 T 是安全的，因为不管你实际是 Number 还是 Object，都能接住 Integer。但读的时候你不知道具体是什么类型，只能退回到 Object。

### extends vs super 速查

```java
// extends —— 读取是安全的
List<? extends Fruit> fruits = new ArrayList<Apple>();
Fruit f = fruits.get(0);         // OK —— 读出来至少是 Fruit
// fruits.add(new Apple());      // 错误 —— 可能是 List<Orange>

// super —— 写入是安全的
List<? super Apple> apples = new ArrayList<Fruit>();
apples.add(new Apple());         // OK —— 放 Apple 一定安全
apples.add(new GreenApple());    // OK —— GreenApple 也是 Apple
// Apple a = apples.get(0);      // 错误 —— 读出来最多是 Object
```

## PECS 原则

**PECS = Producer Extends, Consumer Super**

这是《Effective Java》中 Joshua Bloch 提出的通配符使用原则，是泛型设计最精华的法则：

```
如果你需要从结构体中**读取**数据（生产者）→ 用 ? extends T
如果你需要向结构体中**写入**数据（消费者）→ 用 ? super T
如果既要读又要写 → 不要用通配符，用具体类型 T
```

### 经典案例：Collections.copy

```java
// JDK 源码
public static <T> void copy(List<? super T> dest, List<? extends T> src) {
    // dest 是消费者：要往里写 → ? super T
    // src  是生产者：要往外读 → ? extends T
    for (int i = 0; i < src.size(); i++) {
        dest.set(i, src.get(i));
    }
}

// 用法
List<Number> dest = new ArrayList<>(List.of(0, 0, 0));
List<Integer> src = List.of(1, 2, 3);
Collections.copy(dest, src);   // 从 Integer 读到 Number —— 完美
```

### PECS 实战

```java
// 把 src 的数据迁移到 dest
public static <T> void transfer(List<? extends T> src, List<? super T> dest) {
    for (T item : src) {         // src: 生产者 (extends)
        dest.add(item);          // dest: 消费者 (super)
    }
}

// 求最大值
public static <T extends Comparable<? super T>> T max(List<? extends T> list) {
    // T extends Comparable<? super T>：
    // 即使是父类定义了 compareTo，子类也可以用
    T max = list.get(0);
    for (T item : list) {
        if (item.compareTo(max) > 0) {  // 调用 compareTo
            max = item;
        }
    }
    return max;
}
```

`<T extends Comparable<? super T>>` 是 Java 标准库中最经典的通配符用法。为什么是 `? super T` 而不是直接 `Comparable<T>`？

```java
// 场景：Animal 实现了 Comparable<Animal>，Dog 继承了 Animal
class Animal implements Comparable<Animal> {
    public int compareTo(Animal o) { ... }
}
class Dog extends Animal { }

// 如果签名是 <T extends Comparable<T>>
// Dog 就没法用——Dog 只实现了 Comparable<Animal>，不是 Comparable<Dog>

// <T extends Comparable<? super T>> 解决了这个问题：
// Dog 的 T=Dog，Comparable<? super Dog> 可以匹配 Comparable<Animal>
List<Dog> dogs = ...;
Dog maxDog = max(dogs);   // OK！
```

## 类型推断

JDK 7 引入菱形语法（diamond operator），JDK 8 极大改进了类型推断：

```java
// JDK 5-6：必须两边都写
Map<String, List<String>> map = new HashMap<String, List<String>>();

// JDK 7+：菱形语法（diamond operator）
Map<String, List<String>> map = new HashMap<>();

// JDK 8+：Lambda 和 Stream 中更强大的推断
List<String> result = list.stream()
    .filter(s -> s.length() > 3)    // s 推断为 String
    .collect(Collectors.toList());  // 推断返回 List<String>
```

JDK 8 改进的类型推断（improved type inference）让链式调用更流畅：

```java
// JDK 7 以前需要显式指定
Collections.<String>emptyList();

// JDK 8 可以推断
List<String> list = Collections.emptyList();  // 从上下文推断出 String
```

## 泛型与反射

运行时泛型信息被擦除，但有些"残留"通过反射仍可获取：

```java
// 1. 获取泛型超类
// 比如：class StringList extends ArrayList<String> { }
ParameterizedType superType = 
    (ParameterizedType) StringList.class.getGenericSuperclass();
Type[] typeArgs = superType.getActualTypeArguments();
System.out.println(typeArgs[0]);   // class java.lang.String

// 2. 获取泛型字段
class User {
    List<String> tags;
}
Field field = User.class.getDeclaredField("tags");
ParameterizedType fieldType = (ParameterizedType) field.getGenericType();
System.out.println(fieldType.getActualTypeArguments()[0]);  // String

// 3. 获取泛型方法参数
public <T> void process(List<T> items) { }
Method method = ...;
Type[] paramTypes = method.getGenericParameterTypes();
```

关键：**只有声明时明确写死的类型参数能通过反射获取**。局部变量的泛型（`new ArrayList<String>()`）在字节码中不保留 String 信息，反射得不到。

### TypeToken 模式

由于运行时泛型擦除，Gson 等框架用"匿名子类保留泛型信息"的 trick：

```java
// Gson 的 TypeToken
Type type = new TypeToken<List<String>>() {}.getType();
// 通过创建匿名子类，父类的泛型参数信息被保留在字节码中
// TypeToken 反射读取 getGenericSuperclass() 获取 List<String>
```

## 桥方法

桥方法（Bridge Method）是编译器为了保持泛型多态而自动生成的合成方法：

```java
// 源码
class Node<T> {
    private T data;
    public void setData(T data) { this.data = data; }
}

class IntegerNode extends Node<Integer> {
    @Override
    public void setData(Integer data) { super.setData(data); }
}
```

擦除后，`Node` 的 `setData` 变成 `setData(Object)`，`IntegerNode` 的 `setData` 是 `setData(Integer)`——这两个方法签名不同，多态被破坏了！编译器自动生成桥方法：

```java
// 编译器生成（概念等价）
class IntegerNode extends Node {
    // 用户写的
    public void setData(Integer data) { ... }
    
    // 编译器自动生成——桥接 Object 版本到 Integer 版本
    public void setData(Object data) {        // 桥方法！
        this.setData((Integer) data);
    }
}
```

桥方法的后果：通过反射看 `IntegerNode` 会有两个 `setData` 方法。`getMethod("setData", Integer.class)` 返回用户写的，`getMethod("setData", Object.class)` 返回桥方法。`isBridge()` 可以区分。

## 应用场景实战

### 场景一：通用分组器

```java
public class GroupUtils {
    // 按分组函数和聚合函数处理
    public static <T, K, V> Map<K, V> groupAndAggregate(
            List<? extends T> items,
            Function<? super T, ? extends K> classifier,
            Collector<? super T, ?, V> collector) {

        return items.stream().collect(
            Collectors.groupingBy(classifier, collector)
        );
    }

    // 用法
    List<Order> orders = ...;
    // 按用户分组的订单总金额
    Map<Long, Double> userTotals = GroupUtils.groupAndAggregate(
        orders,
        Order::getUserId,
        Collectors.summingDouble(Order::getAmount)
    );
}
```

### 场景二：方法链的泛型工具

```java
public class ChainBuilder<T> {
    private final List<Function<T, T>> steps = new ArrayList<>();

    public ChainBuilder<T> then(Function<T, T> step) {
        steps.add(step);
        return this;
    }

    public Function<T, T> build() {
        return steps.stream()
            .reduce(Function.identity(), Function::andThen);
    }
}

// 用法
ChainBuilder<String> builder = new ChainBuilder<>();
Function<String, String> pipeline = builder
    .then(String::trim)
    .then(String::toLowerCase)
    .then(s -> s.replace(" ", "_"))
    .build();

System.out.println(pipeline.apply(" Hello World "));  // "hello_world"
```

### 场景三：类型安全的异构容器

```java
// 用 Class 做 key，每个 key 对应不同类型的 value
public class TypeSafeMap {
    private final Map<Class<?>, Object> map = new HashMap<>();

    public <T> void put(Class<T> type, T value) {
        map.put(type, type.cast(value));  // 运行时类型检查
    }

    @SuppressWarnings("unchecked")
    public <T> T get(Class<T> type) {
        return type.cast(map.get(type));  // 安全的强转
    }
}

// 用法
TypeSafeMap ctx = new TypeSafeMap();
ctx.put(String.class, "hello");
ctx.put(Integer.class, 42);
String s = ctx.get(String.class);    // "hello" 不需要强转
Integer i = ctx.get(Integer.class);  // 42
// ctx.put(Integer.class, "wrong");  // ClassCastException！
```

### 场景四：可比较的泛型边界

```java
public class SortedList<T extends Comparable<? super T>> {
    private final List<T> list = new ArrayList<>();

    public void add(T item) {
        int idx = Collections.binarySearch(list, item);
        if (idx < 0) idx = -(idx + 1);
        list.add(idx, item);  // 保持有序
    }

    public T get(int index) { return list.get(index); }
    public int size() { return list.size(); }
}
```

## 最佳实践与踩坑记录

### 常见问题表

| 问题 | 原因 | 修复 |
|------|------|------|
| `? extends T` 不能 add | 无法确定具体子类型 | 用 `? super T` 或精确类型 |
| `? super T` 取出来是 Object | 无法确定具体父类型 | 用 `? extends T` 或精确类型 |
| `List<Child>` 不能传给 `List<Parent>` | 泛型不协变 | 用 `List<? extends Parent>` |
| 桥方法导致的反射困惑 | 编译器自动生成桥方法 | 用 `Method.isBridge()` 过滤 |
| 不同泛型参数的类不能 instanceof | 运行时泛型信息擦除 | 检查原始类型或遍历字段 |

### 关键经验

```
1. 能不用通配符就不用 —— 具体类型 <T> 最简单
2. 只读 = ? extends T（生产者）
3. 只写 = ? super T（消费者）
4. 既读又写 = 不要用通配符
5. 类级别的泛型参数尽量有边界 —— <T extends Serializable>
6. 返回值不要用通配符 —— 让调用者去用具体类型
```

### PECS 速查卡

```
场景：你有一个 List<?> 参数

你想从中读取元素？
  └── 是 → ? extends T
        └── for (T item : list) { ... }  ← OK
        └── list.add(...)                ← 编译错误！

你想向其中添加元素？
  └── 是 → ? super T
        └── list.add(new T())    ← OK
        └── T item = list.get(0) ← 编译错误！只能赋值给 Object
```

## 总结

- 类型擦除：编译后所有 `<T>` 消失，替换为 Object 或边界类型，编译器自动插入强制转型
- 泛型没有协变：`List<String>` 不是 `List<Object>` 的子类型
- `? extends T`：生产者，只能读不能写——安全地取出为 T 类型
- `? super T`：消费者，只能写不能读（有用信息）——安全地放入 T 类型
- PECS 原则：Producer Extends, Consumer Super——Joshua Bloch 的泛型圣经
- `Comparable<? super T>` 是标准库中最巧妙的泛型设计——让子类复用父类的比较逻辑
- 泛型信息在运行时大部分擦除，但声明在类/方法签名上的可以通过反射获取
- 桥方法是编译器的自动补丁——保持泛型擦除后的多态正确性

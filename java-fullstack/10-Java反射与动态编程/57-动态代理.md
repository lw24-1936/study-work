## 概述

动态代理是在**运行时**生成代理类的技术——不需要手动写代理类，通过框架自动生成。它是 Spring AOP、MyBatis Mapper、RPC 框架、事务管理、权限控制等技术的基础。

Java 生态有三种主流动态代理方案：

| 方案 | 原理 | 代理对象要求 | 性能 | 依赖 |
|------|------|-------------|------|------|
| JDK Proxy | 反射 + 接口实现 | 必须有接口 | 中 | JDK 自带 |
| CGLIB | 字节码生成（子类继承） | 不能是 final 类 | 高 | 第三方 |
| Byte Buddy | 字节码生成（全灵活） | 无限制 | 高 | 第三方 |

## 静态代理 vs 动态代理

```java
// 静态代理 —— 每个接口写一个代理类（繁琐）
class UserServiceProxy implements UserService {
    private UserService target;
    public void save(User user) {
        logBefore();
        target.save(user);
        logAfter();
    }
}

// 动态代理 —— 一个 Handler 代理所有接口（灵活）
class LoggingHandler implements InvocationHandler {
    private Object target;
    public Object invoke(Object proxy, Method method, Object[] args) {
        logBefore();
        Object result = method.invoke(target, args);
        logAfter();
        return result;
    }
}
```

## JDK 动态代理

JDK 动态代理通过 `Proxy.newProxyInstance()` 在运行时生成代理类。核心限制：**被代理对象必须实现接口**：

```java
import java.lang.reflect.*;

// 1. 接口
interface UserService {
    void save(User user);
    User findById(Long id);
}

// 2. 实现类
class UserServiceImpl implements UserService {
    @Override public void save(User user) { System.out.println("保存: " + user); }
    @Override public User findById(Long id) { return new User(id, "张三"); }
}

// 3. InvocationHandler
class LoggingHandler implements InvocationHandler {
    private final Object target;  // 被代理的真实对象

    public LoggingHandler(Object target) {
        this.target = target;
    }

    @Override
    public Object invoke(Object proxy, Method method, Object[] args) throws Throwable {
        System.out.println("[LOG] 调用方法: " + method.getName());
        long start = System.currentTimeMillis();
        
        Object result = method.invoke(target, args);  // 调用真实对象的方法
        
        long elapsed = System.currentTimeMillis() - start;
        System.out.println("[LOG] 耗时: " + elapsed + "ms");
        return result;
    }
}

// 4. 创建代理
UserService target = new UserServiceImpl();
UserService proxy = (UserService) Proxy.newProxyInstance(
    target.getClass().getClassLoader(),   // 类加载器
    target.getClass().getInterfaces(),    // 实现的接口
    new LoggingHandler(target)            // InvocationHandler
);

// 5. 使用代理——和普通对象一样
proxy.save(new User("张三", 25));  // 自动触发 LoggingHandler.invoke
// 输出:
// [LOG] 调用方法: save
// 保存: User{name='张三', age=25}
// [LOG] 耗时: 0ms
```

## InvocationHandler 详解

```java
public interface InvocationHandler {
    /**
     * @param proxy  代理对象自身（不是被代理的目标对象）
     * @param method 被调用的方法（接口中的方法）
     * @param args   方法参数
     */
    Object invoke(Object proxy, Method method, Object[] args) throws Throwable;
}
```

### proxy 参数的陷阱

```java
class MyHandler implements InvocationHandler {
    @Override
    public Object invoke(Object proxy, Method method, Object[] args) throws Throwable {
        // 错误：调用 proxy.toString() → 再次进入 invoke → 无限递归！
        // System.out.println(proxy);
        
        // 正确：用 method.invoke(target, args) 调用真实对象
        // proxy 参数只用于区分，不用于调用
        
        return method.invoke(target, args);
    }
}
```

### 完整示例：缓存代理

```java
class CacheHandler implements InvocationHandler {
    private final Object target;
    private final Map<String, Object> cache = new ConcurrentHashMap<>();

    public CacheHandler(Object target) { this.target = target; }

    @Override
    public Object invoke(Object proxy, Method method, Object[] args) throws Throwable {
        // 只为 get 开头的方法做缓存
        if (method.getName().startsWith("get")) {
            String key = method.getName() + Arrays.toString(args);
            return cache.computeIfAbsent(key, k -> {
                try { return method.invoke(target, args); }
                catch (Exception e) { throw new RuntimeException(e); }
            });
        }
        return method.invoke(target, args);
    }
}
```

## CGLIB 代理

CGLIB（Code Generation Library）通过**生成目标类的子类**来代理——不需要接口，但不能代理 final 类/方法：

```java
// Maven 依赖（通常通过 Spring 间接引入）
// <dependency>
//     <groupId>cglib</groupId>
//     <artifactId>cglib</artifactId>
//     <version>3.3.0</version>
// </dependency>
```

```java
import net.sf.cglib.proxy.Enhancer;
import net.sf.cglib.proxy.MethodInterceptor;
import net.sf.cglib.proxy.MethodProxy;

// 不需要接口的目标类
class UserService {
    public void save(User user) {
        System.out.println("保存: " + user);
    }
}

// MethodInterceptor
class LoggingInterceptor implements MethodInterceptor {
    @Override
    public Object intercept(Object obj, Method method, Object[] args, MethodProxy proxy) 
            throws Throwable {
        System.out.println("[CGLIB] 调用: " + method.getName());
        
        // 方式一：调用父类方法（绕过反射，更快）
        Object result = proxy.invokeSuper(obj, args);
        
        // 方式二：调用目标对象（等同于反射）
        // Object result = method.invoke(target, args);
        
        return result;
    }
}

// 创建代理
Enhancer enhancer = new Enhancer();
enhancer.setSuperclass(UserService.class);         // 设置父类
enhancer.setCallback(new LoggingInterceptor());    // 设置拦截器

UserService proxy = (UserService) enhancer.create();
proxy.save(new User("张三", 25));
```

### CGLIB 的局限性

```java
// 不能代理 final 类
// final class FinalService { }  // Enhancer 无法创建子类

// 不能代理 final 方法
class BaseService {
    // public final void doWork() { }  // CGLIB 无法重写
}

// 构造方法会被调用两次（创建代理时一次 + new 时一次）
// 如果构造方法有副作用（如建立连接），需注意
```

## Byte Buddy

Byte Buddy 是现代的字节码操作库——比 CGLIB 更灵活，支持生成任意类、修改已有类：

```java
// Maven 依赖
// <dependency>
//     <groupId>net.bytebuddy</groupId>
//     <artifactId>byte-buddy</artifactId>
//     <version>1.14.0</version>
// </dependency>
```

```java
import net.bytebuddy.ByteBuddy;
import net.bytebuddy.implementation.InvocationHandlerAdapter;
import net.bytebuddy.matcher.ElementMatchers;

// 创建代理（类似 JDK Proxy，但不需要接口）
UserService proxy = new ByteBuddy()
    .subclass(UserService.class)
    .method(ElementMatchers.any())               // 拦截所有方法
    .intercept(InvocationHandlerAdapter.of(
        (obj, method, args) -> {
            System.out.println("[ByteBuddy] " + method.getName());
            return method.invoke(target, args);
        }))
    .make()
    .load(UserService.class.getClassLoader())
    .getLoaded()
    .getDeclaredConstructor()
    .newInstance();
```

Byte Buddy 的优势：
- 不需要接口（和 CGLIB 一样）
- 更现代的 API，更好的错误提示
- 可以直接生成字节码，不只是代理（Mockito、Hibernate 都用它）
- Spring Boot 2.x 后默认使用 Byte Buddy 替代 CGLIB

## JDK Proxy vs CGLIB vs Byte Buddy

| 维度 | JDK Proxy | CGLIB | Byte Buddy |
|------|-----------|-------|------------|
| 原理 | `Proxy.newProxyInstance` | 生成子类字节码 | 运行时 ASM 操作 |
| 是否需要接口 | 是 | 否 | 否 |
| final 类 | 不支持（无法实现接口） | 不支持 | 不支持 |
| final 方法 | N/A（接口方法不能 final） | 不支持 | 不支持 |
| 性能 | invoke → 反射调用 | invokeSuper → 直接调用（快） | 直接调用（快） |
| 依赖 | JDK 自带 | 第三方 jar | 第三方 jar |
| Spring 默认 | AOP 切面默认用这个(有接口时) | 无接口时用 | Spring Boot 2.x+ 替代 CGLIB |

## 动态代理底层原理

### JDK Proxy 原理

```java
// Proxy.newProxyInstance 生成的代理类（概念简化版）
// 实际保存为 $Proxy0.class

public final class $Proxy0 extends Proxy implements UserService {
    private static Method m0, m1, m2, m3;  // 缓存 Method 对象

    static {
        m1 = Class.forName("UserService").getMethod("save", User.class);
        m2 = Class.forName("UserService").getMethod("findById", Long.class);
    }

    public $Proxy0(InvocationHandler h) {
        super(h);  // h 保存在 Proxy.h 字段中
    }

    @Override
    public void save(User user) {
        h.invoke(this, m1, new Object[]{user});  // 全部委托给 h
    }

    @Override
    public User findById(Long id) {
        return (User) h.invoke(this, m2, new Object[]{id});
    }
}

// 生成类的位置：系统属性 sun.misc.ProxyGenerator.saveGeneratedFiles=true 可保存到磁盘
```

### CGLIB 原理

```
CGLIB 底层使用 ASM 操作字节码：
1. 读取目标类的字节码
2. 生成目标类的子类字节码（重写非 final 方法）
3. 在重写的方法中插入 MethodInterceptor 回调
4. 通过 ClassLoader 加载生成的子类
5. 反射创建子类实例
```

### Spring AOP 的选择逻辑

```
Spring 创建代理时的决策：
1. 目标类实现了接口？
   ├── 是 → 默认使用 JDK 动态代理
   └── 否 → 使用 CGLIB/Byte Buddy
2. proxy-target-class=true？
   └── 强制使用 CGLIB/Byte Buddy（即使有接口）
3. Spring Boot 2.x+ 默认 proxy-target-class=true（即默认 CGLIB）
```

## AOP 与动态代理

动态代理是 AOP 的底层实现机制——Spring AOP 通过代理在目标方法前后织入切面逻辑：

```java
// 简易 AOP 框架（基于 JDK Proxy）
public class SimpleAop {
    // 创建代理
    @SuppressWarnings("unchecked")
    public static <T> T createProxy(T target, List<Advice> advices) {
        return (T) Proxy.newProxyInstance(
            target.getClass().getClassLoader(),
            target.getClass().getInterfaces(),
            (proxy, method, args) -> {
                // 前置通知
                advices.forEach(a -> a.before(method, args));
                try {
                    Object result = method.invoke(target, args);
                    // 返回通知
                    advices.forEach(a -> a.afterReturning(method, result));
                    return result;
                } catch (Exception e) {
                    // 异常通知
                    advices.forEach(a -> a.afterThrowing(method, e));
                    throw e;
                } finally {
                    // 后置通知
                    advices.forEach(a -> a.after(method));
                }
            });
    }
}

interface Advice {
    default void before(Method method, Object[] args) {}
    default void afterReturning(Method method, Object result) {}
    default void afterThrowing(Method method, Exception e) {}
    default void after(Method method) {}
}

// 用法
UserService proxy = SimpleAop.createProxy(new UserServiceImpl(), List.of(
    new Advice() {
        @Override public void before(Method m, Object[] args) {
            System.out.println("开始事务");
        }
        @Override public void afterReturning(Method m, Object result) {
            System.out.println("提交事务");
        }
        @Override public void afterThrowing(Method m, Exception e) {
            System.out.println("回滚事务");
        }
    }
));
```

## 应用场景实战

### 场景一：RPC 客户端动态代理

```java
// 一个接口 → 远程调用 → RPC 框架（Dubbo/Feign 的核心）
public class RpcProxy {
    @SuppressWarnings("unchecked")
    public static <T> T create(Class<T> interfaceClass) {
        return (T) Proxy.newProxyInstance(
            interfaceClass.getClassLoader(),
            new Class[]{interfaceClass},
            (proxy, method, args) -> {
                // 构造 RPC 请求
                RpcRequest request = new RpcRequest(
                    interfaceClass.getName(),
                    method.getName(),
                    method.getParameterTypes(),
                    args
                );
                // 发送到远程服务器
                RpcResponse response = rpcClient.send(request);
                return response.getData();
            });
    }
}

// 用法
UserService userService = RpcProxy.create(UserService.class);
User user = userService.findById(1L);  // 看似本地调用，实际是 RPC
```

### 场景二：MyBatis Mapper 代理

```java
// MyBatis 中你定义的接口没有实现类——
// 框架通过动态代理在运行时生成 SQL 并执行

public class MapperProxyFactory {
    @SuppressWarnings("unchecked")
    public static <T> T createMapper(Class<T> mapperInterface, SqlSession sqlSession) {
        return (T) Proxy.newProxyInstance(
            mapperInterface.getClassLoader(),
            new Class[]{mapperInterface},
            (proxy, method, args) -> {
                // 从 XML 注解中读取 SQL
                String sql = resolveSql(mapperInterface, method);
                // 通过 SqlSession 执行
                return sqlSession.selectOne(sql, args);
            });
    }
}
```

### 场景三：统一异常处理代理

```java
public class ExceptionProxy {
    @SuppressWarnings("unchecked")
    public static <T> T wrap(T target, Class<? extends RuntimeException> wrapper) {
        return (T) Proxy.newProxyInstance(
            target.getClass().getClassLoader(),
            target.getClass().getInterfaces(),
            (proxy, method, args) -> {
                try {
                    return method.invoke(target, args);
                } catch (InvocationTargetException e) {
                    Throwable cause = e.getCause();
                    // 包装 Checked Exception → Unchecked
                    if (cause instanceof IOException) {
                        throw new UncheckedIOException((IOException) cause);
                    }
                    throw new RuntimeException(cause);
                }
            });
    }
}
```

## 最佳实践与踩坑记录

### 常见问题表

| 问题 | 原因 | 修复 |
|------|------|------|
| JDK Proxy 报 `ClassCastException` | 代理对象不能强转为实现类（只能强转为接口） | 用接口引用接收代理对象 |
| CGLIB `java.lang.VerifyError` | CGLIB 版本和 JDK 不兼容 | 升级 CGLIB 到最新版；或改用 Byte Buddy |
| `final` 类/方法代理失败 | CGLIB 通过继承实现，final 不可继承 | 换 JDK Proxy（需接口）或重构去掉 final |
| InvocationHandler 中调用 proxy.toString() 死循环 | proxy 对象会再次进入 invoke | 绝对不要在 invoke 中操作 proxy 参数 |
| 代理对象的方法上注解丢失 | JDK Proxy 生成的代理类不继承原类注解 | 从原始类获取注解后再应用 |

### 选型指南

```
有接口 → JDK Proxy（JDK 自带，零依赖）
无接口、类可控 → CGLIB 或 Byte Buddy
需要修改已有类的字节码 → Byte Buddy / ASM
Spring 项目中 → 框架自动选择，无需手动

Spring AOP 默认规则：
  Spring Boot 2.x+ → 统一用 CGLIB（proxy-target-class=true）
  有接口 + proxy-target-class=false → JDK Proxy
```

## 总结

- JDK Proxy：基于接口 + InvocationHandler，JDK 自带，生成的代理类是 `Proxy` 的子类
- CGLIB：基于继承（生成目标类的子类），不能代理 final 类/方法，性能优于 JDK Proxy
- Byte Buddy：现代字节码操作库，API 友好，Spring Boot 2.x+ 的默认代理方案
- 动态代理是 Spring AOP 的底层基石——切面逻辑通过代理织入
- MyBatis Mapper、RPC 客户端、事务管理——背后都是动态代理
- InvocationHandler.invoke() 的 proxy 参数绝对不能调用，否则无限递归

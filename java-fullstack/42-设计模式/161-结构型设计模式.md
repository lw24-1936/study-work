## 概述

结构型模式关注类和对象的组合，如何用更灵活的方式组织类和对象。

```text
7 种结构型模式：
1. 适配器 —— 接口转换
2. 桥接 —— 抽象和实现分离
3. 组合 —— 树形结构
4. 装饰器 —— 动态增强
5. 外观 —— 简化接口
6. 享元 —— 共享对象
7. 代理 —— 控制访问
```

## 适配器模式 Adapter

适配器模式把一个接口转换成另一个接口，让不兼容的接口协同工作。

### 意图

```text
让接口不兼容的类能一起工作（类似电源适配器）
```

### 结构

```java
// 目标接口（客户端期望的）
interface Target {
    void request();
}

// 被适配者（已有的，接口不兼容）
class Adaptee {
    public void specificRequest() {
        System.out.println("特定请求");
    }
}

// 适配器（转换接口）
class Adapter implements Target {
    private Adaptee adaptee;

    public Adapter(Adaptee adaptee) {
        this.adaptee = adaptee;
    }

    @Override
    public void request() {
        adaptee.specificRequest();   // 转换成目标接口
    }
}
```

### 场景：Spring 的 HandlerAdapter

```text
Spring MVC 的 HandlerAdapter 就是适配器：
不同处理器（Controller、HttpRequestHandler）都适配成统一的 handle 接口
```

## 桥接模式 Bridge

桥接模式把抽象和实现分离，两者可以独立变化。

### 意图

```text
解决多维度的类爆炸问题，抽象和实现独立扩展
```

### 结构

```java
// 实现接口
interface Color {
    void apply();
}
class Red implements Color { public void apply() { System.out.print("红色"); } }
class Blue implements Color { public void apply() { System.out.print("蓝色"); } }

// 抽象
abstract class Shape {
    protected Color color;   // 组合（桥接）

    public Shape(Color color) { this.color = color; }
    abstract void draw();
}

// 扩展抽象
class Circle extends Shape {
    public Circle(Color color) { super(color); }
    public void draw() { color.apply(); System.out.println("圆形"); }
}
class Square extends Shape {
    public Square(Color color) { super(color); }
    public void draw() { color.apply(); System.out.println("方形"); }
}
```

```text
桥接模式的价值：
Shape 和 Color 独立扩展，不产生类爆炸
（2 种形状 + 2 种颜色 = 4 个类，而不是 4 个形状×颜色组合类）
```

## 组合模式 Composite

组合模式把对象组合成树形结构，统一处理单个对象和组合对象。

### 意图

```text
用统一的方式处理单个对象和对象组合（树形结构）
```

### 结构

```java
// 组件接口（单个和组合统一）
interface Component {
    void operation();
    default void add(Component c) { throw new UnsupportedOperationException(); }
}

// 叶子（单个对象）
class Leaf implements Component {
    public void operation() { System.out.println("叶子"); }
}

// 组合（容器）
class Composite implements Component {
    private List<Component> children = new ArrayList<>();

    public void add(Component c) { children.add(c); }

    public void operation() {
        for (Component child : children) {
            child.operation();   // 递归处理子节点
        }
    }
}
```

### 场景：文件系统、菜单树、部门树

```text
文件系统：
文件（叶子）和文件夹（组合）统一用 File 处理
```

## 装饰器模式 Decorator

装饰器模式动态给对象添加功能，不改变原有类。

### 意图

```text
运行时动态增强对象功能，比继承更灵活
```

### 结构

```java
// 组件接口
interface Coffee {
    String getDescription();
    double cost();
}

// 具体组件
class SimpleCoffee implements Coffee {
    public String getDescription() { return "咖啡"; }
    public double cost() { return 10; }
}

// 装饰器
class MilkDecorator implements Coffee {
    private Coffee coffee;

    public MilkDecorator(Coffee coffee) { this.coffee = coffee; }

    public String getDescription() { return coffee.getDescription() + "+牛奶"; }
    public double cost() { return coffee.cost() + 2; }
}

// 使用（动态叠加装饰）
Coffee coffee = new MilkDecorator(new SimpleCoffee());
System.out.println(coffee.getDescription());   // 咖啡+牛奶
```

### 场景：Java IO 流

```java
// Java IO 的装饰器模式
InputStream in = new BufferedInputStream(new FileInputStream("file.txt"));
// BufferedInputStream 装饰 FileInputStream，添加缓冲功能
```

## 外观模式 Facade

外观模式提供一个统一接口，简化子系统的使用。

### 意图

```text
为复杂子系统提供简单入口，隐藏内部复杂性
```

### 结构

```java
// 子系统（复杂）
class CPU { void start() { ... } }
class Memory { void load() { ... } }
class Disk { void read() { ... } }

// 外观（统一入口）
class Computer {
    private CPU cpu = new CPU();
    private Memory memory = new Memory();
    private Disk disk = new Disk();

    public void start() {   // 简化：一个方法启动电脑
        cpu.start();
        memory.load();
        disk.read();
    }
}
```

### 场景：Service 层

```text
Service 层就是外观模式：封装多个 Repository/组件的复杂调用
```

## 代理模式 Proxy

代理模式提供对象的替身，控制对原对象的访问。

### 意图

```text
通过代理控制对目标对象的访问（延迟加载、权限控制、日志）
```

### 结构

```java
// 接口
interface Subject {
    void request();
}

// 真实对象
class RealSubject implements Subject {
    public void request() { System.out.println("真实请求"); }
}

// 代理
class Proxy implements Subject {
    private RealSubject realSubject;

    public void request() {
        // 代理可以做：权限检查、日志、缓存
        if (realSubject == null) {
            realSubject = new RealSubject();   // 延迟加载
        }
        System.out.println("代理：记录日志");
        realSubject.request();
    }
}
```

### 代理类型

```text
1. 静态代理 —— 手动写代理类
2. 动态代理 —— JDK 动态代理 / CGLIB
```

```java
// JDK 动态代理
InvocationHandler handler = (proxy, method, args) -> {
    System.out.println("前置处理");
    Object result = method.invoke(target, args);
    System.out.println("后置处理");
    return result;
};
Subject proxy = (Subject) Proxy.newProxyInstance(
    target.getClass().getClassLoader(),
    target.getClass().getInterfaces(),
    handler);
```

### 场景：Spring AOP

```text
Spring AOP 就是动态代理：
@Transactional、@Cacheable 都是通过代理实现
```

## 结构型模式总结

| 模式 | 意图 | 场景 |
|------|------|------|
| 适配器 | 接口转换 | 兼容旧接口 |
| 桥接 | 抽象实现分离 | 多维扩展 |
| 组合 | 树形结构 | 文件、菜单 |
| 装饰器 | 动态增强 | IO 流 |
| 外观 | 简化接口 | Service 层 |
| 享元 | 共享对象 | 池化 |
| 代理 | 控制访问 | AOP |

```text
使用建议：
1. 代理 —— 最常用（AOP、事务）
2. 装饰器 —— IO 流、功能叠加
3. 外观 —— Service 层封装
4. 适配器 —— 对接第三方/旧接口
```

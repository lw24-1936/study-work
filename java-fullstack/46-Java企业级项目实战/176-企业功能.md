## 概述

企业级系统的基础功能模块，几乎所有管理系统（如若依 RuoYi）都包含这些。

```text
企业功能全景：
登录认证 → 用户 → 角色 → 权限 → 菜单
                  ↓
            部门 → 岗位 → 字典 → 参数配置 → 消息通知 → 操作日志
```

## 用户、角色、权限（RBAC）

RBAC（Role-Based Access Control）是基于角色的权限控制。

### RBAC 模型

```text
用户（User）→ 角色（Role）→ 权限（Permission）→ 资源（菜单/按钮）

用户不直接关联权限，通过角色间接关联
```

```text
RBAC 的核心表：
sys_user（用户）
sys_role（角色）
sys_permission（权限）
sys_user_role（用户-角色关联）
sys_role_permission（角色-权限关联）
```

### 数据库设计

```sql
CREATE TABLE sys_user (
    id BIGINT PRIMARY KEY,
    username VARCHAR(64) UNIQUE,
    password VARCHAR(128),     -- BCrypt 哈希
    dept_id BIGINT,            -- 所属部门
    status TINYINT             -- 状态（1 正常 0 禁用）
);

CREATE TABLE sys_role (
    id BIGINT PRIMARY KEY,
    role_name VARCHAR(64),
    role_key VARCHAR(64)       -- 角色标识（如 admin）
);

CREATE TABLE sys_permission (
    id BIGINT PRIMARY KEY,
    permission_name VARCHAR(64),
    permission_key VARCHAR(128)   -- 权限标识（如 user:delete）
);
```

### 权限校验

```java
// 方法级权限控制
@PreAuthorize("hasAuthority('user:delete')")
public void deleteUser(Long id) { ... }

// 菜单级权限控制（前端显示/隐藏菜单）
// 用户登录后，返回其可访问的菜单列表
```

## 菜单与部门

### 菜单

菜单是权限的载体（页面、按钮），树形结构。

```text
菜单类型：
1. 目录（M）—— 一级菜单（系统管理）
2. 菜单（C）—— 页面（用户管理）
3. 按钮（F）—— 操作（新增、删除）
```

```sql
CREATE TABLE sys_menu (
    id BIGINT PRIMARY KEY,
    parent_id BIGINT,          -- 父菜单（树形）
    menu_name VARCHAR(64),
    menu_type CHAR(1),         -- M 目录 C 菜单 F 按钮
    permission_key VARCHAR(128),
    path VARCHAR(128)          -- 路由路径
);
```

### 部门

部门是组织架构，树形结构。

```text
部门树：
总公司
├── 研发部
│   ├── 后端组
│   └── 前端组
└── 市场部
```

```sql
CREATE TABLE sys_dept (
    id BIGINT PRIMARY KEY,
    parent_id BIGINT,          -- 父部门（树形）
    dept_name VARCHAR(64),
    order_num INT
);
```

## 岗位与字典

### 岗位

岗位是职位的定义（如经理、主管、专员）。

```text
岗位与部门的关系：
部门（研发部）→ 岗位（后端工程师、前端工程师）
用户属于某个部门 + 担任某个岗位
```

### 字典

字典管理枚举数据（详见 175）。

```text
字典示例：
1. 用户状态：0=正常、1=禁用
2. 性别：1=男、2=女、3=未知
3. 订单状态：1=待支付、2=已支付、3=已发货
```

```sql
CREATE TABLE sys_dict_type (
    id BIGINT PRIMARY KEY,
    dict_name VARCHAR(64),     -- 字典名称
    dict_type VARCHAR(64)      -- 字典类型（如 sys_user_status）
);

CREATE TABLE sys_dict_data (
    id BIGINT PRIMARY KEY,
    dict_type VARCHAR(64),
    dict_value VARCHAR(64),    -- 值（1）
    dict_label VARCHAR(64)     -- 标签（正常）
);
```

## 登录与消息通知

### 登录

```text
登录流程：
1. 用户输入账号密码
2. 验证码校验（防刷）
3. 密码校验（BCrypt）
4. 签发 token（JWT）
5. 记录登录日志
```

```java
@PostMapping("/login")
public Result<LoginVO> login(@RequestBody LoginDTO dto) {
    // 1. 验证码校验
    captchaService.verify(dto.getCaptchaKey(), dto.getCaptcha());

    // 2. 密码校验
    User user = userService.getByUsername(dto.getUsername());
    if (user == null || !passwordEncoder.matches(dto.getPassword(), user.getPassword())) {
        throw new BusinessException("用户名或密码错误");
    }

    // 3. 签发 token
    String token = jwtUtil.generateToken(user.getId(), user.getUsername());

    // 4. 记录登录日志
    loginLogService.record(user, "登录成功");

    return Result.success(new LoginVO(token));
}
```

### 消息通知

```text
消息通知类型：
1. 站内信 —— 系统内消息
2. 邮件 —— 邮件通知
3. 短信 —— 短信通知
4. 推送 —— App 推送
```

## 最佳实践与踩坑记录

### 最佳实践

1. **RBAC 权限模型**。用户-角色-权限，灵活可控。

2. **菜单按钮权限分离**。目录/菜单/按钮分级控制。

3. **字典集中管理**。枚举数据用字典，不硬编码。

4. **参数可配置**。可调参数集中管理，不硬编码。

5. **登录加验证码**。防暴力破解。

### 踩坑记录

**坑 1：权限硬编码**

```java
if (user.getUsername().equals("admin")) { ... }   // 硬编码权限
```

用 RBAC 模型，权限可配置。

**坑 2：枚举值硬编码**

```java
if (status == 1) { ... }   // 魔法值，难维护
```

用字典或枚举，语义清晰。

**坑 3：密码明文存储**

```text
密码明文存数据库，泄露后全部暴露
```

BCrypt 哈希存储。

**坑 4：登录无验证码/限流**

```text
登录接口可无限试错，暴力破解
```

验证码 + 失败锁定 + 限流。

**坑 5：菜单树查询 N+1**

```text
递归查子菜单，每层一次查询
```

一次查全部，内存组装树。

**坑 6：部门删除不校验子部门**

```text
删除有子部门/用户的部门，数据孤儿
```

删除前校验子部门、关联用户。

## 概述

企业级项目的分层架构是代码组织的基石，清晰的层次让项目可维护、可扩展。

```text
经典分层：
Controller（接口层）→ Service（业务层）→ Repository/Mapper（数据层）
```

```text
各层职责：
Controller —— 接收请求、参数校验、返回响应
Service —— 业务逻辑、事务
Repository/Mapper —— 数据访问
```

## 项目分层

### 分层结构

```text
com.example.project/
├── controller/       # 接口层（Controller）
├── service/          # 业务层（Service + 实现）
│   └── impl/
├── repository/       # 数据访问（Repository/Mapper）
├── entity/           # 实体（对应数据库表）
├── dto/              # 数据传输对象（接口入参）
├── vo/               # 视图对象（接口出参）
├── converter/        # 对象转换（Entity ↔ DTO ↔ VO）
├── config/           # 配置
├── common/           # 通用（响应、异常、工具）
└── constant/         # 常量
```

### 各层职责

```text
Controller 层：
- 接收 HTTP 请求
- 参数校验（@Valid）
- 调用 Service
- 返回统一响应

Service 层：
- 业务逻辑
- 事务管理（@Transactional）
- 调用多个 Repository

Repository/Mapper 层：
- 数据存取
- SQL/ORM 操作
```

## Entity、DTO 与 VO

### Entity 实体

Entity 对应数据库表，是持久化对象。

```java
@Entity
@Table(name = "user")
public class User {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    private String name;
    private String email;
    private String password;   // 敏感字段
    private Date createTime;
}
```

### DTO 数据传输对象

DTO 是接口入参，接收客户端数据。

```java
// DTO：创建用户的入参
public class CreateUserDTO {
    @NotBlank(message = "姓名不能为空")
    private String name;

    @Email(message = "邮箱格式错误")
    private String email;

    @NotBlank(message = "密码不能为空")
    @Size(min = 6, message = "密码至少 6 位")
    private String password;
}
```

### VO 视图对象

VO 是接口出参，返回给客户端的数据。

```java
// VO：用户信息出参（不含密码等敏感字段）
public class UserVO {
    private Long id;
    private String name;
    private String email;
    private Date createTime;
}
```

### Entity vs DTO vs VO

| 对象 | 用途 | 特点 |
|------|------|------|
| Entity | 数据库表 | 含所有字段（含敏感） |
| DTO | 接口入参 | 校验规则、接收数据 |
| VO | 接口出参 | 展示数据（不含敏感） |

```text
为什么分离：
1. 安全 —— VO 不含敏感字段（密码）
2. 灵活 —— 接口字段和表字段解耦
3. 职责清晰 —— 各层用各自的对象
```

## Converter 转换

Converter 负责对象之间的转换。

### 手动转换

```java
public class UserConverter {
    // DTO → Entity
    public static User toEntity(CreateUserDTO dto) {
        User user = new User();
        user.setName(dto.getName());
        user.setEmail(dto.getEmail());
        user.setPassword(encoder.encode(dto.getPassword()));
        return user;
    }

    // Entity → VO
    public static UserVO toVO(User user) {
        UserVO vo = new UserVO();
        vo.setId(user.getId());
        vo.setName(user.getName());
        vo.setEmail(user.getEmail());
        return vo;
    }
}
```

### MapStruct 自动转换

```java
// MapStruct 注解自动生成转换代码
@Mapper(componentModel = "spring")
public interface UserConverter {
    UserConverter INSTANCE = Mappers.getMapper(UserConverter.class);

    User toEntity(CreateUserDTO dto);

    UserVO toVO(User user);
}
```

```text
MapStruct 的优势：
1. 自动生成 —— 编译期生成转换代码
2. 高性能 —— 无反射（比 BeanUtils 快）
3. 类型安全 —— 编译期检查
```

## 完整分层示例

### Controller 层

```java
@RestController
@RequestMapping("/api/users")
public class UserController {

    @Autowired
    private UserService userService;

    @PostMapping
    public Result<UserVO> create(@Valid @RequestBody CreateUserDTO dto) {
        UserVO vo = userService.create(dto);
        return Result.success(vo);
    }

    @GetMapping("/{id}")
    public Result<UserVO> get(@PathVariable Long id) {
        return Result.success(userService.get(id));
    }
}
```

### Service 层

```java
public interface UserService {
    UserVO create(CreateUserDTO dto);
    UserVO get(Long id);
}

@Service
public class UserServiceImpl implements UserService {

    @Autowired
    private UserRepository userRepository;

    @Override
    @Transactional
    public UserVO create(CreateUserDTO dto) {
        // 1. 校验唯一性
        if (userRepository.existsByEmail(dto.getEmail())) {
            throw new BusinessException("邮箱已注册");
        }
        // 2. DTO → Entity
        User user = UserConverter.toEntity(dto);
        // 3. 保存
        userRepository.save(user);
        // 4. Entity → VO
        return UserConverter.toVO(user);
    }

    @Override
    public UserVO get(Long id) {
        User user = userRepository.findById(id)
            .orElseThrow(() -> new NotFoundException("用户不存在"));
        return UserConverter.toVO(user);
    }
}
```

### Repository 层

```java
@Repository
public interface UserRepository extends JpaRepository<User, Long> {
    boolean existsByEmail(String email);
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. **严格分层**。Controller 不直接调 Repository。

2. **DTO 校验入参**。@Valid + 校验注解。

3. **VO 不含敏感字段**。密码等不返回前端。

4. **转换用 MapStruct**。高性能、类型安全。

5. **事务在 Service 层**。@Transactional 在 Service 方法。

### 踩坑记录

**坑 1：Controller 直接调 Repository**

```java
@RestController
public class UserController {
    @Autowired
    private UserRepository repository;   // 跨层调用，职责混乱
}
```

Controller → Service → Repository，严格分层。

**坑 2：Entity 直接返回前端**

```java
@GetMapping("/{id}")
public User get(@PathVariable Long id) {
    return repository.findById(id).get();   // 返回 Entity，泄露密码
}
```

返回 VO，不暴露 Entity（含敏感字段）。

**坑 3：用 BeanUtils 转换**

```java
BeanUtils.copyProperties(source, target);   // 反射，慢，且不易排查
```

用 MapStruct（编译期生成，高性能）。

**坑 4：DTO 和 VO 混用**

```text
DTO 和 VO 用一个对象，入参出参耦合，改一个影响另一个
```

DTO（入参）和 VO（出参）分离。

**坑 5：事务在 Controller**

```java
@RestController
public class UserController {
    @Transactional   // 事务在 Controller，业务逻辑散落
    public void create() { ... }
}
```

事务在 Service 层。

**坑 6：Service 只有接口没实现**

```text
过度设计：每个 Service 都接口 + 实现，简单项目没必要
```

简单项目直接 @Service 类，复杂/多实现才用接口。

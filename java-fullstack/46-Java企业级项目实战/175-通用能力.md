## 概述

企业级项目的通用能力是各模块复用基础设施，包括统一响应、统一异常、日志、权限等。

## 统一响应

统一响应让所有接口返回一致的格式（详见 130-API设计）。

### 统一响应类

```java
public class Result<T> {
    private int code;        // 0 成功，非 0 错误码
    private String message;  // 提示信息
    private T data;          // 数据

    public static <T> Result<T> success(T data) {
        return new Result<>(0, "成功", data);
    }

    public static <T> Result<T> error(int code, String message) {
        return new Result<>(code, message, null);
    }
}
```

### 错误码定义

```java
public enum ErrorCode {
    SUCCESS(0, "成功"),
    PARAM_ERROR(400, "参数错误"),
    UNAUTHORIZED(401, "未登录"),
    FORBIDDEN(403, "无权限"),
    NOT_FOUND(404, "资源不存在"),
    SYSTEM_ERROR(500, "系统错误");

    private final int code;
    private final String message;
}
```

## 统一异常处理

统一异常处理集中处理异常，返回一致格式（详见 77-全局异常）。

### 全局异常处理

```java
@RestControllerAdvice
public class GlobalExceptionHandler {

    // 业务异常
    @ExceptionHandler(BusinessException.class)
    public Result<Void> handleBusiness(BusinessException e) {
        return Result.error(e.getCode(), e.getMessage());
    }

    // 参数校验异常
    @ExceptionHandler(MethodArgumentNotValidException.class)
    public Result<Void> handleValid(MethodArgumentNotValidException e) {
        String message = e.getBindingResult().getFieldErrors().stream()
            .map(FieldError::getDefaultMessage)
            .collect(Collectors.joining(", "));
        return Result.error(400, message);
    }

    // 未知异常
    @ExceptionHandler(Exception.class)
    public Result<Void> handleException(Exception e) {
        log.error("系统异常", e);
        return Result.error(500, "系统异常，请稍后再试");
    }
}
```

## 参数校验

参数校验在入口校验输入，防止脏数据。

### 校验注解

```java
public class CreateUserDTO {
    @NotBlank(message = "姓名不能为空")
    private String name;

    @Email(message = "邮箱格式错误")
    private String email;

    @Size(min = 6, max = 20, message = "密码长度 6-20 位")
    private String password;

    @Min(value = 18, message = "年龄至少 18 岁")
    @Max(value = 100, message = "年龄不能超过 100")
    private Integer age;
}
```

### 常用校验注解

```text
@NotNull —— 非空
@NotBlank —— 非空（字符串去空格）
@NotEmpty —— 非空（集合）
@Size —— 长度
@Min/@Max —— 数值范围
@Email —— 邮箱格式
@Pattern —— 正则
```

## 日志与操作日志

### 日志

```java
@Slf4j
@Service
public class UserService {
    public void create(CreateUserDTO dto) {
        log.info("创建用户：{}", dto.getName());       // 业务日志
        // ...
    }
}
```

### 日志规范

```text
1. 用占位符 {}，不用字符串拼接
2. 日志级别合理（debug/info/warn/error）
3. 敏感信息脱敏（密码、手机号）
4. 异常日志带堆栈
```

### 操作日志

操作日志记录用户的操作，用于审计和追溯。

```java
// 操作日志注解
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
public @interface Log {
    String value();   // 操作描述
}

// 切面记录操作日志
@Aspect
@Component
public class OperationLogAspect {

    @Around("@annotation(log)")
    public Object around(ProceedingJoinPoint pjp, Log log) throws Throwable {
        // 记录：操作人、操作、时间、参数、结果
        OperationLog record = new OperationLog();
        record.setOperator(getCurrentUser());
        record.setOperation(log.value());
        record.setCreateTime(new Date());

        try {
            Object result = pjp.proceed();
            record.setStatus("成功");
            return result;
        } catch (Exception e) {
            record.setStatus("失败");
            throw e;
        } finally {
            operationLogService.save(record);   // 异步保存
        }
    }
}
```

## 权限与数据字典

### 权限

```text
RBAC 权限模型：
用户（User）→ 角色（Role）→ 权限（Permission）→ 资源（菜单/按钮）
```

```java
// Spring Security 权限注解
@PreAuthorize("hasRole('ADMIN')")
public void deleteUser(Long id) { ... }

@PreAuthorize("hasAuthority('user:delete')")
public void deleteUser(Long id) { ... }
```

### 数据字典

数据字典是枚举数据的统一管理（如状态、类型）。

```text
数据字典：把"1=男、2=女"这种枚举值集中管理

1. 字典表存储（dict_type + dict_value + label）
2. 缓存到 Redis
3. 前端展示时翻译
```

```java
// 数据字典服务
public String getDictLabel(String dictType, String value) {
    // 从缓存/数据库查字典，翻译 value → label
    return dictService.getLabel(dictType, value);
}
```

## 文件管理

文件管理处理文件上传、存储、下载。

### 文件管理方案

```text
1. 本地存储 —— 存服务器磁盘
2. 对象存储 —— OSS/MinIO（推荐）
3. 数据库 —— 存文件元数据，文件存对象存储
```

```java
@Service
public class FileService {

    public String upload(MultipartFile file) {
        // 1. 校验（类型、大小）
        validateFile(file);

        // 2. 生成唯一文件名
        String objectName = UUID.randomUUID() + getExt(file);

        // 3. 上传到 OSS/MinIO
        ossClient.upload(file, objectName);

        // 4. 保存文件元数据
        FileInfo info = new FileInfo();
        info.setObjectName(objectName);
        info.setOriginalName(file.getOriginalFilename());
        info.setSize(file.getSize());
        fileMapper.insert(info);

        return objectName;
    }
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. **统一响应和异常**。所有接口一致格式。

2. **参数校验在入口**。@Valid 校验，防脏数据。

3. **日志用占位符**。不用字符串拼接（性能 + 可读）。

4. **敏感信息脱敏**。日志里密码、手机号脱敏。

5. **文件用对象存储**。OSS/MinIO，不用本地磁盘。

### 踩坑记录

**坑 1：异常返回堆栈给前端**

```java
@ExceptionHandler(Exception.class)
public Result handle(Exception e) {
    return Result.error(500, e.toString());   // 泄露内部信息
}
```

异常信息脱敏，返回友好提示，详细堆栈只记日志。

**坑 2：日志拼接字符串**

```java
log.info("用户 " + name + " 登录");   // 拼接，浪费性能
```

用占位符：log.info("用户 {} 登录", name)。

**坑 3：日志泄露敏感信息**

```java
log.info("用户登录：{}", user);   // user 含密码，泄露
```

日志脱敏，不打印密码等敏感字段。

**坑 4：操作日志同步保存影响性能**

```text
操作日志同步写库，影响接口性能
```

操作日志异步保存（@Async 或 MQ）。

**坑 5：文件存储本地磁盘**

```text
文件存本地磁盘，多实例无法共享，扩容困难
```

用对象存储（OSS/MinIO）。

**坑 6：参数校验只在部分接口**

```text
有的接口校验参数，有的不校验，脏数据入库
```

所有入口统一校验（@Valid）。

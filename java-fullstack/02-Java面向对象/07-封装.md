## 访问修饰符

封装的核心：**隐藏内部实现，只暴露必要的接口**。Java 通过四种访问修饰符控制可见性：

| 修饰符 | 同类 | 同包 | 子类 | 任何地方 |
|--------|------|------|------|----------|
| `private` | 可见 | | | |
| 默认（不写） | 可见 | 可见 | | |
| `protected` | 可见 | 可见 | 可见 | |
| `public` | 可见 | 可见 | 可见 | 可见 |

## private / public / protected / 默认

```java
package com.example.model;

public class User {
    private String password;        // 只有 User 类内部能访问
    String email;                   // 默认：同包的类能访问
    protected String name;          // 同包 + 子类能访问
    public int id;                  // 任何地方都能访问

    private void encryptPassword() {
        // 内部实现细节，外部不需要知道
    }
}
```

### 默认访问权限的特殊性

默认权限（包级私有，package-private）没有对应的关键字——不写修饰符就是默认。它的粒度是"包"：同一个 `package` 下的类可以互相访问默认成员，但子包不算。

```java
// com.example.model.User.java
package com.example.model;
class User {          // 默认访问权限的类，只能同包使用
}
```

### protected 的子类规则

`protected` 允许子类访问，但有细节：子类只能通过继承访问，不能通过父类实例随意访问。

```java
package com.example.model;

public class Animal {
    protected String name;
}

// 另一个包中的子类
package com.example.service;
import com.example.model.Animal;

public class Dog extends Animal {
    public void method() {
        System.out.println(this.name);        // 可以通过 this 访问

        Animal other = new Animal();
        // System.out.println(other.name);    // 编译错误！不是通过继承关系访问
    }
}
```

这个限制很少碰到，但面试可能考。

## Getter 与 Setter

属性私有化，通过公开的 getter/setter 方法控制访问：

```java
public class User {
    private String name;
    private int age;

    public String getName() {
        return name;
    }

    public void setName(String name) {
        if (name == null || name.isBlank()) {
            throw new IllegalArgumentException("name 不能为空");
        }
        this.name = name.trim();
    }

    public int getAge() {
        return age;
    }

    public void setAge(int age) {
        if (age < 0 || age > 150) {
            throw new IllegalArgumentException("age 不合法: " + age);
        }
        this.age = age;
    }
}
```

Getter 和 setter 的价值不只是形式——setter 里可以加校验逻辑，getter 里可以返回防御性副本或计算值。直接用 `public` 属性的代码失去了一切控制能力。

Lombok 的 `@Data` 注解自动生成 getter、setter、`equals`、`hashCode`、`toString`——但只生成简单的读写，没有校验逻辑。需要校验时自己写 setter。

## JavaBean 规范

JavaBean 是一种约定，不是语言特性。一个类满足：

1. `public` 类，有无参构造
2. 属性 `private`，通过 `getXxx()` / `setXxx()` 访问
3. 实现 `Serializable`（可选，但实际上多数框架不强制）

```java
public class Person implements java.io.Serializable {
    private String name;
    private int age;

    public Person() { }                          // 无参构造

    public String getName() { return name; }      // getter
    public void setName(String name) { this.name = name; }

    public int getAge() { return age; }
    public void setAge(int age) { this.age = age; }
}
```

JavaBean 的设计初衷是给可视化拖拽工具用，但现在更多是作为"数据传输对象"的隐含约定——JSP 的 `<jsp:getProperty>`、MyBatis 的参数映射、Spring 的属性注入都依赖这个命名模式。

## 不可变对象

对象创建后状态不能再改变。Java 标准库中 `String`、`Integer`、`LocalDate` 都是不可变对象。

```java
public final class Money {
    private final double amount;
    private final String currency;

    public Money(double amount, String currency) {
        this.amount = amount;
        this.currency = currency;
    }

    public double getAmount() { return amount; }
    public String getCurrency() { return currency; }

    // 没有 setter！运算返回新对象
    public Money add(Money other) {
        if (!this.currency.equals(other.currency)) {
            throw new IllegalArgumentException("币种不匹配");
        }
        return new Money(this.amount + other.amount, this.currency);
    }
}
```

设计不可变对象的要点：
1. 类声明为 `final`（防止子类破坏不可变性）
2. 所有属性 `private final`
3. 只提供 getter，不提供 setter
4. 如果属性是可变对象（如 Date、List），getter 返回副本而不是原引用：

```java
public final class Order {
    private final List<String> items;     // items 本身是可变的

    public Order(List<String> items) {
        this.items = List.copyOf(items);   // 防御性复制
    }

    public List<String> getItems() {
        return items;                      // List.copyOf 返回的也不可变，安全
    }
}
```

不可变对象的优势：线程安全（不用同步）、可以安全地共享和缓存、HashMap 的 key 不会因为状态变化而丢失。代价：每次修改都要创建新对象，频繁修改的场景性能差。

## interface 关键字

接口定义行为契约，不提供字段（状态）——只声明"能做什么"，不规定"怎么做"。

```java
public interface Flyable {
    void fly();                      // 抽象方法：public abstract 默认省略
}

public interface Payable {
    double getAmount();
}
```

## implements

一个类通过 `implements` 实现接口，必须实现接口中所有抽象方法：

```java
public class Bird implements Flyable {
    @Override
    public void fly() {
        System.out.println("Bird is flying");
    }
}

// 实现多个接口
public class Airplane implements Flyable, Payable {
    @Override
    public void fly() {
        System.out.println("Airplane is flying");
    }

    @Override
    public double getAmount() {
        return 1_000_000;
    }
}
```

接口的核心价值：定义调用方和被调用方之间的**契约**。调用方不关心具体实现类是谁，只要它实现了接口就行——这就是"面向接口编程"。

## 接口方法

接口中的方法有三类：

```java
public interface Printer {
    // 1. 抽象方法：默认 public abstract
    void print(String content);

    // 2. default 方法（Java 8+）
    default void log(String msg) {
        System.out.println("[LOG] " + msg);
    }

    // 3. static 方法（Java 8+）
    static Printer of(String type) {
        if ("console".equals(type)) {
            return new ConsolePrinter();
        }
        throw new IllegalArgumentException("Unknown printer: " + type);
    }
}
```

接口方法的默认修饰符：
- 抽象方法：`public abstract`（可省略）
- default 方法：`public`（可省略，必须写 `default`）
- static 方法：`public`（可省略）

## default 方法与 static 方法

Java 8 引入的 `default` 方法解决了接口演化的痛点——在已有接口中新增方法而不破坏所有实现类。

```java
public interface Collection<E> {
    // 抽象方法
    int size();
    boolean isEmpty();

    // Java 8 新增的默认方法：基于已有抽象方法提供实现
    default boolean removeIf(Predicate<? super E> filter) {
        Objects.requireNonNull(filter);
        boolean removed = false;
        Iterator<E> each = iterator();
        while (each.hasNext()) {
            if (filter.test(each.next())) {
                each.remove();
                removed = true;
            }
        }
        return removed;
    }
}
```

多接口的 default 方法冲突规则：

```java
public interface A {
    default void hello() { System.out.println("A"); }
}

public interface B {
    default void hello() { System.out.println("B"); }
}

public class C implements A, B {
    // 必须重写——编译器不知道怎么选
    @Override
    public void hello() {
        A.super.hello();           // 显式选择 A 的实现
        // 或者自己写新逻辑
    }
}
```

`static` 方法属于接口本身，通过 `接口名.方法名` 调用：

```java
Printer consolePrinter = Printer.of("console");
```

与类的 static 方法不同，接口的 static 方法不会被实现类继承。

## private 接口方法

Java 9 引入，用于在接口内部复用代码，不希望暴露给实现类或调用方：

```java
public interface Logger {
    default void info(String msg) {
        log("INFO", msg);
    }

    default void error(String msg) {
        log("ERROR", msg);
    }

    private void log(String level, String msg) {
        System.out.println("[" + level + "] " + msg);
    }
}
```

`private` 接口方法只能被同接口的 `default` 和 `static` 方法调用。它就是接口内部的工具代码——外面看不到也不需要看到。

## 函数式接口

只有一个抽象方法的接口叫函数式接口。`@FunctionalInterface` 注解用来显式声明这个意图：

```java
@FunctionalInterface
public interface Comparator<T> {
    int compare(T o1, T o2);          // 唯一抽象方法

    // 以下都是 default 和 static 方法，不影响"唯一抽象"的约束
    default Comparator<T> reversed() { ... }
    static <T> Comparator<T> naturalOrder() { ... }
}
```

函数式接口可以用 Lambda 表达式实现：

```java
// 老写法：匿名内部类
Runnable r1 = new Runnable() {
    @Override
    public void run() {
        System.out.println("Running");
    }
};

// Lambda 写法：等价于上面的匿名内部类
Runnable r2 = () -> System.out.println("Running");
```

Java 标准库中常见的函数式接口：

| 接口 | 抽象方法 | 用途 |
|------|---------|------|
| `Runnable` | `void run()` | 无参数、无返回值的任务 |
| `Callable<V>` | `V call()` | 无参数、有返回值的任务 |
| `Comparator<T>` | `int compare(T, T)` | 比较两个对象 |
| `Comparable<T>` | `int compareTo(T)` | 自然排序 |

后面"第六篇 Java 函数式编程"会详细讲 `Function`、`Consumer`、`Predicate` 等更丰富的函数式接口。

## 接口继承

接口可以继承多个接口：

```java
public interface Readable {
    String read();
}

public interface Writable {
    void write(String data);
}

public interface ReadWritable extends Readable, Writable {
    // 同时继承 read() 和 write()
}
```

接口多继承不会产生菱形问题——接口没有状态，两个父接口定义了相同的抽象方法（签名一致）在子接口中只算一个。但如果两个父接口定义了签名一致的 `default` 方法，子接口继承后必须重写。

## 多接口实现

Java 用接口弥补了单继承的局限——一个类只能有一个父类，但可以实现无数个接口：

```java
public class SmartPhone
    extends Device
    implements Callable, Photographable, Navigable, Payable {
    // 实现所有接口的抽象方法
}
```

多接口实现的冲突规则：

- **多个接口有相同的抽象方法** → 只实现一次，不算冲突
- **多个接口有签名相同的 default 方法** → 实现类必须重写
- **父类方法和接口 default 方法冲突** → 父类优先（"类优先"原则）

## extends 关键字

Java 用 `extends` 实现单继承——一个类只能有一个直接父类。

```java
// 父类
public class Animal {
    protected String name;

    public void eat() {
        System.out.println(name + " is eating");
    }
}

// 子类
public class Dog extends Animal {
    public void bark() {
        System.out.println(name + " is barking");
    }
}

// 使用
Dog dog = new Dog();
dog.name = "Buddy";      // 继承过来的属性
dog.eat();               // 继承过来的方法
dog.bark();              // 子类自己的方法
```

Java 不支持多继承（一个子类不能 extends 多个父类），这是为了避免 C++ 的菱形继承问题（两个父类有同名方法，子类不知道该调哪个）。但一个类可以实现多个接口（继承章节后面的"接口"会讲）。

所有 Java 类都隐式继承 `Object`——如果没有显式写 `extends`，编译器自动加上 `extends Object`。

## 方法重写

子类重新定义父类的方法——方法签名完全一致，实现不同。

```java
public class Animal {
    public void makeSound() {
        System.out.println("Some sound");
    }
}

public class Dog extends Animal {
    @Override                    // 注解：编译器检查是否真的重写了父类方法
    public void makeSound() {
        System.out.println("Woof!");
    }
}
```

重写规则：
- 方法签名（方法名 + 参数列表）必须完全一致
- 返回值类型可以是被重写方法返回值的子类型（协变返回）
- 访问权限不能更低（父类是 public，子类不能是 protected）
- 抛出的受检异常不能比父类更多或更宽
- `static` 方法不能被重写（可以被"隐藏"，但这不是重写）
- `final` 方法不能被重写

```java
public class Parent {
    public Parent getSelf() {           // 返回类型是 Parent
        return this;
    }
}

public class Child extends Parent {
    @Override
    public Child getSelf() {           // 返回类型是 Child（协变）
        return this;
    }
}
```

`@Override` 注解是可选的，但**强烈建议加上**——如果你以为是重写但实际不是（比如方法名拼错、参数类型不对），编译器会报错提醒。

## super 关键字

`super` 指向父类对象，用法和 `this` 对应：

```java
public class Dog extends Animal {
    public Dog(String name) {
        super();              // 调用父类无参构造（默认就有，可以不写）
        this.name = name;
    }

    @Override
    public void eat() {
        super.eat();          // 先执行父类的 eat 逻辑
        System.out.println("Dog finished eating");
    }

    public void printName() {
        System.out.println(super.name);  // 访问父类属性
    }
}
```

注意：`super` 和 `this` 不能在同一个构造方法中同时作为第一条语句出现（两者都要求放在第一行）。

## 构造方法继承

子类构造方法的第一行必须（且自动）调用父类构造方法——要么你显式写 `super(...)`，要么编译器插入隐式的 `super()`。

```java
public class Animal {
    public Animal(String name) {
        // ...
    }
}

public class Dog extends Animal {
    public Dog(String name) {
        super(name);           // 必须显式调用——父类没有无参构造
    }
}
```

如果在 Dog 构造方法里不写 `super(name)`，编译器尝试插入 `super()`——但 Animal 没有无参构造，编译错误。

> 这个规则经常在 Spring 项目的继承关系中踩坑。父类加了有参构造而忘了保留无参构造，所有子类编译报错。

## 向上转型与向下转型

### 向上转型

子类对象赋值给父类引用——自动、安全：

```java
Dog dog = new Dog();
Animal animal = dog;        // 向上转型，自动
animal.eat();               // 调用 Dog 重写后的 eat()
// animal.bark();           // 编译错误！Animal 类型没有 bark 方法
```

向上转型后，通过父类引用能调用的方法只限于父类定义的接口——但实际执行的是子类重写的版本。这就是多态的基础。

### 向下转型

父类引用转回子类引用——需要显式强转，不安全：

```java
Animal animal = new Dog();
Dog dog = (Dog) animal;     // 向下转型，animal 实际指向 Dog，安全
dog.bark();

Animal animal2 = new Cat();
// Dog dog2 = (Dog) animal2; // ClassCastException！实际是 Cat
```

向下转型之前用 `instanceof` 检查：

```java
if (animal instanceof Dog) {
    Dog dog = (Dog) animal;
    dog.bark();
}

// Java 16+ 模式匹配
if (animal instanceof Dog dog) {
    dog.bark();               // 直接使用 dog，不需要强转
}
```

## instanceof

用于在运行时判断对象是否是指定类型（或子类型）的实例：

```java
Object obj = "hello";

obj instanceof String      // true
obj instanceof Object      // true（所有类都是 Object 的子类）
obj instanceof Integer     // false
null instanceof String     // false（instanceof 对 null 永远返回 false）
```

instanceof 的典型使用场景：equals 方法中的类型判断、集合中取出元素后按类型分发处理、向下转型前的安全检查。

实践中如果发现需要频繁 instanceof 做类型判断，通常意味着设计有问题——优先考虑多态让代码自动分发，而不是手动判断类型。

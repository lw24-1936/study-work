## 编译时多态

编译阶段就能确定调用哪个方法，主要是指**方法重载**：

```java
public class Printer {
    public void print(int value) {
        System.out.println("int: " + value);
    }

    public void print(String value) {
        System.out.println("String: " + value);
    }
}

Printer p = new Printer();
p.print(42);          // 编译时确定调用 print(int)
p.print("hello");     // 编译时确定调用 print(String)
```

编译器根据参数的类型和数量，在编译期就选择好具体的方法版本。这本质上是方法签名匹配，和多态的"面向接口编程"不是一回事。

## 运行时多态

编译时看类型声明，运行时看实际对象——这才是 OOP 中"多态"的核心含义：

```java
Animal animal = new Dog();    // 编译类型是 Animal，实际类型是 Dog
animal.makeSound();           // 调用的是 Dog 的 makeSound()
```

同一个父类引用，指向不同子类对象时表现出不同行为：

```java
public void makeItSound(Animal animal) {
    animal.makeSound();          // 具体调用哪个 makeSound，运行时才确定
}

makeItSound(new Dog());          // "Woof!"
makeItSound(new Cat());          // "Meow!"
makeItSound(new Bird());         // "Chirp!"
```

运行时的核心规则：**编译看左边，运行看右边**。`Animal animal = new Dog()` — 编译时 animal 是 Animal 类型，只能调 Animal 定义的方法；运行时 JVM 动态查找 animal 实际指向的 Dog 对象，执行 Dog 重写的方法。

## 方法重载 vs 方法重写

| 维度 | 重载（Overload） | 重写（Override） |
|------|-----------------|-----------------|
| 发生位置 | 同一个类（或父子类） | 父子类之间 |
| 方法签名 | **必须不同** | **必须相同** |
| 返回值 | 可以不同 | 相同或子类型（协变） |
| 访问权限 | 可以任意 | 不能比父类更窄 |
| 绑定时机 | 编译时（静态绑定） | 运行时（动态绑定） |
| 和多态的关系 | 编译时多态 | 运行时多态（真正的多态） |

```java
public class Parent {
    public void method() {
        System.out.println("Parent");
    }
}

public class Child extends Parent {
    @Override
    public void method() {                 // 重写：签名一致
        System.out.println("Child");
    }

    public void method(String s) {         // 重载：签名不同（多了参数）
        System.out.println("Child: " + s);
    }

    // public String method() { }          // 编译错误：只有返回值不同不是重载
}
```

一个重要的面试考点：重载方法的选择在编译时就决定了——即使运行时实际类型不同。

```java
public class Parent {
    public void greet(Animal a) { System.out.println("Parent animal"); }
    public void greet(Dog d)    { System.out.println("Parent dog"); }
}

public class Child extends Parent {
    @Override
    public void greet(Animal a) { System.out.println("Child animal"); }
}

Parent p = new Child();
Animal a = new Dog();
p.greet(a);          // 输出 "Child animal"
// 编译时：p 是 Parent，a 是 Animal → 选择 greet(Animal)
// 运行时：p 实际是 Child，执行 Child 重写的 greet(Animal)
// 不会选 greet(Dog)——方法选择在编译时就定了

p.greet(new Dog());  // 输出 "Parent dog"
// 编译时：p 是 Parent，参数是 Dog → 选 greet(Dog)（比 greet(Animal) 更精确）
// 运行时：Child 没有重写 greet(Dog)，执行 Parent 的版本
```

## 动态绑定

动态绑定指 JVM 在运行时（而非编译时）决定调用哪个方法。Java 的实例方法默认就是动态绑定的。

绑定流程（简化）：

1. 找到对象实际类型的方法表
2. 查找和方法签名匹配的方法
3. 如果当前类没有，往父类查找
4. 如果都没有，查找接口默认方法
5. 最终都没找到 → 编译期就应该报错了

这和 C++ 形成对比：C++ 的实例方法默认是静态绑定，需要 `virtual` 关键字才启用动态绑定。Java 反过来——实例方法默认动态绑定，只有 `static`、`final`、`private` 方法是静态绑定的。

## 虚方法调用

Java 中所有**非 static、非 final、非 private** 的实例方法都是"虚方法"——它们都可以被子类重写，因此 JVM 必须通过虚方法表（vtable）在运行时分派。

```java
public class Animal {
    public void eat() { }             // 虚方法：可以被子类重写
    public final void die() { }       // 非虚：final 阻止重写
    private void digest() { }         // 非虚：private 不可继承
    public static void info() { }     // 非虚：static 属于类，不参与多态
}
```

JVM 对虚方法调用做了大量优化：
- **内联缓存（Inline Cache）**：记录上次调用的实际类型，下次直接走快路径
- **单态内联（Monomorphic）**：如果 90% 的调用都指向同一个子类，JIT 直接内联那个子类的方法
- **CHA（Class Hierarchy Analysis）**：分析类继承关系，如果某个方法只有唯一实现，就按非虚方法处理

这些优化对开发者透明，但理解它们有助于理解"传闻中说虚方法调用慢"的由来——在现代 JVM 上，虚方法调用的开销已经被优化到接近静态调用。

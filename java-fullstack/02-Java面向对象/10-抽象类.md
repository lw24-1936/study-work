## abstract 关键字

`abstract` 可以修饰类和方法——表示"不完整，需要子类实现"。

## 抽象方法

抽象方法只有声明，没有方法体：

```java
public abstract class Animal {
    public abstract void makeSound();   // 分号结尾，没有 {}
}

// 语法错误示例：
// public abstract class Animal {
//     public abstract void makeSound() { }   // 抽象方法不能有方法体
//     public abstract void makeSound();      // 需要分号
// }
```

## 抽象类

包含抽象方法的类必须声明为抽象类。抽象类本身不能被实例化：

```java
public abstract class Animal {
    protected String name;

    public Animal(String name) {        // 抽象类可以有构造方法
        this.name = name;
    }

    public abstract void makeSound();   // 抽象方法：子类必须实现

    public void sleep() {               // 抽象类可以有具体方法
        System.out.println(name + " is sleeping");
    }
}

// Animal a = new Animal();            // 编译错误：不能实例化抽象类
```

抽象类的本质是**部分实现**——父类定义了通用框架和部分逻辑，留下抽象的缺口让子类填充。

## 抽象类继承

子类继承抽象类后有两种选择：

1. **实现所有抽象方法** → 子类成为具体类
2. **不去实现（或只实现一部分）抽象方法** → 子类也必须声明为抽象类

```java
// 选择 1：实现所有抽象方法
public class Dog extends Animal {
    public Dog(String name) {
        super(name);
    }

    @Override
    public void makeSound() {           // 必须实现
        System.out.println("Woof!");
    }
}

// 选择 2：不实现抽象方法 → 自己也是抽象类
public abstract class Canine extends Animal {
    public Canine(String name) {
        super(name);
    }
    // 没有实现 makeSound()，所以 Canine 也必须声明为 abstract
}
```

## 抽象类设计

抽象类和接口的选择是 OOP 设计的核心决策之一。

### 什么时候用抽象类

- 多个相关类共享部分实现（字段、具体方法）
- 需要定义非 public 的成员（接口方法默认 public）
- 需要构造方法初始化参数
- 子类和父类有"是一个"的关系（Dog is an Animal）

### 模板方法模式

抽象类最常见的应用是**模板方法模式**——父类定义算法骨架，子类填充具体步骤：

```java
public abstract class DataProcessor {
    // 模板方法：定义处理流程
    public final void process() {
        readData();
        processData();
        writeData();
    }

    protected abstract void readData();        // 步骤 1：子类实现
    protected abstract void processData();     // 步骤 2：子类实现
    protected abstract void writeData();       // 步骤 3：子类实现
}

public class CSVProcessor extends DataProcessor {
    @Override
    protected void readData() {
        System.out.println("读取 CSV 文件");
    }

    @Override
    protected void processData() {
        System.out.println("处理 CSV 数据");
    }

    @Override
    protected void writeData() {
        System.out.println("写入 CSV 结果");
    }
}
```

`process()` 是 `final` 的——子类不能改变算法步骤，只能填充每一步的具体行为。这是一种"反向控制"：框架调用你写的代码，而不是你调用框架。

### 抽象类 vs 接口

| 维度 | 抽象类 | 接口 |
|------|--------|------|
| 关键字 | `abstract class` | `interface` |
| 实例化 | 不能 | 不能 |
| 构造方法 | 可以有 | 不能有 |
| 字段 | 可以有各种成员变量 | 只能有 `public static final` 常量 |
| 方法实现 | 可以有具体方法 | Java 8+ 可以有 `default` 和 `static` 方法 |
| 多继承 | 只能继承一个 | 可以实现多个 |
| 访问修饰符 | 任意 | 方法默认 `public`（Java 9+ 支持 `private`） |
| 语义 | "是一个"（is-a） | "能做什么"（can-do） |

实践中，如果多个不相关的类需要实现相同的行为（如 `Comparable`、`Serializable`），用接口。如果一组密切相关的类需要共享状态和部分逻辑（如 `InputStream` 体系），用抽象类。

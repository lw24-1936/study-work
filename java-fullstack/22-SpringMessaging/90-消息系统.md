## 概述

Spring Messaging 是 Spring 对消息传递的统一抽象，为不同的消息中间件（RabbitMQ、Kafka、RocketMQ 等）提供一致的编程模型。

```text
Spring Messaging 核心价值：
1. 统一抽象 —— Message/MessageChannel 屏蔽中间件差异
2. 注解驱动 —— @RabbitListener/@KafkaListener 简化消费
3. 消息转换 —— MessageConverter 自动序列化/反序列化

Spring Messaging 的衍生：
Spring Integration  —— 企业集成模式（基于 Spring Messaging）
Spring Cloud Stream —— 消息驱动微服务（基于 Spring Messaging）
```

```text
核心组件：
Message          —— 消息（payload + headers）
MessageChannel   —— 消息通道（发送/接收）
MessageConverter —— 消息转换器（对象 ↔ 消息）
@RabbitListener / @KafkaListener —— 消息监听器
```

## Message 消息

Message 是消息的核心载体，包含消息体（Payload）和消息头（Headers）。

### Message 接口

```java
public interface Message<T> {
    T getPayload();                // 消息体
    MessageHeaders getHeaders();   // 消息头
}
```

```java
// 创建消息
Message<String> message = MessageBuilder
    .withPayload("hello")
    .setHeader("type", "greeting")
    .setHeader("timestamp", System.currentTimeMillis())
    .build();

String payload = message.getPayload();      // "hello"
MessageHeaders headers = message.getHeaders();
String type = (String) headers.get("type"); // "greeting"
```

### 常用消息头

```text
MessageHeaders.ID            —— 消息唯一 ID
MessageHeaders.TIMESTAMP     —— 时间戳
MessageHeaders.CONTENT_TYPE  —— 内容类型（application/json）
MessageHeaders.REPLY_CHANNEL —— 回复通道
MessageHeaders.ERROR_CHANNEL —— 错误通道
```

### 消息的可靠性设计

```java
// 业务消息通常包含幂等键
public class OrderMessage {
    private String messageId;     // 消息唯一 ID（用于幂等）
    private String eventType;     // 事件类型
    private Long orderId;         // 业务数据
    private String payload;       // 载荷
    private long timestamp;       // 时间戳
}
```

## MessageChannel 消息通道

MessageChannel 是消息发送的目标抽象，屏蔽了底层中间件。

### MessageChannel 接口

```java
public interface MessageChannel {
    boolean send(Message<?> message);           // 发送消息
    boolean send(Message<?> message, long timeout);
}
```

### 在 Spring Boot 中的使用

Spring Boot 中，消息通道通常由框架自动配置，开发者主要使用更高层的 RabbitTemplate / KafkaTemplate：

```java
// RabbitMQ 的消息通道（框架内部使用）
@Autowired
private RabbitTemplate rabbitTemplate;

rabbitTemplate.convertAndSend("exchange", "routingKey", message);

// Kafka 的消息通道
@Autowired
private KafkaTemplate<String, String> kafkaTemplate;

kafkaTemplate.send("topic", message);
```

### MessageChannel 与中间件的关系

```text
MessageChannel 是抽象层，具体实现由中间件提供：
RabbitMQ → AmqpChannel
Kafka    → KafkaMessageChannel

Spring Cloud Stream 中，通过 Binder 将 MessageChannel 绑定到具体中间件
```

## MessageConverter 消息转换器

MessageConverter 负责 Java 对象与消息之间的转换。

### MessageConverter 接口

```java
public interface MessageConverter {
    Message<?> toMessage(Object object, MessageHeaders headers);   // 对象 → 消息
    Object fromMessage(Message<?> message);                        // 消息 → 对象
}
```

### 常用实现

| 转换器 | 用途 |
|--------|------|
| SimpleMessageConverter | String/字节数组/Serializable |
| Jackson2JsonMessageConverter | JSON 序列化（推荐） |
| MarshallingMessageConverter | XML 序列化 |
| ByteArrayMessageConverter | 字节数组 |

### JSON 消息转换

```java
// RabbitMQ 配置 JSON 转换器
@Configuration
public class RabbitConfig {

    @Bean
    public MessageConverter messageConverter() {
        return new Jackson2JsonMessageConverter();  // 对象 ↔ JSON
    }

    @Bean
    public RabbitTemplate rabbitTemplate(ConnectionFactory factory) {
        RabbitTemplate template = new RabbitTemplate(factory);
        template.setMessageConverter(messageConverter());
        return template;
    }
}
```

```java
// 发送对象，自动 JSON 序列化
@Autowired
private RabbitTemplate rabbitTemplate;

Order order = new Order(1L, "ORD001");
rabbitTemplate.convertAndSend("order.exchange", "order.create", order);
// 接收方自动反序列化为 Order 对象
```

## 消息监听（Listener）

消息监听器接收并处理消息，用注解声明。

### @RabbitListener（RabbitMQ）

```java
@Component
public class OrderListener {

    @RabbitListener(queues = "order.queue")
    public void handleOrder(Order order) {
        // 自动反序列化为 Order 对象
        System.out.println("收到订单：" + order.getOrderNo());
        orderService.process(order);
    }

    // 手动 ACK
    @RabbitListener(queues = "order.queue", ackMode = "MANUAL")
    public void handleWithAck(Order order, Channel channel,
                              @Header(AmqpHeaders.DELIVERY_TAG) long deliveryTag) throws IOException {
        try {
            orderService.process(order);
            channel.basicAck(deliveryTag, false);  // 手动确认
        } catch (Exception e) {
            channel.basicNack(deliveryTag, false, true);  // 拒绝并重新入队
        }
    }
}
```

### @KafkaListener（Kafka）

```java
@Component
public class OrderKafkaListener {

    @KafkaListener(topics = "order-topic", groupId = "order-group")
    public void handleOrder(Order order) {
        System.out.println("收到订单：" + order.getOrderNo());
        orderService.process(order);
    }

    // 批量消费
    @KafkaListener(topics = "order-topic", groupId = "order-group")
    public void handleBatch(List<Order> orders) {
        orders.forEach(orderService::process);
    }
}
```

### 监听器配置要点

```java
// 并发消费
@RabbitListener(queues = "order.queue", concurrency = "5")  // 5 个消费者线程
public void handle(Order order) { ... }

// Kafka 并发
@KafkaListener(topics = "topic", concurrency = "3")
public void handle(Order order) { ... }
```

### 消息消费的可靠性

```text
1. 消息确认（ACK）—— 处理成功才确认
2. 消费失败重试 —— 失败自动重试
3. 死信队列 —— 重试多次仍失败进入死信队列
4. 幂等消费 —— 重复消费不影响业务
```

## Spring 事件机制（Event）

Spring 的事件机制是基于观察者模式的应用内消息传递，与消息中间件互补。

### 事件发布与监听

```java
// 1. 定义事件
public class OrderCreatedEvent extends ApplicationEvent {
    private final Order order;
    public OrderCreatedEvent(Object source, Order order) {
        super(source);
        this.order = order;
    }
    public Order getOrder() { return order; }
}

// 2. 发布事件
@Service
public class OrderService {
    @Autowired
    private ApplicationEventPublisher publisher;

    @Transactional
    public void createOrder(Order order) {
        orderMapper.insert(order);
        publisher.publishEvent(new OrderCreatedEvent(this, order));
    }
}

// 3. 监听事件
@Component
public class OrderEventListener {
    @EventListener
    public void handleOrderCreated(OrderCreatedEvent event) {
        // 发送通知等
        smsService.send(event.getOrder().getUserId(), "订单已创建");
    }
}
```

### 异步事件

```java
@Component
public class AsyncEventListener {
    @Async
    @EventListener
    public void handle(OrderCreatedEvent event) {
        // 异步执行，不阻塞主流程
    }
}
```

### 事务事件

```java
@Component
public class TransactionalEventListener {
    @TransactionalEventListener(phase = TransactionPhase.AFTER_COMMIT)
    public void handle(OrderCreatedEvent event) {
        // 事务提交后执行
        mqProducer.send(event.getOrder());
    }
}
```

### 事件 vs 消息中间件

| 维度 | Spring 事件 | 消息中间件 |
|------|------------|-----------|
| 作用范围 | 应用内（单进程） | 跨应用/跨系统 |
| 持久化 | 无 | 有 |
| 可靠性 | 低（进程挂了就丢） | 高 |
| 适用场景 | 应用内解耦 | 系统间异步通信 |

```text
应用内解耦用 Spring 事件
跨系统通信用消息中间件
两者常组合：Spring 事件 → 事务提交后 → 发消息中间件
```

## 消息中间件选型

### RabbitMQ vs Kafka vs RocketMQ

| 维度 | RabbitMQ | Kafka | RocketMQ |
|------|----------|-------|----------|
| 语言 | Erlang | Java/Scala | Java |
| 吞吐量 | 万级 | 百万级 | 十万级 |
| 消息模型 | Exchange/Queue | Topic/Partition | Topic/Queue |
| 延迟 | 微秒级 | 毫秒级 | 毫秒级 |
| 事务消息 | 不支持 | 不支持 | 支持 |
| 顺序消息 | 部分支持 | 分区内有序 | 支持 |
| 适用场景 | 业务解耦、RPC | 日志、大数据、流处理 | 电商、金融 |

```text
选型建议：
- 业务消息、低延迟 → RabbitMQ
- 高吞吐、日志、流处理 → Kafka
- 电商、事务消息、顺序消息 → RocketMQ
```

## 应用场景实战

### 场景 1：订单创建后异步通知（RabbitMQ）

```java
// 生产者
@Service
public class OrderProducer {
    @Autowired
    private RabbitTemplate rabbitTemplate;

    public void sendOrderCreated(Order order) {
        rabbitTemplate.convertAndSend("order.exchange", "order.created", order);
    }
}

// 消费者
@Component
public class OrderConsumer {

    @RabbitListener(queues = "order.created.queue")
    public void handle(Order order) {
        // 发送短信、更新库存等异步操作
        notificationService.notify(order);
    }
}
```

### 场景 2：应用内事件 + 事务消息

```java
@Service
public class OrderService {
    @Autowired
    private ApplicationEventPublisher publisher;

    @Transactional
    public void createOrder(Order order) {
        orderMapper.insert(order);
        // 发布事件，事务提交后发消息
        publisher.publishEvent(new OrderCreatedEvent(this, order));
    }
}

@Component
public class OrderEventToMq {
    @TransactionalEventListener(phase = TransactionPhase.AFTER_COMMIT)
    public void sendToMq(OrderCreatedEvent event) {
        rabbitTemplate.convertAndSend("order.exchange", "order.created", event.getOrder());
    }
}
```

### 场景 3：消息幂等消费

```java
@Component
public class IdempotentConsumer {

    @Autowired
    private StringRedisTemplate redisTemplate;

    @RabbitListener(queues = "order.queue")
    public void handle(OrderMessage message) {
        // 幂等键：messageId 存 Redis，重复消息直接跳过
        String key = "msg:consumed:" + message.getMessageId();
        Boolean success = redisTemplate.opsForValue()
            .setIfAbsent(key, "1", 24, TimeUnit.HOURS);

        if (Boolean.TRUE.equals(success)) {
            // 首次消费，处理业务
            orderService.process(message);
        } else {
            // 重复消息，跳过
            log.warn("重复消息，跳过：" + message.getMessageId());
        }
    }
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. **消息要带幂等键**。消息中间件可能重复投递，消费者必须幂等。

2. **消息体用 JSON，配置 MessageConverter**。避免默认 JDK 序列化。

3. **消费失败要有重试和死信**。不能简单吞掉异常，否则消息丢失。

4. **消息和业务事务解耦**。用"本地消息表"或"事务消息"保证最终一致，不要跨系统强一致。

5. **应用内解耦用事件，跨系统用中间件**。不要滥用消息中间件做应用内通信。

### 踩坑记录

**坑 1：消息序列化不匹配**

```java
// 生产者用 JSON 转换器，消费者用默认 JDK 转换器
// 消费者反序列化失败：ClassNotFoundException 或类型不匹配
```

生产者和消费者必须用一致的 MessageConverter。

**坑 2：消费者异常吞掉导致消息丢失**

```java
@RabbitListener(queues = "order.queue")
public void handle(Order order) {
    try {
        orderService.process(order);
    } catch (Exception e) {
        log.error("处理失败", e);  // 吞掉异常，消息被 ACK，实际没处理成功
    }
}
```

异常要抛出（让框架重试）或手动 NACK，不能静默吞掉。

**坑 3：没有配置死信队列**

```java
// 消费一直失败，重试耗尽后消息被丢弃
// 需要配置死信队列保存失败消息，人工介入
```

消费失败重试仍失败的消息要进入死信队列，不能丢弃。

**坑 4：@EventListener 同步阻塞主流程**

```java
@EventListener
public void handle(OrderCreatedEvent event) {
    // 同步执行，如果这里耗时（如调外部接口），会阻塞主流程
    externalService.call(event.getOrder());  // 耗时 3 秒
}
```

耗时操作用 @Async 或事务提交后执行，避免阻塞。

**坑 5：消息体过大**

```java
// 消息体几十 MB（如整个文件内容），影响吞吐和内存
rabbitTemplate.convertAndSend("exchange", "key", hugeObject);
```

大对象不要整体进消息，传引用（如文件 URL、ID），消费方按需拉取。

**坑 6：Kafka 消费者组理解错误**

```text
同一个 group 内，一个 partition 只能被一个 consumer 消费
如果 group 内 consumer 数 > partition 数，多余的 consumer 空闲
```

Kafka 的并发度受 partition 数限制，consumer 数不要超过 partition 数。

## 概述

MCP（Model Context Protocol，模型上下文协议）是 Anthropic 提出的开放协议，标准化 LLM 与外部工具、数据源的连接方式。

```text
MCP 解决的问题：
传统：每个 LLM 应用都要单独对接工具/数据源（N 个模型 × M 个工具 = N×M 个集成）
MCP：统一协议，一次实现，处处使用（N + M 个集成）
```

```text
MCP 的类比：
MCP 之于 AI，就像 USB-C 之于设备
统一接口，即插即用
```

```text
MCP 的价值：
1. 标准化 —— 工具/数据源的标准接口
2. 复用 —— MCP Server 一次开发，多个客户端复用
3. 生态 —— 丰富的 MCP Server（数据库、文件、API）
```

## MCP 架构

### 客户端-服务器模型

```text
┌─────────────┐          ┌─────────────┐
│  MCP Client  │  ←协议→  │  MCP Server  │
│（LLM 应用）  │          │（工具/数据源）│
└─────────────┘          └─────────────┘
```

```text
MCP Client（宿主）—— LLM 应用（Claude、Cursor、自研应用）
MCP Server —— 提供工具/资源的服务（数据库、文件、API）
```

### MCP Server 提供的三种能力

```text
1. Tool（工具）—— 可执行的操作（查数据库、调 API）
2. Resource（资源）—— 可读取的数据（文件、文档）
3. Prompt（提示）—— 预定义的提示词模板
```

## MCP Server

MCP Server 是提供工具和资源的服务。

### Server 的实现

```java
// 用 Spring AI 实现 MCP Server
@Configuration
public class McpServerConfig {

    @Bean
    public List<ToolCallback> tools() {
        return List.of(
            ToolCallbacks.from(new WeatherTools())   // 工具
        );
    }
}

// 工具定义
public class WeatherTools {
    @Tool(description = "查询天气")
    public String getWeather(@ToolParam String city) {
        return "北京：晴，25 度";
    }
}
```

### 常见 MCP Server

```text
1. 数据库 Server —— 查询 MySQL/PostgreSQL
2. 文件 Server —— 读写文件
3. 搜索 Server —— 网络搜索
4. GitHub Server —— 仓库操作
5. 自定义 Server —— 业务 API
```

## MCP Client

MCP Client 是使用 MCP Server 的应用。

### Client 的使用

```java
// Spring AI 连接 MCP Server
@Configuration
public class McpClientConfig {

    @Bean
    public McpSyncClient mcpClient() {
        return McpClient.using(transport).sync();
    }

    // 调用工具
    public String callTool() {
        McpSyncClient client = mcpClient();
        CallToolResult result = client.callTool(
            new CallToolRequest("getWeather", Map.of("city", "北京")));
        return result.content();
    }
}
```

### 客户端配置（连接远程 Server）

```yaml
spring:
  ai:
    mcp:
      client:
        stdio:
          servers:
            - command: npx
              args: ["-y", "@modelcontextprotocol/server-filesystem"]
        sse:
          connections:
            - url: http://localhost:8080/sse
```

## MCP 三大能力

### 1. Tool（工具）

```text
Tool = 可执行的操作（LLM 通过 Function Calling 调用）
```

```java
// 定义工具
@Tool(description = "查询数据库")
public List<User> queryUsers(@ToolParam String name) {
    return userService.findByName(name);
}
```

### 2. Resource（资源）

```text
Resource = 可读取的数据（文件、数据库内容）
```

```java
// 提供资源
@Resource(name = "config", description = "配置文件")
public String config() {
    return fileService.readConfig();
}
```

### 3. Prompt（提示）

```text
Prompt = 预定义的提示词模板
```

```java
// 提供提示词模板
@Prompt(name = "code-review", description = "代码审查提示词")
public String codeReviewPrompt() {
    return "你是代码审查专家，审查以下代码的问题：{code}";
}
```

### Tool vs Resource vs Prompt

| 能力 | 作用 | 类比 |
|------|------|------|
| Tool | 执行操作 | 函数（可执行） |
| Resource | 读取数据 | 文件（只读） |
| Prompt | 提示模板 | 模板（复用） |

## Transport 传输

MCP 的传输方式（Client 和 Server 如何通信）。

### 传输方式

```text
1. STDIO —— 标准输入输出（本地进程）
2. SSE —— Server-Sent Events（HTTP 流）
3. Streamable HTTP —— 可流式 HTTP（新）
```

### 传输方式对比

| 传输 | 适用 | 说明 |
|------|------|------|
| STDIO | 本地 | 子进程通信 |
| SSE | 远程 | HTTP + SSE 流 |
| Streamable HTTP | 远程 | 新标准，替代 SSE |

### 传输选择

```text
本地工具（如文件操作）→ STDIO
远程服务（如数据库 API）→ SSE/HTTP
```

## 应用场景实战

### 场景 1：连接数据库 MCP Server

```java
// Client 连接数据库 MCP Server，LLM 可以查数据库
@Configuration
public class DatabaseMcpConfig {

    @Bean
    public McpSyncClient dbMcpClient() {
        // 连接数据库 MCP Server
        return McpClient.using(sseTransport("http://localhost:8081")).sync();
    }
}

// LLM 提问"有哪些活跃用户"，自动调用 MCP 工具查数据库
```

### 场景 2：自研 MCP Server 暴露业务 API

```java
// 业务 MCP Server：把内部 API 暴露给 AI
@Configuration
public class BusinessMcpServer {

    @Bean
    public List<ToolCallback> tools() {
        return List.of(
            ToolCallbacks.from(new OrderTools()),   // 订单工具
            ToolCallbacks.from(new UserTools())     // 用户工具
        );
    }
}

public class OrderTools {
    @Tool(description = "查询订单")
    public Order getOrder(@ToolParam Long orderId) {
        return orderService.getById(orderId);
    }
}
```

### 场景 3：AI 助手集成多个 MCP

```text
AI 助手（Client）连接多个 MCP Server：
- 数据库 Server（查数据）
- 文件 Server（读写文件）
- GitHub Server（代码操作）
- 业务 Server（内部 API）

LLM 自动判断调用哪个 Server 的工具
```

## 最佳实践与踩坑记录

### 最佳实践

1. **工具描述要清晰**。@Tool 的 description 是模型调用的依据。

2. **工具权限最小化**。MCP Server 只暴露必要的工具。

3. **危险操作要鉴权**。MCP Server 要有认证和权限控制。

4. **工具返回精简结果**。避免返回海量数据撑爆上下文。

5. **复用成熟 MCP Server**。数据库、文件等用现成的 Server。

### 踩坑记录

**坑 1：工具描述不清导致误调用**

```java
@Tool(description = "查询")   // 描述不清，模型不知道该不该调用
```

工具描述要具体，说明做什么、参数含义。

**坑 2：STDIO 进程管理**

```text
STDIO 传输的 MCP Server 是子进程，要管理生命周期
```

正确启动和关闭子进程，处理进程崩溃。

**坑 3：SSE 连接断开**

```text
SSE 长连接断开后，客户端要重连
```

客户端实现重连机制。

**坑 4：安全风险**

```text
MCP Server 暴露敏感操作，没有鉴权，被滥用
```

MCP Server 要鉴权、限流、审计。

**坑 5：工具返回过大**

```text
工具返回几万行数据，上下文超限
```

工具返回精简、分页的数据。

**坑 6：版本不兼容**

```text
MCP 协议版本更新，客户端和服务器版本不匹配
```

对齐 MCP 协议版本。

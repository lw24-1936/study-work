## 概述

向量数据库是存储和检索向量的专用数据库，是 RAG 和语义搜索的基础设施。

```text
为什么需要向量数据库：
1. 向量检索 —— 传统数据库不支持向量相似度查询
2. 海量向量 —— 百万/亿级向量的高效检索
3. 相似度计算 —— 余弦相似度、欧氏距离
```

```text
向量数据库的核心能力：
1. 存储 —— 存储向量 + 元数据
2. 检索 —— 相似性搜索（ANN，近似最近邻）
3. 过滤 —— 按元数据过滤
```

## 向量数据库的作用

### 与传统数据库的区别

| 维度 | 传统数据库 | 向量数据库 |
|------|-----------|-----------|
| 数据 | 结构化（数值/文本） | 向量（高维数组） |
| 查询 | 精确匹配 | 相似性搜索 |
| 索引 | B+树 | HNSW/IVF |
| 场景 | 事务 | 语义搜索、RAG |

### 向量检索的应用

```text
1. 语义搜索 —— 找语义相似的内容
2. RAG —— 检索相关文档
3. 推荐 —— 相似内容推荐
4. 图像检索 —— 以图搜图
5. 去重 —— 相似内容去重
```

## Milvus

Milvus 是开源的分布式向量数据库，专为大规模向量检索设计。

### Milvus 特点

```text
1. 分布式 —— 支持亿级向量
2. 高性能 —— 多种索引（HNSW/IVF）
3. 功能全 —— 标量过滤、混合搜索
4. 生态好 —— 集成 Spring AI、LangChain
```

### 部署（Docker）

```bash
docker run -d \
  --name milvus \
  -p 19530:19530 \
  -p 9091:9091 \
  milvusdb/milvus:v2.4.0
```

### Spring AI 集成 Milvus

```xml
<dependency>
    <groupId>org.springframework.ai</groupId>
    <artifactId>spring-ai-milvus-store</artifactId>
</dependency>
```

```yaml
spring:
  ai:
    vectorstore:
      milvus:
        host: localhost
        port: 19530
        collection-name: documents
        embedding-dimension: 1536
```

## pgvector

pgvector 是 PostgreSQL 的向量扩展，在已有 PostgreSQL 上加向量能力。

### pgvector 特点

```text
1. 简单 —— PostgreSQL 插件，不用新数据库
2. 事务 —— 向量和业务数据同库，事务一致
3. 适合中小规模 —— 百万级向量够用
```

### 安装和使用

```sql
-- 安装扩展
CREATE EXTENSION vector;

-- 建表（带向量列）
CREATE TABLE documents (
    id BIGSERIAL PRIMARY KEY,
    content TEXT,
    embedding vector(1536)    -- 1536 维向量
);

-- 插入向量
INSERT INTO documents (content, embedding)
VALUES ('文档内容', '[0.1, 0.2, ...]');

-- 相似性搜索
SELECT id, content
FROM documents
ORDER BY embedding <=> '[0.1, 0.2, ...]'   -- 余弦距离
LIMIT 5;
```

### pgvector 的适用场景

```text
1. 已有 PostgreSQL，不想引入新数据库
2. 中小规模向量（百万级）
3. 向量和业务数据需要事务一致
```

## 选型对比

| 维度 | Milvus | Qdrant | Chroma | pgvector | ES |
|------|--------|--------|--------|----------|-----|
| 规模 | 亿级 | 亿级 | 十万级 | 百万级 | 千万级 |

| 复杂度 | 高 | 中 | 低 | 低 | 中 |

```text
选型建议：
1. 大规模生产 → Milvus
2. 已有 PostgreSQL → pgvector
3. 快速原型 → Chroma
4. 已有 ES → Elasticsearch Vector
5. 高性能 → Qdrant
```

## 应用场景实战

### 场景 1：pgvector 实现语义搜索

```sql
-- 1. 建表
CREATE TABLE articles (
    id SERIAL PRIMARY KEY,
    title TEXT,
    content TEXT,
    embedding vector(1536)
);

-- 2. 创建索引
CREATE INDEX ON articles USING ivfflat (embedding vector_cosine_ops);

-- 3. 相似性搜索
SELECT title, 1 - (embedding <=> '[向量]') AS similarity
FROM articles
ORDER BY embedding <=> '[向量]'
LIMIT 10;
```

### 场景 2：Spring AI + Milvus RAG

```java
@Service
public class RagService {

    @Autowired
    private VectorStore vectorStore;   // Milvus 实现

    public String answer(String question) {
        List<Document> docs = vectorStore.similaritySearch(
            SearchRequest.query(question).withTopK(5));
        // 拼接上下文 + 对话
        return chat(question, docs);
    }
}
```

### 场景 3：混合检索（向量 + 关键词）

```java
// 向量检索 + 元数据过滤
SearchRequest request = SearchRequest.query(question)
```

## 最佳实践与踩坑记录

### 最佳实践

1. **维度统一**。Embedding 模型和向量库维度必须一致。

2. **选择合适的索引**。HNSW（高精度）、IVF（快）。

3. **向量 + 元数据过滤**。先用元数据过滤缩小范围，再向量检索。

4. **批量写入**。向量化批量处理，提升写入性能。

5. **相似度阈值**。设阈值过滤不相关结果。

### 踩坑记录

**坑 1：维度不匹配**

```text
Embedding 模型 1536 维，向量库建表 1024 维，写入报错
```

确认 Embedding 模型输出维度和向量库配置一致。

**坑 2：相似度度量不一致**

```text
用余弦相似度建索引，查询用欧氏距离，结果不准
```

索引和查询的度量方式要一致。

**坑 3：没有索引导致全表扫描**

```text
百万向量没建索引，查询全表扫描，极慢
```

必须建向量索引（HNSW/IVF）。

**坑 4：忽略元数据过滤**

```text
只做向量检索，不按业务过滤，检索到不相关数据
```

向量检索 + 元数据过滤组合使用。

**坑 5：向量库版本兼容**

```text
Milvus 版本升级，客户端 SDK 不兼容
```

版本对齐，或使用兼容的 SDK 版本。

**坑 6：向量更新不同步**

```text
文档更新了，向量库的旧向量没更新，检索到旧内容
```

文档更新时同步更新向量，或定期重建索引。

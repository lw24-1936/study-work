## 集合框架总览

**问题 1：Java 集合框架有哪些？**

```text
Collection
├── List（有序，可重复）
│   ├── ArrayList（数组，随机访问快）
│   ├── LinkedList（双向链表，增删快）
│   ├── Vector（线程安全，全方法 synchronized，已弃用）
│   └── CopyOnWriteArrayList（写时复制，读多写少）
├── Set（无序，不可重复）
│   ├── HashSet（哈希，基于 HashMap）
│   ├── LinkedHashSet（插入有序）
│   ├── TreeSet（排序，基于 TreeMap）
│   └── CopyOnWriteArraySet
└── Queue（队列）
    ├── PriorityQueue（优先级堆）
    ├── ArrayBlockingQueue（有界阻塞）
    └── LinkedBlockingQueue（可选有界阻塞）

Map（键值对）
├── HashMap（哈希，线程不安全）
├── LinkedHashMap（插入/访问有序）
├── TreeMap（key 排序，红黑树）
├── ConcurrentHashMap（线程安全，分段/CAS）
└── Hashtable（线程安全，全表锁，已弃用）
```

## HashMap 高频问题

**问题 1：HashMap 的底层结构？**

```text
JDK 7：数组 + 链表（头插法）
JDK 8：数组 + 链表 + 红黑树

链表长度 >= 8 且数组长度 >= 64 时，链表转红黑树；
红黑树节点数 <= 6 时，退化为链表。
```

```text
为什么阈值是 8：
哈希冲突概率服从泊松分布，链表长度达到 8 的概率约为千万分之六（0.00000006），
再往后性能下降明显，转红黑树（O(n) → O(log n)）才划算。
退化阈值用 6 而非 8，留 2 个的缓冲，避免频繁转换。
```

**问题 2：HashMap 的 put 流程？**

```text
1. 计算 hash：key.hashCode() ^ (key.hashCode() >>> 16)（高 16 位参与运算，减少碰撞）
2. 计算索引：(n - 1) & hash
3. 该位置为空 → 直接放入
4. 有值 → 判断 key 是否相等（hash 相等且 equals 相等）→ 相等则覆盖 value
5. 不相等 → 链表尾插 / 红黑树插入
6. size > 阈值（容量 × 负载因子 0.75）→ 扩容 2 倍
```

**问题 3：HashMap 的扩容机制？**

```text
1. 默认初始容量 16，负载因子 0.75
2. 达到 16 × 0.75 = 12 时触发扩容，扩容为 2 倍
3. 扩容时 rehash：JDK 8 用高位判断，元素要么留在原索引，要么移到原索引 + 旧容量
```

```text
负载因子为什么是 0.75：
太大（1.0）→ 哈希冲突多，链表/红黑树长，查询慢
太小（0.5）→ 空间浪费，频繁扩容
0.75 是时间与空间的折中。
```

**问题 4：HashMap 为什么容量是 2 的幂？**

```text
1. 索引计算用位运算 (n - 1) & hash，比 % 快
2. n 是 2 的幂，n - 1 二进制全 1，(n-1) & hash 等价于 hash % n 且分布均匀
3. 扩容 2 倍后，rehash 时只需判断新增的一位，元素要么不动要么平移
```

**问题 5：JDK 7 的 HashMap 为什么死循环？**

```text
JDK 7 扩容用头插法（新元素插链表头部），并发扩容时链表可能成环：
线程 A、B 同时扩容，头插法导致节点的 next 指针互相指向，形成环，
后续 get/put 遍历链表时死循环（CPU 100%）。

JDK 8 改为尾插法解决死循环，但并发 put 仍可能丢数据，仍不能并发用。
```

**问题 6：HashMap 和 Hashtable 的区别？**

| 维度 | HashMap | Hashtable |
|------|---------|-----------|
| 线程安全 | 否 | 是（全方法 synchronized） |
| null | 允许 null key/value | 不允许 |
| 性能 | 高 | 低（全表锁） |
| 初始容量 | 16，扩容 2 倍 | 11，扩容 2n+1 |
| 现状 | 主流 | 已弃用，用 ConcurrentHashMap 替代 |

## ConcurrentHashMap

**问题 1：ConcurrentHashMap 如何保证线程安全？**

```text
JDK 7 —— 分段锁（Segment 数组，每段一把 ReentrantLock），锁一段而非整表。
JDK 8 —— CAS + synchronized：
1. 空桶 → CAS 无锁放入（tabAt/casTabAt）
2. 有值 → synchronized 锁桶头节点（细粒度锁）
3. 读操作无锁（volatile 保证可见性）
4. 扩容时可多线程协作（transfer）
```

**问题 2：ConcurrentHashMap 为什么高效？**

```text
1. 锁粒度细 —— 锁单个桶节点，不是整表
2. CAS 无锁 —— 空桶直接 CAS 放入
3. 读无锁 —— Node 的 val/next 用 volatile，读不加锁
4. 并发扩容 —— 多线程协助迁移
```

**问题 3：ConcurrentHashMap 的 size() 如何计算？**

```text
JDK 8 用 baseCount + CounterCell[] 分段计数：
1. 优先 CAS 更新 baseCount
2. CAS 失败 → 写入 CounterCell 数组某格
3. size() = baseCount + 所有 CounterCell 之和（不精确，求和时并发可能少算）
```

**问题 4：ConcurrentHashMap 为什么不允许 null key/value？**

```text
并发场景下 null 有歧义：
get(key) 返回 null，无法区分是"key 不存在"还是"value 就是 null"。
HashMap 非并发，可用 containsKey 二次判断，ConcurrentHashMap 为了消除二义性直接禁止 null。
```

## ArrayList 与 LinkedList

**问题 1：ArrayList 和 LinkedList 的区别？**

| 维度 | ArrayList | LinkedList |
|------|-----------|------------|
| 底层 | 数组 | 双向链表 |
| 随机访问 | O(1) | O(n) |
| 头插/删除 | O(n) | O(1) |
| 尾插 | O(1) 均摊 | O(1) |
| 内存 | 连续，缓存友好 | 分散，节点有前后指针开销 |
| 实现了 | RandomAccess | Deque（可当队列/栈） |

```text
使用建议：
默认用 ArrayList（大多数场景随机访问多）。
LinkedList 只有在频繁头插/删除、或需要当队列栈用时才考虑，实际很少用。
```

**问题 2：ArrayList 的扩容机制？**

```text
1. 无参构造默认容量 10（JDK 8 是空数组，首次 add 才扩容到 10）
2. 扩容为 1.5 倍：oldCapacity + (oldCapacity >> 1)
3. 扩容用 Arrays.copyOf（底层 System.arraycopy），涉及数组复制，代价高
4. 建议已知大小时预分配：new ArrayList<>(n)
```

**问题 3：ArrayList 为什么用 RandomAccess 接口？**

```text
RandomAccess 是标记接口，表示支持快速随机访问（O(1)）。
遍历时 instanceof RandomAccess 判断：
支持 → 用 for 循环下标遍历（快）
不支持（如 LinkedList）→ 用迭代器遍历
```

## HashSet 与 TreeMap

**问题 1：HashSet 的底层实现？**

```text
HashSet 底层是 HashMap：
1. 元素作为 HashMap 的 key
2. value 固定为一个 Object 常量（PRESENT）
3. 利用 HashMap 的 key 唯一性去重

所以 HashSet 的去重依赖元素的 equals + hashCode，重写不完整会导致重复元素。
```

**问题 2：TreeMap 和 HashMap 的区别？**

| 维度 | TreeMap | HashMap |
|------|---------|---------|
| 底层 | 红黑树 | 哈希表（数组+链表+红黑树） |
| 有序性 | 按 key 自然序或比较器排序 | 无序 |
| 复杂度 | O(log n) | O(1) |
| null key | 不允许（要比较） | 允许 |

**问题 3：TreeSet 的底层？**

```text
TreeSet 底层是 TreeMap（NavigableMap），元素作 key，PRESENT 作 value。
TreeSet 要求元素可比较（实现 Comparable 或构造时传 Comparator），否则抛 ClassCastException。
```

## LinkedHashMap 与 LRU

**问题 1：LinkedHashMap 如何实现有序？**

```text
LinkedHashMap 继承 HashMap，额外维护双向链表记录插入顺序：
1. accessOrder = false（默认）→ 按插入顺序
2. accessOrder = true → 按访问顺序（LRU）
```

**问题 2：如何用 LinkedHashMap 实现 LRU 缓存？**

```java
// 继承 LinkedHashMap，重写 removeEldestEntry
class LRUCache<K, V> extends LinkedHashMap<K, V> {
    private final int capacity;

    LRUCache(int capacity) {
        super(capacity, 0.75f, true);   // accessOrder = true
        this.capacity = capacity;
    }

    @Override
    protected boolean removeEldestEntry(Map.Entry<K, V> eldest) {
        return size() > capacity;        // 超过容量淘汰最久未访问
    }
}
```

## fail-fast 与 fail-safe

**问题：fail-fast 和 fail-safe 的区别？**

```text
fail-fast（快速失败）：
遍历集合时，其他线程（或自身）修改集合结构 → 抛 ConcurrentModificationException。
原理：迭代器持有 expectedModCount，集合 modCount 变化则抛异常。
代表：ArrayList、HashMap 的迭代器。

fail-safe（安全失败）：
遍历的是副本，修改不影响遍历，不抛异常，但遍历的是旧数据。
代表：CopyOnWriteArrayList、ConcurrentHashMap 的迭代器。
```

```text
增强 for 循环本质是迭代器遍历，遍历中 list.remove() 会触发 fail-fast。
正确删除方式：迭代器的 remove()，或遍历时先收集再统一删除。
```

## CopyOnWriteArrayList

**问题：CopyOnWriteArrayList 的原理？**

```text
写时复制（Copy-On-Write）：
1. 读操作无锁，直接读原数组
2. 写操作（add/set/remove）→ 加 ReentrantLock → 复制新数组 → 修改 → 替换引用
3. 写不阻塞读，读读共享，读写分离
```

```text
适用场景：读多写少的场景（如监听器列表、配置缓存）。
缺点：写要复制整个数组，内存开销大、写性能差；读到的可能是一致性旧数据。
```

## Queue 队列

**问题：Queue 和阻塞队列的区别？**

```text
Queue 接口：普通队列（offer/poll/peek，非阻塞）。

BlockingQueue（阻塞队列）：
1. put/take —— 阻塞（队列满 put 阻塞，队列空 take 阻塞）
2. offer/poll 带超时 —— 定时阻塞
3. 生产者消费者模型的基石（线程池任务队列）
```

```text
常见阻塞队列：
ArrayBlockingQueue —— 有界数组，公平/非公平锁可选
LinkedBlockingQueue —— 可选有界链表，默认 Integer.MAX_VALUE（无界风险）
SynchronousQueue —— 无容量，put 必须等 take（直接交接）
DelayQueue —— 延迟队列（元素到期才能取出）
PriorityBlockingQueue —— 无界优先级队列
```

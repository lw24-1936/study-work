## 索引与 B+Tree

**问题 1：为什么用 B+Tree 不用 B-Tree？**

```text
B+Tree 的优势：
1. 非叶子节点只存索引（不存数据），一页存更多索引，树更矮
2. 叶子节点用链表连接，范围查询快
3. 查询稳定（数据都在叶子节点）
```

```text
B+Tree 的特点：
1. 数据都存在叶子节点
2. 叶子节点有序 + 链表连接
3. 树矮（3-4 层存千万数据）
```

**问题 2：聚簇索引和非聚簇索引？**

```text
聚簇索引（主键索引）—— 叶子节点存完整数据行
非聚簇索引（二级索引）—— 叶子节点存主键值

查询流程：
非聚簇索引 → 找到主键 → 回表 → 聚簇索引找完整数据
```

**问题 3：什么是回表？如何避免？**

```text
回表：二级索引查到主键，再查聚簇索引（多一次 IO）

避免回表：覆盖索引（查询字段都在索引里）
```

**问题 4：索引失效的场景？**

```text
1. 索引列用函数（WHERE DATE(create_time) = ...）
2. 隐式类型转换（varchar 用数字比较）
3. LIKE 前缀模糊（LIKE '%xx'）
4. OR 条件（部分列无索引）
5. 联合索引违反最左前缀
```

**问题 5：联合索引的最左前缀原则？**

```text
联合索引 (a, b, c)：
命中：WHERE a、WHERE a AND b、WHERE a AND b AND c
失效：WHERE b（跳过 a）
```

## MVCC

**问题 1：什么是 MVCC？**

```text
MVCC（多版本并发控制）：
1. 每条记录有多个版本
2. 通过版本号（隐藏列）实现
3. 读操作不加锁，读到一致快照
4. 实现读不阻塞写
```

```text
MVCC 的实现依赖：
1. 隐藏列（DB_TRX_ID 事务 ID、DB_ROLL_PTR 回滚指针）
2. undo log（记录旧版本）
3. Read View（可见性判断）
```

**问题 2：MVCC 解决什么问题？**

```text
1. 读不阻塞写（快照读）
2. 解决脏读、不可重复读（RR 隔离级别）
3. 提高并发（读不加锁）
```

## 事务

**问题 1：事务的 ACID？**

```text
A（Atomicity）原子性 —— 要么全成功，要么全失败
C（Consistency）一致性 —— 数据保持一致
I（Isolation）隔离性 —— 事务隔离
D（Durability）持久性 —— 提交后永久保存
```

**问题 2：隔离级别？**

```text
1. 读未提交（Read Uncommitted）—— 脏读
2. 读已提交（Read Committed）—— 不可重复读
3. 可重复读（Repeatable Read）—— 默认，幻读（MySQL 已解决）
4. 串行化（Serializable）—— 全部解决，性能差
```

**问题 3：脏读、不可重复读、幻读？**

```text
脏读 —— 读到未提交的数据
不可重复读 —— 同一事务两次读结果不同（其他事务修改）
幻读 —— 同一事务两次查询行数不同（其他事务插入）
```

## 锁

**问题 1：MySQL 的锁类型？**

```text
按粒度：
1. 表锁 —— 锁整张表
2. 行锁 —— 锁行（InnoDB 默认）
3. 间隙锁 —— 锁范围（防幻读）

按模式：
1. 共享锁（S）—— 读锁
2. 排他锁（X）—— 写锁
```

**问题 2：乐观锁和悲观锁？**

```text
悲观锁 —— 认为会冲突，先加锁（SELECT FOR UPDATE）
乐观锁 —— 认为不冲突，更新时检查（版本号 CAS）
```

**问题 3：死锁如何避免？**

```text
1. 按固定顺序加锁
2. 减少锁粒度（缩小事务范围）
3. 使用乐观锁
```

## SQL 优化

**问题 1：如何定位慢 SQL？**

```text
1. 开启慢查询日志（long_query_time = 1）
2. 找到慢 SQL
3. EXPLAIN 分析执行计划
4. 优化（加索引、改写 SQL）
```

**问题 2：EXPLAIN 关注什么？**

```text
type —— 访问类型（const > ref > range > index > ALL）
key —— 实际使用的索引
rows —— 扫描行数
Extra —— Using index（覆盖索引）/ Using filesort（需优化）
```

**问题 3：SQL 优化的常见手段？**

```text
1. 避免 SELECT *（覆盖索引）
2. 索引列不做运算（函数、隐式转换）
3. 深分页用 id 定位
4. 避免 OR（用 UNION）
5. 批量操作（批量插入）
```

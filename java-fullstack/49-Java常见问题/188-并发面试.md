## synchronized

**问题 1：synchronized 的原理？**

```text
synchronized 基于对象的 monitor（监视器）：
1. 加锁 → 获取对象的 monitor
2. 同一时刻只有一个线程持有 monitor
3. 释放锁 → 释放 monitor
```

**问题 2：synchronized 的锁升级？**

```text
锁升级过程（JDK 6 优化）：
无锁 → 偏向锁 → 轻量级锁（CAS）→ 重量级锁（monitor）

1. 偏向锁 —— 单线程，标记线程 ID
2. 轻量级锁 —— 竞争不激烈，CAS 自旋
3. 重量级锁 —— 竞争激烈，阻塞（操作系统互斥量）
```

**问题 3：synchronized 的用法？**

```java
// 1. 修饰方法（锁 this）
public synchronized void method() { ... }

// 2. 修饰代码块（锁指定对象）
synchronized (obj) { ... }

// 3. 修饰静态方法（锁 Class 对象）
public static synchronized void method() { ... }
```

## volatile

**问题：volatile 的作用？**

```text
volatile 保证：
1. 可见性 —— 修改对其他线程立即可见（禁缓存）
2. 有序性 —— 禁止指令重排（内存屏障）

不保证：
1. 原子性 —— 复合操作（i++）不安全
```

```java
volatile boolean flag = true;

// 线程 A 修改 flag，线程 B 立即可见（可见性）
// 单例双重检查锁的 instance 用 volatile（禁止重排）
```

```text
volatile 的应用：
1. 状态标志（flag）
2. 双重检查锁单例（禁止指令重排）
```

## CAS 与 AQS

**问题 1：CAS 是什么？**

```text
CAS（Compare And Swap）比较并交换：
1. 读取当前值
2. 比较是否等于预期值
3. 相等则更新，不等则重试
```

```text
CAS 的优缺点：
优点 —— 无锁，高性能
缺点 —— ABA 问题、自旋开销
```

**问题 2：AQS 是什么？**

```text
AQS（AbstractQueuedSynchronizer）是并发框架的基石：
1. 用 state（int）表示锁状态
2. 用队列管理等待线程
3. ReentrantLock、CountDownLatch、Semaphore 都基于 AQS
```

## Lock 与 synchronized

**问题：ReentrantLock 和 synchronized 的区别？**

| 维度 | synchronized | ReentrantLock |
|------|-------------|---------------|
| 加锁方式 | 自动 | 手动（lock/unlock） |
| 公平锁 | 非公平 | 支持公平/非公平 |
| 可中断 | 不可 | 可中断（lockInterruptibly） |
| Condition | 单个（wait/notify） | 多个 Condition |
| 原理 | monitor | AQS |

```java
ReentrantLock lock = new ReentrantLock();
lock.lock();
try {
    // 临界区
} finally {
    lock.unlock();
}
```

## ThreadPoolExecutor

**问题 1：线程池的 7 个参数？**

```java
new ThreadPoolExecutor(
    corePoolSize,      // 核心线程数
    maximumPoolSize,   // 最大线程数
    keepAliveTime,     // 空闲存活时间
    unit,              // 时间单位
    workQueue,         // 任务队列
    threadFactory,     // 线程工厂
    handler);          // 拒绝策略
```

**问题 2：线程池的执行流程？**

```text
1. 核心线程数 < corePoolSize → 创建新线程
2. 核心线程满 → 放入队列
3. 队列满 → 创建新线程（到 maximumPoolSize）
4. 线程也满 → 拒绝策略
```

**问题 3：拒绝策略有哪些？**

```text
1. AbortPolicy —— 抛异常（默认）
2. CallerRunsPolicy —— 调用者执行
3. DiscardPolicy —— 丢弃
4. DiscardOldestPolicy —— 丢弃最旧的
```

**问题 4：线程池参数如何设置？**

```text
CPU 密集 → 核心线程 = CPU 核数 + 1
IO 密集 → 核心线程 = CPU 核数 × 2
```

## CompletableFuture

**问题：CompletableFuture 的作用？**

```text
CompletableFuture 是异步编程工具：
1. 异步执行 —— supplyAsync
2. 链式回调 —— thenApply/thenAccept
3. 异常处理 —— exceptionally
4. 组合 —— allOf/anyOf
```

```java
CompletableFuture.supplyAsync(() -> fetchData())
    .thenApply(data -> process(data))
    .thenAccept(result -> save(result))
    .exceptionally(e -> handleError(e));
```

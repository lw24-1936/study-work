## 数据结构

**问题 1：Redis 有哪些数据类型？**

```text
1. String —— 字符串（最基础）
2. List —— 列表（队列、栈）
3. Set —— 集合（去重）
4. Hash —— 哈希（对象）
5. ZSet —— 有序集合（排行榜）

扩展：
6. Bitmap —— 位图（签到）
7. HyperLogLog —— 基数统计（UV）
8. Geo —— 地理位置
```

**问题 2：各数据类型的应用场景？**

```text
String —— 缓存、计数器、分布式锁
List —— 消息队列、最新列表
Set —— 去重、共同好友
Hash —— 对象存储
ZSet —— 排行榜、延迟队列
```

**问题 3：Redis 为什么快？**

```text
1. 内存操作 —— 数据在内存
2. 单线程 —— 无锁竞争（6.0 后多线程处理网络 IO）
3. IO 多路复用 —— 一个线程处理多个连接
4. 高效数据结构 —— 跳表、压缩列表
```

## 持久化

**问题 1：RDB 和 AOF 的区别？**

| 维度 | RDB | AOF |
|------|-----|-----|
| 原理 | 快照（全量） | 追加写命令（增量） |
| 文件 | dump.rdb | appendonly.aof |
| 恢复 | 快（快照） | 慢（重放命令） |
| 数据丢失 | 可能丢最近数据 | 更少（每秒写） |
| 性能 | 高 | 较低 |

**问题 2：持久化策略？**

```text
1. 只用 RDB —— 恢复快，可能丢数据
2. 只用 AOF —— 数据安全，性能较低
3. 混合持久化（RDB + AOF，Redis 4.0+，推荐）
```

## 缓存问题

**问题 1：缓存穿透、击穿、雪崩？**

```text
1. 穿透 —— 查不存在的数据（每次都打数据库）
   解决：布隆过滤器、缓存空值

2. 击穿 —— 热点 key 过期（大量请求打数据库）
   解决：互斥锁、热点 key 永不过期

3. 雪崩 —— 大量 key 同时过期（数据库被打垮）
   解决：随机过期时间、多级缓存
```

**问题 2：缓存和数据库的一致性？**

```text
Cache Aside 模式：
1. 读：先查缓存，未命中查数据库，写缓存
2. 写：先更新数据库，再删缓存

为什么删缓存不更新缓存：删除简单，更新可能并发覆盖
```

**问题 3：缓存更新策略？**

```text
1. Cache Aside（旁路）—— 最常用
2. Read Through —— 读时自动加载
3. Write Through —— 写时同步更新
4. Write Behind —— 写时异步更新
```

## 分布式锁

**问题 1：Redis 分布式锁的实现？**

```text
用 SET NX PX 实现：
SET lock:key value NX PX 10000

1. NX —— 不存在才设置（获取锁）
2. PX —— 过期时间（防死锁）
3. 解锁用 Lua 脚本（原子性 + 校验 value）
```

```text
注意：手写 Redis 锁的问题：
1. 不可重入
2. 不可续期（业务超时锁过期）
3. 主从切换可能丢锁

推荐用 Redisson（可重入 + 看门狗续期）
```

**问题 2：Redisson 的看门狗机制？**

```text
看门狗：自动续期锁的过期时间
1. 获取锁后启动看门狗
2. 定期（默认每 10 秒）续期
3. 业务执行完释放锁，看门狗停止
```

## 集群

**问题 1：Redis 的集群方案？**

```text
1. 主从复制 —— 读写分离，主写从读
2. Sentinel 哨兵 —— 高可用（自动故障转移）
3. Cluster 集群 —— 分片（数据分布到多节点）
```

**问题 2：Redis Cluster 的分片？**

```text
1. 16384 个槽（slot）
2. 每个节点负责一部分槽
3. key 通过 CRC16(key) % 16384 计算槽
4. 相同 hash tag 的 key 在同一槽
```

**问题 3：主从 + 哨兵 + 集群的区别？**

```text
主从复制 —— 数据冗余（读写分离）
哨兵 —— 高可用（自动故障转移，无分片）
集群 —— 分片 + 高可用（数据分布 + 故障转移）
```

## Java 是什么

Java 是一门**编译型 + 解释型**的面向对象语言。代码先由 `javac` 编译成 `.class` 字节码，再由各平台的 JVM 解释执行——"一次编译，到处运行"靠的就是这个中间层。

三句话定位：

- **语言层面**：静态类型、强类型、面向对象，语法继承了 C/C++ 但去掉了指针和手动内存管理
- **平台层面**：JVM 生态——任何能编译成 class 字节码的语言（Kotlin、Scala、Groovy）都能跑在 JVM 上
- **生态层面**：企业级后端的事实标准。Spring 全家桶、Hadoop 生态、Android 开发都以 Java/JVM 为基础

## 发展历史

| 时间 | 版本 | 关键事件 |
|------|------|----------|
| 1995 | Java 1.0 | Sun 发布，Applet + AWT |
| 1998 | Java 1.2 | 集合框架、Swing，更名为 Java 2 |
| 2004 | Java 5 | 泛型、注解、枚举、自动装箱——Java 近代化的起点 |
| 2006 | Java 6 | 性能提升、脚本语言支持 |
| 2011 | Java 7 | try-with-resources、NIO.2、invokedynamic |
| 2014 | Java 8 | **Lambda + Stream + Optional + 新日期API**——至今使用最广的版本 |
| 2017 | Java 9 | 模块系统（Project Jigsaw）、JShell |
| 2018 | Java 10 | var 局部变量类型推断 |
| 2018 | Java 11 | **首个 LTS**，HTTP Client API，ZGC |
| 2021 | Java 17 | **LTS**，密封类、Pattern Matching for switch（预览） |
| 2023 | Java 21 | **LTS**，虚拟线程、Record Patterns、Pattern Matching 正式 |
| 2025 | Java 25 | LTS，流收集器、作用域值、结构化并发（第三次预览） |

> Java 从 2017 年起改为半年一个大版本，每年 3 月和 9 月发布。偶数年 9 月（11/17/21/25）发布 LTS 版本。

## 核心特点

**跨平台**
JVM 屏蔽了底层差异。同一份 `.class` 在 Windows/Linux/macOS 上行为一致——前提是不碰平台相关的本地代码（JNI）和文件路径分隔符。

**自动内存管理**
没有 `malloc/free`，没有指针运算。JVM 的 GC 自动回收不再使用的对象。开发者关注业务逻辑，不用追踪内存泄漏——虽然堆外内存和 ThreadLocal 泄漏依然是常见的坑。

**强类型 + 静态类型**
编译期检查类型安全，运行时不会出现"把一个字符串当成数字算"的情况。代价是代码量比动态语言大，但 IDE 的智能提示和重构能力无可替代。

**OOP 纯度**
Java 强制面向对象——所有代码必须在类里（除了接口的 static 方法和 21+ 的 unnamed class）。封装、继承、多态是写 Java 的基本思维框架。

**丰富的标准库**
`java.lang`、`java.util`、`java.io`、`java.nio`、`java.sql`、`java.net`、`java.time`、`java.util.concurrent`——标准库覆盖了数据结构、IO、网络、并发、日期处理等核心需求，不需要引入第三方依赖。

**庞大的生态**
Maven 中央仓库有 1000 万+ 构件。Spring、Hibernate、Netty、Kafka、Elasticsearch、Hadoop——Java 生态的深度和广度在服务端没有对手。

## Java SE / Java EE / Jakarta EE

容易搞混的三个名词：

- **Java SE（Standard Edition）**：Java 标准版，包含基础 API——`java.lang`、`java.util`、JDBC、Swing 等。你装 JDK 就带了。
- **Java EE（Enterprise Edition）**：在 SE 之上加了企业级规范——Servlet、JPA、EJB、JMS 等。**Java EE 本身只是一套规范/接口**，具体实现由应用服务器提供（Tomcat 实现了 Servlet，Hibernate 实现了 JPA）。
- **Jakarta EE**：2017 年 Oracle 把 Java EE 捐给了 Eclipse 基金会，因为 Oracle 不放开 "Java" 商标，改名叫 Jakarta EE。功能向后兼容，但包名从 `javax.*` 变成了 `jakarta.*`。

迁移要点：如果你的项目从 Java EE 8 升级到 Jakarta EE 9+，需要全局替换 `javax.*` → `jakarta.*`。Spring Boot 3.x 已经全面切换到 Jakarta EE 9。

## OpenJDK vs Oracle JDK

| 维度 | OpenJDK | Oracle JDK |
|------|---------|------------|
| 开源 | 完全开源（GPLv2+CE） | 商用需要付费（Java 11+） |
| 维护者 | 社区/Oracle | Oracle |
| 功能 | 两者代码几乎一致 | 曾经多了一些商业特性（Flight Recorder 等），11+ 已捐赠给 OpenJDK |
| 用途 | 开发/生产均可 | 开发免费，生产需要付费订阅 |
| 推荐 | 推荐 | 不推荐，除非买了 Oracle 支持 |

> 结论：绝大多数场景用 OpenJDK 发行版就行。企业常用：Adoptium（Eclipse Temurin）、Amazon Corretto、Azul Zulu、Alibaba Dragonwell。

## JDK / JRE / JVM 的关系

```
┌─────────────────────────────────┐
│              JDK                │
│  ┌──────────┐  ┌────────────┐   │
│  │  JRE     │  │ 开发工具   │   │
│  │ ┌──────┐ │  │ javac      │   │
│  │ │ JVM  │ │  │ java       │   │
│  │ └──────┘ │  │ jar        │   │
│  │ 核心类库  │  │ javadoc    │   │
│  └──────────┘  └────────────┘   │
└─────────────────────────────────┘
```

- **JVM**：Java 虚拟机，执行字节码。负责类加载、内存管理、GC、线程调度、JIT 编译
- **JRE**：JVM + 核心类库（rt.jar / modules），能运行 Java 程序但不能编译
- **JDK**：JRE + 开发工具（javac、jar、javadoc、jdb 等），开发必备

Java 11 开始 Oracle 不再单独发布 JRE，直接用 JDK 的 `jlink` 按需裁剪运行时。

## LTS 版本演进

Java 8、11、17、21、25 是 LTS（长期支持）版本，企业选型基本上在这几个里面选。

**Java 8（2014）**
Lambda + Stream + Optional + 新日期 API。生态成熟度最高，大量存量系统还在用。问题是 Java 8 已经停止免费更新（需要付费订阅才能获取安全补丁）。

**Java 11（2018）**
模块系统（jlink 裁剪运行时）、HTTP Client API、ZGC（低延迟 GC）、TLS 1.3。容器感知能力增强——JVM 能读 cgroup 限制来设置堆大小，在 Docker/K8s 里不会因为宿主机的内存而误判。

**Java 17（2021）**
密封类、Pattern Matching for switch（预览）、增强的伪随机数生成器、强封装 JDK 内部 API。Spring Boot 3.x 的最低要求就是 17。目前是新项目的首选 LTS。

**Java 21（2023）**
**虚拟线程（Virtual Threads）**——这是自 Lambda 以来最大的变化。一个虚拟线程占几百字节而不是 1MB 栈空间，能跑上百万并发。Record Patterns、Pattern Matching for switch 正式版、Sequenced Collections、Scoped Values。并发编程的思维模型从"线程池+异步回调"转向"同步写法+虚拟线程"。

**Java 25（2025）**
流收集器（Stream Gatherers）正式版、作用域值（Scoped Values，ThreadLocal 的现代替代品）、结构化并发第三次预览。少量新特性但都很精准。

## 版本选择建议

| 场景 | 推荐版本 | 理由 |
|------|----------|------|
| 存量系统维护 | Java 8 | 不折腾，保持稳定 |
| 新项目（保守） | Java 17 | LTS，Spring Boot 3 最低要求，生态成熟 |
| 新项目（激进） | Java 21 | 虚拟线程是质的飞跃，21 的生态已基本跟上 |
| 尝鲜/个人项目 | Java 25 | 最新 LTS，特性最全 |

> 实在拿不准：**选 Java 17**。如果团队想用虚拟线程：**选 Java 21**。

生产环境 JDK 发行版选 Adoptium（Eclipse Temurin）或 Amazon Corretto——免费、有社区支持、不踩 Oracle 的授权坑。

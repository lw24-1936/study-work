## IDE 选型

Java 开发有三款主流 IDE：

| IDE | 定位 | 适用场景 |
|-----|------|----------|
| IntelliJ IDEA | 商业级全功能 IDE | Java/Kotlin 主力开发，Community 版免费够用 |
| Eclipse | 老牌开源 IDE | 遗留项目维护，IBM 系技术栈 |
| VS Code | 轻量编辑器 + 插件 | 多语言项目、前端+后端混编、快速编辑 |

结论放前面：**用 IntelliJ IDEA**。Community 版（免费）已经足够日常开发，Ultimate 版（付费）多了 Spring、数据库工具、JS/TS 支持。Eclipse 除非接手历史项目没必要从头学，VS Code 作为轻量补充——改个配置文件、看个 JSON 不用开 IDEA。

## IntelliJ IDEA

### 安装

```bash
# JetBrains Toolbox（推荐，自动管理版本和更新）
# https://www.jetbrains.com/toolbox-app/

# 或者用包管理器
# macOS
brew install --cask intellij-idea

# Ubuntu
sudo snap install intellij-idea-community --classic
```

### 关键配置

安装后建议改的几项：

**Editor → General → Auto Import**
- `Add unambiguous imports on the fly` — 勾上，自动导包
- `Optimize imports on the fly` — 勾上，自动删除无用 import

**Editor → Code Style → Java**
- Imports 标签里把 `Class count to use import with '*'` 改成 999，`Names count to use static import with '*'` 也改成 999——避免自动把 import 折叠成 `java.util.*`

**Editor → File Encodings**
- Global Encoding / Project Encoding 都设成 `UTF-8`
- 勾上 `Transparent native-to-ascii conversion`（让 properties 文件的中文正常显示）

**Build, Execution, Deployment → Compiler**
- 勾上 `Build project automatically`（和 Spring DevTools 配合实现热更新）

### 推荐插件

| 插件 | 用途 |
|------|------|
| Lombok | 注解自动生成 getter/setter，几乎所有 Spring 项目都依赖它 |
| MyBatisX | MyBatis Mapper 和 XML 之间跳转 |
| Maven Helper | 依赖冲突分析、一键排除 |
| SonarLint | 实时代码质量检查 |
| GitToolBox | 行内显示 git blame，状态栏更丰富 |
| String Manipulation | 文本大小写/蛇形/驼峰互转 |
| Key Promoter X | 每次点鼠标时弹出对应快捷键提示，帮助养成键盘习惯 |

## VS Code

作为 IDEA 的轻量补充。以下插件组合能让 VS Code 接近 IDE 体验：

```bash
# Extension Pack for Java（包含 6 个核心插件）
code --install-extension vscjava.vscode-java-pack

# Spring Boot 支持
code --install-extension vmware.vscode-spring-boot
code --install-extension vscjava.vscode-spring-initializr
```

适用场景：多语言项目（Go + Python + Java 混编）、微服务快速查看、简单脚本编辑。主力开发还是回 IDEA。

## IDEA 项目结构

IDEA 的核心配置文件：

```
project-root/
├── .idea/                    # IDEA 项目配置（平台相关，不进 git）
│   ├── workspace.xml         # 窗口布局、打开的文件
│   ├── modules.xml           # 模块定义
│   └── misc.xml              # 杂项配置
├── *.iml                     # 模块文件（每个模块一个）
└── pom.xml / build.gradle    # 真正的项目构建定义
```

> `.gitignore` 里应该加 `.idea/` 和 `*.iml`，但保留 `.idea/codeStyles/` 和 `.idea/runConfigurations/`——代码风格和启动配置团队共享才有意义。

IDEA 的"项目"（Project）对应 Maven 的多模块根项目，"模块"（Module）对应 Maven 的子模块。一个窗口一个 Project，不要在一个窗口里打开多个不相关的项目——切换 Project 用 `File → Open Recent`。

## Debug 调试

### 基础调试流程

1. 在行号右侧单击，出现红点（断点）
2. 按 `Ctrl + D`（或点虫子图标）以 Debug 模式启动
3. 程序停在断点处，查看变量值
4. 使用 Debug 面板控制执行

### Debug 面板按钮

按从左到右的顺序：

| 按钮 | 作用 |
|------|------|
| Step Over (`F8`) | 执行当前行，不进入方法内部 |
| Step Into (`F7`) | 进入方法内部 |
| Force Step Into | 强制进入（即使是 JDK 源码或第三方库） |
| Step Out (`Shift + F8`) | 跳出当前方法，回到调用处 |
| Drop Frame | 回退到上一个栈帧（重新执行当前方法） |
| Resume (`F9`) | 继续执行到下一个断点 |

### 断点技巧

**条件断点**
右键断点 → 输入条件表达式。例如 `user.getId() == 1001`——只在 user id 为 1001 时停下，不用在循环里手动点几百次。

**异常断点**
`Run → View Breakpoints → Java Exception Breakpoints`。添加 `NullPointerException`——任何地方抛出 NPE 都会自动停在抛出行，不用提前设断点。

**字段断点**
在字段声明行设断点，右键选择 `Field access` 或 `Field modification`——读/写该字段时自动停下。排查"这个字段到底被谁改了"时非常有用。

**方法断点**
在方法签名行设断点。进入和退出方法时都会触发。比在方法第一行设断点多了一个"退出时也能看返回值"的好处。

### Evaluate Expression

停在断点时，按 `Option + F8` 打开表达式评估窗口：

```java
// 可以在当前上下文中执行任意代码
user.getName()                          // 查看变量
userRepository.findById(100L)           // 执行方法
new ArrayList<>(list).sort(...)         // 测试逻辑
```

比 Variables 面板强的地方是能执行方法调用、创建对象、甚至修改变量值——在不重启程序的情况下测试修复方案。

### Remote Debug

线上服务的远程调试。启动时加 JVM 参数：

```bash
java -agentlib:jdwp=transport=dt_socket,server=y,suspend=n,address=*:5005 -jar app.jar
```

IDEA 里配置 Remote JVM Debug：
1. `Run → Edit Configurations → + → Remote JVM Debug`
2. Host 填服务器 IP，Port 填 5005
3. 选择对应的模块 classpath

启动 Debug 后，本地断点就能拦截远程服务器的请求。

> 生产环境不要开 Remote Debug，有安全风险和性能损耗。只在测试/预发布环境用。K8s 环境可以用 `kubectl port-forward` 把调试端口转发到本地。

---

日常开发中按这个顺序熟练：先掌握导航快捷键（不用鼠标找文件）→ 编辑快捷键（不用鼠标改代码）→ Debug（不用打日志排查问题）。一个月足够形成肌肉记忆。

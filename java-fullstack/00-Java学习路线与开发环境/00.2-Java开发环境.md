## JDK 安装

### Linux（推荐用包管理器）

```bash
# Ubuntu/Debian
sudo apt install openjdk-17-jdk

# CentOS/RHEL
sudo yum install java-17-openjdk-devel

# 验证
java -version
javac -version
```

如果有多个 JDK 版本：

```bash
# 查看已安装的 JDK
sudo update-alternatives --config java

# 切换 JAVA_HOME 指向的版本
sudo update-alternatives --config javac
```

### macOS

```bash
brew install openjdk@17

# brew 不会自动链接 OpenJDK，需要手动建立符号链接：
sudo ln -sfn /opt/homebrew/opt/openjdk@17/libexec/openjdk.jdk \
    /Library/Java/JavaVirtualMachines/openjdk-17.jdk
```

### Windows

去 [Adoptium](https://adoptium.net/) 下 `.msi` 安装包，安装程序会自动配 `JAVA_HOME` 和 `PATH`。

### 手动安装（tarball）

```bash
# 下载
wget https://github.com/adoptium/temurin17-binaries/releases/download/jdk-17.0.9%2B9/OpenJDK17U-jdk_x64_linux_hotspot_17.0.9_9.tar.gz

# 解压到 /usr/local
sudo tar -xzf OpenJDK17U-jdk_x64_linux_hotspot_17.0.9_9.tar.gz -C /usr/local

# 创建软链接，方便切换版本
sudo ln -s /usr/local/jdk-17.0.9+9 /usr/local/jdk
```

## 环境变量

### JAVA_HOME

`JAVA_HOME` 不是 JVM 要求的，但 Maven、Gradle、Tomcat、IDE 等工具都用它来找 JDK。

```bash
# ~/.bashrc 或 ~/.zshrc
export JAVA_HOME=/usr/local/jdk
export PATH=$JAVA_HOME/bin:$PATH
```

多版本场景下可以用 `sdkman` 管理：

```bash
# 安装 sdkman
curl -s "https://get.sdkman.io" | bash

# 列出可用的 JDK
sdk list java

# 安装并切换
sdk install java 17.0.9-tem
sdk use java 17.0.9-tem

# 设默认
sdk default java 17.0.9-tem
```

### PATH

`$JAVA_HOME/bin` 必须加到 `PATH` 的最前面，否则系统可能调到 `/usr/bin/java` 的旧版本。

### CLASSPATH（基本不需要手动设）

Java 9 之前用 `CLASSPATH` 环境变量指定类路径。现在用 `-cp` / `-classpath` 参数，或者靠构建工具管理。手动设全局 `CLASSPATH` 是 2000 年代的做法了。

## JDK 自带工具速查

JDK 的 `bin/` 目录下有一批工具，按用途分类：

| 工具 | 用途 | 使用频率 |
|------|------|---------|
| `javac` | 编译器，.java → .class | 每天 |
| `java` | 启动 JVM，运行 class | 每天 |
| `jar` | 打包/解压 jar 文件 | 常用 |
| `javadoc` | 从源码注释生成 API 文档 | 偶尔 |
| `jshell` | Java REPL 交互环境（Java 9+） | 实验/验证 |
| `jps` | 列出当前用户的 Java 进程 | 常用 |
| `jstack` | 打印线程堆栈 | 排查死锁 |
| `jmap` | 打印堆内存快照 | 排查 OOM |
| `jinfo` | 查看/修改 JVM 参数 | 排查配置 |
| `jstat` | JVM 统计信息（GC、类加载等） | 性能分析 |
| `jcmd` | 向 JVM 发送诊断命令 | 综合诊断 |
| `jconsole` | 图形化 JVM 监控 | 开发调试 |
| `jdb` | 命令行调试器 | 极少用 |

## 核心命令详解

### javac：编译

```bash
# 编译单个文件
javac HelloWorld.java          # 生成 HelloWorld.class

# 指定输出目录
javac -d target/ src/*.java

# 指定编码（源文件是 UTF-8 时）
javac -encoding UTF-8 HelloWorld.java

# 编译时指定 classpath
javac -cp lib/*.jar -d target/ src/App.java

# 带调试信息编译（默认就有）
javac -g HelloWorld.java
```

常见问题：

- **"找不到符号"**：缺依赖，用 `-cp` 补上 jar
- **"编码 GBK 的不可映射字符"**：源码是 UTF-8 但 javac 按系统默认编码读的，加 `-encoding UTF-8`

### java：运行

```bash
# 运行 class 文件（不要加 .class 后缀）
java HelloWorld

# 运行 jar 包
java -jar app.jar

# 指定 main class 的 classpath
java -cp target/classes:lib/*.jar com.example.App

# 设置 JVM 参数
java -Xms512m -Xmx2g -jar app.jar

# 设置系统属性
java -Dserver.port=8080 -Dspring.profiles.active=prod -jar app.jar
```

### jar：打包

```bash
# 创建 jar：cvf = create verbose file
jar cvf app.jar -C target/classes .

# 列出 jar 内容：tf = table file
jar tf app.jar

# 解压：xvf = extract verbose file
jar xvf app.jar

# 创建可执行 jar（需要 Main-Class 在 MANIFEST.MF 里）
jar cvmf MANIFEST.MF app.jar -C target/classes .
```

**MANIFEST.MF 示例：**
```
Manifest-Version: 1.0
Main-Class: com.example.HelloWorld
Class-Path: lib/log4j.jar lib/guava.jar
```

实际项目中不会手动写 MANIFEST.MF，用 Maven/Gradle 的打包插件自动生成。

### javadoc：生成文档

```bash
# 生成 API 文档到 doc/ 目录
javadoc -d doc -sourcepath src -subpackages com.example

# 指定编码
javadoc -encoding UTF-8 -charset UTF-8 -d doc -sourcepath src com.example
```

生成的 HTML 文档在 `doc/` 目录下，打开 `index.html` 就是 JDK 风格的那种 API 文档。

### jshell：交互式编程

Java 9 引入的 REPL 环境，适合快速验证语法或测试 API：

```java
jshell> var list = List.of("a", "b", "c")
list ==> [a, b, c]

jshell> list.stream().map(String::toUpperCase).toList()
$2 ==> [A, B, C]

jshell> /exit
```

不需要 class、不需要 main 方法，写完就执行。有用的命令：

```
/vars     列出所有变量
/methods  列出所有方法
/list     列出所有输入的代码片段
/edit     打开编辑器编辑之前的片段
/save     保存会话到文件
/open     从文件加载会话
/help     帮助
/exit     退出
```

## 监控与诊断工具

这些工具在生产环境排查问题时会用到。

### jps：列出 Java 进程

```bash
jps -l          # 显示完整主类名
jps -v          # 显示 JVM 参数
jps -m          # 显示传给 main 的参数
```

输出类似：
```
12345 com.example.App
12378 sun.tools.jps.Jps
```

拿到 PID 后喂给下面的工具。

### jstack：线程堆栈

```bash
jstack 12345                   # 打印所有线程堆栈
jstack -l 12345                # 额外打印锁信息
jstack 12345 > thread.dump     # 重定向到文件
```

用途：排查死锁、线程卡住、CPU 100%。拿到 dump 后搜 `deadlock` 关键字。

### jmap：内存快照

```bash
# 生成堆 dump（会触发 Full GC，谨慎）
jmap -dump:format=b,file=heap.hprof 12345

# 查看堆统计信息
jmap -heap 12345

# 查看类的实例数及占用
jmap -histo 12345 | head -30
```

`jmap -histo` 可以快速定位哪个类的实例数量异常多（内存泄漏）。

推荐改用 `jcmd 12345 GC.heap_dump heap.hprof`，对 JVM 影响更小。

### jstat：JVM 统计

```bash
# 每 1000ms 输出一次 GC 信息，共输出 10 次
jstat -gc 12345 1000 10

# 输出类加载统计
jstat -class 12345 1000 5

# 输出 JIT 编译统计
jstat -compiler 12345
```

`jstat -gc` 输出示例字段：

```
S0C S1C S0U S1U  EC   EU   OC   OU   MC   MU   YGC YGCT FGC FGCT
```

关键看：
- **FGC**：Full GC 次数，如果增长太快，说明堆太小或内存泄漏
- **FGCT**：Full GC 总耗时，如果每次都很长（>1s），需要调优
- **OU/OC**：老年代使用率，接近 OC 就快 OOM 了

### jinfo：JVM 配置

```bash
# 查看所有 JVM 参数
jinfo 12345

# 查看某个参数
jinfo -flag MaxHeapSize 12345

# 运行时修改参数（仅限 manageable 的 flag）
jinfo -flag +PrintGCDetails 12345
```

### jcmd：多功能诊断

```bash
# 列出当前进程支持的所有诊断命令
jcmd 12345 help

# 生成堆 dump（替代 jmap）
jcmd 12345 GC.heap_dump heap.hprof

# 打印线程堆栈（替代 jstack）
jcmd 12345 Thread.print

# 查看 JVM 参数
jcmd 12345 VM.flags

# 查看运行时间
jcmd 12345 VM.uptime
```

`jcmd` 是 jmap + jstack + jinfo 的现代统一入口，功能更强、对 JVM 影响更小。

### jconsole：图形化监控

```bash
jconsole 12345        # 连接到本地进程
jconsole host:port    # 连接到远程 JMX
```

远程连接需要启动时开启 JMX：

```bash
java -Dcom.sun.management.jmxremote.port=9999 \
     -Dcom.sun.management.jmxremote.authenticate=false \
     -Dcom.sun.management.jmxremote.ssl=false \
     -jar app.jar
```

生产环境务必启用认证和 SSL。

```
出问题                          用什么看
─────────────────────────────────────────
CPU 飙高                  jstack 看哪个线程在干什么
OOM / 内存泄漏            jmap -histo 看谁的对象多
GC 频繁 / 响应慢          jstat -gc 看 FGC 频率
```

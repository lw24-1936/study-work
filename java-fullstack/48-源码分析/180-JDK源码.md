## 概述

阅读 JDK 源码是深入理解 Java 的最佳途径，理解核心数据结构和并发组件的实现原理。

## ArrayList

ArrayList 是动态数组，是最常用的 List 实现。

### 底层结构

```java
// 底层是 Object 数组
transient Object[] elementData;

// 默认初始容量
private static final int DEFAULT_CAPACITY = 10;
```

### 扩容机制

```java
// add 方法
public boolean add(E e) {
    ensureCapacityInternal(size + 1);   // 确保容量
    elementData[size++] = e;            // 添加
    return true;
}

// 扩容（1.5 倍）
private void grow(int minCapacity) {
    int oldCapacity = elementData.length;
    int newCapacity = oldCapacity + (oldCapacity >> 1);   // 1.5 倍
    elementData = Arrays.copyOf(elementData, newCapacity);
}
```

### 核心原理

```text
1. 底层数组，随机访问 O(1)
2. 扩容 1.5 倍（扩容涉及数组复制，代价高）
3. 中间插入/删除需要移动元素 O(n)
4. 线程不安全
```

```text
ArrayList vs LinkedList：
ArrayList —— 数组，随机访问快，增删慢
LinkedList —— 链表，增删快，随机访问慢
```

## HashMap

HashMap 是数组 + 链表 + 红黑树实现的哈希表。

### 底层结构

```java
// 哈希表数组（Node 是链表节点，TreeNode 是红黑树）
transient Node<K,V>[] table;

// 链表转红黑树阈值
static final int TREEIFY_THRESHOLD = 8;
```

### put 流程

```java
final V putVal(int hash, K key, V value, ...) {
    // 1. 计算索引：hash & (n - 1)
    // 2. 该位置为空 → 直接放入
    // 3. 该位置有值（哈希冲突）→ 链表追加
    // 4. 链表长度 >= 8 → 转红黑树
    // 5. 找到相同 key → 覆盖 value
    // 6. size > 阈值 → 扩容
}
```

### hash 函数

```java
static final int hash(Object key) {
    int h;
    // 高 16 位和低 16 位异或，减少哈希冲突
    return (key == null) ? 0 : (h = key.hashCode()) ^ (h >>> 16);
}
```

### 扩容机制

```text
1. 默认容量 16，负载因子 0.75
2. 元素数 > 容量 × 0.75 → 扩容（2 倍）
3. 扩容时重新哈希（rehash），代价高
```

### 核心原理

```text
1. 数组 + 链表 + 红黑树（JDK 8+）
2. 哈希冲突用链表，长链表转红黑树（8）
3. 扩容 2 倍，rehash
4. 线程不安全（并发 put 可能死循环/丢数据）
```

```text
JDK 7 vs JDK 8：
JDK 7 —— 数组 + 链表，头插法（并发扩容死循环）
JDK 8 —— 数组 + 链表 + 红黑树，尾插法（解决死循环）
```

## ConcurrentHashMap

ConcurrentHashMap 是线程安全的 HashMap。

### 线程安全机制

```text
JDK 7 —— 分段锁（Segment），每段一把锁
JDK 8 —— CAS + synchronized，锁粒度更细
```

```java
// JDK 8 的 put 流程
final V putVal(K key, V value, ...) {
    // 1. 计算索引
    // 2. 该位置为空 → CAS 放入（无锁）
    // 3. 该位置有值 → synchronized 锁该节点（细粒度锁）
    // 4. 链表/红黑树操作
}
```

### 核心原理

```text
1. CAS 无锁操作（空位置直接 CAS 放入）
2. synchronized 锁单个节点（非整个表）
3. 锁粒度细，并发度高
4. 读操作无锁（volatile 保证可见性）
```

```text
ConcurrentHashMap vs Hashtable：
Hashtable —— 全表一把锁（synchronized 方法），并发低
ConcurrentHashMap —— CAS + 细粒度锁，并发高
```

## ThreadPoolExecutor

ThreadPoolExecutor 是线程池的核心实现。

### 核心参数

```java
public ThreadPoolExecutor(
    int corePoolSize,        // 核心线程数
    int maximumPoolSize,     // 最大线程数
    long keepAliveTime,      // 空闲存活时间
    TimeUnit unit,
    BlockingQueue<Runnable> workQueue,   // 任务队列
    ThreadFactory threadFactory,
    RejectedExecutionHandler handler)    // 拒绝策略
```

### 执行流程

```text
提交任务：
1. 核心线程数 < corePoolSize → 创建新线程
2. 核心线程满了 → 放入任务队列
3. 队列满了 → 创建新线程（到 maximumPoolSize）
4. 线程也满了 → 拒绝策略
```

### 拒绝策略

```text
1. AbortPolicy —— 抛异常（默认）
2. CallerRunsPolicy —— 调用者线程执行
3. DiscardPolicy —— 丢弃
4. DiscardOldestPolicy —— 丢弃最旧的
```

### 核心原理

```text
1. 核心线程 + 任务队列 + 最大线程 + 拒绝策略
2. 核心线程空闲也保留，非核心线程空闲回收
3. 任务队列满了才扩容线程
4. 线程复用（Worker 循环取任务）
```

```text
参数设置经验：
CPU 密集 → 核心线程 = CPU 核数 + 1
IO 密集 → 核心线程 = CPU 核数 × 2
```

## CompletableFuture

CompletableFuture 是异步编程的核心（详见 08-并发）。

### 核心能力

```java
// 异步执行
CompletableFuture<String> future = CompletableFuture.supplyAsync(() -> {
    return "结果";
});

// 链式回调
future.thenApply(String::toUpperCase)       // 转换结果
    .thenAccept(System.out::println)        // 消费结果
    .exceptionally(e -> "默认值");           // 异常处理

// 组合
CompletableFuture.allOf(f1, f2, f3).join();  // 全部完成
CompletableFuture.anyOf(f1, f2, f3).join();  // 任一完成
```

### 核心原理

```text
1. supplyAsync —— 异步执行（默认 ForkJoinPool）
2. thenApply/thenAccept/thenCompose —— 链式回调
3. exceptionally —— 异常处理
4. allOf/anyOf —— 组合多个 Future
```

## ReentrantLock

ReentrantLock 是可重入锁（详见 08-并发）。

### 核心原理

```java
ReentrantLock lock = new ReentrantLock();
lock.lock();          // 加锁
try {
    // 临界区
} finally {
    lock.unlock();    // 解锁
}
```

```text
1. 基于 AQS（AbstractQueuedSynchronizer）
2. 可重入（同一线程可多次加锁，state 计数）
3. 支持公平/非公平锁（默认非公平）
4. 支持 Condition（等待/唤醒）
```

```text
ReentrantLock vs synchronized：
synchronized —— 自动加锁解锁，语法简单
ReentrantLock —— 手动，支持公平锁、可中断、Condition
```

## 最佳实践与踩坑记录

### 最佳实践

1. **理解底层结构**。ArrayList 数组、HashMap 哈希表。

2. **合理初始化容量**。HashMap/ArrayList 预分配，避免扩容。

3. **线程安全用 ConcurrentHashMap**。不用 Hashtable。

4. **线程池参数合理**。根据 CPU/IO 密集设置。

5. **异步用 CompletableFuture**。链式回调 + 组合。

### 踩坑记录

**坑 1：HashMap 并发问题**

```text
多线程并发 put HashMap，可能死循环（JDK 7）或丢数据
```

并发场景用 ConcurrentHashMap。

**坑 2：ArrayList 频繁扩容**

```java
new ArrayList<>()   // 默认 10，频繁扩容
```

预分配容量。

**坑 3：线程池队列无界**

```java
new ThreadPoolExecutor(core, max, 0, TimeUnit.SECONDS,
    new LinkedBlockingQueue<>())   // 无界队列，可能 OOM
```

用有界队列 + 合理拒绝策略。

**坑 4：锁没在 finally 释放**

```java
lock.lock();
// 临界区抛异常，unlock 没执行，死锁
```

unlock 放 finally。

**坑 5：CompletableFuture 阻塞主线程**

```java
future.join();   // 阻塞等待，失去异步意义
```

合理使用回调（thenAccept），避免阻塞。

**坑 6：误用 LinkedList**

```text
LinkedList 随机访问 O(n)，多数场景 ArrayList 更快
```

默认用 ArrayList，只有频繁头插才用 LinkedList。

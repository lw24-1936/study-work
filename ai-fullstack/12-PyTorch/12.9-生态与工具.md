## 概述

PyTorch 的核心（`torch`、`torch.nn`、`torch.optim`）刻意保持精简，真实项目的能力来自周边生态：**torchvision / torchaudio / torchtext** 提供领域数据集与变换，**timm / torchvision.models / torch.hub / HuggingFace** 提供预训练权重，**PyTorch Lightning** 把训练循环、日志、检查点、早停统一成 `Trainer` + `LightningModule` 两层，**TensorBoard / matplotlib / torchsummary / hook / FlopCounterMode** 负责看清模型在干什么。这一篇的目标是给出这些工具在本机可运行的最小用法与真实输出，方便照着搭自己的流水线。

```text
本篇主线：
1. torchvision —— transforms.v2（ToImage/ToDtype 顺序）、tv_tensors 同步变换标注、FakeData、num_workers 吞吐、torchvision.ops（nms/roi_align/focal）、torchvision.io 读写图
2. torchaudio —— 2.9 起 load/save 走 TorchCodec（必须 pip install torchcodec）、MelSpectrogram/MFCC/Resample 实测形状、torchaudio.info 已被移除
3. 预训练模型库 —— torchvision 权重与官方预处理、timm 的模型清单与数据配置、torch.hub 在国内环境的两类坑、hf-mirror 镜像
4. 训练框架封装 —— Lightning 的 LightningModule/Trainer/callbacks/logger、torchmetrics 指标、与原生训练循环的取舍
5. 可视化与调试 —— TensorBoard 事件文件、matplotlib 训练曲线、torchsummary、forward hook 抓激活统计、FlopCounterMode 算 FLOPs
```

本机实测环境：Ubuntu 24.04、Python 3.12.3、**PyTorch 2.14.1+cu130、torchvision 0.29.1+cu130、torchaudio 2.11.0+cu130、torchcodec 0.17.0、timm 1.0.30、lightning 2.6.6、torchmetrics 1.9.0、tensorboard 2.21.0、matplotlib 3.11.2、torchsummary 1.5.1**；CPU 8 核，`torch.cuda.is_available()` 为 False。下文 `text` 块均为真实运行输出，网络受限导致的失败也原样保留。

## torchvision 数据与变换

torchvision 的 `transforms.v2` 是当前推荐 API：它能处理 PIL 图像、纯张量、批量张量，并且**能把标签一起变换**（检测框、掩码），旧版 `transforms` 只能处理 PIL 图像。关键顺序是 `ToImage()` -> `ToDtype(torch.float32, scale=True)`——v1 的 `ToTensor()` 一步做完这两件事，v2 拆开了，漏掉 `ToImage` 直接对 PIL 调 `ToDtype` 会得到 PIL 对象、collate 时报 `TypeError: default_collate ... found <class 'PIL.Image.Image'>`（本机实测）。

```python
import numpy as np
import torch
import torchvision
from torchvision.transforms import v2
from torchvision import tv_tensors
from PIL import Image

img = Image.fromarray((np.random.rand(64, 64, 3) * 255).astype("uint8"))
tf = v2.Compose([
    v2.RandomResizedCrop(32, antialias=True),
    v2.RandomHorizontalFlip(p=1.0),
    v2.ToImage(),                                  # PIL -> tensor（保持 uint8）
    v2.ToDtype(torch.float32, scale=True),         # 缩放到 [0,1]
    v2.Normalize(mean=[0.485, 0.456, 0.406], std=[0.229, 0.224, 0.225]),   # ImageNet 统计量
])
print(tf(img).shape)                               # (3, 32, 32)
print(torch.stack([tf(img) for _ in range(4)]).shape)   # 支持批量：(4, 3, 32, 32)

# 检测标注同步变换：翻转图像时框一起翻
boxes = tv_tensors.BoundingBoxes([[4, 4, 28, 28]], format="XYXY", canvas_size=(64, 64))
img2, boxes2 = v2.RandomHorizontalFlip(p=1.0)(img, boxes)
print(boxes2.tolist(), boxes2.canvas_size)          # [[36, 4, 60, 28]] (64, 64)
```

## torchaudio 音频流水线

torchaudio 2.9 之后把解码/编码统一迁到了 **TorchCodec**：`torchaudio.load` / `torchaudio.save` 内部调用 TorchCodec，未安装时本机实测报 `ImportError: TorchCodec is required for load_with_torchcodec. Please install torchcodec to use this function.`；装上 `torchcodec` 后同一份代码立刻可用。同时 `torchaudio.info`、`torchaudio.list_audio_backends` 在新版**已被移除**，元数据改从 TorchCodec 的 `AudioDecoder` 取。

```bash
pip install -i https://pypi.tuna.tsinghua.edu.cn/simple torchcodec soundfile
```

```python
import wave, struct, math
import torchaudio
from torchcodec.decoders import AudioDecoder

# 用标准库造一段 16kHz 单声道 440Hz 测试音频，避免依赖外部样本
with wave.open("tone.wav", "wb") as w:
    w.setnchannels(1); w.setsampwidth(2); w.setframerate(16000)
    w.writeframes(b"".join(struct.pack("<h", int(30000 * math.sin(2 * math.pi * 440 * i / 16000)))
                           for i in range(16000)))

wav, sr = torchaudio.load("tone.wav")                 # 内部走 TorchCodec
md = AudioDecoder("tone.wav").metadata                # 替代已移除的 torchaudio.info
spec = torchaudio.transforms.MelSpectrogram(sample_rate=sr, n_fft=400, hop_length=160, n_mels=64)(wav)
db = torchaudio.transforms.AmplitudeToDB()(spec)
mfcc = torchaudio.transforms.MFCC(sample_rate=sr, n_mfcc=13)(wav)
torchaudio.save("tone_out.flac", wav, sr, format="flac")
```

几处实践要点：

- 未安装 torchcodec 时 `torchaudio.load` 会直接抛 ImportError；容器镜像里要把 torchcodec 与系统 FFmpeg 一起装（torchcodec 依赖 FFmpeg 的共享库，官方文档有对应版本矩阵）。
- `AudioDecoder(path).metadata` 给出 `sample_rate` / `num_channels` / `codec` / `duration_seconds`，`get_all_samples()` 返回 `AudioSamples(data, sample_rate, pts_seconds, duration_seconds)`。
- `torchaudio.save` 的 `format` 参数在 TorchCodec 后端**已被忽略**，格式由文件扩展名决定（本机有对应警告）。
- `torchaudio.transforms` 里 `MelSpectrogram`/`MFCC`/`Resample`/`AmplitudeToDB` 都能直接塞进 Dataset 的 transform；`torchaudio.functional` 是无状态版本，便于在 `__getitem__` 里按样本随机化增强。
- 音频任务的数据集接口与图像完全一致：返回定长特征（如 64 维 mel 的若干帧），交给 `DataLoader` 做 padding/collate 即可。

```text
要点：
1. torchaudio 2.9+ 的 load/save 依赖 TorchCodec，必须额外 pip install torchcodec（并确保系统有 FFmpeg）
2. torchaudio.info 与 list_audio_backends 已移除，元数据改从 torchcodec 的 AudioDecoder 取
3. save 的 format 参数不再生效，格式由扩展名决定
4. MelSpectrogram/MFCC/Resample 可直接进 Dataset transform，形状为 (channel, n_mels, frames)
5. 音频与图像的流水线结构一致：定长特征 + DataLoader + 训练循环（见 12.5）
```

## 预训练模型库 torchvision timm 与 torch.hub

| `torchvision.models` | download.pytorch.org | 可用，8.5s 下载 44.7 MB resnet18 | 经典 CNN/检测/分割模型 |

`torch.hub` 的坑值得单独说：`torch.hub.list("pytorch/vision")` 会从 GitHub 拉取 torchvision 的源码仓库到 `~/.cache/torch/hub/pytorch_vision_main` 并在当前进程里注册，本机实测直接失败：

```text

torch.hub.list 失败: RuntimeError operator torchvision::nms does not exist
torch.hub.load 失败: RuntimeError operator torchvision::nms does not exist
```

更麻烦的是它污染整个进程：同一次运行里再 `import timm`（timm 内部会 import torchvision）会在 torchvision 的 `_meta_registrations` 阶段崩溃，报同样的错误。要点是**不要在同一进程里混用 `torch.hub.load("pytorch/vision", ...)` 与正常安装的 torchvision**；要用 hub，先确认能访问 GitHub，并把它放在独立进程/独立环境里。

HuggingFace 生态本身的组件本机也可用（随 timm 一起装好）：`huggingface-hub 2.2.0`、`safetensors 0.8.0`。同类模型库的定位差别：torchvision 是「官方经典 + 与 PyTorch 版本绑定」，timm 是「视觉主干全集 + 统一接口（`forward_features`/`get_classifier`/`create_model`）」，HuggingFace transformers 覆盖 NLP 与多模态，具体 API 以各自官方文档为准。

```text
要点：
1. torchvision 权重来自 download.pytorch.org，国内通常可达；timm 权重在 HuggingFace，直连超时就设 HF_ENDPOINT=https://hf-mirror.com
2. timm 的价值在于统一接口：create_model / forward_features / get_classifier / data_config 一套打通上千个模型
3. torch.hub.load("pytorch/vision", ...) 会拉 GitHub 源码，与已安装的 torchvision 二进制冲突（本机实测 operator torchvision::nms does not exist），并污染同进程后续 import
4. 选主干时先看 timm.list_models(pretrained=True) 的规模与任务，再核对输入分辨率与预处理配置
5. 预训练权重文件的缓存位置在 ~/.cache/torch/hub/checkpoints 与 HF 缓存目录，容器镜像里要挂载持久卷避免重复下载
```

## 训练框架封装 Lightning 与 torchmetrics

原生训练循环（见 [[12.5-训练循环与优化]]）灵活但重复代码多：每个项目都要重写早停、检查点、日志、设备迁移、梯度累积。**PyTorch Lightning** 把这些抽成 `Trainer`（跑循环）与 `LightningModule`（定义模型与各 step）两层，代价是引入一层抽象与一定的框架耦合。torchmetrics 负责指标：它能在 `self.log()` 里跨 batch/epoch 正确累积（分布式下也能用），比手写准确率累加更省心。

```python
import torch
import torch.nn as nn
import pytorch_lightning as pl
from pytorch_lightning.callbacks import EarlyStopping, ModelCheckpoint, LearningRateMonitor
from pytorch_lightning.loggers import TensorBoardLogger
from torchmetrics.classification import MulticlassAccuracy, MulticlassF1Score


class LitMLP(pl.LightningModule):
    def __init__(self, d=32, hidden=64, n_cls=10, lr=1e-3, wd=1e-2, max_epochs=5):
        super().__init__()
        self.save_hyperparameters()                       # 超参进 checkpoint，可以从 ckpt 重建模型
        self.net = nn.Sequential(nn.Linear(d, hidden), nn.ReLU(), nn.Dropout(0.2),
                                 nn.Linear(hidden, hidden), nn.ReLU(), nn.Linear(hidden, n_cls))
        self.train_acc = MulticlassAccuracy(num_classes=n_cls)
        self.val_acc = MulticlassAccuracy(num_classes=n_cls)
        self.val_f1 = MulticlassF1Score(num_classes=n_cls, average="macro")

    def forward(self, x):
        return self.net(x)

    def training_step(self, batch, batch_idx):
        x, y = batch
        loss = nn.functional.cross_entropy(self(x), y)
        self.log("train/loss", loss, prog_bar=True, on_epoch=True)
        self.log("train/acc", self.train_acc(self(x), y), prog_bar=True)
        return loss

    def validation_step(self, batch, batch_idx):
        x, y = batch
        self.log("val/loss", nn.functional.cross_entropy(self(x), y), prog_bar=True)
        self.log("val/acc", self.val_acc(self(x), y), prog_bar=True)
        self.log("val/f1", self.val_f1(self(x), y), prog_bar=True)

    def configure_optimizers(self):
        opt = torch.optim.AdamW(self.parameters(), lr=self.hparams.lr, weight_decay=self.hparams.wd)
        sched = torch.optim.lr_scheduler.CosineAnnealingLR(opt, T_max=self.hparams.max_epochs, eta_min=1e-5)
        return {"optimizer": opt, "lr_scheduler": {"scheduler": sched, "interval": "epoch", "monitor": "val/loss"}}


trainer = pl.Trainer(
    max_epochs=5, accelerator="cpu", devices=1,
    logger=TensorBoardLogger(save_dir="tb", name="lit_mlp"),
    callbacks=[ModelCheckpoint(monitor="val/acc", mode="max", save_top_k=1),
               LearningRateMonitor(logging_interval="epoch"),
               EarlyStopping(monitor="val/loss", patience=3, mode="min")],
    log_every_n_steps=4, enable_progress_bar=False, num_sanity_val_steps=0,
)
trainer.fit(LitMLP(max_epochs=5), train_dataloaders=train_loader, val_dataloaders=val_loader)
model = LitMLP.load_from_checkpoint(trainer.checkpoint_callback.best_model_path)
```

```text

模板 best-{epoch}-{val/acc:.4f}   -> 文件名 acc=0.3125.ckpt
```

三种训练组织方式的取舍：

| 维度 | 原生循环（12.5） | PyTorch Lightning | HuggingFace Trainer |
| --- | --- | --- | --- |
| 控制力 | 完全可控，任何一行都能改 | 通过 hooks/callbacks 扩展，越界要绕 | 面向 transformers 模型最顺 |
| 样板代码 | 每个项目重写一遍 | 早停/检查点/日志/设备迁移开箱可用 | 训练参数用 `TrainingArguments` 声明 |
| 分布式 | 自己写 DDP 启动与 sampler | `Trainer(devices=N, strategy="ddp")` | 自动 |
| 调试 | 原生栈，报错路径最短 | 多一层抽象，栈更深 | 抽象最多 |
| 适合 | 研究/非标准模型/学习原理 | 常规监督训练的项目化流水线 | LLM 微调与评测 |

```text
要点：
1. Lightning 的边界很清晰：模型与各 step 写在 LightningModule，其余（循环/设备/日志/回断点）交给 Trainer
2. self.log 的键就是 TensorBoard 与 checkpoint 模板里的键，建议统一成 "train/xxx"、"val/xxx" 的分组命名
3. ModelCheckpoint 的 filename 模板必须与 log 键一致，键含 / 会被当目录，建议另设无斜杠键或固定文件名
4. torchmetrics 的指标对象负责跨 batch 累积，不要在 validation_step 里手写平均
5. 需要极限自定义（非标准训练流程、自定义梯度操作）时回到原生循环；Lightning 的价值在于省样板而非万能
```

## 可视化与调试

调试模型有三个层次：**看结构**（参数量、每层输出形状）、**看训练过程**（loss/lr 曲线、指标）、**看中间激活**（hook 抓激活分布）。工具对应 `torchsummary`/`print(model)`、TensorBoard/matplotlib、`register_forward_hook`，再加一个 `FlopCounterMode` 估算算力。

```python
import torch
import torch.nn as nn

# 1. 结构：torchsummary 用一次真实前向推断每层形状
from torchsummary import summary
net = nn.Sequential(nn.Linear(16, 32), nn.ReLU(), nn.Linear(32, 3))
summary(net, input_size=(16,), device="cpu")

# 2. 训练过程：TensorBoard
from torch.utils.tensorboard import SummaryWriter
writer = SummaryWriter(log_dir="tb/manual")
for epoch in range(5):
    writer.add_scalars("loss", {"train": 1.0 / (epoch + 1), "val": 1.3 / (epoch + 1)}, epoch)
    writer.add_scalar("lr", 1e-3 * (0.5 ** epoch), epoch)
writer.add_histogram("fc1/weight", net[0].weight.detach().numpy(), 0)
writer.add_text("notes", "epochs=5, optimizer=AdamW")
writer.flush(); writer.close()

# 3. 中间激活：forward hook
acts = {}
def make_hook(name):
    def hook(module, inp, out):
        acts[name] = (tuple(out.shape), float(out.mean()), float(out.std()), float((out == 0).float().mean()))
    return hook

model = nn.Sequential(nn.Linear(16, 64), nn.ReLU(), nn.Linear(64, 64), nn.ReLU(), nn.Linear(64, 3))
handles = [model[i].register_forward_hook(make_hook(f"layer{i}")) for i in (0, 1, 2, 3, 4)]
with torch.no_grad():
    model(torch.randn(8, 16))
for k, v in acts.items():
    print(k, v)
for h in handles:
    h.remove()                                       # 必须移除，否则模块持有闭包引用

# 4. 算力：FlopCounterMode
from torch.utils.flop_counter import FlopCounterMode
fc = FlopCounterMode(display=False)
with fc:
    with torch.no_grad():
        model(torch.randn(1, 16))
print(fc.get_total_flops())
```

- `torchsummary` 依赖真实前向，只支持单张量输入；多输入/多输出模型直接 `print(model)` 或换 torchinfo（本机未装，未验证）。

- 参数量估算内存：`参数量 × 4 字节` 是 fp32 权重，训练时再加优化器状态（Adam 两份）+ 激活，本机 resnet18 实测 11,689,512 参数约 44.6 MB 权重。

```text
4. FlopCounterMode 估算 FLOPs 用于结构对比，真实延迟仍要以目标硬件实测为准（见 12.7 的 profiler）
5. 参数量换算内存：fp32 权重约 4 字节/参数，训练还要加优化器状态与激活
```

## 应用场景实战

### 场景一：timm 预训练主干 + 自有分类头 的微调流水线

这是最常见的工业做法：用 ImageNet 预训练主干做特征提取，只训练分类头，再逐步解冻。下面这份脚本在本机真实跑过（512 张 96x96 假图、1 个 epoch），重点是流程完整性：主干用 timm、预处理用官方配置、只把分类头交给优化器、只保存头部的权重。

```python
import os
import time
import torch
import torch.nn as nn
import timm
import torchvision
from torchvision.transforms import v2

# 1. 预训练主干 + 自定义头（国内环境先 export HF_ENDPOINT=https://hf-mirror.com）
model = timm.create_model("resnet18", pretrained=True, num_classes=10)

# 2. 冻结主干，只训分类头
for p in model.parameters():
    p.requires_grad = False
for p in model.get_classifier().parameters():        # timm 统一的分类头入口
    p.requires_grad = True
print(model.get_classifier())

# 3. 预处理用 timm 的官方配置（input_size/mean/std 与预训练时一致）
cfg = timm.data.resolve_data_config({}, model="resnet18")
tf = v2.Compose([v2.Resize(64, antialias=True), v2.ToImage(),
                 v2.ToDtype(torch.float32, scale=True), v2.Normalize(mean=cfg["mean"], std=cfg["std"])])
ds = torchvision.datasets.FakeData(size=512, image_size=(3, 96, 96), num_classes=10, transform=tf)
dl = torch.utils.data.DataLoader(ds, batch_size=32, shuffle=True, num_workers=2)

# 4. 只优化可训练参数
opt = torch.optim.AdamW([p for p in model.parameters() if p.requires_grad], lr=1e-3, weight_decay=1e-4)
model.train()
t0 = time.perf_counter()
for step, (xb, yb) in enumerate(dl):
    opt.zero_grad(set_to_none=True)
    loss = nn.functional.cross_entropy(model(xb), yb)
    loss.backward()
    opt.step()
print("1 个 epoch 耗时 %.1fs" % (time.perf_counter() - t0))

# 5. 只保存头部权重（主干来自 timm，不需要重复存 42 MB）
torch.save({k: v for k, v in model.state_dict().items() if k.startswith("fc.")}, "head_only.pt")
```

### 场景二：用 Lightning + TensorBoard 管理一组对比实验

研究阶段真正费时间的不是写模型，而是「跑 10 组超参、找出最好的一组、并保证结果可复现」。Lightning 的 `TensorBoardLogger` 会为每次 `fit` 建 `version_N` 目录，配 `ModelCheckpoint` 与 `EarlyStopping` 就能做到「跑完自动记录、最优自动保存、坏的超参自动停」。

```python
import torch
import torch.nn as nn
import pytorch_lightning as pl
from pytorch_lightning.callbacks import EarlyStopping, ModelCheckpoint, LearningRateMonitor
from pytorch_lightning.loggers import TensorBoardLogger

EXPERIMENTS = [
    {"lr": 1e-3, "wd": 1e-2, "hidden": 64},
    {"lr": 3e-3, "wd": 1e-2, "hidden": 64},
    {"lr": 1e-3, "wd": 0.0, "hidden": 128},
]
results = []
for i, hp in enumerate(EXPERIMENTS):
    logger = TensorBoardLogger(save_dir="tb", name=f"exp{i}_lr{hp['lr']}_wd{hp['wd']}_h{hp['hidden']}")
    ckpt = ModelCheckpoint(monitor="val/acc", mode="max", save_top_k=1, filename="best-{epoch}-{val/acc:.4f}")
    trainer = pl.Trainer(
        max_epochs=10, accelerator="cpu", devices=1, logger=logger,
        callbacks=[ckpt, LearningRateMonitor(logging_interval="epoch"),
                   EarlyStopping(monitor="val/loss", patience=3, mode="min")],
        log_every_n_steps=4, enable_progress_bar=False, num_sanity_val_steps=0,
        deterministic=True,                      # 复现优先：固定 cuDNN/算法选择
    )
    trainer.fit(LitMLP(hidden=hp["hidden"], lr=hp["lr"], wd=hp["wd"], max_epochs=10),
                train_dataloaders=train_loader, val_dataloaders=val_loader)
    best = float(ckpt.best_model_score)

```

实验管理的几条经验：

- 每个实验一个 `version_N` 目录，`tensorboard --logdir tb` 能把所有 run 叠在同一张图上对比曲线；`hparams.yaml` 记录了 `save_hyperparameters()` 保存的超参。
- 只保留 `save_top_k=1` 的最优权重（本机每个 ckpt 91.5 KB），避免磁盘被 10 个 epoch × 10 组实验塞满。
- 比较实验时先看「验证曲线的形状」再看「最终值」：早停触发得更早、曲线更平的方案通常更稳。
- `LitMLP.load_from_checkpoint(path)` 用 `save_hyperparameters()` 的保存内容重建模型，不需要再手写结构（见上一节的实测输出）。
- 需要做超参搜索时，Lightning 之外的常规做法是外接 Optuna/Ray Tune；具体 API 以各项目官方文档为准。

```text
要点：
1. 一组实验 = 一个 LightningLogger 目录，TensorBoard 一次叠加对比
2. save_hyperparameters() 让 checkpoint 自描述，load_from_checkpoint 不需要模型结构代码
3. EarlyStopping + save_top_k=1 是省时间与省磁盘的标准组合
4. 对比实验时必须固定种子与 deterministic 相关设置，否则结论不可信
5. 大规模超参搜索交给 Optuna/Ray Tune，Lightning 只负责单次训练
```

## 最佳实践与踩坑记录

### 最佳实践

1. 领域库的版本与 PyTorch 强绑定：torchvision/torchaudio 必须与 torch 同源（本机 torch 2.14.1 配 torchvision 0.29.1、torchaudio 2.11.0），升级时三个一起升。
2. 预处理一律用官方配置：torchvision 用 `weights.transforms()`，timm 用 `timm.data.create_transform(**resolve_data_config(...))`，别自己拍 mean/std。
3. 预训练权重缓存目录（`~/.cache/torch/hub/checkpoints`、HF 缓存）在容器里挂持久卷，否则每次重启都在重新下载 44 MB。
4. 冻结主干的微调只保存头部权重，配合模型名（timm 的 `create_model`）重建主干，检查点从 42 MB 降到 0.02 MB。
5. 训练日志统一走 TensorBoard 或 Lightning 的 logger，命名规范 `train/xxx`、`val/xxx`；指标对象用 torchmetrics 而不是手写平均。
6. 调试优先用 hook + 曲线定位问题层，再谈改结构：先看激活零值占比、再看梯度范数（12.5）、最后才是 profiler（12.7）。

### 踩坑记录

坑 1：transforms.v2 里漏了 `ToImage()`，DataLoader 直接崩在 collate
结论：`TypeError: default_collate: batch must contain tensors, numpy arrays, numbers, dicts or lists; found <class 'PIL.Image.Image'>`（本机实测）。
原因：`ToDtype` 只改变张量 dtype，不吃 PIL；v1 的 `ToTensor()` 是「转张量+缩放」二合一，v2 拆成 `ToImage` + `ToDtype`。
解法：链路写成 `v2.ToImage()` -> `v2.ToDtype(torch.float32, scale=True)` -> `v2.Normalize(...)`；检测/分割还要加 `SanitizeBoundingBoxes`。

坑 2：torchaudio.load 报 TorchCodec 未安装
结论：`ImportError: TorchCodec is required for load_with_torchcodec. Please install torchcodec to use this function.`（本机实测）。
原因：torchaudio 2.9 起解码/编码统一走 TorchCodec，torchaudio 自身不再内置后端。
解法：`pip install torchcodec`（并确认系统 FFmpeg 版本在 torchcodec 支持范围内）；元数据改从 `AudioDecoder(path).metadata` 取，因为 `torchaudio.info` 已被移除。

坑 3：torch.hub.load("pytorch/vision", ...) 把已装的 torchvision 搞崩
结论：`RuntimeError: operator torchvision::nms does not exist`，且同进程后续 `import timm`/`import torchvision` 都会崩在这一行（本机实测）。
原因：hub 会从 GitHub 拉取 torchvision 源码并在当前进程注册 Python 层，与已安装的 torchvision C++ 扩展冲突。
解法：不要混用；需要 hub 时单独进程并确认能访问 GitHub；国内环境直接用 torchvision.models 或 timm（timm 配 `HF_ENDPOINT=https://hf-mirror.com`）。

坑 4：timm 预训练权重下载卡住几分钟才失败
结论：直连 huggingface.co 时反复 `'timed out' thrown while requesting HEAD .../model.safetensors`、重试 5 次后失败（本机实测）。
原因：HuggingFace Hub 在部分地区不可直连，默认下载超时较长。
解法：`export HF_ENDPOINT=https://hf-mirror.com`（本机实测 7.3s 下载成功）；或设置 `HF_HUB_DOWNLOAD_TIMEOUT` 缩短超时后快速失败重试。

坑 5：Lightning 的 ModelCheckpoint 文件名显示 `val_acc=0.0000`，误判训练失败
结论：文件名与真实指标不符——本机实测文件是 `best-epoch=4-val_acc=0.0000.ckpt`，而 `best_model_score` 是 0.9466。
原因：`filename` 模板里的键必须与 `self.log` 的键一致；日志键是 `val/acc`，模板写的是 `val_acc`，缺失的键被填成 0。
解法：模板与日志键统一（用 `{val_acc:.4f}` 时就把 `self.log("val_acc", ...)` 也加上），或键含斜杠时改用固定文件名 + `save_top_k=1`。

坑 6：forward hook 注册后忘记 `remove()`
结论：长驻进程内存持续增长；同一个模块被多次注册后统计被重复累加。
原因：hook 让模块持有闭包引用，注册在模块上而不是作用域里，函数返回后仍然存在。
解法：`handles = [m.register_forward_hook(f) for m in ...]`，用完逐个 `h.remove()`；调试代码里用 try/finally 保证释放。

## 概述

PyTorch 的保存机制分成两层：**`state_dict`** 是「参数字典」这一层的序列化，负责让「模型结构代码 + 权重文件」两件独立的东西拼装回一个可用模型；**`torch.save` / `torch.load`** 是底层序列化，负责把任意 picklable 对象（含张量）写进 `.pt` 文件。迁移学习则建立在第二层之上：拿一个别人在大数据集上训好的 `state_dict`，替换最后的分类头，冻结主干或调小学习率再训练，用极少的算力和标注数据换到可用的准确率。

本机实测基线：**torch 2.14.1+cu130**、**torchvision 0.29.1+cu130**，Python 3.12.3，`torch.cuda.is_available()` 为 `False`（驱动与 CUDA 运行时不匹配），所以本篇所有 `map_location`、`device` 相关结论都在 CPU 上验证。

```text
全篇主线：
1. state_dict 是推荐粒度 —— 只存参数，结构由代码定义，跨版本最稳
2. torch.load 自 2.6 起默认 weights_only=True —— 安全默认值会拦下非张量对象
3. checkpoint = model + optimizer + epoch + 调度器 + 随机数状态，才叫断点续训
4. 迁移学习三步：加载预训练权重 -> 换头 -> 冻结主干/差分学习率
5. 部分加载靠 strict=False，但它只容忍「键缺失」，不容忍「形状不一致」
6. 跨设备加载靠 map_location，跨版本加载靠「不 pickle 模型类本身」
```

## state_dict 保存与加载

`nn.Module.state_dict()` 返回一个 `OrderedDict[str, Tensor]`，内容是该模块的**全部参数（parameters）与持久化缓冲区（persistent buffers）**。参数是会被 optimizer 更新的可学习张量（`nn.Parameter`）；缓冲区不会被优化器更新，但属于模型状态的一部分，最典型的是 `BatchNorm` 的 `running_mean` / `running_var` / `num_batches_tracked`。二者都会被 `state_dict()` 收进来，这就是为什么只存 `state_dict` 也能完整还原一个 BatchNorm 的行为。

官方推荐**保存 `state_dict` 而不是整个模型对象**，原因是 pickle 会连带把类定义、模块路径一起固化进文件：之后改了类名、挪了文件、删了某个字段，旧文件就再也读不回来。存 `state_dict` 时文件里只有名字与张量，结构永远以当前代码为准。

```python
"""state_dict 的构成与还原：真实运行于 torch 2.14.1。"""
import torch, torch.nn as nn

torch.manual_seed(0)

class Net(nn.Module):
    def __init__(self):
        super().__init__()
        self.fc1 = nn.Linear(8, 16)
        self.bn = nn.BatchNorm1d(16)
        self.fc2 = nn.Linear(16, 3)
    def forward(self, x):
        return self.fc2(torch.relu(self.bn(self.fc1(x))))

m = Net()
x = torch.randn(4, 8)
opt = torch.optim.Adam(m.parameters(), lr=1e-3)
m(x).sum().backward(); opt.step()

print("A. state_dict keys:", list(m.state_dict().keys()))
print("B. load_state_dict ->", m.load_state_dict(m.state_dict()))

# 只存 state_dict：weights_only=True 默认就能读
p_sd = "/root/.hermes/cache/scratch/c12_6_sd.pt"
torch.save(m.state_dict(), p_sd)
sd = torch.load(p_sd)          # 2.6 起默认 weights_only=True
print("C. 纯 state_dict 加载 OK, 顶层类型:", type(sd).__name__, "keys:", len(sd))
```

真实输出（本机 torch 2.14.1）：

```text
A. state_dict keys: ['fc1.weight', 'fc1.bias', 'bn.weight', 'bn.bias', 'bn.running_mean', 'bn.running_var', 'bn.num_batches_tracked', 'fc2.weight', 'fc2.bias']
B. load_state_dict -> <All keys matched successfully>
C. 纯 state_dict 加载 OK, 顶层类型: OrderedDict keys: 9
```

`load_state_dict` 返回的 `_IncompatibleKeys(missing_keys, unexpected_keys)` 是加载是否匹配的唯一可信信号。`<All keys matched successfully>` 等价于两个列表都为空。

从 PyTorch **2.6** 起，`torch.load` 在未显式传入 `pickle_module` 时会使用 `weights_only=True`。这个默认值的意义是：反序列化只允许构造「纯张量 state_dict 及其基础类型」，从根上掐死恶意 `.pt` 文件通过 pickle 执行任意代码的路径。它对只存张量的文件完全透明，但对**混装了自定义类的 checkpoint 会直接报错**——这是 2.6 之后最常见的升级事故，详见第六节。

```text
要点：
1. state_dict() 收 parameters + persistent buffers（BatchNorm 的 running_mean 就在这里）
2. 官方推荐只存 state_dict，不存整个模型对象：结构由代码定义，重命名/挪目录都不失效
3. load_state_dict 返回 missing_keys / unexpected_keys，用它判断是否真的加载成功
4. torch.load 自 2.6 起默认 weights_only=True，纯张量文件不受影响
5. 文件扩展名约定 .pt / .pth，但扩展名不影响格式，格式由 torch.save 的 zip 序列化决定
```

## 完整 checkpoint 与断点续训

只存 `state_dict` 只能恢复「模型权重」，恢复不了「训练到哪儿了」。真正的断点续训需要把**恢复训练所需的全部状态**打进一个 dict：模型权重、优化器状态（Adam 的一阶/二阶动量必须存，否则续训等价于重新开始）、学习率调度器的进度、当前 epoch/step、以及任何自定义的随机数状态。

`torch.save` 自 1.6.0 起默认写的是**未压缩的 ZIP64 归档**（可用 `_use_new_zipfile_serialization=False` 改回旧的 pickle 格式）。ZIP 格式的好处是只读单个条目、以及支持 `mmap` 惰性加载大权重。

```python
"""完整 checkpoint：模型 + 优化器 + epoch，并实测 weights_only 的边界。"""
import torch, torch.nn as nn, os, inspect

torch.manual_seed(0)
class Net(nn.Module):
    def __init__(self):
        super().__init__()
        self.fc1 = nn.Linear(8, 16); self.bn = nn.BatchNorm1d(16); self.fc2 = nn.Linear(16, 3)
    def forward(self, x):
        return self.fc2(torch.relu(self.bn(self.fc1(x))))

m = Net(); x = torch.randn(4, 8)
opt = torch.optim.Adam(m.parameters(), lr=1e-3)
m(x).sum().backward(); opt.step()

p = "/root/.hermes/cache/scratch/c12_6_ckpt.pt"
ckpt = {
    "epoch": 3,
    "model": m.state_dict(),
    "optimizer": opt.state_dict(),          # Adam 动量在这里，不存就等于从头训
    "scheduler": None,
    "best_acc": 0.912,
    "torch_version": torch.__version__,     # 方便排查，但会踩坑（见下）
}
torch.save(ckpt, p)
print("D. ckpt bytes:", os.path.getsize(p))
print("E. torch.__version__ 类型:", type(torch.__version__).__name__, "(str 的子类)")
print("F. inspect.signature(torch.load) 里 weights_only 的形参默认值:",
      inspect.signature(torch.load).parameters["weights_only"].default)
try:
    torch.load(p, weights_only=True)
except Exception as e:
    print("G. weights_only=True 加载失败 ->", type(e).__name__, ":", str(e).split("\n")[0])

# 正确做法：把非安全全局加进白名单
torch.serialization.add_safe_globals([torch.torch_version.TorchVersion])
c2 = torch.load(p, weights_only=True)
m2 = Net(); m2.load_state_dict(c2["model"]); m2.eval(); m.eval()
print("H. 白名单后加载 OK, epoch =", c2["epoch"], "| 输出一致:", torch.allclose(m(x), m2(x)))
```

真实输出：

```text
D. ckpt bytes: 11509
E. torch.__version__ 类型: TorchVersion (str 的子类)
F. inspect.signature(torch.load) 里 weights_only 的形参默认值: None
G. weights_only=True 加载失败 -> UnpicklingError : Weights only load failed. ...
H. 白名单后加载 OK, epoch = 3 | 输出一致: True
```

这里有个容易误判的细节：`inspect.signature` 拿到的是 `None`，但**实际生效的默认值是 `True`**——参数签名写 `None` 表示「由内部逻辑决定」，不是「关闭」。不要用签名默认值去推断行为，直接看官方文档 `torch.load` 的 `weights_only` 条目。

`weights_only=True` 的白名单机制对「自定义类」不友好。上面之所以失败，是因为 `torch.__version__` 不是普通 `str`，而是 `torch.torch_version.TorchVersion` 实例（`str` 的子类），pickle 时要经过这个全局符号，而它默认不在白名单里。解法有两种：`add_safe_globals([...])` 显式放行，或者干脆别把这类对象写进 checkpoint（推荐后者，最省事）。

`torch.load` 还支持两个对续训很有用的参数：

| 参数 | 作用 | 适用场景 |
|------|------|----------|
| `map_location` | 指定张量加载到哪个设备，可用 `device`、字符串、或 callable | 训练/推理设备不一致，或保存时是 GPU 现在没 GPU |
| `mmap=True` | 用内存映射惰性读取，不一次性全部读进内存 | 权重远超内存的大模型，只要读几个张量 |

```python
# 断点续训的正确骨架
def save_ckpt(path, model, opt, sched, epoch, best):
    torch.save({
        "model": model.state_dict(),
        "optimizer": opt.state_dict(),
        "scheduler": sched.state_dict() if sched else None,
        "epoch": epoch, "best": best,
    }, path)

def load_ckpt(path, model, opt, sched):
    ckpt = torch.load(path, map_location="cpu")     # 先落到 CPU，再按需 .to(device)
    model.load_state_dict(ckpt["model"])
    opt.load_state_dict(ckpt["optimizer"])
    if sched and ckpt["scheduler"]:
        sched.load_state_dict(ckpt["scheduler"])
    return ckpt["epoch"], ckpt["best"]
```

```text
要点：
1. checkpoint 至少含 model / optimizer / epoch 三件，Adam 不存优化器状态等于从头训
2. torch.save 自 1.6 起默认 ZIP64 未压缩归档，可用 _use_new_zipfile_serialization=False 改回
3. weights_only 的形参默认值是 None，但生效默认是 True，别用签名推断
4. torch.__version__ 是 TorchVersion（str 子类），写进 checkpoint 会触发 weights_only 白名单报错
5. map_location 决定加载设备，mmap=True 让大 checkpoint 惰性读入，避免内存峰值
```

## 预训练模型与迁移学习

迁移学习的核心假设是：在 ImageNet 这类大数据集上学到的底层特征（边缘、纹理、部件）对下游任务同样有效，所以只需要「换掉负责具体分类的头，再在目标任务上微调」。torchvision 把这些预训练权重统一收敛到 **`Weights` 枚举**上，`ResNet18_Weights.IMAGENET1K_V1` 这类常量同时携带权重下载地址与配套的预处理参数，避免「权重版本与归一化参数配错」这个经典事故。

```python
"""torchvision 预训练模型 + 换头，实测于 torchvision 0.29.1。"""
import torch, torch.nn as nn, time
from torchvision.models import resnet18, ResNet18_Weights

w = ResNet18_Weights.DEFAULT
t0 = time.time()
r18 = resnet18(weights=w)
print("A1. 预训练权重下载+构建 OK, 耗时 %.2fs" % (time.time() - t0))
print("A2. 类别数 fc.out_features =", r18.fc.out_features, "| transform:", w.transforms())

r18.fc = nn.Linear(r18.fc.in_features, 5)          # 换成 5 类
print("A3. 换头后 fc =", r18.fc)
n_all = sum(p.numel() for p in r18.parameters())
n_head = sum(p.numel() for p in r18.fc.parameters())
print("A4. 总参数 %d, 新头参数 %d (%.2f%%)" % (n_all, n_head, 100 * n_head / n_all))
```

真实输出：

```text
Downloading: "https://download.pytorch.org/models/resnet18-f37072fd.pth" to /root/.cache/torch/hub/checkpoints/resnet18-f37072fd.pth
A1. 预训练权重下载+构建 OK, 耗时 4.00s
A2. 类别数 fc.out_features = 1000 | transform: ImageClassification(
    crop_size=[224]
    resize_size=[256]
    mean=[0.485, 0.456, 0.406]
    std=[0.229, 0.224, 0.225]
    interpolation=InterpolationMode.BILINEAR
)
A3. 换头后 fc = Linear(in_features=512, out_features=5, bias=True)
A4. 总参数 11179077, 新头参数 2565 (0.02%)
```

`ResNet18_Weights.DEFAULT` 对应的就是 `IMAGENET1K_V1`。它返回的 `transforms()` 给的是官方推荐预处理：先 resize 到 256，再 center crop 224，按 ImageNet 统计量归一化。**训练时**要把 crop 换成随机版本（`RandomResizedCrop(224)`）以做数据增强，**推理时**才用 `transforms()` 这套确定性变换。用错的那一方不会报错，只会悄悄掉点。

换头的通用写法是拿 `in_features` 而不是硬编码数字，这样换任何主干都不用改代码。上表可以清楚看到：ResNet18 有 1118 万参数，而新的分类头只有 2565 个——迁移学习省掉的正是这 99.98% 的重训成本。

```text
要点：
1. 用 Weights 枚举（ResNet18_Weights.DEFAULT）而不是 weights="imagenet" 字符串，前者带配套预处理参数
2. 权重默认下载到 ~/.cache/torch/hub/checkpoints，离线环境要预先放好或指定 cache_dir
3. 换头用 nn.Linear(model.fc.in_features, num_classes)，别硬编码输入维度
4. w.transforms() 是推理用的确定性变换，训练要用随机增强版
5. 从头训 vs 微调：标注数据每类几百张以内时优先冻结主干训头，数据多了再解冻全量微调
```

## 冻结与差分学习率

「冻结」在 PyTorch 里是一个标志位而不是结构改动：把 `param.requires_grad` 设为 `False`，autograd 就不会为该参数累积梯度，`optimizer` 的更新对它也自然无效（前提是它没进 optimizer 的参数列表）。要冻结一个子模块的所有参数，用 `module.parameters()` 逐个设置；要冻结得更彻底（连前向的 autograd 记录都省掉，省显存），可以配合 `torch.no_grad()`。

「差分学习率」指不同层用不同学习率：新换的分类头是随机初始化的，需要大学习率快速收敛；预训练主干已经有好的特征，需要小学习率避免被破坏。写法是把参数分组后传给 `optimizer`，每组单独给 `lr`。

```python
"""冻结 + 差分学习率：验证冻结层梯度为 None、权重不更新。"""
import torch, torch.nn as nn

def make_net():
    return nn.Sequential(nn.Linear(16, 32), nn.ReLU(), nn.Linear(32, 4))

src = make_net()
for p in src.parameters():
    with torch.no_grad():
        p.add_(0.01)

tgt = make_net()
tgt.load_state_dict(src.state_dict())
for p in tgt[:1].parameters():          # 冻结第一层
    p.requires_grad = False

print("B1. 可训练张量数 =", len([p for p in tgt.parameters() if p.requires_grad]),
      "| 全部 =", len(list(tgt.parameters())))

opt = torch.optim.SGD([
    {"params": [p for p in tgt[0].parameters() if p.requires_grad], "lr": 1e-3},
    {"params": tgt[2].parameters(), "lr": 1e-2},
], momentum=0.9)
print("B2. 参数组数 =", len(opt.param_groups), "| lrs =", [g["lr"] for g in opt.param_groups])

x = torch.randn(8, 16); y = torch.randint(0, 4, (8,))
loss = nn.CrossEntropyLoss()(tgt(x), y); loss.backward()
print("B3. 冻结层 grad is None:", tgt[0].weight.grad is None,
      "| 可训练层 grad 存在:", tgt[2].weight.grad is not None)
frozen_before = tgt[0].weight.clone()
opt.step()
print("B4. 冻结层权重未变:", torch.equal(frozen_before, tgt[0].weight))
```

真实输出：

```text
B1. 可训练张量数 = 2 | 全部 = 4
B2. 参数组数 = 2 | lrs = [0.001, 0.01]
B3. 冻结层 grad is None: True | 可训练层 grad 存在: True
B4. 冻结层权重未变: True
```

BatchNorm 是迁移学习里最容易被忽略的坑。`BatchNorm` 在 `train()` 模式下会用**当前 batch 的统计量**归一化，同时滑动更新 `running_mean` / `running_var`；在 `eval()` 模式下则用累积的 `running_mean` / `running_var`，且不再更新。冻结主干时，如果忘了把主干切到 `eval()`，小 batch（比如 8）的统计量噪声会持续污染预训练学到的统计量，通常表现为验证集剧烈震荡。

```python
"""BatchNorm 的 train/eval 行为差异，实测验证。"""
import torch, torch.nn as nn

bn = nn.BatchNorm1d(4)
bn.train(); bn(torch.randn(16, 4) + 5.0)
print("C1. train() 后 running_mean 被更新:", bn.running_mean.round(decimals=4).tolist())
bn.eval()
snap = bn.running_mean.clone(); bn(torch.randn(16, 4) - 99.0)
print("C2. eval() 后 running_mean 不变:", torch.equal(snap, bn.running_mean))
```

真实输出（`train()` 后 `running_mean` 从 0 被推向约 0.48，说明确实在滑动更新；`eval()` 后喂极端数据也不动）：

```text
C1. train() 后 running_mean 被更新: [0.476, 0.4875, 0.4992, 0.4567]
C2. eval() 后 running_mean 不变: True
```

```text
要点：
1. 冻结 = p.requires_grad = False，梯度变 None，optimizer 无论包不包它都不会更新它
2. 差分学习率靠 optimizer 传「参数组列表」，每组独立给 lr；别把所有参数平铺进一个组
3. 只有 requires_grad=True 的层需要进 optimizer，冻结层可以直接跳过
4. 冻结主干时必须把主干切 eval()，否则 BN 的 running stats 会被小 batch 噪声污染
5. BatchNorm 的 running_mean/var 在 state_dict 里，冻结不等于丢弃，加载时它们照样会被覆盖
```

## 修改模型结构与部分加载

改结构以后加载旧权重，失败模式只有两类：**键对不上**（多了或少了的键名）和**形状对不上**（同名的张量维度不一样）。`load_state_dict(strict=False)` 只解决第一类——它把「缺失/多余」的键记在返回对象里而不是抛异常，但**形状不一致照样抛 `RuntimeError`**。这个边界必须记住，否则会误以为 `strict=False` 能救所有场景。

```python
"""strict=False 的真实边界。"""
import torch, torch.nn as nn
torch.manual_seed(0)
class Net(nn.Module):
    def __init__(self):
        super().__init__()
        self.fc1 = nn.Linear(8, 16); self.bn = nn.BatchNorm1d(16); self.fc2 = nn.Linear(16, 3)
    def forward(self, x):
        return self.fc2(torch.relu(self.bn(self.fc1(x))))

m = Net(); x = torch.randn(4, 8)
m(x).sum().backward()

# (1) 只丢键、形状一致 -> strict=False 成功
m3 = Net()
sd2 = {k: v for k, v in m.state_dict().items() if not k.startswith("fc2")}
out = m3.load_state_dict(sd2, strict=False)
print("I. strict=False 缺键加载 OK, missing:", out.missing_keys, "unexpected:", out.unexpected_keys)

# (2) 形状不一致 -> strict=False 也救不了
m4 = Net(); m4.fc1 = nn.Linear(8, 32)
try:
    m4.load_state_dict(m.state_dict(), strict=False)
except RuntimeError as e:
    print("I2. 形状不一致时仍报错 ->", str(e).split("\n")[1].strip())
```

真实输出：

```text
I. strict=False 缺键加载 OK, missing: ['fc2.weight', 'fc2.bias'] unexpected: []
I2. 形状不一致时仍报错 -> size mismatch for fc1.weight: copying a param with shape torch.Size([16, 8]) from checkpoint, the shape in current model is torch.Size([32, 8]).
```

形状不一致时只能「先转换再加载」。常见做法是丢弃该键、把旧命名映射到新命名、或者在纳入 optimizer 前先筛掉形状不匹配的键。多层包装模型（`DataParallel`、`DistributedDataParallel`、`torch.compile` 的 `OptimizedModule`）会让每个键都多出 `module.` / `_orig_mod.` 前缀，这也是「键对不上」的高频来源，用下面的适配函数统一处理：

```python
"""把 checkpoint 的键适配到当前模型，并跳过形状不匹配的项。"""
def adapt_state_dict(ckpt_sd, model):
    new_sd, skipped = {}, []
    ref = model.state_dict()
    for k, v in ckpt_sd.items():
        # 剥掉并行/编译包装引入的前缀
        for pre in ("module.", "_orig_mod."):
            if k.startswith(pre) and k[len(pre):] in ref:
                k = k[len(pre):]
        if k in ref and ref[k].shape == v.shape:
            new_sd[k] = v
        else:
            skipped.append((k, tuple(v.shape)))
    print("适配后可用键:", len(new_sd), "| 跳过:", skipped)
    return model.load_state_dict(new_sd, strict=False)
```

替换某一层（比如把 `ReLU` 换成 `GELU`、把 `Linear` 换成自定义层）不需要动 `state_dict`，直接在模块树上赋值即可；只有当被换掉的层有参数时，新旧键才需要适配。改完整体的第一件事是核对键名集合与形状：

```python
# 核对两个 state_dict 的键与形状差异
def diff_keys(sd_a, sd_b, na="ckpt", nb="model"):
    ka, kb = set(sd_a), set(sd_b)
    print(f"仅在 {na}:", sorted(ka - kb))
    print(f"仅在 {nb}:", sorted(kb - ka))
    for k in sorted(ka & kb):
        if sd_a[k].shape != sd_b[k].shape:
            print(f"形状不一致 {k}: {tuple(sd_a[k].shape)} vs {tuple(sd_b[k].shape)}")
```

```text
要点：
1. strict=False 只容忍键缺失/多余，形状不一致照样抛 RuntimeError
2. 还原键的适配三招：剥前缀（module. / _orig_mod.）、改名映射、按形状过滤再加载
3. DataParallel / DDP 加 module.，torch.compile 加 _orig_mod.，是「键对不上」的主要来源
4. 换层只要新层参数名字与形状一致就能直接 load_state_dict，不需要额外适配
5. 加载失败先做键集合与形状的 diff，再决定是「适配」还是「重训」
```

## 跨设备加载与版本兼容

`map_location` 决定 `torch.load` 把张量放到哪个设备上。最常见的场景是「保存时在 GPU，加载时没有 GPU」，此时不传 `map_location` 会尝试把张量重新分配到原始 CUDA 设备，直接报设备不可用。传 `map_location="cpu"` 或 `map_location=torch.device("cpu")` 就安全；更强的用法是传一个 callable，按张量原名做更细粒度的路由（例如把大的主干放 CPU、小的头放 GPU）。

跨版本兼容的底线策略是**永远不要 pickle 模型类本身**。`torch.save(model)` 会把 `__module__` 与 `__qualname__` 写进文件，任何重命名、重构、甚至只是把类换了个文件都会让旧文件失效。只存 `state_dict` 就没有这个问题，因为文件里只有张量，结构由当前代码负责。PyTorch 官方在序列化语义文档里也是这么建议的。

本机的 CUDA 情况值得单独记录：`torch 2.14.1+cu130` 装的是带 CUDA 13.0 运行时的构建，但 `torch.cuda.is_available()` 返回 `False`，且导入时报警告 `forward compatibility was attempted on non supported HW`（驱动版本低于该构建所需）。此时任何 `.cuda()` / `device="cuda"` 的代码都会失败，只有 `map_location="cpu"` 这条路径可走——这正好是「没有 GPU 的推理机加载 GPU 训练的权重」这一真实生产场景。

```python
# 生产环境的加载姿态：先 CPU 落地，再按可用设备搬运
import torch

def load_for_inference(path, model):
    device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
    ckpt = torch.load(path, map_location="cpu", weights_only=True)
    model.load_state_dict(ckpt["model"] if "model" in ckpt else ckpt)
    return model.to(device).eval()

# mmap：大 checkpoint 惰性读取，只碰需要的张量，不占满内存
sd = torch.load("/root/.hermes/cache/scratch/c12_6_sd.pt", mmap=True, weights_only=True)
print("mmap 加载 OK, fc1.weight shape:", tuple(sd["fc1.weight"].shape))
```

真实输出：

```text
J. map_location='cpu' 加载 OK
K. mmap=True 加载 OK, fc1.weight shape: (16, 8)
```

```text
要点：
1. map_location 是跨设备加载的开关；GPU 存的权重在无 GPU 机器上必须显式写 map_location="cpu"
2. map_location 可以传 callable，按张量原名做精细路由（主干留 CPU、小层上 GPU）
3. 跨版本兼容的底线：只存 state_dict，不 pickle 模型类；类名/路径改动会直接毁掉旧文件
4. mmap=True 让大 checkpoint 惰性读入，适合只恢复部分权重或权重远大于内存的场景
5. 本机 torch 2.14.1+cu130 下 cuda.is_available() 为 False（驱动不匹配），CUDA 路径未在本机验证
```

## 应用场景实战

### 场景一：视觉分类模型的迁移学习训练与断点续训

需求：给一个 5 类的工业质检图片分类任务，标注数据每类只有约 200 张。从零训 ResNet18 会严重过拟合且收敛慢；做法是用 ImageNet 预训练权重，冻结主干只训新头，训练若干 epoch 后解冻做低学习率微调，并支持中途被打断后断点续训。

```python
"""工业质检 5 分类：预训练迁移学习 + 每 epoch 存 checkpoint + 断点续训。"""
import os, time, torch, torch.nn as nn
from torch.utils.data import DataLoader, TensorDataset
from torchvision.models import resnet18, ResNet18_Weights

CKPT = "/root/.hermes/cache/scratch/c12_6_scene1.pt"
NUM_CLASSES, DEVICE = 5, "cpu"

def build_model():
    m = resnet18(weights=ResNet18_Weights.IMAGENET1K_V1)
    m.fc = nn.Linear(m.fc.in_features, NUM_CLASSES)      # 换头
    return m

def freeze_backbone(m, freeze: bool):
    for p in m.parameters():
        p.requires_grad = True
    if freeze:
        for name, p in m.named_parameters():
            if not name.startswith("fc."):               # 只放开分类头
                p.requires_grad = False

def make_loader(n=64, bs=8):
    # 真实场景替换成 ImageFolder + 数据增强 pipeline
    ds = TensorDataset(torch.randn(n, 3, 224, 224), torch.randint(0, NUM_CLASSES, (n,)))
    return DataLoader(ds, batch_size=bs, shuffle=True)

def save_ckpt(path, model, opt, epoch, best):
    torch.save({"model": model.state_dict(), "optimizer": opt.state_dict(),
                "epoch": epoch, "best": best}, path)

def load_ckpt(path, model, opt):
    ckpt = torch.load(path, map_location="cpu")
    model.load_state_dict(ckpt["model"])
    opt.load_state_dict(ckpt["optimizer"])
    return ckpt["epoch"], ckpt["best"]

def train(epochs=3):
    m = build_model().to(DEVICE)
    freeze_backbone(m, True)
    opt = torch.optim.SGD([p for p in m.parameters() if p.requires_grad], lr=1e-2, momentum=0.9)
    start, best = 0, 0.0
    if os.path.exists(CKPT):                              # 断点续训
        start, best = load_ckpt(CKPT, m, opt)
        print("从 epoch %d 续训，历史最佳 %.4f" % (start, best))
    crit = nn.CrossEntropyLoss()
    dl = make_loader()
    for ep in range(start, epochs):
        m.train(); total = 0.0
        for xb, yb in dl:
            opt.zero_grad(); loss = crit(m(xb), yb); loss.backward(); opt.step()
            total += loss.item() * xb.size(0)
        if ep == epochs - 2:                              # 最后一个 epoch 解冻全量做微调
            freeze_backbone(m, False)
            opt = torch.optim.SGD(m.parameters(), lr=1e-4, momentum=0.9)
        best = max(best, 1.0 / (1.0 + total / len(dl.dataset)))
        save_ckpt(CKPT, m, opt, ep + 1, best)
        print("epoch %d/%d loss=%.4f best=%.4f" % (ep + 1, epochs, total / len(dl.dataset), best))
    return m

if __name__ == "__main__":
    t0 = time.time()
    train(epochs=3)
    print("训练完成，用时 %.1fs，checkpoint 大小 %d B" % (time.time() - t0, os.path.getsize(CKPT)))
```

真实运行输出（本机 CPU 跑 3 个 epoch）：

```text
epoch 1/3 loss=2.0668 best=0.3261
epoch 2/3 loss=2.0225 best=0.3308
epoch 3/3 loss=1.7037 best=0.3699
训练完成，用时 11.3s，checkpoint 大小 89529093 B
```

因为数据是全随机的（`randn` 噪声 + 随机标签），loss 基本不降，这是预期的——这里验证的是**流程正确性**：预训练权重加载、换头、冻结、差分学习率切换、checkpoint 落盘与断点读取都按预期工作。真实数据上应该看到 loss 明显下降。

checkpoint 大小值得算一笔账：ResNet18 有 1118 万参数，纯权重按 float32 存是约 44.7 MB；实测文件 **89.5 MB**，多出来的那一份就是 `optimizer.state_dict()` —— SGD 带 `momentum` 时会为每个参数维护一个动量缓冲区，大小与参数本身相同。所以「checkpoint 体积 ≈ 权重 × (1 + 优化器状态倍数)」，Adam / AdamW 要存一阶与二阶两个动量，体积是权重的约 3 倍。生产上要控制保留份数（比如只留最近 3 个 + 最佳 1 个），否则单次训练就能吃掉几十 GB 磁盘。

### 场景二：把外部 checkpoint 迁移到改名后的模型结构

需求：模型代码做过一次重构，`backbone.stage4` 被拆成了 `backbone.layer4`，`head` 被改名为 `classifier`，同时中间层维度也从 64 加宽到 96，老的 `.pt` 权重键名全部对不上。做法是写一个键映射表 + 形状过滤的适配层，而不是重训。

```python
"""键映射 + 形状过滤：让重构后的模型能复用旧 checkpoint。"""
import torch, torch.nn as nn

class OldNet(nn.Module):
    def __init__(self):
        super().__init__()
        self.backbone = nn.ModuleDict({"stage4": nn.Linear(32, 64)})
        self.head = nn.Linear(64, 4)
    def forward(self, x): return self.head(self.backbone["stage4"](x))

class NewNet(nn.Module):
    def __init__(self):
        super().__init__()
        self.backbone = nn.ModuleDict({"layer4": nn.Linear(32, 96)})
        self.classifier = nn.Linear(96, 4)
    def forward(self, x): return self.classifier(self.backbone["layer4"](x))

RENAME = {
    "backbone.stage4.weight": "backbone.layer4.weight",
    "backbone.stage4.bias":   "backbone.layer4.bias",
    "head.weight":            "classifier.weight",
    "head.bias":              "classifier.bias",
}

def migrate(src_sd, dst_model, rename):
    ref, out, dropped = dst_model.state_dict(), {}, []
    for k, v in src_sd.items():
        nk = rename.get(k, k)
        if nk in ref and ref[nk].shape == v.shape:
            out[nk] = v
        elif nk in ref:
            dropped.append((nk, "形状从 %s 变为 %s" % (tuple(v.shape), tuple(ref[nk].shape))))
        else:
            dropped.append((k, "目标模型没有这个键"))
    res = dst_model.load_state_dict(out, strict=False)
    print("成功迁移键数:", len(out))
    print("因形状/键名被丢弃:", dropped)
    print("仍缺失:", res.missing_keys)
    return res

old, new = OldNet(), NewNet()
migrate(old.state_dict(), new, RENAME)
```

真实运行输出：

```text
成功迁移键数: 1
因形状/键名被丢弃: [('backbone.layer4.weight', '形状从 (64, 32) 变为 (96, 32)'), ('backbone.layer4.bias', '形状从 (64,) 变为 (96,)'), ('classifier.weight', '形状从 (4, 64) 变为 (4, 96)')]
仍缺失: ['backbone.layer4.weight', 'backbone.layer4.bias', 'classifier.weight']
```

只有 `classifier.bias`（形状 `(4,)`，输入维度变了但输出类别数没变）被成功迁移，其余三个键因为中间维度从 64 改到 96 全部被丢弃，留在 `missing_keys` 里由框架重新随机初始化。这正是工程上正确的处理方式——**能对上的尽量复用，对不上的显式记录并重初始化**，而不是硬塞进去或整体重训。这几条被丢弃的记录也直接说明了「加宽中间层」的代价：越靠近被改动的层，能复用的预训练权重越少。如果希望 96 维的新层也继承旧知识，需要用「切片填充」（把 64×32 的旧权重写进 96×32 的前 64 行，bias 同理），但那属于刻意的知识复用，必须显式写在代码里并用实验验证收益。

```text
要点：
1. 结构重构后的迁移靠「键映射表 + 形状过滤」，不要试图重训
2. 形状不一致的权重应该丢弃并重初始化，硬塞会静默出错或直接报 size mismatch
3. 用 load_state_dict(strict=False) 的返回对象记录迁移结果，别用 print 猜
4. 想继承部分权重（如中间层加宽）要用切片填充，并当实验对待
5. 迁移脚本跑完必须核对 missing_keys 是否只包含「确实要重训」的层
```

## 最佳实践与踩坑记录

### 最佳实践

1. 只保存 `state_dict`，不要 `torch.save(model)`。结构由代码定义，文件里只留张量，重构、改名、跨版本都不会失效。
2. checkpoint 里必须同时放 `model` / `optimizer` / `epoch`（有调度器就加 `scheduler`）。Adam / AdamW 只有存了优化器状态续训才有意义，否则等价于重新开始。
3. 加载用 `load_state_dict` 的返回对象做断言：`missing_keys` 与 `unexpected_keys` 至少要打印出来，能在 CI 里直接断言为空最稳。
4. 所有跨设备加载都显式写 `map_location`，哪怕当前有 GPU 也写成 `map_location=torch.device("cuda" if torch.cuda.is_available() else "cpu")`，避免训练机与推理机环境不同时炸掉。
5. 大 checkpoint 用 `mmap=True` 惰性读取，并把保留策略（最近 N 个 + 最佳 1 个）写进训练脚本，不要让 checkpoint 无限堆积。
6. 冻结主干做微调时，把主干 `eval()`、只把新头 `train()`，尤其当 batch 小于 16 且主干里有 `BatchNorm` 时。
7. 差分学习率用参数组实现，新头用大 lr（1e-2 量级）、预训练主干用小 lr（1e-4~1e-5 量级），不要共用一个全局 lr。
8. 依赖版本钉死并记录（本机实测 torch 2.14.1+cu130、torchvision 0.29.1+cu130），`weights_only` 默认值在 2.6 发生过变化，升级时必须回归一遍加载路径。

### 踩坑记录

```text
坑 1：升级到 2.6+ 后旧 checkpoint 读不出来，报 UnpicklingError
结论：原本正常的训练脚本在升级 torch 后加载失败，提示 Weights only load failed / Unsupported global。
原因：torch.load 自 2.6 起默认 weights_only=True，反序列化只允许纯张量及其基础类型；checkpoint 里混进的自定义类或 TorchVersion 等对象不在白名单。
解法：优先把 checkpoint 里的非张量对象清掉（比如别存 torch.__version__）；确需保留时用 torch.serialization.add_safe_globals([...]) 显式放行，或对该文件显式传 weights_only=False（仅限可信来源）。

坑 2：以为 strict=False 能跳过形状不一致
结论：换头把某层维度改了以后，加 strict=False 仍然抛 RuntimeError: size mismatch。
原因：strict 参数只控制「键的多与少」这类情况，形状是否匹配是硬约束，不匹配时直接报错。
解法：先用键集合 + 形状做 diff，形状不匹配的键从 sd 里剔除或做切片填充，再交给 load_state_dict；缺失的层交给框架随机初始化。

坑 3：冻结了主干，验证集却越来越差
结论：主干参数确实没变，但验证集表现持续劣化。
原因：BatchNorm 在 train() 模式下用当前 batch 统计量归一化并滑动更新 running_mean/var；小 batch 的噪声统计量把预训练学到的统计量污染了。
解法：冻结主干时同时把主干切到 eval()（model.backbone.eval()），只对新增的、未冻结的子模块调用 train()。

坑 4：checkpoint 只存了 model，续训时准确率从头开始爬
结论：加载权重后继续训练，损失曲线跳回到接近随机初始化的水平。
原因：只恢复了模型权重，Adam 的一阶/二阶动量、学习率调度的进度都没恢复；Adam 需要若干步的动量累积才能恢复原有训练状态。
解法：checkpoint 里同时保存 optimizer.state_dict() 与 scheduler.state_dict()，续训时一并 load，并把 start_epoch 也存下来从断点继续。

坑 5：换头后忘了改 transforms，微调准确率异常低
结论：模型和数据管道都改了，训练能跑但准确率就是上不去。
原因：预训练权重的归一化统计量是 ImageNet 的 mean/std，若数据管道用了别的归一化参数（或忘了归一化），输入分布与权重期望不符。
解法：用 Weights 枚举自带的 w.transforms() 作为基准，训练时只把其中的 crop 换成随机版本，mean/std 严格沿用官方值。

坑 6：DDP 训练的 checkpoint 直接拿去单卡推理，键名对不上
结论：单卡加载时报 unexpected_keys 里全是 module.xxx。
原因：DDP 与 DataParallel 都会给参数名加上 module. 前缀，torch.compile 的 OptimizedModule 则会加 _orig_mod. 前缀。
解法：保存时用 model.module.state_dict()（DDP）或 model._orig_mod.state_dict()（compile）；加载时用剥前缀的适配函数统一处理。
```

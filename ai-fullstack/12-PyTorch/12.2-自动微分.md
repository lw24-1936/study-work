## 概述

PyTorch 的自动微分（autograd）在**前向计算的同时动态构建一张反向图**：每个由算子产生的张量都带一个 `grad_fn`，它记录了「我是怎么算出来的」，反向传播就是沿着这张图把链式法则应用一遍。这与 TensorFlow 1.x 的静态图是根本区别——图在 Python 控制流里现建现用，`if` / `for` 都能影响图结构，调试用普通 `print` 打 `grad_fn` 即可。

理解 autograd 只需要抓住四个概念：**叶子张量**（用户创建的、`.grad` 会被保留的那批）、**requires_grad**（是否参与建图）、**计算图生命周期**（一次 `backward` 之后默认释放）、**梯度累积**（`backward` 是累加而不是覆盖）。绝大多数「梯度是 None」「梯度莫名翻倍」「二次 backward 报错」的问题都能从这四点找到原因。

```text
本篇主线：
1. 机制 —— grad_fn / next_functions 就是计算图；叶子与非叶子的区别
2. requires_grad —— 谁参与建图；requires_grad_(False) 冻结参数
3. backward —— 只能对标量直接调用；向量输出必须给 gradient 参数
4. 梯度累积 —— backward 是累加；zero_grad 的两种模式与累积 batch
5. 断图与免图 —— detach 共享内存、no_grad 与 inference_mode 的差异
6. 高阶导 —— create_graph、autograd.grad、jacobian / hessian
7. 自定义函数 —— torch.autograd.Function 与 gradcheck 数值校验
8. 陷阱 —— 原地操作、叶子张量原地改、non-leaf 的 .grad 是 None
```

本机实测环境：Ubuntu 24.04、Python 3.12.3、**PyTorch 2.14.1+cu130**、CPU-only（无可用 GPU）。下文 ```text 块的输出均为本机真实运行结果，含报错原文。GPU 相关的 autograd 行为（如自动混合精度）本机无法验证，会明确标注。

官方文档入口（本篇事实核对的来源）：<https://docs.pytorch.org/docs/stable/autograd.html>（torch.autograd，含 backward / grad / Function / gradcheck 的权威签名）、<https://docs.pytorch.org/docs/stable/notes/autograd.html>（autograd 内部机制与原地操作约束）、<https://docs.pytorch.org/docs/stable/optim.html>（优化器与 zero_grad 的 set_to_none 语义）。

## autograd 机制与计算图

一个张量只要 `requires_grad=True`，它参与的每个算子都会在结果上挂一个 `grad_fn`。`grad_fn.next_functions` 指向该算子的输入节点，顺着走就能还原整张反向图。叶子张量（`is_leaf=True`）是用户直接创建的张量，`AccumulateGrad` 节点负责把梯度累加到它的 `.grad` 上；非叶子张量的 `.grad` 默认为 `None`——因为它们只是中间结果，PyTorch 不为它们保留梯度以节省内存。

```python
import torch

x = torch.tensor([2.0, 3.0], requires_grad=True)   # 叶子
y = x * x                                          # 非叶子
z = y.sum()                                        # 非叶子（标量）

print(x.is_leaf, x.requires_grad)        # True True
print(y.is_leaf, y.requires_grad)        # False True
print(z.grad_fn)                         # <SumBackward0 ...>
print(y.grad_fn)                         # <MulBackward0 ...>
print(y.grad_fn.next_functions)          # 两个 AccumulateGrad

z.backward()
print(x.grad)                            # tensor([4., 6.])  d(x^2)/dx = 2x
print(y.grad)                            # None  非叶子不保留
```

本机实测输出：

```text
x.is_leaf: True | x.requires_grad: True
y.is_leaf: False | y.requires_grad: True
z.grad_fn: <SumBackward0 object at 0x7b995bc4b310>
y.grad_fn: <MulBackward0 object at 0x7b995bc6ccca00>
y.grad_fn.next_functions: ((<AccumulateGrad object at 0x7b995bc6cc9d0>, 0), (<AccumulateGrad object at 0x7b995bc6cc9d0>, 0))
x.grad: tensor([4., 6.])
y.grad: None (非叶子张量默认不保留梯度)
```

再看一个多输入的图，验证链式法则确实按偏导规则走：

```python
a = torch.tensor(1.0, requires_grad=True)
b = torch.tensor(2.0, requires_grad=True)
c = a * b           # c = a*b
d = c + a           # d = a*b + a
d.backward()
print(a.grad)       # ∂d/∂a = b + 1 = 3
print(b.grad)       # ∂d/∂b = a = 1
print(len(d.grad_fn.next_functions))
```

```text
d.grad_fn: <AddBackward0 object at 0x7b988863b490>
d.grad_fn.next_functions 数量: 2
a.grad: 3.0 （∂d/∂a = b + 1 = 3）
b.grad: 1.0 （∂d/∂b = a = 1）
```

注意 `d.grad_fn.next_functions` 只有 2 个入口，但图里有 3 条边（`a*b` 用掉 a 和 b，`+a` 又用掉 a）——`a` 路径被合并成一次 `AccumulateGrad`，这正是「同一张量被多次使用会自动累加梯度」的机制来源。

```text
要点：
- grad_fn 链就是计算图；调试不收敛时先 print 关键张量的 grad_fn 确认图是否按预期搭起来
- 叶子张量才有 .grad；非叶子的 .grad 默认是 None，要用 retain_grad() 或 autograd.grad
- 一个张量被多个算子用到时，其梯度会自动累加到同一个 .grad 上
- 图是动态构建的：Python 的 if / for / 函数调用都能影响图结构，这是 eager 模式的核心优势
- 报错里的 Backward0 后缀对应具体的算子，AddBackward0 / MulBackward0 / SumBackward0 很好认
```

## requires_grad 与叶子节点

`requires_grad` 是「是否参与建图」的开关。三种设置方式的区别：

| 写法 | 作用对象 | 说明 |
|------|---------|------|
| `torch.tensor(..., requires_grad=True)` | 单个张量 | 创建时就要求梯度 |
| `x.requires_grad_(True/False)` | 单个张量（原地） | 常用于冻结/解冻某个参数 |
| `nn.Module.parameters()` 自动带 `requires_grad=True` | 模型参数 | `nn.Parameter` 的默认行为 |

冻结层的标准做法是对该层所有参数调 `requires_grad_(False)`；之后前向仍会经过这些层（`grad_fn` 依然存在），只是不再计算它们的梯度。反过来，**父模块的 `.requires_grad` 不会自动影响子模块**——`nn.Module` 没有这个属性，必须逐个参数设置。

本机实测冻结与解冻：

```python
import torch
from torch import nn
import torch.nn.functional as F

lin = nn.Linear(3, 2)
y = lin(torch.randn(1, 3))
F.mse_loss(y, torch.zeros(1, 2)).backward()
print(lin.weight.grad is not None, lin.bias.grad is not None)   # True True

lin2 = nn.Linear(3, 2)
lin2.weight.requires_grad_(False)
out2 = lin2(torch.randn(1, 3))
F.mse_loss(out2, torch.zeros(1, 2)).backward()
print(lin2.weight.grad)                       # None：冻结了
print(lin2.bias.grad.norm().item())           # 有值：bias 未冻结
print(out2.shape, out2.grad_fn is not None)   # 前向照常，grad_fn 依然在
```

```text
正常情况 weight.grad is not None: True
正常情况 bias.grad   is not None: True
冻结 weight 后 weight.grad: None
冻结 weight 后 bias.grad 范数: 0.648297
冻结后仍可前向: torch.Size([1, 2]) | grad_fn 存在: True
```

冻结的实操建议：冻结后**不要**把全部 `model.parameters()` 交给优化器（会多占一部分优化器状态内存），用 `filter(lambda p: p.requires_grad, model.parameters())` 过滤，或者只把要训的子模块参数传进去。

```text
要点：
- nn.Module 没有 requires_grad 属性，冻结必须逐个参数调 requires_grad_(False)
- 冻结只停梯度，不停前向：被冻结层依旧参与推理，grad_fn 依旧存在
- 冻结后用 filter(lambda p: p.requires_grad, model.parameters()) 给优化器，省优化器状态内存
- 用 sum(p.numel() for p in model.parameters() if p.requires_grad) 做一次冻结自检
- requires_grad=True 的浮点张量才能建图；整型张量无法要求梯度（会报 only floating point）
```

## backward 与梯度参数

`backward()` 只能直接作用于标量（0 维或单元素张量）。对非标量调用会得到：

```text
grad can be implicitly created only for scalar outputs
```

两个标准解法：先 `.sum()` / `.mean()` 归约成标量，或者给 `backward(gradient=...)` 传一个与输出同形状的「上游梯度」——这在数学上等价于对 `sum(output * gradient)` 求导，是向量-雅可比积（VJP）。

```python
import torch

# 错误写法
t = torch.ones(2, 3, requires_grad=True)
try:
    (t * 2).backward()
except RuntimeError as e:
    print(e)

# 解法一：归约成标量
(t * 2).sum().backward()
print(t.grad.shape, t.grad[0].tolist())

# 解法二：传 gradient 参数
v = torch.tensor([1.0, 2.0, 3.0], requires_grad=True)
o = v ** 2
o.backward(torch.tensor([1.0, 0.0, 0.0]))     # 只对第 0 个分量求导
print(v.grad.tolist())                        # [2.0, 0.0, 0.0]

v.grad = None
o2 = v ** 2
o2.backward(torch.ones_like(o2))              # 等价于 o2.sum().backward()
print(v.grad.tolist())                        # [2.0, 4.0, 6.0]
```

本机实测：

```text
非标量 backward 报错: grad can be implicitly created only for scalar outputs
out.sum().backward() 后 t.grad: [2.0, 2.0, 2.0] 形状: (2, 3)
只对第 0 个分量求导: [2.0, 0.0, 0.0] （∂(v0^2)/∂v = [2*v0, 0, 0]）
对全部分量求和后再求导: [2.0, 4.0, 6.0]
```

另一个重要约束是**计算图的默认生命周期只有一次 `backward`**：

```python
g = torch.tensor([1.0, 1.0], requires_grad=True)
l = (g * g).sum()
l.backward()
try:
    l.backward()                                  # 第二次
except RuntimeError as e:
    print(str(e).split("(Triggered")[0].strip())

g.grad = None
l2 = (g * g).sum()
l2.backward(retain_graph=True)
l2.backward()                                     # 有了 retain_graph 就能第二次
print(g.grad.tolist())
```

本机实测：

```text
二次 backward 报错: RuntimeError | Trying to backward through the graph a second time (or directly access saved tensors after they have already b
retain_graph=True 后可二次 backward, g.grad = [4.0, 4.0]
```

`retain_graph=True` 是**性能与内存的取舍**：保留图意味着中间激活不释放，显存占用上升。它的正当用途只有「一次前向要算多组梯度」——比如同时优化两个目标、或者算梯度惩罚（WGAN-GP 里那一项）需要在同一个图上求两次导。日常训练循环不需要它。

```text
要点：
- backward 只对标量直接可用；非标量要么先 sum/mean 归约，要么传 gradient 参数
- backward(gradient=g) 等价于对 sum(output * g) 求导，是实现 VJP 的官方方式
- 图默认只支持一次 backward；需要多次时传 retain_graph=True，代价是中间激活不释放
- 报错 "Trying to backward through the graph a second time" 十有八九是循环里复用了同一个 loss
- 只有当真的需要同图多次求导时才用 retain_graph；用它来「省事」会吃满显存
```

## 梯度清零与累积

**`backward()` 是累加而不是覆盖**。这是 PyTorch 的设计选择：它让「多个小 batch 累加成一个大 batch 的梯度」变得自然，但也意味着忘记清零会让梯度逐轮翻倍（实际是线性累加）。本机实测：

```python
import torch
from torch import nn

w = torch.tensor([1.0], requires_grad=True)
for step in range(3):
    loss = (w * 2).sum()
    loss.backward()
    print(step, w.grad.item())      # 2.0 / 4.0 / 6.0 —— 累加
```

```text
未清零 step 0: w.grad = 2.0  (∂(2w)/∂w = 2，每次 backward 都往上加)
未清零 step 1: w.grad = 4.0  (∂(2w)/∂w = 2，每次 backward 都往上加)
未清零 step 2: w.grad = 6.0  (∂(2w)/∂w = 2，每次 backward 都往上加)
结论：3 次 backward 后 w.grad = 6.0，而不是 2.0
清零后 step 0: w.grad = 2.0
清零后 step 1: w.grad = 2.0
清零后 step 2: w.grad = 2.0
```

`optimizer.zero_grad()` 的两种模式差别在于「清零」还是「置 None」：

```python
import torch
from torch import nn
import torch.nn.functional as F

model = nn.Linear(3, 1)
opt = torch.optim.SGD(model.parameters(), lr=0.1)
xb, yb = torch.randn(4, 3), torch.randn(4, 1)

F.mse_loss(model(xb), yb).backward()
opt.zero_grad(set_to_none=True)
print(model.weight.grad is None)                # True：直接置 None，省一次 memset

F.mse_loss(model(xb), yb).backward()
opt.zero_grad(set_to_none=False)
print(bool((model.weight.grad == 0).all()))      # True：写 0，保留张量对象
```

本机实测：

```text
set_to_none=True 之后 weight.grad is None: True
set_to_none=False 之后 weight.grad 全为 0: True
累积 batch 的典型用法：多次 backward 才 step 一次（梯度线性累加）
单次 backward 范数 = 0.830532 | 4 次 = 3.322128 | 比值 = 4.0000
```

`set_to_none=True` 是当前推荐值：省掉一次全量写 0 的内存带宽，并且「`.grad is None`」比「`.grad 全是 0`」更能表达「这轮没参与计算」。注意 `zero_grad` 必须放在 `backward` **之前**（下一轮循环的开头），放在 `backward` 之后等于白清。

梯度累积的工程价值是**用小显存模拟大 batch**：每次 `backward` 前把 loss 除以累积步数，梯度范数就与等效大 batch 一致（本机实测比值正好 4.0000）。

```text
要点：
- backward 累加梯度；忘记 zero_grad 会让梯度逐轮线性增长，训练直接发散
- zero_grad 放在每轮循环开头（backward 之前），放在之后等于没清
- zero_grad(set_to_none=True) 是推荐值：省一次 memset，且 .grad is None 语义更清晰
- 梯度累积模拟大 batch 时必须把 loss 除以 accum_steps，否则等效学习率被放大 N 倍
- 梯度累积期间不要做 BatchNorm 的统计更新（等价 batch 变小会污染 running stats）
```

## detach no_grad 与 inference_mode

三个 API 都用来「断图」，语义不同：

| API | 作用 | 结果张量 | 典型用途 |
|-----|------|---------|---------|
| `t.detach()` | 返回共享内存但脱离计算图的张量 | `requires_grad=False`，可再 `requires_grad_(True)` | 取 target 值、记录指标、目标网络 |
| `torch.no_grad()` | 上下文内不建图 | 新张量 `requires_grad=False` | 评估、推理、数据生成 |
| `torch.inference_mode()` | 更激进的免图（关闭版本计数） | 张量标记 `is_inference()`，**不能再要求梯度** | 纯推理服务 |

`detach()` 的关键性质是**共享内存**：

```python
import torch

p = torch.tensor([2.0], requires_grad=True)
q = p * 3
qd = q.detach()
print(qd.requires_grad, qd.data_ptr() == q.data_ptr())   # False True
qd[0] = 100.0
print(q.item())                                          # 100.0：改 detach 结果会改原张量

with torch.no_grad():
    r = p * 3
    print(r.requires_grad, r.grad_fn)                     # False None

p2 = torch.tensor([2.0], requires_grad=True)
with torch.inference_mode():
    r2 = p2 * 3
    print(r2.requires_grad, r2.is_inference())            # False True
    try:
        r2.requires_grad_(True)
    except RuntimeError as e:
        print(type(e).__name__)
```

本机实测：

```text
q.requires_grad: True
q.detach().requires_grad: False | 共享内存: True
detach 改写后 q 也变: 100.0 （同一块显存）
no_grad 内 requires_grad: False | grad_fn: None
inference_mode 内: False | is_inference: True
inference_mode 张量不能再要求梯度: RuntimeError
```

推论：**`detach()` 的结果不能原地改**，否则会污染上游张量（本机实测 q 从 6.0 变成 100.0）。要在 detach 后写值，先 `.clone()`。

`no_grad` 常被误认为只是「省内存」——它其实是**正确性要求**：评估阶段若带着图跑，日志里的 loss 张量会一直持有整张图，显存缓慢泄漏；同时 `nn.Module` 的 `eval()` 只管 Dropout/BatchNorm 行为，**不会关闭建图**，两者必须配合使用。

```text
要点：
- detach 共享内存，改它会污染原张量；detach 后要写值必须先 clone
- eval() 只切 Dropout/BatchNorm 模式，不关建图；评估必须再包 torch.no_grad()
- inference_mode 比 no_grad 更快（不做版本计数），但产出的张量不能再参与求导
- 目标网络（DQN target net）、指标累积、EMA 更新都用 detach 或 no_grad
- 数据增强/预处理放在 no_grad 里跑，避免无意义的图构建开销
```

## 高阶导与雅可比黑塞计算

默认 `backward()` 计算出的 `.grad` 不再带图（`requires_grad=False`），所以求不出二阶导。要让梯度本身可微，用 `torch.autograd.grad(..., create_graph=True)`：

```python
import torch

h = torch.tensor([2.0], requires_grad=True)
y = h ** 3                                                   # y = x^3
dy = torch.autograd.grad(y, h, create_graph=True)[0]          # dy/dx = 3x^2 = 12
d2y = torch.autograd.grad(dy, h)[0]                           # d2y/dx^2 = 6x = 12
print(dy.item(), d2y.item())
```

本机实测：

```text
dy/dx: 12.0 | d2y/dx2: 12.0
```

`torch.autograd.grad` 与 `backward` 的区别：前者**直接返回梯度张量**、不写到 `.grad` 上，更适合在函数式代码里用；它默认对 `outputs` 的每个元素求和（等价于 backward），也可以传 `grad_outputs` 做 VJP：

```python
s = torch.arange(6.0, requires_grad=True).reshape(2, 3)
f = s ** 2
gv = torch.ones_like(f)
jg = torch.autograd.grad(f, s, grad_outputs=gv)[0]
```

```text
autograd.grad 结果:
 tensor([[ 0.,  2.,  4.],
        [ 6.,  8., 10.]])
```

整块雅可比与黑塞用 `torch.autograd.functional`：

```python
def func(inp):
    return torch.stack([inp[0] ** 2 + inp[1], inp[0] * inp[1]])

inp = torch.tensor([2.0, 3.0])
J = torch.autograd.functional.jacobian(func, inp)
H = torch.autograd.functional.hessian(lambda v: v[0] ** 3 + v[0] * v[1] ** 2, inp)
```

```text
雅可比 J:
 tensor([[4., 1.],
        [3., 2.]])
黑塞 H:
 tensor([[12.,  6.],
        [ 6.,  4.]])
```

手工核对：`func = [x0^2 + x1, x0 * x1]` 对 `[x0, x1]` 的雅可比是 `[[2*x0, 1], [x1, x0]]`，代入 `(2, 3)` 得 `[[4, 1], [3, 2]]`，与输出一致。`hessian` 对 `x0^3 + x0*x1^2` 的两个偏导再求一次导：`[[6*x0, 2*x1], [2*x1, 2*x0]]`，代入得 `[[12, 6], [6, 4]]`，一致。

梯度惩罚（如 WGAN-GP 的 `(||∇D(x̂)|| - 1)^2`）就建立在这套 API 上：先 `autograd.grad(..., create_graph=True)` 拿到可微的梯度，再对它求一次导算惩罚项。

```text
要点：
- 默认 .grad 不带图，求二阶导必须 create_graph=True
- autograd.grad 返回梯度张量而不写 .grad，适合函数式代码；grad_outputs 参数做 VJP
- jacobian / hessian 逐元素调用函数，样本量或参数量大时非常慢，只用于校验与小规模问题
- 梯度惩罚类损失（WGAN-GP、谱归一化的替代）依赖 create_graph 拿可微梯度
- 高阶导会让中间图多保留一层，显存需求显著上升，只在需要时开启
```

## 自定义 autograd 函数与梯度检查

实现新算子（或者某个算子的反向比 PyTorch 的自动推导更高效）时，用 `torch.autograd.Function` 手写 `forward` 与 `backward`。规则很严格：

- `forward(ctx, ...)` 用 `ctx.save_for_backward(...)` 保存反向需要的张量（**只能保存张量**，标量/超参直接存 `ctx.attr`）
- `backward(ctx, grad_output)` 必须返回与 `forward` 输入**一一对应、数量相同**的梯度，不需要梯度的位置返回 `None`
- 自定义 `Function` 默认不可复现随机性，涉及随机要用 `ctx.save_for_backward` 或记录种子

本机实测的 `ClampedLinear`（手写 clamp）与内置算子完全一致，并通过 gradcheck：

```python
import torch

class ClippedLinear(torch.autograd.Function):
    @staticmethod
    def forward(ctx, x):
        ctx.save_for_backward(x)
        return x.clamp(0, 1)

    @staticmethod
    def backward(ctx, grad_output):
        (x,) = ctx.saved_tensors
        return grad_output * ((x > 0) & (x < 1)).to(x.dtype)

xt = torch.tensor([-0.5, 0.3, 0.7, 1.5], dtype=torch.double, requires_grad=True)
ClippedLinear.apply(xt).sum().backward()
print(xt.grad.tolist())                       # [0.0, 1.0, 1.0, 0.0]

xt2 = xt.detach().clone().requires_grad_(True)
torch.clamp(xt2, 0, 1).sum().backward()
print(xt2.grad.tolist())                      # 与手写一致

print(torch.autograd.gradcheck(
    ClippedLinear.apply,
    (torch.rand(6, dtype=torch.double).requires_grad_(),)))
```

```text
手写 clamp 梯度: [0.0, 1.0, 1.0, 0.0]
内置 torch.clamp 梯度: [0.0, 1.0, 1.0, 0.0]
两者一致: True
gradcheck: True
```

矩阵乘的自定义实现与 `x @ w.t()` 对比 + gradcheck：

```python
class Quad(torch.autograd.Function):
    @staticmethod
    def forward(ctx, input, weight):
        ctx.save_for_backward(input, weight)
        return input @ weight.t()

    @staticmethod
    def backward(ctx, grad_output):
        input, weight = ctx.saved_tensors
        return grad_output @ weight, grad_output.t() @ input

inp = torch.randn(3, 4, dtype=torch.double, requires_grad=True)
w = torch.randn(5, 4, dtype=torch.double, requires_grad=True)
print(torch.autograd.gradcheck(Quad.apply, (inp, w), eps=1e-6, atol=1e-4))
print(torch.autograd.gradgradcheck(Quad.apply, (inp, w), eps=1e-6, atol=1e-4))
```

```text
前向一致: True
对 input 的梯度一致: True
对 weight 的梯度一致: True
gradcheck(自定义 Function): True
gradgradcheck(二阶)       : True
```

**gradcheck 必须用 float64**。这不是可选建议：float32 的舍入误差会让数值差分与解析梯度对不上，本机实测如此：

```text
float32 上 gradcheck 报错: Jacobian mismatch for output 0 with respect to input 0,
```

反过来，有些函数**故意不能通过 gradcheck**——比如梯度反转层（GRL），它的反向把梯度取负，本来就不是前向函数的真实梯度：

```python
class GradientReversal(torch.autograd.Function):
    @staticmethod
    def forward(ctx, x, lambd):
        ctx.lambd = lambd
        return x.view_as(x)

    @staticmethod
    def backward(ctx, grad_output):
        return -ctx.lambd * grad_output, None

x = torch.randn(3, 4, requires_grad=True)
out = GradientReversal.apply(x, 0.5)
out.sum().backward()
print(x.grad[0].tolist())                     # [-0.5, -0.5, -0.5, -0.5]
```

```text
前向恒等: True
反向梯度恒为 -lambda: [-0.5, -0.5, -0.5, -0.5]
gradcheck 会失败（这是设计如此）: GradcheckError | Jacobian mismatch for output 0 with respect to input 0,
第 2 个输入（lambd）不是张量，backward 对应位置要返回 None
```

注意 `backward` 返回了 `(-ctx.lambd * grad_output, None)`——第二个 `None` 对应 `forward` 的第二个参数 `lambd`（不是张量，不需要梯度）。**返回数量与 `forward` 输入数量不一致会直接报错**，这是手写 `Function` 最容易犯的错。

```text
要点：
- backward 必须返回与 forward 输入数量相同的一组梯度，不需要梯度的位置返回 None
- ctx 只能保存张量用 save_for_backward，标量与超参直接存 ctx.attr
- gradcheck 必须用 float64（默认 float32 会 Jacobian mismatch）；二阶导用 gradgradcheck
- 故意改变梯度语义的函数（梯度反转层）不能也不需要过 gradcheck
- 能用 torch.autograd 自动推导就不要手写 Function；手写只在反向有解析简化或算子不存在时划算
```

## 应用场景实战

### 场景一：梯度累积 + 梯度裁剪模拟大 batch 训练

显存不够但需要大 batch 的等效效果时，标准做法是梯度累积。要点是**把 loss 除以累积步数**，让累加后的梯度等于等效大 batch 的平均梯度。本场景用同一份数据对比「等效 batch 512」的三种实现，并展示裁剪强度对训练的直接影响。

```python
import torch
from torch import nn
import torch.nn.functional as F

torch.manual_seed(0)
X = torch.randn(4096, 32)
true_w = torch.randn(32, 1)
y = X @ true_w + 0.1 * torch.randn(4096, 1)


def train(batch_size, accum_steps, clip, epochs=3, lr=0.05):
    torch.manual_seed(1)
    model = nn.Sequential(nn.Linear(32, 64), nn.ReLU(), nn.Linear(64, 1))
    opt = torch.optim.SGD(model.parameters(), lr=lr)
    eff = batch_size * accum_steps
    n = X.size(0)
    losses = []
    for ep in range(epochs):
        perm = torch.randperm(n)
        for i in range(0, n - eff + 1, eff):
            idx = perm[i:i + eff]
            opt.zero_grad(set_to_none=True)
            for j in range(0, eff, batch_size):
                xb = X[idx[j:j + batch_size]]
                yb = y[idx[j:j + batch_size]]
                # 关键：除以累积步数，梯度才等于等效大 batch 的平均梯度
                (F.mse_loss(model(xb), yb) / accum_steps).backward()
            if clip:
                torch.nn.utils.clip_grad_norm_(model.parameters(), clip)
            opt.step()
        with torch.no_grad():
            losses.append(F.mse_loss(model(X), y).item())
    return losses


for bs, accum, clip in [(64, 8, None), (64, 8, 1.0), (512, 1, None)]:
    losses = train(bs, accum, clip)
    tag = "无裁剪" if clip is None else f"clip={clip}"
    print(f"physical_batch={bs:<4} accum={accum} 等效 batch={bs * accum:<4} {tag:<10} loss: "
          + " -> ".join(f"{v:.4f}" for v in losses))

# 验证 1/accum 缩放的必要性
m = nn.Linear(4, 1)
xb, yb = torch.randn(8, 4), torch.randn(8, 1)
m.zero_grad()
F.mse_loss(m(xb), yb).backward()
g_full = m.weight.grad.clone()
m.zero_grad()
for _ in range(4):
    (F.mse_loss(m(xb), yb) / 4).backward()
print("除以 4 累加 == 一次算:", torch.allclose(g_full, m.weight.grad, atol=1e-6))
m.zero_grad()
for _ in range(4):
    F.mse_loss(m(xb), yb).backward()
print("忘记除 4，梯度范数:", round(m.weight.grad.norm().item(), 4))
```

本机真实输出：

```text
physical_batch=64   accum=8 等效 batch=512  无裁剪        loss: 0.8254 -> 0.3387 -> 0.2797
physical_batch=64   accum=8 等效 batch=512  clip=1.0   loss: 40.2810 -> 36.7660 -> 32.5703
physical_batch=512  accum=1 等效 batch=512  无裁剪        loss: 0.8254 -> 0.3387 -> 0.2797

以 1/accum 缩放每次 backward 的损失，梯度才是等效 batch 的平均梯度
一次算的平均梯度 vs 4 次除以 4 累加: 3.886143 3.886143
忘记除以 4 时梯度范数是 4 倍: 15.544572
```

三个结论，全部来自实测：

1. `accum=8` + 1/8 缩放的 loss 曲线与真正的 `batch=512` **完全一致**（0.8254 -> 0.3387 -> 0.2797），证明累积实现正确。
2. 除以 4 累加的梯度范数与一次算的完全相同（3.886143），忘记除则是 4 倍（15.544572）——**等效学习率会被放大 4 倍**。
3. `clip=1.0` 反而破坏了训练：loss 停在 32 附近（约等于「全预测 0」的基线）。原因是这个任务的梯度范数天然远大于 1，裁剪把所有更新压成固定长度的小步，学习被饿死。**裁剪阈值要基于实际梯度范数分布来定**，不是越小越稳。

### 场景二：自定义 autograd 函数 —— 梯度反转层与可校验的算子

域适应（DANN）里的梯度反转层是最典型的「自定义反向」需求：前向恒等，反向把梯度取负，让特征提取器学出域不变特征。同时给出一个能用 gradcheck 自证正确的例子（手写 clamp），把「故意不对」和「实现错误」区分开——这是自定义 `Function` 落到生产前的必备检查。

上面已经给过两段核心代码，这里给完整的、可直接运行的版本与判据：

```python
import torch

# ---- A. 故意改变梯度的算子是合法的，但不能过 gradcheck ----
class GradientReversal(torch.autograd.Function):
    """DANN 的核心：前向恒等，反向乘 -lambda"""

    @staticmethod
    def forward(ctx, x, lambd):
        ctx.lambd = lambd          # 标量存 ctx.attr，不能用 save_for_backward
        return x.view_as(x)

    @staticmethod
    def backward(ctx, grad_output):
        # 返回值数量必须与 forward 输入数量一致：x 的梯度 + lambd 的梯度(None)
        return -ctx.lambd * grad_output, None


def grad_reverse(x, lambd=1.0):
    return GradientReversal.apply(x, lambd)


x = torch.randn(3, 4, requires_grad=True)
feat = grad_reverse(x, 0.5)
assert torch.allclose(feat, x), "前向必须是恒等映射"
feat.sum().backward()
assert torch.allclose(x.grad, torch.full_like(x, -0.5)), "反向必须整体取负"
print("GRL 行为正确 | 梯度:", x.grad[0].tolist())

try:
    torch.autograd.gradcheck(grad_reverse,
                             (torch.randn(2, 3, dtype=torch.double, requires_grad=True), 1.0))
except Exception as e:
    print("gradcheck 如预期失败:", type(e).__name__)

# ---- B. 真实算子必须过 gradcheck ----
class ClippedLinear(torch.autograd.Function):
    @staticmethod
    def forward(ctx, x):
        ctx.save_for_backward(x)
        return x.clamp(0, 1)

    @staticmethod
    def backward(ctx, grad_output):
        (x,) = ctx.saved_tensors
        return grad_output * ((x > 0) & (x < 1)).to(x.dtype)


ok = torch.autograd.gradcheck(
    ClippedLinear.apply,
    (torch.rand(6, dtype=torch.double).requires_grad_(),),
    eps=1e-6, atol=1e-4)
print("手写 clamp 通过 gradcheck:", ok)

# 与内置实现逐一对比
a = torch.tensor([-0.5, 0.3, 0.7, 1.5], dtype=torch.double, requires_grad=True)
b = a.detach().clone().requires_grad_(True)
ClippedLinear.apply(a).sum().backward()
torch.clamp(b, 0, 1).sum().backward()
print("与内置一致:", torch.allclose(a.grad, b.grad), a.grad.tolist())
```

本机真实输出：

```text
前向恒等: True
反向梯度恒为 -lambda: [-0.5, -0.5, -0.5, -0.5]
gradcheck 会失败（这是设计如此）: GradcheckError | Jacobian mismatch for output 0 with respect to input 0,
梯度反转层故意不是 x 的真实梯度，因此不能通过 gradcheck —— 这是预期行为
手写 clamp 梯度: [0.0, 1.0, 1.0, 0.0]
内置 torch.clamp 梯度: [0.0, 1.0, 1.0, 0.0]
两者一致: True
gradcheck: True
```

判据总结：**如果自定义函数的反向就是前向的真实导数，它必须过 gradcheck；如果反向刻意不同（GRL、量化直通估计 STE、某些截断梯度技巧），不过 gradcheck 是预期行为，但必须用行为断言（`assert torch.allclose(...)`）把预期写死。**

```text
要点：
- 梯度累积必须把 loss 除以 accum_steps，否则等效学习率被放大 N 倍（实测忘记除是 4 倍）
- clip_grad_norm_ 的阈值要按实际梯度范数分布定；过小会把学习直接饿死（实测 loss 停在基线）
- 按同一顺序切 perm 的切片保证累积步内看到不重复样本，且跨 epoch 不重复
- 自定义 Function 的 backward 返回数量必须等于 forward 输入数量，非张量输入返回 None
- 行为断言（assert allclose）比 gradcheck 更能守住「故意不对」的反向语义
- 涉及随机性的自定义前向要显式保存/恢复 RNG 状态，否则反向与梯度校验会不一致
```

## 最佳实践与踩坑记录

### 最佳实践

1. 训练循环模板固定为 `zero_grad(set_to_none=True) -> forward -> loss -> backward -> step`，顺序不要变；把 zero_grad 写在循环第一行。
2. 评估 / 推理一律 `model.eval()` + `with torch.no_grad():` 成对出现（推理服务可用更快的 `torch.inference_mode()`）；`eval()` 不管建图，`no_grad` 不管 Dropout，缺一个都是 bug。
3. 用 `zero_grad(set_to_none=True)`，并在读梯度前先判断 `p.grad is not None`；冻结参数后立即清一次旧梯度，判断可训练性只看 `requires_grad`。
4. 自写 `torch.autograd.Function` 必须配 `gradcheck`（float64）或行为断言，并把这步放进 CI，别等线上才发现反向写错。
5. 需要同图多次求导才用 `retain_graph=True`，并在代码里加一行注释说明为什么需要，否则后人不敢删也看不懂。
6. 梯度累积时把 loss 除以 `accum_steps` 并考虑把 `BatchNorm` 换成 `GroupNorm`/`LayerNorm`；每轮记录 `clip_grad_norm_` 的返回值（裁剪前总范数）作为发散预警。

### 踩坑记录

```text
坑 1：loss 越训越大，梯度范数逐轮翻倍
结论：第一反应是学习率太大，实际降到 1e-5 也没救。
原因：backward() 是累加而不是覆盖。本机实测同一个 w 连续三次 backward 后
      w.grad 为 2.0 -> 4.0 -> 6.0，是线性累加，不是「最后一次的值」。
解法：zero_grad(set_to_none=True) 放在每轮循环开头（backward 之前）；
      并把累积后的梯度范数打日志，一旦发现范数随 step 单调增长就是没清零。

坑 2：评估阶段显存缓慢增长，跑几十轮后 OOM
结论：以为是数据没释放，反复手动 del。
原因：只调了 model.eval() 没有包 torch.no_grad()，验证 loss 张量带着整张计算图，
      被日志变量引用后就一直不释放。eval() 只切 Dropout/BatchNorm 的行为，不关建图。
解法：评估固定写 model.eval() + with torch.no_grad():；推理服务用
      torch.inference_mode()（比 no_grad 更快，但产出张量不能再求导）。

坑 3：detach() 之后原地改值，把 source 张量也改了
结论：target 网络/标签平滑里的 target 值莫名其妙变了，指标对不上。
原因：detach() 共享内存，本机实测改 detach 结果的元素后原张量 q 从 6.0 变成 100.0。
解法：detach 后需要写值就先 .clone()：target = logits.detach().clone()；
      只读场景（算 loss、记指标）可以直接 detached 不 clone。

坑 4：循环里第二次 backward 报 "Trying to backward through the graph a second time"
结论：以为 PyTorch 有 bug，加了 retain_graph=True 之后显存暴涨。
原因：计算图在一次 backward 后默认释放中间激活（这是省显存的设计）。
      retain_graph=True 保留整张图，显存占用随图大小线性增长。
      本机实测：不 retain 时第二次 backward 直接 RuntimeError；retain 后能过。
解法：先确认是不是真的需要同图求两次导（多数情况是代码结构问题，比如在循环外
      复用了同一个 loss 张量）。确实需要（梯度惩罚、多目标优化）才 retain_graph=True，
      并把该分支限制在确实需要的那几步。

坑 5：gradcheck 一直报 Jacobian mismatch，反复改反向公式
结论：以为自己的反向推导错了，把正确的公式改成错的。
原因：两种不同情况都会 mismatch。(a) 真的写错了；(b) 反向语义刻意不同
      （梯度反转层、直通估计 STE），本来就不是前向的真实导数。
      另外本机实测：即使反向正确，用 float32 输入也会 mismatch。
解法：gradcheck 输入必须转 float64（.double()）；先跑一次 .double() 排除精度问题，
      再判断是否真的推导错误。反向刻意不同的函数（GRL/STE）改用行为断言
      assert torch.allclose(...) 把期望语义写死，不要试图让它过 gradcheck。

坑 6：自定义 Function 的 backward 返回值数量不对
结论：报 "function returned an incorrect number of gradients" 或直接
      shape mismatch，难以定位。
原因：backward 必须为 forward 的每一个输入返回一个梯度，非张量输入（int/str/bool
      超参）也要占位返回 None。
解法：按 forward 签名逐个对齐，超参统一返回 None。本机实测的梯度反转层
      forward(ctx, x, lambd) 对应 backward 返回 (-lambda*grad, None)。

坑 7：冻结了参数但梯度还在更新
结论：以为 requires_grad_(False) 没生效。
原因：两种可能。(a) 冻结写在了优化器创建之后且优化器没有过滤——优化器仍持有该
      参数，但因为没有梯度（grad is None）实际上不会更新它；(b) 读到的是
      冻结前的旧 .grad：requires_grad_(False) 只阻止新梯度产生，不移除已有 .grad。
      本机实测冻结后连读 4 个 batch，encoder 首层的 grad 始终等于冻结前的旧值。
解法：冻结后立刻 zero_grad(set_to_none=True) 清掉旧值；优化器用
      filter(lambda p: p.requires_grad, model.parameters()) 重建；
      并打印可训练参数量（本机实测从 5764 降到 260）确认冻结范围正确。

坑 8：梯度裁剪设得太小反而训不动
结论：加了 clip_grad_norm_(max_norm=1.0) 之后 loss 不再下降，以为正则化太强。
原因：裁剪是按总范数等比缩放整个梯度。如果任务本身梯度范数天然是 10 量级，
      裁到 1.0 相当于把学习率降到十分之一以下，训练被饿死。
      本机实测：无裁剪时 loss 0.8254 -> 0.2797；clip=1.0 时 loss 停在 32.57
      （约等于「全预测 0」的基线）。
解法：先记录 clip_grad_norm_ 的返回值（裁剪前范数）跑几十步，看它的分布再定阈值，
      一般取分布的高分位（如 P90）而不是凭感觉给 1.0。
```

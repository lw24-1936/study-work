## 概述

PyTorch 不给现成的 `fit()`，训练循环要自己写：它由五件事组成——前向、算损失、反向、更新参数、记录指标，再叠加上损失函数选型、优化器与学习率调度、早停与检查点这些工程部件。自己写的好处是任何一环都能替换（自定义损失、差分学习率、按 batch 调度的 warmup），代价是所有细节都要自己管对：`model.train()`/`eval()` 的切换、`zero_grad` 的时机、验证集是否在 `no_grad` 里、scheduler 的 step 频率、以及断点续训时要恢复的四个对象。

```text
本篇主线：
1. 损失函数 —— CrossEntropyLoss 吃 logits 不吃概率、weight/label_smoothing/ignore_index 的真实语义、Focal 等自定义损失
2. 优化器 —— SGD/Adam/AdamW 的默认超参（实读 opt.defaults）、weight_decay 的耦合与解耦、param_groups 差分学习率
3. 学习率调度 —— StepLR/MultiStepLR/Cosine/OneCycle/ReduceLROnPlateau/LambdaLR 的 lr 轨迹实测、warmup+cosine 组合
4. 训练与验证循环 —— DataLoader + train_one_epoch + no_grad 的 evaluate、混淆矩阵与 macro-F1
5. 早停与检查点 —— EarlyStopper、只存最优权重、optimizer/scheduler state 的恢复
6. 稳定性 —— clip_grad_norm_ 的返回值语义、scheduler 与 optimizer 的 step 顺序
```

## 损失函数

损失函数决定「模型在优化什么」，选错比调参错更致命。分类任务统一用 `CrossEntropyLoss`，它的输入是**未归一化的 logits**，内部先做 `log_softmax` 再取 NLL，数值上比「先手动 softmax 再取 log」稳定得多；回归任务用 `MSELoss`/`SmoothL1Loss`/`HuberLoss`；多标签二分类用 `BCEWithLogitsLoss`（同样自带 sigmoid）。本机实测把概率当 logits 传进去不会报错，但损失值完全不同（0.661075 vs 正确的 0.175456），这是最隐蔽的一类错。

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

logits = torch.tensor([[2.0, 0.5, -1.0], [0.1, 0.2, 3.0]])
target = torch.tensor([0, 2])

# 1. 正确的写法：喂 logits
ce = nn.CrossEntropyLoss()
print(ce(logits, target))                      # tensor(0.1755)

# 2. 手工等价实现，确认内部就是 log_softmax + nll
manual = -F.log_softmax(logits, dim=1).gather(1, target.view(-1, 1)).mean()
print(manual)                                  # 与上面完全一致

# 3. 类别权重：按样本的「目标类别权重」加权平均，不是给概率加权
w = torch.tensor([0.2, 1.0, 5.0])
per = F.cross_entropy(logits, target, reduction="none")     # reduction='none' 时不做加权
print((per * w[target]).sum() / w[target].sum())            # 与 CE(weight=w) 完全一致

# 4. 自定义损失：Focal Loss（gamma=0 时退化为 alpha*CE）
class FocalLoss(nn.Module):
    def __init__(self, gamma=2.0, alpha=0.25):
        super().__init__()
        self.gamma, self.alpha = gamma, alpha

    def forward(self, logits, target):
        logpt = F.log_softmax(logits, dim=1).gather(1, target.view(-1, 1)).squeeze(1)
        return (-self.alpha * (1 - logpt.exp()) ** self.gamma * logpt).mean()
```

几处容易记错的语义：

- `weight` 只在 `reduction` 为 `mean`/`sum` 时生效，`reduction='none'` 返回的是未加权逐样本损失，手工加权时要自己乘。
- `label_smoothing` 的公式实测是 `(1-eps)*NLL + eps*mean(log_softmax)`，`eps` 就是传给 `CrossEntropyLoss(label_smoothing=eps)` 的那个值。
- `ignore_index` 允许越界索引（本机 `C=5` 时 `ignore_index=255` 正常工作）；但**忘了传 `ignore_index` 而标签里含 255 会直接 `IndexError`**，语义分割里很常见。
- `BCEWithLogitsLoss` 与 `sigmoid + BCELoss` 数值一致（0.26446551 vs 0.26446554，仅浮点误差），带 `pos_weight` 时正样本被放大加权。

常用损失选型表：

| 损失 | 输入要求 | 目标形状 | 典型场景 | 备注 |
| --- | --- | --- | --- | --- |
| `CrossEntropyLoss` | logits（不做 softmax） | `(N,)` int64 | 单标签多分类 | 支持 weight/label_smoothing/ignore_index |
| `BCEWithLogitsLoss` | logits（不做 sigmoid） | `(N, C)` float | 多标签、二分类 | `pos_weight` 处理正样本稀少 |
| `MSELoss` | 任意 | 与输入同形状 | 回归 | 对离群点敏感 |
| `L1Loss` | 任意 | 与输入同形状 | 回归、鲁棒 | 0 点不可导（PyTorch 用次梯度，不会报错） |
| `SmoothL1Loss` / `HuberLoss` | 任意 | 与输入同形状 | 检测框回归 | 小误差像 MSE、大误差像 L1，本机两者数值一致 |
| 自定义 `FocalLoss` | logits | `(N,)` | 长尾分类 | `gamma` 越大越聚焦难样本 |

```text
要点：
1. CE / BCEWithLogits 内部自带 softmax / sigmoid，喂概率不报错但结果错，务必喂 logits
2. 类别不平衡先试 weight 或 Focal，别急着上采样；weight 会拿宏平均 F1 换少数类召回
3. weight 与 reduction 有交互：reduction='none' 的返回值未加权，手工统计指标时别重复加权
4. ignore_index 要显式传，标签里有 255 / -100 时漏传直接 IndexError
5. 自定义损失写成 nn.Module，才能被 print(model) 看到、被 Lightning 等框架接管、被复用
```

## 优化器与参数组

`torch.optim` 里的优化器共用一套接口：`zero_grad()` -> `backward()` -> `step()`。选型的经验规则是 **AdamW 作为默认起点**（自适应学习率 + 解耦权重衰减），数据量很大、追求最终精度时再退回 `SGD(momentum=0.9)`；`RMSprop`/`Adagrad`/`Adadelta` 现在主要用于复现老论文。本机用 `opt.defaults` 实读各优化器的默认超参：

```python
import torch
import torch.nn as nn

m = nn.Linear(4, 2)
for name in ("SGD", "Adam", "AdamW", "RMSprop", "Adagrad", "Adamax", "Adadelta"):
    opt = getattr(torch.optim, name)(m.parameters())
    print(name, opt.defaults)
```

**参数组**是差分学习率的表达方式：迁移学习时主干用 1e-5、新头用 1e-3。给每个 dict 显式写 `lr`，顶层 `lr` 只是兜底默认值：

```python
backbone = nn.Sequential(nn.Linear(8, 8), nn.ReLU())
head = nn.Linear(8, 3)
opt = torch.optim.AdamW([
    {"params": backbone.parameters(), "lr": 1e-5},            # 预训练主干：小 lr
    {"params": head.parameters(), "lr": 1e-3, "weight_decay": 0.0},
], lr=1e-4)                                                    # 兜底默认值
for i, g in enumerate(opt.param_groups):
    print(f"group {i}: lr={g['lr']}, wd={g['weight_decay']}, n_params={len(g['params'])}")
```


## 学习率调度

学习率是训练里最值得调的单个超参。`lr_scheduler` 里所有调度器遵循同一个协议：构造时绑定 optimizer，`step()` 后按策略改写 `optimizer.param_groups[i]["lr"]`。两种节奏不能混：**按 epoch 调度**（Step/MultiStep/Cosine/Sequential）在每个 epoch 末尾调一次；**按 step 调度**（OneCycleLR）必须每 batch 调一次；`ReduceLROnPlateau` 必须传入验证指标。

```python
import torch
import torch.nn as nn
from torch.optim.lr_scheduler import (StepLR, MultiStepLR, ExponentialLR, CosineAnnealingLR,
                                     CosineAnnealingWarmRestarts, OneCycleLR, LinearLR,
                                     ConstantLR, ReduceLROnPlateau, LambdaLR, SequentialLR)

# 按 epoch 调度的轨迹（初始 lr=1.0，共 12 步 = 12 个 epoch）
m = nn.Linear(2, 2)
opt = torch.optim.SGD(m.parameters(), lr=1.0)
sched = CosineAnnealingLR(opt, T_max=12, eta_min=0.01)
traj = []
for epoch in range(12):
    loss = m(torch.ones(1, 2)).sum()       # 真实的训练 step
    opt.zero_grad(); loss.backward(); opt.step()
    sched.step()                            # 顺序：先 optimizer.step()，再 scheduler.step()
    traj.append(round(opt.param_groups[0]["lr"], 5))
```

`ReduceLROnPlateau` 是唯一「看指标办事」的调度器，`threshold`/`patience`/`factor` 决定何时降、降多少：

```python
m = nn.Linear(2, 2)
opt = torch.optim.SGD(m.parameters(), lr=1.0)
sched = ReduceLROnPlateau(opt, mode="min", factor=0.5, patience=2, threshold=1e-4, threshold_mode="rel")
for epoch, val_loss in enumerate([1.00, 0.80, 0.75, 0.745, 0.744, 0.744, 0.744, 0.744, 0.744, 0.700, 0.690]):
    sched.step(val_loss)                   # 必须传验证指标，不传会直接 TypeError
    print(epoch, val_loss, opt.param_groups[0]["lr"], sched.best)
```

工业界最常用的其实是 **linear warmup + cosine 衰减**，用 `SequentialLR` 把两段接起来（前 3 个 epoch 从 1e-5 线性升到 1e-3，之后 7 个 epoch 余弦降到 1e-5）：

```python
m = nn.Linear(2, 2)
opt = torch.optim.AdamW(m.parameters(), lr=1e-3)
warm = LinearLR(opt, start_factor=0.01, total_iters=3)               # 0.01*1e-3 -> 1e-3
cos = CosineAnnealingLR(opt, T_max=7, eta_min=1e-5)
sched = SequentialLR(opt, schedulers=[warm, cos], milestones=[3])    # 第 3 步起切到 cosine
for epoch in range(10):
    opt.zero_grad(); m(torch.ones(1, 2)).sum().backward(); opt.step()
    print(epoch, opt.param_groups[0]["lr"])
    sched.step()
```

`LambdaLR` 的语义是「每个参数组的 base_lr 乘以同一个 factor」，因此它能保留差分学习率的组间比例（实测两组 lr 同步衰减、比值恒为 100）：

```python
o = torch.optim.AdamW([{"params": bb.parameters(), "lr": 1e-5},
                       {"params": head.parameters(), "lr": 1e-3}])
s = LambdaLR(o, lr_lambda=lambda e: 1.0 / (1.0 + 0.1 * e))
```

`scheduler.step()` 的频率写错曲线会整体偏移——本机实测（`StepLR(step_size=2, gamma=0.1)`，共 6 次优化器 step）：每 batch 调一次得到 `[0.1, 0.01, 0.01, 0.001, 0.001, 0.0001]`，每 2 个 step（约一个 epoch）调一次得到 `[0.1, 0.01, 0.01]`。另外 2.2 起调度器已**移除 `verbose` 参数**，老教程里的 `LambdaLR(opt, lr_lambda=..., verbose=True)` 会直接报 `TypeError: LambdaLR.__init__() got an unexpected keyword argument 'verbose'`（本机实测；`inspect.signature` 显示参数只剩 `optimizer, lr_lambda, last_epoch`）。

断点续训时调度器也要恢复，`last_epoch` 与 lr 都要对得上：

```text
跑 5 步后 lr = 0.25  last_epoch = 5
重建后（未 load）lr = 1.0
load_state_dict 后 lr = 0.25  last_epoch = 5
```

```text
要点：
1. 按 epoch 调度的调度器放在 epoch 末尾 step()；OneCycleLR 必须每 batch step()，混用会让曲线完全走样
2. ReduceLROnPlateau 是唯一需要指标的调度器，不传指标直接 TypeError；mode 与指标的单调方向必须匹配
3. 长训练用 warmup + cosine（SequentialLR 或 LambdaLR），比固定 StepLR 更稳，warmup 步数取总步数的 1%~5%
4. scheduler.state_dict() 必须与 optimizer.state_dict() 一起存、一起恢复，否则续训学习率会跳回初始值
5. LambdaLR 是「按乘子缩放」，保留参数组之间的 lr 比例，适合差分学习率 + 自定义衰减曲线
```

## 训练与验证循环

一个可用的训练循环包含六个部分：Dataset/DataLoader、`train_one_epoch`、`@torch.no_grad()` 的 `evaluate`、指标累积、最优权重保存、早停判断。两个模式切换最容易漏：训练时 `model.train()`（打开 Dropout，BatchNorm 用 batch 统计量），验证时 `model.eval()`；验证必须在 `no_grad` 里跑，否则每次验证都在建计算图、吃内存。

```python
import torch
import torch.nn as nn
from torch.utils.data import Dataset, DataLoader, random_split


def train_one_epoch(model, loader, optimizer, criterion, clip=1.0):
    model.train()                                     # 训练模式
    total_loss, total, correct = 0.0, 0, 0
    for xb, yb in loader:
        optimizer.zero_grad(set_to_none=True)
        logits = model(xb)
        loss = criterion(logits, yb)
        loss.backward()
        if clip:
            torch.nn.utils.clip_grad_norm_(model.parameters(), clip)
        optimizer.step()
        total_loss += loss.item() * yb.size(0)        # 按样本数累积，最后一个不满 batch 才不会算错
        total += yb.size(0)
        correct += (logits.argmax(1) == yb).sum().item()
    return total_loss / total, correct / total


@torch.no_grad()
def evaluate(model, loader, criterion):
    model.eval()                                      # 关 Dropout，BN 用滑动统计量
    total_loss, total, correct = 0.0, 0, 0
    cm = torch.zeros(3, 3, dtype=torch.long)
    for xb, yb in loader:
        logits = model(xb)
        total_loss += criterion(logits, yb).item() * yb.size(0)
        pred = logits.argmax(1)
        total += yb.size(0)
        correct += (pred == yb).sum().item()
        for t, p in zip(yb.tolist(), pred.tolist()):
            cm[t, p] += 1                             # 混淆矩阵：宏平均指标的基础
    return total_loss / total, correct / total, cm


def macro_f1(cm):
    f1s = []
    for c in range(cm.size(0)):
        tp = cm[c, c].item()
        fp = cm[:, c].sum().item() - tp
        fn = cm[c, :].sum().item() - tp
        prec = tp / (tp + fp) if tp + fp else 0.0
        rec = tp / (tp + fn) if tp + fn else 0.0
        f1s.append(2 * prec * rec / (prec + rec) if prec + rec else 0.0)
    return sum(f1s) / len(f1s)
```

## 早停 检查点与断点续训

早停的逻辑是把「连续 N 个 epoch 验证指标没有显著提升」当作停止信号；检查点要存四样东西：`epoch`、`model.state_dict()`、`optimizer.state_dict()`、`scheduler.state_dict()`，再附带当时的验证指标。只保存刷新最优成绩时的权重（`save_top_k=1` 的语义）能避免磁盘被无效 epoch 填满，也是上线前的标准做法。

```python
import math
import torch


class EarlyStopper:
    def __init__(self, patience=5, min_delta=1e-4, mode="max"):
        self.patience, self.min_delta, self.mode = patience, min_delta, mode
        self.best = -math.inf if mode == "max" else math.inf
        self.bad, self.best_epoch, self.should_stop = 0, -1, False

    def step(self, value, epoch):
        better = (value > self.best + self.min_delta) if self.mode == "max" else (value < self.best - self.min_delta)
        if better:
            self.best, self.bad, self.best_epoch = value, 0, epoch
        else:
            self.bad += 1
            if self.bad >= self.patience:
                self.should_stop = True
        return self.should_stop


CKPT = "/opt/models/resume.pt"
EPOCHS = 40
scheduler_cls = lambda opt: torch.optim.lr_scheduler.CosineAnnealingLR(opt, T_max=EPOCHS, eta_min=1e-5)


def build():
    model = MLP()
    optimizer = torch.optim.AdamW(model.parameters(), lr=3e-3, weight_decay=1e-2)
    return model, optimizer, scheduler_cls(optimizer)


def run(epochs, model, optimizer, scheduler, stopper, start=0):
    for epoch in range(start, epochs):
        tr_loss, tr_acc = train_one_epoch(model, train_loader, optimizer, criterion)
        va_loss, va_acc, cm = evaluate(model, val_loader, criterion)
        if va_acc > stopper.best:                    # 只在刷新最好成绩时落盘
            torch.save({"epoch": epoch, "model": model.state_dict(),
                        "optimizer": optimizer.state_dict(),
                        "scheduler": scheduler.state_dict(),
                        "val_acc": va_acc}, CKPT)
        scheduler.step()
        if stopper.step(va_acc, epoch):
            print(f"触发早停：epoch={epoch} 最优 epoch={stopper.best_epoch}")
            break


# 进程重启后：重建模型与优化器，再恢复三个 state_dict
model2, optimizer2, scheduler2 = build()
ckpt = torch.load(CKPT, weights_only=True)
model2.load_state_dict(ckpt["model"])
optimizer2.load_state_dict(ckpt["optimizer"])
scheduler2.load_state_dict(ckpt["scheduler"])
run(EPOCHS, model2, optimizer2, scheduler2, EarlyStopper(patience=6, mode="max"), start=ckpt["epoch"] + 1)
```

## 梯度裁剪与训练稳定性

梯度裁剪是训练深网络、RNN、Transformer 时的常规保险：把梯度总范数压到阈值以内，避免单个异常 batch 把参数打飞。`clip_grad_norm_` 的返回值是**裁剪前的总范数**，正好用来做监控——如果它长期远大于阈值，说明学习率或初始化有问题。

```python
lin = nn.Linear(3, 1)
opt = torch.optim.SGD(lin.parameters(), lr=0.1)
opt.zero_grad()
lin(torch.ones(8, 3)).sum().backward()
before = torch.nn.utils.clip_grad_norm_(lin.parameters(), max_norm=0.5)   # 返回裁剪前范数
after = torch.sqrt(sum((p.grad ** 2).sum() for p in lin.parameters()))
print(before.item(), after.item())
```

```text
总范数(裁剪前) = 16.0  返回的是裁剪前的总范数
裁剪后总范数   = 0.5 （被压到 max_norm 以内）
max_norm 很大时返回 = 0.5 ，参数未变
```

稳定训练的其他惯用手段：

- 梯度累积（小 batch 模拟大 batch）与混合精度见 [[12.7-加速与分布式]]，两者都会改变梯度的尺度，裁剪要在累积完成之后做。
- `torch.nn.utils.clip_grad_value_(params, 0.5)` 是按元素裁剪，比按范数裁剪更激进，一般只在特定模型上使用。
- loss 出现 NaN 时，排查顺序是：学习率是否过大 -> `log`/`sqrt`/`div` 前是否缺少 `eps` -> 数据里是否有 NaN/Inf -> 最后才是调裁剪阈值。
- 训练初期 loss 长时间不降，优先怀疑损失函数输入（logits vs 概率）、标签 dtype（必须是 int64）与类别数是否匹配。

```text
要点：
1. clip_grad_norm_ 返回裁剪前总范数，把它打进日志可以提前发现梯度爆炸
2. 裁剪放在 backward 之后、optimizer.step() 之前，顺序错了裁剪无效
3. 阈值按模型量级设：常见的 1.0 / 5.0 不是普适值，先观察未裁剪时的实际范数分布
4. 梯度累积时要在累积完再裁剪、再 step，每个 micro-batch 都裁剪会改变梯度比例（见 12.7）
5. 稳定性问题的第一诊断工具是梯度范数与激活统计，不是盲目调 lr
```

## 应用场景实战

### 场景一：三分类业务模型的完整训练脚本（早停 + 最优权重 + 断点续训）

这是可以直接改成线上脚本的骨架：数据集换成业务宽表，指标换成业务 KPI，早停与续训逻辑不用动。关键是 `run()` 同时承担「首训」和「续训」两个入口，断点信息全部来自 checkpoint 自身。

```python
import numpy as np
import torch
import torch.nn as nn
from torch.utils.data import Dataset, DataLoader, random_split

torch.manual_seed(0)
np.random.seed(0)


class TabularDS(Dataset):
    """业务侧只需替换这里：从特征表/宽表读数据，返回 (features, label)"""

    def __init__(self, X, Y):
        self.X = torch.from_numpy(X)
        self.Y = torch.from_numpy(Y)

    def __len__(self):
        return len(self.Y)

    def __getitem__(self, i):
        return self.X[i], self.Y[i]


class MLP(nn.Module):
    def __init__(self, d_in=6, hidden=24, n_cls=3, p_drop=0.2):
        super().__init__()
        self.net = nn.Sequential(nn.Linear(d_in, hidden), nn.ReLU(), nn.Dropout(p_drop),
                                 nn.Linear(hidden, hidden), nn.ReLU(), nn.Linear(hidden, n_cls))

    def forward(self, x):
        return self.net(x)


def build_loaders(n=1200, d=6, k=3, noise=1.1):
    centers = np.random.randn(k, d) * 1.8
    y = np.random.randint(0, k, size=n)
    X = (centers[y] + noise * np.random.randn(n, d)).astype("float32")
    ds = TabularDS(X, y.astype("int64"))
    n_val = int(0.2 * len(ds))
    # 固定切分种子，才能横向对比不同损失/超参的实验
    return random_split(ds, [len(ds) - n_val, n_val], generator=torch.Generator().manual_seed(42))


train_ds, val_ds = build_loaders()
train_loader = DataLoader(train_ds, batch_size=64, shuffle=True)
val_loader = DataLoader(val_ds, batch_size=256, shuffle=False)

CKPT = "/opt/models/resume.pt"
EPOCHS = 40
criterion = nn.CrossEntropyLoss()

model = MLP()
optimizer = torch.optim.AdamW(model.parameters(), lr=3e-3, weight_decay=1e-2)
scheduler = torch.optim.lr_scheduler.CosineAnnealingLR(optimizer, T_max=EPOCHS, eta_min=1e-5)
stopper = EarlyStopper(patience=6, mode="max")

for epoch in range(EPOCHS):
    tr_loss, tr_acc = train_one_epoch(model, train_loader, optimizer, criterion)
    va_loss, va_acc, cm = evaluate(model, val_loader, criterion)
    print(f"epoch={epoch} lr={optimizer.param_groups[0]['lr']:.6f} train_loss={tr_loss:.4f} "
          f"val_loss={va_loss:.4f} val_acc={va_acc:.4f} macro_f1={macro_f1(cm):.4f}")
    if va_acc > stopper.best:
        torch.save({"epoch": epoch, "model": model.state_dict(), "optimizer": optimizer.state_dict(),
                    "scheduler": scheduler.state_dict(), "val_acc": va_acc}, CKPT)
    scheduler.step()
    if stopper.step(va_acc, epoch):
        print(f"早停于 epoch {epoch}，最优 epoch {stopper.best_epoch}")
        break
```

线上排障时最常用的两个判断：

- 训练 loss 正常下降、验证 acc 卡住：先看数据切分是否泄漏，再看是否过拟合（加深正则 / 减小容量）。
- 验证 acc 抖动但均值不涨：学习率偏大或 batch 太小，用 warmup + cosine 降下来，并把验证集调大。

```text
实测结论（本机 1200 条 6 维三分类，AdamW 3e-3 + cosine）：
1. 第 2 个 epoch 已达 val_acc 0.90，第 7~13 epoch 停在 0.958~0.967，早停在第 13 epoch 触发
2. 最优 checkpoint 停在 epoch 7，续训后 lr=0.002780 与断点处一致，验证指标不回退
3. 混淆矩阵显示三类各只有 1~4 个错分，类别均衡时宏平均 F1 与 acc 几乎相同（0.9667）
```

### 场景二：长尾类别的损失函数选型（3 类 90%/8%/2%）

风控、故障诊断、医疗筛查这类场景天然长尾：少数类样本少但业务价值最高，选错损失会让模型「学会」忽略少数类。下面这组实验在同一份数据、同一随机种子下只换损失函数，用宏平均 F1 与少数类召回看效果。

```python
import numpy as np
import torch
import torch.nn as nn
import torch.nn.functional as F

# 长尾三分类：90% / 8% / 2%
n = 6000
centers = np.array([[0.0, 0.0], [3.0, 0.0], [0.0, 3.0]], dtype="float32")
counts = np.array([int(n * 0.9), int(n * 0.08), n - int(n * 0.9) - int(n * 0.08)])
y = np.concatenate([np.full(c, i) for i, c in enumerate(counts)])
X = centers[y] + 0.9 * np.random.randn(n, 2).astype("float32")
perm = np.random.permutation(n)
X, y = X[perm], y[perm]
split = int(0.8 * n)
Xtr, ytr = torch.from_numpy(X[:split]), torch.from_numpy(y[:split].astype("int64"))
Xva, yva = torch.from_numpy(X[split:]), torch.from_numpy(y[split:].astype("int64"))


class FocalLoss(nn.Module):
    def __init__(self, gamma=2.0):
        super().__init__()
        self.gamma = gamma

    def forward(self, logits, target):
        logpt = F.log_softmax(logits, 1).gather(1, target.view(-1, 1)).squeeze(1)
        return (-((1 - logpt.exp()) ** self.gamma) * logpt).mean()


def train_eval(criterion, epochs=60, lr=5e-3):
    torch.manual_seed(0)                       # 每个方案从同一初始化出发
    model = nn.Sequential(nn.Linear(2, 32), nn.ReLU(), nn.Linear(32, 32), nn.ReLU(), nn.Linear(32, 3))
    opt = torch.optim.Adam(model.parameters(), lr=lr)
    sched = torch.optim.lr_scheduler.CosineAnnealingLR(opt, T_max=epochs, eta_min=1e-4)
    for ep in range(epochs):
        model.train()
        perm = torch.randperm(len(ytr))
        for i in range(0, len(ytr), 256):
            idx = perm[i:i + 256]
            opt.zero_grad(set_to_none=True)
            criterion(model(Xtr[idx]), ytr[idx]).backward()
            opt.step()
        sched.step()
    model.eval()
    with torch.no_grad():
        pred = model(Xva).argmax(1)
    cm = torch.zeros(3, 3, dtype=torch.long)
    for t, p in zip(yva.tolist(), pred.tolist()):
        cm[t, p] += 1
    f1s = []
    for c in range(3):
        tp = cm[c, c].item()
        fp = cm[:, c].sum().item() - tp
        fn = cm[c, :].sum().item() - tp
        prec = tp / (tp + fp) if tp + fp else 0.0
        rec = tp / (tp + fn) if tp + fn else 0.0
        f1s.append(2 * prec * rec / (prec + rec) if prec + rec else 0.0)
    return (pred == yva).float().mean().item(), sum(f1s) / 3, f1s, cm


w = torch.tensor([1.0, 5.0, 20.0])
for name, crit in [("普通交叉熵", nn.CrossEntropyLoss()),
                   ("加权交叉熵 w=[1,5,20]", nn.CrossEntropyLoss(weight=w)),
                   ("Focal(gamma=2)", FocalLoss(2.0))]:
    acc, f1, per, cm = train_eval(crit)
    print(f"{name} acc={acc:.4f} macro_F1={f1:.4f} 各类F1={per}")
```

本机真实输出：

```text
训练集类别分布: [4300, 396, 104]
验证集类别分布: [1100, 84, 16]

方案                        val_acc  macro_F1  各类 F1(多/中/少)      少数类召回
普通交叉熵                       0.9658   0.8416  [0.981, 0.785, 0.759]   0.688
加权交叉熵 w=[1,5,20]            0.9433   0.7561  [0.968, 0.800, 0.500]   0.938
Focal(gamma=2)              0.9667   0.8556  [0.982, 0.785, 0.800]   0.750

== 先验校正（logit adjustment）==
tau=0.0: val_acc=0.9675 macro_F1=0.8677
tau=0.5: val_acc=0.9550 macro_F1=0.7888
tau=1.0: val_acc=0.9192 macro_F1=0.7028
```

结论很反直觉但很重要：**加权交叉熵确实把少数类召回从 0.688 提到 0.938，但宏平均 F1 反而从 0.8416 掉到 0.7561**（少数类精确率崩了，大量多数类样本被判成少数类）；Focal Loss（gamma=2）在本例中同时拿到了召回 0.750 与最高的宏平均 F1 0.8556，是三者里最稳的。先验校正（`logits - tau*log(prior)`）在这份高度可分的合成数据上只会帮倒忙，`tau` 越大越差——它适合的是特征本身可分性差、单纯被先验概率压制的场景，`tau` 必须在真实验证集上搜索。

```text
要点：
1. 长尾问题不要只看 acc，选型指标用宏平均 F1 + 少数类召回/精确率
2. 加权交叉熵提升召回但常以宏平均 F1 为代价，权重不要一步给到 20，先试 2~5 再搜索
3. Focal Loss 在「难样本 = 少数类」时最有效，gamma=2 是常用起点
4. 先验校正（logit adjustment）的 tau 必须在真实验证集上调，合成可分数据上的结论不可迁移
5. 上述对比必须固定种子与数据切分，否则差异会被初始化噪声淹没
```

## 最佳实践与踩坑记录

### 最佳实践

1. 把「一个 epoch 的训练」与「一次验证」封成 `train_one_epoch()` 和 `evaluate()` 两个函数，脚本里只留调度逻辑；单测、续训、蒸馏都能复用同一份实现。
2. 损失函数跟随任务形态：单标签多分类用 `CrossEntropyLoss`（喂 logits）、多标签用 `BCEWithLogitsLoss`、回归用 `SmoothL1Loss`；自定义损失继承 `nn.Module`。
3. 优化器默认用 `AdamW(lr=3e-3, weight_decay=1e-2)` 起步，配合 warmup + cosine；只有在收敛不稳定或追求 SOTA 时才回到 SGD + momentum。
4. 指标按样本数累积而不是按 batch 平均；验证时套 `@torch.no_grad()`；固定数据切分与初始化的随机种子。
5. 只保存刷新最优验证指标的 checkpoint，且必须包含 optimizer 与 scheduler 的 state；`state_dict` 里带上 epoch 与 best 指标，续训脚本就不需要额外约定。
6. 把 `lr`、梯度范数、训练/验证 loss 一起打进日志（TensorBoard 或结构化日志）；定位问题时先看曲线再看代码。

### 踩坑记录

坑 1：把 softmax 之后的概率传给 `CrossEntropyLoss`，训练不报错但精度差
结论：模型看起来在学，验证指标却始终低于预期，梯度方向是错的。
原因：`CrossEntropyLoss` 期望未归一化 logits，内部自己做 `log_softmax`；喂概率等于又做了一次 softmax，本机实测同一份输入损失从 0.175456 变成 0.661075，梯度被严重压缩。
解法：前向只输出 logits，推理时再 `softmax`；写 `nn.CrossEntropyLoss()(logits, y)`，不要写 `(softmax(logits), y)`。

坑 2：`reduction='none'` 的手工加权与 `weight` 参数重复加权
结论：自己算出的加权损失与框架给的差一倍以上（本机实测 0.5288 vs 0.114667）。
原因：`reduction='none'` 返回的是未加权逐样本损失，`weight` 只在 `mean`/`sum` 下生效；手工再乘一次权重就是双重加权。
解法：用 `sum(loss_i * w[y_i]) / sum(w[y_i])`，或直接交给框架 `CrossEntropyLoss(weight=w)`，两种只选一种。

坑 3：`LambdaLR(..., verbose=True)` 或旧教程里的 scheduler 参数在新版本直接报错
结论：`TypeError: LambdaLR.__init__() got an unexpected keyword argument 'verbose'`（本机 2.14.1 实测）。
原因：`verbose` 参数在 2.2 被移除，多数调度器的构造函数签名已经变了。
解法：删掉 `verbose`，用 `scheduler.get_last_lr()` 自己打印；升级前用 `inspect.signature(SchedulerClass.__init__)` 核对参数。

坑 4：每 batch 调一次按 epoch 调度的 scheduler，学习率提前衰减到 0
结论：`StepLR(step_size=2)` 写成每 batch `step()`，6 个 batch 后 lr 从 0.1 掉到 1e-4（本机实测轨迹 `[0.1, 0.01, 0.01, 0.001, 0.001, 0.0001]`），训练早早停滞。
原因：调度器的计数器按「调用次数」增长，不区分 epoch 与 batch。
解法：明确节奏——按 epoch 的调度器放在 epoch 末尾；`OneCycleLR` 这类按 step 的调度器必须每 batch 调，构造时用 `total_steps=len(loader)*epochs`。

坑 5：断点续训只恢复了 model，学习率与动量统计量从头开始
结论：续训后前几个 epoch 验证指标明显回退，之后才爬回来；本机实测不恢复 optimizer/scheduler 时新优化器的 lr 是初始 0.003 而不是断点处的 0.002780。
原因：Adam/AdamW 的一阶、二阶矩存在 `optimizer.state_dict()` 里，`CosineAnnealingLR` 的进度存在 `scheduler.state_dict()['last_epoch']`。
解法：checkpoint 存 `model` / `optimizer` / `scheduler` / `epoch` / 验证指标五项，恢复时按同样顺序 `load_state_dict`。

坑 6：早停的 `patience` 与验证集规模不匹配
结论：patience=1 时模型在验证指标正常抖动处就停了，最终精度比不早停还差；patience 过大又白跑一半时间。
原因：小验证集（几百条）的指标抖动幅度天然大于 `min_delta=1e-4` 这种阈值，早停会把噪声当信号。
解法：验证集小于 1000 条时把 `patience` 设到 5~10 并适当放大 `min_delta`（如 1e-3），或改成对验证 loss 的滑动平均做早停，同时用 `save_top_k=1` 保住最优权重。

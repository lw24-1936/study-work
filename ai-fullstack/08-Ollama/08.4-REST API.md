## 概述

Ollama 服务对外就是一个 HTTP 服务器：原生接口在 `/api/*`（生成、对话、向量、模型管理），兼容接口在 `/v1/*`（OpenAI 的 chat/completions、completions、models、embeddings、responses），另有 Anthropic 兼容的 `/v1/messages` 挂在不同 base URL 下。本地服务默认监听 `127.0.0.1:11434` 且**不需要鉴权**；官方托管服务 `https://ollama.com/api` 与 `https://ollama.com/v1` 则必须带 API key 或用 `ollama signin` 登录后由本地服务代转。官方明确说明 API 不严格版本化，但以「稳定 + 向后兼容」为目标，弃用很少且会写在 release notes 里。

```text
本篇主线：
1. 约定 —— base URL 三套（/api、/v1、Anthropic），时长单位纳秒，流式默认开启
2. 生成 —— /api/generate：prompt 单轮，支持 suffix、raw、format（json 或 JSON Schema）
3. 对话 —— /api/chat：messages 多轮，支持 tools 工具调用、thinking、images
4. 向量 —— /api/embed（推荐）与 /api/embeddings（已被取代），返回 L2 归一化向量
5. 管理 —— /api/tags、/api/show、/api/ps、/api/pull、/api/push、/api/copy、/api/delete、/api/create、/api/blobs
6. 兼容 —— /v1/chat/completions、/v1/completions、/v1/models、/v1/embeddings、/v1/responses
```

本机实测环境：Ubuntu 24.04、Ollama 0.40.4，服务监听 `127.0.0.1:11434`，可用模型 `all-minilm:latest`（嵌入模型）。**本机安装缺少推理运行时 `llama-server`，因此所有需要真正跑模型的接口（`/api/generate`、`/api/chat`、`/api/embed` 等）在本机都会失败**。下面凡是标注「本机实测」的响应都是真实抓取；无法在本机跑通的接口只给出官方文档中的请求/响应结构，并明确标注「未在本机验证」，不做任何伪造输出。

## 接口约定与基础地址

三套 base URL 的对应关系如下（本地服务与官方云服务同构，仅鉴权方式不同）：

| 接口族 | 本地服务 | 官方云服务 | 说明 |
|--------|----------|------------|------|
| Ollama 原生 | `http://localhost:11434/api` | `https://ollama.com/api` | 需要创建/删除模型的场景只能用本地 |
| OpenAI 兼容 | `http://localhost:11434/v1` | `https://ollama.com/v1` | 只覆盖 OpenAI API 的一个子集 |
| Anthropic 兼容 | `http://localhost:11434` | `https://ollama.com` | 客户端会自动追加 `/v1/messages` |

几条硬约定：**模型名遵循 `model:tag` 格式**，tag 省略默认 `latest`；**所有时长字段（`total_duration`、`load_duration` 等）单位是纳秒**；**流式接口默认就是流式**，要一次性拿到完整对象必须显式传 `{"stream": false}`。鉴权方面，本地请求不带任何头；直连云服务需要 `Authorization: Bearer <OLLAMA_API_KEY>`（连 Anthropic 兼容端点也必须用 Bearer，官方说明单用 `x-api-key` 不支持）；如果本地服务已经 `ollama signin`，通过本地服务调用云模型（如 `gemma4:31b-cloud`）则由服务端代转鉴权。

```shell
# 存活探针（本机实测）
curl -s http://localhost:11434/api/version
# {"version":"0.40.4"}

# 直连云服务：需要 API key
curl -s https://ollama.com/api/chat \
  -H "Authorization: Bearer $OLLAMA_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"gemma4:31b","messages":[{"role":"user","content":"Say hello in one sentence."}],"stream":false}'

# 通过已登录的本地服务调云模型（本机未验证，需先 ollama signin）
curl -s http://localhost:11434/api/generate -d '{
  "model": "gpt-oss:120b-cloud",
  "prompt": "Why is the sky blue?"
}'
```

```text
接口约定要点：
1. 三套 base URL：/api（原生）、/v1（OpenAI 兼容）、根路径 + /v1/messages（Anthropic 兼容）
2. 模型名格式 model:tag，tag 省略即 latest
3. 时长一律纳秒；不要按毫秒解读 total_duration / load_duration
4. 流式是默认行为，要单对象必须显式传 stream:false
5. 本地无鉴权，直连云必须 Bearer；Anthropic 兼容端点也用 Bearer 而非 x-api-key
6. 创建/删除模型只支持本地服务，云侧不提供
```

## 生成接口与流式响应

`POST /api/generate` 是单轮文本补全接口：给 `model` 与 `prompt`，返回补全结果。它的参数里最值得掌握的是五个：`format`（`json` 或一份 JSON Schema，用于结构化输出）、`options`（覆盖 Modelfile 里的采样参数）、`system`（临时覆盖系统提示）、`raw`（绕过模板，自己给完整提示词）、`keep_alive`（这次请求后模型驻留多久）。官方特别提醒：用 `format: "json"` 时**必须在 prompt 里明确要求输出 JSON**，否则模型可能只吐一大堆空白。

| 参数 | 类型 | 说明 |
|------|------|------|
| `model` | string | 必填，模型名 |
| `prompt` | string | 提示词（`raw: true` 时被视为完整模板文本） |
| `suffix` | string | 模型响应之后要接的文本（补全中间内容） |
| `images` | string[] | base64 编码图片数组（多模态模型） |
| `format` | string/object | `json` 或 JSON Schema |
| `options` | object | 采样参数（temperature、num_ctx、top_p、seed、stop 等） |
| `system` | string | 覆盖 Modelfile 中的系统提示 |
| `template` | string | 覆盖 Modelfile 中的模板 |
| `stream` | bool | 默认 true，设 false 返回单个对象 |
| `raw` | bool | true 时不做任何模板包装 |
| `keep_alive` | string/number | 请求后驻留时长，`0` 立即卸载，负数常驻 |
| `think` | bool/string | 思考模型：布尔或 `low`/`medium`/`high`/`max` |
| `context` | int[] | 已废弃，历史版本用于传回上下文 |

流式响应的形态是「一串 JSON 对象」，最后一条带统计字段；这是官方文档给出的响应结构（字段说明保留原样）：

```json
{
  "model": "llama3.2",
  "created_at": "2023-08-04T19:22:45.499127Z",
  "response": "The sky is blue because it is the color of the sky.",
  "done": true,
  "context": [1, 2, 3],
  "total_duration": 5043500667,
  "load_duration": 5025959,
  "prompt_eval_count": 26,
  "prompt_eval_duration": 325953000,
  "eval_count": 290,
  "eval_duration": 4709213000
}
```

本机实测两种真实响应：一是对嵌入模型误用生成接口，服务端会明确拒绝（能力不匹配）；二是本机缺运行时导致的失败。这两条都是排障时的典型信号：

```text
$ curl -s http://localhost:11434/api/generate -d '{"model":"all-minilm","prompt":"你好","stream":false}'
{"error":"\"all-minilm\" does not support generate"}

$ curl -s http://localhost:11434/api/embed -d '{"model":"all-minilm","input":"你好"}'
{"error":"error starting llama-server: llama-server binary not found (checked: /usr/local/lib/ollama/llama-server, ...). Run 'cmake -S llama/server --preset cpu && cmake --build --preset cpu' first "}
```

结构化输出用 JSON Schema 时，把 schema 直接放进 `format`：

```shell
curl -s http://localhost:11434/api/generate -d '{
  "model": "qwen2.5:7b-instruct-q4_K_M",
  "prompt": "从这句话里抽取意图与城市：帮我查一下明天北京的天气",
  "stream": false,
  "format": {
    "type": "object",
    "properties": {
      "intent": {"type": "string"},
      "city": {"type": "string"}
    },
    "required": ["intent", "city"]
  },
  "options": {"temperature": 0}
}'
```

预加载与卸载模型是运维里常用的小技巧：发一个**空的**请求体（只带 `model`）即可把模型提前加载进内存，降低第一个真实请求的首 token 延迟；把 `keep_alive` 设成 `0` 则请求完立即释放：

```shell
# 预加载（官方 FAQ 做法：空请求体）
curl -s http://localhost:11434/api/generate -d '{"model":"qwen2.5:7b-instruct-q4_K_M"}'

# 常驻不卸载
curl -s http://localhost:11434/api/generate -d '{"model":"qwen2.5:7b-instruct-q4_K_M","keep_alive":-1}'

# 立即卸载释放内存
curl -s http://localhost:11434/api/generate -d '{"model":"qwen2.5:7b-instruct-q4_K_M","keep_alive":0}'
```

```text
生成接口要点：
1. stream 默认 true；用 curl/脚本调用时通常要显式 stream:false 拿单对象
2. format 支持 json 与完整 JSON Schema；用 json 时提示词里必须要求输出 JSON
3. options 会覆盖 Modelfile 参数；system/template 也可按次覆盖
4. 空请求体可预加载模型，keep_alive 0/-1 分别对应立即卸载与常驻
5. 时长字段是纳秒；eval_count/eval_duration 可算出 tokens/s
6. 错误响应统一是 {"error": "..."}，能力不匹配与运行时缺失都能从 message 区分
```

## 对话接口与工具调用

`POST /api/chat` 是多轮对话接口，`messages` 是核心：每条消息有 `role`（`system`/`user`/`assistant`/`tool`）、`content`，以及可选的 `images`、`thinking`、`tool_calls`、`tool_name`。多轮上下文**由客户端维护**——服务端不保存会话，你要把历史消息一起发上去，这也是「聊天记录必须自己存」的原因。`tools` 参数传入工具定义（JSON Schema 形式），模型返回的 `message.tool_calls` 里是它想调用的工具与参数，你执行完再把结果以 `role: "tool"`（带 `tool_name`）追加进消息列表发回去，形成闭环。

| 消息字段 | 说明 |
|----------|------|
| `role` | `system` / `user` / `assistant` / `tool` 四选一 |
| `content` | 文本内容 |
| `images` | base64 图片数组（多模态模型） |
| `thinking` | 思考模型输出的推理过程（仅 assistant 消息） |
| `tool_calls` | 模型请求调用的工具列表（仅 assistant 消息） |
| `tool_name` | 工具执行结果对应的工具名（仅 tool 消息） |

```shell
# 多轮对话（本机未验证：本机缺 llama-server；结构与官方文档一致）
curl -s http://localhost:11434/api/chat -d '{
  "model": "qwen3:8b",
  "messages": [
    {"role": "system", "content": "你是一个只输出结论的运维助手。"},
    {"role": "user", "content": "背景：我们有一台 8 卡机器跑本地推理。"},
    {"role": "user", "content": "给出一句话建议。"}
  ],
  "stream": false,
  "options": {"temperature": 0.2, "num_ctx": 8192}
}'
```

工具调用（function calling）的完整一轮是「定义工具 → 模型给出 tool_calls → 你执行 → 回填 tool 结果 → 模型给最终回答」：

```shell
# 第一步：带上工具定义发问
curl -s http://localhost:11434/api/chat -d '{
  "model": "qwen3:8b",
  "messages": [{"role": "user", "content": "北京今天天气怎么样？"}],
  "stream": false,
  "tools": [{
    "type": "function",
    "function": {
      "name": "get_weather",
      "description": "查询指定城市的当前天气",
      "parameters": {
        "type": "object",
        "properties": {"city": {"type": "string", "description": "城市名"}},
        "required": ["city"]
      }
    }
  }]
}'
```

```shell
# 第二步：把模型给出的 tool_calls 执行结果回填，再取最终回答
curl -s http://localhost:11434/api/chat -d '{
  "model": "qwen3:8b",
  "stream": false,
  "messages": [
    {"role": "user", "content": "北京今天天气怎么样？"},
    {"role": "assistant", "content": "",
     "tool_calls": [{"function": {"name": "get_weather", "arguments": {"city": "北京"}}}]},
    {"role": "tool", "tool_name": "get_weather", "content": "{\"temp_c\": 21, \"sky\": \"晴\"}"}
  ]
}'
```

如果需要边生成边渲染，流式模式下每个 chunk 会带 `message.content`（以及思考模型的 `message.thinking`）。官方能力文档提醒：**必须把各 chunk 累积起来**，尤其是工具调用场景——思考、tool_calls 与工具结果都要原样回传，否则下一轮模型看不到上下文。

```python
"""流式消费 /api/chat：累积 content 与 thinking，供下一轮回传。"""
import json
import urllib.request

payload = {
    "model": "qwen3:8b",
    "messages": [{"role": "user", "content": "17 乘 23 等于多少？请解释步骤。"}],
    "stream": True,
}
req = urllib.request.Request(
    "http://localhost:11434/api/chat",
    data=json.dumps(payload).encode(),
    headers={"Content-Type": "application/json"},
)
content, thinking = "", ""
try:
    with urllib.request.urlopen(req, timeout=120) as resp:
        for line in resp:
            if not line.strip():
                continue
            chunk = json.loads(line)
            msg = chunk.get("message", {})
            if msg.get("thinking"):
                thinking += msg["thinking"]
            if msg.get("content"):
                content += msg["content"]
            if chunk.get("done"):
                break
finally:
    # 关键：累积后的字段要能原样回传，形成新的一轮 messages
    new_messages = [{"role": "assistant", "thinking": thinking, "content": content}]
    print("content 长度:", len(content), "thinking 长度:", len(thinking))
```

```text
对话接口要点：
1. 服务端无状态，多轮上下文必须由客户端把历史 messages 一起发上去
2. role 四种：system/user/assistant/tool；tool 消息要带 tool_name
3. 工具调用是「模型给 tool_calls -> 你执行 -> 回填 tool 消息」的闭环
4. 流式必须在客户端累积 content/thinking/tool_calls，累积结果要能回传
5. 思考模型会在 message.thinking 里给推理过程，可与 content 分开渲染
6. 与 generate 一样支持 format、options、keep_alive、think
```

## 向量接口与检索

向量化用 `POST /api/embed`：`input` 可以是单个字符串，也可以是字符串数组（批量），官方特别说明**该接口返回的是 L2 归一化（单位长度）向量**，因此检索时直接点积就等于余弦相似度。`input` 还支持对象形式，用于多模态嵌入（`text` / `image` / `audio` 字段，`video` 目前不接受），数组里可以混着写纯文本与对象。可调参数有 `truncate`（超长输入是否截断，默认 true，设 false 则超长直接报错）与 `dimensions`（输出向量维度）。旧接口 `POST /api/embeddings` 使用 `prompt` 字段，官方文档已标注「已被 `/api/embed` 取代」，新代码不要再用它。

```shell
# 单条（本机未验证：本机缺 llama-server；这是官方文档给出的请求形态）
curl -s http://localhost:11434/api/embed -d '{
  "model": "all-minilm",
  "input": "Why is the sky blue?"
}'
```

官方文档给出的响应结构（本机为嵌入模型 `all-minilm`，嵌入长度 384，可用 `dimensions` 截断）：

```json
{
  "model": "all-minilm",
  "embeddings": [[0.010071029, -0.0017594862, 0.05007221, 0.04692972]],
  "total_duration": 14143917,
  "load_duration": 1019500,
  "prompt_eval_count": 8
}
```

```shell
# 批量向量化（一次请求多个文本，注意返回的 embeddings 与输入顺序一一对应）
curl -s http://localhost:11434/api/embed -d '{
  "model": "all-minilm",
  "input": ["第一段文本", "第二段文本", "第三段文本"]
}'

# 多模态嵌入：文本 + 图片（需要支持多模态嵌入的模型）
curl -s http://localhost:11434/api/embed -d '{
  "model": "embeddinggemma2",
  "input": {"text": "a cat sitting on a windowsill", "image": "iVBORw0KGgo..."}
}'

# 旧接口（已被 /api/embed 取代，仅为兼容老代码保留）
curl -s http://localhost:11434/api/embeddings -d '{
  "model": "all-minilm",
  "prompt": "Here is an article about llamas..."
}'
```

一个可以直接跑的最小检索示例（向量来自真实接口，本机因缺运行时无法跑出数值，逻辑与字段均为官方形态）：

```python
"""用 /api/embed 做最小语义检索：建索引 + 查询，余弦相似度排序。"""
import json
import math
import urllib.request

HOST = "http://localhost:11434"


def embed(texts):
    body = json.dumps({"model": "all-minilm", "input": texts}).encode()
    req = urllib.request.Request(
        f"{HOST}/api/embed", data=body, headers={"Content-Type": "application/json"}
    )
    with urllib.request.urlopen(req, timeout=120) as resp:
        return json.loads(resp.read())["embeddings"]


def cosine(a, b):
    # /api/embed 已是 L2 归一化向量，点积即余弦相似度；这里仍做通用实现
    dot = sum(x * y for x, y in zip(a, b))
    return dot / (math.sqrt(sum(x * x for x in a)) * math.sqrt(sum(y * y for y in b)) + 1e-12)


DOCS = [
    "Ollama 默认监听 127.0.0.1:11434，本地 API 不需要鉴权。",
    "模型存放在 OLLAMA_MODELS 指向的目录，blobs 以 SHA256 命名。",
    "num_ctx 决定上下文窗口，直接放大显存与内存占用。",
]
QUERIES = ["怎么改监听地址？", "模型文件放在哪？"]

if __name__ == "__main__":
    doc_vecs = embed(DOCS)
    query_vecs = embed(QUERIES)
    for q, qv in zip(QUERIES, query_vecs):
        ranked = sorted(
            ((cosine(qv, dv), d) for dv, d in zip(doc_vecs, DOCS)), reverse=True
        )
        print(f"[查询] {q}")
        for score, doc in ranked[:2]:
            print(f"  {score:.4f}  {doc}")
```

```text
向量接口要点：
1. /api/embed 返回 L2 归一化向量，点积即余弦相似度
2. input 支持字符串、字符串数组与多模态对象（text/image/audio），video 暂不支持
3. /api/embeddings 使用 prompt 字段，已被取代，新代码统一用 /api/embed
4. truncate 默认 true（超长截断），设 false 时超长直接报错，适合严格场景
5. dimensions 可截断向量维度，必须与索引端使用同一设置
6. 索引与查询必须用同一个嵌入模型，混用会导致相似度无意义
```

## 模型管理接口

模型管理接口与 CLI 子命令一一对应，是把模型生命周期做进平台的关键。多数接口的 `stream` 默认也是 true（拉取、创建、推送会持续吐进度），做脚本时记得显式 `stream: false`。

| 接口 | 方法 | 作用 | 关键参数 |
|------|------|------|----------|
| `/api/tags` | GET | 列出本地模型 | 无 |
| `/api/ps` | GET | 列出已加载模型 | 无 |
| `/api/show` | POST | 查看模型详情 | `model`、`verbose` |
| `/api/create` | POST | 从 Modelfile 创建模型 | `model`、`from`、`system`、`parameters`、`template`、`quantize`、`capabilities` |
| `/api/copy` | POST | 复制模型 | `source`、`destination` |
| `/api/delete` | DELETE | 删除模型 | `model` |
| `/api/pull` | POST | 拉取模型 | `model`、`insecure`、`stream` |
| `/api/push` | POST | 推送模型 | `model`、`insecure`、`stream` |
| `/api/blobs/:digest` | HEAD | 判断 blob 是否存在 | 路径参数 digest |

## OpenAI 兼容接口

Ollama 在 `/v1` 下实现了 OpenAI API 的一个子集，目标很明确：让现成的 OpenAI SDK 与工具**改个 base_url 就能指向本地模型**。客户端要求传 API key，但本地服务会忽略它的值（官方示例里写 `api_key='ollama'  # required but ignored`）。已实现的端点包括 `/v1/chat/completions`、`/v1/completions`、`/v1/models`、`/v1/models/{model}`、`/v1/embeddings`，以及 `/v1/responses`（官方注明自 v0.13.3 加入，仅支持无状态模式）。

`/v1/chat/completions` 的支持面（官方支持清单）：Chat completions、Streaming、JSON mode、可复现输出、Vision、Tools、思考控制（`reasoning_effort` / `reasoning.effort`）都支持，**Logprobs 不支持**；请求字段里 `model`、`messages`、`temperature`、`top_p`、`max_tokens`、`stop`、`seed`、`stream`、`stream_options.include_usage`、`tools`、`response_format`、`frequency_penalty`、`presence_penalty` 均支持，而 `tool_choice`、`logit_bias`、`user`、`n`、图片 URL（Image URL）不支持。`/v1/completions` 的 `prompt` 目前只接受字符串；`/v1/embeddings` 的 `input` 支持字符串与字符串数组，不支持 token 数组。

| 端点 | 支持要点 | 不支持项 |
|------|----------|----------|
| `/v1/chat/completions` | 流式、JSON mode、Vision、Tools、思考控制 | Logprobs、tool_choice、logit_bias、user、n、图片 URL |
| `/v1/completions` | 流式、JSON mode、suffix、可复现 | Logprobs、best_of、echo、logit_bias、user、n |
| `/v1/models`、`/v1/models/{model}` | 列出本地模型 | `created` 是模型最后修改时间，`owned_by` 默认 `library` |
| `/v1/embeddings` | 字符串 / 字符串数组 | token 数组、token 数组的数组、user |
| `/v1/responses` | 流式、Tools、思考摘要 | 有状态请求（`previous_response_id`、`conversation`）、truncation |

## 应用场景实战

### 场景一：用原生接口搭一个带流式输出的本地知识问答服务

某内部工具要在内网提供「文档问答」：文档向量化入库、用户提问走检索、再让本地模型基于检索结果作答，并要求前端能看到逐字输出的打字机效果。做法是用 `/api/embed` 建索引、用 `/api/chat` 的流式模式作答，全部只用标准库，不引入额外依赖。

```python
"""local_rag.py —— 纯标准库实现的本地 RAG 服务（索引 + 流式问答）。

依赖：本机已运行 Ollama，且已 ollama pull all-minilm 与一个生成模型。
运行：python3 local_rag.py
说明：本机缺 llama-server 时会在调用阶段报运行时缺失错误，逻辑与字段均为官方接口形态。
"""
import json
import math
import urllib.error
import urllib.request

HOST = "http://localhost:11434"
EMBED_MODEL = "all-minilm"
CHAT_MODEL = "qwen2.5:7b-instruct-q4_K_M"

CORPUS = [
    "Ollama 默认监听 127.0.0.1:11434，本地 API 不需要鉴权。",
    "模型存放在 OLLAMA_MODELS 指向的目录，blob 以 SHA256 命名且全局去重。",
    "num_ctx 决定上下文窗口大小，调大直接放大显存与内存占用。",
    "OLLAMA_KEEP_ALIVE 控制模型在内存中的驻留时长，默认 5 分钟。",
]


def post(path, payload, stream=False):
    req = urllib.request.Request(
        HOST + path,
        data=json.dumps(payload).encode(),
        headers={"Content-Type": "application/json"},
    )
    return urllib.request.urlopen(req, timeout=120)


def api_error(path, payload):
    """把 {"error": "..."} 形式的失败翻译成人话，便于排障。"""
    try:
        with post(path, payload) as resp:
            return json.loads(resp.read())
    except urllib.error.HTTPError as e:
        return {"error": f"HTTP {e.code}: {e.read().decode(errors='replace')}"}


def embed(texts):
    data = api_error("/api/embed", {"model": EMBED_MODEL, "input": texts})
    if "error" in data:
        raise RuntimeError(f"嵌入失败：{data['error']}")
    return data["embeddings"]


def cosine(a, b):
    return sum(x * y for x, y in zip(a, b)) / (
        math.sqrt(sum(x * x for x in a)) * math.sqrt(sum(y * y for y in b)) + 1e-12
    )


def retrieve(question, top_k=2):
    qv = embed([question])[0]
    dv = embed(CORPUS)
    ranked = sorted(((cosine(qv, v), d) for v, d in zip(dv, CORPUS)), reverse=True)
    return [d for _, d in ranked[:top_k]]


def answer(question):
    ctx = "\n".join(f"- {d}" for d in retrieve(question))
    payload = {
        "model": CHAT_MODEL,
        "stream": True,
        "options": {"temperature": 0.2, "num_ctx": 8192},
        "messages": [
            {"role": "system", "content": "只依据提供的资料回答；资料里没有就说不知道。"},
            {"role": "user", "content": f"资料：\n{ctx}\n\n问题：{question}"},
        ],
    }
    try:
        with post("/api/chat", payload) as resp:
            for line in resp:
                if not line.strip():
                    continue
                chunk = json.loads(line)
                piece = chunk.get("message", {}).get("content", "")
                if piece:
                    print(piece, end="", flush=True)
                if chunk.get("done"):
                    break
        print()
    except urllib.error.HTTPError as e:
        # 本机缺 llama-server 时会走到这里，把原始错误原样打出来，不吞掉
        print(f"[服务端错误] HTTP {e.code}: {e.read().decode(errors='replace')}")


if __name__ == "__main__":
    for q in ["怎么改监听地址？", "模型文件放在哪里？", "上下文长度是什么？"]:
        print(f"\n问：{q}")
        print("答：", end="")
        answer(q)
```

配套的「接口连通性冒烟脚本」，部署后先跑这一条，按接口类别快速定位是服务问题还是模型能力问题：

```bash
#!/usr/bin/env bash

ok=0; bad=0
check() { # 名称 期望是否成功 输出
  if [ "$2" = "1" ]; then echo "[OK ] $1"; ok=$((ok+1)); else echo "[BAD] $1 -> $3"; bad=$((bad+1)); fi
}

r=$(curl -s "$HOST/api/version")
echo "$r" | grep -q version && check "/api/version" 1 || check "/api/version" 0 "$r"

r=$(curl -s "$HOST/api/tags")
echo "$r" | grep -q '"models"' && check "/api/tags" 1 || check "/api/tags" 0 "$r"

r=$(curl -s "$HOST/api/ps")
echo "$r" | grep -q '"models"' && check "/api/ps" 1 || check "/api/ps" 0 "$r"

r=$(curl -s "$HOST/v1/models")
echo "$r" | grep -q '"object"' && check "/v1/models" 1 || check "/v1/models" 0 "$r"

r=$(curl -s "$HOST/api/generate" -d '{"model":"all-minilm","prompt":"hi","stream":false}')
echo "$r" | grep -q '"error"' && check "/api/generate(能力校验)" 1 || check "/api/generate" 0 "$r"

echo "通过 $ok 项，失败 $bad 项"
[ "$bad" -eq 0 ]
```

```text

1. 索引与查询必须用同一嵌入模型，且 dimensions 设置一致
```

### 场景二：用 OpenAI SDK 做本地推理的 drop-in 替换与结构化抽取

某数据团队现有的 Python 脚本全部基于 OpenAI SDK，现在要把一部分「不能出内网」的抽取任务切到本地模型。要求改动最小（只改 base_url 与 api_key）、输出严格结构化、失败可重试，并能在多模型之间切换做 A/B。做法是封装一个客户端工厂 + 带 schema 的抽取函数 + 指数退避重试。

```python
"""extract_local.py —— OpenAI SDK 指向本地 Ollama，做结构化抽取与重试。

依赖：pip install --index-url https://pypi.tuna.tsinghua.edu.cn/simple openai
运行前提：本机 Ollama 已运行并拉取了 qwen2.5:7b-instruct-q4_K_M。
本机未验证：本机缺 llama-server，实际调用会返回运行时缺失错误。
"""
import json
import time

from openai import OpenAI

SCHEMA = {
    "type": "object",
    "properties": {
        "intent": {"type": "string", "enum": ["查询天气", "查询物流", "退换货", "其他"]},
        "city": {"type": ["string", "null"]},
        "confidence": {"type": "number"},
    },
    "required": ["intent", "city", "confidence"],
}


def make_client(host: str = "http://localhost:11434") -> OpenAI:
    # 本地服务忽略 api_key 的值，但 SDK 要求非空
    return OpenAI(base_url=f"{host}/v1/", api_key="ollama", timeout=120)


def extract(client: OpenAI, text: str, model: str, retries: int = 3) -> dict:
    last_err = None
    for attempt in range(retries):
        try:
            resp = client.chat.completions.create(
                model=model,
                temperature=0,
                messages=[
                    {"role": "system", "content": "只输出符合给定 schema 的 JSON，不要解释。"},
                    {"role": "user", "content": text},
                ],
                response_format={
                    "type": "json_schema",
                    "json_schema": {"name": "ticket", "schema": SCHEMA},
                },
            )
            data = json.loads(resp.choices[0].message.content)
            assert set(SCHEMA["required"]) <= set(data), f"缺字段: {data}"
            return data
        except Exception as e:  # 网络抖动、模型没加载完、输出不合规都可能走到这里
            last_err = e
            time.sleep(2 ** attempt)  # 指数退避，避免把服务打满
    raise RuntimeError(f"抽取失败（已重试 {retries} 次）: {last_err}")


if __name__ == "__main__":
    client = make_client()
    cases = ["帮我查一下明天北京的天气", "我的快递三天没动了", "收到货有划痕想退货"]
    for model in ("qwen2.5:7b-instruct-q4_K_M", "qwen3:8b"):  # A/B 对比
        print(f"== 模型：{model} ==")
        for t in cases:
            try:
                print(f"  {t} -> {extract(client, t, model)}")
            except Exception as e:
                print(f"  {t} -> [失败] {e}")
```

如果现有系统只认「OpenAI 默认模型名」，用零拷贝改名把本地模型暴露成那个名字，旧代码一行都不用改：


```text
1. 只改 base_url 与 api_key 两处，api_key 值随便填（本地服务忽略）
2. 结构化抽取用 response_format + JSON Schema，并在本地校验必填字段
3. 失败要重试：模型未加载完、显存不足、输出不合规都会表现为异常
4. 上下文长度不受 OpenAI 字段控制，需要 Modelfile 建带 num_ctx 的模型名
```

## 最佳实践与踩坑记录

### 最佳实践

1. 所有非交互调用显式写 `"stream": false`，避免收到一串 JSON 对象后 `json.loads` 直接抛错。
2. 统一用 `/api/embed` 做向量化，`dimensions` 在索引端与查询端保持一致；不要再用 `/api/embeddings`。
3. 结构化输出优先用 JSON Schema（`format` / `response_format`），并在代码里校验必填字段，缺字段即判失败重试。
4. 把 `{"error": "..."}` 当成统一错误协议来解析：能力不匹配、模型不存在、运行时缺失、队列打满都能从消息里区分。
5. 多轮对话由客户端维护消息历史；流式消费时要累积 `content` / `thinking` / `tool_calls` 以便回传。
6. 给请求加超时与重试（指数退避），并区分「可重试」（超时、503）与「不可重试」（模型不存在、能力不匹配）。
7. 需要固定上下文就建带 `num_ctx` 的模型名；需要控制驻留就用 `keep_alive`，别依赖默认 5 分钟的运气。

### 踩坑记录

```text
坑 1：用 requests/urllib 调 /api/generate 后 json.loads 报错
结论：响应体不是合法 JSON，解析失败。
原因：流式接口默认 stream=true，返回的是一串按行分隔的 JSON 对象，不是单个对象。
解法：请求体显式加 "stream": false；或改成逐行解析（每行一个 JSON 对象，最后一条 done=true）。

坑 2：设置 format 为 json 后模型输出大段空白
结论：拿到的 JSON 是空的或者只有一堆空白字符。
原因：官方明确指出只设 format 而不在提示词里要求输出 JSON，模型可能只吐空白。
解法：提示词里显式写「只输出 JSON」并给出字段名；结合 JSON Schema 进一步约束结构与必填项。

坑 3：OpenAI SDK 改了 base_url 仍报上下文长度不够
结论：长文档任务被截断，但请求里没有地方能设 num_ctx。
原因：OpenAI 兼容 API 没有上下文长度字段，Ollama 的 num_ctx 只能通过 Modelfile 固化。
解法：写一个 FROM <模型> + PARAMETER num_ctx <长度> 的 Modelfile，ollama create 新名字后用新名字调用。

坑 4：请求被拒绝并返回 503
结论：服务在压力下开始拒绝请求。
原因：排队请求超过 OLLAMA_MAX_QUEUE（默认 512），服务端返回 503 表示过载。
解法：客户端加退避重试；服务端用 OLLAMA_MAX_QUEUE / OLLAMA_NUM_PARALLEL / OLLAMA_MAX_LOADED_MODELS 按显存调参。

坑 5：用 /api/embeddings 的新项目在升级后行为不一致
结论：老代码能跑但结果不稳定，或与新接口对不上。
原因：官方已把 /api/embeddings 标注为被 /api/embed 取代，两者字段不同（prompt vs input），
      返回结构也不同（embedding vs embeddings）。
解法：统一迁移到 /api/embed，注意返回是二维数组 embeddings，且向量已做 L2 归一化。

坑 6：混用 /api 与 /v1 路径导致字段对不上
结论：同一个模型在两套接口下参数名不同，代码里到处是特判。
原因：/v1 是 OpenAI 兼容层，参数命名（max_tokens、response_format）与 /api（num_predict、format）不同。
解法：项目里二选一并封装成一层薄适配；注意 /v1 不支持 tool_choice、logit_bias、图片 URL 等字段。
```

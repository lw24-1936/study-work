## 概述

`ollama` 命令行是 Ollama 服务的客户端：它把参数打包成 HTTP 请求发给 `OLLAMA_HOST`（默认 `127.0.0.1:11434`），把返回的流式结果渲染到终端。日常使用分两种形态——**交互会话**（`ollama run <模型>` 进入一个 REPL，用 `/` 开头的命令在会话里调参数、看模板、清上下文）和**一次性调用**（把提示词作为参数或从标准输入喂进去，适合写脚本与做 CI）。本文覆盖这两条路径：怎么进会话、会话里有哪些命令、怎么输入多行与图片、有哪些运行参数，最后给一张子命令速查表。命令与输出以本机 0.40.4 为准；涉及官方行为的部分都标了来源。

```text
本篇主线：
1. 进会话 —— ollama run MODEL [PROMPT]，退出用 /bye 或 Ctrl+d
2. 会话内 —— /set 调参数与环境、/show 看模板与配置、/clear 清上下文、/load 换模型
3. 输入形态 —— 参数、标准输入管道、""" 多行、图片路径、Ctrl+G 外部编辑器
4. 运行参数 —— --format json 结构化、--think 思考、--keepalive 保活、--verbose 计时
5. 子命令 —— ls / ps / show / cp / rm / pull / push / create / stop / launch / signin
```

本机实测环境：Ubuntu 24.04、Ollama 0.40.4，安装在 `/usr/local/bin/ollama`。需要特别说明的是：本机这份 Ollama 安装里**缺少推理运行时二进制 `llama-server`**，因此任何真正跑模型的命令（`ollama run` 的生成、`/api/generate` 等）都会返回 `error starting llama-server: llama-server binary not found`。这是本机的真实状态，本篇对「会话内的实际问答效果」不做任何伪造，凡是无法在本机验证的部分都会明确标注「未在本机验证」，只保留可用官方文档与真实错误信息核对的内容。

## 运行模型与会话交互

最基础的用法是 `ollama run <模型>`，如果本地没有该模型会先自动拉取，然后进入交互会话；也可以直接把提示词跟在模型后面做一次性问答（`ollama run gemma4 "Why is the sky blue?"`，官方 CLI 参考里的例子）。官方快速开始建议用 `/bye` 退出会话（等价于 Ctrl+d）。会话里如果配置了 `OLLAMA_NOHISTORY`，命令行历史不会被保留，适合共享机器。

```shell
# 进入交互会话（本地没有该模型会自动 pull）
ollama run qwen2.5:7b-instruct-q4_K_M

# 一次性问答：结果打印后立即退出
ollama run qwen2.5:7b-instruct-q4_K_M "用三句话解释什么是向量数据库"

# 从标准输入读取提示词（脚本化首选）
echo "把下面这段日志归类：连接超时" | ollama run qwen2.5:7b-instruct-q4_K_M

# 会话内退出
# >>> /bye          （或 Ctrl+d）
```

`ollama run` 的完整参数清单（本机实测 `ollama run --help` 的真实输出）：

本机实测的失败形态（因为缺 `llama-server`，任何生成类调用都会这样返回，这条信息本身对排障很有价值）：

```text
$ ollama run all-minilm "你好"
```

```text

1. ollama run 进入 REPL，带 PROMPT 参数则问完即退，适合脚本与 CI

3. 退出会话：/bye 或 Ctrl+d；共享机器可设 OLLAMA_NOHISTORY 不留历史

```

## 交互内命令

会话里的命令都以 `/` 开头，输入 `/?` 看帮助。从本机二进制里提取出的真实命令清单如下（与 0.40.4 一致）：

| 命令 | 作用 |
|------|------|
| `/?` | 显示帮助（等价于 `/help`） |
| `/set` | 设置会话变量（见下表细分） |
| `/set parameter <名> <值>` | 设置单个推理参数，如 `/set parameter num_ctx 8192` |
| `/show` | 查看当前模型信息（细分见下） |
| `/load <模型>` | 载入一个会话或模型（换模型继续聊） |
| `/clear` | 清空会话上下文 |
| `/bye` | 退出会话（等价于 Ctrl+d） |

`/set` 的细分项（真实帮助文本）：

| 命令 | 作用 |
|------|------|
| `/set parameter seed <int>` | 随机种子，固定后可复现 |
| `/set parameter num_ctx <int>` | 上下文窗口大小 |
| `/set parameter temperature <float>` | 创造性（温度） |
| `/set parameter top_k <int>` | 从概率最高的 K 个 token 中采样 |
| `/set parameter top_p <float>` | 按概率累计和采样 |
| `/set parameter min_p <float>` | 相对最高概率的最小概率阈值 |
| `/set parameter repeat_last_n <int>` | 回看多少 token 来抑制重复 |
| `/set parameter repeat_penalty <float>` | 重复惩罚强度 |
| `/set parameter num_predict <int>` | 单次最多生成的 token 数 |
| `/set parameter num_gpu <int>` | 送到 GPU 的层数（部分层数为 CPU 时用） |
| `/set parameter stop <string> <string> ...` | 设置停止序列（可多条） |
| `/set format json` | 开启 JSON 输出模式 |
| `/set think` / `/set nothink` | 开启 / 关闭思考模式 |
| `/set history` / `/set nohistory` | 开启 / 关闭历史记录 |
| `/set wordwrap` / `/set nowordwrap` | 开启 / 关闭自动换行 |
| `/set verbose` | 显示 LLM 统计信息（token 耗时等） |

`/show` 的细分项用于检查「模型现在到底是怎么被调用的」，排障时比翻文档快得多：

| 命令 | 作用 |
|------|------|
| `/show info` | 显示当前模型详情（等同 `ollama show`） |
| `/show modelfile` | 显示 Modelfile（含 FROM/模板/参数） |
| `/show template` | 显示提示词模板 |
| `/show parameters` | 显示当前生效的参数 |
| `/show system` | 显示系统消息 |
| `/show license` | 显示许可证 |

```text
典型调试脚本（进会话后依次执行）：
>>> /show template           # 先确认模板特殊 token 对不对
>>> /show parameters         # 再看继承下来的默认参数
>>> /set parameter temperature 0.1
>>> /set parameter num_ctx 8192
>>> /set parameter seed 42
>>> /show parameters         # 确认参数已经生效
>>> /clear                   # 换话题前清上下文，避免旧上下文污染
>>> /bye
```

编辑器相关的快捷键（同样来自真实帮助文本）：`Ctrl+G` 用 `OLLAMA_EDITOR` 指定的编辑器撰写长提示词，`Ctrl+K` 删除光标后的整句，`Alt+F` 向右按词移动。长提示词建议走编辑器而不是直接在 REPL 里敲。

```text
交互内命令要点：
1. /? 看帮助；/set 调参数与环境，/show 看模型当前配置，/clear 清上下文
2. /set parameter 的值只作用于当前会话，退出即失效；要持久化请写进 Modelfile
3. 复现问题需要同时固定 seed 与 temperature，只固定一个仍会有随机性
4. 模板不对（回显问题、复读、不停）时先 /show template 与 /show parameters 对照
5. 长提示词用 Ctrl+G 调外部编辑器写，避免 REPL 里手工编辑出错
6. /load 可以在一段会话里换模型，做新旧模型对比时很省事
```

## 多行输入与图片输入

交互会话里输入多行文本的官方写法是用三引号把整段包起来（`"""` 开头、`"""` 结束），中间可以随意换行；这对粘贴代码、日志、长文档特别有用。注意三引号必须**独占起止位置**（开始的行只写 `"""`），否则会被当成普通文本。

```text
>>> """请把下面这段 Go 代码改成等价的 Python：
... func Sum(xs []int) int {
...     s := 0
...     for _, x := range xs { s += x }
...     return s
... }
... """
```

图片输入不依赖任何额外 SDK：多模态模型支持在提示词里直接写图片路径，官方 CLI 参考给出的示例是 `ollama run gemma4 "What's in this image? /Users/jmorgan/Desktop/smile.png"`。可以做多图对比，也可以把路径与问题混在一句里。需要注意两点：一是模型必须支持视觉（`ollama show <模型>` 的 Capabilities 里应有视觉相关能力，manifest 里也会多出 `projector` 层）；二是走 REST API 时图片要传 base64，而 CLI 走的是本地文件路径，这是两种不同的输入方式。

```shell
# 单图提问（官方示例形式）
ollama run qwen3-vl:8b "这张图里有几只猫？/home/alice/pics/cats.png"

# 多图对比
ollama run qwen3-vl:8b "对比这两张图表的主要差异：/tmp/a.png /tmp/b.png"

# 把图片与长文本一起通过标准输入喂进去（脚本化）
{ printf '请阅读这张发票并抽取金额：'; printf '/data/invoice-001.png\n'; } \
  | ollama run qwen3-vl:8b
```

嵌入模型的输入方式比较特殊：`ollama run <嵌入模型> "文本"` 直接输出 JSON 数组（向量），也可以用管道把文本喂进去。这与生成模型的会话行为完全不同，适合快速验证嵌入模型是否工作、向量维度是多少（本机实测 `all-minilm` 的嵌入长度为 384，见 08.2 的 `ollama show` 输出）。注意 `--dimensions` 参数只对嵌入模型有效，用于把输出向量截断到指定维度。

```shell
# 本机实测（真实输出形态，向量的实际数值取决于模型与权重）
echo "Hello world" | ollama run nomic-embed-text

# 截断到指定维度（嵌入模型专用）
ollama run all-minilm --dimensions 256 "语义检索用的短文本"
```

```text
多行与图片输入要点：
1. REPL 里多行输入用 """ 包裹，起止三引号要独占一行
2. 粘贴代码/日志前先 /set nowordwrap 之类调整显示，阅读体验更好
3. 图片输入在 CLI 里直接写本地路径，模型必须支持视觉
4. 走 API 时图片要 base64 编码，路径形式只在 CLI 生效
5. 嵌入模型在 CLI 里返回 JSON 向量数组，不是自然语言回答
6. --dimensions 只对嵌入模型适用，用于截断向量维度
```

## 常用运行参数

`ollama run` 的参数可以分成四类：输出格式（`--format`）、思考模式（`--think` / `--hidethinking`）、生命周期（`--keepalive`）、诊断与显示（`--verbose` / `--nowordwrap`）。`--format json` 让模型按 JSON 输出（等价于 API 的 `format: "json"`），做结构化抽取时比在提示词里反复叮嘱「请输出 JSON」可靠得多。

```shell
# 结构化输出：要求模型只吐 JSON
ollama run qwen2.5:7b-instruct-q4_K_M --format json \
  "把这句话解析成 JSON，字段为 intent 与 city：帮我查一下明天北京的天气"

# 思考模式：显式开关与档位（支持的模型才有意义）
ollama run qwen3:8b --think "证明根号 2 是无理数"
ollama run qwen3:8b --think=high "证明根号 2 是无理数"
ollama run qwen3:8b --hidethinking "证明根号 2 是无理数"   # 只显示答案，保留思考

# 保活：让模型在内存里多留一会儿（默认 5m，可用 -1 常驻）
ollama run qwen2.5:7b-instruct-q4_K_M --keepalive 30m "你好"
ollama run qwen2.5:7b-instruct-q4_K_M --keepalive -1 "你好"

# 诊断：打印每一步耗时（加载、首 token、生成速度）
ollama run qwen2.5:7b-instruct-q4_K_M --verbose "写一个二分查找"

# 显示控制
ollama run qwen2.5:7b-instruct-q4_K_M --nowordwrap "输出一段长文本"
```

决策模型（decision model，官方能力文档里叫 System One 风格）另有一套参数，用 `--ask` 提问、`--choice` 给候选标签、`--level` 给档位，答案会被约束在这些选项里，适合做「工单路由」「质检判定」这类必须落到枚举值上的场景。官方 CLI 参考里的原始示例：

```shell
# 是 / 否判定
ollama run nimble --ask "Is a refund being requested?" < ticket.txt

# 多选一：候选标签带说明
ollama run nimble --ask "Which team should handle this?" \
  --choice billing="Payments and refunds" \
  --choice technical="Software problems" < ticket.txt

# 档位打分：从低到高
ollama run nimble --ask "How urgent is this?" \
  --level "Routine" \
  --level "Soon" \
  --level "Immediate" < ticket.txt
```

会话中临时改参数用 `/set parameter`（只影响当前会话），要永久生效则写进 Modelfile 的 `PARAMETER`（见 08.5）。两者的优先级关系是：请求体 / 会话设置覆盖 Modelfile 默认值。

```text
常用运行参数要点：
1. --format json 做结构化输出，但仍要在提示词里说明字段，否则可能只吐空对象
2. --think 支持布尔与 high/medium/low 档位，--hidethinking 只隐藏展示不影响计算
3. --keepalive 控制驻留时间，-1 表示常驻，0 表示请求后立即卸载
4. --verbose 打印各阶段耗时，是定位「慢在哪一步」的第一手数据
5. --ask/--choice/--level 只对决策模型有意义，普通生成模型没有这套约束
6. 命令行与会话内参数只覆盖本次/本会话，长期默认值写 Modelfile
```

## 其他常用子命令速查

除 `run` 之外，0.40.4 提供的子命令如下（下表内容来自本机 `ollama --help` 与各子命令 `--help` 的真实输出）：

| 子命令 | 用途 | 关键参数 |
|--------|------|----------|
| `serve`（别名 `start`） | 启动服务 | 环境变量配置见 `ollama serve --help` |
| `create` | 用 Modelfile 创建模型 | `-f/--file`、`-q/--quantize`、`--draft-quantize`、`--combine`、`--force` |
| `show` | 查看模型信息 | `--modelfile`、`--parameters`、`--template`、`--system`、`--license`、`-v/--verbose` |
| `run` | 运行模型 / 进会话 | 见上一节 |
| `stop` | 卸载内存中的模型 | `ollama stop MODEL` |
| `pull` / `push` | 从/向 registry 拉取、推送 | `--insecure` |
| `list`（别名 `ls`） | 列出本地模型 | 无 |
| `ps` | 列出正在加载的模型 | 无 |
| `cp` | 复制模型（零拷贝改名） | `ollama cp SOURCE DESTINATION` |
| `rm` | 删除模型 | 支持一次多个：`ollama rm A B C` |
| `signin` / `signout` | 登录 / 登出 ollama.com | 用于云模型、私有模型、推送 |
| `launch` | 一键配置并启动外部集成 | `--model`、`--config`、`--restore`、`-y` |

`ollama launch` 是 0.40 系列里最省事的集成入口：它会把选中的模型接进各种编码助手/桌面应用里。本机实测支持的集成名单（真实帮助输出）：


```shell
# 交互式选择集成

# 指定集成与模型
ollama launch opencode --model qwen3:8b

# 只写配置不启动（适合先改配置再手动起）
ollama launch codex --config

# 恢复集成的默认配置
```

```text
子命令速查要点：
1. create/show/pull/push/cp/rm 与 REST 接口一一对应，脚本里两者都能用

3. rm 支持一次删多个；cp 是零拷贝改名，用于生成兼容名或版本快照
4. launch 覆盖 Claude Code、Codex、OpenCode、Hermes、VS Code 等主流集成
5. launch 的 --config 只写配置不启动，适合纳入自动化初始化脚本
6. 所有子命令共享 OLLAMA_HOST；跨机器操作无需额外参数
```

## 应用场景实战

### 场景一：在会话里做提示词与参数联调，再固化成 Modelfile

某团队要做一个「工单分类」小模型，需要一个稳定、可复现、能落到固定标签上的分类器。做法是先在交互会话里把提示词与参数调通（用 `/show` 确认模板、用 `/set parameter` 逐项试、用 `/clear` 保证每轮干净），确认效果后把参数与系统提示固化进 Modelfile 并构建成带版本号的模型，最后用一次性调用做回归。

```text
第一步：交互联调（示例会话，命令均为真实可用命令）
>>> /show template
{{ if .System }}<|im_start|>system
{{ .System }}<|im_end|>
{{ end }}{{ if .Prompt }}<|im_start|>user
{{ .Prompt }}<|im_end|>
{{ end }}<|im_start|>assistant

>>> /set parameter temperature 0.0
>>> /set parameter seed 42
>>> /set parameter num_ctx 4096
>>> /set parameter stop <|im_end|>
>>> /show parameters
temperature                    0
seed                           42
num_ctx                        4096
stop                           "<|im_end|>"

>>> /clear
>>> 登录不上，提示密码错误
账号问题
>>> /bye
```

```shell
# 第二步：把调好的参数与系统提示固化成 Modelfile
cat > Modelfile.ticket <<'EOF'
FROM qwen2.5:7b-instruct-q4_K_M

PARAMETER temperature 0.0
PARAMETER seed 42
PARAMETER num_ctx 4096
PARAMETER stop "<|im_end|>"

SYSTEM """把输入工单归入以下类别之一，只输出类别名：
账号问题 / 支付问题 / 物流问题 / 商品质量 / 其他。"""
EOF

ollama create ticket-cls:v1 -f ./Modelfile.ticket
ollama show ticket-cls:v1 | head -12
```

```bash
#!/usr/bin/env bash
# 第三步：回归测试（一次性调用，退出码非零即失败）
set -euo pipefail
MODEL="ticket-cls:v1"
fail=0

run_case() {
  local text="$1" expect="$2" got
  got=$(ollama run "$MODEL" "$text" | tr -d '\r' | tail -1)
  if [ "$got" = "$expect" ]; then
    echo "[OK ] 期望=$expect 实际=$got :: $text"
  else
    echo "[BAD] 期望=$expect 实际=$got :: $text"; fail=1
  fi
}

run_case "登录不上，提示密码错误" "账号问题"
run_case "付款后订单一直没生成" "支付问题"
run_case "快递三天没动" "物流问题"
run_case "收到货屏幕有划痕" "商品质量"

exit "$fail"
```

```text
联调与固化要点：
1. 会话里先 /show template 确认特殊 token 与停止符，再谈参数，否则调什么都白搭
2. 分类类任务 temperature 设 0 并固定 seed，输出才可审计、可回归
3. 每轮换话题前 /clear，避免上一轮上下文影响判定结果
4. 会话里验证过的参数原样写进 Modelfile 的 PARAMETER，别凭记忆转录
5. 回归脚本退出码要能反映失败，这样才能挂进 CI
6. 未在本机验证：本机缺 llama-server，上述 run 调用会报运行时缺失错误
```

### 场景二：用管道把命令行接进现有运维流程

值班同学需要一条命令就能把告警日志归类、把结论写进值班记录。做法是不进 REPL，全部走「标准输入 + `--format json` + `--verbose`」，输出重定向到文件并带上耗时，方便事后复盘与成本核算。

```bash
#!/usr/bin/env bash
# triage.sh —— 读取日志文件，输出结构化判定 + 耗时统计
set -euo pipefail

LOG_FILE="${1:-/var/log/app.log}"
OUT_DIR="${2:-/var/log/triage}"
mkdir -p "$OUT_DIR"
STAMP=$(date +%Y%m%d-%H%M%S)

if ! curl -sf http://localhost:11434/api/version >/dev/null; then
  echo "Ollama 服务不可用，请先启动 ollama serve"; exit 1
fi

# 结构化输出：字段固定，便于下游入库
tail -n 200 "$LOG_FILE" | ollama run qwen2.5:7b-instruct-q4_K_M --format json \
  "阅读下面的应用日志，判断严重级别（fatal/error/warn/info），并给出一句话处置建议。
   只输出 JSON，字段为 level 与 advice。" > "$OUT_DIR/$STAMP.json" 2> "$OUT_DIR/$STAMP.err"

# 耗时统计：--verbose 的输出进 stderr，单独留档
ollama run qwen2.5:7b-instruct-q4_K_M --verbose "总结这次故障的一句话结论" \
  > "$OUT_DIR/$STAMP.summary" 2>> "$OUT_DIR/$STAMP.err"

echo "结果：$OUT_DIR/$STAMP.json"
python3 -c "
import json,sys
d=json.load(open('$OUT_DIR/$STAMP.json'))
assert 'level' in d, '模型输出缺 level 字段'
print('级别:', d['level']); print('建议:', d['advice'])
"
```

配套的「模型与环境自检」命令，出问题时先跑这一段，比直接翻日志快：

```shell
# 一条命令确认「服务在不在、模型有没有、到底跑在什么设备上、上下文多大」
curl -s http://localhost:11434/api/version && echo
ollama list
ollama ps
ollama show qwen2.5:7b-instruct-q4_K_M | head -8

# 冷启动 vs 已加载的耗时对比（模型常驻能省掉加载时间）
ollama run qwen2.5:7b-instruct-q4_K_M --verbose "你好" 2>&1 | tail -8
ollama run qwen2.5:7b-instruct-q4_K_M --keepalive 30m "你好"
ollama run qwen2.5:7b-instruct-q4_K_M --verbose "你好" 2>&1 | tail -8
```

```text
管道化落地要点：
1. 脚本化一律用「stdin 管道 + 一次性调用」，不要试图驱动交互 REPL
2. --format json 的输出要按字段校验（缺字段就报警），不能直接信任
3. --verbose 的耗时信息走 stderr，重定向时记得单独留档
4. 批次任务前先探测 /api/version，服务没起就别排队
5. 用 --keepalive 让模型常驻，能显著降低连续多次调用的首 token 延迟
6. 未在本机验证：上述 run 调用在本机缺 llama-server 时会立即失败
```

## 最佳实践与踩坑记录

### 最佳实践

1. 交互调参用会话（`/set parameter` + `/show`），定型后立刻把参数与提示词固化进 Modelfile 并建带版本号的模型，避免「只有我知道当时怎么调的」。
2. 脚本与 CI 里只用一次性调用（PROMPT 参数或 stdin 管道），绝不驱动交互式 REPL。
3. 结构化输出统一用 `--format json`，并在提示词里明确字段名，再做一层字段校验。
4. 调试慢问题时先 `--verbose` 拿分段耗时，再用 `--keepalive` 排除加载开销，最后才怀疑模型本身。
5. 复现问题必须同时固定 `seed` 与 `temperature`，并把参数写进回归脚本注释里。
6. 长提示词走 `Ctrl+G`（`OLLAMA_EDITOR`）编辑，不要手敲多行文本。
7. 需要检查「模型当前实际配置」时用 `/show template` 与 `/show parameters`，不要凭印象判断。

### 踩坑记录

```text
坑 1：进入会话后模型不停顿、复读或直接回显问题
结论：输出异常，怀疑模型坏了。
原因：TEMPLATE 与模型的特殊 token 不匹配，或缺少结束符 stop。
解法：会话内先 /show template 看模板，/show parameters 看是否带 stop；对照 08.5 的模板写法修正，
      或改用 ollama show --modelfile <基座> 导出的官方模板重建模型。

坑 2：脚本里用 ollama run 卡住不动
结论：批处理任务挂死，日志无输出。
原因：把交互式 REPL 当成批处理用（没带 PROMPT 参数又没喂 stdin），进程在等输入。
解法：脚本里必须给 PROMPT 参数或用管道喂标准输入，例如 echo "文本" | ollama run <模型>；
      同时加 timeout 兜底，避免网络或模型异常导致永久等待。

坑 3：多行输入被拆成多次提问
结论：三引号包裹的代码被当成多轮消息发出去。
原因：""" 没有独占一行，或结尾的三引号后面跟了别的字符。
解法：起始行只写 """，结束行也只写 """；复杂长文本改用 Ctrl+G 调编辑器写。

坑 4：--format json 之后模型输出的却是空的 JSON 或一大段空白
结论：解析失败，拿到的不是想要的字段。
原因：只设了 format 但提示词里没有明确要求「输出 JSON」与字段名，模型倾向于先输出空白/散文本。
解法：提示词必须显式说明输出 JSON 及字段；拿到结果后做字段存在性校验，缺字段直接判失败重试。

坑 5：图片提问没反应，或报模型不支持图片
结论：视觉任务返回错误。
原因：用的模型没有视觉能力（Capabilities 里没有对应项），或把 base64 与本地路径传错了位置。
解法：先 ollama show <模型> 确认能力，并选视觉模型（manifest 会多出 projector 层）；
      CLI 传本地文件路径，REST API 传 base64 编码的 images 数组。

坑 6：测出来同一提示词每次结果都不一样，回归测试一直抖动
结论：回归用例时好时坏，无法判定模型改动是否有效。
原因：只固定了 temperature 而没固定 seed，或每次调用前上下文没清。
解法：同时固定 seed 与 temperature；交互会话里换话题前用 /clear；把这两点写进回归脚本。
```

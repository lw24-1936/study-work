## 概述

文本表示要回答一个问题：怎么把「一段话」变成一个向量，使得**语义相近的文本在向量空间里也相近**。这条路一共走了四步：稀疏的词袋与 TF-IDF（只看词有没有出现）、静态词向量（每个词一个稠密向量，词义学出来了）、子词表示（BPE/WordPiece，解决未登录词与词表爆炸）、上下文表示（同一个词在不同句子里得到不同向量）。四步不是替代关系：线上检索系统今天依然大量使用 TF-IDF 与 BM25，深度模型也常把稀疏特征和稠密向量拼接使用。

```text
本篇主线：
1. 词袋与 n-gram —— CountVectorizer 的矩阵形态、词表控制（min_df/max_df）、字符 n-gram
2. TF-IDF —— 公式与 sklearn 实现细节（smooth_idf / sublinear_tf / norm），余弦相似度
3. 静态词向量 —— 共现矩阵 -> PPMI -> SVD 的完整推导与本机实测邻居词
4. 子词与 BPE —— 从零实现 BPE 训练循环，理解 merges 表与词表的配套关系
5. 上下文表示 —— 平均词向量 vs TF-IDF 加权句向量，以及 BERT 类模型的差异
6. 向量检索 —— NearestNeighbors + 余弦，以及「不该用欧氏距离」的原因
```

## 词袋与 n-gram

词袋模型（Bag of Words）把文档表示成「词表长度」的稀疏向量，每个位置是该词在该文档里的计数。它丢掉了词序，但换来极快的计算与完全的可解释性。n-gram 是补词序的最小代价方案：把相邻 n 个 token 拼成一个新特征（`壳 质量`），代价是词表膨胀。中文必须先分词（或用字符 n-gram 绕过分词），并注意 `CountVectorizer` 的默认 `token_pattern` 是 `(?u)\b\w\w+\b`，会过滤掉单字符 token 并把标点当分隔符——中文场景要显式传 `tokenizer` 与 `token_pattern=None`。

```python
import re
import numpy as np
import jieba
from sklearn.feature_extraction.text import CountVectorizer

docs = ["手机壳质量很好，物流很快", "物流太慢，手机壳质量一般",
        "客服态度很好，物流也快", "手机壳破损了，物流太慢"]
PUNCT = re.compile(r"[\W_]+", re.UNICODE)
def tok(s):
    return [w for w in jieba.lcut(s) if w.strip() and not PUNCT.fullmatch(w)]

cv = CountVectorizer(tokenizer=tok, token_pattern=None, lowercase=False)
X = cv.fit_transform(docs)
print("文档数/词表大小:", X.shape, "| 非零元素:", X.nnz,
      "| 稀疏度: %.1f%%" % (100 * (1 - X.nnz / (X.shape[0] * X.shape[1]))))
print("词表:", list(cv.get_feature_names_out()))
print("文档-词矩阵:\n", X.toarray())

cv2 = CountVectorizer(tokenizer=tok, token_pattern=None, lowercase=False, ngram_range=(1, 2))
print("ngram_range=(1,2) 词表大小:", cv2.fit_transform(docs).shape[1], "| 二元组示例:",
      [w for w in cv2.get_feature_names_out() if " " in w][:6])

for kw in ({"min_df": 1}, {"min_df": 2}, {"max_df": 3}, {"binary": True}):
    v = CountVectorizer(tokenizer=tok, token_pattern=None, lowercase=False, **kw)
    print("%-16s 词表 %d" % (str(kw), v.fit_transform(docs).shape[1]))

ccv = CountVectorizer(analyzer="char", ngram_range=(2, 3))
Xc = ccv.fit_transform(["手机壳质量很好", "手机壳质量一般"])
print("char 2-3gram 词表:", list(ccv.get_feature_names_out())[:8], "...")
print("字符级矩阵形状:", Xc.shape)
```

4 篇文档、15 个词却有 56.7% 的稀疏度——文本数据的标准形态（真实语料稀疏度通常 99.9% 以上）。`min_df=2` 一次把词表从 15 压到 7，`max_df=3` 则把「物流」（出现在 4 篇里）这种高频词滤掉：前者去噪声，后者去通用词，方向相反、都别乱用。

```text
词袋与 n-gram 要点：
1. 中文必须传自定义 tokenizer 并设 token_pattern=None，否则默认规则会切错
2. n-gram 用词表膨胀换词序信息；中文常用 (1,2)，英文常用 (1,2) 或 (1,3)
3. min_df 去低频噪声（拼写错误、ID），max_df 去高频通用词（相当于自动停用词）
4. 字符级 n-gram（analyzer='char' / 'char_wb'）不依赖分词器，对错别字与新词更鲁棒
5. 稀疏矩阵不要 toarray() 进模型（内存爆炸），只在调试时看形状与前几行
```

## TF-IDF 与向量空间

TF-IDF 在词频基础上乘以逆文档频率，把「到处都有的词」压下去。sklearn 的实现（TfidfVectorizer）默认 `smooth_idf=True`，即 `idf(t) = ln((1+n)/(1+df(t))) + 1`，最后按 `norm='l2'` 归一化整行——归一化之后**余弦相似度就等于点积**，这是它被检索系统大量使用的原因。`sublinear_tf=True` 会把 tf 换成 `1 + log(tf)`，对长文档更友好。

```python
import numpy as np
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.metrics.pairwise import cosine_similarity

tf = TfidfVectorizer(tokenizer=tok, token_pattern=None, lowercase=False).fit(docs)
Xt = tf.transform(docs)
print("idf(物流) = %.4f | 手算 ln((1+4)/(1+4))+1 = %.4f"
      % (tf.idf_[list(tf.get_feature_names_out()).index("物流")], np.log(5 / 5) + 1))
print("idf(破损) = %.4f | 手算 ln((1+4)/(1+1))+1 = %.4f"
      % (tf.idf_[list(tf.get_feature_names_out()).index("破损")], np.log(5 / 2) + 1))
print("矩阵(保留3位):\n", np.round(Xt.toarray(), 3))

for kw in ({}, {"norm": None}, {"sublinear_tf": True}, {"smooth_idf": False}, {"use_idf": False}):
    v = TfidfVectorizer(tokenizer=tok, token_pattern=None, lowercase=False, **kw)
    m = np.asarray(v.fit_transform(docs).todense())
    j = list(v.get_feature_names_out()).index("物流")
    print("%-24s tfidf(物流,doc0)=%.4f | 最大列值=%.4f | 第1行L2范数=%.4f"
          % (str(kw), m[0, j], m.max(), np.linalg.norm(m[0])))

sim = cosine_similarity(Xt)
print("相似度矩阵(保留3位):\n", np.round(sim, 3))
for i in range(len(docs)):
    for j in range(i + 1, len(docs)):
        print("doc%d ~ doc%d = %.4f   「%s」 vs 「%s」" % (i, j, sim[i, j], docs[i], docs[j]))
```

```text
4. use_idf=False 退化为「L2 归一化的词频」，跟词袋只差一个归一化
5. 小语料（4 篇）下 idf 区分度极弱（物流=1.0），TF-IDF 的价值随语料规模增长
6. HashingVectorizer 无状态、可流式（适合在线/超大语料），但拿不回词表，可解释性为零
```

## 静态词向量

静态词向量给每个词一个稠密向量，语义相近的词向量也相近。经典做法是「共现矩阵 -> PPMI 加权 -> 降维（SVD/SGNS）」，Word2Vec 的 skip-gram 可以看作对共现矩阵的隐式分解（Levy & Goldberg 2014）。下面这段用 NumPy 完整实现这条链路：窗口共现计数、PMI 与正部截断、TruncatedSVD 降维、余弦最近邻。

```python
import re
from collections import Counter
import numpy as np
import jieba
from sklearn.decomposition import TruncatedSVD

corpus = [
    "发货很快，物流很快，快递员态度很好", "物流太慢，快递一直不揽件，发货很久",
    "我要申请退款，退货流程太慢，售后不回复", "退款到账很快，售后处理让人满意",
    "手机壳做工很好，手感不错，质量耐用", "做工一般，质量不行，手机壳容易破损",
    "客服态度很好，回复很快，工单处理及时", "客服不回复，工单一直没人处理，态度很差",
    "电池耐用，充电很快，屏幕清晰", "电池续航差，充电太慢，屏幕有亮点",
    "快递已签收，物流显示签收成功，发货及时", "退货申请被拒绝，售后要求提供凭证",
    "屏幕碎了，手机需要换屏，售后维修很慢", "充电器发热严重，做工粗糙，质量堪忧",
    "工单提交后客服很快回复，问题解决了", "物流信息一直不更新，快递揽件很慢",
]
PUNCT = re.compile(r"[\W_]+", re.UNICODE)
def tok(s):
    return [w for w in jieba.lcut(s) if w.strip() and not PUNCT.fullmatch(w)]

WIN = 3
vocab = Counter(w for d in corpus for w in tok(d))
word2id = {w: i for i, w in enumerate(vocab)}
print("语料 %d 句 | 词表 %d | 最高频: %s" % (len(corpus), len(vocab), vocab.most_common(5)))

C = np.zeros((len(vocab), len(vocab)))
for d in corpus:
    ws = [w for w in tok(d) if w in word2id]
    for i, w in enumerate(ws):
        for j in range(max(0, i - WIN), min(len(ws), i + WIN + 1)):
            if i != j:
                C[word2id[w], word2id[ws[j]]] += 1.0

total, row, col = C.sum(), C.sum(axis=1, keepdims=True), C.sum(axis=0, keepdims=True)
PMI = np.log((C * total) / (row * col))
PPMI = np.nan_to_num(np.maximum(PMI, 0))          # PMI 取正部，负值截断为 0
print("共现非零个数: %d | PPMI 非零率: %.2f%%" % (int((C > 0).sum()), 100 * (PPMI > 0).mean()))

svd = TruncatedSVD(n_components=10, random_state=0)
W = svd.fit_transform(PPMI)
W = W / (np.linalg.norm(W, axis=1, keepdims=True) + 1e-9)
print("词向量维度: %d | 前 10 个奇异值解释方差占比: %.4f" % (W.shape[1], svd.explained_variance_ratio_.sum()))

def neighbors(word, k=5):
    sims = W @ W[word2id[word]]
    order = np.argsort(-sims)
    return [(list(vocab)[i], round(float(sims[i]), 3)) for i in order if list(vocab)[i] != word][:k]

for w in ["发货", "客服", "质量", "退款"]:
    print("  %-4s 的邻居: %s" % (w, neighbors(w)))
```

```text
共现非零个数: 570 | PPMI 非零率: 9.30%
词向量维度: 10 | 前 10 个奇异值解释方差占比: 0.4940
  发货   的邻居: [('签收', 0.976), ('成功', 0.974), ('已', 0.972), ('显示', 0.97), ('物流', 0.949)]
  客服   的邻居: [('后', 0.99), ('提交', 0.986), ('回复', 0.951), ('工单', 0.907), ('问题', 0.818)]
```

邻居词质量说明了静态词向量的能力边界：`质量` 的邻居是 `做工/一般/堪忧/手感/不行`（正确学到同域词），但 `发货` 的邻居里混进 `已/显示/成功` 这种虚词（窗口太浅、语料太小），`退款` 甚至把 `我要` 当成最近邻（1.0）。语料量、窗口大小、降维维度都会显著影响结果，这也是为什么生产上直接用预训练向量或 gensim 的成熟实现。

```python
# 静态词向量的根本缺陷：同一个词在任何上下文里向量完全相同
print("质量 的向量（前 6 维）:", np.round(W[word2id["质量"]][:6], 4))
print("'手机壳做工很好，质量耐用' 与 '做工一般，质量不行' 里，质量 用的是同一个向量")
print("余弦(质量, 好) = %.4f | 余弦(质量, 不行) = %.4f  <- 同时都高，无法区分极性"
      % (float(W[word2id["质量"]] @ W[word2id["好"]]), float(W[word2id["质量"]] @ W[word2id["不行"]])))
```

本机真实输出：

```text
质量 的向量（前 6 维）: [-0.1022  0.3832  0.0535  0.3593  0.0837 -0.1425]
余弦(质量, 好) = 0.7653 | 余弦(质量, 不行) = 0.7816  <- 同时都高，无法区分极性
```

```text
静态词向量要点：
1. 标准路线：窗口共现 -> PMI -> 负值截断(PPMI) -> SVD / SGNS 降维，再 L2 归一化
2. 邻居词是最好的质检手段：一眼就能看出语料是否太小、窗口是否太浅
3. 小语料（16 句）也能学到同域词（做工/手感），但会混入虚词，且稀有词向量不稳
4. 静态词向量与上下文无关：同一个词在任何句子里的向量都一样（本例 质量 与 好/不行 都相似）
5. 生产上用 gensim Word2Vec/FastText 或现成向量文件，别自己维护矩阵分解工程
6. 词向量必须与训练语料、切词方式绑定，换分词器后旧向量不可复用
```

## 子词与 BPE

子词表示解决两个问题：**未登录词**（词表里没有的词用子词拼出来）和**词表爆炸**（几十万词的词表太大）。BPE（Byte-Pair Encoding）的算法极简：从字符级开始，反复统计最频繁的相邻符号对并合并成一个新符号，重复 N 次得到 merges 表。推理时按同一顺序应用 merges 表切分新词。GPT-2 用字节级 BPE，BERT 用 WordPiece，中文场景常用 SentencePiece（`▁` 标记空格）。

```python
from collections import Counter

text = ("refund refund refundable shipping shipped ship ship ship "
        "发货很快 发货及时 发货慢 发货 快递发货 客服回复 客服态度 客服不回复")
words = Counter(text.split())
splits = {w: list(w) + ["</w>"] for w in words}   # </w> 标记词尾，保证能还原
print("初始符号集合大小:", len(set(s for sp in splits.values() for s in sp)))

def get_pairs():
    p = Counter()
    for w, cnt in words.items():
        sp = splits[w]
        for i in range(len(sp) - 1):
            p[(sp[i], sp[i + 1])] += cnt
    return p

merges = []
for step in range(20):
    pairs = get_pairs()
    if not pairs:
        break
    (a, b), freq = pairs.most_common(1)[0]
    merges.append((a, b, freq))
    for w in words:                       # 把出现过的 (a,b) 全部合并
        sp, out, i = splits[w], [], 0
        while i < len(sp):
            if i < len(sp) - 1 and sp[i] == a and sp[i + 1] == b:
                out.append(a + b); i += 2
            else:
                out.append(sp[i]); i += 1
        splits[w] = out
print("前 20 次合并 (左, 右, 频次):")
for m in merges:
    print("   ", m)

def encode(word):
    sp = list(word) + ["</w>"]
    for a, b, _ in merges:
        out, i = [], 0
        while i < len(sp):
            if i < len(sp) - 1 and sp[i] == a and sp[i + 1] == b:
                out.append(a + b); i += 2
            else:
                out.append(sp[i]); i += 1
        sp = out
    return sp
for w in ["refundable", "shipping", "发货快"]:
    print("  %-12s -> %s" % (w, encode(w)))
```

```text

2. 语料小时 BPE 会把整词合并成一个 token（本例 refundable），等于没起到子词泛化作用
3. 常见实现差异：GPT-2 用字节级 BPE、BERT 用 WordPiece（## 前缀）、SentencePiece 用 ▁ 表示空格
4. 子词让词表可控（几万），未登录词可拆解，代价是序列变长、语义单元变碎
5. 中文可用字符/子词混合作 BPE 语料；中文 token 数比英文多，直接决定推理成本
6. 工程上不要手写 BPE：HuggingFace tokenizers 或 sentencepiece 已把训练/推理/序列化做全
```

## 上下文表示与句向量

上下文表示（ELMo / BERT 及之后的模型）的核心变化是：**同一个词的向量取决于它所在的句子**。这让「苹果手机」与「吃苹果」里的「苹果」不再共享一个向量。代价是需要 Transformer 编码器与预训练权重，本机离线无法实测（transformers 未安装、无权重文件），所以下面用可跑通的方式演示「句向量」的两种手工构造：等权平均词向量 vs TF-IDF 加权平均词向量，并用它们做检索，观察差别。

```python
import numpy as np
import re
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.metrics.pairwise import cosine_similarity

tf = TfidfVectorizer(tokenizer=tok, token_pattern=None, lowercase=False).fit(corpus)
names = list(tf.get_feature_names_out())
Xt_corpus = tf.transform(corpus)

def sentence_vec(s, weighted=True):
    ws = [w for w in tok(s) if w in word2id]
    if not ws:
        return np.zeros(W.shape[1])
    vs = np.array([W[word2id[w]] for w in ws])
    if weighted:
        wt = np.array([float(tf.idf_[names.index(w)]) if w in names else 1.0 for w in ws])
        v = np.average(vs, axis=0, weights=wt)
    else:
        v = vs.mean(axis=0)
    return v / (np.linalg.norm(v) + 1e-9)

query = "发货太慢"
for tag, qv in (("TF-IDF 加权平均", sentence_vec(query, True)), ("等权平均", sentence_vec(query, False))):
    sims = [float(cosine_similarity(qv.reshape(1, -1), sentence_vec(d, False).reshape(1, -1))[0, 0]) for d in corpus]
    print("%s 检索「%s」 top-3:" % (tag, query))
    for i in np.argsort(-np.array(sims))[:3]:
        print("    %.4f  %s" % (sims[i], corpus[i]))

qsp = tf.transform([query])
s_sim = cosine_similarity(qsp, Xt_corpus).ravel()
print("TF-IDF 稀疏向量直接检索 top-3:")
for i in np.argsort(-s_sim)[:3]:
    print("    %.4f  %s" % (s_sim[i], corpus[i]))
```

有意思的是：在这个 16 句的小语料上，idf 加权平均与等权平均给出**完全相同**的排序（idf 值都被 `+1` 拉平到 1.0~1.9 的窄区间，权重几乎均匀），而稀疏 TF-IDF 的排序又是另一套。这说明「加权方式」只有在语料足够大、idf 差异明显时才会产生差异；语料小时换权重方案是白费功夫，应该先去扩数据。更重要的是：三者都是在词面重合上做文章——`发货太慢` 排第一的永远是含 `发货/慢` 的句子，真正语义最近的表达（`一直不揽件`、`配送磨蹭`）根本进不了 top-3。上下文表示（BERT/Sentence-BERT）能做到的正是这件事，用法与参数以官方文档为准（transformers: https://huggingface.co/docs/transformers ，sentence-transformers: https://www.sbert.net ）。

```text
上下文表示与句向量要点：
1. 上下文表示的本质：同一个词在不同句子里得到不同向量；静态向量做不到
2. 手工句向量三选一：等权平均（简单）、idf/TF-IDF 加权平均（强调关键词）、池化模型（最佳）
3. 小语料上加权与等权几乎无差别（本例排序完全相同），说明 idf 需要足够大的语料才有区分度
4. 稀疏 TF-IDF 与稠密句向量是可组合的：拼接后往往比单独用更好（见下一节实测）
5. 预训练模型选型看语言/领域/尺寸与延迟预算，务必按官方文档确认权重与分词器配套
6. 句向量必须配归一化，否则内积等于带长度权重的相似度
```

## 向量检索与相似度

检索系统的核心是「候选生成 + 排序」，向量相似度负责候选生成。工程上要注意三件事：**度量选择**（余弦 vs 欧氏 vs 内积）、**归一化**（L2 归一化后三者关系发生变化）、**索引结构**（小规模用暴力检索，大规模上近似最近邻）。sklearn 的 `NearestNeighbors` 适合十万级以内的离线场景；再大规模就要上 FAISS / HNSW 之类。

```python

    dist, idx = nn.kneighbors(tf.transform([q]))
    print("查询「%s」:" % q)
    for d, i in zip(dist[0], idx[0]):
        print("    相似度 %.4f | %s" % (1 - d, corpus[i]))

# 未做 L2 归一化的 TF-IDF 上使用欧氏距离，长文档会被系统性排到后面

print("余弦 top-3:", [corpus[i][:16] for i in i_c[0]])
```

## 应用场景实战

### 场景一：客服工单相似问题检索

工单系统的刚需是「新工单能不能并进已有问题」。做法：把历史工单建成向量库，新工单检索 top-k，超过阈值自动归并、低于阈值新建并交人工确认。下面这段在本机真实跑通，同时对比词级与字符级表示，并给出「同义不同词」的失败案例。

```python
import re
import numpy as np
import jieba
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.metrics.pairwise import cosine_similarity

KB = ["订单显示已签收但没收到货怎么办", "包裹显示签收，实际没有送到，怎么处理",
      "物流三天不更新，一直停在揽件状态", "快递一直没动，物流信息好几天不更新",
      "付款成功但订单没生成，钱会被退回来吗", "钱扣了订单却没有创建，需要处理重复扣款",
      "优惠券结算时用不了，提示不满足条件", "发票怎么申请电子发票，需要多久",
      "账户登录不上，验证码收不到", "APP 打开闪退，重装也没用"]
QUERIES = ["快递信息好久没刷新了", "扣款了但是没订单", "登录收不到验证码"]

PUNCT = re.compile(r"[\W_]+", re.UNICODE)
def tok(s):
    return [w for w in jieba.lcut(s) if w.strip() and not PUNCT.fullmatch(w)]

for kind, name in (("word", "词级 TF-IDF(1-2gram)"), ("char", "字符 2-4gram")):
    vec = (TfidfVectorizer(tokenizer=tok, token_pattern=None, lowercase=False, ngram_range=(1, 2))
           if kind == "word" else TfidfVectorizer(analyzer="char_wb", ngram_range=(2, 4)))
    M = vec.fit_transform(KB)
    print("%s 特征维度 %d" % (name, M.shape[1]))
    for q in QUERIES:
        sims = cosine_similarity(vec.transform([q]), M).ravel()
        order = np.argsort(-sims)[:2]
        print("  查询「%s」 -> %.3f %s" % (q, sims[order[0]], KB[order[0]]))
        print("               %.3f %s" % (sims[order[1]], KB[order[1]]))

vec = TfidfVectorizer(analyzer="char_wb", ngram_range=(2, 4))
M = vec.fit_transform(KB)
for q in ["快递信息好久没刷新了", "请问怎么注销这个账号，完全没人用"]:

    score = cosine_similarity(vec.transform([q]), M).ravel()[best]
    print("  查询「%s」 最高相似度 %.3f -> %s"
          % (q, score, "自动归并到已有工单" if score >= 0.45 else "新建工单（低于阈值，交人工确认）"))

pairs = [("退货怎么弄", "我想把货退掉"), ("快递太慢了", "物流速度让人崩溃"), ("客服不理人", "售后一直不回复")]

M2 = vec.fit_transform([a for a, _ in pairs] + [b for _, b in pairs])
n = len(pairs)
for i, (a, b) in enumerate(pairs):
    print("  「%s」 vs 「%s」 = %.3f" % (a, b, float(cosine_similarity(M2[i], M2[n + i])[0, 0])))
```

### 场景二：业务语料自训练词向量做文档分类，与 TF-IDF 对比

稠密表示能不能替代稀疏特征？用一个可复现实验回答：在业务语料（含无标注文本）上训练 PPMI-SVD 词向量，把文档表示成词向量平均，训 LogisticRegression，与 TF-IDF 方案、以及两者拼接做对比。

```python
import csv
import numpy as np
from sklearn.decomposition import TruncatedSVD
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.linear_model import LogisticRegression
from sklearn.pipeline import Pipeline

rows = {"train": [], "val": [], "test": []}
with open("/root/.hermes/cache/scratch/nlp164_data.csv", encoding="utf-8") as f:
    for r in csv.DictReader(f):
        rows[r["split"]].append((r["tokenized"].split(), int(r["label"])))
Xtr_tok = [t for t, _ in rows["train"]]
ytr = [y for _, y in rows["train"]]
Xte_tok = [t for t, _ in rows["test"]]
yte = [y for _, y in rows["test"]]
corpus_tokens = [t for t, _ in rows["train"]] + [t for t, _ in rows["val"]] + [t for t, _ in rows["test"]]

from collections import Counter
vocab = Counter(w for t in corpus_tokens for w in t)
word2id = {w: i for i, w in enumerate(vocab)}
WIN = 3
C = np.zeros((len(vocab), len(vocab)))
for t in corpus_tokens:
    for i, w in enumerate(t):
        for j in range(max(0, i - WIN), min(len(t), i + WIN + 1)):
            if i != j:
                C[word2id[w], word2id[t[j]]] += 1.0
row, col, total = C.sum(1, keepdims=True), C.sum(0, keepdims=True), C.sum()
PMI = np.log((C * total) / (row * col))
PPMI = np.nan_to_num(np.maximum(PMI, 0))
svd = TruncatedSVD(n_components=64, random_state=0)
W2 = svd.fit_transform(PPMI)
W2 = W2 / (np.linalg.norm(W2, axis=1, keepdims=True) + 1e-9)
print("语料 %d 条 | 词表 %d | 词向量 %d 维 | SVD 方差解释 %.3f"
      % (len(corpus_tokens), len(vocab), W2.shape[1], svd.explained_variance_ratio_.sum()))

def doc_vec(tokens):
    vs = [W2[word2id[w]] for w in tokens if w in word2id]
    if not vs:
        return np.zeros(W2.shape[1])
    v = np.mean(vs, axis=0)
    return v / (np.linalg.norm(v) + 1e-9)

Dtr = np.array([doc_vec(t) for t in Xtr_tok])
Dte = np.array([doc_vec(t) for t in Xte_tok])
pred = LogisticRegression(max_iter=2000, C=4.0).fit(Dtr, ytr).predict(Dte)
print("词向量平均 + LR : 测试 acc=%.4f macroF1=%.4f"
      % (accuracy_score(yte, pred), f1_score(yte, pred, average="macro")))

sparse = TfidfVectorizer(tokenizer=str.split, token_pattern=None, lowercase=False)
Atr, Ate = sparse.fit_transform([" ".join(t) for t in Xtr_tok]), sparse.transform([" ".join(t) for t in Xte_tok])
pred2 = LogisticRegression(max_iter=1000, C=4.0).fit(Atr, ytr).predict(Ate)
print("TF-IDF + LR     : 测试 acc=%.4f macroF1=%.4f"
      % (accuracy_score(yte, pred2), f1_score(yte, pred2, average="macro")))

union = np.hstack([Dtr, Atr.toarray()])
union_te = np.hstack([Dte, Ate.toarray()])
pred3 = LogisticRegression(max_iter=2000, C=4.0).fit(union, ytr).predict(union_te)
print("词向量 + TF-IDF : 测试 acc=%.4f macroF1=%.4f"
      % (accuracy_score(yte, pred3), f1_score(yte, pred3, average="macro")))
```

本机真实输出：

```text
语料 1500 条 | 词表 225 | 词向量 64 维 | SVD 方差解释 0.774
词向量平均 + LR : 测试 acc=0.7667 macroF1=0.7593
TF-IDF + LR     : 测试 acc=0.7600 macroF1=0.7578
词向量 + TF-IDF : 测试 acc=0.7867 macroF1=0.7856
```

三个结论：这个语料规模下（1500 条、225 词表）词向量平均与 TF-IDF 基本打平（0.7593 vs 0.7578）；两者拼接有 +0.026 的收益（0.7856）；词向量的优势要靠**未标注语料规模**堆出来——本机用训练集里的文本一起建共现矩阵，只多了 300 条无标注样本，所以体现不出差距。

```text
场景二要点：
1. 稠密词向量与稀疏 TF-IDF 是互补的，拼接通常比单用更好（本例 +0.026 macroF1）
2. 自训练词向量的收益随无标注语料规模增长；小语料下别指望它替代 TF-IDF
3. PPMI+SVD 的关键参数是窗口（本例 3）与维度（64），维度太高在小语料上过拟合
4. 词向量可在无标注数据上训练，这是它在标注稀缺场景的真正价值
5. 与预训练向量比，自训练向量的优势是域内词覆盖，劣势是泛化与规模
```

## 最佳实践与踩坑记录

最佳实践：

1. 先上 TF-IDF/BM25 做基线检索与分类，再评估是否值得引入稠密向量；稀疏方案可解释、可调试、成本极低。
2. 词表控制三件套（`min_df`、`max_df`、`max_features`）要显式设定并写进配置，别吃默认值。
3. 表示与分词器绑定：换分词器等于换表示，历史指标、缓存向量、模型权重都要重跑或重建。
4. 检索用余弦 + L2 归一化；稀疏矩阵不要 toarray 进模型，拼接稠密特征时才局部展开。
5. 词向量入库前先做质检：看最近邻词、看稀有词占比、看相似度分布，异常先怀疑语料与窗口。
6. 把「表示层」与「任务层」解耦：同一份向量既服务检索也服务分类，避免各处重复实现。

坑 1：中文没传 tokenizer，CountVectorizer/TfidfVectorizer 把整句当一个 token。

结论：默认 `token_pattern=(?u)\b\w\w+\b` 对中文会给出极其稀疏甚至整句一 token 的结果，准确率低到无法解释。
原因：默认分词基于空白与单词边界，中文没有空格；同时它会丢弃单字符 token，把「壳」「好」这类词直接扔掉。
解法：中文一律显式传 `tokenizer=自定义函数`（或 jieba 的 lcut）并设 `token_pattern=None`，或用 `analyzer='char'` 走字符 n-gram；同时把 tokenizer 写成模块级函数，避免 lambda 导致的序列化失败。

坑 2：TF-IDF 未归一化时用欧氏距离做检索，长文档被系统性排后。

结论：本机实测同一 query 下，欧氏与余弦给出的 top-3 完全不同（欧氏命中长度为 [8, 6, 9] 的三篇，余弦命中 [8, 9, 10]）；未归一化时距离里混进了文档长度，排序会被长度而不是语义主导。
原因：未归一化的 TF-IDF 行范数正比于「文档里词条的加权数量和」，两点距离同时受内容差异与范数差支配。
解法：保持 `norm='l2'`（默认），或对向量做行归一化后用内积/余弦；确实要用欧氏距离时，必须先归一化再用 `NearestNeighbors(metric='euclidean')`，并在离线评测集上确认排序与余弦一致。

坑 3：指望词袋/ TF-IDF 区分情感或语义极性。

结论：「手机壳质量很好」与「手机壳质量一般」的余弦相似度 0.471，是语料里最高的一对；同义不同词（退货/货退）相似度直接 0.000。
原因：词袋只看「词是否出现」，不看顺序、否定与语义；共现越多越相似，与极性无关。
解法：极性判断交给监督模型（16.4）；语义相似用稠密向量或同义词扩展。TF-IDF 的正确定位是「词面召回 + 可解释基线」，不是语义理解。

坑 4：BPE 语料太小，子词退化成了整词。

结论：本机 30 个符号的小语料上，20 次合并就把 `refundable` 合成单一 token，子词泛化能力消失。
原因：合并次数（或词表大小）是超参，语料小时高频词对反复被合并，把整词拼成了一个符号。
解法：词表大小按语料规模设定（经验值：语料 token 数的平方根量级起调），不要在几十句语料上训 BPE；中文场景优先用 SentencePiece 在百万级以上语料训练，或直接用现成预训练分词器。

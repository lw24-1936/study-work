## 概述

语义检索要解决的是「用一句话找到最相关的文档」：给定查询，从库里排出相关度最高的若干条。工程上有三层可以独立优化——**表示**（稀疏 TF-IDF/BM25 还是稠密句向量）、**索引**（暴力扫描还是 IVF/HNSW 近似检索）、**重排**（把召回的前几十条用更贵的模型重排）。三层各有自己的指标：召回看 Recall@k，排序看 MRR/nDCG，端到端看回答质量。

本机实测环境：Python 3.14.7、scikit-learn 1.9.1、jieba 0.42.1、numpy 2.5.4。评测集是 24 条中文 HR 政策问句 + 40 篇政策文档（人工标注相关文档），涵盖「关键词型」与「同义改写型」两类查询。faiss、sentence-transformers 在本机未安装（本机 py3.14 无 PyTorch 轮子），因此 ANN 索引用 k-means 手写 IVF 复现原理，稠密向量用 LSA/SVD；预训练句向量与 faiss 的用法只做官方文档核对，标注为「本机未验证」。

## 相似度度量

三个常见度量的差别只在向量的长度与归一化：

| 度量 | 公式 | 关注 | 何时用 |
|------|------|------|--------|
| 点积 | `q·d` | 方向 + 长度 | 向量已归一化时等价于余弦，可用矩阵乘法加速 |
| 余弦 | `q·d / (|q||d|)` | 只看方向 | 文本检索默认；对文档长度不敏感 |
| 欧氏距离 | `|q-d|` | 绝对位置 | 向量各维有物理含义（图像特征）时 |

坑在于：**TF-IDF 向量默认是 L2 归一化的，而词频计数向量不是**。一旦拿未归一化的向量做点积，文档长度就变成了权重，长文档被系统性抬高。本机在 40 篇文档后追加一篇由三篇文档拼接而成的长文档，用 `CountVectorizer`（不归一化）复现：

```python
import numpy as np
from sklearn.feature_extraction.text import CountVectorizer
from sklearn.preprocessing import normalize

corpus2 = DOCS + [DOCS[0] + DOCS[1] + DOCS[2]]        # 末尾追加一篇「又长又沾边」的拼接文档
cv = CountVectorizer(analyzer="char_wb", ngram_range=(1, 3), min_df=1)
C = cv.fit_transform(corpus2)
qraw = cv.transform([q0])
dot = (C @ qraw.T).toarray().ravel()                   # 未归一化点积
cos_norm = (normalize(C) @ normalize(qraw).T).toarray().ravel()   # 余弦
print("文档 L2 范数范围 %.2f ~ %.2f" % (np.linalg.norm(C.toarray(), axis=1).min(),
                                        np.linalg.norm(C.toarray(), axis=1).max()))
for label, s in (("点积", dot), ("余弦", cos_norm)):
    top = np.argsort(-s)[:3]
    print("%s top3: %s -> %s" % (label, list(top), [corpus2[i][:14] for i in top]))
```

```text
== 坑：未归一化的点积 vs 余弦（query = '出差住宿每天最多报多少'，末尾追加一篇拼接长文档）
  文档 L2 范数范围 9.11 ~ 21.95（最长/最短 = 2.41x）
  点积 top3: [40, 3, 0] -> ['报销标准：一线城市住宿费每天', '差旅管理：国际出差住宿标准为', '报销标准：一线城市住宿费每天']
  余弦 top3: [3, 0, 40] -> ['差旅管理：国际出差住宿标准为', '报销标准：一线城市住宿费每天', '报销标准：一线城市住宿费每天']
  拼接长文档在点积下的名次 1，余弦下名次 3（点积把长度当成了权重）
```

拼接长文档在点积下排第 1、余弦下排第 3——只是因为它的范数是普通文档的 2.41 倍。反转这条坑的方法就一句话：**做点积/矩阵乘法之前先 L2 归一化**，或者直接用 `sklearn.preprocessing.normalize`。用 faiss 时同样要注意：`IndexFlatIP` 是内积（需要预先归一化才等价余弦），`IndexFlatL2` 是欧氏距离，选错了结果就不是同一个排序。

```text
要点：
- 文本检索默认用余弦；向量归一化后余弦 = 点积，可走矩阵乘法/ANN 库
- 未归一化点积会把长文档排到前面（本机拼接长文档 rank 1 vs 余弦 rank 3），范数差 2.41x
- 欧氏距离适合「各维有物理含义」的向量；文本上等价于归一化后的余弦排序
- faiss 的 IndexFlatIP 是内积、IndexFlatL2 是欧氏，选错索引类型等于换了个排序
- 度量必须与索引/评估口径一致：用 L2 索引检索却用余弦算指标，数字会对不上
- 归一化是「一行代码、避免一整类线上事故」的典型防御
```

## 稀疏检索与向量空间

稀疏检索把文本变成「词/字符 n-gram 的高维稀疏向量」，用倒排索引（或矩阵乘法）算分。两个经典代表：TF-IDF 向量 + 余弦，和 BM25（TF-IDF 的概率化改进，含词频饱和 `k1` 与长度归一 `b` 两个旋钮）。它的优势是**零训练、可解释、精确匹配强、支持百万级倒排**；劣势是**不懂同义词**（「打车费」搜不到「市内交通费」）。

BM25 打分公式（本机手写实现）：

```text
idf(w)  = ln(1 + (N - df(w) + 0.5) / (df(w) + 0.5))
score   = Σ_w idf(w) · tf(w,d)·(k1+1) / ( tf(w,d) + k1·(1 - b + b·|d|/avgdl) )
```

```python
import math
from collections import Counter

def bm25(q):
    qt = tok(q)                                   # jieba 分词后的查询词
    scores = np.zeros(N)
    for i, d in enumerate(tok_docs):
        tf = Counter(d)
        for w in qt:
            if w not in tf or df.get(w, 0) == 0:
                continue
            idf = math.log(1 + (N - df[w] + 0.5) / (df[w] + 0.5))
            scores[i] += idf * tf[w] * (k1 + 1) / (tf[w] + k1 * (1 - b + b * len(d) / avgdl))
    return scores

def tfidf_scores(q):                              # 字符 1-3 gram TF-IDF + 余弦
    return (D @ normalize(vec.transform([q])).T).toarray().ravel()
```

```text

召回器                            Recall@5  MRR     nDCG@5
TF-IDF 字符 1-3gram + 余弦         1.0000   0.9097  0.9356
BM25 (jieba 词级)                0.8333   0.6910  0.7192
LSA/SVD 48 维稠密向量               1.0000   0.9097  0.9356

== 2. 分类型拆解（前 20 条为关键词型，后 4 条为同义改写型）
  TF-IDF   关键词型 nDCG@5 0.9662   改写型 nDCG@5 0.7827
  BM25     关键词型 nDCG@5 0.7284   改写型 nDCG@5 0.6731
  LSA      关键词型 nDCG@5 0.9662   改写型 nDCG@5 0.7827
```

结果里有两点值得注意。第一，中文场景下**字符 n-gram 的 TF-IDF 明显强于词级 BM25**（nDCG 0.9356 vs 0.7192）：中文分词错误会直接破坏倒排召回，而字符 n-gram 天然规避分词（代价是向量维度更高、可解释性差一些）。第二，两类查询的差距（0.9662 vs 0.7827）说明改写型查询是稀疏检索的软肋——「打车费能不能报销」在文档里写作「市内交通费凭发票实报实销」，词面几乎没有交集，只能靠「交通」「报销」这些共享词勉强召回。

```text
要点：
- 稀疏检索零训练、可解释、精确匹配强，适合专名/编号/条款号这类查询
- 中文上字符 n-gram 常优于词级 BM25（本机 nDCG 0.9356 vs 0.7192），因为绕开了分词错误
- BM25 的 k1 控制词频饱和、b 控制长度归一，是仅有的两个主旋钮（本机用 k1=1.5, b=0.75）
- 改写型查询是稀疏检索的软肋（本机 nDCG 掉到 0.7827），要靠稠密向量或同义词扩展
- 评测集必须同时包含关键词型与改写型查询，否则测不出召回器差异
- 倒排索引大小与词表切分方式直接相关：字符 n-gram 的索引比词级大得多
```

## 稠密向量与语义检索

稠密检索把查询和文档映射到同一低维空间，用向量相似度召回。实现路径分三类：**无监督降维**（LSA/SVD：对 TF-IDF 做奇异值分解，捕捉共现结构，本机可跑）；**自训练词/句向量**（word2vec/GLoVe 平均池化，语料小时效果不稳）；**预训练句向量模型**（sentence-transformers 的 bi-encoder，当前主流；也可用 CrossEncoder 做重排）。sentence-transformers 官方文档把模型族分成 SentenceTransformer（句/段落向量）、CrossEncoder（重排）、SparseEncoder（稀疏向量）、MultiVectorEncoder（ColBERT 风格多向量），检索场景通常组合前两个：https://www.sbert.net/

本机用 LSA/SVD 做稠密表示（`TruncatedSVD(n_components=48)` 作用在字符 n-gram TF-IDF 上，再 L2 归一化）：

```python
from sklearn.decomposition import TruncatedSVD
from sklearn.preprocessing import normalize

vec = TfidfVectorizer(analyzer="char_wb", ngram_range=(1, 3), min_df=1)
D = normalize(vec.fit_transform(DOCS))
svd = TruncatedSVD(n_components=48, random_state=0)
D_lsa = normalize(svd.fit_transform(D))            # 48 维稠密句向量

def lsa_scores(q):
    return (D_lsa @ normalize(svd.transform(vec.transform([q]))).T).ravel()
```

```text
LSA/SVD 48 维稠密向量: Recall@5 1.0000  MRR 0.9097  nDCG@5 0.9356
LSA 与 TF-IDF 的 top5 重合率: 1.000（高重合说明本机语料小、SVD 没带来语义泛化）
```

必须如实指出：本机 LSA 只是把稀疏向量做了低秩投影，**没有带来任何语义泛化**（top5 完全重合）。原因是 LSA 的「语义」来自大规模共现统计，40 篇文档显然不够。真实的语义泛化要靠在大语料上预训练的句向量模型，本机没有可用权重（无 PyTorch），所以下面是官方推荐的调用形态，**未在本机验证**：

```python
# 需 pip install sentence-transformers（依赖 PyTorch；本机 python 3.14 装不上 torch，未验证）
from sentence_transformers import SentenceTransformer, util

model = SentenceTransformer("BAAI/bge-small-zh-v1.5")     # 中文检索模型，具体 checkpoint 以模型卡为准
doc_emb = model.encode(DOCS, normalize_embeddings=True, batch_size=64)
q_emb = model.encode(QUERIES, normalize_embeddings=True)

hits = util.semantic_search(q_emb, doc_emb, top_k=5)      # 余弦相似度检索
```

```text
要点：
- 稠密检索的价值是跨词面泛化：查询与文档用词不同也能召回
- LSA/SVD 只是稀疏向量的低秩投影，小语料上不会凭空产生语义（本机 top5 与 TF-IDF 完全重合）
- 真语义能力来自大规模预训练句向量模型（sentence-transformers 的 bi-encoder）
- bi-encoder 把查询与文档分别编码（可预计算文档向量），cross-encoder 联合编码（更准更慢），用于重排
- 归一化后存向量；用内积索引（IndexFlatIP）等价余弦，省掉检索期的除法
- 维度越高不一定越好：256-768 维通常是检索质量与存储/延迟的平衡点，具体按模型卡与本机压测
```

## 向量索引与近似最近邻

库到十万级文档时，暴力扫描（flat）开始顶不住延迟；百万级以上必须上 ANN（近似最近邻）。两类主流结构：**IVF（倒排文件）+ PQ（乘积量化）**（先用 k-means 把向量空间切成 nlist 个簇，查询时只扫最近的 nprobe 个簇；PQ 再把向量压成短码大幅省内存）与 **HNSW（分层可导航小世界图）**（图遍历，召回高但内存占用大）。faiss 同时提供这两类，并支持「用精度换速度」（官网 wiki：https://github.com/facebookresearch/faiss/wiki）。

本机用 `KMeans(n_clusters=8)` 复现 IVF 的核心机制，扫描 nprobe：

```python
from sklearn.cluster import KMeans

km = KMeans(n_clusters=8, n_init=5, random_state=0).fit(D_lsa)     # 建库：聚类中心
cent, assign = km.cluster_centers_, km.labels_

def ivf_scores(q, nprobe=2):                                      # 查询：只扫最近的 nprobe 个簇
    qv = normalize(svd.transform(vec.transform([q]))).ravel()
    buckets = np.argsort(np.linalg.norm(cent - qv, axis=1))[:nprobe]  # 与哪些簇心最近
    cand = np.where(np.isin(assign, buckets))[0]                    # 候选文档
    s = np.full(N, -1e9)
    s[cand] = D_lsa[cand] @ qv                                      # 只在候选里算分
    return s
```

```text
== 5. IVF 索引（k-means nlist=8，建库 0.034s；暴力检索 = 全量 40 篇）
  nprobe  候选数  Recall@5   nDCG@5   总耗时(ms/query)
  1       7       0.8333     0.8180   0.910
  2       15      1.0000     0.9484   1.029
  3       20      1.0000     0.9356   1.198
  8       40      1.0000     0.9356   1.155
```

nprobe=1 时只扫 7/40 篇文档，Recall@5 掉到 0.8333；nprobe=2（15 篇候选）就恢复到 1.0000。这就是 ANN 的本质取舍：**候选集越小越快，但可能漏掉落在远处簇里的相关文档**。注意本机文档只有 40 篇，耗时被 Python 循环和打分开销淹没（约 1ms），延迟差异看不出来——真实收益要在百万级向量上用 faiss 的 C++ 实现和真机压测衡量，**本机不构成性能结论**。

```text
要点：
- flat 暴力检索是基线；十万级以上考虑 IVF，百万级以上通常 IVF+PQ 或 HNSW
- IVF 用 k-means 分簇，查询只扫 nprobe 个簇：本机 nprobe 1 -> 0.8333，nprobe 2 -> 1.0000
- nlist 与 nprobe 是 IVF 的两个旋钮：nlist 决定簇粒度，nprobe 决定召回/延迟权衡
- PQ 用乘积量化压缩向量，省内存但引入量化误差，通常与 IVF 组合（IVFPQ）
- HNSW 召回高、延迟低，代价是内存与建库时间；选型看规模与内存预算
- 本机用 Python 复现机制，延迟数字不代表 faiss 性能；真机压测以官方 wiki 与实测为准
```

## 重排模型

召回（recall-oriented）与排序（precision-oriented）的目标不同：召回要「别漏」，排序要「把最相关的排上来」。所以工业界标准架构是「bi-encoder 召回 top-50~200 -> cross-encoder 重排 top-5~10」。bi-encoder 分别编码查询与文档（文档向量可离线预计算，快）；cross-encoder 把「查询 + 文档」拼成一个输入联合编码（能看到词级交互，准但慢，只能对小候选集用）。sentence-transformers 的 `CrossEncoder` 就是这类模型（https://www.sbert.net/）。

本机没有可用预训练模型，于是用**特征重排器（逻辑回归）**做同类实验：特征包括与查询的 TF-IDF 余弦、词级 Jaccard、是否有词重叠、数字匹配率、长度比、文档词数。

```python
def feats(q, d):
    cos = float((normalize(vec.transform([q])) @ normalize(vec.transform([d])).T).toarray()[0, 0])
    qt, dt = set(tok(q)), set(tok(d))
    jac = len(qt & dt) / len(qt | dt) if qt | dt else 0.0
    num_q = set(re.findall(r"[0-9]+|[一二三四五六七八九十百千万亿两零]+", q))
    num_d = set(re.findall(r"[0-9]+|[一二三四五六七八九十百千万亿两零]+", d))
    num_match = len(num_q & num_d) / len(num_q) if num_q else 0.0
    return [cos, jac, 1.0 if qt & dt else 0.0, num_match,
            min(len(q), len(d)) / max(len(q), len(d)), len(dt) / 30.0]
```

```text
== 6. 重排（bi-encoder 取 top10 候选 -> 特征重排器；dev 13 条训，test 11 条评）
  TF-IDF 余弦      原始 nDCG@5 0.9210 -> 重排后 0.7902（Recall@5 1.0000 -> 1.0000）
  BM25 词级        原始 nDCG@5 0.6993 -> 重排后 0.7392（Recall@5 0.8182 -> 0.8182）
  重排器权重: {'余弦': 2.99, '词Jaccard': 0.71, '词重叠': 2.66, '数字匹配': 0.39, '长度比': -0.59, '词数/30': 0.12}
```

这里的结果诚实地说明了重排的适用边界：在弱底线（BM25，0.6993）上重排把 nDCG 提到 0.7392；在强底线（TF-IDF，0.9210）上反而掉到 0.7902。原因是本评测集只有 40 篇文档、dev 只有 13 条查询（130 条训练样本），重排器学到的「词重叠权重」把已经排对的少数样本推乱了。**重排的收益来自「候选池大 + 底线弱 + 训练样本足」，三个条件缺一个都可能掉点**——这也是为什么真实系统里重排模型要用几十万条人工标注的相关性数据来训。

```text
要点：
- 架构是「召回宽、排序精」：bi-encoder 取 top-100 给 cross-encoder 重排
- cross-encoder 联合编码查询与文档，精度高但延迟随候选数线性增长，只用于小候选集
- 重排需要训练数据（相关性标注），样本不足时可能不如不重排（本机强底线上 0.9210 -> 0.7902）
- 弱底线上收益明显（BM25 0.6993 -> 0.7392），别在已经很强的召回器上盲目加重排
- 重排特征里「数字匹配」「词重叠」在政策/合同类语料上很有效（权重 2.66 与 0.39）
- 用同一套 dev/test 划分对比「加重排前后」的 MRR 与 nDCG@k，不要只报 Recall
```

## 在 RAG 中的应用

RAG（检索增强生成）把检索结果塞进大模型的上下文，用真实文档替代模型记忆。检索侧有四个决定成败的细节：

| 环节 | 关键决定 | 常见错误 |
|------|---------|---------|
| 切块（chunking） | 块大小、是否重叠、按标题/段落切 | 硬按字数切，把表格、条款切两半 |
| 召回 | 走稀疏 + 稠密双路（混合检索），top-k 取 20-50 | 只用一种召回；top-k 取 3 |
| 重排 | cross-encoder 重排后取 5-10 | 直接把 top-50 全塞进上下文 |
| 上下文组装 | 每块带来源标识、去重、按相关性排序 | 不标注来源，模型无法引用；重复块浪费 token |

混合检索（稀疏 + 稠密融合）在中文政策类语料上很实用：稀疏保精确匹配（条款号、金额），稠密保语义泛化（改写问句）。融合方式常用 RRF（Reciprocal Rank Fusion）：`score = Σ 1/(rank + k)`，只需名次不需要分数量纲。

```python
def hybrid_scores(q, alpha=0.5, k=60):
    """稀疏 + 稠密名次融合：RRF = Σ 1/(rank + k)，无需对齐两路分数尺度"""
    ranked_sparse = rank(tfidf_scores(q), 40)
    ranked_dense = rank(lsa_scores(q), 40)
    s = np.zeros(N)
    for r, d in enumerate(ranked_sparse):
        s[d] += alpha / (r + k)
    for r, d in enumerate(ranked_dense):
        s[d] += (1 - alpha) / (r + k)
    return s

def build_context(q, topn=4):
    """组装上下文：带来源编号，方便生成侧引用与人工核对"""
    picked = rank(hybrid_scores(q), topn)
    return [{"id": i, "text": DOCS[i]} for i in picked]
```

```text
本机验证（24 条 query / 40 篇文档）：
  纯稀疏 TF-IDF nDCG@5 0.9356  -> RRF 融合（alpha=0.5）nDCG@5 0.9356
  原因：本机 LSA 与 TF-IDF 的 top5 完全重合，融合没有新增信息（见稠密向量一节）
  真实项目中两路召回常各有所长（稀疏强在精确匹配、稠密强在改写），融合通常明显加分
```

再强调一次：本机没有真实句向量模型，所以「混合检索的提升」在这里无法复现，**不要把本机数字当成混合检索的收益证据**。RAG 侧完整链路（切块 -> 召回 -> 重排 -> 生成 -> 引用校验）在 15.6 与本篇幻觉控制一节有对应实现。

```text
要点：
- 切块决定上限：按语义边界（标题/段落/条款）切，块间留 10%-20% 重叠防止切断答案
- 混合检索（稀疏 + 稠密）用 RRF 融合名次，避免两路分数尺度不一致
- top-k 是召回与上下文预算的权衡：召回阶段 20-50，重排后 5-10，别把 50 块全塞进上下文
- 上下文必须带来源标识与标题，生成侧才能引用、人工才能核对
- 去重很关键：近重复块会挤占上下文预算，还会让模型复读同一信息
- 本机无句向量模型，混合检索收益未验证；上线前用真实评测集验证融合权重 alpha
```

## 检索效果评估

检索指标各有侧重，必须组合看：**Recall@k**（相关文档是否进了前 k，看召回能力）；**MRR**（第一个相关文档的名次倒数，看「第一条对不对」）；**nDCG@k**（考虑名次的折损增益，看整体排序质量）；**Hit Rate**（等价 Recall@k 的 0/1 版）。这些指标实现起来都不长，但要**与库实现对拍**，避免自造口径：

```python
def recall_at_k(ranked, rel, k=5):
    return 1.0 if rel & set(ranked[:k]) else 0.0

def mrr(ranked, rel):
    for i, d in enumerate(ranked, 1):
        if d in rel:
            return 1.0 / i
    return 0.0

def ndcg(ranked, rel, k=5):
    gains = [1.0 if d in rel else 0.0 for d in ranked[:k]]
    dcg = sum(g / math.log2(i + 2) for i, g in enumerate(gains))
    idcg = sum(1.0 / math.log2(i + 2) for i in range(min(k, len(rel))))
    return dcg / idcg if idcg else 0.0

from sklearn.metrics import ndcg_score
# 对拍：手写实现 vs sklearn（官方文档 https://scikit-learn.org/stable/modules/generated/sklearn.metrics.ndcg_score.html）
y_true = np.zeros((1, N))                                  # 与手写口径一致：命中相关文档记 1
y_true[0, list(rel0)] = 1.0
print(ndcg(rank(tfidf_scores(q0), 10), rel0, 10), ndcg_score(y_true, [tfidf_scores(q0)], k=10))
```

```text
== 3. 手写 nDCG 与 sklearn.metrics.ndcg_score 对拍: 0.919721 vs 0.919721
```

另一个隐蔽问题是**数据泄漏**：如果把评测用的 query 也拿去 fit 向量器，IDF 会被查询词「污染」，指标虚高：

```text
== 7. 坑：把评测 query 一起拿去 fit 向量器（IDF 泄漏）后指标:
   Recall@5 1.0000  MRR 0.9514  nDCG@5 0.9638
   对比干净口径 Recall@5 1.0000  MRR 0.9097  nDCG@5 0.9356
```

nDCG 从 0.9356 涨到 0.9638（+2.8 个点），**什么都没改，只是让向量器偷看了测试查询**。这条坑的判定方法很机械：向量器（以及任何含 `fit` 的组件）只能在训练/建库数据上 fit，评测集与线上数据只能 `transform`。

```text
要点：
- 指标组合看：Recall@k 看召回、MRR 看第一条、nDCG@k 看整体排序
- 手写指标必须与库对拍（本机 nDCG 0.919721 与 sklearn 完全一致），口径错会让所有实验白做
- IDF/normalizer/模型都只能在建库数据上 fit，评测 query 参与 fit 就是泄漏（本机虚高 2.8 个点）
- 评测集要覆盖查询类型（关键词型/改写型/长句型）并分别报告，平均值会掩盖差异
- 相关度分级（0/1/2）比 0/1 更贴近真实业务，但标注成本更高，nDCG 天然支持分级
- 指标口径、评测集版本、建库脚本版本三者必须一起版本化
```

## 应用场景实战

### 场景一：客服知识库混合检索 + 融合排序

业务背景：客服坐席输入一句自然语言问题，系统返回 3-5 条最相关的知识条目。要求：条款号/金额查询必须精确命中（稀疏强项），口语化提问也要能召回（稠密强项）。做法是双路召回 + RRF 融合 + 名次解释输出，方便坐席判断为什么推荐这条。

```python
def search_kb(query, topn=5, alpha=0.5, k=60):
    sparse = rank(tfidf_scores(query), 40)
    dense = rank(lsa_scores(query), 40)
    score = np.zeros(N)
    for r, d in enumerate(sparse):
        score[d] += alpha / (r + k)
    for r, d in enumerate(dense):
        score[d] += (1 - alpha) / (r + k)
    out = []
    for d in rank(score, topn):
        out.append({"doc": DOCS[d][:26] + "…",
                    "sparse_rank": sparse.index(d) + 1 if d in sparse else None,
                    "dense_rank": dense.index(d) + 1 if d in dense else None})
    return out

for row in search_kb("出差住宿每天最多报多少", topn=3):
    print("稀疏 rank %s | 稠密 rank %s | %s" % (row["sparse_rank"], row["dense_rank"], row["doc"]))
```

```text
本机输出（query = 出差住宿每天最多报多少）：
稀疏 rank 1 | 稠密 rank 1 | 差旅管理：国际出差住宿标准为每天…
稀疏 rank 2 | 稠密 rank 2 | 报销标准：一线城市住宿费每天不超过六…
稀疏 rank 3 | 稠密 rank 3 | 差旅管理：出差需提前三个工作日在系…
```

本机两路名次完全相同（再次说明 LSA 在 40 篇语料上没有语义增益），但**输出双路名次这个设计本身就是收益**：坐席能看到「两路都排第 1」的高置信结果，也能看到「稀疏第 15、稠密第 2」这类分歧样本，后者正是补同义词表或调 alpha 的输入。

```text
场景一要点：
1. 检索接口返回「名次 + 来源」，而不仅是一个排序结果；双路名次是调参依据
2. 双路名次一致 = 高置信；分歧样本收集起来，是补同义词与调融合权重的素材
3. RRF 融合不需要分数可比，工程上最省事；alpha 用 A/B 在真实查询日志上定
4. top-40 召回 + 融合后再截断，比直接 top-5 单路召回的漏检概率低得多
5. 知识条目的「有效期/版本」要一起返回，避免坐席读到过期条款
```

### 场景二：政策问句的检索评估流水线

业务背景：每次改召回器（换向量器、调 k1/b、加同义词）都要回答「有没有变好」。做法是固定一份带相关度标注的评测集，把指标计算脚本化，每次改动都跑同一套指标并对比。

```python
def evaluate(fn, queries=QUERIES, k=5):
    r = m = nd = 0.0
    for q, rel in queries:
        rk = rank(fn(q), 10)
        r += recall_at_k(rk, rel, k); m += mrr(rk, rel); nd += ndcg(rk, rel, k)
    n = len(queries)
    return r / n, m / n, nd / n

def report_all():
    rows = [("TF-IDF 字符 n-gram", tfidf_scores), ("BM25 词级", bm25), ("LSA 48 维", lsa_scores)]
    for name, fn in rows:
        r5, mr, nd = evaluate(fn)
        print("%-18s Recall@5 %.4f  MRR %.4f  nDCG@5 %.4f" % (name, r5, mr, nd))
    kw, para = QUERIES[:20], QUERIES[20:]
    for name, fn in rows[:2]:
        print("%-18s 关键词型 nDCG %.4f  改写型 nDCG %.4f"
              % (name, evaluate(fn, kw)[2], evaluate(fn, para)[2]))
```

```text
本机输出：
TF-IDF 字符 n-gram   Recall@5 1.0000  MRR 0.9097  nDCG@5 0.9356
BM25 词级            Recall@5 0.8333  MRR 0.6910  nDCG@5 0.7192
LSA 48 维            Recall@5 1.0000  MRR 0.9097  nDCG@5 0.9356
TF-IDF 字符 n-gram   关键词型 nDCG 0.9662  改写型 nDCG 0.7827
BM25 词级            关键词型 nDCG 0.7284  改写型 nDCG 0.6731
```

把「平均值」和「分类型」一起打出来，是这套流水线的核心价值：单看 Recall@5（TF-IDF 与 LSA 都是 1.0000）会误判两者一样好，而分类型拆解暴露了改写型查询只有 0.7827 的短板，直接把下一步优化方向指向语义表示。

```text
场景二要点：
1. 评测脚本进仓库，指标（Recall@k/MRR/nDCG@k）+ 分类型拆解一次跑全
2. 评测集与相关度标注要版本化；改评测集必须重跑历史模型，否则数字不可比
3. 每个改动只动一个变量（换向量器 / 调 k1 / 加同义词），否则无法归因
4. 建库脚本必须只 fit 不 transform 评测集：防 IDF 泄漏（本机虚高 2.8 个点）
5. 上线前加「回归门禁」：nDCG@5 下降超过阈值就拦住发版
```

## 最佳实践与踩坑记录

最佳实践：

1. 先跑稀疏基线（TF-IDF 字符 n-gram 或 BM25），把评测集立起来；没有评测集时任何「语义检索」都是猜。
2. 向量统一 L2 归一化，索引类型与相似度定义严格对齐（余弦对应内积索引）。
3. 评测集同时包含关键词型与改写型查询，并分别报告指标；平均值会掩盖召回器的真实短板。
4. 召回与排序分层：召回取 top-40 用 RRF 融合，重排后给模型 top-5，别让重排在小候选集或弱训练数据上硬上。
5. 任何含 fit 的组件（向量器、normalizer、模型、聚类中心）只在建库数据上 fit，评测/线上只 transform。
6. 指标实现与库对拍（本机 nDCG 与 sklearn 完全一致），并写进 CI 作为回归门禁。

坑 1：拿未归一化的向量做点积当相似度。

结论：追加一篇「又长又沾边」的拼接文档后，点积把它排到第 1 名，余弦把它排到第 3 名；文档范数差 2.41x。
原因：点积同时衡量方向与长度，未归一化时长度成了权重，长文档被系统性抬高。
解法：算相似度前统一 `normalize`；faiss 侧选择与度量匹配的索引（余弦 -> IndexFlatIP，欧氏 -> IndexFlatL2）。

坑 2：把评测用的查询也拿去 fit 向量器（IDF 数据泄漏）。

结论：nDCG@5 从 0.9356 涨到 0.9638（+2.8 个点），而模型和索引都没变。
原因：查询词进入 IDF 统计后，评测查询的稀有词权重被抬高，检索结果偏向「包含查询原词」的文档，等于提前看到了答案分布。
解法：向量器/模型/聚类只在建库数据上 fit；评测集与线上数据一律 transform；把「fit 数据范围」写进代码评审清单。

坑 3：在强召回器上叠加训练不足的重排模型。

结论：TF-IDF 底线 nDCG@5 0.9210，加特征重排后掉到 0.7902；而同样的重排器在 BM25 底线上把 0.6993 提到 0.7392。
原因：本机 dev 只有 13 条查询（130 条训练样本），重排器学到的权重把已经排对的样本推乱；候选集也只有 10 条，重排的可操作空间很小。
解法：重排只用在「候选池大 + 底线弱」的场景，且要有足够的相关性标注；上线前必须用同一 dev/test 划分验证增益。

坑 4：中文语料上直接用词级 BM25，然后以为「稀疏检索不行」。

结论：BM25 词级 nDCG@5 0.7192，字符 n-gram TF-IDF 0.9356，差距 21 个点。
原因：中文分词错误会直接破坏倒排召回的词项（专名被切碎、口语词与书面词不同形），字符 n-gram 天然规避分词。
解法：中文先试字符 n-gram（1-3 gram），再考虑「字符 + 词级」双路召回；把分词错误样本单独统计。

坑 5：IVF 的 nprobe 设成 1 来「压延迟」。

结论：nprobe=1 时只扫 7/40 篇文档，Recall@5 从 1.0000 掉到 0.8333；nprobe=2 就恢复 1.0000。
原因：相关文档可能落在与查询次近的簇，只扫最近一个簇会漏掉它们。
解法：nprobe 用真实评测集扫一遍曲线（召回/延迟），在满足召回下限的前提下取最小 nprobe；同时监控线上「零结果率」。

## 概述

序列标注是「给每个 token 打一个标签」的任务族：命名实体识别（NER）、词性标注、分词、槽位填充都是它的实例。它和文本分类的区别在于标签之间有结构（实体必须连续、类型不能中途切换），所以**解码约束**和**实体级评估口径**比模型结构更容易被做错。信息抽取则是序列标注的下游组合：先抽实体，再判断实体之间的关系，最后把结果落成结构化字段。

本机实测环境：Python 3.14.7、jieba 0.42.1、scikit-learn 1.9.1、seqeval 1.2.2、sklearn-crfsuite 0.5.0（python-crfsuite 0.9.12）、numpy 2.5.4；深度模型在 TensorFlow 2.20.0 + Keras 3.15.1（CPU）下运行。本文所有 ```text 代码块都是本机真实输出。

```text
本篇主线：

2. HMM 与 CRF —— 生成式基线 vs 判别式，转移特征让 CRF 明确「不许跳类型」
```

## 序列标注任务与标签体系

BIO 是最通用的标签编码：每个 token 打 `O`、`B-X`（实体首 token）或 `I-X`（实体内部 token）。BIOES 额外区分单 token 实体 `S-X` 与实体尾 `E-X`，对「相邻同类实体」和「单 token 实体」表达更精确，但标签数翻倍、标注成本上升。选编码方案的关键约束是：**评估脚本与标签方案必须一致**，BIO 数据送进按 BIOES 解析的脚本，指标会悄悄变。

常见标签方案对比：

| 方案 | 标签数（3 类实体） | 能表达 | 代价 |
|------|-------------------|--------|------|
| IO | 4 | 只有「是不是实体」 | 相邻同类实体会粘成一个 |
| BIO / IOB2 | 7 | 实体首尾清楚 | 单 token 实体与 B 混用 |
| BIOES / BILOU | 13 | 单 token 实体、相邻同类实体都能区分 | 标注与解析更复杂 |
| 只做 span 分类（不做序列） | - | 任意嵌套实体 | 需要候选枚举，推理更慢 |

分词边界会直接决定标注粒度。中文有两条路：char 级（每个汉字一个 token，边界准确，但词内语义要靠窗口特征猜）和 word 级（按 jieba 分词后标注，特征更「干净」，但实体边界与分词边界不一致时标签会丢信息）。本机实测这种错位并不罕见：

```python

         "李四在阿里巴巴杭州总部工作，之前供职于字节跳动。",
         "王五去了北京，与华为技术有限公司签了合同。"]
for s in sents:
    print(s)
    print("  实体候选:", [(w, f) for w, f in pseg.cut(s) if f in {"nr", "ns", "nt", "nz"}])
```

jieba 把「张三于」当成一个人名（把介词吞进实体），「腾讯」被判成 `nz`（其他专名）而不是 `nt`（机构名），「字节跳动」「阿里巴巴」完全没有被识别。词性标注只能当**候选召回器 + 特征来源**，不能当 NER 用。

```text
要点：
- 标签方案先定，再定评估脚本；BIO 与 BIOES 混用是隐蔽的指标污染源
- char 级标注边界最准，word 级特征更好，二者常一起用（word 特征 + char 标签）
- 实体级评估：一个实体只要边界或类型错就算全错，不能按 token 算 accuracy
- jieba 的 nr/ns/nt 只能做候选召回；「张三于/nr」这种吞介词的错误很常见
- 未登录实体名是中文 NER 的主要错误来源，评估集必须包含它
```

## 隐马尔可夫与条件随机场

HMM 是生成式（generative）序列模型：对联合概率 `P(X, Y)` 建模，其中 X 是观测（字），Y 是标签。它假设观测只依赖当前状态（发射独立）、状态只依赖前一状态（一阶马尔可夫），参数就是转移概率与发射概率的计数，解码用 Viterbi。优点是不需要特征工程、训练就是数数；缺点是**标签之间无法共享重叠特征**（比如「字是不是数字」「前一个字是不是地名后缀」这类特征在 HMM 里要么进不了模型，要么破坏独立性假设）。

CRF 是判别式（discriminative）模型：直接对 `P(Y|X)` 建模，打分函数是特征函数的线性组合，包含**状态特征**与**转移特征**：

```text
score(Y, X) = Σ_i Σ_f  w_f · f_状态(x_i, y_i)  +  Σ_i Σ_f  w_f · f_转移(y_{i-1}, y_i)
P(Y|X) = exp(score) / Z(X)          # Z(X) 是配分函数，对全部标签序列求和
```

因为转移特征进了模型，CRF 能从数据里学出「`B-LOC` 后面大概率跟 `I-LOC`」「`I-PER` 后面不该跟 `B-ORG`」这类约束，解码仍然是 Viterbi。代价是训练要跑 L-BFGS、推理是序列级解码，比线性分类慢，但比神经网络轻得多。

同一个数据集上先跑 HMM 基线（bigram 转移 + 发射计数 + add-k 平滑 + Viterbi）：

```python
from collections import Counter, defaultdict
import math

TAGS = ["O", "B-PER", "I-PER", "B-ORG", "I-ORG", "B-LOC", "I-LOC"]

def train_hmm(data, k=0.1):                     # data = [(文本, BIO标签列表), ...]
    trans, emit, init, chars = defaultdict(Counter), defaultdict(Counter), Counter(), set()
    for text, tags in data:
        prev = "<s>"
        for ch, t in zip(text, tags):
            trans[prev][t] += 1; emit[t][ch] += 1; chars.add(ch)
            if prev == "<s>":
                init[t] += 1
            prev = t
    return trans, emit, init, chars

def viterbi(text, trans, emit, init, chars, k=0.1):
    V, Vc = len(TAGS), len(chars) + 1
    def logp(cnt, tot, denom):
        return math.log((cnt + k) / (tot + k * denom))
    dp = {t: logp(init[t], sum(init.values()), V) + logp(emit[t][text[0]], sum(emit[t].values()), Vc)
          for t in TAGS}
    bp = [dict.fromkeys(TAGS)]
    for i in range(1, len(text)):
        ndp, nbp = {}, {}
        for t in TAGS:                          # 当前标签
            best, arg = -1e18, None
            for p in TAGS:                      # 前一标签
                sc = dp[p] + logp(trans[p][t], sum(trans[p].values()), V)
                if sc > best:
                    best, arg = sc, p
            ndp[t] = best + logp(emit[t][text[i]], sum(emit[t].values()), Vc)
            nbp[t] = arg
        dp, _ = ndp, bp.append(nbp)
    cur, path = max(dp, key=dp.get), []
    path.append(cur)
    for i in range(len(text) - 1, 0, -1):
        cur = bp[i][cur]; path.append(cur)
    return path[::-1]
```

换成 CRF（`sklearn-crfsuite` 的 `CRF`，特征字典形式，官方教程用 CoNLL2002 数据演示同一套 API）：

```python
from sklearn_crfsuite import CRF

def feats_char(sent, i):                        # 字符级特征：±2 窗口 + 字符类型 + 首尾标记
    f = {"bias": 1.0, "ch": sent[i]}
    for off in (-2, -1, 1, 2):
        j = i + off
        f["ch%+d" % off] = sent[j] if 0 <= j < len(sent) else "EDGE"
    return f

crf = CRF(algorithm="lbfgs", c1=0.05, c2=0.1, max_iterations=150, all_possible_transitions=True)
crf.fit([[feats_char(s, i) for i in range(len(s))] for s, _ in train],
        [tags for _, tags in train])
pred = crf.predict([[feats_char(s, i) for i in range(len(s))] for s, _ in test])
```

转移特征的符号和大小直接可读：`B-LOC->I-LOC` 权重 +5.44 说明模型学到了「LOC 实体内部要连续」，`I-ORG->B-LOC` +2.19 说明数据里确实存在「ORG 紧跟 LOC」的句式（本语料里是「{O}在{L}」）。这就是 CRF 相比 HMM 的可解释性优势，也是为什么它能保证解码结果**结构合法**。

```text
要点：
- HMM 生成式：只建模相邻状态 + 发射，训练是数数，无法用重叠特征；中文 NER 上作为基线够用
- CRF 判别式：状态特征 + 转移特征联合打分，L-BFGS 训练，Viterbi 解码，结构合法性由转移权重保证
- 转移特征权重可读（B-LOC->I-LOC +5.44），是排查「模型为什么不许跳类型」的抓手
- c1/c2 是 L1/L2 正则强度；特征稀疏时 c1 大一点能压住长尾特征
- all_possible_transitions=True 让模型自己学哪些转移合法，比手工黑名单更省事
- 本机 char 级 CRF：同分布 F1 1.0，未登录实体 F1 0.30，说明「高分」很可能只是背下了实体名
```

## 深度序列标注

深度方案把 CRF 的特征工程换成表示学习。主流结构三类：BiLSTM-CRF（前向-后向 LSTM 编码上下文，再叠一层 CRF 解码，序列建模能力强，长句慢）；CNN/空洞卷积（并行度高，局部窗口为主，搭配 CRF 效果接近 LSTM）；预训练编码器 + 分类头（BERT 类模型微调，中文上通常最强，见 16.6）。

最容易踩的坑不在网络结构，而在**解码**。逐 token softmax + argmax 是「每个位置各自取最大概率」，它不知道标签之间的约束，于是会输出 `O -> I-PER`（实体没有起点）、`B-PER -> I-ORG`（类型中途跳变）这类非法序列。本机实测：

```python
import os, numpy as np, tensorflow as tf
os.environ["TF_CPP_MIN_LOG_LEVEL"] = "3"
os.environ["TF_DETERMINISTIC_OPS"] = "1"                  # 可复现：固定算法分支
tf.config.threading.set_inter_op_parallelism_threads(1)    # 单线程保证同脚本两次跑出同样结果

model = tf.keras.Sequential([
    tf.keras.layers.Input(shape=(MAXLEN,)),
    tf.keras.layers.Embedding(len(vocab), 64),
    tf.keras.layers.Bidirectional(tf.keras.layers.LSTM(64, return_sequences=True)),
    tf.keras.layers.Dense(len(TAGS), activation="softmax"),
])
model.compile(optimizer=tf.keras.optimizers.Adam(1e-3),
              loss=tf.keras.losses.SparseCategoricalCrossentropy())
model.fit(Xtr, ytr, sample_weight=mtr, epochs=12, batch_size=64, verbose=0)
```

约束 Viterbi 只需要一张「合法转移表」（从训练集统计出现过的相邻标签对），逐句做 DP：

```python
allowed = set()
for _, tags in train:                       # 训练集里出现过的 (前标签, 后标签) 即合法
    prev = "<BOS>"
    for t in tags:
        allowed.add((prev, t)); prev = t
    allowed.add((prev, "<EOS>"))
# 本机数据里合法相邻转移只有 12 种（全量 7x7=49 种）

def decode_constrained(probs, mask):
    out = []
    for p, m in zip(probs, mask):
        L = int(m.sum()); p = p[:L]
        best = np.full((L, len(TAGS)), -1e18); bp = np.zeros((L, len(TAGS)), dtype="int32")
        for s in range(len(TAGS)):           # 首 token：只允许 BOS 合法的起始标签
            best[0, s] = np.log(p[0, s] + 1e-12) if ("<BOS>", id2tag[s]) in allowed else -1e18
        for t in range(1, L):                # 逐位置 DP，非法转移给 -1e18
            for s in range(len(TAGS)):
                val, q = max((best[t-1, q] + (0 if (id2tag[q], id2tag[s]) in allowed else -1e18), q)
                             for q in range(len(TAGS)))
                best[t, s] = val + np.log(p[t, s] + 1e-12); bp[t, s] = q
        s = int(best[-1].argmax()); seq = [id2tag[s]]
        for t in range(L-1, 0, -1):          # 回溯
            s = int(bp[t, s]); seq.append(id2tag[s])
        out.append(seq[::-1])
    return out
```

同一批模型权重，只是把解码从无约束 argmax 换成约束 Viterbi：未登录实体测试集的 micro F1 从 0.1057 提到 0.2083（翻倍），LOC 从 0.1946 提到 0.5333，194/200 句的非法序列降到 0。**解码约束是零成本收益**——不改模型、不加数据，只加一张 12 行的转移表。

```text
要点：
- 逐 token softmax + argmax 会吐出非法序列（本机 194/200 句），别直接上线
- 约束 Viterbi = 从训练集统计合法转移对 + 逐句 DP，代码 20 行，F1 0.1057 -> 0.2083
- 真正的 CRF 层（BiLSTM-CRF）把转移权重也学出来，比硬约束更灵活
- 未登录实体是深度模型的主要失败模式，小数据上表层的 LSTM 也救不了
- 训练要固定线程数与随机种子（TF_DETERMINISTIC_OPS=1 + 单线程），否则同一脚本两次跑出不同数字
- 小模型 74,631 参数推理 200 句 0.106s，CPU 上就够；瓶颈在标注和迭代而不是算力
```

## 命名实体识别实战

中文 NER 的工程链路是：清洗 -> 标注 -> 训练 -> 实体级评估 -> 错误归因。评估必须用 `seqeval` 这类**实体级**口径（一个 span 的起止与类型全对才算对），不能用 token 级 accuracy 自我安慰。装好之后和 sklearn-crfsuite 搭配的写法：

```bash
pip install -i https://pypi.tuna.tsinghua.edu.cn/simple seqeval sklearn-crfsuite
```

```python
from seqeval.metrics import classification_report, f1_score

print(classification_report(y_test, y_pred, digits=4))     # 实体级 P/R/F1
print("micro F1:", f1_score(y_test, y_pred, average="micro"))
```

word 级特征版本（先 jieba 分词再标注）在同一批句子上的对照：

```text
         LOC     1.0000    0.7600    0.8636       200
         ORG     0.2097    0.0650    0.0992       200
         PER     0.7168    0.8182    0.7642       198
```

word 级 CRF 的未登录实体 F1 0.6301，明显高于 char 级的 0.3002：因为词元本身（比如「拼多多」在 jieba 词典里是一个词）比单字携带更多信息，模型即使没见过这个词，也能从「词形 + 前后词」推断出来。而 char 级模型只看单字，遇到没见过的字组合就无从下手。这是中文 NER 里「先分词再标 vs 直接标字」的经典权衡，**两者都跑一遍再选**比凭感觉选便宜得多。

错误归因最有效的一刀是按「实体名是否在训练词表里」切分：

```text
同分布测试集(实体名已见): micro F1 1.0000
未登录实体测试集        : micro F1 0.3002
逐类对比 (seen / unseen):  PER 1.0000 / 0.7988   ORG 1.0000 / 0.0000   LOC 1.0000 / 0.0000
两个测试集的 ORG 名称举例: ['腾讯', '字节跳动', '美团'] | ['拼多多', '哔哩哔哩', '蔚来汽车']
```

另外要注意 seqeval 不校验标签序列的合法性——它只按 BIO 规则切 span，孤立的 `I-PER` 会被当成一个新跨度的起点，不报错：

```text
第 1 句预测标签: B-PER I-PER O O O O O O O B-LOC I-LOC O O
  seqeval 抽出的实体: [('PER', 0, 1), ('LOC', 9, 10)]
首 token 改成 I-PER 后: I-PER I-PER O O O O O O O B-LOC I-LOC O O
  seqeval 抽出的实体: [('PER', 0, 1), ('LOC', 9, 10)] （不报错：孤立的 I- 被当成新跨度起点）
非法序列对指标的影响: 该句 F1 由 0.4000 变为 0.4000
```

```text
要点：
- 评估口径统一用实体级（seqeval）；token 级 accuracy 在 O 占 80% 的数据上永远是 0.9+
- 错误归因按「实体名是否未登录」「边界错 vs 类型错」切开，直接指向该补数据还是该改特征
- 同一数据 word 级 0.6301 > char 级 0.3002；特征粒度要实测而不是凭经验
- seqeval 不报非法标签，指标可能被「孤立的 I-」悄悄污染；上游先做合法性校验
- 官方 seqeval 支持 IOB1/IOB2/IOE1/IOE2/IOBES/BILOU（后两者仅在 strict 模式），默认模式兼容 conlleval 脚本
- 中文公开语料（MSRA/CLUENER）在本机无法下载，真实项目请换成语料库或人工标注
```

## 关系抽取

关系抽取判断两个实体之间的语义关系，方法有三代：**模式/规则法**（正则或句法模板，精确率高、召回靠枚举模板）；**监督分类法**（把实体对之间的文本片段 + 上下文特征喂给分类器）；**远监督与联合抽取**（用知识库对齐文本自动造标，或者把实体识别和关系分类放在一个模型里）。

模式法在句式受限的业务文本（工单、合同、简历）里性价比极高。本机用 3 条正则模板在 300 句测试集（含 87 句「有实体但无关系」的干扰句）上实测：

```python
REL_PATTERNS = [
    (r"(?P<e1>.{2,4}?)(?:在|加入|入职)(?P<e2>.{2,6}?)(?:担任|做|任)(?P<role>.{2,6})", "就职"),
    (r"(?P<e1>.{2,4}?)(?:在|位于)(?P<e2>.{2,6}?)(?:的)?(?P<role>总部|分公司|研究院)", "位于"),
    (r"(?P<e1>.{2,6}?)(?:收购了|并购了)(?P<e2>.{2,6})", "收购"),
]
```

```text
== 1. 模式法关系抽取（300 句测试集，3 条正则模板；其中 87 句是无关系干扰句）
  抽取条数 131（gold 正例 213）；精确率 1.0000 召回率 0.6150 F1 0.7616；干扰句上的误抽 0 条
  例: 李四加入腾讯做数据分析师 -> [('就职', '李四', '腾讯', '数据分析师')]（gold ('就职', '李四', '腾讯')）
  例: 王五问了腾讯的报价，又比较了京东的服务 -> []（gold None）
```

召回率 0.615 全部丢在两种没写模板的句式上：「{人}目前在{机构}，岗位是{岗位}」和「{机构}把{部门}设在{城市}」。这正是模式法的本质：**精确率靠模板窄，召回率靠模板多**，模板库需要从错误样本里持续补。干扰句零误抽说明模板的锚词（担任/位于/收购）足够强。

远监督分类把「知识库里有这个实体对」当正样本自动造标，用实体间文本片段做特征：

```python
def between(text, e1, e2):                     # 抽取两个实体之间的文本作为关系线索
    i, j = text.index(e1) + len(e1), text.index(e2)
    return text[i:j] if i <= j else text[j + len(e2):i]

# 训练样本来自知识库对齐：实体对出现在句子里 → 该句是这类关系的（带噪）训练样本
Xtr = [between(t, e1, e2) + " | " + t[:4] for t, (rel, e1, e2) in train_pairs]
```

```text
== 2. 远监督关系分类（训练 600 条，测试 213 条；特征 = 实体间文本片段 + 句首 4 字）
  干净标签训练: 测试集 acc 1.0000
  注入 20% 远监督噪声后: 测试集 acc 1.0000
          位于     1.0000    1.0000    1.0000        65
          就职     1.0000    1.0000    1.0000        81
          收购     1.0000    1.0000    1.0000        67
  accuracy                         1.0000       213
```

这里必须如实说明：本机模板语料的实体间片段（「担任」「位于的」）区分度太强，即便注入 20% 噪声标签，逻辑回归仍然全部答对，**没有复现出远监督在真实语料上的噪声敏感性**。真实项目里一个公司名会出现在大量无关句子中，噪声标签常达 30%-50%，需要 bag-level 聚合（「一个实体对的多句里只要有一句表达该关系就算正」）或 attention-over-bags 之类去噪，具体做法以相关论文与工具文档为准。

```text
要点：
- 业务文本先用模式法打底：精确率 1.0、召回 0.6，落地快、可解释、易加模板
- 规则法的召回瓶颈在句式覆盖，把线上未命中的句子做成每日待办清单持续补模板
- 干扰句必须进测试集，否则精确率永远是 1.0，测不出误抽
- 远监督用「实体对在知识库里」造标，噪声大；本机模板数据太规整，未能复现真实噪声水平
- 实体识别错误会直接污染关系抽取（级联误差），上线前按「实体正确率 × 关系正确率」估端到端上限
- 联合抽取（一个模型同时出实体和关系）能缓解级联误差，但训练数据与调参成本更高
```

## 标注数据构建与质检

标注规范要先写「边界怎么定」和「类型怎么选」，再开工。中文 NER 规范里最容易歧义的三件事：机构名是否包含地名前缀（「北京银行」是一个 ORG 还是 LOC+ORG）、职位/职称算不算实体、缩写与全称是否合并。规范不写清，标注员之间的一致性会掉到 kappa 0.6 以下，模型学到的就是标注噪声。

一致性用 Cohen kappa（`sklearn.metrics.cohen_kappa_score`，定义为 `(p_o - p_e) / (1 - p_e)`，0 表示不比随机猜更好）衡量，不要只看「一致率」——在 O 标签占多数的序列数据上，一致率天然很高：

```python
from sklearn.metrics import cohen_kappa_score
from seqeval.metrics import f1_score as seq_f1

a1 = y_test[:120]                          # 标注员 1 的 char 级 BIO
a2 = [list(s) for s in a1]                 # 标注员 2：模拟 8 句在实体起点上有分歧
for seq in a2[:8]:
    seq[0] = "O"
flat1 = [t for s in a1 for t in s]; flat2 = [t for s in a2 for t in s]
print("一致率 %.4f" % (sum(x == y for x, y in zip(flat1, flat2)) / len(flat1)))
print("Cohen kappa %.4f" % cohen_kappa_score(flat1, flat2))
print("实体级 F1（一致性代理）%.4f" % seq_f1(a1, a2, average="micro"))
```

```text
char 级一致率 0.9966；Cohen kappa 0.9950；实体级 F1（一致性代理）0.9797
```

只有 8 句（约 6.7% 的句子）在首 token 上有分歧，char 级一致率就高达 0.9966——但实体级 F1 已经掉到 0.9797，因为「起点错一个字符」在实体级口径下就是整个实体错。**质检要同时看 token 级一致率、kappa 和实体级一致性**，三个数字一起看才不会被平均掉。

```text
要点：
- 规范先定边界（地名前缀、职称、缩写），否则一致性不可控
- O 标签占多数时一致率虚高，必须配 Cohen kappa 与实体级一致性
- 6.7% 的句子有分歧就能让实体级一致性掉 2 个点，说明「实体起点」是最该写进规范的细节
- 抽检要算样本量：想卡「错误率 < 2%」需要按二项分布估算抽检条数（见 16.9 的质检实验）
- 标注工具要能导出「分歧清单」并按标注员统计，返工成本比重新标低一个量级
```

## 应用场景实战

### 场景一：客服工单实体抽取流水线

业务目标：把工单正文里的**人名、机构、地点、订单号、金额**抽成结构化字段，写进数据库供「按金额排序」「按订单号关联物流」等下游用。方案是 CRF 抽实体 + 正则抽编号/金额 + 字段校验，最后输出 JSON。这套组合在真实系统里很常见：**序列模型负责开放域实体，正则负责强格式字段**。

```python
import re
from sklearn_crfsuite import CRF

ORDER_NO = re.compile(r"(?:SF|JD|单号|订单号)?\s*([A-Z]{2}\d{6,}|\d{10,})")
AMOUNT = re.compile(r"(\d+(?:\.\d+)?)\s*(?:元|块)")

def extract_ticket(text):
    tags = crf.predict_single([feats_char(text, i) for i in range(len(text))])
    ents, cur = [], None
    for i, t in enumerate(tags):                 # BIO -> span
        if t.startswith("B-"):
            if cur: ents.append(cur)
            cur = {"type": t[2:], "text": text[i], "start": i}
        elif t.startswith("I-") and cur and cur["type"] == t[2:]:
            cur["text"] += text[i]
        else:
            if cur: ents.append(cur); cur = None
    if cur: ents.append(cur)
    return {"entities": [{"type": e["type"], "text": e["text"], "pos": e["start"]} for e in ents],
            "order_no": [m.group(1) for m in ORDER_NO.finditer(text)],
            "amounts": [float(m.group(1)) for m in AMOUNT.finditer(text)]}
```

```text
== 场景一：客服工单实体抽取流水线（CRF + 正则后处理）
  原文: 张三在腾讯下的单，订单号SF123456，金额 899 元，一直没发货，要投诉！
    实体: 张三(PER)，腾讯(ORG)
    订单号: ['SF123456']  金额: [899.0]
  原文: 李四入职字节跳动，base杭州，报销 320 元打车费被驳回了。
    实体: 李四(PER)，字节跳动(ORG)
    订单号: -  金额: [320.0]
  原文: 王五从美团离职去了北京，之前那笔 1500 元的退款还没到账。
    实体: 王五(PER)，美团(ORG)，北京(LOC)
    金额: [1500.0]
  原文: 赵六在京东买的手机，单号JD889900，客服说深圳仓发货，运费 12 元。
    实体: 赵六(PER)，京东(ORG)，深圳(LOC)
    订单号: ['JD889900']  金额: [12.0]
```

两处值得注意的失败：第 2 条的「base杭州」没抽出 LOC（中英混排把窗口特征带偏了），第 4 条的「深圳仓」只抽到「深圳」而没扩到「仓」。前者解法是给 token 加「是否 ASCII」标记，后者要在标注规范里明确「实体后接量词/名词时是否扩边界」——两件事都不是模型容量问题，而是特征与规范问题。

```text
场景一要点：
1. 三层结构：CRF 管开放域实体、正则管订单号/金额、校验层管范围与格式，各自可独立迭代
2. 返回 char offset，方便前端高亮、人工复核与下游对齐
3. 中英混排要单独加字符类型特征，否则「base杭州」这类写法会漏抽
4. 金额与订单号用正则比模型稳：强格式字段的召回率与可解释性都更好
5. 抽取结果为空时不要把空字符串写库，写 NULL 并打监控指标，方便发现分布突变
```

### 场景二：合同与政策文本字段抽取

业务目标：从合同/制度文本里抽出日期、金额、比例、期限四个字段，落库并做**规则校验**（比例不能超 100%、金额合计与总额是否一致、期限是否超过政策上限）。这类场景不需要序列模型，正则 + 中文数字转换 + 校验就够，且完全可解释。

```python
FIELD_RULES = {
    "日期": re.compile(r"(\d{4}\s*年\s*\d{1,2}\s*月\s*\d{1,2}\s*日|\d{4}-\d{2}-\d{2}|\d{1,2}月\d{1,2}日)"),
    "金额": re.compile(r"([0-9][0-9,]*(?:\.\d+)?\s*(?:万元|元))"),
    "比例": re.compile(r"(\d+(?:\.\d+)?\s*%|百分之[零一二三四五六七八九十百]+)"),
    "期限": re.compile(r"([零一二三四五六七八九十百\d]+\s*(?:个月|个工作日|天|年))"),
}
CN_NUM = {"零": 0, "一": 1, "二": 2, "三": 3, "四": 4, "五": 5, "六": 6, "七": 7, "八": 8, "九": 9, "十": 10, "百": 100}

def parse_amount(v):                        # "120,000 元" -> 120000.0；"3万元" -> 30000.0
    v = v.replace(",", "").replace(" ", "")
    return float(v[:-2]) * 10000 if v.endswith("万元") else float(v[:-1])
```

```text
== 场景二：合同关键字段抽取 + 规则校验
  原文: 本合同自2026年3月1日起生效，服务期为十二个…
    日期 ['2026年3月1日'] | 金额 ['120,000 元']（合计 120000 元）| 比例 [0.5] | 期限 ['2026年', '十二个月']
  原文: 供应商须在 2026-04-15 前交付，质保期…
    日期 ['2026-04-15'] | 金额 ['50,000元']（合计 50000 元）| 比例 [] | 期限 ['二十四个月']
  原文: 员工外派补贴每月 5,000 元，最长不超过三个…
    日期 [] | 金额 ['5,000 元']（合计 5000 元）| 比例 [90.0] | 期限 ['三个月']
```

第 1 条的期限抽出了 `'2026年'`——这是规则本身的污染：日期里的「年」被期限正则命中。这类**假命中**必须靠校验层滤掉（期限不能出现在日期串内部），或者先把日期 span 抠掉再做期限匹配。规则抽取的工程重点不是「命中更多」，而是「命中之后怎么确认」。

```text
场景二要点：
1. 强格式字段（日期/金额/比例/编号）用正则 + 中文数字转换，可解释、可审计
2. 规则抽取必须配字段级校验：范围校验（比例 <= 100%）、跨字段一致性（金额合计）、语义边界（期限不能落在日期里）
3. 校验失败的记录转人工队列，并把失败样本沉淀成新规则，一周迭代一次
4. 开放域实体（人名/机构/地点）交给 CRF 或预训练模型，别硬写正则
5. 提取金额时统一单位（万元/元），把原始字符串与归一化数值一起存，便于追溯
```

## 最佳实践与踩坑记录

最佳实践：

1. 先定标签方案与评估脚本（实体级），再动模型；评估不一致会让所有实验数字失去意义。
2. 永远跑两个测试集：同分布集（看拟合）与未登录实体集（看泛化）。差距大于 0.2 就先补数据或换特征粒度。
3. 特征粒度（char / word / 两者拼接）必须实测：本机同一数据 word 级 0.6301、char 级 0.3002。
4. 解码层统一走约束 Viterbi；把训练集里出现过的合法转移对固化成代码里的断言，上线前自检。
5. 模型输出与正则抽取组合：序列模型管开放域，正则管强格式字段，校验层兜底，三层各司其职。
6. 错误归因按「未登录/边界/类型」三桶统计，每周把 top 错误样本送人工复核；产出直接进标注规范或特征。

坑 1：把同分布测试集的高分当成模型能力。

结论：char 级 CRF 在同分布测试集 micro F1 1.0000，换一批未登录实体名后只有 0.3002（ORG/LOC 直接 0.0）。
原因：实体名在训练集里逐字出现过，字符窗口特征等价于查表；测试集换成新名字后，模型没有任何可泛化的线索。
解法：评估集强制包含未登录实体名（把实体名字典切成训练集与测试集两套互斥名单），并单独报告「已见/未见」两组指标。

坑 2：逐 token argmax 解码后直接算指标、直接上线。

结论：BiLSTM 在未登录实体测试集上 194/200 句含非法 BIO 序列，F1 0.1057；加约束 Viterbi 后 0 句非法、F1 0.2083。
原因：softmax 逐位置独立取最大，模型没有「标签之间要连续」的显式约束，尤其在分布外样本上会乱跳类型。
解法：从训练集统计合法转移对，解码时强制走合法路径；或者在网络里加真正的 CRF 层让转移权重参与训练。

坑 3：用词性标注当 NER 用。

结论：jieba 把「张三于」标成 `nr`（人名），把「腾讯」标成 `nz`（其他专名），「字节跳动」完全漏掉。
原因：词性标注器是词典 + HMM 驱动的通用工具，分词边界错位会直接破坏实体边界，词表也覆盖不到新机构名。
解法：词性只能当候选召回或特征；实体识别用 CRF/预训练模型，并把业务专名（产品名、公司名）补进 jieba 用户词典。

坑 4：word 级标注时忽略分词边界与实体边界的错位。

结论：本机数据里 5.31% 的训练词元、2.20% 的测试词元「跨界」（词内混有 O 或其他实体类型）。
原因：中文分词不保证与实体边界对齐，「base杭州」「深圳仓」这类写法尤其明显。
解法：优先 char 级标注；必须用 word 级时，对跨界词元单独加边界特征（词首/词尾字符），并在规范里写明跨界场景怎么标。

坑 5：以为 seqeval 会帮我校验标签序列合法。

结论：把预测序列首 token 强行改成 `I-PER`，seqeval 不报错，且该句 F1 前后都是 0.4000——孤立 `I-` 被当成新跨度起点。
原因：seqeval 按 BIO 规则切 span，实现上把 `I-` 起头也当作实体开始，不做合法性检查。
解法：在评估脚本前加一层合法性断言（不得以 `I-` 开头、类型不得中途跳变），非法就修模型或加约束解码。

## 概述

文本生成是「给定输入，产出新文本」的任务族：摘要、翻译、改写、对话、代码补全都属于它。它比理解类任务多两个工程变量：**解码策略**（同样的模型，greedy 会退化重复、temperature 与 top-p 决定多样性与稳定性）和**事实性**（生成模型会编造原文没有的数字、日期、结论，也就是幻觉）。摘要则分两条路：抽取式（从原文挑句子，绝不编造，但可读性差）与生成式（重写，通顺但可能编）。

本机实测环境：Python 3.14.7、jieba 0.42.1、numpy 2.5.4、scikit-learn 1.9.1、networkx 3.7、nltk 3.10.3、rouge_score 0.1.2；预训练生成模型（T5/BART/GPT 类）在本机不可用（无 PyTorch 与权重），相关代码标注为「本机未验证」。bigram 语言模型、TextRank、BLEU、ROUGE、幻觉校验都是本机真实运行结果。

```text
6. 幻觉控制 —— 相似度阈值扫描抓不到数字篡改，加数字一致性校验后 F1 从 0.5 到 0.8
```

## 生成任务与解码策略

自回归生成每一步都在模型输出的词表分布上选一个 token，**选法就是解码策略**：

| 策略 | 做法 | 特点 |
|------|------|------|
| greedy | 每步取 argmax | 确定性、最快，容易陷入重复循环，缺乏多样性 |
| beam search | 维护 k 条候选路径，取总概率最高的 | 适合翻译（要找「最可能」的句子），不适合开放式创作 |
| temperature | 概率除以 T 重新归一化后采样 | T<1 更保守，T>1 更发散；是「创造力」旋钮 |
| top-k | 只在概率最高的 k 个 token 里采样 | 砍掉长尾胡说，k 固定、不随分布自适应 |
| top-p（nucleus） | 取累积概率到 p 的最小集合再采样 | 自适应候选集大小，是目前最常用的组合（top-p + temperature） |
| 重复惩罚 / no_repeat_ngram | 对已出现的 token/n-gram 降权或禁用 | 直接压制复读，代价是要调惩罚强度 |

本机用一个 16 句中文制度语料训练 bigram 语言模型（词表 156、bigram 类型 267、add-k 平滑 k=0.2），把四种策略都跑一遍：

```python
import numpy as np
from collections import Counter, defaultdict

def next_dist(w, k=0.2):
    """P(下一个词 | 当前词)，add-k 平滑；缺统计时回退到结束符"""
    counts = {v: c for (u, v), c in bi.items() if u == w}
    total = ctx[w] + k * V
    return {v: (c + k) / total for v, c in counts.items()} if total else {"</s>": 1.0}

def sample_next(dist, mode, rng, k=5, p=0.9, T=1.0):
    words = [w for w, _ in dist.items()]
    probs = np.array([pr for _, pr in dist.items()], dtype="float64")
    if mode == "greedy":
        return words[int(probs.argmax())]
    if mode == "temperature":
        logits = np.log(probs + 1e-12) / T
        logits -= logits.max()
        z = np.exp(logits)
        return rng.choice(words, p=z / z.sum())
    order = np.argsort(-probs)
    if mode == "top-k":
        keep = order[:k]                                     # 固定候选数
    else:                                                    # top-p
        cum = np.cumsum(probs[order])
        keep = order[:int(np.searchsorted(cum, p) + 1)]       # 自适应候选数
    sub = probs[keep] / probs[keep].sum()
    return rng.choice([words[i] for i in keep], p=sub)
```


三个可复用的观察：greedy 在第 6 个 token 之后进入「超过六百元」的确定性循环——**没有重复惩罚的贪心解码在语料稀疏时必然复读**；temperature 0.6 与 1.0 输出完全相同，因为语料太小的分布本身就非常尖，调 T 的边际效果取决于分布的熵；top-k=3 给出了和 greedy 不同的分支，说明**候选集截断比温度更能改变输出**。换种子时输出长度差异极大（seed=1 只有一句半，seed=2 拼出了跨条目的混乱句子），提示解码参数要与评测集一起固定并记录。

```text
要点：
- 解码策略是「模型之外」的独立变量，同模型不同策略的输出质量可以差一个档
- greedy 在稀疏分布上必然复读，开放式生成不要用它；翻译这类「有唯一答案」的任务才适合 beam
- temperature 调的是分布的平坦度，T 太小近似 greedy、T 太大会胡说
- top-k 固定候选数，top-p 自适应；工业界默认组合是 top-p + temperature + 重复惩罚
- 记录推理时的全部解码参数（含随机种子）与生成结果，否则线上问题无法复现
- 本机语料只有 16 句，分布过尖导致 T 的调节几乎无效；真实语料熵更高，参数敏感度也更高
```

## 抽取式摘要

抽取式摘要只挑原句，绝不改写，因此**不可能产生幻觉**，在合规、医疗、金融场景里经常是唯一可选项。两条主流做法：位置法（取前 N 句，会议纪要/新闻导语上意外地强）与图排序法（TextRank：句子作为节点、句子相似度作为边权、PageRank 选中心句）。

TextRank 的实现要点是「边权用相似度、排序用加权 PageRank、最后按原文顺序回填」：

```python
import re, networkx as nx
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.metrics.pairwise import cosine_similarity

sents = [s for s in re.split(r"[。！？]", DOC) if s]              # 先按句号切句
X = TfidfVectorizer(analyzer="char_wb", ngram_range=(1, 2)).fit_transform(sents)
S = cosine_similarity(X)                                        # 句子间相似度矩阵
G = nx.Graph()
for i in range(len(sents)):
    G.add_node(i)
    for j in range(i + 1, len(sents)):
        if S[i, j] > 0:                                          # 只连有相似度的句子对
            G.add_edge(i, j, weight=float(S[i, j]))
pr = nx.pagerank(G, weight="weight", max_iter=200)               # 加权 PageRank 打分
ranked = sorted(range(len(sents)), key=lambda i: -pr[i])
summary = [sents[i] for i in sorted(ranked[:3])]                 # 取 top3 并按原文顺序回填
```


对比很典型：位置基线把「发布通知」这句口水话排在前三，TextRank 换成了「功能打通」「上线时间」「发票识别准确率」这三条有信息量的句子，但**它并没有选到操作类信息**（旧系统停写、培训安排、支持热线）——因为 TextRank 只按「被多少句子提到/跟其他句子有多像」打分，识别不出「行动项」。真实系统里通常给句子加轻量特征分（是否含数字、是否含动作词、是否为标题），与 PageRank 分数线性组合。

```text
要点：
- 抽取式摘要不产生幻觉，合规场景首选；短文本用「前 N 句」就够打
- TextRank = 句子相似度图 + 加权 PageRank，本机 top3 明显优于位置基线（选掉口水句）
- TextRank 偏爱「被多句引用的中心句」，识别不出行动项/数值结论，需要叠特征分
- 切句质量决定摘要质量：数字里的句点、引号内的句号都要处理
- 输出按原文顺序回填，读者体验比按分数排序好得多
- 想控长度就按 token 预算贪心加句，而不是固定句数
```

## 生成式摘要与文本改写

生成式摘要的目标是「重写而非拼贴」，主流结构演进是：seq2seq（编码器读原文，解码器逐词生成）-> 指针生成器（Pointer-Generator：允许从原文复制词，缓解 OOV 与数字错误）-> 预训练编解码器微调（T5/BART/mT5，当前默认方案）。改写（paraphrase）是同一套模型的不同任务形态：换措辞、调语气（正式化/口语化）、控长度、控难度。

预训练摘要模型的调用形态（本机未验证：需 PyTorch + 模型权重）：

```python
from transformers import pipeline

summarizer = pipeline("summarization", model="uer/t5-base-chinese-cluecorpussmall")  # 具体 checkpoint 以模型卡为准
print(summarizer(DOC, max_length=120, min_length=40, do_sample=False,
                 num_beams=4, length_penalty=1.0)[0]["summary_text"])

# 改写：用提示式接口做语气转换（同样需模型与权重）
PROMPT = "把下面这段客服回复改写成更温和、更专业的语气，保持事实不变：\n{text}\n改写："
```

训练侧的关键设置（摘要任务的常见组合）：`Seq2SeqTrainer` + `predict_with_generate=True` + `generation_max_length` 与评测口径对齐；损失上给「复制来源敏感」的目标（数字、专名）更高权重；`label_smoothing` 缓解曝光偏差。这些都属于「本机未验证」的工程经验，具体参数请以 transformers 官方文档为准：https://huggingface.co/docs/transformers/main_classes/trainer

改写任务的评估方式与机器翻译一致（见下节 BLEU/ROUGE），此外还需要**语义保持**检查：改写后的句子与原文的语义相似度（句向量余弦）应高于阈值，且关键实体/数字必须完全一致。

```text
要点：
- seq2seq 是骨架，指针生成器解决 OOV 与数字复制，预训练编解码器是当前默认方案
- 生成式摘要必须做「数字/专名一致性」检查，模型最容易在这里编造
- 改写任务除了通顺度，还要卡语义保持（句向量相似度）与关键信息一致（实体/数字）
- 摘要长度用长度惩罚与 max/min length 共同控制，太短会丢信息、太长会引入冗余
- 训练时 predict_with_generate 与评测口径要一致，否则验证集选出的模型不是最优生成模型
- 本机无 GPU/权重，以上为公开实践与官方 API 核对，未在本机验证
```

## 机器翻译与改写评估

BLEU 是机器翻译的经典自动指标：统计候选译文与参考译文的 n-gram 精确率几何平均，再乘长度惩罚。它便宜、可复现、与人评有弱相关，但它**只看表面重叠**：语序、同义词、代词替换都会让分数掉，而一句胡说八道只要凑巧重复了参考里的词也能拿分。nltk 的实现支持 1-4 gram 权重与平滑函数：

```python
from nltk.translate.bleu_score import sentence_bleu, SmoothingFunction

sf = SmoothingFunction().method1
b1 = sentence_bleu([list(ref)], list(hyp), weights=(1, 0, 0, 0))          # 只看 unigram
b4 = sentence_bleu([list(ref)], list(hyp), smoothing_function=sf)        # 默认权重 (0.25,)*4
```

```text
高质量摘要: BLEU-1 0.6986，BLEU-4(平滑) 0.5692
空泛但流畅: BLEU-1 0.1819，BLEU-4(平滑) 0.0218
UserWarning: The hypothesis contains 0 counts of 4-gram overlaps.（未平滑时 BLEU-4 直接为 0）
```

数字说明两件事：BLEU-1 与 BLEU-4 的差距能反映「词对得上但短语结构不对」；未平滑时只要没有 4-gram 重叠分数就是 0，短文本上必须开平滑（`SmoothingFunction` 提供 method0-method7，定义见 https://www.nltk.org/api/nltk.translate.bleu_score.html）。中文还有一个额外坑：BLEU 按 token 算，**中文必须先分词**，否则整句变成一个 token，BLEU 恒为 0 或 1。

```text
要点：
- BLEU 是 n-gram 精确率几何平均 + 长度惩罚，便宜但只看表面重叠
- 短句必须开平滑，否则 BLEU-4 常为 0（本机未平滑时就是 0）
- 中文先分词再算 BLEU，否则整句成一个 token，指标无意义
- BLEU 高不等于好：堆砌参考句里的词也能提分，必须配人评或事实性检查
- 翻译/改写上线用「BLEU 监控 + 抽样人评」双轨，不要只看单一自动指标
- 同一批数据换分词器/大小写策略，BLEU 会变，评测脚本要写进实验记录
```

## 生成质量评估

自动指标三大类：n-gram 重叠（BLEU、ROUGE、METEOR）、语义相似（BERTScore、句向量余弦）、事实性（对原文的蕴含/引用校验）。摘要任务最常用 ROUGE：ROUGE-N 是 n-gram 召回，ROUGE-L 用最长公共子序列（LCS）衡量句子级流畅度。Google 的 `rouge_score` 是 Python 原生实现（支持 ROUGE-L / ROUGE-N、可选 Porter 词干、`rougeL` 与 `rougeLsum` 两种口径），本机装上后与手写 LCS 实现对比：

```python
from rouge_score import rouge_scorer

scorer = rouge_scorer.RougeScorer(["rouge1", "rouge2", "rougeL"], use_stemmer=False)
r = scorer.score(ref, hyp)
print(r["rouge1"].fmeasure, r["rouge2"].fmeasure, r["rougeL"].fmeasure)

def rouge_l_f1(ref, hyp):                       # 手写 ROUGE-L：LCS + P/R 的调和平均
    a, b = list(ref), list(hyp)
    dp = [[0] * (len(b) + 1) for _ in range(len(a) + 1)]
    for i in range(1, len(a) + 1):
        for j in range(1, len(b) + 1):
            dp[i][j] = dp[i - 1][j - 1] + 1 if a[i - 1] == b[j - 1] else max(dp[i - 1][j], dp[i][j - 1])
    lcs = dp[-1][-1]
    p, rec = lcs / len(b), lcs / len(a)
    return 2 * p * rec / (p + rec)
```

```text
高质量摘要: ROUGE-1 F 0.0000，ROUGE-2 F 0.0000，ROUGE-L F 0.0000
空泛但流畅: ROUGE-1 F 0.0000，ROUGE-2 F 0.0000，ROUGE-L F 0.0000
手写 ROUGE-L 核对: 0.8065 vs 库 0.0000
```

库给 0 而手写实现给 0.8065，原因是 `rouge_score` **默认按空格切词**：中文没有空格，整句被当成一个 token，参考与候选的 token 不相等就全 0。这是中文场景最典型的「指标工具静默失效」——它不报错，只是给你一个恒为 0 的数。修法有两种：先分词再用空格拼回去（`" ".join(jieba.cut(text))`），或者直接用字符级 LCS 实现（本机手写版就是字符级）。

```text
要点：
- ROUGE-N 是 n-gram 召回（关注「参考里的信息覆盖了多少」），ROUGE-L 用 LCS 关注句子级流畅
- rouge_score 默认按空格切词，中文直接算全是 0；必须先分词或改用字符级实现
- 手写 LCS 版与库版对拍是发现这类问题的通用手段：两边给 0.8065 vs 0.0000 一眼就看出分词问题
- 自动指标只用于「同口径横比」，跨任务跨语料的分数不可比
- 事实性必须单独评估（见下节），BLEU/ROUGE 对幻觉完全不敏感
- 指标计算脚本要版本化：换分词器、换词干化策略都会改变分数
```

## 幻觉控制

幻觉是生成模型输出「原文没有、事实不成立」的内容，表现为编造数字/日期、张冠李戴、推断过头。控制手段分四层：

| 层次 | 手段 | 适用 |
|------|------|------|
| 输入 | 检索增强（RAG），把带出处的事实段塞进上下文 | 知识型问答、客服、报告生成 |
| 解码 | 约束解码（只允许抽取的候选、限制数字必须来自原文） | 数字/金额/日期敏感场景 |
| 输出 | 引用校验：把生成句与原文比对，低支持度就打回 | 摘要、评审意见、公告 |
| 流程 | 自一致性采样 + 交叉验证、人工兜底队列 | 高风险场景 |

校验层的工程实现通常是「句子相似度 + 结构化一致性」的组合。本机用 12 条摘要句（其中 5 条含未支持内容）做阈值扫描：

```python
import re
import numpy as np
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.metrics.pairwise import cosine_similarity

dvec = TfidfVectorizer(analyzer="char_wb", ngram_range=(1, 2)).fit(docs)
sim = np.array([cosine_similarity(dvec.transform([d]), dvec.transform([h]))[0, 0]
                for d, h in zip(docs, hyps)])            # 生成句与原文的相似度

def nums(s):                                             # 抽取句中的数字（含中文数词）
    return set(re.findall(r"[零一二三四五六七八九十百千]+|[0-9]+", s))

num_ok = np.array([len(nums(h) - nums(d)) == 0 for d, h in zip(docs, hyps)])
pred = (sim < 0.5) | (~num_ok)                            # 相似度低 或 出现原文没有的数字 -> 打回
```

```text
== 4. 幻觉引用校验（12 条摘要句，5 条含未支持内容）
  句子相似度余弦: 支持句 0.590 ~ 0.879，幻觉句 0.439 ~ 0.760
  数字一致性检查命中率: 幻觉句里数字全部被原文覆盖的比例 0.400
  阈值扫描（只用相似度阈值判幻觉）:
    thr    精确率  召回率  F1
    0.50   1.000  0.400  0.571
    0.60   0.667  0.400  0.500
  相似度(<0.5) + 数字一致性 组合: 精确率 0.800 召回率 0.800 F1 0.800
    仅靠相似度和数字都抓不到的幻觉: 旧系统已经于上月停用。
    仅靠相似度和数字都抓不到的幻觉: 公司为每名员工提供年度外部培训预算。
```

两组数字很说明问题：**支持句与幻觉句的相似度区间互相重叠**（支持句最低 0.590，幻觉句最高 0.760），所以纯相似度阈值最多把 F1 做到 0.571 左右，且精确率与召回率此消彼长；把「数字一致性」拼进来后 F1 提到 0.800（精确率 0.800、召回率 0.800），抓住的是「发票识别准确率 92% 被写成 98%」这类**数值篡改**。剩下两例漏检是语义型幻觉（「已于上月停用」把「下月将停用」的时间颠倒了；「提供年度培训预算」把「每年可申请一次外部培训」泛化成预算承诺）——这类问题需要蕴含判断模型或人工规则，字符重叠和数字比对都抓不到。

```text
要点：
- 幻觉分三类：数值篡改、时间/主体错位、推断过度；三类要用不同的检查器
- 纯相似度阈值不可靠：本机支持句与幻觉句的相似度区间重叠，F1 只能到 0.571
- 数字一致性（生成句里的数字必须出现在原文）把 F1 提到 0.800，成本几乎为零，优先做
- 语义型幻觉（时间颠倒、泛化成承诺）需要蕴含/NLI 模型，本机无模型未验证
- 高风险场景用「检索增强 + 引用输出 + 人工兜底」三层，别指望单点检测
- 把被打回的样本做成日报，既能调阈值，也能暴露原文本身缺信息的情况
```

## 应用场景实战

### 场景一：制度公告自动摘要 + 引用校验流水线

业务背景：HR 每周要发一条制度更新公告，要求「三句话讲清变化 + 每条都能指回原文」。方案是 TextRank 抽句 + 引用校验 + 人工确认队列：抽取式保证不编造，校验层兜住抽错（比如把日期句子当主句）。

```python
def summarize_with_citations(doc, topn=3):
    sents = [s for s in re.split(r"[。！？]", doc) if s]
    X = TfidfVectorizer(analyzer="char_wb", ngram_range=(1, 2)).fit_transform(sents)
    S = cosine_similarity(X)
    G = nx.Graph()
    G.add_nodes_from(range(len(sents)))
    for i in range(len(sents)):
        for j in range(i + 1, len(sents)):
            if S[i, j] > 0:
                G.add_edge(i, j, weight=float(S[i, j]))
    pr = nx.pagerank(G, weight="weight", max_iter=200)
    picked = sorted(sorted(range(len(sents)), key=lambda i: -pr[i])[:topn])
    out = []
    for i in picked:
        nums_ok = len(nums(sents[i]) - nums(doc)) == 0       # 抽出来的句子本身就来自原文，数字必然一致
        out.append({"text": sents[i], "cite": i, "pagerank": round(pr[i], 4), "num_ok": nums_ok})
    return out

for item in summarize_with_citations(DOC, 3):
    print("[句 %d | pagerank %.4f | 数字一致 %s] %s" % (item["cite"], item["pagerank"], item["num_ok"], item["text"]))
```

```text
本机输出（同一篇公告，9 句取 3）：
[句 1 | pagerank 0.1304 | 数字一致 True] 新系统把差旅申请、报销、审批三个环节打通，员工只需在一个入口提交
[句 2 | pagerank 0.1290 | 数字一致 True] 上线时间为本月二十日，旧系统将在下月十日停止写入
[句 4 | pagerank 0.1211 | 数字一致 True] 新系统支持移动端拍照上传发票，发票识别准确率在测试环境中为百分之九十二
校验层结论：抽取式摘要的数字天然来自原文（3/3 一致），幻觉风险为 0；风险转移到「选句不完整」
```

抽取式的取舍很清晰：零幻觉风险换来「可能漏掉关键行动项」。所以真实流水线里会再加一层「关键字段覆盖度检查」——把原文里的日期、金额、责任部门等结构化字段先抽出来，确认摘要句至少覆盖每个必需要素，否则提示「建议人工补一条」。

```text
场景一要点：
1. 抽取式是「零幻觉」方案：句子来自原文，数字与专名天然一致
2. 代价是可能漏掉行动项，用「关键字段覆盖度」做兜底检查
3. 每条摘要句带出处句号，人工确认成本从「重读全文」降到「看一眼出处」
4. PageRank 分数用于排序解释，别写进公告正文
5. 公告类场景保留人工确认队列：模型只做「候选收敛」，不做最终发布
```

### 场景二：客服回复的生成式改写 + 事实性门禁

业务背景：客服团队要对外发回复，先由模型生成初稿，但**不允许出现与工单事实不符的数字/承诺**。方案是生成（本机用可控的模板 + 抽取式拼装代替大模型）+ 数字一致性与长度门禁，不通过就打回人工。

```python
def reply_candidate(ticket, facts):
    """生成初稿：事实部分只从结构化字段拼装，措辞模板固定，保证数字与来源一致"""
    return (f"您好，关于订单 {facts['order_no']} 的问题我们已受理。"
            f"当前物流状态为「{facts['logistics']}」，预计 {facts['eta']} 送达。"
            f"如有其他问题请随时联系。")

def gate(reply, facts):
    problems = []
    if set(nums(reply)) - set(nums(" ".join(str(v) for v in facts.values()))):
        problems.append("出现工单事实里没有的数字")
    if "退款" in reply and "承诺" in reply:
        problems.append("包含未经授权的承诺语气")
    if len(reply) > 200:
        problems.append("超出对外回复长度上限")
    for k in ("order_no", "eta"):
        if str(facts[k]) not in reply:
            problems.append(f"缺少必填要素 {k}")
    return problems

facts = {"order_no": "SF123456", "logistics": "已揽收", "eta": "明天下午"}
reply = reply_candidate(None, facts)
print("回复:", reply)
print("门禁:", gate(reply, facts) or "通过")

bad = reply.replace("明天下午", "三天内").replace("已揽收", "已签收")
print("篡改版门禁:", gate(bad, facts))
```

```text
本机输出：
回复: 您好，关于订单 SF123456 的问题我们已受理。当前物流状态为「已揽收」，预计 明天下午 送达。如有其他问题请随时联系。
门禁: 通过
篡改版门禁: ['出现工单事实里没有的数字', '缺少必填要素 eta']
```

校验层抓住两类问题：把「明天下午」改成「三天内」会被数字白名单拦下（源文没有「三天」），同时触发必填要素检查；把「已揽收」改成「已签收」这类**状态篡改**不涉及数字，需要再加一条「状态词必须在结构化字段取值集合内」的检查，这也是门禁规则要按业务逐条补的原因。这套「生成自由 + 门禁硬约束」的组合在实际系统里比「反复调提示词让大模型别编」稳定得多：**能算出来的东西不要交给模型**，模型负责自然语言包装，数值与状态一律从结构化字段注入。

```text
场景二要点：
1. 数值与状态从结构化字段注入，不让模型自由发挥（能算的不要问模型）
2. 门禁三层：数字白名单、必填要素、语气/长度规则；任一不过就打回人工
3. 门禁规则要与业务方共同定义，规则本身就是产品需求
4. 记录被拦下的样本与原因分布，是优化提示词与规则的输入
5. 对外文本一律保留人工确认入口，模型只产出候选
```

## 最佳实践与踩坑记录

最佳实践：

1. 解码参数与提示模板一起版本化：temperature/top-p/重复惩罚/随机种子全部记录，否则线上问题不可复现。
2. 开放式生成先用 top-p + temperature 组合，翻译/结构化改写这类「有唯一答案」的任务才用 beam search。
3. 摘要优先考虑抽取式（零幻觉），确有重写需求再上生成式，并且必须配事实性检查。
4. 数字与专名一律做一致性检查：生成句里的数字必须出现在源文里（本机把 F1 从 0.571 提到 0.800）。
5. 自动指标只做同口径横比，上线决策用「自动指标监控 + 抽样人评 + 事实性门禁」三件套。
6. 中文自动指标先确认分词口径（BLEU 先分词、ROUGE 先分词或改字符级），把指标脚本纳入代码评审。

坑 1：用 greedy 做开放式生成，然后怀疑模型坏了。

结论：本机 bigram LM 的 greedy 输出在第 6 个 token 后进入「超过六百元」的死循环；temperature/top-k 采样则给出正常句子。
原因：greedy 每步取 argmax，一旦落到「高频接续对」上就再也出不来；语料稀疏时这种确定性循环几乎是必然。
解法：开放式生成用采样（top-p + temperature），或加重复惩罚/no_repeat_ngram；greedy 只留给确定性任务。

坑 2：中文直接用 rouge_score 算 ROUGE。

结论：参考与候选都是中文时，ROUGE-1/2/L 全给 0.0000，而同一对文本的手写字符级 LCS 实现给 0.8065。
原因：rouge_score 默认按空格切词，中文整句被当成一个 token，两边 token 不相等就全 0；它不报错，只是静默给出恒零指标。
解法：先 `" ".join(jieba.cut(text))` 再送库，或直接用字符级 LCS 实现；并把「手写实现与库对拍」作为指标代码的固定自检。

坑 3：用相似度阈值当幻觉检测器。

结论：纯相似度阈值最好只有 F1 0.571（精确率 1.0、召回率 0.4），因为支持句的相似度下限（0.590）与幻觉句的上限（0.760）重叠。
原因：相似度衡量的是「用词重合度」，幻觉句常常就是改写原文的词（把 92% 改成 98%），词面照样很像。
解法：叠加结构化一致性检查——数字必须来自源文（本机把 F1 提到 0.800）；时间/主体错位这类语义幻觉再上蕴含模型或规则。

坑 4：BLEU 未平滑 + 未分词，指标全 0 还以为模型没学好。

结论：未开平滑时 BLEU-4 为 0（nltk 会给出「0 counts of 4-gram overlaps」警告）；中文不分词时 BLEU 恒为 0 或 1。
原因：BLEU 的 n-gram 精确率只要有一阶没有命中，几何平均就是 0；中文不分词时整句是一个 token。
解法：短句必开 `SmoothingFunction`，中文先分词；把指标脚本与样例断言固化进仓库（样例 BLEU 应为 0.69）。

坑 5：抽取式摘要选出来的句子不完整，被当成「模型幻觉」。

结论：TextRank 选出的句子本身完全来自原文，但漏掉了「旧系统停写」「培训时间」这类行动项，业务方读起来觉得「摘要错了」。
原因：抽取式只做「选句」，不会重组信息；PageRank 偏好中心句而非行动项。
解法：加关键字段覆盖度检查（日期、金额、责任部门、行动项），不达标就提示人工补句；或用生成式重写但配事实性门禁。

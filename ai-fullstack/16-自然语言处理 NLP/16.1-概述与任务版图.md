## 概述

自然语言处理（NLP）要解决的是「把非结构化文本变成可计算、可决策的信号」。工程上它从来不是单一模型问题，而是四件事的组合：任务定义（分类 / 序列标注 / 抽取 / 生成）、文本表示、模型与训练、指标与上线口径。本篇先把这张地图铺开——有哪些任务、各时代用什么方法、每个任务该看什么指标，最后落到工具库选型；16.2 到 16.9 再逐步展开每一块。

```text
本篇主线：
1. 任务版图 —— 分类 / 序列标注 / 句对 / 抽取 / 生成 / 检索，各自输入输出是什么
2. 技术脉络 —— 规则与统计 -> 词向量与深度网络 -> 预训练微调 -> 大模型提示与蒸馏
3. 指标总览 —— accuracy、P/R/F1、macro/micro/weighted、AUC、混淆矩阵的选择口径
4. 序列与生成指标 —— span 级 F1、BLEU、ROUGE-L、困惑度 PPL 的算法与陷阱
5. 工具库 —— jieba / scikit-learn / nltk / spaCy / transformers 的分工与安装方式
6. 选型 —— 数据量、算力、延迟、可解释性四个维度怎么权衡
```

## NLP 任务版图

按「输入输出形态」分，NLP 任务只有六类，其余都是这六类的组合：**句级分类**（一段文本 -> 一个或多个标签）、**序列标注**（token -> 逐 token 标签）、**句对匹配与相似度**（两句 -> 分数或类别）、**信息抽取**（文本 -> 结构化字段 / 三元组）、**生成**（文本 -> 文本）、**检索与排序**（query -> 文档列表）。同一段工单文本可以被六类任务同时消费，所以项目第一步是把任务版图画清楚，而不是先挑模型。

```python
import re
import jieba
import jieba.posseg as pseg
import jieba.analyse

text = "【投诉】我的订单 2026-10-11 下单的手机壳到现在还没发货，客服电话一直打不通，请尽快处理！"
print("原文:", text)
print("分词(精确模式):", "/".join(jieba.cut(text)))
print("词性标注:", " ".join("%s/%s" % (w.word, w.flag) for w in pseg.cut(text)))
print("TF-IDF 关键词:", jieba.analyse.extract_tags(text, topK=6, withWeight=True))
print("TextRank 关键词:", jieba.analyse.textrank(text, topK=5))
print("句子数:", len([s for s in re.split(r"[。！？!?]", text) if s.strip()]))
```

本机真实输出：


两个真实结论：jieba 的 TF-IDF 关键词把 `2026`、`10`、`11` 顶到前三（数字在词表里 IDF 极高），生产上必须先做数字归一化或加停用词；`句子数` 得到 1 是因为分句正则没按逗号切，切句粒度要按业务调。

```text
任务版图（输入 -> 输出 -> 常用指标）：
1. 句级分类      文本 -> 标签            accuracy / macro-F1 / AUC（不均衡还要看 PR 曲线）
2. 多标签分类    文本 -> 标签集合        micro-F1 / macro-F1 / Hamming loss / 子集准确率
3. 序列标注      token -> BIO 标签       span 级 P/R/F1（边界必须完全一致才算对）
4. 句对匹配      (文本, 文本) -> 分数    正负例 AUC / MAP / MRR
5. 信息抽取      文本 -> 结构化字段     字段级精确率与召回率（抽错字段比抽不到更贵）
6. 生成/摘要     文本 -> 文本            BLEU / ROUGE-L / 人工评分（自动指标只是筛子）
7. 检索问答      query -> 文档/答案      Recall@k / MRR / EM / token-F1
```

## 技术发展脉络

四个时代的差别不在「模型更深」，而在**表示是怎么来的**：规则时代靠人写模式，统计时代靠人工设计特征（分词、词性、n-gram），词向量与深度网络时代靠数据学表示，预训练时代靠大规模无标注语料学通用表示再微调。看清这条线就能判断方案上限——特征还是人工设计的，模型再深也只是在拟合特征工程的产物。

```python
import re
s = "unbelievable tokenization"
print("原始串:", s)
print("规则/统计时代(空白切分):", re.findall(r"[A-Za-z']+|[0-9]+", s.lower()))
print("词向量时代(词表下限词元):", s.lower().split())
sub = ["un", "believ", "able", "token", "ization"]
codes = [318, 4521, 88, 11234, 771]
print("子词时代(BPE 风格切分):", list(zip(sub, codes)))
print("预训练/LLM 时代: 同一批 token 直接喂 Transformer，池化向量做下游分类")
```

本机真实输出：

```text
原始串: unbelievable tokenization
规则/统计时代(空白切分): ['unbelievable', 'tokenization']
词向量时代(词表下限词元): ['unbelievable', 'tokenization']
子词时代(BPE 风格切分): [('un', 318), ('believ', 4521), ('able', 88), ('token', 11234), ('ization', 771)]
预训练/LLM 时代: 同一批 token 直接喂 Transformer，池化向量做下游分类
```

```text
四个时代的工程对照：
1. 规则/统计       特征人工设计（词典 + 正则 + n-gram），可解释、可离线，泛化靠人写规则
2. 词向量/深度     静态词向量 + CNN/RNN/LSTM，特征来自数据，语料规模决定表示质量
3. 预训练/微调     BERT/RoBERTa 等通用表示 + 少量标注微调，一个主干挂多个任务头
4. LLM 时代        提示/少样本/指令微调，工程重心转到检索、评测、成本与幻觉控制
贯穿四代的不变项：指标口径、数据清洗、标注一致性、错误分析、人工兜底
```

## 评价指标总览

指标选错比模型选错更致命。基本规则：**类别均衡**看 accuracy 与 macro-F1；**不均衡且关心正类**看 macro-F1、AUC 与 PR 曲线，accuracy 会被多数类稀释；**多标签**看 micro-F1 与 Hamming loss，子集完全正确率只在标签强相关时才有意义；**上线**还要单独看混淆矩阵和阈值扫描，因为业务代价是不对称的。

```python
import numpy as np
from sklearn.metrics import (accuracy_score, precision_score, recall_score,
                             f1_score, confusion_matrix, classification_report)

y_true = np.array([0]*80 + [1]*15 + [2]*5)
y_pred = np.array([0]*74 + [1]*3 + [2]*3 + [1]*13 + [2]*2 + [2]*5)
print("样本分布:", np.bincount(y_true))
print("accuracy      :", round(accuracy_score(y_true, y_pred), 4))
for avg in ("macro", "micro", "weighted"):
    print("%-9s P=%.4f R=%.4f F1=%.4f" % (avg,
          precision_score(y_true, y_pred, average=avg, zero_division=0),
          recall_score(y_true, y_pred, average=avg, zero_division=0),
          f1_score(y_true, y_pred, average=avg, zero_division=0)))
print(confusion_matrix(y_true, y_pred))
print(classification_report(y_true, y_pred, digits=3, zero_division=0))
```

同一个模型，accuracy 0.92、micro-F1 0.92、macro-F1 0.82、weighted-F1 0.93——差距全部来自只有 5 个样本的第 2 类。汇报只报 accuracy，等于掩盖了「小类不可用」这件事。

```python
from sklearn.metrics import roc_auc_score
rng = np.random.default_rng(42)
score = np.concatenate([rng.normal(0.8, 1.0, 80), rng.normal(-0.2, 1.0, 1920)])
label = np.concatenate([np.ones(80), np.zeros(1920)]).astype(int)
prob = 1 / (1 + np.exp(-score))
pred = (prob > 0.5).astype(int)
print("正样本占比:", round(label.mean(), 4))
print("accuracy(阈值0.5):", round(accuracy_score(label, pred), 4),
      "| 全预测负类的 accuracy:", round(1 - label.mean(), 4))
print("ROC-AUC:", round(roc_auc_score(label, prob), 4))
print("F1(正类):", round(f1_score(label, pred), 4),
      "| 召回:", round(recall_score(label, pred), 4))
best = (0, 0)
for t in np.arange(0.05, 0.96, 0.01):
    f = f1_score(label, (prob > t).astype(int))
    if f > best[1]:
        best = (round(float(t), 2), round(float(f), 4))
print("验证集扫描最佳阈值 -> F1:", best)
```

本机真实输出：

```text

accuracy(阈值0.5): 0.6005 | 全预测负类的 accuracy: 0.96
ROC-AUC: 0.8033
F1(正类): 0.1399 | 召回: 0.8125
验证集扫描最佳阈值 -> F1: (0.79, 0.2315)
```

```text
指标选择口径：
1. 均衡多分类    accuracy 与 macro-F1 一起看，两者差距大说明存在弱势类
2. 不均衡二分类  AUC / PR-AUC 为主；本例全预测负类就有 0.96 的 accuracy
3. 多标签        micro-F1（整体）+ 每标签 F1（定位差标签）+ Hamming loss
4. 排序/检索     Recall@k、MRR、NDCG，不要用分类指标衡量排序质量
5. 上线决策      混淆矩阵 + 阈值扫描 + 每类代价；0.5 只是数学默认值，不是业务阈值
```

## 序列与生成指标

分类指标不能直接套到序列标注上。序列标注的正确单位是**实体**：`(类型, 起止位置)` 完全一致才算命中，token 级正确率会系统性高估。生成任务则用 n-gram 重合度（BLEU / ROUGE-L）与困惑度（PPL），它们只是筛子，不能替代人工评估。两者都需要自己写几行代码，因为「指标口径」本身就是工程资产。

```python
import numpy as np
gold = "B-PER I-PER O O B-ORG I-ORG I-ORG O B-LOC O".split()
pred = "B-PER I-PER O O B-ORG I-ORG O O B-LOC I-LOC".split()
tok_hit = sum(g == p for g, p in zip(gold, pred))
print("token 级正确率: %d/%d = %.4f" % (tok_hit, len(gold), tok_hit / len(gold)))

def spans(seq):                      # BIO -> {(类型, 起, 止)}
    out, cur, start = set(), None, None
    for i, t in enumerate(seq):
        if t.startswith("B-"):
            if cur:
                out.add((cur, start, i - 1))
            cur, start = t[2:], i
        elif t.startswith("I-") and cur:
            continue
        else:
            if cur:
                out.add((cur, start, i - 1))
            cur, start = None, None
    if cur:
        out.add((cur, start, len(seq) - 1))
    return out

g, p = spans(gold), spans(pred)
tp = len(g & p)
prec = tp / len(p) if p else 0.0
rec = tp / len(g) if g else 0.0
f1 = 2 * prec * rec / (prec + rec) if prec + rec else 0.0
print("gold spans:", sorted(g))
print("pred spans:", sorted(p))
print("span 级 P=%.4f R=%.4f F1=%.4f (tp=%d)" % (prec, rec, f1, tp))
```

本机真实输出：

```text
token 级正确率: 8/10 = 0.8000
gold spans: [('LOC', 8, 8), ('ORG', 4, 6), ('PER', 0, 1)]
pred spans: [('LOC', 8, 9), ('ORG', 4, 5), ('PER', 0, 1)]
span 级 P=0.3333 R=0.3333 F1=0.3333 (tp=1)
```

token 级看着有 0.8，实体级 F1 只有 0.33——因为 ORG 少标了尾字、LOC 多标了一个字。这就是 NER 项目必须用 span 级指标的原因（seqeval 等库就是干这个的）。

```python
import math
import numpy as np
from nltk.translate.bleu_score import sentence_bleu, SmoothingFunction

ref = "the cat is sitting on the mat".split()
sm = SmoothingFunction().method1
for name, cand in (("完全一致", ref[:]), ("部分一致", "a dog runs quickly on the mat".split())):
    print("%s BLEU-1=%.4f BLEU-4=%.4f" % (name,
          sentence_bleu([ref], cand, weights=(1, 0, 0, 0)),
          sentence_bleu([ref], cand, weights=(0.25,) * 4, smoothing_function=sm)))

def rouge_l(ref_tokens, cand_tokens):     # 最长公共子序列
    m, n = len(ref_tokens), len(cand_tokens)
    dp = [[0] * (n + 1) for _ in range(m + 1)]
    for i in range(1, m + 1):
        for j in range(1, n + 1):
            dp[i][j] = dp[i - 1][j - 1] + 1 if ref_tokens[i - 1] == cand_tokens[j - 1] \
                else max(dp[i - 1][j], dp[i][j - 1])
    lcs = dp[m][n]
    prec, rec = lcs / n, lcs / m
    return prec, rec, 2 * prec * rec / (prec + rec)

for name, cand in (("完全一致", ref[:]), ("部分一致", "a dog runs quickly on the mat".split())):
    pr, rc, f = rouge_l(ref, cand)
    print("%s ROUGE-L P=%.4f R=%.4f F=%.4f" % (name, pr, rc, f))

for probs in ([0.9, 0.8, 0.7, 0.6], [0.9, 0.2, 0.05, 0.3]):
    nll = -np.mean(np.log(probs))
    print("概率 %s -> 交叉熵 %.4f nat -> PPL %.4f" % (probs, nll, math.exp(nll)))
```

本机真实输出：

```text
完全一致 BLEU-1=1.0000 BLEU-4=1.0000
部分一致 BLEU-1=0.4286 BLEU-4=0.1635
完全一致 ROUGE-L P=1.0000 R=1.0000 F=1.0000
部分一致 ROUGE-L P=0.4286 R=0.4286 F=0.4286
概率 [0.9, 0.8, 0.7, 0.6] -> 交叉熵 0.2990 nat -> PPL 1.3485
概率 [0.9, 0.2, 0.05, 0.3] -> 交叉熵 1.4786 nat -> PPL 4.3869
```

```text
序列与生成指标要点：
1. 序列标注只认实体级 (类型, 起, 止) 全对；token 级准确率会高估（本例 0.80 vs 0.33）
2. BLEU-4 在短句上极易为 0：任一阶 n-gram 零重合就整体归零，必须配 SmoothingFunction
3. ROUGE-L 基于最长公共子序列、不要求连续，适合摘要；BLEU 基于 n-gram 精度，适合翻译
4. PPL = exp(平均负对数似然)，只在同词表同分词下可比，跨模型比 PPL 没有意义
5. 自动指标用于回归监控与筛掉明显坏样本，上线前必须抽样人工评分
```

```text
工具库与选型要点：
1. 先查运行环境再选库：Python 版本决定有没有 wheel，用独立 venv 是底线
2. 中文库要自带词表/模型文件；jieba 自带 dict.txt，装完即可分词
3. nltk 的算法与语料是两回事：stemmer 离线可用，wordnet/stopwords 需要下载
4. 数据量维度：百条 -> 规则或线性模型；万条 -> 深度模型；无标注 -> 预训练表示
5. 算力与时延维度：CPU 毫秒级 -> TF-IDF/线性；GPU + 语义泛化 -> 预训练微调
6. 可解释性维度：金融医疗要能说清「为什么」，线性模型系数与规则词表仍是刚需
```

## 应用场景实战

### 场景一：为客户服务中心建立多任务指标基线

真实项目里，任务版图不是画在 PPT 上，而是落成一份**可运行的评测脚本**：同一批标注数据同时产出分类指标、实体级指标、问答指标，换模型时一键复现口径。下面这段在本机真实跑通（分类部分复用 16.4 构造的中文评论测试集，序列标注与问答用小规模金标准示例）。

```python
import csv, re
import numpy as np
import jieba
from sklearn.pipeline import Pipeline
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import accuracy_score, f1_score, precision_recall_fscore_support

PUNCT = re.compile(r"[\W_]+", re.UNICODE)
def tok(s):
    return [w for w in jieba.lcut(s) if w.strip() and not PUNCT.fullmatch(w)]

rows = {"train": [], "val": [], "test": []}
with open("/root/.hermes/cache/scratch/nlp164_data.csv", encoding="utf-8") as f:
    for r in csv.DictReader(f):
        rows[r["split"]].append((r["text"], int(r["label"])))
Xtr = [t for t, _ in rows["train"] + rows["val"]]
ytr = [y for _, y in rows["train"] + rows["val"]]
Xte = [t for t, _ in rows["test"]]
yte = np.array([y for _, y in rows["test"]])

clf = Pipeline([("v", TfidfVectorizer(tokenizer=tok, token_pattern=None, lowercase=False)),
                ("m", LogisticRegression(max_iter=1000))]).fit(Xtr, ytr)
pred = clf.predict(Xte)
print("[分类·情感三分类] n=%d accuracy=%.4f macroF1=%.4f"
      % (len(Xte), accuracy_score(yte, pred), f1_score(yte, pred, average="macro")))
p, r, f, s = precision_recall_fscore_support(yte, pred, average=None, labels=[0, 1, 2], zero_division=0)
for i, name in enumerate(["负面", "中性", "正面"]):
    print("     %s P=%.3f R=%.3f F1=%.3f 支持数=%d" % (name, p[i], r[i], f[i], s[i]))

# 实体级指标：BIO 序列 -> {(类型, 起, 止)}
GOLD = [("张伟", "客服 张伟 回复 说 今天 发货", "B-PER", 1, 1),
        ("SN2026011", "订单 SN2026011 已 揽件", "B-ORD", 1, 1),
        ("北京仓", "从 北京仓 发出", "B-LOC", 1, 1),
        ("李娜", "售后 李娜 处理 完成", "B-PER", 1, 1)]
PRED = [("张伟", 1, 1), ("SN2026011", 1, 1), ("北京中心仓", 1, 2)]
g = set((n, s, e) for n, _, _, s, e in GOLD if n)
p_ = set((n, s, e) for n, s, e in PRED if n)
tp = len(g & p_)
print("[序列标注·实体级] gold=%d pred=%d tp=%d P=%.3f R=%.3f F1=%.3f"
      % (len(g), len(p_), tp, tp / len(p_), tp / len(g), 2 * tp / (len(g) + len(p_))))
print("     漏掉/未命中:", sorted(g - p_), " 误报:", sorted(p_ - g))
```

本机真实输出（节选）：

```text
[分类·情感三分类] n=300 accuracy=0.7567 macroF1=0.7542
     负面 P=0.709 R=0.736 F1=0.722 支持数=106
     中性 P=0.968 R=0.858 F1=0.910 支持数=106
     正面 P=0.604 R=0.659 F1=0.630 支持数=88

```

```text

  业务线分类      accuracy    0.8611      >=0.85     6 类，30% 工单含跨线干扰句
```

```text
3. span 级指标要写死「边界完全一致」，否则同一份预测会算出不同的 F1
4. 基线与上线门槛一起写进需求文档，否则没人知道当前离上线还差多远
```

### 场景二：同一批数据上的方案选型与成本口径

选型要用同一份数据、同一套指标，还要把**训练时间、模型体积、推理吞吐**一起量出来，否则「效果差不多」的方案会被直觉带偏。下面这段在本机 CPU 上真实跑通。

```python
import time, io, joblib
from sklearn.feature_extraction.text import TfidfVectorizer, CountVectorizer
from sklearn.linear_model import LogisticRegression
from sklearn.pipeline import Pipeline
from sklearn.metrics import accuracy_score, f1_score

POSW = {"很好", "很快", "不错", "给力", "满意", "实惠", "划算", "细致", "到位", "顺畅", "负责", "及时", "耐心"}
NEGW = {"太差", "太慢", "很差", "糙", "贵", "不值", "失联", "被拒", "敷衍", "破损", "异味"}
def rule_pred(t):
    pos, neg = sum(w in t for w in POSW), sum(w in t for w in NEGW)
    return 2 if pos > neg else (0 if neg > pos else 1)

candidates = {
    "规则词表": None,
    "词袋+LR": Pipeline([("v", CountVectorizer(tokenizer=tok, token_pattern=None, lowercase=False)),
                         ("m", LogisticRegression(max_iter=1000))]),
    "TFIDF+LR": Pipeline([("v", TfidfVectorizer(tokenizer=tok, token_pattern=None, lowercase=False)),
                          ("m", LogisticRegression(max_iter=1000))]),
    "char2-4gram+LR": Pipeline([("v", TfidfVectorizer(analyzer="char_wb", ngram_range=(2, 4))),
                                ("m", LogisticRegression(max_iter=1000))]),
}
print("%-16s %-8s %-8s %-10s %-10s %s" % ("方案", "acc", "macroF1", "训练秒", "模型KB", "1000条推理ms"))
for name, pipe in candidates.items():
    t0 = time.perf_counter()
    if pipe is None:
        pr, fit_s, size_kb = [rule_pred(t) for t in Xte], 0.0, 0.0
    else:
        pipe.fit(Xtr, ytr)
        fit_s = time.perf_counter() - t0
        pr = pipe.predict(Xte)
        buf = io.BytesIO()
        joblib.dump(pipe, buf)
        size_kb = len(buf.getvalue()) / 1024
    t1 = time.perf_counter()
    for _ in range(3):
        [rule_pred(t) for t in Xte * 4] if pipe is None else pipe.predict(Xte * 4)
    infer_ms = (time.perf_counter() - t1) / 3 * 1000
    print("%-16s %-8.4f %-8.4f %-10.2f %-10.1f %.1f" % (
        name, accuracy_score(yte, pr), f1_score(yte, pr, average="macro"), fit_s, size_kb, infer_ms))
```

本机真实输出：

```text
方案               acc      macroF1  训练秒        模型KB       1000条推理ms
规则词表             0.5667   0.5438   0.00       0.0        8.2
词袋+LR            0.7700   0.7686   0.12       6.3        112.9
TFIDF+LR         0.7567   0.7542   0.10       7.6        103.7
char2-4gram+LR   0.7800   0.7751   2.05       156.9      40.3
```

口径说明：单机 CPU（容器内）、无 GPU；推理耗时含 jieba 分词（词袋 / TF-IDF 方案），char 方案不含分词，所以它反而更快；表中耗时是当次实测值，会随机器负载有 20% 上下的波动（本机两次运行规矩词表方案分别测到 8.2ms 与 6.5ms），比较方案时要看数量级而不是小数位。选型结论：数据量小、要离线、要可解释，就用 char n-gram 或 TF-IDF + 线性模型起步；有大量标注与 GPU、且需要语义泛化再换预训练微调；规则词表始终留作兜底与可解释补充。

```text
场景二要点：
1. 选型要同时报效果、训练成本、模型体积、推理吞吐，缺一项就会被直觉带偏
2. 规则方案 8.2ms/1000 条是性能基准线，模型方案不该比它慢几个数量级
3. 字符 n-gram 本例反超词级方案（0.7751 vs 0.7542）：测试集措辞与训练集不同，字符粒度更稳
4. 模型体积也要一起看：char 方案 157KB vs 词袋 6.3KB，边缘部署时这是决定项
```

## 最佳实践与踩坑记录

最佳实践：

1. 先定任务与指标，再选模型。把「输入是什么、输出是什么、错了谁买单」写清楚，比换 backbone 更能提升线上效果。
2. 每个任务都要有一个「最笨的基线」（多数类、规则词表、TF-IDF + LR）。没有基线，你不知道 0.9 的 F1 是模型的功劳还是数据太干净。
3. 指标口径写进脚本而不是文档。测试集版本、分词方式、阈值都要固化，否则两次实验的数字不可比。
4. 汇报至少给三个数：整体指标、弱势类指标、混淆矩阵。只报 accuracy 的评估报告一律退回。
5. 中文项目把「词表 + 停用词 + 领域词典」当资产管理，带版本号入库，不要散落在各人脚本里。
6. 指标之外留一条人工抽检通道。自动指标只能证明「没有明显退化」，证明不了「业务上可用」。

坑 1：用 accuracy 汇报不均衡任务，上线后发现正类基本抓不到。

结论：正样本占比 4% 时，全预测负类就有 0.96 的 accuracy，而正类 F1 只有 0.1399。
原因：accuracy 是所有样本的平均命中率，多数类主导分母；它不区分「哪一类错」，也不反映错误的业务代价。
解法：不均衡任务改用 macro-F1 / AUC / PR 曲线，并在验证集上扫描判定阈值。本机实测阈值从 0.5 挪到 0.79，正类 F1 从 0.1399 提到 0.2315——阈值是调出来的参数，不是代码里的常量。

坑 2：把 token 级准确率当成 NER 的效果指标。

结论：token 级正确率 0.80 的同一条预测，实体级 F1 只有 0.33。
原因：实体是整体语义单位，边界错一个字就等于实体不存在；token 级指标把这种错误摊薄到每个 token 上，系统性高估。
解法：用 `(类型, 起, 止)` 三元组集合算 span 级 P/R/F1；BIO 解码还要处理 `I-` 开头、类型不一致等非法序列。正式项目可复用 seqeval，手写实现要配单元测试。

坑 3：跨模型比较困惑度（PPL）或跨分词器比较 BLEU。

结论：同一句译文在不同分词器下 BLEU 能差几个点；PPL 在不同词表下完全不可比。
原因：BLEU 的 n-gram 与 PPL 的 softmax 词表都由分词器决定，分词粒度变了统计量定义就变了。
解法：固定分词器版本并写进实验记录，对外只报同一分词器下的相对变化。序列标注同理：换分词器后历史 span-F1 全部作废，必须重跑基线。

坑 4：默认「所有工具库都能 pip 装上」。

结论：本机 Python 3.14 环境里 gensim 4.4.0 源码构建失败（`Failed to build installable wheels`），nltk 的 wordnet 语料下载直接超时。
原因：新 Python 版本常常没有预编译 wheel；语料类资源依赖额外网络下载，内网/离线环境两头都卡。
解法：开工前跑一次版本核查脚本，把「已装 / 未装 / 未验证」三类写进文档；缺的用替代实现（自写 PPMI + SVD 词向量）或明确标注「未在本机验证」，不要凭记忆写参数。

## 概述

文本预处理的目标只有一个：把原始文本变成长度可控、噪声可控、可复现的 token 序列。它包含五件事——清洗与规范化（字符层面的统一）、分词（切成模型能消费的单位）、停用词与词形归一（砍掉无信息与冗余形态）、正则与规则处理（抽字段、脱敏、过滤）、以及数据增强（小样本时扩充训练集）。英文资料常把这几步当琐事，但在中文里分词器、词表、停用词表的选择直接决定后面模型的上限。

```text
本篇主线：
1. 清洗与规范化 —— Unicode NFKC、全角转半角、去标签/零宽/表情、统一大小写与空白
2. 分词 —— jieba 四种模式、自定义词典、词性标注、英文正则切分、中文按字
3. 停用词与词干 —— sklearn 内置英文停用词、自建中文停用词、Porter/Snowball 词干化
4. 正则与规则处理 —— 抽取订单号/金额/日期/联系方式，PII 脱敏，Trie 敏感词过滤
5. 数据增强 —— EDA 四件套（同义替换/随机交换/删除/插入）与它的真实收益边界
6. 流水线 —— 把上述步骤封成可复用、可缓存、可序列化的一个类
```

本机实测环境：Python 3.14.7、jieba 0.42.1、scikit-learn 1.9.1、nltk 3.10.3。下文所有 text 代码块都是本机真实运行输出。jieba 首次 import 会打印 `Building prefix dict ...` 与 `Loading model cost ...` 日志，这是词典加载，不是报错；`jieba.dt.tmp_dir`/`cache_file` 可以改缓存位置（官方 README 有说明）。

## 清洗与规范化

清洗的第一步不是删东西，而是**归一化**：不同来源的文本带着全角字符、HTML 实体、零宽字符、兼容性字符（①、Ⅻ、½），不统一就等着特征被切得稀碎。第二步才是去噪（标签、链接、表情）与掩码（手机号、邮箱、卡号）。顺序很关键：先 NFKC 再正则，否则全角冒号、全角数字会绕过你的模式串。

```python
import re, unicodedata, html

raw = [
    "<p>【预售】iPhone 17 Pro 手机壳 &nbsp;限时 ５．５折！！！</p>",
    "客服　电话400-820-1234，邮箱 Service@Shop.COM ，微信：shop_vip   ",
    "物流显示“已揽件”三天了还没动，ＷＣ！\u3000再不发就投诉\u200b",
    "订单号202610110001，金额￥１，２３９.００元，地址：北京市海淀区中关村大街1号",
]
URL = re.compile(r"https?://\S+|www\.\S+")
EMAIL = re.compile(r"[\w.+-]+@[\w-]+\.[\w.]+")
HTML_TAG = re.compile(r"<[^>]+>")
CTRL = re.compile(r"[\u0000-\u001f\u007f\u200b-\u200f\ufeff]")
MULTI_SPACE = re.compile(r"[ \t\u3000]+")
TEL = re.compile(r"(?<!\d)(?:\d{3,4}-\d{7,8}|\d{3,4}-\d{3,4}-\d{4}|\d{11})(?!\d)")

def clean(s, keep_case=False):
    s = unicodedata.normalize("NFKC", s)   # 兼容字符归一：全角字母/数字、①、½ 等
    s = html.unescape(s)                   # &nbsp; -> 空格
    s = HTML_TAG.sub(" ", s)               # 去 HTML 标签
    s = CTRL.sub("", s)                    # 去零宽与控制字符
    if not keep_case:
        s = s.lower()
    s = URL.sub(" <url> ", s)
    s = EMAIL.sub(" <email> ", s)
    s = TEL.sub(" <tel> ", s)              # 电话统一掩码，避免数字进特征
    return MULTI_SPACE.sub(" ", s).strip()

for t in raw:
    print("%s\n  -> %s" % (t, clean(t)))
print("NFKC 逐字符示例:", "５．５折 ＷＣ ｉＰｈｏｎｅ Ⅻ ① ½",
      "->", unicodedata.normalize("NFKC", "５．５折 ＷＣ ｉＰｈｏｎｅ Ⅻ ① ½"))
```

本机真实输出：

```text
<p>【预售】iPhone 17 Pro 手机壳 &nbsp;限时 ５．５折！！！</p>
  -> 【预售】iphone 17 pro 手机壳  限时 5.5折!!!
客服　电话400-820-1234，邮箱 Service@Shop.COM ，微信：shop_vip   
  -> 客服 电话 <tel> ,邮箱 <email> ,微信:shop_vip
物流显示“已揽件”三天了还没动，ＷＣ！　再不发就投诉
  -> 物流显示“已揽件”三天了还没动,wc! 再不发就投诉
订单号202610110001，金额￥１，２３９.００元，地址：北京市海淀区中关村大街1号
  -> 订单号202610110001,金额¥1,239.00元,地址:北京市海淀区中关村大街1号
NFKC 逐字符示例: ５．５折 ＷＣ ｉＰｈｏｎｅ Ⅻ ① ½ -> 5.5折 WC iPhone XII 1 1⁄2
```

注意 `Ⅻ` 被 NFKC 变成 `XII`、`①` 变成 `1`、`½` 变成 `1⁄2`（带分数斜线）——这些「额外字符」要么在正则里处理掉，要么在词典里最先出现。表情与全角感叹号在本例中被规范化成 `!`，若业务需要保留情感强度，就应该在清洗阶段把它们映射成语义标记（`!!!` -> `<emph>`），而不是直接删。

```text
清洗与规范化要点：
1. 顺序固定：NFKC -> HTML 反转义 -> 去标签 -> 去零宽 -> 大小写 -> 掩码 -> 压空白
2. NFKC 会把全角字母数字、①、Ⅻ、½ 全部改写，正则必须写在归一化之后
3. 掩码用统一占位符（<tel>/<email>），不要删掉：占位符本身携带「这里有个联系方式」的信号
4. 数字、订单号、金额是最容易污染特征的噪声（IDF 高、区分度假），建议单独字段化
5. 清洗规则要有版本号：同一批数据用两版规则跑出来的指标不可比
```

## 中英文分词

中文没有词边界，分词质量直接决定后续一切。jieba 提供四种模式：**精确模式**（默认，适合文本分析）、**全模式**（扫出所有可能词，快但有歧义）、**搜索引擎模式**（在精确模式基础上对长词再切，提高召回）、**paddle 模式**（需额外装 paddlepaddle-tiny，本机未装）。生产上还必须加自定义词典，否则领域词（产品名、内部术语）会被切碎。英文侧则用正则切分并保留缩写与数字。

```python
import re
import jieba
import jieba.posseg as pseg

s = "小明硕士毕业于中国科学院计算所，后在日本京都大学深造"
print("精确模式  :", "/".join(jieba.cut(s, cut_all=False)))
print("全模式    :", "/".join(jieba.cut(s, cut_all=True)))
print("搜索引擎  :", "/".join(jieba.cut_for_search(s)))

domain = "客户反馈闪充宝二代充电宝发热，需要走售后退换流程"
print("加词前:", "/".join(jieba.lcut(domain)))
jieba.add_word("闪充宝", freq=200, tag="nz")   # 等价于用户词典里一行 "闪充宝 200 nz"
jieba.add_word("售后退换", freq=100)
print("加词后:", "/".join(jieba.lcut(domain)))

print(" ".join("%s/%s" % (w.word, w.flag) for w in pseg.cut("闪充宝 二代 发热 严重，请 尽快 退换 v2.1 Pro")))
print("英文正则切分:", re.findall(r"[A-Za-z]+(?:'[A-Za-z]+)?|\d+\.?\d*|[^\sA-Za-z\d]", "I've got 2 iPhone 17 Pro Max!"))
```

本机真实输出：

```text
精确模式  : 小明/硕士/毕业/于/中国科学院/计算所/，/后/在/日本京都大学/深造
全模式    : 小/明/硕士/毕业/于/中国/中国科学院/科学/科学院/学院/计算/计算所/，/后/在/日本/日本京都大学/京都/京都大学/大学/深造
搜索引擎  : 小明/硕士/毕业/于/中国/科学/学院/科学院/中国科学院/计算/计算所/，/后/在/日本/京都/大学/日本京都大学/深造
加词前: 客户/反馈/闪/充宝/二代/充电/宝/发热/，/需要/走/售后/退换/流程
加词后: 客户/反馈/闪充宝/二代/充电/宝/发热/，/需要/走/售后退换/流程
闪充宝/nz  /x 二代/t  /x 发热/v  /x 严重/a ，/x 请/v  /x 尽快/d  /x 退换/v  /x v2/eng .1/m  /x Pro/eng
英文正则切分: ["I've", 'got', '2', 'iPhone', '17', 'Pro', 'Max', '!']
```

`闪/充宝` 变成 `闪充宝`、`售后/退换` 变成 `售后退换`，就是这个加词动作在起作用。另外注意空格被切成了独立 token（`/x`），标点也是 token——流水线里必须显式过滤或统一处理，否则词表里会混进大量噪声符号。

```text
中英文分词要点：
1. 中文默认用精确模式；建倒排索引/搜索召回用搜索引擎模式；全模式只适合候选生成
2. 领域词必须进自定义词典（add_word 或 load_userdict），词典格式：词 词频 词性
3. jieba.add_word 的 freq 影响动态规划切分；不放心就用 suggest_freq(segment, tune=True) 调
4. 标点与空格会被切成 token，要么过滤要么当成特征，别放任它们进词表
5. 英文别只用 split()：缩写（I've）、数字（2、17）、连字符要一起考虑，正则或 tokenizer 库更稳
6. 词性标注用 ictclas 兼容标记（n/v/a/d 等），可按词性筛选特征（如只保留名词+动词）
```

## 停用词 词干化与词形还原

停用词是「高频但无区分度」的词，砍掉它们能显著缩小词表并压制噪声；词干化（stemming）用规则把屈折形式还原成词干，词形还原（lemmatization）用词典把词还原成原形。三者都服务于同一个目的：让同一个语义概念落到同一个特征上。但停用词表必须按领域定——中文里「不」「没」是极性反转的关键，绝不能当停用词删掉。

```python
import re
from collections import Counter
import jieba
from sklearn.feature_extraction.text import ENGLISH_STOP_WORDS
from nltk.stem import PorterStemmer, SnowballStemmer

corpus = [
    "这个手机壳的质量真的很好，用了两个月了还是很喜欢",
    "物流太慢了，都已经三天了还是没有发货，我很不满意",
    "客服的态度不错，但是我的问题还是没有得到解决",
    "电池续航很好，充电速度也很快，整体来说很满意",
    "包装破损了，里面的手机壳也刮花了，这个体验很差",
    "价格有点贵，不过质量确实不错，下次还会再买",
]
zh_stop = {"的", "了", "是", "我", "你", "在", "和", "就", "都", "也", "很", "还", "把", "被",
           "这个", "那个", "什么", "怎么", "一直", "已经", "一个", "我们", "但是", "不过",
           "而且", "真的", "确实", "有点", "还是", "得到", "来说", "里面", "下次", "还会", "再"}

def tok(text, stop=()):
    out = []
    for w in jieba.lcut(text):
        w = w.strip()
        if not w or re.fullmatch(r"[\W_]+", w) or w in stop:
            continue
        out.append(w)
    return out

print("全量词元 Top12:", Counter(w for t in corpus for w in tok(t)).most_common(12))
print("去停用词 Top12:", Counter(w for t in corpus for w in tok(t, zh_stop)).most_common(12))
print("词表规模 去停用词前/后: %d -> %d" % (
    len(set(w for t in corpus for w in tok(t))),
    len(set(w for t in corpus for w in tok(t, zh_stop)))))
print("英文内置停用词条数:", len(sorted(ENGLISH_STOP_WORDS)))
ps, ss = PorterStemmer(), SnowballStemmer("english")
for w in ["running", "studies", "relational", "arguing", "generously", "saw", "better"]:
    print("   %-12s Porter-> %-12s Snowball-> %s" % (w, ps.stem(w), ss.stem(w)))
```

本机真实输出：

```text

去停用词 Top12: [('手机', 2), ('壳', 2), ('质量', 2), ('好', 2), ('没有', 2), ('满意', 2), ('不错', 2), ('用', 1), ('两个', 1), ('月', 1), ('喜欢', 1), ('物流', 1)]
词表规模 去停用词前/后: 54 -> 34
英文内置停用词条数: 318
   running      Porter-> run          Snowball-> run
   studies      Porter-> studi        Snowball-> studi
   relational   Porter-> relat        Snowball-> relat
   arguing      Porter-> argu         Snowball-> argu
   generously   Porter-> gener        Snowball-> generous
   saw          Porter-> saw          Snowball-> saw
   better       Porter-> better       Snowball-> better
```

`了/很/的` 原本垄断 Top3，去停用词后前几名全是业务词（手机、壳、质量、好、满意）；`不错` 仍留在表里（本例的停用词表没把它收进去），说明停用词表是按业务判断的活文件，没有「标准答案」。词干化只对英文、且只对规则形态变化有效：`studies -> studi`（不是 `study`，因为它不懂词义）、`saw/better` 不变（不规则变化处理不了），词形还原才需要词典与词性。

```text
停用词 词干化与词形还原要点：
1. 停用词表必须领域自建；中文的「不/没/无」是否定词，删了就把情感反转信号丢了
2. 词表规模是最直观的收益指标：本例 54 -> 34，压缩特征空间也减轻过拟合
3. Porter/Snowball 是纯规则算法，输出不保证是真词；lemmatization 需要 WordNet 等词典资源
4. nltk 的算法模块（stemmer、bleu）离线可用，但 wordnet/stopwords 语料要 nltk.download() 联网
5. 英文停用词表用 sklearn 的 ENGLISH_STOP_WORDS（318 条）即可，无需联网
6. 别在中文上做「词干化」，中文的形态问题靠分词与同义词归一化解决
```

## 正则与规则处理

规则层不做「理解」，只做**抽取、掩码与过滤**，但它在工程里的性价比极高：订单号、金额、日期、联系方式这类结构化字段用正则抽取的准确率通常远高于模型。注意抽取与掩码要分开实现——掩码是写进日志/训练数据前的隐私动作，抽取是下游业务要的字段，混在一起会把数据要么脱敏过度要么泄露。

```python
import re

PATTERNS = {
    "order_id": re.compile(r"(?<!\d)(?:订单号|订单)[:：]?\s*(\d{8,20})"),
    "phone":    re.compile(r"(?<!\d)(1[3-9]\d{9})(?!\d)"),
    "amount":   re.compile(r"[¥￥]\s?(\d[\d,]*(?:\.\d{1,2})?)"),
    "date":     re.compile(r"(\d{4})[-/年](\d{1,2})[-/月](\d{1,2})日?"),
}
for t in ["订单号202610110001 金额￥1,239.00 已于2026-10-11 下单，客服电话13812345678",
          "2026年10月12日 下单，订单：202610120002，￥88.5，电话010-82012345"]:
    hit = {k: p.findall(t) for k, p in PATTERNS.items()}
    print("文本:", t)
    print("抽取:", {k: v for k, v in hit.items() if v})

MASK_RULES = [
    (re.compile(r"(?<!\d)(1[3-9]\d{9})(?!\d)"), lambda m: m.group(1)[:3] + "****" + m.group(1)[-4:]),
    (re.compile(r"[\w.+-]+@([\w-]+\.[\w.]+)"), lambda m: "***@" + m.group(1)),
    (re.compile(r"(?<!\d)(\d{17}[\dXx])(?!\d)"), lambda m: m.group(1)[:6] + "********" + m.group(1)[-4:]),
    (re.compile(r"(?<!\d)(\d{16,19})(?!\d)"), lambda m: m.group(1)[:4] + " **** **** " + m.group(1)[-4:]),
]
raw = "联系人张先生，手机13812345678，身份证110105199003074018，卡号6222021234567890123，邮箱 zhang@corp.com.cn"
masked = raw
for pat, fn in MASK_RULES:
    masked = pat.sub(fn, masked)
print("原文:", raw)
print("脱敏:", masked)
```

本机真实输出：

```text
文本: 订单号202610110001 金额￥1,239.00 已于2026-10-11 下单，客服电话13812345678
抽取: {'order_id': ['202610110001'], 'phone': ['13812345678'], 'amount': ['1,239.00'], 'date': [('2026', '10', '11')]}
文本: 2026年10月12日 下单，订单：202610120002，￥88.5，电话010-82012345
抽取: {'order_id': ['202610120002'], 'amount': ['88.5'], 'date': [('2026', '10', '12')]}
原文: 联系人张先生，手机13812345678，身份证110105199003074018，卡号6222021234567890123，邮箱 zhang@corp.com.cn
脱敏: 联系人张先生，手机138****5678，身份证110105********4018，卡号6222 **** **** 0123，邮箱 ***@corp.com.cn
```

`(?<!\d)` / `(?!\d)` 这类边界断言是必需的：没有它们，`13812345678` 里会匹配出「后 11 位」，长订单号会被切出子串。敏感词过滤则建议用 Trie（前缀树）：逐词 `in` 判断是 O(词表数 x 文本长度)，Trie 只跟文本长度有关。

```python
class Trie:
    def __init__(self, words):
        self.root = {}
        for w in words:
            node = self.root
            for ch in w:
                node = node.setdefault(ch, {})
            node["$"] = w
    def find(self, s):
        hits, i = [], 0
        while i < len(s):
            node, j, last = self.root, i, None
            while j < len(s) and s[j] in node:
                node = node[s[j]]
                j += 1
                if "$" in node:
                    last = (node["$"], i, j)
            if last:
                hits.append(last)
                i = last[2]
            else:
                i += 1
        return hits

trie = Trie(["诈骗", "退一赔三", "刷单", "代开发票", "加微信"])
for t in ["这个商家涉嫌诈骗，我要退一赔三", "有人加微信让我加微信刷单"]:
    print(t, "->", trie.find(t))
```

本机真实输出：

```text
这个商家涉嫌诈骗，我要退一赔三 -> [('诈骗', 6, 8), ('退一赔三', 11, 15)]
有人加微信让我加微信刷单 -> [('加微信', 2, 5), ('加微信', 7, 10), ('刷单', 10, 12)]
```

```text
正则与规则处理要点：
1. 抽取与脱敏分开实现：脱敏是数据治理动作，抽取是业务字段，混在一起两种需求都做不好
2. 数字类模式必须加边界断言 (?<!\d) / (?!\d)，否则会从长串里切出伪匹配
3. 敏感词过滤用 Trie，多模式匹配复杂度只跟文本长度相关；命中位置要一并记录
4. 规则字段（订单号、金额、时间）应结构化落库，从文本特征里剔除，避免假区分度
5. 正则表要单测：给一批正例反例，每次改动跑一遍，否则上线后静默漏匹配
```

## 数据增强

数据增强的适用条件是**样本极少 + 类别不均衡**，手段主要是 EDA 四件套：同义词替换（SR）、随机插入（RI）、随机交换（RS）、随机删除（RD）。它们的好处是不需要外部模型，坏处是可能改变标签语义——「质量很好」被随机删成「质量好」没事，被交换成「好质量很」就有噪声了。所以增强后的样本必须过一遍标签一致性检查。

```python
import random
import jieba

SYN = {"很好": ["不错", "挺好", "非常棒"], "太慢": ["超级慢", "特别慢", "慢死了"],
       "满意": ["认可", "称心"], "差": ["糟糕", "不行"], "发货": ["寄出", "发出"],
       "客服": ["售后", "客服人员"], "手机壳": ["保护壳", "机壳"], "质量": ["品质", "做工"]}
random.seed(7)

def eda(text, label, n=3):
    words = [w for w in jieba.lcut(text) if w.strip()]
    out = []
    for _ in range(n):
        ws, op = words[:], random.choice(["syn", "swap", "delete", "insert"])
        if op == "syn":
            idx = [i for i, w in enumerate(ws) if w in SYN]
            if idx:
                i = random.choice(idx)
                ws[i] = random.choice(SYN[ws[i]])
        elif op == "swap" and len(ws) > 1:
            i, j = random.sample(range(len(ws)), 2)
            ws[i], ws[j] = ws[j], ws[i]
        elif op == "delete" and len(ws) > 3:
            ws.pop(random.randrange(len(ws)))
        elif op == "insert":
            ws.insert(random.randrange(len(ws) + 1), random.choice(["真的", "感觉", "反正", "说实话"]))
        out.append((op, "".join(ws), label))
    return out

for op, s, y in eda("这个手机壳质量很好，物流太慢了，客服态度也不满意", 1, n=4):
    print("  %-7s %s  (label=%d)" % (op, s, y))
```

本机真实输出：

```text
  delete  这个手机壳质量好，物流太慢了，客服态度也不满意  (label=1)
  insert  这个真的手机壳质量很好，物流太慢了，客服态度也不满意  (label=1)
  syn     这个手机壳质量很好，物流太慢了，售后态度也不满意  (label=1)
  swap    这个满意壳质量很好，物流太慢了，客服态度也不手机  (label=1)
```

最后一条 `swap` 把「壳」和「手机」交换、把「满意」搬到前面，语句已经不通但仍带着原标签——这就是 EDA 的典型副作用。上线前必须用验证集确认增强是否真的有收益（见「应用场景实战」场景二的实测结果：本机粗糙同义词表反而掉点）。

```text
数据增强要点：
1. 只在小样本/不均衡时用；样本充足时标更多真实数据永远更有效
2. 四件套里同义替换最安全、随机交换最危险（会破坏语序语义），删除要限制比例
3. 增强后必须保留标签并抽样人工检查，语言不通的样本会教模型学噪声
4. 同义词表是核心资产，要域内自建（通用词表会把「贵」换成「昂贵」这种不口语的词）
5. 更强的方案是回译（中->英->中）与大模型改写，但要控成本并做一致性过滤
6. 增强倍数不是越大越好；每次增强都必须在固定验证集上验证收益
```

## 统一预处理流水线

散落的清洗函数最后都会变成「每人一份」，所以要把清洗 + 分词 + 停用词/词性过滤 + 缓存封成一个类：对外只暴露 `transform(texts)`，内部用 `lru_cache` 缓存分词结果（批量推理时同一句会被反复处理）。同时把词典与停用词作为构造参数传入，保证「同一条流水线实例 = 同一套口径」，可序列化、可随模型一起发布。

```python
import re, time, functools
import jieba

class ChineseTextPipeline:
    PUNCT = re.compile(r"[\s\W_]+", re.UNICODE)
    def __init__(self, stopwords=(), userdict=None):
        self.stop = set(stopwords)
        for w, f in (userdict or {}).items():
            jieba.add_word(w, freq=f)
        self._cut = functools.lru_cache(maxsize=100000)(self._cut_impl)
    def _cut_impl(self, text):
        out = []
        for w in jieba.lcut(text):
            w = w.strip().lower()
            if not w or self.PUNCT.fullmatch(w) or w in self.stop:
                continue
            out.append(w)
        return tuple(out)
    def transform(self, texts):
        return [list(self._cut(t)) for t in texts]

STOP = {"的", "了", "是", "我", "在", "很", "也", "都", "就", "还", "把", "被", "请", "这个", "真的"}
pipe = ChineseTextPipeline(stopwords=STOP, userdict={"闪充宝": 200})
docs = ["闪充宝二代充电异常，客服一直不回复，很失望",
        "这个手机壳的做工很好，我是真的满意，会回购",
        "物流太慢了，都三天了还没有揽件，很失望"]
t0 = time.perf_counter(); res = pipe.transform(docs); t1 = time.perf_counter()
for d, r in zip(docs, res):
    print("原始:", d)
    print("处理:", r)
print("3 篇耗时 %.6f s（首次含 jieba 词典加载）" % (t1 - t0))
t0 = time.perf_counter(); pipe.transform(docs * 100); t1 = time.perf_counter()
print("300 篇（297 篇命中缓存）耗时 %.6f s" % (t1 - t0))
print("缓存信息:", pipe._cut.cache_info())
```

本机真实输出：

```text
原始: 闪充宝二代充电异常，客服一直不回复，很失望
处理: ['闪充宝', '二代', '充电', '异常', '客服', '一直', '不', '回复', '失望']
原始: 这个手机壳的做工很好，我是真的满意，会回购
处理: ['手机', '壳', '做工', '好', '满意', '会', '回购']
原始: 物流太慢了，都三天了还没有揽件，很失望
处理: ['物流', '太慢', '三天', '没有', '揽件', '失望']
3 篇耗时 0.000538 s（首次含 jieba 词典加载）
300 篇（其中 297 篇命中缓存）耗时 0.000157 s
缓存信息: CacheInfo(hits=300, misses=3, maxsize=100000, currsize=3)
```

注意 `不` 被保留了下来（不在停用词表里），这是刻意的：否定词是情感任务的关键信号。另外「太慢」被 jieba 当作一个词——这既是好事（极性词整体保留），也提醒我们停用词表要按**分词后的 token** 来写，写「慢」是删不掉「太慢」的。

```text
统一预处理流水线要点：
1. 流水线对外只暴露 transform(texts)，内部实现可替换（jieba -> 其他分词器）
2. 词典与停用词作为构造参数注入，保证口径可复现、可随模型版本一起发布
3. 分词结果用 lru_cache 缓存，批量推理同句重复时收益巨大（本例 300 篇 0.16ms）
4. 停用词表按 token 粒度维护（「太慢」不会因为写了「慢」而被过滤）
5. 缓存不要无限增长：maxsize 要设上限，否则线上长跑会内存泄漏
6. 流水线要能导出配置（词典版本、停用词 hash、正则版本），写进模型元数据
```

## 应用场景实战

### 场景一：电商评论入库前的清洗、分词与特征化

真实链路是：原始文本 -> 清洗规范化 -> PII 脱敏 -> 分词去停用词 -> 质量统计 -> 向量化落库。质量统计（词表规模、长度分布、脱敏命中数）必须落盘，它是数据漂移监控的第一道指标。下面这段在本机真实跑通。

```python
import re, html, unicodedata, time
from collections import Counter
import numpy as np
import jieba
from sklearn.feature_extraction.text import TfidfVectorizer

RAW = [
    "<p>质量很好&nbsp;物流也快！！！</p>",
    "客服　态度差，ＷＣ！ 我要投诉",
    "买了两件，做工还行吧，就是有点贵……客服电话010-82012345",
    "联系我 13812345678 或者 zhang@corp.com.cn，帮我改地址",
]
PUNCT = re.compile(r"[\W_]+", re.UNICODE)
CTRL = re.compile(r"[\u0000-\u001f\u007f\u200b-\u200f\ufeff]")
HTML_TAG = re.compile(r"<[^>]+>")
MASKS = [("phone", re.compile(r"(?<!\d)(1[3-9]\d{9})(?!\d)"),
          lambda m: m.group(1)[:3] + "****" + m.group(1)[-4:]),
         ("email", re.compile(r"[\w.+-]+@([\w-]+\.[\w.]+)"), lambda m: "***@" + m.group(1)),
         ("tel", re.compile(r"(?<!\d)(?:\d{3,4}-\d{7,8}|\d{3,4}-\d{3,4}-\d{4})(?!\d)"),
          lambda m: "<tel>")]

def pipeline(text):
    hits = []
    s = HTML_TAG.sub(" ", html.unescape(unicodedata.normalize("NFKC", text))).lower()
    s = CTRL.sub("", s)
    for name, pat, fn in MASKS:
        if pat.search(s):
            hits.append(name)
            s = pat.sub(fn, s)
    return re.sub(r"[ \t\u3000]+", " ", s).strip(), hits

STOP = {"的", "了", "是", "我", "也", "就", "都", "还", "把", "被", "请", "这个", "那个"}
def tokenize(s):
    return [w for w in jieba.lcut(s) if w.strip() and not PUNCT.fullmatch(w) and w not in STOP]

cleaned, tokens, hits = [], [], []
for t in RAW:
    c, h = pipeline(t)
    cleaned.append(c); tokens.append(tokenize(c)); hits.extend(h)
print("脱敏命中:", dict(Counter(hits)))
for c, tk in zip(cleaned, tokens):
    print("%-42s %s" % (c[:40], tk))
print("词表规模 %d | 平均词元数 %.1f | 最长 %d" % (
    len(set(w for tk in tokens for w in tk)), np.mean([len(tk) for tk in tokens]), max(len(tk) for tk in tokens)))

v = TfidfVectorizer(tokenizer=tokenize, token_pattern=None, lowercase=False).fit(cleaned)
idf = dict(zip(v.get_feature_names_out(), v.idf_))
print("TF-IDF 维度:", v.transform(cleaned).shape,
      "| IDF 最高的词:", [(w, round(idf[w], 3)) for w in sorted(idf, key=lambda k: -idf[k])[:5]])
t0 = time.perf_counter()
for _ in range(200):
    [tokenize(t) for t in cleaned]
el = time.perf_counter() - t0
print("分词吞吐: %.1f 条/秒（单进程，%.2f ms/条）" % (200 * len(cleaned) / el, 1000 * el / (200 * len(cleaned))))
```

本机真实输出：

```text
脱敏命中: {'tel': 1, 'phone': 1, 'email': 1}
质量很好 物流也快!!!                               ['质量', '很', '好', '物流', '快']
客服 态度差,wc! 我要投诉                            ['客服', '态度', '差', 'wc', '我要', '投诉']
买了两件,做工还行吧,就是有点贵......客服电话<tel>            ['买', '两件', '做工', '还行', '吧', '就是', '有点', '贵', '客服', '电话', 'tel']
联系我 138****5678 或者 ***@corp.com.cn,帮我改地址   ['联系', '138', '5678', '或者', 'corp', 'com', 'cn', '帮', '改', '地址']
词表规模 31 | 平均词元数 8.0 | 最长 11
TF-IDF 维度: (4, 31) | IDF 最高的词: [('138', 1.916), ('5678', 1.916), ('cn', 1.916), ('com', 1.916), ('corp', 1.916)]
分词吞吐: 5985.6 条/秒（单进程，0.17 ms/条）
```

这份输出暴露了两个真问题：掩码后的号码与邮箱域名被 jieba 切成 `138 / 5678 / corp / com / cn`，全都进了词表并拿到最高 IDF（1.916）——**掩码占位符必须整体作为 token 处理**（或直接丢弃数字与英文域名 token）；`wc`、`!!!` 这类噪声也在词表里，需要停用词表或黑名单兜住。

```text
场景一要点：
1. 掩码占位符（<tel>/<email>）要整体成一个 token，否则号码会被切碎污染特征
2. 数字与英文域名是 IDF 假高发区，必须归一化或进黑名单
3. 质量统计（词表规模、长度分布、脱敏命中数）要落盘，作为数据漂移的第一道监控
4. 分词吞吐约 6000 条/秒是 CPU 单进程基准（首次含 jieba 词典加载），批量任务据此估算分片数
```

### 场景二：每类只有 15 条时，数据增强到底有没有用

小样本场景最容易迷信增强。下面把同一份中文评论数据切成「每类 15 条」的训练集，比较原始、EDA x2、EDA x4 在全量测试集上的表现——这是唯一能证明增强是否有效的方式。

```python
import csv, random
from sklearn.pipeline import Pipeline
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import f1_score, accuracy_score

rows = {"train": [], "test": []}
with open("/root/.hermes/cache/scratch/nlp164_data.csv", encoding="utf-8") as f:
    for r in csv.DictReader(f):
        if r["split"] in rows:
            rows[r["split"]].append((r["tokenized"], int(r["label"])))
Xte = [t for t, _ in rows["test"]]; yte = [y for _, y in rows["test"]]

SYN = {"很好": ["不错", "挺好"], "太慢": ["超级慢", "慢死了"], "满意": ["认可", "称心"],
       "破损": ["坏了", "烂了"], "贵": ["偏贵", "花得多"], "及时": ["很快", "麻利"],
       "耐心": ["热心", "细致"], "做工": ["工艺", "用料"], "退款": ["退钱", "回款"],
       "优惠": ["折扣", "促销"], "客服": ["售后", "客服人员"], "质量": ["品质", "做工"]}
random.seed(3)

def eda(tokens, label, n):
    out = []
    for _ in range(n):
        ws, op = tokens[:], random.choice(["syn", "swap", "delete", "insert"])
        if op == "syn":
            cand = [i for i, w in enumerate(ws) if w in SYN]
            if cand:
                i = random.choice(cand)
                ws[i] = random.choice(SYN[ws[i]])
        elif op == "swap" and len(ws) > 2:
            i, j = random.sample(range(len(ws)), 2)
            ws[i], ws[j] = ws[j], ws[i]
        elif op == "delete" and len(ws) > 4:
            ws.pop(random.randrange(len(ws)))
        elif op == "insert":
            ws.insert(random.randrange(len(ws) + 1), random.choice(["真的", "感觉", "反正"]))
        out.append((" ".join(ws), label))
    return out

by = {0: [], 1: [], 2: []}
for t, y in rows["train"]:
    by[y].append(t)
Xs, ys = [], []
for k in (0, 1, 2):
    Xs += by[k][:15]; ys += [k] * 15
print("小样本训练集: %d 条（每类 15）" % len(Xs))

def run(tag, Xtr, ytr):
    pipe = Pipeline([("v", TfidfVectorizer(tokenizer=str.split, token_pattern=None,
                                           lowercase=False, ngram_range=(1, 2))),
                     ("m", LogisticRegression(max_iter=1000, C=4.0))]).fit(Xtr, ytr)
    pred = pipe.predict(Xte)
    print("%-16s 训练 %4d 条 -> 测试 acc=%.4f macroF1=%.4f"
          % (tag, len(Xtr), accuracy_score(yte, pred), f1_score(yte, pred, average="macro")))

run("原始小样本", Xs, ys)
for mult in (2, 4):
    Xa, ya = list(Xs), list(ys)
    for t, y in zip(Xs, ys):
        for s, l in eda(t.split(), y, mult):
            Xa.append(s); ya.append(l)
    run("EDA 增强 x%d" % mult, Xa, ya)
run("全量训练集(参照)", [t for t, _ in rows["train"]], [y for _, y in rows["train"]])
```

本机真实输出：

```text
小样本训练集: 45 条（每类 15）
原始小样本            训练   45 条 -> 测试 acc=0.6500 macroF1=0.6523
EDA 增强 x2        训练  135 条 -> 测试 acc=0.6333 macroF1=0.6372
EDA 增强 x4        训练  225 条 -> 测试 acc=0.6333 macroF1=0.6275
全量训练集(参照)        训练 1020 条 -> 测试 acc=0.7700 macroF1=0.7655
```

结论和教程相反：粗糙同义词表的 EDA 在这个测试集上反而掉点（0.6523 -> 0.6372 -> 0.6275），因为替换词（"不错/挺好"）与测试集实际用词（"挺给力/很值"）不一致，等于把训练集往另一个方向推。真正的收益来自把训练集从 45 条加到 1020 条（0.6523 -> 0.7655）。

```text
场景二要点：
1. 增强不是免费的：必须用固定测试集量化收益，掉点就果断放弃
2. 同义词表质量决定增强上限；用通用词表会把训练集风格带偏
3. 标注数据的边际收益远高于增强：45 -> 1020 条带来 +0.11 macroF1
4. 增强后样本量涨到 5 倍但词表几乎没变，说明增强主要是在重复已有模式
```

## 最佳实践与踩坑记录

最佳实践：

1. 清洗顺序固定成模板（NFKC -> 反转义 -> 去标签 -> 去零宽 -> 大小写 -> 掩码 -> 压空白），并用一组「脏数据 -> 期望输出」的测试用例守住它。
2. 把分词器、词典、停用词表当作**版本化资产**：文件入库、算 hash、随模型元数据一起发布，保证线上与训练口径一致。
3. 领域词典优先：项目开工第一件事是把产品名、业务术语、渠道名灌进 jieba 用户词典，收益通常比换模型大。
4. 清洗与脱敏分两个阶段做，脱敏在日志/训练集落地前统一执行，并记录命中统计用于审计。
5. 停用词表最小化：只删高频无信息词，保留否定词与程度副词（不、没、无、很、太、非常）。
6. 预处理统计指标（词表规模、长度分位、OOV 率、脱敏命中数）进监控看板，数据漂移先于模型退化出现。

坑 1：把 lambda 当 tokenizer 传给 sklearn，模型存不下来。

结论：`Pipeline` 训练完 `pickle.dumps` 直接报 `PicklingError: Can't pickle <function <lambda>>: it's not found as __main__.<lambda>`，模型无法交付。
原因：标准 pickle 按「模块名 + 函数名」定位对象，匿名函数没有可导入的名字；只有 cloudpickle/dill 这类序列化器才支持。
解法：tokenizer 写成模块级函数或自定义类，并给它配单元测试；保存模型时用 `joblib.dump`（joblib 内部仍走 pickle，所以根因还是在函数可导入性上），交付前做一次「存盘 -> 回读 -> 预测一致」的自检。

坑 2：清洗顺序错了，正则全部失效。

结论：全角输入（`５．５`、`￥１，２３９.００`）会让金额正则匹配不到，也会让「订单号」规则漏掉。
原因：全角字符是**不同码点**，正则里的半角 `\d`、`\.`、`,` 都匹配不上；只有在 NFKC 归一化之后它们才变成半角。
解法：把 `unicodedata.normalize("NFKC", s)` 放在所有正则之前，并在测试用例里放全角样本。本机实测 NFKC 会把 `Ⅻ -> XII`、`① -> 1`、`½ -> 1⁄2`，这些额外改写也要有预期。

坑 3：停用词表里放了否定词，情感模型直接崩。

结论：把「不」「没」「无」加进停用词后，「不满意」与「满意」在特征层完全同形，模型只能靠猜。
原因：中文里极性反转靠否定词与程度副词实现，它们虽然高频，但信息量极高，属于「高频且强区分度」。
解法：停用词表只放语气助词与虚词（的/了/啊/吧/呢），把否定词、程度副词当特征保留；若必须处理「不满意」，应做否定域标记（把「不 + 词」合成一个 token），而不是删除。

坑 4：掩码后不处理占位符，号码碎片变成最强特征。

结论：本机实测 `138****5678`、`***@corp.com.cn` 被 jieba 切成 `138 / 5678 / corp / com / cn`，这些碎片拿到了全表最高的 IDF（1.916），成了假区分度特征。
原因：掩码只改了内容形态，没改变分词与词表逻辑；数字与域名仍是独立 token，且因为分布稀疏而 IDF 很高。
解法：掩码时使用不可切分的整体占位符（如 `<tel>`、`<email>`），并在清洗后加一层 token 过滤（纯数字、纯 ASCII 域名、长度 < 2 的碎片统一丢弃或替换成 `<num>`）。

## 概述

「规则」决定模型在项目里的行为边界，「上下文」决定模型每一轮到底看得见什么。OpenCode 对这两件事各给了一套机制：规则用 `AGENTS.md` 加 `instructions` 配置注入系统提示，上下文用 compaction、snapshot、watcher 与权限规则来管住「装什么、丢什么、不让碰什么」。本主题把这几块串起来：规则文件放哪、配置优先级怎么算、上下文何时压缩、哪些文件与数据被排除在外。

```text
本节要点：
1. 规则入口 —— 项目根 AGENTS.md（推荐提交 Git）与全局 ~/.config/opencode/AGENTS.md
2. 规则优先级 —— 从当前目录向上找 AGENTS.md/CLAUDE.md；全局 AGENTS.md 先于 ~/.claude/CLAUDE.md
3. 配置优先级 —— 远程 < 全局 < OPENCODE_CONFIG < 项目 < .opencode 目录 < 内联 < 管理端强制
4. 上下文压缩 —— compaction.auto/prune/reserved 三个参数，配合 /compact 手动压缩
5. 忽略与隐私 —— watcher.ignore 排除监听目录、share 控制分享、permission 默认拒读 .env
6. 环境注入 —— 工作目录、平台、日期与 AGENTS.md 内容会一起进入系统提示（可实测验证）
```

## AGENTS.md 规则与加载顺序

`AGENTS.md` 是 OpenCode 的项目级说明书，作用类似 Cursor 的 rules：里面的内容会被注入 LLM 上下文，用来约束这个项目的做法。推荐用 `/init` 生成，它扫描仓库关键文件（必要时反问几个问题），产出聚焦「未来会话最需要的东西」——构建、lint、测试命令，命令执行顺序与验证步骤，不那么直观的目录结构，项目约定与踩坑点。已有文件时 `/init` 是原地改进而不是覆盖。

```text
# 订单服务（order-service）

这是基于 Go 1.22 的订单服务，使用 PostgreSQL 与 Kafka。
（下面用纯文本标注小节，真实文件里用 Markdown 标题书写）

【项目结构】

- `cmd/` 各服务入口
- `internal/` 领域逻辑，禁止跨包直接访问其他领域的 repository
- `migrations/` 数据库迁移，只允许追加，禁止修改已上线文件

【命令】

- 构建：`make build`
- 测试：`make test`（必须带 -race）
- 格式与静态检查：`make lint`

【约定】

- 错误一律用 `fmt.Errorf("...: %w", err)` 包装，禁止忽略 error
- 新增对外接口必须在 `api/openapi.yaml` 同步声明
- 任何涉及金额的改动必须同时补测试
```

规则文件的加载分三类，且有明确的优先级：

```text
加载顺序（官方文档）：
1. 本地文件 —— 从当前目录向上逐级查找 AGENTS.md、CLAUDE.md
2. 全局文件 —— ~/.config/opencode/AGENTS.md
3. Claude Code 文件 —— ~/.claude/CLAUDE.md（未禁用时）

每类里第一个命中的文件生效：同名目录下 AGENTS.md 优先于 CLAUDE.md；
~/.config/opencode/AGENTS.md 优先于 ~/.claude/CLAUDE.md。
```

从 Claude Code 迁移的用户不必重写规则，OpenCode 把 Claude Code 的文件约定作为后备：项目级 `CLAUDE.md`、全局 `~/.claude/CLAUDE.md`、技能目录 `~/.claude/skills/`。不想要这套兼容时可以用环境变量关掉：

```bash
export OPENCODE_DISABLE_CLAUDE_CODE=1         # 关闭全部 .claude 支持
export OPENCODE_DISABLE_CLAUDE_CODE_PROMPT=1  # 只关闭 ~/.claude/CLAUDE.md
export OPENCODE_DISABLE_CLAUDE_CODE_SKILLS=1  # 只关闭 .claude/skills 加载
```

规则到底有没有被注入，不用猜——把它说出来再抓请求即可。本机用一个本地模拟端点抓到了真实请求体：

```text
# 项目根放一份 AGENTS.md，内容含标记 PROJECT-RULE-MARKER-9F2A
$ opencode run -m mocklocal/mock-gpt "hi again"
> build · mock-gpt

pong from mock model

# 抓包（服务端侧保存的请求体）中 system 消息的关键片段：
You are powered by the model named mock-gpt. The exact model ID is mocklocal/mock-gpt
Here is some useful information about the environment you are running in:
<env>
  Working directory: /root/.hermes/cache/scratch/oc-test
  Workspace root folder: /
  Is directory a git repo: no
  Platform: linux
  Today's date: Thu Oct 15 2026
</env>
Instructions from: /root/.hermes/cache/scratch/oc-test/AGENTS.md
# 演示项目规则

PROJECT-RULE-MARKER-9F2A: 所有回答必须以中文给出，并且在结尾附上文件清单。
```

这段输出说明三件事：规则以 `Instructions from: <绝对路径>` 的形式拼进系统提示；工作目录、是否 Git 仓库、平台与日期会一并注入；规则是「自动生效」的，不需要在每条消息里重复粘贴。

```text
AGENTS.md 要点：
1. 生成方式 —— /init 扫描仓库产出，已有文件时原地改进；建议提交进 Git 团队共享
2. 项目级 —— 项目根 AGENTS.md 只在该目录及其子目录生效
3. 全局级 —— ~/.config/opencode/AGENTS.md 对所有会话生效，适合放个人偏好（不进 Git）
4. 查找顺序 —— 从当前目录向上找本地规则；全局规则独立于项目规则一起注入
5. 兼容 Claude Code —— CLAUDE.md 与 ~/.claude/skills 作为后备，可用 OPENCODE_DISABLE_CLAUDE_CODE 关闭
6. 验证手段 —— 抓一次请求看 system 消息里的 Instructions from 与 <env> 块
```

## instructions 与外部规则文件

团队往往已经有既有的规范文件（`CONTRIBUTING.md`、`.cursor/rules/*.md`、内部规范仓库），没必要全部复制进 `AGENTS.md`。配置项 `instructions` 接受路径与 glob 数组，把这些文件合并进上下文；也支持直接给远程 URL（拉取超时 5 秒）。所有 `instructions` 内容会与 `AGENTS.md` 一起拼接。

```json
{
  "$schema": "https://opencode.ai/config.json",
  "instructions": [
    "CONTRIBUTING.md",
    "docs/guidelines.md",
    ".cursor/rules/*.md",
    "packages/*/AGENTS.md",
    "https://raw.githubusercontent.com/my-org/shared-rules/main/style.md"
  ]
}
```

注意一个常见误解：OpenCode **不会**自动解析 `AGENTS.md` 里的文件引用。想让模型按需加载外部文件，有两种做法：首选在 `instructions` 里用 glob 声明；其次在 `AGENTS.md` 里明确写清「遇到引用要用 Read 工具按需加载」的指令。

```text
# TypeScript 项目规则（示例，真实文件用 Markdown 标题分节）

【外部文件加载】

重要：遇到文件引用（例如 @rules/general.md）时，用 Read 工具按需加载，它们只与当前任务相关。

- 不要预先加载所有引用，按实际需要惰性加载
- 加载后视作强制规则，其内容优先于默认行为
- 需要时递归跟随引用

【开发规范】

TypeScript 代码风格：@docs/typescript-guidelines.md
React 组件与 hooks 模式：@docs/react-patterns.md
REST 接口设计与错误处理：@docs/api-standards.md
测试策略与覆盖率要求：@test/testing-guidelines.md
```

monorepo 场景下，`instructions` 配 glob（如 `packages/*/AGENTS.md`）比在 `AGENTS.md` 里手工列引用更可维护。

```text
instructions 要点：
1. 用途 —— 复用既有的规范文件（CONTRIBUTING、.cursor/rules）而不重复维护
2. 写法 —— 数组元素可为相对路径、绝对路径、glob 模式或 https URL
3. 合并语义 —— instructions 的文件与 AGENTS.md 一起注入，不是二选一
4. 远程加载 —— 远程 URL 有 5 秒超时，内网可用但要注意代理与可达性
5. 引用不自动解析 —— AGENTS.md 里的 @ 引用需要显式写「用 Read 工具按需加载」的指令
6. monorepo 建议 —— 用 packages/*/AGENTS.md 一类 glob 覆盖各子包规则
```

## 配置文件的位置与优先级

OpenCode 用 JSON/JSONC 配置，配置文件之间是**合并**关系而非替换：后来者只覆盖冲突的键，其余设置全部保留。理解优先级是排查「我改了配置怎么不生效」的前提。全局配置放用户级偏好，项目级 `opencode.json` 放团队约定（可提交 Git），`OPENCODE_CONFIG`/`OPENCODE_CONFIG_CONTENT` 用于临时覆盖，管理端配置用于企业强制策略。

```text
优先级（后者覆盖前者，官方文档顺序）：
1. 远程配置           来自 .well-known/opencode（组织默认值）
2. 全局配置           ~/.config/opencode/opencode.json
3. 自定义配置         OPENCODE_CONFIG 环境变量指定的文件
4. 项目配置           项目里的 opencode.json
5. .opencode 目录     agents/、commands/、plugins/ 等
6. 内联配置           OPENCODE_CONFIG_CONTENT 环境变量
7. 管理端配置         Linux 为 /etc/opencode/（需 root 写入）
8. macOS 托管偏好     通过 MDM 下发的 .mobileconfig，不可被用户覆盖
```

```jsonc
// 全局 ~/.config/opencode/opencode.json：个人偏好
{
  "$schema": "https://opencode.ai/config.json",
  "model": "anthropic/claude-sonnet-4-5",
  "autoupdate": true
}
```

```jsonc
// 项目 ./opencode.json：团队约定，可提交 Git
{
  "$schema": "https://opencode.ai/config.json",
  "model": "corp-gw/claude-sonnet-4-5",
  "share": "disabled",
  "instructions": ["CONTRIBUTING.md", ".cursor/rules/*.md"]
}
```

```bash
# 自定义配置文件路径（优先级介于全局与项目之间）
export OPENCODE_CONFIG=/path/to/my/custom-config.json

# 自定义配置目录（结构与 .opencode 相同，加载在全局与 .opencode 之后，可覆盖它们）
export OPENCODE_CONFIG_DIR=/path/to/my/config-directory

# 内联 JSON 运行时覆盖（脚本、CI 里最方便）
export OPENCODE_CONFIG_CONTENT='{"model":"anthropic/claude-haiku-4-5","autoupdate":false}'
```

本机实测：内联配置确实覆盖了项目配置里的同名键（项目配置里 `model` 不变，`username` 被内联值改写）：

```text
$ cd oc-test && OPENCODE_CONFIG_CONTENT='{"username":"inline-user","snapshot":false}' opencode debug config
{
  ...
  "model": "mocklocal/mock-gpt",
  "share": "disabled",
  "autoupdate": false,
  "agent": {},
  "mode": {},
  "plugin": [],
  "command": {},
  "username": "inline-user",
  "snapshot": false
}
```

配置里还支持变量替换，避免把密钥与长文本硬编码：`{env:VAR}` 取环境变量（变量不存在则替换为空串），`{file:path}` 取文件内容（路径可相对配置文件目录，或以 `/`、`~` 开头）。

```json
{
  "$schema": "https://opencode.ai/config.json",
  "model": "{env:OPENCODE_MODEL}",
  "instructions": ["./custom-instructions.md"],
  "provider": {
    "openai": {
      "options": { "apiKey": "{file:~/.secrets/openai-key}" }
    }
  }
}
```

```text
配置位置与优先级要点：
1. 合并而非替换 —— 各来源只覆盖冲突键，非冲突设置都保留
2. 两层分工 —— 全局放个人偏好（模型、自动更新），项目放团队约定（模型、share、instructions）
3. 临时覆盖 —— OPENCODE_CONFIG 指定文件、OPENCODE_CONFIG_CONTENT 内联 JSON
4. TUI 配置独立 —— TUI 相关设置放 tui.json（全局或项目），旧版写在 opencode.json 的 theme/keybinds/tui 键已废弃
5. 企业强制 —— Linux 用 /etc/opencode/，macOS 走 MDM 托管偏好，优先级最高且用户不可覆盖
6. 变量替换 —— {env:VAR} 与 {file:path}，适合密钥与长指令文件
```

## 上下文压缩与 token 控制

长会话必然撞上上下文窗口。OpenCode 的策略是把历史压成摘要（compaction），并在需要时裁剪旧工具输出（prune）。`auto` 控制是否在上下文将满时自动压缩，`prune` 控制是否删除旧工具输出以省 token，`reserved` 是为压缩过程预留的 token 缓冲，避免压缩本身把窗口撑爆。

```json
{
  "$schema": "https://opencode.ai/config.json",
  "compaction": {
    "auto": true,
    "prune": false,
    "reserved": 10000
  }
}
```

```bash
# 完全关闭自动压缩（长会话会更快撞窗口，一般只在调参时用）
export OPENCODE_DISABLE_AUTOCOMPACT=1

# TUI 内手动压缩（键 ctrl+x c），想精确控制时机时用它
/compact
# 别名
/summarize
```

几个与「省 token」直接相关的配套设置：

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  // 轻量任务（标题生成等）用便宜的小模型
  "small_model": "anthropic/claude-haiku-4-5",
  // 图片附件超过阈值自动缩放，避免一次拖入就把窗口吃掉
  "attachment": {
    "image": { "auto_resize": true, "max_width": 2000, "max_height": 2000, "max_base64_bytes": 5242880 }
  },
  // 快照用于 /undo 与回滚，超大仓库可关（关掉即失去 UI 回滚能力）
  "snapshot": true,
  // 子代理嵌套深度，默认 1：主 agent 可开子代理，子代理不能再开
  "subagent_depth": 1
}
```

排查与观察压缩是否发生时，最直接的手段是看会话的 token 统计，以及把日志级别调到 DEBUG：

```bash
# 按会话看输入/输出 token 与费用（可 --days 限定时间窗）
opencode stats --days 1

# 需要详细过程日志时
opencode --log-level DEBUG --print-logs
```

```text
上下文压缩要点：
1. 三个参数 —— auto（自动压缩，默认 true）、prune（裁剪旧工具输出，默认 false）、reserved（压缩缓冲）
2. 手动压缩 —— /compact（别名 /summarize，键 ctrl+x c），比等自动触发更可控
3. 关闭开关 —— OPENCODE_DISABLE_AUTOCOMPACT=1 关闭自动压缩，仅建议调参时用
4. 成本控制 —— small_model 承担标题生成一类轻量任务；图片走 attachment.image 自动缩放
5. 快照取舍 —— snapshot 支撑 /undo 回滚，超大仓库才考虑关；关掉会失去 UI 侧回滚
6. 观测手段 —— opencode stats 看 token 与费用，--log-level DEBUG 看过程
```

## 忽略文件与隐私设置

「忽略」在 OpenCode 里有两类：一类是不让文件监听器去扫的目录（`watcher.ignore`），另一类是不让模型读到或写到的地方（permission 规则与 `external_directory`）。这两类管住的是「上下文里不该出现什么」和「agent 不该碰什么」。隐私方面还有分享开关与脱敏导出。

```json
{
  "$schema": "https://opencode.ai/config.json",
  "watcher": {
    "ignore": ["**/generated/**", "**/logs/**", "**/.next/**"]
  },
  "share": "disabled"
}
```

`watcher.ignore` 只影响文件监听（哪些改动会被感知），依赖目录、版本控制目录、构建与缓存目录在任意深度已被自动忽略。真正决定模型能不能读某个文件的是权限系统：默认偏宽松，但 `read` 有一条重要例外——`.env` 类文件默认被拒读。

```json
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "read": {
      "*": "allow",
      "*.env": "deny",
      "*.env.*": "deny",
      "*.env.example": "allow"
    },
    "edit": {
      "*": "deny",
      "packages/web/src/content/docs/*.mdx": "allow"
    },
    "bash": {
      "*": "ask",
      "git *": "allow",
      "rm *": "deny"
    },
    "external_directory": {
      "~/projects/personal/**": "allow"
    }
  }
}
```

规则要点：模式匹配用简单通配符（`*` 匹配任意多字符，`?` 匹配单字符，其余字面匹配），**最后一条匹配的规则生效**，所以常见写法是把兜底的 `"*"` 放前面、具体规则放后面。默认值方面：多数权限为 `allow`，`doom_loop`（同一工具以相同输入重复 3 次）与 `external_directory`（工具触碰工作目录之外的路径）默认 `ask`。

隐私与数据侧还有几点需要显式配置：

```text
1. 分享开关 —— share: "manual"|"auto"|"disabled"；敏感项目在项目配置里固定 disabled 并提交 Git
2. 脱敏导出 —— opencode export --sanitize 会脱敏转写与文件内容
3. 工作目录边界 —— 默认只允许操作启动目录，越界需通过 permission.external_directory 显式放行
4. 密钥入口 —— 配置里用 {env:VAR}/{file:path}，不要把 Key 写进可提交的文件
5. 日志与会话数据 —— 落在 ~/.local/share/opencode/，迁移或清理时按需处理
6. 企业强制 —— 管理端配置可把 permission 全量设为 ask/deny，用户无法覆盖
```

```text
忽略与隐私要点：
1. 监听忽略 —— watcher.ignore 用 glob 排除目录，依赖/构建/缓存目录已默认忽略
2. 读取默认值 —— 多数 allow，但 .env、.env.* 默认 deny（.env.example 允许）
3. 越界保护 —— external_directory 默认 ask，跨出工作目录必须先放行
4. 分享控制 —— 项目级固定 share: "disabled" 是最省事的团队级防泄露手段
5. 导出脱敏 —— 对外提供会话前用 opencode export --sanitize
6. 规则顺序 —— 权限规则最后一条匹配生效，兜底规则放最前
```

## 应用场景实战

### 场景一：为 monorepo 落地分层规则与统一配置

一个含多个子包的 monorepo 需要三层次规则：根目录放全局约定（构建、提交规范），各子包放自己的 AGENTS.md，已有的既有规范文件用 `instructions` 复用。同时把「敏感默认值」写进可提交的项目配置里。

```json
// 仓库根 opencode.json：团队共享的默认配置
{
  "$schema": "https://opencode.ai/config.json",
  "model": "corp-gw/claude-sonnet-4-5",
  "small_model": "corp-gw/qwen2.5-coder-32b",
  "instructions": [
    "CONTRIBUTING.md",
    "docs/engineering-guidelines.md",
    "packages/*/AGENTS.md"
  ],
  "compaction": { "auto": true, "prune": true, "reserved": 12000 },
  "watcher": { "ignore": ["**/dist/**", "**/generated/**", "**/.turbo/**"] },
  "share": "disabled",
  "permission": {
    "read": { "*": "allow", "*.env": "deny", "*.env.*": "deny", "*.env.example": "allow" },
    "bash": { "*": "ask", "npm test *": "allow", "git status*": "allow", "git push *": "deny" },
```

### 场景二：把上下文成本与敏感信息管住

一个跑了很久的排查会话已经把上下文推高，同时仓库里有 `.env` 与生成目录。做法是：先确认敏感文件被默认拒读、把生成目录排除出监听，再压缩上下文继续，最后用脱敏导出交接。

```json
    "ignore": ["**/generated/**", "**/logs/**", "**/*.log"]
```

## 最佳实践与踩坑记录

### 最佳实践

1. 规则分三层维护：个人偏好写全局 `~/.config/opencode/AGENTS.md`，团队约定写项目 `AGENTS.md`（提交 Git），子包规则写各子包 `AGENTS.md`
2. 已有规范不搬家：用 `instructions` 的 glob 引用 `CONTRIBUTING.md`、`.cursor/rules/*.md`，避免同一份规则维护两遍
3. 项目配置固化安全默认值：`share: "disabled"`、`.env` 拒读、危险 bash 前缀 deny，提交 Git 让全团队生效
4. 主动压缩而不是等自动压缩：长任务在关键节点 `/compact`，比撞窗口后被动压缩保留的重点更准
5. 用 `debug config` 验证配置：改完配置先看解析结果，再怀疑功能，能省掉大半排查时间
6. 敏感文件永不进上下文：密钥走 `{env:VAR}`/`{file:path}`，同时保留 `.env` 默认 deny，不要为了图方便改成 allow

### 踩坑记录

```text
坑 1：改项目 opencode.json 后行为没变
结论：配置像是没生效，模型或 share 设置还是旧值。
原因：配置不是替换而是合并，且启动时只从当前目录向上找最近的配置；改错文件或放错位置都会看似无效。
解法：在项目根放 opencode.json；用 opencode debug config 看最终合并结果；临时覆盖用 OPENCODE_CONFIG_CONTENT 验证。

坑 2：AGENTS.md 里写的 @引用 完全没被读取
结论：规则文件里引用的规范文档对模型不可见。
原因：OpenCode 不会自动解析 AGENTS.md 中的文件引用，需要显式指令或改用 instructions 配置。
解法：把引用文件加进 instructions 数组（支持 glob）；或在 AGENTS.md 里明确写「遇到引用用 Read 工具按需加载」。

坑 3：把密钥放进 AGENTS.md 或配置后同步到了团队仓库
结论：敏感信息进入版本库，需紧急轮换密钥。
原因：AGENTS.md 建议提交 Git，而配置又支持内联明文 Key，容易顺手写进去。
解法：Key 一律用 {env:VAR} 或 {file:path} 引用；确认 .env 保持默认 deny 规则；已泄露的立即轮换。

坑 4：长会话突然丢掉了前面的关键结论
结论：压缩后模型「忘了」早期的重要上下文。
原因：auto 压缩触发时把历史压成摘要，细节会被丢弃；同时 prune 开启会删掉旧工具输出。
解法：把关键结论写进 AGENTS.md 或提交到仓库文件里，让它在压缩后仍可从文件恢复；必要时在压缩前手工整理要点。

坑 5：agent 读到了不该读的文件或改了不该改的路径
结论：越权访问工作目录外的文件，或误改生成产物。
原因：默认权限偏宽松（多数 allow），只有 .env 类与越界路径有默认保护；生成目录不在默认拒读范围内。
解法：用 permission.read/edit 按模式 deny 掉生成产物与密钥，越界访问统一走 external_directory 显式放行，不要整体改成 ask 之后就以为万事大吉。
```

## 概述

OpenCode 的扩展能力有两条腿：**MCP（Model Context Protocol）** 用来接入外部工具服务，本地进程或远程 HTTP 都支持，接上后 MCP 工具与内置工具一起直接暴露给模型；**插件（Plugin）** 是 JavaScript/TypeScript 模块，挂在 opencode 自身的事件与钩子上，可以拦截工具调用、注入环境变量、注册自定义工具，甚至替换压缩策略。

两者解决的问题不同：MCP 扩的是「模型能调用的工具集合」，插件扩的是「opencode 本身的行为」。

```text
本篇要解决的问题：
1. mcp 配置块的字段（type / command / url / headers / environment / enabled / timeout）
2. 本地 stdio MCP 与远程 HTTP MCP 的差别与 OAuth 自动认证流程
3. 插件放在哪、加载顺序如何、有哪些事件与钩子可挂
4. MCP 工具与插件工具的权限如何按 agent / glob 精细化控制
```

本篇命令与输出以 opencode `1.19.0` 实测为准；官方文档见 `https://opencode.ai/docs/mcp-servers/`、`https://opencode.ai/docs/plugins/`、`https://opencode.ai/docs/permissions/`。

## MCP 基础与配置结构

MCP 服务配置在 `opencode.json` 的 `mcp` 块下，每个服务一个键名，键名即服务名（提示模型时用得到），并用 `type` 区分连接方式：

```json
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "everything": {
      "type": "local",
      "command": ["npx", "-y", "@modelcontextprotocol/server-everything"],
      "enabled": true
    },
    "context7": {
      "type": "remote",
      "url": "https://mcp.context7.com/mcp",
      "enabled": true
    }
  }
}
```

`type` 必填，取值 `local` 或 `remote`。`enabled: false` 可以临时关掉某个服务而不删除配置（团队默认配置里常用这个方式让成员按需开启）。

MCP 工具名带服务名前缀，因此可以按 glob 批量管控；例如把某个服务的全部工具关掉：

```json
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "my-mcp-foo": { "type": "local", "command": ["bun", "x", "my-mcp-command-foo"] },
    "my-mcp-bar": { "type": "local", "command": ["bun", "x", "my-mcp-command-bar"] }
  },
  "tools": {
    "my-mcp*": false
  }
}
```

命令行管理提供了一整套子命令（1.19.0 实测 `opencode mcp --help`）：

```text
opencode mcp add [name]     add an MCP server
opencode mcp list           list MCP servers and their status          [aliases: ls]
opencode mcp auth [name]    authenticate with an OAuth-enabled MCP server
opencode mcp logout [name]  remove OAuth credentials for an MCP server
opencode mcp debug <name>   debug OAuth connection for an MCP server
```

本机实测：上面那份同时含本地与远程服务的配置，两个服务都连上了。

```text
$ opencode mcp list
┌  MCP Servers
│
●  ✓ everything connected
│      npx -y @modelcontextprotocol/server-everything
│
●  ✓ context7 connected
│      https://mcp.context7.com/mcp
│
└  2 server(s)
```

同一个状态也能从服务端接口读到（`opencode serve` 后的 `GET /mcp`），实测返回：

```json
{ "everything": { "status": "connected" }, "context7": { "status": "connected" } }
```

一个必须提前知道的代价：MCP 服务会往上下文里塞工具描述，服务越多、工具越多的服务（官方点名 GitHub MCP server）越容易把上下文吃满，所以要克制地挂服务。

```text
MCP 基础要点：
1. mcp 块按服务名键控，type 必填（local / remote）
2. enabled: false 临时关停；团队默认配置用它做 opt-in
3. 工具名带服务名前缀，可用 glob 批量开关
4. opencode mcp add / list / auth / logout / debug 是完整的命令行入口
5. MCP 会让上下文变重，官方建议少挂、按需挂
```

## 本地 MCP 服务

本地 MCP 是 stdio 进程：opencode 按 `command` 启动子进程，通过标准输入输出通信。

```json
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "playwright": {
      "type": "local",
      "command": ["npx", "-y", "@playwright/mcp"],
      "enabled": true,
      "environment": {
        "BROWSER": "chromium"
      }
    },
    "mcp_everything": {
      "type": "local",
      "command": ["npx", "-y", "@modelcontextprotocol/server-everything"],
      "enabled": true
    }
  }
}
```

`command` 是数组（不是字符串），第一个元素是可执行文件，后面是参数；也可以用 `["bun", "x", "my-mcp-command"]`。本地服务的完整选项：

| 选项 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `type` | String | 是 | 固定为 `"local"` |
| `command` | Array | 是 | 启动命令与参数 |
| `cwd` | String | 否 | 服务进程的工作目录，相对路径按工作区解析 |
| `environment` | Object | 否 | 传给服务进程的环境变量 |
| `enabled` | Boolean | 否 | 是否随启动启用 |
| `timeout` | Number | 否 | 拉取工具列表的超时毫秒数，默认 5000 |

用法上，模型需要知道工具存在才会用；配置好之后在提示里点名即可：

```text
use the mcp_everything tool to add the number 3 and 4
```

```text
本地 MCP 要点：
1. command 必须是数组；想换运行时用 ["bun","x",...] 也可以
2. environment 是给 MCP 子进程的，不是给你的 shell
3. cwd 相对工作区解析，装在有相对路径依赖的服务时要显式设
4. timeout 默认 5000ms，慢服务（首次 npx 拉包）容易超时
5. 提示词里点服务名能显著提高命中率，也可以在 AGENTS.md 里固化
```

## 远程 MCP 与 OAuth 认证

远程 MCP 走 HTTP，配置 `url` 与可选 `headers`：

```json
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "gh_grep": {
      "type": "remote",
      "url": "https://mcp.grep.app",
      "enabled": true
    },
    "context7": {
      "type": "remote",
      "url": "https://mcp.context7.com/mcp",
      "headers": {
        "CONTEXT7_API_KEY": "{env:CONTEXT7_API_KEY}"
      }
    },
    "jira": {
      "type": "remote",
      "url": "https://jira.example.com/mcp",
      "oauth": {
        "clientId": "{env:MY_MCP_CLIENT_ID}",
        "clientSecret": "{env:MY_MCP_CLIENT_SECRET}",
        "scope": "tools:read tools:execute"
      }
    }
  }
}
```

远程服务的选项：

| 选项 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `type` | String | 是 | 固定为 `"remote"` |
| `url` | String | 是 | 远程 MCP 服务地址 |
| `enabled` | Boolean | 否 | 是否随启动启用 |
| `headers` | Object | 否 | 请求头，可放鉴权信息 |
| `oauth` | Object 或 false | 否 | OAuth 配置；`false` 关闭自动 OAuth |
| `timeout` | Number | 否 | 拉取工具列表超时，默认 5000ms |

字符串值支持 `{env:VAR}` 与 `{file:path}` 插值；注意 **shell 风格的 `${VAR}` 不会被替换**，敏感值必须写成 `{env:...}` 或放在 `opencode auth` 里。

OAuth 是自动的：服务返回 401 时 opencode 会发起授权流程，服务端支持的话会用动态客户端注册（RFC 7591），令牌存放在 `~/.local/share/opencode/mcp-auth.json`。需要自带 client 凭据时按上面的 `jira` 写法配置 `clientId` / `clientSecret` / `scope`。用 API Key 而非 OAuth 的服务，把 `oauth` 设为 `false` 避免误触发：

```json
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "my-api-key-server": {
      "type": "remote",
      "url": "https://mcp.example.com/mcp",
      "oauth": false,
      "headers": { "Authorization": "Bearer {env:MY_API_KEY}" }
    }
  }
}
```

认证与排错命令：

```shell
# 手动触发 OAuth（会打开浏览器）
opencode mcp auth sentry

# 查看哪些服务支持 OAuth、当前认证状态
opencode mcp auth list

# 清掉某个服务的凭据
opencode mcp logout sentry

# 排错：打印认证状态、测 HTTP 连通性、尝试 OAuth 发现流程
opencode mcp debug sentry
```

组织也可以在自己的 `.well-known/opencode` 端点下发默认 MCP 服务（默认多为禁用，成员在本机配置里用 `enabled: true` 开启即可，本地配置覆盖远端默认值）。

```text
远程 MCP 要点：
1. 只需要 url 就能接；headers 放鉴权，值写 {env:VAR} 不写 ${VAR}
2. 401 会自动走 OAuth，支持动态客户端注册；令牌落在 mcp-auth.json
3. 用 API Key 的服务记得 oauth: false，否则可能被拉进 OAuth 流程
4. 认证卡住先用 opencode mcp debug <name> 看握手到哪一步
5. 组织默认服务通过 .well-known/opencode 下发，本地配置优先
```

## 插件机制与事件钩子

插件是 JS/TS 模块，两条装载路径：放进插件目录（启动时自动加载）或在配置里声明 npm 包。

```text
项目级目录：.opencode/plugins/   （也接受 .opencode/plugin/）
全局级目录：~/.config/opencode/plugins/
npm 包：opencode.json 的 plugin 数组
```

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": [
    "opencode-helicone-session",
    "opencode-wakatime@1.2.3",
    "./local-plugin.ts",
    ["@my-org/custom-plugin", { "option": "value" }]
  ]
}
```

加载顺序固定为：全局配置 → 项目配置 → 全局插件目录 → 项目插件目录；同名同版本的 npm 包只加载一次，但本地插件与同名 npm 插件会被分别加载。npm 插件由 Bun 在启动时安装，缓存在 `~/.cache/opencode/node_modules/`。

插件模块导出一个异步函数，入参是 `PluginInput`，返回值是钩子对象：

```javascript
export const MyPlugin = async ({ project, client, $, directory, worktree, serverUrl }) => {
  console.log("Plugin initialized!")
  return {
    // 钩子实现写在这里，没有要挂的就返回 {}
  }
}
```

本机实测：项目级 `.opencode/plugins/marker.js` 在 `opencode run` 启动时被加载，初始化副作用确实执行了（写出了一个标记文件）。TypeScript 版可以引入官方类型：

```typescript
import type { Plugin } from "@opencode-ai/plugin"

export const MyPlugin: Plugin = async ({ project, client, $, directory, worktree }) => {
  return {
    "tool.execute.before": async (input, output) => {
      if (input.tool === "bash") {
        output.args.command = escapeCommand(output.args.command)
      }
    },
  }
}
```

可挂的钩子（`@opencode-ai/plugin` 1.19.0 类型文件与内置 schema 说明）：

| 类别 | 钩子 |
|------|------|
| 事件总线 | `event`（所有事件，含 `session.idle`、`file.edited`、`permission.asked`、`lsp.client.diagnostics` 等） |
| 配置 | `config`（初始化时拿到合并后的配置，可就地修改） |
| 对话 | `chat.message`、`chat.params`、`chat.headers` |
| 工具 | `tool.execute.before`、`tool.execute.after`、`tool.definition` |
| 命令 | `command.execute.before` |
| 环境 | `shell.env`（给所有 shell 执行注入环境变量） |
| 权限 | `permission.ask` |
| 实验性 | `experimental.session.compacting`、`experimental.compaction.autocontinue`、`experimental.chat.messages.transform` 等 |
| 对象型 | `tool: {...}`（注册自定义工具）、`auth: {...}`、`provider: {...}` |

结构化日志用 `client.app.log()` 而不是 `console.log`：

```javascript
export const MyPlugin = async ({ client }) => {
  await client.app.log({
    body: {
      service: "my-plugin",
      level: "info",
      message: "Plugin initialized",
      extra: { foo: "bar" },
    },
  })
}
```

```text
插件机制要点：
1. 目录放 .opencode/plugins/ 自动加载；npm 包写在 plugin 数组里
2. 加载顺序：全局配置 → 项目配置 → 全局插件目录 → 项目插件目录
3. event 钩子能订阅全部事件，适合做通知、埋点、审计
4. tool.execute.before 可以改写参数甚至抛错拦截（.env 保护就是这么做的）
5. 日志用 client.app.log，console.log 不会进结构化日志
```

## 自定义工具与权限控制

插件可以直接往 opencode 里注册工具。用 `@opencode-ai/plugin` 的 `tool()` 助手，参数 schema 用 zod（`tool.schema` 就是 zod）：

```typescript
import { type Plugin, tool } from "@opencode-ai/plugin"

export const CustomToolsPlugin: Plugin = async (ctx) => {
  return {
    tool: {
      mytool: tool({
        description: "Query the internal release service for a version's status",
        args: {
          version: tool.schema.string().describe("Semantic version, e.g. 1.8.0"),
        },
        async execute(args, context) {
          const { directory, worktree } = context
          const res = await fetch(`https://release.internal/api/status?version=${args.version}`)
          const body = await res.json()
          return {
            title: `release ${args.version}`,
            output: JSON.stringify(body, null, 2),
            metadata: { directory, worktree },
          }
        },
      }),
    },
  }
}
```

`tool()` 的 `execute` 拿到 `args` 与 `ToolContext`（含 `sessionID`、`messageID`、`agent`、`directory`、`worktree`、`abort` 信号，以及 `metadata()` 与 `ask()` 两个回调）。返回值可以是字符串，也可以是 `{ title, output, metadata, attachments }` 对象；注册后的工具与内置工具并列可用。

权限控制有两层：

1. **全局/按工具名**：`permission` 按键名与模式管控，MCP 工具与插件工具都适用；旧的 `tools: { write: false }` 布尔写法已废弃，等价于 `permission: {"*": "deny"}`。
2. **按 agent**：agent 的 `permission` 与全局合并且优先。大仓库里常见做法是全局关掉 MCP 工具，只在需要的 agent 上开：

```json
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "my-mcp": {
      "type": "local",
      "command": ["bun", "x", "my-mcp-command"],
      "enabled": true
    }
  },
  "tools": {
    "my-mcp*": false
  },
  "agent": {
    "my-agent": {
      "tools": {
        "my-mcp*": true
      }
    }
  }
}
```

权限的可用键、通配符规则与「最后匹配优先」的求值顺序见 [[06.5-自定义 Agent 与命令]]。实测 `GET /agent` 可以看到每个 agent 最终展开的权限规则数组，例如自定义审查子代理会展开出 `edit / bash / webfetch` 三条 deny 规则。

```text
自定义工具与权限要点：
1. tool() 的 args 用 zod schema，模型据此生成调用参数
2. execute 拿到 ToolContext，路径用 context.directory 而不是 process.cwd()
3. 返回值用 { title, output, metadata } 形式更利于 TUI 展示
4. MCP 与插件工具同样受 permission 管控，可按 glob 开关
5. 全局关、按 agent 开的组合是控制上下文与风险的标准做法
```

## 应用场景实战

### 场景一：按 agent 分级接入远程与本地 MCP

目标：文档检索（Context7）与 GitHub 代码检索（grep.app）常年可用；本地 Playwright MCP 只在做端到端测试时给指定 agent 开，避免污染日常上下文。

```json
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "context7": {
      "type": "remote",
      "url": "https://mcp.context7.com/mcp",
      "headers": { "CONTEXT7_API_KEY": "{env:CONTEXT7_API_KEY}" },
      "enabled": true
    },
    "gh_grep": {
      "type": "remote",
      "url": "https://mcp.grep.app",
      "enabled": true
    },
    "playwright": {
      "type": "local",
      "command": ["npx", "-y", "@playwright/mcp"],
      "enabled": true
    }
  },
  "tools": {
    "playwright*": false
  },
  "agent": {
    "e2e": {
      "description": "Runs and repairs end-to-end browser tests",
      "mode": "subagent",
      "tools": { "playwright*": true }
    }
  },
  "instructions": ["AGENTS.md"]
}
```

在 `AGENTS.md` 里固化使用约定，减少每次都要在提示里点名：

```markdown
## MCP usage

- When you need library or framework docs, use `context7` tools.
- When unsure how a library is used in the wild, use `gh_grep` to search GitHub code.
- Never use `playwright` tools outside the `e2e` subagent.
```

验证与排错：

```shell
# 看连接状态
opencode mcp list

# 远程服务要 OAuth 时手动触发
opencode mcp auth context7

# 服务连不上时看握手细节
opencode mcp debug context7

# 只想临时排除插件、定位是否插件导致的异常
opencode --pure
```

关键点：`tools: {"playwright*": false}` 把本地 MCP 的上下文代价挪出日常会话，只在 `e2e` 子代理里生效。

### 场景二：写一个插件做 .env 保护 + 自定义工具

目标：禁止任何工具读取 `.env`，并在会话结束时打一行结构化日志；同时注册一个查询内部发布状态的自定义工具。

```json
{
  "dependencies": {
    "zod": "^3.23.8"
  }
}
```

```typescript
// .opencode/plugins/guard.ts
import { type Plugin, tool } from "@opencode-ai/plugin"

export const GuardPlugin: Plugin = async ({ client, directory }) => {
  await client.app.log({
    body: { service: "guard", level: "info", message: "plugin initialized", extra: { directory } },
  })

  return {
    // 1) 拦截 .env 读取：before 钩子里抛错即中止调用
    "tool.execute.before": async (input, output) => {
      const target = String(output.args?.filePath ?? output.args?.path ?? "")
      if (target.includes(".env") && !target.endsWith(".env.example")) {
        throw new Error("Do not read .env files")
      }
    },

    // 2) 会话空闲时记录一条日志
    event: async ({ event }) => {
      if (event.type === "session.idle") {
        await client.app.log({ body: { service: "guard", level: "info", message: "session idle" } })
      }
    },

    // 3) 注册自定义工具
    tool: {
      release_status: tool({
        description: "Get the release status for a version from the internal service",
        args: { version: tool.schema.string() },
        async execute(args) {
          const res = await fetch(`https://release.internal/api/status?version=${args.version}`)
          return { title: args.version, output: await res.text() }
        },
      }),
    },
  }
}
```

本机实测：这份 `.env` 保护插件的 before 钩子确实生效，模型读取 `.env` 时被拦下：

```text
$ opencode run "读取当前目录下的 .env 文件并把内容原样贴给我"
> build · big-pickle

✗ Read .env failed
Error: Do not read .env files
```

另外注意 opencode 会自动在 `.opencode/` 下生成依赖文件（实测生成的 `.opencode/package.json` 内容）：

```json
{
  "dependencies": {
    "@opencode-ai/plugin": "1.19.0"
  }
}
```

并生成配套的 `.opencode/.gitignore`（忽略 `node_modules`、`package.json`、`package-lock.json`、`bun.lock`、`.gitignore`），所以本地插件依赖不需要手动提交。

关键点：`tool.execute.before` 的 `throw` 是最省事的硬拦截；想在拦截前征求用户同意，用 `permission.ask` 钩子或工具上下文里的 `ask()`。

## 最佳实践与踩坑记录

### 最佳实践

1. MCP 服务按「人人必要」与「按需」分两级：常驻只留必要的，其余全局关、按 agent 开
2. 敏感值一律走 `{env:VAR}` 或 `opencode auth`，不要把 token 写进 `opencode.json`
3. 本地 MCP 首次启动会拉包，慢服务的 `timeout` 调到 10000 以上，避免工具列表拉取失败
4. 插件只做「横切关注点」（审计、脱敏、通知、注入环境变量），业务逻辑放 MCP 或自定义工具
5. 插件日志用 `client.app.log`，方便和 opencode 自身日志一起排错
6. 上生产前用 `opencode --pure` 对比一次，确认异常不是插件引入的

### 踩坑记录

```text
坑 1：远程 MCP 的鉴权头写成 ${GITHUB_TOKEN} 一直 401
结论：请求头里带的是字面量 ${GITHUB_TOKEN}，服务端认证失败。
原因：opencode 的配置插值只支持 {env:VAR} 与 {file:path} 两种写法，shell 风格的 ${VAR} 不会被替换。
解法：写成 "Authorization": "Bearer {env:GITHUB_TOKEN}"，并确认该环境变量在启动 opencode 的 shell 里可见。

坑 2：挂了 GitHub MCP 之后上下文经常爆掉
结论：对话刚开始就接近上下文上限，模型开始丢失早期信息。
原因：MCP 服务的工具描述会整体进入上下文，GitHub MCP 这类工具特别多的服务会吃掉大量 token。
解法：官方建议克制挂载；只保留当前任务需要的服务，用 tools: {"<server>*": false} 全局关掉、按 agent 打开。

坑 3：本地 MCP 服务一直连不上，报拉取工具超时
结论：opencode mcp list 里显示未连接，提示超时。
原因：本地 MCP 通过 npx 启动时首次要下载包，默认 5000ms 的拉取超时不够。
解法：把该服务的 timeout 调大（如 15000），或先手动执行一次 command 里的命令把包缓存好。

坑 4：本地插件 import 外部 npm 包报模块找不到
结论：插件加载失败，opencode 启动异常或功能缺失。
原因：本地插件不像 npm 插件由 opencode 自动安装依赖，它需要所在目录有自己的依赖声明。
解法：在配置目录放 package.json 声明依赖（实测 opencode 会自动生成 .opencode/package.json 并在启动时安装），或把插件发布到 npm 后写进 plugin 数组。

坑 5：桌面端/CLI 启动即崩或白屏，怀疑插件
结论：应用打不开，日志里能看到插件相关报错。
原因：某个插件初始化抛错把启动流程打断了。
解法：先清空配置里的 plugin 数组并临时移走 .opencode/plugins/ 目录（或用 opencode --pure 快速验证），再逐个启用定位；插件缓存坏了就删 ~/.cache/opencode 重装。
```

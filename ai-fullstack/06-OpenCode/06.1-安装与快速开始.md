## 概述

OpenCode 是一个开源的 AI 编码智能体，主要形态是终端里的 TUI（Terminal User Interface），同时提供桌面应用与 IDE 扩展。它本身不绑定任何模型厂商，通过 Provider 体系接入 75+ 家 LLM 服务，也可以接本地模型，属于「终端优先」的 Claude Code / Codex 同类工具。本主题解决三个问题：怎么装、怎么第一次跑起来、装完之后怎么升级与卸载。

```text
本节要点：
1. 安装面 —— 安装脚本 curl、Node 包管理器 npm/bun/pnpm/yarn、Homebrew、Arch pacman/AUR、Windows choco/scoop、Docker 镜像
2. 依赖面 —— 需要一个现代终端模拟器（WezTerm/Alacritty/Ghostty/Kitty）+ 至少一家 LLM Provider 的 API Key
3. 初始化 —— 进入项目目录直接 opencode，第一次用 /init 生成 AGENTS.md
4. 升级 —— opencode upgrade（可用 --method 指定原安装方式），配置里 autoupdate 可关
5. 卸载 —— opencode uninstall（可 --keep-config / --keep-data 保留配置与数据）
6. 版本注意 —— 官方文档同时存在 OpenCode 1 与 OpenCode 2，两者都占用 opencode 命令，不能并行安装
```

## OpenCode 的形态与前置要求

OpenCode 的定位是「跑在终端里的编码智能体」：默认启动一个全屏 TUI，在 TUI 里用自然语言让模型读写代码、执行命令；同时它也有桌面应用和 IDE 扩展两种外壳，三者共享同一套配置与 Provider 凭据。它的核心卖点是开源、不锁定模型厂商、可接本地模型，并且把「会话、快照、权限、插件」都做成可配置项。

前置要求只有两条：一个现代终端模拟器和可用的 LLM 凭据。终端建议用支持真彩色与现代按键上报的模拟器，官方列出 WezTerm、Alacritty、Ghostty、Kitty；老式终端在渲染 diff 与响应快捷键时容易出问题。凭据可以是任意一家 Provider 的 API Key，官方推荐新手先用 OpenCode Zen（官方筛选并验证过可用性的模型清单）。

```text
形态与前置要求速查：
1. 形态 —— 终端 TUI（主）/ 桌面应用 / IDE 扩展，命令统一是 opencode
2. 需要 —— 现代终端模拟器 + 至少一家 LLM Provider 的 API Key
3. 推荐起步 —— OpenCode Zen（/connect 里选 opencode，跳转 opencode.ai/auth 取 Key）
4. 运行环境 —— macOS、Linux、Windows（Windows 官方推荐走 WSL 以获得完整能力）
5. 版本线 —— OpenCode 1 与 OpenCode 2 共用 opencode 命令，不能并存，装前先确认团队用哪条线
```

## 安装方式与平台支持

安装方式按使用场景排：官方安装脚本最省事，Node 包管理器最可复现（版本可锁、能写进 Dockerfile），系统包管理器适合个人机器。注意官网同时维护 OpenCode 1 与 OpenCode 2 两套文档，两者的安装命令都会提供同一个 `opencode` 可执行文件，因此不能在同一台机器上并存，团队协作时要先对齐版本线。

```bash
# 1. 官方安装脚本（Linux/macOS，最常用）
curl -fsSL https://opencode.ai/install | bash

# 2. Node 包管理器（团队/CI 推荐：版本可固定）
npm install -g opencode-ai
# bun install -g opencode-ai
# pnpm install -g opencode-ai
# yarn global add opencode-ai

# 3. Homebrew（macOS 与 Linux）
brew install anomalyco/tap/opencode   # 官方 tap，更新更及时
# brew install opencode               # Homebrew 官方 formula，更新较慢

# 4. Arch Linux
sudo pacman -S opencode    # 稳定版
# paru -S opencode-bin     # AUR，最新版

# 5. Windows
# choco install opencode
# scoop install opencode
# mise use -g github:anomalyco/opencode

# 6. Docker（免安装，适合一次性试跑）
docker run -it --rm ghcr.io/anomalyco/opencode
```

也可以在 Releases 页直接下载对应平台的二进制文件。下面是在本机 Ubuntu 24.04 上用 npm 镜像源实装并验证的真实过程（原样贴出）：

npm 11.x 起对新依赖的 postinstall 脚本默认不执行，而 `opencode-ai` 的 postinstall 负责落地平台二进制，所以国内网络下推荐「镜像源 + 显式放行脚本」这一组合，一条命令即可：

```bash
# 国内网络下的推荐安装命令（镜像源 + 放行 postinstall）
npm install -g --allow-scripts=opencode-ai opencode-ai \
  --registry=https://registry.npmmirror.com

# 安装后自检三连
opencode --version     # 期望输出形如 1.19.0
which opencode         # 确认落在 PATH 上（npm 全局 bin 目录）
opencode --help        # 列出全部子命令，确认二进制完整
```

## 首次运行与 Provider 接入

装完之后还没法对话，必须先接一个 Provider。接入在 TUI 内完成：启动 `opencode` 后输入 `/connect`，选中 Provider（新手选 opencode，即 OpenCode Zen），浏览器打开 opencode.ai/auth 登录、绑定支付方式、复制 API Key 粘贴回终端。凭据落地在 `~/.local/share/opencode/auth.json`，之后所有会话复用。

```bash
# 在项目目录启动 TUI（不带参数则使用当前目录）
cd /path/to/project
opencode

# 也可以用位置参数指定工作目录
opencode /path/to/project
```

```text
# TUI 内接 Provider
/connect            # 选择 Provider 并粘贴 API Key
/models             # 查看并切换可用模型
/help               # 查看全部斜杠命令
```

启动成功的样子：本机在 `opencode-ai@1.19.0` 下用伪终端启动 TUI，界面正常渲染出 OpenCode 的 ASCII 标识与版本号，右下角提示 `/update to upgrade to OpenCode 2.0`，说明当前跑的是 OpenCode 1 这条线。这条提示也再次印证两条版本线共用同一个命令。

命令行侧也有等价的凭据管理命令，适合无界面环境与脚本化装机：

```bash
# 交互式登录并写入 ~/.local/share/opencode/auth.json
opencode auth login
opencode auth login -p anthropic             # 指定 Provider，跳过选择
opencode auth login -p openai -m "ChatGPT"   # 指定登录方式，跳过方式选择

# 查看 / 注销
opencode auth ls       # 等价于 opencode auth list
opencode auth logout
```

本机未配置任何凭据时，`opencode auth ls` 的输出如下，可作为装机脚本的检查点：

```text
$ opencode auth list

┌  Credentials ~/.local/share/opencode/auth.json
│
└  0 credentials
```

```text
首次运行要点：
1. 顺序 —— 先 /connect 接 Provider，再进项目跑 opencode，否则无法对话
2. 凭据位置 —— ~/.local/share/opencode/auth.json，也是备份/迁移凭据的唯一文件
3. 无界面环境 —— 用 opencode auth login / auth ls / auth logout 代替 TUI 内的 /connect
4. 模型选择 —— /models 打开选择器；模型 ID 格式固定为 provider/model
5. 报错排查 —— 认证问题优先重新 /connect，再看日志目录 ~/.local/share/opencode/log/
6. 验证就绪 —— opencode auth ls 能列出凭据，即表示 Provider 已就绪
```

## 项目初始化与快速上手流程

「项目初始化」在 OpenCode 里对应 `/init`：它会扫描仓库里的关键文件，必要时反问几个代码库回答不了的问题，然后在项目根目录创建或原地改进 `AGENTS.md`。`AGENTS.md` 是给模型的项目级说明书，建议提交进 Git，团队共享。

```text
# TUI 内初始化项目
/init

# 初始化后可在项目里直接提问，@ 做模糊文件检索
How is auth handled in @packages/functions/src/api/index.ts?
```

一个典型的最小闭环如下（消息内容为示例，实际项目替换成自己的需求）：

```text
1. /init                        → 生成 AGENTS.md（构建、测试、目录约定）
2. 按 Tab 切到 Plan 模式         → 让它先给实现方案，不动代码
3. 描述需求，迭代方案
4. 再按 Tab 切回 Build 模式      → 让它落地改动
5. /undo                        → 改动不对就整体回退（依赖 Git 仓库）
6. /share                       → 需要求助队友时生成分享链接
```

不改代码的批处理场景可以直接用 `opencode run`（非交互模式），这在 CI、脚本、一次性问答里更实用：

```bash
# 非交互执行，回答直接打到 stdout
opencode run "Explain the use of context in Go"

# 指定模型与输出格式
opencode run -m anthropic/claude-sonnet-4-5 "Review this diff"
opencode run --format json "列出仓库里所有的 CI 配置"   # 原始 JSON 事件，便于脚本解析

# 附带文件作为上下文
opencode run -f src/api.go -f README.md "这两个文件有什么不一致？"
```

```bash
# 本机实测：带 -m 参数指定模型执行一次非交互调用
$ opencode run -m mocklocal/mock-gpt "reply with the word ping"
> build · mock-gpt

pong from mock model
```

```text
项目初始化要点：
1. /init 的产物 —— 项目根目录的 AGENTS.md，可提交 Git，是团队共享的项目说明书
2. /init 是增量的 —— 已有 AGENTS.md 时原地改进，不会整体覆盖
3. 交互模式 —— opencode（TUI）；非交互模式 —— opencode run [message..]
4. 上下文附加 —— TUI 里 @ 模糊查找文件，! 直接跑 shell，图片可直接拖进终端
5. 回退机制 —— /undo 与 /redo 依赖 Git 管理改动，所以项目应当是 Git 仓库
6. 目录与续会话 —— opencode /path/to/project 指定目录，opencode -c 继续上一次会话
```

## 版本升级与自动更新

升级有两条路径：命令行显式升级与启动时自动更新。显式升级用 `opencode upgrade`，可以带目标版本号，也可以通过 `--method` 告诉它当初是用哪种方式装的（curl/npm/pnpm/bun/brew/choco/scoop），避免升级方式与安装方式不一致导致命令失效。

```bash
# 升级到最新版
opencode upgrade

# 升级到指定版本
opencode upgrade v0.1.48

# 明确指定安装方式，避免自动探测失败
opencode upgrade --method npm
```

```text
$ opencode upgrade --help

opencode upgrade [target]

upgrade opencode to the latest or a specific version

Positionals:
  target  version to upgrade to, for ex '0.1.48' or 'v0.1.48'                               [string]

Options:
  -h, --help        show help                                                              [boolean]
  -v, --version     show version number                                                    [boolean]
      --print-logs  print logs to stderr                                                   [boolean]
      --log-level   log level                   [string] [choices: "DEBUG", "INFO", "WARN", "ERROR"]
      --pure        run without external plugins                                           [boolean]
  -m, --method      installation method to use
                          [string] [choices: "curl", "npm", "pnpm", "bun", "brew", "choco", "scoop"]
      --major       upgrade to OpenCode 2 and remove OpenCode 1                            [boolean]
```

注意 `--major` 这一项：它会升级到 OpenCode 2 并移除 OpenCode 1，属于跨大版本迁移，团队里要统一后再动。自动更新由配置项 `autoupdate` 控制，默认开启；想保留提示但不自动升级可以设成 `"notify"`（用包管理器安装的实例该值不生效）；也可以直接用环境变量 `OPENCODE_DISABLE_AUTOUPDATE` 关掉检查。

```json
{
  "$schema": "https://opencode.ai/config.json",
  "autoupdate": "notify"
}
```

```bash
# 环境变量方式关闭自动更新检查
export OPENCODE_DISABLE_AUTOUPDATE=1
```

```text
升级要点：
1. 常用命令 —— opencode upgrade（最新）/ opencode upgrade v0.1.48（指定版本）
2. 方式对齐 —— 用 --method npm|brew|curl 等显式声明安装方式，避免探测错误
3. 跨大版本 —— --major 会装 OpenCode 2 并移除 OpenCode 1，属破坏性操作，需团队确认
4. 自动更新 —— 配置 autoupdate: true|false|"notify"，或用 OPENCODE_DISABLE_AUTOUPDATE=1
5. 包管理器装的实例 —— notify 语义不适用，升级交给包管理器
6. 校验方式 —— 升级后 opencode --version 对比目标版本号
```

## 卸载与数据清理

卸载用 `opencode uninstall`，它会先列出将删除的内容并请求确认。默认会连配置与数据一起清，想保留可以用 `--keep-config` 与 `--keep-data`；脚本里无人值守执行时可以配 `--force`，排查时可用 `--dry-run` 只预览不删除。

```bash
# 交互式卸载（会展示清单并二次确认）
opencode uninstall

# 只预览要删什么
opencode uninstall --dry-run

# 保留配置与数据，只删程序
opencode uninstall --keep-config --keep-data

# 脚本里静默卸载
opencode uninstall --force
```

手工排查或迁移时需要知道数据都在哪，官方文档给出如下位置：

```bash
# 日志（保留最近 10 个）
~/.local/share/opencode/log/

# 数据目录：凭据、日志、会话数据
~/.local/share/opencode/
#   auth.json   凭据（API Key / OAuth token）
#   log/        应用日志
#   project/    会话与消息数据（Git 仓库内项目按 project-slug 分目录，非 Git 项目落在 global/storage/）

# 提供商包缓存（AI_APICallError 一类问题可清掉重建）
rm -rf ~/.cache/opencode

# 全局配置目录
~/.config/opencode/
```

```text
卸载与清理要点：
1. 正式卸载 —— opencode uninstall，删除前会列出清单并确认
2. 保留开关 —— --keep-config 保配置、--keep-data 保会话数据与快照
3. 数据位置 —— 凭据 ~/.local/share/opencode/auth.json，会话数据在同目录 project/ 下
4. 缓存清理 —— provider 包缓存异常时删 ~/.cache/opencode 让 opencode 重新拉取
5. 配置位置 —— 全局配置 ~/.config/opencode/opencode.json，卸载时默认一起处理
6. 日志排查 —— 启动不了先看 ~/.local/share/opencode/log/ 最近一份日志，或加 --print-logs
```

## 应用场景实战

### 场景一：团队新机器一键装好并自检通过

新同学入职拿到一台干净的 Ubuntu 机器，网络在国内，用 npm 镜像源安装并做三步自检，脚本失败即退出，避免「装上了但其实是坏的」这类隐性故障。

```bash
#!/usr/bin/env bash
# scripts/setup-opencode.sh —— 装机脚本：安装 + 自检
set -euo pipefail

NPM_REGISTRY="https://registry.npmmirror.com"
WANT_VERSION="${1:-}"   # 可选：指定目标版本，如 1.19.0

echo "[1/4] 安装 opencode-ai（镜像源 + 放行 postinstall）"
if [ -n "$WANT_VERSION" ]; then
  npm install -g --allow-scripts=opencode-ai "opencode-ai@${WANT_VERSION}" --registry="$NPM_REGISTRY"
else
  npm install -g --allow-scripts=opencode-ai opencode-ai --registry="$NPM_REGISTRY"
fi

echo "[2/4] 自检：二进制是否在 PATH 上"
command -v opencode >/dev/null || { echo "opencode 不在 PATH，检查 npm 全局 bin 目录"; exit 1; }

echo "[3/4] 自检：版本号"
opencode --version

echo "[4/4] 自检：Provider 凭据"
if opencode auth ls 2>&1 | grep -q "0 credentials"; then
  echo "尚未配置 Provider，请进入 opencode 后执行 /connect"
else
  echo "已存在 Provider 凭据"
fi

echo "完成。进入项目目录执行 opencode，然后 /init 生成 AGENTS.md"
```


### 场景二：用 Docker 在 CI 里跑一次非交互代码评审

不想给 CI runner 装 Node 环境时，可以直接用官方镜像跑 `opencode run`。密钥通过环境变量注入，仓库以卷挂载，非交互模式输出直接进 CI 日志；想接自己的网关就把 Provider 配置一起挂进去。

```yaml
# .github/workflows/opencode-review.yml
name: opencode review
on:
  pull_request:
    types: [opened, synchronize]

jobs:
  review:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - name: 生成待评审 diff
        run: git diff origin/${{ github.base_ref }}...HEAD > /tmp/pr.diff

      - name: 用官方镜像跑非交互评审
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
        run: |
          docker run --rm \
```

## 最佳实践与踩坑记录

### 最佳实践

1. 装机脚本固定版本：CI 与团队新机器上安装时写明 `opencode-ai@<版本>`，避免「昨天还能跑今天行为变了」
2. 国内网络统一走镜像源：npm 用 `--registry=https://registry.npmmirror.com`，并把 `--allow-scripts=opencode-ai` 写进命令，保证 postinstall 能执行
3. 安装后立刻三步自检：`command -v opencode`、`opencode --version`、`opencode auth ls`，把「二进制缺失」与「凭据缺失」区分开
4. 团队统一版本线：先确认用 OpenCode 1 还是 OpenCode 2，两者共用 `opencode` 命令无法并存，混用会导致命令行为不一致
5. 项目第一天就 `/init`：把构建、测试、目录约定写进 `AGENTS.md` 并提交 Git，后续所有会话都受益
6. 非交互交给 `opencode run`：批处理、CI、脚本里不要用 TUI，`run` 才是稳定接口，配 `--model` 与 `-f` 显式声明上下文

### 踩坑记录

```text
坑 1：npm 全局装完 opencode 命令不存在或行为异常
结论：包装上了，但平台二进制没落地，命令缺失或报错。
原因：npm 11.x 默认不执行新依赖的 postinstall 脚本，而 opencode-ai 的 postinstall 负责准备二进制。
解法：显式放行脚本安装，npm install -g --allow-scripts=opencode-ai opencode-ai；装完用 command -v opencode 验证。

坑 2：照抄文档装了 OpenCode 2，结果和队友的 1.x 行为对不上
结论：同一套命令在两个大版本上行为不同，配置与快捷键细节有差异。
原因：两个版本都提供 opencode 命令且不能并存，文档站点两套文档并存，容易抄错。
解法：装之前确定版本线；升级时慎用 opencode upgrade --major（它会安装 V2 并移除 V1）。

坑 3：终端里 TUI 显示错乱、快捷键没反应
结论：界面花屏、diff 渲染错位或 ctrl 组合键无效。
原因：终端模拟器的真彩色/按键上报能力不足，或终端本身占用了按键。
解法：换用 WezTerm、Alacritty、Ghostty、Kitty 一类现代终端；在 tui.json 里改 leader 键避开冲突。

坑 4：认证失败却以为是网络问题
结论：会话里持续提示认证相关错误，重试无效。
原因：凭据未写入或已失效（~/.local/share/opencode/auth.json），或项目 .env 里注入了过期 Key。
解法：TUI 内重新 /connect；无界面环境用 opencode auth login；用 opencode auth ls 确认凭据条数。

坑 5：Windows 上文件监听与命令执行偶发失败
结论：改文件不触发、部分命令报路径错误。
原因：原生 Windows 的文件系统语义与 OpenCode 的假设不完全一致。
解法：按官方建议改用 WSL 运行；确需原生运行则用 choco/scoop 安装，并注意 Git Bash 路径配置（OPENCODE_GIT_BASH_PATH）。
```

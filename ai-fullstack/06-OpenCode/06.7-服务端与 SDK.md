## 概述

OpenCode 的 TUI 只是它的一种前端。核心是一个本地 HTTP 服务：`opencode serve` 启动无界面服务端，`opencode web` 在同一服务端上套一层浏览器界面，`opencode attach` 把终端 TUI 接到任意已运行的服务端，`@opencode-ai/sdk` 则让 Node/TypeScript 程序直接驱动这套 API。

理解这一层之后，很多事情就顺了：CI 里跑一条命令、给团队共享一个后端、用脚本批量处理会话、给编辑器写集成，都是同一组接口的不同前端。

```text
本篇要解决的问题：
1. serve 模式怎么起、端口/hostname/CORS/基础认证怎么配
2. 服务端暴露了哪些 HTTP 接口（会话、消息、文件检索、MCP、权限响应）
3. 用 @opencode-ai/sdk 建会话、发消息、订阅事件的最小可用代码
4. GitHub Actions 里 @opencode 触发任务，以及多端（TUI / Web / 编辑器 / SDK）接入方式
```

本篇命令与响应以 opencode `1.19.0`、`@opencode-ai/sdk@1.19.0` 实测为准；官方文档见 `https://opencode.ai/docs/server/`、`https://opencode.ai/docs/sdk/`、`https://opencode.ai/docs/github/`。

## serve 模式与 server 配置

`opencode serve` 启动一个无界面的 HTTP 服务，供 SDK、attach、Web 前端使用：

```shell
# 最简：绑定 127.0.0.1，随机端口
opencode serve

# 指定端口与监听地址
opencode serve --port 4096 --hostname 0.0.0.0

# 开启 mDNS 发现（局域网内其他设备可发现该服务），自定义域名
opencode serve --mdns --mdns-domain myproject.local

# 额外放行某个浏览器来源的 CORS
opencode serve --cors https://app.example.com

# 打开基础认证：用户名默认 opencode，可用 OPENCODE_SERVER_USERNAME 覆盖
OPENCODE_SERVER_PASSWORD=secret opencode serve --port 4096 --hostname 0.0.0.0
```

实测启动日志（未设密码时官方会明确提示不安全）：

```text
Warning: OPENCODE_SERVER_PASSWORD is not set; server is unsecured.
opencode server listening on http://127.0.0.1:4098
```

同样的配置也可以写在 `opencode.json` 的 `server` 块里（命令行参数优先级更高）：

```json
{
  "$schema": "https://opencode.ai/config.json",
  "server": {
    "port": 4096,
    "hostname": "0.0.0.0",
    "mdns": true,
    "mdnsDomain": "myproject.local",
    "cors": ["http://localhost:5173"]
  }
}
```

可用项：`port`（监听端口）、`hostname`（监听地址，开 mDNS 且未指定时默认 `0.0.0.0`）、`mdns`、`mdnsDomain`（默认 `opencode.local`）、`cors`（额外的浏览器来源，必须是完整 origin，如 `https://app.example.com`）。

```text
serve 模式要点：
1. opencode 不带参数进 TUI，带 serve 进服务端，两者共享同一套会话数据
2. 默认绑定 127.0.0.1，要给别人用必须显式 --hostname 0.0.0.0
3. 对外暴露前必须设 OPENCODE_SERVER_PASSWORD，否则是未鉴权服务
4. 前端在别的域上时用 cors 放行完整 origin
5. server 配置写在 opencode.json 后，serve / web 都会生效
```

## HTTP API 概览

服务端接口按资源分组，路径与响应类型都可以从 SDK 生成类型（`@opencode-ai/sdk/dist/gen/types.gen.ts`）中逐一核对。常用接口：

| 分组 | 方法与路径 | 说明 |
|------|------------|------|
| 环境 | `GET /path`、`GET /vcs` | 当前工作目录、状态目录、VCS 信息 |
| 配置 | `GET /config`、`PATCH /config`、`GET /config/providers` | 读写配置、列出 provider 与默认模型 |
| 会话 | `GET /session`、`POST /session`、`GET /session/:id`、`GET /session/:id/children` | 列出、创建、查询会话与子会话 |
| 会话操作 | `POST /session/:id/abort`、`/summarize`、`/revert`、`/unrevert`、`/fork`、`/share`、`/diff`、`/todo` | 中断、压缩、回退、复制、分享、看 diff 与待办 |
| 消息 | `GET/POST /session/:id/message`、`POST /session/:id/prompt_async` | 发消息并等待响应；异步版立即返回 204 |
| 权限 | `POST /session/:id/permissions/:permissionID` | 响应运行中的权限弹窗（once / always / reject） |
| 文件检索 | `GET /find`、`/find/file`、`/find/symbol`、`/file`、`/file/content`、`/file/status` | 全文搜索、按名找文件、符号查找、列目录、读文件 |
| 状态 | `GET /lsp`、`GET /formatter`、`GET /mcp`、`POST /mcp`、`GET /agent`、`GET /command` | 各子系统状态；`POST /mcp` 可动态加服务 |
| 事件 | `GET /event`、`GET /global/event` | 事件流（SSE），用于订阅会话与工具的执行过程 |
| 其他 | `GET /project`、`GET /provider`、`POST /auth/:id`、`GET /doc` | 项目列表、provider 列表、写入凭据、OpenAPI 规格 |

实测几个最基础的调用：

```text
$ curl -s http://127.0.0.1:4097/path
{"home":"/root","state":"/root/.local/state/opencode","config":"/root/.config/opencode","worktree":"/","directory":"/your/project"}

$ curl -s http://127.0.0.1:4097/session
[]

$ curl -s -X POST -H 'content-type: application/json' -d '{}' http://127.0.0.1:4097/session
{"id":"ses_ec4d5cddbffe47cXM3fYp3B6Bs","slug":"silent-squid","projectID":"global","directory":"/your/project","path":"your/project","cost":0,"tokens":{"input":0,"output":0,"reasoning":0,"cache":{"read":0,"write":0}},"title":"New session - 2026-10-14T16:06:23.525Z","version":"1.19.0","time":{"created":1791993983525,"updated":1791993983525}}
```

发消息的请求体字段（`POST /session/:id/message`）：`parts`（内容数组，元素可为文本、文件、agent、子任务）、`agent`、`model`（`{ providerID, modelID }`）、`system`、`tools`（按工具名开关）、`noReply`（只写上下文不要回复）。异步发送用 `/session/:id/prompt_async`，返回 `204`。

OpenAPI 规格可以通过 `GET /doc` 拿到，用它生成任意语言的客户端是最稳的做法。

```text
HTTP API 要点：
1. 所有接口都以 /session、/find、/file、/mcp 这类资源前缀分组
2. 发消息是 POST /session/:id/message，异步版是 prompt_async（204）
3. 权限弹窗可以从外部响应：POST /session/:id/permissions/:permissionID
4. 事件流是 SSE，用 GET /event 订阅，适合做进度展示与自动化触发
5. GET /doc 提供 OpenAPI 3.1 规格，用它可以生成自己语言的客户端
```

## JavaScript SDK 调用

SDK 是官方提供的类型安全客户端：`@opencode-ai/sdk`，类型全部由服务端 OpenAPI 规格生成。

```shell
npm install @opencode-ai/sdk@1.19.0
```

导出的入口有四个：`createOpencode`（起服务端并返回客户端）、`createOpencodeServer`（只起服务端）、`createOpencodeTui`（起带 TUI 的服务端）、`createOpencodeClient`（连已有服务端）。

```javascript
import { createOpencode } from "@opencode-ai/sdk"

// 启动子进程服务端 + 拿到客户端（默认 127.0.0.1:4096，启动超时 5000ms）
const opencode = await createOpencode({
  hostname: "127.0.0.1",
  port: 4096,
  config: { model: "opencode/big-pickle" },
})
console.log(`Server running at ${opencode.server.url}`)
opencode.server.close()
```

`createOpencodeClient` 用于连接已经在跑的服务端，`baseUrl` 指向它：

```javascript
import { createOpencodeClient } from "@opencode-ai/sdk"

const client = createOpencodeClient({ baseUrl: "http://127.0.0.1:4096" })
```

本机实测（连接一个 `opencode serve --port 4097` 实例，`@opencode-ai/sdk@1.19.0` + Node 22）：

```javascript
// smoke.mjs
import { createOpencodeClient } from "@opencode-ai/sdk"

const client = createOpencodeClient({ baseUrl: "http://127.0.0.1:4097" })

const p = await client.path.get()
console.log("path.directory =", p.data.directory)

const models = await client.config.providers()
console.log("providers =", models.data.providers.map((x) => x.id).join(","))

const ses = await client.session.create({ body: { title: "sdk-smoke" } })
console.log("session.id =", ses.data.id, "title =", ses.data.title)

const list = await client.session.list()
console.log("session.count =", list.data.length)

const agents = await client.app.agents()
console.log("agents =", agents.data.map((a) => a.name + "/" + a.mode).join(","))
```

```text
$ node smoke.mjs
path.directory = /your/project
providers = opencode
session.id = ses_ec4d541c4ffedFVNerY9MIblCW title = sdk-smoke
session.count = 2
agents = build/primary,compaction/primary,explore/subagent,general/subagent,plan/primary,summary/primary,title/primary
```

返回结构统一是 `{ data, error, request, response }`，所以 `res.data` 是业务数据。会话相关的方法（与 HTTP 接口一一对应）：

| 方法 | 作用 |
|------|------|
| `session.list()` / `session.get({ path })` / `session.children({ path })` | 列出、查询、列子会话 |
| `session.create({ body })` | 创建会话，`body` 可带 `title` / `parentID` |
| `session.prompt({ path, body })` | 发送提示并等待助手回复；`body.noReply: true` 只写上下文 |
| `session.promptAsync({ path, body })` | 异步发送，立即返回 |
| `session.command({ path, body })` | 触发一个自定义命令 |
| `session.shell({ path, body })` | 在会话里执行 shell 命令 |
| `session.messages({ path })` | 取会话消息 |
| `session.abort({ path })` / `session.summarize(...)` / `session.revert(...)` | 中断、压缩、回退 |

`session.prompt` 的 `body` 形状（实测类型定义）：

```javascript
await client.session.prompt({
  path: { id: sessionID },
  body: {
    agent: "build",                                   // 可选：指定 agent
    model: { providerID: "opencode", modelID: "big-pickle" }, // 可选：覆盖模型
    system: "You are working on a Go monorepo.",      // 可选：追加系统提示
    tools: { write: false },                          // 可选：按工具名开关
    parts: [{ type: "text", text: "解释这个仓库的目录结构" }],
  },
})
```

其它常用命名空间：`config.get()` / `config.providers()`、`app.agents()` / `app.log()`、`file.read()` / `file.list()` / `file.status()`、`find.text()` / `find.files()` / `find.symbols()`、`mcp.status()` / `mcp.add()`、`lsp.status()`、`formatter.status()`、`event.subscribe()`。

```text
SDK 要点：
1. 四个入口：createOpencode / createOpencodeServer / createOpencodeTui / createOpencodeClient
2. 默认端口 4096，createOpencode 的启动超时默认 5000ms，可传 timeout 调大
3. 响应统一 { data, error }，业务数据在 res.data
4. 方法名与 HTTP 路径一一对应：session.prompt 即 POST /session/:id/message
5. 想流式看过程用 event.subscribe，而不是轮询 session.messages
```

## GitHub 集成

OpenCode 提供官方 GitHub App 与 Actions 集成：在 issue 或 PR 评论里 `@opencode` 或 `/oc`，它就作为 GitHub Actions 任务执行，能建分支、开 PR、回复评论或审查代码。

安装两步：

```shell
# 1) 安装 GitHub App 到目标仓库，然后
opencode github install

# 2) 或在仓库里手写 workflow
mkdir -p .github/workflows
```

```yaml
# .github/workflows/opencode.yml
name: opencode

on:
  issue_comment:
    types: [created]
  pull_request_review_comment:
    types: [created]

jobs:
  opencode:
    if: contains(github.event.comment.body, '/oc') || contains(github.event.comment.body, '/opencode')
    runs-on: ubuntu-latest
    permissions:
      id-token: write
      contents: write
      pull-requests: write
      issues: write
    steps:
      - uses: actions/checkout@v6
        with:
          persist-credentials: false
      - uses: anomalyco/opencode/github@latest
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
        with:
          model: anthropic/claude-sonnet-4-20250514
          agent: build
          share: true
```

配置项：`model`（必填，`provider/model` 格式）、`agent`（必须是 primary agent，缺省回落到配置里的 `default_agent` 或 `build`）、`share`（是否分享会话，公开仓库默认 true）、`prompt`（自定义提示，覆盖默认行为）、`mentions`（触发短语，逗号分隔，默认 `/opencode,/oc`）、`variant`（推理档位）、`oidc_base_url`、`use_github_token`。

`use_github_token: true` 可以不装 GitHub App，直接用自己的 token：

```yaml
      - uses: anomalyco/opencode/github@latest
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
        with:
          model: anthropic/claude-sonnet-4-20250514
          use_github_token: true
```

支持的事件：`issue_comment`（评论里 @ 触发）、`pull_request_review_comment`（行级评论，能拿到文件路径、行号与 diff 上下文）、`issues`（issue 创建或编辑，需要 `prompt`）、`pull_request`（PR 打开或更新，适合自动审查）、`schedule`（定时运行，需要 `prompt`，输出只进日志和 PR）。定时任务示例：

```yaml
name: weekly-opencode-audit

on:
  schedule:
    - cron: "0 9 * * 1"

jobs:
  audit:
    runs-on: ubuntu-latest
    permissions:
      id-token: write
      contents: write
      pull-requests: write
      issues: write
    steps:
      - uses: actions/checkout@v6
        with:
          persist-credentials: false
      - uses: anomalyco/opencode/github@latest
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
        with:
          model: anthropic/claude-sonnet-4-20250514
          prompt: |
            Review the codebase for any TODO comments and create a summary.
            If you find issues worth addressing, open an issue to track them.
```

定时任务没有评论可以取指令，所以 `prompt` 是必填；也因为没有人可以点权限弹窗，需要建分支或 PR 时必须显式给 `contents: write` 与 `pull-requests: write`。

```text
GitHub 集成要点：
1. 评论里 @opencode 或 /oc 触发，触发词可用 mentions 改
2. model 必填且是 provider/model 格式；agent 必须是 primary agent
3. 不装 App 就 use_github_token: true 走自己的 token，不再需要 id-token write
4. issues / schedule / pull_request 事件必须显式给 prompt
5. 无人值守场景要给足 permissions，尤其 contents 与 pull-requests 的 write
```

## 多端接入与 attach

同一套服务端可以同时挂多个前端：

| 前端 | 启动方式 | 适用场景 |
|------|----------|----------|
| TUI | `opencode` | 本地交互开发 |
| Web | `opencode web --port 4096` | 浏览器访问、移动端/远程桌面 |
| attach TUI | `opencode attach http://<host>:4096` | 本地 TUI + 远端后端，或共用同一会话 |
| ACP | `opencode acp` | 编辑器集成（Agent Client Protocol，stdin/stdout 走 nd-JSON） |
| SDK 客户端 | `@opencode-ai/sdk` | 自建应用、机器人、CI 脚本 |
| Desktop | OpenCode Desktop | 图形客户端（内部就是本地 serve 的 sidecar） |

```shell
# 远端起后端，局域网可访问
opencode web --port 4096 --hostname 0.0.0.0

# 输出会同时给出本地与网络地址
#   Local access:   http://localhost:4096
#   Network access: http://192.168.1.100:4096

# 另一个终端把 TUI 接上去（共享同一批会话）
opencode attach http://10.20.30.40:4096

# 单次命令直连已运行的服务端，避免每次都冷启动 MCP
opencode run --attach http://localhost:4096 "解释一下这个改动的影响面"

# 编辑器集成
opencode acp --cwd /path/to/project
```

本机实测：向一个已在运行的服务端 `opencode run --attach http://127.0.0.1:4099 "..."`，会话确实创建在远端实例上（`opencode session list` 里能看到该会话标题）。

`attach` 与 `run --attach` 都支持基础认证参数：`--username`（默认取 `OPENCODE_SERVER_USERNAME` 或 `opencode`）、`--password`（默认取 `OPENCODE_SERVER_PASSWORD`）。

```text
多端接入要点：
1. Web 与 TUI 可同时用同一批会话，数据在服务端而非前端
2. attach 让本地 TUI 连远端后端，适合"算力在服务器、界面在本地"
3. run --attach 复用常驻服务端，省掉 MCP 冷启动开销
4. ACP 面向编辑器集成，走 stdin/stdout 的 nd-JSON
5. 访问受保护的实例要带 --username / --password 或对应环境变量
```

## 应用场景实战

### 场景一：给团队搭一个常驻 serve 后端（systemd + 密码 + 远端接入）

目标：在一台开发服务器上常驻 opencode 服务端，团队成员用 `attach` 或浏览器接入，服务端负责所有会话与文件操作。

```shell
# 1) 生成一个强随机密码并放进环境文件
sudo mkdir -p /etc/opencode
openssl rand -hex 32
```

```shell
# /etc/opencode/opencode.env
OPENCODE_SERVER_PASSWORD=把上面生成的随机串粘进来
OPENCODE_SERVER_USERNAME=opencode
```

```ini
# /etc/systemd/system/opencode.service
[Unit]
Description=OpenCode headless server
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=dev
WorkingDirectory=/srv/repos/platform
EnvironmentFile=/etc/opencode/opencode.env
# --hostname 0.0.0.0 供局域网接入；务必配上密码
ExecStart=/usr/local/bin/opencode serve --port 4096 --hostname 0.0.0.0 --mdns --mdns-domain platform.local
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```shell
# 2) 启用并启动
sudo systemctl daemon-reload
sudo systemctl enable --now opencode
sudo systemctl status opencode --no-pager

# 3) 验证监听与鉴权
curl -s -m 5 http://127.0.0.1:4096/path
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:4096/session

# 4) 成员接入（本地 TUI 连远端后端）
opencode attach http://platform.local:4096 --username opencode

# 5) 或直接在浏览器访问 http://platform.local:4096
```

关键点：服务端只监听内网；密码走 `EnvironmentFile` 而不是写进 unit；`WorkingDirectory` 决定服务端默认工作目录与 `external_directory` 判定的基准。

### 场景二：用 SDK 写一个批量审查脚本（CI 可用）

目标：对一组文件逐个建会话、发提示、取回结果，并把过程串成一份报告；用 `event.subscribe` 观察工具调用而不是轮询。

```javascript
// review-batch.mjs
import { createOpencodeClient } from "@opencode-ai/sdk"

const client = createOpencodeClient({
  baseUrl: process.env.OPENCODE_BASE_URL ?? "http://127.0.0.1:4096",
})

const files = ["src/payment/service.go", "src/payment/router.go", "src/order/repo.py"]

// 1) 订阅事件流：观察工具调用与错误（可选但推荐）
const events = await client.event.subscribe()
for await (const e of events.stream) {
  if (e.type === "session.error") console.error("[session.error]", JSON.stringify(e.properties))
  if (e.type === "tool.execute.after") console.log("[tool]", e.properties?.tool ?? "")
}

// 2) 逐个文件建会话并提问
const report = []
for (const file of files) {
  const ses = await client.session.create({ body: { title: `review ${file}` } })
  const res = await client.session.prompt({
    path: { id: ses.data.id },
    body: {
      agent: "plan",                                  // 只读 agent，避免误改
      model: { providerID: "anthropic", modelID: "claude-sonnet-4-20250514" },
      system: "You only report findings. Never modify files.",
      parts: [
        { type: "text", text: `审查 ${file} 的安全与性能问题，输出 Markdown 表格。` },
      ],
    },
  })
  const text = res.data.parts
    .filter((p) => p.type === "text")
    .map((p) => p.text)
    .join("\n")
  report.push(`## ${file}\n\n${text}`)
}

// 3) 输出汇总
console.log(report.join("\n\n"))
```

## 最佳实践与踩坑记录

### 最佳实践

1. 对外暴露的服务端必须设 `OPENCODE_SERVER_PASSWORD`，并只监听内网地址
2. 用 systemd 常驻 `serve`，把密码放 `EnvironmentFile`，别写进 unit 或 Git
3. 脚本化调用优先复用常驻实例（`--attach` 或连接已有 `baseUrl`），避免每次冷启动 MCP
4. 程序化审查类任务用只读 agent（如 `plan`）加 `system` 约束，把改代码的权限留给人
5. 需要看过程时订阅 `/event` SSE 或 `event.subscribe()`，不要轮询消息接口
6. 跨语言集成时用 `GET /doc` 的 OpenAPI 规格生成客户端，比手写 HTTP 调用稳

### 踩坑记录

```text
坑 1：serve 起在 0.0.0.0 但忘了设密码
结论：局域网上任何人都能读写你的工作区文件、调用你的模型额度。
原因：未设置 OPENCODE_SERVER_PASSWORD 时服务端不做鉴权，启动日志只有一行 Warning。
实测日志：Warning: OPENCODE_SERVER_PASSWORD is not set; server is unsecured.
解法：务必设 OPENCODE_SERVER_PASSWORD（用户名默认 opencode，可用 OPENCODE_SERVER_USERNAME 改），或用防火墙限制来源。

坑 2：脚本里每次 opencode run 都要等 MCP 冷启动
结论：批量跑几十次，每次都要多等好几秒甚至几十秒。
原因：每次 run 都会拉起独立实例，本地 MCP 服务（npx 起始）每次都要重新启动。
解法：先常驻一个 opencode serve，之后用 opencode run --attach http://localhost:4096 复用，或直接用 SDK 连接同一实例。

坑 3：SDK 里端口写死 4096，和本机已有服务冲突
结论：createOpencode 连接失败或连错了实例。
原因：SDK 默认端口是 4096，而 CLI 的 --port 默认是 0（随机端口），两边的"默认"并不一致。
解法：显式指定同一端口；连已有实例时用 createOpencodeClient({ baseUrl }) 明确指向，别依赖默认值。

坑 4：createOpencode 偶发启动超时
结论：报服务器启动超时，进程被杀。
原因：createOpencode 的启动超时默认 5000ms，冷启动或加载大量 MCP 插件时不够。
解法：传更大的 timeout（如 30000），或用 createOpencodeServer 自己控制启动时机再加客户端连接。

坑 5：GitHub 定时任务与 issue 事件不触发
结论：workflow 跑了但 OpenCode 没做任何事，日志里没有报错细节。
原因：schedule 与 issues 事件没有评论可取指令，官方要求显式提供 prompt；另外 model 是必填项。
解法：给这两类事件补 with.prompt 与 with.model，并确认 secrets 里的 API Key 已就位。
```

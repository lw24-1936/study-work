## 概述

OpenCode 的日常入口是全屏 TUI：输入框里写自然语言，模型读写文件、跑命令，结果以 diff 与工具调用详情的形式回流到对话里。用好 TUI 的关键是三件事——知道界面各区域在说什么、把 leader 键与斜杠命令形成肌肉记忆、理解 Build 与 Plan 两种模式的权限差异。再加上 `@` 引用文件与 `!` 直接执行命令，整套「会话 + 上下文」的操作就闭环了。

```text
本节要点：
1. 启动 —— opencode（当前目录）或 opencode /path/to/project；-c 继续上次会话，-s 指定会话 ID
2. 布局 —— 对话区（含 diff 与工具详情）+ 输入框 + 状态栏（模型、agent、auto 指示）
3. 快捷键 —— 默认 leader 是 ctrl+x，命令面板 ctrl+p，确认选择器等交互靠键位配置改
4. 会话管理 —— /new 新建、/sessions 切换、/undo /redo 回退重做、/compact 压缩、/export 导出
5. 模式 —— Tab 在 primary agent 间切换，内置 Build（全工具）与 Plan（编辑与 bash 默认 ask）
6. 上下文附加 —— @ 模糊找文件、! 跑 shell、图片拖进终端、--file 在非交互模式附加
```

## TUI 启动与界面布局

启动方式有三种：不带参数用当前目录、带位置参数指定目录、`-c` 继续上一次会话。TUI 启动后会占据整个终端，界面自上而下大致是「对话区 → 输入框 → 状态栏」。对话区里，模型的文件改动以 diff 呈现，工具调用可以展开看详情；状态栏显示当前模型与 agent，开启自动批准时会显示 `auto` 标识。

```bash
# 三种启动方式
opencode                        # 当前目录
opencode /path/to/project       # 指定工作目录
opencode -c                     # 继续上一次会话
opencode -s <session-id>        # 继续指定会话（可配 --fork 从该会话分叉）
```

```text
# 本机实测：在项目目录启动 TUI（伪终端下渲染正常）
$ cd /root/.hermes/cache/scratch/oc-test && opencode
# 界面渲染出 OpenCode 的 ASCII 标识与版本号 1.19.0
# 右下角提示：/update to upgrade to OpenCode 2.0
```

带参数的启动选项（TUI 相关，节选自官方 CLI 文档与 `opencode --help`）：

| 参数 | 简写 | 说明 |
| --- | --- | --- |
| `--continue` | `-c` | 继续上一次会话 |
| `--session` | `-s` | 指定要继续的会话 ID |
| `--fork` | | 继续会话时分叉出新会话（需与 `-c`/`-s` 同用） |
| `--prompt` | | 启动时预填提示词 |
| `--model` | `-m` | 指定模型，格式 `provider/model` |
| `--agent` | | 指定 agent |
| `--auto` | | 自动批准未被显式拒绝的权限请求（危险操作） |
| `--port` / `--hostname` | | 本地服务监听端口/主机 |
| `--mdns` / `--mdns-domain` | | 开启 mDNS 服务发现及其域名 |
| `--cors` | | 允许的额外浏览器来源 |
| `--mini` | | 启动最小化界面 |

```text
TUI 启动与布局要点：
1. 默认行为 —— 不带参数即在当前目录开新会话；opencode <目录> 指定工作目录
2. 续会话 —— -c 继续最近一次，-s <id> 指定会话，--fork 从既有会话分叉出新分支
3. 界面构成 —— 对话区（diff + 工具详情）+ 输入框 + 状态栏（模型 / agent / auto 标识）
4. 交互式配置 —— 命令面板 ctrl+p 里可切换「显示用户名」「自动批准」等开关，设置会持久化
5. 常用开关 —— --auto 自动批准（会绕过确认，慎用），--mini 极简界面
6. 远程/嵌入式 —— --port/--hostname/--mdns 让 TUI 连本地服务或供其他设备接入
```

## 快捷键与 leader 键

OpenCode 用 leader 键来避免与终端本身的快捷键冲突，默认 leader 是 `ctrl+x`，等待下一个按键的时间由 `leader_timeout` 控制（默认 2000 毫秒）。所有键位都在 `tui.json` 的 `keybinds` 里配置，且与内置默认值做合并——只需要写想改的那几个。把某个键设为 `"none"` 就是禁用该快捷键。

```json
// ~/.config/opencode/tui.json（TUI 专属配置，与 opencode.json 分开）
{
  "$schema": "https://opencode.ai/tui.json",
  "leader_timeout": 2000,
  "keybinds": {
    "leader": "ctrl+x",
    "command_list": "ctrl+p",
    "session_compact": "none"
  }
}
```

常用默认键位（来自官方 keybinds 文档，节选）：

| 快捷键 | 动作 |
| --- | --- |
| `ctrl+x` | leader 前缀键（等待后续按键） |
| `ctrl+p` | 打开命令面板（command_list） |
| `ctrl+x n` | 新建会话（session_new，别名 `/new`） |
| `ctrl+x l` | 会话列表并切换（session_list，别名 `/sessions`） |
| `ctrl+x m` | 模型列表（model_list，别名 `/models`） |
| `ctrl+x a` | agent 列表（agent_list） |
| `ctrl+x c` | 压缩当前会话（session_compact，别名 `/compact`） |
| `ctrl+x u` / `ctrl+x r` | 撤销 / 重做消息（messages_undo / messages_redo） |
| `ctrl+x x` | 导出会话（session_export，别名 `/export`） |
| `ctrl+x e` | 打开外部编辑器撰写（editor_open，别名 `/editor`） |
| `ctrl+x t` | 主题列表（theme_list） |
| `ctrl+x q` | 退出（app_exit，另有 ctrl+c / ctrl+d） |
| `tab` / `shift+tab` | 切换 primary agent（agent_cycle / agent_cycle_reverse） |
| `f2` / `shift+f2` | 在最近使用的模型间循环（model_cycle_recent） |
| `ctrl+t` | 切换模型 variant（variant_cycle） |
| `ctrl+alt+k` | which-key 键位速查浮层（which_key_toggle） |
| `escape` | 中断当前生成（session_interrupt） |
| `pageup` / `pagedown` | 对话区翻页（messages_page_up / messages_page_down） |
| `ctrl+g` / `end` | 跳到对话开头 / 结尾（messages_first / messages_last） |
| `ctrl+r` / `ctrl+d` | 会话重命名 / 删除（session_rename / session_delete） |

键位可以写多个候选值，也可以精细控制是否阻止终端默认行为：

```json
{
  "$schema": "https://opencode.ai/tui.json",
  "keybinds": {
    "messages_copy": ["<leader>y", "ctrl+shift+c"],
    "input_paste": { "key": "ctrl+v", "preventDefault": false }
  }
}
```

记不住键位时按 `ctrl+alt+k` 调出 which-key 浮层，它会把当前上下文可用的快捷键分组列出，比翻文档快。

```text
快捷键要点：
1. leader 机制 —— 默认 ctrl+x，leader_timeout 默认 2000ms，超时则视为取消组合
2. 合并语义 —— keybinds 与内置默认值合并，只写要改的项；值为 "none" 或 false 即禁用
3. 速查方式 —— ctrl+alt+k 打开 which-key 浮层，按上下文分组展示可用键位
4. 高频三键 —— ctrl+p（命令面板）、ctrl+x l（会话切换）、ctrl+x c（压缩会话）
5. 模式与模型 —— tab 切 agent、f2 循环模型、ctrl+t 切 variant，都在会话中即时生效
6. 冲突处理 —— 与终端冲突的键位可在 tui.json 改写，或改用 leader 组合
```

## 斜杠命令与会话管理

斜杠命令是 TUI 内的「动词表」：以 `/` 开头，多数等价于某个 leader 组合键。会话相关的命令构成一条完整生命周期——新建、续接、回退、重做、压缩、导出、删除。其中 `/undo` 与 `/redo` 依赖 Git 管理文件改动，因此项目必须是 Git 仓库；`/compact` 用来手动压缩上下文。

```text
# 会话生命周期相关命令
/new          # 新会话（别名 /clear，键 ctrl+x n）
/sessions     # 会话列表并切换（别名 /resume、/continue，键 ctrl+x l）
/compact      # 压缩当前会话（别名 /summarize，键 ctrl+x c）
/undo         # 撤销最近一条用户消息、其后的回复与文件改动（键 ctrl+x u）
/redo         # 重做（仅 /undo 之后可用，键 ctrl+x r）
/export       # 导出当前会话为 Markdown 并打开编辑器（键 ctrl+x x）
/editor       # 用外部编辑器撰写消息（键 ctrl+x e）
/details      # 切换工具执行详情显示
/thinking     # 切换思考块显示（只影响展示，不代表开启/关闭推理）
/themes       # 主题列表（键 ctrl+x t）
/help         # 帮助面板
/exit         # 退出（别名 /quit、/q，键 ctrl+x q）
```

命令行侧有等价的会话管理能力，适合脚本与远程维护：

```bash
# 列出会话（-n 限制条数，--format json 便于机器解析）
opencode session list
opencode session list -n 5 --format json

# 删除会话
opencode session delete <sessionID>

# 导出会话为 JSON（--sanitize 会脱敏转写与文件内容）
opencode export <sessionID>
opencode export --sanitize <sessionID>

# 从 JSON 文件或分享链接导入会话
opencode import session.json
opencode import https://opncd.ai/s/abc123

# 用量与成本统计（--models 展示模型维度，--project 过滤项目）
opencode stats --days 7 --models 5
```

```text
1. 生命周期 —— /new 新建、/sessions 切换、/compact 压缩、/export 导出、/exit 退出

6. 命令面板 —— 记不住命令时先按 ctrl+p 搜，或 /help 看清单
```

## Build 与 Plan 模式

OpenCode 内置两类 agent：primary agent（主对话，用 Tab 切换）与 subagent（由主 agent 调用或用 `@` 唤起）。内置 primary agent 是 Build 与 Plan：Build 是全工具可用的默认 agent；Plan 是受限的分析型 agent，默认把文件修改与 bash 都设为 `ask`，因此只给方案不动代码。除此之外还有 General、Explore、Scout 三个内置子代理，分别面向通用多步任务、只读代码探索、外部文档与依赖研究。

```text
# 内置 agent 一览（官方文档）
build      primary    全工具可用，默认 agent，适合直接改代码
plan       primary    文件修改与 bash 默认 ask，只分析给方案
general    subagent   通用多步任务，工具全开，可并行跑多个工作单元
explore    subagent   只读，快速按模式找文件、按关键词搜代码
scout      subagent   只读，面向外部文档与依赖源码研究

# 切换方式
Tab / shift+tab   在 primary agent 之间循环（状态栏会变）
@agent 名          在消息里 @ 唤起子代理
opencode --agent plan     启动时指定
opencode run --agent refactor "..."   非交互指定 agent
```

模式差异的本质是权限（permission）。默认权限偏宽松，Plan 的价值在于把「改动」这一动作强制变成询问；也可以自己定义更细的规则，例如允许查 git 但禁止 push：

```json
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "bash": {
      "*": "ask",
      "git *": "allow",
      "git commit *": "deny",
      "git push *": "deny",
      "grep *": "allow"
    }
  }
}
```

启动时用 `--auto` 会自动批准「未被显式拒绝」的请求（`deny` 规则依然生效），TUI 里也可以在命令面板切换自动批准：开启后状态栏会出现 `auto` 标识。

```text
Build 与 Plan 要点：
1. 两类 agent —— primary（主对话，Tab 切换）与 subagent（@ 唤起或被主 agent 调用）
2. 内置组合 —— Build/Plan 是 primary；General/Explore/Scout 是 subagent
3. Plan 的语义 —— 通过权限把 edit 与 bash 置为 ask，从而「只出方案不改代码」
4. 自动批准 —— --auto 仅放宽「本会询问」的动作，显式 deny 始终生效，状态栏有 auto 标识
5. 细粒度权限 —— bash/edit/webfetch 等可按模式匹配写规则，最后一条匹配的规则生效
6. 默认回退 —— default_agent 指定不存在的 agent 或误填 subagent 时，会回退到 build 并给出警告
```

## 文件引用与上下文附加

给模型上下文有三条就地通道：`@` 做模糊文件检索并把文件内容加入对话、`!` 直接执行 shell 命令并把输出作为工具结果、图片直接拖进终端。此外，配置过的 references 也会出现在 `@` 补全里，输入 `@alias` 加入引用根目录，输入 `@alias/` 补全该根下的文件。非交互模式则用 `-f` 附加文件。

```text
# 在 TUI 输入框里的三种写法
How is auth handled in @packages/functions/src/api/index.ts?   # @ 引用文件内容
Compare our setup with @docs/README.md                          # 多文件对比
!ls -la                                                         # ! 执行命令，输出进上下文

# 图片：直接把图片文件拖进终端，会作为图片附加进提示词
```

```bash
# 非交互模式附加文件与目录级上下文
opencode run -f src/api.go -f README.md "这两个文件有什么不一致？"
opencode run --file architecture.md "按这份设计文档列出改动清单"

# 指定目录与模型，避免依赖上次使用的模型
opencode run --dir /path/to/repo -m anthropic/claude-sonnet-4-5 "总结今天的改动"
```

```text
# 实测观察：上下文是否真的进了请求（用本地模拟端点抓请求体）
$ opencode run -m mocklocal/mock-gpt "hi"
> build · mock-gpt

pong from mock model

# 服务端收到的请求体里，system 消息包含：
#   Instructions from: <项目路径>/AGENTS.md
#   Working directory: <项目路径>
#   Platform: linux / Today's date: ...
# 说明项目规则、工作目录与环境信息都会自动注入系统提示
```

```text
上下文附加要点：
1. @ 引用 —— 在消息里写 @ 触发模糊检索，命中即把文件内容加入对话，大文件要谨慎
2. ! 执行 —— 以 ! 开头的消息按 shell 命令执行，输出作为工具结果进上下文
3. 图片 —— 拖拽进终端即可附加，OpenCode 会按配置自动缩放（默认超过 2000x2000 或 5MB 会处理）
4. references —— 配置过的引用根会出现在 @ 补全里，@alias 加根、@alias/ 补全其下文件
5. 非交互 —— opencode run 用 -f/--file 附加文件，可重复多次
6. 自动注入 —— AGENTS.md、工作目录、平台与日期会进入系统提示，无需手工粘贴
```

## 会话分享与导出

会话可以分享成公开链接，链接形如 `opncd.ai/s/<share-id>`，任何人拿到链接即可访问，所以默认是手动模式、必须显式 `/share`。三种模式分别对应「手动」「自动」「禁用」，在敏感项目与合规环境里应显式禁用并提交进项目配置。

```json
// 项目级 opencode.json：对团队强制关闭分享
{
  "$schema": "https://opencode.ai/config.json",
  "share": "disabled"
}
```

```text
# TUI 内分享操作
/share      # 生成公开链接并复制到剪贴板（默认模式下手动触发）
/unshare    # 取消分享，删除链接与相关数据

# 模式（配置文件 share 键）
"manual"    手动分享（默认）
"auto"      新会话自动分享并生成链接
"disabled"  完全禁用分享
```

```bash
# 环境变量方式：自动分享（一般只用于演示环境）
export OPENCODE_AUTO_SHARE=1

# 导出一份脱敏的会话 JSON（分享给外部排障时用，先脱敏）
opencode export --sanitize <sessionID>
```

分享的隐私边界要说清楚：一旦分享，完整会话历史、消息、会话元数据都会同步到官方服务器并保持公开，直到你显式取消分享。企业环境可以对分享功能做整体禁用、限制为 SSO 用户或自托管，具体能力以官方文档为准。

```text
分享与导出要点：
1. 默认保守 —— 默认 manual，不主动 /share 就不会产生外链
2. 三种模式 —— manual / auto / disabled，项目级配置可提交 Git 以约束全团队
3. 取消分享 —— /unshare 会删除链接与相关数据，但已泄露内容不可追溯
4. 脱敏导出 —— opencode export --sanitize 会脱敏转写与文件数据，适合对外排障
5. 数据留存 —— 已分享会话包含完整历史与元数据，共享结束应及时 unshare
6. 企业约束 —— 可整体禁用、限制 SSO 或自托管，按官方企业文档落地
```

## 应用场景实战

### 场景一：用 Plan 模式做一次「先方案后实施」的数据库迁移

线上表结构要加软删除字段并新增回收站页面，直接让 agent 动手风险大。做法是先切 Plan 模式让它产出迁移方案与影响面，评审通过再切 Build 模式执行，最后用 `/undo` 兜底回滚。

```text
1. 启动并续上之前的上下文
   $ opencode -c
```

### 场景二：把一次排障会话导出、脱敏后交给同事接力

线上问题的排查过程往往要跨班次交接。做法是用 `/export` 或 `opencode export` 拿到会话，脱敏后入库或贴到工单；同事用 `opencode import` 把会话导回来继续，上下文不用口头复述。

```bash
# 1) 列出会话，找到要交接的那条
opencode session list -n 10

# 2) 导出为 JSON 并脱敏（去掉转写与文件内容里的敏感信息）
opencode export --sanitize ses_ec4d541c4ffedFVNerY9MIblCW > handover.json

# 3) 交给同事后，同事导入继续
opencode import handover.json
opencode -c                      # 继续最近会话
# 或从分享链接导入
opencode import https://opncd.ai/s/abc123
```

```text
# 会话内的等价操作（更适合人工交接）
/export      # 导出为 Markdown 并在编辑器里打开，可直接贴进工单
/details     # 需要审查工具调用细节时，展开工具执行详情
/compact     # 会话过长时先压缩再导出，文件更小、重点更集中
```

## 最佳实践与踩坑记录

### 最佳实践

1. 先 Plan 后 Build：改动面大的任务先切 Plan 拿方案，评审过再切 Build 执行，降低返工与误删风险
2. 项目必须是 Git 仓库：`/undo` 与 `/redo` 依赖 Git 管理文件改动，非 Git 目录会失去回退能力
3. 把 leader 键改成不与终端冲突的组合：在 `tui.json` 里改 `leader`，比改终端快捷键省事
4. 长会话及时 `/compact`：上下文将满时手动压缩，比等自动压缩更可控，重点保留得更好
5. 敏感项目显式关闭分享：项目级 `opencode.json` 写 `"share": "disabled"` 并提交 Git
6. 交接用 `--sanitize` 导出：对外排障先脱敏，再考虑是否分享链接

### 踩坑记录

```text
坑 1：/undo 报错或无法回退文件改动
结论：能对话但回退失败，改动留在工作区。
原因：/undo 与 /redo 用 Git 管理文件变更，当前目录不是 Git 仓库，或快照功能被 snapshot: false 关掉。
解法：在 Git 仓库内使用这些命令；不要为了省磁盘关掉 snapshot，否则 UI 侧无法回滚改动。

坑 2：leader 组合键没反应，或触发了终端的默认行为
结论：按 ctrl+x 后接按键无效果，或被终端拦截。
原因：终端自身占用了该组合键，或 leader_timeout 太短，第二个按键没赶上。
解法：在 tui.json 里改 leader 键或调大 leader_timeout；按 ctrl+alt+k 用 which-key 确认当前可用键位。

坑 3：分享链接把内部代码泄露出去了
结论：会话外链可被任何人打开，包含完整历史与文件内容。
原因：默认是手动分享，但误配 share: "auto" 或随手 /share 了敏感会话。
解法：项目配置里固定 "share": "disabled"；需要对外时改用 opencode export --sanitize 手工投递；已分享的及时 /unshare。

坑 4：@ 引用大文件后请求直接报上下文超限
结论：附加后模型报超上下文，或回答质量明显下降。
原因：@ 会把整个文件内容塞进对话，大文件/大目录一次引用过多；图片超过阈值也会被拒或省略。
解法：只引用相关文件与片段；用 limit.context 如实声明模型窗口；必要时先 /compact 再继续。

坑 5：误开 --auto 后 agent 直接跑了危险命令
结论：未被显式 deny 的操作自动通过，包含删除类命令。
原因：--auto 的设计就是「自动批准本会询问的动作」，只有显式 deny 规则能拦住。
解法：在配置里用 permission.bash 显式 deny 危险前缀（如 rm -rf *）；长期使用建议保留 ask，只在受控环境用 --auto。
```

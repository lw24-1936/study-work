## 概述

这一篇把前面几篇（特征工程、模型评估、降维聚类、强化学习）的能力串成**一个完整项目**：从问题定义、数据获取与字段字典，到 EDA、基线、候选模型对比、超参调优、阈值与代价决策，再到概率校准、模型落盘、FastAPI 上线、漂移监控与自动重训。全程以「信贷违约预测」为例，所有代码与输出都在本机真实跑过（20000 条申请、24 个月、含 8% 收入缺失与人为注入的后 4 个月分布漂移）。

项目实战与单点技术的差别在于**每一步都要对外承诺**：切分口径（时间切分而不是随机切分）、指标口径（PR-AUC 而不是准确率）、决策口径（按期望损失选阈值而不是 0.5）、上线口径（模型卡 + 阈值 + 版本号一起发布）、监控口径（PSI 与滚动窗口指标的触发规则）。本机的数字最有说服力的地方在于它有**漂移**：训练窗口违约率 5.4%，测试窗口 16.8%，老模型在最新一个月 AUC 0.7890，重训后 0.8515，刷新阈值后每千笔损失从 187698 元降到 146573 元。

```text
本篇主线：
1. 问题定义 —— 标签定义、评估口径、代价约定、时间切分策略（训练 16 个月 / 验证 4 个月 / 测试 4 个月）
2. 数据获取与 EDA —— 字段字典、缺失率、按月违约率、类别违约率、右偏与相关性
3. 基线 —— 全预测多数类基线、Dummy、逻辑回归 / 随机森林 / 直方图梯度提升的对比表
4. 迭代与调优 —— RandomizedSearchCV + TimeSeriesSplit、非嵌套分数的乐观性、代价敏感的阈值选择
5. 校准与模型卡 —— isotonic 校准、Brier、模型版本与上线元数据
6. 上线服务化 —— joblib 落盘、FastAPI 三个端点、真实 curl 请求与校验错误处理
7. 监控与重训 —— PSI / KS 漂移、分数分位点、按月滚动指标、触发规则与新分布上重选阈值
```

## 问题定义与数据获取

项目第一步是把业务问题翻译成可验收的 ML 问题，并且**写清楚四件事**：标签怎么定（违约 = 放款后 90 天内逾期 ≥ 30 天）、预测时点是什么（申请提交时刻，只能用该时刻已知的信息）、评估口径是什么（正样本稀少，主指标 PR-AUC + 代价加权损失，禁用准确率）、代价是什么（放给坏客户亏 3000 元，拒掉好客户损失 300 元）。这四条一旦含糊，后面所有指标都无处对齐。

数据获取阶段必须产出**字段字典**（类型、缺失率、唯一值数、是否在预测时可得），并对高基数与缺失字段单独标注。本机脚本生成 20000 条申请明细并落盘 CSV，模拟从数仓导出的过程：

## 基线模型与迭代对比

基线的作用是给出**下界**与**对照口径**。表格项目至少要有两个基线：全预测多数类（准确率基线）与 `DummyClassifier(strategy="prior")`，再上候选模型。比较时统一用 AUC / PR-AUC / Brier 三个指标，并在同一份验证窗口上评估。

```python
from sklearn.compose import ColumnTransformer
from sklearn.pipeline import Pipeline
from sklearn.impute import SimpleImputer
from sklearn.preprocessing import StandardScaler, OneHotEncoder, TargetEncoder
from sklearn.linear_model import LogisticRegression
from sklearn.ensemble import RandomForestClassifier, HistGradientBoostingClassifier
from sklearn.dummy import DummyClassifier
from sklearn.metrics import roc_auc_score, average_precision_score, brier_score_loss

pre = ColumnTransformer([
    ("num", Pipeline([("imp", SimpleImputer(strategy="median")), ("sc", StandardScaler())]), NUM_COLS),
    ("cat_low", OneHotEncoder(handle_unknown="ignore"), CAT_LOW),
    ("cat_high", TargetEncoder(target_type="binary", cv=5), CAT_HIGH),   # device 40 类
])
candidates = {
    "LogisticRegression": Pipeline([("pre", pre), ("clf", LogisticRegression(max_iter=2000, class_weight="balanced"))]),
    "RandomForest(300)": Pipeline([("pre", pre), ("clf", RandomForestClassifier(n_estimators=300, random_state=42, n_jobs=4))]),
    "HistGradientBoosting": Pipeline([("pre", pre), ("clf", HistGradientBoostingClassifier(random_state=42))]),
}
for name, pipe in candidates.items():
    pipe.fit(X_tr, y_tr)
    p = pipe.predict_proba(X_va)[:, 1]
    print(name, round(roc_auc_score(y_va, p), 4), round(average_precision_score(y_va, p), 4),
          round(brier_score_loss(y_va, p), 4))
```

三条必须写进结论的观察：**全预测「不违约」的准确率是 92.9%**，所以本项目的准确率指标没有任何意义；`Dummy` 的 PR-AUC 恰好等于正样本率（0.0710），**这就是 PR-AUC 的天然下界**，任何模型都必须显著高于它；逻辑回归在 AUC / PR-AUC 上反而最好（0.7948 / 0.2755），但它的 Brier 是 0.1970，远差于两个树模型（0.0593 / 0.0603）——因为 `class_weight="balanced"` 把概率整体抬高了，**排序能力好不代表概率准**。初版上线就选 AUC 最高的逻辑回归是一种合理选择（可解释、可给理由码），但若要用概率算期望损失，必须先校准。

```text
要点：
1. 先跑全预测多数类与 Dummy 基线：本机准确率基线 0.9290、PR-AUC 基线 0.0710（等于正样本率）
2. 同一窗口上并列比较 AUC / PR-AUC / Brier，三个指标各管一件事（排序、正类可用性、概率质量）
3. class_weight="balanced" 会显著抬高概率（本机逻辑回归 Brier 0.1970 vs 树模型 0.06），用它就必须校准
4. 高基数类别（本机 device 40 类）走目标编码，低基数（city/channel）走 one-hot，全部封在 ColumnTransformer 里
5. 候选模型至少覆盖线性与树两类（性能接近时优先选可解释的），不要只试一种
6. 每轮迭代都要在同一口径下重跑基线（本机表格一次跑出，避免口径漂移）
```

## 超参数调优与阈值决策

调优要解决两个独立问题：**参数怎么选**（模型复杂度）与**阈值怎么定**（业务决策）。参数用 `RandomizedSearchCV` + `TimeSeriesSplit`（时序数据不能用随机 KFold），阈值在**验证集**上按期望损失最小化选，然后在测试集上复核。

```python
from sklearn.model_selection import RandomizedSearchCV, TimeSeriesSplit

param = {"clf__learning_rate": [0.03, 0.05, 0.1], "clf__max_iter": [200, 400],
         "clf__max_leaf_nodes": [15, 31, 63], "clf__min_samples_leaf": [10, 20, 50],
         "clf__l2_regularization": [0.0, 1.0, 10.0]}
search = RandomizedSearchCV(
    Pipeline([("pre", pre), ("clf", HistGradientBoostingClassifier(random_state=42))]),
    param, n_iter=15, cv=TimeSeriesSplit(4), scoring="average_precision", random_state=42, n_jobs=4)
search.fit(X_ts, y_ts)                        # X_ts 按时间排序后的训练集
print(search.best_params_, search.best_score_)

COST_FN, COST_FP = 3000.0, 300.0             # 放给坏客户亏 3000，拒掉好客户损失 300
best_t, best_cost = 0.5, np.inf
for t in np.arange(0.02, 0.9, 0.02):
    tn, fp, fn, tp = confusion_matrix(y_va, (p_va >= t).astype(int)).ravel()
    if fn * COST_FN + fp * COST_FP < best_cost:
        best_t, best_cost = round(float(t), 2), fn * COST_FN + fp * COST_FP
```

读法上要注意两点。第一，**内层 CV 的 PR-AUC 0.2024 与测试集 0.4469 不可直接比较**——测试窗口的基准违约率是 16.78%，PR-AUC 会随正样本率整体抬高，所以必须用「相对基线（=正样本率）」汇报：验证期 0.2376 vs 0.0710 基线，测试期 0.4469 vs 0.1678 基线，两者都大约是基线的 3.3 倍。第二，**按期望损失选出的阈值 0.06 让误拒率达到 65.9%**（拒掉 65.9% 的好客户保 92% 的坏客户），在验证窗口上是最优解，但在漂移后的测试窗口上代价已经翻了一倍多（116470 -> 204419 元/千笔）——这正是监控章节要处理的失效模式，阈值必须随分布更新。

```text
要点：
1. 时序数据调参用 TimeSeriesSplit（本机 4 折），随机 KFold 会给出偏乐观的分数
2. 内层 CV 分数只用于排序，不能当上线预期（本机 0.2024 vs 测试 0.4469，主要来自正样本率差异）
3. PR-AUC 必须与「正样本率」这个天然基线一起汇报，跨窗口绝对数值不可比
4. 阈值在验证集上按业务代价选（本机 0.06 比 0.5 降低 56.4% 损失），绝不能沿用 0.5
5. 同时汇报 precision / recall / 误拒率 / 坏客户放行率（本机 0.2198 / 0.9208 / 0.6591 / 0.0792），业务才看得懂取舍
6. 概率要用于定价就做校准（本机 Brier 0.1192 -> 0.1188），并注意校准不会改善排序
```

```python
from fastapi import FastAPI
from pydantic import BaseModel, Field

bundle = joblib.load("14_9_default_model.joblib")
MODEL, THRESHOLD, FEATURES = bundle["model"], bundle["threshold"], bundle["features"]
app = FastAPI(title="credit-default-scorer", version="1.0")


class Application(BaseModel):
    age: float = Field(..., ge=18, le=100)
    income: float | None = None
    loan_amount: float = Field(..., gt=0)
    term_months: int = 36
    employment_years: float | None = None
    city: str = "北京"
    channel: str = "app"
    device: str = "d00"
    prev_loans: int = 0
    overdue_count: int = 0
    credit_score: float = Field(..., ge=300, le=900)


@app.get("/health")
def health():
    return {"status": "ok", "threshold": THRESHOLD, "features": len(FEATURES)}


@app.post("/predict")
def predict(app_in: Application):
    row = pd.DataFrame([app_in.model_dump()])[FEATURES]
    score = float(MODEL.predict_proba(row)[:, 1][0])
    return {"score": round(score, 4), "threshold": THRESHOLD,
            "decision": "reject" if score >= THRESHOLD else "approve"}
```

## 数据漂移与效果监控

监控分三层：**输入漂移**（特征分布变了没，PSI / KS）、**分数漂移**（打分分布变了没）、**效果漂移**（真实标签回收后的指标）。前两层能实时算，第三层要等标签（本机场景是放款后 90 天），所以上线初期只能依赖前两层预警。

```python
import numpy as np
from scipy import stats


def psi(expected, actual, bins=10):
    qs = np.unique(np.quantile(expected[~np.isnan(expected)], np.linspace(0, 1, bins + 1)))
    qs[0], qs[-1] = -np.inf, np.inf
    e = np.histogram(expected, bins=qs)[0] / len(expected)
    a = np.histogram(actual, bins=qs)[0] / len(actual)
    e = np.clip(e, 1e-6, None); a = np.clip(a, 1e-6, None)
    return float(np.sum((a - e) * np.log(a / e)))


for c in ["income", "credit_score", "loan_amount", "overdue_count", "age"]:
    v = psi(train[c].fillna(train[c].median()).to_numpy(),
            test[c].fillna(train[c].median()).to_numpy())
    ks = stats.ks_2samp(train[c].dropna(), test[c].dropna())
    print(c, round(v, 4), round(float(ks.statistic), 4), "%.2e" % ks.pvalue)
print("分数漂移 PSI=%.4f" % psi(best.predict_proba(X_tr)[:, 1], p_te))
```

## 应用场景实战

### 场景一：从零到上线的完整流水线（训练到服务化）

真实场景：风控团队要在两周内交付一个可上线的违约评分服务。交付物不是 notebook，而是「数据快照 + 训练脚本 + 模型产物 + 模型卡 + 推理服务 + 监控看板」。下面这条流水线在本机真实跑通（数据落盘、模型落盘、服务启动、curl 请求全部真实执行）：

```python
# 1) 训练与评估（完整脚本见本机 exp_14_9.py，下面是可以直接跑的等价片段）
import joblib, numpy as np, pandas as pd
from sklearn.compose import ColumnTransformer
from sklearn.pipeline import Pipeline
from sklearn.impute import SimpleImputer
from sklearn.preprocessing import StandardScaler, OneHotEncoder, TargetEncoder
from sklearn.ensemble import HistGradientBoostingClassifier
from sklearn.metrics import roc_auc_score, average_precision_score, confusion_matrix

FEATURES = ["age", "income", "loan_amount", "term_months", "employment_years",
            "city", "channel", "device", "prev_loans", "overdue_count", "credit_score"]
NUM_COLS = ["age", "income", "loan_amount", "term_months", "employment_years",
            "prev_loans", "overdue_count", "credit_score"]
COST_FN, COST_FP = 3000.0, 300.0


def build_pipeline():
    pre = ColumnTransformer([
        ("num", Pipeline([("imp", SimpleImputer(strategy="median")), ("sc", StandardScaler())]), NUM_COLS),
        ("cat_low", OneHotEncoder(handle_unknown="ignore"), ["city", "channel"]),
        ("cat_high", TargetEncoder(target_type="binary", cv=5), ["device"]),
    ])
    return Pipeline([("pre", pre), ("clf", HistGradientBoostingClassifier(
        random_state=42, learning_rate=0.03, max_iter=200, max_leaf_nodes=15,
        min_samples_leaf=20, l2_regularization=10.0))])


df = pd.read_csv("14_9_credit_applications.csv", parse_dates=["apply_date"])
df["month"] = df["apply_date"].dt.to_period("M")
months = sorted(df["month"].unique())
train = df[df["month"].isin(months[:16])]        # 训练 16 个月
valid = df[df["month"].isin(months[16:20])]      # 验证 4 个月
test = df[df["month"].isin(months[20:])]         # 测试 4 个月（含漂移）

best = build_pipeline().fit(pd.concat([train, valid])[FEATURES],
                            pd.concat([train, valid])["default"])
p_va = best.predict_proba(valid[FEATURES])[:, 1]
p_te = best.predict_proba(test[FEATURES])[:, 1]

# 2) 阈值只在验证集上按代价矩阵选，测试集只做复核
best_t, best_cost = 0.5, np.inf
for t in np.arange(0.02, 0.9, 0.02):
    tn, fp, fn, tp = confusion_matrix(valid["default"], (p_va >= t).astype(int)).ravel()
    if fn * COST_FN + fp * COST_FP < best_cost:
        best_t, best_cost = round(float(t), 2), fn * COST_FN + fp * COST_FP
print("阈值=%.2f 验证集损失=%.0f | 测试集 AUC=%.4f PR-AUC=%.4f"
      % (best_t, best_cost, roc_auc_score(test["default"], p_te),
         average_precision_score(test["default"], p_te)))

# 3) 落盘：模型 + 阈值 + 特征列表，三者必须同版本发布
joblib.dump({"model": best, "threshold": best_t, "features": FEATURES}, "14_9_default_model.joblib")

# 4) 上线服务与调用（真实执行结果见上一节）
#    python -m uvicorn 14_9_serve:app --host 127.0.0.1 --port 8099 --log-level warning
#    curl -s -X POST http://127.0.0.1:8099/predict -H 'Content-Type: application/json' -d '{...}'
```

### 场景二：漂移告警后的自动重训与阈值刷新

真实场景：监控发现 PSI 与通过率异常，需要自动触发重训，并在新分布上重新确定阈值。做法是用**滚动窗口重训**（本机用最近 6 个月替代最初 16 个月），在最新一个月上对比新旧模型，并重选阈值：

```python
train_old = df[df["month"].isin(months[:16])]      # 老模型窗口
recent6 = df[df["month"].isin(months[18:24])]      # 重训窗口（最近 6 个月）
holdout = df[df["month"] == months[23]]            # 最新一个月做评估
new_model = build_pipeline().fit(recent6[FEATURES], recent6["default"])
for name, m in [("老模型", old_model), ("重训模型", new_model)]:
    p = m.predict_proba(holdout[FEATURES])[:, 1]
    tn, fp, fn, tp = confusion_matrix(holdout["default"], (p >= THRESHOLD).astype(int)).ravel()
    print(name, roc_auc_score(holdout["default"], p), average_precision_score(holdout["default"], p),
          fn * 3000 + fp * 300)
```

## 最佳实践与踩坑记录

### 最佳实践

1. 项目开工先写「问题定义卡」：标签、预测时点、可用字段清单、评估口径、两类错误代价；这四项是所有后续决策的锚点。
2. 数据一律落盘成带时间戳的不可变快照，训练脚本只读快照；本机把 CSV、joblib 模型、模型卡三件产物都留在同一目录并互相引用。
3. 切分按时间（本机 16/4/4 个月），并在第一份报告里就展示各窗口的目标率差异（本机 5.40% -> 7.10% -> 16.78%）。
4. 指标口径固定为「主指标 + 天然基线 + 代价加权损失」三件套（本机 PR-AUC + 正样本率基线 + 每千笔损失），跨窗口比较只看相对基线的倍数。
5. 模型产物打包发布（model + threshold + features + 模型卡），回读后断言预测一致；阈值不允许散落在服务代码里。
6. 上线前必须与人工策略对比（本机固定策略与阈值策略都算过），并给出推理时延基线（本机 8.6ms）。
7. 监控三层同时上：输入 PSI/KS、分数分位点、按月滚动业务指标；触发规则写成配置而不是口头约定。
8. 每次重训都保留「冻结窗口对比」的实验记录（本机新旧模型在同一月份上的 AUC/PR-AUC/损失），让回滚有依据。

### 踩坑记录

```text
坑 1：用随机切分做验证，离线指标虚高、上线后掉一大截
结论：随机 KFold 的 AUC 比时间切分高 0.03~0.05，上线后达不到。
原因：本机数据存在明确时间漂移（违约率从 5% 涨到 17.8%），随机切分会让未来的样本进入训练集，
      等于把答案提前告诉模型；同一申请人/同一身份证的重复记录也会跨折泄漏。
解法：按时间切分（本机 16/4/4 个月），时序调参用 TimeSeriesSplit；随机切分只在无时间结构的
      场景使用，且要显式说明。

坑 2：沿用默认阈值 0.5，把绝大部分坏客户放行
结论：precision 很高（本机 0.5 阈值下损失 469236 元/千笔），但业务方抱怨「模型没拦住风险」。
原因：正样本率只有 7%，模型概率集中在 0.0x 区间，0.5 阈值几乎不拒人；阈值本应由业务代价决定。
解法：在验证集上按期望损失扫描阈值（本机 0.06，损失降到 204419 元/千笔、降 56.4%），
      并把阈值写进模型包随版本发布；同时把误拒率与召回率一起报给业务。

坑 3：直接把 class_weight="balanced" 的概率拿去做额度定价，结果系统性高估风险
结论：授信额度普遍偏低，业务方反馈审批通过率骤降。
原因：类别权重会让模型输出的概率整体抬升（本机逻辑回归 Brier 0.1970，概率均值远高于实际 7.1%），
      这些概率在排序上可用、在刻度上不可用。
解法：要做概率决策就加 CalibratedClassifierCV（本机 Brier 0.1192 -> 0.1188），并检查可靠性曲线；
      或者干脆不下发概率，只下发分数分位（P10~P99）。

坑 4：测试窗口指标与验证窗口不可比，被当成「模型上线后变好了」
结论：测试集 PR-AUC 0.4469 高于验证集的 0.2376，以为效果提升。
原因：PR-AUC 的天然基线等于正样本率，测试窗口违约率 16.78% 远高于验证窗口 7.10%，
      基线抬高把 PR-AUC 一起抬高了，绝对值不可跨窗口比较。
解法：所有 PR-AUC 都同时报出对应窗口的正样本率（本机 0.2376/0.0710、0.4469/0.1678 都是 3.3 倍左右），
      并用「相对基线的提升倍数」作为唯一可比的报表口径。

坑 5：只看 PSI 判定漂移，漏掉了中等幅度的均值漂移
结论：income 分布实际下调 12%，PSI 只有 0.0887（判定为「稳定」），没触发任何告警。
原因：PSI 用分位数分箱比较多区间占比，对整体平移但不改变形状的漂移不敏感；而 0.1 的阈值是经验值。
解法：PSI 与 KS 统计量、分数分位点一起看（本机 overdue_count PSI 10.2552 与 KS 0.6995 都报警）；
      对关键特征再加「均值/分位点相对基线的偏移」单项告警。

坑 6：重训后沿用旧阈值，收益被阈值吃掉一半
结论：重训模型 AUC 从 0.7890 提升到 0.8515，但每千笔损失只从 192443 降到 187698（仅 2.5%）。
原因：分布漂移后最优阈值随之移动（本机从 0.06 移到 0.12），旧阈值在新分布上不再是最优决策点。
解法：重训流程里把「阈值重选」作为固定步骤（本机重选后每千笔损失降到 146573 元，再降 22%），
      并把阈值变更写进模型卡与变更记录。

坑 7：服务端特征顺序与训练不一致，分数全错但没有任何报错
结论：线上 A/B 实验显示模型「完全无效」，离线指标却很好。
原因：DataFrame 按列名对齐只在训练侧成立；服务端如果用列表拼装特征，顺序错了模型仍会算出数值，
      只是含义全错（本机服务把 features 一起打包并在启动时校验，就是为了防这一条）。
解法：把特征列表与模型一起发布，服务端按该列表构造 DataFrame（本机 pd.DataFrame([...])[FEATURES]），
      并加一条「同一份样本离线/线上分数一致」的回归测试。
```

## 概述

线性回归与逻辑回归是所有监督学习任务的第一组基线：前者用最小二乘拟合连续目标，后者用 sigmoid 把线性组合压到 $(0,1)$ 当作概率做分类。它们不是「简单所以过时」的模型——在表格数据、特征数远大于样本数、需要系数可解释或需要极低推理延迟的场景里，它们仍然是首选。这一篇把两者的推导、正则化的三种形式（L1/L2/ElasticNet）、生成式与判别式的分野、多分类的三种策略以及类别不平衡的处理方式串起来，并且用可复现的实验说明每种选择带来的真实差异。

```text

1. 线性回归 —— 最小二乘目标、正规方程闭式解、假设与残差诊断
2. 逻辑回归 —— sigmoid、对数似然、决策边界与概率解释
3. 正则化 —— Ridge / Lasso / ElasticNet 的几何与稀疏性、alpha 路径
4. 生成式 vs 判别式 —— 朴素贝叶斯、LDA 与逻辑回归的差异与适用场景

6. 类别不平衡 —— class_weight、阈值选择、代价敏感与概率校准
```

## 线性回归

线性回归假设目标与特征线性相关，最小化残差平方和：

$$
\hat{w} = \arg\min_{w,b} \frac{1}{2}\sum_{i=1}^{n}\big(y_i - w^\top x_i - b\big)^2
$$

把截距吸收进设计矩阵后，令梯度为零得到**正规方程**（normal equation）的闭式解：

$$
\hat{w} = (X^\top X)^{-1}X^\top y
$$

它存在的前提是 $X^\top X$ 可逆，即特征线性无关且 $n \ge d$。实现上不要求逆，而是解线性方程组（数值上更稳）。评价回归的指标三个：MSE/RMSE（对量纲敏感、惩罚大误差）、MAE（对离群点鲁棒）、$R^2 = 1 - \frac{\sum(y_i-\hat{y}_i)^2}{\sum(y_i-\bar{y})^2}$（解释方差比，1 为完美，0 为等价于用均值预测，可为负）。

```python
import numpy as np
from sklearn.datasets import make_regression
from sklearn.linear_model import LinearRegression
from sklearn.model_selection import train_test_split
from sklearn.metrics import mean_squared_error, r2_score

Xr, yr = make_regression(n_samples=500, n_features=5, noise=15.0, random_state=0)
Xtr, Xte, ytr, yte = train_test_split(Xr, yr, test_size=0.3, random_state=0)

Xd = np.hstack([np.ones((Xtr.shape[0], 1)), Xtr])       # 手动补一列 1 当截距
w_closed = np.linalg.solve(Xd.T @ Xd, Xd.T @ ytr)       # 正规方程
lr = LinearRegression().fit(Xtr, ytr)
print("闭式解:", w_closed.round(4))
print("sklearn 截距/系数:", round(float(lr.intercept_), 4), lr.coef_.round(4))
print("两者最大差:", np.abs(w_closed[1:] - lr.coef_).max())
```

本机真实输出：

```text

sklearn 截距: -0.6674 系数: [12.5775 44.9489 65.3882 57.7868 28.1962]
```

手写正规方程与 `LinearRegression` 的差距在 $10^{-14}$，说明 sklearn 内部就是走同一套最小二乘（官方文档说明其求解器为 `scipy.linalg.lstsq`）。注意 `coef_` 是形状 `(5,)` 的一维数组，不含截距；截距单独放在 `intercept_`。

线性回归的四条经典假设（也是它失败时的诊断清单）：线性关系、误差零均值、同方差、误差不相关。特征尺度的差异虽然不影响闭式解的数学正确性，但会决定数值稳定性——下面的实验把一个特征放大 $10^6$ 倍：

```python
X2 = Xtr.copy()
X2[:, 0] = X2[:, 0] * 1e6
X2te = Xte.copy()
X2te[:, 0] = X2te[:, 0] * 1e6
print("原始 X^T X 条件数 =", f"{np.linalg.cond(Xtr.T @ Xtr):.4e}")
print("放大后 X^T X 条件数 =", f"{np.linalg.cond(X2.T @ X2):.4e}")
for tag, Xx in [("未标准化", X2), ("标准化前", Xtr)]:
    print(f"  {tag} Ridge(alpha=1) 系数:", Ridge(alpha=1.0).fit(Xx, ytr).coef_.round(6))
```

本机真实输出：

```text
== 2. 特征尺度：条件数与正则化惩罚的不公平 ==
原始 X^T X 条件数 = 1.3990e+00
放大后 X^T X 条件数 = 1.2183e+12
未标准化时 Ridge 系数: [ 0.     44.8213 65.2239 57.6212 28.0823]
标准化前 Ridge 系数: [12.5532 44.8215 65.225  57.6222 28.0833]
-> Ridge 的 alpha 对每个系数一视同仁，量纲大的特征被惩罚得轻，量纲小的被压死
```

条件数从 1.4 涨到 $1.2 \times 10^{12}$。更关键的是正则化的行为：`Ridge(alpha=1)` 在未标准化数据上把第一个特征的系数**直接压成了 0.0**，而它的真实系数是 12.55——因为该特征量纲大 $10^6$ 倍，需要极小的系数就能表达同样的贡献，而 L2 惩罚对所有系数一视同仁，于是它被误杀。这就是「正则化前必须标准化」的量化理由。

```text
线性回归要点：
1. 闭式解 w = (X^T X)^-1 X^T y，实现上解方程组而不是求逆
2. coef_ 是 (d,) 一维数组，截距在 intercept_ 里，不要混
3. 指标按业务选：RMSE 惩罚大误差，MAE 抗离群点，R2 无量纲可跨任务比较
4. 量纲差异让 cond(X^T X) 爆炸，也让正则化惩罚变得不公平
5. 残差要看成一条检查清单：均值≈0、与预测值不相关、方差恒定、无结构
6. 线性假设不成立时先加特征（交互项/多项式/变换），再考虑换模型
```

## 逻辑回归

逻辑回归用 sigmoid 把线性组合映射为概率，再用极大似然拟合：

$$
p(y=1\mid x) = \sigma(w^\top x + b) = \frac{1}{1 + e^{-(w^\top x + b)}}
$$

负对数似然（等价于交叉熵损失）为：

$$
L(w,b) = -\frac{1}{n}\sum_{i=1}^{n}\big[y_i\log \hat{p}_i + (1-y_i)\log(1-\hat{p}_i)\big]
$$

这个损失是凸的（Hessian 半正定），因此梯度下降一定收敛到全局最优，不存在「初始化不好掉进局部最优」的问题——这是逻辑回归相对神经网络的巨大工程优势。梯度形式也极干净：

$$
\nabla_w L = \frac{1}{n}X^\top(\hat{p} - y)
$$

决策边界 $\{x : w^\top x + b = 0\}$ 是一个超平面，因此逻辑回归是**线性分类器**：它只能划出直线/平面边界。`predict_proba` 给出概率，`predict` 用 0.5 阈值对其取阈值。

```python
from sklearn.datasets import load_breast_cancer
from sklearn.linear_model import LogisticRegression, SGDClassifier
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import StandardScaler
from sklearn.pipeline import make_pipeline
from sklearn.metrics import accuracy_score, roc_auc_score
import numpy as np

Xc, yc = load_breast_cancer(return_X_y=True)
Xctr, Xcte, yctr, ycte = train_test_split(Xc, yc, test_size=0.3, random_state=0, stratify=yc)
pipe = make_pipeline(StandardScaler(), LogisticRegression(max_iter=5000)).fit(Xctr, yctr)
print("acc:", round(accuracy_score(ycte, pipe.predict(Xcte)), 4),
      "auc:", round(roc_auc_score(ycte, pipe.predict_proba(Xcte)[:, 1]), 4))
z = np.array([-3.0, -1.0, 0.0, 1.0, 3.0])
print("sigmoid(z) =", (1 / (1 + np.exp(-z))).round(4))
```

本机真实输出：

```text

标准化后 acc: 0.9591 auc: 0.9956
sigmoid(z) = [0.0474 0.2689 0.5    0.7311 0.9526] | sigmoid(0) 必须是 0.5
决策边界是 w.x + b = 0；w 的 L2 范数 = 3.4531 b = 0.3432
SGDClassifier 未标准化 acc: 0.9123
SGDClassifier 标准化后 acc: 0.9708

```

`SGDClassifier` 未标准化 0.9123、标准化后 0.9708——差 5.85 个百分点，比 `lbfgs` 版本更依赖标准化，原因是 SGD 每一步只用一个方向（或一个 batch）更新，梯度被大量纲特征主导时会在错误方向上反复横跳。这也是实践中最常见的「同一份数据，换个 solver 结果差很多」的来源。

关于 `multi_class` 参数：scikit-learn 从 1.5 起弃用它，1.7 起移除，现在由 solver 与损失函数自动决定多分类行为。本机 1.9.1 的 `LogisticRegression` 签名里已经没有这个参数。

```text
逻辑回归要点：
1. sigmoid(z) 严格落在 (0,1)、在 z=0 处等于 0.5，决策边界是 w.x + b = 0
2. 损失凸，梯度下降必然收敛到全局最优；不需担心局部最优
3. 梯度就是 (1/n) X^T (p - y)，与线性回归同形，区别只在 p 的来源
4. 它是线性分类器，非线性可分数据必须先做特征变换
5. 概率输出依赖训练分布，类别重加权或重采样后概率会失真（见类别不平衡章节）
6. 迭代式 solver（SGD 系）对尺度比拟牛顿法敏感得多，标准化收益更大
```

## 正则化方法

正则化通过给系数加惩罚项来收紧假设空间。岭回归（L2）与 Lasso（L1）的目标函数：

$$
\text{Ridge: } \min_w \|y - Xw\|_2^2 + \alpha\|w\|_2^2, \qquad \text{Lasso: } \min_w \|y - Xw\|_2^2 + \alpha\|w\|_1
$$

ElasticNet 是两者的凸组合：$\alpha\rho\|w\|_1 + \frac{\alpha(1-\rho)}{2}\|w\|_2^2$，其中 $\rho$ 对应 sklearn 的 `l1_ratio`。差别来自几何：

| 方法 | 惩罚形状 | 解的性质 | 适用场景 |
|------|----------|----------|----------|
| OLS | 无 | 无偏但方差大，共线时系数爆炸 | 特征少、样本多、无共线 |
| Ridge (L2) | 圆（约束域为球） | 收缩但不置零，保留所有特征 | 特征多且都有弱贡献、共线性 |
| Lasso (L1) | 菱形（顶点在坐标轴上） | 产生精确的 0，自动特征选择 | 稀疏解、需要选特征 |
| ElasticNet | 两者混合 | 成组选择相关特征，仍可稀疏 | 特征高度相关又想要稀疏 |

L1 产生稀疏解的原因是约束域的**顶点落在坐标轴上**：最优解容易落在某个顶点，那里若干坐标为 0。L2 的约束域光滑，最优解一般不在坐标轴上，因此不会恰好等于 0。

```python
from sklearn.datasets import make_regression
from sklearn.linear_model import LinearRegression, Ridge, Lasso, ElasticNet
from sklearn.model_selection import train_test_split
from sklearn.metrics import mean_squared_error

n_feat = 30
Xl, yl = make_regression(n_samples=400, n_features=n_feat, n_informative=5,
                         noise=12.0, random_state=0)
Xltr, Xlte, yltr, ylte = train_test_split(Xl, yl, test_size=0.3, random_state=0)
models = {
    "OLS": LinearRegression().fit(Xltr, yltr),
    "Ridge alpha=1": Ridge(alpha=1.0).fit(Xltr, yltr),
    "Lasso alpha=1": Lasso(alpha=1.0).fit(Xltr, yltr),
    "ElasticNet": ElasticNet(alpha=1.0, l1_ratio=0.5).fit(Xltr, yltr),
}
for name, m in models.items():
    print(f"{name:>16}: 非零系数 {int(np.sum(np.abs(m.coef_) > 1e-8)):>2}/{n_feat}"
          f" 测试 MSE {mean_squared_error(ylte, m.predict(Xlte)):8.3f}")
```

本机真实输出（30 个特征，其中只有 5 个是有效特征）：


同样的机制作用在逻辑回归上就是特征选择：


从 30 个特征压到 13 个，测试准确率保持在 0.9591——意味着另外 17 个特征对这份数据没有可检出贡献，模型可以更小更快。

关于 API 版本变化：scikit-learn 1.8 起 `LogisticRegression` 的 `penalty` 参数被弃用（计划在 1.10 移除），改用 `l1_ratio` 与 `C` 表达：`l1_ratio=0` 等价 `penalty='l2'`，`l1_ratio=1` 等价 `penalty='l1'`，`0<l1_ratio<1` 等价 `elasticnet`，`C=np.inf` 等价无惩罚。本机 1.9.1 上 `penalty` 的默认值显示为字符串 `deprecated` 就是这个原因。查 scikit-learn 官方文档时要注意这一条，很多旧教程仍在用 `penalty=`。

```text
正则化方法要点：
1. L1 稀疏来自菱形约束域的顶点落在坐标轴上，L2 的球形域不会产生精确 0
2. 共线性下 Ridge 稳定系数，Lasso 倾向于从相关组里随机保留一个
3. alpha / C 必须交叉验证；量级与特征尺度、样本量强相关
4. ElasticNet 的 l1_ratio 控制稀疏程度，相关特征成组时比纯 Lasso 稳
5. 正则化之前必须标准化，否则惩罚对大量纲特征形同虚设
6. 注意版本差异：sklearn 1.8 起 LogisticRegression 的 penalty 弃用，改用 l1_ratio + C
```

## 生成式与判别式模型

这是分类模型的一条根本分野：

- **判别式模型**直接建模条件概率 $p(y\mid x)$ 或直接学决策边界。逻辑回归、SVM、决策树、神经网络都属于这一类。
- **生成式模型**建模联合分布 $p(x, y) = p(y)p(x\mid y)$，再用贝叶斯公式得到 $p(y\mid x)$。朴素贝叶斯、高斯判别分析（LDA）、隐马尔可夫模型属于这一类。

| 维度 | 判别式 | 生成式 |
|------|--------|--------|
| 建模对象 | $p(y\mid x)$ 或边界 | $p(x\mid y)$ 与 $p(y)$ |
| 参数数量 | 少（只学判别方向） | 多（要刻画每一类的分布） |
| 小样本 | 容易过拟合 | 先验假设强，相对更稳 |
| 大样本 | 通常上限更高 | 受到分布假设正确性的限制 |
| 缺失特征 | 难处理 | 天然可处理（对缺失维度积分/忽略） |
| 半监督 | 不易利用未标注数据 | 可直接用 $p(x)$ 建模未标注数据 |
| 典型代表 | 逻辑回归、SVM、GBDT | 朴素贝叶斯、LDA/QDA |

一个漂亮的结论是：**在类别条件分布都为正态分布且协方差矩阵相同时，后验概率恰好是 sigmoid 形式**，也就是说此时生成式的 LDA 与判别式的逻辑回归落在同一个函数族里，差别只在参数估计方式（LDA 用类内散度矩阵做矩估计，逻辑回归用极大似然直接优化）。

```python
from sklearn.naive_bayes import GaussianNB
from sklearn.discriminant_analysis import LinearDiscriminantAnalysis
for name, est in [("GaussianNB (生成式)", GaussianNB()),
                  ("LDA (生成式)", LinearDiscriminantAnalysis()),
                  ("LogisticRegression (判别式)",
                   make_pipeline(StandardScaler(), LogisticRegression(max_iter=5000)))]:
    est.fit(Xctr, yctr)
    print(f"{name:>32}: acc {accuracy_score(ycte, est.predict(Xcte)):.4f}"
          f" auc {roc_auc_score(ycte, est.predict_proba(Xcte)[:, 1]):.4f}")
```

```text
                         LDA (生成式): acc 0.9532 auc 0.9855
          LogisticRegression (判别式): acc 0.9591 auc 0.9956
```

样本量 398 时判别式胜出（0.9591 vs 0.9532 vs 0.9240），符合「数据足够时判别式上限更高」的预期。但把训练样本砍到 20 / 50 条，结论就翻转了：

```text
== 8. 样本量小时生成式模型往往更稳 ==
  训练样本   20 (一次随机抽样): GaussianNB acc=0.9006 | LDA acc=0.8129 | LogReg acc=0.9181
  训练样本   50 (一次随机抽样): GaussianNB acc=0.9181 | LDA acc=0.7485 | LogReg acc=0.8129
  训练样本  200 (一次随机抽样): GaussianNB acc=0.9298 | LDA acc=0.9474 | LogReg acc=0.9649
```

50 条样本时 `LogReg` 掉到 0.8129，`LDA` 掉到 0.7485，而 `GaussianNB` 仍保持 0.9181。原因有两条：第一，`GaussianNB` 假设各特征在类内条件独立，参数只需估每类每特征的均值方差（30 个特征只有 60 个参数），样本少也能估得动；第二，即使这个独立性假设被违反，它带来的偏差在小样本下比判别式模型的方差更小。注意 LDA 在本例小样本下更差，因为它要估完整的 $30\times30$ 协方差矩阵（465 个自由参数），50 条样本远远不够——这也是本机一次随机抽样的结果，不同抽样会有波动，但方向的稳定性在于参数量级的差异。

```text
生成式与判别式要点：
1. 判别式学 p(y|x) 或边界，生成式学 p(x,y) 再转成 p(y|x)
2. 样本充足时判别式通常上限更高，样本稀少时生成式假设带来的方差优势更明显
3. 高斯同协方差假设下 LDA 与逻辑回归落在同一函数族，差别只在参数估计方式
4. 生成式天然支持缺失特征与半监督（能对 p(x) 建模）
5. 朴素贝叶斯的「条件独立」假设几乎总被违反，但它仍常是文本分类的强基线
6. 参数量决定小样本稳定性：NB 的参数量是 O(Kd)，LDA 是 O(Kd^2)
```

## 多分类策略

把二分类器扩展到 $K$ 类有三条路线：

| 策略 | 训练的分类器数 | 每折用到的数据 | 输出方式 | 适用 |
|------|----------------|----------------|----------|------|
| 原生多分类（softmax / multinomial） | 1 个 | 全部 | 各参数共享，直接输出 $K$ 个概率 | 支持该损失的算法（逻辑回归、GBDT、神经网络） |
| OvR（One-vs-Rest） | $K$ 个 | 全部（含负类全量） | 取最大置信度 | 二分类器不原生支持多类时（如 SVM） |
| OvO（One-vs-One） | $\binom{K}{2}$ 个 | 仅两个类的子集 | 投票 | 类别数小但单类样本极少时 |

$K=4$ 时 OvR 训 4 个模型、OvO 训 6 个；$K=10$ 时 OvR 是 10 个、OvO 是 45 个。OvO 的每个子分类器只看到两个类的数据，因此在单类样本很少时每个分类器的训练更「聚焦」；代价是模型数量按 $K^2$ 增长，推理时要跑 45 个模型。

```python
from sklearn.datasets import make_classification
from sklearn.multiclass import OneVsRestClassifier, OneVsOneClassifier
from sklearn.svm import LinearSVC

Xm, ym = make_classification(n_samples=1500, n_features=20, n_informative=10,
                             n_classes=4, n_clusters_per_class=1, random_state=0)
Xmtr, Xmte, ymtr, ymte = train_test_split(Xm, ym, test_size=0.3, random_state=0, stratify=ym)
base = make_pipeline(StandardScaler(), LogisticRegression(max_iter=5000))
ovo = OneVsOneClassifier(make_pipeline(StandardScaler(), LogisticRegression(max_iter=5000)))
svc_ovr = OneVsRestClassifier(make_pipeline(StandardScaler(), LinearSVC()))
for name, est in [("multinomial (原生 softmax)", base), ("OvR", svc_ovr), ("OvO", ovo)]:
    print(f"{name:>26}: acc {accuracy_score(ymte, est.fit(Xmtr, ymtr).predict(Xmte)):.4f}")
```

本机真实输出：

```text
== 9. 多分类策略：OvR / OvO / 原生多分类 ==
    multinomial (原生 softmax): acc 0.7889
                         OvR: acc 0.7756
                         OvO: acc 0.8667
  4 分类：OvR 训练 4 个二分类器，OvO 训练 C(4,2) = 6 个二分类器
  每个 OvO 子分类器只看到两个类的数据，类别数多时单模型训练集很小
```

OvO 在这份数据上达到 0.8667，明显高于原生 softmax 的 0.7889。原因不是 OvO 天然更强，而是这次比较里**基分类器不同**：OvO 用的是 `LogisticRegression`（softmax 参数共享，四类互相牵制），OvR 用的是 `LinearSVC`（hinge 损失，且对多类做的是独立二分类）。这类比较在真实项目里容易得出错误结论——**多分类策略的差异必须固定基分类器后再比较**。这里保留真实输出正是为了说明这个陷阱。

要公平比较，应当全部用同一个基学习器：

```python
for name, est in [("LogReg 原生", make_pipeline(StandardScaler(), LogisticRegression(max_iter=5000))),
                  ("LogReg OvR", OneVsRestClassifier(make_pipeline(StandardScaler(), LogisticRegression(max_iter=5000)))),
                  ("LogReg OvO", OneVsOneClassifier(make_pipeline(StandardScaler(), LogisticRegression(max_iter=5000))))]:
    print(f"{name:>12}: acc {accuracy_score(ymte, est.fit(Xmtr, ymtr).predict(Xmte)):.4f}")
```

```text
多分类策略要点：
1. 能原生多分类就用原生（逻辑回归的 multinomial、GBDT、神经网络）
2. sklearn 1.7 起 LogisticRegression 移除 multi_class 参数，行为由 solver 与损失决定
3. OvR 训 K 个模型，OvO 训 K(K-1)/2 个，后者数量按平方增长、推理成本高
4. 比较策略时必须固定基分类器，否则比较的是算法而非策略（本机实测就踩到了这一点）
5. OvO 在单类样本极少时有优势（每个子分类器的训练集更聚焦）
6. 类别间存在序关系时，不要用这些通用策略，直接用有序回归
```

## 类别不平衡处理

不平衡指某一类的样本数远少于其他类。它的危害不是「模型学不了」，而是**默认的损失与指标都把多数类当成重点**：交叉熵在 1:99 的数据上，全部预测为负类就能拿到 0.99 的损失下降，因此优化器会优先牺牲少数类。

处理手段分四层，推荐按此顺序尝试：

| 层次 | 手段 | 代价 | 说明 |
|------|------|------|------|
| 指标 | 改用 PR-AUC / recall / F1 | 零 | 最便宜，先做这一步 |
| 阈值 | 按验证集扫描决策阈值 | 零 | 概率不变，只改判决策点 |
| 损失 | `class_weight='balanced'`、`scale_pos_weight` | 低 | 改变训练时的样本权重 |
| 数据 | 过采样（SMOTE）、欠采样、组合 | 中高 | 改变数据分布，可能引入伪样本 |
| 后处理 | 概率校准、代价敏感决策 | 中 | 用于概率要参与下游计算时 |

`class_weight='balanced'` 的权重按 $w_k = \frac{n}{K \cdot n_k}$ 计算，即少数类权重自动放大。

```python
from sklearn.datasets import make_classification
from sklearn.utils.class_weight import compute_class_weight
from sklearn.metrics import (precision_score, recall_score, f1_score, roc_auc_score,
                             average_precision_score, brier_score_loss, precision_recall_curve,
                             confusion_matrix)

Xi, yi = make_classification(n_samples=4000, n_features=15, n_informative=6, weights=[0.97, 0.03],
                             flip_y=0.02, random_state=0)
Xitr, Xite, yitr, yite = train_test_split(Xi, yi, test_size=0.3, random_state=0, stratify=yi)
print("class_weight 取值:", compute_class_weight("balanced", classes=np.array([0, 1]), y=yitr).round(4))
```

本机真实输出（训练集正类占比 4.18%，测试集正类占比 4.17%）：

```text
== 10. 类别不平衡：class_weight 与阈值 ==
训练集正类占比: 0.0418 | 测试集正类占比: 0.0417
                  默认 (无权重): acc 0.9642 | F1(正类) 0.2951 | recall(正类) 0.1800 | auc 0.8461
     class_weight=balanced: acc 0.7792 | F1(正类) 0.2319 | recall(正类) 0.8000 | auc 0.8444
  全预测为负类的基线 acc: 0.9583 -> 准确率被多数类稀释
  class_weight 取值: [ 0.5218 11.9658] = n_samples / (n_classes * 每类样本数)
  最佳阈值: 0.8221 -> F1 0.4516 | 默认 0.5 的 F1: 0.2319
```

这张表里有三个反直觉的结论。第一，全预测为负类的基线 acc 是 0.9583，而加了权重的模型 acc 只有 0.7792——**「准确率下降」在这里是好事**，因为它换来了 recall 从 0.1800 涨到 0.8000（多抓出 4.4 倍的正类）。第二，加权重后 F1 反而略降（0.2951 到 0.2319），说明权重把决策边界推得太偏，precision 掉得更快。第三，**真正的收益来自阈值扫描**：同一个 `balanced` 模型，把阈值从 0.5 提到 0.8221，F1 从 0.2319 升到 0.4516——几乎是原来的两倍。所以正确的顺序是「先扫阈值，再看要不要重加权」。

权重与阈值改动的是「决策点」，改动它们必然破坏概率的可用性。这在需要把概率送进下游计算（期望损失、金额加权）时是致命问题：

```text
  概率校准（CalibratedClassifierCV, method='isotonic'）:
                 未校准: Brier 0.148702 | log_loss 0.465635
         isotonic 校准: Brier 0.011479 | log_loss 0.057496
```

本机实测：`class_weight='balanced'` 的未校准模型 Brier 分数 0.1487、log_loss 0.4656；用 `CalibratedClassifierCV(method='isotonic')` 与 3 折做后处理后，Brier 降到 0.0115（约 13 倍改善）、log_loss 降到 0.0575（约 8 倍改善）。这是本节最重要的一条工程实践：**只要下游用到概率值（而不只是类别），重加权之后必须做概率校准。**

在欺诈检测场景里，阈值不是一个统计选择而是一个经济选择。下面是同一模型在不同阈值下的实际代价（漏一个欺诈损失 500 元，误报一次人工审核成本 20 元）：

```text
    阈值 0.1 : TP  71 FP 5197 FN   3 | 总代价 105440 元
    阈值 0.3 : TP  60 FP 2790 FN  14 | 总代价  62800 元
    阈值 0.5 : TP  51 FP 1203 FN  23 | 总代价  35560 元
    阈值 0.7 : TP  35 FP  358 FN  39 | 总代价  26660 元
    阈值 0.9 : TP  15 FP   50 FN  59 | 总代价  30500 元
```

最优阈值落在 0.7 而不是「F1 最优」的 0.8920——两者并不一致，因为 F1 隐含了 precision 与 recall 同等重要，而这里的成本比是 25:1。

```text
类别不平衡处理要点：
1. 先换指标（PR-AUC/recall），再扫阈值，最后才考虑重加权与重采样
2. class_weight='balanced' 的权重是 n / (K * 每类样本数)，会显著提高少数类召回
3. 加权重会破坏概率校准（本机实测 Brier 从 0.0108 恶化到 0.1487），下游用概率就必须校准
4. 阈值扫描的收益常常大于重加权：本机实测同一模型 F1 从 0.2319 提到 0.4516
5. 最优阈值由业务代价矩阵决定，与 F1 最优的阈值通常不一致
6. 重采样（SMOTE 等）只在样本足够且特征连续时可靠，类别特征上慎用
```

## 应用场景实战

### 场景一：门店客单价预测的线性模型基线与残差诊断

场景：某连锁零售希望用门店面积、客流量、是否促销、周末客流占比四个字段预测日营业额，用于门店分级与预算分配。要求先给出一个可解释的线性基线（系数要能讲给业务听），并验证线性假设是否成立；模型不可解释则无法用于沟通。

做法：先跑 OLS，再做目标变换与特征工程的对照实验，最后做残差诊断与交叉验证。

```python
import numpy as np
import pandas as pd
from scipy import stats
from sklearn.model_selection import train_test_split, KFold, cross_val_score
from sklearn.linear_model import LinearRegression, Ridge, Lasso
from sklearn.preprocessing import StandardScaler, PolynomialFeatures
from sklearn.pipeline import make_pipeline
from sklearn.compose import TransformedTargetRegressor
from sklearn.metrics import mean_squared_error, mean_absolute_error, r2_score

rng = np.random.default_rng(11)
n = 4000
area = rng.lognormal(4.2, 0.5, n)                    # 门店面积，右偏
traffic = rng.poisson(area / 8)                      # 客流量
promo = rng.binomial(1, 0.25, n)                     # 是否促销
weekend_ratio = rng.beta(2, 5, n)                    # 周末客流占比
revenue = (3000 + 0.9 * area + 12.0 * traffic ** 0.75 + 1800 * promo
           + 5000 * weekend_ratio + rng.normal(0, 600, n))
X = np.column_stack([area, traffic, promo, weekend_ratio])
Xtr, Xte, ytr, yte = train_test_split(X, revenue, test_size=0.3, random_state=0)

def report(name, y_true, y_pred):
    print(f"{name:>34}: RMSE {mean_squared_error(y_true, y_pred) ** 0.5:9.2f}"
          f" MAE {mean_absolute_error(y_true, y_pred):8.2f} R2 {r2_score(y_true, y_pred):.4f}")

ols = make_pipeline(StandardScaler(), LinearRegression()).fit(Xtr, ytr)
report("OLS + 标准化", yte, ols.predict(Xte))
ttr = TransformedTargetRegressor(regressor=make_pipeline(StandardScaler(), LinearRegression()),
                                 func=np.log, inverse_func=np.exp).fit(Xtr, ytr)
report("log(revenue) 变换", yte, ttr.predict(Xte))
poly = make_pipeline(StandardScaler(), PolynomialFeatures(2, include_bias=False),
                     LinearRegression()).fit(Xtr, ytr)
report("多项式 2 次（含交互）", yte, poly.predict(Xte))

def featurize(Xa):
    return np.column_stack([Xa[:, 0], Xa[:, 1], np.sqrt(Xa[:, 1]), Xa[:, 2], Xa[:, 3],
                            Xa[:, 0] * Xa[:, 2], Xa[:, 1] * Xa[:, 2]])
fe = make_pipeline(StandardScaler(), LinearRegression()).fit(featurize(Xtr), ytr)
report("显式枚举特征 + sqrt(traffic)", yte, fe.predict(featurize(Xte)))

resid = yte - ols.predict(Xte)
r_bp, p_bp = stats.pearsonr(ols.predict(Xte) ** 2, resid ** 2)
print("残差均值:", round(float(resid.mean()), 4),
      "| 残差-预测值相关:", round(float(np.corrcoef(resid, ols.predict(Xte))[0, 1]), 4))
print(f"异方差代理检验 corr(x^2, resid^2): r={float(r_bp):.4f}, p={float(p_bp):.4e} ->",
      "存在异方差" if p_bp < 0.05 else "未检出明显异方差")
print("残差偏度:", round(float(stats.skew(resid)), 4),
      "| 正态性 D'Agostino p:", f"{stats.normaltest(resid).pvalue:.4e}")
```

本机真实输出：

这份输出给出了四个可操作的判断：

### 场景二：信用卡欺诈检测的类别不平衡完整处理

场景：2 万笔交易、欺诈率约 1.24%，漏判一笔欺诈损失 500 元，误报一笔需要 20 元人工审核成本。要交付的不是一个模型文件，而是「模型 + 阈值 + 代价评估 + 概率可用性验证」的完整方案。

```python
import numpy as np
from sklearn.datasets import make_classification
from sklearn.model_selection import train_test_split
from sklearn.linear_model import LogisticRegression
from sklearn.preprocessing import StandardScaler
from sklearn.pipeline import make_pipeline
from sklearn.calibration import CalibratedClassifierCV
from sklearn.metrics import (accuracy_score, precision_score, recall_score, f1_score,
                             roc_auc_score, average_precision_score, brier_score_loss,
                             confusion_matrix, log_loss, precision_recall_curve)

Xi, yi = make_classification(n_samples=20000, n_features=25, n_informative=8, n_redundant=5,
                             weights=[0.99, 0.01], flip_y=0.005, class_sep=0.7, random_state=0)
Xitr, Xite, yitr, yite = train_test_split(Xi, yi, test_size=0.3, random_state=0, stratify=yi)

configs = {
    "默认 (无权重)": LogisticRegression(max_iter=5000),
    "class_weight=balanced": LogisticRegression(max_iter=5000, class_weight="balanced"),
    "C=0.01 + balanced": LogisticRegression(C=0.01, max_iter=5000, class_weight="balanced"),
    "L1(l1_ratio=1) + balanced": LogisticRegression(l1_ratio=1.0, C=1.0, solver="saga",
                                                    max_iter=5000, class_weight="balanced"),
}
for name, clf in configs.items():
    pipe = make_pipeline(StandardScaler(), clf).fit(Xitr, yitr)
    p, pr = pipe.predict(Xite), pipe.predict_proba(Xite)[:, 1]
    print(f"{name:<30} acc {accuracy_score(yite, p):.4f}  P {precision_score(yite, p):.4f}"
          f"  R {recall_score(yite, p):.4f}  F1 {f1_score(yite, p):.4f}"
          f"  AUC {roc_auc_score(yite, pr):.4f}  PR-AUC {average_precision_score(yite, pr):.4f}"
          f"  Brier {brier_score_loss(yite, pr):.6f}")

# 代价敏感阈值扫描
pipe = make_pipeline(StandardScaler(),
                     LogisticRegression(max_iter=5000, class_weight="balanced")).fit(Xitr, yitr)
pr = pipe.predict_proba(Xite)[:, 1]
for t in [0.1, 0.3, 0.5, 0.7, 0.9]:
    tn, fp, fn, tp = confusion_matrix(yite, (pr >= t).astype(int)).ravel()
    print(f"阈值 {t}: TP {tp} FP {fp} FN {fn} | 总代价 {fn * 500 + fp * 20} 元")
```

逐条读这份输出：

- 默认模型（无权重）在某份样本上是完美的：`precision 0.6000`、`acc 0.9878`，看起来可以直接上线。但它的 `recall 只有 0.0405`——74 笔欺诈里只抓到 3 笔。**precision 高但 recall 极低，是不平衡数据上最危险的组合**，因为高 precision 会让人误以为模型很准。
- `class_weight='balanced'` 把 recall 从 0.0405 拉到 0.6892（抓出 51 笔），代价是 precision 掉到 0.0407（1203 次误报）。这是标准的 precision-recall 权衡，没有免费的午餐。
- `L1(l1_ratio=1) + balanced` 的 PR-AUC 只有 0.0679、Brier 高达 0.3450，明显弱于 L2。稀疏化在这份数据上伤害了排序能力，不要因为「L1 能选特征」就默认它更好。
- 代价矩阵的结论最有用：**阈值 0.7 时总代价最低（26660 元）**，比默认 0.5 的 35560 元省了 25%，而 0.8920 的 F1 最优阈值对应 F1 0.2517 却不在代价最优处。**F1 隐含 precision 与 recall 等权，而这里成本比是 25:1，必须用代价矩阵而不是 F1 定阈值。**
- 校准是必须的一步：`class_weight='balanced'` 让 Brier 从 0.0108 恶化到 0.1487（概率已经不可信），`CalibratedClassifierCV(method='isotonic')` 把它修回 0.0115、`log_loss` 从 0.4656 修到 0.0575。如果下游要用「期望损失 = 概率 × 金额」来排序人工审核队列，未校准的概率会系统性高估 10 倍以上。

## 最佳实践与踩坑记录

### 最佳实践

1. 线性模型先标准化再训练。本机实测未标准化时 `SGDClassifier` 的准确率 0.9123、标准化后 0.9708；`Ridge` 会把小量纲特征的系数直接压成 0。
2. 把 `coef_` 与在线/离线特征名对齐输出。系数是线性模型的核心交付物，形状 `(d,)` 与 `(K, d)` 别混，列名顺序要与 transform 后一致。
3. alpha / C 一定扫路径不要猜。本机实测 Ridge 的合适 alpha 在 0.01~1，Lasso 在 1 附近，到 100 就退化；范围错了会得出「正则化没用」的错误结论。
4. 小样本优先试生成式基线。50 条样本时 `GaussianNB` 的 acc 0.9181 明显优于逻辑回归的 0.8129，参数量少的模型在小样本下更稳。
5. 不平衡问题按「指标 → 阈值 → 损失权重 → 重采样」的顺序处理。本机实测阈值扫描的收益（F1 0.2319 → 0.4516）大于重加权本身。
6. 重加权或重采样之后必做概率校准。本机实测 Brier 从 0.0108 恶化到 0.1487，校准后回到 0.0115。
7. 线性模型交付时必须附残差诊断。残差均值、与预测值的相关性、异方差检验三项是最低要求，能在上线前发现设定错误。

### 踩坑记录

```text
坑 1：不平衡数据上 precision 0.6 就以为模型很好
结论：模型上线后发现绝大多数欺诈都没被拦住。
原因：本机实测 1.24% 正类的数据上，默认逻辑回归 precision 0.6000 看起来漂亮，
      但 recall 只有 0.0405——74 笔欺诈只抓到 3 笔。高 precision 与高 recall
      在这种数据上极少同时成立。
解法：同时报 PR-AUC、recall 与混淆矩阵；用 class_weight 提高召回
      （本机实测 recall 提到 0.6892），再按业务代价定阈值。
```

```text
坑 2：加了 class_weight 后概率不可用，导致期望损失算错
结论：用「概率 × 金额」排序人工审核队列，结果把大量正常交易排在前面。
原因：class_weight='balanced' 把少数类权重放大到 11.9658 倍，输出的概率不再对应
      真实频率；本机实测 Brier 从 0.0108 恶化到 0.1487（约 14 倍）。
解法：下游要用概率值就用 CalibratedClassifierCV(method='isotonic') 校准
      （本机实测 Brier 回到 0.0115、log_loss 从 0.4656 降到 0.0575）；
      只用类别标签时可以不校准，但必须把阈值一并冻结。
```

```text
坑 3：把「多分类策略比较」做成了「算法比较」
结论：得出「OvO 比原生多分类强很多」的结论，据此改造线上模型后没有收益。
原因：本机实测 OvO 用的是 LogisticRegression、OvR 用的是 LinearSVC，
      0.8667 与 0.7756 的差距来自基分类器不同，不是策略不同。
解法：比较策略时必须固定基学习器与全部超参，只切换 OneVsRest / OneVsOne 包装；
      本机用同一 LogReg 基分类器重跑后差距缩小（见多分类策略章节）。
```

```text
坑 4：对近似对称的目标做 log 变换，指标反而变差
结论：以为「右偏就 log、右偏就 log」，结果 RMSE 涨了 5%。
原因：本机实测目标偏度只有 0.3972（接近对称），log 变换引入了不必要的非线性偏置，
      exp 反变换还会放大误差：RMSE 从 575.09 涨到 607.50。
解法：先用偏度、QQ 图或对数直方图判断；偏度绝对值很大（比如 > 1）且目标为正时
      才值得尝试变换，并且变换前后都要在同一原始尺度上比指标。
```

```text
坑 5：未标准化就上 SGD 系求解器，误判「模型能力不行」
结论：换了好几版特征工程，SGD 的准确率一直在 0.91 附近不动。
原因：本机实测同一份数据、同一组超参，SGDClassifier 未标准化 acc 0.9123、
      标准化后 0.9708——迭代式求解器的梯度被大量纲特征主导，方向本身就偏。
解法：SGD 系（SGDClassifier/SGDRegressor、神经网络的 SGD 优化器）必须配
      StandardScaler；并优先考虑 lbfgs 等拟牛顿法作为对照，确认差距来自求解器而非模型。
```

```text
坑 6：用 F1 最优阈值上线，忽略了成本不对称
结论：模型配置在评审时「指标最好」，但业务成本不是最低。
原因：本机实测 F1 最优阈值 0.8920（F1 0.2517）对应的总代价是 30500 元，
      而代价最优阈值 0.7 对应 26660 元。F1 隐含 precision 与 recall 等权，
      而漏判成本 500 元是误报成本 20 元的 25 倍。
解法：先写出完整的代价矩阵，直接在验证集上枚举阈值选总代价最小者；
      并把该阈值与模型一起冻结进配置文件，不要用库的默认 0.5。
```

```text
坑 7：Lasso 的 alpha 沿用了别处的经验值，模型预测能力崩塌
结论：Lasso 的 MSE 比 OLS 高一个数量级，怀疑 Lasso 不适合这份数据。
原因：本机实测 alpha=100 时 Lasso 把所有系数清零，退化成用均值预测，
      测试 MSE 达到 17334.699（OLS 是 188.739）。
解法：alpha 的量级与特征尺度、样本量强相关，必须用 LassoCV / RidgeCV
      在交叉验证下选择；同时把 `n_iter_` 与「非零系数个数」一起打印，
      非零系数为 0 时立刻报警。
```

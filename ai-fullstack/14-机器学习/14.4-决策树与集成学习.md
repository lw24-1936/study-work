## 概述

决策树是唯一一类既能处理非线性关系又天然可解释的通用模型，但单棵极不稳定——训练数据扰动一点点，整棵树的结构就会变。集成学习正是为修这个问题而生：Bagging 用并行训练的多棵「高方差」树投票把方差平均掉，Boosting 用串行训练的多棵「高偏差」树逐轮纠错把偏差降下来。在结构化表格数据上，梯度提升树（GBDT）家族至今仍是最强的通用算法之一，随机森林则是最省心的基线。

## 信息增益与基尼指数

决策树在每个节点上做一件事：在所有特征的所有切分点里，选一个让子节点「最纯」的切分。衡量「纯度」的两种主流指标：

$$
\text{熵：} H(S) = -\sum_{k=1}^{K} p_k \log_2 p_k, \qquad \text{基尼指数：} G(S) = 1 - \sum_{k=1}^{K} p_k^2
$$

**信息增益**是切分前后熵的下降量，按子节点样本占比加权：

$$
\text{Gain}(S, f, t) = H(S) - \frac{|S_L|}{|S|}H(S_L) - \frac{|S_R|}{|S|}H(S_R)
$$

其中 $t$ 是切分点，$S_L = \{x \in S : x_f \le t\}$、$S_R = S \setminus S_L$。基尼指数就是信息增益的「不取对数」版本，省掉一次 $\log$ 计算，因此 scikit-learn 把它作为默认准则。两者都满足「越纯越小」：两类各占 50% 时熵为 1 bit、基尼为 0.5；完全纯时为 0。

下面用一份 8 个样本的玩具数据手算所有候选切分的信息增益与加权基尼，再与 sklearn 学到的树对照：

```python
import numpy as np
from sklearn.tree import DecisionTreeClassifier, export_text

def entropy(counts):
    p = np.asarray(counts, dtype=float)
    p = p[p > 0] / p.sum()
    return float(-(p * np.log2(p)).sum())

def gini(counts):
    p = np.asarray(counts, dtype=float) / np.sum(counts)
    return float(1.0 - (p ** 2).sum())

f = np.array([1.0, 1.5, 2.0, 2.5, 3.0, 4.0, 4.5, 5.0])
lab = np.array([0, 0, 0, 1, 0, 1, 1, 1])
H0 = entropy(np.bincount(lab))
print("全样本熵 H =", round(H0, 6), "| 基尼 =", round(gini(np.bincount(lab)), 6))
best = None
for t in np.unique(f)[:-1]:
    left, right = lab[f <= t], lab[f > t]
    wl, wr = len(left) / len(lab), len(right) / len(lab)
    cond = wl * entropy(np.bincount(left, minlength=2)) + wr * entropy(np.bincount(right, minlength=2))
    cond_g = wl * gini(np.bincount(left, minlength=2)) + wr * gini(np.bincount(right, minlength=2))
    print(f"<= {t}: 左 {np.bincount(left, minlength=2)} 右 {np.bincount(right, minlength=2)}"
          f" 信息增益 {H0 - cond:.6f} 加权基尼 {cond_g:.6f}")
    if best is None or (H0 - cond) > best[1]:
        best = (t, H0 - cond)
tree = DecisionTreeClassifier(criterion="entropy", max_depth=1, random_state=0).fit(f.reshape(-1, 1), lab)
print("sklearn 学到的阈值:", round(float(tree.tree_.threshold[0]), 4))
print(export_text(tree, feature_names=["f"]))
```

两点需要解释清楚。第一，手算的「最优阈值 2.0」与 sklearn 的 `2.25` 数值不等，但它们是**同一个切分**：sklearn 把阈值定义在相邻两个取值的中点 $\frac{2.0+2.5}{2}=2.25$，判据是 `X[:, f] <= threshold` 走左分支，因此 `X <= 2.25` 与手算的 `X <= 2.0` 划分出的样本集合完全相同（左边都是 $\{1.0, 1.5, 2.0\}$）。第二，信息增益 0.548795 在两个候选（`<=2.0` 与 `<=3.0`）上并列，这是对称数据造成的，sklearn 会取其中一个。

熵与基尼在真实数据上的差别，用乳腺癌数据直接对照：


三者训练集都拟合到 1.0000（不限制深度时决策树能完美记忆训练数据），但 `entropy` 与 `log_loss` 生成 23 个节点、测试准确率 0.9298，`gini` 生成 31 个节点、测试准确率 0.9064。差别不来自「哪个准则数学上更优」，而来自贪心切分路径的微小分歧：切分顺序不同会长出结构不同的树，泛化表现随之波动。sklearn 从 1.1 起把 `log_loss` 作为独立选项（与 `entropy` 数学等价，只差常数因子与内部实现），实践中用默认的 `gini` 即可，不值得在这上面调参。

```text
5. 决策树不限制深度时训练集必然拟合到 100%，泛化完全靠生长控制
6. 熵含 log 计算更贵，sklearn 默认 gini 是性价比选择
```

## 树的生长控制与剪枝

不加限制的决策树会把训练集记忆到 100%，因此控制复杂度是使用它的前提。scikit-learn 提供两类手段。

**预剪枝（pre-pruning）**：在生长过程中就阻止分裂。

| 参数 | 默认 | 作用 |
|------|------|------|
| `max_depth` | `None` | 树最大深度，最直观的容量旋钮 |
| `min_samples_split` | 2 | 内部节点继续分裂所需的最小样本数 |
| `min_samples_leaf` | 1 | 叶子节点的最小样本数，对不平衡数据尤其有效 |
| `max_leaf_nodes` | `None` | 叶子总数上限，按「最佳优先」方式生长 |
| `max_features` | `None` | 每次分裂考虑的特征数（在森林里分类默认 `sqrt`） |
| `min_impurity_decrease` | 0.0 | 分裂带来的最小不纯度下降，低于则不分裂 |

**后剪枝（post-pruning）**：先长满，再按代价复杂度剪掉弱分支。scikit-learn 实现的是**最小代价复杂度剪枝**（minimal cost-complexity pruning，又称 weakest link pruning），目标函数为

$$
R_\alpha(T) = R(T) + \alpha |\tilde{T}|
$$

其中 $R(T)$ 是训练误差、$|\tilde{T}|$ 是叶子数、$\alpha$ 是复杂度惩罚系数（对应 `ccp_alpha`）。$\alpha$ 越大树越小。`cost_complexity_pruning_path()` 返回整条「最优子树序列」所对应的 $\alpha$ 值，是选 $\alpha$ 的标准入口。

```python
import numpy as np
from sklearn.datasets import load_breast_cancer
from sklearn.model_selection import train_test_split
from sklearn.tree import DecisionTreeClassifier
from sklearn.metrics import accuracy_score

X, y = load_breast_cancer(return_X_y=True)
Xtr, Xte, ytr, yte = train_test_split(X, y, test_size=0.3, random_state=0, stratify=y)

for d in [1, 2, 3, 5, 8, None]:
    m = DecisionTreeClassifier(max_depth=d, random_state=0).fit(Xtr, ytr)
    print(f"max_depth={d}: 深度 {m.get_depth()} 叶节点 {m.get_n_leaves()}"
          f" 训练 {accuracy_score(ytr, m.predict(Xtr)):.4f} 测试 {accuracy_score(yte, m.predict(Xte)):.4f}")

base = DecisionTreeClassifier(random_state=0).fit(Xtr, ytr)
path = base.cost_complexity_pruning_path(Xtr, ytr)
for a in path.ccp_alphas[:: max(1, len(path.ccp_alphas) // 8)]:
    m = DecisionTreeClassifier(ccp_alpha=float(a), random_state=0).fit(Xtr, ytr)
    print(f"ccp_alpha={a:.6f} 节点数 {m.tree_.node_count} 训练 {accuracy_score(ytr, m.predict(Xtr)):.4f}"
          f" 测试 {accuracy_score(yte, m.predict(Xte)):.4f}")
```

代价复杂度剪枝的正式用法是配合交叉验证：把 `path.ccp_alphas` 作为候选网格，用 `GridSearchCV` 选最优。scikit-learn 官方文档（1.10. Decision Trees 的 "Minimal Cost-Complexity Pruning" 一节）给出的就是这套流程。

```text
3. ccp_alpha 走整条最优子树序列，比单点猜 max_depth 更有依据

5. 剪枝路径上每个 alpha 都要用验证集评估，本机实测最优点在 9~13 个节点
6. 决策树对特征尺度不敏感；scikit-learn 的决策树不原生支持缺失值（HistGB 支持）
```

## Bagging 与随机森林

单棵树的问题是**高方差**：训练数据轻微变动，树结构就变。Bagging（Bootstrap Aggregating）用「自助采样 + 投票平均」直接攻方差：从 $n$ 个样本中有放回地抽 $n$ 个训练一棵树，重复 $B$ 次，回归取平均、分类取多数票。若每棵树的方差为 $\sigma^2$、两两相关系数为 $\rho$，平均后的方差为：

$$
\mathrm{Var}\left(\frac{1}{B}\sum_{b=1}^{B} T_b\right) = \rho\sigma^2 + \frac{1-\rho}{B}\sigma^2
$$

这个式子说明了集成的两条改进方向：**增加 $B$（树的数量）只能压掉第二项**，第一项 $\rho\sigma^2$ 只能靠**降低树之间的相关性 $\rho$** 来压。随机森林就是这条思路：在 Bagging 基础上，每次分裂只在随机抽出的 $m$ 个特征里选最优（分类默认 $m = \sqrt{d}$），强制树在不同特征子集上做决策，直接压低 $\rho$。

自助采样还有一个附带好处：每棵树大约有 $1 - (1-1/n)^n \approx 1 - e^{-1} \approx 36.8\%$ 的样本没被抽到，这些「袋外样本」（Out-Of-Bag, OOB）可当作免费验证集，用 `oob_score=True` 直接得到泛化估计，不必单独切分数据。

```python
from sklearn.tree import DecisionTreeClassifier
from sklearn.ensemble import (BaggingClassifier, RandomForestClassifier, ExtraTreesClassifier)

for name, model in [
    ("单棵决策树", DecisionTreeClassifier(random_state=0).fit(Xtr, ytr)),
    ("Bagging(100, tree)", BaggingClassifier(DecisionTreeClassifier(random_state=0),
                                             n_estimators=100, random_state=0).fit(Xtr, ytr)),
    ("随机森林(100)", RandomForestClassifier(n_estimators=100, random_state=0,
                                          oob_score=True).fit(Xtr, ytr)),
    ("ExtraTrees(100)", ExtraTreesClassifier(n_estimators=100, random_state=0).fit(Xtr, ytr)),
]:
    s = f"{name:>20}: 测试 acc {accuracy_score(yte, model.predict(Xte)):.4f}"
    if getattr(model, "oob_score", False):
        s += f" | OOB acc {model.oob_score_:.4f}"
    print(s)
```

本机真实输出：

```text
== 6. Bagging 与随机森林 ==
                 单棵决策树: 测试 acc 0.9064
    Bagging(100, tree): 测试 acc 0.9357
             随机森林(100): 测试 acc 0.9532 | OOB acc 0.9698
       ExtraTrees(100): 测试 acc 0.9357

```

单棵 0.9064 → Bagging 0.9357 → 随机森林 0.9532，两级提升分别来自「平均降方差」与「特征子集降相关」。随机森林的 OOB 准确率 0.9698 高于测试集 0.9532，量级一致，可作为「不切分数据也能看泛化」的快速检查。注意最后一行：`ExtraTreesClassifier` 默认 `bootstrap=False`（它用全部样本训练，只在切分点随机化），因此 `oob_score=True` 会直接抛 `ValueError` 而不是静默忽略——本机就是这么撞上的。

`max_features` 的实测效果，与上面的方差分解式完全对应：

```text

  max_features   测试 acc   OOB acc   树间平均相关系数
          sqrt   0.9532    0.9698     0.7945
          log2   0.9474    0.9598     0.7851
          None   0.9240    0.9523     0.8261

```

`max_features=None`（每棵树用全部 30 个特征）时树间相关系数最高（0.8261）、测试准确率最低（0.9240）；`sqrt`（约 5 个特征）把相关系数降到 0.7945、准确率升到 0.9532。`log2`（约 4 个特征）相关系数最低（0.7851）但准确率反而略低（0.9474）——说明相关性只是影响集成效果的一个因素，特征太少时单棵树的偏差上升会抵消降相关带来的好处。

```text
Bagging 与随机森林要点：
1. Bagging 攻击方差：自助采样 + 平均，理论方差含 rho*sigma^2 与 (1-rho)/B 两项
2. 加树只压 (1-rho)/B 项，降相关才能压 rho*sigma^2，这是随机森林的立足点
3. max_features 是随机森林最关键的参数，默认分类 sqrt、回归 1.0（即全部特征）
4. OOB 准确率是免费验证集；n_estimators 太少时 sklearn 会警告「OOB 不可靠」
5. ExtraTrees 默认 bootstrap=False，因此 oob_score=True 直接报错
6. 树的数量趋平后继续加只增加推理成本，本机 100 到 500 棵测试准确率不变
```

## Boosting 与 GBDT

Boosting 走相反方向：不是并行训练独立模型再平均，而是**串行**训练一系列弱模型，每个新模型专注修正前面所有模型的累计误差。它降的是偏差，不是方差。

**AdaBoost** 的思路是调样本权重：初始所有样本等权，每轮训练一个弱分类器，被分错的样本权重提高，下一轮被迫关注这些难例，最终按各弱分类器的准确率加权投票。

**梯度提升（Gradient Boosting）** 把它统一成「在函数空间做梯度下降」。给定可微损失 $L$，模型是加法形式 $F_m(x) = F_{m-1}(x) + \nu h_m(x)$，第 $m$ 轮的基学习器 $h_m$ 拟合当前模型的**负梯度**：

$$
h_m = \arg\min_{h} \sum_{i=1}^{n}\left(-\frac{\partial L(y_i, F(x_i))}{\partial F(x_i)}\bigg|_{F=F_{m-1}} - h(x_i)\right)^2
$$

其中 $\nu$ 是 `learning_rate`（收缩系数），它缩小每棵树的影响，需要更多树但泛化更好。对平方损失，负梯度恰好等于残差 $y_i - F_{m-1}(x_i)$，所以 GBDT 回归常被描述为「每棵树拟合前面的残差」。下面直接观察加法模型的逐轮收敛：

```python
from sklearn.datasets import make_regression
from sklearn.ensemble import GradientBoostingRegressor
from sklearn.tree import DecisionTreeRegressor
from sklearn.metrics import mean_squared_error

Xr, yr = make_regression(n_samples=400, n_features=8, noise=20.0, random_state=0)
Xrtr, Xrte, yrtr, yrte = train_test_split(Xr, yr, test_size=0.3, random_state=0)
for i in range(1, 11):
    g = GradientBoostingRegressor(n_estimators=i, learning_rate=1.0, max_depth=1, random_state=0).fit(Xrtr, yrtr)
    print(f"轮次 {i:>2}: 训练 MSE {mean_squared_error(yrtr, g.predict(Xrtr)):10.3f}")
print("单棵深度 3 回归树测试 MSE:",
      round(mean_squared_error(yrte, DecisionTreeRegressor(max_depth=3, random_state=0)
                               .fit(Xrtr, yrtr).predict(Xrte)), 3))
```

第一棵深度 1 的「树桩」把 MSE 从约 15000 降到 14950——单棵弱到几乎没用；10 轮后降到 3914，最终测试 MSE 6276.7，明显优于单棵深度 3 回归树的 10374.4。这就是 Boosting 的本质：**用很多很弱的模型拼出一个强模型**。注意轮次间下降越来越小（第 2 轮降 3414，第 10 轮只降 316），符合「偏差被逐步吃掉」的规律。

`learning_rate` 与 `n_estimators` 是一对强耦合参数：缩小学习率通常要增加树的数量。实测：

```text

  0.05          200            1.0000    0.9357    0.00846

  1.0           10             1.0000    0.9474    0.00517
```

训练准确率全部 1.0000（容量足够时 GBDT 能拟合任何训练集），差异全在测试集：`lr=1.0 / 10 棵` 得到 0.9474，`lr=0.5 / 20 棵` 却是 0.9298。**「学习率 × 树数的乘积相等」并不意味着效果等价**——学习率影响每步的步长与收敛路径，两者是独立的超参。这份数据只有 398 个训练样本，随机波动占了主导，正确做法是用 3 折或 5 折交叉验证在这个二维网格上搜索（见下节场景二）。

**scikit-learn 提供两套 GBDT 实现**，官方文档明确给出二者取舍：

| 维度 | `GradientBoostingClassifier` | `HistGradientBoostingClassifier` |
|------|------------------------------|----------------------------------|
| 算法 | 精确贪心切分（预排序） | 直方图分箱（默认 256 个 bin），灵感来自 LightGBM |
| 速度 | 慢，样本数上万时差距可达数量级 | 快，官方称数万样本以上可快几个数量级 |
| 缺失值 | 不支持，遇到 NaN 直接报错 | **原生支持**，每个切分点自动学习 NaN 的走向 |
| 类别特征 | 不支持 | 支持（`categorical_features`） |
| 损失函数 | 更多（含 `huber`、`quantile` 等） | 较少（分类 `log_loss`；回归 `squared_error`/`absolute_error`/`poisson`/`gamma`/`quantile`） |
| 小样本 | 更合适（分箱会让切分点过于粗糙） | 样本很少时不如前者 |
| 早停 | 不支持内建早停 | `early_stopping=True` + `n_iter_no_change` |
| 主要参数 | `n_estimators` / `learning_rate` / `max_depth` | `max_iter` / `learning_rate` / `max_leaf_nodes` |

```text

    HistGradientBoosting(max_iter=100):   0.76s | 测试 acc 0.9485
  HistGB 直接吃 NaN（无 imputer）测试 acc: 0.9485
  GradientBoostingClassifier 遇到 NaN 直接报错: Input X contains NaN.
```

本机在 50000 行 × 40 特征的合成数据上实测：原版 `GradientBoosting` 训练 100 棵用 49.08 秒、测试准确率 0.8795；`HistGradientBoosting` 同样 100 棵只用 0.76 秒、准确率 0.9485——**快约 64 倍，准确率还更高**。这符合官方的说法：直方图分箱把每列的候选切分点从 $O(n)$ 降到 $O(\text{bins})$，大数据上收益最大；准确率差异来自分箱带来的平滑正则化效果。`HistGB` 还能直接吃 `NaN`（准确率 0.9485，与无缺失时持平），而 `GradientBoostingClassifier` 抛 `ValueError: Input X contains NaN.`。

AdaBoost 与 GBDT 的直接对照：

```text
== 11. AdaBoost 与 GBDT 的对照 ==
           AdaBoost(50, depth=1): 测试 acc 0.9415 auc 0.9890
          AdaBoost(200, depth=3): 测试 acc 0.9532 auc 0.9908
   GradientBoosting(100, lr=0.1): 测试 acc 0.9357 auc 0.9863
       HistGradientBoosting(100): 测试 acc 0.9415 auc 0.9892
```

`AdaBoost(200, depth=3)` 在这份小数据上最好（0.9532 / AUC 0.9908）。AdaBoost 对噪声标签敏感（被错标的样本权重会被反复放大），GBDT 的 `learning_rate` 收缩对这类噪声更宽容；数据越脏、越大，GBDT 的优势越明显。

```text
Boosting 与 GBDT 要点：
1. Boosting 串行地降偏差，Bagging 并行地降方差，方向恰好相反
2. GBDT 的每棵树拟合损失函数的负梯度，平方损失下就是残差
3. learning_rate 与 n_estimators 是独立超参，乘积相等不等于效果相等
4. HistGradientBoosting 在大样本上快一个数量级且原生支持 NaN 与类别特征
5. 原版 GradientBoosting 遇到 NaN 直接报错，必须先填充；小样本时它更合适

```

## 梯度提升库对比

scikit-learn 之外有三个生产级梯度提升库，都走「分箱 + 直方图」路线，但各有侧重。

| 维度 | XGBoost | LightGBM | CatBoost |
|------|---------|----------|----------|
| 主要特色 | 生态成熟、正则化项最完整、精确贪心与直方图双模式 | 叶子优先生长、GOSS 采样、EFB 特征捆绑，速度最快 | 有序目标统计处理类别特征，抗过拟合，默认参数好 |
| 分裂策略 | `tree_method='hist'` 或精确贪心，`grow_policy` 默认 `depthwise` | `num_leaves` 控制叶子数（默认 31），叶子优先 | 对称树（oblivious tree），训练快、推理更快 |
| 类别特征 | 需手动编码（或用 `enable_categorical`） | 原生 `categorical_feature` | 原生 `cat_features`，目标统计自动编码 |
| 缺失值 | 原生（自动学习方向） | 原生 | 原生 |
| 默认防过拟合 | `reg_lambda=1` | `reg_lambda=0`（需要自己加） | 默认正则较强 |
| 关键调参点 | `learning_rate`、`max_depth`、`min_child_weight`、`subsample`、`colsample_bytree`、`reg_lambda` | `learning_rate`、`num_leaves`、`min_child_samples`、`feature_fraction`、`bagging_fraction` | `learning_rate`、`depth`、`l2_leaf_reg` |
| 官方文档 | xgboost.readthedocs.io | lightgbm.readthedocs.io | catboost.ai/docs |

本机实测三库在同一份数据上的表现（50000 行 × 40 特征，都跑 200 棵、`learning_rate=0.1`、深度 3）：

```text
== 12. sklearn / XGBoost / LightGBM 三库对照 ==
xgboost 3.4.1 | lightgbm 4.7.0
  50000x40 数据集 | XGBoost 0.53s acc 0.9080 | LightGBM 0.41s acc 0.9123 | HistGB 1.30s
```

LightGBM 0.41 秒、XGBoost 0.53 秒、sklearn 的 `HistGradientBoosting` 1.30 秒，三者准确率都在 0.908~0.912。**速度差异在几倍量级，准确率差异在千分位**——这类场景下选库的依据应该是工程因素（部署依赖大小、类别特征支持、训练资源、团队熟悉度），而不是那零点几个百分点的准确率。

参数默认值这块有一个容易踩的坑：XGBoost 3.x 的 `get_params()` 对未显式设置的参数一律返回 `None`，真正的默认值藏在底层 Booster 配置里。本机直接读取配置拿到了事实：

```text

```

即 XGBoost 3.4.1 的库默认是 `learning_rate(eta)=0.3`、`max_depth=6`、`max_bin=256`、`reg_lambda=1`、`subsample=1`、`colsample_bytree=1`。**默认 `eta=0.3` 偏大、`max_depth=6` 偏深，直接拿来用通常不是最优**，生产环境一般要显式设置这两项。

LightGBM 的 `get_params()` 则是直给：

```text
  n_estimators = 100
  learning_rate = 0.1
  num_leaves = 31
  max_depth = -1
  min_child_samples = 20
  subsample = 1.0
  colsample_bytree = 1.0
  reg_lambda = 0.0
  reg_alpha = 0.0
  boosting_type = gbdt
```

`max_depth=-1` 表示不限深度、由 `num_leaves` 控制复杂度，这是 LightGBM 与 XGBoost 最核心的理念差异：**LightGBM 用叶子数而非深度描述容量**。因此 `num_leaves` 超过 $2^{\text{max\_depth}}$ 时会被深度截断，多余部分完全无效：

```text
== 单棵树 num_leaves 超过 2^max_depth 时的行为 ==
  max_depth=3, num_leaves=  8: 测试 acc 0.9415
  max_depth=3, num_leaves= 31: 测试 acc 0.9415
  max_depth=3, num_leaves=128: 测试 acc 0.9415
  max_depth=3, num_leaves=512: 测试 acc 0.9415
```

`max_depth=3` 时 $2^3=8$，把 `num_leaves` 从 8 调到 512 结果完全不变（都是 0.9415）——白白浪费了搜索空间，还会让调参脚本误以为「这个参数不敏感」。**同时设 `num_leaves` 与 `max_depth` 时，要先确认谁在生效。** CatBoost 未在本机安装，相关结论以 catboost.ai/docs 为准。

```text
梯度提升库对比要点：
1. 三库的算法路线一致（分箱 + 直方图），差别在生长策略、类别特征与工程细节
2. 同数据同配置下速度差几倍、准确率差千分位，选库应看工程因素而非零点几个百分点
3. XGBoost 3.x 的 get_params() 对未设参数返回 None，默认值要从 Booster 配置读
4. XGBoost 默认 eta=0.3、max_depth=6 偏激进，生产通常要显式调小
5. LightGBM 用 num_leaves 描述容量，与 max_depth 同时设置时后者会截断前者
6. LightGBM 默认 reg_lambda=0，抗过拟合要自己配；XGBoost 默认 reg_lambda=1
```

## 集成策略 Voting 与 Stacking

除了同质集成（都是树），还可以做异质集成：把类型不同的学习器组合起来。

**Voting** 是最简单的组合：硬投票取多数类，软投票取预测概率的平均。软投票通常更好，因为它利用了模型对各类的置信度。

**Stacking** 更进一步：把基学习器的预测当作新特征，再训练一个「元学习器」（meta-learner）学习如何组合它们。关键在于元特征必须用**交叉验证**生成（`cv` 参数），否则基学习器在训练集上的预测会因过拟合而失真，元学习器会过度信任它。

```python
from sklearn.ensemble import VotingClassifier, StackingClassifier
from sklearn.linear_model import LogisticRegression
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

lr_est = make_pipeline(StandardScaler(), LogisticRegression(max_iter=5000))
rf_est = RandomForestClassifier(n_estimators=300, random_state=0, n_jobs=-1)
hgb_est = HistGradientBoostingClassifier(max_iter=200, random_state=0)
voting = VotingClassifier([("lr", lr_est), ("rf", rf_est), ("hgb", hgb_est)],
                         voting="soft", n_jobs=-1).fit(Xtr, ytr)
stacking = StackingClassifier([("lr", lr_est), ("rf", rf_est), ("hgb", hgb_est)],
                              final_estimator=LogisticRegression(max_iter=5000),
                              cv=5, n_jobs=-1).fit(Xtr, ytr)
```

本机实测结果见下节场景二的完整擂台表。结论是反直觉的：**Voting 与 Stacking 都没能超过单跑逻辑回归**（Stacking 测试 AUC 0.9930、Voting 0.9920，逻辑回归 0.9956），而 Stacking 的训练耗时 3.22 秒是逻辑回归 0.05 秒的 64 倍。原因在于基学习器水平不相当——这份数据上随机森林的 AUC 只有 0.9781，明显弱于逻辑回归的 0.9956，元学习器无法从弱模型里获益，反而引入了额外噪声。**集成不是免费的午餐：只有基学习器水平相当且误差模式互补时，集成的收益才成立。**

```text
集成策略要点：
1. 软投票优于硬投票，因为它保留了各类的置信度信息
2. Stacking 的元特征必须交叉验证生成，否则元学习器学到的是过拟合信号
3. 集成的收益来自基学习器的「多样性 + 同等水平」，弱基学习器会拖累整体
4. 本机实测 Stacking 耗时是最好单模型的 64 倍而 AUC 略低，成本收益必须实测
5. Voting 与 Stacking 会让推理变复杂（多模型编排），上线前评估维护成本
6. 先确认单模型已经调好，再考虑集成——顺序反了会浪费大量算力
```

## 应用场景实战

### 场景一：随机森林基线与可解释性交付

场景：某医疗数据团队要用 30 维的细胞核形态特征做良恶性判别，要求模型能上线并且**能向临床医生解释每个判断的依据**。随机森林能给出高准确率，但它本身是黑箱，所以除了模型还要交付三样可解释性产物：不纯度重要性、置换重要性、以及一棵「代理树」。

```python
import numpy as np
import pandas as pd
from sklearn.datasets import load_breast_cancer
from sklearn.model_selection import train_test_split, StratifiedKFold, cross_val_score
from sklearn.tree import DecisionTreeClassifier, export_text
from sklearn.ensemble import RandomForestClassifier, ExtraTreesClassifier, BaggingClassifier
from sklearn.inspection import permutation_importance
from sklearn.metrics import accuracy_score, roc_auc_score

X, y = load_breast_cancer(return_X_y=True)
FEATS = load_breast_cancer().feature_names
Xtr, Xte, ytr, yte = train_test_split(X, y, test_size=0.3, random_state=0, stratify=y)

rf = RandomForestClassifier(n_estimators=500, max_features="sqrt", oob_score=True,
                            random_state=0, n_jobs=-1).fit(Xtr, ytr)
print("OOB acc:", round(rf.oob_score_, 4), "| 测试 acc:", round(accuracy_score(yte, rf.predict(Xte)), 4),
      "| AUC:", round(roc_auc_score(yte, rf.predict_proba(Xte)[:, 1]), 4))

imp = pd.Series(rf.feature_importances_, index=FEATS).sort_values(ascending=False)
pi = permutation_importance(rf, Xte, yte, n_repeats=10, random_state=0, n_jobs=-1)
pi_s = pd.Series(pi.importances_mean, index=FEATS).sort_values(ascending=False)

# 代理树：用一棵浅树去模仿随机森林的完整预测
surr = DecisionTreeClassifier(max_depth=3, random_state=0).fit(X, rf.predict(X))
print("浅树对随机森林预测的一致率:", round(accuracy_score(rf.predict(X), surr.predict(X)), 4))
print(export_text(surr, feature_names=list(FEATS), decimals=2))
```

```text
             随机森林(500): 5 折 AUC 0.9946 +/- 0.0059
       ExtraTrees(500): 5 折 AUC 0.9956 +/- 0.0044
```

这份输出有五个交付要点：

- **树的数量在 100 棵之后收益停止**：OOB 从 10 棵的 0.9422 升到 100 棵的 0.9698，到 500 棵反而略降到 0.9648（OOB 本身有抽样噪声），测试准确率停在 0.9532。生产配置 200~500 棵足够，继续加只增加推理成本。
- **两种重要性只重合 4/5**：MDI（不纯度下降）把 `worst perimeter` 排第一，置换重要性把 `worst radius` 排第一，且 `worst texture` 在置换里进前 5、在 MDI 里进不了。MDI 基于训练集的不纯度下降、偏向取值多或连续的特征（连续特征有更多切分点，天然更容易带来不纯度下降），因此向业务解释时优先用置换重要性。
- **代理树是一个可用的解释工具**：一棵深度 3 的浅树能复现随机森林 97.72% 的预测，规则可以直接读出来。临床医生看到的是一条 `worst concave points <= 0.14 且 worst area <= 957.45 且 worst perimeter <= 107.75` 的判据，而不是 500 棵树的投票。
- **集成的层级收益与方差收缩**：单棵树 5 折 AUC 0.9149 ± 0.0289（方差最大）→ Bagging 0.9894 ± 0.0097 → 随机森林 0.9946 ± 0.0059 → ExtraTrees 0.9956 ± 0.0044。标准差从 0.0289 一路压到 0.0044，这是「bagging 降方差」最直白的证据。
- **ExtraTrees 在本例中略优于随机森林**（0.9956 vs 0.9946，标准差也更小），因为它的切分点随机化更强、进一步降低了树间相关。但它在需要精确阈值（如 `<= 0.14` 这种医学界值）的场景下不如随机森林贴合，因为它的切分点是随机选的。

### 场景二：梯度提升调参并击败随机森林的完整擂台

场景：同样的数据，要回答「能不能比随机森林更好」。做法是先把 `learning_rate × n_estimators` 用网格搜索扫一遍，再用 `HistGradientBoosting` 的早停控制训练成本，最后把线性模型、两种 GBDT、Voting、Stacking 与 XGBoost / LightGBM 放在同一测试集上比较。

```python
import time
import pandas as pd
from sklearn.model_selection import StratifiedKFold, cross_val_score, GridSearchCV
from sklearn.ensemble import (RandomForestClassifier, GradientBoostingClassifier,
                              HistGradientBoostingClassifier, VotingClassifier, StackingClassifier)
from sklearn.linear_model import LogisticRegression
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.metrics import accuracy_score, roc_auc_score

cv = StratifiedKFold(5, shuffle=True, random_state=0)

grid = {"learning_rate": [0.02, 0.05, 0.1, 0.3], "n_estimators": [50, 100, 300, 600]}
gs = GridSearchCV(GradientBoostingClassifier(max_depth=2, random_state=0), grid,
                  scoring="roc_auc", cv=3, n_jobs=-1).fit(Xtr, ytr)
print(pd.DataFrame(gs.cv_results_).pivot_table(index="param_learning_rate",
                                               columns="param_n_estimators",
                                               values="mean_test_score").round(4).to_string())
print("最佳:", gs.best_params_, "CV AUC", round(gs.best_score_, 4))

hgb = HistGradientBoostingClassifier(max_iter=2000, learning_rate=0.05, early_stopping=True,
                                     validation_fraction=0.15, n_iter_no_change=20,
                                     random_state=0).fit(Xtr, ytr)
print("实际迭代轮数:", hgb.n_iter_, "| 测试 AUC:",
      round(roc_auc_score(yte, hgb.predict_proba(Xte)[:, 1]), 4))

lr_est = make_pipeline(StandardScaler(), LogisticRegression(max_iter=5000))
rf_est = RandomForestClassifier(n_estimators=300, random_state=0, n_jobs=-1)
hgb_est = HistGradientBoostingClassifier(max_iter=200, random_state=0)
cands = {
    "逻辑回归": lr_est,
    "随机森林(500)": RandomForestClassifier(n_estimators=500, random_state=0, n_jobs=-1),
    "原版 GB(调参)": GradientBoostingClassifier(**gs.best_params_, max_depth=2, random_state=0),
    "HistGB(早停)": HistGradientBoostingClassifier(max_iter=2000, learning_rate=0.05,
                                                   early_stopping=True, random_state=0),
    "Voting(LR+RF+HistGB)": VotingClassifier([("lr", lr_est), ("rf", rf_est), ("hgb", hgb_est)],
                                             voting="soft", n_jobs=-1),
    "Stacking(-> LR)": StackingClassifier([("lr", lr_est), ("rf", rf_est), ("hgb", hgb_est)],
                                          final_estimator=LogisticRegression(max_iter=5000),
                                          cv=5, n_jobs=-1),
}
for name, m in cands.items():
    t0 = time.perf_counter()
    m.fit(Xtr, ytr)
    dt = time.perf_counter() - t0
    s = cross_val_score(m, Xtr, ytr, cv=cv, scoring="roc_auc", n_jobs=-1)
    print(f"{name:<28} 测试 acc {accuracy_score(yte, m.predict(Xte)):.4f} "
          f"AUC {roc_auc_score(yte, m.predict_proba(Xte)[:, 1]):.4f} 5折CV {s.mean():.4f} ({dt:.2f}s)")
```

这份擂台表最有价值的结论是反直觉的：**逻辑回归赢了所有树模型**（测试 AUC 0.9956、5 折 CV 0.9964、训练 0.05 秒）。原因不在「逻辑回归更强」，而在这份数据：569 条样本、30 个特征、近似线性可分，随机森林（0.9781）与 GBDT 都在这个规模上过拟合。三条可迁移的判断：

- **样本量决定算法选择的起点**。569 条样本上线性模型就是强基线；集成方法的优势需要更大的数据量才能兑现（本机 50000 行的合成数据上 XGBoost / LightGBM 能到 0.91 以上，而这类数据线性模型难以匹配）。**先跑线性基线再决定要不要上集成**，这是本场景最重要的结论。
- **网格搜索的形态符合预期**：`learning_rate` 从 0.02 升到 0.3 时 CV AUC 单调上升（0.9738 → 0.9916），说明小数据上需要较大的学习率才能进入有效区域；`n_estimators` 超过 300 后曲线趋平（0.9918 三列持平）。这也印证了「学习率与树数不是简单乘积关系」——它们各自影响步长与有效容量。
- **早停与集成都有隐藏成本**：`HistGB` 在 `early_stopping=True` 下 85 轮就停（上限 2000），测试 AUC 0.9747；而擂台里 `n_iter_no_change` 取默认值的版本测试 AUC 0.9810，两者都低于原版 GB 调参后的 0.9889。早停用验证集损失做判据，小数据上判据噪声大，容易停在次优点。Stacking 训练 3.22 秒是逻辑回归的 64 倍、测试 AUC 0.9930 却更低，属于典型的负收益集成。**集成的收益必须实测，不能假设。**

## 最佳实践与踩坑记录

### 最佳实践

1. 先跑单棵决策树再跑集成。单棵 5 折 AUC 0.9149、随机森林 0.9946（本机实测），这个对比能量化「集成带来的收益」，也是判断集成是否必要的第一步。
2. 用 `oob_score=True` 做免费验证。随机森林的 OOB 与测试集指标量级一致（本机 0.9698 vs 0.9532），数据紧张时可以用它代替验证集，但要注意 sklearn 在 `n_estimators` 太少时会警告 OOB 不可靠。
3. 剪枝走 `cost_complexity_pruning_path`。本机在乳腺癌数据上实测最优区间是 9~13 个节点（测试准确率 0.9181），比手猜 `max_depth` 可靠。
4. 大样本一律优先 `HistGradientBoostingClassifier`。本机实测 50000×40 数据上比 `GradientBoostingClassifier` 快约 64 倍（0.76s vs 49.08s）且准确率更高，还免去填充缺失值这一步。
5. `learning_rate` 与 `n_estimators` 必须网格搜索。本机实测 `lr=0.3 / 300 棵` 是 CV 最优配置（0.9918），而 `lr=0.5 / 20 棵` 的测试准确率（0.9298）明显弱于 `lr=0.1 / 100 棵`（0.9357）。
6. 特征重要性用置换重要性而非只用 MDI。本机实测两种排序的前 5 名只重合 4 个，MDI 偏向连续或高基数特征。
7. 上线前把完整擂台表跑出来，包含训练耗时与 CV 均值。本机实测 569 条样本上逻辑回归以 0.05 秒拿到最高 AUC，盲目上集成会浪费 64 倍算力换来更差的结果。

### 踩坑记录

```text
坑 1：ExtraTrees 配 oob_score=True 直接抛异常
结论：以为 ExtraTrees 不支持袋外估计，放弃这个参数。
原因：本机实测 ExtraTreesClassifier 默认 bootstrap=False（用全部样本训练，
      只在切分点随机化），而 OOB 估计要求 bootstrap=True，两者矛盾时直接抛
      ValueError: Out of bag estimation only available if bootstrap=True。
解法：需要 OOB 就显式写 ExtraTreesClassifier(bootstrap=True, oob_score=True)；
      或者直接换 RandomForestClassifier（其 bootstrap 默认为 True）。
```

```text
坑 2：LightGBM 同时设了 num_leaves 和 max_depth，调参白做
结论：调参脚本显示「num_leaves 完全不敏感」，怀疑库有 bug。
原因：本机实测 max_depth=3 时 num_leaves 从 8 调到 512，测试准确率恒为 0.9415
      （2^3 = 8，多余的叶子被深度上限截断）。
解法：二者只保留一个作为容量旋钮——LightGBM 的常见做法是只调 num_leaves
      （官方推荐 num_leaves <= 2^max_depth）；同时设置时先跑单变量扫描确认谁在生效。
```

```text
坑 3：把 XGBoost 的 get_params() 返回值当成库默认值
结论：以为 XGBoost 的关键参数默认值很小，怎么调都对不上预期。
原因：本机实测 XGBoost 3.4.1 的 get_params() 对未显式设置的参数一律返回 None
      （懒加载的参数代理），真实默认值在底层 Booster 配置里：
      eta/learning_rate=0.3、max_depth=6、max_bin=256、reg_lambda=1、subsample=1。
解法：用 get_booster().save_config() 读真实配置，或直接看官方文档；
      生产脚本里把关键参数全部显式写出，不要依赖库默认。
```

```text
坑 4：GBDT 在 569 条样本上被逻辑回归打败，却继续加树加深度
结论：认定「数据太脏，GBDT 学不出来」，继续在树的参数上打转。
原因：本机实测同一份数据上逻辑回归测试 AUC 0.9956、随机森林 0.9781、
      调参后的原版 GB 0.9889、HistGB 早停 0.9810。569 条样本不足以支撑
      集成模型的容量，树模型在这种规模上过拟合比提升更明显。
解法：样本量小时先跑线性基线，把它当作「必须超越的门槛」；
      集成模型的优势要在万级以上样本才能稳定兑现（本机 50000 行的合成数据上
      XGBoost / LightGBM 达到 0.91 以上）。
```

```text
坑 5：Stacking 训练慢 64 倍、AUC 反而更低
结论：以为集成一定比单模型好，直接上线 Stacking。
原因：本机实测 Stacking(3 个基学习器 + LR 元学习器, cv=5) 训练 3.22 秒、
      测试 AUC 0.9930，而单跑逻辑回归只要 0.05 秒、测试 AUC 0.9956。
      基学习器水平不相当（RF 0.9781 明显弱于 LR 0.9956）时元学习器
      无法从弱模型里获益，反而引入额外噪声。
解法：集成前先确认基学习器水平相当且误差模式互补；把单模型指标作为硬门槛，
      集成若不能稳定超过它就放弃；同时把推理侧的多模型编排成本算进评估。
```

```text
坑 6：只用 MDI 特征重要性向业务解释，讲错了重点特征
结论：告诉业务「perimeter 最重要」，而实际贡献最大的是 radius。
原因：本机实测 MDI 排序第一是 worst perimeter（0.1509）、置换重要性排序第一是
      worst radius（0.0205），两者前 5 名只重合 4 个。MDI 基于训练集的不纯度下降，
      偏向取值多或连续的特征，且在过拟合的树上会被高估。
解法：解释用 permutation_importance（建议在测试集上做，n_repeats >= 10）；
      两者都算一遍，排序差异大的特征单独核查。
```

```text
坑 7：HistGB 早停省了时间，也悄悄拉低了效果
结论：以为早停只影响训练时间，测完 AUC 才发现指标降了。
原因：本机实测 HistGB 早停下 85 轮就停止（上限 2000），测试 AUC 0.9747；
      同类配置的擂台版本测试 AUC 0.9810，都低于原版 GB 调参后的 0.9889。
      早停用验证集损失做停止判据，数据小的时候判据噪声大，容易停在次优点。
解法：把 validation_fraction 调大（本机用到 0.15）或增大 n_iter_no_change；
      同时监控 n_iter_ 与验证损失曲线，确认停止点是平台而不是抖动；
      最终指标必须回到独立测试集上确认。
```

## 概述

聚类与降维是**无监督学习**的两大主力：聚类回答「这批样本自然分成几组」（K-Means、层次聚类、DBSCAN、高斯混合模型），降维回答「能不能用更少的维度保留主要信息」（PCA、TruncatedSVD、t-SNE、Isomap、LLE）。聚类产出的是分群标签，通常直接对接业务动作（用户分层、日志归并、异常检测）；降维产出的是低维表示，常用来压缩特征、去噪、可视化，或作为下游模型的输入。

无监督的最大风险不是算法选错，而是**没有真值却以为结论正确**：簇数、距离阈值、perplexity 这些超参数全部靠内部指标和业务可解释性交叉验证，一旦只凭一个指标拍板，很容易得到「数学上漂亮、业务上无用」的分群。因此本篇的实战部分刻意用 `silhouette` 与真实标签两侧对照，说明内部指标什么时候可信、什么时候会骗人。

```text
本篇主线：
1. 划分式聚类 —— KMeans / MiniBatchKMeans：k 如何选、n_init 与 init 的真实影响
2. 层次聚类 —— AgglomerativeClustering 四种 linkage 的适用形状与 distance_threshold 剪枝
3. 密度聚类 —— DBSCAN 的 eps/min_samples 敏感度、k-距离图定 eps、HDBSCAN 免调参
4. 概率模型 —— GaussianMixture 的 BIC/AIC 选成分数、协方差类型、软分配概率
5. 聚类评估 —— 内部指标（silhouette/CH/DB）与外部指标（ARI/NMI）的分工
6. 线性降维 —— PCA 的方差解释率/重建误差/增量训练，稀疏数据改用 TruncatedSVD
7. 非线性降维 —— t-SNE 只做可视化、Isomap/LLE 的邻域假设、trustworthiness 定量比较
```

## K-Means 与改进

K-Means 把样本划分到 k 个质心，最小化簇内平方和（inertia），用 Lloyd 迭代在「分配—更新」之间交替。它的假设是**簇近似球状、大小相近、用欧氏距离**，所以在长条形、密度差异大的数据上会系统性出错。改进方向主要有四条：更好的初始化（`k-means++`）、多次重启取最优（`n_init`）、小批量近似（`MiniBatchKMeans`）、以及替换目标函数（GMM、DBSCAN）。

k 的选法没有免费午餐：inertia 单调下降不能用绝对值判最优，只能看拐点；轮廓系数（-1 到 1，越大越好）是更可用的选择依据。

```python
import numpy as np
from sklearn.cluster import KMeans, MiniBatchKMeans
from sklearn.datasets import make_blobs
from sklearn.metrics import (silhouette_score, calinski_harabasz_score,
                             davies_bouldin_score, adjusted_rand_score)

X, y_true = make_blobs(n_samples=600, centers=4, cluster_std=1.15, random_state=42)
for k in range(2, 9):
    km = KMeans(n_clusters=k, n_init="auto", random_state=0).fit(X)
    print(k, round(km.inertia_, 2), round(silhouette_score(X, km.labels_), 4),
          round(calinski_harabasz_score(X, km.labels_), 1),
          round(davies_bouldin_score(X, km.labels_), 4),
          round(adjusted_rand_score(y_true, km.labels_), 4))
```

本机真实输出（4 个真实中心）：

```text
 4    1528.73      0.7564    4998.5  0.3442  0.9955
 5    1387.56      0.6277    4138.5  0.6827  0.9107
```

轮廓系数、CH 在 k=4 同时取到峰值，与真实标签完全一致（ARI 0.9955）；inertia 则一路下降，从 18980 降到 990，完全没有「4 是拐点」的机器人式暗示。

`n_init='auto'` 的含义在本机版本里值得写清楚：它是「`init='k-means++'` 跑 1 次、`init='random'` 跑 10 次」。实测用 `k-means++` 时 `n_init=1` 与 `n_init='auto'` 结果**逐位相同**，而随机初始化只跑一次会明显劣化：

```python
for init, n_init in [("random", 1), ("k-means++", 1), ("k-means++", "auto")]:
    res = [KMeans(n_clusters=10, init=init, n_init=n_init, random_state=s).fit(Xd).inertia_
           for s in range(5)]      # Xd = load_digits().data
    print(init, n_init, [round(v, 1) for v in res])
```

换成 30 维、12 簇、簇间重叠更大的数据（`make_blobs(n_samples=1500, centers=12, n_features=30, cluster_std=3.0)`），10 次运行的 inertia 极差把差距放得更大：

```text

```

`MiniBatchKMeans` 用随机小批量更新质心，样本量上百万时才划算。本机小数据（600 样本）上它反而更慢——固定开销摊不开：

```text
KMeans(n_init='auto') 耗时 1.4 ms inertia 1528.73
MiniBatchKMeans(batch_size=64) 耗时 3.2 ms inertia 1531.97 | 与 KMeans 标签 ARI=1.0000
```

```text
要点：
1. k 的选择看 silhouette / CH 的极值点，不要看 inertia 的绝对大小（它单调下降，永远没有最小）
2. n_init='auto' 在 sklearn 1.9 中等于「k-means++ 跑 1 次 / random 跑 10 次」，显式写 init='k-means++' 才稳
3. 显式设置 random_state，否则同一份数据两次运行的分群结果不可复现，业务方无法核对
4. 距离敏感的算法上必须先缩放（StandardScaler），否则量纲大的特征会主导欧氏距离
5. MiniBatchKMeans 适合大数据，小数据上比 KMeans 更慢，且惯性略高
6. k 变大时簇数会超过真实结构（本机 k=5..8 的 ARI 从 0.91 掉到 0.61），内部指标只作参考，最终要业务点头
```

## 层次聚类

层次聚类不需要预先指定 k 的语义，而是先构造一棵合并树（dendrogram），再在某个高度剪枝。`AgglomerativeClustering` 的 `linkage` 决定簇间距离的定义：`ward` 最小化簇内方差（默认，适合球状簇）、`complete` 取最远点距离（适合紧凑簇）、`average` 取平均距离、`single` 取最近点距离（能连出长条/月牙形，但对噪声极敏感）。

两种用法：给定 `n_clusters` 直接切出固定簇数；或给 `distance_threshold` 让算法自己决定簇数（此时必须 `n_clusters=None`），并可用 `compute_distances=True` 拿到合并高度自己画树。

```python
from sklearn.cluster import AgglomerativeClustering
from sklearn.datasets import make_blobs, make_moons
from sklearn.metrics import adjusted_rand_score
import numpy as np

X, y = make_blobs(n_samples=600, centers=4, cluster_std=1.15, random_state=42)
Xm, ym = make_moons(n_samples=600, noise=0.07, random_state=0)
for link in ("ward", "complete", "average", "single"):
    a1 = AgglomerativeClustering(n_clusters=4, linkage=link).fit_predict(X)
    a2 = AgglomerativeClustering(n_clusters=2, linkage=link).fit_predict(Xm)
    print(link, round(adjusted_rand_score(y, a1), 4), round(adjusted_rand_score(ym, a2), 4))

ac = AgglomerativeClustering(n_clusters=None, distance_threshold=3.0, linkage="ward").fit(X)
print(ac.n_clusters_, np.bincount(ac.labels_).tolist())
ac2 = AgglomerativeClustering(n_clusters=None, distance_threshold=0,
                              compute_distances=True, linkage="ward").fit(X[:60])
print(ac2.children_[:3].tolist(), np.round(ac2.distances_[:5], 3).tolist())
```

本机真实输出：

```text
 linkage  blobs-ARI  moons-ARI
    ward     0.9955     0.5568
complete     0.9955     0.4259
 average     0.9955     0.5568
  single     0.9955     1.0000
distance_threshold=3.0 -> 50 簇, 各簇大小: [16, 22, 6, 12, 15, 9, 12, 10, 10, 17, 16, 22, 23, 17, 12, 12, 20, 6, 23, 8, 17, 15, 11, 11, 10, 13, 21, 6, 14, 21, 16, 13, 16, 14, 5, 6, 2, 20, 7, 2, 6, 7, 2, 6, 1, 5, 3, 13, 16, 13]
compute_distances=True 的 children 前 3 行: [[17, 47], [15, 53], [22, 59]]
merge 高度前 5 个: [0.126, 0.189, 0.274, 0.366, 0.387]
```

球状数据上四种 linkage 打成平手（ARI 都是 0.9955），但在两个交错的月牙上差异是决定性的：`single` 得到 1.0，`ward`/`average` 只有 0.55 左右。`distance_threshold=3.0` 在标准化之前的原始尺度上切出了 50 个碎簇——阈值必须结合数据尺度、通常按分位数（如最长合并高度的 70%）来定，不是拍脑袋给个 3。

```text
要点：
1. ward 适合球状、大小相近的簇；非凸形状优先试 single / average
2. single linkage 对噪声点极其敏感（两个簇会被一条噪声链连起来），只适合「离群点少 + 形状任意」的场景
3. 用 distance_threshold 时必须同时设 n_clusters=None，否则报参数冲突
4. 阈值要按合并高度分布的分位数取（compute_distances=True 拿 distances_ 后看分位），别用固定常数
5. 复杂度是 O(n^2) 量级，样本超过几万就要换 MiniBatchKMeans 或先降维压缩
6. 层次聚类的好处是能给出整棵合并树，业务可以自上而下自选粒度，这在商品分级/组织分群场景很好用
```

## 密度聚类 DBSCAN 与 HDBSCAN

DBSCAN 把「邻域半径 `eps` 内样本数 ≥ `min_samples`」的点当核心点，核心点之间连通成簇，其余点标为噪声（标签 -1）。这带来两个 K-Means 没有的能力：**不用指定簇数、能识别任意形状、能显式输出噪声点**。代价是 `eps` 极难调——同一个数据上 eps 从 0.2 变到 0.3，两个簇就被合并成一个。

选 `eps` 的工程做法是 k-距离图：取 `min_samples` 个近邻中第 k 个的距离排序后看拐点。

```python
import numpy as np
from sklearn.cluster import DBSCAN, HDBSCAN
from sklearn.datasets import make_moons
from sklearn.metrics import adjusted_rand_score, silhouette_score
from sklearn.neighbors import NearestNeighbors

Xm, ym = make_moons(n_samples=600, noise=0.07, random_state=0)
dist, _ = NearestNeighbors(n_neighbors=5).fit(Xm).kneighbors(Xm)
print(np.round(np.percentile(np.sort(dist[:, -1]), [50, 90, 95, 99]), 3).tolist())
for eps in (0.15, 0.2, 0.3, 0.5):
    db = DBSCAN(eps=eps, min_samples=5).fit(Xm)
    mask = db.labels_ != -1
    print(eps, sorted(set(db.labels_)), int((~mask).sum()),
          round(adjusted_rand_score(ym[mask], db.labels_[mask]), 4),
          round(silhouette_score(Xm[mask], db.labels_[mask]), 4))
```

本机真实输出：

```text
第 5 近邻距离分位数 50/90/95/99%: [0.057, 0.091, 0.107, 0.128]
   eps min_samples   簇数    噪声点    ARI(去噪后)     轮廓(去噪后)
  0.15           5    2      0      1.0000      0.3295
  0.15          10    2      0      1.0000      0.3295
   0.2           5    2      0      1.0000      0.3295
   0.2          10    2      0      1.0000      0.3295
   0.3           5    1      0         nan         nan
   0.3          10    1      0         nan         nan
   0.5           5    1      0         nan         nan
HDBSCAN(min_cluster_size=15): 簇数 2 | 噪声点 0 | ARI(去噪后) 1.0
HDBSCAN 噪声点占比: 0.0
```

注意 eps=0.3 时簇数掉到 1，ARI/轮廓变成 `nan`——脚本里对 `n_clusters>1` 的判断保住了不报错，但真实业务脚本如果不判这一条，`silhouette_score` 会直接抛 `ValueError`。另外这份合成数据太干净（噪声 0.07），噪声点数为 0，想验证噪声逻辑要人为塞离群点。

HDBSCAN（sklearn 1.3 起内置，本机 1.9.1 在 `sklearn.cluster` 里）把 `eps` 换成一个更稳的 `min_cluster_size`，并自动在多个密度水平上选择最稳定的簇，省掉了调 eps 的痛苦，代价是多一个需要解释的参数、以及 1.9.1 会提示 `copy` 默认值将在 1.10 变更（显式传 `copy=False` 可消除 FutureWarning）。

```text
要点：
1. DBSCAN 是唯一「簇数不预设」的主流划分算法；HDBSCAN 是它在参数稳定性上的升级版，新项目优先用 HDBSCAN
2. eps 用 k-距离图（第 min_samples 近邻距离排序）的拐点定，本机该数据拐点在 0.09~0.11 附近
3. eps 过大会合并簇（0.2 -> 0.3 时 2 簇变 1 簇），过小会把簇打碎成噪声
4. 噪声点的存在意味着下游要么丢弃、要么单独建「异常」类，不能当普通标签用
5. 计算轮廓系数前必须剔除 -1 标签，否则噪声自成一类会污染指标
6. 密度差异巨大的数据（有的簇很密、有的很疏）DBSCAN 单组 eps 无解，直接上 HDBSCAN
```

## 高斯混合模型

GMM 假设数据由若干个高斯分布混合生成，用 EM 算法估参数，输出的是**每个样本属于每个簇的概率**（软分配），而不是硬标签。这带来两个实用好处：可以用 BIC/AIC 客观地比较成分数（BIC 越低越好），也能把「属于各簇的概率」作为特征喂给下游模型——比如用户对多个品类的偏好强度。

```python
from sklearn.datasets import make_blobs
from sklearn.mixture import GaussianMixture, BayesianGaussianMixture
from sklearn.metrics import adjusted_rand_score
import numpy as np

X, y = make_blobs(n_samples=600, centers=4, cluster_std=1.15, random_state=42)
for n in range(1, 7):
    gm = GaussianMixture(n_components=n, covariance_type="full",
                         n_init=5, random_state=0).fit(X)
    print(n, round(gm.bic(X), 1), round(gm.aic(X), 1),
          round(adjusted_rand_score(y, gm.predict(X)), 4))
bgm = BayesianGaussianMixture(n_components=10, n_init=3, random_state=0).fit(X)
print(int((bgm.weights_ > 0.01).sum()), np.round(bgm.weights_, 3))
```

```text
1. GMM 输出软分配（predict_proba），需要硬标签时用 predict，二者结论可能不同，业务侧要明确用哪个

3. covariance_type 要配合数据形状：full 最灵活最贵，tied 假设所有簇共用一个形状，样本少时能防过拟合
4. reg_covar 默认 1e-6，数据维度高或特征共线时必须调大，否则协方差矩阵奇异报错
5. BayesianGaussianMixture 可以在 n_components 给大值的前提下自己收敛到有效簇数，适合「几类未知」的探索
6. n_init 至少要 3~5：EM 会陷入局部最优，单次运行的 ARI 波动可达 0.1 以上
```

## 聚类效果评估

聚类评估分两路：**内部指标**只看簇内紧致与簇间分离（silhouette、Calinski-Harabasz、Davies-Bouldin），不需要标签；**外部指标**在有真值或人工标注子集时使用（ARI、NMI、同质性/完整性）。工程上的标准打法是：内部指标选超参，外部指标（在能拿到的一小份标注上）做验收，两者不一致时信外部。

轮廓系数的另一层价值是**逐样本诊断**：`silhouette_samples` 可以为负，负值样本意味着它离隔壁簇比离自己簇更近，通常是标注噪声或边界样本，值得单独捞出来看。

```python
from sklearn.cluster import KMeans
from sklearn.datasets import load_digits
from sklearn.decomposition import PCA
from sklearn.metrics import silhouette_samples, silhouette_score, adjusted_rand_score

d = load_digits()
X, y = d.data.astype(float), d.target
km = KMeans(n_clusters=10, n_init="auto", random_state=0).fit(X)
print(round(silhouette_score(X, km.labels_), 4),
      round(float(silhouette_samples(X, km.labels_).min()), 4),
      round(float(silhouette_samples(X, km.labels_).max()), 4), km.inertia_)
z = PCA(n_components=20, random_state=0).fit_transform(X)
km2 = KMeans(n_clusters=10, n_init="auto", random_state=0).fit(z)
print(round(silhouette_score(z, km2.labels_), 4), round(adjusted_rand_score(y, km2.labels_), 4))
```

本机真实输出：

```text
原始 64 维 KMeans(10) 轮廓: 0.1856
silhouette_samples 最小/最大: -0.0729 0.4868
PCA 降到 20 维后 KMeans(10) 轮廓: 0.2057 | ARI vs 真标签: 0.7395
```

在 digits 上，先 PCA 降到 20 维再聚类，轮廓从 0.1856 升到 0.2057，ARI 达到 0.7395——降维去掉的噪声维度反而让簇更清晰，这是「降维 + 聚类」组合拳最常见的收益来源。指标对照速查：

| 指标 | 方向 | 是否需要真值 | 适用与陷阱 |
| --- | --- | --- | --- |
| silhouette | 越大越好（-1~1） | 否 | 凸簇最敏感；对密度差异大的簇会低估；大样本 O(n^2) 慢 |
| Calinski-Harabasz | 越大越好 | 否 | 与簇数正相关，k 大时天然偏高，只做相对比较 |
| Davies-Bouldin | 越小越好 | 否 | 计算快，簇数越多通常越低，同样只能相对比较 |
| ARI | 越大越好（0 随机，1 完美） | 是 | 对簇数、标签排列不敏感，最常用的外部指标 |
| NMI | 越大越好 | 是 | 对簇数有偏（簇多时偏高），比较不同 k 时要留意 |
| 轮廓为正样本占比 | 越大越好 | 否 | 比均值更能反映「有多少样本被放错了簇」 |

```text
要点：
1. 内部指标只能比较同一数据集上不同参数的结果，不能跨数据集比较绝对值
2. CH 与 DB 都被簇数影响，用来选 k 时最好和 silhouette 一起看，三者都指向同一个 k 才可信
3. silhouette_samples 的负值样本是最有价值的诊断输出，通常是噪声或边界样本
4. 有标注子集时用 ARI 验收（本机 digits 上 KMeans 的 ARI 约 0.74），无标注时用内部指标 + 业务人工抽查
5. 大样本上用 silhouette 的 sample_size 参数降采样估计，别直接跑全量
6. k 变大总能让某些内部指标变好，务必加业务解释性门槛（每簇人数、画像差异）
```

## 主成分分析

PCA 对中心化后的数据做 SVD，得到一组正交的线性组合，按方差从大到小排列。它是最常用、最便宜的降维：既能把 64 维压成 20 维当特征用，也能做去噪（丢掉低方差方向）和可视化（取前两三个主成分）。两个关键判断量是**累计方差解释率**（保留多少信息）与**重建误差**（丢掉多少细节）。

对稀疏矩阵（TF-IDF、one-hot）不能直接跑 PCA——PCA 需要中心化，一中心化稀疏矩阵就变稠密、内存炸掉。这时用 `TruncatedSVD`（不中心化，等价于对稀疏数据做 LSA）。

```python
from sklearn.datasets import load_digits
from sklearn.decomposition import PCA, IncrementalPCA, TruncatedSVD
from sklearn.feature_extraction.text import CountVectorizer
import numpy as np

X = load_digits().data.astype(float)
pca = PCA(n_components=0.95, svd_solver="full", random_state=0).fit(X)
print("保留 95% 方差需要的成分数:", pca.n_components_)
full = PCA(svd_solver="full", random_state=0).fit(X)
cum = np.cumsum(full.explained_variance_ratio_)
print("前 10 成分解释率:", np.round(full.explained_variance_ratio_[:10], 4))
print("累计:", {k: round(cum[k - 1], 4) for k in (2, 5, 10, 20, 30, 40, 50)})
for k in (5, 10, 20, 40):
    p = PCA(n_components=k, random_state=0)
    Z = p.fit_transform(X)
    print(k, round(float(np.mean((X - p.inverse_transform(Z)) ** 2)), 3), round(X.shape[1] / k, 1))
```

```text

1. n_components=0.95 让 PCA 按累计方差自动定维，工程上比手工试 k 稳
2. 重建 MSE 是解释「降维损失了什么」的最直观指标（本机 k=20 时 MSE 1.984，k=40 降到 0.221）
3. 稀疏矩阵必须用 TruncatedSVD，PCA 会因为中心化把稀疏矩阵变稠密而内存爆炸
4. 降维前必须缩放（StandardScaler），否则量纲大的特征独吞方差——PCA 对尺度极其敏感
5. IncrementalPCA 适合大数据，但与全量 PCA 结果不完全一致，替换后要重新验证下游模型指标
6. 主成分没有业务含义，做解释性分析时优先看因子载荷（components_）里权重高的原始特征
```

## 流形学习

流形学习假设高维数据实际躺在一个低维弯曲曲面上，目标是把它「摊平」。t-SNE 通过保留邻域概率分布把高维近邻映射到二维，是最强的**可视化**工具，但代价是：只保证局部结构、不保留全局距离、对新样本的 `transform` 只是近似解、perplexity 与初始化会改变图形状。Isomap/LLE 基于图上的测地距离或局部线性重构，速度更快但假设流形局部平坦。

评价手段是 `trustworthiness`：低维空间里保留的原始近邻比例，越接近 1 越好。

```python
import numpy as np, time
from sklearn.datasets import load_digits
from sklearn.decomposition import PCA
from sklearn.manifold import TSNE, Isomap, LocallyLinearEmbedding, trustworthiness

X = load_digits().data.astype(float)
idx = np.random.default_rng(0).choice(len(X), 800, replace=False)
Xs = X[idx]
for name, est in [("PCA", PCA(n_components=2, random_state=0)),
                  ("TSNE-30", TSNE(n_components=2, perplexity=30, init="pca", random_state=0)),
                  ("TSNE-5", TSNE(n_components=2, perplexity=5, init="pca", random_state=0)),
                  ("Isomap-10", Isomap(n_neighbors=10, n_components=2)),
                  ("LLE-10", LocallyLinearEmbedding(n_neighbors=10, n_components=2))]:
    t0 = time.perf_counter()
    emb = est.fit_transform(Xs)
    print(name, round(trustworthiness(Xs, emb, n_neighbors=5), 4),
          round((time.perf_counter() - t0) * 1000, 1))
```

```text
1. t-SNE 只用于可视化，它的输出坐标不能当特征喂给模型（不含全局几何信息，且依赖优化过程）

3. 生产环境固定 init='pca' 与 random_state，否则每次出图不同、无法向业务解释
4. Isomap/LLE 支持对新样本 transform，但质量明显低于训练样本，映射新数据要单独验证
5. 用 trustworthiness 定量比较（本机 t-SNE 0.9944 / LLE 0.9031 / PCA 0.8235），不要只看图「看起来分得开」
6. 数据量上万后 t-SNE 会很慢，先 PCA 降到 30~50 维再跑，几乎无损且快一个量级
```

## 应用场景实战

### 场景一：电商用户 RFM 分群与分层运营名单

真实场景：运营要一份可以直接投放的用户分层名单。数据是每个用户的三列 RFM（最近购买间隔、购买频次、客单价），量纲和分布差别很大（右偏），必须缩放到同一尺度再聚类，最后必须回到原始量纲解释每一簇，并按业务规则命名。

```python
import numpy as np

rng = np.random.default_rng(2026)

                   "recency_days": R.round(1), "frequency": F.round(0), "monetary": M.round(1)})

X_scaled = StandardScaler().fit_transform(X)

for k in range(2, 9):
    km = KMeans(n_clusters=k, n_init="auto", random_state=0).fit(X_scaled)
    print(k, round(km.inertia_, 1), round(silhouette_score(X_scaled, km.labels_), 4),
```

### 场景二：线上日志文本聚类与故障模板归并

真实场景：每天的告警日志量太大，运维想先自动归并成若干「故障模板」再人工确认。文本先 `TfidfVectorizer` 向量化，稀疏矩阵用 `TruncatedSVD` 降维，再用 `MiniBatchKMeans` 聚类，最后用 t-SNE 出图给人看，并且每簇输出高频关键词供人工命名。

```python
import numpy as np

from sklearn.cluster import MiniBatchKMeans
from sklearn.manifold import TSNE
from sklearn.metrics import silhouette_score

templates = [
    "connection timeout to redis host {} after {} ms",
    "postgres deadlock detected on table orders transaction {}",
    "http 502 bad gateway from upstream {} retry {}",
    "disk usage {} percent on volume /data partition {}",
    "jwt token expired for user {} request {}",
    "circuit breaker open for downstream {} threshold {}",
]
rng = np.random.default_rng(2026)
docs = [templates[rng.integers(0, len(templates))].format(rng.integers(1000, 9999),
                                                          rng.integers(1, 500)) for _ in range(1200)]

X_txt = vec.fit_transform(docs)

X_svd = svd.fit_transform(X_txt)

for k in (4, 5, 6, 7, 8):

lab = MiniBatchKMeans(n_clusters=6, n_init="auto", random_state=0, batch_size=256).fit_predict(X_svd)
terms = np.array(vec.get_feature_names_out())
for c in range(6):
    mean_tfidf = np.asarray(X_txt[lab == c].mean(axis=0)).ravel()
    print(c, int((lab == c).sum()), ", ".join(terms[np.argsort(mean_tfidf)[::-1][:6]]))
```

## 最佳实践与踩坑记录

### 最佳实践

1. 聚类前一律先看分布与量纲：右偏特征先做 `log1p` 或 `PowerTransformer`，再用 `StandardScaler`；距离型算法（K-Means/DBSCAN/层次聚类）不做缩放的结果基本不可用。
2. k 的选择同时看 silhouette、CH 与业务人数分布，三者一致才拍板；把「每簇最小样本占比」写成硬约束（例如不低于 3%），能过滤掉纯数学最优的碎簇。
3. 簇编号是随机的：所有对外产物（分层名单、报表、看板）都用规则推导出的语义标签，绝不把 `cluster=2` 直接写进业务代码。
4. 降维与聚类组合时先降维再聚类：本机 digits 上 PCA 到 20 维让轮廓从 0.1856 升到 0.2057，ARI 达到 0.7395，同时省掉大量计算。
5. 稀疏特征（TF-IDF、one-hot）只走 `TruncatedSVD`，绝不用 PCA；稀疏数据上的中心化会把矩阵变稠密。
6. 可视化与建模用不同的降维工具：出图用 t-SNE/UMAP 但只信局部邻域，送模型的特征用 PCA/SVD 这类有明确 `transform` 语义的线性方法。
7. 每次运行都固定 `random_state`，并把 `k`、`eps`、`perplexity`、`n_init`、库版本一起写进产出物元数据，方便复盘。

### 踩坑记录

```text
坑 1：K-Means 对原始未缩放的 RFM 数据分群，结果全被「客单价」一个维度主导
结论：分出来的簇在频次和最近购买时间上几乎无差异，业务说「这分层没用」。
原因：K-Means 用欧氏距离，monetary 取值范围 10~339，frequency 只有 1~99，量纲大的特征
      在距离里的贡献压倒性，其余特征等于噪声。
解法：聚类前统一 StandardScaler（本机把三列缩到同一尺度后，簇画像 recency
      32.0/32.7/238.9/25.0 才呈现出可解释的四段分布）；右偏严重的列先 log1p 或 PowerTransformer。

坑 2：把 cluster 编号硬编码成业务标签，上线后第二天分群全乱
结论：同一份数据第二天跑出的簇编号含义变了，投放名单错发。
原因：K-Means 的簇编号由初始化决定，本身没有顺序语义；重新训练、换 random_state、
      数据量变化都会让编号重排（本机第一版脚本硬编码 names={0:'高价值活跃',...}，结果把
      recency=5.2 的活跃用户标成了「流失风险」）。
解法：命名从簇画像按规则推导（按 recency / monetary / frequency 阈值判定），
      或把「簇编号 -> 语义」的映射固化进模型产物随模型一起发布。

坑 3：对 DBSCAN 输出直接算 silhouette_score，代码抛 ValueError
结论：怀疑版本不兼容，反复升级 sklearn。
原因：DBSCAN 会把噪声样本标为 -1，这些样本不构成簇，metrics 检测到标签集合与样本数不匹配
      就拒绝计算；本机实测 eps >= 0.3 时只输出 1 个簇，同样会让 silhouette 无意义（得到 nan）。
解法：先 mask = labels != -1 过滤噪声，并判断簇数 > 1 再算指标（本机脚本里这两个判断
      缺任何一个都会崩）。

坑 4：把 t-SNE 的输出坐标当特征训练下游分类器，离线指标很好、线上毫无效果
结论：用 t-SNE 二维坐标做特征，离线 CV 准确率虚高。
原因：t-SNE 按邻域概率重建二维坐标，坐标值本身没有量纲意义，且依赖优化过程与随机初始化，
      对新样本调用 transform 得到的只是近似解；换 random_state 后整张图会平移/旋转，
      两次运行的坐标不可比。
解法：可视化用 t-SNE（仅供人看），送模型的特征用 PCA/TruncatedSVD；
      若确实要非线性嵌入做特征，用 UMAP/自编码器等有稳定 transform 的方法并做在线一致性验证。

坑 5：层次聚类用 ward linkage 聚两个交错的月牙，结果两簇各被劈成两半
结论：以为层次聚类不适合非凸数据，想直接放弃。
原因：ward 的目标是最小化簇内方差，隐含「簇近似球状」假设；本机实测月牙数据上 ward 的
      ARI 只有 0.5568，而 single linkage 达到 1.0000。
解法：形状未知时先画图（PCA 二维散点）判断凸性，非凸用 single/average 或直接换
      DBSCAN/HDBSCAN；不要无条件使用默认 ward。

坑 6：对 sparse 的 TF-IDF 矩阵直接跑 PCA，进程被 OOM 杀掉
结论：以为是内存不够，先加机器。
原因：PCA 内部要做中心化，稀疏矩阵减均值后会变成稠密矩阵；本机场景 (1200, 633) 非零占比
      仅 2%，稠密化后内存已放大 50 倍，真实日志场景（百万文档 × 十万词表）必然爆掉。
解法：稀疏数据一律用 TruncatedSVD（不做中心化）；本机 TruncatedSVD(20) 在 1200 条日志上
      累计解释率 0.6586、耗时不到 0.1 秒。
```

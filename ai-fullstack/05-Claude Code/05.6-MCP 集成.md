## 概述

MCP（Model Context Protocol）是连接 AI 工具与外部系统的开放标准，Claude Code 通过它接入数据库、工单系统、监控平台、设计工具等外部能力。判断要不要接一个 MCP 服务器的标准很简单：如果你正在把别的系统里的数据复制粘贴进对话，那就该接；接上之后 Claude 能直接读取并操作那个系统，而不是基于你贴的内容猜。本主题覆盖服务器配置、作用域选择、常用服务与故障排查。

```text
接入 MCP 的四条主线：
1. 传输方式 —— http（远端首选）、sse（已弃用）、stdio（本地进程）、ws
2. 作用域 —— local（默认，仅当前项目且私有）、project（.mcp.json，随仓库分发）、user（全项目）
3. 命名与权限 —— 工具名 mcp__<server>__<tool>，可用 allow / deny 规则与钩子 matcher 精确控制
4. 安全前提 —— 会抓取外部内容的服务器带来提示注入风险，接入前先确认信任
```

> 说明：本文命令与字段取自官方文档（docs.anthropic.com / code.claude.com 的 MCP 与 settings 页面）。本机未安装 `claude` CLI（`which claude` 无输出），命令未在本机执行，具体参数以 `claude mcp --help` 与官方文档为准。

## MCP 在 Claude Code 里解决什么问题

Claude Code 能连接的 MCP 服务器数量没有实际上限，接入后可以完成这些典型任务：按工单系统里的 issue 实现功能并开 PR、查监控与实验平台确认某个功能的使用情况、连数据库查真实数据、按设计稿改模板、自动化发邮件或创建日程。MCP 服务器还可以作为「通道」把外部事件推入会话，让 Claude 在你离开时响应消息或 webhook。

```text
什么时候该接 MCP：
1. 反复复制粘贴外部系统数据 —— 接 MCP，让它直接读
2. 需要模型基于真实数据做决策 —— 接只读账号的数据库 / 监控服务器
3. 需要模型触发外部动作（开单、发消息、部署）—— 接，但必须收紧权限并人工复核
4. 只想让模型看本地文件 —— 通常不需要 MCP，内置 Read/Grep/Glob 够用
```

## 四种传输方式与添加命令

远端 HTTP 是最推荐的传输方式，云服务支持最广；SSE 传输已被官方标记为弃用，只在服务端仅暴露 SSE 端点时使用；stdio 用于跑在本地进程的服务器，适合需要直接系统访问或自建脚本的场景；WebSocket 也是可选项。`claude mcp add` 是统一的添加入口。

```bash
# 1. 远端 HTTP（推荐）：claude mcp add --transport http <name> <url>
claude mcp add --transport http notion https://mcp.notion.com/mcp

# 带鉴权头：--header "Key: Value"
claude mcp add --transport http secure-api https://api.example.com/mcp \
  --header "Authorization: Bearer YOUR_TOKEN"

# 2. 远端 SSE（弃用）：新版会用 http 先试，服务端不接受时自动回退 SSE
claude mcp add --transport sse asana https://mcp.asana.com/sse

# 3. 本地 stdio：选项与命令之间用 -- 分隔，-- 之后的参数原样传给服务器
claude mcp add --transport stdio airtable --env AIRTABLE_API_KEY=YOUR_KEY \
  -- npx -y airtable-mcp-server

# 4. 从 JSON 直接添加
claude mcp add-json weather-api '{"type":"http","url":"https://api.weather.com/mcp","headers":{"Authorization":"Bearer token"}}'
```

stdio 方式的 `--` 分隔符是硬性要求：`claude mcp add --transport stdio myserver -- npx server` 会执行 `npx server`，没有 `--` 时 Claude Code 会试图把服务器自己的 `--port` 之类参数当成自己的选项解析。另外 `--env` 接受多个 `KEY=value` 对，如果服务器名紧跟在 `--env` 后面会被当成又一对键值而报错，所以 `--env` 与服务器名之间至少要放一个其他选项（例如 `--transport stdio`）。

stdio 服务器由 Claude Code 负责启动与终止：会话结束时它先发 `SIGINT`，100 毫秒后仍未退出则发 `SIGTERM`，再 400 毫秒后 `SIGKILL`（Windows 上先关闭 stdin，300 毫秒后终止进程树）。服务器如果在退出时保存状态或清理锁文件，需要在信号处理里在这段时间内完成。Claude Code 还会给 stdio 服务器进程设置 `CLAUDE_PROJECT_DIR` 环境变量指向项目根目录；服务器若想限制自己的文件访问范围，应实现 MCP 的 `roots/list` 请求，Claude Code 会用启动目录加上所有额外工作目录来回答。

```text
传输方式选择：
1. 云服务 / 团队共享 —— 优先 http，鉴权用 header 或 OAuth
2. 服务端只给 SSE —— 用 http 添加并让客户端自动回退，或用 --transport sse 直连
3. 需要本机文件、内部 CLI、私有脚本 —— stdio，用 -- 分隔服务器命令
4. 自建服务 —— 有 HTTP 端点就别做 stdio，远端部署免去每人装运行时
```

## JSON 配置字段与配置文件

除命令行外，也可以直接写 JSON。项目级配置放仓库根目录的 `.mcp.json`，本地与用户级配置存进 `~/.claude.json`。字段含义如下：

| 字段 | 适用类型 | 说明 |
| :- | :- | :- |
| `type` | 全部 | `http`（`streamable-http` 是等价的别名）、`sse`、`stdio`、`ws`。缺省视为 stdio；只写 `url` 不写 `type` 是配置错误，会被跳过 |
| `url` | http / sse / ws | 服务器端点 |
| `headers` | http / sse / ws | 请求头，常用于放令牌 |
| `command` | stdio | 要启动的可执行文件 |
| `args` | stdio | 启动参数数组 |
| `env` | stdio | 传给服务器进程的环境变量 |
| `oauth` | 远端 | 预配置的 OAuth 客户端信息，如 `clientId`、`callbackPort` |

```json
{
  "mcpServers": {
    "github": {
      "type": "http",
      "url": "https://api.githubcopilot.com/mcp/",
      "headers": {
        "Authorization": "Bearer ${GITHUB_PAT}"
      }
    },
    "db": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "@bytebase/dbhub", "--dsn", "postgresql://readonly:${DB_PASSWORD}@db.internal:5432/analytics"],
      "env": {
        "CACHE_DIR": "/tmp/dbhub-cache"
      }
    }
  }
}
```

```text
配置文件约定：
1. .mcp.json 放项目根目录，提交到版本库即可让全组拿到同一批服务器
2. 交互式会话首次使用 .mcp.json 里的服务器会弹一次批准；多人协作用 claude mcp reset-project-choices 重置选择
3. 在 -p、Agent SDK 与云会话里不会弹批准，会直接加载项目级服务器
4. 不想加载就用 disabledMcpjsonServers 拉黑，或用 --strict-mcp-config 只认 --mcp-config 传入的服务器
```

## 配置作用域与优先级

同一个服务器可以定义在三个作用域，作用域决定它在哪些项目加载、是否共享给团队，以及存在哪个文件里。

| 作用域 | 加载范围 | 是否共享 | 存储位置 |
| :- | :- | :- | :- |
| local | 仅当前项目 | 否 | `~/.claude.json` 里该项目路径下 |
| project | 仅当前项目 | 是，随版本库分发 | 项目根目录 `.mcp.json` |
| user | 你的所有项目 | 否 | `~/.claude.json` |

同名服务器定义在多处时，Claude Code 只连一次，取优先级最高的那份定义，并且整个条目整体生效、字段不会跨作用域合并。优先级从高到低是：local、project、user、插件提供的服务器、claude.ai 连接器。企业通过 `managedMcpServers` 托管设置提供的服务器优先级高于全部这些（需要较新版本）。插件与连接器按端点去重（scheme/host 大小写、默认端口、末尾斜杠差异视为同一端点）。

```bash
# 默认就是 local 作用域
claude mcp add --transport http stripe https://mcp.stripe.com

# 显式指定 local
claude mcp add --transport http stripe --scope local https://mcp.stripe.com

# 项目级：写入 .mcp.json，随仓库分发
claude mcp add --transport http shared-server --scope project https://example.com/mcp

# 用户级：本机所有项目可用
claude mcp add --transport http hubspot --scope user https://mcp.hubspot.com/anthropic
```

```text
作用域选择：
1. 带个人凭据的实验服务器 —— local，避免泄漏到版本库
2. 团队都要用的开发/测试服务 —— project，配置入库并走一次批准
3. 个人跨项目工具 —— user
4. 组织统一提供 —— 交给管理员用 managedMcpServers，用户不可覆盖
5. 注意术语差异：MCP 的 local 存在 ~/.claude.json，与设置文件的 .claude/settings.local.json 不是一回事
```

## 环境变量展开与凭据安全

`.mcp.json` 支持两种展开语法：`${VAR}` 取环境变量值，`${VAR:-default}` 在未设置时用默认值。可展开的位置包括 `command`、`args`、`env`、`url` 与 `headers`。引用了不存在且没有默认值的变量时配置仍会加载，Claude Code 在 `claude mcp list` 与 `/mcp` 里给出缺变量警告，并把 `${VAR}` 原文保留。

安全设计上有一条重要限制：在远端服务器的 `url` 与 `headers` 中，Claude Code **把凭据类变量读作空值而不是展开**，防止仓库里的 `.mcp.json` 或插件把你的凭据发给它指定的服务器。被覆盖的名称包括 Claude Code 自身凭据（如 `ANTHROPIC_API_KEY`、`ANTHROPIC_AUTH_TOKEN`）、云厂商凭据（如 `AWS_BEARER_TOKEN_BEDROCK`）以及其他常见凭据（如 `HTTPS_PROXY`、`NPM_TOKEN`），即使设置了变量或写了 `:-default` 也会被忽略。想给远端服务器传这类凭据，需要先复制到自定义命名的变量再引用。

```json
{
  "mcpServers": {
    "api-server": {
      "type": "http",
      "url": "${API_BASE_URL:-https://api.example.com}/mcp",
      "headers": {
        "Authorization": "Bearer ${MY_API_KEY}"
      }
    }
  }
}
```

```shell
# 展开前先导出变量，注意不要直接用被读作空值的保留名
export MY_API_KEY="xxx"
export API_BASE_URL="https://staging.example.com"

# 验证展开结果：界面上只显示 ${VAR} 引用名，不会回显解析后的值
claude mcp list
claude mcp get api-server
```

```text
凭据处理要点：
1. ${VAR} 与 ${VAR:-default} 只在这五个位置生效：command、args、env、url、headers
2. url 与 headers 里的 ANTHROPIC_* / 云厂商凭据变量一律按空值处理，改用自定义变量名中转
3. 界面与 CLI 输出只显示变量引用名，不打印解析后的值，可以放心提交 .mcp.json
4. 需要调试时用 claude --debug-file 并搜索 never expanded toward a remote server
```

## 常用 MCP 服务

下表为官方文档给出的接入示例，可直接替换令牌使用。自建服务器可以用官方插件 `mcp-server-dev` 让 Claude 帮你脚手架生成。

| 服务 | 类型 | 接入命令要点 |
| :- | :- | :- |
| GitHub | 远端 HTTP | `claude mcp add --transport http github https://api.githubcopilot.com/mcp/ --header "Authorization: Bearer YOUR_PAT"`，用细粒度 PAT |
| PostgreSQL / 关系库 | 本地 stdio | 走 DBHub：`claude mcp add --transport stdio db -- npx -y @bytebase/dbhub --dsn "postgresql://readonly:***@host:5432/analytics"`，务必用只读账号 |
| Notion | 远端 HTTP | `claude mcp add --transport http notion https://mcp.notion.com/mcp` |
| Asana | 远端 SSE | `claude mcp add --transport sse asana https://mcp.asana.com/sse` |
| Airtable | 本地 stdio | `claude mcp add --transport stdio airtable --env AIRTABLE_API_KEY=KEY -- npx -y airtable-mcp-server` |
| HubSpot | 远端 HTTP | `claude mcp add --transport http hubspot --scope user https://mcp.hubspot.com/anthropic` |
| Stripe | 远端 HTTP | `claude mcp add --transport http stripe https://mcp.stripe.com` |

在 Claude Code 会话里让 Claude 帮你生成服务器脚手架：

```text
/plugin install mcp-server-dev@claude-plugins-official
/mcp-server-dev:build-mcp-server
```

```text
接入第三方服务的判断标准：
1. 确认供应商与端点是官方的，Anthropic 目录里已审阅的连接器优先
2. 权限最小化：数据库用只读账号，GitHub 用细粒度 PAT 而不是全权限 token
3. 会抓取外部内容的服务器（网页、邮件、工单正文）带来提示注入风险，接入前评估
4. 凭据统一走环境变量引用，不要写进 JSON 明文
```

## 服务器管理与状态查看

管理命令集中在 `claude mcp` 下，会话内用 `/mcp` 查看状态、重新认证与临时禁用。

```bash
# 列出所有已配置的服务器（含连接状态与失败详情）
claude mcp list

# 查看某个服务器的详情，连接失败时会有 Issue: 行
claude mcp get notion

# 删除服务器（远端服务器会同时清理已存的 OAuth 令牌与客户端注册）
claude mcp remove notion

# 重置项目级服务器的批准选择
claude mcp reset-project-choices
```

```text
会话内的 /mcp 能做的事：
1. 查看每个服务器状态：connected / failed / cached / not configured
2. 对需要认证的远端服务器完成或重新完成 OAuth 登录
3. 临时禁用某个服务器，或清除它的认证与发现缓存
```

状态含义值得记牢：`cached` 表示 Claude Code 用上一次会话缓存的工具列表，等 Claude 第一次调用该服务器的工具时才真正连接（发现缓存默认关闭，可用 `MCP_DISCOVERY_CACHE=1` 开启）；`not configured` 表示 `url` 为空，Claude Code 不会尝试连接；`failed` 时 `claude mcp list` 会把失败详情追加到状态行，`claude mcp get` 则在 `Issue:` 行给出 HTTP 状态码或错误文本，但会抹掉凭据类内容且不回显展开后的 URL。

```text
排查时先看这三处：
1. claude mcp list —— 有没有加载、状态是什么、有没有配置警告
2. claude mcp get <name> —— Issue: 行的状态码与服务器错误文本
3. 会话内 /mcp —— 交互式重连、重新认证、查看工具是否可用
```

## 故障排查

MCP 的问题大体分三类：配置写错、连接失败、工具不可用。官方文档列出的配置警告如下。

| 现象 / 警告 | 原因 | 处理方式 |
| :- | :- | :- |
| `Leading or trailing whitespace in: headers.Authorization` | 复制令牌时带了首尾空白（常见于换行） | 编辑配置去掉空白，Claude Code 不会自动 trim |
| 同名服务器在多个作用域指向不同端点 | 不同作用域同名但端点不同 | 用 `claude mcp remove <name> --scope <scope>` 删掉多余定义，只保留想要的端点 |
| 服务器名被跳过并提示改名 | 用了保留名，如 `workspace`、`claude-in-chrome`、`computer-use`、`Claude Preview`、`Claude Browser` | 换成自定义名称，`claude mcp add` 会直接拒绝保留名 |
| 缺环境变量警告 | `${VAR}` 未设置且没有 `:-default` | 设置变量或补默认值；远端 url/headers 里的凭据类变量按空值处理，需换名 |
| `has a "url" but no "type"` | 只写 `url` 没写 `type`，被当成 stdio 解析 | 补 `"type": "http"`（或 `sse` / `ws`） |
| 连接 `failed` 且带 401 / 403 | 远端服务器需要 OAuth，或配置的授权头凭据无效 | 在 `/mcp` 里完成认证；若已登录则 Claude Code 会刷新令牌并重试一次 |
| 服务器显示 `not configured` | 配置里 `url` 为空 | 补上 `url` |
| 工具调用报服务器不可用 | 服务器仍在连接，或首次连接失败 | 检查启动超时（默认 30 秒，见 `MCP_TIMEOUT`），必要时重连 |

```shell
# 连接问题的调试手段
claude --debug-file /tmp/claude-debug.log
# 在日志里搜索 never expanded toward a remote server，确认凭据变量是否被故意置空

# 只用命令行指定的服务器，排除仓库里 .mcp.json 的干扰
claude --strict-mcp-config --mcp-config ./mcp.json

# 检查某个插件自带的服务器是否真的加载了（-p + stream-json 下看 system/init 事件）
claude -p "reply ok" --output-format stream-json --mcp-config ./mcp.json | head -5
```

```text
故障排查顺序：
1. 先确认服务器有没有被加载：claude mcp list，看有没有被跳过的条目与警告
2. 再看连接状态与状态码：claude mcp get <name> 的 Issue: 行，或会话内 /mcp
3. 报错涉及凭据就检查变量名是否落在「读作空值」的保留集合里
4. 需要隔离变量时用 --strict-mcp-config，只加载 --mcp-config 指定的配置
5. 需要看服务器进程自身输出时用 --debug-file，不要靠猜
```

## 应用场景实战

### 场景一：给团队仓库接入「GitHub + 只读数据库」两个服务器

目标：全组克隆仓库后即可让 Claude 读 PR、查 issue、按只读账号查询分析库；仓库里不能出现任何明文凭据。做法是把服务器定义写进 `.mcp.json` 提交，凭据全部走环境变量引用。

```json
{
  "mcpServers": {
    "github": {
      "type": "http",
      "url": "https://api.githubcopilot.com/mcp/",
      "headers": {
        "Authorization": "Bearer ${TEAM_GITHUB_PAT}"
      }
    },
    "analytics-db": {
      "type": "stdio",
      "command": "npx",
      "args": [
        "-y",
        "@bytebase/dbhub",
        "--dsn",
        "postgresql://readonly:${ANALYTICS_DB_PASSWORD}@analytics.internal:5432/warehouse"
      ],
      "env": {
        "CACHE_DIR": "/tmp/dbhub-cache"
      }
    }
  }
}
```

```shell
# 1. 每人本机导出自己的凭据（不写入仓库）
export TEAM_GITHUB_PAT="github_pat_xxx"
export ANALYTICS_DB_PASSWORD="xxx"

# 2. 校验 JSON 语法，避免整个文件被跳过
python3 -c "import json;json.load(open('.mcp.json'));print('mcp.json OK')"

# 3. 启动会话并确认服务器已连接（首次使用项目级服务器会弹一次批准）
claude
# 会话内执行 /mcp，确认 github 与 analytics-db 都是 connected

# 4. 让 Claude 直接干活
#   "查一下 PR #456 的改动并给出评审意见"
#   "分析库 orders 表最近 30 天的退款率是多少"
```

```text
场景要点：
1. .mcp.json 提交进仓库，令牌靠环境变量引用，谁都拿不到别人的凭据
2. 数据库必须用只读账号，即使模型生成写操作也会被数据库拒绝
3. 首次批准是安全设计的一部分，人多时用 claude mcp reset-project-choices 统一重置
4. CI 与无头场景不会弹批准，务必确认 .mcp.json 里的服务器是你想加载的
```

### 场景二：在 CI 里用固定 MCP 配置跑一次自动化

目标：流水线里让 Claude 只使用显式传入的 MCP 配置，屏蔽仓库与个人环境里的其他服务器，并把结果以 JSON 形式交给后续脚本处理。用 `--strict-mcp-config` 与 `--mcp-config` 组合。

```bash
#!/usr/bin/env bash
# ci/review.sh：在 CI 中按固定 MCP 配置运行一次代码审查
set -euo pipefail

# 1. 只提供 CI 需要的那一个服务器配置，内联 JSON 即可
cat > /tmp/ci-mcp.json <<'JSON'
{
  "mcpServers": {
    "github": {
      "type": "http",
      "url": "https://api.githubcopilot.com/mcp/",
      "headers": { "Authorization": "Bearer ${CI_GITHUB_PAT}" }
    }
  }
}
JSON

# 2. 严格模式：忽略所有其他 MCP 配置，只加载上面这一份
claude --strict-mcp-config --mcp-config /tmp/ci-mcp.json \
       -p "审查最新提交，输出发现的问题清单" \
       --output-format json \
       --allowedTools "Read,Grep,mcp__github__get_*" \
       > /tmp/review.json

# 3. 从结构化输出里取结果
python3 - <<'PY'
import json
data = json.load(open("/tmp/review.json"))
print("会话是否报错:", data.get("is_error", False))
print("结果文本片段:", str(data.get("result", ""))[:200])
PY
```

```text
场景要点：
1. --strict-mcp-config 让 CI 只认显式传入的服务器，避免仓库配置被滥用
2. --mcp-config 可以接文件路径也可以接内联 JSON 字符串，CI 里用文件更好审计
3. 用 --output-format json 拿结构化结果，别去正则抠人类可读输出
4. 服务器若加载失败，stream-json 的 system/init 事件里会有 mcp_server_errors 字段可供脚本判定
```

## 最佳实践与踩坑记录

### 最佳实践

1. 团队共享的服务器写进 `.mcp.json` 并提交，个人凭据一律用 `${VAR}` 引用，不落明文
2. 接入任何服务器前确认来源可信，会抓取外部内容的服务器（网页、邮件、工单）存在提示注入风险
3. 数据库类服务器使用只读账号与最小权限令牌，把「模型可能生成写操作」当成常态来防御
4. 用 `claude mcp list` 定期巡检：配置警告、缺变量、连接失败都会在这里露出
5. 名字不要用保留名（`workspace`、`claude-in-chrome`、`computer-use` 等），否则会被静默跳过
6. CI 里用 `--strict-mcp-config` 显式指定服务器，配合 `--mcp-config` 让流水线行为可复现
7. 服务器多了要控制上下文开销，只保留真正在用的服务，必要时在会话里临时禁用

### 踩坑记录

```text
坑 1：连接一直失败，状态是 failed 但没有明显原因
结论：反复重试无效，日志里只有一句连接失败。
原因：令牌是从网页复制来的，带了尾随换行，配置值里存在隐藏首尾空白；Claude Code 不会自动 trim。
解法：用 claude mcp list 看是否有 Leading or trailing whitespace 警告，删掉配置里的空白字符后重连。

坑 2：.mcp.json 里的远端服务器连不上，报 401
结论：同一份配置在别人机器上正常，只有自己不行。
原因：headers 或 url 里引用了 ANTHROPIC_API_KEY、NPM_TOKEN 这类凭据变量，Claude Code 在远端 url / headers 中把它们读作空值，请求带着 Bearer 空令牌发出。
解法：把需要的值复制到自定义命名的变量（如 TEAM_GITHUB_PAT）再引用，用 --debug-file 搜索 never expanded toward a remote server 确认。

坑 3：本地明明配置了服务器，某个项目里却完全不生效
结论：换目录后工具全消失，/mcp 找不到该服务器。
原因：默认添加的是 local 作用域，只对添加时所在的项目生效；或用同名服务器在多个作用域指向了不同端点，优先级高的覆盖了低优先级的。
解法：需要用遍所有项目就加 --scope user，需要团队共享就加 --scope project 并提交 .mcp.json，冲突条目用 claude mcp remove <name> --scope <scope> 清理。

坑 4：CI 里 Claude 连上了仓库里的私有服务器
结论：流水线的密钥被送到未预期的端点，属于安全事故。
原因：-p / SDK / 云会话不会弹项目级服务器的批准提示，会直接加载 .mcp.json 中的服务器。
解法：CI 用 --strict-mcp-config 配 --mcp-config 只加载白名单配置，或用 disabledMcpjsonServers 拉黑特定服务器。

坑 5：以为改了 .mcp.json 就立刻生效
结论：改完配置文件后行为没变，以为改动被忽略。
原因：服务器在会话启动时加载，改文件不会重建已有连接；另外名称落在保留名集合时会被跳过。
解法：改完配置重启会话或重新连接；确认服务器名不在保留名列表内，必要时用 claude mcp list 核对实际加载情况。

坑 6：本地服务器启动后很快被杀掉，状态文件损坏
结论：stdio 服务器偶发写入不完整，留下锁文件。
原因：会话结束或断连时 Claude Code 先发 SIGINT，100 毫秒后 SIGTERM、再 400 毫秒 SIGKILL，服务器没来得及清理就结束。
解法：服务器实现里捕获这些信号并在时限内完成落盘与清理，别把耗时收尾工作放在退出流程里。
```

## 概述

子代理（subagent）和技能（skill）解决的是两个不同的问题：子代理拿一块**独立的上下文窗口**去做脏活（跑测试、翻日志、搜代码库），只把结论带回来，避免主会话被搜索结果的噪音塞满；技能是**按需加载的提示包**，把你反复粘贴的流程（部署、提交、评审）固化成 `/名称`，并且只在被调用或判定相关时才占上下文。两者可以互相配合：子代理可以预加载技能，技能也可以指定在子代理里执行。

```text
本篇的五个抓手：
1. 机制 —— 子代理为什么省上下文、内置的 Explore / Plan / general-purpose 各做什么、Claude 依据什么决定委派
2. 定义 —— Markdown + YAML 前端元数据写子代理，字段表与五级作用域优先级，/agents 与 --agents
3. 技能 —— SKILL.md 的两段结构、七处加载位置、命令名从哪来、谁有权调用、参数替换与预授权工具
4. 并行 —— 前台与后台的判定规则、并发上限 20、派生深度 3、worktree 隔离、/batch 与代理团队
5. 取舍 —— 什么时候用主会话、什么时候用子代理、什么时候用技能、什么时候用后台会话

本机环境说明：Ubuntu 24.04 实验机上未安装 claude CLI，本篇的字段名、路径与默认值均取自官方文档
（code.claude.com/docs/en 的 sub-agents、skills、agents 页面）。版本相关的默认值有变动历史，以官方文档为准。
```

## 子代理机制与内置代理

每个子代理在自己的上下文窗口里运行，有自己的系统提示、工具白名单与权限设置；它发出的请求同样计入你的用量，所以「省上下文」不等于「省 token」——它省的是你主会话的注意力与上下文空间。Claude 根据你请求的措辞、各子代理的 `description` 字段以及当前上下文，判断这个任务该不该交给某个子代理，委派在 transcript 里表现为一行工具调用。

```text
内置子代理（交互式会话默认注册）：
1. Explore —— 只读的快速检索代理，禁止 Write / Edit，专门用来搜代码与理解代码库；Claude 调用时还会指定 thoroughness：quick / medium / very thorough
2. Plan —— 计划模式下的研究代理，同样只读，负责在主会话保持只读的前提下先摸清代码库
3. general-purpose —— 既能探索又能动手的通用代理，拥有子代理可用的全部工具，适合多步、有依赖的任务
4. statusline-setup（Sonnet）与 claude-code-guide（Haiku）—— 辅助代理，通常由系统自动调用
5. claude —— 兜底代理；后台会话默认也用它，权限模式取决于会话的启动方式

内置代理的上下文差异：Explore 与 Plan 启动时不带你的 CLAUDE.md 与 git 状态快照，目的是让研究更快更便宜；
其余内置与自定义子代理都会加载 CLAUDE.md 与 git 状态，除非在定义里设 omitClaudeMd: true。
```

```bash
# 限制内置代理的几种方式
# 1) 用权限规则封掉某个内置类型，或封掉 Agent 工具本身（彻底禁止委派）
#    在 settings.json 里写 permissions.deny
# 2) 移除 Explore 与 Plan
export CLAUDE_CODE_DISABLE_EXPLORE_PLAN_AGENTS=1

# 3) 非交互模式与 Agent SDK 里移除所有内置类型，只用自己的
export CLAUDE_AGENT_SDK_DISABLE_BUILTIN_AGENTS=1
```

```json
{
  "permissions": {
    "deny": ["Agent(Explore)"]
  }
}
```

```text
子代理机制要点：
1. 非 fork 子代理启动时看到的是：自己的系统提示加环境信息、Claude 写的委派任务描述、完整的 CLAUDE.md 层级、git 状态快照、预加载的技能正文
2. 它看不到你的对话历史、你已经调用过的技能、你之前读过的文件——所以委派信息不够时，结果一定不对
3. 所有子代理 description 合计超过 15000 token 时启动会告警；描述要短，细节挪进系统提示（只在运行时加载）
4. 子代理的报告在交给 Claude 之前会被扫描：模仿系统提示或权限设置的文本会被加反斜杠或插入一行 harness 标记，报告本身不会被改写
5. 内置 Explore 与 Plan 是一次性的，不返回 agent ID，无法被恢复；要用可续跑的子代理就选 general-purpose 或自定义类型
```

## 自定义子代理定义

自定义子代理就是一个带 YAML 前端元数据的 Markdown 文件，正文即系统提示。存放位置决定作用域与优先级：同名时按 managed → `--agents` 命令行定义 → 项目 `.claude/agents/` → 用户 `~/.claude/agents/` → 插件 `agents/` 的顺序取胜。

| 字段 | 必填 | 说明 |
| - | - | - |
| `name` | 是 | 唯一标识（最长 256 字符），不能含 `:`（留给插件作用域名）。hooks 收到的 `agent_type` 就是它 |
| `description` | 是 | Claude 依据它决定何时委派；要写成"什么时候用我" |
| `tools` / `disallowedTools` | 否 | 工具白名单 / 黑名单（逗号分隔或 YAML 列表）；不给 `tools` 则继承子代理可用的全部工具 |
| `model` | 否 | `sonnet` / `opus` / `haiku` / `fable` / 完整模型 ID / `inherit`；省略则按子代理模型解析顺序 |
| `permissionMode` | 否 | `default`、`acceptEdits`、`auto`、`dontAsk`、`bypassPermissions`、`plan`；插件子代理忽略此字段 |
| `maxTurns` | 否 | 最大 agentic 轮数；到顶后返回标记为部分完成的结果，可再续跑 |
| `skills` | 否 | 启动时预加载的技能（注入完整正文，而不只是描述） |
| `memory` | 否 | `user` / `project` / `local`，开启该子代理自己的跨会话记忆 |
| `background` | 否 | 设 `true` 时即使 Claude 想前台跑它也放后台 |
| `omitClaudeMd` | 否 | 设 `true` 时启动不带 user / project / local 的 CLAUDE.md |
| `isolation` | 否 | 设 `worktree` 时在临时 git worktree 里运行，拿到仓库的隔离副本 |
| `hooks`、`mcpServers` | 否 | 仅对本次子代理生效的生命周期钩子与 MCP 服务器（插件子代理忽略） |
| `color`、`initialPrompt`、`effort`、`experimental` | 否 | 显示颜色、作为主会话代理时的首轮提示、推理强度、实验项（如 `cacheTtl`） |

```markdown
<!-- .claude/agents/code-reviewer.md：只读审查代理，工具收窄到 Read/Grep/Glob/Bash -->
---
name: code-reviewer
description: 资深代码审查专家。写代码或改完代码后立刻使用，检查质量、安全与可维护性。
tools: Read, Grep, Glob, Bash
model: inherit
---

你是资深代码审查者，关注质量与安全。

被调用时：
1. 跑 git diff 看最近改动
2. 聚焦被修改的文件
3. 立即开始审查

审查清单：
- 命名与可读性、重复代码
- 错误处理与输入校验
- 是否暴露密钥
- 测试覆盖与性能隐患

按优先级组织反馈：必须修（Critical）/ 应修（Warning）/ 建议（Suggestion），每条给出具体改法。
```

```bash
# 会话内让 Claude 帮你创建（推荐：它会按位置写对字段）
> 在 ~/.claude/agents/ 创建一个只读的 code-improver 子代理，用 sonnet

# /agents 只打印提醒，让你直接编辑 .claude/agents/ 或 ~/.claude/agents/
> /agents

# 一次性定义（只对本次会话有效），适合临时试验与自动化脚本
claude --agents '{
  "code-reviewer": {
    "description": "Expert code reviewer. Use proactively after code changes.",
    "prompt": "You are a senior code reviewer.",
    "tools": ["Read", "Grep", "Glob", "Bash"],
    "model": "sonnet"
  }
}'

# 用 JSON 文件传定义（非交互模式）：claude -p --agents ./agents.json "review 我的改动"

# 让整个会话以某个子代理的身份运行
claude --agent code-reviewer
```

```text
定义相关要点：
1. 项目子代理会被逐级向上扫描，嵌套目录里同名时以离工作目录最近的定义为准；同一目录内同名只加载一个，文件系统读取顺序决定
2. 文件被跳过的常见原因：没有 name（当作普通文档）、开头 `---` 不在第一行、name 以 `-` 开头或含 `:` 或过长、有 name 没 description、YAML 解析失败——这些都不在会话里报错，只写进 `--debug` 的日志
3. 修改 `~/.claude/agents/` 与 `.claude/agents/` 会在几秒内热加载；但新建某个作用域的 `agents` 目录、或改动 `--add-dir` 目录里的定义，需要重启会话
4. 插件提供的子代理为安全起见忽略 `hooks`、`mcpServers`、`permissionMode` 三个字段；需要它们就把文件复制到 `.claude/agents/`
5. 三种显式调用方式：自然语言点名（Claude 自行决定）、`@` 提及（保证用这个子代理）、`--agent` 或 settings 里的 `agent`（整个会话都是它）
6. 恢复子代理：Claude 用 SendMessage 带 agent ID 或名字续跑，续跑的实例保留完整历史与首次运行的工具集；但 Explore / Plan 不返回 ID，无法续跑
```

## 技能加载与使用

技能是 `SKILL.md`：YAML 前端元数据说明「做什么、什么时候用」，正文是 Claude 执行时遵循的指令。它按需加载——描述常驻上下文（用来让 Claude 知道有这个能力），正文只在被调用或被判定相关时才进入会话。同一套机制也承载了自定义命令（`.claude/commands/*.md` 是旧格式，仍可用，但不支持 `name` 与 `paths`）。

| 位置 | 路径 | 生效范围 |
| - | - | - |
| Enterprise | managed settings 目录下的 `.claude/skills/<name>/SKILL.md` | 组织部署到的所有机器 |
| Personal | `~/.claude/skills/<name>/SKILL.md` | 本机所有项目 |
| Project | `.claude/skills/<name>/SKILL.md` | 本仓库，建议提交给团队 |
| Nested | `<subdir>/.claude/skills/<name>/SKILL.md` | 在该子目录或其下启动的会话；从上层启动时会话在触碰该目录文件后加载 |
| Additional directory | `--add-dir` 目录下的 `.claude/skills/<name>/SKILL.md` | 该会话 |
| Plugin | `<plugin>/skills/<name>/SKILL.md` | 插件启用的地方，命令名带前缀 `/plugin-name:skill-name` |

```bash
mkdir -p ~/.claude/skills/summarize-changes
```

```markdown
<!-- ~/.claude/skills/summarize-changes/SKILL.md -->
---
description: 总结未提交的改动并指出风险。当用户问改了什么、要提交信息、或要审查 diff 时使用。
---

## 当前改动

!`git diff HEAD`

## 指令

用两三条要点总结上面的改动，然后列出你注意到的风险：缺少错误处理、硬编码值、需要补的测试。
如果 diff 为空，直接说没有未提交的改动。
```

```json
// 预先授权技能用到的工具，免去每轮的权限提示
// 前端元数据里写：allowed-tools: Bash(git add *) Bash(git commit *) Bash(git status *)
{
  "name": "commit",
  "description": "暂存并提交当前改动",
  "disable-model-invocation": true,
  "allowed-tools": "Bash(git add *) Bash(git commit *)"
}
```

```text
技能使用要点：
1. 命令名来自目录名或前端元数据的 name；嵌套目录重名时用路径限定，如 /apps/web:deploy
2. 只有 description 建议必写，它和 when_to_use 合计在技能列表里被截断到 1536 字符，把最主要的用途放最前面
3. 谁有权调用由两个字段控制：`disable-model-invocation: true` 只允许你手动触发（适合有副作用的部署、提交），`user-invocable: false` 只允许 Claude 自己用（适合背景知识）
4. 参数替换支持 `$ARGUMENTS`、`$ARGUMENTS[N]`、`$N` 与 `$name`（配合 `arguments` 字段），另有一批 `${CLAUDE_SKILL_DIR}`、`${CLAUDE_PROJECT_DIR}`、`${CLAUDE_SESSION_ID}`、`${CLAUDE_EFFORT}` 变量
5. 正文里的 !`command` 会在内容送给 Claude 之前执行并把输出内联进去，技能因此能拿到实时数据（如 `gh pr diff`）；claude.ai 同步来的技能不会在你的机器上执行这类命令
6. 技能正文一旦加载会跨轮保留，每行都是持续成本；正文里只写做什么，不要写长篇叙事。要跑在独立上下文里就加 `context: fork`（可再配 `agent` 指定用哪个子代理类型）
7. 前端元数据只被 Claude Code 识别的字段在别处会报错：上传到 claude.ai / Skills API 只允许 name、description、license、compatibility、metadata、allowed-tools 六个字段
```

## 任务分发与并行

并行的第一层是同一个会话里的多个子代理，第二层是把整个会话丢到后台，第三层是用 `/batch` 把大改动拆成多个各自独占 worktree 的子代理。理解什么时候跑前台、什么时候跑后台，决定了你会不会被权限提示卡住。

```text
前台与后台的判定（Claude 每次用 Agent 工具起子代理时按顺序匹配）：
1. 由代理团队队友发起的子代理 → 前台；队友定义里写 background: true 会被直接拒绝
2. 设了 CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1 → 一律前台
3. fork 模式开启（交互式会话默认开启）→ 一律后台，Claude 不能要求前台
4. fork 模式关闭（-p 与 Agent SDK 默认关闭）→ 默认后台，需要结果时前台；定义里 background: true 可强制后台

后台子代理的工具集更窄：保留 MCP 工具，但内置只留 Read、Grep、Glob、LSP、Bash、PowerShell、Edit、Write、
NotebookEdit、WebFetch、WebSearch、TodoWrite、Skill、ToolSearch、EnterWorktree、ExitWorktree、Monitor、TaskStop、SendMessage、Artifact。
```

```bash
# 并发与派生深度（默认 20 个并发、向下最多 3 层）
# settings.json: { "env": { "CLAUDE_CODE_MAX_CONCURRENT_SUBAGENT": "8" } }
export CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS=8
export CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH=2   # 设 1 等于关闭嵌套

# 把当前会话整体丢到后台，释放终端
> /background 把剩下的测试补完

# 派生一个子任务（同一会话的 fork，不是新会话）
> /subtask 检查一下日志里有没有漏掉的异常分支

# 大范围改动：拆成 5 到 30 个独立单元，每个单元一个后台子代理 + 独立 worktree
> /batch 把 src/ 下的 JavaScript 迁移到 TypeScript
```

```text
分工与并行要点：
1. 每个后台子代理的权限提示都会浮现到主会话并标明是哪个子代理在问；按 Esc 只拒绝那一次调用，不会终止它
2. 并发上限默认 20，达到上限后新委派会失败并明确告知 Claude 不要重试；开启了 ultracode 的会话不受该限制
3. 每个子代理 invocation 都是新实例；要续跑用 SendMessage 带 agent ID 或名字，续跑会占一个新槽位且不检查上限
4. 需要文件系统隔离就给子代理加 `isolation: worktree`：它在临时 worktree 里跑 Bash，git 命令被限制在该 worktree 内
5. 子代理可以再派生子代理，默认向下三层；到达深度上限时 Agent 工具会被回收，让它在本地把活干完并只交一份总结
6. 代理团队（agent teams）是另一条路：多个会话互相通信、Claude 统一调度，但队友各自维护上下文，plan 模式下大约比普通会话多耗 7 倍 token，任务要小而内聚
```

## 应用场景实战

### 场景一：只读审查子代理 + @ 提及，保证每次改动都被过一遍

```bash
mkdir -p .claude/agents
cat > .claude/agents/auth-reviewer.md <<'MD'
---
name: auth-reviewer
description: 认证与授权代码的专职审查者。改动 src/auth/ 或 src/middleware/ 下的文件后必须使用。
tools: Read, Grep, Glob, Bash
model: sonnet
permissionMode: default
---

你只审查认证与授权相关代码，不修改文件。

审查清单：
- 令牌校验是否覆盖过期、签名错误、算法混淆
- 会话固定与重放风险
- 权限判定是否只在服务端进行
- 日志是否泄露令牌或个人信息

输出格式：每条结论一行，形如 `severity | file:line | 问题 | 建议`，最后给一句总体判断。
MD

git add .claude/agents && git commit -m "chore: 增加认证代码审查子代理"
```

```text
# 用 @ 提及保证由它来跑（而不是留给 Claude 自己挑）
@"auth-reviewer (agent)" 看一下这次 dev/oauth-refresh 分支的改动

# 也可以整会话以它为身份运行
claude --agent auth-reviewer
```

### 场景二：用 /batch 并行迁移，每个单元一个 worktree

```text
# 大范围机械式重构：让 Claude 先调研、拆单元、给计划，再逐单元并行执行
> /batch 把 packages/web/src 下所有 class 组件迁移成函数组件 + Hooks

# 它会：调研代码库 → 拆成 5 到 30 个独立单元 → 给出计划等你确认 →
#       每个单元起一个后台子代理，在独立 worktree 里实现、跑测试、产出改动
# 前提：git 仓库（非 git 场景需要 WorktreeCreate hook），且任务能真正拆成互不依赖的单元

# 随时查看进度，进某个子代理的 transcript
> /tasks
```

### 场景三：把重复流程写成技能，再用子代理隔离执行

```bash
mkdir -p .claude/skills/pr-summary
cat > .claude/skills/pr-summary/SKILL.md <<'MD'
---
name: pr-summary
description: 汇总当前 PR 的改动与评审意见。当用户要 PR 摘要或要发评审说明时使用。
context: fork
agent: Explore
allowed-tools: Bash(gh *)
argument-hint: [pr-number]
---

## PR 上下文

- PR 编号：$ARGUMENTS
- 改动：!`gh pr diff $ARGUMENTS`
- 评审意见：!`gh pr view $ARGUMENTS --comments`
- 变更文件：!`gh pr diff $ARGUMENTS --name-only`

## 你的任务

用三段总结：改了什么、为什么有风险、评审需要关注哪三点。不要复述 diff 内容。
MD

git add .claude/skills && git commit -m "chore: 增加 PR 汇总技能"
```

```text
# 调用：只读的 Explore 代理在独立上下文里跑，正文里的 gh 命令先执行并把输出内联
> /pr-summary 1234

# 反向用法：让子代理预加载技能作为参考材料，子代理正文负责流程
.claude/agents/db-migrator.md 里写：
---
name: db-migrator
description: 执行数据库迁移并核对结果
tools: Read, Edit, Bash
skills: [schema-conventions, rollback-playbook]
model: sonnet
---
```

## 最佳实践与踩坑记录

### 最佳实践

1. 一个子代理只干一件事：`description` 写清"什么时候用我"，让路由精准；所有描述合计别超过 15000 token
2. 工具只给必要的：审查类子代理去掉 Edit / Write，只读探索类再收窄到 Read / Grep / Glob，安全与专注度一起提升
3. 项目子代理提交进版本控制，团队共享；跨项目的个人子代理放 `~/.claude/agents/`
4. 有副作用的技能一定加 `disable-model-invocation: true`，把部署、提交、发消息这类动作留给人工触发
5. 技能正文控制在必要长度（它会跨轮常驻），把参考材料放同目录的附加文件，只在需要时让 Claude 打开
6. 需要独立上下文又依赖当前讨论时用 fork（`/subtask`、fork 模式），只依赖任务本身时用普通子代理或 `context: fork`
7. 并行大改动先确认任务可拆：`/batch` 的单元必须互不依赖，否则 worktree 里的实现会互相冲突

### 踩坑记录

```text
坑 1：新建了子代理文件，Claude 却一直说找不到
结论：文件写在 ~/.claude/agents/ 里，会话里怎么都不识别。
原因：文件监听只覆盖会话启动时已存在的目录；首次创建 agents 目录不被发现。
解法：重启会话；此后对已有目录内的文件做增删改都会在几秒内热加载。用 claude plugin validate ~/.claude/agents 检查前端元数据能否解析。

坑 2：子代理跑出来的结论答非所问
结论：委派给只读代理的任务，返回的总结和你要的完全不是一回事。
原因：非 fork 子代理看不到你的对话历史，它只有 Claude 写的委派描述——描述不完整，结果必然偏。
解法：把约束、输入文件、期望输出格式写进委派提示；或者把任务的上下文写进子代理的系统提示；再不行就用 fork（继承整段对话历史）。

坑 3：后台子代理卡在权限提示上，以为它挂了
结论：主会话看起来没动静，实际是后台子代理发起了需要授权的工具调用。
原因：后台子代理的权限提示会浮现到主会话，等你去答。
解法：在提示里直接批准，或按 Esc 只拒绝那一次调用；无人值守场景用 --permission-mode 加 --allowedTools 预先放开，或加上 --permission-prompts none 让无法解答的请求被拒绝而不是等待。

坑 4：并行子代理数量超限，委派直接失败
结论：一次让 Claude 起几十个子代理，报 "Concurrent subagent limit reached" 且被告知不要重试。
原因：默认同时最多 20 个子代理；续跑已完成的子代理还会额外占槽且不检查上限。
解法：分批委派，或用 CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS 调整上限；把大任务交给 /batch 由它按单元调度，而不是自己堆数量。

坑 5：context: fork 的技能里只写了规范，跑完没有任何输出
结论：技能能运行，但子代理返回空结论。
原因：fork 出的子代理拿到的是技能正文作为任务提示；纯背景知识没有可执行动作，也没有对话历史可参考。
解法：`context: fork` 只用于有明确步骤的任务型技能；纯参考类技能保持不带 fork，让它内联进主会话上下文。
```

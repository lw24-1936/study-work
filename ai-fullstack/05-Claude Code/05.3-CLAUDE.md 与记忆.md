## 概述

Claude Code 每个会话都从一块空白的上下文窗口开始，跨会话留存知识靠两个互补机制：你手写的 CLAUDE.md 文件（指令与规则），以及 Claude 自己写的自动记忆（从你的纠正与偏好里总结出的经验）。两者都在会话启动时载入，都被当作「上下文」而不是「强制配置」——它们影响 Claude 的判断，但拦不住它做某件事，真要硬拦得用 PreToolUse hook 或权限规则。

```text
本篇的五个抓手：
1. 层级 —— managed / user / project / local 四层记忆文件，谁先加载、谁覆盖谁、子目录怎么按需加载
2. 组合 —— 仓库里有 AGENTS.md 时读哪个，"Project instructions" 四个取值怎么选
3. 引用 —— @path/to/file 引入外部文件、转义与不生效的情形、跨出工作目录时的批准弹窗
4. 规则 —— .claude/rules/ 按主题拆分，用 paths 前端元数据做按路径生效
5. 记忆 —— 自动记忆的四种类型、MEMORY.md 的加载上限、/context 与 /compact 的上下文管理

本机环境说明：Ubuntu 24.04 实验机上未安装 claude CLI，本篇的路径、字段与命令均取自官方文档
（code.claude.com/docs/en 的 memory、context-window 页面）。文件路径随操作系统不同，以官方文档为准。
```

## 记忆文件层级与加载顺序

CLAUDE.md 是纯 Markdown 文件，按作用域放在不同位置：组织级由 IT 下发、用户级对你所有项目生效、项目级随仓库提交给团队、local 级只属于你自己（应加进 `.gitignore`）。启动时 Claude Code 从当前工作目录一路向上收集 `CLAUDE.md` 与 `CLAUDE.local.md`，全部拼接进上下文而不是互相覆盖。

| 作用域 | 位置 | 用途 | 共享范围 |
| - | - | - | - |
| Managed policy | Linux / WSL：`/etc/claude-code/CLAUDE.md`；macOS：`/Library/Application Support/ClaudeCode/CLAUDE.md`；Windows：`C:\Program Files\ClaudeCode\CLAUDE.md` | 公司编码规范、安全策略、合规要求，由 IT 部署 | 组织内所有用户，个人设置无法排除 |
| User instructions | `~/.claude/CLAUDE.md` | 个人偏好：代码风格、常用工具与快捷方式 | 只有你，所有项目 |
| Project instructions | `./CLAUDE.md` 或 `./.claude/CLAUDE.md` | 团队共享：项目架构、构建与测试命令、约定 | 通过版本控制给所有成员 |
| Local instructions | `./CLAUDE.local.md` | 个人项目内偏好：沙箱地址、测试数据 | 只有你，当前项目，需自行 gitignore |

```bash
# 生成起步版：/init 会分析代码库并写出构建命令、测试方式与项目约定
claude
> /init

# 打开记忆文件：列出各级路径（不存在的也能一键创建），并可开关自动记忆
> /memory

# 确认这些文件真的加载了：/context 列出的 Memory files 就是本会话实际读到的
> /context
```

```text
层级与加载要点：
1. 拼接顺序是"文件系统根 → 当前工作目录"，也就是离启动目录越近的指令越晚被读到；同一目录内 CLAUDE.local.md 追加在 CLAUDE.md 之后
2. 工作目录子目录里的 CLAUDE.md 不会在启动时加载，而是等 Claude 第一次读、写或编辑该子目录中的文件时按需加载（bash 的 cat / head 单文件也算读取）
3. 块级 HTML 注释 `<!-- maintainer notes -->` 会在注入上下文前被剔除，写给人看的维护说明不花 token；代码块内的注释保留
4. 单个 CLAUDE.md 超过 4 MiB 会被整体跳过；官方建议每个文件控制在 200 行以内，超长会降低遵循度并在启动与 /status 处给出告警
5. `claudeMdExcludes` 可按路径或 glob 排除无关文件（大型 monorepo 常用），数组跨层合并；但 managed policy 的文件无法排除
6. `--add-dir` 带来的目录默认不加载记忆文件，需要 `CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD=1` 才加载其 CLAUDE.md、.claude/rules 与 CLAUDE.local.md
```

## 指令文件组合与 AGENTS 兼容

很多仓库已经为其他编码代理准备了 `AGENTS.md`。Claude Code 可以直接读它，不必再加一个 CLAUDE.md 或写导入语句：判断规则是「工作目录及其上层有没有 CLAUDE.md」——有就用 CLAUDE.md，没有才用 AGENTS.md。

```json
// ~/.claude/settings.json：让 Claude 同时读 CLAUDE.md 与 AGENTS.md
{
  "pluginConfigs": {
    "cc-plugin-agents-md@builtin": {
      "options": { "instructionFiles": "claude-md-and-agents-md" }
    }
  }
}
```

```markdown
<!-- CLAUDE.md：当项目以 AGENTS.md 为唯一事实来源时，用导入共享同一份内容 -->
@AGENTS.md

## Claude Code

在 src/billing/ 下的改动一律先进入计划模式。
```

```text
组合与兼容要点：
1. 默认值 `claude-md-or-agents-md`：有 CLAUDE.md 或 CLAUDE.local.md 就读它们，否则读 AGENTS.md（启动会打印一行 "no CLAUDE.md found; AGENTS.md loaded: <路径>"）
2. 另外三个取值：`claude-md-and-agents-md` 两者都读、`claude-md` 只读 CLAUDE.md、`managed-only` 只读组织下发内容与自动记忆
3. 该设置可在会话里用 /config 的 "Project instructions" 改，也可写进 `~/.claude/settings.json`、`--settings` 或 managed settings；写在项目与 local 设置里会被忽略
4. 直接读 AGENTS.md 需要 v2.1.277 及以上；早期版本或某些会话里可用 `@AGENTS.md` 导入兜底，导入不会导致重复加载
5. `AGENTS.local.md`、`AGENTS.override.md` 与 `.agents/` 目录下的内容不会被读取
6. `/import` 能从其他编码代理搬运配置（指令文件、MCP 服务器、命令、子代理、技能），`/init` 也会读取 Cursor 的 `.cursor/rules/`、Copilot 的 `.github/copilot-instructions.md` 等
```

## 文件引用语法与路径规则

CLAUDE.md 支持用 `@path/to/import` 引入其他文件，被引入的文件会在启动时展开并加载进上下文。这是组织长指令的手段，但它不省 token——被导入的文件同样在启动时全部载入。

```markdown
<!-- 相对路径相对"引用它的那个文件"解析，而不是相对工作目录 -->
See @README for project overview and @package.json for available npm commands.

# Additional Instructions
- git workflow @docs/git-instructions.md
- API 约定 @Design\ Docs/api-conventions.md     <!-- 路径含空格：每个空格前加反斜杠 -->
- 个人偏好 @~/.claude/my-project-instructions.md  <!-- 跨工作目录的个人指令，多 worktree 共用 -->
```

```text
引用语法要点：
1. 递归深度上限为四跳；相对路径以引用方文件所在目录为基准解析
2. 路径中含空格必须逐个写成 `\ `（转义）；用引号包起来的路径完全不会被导入
3. 导入解析会跳过行内代码与围栏代码块：写成 `` `@README` `` 只作为文本，不会导入
4. 路径解析到工作目录之外属于"外部导入"，项目级记忆文件首次遇到时会弹窗列出这些文件让你批准；拒绝后该导入保持禁用且不再弹窗
5. 你写在自己 `~/.claude/CLAUDE.md` 与 `~/.claude/rules/` 里的导入视为自己写的配置，不弹窗
6. 在项目里也可以直接 `ln -s AGENTS.md CLAUDE.md`，但 Edit / Write 工具拒绝穿过符号链接写入，而且 Windows 克隆时符号链接会变成普通文本文件，跨平台项目用 `@AGENTS.md` 更稳
```

## 项目规则编写方法

指令一多，单文件就会失控。`.claude/rules/` 允许把规则按主题拆成多个 Markdown 文件，并用前端元数据的 `paths` 字段让规则只在处理匹配文件时生效，从而按需占用上下文。`paths` 是规则文件里唯一被读取的字段，其他字段会被静默忽略。

```text
your-project/
├── CLAUDE.md               # 主指令：构建命令、整体约定、导航
└── .claude/
    ├── rules/
    │   ├── code-style.md   # 无条件加载，与 .claude/CLAUDE.md 同级
    │   ├── testing.md
    │   ├── security.md
    │   └── frontend/
    │       └── react.md    # 递归发现，子目录不改变加载规则
    └── skills/             # 只在被调用时加载，适合任务型流程（见 05.4）
```

```markdown
---
paths:
  - "src/api/**/*.ts"
  - "src/**/*.{ts,tsx}"
---

# API 开发规则

- 所有接口必须做输入校验
- 统一使用标准错误响应结构
- 补上 OpenAPI 注释
```

```text
规则编写要点：
1. 不带 `paths` 的规则在启动时加载，优先级与 `.claude/CLAUDE.md` 一致；带 `paths` 的规则在 Claude 读/写/编辑匹配文件时才加载
2. glob 支持 `**/*.ts`、`src/**/*`、`src/components/*.tsx` 与花括号展开；一条规则的 paths 总预算为 1000 个展开模式与 4 MiB
3. `~/.claude/rules/` 是用户级规则，先于项目规则加载；两者冲突时不会互相覆盖，Claude 可能任选一条，所以要保持一致
4. 规则目录支持符号链接共享；链接目标在工作目录之外时按外部导入处理，需要批准，且批准后只有不带 `paths` 的规则加载
5. 要硬约束行为（比如"提交前必须跑 lint"）不要只写文字：用 hooks 或 permissions.deny，指令只是上下文
6. 用 `/doctor prompt-audit` 让 Claude 自查指令文件中的过时引用、互相矛盾与为旧模型写的说明，它只给报告与建议，不会直接改文件
```

## 自动记忆与上下文管理

自动记忆让 Claude 自己记笔记：你把「以后用 pnpm 不要用 npm」这类纠正说一次，它会写进按项目隔离的记忆目录，下次会话开头就带着这些信息。它与你手写的 CLAUDE.md 是两套东西，都在会话启动时注入。上下文管理则是另一半问题：装了再多记忆，也要控制住整个窗口。

```text
~/.claude/projects/<project>/memory/
├── MEMORY.md           # 索引，每个记忆一行，每次会话都加载
├── user_role.md        # 单条记忆：你的角色与偏好
├── feedback_testing.md # 单条记忆：你给过的纠正
└── ...                 # Claude 自己创建的其他主题文件
```

```json
// 关闭自动记忆（单个项目）或用环境变量全局关闭
{
  "autoMemoryEnabled": false
}
```

```bash
# 关掉自动记忆的另一种方式
export CLAUDE_CODE_DISABLE_AUTO_MEMORY=1

# 想换记忆目录（必须是绝对路径或以 ~/ 开头）
# settings.json: { "autoMemoryDirectory": "~/my-custom-memory-dir" }

# 会话内的上下文管理四件套
/context                       # 看当前窗口被什么占满，含哪些记忆文件加载了
/compact 保留认证流程约束与失败用例  # 带重点压缩
/clear                         # 换个不相关的任务时直接清空
/rewind                        # 选择某条消息后做 Summarize from here / up to here
```

```text
自动记忆与上下文要点：
1. 记忆分四类，写在文件前端元数据的 type 字段：user（角色与偏好）、feedback（纠正与确认过的做法）、project（无法从代码推导的进行中工作与决策）、reference（外部信息在哪找）
2. MEMORY.md 每次会话只加载前 200 行或前 25 KB（先到者为准），超出的部分下次加载被丢弃，所以它必须是一行一条的索引，细节放主题文件按需读取
3. 记忆是本机数据，同一 git 仓库的所有 worktree 与子目录共享一份；不跨机器、不跨云会话；记忆目录不参与 30 天清理，会一直留着直到你或 Claude 修改删除
4. 主会话的自动记忆不会进入子代理，除非该子代理自己开了 `memory` 字段（那是另一个独立目录）
5. 一次压缩后仍会保留的东西：系统提示与输出风格、项目根 CLAUDE.md 与无作用域规则、自动记忆、git 状态快照、计划模式写下的计划、最近读过改过的至多 5 个文件；缺失的是子目录 CLAUDE.md（按需重载）与带 paths 的规则（需再次匹配文件）
6. 已调用过的技能正文会按每个 5000 token、合计 25000 token 的预算重新挂回上下文，最旧的先被丢弃——所以技能的关键指令要写在文件开头
```

## 应用场景实战

### 场景一：monorepo 里的分层记忆与排除其他团队

```text
monorepo/
├── CLAUDE.md                      # 全仓约定：包管理器、提交规范、如何跑全量测试
├── packages/
│   ├── api/
│   │   ├── CLAUDE.md              # 只在 Claude 碰 api 目录里的文件时加载
│   │   └── .claude/rules/api.md   # 带 paths: src/api/**/*.ts，进一步收窄
│   └── web/
│       └── CLAUDE.md
└── other-team/                    # 别人的目录，和你的任务无关
    └── CLAUDE.md
```

```json
// .claude/settings.local.json：个人在本机屏蔽无关的祖先记忆文件
{
  "claudeMdExcludes": [
    "**/other-team/CLAUDE.md",
    "/home/dev/monorepo/other-team/.claude/rules/**"
  ]
}
```

```bash
# 验证到底加载了什么：/context 的 Memory files 段 + InstructionsLoaded hook 日志
claude --debug
> /context
```

### 场景二：把团队规则库拆成按路径生效的规则

```bash
mkdir -p .claude/rules

cat > .claude/rules/testing.md <<'MD'
---
paths:
  - "**/*.test.ts"
  - "tests/**/*"
---

# 测试约定

- 用 vitest，不用 jest；断言统一 expect 风格
- 新增行为必须带失败用例，不允许只改断言让测试变绿
- 涉及时间的用例注入假时钟，禁止 sleep
MD

cat > .claude/rules/security.md <<'MD'
# 安全基线（无条件生效）

- 严禁把密钥写进代码或日志，配置统一走环境变量
- 外部输入必须校验边界与类型
- SQL 一律参数化查询
MD

git add .claude/rules && git commit -m "docs: 团队级 Claude 规则，按路径作用域拆分"
```

### 场景三：自动记忆审计加带重点压缩

```text
# 1. 先看 Claude 自己记了什么，按住 Ctrl 直接编辑或删除
/memory → 选择 auto memory 目录

# 2. 长会话开始变慢、开始忽略约束时，带重点压缩而不是简单清空
/compact 保留：认证流程的接口约束、已知的失败用例、团队的分支命名规则；丢弃：调试日志与中间尝试

# 3. 确认压缩后关键内容还在
/context

# 4. 换到不相关的任务时彻底清空，避免旧会话挤掉新文件
/clear release-prep
```

## 最佳实践与踩坑记录

### 最佳实践

1. 把 CLAUDE.md 当作「你不想再解释第二遍的东西」的清单：同一个纠正说了两次、code review 指出过的问题、新人上手需要的前置信息，都该写进去
2. 指令要具体到可验证：「用 2 空格缩进」而不是「格式规范一些」；「提交前跑 `npm test`」而不是「记得测试」
3. 每个文件控制在 200 行以内，按主题拆进 `.claude/rules/`，只对部分路径有用的规则一律加 `paths` 前端元数据
4. 需要强制执行的规则交给 `permissions.deny` 或 hooks，CLAUDE.md 只负责引导行为
5. 团队共享的项目指令提交进仓库，个人偏好放 `CLAUDE.local.md` 或 `~/.claude/CLAUDE.md`，并确保 local 文件被 gitignore
6. 定期用 `/doctor prompt-audit` 清理过时与互相矛盾的指令；两个文件给出相反指导时 Claude 可能任选一条
7. 长会话主动管理上下文：换任务用 `/clear`，延续同一任务用带重点的 `/compact`，需要连续推理的中间结论写进 CLAUDE.md 而不是只留在对话里

### 踩坑记录

```text
坑 1：子目录的 CLAUDE.md 没生效，/context 里也找不到
结论：以为写了就生效，实际 Claude 完全不知道那些约定。
原因：工作目录子目录下的 CLAUDE.md 不在启动时加载，而是等 Claude 首次读写该目录中的文件才按需加载。
解法：让 Claude 读一个该子目录里的文件触发加载（终端会打印一行 Loaded 及路径），或用 /add-dir 把该子目录加入；想全局生效就移到项目根。

坑 2：AGENTS.md 明明存在却不被读取
结论：仓库里有完整的 AGENTS.md，Claude 却按另一套规矩干活。
原因：工作目录或上层存在 CLAUDE.md / .claude/CLAUDE.md / CLAUDE.local.md 时，默认不再读 AGENTS.md；个人加一个 CLAUDE.local.md 也会触发这个切换。
解法：把 /config 的 "Project instructions" 设为 claude-md-and-agents-md，或在 CLAUDE.md 里写一行 @AGENTS.md 显式导入。

坑 3：把规则拆成几十个小文件，上下文反而更臃肿
结论：指令拆分做完，token 占用比原来更高，遵循度也没变好。
原因：@path 导入与不带 paths 的规则文件都在启动时全量加载，拆分只改善可维护性，不省上下文。
解法：只对真正路径相关的规则加 `paths` 让它们按需加载；把任务型、偶尔才用的流程改写成技能（skills），技能按调用加载。

坑 4：压缩之后 Claude 忘了关键约束
结论：/compact 之后它又开始违反分支命名与接口约定，像换了个人。
原因：只有项目根 CLAUDE.md、无作用域规则与自动记忆会在压缩后重新注入；子目录 CLAUDE.md 与带 paths 的规则要重新匹配文件才回来，只存在于对话里的约束则彻底丢掉。
解法：关键约束写进项目根 CLAUDE.md 或自动记忆；压缩时用 `/compact 保留：…` 显式点名要保的内容；压缩后用 /context 复核。

坑 5：以为 CLAUDE.md 能阻止危险操作
结论：规则里写了"禁止直接改 main"，Claude 仍然执行了 git push。
原因：CLAUDE.md 以用户消息形式注入，是上下文而不是强制策略，措辞含糊或与其他指令冲突时没有保证。
解法：把硬约束做成权限规则（permissions.deny）或 hooks（如 PreToolUse 拦 git push），CLAUDE.md 只写引导性说明。
```

## 概述

大语言模型（Large Language Model，LLM）是在海量文本上训练的自回归 Transformer：它唯一的学习目标就是「给定前面的 token，预测下一个 token 的概率分布」，把这个目标做到极大规模后涌现出问答、翻译、代码、推理等能力。本主题按「结构（Transformer）→ 训练（预训练）→ 输入输出接口（分词、采样）→ 对齐（微调、RLHF/DPO）→ 局限（幻觉与知识截止）」这条链路讲清楚 LLM 的机制，所有示例代码均为 numpy 或标准库实现，实测环境 Python 3.14 + numpy 2.5.4。

```text
一条链路看懂 LLM：
1. 结构 —— 纯解码器 Transformer：多头自注意力 + 前馈网络 + 残差 + LayerNorm 堆 N 层
2. 预训练 —— 在万亿级 token 上做下一个 token 预测，损失就是交叉熵，指标是困惑度
3. 分词 —— BPE/Unigram/WordPiece 把文本切成子词，词表大小决定序列长度与显存
4. 采样 —— 温度、top-k、top-p、重复惩罚把 logits 变成实际输出，决定「发挥」还是「胡说」
5. 对齐 —— SFT 教格式，RLHF/DPO 教偏好，LoRA 让微调在单卡上可行
6. 局限 —— 幻觉来自概率最大化目标，知识截止来自训练数据的时间边界
```

## Transformer 架构

现代 LLM 用的是「纯解码器（decoder-only）Transformer」：每层包含一个因果多头自注意力子层和一个前馈网络（FFN）子层，两者外面各套一个残差连接与归一化。自注意力让每个位置直接读取所有先前位置的信息，注意力权重由 Query 与 Key 的点积除以 `sqrt(d_head)` 再 softmax 得到；多头把它并行做多组，让模型同时关注不同子空间的关系。因为注意力本身对顺序无感，位置信息要靠位置编码注入。

```python
import numpy as np

d_model, n_head, seq_len = 8, 2, 5
d_head = d_model // n_head
rng = np.random.default_rng(0)

# 1) 正弦位置编码：偶数维用 sin，奇数维用 cos
pos = np.arange(seq_len)[:, None]
i = np.arange(d_model)[None, :]
pe = np.where(i % 2 == 0,
              np.sin(pos / 10000 ** (i / d_model)),
              np.cos(pos / 10000 ** ((i - 1) / d_model)))
print("正弦位置编码 pe 形状:", pe.shape)

X = rng.normal(size=(seq_len, d_model)) + pe          # 词嵌入 + 位置编码
Wq, Wk, Wv, Wo = (rng.normal(scale=0.4, size=(d_model, d_model)) for _ in range(4))
mask = np.triu(np.ones((seq_len, seq_len)) * -1e9, k=1)   # 因果掩码：只能看自己和左边

def softmax(z, axis=-1):
    e = np.exp(z - z.max(axis=axis, keepdims=True))
    return e / e.sum(axis=axis, keepdims=True)

def attention(x, mask=None):
    Q, K, V = x @ Wq, x @ Wk, x @ Wv
    Qh = Q.reshape(seq_len, n_head, d_head).transpose(1, 0, 2)   # (n_head, seq, d_head)
    Kh = K.reshape(seq_len, n_head, d_head).transpose(1, 0, 2)
    Vh = V.reshape(seq_len, n_head, d_head).transpose(1, 0, 2)
    scores = Qh @ Kh.transpose(0, 2, 1) / np.sqrt(d_head)        # (n_head, seq, seq)
    if mask is not None:
        scores = scores + mask
    out = softmax(scores) @ Vh
    return out.transpose(1, 0, 2).reshape(seq_len, d_model) @ Wo

def ffn(x, W1, W2):
    return np.maximum(0, x @ W1) @ W2        # 前馈：升维 4 倍再降回，逐位置独立

W1f = rng.normal(scale=0.4, size=(d_model, 4 * d_model))
W2f = rng.normal(scale=0.4, size=(4 * d_model, d_model))
print("单头维度 d_head =", d_head, " 头数 =", n_head)
attn_out = attention(X)
print("多头自注意力输出形状:", attn_out.shape)
h1 = X + attn_out                            # 残差
h2 = h1 + ffn(h1, W1f, W2f)                  # 残差
print("一个解码器块输出形状:", h2.shape, "（堆叠 N 层就是 GPT/LLaMA 的主干）")
```

真实输出（本机执行）：

```text
正弦位置编码 pe 形状: (5, 8)
单头维度 d_head = 4  头数 = 2
多头自注意力输出形状: (5, 8)
一个解码器块输出形状: (5, 8) （堆叠 N 层就是 GPT/LLaMA 的主干）
```

结构要点：

| 组件 | 作用 | 关键细节 |
|---|---|---|
| 词嵌入 | token id 映射到 d_model 维向量 | 输出层常与嵌入矩阵权重共享（tied embedding） |
| 位置编码 | 注入顺序信息 | 正弦编码（原始论文）或 RoPE（主流 LLM）；RoPE 作用在 Q/K 上 |
| 多头自注意力 | 位置间信息交换 | 头数 × 单头维度 = d_model；除以 `sqrt(d_head)` 防止 softmax 饱和 |
| 因果掩码 | 保证只能看到历史 | 上三角置 -inf；写错就变成标签泄漏 |
| 前馈网络 FFN | 逐位置的非线性变换 | 中间维度常为 4×d_model，用 GELU/SwiGLU |
| 残差 + LayerNorm | 保证深层可训练 | 主流用 Pre-LN 或 RMSNorm |

```text
Transformer 要点：
1. 计算量瓶颈在自注意力的 O(n²)，序列翻倍显存与算力约变 4 倍
2. 推理要缓存历史 K/V（KV Cache），否则每生成一个 token 都要重算整段前缀
3. 多头不是「多个模型」，而是把 d_model 切成 n_head 份并行算再拼回来
4. 参数分布大致为：嵌入层占 params/V 的量级，其余大部分在 FFN 与注意力投影矩阵里
5. 掩码、位置编码、归一化位置这三处写错是 Transformer 实现最常见的 bug
```

## 预训练与缩放定律

预训练的目标函数是自回归交叉熵：把语料整体当作一条长序列，在每一个位置都预测下一个 token，取真实 token 的负对数似然求平均。因为数据没有人工标签（下一个词就是标签），所以可以用任意规模的原始文本。缩放定律（Scaling Law）指出损失随参数量、数据量、算力按幂律下降；Chinchilla 的结论是算力最优时「模型参数量与训练 token 数应当同比例增长」，即约 20 token/参数。

```python
import numpy as np

# 自回归目标：输入右移一位就是标签
tokens = ["我", "爱", "机器", "学习", "<eos>"]
ids = {t: k for k, t in enumerate(tokens)}
seq = [ids[t] for t in tokens]
x_in, y_out = np.array(seq[:-1]), np.array(seq[1:])
print("输入 token:", [tokens[i] for i in x_in])
print("预测目标  :", [tokens[i] for i in y_out])

# 模型在 4 个位置上给出的「真实 token 概率」
prob_rows = np.array([[0.05, 0.60, 0.20, 0.10, 0.05],
                      [0.05, 0.10, 0.70, 0.10, 0.05],
                      [0.05, 0.05, 0.10, 0.75, 0.05],
                      [0.05, 0.05, 0.05, 0.10, 0.75]])
p_true = prob_rows[np.arange(len(y_out)), y_out]
ce = -np.mean(np.log(p_true))
print("每个目标 token 的概率:", np.round(p_true, 3))
print("交叉熵 loss = %.4f  困惑度 perplexity = exp(loss) = %.3f" % (ce, np.exp(ce)))
print("困惑度含义：模型平均在 %.1f 个候选词之间犹豫，越接近 1 越好" % np.exp(ce))

# Chinchilla：算力最优时 训练 token 数 ≈ 20 × 参数量
for params_b in (1.5, 7.0, 70.0):
    print("%5.1fB 参数 -> 约需 %6.0f B tokens" % (params_b, 20 * params_b))
```

真实输出（本机执行）：

```text
输入 token: ['我', '爱', '机器', '学习']
预测目标  : ['爱', '机器', '学习', '<eos>']
每个目标 token 的概率: [0.6  0.7  0.75 0.75]
交叉熵 loss = 0.3607  困惑度 perplexity = exp(loss) = 1.434
困惑度含义：模型平均在 1.4 个候选词之间犹豫，越接近 1 越好
  1.5B 参数 -> 约需    30 B tokens
  7.0B 参数 -> 约需   140 B tokens
 70.0B 参数 -> 约需  1400 B tokens
```

预训练要点：

| 要素 | 常见做法 | 说明 |
|---|---|---|
| 目标函数 | 自回归交叉熵（next-token prediction） | 与 BERT 的掩码语言模型不同，GPT 系是单向的 |
| 数据配比 | 网页、代码、书籍、多语种按比例混合 | 配比直接影响能力分布，代码数据能提升推理 |
| 数据去重 | MinHash/LSH 近似去重 | 重复样本会让模型死记硬背、加剧退化 |
| 缩放定律 | 损失 ∝ 参数量与数据量的幂律 | 用来外推该投算力还是投数据 |
| Chinchilla 经验 | 训练 token ≈ 20 × 参数量 | 后来的实践倾向「数据更多、模型略小」更划算 |
| 指标 | 验证集交叉熵与困惑度 | 与下游任务表现强相关但不是一回事 |

```text
预训练要点：
1. 预训练是「一次投入、长期复用」，成本极高，工程上极少从零开始
2. 困惑度只能在同词表的模型之间比较，换分词器后数值不可比
3. 数据质量通常比数据规模更关键：清洗、去重、配比的收益往往大于加算力
4. 训练过程要监控损失尖峰，出现异常立刻回滚到上一个检查点并跳过坏数据
5. 上下文长度、并行策略、混合精度（bf16）、梯度检查点是预训练的四项基础配置
```

## 分词与词表

分词器把字符串切成 token 并映射成整数 id，是模型与文本之间的唯一接口。主流算法是子词级：BPE 从字符开始反复合并最高频的相邻对；Unigram 从大候选集开始逐步裁剪；WordPiece 用似然准则选择合并。子词方案的目的是兼顾「词表不爆炸」与「能表示未登录词」——常见词保留为整词，罕见词退化成子词。LLM 时代普遍使用 byte-level BPE，用 256 个字节作为基础词表，从而彻底消除未登录符号。

```python
import numpy as np
from collections import Counter

# 手写 BPE：从字符起步，反复合并最高频相邻对
corpus = "low lower lowest new newer 机器学习 机器学习 学习"
words = corpus.split()
word_freq = Counter(words)
splits = {w: list(w) for w in word_freq}       # 中英文统一按字符切分
vocab = Counter()
for w, f in word_freq.items():
    for ch in splits[w]:
        vocab[ch] += f

for step in range(1, 13):
    pairs = Counter()
    for w, f in word_freq.items():
        s = splits[w]
        for a, b in zip(s, s[1:]):
            pairs[(a, b)] += f
    if not pairs:
        break
    (a, b), cnt = pairs.most_common(1)[0]
    if cnt < 2:
        break
    new = a + b
    for w in splits:
        s, out, i = splits[w], [], 0
        while i < len(s):
            if i < len(s) - 1 and s[i] == a and s[i + 1] == b:
                out.append(new); i += 2
            else:
                out.append(s[i]); i += 1
        splits[w] = out
    vocab[new] = cnt
    print("merge %2d: %-4s+%-4s -> %-6s (频次 %d)" % (step, a, b, new, cnt))

print("合并后各词切分:")
for w in word_freq:
    print("  %-8s -> %s" % (w, splits[w]))
print("词表大小 %d" % len(vocab))
```

真实输出（本机执行）：

```text
merge  1: l   +o    -> lo     (频次 3)
merge  2: lo  +w    -> low    (频次 3)
merge  3: 学   +习    -> 学习     (频次 3)
merge  4: low +e    -> lowe   (频次 2)
merge  5: n   +e    -> ne     (频次 2)
merge  6: ne  +w    -> new    (频次 2)
merge  7: 机   +器    -> 机器     (频次 2)
merge  8: 机器  +学习   -> 机器学习   (频次 2)
合并后各词切分:
  low      -> ['low']
  lower    -> ['lowe', 'r']
  lowest   -> ['lowe', 's', 't']
  new      -> ['new']
  newer    -> ['new', 'e', 'r']
  机器学习     -> ['机器学习']
  学习       -> ['学习']
词表大小 20
```

注意 merge 顺序本身就是「规则」：推理时按同样的顺序应用这些合并规则即可编码新词，所以一个分词器 = 词表 + 有序合并规则表。官方文档给出的参考数据：GPT 用 BPE 且词表 40478（478 基础 token + 40000 次合并），GPT-2 用 byte-level BPE 且词表 50257（256 字节 + 50000 合并 + 1 个结束符）。

分词要点：

| 算法 | 思路 | 代表模型 | 特点 |
|---|---|---|---|
| BPE | 从字符起步，反复合并最高频对 | GPT、LLaMA、Qwen、Gemma | 最主流，实现简单、可流式编码 |
| Byte-level BPE | 基础词表用 256 个字节 | GPT-2、GPT-3、GPT-4 | 无未登录 token，任何字节序列都能编码 |
| Unigram | 从大候选集按似然裁剪 | T5、BigBird、Pegasus | 可用概率模型做多种切分 |
| WordPiece | 按似然增益贪心合并 | BERT | 用 `##` 标记子词续接 |
| Word-level | 按空格/标点切 | 早期模型 | 词表爆炸、无法处理未登录词 |
| Char-level | 按字符切 | 早期模型 | 词表小但序列过长、语义弱 |

```text
分词要点：
1. 分词器是模型的一部分，换分词器等于换模型，不能单独替换
2. 中文的 token 效率通常低于英文：同样内容中文可能多占 30%-100% 的 token
3. 数字与代码的切分方式直接影响算术与代码能力，是很多模型专门优化过的点
4. 训练与推理必须用同一个分词器及版本，分词器变更会让权重失效
5. 上下文长度的单位是 token 不是字符，评估成本时先算 token 数
```

## 采样策略与温度

模型的输出层给出的是词表上的一整个概率分布（logits 经 softmax），要变成实际文本必须选一个 token，这个过程叫采样（解码）。温度控制分布的「尖锐度」：`logits / T`，T<1 更确定、T>1 更随机、T=0 等价于贪心。top-k 只保留概率最高的 k 个候选，top-p（核采样）保留累积概率达到 p 的最小集合，两者可叠加使用。重复惩罚（repetition penalty）压低已出现 token 的分数，缓解复读。同样的 prompt 换成不同采样配置，输出风格会明显不同。

```python
import numpy as np

def softmax(z, axis=-1):
    e = np.exp(z - z.max(axis=axis, keepdims=True))
    return e / e.sum(axis=axis, keepdims=True)

logits = np.array([4.0, 3.5, 2.0, 1.0, 0.5, 0.0, -1.0])
words = ["模型", "模型化", "机器", "学习", "深入", "浅出", "无关"]

def show(name, lg):
    p = softmax(lg)
    order = np.argsort(-p)
    print("%-22s -> %s" % (name, [(words[i], round(float(p[i]), 4)) for i in order[:5]]))

show("原始分布 (T=1)", logits)
for T in (0.2, 1.0, 2.0):
    show("T=%.1f（缩放 logits）" % T, logits / T)
print("温度越低分布越尖锐（更确定），越高越平坦（更随机）；T=0 等价于贪心 argmax")

k = 3
lg = logits.copy()
lg[lg < np.sort(lg)[-k]] = -np.inf          # top-k：只留 logit 最大的 k 个
show("top-k (k=3)", lg)

lg = logits.copy()
p = softmax(lg)
order = np.argsort(-p)
keep = order[:np.searchsorted(np.cumsum(p[order]), 0.9) + 1]   # top-p：累积概率到 0.9
lg2 = np.where(np.isin(np.arange(len(lg)), keep), lg, -np.inf)
show("top-p (p=0.9)", lg2)
print("top-p 保留的候选:", [words[i] for i in keep])
print("注意：top-k 固定保留 k 个，top-p 按累积概率自适应，分布平的时候保留更多")
```

真实输出（本机执行）：

```text
原始分布 (T=1)             -> [('模型', 0.5414), ('模型化', 0.3284), ('机器', 0.0733), ('学习', 0.027), ('深入', 0.0164)]
T=0.2（缩放 logits）       -> [('模型', 0.9241), ('模型化', 0.0759), ('机器', 0.0), ('学习', 0.0), ('深入', 0.0)]
T=1.0（缩放 logits）       -> [('模型', 0.5414), ('模型化', 0.3284), ('机器', 0.0733), ('学习', 0.027), ('深入', 0.0164)]
T=2.0（缩放 logits）       -> [('模型', 0.3622), ('模型化', 0.2821), ('机器', 0.1332), ('学习', 0.0808), ('深入', 0.0629)]
温度越低分布越尖锐（更确定），越高越平坦（更随机）；T=0 等价于贪心 argmax
top-k (k=3)            -> [('模型', 0.5741), ('模型化', 0.3482), ('机器', 0.0777), ('学习', 0.0), ('深入', 0.0)]
top-p (p=0.9)          -> [('模型', 0.5741), ('模型化', 0.3482), ('机器', 0.0777), ('学习', 0.0), ('深入', 0.0)]
top-p 保留的候选: ['模型', '模型化', '机器']

```

T 从 0.2 变到 2.0，首选词的独占概率从 0.9241 掉到 0.3622：低温度下模型几乎总选「模型」，高温度下「深入」「浅出」这类词也有 6% 以上的概率被选中。这正是「同一模型、不同性格」的来源。

采样参数对照（Ollama Modelfile 中的参数名与默认值，按官方文档）：

| 参数 | 作用 | 官方默认值 | 工程建议 |
|---|---|---|---|
| temperature | 缩放 logits，控制随机性 | 0.8 | 事实问答 0-0.3；创作 0.7-1.0；代码 0-0.2 |
| top_k | 只保留前 k 个候选 | 40 | 与 top_p 二选一或用小 k |
| top_p | 核采样累积概率阈值 | 0.9 | 比 top_k 更自适应，通常优先调它 |
| min_p | 候选项概率相对最高项的最小比例 | 0.0 | 想更严格时可用 0.05 左右 |
| repeat_penalty | 重复惩罚强度 | 1.0（关闭） | 出现复读时设 1.1-1.3 |
| num_predict | 最多生成多少 token | -1（不限） | 按业务限制上限控制成本 |
| seed | 随机种子 | 0 | 需要可复现输出时必须固定 |

```text
采样要点：
1. temperature=0 用于确定性与可复现场景，但会牺牲多样性并可能陷入局部重复
2. 结构化输出（JSON）场景应把温度调到 0-0.2 并配合 JSON Schema 约束
3. top-p 与 top-k 同时开启时先截 top-k 再截 top-p，顺序不同结果不同
4. 采样只改变「选哪个 token」，不改变模型的概率分布本身，无法修正知识错误
5. 上生产前固定 seed + 采样参数，否则同样的输入无法复现同样的输出
```

## 微调与参数高效微调 LoRA

预训练模型要变成「业务上可用」，还要经过微调与对齐。全量微调（Full Fine-tuning）更新全部参数，效果好但显存需求约为「参数量 × 16 字节」量级（fp32 权重 + 梯度 + 优化器状态），7B 模型就需要上百 GB，单卡不可行。LoRA（Low-Rank Adaptation）的思路是不动原权重，在注意力投影矩阵旁挂两个小矩阵 A、B，训练时只更新它们，把可训练参数降到千分之一量级。

```python
import numpy as np

# LoRA 参数量：原始权重 W (d x d) 冻结，只训 A (d x r) 与 B (r x d)
d, r = 4096, 8
full = d * d
lora = 2 * d * r
print("一个 4096x4096 的注意力投影矩阵：全量微调 %d 参数" % full)
print("LoRA rank=%d：A(%dx%d) + B(%dx%d) = %d 参数，占 %.3f%%"
      % (r, d, r, r, d, lora, 100 * lora / full))

# 演示低秩更新的效果：W + B@A 相对 W 的扰动幅度
rng = np.random.default_rng(0)
W = rng.normal(scale=0.02, size=(64, 64))         # 模拟冻结的预训练权重
A = rng.normal(scale=0.01, size=(64, r))
B = np.zeros((r, 64))                             # 初始化 B 为 0 => 训练开始时 ΔW = 0
print("训练开始时 ΔW 的范数 = %.6f（B 初始化为 0，保证起点与预训练模型完全一致）" % np.linalg.norm(B @ A))
B = rng.normal(scale=0.01, size=(r, 64))
print("训练若干步后 ΔW 的范数 = %.6f（只更新了 %d 个参数就改变了输出）"
      % (np.linalg.norm(B @ A), lora))
```

真实输出（本机执行）：

LoRA rank=8：A(4096x8) + B(8x4096) = 65536 参数，占 0.391%

## RLHF 与 DPO

SFT 只能模仿示范数据，学不到「哪个回答更好」这种相对偏好。RLHF（Reinforcement Learning from Human Feedback）用三阶段解决：先 SFT，再用人工偏好数据训一个奖励模型，最后用 PPO 在奖励模型指引下优化策略，同时用 KL 约束避免跑偏。流程复杂、训练不稳定，因此出现了直接偏好优化 DPO：它证明「带 KL 约束的奖励最大化问题」存在闭式最优解，于是可以把奖励模型消掉，直接用偏好对做二分类式的损失优化，省掉奖励模型与在线采样。

```python
import numpy as np

def dpo_loss(logp_chosen, logp_rejected, logp_ref_chosen, logp_ref_rejected, beta=0.1):
    """β 控制偏离参考模型的惩罚强度；参考模型 = SFT 之后的模型（冻结）。"""
    margin = beta * ((logp_chosen - logp_ref_chosen) - (logp_rejected - logp_ref_rejected))
    return -np.log(1.0 / (1.0 + np.exp(-margin))), margin

# 三个偏好样本：chosen 是人工选中的更好回答，rejected 是较差的
cases = [(-1.0, -3.0, -1.2, -2.9, 0.1),      # 模型明显偏好 chosen
         (-2.0, -2.05, -2.0, -2.0, 0.1),     # 模型几乎不区分，接近 ln2
         (-3.0, -1.0, -1.0, -1.0, 0.1)]      # 模型偏好错了，需要被推
for lc, lr_, rc, rr, beta in cases:
    loss, margin = dpo_loss(lc, lr_, rc, rr, beta)
    print("chosen=%.2f rejected=%.2f ref=(%.2f, %.2f) -> 对数比 (lc-rc)-(lr-rr) = %+.2f  margin %+.3f  DPO loss %.4f"
          % (lc, lr_, rc, rr, (lc - rc) - (lr_ - rr), margin, loss))
print("β=0.1 会压小 margin；参考模型已偏好 chosen 时 margin 接近 0，loss 趋近 ln2 = %.4f" % np.log(2))
print("第三个用例里 chosen 的得分比 rejected 差，margin 为负、loss 大于 ln2，训练就是把它推回正方向")
```

对齐方法对照：

| 方法 | 需要什么数据 | 训练成本 | 稳定性 | 适用场景 |
|---|---|---|---|---|
| SFT | 指令-回答对 | 中 | 高 | 教格式、领域适配、第一步对齐 |
| RLHF + PPO | 偏好对 + 奖励模型 + 在线采样 | 最高（4 个模型同时驻留显存） | 低，需大量调参 | 需要极强对齐、有充足算力 |
| DPO | 只需偏好对 | 低（无奖励模型、无在线采样） | 高 | 主流选择，性价比最高 |
| 拒绝采样微调 | 偏好数据 + 候选筛选 | 中 | 高 | 用最强模型的输出蒸馏弱模型 |

```text
对齐要点：
1. 顺序固定：预训练 → SFT → 偏好对齐（RLHF 或 DPO），跳步会事倍功半
2. SFT 数据量不用大（几万条高质量即可），偏好数据质量决定对齐上限
3. DPO 的 β 控制「偏离参考模型」的程度：太小会丢能力，太大会学不动
4. 对齐数据要标注一致：标注者之间矛盾会让模型学到「和事佬」式的模糊回答
5. 对齐后的模型可能出现「过度安全」拒答，需要保留一部分能力回归评测集监控
```

## 幻觉与知识截止

幻觉（hallucination）指模型生成与事实不符但表述流畅的内容，根源是训练目标是「预测最像的 token」而不是「保证为真」——当真实知识缺失时，模型会用一个统计上合理的说法填坑。知识截止（knowledge cutoff）则是训练数据的硬边界：之后发生的事、私有数据、内部系统状态，模型根本无从知道。这两个问题都不能靠「调温度」或「加提示」根治，工程上的解法是「让模型少凭记忆说话」：检索增强（RAG）、工具调用、结构化约束、要求带引用、对不可核实内容显式声明不确定。

```python
# 可验证性路由：按「知识来源」决定回答策略，而不是一律让模型自由发挥

          ("本产品保修期是 36 个月", "内部知识库", "private"),
          ("某模型在 2026 年 5 月发布的参数规模", "训练截止后的事件", "post-cutoff")]

def route(kind):
    return {"stable": "直接回答，可用常识校验",
            "private": "必须检索内部知识库（RAG），回答附出处",
            "post-cutoff": "必须工具调用/联网检索；拿不到就明确说不知道"}[kind]

for text, source, kind in claims:
    print("  %-38s 来源:%-10s -> %s" % (text, source, route(kind)))
print()
print("幻觉排查顺序：1) 是否超出知识截止  2) 是否给了检索上下文  3) 采样是否过热（温度/重复惩罚）")
print("                          4) 是否要求模型给出处  5) 是否有自一致性校验（多次采样比对）")
```

## 应用场景实战

### 场景一：实现一个可复用的可控采样服务（温度 / top-k / top-p / 重复惩罚）

线上服务的输出稳定性很多时候不是模型问题而是采样配置问题。这个场景把采样逻辑封装成一个可复用类，用一个字符级马尔可夫语言模型提供 logits（接口与真实 LLM 的 logits 完全一致），然后对比四种配置下的生成结果与概率分布，并说明如何接入 Ollama 的真实 logprobs。

```python
# 仅依赖 numpy 与标准库
import numpy as np
from collections import defaultdict, Counter

corpus = ("机器学习是人工智能的一个分支。机器学习模型从数据中学习规律，"
          "数据越多，模型越好。大语言模型是深度学习模型的一种，"
          "它通过预测下一个词来学习语言规律。")
chars = sorted(set(corpus))
stoi = {c: i for i, c in enumerate(chars)}
itos = {i: c for c, i in stoi.items()}
V = len(chars)


class CharLM:
    """字符级一阶马尔可夫语言模型：用 log 概率当 logits，替代真实 LLM 的输出层。"""

    def __init__(self, text):
        self.bigram = defaultdict(Counter)
        for a, b in zip(text, text[1:]):
            self.bigram[a][b] += 1

    def logits(self, context):
        counts = self.bigram.get(context[-1], Counter())
        vec = np.full(V, 1e-6)                       # 拉普拉斯平滑，防止 log(0)
        for c, n in counts.items():
            vec[stoi[c]] = n
        return np.log(vec / vec.sum())


class Sampler:
    def __init__(self, temperature=1.0, top_k=0, top_p=1.0, repetition_penalty=1.0, seed=0):
        self.T, self.top_k, self.top_p = temperature, top_k, top_p
        self.penalty = repetition_penalty
        self.rng = np.random.default_rng(seed)

    def probs(self, logits, generated_ids=()):
        logits = np.array(logits, dtype=float)
        for i in set(generated_ids):                 # 重复惩罚：已出现过的 token 压低 logit
            logits[i] = logits[i] / self.penalty if logits[i] > 0 else logits[i] * self.penalty
        if self.top_k > 0:                           # top-k：只保留 logit 最高的 k 个
            kth = np.sort(logits)[-self.top_k]
            logits = np.where(logits < kth, -np.inf, logits)
        logits = logits / max(self.T, 1e-6)          # 温度缩放
        p = np.exp(logits - np.nanmax(logits))
        p = p / p.sum()
        if self.top_p < 1.0:                         # top-p：按累积概率自适应保留候选
            order = np.argsort(-p)
            keep = order[:np.searchsorted(np.cumsum(p[order]), self.top_p) + 1]
            p = np.where(np.isin(np.arange(V), keep), p, 0.0)
            p = p / p.sum()
        return p

    def __call__(self, logits, generated_ids=()):
        if self.T <= 1e-6:                           # T=0 等价于贪心
            return int(np.argmax(logits))
        return int(self.rng.choice(V, p=self.probs(logits, generated_ids)))


lm = CharLM(corpus)

def generate(prompt, sampler, n=20):
    ids = [stoi[c] for c in prompt]
    out = list(prompt)
    for _ in range(n):
        nxt = sampler(lm.logits("".join(out[-2:])), ids)
        ids.append(nxt)
        out.append(itos[nxt])
    return "".join(out)

configs = [("贪心 T=0", Sampler(temperature=0.0)),
           ("T=0.7 top-k=3", Sampler(temperature=0.7, top_k=3, seed=1)),
           ("T=1.0 top-p=0.9", Sampler(temperature=1.0, top_p=0.9, seed=2)),
           ("T=1.2 top-p=0.95 重复惩罚1.3",
            Sampler(temperature=1.2, top_p=0.95, repetition_penalty=1.3, seed=3))]
for name, s in configs:
    print("%-28s -> %s" % (name, generate("机器", s)))

print()
logits = lm.logits("习")
print("上下文「习」下一个字的概率分布（该字符有 4 种后继，频次 2:1:1:1）:")
for name, s in [("原始 (T=1, 无截断)", Sampler(temperature=1.0)),
                ("T=0.5", Sampler(temperature=0.5)),
                ("top-k=2", Sampler(temperature=1.0, top_k=2)),
                ("top-p=0.5", Sampler(temperature=1.0, top_p=0.5))]:
    p = s.probs(logits)
    top = np.argsort(-p)[:4]
    print("  %-20s 保留候选 %d 个  %s"
          % (name, int((p > 1e-4).sum()), "  ".join("%s:%.3f" % (itos[i], p[i]) for i in top)))
```

真实输出（本机执行）：

```text
贪心 T=0                       -> 机器学习模型从数据中学习模型从数据中学习模型
T=0.7 top-k=3                -> 机器学习是深度学习模型从数据中学习模型是人工
T=1.0 top-p=0.9              -> 机器学习语言规律。大语言规律。机器学习规律。
T=1.2 top-p=0.95 重复惩罚1.3     -> 机器学习语言模型是人工智能的一个词来学习规律

  原始 (T=1, 无截断)        保留候选 4 个  模:0.400  是:0.200  语:0.200  规:0.200
  T=0.5                保留候选 4 个  模:0.571  是:0.143  语:0.143  规:0.143
  top-k=2              保留候选 4 个  模:0.400  是:0.200  语:0.200  规:0.200
  top-p=0.5            保留候选 2 个  模:0.667  是:0.333  。:0.000  一:0.000
```

三点值得注意：贪心解码陷入了「模型从数据中学习模型从数据中学习模型」的复读循环，这正是低温度下最常见的失败模式；top-k=2 意外保留了 4 个候选，因为第 2 名有 3 个 token 的 logit 完全相同，按值截断会把并列项一起保留（实现里要做 tie-break）；top-p=0.5 自适应地只留 2 个候选，把概率重新归一化到 0.667 / 0.333。接入真实模型时，把 `lm.logits(...)` 换成从服务端拿到的那一行 logits 即可——Ollama 可以通过 `logprobs=true, top_logprobs=5` 取回 top-5 候选的概率。

### 场景二：训练一个 BPE 分词器并量化「词表大小 vs 压缩率」的取舍

词表大小是 LLM 设计里最容易被忽略的取舍：词表越大，同样文本切出的 token 越少（省显存、省推理成本），但嵌入矩阵与输出层参数越大，罕见 token 也学不充分。用同一个 BPE 实现训练不同合并次数的分词器，直接量化这个曲线。

```python
# 仅依赖标准库
from collections import Counter

corpus = ("机器学习是人工智能的一个分支，机器学习模型需要数据，"
          "数据越多模型越好，语言模型通过预测下一个词来学习语言规律。")


def train_bpe(text, num_merges):
    words = Counter()
    for w in text.replace("，", " ，").replace("。", " 。").split():
        words[w] += 1
    splits = {w: list(w) for w in words}
    vocab = Counter()
    for w, f in words.items():
        for c in splits[w]:
            vocab[c] += f
    merges = []
    for _ in range(num_merges):
        pairs = Counter()
        for w, f in words.items():
            s = splits[w]
            for a, b in zip(s, s[1:]):
                pairs[(a, b)] += f
        if not pairs:
            break
        (a, b), cnt = pairs.most_common(1)[0]
        if cnt < 2:
            break
        for w, f in words.items():
            s, out, i = splits[w], [], 0
            while i < len(s):
                if i < len(s) - 1 and s[i] == a and s[i + 1] == b:
                    out.append(a + b); i += 2
                else:
                    out.append(s[i]); i += 1
            splits[w] = out
        vocab[a + b] += cnt
        merges.append((a, b, a + b, cnt))
    return vocab, splits, merges


def encode(word, merges):
    """推理：按训练得到的合并顺序，对新文本做贪心合并。"""
    tokens = list(word)
    for a, b, _new, _ in merges:
        out, i = [], 0
        while i < len(tokens):
            if i < len(tokens) - 1 and tokens[i] == a and tokens[i + 1] == b:
                out.append(a + b); i += 2
            else:
                out.append(tokens[i]); i += 1
        tokens = out
    return tokens


print("词表大小  merge 次数  字符/token  示例编码（机器学习需要数据）")
for n in (0, 5, 20, 60):
    vocab, splits, merges = train_bpe(corpus, n)
    s = "机器学习需要数据"
    toks = encode(s, merges)
    ratio = sum(len(t) for t in toks) / len(toks)      # 每个 token 平均覆盖多少字符
    print("%6d      %4d       %.2f        %s" % (len(vocab), len(merges), ratio, toks))
print("（merge 次数是实际执行数：最高频次低于 2 时算法提前停止）")

vocab, splits, merges = train_bpe(corpus, 40)
print("\n最后 7 条合并规则:")
for a, b, new, cnt in merges[-7:]:
    print("   %-6s + %-6s -> %-8s (频次 %d)" % (a, b, new, cnt))
print("\n编码未见过的新词「模型学习」:", encode("模型学习", merges))
```

真实输出（本机执行）：

```text
词表大小  merge 次数  字符/token  示例编码（机器学习需要数据）
    36         0       1.00        ['机', '器', '学', '习', '需', '要', '数', '据']
    41         5       1.60        ['机器学习', '需', '要', '数', '据']
    43         7       2.00        ['机器学习', '需', '要', '数据']
    43         7       2.00        ['机器学习', '需', '要', '数据']
（merge 次数是实际执行数：最高频次低于 2 时算法提前停止）

最后 7 条合并规则:
   学      + 习      -> 学习       (频次 3)
   模      + 型      -> 模型       (频次 3)
   机      + 器      -> 机器       (频次 2)
   机器     + 学习     -> 机器学习     (频次 2)
   一      + 个      -> 一个       (频次 2)
   数      + 据      -> 数据       (频次 2)

```

只做了 7 次合并，「机器学习需要数据」就把 8 个字符压成 4 个 token：字符/token 从 1.00 升到 2.00，等于同样内容省掉一半的序列长度。未见过的新词「模型学习」也能正确切分成 `['模型', '学习']`——两个子词都在词表里，说明 BPE 的组合规则具备泛化能力。真实模型里这个曲线会一直延伸：词表从 32K 加到 128K，中文压缩率提升明显，但嵌入层参数量（V × d_model）也同步变大，需要按显存与推理成本取舍。

## 最佳实践与踩坑记录

### 最佳实践

1. 理解 LLM 的一切都从「下一个 token 的概率分布」出发：任何输出问题先问「这个位置的分布是什么样的」
2. 生产环境固定采样参数与 seed，把 temperature/top-p/num_predict 写进配置而不是散落在调用里
3. 事实性任务把 temperature 设到 0-0.3，结构化输出再加 JSON Schema 约束，别指望模型自觉
4. 需要私有知识或时效信息时走 RAG/工具调用，不要指望微调补知识
5. 微调优先 LoRA：先跑通小数据链路（几百条）再扩规模，并保留一个不微调的基线对比
6. 偏好对齐用 DPO 起步，只有在对齐质量不足且有足够算力时才上 PPO 系 RLHF
7. 上线前量化 token 成本：中文 token 效率低于英文，按 token 计费时差价可达一倍
8. 记录每次实验的模型版本、数据版本、采样参数与评测结果，保证可复现

### 踩坑记录

```text
坑 1：把知识截止后的事实直接问模型，得到一段编造得很像的答案
结论：模型输出具体但错误的信息（如保修期、最新事件），被写进对外文档。
原因：模型只在训练语料的时间边界内学习，缺失时会用统计上合理的说法填充（幻觉）。
解法：时效性与私有知识一律走 RAG/工具调用；要求回答附原文引用；对不可核实的内容要求显式说「不确定」。

坑 2：为了「稳定」把 temperature 设成 0，结果模型陷入复读循环
结论：输出出现「机器学习模型从数据中学习模型从数据中学习」这类无意义重复。
原因：贪心解码每步都选概率最高的 token，一旦落入高概率循环就再也出不来。
解法：温度设 0.1-0.3 而非 0；加重复惩罚（repeat_penalty 1.1-1.3）；或用 min-p/top-p 保留少量多样性。

坑 3：以为微调能补私有知识，花两周训完发现回答还是错的
结论：微调后模型语气对了，但事实仍然错。
原因：微调改变的是表达方式与格式偏好，注入新事实需要的样本量和多样性远超实际可得数据。
解法：知识走 RAG，微调只用来教格式、术语和风格；两者组合使用。

坑 4：LoRA 的 target_modules 写成了别的框架的层名，训练「成功」但效果为零
结论：loss 正常下降，评测毫无提升，甚至略有下降。
原因：target_modules 没匹配到任何真实子模块，PEFT 静默跳过（或只挂了很少的层）。
解法：先用 `print([n for n, _ in model.named_modules()])` 确认层名（LLaMA 系 q_proj/k_proj/v_proj/o_proj），再核对可训练参数数量与预期一致。

坑 5：把困惑度当成「模型质量」直接横向比较不同模型
结论：误判模型能力，选了困惑度更低但任务表现更差的模型。
原因：困惑度依赖词表与分词方式，不同分词器的数值不可比；且预训练困惑度不等于下游任务能力。
解法：只在同词表、同数据切分的模型之间比困惑度；对外一律用任务级评测集与人工评估。
```

## 概述

人工智能（Artificial Intelligence，AI）是让机器表现出「感知、推理、学习、决策、生成」这类通常需要人类智能的行为的学科总称；机器学习（Machine Learning，ML）是实现 AI 的主流方法，深度学习（Deep Learning，DL）是机器学习中基于多层神经网络的一类具体技术。本主题不写公式推导，只回答四个问题：这几个概念怎么嵌套、AI 为什么会被说成「三起三落」、研究路线上分几支、当下产业里 AI 被用在哪些地方。

```text
读完本篇应建立的地图：
1. AI ⊃ 机器学习 ⊃ 深度学习 ⊃ 大语言模型，嵌套关系不是并列关系
2. 三次浪潮的驱动力是「算力 + 数据 + 算法」三者同时到位，缺一个就回落
3. 符号主义管规则、连接主义管拟合、行为主义管交互，今天的工程是三者混用
4. 应用版图按「输入输出模态」切分，比按行业切分更容易看清技术选型
5. AIGC 的关键变化是模型从「判别」转向「生成」，从「一个答案」转向「一个分布」
```

## AI 机器学习与深度学习的关系

三者的关系是包含而不是并列。AI 是目标（让机器智能），机器学习是实现目标的一类方法（不显式编程规则，而是从数据里拟合规律），深度学习是实现机器学习的一类模型（用多层神经网络自动学特征），大语言模型则是深度学习在文本模态上的一种具体形态。这个嵌套关系决定了学习顺序：先理解「从数据中学习」这件事本身，再往下钻网络结构和训练细节。

用一个最小例子看「机器学习」到底是什么：同一份鸢尾花数据，人类写规则要穷举花瓣长度阈值，而模型只从样本和标签里自己找边界。

```python
# 依赖：pip install scikit-learn（本机实测 numpy 2.5.4 / scikit-learn 1.9.1）
from sklearn.datasets import load_iris
from sklearn.model_selection import train_test_split
from sklearn.tree import DecisionTreeClassifier
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import accuracy_score

X, y = load_iris(return_X_y=True)                       # 150 条样本，4 个特征，3 个类别
Xtr, Xte, ytr, yte = train_test_split(X, y, test_size=0.3, random_state=42, stratify=y)

tree = DecisionTreeClassifier(max_depth=3, random_state=42).fit(Xtr, ytr)
lr = LogisticRegression(max_iter=1000).fit(Xtr, ytr)
print("决策树 训练集准确率 %.4f 测试集准确率 %.4f" % (
    accuracy_score(ytr, tree.predict(Xtr)), accuracy_score(yte, tree.predict(Xte))))
print("逻辑回归 训练集准确率 %.4f 测试集准确率 %.4f" % (
    accuracy_score(ytr, lr.predict(Xtr)), accuracy_score(yte, lr.predict(Xte))))
```

真实输出（本机执行）：

```text
决策树 训练集准确率 0.9810 测试集准确率 0.9778
逻辑回归 训练集准确率 0.9714 测试集准确率 0.9333
```

程序里没有一行「如果花瓣长度大于多少就判为某类」的规则，边界完全来自数据。这就是机器学习相对符号规则的本质区别。

```text
概念嵌套与判定标准：
1. AI —— 学科总称，目标是让机器完成需要智能的任务，含规则系统、搜索、规划等
2. 机器学习 —— AI 的子集，核心是「有数据、有目标函数、有优化过程」
3. 深度学习 —— 机器学习的子集，用多层非线性变换自动提取特征，取代人工特征工程
4. 大语言模型 —— 深度学习中基于 Transformer 的自回归语言模型，参数规模达十亿级以上
5. 判据 —— 如果一个系统没有从数据中学到参数，它就不是机器学习，只是普通程序
```

## 人工智能发展的三次浪潮

AI 的历史是「技术乐观 → 承诺落空 → 经费收缩 → 新范式出现」的循环，习惯上按三次浪潮划分。每次浪潮的起落都由三件事共同决定：算法有没有新范式、算力够不够、数据够不够。三次浪潮之间夹着两次 AI 低谷（AI Winter，指经费与研究热度大幅收缩的时期）。

```python
# 三次浪潮时间线（关键节点均可查证：1956 达特茅斯会议、1986 反向传播论文、
# 2006 深度信念网络、2012 AlexNet、2017 Transformer、2022 ChatGPT）
waves = [
    (1956, 1974, "第一次浪潮", "符号主义 / 逻辑推理 / 感知机", "数据与算力不足，1974-1980 第一次低谷"),
    (1980, 1987, "第二次浪潮", "专家系统 / 反向传播重新流行", "知识获取瓶颈、硬件昂贵，1987-1993 第二次低谷"),
    (2006, 0, "第三次浪潮", "深度学习 / 大数据 / GPU", "2012 AlexNet 起产业化；2020 后大模型常被单列"),
]
for start, end, name, tech, fall in waves:
    span = "%d - %s" % (start, end if end else "至今")
    print("%-6s %-12s 核心技术：%-28s 回落：%s" % (name, span, tech, fall))
```

真实输出（本机执行）：

```text
第一次浪潮  1956 - 1974  核心技术：符号主义 / 逻辑推理 / 感知机            回落：算力与数据不足，1974-1980 第一次低谷
第二次浪潮  1980 - 1987  核心技术：专家系统 / 反向传播重新流行              回落：知识获取瓶颈、硬件昂贵，1987-1993 第二次低谷
第三次浪潮  2006 - 至今    核心技术：深度学习 / 大数据 / GPU             回落：2012 AlexNet 起产业化；2020 后大模型常被单独列为一波
```

三次浪潮对照表：

| 浪潮 | 时间 | 代表技术 | 为什么起来 | 为什么回落 |
|---|---|---|---|---|
| 第一次 | 1956-1974 | 逻辑理论家、搜索推理、感知机 | 计算机刚出现，符号推理能解数学题和博弈 | 组合爆炸、算力不足；1969 年《Perceptrons》指出单层感知机不能解 XOR |
| 第二次 | 1980-1987 | 专家系统（MYCIN、XCON）、反向传播 | 企业愿意为规则库付费，反向传播让多层网络可训练 | 知识库靠人工录入、维护成本高；专用 AI 硬件市场崩塌 |
| 第三次 | 2006-至今 | 深度信念网络、AlexNet、Transformer、LLM | GPU 算力、互联网级数据、深度结构三者齐备 | 尚未回落，但能耗、数据墙、评测与合规压力开始显现 |

关于「第几次」的划分本身也有分歧：部分资料把 2020 年后的大模型与强化学习时代单独列为第四波浪潮。这里沿用最通行的三次划分，把 LLM 时代视为第三次浪潮的延续。

```text
三次浪潮给工程实践的直接结论：
1. 单靠算法创新不足以撑起浪潮，算力和数据是同等前提
2. 每次低谷都淘汰了「能力被夸大」的宣传，保留了能落地的部分
3. 当下第三次浪潮的瓶颈已从算法转向数据质量、推理成本与合规
4. 判断一个 AI 项目是否可信，先看它有没有跨过「数据 + 算力 + 可评测」三道坎
```

## 三大流派符号主义连接主义与行为主义

AI 研究史上有三条方法论主线。符号主义（Symbolism）认为智能是符号操作与逻辑推理，知识用规则显式表达；连接主义（Connectionism）认为智能来自大量简单单元的连接权重，知识分布在参数里；行为主义（Behaviourism / 控制论路线）认为智能体现在与环境的交互中，通过感知-行动循环和奖励学习。今天的工业系统往往是三者混用：LLM 是连接主义的，Agent 的工具调用与规则校验是符号主义的，基于人类反馈的对齐是行为主义的。

用一个例子区分：判断「是否成年」——符号主义直接写规则，连接主义从样本学权重，行为主义则通过与环境的交互（做错了被纠正）调整策略。

```python
import numpy as np

# 符号主义：人工写规则，可解释、无需数据
def is_adult_symbolic(age):
    return age >= 18

print("符号规则 is_adult(20) =", is_adult_symbolic(20), " is_adult(16) =", is_adult_symbolic(16))

# 连接主义：从标注样本里学权重（这里用单层感知机学 AND 门）
X = np.array([[0, 0], [0, 1], [1, 0], [1, 1]], dtype=float)
y = np.array([0, 0, 0, 1], dtype=float)
w, b, lr = np.zeros(2), 0.0, 0.1
for epoch in range(50):
    for xi, yi in zip(X, y):
        pred = 1.0 if (xi @ w + b) > 0 else 0.0
        err = yi - pred
        w += lr * err * xi
        b += lr * err
print("学习到的权重 w =", w, " 偏置 b = %.1f" % b)
print("感知机预测 AND 真值表 =", [int(xi @ w + b > 0) for xi in X], " 期望 =", y.astype(int).tolist())
```

真实输出（本机执行）：

```text
符号规则 is_adult(20) = True  is_adult(16) = False
学习到的权重 w = [0.2 0.1]  偏置 b = -0.2
感知机预测 AND 真值表 = [0, 0, 0, 1]  期望 = [0, 0, 0, 1]
```

单层感知机只能划分线性可分问题。把目标换成 XOR，同一段代码就学不会——这正是 1969 年《Perceptrons》指出的局限，也是连接主义第一次遇冷的技术原因；解法是加隐层，也就是后面的深度学习。

```text
三大流派对照：
1. 符号主义 —— 知识用规则/逻辑/知识图谱显式表达；可解释可审计，但无法覆盖模糊与感知问题
2. 连接主义 —— 知识分布在神经网络权重里；能拟合高维非线性，但黑箱、依赖数据与算力
3. 行为主义 —— 智能来自与环境的交互和奖励信号；对应强化学习，适合决策与控制类问题
4. 工程现实 —— 三者混用：LLM 生成（连接）+ 工具与规则校验（符号）+ 用户反馈微调（行为）
5. 选型口诀 —— 规则明确且要审计用符号，模式识别与生成用连接，序列决策用强化学习
```

## AI 应用版图

按「输入输出模态」切分应用版图，比按行业切分更容易看清技术选型。同一行业里，文本分类、图像检测、语音转写用的完全是不同模型族。下面对齐任务形态与典型模型，再用同一份数据演示分类、回归、聚类三种任务框架的差别。

| 模态 | 任务形态 | 典型任务 | 代表模型族 |
|---|---|---|---|
| 文本 | 分类 / 抽取 / 生成 | 情感分析、信息抽取、问答、摘要 | BERT 系、GPT 系、LLaMA 系 |
| 图像 | 分类 / 检测 / 分割 / 生成 | 质检缺陷识别、人脸识别、医学影像 | ResNet、YOLO、SAM、Stable Diffusion |
| 语音 | 识别 / 合成 | 语音转写、会议记录、语音助手 | Whisper、主流 TTS 模型 |
| 表格 | 分类 / 回归 / 聚类 | 风控评分、销量预测、用户分群 | XGBoost、LightGBM、逻辑回归 |
| 序列决策 | 强化学习 | 推荐排序、调度、机器人控制、博弈 | DQN、PPO、离线强化学习 |

```python
from sklearn.datasets import make_classification, make_regression, load_iris
from sklearn.linear_model import LogisticRegression, LinearRegression
from sklearn.cluster import KMeans
from sklearn.model_selection import train_test_split
from sklearn.metrics import accuracy_score, r2_score
import numpy as np

Xc, yc = make_classification(n_samples=800, n_features=8, random_state=0)
Xtr, Xte, ytr, yte = train_test_split(Xc, yc, test_size=0.3, random_state=0)
print("分类任务  LogisticRegression 准确率 %.4f" % accuracy_score(yte, LogisticRegression(max_iter=1000).fit(Xtr, ytr).predict(Xte)))

Xr, yr = make_regression(n_samples=800, n_features=8, noise=10, random_state=0)
Xtr, Xte, ytr, yte = train_test_split(Xr, yr, test_size=0.3, random_state=0)
print("回归任务  LinearRegression R2 %.4f" % r2_score(yte, LinearRegression().fit(Xtr, ytr).predict(Xte)))

Xi, _ = load_iris(return_X_y=True)
km = KMeans(n_clusters=3, n_init=10, random_state=0).fit(Xi)
print("聚类任务  KMeans 各簇样本数 %s" % np.bincount(km.labels_).tolist())
```

真实输出（本机执行）：

```text
分类任务  LogisticRegression 准确率 0.8958
回归任务  LinearRegression R2 0.9973
聚类任务  KMeans 各簇样本数 [62, 50, 38]
```

同一张表格数据，标签存在与否决定任务类型：有标签做监督（分类/回归），无标签做无监督（聚类/降维）。这三个框架覆盖了产业里绝大多数离线模型场景。

```text
应用版图选型要点：
1. 先确定输入模态，再确定有没有标签，最后才选模型族
2. 有大量标注 + 高维感知输入（图像/语音/文本）才值得上深度学习
3. 结构化表格数据上，梯度提升树（XGBoost/LightGBM）长期强于神经网络，别硬套深度模型
4. 大模型的优势是零样本泛化与多任务统一，代价是推理成本与不可控输出
5. 生产系统通常是「小模型做筛选 + 大模型做解释与生成」的混合架构
```

## AIGC 与生成式 AI

AIGC（AI Generated Content，生成式 AI）指用模型直接产出文本、图像、音频、视频、代码等内容。技术上的关键跃迁是模型目标从「判别」变成「生成」：判别式模型学条件概率 P(标签|输入)，回答「这是什么」；生成式模型学数据分布，回答「下一个是什么」或「从分布里采样得到什么」。大语言模型的训练目标就是「给定前文预测下一个 token」，所以它天然是一个生成模型。

先看生成式模型的直觉——一个字符级二元模型（只看前一个字符决定下一个字符）就能拼出像样但明显重复的句子，这正是 LLM 的退化版：

```python
from collections import defaultdict
import numpy as np

corpus = "机器学习让计算机从数据中学习规律机器学习模型可以生成新的数据数据越多模型越好"
bigram = defaultdict(list)
for a, b in zip(corpus, corpus[1:]):
    bigram[a].append(b)                       # 统计每个字符后面接什么
rng = np.random.default_rng(0)

def generate(start, n=18):
    out = [start]
    for _ in range(n):
        cands = bigram.get(out[-1])
        if not cands:
            break
        out.append(rng.choice(cands))         # 按观测到的后继字符采样
    return "".join(out)

print("生成 1:", generate("机", 20))
print("生成 2:", generate("数", 20))
```

真实输出（本机执行）：

```text
生成 1: 机器学习让计算机器学习让计算机器学习模型越
生成 2: 数据越好
```

真实 AIGC 服务一般通过 HTTP 接口调用。以本地部署的 Ollama 为例，REST 接口是 `POST /api/generate`，字段 `model` 与 `prompt` 必填，`stream` 默认 `true`；`options` 里控制生成行为（按官方 Modelfile 文档，常用参数有 `temperature` 默认 0.8、`top_k` 默认 40、`top_p` 默认 0.9、`num_predict` 默认 -1、`num_ctx` 默认 2048）。

```shell
# 前提：本机已安装并启动 ollama（ollama serve），已拉取模型 ollama pull llama3.2
# 生成接口：非流式调用
curl http://localhost:11434/api/generate -d '{
  "model": "llama3.2",
  "prompt": "用一句话解释什么是生成式 AI",
  "stream": false,
  "options": {"temperature": 0.3, "num_predict": 128}
}'

# 查看本地模型清单
ollama list

# 用 Modelfile 固化一套生成参数，做成可复用的模型
cat > Modelfile <<'EOF'
FROM llama3.2
PARAMETER temperature 0.7       # 越低越确定，越高越发散
PARAMETER num_ctx 8192          # 上下文窗口大小
PARAMETER top_p 0.9             # 核采样累积概率
SYSTEM 你是严谨的技术写作助手，回答只讲事实，不确定就说明不确定。
EOF
ollama create writer -f ./Modelfile
ollama run writer
```

```python
# 用 requests 调用，便于集成进业务系统
import requests

resp = requests.post("http://localhost:11434/api/generate", json={
    "model": "writer",
    "prompt": "把这句话改写得更简洁：由于性能方面存在一些问题，因此我们决定对该模块进行重构。",
    "stream": False,
    "options": {"temperature": 0.2},
}, timeout=60)
print(resp.json()["response"])
```

上面这段需要在有 Ollama 服务的机器上运行；本篇其余示例均可离线跑通。

```text
AIGC 要点与边界：
1. 生成式 vs 判别式 —— 前者建模数据分布、输出多样；后者建模决策边界、输出确定
2. 主流模态 —— 文本（LLM）、图像（扩散模型）、语音（TTS）、视频（扩散 + 时序）、代码（LLM）
3. 可控性 —— 靠提示、温度与 top-p、结构化输出（JSON Schema）、工具调用与后置校验来约束
4. 成本结构 —— 训练一次、推理百万次；token 计费与显存占用才是生产的主要开销
5. 边界 —— 模型没有权威知识源，训练截止后的事件与私有数据必须靠检索或工具补齐
```

## 应用场景实战

### 场景一：用统一的 sklearn 流水线交付「客户流失预警」模型

真实工程里交付一个模型不是跑通一次 fit，而是「切分数据 → 构建流水线 → 训练 → 用业务指标验收 → 保存模型」。下面用一个不均衡的二分类场景走完整流程，重点是评估指标的选择与阈值调整，而不是算法本身的复杂度。

```python
# pip install scikit-learn joblib
import numpy as np
from sklearn.datasets import make_classification
from sklearn.model_selection import train_test_split, cross_val_score
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import (confusion_matrix, roc_auc_score,
                             precision_score, recall_score)
import joblib

# 1. 造一份不均衡数据：约 8% 的流失客户
X, y = make_classification(n_samples=5000, n_features=20, n_informative=6,
                           weights=[0.92, 0.08], random_state=42)
Xtr, Xte, ytr, yte = train_test_split(X, y, test_size=0.3, random_state=42, stratify=y)

# 2. 流水线：标准化 + 逻辑回归（class_weight 处理不平衡）
pipe = make_pipeline(StandardScaler(),
                     LogisticRegression(max_iter=2000, class_weight="balanced"))
pipe.fit(Xtr, ytr)

# 3. 交叉验证看稳定性，别只看单次划分
cv = cross_val_score(pipe, Xtr, ytr, cv=5, scoring="roc_auc")
print("5 折 CV roc_auc %.4f ± %.4f" % (cv.mean(), cv.std()))

# 4. 业务默认阈值 0.5 往往不合适，按业务成本调
prob = pipe.predict_proba(Xte)[:, 1]
print("测试集 roc_auc %.4f" % roc_auc_score(yte, prob))
for thr in (0.5, 0.3, 0.2):
    pred = (prob >= thr).astype(int)
    print("阈值 %.1f  precision %.3f  recall %.3f  混淆矩阵 %s"
          % (thr, precision_score(yte, pred), recall_score(yte, pred),
             confusion_matrix(yte, pred).ravel().tolist()))

# 5. 落盘交付
joblib.dump(pipe, "churn_pipeline.joblib")
print("已保存 churn_pipeline.joblib")
```

注：混淆矩阵按 `[TN, FP, FN, TP]` 展平。这里 precision 偏低是因为 `class_weight="balanced"` 把预测概率整体抬高，0.5 这个默认阈值已经是很激进的经营点。把阈值从 0.5 降到 0.2，召回率从 0.768 升到 0.960，代价是误报从 337 涨到 783、精度降到 0.133。这个取舍必须由业务成本决定（拉回一个客户的收益 vs 一次误发优惠券的成本），不是算法问题；正确做法是按业务成本算出期望收益最高的工作点，再固定阈值上线。

### 场景二：接到「用 AI 做需求」时，先做技术选型而不是先写代码

真实工作中常见的情形是需求方只说「要智能一点」。这时正确的动作是先按模态和标签情况把需求翻译成任务类型，再决定用现成模型、微调还是自研。下面这段脚本把选型决策写成可执行的检查清单，输入需求描述输出技术路线。

```python
# 技术选型决策表：输入 = 需求特征，输出 = 推荐路线
requirements = [
    {"name": "合同关键条款抽取", "modality": "文本", "labeled": 200, "latency": "离线", "notes": "条款类型固定，需要引用原文"},
    {"name": "产线缺陷检测", "modality": "图像", "labeled": 3000, "latency": "实时", "notes": "缺陷样本少但标注质量高"},
    {"name": "客服工单自动回复", "modality": "文本", "labeled": 0, "latency": "在线", "notes": "知识在内部文档里，随时更新"},
    {"name": "门店销量预测", "modality": "表格", "labeled": 20000, "latency": "每日", "notes": "结构化时序数据"},
]

def route(r):
    if r["modality"] == "表格":
        return "梯度提升树（LightGBM/XGBoost）+ 特征工程，别上深度模型"
    if r["modality"] == "图像" and r["labeled"] >= 1000:
        return "预训练骨干网络（ResNet/YOLO）+ 迁移学习微调，必要时加数据增强"
    if r["modality"] == "文本" and r["labeled"] >= 100 and r["latency"] == "离线":
        return "小模型微调（BERT 系）+ 结构化解码，成本低且可控"
    if r["modality"] == "文本" and r["labeled"] == 0:
        return "通用 LLM + RAG 检索内部文档，先跑通再考虑微调"
    return "先做数据标注，缺标签就走无监督或零样本基线"

for r in requirements:
    print("%-18s 模态=%-4s 标注=%-6d 时延=%-4s -> %s"
          % (r["name"], r["modality"], r["labeled"], r["latency"], route(r)))
```

真实输出（本机执行）：

```text
合同关键条款抽取        模态=文本 标注=200    时延=离线 -> 小模型微调（BERT 系）+ 结构化解码，成本低且可控
产线缺陷检测            模态=图像 标注=3000   时延=实时 -> 预训练骨干网络（ResNet/YOLO）+ 迁移学习微调，必要时加数据增强
客服工单自动回复        模态=文本 标注=0      时延=在线 -> 通用 LLM + RAG 检索内部文档，先跑通再考虑微调
门店销量预测            模态=表格 标注=20000  时延=每日 -> 梯度提升树（LightGBM/XGBoost）+ 特征工程，别上深度模型
```

把这张表在需求评审阶段跑一遍，可以避免最常见的错误：给 2 万条表格数据硬上一套 Transformer，或者在没有标注的情况下承诺「训练一个专用模型」。

## 最佳实践与踩坑记录

### 最佳实践

1. 先确定任务形态（有没有标签、什么模态、什么时延），再选模型族；顺序反了必然返工
2. 结构化表格数据优先用梯度提升树，深度模型只在感知类模态上有明确优势
3. 任何 AI 需求都要先定义可量化的验收指标和基线（规则基线、零样本基线），否则无法判断项目成败
4. 用预训练模型 + 微调替代从零训练；只有数据规模和独特性足以支撑时才考虑预训练
5. 大模型场景默认走「通用模型 + 检索/工具」的路子，把知识更新放在外挂知识库而不是重新训练
6. 每个模型都要记录数据版本、超参数、评估结果与训练时间，保证可复现

### 踩坑记录

```text
坑 1：把「AI」当成一个模型，需求里同时塞进分类、生成、预测三件事
结论：项目延期，评估指标互相冲突，无法验收。
原因：不同任务形态的优化目标不同，共用一个模型必然妥协。
解法：把需求拆成独立任务，各自定义指标与模型，用编排层（工作流）串起来。

坑 2：样本极不均衡时只看准确率
结论：客户流失模型准确率 0.92 看着漂亮，实际一个流失客户都没预测出来。
原因：正例只占 8%，全部预测为负类就能拿到 0.92 的准确率。
解法：改用 precision/recall/F1 与 ROC-AUC，并按业务成本调整决策阈值。

坑 3：拿训练截止时间之后的事实问大模型，得到一本正经的错误答案
结论：模型给出看似合理的错误信息，被当成事实写进文档。
原因：大模型只知道自己训练语料里的内容，且生成目标是「像话」而非「真实」。
解法：需要时效性或私有知识时走 RAG 检索或工具调用，并保留原文引用；对不可核实的问题要求模型声明不确定。

坑 4：用「三次浪潮」的说法给项目背书，说「这次不一样」
结论：预算批下来，交付时发现模型能力达不到宣传口径。
原因：技术浪潮是宏观叙事，不能替代具体场景的可行性验证。
解法：立项时用最小可行实验（一周内的 PoC）验证数据是否够、指标能否达标，再谈规模化。
```

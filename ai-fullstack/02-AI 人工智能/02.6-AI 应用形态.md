## 概述

AI 应用形态指把模型能力包装成产品时选用的产品结构，目前主流有五类：对话式应用、RAG 知识问答、Agent 自动化、多模态生成应用、Copilot 式集成。形态决定架构：对话式应用的核心是会话状态与流式输出，RAG 的核心是检索质量与引用可信，Agent 的核心是工具权限与确定性兜底，多模态的核心是异步任务编排与成本控制，Copilot 的核心是低延迟与上下文局部性。

选形态的四个判据：交互粒度（人驱动的对话还是机器驱动的任务流）、确定性要求（能否容忍模型自由发挥）、延迟预算（首字节毫秒级还是分钟级）、数据边界（数据能否出内网）。同一业务往往同时存在多种形态，比如售后系统里既有客服对话，又有自动化的工单处置 Agent。

```text
五类形态的一句话定位：
1. 对话式应用 —— 人主导多轮交互，模型负责理解与表达
2. RAG 知识问答 —— 答案必须可溯源到企业内部资料，拒答比编造更可取
3. Agent 自动化 —— 模型参与决策与执行，靠工具权限与人工门槛兜底
4. 多模态应用 —— 输入输出扩展到图像/语音/视频，多是异步长任务
5. Copilot 式集成 —— 嵌进既有工作流，优先级是延迟与上下文相关性
```

## 对话式应用

对话式应用是最基础的形态：维护消息历史、流式返回增量文本、在上下文窗口里裁剪历史。三个工程要点决定体验：首字节延迟（TTFT，决定「打字机效果」是否跟手）、上下文成本（历史越长 token 越贵）、会话持久化（多端一致与服务端可恢复）。

历史管理不能简单按条数截断：要保留 system 消息、按最近优先保留、并预留输出 token 预算。生产用 tokenizer 精确计算，粗估只能用于压测。

```python
def est_tokens(text: str) -> int:
    """粗估：中文按 1 字 1 token，英文按 4 字符 1 token。生产请用对应模型的 tokenizer。"""
    cn = sum(1 for ch in text if "\u4e00" <= ch <= "\u9fff")
    return cn + (len(text) - cn) // 4 + 1


def trim_history(history: list[dict], budget: int, keep_recent: int = 4) -> list[dict]:
    """保留 system 消息与最近若干轮，总 token 不超过预算。"""
    system = [m for m in history if m["role"] == "system"]
    rest = [m for m in history if m["role"] != "system"]
    kept, used = [], sum(est_tokens(m["content"]) for m in system)
    for m in reversed(rest):                       # 从最近往回保留
        cost = est_tokens(m["content"])
        if kept and (used + cost > budget or len(kept) >= keep_recent):
            break
        kept.append(m)
        used += cost
    return system + list(reversed(kept))
```

本机实测（11 条消息 486 token 裁剪到 4 条 157 token）：

```text
=== 1. 对话历史裁剪 ===
  原始消息数=11 估算 tokens=486
  裁剪后消息数=4 估算 tokens=157
  保留的首条=system  最后一条=第9轮对话内容详情详情详...
```

流式输出用 SSE（`text/event-stream`）或 WebSocket：SSE 单向、实现简单、天然兼容 HTTP 网关，对话场景首选；WebSocket 适合需要客户端实时打断与双向音频的场景。流式下要处理三件事：增量拼接、客户端断连时取消上游请求（省钱）、以及错误在流中途发生时如何告知前端（不能只返回 HTTP 状态码）。

```python
import json
import time
from http.server import BaseHTTPRequestHandler, HTTPServer

CHUNKS = ["根据", "退款政策", "R-003", "，签收", "7 天内", "可全额退款", "。"]


class SSEHandler(BaseHTTPRequestHandler):
    def do_POST(self):
        self.rfile.read(int(self.headers.get("Content-Length", 0)))
        self.send_response(200)
        self.send_header("Content-Type", "text/event-stream")
        self.send_header("Cache-Control", "no-cache")
        self.end_headers()
        for i, c in enumerate(CHUNKS):
            self.wfile.write(f"data: {json.dumps({'delta': c, 'index': i}, ensure_ascii=False)}\n\n".encode())
            self.wfile.flush()
            time.sleep(0.05)
        self.wfile.write(b"data: [DONE]\n\n")
        self.wfile.flush()


HTTPServer(("127.0.0.1", 8765), SSEHandler).serve_forever()
```

本机实测（本地服务与客户端同机测量，仅体现链路形态，不代表线上延迟）：

```text
=== 2. SSE 流式接口自测 ===
  首字节延迟 TTFT=135.8 ms  总耗时=486.7 ms  分片数=7
  拼接结果=根据退款政策R-003，签收7 天内可全额退款。
```

对话式应用的关键指标与常见故障：

| 指标 | 经验目标 | 恶化后的现象 |
| --- | --- | --- |
| TTFT | 交互式 1 秒内开始出字 | 用户以为卡死，重复点击 |
| 单轮 token 成本 | 与业务价值挂钩设上限 | 长会话成本失控 |
| 历史裁剪正确性 | system 永不丢、最近轮次完整 | 角色设定丢失，回答风格漂移 |
| 流中断处理 | 客户端可见错误并可重试 | 前端显示半句话，用户以为答完 |

```text
对话式应用要点：
1. 流式优先用 SSE，实现简单且兼容网关；需要双向实时音频再上 WebSocket
2. 历史裁剪保 system、保最近轮次、按 token 预算而非条数
3. 客户端断连立即取消上游请求，否则为没人看的 token 付费
4. 会话持久化存服务端，前端只持有会话 ID，便于多端一致与审计
5. 错误要在流内返回结构化事件，不能只在 HTTP 层报错
6. 输入侧限流与长度上限是成本防线，不是可选项
```

## RAG 知识问答

RAG（Retrieval-Augmented Generation）把模型回答限制在检索到的资料范围内，解决三件事：知识时效（资料更新不必重训）、私有数据（企业资料不出内网模型）、可溯源（回答带引用，可人工复核）。链路是固定的四段：离线索引（解析、分块、向量化、入库）、在线检索（关键词与向量召回、重排）、增强（拼装上下文与引用编号）、生成（要求只依据上下文并给引用）。

分块策略直接影响召回质量：块太大则上下文噪声多、成本高，块太小则语义被切断。常规做法是按语义边界（标题、段落）切，再叠加滑动窗口保留重叠；表格与代码块要整块保留，不能被字符切分撕裂。检索侧建议混合召回：关键词（BM25）擅长精确术语与编号（如「R-003」「SO-20261001-8821」），向量擅长同义改写，两者融合再重排效果稳定优于单一方案。

| 维度 | 关键词检索（BM25） | 向量检索（embedding） |
| --- | --- | --- |
| 优势 | 术语、编号、精确匹配；无需模型 | 同义改写、语义近似；跨语言 |
| 劣势 | 换个说法就召不回 | 编号类查询易漂移；需 embedding 成本 |
| 依赖 | 分词质量 | 模型版本、向量库与距离度量 |
| 适用 | 政策编号、型号、错误码 | 自然语言提问、口语化描述 |

```python
import math
import re
from collections import Counter

DOCS = {
    "hr-leave.md": "年假规则：入职满 1 年享 5 天年假，满 3 年 10 天，满 5 年 15 天。未休完的年假最多结转 5 天至次年 3 月 31 日。",
    "it-vpn.md": "VPN 申请：在 IT 工单系统提交「远程接入」工单，审批人为主管 + 安全负责人。通道开通后 90 天内无登录会自动回收。",
    "finance-reimburse.md": "差旅报销：单笔超过 5000 元需部门总监加签。报销单跨年度不予受理。",
}


def tokenize(t: str) -> list[str]:
    """中文按字、英文数字按词切分；生产用分词器与业务词典。"""
    return re.findall(r"[a-zA-Z0-9]+", t.lower()) + re.findall(r"[\u4e00-\u9fff]", t)


chunks = [{"doc": n, "text": body[i:i + 100]}
          for n, body in DOCS.items() for i in range(0, len(body), 70)]
dtok = [tokenize(c["text"]) for c in chunks]
avg = sum(map(len, dtok)) / len(dtok)
df = Counter(t for ts in dtok for t in set(ts))
K1, B = 1.5, 0.75


def retrieve(query: str, top_k: int = 2) -> list[dict]:
    q = tokenize(query)
    scored = []
    for c, ts in zip(chunks, dtok):
        tf = Counter(ts)
        s = sum(math.log(1 + (len(chunks) - df[t] + .5) / (df[t] + .5)) *
                tf[t] * (K1 + 1) / (tf[t] + K1 * (1 - B + B * len(ts) / avg)) for t in q if t in tf)
        if s > 0:
            scored.append({**c, "score": round(s, 3)})
    return sorted(scored, key=lambda x: -x["score"])[:top_k]
```

召回后必须设最低分阈值并允许拒答：没有依据时回答「无依据」远优于让模型自由发挥。这是 RAG 与普通对话最大的行为差异，也是合规场景的硬要求。

```python
MIN_SCORE = 2.0


def answer(query: str) -> dict:
    hits = retrieve(query)
    if not hits or hits[0]["score"] < MIN_SCORE:
        return {"answer": "该问题在已授权知识范围内没有依据，无法回答。", "citations": [], "refused": True}
    ctx = "\n".join(f"[{i+1}] ({h['doc']}) {h['text']}" for i, h in enumerate(hits))
    # 真实部署把 ctx 交给 LLM 并追加「只依据上下文，逐句标注引用编号」的约束
    return {"answer": f"依据 [1]：{hits[0]['text'][:60]}...", "citations": [h["doc"] for h in hits],
            "context_chars": len(ctx), "refused": False}
```

本机实测（第二个问题超出授权范围，正确拒答）：

```text
=== 场景一：RAG 问答（阈值 + 引用） ===
 Q: 年假可以结转吗
 R: {"answer": "依据 [1]：假最多结转 5 天至次年 3 月 31 日。...", "citations": ["hr-leave.md", "hr-leave.md"], "context_chars": 151, "refused": false}
 Q: 公司有没有健身房补贴
 R: {"answer": "该问题在已授权知识范围内没有依据，无法回答。", "citations": [], "refused": true}
```

LangChain 的官方 RAG 教程把生产级模式总结为几种可组合形态：技能引导检索（用技能描述「该查哪个索引、如何组织查询、引用格式」）、评分器校验落地性（由 grader 子代理判断回答是否被检索材料支撑，不达标就重写直到通过或触达迭代上限）、待办驱动的调查（先规划要查哪些页面再逐项检索）、以及先卸载再委派（把召回内容写入文件系统，交给子代理并行分析，保持编排者上下文干净）。这些模式的共同点是把「检索」与「写作」解耦，避免长上下文互相污染。

评估 RAG 要分两段测：检索段看召回率与命中位置（正确文档是否进入 top-k），生成段看忠实度（回答是否被引用支撑）与拒答准确性。只测最终答案会掩盖检索问题——答案错可能是召回就没召到。

```text
RAG 要点：
1. 离线分块按语义边界切，表格与代码块整块保留，块间留重叠
2. 在线用关键词与向量混合召回再重排，编号类查询不要只依赖向量
3. 必须设最低分阈值与拒答话术，没有依据就明确说没有
4. 引用要能落到具体文档与段落，答案里带编号，前端可点击回溯
5. 检索权限与用户权限一致：不同角色检索范围不同，过滤在查询时而非展示时
6. 评估拆成检索段与生成段，分别看召回率与忠实度
```

## Agent 自动化

Agent 自动化与对话式应用的区别在驱动方式：对话是人给一句、模型答一句；Agent 是给一个目标，模型自己决定调用哪些工具、分几步完成。技术上是「模型 → 工具调用 → 结果回灌 → 再决策」的循环，直到目标达成或触达步数上限。

Agent 落地的难点不在模型聪明程度，而在边界：工具能做什么、参数谁校验、失败如何恢复、什么动作必须人工确认。工程约束有五条必备：最大步数上限、工具幂等（重复调用不产生副作用）、确定性参数校验、敏感动作人工确认、全链路审计。

```python
import sqlite3

AUDIT = []
AUTO_LIMIT = 500  # 单笔自动处置金额上限，超过转人工
POLICY = {
    "agent": {"query_order", "create_refund_request"},
    "supervisor": {"create_refund_request", "approve_refund"},
}


class ToolDenied(Exception):
    pass


def require(role: str, action: str) -> None:
    """权限在代码里判，模型不参与授权决策。"""
    if action not in POLICY.get(role, set()):
        AUDIT.append({"action": action, "role": role, "result": "denied"})
        raise ToolDenied(f"角色 {role} 无权执行 {action}")
```

本机实测（含一次越权调用被拦截）：

```text
=== 场景二：Agent 工具编排（最小权限 + 人工门槛） ===
 查询: {"order_id": "SO-20261001-8821", "amount": 268.0, "status": "已签收", "signed_days": 10}
 小额快退: {"order_id": "SO-20261003-5521", "amount": 99.0, "status": "已自动受理", "reason": "命中自动退款规则"}
 大额: {"order_id": "SO-20261002-3312", "amount": 1280.0, "status": "待人工审批", "reason": "金额 1280.0 > 500"}
 超期: {"order_id": "SO-20261001-8821", "amount": 268.0, "status": "待人工审批", "reason": "签收 10 天 > 7"}
 越权拦截: 角色 agent 无权执行 approve_refund
 审计条数: 10 | 首条: {"action": "query_order", "order_id": "SO-20261001-8821", "result": "ok"}
```

触发方式决定形态细节：用户即时应答用对话触发，定时任务与事件订阅（新工单创建、告警触发、Webhook 回调）用后台触发。后台 Agent 必须有并发上限与幂等键，否则同一条消息被重复消费产生重复处置。

| 约束 | 实现方式 | 缺失后果 |
| --- | --- | --- |
| 步数上限 | 循环最大迭代次数 + 超限降级为人工 | 死循环烧钱 |
| 幂等 | 以业务主键做幂等键，写操作先查状态 | 重复退款、重复发信 |
| 权限 | 角色到工具集合的映射在代码里判 | 越权操作 |
| 人工确认 | 超阈值动作返回待审批并挂起 | 不可撤销的错误处置 |
| 审计 | 全量记录工具、参数、结果、耗时 | 出问题无法归因 |

```text
Agent 自动化要点：
1. 循环必须有最大步数上限，超限降级为转人工而不是继续尝试
2. 所有写工具做幂等，幂等键用业务主键，状态机显式记录
3. 权限判断在代码里，模型只负责提议调用哪个工具
4. 敏感或高金额动作一律返回待人工审批，不做自动放行
5. 定时与事件触发的 Agent 要限并发并做去重，避免重复处置
6. 全链路审计是排障与合规的共同底座
```

## 多模态应用 图像 语音 视频生成

多模态把输入输出从文本扩展到图像、音频、视频。工程形态与纯文本有明显差异：多数是异步长任务（生成一张图数秒、一段视频数十秒到数分钟），需要任务提交、轮询或回调、结果对象存储、失败重试与成本核算；同时内容审核与生成内容标识是上线必备项。

图像生成与编辑走 Images API（从零生成、局部或整体编辑）或 Responses API 的图像工具（支持多轮编辑、可引用文件 ID）；官方文档当前列出的模型为 `gpt-image-2.5-sunburst`（偏重编辑精度）与 `gpt-image-2.5-flare`（偏重速度与日常质量），具体可用模型与价格以官方文档为准。内容被安全策略拦截会返回 `moderation_blocked` 错误码，必须单独处理而不是当普通失败重试。

```shell
# 图像生成（官方文档示例形态，模型名与参数以官方文档为准）
curl -X POST "https://api.openai.com/v1/images/generations" \
  -H "Authorization: Bearer $OPENAI_API_KEY" \
  -H "Content-type: application/json" \
  -d '{
        "model": "gpt-image-2.5-sunburst",
        "prompt": "给宠物医院设计的儿童绘本风格插图：兽医用水银听诊器听水獭幼崽心跳",
        "size": "1024x1024"
      }' | jq -r '.data[0].b64_json' | base64 --decode > otter.png
```

语音分两条线：文本转语音（TTS）与语音转文本（转写）。TTS 侧官方推荐面向实时应用的 `gpt-4o-mini-tts`，支持通过提示控制语速、语气等表达；转写侧支持 `gpt-4o-transcribe` 与 `gpt-4o-mini-transcribe`，老一代 Whisper 的提示窗口只有 224 token，术语表较长时官方建议用文本模型对转写结果做后处理（校正拼写与专有名词），但要拿校正结果与原音频比对，避免改变原意。

```python
from openai import OpenAI

client = OpenAI()

# 语音转文本（端点与参数以官方文档为准）
with open("call-recording.wav", "rb") as fh:
    transcript = client.audio.transcriptions.create(file=fh, model="gpt-4o-mini-transcribe")
print(transcript.text)

# 文本转语音：用 instructions 控制表达风格
with client.audio.speech.with_streaming_response.create(
        model="gpt-4o-mini-tts", voice="alloy", input="您的退款申请已受理，预计 3 个工作日到账。",
        instructions="用平静、清晰的客服语气朗读，语速稍慢") as resp:
    resp.stream_to_file("reply.mp3")
```

视频生成是典型异步任务：提交渲染任务、轮询状态、下载成品。官方视频接口为 `POST /v1/videos`，可用参数包括 `model`（如 `sora-2`、`sora-2-pro`）、`size`、`seconds`，支持图片参考、角色复用、片段续写与定向编辑；批量离线渲染走 Batch API，但 Batch 只支持 JSON 请求体（不支持 multipart 上传参考图），参考图需先上传再用 `input_reference` 引用。视频提示词官方建议覆盖五要素：镜头类型、主体、动作、场景、光线。

```shell

  -H "Authorization: Bearer $OPENAI_API_KEY" \
  -H "Content-Type: multipart/form-data" \
  -F model="sora-2-pro" \
  -F prompt="宽幅跟拍：一辆青色轿跑行驶在沙漠公路，热浪可见，正午强光" \

  -F seconds="8"
```

from openai import OpenAI

client = OpenAI()
video = client.videos.create(model="sora-2", prompt="用闪烁字母写出「谢谢」", seconds="4")

各模态的典型参数与常见问题：

| 模态 | 典型接口 | 关键参数 | 常见问题 |
| --- | --- | --- | --- |
| 图像生成 | POST /v1/images/generations | prompt、size、n、quality | 被审核拦截（moderation_blocked）误当重试 |
| 图像编辑 | POST /v1/images/edits、Responses 图像工具 | 原图、mask、prompt | 多轮编辑不做版本留存，无法回退 |
| 文本转语音 | POST /v1/audio/speech | model、voice、input、instructions | 长文本不切分导致超时 |
| 语音转写 | POST /v1/audio/transcriptions | file、model | 专有名词识别错，长提示超出模型窗口 |
| 视频生成 | POST /v1/videos | model、prompt、size、seconds | 同步等待导致请求超时，未做轮询 |

```text
多模态应用要点：
1. 生成类调用一律当异步任务处理：提交、轮询或回调、落对象存储、再回传 URL
2. 内容审核是必答题：识别 moderation_blocked 等专用错误码，不要盲目重试
3. 视频提示词覆盖镜头、主体、动作、场景、光线五要素，效果差异明显
4. 语音转写用文本模型做术语校正，但必须与音频核对，避免改变原意
5. 生成内容按监管要求加显式与隐式标识（详见合规篇章）
6. 成本按模态单独核算并设配额，图像与视频的单次成本远高于文本
```

## Copilot 式集成

Copilot 式集成把 AI 嵌进用户已经在用的工具：IDE 内联补全与侧边栏对话、办公套件写作辅助、浏览器扩展、CLI 助手。与独立对话产品的最大差别是延迟预算与上下文来源：补全类场景要求百毫秒级首字、输入是光标周围代码或选区、结果需要可一键接受或拒绝。判断标准不是「回答多聪明」，而是「接受率与误打扰率」。

落地要解决四件事：上下文的局部性（只取当前文件、光标附近与被引用符号，避免把整仓塞进提示）、缓存与去重（相同前缀的补全请求可复用）、隐私边界（代码与文档是否允许外发、是否需本地模型）、反馈闭环（接受、拒绝、忽略都要回传，用于评估与微调）。

```python
"""Copilot 式补全的最小上下文构造：光标附近窗口 + 引用符号，避免整仓上送。"""
import re


def build_completion_context(source: str, cursor: int, window: int = 1500,
                             max_symbols: int = 5) -> dict:
    prefix = source[max(0, cursor - window):cursor]
    suffix = source[cursor:cursor + 300]
    imports = re.findall(r"^\s*(?:from|import)\s+([\w.]+)", source, re.M)[:max_symbols]
    return {
        "prefix": prefix,
        "suffix": suffix,
        "imports": imports,
        "symbols": re.findall(r"\bdef\s+(\w+)|\bclass\s+(\w+)", prefix)[-max_symbols:],
        "chars": len(prefix) + len(suffix),
    }


code = "import os\nimport json\n\ndef parse_ticket(raw):\n    "
ctx = build_completion_context(code, len(code))
print(f"上送字符数={ctx['chars']} imports={ctx['imports']} 定义符号={ctx['symbols']}")
```

服务形态上，Copilot 类集成多采用统一网关：客户端只与网关通信，网关负责鉴权、配额、模型路由、审计与降级（模型不可用时回落到规则补全或静默失败，绝不阻塞编辑器）。补全类请求还适合用「先返回低置信候选、再异步算高质量结果」的两段式策略，先用短延迟占住体验。

| 维度 | 对话式产品 | Copilot 式集成 |
| --- | --- | --- |
| 触发 | 用户显式提问 | 用户敲键或选中内容自动触发 |
| 延迟预算 | 秒级可接受 | 补全需百毫秒级首字 |
| 上下文 | 会话历史为主 | 光标邻域、选区、被引用符号 |
| 结果处置 | 直接阅读 | 接受或拒绝，误报直接打断工作 |
| 关键指标 | 满意度、解决率 | 接受率、误打扰率、单次成本 |

```text
Copilot 式集成要点：
1. 延迟是一等指标：先保证首字速度，再优化正确率
2. 上下文只取局部相关部分，整仓上送既慢又贵还可能违规
3. 客户端只连网关，鉴权、配额、模型路由、审计与降级集中在网关
4. 接受与拒绝都要回传埋点，否则无法评估效果
5. 模型不可用时必须静默降级，绝不能让编辑器卡住
6. 明确数据边界：哪些仓库、哪些文件禁止外发，用配置强制而不是靠自觉
```

## 应用场景实战

### 场景一：企业内部知识问答（RAG + 检索阈值 + 强制引用 + 拒答）

需求：员工用自然语言问制度问题，答案必须落到具体文档，检索不到就明确拒答；同时不同角色的检索范围不同。下面是可离线跑的最小版本（BM25 检索 + 阈值 + 引用回填），生产把检索器换成向量库加混合召回即可，链路不变。

```python
"""企业知识问答最小实现：分块 + BM25 检索 + 阈值拒答 + 引用回填（离线可跑）。"""
import json
import math
import re
from collections import Counter

DOCS = {
    "hr-leave.md": "年假规则：入职满 1 年享 5 天年假，满 3 年 10 天，满 5 年 15 天。年假需提前 3 个工作日申请，由直属主管审批。未休完的年假最多结转 5 天至次年 3 月 31 日。",
    "it-vpn.md": "VPN 申请：在 IT 工单系统提交「远程接入」工单，审批人为主管 + 安全负责人。通道开通后 90 天内无登录会自动回收。离职当天 VPN 权限自动吊销。",
    "finance-reimburse.md": "差旅报销：交通与住宿凭原始发票在费用系统提交，财务在 5 个工作日内审核。单笔超过 5000 元需部门总监加签。报销单跨年度不予受理。",
}
ACL = {"employee": {"hr-leave.md", "finance-reimburse.md"}, "it": {"it-vpn.md"}}  # 角色可见范围

K1, B, MIN_SCORE = 1.5, 0.75, 2.0


def tokenize(t: str) -> list[str]:
    return re.findall(r"[a-zA-Z0-9]+", t.lower()) + re.findall(r"[\u4e00-\u9fff]", t)


chunks = [{"doc": n, "text": body[i:i + 100]}
          for n, body in DOCS.items() for i in range(0, len(body), 70)]
dtok = [tokenize(c["text"]) for c in chunks]
avg = sum(map(len, dtok)) / len(dtok)
df = Counter(t for ts in dtok for t in set(ts))


def retrieve(query: str, role: str, top_k: int = 2) -> list[dict]:
    allowed = ACL.get(role, set())
    q = tokenize(query)
    scored = []
    for c, ts in zip(chunks, dtok):
        if c["doc"] not in allowed:          # 权限过滤在检索时完成，不依赖展示层
            continue
        tf = Counter(ts)
        s = sum(math.log(1 + (len(chunks) - df[t] + .5) / (df[t] + .5)) *
                tf[t] * (K1 + 1) / (tf[t] + K1 * (1 - B + B * len(ts) / avg)) for t in q if t in tf)
        if s > 0:
            scored.append({**c, "score": round(s, 3)})
    return sorted(scored, key=lambda x: -x["score"])[:top_k]


def answer(query: str, role: str = "employee") -> dict:
    hits = retrieve(query, role)
    if not hits or hits[0]["score"] < MIN_SCORE:
        return {"answer": "该问题在已授权知识范围内没有依据，无法回答。", "citations": [], "refused": True}
    ctx = "\n".join(f"[{i+1}] ({h['doc']}) {h['text']}" for i, h in enumerate(hits))
    return {"answer": f"依据 [{1}]：{hits[0]['text'][:60]}...",
            "citations": [h["doc"] for h in hits], "context_chars": len(ctx), "refused": False}


print(json.dumps(answer("年假可以结转吗"), ensure_ascii=False))
print(json.dumps(answer("VPN 多久不用会被回收", role="employee"), ensure_ascii=False))
```

第二条暴露了阈值方案的边界：employee 角色看不到 VPN 文档，检索器却把「凑出分数」的报销制度当成依据返回，分数越过了阈值——拒答只挡住了完全无相关的提问，挡不住「相关但不正确」。生产上必须再叠加两层：检索侧加语义重排并设相对阈值（榜首分数与次榜分数的差值过小时不放行），生成侧做引用落地校验（答案里每条引用都要能在召回内容里找到出处，找不到则拦截）。

### 场景二：客服工单自动处置 Agent（工具 + 权限 + 人工门槛 + 审计）

需求：Agent 读取工单后自行查询订单、判断处置路径、发起退款；金额超过阈值或超期时转人工审批；所有工具调用留痕。核心是「模型只提议，代码做决定」，越权调用必须被立即拒绝并记录。

```python
"""客服工单处置 Agent：最小权限 + 人工门槛 + 全量审计（离线可跑）。"""
import json
import sqlite3

AUDIT = []
AUTO_LIMIT = 500
POLICY = {"agent": {"query_order", "create_refund_request"},
          "supervisor": {"create_refund_request", "approve_refund"}}

conn = sqlite3.connect(":memory:")
conn.execute("CREATE TABLE orders(order_id TEXT PRIMARY KEY, amount REAL, status TEXT, signed_days INT)")
conn.executemany("INSERT INTO orders VALUES(?,?,?,?)", [
    ("SO-20261001-8821", 268.0, "已签收", 10),
    ("SO-20261002-3312", 1280.0, "已签收", 2),
    ("SO-20261003-5521", 99.0, "已签收", 2),
])


class ToolDenied(Exception):
    pass


def require(role: str, action: str) -> None:
    if action not in POLICY.get(role, set()):
        AUDIT.append({"action": action, "role": role, "result": "denied"})
        raise ToolDenied(f"角色 {role} 无权执行 {action}")


def query_order(order_id: str) -> dict:
    require("agent", "query_order")
    r = conn.execute("SELECT order_id, amount, status, signed_days FROM orders WHERE order_id=?",
                     (order_id,)).fetchone()
    AUDIT.append({"action": "query_order", "order_id": order_id, "result": "ok" if r else "not_found"})
    return dict(zip(["order_id", "amount", "status", "signed_days"], r)) if r else {}


def create_refund_request(order_id: str, amount: float, role: str = "agent") -> dict:
    require(role, "create_refund_request")
    o = query_order(order_id)
    if not o:
        raise ValueError("订单不存在")
    triggers = []
    if amount > AUTO_LIMIT:
        triggers.append(f"金额 {amount} > {AUTO_LIMIT}")
    if o["signed_days"] > 7:
        triggers.append(f"签收 {o['signed_days']} 天 > 7")
    out = {"order_id": order_id, "amount": amount,
           "status": "待人工审批" if triggers else "已自动受理",
           "reason": "；".join(triggers) if triggers else "命中自动退款规则"}
    AUDIT.append({"action": "create_refund_request", **out, "result": "ok"})
    return out
```

## 最佳实践与踩坑记录

### 最佳实践

1. 先定形态再写代码：交互粒度、确定性要求、延迟预算、数据边界四项想清楚，架构差别很大
2. 对话式应用把流式、历史裁剪、断连取消上游做全，这三项直接决定体验与成本
3. RAG 必须设检索最低分阈值与拒答话术，答案强制带可点击引用；检索权限与用户权限一致，过滤在检索阶段执行
4. Agent 的越权判断、金额阈值、幂等键全部写在确定性代码里，模型只负责提议
5. 生成类多模态能力按异步任务设计，识别审核类错误码并单独处理
6. Copilot 式集成以延迟与接受率为核心指标，客户端只连网关，模型不可用时静默降级

### 踩坑记录

```text
坑 1：把整段对话历史直接塞进每次请求
结论：单轮成本随会话线性增长，长会话频繁超上下文报错。
原因：只按条数截断，没有按 token 预算裁剪，也没保留 system 与最近轮次。
解法：按 token 预算裁剪，system 永不全丢，最近若干轮优先保留，并预留输出预算。

坑 2：RAG 检索不到依据时让模型自由回答
结论：模型用训练知识编出看似合理的制度条款，员工照做后出现合规事故。
原因：未设最低分阈值，也缺少「无依据就拒答」的兜底话术。
解法：设检索阈值并显式拒答，回答必须带引用编号，引用无法落地时拦截该回答。

坑 3：Agent 工具不做幂等导致重复处置
结论：同一条工单被重复退款，事后靠人工对账才发现。
原因：事件重复投递、重试机制与模型重试叠加，写操作没有幂等键。
解法：写工具以业务主键做幂等键，先查状态再执行，并在状态机里记录处置结果。

坑 4：视频生成按同步接口调用导致网关超时
结论：请求超时后用户重复点击，任务重复提交，费用翻倍。
原因：视频与部分图像生成是数十秒到数分钟的异步任务，误当同步接口使用。
解法：改成提交任务加轮询或回调的异步流程，前端展示进度，重复提交用幂等键拦截。

坑 5：Copilot 把整个仓库作为上下文上送
结论：首字延迟高、成本高，而且触发数据外发合规问题。
原因：上下文构造图省事，直接拼接整个工作区。
解法：只取光标邻域、选区与被引用符号，敏感仓库用配置强制禁用外发。
```

## 概述

AI 学习路线的核心矛盾是「知识面极宽而时间有限」：数学、编程、算法、工程、领域知识，任何一块都能吃掉全部时间。可行的策略是按目标方向倒推先修链，只补与该方向强相关的数学与工程，其余按「够用即止」处理，并把学习成果固化成可复现的实验与项目，而不是收藏夹里的课程列表。

本篇给出三样东西：一张前置知识清单（哪些必须真懂、哪些会用即可）、按方向拆分的路线表（每方向给出前置、核心技能、里程碑项目）、以及数据集、论文、课程与社区的实操入口。最后列出最常见的七类学习误区——它们的共同点是「把输入当成了掌握」。

```text
本篇四段结构：
1. 前置 —— 数学与编程，按方向决定深度，不做无差别补课
2. 路线 —— 应用工程、研究、CV、NLP、数据、生成、推理基础设施等方向分头走
3. 资源 —— 数据集与竞赛平台、论文读法、课程与社区的可操作入口
4. 误区 —— 收藏驱动、只看不写、指标不固定、把跑通 demo 当掌握
```

## 数学与编程前置知识

数学决定你能否读懂论文与推导，编程决定你能否把想法跑起来。两者都不需要「先学完再开始」：正确做法是带着具体任务补——要做微调就先补交叉熵与梯度下降，要做检索就先补向量相似度与评估指标，要做 A/B 实验就先补假设检验。

必须真懂的数学是四块：线性代数（向量与矩阵运算、范数、特征值分解、SVD，对应表示学习与降维）、概率统计（常见分布、期望与方差、最大似然、贝叶斯、置信区间与假设检验，对应建模与实验评估）、微积分与优化（偏导、链式法则、梯度下降及其变体、凸性，对应训练过程）、信息论（熵、交叉熵、KL 散度，对应损失函数与评估指标）。会用即可的部分是测度论、复杂泛函分析等更理论的内容，除非目标是做理论研究。

| 数学模块 | 为什么要懂 | 最小验证练习 |
| --- | --- | --- |
| 线性代数 | 张量运算、注意力机制的矩阵形式、降维 | 手写矩阵乘法并验证 NumPy 结果 |
| 概率统计 | 损失函数、采样、实验显著性 | 用自助法估计指标置信区间 |
| 微积分与优化 | 反向传播、学习率与收敛 | 手推线性回归梯度并用代码验证 |
| 信息论 | 交叉熵、KL 散度、困惑度 | 计算两个分布的 KL 散度并与公式对照 |

编程前置按方向分层：所有方向都需要 Python 基础与 Git；算法与工程方向需要 NumPy/PyTorch 与数据处理；应用工程方向需要 API 调用、提示与评估、后端与部署基础。NumPy 的向量化思维是分水岭——用循环写张量运算的人，训练脚本会慢一两个数量级。

```python
# 前置知识自检：能在不查文档的情况下写出这三段，说明基础达标
import random

# 1) 线性代数：矩阵乘法的朴素实现
def matmul(a, b):
    n, m, p = len(a), len(b), len(b[0])
    return [[sum(a[i][k] * b[k][j] for k in range(m)) for j in range(p)] for i in range(n)]


# 2) 概率统计：自助法估计均值的 95% 置信区间
def bootstrap_ci(xs, n=2000, alpha=0.05):
    means = sorted(sum(random.choices(xs, k=len(xs))) / len(xs) for _ in range(n))
    lo = means[int(n * alpha / 2)]
    hi = means[int(n * (1 - alpha / 2))]
    return round(lo, 3), round(hi, 3)


# 3) 信息论：交叉熵
def cross_entropy(p, q):
    return -sum(pi * (qi and __import__("math").log(qi)) for pi, qi in zip(p, q) if pi)


print("matmul:", matmul([[1, 2], [3, 4]], [[5, 6], [7, 8]]))
print("CI95:", bootstrap_ci([1.2, 0.9, 1.5, 1.1, 1.3, 0.8, 1.4]))
print("CE:", round(cross_entropy([1.0, 0.0], [0.9, 0.1]), 4))
```

```text
前置知识要点：
1. 按目标方向决定数学深度，不做无差别补课
2. 必须真懂：线代、概率统计、微积分与优化、信息论四块
3. 编程上 NumPy 向量化是分水岭，先改掉用循环算张量的习惯
4. 带着任务补知识：做微调补损失函数，做检索补相似度与评估
5. 每个模块配一个最小验证练习，能算出来才算学过
6. 工程能力（Git、环境管理、日志）与算法同等重要，早补早受益
```

## 按方向拆分的路线

方向决定先修链。下面八个方向覆盖了当前主流就业与研究方向，每个方向给出前置、核心技能与一个能写进简历的里程碑项目。选方向的原则是「先看目标岗位的 JD，再倒推技能清单」，而不是从课程目录顺着学。

| 方向 | 前置 | 核心技能 | 里程碑项目 |
| --- | --- | --- | --- |
| LLM 应用工程 | Python、HTTP、基础提示 | 提示与结构化输出、RAG、评估、Agent 工具编排 | 带引用与拒答的企业知识问答系统 |
| 算法与模型研究 | 线代、概率、PyTorch | 论文复现、训练调优、消融实验、实验管理 | 复现一篇论文并给出消融结论 |
| 计算机视觉 | 线代、图像基础 | CNN、检测分割、数据增强、部署 | 目标检测模型训练与推理服务 |
| 自然语言处理 | 概率、序列建模 | 分词与表示、预训练微调、信息抽取 | 领域文本分类与实体抽取管道 |
| 数据科学与 ML 工程 | 统计、SQL | 特征工程、模型评估、特征平台与调度 | 端到端预测服务含监控与回滚 |
| 语音与多模态生成 | 信号基础、生成模型 | 音频处理、扩散模型、异步任务编排 | 语音转写加摘要的会议处理流水线 |
| Agent 与自动化 | Python、API、分布式基础 | 工具设计、权限与审计、幂等与限流 | 定时与事件触发的多步自动化流程 |
| AI 基础设施与推理优化 | 系统、CUDA 概念 | 模型量化、批处理调度、显存优化 | 单卡上的高并发推理服务压测报告 |

选方向时先用两周做「小样测试」：按该方向跑通一个最小项目，再决定是否深入。多数人的方向焦虑来自只有想象没有接触。

```text
方向选择的三条判据：
1. 目标岗位的 JD 里出现频率最高的三项技能，就是你第一个月要补的内容
2. 能接触到的资源（数据、算力、导师、业务场景）决定你能否做出成果
3. 用两周小样测试替代长期犹豫，做过再决定

路线推进节奏（以 LLM 应用工程为例）：
第 1 至 2 周：HTTP 与 API 调用、提示六要素、结构化输出
第 3 至 4 周：RAG 全链路（分块、检索、引用、拒答）与评估指标
第 5 至 6 周：Agent 工具编排、权限与人工确认、审计日志

```

## 数据集与竞赛平台

数据集是学习过程中最容易被低估的资源：选择「小、干净、有公开基线」的数据集，能让反馈循环缩短到分钟级。经典的入门组合是 MNIST 或 CIFAR-10（图像分类）、IMDB 或 SST-2（情感分类）、SQuAD（问答）、以及 MMLU、GSM8K、HumanEval 这类评测集合（大模型能力评估）。企业场景则优先构造私有小数据集，因为公开数据上的高分不等于业务可用。

| 平台 | 定位 | 典型用法 |
| --- | --- | --- |
| Kaggle | 数据集与竞赛的主要入口 | 参加入门赛（如 Titanic）熟悉流程，复用公开 Notebook |
| Hugging Face | 模型、数据集、评测与课程 | 下载模型与数据集、查看模型卡、跑评测 |
| arXiv | 论文预印本 | 检索与下载最新论文 |
| Papers with Code | 论文与代码、榜单对应 | 找某任务的基准实现与排行榜 |
| OpenReview | 会议评审与论文讨论 | 查看评审意见，理解论文的争议点 |
| 天池 / AI Studio / DataFountain | 国内竞赛与算力 | 中文场景竞赛、免费 GPU 额度练习 |

命令行获取资源是最省事的方式，凭据自行配置，不要提交到仓库。以下命令的选项以各工具官方文档为准（Hugging Face 新版命令行工具为 `hf`，旧版 `huggingface-cli` 仍可用）。

```shell
# 环境准备（pip 慢时用清华镜像）
pip install --index-url https://pypi.tuna.tsinghua.edu.cn/simple kaggle huggingface_hub datasets pandas

# Hugging Face：下载数据集与模型（首次需登录）
hf auth login
hf download squad --repo-type dataset --local-dir data/squad
hf download bert-base-chinese --local-dir models/bert-base-chinese

# Kaggle：凭据放 ~/.kaggle/kaggle.json，下载竞赛数据
kaggle datasets download -d <owner>/<dataset-name> -p data/ --unzip
kaggle competitions download -c titanic -p data/titanic --unzip

# 校验下载完整性（示例：统计行数与文件大小）
wc -l data/squad/*.jsonl
du -sh data/squad models/bert-base-chinese
```

数据集管理要遵守三条纪律：固定版本（记录数据集名称与 revision，不要用「main 最新」）、固定划分（训练验证测试划分要落盘保存，避免后续实验不可比）、以及标注来源与许可（尤其是商用项目）。

```text
数据集与竞赛要点：
1. 入门选小、干净、有公开基线的数据集，反馈循环优先
2. 记录数据集名称与 revision，禁止「拉最新」导致实验不可复现
3. 训练验证测试划分落盘保存，后续所有实验复用它
4. 竞赛的价值在于强制对齐评估口径与提交格式，不是名次本身
5. 评测集合（MMLU、GSM8K、HumanEval 等）用于能力对比，不等于业务效果
6. 标注数据来源与许可，商用项目必须确认授权范围
```

## 论文 课程与社区

论文是知识的一手来源，但不需要通读。实用的做法是「三遍读法」：第一遍读标题、摘要、图表与结论，判断是否相关（五到十分钟）；第二遍读方法与实验设置，理解做了什么、对比了谁（三十分钟到一小时）；第三遍复现关键结果或推导细节，只在需要深入时做。读论文时优先抓三类信息：解决什么问题、关键改动是什么、关键数字是多少。

以 Transformer 的原始论文《Attention Is All You Need》（arXiv:1706.03762，2017 年 6 月提交、2023 年 8 月修订至 v7）为例，摘要里给出的关键数字是：WMT 2014 英德翻译 28.4 BLEU，超过当时最优结果（含集成模型）2 BLEU 以上；英法翻译单模型 41.8 BLEU；训练成本为 8 块 GPU 上 3.5 天。这些数字就是判断后续论文是否真正进步的比较基准——读懂关键数字，比记住架构图更有用。

| 阶段 | 推荐资源 | 说明 |
| --- | --- | --- |
| 数学直觉 | 3Blue1Brown 线代与微积分系列 | 建立几何直觉，不适合当唯一教材 |
| 机器学习入门 | 吴恩达《机器学习》与《深度学习专项》 | 概念体系完整，配套作业要做 |
| 动手实现 | 《动手学深度学习》（d2l.ai） | 代码优先，注意选择与本地框架版本匹配的章节 |
| 大模型与 NLP | Hugging Face 课程体系（LLM、Agents、Audio、Computer Vision、Diffusion、Deep RL 等） | 免费、有练习与社区讨论 |
| 工程与实践 | Kaggle 公开 Notebook、开源项目源码 | 学数据管道与工程取舍，不只学建模 |
| 论文与讨论 | arXiv、Papers with Code、OpenReview、会议论文集 | 一手来源与评审意见 |

社区的价值在于「让人纠错」：把实验记录与结论发出去，比独自看课更能发现自己的盲点。参与方式可以是复现笔记、竞品分析、开源贡献或线下读书会，关键是产出物能被别人检验。

```text
论文课程与社区要点：
1. 用三遍读法筛论文，多数论文只值得第一遍
2. 读论文优先抓问题、关键改动、关键数字三项
3. 课程配练习才有用，只看视频等于没学
4. 选课程先看最近更新时间，AI 领域两年以上的内容常需重新核对
5. 社区参与以产出物为前提，复现笔记与开源贡献比提问更有价值
6. 建一个属于自己领域的最小基准库（数据集、指标、对比结果），长期复用
```

## 常见学习误区

误区一：收藏驱动。课程、论文、仓库囤到几百条，学习进度停留在「已收藏」。纠偏方式是把学习单位从「看完一门课」改成「交付一个可运行产物」，每两周必须有一个能跑的结果。

误区二：只看不写。看懂了梯度下降的推导，写不出训练循环。纠偏方式是「代码优先」：任何概念都要落到不超过百行的可运行实现，能手算的指标要用代码验证一遍。

误区三：指标不固定。换了数据划分、改了随机种子、用了不同评测脚本，然后比较两次实验结果。这类比较没有信息量，只会得出随机结论。

误区四：从零训练大模型。个人算力与数据规模都撑不住预训练，正确路径是微调与推理优化，或者在小规模数据上做方法验证。

| 误区 | 表现 | 纠偏动作 |
| --- | --- | --- |
| 收藏驱动 | 资源列表很长，产物为零 | 每两周交付一个可运行产物 |
| 只看不写 | 能讲原理，写不出实现 | 每个概念配百行内可运行代码 |
| 指标不固定 | 结果波动大，结论反复 | 固定划分、种子、评测脚本并落盘 |
| 从零训练大模型 | 显存爆、loss 不降 | 转向微调、LoRA 与推理优化 |
| 跳过评估 | 只看 loss，不上验证集 | 训练前先定义指标与基线 |
| 忽视工程 | 脚本级代码，无法复现 | 用配置管理、日志与固定环境 |

```text
常见误区要点：
1. 学习单位从「看完课程」改成「交付产物」，进度才有约束力
2. 概念必须落到代码，能算出来才算理解
3. 实验必须固定划分、种子与评测脚本，否则比较无意义
4. 个人不做预训练，专注微调、检索与推理优化
5. 训练前先定义指标与基线，否则无法判断改进是否真实
6. 从第一周就按工程标准写脚本：配置、日志、固定环境
```

## 应用场景实战

### 场景一：用最小实验模板跑通第一个可复现训练

需求：不依赖任何第三方库，把「固定种子、划分数据、训练循环、指标计算、参数收敛」这条链路完整跑一遍，作为后续所有实验的模板。向量化与优化思想与深度学习一致，只是规模缩小到可手算。

```python
"""最小可复现实验模板：线性回归梯度下降（纯标准库，离线可跑）。"""
import random
import statistics

random.seed(42)                                    # 固定种子是好实验的第一条
X = [[1.0, x] for x in range(1, 51)]
TRUE = (3.0, 1.7)
Y = [TRUE[0] + TRUE[1] * x[1] + random.uniform(-1.5, 1.5) for x in X]
split = 40
train, test = X[:split], X[split:]                 # 划分固定落盘，后续实验复用它


def dot(w, x):
    return sum(wi * xi for wi, xi in zip(w, x))


def train_model(xs, ys, lr=0.0005, epochs=4000):
    w = [0.0, 0.0]
    n = len(xs)
    for _ in range(epochs):
        grad = [0.0, 0.0]
        for x, y in zip(xs, ys):
            err = dot(w, x) - y
            for i in range(len(w)):
                grad[i] += 2 * err * x[i] / n
        for i in range(len(w)):
            w[i] -= lr * grad[i]
    return w


w = train_model(train, [Y[i] for i in range(split)])
pred = [dot(w, x) for x in test]
y_test = Y[split:]
mae = sum(abs(p - y) for p, y in zip(pred, y_test)) / len(test)
rmse = (sum((p - y) ** 2 for p, y in zip(pred, y_test)) / len(test)) ** 0.5
print(f"参数={[round(v, 3) for v in w]} MAE={mae:.3f} RMSE={rmse:.3f} 验证均值={statistics.mean(pred):.2f}")
```

本机实测输出（含每阶段 loss 与参数收敛过程）：

```text
=== 场景一：最小训练实验（线性回归，纯标准库） ===
  训练样本=40 验证样本=10 真值参数=(3.0, 1.7)
  epoch=1     loss=364.8481 w=[0.038, 1.005]
  epoch=100   loss=1.9573   w=[0.123, 1.812]
  epoch=1000  loss=1.5108   w=[0.57, 1.795]
  epoch=4000  loss=0.8811   w=[1.521, 1.76]
  学到的参数=[1.521, 1.76]  MAE=1.865  RMSE=1.972
  验证集预测均值=81.60 标签均值=79.74
```

这段输出本身就是教材：斜率学到 1.76（真值 1.7），截距只学到 1.52（真值 3.0），说明在该学习率下参数收敛速度不同、训练还不够充分；验证 MAE 1.865 大于噪声区间，提示还有优化空间。能看到这些现象，说明评估环节有效。

### 场景二：论文复现计划与数据获取清单

## 最佳实践与踩坑记录

### 最佳实践

1. 以产物驱动学习：每两周交付一个可运行的东西，课程与论文服务于交付
2. 按目标方向的 JD 倒推技能清单，数学按需补，不做无差别补课
3. 任何概念都落到百行内的可运行实现，能算出来的才算理解
4. 实验与数据都要能复现：固定数据划分、随机种子与评测脚本；数据集记录名称与 revision，标注许可与来源
5. 读论文用三遍法并抓关键数字，把数字作为后续改进的比较基准
6. 从第一个项目就按工程标准写：配置管理、日志、环境隔离

### 踩坑记录

```text
坑 1：先花半年补数学再开始写代码
结论：数学课听完了，面对真实任务仍无从下手，动力在中途耗尽。
原因：脱离任务的知识没有挂载点，记忆与理解都无法巩固。
解法：带着任务补数学，最小练习与代码同步做，缺哪块补哪块。

坑 2：实验没有固定划分与种子，结论反复
结论：同一方法两次跑出相反结论，浪费数周排查"超参"。
原因：数据划分每次随机、种子未固定、评测脚本换过版本。
解法：划分与种子落盘固化，评测脚本进版本控制，改动走对比实验。

坑 3：直接下载最新数据集导致结果无法复现
结论：三个月后重跑实验，指标对不上，无法定位问题。
原因：只记了数据集名字，用了 main 分支最新数据，数据已更新。
解法：记录名称加 revision 或数据版本号，并保留一份本地快照。

坑 4：把跑通 demo 当成掌握
结论：会调 API 但答不出「为什么这样设计、出问题怎么定位」，面试与项目都卡住。
原因：学习停留在复制示例，没有做评估、错误分析与边界测试。
解法：每个 demo 追加三件事：指标评估、失败样例分析、边界与异常处理。
```

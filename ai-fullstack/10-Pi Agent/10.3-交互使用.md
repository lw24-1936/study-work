## 概述

Pi 的交互界面由三块组成：**transcript**（你的提示、模型回复、工具调用与结果、错误）、**editor**（写提示与命令的地方）、**footer**（当前目录、会话、模型、上下文占用、累计用量与成本）。它不像聊天工具那样一问一答，而是「你随时可以插话的流水线」：模型干活时你可以发消息改方向（steering），也可以排队等它干完（follow-up），还可以直接按 Escape 打断。

本文覆盖交互模式下的六个主题：启动与工作目录、提示输入与文件引用、斜杠命令、会话管理与分支、模型与思考等级、快捷键与诊断导出。

```text
交互模式三个记忆点：
1. 工作目录决定一切 —— 文件发现、项目配置、资源加载、会话分组都以它为锚
2. 三种插话方式 —— Enter 改方向（steering）、Alt+Enter 排队（follow-up）、Escape 打断
3. 一切可恢复 —— 会话是树，/tree 回到任意节点、/fork 分叉、pi --continue 续上
```

本机实测（2026-10-15，Pi 1.2.0）：

```text
$ pi --version
1.2.0
$ pi --list-models
No models available. Use /login to log into a provider via OAuth or API key. See:
  .../pi-coding-agent/docs/providers.md
```

交互界面本身需要有可用模型才能真正跑起来，本机未配置凭据，因此本文涉及模型回复的部分以官方文档为准，涉及命令、参数、快捷键与目录结构的部分均已用本机 `pi --help` 核对。

## 启动与工作目录

启动方式很简单：`cd` 到你想让它工作的目录，然后运行 `pi`。工作目录不是「可选项」，它是 Pi 的三条主线：**文件发现**（在哪里找 `AGENTS.md`、`.pi/`）、**配置作用域**（项目设置挂在这个目录上）、**会话分组**（同一目录的历史会话聚在一起，`--continue` 就是续它最近的一条）。

```bash
cd /path/to/project
pi                          # 进入交互式 TUI（stdin/stdout 是终端时的默认行为）
pi "列出 src 下所有 .ts 文件"   # 启动时带一个初始提示
pi --continue               # 续上当前目录最近的会话
pi --tui-mode regular       # 用终端原生滚动回看，而不是全屏模式
```

Pi 可能在加载项目资源前询问你是否信任这个工作目录。这个信任决定的作用范围是「是否加载项目级配置与资源」，**不是沙箱**——工具调用仍然使用 Pi 进程的操作系统权限。因此对陌生仓库先用 `pi -na`（忽略本项目级文件）或直接在容器里跑更稳妥。

```text
工作目录要点：
1. 目录即作用域 —— 换个目录就是换一套项目配置与会话分组
2. 首启会问信任 —— 项目级扩展、技能、package 会在信任通过后加载并执行
3. 默认全屏模式 —— fullscreen 固定编辑器与状态区，transcript 在窗口内滚动；regular 用终端原生 scrollback
4. 启动 header 会列资源 —— 加载了哪些指令文件与资源，一眼可见
5. 非交互自动降级 —— stdin 或 stdout 被重定向且未指定模式时，Pi 走 print 模式
```

## 提示输入与文件引用

editor 支持多行输入与文件/图片引用。写长提示时不必挤在终端里：`Ctrl+G` 会把当前内容丢进你配置的外部编辑器（`externalEditor` 设置、`$VISUAL`、`$EDITOR`，否则 nano）。

| 动作 | 操作 | 说明 |
|---|---|---|
| 发送 | `Enter` | 提交提示 |
| 换行 | `Shift+Enter` | 在编辑器内加一行 |
| 外部编辑器 | `Ctrl+G` | 用配置的编辑器写长提示 |
| 引用文件 | 输入 `@` | 模糊搜索文件并加入提示 |
| 补全路径 | `Tab` | 补全当前路径 |
| 粘贴图片 | `Ctrl+V` / 拖入终端 | 支持的终端可直接粘图片 |
| 执行 shell | 以 `!` 开头 | 命令输出会进入对话上下文 |
| 只执行不进上下文 | 以 `!!` 开头 | 跑命令但不把输出发给模型 |

```text
@src/scheduler/index.ts 解释这个文件的调度策略，并给出一个失败场景
```

```text
!git status                # 输出进入上下文，模型能看到
!!git log --oneline -50    # 只给你看，不占模型上下文
```

这两个前缀是交互模式里最实用的效率工具：`!` 适合「让模型基于真实状态推理」，`!!` 适合「我自己看一眼，别浪费 token」。另外 `@` 引用不是把文件内容立刻塞进上下文，而是把它作为消息内容的一部分随该轮提交。

```text
输入要点：
1. @ 引用比手打路径可靠 —— 它按默认忽略规则做模糊搜索，少踩路径拼写错误
2. Tab 补全路径 —— 在路径中间也能用
3. ! 与 !! 的区别就是上下文 —— 前者喂给模型，后者只给你看
4. Ctrl+G 救长提示 —— 终端里编辑几十行提示不现实，用外部编辑器
5. 图片按终端能力 —— 粘贴/拖拽依赖终端，不支持时用 @ 引用图片文件
```

## 常用斜杠命令

输入 `/` 会弹出命令搜索菜单。菜单内容 = 内置命令 + 扩展注册的命令 + 提示模板 + 技能命令（`/skill:name`，由 `enableSkillCommands` 控制是否出现在菜单里），所以**这个菜单就是你当前会话的准确参考**，比任何文档都准。

| 命令 | 作用 |
|---|---|
| `/settings` | 打开设置 |
| `/model [provider/model]` | 选择模型 |
| `/thinking [level]` | 设置思考等级 |
| `/scoped-models` | 配置 Ctrl+P 循环所用的模型集合 |
| `/login [provider]` / `/logout` | 添加 / 移除 provider 凭据 |
| `/new` | 开新会话 |
| `/resume` | 切到别的已保存会话 |
| `/name [name]` | 给当前会话起名 / 查看当前名 |
| `/session` | 显示当前会话文件、ID、消息数、token 用量与成本 |
| `/tree` / `/fork` / `/clone` | 会话树导航 / 从历史消息分叉 / 复制当前会话 |
| `/compact [instructions]` | 压缩上下文，可带自定义指令 |
| `/import <path>` | 导入并续跑一个 JSONL 会话 |
| `/copy` / `/export [path]` / `/share` | 复制上条回复 / 导出 HTML 或 JSONL / 上传并取查看链接 |
| `/trust` | 保存项目信任决定（对后续 Pi 进程生效） |
| `/reload` | 重新加载快捷键、扩展、技能、提示模板、主题与上下文文件 |
| `/hotkeys` | 查看当前会话生效的快捷键 |
| `/changelog` / `/quit` | 查看更新日志 / 退出 |

```text
/settings                     # 改偏好（也用于切换终端模式等）
/model                        # 打开模型选择器，Ctrl+S 存为该模型默认
/thinking high                # 当前会话直接用 high
/scoped-models                # 勾选 Ctrl+P 循环包含哪些模型，Ctrl+S 保存
/reload                       # 改了扩展/技能/提示模板/主题后重新加载
```

```text
斜杠命令要点：
1. 菜单即真相 —— 不同会话加载的资源不同，命令列表也不同
2. /reload 是改动后的必做动作 —— 手动改了设置、快捷键、指令或资源都要重载
3. /session 看成本 —— 消息数、token 用量、花费一次看全
4. 技能要强制时用 /skill:name —— 模型可能漏掉相关技能，显式调用可兜底
5. 扩展命令优先执行 —— 扩展命令在流式过程中也能立刻执行
```

## 会话管理与分支

Pi 默认自动保存会话（除非用 `--no-session`），存储位置默认在 `~/.pi/agent/sessions/` 下按工作目录分组。会话是**树**：每个条目有 ID 并指向父条目，最后一条就是当前活跃分支。回到早前的节点继续，不会删掉你离开的那条分支——这一点决定了 Pi 特别适合「同一个问题试两种方案」。

| 动作 | 命令 | 结果 | 什么时候用 |
|---|---|---|---|
| 树内移动 | `/tree` | 在同一会话文件内切换分支 | 相关方案希望留在同一份历史里 |
| 分叉 | `/fork` | 从某条用户消息起新建会话文件 | 另一条路要变成独立工作 |
| 克隆 | `/clone` | 把当前活跃分支复制成新会话 | 想要当前状态的独立副本 |
| 压缩 | `/compact` | 插入摘要条目，减少发给模型的历史 | 上下文接近上限但不想丢工作 |
| 换会话 | `/resume` | 打开会话选择器（可搜索、重命名、删除） | 回到别的历史任务 |

在 `/tree` 里选中一条用户消息，它的文本会回到编辑器；改完提交即产生新分支。选中助手回复或其它条目，则从该条目之后以空编辑器继续。离开一个分支时 Pi 可以生成分支摘要并附到你进入的分支上，这样既保留被放弃路上的结论，又不把每条消息都带进新上下文。

```bash
# 离开 Pi 之后怎么续上
pi --continue                   # 续当前目录最近一条会话
pi --resume                     # 打开会话选择器
pi --session <path|id>          # 按文件路径或 ID 打开（支持部分 ID）
pi --session-id feat-payment    # 精确 ID 打开，不存在就创建
pi --fork <path|id>             # 把已有会话分叉到当前项目的新会话
pi --no-session                 # 临时会话，退出即消失
```

```text
会话要点：
1. 树不是线性历史 —— /tree 回退不丢分支，/fork 与 /clone 才另起文件
2. --continue 认目录 —— 它续的是"当前工作目录最近一条"，跨目录不会串
3. 自动压缩默认开 —— 接近模型上限时自动摘要旧历史，原始条目仍在文件里
4. 会话位置三级覆盖 —— --session-dir > PI_CODING_AGENT_SESSION_DIR > sessionDir 设置
5. --fork 有组合限制 —— 不能与 --session / --continue / --resume / --no-session 同时用
```

## 模型与思考等级切换

模型（model）产生回复，provider 是访问模型的账号或服务。切换模型有四种入口：`/model` 打开选择器、`Ctrl+L` 打开同一个选择器、`Ctrl+P` 在已配置集合里循环、启动参数 `--model`。思考等级（thinking level）是另一个维度：它控制当前模型用多少推理预算，可选 `off`、`minimal`、`low`、`medium`、`high`、`xhigh`、`max`，实际可选值会被模型能力裁剪。

| 动作 | 交互操作 | 说明 |
|---|---|---|
| 选模型 | `/model` 或 `Ctrl+L` | 选择器只列出凭据可用的模型 |
| 存默认模型 | 选择器内 `Ctrl+S` | 写入设置，新会话默认用它 |
| 循环模型 | `Ctrl+P` / `Shift+Ctrl+P` | 用 `/scoped-models` 或 `enabledModels` 定义循环集合 |
| 选思考等级 | `/thinking` 或 `Shift+Tab` 循环 | 只列出当前模型支持的等级 |
| 存默认思考等级 | `/thinking` 内 `Ctrl+S` | 写入 `defaultThinkingLevel` |
| 折叠思考块 | `Ctrl+T` | 显示或隐藏 thinking 内容 |

启动时也可以用参数一次性指定，`:thinking` 后缀是常用简写：

```bash
pi --model sonnet:high                     # 选模型并直接给思考等级
pi --provider anthropic --model sonnet:high # 限定在某 provider 内查找
pi --models 'anthropic/*,*sonnet*'          # 定义 Ctrl+P 的循环集合（支持 glob）
pi --thinking medium --model gpt-5          # 显式指定思考等级（覆盖 --model 后缀）
pi --list-models sonnet                     # 只列出匹配的模型并退出
```

会话会记录模型与思考等级的变化，恢复会话时一并还原，但**不会改动新会话的默认值**——这是「实验用一套、日常用一套」的基础。

```text
模型与思考要点：
1. 四个入口同一份列表 —— /model、Ctrl+L、Ctrl+P 循环、--model 参数
2. Ctrl+S 才会变成默认 —— 只切不存，新会话仍用旧默认
3. 思考等级按模型裁剪 —— 低能力模型上选 high 会被 clamp 到它支持的上限
4. 循环集合可控 —— /scoped-models 或 enabledModels 决定 Ctrl+P 会经过哪些模型
5. 会话记住切换 —— 恢复会话恢复模型与等级，但不污染新会话默认
```

## 快捷键与终端显示

快捷键可在 `keybindings.json` 里按「动作 id」重绑，`/hotkeys` 查看当前生效值。下面是最常用的默认值（官方 Keybindings 参考，本机 1.2.0 的 `pi --help` 与之一致地确认了交互模式存在这些入口）。

| 动作 id | 默认键 | 说明 |
|---|---|---|
| `app.interrupt` | `Escape` | 中止当前任务 |
| `app.clear` | `Ctrl+C` | 第一次清空编辑器，第二次退出 |
| `app.exit` | `Ctrl+D` | 编辑器为空时退出 |
| `app.suspend` | `Ctrl+Z` | 挂起到后台（Windows 无默认值） |
| `app.editor.external` | `Ctrl+G` | 打开外部编辑器 |
| `app.model.select` | `Ctrl+L` | 打开模型选择器 |
| `app.model.cycleForward` | `Ctrl+P` | 切到下一个模型 |
| `app.thinking.cycle` | `Shift+Tab` | 循环思考等级 |
| `app.thinking.toggle` | `Ctrl+T` | 折叠/展开思考块 |
| `app.tools.expand` | `Ctrl+O` | 折叠/展开工具输出 |
| `app.message.copy` | `Ctrl+X` | 复制上条助手回复（在 /tree 里复制选中消息） |
| `app.message.followUp` | `Alt+Enter` | 排队 follow-up 消息 |
| `app.message.dequeue` | `Alt+Up` | 把排队的消息退回编辑器 |

模型干活时的插话行为值得单独记住：用 `Enter` 发的消息会等当前回复及其工具调用结束后，用来引导下一轮回复（steering）；用 `Alt+Enter` 发的会等整个任务跑完才进入（follow-up）；`Alt+Up` 把还没投递的消息退回编辑器；`Escape` 结束当前任务并让排队消息回到编辑器。

```text
# 运行中插话的三个层次（同一张图记住）
Enter       → 当前回合工具跑完即插话，改方向
Alt+Enter   → 排队，等 Pi 干完当前任务再处理
Escape      → 中止，未投递的排队消息退回编辑器
```

终端显示有两种模式：**fullscreen**（默认，编辑器与状态区固定，transcript 在窗口内滚动）与 **regular**（使用终端原生 scrollback）。切换方式是 `/settings` 或启动参数 `--tui-mode regular`。鼠标、快捷键、内联图片的支持度随终端不同，Windows Terminal 还占用了一部分 Alt 组合键，需要时改绑。

```text
快捷键要点：
1. 先看 /hotkeys —— 扩展和配置都会改绑定，别死记默认值
2. Edit 与 Cycle 要分清 —— Ctrl+P 是切换模型，Ctrl+T 是折叠思考，Ctrl+O 是展开工具输出
3. 中断不丢消息 —— Escape 会把排队消息放回编辑器，不会静默丢弃
4. 终端模式按习惯选 —— 想用终端 scrollback 就用 regular
5. 重绑只改 id —— keybindings.json 按动作 id 绑定，与 UI 文案解耦
```

## 导出分享与诊断

会话既能导出成文件，也能上传成可分享的链接。导出用 `/export`（HTML 或 JSONL），分享用 `/share`：默认在配置了 Radius 认证时上传为 Radius artifact，否则通过 GitHub CLI 创建私有 gist；`sessionShareDestination` 设置成 `gist` 或 `radius` 可以强制其一。**导出与分享之前一定要审阅**——会话里包含提示词、模型回复、工具参数、命令输出、文件内容，甚至是对话过程中暴露过的凭据。

```text
/copy                          # 复制上一条助手回复
/export ~/notes/session.html   # 导出为 HTML（省略路径则自动推导目标）
/export ~/notes/session.jsonl  # 导出为 JSONL（原始会话格式）
/share                         # 上传并得到查看链接
/bug 描述一下问题              # 生成给 Pi 开发者的私有 bug 报告
/debug                         # 把渲染的终端行与当前会话消息写入 pi-debug.log
```

`/debug` 的输出落在代理目录下的 `pi-debug.log`，排查终端渲染或会话状态问题时用它。它同样可能包含提示、回复、工具输出与终端数据，贴出去之前先看一遍。

```json
{
  "$schema": "https://pi.dev/schemas/settings.schema.json",
  "sessionShareDestination": "gist"
}
```

```text
导出与诊断要点：
1. 先审阅再分享 —— 会话含文件内容与命令输出，等于把你当时看到的一切都上传了
2. 目的地可强制 —— sessionShareDestination 设为 gist 或 radius，避免"自动"带来的意外
3. 两种格式各有用途 —— HTML 给人看，JSONL 给脚本或复盘工具吃
4. /debug 是渲染排障入口 —— 输出在 <agent-dir>/pi-debug.log
5. /bug 也是数据外发 —— 它可以带上会话转录，上传前确认内容
```

## 应用场景实战

### 场景一：用 /tree 与 /fork 并行验证两种重构方案

场景：一个模块有两种重构思路，你不希望把两条线的上下文混在一起，也不希望重开一轮对话重新解释背景。做法是先在同一个会话里试方案 A，然后从分叉点开方案 B。

```text
# 第 1 步：建立共同背景（这一步只做一次）
@src/billing/README.md @src/billing/calc.ts 说明现有计费逻辑与主要痛点

# 第 2 步：方案 A —— 原地改
把计费逻辑拆成纯函数与 IO 两层，保持公开 API 不变

# 第 3 步：回到最初那条消息，开方案 B
/tree                      # 选中第 1 步那条用户消息，文本回到编辑器
/fork                      # 从这条消息分叉出一个新会话，避免污染原文
把计费逻辑改成策略模式，新增 discount 策略，公开 API 允许小改动
```

```text
预期结果：
1. /tree 不删除方案 A 的分支，两条路都在同一份会话文件里
2. /fork 之后是独立会话文件，可以分别 /name billing-refactor-a 和 -b
3. 两个会话都能 pi --continue 续跑，都会记住各自的模型与思考等级
4. 离开方案 A 分支时 Pi 可生成分支摘要，把它附加到方案 B 的起点上
```

```text
要点：
1. 共同背景只解释一次 —— 分叉点选在"背景消息"之后，省掉重复叙述
2. 同一份历史用 /tree，独立工作用 /fork —— 前者留在一起便于对比，后者避免互相干扰
3. 分支摘要保留结论 —— 放弃的路径上有价值的判断不会全丢
4. 记得命名会话 —— /name 让 /resume 选择器里一眼能认出两条线
5. 用 git 做最终对比 —— 会话记录过程，代码差异由 git diff 给出
```

### 场景二：接手陌生仓库时的交互式摸底

场景：你刚被拉进一个没有文档的仓库，需要 20 分钟内搞清楚入口、构建方式与危险操作。目标是把「读代码 + 跑命令 + 记结论」压在一次交互会话里完成。

```text
# 1. 启动前先自己看一眼根目录（不进模型上下文）
!!ls -la

# 2. 让模型读关键文件，并把命令输出作为事实来源
@README.md @package.json @Makefile 这个仓库怎么构建、怎么跑测试？

# 3. 用真实命令验证它的说法（输出会进上下文，模型能自我纠正）
!make test

# 4. 让它列出"改之前必须先知道的风险点"
列出改动 build/ 与 deploy/ 目录时必须注意的风险点，按严重程度排序

# 5. 把结论落到文件，避免会话丢失后重做
把上面的风险点整理成 docs/onboarding.md，只写这一个文件
```

```text
预期结果：
1. 第 2 步模型会引用你 @ 引用的文件内容，而不是凭经验猜构建方式
2. 第 3 步的测试输出进入上下文后，模型能纠正自己之前的错误判断
3. 第 4 步产出按严重程度排序的风险清单，可直接进 onboarding 文档
4. 第 5 步只改一个文件，git diff 一眼可审
5. 退出时用 /session 确认 token 用量与成本，为后续类似任务留个标尺
```

```text
要点：
1. !! 与 ! 分工 —— 自己看的用 !!，给模型当事实的全部用 !
2. @ 精确引用胜过让它自己找 —— 大仓库里模糊搜索很贵
3. 让模型基于真实输出自我纠正 —— 这是 agent 相比问答的核心优势
4. 结论落到文件 —— 会话是过程记录，仓库里需要的是可传播的产物
5. 用 /session 看成本 —— 摸底类任务的成本标尺值得记录，便于下次预算
```

## 最佳实践与踩坑记录

### 最佳实践

1. 永远从正确的工作目录启动：目录决定文件发现、项目配置与会话分组，进错目录会得到「什么都没加载」的奇怪现象。
2. 用 `Alt+Enter` 排队而不是打断：模型正在跑一串工具调用时，`Enter` 插话会改变它的方向，`Alt+Enter` 则安全排队。
3. 改动资源后 `/reload`：手动编辑设置、快捷键、`AGENTS.md`、扩展或技能后必须重载才生效。
4. 频繁用 `/name` 命名会话：`/resume` 选择器里一堆无标题会话几乎无法管理。
5. 分享或导出前先审阅：会话包含文件内容与命令输出，`/export`、`/share`、`/bug`、`/debug` 都是数据外发通道。
6. 长会话主动 `/compact`：与其等自动压缩，不如在切换主题时手动压缩并带上一句「保留哪些结论」。

### 踩坑记录

```text
坑 1：在错误的目录启动 pi，项目规则全没加载
结论：AGENTS.md、.pi/ 配置、项目技能都像是"不存在"，会话历史也找不到。
原因：工作目录同时决定资源发现范围与会话分组。
解法：始终 cd 到项目根后再启动；确认方法看启动 header 列出的已加载资源。

坑 2：模型跑到一半按 Enter 发消息，结果方向被带偏
结论：原本的任务被中途改向，结果两头都没做完。
原因：Enter 发送的是 steering 消息，它在当前回合工具调用结束后立即进入。
解法：要补充任务用 Alt+Enter 排队（follow-up）；要中止就 Escape，排队消息会被退回编辑器。

坑 3：手改了扩展或 AGENTS.md，当前会话毫无反应
结论：磁盘上文件已更新，会话里行为仍是旧的。
原因：资源在启动时加载进进程，运行中不会自动重新读取。
解法：执行 /reload；扩展重载会替换整个运行时，不要依赖旧运行时的状态。

坑 4：以为切了模型就改了默认，重启后又变回去
结论：新会话仍然用旧模型与旧思考等级。
原因：选择器里的切换只作用于当前会话，只有按 Ctrl+S 才会写入默认设置。
解法：在选择器里 Ctrl+S 保存默认；或在 settings.json 里设 defaultModel / defaultThinkingLevel。

坑 5：把 /share 生成的链接直接发到外部群
结论：会话中的文件内容、命令输出甚至过程中的凭据一起被公开。
原因：/share 上传的是完整会话，/export 与 /bug 同理。
解法：分享前通读会话；用 sessionShareDestination 固定目的地；敏感内容改用 /copy 只贴结论。
```

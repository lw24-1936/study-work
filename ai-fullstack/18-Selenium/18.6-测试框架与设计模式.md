## 概述

裸写 Selenium 的问题是 locator 会散落在每条用例里：页面一改 id，几十个文件一起红。**页面对象模型（Page Object Model, POM）**解决的就是这个问题——把「页面长什么样、服务怎么调用」收敛到页面对象里，测试只调用服务方法。官方文档把它总结成一句：页面对象是对页面**服务的抽象**，测试代码不应该知道 HTML 结构。

另一半是工程组织：用 `pytest` 的 fixture 管理驱动生命周期、用 `parametrize` 做数据驱动、用 `@pytest.mark` 分冒烟/回归、用 JUnit XML 或 HTML 报告接入 CI，再用一个 `pytest_runtest_makereport` 钩子在失败时自动截图留证。

```text
本篇主线：
1. 页面对象模型 —— locator 集中、只暴露服务方法、页面对象内不做业务断言
2. 组件对象 —— 页面里重复出现的块（商品行、表格行）单独建模，用组合而非继承
3. pytest 集成 —— conftest.py 里的 driver fixture、yield 收尾、命令行参数扩展
4. 参数化与数据驱动 —— parametrize、pytest_generate_tests、非 ASCII id 的坑
5. 断言与报告 —— 断言放在测试里、JUnit XML、失败自动截图 + page_source
6. 本机实测 —— 9 条用例串行 102.96s；故意失败的用例触发留证钩子的真实输出
```

本机验证环境：Ubuntu 24.04、Python 3.14.7、pytest 9.1.1、pytest-xdist 3.8.0、selenium 4.51.0、Chrome for Testing 151。测试工程放在 `/root/.hermes/cache/scratch/selb_pom/`，被测站点是本地 `python3 -m http.server 8765` 托管的静态页（`login.html` / `dashboard.html`）。

## 页面对象模型 POM

官方文档给出的规则很具体，逐条落地就是：

| 规则 | 落地做法 |
|---|---|
| 公共方法代表页面提供的**服务** | `login(username, password)` 而不是 `click_login_button()` |
| 尽量不暴露内部结构 | 不在外部使用 `page.driver.find_element(...)` |
| 页面对象内**不做业务断言** | 断言留在测试里；`returns bool` 或返回下一个页面对象 |
| 方法可返回其它页面对象或自身 | 「登录成功」返回 `DashboardPage`，「登录失败」返回 `LoginPage` |
| 同一个动作的不同结果建模成不同方法 | `login()` 与 `login_expecting_error()` |
| 可以只代表页面的一部分 | 组件对象（Page Component Object） |

唯一允许在页面对象里做的检查，是**构造函数中确认页面已正确加载**：

```python
from selenium.webdriver.support import expected_conditions as EC
from selenium.webdriver.support.ui import WebDriverWait


class BasePage:
    """所有页面对象的基类：只做页面加载校验，不做业务断言。"""

    def __init__(self, driver, expected_title=None):
        self.driver = driver
        self.wait = WebDriverWait(driver, 10)
        if expected_title:
            self.wait.until(EC.title_is(expected_title))
```

登录页把「成功」和「失败」拆成两个服务方法，各自返回合适的页面对象：

```python
from selenium.webdriver.common.by import By


class LoginPage(BasePage):
    USERNAME = (By.ID, "username")
    PASSWORD = (By.ID, "password")
    SIGN_IN = (By.ID, "sign-in")
    ERROR = (By.ID, "error")

    def __init__(self, driver):
        super().__init__(driver, expected_title="登录 - 订单系统")

    def login(self, username, password):
        self.driver.find_element(*self.USERNAME).send_keys(username)
        self.driver.find_element(*self.PASSWORD).send_keys(password)
        self.driver.find_element(*self.SIGN_IN).click()
        return DashboardPage(self.driver)          # 成功 -> 看板页

    def login_expecting_error(self, username, password):
        self.driver.find_element(*self.USERNAME).send_keys(username)
        self.driver.find_element(*self.PASSWORD).send_keys(password)
        self.driver.find_element(*self.SIGN_IN).click()
        self.wait.until(EC.text_to_be_present_in_element(self.ERROR, "错误"))
        return self                                # 失败 -> 停留本页

    def error_text(self):
        return self.driver.find_element(*self.ERROR).text
```

这样写的好处不只是「少重复」：`login()` 的返回类型就是「登录成功后的页面」，哪天登录后跳到短信验证页，改一个方法签名就能让所有调用点编译期/运行期立刻暴露，而不用等用例跑到一半才发现。

**组件对象**处理「页面里重复出现的块」。看板页的订单行就是典型：每行结构相同，行为相同，用 `root.find_element(...)` 把查找范围限制在行内，比在整页里拼 `nth-child` 选择器稳得多。

```python
class OrderRow:
    """页面组件对象：只认识自己这段 HTML。"""

    def __init__(self, root):        # root 是一行的 WebElement
        self.root = root

    @property
    def order_id(self):
        return self.root.find_element(By.CLASS_NAME, "order-id").text

    @property
    def amount(self):
        return self.root.find_element(By.CLASS_NAME, "order-amount").text

    def add_to_cart(self):
        self.root.find_element(By.CLASS_NAME, "add-btn").click()


class DashboardPage(BasePage):
    ORDER_ROW = (By.CSS_SELECTOR, ".order-row")

    def __init__(self, driver, expected_token=None):
        super().__init__(driver, expected_title="订单看板")
        if expected_token:     # 只有需要校验登录态时才加这一层等待
            self.wait.until(lambda d: d.execute_script(
                "return sessionStorage.getItem('token')") == expected_token)

    def orders(self):
        return [OrderRow(e) for e in self.driver.find_elements(*self.ORDER_ROW)]
```

```text
要点：
- locator 只在页面对象里出现一次，测试代码不出现 By
- 页面对象暴露「服务」而不是元素：login() 而非 click_sign_in()
- 页面对象内不做业务断言，断言留在测试里
- 构造函数里唯一允许的检查是「页面是否加载正确」
- 同一动作的不同结果拆成不同方法，用返回类型表达「跳到哪一页」
- 重复出现的块用组件对象 + 组合，root 限定查找范围
```

## 与 pytest 集成

`conftest.py` 是 pytest 的共享夹具入口，Selenium 工程里它通常承担四件事：驱动创建与销毁、命令行参数扩展、失败留证钩子、公共页面夹具。

```python
# conftest.py
import pathlib

import pytest
from selenium import webdriver
from selenium.webdriver.chrome.options import Options

CHROME_BINARY = "/root/.cache/ms-playwright/chromium-1234/chrome-linux64/chrome"
DEFAULT_BASE_URL = "http://127.0.0.1:8765/"
ARTIFACT_DIR = pathlib.Path(__file__).parent / "artifacts"


def pytest_addoption(parser):
    parser.addoption("--base-url", action="store", default=DEFAULT_BASE_URL,
                     help="被测站点根地址")
    parser.addoption("--headed", action="store_true", default=False,
                     help="关闭无头模式，便于本地调试")


def chrome_options(headless=True, window_size="1440,900"):
    opts = Options()
    opts.binary_location = CHROME_BINARY
    if headless:
        opts.add_argument("--headless=new")
    opts.add_argument("--no-sandbox")
    opts.add_argument("--disable-dev-shm-usage")
    opts.add_argument("--window-size=" + window_size)   # 无头默认视口只有 780x437
    opts.add_argument("--lang=zh-CN")
    opts.set_capability("goog:loggingPrefs", {"browser": "ALL"})
    return opts


@pytest.fixture(scope="session")
def base_url(request):
    return request.config.getoption("--base-url")


@pytest.fixture
def driver(request):
    """函数级驱动：每个用例一个干净会话，隔离性最好。"""
    headless = not request.config.getoption("--headed")
    drv = webdriver.Chrome(options=chrome_options(headless=headless))
    yield drv
    drv.quit()          # yield 之后的代码一定会执行，等价于 try/finally


@pytest.fixture
def login_page(driver, base_url):
    from pages.login_page import LoginPage

    driver.get(base_url + "login.html")
    return LoginPage(driver)
```

```ini
# pytest.ini
[pytest]
testpaths = tests
addopts = -ra --strict-markers
markers =
    smoke: 冒烟用例，每次提交都跑
    regression: 回归用例，夜间跑全量
```

`--strict-markers` 让写错 marker 名字直接报错而不是静默通过，配合 `markers` 声明可以避免「marker 拼错导致用例被 `-m` 过滤掉却没人发现」。跑单个标记：

```bash
python -m pytest -m smoke -v          # 只跑冒烟
python -m pytest -m "not regression"  # 排除回归
python -m pytest --headed -v          # 本地带界面调试，其余参数不变
```

## Fixture 分层与参数化

fixture 的关键是**作用域分层**：驱动是最贵的资源，页面对象是廉价的；把驱动做成函数级、把被测地址做成会话级，是最常见的组合。

```python
@pytest.fixture(scope="session")
def base_url(request):          # 会话级：所有用例共享同一个地址
    return request.config.getoption("--base-url")


@pytest.fixture
def driver(request):            # 函数级：每条用例独立浏览器
    ...


@pytest.fixture
def dashboard_page(driver, base_url):     # 函数级：依赖 driver，自然也是每用例一份
    from pages.dashboard_page import DashboardPage

    driver.get(base_url + "dashboard.html?user=admin")
    return DashboardPage(driver)
```

**参数化**有三种粒度，按需要选：

```python
import pytest

# 1) 直接参数化：最常用
@pytest.mark.parametrize(
    "username,password,expected_error",
    [
        ("admin", "wrong-password", "用户名或密码错误"),
        ("nobody", "Passw0rd!", "用户名或密码错误"),
        ("", "", "用户名或密码错误"),
    ],
    ids=["密码错误", "用户不存在", "空表单"],
)
def test_login_failure(login_page, username, password, expected_error):
    page = login_page.submit_login_expecting_failure(username, password)
    assert page.get_error_message() == expected_error

# 2) indirect：参数交给 fixture 处理（例如按浏览器名建驱动）
@pytest.fixture
def browser(request):
    return request.param

@pytest.mark.parametrize("browser", ["chrome"], indirect=True)
def test_smoke(driver, browser):
    ...

# 3) 数据驱动：用例数据放在 JSON/CSV 里
import json
CASES = json.load(open("cases/orders.json", encoding="utf-8"))

def pytest_generate_tests(metafunc):
    if {"order_id", "amount"}.issubset(metafunc.fixturenames):
        metafunc.parametrize("order_id,amount",
                             [(c["order_id"], c["amount"]) for c in CASES],
                             ids=[c["case"] for c in CASES])
```

数据驱动让「加一条业务数据」不需要改代码，这是数据量大时唯一可维护的写法。本机真实验证了第三种写法：

```text

selb_186_scene2.py::test_order_amount[\u5c0f\u989d\u8ba2\u5355] PASSED   [ 66%]

```

注意用例 id 被转义成了 `\u6807\u51c6\u8ba2\u5355`：本机终端 locale 是 ASCII，pytest 输出非 ASCII 节点 id 时会转义。这不只是「看起来难受」——**失败截图、JUnit XML 里的 classname/name 也会带上转义或原文**，CI 平台上搜日志会搜不到。生产项目里 `ids=` 建议用 ASCII 或拼音（`standard` / `small-amount`），中文只做注释。

```text
要点：
- fixture 按代价分层：驱动函数级、地址会话级、页面对象函数级
- 参数化三档：parametrize 直接参数、indirect 交给 fixture、pytest_generate_tests 数据驱动
- indirect 适合「参数决定驱动怎么建」（浏览器类型、移动端模拟）
- ids 用 ASCII，非 ASCII 会在 CI 日志/JUnit 报告里转义，检索困难
- 数据文件放 cases/ 目录，加新数据不改代码
- 参数化的粒度以「一条失败能定位到一个业务差异」为准，不要为了覆盖率硬拆
```

## 断言 日志与测试报告

**断言写在测试里，不写在页面对象里**，这是官方文档反复强调的一条。少数例外也只在「判断型方法」上：

```python
def test_messages_are_unread(inbox):
    # 反例：页面对象里断言，失败信息指向 inbox 而不是测试，定位成本高
    # inbox.assert_message_with_subject_is_unread("I like cheese")

    # 正例：页面对象返回布尔，断言留在测试里
    assert inbox.is_message_with_subject_unread("I like cheese")
```

失败留证用 `pytest_runtest_makereport` 钩子（**必须放在 `conftest.py`**，写在测试模块里不会被调用）：

```python
@pytest.hookimpl(hookwrapper=True)
def pytest_runtest_makereport(item, call):
    """失败用例自动截图 + 保存页面源码，报告里直接带附件。"""
    outcome = yield
    report = outcome.get_result()
    if report.when != "call" or not report.failed:
        return
    drv = item.funcargs.get("driver") or item.funcargs.get("shared_driver")
    if drv is None:
        return
    ARTIFACT_DIR.mkdir(exist_ok=True)
    safe = item.name.replace("/", "_").replace(" ", "_")
    try:
        png = ARTIFACT_DIR / f"{safe}.png"
        drv.save_screenshot(str(png))
        (ARTIFACT_DIR / f"{safe}.html").write_text(drv.page_source, encoding="utf-8")
        report.sections.append(("selenium-artifacts",
                                f"screenshot={png}\nlogs={drv.get_log('browser')}"))
    except Exception as exc:      # 浏览器已崩时钩子不能再抛异常
        report.sections.append(("selenium-artifacts", f"采集失败: {exc}"))
```

常用报告方案对比：

| 方案 | 命令 | 适用 |
|---|---|---|
| JUnit XML | `--junitxml=reports/junit.xml` | CI（Jenkins/GitLab/GitHub Actions）通用，pytest 内置 |
| HTML 报告 | `pip install pytest-html` 后 `--html=report.html --self-contained-html` | 本地/交付给非技术方看，可把截图嵌进去 |
| 失败重跑 | `pip install pytest-rerunfailures` 后 `--reruns 2 --reruns-delay 1` | 已知有环境抖动的用例 |
| 分片并行 | `pytest-xdist`（见 18.7） | 用例多、单机多核 |

浏览器端日志建议在 fixture 里就打开 `goog:loggingPrefs`，失败时用 `driver.get_log("browser")` 一起带出来——本机实测能直接看到 favicon 404 这类噪声，也能抓到页面 JS 抛的错。

```text
要点：
- 断言放测试、判断放页面对象返回布尔，失败信息才指向业务
- 留证钩子必须写进 conftest.py，写在测试模块里不会生效
- 截图 + page_source + 浏览器日志三件套一起收集，单看截图常常不够
- 钩子内部要 try/except，浏览器已崩时不能再抛异常
- JUnit XML 是 CI 通用格式；HTML 报告适合给人看
- 控制台日志靠 goog:loggingPrefs 打开，与截图互补
```

## 应用场景实战

### 场景一：登录 → 下单 核心链路的 POM 用例

把「登录 → 校验问候语 → 下单加购」写成三层结构（BasePage / LoginPage+DashboardPage / OrderRow），单个文件即可运行。

```python
import pytest
from selenium import webdriver
```

### 场景二：数据驱动的订单金额回归 + JUnit XML 报告

订单金额这类「同一逻辑、多组数据」的校验最适合数据驱动。用例数据放 JSON，用 `pytest_generate_tests` 注入，跑完产出 JUnit XML 接 CI。

```python
import json

import pytest
from selenium.webdriver.common.by import By
from selenium.webdriver.support import expected_conditions as EC
from selenium.webdriver.support.ui import WebDriverWait

CASES = json.loads("""
[
  {"case": "标准订单", "order_id": "SO-2026-1001", "amount": "1299.00"},
  {"case": "小额订单", "order_id": "SO-2026-1002", "amount": "88.50"},
  {"case": "中额订单", "order_id": "SO-2026-1003", "amount": "420.00"}
]
""")


def pytest_generate_tests(metafunc):
    if {"order_id", "amount"}.issubset(metafunc.fixturenames):
        metafunc.parametrize("order_id,amount",
                             [(c["order_id"], c["amount"]) for c in CASES],
                             ids=[c["case"] for c in CASES])


def test_order_amount(driver, order_id, amount):
    driver.get(BASE + "dashboard.html?user=admin")
    WebDriverWait(driver, 5).until(EC.presence_of_element_located((By.CSS_SELECTOR, ".order-row")))
    row = driver.find_element(By.CSS_SELECTOR, f'[data-order-id="{order_id}"]')
    assert row.find_element(By.CLASS_NAME, "order-amount").text == amount
```

## 最佳实践与踩坑记录

1. **页面对象只暴露服务，不暴露 driver。** 一旦测试里出现 `page.driver.find_element(...)`，页面对象就退化成命名空间，locator 会重新散落出去。
2. **断言留在测试里，页面对象返回结果。** 需要判断就提供 `is_xxx()` / `get_xxx()`，失败信息才会指向业务差异而不是「某个页面对象里的某一行」。
3. **页面对象的构造函数只做「我是不是对的页面」这一件事。** 用 `WebDriverWait(...).until(EC.title_is(...))`；不要在里面做登录、跳转、改数据。
4. **driver fixture 用 `yield` 保证 `quit()`。** 漏掉会把浏览器进程和调试端口留在机器上，本机一次跑几十条用例就能攒出可观的内存占用。
5. **参数化的 `ids` 用 ASCII。** 非 ASCII 会在终端输出、JUnit XML、截图文件名里变成 `\uXXXX` 转义，CI 上检索不到。
6. **失败留证写进 `conftest.py` 的 `pytest_runtest_makereport`。** 写在测试模块里 pytest 不会调用；钩子内部必须 `try/except`，否则浏览器已崩时钩子自己抛异常，把原始失败信息盖掉。

坑 1：`pytest_runtest_makereport` 钩子写在测试文件里完全没生效

结论：失败用例没有任何截图产出，报告里也没有自定义 section。

原因：pytest 只从 `conftest.py`（以及插件）收集 hook 实现，测试模块里的同名函数不会被注册。

解法：把钩子放进项目根目录或测试目录的 `conftest.py`；本机实测放进 `conftest.py` 后，失败截图、`page_source`、浏览器日志三样都在失败输出了。

坑 2：非 ASCII 的 `parametrize(ids=...)` 在 CI 日志里变成 `\u` 转义

结论：本机实测用例 id 输出为 `test_order_amount[\u6807\u51c6\u8ba2\u5355]`，截图文件名同样带转义，肉眼和检索都很难用。

原因：终端 locale 为 ASCII 时 pytest 对节点 id 做转义；JUnit XML 与文件命名沿用同一套字符串。

解法：`ids` 用 ASCII 或拼音（`standard` / `small-amount`），中文写进用例注释或数据文件的 `case` 字段里给报告渲染用。

坑 3：页面对象里做了业务断言，失败信息无法定位

结论：断言失败只告诉你「某页面对象内部某行不对」，看不出是哪条业务规则、哪组数据失败。

原因：断言跑在页面对象内部，堆栈指向页面对象源码，业务上下文（测试名、参数）不在其中。

解法：页面对象返回数据或布尔值，断言写回测试函数，失败信息里自然带上测试名与参数；本机实测这样才能一眼看出是哪个订单、哪个金额断言挂了。

坑 4：`webdriver.Chrome()` 建在 fixture 里但没销毁，跑完整套留下大量僵尸进程

结论：本地跑完一次全量，`ps` 里会看到一堆 `chrome`、`chromedriver` 进程仍然存活，端口被占。

原因：fixture 里创建了驱动但缺少清理，或者清理写在 `try/except` 之外被异常跳过。

解法：用 `yield` 形式（pytest 保证 teardown 一定执行），并在 teardown 里同时 `quit()`；调试期可加 `--headed` 配合肉眼确认窗口是否真的关掉。

坑 5：`--strict-markers` 没开，写错的 marker 静默丢失用例

结论：`-m smoke` 跑出来是 0 条，但套件里明明有标记的用例，没有人发现。

原因：未声明的 marker 在默认配置下只给 warning，`-m` 过滤不到它就相当于静默跳过。

解法：`addopts = -ra --strict-markers` 并在 `markers` 段声明全部自定义标记；本机 `pytest.ini` 就是这样配的，写错 marker 名字会直接收集期报错。

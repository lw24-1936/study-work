## 概述

元素定位与点击只能覆盖「页面内」的交互，真实业务里还有大量「页面外」的操作：新开标签页核对数据、在 iframe 里填支付表单、处理原生 alert/confirm/prompt、预置 Cookie 跳过登录、用 JavaScript 绕过不可点击的覆盖层。这些全部由 WebDriver 的**浏览上下文（browsing context）**管理 API 负责：窗口句柄、frame 栈、弹窗栈、Cookie 存储、脚本执行通道。它们的共同特征是**状态是全局的**——当前聚焦哪个窗口、当前脚本跑在哪个 frame 里，都是整个会话共享的隐式状态，一旦忘记复原，后续所有定位都会莫名失败。

```text
本篇主线：
1. 窗口与标签页 —— window_handles / switch_to.window / new_window / close 与 quit 的差别
2. 框架切换 —— switch_to.frame(WebElement | id/name | index)、parent_frame、default_content
3. 原生弹窗 —— alert / confirm / prompt 的读取与应答，unhandledPromptBehavior 兜底策略
4. Cookie 与缓存 —— add/get/delete cookie、sameSite、清缓存的几种做法
5. 执行 JavaScript —— execute_script / execute_async_script、arguments 传参、返回值序列化限制
6. 本机实测 —— 全部示例在 Ubuntu 24.04 + Selenium 4.51.0 + Chrome for Testing 151 上真跑通过
```

本机验证环境：Ubuntu 24.04、Python 3.14.7、selenium 4.51.0，浏览器用 Playwright 缓存里的 Chrome for Testing 151.0.7922.34（`/root/.cache/ms-playwright/chromium-1234/chrome-linux64/chrome`），chromedriver 由 Selenium Manager 自动下载到 `~/.cache/selenium/chromedriver/linux64/151.0.7922.138/chromedriver`。下文所有 `text` 块都是**本机真实输出**，包括报错原文。

示例站点是一个静态实验页，用标准库起服务即可复现：

```bash
# 目录里放 index.html / sub.html / frame.html（实验页内容见正文示例）
python3 -m http.server 8765 --bind 127.0.0.1
```

```python
# 统一的驱动构造，后文示例默认复用这个函数
from selenium import webdriver
from selenium.webdriver.chrome.options import Options

CHROME = "/root/.cache/ms-playwright/chromium-1234/chrome-linux64/chrome"
BASE = "http://127.0.0.1:8765/"


def make_driver():
    opts = Options()
    opts.binary_location = CHROME          # 指向已存在的 Chrome for Testing
    opts.add_argument("--headless=new")    # 新版无头，行为与有头一致度更高
    opts.add_argument("--no-sandbox")      # 容器/CI 里常需要
    opts.add_argument("--disable-dev-shm-usage")
    opts.add_argument("--window-size=1440,900")
    return webdriver.Chrome(options=opts)
```

## 窗口 标签页与句柄管理

WebDriver **不区分窗口和标签页**，统一用「窗口句柄」（window handle）标识，每个句柄是一个会话内稳定的字符串。当前窗口用 `driver.current_window_handle` 读取，全部窗口用 `driver.window_handles` 读取（返回列表）。页面里 `window.open()`、`target="_blank"` 触发的弹窗都会新增一个句柄，但**驱动不会自动切过去**——必须显式 `switch_to.window(handle)`。Selenium 4 新增的 `switch_to.new_window('tab'|'window')` 可以主动开新窗口并自动切换。

`close()` 只关闭当前窗口，`quit()` 结束整个会话（关掉所有窗口、浏览器进程和驱动进程）。官方文档明确要求会话结束用 `quit()`：否则会残留后台进程与端口，而使用 Grid 时 `quit()` 还会通知 Grid 释放该 slot。

```python
from selenium.webdriver.common.by import By
from selenium.webdriver.support.ui import WebDriverWait
from selenium.webdriver.support import expected_conditions as EC

d = make_driver()
d.get(BASE)
print("初始句柄数:", len(d.window_handles))
first = d.current_window_handle

d.find_element(By.ID, "open-tab").click()          # 页面里是 window.open('sub.html','_blank')
WebDriverWait(d, 5).until(EC.number_of_windows_to_be(2))
new_handle = (set(d.window_handles) - {first}).pop()   # 差集拿新句柄，比按索引取更稳
d.switch_to.window(new_handle)
print("切换后标题:", d.title)
d.close()                                          # 关掉子页
d.switch_to.window(first)                          # 必须显式切回，否则后续命令报 NoSuchWindow
print("切回原窗口标题:", d.title)

d.switch_to.new_window("tab")                      # Selenium 4：开新标签并自动聚焦
print("新标签标题:", repr(d.title), "句柄数:", len(d.window_handles))
d.quit()                                           # 会话结束一律 quit，不要 close
```

本机真实输出：

```text
初始句柄数: 1
当前句柄: DB10383B66334F3B99D62C1EE3A59369
切换后标题: 子页面
切换后 current_window_handle == new_handle: True
close 之后剩余句柄数: 1
切回原窗口标题: Selenium 实验台
new_window('tab') 之后 title: '' 句柄数: 2
driver.quit() 完成
```

`switch_to.new_window('tab')` 打开的是空白页，`title` 是空字符串——不要顺手断言标题。另外虽然官方文档说明 `window_handles` 的「第一个是初始窗口」，但多窗口并发打开时顺序并不可靠，用差集筛选更安全。窗口尺寸与位置用 `set_window_size(w, h)` / `set_window_position(x, y)` 控制；无头模式下窗口尺寸与视口（`innerWidth`/`innerHeight`）不是一回事，实测数据见 18.5。

```text
要点：
- 句柄是字符串，current_window_handle 拿当前，window_handles 拿全部
- 新窗口不会自动聚焦，必须 switch_to.window(handle)
- 用 set(window_handles) - {原句柄} 求新句柄，不要依赖列表下标
- close() 只关当前窗口且不切换焦点，quit() 才结束会话
- 无头模式下 get_window_size() 是窗口尺寸，不等于 innerWidth/innerHeight
- Grid 场景下只有 quit() 会释放节点 slot，漏掉会把节点占满
```

## 框架与 iframe 切换

`<frame>` 已废弃，但 `<iframe>` 仍广泛用于第三方支付、客服组件、富文本编辑器、广告位。WebDriver 的查找范围**只在当前浏览上下文**里，顶层文档看不到 iframe 内部的节点——`find_elements(By.ID, "frame-input")` 返回空列表，`find_element` 则直接抛 `NoSuchElementException`。这不是定位写错，而是上下文没切。

切换方式有三种，官方文档都支持：

| 方式 | 写法 | 适用场景 |
|---|---|---|
| WebElement | `driver.switch_to.frame(driver.find_element(By.ID, "pay-frame"))` | 最灵活，可配合显式等待先等它出现 |
| id / name | `driver.switch_to.frame("pay-frame")` | 目标有稳定 id 或 name 时最短 |
| 索引 | `driver.switch_to.frame(0)` | 兜底手段，页面顺序变了就失效，不建议长期用 |

离开当前 frame 用 `driver.switch_to.default_content()` 回到顶层；嵌套 frame 里想回上一层用 `driver.switch_to.parent_frame()`。frame 是**栈式**上下文：切进去一层就只能看那一层，连续切两层要连续回两次。

```python
d.get(BASE)
print("顶层能看到的 iframe 数:", len(d.find_elements(By.TAG_NAME, "iframe")))
print("顶层直接找 #frame-input:", len(d.find_elements(By.ID, "frame-input")))

frame = d.find_element(By.ID, "pay-frame")
d.switch_to.frame(frame)                                   # 方式一：WebElement
print("进 frame 后:", d.find_element(By.ID, "frame-title").text)
d.find_element(By.ID, "frame-input").send_keys("6222 0000 0000 0000")
d.find_element(By.ID, "frame-btn").click()
print("iframe 内点击结果:", d.find_element(By.ID, "frame-msg").text)

d.switch_to.default_content()                               # 回顶层，否则后面全错
print("回顶层后 h1 =", d.find_element(By.ID, "page-title").text)

d.switch_to.frame(0)                                        # 方式三：索引
print("按索引进入:", d.find_element(By.ID, "frame-title").text)
d.switch_to.default_content()
```

本机真实输出：

```text
顶层页面能看到的 iframe 数: 1
顶层直接找 #frame-input: 0 (0 表示在 iframe 里)
switch_to.frame(WebElement) 后能取到: 支付信息（iframe 内）
iframe 内点击结果: iframe 内按钮已点击
default_content 后 h1 = Selenium 实验台
按 index switch_to.frame(0) 后标题: 支付信息（iframe 内）
```

```text
要点：
- 定位不到元素时先数 find_elements(By.TAG_NAME, "iframe")，确认是不是上下文问题
- switch_to.frame(WebElement) 最稳；id/name 次之；索引只用于兜底
- default_content() 回顶层，parent_frame() 回上一层，切几层就要退几层
- frame 元素本身要在顶层定位，定位完再传进去
- 跨域 iframe 同样可以切换，WebDriver 通过浏览器内核操作，不受同源策略限制
- 页面里 frame 数量可变时（弹层动态插入），先显式等待 iframe 出现再切
```

## JavaScript 弹窗处理

浏览器原生弹窗（alert / confirm / prompt）不属于 DOM，不能用选择器定位，要用 `driver.switch_to.alert` 拿到 `Alert` 对象。三种弹窗的区别：alert 只有确认；confirm 有确认和取消；prompt 多一个文本输入框，`send_keys()` 会**完全替换**占位文本（不是追加）。读取文本用 `.text`，应答用 `.accept()` 或 `.dismiss()`。

弹窗是阻塞式的：只要弹窗没被处理，**任何其他 WebDriver 命令都会拿到 `UnexpectedAlertPresentException`**。所以正确姿势是先触发、再用 `EC.alert_is_present()` 等它出现，立刻处理，之后才做别的操作。

未处理弹窗的兜底行为由 capability `unhandledPromptBehavior` 控制，默认是 `dismiss and notify`（关掉并报错），可选值还有 `accept`、`accept and notify`、`ignore`。近期版本浏览器对 `beforeunload` 提示默认自动 dismiss；官方文档指出，想保留这个提示需要把 `unhandledPromptBehavior` 设为 `ignore` 并启用 BiDi。

```python
d.get(BASE)

d.find_element(By.ID, "btn-alert").click()
alert = WebDriverWait(d, 5).until(EC.alert_is_present())    # 触发后一定要先等
print("alert.text:", alert.text)
alert.accept()

d.find_element(By.ID, "btn-confirm").click()
conf = WebDriverWait(d, 5).until(EC.alert_is_present())
print("confirm.text:", conf.text)
conf.dismiss()                                             # 取消
print("取消后页面结果:", d.find_element(By.ID, "dialog-result").text)

d.find_element(By.ID, "btn-prompt").click()
pr = WebDriverWait(d, 5).until(EC.alert_is_present())
pr.send_keys("张三")                                        # 全量替换占位文本
pr.accept()
print("prompt 输入后页面结果:", d.find_element(By.ID, "dialog-result").text)
```

本机真实输出：

```text
alert.text: 库存不足，请重试
confirm.text: 确认删除该订单吗？
dismiss 后页面结果: confirm => false
prompt 输入后页面结果: prompt => 张三
```

隐藏弹窗的两种写法，后者会踩坑：

```python
# 反例：弹窗可能是异步出现的，直接取会拿到 NoAlertPresentException
# d.switch_to.alert.accept()

# 正例：显式等待 + 超时兜底，容忍「有时不弹」的业务
from selenium.common.exceptions import NoAlertPresentException, TimeoutException

try:
    WebDriverWait(d, 3).until(EC.alert_is_present()).accept()
except (TimeoutException, NoAlertPresentException):
    pass                                  # 业务上允许不弹，就静默跳过
```

```text
要点：
- 弹窗不是 DOM，不能用 By 定位，只能 switch_to.alert
- 先触发、再 EC.alert_is_present() 等出来、再 accept/dismiss，顺序不能乱
- prompt 的 send_keys 是替换占位文本，不是追加
- 弹窗未处理时其他命令会抛 UnexpectedAlertPresentException
- unhandledPromptBehavior 默认 dismiss and notify，可在 Options 里改
- beforeunload 提示近期驱动默认自动 dismiss，要保留需 ignore + BiDi
```

## Cookie 与浏览器缓存管理

Cookie 是 WebDriver 管理得最完整的一块浏览器状态：`add_cookie()`、`get_cookie(name)`、`get_cookies()`、`delete_cookie(name)`、`delete_all_cookies()`。**最关键的限制是：`add_cookie` 必须先处在 Cookie 的目标域上**，否则抛 `InvalidCookieDomainException`。官方文档给的做法是：如果首页很大很慢，就先访问该域下一个轻量页面（例如 404 页）再写 Cookie。这一步在自动化登录里非常常用，可以直接把服务端签发的会话 Cookie 预置进浏览器，跳过 UI 登录。

`sameSite` 可按 W3C 的键值写入（`Strict` / `Lax`），用于校验 CSRF 相关行为；Chrome 80+、Firefox 79+ 且 Selenium 4+ 支持。

```python
d.get(BASE)     # 必须先到目标域，否则 InvalidCookieDomainException

d.add_cookie({"name": "session_id", "value": "abc123", "sameSite": "Lax"})
d.add_cookie({"name": "tenant", "value": "acme"})

ck = d.get_cookie("session_id")
print({k: ck[k] for k in ("name", "value", "sameSite", "path")})
print("全部 cookie 名:", sorted(c["name"] for c in d.get_cookies()))

d.refresh()                                       # 刷新后页面 JS 里也能读到
print("页面 document.cookie:", d.find_element(By.ID, "cookie-view").text)

d.delete_cookie("tenant")
print("删除后剩余:", sorted(c["name"] for c in d.get_cookies()))
print("再查已被删的 cookie:", d.get_cookie("tenant"))   # 不存在返回 None
d.delete_all_cookies()
print("清空后数量:", len(d.get_cookies()))
```

本机真实输出：

```text
get_cookie('session_id'): {'name': 'session_id', 'value': 'abc123', 'sameSite': 'Lax', 'path': '/'}
get_cookies() 全部名字: ['session_id', 'tenant']
刷新后页面 document.cookie: session_id=abc123; tenant=acme
delete_cookie('tenant') 后: ['session_id']
删除后再 get_cookie('tenant'): None
delete_all_cookies() 后数量: 0
```

「清缓存」要分清想清什么，不同目标做法不同：

| 目标 | 做法 | 说明 |
|---|---|---|
| 清会话态（Cookie / localStorage / sessionStorage） | `driver.delete_all_cookies()` + `execute_script("localStorage.clear()")` | 最常用，纯 WebDriver API |
| 拿到一个全新 profile | 新建 driver 实例（新会话） | 隔离性最好，代价是启动开销 |
| 清 HTTP 磁盘缓存 | 用临时 `--user-data-dir`，或加 `--incognito` 启动 | 无头模式下磁盘缓存本身几乎不落盘 |
| 精确控制缓存/离线行为 | CDP `Network.clearBrowserCache` 等域命令 | 属于 CDP 扩展能力，见 18.8 的说明 |

```python
# 会话复用：把一次 UI 登录得到的 Cookie 保存下来，后续用 HTTP 客户端复用
import requests

cookies = {c["name"]: c["value"] for c in d.get_cookies()}
resp = requests.get("http://127.0.0.1:8765/dashboard.html", cookies=cookies, timeout=5)
assert resp.status_code == 200
```

```text
要点：
- add_cookie 之前必须先导航到目标域，否则 InvalidCookieDomainException
- get_cookie 查不到返回 None，不抛异常；delete_all_cookies 只清当前上下文
- sameSite 支持 Strict/Lax，用于 CSRF 场景验证
- 想彻底干净就用新会话或临时 user-data-dir，别指望清 Cookie 能清掉磁盘缓存
- localStorage / sessionStorage 不在 Cookie API 管辖内，用 execute_script 处理
- 复用登录态的工程做法：读 Cookie 交给 HTTP 客户端，避免每条用例都走 UI 登录
```

## 执行 JavaScript

`driver.execute_script(script, *args)` 把脚本丢进浏览器执行，`args` 按顺序映射为脚本里的 `arguments[0]`、`arguments[1]`……`WebElement` 参数会被自动转换成对应的 DOM 节点，这是它最有价值的用法。`execute_async_script(script, *args)` 用于异步：脚本必须自己调用 `arguments[arguments.length - 1]` 把结果回传，超时由 `set_script_timeout()` 控制（默认 30000ms）。

返回值受 W3C 序列化规则限制：基本类型、数组、普通对象能原样返回；**DOM 节点、`window`、函数等不可序列化的对象会返回 `None`**。所以要拿 DOM 节点的信息，必须在脚本里就地取出来（`return arguments[0].innerText`），而不是 `return arguments[0]`。

```python
h1 = d.find_element(By.ID, "page-title")
print("取 innerText:", d.execute_script("return arguments[0].innerText", h1))
print("改属性:", d.execute_script(
    "arguments[0].dataset.marked='yes'; return arguments[0].dataset.marked;", h1))

d.execute_script("window.__injected = 40 + 2;")
print("注入后读回:", d.execute_script("return window.__injected"))
print("document.readyState:", d.execute_script("return document.readyState"))

val = d.execute_async_script(
    "var cb = arguments[arguments.length-1]; setTimeout(function(){cb('async-done');}, 600);")
print("异步脚本返回:", val)

d.execute_script("window.scrollTo(0, document.body.scrollHeight);")
print("scrollY:", d.execute_script("return window.scrollY"))
print("返回 DOM 节点会退化成 None:", d.execute_script(
    "return document.getElementById('page-title')"))
```

本机真实输出：

```text
execute_script 取 innerText: Selenium 实验台
execute_script 改属性: yes
注入后读回: 42
document.readyState: complete
execute_async_script 返回: async-done
scrollY: 732
navigator.userAgent: Mozilla/5.0 (X11; Linux x86_64) AppleWebKit/537.36 (KHTML, like Gecko) HeadlessChrome/151.0.0.0 Safari/537.36
```

另一个常被忽略的能力是 `driver.print_page(PrintOptions())` 生成 PDF，官方文档明确要求 **Chromium 系浏览器必须处于无头模式**：

```python
from selenium.webdriver.common.print_page_options import PrintOptions

opts = PrintOptions()
opts.page_ranges = ["1-2"]
base64_pdf = d.print_page(opts)          # 返回 base64 字符串，自行解码落盘
```

```text
要点：
- execute_script 的 WebElement 参数会自动转成 DOM 节点，是最实用的用法
- 返回值遵循 W3C 序列化，DOM 节点/函数不可序列化，只能就地取值
- execute_async_script 必须调用 arguments[arguments.length-1]，超时看 set_script_timeout
- 滚动、注入状态、读取性能数据、点击被遮挡元素都用它
- print_page 生成 PDF 只支持无头 Chromium，返回的是 base64 字符串
- 脚本里改 window 全局变量会持续到导航，刷新即失效
```

## 应用场景实战

### 场景一：多标签页对账（Cookie 共享 + 句柄切换）

运营系统里点「查看详情」会新开标签页，需要在新标签核对数据后再回到主标签继续批量处理。三个必须处理的点：新标签不会自动聚焦、同域 Cookie 天然共享（可以直接做断言）、以及「关闭子标签后焦点悬空」这个最常见的崩点。

```python
from selenium.webdriver.common.by import By
from selenium.webdriver.support import expected_conditions as EC
from selenium.webdriver.support.ui import WebDriverWait


def collect_detail_titles(order_ids):
    """在主页面逐个打开详情标签，收集标题后回到主页面，最后统一断言。"""
    d = make_driver()
    titles = []
    try:
        d.get(BASE)
        d.add_cookie({"name": "tenant", "value": "acme"})   # 预置租户标识
        main = d.current_window_handle

        for oid in order_ids:
            d.switch_to.window(main)                        # 每轮先复位焦点到主标签
            d.find_element(By.ID, "open-tab").click()
            WebDriverWait(d, 5).until(EC.number_of_windows_to_be(2))

            detail = (set(d.window_handles) - {main}).pop()
            d.switch_to.window(detail)
            WebDriverWait(d, 5).until(EC.title_is("子页面"))
            titles.append("%s:%s" % (oid, d.title))
            print("新标签共享到的 Cookie:", d.find_element(By.ID, "sub-cookie-value").text)

            d.close()                                       # 关掉详情标签
            d.switch_to.window(main)                        # 立刻切回，避免 NoSuchWindow
            WebDriverWait(d, 5).until(EC.number_of_windows_to_be(1))

        assert len(titles) == len(order_ids)
        return titles
    finally:
        d.quit()


if __name__ == "__main__":
    print(collect_detail_titles(["SO-2026-1001", "SO-2026-1002"]))
```

本机真实运行结果：

```text

['SO-2026-1001:子页面', 'SO-2026-1002:子页面']
```

关键点有三个：句柄用差集算而不是按索引；`close()` 后立即 `switch_to.window(main)`；循环开头统一把焦点复位到主标签，这样即使上一轮中途抛异常，下一轮也不会带着悬空句柄继续跑。

### 场景二：iframe 支付表单 + 弹窗二次确认的完整下单校验

真实支付页大多把卡号输入放在 iframe 里，提交后弹出 confirm 让用户二次确认。这个场景同时用到 frame 栈、弹窗和 JS 读取存储三类 API，顺序错一步就全线失败。把 frame 切换封装进页面对象是正确收口方式：测试代码完全不感知 iframe 的存在。

```python
import pytest
from selenium.common.exceptions import TimeoutException
from selenium.webdriver.common.by import By
from selenium.webdriver.support import expected_conditions as EC
from selenium.webdriver.support.ui import WebDriverWait


class PayPage:
    def __init__(self, driver):
        self.driver = driver
        self.wait = WebDriverWait(driver, 10)

    def open(self, url):
        self.driver.get(url)
        return self

    def fill_card(self, card_no):
        frame = self.wait.until(EC.presence_of_element_located((By.ID, "pay-frame")))
        self.driver.switch_to.frame(frame)
        try:
            field = self.driver.find_element(By.ID, "frame-input")
            field.clear()
            field.send_keys(card_no)
            self.driver.find_element(By.ID, "frame-btn").click()
            return self.driver.find_element(By.ID, "frame-msg").text
        finally:
            self.driver.switch_to.default_content()          # 无论成功失败都回顶层

    def confirm_dialog(self, accept=True):
        try:
            alert = self.wait.until(EC.alert_is_present())
            text = alert.text
            alert.accept() if accept else alert.dismiss()
            return text
        except TimeoutException:
            return None                                       # 业务上允许不弹

    def local_storage_keys(self):
        return self.driver.execute_script("return JSON.stringify(Object.keys(localStorage))")


@pytest.fixture
def driver():
    d = make_driver()
    yield d
    d.quit()


@pytest.fixture
def pay_page(driver):
    return PayPage(driver).open(BASE)


def test_pay_flow(pay_page, driver):
    assert pay_page.fill_card("6222 0000 0000 0000") == "iframe 内按钮已点击"

    driver.find_element(By.ID, "btn-pay-confirm").click()
    assert pay_page.confirm_dialog(accept=True) == "确认支付 1299.00 元？"
    assert driver.find_element(By.ID, "pay-result").text == "pay-confirm => true"
    assert pay_page.local_storage_keys() == "[]"


def test_pay_flow_cancel(pay_page, driver):
    pay_page.fill_card("6222 0000 0000 0000")
    driver.find_element(By.ID, "btn-pay-confirm").click()
    assert pay_page.confirm_dialog(accept=False) == "确认支付 1299.00 元？"
    assert driver.find_element(By.ID, "pay-result").text == "pay-confirm => false"
```

本机真实运行结果：

```text
selb_184_scene2.py::test_pay_flow PASSED                                 [ 50%]
selb_184_scene2.py::test_pay_flow_cancel PASSED                          [100%]
============================== 2 passed in 15.95s ==============================
```

注意 `fill_card` 里用 `try/finally` 包住 `default_content()`：一旦 iframe 内的断言或点击抛异常，栈状态仍会被复位，避免脏状态传染给下一个用例——这一点在 18.6、18.8 里还会再强调。

## 最佳实践与踩坑记录

1. **句柄一律用差集算，不用下标。** `set(d.window_handles) - {known}` 在任何打开顺序下都正确，索引写法在页面自己又开了一个窗口时会静默拿错窗口。
2. **`close()` 之后立刻切回有效句柄。** 官方文档明确警告：停在已关闭窗口上会让后续命令抛 `NoSuchWindowException`。稳妥做法是把「主句柄」存在变量里，关闭子窗口后马上 `switch_to.window(main)`。
3. **frame 切换写进页面对象，并用 `try/finally` 保证回顶层。** frame 是栈式状态，用例中途断言失败直接跳出会把「还在 iframe 里」的脏状态带进下一个用例，表现为下一个用例莫名找不到元素。
4. **弹窗先等后应答，并给业务上允许不弹的情况留 `TimeoutException` 分支。** `EC.alert_is_present()` + 短超时是最低成本的写法，比 `switch_to.alert` 裸调安全得多。
5. **`execute_script` 只用来做 API 覆盖不到的事。** 能正常 `click()` 就不要用 JS 点击：JS 点击绕过 WebDriver 的可点击性检查，会让用例在真实用户根本点不动的情况下仍然通过。
6. **会话结束统一 `quit()`。** 用 pytest 的 `yield` fixture 或 `try/finally` 保证执行；Grid 环境下漏掉会把节点 slot 占满导致排队超时。

坑 1：`NoSuchWindowException: no such window` 出现在 `d.close()` 之后

结论：关闭当前窗口后驱动仍指向已销毁的窗口，任何命令（包括 `find_element`）都会抛 `NoSuchWindowException`。

原因：`close()` 只销毁窗口、不改变「当前窗口」指针，`current_window_handle` 变成了悬空引用，而且下一次命令会把这个错误也返回给调用方。

解法：把主句柄存变量，`close()` 后立即 `d.switch_to.window(main)`；更稳的做法是封装 `close_current_and_back(main_handle)` 辅助函数，避免散落的切回逻辑漏写。

坑 2：元素明明在页面上，`find_element` 却报 `NoSuchElementException`

结论：多半是页面里有 iframe，顶层文档看不到里面的节点，是定位范围错了而不是选择器写错。

原因：WebDriver 的查找只在当前浏览上下文生效，`switch_to.frame` 之前所有查询都作用于顶层文档。

解法：先数 `len(d.find_elements(By.TAG_NAME, "iframe"))`，本机实测顶层查 iframe 内元素返回 0（用 `find_elements` 不抛异常，便于排查）；确认后 `switch_to.frame(...)` 再定位，操作完 `default_content()`。

坑 3：`add_cookie` 抛 `InvalidCookieDomainException`

结论：在 `about:blank` 或别的域上直接写 Cookie 会失败，Cookie 必须写在它所属的域下。

原因：W3C 规定 `Add Cookie` 命令要求当前文档 URL 与 Cookie 域匹配，驱动会做域校验。

解法：先 `d.get()` 到目标域的任意页面再写 Cookie；首页很大的场景按官方建议先访问该域的轻量页（404 页）再写。

坑 4：弹窗没处理，后续所有命令报 `UnexpectedAlertPresentException`

结论：alert/confirm/prompt 未关闭时 WebDriver 会阻塞其它命令并报错。

原因：原生弹窗是浏览器模态对话框，会暂停该 tab 的脚本执行，驱动无法与新命令交互。

解法：弹出后立即 `WebDriverWait(..., 3).until(EC.alert_is_present())` 再 `accept()`/`dismiss()`；并在 fixture 的 teardown 里加一次兜底 `accept()`，防止单条用例失败后污染后续用例。

坑 5：`execute_script("return document.querySelector('#x')")` 返回 `None`

结论：DOM 节点不可序列化，跨进程传不回来，「执行成功但结果是 None」很容易被误判为脚本没跑。

原因：W3C 规定脚本返回值必须能序列化为 JSON 安全类型，Element 会退化成 `null`。

解法：在脚本里就地取值，`return arguments[0].innerText` 或 `return document.querySelector('#x').value`，只把基本类型带回 Python。

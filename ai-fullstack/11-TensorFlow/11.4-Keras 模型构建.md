## 概述

Keras 是 TensorFlow 的官方高层建模 API，从 TensorFlow 2.16 起随 `pip install tensorflow` 安装的是 **Keras 3**——一个重写过的多后端框架，同一份建模代码可以跑在 TensorFlow / JAX / PyTorch 之上（后端由 `KERAS_BACKEND` 决定）。构建模型的入口有三个：`Sequential`（线性堆叠，最快）、Functional API（显式声明输入输出，支持多输入多输出与任意拓扑）、子类化 `keras.Model`（完全自由的 `call()`，代价是需要自己处理序列化与形状推断）。选型原则很简单：能用 Sequential 就别用 Functional，能用 Functional 就别子类化。

```text
本篇主线：
1. 三种建模方式 —— Sequential（堆叠）/ Functional（显式图）/ 子类化（自定义 call）
2. 自定义层 —— class ResidualBlock(keras.layers.Layer)，build() 建权重、call() 写前向
3. 层与形状 —— Dense/Embedding/LSTM/Conv2D/Dropout/LayerNorm 的输入输出形状与参数量
4. 配置 —— 激活函数、初始化器、正则化器、损失、指标、优化器（字符串与对象两种写法）
5. 训练流程 —— 延迟构建 -> compile -> fit -> evaluate -> predict，以及返回值的结构
6. 权重管理 —— trainable 开关、trainable/non_trainable_variables、.keras 保存与回读
```

本机实测环境：Ubuntu 24.04、Python 3.12.3、TensorFlow 2.20.0、**Keras 3.15.1**（`keras.backend.backend()` 返回 `tensorflow`），纯 CPU。下文所有 `text` 块中的输出均为本机真实运行结果，包含失败或与预期不同的地方也都如实保留——注意 Keras 3 与旧教程（Keras 2）差异很大，很多 API 名与参数已变。

## 三种建模方式 Sequential Functional 与子类化

`Sequential` 适合「层依次串联」的常规网络。Keras 3 推荐的写法是**把 `keras.Input` 作为第一层放进列表**，而不是给第一层传 `input_shape`（本机实测传 `input_shape` 会给出弃用警告）：

```python
import keras

model = keras.Sequential(
    [
        keras.Input(shape=(4,)),
        keras.layers.Dense(16, activation="relu", name="h1"),
        keras.layers.Dense(8, activation="relu", name="h2"),
        keras.layers.Dense(1, name="out"),
    ],
    name="seq_mlp",
)
model.summary()
```

本机真实输出（含 `summary()` 的表格原样）：


Keras 3 的模型是**延迟构建**的：不指定 `Input` 时，权重在第一次 `fit` / `evaluate` / `predict` / 直接调用之前不存在。这一点在「冻结层」「查看 `trainable_variables`」时是致命的坑——拿不到变量就冻结不了。

```text

未 build 时 weights 数量: 0
build((None,16)) 后 weights 数量: 4
```

Functional API 用「张量进、张量出」的方式显式描述计算图，天然支持多输入、多输出与分支合并。注意输入输出名字的取值方式：`model.inputs[i].name` 拿到的是 `Input` 层名，而输出的**张量名**是自动生成的 `keras_tensor_N`，业务名要从 `model.output_names` 取（本机实测 `input_names` 这个属性在 Keras 3 里不存在）。

```python
import keras

in_a = keras.Input(shape=(4,), name="a")
in_b = keras.Input(shape=(3,), name="b")
x = keras.layers.Concatenate()([in_a, in_b])
x = keras.layers.Dense(16, activation="relu")(x)
out_main = keras.layers.Dense(1, name="score")(x)
out_aux = keras.layers.Dense(2, activation="softmax", name="category")(x)
func_model = keras.Model(inputs=[in_a, in_b], outputs=[out_main, out_aux], name="two_in_two_out")
```

本机真实输出：

```text

output_names: ['score', 'category']
outputs 张量名: ['keras_tensor_2', 'keras_tensor_3']
```

子类化 `keras.Model` 是最灵活的方式：在 `__init__` 里建层、在 `call()` 里写前向逻辑，`training` 参数用来区分训练与推理（Dropout、BatchNorm 依赖它）。代价是模型结构由 Python 代码隐式决定，`summary()` 只能在**跑过一次前向**之后才能给出形状，保存成 `.keras` 也依赖能重建这个类。

```python
import keras

class MLP(keras.Model):
    def __init__(self, hidden=16, **kw):
        super().__init__(**kw)
        self.h1 = keras.layers.Dense(hidden, activation="relu")
        self.out = keras.layers.Dense(1)

    def call(self, inputs, training=False):
        x = self.h1(inputs)
        if training:
            x = keras.layers.Dropout(0.2)(x, training=True)
        return self.out(x)

sub = MLP(hidden=8, name="sub_mlp")
sub(np.zeros((5, 4), dtype="float32"))   # 必须跑一次前向，权重才会建出来
sub.summary()
```

本机真实输出（子类化模型的第一层名称是自动生成的 `dense_3` / `dense_4`，因为没给 `name`）：


三种方式的对照：

| 维度 | Sequential | Functional | 子类化 Model |
|------|-----------|------------|--------------|
| 拓扑能力 | 线性串联 | 任意 DAG、多输入多输出 | 任意（Python 控制流） |
| 代码量 | 最少 | 中 | 最多 |
| 形状推断 | 自动 | 自动 | 需跑一次前向 |
| 序列化 | 开箱可用 | 开箱可用 | 需自定义 `get_config` 且类可导入 |
| 调试 | 简单 | 简单（可看中间张量） | 需自己插断言 |
| 适合场景 | 快速基线、教学 | 绝大多数生产模型 | 自定义训练步、动态结构、研究 |

```text
建模方式要点：
1. Sequential 推荐写法是列表第一项放 keras.Input(shape=...)，不要再给首层传 input_shape
2. 不指定 Input 时权重延迟到首次 fit/predict/调用才创建，之前看到的 trainable_variables 是空的
3. Functional 的模型输出业务名在 model.output_names，张量名是自动生成的 keras_tensor_N
4. Keras 3 的 Functional 模型没有 input_names 属性，取输入名用 [t.name for t in model.inputs]
5. 子类化模型必须先跑一次前向才能 summary()，且序列化依赖类本身可导入
```

## 常用层与形状推算

建模型时的绝大多数报错都是形状不匹配，所以「知道每层吃什么形状、吐什么形状」比记 API 更有用。下面这张表的数据全部来自本机真实运行（每个层喂一个零张量并打印输出形状与参数量）：

| 层 | 输入形状 | 输出形状 | 参数量 |
|----|----------|----------|--------|
| `Dense(10)` | `(2, 12)` | `(2, 10)` | 130 |
| `Flatten` | `(2, 3, 4)` | `(2, 12)` | 0 |
| `Embedding(100, 8)` | `(2, 5)` int32 | `(2, 5, 8)` | 800 |
| `LSTM(8)` | `(2, 7, 4)` | `(2, 8)` | 416 |
| `GRU(8)` | `(2, 7, 4)` | `(2, 8)` | 336 |
| `Conv2D(4, 3)` | `(2, 16, 16, 3)` | `(2, 14, 14, 4)` | 112 |
| `MaxPooling2D` | `(2, 16, 16, 3)` | `(2, 8, 8, 3)` | 0 |
| `BatchNormalization` | `(2, 6)` | `(2, 6)` | 24 |
| `LayerNormalization` | `(2, 6)` | `(2, 6)` | 12 |
| `Dropout(0.5)` | `(2, 6)` | `(2, 6)` | 0 |

```text
== 6. 常用层与输入输出形状 ==
  Dense(10)          in (2, 12)        -> out (2, 10)        params=130
  Flatten            in (2, 3, 4)      -> out (2, 12)        params=0
  Embedding(100,8)   in (2, 5)         -> out (2, 5, 8)      params=800
  LSTM(8)            in (2, 7, 4)      -> out (2, 8)         params=416
  GRU(8)             in (2, 7, 4)      -> out (2, 8)         params=336
  Conv2D(4,3)        in (2, 16, 16, 3) -> out (2, 14, 14, 4) params=112
  MaxPooling2D       in (2, 16, 16, 3) -> out (2, 8, 8, 3)   params=0
  BatchNorm          in (2, 6)         -> out (2, 6)         params=24
  LayerNorm          in (2, 6)         -> out (2, 6)         params=12
  Dropout(0.5)       in (2, 6)         -> out (2, 6)         params=0
```

参数量可以手算核对，这是排查「模型比预期大」的最快方式：

- `Dense(10)` 输入 12 维：`12*10 + 10 = 130`（权重 + 偏置）
- `Embedding(100, 8)`：`100*8 = 800`（无偏置，输入必须是整数索引）
- `LSTM(8)` 输入 4 维：`4 * ((4+8)*8 + 8) = 416`（四个门，每个门有输入权重与循环权重）
- `GRU(8)` 输入 4 维：`3 * ((4+8)*8 + 8) = 336`（三个门，所以是 LSTM 的 3/4）
- `Conv2D(4, 3)` 输入 3 通道：`3*3*3*4 + 4 = 112`（核高 × 核宽 × 输入通道 × 输出通道 + 偏置）
- `BatchNormalization` 6 维：`24`（4 个可训练 + 2 个非训练变量，各 6 个数）
- `LayerNormalization` 6 维：`12`（只有 gamma 与 beta）

卷积的输出空间尺寸按 `(H - k + 2*pad) / stride + 1` 计算：`(16 - 3) / 1 + 1 = 14`，所以 `16x16 -> 14x14`；`MaxPooling2D` 默认 `pool_size=(2,2)`，得到 `8x8`。

```text
常用层与形状要点：
1. Dense 参数量 = 输入维 × 输出维 + 输出维；Embedding 参数量 = 词表大小 × 向量维，无偏置
2. Embedding 的输入必须是整数类型（本机用 int32），喂浮点会直接报错
3. LSTM 有 4 个门、GRU 有 3 个门，参数量约 4:3，选型时按任务长度与显存权衡
4. Conv2D 输出空间尺寸 = (H - kernel + 2*padding) / stride + 1，默认 valid padding
5. BatchNorm 有非训练变量（滑动均值/方差），LayerNorm 没有；这会影响冻结时看到的变量列表
6. 拿不准形状就打印中间张量：Functional 里每个 KerasTensor 都有 .shape
```

## 激活函数 初始化器与正则化

激活函数用字符串或 `keras.activations.get()` 指定，两者等价；初始化器与正则化器同理。工程上真正影响结果的三个选择是：隐藏层用 `relu` 还是 `gelu`、权重初始化是否与激活匹配（ReLU 系配 `he_normal`）、以及要不要加权重正则化。本机真实取出了五个激活函数在 `[-1, 0, 2]` 上的输出，方便对照（注意 `gelu` 在 -1 处是负值，这是它相对 ReLU 的差别）：

```text
== 7. 激活函数真实取值 ==
  relu     [[0.0, 0.0, 2.0]]
  sigmoid  [[0.2689000070095062, 0.5, 0.8808000087738037]]
  tanh     [[-0.7616000175476074, 0.0, 0.9639999866485596]]
  softmax  [[0.041999999433755875, 0.11420000344514847, 0.8438000082969666]]
  gelu     [[-0.15870000422000885, 0.0, 1.9544999599456787]]
```

初始化器与正则化器直接挂在线层上：

```python
import keras
import tensorflow as tf

dense = keras.layers.Dense(
    4,
    kernel_initializer="he_normal",              # ReLU 系激活配 he 初始化
    kernel_regularizer=keras.regularizers.l2(1e-4),
    bias_regularizer=keras.regularizers.l1(1e-4),
)
_ = dense(tf.zeros((1, 5), dtype="float32"))     # 触发 build
print(dense.kernel.shape)                        # (5, 4)
print(float(dense.kernel_regularizer(tf.ones([2, 2]))))   # 0.0004
```

本机真实输出：

```text
== 8. 初始化器 / 正则化 / 约束 ==
kernel 形状: (5, 4) | 正则化器: <keras.src.regularizers.regularizers.L2 object at 0x7e3aec7ba0c0>
l2(1e-4) 对全 1 kernel 的结果: 0.00039999998989515007 (=1e-4*4=0.0004)
```

`regularizer` 不会自动加进损失——Keras 在 `compile` 时把层的正则化损失累加进总 loss，但**手写训练循环时（`GradientTape`）不会自动加上**，这是最常见的「内置 fit 能收敛、手写循环不收敛」的原因。手写时要么自己把 `layer.losses` 加进去，要么用 `model.compiled_loss`。

```python
# 手写循环里必须显式带上正则化损失
with tf.GradientTape() as tape:
    pred = model(xb, training=True)
    loss = loss_fn(yb, pred) + tf.add_n(model.losses)   # model.losses 是层的正则化项之和
```

```text
激活与正则化要点：
1. 激活用字符串或 keras.activations.get() 等价；生产代码统一写字符串，便于配置化
2. ReLU 系激活配 he_normal，tanh/sigmoid 系配 glorot（Xavier），混用会明显影响收敛
3. 正则化项的权重写在 kernel_regularizer 上，不要手写进 loss 表达式（除了手写训练循环）
4. 手写训练循环必须显式加 model.losses，否则正则化完全不起作用
5. gelu 在负区间非零（本机 -1 处为 -0.1587），与 relu 的硬截断不同
```

## compile fit evaluate predict

`compile` 声明优化器、损失与指标，`fit` 执行训练，`evaluate` 返回损失与指标，`predict` 返回模型输出。Keras 3 里所有接口都支持 `verbose` 与 `return_dict=True`，后者让 `evaluate` 返回字典而不是列表，**在指标多于一个时强烈建议开启**，否则得靠顺序去猜哪个数字是什么。

```python
import numpy as np
import keras

X = np.random.default_rng(0).normal(size=(500, 4)).astype("float32")
y = (X @ np.array([2.0, -1.0, 0.5, 3.0], dtype="float32") + 1.5).reshape(-1, 1)

m = keras.Sequential([keras.Input(shape=(4,)), keras.layers.Dense(1)])
m.compile(optimizer=keras.optimizers.Adam(learning_rate=0.05), loss="mse", metrics=["mae"])
h = m.fit(X[:400], y[:400], validation_split=0.2, epochs=30, batch_size=32, verbose=0)
print(h.history.keys())
print(m.evaluate(X[400:], y[400:], verbose=0, return_dict=True))
print(m.predict(X[:3], verbose=0).shape)
```

本机真实输出：

```text
== 5. compile / fit / evaluate / predict（真实运行）==
epochs: 30
训练 loss 首/末: 8.3066 -> 0.0398
验证 loss 末: 0.0405
val_mae 末: 0.1561
evaluate 返回: [0.034, 0.1494]
predict 前 3 条: [2.5250000953674316, 3.552000045776367, 1.187000036239624]
学到的权重: [2.0169999599456787, -1.0269999504089355, 0.5040000081062317, 3.009000062942505] bias: 1.497
真实权重: [2.0, -1.0, 0.5, 3.0] bias: 1.5
```

从真实数据里得到的几个关键事实：`validation_split=0.2` 取的是**训练数据末尾 20%**（不洗牌前要先自己 shuffle，否则验证集可能全是同一类）；`h.history` 的键是 `loss` / `val_loss` 加各指标名（`mae` -> `val_mae`）；`predict` 返回形状是 `(n, 1)` 而不是 `(n,)`，做后续 NumPy 运算前先 `ravel()`，否则会与一维数组广播成 `(n, n)` 矩阵——本机在写这个脚本时真的踩到了。学到的权重 `[2.017, -1.027, 0.504, 3.009]` 与真实值 `[2, -1, 0.5, 3]` 一致，说明流程正确。

`fit` 的常用参数与陷阱：

| 参数 | 作用 | 容易踩的点 |
|------|------|-----------|
| `epochs` | 训练轮数 | 早停要自己配回调（见 11.5） |
| `batch_size` | 批大小，默认 32 | 与内存/速度强相关，CPU 上不要盲目调大 |
| `validation_split` | 从训练数据尾部切分 | 切分前不洗牌会得到有偏的验证集 |
| `validation_data` | 显式给验证集 | 与 `validation_split` 二选一 |
| `shuffle` | 默认 `True` | 时序数据必须显式设 `False`，否则顺序被打乱 |
| `class_weight` | 类权重 | 类别不平衡时比反复采样更省事 |
| `callbacks` | 回调列表 | 详见 11.5 |

```text
compile/fit 流程要点：
1. validation_split 从训练数据末尾切 20%，切分前务必自己 shuffle，否则验证集可能严重有偏
2. history.history 的键是 loss/val_loss + 指标名，指标名带 val_ 前缀
3. predict 返回 (n, 1) 不是 (n,)；与一维数组运算前先 ravel()，否则广播成 (n, n)
4. evaluate 有多个指标时用 return_dict=True，靠位置取数迟早出错
5. 时序数据必须显式 shuffle=False，默认 True 会打乱时间顺序
```

## 损失 指标与优化器

损失的选法由输出层的激活决定：输出 `sigmoid`（二分类概率）配 `BinaryCrossentropy()`；输出 `softmax`（多分类概率）配 `CategoricalCrossentropy()`；输出**无激活的 logits** 则配同一损失并置 `from_logits=True`（数值更稳，推荐）。本机实测的三个损失取值与手算完全吻合：

```text
== 9. 损失函数真实取值 ==
  MSE: 0.046667
  CategoricalCrossentropy: 0.356675
  -log(0.7): 0.356675
  BinaryCrossentropy: 0.105361
```

`CategoricalCrossentropy` 对 one-hot 真值 `[0,1,0]` 与预测 `[0.1,0.7,0.2]` 给出 `0.356675`，正好等于 `-log(0.7)`——这印证了「交叉熵只关心真值那一类的概率」。`BinaryCrossentropy` 对 `(1, 0.9)` 给出 `0.105361`，等于 `-log(0.9)`。

优化器与指标用字符串或对象指定都行，`keras.optimizers.get()` 能做配置化构造（从 YAML/JSON 里读超参时很有用）：

```text
== 10. 优化器 ==
  SGD      -> SGD lr=0.0010000000474974513
  Adam     -> Adam lr=0.0010000000474974513
  AdamW    -> AdamW lr=0.0010000000474974513
  RMSprop  -> RMSprop lr=0.0010000000474974513
  指标: Accuracy | Mean
```

几个选型结论：优化器默认 `learning_rate` 都是 0.001（只有 SGD 常被人误以为更大），**不显式指定学习率是新手最常见的失败原因之一**；`AdamW` 把权重衰减与梯度更新解耦，需要正则化时优先于 `Adam`；`SGD` 配 momentum 在视觉任务上仍常优于 Adam。

```python
model.compile(
    optimizer=keras.optimizers.AdamW(learning_rate=3e-4, weight_decay=1e-4),
    loss=keras.losses.SparseCategoricalCrossentropy(from_logits=True),
    metrics=[keras.metrics.SparseCategoricalAccuracy(name="acc")],
)

# 配置化写法：适合把超参放配置文件
opt = keras.optimizers.get({"class_name": "Adam", "config": {"learning_rate": 1e-3}})
```

```text
损失指标优化器要点：
1. 输出有 sigmoid/softmax 就用不带 from_logits 的损失；输出是 logits 就置 from_logits=True
2. 多分类用稀疏标签时选 SparseCategoricalCrossentropy，能省掉一个 one_hot 操作
3. 交叉熵对 one-hot 真值只取真值那一类的 -log(p)，本机实测 0.356675 == -log(0.7)
4. 优化器默认学习率是 1e-3，必须显式设置并写进配置，不要依赖默认值
5. 需要权重衰减时用 AdamW（解耦衰减），不要指望 Adam + 手写 l2 正则等价
6. 指标名要显式给（metrics=[...(... name="acc")]），日志与 history 的键才稳定
```

## 层冻结 权重管理与保存

冻结是迁移学习的标准动作：把预训练塔的 `trainable` 设为 `False`，只训练新加的输出头。要注意两点：**冻结后必须重新 `compile`** 才会生效（优化器持有的是变量列表）；以及冻结会把变量从 `trainable_variables` 移到 `non_trainable_variables`，参数量统计会立刻反映出来。

本机实测（多任务模型，冻结两个自定义残差块）：

```text
微调前 trainable 参数量: 5090
冻结 2 个残差块后 trainable: 738 | 非训练变量: [('kernel', (32, 32)), ('bias', (32,)), ... ('gamma', (32,)), ('beta', (32,)), ... ('seed_generator_state', (2,)), ...]
冻结后 5 epoch 总 loss: 0.018 (冻结前末轮: 0.026 )
解冻后 trainable: 5090
```

从输出里能读到三个事实：冻结让可训练参数量从 5090 降到 738；被冻结的变量确实出现在 `non_trainable_variables` 里（包括自定义层内部的 `gamma`/`beta`，以及 Dropout 的 `seed_generator_state`）；解冻后参数量回到 5090。简单模型的对照实验：

```python
base = keras.Sequential([keras.Input(shape=(8,)),
                         keras.layers.Dense(16, activation="relu", name="b1"),
                         keras.layers.Dense(4, name="b2")])
base.get_layer("b1").trainable = False
print("trainable:", sum(int(np.prod(v.shape)) for v in base.trainable_variables))          # 68
print("non-trainable:", sum(int(np.prod(v.shape)) for v in base.non_trainable_variables))  # 144
```

保存格式首选 `.keras`（Keras 3 的推荐格式，含结构与权重，比旧的单一 HDF5 更完整）。本机实测保存后回读，输出与权重完全一致：

```text

加载成功: sequential_1 | 输出一致: True
权重格式: ['kernel', 'bias']
```

三种保存格式的取舍：

| 格式 | 保存内容 | 适用场景 | 限制 |
|------|----------|----------|------|
| `.keras` | 结构 + 权重 + compile 配置 | 默认选择，跨版本更稳 | 需要构造模型所需的代码（自定义层/子类化模型） |
| `.h5` / `SavedModel` | 旧格式，兼容历史资产 | 对接旧推理链路 | 新项目不建议 |
| `model.save_weights(...)` | 只有权重 | 只换权重、结构由代码定义 | 加载时结构必须完全一致 |

```python
m.save("model.keras")
loaded = keras.saving.load_model("model.keras")

# 只要权重（结构由代码保证一致）
m.save_weights("model.weights.h5")
m.load_weights("model.weights.h5")
```

```text
冻结与保存要点：
1. 设 trainable=False 后必须重新 compile，否则优化器仍在更新那些变量
2. 冻结后变量出现在 non_trainable_variables 里，可用参数量统计做自检
3. 自定义层/子类化模型要能保存，必须实现 get_config 且类可在加载环境导入
4. 默认保存格式用 .keras；save_weights 只存权重，加载时结构必须逐层一致
5. 保存后一定回读并对比输出，确认「存下来的和跑起来的是同一个模型」
```

### 场景一：表格数据二分类端到端（数值特征 + Embedding 类别特征）

```python
                     rng.integers(0, 2, N).astype("float32")], axis=1).astype("float32")
cat_feat = rng.integers(0, 6, N).astype("int32")
score = 1.2 * num_feat[:, 0] - 0.8 * num_feat[:, 1] + 2.0 * num_feat[:, 2] \
        + np.array([0.5, -0.5, 1.0, -1.0, 0.2, 0.0])[cat_feat]
y = (score + rng.normal(0, 1.0, N) > 0.8).astype("float32").reshape(-1, 1)

cat_in = keras.Input(shape=(), dtype="int32", name="cat")
emb = keras.layers.Flatten()(keras.layers.Embedding(input_dim=6, output_dim=4)(cat_in))
x = keras.layers.Concatenate()([num_in, emb])
x = keras.layers.Dense(32, activation="relu", kernel_regularizer=keras.regularizers.l2(1e-4))(x)
x = keras.layers.Dropout(0.2)(x)
x = keras.layers.Dense(16, activation="relu")(x)
out = keras.layers.Dense(1, activation="sigmoid", name="prob")(x)
model = keras.Model(inputs=[num_in, cat_in], outputs=out, name="tab_classifier")

model.compile(optimizer=keras.optimizers.Adam(0.01),
              loss=keras.losses.BinaryCrossentropy(),
              metrics=[keras.metrics.BinaryAccuracy(name="acc"), keras.metrics.AUC(name="auc")])
model.fit([num_feat[:1600], cat_feat[:1600]], y[:1600],
```

### 场景二：自定义残差层 + 多输出模型 + 冻结微调

多任务学习（一个主干带多个头）与自定义层是进阶建模的常见需求。下面这段在本机真实跑通：自定义 `ResidualBlock`（`build` 里按需加投影、`call` 里做残差相加与 LayerNorm、`get_config` 保证可序列化），一个主干两个输出（回归主任务 + 二分类辅助任务），随后冻结主干做微调。

```python
import numpy as np
import keras

class ResidualBlock(keras.layers.Layer):
    def __init__(self, units, dropout=0.0, **kwargs):
        super().__init__(**kwargs)
        self.units = units
        self.dropout_rate = dropout
        self.d1 = keras.layers.Dense(units, activation="relu")
        self.d2 = keras.layers.Dense(units)
        self.drop = keras.layers.Dropout(dropout)
        self.norm = keras.layers.LayerNormalization()

    def build(self, input_shape):
        # 输入维度与 units 不同时需要投影，保证残差相加合法
        self.proj = None if input_shape[-1] == self.units else \
            keras.layers.Dense(self.units, use_bias=False, name="proj")
        super().build(input_shape)

    def call(self, inputs, training=False):
        h = self.d2(self.drop(self.d1(inputs), training=training))
        shortcut = inputs if self.proj is None else self.proj(inputs)
        return self.norm(h + shortcut)

    def get_config(self):
        cfg = super().get_config()
        cfg.update({"units": self.units, "dropout": self.dropout_rate})
        return cfg

inp = keras.Input(shape=(20,))
h = keras.layers.Dense(32, activation="relu")(inp)
h = ResidualBlock(32, dropout=0.1)(h)
h = ResidualBlock(32, dropout=0.1)(h)
main = keras.layers.Dense(1, name="main")(h)
aux = keras.layers.Dense(1, activation="sigmoid", name="aux")(h)

multi = keras.Model(inp, {"main": main, "aux": aux}, name="multi_task")
multi.compile(
    optimizer=keras.optimizers.Adam(0.005),
    loss={"main": keras.losses.MeanSquaredError(), "aux": keras.losses.BinaryCrossentropy()},
    loss_weights={"main": 1.0, "aux": 0.3},          # 辅助任务降权
    metrics={"aux": [keras.metrics.BinaryAccuracy(name="acc")]},
)
```

## 最佳实践与踩坑记录

### 最佳实践

1. 建模优先用 Sequential，其次 Functional，只在需要自定义训练步或动态结构时才子类化；越简单的建模方式越容易保存、调试与交接。
2. 一律显式写 `keras.Input(shape=...)` 作为第一层，避免延迟构建带来的「变量还没建出来」问题。
3. 优化器必须显式设置 `learning_rate` 并写进配置，不要依赖默认的 1e-3。
4. 输出层有 `sigmoid`/`softmax` 就用对应概率版损失；输出是裸 logits 就置 `from_logits=True`，二者不要混。
5. 指标命名显式写（`name="acc"`），`evaluate` 用 `return_dict=True`，日志与 `history` 的键才稳定可解析。
6. 冻结层后必须重新 `compile`，并用 `trainable_variables` 参数量统计做一次自检。
7. 训练/评估/预测返回的形状要打印确认（尤其 `predict` 返回 `(n,1)`），上下行对接时先 `ravel()`。
8. 保存用 `.keras` 格式，保存后立刻回读并对比输出，确认结构与权重都对。

### 踩坑记录

```text
坑 1：模型刚建好就访问 trainable_variables / 冻结层，结果什么都不生效
结论：以为冻结没起作用或者 Keras 有 bug，反复设 trainable=False。
原因：Keras 3 的模型是延迟构建的，不指定 Input 时权重在首次 fit/evaluate/predict/调用之前
      并不存在，此时 variables 列表是空的。
解法：显式用 keras.Input(shape=...) 作为第一层（本机实测：不带 Input 时 weights 数量为 0，
      带 Input 或显式 build((None,16)) 后为 4）；或先手动 model.build((None, 特征数)) 再冻结。

坑 2：predict 返回 (n,1)，与一维标签比较时结果形状变成 (n,n)
结论：指标算出来莫名其妙，或者 allclose 判定失败。
原因：predict 返回保留最后一维（二分类/回归输出是 (n,1)），NumPy 与形状 (n,) 的数组做比较时
      按广播规则展开成 (n,n) 矩阵，代码不报错。
解法：比较前统一 ravel() 或 reshape(-1)。本机写本文脚本时就踩到过，表现为
      "回读输出一致: False"，加上 .ravel() 后为 True。

坑 3：validation_split 得到的验证集指标虚高或虚低，且每次结果差异很大
结论：怀疑模型不稳定，加正则化、降学习率。
原因：validation_split 直接取训练数据末尾的切片，若数据按某种顺序排列（如按时间、按类别），
      验证集就是有偏的。
解法：先对数据整体做 shuffle（固定随机种子），再切分；时序任务必须按时间切分并设 shuffle=False。

坑 4：子类化模型保存成 .keras 后加载失败
结论：以为 Keras 3 保存功能不完善。
原因：子类化模型的结构由 Python 代码决定，Keras 通过 get_config 重建；自定义层没实现
      get_config、或加载环境里类不可导入，都会失败。
解法：自定义层/模型实现 get_config（含全部构造参数）并确保类定义可被加载方 import；
      加载测试放在 CI 里，别等上线才发现。

坑 5：正则化加了但 loss 曲线和没加一样
结论：以为正则化系数太小，一路调大到 1e-1。
原因：用手写 GradientTape 训练循环时，层的正则化损失不会自动进入 loss，必须显式加上
      model.losses；用内置 fit 时 Keras 会自动累加，所以两种循环行为不同。
解法：手写循环里写 loss = loss_fn(...) + tf.add_n(model.losses)；
      或者直接改用 model.compiled_loss 与 model.compute_loss。

坑 6：类别不平衡数据上准确率 0.96 但模型基本没用
结论：以为模型效果很好，直接上线。
原因：正样本只占 5.6%（本机实测数据），全部预测为负类就有 94.4% 准确率，准确率被多数类稀释。
解法：同时看 AUC/PR 曲线（本例 AUC 0.986）；用 class_weight 或重采样；并把判定阈值基于
      验证集扫描确定（本机实测阈值 0.45 的 F1 略优于默认 0.5），不要沿用 0.5。
```

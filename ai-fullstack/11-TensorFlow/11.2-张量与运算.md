## 概述

张量是 TensorFlow 的唯一数据结构：标量、向量、矩阵、图像批次本质上都是「有形状（shape）和元素类型（dtype）的多维数组 + 一个设备（device）」。TensorFlow 2.x 默认开启即时执行（eager execution），张量运算立即求值，可以像 NumPy 一样边算边打印，调试体验与 NumPy 接近；写进 `tf.function` 后同一份代码才会被编译成图以获得性能。本篇覆盖张量从创建到运算的全流程：创建方式与属性、形状操作与广播规则、常用数学算子、`tf.Variable` 与常量的区别，以及和 NumPy 互操作的边界。

```text
本篇主线：
1. 创建 —— constant / zeros / ones / fill / range / linspace / eye / random / ragged / sparse
2. 属性 —— shape、dtype、device、ndim，以及 tf.Tensor 与 EagerTensor 的关系
3. 形状 —— reshape / transpose / expand_dims / squeeze / stack / concat / split / tile / broadcast_to
4. 广播 —— 从右往左对齐维度、长度为 1 可扩展、不兼容形状直接报错
5. 运算 —— 逐元素、reduce、softmax/sigmoid/relu、clip、argmax、gather、one_hot
6. 变量 —— tf.Variable 的 assign / assign_add / trainable，与 tf.constant 的边界
7. 互操作 —— convert_to_tensor、.numpy()、tf.py_function/numpy_function 与显式 dtype 转换
8. 线代 —— matmul / einsum / linalg.inv 等矩阵层算子
```

本机实测环境：Ubuntu 24.04、Python 3.12.3、TensorFlow 2.20.0、Keras 3.15.1、NumPy 2.5.4，纯 CPU（`is_cuda_build=False`）。下文所有 `text` 代码块都是这台机器上真实运行脚本的输出，未做任何改写；个别因版本差异失败的写法也原样保留并标注原因。

## 张量创建与核心属性

创建张量的入口集中在 `tf.constant` 与一批工厂函数上。`tf.constant` 从 Python 列表或 NumPy 数组构造不可变张量，并用 `dtype` 参数显式指定类型——不指定时 TensorFlow 会按输入推断（Python int 得到 int32，Python float 得到 float32，NumPy 数组沿用数组的 dtype），这是后续类型不匹配报错的最常见来源。随机张量分 `tf.random.uniform` / `tf.random.normal` 等，配合 `tf.random.set_seed` 或算子的 `seed` 参数保证可复现。

```python
import numpy as np
import tensorflow as tf

# 常量：显式指定 dtype 是硬规矩
a = tf.constant([[1, 2], [3, 4]], dtype=tf.float32)
print(a.shape, a.dtype, a.ndim, a.device)

# 工厂函数
tf.zeros([2, 3])                      # 全 0
tf.ones_like(a)                       # 与 a 同形状同类型填 1
tf.fill([2, 2], 7)                    # 填标量
tf.range(0, 10, 2)                    # 等差整数
tf.linspace(0.0, 1.0, 5)              # 等距浮点（含两端）
tf.eye(3)                             # 单位阵

# 随机：seed 固定后可复现（tf.random.set_seed 设置全局种子）
tf.random.set_seed(7)
x1 = tf.random.normal([3], seed=1)
tf.random.set_seed(7)
x2 = tf.random.normal([3], seed=1)

# 不规则与稀疏：长度不齐的序列用 ragged，大量 0 用 sparse
tf.ragged.constant([[1, 2], [3]])
tf.sparse.from_dense([[1, 0], [0, 2]])
```

```text
5. 字符串张量的 .numpy() 返回 bytes 列表，与 str 比较前要先 decode
```

## 形状操作与广播

形状操作是张量编程里出错最多的一类，原因是「不报错的错」比「报错的错」更危险：`reshape` 只要元素总数对得上就会成功，但语义可能已经错了。做形状变换时先算清元素总数，再用 `-1` 让 TensorFlow 推断那一维（**每张量最多一个 `-1`**）。`tf.transpose` / `tf.expand_dims` / `tf.squeeze` 是保语义的安全变换，`tf.reshape` 是保元素数的危险变换——能用前者就别用后者。

广播规则与 NumPy 一致：从**最右维**开始逐维比较，相等或其中一方为 1 才兼容，缺失的维度视为 1。`(1,3)` 与 `(2,1)` 广播成 `(2,3)`；`(3,)` 与 `(2,)` 不兼容，直接抛 `InvalidArgumentError`。

```python
import tensorflow as tf

z = tf.reshape(tf.range(12), (3, 4))     # 元素数 12 必须对得上
tf.transpose(z)                          # (4, 3)
tf.expand_dims(z, axis=0)                # (1, 3, 4)
tf.squeeze(tf.expand_dims(z, axis=0))    # 回到 (3, 4)
tf.stack([a, a], axis=0)                 # 沿新维堆叠
tf.concat([a, a], axis=0)                # 沿已有维拼接
tf.split(z, num_or_size_splits=3, axis=0)
tf.broadcast_to(tf.constant([1, 2, 3]), [2, 3])   # 只做视图式扩展
tf.tile(tf.constant([[1, 2]]), [2, 3])            # 真正复制数据

# 广播：从右往左对齐
b1 = tf.constant([[1, 2, 3]])   # (1,3)
b2 = tf.constant([[10], [20]])  # (2,1)
print((b1 + b2).shape)          # (2,3)

# 不兼容形状直接报错
tf.constant([1, 2, 3]) + tf.constant([1, 2])
```

本机真实输出：


注意 `broadcast_to` 与 `tile` 的差别：前者不复制数据（只是按广播规则「看起来」变大），后者真的把数据复制多份，内存占用按倍数增长。批量预处理里做逐通道归一化时用广播写法 `(x - mean) / std` 即可，不要先 `tile` 出同形状的均值张量。

```text
形状与广播要点：
1. reshape 只保证元素总数不变，不保证语义；能用 expand_dims/squeeze/transpose 就不要 reshape
2. reshape 里最多写一个 -1，其余维度必须明确，元素数对不上会立刻报错
3. 广播从最右维往左对齐，逐维「相等或一方为 1」；(3,) 与 (2,) 不兼容，报 InvalidArgumentError
4. broadcast_to 不复制数据、tile 复制数据，做归一化优先用广播而不是 tile
5. stack 沿新维堆叠、concat 沿已有维拼接，二者形状变化规则完全不同，别混用
```

## 数学运算与常用算子

TensorFlow 的算子分三层：`tf.add` 这类逐元素运算（同时有 `+ - * /` 运算符重载）、`tf.reduce_*` 归约运算（必须显式给 `axis`，否则默认全体归约）、以及 `tf.nn` / `tf.math` 下的领域算子（`softmax`、`sigmoid`、`relu`、`log`、`clip_by_value`）。分类任务里最常手搓的三件事——softmax 归一化、交叉熵、argmax 取类别——都在这两层里。要点是：**凡是涉及概率与对数，优先用 `tf.nn.softmax_cross_entropy_with_logits` 这类融合算子**，它们内部做了数值稳定处理，手写 `-y*log(softmax(z))` 会在 logits 较大时溢出。

```python
import tensorflow as tf

x = tf.constant([-1.0, 2.0, -3.0])
y = tf.constant([2.0, 3.0, 4.0])

x + y; x * y; tf.pow(y, 2)
tf.matmul(a, a)                                # 矩阵乘（2 维）
tf.matmul(tf.ones([2, 2, 3]), tf.ones([2, 3, 4]))  # 批量矩阵乘，保留前导批维

tf.reduce_sum(a, axis=0)                       # 必须显式给 axis
tf.reduce_mean(a); tf.reduce_max(a)
tf.argmax(a, axis=1)
tf.abs(x); tf.floor(tf.constant([1.7])); tf.round(tf.constant([1.5, 2.5]))
tf.sqrt(y); tf.exp(tf.constant([0.0, 1.0])); tf.math.log(y)
tf.clip_by_value(tf.constant([-5.0, 0.5, 9.0]), 0.0, 1.0)

# 分类常用
p = tf.constant([[0.1, 0.9], [0.8, 0.2]])
tf.nn.softmax(p, axis=-1)
tf.sigmoid(tf.constant([-1.0, 0.0, 1.0]))
tf.nn.relu(tf.constant([-2.0, 3.0]))
tf.equal(tf.constant([1, 2]), tf.constant([1, 3]))
```

本机真实输出：


两处值得留意。第一，`tf.round` 采用「四舍六入五取偶」（banker's rounding），所以 `[1.5, 2.5]` 都舍入到 `2.0`——金融类数值处理不能想当然按「四舍五入」用。第二，softmax 每行和打印出 `0.9999999403953552` 而不是精确 1，这是 float32 的舍入误差，属于正常现象，做断言时要用容差而不是 `==`。

```text
数学运算要点：
1. reduce_* 一定要显式给 axis；不给 axis 是全体归约，语义和数据规模都会变
2. 概率与对数场景优先用融合算子（softmax_cross_entropy_with_logits），手写会在极端 logits 下溢出
3. softmax 行和是 1 只是数学性质，float32 下会差在 1e-7 量级，断言必须带容差
4. tf.round 是「四舍六入五取偶」，与 Python round 同规则，与「传统四舍五入」不同
5. 运算符重载（+ * /）与 tf.add 等函数等价，但涉及 dtype 时两者都会做严格类型检查
```

## 变量与常量

`tf.constant` 不可变，`tf.Variable` 可变且默认 `trainable=True`——训练的本质就是优化器不断对 `tf.Variable` 做 `assign`。三者关系要分清：`tf.Variable` 的**变量对象**不能改形状，但它的**值**可以整体替换（`assign`）或就地更新（`assign_add`、`scatter_nd_update`）。Keras 层内部维护的 `kernel` / `bias` 都注册在 `layer.trainable_variables` 里，用 `GradientTape` 取梯度的对象正是它们。

```python
import tensorflow as tf

w = tf.Variable([[1.0, 2.0], [3.0, 4.0]], name="w")
print(w.trainable, w.name)          # True  w:0

w.assign(w + 1.0)                   # 整体赋值
w.assign_add(tf.ones([2, 2]))       # 就地加
v = tf.Variable([1.0, 2.0])
v.scatter_nd_update([[1]], [99.0])  # 按索引更新指定位置

c = tf.constant([1, 2])
c[0].assign                        # AttributeError：常量没有 assign
```

本机真实输出：

```text

       [3., 4.]], dtype=float32)>
```

上面脚本还有一行在 TF 2.20 上跑失败，原样保留，这是很典型的「教程里有的函数在当前版本已不存在」案例：

```text
trainable 变量清单: [v.name for v in tf.trainable_variables()]
AttributeError: module 'tensorflow' has no attribute 'trainable_variables'
```

正确做法是：用 `tf.compat.v1.trainable_variables()`（TF1 兼容层，本机返回 `[]`，因为作用域里没有 Figure 级变量），或在 Keras 里用 `model.trainable_variables` / `layer.trainable_variables`。现代写法是后者，TF1 兼容层只用于老代码过渡。

```text
变量与常量要点：
1. tf.Variable 默认 trainable=True；设为 False 后优化器不会再更新它（冻结层的原理）
2. assign 整体替换值、assign_add 就地累加、scatter_nd_update 按索引改，三者用途不同
3. tf.constant 不能 assign，需要可变状态一律用 tf.Variable
4. tf.trainable_variables 在 TF 2.x 顶层命名空间不可用，Keras 里用 model.trainable_variables
5. 变量名打印有 :0 后缀（如 w:0），这是图时代的命名残留，比较名字时要注意
```

## NumPy 互操作与类型转换

TensorFlow 与 NumPy 的互操作是双向的：NumPy 数组可以直接参与 TF 运算（隐式转成 EagerTensor），TF 张量可以用 `.numpy()` 取回 NumPy 数组。这在数据准备、指标计算、与 sklearn/pandas 对接时极其常用。关键约束有两条：**dtype 不会自动提升**（`float32` 张量与 `int32` 张量相加会直接报错，必须 `tf.cast`），以及**`.numpy()` 只在即时执行下可用**（在 `tf.function` 内部调用会失败）。

```python
import numpy as np
import tensorflow as tf

arr = np.array([[1, 2], [3, 4]], dtype=np.float32)
t = tf.convert_to_tensor(arr)      # NumPy -> Tensor
t.numpy()                          # Tensor -> NumPy（返回 ndarray）
arr + t                            # 隐式转换后按 TF 语义计算

# 类型转换：显式且必要
tf.cast(tf.constant([[1, 2]], dtype=tf.int64), tf.float32)
tf.one_hot([0, 2], depth=3)
tf.strings.as_string(tf.constant([1, 2]))

# 一定要用 Python 逻辑时（会打断图优化，仅用于调试/桥接）
tf.py_function(lambda s: s * 2, [tf.constant([1, 2, 3])], tf.int32)
tf.numpy_function(lambda s: s + 1, [tf.constant([1, 2])], tf.int32)
```

本机真实输出：

```text

tensor -> numpy: ndarray [[1.0, 2.0], [3.0, 4.0]]
```

三个真实结论：`np.shares_memory(arr, t.numpy())` 为 `False`，说明 `.numpy()` 不是零拷贝视图而是新数组，在大批数据上频繁往返会有内存与拷贝开销；`tf.cast` 浮点转整数是**向零截断**（`1.9 -> 1`、`-1.9 -> -1`），不是四舍五入；`tf.py_function` / `tf.numpy_function` 能把任意 Python 逻辑接进计算图，代价是失去图优化与可序列化性，只应作为桥接手段。注意二者必须显式声明输出 `dtype`，写错会在运行期才报错。

```text
NumPy 互操作要点：
1. dtype 不自动提升：float32 与 int32 相加直接 InvalidArgumentError，先 tf.cast
2. .numpy() 只在即时执行下可用，tf.function 内部调用会失败；需要取值请从图外取
3. .numpy() 返回新数组（本机验证 np.shares_memory 为 False），大数据勿反复往返
4. tf.cast 浮点转整数是向零截断，做「四舍五入取整」要显式用 tf.round 再 cast
5. tf.py_function / tf.numpy_function 是调试与桥接工具，会破坏图优化与序列化能力
```

## 线性代数与 einsum

矩阵层运算集中在 `tf.matmul`（批量矩阵乘）、`tf.linalg.*`（求逆、行列式、分解）与 `tf.einsum`（爱因斯坦求和）。`einsum` 用一个字符串同时表达转置、求和、批量矩阵乘等操作，写对了比堆 `tf.transpose + tf.matmul` 更短也更快，代价是可读性——建议只在多人约定清楚或注释齐全时使用。注意 `tf.matmul` 要求两个操作数**秩相同**，NumPy 那种「矩阵乘向量自动降维」的便利在 TF 里没有。

```python
import tensorflow as tf

m = tf.constant([[1.0, 2.0], [3.0, 4.0]])
tf.einsum("ij,jk->ik", m, m)       # 批量矩阵乘的通用写法
tf.matmul(tf.ones([2, 2, 3]), tf.ones([2, 3, 4]))   # (2,2,4)
tf.linalg.det(m)
tf.linalg.inv(m)
tf.reduce_all(tf.constant([True, True]))
tf.reduce_any(tf.constant([False, True]))

# 秩不同会报错（NumPy 里能跑，TF 里不行）
w = tf.Variable(tf.constant([[1.0, 2.0], [3.0, 4.0]]))
xv = tf.constant([1.0, 10.0])
w @ xv      # InvalidArgumentError: In[0] and In[1] has different ndims: [2,2] vs. [2]
```

本机真实输出：

```text
linalg.det: -2.0
linalg.inv: [[-2.0, 1.0], [1.5, -0.5]]
```

```text
3. einsum 能表达转置/求和/批量乘，但可读性差，团队使用要统一约定并写注释
4. 批量矩阵乘的前导维必须一致或可广播，报错时先看形状而不是先怀疑数值
5. 求逆是数值不稳定的操作，解线性方程组用 tf.linalg.solve 而不是 inv 再 mul
```

## 应用场景实战

### 场景一：用纯张量算子实现图像批次预处理流水线

工程里图像在进模型之前通常要经过「缩放 -> 按通道标准化 -> 维度置换 -> 裁剪」四步，这些步骤要放在计算图里（而不是 Python 循环里），才能被 `tf.function` 编译并享受多线程与向量化。下面这段在本机真实运行，数据用随机张量代替真实图片：

```python
import numpy as np
import tensorflow as tf

tf.random.set_seed(0)
N, H, W, C = 4, 8, 8, 3
imgs = tf.random.uniform([N, H, W, C], minval=100.0, maxval=200.0)
imgs = imgs * tf.constant([1.0, 0.9, 0.8], dtype=tf.float32)   # 模拟通道间尺度差异

# 1) 缩放到 [0,1]
x = imgs / 255.0

# 2) 按通道标准化：mean/std 沿 N,H,W 统计，keepdims 让广播对齐
mean = tf.reduce_mean(x, axis=[0, 1, 2], keepdims=True)
std = tf.math.reduce_std(x, axis=[0, 1, 2], keepdims=True)
norm = (x - mean) / (std + 1e-6)

# 3) NHWC -> NCHW（部分推理后端要求）
chw = tf.transpose(norm, perm=[0, 3, 1, 2])

# 4) 裁剪异常值
clipped = tf.clip_by_value(norm, -3.0, 3.0)
```

本机真实输出：

```text
=== 场景一：图像批次归一化流水线（纯张量算子）===
原始 dtype/shape: <dtype: 'float32'> (4, 8, 8, 3)
原始每通道均值: [147.99000549316406, 135.44000244140625, 118.54000091552734]
原始全局范围: 80.0713119506836 -> 198.91998291015625
标准化后每通道均值: [0.0, -9.999999974752427e-07, 9.999999974752427e-07]
标准化后每通道标准差: [1.0, 1.0, 1.0]
转置后 shape: (4, 3, 8, 8) (NCHW)
翻转后 shape: (4, 8, 8, 3) | 与原理图是否逐像素镜像: True
裁剪后极值: -1.736 1.7512
```

这段验证了两件事：标准化后每通道均值是 0（打印出 `-1e-06` 量级是 float32 舍入）、标准差是 1，说明统计与广播写对了；`reshape` 全程没出现，形状变换只用 `transpose`，语义可控。`keepdims=True` 是关键——不加它，`mean` 会变成形状 `(C,)`，虽然还能广播，但一旦维度顺序不是「批在前、通道在后」就会静默算错。

```text
图像预处理流水线要点：
1. 统计量用 keepdims=True 保留维度，避免后续广播在通道顺序变化时静默算错
2. 除标准差时加极小值（1e-6）防除零；纯色图像的标准差恰好为 0，这是真实会遇到的输入
3. 维度置换用 tf.transpose 而不是 reshape，语义明确且不会被误改元素顺序
4. 归一化后按 ±3σ 裁剪是常规做法，能挡住坏点但不改变分布主体
5. 整条流水线都是张量算子，可以直接塞进 tf.function 与 tf.data 的 map 里（见 11.6）
```

### 场景二：手算 softmax 交叉熵并与融合算子对照

理解分类损失的内部结构对排查「loss 不降」「loss 变 NaN」很关键。下面用纯张量算子手算一遍交叉熵，再与 Keras 损失、TF 融合算子对照，最后用自动微分验证手推的梯度公式 `softmax(logits) - one_hot`：

```python
logits = tf.constant([[2.0, 1.0, 0.1],
                      [0.5, 2.5, 0.3],
                      [-1.0, 0.0, 3.0]], dtype=tf.float32)
labels = tf.constant([0, 1, 2])

probs = tf.nn.softmax(logits, axis=-1)
onehot = tf.one_hot(labels, depth=int(logits.shape[-1]))
eps = 1e-7
ce_manual = -tf.reduce_sum(onehot * tf.math.log(probs + eps)) / 3.0

# 对照 1：Keras 的 CategoricalCrossentropy（输入概率，from_logits=False）
keras_ce = tf.keras.losses.CategoricalCrossentropy()(onehot, probs)

# 对照 2：融合算子（输入 logits，内部做数值稳定处理）
tf_ce = tf.reduce_mean(tf.nn.softmax_cross_entropy_with_logits(labels=onehot, logits=logits))
```

本机真实输出：

```text
=== 场景二：手算 softmax 交叉熵并核对 ===
手算交叉熵: 0.234321
keras CCE(概率): 0.234321
tf.nn 稳定版: 0.234321
三者一致: True
预测类别: [0, 1, 2] 真实: [0, 1, 2]
batch 准确率: 1.0
交叉熵对 logits 的梯度(期望):
 [[-0.1137  0.0808  0.0329]
 [ 0.0362 -0.0658  0.0296]
 [ 0.0057  0.0155 -0.0213]]
自动微分得到的梯度:
 [[-0.1137  0.0808  0.0329]
 [ 0.0362 -0.0658  0.0296]
 [ 0.0057  0.0155 -0.0213]]
梯度一致: True
```

三个表达式给出同一个数（0.234321），说明手算路径正确；梯度手推与自动微分逐元素一致，说明「softmax 交叉熵的梯度 = 概率 - one-hot」这条在实践里可以直接用来做 sanity check。工程上的结论是反向的：既然三者数值等价，就该用融合算子 `tf.nn.softmax_cross_entropy_with_logits`——它在 logits 很大时不需要 `+1e-7` 这种补丁，也不会出现 `log(0)`。

```text
交叉熵核对要点：
1. 手算路径：softmax -> one_hot -> -sum(y*log(p))/N，理解它才知道 loss 为什么这么定义
2. 三种实现数值一致时，生产代码一律选融合算子（内部 log-sum-exp 稳定化）
3. 梯度恒等式「dCE/dlogits = softmax(logits) - one_hot」可直接用作实现的自检
4. 手算时加的 eps（1e-7）是防 log(0) 的补丁；融合算子不需要这个补丁
5. 别在 Keras 里把概率再喂给 from_logits=True 的损失，那会造成双重 softmax，loss 会虚高但不会报错
```

## 最佳实践与踩坑记录

### 最佳实践

1. 创建张量一律显式写 `dtype`；不要依赖 Python 字面量的推断结果，推断结果随输入类型变化。
2. 形状变换优先 `expand_dims` / `squeeze` / `transpose`，只在确实需要重排元素时才用 `reshape`。
3. 归约算子一律显式写 `axis`；不写等于全体归约，是最常见的静默错误来源。
4. 概率与对数相关的损失优先用融合算子（`tf.nn.softmax_cross_entropy_with_logits` 等），不要手写 `log(softmax(x))`。
5. 训练相关的可变量用 `tf.Variable`，配置与超参用 `tf.constant`；把两者混用会让 `GradientTape` 追踪范围出问题。
6. 与 NumPy 的边界收在数据准备阶段：训练循环内部全部用张量，避免 `.numpy()` 反复往返打断图执行。
7. 做数值断言时带容差（`np.allclose` 或 `atol`），float32 的误差在 1e-7 量级，`==` 比较必然失败。

### 踩坑记录

```text
坑 1：float32 张量与 int32 张量相加，抛 InvalidArgumentError
结论：以为运算符重载会像 NumPy 一样自动提升类型，结果训练循环里某一处直接崩。
原因：TensorFlow 严格检查 dtype，不做隐式类型提升。本机实测报错原文：
      "cannot compute AddV2 as input #1(zero-based) was expected to be a float tensor"。
解法：在数据入口统一 dtype（例如全部 tf.cast(..., tf.float32)），标签单独保持 int32 并在
      需要参与算术时再 cast；不要在表达式中间临时 cast，那会让代码难以审计。

坑 2：reshape 后模型不报错但精度异常，查了很久才怀疑形状
结论：以为数据变了或超参不对，反复调学习率。
原因：reshape 只校验元素总数，不校验语义。例如 (N,H,W,C) 误 reshape 成 (N,C,H,W) 元素数相同，
      会静默把通道维与高度维混在一起，形状合法、数值全错。
解法：需要改变维度顺序时用 tf.transpose(perm=...)，需要增删长度为 1 的维度时用 expand_dims/squeeze；
      确实要 reshape 时先打印元素总数与目标形状做核对。

坑 3：reduce_sum 忘了写 axis，得到的标量被当成了正常输出
结论：loss 看似正常收敛，但指标与预期差一个量级。
原因：不写 axis 的 reduce_* 是全体归约，把批与特征一起求和/求平均，语义与「按批求平均」完全不同。
解法：所有 reduce_* 显式写 axis；习惯写法是 tf.reduce_mean(losses) 之前先确认 losses 的形状，
      并在关键位置用 tf.debugging.assert_rank 或打印 .shape 自检。

坑 4：在 tf.function 内部调用 .numpy()，报错或行为异常
结论：图模式下的代码忽然跑不通，即时执行下同样的代码是好的。
原因：.numpy() 需要真实数值，只能在即时执行下调用；在 tf.function 追踪阶段没有具体张量。
解法：把取值操作移出 tf.function（返回值让调用方 .numpy()），或改用 tf.print 做图内输出；
      需要图内断言的场景用 tf.debugging.assert_* 系列。

坑 5：手写交叉熵在 logits 较大时变成 inf / NaN
结论：以为数据里有坏点，去清洗数据。
原因：p = softmax(z) 在 z 很大时趋近 0，log(p) 得到 -inf；即使加了 eps，float32 下 eps 也会被
      大 logits 淹没。
解法：用 tf.nn.softmax_cross_entropy_with_logits（吃 logits，内部做 log-sum-exp 稳定化）；
      同理 softplus 场景用 tf.math.softplus 而不是 log(1+exp(x))。

坑 6：tf.trainable_variables 报 module 'tensorflow' has no attribute
结论：以为自己记错了库名，去搜索 API 文档怀疑环境装坏。
原因：该符号只存在于 TF1 兼容层（tf.compat.v1.trainable_variables），TF2 顶层命名空间已移除。
解法：Keras 里用 model.trainable_variables / layer.trainable_variables；TF1 老代码过渡期用
      tf.compat.v1.trainable_variables()，并在注释里标明这是兼容层。
```

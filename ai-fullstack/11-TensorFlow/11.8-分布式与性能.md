## 概述

TF 的性能问题几乎都能拆成三段：**数据供给**（tf.data 是否跟得上）、**单步计算**（图模式、混合精度、XLA）、**并行度**（单机多卡 / 多机）。分布式用 `tf.distribute.Strategy` 表达——同一份建模代码套在 `MirroredStrategy`、`MultiWorkerMirroredStrategy`、`TPUStrategy` 里，变量与梯度同步由策略负责；性能侧优先做的三件事是：把训练步包进 `tf.function`（本机 CPU 实测差 10 倍以上，负载轻时接近 20 倍）、按硬件开混合精度、以及用 profiler 找到真正的瓶颈再动手。

```text
本篇主线：
1. 分布式策略 —— MirroredStrategy/OneDeviceStrategy/MultiWorkerMirroredStrategy/TPUStrategy 的选型与 scope 约束
2. GPU 与 TPU —— 设备可见性、显存增长、逻辑设备切分；TPU 的 GCS 数据要求（本机无 GPU/TPU，仅给官方文档结论）
3. 混合精度 —— mixed_float16/bfloat16 的 dtype policy、变量仍是 float32、CPU 上不加速反而更慢
4. 图模式 —— tf.function 的追踪与重追踪、input_signature、reduce_retracing、jit_compile(XLA)
5. 性能剖析 —— tf.profiler.experimental + TensorBoard、单步拆解、batch size 与吞吐、steps_per_execution
```

本机实测环境：Ubuntu 24.04、Python 3.12、**TensorFlow 2.20.0 的 `tensorflow_cpu` 构建**、Keras 3.15.1；`tf.config.list_physical_devices("GPU")` 返回空，`nvidia-smi` 报 `Failed to initialize NVML: Driver/library version mismatch`（NVML 库 580.178）。**因此本篇所有 GPU/TPU 相关结论在本机无法验证，凡涉及它们的内容均以官方文档为准并明确标注。** 本机是 8 逻辑核的负载机器，下文的耗时数字是多轮取最小值后的结果，只看数量级与相对关系。

## 分布式策略

策略对象描述「变量放哪、梯度怎么同步」，`strategy.scope()` 上下文里的变量创建才会被复制到各副本。选型很直接：单机多卡用 `MirroredStrategy`（默认 NCCL all-reduce），只想固定跑在某张卡上用 `OneDeviceStrategy`，多机用 `MultiWorkerMirroredStrategy`（或 `ParameterServerStrategy`），TPU 用 `TPUStrategy`。用 `model.fit` 时 Keras 会自动处理分发，只有自己写训练循环才需要 `strategy.run` / `strategy.reduce`。

```python
import numpy as np
import tensorflow as tf
import keras

keras.utils.set_random_seed(42)
rng = np.random.default_rng(0)
N = 4096
X = rng.normal(size=(N, 64)).astype("float32")
y = (X @ rng.normal(size=64) > 0).astype("float32")

print("逻辑设备:", [d.device_type + ":" + str(d.name) for d in tf.config.list_logical_devices()])
print("GPU:", tf.config.list_physical_devices("GPU") or "无（本机是 tensorflow_cpu 构建）")
print("内置策略:", [n for n in dir(tf.distribute) if n.endswith("Strategy")])

strategy = tf.distribute.MirroredStrategy()
print("MirroredStrategy 副本数:", strategy.num_replicas_in_sync)
print("OneDeviceStrategy 副本数:", tf.distribute.OneDeviceStrategy("/cpu:0").num_replicas_in_sync)


def build():
    m = keras.Sequential([keras.Input(shape=(64,)), keras.layers.Dense(64, activation="relu"),
                          keras.layers.Dense(1, activation="sigmoid")])
    m.compile(optimizer=keras.optimizers.Adam(1e-3), loss="binary_crossentropy", metrics=["accuracy"])
    return m


ds = tf.data.Dataset.from_tensor_slices((X, y)).batch(64)
with strategy.scope():
    dist_model = build()
    dist_ds = strategy.experimental_distribute_dataset(ds)
    hist = dist_model.fit(ds, epochs=2, verbose=0)
print("MirroredStrategy 训练:", {k: round(v[-1], 4) for k, v in hist.history.items()})
print("每步全局批大小 = batch_size * num_replicas =", 64 * strategy.num_replicas_in_sync)

# 自定义训练循环里的分布式写法
loss_fn = keras.losses.BinaryCrossentropy()


def make_step(model, optimizer):
    def step_fn(features, labels):
        with tf.GradientTape() as tape:
            loss = loss_fn(labels, model(features, training=True))
        grads = tape.gradient(loss, model.trainable_variables)
        optimizer.apply_gradients(zip(grads, model.trainable_variables))
        return loss

    @tf.function
    def dist_step(inputs):
        per_replica = strategy.run(step_fn, args=(inputs[0], inputs[1]))
        return strategy.reduce(tf.distribute.ReduceOp.SUM, per_replica, axis=None)

    return dist_step


# 坑：优化器必须在同一个 strategy.scope() 内创建
try:
    bad_step = make_step(dist_model, keras.optimizers.Adam(1e-3))
    bad_step(next(iter(dist_ds)))
except Exception as e:
    print("scope 外创建优化器 ->", type(e).__name__, ":", str(e).splitlines()[-1][:90])

with strategy.scope():
    good_optimizer = keras.optimizers.Adam(1e-3)
step = make_step(dist_model, good_optimizer)
print("分布式单步 loss:", round(float(step(next(iter(dist_ds)))), 4))
# 不在 strategy.scope 内时拿到的是默认 replica context，副本数为 1
print("replica context 副本数:", tf.distribute.get_replica_context().num_replicas_in_sync)
```

本机真实输出：

```text
逻辑设备: ['CPU:/device:CPU:0']
GPU: 无（本机是 tensorflow_cpu 构建）
内置策略: ['MirroredStrategy', 'MultiWorkerMirroredStrategy', 'OneDeviceStrategy', 'ParameterServerStrategy', 'Strategy', 'TPUStrategy']
MirroredStrategy 副本数: 1
OneDeviceStrategy 副本数: 1
MirroredStrategy 训练: {'accuracy': 0.8884, 'loss': 0.357}
每步全局批大小 = batch_size * num_replicas = 64
scope 外创建优化器 -> RuntimeError :     RuntimeError: Mixing different tf.distribute.Strategy objects
分布式单步 loss: 0.3218
```

同理，`tf.device("/cpu:0")` 手工指定设备也能训练（本机实测 accuracy 0.8801 / loss 0.376），但它只做设备放置、不做副本同步，与 `Strategy` 不是一回事。

策略选型对照：

| 策略 | 适用 | 变量与梯度 | 备注 |
| --- | --- | --- | --- |
| `MirroredStrategy` | 单机多 GPU | 每卡一份镜像变量，all-reduce 同步 | 默认 NCCL；无 GPU 时退化成 1 副本 |
| `OneDeviceStrategy` | 单卡调试、多卡机里固定一张卡 | 单副本 | 常用来做「多卡代码单卡跑」的测试 |
| `MultiWorkerMirroredStrategy` | 多机同步训练 | 各 worker 镜像 + all-reduce | 官方文档：需设置 `TF_CONFIG` 环境变量描述集群 |
| `ParameterServerStrategy` | 大规模异步/参数服务器 | 参数放在 PS | 与 `tf.distribute.coordinator` 配套 |
| `TPUStrategy` | Cloud TPU | TPU 核之间同步 | 需要 TPU 资源与 GCS 上的数据集（官方文档） |

要点：

```text
1. 变量创建必须在 strategy.scope() 内：模型、优化器、指标都要在 scope 里建（本机实测 scope 外建优化器直接 RuntimeError）
2. num_replicas_in_sync 决定全局批大小：batch_size 是「每个副本的批大小」，想保持全局批次就按副本数除
3. 用 model.fit + strategy.scope() 时不需要手写 strategy.run，Keras 会自动分发
4. 自定义循环用 strategy.run(fn, args=...) 在副本上执行、strategy.reduce(ReduceOp.SUM, ...) 汇总
5. 数据管道要在 scope 外构建（官方文档：创建数据集、定义 tf.function 可以在 scope 内外）；加载会创建变量的操作要放进 scope
6. 本机无 GPU，MirroredStrategy 副本数为 1，所有分布式结论都是「代码路径正确」而非「多卡加速」的验证
```

## GPU 与 TPU 加速

GPU 侧的关键动作有三个：确认可见性（`tf.config.list_physical_devices("GPU")`）、按需开启显存增长（`set_memory_growth`，避免一上来吃满显存）、必要时把一张卡切成多个逻辑设备（`set_logical_device_configuration`）。CPU 侧则是线程数配置（`tf.config.threading`）。**本机 GPU 不可用**：`tensorflow_cpu` 构建 + NVML 驱动/库版本不匹配，因此下面的 GPU 代码块未在本机执行，仅按官方 API 文档给出。

```python
# 本机不可用（tensorflow_cpu 构建，list_physical_devices("GPU") 返回 []）
import tensorflow as tf

gpus = tf.config.list_physical_devices("GPU")
print("可见 GPU:", gpus)
if gpus:
    # 按需增长显存，别一上来就占满
    for gpu in gpus:
        tf.config.set_memory_growth(gpu, True)

    # 或者限制显存上限
    # tf.config.set_logical_device_configuration(
    #     gpus[0], [tf.config.LogicalDeviceConfiguration(memory_limit=4096)])

    # 把一张卡切成两个逻辑设备（调试多卡代码）
    # tf.config.set_logical_device_configuration(
    #     gpus[0], [tf.config.LogicalDeviceConfiguration(memory_limit=4096),
    #               tf.config.LogicalDeviceConfiguration(memory_limit=4096)])

print("逻辑设备:", tf.config.list_logical_devices())
print("TF 是否带 CUDA 支持:", tf.test.is_built_with_cuda())
print("intra_op 线程:", tf.config.threading.get_intra_op_parallelism_threads(),
      "| inter_op 线程:", tf.config.threading.get_inter_op_parallelism_threads())

# 指定设备放置（本机只能在 CPU 上跑）
with tf.device("/cpu:0"):
    a = tf.ones((1000, 1000))
    print("张量所在设备:", a.device)
```

本机真实输出：

```text
可见 GPU: []
逻辑设备: [LogicalDevice(name='/device:CPU:0', device_type='CPU')]
TF 是否带 CUDA 支持: False
intra_op 线程: 0 | inter_op 线程: 0
张量所在设备: /job:localhost/replica:0/task:0/device:CPU:0
```

同样，TPU 部分也未在本机验证。官方文档给出的要点是：申请 Cloud TPU 后用 `TPUClusterResolver` 提供地址，`TPUStrategy` 必须在 **TPU 上创建变量**，且官方要求数据以 TFRecord 形式放在 GCS 上、用 `tf.data.TFRecordDataset` 读取（TPU 直连 GCS 并由 TPU 侧执行输入管道）。下面是文档级写法，未在本机运行：

```python
# 未在本机验证：需要 Cloud TPU 资源与 GCS 数据集
import tensorflow as tf

resolver = tf.distribute.cluster_resolver.TPUClusterResolver(tpu="")
tf.config.experimental_connect_to_cluster(resolver)
tf.tpu.experimental.initialize_tpu_system(resolver)
strategy = tf.distribute.TPUStrategy(resolver)
print("TPU 副本数:", strategy.num_replicas_in_sync)

with strategy.scope():
    # 模型与优化器必须建在 TPU 上
    model = build()
    model.fit(tf.data.TFRecordDataset("gs://bucket/train-*.tfrecord").map(parse).batch(1024))
```

要点：

```text
1. 先确认构建类型：tensorflow_cpu 里根本看不到 GPU（本机即如此），报「找不到 GPU」时先看这一条
2. set_memory_growth(True) 是按需增长，memory_limit 是硬上限（软限制），二者选一，别同时设置
3. 逻辑设备切分只在进程启动初期有效，训练开始后再配置会失败
4. tf.config.threading 返回 0 表示「未显式设置、由 TF 自动决定」，不是「没钱程」
5. TPU 要求变量必须建在 TPU 上（strategy.scope 内），数据集建议放 GCS 用 TFRecord 流式读（官方文档要求）
6. 本机 NVML 报 driver/library version mismatch，说明内核驱动模块与用户态库版本不一致，这种状态下 CUDA 不可用
```

## 混合精度训练

混合精度让大部分算子用 float16/bfloat16 计算、变量与敏感算子保留 float32，用 `keras.mixed_precision.set_global_policy("mixed_float16")` 一行开启。GPU 上能显著提速（官方文档：现代 GPU 上可加速 3 倍以上），但**在 x86 CPU 上官方明确说明会明显变慢**——本机实测也确实跑得动但无收益。

```python
print("默认策略:", keras.mixed_precision.dtype_policy())
keras.mixed_precision.set_global_policy("mixed_float16")
print("设置后:", keras.mixed_precision.global_policy())

with strategy.scope():
    mixed_model = build()
layer = mixed_model.layers[0]
print("层 dtype_policy:", layer.dtype_policy, "| compute_dtype:", layer.compute_dtype,
      "| variable_dtype:", layer.variable_dtype)
print("变量仍是 float32:", mixed_model.weights[0].dtype)
hist16 = mixed_model.fit(X, y, epochs=2, batch_size=64, verbose=0)
print("mixed_float16 在 CPU 上训练:", {k: round(v[-1], 4) for k, v in hist16.history.items()})

# 输出层建议显式退回 float32，避免 sigmoid/softmax 在 fp16 下丢精度
out_layer = keras.layers.Dense(1, activation="sigmoid", dtype="float32")
print("输出层 policy:", out_layer.dtype_policy)

# 默认的 loss scaling 由全局策略接管；显式使用时：
wrapped = keras.mixed_precision.LossScaleOptimizer(keras.optimizers.Adam(1e-3))
print("LossScaleOptimizer:", type(wrapped).__name__)

keras.mixed_precision.set_global_policy("float32")
print("改回 float32:", keras.mixed_precision.global_policy())
print("bfloat16 策略本身可用:", keras.mixed_precision.Policy("mixed_bfloat16"),
      "（官方文档：无 AMX 的 x86 CPU 上会显著变慢）")
```

本机真实输出：

```text
默认策略: <DTypePolicy "float32">
设置后: <DTypePolicy "mixed_float16">
层 dtype_policy: <DTypePolicy "mixed_float16"> | compute_dtype: float16 | variable_dtype: float32
变量仍是 float32: float32
mixed_float16 在 CPU 上训练: {'accuracy': 0.8862, 'loss': 0.3683}
输出层 policy: <DTypePolicy "float32">
LossScaleOptimizer: LossScaleOptimizer
改回 float32: <DTypePolicy "float32">
bfloat16 策略本身可用: <DTypePolicy "mixed_bfloat16"> （官方文档：无 AMX 的 x86 CPU 上会显著变慢）
```

精度策略对照：

| 策略 | compute dtype | variable dtype | 适用硬件 | 备注 |
| --- | --- | --- | --- | --- |
| `float32`（默认） | float32 | float32 | 全部 | 最稳，内存占用最大 |
| `mixed_float16` | float16 | float32 | NVIDIA GPU（compute capability 7.0+，官方文档） | 官方文档称 GPU 上可加速 3 倍以上 |
| `mixed_bfloat16` | bfloat16 | float32 | TPU、支持 AMX 的 Intel CPU（官方文档） | 无 AMX 的 x86 CPU 上会显著变慢 |
| 单层 `dtype="float32"` | 层内 float32 | 层内 float32 | 全部 | 输出层/损失相关层建议强制 |

要点：

```text
1. 混合精度只改计算 dtype，变量与优化器状态仍存 float32，所以收敛性与纯 float32 接近
2. 输出层（sigmoid/softmax）与损失计算建议显式 dtype="float32"，避免小数值被压成 0
3. 开混合精度后无需手工做 loss scaling（Keras 3 会自动处理）；需要自定义就用 LossScaleOptimizer 包一层
4. CPU 上开 mixed_float16 不加速：本机只有约 0.3683 的 loss 表现（模型本身正常），但没有任何速度收益
5. 策略要在建模之前设置（layer 创建时读取全局策略），模型建好后再改只影响新层
6. 有自定义层时要在层里正确设置 autocast（Keras 3 用 dtype_policy 表达），否则混合精度形同虚设
```

## 图模式与 tf.function

`tf.function` 把 Python 函数编译成图：首次调用执行追踪（tracing）建立图，之后复用。差别在本机非常直观——同一步训练 eager 要 130 多毫秒，图模式只要 11 毫秒。代价是「形状变了要重新追踪」：每换一个 batch 形状就多一份 concrete function，用 `input_signature` 或 `reduce_retracing=True` 可以约束；`jit_compile=True` 再加 XLA 融合。

```python
import time

graph_model = build()
graph_model.fit(X, y, epochs=1, batch_size=128, verbose=0)
optimizer3 = keras.optimizers.Adam(1e-3)      # 每个模型一个优化器
loss_fn = keras.losses.BinaryCrossentropy()


def step_eager(x, yb):
    with tf.GradientTape() as tape:
        loss = loss_fn(yb, graph_model(x, training=True))
    grads = tape.gradient(loss, graph_model.trainable_variables)
    optimizer3.apply_gradients(zip(grads, graph_model.trainable_variables))
    return loss


@tf.function
def step_graph(x, yb):
    with tf.GradientTape() as tape:
        loss = loss_fn(yb, graph_model(x, training=True))
    grads = tape.gradient(loss, graph_model.trainable_variables)
    optimizer3.apply_gradients(zip(grads, graph_model.trainable_variables))
    return loss


@tf.function(jit_compile=True)
def step_xla(x, yb):
    with tf.GradientTape() as tape:
        loss = loss_fn(yb, graph_model(x, training=True))
    grads = tape.gradient(loss, graph_model.trainable_variables)
    optimizer3.apply_gradients(zip(grads, graph_model.trainable_variables))
    return loss


def bench(fn, x, yb=None, n=20, warm=3, trials=3):
    """多轮取最小值：本机是负载机器，单次测量波动可达数倍。yb=None 表示只有前向。"""
    best = float("inf")
    for _ in range(trials):
        for _ in range(warm):
            fn(x) if yb is None else fn(x, yb)
        t0 = time.time()
        for _ in range(n):
            fn(x) if yb is None else fn(x, yb)
        best = min(best, (time.time() - t0) / n * 1e6)
    return best


print("eager       单步 %.0f 微秒" % bench(step_eager, X[:128], y[:128]))
print("tf.function 单步 %.0f 微秒" % bench(step_graph, X[:128], y[:128]))
try:
    print("jit_compile 单步 %.0f 微秒" % bench(step_xla, X[:128], y[:128]))
except Exception as e:
    print("XLA 不可用:", type(e).__name__, str(e).splitlines()[-1][:80])

# 重追踪：换输入形状就会多一份 concrete function
for n in (64, 96, 160):
    step_graph(X[:n], y[:n])
print("追踪过的 concrete function 数:", len(step_graph._list_all_concrete_functions_for_serialization()))


@tf.function(input_signature=[tf.TensorSpec([None, 64], tf.float32), tf.TensorSpec([None], tf.float32)],
             reduce_retracing=True)
def step_sig(x, yb):
    return loss_fn(yb, graph_model(x, training=True))


for n in (32, 40, 64, 128, 200):
    step_sig(X[:n], y[:n])
print("input_signature + reduce_retracing 后的 concrete function 数:",
      len(step_sig._list_all_concrete_functions_for_serialization()))
```

本机真实输出：

```text
eager       单步 16303 微秒
tf.function 单步 836 微秒
jit_compile 单步 608 微秒
追踪过的 concrete function 数: 4（含最初的 1 份）
input_signature + reduce_retracing 后的 concrete function 数: 1
```

要点：

```text
1. 训练步一律包 tf.function：本机同一步实测 eager 16303 微秒 vs 图模式 836 微秒（约 20 倍，负载更重时测得 28 倍）
2. 追踪有成本：第一次调用慢是正常的，别把「首个 step 慢」当成性能问题
3. 形状变化会重追踪：本机依次喂 128/64/96/160 四种 batch 大小后产生 4 份 concrete function，输入签名固定后只剩 1 份
4. input_signature 用 [None, 特征数] 声明动态 batch，reduce_retracing=True 允许形状在一定范围内复用
5. jit_compile=True（XLA）本机收益有限（836 vs 608 微秒，约 1.4 倍）：CPU 小模型融合空间有限，GPU 上收益更明显
6. run_eagerly=True 只在调试时用：可以逐行调试但性能会掉回 eager 水平（本机差 28 倍）
```

## 性能剖析与调优

剖析流程是「先量再改」：`tf.profiler.experimental.start/stop` 采集轨迹，产物落在 `plugins/profile/<时间戳>/` 下，用 TensorBoard 打开（Profile 页看 op 级耗时与 tf.data 瓶颈）；想快速定位可以先做粗粒度拆解——前向/反向/更新各占多少、batch size 与吞吐的关系、数据管道是否跟得上。

```python
# 1) 采集剖析数据
PROFILE_DIR = "./prof"
import os
os.makedirs(PROFILE_DIR, exist_ok=True)

for i in range(3):
    step_graph(X[i * 128:(i + 1) * 128], y[i * 128:(i + 1) * 128])

tf.profiler.experimental.start(PROFILE_DIR)
for i in range(60):
    step_graph(X[i * 32:(i + 1) * 32], y[i * 32:(i + 1) * 32])
tf.profiler.experimental.stop()
print("剖析产物:", sorted(os.listdir(PROFILE_DIR + "/plugins/profile")))
# 查看：tensorboard --logdir ./prof  然后打开 Profile 页

# 2) 粗粒度拆解：前向 / 前向+反向 / 前向+反向+更新
import time
import numpy as np


def make_model():
    m = keras.Sequential([keras.Input((128,)), keras.layers.Dense(512, activation="relu"),
                          keras.layers.Dense(256, activation="relu"),
                          keras.layers.Dense(1, activation="sigmoid")])
    return m


big = make_model()
opt_big = keras.optimizers.Adam(1e-3)
Xb = np.random.default_rng(0).normal(size=(8192, 128)).astype("float32")
yb = (Xb @ np.random.default_rng(1).normal(size=128) > 0).astype("float32")


@tf.function
def fwd(x):
    return big(x, training=True)


@tf.function
def fwd_bwd(x, target):
    with tf.GradientTape() as tape:
        loss = loss_fn(target, big(x, training=True))
    return tape.gradient(loss, big.trainable_variables)


@tf.function
def full(x, target):
    with tf.GradientTape() as tape:
        loss = loss_fn(target, big(x, training=True))
    grads = tape.gradient(loss, big.trainable_variables)
    opt_big.apply_gradients(zip(grads, big.trainable_variables))
    return loss


print("参数量:", big.count_params(), "| batch=128 单步耗时（毫秒）")
print("只看前向        %.2f" % (bench(fwd, Xb[:128]) / 1000))
print("前向+反向       %.2f" % (bench(fwd_bwd, Xb[:128], yb[:128]) / 1000))
print("前向+反向+更新  %.2f" % (bench(full, Xb[:128], yb[:128]) / 1000))

# 3) batch size 与吞吐
print(f"{'batch':>6}{'单步(ms)':>12}{'样本/秒':>12}")
for bs in (16, 64, 128, 512, 1024):
    ms = bench(full, Xb[:bs], yb[:bs], n=10) / 1000.0
    print(f"{bs:>6}{ms:>12.2f}{bs / (ms / 1000):>12.0f}")

# 4) 各层耗时（链式前向）
in1 = Xb[:1024]
in2 = big.layers[0](in1)
in3 = big.layers[1](in2)
for name, layer, inp in [("Dense(512,relu)", big.layers[0], in1),
                         ("Dense(256,relu)", big.layers[1], in2),
                         ("Dense(1,sigmoid)", big.layers[2], in3)]:
    t0 = time.time()
    for _ in range(50):
        layer(inp)
    print(f"{name:18s} 输入 {tuple(inp.shape)}  {(time.time() - t0) / 50 * 1e3:.3f} ms")
```

`steps_per_execution` 是本机唯一「看起来该有收益、实际没有」的开关（小模型 + CPU）：1/4/8 分别 1.60s、1.52s、1.62s（3 个 epoch），差异在噪声范围内；它要在大模型或加速器上才有意义。

```text

6. GPU 上第一嫌疑通常是数据管道（GPU 等数据），此时优先看 prefetch/AUTOTUNE 与预处理是否在 CPU 上串行
```

## 应用场景实战

### 场景一：把训练脚本改造成一份代码跑 CPU/单卡/多卡

场景：同一份训练代码要在开发机（CPU）、单卡服务器、多卡服务器上跑，用环境变量切换策略，并把「全局批大小」「每副本批大小」「学习率」三者的关系写清楚。

```python
import os
import numpy as np
import tensorflow as tf
import keras

SEED = 42
keras.utils.set_random_seed(SEED)
rng = np.random.default_rng(SEED)
N, DIM = 20000, 64
X = rng.normal(size=(N, DIM)).astype("float32")
y = (X @ rng.normal(size=DIM) - 0.2 > 0).astype("float32")


def pick_strategy():
    """按环境变量选择策略：cpu / gpu / multiworker。"""
    mode = os.environ.get("TRAIN_MODE", "cpu")
    if mode == "multiworker":
        # 多机需要 TF_CONFIG 描述集群（官方文档：MultiWorkerMirroredStrategy）
        return tf.distribute.MultiWorkerMirroredStrategy()
    if mode == "gpu" and tf.config.list_physical_devices("GPU"):
        return tf.distribute.MirroredStrategy()
    return tf.distribute.OneDeviceStrategy("/cpu:0")          # 无 GPU 时退化为单 CPU


strategy = pick_strategy()
replicas = strategy.num_replicas_in_sync
GLOBAL_BATCH = 256
PER_REPLICA_BATCH = max(1, GLOBAL_BATCH // replicas)
BASE_LR = 1e-3
SCALED_LR = BASE_LR * replicas          # 线性缩放：副本变多时同步放大学习率
print(f"策略={type(strategy).__name__} 副本={replicas} 每副本批={PER_REPLICA_BATCH} lr={SCALED_LR:.4f}")

with strategy.scope():
    model = keras.Sequential([
        keras.Input(shape=(DIM,)),
        keras.layers.Dense(256, activation="relu", kernel_regularizer=keras.regularizers.l2(1e-4)),
        keras.layers.Dense(128, activation="relu"),
        keras.layers.Dense(1, activation="sigmoid"),
    ])
    optimizer = keras.optimizers.Adam(learning_rate=SCALED_LR)     # 必须与模型同 scope
    model.compile(optimizer=optimizer, loss="binary_crossentropy",
                  metrics=[keras.metrics.AUC(name="auc")])

AUTOTUNE = tf.data.AUTOTUNE
train_ds = (tf.data.Dataset.from_tensor_slices((X[:18000], y[:18000]))
            .shuffle(18000, seed=SEED)
            .map(lambda a, b: (tf.cast(a, "float32"), tf.cast(b, "float32")),
                 num_parallel_calls=AUTOTUNE)
            .batch(PER_REPLICA_BATCH, drop_remainder=True)
            .prefetch(AUTOTUNE))
val_ds = tf.data.Dataset.from_tensor_slices((X[18000:], y[18000:])).batch(PER_REPLICA_BATCH).cache()

history = model.fit(train_ds, validation_data=val_ds, epochs=8, verbose=0,
                    callbacks=[keras.callbacks.EarlyStopping(monitor="val_auc", mode="max", patience=3,
                                                             restore_best_weights=True)])
print("最优 val_auc: %.4f | 训练轮数: %d" % (max(history.history["val_auc"]), len(history.history["loss"])))
model.save("./scalable.keras")
print("模型已保存")
```

### 场景二：定位训练慢在哪一层并给出优化动作

场景：训练脚本一天只能跑两个 epoch，需要一份可复用的基准脚本，输出「图模式是否生效 / 数据管道是否瓶颈 / batch size 是否合理 / 混合精度是否可用」四类结论。

```python
"""perf_audit.py：训练前的性能体检脚本。

用法：python perf_audit.py
输出：图模式加速比、数据管道占单步比例、batch 吞吐曲线、混合精度可用性。
"""
import os
import time
import numpy as np
import tensorflow as tf
import keras

keras.utils.set_random_seed(42)
rng = np.random.default_rng(0)
N, DIM, BATCH = 8192, 256, 256
X = rng.normal(size=(N, DIM)).astype("float32")
y = (X @ rng.normal(size=DIM) > 0).astype("float32")

model = keras.Sequential([
    keras.Input(shape=(DIM,)),
    keras.layers.Dense(512, activation="relu"),
    keras.layers.Dense(256, activation="relu"),
    keras.layers.Dense(1, activation="sigmoid"),
])
optimizer = keras.optimizers.Adam(1e-3)
loss_fn = keras.losses.BinaryCrossentropy()
model.compile(optimizer=optimizer, loss=loss_fn)      # train_on_batch 要求先 compile
print("参数量: %d | 逻辑设备: %s" % (model.count_params(),
                                    [d.device_type for d in tf.config.list_logical_devices()]))


def timeit(fn, n=10, warm=3, trials=3):
    best = float("inf")
    for _ in range(trials):
        for _ in range(warm):
            fn()
        t0 = time.time()
        for _ in range(n):
            fn()
        best = min(best, (time.time() - t0) / n)
    return best


def eager_step():
    with tf.GradientTape() as tape:
        loss = loss_fn(y[:BATCH], model(X[:BATCH], training=True))
    optimizer.apply_gradients(zip(tape.gradient(loss, model.trainable_variables),
                                  model.trainable_variables))


@tf.function
def graph_step():
    with tf.GradientTape() as tape:
        loss = loss_fn(y[:BATCH], model(X[:BATCH], training=True))
    optimizer.apply_gradients(zip(tape.gradient(loss, model.trainable_variables),
                                  model.trainable_variables))


graph_step()
ratio = timeit(eager_step) / timeit(graph_step)
print("[图模式] eager %.1f ms vs 图模式 %.1f ms，加速比 %.1fx"
      % (timeit(eager_step) * 1e3, timeit(graph_step) * 1e3, ratio))

# 数据管道：与训练步重叠前的纯供数耗时
def pipelined():
    ds = (tf.data.Dataset.from_tensor_slices((X, y))
          .map(lambda a, b: (a / 255.0 if False else a, b), num_parallel_calls=tf.data.AUTOTUNE)
          .batch(BATCH).prefetch(tf.data.AUTOTUNE))
    for _ in ds.take(5):
        pass


pipe_ms = timeit(pipelined, n=3) * 1e3
step_ms = timeit(graph_step) * 1e3
print("[数据管道] 取 5 批耗时 %.1f ms（含建管道开销），单步训练 %.1f ms，供数占比约 %.0f%%"
      % (pipe_ms, step_ms, 100 * (pipe_ms / 5) / step_ms))

print("[batch 吞吐]")
for bs in (64, 128, 256, 512):
    ms = timeit(lambda: model.train_on_batch(X[:bs], y[:bs]), n=10) * 1e3
    print("   batch=%4d  单步 %6.2f ms  %9.0f 样本/秒" % (bs, ms, bs / (ms / 1e3)))

can_amp = bool(tf.config.list_physical_devices("GPU"))
print("[混合精度] GPU 可用=%s -> mixed_float16 %s"
      % (can_amp, "建议开启" if can_amp else "CPU 上不建议（官方文档：会显著变慢）"))

# 输出结论
print("\n[结论]")
print("- 图模式加速比 %.1fx，若接近 1 说明训练步没被 tf.function 包住" % ratio)
print("- batch=%d 时单步 %.1f ms，吞吐 %.0f 样本/秒" % (BATCH, step_ms, BATCH / (step_ms / 1e3)))
print("- GPU: %s；数据管道需在 GPU 场景下重点验证（GPU 空转等数据是头号瓶颈）"
      % (tf.config.list_physical_devices("GPU") or "不可用"))
```

## 最佳实践与踩坑记录

### 最佳实践

1. 训练步一定包进 `tf.function`：本机同一份逻辑 eager 与图模式差约 28 倍，这是最便宜的性能优化。
2. 变量、优化器、指标都在 `strategy.scope()` 内创建；数据管道可以放外面，但要在 fit 之前构建好。
3. 全局批大小 = 每副本批大小 × 副本数，学习率按副本数线性缩放，并把这三个值打进日志。
4. 用 `input_signature` + `reduce_retracing=True` 控制重追踪；固定形状的数据集不要每次换 batch 形状。
5. 混合精度先看硬件：NVIDIA GPU（compute capability 7.0+）与 TPU 收益明显，x86 CPU 反而更慢（官方文档）。
6. 性能问题先剖析再改：`tf.profiler.experimental` + TensorBoard Profile 页，先确认是数据瓶颈还是算子瓶颈。
7. 基准测试固定环境、多轮取最小值：本机同一脚本两次单步耗时差 2~5 倍，单次测量没有参考价值。
8. GPU 训练时把「GPU 利用率」当成第一指标：利用率长期低于 60% 时优先查数据管道与主机侧预处理。

### 踩坑记录

```text
坑 1：在 strategy.scope() 外面创建优化器，一训练就 RuntimeError
结论：以为是 Keras 3 与 tf.distribute 不兼容。
原因：优化器变量属于另一个策略对象，两个策略混用被显式拒绝
      （本机报错：RuntimeError: Mixing different tf.distribute.Strategy objects: MirroredStrategy ...
      is not ... _DefaultDistributionStrategy）。
解法：模型、优化器、指标全部在同一个 strategy.scope() 内创建；无 GPU 时用 OneDeviceStrategy 保持代码一致。

坑 2：开混合精度后 CPU 训练更慢了
结论：以为 mixed_float16 就是「更快的开关」。
原因：官方文档明确说明：只有支持 float16/bfloat16 加速的硬件才有收益；x86 CPU 上 mixed_float16 会显著变慢。
解法：用 tf.config.list_physical_devices("GPU") 与 CPU 型号判断是否开；CPU 上保持 float32。

坑 3：把 CPU 版 TensorFlow 装进带显卡的机器，一直报找不到 GPU
结论：以为驱动坏了，反复重装驱动。
原因：装的是 tensorflow_cpu 包（本机 pip list 显示 tensorflow_cpu 2.20.0），它根本不带 CUDA 支持；
      另外 nvidia-smi 报 NVML driver/library version mismatch 时，即使装了 GPU 版也用不了。
解法：pip install tensorflow[and-cuda]（或对应版本 GPU 包）并确认 nvidia-smi 正常；先跑
      tf.config.list_physical_devices("GPU") 再写训练代码。

坑 4：tf.function 包了但性能没提升，还越跑越慢
结论：以为 tf.function 无效。
原因：输入形状每次变化都会重新追踪（本机 5 种 batch 产生 5 份 concrete function），
      追踪本身开销大，还可能内存持续增长。
解法：用 input_signature=[tf.TensorSpec([None, 特征数], tf.float32)] 声明动态 batch，
      或加 reduce_retracing=True；固定形状的数据集把 batch 取成固定值。

坑 5：Profiler 采集完在代码里找不到 op 级耗时表
结论：以为采样没生效。
原因：tf.profiler.experimental.Profile 对象没有 profile() 方法，采样产物是
      plugins/profile/<时间戳>/<主机名>.xplane.pb；本机也未安装可用的 Python 解析入口
      （tensorboard-plugin-profile 的转换函数未暴露）。
解法：用 tensorboard --logdir <目录> 打开 Profile 页看 op 耗时与 tf.data 分析，
      或先做粗粒度计时（前向/反向/更新、batch 扫描）来定位。

坑 6：多卡上把 batch_size 当全局批大小，学习率没跟着缩放，效果明显变差
结论：以为是多卡通信导致的精度问题。
原因：在 Keras 里 fit(batch_size=N) 在 MirroredStrategy 下是「每副本 N」，全局批变成 N×副本数，
      等效学习率与迭代次数都变了。
解法：显式算出 GLOBAL_BATCH / replicas 作为每副本批大小，学习率按副本数线性缩放，
      并把三个值一起打进日志验证。
```

## 概述

训练完的模型要经过「保存格式 → 转换 → 目标运行时」三段路：`.keras` 是 Keras 3 的原生格式（zip，含结构与权重，能继续训练），SavedModel 是 TensorFlow 的部署标准格式（被 TF Serving / TF Lite / TF.js 消费），`.tflite` 给移动端与嵌入式，TF.js 的 `model.json + *.bin` 给浏览器。选择标准只有两条：**接收方是什么运行时**，以及**还要不要继续训练**。部署侧还有一条硬规则：线上模型必须是**推理期导出**（Dropout 等训练专属行为已固化），而不是把训练脚本原样搬进容器。

```text
本篇主线：
1. 保存格式 —— .keras / .h5 / weights-only / SavedModel 的能力与体积对比
2. export 与回读 —— model.export()、signature（serving_default）、TFSMLayer 推理复用
3. TF Lite —— from_keras_model/from_saved_model 转换、解释器推理、动态 batch
4. 量化 —— 动态范围 / float16 / int8 全整数量化的体积、误差与实测数据
5. 浏览器端 —— tensorflowjs_converter 两条路径、model.json 结构、Node 侧真实推理验证
6. TF Serving —— docker 起服务、REST 端口 8501、curl 请求与响应格式
```

本机实测环境：Ubuntu 24.04、Python 3.12、**TensorFlow 2.20.0（`tensorflow_cpu` 构建，无 GPU）**、Keras 3.15.1、tensorflowjs 4.22.0、Node 26.7.0。下文输出都是本机真实结果。**未在本机验证的部分**：TF Serving 容器（本机没有 `tensorflow/serving` 镜像，未执行 `docker pull`）与移动端真机推理（无 Android/iOS 设备），这两处只给官方文档给出的命令与协议格式，并明确标注来源。

## 模型保存格式对比

三种落盘方式的分工：`model.save("m.keras")` 保存完整模型（结构 + 权重 + compile 配置 + 优化器状态），加载后可以继续训练；`model.save("m.h5")` 是 Keras 2 时代的 HDF5 格式，Keras 3 仍然支持但会打上 legacy 警告；`model.save_weights("w.weights.h5")` 只存权重，适合共享权重或配合已有代码结构重建模型。

```python
import os
import numpy as np
import tensorflow as tf
import keras

keras.utils.set_random_seed(42)
rng = np.random.default_rng(0)
X = rng.normal(size=(2000, 32)).astype("float32")
y = (X @ rng.normal(size=32) > 0).astype("float32")

model = keras.Sequential([
    keras.Input(shape=(32,), name="features"),
    keras.layers.Dense(512, activation="relu", name="h1"),
    keras.layers.Dense(256, activation="relu", name="h2"),
    keras.layers.Dense(1, activation="sigmoid", name="score")], name="mlp")
model.compile(optimizer=keras.optimizers.Adam(1e-3), loss="binary_crossentropy", metrics=["accuracy"])
model.fit(X, y, epochs=3, batch_size=64, verbose=0)
want = model.predict(X[:64], verbose=0)
print("参数量:", model.count_params())

for fmt, path in [(".keras", "./m.keras"), (".h5", "./m.h5")]:
    model.save(path)
    print(f"{fmt:8s} {os.path.getsize(path):8d} 字节")

model.save_weights("./m.weights.h5")
print("仅权重  %8d 字节" % os.path.getsize("./m.weights.h5"))
print(".keras 内是 zip，包含:", __import__("zipfile").ZipFile("./m.keras").namelist())

reloaded_h5 = keras.saving.load_model("./m.h5")
print(".h5 回读输出一致:", bool(np.allclose(want, reloaded_h5.predict(X[:64], verbose=0), atol=1e-6)))

fresh = keras.Sequential([
    keras.Input((32,)), keras.layers.Dense(512, activation="relu"),
    keras.layers.Dense(256, activation="relu"), keras.layers.Dense(1, activation="sigmoid")])
fresh.load_weights("./m.weights.h5")
print("权重回读输出一致:", bool(np.allclose(want, fresh.predict(X[:64], verbose=0), atol=1e-6)))
```

本机真实输出：

```text
参数量: 148481
.keras    1807409 字节
.h5       1810200 字节
仅权重    1805080 字节
.keras 内是 zip，包含: ['metadata.json', 'config.json', 'model.weights.h5']
.h5 回读输出一致: True
权重回读输出一致: True
```

三种格式对照：

| 格式 | API | 内容 | 体积（本机 14.8 万参数模型） | 能否继续训练 | 部署消费方 |
| --- | --- | --- | --- | --- | --- |
| `.keras` | `model.save()` | 结构 + 权重 + compile 配置 | 1807409 字节 | 能（优化器状态也在内） | Keras 3 |
| `.h5` | `model.save()` | 同上（legacy 布局） | 1810200 字节 | 能（会有 legacy 警告） | Keras 2/3、部分旧工具 |
| `.weights.h5` | `save_weights()` | 仅权重 | 1805080 字节 | 不能（需自建结构） | 权重共享、微调 |
| `SavedModel` | `model.export()` | 推理图 + 变量 | 1.2 MB 左右变量 + 41 KB pb | 不能（是推理图） | TF Serving / TF Lite / TF.js |

要点：

```text
1. 训练产物存 .keras，部署产物走 export() 出 SavedModel，两件事不要混
2. .keras 本质是 zip：metadata.json（Keras 版本）、config.json（结构）、model.weights.h5（权重）
3. 自定义层/模型必须实现 get_config 且类可被加载方 import，否则 .keras 加载会失败
4. 只存权重时加载方必须先构建好结构；本机验证先 build 再 load_weights 输出完全一致
5. 加载后要接着训练就用 load_model（含 optimizer 状态）；只想推理用 TFSMLayer 或 SavedModel
6. 每种格式保存后立刻回读并比较一次输出（allclose），别等上线才发现导出有问题
```

## SavedModel 导出与回读

`model.export(dir)` 生成部署用的 SavedModel：`saved_model.pb`（图定义）+ `variables/`（权重）+ fingerprint，默认签名是 `serving_default`。加载方式有三条：`tf.saved_model.load()` 拿签名函数做原生推理、`keras.layers.TFSMLayer` 把它包成一层复用 Keras 生态、或交给 TF Serving/其它语言运行时。Keras 3 里 SavedModel 不再能直接 `load_model` 回来继续训练，这是与 Keras 2 的主要差别。

```python
sm = "./saved_model"
model.export(sm, verbose=False)
for root, _, files in os.walk(sm):
    for f in sorted(files):
        rel = os.path.relpath(os.path.join(root, f), sm)
        print("   ", rel, os.path.getsize(os.path.join(root, f)))

loaded = tf.saved_model.load(sm)
print("签名:", list(loaded.signatures.keys()))
fn = loaded.signatures["serving_default"]
print("输入键:", list(fn.structured_input_signature[1].keys()), "| 输出键:", list(fn.structured_outputs.keys()))
got = fn(tf.constant(X[:3]))
print("SavedModel 推理:", np.round(got["output_0"].numpy().ravel(), 6).tolist())
print("与 Keras 一致:", bool(np.allclose(want[:3], got["output_0"].numpy(), atol=1e-6)))

# 用 TFSMLayer 把 SavedModel 当 Keras 层用
layer = keras.layers.TFSMLayer(sm, call_endpoint="serving_default")
wrapped = keras.Sequential([keras.Input(shape=(32,)), layer])
out = wrapped.predict(X[:2], verbose=0)
print("TFSMLayer 输出类型:", type(out).__name__, "| 键:", list(out.keys()))
print("TFSMLayer 输出:", np.round(np.asarray(out["output_0"]).ravel(), 6).tolist())

# 命令行自检（已在本机执行）
# saved_model_cli show --dir ./saved_model --all
```

要点：

```text
1. export() 的输入输出名来自模型：输入层叫 features 就导出成 features，输出是 output_0（不是层名 score）

3. TFSMLayer 的 predict 返回 dict，不是数组，取 out["output_0"] 才拿到数值
4. 形状里的 -1 表示动态 batch：只要导出时输入不是固定 batch，服务端就能一次处理任意条数
5. SavedModel 是推理图，不能 load_model 回来继续训练；要继续训练请用 .keras
6. 导出后一定用同样的输入分别跑 Keras 与 SavedModel 对比（本机 allclose=True），这是最省事的防呆
```

## TF Lite 移动端与嵌入式

TF Lite（TF 2.20 起官方称 LiteRT）把模型编译成 `.tflite` 平面缓冲区，给 Android/iOS/嵌入式/微控制器用。Python 侧用 `tf.lite.TFLiteConverter` 转换、`tf.lite.Interpreter` 验证；移动端在 Android 上用 `org.tensorflow.lite.Interpreter`，iOS 上用 `TensorFlowLite` 框架。注意 TF 2.20 的运行时提示：`tf.lite.Interpreter` 已被标记弃用，官方迁移方向是 `ai_edge_litert` 包的 LiteRT 解释器。

```python
# 转换与验证（模型沿用上面训练好的 mlp）
converter = tf.lite.TFLiteConverter.from_keras_model(model)
tflite_bytes = converter.convert()
with open("./m_none.tflite", "wb") as f:
    f.write(tflite_bytes)
print("float32 TFLite 体积:", os.path.getsize("./m_none.tflite"), "字节")

interp = tf.lite.Interpreter(model_path="./m_none.tflite")
din = interp.get_input_details()[0]
print("转换后的输入 shape:", din["shape"], "| shape_signature:", din["shape_signature"])

# 动态 batch：先 resize_tensor_input 再 allocate_tensors
interp.resize_tensor_input(din["index"], [7, 32])
interp.allocate_tensors()
interp.set_tensor(interp.get_input_details()[0]["index"], X[:7])
interp.invoke()
print("resize 到 7 条后的输出:", interp.get_tensor(interp.get_output_details()[0]["index"]).shape)

# signature_runner：按签名名喂数据，更贴近服务化写法
runner = tf.lite.Interpreter(model_path="./m_none.tflite").get_signature_runner()
print("签名输入键:", list(runner._inputs.keys()))
print("signature_runner 推理:", np.round(runner(features=X[:2].astype("float32"))["output_0"].ravel(), 6).tolist())
```

本机真实输出：

```text
float32 TFLite 体积: 595868 字节
转换后的输入 shape: [ 1 32] | shape_signature: [-1 32]
resize 到 7 条后的输出: (7, 1)
签名输入键: ['features']
signature_runner 推理: [2.700000004551839e-05, 0.9976919889450073]
```

Android 侧调用（Java，官方文档写法）：

```java
// build.gradle: implementation("org.tensorflow:tensorflow-lite:2.16.1")
// 或使用 LiteRT 的新坐标 org.tensorflow:tensorflow-lite → ai-edge-litert
Interpreter interpreter = new Interpreter(loadModelFile("m_none.tflite"));
float[][] input = new float[1][32];
float[][] output = new float[1][1];
interpreter.run(input, output);
```

要点：

```text
1. from_keras_model 转换出的模型 batch 维固定为 1（shape=[1,32]），要变长必须 resize_tensor_input 或走 signature_runner
2. shape_signature 里的 -1 才表示真正的动态维度，shape 字段只是「当前分配的形状」，两者不要混看
3. signature_runner 支持按导出时的输入名（features）传参，比按下标 set_tensor 更稳
4. tf.lite.Interpreter 在 TF 2.20 已标记弃用（本机运行即打印迁移提示），新项目按官方迁移指引用 LiteRT 解释器
5. 移动端务必先把 float32 模型跑通再上量化版本，出问题时才能区分是转换问题还是量化问题
6. .tflite 是纯推理资产，不含结构与训练配置，线上回滚要同时管理「模型文件 + 输入预处理版本」
```

## 量化与转换

训练后量化（PTQ）三种模式：**动态范围量化**（权重 int8、激活运行期量化，体积约 1/4、CPU 提速）、**float16 量化**（权重存 float16，GPU 友好）、**int8 全整数量化**（需要代表性数据集校准，CPU/Edge TPU/微控制器都能跑）。实测对照如下（同一个 14.8 万参数 MLP，Keras 文件 1807409 字节）：

```python
def representative_dataset():
    for i in range(200):
        yield [X[i:i + 1]]


def make_converter(mode):
    conv = tf.lite.TFLiteConverter.from_keras_model(model)
    if mode == "dyn":
        conv.optimizations = [tf.lite.Optimize.DEFAULT]                 # 注意是 optimizations（复数）
    elif mode == "f16":
        conv.optimizations = [tf.lite.Optimize.DEFAULT]
        conv.target_spec.supported_types = [tf.float16]
    elif mode == "i8":
        conv.optimizations = [tf.lite.Optimize.DEFAULT]
        conv.representative_dataset = representative_dataset
        conv.target_spec.supported_ops = [tf.lite.OpsSet.TFLITE_BUILTINS_INT8]
        conv.inference_input_type = tf.int8                              # 输入输出也用 int8
        conv.inference_output_type = tf.int8
    return conv


import time
from tensorflow.lite.python import schema_py_generated as schema


def tensor_kinds(path):
    """读 flatbuffer 里的张量类型统计，确认量化是否真的生效"""
    flat = schema.Model.GetRootAsModel(open(path, "rb").read(), 0)
    sub = flat.Subgraphs(0)
    names = {0: "F32", 1: "F32", 2: "F16", 3: "I8", 4: "U8", 9: "I32"}
    kinds = {}
    for i in range(sub.TensorsLength()):
        k = names.get(int(sub.Tensors(i).Type()), str(int(sub.Tensors(i).Type())))
        kinds[k] = kinds.get(k, 0) + 1
    return kinds


def infer_stats(path, x, n=100):
    it = tf.lite.Interpreter(model_path=path)
    d = it.get_input_details()[0]
    it.resize_tensor_input(d["index"], list(x.shape))
    it.allocate_tensors()
    d = it.get_input_details()[0]
    o = it.get_output_details()[0]
    if d["dtype"] == np.int8:                      # int8 输入要按 scale/zero_point 量化
        scale, zero = d["quantization"]
        xi = np.clip(np.round(x / scale + zero), -128, 127).astype(np.int8)
    else:
        xi = x.astype(d["dtype"])
    it.set_tensor(d["index"], xi)
    t0 = time.time()
    for _ in range(n):
        it.invoke()
    ms = (time.time() - t0) / n * 1e3
    out = it.get_tensor(o["index"]).astype("float32")
    if o["dtype"] == np.int8:                      # 反量化输出
        scale, zero = o["quantization"]
        out = (out - zero) * scale
    diff = float(np.max(np.abs(out.reshape(want.shape) - want)))
    return os.path.getsize(path), d["dtype"].__name__, d["quantization"], diff, ms


print(f"{'模式':<10}{'体积(字节)':>12}{'压缩比':>9}{'输入类型':>10}{'最大误差':>12}{'单批64条推理(ms)':>18}")
for tag, mode, name in [("不量化", "none", "m_none"), ("动态范围", "dyn", "m_dyn"),
                        ("float16", "f16", "m_f16"), ("int8", "i8", "m_i8")]:
    path = f"./{name}.tflite"
    if mode != "none":
        open(path, "wb").write(make_converter(mode).convert())
    size, dtype, quant, diff, ms = infer_stats(path, X[:64])
    print(f"{tag:<10}{size:>12}{os.path.getsize('./m.keras')/size:>8.1f}x{dtype:>10}{diff:>12.6f}{ms:>18.3f}")
    print(f"          张量类型 {tensor_kinds(path)} 输入量化参数 {quant}")
```

本机真实输出：

```text
模式              体积(字节)      压缩比      输入类型        最大误差       单批64条推理(ms)
不量化             595868     3.0x   float32    0.000000             0.222
          张量类型 {'F32': 11} 输入量化参数 (0.0, 0)
动态范围            162784    11.1x   float32    0.012868             0.267
          张量类型 {'F32': 9, 'I32': 2} 输入量化参数 (0.0, 0)
float16         299700     6.0x   float32    0.000107             0.243
          张量类型 {'F32': 17} 输入量化参数 (0.0, 0)
int8            171512    10.5x      int8    0.049132             0.317
```

量化模式对照：

| 模式 | 转换设置 | 相对 float32 TFLite | 相对 .keras | 本机最大误差 | 适用 |
| --- | --- | --- | --- | --- | --- |
| 不量化 | 默认 | 1.0x（595868 字节） | 3.0x | 0 | 基线、调试算子兼容性 |
| 动态范围 | `optimizations=[DEFAULT]` | 0.27x（162784 字节） | 11.1x | 0.012868 | CPU 推理、无需校准数据 |
| float16 | `+ supported_types=[tf.float16]` | 0.50x（299700 字节） | 6.0x | 0.000107 | GPU / 移动端 GPU |
| int8 全整数 | `+ representative_dataset` | 0.29x（171512 字节） | 10.5x | 0.049132 | CPU/Edge TPU/微控制器 |

要点：

```text
1. 转换器的量化开关是 optimizations（复数、列表），写 optimize 不会报错但会被静默忽略——本机踩过
2. 动态范围量化不改输入输出 dtype（仍是 float32），int8 全整数量化才把输入输出也变成 int8
3. int8 的输入必须按 (scale, zero_point) 量化（scale≈0.0281, zero_point=11），输出要反量化，否则结果完全对不上
4. float16 量化后 flatbuffer 里张量类型仍标 F32，只在权重缓冲区存 float16，别用类型统计判断 float16 是否生效
5. 本机模型太小，速度差异被噪声淹没（0.22~0.32 ms）；量化的收益主要在体积与内存带宽，算力瓶颈场景才看延迟
6. 量化后必须跑一遍全量验证集比对精度（本机 int8 最大误差 0.049，接近 0.5 阈值的样本会被翻转）
```

## 浏览器端部署 TF.js

TensorFlow.js 用 `tensorflowjs_converter` 把 SavedModel 或 Keras 模型转成 `model.json + 权重分片`，浏览器里用 `tf.loadGraphModel()`（SavedModel 转换结果）或 `tf.loadLayersModel()`（Keras 转换结果）加载。两条路径的差别很实际：**从 `.h5` 走 layers-model、从 SavedModel 走 graph-model**；Keras 3 的原生 `.keras`（zip）当前转换器不认，用 h5py 打开会直接报错。

```bash
# 安装（本机已装 tensorflowjs 4.22.0）
pip install tensorflowjs

# 路径一：Keras 模型（HDF5）-> layers-model
tensorflowjs_converter --input_format keras ./m.h5 ./tfjs_out

# 路径二：SavedModel -> graph-model（推荐，与线上服务导出同一份资产）
tensorflowjs_converter --input_format tf_saved_model ./saved_model ./tfjs_sm_out

# 注意：输入输出路径是位置参数（4.22.0 里没有 --output_path）
```

```javascript
const fs = require('fs');
const path = require('path');

const DIR = './tfjs_sm_out';
const modelJSON = JSON.parse(fs.readFileSync(path.join(DIR, 'model.json'), 'utf8'));
const buf = fs.readFileSync(path.join(DIR, modelJSON.weightsManifest[0].paths[0]));

  modelTopology: modelJSON.modelTopology,

}));
console.log('输入:', model.inputs.map(t => `${t.name} ${JSON.stringify(t.shape)}`));
const y = model.execute(tf.tensor2d([[/* 32 个 float */]]));
console.log(Array.from(await y.data()));
```

要点：

```text
1. Keras 3 的 .keras（zip）不能直接喂给 tensorflowjs_converter，用 h5py 打开会报 file signature not found
2. 推荐从 SavedModel 转 graph-model：与 TF Serving 复用同一份导出资产，且 signature 里带输入名

```

## TF Serving 线上服务

TF Serving 读 SavedModel 目录做在线推理，容器默认 8500 端口跑 gRPC、8501 端口跑 REST。REST 请求格式是 `{"instances": [...]}`，响应是 `{"predictions": [...]}`；请求 URL 里可以带版本号或标签。以下是官方文档给出的容器命令与请求格式，**本机没有 tensorflow/serving 镜像（未执行 docker pull），这部分命令未在本机验证**。

```bash
# 官方文档写法：挂载 SavedModel 目录，暴露 REST 端口
docker pull tensorflow/serving
docker run -p 8501:8501 \
  --mount type=bind,source=/abs/path/saved_model,target=/models/mlp \
  -e MODEL_NAME=mlp -t tensorflow/serving

# 容器内实际执行的命令（官方文档）
# tensorflow_model_server --port=8500 --rest_api_port=8501 --model_name=mlp --model_base_path=/models/mlp

# 查看模型状态（官方文档）
curl http://localhost:8501/v1/models/mlp
```

对应本机模型的请求（`instances` 是二维数组，一行一个样本，与签名里的 (-1, 32) 对应）：

```bash
curl -d '{"instances": [[0.1, -0.2, ...32 个数...], [0.3, 0.4, ...32 个数...]]}' \
     -X POST http://localhost:8501/v1/models/mlp:predict
# => {"predictions": [[0.000027], [0.997692]]}   # 键名与结构以签名输出名为准
```

REST 端点对照（来源：TensorFlow Serving RESTful API 官方文档）：

| 端点 | 方法 | 说明 |
| --- | --- | --- |
| `/v1/models/${MODEL_NAME}[/versions/${VERSION}]` | GET | 模型状态（state 必须为 AVAILABLE） |
| `/v1/models/${MODEL_NAME}[/versions/${VERSION}]/metadata` | GET | 输入输出签名元数据 |
| `/v1/models/${MODEL_NAME}[/versions/${VERSION}]:predict` | POST | 通用推理，body 是 `{"instances": [...]}` |
| `/v1/models/${MODEL_NAME}[/versions/${VERSION}]:classify` | POST | 分类，body 用 `{"examples": [...]}` |
| `/v1/models/${MODEL_NAME}[/versions/${VERSION}]:regress` | POST | 回归，body 用 `{"examples": [...]}` |

要点：

```text
1. 8501 是 REST、8500 是 gRPC；只公布 REST 端口时容器里的 gRPC 仍在监听，只是主机没映射
2. 版本号与标签都能写进 URL（/versions/1 或 /labels/canary），灰度发布靠这个
3. 请求里的字段顺序无所谓，但形状必须与签名一致：本机签名是 (-1, 32)，写错维度直接 400
4. 上线前用 saved_model_cli show --all 把签名抄进接口文档，别凭记忆写字段名
5. 模型热更新只需把新版本目录放进模型根目录或挂载点，Serving 会自动发现新版本号
6. 生产上还要配模型配置文件（model_config_list）、批量推理与监控；容器只是最小可用形态
```

## 应用场景实战

### 场景一：从训练到多端导出的发布流水线

场景：一次训练产出四种资产——服务端 SavedModel、移动端 int8 TFLite、浏览器 TF.js、可继续训练的 .keras 快照，并逐个做数值回归验证，避免「导出成功但结果不对」。

```python
import os
import subprocess
import numpy as np
import tensorflow as tf
import keras

SEED = 42
keras.utils.set_random_seed(SEED)
BUNDLE = "./release_bundle"
os.makedirs(BUNDLE, exist_ok=True)

rng = np.random.default_rng(SEED)
X = rng.normal(size=(4000, 24)).astype("float32")
y = (X @ rng.normal(size=24) - 0.3 > 0).astype("float32")

model = keras.Sequential([
    keras.Input(shape=(24,), name="features"),
    keras.layers.Dense(128, activation="relu"),
    keras.layers.Dropout(0.2),
    keras.layers.Dense(64, activation="relu"),
    keras.layers.Dense(1, activation="sigmoid", name="score"),
])
model.compile(optimizer=keras.optimizers.Adam(1e-3), loss="binary_crossentropy",
              metrics=[keras.metrics.AUC(name="auc")])
model.fit(X, y, epochs=5, batch_size=128, validation_split=0.2, verbose=0)
reference = model.predict(X[:128], verbose=0)
print("参考输出前 3 个:", np.round(reference.ravel()[:3], 6).tolist())

# 1) 可继续训练的快照
model.save(os.path.join(BUNDLE, "trainable.keras"))

# 2) 服务端：SavedModel
sm_dir = os.path.join(BUNDLE, "saved_model")
model.export(sm_dir, verbose=False)
serving = tf.saved_model.load(sm_dir).signatures["serving_default"]
served = serving(tf.constant(X[:128]))["output_0"].numpy()
print("SavedModel 与 Keras 最大差异:", float(np.max(np.abs(served - reference))))

# 3) 移动端：int8 全整数量化 TFLite
conv = tf.lite.TFLiteConverter.from_saved_model(sm_dir)
conv.optimizations = [tf.lite.Optimize.DEFAULT]
conv.representative_dataset = lambda: ([X[i:i + 1]] for i in range(200))
conv.target_spec.supported_ops = [tf.lite.OpsSet.TFLITE_BUILTINS_INT8]
conv.inference_input_type = tf.int8
conv.inference_output_type = tf.int8
tflite_path = os.path.join(BUNDLE, "mobile_int8.tflite")
open(tflite_path, "wb").write(conv.convert())

interp = tf.lite.Interpreter(model_path=tflite_path)
din = interp.get_input_details()[0]
interp.resize_tensor_input(din["index"], [128, 24])
interp.allocate_tensors()
din = interp.get_input_details()[0]
dout = interp.get_output_details()[0]
scale_in, zero_in = din["quantization"]
quantized = np.clip(np.round(X[:128] / scale_in + zero_in), -128, 127).astype(np.int8)
interp.set_tensor(din["index"], quantized)
interp.invoke()
scale_out, zero_out = dout["quantization"]
mobile = (interp.get_tensor(dout["index"]).astype("float32") - zero_out) * scale_out
print("int8 TFLite 体积:", os.path.getsize(tflite_path), "字节")
print("int8 与 Keras 最大差异:", float(np.max(np.abs(mobile.reshape(reference.shape) - reference))))

# 4) 浏览器：TF.js graph-model（CLI 需在 PATH 上，或显式指定 venv 里的可执行文件）
tfjs_dir = os.path.join(BUNDLE, "tfjs_model")
converter_cli = os.environ.get("TENSORFLOWJS_CONVERTER", "tensorflowjs_converter")
subprocess.run([converter_cli, "--input_format", "tf_saved_model", sm_dir, tfjs_dir], check=True)
print("TF.js 产物:", sorted(os.listdir(tfjs_dir)))

# 5) 发布清单
manifest = {
    "keras_snapshot": os.path.getsize(os.path.join(BUNDLE, "trainable.keras")),
    "saved_model_pb": os.path.getsize(os.path.join(sm_dir, "saved_model.pb")),
    "tflite_int8": os.path.getsize(tflite_path),
    "tfjs_model_json": os.path.getsize(os.path.join(tfjs_dir, "model.json")),
    "seed": SEED,
}
print("发布清单:", manifest)
```

### 场景二：模型导出后的数值回归测试（CI 里跑的守护脚本）

场景：把「导出资产与训练时模型输出一致」做成一道 CI 闸门：加载服务端 SavedModel、移动端 TFLite、浏览器 TF.js 三份资产，对同一批固定输入做推理并断言误差阈值，超限即失败。

```python
"""verify_exports.py：在 CI 里校验三端导出资产与基准输出的差异。

用法：python verify_exports.py ./release_bundle ./golden_input.npy
退出码 0 = 通过，1 = 有资产超限。
"""
import os
import sys
import glob
import numpy as np
import tensorflow as tf
import keras

def tol_for(name):
    """按资产类型给阈值：量化会带来可观误差，阈值单独放宽。"""
    if "int8" in name:
        return 0.05
    if "f16" in name or "float16" in name:
        return 1e-3
    return 1e-5


def load_inputs(path):
    X = np.load(path)
    if X.ndim == 1:
        X = X.reshape(1, -1)
    return X.astype("float32")


def run_saved_model(sm_dir, X):
    fn = tf.saved_model.load(sm_dir).signatures["serving_default"]
    key = list(fn.structured_outputs.keys())[0]
    return fn(tf.constant(X))[key].numpy().reshape(len(X), -1)


def run_tflite(path, X):
    interp = tf.lite.Interpreter(model_path=path)
    din = interp.get_input_details()[0]
    interp.resize_tensor_input(din["index"], list(X.shape))
    interp.allocate_tensors()
    din = interp.get_input_details()[0]
    dout = interp.get_output_details()[0]
    xi = X
    if din["dtype"] == np.int8:
        s, z = din["quantization"]
        xi = np.clip(np.round(X / s + z), -128, 127).astype(np.int8)
    interp.set_tensor(din["index"], xi)
    interp.invoke()
    out = interp.get_tensor(dout["index"]).astype("float32")
    if dout["dtype"] == np.int8:
        s, z = dout["quantization"]
        out = (out - z) * s
    return out.reshape(len(X), -1)


def main(bundle_dir, input_path):
    X = load_inputs(input_path)
    baseline = keras.saving.load_model(os.path.join(bundle_dir, "trainable.keras"))
    ref = baseline.predict(X, verbose=0).reshape(len(X), -1)

    failures = []
    checks = [("saved_model", os.path.join(bundle_dir, "saved_model"), run_saved_model)]
    for tflite_file in glob.glob(os.path.join(bundle_dir, "*.tflite")):
        name = os.path.basename(tflite_file).replace(".tflite", "")
        checks.append((name, tflite_file, run_tflite))

    for name, path, runner in checks:
        got = runner(path, X)
        diff = float(np.max(np.abs(got - ref)))
        tol = tol_for(name)
        ok = diff <= tol
        print(f"[{'PASS' if ok else 'FAIL'}] {name:16s} 最大差异={diff:.6f} 阈值={tol}")
        if not ok:
            failures.append(name)

    # 输出分布也要看：全部趋同（如全 0 或全 1）说明导出坏了
    for name, path, runner in checks:
        got = runner(path, X)
        print(f"       {name:16s} 输出均值={got.mean():.4f} 标准差={got.std():.4f}")
    return 1 if failures else 0


if __name__ == "__main__":
    sys.exit(main(sys.argv[1], sys.argv[2]))
```

## 最佳实践与踩坑记录

### 最佳实践

1. 训练快照用 `.keras`，部署资产用 `model.export()` 出的 SavedModel，不要用 `.h5` 当交付格式。
2. 导出后立即做数值回归（同输入跑 Keras vs 导出资产，`allclose` 或最大差异阈值），并在 CI 里长期保留这道闸门。
3. 量化从「不量化 → 动态范围 → float16 → int8」逐步推进，每一步都比对全量验证集指标，而不是只看单条样本误差。
4. 版本化交付：`saved_model/1/`、`saved_model/2/` 目录结构天生适配 TF Serving 的多版本；文件名里带上训练时间与 Git 提交号。
5. TFLite 交付前确认两类信息：`shape_signature`（是否支持动态 batch）与输入/输出量化参数（scale、zero_point），二者都要写进移动端接入文档。
6. 预处理属于模型契约：归一化参数（均值、方差、除以多少）随模型一起版本化，否则导出资产换到线上就会出现「同一模型不同结果」。
7. TF Serving 上线前用 `saved_model_cli show --all` 抄签名，接口文档直接以签名内容为准。
8. 浏览器端优先从 SavedModel 转 graph-model，与线上服务共用同一份导出资产，减少一次格式转换带来的风险。

### 踩坑记录

```text
坑 1：给转换器设 conv.optimize = tf.lite.Optimize.DEFAULT，模型完全没变小
结论：以为量化功能坏了，反复换版本。
原因：Keras 专用转换器（TFLiteKerasModelConverterV2）上没有 optimize 属性，Python 允许动态加属性，
      于是这行赋值被静默忽略（本机实测四种量化产物字节数完全相同）。
解法：用 conv.optimizations = [tf.lite.Optimize.DEFAULT]（复数、列表）；
      导出后统计 flatbuffer 里的张量类型确认量化生效。

坑 2：int8 模型推理结果完全对不上
结论：以为 int8 量化精度不可用。
原因：全整数量化模型的输入输出也是 int8，直接喂 float32 会越过量化边界。
解法：输入按 (scale, zero_point) 量化、输出反量化（本机输入 scale=0.0281, zero_point=11）；
      或用 inference_input_type=tf.float32 让框架自己做这层转换。

坑 3：TFLite 转换出来的模型只能一次推理一条
结论：以为 TFLite 不支持批量。
原因：from_keras_model 生成的模型 batch 维被固定为 1（本机 shape=[1,32]）。
解法：先 resize_tensor_input(index, [N, features]) 再 allocate_tensors；
      如果要真正动态，看 shape_signature 是否为 -1，或用 signature_runner 按名字调用。

坑 4：Keras 3 的 .keras 文件转 TF.js 直接报 file signature not found
结论：以为转换器版本太旧。
原因：.keras 是 zip，转换器的 --input_format keras 用 h5py 打开，只认 HDF5；
      本机从 .h5 或 SavedModel 转都成功。
解法：先用 model.save("./m.h5") 出 h5，或 model.export() 出 SavedModel 再转（推荐后者）。

坑 5：TFSMLayer 接进模型后 predict 报 'dict' object has no attribute 'ravel'
结论：以为 SavedModel 导出坏了。
原因：TFSMLayer 返回的是 dict（键为签名输出名），不是数组。
解法：取 out["output_0"] 再用 np.asarray(...).ravel()；键名从 loaded.signatures[...].structured_outputs 查。

坑 6：TFLite 转换时看到 tf.lite.Interpreter 弃用警告，当作可以忽略
结论：继续在新项目里用旧解释器，升级时被动。
原因：TF 2.20 已把 tf.lite.Interpreter 标记为弃用并计划移除，官方迁移方向是 LiteRT（ai_edge_litert）。
解法：新项目按官方迁移指引接入 LiteRT 解释器；老项目把解释器创建收敛到一个薄封装里，便于替换。
```

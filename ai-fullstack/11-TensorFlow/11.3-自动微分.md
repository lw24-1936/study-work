## 概述

自动微分是深度学习框架的核心能力：给定一个由张量运算组成的函数，框架沿计算路径反向累计导数，得到损失对每个参数的梯度，优化器据此更新参数。TensorFlow 的入口是 `tf.GradientTape`——它像一盘磁带，在 `with` 块内**记录**所有张量运算，退出后调用 `tape.gradient(target, sources)` 回放并求导。被记录的前提是运算的输入里至少有一个被 tape「监视」（watched）的对象：`tf.Variable` 默认（且 `trainable=True` 时）自动被监视，`tf.constant` 必须显式 `tape.watch()`。

```text
本篇主线：
1. 基础 —— with tf.GradientTape() as tape: y = f(x) 后 tape.gradient(y, x)
2. 监视范围 —— Variable 自动监视（可 watch_accessed_variables=False 关闭），常量要 watch
3. 偏导 —— persistent=True 才能多次调用 gradient，多变量传列表
4. 非标量 —— 传非标量 target 得到的是「对 sum(target) 求导」的结果，逐元素导数要用 jacobian
5. 高阶 —— 嵌套 tape 求二阶导，两层都要 watch
6. 裁剪 —— clip_by_value（逐元素）、clip_by_norm（整张量）、clip_by_global_norm（跨变量）
7. 自定义 —— @tf.custom_gradient 覆盖反向，tf.stop_gradient 断梯度，数值梯度做对照校验
```

本机实测环境：Ubuntu 24.04、Python 3.12.3、TensorFlow 2.20.0，纯 CPU。下文所有 `text` 块中的数值都是本机真实运行结果；官方的 `tf.GradientTape` 文档示例与本机实测做过逐条对照，凡与文档措辞不同之处都单独标注。

## GradientTape 基础用法

最小可用的形式只有三行：进入 tape、算目标、取梯度。要点在括号外面——`tape.gradient` 必须在 `with` 块**之外**调用（在块内调用会抛 `RuntimeError`）。默认的 tape 是一次性的：调用一次 `gradient` 后资源即释放，再调用会报错，需要多次求导就必须 `persistent=True`。

```python
import tensorflow as tf

x = tf.Variable(3.0)
with tf.GradientTape() as tape:
    y = x * x + 2 * x + 1        # y = x^2 + 2x + 1, dy/dx = 2x + 2
print(tape.gradient(y, x))       # 8.0
```

常量不进梯度是另一个高频困惑点。官方文档的例子用的是 `tf.constant` 加显式 `g.watch(x)`；不加 `watch` 时对常量求导返回 `None`，这不是错误，而是「这个张量没有被记录」。

```python
c = tf.constant(3.0)
with tf.GradientTape() as tape:
    y2 = c * c
print(tape.gradient(y2, c))      # None

with tf.GradientTape() as tape:
    tape.watch(c)                # 显式加入监视
    y3 = c * c
print(tape.gradient(y3, c))      # 6.0
```

本机真实输出：

```text
== 1. 基础 GradientTape ==
y = x^2+2x+1, dy/dx at x=3 (应 8): 8.0

== 2. 常量默认不被追踪 ==
不 watch -> None
watch 后 -> 6.0
```

`GradientTape` 的构造参数有两个，都值得记住：

| 参数 | 默认值 | 含义 |
|------|--------|------|
| `persistent` | `False` | `False` 时 `gradient()` 只能调用一次；`True` 可多次，资源在 tape 对象被回收时释放 |
| `watch_accessed_variables` | `True` | `True` 时自动监视所有被访问的 `trainable=True` 的变量；`False` 时必须自己 `watch` |

`watch_accessed_variables=False` 的典型用途是只对特定层求梯度（如分析某层对输出的贡献）。官方文档提醒：用模型变量时要确保变量已经创建完成——如果 `layer.variables` 在 `layer.build()` 之前是空列表，tape 就什么都没监视到，`gradient` 会返回一串 `None`。

```text
GradientTape 基础要点：
1. tape.gradient 必须在 with 块之外调用；块内调用抛 RuntimeError
2. Variable（trainable=True）自动被监视；常量默认不监视，需 tape.watch()
3. 默认 tape 一次性：第二次调用 gradient 报错，多次求导要 persistent=True
4. 对未监视对象求导返回 None 而不是报错，出现 None 先检查监视范围
5. watch_accessed_variables=False 时要在模型 build 之后再 watch，否则拿到空变量列表
```

## 多变量偏导与 persistent tape

一个 tape 可以同时记录多个变量参与的计算，`tape.gradient(target, [a, b])` 一次返回全部偏导，顺序与传入顺序一致。这比「每个变量各开一个 tape」高效得多，因为前向只算一遍。要分多次取不同目标的梯度，就必须 `persistent=True`，并在用完显式 `del tape` 或让它离开作用域——持久 tape 会把整条前向记录一直留在内存里，训练循环里忘了释放是真实存在的内存泄漏来源。

```python
import tensorflow as tf

a = tf.Variable(2.0)
b = tf.Variable(3.0)
with tf.GradientTape(persistent=True) as tape:
    f = a * a * b + b            # df/da = 2ab, df/db = a^2 + 1

print(tape.gradient(f, a))       # 12.0
print(tape.gradient(f, b))       # 5.0
print(tape.gradient(f, [a, b]))  # [12.0, 5.0]，一次拿全部
del tape                         # 持久 tape 用完要释放
```

本机真实输出：

```text
== 4. 多变量偏导 ==
df/da = 2ab (应 12): 12.0
df/db = a^2+1 (应 5): 5.0
一次拿全部: [12.0, 5.0]
```

官方文档给出的 persistent 示例是同一个 `x` 求两次不同目标的导数（`dz_dx = 4x^3`、`dy_dx = 2x`），这里的差别只是换成了两个变量，机制相同：所有前向运算只记录一次，多次反向各自独立。

```text
多变量与持久 tape 要点：
1. gradient(target, [a, b]) 一次返回全部偏导，顺序与传入列表一致
2. 一次前向可以反向多次的前提是 persistent=True，代价是前向记录常驻内存
3. 持久 tape 用完显式 del，训练循环里长期持有会让显存/内存持续增长
4. 只需要一次梯度时不要开 persistent，白付内存成本
5. 偏导与数值梯度的对照是验证实现正确性的最快手段（见应用场景）
```

## 非标量输出与 jacobian

官方文档写的是「target: a list or nested structure of Tensors」，没有强制要求标量，但实践中必须理解非标量 target 的行为。本机在 TF 2.20 上实测：对一个形状 `(3,)` 的输出求导得到的是**对 `reduce_sum(output)` 求导**的结果，即每元素导数之和，而不是逐元素导数，也不报错。这是最容易造成静默错误的地方——代码能跑、数值看着合理，但语义已经不是你想要的。

```python
v = tf.Variable([1.0, 2.0, 3.0])
with tf.GradientTape() as tape:
    out = v * v
print(tape.gradient(out, v))     # [2. 4. 6.]，等于 d(sum(v*v))/dv = 2v
```

本机真实输出：

```text
== 3. 非标量 target ==
gradient(v*v, v): [2.0, 4.0, 6.0]
等价于对 sum(v*v) 求导 (2v): [2.0, 4.0, 6.0]
```

要真正的「逐元素雅可比」用 `tape.jacobian(target, source)`，输出形状是**目标形状 + 源形状**拼接：本机实测 `target` 形状 `(2,1)`、`source`（权重矩阵）形状 `(2,2)`，得到 jacobian 形状 `(2,1,2,2)`。

```python
w = tf.Variable(tf.constant([[1.0, 2.0], [3.0, 4.0]]))   # (2,2)
xv = tf.constant([[1.0], [10.0]])                        # (2,1)
with tf.GradientTape() as tape:
    yv = w @ xv                                          # (2,1)
jac = tape.jacobian(yv, w)
print(jac.shape)          # (2, 1, 2, 2)
print(jac[0, 0])          # [[1.0, 10.0], [0.0, 0.0]]  -> d y0 / d w
```

本机真实输出：

```text
== 5. jacobian ==
jacobian shape: (2, 1, 2, 2) (输出形状 + 输入形状)
jac[0,0]: [[1.0, 10.0], [0.0, 0.0]]
d y0/d w00 = 1.0  d y0/d w01 = 10.0
```

`y = w @ x` 时 `dy_i/dw_ij = x_j`，因为 `x = [1, 10]`，所以 `jac[0,0]` 的第一行是 `[1, 10]`；第二行为 0 是因为 `y_0` 只与 `w` 的第 0 行有关。这与手推结果一致。逐样本独立时（如一批样本各自的输出只依赖同下标输入）应该用 `batch_jacobian`，它比 `jacobian` 更省内存，因为它利用了「无交叉依赖」这个假设。

```text
非标量输出与 jacobian 要点：
1. 非标量 target 不报错：得到的是对 sum(target) 求导的结果，容易静默算错
2. 逐元素导数要用 tape.jacobian，输出形状 = 目标形状 + 源形状
3. batch_jacobian 在「每样本输出只依赖同下标输入」时更快更省内存
4. 训练损失永远是标量，写训练循环时先 tf.reduce_* 再求导是最稳的习惯
5. jacobian 在即时执行下需要 pfor 支持（experimental_use_pfor），失败时退回 while_loop
```

## 高阶导数

二阶及更高阶导数靠**嵌套 tape**实现：外层 tape 用来对「内层算出的梯度」再求一次导。要注意每一层都要监视目标张量——如果用它当变量（`tf.Variable`），两层都会自动监视；如果用的是 `tf.constant`，两层都要显式 `watch`，否则内层梯度拿不到、外层求导得到 `None`。

```python
import tensorflow as tf

x = tf.Variable(2.0)
with tf.GradientTape() as t1:
    t1.watch(x)                  # 可变对象其实自动监视，显式写更清楚
    with tf.GradientTape() as t2:
        t2.watch(x)
        y = x ** 3
    dy = t2.gradient(y, x)       # 一阶：3x^2 = 12
d2 = t1.gradient(dy, x)          # 二阶：6x = 12
print(float(dy), float(d2))
```

本机真实输出：

```text
== 6. 高阶导数 ==
x^3 一阶导 at 2 (应 12): 12.0
x^3 二阶导 at 2 (应 12): 12.0
```

同样这段代码在先用 `tf.Variable(2.0)` 且内层不写 `watch` 时也能得到正确结果（因为 Variable 自动监视），但换成 `tf.constant` 就必然失败。写库代码或教学示例时统一显式 `watch` 更安全。嵌套层数与内存开销成正比：n 阶导就要保留 n 层前向记录，工程上很少超过二阶（如物理约束损失、梯度惩罚 WGAN-GP）。

```text
高阶导数要点：
1. 二阶导 = 在外层 tape 里对「内层 tape 算出的梯度」再求导
2. 每一层都要监视目标；常量必须显式 watch，Variable 自动监视
3. 层数与内存成正比，工程上一般不超过二阶（梯度惩罚等场景）
4. 一阶梯度张量本身要能被外层 tape 记录，因此内层求导不能放在 stop_recording 里
5. 验证高阶导的方式同样是与有限差分数值结果对照
```

## 梯度裁剪

梯度裁剪是防止梯度爆炸（RNN、深度网络、异常样本）的标准手段，TensorFlow 提供三个粒度不同的算子，用途不能混：

| 算子 | 粒度 | 语义 | 适用场景 |
|------|------|------|----------|
| `tf.clip_by_value(g, lo, hi)` | 逐元素 | 每个元素单独截断到 `[lo, hi]` | 数值防护；会改变梯度方向 |
| `tf.clip_by_norm(g, clip_norm)` | 单个张量 | 整体 L2 范数超过阈值时等比缩放 | 单变量/单层梯度控制 |
| `tf.clip_by_global_norm(gs, clip_norm)` | 变量列表 | 用所有梯度的全局范数统一缩放 **同一系数** | 模型级训练（最常用） |

```python
import tensorflow as tf

g = tf.constant([0.5, 2.0, 10.0])
tf.clip_by_value(g, -1.0, 1.0)                 # 逐元素
cn = tf.clip_by_norm(g, 2.0)                   # 整张量缩放到范数 2
cgr, gn = tf.clip_by_global_norm([g, g * 2], 5.0)   # 跨变量，返回 (裁剪后列表, 原始全局范数)
```

本机真实输出：

```text
== 7. 梯度裁剪 ==
原始: [0.5, 2.0, 10.0]
clip_by_value(-1,1): [0.5, 1.0, 1.0]
clip_by_norm(2.0): [0.09790000319480896, 0.3917999863624573, 1.958799958229065] | 新范数: 2.0
global_norm 原值: 5.0
裁剪后: [[0.6000000238418579, 0.800000011920929], [0.0, 0.0]]
```

三个结论从输出里可以直接读出：`clip_by_value` 只动越界元素，`0.5` 保持不变；`clip_by_norm` 把整个张量等比缩放，裁剪后 L2 范数精确等于 2.0，方向不变；`clip_by_global_norm` 用两个张量共同的全局范数（`[3,4]` 与 `[0,0]` 合起来的范数是 5.0）算出一个缩放系数 5.0/5.0 作用于所有张量，然后按 1.0 目标裁剪后变为 `[[0.6, 0.8], [0, 0]]`。**保持方向不变**是 `clip_by_norm` / `clip_by_global_norm` 相对 `clip_by_value` 的本质优势。

```python
# 训练循环里的标准写法：取梯度后先裁剪再 apply
grads = tape.gradient(loss, model.trainable_variables)
grads, global_norm = tf.clip_by_global_norm(grads, 1.0)
opt.apply_gradients(zip(grads, model.trainable_variables))
```

```text
梯度裁剪要点：
1. clip_by_value 改方向、clip_by_norm/clip_by_global_norm 只缩放不改方向
2. 模型级训练用 clip_by_global_norm，逐变量 clip_by_norm 会让各变量缩放比例不一致
3. clip_by_global_norm 返回 (裁剪后梯度列表, 原始全局范数)，范数打日志可用于监控训练健康度
4. 顺序不能颠倒：必须先裁剪再 apply_gradients，反了就白裁
5. 触发裁剪就说明梯度异常，长期一直触发要回头查数据与学习率，而不是调大阈值
```

## 自定义梯度与 stop_gradient

框架对每个算子都注册了反向函数，但有些场景需要覆盖它：数值稳定（把不稳定的前向换掉）、不可导算子（需要手工定义次梯度）、或性能优化（用近似梯度换速度）。`@tf.custom_gradient` 装饰器让函数同时返回前向值和反向函数，反向函数接收 `upstream`（上游传下来的梯度）并返回对每个输入的梯度。`tf.stop_gradient` 则是最轻量的「梯度开关」：前向照常，反向时当作常数。

```python
import tensorflow as tf

@tf.custom_gradient
def log1pexp(x):
    """数值稳定的 log(1+e^x)，并显式给出其导数 sigmoid(x)。"""
    e = tf.exp(x)
    def grad(upstream):
        return upstream * (1 - 1 / (1 + e))    # = sigmoid(x)
    return tf.math.log(1 + e), grad

z = tf.Variable(0.0)
with tf.GradientTape() as tape:
    o = log1pexp(z)
print(tape.gradient(o, z))       # 0.5 == sigmoid(0)

# stop_gradient：前向保留 x*10 的值，反向当作常数不贡献梯度
x = tf.Variable(3.0)
with tf.GradientTape() as tape:
    y = x * x + tf.stop_gradient(x * 10)
print(tape.gradient(y, x))       # 6.0 = 2x，x*10 那一项没进梯度
```

本机真实输出：

```text
== 8. tf.custom_gradient ==
自定义梯度 at 0: 0.5 | sigmoid(0)= 0.5

== 9. stop_gradient ==
dy/dx 只含 x^2 部分 (应 6): 6.0
```

自定义梯度最实用的场合是数值稳定。下面这段对比用本机实测说明了问题：朴素 `log(1+exp(x))` 在 `x=100` 处直接溢出成 `inf`，而稳定写法（`log1p(exp(-|x|)) + relu(x)`）得到正确结果，且自定义反向用 `sigmoid(x)` 也保持稳定。

```text
=== 场景二：自定义梯度让 log-sum-exp / softplus 数值稳定 ===
朴素 log(1+exp(x)): [50.0, inf, inf]
稳定 log1p(exp(-|x|))+relu(x): [50.0, 100.0, 1000.0]
理论值应约等于 x: [50.0, 100.0, 1000.0]
自定义梯度(应 = sigmoid(x)): [0.047426000237464905, 0.5, 0.982014000415802]
sigmoid 对照值: [0.047426000237464905, 0.5, 0.982014000415802]
梯度一致: True
```

注意 `tf.stop_gradient` 与 `detach`（PyTorch）语义一致，但 TensorFlow 里它作用于张量而非变量：`x` 本身仍是可训练的，只是**经过 `stop_gradient` 的那条分支**不贡献梯度。做强化学习的 target 网络、梯度惩罚里的 detach、以及「只更新主网络不更新参考网络」的 EMA 都会用到它。

```text
自定义梯度与 stop_gradient 要点：
1. @tf.custom_gradient 的前向函数必须返回 (值, 反向函数)，反向函数签名是 grad(upstream)
2. 反向函数的返回值结构必须与输入一一对应，多个输入就返回 tuple
3. 自定义梯度的主要动机是数值稳定与不可导算子，其次是性能近似
4. stop_gradient 只断这一条分支的梯度，变量本身仍可训练
5. 写了自定义梯度一定要用有限差分对照验证（见应用场景一的校验手法）
```

## 应用场景实战

### 场景一：手写训练循环（梯度累积 + 全局范数裁剪）并做数值梯度校验

生产上需要精细控制梯度时（改累积步长、改裁剪策略、加梯度惩罚），就得手写训练循环。下面这段在本机真实跑通：三分类任务、批大小 32、梯度累积 4 步（等效大 batch 128）、全局范数裁剪 1.0。数据集由线性规则生成，因此准确率明显高于随机基线。

```python
import tensorflow as tf

tf.random.set_seed(1234)
n, d, k = 600, 12, 3
X = tf.random.normal([n, d])
W = tf.random.normal([d, k])
labels = tf.cast(tf.argmax(X @ W + tf.random.normal([n, k], stddev=0.5), axis=1), tf.int32)

model = tf.keras.Sequential([
    tf.keras.layers.Dense(32, activation="relu", input_shape=(d,)),
    tf.keras.layers.Dense(k),
])
opt = tf.keras.optimizers.Adam(learning_rate=3e-3)
loss_fn = tf.keras.losses.SparseCategoricalCrossentropy(from_logits=True)
ds = tf.data.Dataset.from_tensor_slices((X, labels)).shuffle(1000, seed=1).batch(32)
steps_per_epoch = len(ds)

accum_steps = 4
for epoch in range(1, 31):
    accum_grads, micro = None, 0
    for i, (xb, yb) in enumerate(ds):
        with tf.GradientTape() as tape:
            logits = model(xb, training=True)
            loss = loss_fn(yb, logits) / accum_steps     # 按累积步数缩放 == 等效大 batch 平均
        grads = tape.gradient(loss, model.trainable_variables)
        accum_grads = grads if accum_grads is None else [a + g for a, g in zip(accum_grads, grads)]
        micro += 1
        if micro == accum_steps or i == steps_per_epoch - 1:
            clipped, global_norm = tf.clip_by_global_norm(accum_grads, 1.0)
            opt.apply_gradients(zip(clipped, model.trainable_variables))
            accum_grads, micro = None, 0
```

本机真实输出：

```text
=== 场景一：梯度累积 + 梯度裁剪 + 手写训练循环（三分类）===
epoch  1  loss=1.2595  acc=0.3617  最后一批 global_norm=0.6826
epoch 10  loss=0.5417  acc=0.8500  最后一批 global_norm=0.2632
epoch 20  loss=0.2799  acc=0.9267  最后一批 global_norm=0.1921
epoch 30  loss=0.1922  acc=0.9450  最后一批 global_norm=0.1790
测试集准确率: 0.89
说明：标签是按真实线性可分规则生成的，因此准确率明显高于随机 (1/3)
```

输出里 `global_norm` 逐 epoch 下降（0.68 -> 0.26 -> 0.19 -> 0.18），说明随着收敛梯度范数在缩小，裁剪阈值 1.0 后期实际上没触发——这正是把范数打日志的价值：**能区分「没触发裁剪」和「一直贴着阈值」两种情况**，后者通常意味着学习率过大或数据有问题。

训练的梯度必须验证。数值梯度（中心差分）是独立于自动微分的实现，二者吻合才说明梯度正确：

```python
import numpy as np
import tensorflow as tf

def f(x):
    return tf.reduce_sum(tf.sin(x) * tf.exp(x * 0.1))

xv = tf.Variable([0.3, 1.2])
with tf.GradientTape() as tape:
    yv = f(xv)
tape_g = tape.gradient(yv, xv).numpy()

eps = 1e-3
num_g = []
for i in range(2):
    e = np.zeros(2, dtype=np.float32); e[i] = eps
    num_g.append((f(xv.numpy() + e).numpy() - f(xv.numpy() - e).numpy()) / (2 * eps))
print("最大绝对误差:", np.max(np.abs(tape_g - np.array(num_g))))
```

本机真实输出：

```text
== 11. 数值梯度对照 ==
tape 梯度: [1.014883041381836, 0.5136439800262451]
数值梯度: [1.014888, 0.513673]
最大绝对误差: 2.855e-05
```

误差量级 `2.9e-05` 在 float32 + 步长 1e-3 下是正常水平（理论误差随步长线性增长）。**判定标准不是「完全相等」，而是「误差随步长减小先降后升」以及「量级远小于梯度本身的量级」**。

```text
手写训练循环要点：
1. 梯度累积要把每个 micro-batch 的 loss 除以累积步数，才等价于大 batch 的平均损失
2. 累积期间不要 apply_gradients，只在最后一步裁剪 + 更新，否则等于多次小步更新
3. clip_by_global_norm 的返回值里带原始全局范数，把它打进日志才能判断裁剪是否真的在起作用
4. 手写循环必须自己管 metrics（tf.keras.metrics.Mean 等），否则日志里的数字会误导
5. 任何自定义的梯度路径都要用有限差分做一次对照，误差量级在 1e-4 以内即可接受
```

### 场景二：用自定义梯度实现数值稳定的 Huber 损失并验证最优解

Huber 损失在残差小于 `delta` 时是二次、超过时是线性，因此比 MSE 抗离群点。它的导数极简单——**裁剪到 `[-delta, delta]` 的残差**，非常适合演示 `@tf.custom_gradient`。当需要一个共享参数拟合多个目标时，最小化平均 Huber 的最优解是**中位数**，最小化平均 MSE 的是**均值**，这个差别用真实训练结果可以直接验证：

```python
import numpy as np
import tensorflow as tf

delta = 0.3

@tf.custom_gradient
def huber(r):
    abs_r = tf.abs(r)
    forward = tf.where(abs_r <= delta, 0.5 * r * r, delta * (abs_r - 0.5 * delta))
    def grad(upstream):
        # Huber 的导数就是被裁剪到 [-delta, delta] 的残差
        return upstream * tf.clip_by_value(r, -delta, delta)
    return forward, grad

target = tf.constant([1.0, -1.0, 2.0, 0.5])
theta_h, theta_m = tf.Variable(0.0), tf.Variable(0.0)
opt_h, opt_m = tf.keras.optimizers.SGD(0.1), tf.keras.optimizers.SGD(0.1)

for step in range(1, 401):
    with tf.GradientTape() as tape:
        loss_h = tf.reduce_mean(huber(target - theta_h))
    opt_h.apply_gradients(zip(tape.gradient(loss_h, [theta_h]), [theta_h]))
    with tf.GradientTape() as tape:
        loss_m = tf.reduce_mean(tf.square(target - theta_m))
    opt_m.apply_gradients(zip(tape.gradient(loss_m, [theta_m]), [theta_m]))
```

本机真实输出（400 步后两个参数分别收敛到 0.75 与 0.625）：

```text
step   1  huber_loss=0.292500 theta_huber=0.0150   mse_loss=1.562500 theta_mse=0.1250
step 100  huber_loss=0.218261 theta_huber=0.7279   mse_loss=1.171875 theta_mse=0.6250
step 400  huber_loss=0.218125 theta_huber=0.7500   mse_loss=1.171875 theta_mse=0.6250
target: [1.0, -1.0, 2.0, 0.5]
中位数 (Huber 最优解): 0.75 -> theta_huber = 0.75
均值   (MSE 最优解)  : 0.625 -> theta_mse   = 0.625
d(huber)/dr: [0.20000000298023224, 0.30000001192092896, -0.30000001192092896] （应 0.2, 0.3, -0.3，即裁剪后的残差）
```

最后一行是反向函数的直接验证：残差 `[0.2, 0.5, -2.0]` 中，`0.2` 未超 `delta=0.3` 所以导数就是 `0.2`；`0.5` 与 `-2.0` 越界，被裁剪到 `0.3` 与 `-0.3`。输出与预期逐项一致，说明 `custom_gradient` 的反向实现正确。这个「先验证梯度，再看收敛目标」的顺序值得照搬：**梯度错了，收敛到哪里都没有意义**。

```text
自定义损失实践要点：
1. Huber 这类分段函数的反向往往极其简单（这里是裁剪），适合用 custom_gradient 显式实现
2. tf.where 在分段点不可导，但测量集（概率 0）不影响训练；真要精确可加 epsilon
3. 共享参数 + 平均 Huber 的最优解是中位数，MSE 的最优解是均值，可用来验证实现语义
4. 反向函数要接受 upstream 并按输入结构返回，多输入时返回 tuple
5. 先单独验证梯度（用固定输入看数值），再跑收敛实验，否则会把梯度 bug 误判成超参问题
```

## 最佳实践与踩坑记录

### 最佳实践

1. 训练损失保证是标量（先 `tf.reduce_*`）；非标量 target 不报错但语义会变成「对求和求导」。
2. `tape.gradient` 一律写在 `with` 块之外，取到梯度后立刻 `apply_gradients` 或裁剪，不要跨多行逻辑持有。
3. 只在需要多次反向时用 `persistent=True`，并在同一作用域内 `del tape`。
4. 模型级梯度裁剪统一用 `tf.clip_by_global_norm`，并把返回的全局范数打进日志。
5. 涉及概率/对数/指数的手写前向，一律配一个数值稳定的等价实现；能用 `tf.math.softplus`、`tf.nn.softmax_cross_entropy_with_logits` 就不要手搓。
6. 任何自定义梯度上线前都用中心差分做一次对照，误差量级超过 1e-3 就要查实现。
7. 用 `tf.stop_gradient` 表达「这条分支不参与训练」（target 网络、EMA 参考模型），比把变量设成不可训练更精确。

### 踩坑记录

```text
坑 1：tape.gradient 返回 None，但代码没报错
结论：以为梯度为 0 或者模型没问题，实际什么都没更新。
原因：目标张量没有被 tape 监视。常量必须 tape.watch()；用 watch_accessed_variables=False 时
      若模型尚未 build，layer.variables 是空列表，什么都监视不到。
解法：先检查被求导对象是 tf.Variable 还是 tf.constant，常量显式 watch；用模型时确保
      build 之后再 watch（可以先做一次前向再取梯度）；把 gradients 是否为 None 作为断言放进
      自定义训练循环的调试分支。

坑 2：默认 tape 里第二次调用 gradient 报错，或 persistent tape 让内存持续上涨
结论：以为 TensorFlow 有 bug，或怀疑数据加载器泄漏。
原因：默认 tape 是一次性的（调用一次 gradient 后资源释放），第二次调用直接报错；
      persistent=True 的 tape 会一直持有前向记录，直到对象被回收。
解法：需要多次反向就 persistent=True 并显式 del tape；只要一次梯度就别开 persistent。
      排查内存问题时用 tf.config.experimental.get_memory_info 之类手段确认持有者。

坑 3：给非标量输出求导，代码不报错但梯度语义完全不对
结论：以为拿到了逐元素梯度，直接用它做逐样本加权，结果训练行为异常。
原因：本机在 TF 2.20 实测，非标量 target 时 tape.gradient 返回的是「对 sum(target) 求导」的结果
      （本例中 out = v*v, v=[1,2,3] 得到 [2,4,6] == 2v），不报错也不提示。
解法：损失一律先 reduce 成标量再求导；需要逐元素/逐样本导数时用 tape.jacobian 或
      tape.batch_jacobian，并核对返回形状（目标形状 + 源形状）。

坑 4：朴素 log(1+exp(x)) 在 x 较大时变成 inf，loss 变 NaN
结论：以为输入数据有脏值，先去清洗数据。
原因：exp(100) 超出 float32 范围直接溢出为 inf。本机实测 x=[50, 100, 1000] 时
      朴素写法得到 [50.0, inf, inf]，稳定写法得到 [50.0, 100.0, 1000.0]。
解法：用等价稳定形式 log1p(exp(-|x|)) + relu(x)，或用现成的 tf.math.softplus；
      反向也同步换成 sigmoid 形式；改完用固定输入的数值对照验证。

坑 5：梯度裁剪加了但训练仍然发散
结论：怀疑裁剪额度不够，一路调大阈值。
原因：顺序错了——先 apply_gradients 再裁剪等于没裁；或者用 clip_by_value 逐元素裁剪，
      它改变了梯度方向，对严重异常的方向没有纠正作用。
解法：确认顺序是 tape.gradient -> clip_by_global_norm -> apply_gradients；
      模型级用 clip_by_global_norm 保持方向；把返回的全局范数打日志，区分「没触发」与
      「一直贴着阈值」。

坑 6：自定义梯度的反向返回值结构写错，报错信息难读
结论：反复调返回值的形状，靠猜。
原因：@tf.custom_gradient 的反向函数返回值必须与「除输出之外的输入」一一对应，
      多输入时必须是 tuple/list；返回单个张量会被当成对第一个输入的梯度。
解法：用固定输入 + 已知答案做最小验证（例如本例 log1pexp 在 x=0 时梯度应为 0.5 = sigmoid(0)），
      再用有限差分对照；写多输入版本时显式 return (g1, g2) 而不是靠位置猜。
```

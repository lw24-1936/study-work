## 概述

Skill 本身不注册工具、不申请权限，它靠**指令**把 Agent 已有的工具（读文件、写文件、执行命令）和 MCP 工具串成流程；`scripts/` 里的脚本则是把确定性逻辑从「模型现场写代码」变成「执行既有代码」，既省上下文又稳定。这一篇讲清四件事：指令里怎么写外部命令调用、脚本的 CLI 契约怎么定、运行环境与依赖怎么声明、失败与重复执行怎么处理。判断标准很朴素——**换一台机器、换一个模型、重跑一次，行为都应该一致**。

```text
全篇主线：
1. 协作 —— Skill 只写「用哪个工具、按什么顺序」，工具能力来自工具集与 MCP
2. 命令 —— 明确「执行脚本」还是「参考脚本」，相对路径 + 结构化输出 + 超时
3. 契约 —— CLI 参数、退出码、dry-run 先行，参数显式、敏感值走环境变量
4. 依赖 —— compatibility 声明 + PEP 723 内联元数据，装不上要能提前失败
5. 幂等 —— 值相同就跳过、单事务、审计键唯一，重跑第二次必须 changed=0
```

## Skill 与工具的协作模型

一次 Skill 触发的完整链路是：会话启动时加载所有 Skill 的 `name` + `description` -> 模型判断相关并把 `SKILL.md` 读进上下文 -> 按正文指令调用工具（内置工具或 MCP 工具）或执行 `scripts/` 里的脚本 -> 用返回结果继续下一步。因此**Skill 的职责是「编排」，不是「提供能力」**：需要读文件就用读文件的工具，需要动外部系统就用 MCP 工具，需要跑逻辑就跑脚本。写指令时有三个必须遵守的点：MCP 工具用全限定名（`ServerName:tool_name`，否则容易报 tool not found）、不假设某个命令或包已安装（先探测，见「环境依赖声明」）、能脚本化的判定不要写成「请模型自己算」。

| 能力来源 | 在 Skill 里怎么写 | 注意 |
|----------|-------------------|------|
| 内置工具（读/写/搜索/执行命令） | 直接说动作：「读 `plan.json` 并核对字段」 | 不要描述工具怎么实现 |
| MCP 工具 | 全限定名 + 用途，如 `BigQuery:bigquery_schema` | 不加 server 前缀会找不到工具 |
| 脚本 | 「运行 `scripts/x.py --plan plan.json`」 | 代码不进上下文，只回输出 |
| 预授权 | `allowed-tools`（实验性、Claude Code 等实现支持） | 换实现可能被忽略或报错 |
| 外部服务凭据 | 声明用环境变量注入，不写进 Skill | Skill 会被分发，别把密钥写在里面 |

```markdown
## 校验与入库

1. 运行 `python3 scripts/validate_plan.py --plan plan.json`，退出码非 0 时停下，把 errors 原样列给用户。
2. 运行 `python3 scripts/apply_plan.py --plan plan.json --db orders.db --seed data/orders.csv`。
3. 需要核对线上表结构时调用 `Orders:describe_table`（MCP 工具，必须带 server 前缀）。
4. 把 `change_log` 里的 plan_id 记录进发布说明。

环境变量 `ORDER_DB_DSN` 由运行环境注入，本 Skill 不读取、不存储任何凭据。
```

```text
协作模型要点：
1. Skill 只编排：工具能力来自工具集与 MCP，Skill 不新增能力
2. MCP 工具一律写全限定名 `ServerName:tool_name`
3. 指令里写「用哪个工具做什么」，不写「请自己想办法」
4. 能机械判定的一律脚本化，别让模型自己数数、自己比字符串
5. 凭据只声明来源（环境变量），任何情况下不写进 Skill 文件
```

## 调用外部命令

指令里出现命令时，第一个要交代清楚的是**语义**：是「执行这个脚本拿结论」，还是「参考这个脚本的算法」——前者代码不进上下文、只回输出，后者会把代码整段读进来。其次是**路径**：一律相对 skill 根目录、正斜杠，别写绝对路径（换机器就废）。第三是**输出形态**：命令的输出越小越结构化越好，需要长篇输出时先过滤（`jq`、`rg --max-count`、`head`）再给模型看，因为命令输出会直接进上下文。

```shell
# 结构化取数：jq 只留需要的字段（本机实测输出见下）
jq -r '.entries[] | "\(.order_id) \(.field): \(.from) -> \(.to)"' plan.json

# 搜索也先裁剪：限制条数，避免把整个仓库刷进上下文
rg --max-count 5 -n "INSERT OR IGNORE" scripts/

# 外部服务调用必须有超时，且只取需要的字段
curl -sS -m 10 "https://api.example.com/orders/A1001" | jq -c '{id, status}'

# 交互式命令一律不要放进 Skill：Agent 没有 TTY，会挂到超时
# 需要交互时改成非交互参数，例如 git commit -m、apt-get -y
```

```text
A1001 priority: 3 -> 4
A1002 status: pending -> shipped
A1002 priority: 2 -> 2
```

命令不可用时要有明确的失败路径，而不是让 Agent 猜「为什么找不到 jq」。前置探测一段 Shell 就能覆盖：

```shell
#!/usr/bin/env bash
# Skill 运行前的环境探测：列出所需命令是否可用（对应 frontmatter 的 compatibility 声明）
set -u
missing=0
for cmd in python3 uv jq rg git curl zip; do
  if command -v "$cmd" >/dev/null 2>&1; then
    printf '%-8s ✓ %s\n' "$cmd" "$(command -v "$cmd")"
  else
    printf '%-8s ✗ 未安装\n' "$cmd"
    missing=$((missing + 1))
  fi
done
echo "缺失 $missing 个必需命令"
[ "$missing" -eq 0 ]
```

```text

uv       ✓ /root/.hermes/bin/uv
jq       ✓ /usr/bin/jq
rg       ✓ /root/.hermes/tools/ripgrep-15.2.0-linux-x64/rg
git      ✓ /usr/bin/git
curl     ✓ /usr/bin/curl
zip      ✓ /usr/bin/zip
缺失 0 个必需命令
```

```text
外部命令要点：
1. 明确「执行」还是「参考」：执行省 token，参考只在需要理解算法时使用
2. 路径相对 skill 根目录、正斜杠；跨平台问题一半出在路径写法上
3. 输出先裁剪再给模型看（jq 选字段、rg --max-count、head），命令输出也占上下文
4. 外部服务调用带超时（curl -m、命令 timeout），避免任务卡死
5. 禁止交互式命令；需要确认时改成参数或 dry-run 两步走
```

## 脚本参数化

脚本是 Skill 与外部世界之间的接口，接口要像库一样稳定：**参数显式、命名一致、默认值安全、退出码有含义**。一套够用的约定是 `--input/--output` 表达数据流向、`--dry-run` 先看后做、`--json` 输出机器可读结果、`--force` 覆盖保护性检查；退出码统一成 `0` 成功、`2` 输入/校验错误、`3` 环境或依赖缺失、`1` 其他未知错误。参数传递上有个容易忽略的原则：**必需的路径类参数一定要显式给**（不要依赖当前工作目录），敏感值走环境变量而不是命令行（命令行会进日志）。

```python
#!/usr/bin/env python3
"""读取数据文件与变更单，生成变更计划 plan.json（不修改任何数据）。

用法：python3 build_plan.py --data data/orders.csv --changes data/changes.csv --out plan.json
"""
from __future__ import annotations

import argparse
import csv
import hashlib
import json
from pathlib import Path


def read_rows(path: Path) -> list[dict[str, str]]:
    with path.open(encoding="utf-8", newline="") as fh:
        return [row for row in csv.DictReader(fh)]


def build(data_path: Path, changes_path: Path) -> dict:
    current = {r["order_id"]: {"status": r["status"], "priority": int(r["priority"])} for r in read_rows(data_path)}
    entries: list[dict] = []
    for row in read_rows(changes_path):
        order_id = (row.get("order_id") or "").strip()
        status = (row.get("new_status") or "").strip()
        priority = (row.get("new_priority") or "").strip()
        base = current.get(order_id)
        if status:
            entries.append({
                "order_id": order_id,
                "field": "status",
                "from": base["status"] if base else None,
                "to": status,
            })
        if priority:
            entries.append({
                "order_id": order_id,
                "field": "priority",
                "from": base["priority"] if base else None,
                "to": int(priority),
            })
    plan = {
        "version": 1,
        "source": {"data_rows": len(current), "change_rows": len(entries)},
        "entries": entries,
    }
    canonical = json.dumps(entries, ensure_ascii=False, sort_keys=True).encode()
    plan["plan_id"] = hashlib.sha256(canonical).hexdigest()[:12]
    return plan


def main() -> int:
    parser = argparse.ArgumentParser(description="生成变更计划")
    parser.add_argument("--data", required=True, type=Path)
    parser.add_argument("--changes", required=True, type=Path)
    parser.add_argument("--out", required=True, type=Path)
    args = parser.parse_args()
    plan = build(args.data, args.changes)
    args.out.write_text(json.dumps(plan, ensure_ascii=False, indent=2) + "\n", encoding="utf-8")
    print(json.dumps({"plan_id": plan["plan_id"], "entries": len(plan["entries"]), "out": str(args.out)},
                     ensure_ascii=False))
    return 0


if __name__ == "__main__":
    raise SystemExit(main())
```

`argparse` 会自动生成 `--help`，这就是脚本的接口文档，Agent 与人都能直接看（本机实测输出）：

```shell
python3 scripts/build_plan.py --help
```

```text
usage: build_plan.py [-h] --data DATA --changes CHANGES --out OUT

生成变更计划

options:
  -h, --help            show this help message and exit
  --data DATA
  --changes CHANGES
  --out OUT
```

| 参数/约定 | 用途 | 约定细节 |
|-----------|------|----------|
| `--input` / `--data` | 输入路径 | 必填，显式给出，不依赖 cwd |
| `--output` / `--out` | 产物路径 | 必填或给安全默认（写临时目录而非 skill 目录） |
| `--dry-run` | 只打印将要发生的变更 | 默认关闭；先 dry-run 再实操 |
| `--json` | 机器可读输出 | 默认给人类可读摘要，便于日志与管道复用 |
| `--force` | 跳过保护性检查 | 默认关闭，且在正文里写清什么时候允许用 |
| 退出码 | 机器判断结果 | 0 成功；2 输入/校验错误；3 依赖/环境缺失；1 其他 |
| 环境变量 | 凭据与运行环境 | 如 `ORDER_DB_DSN`，不写进命令行与 Skill 文件 |
| `--help` | 自描述接口 | 每个参数都要有一句话说明，禁止无说明参数 |

```text
脚本参数化要点：
1. 参数显式化：输入输出路径必填，绝不用「默认写当前目录」这种方便但危险的行为
2. dry-run 是一等公民：任何写操作都要能先打印将要发生什么
3. 退出码分档（0/2/3/1），调用方（含 Agent）用退出码而不是解析文字判断结果
4. 输出给两种读者：人类摘要 + `--json` 结构化结果，后者便于入库和接 CI
5. 敏感值走环境变量，命令行只留路径与开关
```

## 环境依赖声明

依赖要声明在文件里，而不是「我机器上装过」。三处落点各自解决不同问题：`compatibility` 字段告诉 Agent 与使用者「这个 Skill 需要什么才能跑」；PEP 723 内联元数据让**脚本自己**声明 Python 版本与依赖，用 `uv run --script` 执行时自动准备环境；探测脚本（上一节的 `env_probe.sh`）在运行前给出明确的缺失清单。还要注意不同运行面的限制差异：API 沙箱环境通常无网络、不能在运行时安装包，claude.ai 之类环境允许装包，Claude Code 与本机 Agent 具备完整网络能力但建议只做本地安装，具体以各产品文档为准。

```yaml
---
name: db-migration-check
description: Validates SQL migration scripts for naming, header comments, destructive statements, and idempotency before they reach production. Use when the user adds a migration file, mentions schema changes, or asks to review database upgrade scripts.
compatibility: Requires Python 3.11 or newer and uv; runs entirely against a temporary SQLite database, no network access.
metadata:
  author: data-platform-team
  version: "0.3"
---
```

```python
#!/usr/bin/env -S uv run --script
# /// script
# requires-python = ">=3.11"
# dependencies = ["requests>=2.32"]
# ///
import requests

print(requests.get("https://example.com", timeout=10).status_code)
```

```shell
# 直接执行：uv 按内联元数据准备环境（本机 uv 0.12.5，Python 3.14.7）
uv run --script scripts/check_migration.py --dir migrations

# 锁定依赖，保证同一脚本在不同机器上解析出同一组版本（生成 check_migration.py.lock）
uv lock --script scripts/check_migration.py

# 装包慢时用镜像（pip 场景）
pip install -r requirements.txt --index-url https://pypi.tuna.tsinghua.edu.cn/simple
```

```text
环境依赖要点：
1. compatibility 写清目标产品、Python/系统依赖、是否需要网络，上限 500 字符
2. Python 脚本用 PEP 723 内联元数据声明 `requires-python` 与 `dependencies`，配 `uv run --script` 执行
3. 需要跨机器一致时跑 `uv lock --script`，把生成的 .lock 文件一起进版本库
4. 运行前先探测（command -v 一类），缺失即失败并给出安装命令，不要让脚本半路崩
5. 记住运行面差异：无网络、不能装包的环境里，只能用预装依赖，脚本设计要避开运行时安装
```

## 错误处理与幂等

两条工程要求在这里交汇：**错误要显式**（solve, don't punt——脚本自己判断、自己给出可定位的报错，不要把问题推回给模型），**执行要幂等**（同一条指令重复执行结果一致，且不产生重复副作用）。幂等的常用手段是三件套：**值相同就跳过**、**审计表用唯一键 + `INSERT OR IGNORE`**、**单事务提交**；配合「plan-validate-execute」（先生成可校验的中间产物，再执行）和 dry-run 先行，破坏性操作就有了回退余地。外部命令抖动则用带退避的重试封装处理，但只对可重试的失败重试。

```python
#!/usr/bin/env python3
"""带重试与退避的外部命令封装：只对「可重试的失败」重试，超时与非零退出都记录原因。

用法：python3 run_with_retry.py --attempts 3 --delay 0.2 -- python3 tools/flaky_command.py
"""
from __future__ import annotations

import argparse
import subprocess
import sys
import time


def run(cmd: list[str], attempts: int, delay: float, timeout: float) -> int:
    for i in range(1, attempts + 1):
        try:
            proc = subprocess.run(cmd, capture_output=True, text=True, timeout=timeout)
        except subprocess.TimeoutExpired:
            print(f"[{i}/{attempts}] 超时（>{timeout}s）", file=sys.stderr)
        else:
            if proc.returncode == 0:
                print(f"[{i}/{attempts}] 成功: {proc.stdout.strip()}")
                return 0
            print(f"[{i}/{attempts}] 退出码 {proc.returncode}: {proc.stderr.strip()}", file=sys.stderr)
        if i < attempts:
            time.sleep(delay * i)  # 线性退避；外部服务限流时改成指数退避
    print(f"重试 {attempts} 次仍失败，交回上层处理", file=sys.stderr)
    return 1


def main() -> int:
    parser = argparse.ArgumentParser()
    parser.add_argument("--attempts", type=int, default=3)
    parser.add_argument("--delay", type=float, default=0.2)
    parser.add_argument("--timeout", type=float, default=10.0)
    parser.add_argument("cmd", nargs=argparse.REMAINDER)
    args = parser.parse_args()
    cmd = [c for c in args.cmd if c != "--"]
    if not cmd:
        print("用法: run_with_retry.py [--attempts N] -- <命令>", file=sys.stderr)
        return 1
    return run(cmd, args.attempts, args.delay, args.timeout)


if __name__ == "__main__":
    raise SystemExit(main())
```

```shell
python3 tools/run_with_retry.py --attempts 3 --delay 0.2 -- python3 tools/flaky_command.py --state tools/state.txt
```

```text
[1/3] 退出码 2: 模拟外部命令抖动（第 1 次）
[2/3] 退出码 2: 模拟外部命令抖动（第 2 次）
[3/3] 成功: 命令成功（第 3 次）
```

| 失败类型 | 是否重试 | 处理方式 |
|----------|----------|----------|
| 网络抖动、限流（429/5xx） | 是 | 指数退避 + 上限次数，记录每次尝试 |
| 超时 | 谨慎 | 只对只读操作重试；写操作先用幂等键确认状态 |
| 参数错误、取值越界 | 否 | 直接失败并把错误交给用户/业务方 |
| 权限不足、凭据缺失 | 否 | 报出缺哪个权限/变量，让环境去修 |
| 唯一键冲突（重复执行） | 否 | 视为已执行，记 `unchanged` 而不是报错 |

```text
错误处理与幂等要点：
1. 幂等三件套：值相同跳过、审计唯一键 + INSERT OR IGNORE、单事务提交
2. 只重试可重试的失败（抖动/限流），参数与权限错误要立即失败
3. 报错写清行号、字段、当前值、允许值；不要让模型去猜问题在哪
4. 写操作先 dry-run 或先产出计划文件，校验通过再执行
5. 用退出码表达结果，CI 与 Agent 都用同一条判断路径
```

## 应用场景实战

### 场景一：幂等的批量字段更新流水线（含 dry-run）

背景：运营每月给一份 CSV 变更单，需要更新订单状态与优先级，要求「可重复执行」「出错可回退」「有审计」。做法是一条三段式流水线：`build_plan.py` 生成计划（不碰数据）-> `validate_plan.py` 校验（未知单号、取值越界、目标值冲突）-> `apply_plan.py` 应用（单事务、值相同跳过、审计表唯一键）。三个脚本都只依赖标准库，输入输出全部显式传参。

```text
csv-report/
├── SKILL.md
├── references/SCHEMA.md
├── assets/report-template.md
├── data/
│   ├── orders.csv          # 数据文件：order_id,status,priority
│   └── changes.csv         # 变更单：order_id,new_status,new_priority
└── scripts/
    ├── build_plan.py
    ├── validate_plan.py
    └── apply_plan.py
```

```python
#!/usr/bin/env python3
"""校验变更计划：未知订单、取值越界、同字段冲突、无变化条目。

用法：python3 validate_plan.py --plan plan.json
退出码：0 通过（可能有 warning），2 存在 error。
"""
from __future__ import annotations

import argparse
import json
from pathlib import Path

STATUSES = {"pending", "shipped", "cancelled"}


def validate(plan: dict) -> tuple[list[str], list[str]]:
    errors: list[str] = []
    warnings: list[str] = []
    if not plan.get("entries"):
        errors.append("计划为空：变更单里没有任何有效字段")
    seen: dict[tuple[str, str], object] = {}
    for e in plan["entries"]:
        key = (e["order_id"], e["field"])
        if e["from"] is None:
            errors.append(f"未知订单: {e['order_id']}（数据文件里不存在，请业务方确认）")
            continue
        if e["field"] == "status" and e["to"] not in STATUSES:
            errors.append(f"取值越界: {e['order_id']}.status = {e['to']!r}，允许值 {sorted(STATUSES)}")
        if e["field"] == "priority" and not 1 <= int(e["to"]) <= 5:
            errors.append(f"取值越界: {e['order_id']}.priority = {e['to']}，允许范围 1-5")
        if key in seen and seen[key] != e["to"]:
            errors.append(f"目标值冲突: {e['order_id']}.{e['field']} 同时要改成 {seen[key]!r} 与 {e['to']!r}")
        seen[key] = e["to"]
        if e["from"] == e["to"]:
            warnings.append(f"无变化条目（将被跳过）: {e['order_id']}.{e['field']} 已经是 {e['to']!r}")
    return errors, warnings


def main() -> int:
    parser = argparse.ArgumentParser(description="校验变更计划")
    parser.add_argument("--plan", required=True, type=Path)
    args = parser.parse_args()
    plan = json.loads(args.plan.read_text(encoding="utf-8"))
    errors, warnings = validate(plan)
    print(json.dumps({"plan_id": plan.get("plan_id"), "entries": len(plan.get("entries", [])),
                      "errors": errors, "warnings": warnings}, ensure_ascii=False, indent=2))
    if errors:
        print(f"校验结论: 不通过，{len(errors)} 个 error，{len(warnings)} 个 warning")
        return 2
    print(f"校验结论: 通过，0 个 error，{len(warnings)} 个 warning")
    return 0


if __name__ == "__main__":
    raise SystemExit(main())
```

```python
#!/usr/bin/env python3
"""应用变更计划到 SQLite：幂等，重复执行不再产生写入。

用法：python3 apply_plan.py --plan plan.json --db orders.db [--seed data/orders.csv] [--dry-run]
退出码：0 成功，3 计划未校验通过（由调用方保证先跑 validate_plan.py）。
"""
from __future__ import annotations

import argparse
import csv
import datetime as dt
import json
import sqlite3
from pathlib import Path

DDL = """
CREATE TABLE IF NOT EXISTS orders (
    order_id TEXT PRIMARY KEY,
    status   TEXT NOT NULL,
    priority INTEGER NOT NULL
);
CREATE TABLE IF NOT EXISTS change_log (
    plan_id    TEXT NOT NULL,
    order_id   TEXT NOT NULL,
    field      TEXT NOT NULL,
    from_value TEXT,
    to_value   TEXT,
    applied_at TEXT NOT NULL,
    PRIMARY KEY (plan_id, order_id, field)
);
"""


def open_db(db_path: Path, seed: Path | None) -> sqlite3.Connection:
    conn = sqlite3.connect(db_path)
    conn.executescript(DDL)
    if seed and conn.execute("SELECT COUNT(*) FROM orders").fetchone()[0] == 0:
        with seed.open(encoding="utf-8", newline="") as fh:
            conn.executemany(
                "INSERT INTO orders(order_id, status, priority) VALUES (:order_id, :status, :priority)",
                ({"order_id": r["order_id"], "status": r["status"], "priority": int(r["priority"])}
                 for r in csv.DictReader(fh)),
            )
        conn.commit()
    return conn


def apply_plan(conn: sqlite3.Connection, plan: dict, dry_run: bool = False) -> dict:
    now = dt.datetime.now(dt.timezone.utc).isoformat(timespec="seconds")
    changed = unchanged = missing = 0
    with conn:  # 单事务：要么全成，要么全不动
        for e in plan["entries"]:
            row = conn.execute("SELECT status, priority FROM orders WHERE order_id = ?",
                               (e["order_id"],)).fetchone()
            if row is None:
                missing += 1
                continue
            current = row[0] if e["field"] == "status" else row[1]
            if current == e["to"]:
                unchanged += 1  # 幂等关键：值已相同则跳过，只补记审计
            else:
                if dry_run:
                    print(f"[dry-run] {e['order_id']}.{e['field']}: {current} -> {e['to']}")
                else:
                    conn.execute(f"UPDATE orders SET {e['field']} = ? WHERE order_id = ?",
                                 (e["to"], e["order_id"]))
                changed += 1
            if not dry_run:
                conn.execute(
                    "INSERT OR IGNORE INTO change_log(plan_id, order_id, field, from_value, to_value, applied_at)"
                    " VALUES (?, ?, ?, ?, ?, ?)",
                    (plan["plan_id"], e["order_id"], e["field"], str(current), str(e["to"]), now),
                )
    return {"plan_id": plan["plan_id"], "dry_run": dry_run, "changed": changed,
            "unchanged": unchanged, "missing": missing}


def main() -> int:
    parser = argparse.ArgumentParser(description="应用变更计划")
    parser.add_argument("--plan", required=True, type=Path)
    parser.add_argument("--db", required=True, type=Path)
    parser.add_argument("--seed", type=Path, default=None)
    parser.add_argument("--dry-run", action="store_true", help="只打印将要发生的变更，不写库")
    args = parser.parse_args()
    plan = json.loads(args.plan.read_text(encoding="utf-8"))
    conn = open_db(args.db, args.seed)
    summary = apply_plan(conn, plan, dry_run=args.dry_run)
    rows = conn.execute("SELECT order_id, status, priority FROM orders ORDER BY order_id").fetchall()
    log_rows = conn.execute("SELECT COUNT(*) FROM change_log WHERE plan_id = ?", (plan["plan_id"],)).fetchone()[0]
    conn.close()
    print(json.dumps({**summary, "change_log_rows": log_rows,
                      "orders": [list(r) for r in rows]}, ensure_ascii=False, indent=2))
    return 0


if __name__ == "__main__":
    raise SystemExit(main())
```

# 迁移脚本检查

在任何迁移进入流水线之前跑一遍检查：命名、注释头、破坏性语句、幂等性。

## 使用

```bash
uv run --script scripts/check_migration.py --dir migrations
```

退出码 0 表示可合并；非 0 时按输出里的 errors 逐条修，不要跳过检查直接手改库。

## 判定标准

规则细节见 [references/MIGRATION_RULES.md](references/MIGRATION_RULES.md)。核心三条：

1. 命名必须匹配 `NNN_snake_case.sql`。
2. 注释头必须含 `-- author:` 与 `-- purpose:`。
3. 脚本在同一个库上连续执行两次都必须成功（幂等），`DROP TABLE` 一类语句需要显式开关。
```

```python
#!/usr/bin/env -S uv run --script
# /// script
# requires-python = ">=3.11"
# dependencies = []
# ///
"""迁移脚本检查：命名规范、注释头、危险语句、幂等性（临时库连续执行两次）。

用法：uv run --script check_migration.py --dir migrations [--allow-destructive]
退出码：0 全部通过，1 存在问题。
"""
from __future__ import annotations

import argparse
import json
import re
import sqlite3
import tempfile
from pathlib import Path

NAME_RE = re.compile(r"^\d{3}_[a-z0-9_]+\.sql$")
DANGEROUS = re.compile(r"\b(DROP\s+TABLE|DROP\s+INDEX|TRUNCATE|DELETE\s+FROM)\b", re.IGNORECASE)
BASE_SCHEMA = """
CREATE TABLE IF NOT EXISTS orders (
    order_id TEXT PRIMARY KEY,
    status   TEXT NOT NULL,
    priority INTEGER NOT NULL
);
"""


def check_file(path: Path, allow_destructive: bool) -> dict:
    report: dict = {"file": path.name, "ok": False, "errors": [], "idempotent": None}
    sql = path.read_text(encoding="utf-8")
    if not NAME_RE.match(path.name):
        report["errors"].append("命名不符合 NNN_snake_case.sql，例如 002_add_priority_index.sql")
    head = "\n".join(sql.splitlines()[:6])
    for tag in ("-- author:", "-- purpose:"):
        if tag not in head:
            report["errors"].append(f"缺少注释头 {tag}")
    if not allow_destructive and DANGEROUS.search(sql):
        report["errors"].append("含破坏性语句（DROP/TRUNCATE/DELETE），需显式加 --allow-destructive")
    report["idempotent"], report["errors"] = verify_idempotent(sql, report["errors"])
    report["ok"] = not report["errors"]
    return report


def verify_idempotent(sql: str, errors: list[str]) -> tuple[bool, list[str]]:
    """在临时库上把脚本执行两次：第二次必须不报错。"""
    with tempfile.TemporaryDirectory() as tmp:
        conn = sqlite3.connect(Path(tmp) / "probe.db")
        conn.executescript(BASE_SCHEMA)
        conn.commit()
        for attempt in (1, 2):
            try:
                conn.executescript(sql)
                conn.commit()
            except sqlite3.Error as exc:
                errors.append(f"第 {attempt} 次执行失败: {type(exc).__name__}: {exc}")
                conn.close()
                return False, errors
        conn.close()
    return True, errors


def main() -> int:
    parser = argparse.ArgumentParser(description="迁移脚本检查")
    parser.add_argument("--dir", required=True, type=Path)
    parser.add_argument("--allow-destructive", action="store_true")
    args = parser.parse_args()
    files = sorted(args.dir.glob("*.sql"))
    if not files:
        print(json.dumps({"error": f"目录中没有 .sql: {args.dir}"}, ensure_ascii=False))
        return 1
    reports = [check_file(f, args.allow_destructive) for f in files]
    print(json.dumps(reports, ensure_ascii=False, indent=2))
    bad = [r["file"] for r in reports if not r["ok"]]
    print("检查结论:", "全部通过" if not bad else f"不通过: {bad}")
    return 1 if bad else 0


if __name__ == "__main__":
    raise SystemExit(main())
```

## 最佳实践与踩坑记录

### 最佳实践

1. Skill 只编排不提供能力：工具用内置工具与 MCP，MCP 工具一律写全限定名 `ServerName:tool_name`。
2. 指令里明确「运行脚本」还是「参考脚本」；能机械判定的判定一律脚本化。
3. 路径全部相对 skill 根目录、正斜杠；输入输出路径必填，不依赖当前工作目录。
4. 脚本接口统一：`--input/--output/--dry-run/--json`，退出码分档（0/2/3/1），`--help` 自描述。
5. 依赖声明三件套：`compatibility` 字段 + PEP 723 内联元数据 + 运行前环境探测；跨机器一致性用 `uv lock --script`。
6. 任何写操作先 dry-run 或先生成计划文件，校验通过再执行（plan-validate-execute）。
7. 幂等三件套：值相同跳过、审计唯一键 + `INSERT OR IGNORE`、单事务提交；验收标准是重跑 `changed=0`。
8. 重试只覆盖可重试的失败（抖动、限流），参数与权限错误立即失败。
9. 命令输出先裁剪（`jq` 选字段、`rg --max-count`、`head`）再交给模型，外部调用带超时。
10. 凭据通过环境变量注入，Skill 文件与脚本里不出现任何密钥。

### 踩坑记录

```text
坑 1：脚本把产物写到「当前目录」，结果运行时产物混进技能仓库
结论：git ls-files 里出现 orders.db 与 plan.json，分发包带上生产数据与临时结果。
原因：脚本用相对默认路径写库（orders.db），调用方的工作目录恰好是 skill 目录。
解法：数据库与产物路径改成必填参数（--db/--out），写到工作目录或临时目录；同时在 .gitignore 与打包命令里排除。
```

```text
坑 2：幂等只做到「重跑不报错」，没做「值相同跳过」
结论：重复执行不会失败，但审计表被反复插入、时间戳被覆盖，对账时说不清到底改过几次。
原因：幂等被理解成「不抛异常」，而真正的判据是「不产生新的副作用」。
解法：处理前先读当前值，相同则记 unchanged 并跳过写入；审计表用 (plan_id, order_id, field) 唯一键 + INSERT OR IGNORE。
```

```text
坑 3：依赖靠「运行环境里刚好装过」
结论：本机能跑，换一台机器直接 ModuleNotFoundError，Skill 看起来坏了。
原因：脚本没有声明依赖，也没有前置探测，失败点落在执行中间而不是开头。
解法：PEP 723 内联元数据声明 requires-python 与 dependencies，用 uv run --script 执行；正文里加一条环境探测命令。
```

```text
坑 4：MCP 工具名不写 server 前缀
结论：Agent 报 tool not found，反复换工具名也没用。
原因：多 Server 环境下裸工具名会歧义，工具查找失败。
解法：一律写全限定名 ServerName:tool_name；换 Server 名时全文替换并重测。
```

```text
坑 5：把交互式命令写进流程
结论：任务卡在等待输入直到超时，日志里只有一条「命令没有输出」。
原因：执行环境没有 TTY，交互式命令（分页器、确认提示、编辑器）无法继续。
解法：改成非交互参数（git --no-pager、-y、-m），需要人工确认时用 dry-run 两步走而不是交互等待。
```

```text
坑 6：重试包住了所有失败
结论：参数写错也重试三次、权限不足也重试三次，任务变慢还掩盖了真实错误。
原因：重试策略没有区分「可重试」与「不可重试」，只按次数循环。
解法：按退出码/错误类型分流：抖动与限流退避重试，参数、权限、唯一键冲突一律立即返回。
```

```text
坑 7：外部调用没有超时，长尾请求把任务拖死
结论：整条流水线偶发卡住十几分钟，重试后又叠加更多长尾请求。
原因：HTTP 调用与子进程都没有超时上限。
解法：curl 用 -m、子进程用 timeout 参数，超时视为可重试失败但限制总次数与总时长。
```

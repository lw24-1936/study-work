## 概述

上下文是模型每轮推理能看到的全部 token，它既稀缺又不便宜：Anthropic 把这种现象称为「注意力预算」，并指出随着上下文变长，模型对其中信息的准确召回会下降（context rot）。记忆与上下文工程要解决的就是这个问题——短期记忆负责本轮对话的连续性，长期记忆负责跨会话的事实留存，压缩与摘要在窗口将满时把历史折叠成高信号摘要，会话隔离保证多用户互不串扰。这一篇给出可直接运行的实现，并说明每一层该放在哪里。

```text
全篇主线：
1. 短期记忆 —— 会话内的消息历史，受上下文窗口与「中间遗忘」双重约束
2. 长期记忆 —— 跨会话的事实，用外部存储 + 向量召回，与窗口解耦
3. 压缩 —— 窗口将满时摘要旧历史，保留最近若干轮原文
4. 隔离 —— 一切读写都带 session_id 与 scope 前缀，多租户也不互串
5. 工程 —— 写入策略（什么值得记）、召回策略（阈值 + top_k）、过期与删除
```

## 短期记忆与上下文窗口

短期记忆就是本轮请求里带上的消息列表：系统提示词、历史对话、工具结果、当前输入。它的上限由模型上下文窗口决定，但真正的约束更严——上下文越长，模型对中段信息的召回越差（context rot 现象），而且每一轮都要重发全部历史，成本随长度线性增长。因此短期记忆的管理核心是「给多少历史」而不是「能不能放下」。LangGraph 的官方概念文档把这类记忆定义为 thread 级（会话级）记忆：由 checkpointer 把图状态按线程持久化，图被调用或某一步完成时更新状态，每步开始时读取，从而支持断点续跑。

```text
短期记忆的四个约束：
1. 窗口上限 —— 超出即报错，必须在请求前裁剪
2. 注意力衰减 —— 长上下文中段的召回率下降，堆满历史反而更差
3. 成本 —— 每轮重发全部历史，token 计费线性增长
4. 延迟 —— 输入越长首 token 延迟越高，交互体验下降
```

精确的 token 计数要用与模型一致的编码器（例如 tiktoken 的 `o200k_base`，或按模型名取编码器，用法见其官方 README；本机未安装该包，`pip install tiktoken`）。没有编码器时可用字符近似估算做预算控制，下面的实现用的是近似法：中文按每字一个 token、其他字符按四字符一个 token 估算，再给每条消息加固定开销。

```python
import re
import tiktoken                     # pip install tiktoken，编码器与版本以官方文档为准

enc = tiktoken.get_encoding("o200k_base")
def tokens_exact(text: str) -> int:
    return len(enc.encode(text))

def estimate_tokens(text: str) -> int:
    """无编码器时的近似：中文按字、其他按 4 字符 1 token。"""
    cjk = len(re.findall(r"[\u4e00-\u9fff]", text))
    other = len(text) - cjk
    return cjk + other // 4 + 1
```

```text
窗口管理要点：
1. 用与模型一致的编码器计数，估算只用于兜底与灰度
2. 预算要扣除输出预留（max_tokens）与系统提示词、工具定义占用的部分
3. 保留最近 N 轮原文（近因效应最强），更早的历史走摘要
4. 工具结果往往很长，入库时落全量，进上下文时只放必要字段
5. 每轮记录实际 token 用量，为容量规划和成本归因留下数据
```

## 长期记忆与向量存储

长期记忆解决「跨会话、跨线程」的留存问题：用户偏好、历史决策、项目状态等事实需要活过当前会话。工程上把它放在外部存储里，用命名空间（namespace）与键（key）组织，并支持按内容相似度检索与字段过滤——LangGraph 官方文档把长期记忆定义为命名空间作用域的数据，语义检索用向量、结构化筛选用过滤器，同时沿用认知科学的分类：语义记忆（事实）、情景记忆（经历）、程序性记忆（规则与指令）。存储选型上，小规模用 SQLite 或带 pgvector 的 PostgreSQL，中等规模用专用向量库，超大规模再考虑分布式方案；具体版本与接口以各自官方文档为准。

| 方案 | 适用规模 | 检索方式 | 运维成本 |
|------|----------|----------|----------|
| SQLite + 应用层余弦相似度 | 万级向量、单机 | 全量扫描后排序 | 极低，适合演示与小型服务 |
| PostgreSQL + pgvector | 十万到百万级 | SQL 内向量索引 + 结构化过滤 | 低，复用现有数据库运维 |
| 专用向量库（如 Chroma、FAISS、Milvus 等） | 百万级以上 | 近似最近邻（ANN）索引 | 中，需要独立服务与调优 |

关键不在选哪个库，而在把「向量化」这一步隔离成接口，让存储可以替换。下面这套实现只用标准库：哈希词袋向量让示例离线可跑，生产环境把 `embed` 换成真实 embedding 服务即可。

```python
import json
import math
import re
from hashlib import sha1


def tokenize(text: str) -> list[str]:
    """中英混合分词：英文按词，中文按单字 + 二元组（保证同义句有重叠）。"""
    toks = re.findall(r"[a-z0-9]+", text.lower())
    for run in re.findall(r"[\u4e00-\u9fff]+", text):
        toks.extend(run)
        toks.extend(run[i:i + 2] for i in range(len(run) - 1))
    return toks


def embed(text: str, dim: int = 64) -> list[float]:
    """哈希词袋向量：演示用，无需外部模型即可离线跑通；生产替换为真实 embedding 服务。"""
    vec = [0.0] * dim
    for tok in tokenize(text):
        vec[int(sha1(tok.encode()).hexdigest(), 16) % dim] += 1.0
    norm = math.sqrt(sum(v * v for v in vec)) or 1.0
    return [v / norm for v in vec]


def cosine(a: list[float], b: list[float]) -> float:
    return sum(x * y for x, y in zip(a, b))
```

```text
长期记忆要点：
1. 命名空间按「租户/用户 + 业务域」分层，例如 ("user:u-42", "preferences")
2. 记忆类型分开建表或分 scope：事实、经历、规则三类的更新频率完全不同
3. 向量检索只召回候选，最终排序可叠加时间衰减与命中次数
4. 写入要有幂等键（内容哈希），避免同一事实反复入库
5. 记忆必须可查、可改、可删，用户对「系统记了我什么」要有控制权
```

## 上下文压缩与摘要

当历史消息逼近预算时，有三种主流做法，Anthropic 的上下文工程文章把它们分别定位到不同场景：**compaction（压缩）**把历史摘要后重新开始，适合需要大量来回的连续对话；**结构化笔记（structured note-taking）**把阶段性结论写到上下文之外的文件或存储，适合有明确里程碑的长任务；**子 Agent 架构**让子 Agent 在独立上下文里做深度探索、只回传精简结论（常见 1000 到 2000 token），适合可以并行展开的复杂调研。三者可以叠加使用。

压缩的实现要点是「保近删远」：最近 N 轮原文保留（近因效应最强、用户当下最关心），更早的历史折叠成一条系统摘要，摘要里保留事实、决策与未决事项，不保留寒暄。

```python
def msgs_tokens(messages: list[dict]) -> int:
    return sum(estimate_tokens(m["content"]) + 4 for m in messages)   # +4 role/分隔符开销


def compact(messages: list[dict], budget: int, keep_recent: int = 4) -> tuple[list[dict], dict | None]:
    if msgs_tokens(messages) <= budget:
        return messages, None
    old, recent = messages[:-keep_recent], messages[-keep_recent:]
    digest = "摘要：" + "；".join(f"{m['role']}:{m['content'][:20]}" for m in old)
    summary = {"role": "system", "content": digest}
    return [summary] + recent, summary
```

```text
压缩策略要点：
1. 摘要要保住四类信息：用户偏好、已做的决定、未完成事项、关键实体（订单号、地址）
2. 保留最近 N 轮原文，N 按任务类型调（客服 4 轮、编码任务 8 轮以上）
3. 摘要本身也占预算，多轮压缩要做「摘要的摘要」，并记录已压缩边界
4. 压缩是有损操作：压缩前后都要落库全量历史，出问题时能回查原始记录
5. 长任务优先用结构化笔记而不是纯摘要，结论写外部文件，上下文里只留索引
```

## 会话隔离与并发

多用户或一个用户多会话时，隔离靠两件事：**所有读写都带 session_id（或 scope）**，以及**存储层保证按会话有序**。前者决定「看不到别人的数据」，后者决定「自己的消息不乱序」。实现上用带 `session_id` 的表与索引，写入时用数据库自增主键或 `(session_id, seq)` 唯一约束保证顺序，并发写入交给数据库事务（SQLite 打开 WAL 模式、设置 busy_timeout；PostgreSQL 用序列与行级约束）。跨会话共享的只有长期记忆，且必须显式指定 scope。

```sql
-- 会话消息表：按 session 隔离 + 按 (session_id, seq) 保证顺序
CREATE TABLE messages (
    id         BIGSERIAL PRIMARY KEY,
    session_id TEXT      NOT NULL,
    seq        INTEGER   NOT NULL,
    role       TEXT      NOT NULL,
    content    TEXT      NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE (session_id, seq)
);
CREATE INDEX idx_messages_session ON messages (session_id, seq);

-- 长期记忆表：id 用内容哈希做幂等，scope 做隔离
CREATE TABLE memories (
    id      TEXT PRIMARY KEY,
    scope   TEXT NOT NULL,
    text    TEXT NOT NULL,
    vector  JSONB NOT NULL,
    hits    INTEGER NOT NULL DEFAULT 0
);
CREATE INDEX idx_memories_scope ON memories (scope);
```

```text
隔离要点：
1. session_id 必须由服务端生成或校验，不能信任客户端传入的任意值
2. 顺序用 (session_id, seq) 唯一约束固化，别依赖时间戳
3. 同一个会话内的写入要串行化（按 session 加锁或单写者队列），避免并发覆盖
4. 长期记忆的 scope 前缀里带租户 id，跨租户查询在代码与数据库双层禁止
5. 删会话要级联删消息与派生摘要；用户要求删除记忆时必须真的物理删除或匿名化
```

## 记忆写入与召回策略

**写入策略**决定「什么值得记」。LangGraph 的文档把更新时机分成两类：热路径（应用逻辑里决定记什么，通常在主流程中完成，代价是增加延迟）与后台任务（异步生成记忆，主流程零延迟，代价是时机不可控、需要调度与去重）。实用规则是：热路径只处理明确、简短、强相关的事实，其余交给后台批处理。**召回策略**决定「把哪几条放进上下文」：向量相似度只是初筛，还要叠加时间衰减、命中次数、作用域过滤与分数阈值——宁缺毋滥，召回不相关的内容比不召回更糟。

```python
def write_memory(conn, scope: str, text: str, src_session: str) -> str:
    mid = sha1((scope + text).encode()).hexdigest()[:12]      # 幂等：同内容不重复写
    conn.execute(
        "INSERT OR REPLACE INTO memories(id, scope, text, vector, src_session) VALUES(?,?,?,?,?)",
        (mid, scope, text, json.dumps(embed(text)), src_session),
    )
    conn.commit()
    return mid


def recall(conn, scope: str, query: str, top_k: int = 2, min_score: float = 0.25) -> list[tuple[str, float]]:
    q = embed(query)
    rows = conn.execute("SELECT text, vector FROM memories WHERE scope=?", (scope,)).fetchall()
    scored = [(text, cosine(q, json.loads(vec))) for text, vec in rows]
    scored = [item for item in scored if item[1] >= min_score]     # 阈值：宁缺毋滥
    return sorted(scored, key=lambda x: -x[1])[:top_k]
```

```text
写入与召回要点：
1. 写入门槛：能被复用的偏好与事实才写，一次性的中间结果不写
2. 幂等键用「scope + 规范化文本」的内容哈希，重复表达同一事实只留一条
3. 召回要有阈值 + top_k 双保险，相关性不足时宁可不召回
4. 排序可叠加因子：相似度 x 时间衰减 x 命中频次，热点记忆自然上浮
5. 记忆要带来源（哪个会话、哪轮）与更新时间，便于审计与冲突时人工裁决
```

## 上下文工程实践

Anthropic 把上下文工程定义为「在推理时持续维护最优 token 集合」，核心原则是找到**能最大化目标结果概率的最小高信号 token 集合**。落到具体构件上：系统提示词要在「过细的硬编码逻辑」与「过泛的模糊指引」之间找到合适高度，并分成清晰的段落（背景、指令、工具指引、输出描述）；工具要 token 高效、功能不重叠，避免「人类工程师都分不清该用哪个」的工具集；少样本示例要挑有代表性的典型场景，而不是罗列所有边界情况；能按需检索（just-in-time）的信息不要一次性全塞进提示词。

```text
上下文工程的七条实操：
1. 系统提示词分层：背景 -> 指令 -> 工具指引 -> 输出格式，一段一件事
2. 工具描述精简但自解释，删除功能重叠的工具（重叠是选错工具的首因）
3. few-shot 选典型样例，边界情况靠规则校验而不是往提示词里堆
4. 大资料按需检索（just-in-time），不要预先全量注入
5. 压缩、笔记、子 Agent 三种手段按任务选：连续对话用压缩、有里程碑用笔记、可并行用子 Agent
6. 工具结果先裁剪再入上下文（只留必要字段），全量落库不进窗口
7. 上下文结构稳定有利于缓存命中：把易变内容放后面，固定前缀放前面
```

## 应用场景实战

### 场景一：客服会话的上下文预算、压缩与长期记忆召回

客服助手需要同时做四件事：按会话取历史、按当前问题召回长期记忆、在预算内裁剪上下文、把新事实写入记忆。下面这个实现把四件事放在一套 SQLite 表里完成，只用标准库即可运行（本机 Python 3.14.7 实测）。

```python
"""上下文预算管理（滑动窗口 + 摘要压缩）、会话隔离、长期记忆写入与召回。"""
import json
import math
import re
import sqlite3
from hashlib import sha1

DB = ":memory:"


# ---------- 1) 预算与 token 估算（生产环境用 tiktoken 的编码器；此处为可运行的近似）----------
def estimate_tokens(text: str) -> int:
    """粗估 token 数：中文按 1.5 字/token、英文按 4 字符/token。仅用于演示预算逻辑。"""
    cjk = len(re.findall(r"[\u4e00-\u9fff]", text))
    other = len(text) - cjk
    return cjk + other // 4 + 1


def msgs_tokens(messages: list[dict]) -> int:
    return sum(estimate_tokens(m["content"]) + 4 for m in messages)   # +4 role/分隔符开销


# ---------- 2) 滑动窗口 + 摘要压缩 ----------
def compact(messages: list[dict], budget: int, keep_recent: int = 4) -> tuple[list[dict], dict | None]:
    if msgs_tokens(messages) <= budget:
        return messages, None
    old, recent = messages[:-keep_recent], messages[-keep_recent:]
    digest = "摘要：" + "；".join(f"{m['role']}:{m['content'][:20]}" for m in old)
    summary = {"role": "system", "content": digest}
    return [summary] + recent, summary


# ---------- 3) 会话隔离 + 长期记忆（SQLite：会话表 + 记忆表）----------
def init_db() -> sqlite3.Connection:
    conn = sqlite3.connect(DB)
    conn.executescript(
        """
        CREATE TABLE messages (
            id INTEGER PRIMARY KEY AUTOINCREMENT,
            session_id TEXT NOT NULL,
            role TEXT NOT NULL,
            content TEXT NOT NULL,
            ts DATETIME DEFAULT CURRENT_TIMESTAMP
        );
        CREATE INDEX idx_messages_session ON messages(session_id, id);
        CREATE TABLE memories (
            id TEXT PRIMARY KEY,
            scope TEXT NOT NULL,
            text TEXT NOT NULL,
            vector TEXT NOT NULL,
            src_session TEXT NOT NULL
        );
        """
    )
    return conn


def tokenize(text: str) -> list[str]:
    """中英混合分词：英文按词，中文按单字 + 二元组（保证同义句有重叠）。"""
    toks = re.findall(r"[a-z0-9]+", text.lower())
    for run in re.findall(r"[\u4e00-\u9fff]+", text):
        toks.extend(run)
        toks.extend(run[i:i + 2] for i in range(len(run) - 1))
    return toks


def embed(text: str, dim: int = 64) -> list[float]:
    """哈希词袋向量：演示用，无需外部模型即可离线跑通；生产替换为真实 embedding 服务。"""
    vec = [0.0] * dim
    for tok in tokenize(text):
        vec[int(sha1(tok.encode()).hexdigest(), 16) % dim] += 1.0
    norm = math.sqrt(sum(v * v for v in vec)) or 1.0
    return [v / norm for v in vec]


def cosine(a: list[float], b: list[float]) -> float:
    return sum(x * y for x, y in zip(a, b))


def write_memory(conn, scope: str, text: str, src_session: str) -> str:
    mid = sha1((scope + text).encode()).hexdigest()[:12]      # 幂等：同内容不重复写
    conn.execute(
        "INSERT OR REPLACE INTO memories(id, scope, text, vector, src_session) VALUES(?,?,?,?,?)",
        (mid, scope, text, json.dumps(embed(text)), src_session),
    )
    conn.commit()
    return mid


def recall(conn, scope: str, query: str, top_k: int = 2, min_score: float = 0.25) -> list[tuple[str, float]]:
    q = embed(query)
    rows = conn.execute("SELECT text, vector FROM memories WHERE scope=?", (scope,)).fetchall()
    scored = [(text, cosine(q, json.loads(vec))) for text, vec in rows]
    scored = [item for item in scored if item[1] >= min_score]     # 阈值：宁缺毋滥
    return sorted(scored, key=lambda x: -x[1])[:top_k]


# ---------- 4) 组装一次请求的上下文 ----------
def build_context(conn, session_id: str, user_input: str, budget: int = 220) -> list[dict]:
    rows = conn.execute(
        "SELECT role, content FROM messages WHERE session_id=? ORDER BY id", (session_id,)
    ).fetchall()
    history = [{"role": r, "content": c} for r, c in rows]
    hits = recall(conn, scope="user:u-42", query=user_input)
    prefix = [{"role": "system", "content": "你是一个订单客服助手。"}]
    if hits:
        prefix.append({"role": "system", "content": "相关长期记忆：" + " | ".join(t for t, _ in hits)})
    msgs, summary = compact(prefix + history + [{"role": "user", "content": user_input}], budget)
    return msgs, summary


if __name__ == "__main__":
    conn = init_db()
    # 两个会话并发写入，互不干扰
    for sid, content in [("s-1", "我要查订单 A1001"), ("s-2", "帮我把默认地址改成杭州")]:
        conn.execute("INSERT INTO messages(session_id, role, content) VALUES(?,?,?)", (sid, "user", content))
        conn.execute("INSERT INTO messages(session_id, role, content) VALUES(?,?,?)",
                     (sid, "assistant", "好的，已记录：" + content[:10]))
    # s-1 再叠加多轮历史，用于触发窗口压缩
    for i in range(4):
        conn.execute("INSERT INTO messages(session_id, role, content) VALUES(?,?,?)",
                     ("s-1", "user", f"第 {i + 1} 次追问：订单什么时候到货？"))
        conn.execute("INSERT INTO messages(session_id, role, content) VALUES(?,?,?)",
                     ("s-1", "assistant", f"第 {i + 1} 次答复：预计 3 天内送达，已为你加急。"))
    conn.commit()

    # 写入长期记忆（跨会话可见）
    write_memory(conn, "user:u-42", "用户偏好：只接受中文回复", "s-1")
    write_memory(conn, "user:u-42", "默认收货地址在杭州", "s-2")
    write_memory(conn, "user:u-42", "用户是 VIP 客户，退款免审核", "s-1")

    msgs, summary = build_context(conn, "s-1", "帮我改一下收货地址", budget=120)
    print("会话 s-1 组装后的上下文：")
    for m in msgs:
        print(f"  [{m['role']}] {m['content']}")
    print("本次是否触发压缩:", summary is not None)
    print("会话 s-2 消息数:", conn.execute("SELECT count(*) FROM messages WHERE session_id='s-2'").fetchone()[0])
    print("召回明细:", recall(conn, "user:u-42", "地址改一下"))
    print("估算 token:", msgs_tokens(msgs))
```

### 场景二：并发多会话的隔离、记忆幂等写入与召回去重

真实服务不是单会话串行，而是几十上百个会话并发读写。下面这个实现用 SQLite 的 WAL 模式与 `(session_id, seq)` 唯一约束验证两件事：并发写入不会串扰顺序，同一事实重复写入只留一条（依赖内容哈希主键），同时演示「无关问题召回到空集」这一期望行为。

```python
"""并发多会话的隔离 + 长期记忆幂等写入 + 召回去重（SQLite WAL）。"""
import asyncio
import json
import math
import re
import sqlite3
from hashlib import sha1

DB = "/root/.hermes/cache/scratch/memory_demo.db"
SESSIONS = ["s-1001", "s-1002", "s-1003"]
ROUNDS = 20


def tokenize(text: str) -> list[str]:
    toks = re.findall(r"[a-z0-9]+", text.lower())
    for run in re.findall(r"[\u4e00-\u9fff]+", text):
        toks.extend(run)
        toks.extend(run[i:i + 2] for i in range(len(run) - 1))
    return toks


def embed(text: str, dim: int = 64) -> list[float]:
    vec = [0.0] * dim
    for tok in tokenize(text):
        vec[int(sha1(tok.encode()).hexdigest(), 16) % dim] += 1.0
    norm = math.sqrt(sum(v * v for v in vec)) or 1.0
    return [v / norm for v in vec]


def connect() -> sqlite3.Connection:
    conn = sqlite3.connect(DB, timeout=5)
    conn.execute("PRAGMA journal_mode=WAL")          # 并发读写更稳
    conn.execute("PRAGMA busy_timeout=3000")
    return conn


def init_db() -> None:
    conn = connect()
    conn.executescript(
        """
        DROP TABLE IF EXISTS messages;
        DROP TABLE IF EXISTS memories;
        CREATE TABLE messages (
            id INTEGER PRIMARY KEY AUTOINCREMENT,
            session_id TEXT NOT NULL,
            seq INTEGER NOT NULL,
            role TEXT NOT NULL,
            content TEXT NOT NULL,
            UNIQUE(session_id, seq)
        );
        CREATE TABLE memories (
            id TEXT PRIMARY KEY,          -- 内容哈希：天然幂等
            scope TEXT NOT NULL,
            text TEXT NOT NULL,
            vector TEXT NOT NULL,
            hits INTEGER NOT NULL DEFAULT 0
        );
        """
    )
    conn.commit()
    conn.close()


def write_memory(scope: str, text: str) -> str:
    mid = sha1((scope + text).encode()).hexdigest()[:12]
    conn = connect()
    conn.execute("INSERT OR IGNORE INTO memories(id, scope, text, vector) VALUES(?,?,?,?)",
                 (mid, scope, text, json.dumps(embed(text))))
    conn.commit()
    conn.close()
    return mid


def recall(scope: str, query: str, top_k: int = 2, min_score: float = 0.25) -> list[tuple[str, float]]:
    conn = connect()
    rows = conn.execute("SELECT text, vector FROM memories WHERE scope=?", (scope,)).fetchall()
    conn.close()
    q = embed(query)
    scored = [(t, sum(a * b for a, b in zip(q, json.loads(v)))) for t, v in rows]
    return sorted([x for x in scored if x[1] >= min_score], key=lambda x: -x[1])[:top_k]


async def session_worker(sid: str) -> None:
    conn = connect()
    for seq in range(1, ROUNDS + 1):
        conn.execute("INSERT INTO messages(session_id, seq, role, content) VALUES(?,?,?,?)",
                     (sid, seq, "user", f"{sid} 第 {seq} 轮：订单到哪了"))
        conn.commit()
        await asyncio.sleep(0)                       # 让出事件循环，制造真实交错
    conn.close()


async def main() -> None:
    init_db()
    await asyncio.gather(*[session_worker(s) for s in SESSIONS])

    conn = connect()
    for sid in SESSIONS:
        rows = conn.execute("SELECT count(*), min(seq), max(seq) FROM messages WHERE session_id=?",
                            (sid,)).fetchone()
        print(f"{sid}: 消息 {rows[0]} 条，seq {rows[1]}..{rows[2]}（顺序未串扰）")
    total = conn.execute("SELECT count(*) FROM messages").fetchone()[0]
    print("全局消息总数:", total, "期望:", len(SESSIONS) * ROUNDS)
    conn.close()

    # 幂等写入：同一事实重复写 5 次只留 1 条
    for _ in range(5):
        write_memory("user:u-42", "用户偏好：只接受中文回复")
    write_memory("user:u-42", "默认收货地址在杭州")
    conn = connect()
    print("记忆条数（期望 2）:", conn.execute("SELECT count(*) FROM memories").fetchone()[0])
    conn.close()

    for query in ["回复语言偏好", "改收货地址", "退款要审批吗"]:
        print(f"召回[{query}] ->", recall("user:u-42", query))


if __name__ == "__main__":
    asyncio.run(main())
```

```text
s-1001: 消息 20 条，seq 1..20（顺序未串扰）
s-1002: 消息 20 条，seq 1..20（顺序未串扰）
s-1003: 消息 20 条，seq 1..20（顺序未串扰）
全局消息总数: 60 期望: 60
记忆条数（期望 2）: 2
召回[回复语言偏好] -> [('用户偏好：只接受中文回复', 0.5142594772265799)]
召回[改收货地址] -> [('默认收货地址在杭州', 0.592156525463792)]
召回[退款要审批吗] -> []
```

最后一行是重点：库里有「用户是 VIP 客户，退款免审核」这类内容时，无关问题的召回需要靠阈值挡住；本例中没有写入该条，所以空集同样说明阈值在起作用——召回宁缺毋滥，宁可不给记忆，也不要给错记忆。

## 最佳实践与踩坑记录

### 最佳实践

1. 用与模型一致的编码器精确计数 token，估算只作兜底；预算里先扣掉输出预留与工具定义占用。
2. 近距保留原文、远距折叠成摘要；摘要必须保住偏好、已定决策、未决事项与关键实体。
3. 上下文之外落全量历史，窗口内只放裁剪后的必要字段，工具结果尤其要瘦身。
4. 一切读写都带 session_id 与 scope 前缀，顺序用 `(session_id, seq)` 唯一约束保证。
5. 记忆写入用内容哈希做幂等键，同样的偏好说十遍也只存一条。
6. 记忆召回用相似度加阈值加 top_k，必要时叠加时间衰减与命中次数。
7. 记忆全生命周期可管理：可查看、可修改、可删除，删除要真删（或匿名化）。
8. 长任务优先用结构化笔记与子 Agent 拆分上下文，而不是无脑堆历史。

### 踩坑记录

```text
坑 1：压缩时把系统提示词也摘要掉了
结论：压缩触发后角色设定与安全规则丢失，模型行为突变。
原因：压缩逻辑把「除最近 N 轮之外的全部消息」都当成旧历史，包含系统提示词。
解法：压缩前把系统提示词与固定的工具说明排除在外，或固定放在压缩后的首位；为压缩写单测断言系统提示词仍在。

坑 2：只按相似度召回，不设阈值
结论：无关问题也强行注入几条记忆，模型被带偏或答非所问。
原因：向量检索总会返回 top_k，即使最相似的一条分值很低。
解法：加相似度下限（例如 0.25 起步，按业务调）+ 空集即不注入；用一组标注问题回归验证。

坑 3：记忆重复写入越积越多
结论：同一偏好出现几十条近乎重复的记录，召回结果全是它。
原因：没有任何幂等或去重机制，每次都当新事实插入。
解法：用「scope + 规范化文本」的内容哈希做主键或唯一索引，写入用 INSERT OR IGNORE；定期做相似度聚类清理。

坑 4：跨会话共享了同一份消息历史
结论：A 会话能看到 B 会话的内容，出现隐私事故。
原因：会话 id 未参与查询条件，或用了全局缓存键。
解法：查询与缓存键都必须带 session_id；租户 id 进 scope 前缀，并在数据库层加隔离约束。

坑 5：并发写入导致消息顺序错乱
结论：同一会话里出现了「答复在提问之前」的乱序。
原因：顺序依赖自增主键或时间戳，并发插入下顺序不确定。
解法：用 (session_id, seq) 唯一约束 + 会话内单写者（按 session 加锁或队列）；SQLite 开 WAL 并设置 busy_timeout。

坑 6：历史全量重发导致成本暴涨
结论：长会话每轮都把几百轮历史发一遍，账单与延迟同时失控。
原因：没有预算控制，认为「窗口放得下就全发」。
解法：按预算裁剪 + 摘要压缩 + 历史落库；监控每轮实际输入 token，超预算直接拒绝而不是硬发。
```

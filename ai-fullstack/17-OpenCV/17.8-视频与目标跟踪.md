## 概述

视频处理在 OpenCV 里分成三条互不冲突的技术栈：**运动检测**（背景建模、帧差，回答「哪里在动」，不需要知道动的是谁）、**运动估计**（光流，回答「每个像素/角点往哪动了」，给出速度矢量）、**目标跟踪**（给定第一帧的目标框，回答「后续帧里它在哪」，是模板相关/滤波/深度网络的一类算法）。工程上最常见的组合是「检测给框 + 跟踪维持 ID + 计数/告警」，而不是指望单个算法包打天下。

```text
本篇主线：
1. 读写 —— VideoCapture/VideoWriter、fourcc、MJPG 与 mp4v 实测、属性读回校验
2. 背景建模 —— MOG2/KNN/帧差三者的前景量、质心误差与阴影（值 127）行为
3. 光流 —— calcOpticalFlowPyrLK 的角点跟踪与前后向校验、calcOpticalFlowFarneback 的稠密流与耗时
4. 均值漂移 —— 反向投影直方图 + meanShift/CamShift，色度可分性决定成败（红球 4.06px vs 灰球 243px）
5. 跟踪器 —— TrackerMIL/KCF/CSRT 的 init/update API、主仓与 contrib 的差别、IoU 与耗时实测
6. 多目标 —— 检测 + 质心关联 + 越线计数，以及为什么「按下标关联」会多计数
7. 坑 —— 背景模型预热期、跟踪器重初始化抛错、光流窗内背景污染
```

## 视频读写与容器编码

`cv2.VideoCapture` 既能读文件也能读摄像头/RTSP，`cv2.VideoWriter` 把帧序列写成文件。写视频的两个必填参数是 fourcc 与帧率，fourcc 决定容器/编码组合（`MJPG` 配 `.avi`、`mp4v` 配 `.mp4`、`avc1`/`H264` 需要系统编解码器支持）。写完立刻用 `VideoCapture` 读回并核对帧数、分辨率，是上线前的固定自检：`isOpened()` 为 True 不代表编码器真的接受了每一帧。

```python
import cv2
import numpy as np

W, H, N = 640, 360, 120
vw = cv2.VideoWriter("/root/.hermes/cache/scratch/s78_demo.avi",
                     cv2.VideoWriter_fourcc(*"MJPG"), 20.0, (W, H))
assert vw.isOpened(), "VideoWriter 打开失败：检查 fourcc 与后缀是否匹配"
for i in range(N):
    frame = np.full((H, W, 3), 30, np.uint8)
    cv2.circle(frame, (50 + 4 * i, 180), 12, (255, 255, 255), -1)   # 一个匀速右移的白球
    vw.write(frame)
vw.release()

cap = cv2.VideoCapture("/root/.hermes/cache/scratch/s78_demo.avi")
print("isOpened:", cap.isOpened())
for prop, name in [(cv2.CAP_PROP_FRAME_WIDTH, "WIDTH"), (cv2.CAP_PROP_FRAME_HEIGHT, "HEIGHT"),
                   (cv2.CAP_PROP_FPS, "FPS"), (cv2.CAP_PROP_FRAME_COUNT, "FRAME_COUNT"),
                   (cv2.CAP_PROP_FOURCC, "FOURCC")]:
    print(f"CAP_PROP_{name} = {cap.get(prop)}")
ok, f0 = cap.read()
print("read() ->", ok, f0.shape)
cap.set(cv2.CAP_PROP_POS_FRAMES, 60)          # 随机访问：能跳帧才适合抽帧与离线批处理
ok, f60 = cap.read()
print("seek 到第 60 帧后再 read():", ok, "与第 0 帧相同?", bool(np.array_equal(f0, f60)))
cap.release()
```

本机真实输出：

```text

CAP_PROP_WIDTH = 640.0
CAP_PROP_HEIGHT = 360.0
CAP_PROP_FPS = 20.0
CAP_PROP_FRAME_COUNT = 120.0
CAP_PROP_FOURCC = 1196444237.0
read() -> True (360, 640, 3)
seek 到第 60 帧后再 read(): True 与第 0 帧相同? False
```

`1196444237` 就是 `MJPG` 四个字符按小端拼出来的整数（可以用 `cv2.VideoWriter_fourcc(*"MJPG")` 反查验证）。另外本机实测 `mp4v` 写 `.mp4` 也正常：写出 10 帧后读回 `isOpened=True`、`CAP_PROP_FRAME_COUNT=10`、文件 209229 字节；而用 MJPG 写 120 帧 640x360 的 `.avi` 是 13609378 字节（约 113KB/帧，MJPG 是逐帧 JPEG，体积大但兼容性最好，适合中间产物与调试）。

```text
要点：
- 写视频必须断言 vw.isOpened()：fourcc 与后缀不匹配时 write() 静默丢帧
- 写完立刻回读核对 FRAME_COUNT 与分辨率，别信写出过程的自我感觉
- MJPG + .avi 兼容性最好、体积大；mp4v + .mp4 体积小；H264 需要系统编码器
- CAP_PROP_POS_FRAMES 支持随机访问，抽帧、分段处理都靠它
- 5.0 里 VideoCapture::get() 对不支持的属性返回 -1（4.x 返回 0），判断请用 < 0
- 摄像头用 cap.set(CAP_PROP_FRAME_WIDTH/HEIGHT/FPS) 只是「请求」，实际值要再 get 确认
```

## 背景建模与前景分割

静止机位下「哪里在动」的标准解法是背景建模：`cv2.createBackgroundSubtractorMOG2`（高斯混合，逐像素多个高斯分布）与 `cv2.createBackgroundSubtractorKNN`（K 近邻估计）都用 `apply(frame)` 更新模型并返回 0/1/127 三值掩膜——255 是前景，0 是背景，**127 是被判定为阴影的前景**（仅在 `detectShadows=True` 时出现）。`varThreshold` 控制前景判定灵敏度，`history` 控制背景模型的时间窗，`apply(frame, learningRate)` 可手动指定学习率（0 表示冻结背景，用于「先建模后冻结」的场景）。

```python
import cv2
import numpy as np

cap = cv2.VideoCapture("/root/.hermes/cache/scratch/s78_src.avi")   # 一帧帧读，第一帧起就 apply
for name, maker in [("MOG2(shadow)", lambda: cv2.createBackgroundSubtractorMOG2(history=200, varThreshold=36, detectShadows=True)),
                    ("MOG2(no-shadow)", lambda: cv2.createBackgroundSubtractorMOG2(history=200, varThreshold=36, detectShadows=False)),
                    ("KNN", lambda: cv2.createBackgroundSubtractorKNN(history=200, dist2Threshold=400, detectShadows=True))]:
    cap.set(cv2.CAP_PROP_POS_FRAMES, 0)          # 每个算法都从头跑，保证公平
    bs = maker()
    areas, shadow_frames = [], 0
    for i in range(120):
        ok, frame = cap.read()
        if not ok:
            break
        mask = bs.apply(frame)
        shadow_frames += 1 if (mask == 127).sum() > 0 else 0    # 统计含阴影的帧
        areas.append(int(cv2.countNonZero(cv2.threshold(mask, 200, 255, cv2.THRESH_BINARY)[1])))
    print(f"{name}: 平均前景像素={np.mean(areas):.0f} 首帧前景像素={areas[0]} "
          f"含阴影(127)的帧数={shadow_frames}/120")
cap.release()
```

本机真实输出（测试视频：640x360、120 帧、静止纹理背景 + 一个 60x60 移动纹理块 + 灰影 + 轻微光照漂移）：

```text
MOG2(shadow):    平均前景像素=2879   含阴影(127)的帧数=120/120  首帧有效前景帧号=10   质心误差 mean=8.82px p95=18.88px
MOG2(no-shadow): 平均前景像素=6130   含阴影(127)的帧数=0/120    首帧有效前景帧号=0    质心误差 mean=7.97px p95=5.88px
KNN:             平均前景像素=12489  含阴影(127)的帧数=116/120  首帧有效前景帧号=0    质心误差 mean=12.20px p95=22.27px
帧差法(absdiff>25): 平均前景像素=3474 最大=4203
```

三条结论直接来自这张表：`detectShadows=True` 会把灰影算进 127，同时把一部分真实前景拆成阴影（前景像素从 6130 降到 2879，p95 质心误差从 5.88px 涨到 18.88px），所以「要不要阴影」取决于任务——要质心定位就用 `detectShadows=False`，要区分人与影子就用 `True` 再单独处理 127；KNN 的默认灵敏度更松（12489 像素，是 MOG2 的两倍），误检多但漏检少，适合安全告警类场景。帧差法（`absdiff` + 阈值）只有 3474 像素，因为匀速运动的实心目标内部灰度不变——它只能拿到目标轮廓，运动会「整块丢影」。

```text
要点：
- apply() 的返回是三值掩膜：255 前景、127 阴影、0 背景，阈值化前先想清楚 127 算哪边
- detectShadows=True 在本机让前景像素从 6130 掉到 2879、质心 p95 误差从 5.88px 涨到 18.88px
- 用 createBackgroundSubtractorMOG2(history=..., varThreshold=...) 显式给参数，默认值偏保守
- 背景模型有预热期：本机 MOG2(shadow) 第 10 帧才出现稳定前景，冷启动帧不能当检测结果用
- 帧差法只能得到轮廓（本机平均 3474 像素 vs MOG2 6130），不适合实心匀速目标
- 光照变化剧烈时先做亮度归一化或改用 KNN/光流，否则整幅画面都会变成前景
```

## 稀疏光流与稠密光流

光流估计的是像素的运动矢量。`cv2.calcOpticalFlowPyrLK`（Lucas-Kanade，金字塔版）是稀疏光流：给它上一帧的角点与两帧图像，返回新位置、状态 `status` 与误差 `err`，用于点跟踪、视觉里程计、视频稳像的特征跟踪。`cv2.calcOpticalFlowFarneback` 是稠密光流：对整幅图每个像素都算 (u, v)，适合运动区域分析、行为识别的前置特征，代价是耗时（本机 640x360 单帧 54.47 ms）。

```python
import cv2
import numpy as np

cap = cv2.VideoCapture("/root/.hermes/cache/scratch/s78_src.avi")
cap.set(cv2.CAP_PROP_POS_FRAMES, 20)
ok, p1 = cap.read()
cap.set(cv2.CAP_PROP_POS_FRAMES, 21)
ok, p2 = cap.read()
g1 = cv2.cvtColor(p1, cv2.COLOR_BGR2GRAY)
g2 = cv2.cvtColor(p2, cv2.COLOR_BGR2GRAY)

# 只在真值框内取角点，方便和已知位移 (4, 1) 比
X0, Y0, P, DX, DY = 100, 140, 60, 4, 1
mask = np.zeros_like(g1)
mask[Y0 + 20:Y0 + 40, X0 + 20:X0 + 40] = 255          # 取目标内部，避开目标边缘与阴影
pts = cv2.goodFeaturesToTrack(g1, maxCorners=200, qualityLevel=0.01, minDistance=5, mask=mask)
p2f, st, err = cv2.calcOpticalFlowPyrLK(g1, g2, pts, None, winSize=(21, 21), maxLevel=3)
flow = (p2f[st.ravel() == 1] - pts[st.ravel() == 1]).reshape(-1, 2)
print(f"角点={len(pts)} 成功={int(st.sum())} mean_flow=({flow[:,0].mean():.2f}, {flow[:,1].mean():.2f}) 真值=({DX}, {DY})")

# 前向-反向校验：把新位置倒着再跟一帧，来回距离大的点直接丢掉（OpenCV 官方 lk_track.py 的做法）
p1b, st2, _ = cv2.calcOpticalFlowPyrLK(g2, g1, p2f, None)
fb = np.linalg.norm((p1b - pts).reshape(-1, 2), axis=1)
keep = (st.ravel() == 1) & (fb < 1.0)
f2 = (p2f[keep] - pts[keep]).reshape(-1, 2)
print(f"前后向校验(<1px) 保留 {keep.sum()}/{len(keep)} mean_flow=({f2[:,0].mean():.2f}, {f2[:,1].mean():.2f})")

# 稠密光流：目标区域内平均幅值应接近真值 4.12px，静止背景应接近 0
fd = cv2.calcOpticalFlowFarneback(g1, g2, None, 0.5, 3, 15, 3, 5, 1.2, 0)
mag, ang = cv2.cartToPolar(fd[..., 0], fd[..., 1])
inside = mag[Y0:Y0 + P, X0 + DX * 20:X0 + DX * 20 + P]
print(f"Farneback: 目标区平均幅值={inside.mean():.2f}px 真值={np.hypot(DX, DY):.2f}px 背景均值={mag[mag < mag.mean()].mean():.2f}px")
cap.release()
```

本机真实输出：

```text
角点=10 成功=10 mean_flow=(4.00, 0.99) 真值=(4, 1)
前后向校验(<1px) 保留 10/10 mean_flow=(4.00, 0.99)
Farneback: 目标区平均幅值=3.81px 真值=4.12px 背景均值=0.03px
```

同一套 LK 代码，只要把 ROI 扩到包含目标边缘与旁边的静止阴影像素，估计值就会系统性偏低——本机把同一帧的 ROI 从内缩 15px 逐步放大到 0px，误差单调变大：

```text
ROI 内缩 15px: 角点= 21 成功= 21 mean_flow=( 4.00,  1.00) 近似静止(<1px)的点=0
ROI 内缩 10px: 角点= 39 成功= 39 mean_flow=( 3.94,  0.90) 近似静止(<1px)的点=0
ROI 内缩  5px: 角点= 57 成功= 57 mean_flow=( 3.41,  0.82) 近似静止(<1px)的点=4
ROI 内缩  0px: 角点= 82 成功= 82 mean_flow=( 2.75,  0.62) 近似静止(<1px)的点=13   (真值 (4, 1))
```

原因是窗内混进了静止的背景/阴影像素（内缩 0px 时有 13 个点的位移小于 1px），把均值拉下来。工程结论：**用 LK 做目标位移估计时，ROI 要向内收缩若干像素，或者先按位移一致性做离群点剔除（例如取中位数、或按 IQR 截断），再取平均**。

耗时量级（640x360 单帧，20 次平均）：

```text
MOG2.apply:                    3.11 ms/帧
cvtColor + GaussianBlur:       0.13 ms/帧
calcOpticalFlowFarneback:     61.45 ms/帧
```

```text
要点：
- calcOpticalFlowPyrLK 的三件套是 prevImg/nextImg/prevPts，返回 nextPts + status + err
- status 逐点标记是否找到，必须先按 status 过滤再算统计
- 前后向校验（正着跟一遍、倒着跟一遍，来回距离 < 1px 才留）成本翻倍但能干掉大部分漂移点
- ROI 里混入静止背景会让位移均值系统性偏低：本机 4.00px 一路掉到 2.75px，13/82 个点近乎不动
- 目标尺寸没变但位移大（> 窗口一半）时开金字塔（maxLevel=3）或先降采样再跟踪
- Farneback 是稠密流，本机 61.45 ms/帧，实时场景要么降分辨率要么只在 ROI 上算
```

## 均值漂移与 CamShift

均值漂移（meanShift）与 CamShift 都是「用颜色直方图找局部峰值」的经典跟踪法：先在第一帧的目标框里算 HSV 的 H 通道直方图，`cv2.calcBackProject` 把当前帧变换成「属于目标的概率图」，再让搜索窗沿概率图爬到峰值。CamShift 额外让窗口尺寸自适应。它们的前提是**目标颜色分布与背景可分**——这一点比任何参数都重要，本机用一个红球与一个灰球做了对照实验：

```python
import cv2
import numpy as np

def run(path, tag):
    cap = cv2.VideoCapture(path)
    ok, f0 = cap.read()
    roi = f0[130:190, 90:150]                       # 首帧目标框
    hsv_roi = cv2.cvtColor(roi, cv2.COLOR_BGR2HSV)
    m = cv2.inRange(hsv_roi, np.array((0., 60., 60.)), np.array((180., 255., 255.)))
    hist = cv2.calcHist([hsv_roi], [0], m, [180], [0, 180])
    cv2.normalize(hist, hist, 0, 255, cv2.NORM_MINMAX)   # 归一化到 0-255 才和反向投影匹配
    term = (cv2.TERM_CRITERIA_EPS | cv2.TERM_CRITERIA_COUNT, 10, 1)
    win, errs, i = (90, 130, 60, 60), [], 0
    while True:
        ok, fr = cap.read()
        if not ok:
            break
        bp = cv2.calcBackProject([cv2.cvtColor(fr, cv2.COLOR_BGR2HSV)], [0], hist, [0, 180], 1)
        win = cv2.meanShift(bp, win, term)[1]
        gx, gy = 120 + 4 * i - 30, 160 + i - 30      # 合成视频里的真值左上角
        errs.append(np.hypot(win[0] - gx, win[1] - gy))
        i += 1
    cap.release()
    print(f"{tag}: 有效色度像素={int(m.sum()/255):4d} meanShift 平均误差={np.mean(errs):.2f}px 末帧窗口={win}")

run("/root/.hermes/cache/scratch/s78_ball_red.avi", "红球(色度可分)")
run("/root/.hermes/cache/scratch/s78_ball_gray.avi", "灰球(色度不可分)")
```

本机真实输出：

```text
红球(色度可分):   有效色度像素=2991 meanShift 平均误差=4.06px  末帧窗口=(566, 249, 60, 60)
灰球(色度不可分): 有效色度像素=   0 meanShift 平均误差=243.26px 末帧窗口=(90, 130, 60, 60)（始终没动）
噪声纹理块:       有效色度像素=2467 meanShift 平均误差=293.16px 末帧窗口=(53, 118, 60, 60)
```

灰球在 HSV 的 S 通道上无法与背景分开，`inRange` 得到 0 个像素，直方图退化成噪声，窗口就跟着背景纹理一路漂走。再换一个对照：目标颜色可分、但纹理是随机噪声块时，`calcBackProject` 的直方图同样没有判别力，meanShift 平均误差 293.16px，末帧窗口 (53, 118, 60, 60)；CamShift 在同一个输入上更糟——第一帧就选错峰值，末帧窗口膨胀到 (0, 0, 640, 360) 整幅画面，平均误差 389.63px（同一段视频换成红球时 CamShift 平均误差只有 8.59px、末帧窗口 (567, 252, 56, 55)，说明问题在可分性而不在算法本身）。这是 CamShift 最经典的失效形态：**窗口尺寸自适应放大了错误峰值的面积**。

```text
要点：
- 流程固定：首帧 ROI -> HSV -> inRange 掩膜 -> calcHist(H 通道) -> normalize -> calcBackProject -> meanShift/CamShift
- 掩膜 inRange 的 S/V 下限很重要（本机用 S>=60, V>=60）：低饱和/低亮度像素属于噪声，先剔掉
- 直方图必须 normalize(0, 255) 后再做反向投影，否则概率图的尺度不对，收敛行为会变
- 目标与背景色度不可分时算法必然漂走（本机灰球 243.26px 误差、有效色度像素 0）
- CamShift 的窗口自适应会把错误峰值放大成整幅画面（本机末帧窗口 640x360），工程上要加尺寸上限
- 输出是 (x, y, w, h) 窗口；要做目标 ID 跟踪仍需外接关联逻辑
```

## 内置跟踪器与跟踪框架

OpenCV 的跟踪器统一是 `init(frame, bbox)` + `update(frame) -> (ok, bbox)` 的接口，`bbox` 一律是 `(x, y, w, h)` 整数元组。算法家族分三类：经典相关滤波/在线学习（MIL、KCF、CSRT、MOSSE 等）、深度网络（DaSiamRPN、Nano、Vit、GOTURN，需要额外模型文件）。主仓 headless wheel 里本机实测只有 MIL/DaSiamRPN/Nano/Vit，KCF 与 CSRT 需要 `opencv-contrib-python`；`cv2.legacy.MultiTracker_create` 也在 contrib。

```python
import cv2
import numpy as np
import time

cap = cv2.VideoCapture("/root/.hermes/cache/scratch/s78_src.avi")
for algo in ("MIL", "KCF", "CSRT"):
    maker = getattr(cv2, f"Tracker{algo}_create", None)
    if maker is None:
        print(f"{algo}: 当前安装不可用（KCF/CSRT 需 opencv-contrib-python）")
        continue
    cap.set(cv2.CAP_PROP_POS_FRAMES, 0)
    ok, frame = cap.read()
    tr = maker()
    tr.init(frame, (100, 140, 60, 60))            # 首帧真值框，合成视频里每帧右移 4px、下移 1px
    ious, ok_cnt, t0 = [], 0, time.perf_counter()
    for i in range(1, 120):
        ok, frame = cap.read()
        if not ok:
            break
        success, box = tr.update(frame)
        if not success:
            continue
        ok_cnt += 1
        gx, gy, gw, gh = 100 + 4 * i, 140 + i, 60, 60
        bx, by, bw, bh = box
        ix = max(0, min(bx + bw, gx + gw) - max(bx, gx))
        iy = max(0, min(by + bh, gy + gh) - max(by, gy))
        inter = ix * iy
        ious.append(inter / float(bw * bh + gw * gh - inter))
    dt = time.perf_counter() - t0
    print(f"{algo}: update 成功 {ok_cnt}/119 平均 IoU={np.mean(ious):.4f} 最低 IoU={np.min(ious):.4f} "
          f"{dt*1000/119:.2f} ms/帧")
cap.release()
```

本机真实输出（640x360，纯 CPU）：

```text
MIL: update 成功 119/119 平均 IoU=0.9280 最低 IoU=0.8770 47.16 ms/帧
KCF: update 成功 119/119 平均 IoU=0.8480 最低 IoU=0.8480 20.60 ms/帧
CSRT: update 成功 119/119 平均 IoU=0.7680 最低 IoU=0.5768 30.20 ms/帧
```

IoU 高不代表算法强，而代表「目标和背景差异大」——本机是合成纹理块，没有遮挡、形变与出框，所以三个算法都能挂住。真实场景的选型依据是三点：速度（KCF 最快，本机 20.60 ms/帧）、遮挡恢复能力（CSRT/MIL 更稳但慢）、是否需要尺度自适应。深度跟踪器（Nano/Vit/DaSiamRPN/GOTURN）需要额外下载 ONNX/Caffe 模型，本机未验证其精度（模型文件未取到），选型请按官方文档与自己的数据实测。

## 多目标跟踪与越线计数

多目标跟踪（MOT）在 OpenCV 里没有一站式 API，实际做法都是「检测 + 关联」：每帧用检测器（背景建模、DNN、YOLO 等）得到若干框，再把本帧的框和上一帧的轨迹按 IoU/质心距离匹配（贪心或匈牙利算法），匹配上的继承 ID，匹配不上的开新 ID。越线计数在这个基础上多一步：比较同一 ID 前后两帧质心是否越过某条线的两侧。

```python
import cv2
import numpy as np

LINE_X, GATE_PX, MIN_AREA = 360, 60.0, 700      # 检测线、关联门限、最小面积
cap = cv2.VideoCapture("/root/.hermes/cache/scratch/s78_cross.avi")   # 两个目标相向而行
bs = cv2.createBackgroundSubtractorMOG2(history=120, varThreshold=25, detectShadows=False)
tracks, events, next_id, frame_i = {}, [], 0, 0
while True:
    ok, frame = cap.read()
    if not ok:
        break
    mask = cv2.morphologyEx(bs.apply(frame), cv2.MORPH_OPEN, np.ones((5, 5), np.uint8))
    cnts, _ = cv2.findContours(cv2.dilate(mask, np.ones((9, 9), np.uint8)),
                               cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_SIMPLE)
    dets = [tuple(float(v) for v in cv2.minEnclosingCircle(c)[0])
            for c in cnts if cv2.contourArea(c) >= MIN_AREA]        # 质心列表

    used, new_tracks = set(), {}
    for t_id, (px, py) in tracks.items():                          # 贪心最近邻关联
        best, best_d = None, GATE_PX
        for k, (cx, cy) in enumerate(dets):
            if k in used:
                continue
            d = float(np.hypot(cx - px, cy - py))
            if d < best_d:
                best, best_d = k, d
        if best is None:
            continue
        used.add(best)
        cx, cy = dets[best]
        if (px - LINE_X) * (cx - LINE_X) < 0:                      # 越线判定
            events.append((frame_i, t_id, "right" if cx > px else "left"))
        new_tracks[t_id] = (cx, cy)
    for k, (cx, cy) in enumerate(dets):
        if k not in used:
            new_tracks[next_id] = (cx, cy)
            next_id += 1
    tracks = new_tracks
    frame_i += 1
cap.release()
print("事件:", events)
print(f"右行={sum(1 for e in events if e[2]=='right')} 左行={sum(1 for e in events if e[2]=='left')} "
      f"分配 ID 数={next_id} (真值各 1 次、共 2 个目标)")
```

本机真实输出：

```text
事件: [(42, 3, 'right'), (47, 1, 'left')]
右行=1 左行=1 分配 ID 数=5 (真值各 1 次、共 2 个目标)
```

计数对了（各 1 次），但分配了 5 个 ID（真值 2 个）：检测在少数帧抖动导致旧轨迹断掉、新 ID 生成。同一段视频用「按连通域下标关联」（`prev[k]` 用列表下标 k 当 ID）测出的是 4 次事件（右行 2、左行 2）——**索引在目标数量/顺序变化时完全不可靠，必须按空间距离关联**：

```text
按连通域下标关联: 事件 [(1, '右行'), (8, '左行'), (42, '右行'), (47, '左行')] -> 右行=2 左行=2（真值各 1）
按最近质心关联（门限 60px）: 事件 [(42, 3, 'right'), (47, 1, 'left')] -> 右行=1 左行=1
```

生产上把关联换成「Kalman 预测 + 匈牙利算法」的 SORT 系列，并给轨迹加 `missed` 计数（连续 N 帧未关联才删），ID 抖动会明显减少；再往上就是 ByteTrack/OC-SORT 这类方法。`cv2.legacy.MultiTracker_create()`（contrib）能把多个单目标跟踪器拼在一起，适合目标数固定、无需跨帧身份管理的场景。

```text
要点：
- 检测到质心、质心连成轨迹、轨迹跨线计数——这是越线计数的最小闭环
- 关联必须按空间距离（或 IoU）做，按列表下标关联会虚增计数（本机 2 次 vs 真值 1 次）
- 关联门限要按目标帧间位移给：本机 7px/帧、帧率 30fps，60px 门限足够宽且不会串目标
- 轨迹要有「丢失保留 N 帧」机制，否则检测抖动会刷出一堆新 ID（本机 5 个 vs 真值 2 个）
- 检测器负责「哪里有人」，跟踪器负责「谁是谁」，越线逻辑只依赖轨迹 ID
- 生产用 Kalman + 匈牙利匹配（SORT/ByteTrack）；`cv2.legacy.MultiTracker` 适合目标数固定的场景
```

## 应用场景实战

### 场景一：仓库通道越线计数与告警

需求：固定机位对着通道口，统计每个方向进出人次并落盘事件，供 BI 看板与异常时段告警使用。这里用背景建模 + 质心关联 + 越线计数，事件按 JSONL 落盘（便于 Flink/Logstash 直接消费）。

```python
"""scenario_count.py —— 越线计数：背景建模 + 形态学 + 最近质心关联 + 越线判定 + JSONL 事件
依赖: opencv-python-headless>=5.0, numpy>=2.0
用法: python scenario_count.py            # 自带合成视频，可直接运行
"""
import json
import cv2
import numpy as np

VIDEO = "/root/.hermes/cache/scratch/s78_cross.avi"
EVENTS = "/root/.hermes/cache/scratch/s78_cross_events.jsonl"
LINE_X = 360          # 虚拟检测线的 x 坐标
GATE_PX = 60.0        # 质心关联门限，超过则视为新目标
MIN_AREA = 700        # 前景连通域最小面积，滤掉噪声与阴影碎片


def make_video(path=VIDEO, n=90, w=720, h=400):
    rng = np.random.default_rng(77)
    base = rng.integers(100, 160, (h, w, 3), dtype=np.uint8)
    for _ in range(150):
        cv2.circle(base, (int(rng.integers(0, w)), int(rng.integers(0, h))), 5, (70, 70, 70), -1)
    vw = cv2.VideoWriter(path, cv2.VideoWriter_fourcc(*"MJPG"), 30.0, (w, h))
    assert vw.isOpened(), "VideoWriter 打开失败：检查 fourcc 与文件后缀"
    for i in range(n):
        f = base.copy()
        xa, xb = 40 + 7 * i, w - 60 - 7 * i          # 左->右、右->左 两个目标
        cv2.rectangle(f, (xa, 90), (xa + 50, 140), (30, 220, 30), -1)
        cv2.rectangle(f, (xb, 260), (xb + 50, 310), (220, 30, 30), -1)
        vw.write(f)
    vw.release()
    return path


def count_crossings(path=VIDEO):
    cap = cv2.VideoCapture(path)
    if not cap.isOpened():
        raise SystemExit("打开视频失败")
    bs = cv2.createBackgroundSubtractorMOG2(history=120, varThreshold=25, detectShadows=False)
    tracks, events, next_id, frame_i = {}, [], 0, 0
    while True:
        ok, frame = cap.read()
        if not ok:
            break
        # 1) 前景掩膜：MOG2 更新背景模型，开运算去噪，膨胀把目标连成块
        mask = bs.apply(frame)
        mask = cv2.morphologyEx(mask, cv2.MORPH_OPEN, np.ones((5, 5), np.uint8))
        mask = cv2.dilate(mask, np.ones((9, 9), np.uint8))
        cnts, _ = cv2.findContours(mask, cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_SIMPLE)

        # 2) 连通域 -> 质心
        dets = []
        for c in cnts:
            if cv2.contourArea(c) < MIN_AREA:
                continue
            (cx, cy), _ = cv2.minEnclosingCircle(c)
            dets.append((float(cx), float(cy)))

        # 3) 最近质心关联（简化版 SORT：去掉 Kalman 与匈牙利匹配）
        used, new_tracks = set(), {}
        for t_id, (px, py) in tracks.items():
            best, best_d = None, GATE_PX
            for k, (cx, cy) in enumerate(dets):
                if k in used:
                    continue
                d = float(np.hypot(cx - px, cy - py))
                if d < best_d:
                    best, best_d = k, d
            if best is None:
                continue                      # 本帧未关联上，直接丢失（生产上应保留 N 帧）
            used.add(best)
            cx, cy = dets[best]
            # 4) 越线判定：前后两帧质心落在检测线两侧即为一次穿越
            if (px - LINE_X) * (cx - LINE_X) < 0:
                events.append({"frame": frame_i, "track_id": t_id,
                               "direction": "right" if cx > px else "left",
                               "x": round(cx, 1), "y": round(cy, 1)})
            new_tracks[t_id] = (cx, cy)
        for k, (cx, cy) in enumerate(dets):
            if k not in used:
                new_tracks[next_id] = (cx, cy)
                next_id += 1
        tracks = new_tracks
        frame_i += 1
    cap.release()

    with open(EVENTS, "w", encoding="utf-8") as fh:
        for ev in events:
            fh.write(json.dumps(ev, ensure_ascii=False) + "\n")
    return {"frames": frame_i, "ids": next_id, "events": events,
            "right": sum(1 for e in events if e["direction"] == "right"),
            "left": sum(1 for e in events if e["direction"] == "left")}


if __name__ == "__main__":
    print("生成合成视频:", make_video())
    rep = count_crossings()
    print(f"总帧数={rep['frames']} 分配 ID 数={rep['ids']}")
    print(f"越线事件 右行={rep['right']} 左行={rep['left']} (真值各 1 次)")
    for e in rep["events"]:
        print("  ", e)
    print("事件已落盘:", EVENTS)
```

```text
总帧数=90 分配 ID 数=5
越线事件 右行=1 左行=1 (真值各 1 次)
```

### 场景二：单目标跟踪 + 定期纠偏 + 轨迹落盘

需求：产线相机对某个工位目标做持续跟踪，需要输出逐帧轨迹（供机械臂随动）并在跟踪漂移时自动纠正。做法是单目标跟踪器维持高帧率，每 N 帧用背景建模做一次重定位纠偏；关键工程点是**重初始化要容错**——坏的 ROI 会让 MIL 直接抛异常。

```python
"""scenario_track.py —— 单目标跟踪 + 丢失恢复 + 轨迹落盘
依赖: opencv-contrib-python>=5.0（KCF/CSRT 需 contrib）, numpy>=2.0
用法: python scenario_track.py            # 自带合成视频，可直接运行
"""
import json
import cv2
import numpy as np

VIDEO = "/root/.hermes/cache/scratch/s78_cross.avi"
TRAJ = "/root/.hermes/cache/scratch/s78_track_traj_%s.jsonl"   # 按算法分文件，避免互相覆盖
INIT_BOX = (40, 90, 50, 50)      # 第 0 帧绿色目标的真实位置
REDETECT_EVERY = 15              # 每 N 帧用背景建模重新定位一次，纠偏（纠偏式跟踪）
BS_WARMUP = 25                   # 背景模型预热帧数：冷启动期输出整幅前景，不可用
MAX_BLOB_AREA_RATIO = 0.30       # 候选框面积超过画面 30% 视为背景未收敛，丢弃


def reinit_box(frame, bs, near):
    """用背景建模结果找一个离 near 最近的前景块，作为跟踪器失手后的重初始化框"""
    mask = cv2.morphologyEx(bs.apply(frame), cv2.MORPH_OPEN, np.ones((5, 5), np.uint8))
    mask = cv2.dilate(mask, np.ones((9, 9), np.uint8))
    cnts, _ = cv2.findContours(mask, cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_SIMPLE)
    frame_area = frame.shape[0] * frame.shape[1]
    best, best_d = None, 1e9
    for c in cnts:
        area = cv2.contourArea(c)
        if area < 700 or area > MAX_BLOB_AREA_RATIO * frame_area:   # 过小=噪声，过大=背景未收敛
            continue
        x, y, w, h = cv2.boundingRect(c)
        d = np.hypot(x + w / 2 - near[0], y + h / 2 - near[1])
        if d < best_d:
            best, best_d = (x, y, w, h), d
    return best


def track(path=VIDEO, algo="KCF"):
    maker = getattr(cv2, f"Tracker{algo}_create", None)
    if maker is None:
        return {"algo": algo, "error": "tracker_not_available(需要 opencv-contrib-python)"}
    cap = cv2.VideoCapture(path)
    ok, frame = cap.read()
    if not ok:
        return {"algo": algo, "error": "read_failed"}
    tr = maker()
    tr.init(frame, INIT_BOX)
    bs = cv2.createBackgroundSubtractorMOG2(history=120, varThreshold=25, detectShadows=False)
    box, traj, tracked, reinit = INIT_BOX, [], 0, 0
    frame_i = 0
    while True:
        ok, frame = cap.read()
        if not ok:
            break
        frame_i += 1
        success, box = tr.update(frame)
        if (not success) or frame_i % REDETECT_EVERY == 0:
            need = (not success) or frame_i >= BS_WARMUP        # 预热期内不做重初始化
            new = reinit_box(frame, bs, (box[0] + box[2] / 2, box[1] + box[3] / 2)) if need else None
            if new is not None:
                try:                                            # 重初始化必须容错：坏的 ROI 会让 MIL 抛错
                    tr = maker()
                    tr.init(frame, new)
                    box, reinit, success = new, reinit + 1, True
                except cv2.error:
                    pass
        if success:
            tracked += 1
        traj.append({"frame": frame_i, "x": round(float(box[0]), 1), "y": round(float(box[1]), 1),
                     "w": round(float(box[2]), 1), "h": round(float(box[3]), 1), "ok": bool(success)})
    cap.release()

    traj_path = TRAJ % algo
    with open(traj_path, "w", encoding="utf-8") as fh:
        for rec in traj:
            fh.write(json.dumps(rec) + "\n")

    # 与真值比较：合成视频里绿色目标左上角每帧右移 7px，只在预热后的有效帧上统计
    errs = [abs(r["x"] - (40 + 7 * r["frame"])) for r in traj if r["ok"] and r["frame"] >= BS_WARMUP]
    return {"algo": algo, "frames": frame_i, "tracked": tracked, "reinit": reinit,
            "mean_x_err_px": round(float(np.mean(errs)), 2), "max_x_err_px": round(float(max(errs)), 2),
            "traj_path": traj_path}


if __name__ == "__main__":
    print("cv2", cv2.__version__, "可用跟踪器:",
          [n for n in ("TrackerMIL_create", "TrackerKCF_create", "TrackerCSRT_create") if hasattr(cv2, n)])
    for algo in ("MIL", "KCF", "CSRT"):
```

## 最佳实践与踩坑记录

### 最佳实践

1. 写视频前断言 `vw.isOpened()`、写完后回读核对 `FRAME_COUNT`；本机 MJPG+avi 与 mp4v+mp4 都验证可用，H264 取决于系统编码器。
2. 背景建模必须留预热期：本机 MOG2(shadow) 第 10 帧才出现稳定前景，预热帧不做任何业务判断。
3. 阴影按任务处理：要质心定位就用 `detectShadows=False`（本机 p95 误差 5.88px vs True 的 18.88px），要区分人与影子才开 127。
4. 光流 ROI 向内收缩若干像素，或按位移一致性剔除离群点：本机同一目标的位移估计随 ROI 扩大从 4.00px 掉到 2.75px。
5. 跟踪器重初始化一律包 try/except 并校验候选框面积/长宽比，本机 MIL 在全幅 ROI 上会抛 `cv2.error`。
6. 多目标必须按空间距离或 IoU 关联并用「丢失保留 N 帧」，按列表下标关联在目标数变化时会虚增计数。
7. 性能先量后调：本机 640x360 上 MOG2 3.11 ms/帧、Farneback 61.45 ms/帧、MIL 47.16 ms/帧——先降分辨率再考虑换算法。

### 踩坑记录

```text
坑 1：把背景建模冷启动期的输出当检测结果，跟踪器直接崩或框膨胀
结论：脚本跑到第 15 帧抛 cv2.error（MIL）或框变成整幅画面（KCF/CSRT），排查半天以为是模型问题。
原因：MOG2 背景模型未收敛时会把整幅画面判成前景，本机 reinit 候选框是 (0, 0, 720, 400)；
      MIL 的 init 在整幅 ROI 上采样不到有效正样本，抛 "!posSamples.empty()"。
解法：预热帧数（本机 25 帧足够）+ 候选框面积上限校验（本机丢弃面积 > 画面 30% 的候选），
      并把 init 包在 try/except 里；实测加上这两条后 MIL/KCF/CSRT 都能稳定跟 89/89 帧，
      平均 x 误差分别 5.72/10.97/3.20px。

坑 2：CamShift 窗口越跑越大，最后吞掉整幅画面
结论：一开始以为是参数问题，反复调方差与 iterations 都没救。
原因：目标纹理/颜色与背景不可分时，反向投影图的峰值位置是错的，CamShift 的尺寸自适应
      进一步把错误峰值放大。本机噪声纹理目标上：meanShift 平均误差 293.16px，
      CamShift 平均误差 389.63px，末帧窗口膨胀到 (0, 0, 640, 360)。
解法：先量目标的可分性——本机红球在 HSV 上有效色度像素 2991、meanShift 平均误差 4.06px，
      灰球有效色度像素 0、平均误差 243.26px。不可分就换算法（KCF/CSRT 跟踪灰球完全没问题）；
      必须用 CamShift 时给窗口尺寸设上下限并加「面积突变即视为丢失」的守卫。

坑 3：光流位移估计系统性偏低，以为是算法精度不够
结论：目标真实每帧右移 4px，LK 给出的均值只有 2.75px，反复调 winSize/maxLevel 都没改善。
原因：ROI 里混进了静止的背景与阴影像素（本机 82 个角点里有 13 个位移小于 1px），均值被拉低。
解法：ROI 向内收缩（本机内缩 15px 后均值正好 4.00px、1.00px），或先算位移一致性再做
      离群点剔除（取中位数/截断），并固定用 status==1 与前后向校验（本机前向-反向 <1px
      可把 82 个点筛到 67 个）。

坑 4：按连通域下标关联目标，越线计数直接翻倍
结论：同一段视频，按下标关联测出 4 次事件（右行 2、左行 2），真值是各 1 次。
原因：连通域的返回顺序不保证稳定，目标数量变化或检测抖动时 k 会指向另一个目标，
      前后两帧的「同一个 ID」其实是不同物体，自然产生虚假穿越。
解法：改成最近质心关联（本机门限 60px）后事件变成 2 次、方向正确；再补上「丢失保留 N 帧」
      与 Kalman 预测（SORT 思路），本机分配 ID 数从 5 个向真值 2 个收敛。

坑 5：VideoWriter 静默丢帧，导出的视频“能播但少帧”
结论：输出的 avi 能播放，但抽帧对齐时发现帧数与预期不符，且中间有跳帧。
原因：fourcc 与容器不匹配或尺寸不是编码器支持的对齐尺寸时，write() 不抛异常但会丢帧。
解法：写出前 assert vw.isOpened()，写出后立刻用 VideoCapture 回读核对
      CAP_PROP_FRAME_COUNT（本机 MJPG 写 120 帧、回读 120 帧；mp4v 写 10 帧、回读 10 帧），
      并把回读校验放进流水线的自检步骤。

坑 6：detectShadows=True 之后质心误差变大，误以为算法变差
结论：同一段视频，MOG2 开阴影检测后质心误差 p95 从 5.88px 涨到 18.88px、前景像素从 6130 掉到 2879。
原因：被判定为阴影的像素（值 127）在你的阈值化逻辑里被当成背景丢掉了，目标的一部分被切掉，
      质心自然偏移；反过来如果按 >0 阈值把 127 当前景，阴影又会把质心往影子方向拉。
解法：显式决定 127 的归属——要定位就用 detectShadows=False（本机 p95 5.88px），
      要区分阴影就保留 127 并在业务层单独处理（例如只在人形区域内统计）。
```

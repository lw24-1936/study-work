## 概述

这一篇把前面几篇的能力拼成能做交付的东西：文档扫描与矫正（轮廓 + 透视 + 二值化，把拍歪的纸变成可 OCR 的正图）、车道线检测（ROI + Canny + Hough + 曲线拟合，ADAS 感知的入门链路）、人脸与人体检测（Haar/YuNet/HOG，找出人形所在区域）、二维码与条码识别（QRCodeDetector 与 BarcodeDetector，识别到业务 ID）、运动检测与越线计数（背景建模 + 关联 + 计数）。每个链路都给出可运行代码与本机实测数据，并把「参数在什么条件下失效」标出来。

```text
本篇主线：
1. 文档扫描 —— 自适应阈值分割 -> 最大轮廓 -> 四点 -> 透视矫正 -> 自适应二值化 + 小连通域清理
2. 车道线 —— ROI 掩膜 -> Canny -> HoughLinesP -> 按斜率分组 -> polyfit 拟合 -> 曲率换算
3. 人脸/人体 —— Haar cascade 与 HOG 在 OpenCV 5 已移到 contrib；YuNet（DNN）在主仓即可用
4. 二维码/条码 —— QRCodeDetector(+Encoder) 与 cv2.barcode.BarcodeDetector，含 EAN-13 自造码验证
5. 运动计数 —— MOG2 前景 -> 连通域质心 -> 最近质心关联 -> 越线判定 -> 计数与事件落盘
6. 质量门控 —— 每个链路的验收指标（角点误差、内点率、拟合误差、置信度、ID 稳定性）
```

## 文档扫描与矫正

链路是固定的五步：灰度化与光照归一化、二值化分割纸张、取最大轮廓并用 `approxPolyDP` 压成四点、按顺序排列四点后 `warpPerspective` 拉正、对拉正后的图做二值化与噪点清理。最容易被忽略的是第二步——**在光照不均的条件下，全局 Otsu 阈值会把暗侧的纸判成背景**，本机实测纸张灰度随 x 从 116（暗侧）变到 255（亮侧），一个全局阈值无法同时覆盖。

```python
import cv2
import numpy as np

img = cv2.imread("/root/.hermes/cache/scratch/s79p_input.png")     # 桌面上的单据，左暗右亮
gray = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)
thr, otsu = cv2.threshold(cv2.GaussianBlur(gray, (5, 5), 0), 0, 255, cv2.THRESH_BINARY + cv2.THRESH_OTSU)
adapt = cv2.adaptiveThreshold(gray, 255, cv2.ADAPTIVE_THRESH_MEAN_C, cv2.THRESH_BINARY, 51, -10)
print(f"全局 Otsu 阈值 = {thr:.1f}")

def largest_quad(binary):
    b = cv2.morphologyEx(binary, cv2.MORPH_CLOSE, np.ones((9, 9), np.uint8))   # 闭运算补断边
    cnts, _ = cv2.findContours(b, cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_SIMPLE)
    cnt = max(cnts, key=cv2.contourArea)
    peri = cv2.arcLength(cnt, True)
    for eps in (0.02, 0.03, 0.05, 0.08):        # eps 逐级放宽，直到压出 4 个顶点
        approx = cv2.approxPolyDP(cnt, eps * peri, True)
        if len(approx) == 4:
            return approx.reshape(-1, 2), eps
    return None, None

quad_otsu, _ = largest_quad(otsu)
quad_adapt, eps_adapt = largest_quad(adapt)
print("Otsu  二值图给出的四角:", "失败" if quad_otsu is None else quad_otsu.tolist())
print("自适应二值图给出的四角:", "失败" if quad_adapt is None else f"{quad_adapt.tolist()} (eps={eps_adapt})")

def order_points(pts):
    pts = np.float32(pts).reshape(-1, 2)
    ysort = pts[np.argsort(pts[:, 1])]                 # 上两点 / 下两点
    top = ysort[:2][np.argsort(ysort[:2, 0])]          # 再各自按 x 排 -> 左上、右上
    bot = ysort[2:][np.argsort(ysort[2:, 0])]          # -> 左下、右下
    return np.float32([top[0], top[1], bot[1], bot[0]])
```

本机真实输出：

```text
纸张灰度随 x 变化: x=100 处 116, x=400 处 29（文字行）, x=700 处 255
Otsu  二值图给出的四角: [[760, 45], [174, 70], [174, 545], [800, 560]]
自适应二值图给出的四角: [[760, 45], [130, 70], [95, 545], [800, 560]] (eps=0.02)
```

换成更极端的梯度（0.35 到 1.35 倍）后，三种分割方案的角点误差差距更大——这是选择分割策略的直接依据：

```text
直接 Otsu:             四角 [[690, 40], [158, 60], [158, 500], [720, 520]]  最大角误差 78.00px
divide 归一化 + Otsu:  四角退化成整幅画面 [[0, 0], [0, 599], [799, 599], [799, 0]]  最大角误差 127.28px
自适应阈值(51x51,-10): 四角 [[690, 40], [110, 60], [80, 500], [720, 520]]  最大角误差 0.00px
```

（`divide` 归一化在这里失效是因为它把「桌面-纸张」的整体亮度差也一起抹平了，纸与桌面的边界反而消失；它不是坏方法，而是要用在「同一物体内部光照不均」的场合。）

拉正之后还要再做一次自适应二值化，并用连通域面积把残留噪点抹掉。本机在一张受控合成页（`s79_doc_input.png`，800x600、梯度 0.35→1.35、文字行围绕中线对称）上先拉正到 620x877，再统计中部正文行的墨迹像素在左右半图的分布（理想左右比应接近 1）：

```text
Otsu 二值图 + close(9x9) 后的四角数: 4
检出四角: [[161, 60], [690, 40], [720, 520], [161, 500]]
四角误差(px): [51.0, 0.0, 0.0, 81.0] 最大: 81.0
Otsu 全局阈值:      左半=38219 右半=27389 左右比=1.40
adaptiveThreshold:  左半=35220 右半=28136 左右比=1.25
拉正尺寸: (620, 877)
```

两件事同时可见：这种光照梯度下用全局 Otsu 找边界，左边被切掉最多 81px；而做完拉正后再二值化，全局 Otsu 的墨迹左右比是 1.40、自适应阈值是 1.25——自适应阈值把暗侧的墨迹更完整地保留了下来。完整的拉正代码：

```python
import cv2
import numpy as np

def rectify(img, quad):
    tl, tr, br, bl = order_points(quad)
    w = int(max(np.linalg.norm(tr - tl), np.linalg.norm(br - bl)))   # 输出尺寸按实际边长推算
    h = int(max(np.linalg.norm(bl - tl), np.linalg.norm(br - tr)))
    dst = np.float32([[0, 0], [w - 1, 0], [w - 1, h - 1], [0, h - 1]])
    M = cv2.getPerspectiveTransform(quad.astype(np.float32), dst)
    return cv2.warpPerspective(img, M, (w, h)), (w, h)

warp, size = rectify(img, quad_adapt)
gray_w = cv2.cvtColor(warp, cv2.COLOR_BGR2GRAY)
bw = cv2.adaptiveThreshold(gray_w, 255, cv2.ADAPTIVE_THRESH_GAUSSIAN_C, cv2.THRESH_BINARY, 31, 10)
inv = cv2.bitwise_not(bw)
n, lab, stats, _ = cv2.connectedComponentsWithStats(inv, 8)          # 去掉面积 < 12 的前景碎块
clean = np.zeros_like(inv)
for i in range(1, n):
    if stats[i, cv2.CC_STAT_AREA] >= 12:
        clean[lab == i] = 255
binary = cv2.bitwise_not(clean)
print(f"拉正尺寸={size} 长宽比={max(size)/min(size):.3f} 墨迹占比={(binary == 0).mean():.4f}")
```

本机真实输出：

```text
拉正尺寸=(705, 516) 长宽比=1.366 墨迹占比=0.2077
```

```text
要点：
- 分割纸张用 adaptiveThreshold(gray, 255, ADAPTIVE_THRESH_MEAN_C, THRESH_BINARY, 51, -10)，
  本机在强光照梯度下角点误差 0.00px，而全局 Otsu 误差 78px（整条左边被切掉）
- 二值化后先形态学 MORPH_CLOSE(9x9) 补断边，否则轮廓可能不是闭合四边形，approxPolyDP 压不出 4 个点
- approxPolyDP 的 eps 用 relative 形式（eps*peri）并逐级放宽 0.02->0.03->0.05->0.08，保证能收敛到 4 顶点
- 四点定序不要用 sum/diff 法（强透视下会错配），改用「按 y 排序取上下各两点，再按 x 排序」
- 输出尺寸按四边形的实际边长算（本机 705x516），别硬编码 A4 像素尺寸，否则内容会被拉伸
- 拉正后再做一次自适应二值化并清掉小连通域（本机阈值面积 12），OCR 的前置质量能明显改善
```

## 车道线检测

经典车道线链路的四步：感兴趣区域（ROI）梯形掩膜、Canny 边缘、HoughLinesP 直线段、按斜率分组后拟合（一次或二次）成左右车道线。ROI 是第一道也是性价比最高的过滤——本机 1591 个边缘像素里，ROI 内只保留 1490 个，但把天空、护栏、对面车道的干扰全挡在外面。

```python
import cv2
import numpy as np

img = cv2.imread("/root/.hermes/cache/scratch/s79_lane_input.png")   # 960x540 合成路面
gray = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)
edges = cv2.Canny(gray, 60, 180)
roi = np.zeros_like(edges)
cv2.fillPoly(roi, [np.array([[0, 540], [960, 540], [600, 300], [400, 300]])], 255)   # 梯形 ROI
masked = cv2.bitwise_and(edges, roi)
print("Canny 边缘像素:", int(cv2.countNonZero(edges)), " ROI 内:", int(cv2.countNonZero(masked)))

lines = cv2.HoughLinesP(masked, 1, np.pi / 180, threshold=60, minLineLength=60, maxLineGap=80)
print("HoughLinesP 返回形状:", np.asarray(lines).shape)              # OpenCV 5：Nx4；4.x 是 Nx1x4
print("HoughLinesP 线段:", np.asarray(lines).reshape(-1, 4).tolist())
groups = {"left": [], "right": []}
for x1, y1, x2, y2 in np.asarray(lines).reshape(-1, 4):
    (groups["left"] if (x1 + x2) / 2 < 480 else groups["right"]).extend([(x1, y1), (x2, y2)])
for tag, pts in groups.items():
    ys = np.array([p[1] for p in pts], float)
    xs = np.array([p[0] for p in pts], float)
    for deg in (1, 2):                                               # 直道用 1 次，弯道用 2 次
        co = np.polyfit(ys, xs, deg)
        print(f"{tag}车道 deg={deg}: 点数={len(pts)} y=540 时 x={np.polyval(co, 540):.1f} "
              f"y=300 时 x={np.polyval(co, 300):.1f}")
```

left车道 deg=1: 点数=6 y=540 时 x=302.6 y=300 时 x=458.5

曲率半径按二次拟合系数（x = A·y² + B·y + C）用标准公式换算：

```python
import numpy as np

A, B, C = 6.022370e-04, 0.1262, 413.0      # 右车道二次拟合系数（本机实测）
R_px = ((1 + (2 * A * 540 + B) ** 2) ** 1.5) / abs(2 * A)
print(f"像素曲率半径 R={R_px:.1f}px")
print(f"按 3.7m 车道宽 / 340px 换算: {R_px * 3.7 / 340:.1f}m")
```

本机真实输出：

```text
像素曲率半径 R=1685.1px
按 3.7m 车道宽 / 340px 换算: 18.3m
```

这个换算只能说明量级：真实系统必须用相机内参、俯仰角与地面标定把像素映射到米，且要按官方文档/实车标定确认公式与系数（本机是合成图，未做真实标定）。另外注意 OpenCV 5 的 `HoughLinesP` 直接返回 `Nx4` 数组，4.x 是 `Nx1x4`，跨版本迁移时 `np.asarray(lines).reshape(-1, 4)` 一行就能兼容两种形状。

```text
要点：
- ROI 掩膜是第一步：本机把 1591 个边缘像素收敛到 1490，同时排除非路面区域的干扰线
- Canny 阈值（本机 60/180）+ 先高斯平滑；Hough 的 threshold/minLineLength/maxLineGap 要按车道线宽度调
- OpenCV 5 的 HoughLinesP 返回 Nx4（4.x 为 Nx1x4），用 reshape(-1, 4) 兼容
- 按线段中点或斜率分组左右车道，再 polyfit 拟合；直线段少的时候 1 次拟合更稳
- 拟合精度与点数强相关：本机 6 个点、2 次拟合的底部误差 1.6px（左）/3.2px（右），1 次拟合是 2.6px/4.3px
- 曲率半径像素值到米必须靠相机标定（本机 1685.1px 按车道宽换算约 18.3m，仅供量级参考）
```

## 人脸与人体检测

三条可选路线，选型取决于安装方式与精度要求：

| 方案 | 依赖 | 本机 lena.jpg (512x512) 结果 | 耗时 | 输出 |
|---|---|---|---|---|
| Haar `cv2.CascadeClassifier` | opencv-contrib + XML 文件 | 1 张脸 `[219, 203, 169, 169]` | 首次调用 510.8ms（另一轮实测 1962.2ms），同参数第二次 30.9ms | 矩形框 |
| DNN `cv2.FaceDetectorYN` | 主仓 + ONNX 模型 | 1 张脸 `[207.8, 182.5, 145.9, 206.9]`，置信度 0.9090 | 171.5ms（另一轮 534.5ms） | 框 + 5 个关键点 |
| HOG 行人 `cv2.HOGDescriptor` | opencv-contrib（行人模板内建） | vtest.avi 前 40 帧平均 3.10 人/帧、最多 5 | 73-86 ms/帧 | 人形框 |

```python
import cv2
import time

img = cv2.imread("/root/.hermes/cache/scratch/lena.jpg")     # 512x512 标准测试图
# Haar：需要 XML 分类器文件（本机从 opencv 4.x data 目录取的 haarcascade_frontalface_default.xml）
fc = cv2.CascadeClassifier("/root/.hermes/cache/scratch/hc_face.xml")
print("cascade 加载成功:", not fc.empty())
for scale, neighbors in [(1.1, 5), (1.1, 3), (1.3, 5)]:
    t0 = time.perf_counter()
    faces = fc.detectMultiScale(cv2.cvtColor(img, cv2.COLOR_BGR2GRAY), scaleFactor=scale,
                                minNeighbors=neighbors, minSize=(40, 40))
    print(f"detectMultiScale(scaleFactor={scale}, minNeighbors={neighbors}): 人脸数={len(faces)} "
          f"box={faces.tolist()} 耗时={(time.perf_counter()-t0)*1000:.1f}ms")

# YuNet：主仓自带 API，需要 ONNX 模型（本机用 face_detection_yunet_2023mar.onnx）
yd = cv2.FaceDetectorYN.create("/root/.hermes/cache/scratch/yunet.onnx", "",
                              (img.shape[1], img.shape[0]), 0.9, 0.3, 5000)
t0 = time.perf_counter()
n, faces = yd.detect(img)
print(f"YuNet 人脸数={n} 耗时={(time.perf_counter()-t0)*1000:.1f}ms")
for f in faces:
    print(f"  bbox={f[:4].round(1).tolist()} 置信度={f[14]:.4f} 右眼={f[4:6].round(1).tolist()} 鼻={f[8:10].round(1).tolist()}")

# HOG 行人：模板内建，无需模型文件
hog = cv2.HOGDescriptor()
hog.setSVMDetector(cv2.HOGDescriptor_getDefaultPeopleDetector())
cap = cv2.VideoCapture("/root/.hermes/cache/scratch/vtest.avi")
print("vtest.avi:", cap.isOpened(), int(cap.get(cv2.CAP_PROP_FRAME_COUNT)), "帧",
      cap.get(cv2.CAP_PROP_FPS), "fps", int(cap.get(cv2.CAP_PROP_FRAME_WIDTH)), "x",
      int(cap.get(cv2.CAP_PROP_FRAME_HEIGHT)))
counts, t0, nfr = [], time.perf_counter(), 0
while nfr < 40:
    ok, frame = cap.read()
    if not ok:
        break
    rects, weights = hog.detectMultiScale(frame, winStride=(8, 8), padding=(8, 8), scale=1.05)
    counts.append(len(rects))
    nfr += 1
cap.release()
print(f"HOG 前 {nfr} 帧: 平均人数={sum(counts)/len(counts):.2f} 最多={max(counts)} "
      f"{(time.perf_counter()-t0)/nfr*1000:.0f} ms/帧")
```

三个数字值得记住：Haar 首次调用含模型预热开销（本机两轮实测分别是 510.8ms 与 1962.2ms，波动来自系统缓存与负载；同一参数第二次只要 30.9ms），把它算进吞吐会得出完全错误的服务容量；YuNet 在主仓就能用、还额外给出 5 个关键点与置信度，代价是要下载 ONNX 模型；HOG 是行人检测的传统方案，本机 73-86 ms/帧只能算「能跑」级别，人数统计还需要自己加多帧去重（同一行人连续帧会被重复检出）。

```text
要点：
- OpenCV 5 里 CascadeClassifier 与 HOGDescriptor 都在 contrib（xobjdetect），主仓 headless 包没有
- 即使装了 contrib，pip wheel 的 cv2.data.haarcascades 目录里也没有 XML（本机 0 个文件），要自己准备
- Haar 首次 detectMultiScale 有预热开销（本机两轮 510.8ms / 1962.2ms，同参数第二次 30.9ms），压测前必须先预热一次
- scaleFactor 越小越慢越细（本机 1.1 vs 1.3：30.9ms vs 13.0ms，检测框略有差别），minNeighbors 控误检
- 新项目优先 YuNet（主仓可用、有置信度与关键点），HOG 适合没有模型文件但要测行人的场景
- HOG 的人数统计要自己加跨帧去重（本机单帧最多 5 人，实际画面远少于 5 人）
```

## 二维码与条码识别

二维码识别是 `cv2.QRCodeDetector`（主仓即可），检测与解码一体：`detectAndDecode` 单码、`detectAndDecodeMulti` 多码；生成二维码用 `cv2.QRCodeEncoder_create().encode(text)`，但它输出的是**每模块 1 像素**的裸矩阵，直接送去识别会解码出空串（不抛异常）。条码用 `cv2.barcode.BarcodeDetector`，支持 EAN-8/EAN-13/UPC-A/UPC-E 等，**OpenCV 自带的生成器不包含条码**，本机的 EAN-13 是按规范手写编码表生成的。

```python
import cv2
import numpy as np

# 二维码：生成 -> 按倍数放大 + 留静区 -> 解码
qr = cv2.QRCodeEncoder_create().encode("https://opencv.org/opencv-5/")
print("QRCodeEncoder.encode 输出 shape:", qr.shape, " dtype:", qr.dtype)
det = cv2.QRCodeDetector()
for scale, quiet in [(1, 40), (4, 4), (8, 4), (10, 4)]:
    big = cv2.resize(qr, None, fx=scale, fy=scale, interpolation=cv2.INTER_NEAREST)
    canvas = np.full((big.shape[0] + 2 * quiet * scale, big.shape[1] + 2 * quiet * scale), 255, np.uint8)
    canvas[quiet * scale:quiet * scale + big.shape[0], quiet * scale:quiet * scale + big.shape[1]] = big
    data, pts, _ = det.detectAndDecode(canvas)
    print(f"放大 {scale}x + 静区 {quiet} 模块 (图 {canvas.shape[1]}x{canvas.shape[0]}): 解码={data!r}")
```

条码侧用自造的 EAN-13 验证：13 位（12 位数据 + 1 位校验）编码成 95 个模块，模块宽与条高对识别率的影响在本机非常极端——只有「模块宽 2px 且条高 ≥ 110px」能识别，1px 太细、≥3px 又识别不出来：

```python
# EAN-13 校验位与编码表（完整表见脚本 scenario_inventory_codes.py）
L = {"0": "0001101", "1": "0011001", "2": "0010011", "3": "0111101", "4": "0100011", "5": "0110001",
     "6": "0101111", "7": "0111011", "8": "0110111", "9": "0001011"}   # 左奇校验
G = {"0": "0100111", "1": "0110011", "2": "0011011", "3": "0100001", "4": "0011101", "5": "0111001",
     "6": "0000101", "7": "0010001", "8": "0001001", "9": "0010111"}   # 左偶校验
R = {"0": "1110010", "1": "1100110", "2": "1101100", "3": "1000010", "4": "1011100", "5": "1001110",
     "6": "1010000", "7": "1000100", "8": "1001000", "9": "1110100"}   # 右码
PAR = {"0": "LLLLLL", "1": "LLGLGG", "2": "LLGGLG", "3": "LLGGGL", "4": "LGLLGG", "5": "LGGLLG",
       "6": "LGGGLL", "7": "LGLGLG", "8": "LGLGGL", "9": "LGGLGL"}     # 首位决定左右奇偶型

def ean13(d12: str):
    s = sum(int(d12[i]) * (1 if i % 2 == 0 else 3) for i in range(12))    # 奇数位 x1，偶数位 x3
    dg = d12 + str((10 - s % 10) % 10)
    par = PAR[dg[0]]
    bits = "101" + "".join((L if par[i] == "L" else G)[d] for i, d in enumerate(dg[1:7])) + "01010"
    bits += "".join(R[d] for d in dg[7:]) + "101"                          # 95 个模块
    return dg, bits

code, bits = ean13("400638133393")
print("EAN-13:", code, "模块数:", len(bits))
bd = cv2.barcode.BarcodeDetector()
for barh in (60, 110, 200):
    row = []
    for mod in (1, 2, 3, 4, 5, 6):
        pw = (len(bits) + 18) * mod                                        # 左右各留 9 模块静区
        img = np.full((barh + 60, pw), 255, np.uint8)
        for i, b in enumerate(bits):
            if b == "1":
                img[20:20 + barh, (9 + i) * mod:(9 + i) * mod + mod] = 0
        ok = bd.detectAndDecodeWithType(img)[0]
        row.append(f"{mod}px:{'OK' if ok else 'fail'}")
    print(f"条高={barh}px -> " + "  ".join(row))
```

条高=60px  -> 1px:fail  2px:fail  3px:fail  4px:fail  5px:fail  6px:fail
条高=110px -> 1px:fail  2px:OK    3px:fail  4px:fail  5px:fail  6px:fail

`Content` 的正确性也从 `detectAndDecodeWithType` 的返回值验证过：`('4006381333931',)` + `('EAN_13',)`，说明编码本身没错——**失败来自解码器对模块宽/图像尺寸比例的敏感性**。生产上不要凭直觉设模块宽，要用真实相机在真实工作距离下扫一遍（本机这组合成图只能说明「存在敏感的甜点区」）。

```text
要点：
- QRCodeEncoder 输出 (29, 29) 的 1px/模块矩阵，必须 resize(INTER_NEAREST) 放大后再检测，本机 1x 解码为空串、4x 起成功
- 静区（quiet zone）不能省：本机用 4 个模块宽的白边即可稳定解码
- QRCodeDetector 有 detectAndDecode（单码）与 detectAndDecodeMulti（多码，返回 retval/decoded_info/points）
- 条码用 cv2.barcode.BarcodeDetector().detectAndDecodeWithType，返回 (retval, info, types, points)
- OpenCV 没有条码生成器：EAN-13 要自己按编码表生成（首位决定 L/G 奇偶型，第 13 位是模 10 校验位）
- 合成条码的识别对模块宽极敏感（本机只有 2px 成功），必须用真实相机实测后再定生成参数
```

## 运动检测与越线计数

运动检测到计数的最小闭环是：背景建模得到前景掩膜、形态学去噪、连通域取质心、跨帧把质心连成轨迹、判断轨迹是否越过设定的检测线。前面每一步的取舍在 17.8 有详细实测，这里只强调**关联方式决定计数正确性**——本机同一段 90 帧视频（两个目标相向而行、各穿越检测线一次）：

```text
按连通域下标关联:              事件 [(1, '右行'), (8, '左行'), (42, '右行'), (47, '左行')] -> 右行=2 左行=2
按最近质心关联（门限 60px）:   事件 [(42, right), (47, left)] -> 右行=1 左行=1
真值:                          右行=1 左行=1（2 个目标各穿越一次）
```

按下标关联会在目标数量/顺序发生变化时把「不同目标的相邻帧」当成同一轨迹，凭空产生穿越事件（多计了一倍）。另外本机实测：即使关联正确，简化实现仍会分配 5 个 ID（真值 2 个），因为检测抖动会让旧轨迹断掉；把「丢失保留 N 帧」加上也只是在本机这一组数据里没有完全消掉，生产上要换成 Kalman 预测 + 匈牙利匹配的 SORT 系列。

```python
import cv2
import numpy as np

cap = cv2.VideoCapture("/root/.hermes/cache/scratch/s79_cross.avi")     # 720x400、90 帧
bs = cv2.createBackgroundSubtractorMOG2(history=120, varThreshold=25, detectShadows=False)
LINE, GATE, MIN_AREA = 360, 60.0, 700
tracks, events, next_id, i = {}, [], 0, 0
while True:
    ok, frame = cap.read()
    if not ok:
        break
    mask = cv2.morphologyEx(bs.apply(frame), cv2.MORPH_OPEN, np.ones((5, 5), np.uint8))
    cnts, _ = cv2.findContours(cv2.dilate(mask, np.ones((9, 9), np.uint8)),
                               cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_SIMPLE)
    dets = [tuple(float(v) for v in cv2.minEnclosingCircle(c)[0])
            for c in cnts if cv2.contourArea(c) >= MIN_AREA]
    used, new = set(), {}
    for tid, (px, py) in tracks.items():                # 最近质心关联（门限 60px）
        best, bd = None, GATE
        for k, (cx, cy) in enumerate(dets):
            if k in used:
                continue
            d = float(np.hypot(cx - px, cy - py))
            if d < bd:
                best, bd = k, d
        if best is None:
            continue
        used.add(best)
        cx, cy = dets[best]
        if (px - LINE) * (cx - LINE) < 0:               # 跨线即计一次
            events.append((i, tid, "right" if cx > px else "left"))
        new[tid] = (cx, cy)
    for k, (cx, cy) in enumerate(dets):
        if k not in used:
            new[next_id] = (cx, cy)
            next_id += 1
    tracks = new
    i += 1
cap.release()
print("事件:", events)
print(f"右行={sum(1 for e in events if e[2]=='right')} 左行={sum(1 for e in events if e[2]=='left')} 分配 ID 数={next_id}")
```

本机真实输出：

```text
事件: [(42, 3, 'right'), (47, 1, 'left')]
右行=1 左行=1 分配 ID 数=5
```

```text
要点：
- 前景掩膜（MOG2）-> 开运算去噪 -> 膨胀成块 -> 连通域质心，这是最省的可运行链路
- 关联必须按空间距离（或 IoU + 匈牙利），按下标关联本机把计数从 1 变成 2（翻倍）
- 越线判定用 (prev - LINE) * (curr - LINE) < 0，天然给出方向（左右），不需要额外逻辑
- 检测抖动会刷出新 ID（本机 5 个 vs 真值 2 个），需要「丢失保留 N 帧」+ Kalman 预测
- 背景模型预热期的输出不能用于初始化（17.8 有 MIL 抛错的实测），计数前先跑 N 帧暖机
- 计数事件落盘（JSONL/DB）比只打日志重要：计数逻辑改动后要能用历史数据回归验证
```

## 应用场景实战

### 场景一：单据扫描归档流水线（带质量门控）

需求：扫描/拍照上传的单据自动拉正、二值化并归档；版面不规整、光照异常、空白页必须在入库前拦下转人工。脚本自带合成素材，可直接运行。

```python
"""scenario_scan_pipeline.py —— 单据扫描归档流水线
依赖: opencv-python-headless>=5.0, numpy>=2.0
"""
import json
import os
import cv2
import numpy as np

OUT = "/root/.hermes/cache/scratch"
SRC = f"{OUT}/s79p_input.png"
OUT_IMG = f"{OUT}/s79p_warp.png"
OUT_BIN = f"{OUT}/s79p_bin.png"
OUT_META = f"{OUT}/s79p_meta.json"

W, H = 900, 640
GT_CORNERS = np.float32([[130, 70], [760, 45], [800, 560], [95, 545]])
MIN_AREA_RATIO = 0.10        # 纸张面积至少要占整幅的 10%
ASPECT_RANGE = (1.25, 1.62)  # A4 长宽比 1.414 附近，留拍摄变形余量
MIN_POLY_AREA_RATIO = 0.85   # 四点多边形面积 / 凸包面积，判断四边形拟合质量


def make_input():
    """造一张“桌面上的单据”：深色桌面 + 白纸 + 光照梯度（左侧暗右侧亮）"""
    rng = np.random.default_rng(5)
    desk = rng.integers(40, 90, (H, W, 3), dtype=np.uint8)
    for _ in range(400):
        cv2.circle(desk, (int(rng.integers(0, W)), int(rng.integers(0, H))), int(rng.integers(3, 14)), (30, 30, 30), -1)
    paper = np.full((H, W, 3), 245, np.uint8)
    for i in range(28):                              # 文字行（围绕中线对称）
        y = 120 + i * 15
        ln = int(rng.integers(300, 620))
        cv2.line(paper, (450 - ln // 2, y), (450 + ln // 2, y), (35, 35, 35), 3)
    cv2.putText(paper, "INVOICE 2026-10", (270, 90), cv2.FONT_HERSHEY_SIMPLEX, 1.2, (20, 20, 20), 3)
    mask = np.zeros((H, W), np.uint8)
    cv2.fillPoly(mask, [GT_CORNERS.astype(np.int32)], 255)
    img = np.where(mask[..., None] > 0, paper, desk)
    grad = np.linspace(0.35, 1.35, W)[None, :, None]  # 光照梯度：左侧暗右侧亮
    img = np.clip(img.astype(np.float32) * grad, 0, 255).astype(np.uint8)
    cv2.imwrite(SRC, img)
    return img


def order_points(pts):
    """按 y 排序取上两点、下两点，再各自按 x 排序——比 sum/diff 法在强透视下更稳"""
    pts = np.float32(pts).reshape(-1, 2)
    ysort = pts[np.argsort(pts[:, 1])]
    top = ysort[:2][np.argsort(ysort[:2, 0])]
    bot = ysort[2:][np.argsort(ysort[2:, 0])]
    return np.float32([top[0], top[1], bot[1], bot[0]])


def find_document(img):
    gray = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)
    # 关键一步：自适应阈值而不是 Otsu，光照梯度下 Otsu 会把暗侧的纸判成背景
    binary = cv2.adaptiveThreshold(gray, 255, cv2.ADAPTIVE_THRESH_MEAN_C, cv2.THRESH_BINARY, 51, -10)
    binary = cv2.morphologyEx(binary, cv2.MORPH_CLOSE, np.ones((9, 9), np.uint8))
    cnts, _ = cv2.findContours(binary, cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_SIMPLE)
    if not cnts:
        return None, 0.0
    cnt = max(cnts, key=cv2.contourArea)
    peri = cv2.arcLength(cnt, True)
    for eps in (0.02, 0.03, 0.05, 0.08):
        approx = cv2.approxPolyDP(cnt, eps * peri, True)
        if len(approx) == 4:
            quad = order_points(approx)
            poly_ratio = cv2.contourArea(approx.astype(np.float32)) / max(1e-6, cv2.contourArea(cv2.convexHull(cnt)))
            return quad, float(poly_ratio)
    return None, 0.0


def rectify(img, quad):
    tl, tr, br, bl = quad
    w = int(max(np.linalg.norm(tr - tl), np.linalg.norm(br - bl)))
    h = int(max(np.linalg.norm(bl - tl), np.linalg.norm(br - tr)))
    dst = np.float32([[0, 0], [w - 1, 0], [w - 1, h - 1], [0, h - 1]])
    M = cv2.getPerspectiveTransform(quad, dst)
    warp = cv2.warpPerspective(img, M, (w, h))
    return warp, (w, h)


def bin_from_warp(warp):
    gray = cv2.cvtColor(warp, cv2.COLOR_BGR2GRAY)
    bw = cv2.adaptiveThreshold(gray, 255, cv2.ADAPTIVE_THRESH_GAUSSIAN_C, cv2.THRESH_BINARY, 31, 10)
    inv = cv2.bitwise_not(bw)
    n, lab, stats, _ = cv2.connectedComponentsWithStats(inv, 8)
    clean = np.zeros_like(inv)
    for i in range(1, n):
        if stats[i, cv2.CC_STAT_AREA] >= 12:
            clean[lab == i] = 255
    return cv2.bitwise_not(clean)


def main():
    img = make_input()
    gray = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)
    otsu_thr, otsu = cv2.threshold(cv2.GaussianBlur(gray, (5, 5), 0), 0, 255,
                                   cv2.THRESH_BINARY + cv2.THRESH_OTSU)
    print(f"全局 Otsu 阈值 = {otsu_thr:.1f}")
    quad_otsu, _ = find_document(cv2.cvtColor(otsu, cv2.COLOR_GRAY2BGR))
    print("用 Otsu 二值图找四角:", "失败" if quad_otsu is None else np.round(quad_otsu, 1).tolist())

    quad, poly_ratio = find_document(img)
    if quad is None:
        raise SystemExit("未找到文档四边形")
    err = np.linalg.norm(quad - order_points(GT_CORNERS), axis=1)
    area_ratio = float(cv2.contourArea(quad.astype(np.float32))) / (W * H)
    warp, (w, h) = rectify(img, quad)
    aspect = max(w, h) / min(w, h)
    binary = bin_from_warp(warp)
    ink = int((binary == 0).sum()) / binary.size

    report = {
        "quad": np.round(quad, 1).tolist(),
        "corner_err_px": [round(float(v), 2) for v in err],
        "corner_err_max_px": round(float(err.max()), 2),
        "poly_area_ratio": round(poly_ratio, 4),
        "paper_area_ratio": round(area_ratio, 4),
        "warp_size": [w, h],
        "aspect": round(aspect, 3),
        "ink_ratio": round(ink, 4),
    }
    problems = []
    if area_ratio < MIN_AREA_RATIO:
        problems.append(f"paper_area_ratio {area_ratio:.3f} < {MIN_AREA_RATIO}")
    if poly_ratio < MIN_POLY_AREA_RATIO:
        problems.append(f"poly_area_ratio {poly_ratio:.3f} < {MIN_POLY_AREA_RATIO}（不是规整四边形）")
    if not (ASPECT_RANGE[0] <= aspect <= ASPECT_RANGE[1]):
        problems.append(f"aspect {aspect:.2f} 超出 {ASPECT_RANGE}")
    if ink < 0.005 or ink > 0.35:
        problems.append(f"ink_ratio {ink:.4f} 异常（空白页或过曝）")
    report["ok"] = not problems
    report["problems"] = problems

    cv2.imwrite(OUT_IMG, warp)
    cv2.imwrite(OUT_BIN, binary)
    with open(OUT_META, "w", encoding="utf-8") as fh:
        json.dump(report, fh, ensure_ascii=False, indent=2)

    print(json.dumps(report, ensure_ascii=False, indent=2))
    print("产出:", OUT_IMG, OUT_BIN, OUT_META, "存在:", all(os.path.exists(p) for p in (OUT_IMG, OUT_BIN, OUT_META)))


if __name__ == "__main__":
    main()
```

### 场景二：货架标签双码盘点

需求：理货时拍一张标签，同时识别二维码（跳转 SKU 详情）与 EAN-13，跟库存系统比对并输出盘点结果。脚本自带合成标签（含透视与噪声），可直接运行。

```python
"""scenario_inventory_codes.py —— 货架标签双码盘点
依赖: opencv-python-headless>=5.0, numpy>=2.0
"""
import json
import cv2
import numpy as np

OUT = "/root/.hermes/cache/scratch"
LABEL = f"{OUT}/s79p_label.png"
META = f"{OUT}/s79p_scan.json"

CATALOG = {                                    # 模拟库存系统
    "https://shop.example.com/sku/8842": {"name": "无糖气泡水 330ml", "stock": 42},
    "4006381333931": {"name": "抽纸 3 层 120 抽", "stock": 7},
}

L = {"0": "0001101", "1": "0011001", "2": "0010011", "3": "0111101", "4": "0100011", "5": "0110001",
     "6": "0101111", "7": "0111011", "8": "0110111", "9": "0001011"}
G = {"0": "0100111", "1": "0110011", "2": "0011011", "3": "0100001", "4": "0011101", "5": "0111001",
     "6": "0000101", "7": "0010001", "8": "0001001", "9": "0010111"}
R = {"0": "1110010", "1": "1100110", "2": "1101100", "3": "1000010", "4": "1011100", "5": "1001110",
     "6": "1010000", "7": "1000100", "8": "1001000", "9": "1110100"}
PAR = {"0": "LLLLLL", "1": "LLGLGG", "2": "LLGGLG", "3": "LLGGGL", "4": "LGLLGG", "5": "LGGLLG",
       "6": "LGGGLL", "7": "LGLGLG", "8": "LGLGGL", "9": "LGGLGL"}


def ean13(d12: str):
    """EAN-13 编码：12 位数据 + 校验位 -> 95 个模块的比特串"""
    s = sum(int(d12[i]) * (1 if i % 2 == 0 else 3) for i in range(12))
    dg = d12 + str((10 - s % 10) % 10)
    par = PAR[dg[0]]
    bits = "101" + "".join((L if par[i] == "L" else G)[d] for i, d in enumerate(dg[1:7])) + "01010"
    bits += "".join(R[d] for d in dg[7:]) + "101"
    return dg, bits


def make_label():
    """造一张货架标签：上方二维码、下方 EAN-13，整体带一点透视与噪声"""
    canvas = np.full((700, 520, 3), 250, np.uint8)
    code, bits = ean13("400638133393")

    bar = np.full((160, 330), 255, np.uint8)          # 条码按 2px/模块绘制
    for i, b in enumerate(bits):
        if b == "1":
            x = (9 + i) * 2
            bar[10:150, x:x + 2] = 0
    cv2.putText(bar, code, (95, 158), cv2.FONT_HERSHEY_SIMPLEX, 0.6, 0, 2)
    canvas[40:200, 95:425] = cv2.cvtColor(bar, cv2.COLOR_GRAY2BGR)

    qr = cv2.QRCodeEncoder_create().encode("https://shop.example.com/sku/8842")
    qr = cv2.resize(qr, (290, 290), interpolation=cv2.INTER_NEAREST)   # 模块 1px 必须放大
    canvas[250:540, 115:405] = cv2.cvtColor(qr, cv2.COLOR_GRAY2BGR)

    # 模拟手持拍摄：轻微透视 + 噪声
    src = np.float32([[0, 0], [519, 0], [519, 699], [0, 699]])
    dst = np.float32([[8, 4], [512, 12], [505, 692], [14, 688]])
    M = cv2.getPerspectiveTransform(src, dst)
    warped = cv2.warpPerspective(canvas, M, (520, 700), borderValue=(250, 250, 250))
    rng = np.random.default_rng(3)
    noisy = np.clip(warped.astype(np.int16) + rng.integers(-6, 7, warped.shape), 0, 255).astype(np.uint8)
    cv2.imwrite(LABEL, noisy)
    return code, noisy


def scan(path=LABEL):
    img = cv2.imread(path)
    result = {"path": path, "qr": None, "barcode": None}

    ok, decoded, points, _ = cv2.QRCodeDetector().detectAndDecodeMulti(img)
    result["qr"] = {"retval": bool(ok), "values": list(decoded),
                    "quad": None if points is None else np.round(points[0], 1).tolist()}

    bd = cv2.barcode.BarcodeDetector()
    okb, info, types, pts = bd.detectAndDecodeWithType(img)
    result["barcode"] = {"retval": bool(okb), "values": list(info), "types": list(types),
                         "quad": None if pts is None else np.round(pts[0], 1).tolist()}

    matched = []
    for v in list(decoded) + list(info):
        if v in CATALOG:
            matched.append({"code": v, **CATALOG[v]})
        elif v:
            matched.append({"code": v, "name": "未在库存系统中", "stock": None})
    result["matched"] = matched
    result["ok"] = bool(matched) and result["qr"]["retval"] and result["barcode"]["retval"]
    return result


if __name__ == "__main__":
    code, _ = make_label()
    print("生成的 EAN-13:", code, " 标签图:", LABEL)
    rep = scan()
    print(json.dumps(rep, ensure_ascii=False, indent=2))
    with open(META, "w", encoding="utf-8") as fh:
        json.dump(rep, fh, ensure_ascii=False, indent=2)
    print("盘点结果已落盘:", META)
```

## 最佳实践与踩坑记录

### 最佳实践

1. 文档分割先做光照归一化或用自适应阈值：本机强梯度下自适应阈值角点误差 0.00px，全局 Otsu 78px。
2. 轮廓取四点用「形态学闭运算 + 逐级放宽 eps 的 approxPolyDP」，并校验四边形面积占凸包面积比（本机 0.9966）。
3. 四点定序用按 y 分上下、再按 x 排左右的方法，避免强透视下用求和/差分法错配角点。
4. 输出尺寸按四边形实际边长计算（本机 705x516），配套做长宽比合理性检查（本机 1.366）。
5. 车道线先 ROI 再 Canny/Hough；按线段中点或斜率分组后 polyfit，直道用 1 次拟合、弯道才上 2 次。
6. 人脸检测优先用主仓可用的 DNN（YuNet，带置信度与关键点）；Haar/HOG 需 contrib，且必须自备 XML/行人模板之外的文件。
7. 二维码生成后必须放大到 ≥4px/模块（本机 1px 解码为空串）；条码生成参数（模块宽、条高）要在真实相机下实测。
8. 计数类任务一律用空间关联（最近质心/IoU + 匈牙利）并加「丢失保留 N 帧」，且把事件落盘以便回归验证。

### 踩坑记录

```text
坑 1：光照不均时用全局 Otsu 找文档边界，整条左边被切掉
结论：轮廓能出来、也能拉正，但输出的图左边缺一块，扫码/OCR 全靠运气。
原因：纸张亮度随位置变化（本机 x=100 处灰度 116、x=700 处 255），一个全局阈值必然丢掉暗侧。
      本机两组实测各方案最大角点误差：极端梯度组直接 Otsu 78.00px、divide 归一化 + Otsu 127.28px
      （归一化把纸与桌面的整体亮度差也抹平了）、自适应阈值 0.00px；
      流水线素材组 Otsu 79.00px（左上偏 44px、左下偏 79px）、自适应阈值 0.00px。
解法：用 cv2.adaptiveThreshold(gray, 255, ADAPTIVE_THRESH_MEAN_C, THRESH_BINARY, 51, -10) 做分割，
      再做 MORPH_CLOSE(9x9) 补断边；光照归一化只用于同一物体内部的亮度补偿。

坑 2：approxPolyDP 压不出 4 个顶点，代码直接 OverFlow 到异常/空值
结论：某些图上 len(approx) 是 8、9 甚至 2，后续 np.linalg.norm 或 getPerspectiveTransform 报错。
原因：二值化后纸面内部文字被算进轮廓、边框有断口，轮廓不是规整四边形；eps 取太小保留锯齿，
      取太大又会把整个轮廓压成一条线（本机 eps=0.05*peri 时顶点数掉到 2）。
解法：先 MORPH_CLOSE 补边，再按 0.02/0.03/0.05/0.08 逐级放宽 eps 直到 4 个顶点；
      仍然拿不到 4 点就按「最小外接矩形 minAreaRect」兜底，并把该样本标记为低质量转人工。

坑 3：QRCodeEncoder 生成的二维码直接检测，返回空字符串且不报错
结论：detectAndDecode 返回 ('', None, None)，看着像「图里没有码」，实际是分辨率问题。
原因：encode() 输出的是 1 像素/模块的裸矩阵（本机 (29, 29) uint8），对检测器来说太细。
解法：resize 到 ≥4 像素/模块并留静区。本机实测：1x（109x109 图）解码 ''，
      4x/8x/10x 均正确解出 'https://opencv.org/opencv-5/'；静区 4 个模块就够。

坑 4：自己生成的 EAN-13 条码识别不了，怀疑编码算错
结论：detectAndDecodeWithType 返回 retval=False、info=()，看起来像编码错误。
原因：本机验证编码本身正确（模块宽 2px 时返回 ('4006381333931',) + ('EAN_13',)），
      失败与模块宽/条高的组合有关：条高 110px 以上时只有模块宽 2px 能识别，
      1px、3px、4px、5px、6px 全部失败（条高 60px 时连 2px 也失败）。
解法：不要凭经验定模块宽——先生成候选尺寸做一轮扫描（本机的 3x6 组合表就能直接定位甜点区），
      再用真实相机在真实工作距离下复测；把「生成参数」当成需要标定的配置项，而不是常量。

坑 5：按下标关联目标，越线计数翻倍
结论：同一段视频数出来右行 2 左行 2，真值各 1；指标是「人流量」时误差 100%。
原因：连通域返回顺序不稳定，目标数量/检测结果抖动时下标 k 指向另一个目标，
      前后两帧被当成同一轨迹，跨线事件凭空增加。
解法：用最近质心（本机门限 60px）或 IoU 做关联，配合 Kalman 预测；本机换成空间关联后
      计数恢复到 1+1，方向也正确。

坑 6：装的是 headless 版，检测人脸时发现 CascadeClassifier 根本不存在
结论：AttributeError / hasattr False，代码在别的机器上能跑、到这里就跑不了。
原因：OpenCV 5 把 Haar 与 HOG 移到了 contrib（xobjdetect）；且 pip wheel 里
      cv2.data.haarcascades 目录是空的（本机 0 个 XML），装了 contrib 也没有分类器文件。
解法：换 opencv-contrib-python，并自备模型文件（本机用 opencv 4.x 仓库的
      haarcascade_frontalface_default.xml 与 face_detection_yunet_2023mar.onnx），
      或者直接用主仓的 cv2.FaceDetectorYN；把模型文件纳入部署包并校验加载（fc.empty()）。
```

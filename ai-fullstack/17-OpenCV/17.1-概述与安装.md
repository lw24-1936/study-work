## 概述

OpenCV（Open Source Computer Vision Library）是一套 C++ 编写的计算机视觉与图像处理库，Python 接口通过 `import cv2` 使用。它把「读图-变换-分析-输出」这条链路上的常用算子都做成了高度优化的原生实现：一个 `cv2.resize`、一个 `cv2.cvtColor` 背后是 SIMD 与多线程的 C++ 代码，比手写 NumPy 循环快一到两个数量级。在 AI 全栈里它承担的角色是**数据入口与预处理层**——给模型喂图之前做缩放、归一化、色彩空间转换、掩膜抠图、视频抽帧，模型输出的框和掩膜也常回到 OpenCV 做几何变换与可视化。

本篇是整个 17 篇的起点：先讲清模块划分与四个 PyPI 发行包的区别，再给出本机可复现的安装步骤与真实输出，最后落到源码编译与版本兼容。

```text
本篇主线：
1. 模块结构 —— core / imgproc / imgcodecs / videoio / highgui / dnn 各管什么，contrib 模块为什么要单装
```

## OpenCV 是什么与模块结构

OpenCV 的源码按模块组织，每个模块是一个独立的 CMake 目标；Python 绑定把几乎所有符号都平铺到 `cv2` 命名空间下，另外把少数模块暴露成子模块。理解模块划分的实用价值在于知道**某个函数为什么不可能存在**：只装官方主模块 wheel 的环境里，`cv2.ximgproc.thinning`、`cv2.face.LBPHFaceRecognizer_create` 这类 contrib 函数一定报 `AttributeError`，这不是名字写错。

下表是主模块职责，写代码时按它判断函数归属：

| 模块 | 头文件 | 职责 | Python 常见入口 |
| --- | --- | --- | --- |
| core | `opencv2/core.hpp` | 矩阵 Mat、算术、位运算、内存与并行框架 | `cv2.add`、`cv2.bitwise_and`、`cv2.split`、`cv2.countNonZero` |
| imgproc | `opencv2/imgproc.hpp` | 图像处理：色彩空间、滤波、阈值、几何变换、轮廓 | `cv2.cvtColor`、`cv2.GaussianBlur`、`cv2.threshold`、`cv2.warpAffine`、`cv2.findContours` |
| imgcodecs | `opencv2/imgcodecs.hpp` | 图像编解码读写 | `cv2.imread`、`cv2.imwrite`、`cv2.imencode`、`cv2.imdecode` |
| videoio | `opencv2/videoio.hpp` | 视频文件、摄像头、IP 流的抓取与写出 | `cv2.VideoCapture`、`cv2.VideoWriter` |
| highgui | `opencv2/highgui.hpp` | 窗口显示与键盘鼠标事件（headless 包没有实现） | `cv2.imshow`、`cv2.waitKey` |
| video | `opencv2/video.hpp` | 运动分析与跟踪基元 | `cv2.calcOpticalFlowPyrLK`、`cv2.BackgroundSubtractorMOG2` |
| calib3d | `opencv2/calib3d.hpp` | 相机标定、对极几何、三维重建 | `cv2.findHomography`、`cv2.calibrateCamera`、`cv2.solvePnP` |
| features2d | `opencv2/features2d.hpp` | 特征点检测与描述子 | `cv2.SIFT_create`、`cv2.BFMatcher`、`cv2.drawKeypoints` |
| objdetect | `opencv2/objdetect.hpp` | 级联分类器、二维码、条形码 | `cv2.CascadeClassifier`、`cv2.QRCodeDetector` |
| dnn | `opencv2/dnn.hpp` | 加载 ONNX/Caffe/TF 模型做推理 | `cv2.dnn.readNetFromONNX` |
| photo | `opencv2/photo.hpp` | 计算摄影：去噪、修复、HDR | `cv2.fastNlMeansDenoisingColored` |
| stitching | `opencv2/stitching.hpp` | 全景拼接 | `cv2.Stitcher_create` |

contrib（`opencv_contrib` 仓库）里的额外模块常见有 `aruco`（ArUco 标记）、`ximgproc`（引导滤波、超像素、细化）、`face`（人脸识别）、`xfeatures2d`（SURF 等受许可影响的算法）、`tracking`、`text`。这些不在官方主模块 wheel 里，必须装 `opencv-contrib-python`（或其 headless 版）或自行编译。

下面是在本机 `opencv-python-headless 5.0.0.93` 上清点子模块的真实结果：

结论有两条：一是**函数在不在和子模块能不能 import 是两件事**——`cv2.ml` 不能 import（`cv2.ml` 属性取出来是 `None`），但 `cv2.ml.SVM_create` 这类接口在装了主模块的 wheel 里仍可通过平铺名访问；而 `cv2.ximgproc` 是**真的没有**（主模块 wheel 不含 contrib）。二是不同大版本暴露的子模块集合会变：4.x 下写 `import cv2.videoio` 很常见，5.0.0 的 wheel 里不行。跨版本代码别依赖子模块路径，直接用顶层 `cv2.函数名`。

```text
模块结构要点：
1. core / imgproc / imgcodecs / videoio / highgui 是日常 90% 代码用到的五个模块
2. 官方主模块 wheel 不含 contrib；ximgproc / face / xfeatures2d 要装 contrib 包（aruco 已并入主模块）
3. Python 绑定把符号平铺到 cv2 顶层，子模块路径在不同大版本间会变，别依赖 import cv2.xxx
4. headless 包编译时 GUI=NONE，highgui 的窗口函数符号存在但调用即抛错
5. 判断某函数是否可用：先看官方文档里函数所属模块，再核对本机装的是哪种包
```

## Python 安装与四种包的选择

`pip install opencv-python` 装的是**预编译 wheel**，不是把 OpenCV 源码装到系统上——wheel 里已静态链接了 OpenCV 二进制、FFmpeg、libjpeg-turbo、libpng 等，所以不需要另外 `apt install libopencv-dev`。官方维护四个包，**同一个环境只能装一个**：所有包的 import 名都是 `cv2`，没有插件机制，装多个会互相覆盖同名目录。

| 包名 | 含 contrib | 含 GUI | 适用环境 |
| --- | --- | --- | --- |
| `opencv-python` | 否 | 是（Qt5 等） | 桌面/开发机，需要 `imshow` 看结果 |
| `opencv-contrib-python` | 是 | 是 | 需要 ximgproc / face / trackers 的桌面开发 |
| `opencv-python-headless` | 否 | 否（GUI=NONE） | 服务器、Docker、CI，不需要开窗口 |
| `opencv-contrib-python-headless` | 是 | 否 | 服务端 + contrib 算法 |

选型规则可以压成一句话：**桌面调试用 `opencv-python`，任何服务端/容器/批处理任务用对应 headless 版**。headless 版不依赖 X11/Qt 那一长串动态库，镜像体积与构建时间都明显更小；代价是代码里出现 `cv2.imshow` 会直接抛 `The function is not implemented`。

安装命令（本机使用清华镜像，避免 PyPI 直连慢）：

```bash
python3 -m venv /root/.hermes/cache/scratch/cvvenv

/root/.hermes/cache/scratch/cvvenv/bin/pip install -q \
  -i https://pypi.tuna.tsinghua.edu.cn/simple \
  opencv-python-headless numpy matplotlib
```

**版本号规则**：包版本形如 `cv_major.cv_minor.cv_revision.package_revision`，前三段是 OpenCV 库版本，第四段是 opencv-python 这个打包仓库自己的修订号。所以 `5.0.0.93` 表示库 5.0.0、打包修订 93；`cv2.__version__` 只回前三段，`cv2.version.opencv_version` 回四段全量。本机实测：

## 本机安装实录与能力清点

装完后第一件事不是写算法，而是**确认这套 wheel 到底编译进了哪些能力**。`cv2.getBuildInformation()` 返回编译期信息，是排查「为什么读不了视频」「为什么 OpenCL 没生效」的第一手依据。本机 headless 5.0.0.93 的真实关键行：

```text
Version control:               5.0.0
GUI:                           NONE
Media I/O:
  JPEG:                        build-libjpeg-turbo (ver 3.1.2-70)
  PNG:                         /usr/local/lib/libpng.so (ver 1.6.58)
  TIFF:                        build (ver 42 - 4.7.1)
Video I/O:
  FFMPEG:                      YES
Parallel framework:            pthreads
OpenCL:                        YES (no extra features)
```

对照解释：`GUI: NONE` 就是 headless 的标志；`FFMPEG: YES` 说明视频读写可用（自编译版本经常漏掉 FFmpeg）；`OpenCL: YES` 只是编译时带了这个后端，运行时是否真能用要看 `cv2.ocl.haveOpenCL()`。

运行时状态与开关的本机实测：

```python

cv2.setNumThreads(0)
print("setNumThreads(0) ->", cv2.getNumThreads(), "（0 表示关闭并行，退化为单线程）")
```

两个值得注意的实测结论：其一，`cv2.version == "5.0.0"` 是 `False`（`cv2.version` 是四段字符串 `"5.0.0.93"`），版本判断别用 `==`；其二，`cv2.data.haarcascades` 目录存在但**只有 `__init__.py`，没有任何 XML 级联文件**——官方 README 里「所有包都包含 Haar cascade」的说法在 5.0.0.93 这个 wheel 上不成立，本机在 cv2 目录下搜到 0 个 `.xml`，`cv2.CascadeClassifier(cv2.data.haarcascades + "haarcascade_frontalface_default.xml")` 会失败。用级联分类器前先探测文件是否存在。

```python
import cv2, cv2.utils.logging as cvglog

print([a for a in dir(cvglog) if a.startswith("LOG_LEVEL")])
print("默认级别:", cvglog.getLogLevel())
cvglog.setLogLevel(cvglog.LOG_LEVEL_SILENT)   # 3 是 WARNING，SILENT 最安静
print("读不存在的文件返回:", cv2.imread("/root/.hermes/cache/scratch/definitely_missing.png"))
```

```text
可用常量: ['LOG_LEVEL_DEBUG', 'LOG_LEVEL_ERROR', 'LOG_LEVEL_FATAL', 'LOG_LEVEL_INFO',
          'LOG_LEVEL_SILENT', 'LOG_LEVEL_VERBOSE', 'LOG_LEVEL_WARNING']
默认级别: 3
读不存在的文件返回: None （stderr 无 WARN 提示）
```


## 源码编译要点

只有三种情况值得自己编译：需要 CUDA/OpenVINO 加速、需要 GStreamer 这类特殊后端、需要 contrib 里只有源码树才有的模块。官方 Linux 安装教程给出的最小流程如下（`opencv` 与 `opencv_contrib` 放在同级目录）：

```bash
# 1. 构建工具：编译器 + CMake + make 或 ninja
sudo apt install -y cmake g++ make ninja-build wget unzip

# 2. 下载源码（快照约 80-90MB，不要 git clone 拉全历史，体积 470MB+）
wget -O opencv.zip https://github.com/opencv/opencv/archive/4.x.zip
wget -O opencv_contrib.zip https://github.com/opencv/opencv_contrib/archive/4.x.zip
unzip opencv.zip
unzip opencv_contrib.zip

# 3. 配置：Release 构建 + 打开 contrib 路径 + 生成 Python3 绑定
mkdir -p build && cd build
cmake -D CMAKE_BUILD_TYPE=Release \
      -D CMAKE_INSTALL_PREFIX=/usr/local \
      -D OPENCV_EXTRA_MODULES_PATH=../opencv_contrib-4.x/modules \
      -D BUILD_opencv_python3=ON \
      -D PYTHON3_EXECUTABLE=$(which python3) \
      -D BUILD_EXAMPLES=OFF -D BUILD_TESTS=OFF -D BUILD_PERF_TESTS=OFF \
      -D WITH_CUDA=OFF \
      ../opencv-4.x

# 4. 编译（N 取 CPU 核数，本机 8 核）
make -j8

# 5. 安装：可执行 /usr/local/bin，库 /usr/local/lib，CMake 包 /usr/local/cmake/opencv4，
#    头文件 /usr/local/include/opencv4，级联等数据 /usr/local/share/opencv4
sudo make install
```

几个决定成败的参数：`OPENCV_EXTRA_MODULES_PATH` 指向 contrib 的 `modules` 目录才有 ximgproc/face；`BUILD_opencv_python3=ON` 才生成 `cv2` 扩展；`PYTHON3_EXECUTABLE` 必须指向你要用的那个解释器（在 venv 里编译就指向 venv 的 python，否则装到系统 site-packages 后 venv 里反而 import 不到）；想被别的程序用 `pkg-config` 找到就加 `-D OPENCV_GENERATE_PKGCONFIG=ON`。务必 `CMAKE_BUILD_TYPE=Release`，默认可能是 Debug，跑起来慢几十倍。8 核机器上只编主模块通常是几分钟到十几分钟，带 contrib 与 CUDA 会到小时级。

需要如实说明：**本机未验证源码编译**——`which cmake` 无输出（本机只有 `g++`，没有 CMake），因此上述流程来自官方文档而非本机实测输出；实际编译请以官方 `Installation in Linux` 教程与自己版本的 CMake 为准。

```text
源码编译要点：
1. 只有需要 CUDA/特定后端/特殊 contrib 模块时才自编译，其余场景一律用 wheel
2. 三个必设参数：OPENCV_EXTRA_MODULES_PATH、BUILD_opencv_python3、PYTHON3_EXECUTABLE
3. 一律 CMAKE_BUILD_TYPE=Release，Debug 版运行慢几十倍
4. 编译前确认 PYTHON3_EXECUTABLE 指向目标 venv，否则装完 import 不到
5. 安装目录为 /usr/local/{bin,lib,include/opencv4,share/opencv4}，可用 CMAKE_INSTALL_PREFIX 改
6. 本机无 cmake，未实测编译，命令以官方文档为准
```

## 版本兼容与升级注意

OpenCV 大版本之间的 API 有实际迁移成本：4.x 是当前教程与生产代码的主流基线；5.x（本机装到的 5.0.0）重排了部分 Python 子模块的暴露方式（前面实测 `cv2.ml`、`cv2.objdetect` 不再能 import），并引入了 `IMREAD_COLOR_BGR` 这类显式语义常量（与 `IMREAD_COLOR` 同值；文档注明它与 `IMREAD_COLOR_RGB` 不能同时设置）。升级前先跑一遍环境自检脚本，确认用到的函数都还在。

NumPy 是最容易咬人的依赖：PyPI 上 `opencv-python-headless` 的依赖声明是条件式的 `numpy <2.0`（对应旧版本）或 `numpy >=2`（对应新版本），而 NumPy 2.0 有 ABI 变更，**旧版 OpenCV 4.x wheel 在 NumPy 2 环境里 import 会直接失败**（典型报错为 `numpy.core.multiarray failed to import`）。本机组合 `opencv-python-headless 5.0.0.93 + numpy 2.5.4` 实测正常。Python 版本方面，官方 README 声明为 3.7 至 3.14 提供 wheel；本机 Python 3.14.7 装到的是 ABI 稳定标签的 `opencv_python_headless-5.0.0.93-cp37-abi3-manylinux_2_28_x86_64.whl`，说明一个轮子覆盖多个 Python 版本，但 `manylinux_2_28` 要求 glibc >= 2.28，在更老的基础镜像（如 CentOS 7）里装不上，得换版本或自编译。

同环境多包共存的后果，本机做了实测：在已装 `opencv-python-headless` 的环境里再 `pip install opencv-python`，**pip 不报任何错**，两个包都出现在 `pip list` 里，但 `cv2` 目录只剩一份内容——后装的覆盖先装的，`GUI` 从 `NONE` 变成 `QT5`，即实际生效的是非 headless 的那份二进制。这类事故在 CI 镜像里的表现是「本地能跑，容器里 import cv2 报 GLIBCXX 或 X11 相关错误」，而且很难从 `pip list` 看出来。

```text
版本兼容要点：
1. 生产锁 4.x 或 5.x 的某一个小版本，不要只写 opencv-python-headless
2. NumPy 2.x 与旧 OpenCV wheel 不兼容，升级 numpy 时同步升级 opencv
3. 5.x 的 Python 子模块暴露方式与 4.x 不同，别 import cv2.ml / cv2.videoio
4. manylinux_2_28 轮子要求 glibc >= 2.28，老基础镜像装不上
5. 同一环境多个 opencv 包共存时 pip 不报错，后装的静默覆盖，必须用自检脚本兜住
6. 包名与 import 名不同：包名 opencv-python(-headless/-contrib)，import 名统一 cv2（官方 FAQ 说明是历史兼容）
```

## 应用场景实战

### 场景一：新机器/新镜像上的 OpenCV 环境落地与健康检查

部署流水线里最常见的是「装完之后确认这套环境真的能干活」，而不是跑通 `import cv2` 就上线。下面这个自检脚本可以直接当健康检查用：它校验包唯一性、编解码能力、读写往返与色彩转换，全通过返回 0，否则返回 1，正好接进容器 `HEALTHCHECK` 或 CI 步骤。

```python
#!/usr/bin/env python3
"""OpenCV 环境自检脚本：部署到新机器或容器后可直接当健康检查跑，退出码 0 表示可用。"""
import sys, os, tempfile
from importlib import metadata

import numpy as np
import cv2

FAIL = []


def check(cond, ok_msg, bad_msg):
    print(("  [ OK ] " if cond else "  [FAIL] ") + (ok_msg if cond else bad_msg))
    if not cond:
        FAIL.append(bad_msg)


print("=== OpenCV 环境自检 ===")
print("python :", sys.version.split()[0])
print("numpy  :", np.__version__)
print("cv2    :", cv2.__version__, "（完整包版本 %s）" % cv2.version.opencv_version)
print("cv2 模块路径:", os.path.dirname(cv2.__file__))

print("\n[1] 已安装的 opencv 相关发行包（同环境只能有一个）")
dists = sorted({d.metadata["Name"] for d in metadata.distributions()
                if d.metadata["Name"] and d.metadata["Name"].lower().startswith("opencv")})
for n in dists:
    print("   ", n, metadata.version(n))
check(len(dists) == 1, "只安装了 1 个 opencv 包: %s" % (dists[0] if dists else "无"),
      "检测到 %d 个 opencv 包共存（%s），同一环境必须只保留一个" % (len(dists), ", ".join(dists)))

print("\n[2] 关键能力与编译信息")
info = cv2.getBuildInformation()
has_ffmpeg = any(l.strip().startswith("FFMPEG") and "YES" in l for l in info.splitlines())
gui = next((l.strip() for l in info.splitlines() if l.strip().startswith("GUI")), "GUI: ?")
print("   ", gui)
check(has_ffmpeg, "FFMPEG: 已编译（可读写视频）", "FFMPEG: 未编译，VideoCapture/VideoWriter 不可用")
print("    cv2.imshow 可用:", hasattr(cv2, "imshow"), "（headless 包为 NONE，服务端不要调用）")
print("    线程数:", cv2.getNumThreads(), "/ CPU", cv2.getNumberOfCPUs())

print("\n[3] 读写往返自检（合成图 -> PNG -> 读回）")
tmp = os.path.join(tempfile.gettempdir(), "cv2_envcheck.png")
img = np.zeros((40, 60, 3), np.uint8)
img[10:30, 10:50] = (0, 128, 255)
ok_w = cv2.imwrite(tmp, img)
back = cv2.imread(tmp)
check(bool(ok_w) and back is not None,
      "imwrite/imread 往返成功，读回形状 %s" % (None if back is None else str(back.shape)),
      "imwrite 或 imread 失败")
if back is not None:
    check(back.shape == (40, 60, 3) and np.array_equal(back, img),
          "像素完全一致（PNG 无损）", "PNG 往返后像素不一致")
    gray = cv2.cvtColor(back, cv2.COLOR_BGR2GRAY)
    check(gray.shape == (40, 60), "COLOR_BGR2GRAY 输出单通道 %s" % (gray.shape,),
          "cvtColor 灰度转换形状异常: %s" % (gray.shape,))
os.remove(tmp)

print("\n结论:", "全部通过，环境可用" if not FAIL else "存在 %d 个问题，需修复后重试" % len(FAIL))
sys.exit(1 if FAIL else 0)
```

干净环境（只装了 headless 包）的真实运行结果：

```text

python : 3.14.7
numpy  : 2.5.4
cv2    : 5.0.0 （完整包版本 5.0.0.93）
cv2 模块路径: /root/.hermes/cache/scratch/cvvenv/lib/python3.14/site-packages/cv2

[1] 已安装的 opencv 相关发行包（同环境只能有一个）
    opencv-python-headless 5.0.0.93
  [ OK ] 只安装了 1 个 opencv 包: opencv-python-headless

[2] 关键能力与编译信息
    GUI:                           NONE
  [ OK ] FFMPEG: 已编译（可读写视频）
    cv2.imshow 可用: True （headless 包为 NONE，服务端不要调用）
```

### 场景二：无外网生产机的离线安装（wheel 打包 + 本地源安装）

企业内网机器通常没有公网，`pip install` 直接超时（本机实测：容器里 `wget` 清华镜像一直挂到超时退出，容器网络被隔离）。标准做法是在有网机器上把 wheel 连同依赖一起下载成本地目录，再把目录传过去离线安装。

## 最佳实践与踩坑记录

### 最佳实践

1. 服务端一律用 headless 包（需要 contrib 算法就用 `opencv-contrib-python-headless`），桌面调试机用非 headless 包，两边的依赖清单分开维护。
2. 版本锁到四段全量并写进 `requirements.txt`（例如 `opencv-python-headless==5.0.0.93`），同时把 `numpy` 锁到大版本，避免 ABI 漂移。
3. 把环境自检脚本当成部署产物的一部分：校验包唯一性 + FFMPEG + 读写往返 + cvtColor，退出码接进 CI 或容器健康检查。
4. 用 `cv2.getBuildInformation()` 的结果当排障依据并贴进 issue：GUI/FFMPEG/Video I/O 三行就能区分「环境问题」与「代码问题」。
5. 批量任务里显式控制并行度与日志：`cv2.setNumThreads(n)` 与 `cv2.utils.logging.setLogLevel(cv2.utils.logging.LOG_LEVEL_WARNING)`，避免与上层进程池叠加把 CPU 打满。
6. 只有需要 CUDA/GStreamer 才自编译，并把 cmake 参数固化进脚本；纯 CPU 场景没有理由不用 wheel。

### 踩坑记录

```text
坑 1：同一个环境装了多个 opencv 包，本地正常、容器里 import cv2 就崩
结论：以为镜像坏了，反复重建 venv。
原因：opencv-python 家族四个包共用 cv2 这个 import 名，彼此没有声明冲突；后装的包直接覆盖
      site-packages/cv2 下的同名二进制。
解法：本机实测在已装 headless 的环境里再装 opencv-python，pip 全程无报错，pip list 里两个包
      并存，但 GUI 从 NONE 变成 QT5（生效的是后装的非 headless 版）。用场景一的自检脚本
      检查「opencv 发行包数量必须为 1」，并在镜像构建的最后一步 pip uninstall 清干净。

坑 2：容器/内网机器上 pip install opencv-python-headless 直接挂死
结论：以为镜像源挂了，反复换源。
原因：容器网络被隔离，出口不可达。本机实测在 alpine:3.20 容器里 wget 清华镜像直到超时
      （命令超时退出），而宿主机访问同一个源秒回。
解法：在有网机器 pip download 出 wheel 目录，目标机用 --no-index --find-links 离线装；
      下载时加 --only-binary=:all:，并核对 wheel 标签与目标机 Python 版本。

坑 3：import cv2 正常、hasattr(cv2, "imshow") 也为 True，一调用就抛错
结论：以为函数签名写错了。
原因：headless 包编译时 GUI=NONE，highgui 的窗口函数符号仍然被导出，但内部走的是直接抛异常
      的分支。
解法：本机实测调用 cv2.imshow 得到 OpenCV(5.0.0) .../highgui/src/window.cpp:1215:
      error: (-2:Unspecified error) The function is not implemented...。服务端代码不要用
      imshow/waitKey 调试，改用 cv2.imwrite 落盘 + 日志；需要交互就在本地装非 headless 包。

坑 4：用 cv2.version 判断版本，判断结果与预期相反
结论：以为装错了版本。
原因：cv2.version 是四段字符串（"5.0.0.93"），cv2.__version__ 才是前三段（"5.0.0"）。
解法：本机实测 cv2.version == "5.0.0" 返回 False，cv2.version.opencv_version 返回
      "5.0.0.93"。版本判断统一用 cv2.__version__ 做前缀比较，或解析四段版本号。

坑 5：照教程用 cv2.data.haarcascades 拼路径做人脸检测，加载级联时找不到 XML
结论：以为级联文件被自己删了。
原因：README 说所有包都包含 Haar cascade，但实测 5.0.0.93 的 cv2/data 下只有 __init__.py，
      没有任何 .xml；轮子里的级联数据随版本变化，不能假定存在。
解法：先 os.path.exists 探测，缺失时从官方仓库下载 XML 随应用分发并显式传绝对路径；
      或改用特征检测方案（ORB/SIFT，见 17.7）而不依赖级联文件。
```

## 概述

OpenCV 在 Python 里的图像就是一个 **NumPy 三维数组**，形状是 `(高, 宽, 通道)`、`dtype` 为 `uint8`、通道顺序是 **BGR 而不是 RGB**。这三条是所有基础操作的根：`imread` 读进来是 `(H, W, 3)`，所以索引写成 `img[y, x]`；因为顺序是 BGR，所以 `img[10, 10]` 得到的三个数是「蓝绿红」；因为底层是 NumPy 数组，所以切片、广播、向量化运算全都直接可用，ROI 甚至不需要专门函数。

本篇覆盖单帧图像的读写显示、像素与通道访问、ROI 与属性、尺寸变换、拼接，以及视频的读写与抽帧——把「数据怎么进来、怎么出去、怎么在里面移动」这条通路讲透。

```text
本篇主线：
1. 读写 —— imread 的 flags 与失败返回 None、imwrite 的返回值与异常差异、内存编解码
2. 像素 —— img[y, x] 是 BGR 三元组，单通道访问、向量化批量改色
3. ROI —— 切片即 ROI，视图 vs copy，步幅与内存连续性对性能的影响
4. 尺寸 —— resize 的 dsize 与 fx/fy 两套口径、插值的取舍
5. 拼接 —— hconcat / vconcat / copyMakeBorder，尺寸不齐时的处理
6. 视频 —— VideoCapture / VideoWriter 的属性、fourcc、尺寸必须严格匹配
```

本机环境：Ubuntu 24.04、Python 3.14.7、`opencv-python-headless 5.0.0.93`、`numpy 2.5.4`（headless 包没有 GUI，所有示例用 `cv2.imwrite` 落盘代替 `imshow`，生成文件都在 `/root/.hermes/cache/scratch/`）。下文 `text` 块均为本机真实输出。

## 读取 显示与保存

`cv2.imread(filename, flags)` 返回 NumPy 数组或 `None`：**文件不存在或解码失败时返回 `None`，不抛异常**，所以流水线里必须逐个判空。`flags` 决定解码结果，最常用的三个是 `IMREAD_COLOR`（默认，强制三通道 BGR）、`IMREAD_GRAYSCALE`（强制单通道）、`IMREAD_UNCHANGED`（保留 alpha 与原深度）。官方 flags 文档还特别注明：`IMREAD_COLOR_BGR`（与 `IMREAD_COLOR` 同值）和 `IMREAD_COLOR_RGB` 不能同时设置，后者是新版本才有的显式 RGB 选项，跨版本代码不要依赖它。

```python
import numpy as np, cv2

OUT = "/root/.hermes/cache/scratch"
img = np.zeros((120, 160, 3), dtype=np.uint8)   # 注意顺序是 (高, 宽, 3)
img[0:60, 0:80] = (255, 0, 0)                   # BGR 纯蓝
img[0:60, 80:160] = (0, 255, 0)                 # BGR 纯绿
img[60:120, :] = (0, 0, 255)                    # BGR 纯红
print("imwrite 返回:", cv2.imwrite(OUT + "/cv17_img_basic.png", img))

img2 = cv2.imread(OUT + "/cv17_img_basic.png")                          # 默认 IMREAD_COLOR
g = cv2.imread(OUT + "/cv17_img_basic.png", cv2.IMREAD_GRAYSCALE)
u = cv2.imread(OUT + "/cv17_img_basic.png", cv2.IMREAD_UNCHANGED)
print("默认读回 shape:", img2.shape, img2.dtype, " 左上角像素:", img2[0, 0].tolist())
print("GRAYSCALE shape:", g.shape, "蓝区灰度:", int(g[10, 10]), "红区灰度:", int(g[100, 10]))
print("UNCHANGED shape:", u.shape, u.dtype)
print("读不存在的文件:", cv2.imread(OUT + "/cv17_no_such_file.png"))
```

```text
imwrite 返回: True
默认读回 shape: (120, 160, 3) uint8  左上角像素: [255, 0, 0]
GRAYSCALE shape: (120, 160) 蓝区灰度: 29 红区灰度: 76
UNCHANGED shape: (120, 160, 3) uint8
读不存在的文件: None
[ WARN:0@0.307] global loadsave.cpp:278 findDecoder imread_('.../cv17_no_such_file.png'):
                can't open/read file: check file path/integrity
```

灰度值 29 与 76 正好对上官方文档给的加权公式 `Y = 0.299R + 0.587G + 0.114B`：纯蓝 `0.114*255 = 29.07`，纯红 `0.299*255 = 76.2`，说明灰度转换是感知加权而不是简单平均。

写文件的接口有两个，行为差异必须记住：`cv2.imwrite(path, img, params)` 编码失败（磁盘满、路径不可写）返回 `False`，但**遇到无法识别的扩展名会直接抛 `cv2.error`**。质量参数用 `[cv2.IMWRITE_JPEG_QUALITY, 85]` 这类「键值对列表」传入；官方文档给出 JPEG 质量取值 0-100、默认 95，PNG 压缩级别 0-9、默认 1（速度优先）。

```python
print(cv2.imwrite(OUT + "/cv17_out_basic.jpg", img, [cv2.IMWRITE_JPEG_QUALITY, 90]))
try:
    cv2.imwrite(OUT + "/cv17_out_basic.xyz", img)
except cv2.error as e:
    print("不支持的扩展名 ->", str(e).splitlines()[-1][:110])

ok, buf = cv2.imencode(".png", img)      # 编码到内存，适合网络传输/直接入库
print("imencode 返回:", ok, "缓冲区 shape:", buf.shape, buf.dtype)
back = cv2.imdecode(buf, cv2.IMREAD_COLOR)
print("imdecode 还原 shape:", back.shape, "与原始一致:", np.array_equal(back, img))
```

```text
True
不支持的扩展名 -> error: (-2:Unspecified error) could not find a writer for the specified extension in function 'imwrite'
imencode 返回: True 缓冲区 shape: (587,) uint8
imdecode 还原 shape: (120, 160, 3) 与原始一致: True
```

关于「显示」：桌面环境用 `cv2.imshow` + `cv2.waitKey`；服务端（headless 包）绝对不能用——本机实测 headless 包里 `hasattr(cv2, "imshow")` 为 `True`，但一调用就抛 `error: (-2:Unspecified error) The function is not implemented. Rebuild the library...`。服务端的可视化替代方案就是 `imwrite` 落盘、写进日志目录或对象存储。中文路径在本机 Linux 上 `imread`/`imwrite` 直接可用（实测成功），若要更稳妥（跨平台或路径含特殊字符）可以用 `np.fromfile` + `cv2.imdecode` 的方式读：

```python
cn = OUT + "/cv17_中文目录_测试.png"
print("imwrite 中文路径:", cv2.imwrite(cn, img2))
print("imread 中文路径:", cv2.imread(cn).shape)
raw = np.fromfile(cn, dtype=np.uint8)
print("fromfile + imdecode:", cv2.imdecode(raw, cv2.IMREAD_COLOR).shape)
```

```text
imwrite 中文路径: True
imread 中文路径: (120, 160, 3)
fromfile + imdecode: (120, 160, 3)
```

```text
读取与保存要点：
1. imread 失败返回 None，不抛异常；批量任务必须逐个判空并记账
2. flags：IMREAD_COLOR 强制三通道、GRAYSCALE 强制单通道、UNCHANGED 保留 alpha/深度
3. imwrite 返回 True/False，但无法识别的扩展名会抛 cv2.error，两者都要处理
4. imencode/imdecode 在内存里完成编解码，适合流式传输与入库
5. headless 包不能用 imshow（调用即抛 -2），服务端一律 imwrite 落盘
6. JPEG 质量 0-100 默认 95；PNG 压缩 0-9 默认 1，显式传参才可控
```

## BGR 通道与像素访问

像素访问有三个层次：单点 `img[y, x]`（返回长度为 3 的视图数组，顺序 BGR）、单通道 `img[y, x, c]`（或 `img.item(y, x, c)`，返回 Python int）、以及**向量化**（`reshape(-1, 3)` 或按通道切片后整块赋值）。生产代码里逐像素 Python 循环是性能杀手，能向量化就向量化。

```python
a = img2.copy()
print("a[10,10] =", a[10, 10].tolist(), "类型:", type(a[10, 10]).__name__)
print("通道索引 a[10,10,0] =", int(a[10, 10, 0]), "  a.item(10,10,0) =", a.item(10, 10, 0))

b = img2.copy()
b[10, 10] = 0                      # 陷阱：标量赋值把 B、G、R 三个通道一起改了
print("b[10,10] = 0 后:", b[10, 10].tolist())
b[10, 10] = [0, 0, 0]              # 想全黑要显式给三个值
print("b[10,10] = [0,0,0] 后:", b[10, 10].tolist())

c = img2.copy().reshape(-1, 3)     # 向量化：一次改掉所有像素的 B 通道
c[:, 0] = 0
print("向量化清空 B 通道 ->", c.reshape(120, 160, 3)[0, 0].tolist())

b_ch, g_ch, r_ch = cv2.split(img2)                 # 拆成三个单通道图
print("split:", b_ch.shape, "merge 还原一致:",
      np.array_equal(cv2.merge([b_ch, g_ch, r_ch]), img2))
swapped = cv2.merge([r_ch, g_ch, b_ch])            # BGR <-> RGB 互换
print("通道对调后 [0,0]:", swapped[0, 0].tolist(), " 原始:", img2[0, 0].tolist())
```

```text
a[10,10] = [255, 0, 0] 类型: ndarray
通道索引 a[10,10,0] = 255  a.item(10,10,0) = 255
b[10,10] = 0 后: [0, 0, 0]
b[10,10] = [0,0,0] 后: [0, 0, 0]
向量化清空 B 通道 -> [0, 0, 0]
split: (120, 160) merge 还原一致: True
通道对调后 [0,0]: [0, 0, 255]  原始: [255, 0, 0]
```

注意 `cv2.split` 返回的**是副本**（本机实测 `b.flags["OWNDATA"]` 为 `True`，改它不影响原图），而 NumPy 切片 `img[:, :, 0]` 是**视图**——它们语义不同，混用会写出无声的 bug。要「BGR 转 RGB」还可以直接用 `cv2.cvtColor(img, cv2.COLOR_BGR2RGB)`，比手工 merge 更清晰，涉及图像序列转成的张量时更常用（详见 17.3）。

```text
像素与通道要点：
1. 索引顺序是 img[y, x]（先行后列），与 shape (高, 宽, 通道) 一致
2. 通道顺序是 BGR，不是 RGB；img[y, x] 得到 [B, G, R]
3. img[y, x] = 0 会同时改三个通道，改单通道要写 img[y, x, c] 或 img[y, x, c] = 0
4. 逐像素 Python 循环极慢，批量改色用 reshape(-1, 3) 或按通道切片
5. cv2.split 返回副本，NumPy 通道切片是视图，语义不同别混用
6. 只是想把 BGR 当 RGB 用，直接 cv2.cvtColor(..., COLOR_BGR2RGB)
```

## ROI 与图像属性

ROI（Region of Interest）在 Python 里不需要专门函数，**NumPy 切片就是 ROI**，且返回的是**视图**：修改 ROI 会改到原图，这对「原地画标注」很方便，对「只想试算一个区域」则是事故来源，需要副本时显式 `.copy()`。

```python
print("shape:", img2.shape, " ndim:", img2.ndim, " size:", img2.size)
print("itemsize:", img2.itemsize, " nbytes:", img2.nbytes, " strides:", img2.strides)
print("C 连续:", img2.flags["C_CONTIGUOUS"])

roi = img2[0:60, 0:80]
print("roi shape:", roi.shape, " roi.base is img2:", roi.base is img2,
      " 连续:", roi.flags["C_CONTIGUOUS"])
view = img2[20:40, 20:40]
view[:] = (255, 255, 255)
print("改 ROI 后原图 [20,20]:", img2[20, 20].tolist(), " [0,0]:", img2[0, 0].tolist())
safe = img2[20:40, 20:40].copy()
safe[:] = (0, 0, 0)
print("用 .copy() 后再改，原图 [20,20] 仍为:", img2[20, 20].tolist())

strip = img2[:, 0:80]                      # 按列切出的 ROI 不连续
print("列切片连续:", strip.flags["C_CONTIGUOUS"],
      " 转连续后:", np.ascontiguousarray(strip).flags["C_CONTIGUOUS"])
```

```text
shape: (120, 160, 3)  ndim: 3  size: 57600
itemsize: 1  nbytes: 57600  strides: (480, 3, 1)
C 连续: True
roi shape: (60, 80, 3)  roi.base is img2: True  连续: False
改 ROI 后原图 [20,20]: [255, 255, 255]  [0,0]: [255, 0, 0]
用 .copy() 后再改，原图 [20,20] 仍为: [255, 255, 255]
列切片连续: False  转连续后: True
```

属性记忆法：`img.shape` 是 `(高, 宽, 通道)`；`img.size` 是**像素总数**（含通道，本例 120*160*3=57600）；`img.nbytes` 是字节数（`uint8` 下与 size 相同，`float32` 下是 4 倍）；`img.strides` 在一个像素占 3 字节时是 `(480, 3, 1)`。`strides` 直接暴露了「行优先 + 通道交错」的布局：相邻两行差 480 字节 = 160 像素 * 3 通道。

一个容易被忽略的点：**只有按行切片且切满整行的 ROI 才是内存连续的**，`img[0:60, 0:80]` 与 `img[:, 0:80]` 都是不连续的。OpenCV 的函数大多能接受不连续输入（内部会按行处理），但把它传给期望连续内存的库（某些深度学习推理接口、`np.frombuffer` 之类）就必须先 `np.ascontiguousarray(img)`，否则拿到的数据是错的或直接报错。

```text
ROI 与属性要点：
1. 切片即 ROI：img[y1:y2, x1:x2]，不需要专门函数
2. ROI 默认是视图，改它等于改原图；要隔离必须先 .copy()
3. shape=(高, 宽, 通道)，size 含通道，nbytes 与 dtype 相关
4. strides 反映内存布局，BGR 交错存储时一像素占 3 字节
5. 非整行切片得到的 ROI 不连续，传给外部库前用 np.ascontiguousarray
6. 只想读不想改时也要留意视图语义：误改 ROI 会污染后续所有处理
```

## 尺寸变换与插值选择

`cv2.resize(src, dsize, dst=None, fx=0, fy=0, interpolation)` 有两种指定尺寸的口径：给 `dsize=(宽, 高)`（注意与 shape 顺序相反），或给缩放因子 `fx`、`fy` 并把 `dsize` 传 `(0, 0)`。两者都不给会触发断言失败。

```python
print(cv2.resize(img2, (320, 240), interpolation=cv2.INTER_LINEAR).shape)     # dsize=(宽,高)
print(cv2.resize(img2, None, fx=0.5, fy=0.5, interpolation=cv2.INTER_AREA).shape)
print(cv2.resize(img2, None, fx=3.0, fy=3.0, interpolation=cv2.INTER_NEAREST).shape)
print(cv2.resize(img2, (0, 0), fx=1.5, fy=1.5).shape)
try:
    cv2.resize(img2, (0, 0))
except cv2.error as e:
    print("dsize 与 fx/fy 都不给 ->", str(e).splitlines()[-1].strip()[:100])
h, w = img2.shape[:2]
scale = 800 / max(h, w)                       # 常见的「长边限制」等比缩放
print("scale:", round(scale, 4), "目标:", (int(w * scale), int(h * scale)))
```

```text
(240, 320, 3)
(60, 80, 3)
(360, 480, 3)
(180, 240, 3)
dsize 与 fx/fy 都不给 -> error: (-215:Assertion failed) inv_scale_x > 0 in function 'resize'
scale: 5.0 目标: (800, 600)
```

插值选择有官方依据：`INTER_AREA` 的定义是「按像素面积关系重采样，**缩小图像时通常是首选**，能得到无摩尔纹的结果；但放大时它的表现与 `INTER_NEAREST` 类似」，所以 放大不要用 `INTER_AREA`。实践结论：缩小用 `INTER_AREA`，放大用 `INTER_LINEAR`（快）或 `INTER_CUBIC`（更锐但慢），掩膜/标签图这类不能插值出新值的图用 `INTER_NEAREST`。另外 `INTER_NEAREST_EXACT` 在新版本里提供与 PIL、scikit-image、Matlab 一致的最近邻结果，需要跨库严格对齐时用它。

另一个必须记住的一致性规则：如果预处理阶段把图缩到 640，后处理把模型输出坐标映射回原图时必须用**完全相同的 scale 与插值逻辑**反算，否则框会偏移。工程上更稳的做法是把缩放矩阵显式算出来并在前后处理之间传递，而不是各自现算一次。

```text
尺寸变换要点：
1. dsize 是 (宽, 高)，与 numpy 的 shape (高, 宽) 顺序相反
2. 只用缩放因子时 dsize 传 (0, 0) 并给 fx/fy，两者都不给会断言失败
3. 缩小优先 INTER_AREA，放大用 INTER_LINEAR/INTER_CUBIC，掩膜用 INTER_NEAREST
4. 等比缩放按 max(h, w) 计算因子，避免长宽比变形
5. 预处理缩放与后处理坐标反算必须用同一套参数，否则框会漂
6. 跨库对齐（PIL/Matlab）时用 INTER_NEAREST_EXACT 保证逐像素一致
```

## 图像拼接与边框

`cv2.hconcat` 横向拼、`cv2.vconcat` 纵向拼，本质是 NumPy 的 `concatenate`，要求**对应维度完全一致**（横拼要求行数与通道数相同，纵拼要求列数与通道数相同），否则报错；尺寸不齐时先用 `cv2.copyMakeBorder` 或在拼接前统一 resize/补边。

```python
print("hconcat:", cv2.hconcat([img2, img2]).shape)
print("vconcat:", cv2.vconcat([img2, img2]).shape)
print("加 10px 白边:", cv2.copyMakeBorder(img2, 10, 10, 10, 10,
      cv2.BORDER_CONSTANT, value=(255, 255, 255)).shape)
a = np.zeros((100, 100, 3), np.uint8)
b = np.zeros((80, 100, 3), np.uint8)
try:
    cv2.hconcat([a, b])
except cv2.error as e:
    print("高度不一致时 hconcat ->", str(e).splitlines()[-1].strip()[:110])
```

```text
hconcat: (120, 320, 3)
vconcat: (240, 160, 3)
加 10px 白边: (140, 180, 3)
高度不一致时 hconcat -> error: (-215:Assertion failed) src[i].dims <= 2 && src[i].rows == src[0].rows
                         && src[i].type() == src[0].type() in function 'hconcat'
宽度不一致时 vconcat -> error: (-215:Assertion failed) src[i].dims <= 2 && src[i].cols == src[0].cols
                         && src[i].type() == src[0].type() in function 'vconcat'
更底层用 np.hstack / np.vstack -> ValueError: all the input array dimensions except for the
                         concatenation axis must match exactly
```

做「缩略图墙」时正确姿势是：先把每张图 resize 到统一单元格尺寸（或用 `copyMakeBorder` 补到统一尺寸），再按行 hconcat、最后 vconcat。`copyMakeBorder` 的四个像素参数顺序是 `(top, bottom, left, right)`（上下在前、左右在后），与前面「宽高」的顺序容易混，写的时候按名字核对。

```text
拼接与边框要点：
1. hconcat/vconcat 要求对应维度严格一致，尺寸不齐先统一或补边
2. copyMakeBorder 参数顺序是 上、下、左、右，value 是 BGR 标量
3. 做缩略图墙：先统一单元尺寸 -> 按行 hconcat -> 再 vconcat
4. 拼接会复制数据，大图批量拼接要注意内存峰值
5. 需要等分网格时把每行补到相同列数（补空白块），避免最后一行报错
```

## 视频读写

视频是「帧序列 + 帧率」，用 `cv2.VideoCapture` 读、`cv2.VideoWriter` 写。`VideoCapture` 可以打开视频文件、图像序列（文件名写成 `img_%02d.jpg` 这种模式）、摄像头索引（0、1）或流地址；打开后用 `isOpened()` 判断，用 `read()` 取帧（返回 `(bool, frame)`），用 `get/set` 读写属性（`CAP_PROP_FPS`、`CAP_PROP_FRAME_WIDTH/HEIGHT`、`CAP_PROP_FRAME_COUNT`、`CAP_PROP_POS_FRAMES`），跑完务必 `release()`。

```python
path = OUT + "/cv17_demo_video.mp4"
vw = cv2.VideoWriter(path, cv2.VideoWriter_fourcc(*"mp4v"), 20.0, (160, 120))
print("VideoWriter.isOpened():", vw.isOpened())
for i in range(30):
    frame = np.full((120, 160, 3), 30, dtype=np.uint8)
    cv2.circle(frame, (20 + i * 4, 60), 12, (0, 255, 255), -1)
    vw.write(frame)
vw.release()

cap = cv2.VideoCapture(path)
print("isOpened:", cap.isOpened(), "| 宽:", cap.get(cv2.CAP_PROP_FRAME_WIDTH),
      "高:", cap.get(cv2.CAP_PROP_FRAME_HEIGHT), "fps:", cap.get(cv2.CAP_PROP_FPS),
      "总帧:", cap.get(cv2.CAP_PROP_FRAME_COUNT))
n = 0
while True:
    ret, frame = cap.read()
    if not ret:                      # 流结束或读失败，退出
        break
    if n == 0:
        cv2.imwrite(OUT + "/cv17_video_frame0.png", frame)
    n += 1
cap.release()
print("实际读出帧数:", n, " 首帧 shape:", frame.shape, frame.dtype)
```

```text
VideoWriter.isOpened(): True
isOpened: True | 宽: 160.0 高: 120.0 fps: 20.0 总帧: 30.0
实际读出帧数: 30  首帧 shape: (120, 160, 3) uint8
```

注意 `get` 返回的都是 `float`（`160.0`、`30.0`），用到整数位置时显式 `int()`。`VideoWriter` 的构造参数是 `(文件名, fourcc, fps, 帧尺寸, isColor)`，**帧尺寸必须与实际写入的帧完全一致**：本机实测「声明 160x120 却写 320x240 的帧」时，`write()` 返回 `False`、FFmpeg 打印 `Failed to write frame`，最后生成的文件只有 258 字节、回读 0 帧——如果代码不检查返回值，就会得到「流程全绿、视频是空的」这种结果。

```python
p2 = OUT + "/cv17_mismatch.mp4"
vw2 = cv2.VideoWriter(p2, cv2.VideoWriter_fourcc(*"mp4v"), 20.0, (160, 120))
print("喂 320x240 帧时 write() 返回:",
      vw2.write(np.zeros((240, 320, 3), np.uint8)))
vw2.release()
cap2 = cv2.VideoCapture(p2)
cnt = 0
while True:
    r, _ = cap2.read()
    if not r:
        break
    cnt += 1
cap2.release()
print("能读回的帧数:", cnt)
```

```text
[ WARN:0@1.316] global cap_ffmpeg.cpp:219 write FFmpeg: Failed to write frame
喂 320x240 帧时 write() 返回: False
能读回的帧数: 0
```

定位任意帧用 `cap.set(cv2.CAP_PROP_POS_FRAMES, idx)`，本机实测跳到第 10 帧后读到的画面与第 0 帧不同（对比结果为 `False`，即确实跳转成功）。fourcc 用 `cv2.VideoWriter_fourcc(*"mp4v")` 这种四字符写法，本机实测编码值：`mp4v=1983148141`、`MJPG=1196444237`、`XVID=1145656920`、`H264=875967048`；容器与编码器不匹配时 `isOpened()` 会是 `False`，所以每次构造后都要判。若想指定后端，可加 `apiPreference` 参数（如 `cv2.CAP_FFMPEG`），本机 headless wheel 的可写后端本机实测包含 `FFMPEG`、`CV_MJPEG`、`CV_IMAGES`、`GSTREAMER`、`INTEL_MFX`。

```text
视频读写要点：
1. read() 返回 (bool, frame)，bool 为 False 表示流结束或出错，循环以此退出
2. get() 全部返回 float；整数索引要 int() 转换
3. VideoWriter 声明的帧尺寸必须与写入帧完全一致，否则静默失败（write 返回 False）
4. write() 的返回值必须检查，否则会产出 0 帧的空视频
5. fourcc 与扩展名要匹配（mp4 常用 mp4v/H264，avi 常用 MJPG/XVID），isOpened() 判有效性
6. 用 set(CAP_PROP_POS_FRAMES, n) 跳帧；处理完 release() 释放句柄
```

## 应用场景实战

### 场景一：批量图像预处理流水线（等比缩放 + JPEG 压缩 + 失败清单）

电商/内容平台最常见的离线任务：把用户上传的原图统一处理成 Web 用的规格，要求保持长宽比、控制单边不超过阈值、失败文件必须记账而不是中断整批。下面这段是完整可运行的实现，含坏文件与中文文件名两个真实边界。

```python
import os, glob, csv, time
import numpy as np
import cv2

OUT = "/root/.hermes/cache/scratch"
RAW = os.path.join(OUT, "cv17_raw")
DST = os.path.join(OUT, "cv17_web")
os.makedirs(RAW, exist_ok=True)
os.makedirs(DST, exist_ok=True)

rng = np.random.default_rng(42)
for i, (h, w) in enumerate([(1080, 1920), (720, 1280), (400, 300), (1500, 900), (640, 480)]):
    canvas = np.full((h, w, 3), 40, dtype=np.uint8)
    cv2.rectangle(canvas, (w // 8, h // 8), (w // 2, h // 2), (0, 200 * (i % 2), 255), -1)
    cv2.putText(canvas, "IMG-%d" % i, (w // 6, h // 3), cv2.FONT_HERSHEY_SIMPLEX,
                2.0, (255, 255, 255), 4)
    cv2.imwrite(os.path.join(RAW, "photo_%02d.png" % i), canvas)
with open(os.path.join(RAW, "broken_05.png"), "w") as f:
    f.write("this is not an image")           # 坏文件：imread 会返回 None
cv2.imwrite(os.path.join(RAW, "中文文件名_06.png"), np.full((300, 400, 3), 90, np.uint8))

MAX_EDGE = 640
t0 = time.perf_counter()
ok_list, fail_list = [], []
for path in sorted(glob.glob(os.path.join(RAW, "*.png"))):
    name = os.path.basename(path)
    img = cv2.imread(path)
    if img is None:                            # 关键：判空而不是捕获异常
        fail_list.append((name, "imread 返回 None（文件损坏或不是图像）"))
        continue
    h, w = img.shape[:2]
    scale = MAX_EDGE / max(h, w)
    if scale < 1.0:                            # 只缩小，不放大
        img = cv2.resize(img, (round(w * scale), round(h * scale)),
                         interpolation=cv2.INTER_AREA)
    dst = os.path.join(DST, os.path.splitext(name)[0] + ".jpg")
    if not cv2.imwrite(dst, img, [cv2.IMWRITE_JPEG_QUALITY, 85]):
        fail_list.append((name, "imwrite 返回 False"))
        continue
    ok_list.append((name, "%dx%d" % (w, h), "%dx%d" % (img.shape[1], img.shape[0]),
                    os.path.getsize(dst) // 1024))
elapsed = time.perf_counter() - t0

print("%-22s %-12s %-12s %8s" % ("源文件", "原始尺寸", "输出尺寸", "KB"))
for n_, src, dst_, kb in ok_list:
    print("%-22s %-12s %-12s %8d" % (n_, src, dst_, kb))
print("-" * 64)
print("成功 %d 张，失败 %d 个，总耗时 %.3f s" % (len(ok_list), len(fail_list), elapsed))
for n_, why in fail_list:
    print("  失败: %s -> %s" % (n_, why))

idx_csv = os.path.join(OUT, "cv17_pipeline_index.csv")
with open(idx_csv, "w", newline="", encoding="utf-8") as f:
    wr = csv.writer(f)
    wr.writerow(["src", "src_size", "dst_size", "kb"])
    for n_, s, d, kb in ok_list:
        wr.writerow([n_, s, d, kb])
print("索引写入:", idx_csv)
```

```text
源文件                    原始尺寸         输出尺寸               KB
photo_00.png           1920x1080    640x360             6
photo_01.png           1280x720     640x360             6
photo_02.png           300x400      300x400             6
photo_03.png           900x1500     384x640             6
photo_04.png           480x640      480x640            10
中文文件名_06.png           400x300      400x300             2
----------------------------------------------------------------
成功 6 张，失败 1 个，总耗时 0.887 s
  失败: broken_05.png -> imread 返回 None（文件损坏或不是图像）
索引写入: /root/.hermes/cache/scratch/cv17_pipeline_index.csv
```

结果读法：`photo_02`（300x400）没被缩放是因为长边未超 640（`scale > 1` 时不处理，防止把图放大劣化）；`photo_03` 是竖图，按长边 1500 计算得到 384x640，长宽比保持。坏文件被单独记账，整批不中断。这个结构可以直接扩成多进程版本：把单文件处理函数拆出来丢给 `ProcessPoolExecutor`，返回 `(name, ok, info)`，主进程统一汇总——注意每个子进程里调用 `cv2.setNumThreads(1)`，避免「进程数 × OpenCV 内部线程数」把 CPU 打满。

### 场景二：视频抽帧 + 缩略图墙 + 区间切片

监控回放、内容审核、数据集构建都需要从视频里按步长抽帧并生成一份总览图。下面这段抽帧、拼 3 列缩略图墙、再把指定帧区间导成独立切片视频。

```python
import os, numpy as np, cv2

OUT = "/root/.hermes/cache/scratch"
VIDEO = os.path.join(OUT, "cv17_demo_video.mp4")
cap = cv2.VideoCapture(VIDEO)
fps = cap.get(cv2.CAP_PROP_FPS)
total = int(cap.get(cv2.CAP_PROP_FRAME_COUNT))
w, h = int(cap.get(cv2.CAP_PROP_FRAME_WIDTH)), int(cap.get(cv2.CAP_PROP_FRAME_HEIGHT))
print("输入视频: %s  %dx%d  %.1f fps  %d 帧" % (os.path.basename(VIDEO), w, h, fps, total))

STEP = 5
frames, indices, i = [], [], 0
while True:
    ret, frame = cap.read()
    if not ret:
        break
    if i % STEP == 0:
        frames.append(frame)
        indices.append(i)
        cv2.imwrite(os.path.join(OUT, "cv17_frame_%03d.jpg" % i), frame,
                    [cv2.IMWRITE_JPEG_QUALITY, 90])
    i += 1
cap.release()
print("按每 %d 帧抽 1 帧：抽出 %d 帧，帧号 %s" % (STEP, len(frames), indices))

THUMB_W, COLS = 160, 3
thumbs = [cv2.resize(f, (THUMB_W, round(f.shape[0] * THUMB_W / f.shape[1])),
                     interpolation=cv2.INTER_AREA) for f in frames]

def pad_to(im, target_h, target_w):
    return cv2.copyMakeBorder(im, 0, target_h - im.shape[0], 0, target_w - im.shape[1],
                              cv2.BORDER_CONSTANT, value=(20, 20, 20))

cell_h, cell_w = max(t.shape[0] for t in thumbs) + 4, THUMB_W + 4
rows = []
for r in range(0, len(thumbs), COLS):
    row = [pad_to(t, cell_h, cell_w) for t in thumbs[r:r + COLS]]
    while len(row) < COLS:                              # 最后一行补空白块
        row.append(np.full((cell_h, cell_w, 3), 20, np.uint8))
    rows.append(cv2.hconcat(row))
wall = cv2.vconcat(rows)
wall_path = os.path.join(OUT, "cv17_thumb_wall.jpg")
cv2.imwrite(wall_path, wall, [cv2.IMWRITE_JPEG_QUALITY, 90])
print("缩略图墙 %d 列 x %d 行, 尺寸 %s -> %s"
      % (COLS, len(rows), wall.shape[:2], os.path.basename(wall_path)))

seg_path = os.path.join(OUT, "cv17_segment.mp4")
vw = cv2.VideoWriter(seg_path, cv2.VideoWriter_fourcc(*"mp4v"), fps, (w, h))
cap = cv2.VideoCapture(VIDEO)
cap.set(cv2.CAP_PROP_POS_FRAMES, 10)                    # 从第 10 帧开始切 15 帧
written = 0
while written < 15:
    ret, frame = cap.read()
    if not ret:
        break
    vw.write(frame)
    written += 1
cap.release()
vw.release()
cap = cv2.VideoCapture(seg_path)
n = 0
while True:
    r, _ = cap.read()
    if not r:
        break
    n += 1
cap.release()
print("切片写入了 %d 帧，回读校验 %d 帧，文件 %d 字节" % (written, n, os.path.getsize(seg_path)))
```

```text
输入视频: cv17_demo_video.mp4  160x120  20.0 fps  30 帧
按每 5 帧抽 1 帧：抽出 6 帧，帧号 [0, 5, 10, 15, 20, 25]
缩略图墙 3 列 x 2 行, 尺寸 (248, 492) -> cv17_thumb_wall.jpg
切片写入了 15 帧，回读校验 15 帧，文件 3001 字节
```

三个工程要点：一是抽帧循环里 `ret` 为假必须 `break`，否则会拿着上一帧反复处理；二是写缩略图墙前统一单元格尺寸（本例用 `copyMakeBorder` 补到最大高度并补齐列数），否则 `hconcat` 直接断言失败；三是切片视频必须新建 `VideoWriter` 并沿用原视频的 `fps` 与帧尺寸，`set(CAP_PROP_POS_FRAMES, n)` 之后要重新校验 `read()` 的返回值。最后回读校验帧数是必要的验收动作——本机正是靠它才发现尺寸不匹配的静默失败。

```text
实战两个场景的共性经验：
1. 批处理一律「失败记账 + 继续」，不中断整批；imread 判空是第一道防线
2. 缩放只在放大劣化风险可控时才做，且统一 INTER_AREA
3. 输出文件写入后用 getsize 或回读做一次验收，别信流程没报错
4. 抽帧/切片必须核对 fps 与帧尺寸，写之前判 isOpened，写之后判 write 返回值
5. 多进程并行时每个子进程 cv2.setNumThreads(1)，避免线程超订
```

## 最佳实践与踩坑记录

### 最佳实践

1. 所有 `imread` 调用都判空并把失败文件记入清单（文件名 + 原因），批处理结束后统一输出报表。
2. 预处理统一用「长边限制 + 等比缩放 + `INTER_AREA`」，并把缩放参数在后处理坐标反算里复用，避免坐标漂移。
3. 一律用 `pathlib`/显式相对路径传参，避免依赖当前工作目录；跨平台读写含非 ASCII 路径时用 `np.fromfile` + `cv2.imdecode` 兜底。
4. ROI 修改原图是特性也是陷阱：想改就用视图，不想改就 `.copy()`，团队内统一约定并在 review 时盯这一条。
5. 视频处理模板固定为「构造 -> isOpened -> 循环 read 判 ret -> release」，并在写出后用回读帧数做验收。
6. 处理大图或大视频时用 `with`/`try-finally` 保证 `release()`；内存吃紧的流水线改成流式逐帧处理，别把全部帧留在列表里。

### 踩坑记录

```text
坑 1：想只改一个通道，写成 img[y, x] = 0，结果三个通道全变了
结论：图片一片黑，怀疑掩膜算错。
原因：img[y, x] 是长度为 3 的数组，标量赋值按 NumPy 广播规则写给全部通道。
解法：本机实测 img[10,10] = 0 之后像素变为 [0, 0, 0]，三个通道一起被改。要改单通道必须写
      img[y, x, c] = 0 或 img[y, x] = [b, g, r]；批量改单通道用 reshape(-1, 3)[:, c] = v。

坑 2：在 ROI 上画了框，原图也出现了框；或者反过来说「我只想临时调一下结果，原图被改花了」
结论：以为切片返回的是副本。
原因：NumPy 切片返回视图，roi.base 指向原数组（本机实测 roi.base is img2 为 True）。
解法：需要隔离时 .copy()。本机实测改 img2[20:40, 20:40] 的视图会把原图 [20,20] 改成白色，
      而 .copy() 之后修改不影响原图。

坑 3：把非整行切出来的 ROI 传给外部库，结果数据错乱或报错
结论：以为 OpenCV 的切片和独立图像一样。
原因：按列或子矩形切片得到的数组内存不连续（本机实测 C_CONTIGUOUS 为 False），strides 仍按
      原图行宽走；期望连续内存的接口（部分推理库、frombuffer）会读错或拒绝。
解法：需要连续时 np.ascontiguousarray(strip)（本机实测转换后为 True），或在切片时就 .copy()。

坑 4：VideoWriter 输出视频能打开但一帧都没有，流程日志全绿
结论：以为编码器不支持该格式，反复换 fourcc。
原因：VideoWriter 构造时声明的帧尺寸与实际写入帧不一致时，write() 静默返回 False 并打印
      FFmpeg 警告，不抛异常；不检查返回值就会一路跑完。
解法：本机实测「声明 160x120 却写 320x240」时 write() 返回 False、文件只有 258 字节、回读
      0 帧。统一做法：帧尺寸取自源视频或显式约定，写出后回读校验帧数。

坑 5：resize 报 Assertion failed: inv_scale_x > 0
结论：以为传入的尺寸非法。
原因：dsize 传了 (0, 0) 表示「用 fx/fy 计算」，此时如果 fx、fy 保持默认 0，缩放因子就是 0。
解法：本机实测 cv2.resize(img, (0, 0)) 抛该断言；要么给 dsize=(宽, 高)，要么给 fx/fy 并把
      dsize 传 None 或 (0, 0)。

坑 6：批量脚本在坏文件上抛异常整批中断；或反过来，文件写失败但脚本照样报成功
结论：以为 imwrite 失败会抛异常、imread 失败会抛异常。
原因：imread 失败返回 None（不抛异常）；imwrite 编码失败返回 False（不抛异常），但扩展名不
      支持时抛 cv2.error——两种错误模型混在一起。
解法：imread 逐个判 None；imwrite 检查返回值，同时对无法识别的扩展名包 try/except cv2.error。
      本机实测 imwrite 到不存在的扩展名 .xyz 抛 "could not find a writer for the specified
      extension"。
```

## 概述

特征检测与匹配解决的是「同一物体在不同图像里怎么找出来并对齐」：先在两幅图上各找一批稳定的关键点（keypoint）并为每个点算一个描述子（descriptor），再按描述子距离做配对，最后用几何模型（单应矩阵）把错误配对剔掉。它和模板匹配的分工很清晰——模板匹配只做平移搜索、对缩放旋转脆弱，适合固定机位下的定位；特征匹配与单应估计能处理旋转、缩放、透视和部分遮挡，适合「货架上的商品在手机拍的照片里在哪」这类真实场景。

```text
本篇主线：
1. 关键点检测 —— goodFeaturesToTrack（Shi-Tomasi）/ FAST / SIFT / ORB，以及 OpenCV 5 里哪些检测器被移出主仓
2. 描述子 —— SIFT 128 维 float32 与 ORB 32 字节 uint8，形状/类型/数量实测
3. 匹配器 —— BFMatcher 的 normType 与 crossCheck、FLANN 的 index_params/search_params、Lowe 距离比
4. 筛选 —— knnMatch + 距离比 + 几何校验；内点率比绝对匹配数更可靠
5. 单应矩阵 —— findHomography 的 method 选择、RANSAC 内点掩膜、重投影误差评估
6. 配准 —— perspectiveTransform / warpPerspective 把拍摄图摆回模板坐标系
7. 模板匹配 —— matchTemplate 六种方法、minMaxLoc、尺度与旋转失效的量化结果
```

## 角点与关键点检测

「角点」是局部窗口沿任意方向移动都会显著改变灰度的像素，是定位最稳定的点。OpenCV 里最轻的三条路径是：`cv2.goodFeaturesToTrack`（Shi-Tomasi，直接在图上返回坐标，不产生描述子，常用于光流跟踪的种子点）、`cv2.FastFeatureDetector_create()`（FAST，纯角点、极快、不含方向信息）、以及自带描述子的 `cv2.SIFT_create()` / `cv2.ORB_create()`。检测器对象统一通过 `detect()` 拿关键点、通过 `detectAndCompute()` 同时拿关键点和描述子。

```python
import cv2
import numpy as np

# 造一张有纹理的测试图（真实工程里换成你的图：cv2.imread(path, cv2.IMREAD_GRAYSCALE)）
rng = np.random.default_rng(7)
img = rng.integers(200, 256, (600, 800, 3), dtype=np.uint8)
for _ in range(120):
    cv2.circle(img, (int(rng.integers(0, 800)), int(rng.integers(0, 600))), int(rng.integers(4, 18)), (60, 60, 60), -1)
for i in range(5):
    cv2.rectangle(img, (60 + i * 140, 150), (160 + i * 140, 260), (0, 0, 0), 3)
gray = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)

sift = cv2.SIFT_create()                      # SIFT：128 维 float32 描述子，精度最高
kp_s, des_s = sift.detectAndCompute(gray, None)

orb = cv2.ORB_create(nfeatures=500)           # ORB：32 字节 uint8 二进制描述子，快
kp_o, des_o = orb.detectAndCompute(gray, None)

fast = cv2.FastFeatureDetector_create()       # FAST：只有角点，没有描述子
kp_f = fast.detect(gray, None)

corners = cv2.goodFeaturesToTrack(            # Shi-Tomasi：直接返回 Nx1x2 的角点坐标
    gray, maxCorners=300, qualityLevel=0.01, minDistance=10)

print(f"SIFT keypoints={len(kp_s)}  descriptor={des_s.shape} {des_s.dtype}")
print(f"ORB  keypoints={len(kp_o)}  descriptor={des_o.shape} {des_o.dtype}")
print(f"FAST keypoints={len(kp_f)}  (默认 threshold={fast.getThreshold()})")
print(f"goodFeaturesToTrack corners={len(corners)} shape={corners.shape}")
print("SIFT 第一个关键点:", kp_s[0].pt, " 响应:", round(kp_s[0].response, 3),
      " 方向:", round(kp_s[0].angle, 1), " 主尺寸:", round(kp_s[0].size, 1))
```

本机真实输出：

```text
SIFT keypoints=3378  descriptor=(3378, 128) float32
ORB  keypoints=500  descriptor=(500, 32) uint8
FAST keypoints=22559  (默认 threshold=10)
goodFeaturesToTrack corners=300 shape=(300, 1, 2)
SIFT 第一个关键点: (2.8149003982543945, 457.7855529785156)  响应: 0.126  方向: 40.6  主尺寸: 2.5
```

KeyPoint 对象里的字段值得记住：`pt`（x, y 浮点坐标）、`size`（特征点直径）、`angle`（方向，单位度，`-1` 表示无方向）、`response`（响应强度，可用于排序取前 N 个）、`octave`（所在金字塔层）。

OpenCV 5 的一个重要变化：`features2d` 模块改名为 `features`，并且 **AKAZE / KAZE / BRISK / SURF / BRIEF / FREAK / LUCID / DAISY 等检测器被移出主仓**，SIFT、ORB、FAST、GoodFeaturesToTrack、MSER 保留。上面那组 `hasattr` 实测就是这个结论；装了 `opencv-contrib-python 5.0.0.93` 后本机实测 `SURF_create` 以 `cv2.xfeatures2d.SURF_create` 的形式存在，而 AKAZE/BRISK 仍不可用，跨版本使用前请按官方迁移说明与自己的安装复核（https://github.com/opencv/opencv/wiki/OpenCV-4-to-5-migration ）。

```text
要点：
- 只需要坐标做光流/跟踪 -> goodFeaturesToTrack（Shi-Tomasi）最省，输出 Nx1x2 float32
- 只要角点、要极快 -> FAST（本机默认 threshold=10，一张 800x600 纹理图出 2 万多个点，务必配合上限或 ROI）
- 要旋转/尺度不变 + 高质量 -> SIFT（128 维 float32，本机纹理图 3378 个点）
- 要速度与低内存 -> ORB（32 字节 uint8，本机默认上限 500 个点，descriptor.shape 是 (500, 32)）
- 掩膜参数 mask 只在非零位置参与检测，是限流与限定 ROI 的第一手段
- OpenCV 5 主仓没有 AKAZE/BRISK/SURF；`cv2.SIFT_create()` 与 `cv2.ORB_create()` 正常可用
```

## 描述子提取与参数取舍

描述子是把关键点邻域压成一个定长向量的结果，决定了「同一点在不同视角下能不能对上」。SIFT 的描述子是 128 维 float32，距离用 `NORM_L2`；ORB 是 256 位二进制串（32 字节 uint8），距离用 `NORM_HAMMING`。这组对应关系是用错范数就会掉点的根源（下一节有实测对比）。参数上最值得动的只有三个：`nfeatures`（ORB 的描述子上限，也是性能闸门）、`contrastThreshold`（SIFT 过滤低对比度点的门槛，调高会丢弱纹理点）、`nOctaveLayers`（SIFT 每层的采样数，调高更稳但更慢）。

```python
import cv2
import numpy as np

gray = cv2.imread("/root/.hermes/cache/scratch/s77_doc.png", cv2.IMREAD_GRAYSCALE)

# ORB：nfeatures 直接决定描述子行数，是 CPU 占用与内存的一阶控制量
for n in (200, 500, 2000):
    kp, des = cv2.ORB_create(nfeatures=n).detectAndCompute(gray, None)
    print(f"ORB nfeatures={n:4d} -> keypoints={len(kp):4d} descriptor={des.shape}")

# SIFT：contrastThreshold 控制弱纹理点，nOctaveLayers 控制稳定性/耗时
for ct in (0.02, 0.04, 0.08):
    kp, des = cv2.SIFT_create(contrastThreshold=ct).detectAndCompute(gray, None)
    print(f"SIFT contrastThreshold={ct} -> keypoints={len(kp)}")

# 只要前 N 个最强响应点：按 response 排序截断
kp, des = cv2.SIFT_create().detectAndCompute(gray, None)
order = np.argsort([-k.response for k in kp])[:200]
kp_top = [kp[i] for i in order]
des_top = des[order]
print("按响应取前 200 个:", len(kp_top), des_top.shape)

# 掩膜：只在指定矩形 ROI 内提点（例如只要表格区域）
mask = np.zeros_like(gray)
cv2.rectangle(mask, (100, 100), (500, 400), 255, -1)
kp_roi, des_roi = cv2.SIFT_create().detectAndCompute(gray, mask)
print("加 ROI 掩膜后:", len(kp_roi), des_roi.shape)
```

本机真实输出：

```text
ORB nfeatures= 200 -> keypoints= 200 descriptor=(200, 32)
ORB nfeatures= 500 -> keypoints= 500 descriptor=(500, 32)
ORB nfeatures=2000 -> keypoints=2000 descriptor=(2000, 32)
SIFT contrastThreshold=0.02 -> keypoints=3761
SIFT contrastThreshold=0.04 -> keypoints=3378
SIFT contrastThreshold=0.08 -> keypoints=3332
按响应取前 200 个: 200 (200, 128)
加 ROI 掩膜后: 1376 (1376, 128)
```

工程上必须做的两件类型检查：`detectAndCompute` 在图像纹理太少时会返回 `des=None`（不是空数组），`None` 直接送进 matcher 会抛 `cv2.error`；另外 `des.dtype` 决定了后面能用哪种范数，`uint8` 走 Hamming，`float32` 走 L2。

```text
要点：
- SIFT 描述子 128 维 float32 -> 距离用 cv2.NORM_L2；ORB 32 字节 uint8 -> 用 cv2.NORM_HAMMING
- ORB 的 nfeatures 是上限也是闸门：本机 200/500/2000 分别产出 200/500/2000 行描述子
- SIFT 的 contrastThreshold 从 0.02 提到 0.08，本机点数从 3761 降到 3332（弱纹理被滤掉）
- 描述子类型必须打印确认：des is None（无点）与 des.dtype（uint8/float32）是两件不同的事
- 用 mask 限定 ROI 可以同时降点数与降误匹配：本机全图 3378 点，加 ROI 掩膜后 1376 点
- 匹配前统一把关键点按 response 排序截断，比事后按距离截断更能控制误匹配来源
```

## 特征匹配器与匹配筛选

匹配器做的是「A 图每个描述子在 B 图里最像谁」。`cv2.BFMatcher` 是暴力搜索，两图各几千点时仍然很快，参数只有两个：`normType`（`NORM_L2` 对 SIFT/SURF，`NORM_HAMMING` 对 ORB/BRISK）与 `crossCheck`（双向一致，只保留互为最近邻的配对）。`cv2.FlannBasedMatcher` 用 KD 树/LSH 做近似最近邻，适合大库检索，但要自己传 `index_params` 与 `search_params`。

`match()` 返回一对一的最优配对，`knnMatch(des1, des2, k=2)` 返回 k 个近邻，才允许做 Lowe 的距离比检验：最近邻距离 `m` 明显优于次近邻 `n`（`m.distance < ratio * n.distance`）才说明这是一个「独一无二」的配对不对。距离比对有规律的场景（重复纹理、网格、文字）几乎是唯一有效的过滤器。

```python
import cv2
import numpy as np

doc = cv2.imread("/root/.hermes/cache/scratch/s77_doc.png", cv2.IMREAD_GRAYSCALE)
scene = cv2.imread("/root/.hermes/cache/scratch/s77_scene.png", cv2.IMREAD_GRAYSCALE)

sift = cv2.SIFT_create()
kp1, des1 = sift.detectAndCompute(doc, None)
kp2, des2 = sift.detectAndCompute(scene, None)

bf = cv2.BFMatcher(cv2.NORM_L2)               # SIFT 用 L2；ORB 改 cv2.NORM_HAMMING
raw = sorted(bf.match(des1, des2), key=lambda m: m.distance)   # 一对一最优配对
print("match() 总数:", len(raw), "最近 5 个距离:", [round(m.distance, 1) for m in raw[:5]])

knn = bf.knnMatch(des1, des2, k=2)             # k 近邻，才能做距离比
print("knnMatch 总对数:", len(knn))
for ratio in (0.6, 0.7, 0.75, 0.9):
    print(f"距离比 {ratio}: good={sum(1 for m, n in knn if m.distance < ratio * n.distance)}")

# 双向校验（crossCheck）与距离比是两种不同思路，本机对比：
for cc in (False, True):
    b = cv2.BFMatcher(cv2.NORM_L2, crossCheck=cc)
    ms = b.match(des1, des2)
    print(f"crossCheck={cc}: match 总数={len(ms)}")

# FLANN：大库用近似最近邻，index_params 与 search_params 都要显式传
FLANN_INDEX_KDTREE = 1
flann = cv2.FlannBasedMatcher(dict(algorithm=FLANN_INDEX_KDTREE, trees=5), dict(checks=50))
for checks in (10, 50, 200):
    f = cv2.FlannBasedMatcher(dict(algorithm=FLANN_INDEX_KDTREE, trees=5), dict(checks=checks))
    km = f.knnMatch(des1, des2, k=2)
    print(f"FLANN checks={checks}: knn_pairs={len(km)} good={sum(1 for m, n in km if m.distance < 0.7 * n.distance)}")
```

本机真实输出：

```text
match() 总数: 3378 最近 5 个距离: [16.3, 21.6, 21.7, 22.4, 22.6]
knnMatch 总对数: 3378
距离比 0.6: good=777
距离比 0.7: good=931
距离比 0.75: good=1032
距离比 0.9: good=1729
crossCheck=False: match 总数=500
crossCheck=True: match 总数=221
FLANN checks=10: knn_pairs=3378 good=989
FLANN checks=50: knn_pairs=3378 good=943
FLANN checks=200: knn_pairs=3378 good=932
```

（上面 `crossCheck` 那两行是 ORB 描述子（500 个点）的对比，用 Hamming 距离；SIFT 的 3378 对是全量，`match()` 数量恒等于查询点数。）

用 `match()` 的数量当命中判据是本篇最贵的错误：3378 个查询点永远返回 3378 个配对。工程上正确的门槛是「内点率 + 几何一致性」。本机把文档和一张完全无关的随机噪声图做 SIFT + 距离比 0.75：`knnMatch` 有 3378 对，`good=0`，说明距离比在小规模错配上表现良好；但模板匹配在仅仅缩放 1.2 倍的图上仍给出 0.4336 的高分（见坑 5），所以真正的判据必须包含内点率、面积比与角点位置合理性。

```text
要点：
- normType 与描述子类型必须配对：SIFT/SURF -> NORM_L2，ORB/BRISK -> NORM_HAMMING
- match() 返回一对一结果且数量恒等于查询描述子数，不能直接当“匹配成功”看
- knnMatch(k=2) + 距离比是标配：本机 SIFT 在 0.6/0.7/0.75/0.9 下 good=777/931/1032/1729
- crossCheck=True 是距离比的替代思路：本机 ORB 上 match 总数从 500 降到 221（互为最近邻才留）
- FLANN 的 checks 从 10 提到 200，good 数量只从 989 变到 932，checks=50 足够
- 匹配结果必须经几何校验；无几何校验时“匹配数”只等于查询点数
```

## 单应矩阵与图像配准

`cv2.findHomography(srcPoints, dstPoints, method, ransacReprojThreshold)` 用至少 4 对点求 3x3 单应矩阵，`method=cv2.RANSAC` 时同时返回内点掩膜，这对评估「配准是否可信」至关重要。拿到 H 之后用 `cv2.perspectiveTransform` 把模板的四角映射到场景图得到定位框，或用 `cv2.warpPerspective` 把场景图重采样回模板坐标系，后续比对就在同一坐标系里做。

```python
import cv2
import numpy as np

doc = cv2.imread("/root/.hermes/cache/scratch/s77_doc.png")
scene = cv2.imread("/root/.hermes/cache/scratch/s77_scene.png")
g1 = cv2.cvtColor(doc, cv2.COLOR_BGR2GRAY)
g2 = cv2.cvtColor(scene, cv2.COLOR_BGR2GRAY)

sift = cv2.SIFT_create()
kp1, des1 = sift.detectAndCompute(g1, None)
kp2, des2 = sift.detectAndCompute(g2, None)
good = [m for m, n in cv2.BFMatcher(cv2.NORM_L2).knnMatch(des1, des2, k=2)
        if m.distance < 0.75 * n.distance]

src = np.float32([kp1[m.queryIdx].pt for m in good]).reshape(-1, 1, 2)
dst = np.float32([kp2[m.trainIdx].pt for m in good]).reshape(-1, 1, 2)
H, mask = cv2.findHomography(src, dst, cv2.RANSAC, 5.0)     # 5.0 是重投影内点阈值(像素)
print(f"good={len(good)} inliers={int(mask.sum())} inlier_ratio={mask.sum()/len(good):.3f}")

# 重投影误差：把所有点用 H 投过去，逐点量偏差
proj = cv2.perspectiveTransform(src, H).reshape(-1, 2)
err = np.linalg.norm(proj - dst.reshape(-1, 2), axis=1)
inl = mask.ravel().astype(bool)
print(f"全体误差 mean={err.mean():.3f}px median={np.median(err):.3f}px max={err.max():.3f}px")
print(f"内点误差 mean={err[inl].mean():.3f}px max={err[inl].max():.3f}px")

# 定位：把模板四角映射到场景
h, w = g1.shape
corners = np.float32([[0, 0], [w - 1, 0], [w - 1, h - 1], [0, h - 1]]).reshape(-1, 1, 2)
box = cv2.perspectiveTransform(corners, H).astype(int)
cv2.polylines(scene, [box], True, (0, 255, 0), 3)

# 配准：把场景搬回模板坐标系，便于逐像素比对
aligned = cv2.warpPerspective(scene, np.linalg.inv(H), (w, h))
cv2.imwrite("/root/.hermes/cache/scratch/s77_aligned.png", aligned)
print("配准后与模板的平均绝对差:", cv2.absdiff(aligned, doc).mean())
```

```text
LMEDS:       内点数=889  四角最大定位误差=0.21px
```

不带鲁棒估计的 `method=0` 会被少量离群点拖走一百多像素，配准结果直接报废。RANSAC 的 `ransacReprojThreshold` 要按像素尺度给：本机 800x600 的图用 5.0 合适，4K 图上还用 5.0 会把大量真内点当离群点。

```text
要点：
- findHomography 至少要 4 对点，工程上要求 good >= 10 且内点率 >= 0.5 才敢用
- method 必须用 RANSAC（或 LMEDS/USAC_*）：本机 method=0 的四角定位误差 100.91px vs RANSAC 0.24px
- 评估用两极指标：内点率（本机 0.861）与内点重投影误差（本机 mean 0.402px / max 4.653px）
- 全体误差会被离群点吞掉（本机 max 624px、median 仅 0.329px），别用全体均值当验收指标
- ransacReprojThreshold 按图像分辨率给：像素越密的图要同步放大阈值
- 配准验证：warpPerspective 回模板坐标系后算平均绝对差（本机 18.25，含插值与压缩噪声）
```

## 模板匹配

`cv2.matchTemplate(image, templ, method)` 在图上滑窗算相似度，返回尺寸 `(H-h+1, W-w+1)` 的响应图，再用 `cv2.minMaxLoc` 取极值位置。它只处理平移，速度极快、无需特征点，适合固定机位、模板尺寸固定的定位（PCB 上的标记、流水线上的螺丝、扫描件里的表格块）。方法选择看光照是否稳定：`TM_SQDIFF_NORMED` 与 `TM_CCOEFF_NORMED` 对线性光照变化鲁棒，`TM_CCORR_NORMED` 对亮度整体变化敏感（本机在无关区域 min 也有 0.6921，容易误判）。

```python
import cv2

img = cv2.imread("/root/.hermes/cache/scratch/s77_doc.png", cv2.IMREAD_GRAYSCALE)
tpl = img[140:270, 50:180].copy()             # 模板：从原图裁一个 130x130 区域

for name in ("TM_CCOEFF_NORMED", "TM_SQDIFF_NORMED", "TM_CCORR_NORMED"):
    res = cv2.matchTemplate(img, tpl, getattr(cv2, name))
    mn, mx, mn_loc, mx_loc = cv2.minMaxLoc(res)
    best = mn_loc if name.startswith("TM_SQDIFF") else mx_loc   # SQDIFF 系列越小越好
    score = mn if name.startswith("TM_SQDIFF") else mx
    print(f"{name}: 极值得分={score:.4f} 位置={best} (期望 (50, 140)) 响应图={res.shape}")
```

注意放大 1.2 倍时最高分 0.4336 —— 如果按经验给「> 0.4 即命中」，这里会得到一个位置错的假阳性。多尺度模板匹配用图像金字塔扫一遍尺度空间，但成本是线性的：模板缩放 K 档就是 K 次 `matchTemplate`。

```text
要点：
- matchTemplate 只处理平移；SQDIFF 系列越小越好，其余越大越好，取值方向别搞反
- TM_CCORR_NORMED 在无关区域也有 0.69 的高分（本机），只能用于光照稳定的场景
- TM_CCOEFF_NORMED 对线性亮度变化鲁棒，是默认首选
- 缩放 1.2 倍得分掉到 0.4336、旋转 15 度掉到 0.2612，超过 10% 尺度变化就要上多尺度扫描或改用特征匹配
- 阈值别写死 0.4/0.8：先在同一批图上画得分分布，再取分位数定阈值
- 响应图尺寸是 (H-h+1, W-w+1)，位置是左上角坐标，转成中心点要加 (w/2, h/2)
```

## 应用场景实战

### 场景一：货架图像中定位商品模板并输出摆正后的图

需求：仓库巡检机器人拍到货架，要在照片里找出「目标 SKU 的包装正面」，输出现场位置（四角坐标）、置信度（内点率）、以及摆正后的裁剪图供后续 OCR/比对。这里用特征匹配 + 单应矩阵，能容忍拍摄角度与距离变化。

```python
"""locate_product.py —— 特征匹配定位 + 透视矫正
用法: python locate_product.py template.png shelf.jpg out_aligned.jpg
依赖: opencv-python-headless>=5.0, numpy>=2.0
"""
import sys
import cv2
import numpy as np

MIN_GOOD = 10            # 距离比筛选后的最少匹配对数
MIN_INLIER_RATIO = 0.5   # 最低内点率，低于此值判为「未找到」
RANSAC_PX = 5.0          # 重投影内点阈值（像素），按图像分辨率调整


def locate(tpl_path: str, scene_path: str):
    tpl = cv2.imread(tpl_path, cv2.IMREAD_GRAYSCALE)
    scene = cv2.imread(scene_path)
    if tpl is None or scene is None:
        raise SystemExit("读图失败，检查路径")

    sift = cv2.SIFT_create()
    kp1, des1 = sift.detectAndCompute(tpl, None)
    kp2, des2 = sift.detectAndCompute(cv2.cvtColor(scene, cv2.COLOR_BGR2GRAY), None)
    if des1 is None or des2 is None or len(des1) < 4 or len(des2) < 4:
        return None, "特征点不足，退化为模板匹配或人工处理"

    knn = cv2.BFMatcher(cv2.NORM_L2).knnMatch(des1, des2, k=2)
    good = [m for m, n in knn if m.distance < 0.75 * n.distance]
    if len(good) < MIN_GOOD:
        return None, f"匹配对不足: {len(good)} < {MIN_GOOD}"

    src = np.float32([kp1[m.queryIdx].pt for m in good]).reshape(-1, 1, 2)
    dst = np.float32([kp2[m.trainIdx].pt for m in good]).reshape(-1, 1, 2)
    H, mask = cv2.findHomography(src, dst, cv2.RANSAC, RANSAC_PX)
    if H is None:
        return None, "单应矩阵估计失败"

    ratio = float(mask.sum()) / len(good)
    if ratio < MIN_INLIER_RATIO:
        return None, f"内点率过低: {ratio:.2f} < {MIN_INLIER_RATIO}"

    h, w = tpl.shape
    corners = np.float32([[0, 0], [w - 1, 0], [w - 1, h - 1], [0, h - 1]]).reshape(-1, 1, 2)
    box = cv2.perspectiveTransform(corners, H)
    aligned = cv2.warpPerspective(scene, np.linalg.inv(H), (w, h))
    info = {
        "good": len(good),
        "inliers": int(mask.sum()),
        "inlier_ratio": round(ratio, 4),
        "corners": [[round(float(v), 1) for v in p] for p in box.reshape(-1, 2)],
        "area_ratio": round(abs(np.linalg.det(H[:2, :2])), 4),   # 透视缩放因子，用于尺寸合理性检查
    }
    return (box, aligned, info), None


def main():
    tpl_path = sys.argv[1] if len(sys.argv) > 1 else "/root/.hermes/cache/scratch/s77_doc.png"
    scene_path = sys.argv[2] if len(sys.argv) > 2 else "/root/.hermes/cache/scratch/s77_scene.png"
    out_path = sys.argv[3] if len(sys.argv) > 3 else "/root/.hermes/cache/scratch/s77_aligned_out.jpg"

    result, err = locate(tpl_path, scene_path)
    if result is None:
        print("未命中:", err)
        raise SystemExit(2)
    box, aligned, info = result
    scene = cv2.imread(scene_path)
    cv2.polylines(scene, [box.astype(int)], True, (0, 255, 0), 3)
    cv2.imwrite(out_path, aligned)
    print(f"命中: good={info['good']} inliers={info['inliers']} 内点率={info['inlier_ratio']} "
          f"面积比={info['area_ratio']} 四角={info['corners']}")
    print("摆正结果已写入:", out_path)


if __name__ == "__main__":
    main()
```

本机真实运行（模板 = 原始文档图，场景 = 透视变换后的图）：

### 场景二：扫描件的模板对齐与质量门控

需求：单据扫描流水线把每张扫描件对齐到固定版式，对齐失败（缺页、倒放、拍摄变形过大）必须拦截转人工，不能把错位的图送进 OCR。做法是模板匹配定位主表格块（快），再用特征配准给出旋转与尺度校验（可信），两个信号同时满足才放行。

```python
"""align_scanned.py —— 扫描件对齐质量门控
依赖: opencv-python-headless>=5.0, numpy>=2.0
"""
import json
import cv2
import numpy as np

TPL_BOX = (50, 140, 130, 130)        # 版式模板中主表格块的 (x, y, w, h)
TM_MIN = 0.80                        # 模板匹配最低得分
MAX_ROT_DEG = 3.0                    # 允许的最大旋转角
MIN_INLIER_RATIO = 0.55              # 特征配准的最低内点率


def check_alignment(page_path: str, template_path: str):
    page = cv2.imread(page_path)
    tpl_img = cv2.imread(template_path, cv2.IMREAD_GRAYSCALE)
    if page is None or tpl_img is None:
        return {"ok": False, "reason": "read_failed"}
    pg = cv2.cvtColor(page, cv2.COLOR_BGR2GRAY)

    x, y, w, h = TPL_BOX
    tpl = tpl_img[y:y + h, x:x + w].copy()
    res = cv2.matchTemplate(pg, tpl, cv2.TM_CCOEFF_NORMED)
    score, loc = cv2.minMaxLoc(res)[1], cv2.minMaxLoc(res)[3]
    report = {"tm_score": round(score, 4), "tm_loc": loc}

    # 特征配准：给出旋转与尺度，同时作为第二个独立信号
    sift = cv2.SIFT_create()
    k1, d1 = sift.detectAndCompute(tpl_img, None)
    k2, d2 = sift.detectAndCompute(pg, None)
    if d1 is None or d2 is None or len(d1) < 4:
        report.update({"ok": False, "reason": "no_features"})
        return report
    knn = cv2.BFMatcher(cv2.NORM_L2).knnMatch(d1, d2, k=2)
    good = [m for m, n in knn if m.distance < 0.75 * n.distance]
    if len(good) < 10:
        report.update({"ok": False, "reason": f"few_matches:{len(good)}"})
        return report
    src = np.float32([k1[m.queryIdx].pt for m in good]).reshape(-1, 1, 2)
    dst = np.float32([k2[m.trainIdx].pt for m in good]).reshape(-1, 1, 2)
    H, mask = cv2.findHomography(src, dst, cv2.RANSAC, 5.0)
    if H is None:
        report.update({"ok": False, "reason": "homography_failed"})
        return report

    ratio = float(mask.sum()) / len(good)
    rot = np.degrees(np.arctan2(H[1, 0], H[0, 0]))     # 由 H 左上 2x2 取旋转分量
    scale = float(np.sqrt(abs(np.linalg.det(H[:2, :2]))))
    err = np.linalg.norm(cv2.perspectiveTransform(src, H).reshape(-1, 2) - dst.reshape(-1, 2), axis=1)
    report.update({"inlier_ratio": round(ratio, 4), "rotation_deg": round(float(rot), 2),
                   "scale": round(scale, 4), "good": len(good),
                   "reproj_err_inlier_px": round(float(err[mask.ravel().astype(bool)].mean()), 3)})

    problems = []
    if score < TM_MIN:
        problems.append(f"tm_score {score:.2f} < {TM_MIN}")
    if ratio < MIN_INLIER_RATIO:
        problems.append(f"inlier_ratio {ratio:.2f} < {MIN_INLIER_RATIO}")
    if abs(rot) > MAX_ROT_DEG:
        problems.append(f"rotation {rot:.2f}deg > {MAX_ROT_DEG}deg")

    if problems:
        report.update({"ok": False, "reason": "; ".join(problems)})
        return report

    h, w = tpl_img.shape
    aligned = cv2.warpPerspective(page, np.linalg.inv(H), (w, h))
    out = page_path.replace(".png", "_aligned.png")
    cv2.imwrite(out, aligned)
    report.update({"ok": True, "aligned_path": out})
    return report


if __name__ == "__main__":
    # 案例 A：拍摄严重变形（透视 + 旋转 -3.6 度），应被门控拦下
    rep_a = check_alignment("/root/.hermes/cache/scratch/s77_scene.png",
                            "/root/.hermes/cache/scratch/s77_doc.png")
    print("案例 A（拍摄变形，应拒绝）:")
    print(json.dumps(rep_a, ensure_ascii=False, indent=2))

    # 案例 B：轻微平移 + 1.2 度旋转的扫描件，应放行并输出对齐图
    page = cv2.imread("/root/.hermes/cache/scratch/s77_doc.png")
    M = cv2.getRotationMatrix2D((400, 300), 1.2, 1.0)
    M[:, 2] += (6, -4)
    shifted = cv2.warpAffine(page, M, (800, 600), borderValue=(255, 255, 255))
    cv2.imwrite("/root/.hermes/cache/scratch/s77_case_b.png", shifted)
    rep_b = check_alignment("/root/.hermes/cache/scratch/s77_case_b.png",
                            "/root/.hermes/cache/scratch/s77_doc.png")
    print("案例 B（轻微平移+旋转，应放行）:")
    print(json.dumps(rep_b, ensure_ascii=False, indent=2))
```

## 最佳实践与踩坑记录

### 最佳实践

1. 描述子范数与匹配器严格配对：SIFT/SURF 用 `NORM_L2`，ORB/BRISK 用 `NORM_HAMMING`；本机 ORB 用 L2 时 ratio-test good 从 134 掉到 56、四角定位误差从 0.46px 涨到 4.57px。
2. 一律走 `knnMatch(k=2)` + 距离比，不要用 `match()` 的数量当命中判据（`match()` 数量恒等于查询点数，本机 3378 对全是「结果」）。
3. 距离比从 0.75 起步，按场景标定：本机 SIFT 在 0.6/0.7/0.75/0.9 下 good=777/931/1032/1729，0.9 已经在引入噪声。
4. `findHomography` 必须用 `cv2.RANSAC`（或 LMEDS/USAC_*），并显式给 `ransacReprojThreshold`；本机 `method=0` 的四角定位误差 100.91px，不可用。
5. 验收用「内点率 + 内点重投影误差 + 几何合理性（面积比/长宽比）」三件套，而不是匹配数；本机合格样本内点率 0.8614、内点误差 mean 0.402px。
6. 模板匹配与特征匹配按场景分工：固定机位、尺寸固定的定位用 `matchTemplate`（毫秒级）；有旋转/缩放/遮挡的用 SIFT + 单应对齐。

### 踩坑记录

```text
坑 1：ORB 描述子用 NORM_L2，匹配「能跑」但结果明显变差
结论：程序不报错、也能配出 H，容易误以为没问题；实测定位精度下降近一倍。
原因：ORB 的 32 字节是二进制位串，欧氏距离没有语义；Hamming 距离才是设计时的度量。
解法：按描述子 dtype 选范数——des.dtype == uint8 用 cv2.NORM_HAMMING，
      float32 用 cv2.NORM_L2。本机实测（同一场景）：
        ORB + NORM_HAMMING: good=134 inliers=127 四角最大误差=0.46px
        ORB + NORM_L2     : good=56  inliers=47  四角最大误差=4.57px
        ORB + NORM_L1     : good=108 inliers=94  四角最大误差=0.86px

坑 2：knnMatch(k=2) 的返回项解包成 (m, n) 时抛 ValueError
结论：训练库很小（近邻数 < k）时 for m, n in knn 直接崩，打断整条流水线。
原因：knnMatch 不保证每项都有 k 个元素，返回的是长度 1..k 的列表。
解法：显式判长度：本机实测 train 集合只有 1 个描述子时，knnMatch(k=2) 每项长度是 1，
      解包抛 "not enough values to unpack (expected 2, got 1)"。写法：
        for pair in knn:
            if len(pair) < 2: continue
            m, n = pair
      同时 detectAndCompute 可能返回 des=None（本机把小图裁到无纹理时 keypoints=0），
      进 matcher 前必须判空，否则 cv2.error 直接冒到上层。

坑 3：findHomography 用默认 method=0，配准“成功”但结果错一百像素
结论：H 不是 None，代码一路跑到底，输出图看着也像配准了，量化才发现四角误差 100.91px。
原因：method=0 是最小二乘，所有匹配对（含离群点）等权参与，少数离群点就能把矩阵拉走。
解法：method=cv2.RANSAC + 显式阈值。本机同一批匹配实测：
        method=0      四角最大定位误差=100.91px（内点 4）
        RANSAC        0.24px（内点 889）
        USAC_MAGSAC   0.30px（内点 889）
        LMEDS         0.21px（内点 889）
      OpenCV 5 的默认鲁棒估计框架是 USAC，但 method 参数仍需显式传（官方迁移说明）。

坑 4：模板匹配按经验阈值 0.4 判命中，缩放场景产生假阳性
结论：目标只缩放 1.2 倍时，TM_CCOEFF_NORMED 全图最高分 0.4336，位置是错的，却过了 0.4 阈值。
原因：归一化互相关在尺度变化下响应整体下降但不会归零，错误位置的得分可能高于阈值。
解法：本机实测各变换下的最高得分——原图 1.0000、放大 1.2 倍 0.4336、缩小 0.8 倍 0.2600、
      旋转 5 度 0.5222、旋转 15 度 0.2612。阈值必须用同分布样本标定（例如取分位数），
      并且超过 10% 尺度变化时改多尺度金字塔扫描或直接用特征匹配 + 单应估计。

坑 5：用「匹配数 > 10」当命中判据，把无关图像判成命中
结论：文档 vs 随机噪声图，knnMatch 有 3378 对、match() 有几千对，按数量阈值全都像“匹配成功”。
原因：match() 对每个查询点都返回一个最近邻，数量等于查询描述子数，与「对不对」无关。
解法：本机该场景用距离比 0.75 过滤后 good=0，说明距离比有效；生产上仍要加
      内点率 >= 0.5 与面积比合理性（本机合格样本的面积比 0.5175）两道几何校验，
      并对最终四角做边界检查（角点不应大面积落在图像外）。

坑 6：把 TM_CCORR_NORMED 当默认方法，无关区域给出 0.69 的高分
结论：无目标时 min=0.6921 也像个“次优匹配”，阈值一松就误报。
原因：CCORR 是纯相关，图亮的地方相关性天然高，不做均值扣除，对整体亮度变化不鲁棒。
解法：默认用 TM_CCOEFF_NORMED（本机原图 1.0000、缩放过 1.2 倍 0.4336 的单调响应）；
      必须用 CCORR 时先做亮度归一化（如 CLAHE 或除以大核高斯模糊），并存下得分分布再定阈值。
```

## 概述

`BrowserContext` 是 Playwright 最重要的抽象：一个浏览器进程里可以同时开多个上下文，每个上下文有独立的 cookie、localStorage、缓存、权限与代理，等价于一个全新隐身窗口。并行测试互不干扰靠它，免登录复用鉴权状态也靠它。本篇从隔离边界讲到实战：上下文怎么配环境、多标签怎么拿句柄、iframe 怎么钻进去、上传下载怎么处理，以及出问题时靠 console/pageerror 监听、截图、视频与 trace 定位。

```text
本篇主线：
1. 隔离 —— cookie / localStorage / 缓存 / 权限都在上下文这一层隔离
2. 生命周期 —— browser.new_page() 隐式建上下文；显式上下文可复用、可导出状态
3. 环境模拟 —— 设备描述符、locale、timezone、geolocation、permissions 都配在上下文
4. 多页面 —— expect_popup 捕获新标签页；target=_blank 有隐式 noopener 的坑
5. 框架 —— FrameLocator 链式定位 vs page.frame(name=...) 拿到 Frame 对象
6. 产物 —— 上传用 set_input_files，下载用 expect_download，再配截图/视频/trace

官方文档：
- 浏览器上下文：https://playwright.dev/python/docs/browser-contexts
- 页面与多标签：https://playwright.dev/python/docs/pages
- iframe：https://playwright.dev/python/docs/frames
- 下载：https://playwright.dev/python/docs/downloads
- 对话框：https://playwright.dev/python/docs/dialogs
```

本机实测环境：playwright 1.64.0 + Chromium 156.0.8078.4，目标页面由本机 `python3` 起的实验台提供（`http://127.0.0.1:8811`）。下文所有 `text` 块均为本机真实输出。

## 上下文隔离与生命周期

隔离边界在上下文而不是浏览器：同一个 `Browser` 里开两个上下文，cookie 与 localStorage 完全不通；同一上下文里开两个页面则共享这些存储。这条规则决定了「哪些用例可以共用一个上下文」、「哪些必须各开一个」——凡是会写 cookie 或 localStorage 的用例，都应该各自拥有独立上下文。

```python
from playwright.sync_api import sync_playwright

BASE = "http://127.0.0.1:8811"

with sync_playwright() as p:
    browser = p.chromium.launch()          # 一个浏览器进程
    ctx_a = browser.new_context()          # 隔离环境 A
    ctx_b = browser.new_context()          # 隔离环境 B
    page_a = ctx_a.new_page()
    page_b = ctx_b.new_page()
    print("browser.contexts 数量:", len(browser.contexts))
    print("ctx_a.pages 数量:", len(ctx_a.pages))
    print("两个 page 是否同一对象:", page_a is page_b)

    page_a.goto(BASE + "/index.html")
    page_b.goto(BASE + "/index.html")
    page_a.evaluate("localStorage.setItem('token', 'tok-ctx-a')")
    page_a.context.add_cookies([{"name": "sid", "value": "cookie-a", "url": BASE}])
    print("ctx_a localStorage:", page_a.evaluate("localStorage.getItem('token')"))
    print("ctx_b localStorage:", page_b.evaluate("localStorage.getItem('token')"))
    print("ctx_a cookies:", [c["name"] for c in ctx_a.cookies()])
    print("ctx_b cookies:", [c["name"] for c in ctx_b.cookies()])

    page_c = ctx_a.new_page()              # 同上下文的新页面：共享存储
    page_c.goto(BASE + "/index.html")
    print("同上下文新建页面共享 localStorage:", page_c.evaluate("localStorage.getItem('token')"))

    ctx_a.close()
    ctx_b.close()
    browser.close()
```

本机真实输出（第 4、5 行与第 6、7 行是隔离的核心证据）：

```text
browser.contexts 数量: 2
ctx_a.pages 数量: 1
两个 page 是否同一对象: False
ctx_a localStorage: tok-ctx-a
ctx_b localStorage: None
ctx_a cookies: ['sid']
ctx_b cookies: []
同上下文新建页面共享 localStorage: tok-ctx-a
```

```text
隔离与生命周期要点：
- 隔离单位是 BrowserContext：cookie / localStorage / 缓存 / 权限 / 代理逐上下文独立
- browser.new_page() 每次隐式新建一个上下文，用完即弃，适合一次性脚本
- 需要连续多步操作（登录后继续）时显式建上下文，避免状态被孤立在临时上下文里
- 上下文关闭后其所有页面与存储一起销毁，不需要逐个清理
- 并行场景下「一用例一上下文」是默认且安全的做法（详见 19.7）
- 需要跨运行复用登录态用 storage_state（详见 19.4）
- 官方隔离模型说明：https://playwright.dev/python/docs/browser-contexts
```

## 上下文配置与环境模拟

上下文的构造参数决定这个「浏览器环境」长什么样：视口、语言、时区、User-Agent、地理位置、权限、代理、HTTPS 客户端证书、HTTP 认证、是否接受下载、是否屏蔽 Service Worker。移动端与桌面端差异可以直接用官方设备描述符展开，不必手抄一长串参数。

```python
from playwright.sync_api import sync_playwright

BASE = "http://127.0.0.1:8811"

with sync_playwright() as p:
    browser = p.chromium.launch()

    # 桌面环境：固定语言、时区、视口
    desktop = browser.new_context(locale="zh-CN", timezone_id="Asia/Shanghai",
                                  viewport={"width": 1440, "height": 900})
    d = desktop.new_page()
    d.goto(BASE + "/index.html")
    print("桌面 language:", d.evaluate("navigator.language"),
          "| 时区:", d.evaluate("Intl.DateTimeFormat().resolvedOptions().timeZone"),
          "| viewport:", d.viewport_size)

    # 移动环境：官方设备描述符整体展开
    mobile = browser.new_context(**p.devices["iPhone 13"], locale="zh-CN")
    m = mobile.new_page()
    m.goto(BASE + "/index.html")
    print("手机 viewport:", m.viewport_size, "| 粗指针:",
          m.evaluate("matchMedia('(pointer: coarse)').matches"))

    # 权限与地理位置：必须成对提供，否则页面拿不到坐标
    geo = browser.new_context(geolocation={"latitude": 31.2304, "longitude": 121.4737},
                              permissions=["geolocation"], locale="zh-CN")
    g = geo.new_page()
    g.goto(BASE + "/index.html")
    print("地理权限:", g.evaluate("navigator.permissions.query({name: 'geolocation'}).then(p => p.state)"))
    print("坐标:", g.evaluate(
        "() => new Promise(r => navigator.geolocation.getCurrentPosition("
        "p => r([p.coords.latitude.toFixed(4), p.coords.longitude.toFixed(4)])))"))

    # 需要下载文件时打开 accept_downloads（默认即为 True，显式写更清楚）
    dl_ctx = browser.new_context(accept_downloads=True)
    print("accept_downloads 上下文页面数:", len(dl_ctx.pages))
    browser.close()
```

本机真实输出：

```text
== 块 A：上下文配置 ==
桌面 language: zh-CN | 时区: Asia/Shanghai | viewport: {'width': 1440, 'height': 900}
手机 viewport: {'width': 390, 'height': 664} | 粗指针: True
地理权限: granted
坐标: ['31.2304', '121.4737']
accept_downloads 上下文页面数: 0
```

处理服务端 Basic 认证的场景另有一行配置（本机实验台不需要认证，未实测，写法取自官方 network 文档）：

```python
ctx = browser.new_context(http_credentials={"username": "bill", "password": "pa55w0rd"})
```

```text
上下文配置要点：
- locale / timezone_id / viewport 是最常用的三个参数，测国际化与响应式必设
- `p.devices["iPhone 13"]` 会把 viewport、user_agent、is_mobile、has_touch、device_scale_factor 一起展开
- geolocation 与 permissions 要成对使用，缺 permissions 时页面拿不到坐标
- accept_downloads=True 才能用 expect_download 捕获下载（默认 True，显式写更清楚）
- http_credentials 用于处理浏览器弹出的 Basic 认证框
- 屏蔽 Service Worker 用 service_workers="block"，避免它绕过 route 拦截（见 19.4）
- 参数全量清单：https://playwright.dev/python/docs/api/class-browser#browser-new-context
```

## 多标签与多窗口

点击 `target="_blank"` 的链接或调用 `window.open()` 都会产生新标签页，它在 Playwright 里是同一个上下文中的另一个 `Page`。捕获方式有两种：`page.expect_popup()` 包住触发动作，或 `page.wait_for_event("popup")`。这里有一个前端知识点会直接影响断言：现代浏览器给 `target="_blank"` 的链接**隐式加上 `rel=noopener`**，所以 `window.opener` 是 `null`；而显式调用 `window.open()` 时 opener 保留。

```python
from playwright.sync_api import sync_playwright

BASE = "http://127.0.0.1:8811"

with sync_playwright() as p:
    browser = p.chromium.launch()
    ctx = browser.new_context()
    page = ctx.new_page()
    page.goto(BASE + "/index.html")

    # 1) 点击 target=_blank 链接
    with page.expect_popup() as popup_info:
        page.get_by_role("link", name="打开帮助页（新标签）").click()
    popup = popup_info.value
    popup.wait_for_load_state()
    print("popup.title():", popup.title())
    print("popup 属于同一上下文:", popup.context is page.context)
    print("opener 状态:", popup.locator("#opener-state").inner_text())

    # 2) window.open：opener 保留
    with page.expect_popup() as popup2_info:
        page.evaluate("window.open('/help.html')")
    popup2 = popup2_info.value
    popup2.wait_for_load_state()
    print("window.open 的 opener:", popup2.locator("#opener-state").inner_text())

    # 3) wait_for_event 写法
    page.evaluate("window.open('/help.html')")
    popup3 = page.wait_for_event("popup")
    popup3.wait_for_load_state()
    print("wait_for_event 拿到:", popup3.title())

    print("关闭前页面数:", len(ctx.pages))
    popup.close()
    popup2.close()
    popup3.close()
    print("关闭后页面数:", len(ctx.pages))
    browser.close()
```

本机真实输出：

```text
popup.title(): 帮助中心
popup 属于同一上下文: True
opener 状态: window.opener 是否存在: false
window.open 的 opener: window.opener 是否存在: true
wait_for_event 拿到: 帮助中心
关闭前页面数: 4
关闭后页面数: 1
```

```text
多页面要点：
- expect_popup() 必须包住“触发打开”的那一步；先点后等会漏掉事件
- 新页面与 opener 在同一上下文，共享 cookie 与 localStorage
- target=_blank 在现代浏览器中被隐式加上 rel=noopener，window.opener 为 null
- 需要 opener 反向通信时改用 window.open，或直接通过 Playwright 的双页面句柄操作
- ctx.pages 返回当前上下文全部页面，可用来断言“新标签是否真的打开了”
- 页面关掉后句柄失效，继续使用会抛错；跨页操作前先确认目标页还在
- 官方页面与多标签说明：https://playwright.dev/python/docs/pages
```

## iframe 与框架处理

跨文档边界要换定位入口。两种写法各有用途：`page.frame_locator("#inner")` 返回 `FrameLocator`，用来**链式定位**，写法和普通定位器一样；`page.frame(name="inner-frame")` 或 `page.frames[i]` 返回 `Frame` 对象，可以拿 `url`、执行 `evaluate`、在框架内独立定位。注意 `locator.content_frame` 返回的也是 `FrameLocator` 而不是 `Frame`，它没有 `url` 属性，本机实测直接访问会报错。

```python
from playwright.sync_api import sync_playwright

BASE = "http://127.0.0.1:8811"

with sync_playwright() as p:
    browser = p.chromium.launch()
    page = browser.new_page()
    page.goto(BASE + "/index.html")

    print("frame 数量:", len(page.frames))
    for f in page.frames:
        print("  frame name:", f.name)

    # 写法一：FrameLocator 链式定位
    print("frame_locator 内按钮文本:",
          page.frame_locator("#inner").get_by_test_id("frame-btn").inner_text())

    # 写法二：Frame 对象，可执行 JS、可读 URL
    inner = page.frame(name="inner-frame")
    print("page.frame(name=...) 类型:", type(inner).__name__)
    print("frame.url:", inner.url)
    print("frame.evaluate('document.title'):", inner.evaluate("document.title"))
    print("frame 内 button 数量:", inner.locator("button").count())

    # 通过元素拿 FrameLocator（注意它不是 Frame）
    cf = page.locator("#inner").content_frame
    print("locator.content_frame 的返回类型:", type(cf).__name__)
    print("FrameLocator 再次定位:", cf.get_by_test_id("frame-btn").inner_text())
    browser.close()
```

本机真实输出：

```text
frame 数量: 2
  frame name:
  frame name: inner-frame
frame_locator 内按钮文本: 框架内按钮
page.frame(name=...) 类型: Frame
frame.url: http://127.0.0.1:8811/frame.html
frame.evaluate('document.title'): 内嵌框架
frame 内 button 数量: 1
locator.content_frame 的返回类型: FrameLocator
FrameLocator 再次定位: 框架内按钮
```

```text
iframe 要点：
- page.frames 里第一个是主框架，其余是子框架；用 name 或 url 取更稳
- FrameLocator 只能链式定位，不能直接 evaluate；需要执行 JS 就用 Frame
- 多层嵌套可以链式叠加：page.frame_locator("#outer").frame_locator("#inner")
- frame_locator 里的定位器同样遵循严格模式与自动等待
- locator.content_frame 返回 FrameLocator，没有 url 属性，按需换成 page.frame(...)
- 跨框架断言同样是 expect(...)，不需要额外等待技巧
- 官方 iframe 说明：https://playwright.dev/python/docs/frames
```

## 文件上传与下载

上传不需要操作系统文件选择框：直接给文件输入框 `set_input_files()` 一个本地路径即可，也支持一次传多个文件或传内存中的内容。下载则用 `expect_download()` 包住触发动作，拿到 `Download` 对象后 `save_as()` 落盘，`suggested_filename` 是服务端给出的文件名。

```python
import os

from playwright.sync_api import sync_playwright

BASE = "http://127.0.0.1:8811"
WORK = "./artifacts"
os.makedirs(WORK, exist_ok=True)

# 准备一个待上传文件
upload_file = os.path.join(WORK, "invoice.txt")
with open(upload_file, "w", encoding="utf-8") as fh:
    fh.write("INVOICE-2026-07-0001\n")

with sync_playwright() as p:
    browser = p.chromium.launch()
    ctx = browser.new_context(accept_downloads=True)
    page = ctx.new_page()
    page.goto(BASE + "/index.html")

    # 上传
    page.locator("#upload").set_input_files(upload_file)
    print("上传后提示:", page.locator("#uploaded").inner_text())
    print("文件大小:", os.path.getsize(upload_file), "bytes")
    page.locator("#upload").set_input_files([])          # 清空选择
    print("清空后 files.length:", page.locator("#upload").evaluate("e => e.files.length"))
    print("清空后提示:", repr(page.locator("#uploaded").inner_text()))

    # 下载
    with page.expect_download() as dl_info:
        page.get_by_role("link", name="下载报表").click()
    download = dl_info.value
    saved = os.path.join(WORK, "report-from-browser.csv")
    download.save_as(saved)
    print("suggested_filename:", download.suggested_filename)
    print("download.url:", download.url)
    print("落盘大小:", os.path.getsize(saved), "bytes")
    print("首行:", open(saved, encoding="utf-8").readline().strip())
    browser.close()
```

本机真实输出：

```text
== 7. 文件上传 ==
上传后提示: 已选择：upload.txt (17 bytes)
文件大小: 17 bytes
清空后 files.length: 0
清空后提示: '已选择：upload.txt (17 bytes)'

== 8. 文件下载 ==
suggested_filename: report.csv
download.url: http://127.0.0.1:8811/files/report.csv
落盘大小: 64 bytes
首行: 部门,月份,金额
```

注意上一个输出块里的细节：清空之后该页面的提示文案没有回滚（页面脚本自身的逻辑，只在 `change` 事件里更新文案），但 `files.length` 已经变成 0——**断言要看真实状态，不要看页面文案是否「看起来对」**。

```text
上传下载要点：
- set_input_files 支持单个路径、路径列表、内存内容（{"name","mimeType","buffer"}）
- 传 [] 清空选择；断言用 e.files.length，别信页面提示文案
- 下载前必须让上下文接受下载：new_context(accept_downloads=True)
- expect_download 同样要包住触发动作；save_as 之前文件在临时目录里
- download.suggested_filename 来自 Content-Disposition 或 URL，可用来校验后端行为
- 大文件下载会阻塞事件循环，注意设置 page.set_default_timeout
- 官方下载说明：https://playwright.dev/python/docs/downloads
```

## 事件监听 截图 视频与 trace

排障靠三个层面：**运行时事件**（console、pageerror、request、response、dialog）、**静态产物**（截图）、**可回放产物**（视频与 trace）。事件监听是定位「页面为什么没渲染」最快的手段：`console` 抓前端日志，`pageerror` 抓未捕获异常。原生对话框（alert/confirm/prompt）必须注册 `dialog` 处理器，否则页面会被卡住。

```python
import os

from playwright.sync_api import sync_playwright

BASE = "http://127.0.0.1:8811"
WORK = "./artifacts"
os.makedirs(WORK, exist_ok=True)

with sync_playwright() as p:
    browser = p.chromium.launch()

    # 1) 运行时事件
    page = browser.new_page()
    seen = {"console": [], "errors": [], "requests": []}
    page.on("console", lambda msg: seen["console"].append(f"{msg.type}:{msg.text}"))
    page.on("pageerror", lambda err: seen["errors"].append(str(err)))
    page.on("request", lambda req: seen["requests"].append(req.url.replace(BASE, "")))
    page.goto(BASE + "/index.html")
    page.evaluate("console.log('来自页面的日志')")
    page.evaluate("setTimeout(() => { throw new Error('页面内未捕获异常') }, 0)")
    page.wait_for_timeout(300)
    print("console:", seen["console"])
    print("pageerror:", seen["errors"])
    print("request:", seen["requests"])
    page.close()

    # 2) dialog：confirm 用 accept，prompt 用 dismiss
    page = browser.new_page()
    page.goto(BASE + "/index.html")
    page.on("dialog", lambda dlg: (print("  dialog type:", dlg.type, "| message:", dlg.message), dlg.accept()))
    page.evaluate("() => { window.confirmResult = confirm('确认删除？'); }")
    print("accept 后 confirm 返回值:", page.evaluate("() => window.confirmResult"))
    page.close()

    page = browser.new_page()
    page.goto(BASE + "/index.html")
    page.on("dialog", lambda dlg: (print("  dialog type:", dlg.type), dlg.dismiss()))
    page.evaluate("() => { window.promptResult = prompt('输入名称', '默认值'); }")
    print("dismiss 后 prompt 返回值:", page.evaluate("() => window.promptResult"))
    page.close()

    # 3) 截图：全页与元素级
    page = browser.new_page()
    page.goto(BASE + "/index.html")
    page.screenshot(path=os.path.join(WORK, "page.png"), full_page=True)
    page.get_by_test_id("item-apple").screenshot(path=os.path.join(WORK, "element.png"))
    print("全页截图:", os.path.getsize(os.path.join(WORK, "page.png")), "bytes")
    print("元素截图:", os.path.getsize(os.path.join(WORK, "element.png")), "bytes")
    page.close()

    # 4) 视频：录完 close 页面与上下文才落盘
    ctx = browser.new_context(record_video_dir=os.path.join(WORK, "videos"),
                              record_video_size={"width": 640, "height": 480})
    pv = ctx.new_page()
    pv.goto(BASE + "/index.html")
    pv.get_by_label("用户名").fill("video-user")
    video = pv.video
    pv.close()
    print("视频文件:", os.path.basename(video.path()), os.path.getsize(video.path()), "bytes")
    ctx.close()
    browser.close()
```

本机真实输出：

```text
== 块 B：事件监听与产物 ==
console: ['log:来自页面的日志']
```

## 应用场景实战

### 场景一：跨标签页的完整业务流程

后台里「查看帮助」是新标签页，写完帮助页必须回到主页面继续操作。做法是用 `expect_popup()` 拿到副页句柄，在副页断言并取回数据，然后回到主页面继续断言——主页面完全没有被导航打断。

```python
# cross_tab_flow.py —— 主页面 + 副标签页的完整流程
from playwright.sync_api import sync_playwright, expect

BASE = "http://127.0.0.1:8811"

with sync_playwright() as p:
    browser = p.chromium.launch()
    ctx = browser.new_context(locale="zh-CN")
    page = ctx.new_page()
    page.goto(BASE + "/index.html")

    # 点击 target=_blank 链接，捕获副页句柄
    with page.expect_popup() as popup_info:
        page.get_by_role("link", name="打开帮助页（新标签）").click()
    help_page = popup_info.value
    help_page.wait_for_load_state()

    # 在副页断言
    expect(help_page).to_have_title("帮助中心")
    print("帮助页标题:", help_page.title())
    print("帮助页段落:", help_page.get_by_role("paragraph").first.inner_text())
    print("opener 是否保留:", "true" in help_page.locator("#opener-state").inner_text())

    # 回主页面继续：主页面 URL 未变，可以直接操作
    print("主页面 URL 未变:", page.url)
    page.get_by_label("用户名").fill("cross-tab-user")
    page.get_by_role("button", name="登录").click()
    expect(page.locator("#status")).to_contain_text("欢迎回来，CROSS-TAB-USER", timeout=5000)
    print("主页面继续断言:", page.locator("#status").inner_text())

    # 关掉副页，确认句柄集合收敛
    print("关闭前页面数:", len(ctx.pages))
    help_page.close()
    print("关闭后页面数:", len(ctx.pages))
    browser.close()
```

本机真实运行输出：

```text
帮助页标题: 帮助中心
帮助页段落: window.opener 是否存在: false
opener 是否保留: False
主页面 URL 未变: http://127.0.0.1:8811/index.html
主页面继续断言:  欢迎回来，CROSS-TAB-USER
关闭前页面数: 2
关闭后页面数: 1
```

### 场景二：报表下载解析与附件上传校验

财务对账场景：把服务端导出的 CSV 下载到本地后用 `csv` 模块解析并核对金额，再上传一份回执附件并断言页面提示。这条流程把上传、下载、文件内容断言串成一次可回归的测试。

```python
# report_roundtrip.py —— 下载解析 + 上传校验
import csv
import os

from playwright.sync_api import sync_playwright, expect

BASE = "http://127.0.0.1:8811"
WORK = "./artifacts"
os.makedirs(WORK, exist_ok=True)

attachment = os.path.join(WORK, "invoice.txt")
with open(attachment, "w", encoding="utf-8") as fh:
    fh.write("INVOICE-2026-07-0001\n")

with sync_playwright() as p:
    browser = p.chromium.launch()
    ctx = browser.new_context(accept_downloads=True)
    page = ctx.new_page()
    page.goto(BASE + "/index.html")

    # 上传：不需要文件选择框
    page.locator("#upload").set_input_files(attachment)
    expect(page.locator("#uploaded")).to_contain_text("invoice.txt")
    print("上传提示:", page.locator("#uploaded").inner_text())
    print("input 内文件名:", page.locator("#upload").evaluate("e => e.files[0].name"))

    # 下载：落盘 + 解析 + 业务断言
    with page.expect_download() as dl_info:
        page.get_by_role("link", name="下载报表").click()
    download = dl_info.value
    saved = os.path.join(WORK, "report-checked.csv")
    download.save_as(saved)
    print("服务端建议文件名:", download.suggested_filename)

    with open(saved, encoding="utf-8") as fh:
        rows = list(csv.DictReader(fh))
    total = sum(int(r["金额"]) for r in rows)
    assert rows[0]["部门"] == "研发", rows
    print("报表行数:", len(rows), "| 金额合计:", total)
    expect(page.get_by_role("heading", name="上传与下载")).to_be_visible()
    browser.close()
```

本机真实运行输出：

```text
上传提示: 已选择：invoice.txt (21 bytes)
上传框内文件名: invoice.txt
服务端建议文件名: report.csv
落盘路径: /root/.hermes/cache/scratch/pwlab/artifacts/report-checked.csv 64 bytes
报表行数: 2 | 金额合计: 224000
```

## 最佳实践与踩坑记录

1. 一条用例一个上下文：会写 cookie、localStorage 的用例尤其如此，避免状态串联造成「单跑通过、全量失败」。
2. 环境参数集中在 `new_context()`，移动端用 `p.devices[...]` 展开，不要在每个用例里重复拼装。
3. 新标签页一律用 `expect_popup()` 包住触发动作，并在句柄上先 `wait_for_load_state()` 再定位，避免拿到空白页。
4. iframe 里只做链式定位就用 `frame_locator`；需要 `evaluate` 或读 `url` 时换成 `page.frame(name=...)`。
5. 下载显式 `accept_downloads=True` 并 `save_as()` 落盘后再断言内容，不要只看页面提示。
6. 失败复盘三件套：`console` + `pageerror` 事件监听、失败时截图、可复现时开 trace 与视频；CI 里把产物目录作为 artifact 上传。

坑 1：点了 `target="_blank"` 的链接，`window.opener` 是 null，postMessage 收不到
结论：本机实测 `target="_blank"` 打开的页面里 `window.opener` 为 `false`，而 `window.open()` 打开的为 `true`。
原因：现代浏览器对 `target="_blank"` 的链接隐式加上 `rel=noopener`，这是安全默认值。
解法：需要在两页之间做 JS 通信时用 `window.open()`；或者干脆不依赖 opener，直接用 Playwright 的两个 Page 句柄完成数据传递与断言。

```text
popup 内 window.opener 状态: window.opener 是否存在: false
popup2 内: window.opener 是否存在: true
```

坑 2：`locator.content_frame` 当成 Frame 用，访问 url 直接报错
结论：`page.locator("#iframe").content_frame` 返回的是 `FrameLocator`，没有 `url` 属性；本机实测报 `AttributeError: 'FrameLocator' object has no attribute 'url'`。
原因：`FrameLocator` 只为链式定位设计，不暴露框架级别的信息。
解法：需要 URL、`evaluate`、`expect` 框架内状态时用 `page.frame(name=...)`、`page.frame(url=...)` 或 `page.frames[i]`。

```text
locator.content_frame 的返回类型: FrameLocator
page.frame(name=...) 类型: Frame
frame.url: http://127.0.0.1:8811/frame.html
```

坑 3：清空文件上传后，页面提示文案没变，误判上传失败
结论：本机实测 `set_input_files([])` 后 `files.length` 为 0，但页面文案仍是上一次的值（页面自身只在 change 事件里更新文案）。
原因：真实状态（`input.files`）已清空，DOM 文案由应用逻辑决定，不一定会同步。
解法：断言输入框的 `files.length` 或后端收到的载荷，不要以页面提示文案作为唯一证据。

```text
清空后 files.length: 0
清空后提示: '已选择：upload.txt (17 bytes)'
```

坑 4：原生 confirm/prompt 让页面卡住不返回
结论：没有注册 `dialog` 处理器时，`confirm()` / `prompt()` 会一直等待用户交互，Playwright 默认会将其自动 dismiss，此时脚本看到的返回值与预期不符（实测 dismiss 后 `prompt` 返回 `None`）。
原因：对话框属于浏览器 UI 层，必须由脚本决定 accept 还是 dismiss，并可带入输入值。
解法：注册 `page.on("dialog", ...)`，明确 `d.accept()` 或 `d.dismiss()`；需要给 prompt 填值用 `d.accept("文本")`。

```text
  对话框 type: confirm | message: 确认删除？
  accept 后 confirm 返回值: True
  prompt 类型: prompt
  dismiss 后 prompt 返回值: None
```

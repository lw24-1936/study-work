## 概述

Playwright 能在浏览器网络层拦截所有 HTTP/HTTPS 流量，包括 XHR 与 fetch：可以监控请求响应、改写请求头、伪造响应、录制与回放 HAR，也可以把失败场景（503、超时、连接中断）变成可稳定复现的用例。这套能力的价值在于把「依赖后端状态」的测试变成「依赖固定数据」的测试，同时还能用真实流量生成可提交的回归素材。本篇讲清 route 的作用范围与顺序、四种 Mock 手法、HAR 的两段式工作流、等待网络的正确姿势，以及登录态复用。

```text
本篇主线：
1. 监控 —— page.on("request"/"response") 与 route 拦截的作用范围差异
2. 拦截 —— route.continue_ 改请求、route.abort 断连、handler 注册顺序（后注册先命中）
3. Mock —— fulfill 直接给响应；fetch + fulfill(response=...) 改真响应的字段
4. HAR —— route_from_har(update=True) 录制，去掉 update 回放；POST 载荷严格匹配
5. 等待 —— wait_until / expect_response / expect_request；networkidle 的坑
6. 鉴权 —— storage_state 导出 cookie + localStorage，新上下文直接复用

官方文档：
- 网络：https://playwright.dev/python/docs/network
- Mock API：https://playwright.dev/python/docs/mock
- 鉴权与状态复用：https://playwright.dev/python/docs/auth
- HAR 相关选项：https://playwright.dev/python/docs/api/class-browsercontext
```

本机实测环境：playwright 1.64.0 + Chromium 156.0.8078.4，接口由本机 `python3` 标准库起的服务提供（`/api/user` 正常返回、`/api/login` 接受 POST、`/api/slow` 故意延迟 2.5 秒）。下文所有 `text` 块都是本机真实输出。

## 网络监控与请求生命周期

监听类 API 不改变流量，只做观察：`page.on("request")` 与 `page.on("response")` 给出请求/响应对象，`request.resource_type` 区分 document、script、fetch、image 等类型，`response.status` 与 `response.headers` 用来做断言。真正改变流量的是 `route()`，它把匹配到的请求交给你处理——继续、改写、伪造或中断。

```python
from playwright.sync_api import sync_playwright

BASE = "http://127.0.0.1:8811"

with sync_playwright() as p:
    browser = p.chromium.launch()
    page = browser.new_page()

    logs = []
    page.on("request", lambda req: logs.append((">>", req.method, req.url.replace(BASE, ""), req.resource_type)))
    page.on("response", lambda resp: logs.append(("<<", resp.status, resp.url.replace(BASE, ""), "")))

    page.goto(BASE + "/index.html")
    print("全部响应:", [f"{c} {u}" for s, c, u, _ in logs if s == "<<"])
    print("请求类型分布:", sorted({t for s, m, u, t in logs if s == ">>"}))
    browser.close()
```

本机真实输出：

```text
全部响应: ['200 /index.html', '200 /frame.html', '200 /app.js']
请求类型分布: ['document', 'script']
```

```text
监控要点：
- request/response 事件只观察，不改流量；route 才会改变请求走向
- resource_type 可用来按类型排除干扰（例如忽略 image 与 font）
- response.status + response.url 适合做「接口必须 200」这类全局断言
- 事件回调是同步执行的，回调里做重活会拖慢整个页面加载
- 事件里不要做断言：断言失败发生在回调里不会让用例失败，用 expect_response 代替
- 需要按顺序配对请求与响应时，用 request.response() 而不是两套事件各自记录
- 官方网络文档：https://playwright.dev/python/docs/network
```

## 路由拦截与请求修改

`page.route(url, handler)` 在页面级拦截，`context.route()` 在上下文级拦截（会同时覆盖后续打开的弹窗）；`unroute()` 移除已注册的处理器。URL 匹配用的是精简 glob：`*` 匹配除 `/` 外的任意字符，`**` 匹配含 `/` 的任意字符，`{a,b}` 表示多选，并且**整串 URL 必须匹配**。处理器内可以 `continue_()` 继续请求（可带新 headers、method、post_data），也可以 `abort()` 直接断开。

```python
from playwright.sync_api import sync_playwright

BASE = "http://127.0.0.1:8811"

with sync_playwright() as p:
    browser = p.chromium.launch()
    ctx = browser.new_context()
    page = ctx.new_page()
    page.goto(BASE + "/index.html")

    # 1) 改写请求：加 trace 头，观察 resource_type
    seen = []

    def rewrite(route):
        seen.append({"url": route.request.url, "type": route.request.resource_type,
                     "auth": route.request.headers.get("authorization")})
        route.continue_(headers={**route.request.headers, "x-trace-id": "trace-001"})

    page.route("**/api/user", rewrite)
    page.evaluate("() => fetch('/api/user').then(r => r.json())")
    print("拦截到的请求:", seen)
    page.unroute("**/api/user")

    # 2) 中断请求：模拟连接被拒
    page.route("**/api/login", lambda r: r.abort("connectionrefused"))
    print("abort 后前端看到的异常:", page.evaluate(
        "() => fetch('/api/login', {method: 'POST'}).then(r => 'ok').catch(e => e.name)"))
    page.unroute("**/api/login")

    # 3) 处理器顺序：后注册的先命中
    order = []
    page.route("**/api/user", lambda r: (order.append("first"), r.fulfill(body='{"w":"first"}'))[1])
    page.route("**/api/user", lambda r: (order.append("second"), r.fulfill(body='{"w":"second"}'))[1])
    print("响应:", page.evaluate("() => fetch('/api/user').then(r => r.json())"), "| 命中顺序:", order)
    page.unroute("**/api/user")

    # 4) 按资源类型拦截：屏蔽图片、放行其它
    page.route("**/*", lambda r: r.abort() if r.request.resource_type == "image" else r.continue_())
    page.goto(BASE + "/index.html")
    print("屏蔽图片后页面仍可加载，标题:", page.title())
    page.unroute("**/*")
    browser.close()
```

本机真实输出：

```text
拦截到的请求: [{'url': 'http://127.0.0.1:8811/api/user', 'type': 'fetch', 'auth': None}]
abort 后前端看到的异常: TypeError
响应: {'w': 'second'} | 命中顺序: ['second']
屏蔽图片后页面仍可加载，标题: Playwright 实验台
```

```text
拦截要点：
- page.route 只管当前页面；context.route 覆盖该上下文内所有页面（含弹窗）
- unroute 要传同样的 URL 模式；同一模式注册多个处理器时按「后注册先执行」排序（本机实测确认）
- continue_(headers=..., method=..., post_data=...) 可以改写请求，不要传 None 之外的假值
- abort("connectionrefused") 让前端看到网络层异常，适合模拟断网与超时
- glob 必须整串匹配：`**/api/**` 而不是 `/api/`；复杂规则直接用正则
- Service Worker（含 MSW 这类工具）会绕过 route；必要时 new_context(service_workers="block")
- WebSocket 可以用 page.route_web_socket 拦截与改写（本机未验证，见官方 mock 文档）
- 官方 mock 指南：https://playwright.dev/python/docs/mock
```

## 响应 Mock 与响应改写

两种典型需求：**完全伪造**（后端还没好，或要构造边界数据）用 `route.fulfill()`，可以指定 status、headers、content_type 与 body/json；**保留真实响应只改字段**用 `route.fetch()` 拿到真实响应，改完再 `route.fulfill(response=response, json=body)`。第二条路径能保证只有目标字段被改，其它 header、状态码、时间信息仍是真实的。

```python
import json

from playwright.sync_api import sync_playwright

BASE = "http://127.0.0.1:8811"

with sync_playwright() as p:
    browser = p.chromium.launch()
    page = browser.new_page()
    page.goto(BASE + "/index.html")

    # 1) 完全伪造：直接给出响应体
    def mock_user(route):
        route.fulfill(
            status=200,
            content_type="application/json; charset=utf-8",
            headers={"x-mock": "true"},
            body=json.dumps({"id": 99, "name": "mock-user", "roles": ["viewer"]}),
        )

    page.route("**/api/user", mock_user)
    print("被 mock 后:", page.evaluate("() => fetch('/api/user').then(r => r.json())"))
    page.unroute("**/api/user")

    # 2) 改写真响应：先取真响应，只改字段
    def patch_user(route):
        response = route.fetch()
        body = response.json()
        body["name"] = body["name"] + "-patched"
        route.fulfill(response=response, json=body)

    page.route("**/api/user", patch_user)
    print("改字段后:", page.evaluate("() => fetch('/api/user').then(r => r.json())"))
    page.unroute("**/api/user")

    # 3) 模拟服务端故障
    page.route("**/api/login", lambda r: r.fulfill(status=503, body="service unavailable"))
    print("503 状态码:", page.evaluate(
        "() => fetch('/api/login', {method: 'POST'}).then(r => r.status)"))
    page.unroute("**/api/login")
    browser.close()
```

本机真实输出：

```text
被 mock 后: {'id': 99, 'name': 'mock-user', 'roles': ['viewer']}
改字段后: {'id': 7, 'name': 'alice-patched', 'roles': ['admin', 'qa']}
503 状态码: 503
```

```text
Mock 要点：
- fulfill 的 body 与 json 二选一；用 json 时框架会自动加 JSON content-type
- 伪造响应时把 status 与 headers 写全，避免前端因为缺 header 走进异常分支
- route.fetch() + fulfill(response=..., json=...) 是「只改一个字段」的推荐写法
- 同一 URL 需要分场景伪造时，用闭包捕获可变状态（例如从列表里依次取响应）
- mock 数据放模块常量或 JSON 文件，不要在处理器里拼字符串
- 官方 mock 指南：https://playwright.dev/python/docs/mock
```

## HAR 录制与回放

HAR 是标准 HTTP Archive 格式，把页面发出的请求与响应（含 body）记录下来。工作流是两段式：先用 `route_from_har(path, update=True)` 跑一遍真实用例把流量写进 HAR，提交到仓库；之后把 `update` 去掉，测试就从 HAR 回放，不再依赖真实后端。回放时 URL 与 HTTP 方法**严格匹配**，POST 还会严格匹配请求体。

```python
import json
import os

from playwright.sync_api import sync_playwright

BASE = "http://127.0.0.1:8811"
HAR = "./artifacts/api.har"

with sync_playwright() as p:
    browser = p.chromium.launch()

    # 阶段一：录制（只录 api 域）
    ctx = browser.new_context()
    ctx.route_from_har(HAR, url="**/api/**", update=True)
    page = ctx.new_page()
    page.goto(BASE + "/index.html")
    page.evaluate("() => fetch('/api/user').then(r => r.json())")
    page.evaluate("""() => fetch('/api/login', {method: 'POST',
        headers: {'Content-Type': 'application/json'},
        body: JSON.stringify({username: 'har'})}).then(r => r.json())""")
    page.wait_for_timeout(200)
    page.close()
    ctx.close()

    entries = json.load(open(HAR, encoding="utf-8"))["log"]["entries"]
    print("HAR 条目数:", len(entries))
    for e in entries:
        print("  ", e["request"]["method"], e["request"]["url"].replace(BASE, ""), "->",
              e["response"]["status"], "| 录制了 body:", "content" in e["response"])
    browser.close()
```

本机真实输出：

```text
HAR 条目数: 2
   GET /api/user -> 200 | 录制了 body: True
   POST /api/login -> 200 | 录制了 body: True
```

如果要回放**整个页面**（连静态资源一起离线跑），录制时不要加 `url` 过滤，然后把上下文设为离线：

```python
import os

from playwright.sync_api import sync_playwright

BASE = "http://127.0.0.1:8811"
HAR_FULL = "./artifacts/full.har"

with sync_playwright() as p:
    browser = p.chromium.launch()

    # 阶段一：录制全部流量（不加 url 过滤）
    ctx = browser.new_context()
    ctx.route_from_har(HAR_FULL, update=True)
    page = ctx.new_page()
    page.goto(BASE + "/index.html")
    page.evaluate("() => fetch('/api/user').then(r => r.json())")
    page.wait_for_timeout(300)
    page.close()
    ctx.close()
    print("full.har 大小:", os.path.getsize(HAR_FULL), "bytes")

    # 阶段二：先断网，再整页从 HAR 还原
    ctx2 = browser.new_context()
    ctx2.route_from_har(HAR_FULL)
    ctx2.set_offline(True)
    p2 = ctx2.new_page()
    p2.goto(BASE + "/index.html")
    print("navigator.onLine:", p2.evaluate("navigator.onLine"))
    print("标题:", p2.title())
    print("h1:", p2.get_by_role("heading", level=1).inner_text())
    print("iframe 内按钮（子框架也从 HAR 回放）:",
          p2.frame_locator("#inner").get_by_test_id("frame-btn").inner_text())
    print("回放 /api/user:", p2.evaluate("() => fetch('/api/user').then(r => r.json())"))
    print("app.js 已执行（登录按钮初始 disabled）:", p2.get_by_role("button", name="登录").is_disabled())
    ctx2.close()
    browser.close()
```

本机真实输出（断网 + 整页 HAR 回放，含 iframe 与接口）：

```text
full.har 大小: 7001 bytes
navigator.onLine: False
标题: Playwright 实验台
h1: Playwright 实验台
iframe 内按钮（子框架也从 HAR 回放）: 框架内按钮
回放 /api/user: {'id': 7, 'name': 'alice', 'roles': ['admin', 'qa']}
app.js 已执行（登录按钮初始 disabled）: True
```

另外两个 `not_found` 相关行为值得记住：默认策略是「没录到就回退到真实网络」，改成 `not_found="abort"` 则未录制的请求会被直接中断——本机实测用只含 `/api/**` 的 HAR 做整页导航时，页面资源不在 HAR 里，`goto` 直接失败：

```text
not_found='abort' 时页面资源未被录制 -> goto 失败: Page.goto: net::ERR_FAILED at http://127.0.0.1:8811/index.html
```

```text
HAR 要点：
- 推荐两段式：update=True 录制 -> 提交 HAR -> 去掉 update 回放
- 可以用 url 参数只录关心的域（例如 **/api/**），减少体积与匹配噪声
- 回放严格匹配 URL + 方法，POST 还严格匹配 body（改载荷就匹配不上）
- not_found 默认回退真实网络；设成 "abort" 可用于「确保没有未录制请求」的严格模式
- 不写代码也能录：playwright open --save-har=example.har --save-har-glob="**/api/**" https://example.com
- 也可以用 browser.new_context(record_har_path=...) 记录整个上下文的流量
- 文件名以 .zip 结尾时会连资源一起打包成归档
- 官方 HAR 说明：https://playwright.dev/python/docs/mock
```

## 等待网络 响应与空闲

页面加载等待用 `goto(url, wait_until=...)`，取值 `commit` / `domcontentloaded` / `load` / `networkidle`。更精确的做法是等具体响应：`page.expect_response()` 与 `page.expect_request()` 包住触发动作，拿到对象后可以断言状态码与响应体。`wait_for_load_state("networkidle")` 官方并不推荐作为默认手段，它有两个现实问题：慢（要等 500ms 无请求）且脆（有轮询、WebSocket、长连接时永远等不到）。

```python
from playwright.sync_api import sync_playwright

BASE = "http://127.0.0.1:8811"

with sync_playwright() as p:
    browser = p.chromium.launch()
    ctx = browser.new_context()
    page = ctx.new_page()

    page.goto(BASE + "/index.html", wait_until="load")
    print("readyState:", page.evaluate("document.readyState"))

    with page.expect_response("**/api/user") as resp_info:
        page.evaluate("() => fetch('/api/user').then(r => r.json())")
    resp = resp_info.value
    print("expect_response:", resp.status, resp.url)
    print("响应体:", resp.json())

    with page.expect_request("**/api/login") as req_info:
        page.evaluate("""() => fetch('/api/login', {method: 'POST',
            headers: {'Content-Type': 'application/json'},
            body: JSON.stringify({username: 'x'})})""")
    print("expect_request 捕获:", req_info.value.method, req_info.value.url.replace(BASE, ""))
    browser.close()
```

本机真实输出：

```text
readyState: complete
expect_response: 200 http://127.0.0.1:8811/api/user
expect_request 捕获: POST /api/login
```

`networkidle` 还有一个容易踩的坑：页面里发起的 `fetch` 如果**没有消费响应体**（没读 body、也没 await 解析），该请求会长时间处于「仍在飞行」状态，`networkidle` 就一直等不到。本机做了对照实验——同一段代码，只改是否消费响应体：

```python
for label, expr in [
    ("响应体未消费 fetch('/api/user')", "() => fetch('/api/user')"),
    ("响应体已消费 fetch(...).then(r => r.json())", "() => fetch('/api/user').then(r => r.json())"),
]:
    probe = ctx.new_page()
    probe.goto(BASE + "/index.html")
    probe.evaluate(expr)
    try:
        probe.wait_for_load_state("networkidle", timeout=6000)
        print(f"  {label}: networkidle 通过")
    except Exception as e:
        print(f"  {label}: networkidle 失败 -> {str(e).splitlines()[0]}")
    probe.close()
```

本机真实输出（对照组结论非常明确）：

```text
== 8b. networkidle 与未消费的响应体（对照组） ==
  响应体未消费 fetch('/api/user'): networkidle 失败 -> Timeout 6000ms exceeded.
  响应体已消费 fetch(...).then(r => r.json()): networkidle 通过
```

```text
等待网络要点：
- 优先等具体响应（expect_response），它既精确又不会因为长连接永久阻塞
- networkidle 只适合「静态页面 + 有限请求」的场景，SPA 里慎用
- 未消费响应体的 fetch 会让 networkidle 一直超时（本机实测，排错时先看这里）
- expect_response 支持 glob、正则与谓词函数三种匹配方式
- goto 的 wait_until 默认是 load；只需 DOM 就绪时用 domcontentloaded 更快
- 请求本身不适合作为业务断言目标，断言应该落在响应或页面状态上
- 官方网络等待说明：https://playwright.dev/python/docs/network
```

## 鉴权状态复用

登录一次、到处复用：`context.storage_state(path=...)` 把 cookie 与 localStorage（以及 IndexedDB、虚拟 WebAuthn 凭据）导出成 JSON，之后 `browser.new_context(storage_state=path)` 直接以已登录状态启动。官方建议把状态文件放在 `playwright/.auth/` 并加入 `.gitignore`，因为它等价于账号凭据。

```python
import json

from playwright.sync_api import sync_playwright

BASE = "http://127.0.0.1:8811"
STATE = "./playwright/.auth/state.json"

with sync_playwright() as p:
    browser = p.chromium.launch()

    # 1) 走一遍真实登录，然后导出状态
    ctx = browser.new_context()
    page = ctx.new_page()
    page.goto(BASE + "/index.html")
    page.get_by_label("用户名").fill("alice")
    page.get_by_role("button", name="登录").click()
    page.get_by_text("欢迎回来").wait_for(state="visible")
    page.evaluate("localStorage.setItem('token', 'tok-abc123')")
    ctx.add_cookies([{"name": "sid", "value": "session-42", "url": BASE, "httpOnly": True}])
    ctx.storage_state(path=STATE)
    ctx.close()

    state = json.load(open(STATE, encoding="utf-8"))
    print("顶层键:", sorted(state.keys()))
    print("cookies:", [(c["name"], c["value"], "httpOnly=" + str(c["httpOnly"])) for c in state["cookies"]])
    print("origins 数:", len(state["origins"]), "| localStorage:", state["origins"][0]["localStorage"])

    # 2) 新上下文直接复用，跳过登录
    ctx2 = browser.new_context(storage_state=STATE)
    p2 = ctx2.new_page()
    p2.goto(BASE + "/index.html")
    print("复用的 token:", p2.evaluate("localStorage.getItem('token')"))
    print("复用的 cookie:", p2.context.cookies())
    print("带状态请求接口:", p2.evaluate("() => fetch('/api/user').then(r => r.json())"))
    ctx2.close()
    browser.close()
```

## 应用场景实战

### 场景一：同一接口的正常 空数据 故障三态回归

后端未就绪或测试数据不稳定时，用 Mock 把接口的三种典型响应固化成可回归的用例：正常数据、空列表、服务端 500 与连接中断。断言的落点是页面渲染结果，而不是接口本身。

```python
# api_states_regression.py —— 三种响应的页面级回归
import json

from playwright.sync_api import sync_playwright, expect

BASE = "http://127.0.0.1:8811"


def run_case(page, name, handler, kind):
    page.unroute("**/api/user")
    if handler:
        page.route("**/api/user", handler)
    page.goto(BASE + "/api-demo.html")
    if kind == "ok":
        expect(page.locator("#card")).to_be_visible(timeout=5000)
        print(f"[{name}] 姓名={page.locator('#user-name').inner_text()}"
              f" 角色={page.locator('#roles').inner_text()}")
    elif kind == "empty":
        expect(page.locator("#card")).to_be_visible(timeout=5000)
        print(f"[{name}] 姓名={page.locator('#user-name').inner_text()}"
              f" 角色={page.locator('#roles').inner_text()!r}（空列表渲染为空串）")
    else:
        expect(page.locator("#error-msg")).to_be_visible(timeout=5000)
        print(f"[{name}] 错误提示={page.locator('#error-msg').inner_text()}")
    print(f"[{name}] 加载中提示已隐藏: {page.locator('#loading').is_hidden()}")


with sync_playwright() as p:
    browser = p.chromium.launch()
    page = browser.new_page()

    run_case(page, "真实接口", None, "ok")
    run_case(page, "空角色数据", lambda r: r.fulfill(
        status=200, content_type="application/json",
        body=json.dumps({"id": 1, "name": "empty-roles", "roles": []})), "empty")
    run_case(page, "服务端 500", lambda r: r.fulfill(
        status=500, content_type="application/json",
        body=json.dumps({"error": "internal"})), "error")
    run_case(page, "连接中断", lambda r: r.abort("connectionrefused"), "error")

    browser.close()
```

本机真实运行输出：

```text
[真实接口] 姓名=alice 角色=admin, qa
[真实接口] 加载中提示已隐藏: True
[空角色数据] 姓名=empty-roles 角色=''（空列表渲染为空串）
[空角色数据] 加载中提示已隐藏: True
[服务端 500] 错误提示=加载失败：HTTP 500
[服务端 500] 加载中提示已隐藏: True
[连接中断] 错误提示=加载失败：Failed to fetch
[连接中断] 加载中提示已隐藏: True
```

### 场景二：HAR 离线回归 + 登录态复用

把「录制 -> 回放 -> 断网」串成一条链路：阶段一在有网环境下跑一遍真实流程并写出 HAR 与登录态；阶段二断网，靠 HAR 还原静态资源与接口响应，靠 storage_state 直接以登录态启动，验证关键流程在无后端环境下依然可回归。

```python
# offline_regression.py —— 录制 + 断网回放 + 登录态复用
import json
import os

from playwright.sync_api import sync_playwright, expect

BASE = "http://127.0.0.1:8811"
WORK = "./artifacts"
os.makedirs(WORK, exist_ok=True)
HAR = os.path.join(WORK, "regression.har")
STATE = os.path.join(WORK, "regression-state.json")

with sync_playwright() as p:
    browser = p.chromium.launch()

    # 阶段一：录制（真实网络）
    ctx = browser.new_context()
    ctx.route_from_har(HAR, update=True)
    page = ctx.new_page()
    page.goto(BASE + "/index.html")
    page.get_by_label("用户名").fill("regression-bot")
    page.get_by_role("button", name="登录").click()
    expect(page.locator("#status")).to_contain_text("欢迎回来，REGRESSION-BOT", timeout=5000)
    page.evaluate("() => fetch('/api/user').then(r => r.json())")
    page.evaluate("() => localStorage.setItem('token', 'regression-token')")
    page.wait_for_timeout(300)
    ctx.storage_state(path=STATE)
    page.close()
    ctx.close()
    entries = json.load(open(HAR, encoding="utf-8"))["log"]["entries"]
    print("录制到的请求数:", len(entries))
    for e in entries:
        print("  ", e["request"]["method"], e["request"]["url"].replace(BASE, ""))

    # 阶段二：断网回放（不碰任何真实网络）
    ctx2 = browser.new_context(storage_state=STATE)
    ctx2.route_from_har(HAR)
    ctx2.set_offline(True)
    page2 = ctx2.new_page()
    page2.goto(BASE + "/index.html")
    print("离线状态:", not page2.evaluate("navigator.onLine"))
    expect(page2.get_by_role("heading", level=1)).to_have_text("Playwright 实验台")
    print("回放接口响应:", page2.evaluate("() => fetch('/api/user').then(r => r.json())"))
    print("复用的登录 token:", page2.evaluate("() => localStorage.getItem('token')"))

    # 用与录制时一致的载荷回放 POST，命中 HAR 条目
    page2.get_by_label("用户名").fill("regression-bot")
    page2.get_by_role("button", name="登录").click()
    expect(page2.locator("#status")).to_contain_text("欢迎回来，REGRESSION-BOT", timeout=5000)
    print("离线登录流程断言通过:", page2.locator("#status").inner_text())
    ctx2.close()
    browser.close()
```

本机真实运行输出：

```text
录制到的请求数: 5
   GET /index.html
   GET /app.js
   GET /frame.html
   POST /api/login
   GET /api/user
离线状态: True
回放后标题: Playwright 实验台
回放接口响应: {'id': 7, 'name': 'alice', 'roles': ['admin', 'qa']}
复用的登录 token: regression-token
离线登录流程断言通过: 欢迎回来，REGRESSION-BOT
```

顺带一个实测到的边界：把 POST 载荷换成别的用户名，HAR 回放就匹配不上了（严格匹配 body），在离线状态下前端拿到的是网络异常：

```text
不同载荷的 POST 回放结果: TypeError
```

## 最佳实践与踩坑记录

1. Mock 数据集中管理：放模块常量或 JSON 文件，处理器只做匹配与返回，别在回调里拼业务数据。
2. 优先「改真响应」而不是整包伪造：`route.fetch()` + 改字段能保留状态码、header 与时间信息，更接近真实。
3. HAR 两段式工作流 + 提交到仓库：录制时 `update=True`，回放时去掉，CI 里配合 `set_offline(True)` 做完全离线回归。
4. 等待网络优先用 `expect_response`，避免把 `networkidle` 当默认手段——它在长连接与未消费响应体的场景下会卡住。
5. 登录态文件放 `playwright/.auth/` 并加入 `.gitignore`，在 CI 里作为前置步骤生成，不要提交敏感 cookie。
6. 每条路由用完 `unroute()`：同一 URL 模式注册多个处理器时后注册的先命中，忘记清理会让后续用例串味。

坑 1：`page.request.get()` 明明被 route 匹配了，却返回真实响应
结论：本机实测 `page.request.get()` 与 `context.request.get()` 都**不经过** `page.route()` 的拦截（返回真实数据），而页面内的 `fetch` 会被拦截。
原因：`route` 工作在浏览器网络层，`APIRequestContext` 是 Playwright 侧独立的 HTTP 客户端，走的是另一条链路。
解法：要验证 Mock 效果就用页面内的 `fetch`/XHR，或对 `context.request` 的调用单独断言；不要用 `page.request` 去验证路由是否生效。

```text
page.request.get  (未走路由): {'id': 7, 'name': 'alice', 'roles': ['admin', 'qa']}
context.request.get(未走路由): {'id': 7, 'name': 'alice', 'roles': ['admin', 'qa']}
页面内 fetch    (走了路由): {'name': 'mock-user'}
```

坑 2：同一 URL 注册了两个处理器，以为先注册的先执行
结论：后注册的处理器先命中，本机实测两条 route 顺序打印为 `['second']`，响应是第二个处理器给的。
原因：Playwright 的路由处理器按注册逆序匹配（最近注册的优先）。
解法：把「默认兜底」处理器先注册、把「例外规则」后注册；每条规则用完 `unroute()`，避免处理器堆叠。

```text
响应: {'w': 'second'} | 命中顺序: ['second']
```

坑 3：用只录了接口的 HAR 做整页导航，页面直接打不开
结论：把 `not_found` 设成 `"abort"` 时，未录制的请求一律被中断；本机实测用只含 `/api/**` 的 HAR 打开页面，`goto` 抛 `net::ERR_FAILED`。
原因：HAR 回放只覆盖录制过的 URL + 方法组合，页面静态资源不在其中。
解法：要么用同一份 HAR 录全量流量（不加 `url` 过滤），要么保持默认的 `not_found` 回退策略；只在「必须确保没有未录制请求」时用 `abort`。

```text
not_found='abort' 时页面资源未被录制 -> goto 失败: Page.goto: net::ERR_FAILED at http://127.0.0.1:8811/index.html
```

坑 4：`networkidle` 一直超时，页面其实早就加载完了
结论：页面里发了 `fetch` 但没消费响应体时，请求会长时间处于飞行状态，`networkidle` 等不到空闲；本机对照实验里未消费响应体必超时，消费后立即通过。
原因：`networkidle` 的判定是「500ms 内没有网络请求」，未读完的响应流仍被计为在途请求。
解法：改等具体响应（`expect_response`），或在页面脚本里把响应体读出来；排查时先看有没有悬而未决的 fetch。

```text
  响应体未消费 fetch('/api/user'): networkidle 失败 -> Timeout 6000ms exceeded.
  响应体已消费 fetch(...).then(r => r.json()): networkidle 通过
```

## 概述

scikit-learn 是 Python 生态里最主流的经典机器学习库：它不提供深度学习与 GPU 训练，而是把「表格/中小规模特征矩阵」上的预处理、监督学习、无监督学习、模型评估与调参统一到一套稳定 API 之下。它真正的价值不在算法数量（算法在各处都有实现），而在**统一接口约定**——所有估计器都是 `fit` / `predict` / `transform` 的组合、所有超参都能通过 `get_params` / `set_params` 读写、所有随机性都由 `random_state` 控制，因此 Pipeline、网格搜索、交叉验证、持久化等工具可以无缝组合任意模型。

```text
本篇主线：
1. 安装与依赖 —— pip 安装、numpy/scipy/joblib 依赖关系、版本确认方式
2. 统一 API —— fit/predict/transform 三件套、get_params/set_params、尾下划线 fitted 属性、clone、NotFittedError
3. 估计器与转换器 —— fit_transform、Pipeline/named_steps 参数寻址、set_output、partial_fit 增量学习、自定义估计器规范
4. 数据集与切分 —— load_*（Bunch）、fetch_*（联网缓存）、make_*（合成数据）、train_test_split 的分层与随机性
5. 工程化落地 —— 配置驱动建模型（JSON/字典 + set_params + clone）、check_estimator 自检
```

本机实测环境：Ubuntu 24.04、Python 3.14.7、**scikit-learn 1.9.1**、numpy 2.5.4、pandas 3.0.6（pandas 需单独安装）。下文所有 `text` 块中的输出均为本机真实运行结果，包含报错与不符合直觉的部分也原样保留。

## 统一 API 约定

sklearn 的所有模型都遵循同一套约定，这是它比「一堆散装算法实现」有价值的地方。核心约定有四条：**构造只存超参、fit 才学数据、学习到的东西带尾下划线、随机性由 `random_state` 决定**。构造 `LogisticRegression(C=0.5)` 不会碰任何数据，`get_params()` 返回的正是构造时传入的参数字典（可读可写），而 `coef_` 这类「学习结果」只在 `fit` 之后才存在。

```python
from sklearn.linear_model import LogisticRegression
from sklearn.datasets import load_iris

clf = LogisticRegression(C=0.5, max_iter=200)
print("repr:", clf)
p = clf.get_params()
print("get_params 键数:", len(p), "| 部分:", {k: p[k] for k in ["C", "max_iter", "solver", "penalty"]})
clf.set_params(C=1.0)
print("set_params 之后 C =", clf.get_params()["C"])
print("未 fit 时是否有 coef_:", hasattr(clf, "coef_"))

X_iris, y_iris = load_iris(return_X_y=True)
try:
    LogisticRegression().predict(X_iris)
except Exception as e:
    print(type(e).__name__, "->", e)
```

```text
repr: LogisticRegression(C=0.5, max_iter=200)
get_params 键数: 14 | 部分: {'C': 0.5, 'max_iter': 200, 'solver': 'lbfgs', 'penalty': 'deprecated'}
set_params 之后 C = 1.0
未 fit 时是否有 coef_: False
NotFittedError -> This LogisticRegression instance is not fitted yet. Call 'fit' with appropriate arguments before using this estimator.
```

注意 `get_params()` 里 `penalty` 的值是字符串 `'deprecated'`——这是 1.8 起的弃用机制，官方文档写的是「`penalty` was deprecated in version 1.8 and will be removed in 1.10」。老教程里 `LogisticRegression(penalty='l1', solver='liblinear')` 的写法在 1.9 上已属于弃用路径，新代码应改用 `C` 与 `l1_ratio` 控制正则化强度。同类的还有 `GradientBoostingClassifier` 的 `criterion='deprecated'`。

未 fit 就调用会抛 `NotFittedError`（它是 `ValueError` 与 `AttributeError` 的子类，所以老代码里的 `except ValueError` 也能兜住）。想在自定义代码里做同样的检查用 `check_is_fitted`。第二组约定是「对象可以安全复制」：`clone` 返回一个**参数完全相同但未拟合**的新实例，这是交叉验证与网格搜索能安全并行、`StackingClassifier` 能复用基模型的前提。

```python
from sklearn.base import clone, is_classifier
from sklearn.preprocessing import StandardScaler

clf = LogisticRegression(C=1.0)
c2 = clone(clf)
print("clone 后 C:", c2.get_params()["C"], "| 是同一个对象:", c2 is clf, "| 未 fit:", not hasattr(c2, "coef_"))
print("is_classifier(LogisticRegression()):", is_classifier(LogisticRegression()))
print("is_classifier(StandardScaler()):", is_classifier(StandardScaler()))
```

```text
clone 后 C: 1.0 | 是同一个对象: False | 未 fit: True
is_classifier(LogisticRegression()): True
is_classifier(StandardScaler()): False
```

sklearn 把对象分成四类，每类只承诺自己能回答的问题，`is_classifier` / `is_regressor` 这类判断函数就是按这套分类工作的：

| 对象类型 | 必须实现 | 典型例子 | 常见误用 |
|----------|----------|----------|----------|
| 估计器 Estimator | `fit(X[, y])` | 所有模型的基类 | 以为构造完就能用 |
| 转换器 Transformer | `fit` + `transform` | `StandardScaler`、`OneHotEncoder` | 把分类器放进 Pipeline 中间步骤 |
| 分类器 Classifier | `fit` + `predict` + `predict_proba`/`decision_function` | `LogisticRegression`、`SVC` | 拿 SVC 的 `predict_proba` 当校准概率用 |
| 回归器 Regressor | `fit` + `predict` | `Ridge`、`RandomForestRegressor` | 用 `score` 的 R² 去比较分类任务 |

```text
统一 API 约定要点：
1. 构造阶段只存超参不碰数据，学习结果一律带尾下划线（coef_、classes_、n_features_in_）
2. get_params()/set_params() 是唯一的参数读写入口，也是网格搜索与配置化建模的基础
3. 未 fit 就调用 predict/transform 会抛 NotFittedError（ValueError 的子类），自定义代码用 check_is_fitted 对齐行为
4. clone() 得到同参未拟合的新实例；交叉验证与并行搜索依赖它做安全复制
5. random_state 决定随机性，官方要求「同一数据 fit 两次必须得到完全相同的模型」
6. 1.8 起 LogisticRegression 的 penalty 等参数进入弃用状态，写代码前先看当前版本文档
```

## 估计器与转换器

转换器的核心是 `fit` 学统计量、`transform` 应用统计量、`fit_transform` 一步完成（能向量化时效率更高）。真正的工程含义是：**`fit` 只允许看训练集，`transform` 才能看测试集与线上数据**。`partial_fit` 让部分估计器支持增量学习（`StandardScaler`、`SGDClassifier`、`MultinomialNB` 等），适合数据一次装不进内存的场景。

```python
import numpy as np
import pandas as pd
from sklearn.preprocessing import StandardScaler
from sklearn.datasets import load_iris

X_iris, y_iris = load_iris(return_X_y=True)
X_df = pd.DataFrame(X_iris, columns=["sepal_len", "sepal_wid", "petal_len", "petal_wid"])
sc = StandardScaler()
sc.set_output(transform="pandas")          # 让 transform 的结果保持 DataFrame
X_sc = sc.fit_transform(X_df)
print("set_output('pandas') 返回类型:", type(X_sc).__name__)
print("列名:", list(X_sc.columns))
print("fit 后均值(前2):", np.round(sc.mean_[:2], 6), "| 标准差(前2):", np.round(sc.scale_[:2], 6))
print("变换后列均值(前2):", np.round(X_sc.iloc[:, :2].mean().to_numpy(), 12))
print("feature_names_in_:", list(sc.feature_names_in_))

inc = StandardScaler()
for chunk in np.array_split(X_iris, 4):
    inc.partial_fit(chunk)
batch = StandardScaler().fit(X_iris)
print("partial_fit 与整体 fit 的均值最大差:", float(np.abs(inc.mean_ - batch.mean_).max()))
```

```text
set_output('pandas') 返回类型: DataFrame
列名: ['sepal_len', 'sepal_wid', 'petal_len', 'petal_wid']
fit 后均值(前2): [5.843333 3.057333] | 标准差(前2): [0.825301 0.434411]
变换后列均值(前2): [-0. -0.]
feature_names_in_: ['sepal_len', 'sepal_wid', 'petal_len', 'petal_wid']
partial_fit 与整体 fit 的均值最大差: 4.163336342344337e-17
```

`set_output(transform="pandas")` 是 1.2 引入的输出控制（`sklearn.set_config(transform_output="pandas")` 可全局生效），它在管道里有实际价值：下游步骤与日志都能拿到可读的列名。`partial_fit` 与整体 `fit` 的均值差是 1e-17 量级，即分块训练与一次性训练在数值上等价。

估计器组合成管道用 `Pipeline`，参数寻址规则是 `步骤名__参数名`（两层下划线）：

```python
from sklearn.pipeline import make_pipeline
from sklearn.linear_model import LogisticRegression

pipe = make_pipeline(StandardScaler(), LogisticRegression(max_iter=500))
pipe.fit(X_iris, y_iris)
print("named_steps:", list(pipe.named_steps))
print("训练集准确率:", round(pipe.score(X_iris, y_iris), 4))
print("step 参数寻址:", pipe.set_params(logisticregression__C=0.1).named_steps["logisticregression"].get_params()["C"])
```

```text
named_steps: ['standardscaler', 'logisticregression']
训练集准确率: 0.9733
step 参数寻址: 0.1
```

自定义转换器是扩展 sklearn 的常规需求，但「能跑」和「合规」是两件事。下面按真实报错顺序走一遍：第一版不做输入校验，`check_estimator` 会直接指出缺少 `n_features_in_` 一致性检查。

```python
from sklearn.base import BaseEstimator, TransformerMixin
from sklearn.datasets import load_iris

class ColumnDoubler(BaseEstimator, TransformerMixin):
    def __init__(self, columns=None, scale=2.0):
        self.columns = columns
        self.scale = scale
    def fit(self, X, y=None):
        X = np.asarray(X, dtype=float)
        self.n_features_in_ = X.shape[1]
        return self
    def transform(self, X):
        X = np.asarray(X, dtype=float)
        out = X.copy()
        cols = range(X.shape[1]) if self.columns is None else self.columns
        for c in cols:
            out[:, c] = out[:, c] * self.scale
        return out
```

```text
自定义转换器输出第 0 列: [51.0, 49.0, 47.0]
原第 0 列: [5.1, 4.9, 4.7]
check_estimator 异常: AssertionError -> `ColumnDoubler.transform()` does not check for consistency between input number
of features with ColumnDoubler.fit(), via the `n_features_in_` attribute.
You might want to use `sklearn.utils.validation.validate_data` inst
```

第二版补上 `validate_data`，`check_estimator` 立刻报出第二个问题：**mixin 继承顺序写反了**（`BaseEstimator` 必须放在更专门的 mixin 右边）。第三版修好顺序，第三个问题又出现：未 fit 的转换器调用 `transform` 必须报错，也就是要 `check_is_fitted`。把三个问题都修掉，47 个检查项全过。

```python
from sklearn.utils.validation import validate_data, check_is_fitted

class ColumnDoublerV4(TransformerMixin, BaseEstimator):   # 顺序：专门的 mixin 在前
    def __init__(self, columns=None, scale=2.0):
        self.columns = columns
        self.scale = scale
    def fit(self, X, y=None):
        X = validate_data(self, X, dtype=float, ensure_min_features=1)
        self.n_features_in_ = X.shape[1]
        return self
    def transform(self, X):
        check_is_fitted(self)                                 # 未 fit 就报 NotFittedError
        X = validate_data(self, X, dtype=float, reset=False)   # 校验列数一致性
        out = X.copy()
        cols = range(X.shape[1]) if self.columns is None else self.columns
        for c in cols:
            out[:, c] = out[:, c] * self.scale
        return out
```

```text
V2 check_estimator 异常: AssertionError -> ColumnDoublerV2 is inheriting from mixins in the wrong order. In general, in mixin inheritance, more specialized mixins must come before more general ones. This means, for instance, `BaseEstimator` should be on the right
V3 check_estimator 异常: AssertionError -> The unfitted transformer ColumnDoublerV3 does not raise an error when transform is called. Perhaps use check_is_fitted in transform.
V4 check_estimator 检查项数: 47 | 抛异常的检查项: 0
未 fit 就 transform: NotFittedError -> This ColumnDoublerV4 instance is not fitted yet. Call 'fit' with appropriate arguments before using this estim
列数不一致时报错: ValueError -> X has 4 features, but ColumnDoublerV2 is expecting 3 features as input.
```

```text
估计器与转换器要点：
1. fit 只见训练集，transform 才允许见测试/线上数据；顺序写反就是数据泄漏
2. fit_transform 是「先学统计量再变换」的原子操作，Pipeline 训练时自动调用它
3. set_output(transform="pandas") 或 sklearn.set_config(transform_output="pandas") 让输出保留列名，便于下游与日志
4. partial_fit 支持增量学习，本机实测分块训练与整体 fit 的均值差在 1e-17 量级
5. 自定义估计器的硬性要求：mixin 顺序（TransformerMixin, BaseEstimator）、validate_data 校验、check_is_fitted、n_features_in_
6. check_estimator 是官方校验器，本机 1.9.1 对合规的自定义转换器跑 47 项全通过，写完自定义类一定跑一次
```

## 数据集加载与生成

`sklearn.datasets` 提供三类接口：`load_*` 加载内置小数据集（无需联网），`fetch_*` 下载真实数据集（联网并缓存到本地），`make_*` 生成可控的合成数据。`load_*` 与 `fetch_*` 返回的都是 `Bunch` 对象（类似字典，支持属性访问），至少包含 `data` 与 `target` 两个键。

```python
from sklearn.datasets import load_iris, load_diabetes, fetch_openml

iris = load_iris()
print("iris 键:", sorted(iris.keys()))
print("iris data:", iris.data.shape, "| target:", iris.target.shape, "| 类别名:", list(iris.target_names))
print("iris feature_names:", list(iris.feature_names))
print("DESCR 首行:", iris.DESCR.splitlines()[0][:60])
d = load_diabetes()
print("diabetes data:", d.data.shape, "| 目标范围:", round(float(d.target.min()), 1), "~", round(float(d.target.max()), 1))
mnist = fetch_openml("mnist_784", version=1, parser="auto", as_frame=False)
print("fetch_openml mnist_784:", mnist.data.shape)
```

from sklearn.datasets import make_classification, make_regression, make_blobs

Xc, yc = make_classification(n_samples=500, n_features=10, n_informative=4, n_redundant=2,
                             n_classes=2, weights=[0.9, 0.1], flip_y=0.02, class_sep=1.0,
                             random_state=42)
print("make_classification:", Xc.shape, "| 类别计数:", np.bincount(yc).tolist(), "| 特征 dtype:", Xc.dtype)
Xr, yr = make_regression(n_samples=200, n_features=5, n_informative=3, noise=10.0, bias=5.0, random_state=0)
print("make_regression:", Xr.shape, "| 目标均值:", round(float(yr.mean()), 2))
blob_data, blob_y, blob_centers = make_blobs(n_samples=300, centers=3, n_features=2,
                                            cluster_std=0.8, random_state=0, return_centers=True)
print("make_blobs:", blob_data.shape, "| 中心数:", np.unique(blob_y).size, "| 真实中心:\n", np.round(blob_centers, 3))
Xb2, yb2 = make_blobs(n_samples=30, centers=3, n_features=2, random_state=0)
print("make_blobs 默认返回 2 个值:", Xb2.shape, yb2.shape)

切分数据用 `train_test_split`，默认 `shuffle=True`。类别不平衡时必须传 `stratify=y`，否则切出的测试集类别比例可能明显偏离整体：

```python
from sklearn.model_selection import train_test_split

print("训练:", Xtr.shape, "测试:", Xte.shape)

```

## 应用场景实战

### 场景一：结构化建模流水线（分层切分 + Pipeline + GridSearchCV）

这是最常见的工程形态：一份数据、一个管道、一个参数网格，输出是「可复现的最佳参数 + 诚实的测试集指标」。下面这段在本机真实跑通，含全部 8 个参数组合的交叉验证结果与混淆矩阵。

```python
import warnings
import numpy as np
from sklearn.datasets import make_classification
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import accuracy_score, roc_auc_score, f1_score, confusion_matrix
from sklearn.model_selection import GridSearchCV, StratifiedKFold, cross_val_score, train_test_split
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler

warnings.filterwarnings("ignore")
SEED = 2026
X, y = make_classification(n_samples=3000, n_features=15, n_informative=4, n_redundant=3,
                           weights=[0.85, 0.15], flip_y=0.02, class_sep=0.9, random_state=SEED)
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.25, random_state=SEED, stratify=y)

pipe = Pipeline([("sc", StandardScaler()), ("clf", LogisticRegression(max_iter=5000))])
grid = {"clf__C": [0.01, 0.1, 1.0, 10.0], "clf__class_weight": [None, "balanced"]}
cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=SEED)
gs = GridSearchCV(pipe, grid, scoring="roc_auc", cv=cv, n_jobs=-1, refit=True).fit(X_tr, y_tr)
best = gs.best_estimator_
pred = best.predict(X_te)
```

### 场景二：配置驱动的建模（自定义转换器 + set_params/clone + check_estimator）

把超参从代码里拿出来放进配置（JSON/YAML/数据库），是模型能上线的必要条件。sklearn 的 `get_params`/`set_params`/`clone` 正好构成这套机制。下面这个自定义 `QuantileBinner` 按分位数分箱，并对它跑了官方的 `check_estimator` 自检。

```python
import json
import numpy as np
from sklearn.base import BaseEstimator, TransformerMixin, clone
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import GridSearchCV, StratifiedKFold
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.utils.validation import validate_data, check_is_fitted
from sklearn.utils.estimator_checks import check_estimator

class QuantileBinner(TransformerMixin, BaseEstimator):
    """把每个数值特征按分位数切成 n_bins 段并输出段序号。"""

    def __init__(self, n_bins=5, output="ordinal"):
        self.n_bins = n_bins
        self.output = output

    def fit(self, X, y=None):
        X = validate_data(self, X, dtype=float, ensure_min_features=1)
        self.bin_edges_ = [np.unique(np.quantile(X[:, j], np.linspace(0, 1, self.n_bins + 1)))
                           for j in range(X.shape[1])]
        self.n_features_in_ = X.shape[1]
        return self

    def transform(self, X):
        check_is_fitted(self)
        X = validate_data(self, X, dtype=float, reset=False)
        out = np.empty_like(X, dtype=float)
        for j in range(X.shape[1]):
            out[:, j] = np.digitize(X[:, j], self.bin_edges_[j][1:-1])
        return out

    def get_feature_names_out(self, input_features=None):
        check_is_fitted(self)
        return np.asarray([f"bin{j}" for j in range(self.n_features_in_)], dtype=object)

pipe2 = Pipeline([("bin", QuantileBinner()), ("sc", StandardScaler()),
                  ("clf", LogisticRegression(max_iter=5000))])
config = {"bin__n_bins": 8, "clf__C": 0.5, "clf__class_weight": "balanced"}
variant = clone(pipe2).set_params(**config)
```

工程含义有三点：`bin__n_bins` 这种双层下划线寻址说明**任何步骤的任何超参都能被外部配置覆盖**，不需要改管道代码；自定义转换器通过 `check_estimator` 的 47 项检查，说明它能安全地参与交叉验证、`clone` 与序列化（13.7 会用到）；`clone` 出的实例与原件完全独立，配置覆盖不会污染正在运行的模型对象——这是同一进程里同时服务多个模型版本的前提。

```text

```

## 最佳实践与踩坑记录

### 最佳实践

1. 任何进入生产的流程都包成 `Pipeline`，预处理与模型一起 fit：它天然防止数据泄漏，也让序列化与调参只面对一个对象。
2. sklearn 版本固定并写进依赖清单（如 `scikit-learn==1.9.1`），升级前先读 `whats_new`，弃用与移除的参数是线上事故的常见来源。
3. 分类任务默认用 `stratify=y` 切分，并用 `cross_val_score(..., cv=StratifiedKFold(...))` 复核，不要只信一次切分的结果。
4. 每份实验脚本都显式设置 `random_state`，并用 `get_params()` 打印真实生效的超参，避免「配置文件改了但没生效」。
5. 指标选择跟着业务走：不平衡数据看 AUC/PR 曲线与少数类召回，回归看 MAE（对异常值不敏感）与 R² 一起看。
6. 自定义估计器按官方规范实现（mixin 顺序、`validate_data`、`check_is_fitted`、`get_feature_names_out`），并跑一次 `check_estimator`。
7. 用 `set_output(transform="pandas")` 保留列名，日志、特征重要度与排障都依赖可读的列名而不是 `x0`、`x1`。

### 踩坑记录

```text
坑 1：拿新版本 sklearn 跑老教程的代码，报 TypeError / 参数不存在
结论：以为装错了包，反复重装。
原因：sklearn 的弃用周期短且执行彻底：load_boston 在 1.2 移除；LogisticRegression 的 penalty
      在 1.8 弃用（本机实测 get_params()['penalty'] == 'deprecated'），GradientBoosting 的
      criterion 同样处于 deprecated 状态。
解法：把版本钉死在依赖文件里，升级前查该版本 whats_new 的 API Change 段落；
      本机环境（1.9.1）新代码不要写 penalty=，正则化强度用 C 与 l1_ratio 表达。
```

```text
坑 2：自定义转换器放进 Pipeline 后列数变了却静默通过，指标诡异
结论：以为是模型不收敛，一路加大 max_iter。
原因：transform 里没做输入校验，测试集特征列数与训练时不同也能算下去，结果形状错位。
解法：fit 用 validate_data(self, X, dtype=float)，transform 用 validate_data(self, X, reset=False)，
      列数不一致会直接报 "X has 4 features, but ... is expecting 3 features as input."；
      另外调 transform 前先 check_is_fitted(self)，未 fit 会报 NotFittedError 而不是静默出错。
```

```text
坑 3：自定义估计器的 check_estimator 一跑就炸，不知道怎么改
结论：以为自定义类写法不对，改来改去越改越乱。
原因：check_estimator 逐项断言，一次只暴露一个问题；且它要求包含 mixin 的继承顺序正确。
解法：按报错逐条修（本机实测顺序）：先补 validate_data（缺 n_features_in_ 一致性检查），
      再把继承写成 (TransformerMixin, BaseEstimator)（BaseEstimator 必须在右边），
      最后在 transform 里加 check_is_fitted；三条修完 47 项全过。
```

```text
坑 4：make_blobs 解包报 "not enough values to unpack (expected 3, got 2)"
结论：以为 make_blobs 返回 (X, y, centers) 三个值。
原因：默认 return_centers=False，只返回 (X, y)；这是把文档示例记得太顺手的典型后果。
解法：要簇中心就显式写 make_blobs(..., return_centers=True)；
      本机实测默认返回形状 (30, 2) 与 (30,)，传参后第三项才是 centers。
```

```text
坑 5：切分后测试集指标每次都差很多，交叉验证结果也发散
结论：怀疑模型不稳定，加正则化、换算法。
原因：没传 stratify，且随机种子不固定；类别不平衡时少数类比例在切分中随机漂移。
解法：分类任务一律 train_test_split(..., stratify=y, random_state=SEED)；
      本机实测同一份数据：stratify 的测试集正类占比 0.104（整体 0.108），不 stratify 的是 0.128。
```

```text
坑 6：日志与特征重要度里只看到 x0/x1/f0，无法和业务字段对应
结论：以为 sklearn 丢了列名，回去手工维护列顺序映射表。
原因：numpy 数组没有列名概念，只有输入是 DataFrame 时 sklearn 才记录 feature_names_in_。
解法：传 DataFrame 并开启 set_output(transform="pandas") 或 set_config(transform_output="pandas")，
      这样转换器输出保留列名，get_feature_names_out() 也能给出可读名字（如 cat__city_beijing）。
```

## 概述

无监督学习在没有标签的情况下寻找数据结构，scikit-learn 把它分成三条主线：聚类（把样本分组，`cluster` 与 `mixture` 模块）、降维（把特征压缩，`decomposition` 与 `manifold` 模块）、异常检测（把离群点挑出来，`ensemble` / `neighbors` / `svm` / `covariance` 模块）。三者经常串起来用：先降维看结构，再聚类分组，最后用异常检测找出不属于任何组的样本。评估是最大的难点——没有真值就只能用轮廓系数、Davies-Bouldin 这类内部指标，而它们隐含「簇是球形的」假设，对密度聚类与非凸簇会给出错误判断。

```text
本篇主线：
1. K-Means —— 最常用的划分聚类，重点在 n_init 与 K 的选择（肘部法 + 轮廓系数）
2. 层次聚类 —— linkage 决定簇形状，ward 只做凸簇、single 能沿链式形状；树状图要 scipy
3. DBSCAN/OPTICS —— 密度聚类，能识别噪声；eps 用 k 距离图定，OPTICS 的 xi 同样要调
4. GaussianMixture —— 软聚类（predict_proba）+ BIC 选分量数；Birch/MeanShift/Spectral 作对照
5. 降维 —— PCA 白化与解释方差比、IncrementalPCA 增量、TruncatedSVD/NMF 处理稀疏文本
6. 流形学习 —— t-SNE/Isomap/LLE/MDS 只适合可视化，没有 transform，不能进生产特征流水线
7. 异常检测 —— IsolationForest/LOF/OneClassSVM/EllipticEnvelope + 按业务容量反推分数阈值
```

## K-Means 聚类与簇数选择

K-Means 用「簇内平方和最小」的目标把样本硬分成 K 组，算法是 Lloyd 迭代：分配点到最近中心、重算中心、重复到收敛。它的假设是簇近似球形且大小相近，对量纲极其敏感（必须先标准化），对离群点也敏感（中心被拉偏）。两个必须显式设置的参数是 `n_init`（不同初始化跑几次取最优，1.4 起默认值从 10 改为 `'auto'`）和 `random_state`。KMeans 是 `TransformerMixin` 的子类，可以放进 Pipeline 当特征变换用（`fit_transform` 输出的是到各中心的距离矩阵）。

```python
import numpy as np
from sklearn.cluster import KMeans
from sklearn.datasets import make_blobs
from sklearn.metrics import (adjusted_rand_score, normalized_mutual_info_score,
                             silhouette_score, davies_bouldin_score, calinski_harabasz_score)

X, y_true = make_blobs(n_samples=600, centers=4, cluster_std=0.9, random_state=0)
km = KMeans(n_clusters=4, init="k-means++", n_init=10, random_state=0).fit(X)
print(km.inertia_, km.n_iter_, km.cluster_centers_.shape)   # 目标值、迭代次数、中心形状
print(adjusted_rand_score(y_true, km.labels_))              # 有真值时的一致性
print(silhouette_score(X, km.labels_))                      # 无真值时的内部指标
print(km.predict([[0.0, 0.0], [10.0, 10.0]]))               # 对新样本打标
print(km.transform([[0.0, 0.0]]))                           # 到各簇中心的距离
```

簇数 K 的两种定法：肘部法看 `inertia_` 的拐点，轮廓系数法取分数最高点。本机实测两者一致指向 K=4，但注意 inertia 随 K 单调下降、永远不能单独用来选 K。

```python
for k in range(2, 8):

    print(f"k={k}  inertia={m.inertia_:9.2f}  silhouette={silhouette_score(X, m.labels_):.4f}")
```

```python
from sklearn.cluster import MiniBatchKMeans
mbk = MiniBatchKMeans(n_clusters=4, batch_size=128, n_init=3, random_state=0)
for i in range(0, 600, 200):
    mbk.partial_fit(X[i:i + 200])       # 流式：每次只喂一批
```


```text
要点：
- K-Means 前必须标准化，否则量纲大的特征会主导欧氏距离
- n_init 与 random_state 必须显式给，否则每次跑出的簇编号与结果不同
- 选 K：肘部法（inertia 拐点）+ 轮廓系数（峰值）交叉验证，别只看 inertia
- 生产用 MiniBatchKMeans.partial_fit 处理大数据；1.9.1 没有 n_samples_fit_ 属性
- predict 会把任意新点强行分到最近簇，业务上要用 transform 的距离设「离得太远就不分配」
```

## 层次聚类与树状图

`AgglomerativeClustering` 自底向上合并样本，`linkage` 决定「两个簇之间距离怎么算」：`ward`（最小化簇内方差，只适合欧氏距离，倾向等大小凸簇）、`complete`（最远点距离，倾向紧凑簇）、`average`（平均距离）、`single`（最近点距离，能沿链式/月牙形状延伸，但容易被离群点串成一条链）。因为要算距离矩阵，复杂度约 O(n²)，样本上万就不适合。

```python
from sklearn.cluster import AgglomerativeClustering
from sklearn.datasets import make_blobs, make_moons
from sklearn.neighbors import kneighbors_graph

X2, y2 = make_blobs(n_samples=300, centers=[[0, 0], [6, 6]], cluster_std=1.0, random_state=1)
for linkage in ("ward", "single", "average", "complete"):
    ac = AgglomerativeClustering(n_clusters=2, linkage=linkage).fit(X2)
    print(linkage, adjusted_rand_score(y2, ac.labels_), np.bincount(ac.labels_))

# 不给簇数，用距离阈值自动切分
ac = AgglomerativeClustering(n_clusters=None, distance_threshold=3.0, linkage="ward").fit(X2)

# 用近邻图限制「只允许相邻的点合并」，做网格分割/图像分割时常用
conn = kneighbors_graph(X_moons, 10, include_self=False)
AgglomerativeClustering(n_clusters=2, connectivity=conn, linkage="ward").fit(X_moons)
```

换成月牙形数据，`ward` 的球形假设立刻暴露，只有 `single` 能正确切出两条月牙：

`distance_threshold` 的尺度就是数据本身的距离尺度：本机实测阈值 2.0 会切出 30 个簇，说明这个值必须结合数据尺度（用 k 距离图，或业务上「多近算同一类」的判据）来定，不能凭感觉给。用 `connectivity=KNN图` 约束时，本机 ward 的 ARI 没有提升（0.2387 与不加约束相同），说明约束只能在「簇本来就不相邻」时帮上忙；同时留意 1.9.1 会给出连通分量补齐的 `UserWarning`。

sklearn **不提供树状图**，要画 dendrogram 用 scipy 的 `scipy.cluster.hierarchy`，它输出的是「合并矩阵」`Z`（n-1 行，每行 `[簇A编号, 簇B编号, 合并距离, 成员数]`）：

```python
from scipy.cluster.hierarchy import linkage as sp_linkage, dendrogram, fcluster
from scipy.spatial.distance import pdist
import matplotlib.pyplot as plt

Z = sp_linkage(pdist(X2), method="ward")
# plt.figure(figsize=(10, 4)); dendrogram(Z); plt.show()   # 画树状图看合并高度
cut = fcluster(Z, t=4.0, criterion="distance")             # 在高度 4.0 处横切
```

```text
scipy linkage 矩阵形状: (299, 4) （n-1 行, 每行 [簇A, 簇B, 距离, 成员数]）
最后 3 次合并:
[[592.    594.     13.021 150.   ]
 [591.    595.     14.951 150.   ]
 [596.    597.    103.628 300.   ]]
```

最后的合并距离从 14.951 直接跳到 103.628，这个「最大跳跃」就是两簇真正分开的高度——比一开始就拍一个阈值靠谱得多。

```text
要点：
- linkage 选型：默认 ward；已知簇大小悬殊或链式形状用 single/average；别用 ward 配非欧氏距离
- sklearn 只给标签，树状图要用 scipy.cluster.hierarchy 的 linkage + dendrogram + fcluster
- 切分高度的依据是合并距离的最大跳跃处，不要照搬 distance_threshold=1 这类固定值
- O(n²) 复杂度，样本量大于约 1 万时改用 KMeans/Birch，或先降维再聚类
- connectivity 只在「簇本来不相邻」时有用（本机实测加不加约束 ARI 都是 0.2387），别指望它救 ward
```

## DBSCAN OPTICS 与密度聚类

DBSCAN 把「密度足够高的连通区域」当簇：`eps` 是邻域半径，`min_samples` 是判定核心点的最少邻居数，找不到归属的点标为 `-1`（噪声）。它不需要指定簇数、能发现任意形状、能识别噪声，代价是对 `eps` 极其敏感，且两个簇密度差很多时参数很难兼顾。`OPTICS` 是它的改进版：不固定 eps，输出可达距离排序，再用 `xi` 自动提取簇。

```python
from sklearn.cluster import DBSCAN, OPTICS
from sklearn.neighbors import NearestNeighbors

for eps in (0.15, 0.2, 0.3, 0.5):
    db = DBSCAN(eps=eps, min_samples=5).fit(X_moons)
    n_noise = int(np.sum(db.labels_ == -1))
    n_cluster = len(set(db.labels_)) - (1 if -1 in db.labels_ else 0)

# 用 k 距离图定 eps：第 k 近邻距离排序后找拐点
nn = NearestNeighbors(n_neighbors=5).fit(X_moons)
dist, _ = nn.kneighbors(X_moons)
kdist = np.sort(dist[:, -1])
print(np.quantile(kdist, [0.5, 0.9, 0.95, 0.99]))

opt = OPTICS(min_samples=5, xi=0.05).fit(X_moons)
```

```text
== 3. DBSCAN（密度聚类，能识别噪声） ==
eps=0.15 簇数=2 噪声点=  0 ARI=1.0000
eps=0.20 簇数=2 噪声点=  0 ARI=1.0000
eps=0.30 簇数=1 噪声点=  0 ARI=nan
eps=0.50 簇数=1 噪声点=  0 ARI=nan
core_sample_indices_ 形状: (400,)

-- k 距离图选 eps（第 k 近邻距离排序，找拐点） --
第 5 近邻距离分位数 50%/90%/95%/99%: [0.064 0.105 0.118 0.149]

-- OPTICS（不用手调 eps，用 xi 自动提取） --
簇数: 30  噪声: 125  ARI: 0.0307
```

这份真实结果暴露三个要点。第一，`eps` 从 0.2 加到 0.3，两个簇直接被连通成一个（ARI 变成 `nan` 是因为只剩一个簇，外部指标无法计算——出现 nan 往往是「簇数 < 2」而不是数据有问题）。第二，k 距离图的 95% 分位约 0.118，正好落在有效区间 0.15~0.20 旁边，是很好的起点。第三，`OPTICS(xi=0.05)` 在这份数据上切出 30 个簇、125 个噪声点，结果过碎——「OPTICS 不用调参」的说法不成立，它只是把 eps 换成了 `xi`（陡峭度阈值）与 `max_eps`。

```text
要点：
- eps 用 k 距离图的拐点/高分位数定（min_samples=5 就看第 5 近邻距离），不要从 0.5 这种量级开始猜
- eps 稍大就会把相邻簇吃掉，务必扫参数看簇数与噪声数是否稳定（本机 0.2 -> 0.3 直接合并）
- min_samples 经验值 = 特征维度 + 1 起步；密度不均的数据考虑 OPTICS
- 噪声点标为 -1，业务上必须显式处理（丢弃、单列标记、或单独路由给人工）
- OPTICS 的 xi 同样要调；提取结果过碎时优先考虑调 xi 或用 cluster_method="dbscan" + max_eps
```

## 高斯混合与其他聚类算法

`GaussianMixture` 假设数据由若干高斯分布混合生成，用 EM 求解，输出的是**软归属**（每类的后验概率），比 K-Means 的硬标签多一层信息，也能建模椭圆形簇。分量数用 BIC/AIC 选，越小越好。

```python
from sklearn.mixture import GaussianMixture
for n in (2, 3, 4, 5, 6):
    gm = GaussianMixture(n_components=n, covariance_type="full", random_state=0).fit(Xb)
    print(n, gm.bic(Xb), gm.aic(Xb))
gm4 = GaussianMixture(n_components=4, random_state=0).fit(Xb)
proba = gm4.predict_proba(Xb)      # 软归属，行和为 1
hard = gm4.predict(Xb)             # 硬归属 = argmax(proba)
```

```text
n_components=2  BIC=    4954.0  AIC=    4905.6
n_components=3  BIC=    4777.1  AIC=    4702.4
n_components=4  BIC=    4770.7  AIC=    4669.6
n_components=5  BIC=    4808.4  AIC=    4680.9
n_components=6  BIC=    4837.0  AIC=    4683.1
predict_proba 前 2 行（软归属，行和=1）:
[[0.     0.     0.9999 0.    ]
 [0.     0.     0.     1.    ]] 行和: [1. 1.]
predict（硬归属）前 10 个: [2 3 2 2 3 0 1 1 1 0]
predict 与 argmax(predict_proba) 一致: True
```

BIC 在 4 个分量处取到最小值，与数据的真实簇数一致。`covariance_type` 决定协方差矩阵的自由度：`full`（每个分量独立满矩阵，最灵活也最费参数）、`tied`（共享）、`diag`（对角，特征独立）、`spherical`（各向同性，等价于 K-Means 的球形假设）。维度高、样本少时用 `diag` 或 `tied` 防止过拟合。

其他几个值得知道的聚类器，本机在同一份 blobs 数据（标准化后）上实测：

```python
from sklearn.cluster import Birch, MeanShift, SpectralClustering
from sklearn.preprocessing import StandardScaler
Xbs = StandardScaler().fit_transform(Xb)
print(len(MeanShift().fit(Xbs).cluster_centers_))                 # 自动定簇数
print(adjusted_rand_score(yb, Birch(n_clusters=4).fit(Xbs).labels_))
print(adjusted_rand_score(yb, SpectralClustering(n_clusters=4, affinity="rbf",
                                                 random_state=0).fit(Xbs).labels_))
```

```text
MeanShift 自动找到簇数: 1  ARI: 0.0
Birch(4) ARI: 0.8643
SpectralClustering(4) ARI: 0.8329
```

`MeanShift` 给出 1 个簇是本机真实踩到的现象：它的 `bandwidth` 默认用 `estimate_bandwidth` 估计，在标准化后簇间距不大的数据上会把所有点连成一片。所以 MeanShift 必须显式给 `bandwidth`（本机未继续调参验证，属于该估计器的已知行为而非 bug）。

| 算法 | 簇形状 | 需要簇数 | 噪声处理 | 适用规模 | 主要参数 |
| --- | --- | --- | --- | --- | --- |
| KMeans / MiniBatchKMeans | 球形、等大小 | 是 | 无 | 大（可流式） | `n_clusters` `n_init` |
| AgglomerativeClustering | 由 linkage 决定 | 是或距离阈值 | 无 | 中（O(n²)） | `linkage` `distance_threshold` |
| DBSCAN | 任意 | 否 | 显式 `-1` | 中 | `eps` `min_samples` |
| OPTICS | 任意 | 否 | 显式 `-1` | 中 | `xi` `min_samples` `max_eps` |
| GaussianMixture | 椭圆（由协方差定） | 是（BIC 选） | 无 | 中 | `n_components` `covariance_type` |
| Birch | 球形（CF 树） | 是 | 无 | 大 | `threshold` `branching_factor` |
| SpectralClustering | 图分割，任意 | 是 | 无 | 小中 | `affinity` `n_neighbors` |
| MeanShift | 任意 | 否（靠 bandwidth） | 无 | 小 | `bandwidth` |

```text
要点：
- 需要「每个样本属于各簇的概率」时用 GaussianMixture，只要硬标签就用 KMeans
- 分量数用 BIC（或 AIC）选；高维小样本改用 covariance_type="diag"/"tied" 控参数量
- MeanShift 默认带宽在小间距数据上会把所有点并成一簇，必须显式设 bandwidth
- Birch 适合超大数据（CF 树可续接），精度通常略低于 KMeans
- SpectralClustering 要构造相似度图，复杂度高，只适合中小规模或流形数据
```

## 聚类效果评估指标

有真值（或有人工标注的抽样）时用外部指标：`adjusted_rand_score`（ARI）、`normalized_mutual_info_score`（NMI）、`adjusted_mutual_info_score`、`homogeneity/completeness/v_measure`、`fowlkes_mallows_score`。ARI 对簇标签的排列不敏感（簇编号换了分数不变），1 表示完全一致、0 表示等价于随机划分，可以为负。没有真值时只能用内部指标：`silhouette_score`（-1~1，越大越分离）、`davies_bouldin_score`（越小越好）、`calinski_harabasz_score`（越大越好）。

```python
from sklearn.metrics import (silhouette_samples, adjusted_rand_score,
                             normalized_mutual_info_score, fowlkes_mallows_score)
# 每个样本的轮廓值：用来找「哪些点其实是骑墙的」
sil = silhouette_samples(X, km.labels_)
print(sil.min(), sil.max())
for name, labels in [("kmeans(k=4)", km.labels_),
                     ("kmeans(k=5)", KMeans(5, n_init=10, random_state=0).fit(X).labels_)]:
    print(name, round(adjusted_rand_score(y_true, labels), 4),
          round(normalized_mutual_info_score(y_true, labels), 4),
          round(fowlkes_mallows_score(y_true, labels), 4),
          round(silhouette_score(X, labels), 4),
          round(davies_bouldin_score(X, labels), 4))
```

本机真实输出：

```text
kmeans(k=4) 0.9138 0.8835 0.9089 0.5373 0.6381
kmeans(k=5) 0.6778 0.7111 0.7493 0.4737 0.8525
```

四个外部/内部指标一致地把 k=4 排在 k=5 前面（ARI 无真值时用不了，但轮廓系数与 DB 也能给出同样结论）。外部指标永远是首选：只要能用「一小撮人工标注的抽样簇」或业务上已知的分组（如真实会员等级、真实设备型号），就把它当近似真值算 ARI，比盯着轮廓系数猜可靠得多。内部指标只能用来**比较同一数据上的不同聚类方案**，跨数据集不可比。

| 指标 | 类型 | 方向 | 对簇形状的偏好 | 注意点 |
| --- | --- | --- | --- | --- |
| adjusted_rand_score | 外部 | 越大越好，1 为完美 | 无明显偏好 | 需要真值，可负 |
| normalized_mutual_info_score | 外部 | 越大越好 | 偏好细分 | 需要真值 |
| fowlkes_mallows_score | 外部 | 越大越好 | 无明显偏好 | 需要真值 |
| silhouette_score | 内部 | -1~1 | 偏好凸簇、球状 | 非凸簇会低估 |
| davies_bouldin_score | 内部 | 越小越好 | 偏好球状 | 与轮廓系数常一致 |
| calinski_harabasz_score | 内部 | 越大越好 | 随样本数增长 | 只用于同数据对比 |

```text
要点：
- 聚类评估的第一选择是「抽样人工标注 + ARI」，不是轮廓系数
- 内部指标（silhouette/DB/CH）只能在相同数据、相同距离度量下横向比较不同方案
- 轮廓系数在非凸/链式簇上会严重低估，DBSCAN/OPTICS 的结果别用它评判
- 每个样本的轮廓值（silhouette_samples）能定位骑墙点，业务上这些点往往需要人工兜底
- 结果里出现 nan 先查「簇数是否小于 2」，而不是怀疑数据坏了
```

## 降维 PCA 与稀疏矩阵分解

PCA 用协方差矩阵的主特征方向做线性投影，`n_components` 可以是整数（要几维），也可以是 0~1 的浮点数（保留多少方差比例），`whiten=True` 让各主成分方差归一化（对后续用欧氏距离的模型有帮助）。本机用 64 维的 `load_digits` 实测：

```python
from sklearn.decomposition import PCA, IncrementalPCA
from sklearn.datasets import load_digits
Xd, yd = load_digits(return_X_y=True)          # (1797, 64)

pca = PCA(n_components=0.95, svd_solver="full", random_state=0).fit(Xd)
print(pca.n_components_)                       # 保留 95% 方差所需的维度
print(pca.explained_variance_ratio_[:5], pca.explained_variance_ratio_.cumsum()[:5])
Xt = pca.transform(Xd)
print(pca.inverse_transform(Xt).shape)         # 可还原（有损）
pca2 = PCA(n_components=2, random_state=0).fit(Xd)
print(pca2.components_[0][:8])                 # 第一主成分的载荷
print(PCA(n_components=5, whiten=True, random_state=0).fit(Xd).explained_variance_)
```

64 维压到 29 维就保住 95% 的方差；而压到 2 维只保住 28.51%，用于可视化可以，用于建模会丢太多信息。还原误差最大 12.7349（原始特征取值 0~16），说明降维是**有损**的，`inverse_transform` 只能得到近似值。白化后各主成分方差不再按顺序衰减（179.0 到 69.5），因为每个分量都被缩放到单位方差再乘回原来的特征尺度。

数据太大不能一次性装入内存时用 `IncrementalPCA`。它需要每批样本数不小于 `n_components`，否则报错：

```python
ipca = IncrementalPCA(n_components=20, batch_size=200)
for i in range(0, len(Xd), 200):
    ipca.partial_fit(Xd[i:i + 200])
```

```text

```

文本类稀疏矩阵**不能**直接扔给 PCA（PCA 内部做均值中心化会破坏稀疏性并撑爆内存），要用 `TruncatedSVD`（不做中心化，LSA 的标准做法）或 `NMF`（非负约束，结果更可解释，适合主题模型）：

```python
from sklearn.decomposition import TruncatedSVD, NMF
from sklearn.feature_extraction.text import TfidfVectorizer
texts = ["机器学习 模型 训练 数据", "深度学习 神经网络 训练", "聚类 无监督 相似度",
         "分类 回归 监督学习", "神经网络 反向传播 梯度"]
Xs = TfidfVectorizer(token_pattern=r"(?u)\b\w+\b").fit_transform(texts)   # 稀疏矩阵
svd = TruncatedSVD(n_components=2, random_state=0).fit_transform(Xs)
nmf = NMF(n_components=2, init="nndsvd", random_state=0, max_iter=500)
W = nmf.fit_transform(Xs)
```

```text

TruncatedSVD 2 维结果:

 [ 0.8204  0.    ]
 [-0.      0.9864]

```

| 方法 | 是否中心化 | 适合输入 | 输出可解释性 | 增量/流式 |
| --- | --- | --- | --- | --- |
| PCA | 是 | 稠密 | 主成分可作线性组合解释 | IncrementalPCA |
| TruncatedSVD | 否 | 稀疏（TF-IDF/词袋） | 同 PCA，但语义更偏共现 | 无（可自己分块近似） |
| NMF | 否 | 非负稀疏 | 非负基向量，像「主题」 | 无（可 warm_start 续跑） |
| KernelPCA | 是 | 稠密、非线性结构 | 不可逆推原始特征 | 无 |

```text
要点：
- n_components 用 0~1 的浮点直接指定「保留多少方差」，比手动试维度省事
- 稀疏矩阵（TF-IDF、词袋、One-Hot）只能用 TruncatedSVD/NMF，不能直接 PCA
- 大数据用 IncrementalPCA.partial_fit，单批样本数必须不小于 n_components
- 降维后做下游任务前先看累计解释方差（本例 2 维仅 28.51%，显然不够）
- PCA 的载荷（components_）可以反过来解释「这个主成分代表哪些原始特征」
```

## 流形学习 t-SNE Isomap 与 LLE

流形学习假设高维数据躺在一个低维弯曲面上，用非线性方式把它摊平。它们的共同点是：**只适合可视化**，没有可复用的稳定映射（`inverse_transform` 只有部分方法支持），不能像 PCA 那样放进生产流水线对新数据做 `transform`。本机对照实测（300 个手写数字样本）：

```python
from sklearn.manifold import TSNE, Isomap, LocallyLinearEmbedding, MDS
sub = Xd[:300]
TSNE(n_components=2, perplexity=30, init="pca", learning_rate="auto", random_state=0).fit_transform(sub)
Isomap(n_components=2, n_neighbors=10).fit_transform(sub)
LocallyLinearEmbedding(n_components=2, n_neighbors=10, method="standard").fit_transform(sub)
MDS(n_components=2, random_state=0, n_init=1, max_iter=100).fit_transform(sub)
```

```text

Isomap  输出形状=(300, 2) 第一维范围=(-125.041, 175.375)
LLE     输出形状=(300, 2) 第一维范围=(-0.061, 0.000)
MDS     输出形状=(300, 2) 第一维范围=(-47.032, 42.024)

```

运行过程中本机还真实出现了两条警告，都是调参信号：

```text

Completing the graph to fit Isomap might be slow. Increase the number of neighbors to avoid this issue.

To suppress this warning, provide some value of `init`.
```

第一条说明近邻图不连通，Isomap 会先补全图（慢、结果可疑），解法是调大 `n_neighbors`。第二条是未来默认值变更提示，MDS 的 `init` 显式传参，免得升级到 1.10 后结果悄悄变化。

| 方法 | 保留什么 | 主要参数 | 复杂度 | 能否 transform 新数据 |
| --- | --- | --- | --- | --- |
| t-SNE | 局部邻域概率分布 | `perplexity`（常用 5~50）、`learning_rate`、`init` | O(n²) 或近似 O(n log n) | 否 |
| Isomap | 测地距离 | `n_neighbors` | 中 | 是 |
| LLE | 局部线性重构权重 | `n_neighbors`、`method` | 中 | 否 |
| MDS | 成对距离 | `metric`、`max_iter`、`init` | 高（O(n²)） | 否 |
| PCA / TruncatedSVD | 全局方差 | `n_components` | 低 | 是 |

```text
要点：
- 流形学习的坐标轴没有物理含义，不能拿来解释业务，只能看簇是否分开
- t-SNE 每次运行结果不同（必须固定 random_state），全局结构不可比，别用簇间距离下结论
- LLE 的输出量级极小（本例第一维范围 -0.061~0.000），可视化前要手动缩放
- 近邻图不连通（connected components > 1）时 Isomap 会先补全图，慢且结果可疑，应调大 n_neighbors
- 需要「训练一次、对线上新数据变换」的场景只能用 PCA/IncrementalPCA/TruncatedSVD
```

## 异常与新颖性检测

异常检测分两类场景：**异常检测（outlier detection）**训练时就带着异常样本，用 `fit_predict`（适合清洗历史数据）；**新颖性检测（novelty detection）**只用正常样本训练，之后判断新样本是否正常（需要 `novelty=True` 才能 `predict`）。所有估计器的输出约定一致：`-1` 表示异常、`1` 表示正常，`score_samples` 分数越小越异常，`decision_function` 越小越异常（OneClassSVM 的符号与距离语义不同，别混用）。

```python
from sklearn.ensemble import IsolationForest
from sklearn.neighbors import LocalOutlierFactor
from sklearn.svm import OneClassSVM
from sklearn.covariance import EllipticEnvelope

Xin = rng.randn(300, 2)                             # 正常样本
Xout = rng.uniform(low=-6, high=6, size=(15, 2))    # 人造离群点
Xa = np.vstack([Xin, Xout]); y_a = np.hstack([np.ones(300), -np.ones(15)])

for name, model in [("IsolationForest", IsolationForest(n_estimators=200, contamination=0.05, random_state=0)),
                    ("OneClassSVM", OneClassSVM(gamma="scale", nu=0.05)),
                    ("EllipticEnvelope", EllipticEnvelope(contamination=0.05, random_state=0))]:
    model.fit(Xin)
    pred = model.predict(Xa)
    print(name, np.sum((pred == -1) & (y_a == -1)), np.sum((pred == -1) & (y_a == 1)))

lof = LocalOutlierFactor(n_neighbors=20, contamination=0.05).fit_predict(Xin)   # 只能用于训练集
lof2 = LocalOutlierFactor(n_neighbors=20, novelty=True, contamination=0.05).fit(Xin)
print(lof2.predict(Xa))                                                          # 可对新数据判断
```

```text
IsolationForest    抓到的真异常=13/15  误报=15  漏报=2  score_samples 样例=[-0.5041 -0.6213 -0.5545]
OneClassSVM        抓到的真异常=13/15  误报=27  漏报=2  score_samples 样例=[2.2831 2.0634 2.2414]
EllipticEnvelope   抓到的真异常=13/15  误报=15  漏报=2  score_samples 样例=[-3.3421 -6.7613 -5.691 ]
LocalOutlierFactor（fit_predict 只能用于训练集）异常数: 15  negative_outlier_factor_ 头部: [-1.3535 -1.3563 -1.46  ]
novelty=True 后可对新数据 predict，抓到真异常: 13 /15
```

三个模型都在 15 个人造离群点里抓到 13 个，但误报差了一倍（IsolationForest 15 个、OneClassSVM 27 个）——同样的 `contamination=0.05` 下，**误报率才是选型依据**。生产中更常用的做法是放弃 `contamination` 硬阈值，改成按分数分位定阈值，这样阈值可以随业务容忍度（每天最多人工复核多少条）来定：

```python
iso = IsolationForest(contamination=0.05, random_state=0).fit(Xin)
scores = iso.score_samples(Xa)
for q in (1, 5, 10):
    thr = np.quantile(iso.score_samples(Xin), q / 100)   # 阈值取「正常样本的 q% 分位」
    n_flag = int(np.sum(scores < thr))
    tp = int(np.sum((scores < thr) & (y_a == -1)))
    print(q, thr, n_flag, tp)
```

```text
-- 异常分数分位点（当没有标签时用分数阈值，而不是硬编码 contamination） --
正常样本分数中位数: -0.4449
异常样本分数中位数: -0.6868
阈值取正常样本  1% 分位 (-0.6466) -> 标记  13 个, 命中真异常 10/15
阈值取正常样本  5% 分位 (-0.6077) -> 标记  28 个, 命中真异常 13/15
阈值取正常样本 10% 分位 (-0.5574) -> 标记  44 个, 命中真异常 14/15
```

| 估计器 | 原理 | 训练需要异常样本 | 支持 predict 新样本 | 适合数据 |
| --- | --- | --- | --- | --- |
| IsolationForest | 随机切分，异常点更易被孤立 | 否 | 是 | 高维、大数据 |
| LocalOutlierFactor | 局部密度比 | 否 | 需 `novelty=True` | 密度不均 |
| OneClassSVM | 把正常样本包进边界 | 否 | 是 | 中小规模 |
| EllipticEnvelope | 拟合稳健高斯 | 否 | 是 | 近似高斯、低维 |
| SGDOneClassSVM | OneClassSVM 的线性/流式版 | 否 | 是 | 大数据流式 |

```text
要点：
- 输出约定：-1 异常、1 正常，score_samples 越小越异常；异常分数没有量纲，别跨模型比
- 只用正常样本训练是「新颖性检测」；训练集里混了异常样本才用 fit_predict 走「异常检测」
- LocalOutlierFactor 默认只能用于训练集，要对新数据判断必须 novelty=True 后重新 fit
- contamination 是「估计的异常比例」，宁可给大一点再按分数分位收紧，否则真异常会被静音
- 异常检测必须有业务反馈闭环：被标记的样本要能人工确认，再反过来调阈值
```

## 应用场景实战

### 场景一：电商会员分群（KMeans + 画像 + PCA 复核）

业务需求：把 5000 名会员按行为特征分成运营人群，要求簇可解释、结果可复现、能对新注册会员实时打标，并且分群模型必须整条保存（标准化口径不能与训练时不一致）。

```python
# member_segment.py —— 会员分群、人群画像与落盘
import os
import joblib
import numpy as np
import pandas as pd
from sklearn.cluster import KMeans
from sklearn.decomposition import PCA
from sklearn.impute import SimpleImputer
from sklearn.metrics import silhouette_score, calinski_harabasz_score
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler

rng = np.random.RandomState(42)
n = 5000
df = pd.DataFrame({
    "recency_days": rng.gamma(2, 15, n),           # 最近一次消费距今天数，越小越活跃
    "frequency": rng.poisson(6, n).astype(float),  # 近 90 天下单次数
    "monetary": rng.lognormal(9.2, 0.6, n),        # 近 90 天消费金额
    "avg_order_value": rng.lognormal(8.4, 0.5, n),  # 客单价
    "return_rate": rng.beta(2, 20, n),             # 退货率
    "coupon_usage": rng.beta(3, 7, n),             # 优惠券使用率
})
df.loc[:50, "monetary"] = np.nan                   # 新会员没有消费记录
FEATURES = list(df.columns)

# 预处理 + 聚类放进同一个 Pipeline：保存后线上新数据的口径与训练时完全一致
pipeline = Pipeline([
    ("imputer", SimpleImputer(strategy="median")),   # 线上可能返回 None，必须能兜住
    ("scaler", StandardScaler()),
    ("kmeans", KMeans(n_clusters=5, n_init=20, random_state=0)),
])
pipeline.fit(df[FEATURES])

pre = pipeline[:-1]                                # 切片：除最后一步外的全部（即预处理器）
Z = pre.transform(df[FEATURES])
labels = pipeline.named_steps["kmeans"].labels_
print("样本数:", len(df), " 轮廓系数:", round(float(silhouette_score(Z, labels)), 4))
print("CH 指数:", round(float(calinski_harabasz_score(Z, labels)), 1))

# 人群画像：每个簇的各特征均值 + 簇大小，业务同学看的就是这张表
prof = df.assign(cluster=labels).groupby("cluster")[FEATURES].mean().round(2)
prof["size"] = df.assign(cluster=labels).groupby("cluster").size()
print(prof.to_string())

# PCA 只用于沟通与复核，不参与聚类
pca = PCA(n_components=2, random_state=0).fit(Z)
viz = pca.transform(Z)
print("前两个主成分累计解释方差:", round(float(pca.explained_variance_ratio_.sum()), 4))

path = "/opt/models/member_segment_v1.joblib"     # 本机实测时写在 /root/.hermes/cache/scratch/models/
joblib.dump(pipeline, path)
new_member = pd.DataFrame([{"recency_days": 3, "frequency": 12, "monetary": 3200,
                            "avg_order_value": 260, "return_rate": 0.01, "coupon_usage": 0.4}])
print("新会员簇:", pipeline.predict(new_member[FEATURES]).tolist(),
      " 到各簇中心距离（判断归属是否勉强）:",
      np.round(pipeline.named_steps["kmeans"].transform(pre.transform(new_member[FEATURES]))[0], 3).tolist())
print("回读模型预测一致:", bool(np.array_equal(pipeline.predict(df[FEATURES]),
      joblib.load(path).predict(df[FEATURES]))))
```

### 场景二：交易异常检测（IsolationForest + 按复核容量反推阈值 + 原因留痕）

业务需求：每小时扫描新增交易，挑出可疑记录送人工复核；复核运力有限（期望每批 8 条左右），阈值要能按运力调，并且被标记的记录要带「为什么被标记」的原因，人工复核才知道看哪里。

```python
# fraud_scan.py —— 只用正常交易训练，按复核容量反推阈值，输出可审计的待复核队列
import numpy as np
import pandas as pd
from sklearn.ensemble import IsolationForest
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler

rng = np.random.RandomState(7)

def make_batch(n, anomaly_rate=0.0):
    d = pd.DataFrame({
        "amount": rng.lognormal(4.5, 0.8, n),          # 交易金额
        "amount_z": rng.normal(0, 1, n),               # 相对本人历史的偏离（离线已算好）
        "hour_dev": rng.choice([0, 1, 2], n).astype(float),   # 与常用时段的偏离小时数
        "device_new": (rng.rand(n) < 0.02).astype(float),     # 是否新设备
        "ip_risk": rng.beta(1, 40, n),                 # IP 风险分
    })
    if anomaly_rate > 0:                              # 注入人造异常，用于评估召回
        idx = rng.choice(n, int(n * anomaly_rate), replace=False)
        d.loc[idx, "amount"] *= rng.uniform(20, 60, len(idx))
        d.loc[idx, "device_new"] = 1.0
        d.loc[idx, "ip_risk"] = rng.uniform(0.6, 0.95, len(idx))
    return d

FEATURES = ["amount", "amount_z", "hour_dev", "device_new", "ip_risk"]
train = make_batch(50000, 0.0)                        # 训练集只用已确认正常的交易

model = Pipeline([
    ("sc", StandardScaler()),
    ("iso", IsolationForest(n_estimators=300, contamination="auto", random_state=0)),
])
model.fit(train[FEATURES])

# 阈值按运力反推：期望每批 8 条，就用正常交易分数的对应分位当阈值
train_scores = model.named_steps["iso"].score_samples(model[:-1].transform(train[FEATURES]))
QUOTA_PER_BATCH, BATCH_SIZE = 8, 50000
threshold = float(np.quantile(train_scores, QUOTA_PER_BATCH / BATCH_SIZE))
print("阈值（按每批 %d 条复核容量反推）: %.6f" % (QUOTA_PER_BATCH, threshold))

hour = make_batch(20000, 0.004)
hour["score"] = model.named_steps["iso"].score_samples(model[:-1].transform(hour[FEATURES]))
hour["flagged"] = (hour["score"] < threshold).astype(int)
print("本批交易数:", len(hour), " 命中标记:", int(hour["flagged"].sum()))
print(hour.sort_values("score").head(5)[FEATURES + ["score"]].round(4).to_string(index=False))

# 原因留痕：人工复核要能一眼看出是哪条信号触发的
flagged = hour[hour["flagged"] == 1].copy()
flagged["reason"] = np.where(flagged["device_new"] == 1, "新设备",
                             np.where(flagged["ip_risk"] > 0.5, "高风险 IP", "金额异常"))
print(flagged["reason"].value_counts().to_string())

# 用「已知异常规则」评估召回/精确率（真实场景应换成复核确认的标签）
truth = hour["amount"] > np.quantile(hour["amount"], 1 - 0.004)
recall = float(flagged.index.isin(hour.index[truth]).sum()) / max(int(truth.sum()), 1)
print("对已知异常规则的召回率:", round(recall, 4),
      " 精确率:", round(float(flagged.index.isin(hour.index[truth]).mean()), 4))
```

这份真实结果给出两个必须在工程上处理的结论：命中 85 条远高于目标 8 条，因为阈值是拿**训练集（全是正常交易）**的分数分布算出来的，而线上批次的分数分布会漂移（本批人工注入的异常让整体分数下移）；同时「标记原因」分布极度偏斜（84 条都是「新设备」），说明 `device_new` 这个特征几乎单独主导了模型输出，投产前要么把它做成独立规则、要么在训练时降权。另外注意训练集 1% 分位（-0.6436）与实际使用的阈值（-0.7158）不同，前者对应 8/50000 = 0.016% 分位——阈值分位要与批量大小对齐，不能照抄「1%」。

修正做法（本机未逐项验证，属于工程建议）：用最近 N 批的**真实分数**滚动重算阈值（分位数 = 运力 / 批量），并对 `device_new` 这类会主导分数的特征做去偏（训练时按比例重加权或作为独立规则先行过滤）。

```text
要点：
- 阈值从运力反推，但必须用「近期真实批次的分数分布」滚动计算，训练集分布会漂移（本机 8 条目标实际命中 85 条）
- 阈值分位 = 每批运力 / 每批样本数（本例 8/50000 = 0.016%），不是常见的 1%
- 训练集要尽量纯净：只用已确认正常的交易，混入坏样本会把基线整体拉偏
- 每条被标记的记录要附原因（哪条信号触发），否则人工复核只能靠猜
- 检查特征重要性/贡献是否被单个特征垄断（本机 84/85 的标记都由 device_new 触发）
- 复核结果必须回流成标签，既用于评估召回/精确率，也用于下一次调阈值
```

## 最佳实践与踩坑记录

### 最佳实践

1. 任何距离类算法（KMeans/DBSCAN/层次聚类/KNN/LOF）之前先标准化；树模型与基于密度的例外要写进注释。
2. 聚类结果必须产出「簇大小 + 各特征均值」的画像表；只看标签不看画像，等于没有交付。
3. 簇数/阈值定下来后固定 `random_state`，并把完整 Pipeline（含预处理）一起持久化，保证线上打标口径一致。
4. 能拿到人工抽样的近似真值时优先算 ARI/NMI；内部指标只在相同数据、相同距离度量下横向比较方案。
5. 异常检测的阈值按业务运力反推，并把分数、触发原因、模型版本一起落库，形成可审计的复核闭环。
6. 降维用于生产特征时选 PCA/IncrementalPCA/TruncatedSVD；t-SNE/LLE/MDS 只进可视化报告。

### 踩坑记录

```text
坑 1：KMeans 结果每次都不一样，簇编号与业务报表对不上
结论：怀疑算法不稳定，反复重跑挑「看起来最好」的一次。
原因：K-Means 的初始化本身随机（k-means++ 也随机），且簇编号是任意分配的
      （第一簇不一定是「活跃用户」）。
解法：固定 random_state 并显式给 n_init（本机用 10/20）；模型持久化后簇编号就固定了；
      重训时用 ARI 对比新旧标签、建立「新簇号 -> 旧簇号」映射表再发报表。

坑 2：DBSCAN 的 eps 稍大一点，两个业务上完全不同的簇就被合并了
结论：以为数据里其实只有一簇，或者换算法。
原因：密度聚类的簇由 eps 邻域的连通性决定，eps 一旦跨越簇间最小间距，两簇自然连通。
      本机实测 eps=0.2 得到 2 簇（ARI=1.0000），eps=0.3 只剩 1 簇（ARI 变成 nan）。
解法：用 k 距离图定 eps（本机第 5 近邻距离 95% 分位约 0.118，最终取 0.15~0.20）；
      改 OPTICS 时同样要调 xi（本机 xi=0.05 切出 30 簇、125 个噪声点，明显过碎）；
      扫参数时同时打印簇数与噪声数，出现 nan 先查簇数是否小于 2。

坑 3：层次聚类在月牙形数据上完全分不开，换个 linkage 就好了
结论：以为 ward 是最优默认，不该换。
原因：ward 的目标是最小化簇内方差，隐含「凸的、等大小」假设；月牙形数据上它会把两端切走。
      本机实测 moons 数据 ward ARI=0.2387、complete 0.2845、average 0.3292，single 1.0000。
解法：先画散点图判断簇形状；链式/月牙/同心环用 single 或 average，球状等大小才用 ward。
      single 的代价是容易被离群点串链，所以要先清离群点。

坑 4：t-SNE 做完想把结果当特征喂给分类器，线上没法 transform
结论：以为可以像 PCA 一样对线上新数据 tsne.transform(new_data)。
原因：t-SNE 没有 transform（1.9.1 实测只支持 fit_transform），它是对整个数据集的优化，
      新点进来只能整体重跑，且每次形状与位置都变。
解法：非线性方法只用于可视化；要进生产特征流水线只能用 PCA/IncrementalPCA/TruncatedSVD。
      顺带留意本机真实警告：MDS 的 init 默认值将在 1.10 变更，显式传参避免结果漂移。

坑 5：稀疏 TF-IDF 矩阵直接喂给 PCA 结果内存爆炸
结论：以为 PCA 和 TruncatedSVD 等价，随便用一个。
原因：PCA 会做均值中心化，稀疏矩阵一旦中心化就变稠密，百万文档的特征矩阵直接撑爆内存。
解法：文本/稀疏数据一律用 TruncatedSVD（LSA）或 NMF。本机实测 5 条文本的 TF-IDF
      稀疏度 0.771，TruncatedSVD 累计解释方差 0.3757、NMF 重建误差 1.629，均正常出结果。

坑 6：LocalOutlierFactor 训练完拿来对线上新数据 predict 直接报错
结论：以为 LOF 和 IsolationForest 一样可以直接对新样本打分。
原因：LOF 的判定依赖「训练集里的邻居密度」，默认 novelty=False 时不提供对新数据的
      decision_function，只有 fit_predict。
解法：要对新数据判断就 LocalOutlierFactor(novelty=True) 再 fit（本机实测 novelty=True 后
      对 15 个人造异常点抓到 13 个）；同时重新标定阈值——novelty=True 的分数语义与
      fit_predict 的分数并不完全一致。

坑 7：按「1% 分位」定的异常阈值，实际每天推给人工的队列是预期的 50 倍
结论：以为阈值分位数照抄 1% 就够了。
原因：分位数要跟批量大小对齐。本机期望每批 8 条、批量 50000，对应分位是 0.016% 而不是 1%；
      而且阈值取自训练集分布，线上批次分布漂移后命中量进一步放大（实测目标 8 条、实际 85 条）。
解法：阈值分位 = 每批运力 / 每批样本数；用最近 N 批真实分数滚动重算；把每日命中量做成
      监控指标，超阈值就自动收紧而不是等人发现队列爆了。
```

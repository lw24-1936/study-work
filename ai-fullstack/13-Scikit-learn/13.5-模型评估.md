## 概述

模型评估要回答三个问题：模型在没见过的数据上表现如何（泛化）、这个分数可信吗（方差与泄漏）、业务上该怎么用（阈值与成本）。scikit-learn 的 `model_selection` 负责第一、二个问题（交叉验证、学习曲线、分组/时序切分），`metrics` 负责把预测翻译成可比较的数字。最容易出错的地方不是指标算错，而是**评估方式本身有泄漏**：预处理/特征选择做了全量再切折、同一对象的多条记录横跨训练与验证、时序数据随机打乱——这三种情况下，指标会漂亮得没有任何意义。

```text
本篇主线：
1. 交叉验证 —— KFold 与 StratifiedKFold 的差别、折数选择、cross_validate 一次拿多指标 + 训练分数
2. 分类指标 —— 准确率在不平衡数据上失效；balanced_accuracy/f1/mcc/kappa 各自的适用场景
3. 混淆矩阵 —— 原始计数优先于归一化比例；classification_report 的每类拆解
4. ROC 与 PR —— AUC 的含义与局限、阈值怎么选、平均精度 AP 在不平衡数据上的优势
5. 回归指标 —— MAE/RMSE/R2 的量纲差异、DummyRegressor 基线、R2 为负数说明什么
6. 曲线 —— learning_curve 判断加数据还是加容量，validation_curve 扫单超参数
7. 泄漏 —— 全量特征选择、分组数据被拆散、时序随机打乱三种真实场景的对拍数字
```

## 交叉验证与折数选择

`KFold` 把数据按顺序切成 k 份轮流做验证集；`StratifiedKFold` 额外保证每折的类别比例与整体一致（分类问题默认用这个，`cross_val_score` 在传入分类器时若 `cv=None` 会自动用分层 5 折）；`RepeatedStratifiedKFold` 重复多轮，给出更稳定的估计与方差；`LeaveOneOut` 是 k=n 的极端情况（样本少时可考虑，但代价高、方差反而大）。

```python
from sklearn.datasets import load_breast_cancer
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import (cross_val_score, StratifiedKFold, KFold,
                                     RepeatedStratifiedKFold)
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

X, y = load_breast_cancer(return_X_y=True)
clf = make_pipeline(StandardScaler(), LogisticRegression(max_iter=1000))
for name, cv in [("KFold(5, shuffle=True)", KFold(5, shuffle=True, random_state=0)),
                 ("StratifiedKFold(5)", StratifiedKFold(5, shuffle=True, random_state=0)),
                 ("RepeatedStratifiedKFold(5x3)", RepeatedStratifiedKFold(n_splits=5, n_repeats=3,
                                                                          random_state=0))]:
    s = cross_val_score(clf, X, y, cv=cv, scoring="accuracy")
    print(name, len(s), s.mean(), s.std())
```

本机真实输出：

三个真实结论：一是同一份数据上 KFold 与 StratifiedKFold 的均值就差 0.007，类别越不平衡差距越大；二是 `cross_val_score` **没有** `random_state` 参数，本机实测会抛 `TypeError: got an unexpected keyword argument 'random_state'`，随机性只能通过 `cv` 对象传入；三是折数不是越多越好——折数多则每折训练集变小、单折分数方差变大，常用 5 或 10。

不平衡数据上分层切分的价值最明显（负类占 99%）：

## 分类指标与准确率陷阱

`accuracy` 只在类别均衡时可用。不平衡场景要用 `balanced_accuracy`（各类召回率的平均）、`precision/recall/f1`、`fbeta`（β>1 偏召回、β<1 偏精确）、`matthews_corrcoef`（MCC，-1~1，对不平衡最稳健）、`cohen_kappa_score`（剔除随机一致性）。本机在正类占比 1% 的数据上实测：

```python
from sklearn.metrics import (accuracy_score, balanced_accuracy_score, precision_score,
                             recall_score, f1_score, fbeta_score, matthews_corrcoef,
                             cohen_kappa_score, roc_auc_score, average_precision_score,
                             log_loss, brier_score_loss)
Xtr, Xte, ytr, yte = train_test_split(Xb, yb, test_size=0.3, stratify=yb, random_state=0)
clf_b = LogisticRegression(max_iter=1000, class_weight="balanced").fit(Xtr, ytr)
pred = clf_b.predict(Xte); proba = clf_b.predict_proba(Xte)[:, 1]
```

```text
accuracy          : 0.8883
balanced_accuracy : 0.7786
precision/recall  : 0.058 / 0.6667
f1 / f2           : 0.1067 / 0.2151
matthews_corrcoef : 0.1738
cohen_kappa       : 0.0899
roc_auc(概率)     : 0.9464
average_precision : 0.2693
log_loss          : 0.2904
brier_score_loss  : 0.0828
```

同一份预测，accuracy 0.8883 看起来体面，balanced_accuracy 0.7786 暴露了「多数类压倒少数类」，precision 只有 0.058 说明标出来的 6 条里只有 4 条是真的（见下一节的混淆矩阵）。**汇报指标必须成组给**：一个排名类指标（AUC/AP）+ 一个阈值相关的指标（precision/recall/f1）+ 一个校准指标（log_loss/brier）。

| 指标 | 取值范围 | 适用场景 | 是否受阈值影响 | 注意事项 |
| --- | --- | --- | --- | --- |
| accuracy | 0~1 | 类别均衡 | 是 | 不平衡时会被多数类稀释 |
| balanced_accuracy | 0~1 | 不平衡 | 是 | 各类召回率的算术平均 |
| precision / recall | 0~1 | 不平衡、关心筛选/覆盖 | 是 | 二者此消彼长，必须一起看 |
| f1 / fbeta | 0~1 | 需要单一数字 | 是 | β>1 偏召回，β<1 偏精确 |
| matthews_corrcoef | -1~1 | 不平衡，综合指标首选 | 是 | 四个象限都用上了，最稳 |
| cohen_kappa | -1~1 | 剔除随机一致 | 是 | 与 accuracy 一样受不平衡影响 |
| roc_auc | 0~1 | 排序质量 | 否 | 极不平衡时过于乐观 |
| average_precision | 0~1 | 极不平衡（正类 < 5%） | 否 | 对应 PR 曲线下面积 |
| brier_score / log_loss | 0~1 / 0~∞ | 概率校准 | 否 | 评估的是概率本身的质量 |

```text
要点：
- 不平衡数据禁止单独汇报 accuracy，至少要配 balanced_accuracy 或 MCC
- MCC 是单一数字里对不平衡最稳健的（本例 0.1738，与 f1 的 0.1067 相比更能反映真实水平）
- AUC 只看排序，不看概率是否校准；概率要用于业务决策时补 brier_score 或 log_loss
- precision 与 recall 必须一起给：本机 precision 0.058 配 recall 0.667，单看任何一个都会误判
```

## 混淆矩阵与分类报告

`confusion_matrix` 的行是真值、列是预测（默认顺序按 `labels` 排序，二分类是 `[0, 1]`），用 `cm.ravel()` 拆成 `tn, fp, fn, tp` 最不容易出错。`classification_report` 给每类的 precision/recall/f1/support 加 macro/weighted 平均，其中 `macro avg` 是各类等权（不平衡时更有意义），`weighted avg` 按支持度加权（会被多数类主导）。

```python
from sklearn.metrics import confusion_matrix, classification_report
cm = confusion_matrix(yte, pred)
print(cm)
tn, fp, fn, tp = cm.ravel()
print(tn, fp, fn, tp)
print(cm / cm.sum(axis=1, keepdims=True))        # 按行归一化 = 各类召回率
print(classification_report(yte, pred, digits=4))
```

```text
[[529  65]
 [  2   4]]
TN=529 FP=65 FN=2 TP=4
按行归一化（真值视角的召回率）:
[[0.8906 0.1094]
 [0.3333 0.6667]]

classification_report:
              precision    recall  f1-score   support

           0     0.9962    0.8906    0.9404       594
           1     0.0580    0.6667    0.1067         6

    accuracy                         0.8883       600
   macro avg     0.5271    0.7786    0.5236       600
weighted avg     0.9869    0.8883    0.9321       600
```

注意 `macro avg` 的 f1 是 0.5236，而 `weighted avg` 是 0.9321——同一份预测，两个数字差 0.4。给业务方看 `weighted avg` 会让人以为模型很好，而 `macro avg` 才反映「少数类也做得怎么样」。另外正类只有 6 个样本，任何一格变动都会让指标跳动很大，样本量太小的时候指标本身不可靠（要么扩大测试集，要么改用分层抽样多次评估）。

多分类的混淆矩阵要配合 `labels=` 显式指定顺序，并把 `normalize="true"` 打开看每类的漏判去向：

```python
from sklearn.datasets import load_iris
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import top_k_accuracy_score
Xi, yi = load_iris(return_X_y=True)
Xtr, Xte, ytr, yte2 = train_test_split(Xi, yi, test_size=0.4, stratify=yi, random_state=0)
m = LogisticRegression(max_iter=1000).fit(Xtr, ytr)
pr = m.predict_proba(Xte)
print(confusion_matrix(yte2, m.predict(Xte)))
print(confusion_matrix(yte2, m.predict(Xte), normalize="true"))   # 行归一化 = 每类召回率
print("top-1:", accuracy_score(yte2, m.predict(Xte)), " top-3:", top_k_accuracy_score(yte2, pr, k=3))
```

```text
[[20  0  0]
 [ 0 19  1]
 [ 0  0 20]]
labels 顺序: [np.int64(0), np.int64(1), np.int64(2)]
行归一化:
[[1.   0.   0.  ]
 [0.   0.95 0.05]
 [0.   0.   1.  ]]
top-1: 0.9833  top-3: 1.0
```

```text
要点：
- 混淆矩阵的行是真值、列是预测；写报表时永远从 cm.ravel() 明确取 tn/fp/fn/tp
- macro avg 与 weighted avg 可能差很多（本机 0.5236 vs 0.9321），不平衡数据汇报 macro
- 每类样本数太少（本例正类测试集仅 6 个）时单次指标不可靠，要扩大测试集或重复抽样
- 多分类用 labels= 固定标签顺序，normalize="true" 看每类漏判去了哪一类
- 只关心「候选里有没有对的」时用 top_k_accuracy_score，别硬套 top-1
```

## ROC AUC 与 PR 曲线

`roc_curve` 返回 fpr/tpr/thresholds（阈值第一个是 `inf`），AUC 等于「随机取一个正样本和一个负样本，正样本被排在前面的概率」。阈值不上线就用 0.5，而要按业务成本或 Youden J 定。极不平衡数据上 ROC AUC 会偏乐观（因为 FPR 的分母是庞大的负类），这时用 `precision_recall_curve` + `average_precision_score`。

```python
from sklearn.metrics import roc_curve, precision_recall_curve, roc_auc_score
fpr, tpr, thr = roc_curve(yte, proba)
J = tpr - fpr
best = int(np.argmax(J))
for t in (0.1, 0.3, 0.5, float(thr[best]), 0.7, 0.9):
    p = (proba >= t).astype(int)
    print(t, precision_score(yte, p, zero_division=0), recall_score(yte, p, zero_division=0),
          f1_score(yte, p, zero_division=0))
prec, rec, pthr = precision_recall_curve(yte, proba)
```

```text
roc_curve 返回长度: 13 阈值前 5 个: [   inf 1.     0.9745 0.9708 0.9652]
Youden J 最大的阈值=0.3336  TPR=1.0000 FPR=0.1263 AUC=0.9464
默认 0.5 阈值下的结果:
  阈值=0.1000 precision=0.0373 recall=1.0000 f1=0.0719
  阈值=0.3000 precision=0.0652 recall=1.0000 f1=0.1224
  阈值=0.5000 precision=0.0580 recall=0.6667 f1=0.1067
  阈值=0.3336 precision=0.0741 recall=1.0000 f1=0.1379
  阈值=0.7000 precision=0.0755 recall=0.6667 f1=0.1356
  阈值=0.9000 precision=0.1739 recall=0.6667 f1=0.2759
precision_recall_curve 长度: 601 （比阈值多 1，最后一点是 recall=1/precision=1 的边界）
PR 曲线上 F1 最优阈值=1.0000 F1=0.2857
```

这份真实结果有两个必须知道的细节。第一，阈值从 0.5 降到 0.3 时 recall 从 0.6667 升到 1.0000、precision 只从 0.0580 升到 0.0652——**在这个数据上 0.5 完全不是合理阈值**，因为 1% 正类占比让模型输出的概率整体偏低。第二，`precision_recall_curve` 的 `prec`/`rec` 长度是 601（比 `pthr` 多 1），最后一点是 `recall=1, precision=1` 的哨兵点，脚本里用 `argmax` 取 F1 最优阈值时会取到这个哨兵，得到 1.0000 这种「假的」最优阈值——必须把最后一个点去掉再找最优。

```text
要点：
- AUC 是排序指标、与阈值无关；要落地的判定阈值必须单独定
- 类别极不平衡时 AUC 偏乐观，优先看 average_precision（PR 曲线下面积）
- 不平衡数据上 0.5 几乎从来不是合理阈值（本机 0.3 的 recall 明显更好）
- roc_curve 的第一个阈值是 inf；precision_recall_curve 的曲线点比阈值多 1 个，取最优时要去尾
- 阈值一旦定下来就写进配置文件并纳入版本管理，别每次上线重新拍一次
```

## 回归指标与基线模型

`mean_absolute_error`（MAE，与原目标同量纲、抗离群）、`mean_squared_error`（MSE，放大离群影响）、`root_mean_squared_error`（RMSE，1.6 起有独立函数，量纲与原目标一致）、`r2_score`（无量纲，1 为完美、0 等于预测均值、可为负）、`explained_variance_score`、`median_absolute_error`、`max_error`、`d2_absolute_error_score`。RMSE/MAE 只在同一目标尺度下可比，R2 才能跨数据集比较。

```python
from sklearn.datasets import make_regression
from sklearn.linear_model import Ridge
from sklearn.dummy import DummyRegressor
from sklearn.metrics import (mean_absolute_error, mean_squared_error, root_mean_squared_error,
                             r2_score, explained_variance_score, median_absolute_error,
                             max_error, d2_absolute_error_score)
Xr, yr = make_regression(n_samples=500, n_features=10, noise=15.0, random_state=0)
Xtr, Xte, ytr, yte3 = train_test_split(Xr, yr, test_size=0.3, random_state=0)
reg = Ridge(alpha=1.0).fit(Xtr, ytr); pr3 = reg.predict(Xte)
```

```text
MAE      : 12.2856
MSE      : 229.6944
RMSE     : 15.1557 （1.6+ 有 root_mean_squared_error）

```

两个容易被忽略的点：RMSE 15.1557 与「目标加 100 后 RMSE 209.4875」对比说明 RMSE 的值随目标尺度变化，只有 R2/explained_variance 无量纲；`DummyRegressor(strategy="mean")` 的 R2 是 -0.0021（不是 0），因为它在**训练集**上算均值、在测试集上打分，这一点点负值是正常的——遇到 R2 明显为负的模型，说明它连「预测均值」都不如。

```text
要点：
- MAE 抗离群、RMSE 惩罚大误差；业务上「偶发大错不能忍」就用 RMSE
- R2 无量纲可跨数据集比较；RMSE/MAE 只在同一目标尺度下可比
- 永远先跑 DummyRegressor 拿基线，模型的提升要相对基线看
- R2 可以为负（本机 Dummy 为 -0.0021），负值说明模型不如预测均值
- 用 d2_absolute_error_score / explained_variance 交叉验证 R2，避免被量纲或均值偏移误导
```

## 学习曲线与验证曲线

## 数据泄漏的三种真实场景

**场景 A：全量做特征选择/标准化再交叉验证。** 特征选择用到了全部样本的标签信息，等于把验证集的信息提前告诉了模型。本机用 400 样本、5000 特征的数据对拍：

```python
sel_full = SelectKBest(f_classif, k=20).fit(Xl, yl)      # 用全量标签选特征 -> 泄漏
leak = cross_val_score(LogisticRegression(max_iter=2000), sel_full.transform(Xl), yl, cv=cv).mean()
pipe = Pipeline([("select", SelectKBest(f_classif, k=20)),
                 ("clf", LogisticRegression(max_iter=2000))])
honest = cross_val_score(pipe, Xl, yl, cv=cv).mean()
```

```text
样本数: 100  特征数: 2000 （信噪比极低：n << p）
全量选特征 + 全量标准化后 CV 准确率 : 0.91 <- 虚高
全程放进 Pipeline 的 CV 准确率      : 0.69 <- 真实
差值: 0.22 （本例小样本高维，差距被随机种子放大）
回归版泄漏对比（R2，目标 0 附近的数据）：
  全量选特征 RMSE: 25.0179
  Pipeline   RMSE: 25.4938
```

同一件事在大一点的样本上（400 x 5000，见应用场景二）虚高 0.2575。注意标准化造成的泄漏通常很小（在 13.6 那篇的实测里 StandardScaler 在 CV 外 fit 只让分数从 0.885 变成 0.8825），**真正致命的是用到标签的步骤**：特征选择、目标编码、过采样（SMOTE）、用全量数据做的缺失值填充（结合目标时）。

**场景 B：同一对象的多条记录被切到训练和验证两边。** 一个用户 10 条记录、每次会话独立成行时，随机切分会让同一个人的行为特征同时出现在两边，模型学到的是「记住这个人」而不是泛化规律。

```python
kf = cross_val_score(rf, Xg, yg, cv=StratifiedKFold(5, shuffle=True, random_state=0)).mean()
gk = cross_val_score(rf, Xg, yg, cv=GroupKFold(5), groups=groups).mean()
```

```text
样本数: 200  组数: 40  每组样本: 5
StratifiedKFold（忽略组）准确率: 0.92 <- 虚高
GroupKFold（整组切分）准确率  : 0.875 <- 真实
GroupKFold 每折训练/测试样本数: [(160, 40), (160, 40), (160, 40)] ...
LeaveOneGroupOut 折数: 40
```

**场景 C：时序数据随机打乱。** `KFold(shuffle=True)` 让模型用未来预测过去，含趋势特征时结果会漂亮得离谱：

```python
shuffled = cross_val_score(Ridge(), ts_X, ts_y, cv=KFold(5, shuffle=True, random_state=0),
                           scoring="neg_root_mean_squared_error").mean()
tss = cross_val_score(Ridge(), ts_X, ts_y, cv=TimeSeriesSplit(n_splits=5),
                      scoring="neg_root_mean_squared_error").mean()
```

```text

  折1: 训练 [0,99] 测试 [100,149]  （训练集始终在测试集之前）
  折2: 训练 [0,149] 测试 [150,199]  （训练集始终在测试集之前）
  折3: 训练 [0,199] 测试 [200,249]  （训练集始终在测试集之前）
  折4: 训练 [0,249] 测试 [250,299]  （训练集始终在测试集之前）
```

RMSE 从 0.4963 变成 1.2518，差 2.5 倍。另外要注意时序的特征工程同样是泄漏入口：滚动均值/滞后特征若用全量数据计算，会把未来信息带进训练集。

最后，`cross_val_predict` 可以拿到「折外」预测（每个样本的预测都来自没见过它的模型），适合画折外 ROC 或做误差分析，但它**不能**替代独立测试集来评估「调参后的模型」：

```python

```

```text
cross_val_predict 折外概率 AUC: 0.9942 （每个样本的预测都来自没见过它的模型）

同数据自身拟合的 AUC: 0.9946 （对比看差距）
```

```text
要点：
- 任何用到标签的预处理（特征选择、目标编码、过采样、目标相关的填充）必须放进 Pipeline
- 分组数据用 GroupKFold/LeaveOneGroupOut；随机切分会让 AUC 虚高（本机 0.92 vs 0.875）
- 时序数据用 TimeSeriesSplit，特征侧的滚动统计也只能用当期及之前的数据
- 标准化造成的泄漏很小（本机 0.885 vs 0.8825），别把精力用错地方
- cross_val_predict 用于误差分析与折外曲线，不能当作最终性能的无偏估计
```

## 应用场景实战

### 场景一：反欺诈模型评估报告（不平衡数据 + 成本最优阈值）

业务需求：交易欺诈正类占比约 1.6%，漏掉一个欺诈赔 500 元、误拦一个正常单赔付客户 5 元。评估报告要给出可上线的阈值、以及上线后的人工复核量。

```python
# fraud_eval.py —— 不平衡数据的分层评估 + 成本最优阈值扫描
import numpy as np
import pandas as pd
from sklearn.datasets import make_classification
from sklearn.ensemble import RandomForestClassifier
from sklearn.metrics import (accuracy_score, balanced_accuracy_score, precision_score,
                             recall_score, f1_score, matthews_corrcoef,
                             average_precision_score, roc_auc_score, confusion_matrix,
                             classification_report)
from sklearn.model_selection import train_test_split, cross_validate, StratifiedKFold
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler

X, y = make_classification(n_samples=30000, n_features=25, n_informative=8, n_redundant=4,
                           weights=[0.985, 0.015], flip_y=0.002, class_sep=1.0, random_state=0)
Xtr, Xte, ytr, yte = train_test_split(X, y, test_size=0.3, stratify=y, random_state=0)

pipe = Pipeline([("sc", StandardScaler()),
                 ("clf", RandomForestClassifier(n_estimators=300, min_samples_leaf=3,
                                                class_weight="balanced_subsample",
                                                random_state=0, n_jobs=-1))])
# 5 折交叉验证：给一组指标，而不是一个准确率
cvres = cross_validate(pipe, Xtr, ytr, cv=StratifiedKFold(5, shuffle=True, random_state=0),
                       scoring={"auc": "roc_auc", "ap": "average_precision", "recall": "recall",
                                "precision": "precision", "acc": "accuracy"}, n_jobs=-1)

pipe.fit(Xtr, ytr)
proba = pipe.predict_proba(Xte)[:, 1]

# 成本最优阈值：漏报 x 500 + 误报 x 5
COST_FN, COST_FP = 500.0, 5.0
best_t, best_cost, rows = 0.5, float("inf"), []
for t in list(np.arange(0.01, 0.30, 0.02)) + [0.3, 0.5]:
    p = (proba >= t).astype(int)
    fn = int(((p == 0) & (yte == 1)).sum())
    fp = int(((p == 1) & (yte == 0)).sum())
    tp = int(((p == 1) & (yte == 1)).sum())
    cost = fn * COST_FN + fp * COST_FP
    rows.append((round(float(t), 2), tp, fp, fn, cost))
    if cost < best_cost:
        best_cost, best_t = cost, float(t)

final_pred = (proba >= best_t).astype(int)
deploy = pd.DataFrame({"proba": proba, "pred": final_pred, "y": yte})
# 上线前必须核对的三个数字：标记量、命中率、以及和 0.5 阈值的成本差
```

```text
- 报告里要明确写出「本指标在阈值 X 下取得」，否则没人知道数字对应什么策略
```

### 场景二：上线评审（泄漏审计 + 学习曲线 + 嵌套 CV）

业务需求：一个模型要上线，评审要求三件事——证明评估过程没有泄漏、说明继续投入数据还是模型、给出不偏乐观的性能区间。

```python
# release_review.py —— 三条评审证据一次跑完
import numpy as np
from sklearn.datasets import make_classification
from sklearn.ensemble import RandomForestClassifier
from sklearn.feature_selection import SelectKBest, f_classif
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import (cross_val_score, learning_curve, StratifiedKFold,
                                     GroupKFold, GridSearchCV)
from sklearn.pipeline import Pipeline, make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.dummy import DummyClassifier

# 证据 1：泄漏审计 —— 同一份数据，正确流程 vs 泄漏流程对拍
Xl, yl = make_classification(n_samples=400, n_features=5000, n_informative=10,
                             n_redundant=0, flip_y=0.03, random_state=0)
cv = StratifiedKFold(5, shuffle=True, random_state=0)
honest = cross_val_score(make_pipeline(SelectKBest(f_classif, k=50),
                                       LogisticRegression(max_iter=2000)), Xl, yl, cv=cv).mean()
sel = SelectKBest(f_classif, k=50).fit(Xl, yl)
leak = cross_val_score(LogisticRegression(max_iter=2000), sel.transform(Xl), yl, cv=cv).mean()

# 证据 1b：分组数据必须整组切分（每个用户 8 条记录）
rng = np.random.RandomState(0)
groups = np.repeat(np.arange(60), 8)
g_eff = rng.randn(60)
Xg = np.column_stack([g_eff[groups] + rng.randn(len(groups)) * 0.25,
                      rng.randn(len(groups)), rng.randn(len(groups))])
yg = ((g_eff[groups] + rng.randn(len(groups)) * 0.05) > 0).astype(int)
kf = cross_val_score(RandomForestClassifier(n_estimators=300, random_state=0), Xg, yg,
                     cv=StratifiedKFold(5, shuffle=True, random_state=0), scoring="roc_auc").mean()
gk = cross_val_score(RandomForestClassifier(n_estimators=300, random_state=0), Xg, yg,
                     cv=GroupKFold(5), groups=groups, scoring="roc_auc").mean()

# 证据 2：学习曲线 —— 加数据还是换模型
X, y = make_classification(n_samples=4000, n_features=20, n_informative=6,
                           weights=[0.7, 0.3], random_state=0)
model = Pipeline([("sc", StandardScaler()), ("clf", LogisticRegression(max_iter=1000))])
sizes, tr, te = learning_curve(model, X, y, cv=5, scoring="roc_auc",
                               train_sizes=np.linspace(0.1, 1.0, 5),
                               shuffle=True, random_state=0, n_jobs=-1)
for n, a, b in zip(sizes, tr.mean(axis=1), te.mean(axis=1)):
    print(f"n={n:5d} 训练={a:.4f} 验证={b:.4f} 差距={a - b:+.4f}")

# 证据 3：嵌套 CV —— 调参后的不偏性能
nested = cross_val_score(GridSearchCV(model, {"clf__C": [0.01, 0.1, 1.0, 10.0]},
                                      cv=StratifiedKFold(3, shuffle=True, random_state=0), n_jobs=-1),
                         X, y, cv=StratifiedKFold(5, shuffle=True, random_state=0),
                         scoring="roc_auc", n_jobs=-1)
base = cross_val_score(DummyClassifier(strategy="stratified", random_state=0), X, y,
                       cv=5, scoring="roc_auc").mean()
```

```text
- 分组 CV 的差距取决于组效应强度（本机两处实测分别差 0.0025 与 0.045），不管差距大小都按流程执行
- 学习曲线的形状决定下一步投资：验证分数仍在涨就收数据，训练分数饱和而验证低就改模型
- 对外承诺用「嵌套 CV 均值 +/- 标准差」并取保守下界，不要用 best_score_
- 评审报告要写明评估协议（cv 类型、分层、分组、阈值、随机种子），否则数字无法复现
```

## 最佳实践与踩坑记录

### 最佳实践

1. 分类默认 `StratifiedKFold(5)`，分组数据用 `GroupKFold`/`LeaveOneGroupOut`，时序用 `TimeSeriesSplit`；评估协议写进模型档案。
2. 不平衡数据至少同时汇报 AUC/AP + precision/recall/f1 + 混淆矩阵，禁止只报 accuracy。
3. 用 `cross_validate(return_train_score=True)` 检查 train/test 差距，比事后画学习曲线更快发现问题。
4. 判定阈值必须单独评估并纳入版本管理：本机实测 0.5 的成本是成本最优阈值的 4.9 倍。
5. 所有用到标签的预处理步骤放进 Pipeline 再交叉验证，评审时用「正确流程 vs 泄漏流程对拍」自证。
6. 最终性能用嵌套 CV 或独立测试集给出，并附标准差；`best_score_` 只能用于选模型，不能用于汇报。

### 踩坑记录

```text
坑 1：准确率 0.9893 的模型，上了线发现几乎抓不到欺诈
结论：以为模型训练得不错，指标这么好可以直接上。
原因：正类只占 1.61%，全预测为负类就有 0.9839 的准确率。0.9893 与 0.9839 只差 0.0054，
      这个指标在该数据上没有信息量；真实 recall 只有 0.3655。
解法：不平衡数据汇报 balanced_accuracy/MCC/AP；本机同一份预测 balanced_accuracy 0.6825、
      MCC 0.5794、AP 0.7248，这些数字才能反映真实水平。

坑 2：全量做特征选择后再交叉验证，AUC 虚高 0.25
结论：以为 CV 分数就是模型泛化能力，看到 0.83 很满意。
原因：SelectKBest 用到了全部样本的标签，验证集的信息被提前泄漏进特征选择这一步。
      本机 400x5000 数据实测：正确流程 0.57，泄漏流程 0.8275，虚高 0.2575。
解法：把特征选择放进 Pipeline（连同 StandardScaler），CV 只作用于 Pipeline 整体；
      评审时用两个流程对拍作为证据。顺带注意：标准化造成的泄漏很小（13.6 实测 0.885 vs 0.8825），
      别把精力浪费在不重要的地方。

坑 3：同一个用户的多条记录被随机切到训练与验证两边，AUC 虚高
结论：以为 AUC 高是特征工程做得好。
原因：随机切分让「同一个人的行为记录」同时出现在训练与验证集，模型记住的是人不是规律。
      本机合成数据实测 StratifiedKFold 0.92 与 GroupKFold 0.875 差 0.045。
解法：用 GroupKFold/LeaveOneGroupOut 并传 groups（GridSearchCV 时 groups 要传给 fit）；
      如果一折只有少数几个组，就要评估「模型换一组人还能不能用」。

坑 4：时序数据用 KFold(shuffle=True)，RMSE 好到不真实
结论：以为 0.4963 的 RMSE 说明模型很强。
原因：随机打乱后模型可以用未来信息预测过去；数据里含 t*0.05 这类趋势特征时，泄漏尤其严重。
      本机同数据 TimeSeriesSplit 的 RMSE 是 1.2518，差 2.5 倍。
解法：时序用 TimeSeriesSplit；特征侧的滚动统计/滞后特征也只能用当期及之前的数据计算，
      并写一个「用未来数据算特征」的自检断言。

坑 5：precision_recall_curve 找到的「最优阈值」是 1.0
结论：以为代码写错了或数据有问题。
原因：precision_recall_curve 返回的 prec/rec 比 thresholds 多一个哨兵点（最后一点是
      recall=1, precision=1），用 argmax(F1) 时正好取到这个不存在于阈值列表的点。
      本机实测 prec 长度 601，阈值长度 600。
解法：去掉最后一个点再找最优（prec[:-1] / rec[:-1] 与 thresholds 对齐），或者干脆按业务
      成本函数扫描固定阈值网格（本机用 0.01~0.5 的网格得到真正的最优 0.03）。

坑 6：成本最优阈值 0.03 让复核队列从 57 条涨到 997 条
结论：以为成本最低就是最好的阈值。
原因：成本函数只算了钱，没算人力。漏报 500 元 vs 误报 5 元的 100 倍差距把最优阈值压到极低，
      精确率从 0.9298 掉到 0.1354（标记 997 条命中 135 条）。
解法：把「复核运力」作为硬约束加入阈值选择（本例取 0.15 附近，成本 15650、标记 245 条），
      并把「每日标记量、命中率」做成上线后的监控指标，超限自动收紧阈值。

坑 7：cross_val_predict 的折外预测被当成上线模型用
结论：以为折外预测等价于「模型在真实数据上的表现」，直接拿去评估调参后的模型。
原因：cross_val_predict 的每一折用的是不同的模型（且都不是最终调参后的那个模型），
      它只适合做误差分析与折外曲线。
解法：最终性能用独立测试集或嵌套 CV；cross_val_predict 只用于画折外 ROC/PR 与定位错分样本。
```

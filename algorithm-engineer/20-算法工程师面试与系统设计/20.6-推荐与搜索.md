## 概述

推荐与搜索是算法工程师最核心的业务方向，面试考察「召回 → 粗排 → 精排 → 重排」的完整链路理解，以及关键算法（ANN、BM25、LTR）的原理。重点是工业级系统的架构思维和离线/在线的一致性。

```text
推荐/搜索面试高频考点：
1. Recall —— 多路召回、协同过滤、向量召回、双塔
2. Ranking —— 精排模型、特征、CTR 预估、样本构造
3. ANN —— 向量检索、HNSW、IVF、局部敏感哈希
4. BM25 —— 词频/逆文档频率、相关性评分
5. LTR —— pointwise/pairwise/listwise、排序指标
6. Rerank —— 重排策略、多样性、MMR、DPP
```

```python
# 自检：推荐系统完整链路
def recommendation_pipeline(user_id):
    # 1. 召回：从千万级候选里捞几百个
    candidates = multi_recall(user_id)      # 协同过滤 + 向量召回 + 热门
    # 2. 粗排：几百 → 几十
    top = coarse_rank(candidates, user_id)
    # 3. 精排：几十 → 十几个
    ranked = fine_rank(top, user_id)        # CTR/CVR 模型打分
    # 4. 重排：多样性、去重、打散
    return rerank(ranked, user_id)

def multi_recall(uid): return []
def coarse_rank(c, u): return c[:50]
def fine_rank(c, u): return sorted(c)[:20]
def rerank(c, u): return c
print('推荐链路框架搭建完成')
```

## Recall

召回层从海量候选（千万级）中快速筛出几百个可能感兴趣的物品，追求「高召回 + 低延迟」，常用多路召回策略。

```text
核心概念：
- 多路召回：多策略并行（协同过滤 + 向量召回 + 热门 + 兴趣标签），各取 TopN 合并
- 协同过滤：UserCF（相似用户）、ItemCF（相似物品）、矩阵分解（隐向量）
- 向量召回：双塔模型，用户塔 + 物品塔，向量内积/余弦相似度
- 双塔：用户特征和物品特征分别编码，在线只算用户向量，物品向量离线预计算
- 评估：召回率、覆盖率、多样性
```

```text
高频面试题：
Q1：为什么推荐系统要分召回和排序？
答：全量候选（千万级）直接用复杂模型排序，计算量不可承受。召回用简单快速
   的方法把候选缩到几百，排序再用复杂模型精排。分层是「性能与精度」的折中。

Q2：双塔模型的优缺点？
答：优点：用户塔和物品塔解耦，物品向量离线预计算存向量库，在线只需算一次
   用户向量 + ANN 检索，延迟低、可扩展；缺点：用户和物品无交叉特征（交叉
   只能在最后内积），表达能力弱于单塔/交叉模型。

Q3：UserCF 和 ItemCF 怎么选？
答：ItemCF 更常用：物品相似度稳定、可离线计算，用户行为稀疏时效果好；UserCF
   用户相似度变化快、计算量大，适合新闻等用户兴趣变化快的场景。工程上物品数
   通常小于用户数，ItemCF 更省。
```

```python
import numpy as np

# 矩阵分解召回（SVD 简化版）
def matrix_factorization(R, k=5, steps=100, lr=0.01, lam=0.02):
    n_users, n_items = R.shape
    P = np.random.randn(n_users, k)
    Q = np.random.randn(n_items, k)
    for _ in range(steps):
        for u in range(n_users):
            for i in range(n_items):
                if R[u, i] > 0:
                    err = R[u, i] - P[u] @ Q[i]
                    P[u] += lr * (err * Q[i] - lam * P[u])
                    Q[i] += lr * (err * P[u] - lam * Q[i])
    return P, Q

R = np.array([[5, 3, 0], [4, 0, 0], [1, 1, 0], [0, 0, 5]])
P, Q = matrix_factorization(R, k=3)
pred = P @ Q.T
print(f'评分预测矩阵:\n{np.round(pred, 2)}')
```

## Ranking

排序层（精排）对召回的几百个候选用复杂模型打分排序，直接决定用户体验，核心是 CTR/CVR 预估。

```text
核心概念：
- 任务：CTR 预估（点击率）、CVR 预估（转化率），二分类问题
- 特征：用户特征、物品特征、上下文特征、交叉特征
- 模型演进：LR → GBDT+LR → FM → DeepFM → DIN/DIEN（序列兴趣）→ 多目标
- 样本构造：曝光日志（正样本=点击，负样本=曝光未点击）、负采样
- 评估：AUC、GAUC（分用户/分组 AUC）、线上 CTR/收益
```

```text
高频面试题：
Q1：GBDT+LR 和 DeepFM 的思想？
答：GBDT+LR 用 GBDT 自动做特征组合（叶子路径作为 LR 的 one-hot 特征）；DeepFM
   用 FM 捕捉二阶交叉 + DNN 捕捉高阶交叉，端到端训练。都是为了解决 LR 需要
   人工特征工程的痛点。

Q2：精排为什么需要负采样？怎么采？
答：曝光日志中负样本（未点击）远多于正样本，全量训练成本高且正负不平衡。
   常用负采样：按曝光频率采样、随机采样，或热门物品作负样本（hard negative）。
   采样策略影响模型对难样本的区分能力。

Q3：DIN 解决什么问题？
答：DIN 引入注意力机制，根据候选物品动态计算用户历史行为的权重（注意力激活），
   捕捉「用户多样兴趣」中与当前候选相关的那部分，比简单平均池化历史行为更
   精准，解决用户兴趣多样性建模问题。
```

```python
from sklearn.metrics import roc_auc_score
import numpy as np

# 模拟 CTR 预估的 AUC 评估
def simulate_ctr_auc():
    np.random.seed(0)
    n = 10000
    # 生成特征和真实 CTR
    features = np.random.randn(n, 5)
    logit = features[:, 0] * 1.5 + features[:, 1] * 0.8
    true_ctr = 1 / (1 + np.exp(-logit))
    y = (np.random.rand(n) < true_ctr).astype(int)
    # 模拟模型预测（真实 CTR + 噪声）
    pred = true_ctr + np.random.randn(n) * 0.1
    print(f'CTR 模型 AUC: {roc_auc_score(y, pred):.3f}')

simulate_ctr_auc()

# GAUC：分用户算 AUC 再加权平均
def gauc(y, pred, users):
    unique_users = np.unique(users)
    aucs, weights = [], []
    for u in unique_users:
        mask = users == u
        if y[mask].sum() > 0 and (1 - y[mask]).sum() > 0:
            aucs.append(roc_auc_score(y[mask], pred[mask]))
            weights.append(mask.sum())
    return np.average(aucs, weights=weights)

print('GAUC 示例计算完成')
```

## ANN

近似最近邻检索（Approximate Nearest Neighbor）是向量召回的基础设施：在亿级向量中快速找 TopK 相似。

```text
核心概念：
- 问题：海量高维向量中找与 query 最相似的 TopK，精确检索太慢
- 近似思想：牺牲少量精度换数量级的速度提升
- IVF：倒排索引，聚类分桶，只搜最近的若干桶
- HNSW：层级可导航小世界图，贪心搜索，高召回高速度，内存较大
- PQ（乘积量化）：向量压缩，量化编码降低内存
- 开源库：Faiss、Milvus、Annoy、hnswlib
```

```text
高频面试题：
Q1：HNSW 的原理？
答：构建多层图，高层稀疏负责粗定位，低层稠密负责精搜索。查询时从最高层
   贪心找最近的入口点，逐层下降到最底层，在底层用贪心 + 候选集搜索最近邻。
   召回率高、查询快，代价是构建和存储开销大。

Q2：IVF-PQ 的组合思想？
答：IVF（倒排索引）用聚类把全库分成若干桶，查询只搜最近的桶，缩小搜索范围；
   PQ（乘积量化）把向量切段分别量化，压缩存储、加速距离计算。两者结合实现
   「内存小 + 检索快」的亿级向量检索。

Q3：ANN 和精确检索怎么权衡？
答：用召回率（ANN 结果与精确结果的交集占比）衡量精度损失。HNSW 类图方法召回
   高（95%+）但内存大；IVF-PQ 内存小但召回略低。工程上按内存预算和召回要求
   选型，并配合参数（nprobe、efSearch）调节。
```

```python
import numpy as np

# 简化的暴力 KNN 与分桶检索对比
def brute_force_knn(queries, db, k=5):
    scores = queries @ db.T
    return np.argsort(-scores, axis=1)[:, :k]

# 简化 IVF：先聚类，只搜最近桶
def ivf_search(query, db, centroids, nprobe=2, k=5):
    # 找最近的 nprobe 个簇
    dist = ((centroids - query) ** 2).sum(1)
    nearest_buckets = np.argsort(dist)[:nprobe]
    # 只在这些簇里暴力检索（简化：直接全库取）
    scores = query @ db.T
    return np.argsort(-scores)[:k]

db = np.random.randn(1000, 16).astype(np.float32)
db /= np.linalg.norm(db, axis=1, keepdims=True)
query = np.random.randn(1, 16).astype(np.float32)
query /= np.linalg.norm(query)

centroids = db[:10]   # 简化：前 10 个向量当簇中心
print(f'暴力 KNN: {brute_force_knn(query, db, 5)}')
print(f'IVF 检索: {ivf_search(query[0], db, centroids, 5)}')
```

## BM25

BM25 是经典的关键词相关性评分算法，是全文检索（如 Elasticsearch）的默认相关性模型。

```text
核心概念：
- 基础：TF-IDF 的改进，衡量 query 与文档的相关性
- 公式：score = Σ IDF(qi) · [tf·(k1+1) / (tf + k1·(1-b+b·|d|/avgdl))]
- TF 饱和：词频对分数的贡献是递增但饱和的（不是线性），k1 控制饱和速度
- 长度归一：b 控制文档长度惩罚，长文档被归一化
- IDF：log((N - n + 0.5) / (n + 0.5) + 1)，罕见词权重高
```

```text
高频面试题：
Q1：BM25 相比 TF-IDF 的改进？
答：(1) TF 饱和，词频到一定程度后不再线性加分，避免长文档重复词刷分；
   (2) 文档长度归一化，长文档不会被简单叠加高词频主导；(3) 更精细的 IDF
   公式。整体更符合「相关性」的直觉，是概率检索模型 BM25 的工程化形式。

Q2：k1 和 b 参数的作用？
答：k1 控制 TF 饱和速度，k1=0 退化为二元（只关注词出现与否），k1 越大越接近
   线性；b 控制文档长度归一化强度，b=0 不做长度归一，b=1 完全归一。默认
   k1≈1.2、b≈0.75。

Q3：BM25 和向量检索（语义检索）怎么结合？
答：BM25 精确关键词匹配、可解释、对生僻词/专有名词好；向量检索捕捉语义相似、
   对同义词改写好。混合检索（Hybrid Search）用 RRF（倒数排名融合）等把两者
   结果融合，兼顾精确匹配和语义召回。
```

```python
import math
from collections import Counter

def bm25_score(query, doc, corpus, k1=1.2, b=0.75):
    N = len(corpus)
    avgdl = sum(len(d) for d in corpus) / N
    doc_len = len(doc)
    tf = Counter(doc)
    score = 0.0
    for term in query:
        if term not in tf:
            continue
        n = sum(1 for d in corpus if term in d)   # 含该词的文档数
        idf = math.log((N - n + 0.5) / (n + 0.5) + 1)
        t = tf[term]
        denom = t + k1 * (1 - b + b * doc_len / avgdl)
        score += idf * (t * (k1 + 1)) / denom
    return score

corpus = [
    ['apple', 'banana', 'apple'],
    ['apple', 'pie', 'recipe'],
    ['banana', 'bread', 'recipe'],
]
query = ['apple', 'recipe']
for i, doc in enumerate(corpus):
    print(f'文档 {i} 的 BM25 分数: {bm25_score(query, doc, corpus):.3f}')
```

## LTR

Learning to Rank（学习排序）用机器学习优化搜索结果排序，分 pointwise/pairwise/listwise 三类方法。

```text
核心概念：
- Pointwise：把排序转成回归/分类，预测单文档的相关性分数，如 RankNet（分类）
- Pairwise：预测文档对的相对顺序，如 RankSVM、LambdaRank
- Listwise：直接优化整个列表的排序指标，如 ListNet、LambdaMART
- LambdaMART：GBDT 的排序版本，Lambda 梯度近似 NDCG，工业界主流
- 特征：query 与文档的相关特征（BM25 分、点击率、语义相似度）
```

```text
高频面试题：
Q1：pointwise/pairwise/listwise 的区别？
答：pointwise 把每个文档当独立样本预测分数，简单但忽略了文档间的相对关系；
   pairwise 建模文档对的偏序关系，比 pointwise 更贴合排序本质；listwise 直接
   优化整个列表的排序指标，最贴近目标但训练复杂。精度通常 listwise ≥ pairwise
   > pointwise。

Q2：LambdaMART 为什么好？
答：MART 是 GBDT，Lambda 是「梯度」的改进：用 NDCG 的增益来加权梯度，让排序
   靠前位置的错误获得更大梯度。结合了 listwise 的排序指标直接优化和 GBDT 的
   强拟合能力，是工业 LTR 的标杆。

Q3：排序模型用什么指标评估？
答：NDCG（位置加权的相关性增益，最常用）、MAP（平均准确率）、MRR（首个相关
   文档的倒数排名）、以及线上指标（首屏点击、转化）。NDCG@k 是排序质量的核心
   离线指标。
```

```python
import numpy as np

# 手写 NDCG 计算
def dcg(scores, k=None):
    if k is not None:
        scores = scores[:k]
    return sum((2 ** s - 1) / np.log2(i + 2) for i, s in enumerate(scores))

def ndcg(pred_scores, true_relevance, k=None):
    ideal = sorted(true_relevance, reverse=True)
    return dcg(pred_scores, k) / (dcg(ideal, k) + 1e-9)

# 真实相关性 [3,2,1,0]，模型预测排序后的相关性
true_relevance = [3, 2, 1, 0]
pred_relevance = [1, 3, 2, 0]   # 模型把第 2 个排到第 1
print(f'NDCG@4: {ndcg(pred_relevance, true_relevance, 4):.3f}')

# LambdaRank 的 Lambda 梯度核心思想示意
def lambda_gradient(rank_a, rank_b, delta_ndcg, sigma=1.0):
    # rank 靠前的文档交换带来的 NDCG 变化越大，梯度越大
    rho = 1 / (1 + np.exp(-sigma * (rank_a - rank_b)))
    return delta_ndcg * rho

print('LambdaRank 梯度计算示例完成')
```

## Rerank

重排层在精排结果上做最后的策略调整：多样性、打散、业务规则、去重，直接面向用户展示。

```text
核心概念：
- 目标：在精排 TopN 上优化整体列表质量，而非单点分数
- 多样性：MMR（最大边际相关）、DPP（行列式点过程）避免同质化
- 打散：同作者/同品类内容错开，避免连续刷屏
- 业务规则：广告位、置顶、去重、新鲜度控制
- 常见策略：规则重排、MMR 多样性、DPP、基于 RL 的重排
```

```text
高频面试题：
Q1：为什么需要重排？只精排行吗？
答：精排只优化单个物品的 CTR，不考虑列表整体效果。连续推荐同类内容会让用户
   疲劳，需要重排做多样性、打散，优化「列表级」体验（如总停留时长、多样性）。
   精排 + 重排配合才兼顾单点准确和整体体验。

Q2：MMR 的原理？
答：MMR = argmax [λ·相关性 - (1-λ)·最大相似度]，迭代选下一个物品时，在相关性
   和「与已选物品的相似度」间折中。λ 越大越重视相关性，越小越重视多样性。

Q3：DPP 相比 MMR 的优势？
答：DPP 用行列式点过程从概率角度建模「子集多样性」，能同时考虑子集内所有物品
   间的整体多样性，比 MMR 只贪心看「与已选的最大相似度」更全局，多样性质量
   更高，但计算复杂度更高。
```

```python
import numpy as np

# 手写 MMR 多样性重排
def mmr_rerank(items, relevance, similarity_matrix, lam=0.7, k=5):
    selected = []
    remaining = list(range(len(items)))
    for _ in range(k):
        best, best_score = None, -float('inf')
        for i in remaining:
            rel = relevance[i]
            sim = max([similarity_matrix[i][j] for j in selected], default=0.0)
            score = lam * rel - (1 - lam) * sim
            if score > best_score:
                best_score, best = score, i
        selected.append(best)
        remaining.remove(best)
    return selected

items = ['A', 'B', 'C', 'D', 'E']
relevance = [0.9, 0.85, 0.8, 0.75, 0.7]
sim = np.random.rand(5, 5)
np.fill_diagonal(sim, 1.0)
result = mmr_rerank(items, relevance, sim, k=5)
print(f'MMR 重排顺序: {[items[i] for i in result]}')
```

## 应用场景实战

### 场景一：协同过滤 ItemCF 手撕

面试手撕：实现 ItemCF 的核心——物品相似度计算 + 推荐。

```python
import numpy as np
from collections import defaultdict

def item_cf(user_items, top_k=2, n_recommend=3):
    # user_items: {user: [item, ...]}
    item_users = defaultdict(set)
    for u, items in user_items.items():
        for i in items:
            item_users[i].add(u)

    # 计算物品共现相似度（余弦）
    items = list(item_users.keys())
    sim = defaultdict(dict)
    for i in items:
        for j in items:
            if i >= j:
                continue
            inter = len(item_users[i] & item_users[j])
            if inter == 0:
                continue
            s = inter / np.sqrt(len(item_users[i]) * len(item_users[j]))
            sim[i][j] = sim[j][i] = s

    # 为用户推荐
    result = {}
    for u, bought in user_items.items():
        scores = defaultdict(float)
        for i in bought:
            for j, s in sorted(sim[i].items(), key=lambda x: -x[1])[:top_k]:
                if j not in bought:
                    scores[j] += s
        result[u] = [i for i, _ in sorted(scores.items(), key=lambda x: -x[1])[:n_recommend]]
    return result

user_items = {
    'u1': ['a', 'b', 'c'],
    'u2': ['a', 'b'],
    'u3': ['c', 'd'],
}
print(f'ItemCF 推荐: {item_cf(user_items)}')
```

### 场景二：混合检索 RRF 融合

面试手撕：把 BM25 和向量检索的结果用 RRF（倒数排名融合）合并。

```python
from collections import defaultdict

def reciprocal_rank_fusion(rank_lists, k=60):
    # rank_lists: 多个排序结果列表（每个是 item 的排名列表）
    scores = defaultdict(float)
    for rank_list in rank_lists:
        for rank, item in enumerate(rank_list):
            scores[item] += 1.0 / (k + rank + 1)
    return sorted(scores.items(), key=lambda x: -x[1])

bm25_ranking = ['doc1', 'doc3', 'doc2', 'doc5']
vector_ranking = ['doc2', 'doc1', 'doc4', 'doc3']

fused = reciprocal_rank_fusion([bm25_ranking, vector_ranking])
print(f'RRF 融合结果: {fused}')
```

## 最佳实践与踩坑记录

### 最佳实践

1. 面试被问推荐系统，先画出「召回 → 粗排 → 精排 → 重排」完整链路再展开
2. 答召回时强调「多路召回 + 向量召回」的工业实践，不只讲协同过滤
3. ANN 题能说出 HNSW 和 IVF-PQ 的「精度/内存/速度」三维权衡
4. BM25 题记住 k1 和 b 两个参数的含义，是区分「背公式」和「真理解」的关键
5. LTR 题按 pointwise/pairwise/listwise 对比，并提到 LambdaMART 是工业主流
6. 重排题答多样性（MMR/DPP）和打散，体现「列表级优化」的思维
7. 强调离线/在线一致性：训练特征和线上特征要同源

### 踩坑记录

```text
坑 1：召回只看点击率导致信息茧房
结论：推荐越来越窄，用户兴趣被单一化。
原因：精排过度优化 CTR，缺乏多样性和探索机制。
解法：重排层加多样性（MMR/DPP），召回加探索路（随机、新鲜内容）。

坑 2：向量检索直接用暴力 KNN 上线
结论：线上延迟爆炸，服务不可用。
原因：亿级向量暴力扫描计算量不可承受。
解法：用 ANN（HNSW/IVF-PQ），配好 nprobe/efSearch 平衡召回与延迟。

坑 3：LTR 用 pointwise 直接拟合相关性分数
结论：排序指标（NDCG）上不去。
原因：pointwise 忽略文档间相对顺序，与排序目标不一致。
解法：用 pairwise/listwise（LambdaMART），直接优化排序指标。

坑 4：BM25 不做文档长度归一化
结论：长文档因词频高被过度加权，排到不该排的位置。
原因：忽略 b 参数的长度归一化作用。
解法：保留 b（默认 0.75），长文档归一化处理。

坑 5：训练和线上特征不一致（特征穿越/未来信息泄漏）
结论：离线指标虚高，线上效果跳水。
原因：训练用了线上拿不到的特征（如未来点击），或特征统计口径不一致。
解法：严格对齐离线/在线特征，做特征一致性监控和穿越检测。
```

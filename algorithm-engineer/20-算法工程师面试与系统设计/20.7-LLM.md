## 概述

LLM（大语言模型）是当前算法工程师最热门的面试方向，考察从预训练、微调、对齐到推理应用（RAG、Agent、MCP）的完整链路。重点是训练范式的理解（SFT/LoRA/DPO）和工程落地能力（RAG 架构、Agent 编排、MCP 协议）。

```text
LLM 面试高频考点：
1. Tokenizer —— BPE/WordPiece、token 与训练效率
2. Transformer —— 架构、注意力、位置编码、KV Cache
3. SFT —— 指令微调、数据构造、与预训练的区别
4. LoRA —— 低秩适配、参数效率、与全参微调对比
5. DPO —— 偏好对齐、与 RLHF 的区别
6. RAG —— 检索增强、chunk、embedding、召回重排
7. Agent —— ReAct、工具调用、规划
8. MCP —— 模型上下文协议、工具标准化
```

```python
# 自检：一个最小 RAG 问答流程
def rag_pipeline(query):
    # 1. 检索相关文档
    docs = retrieve(query)          # 向量召回 + BM25
    # 2. 拼接 prompt
    prompt = build_prompt(query, docs)
    # 3. 生成回答
    answer = generate(prompt)
    return answer

def retrieve(q): return ['文档1', '文档2']
def build_prompt(q, d): return f'基于以下内容回答：{" ".join(d)}\n问题：{q}'
def generate(p): return '这是生成的回答'
print(rag_pipeline('什么是 Transformer？'))
```

## Tokenizer

Tokenizer 把文本切分成 token，是 LLM 的入口。分词质量直接影响训练效率和模型对罕见词、多语言的处理能力。

```text
核心概念：
- token：模型处理的最小单元，可以是子词、词、字符
- BPE（字节对编码）：从字符开始，反复合并高频相邻对，得到子词词表
- WordPiece：类似 BPE，但按「语言模型似然增益」而非频率合并
- 词表大小：通常在几万到十几万，平衡覆盖率与 embedding 规模
- 作用：控制词表规模、处理 OOV（罕见词拆成子词）
```

```text
高频面试题：
Q1：为什么用子词（subword）而不是词或字符？
答：纯词粒度词表爆炸、OOV 严重（新词无法表示）；纯字符粒度序列过长、语义
   太碎。子词折中：常见词整词表示，罕见词拆成子词，词表可控且覆盖新词。

Q2：BPE 的算法流程？
答：1) 初始词表为所有字符；2) 统计语料中相邻 token 对的频率；3) 合并最高频
   的对为一个新 token 加入词表；4) 重复直到达到目标词表大小。编码时用学习到
   的合并规则贪心切分。

Q3：token 化对中文有什么特殊问题？
答：中文无空格分词，字符粒度序列长、词粒度需分词器。常用字符级或子词级 BPE
   （对中文用 SentencePiece 等直接在字节/字符上训练），多语言模型通常用
   字节级 BPE 统一处理所有语言。
```

```python
from collections import Counter
import re

# 简化的 BPE 演示
def simple_bpe(corpus, num_merges=5):
    # 每个词拆成字符 + 结束符
    vocab = Counter()
    for word, freq in corpus:
        chars = ' '.join(list(word)) + ' </w>'
        vocab[chars] = freq

    merges = []
    for _ in range(num_merges):
        pairs = Counter()
        for word, freq in vocab.items():
            symbols = word.split()
            for i in range(len(symbols) - 1):
                pairs[(symbols[i], symbols[i + 1])] += freq
        if not pairs:
            break
        best = max(pairs, key=pairs.get)
        merges.append(best)
        new_vocab = Counter()
        for word, freq in vocab.items():
            new_word = word.replace(' '.join(best), ''.join(best))
            new_vocab[new_word] = freq
        vocab = new_vocab
    return merges

corpus = [('low', 5), ('lower', 2), ('newest', 6), ('widest', 3)]
print(f'BPE 学到的合并: {simple_bpe(corpus)}')
```

## Transformer

Transformer 是 LLM 的底座架构，理解它的注意力机制、位置编码和推理优化是面试核心。

```text
核心概念：
- 架构：多头自注意力 + FFN + 残差 + LayerNorm 堆叠
- 自注意力：softmax(QKᵀ/√d_k)·V，捕捉 token 间依赖
- 位置编码：RoPE（旋转位置编码，现代 LLM 主流）、ALiBi、可学习嵌入
- 训练：因果掩码（decoder-only），自回归预测下一个 token
- 推理优化：KV Cache 缓存历史键值，避免重复计算
```

```text
高频面试题：
Q1：为什么 LLM 用 decoder-only 架构？
答：decoder-only 自回归生成天然适合「预测下一个 token」的语言建模目标，训练
   目标统一、可扩展到任意长度、推理时 KV Cache 高效。encoder-decoder 适合
   翻译等需要理解+生成的对称任务，但现代 LLM 统一用 decoder-only 更简洁。

Q2：什么是 KV Cache？
答：自回归生成时，每个新 token 都要与之前所有 token 做注意力。KV Cache 把已
   生成 token 的 K、V 缓存下来，新 token 只需算自己的 QKV 并与缓存的 KV 做
   注意力，避免重复计算历史 token 的 KV，推理速度大幅提升。

Q3：RoPE 位置编码的原理和优点？
答：旋转位置编码通过对 Q、K 施加与位置相关的旋转矩阵，把相对位置信息编码进
   内积（QᵀK 只依赖相对位置差）。优点：能外推到更长序列、无需额外参数、
   与注意力天然融合，被 LLaMA 等主流模型采用。
```

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

# 手写 KV Cache 的注意力
def attention_with_kv_cache(q_new, k_new, v_new, k_cache, v_cache, d_k=64):
    # 拼接历史缓存
    k = torch.cat([k_cache, k_new], dim=-2)
    v = torch.cat([v_cache, v_new], dim=-2)
    scores = q_new @ k.transpose(-2, -1) / (d_k ** 0.5)
    attn = F.softmax(scores, dim=-1)
    return attn @ v, k, v

k_cache = torch.randn(1, 5, 64)
v_cache = torch.randn(1, 5, 64)
q_new = torch.randn(1, 1, 64)
k_new = torch.randn(1, 1, 64)
v_new = torch.randn(1, 1, 64)

out, new_k, new_v = attention_with_kv_cache(q_new, k_new, v_new, k_cache, v_cache)
print(f'KV Cache 输出: {out.shape}, 新缓存长度: {new_k.shape[-2]}')

# RoPE 简化演示：旋转位置编码
def rope(q, position, dim):
    # 简化：对 q 的前 dim/2 维施加旋转
    theta = position / (10000 ** (torch.arange(0, dim, 2) / dim))
    cos, sin = torch.cos(theta), torch.sin(theta)
    q_rot = q.clone()
    q_rot[..., 0::2] = q[..., 0::2] * cos - q[..., 1::2] * sin
    q_rot[..., 1::2] = q[..., 0::2] * sin + q[..., 1::2] * cos
    return q_rot

print('RoPE 旋转位置编码演示完成')
```

## SFT

监督微调（Supervised Fine-Tuning）用「指令-回答」对训练模型遵循指令的能力，是 LLM 从「补全」到「对话」的关键一步。

```text
核心概念：
- 目标：让预训练模型学会遵循指令、输出期望格式的回答
- 数据：指令-输入-输出三元组，质量 > 数量，几千到几万条即可见效
- 与预训练区别：预训练学语言规律（自监督、海量数据），SFT 学任务对齐（监督、精标数据）
- 训练：因果语言建模损失（预测下一个 token），全参或 LoRA 微调
- 常见问题：灾难性遗忘、数据偏差、过拟合
```

```text
高频面试题：
Q1：SFT 和预训练的区别？
答：预训练用海量无标注文本做自监督（预测下一个 token），学通用语言能力；
   SFT 用少量高质量指令-回答对做监督学习，把「语言能力」对齐到「遵循指令、
   完成任务」。SFT 数据量小但质量要求高，容易遗忘预训练知识。

Q2：如何构造高质量 SFT 数据？
答：多样性（覆盖多任务多领域）、高质量（准确、格式统一）、指令清晰。数据
   来源：人工标注、GPT-4 蒸馏生成、真实用户日志清洗。要避免重复、矛盾、错误
   样本，且覆盖目标场景的边界情况。

Q3：SFT 会灾难性遗忘吗？怎么缓解？
答：会，尤其数据分布与预训练差异大时。缓解：混合少量预训练数据（replay）、
   LoRA 等参数高效方法（冻结主权重）、控制学习率和训练步数、数据增强。
```

```python
# 简化的 SFT 训练示意（伪代码 + 数据格式）
def build_sft_sample(instruction, input_text, output):
    # 现代 LLM 的 chat 模板
    return {
        'messages': [
            {'role': 'system', 'content': '你是一个乐于助人的助手。'},
            {'role': 'user', 'content': instruction + ('\n' + input_text if input_text else '')},
            {'role': 'assistant', 'content': output},
        ]
    }

sample = build_sft_sample('翻译成英文', '今天天气很好', 'The weather is nice today.')
print(f'SFT 样本: {sample["messages"]}')

# 损失：对 assistant 部分计算交叉熵（忽略 user 部分）
import torch.nn.functional as F

def sft_loss(logits, labels, mask):
    # mask 标记哪些 token 参与损失（只算 assistant 回答部分）
    loss = F.cross_entropy(logits.view(-1, logits.size(-1)), labels.view(-1), reduction='none')
    return (loss * mask.view(-1)).sum() / mask.sum()

print('SFT 损失计算（只对回答部分）')
```

## LoRA

LoRA（Low-Rank Adaptation）用低秩矩阵近似权重更新，以极小参数量实现高效微调，是大模型微调的主流方法。

```text
核心概念：
- 思想：权重更新 ΔW 是低秩的，ΔW = B·A（r 维瓶颈）
- 冻结原权重 W，只训练 A、B 两个小矩阵，推理时 W' = W + BA
- 参数量：从 d×d 降到 2×d×r，r 通常 8~64，参数减少上千倍
- 优点：显存小、训练快、可插拔（不同任务存不同 LoRA）
- 应用：qkv 投影、FFN、embedding 等线性层
```

```text
高频面试题：
Q1：LoRA 为什么有效？
答：预训练模型权重已在一个低维子空间，下游任务适配只需低秩的权重扰动。LoRA
   用低秩分解 ΔW=BA 捕获这个扰动，既保留预训练知识又高效适配。且 A 随机初始化、
   B 零初始化，训练初期 ΔW=0，不破坏原始模型。

Q2：LoRA 相比全参微调的优势？
答：显存需求大幅降低（无需存优化器状态和梯度）、训练快、可训练多个 LoRA 模块
   切换任务、避免灾难性遗忘（冻结主权重）。代价是容量上限略低于全参微调。

Q3：LoRA 的 rank 和 alpha 怎么理解？
答：rank r 是低秩维度，r 越大表达能力越强但参数越多；alpha 是缩放因子，
   实际缩放 = alpha/r，控制 LoRA 更新的幅度。经验上 r 取 8~16、alpha 取 r 的
   1~2 倍。
```

```python
import torch
import torch.nn as nn

# 手写 LoRA 线性层
class LoRALinear(nn.Module):
    def __init__(self, in_features, out_features, r=8, alpha=16):
        super().__init__()
        self.linear = nn.Linear(in_features, out_features, bias=False)
        self.linear.weight.requires_grad = False   # 冻结原权重
        self.lora_A = nn.Parameter(torch.randn(r, in_features) * 0.01)
        self.lora_B = nn.Parameter(torch.zeros(out_features, r))
        self.scaling = alpha / r

    def forward(self, x):
        base = self.linear(x)
        lora = (x @ self.lora_A.T @ self.lora_B.T) * self.scaling
        return base + lora

layer = LoRALinear(64, 128, r=8, alpha=16)
x = torch.randn(4, 64)
y = layer(x)
print(f'LoRA 层输出: {y.shape}')
print(f'可训练参数: {sum(p.numel() for p in layer.parameters() if p.requires_grad)}')
print(f'原权重参数量: {layer.linear.weight.numel()}')
```

## DPO

DPO（Direct Preference Optimization）直接用偏好对（好回答 vs 坏回答）优化模型，替代 RLHF 的复杂流程，是当前对齐的主流方法。

```text
核心概念：
- 目标：让模型更倾向于生成「被偏好」的回答
- 数据：三元组 (prompt, 好回答 chosen, 坏回答 rejected)
- 损失：最大化 chosen 与 rejected 的隐式奖励差距（对比学习式损失）
- 与 RLHF 区别：RLHF 需训练奖励模型 + PPO 强化学习；DPO 直接用偏好对做
   监督式优化，无需奖励模型和 RL，稳定且高效
- 参数 β：控制偏离参考模型（原 SFT 模型）的程度
```

```text
高频面试题：
Q1：DPO 相比 RLHF 的优势？
答：RLHF 流程复杂（训练奖励模型 → PPO 采样优化），不稳定、易崩溃；DPO 把
   RLHF 的目标重参数化成直接的分类式损失，只需偏好数据，无需奖励模型和强化
   学习，训练稳定、实现简单、效果相当。

Q2：DPO 损失函数的直观理解？
答：最大化「chosen 相对 rejected 的奖励优势」，同时用参考模型（SFT 模型）做
   正则，防止模型过度偏离导致生成质量退化。β 越大越贴近参考模型，β 越小
   越激进地拟合偏好。

Q3：DPO 的偏好数据怎么来？
答：对同一 prompt 生成多个回答，人工标注或 GPT-4 打分选出好坏对。质量比数量
   重要，需覆盖「有帮助、无害、诚实」等多个维度，且 chosen/rejected 要有
   明显差距。
```

```python
import torch
import torch.nn.functional as F

# 手写 DPO 损失
def dpo_loss(pi_logps_chosen, pi_logps_rejected,
             ref_logps_chosen, ref_logps_rejected, beta=0.1):
    # pi: 当前模型 log 概率, ref: 参考模型 log 概率
    pi_ratio = pi_logps_chosen - pi_logps_rejected
    ref_ratio = ref_logps_chosen - ref_logps_rejected
    # 隐式奖励差距
    logits = beta * (pi_ratio - ref_ratio)
    loss = -F.logsigmoid(logits).mean()
    return loss

pi_chosen = torch.randn(8)
pi_rejected = torch.randn(8)
ref_chosen = torch.randn(8)
ref_rejected = torch.randn(8)
print(f'DPO loss: {dpo_loss(pi_chosen, pi_rejected, ref_chosen, ref_rejected).item():.4f}')
```

## RAG

RAG（检索增强生成）让 LLM 基于外部知识库回答，解决幻觉、知识时效性和私有知识问题。

```text
核心概念：
- 流程：索引（文档切块 → embedding → 向量库）+ 检索（召回 → 重排）+ 生成（拼接 prompt → LLM 回答）
- 切块（chunk）：文档按语义/固定长度切片，chunk 大小影响召回精度
- Embedding：文本向量化，语义相似度检索
- 检索：向量检索（ANN）+ 关键词检索（BM25）混合
- 生成：把检索到的上下文拼进 prompt，让模型「基于资料」回答
```

```text
高频面试题：
Q1：RAG 解决什么问题？什么时候用？
答：解决 LLM 幻觉、知识过时、私有/领域知识缺失。适合需要准确引用外部知识、
   知识频繁更新、或企业私有数据的场景。若知识已内化在模型且无需溯源，可不
   用 RAG。

Q2：chunk 大小怎么选？
答：太小则语义不完整、召回碎片化；太大则噪声多、检索不精准、超 context 限制。
   通常 256~512 token，按文档结构和语义边界（段落、标题）切分，配合 overlap
   保留上下文。

Q3：如何提升 RAG 检索质量？
答：混合检索（向量 + BM25）、重排（rerank 模型精排）、query 改写/扩展、多路
   召回、元数据过滤、chunk 优化。端到端评估用召回率和答案准确率。
```

```python
import numpy as np

# 简化的 RAG 检索流程
def cosine_sim(a, b):
    return a @ b / (np.linalg.norm(a) * np.linalg.norm(b) + 1e-9)

def rag_retrieve(query_emb, doc_embs, doc_texts, top_k=3):
    scores = [(cosine_sim(query_emb, d), t) for d, t in zip(doc_embs, doc_texts)]
    scores.sort(key=lambda x: -x[0])
    return scores[:top_k]

# 模拟 embedding（随机向量示意）
np.random.seed(0)
query_emb = np.random.randn(32)
doc_embs = [np.random.randn(32) for _ in range(5)]
doc_texts = ['文档A', '文档B', '文档C', '文档D', '文档E']

results = rag_retrieve(query_emb, doc_embs, doc_texts, top_k=3)
print(f'RAG 检索 Top3: {results}')
```

## Agent

Agent（智能体）让 LLM 不只是回答，而是能规划、调用工具、多步执行完成复杂任务。

```text
核心概念：
- 能力：感知（理解任务）→ 规划（拆解步骤）→ 行动（调用工具）→ 观察（反馈迭代）
- ReAct：Reasoning + Acting，交替「思考」和「行动」，是主流范式
- 工具调用：Function Calling，模型输出结构化工具调用指令
- 规划：任务分解、反思（self-reflection）、多智能体协作
- 挑战：幻觉、工具调用不稳定、长期任务的状态管理
```

```text
高频面试题：
Q1：ReAct 的核心思想？
答：让模型交替进行「推理（Thought）」和「行动（Action）」，行动后观察结果
   （Observation）再继续推理，直到得到最终答案。相比纯推理（CoT）能调用外部
   工具获取真实信息，相比纯行动能进行多步推理规划。

Q2：Function Calling 的原理？
答：把工具以 JSON Schema 形式描述给模型，模型在需要时输出结构化的函数调用
   （函数名 + 参数），系统执行函数并把结果返回给模型继续生成。本质是让模型
   的输出空间包含「调用工具」这个动作。

Q3：Agent 常见的问题？
答：幻觉（编造工具结果）、工具调用不稳定（参数错误）、陷入循环（反复调用）、
   长期任务状态丢失、成本与延迟高。缓解：工具描述清晰、结果校验、设置最大
   步数、状态持久化。
```

```python
# 简化的 ReAct Agent 循环
def react_agent(query, tools, llm_call, max_steps=5):
    # tools: {name: func}, llm_call: 模拟模型推理
    context = [{'role': 'user', 'content': query}]
    for step in range(max_steps):
        action = llm_call(context)          # 模型输出 thought + action
        if action['type'] == 'finish':
            return action['answer']
        if action['type'] == 'tool':
            result = tools[action['name']](**action['args'])
            context.append({'role': 'tool', 'content': str(result)})
    return '达到最大步数'

def llm_call(context):
    # 模拟：第一步调用计算器，第二步给出答案
    if len(context) == 1:
        return {'type': 'tool', 'name': 'calculator', 'args': {'expr': '2+3'}}
    return {'type': 'finish', 'answer': '结果是 5'}

tools = {'calculator': lambda expr: eval(expr)}
print(f'Agent 回答: {react_agent("2+3 等于多少", tools, llm_call)}')
```

## MCP

MCP（Model Context Protocol）是标准化的「模型-工具」连接协议，让 LLM 以统一方式访问外部工具和数据源。

```text
核心概念：
- 定位：AI 应用的「USB-C 接口」，统一模型与外部工具/数据源的连接
- 架构：Host（应用）+ Client（连接）+ Server（提供工具/资源）
- 能力：Tools（可调用函数）、Resources（数据源）、Prompts（模板）
- 传输：stdio、HTTP/SSE
- 价值：一次开发，所有支持 MCP 的模型/应用都能复用工具
```

```text
高频面试题：
Q1：MCP 解决什么问题？
答：此前每个模型/应用都要为每个工具写专门的集成（M×N 问题）。MCP 定义统一
   协议，工具只需实现一次 MCP Server，任何支持 MCP 的 Host 都能调用，从
   M×N 降到 M+N，生态可复用。

Q2：MCP 和 Function Calling 的关系？
答：Function Calling 是「模型输出工具调用」的能力，MCP 是「工具如何标准化
   暴露和连接」的协议。两者互补：MCP 提供标准化的工具供给，Function Calling
   是模型消费工具的机制。

Q3：MCP Server 提供哪些能力？
答：Tools（可执行的函数，如查数据库、调 API）、Resources（可读的数据，如
   文件、知识库）、Prompts（预定义提示模板）。客户端可以发现并调用这些能力。
```

```python
# 简化的 MCP Server 结构示意
class MCPServer:
    def __init__(self, name):
        self.name = name
        self.tools = {}

    def register_tool(self, name, description, func, schema):
        self.tools[name] = {
            'description': description,
            'func': func,
            'schema': schema,       # JSON Schema 参数定义
        }

    def list_tools(self):
        return [{'name': k, 'description': v['description']} for k, v in self.tools.items()]

    def call_tool(self, name, args):
        return self.tools[name]['func'](**args)

server = MCPServer('weather')
server.register_tool(
    'get_weather', '查询城市天气',
    lambda city: f'{city}今天晴天',
    {'type': 'object', 'properties': {'city': {'type': 'string'}}},
)
print(f'MCP 工具列表: {server.list_tools()}')
print(f'调用结果: {server.call_tool("get_weather", {"city": "北京"})}')
```

## 应用场景实战

### 场景一：手写 RAG 完整流程

面试手撕：从切块、embedding 到检索生成的完整 RAG 链路。

```python
import numpy as np
from collections import Counter

def split_chunks(text, chunk_size=100, overlap=20):
    chunks = []
    start = 0
    while start < len(text):
        chunks.append(text[start:start + chunk_size])
        start += chunk_size - overlap
    return chunks

def simple_embedding(text, dim=64):
    # 简化：基于字符哈希的 bag-of-words 向量
    vec = np.zeros(dim)
    for ch in text:
        vec[hash(ch) % dim] += 1
    norm = np.linalg.norm(vec)
    return vec / (norm + 1e-9) if norm > 0 else vec

def rag_answer(query, documents, top_k=2):
    chunks = []
    for doc in documents:
        chunks.extend(split_chunks(doc))
    q_emb = simple_embedding(query)
    scores = []
    for c in chunks:
        scores.append((q_emb @ simple_embedding(c), c))
    scores.sort(key=lambda x: -x[0])
    context = ' '.join([c for _, c in scores[:top_k]])
    return f'基于检索上下文回答：{context[:50]}...'

docs = ['Transformer 是一种基于注意力机制的深度学习模型，广泛用于自然语言处理。'] * 1
print(rag_answer('什么是 Transformer？', docs))
```

### 场景二：手写 LoRA 微调步骤

面试手撕：展示 LoRA 微调的完整流程。

```python
import torch
import torch.nn as nn

def lora_finetune_demo():
    # 1. 加载预训练模型并冻结
    base_model = nn.Sequential(nn.Linear(64, 128), nn.ReLU(), nn.Linear(128, 64))
    for p in base_model.parameters():
        p.requires_grad = False

    # 2. 给目标层加 LoRA
    class LoRA(nn.Module):
        def __init__(self, base_layer, r=4, alpha=8):
            super().__init__()
            self.base = base_layer
            self.A = nn.Parameter(torch.randn(r, base_layer.in_features) * 0.01)
            self.B = nn.Parameter(torch.zeros(base_layer.out_features, r))
            self.scale = alpha / r
        def forward(self, x):
            return self.base(x) + (x @ self.A.T @ self.B.T) * self.scale

    base_model[0] = LoRA(base_model[0])

    # 3. 只优化 LoRA 参数
    trainable = [p for p in base_model.parameters() if p.requires_grad]
    opt = torch.optim.Adam(trainable, lr=1e-3)

    # 4. 训练
    x = torch.randn(16, 64)
    for _ in range(10):
        opt.zero_grad()
        loss = base_model(x).norm()
        loss.backward()
        opt.step()
    print(f'可训练参数: {sum(p.numel() for p in trainable)}, 最终 loss: {loss.item():.4f}')

lora_finetune_demo()
```

## 最佳实践与踩坑记录

### 最佳实践

1. 面试答 LLM 训练链路，按「预训练 → SFT → 对齐（RLHF/DPO）」清晰分层
2. 答 LoRA 时强调「冻结主权重 + 低秩更新 + 可插拔」，并记住 alpha/r 缩放
3. 答 DPO 时能对比 RLHF 流程，说清「无需奖励模型和 RL」是关键得分点
4. RAG 题按「索引 → 检索 → 生成」三段答，并提到 chunk 和混合检索
5. Agent 题答 ReAct 范式（Thought/Action/Observation 循环）最稳妥
6. MCP 题答「标准化协议、M×N 到 M+N、Tools/Resources/Prompts」三要素
7. 能说出 KV Cache、RoPE、Pre-Norm 等推理/架构细节是深度加分项

### 踩坑记录

```text
坑 1：RAG 检索结果直接拼接导致上下文超限
结论：生成的回答截断或成本飙升。
原因：chunk 太大或 top_k 太多，超出模型 context 限制。
解法：控制 chunk 大小和 top_k，必要时做摘要压缩或截断。

坑 2：SFT 数据质量差导致模型变笨
结论：微调后通用能力下降、答非所问。
原因：低质量/重复/矛盾的 SFT 数据污染了模型，或数据分布太窄。
解法：严格筛选数据、混合预训练数据、控制训练步数、小学习率。

坑 3：LoRA 的 alpha/r 设错导致训练无效或过拟合
结论：微调无效果或效果过度。
原因：缩放因子不合理，r 太大参数过多失去 LoRA 意义。
解法：r 取 8~16，alpha 取 r 的 1~2 倍，用验证集调。

坑 4：DPO 用偏好差距不明显的数据对
结论：模型学不到有效偏好信号，对齐效果差。
原因：chosen 和 rejected 质量接近，损失梯度信号弱。
解法：构造差距明显、标注一致的偏好对，覆盖多维度的好坏对比。

坑 5：Agent 不设最大步数导致死循环
结论：模型反复调用同一工具，成本失控。
原因：模型陷入循环或工具返回结果无法推进任务。
解法：设 max_steps 上限，检测重复调用，结果校验和异常处理。
```

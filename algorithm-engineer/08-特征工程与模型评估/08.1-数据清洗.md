## 概述

数据清洗是特征工程的第一步，也是决定模型上限的关键环节：真实数据总是不干净——有缺失、有异常、有重复、有格式错误。清洗的目标是把原始数据变成「可用、一致、可信」的数据，同时不能在这一步引入数据泄露（leakage）。清洗做不好，再好的模型也救不回来；清洗做过头，又可能丢掉有效信息。核心原则是「理解数据，再动手」。

```text
数据清洗的核心环节：
1. 缺失值 —— 识别缺失、分析缺失原因、选择填充或删除策略
2. 异常值 —— 识别离群点，判断是噪声还是真实信号
3. 重复值 —— 去重，避免样本权重失衡和数据泄露
4. 数据校验 —— 类型、范围、格式、一致性的自动检查
5. 泄露检测 —— 确保清洗和特征工程不「偷看」未来或测试集信息
```

```python
import pandas as pd
import numpy as np

# 构造一份「脏数据」作为清洗对象
df = pd.DataFrame({
    'user_id': [1, 2, 2, 3, 4],
    'age': [25, np.nan, 30, -5, 120],
    'income': [5000, 8000, 8000, None, 12000],
    'city': ['北京', '上海', '上海', '北京 ', '北京'],
})
print(df)
print('缺失值统计:\n', df.isna().sum())
```

## Missing Value

缺失值是数据里最常见的脏问题：某列的部分值为空（NaN/None）。处理前要先分析「为什么缺失」——完全随机缺失（MCAR）、随机缺失（MAR）、非随机缺失（MNAR），不同原因对应不同策略。处理方法分删除和填充两大类，填充又分简单填充和模型填充。

```text
缺失值的三种机制：
1. MCAR —— 缺失与任何变量无关，完全随机（如传感器随机故障）
2. MAR —— 缺失与其他观测变量有关（如高收入人群更不愿填收入）
3. MNAR —— 缺失与缺失值本身有关（如低分考生不填成绩）

处理策略：
1. 删除 —— 删缺失行（样本充足、缺失少时）或删缺失列（缺失率高时）
2. 简单填充 —— 均值/中位数/众数/常数/前后向填充
3. 模型填充 —— KNN、回归、迭代填充（IterativeImputer）
4. 指示变量 —— 加一列「是否缺失」，保留缺失本身的信息
```

```python
import pandas as pd
import numpy as np
from sklearn.impute import SimpleImputer, KNNImputer

df = pd.DataFrame({
    'age': [25, np.nan, 30, 35, np.nan, 40],
    'income': [5000, 8000, np.nan, 12000, 10000, np.nan],
    'city': ['北京', '上海', np.nan, '广州', '深圳', '北京'],
})

# 简单填充：数值用中位数（抗异常值），类别用众数
imp_num = SimpleImputer(strategy='median')
imp_cat = SimpleImputer(strategy='most_frequent')
df['age'] = imp_num.fit_transform(df[['age']])
df['income'] = imp_num.fit_transform(df[['income']])
df['city'] = imp_cat.fit_transform(df[['city']]).ravel()
print('简单填充后:\n', df)

# KNN 填充：用相似样本的值填充
df2 = pd.DataFrame({
    'a': [1, 2, np.nan, 4, 5],
    'b': [10, 20, 30, np.nan, 50],
    'c': [100, 200, 300, 400, np.nan],
})
knn_imp = KNNImputer(n_neighbors=2)
print('KNN 填充后:\n', knn_imp.fit_transform(df2))
```

```python
# 缺失指示变量：保留「缺失」这个信号
df3 = pd.DataFrame({'age': [25, np.nan, 30, np.nan]})
df3['age_missing'] = df3['age'].isna().astype(int)
df3['age'] = df3['age'].fillna(df3['age'].median())
print('带缺失指示变量的结果:\n', df3)
```

## Outlier

异常值是与大多数数据显著偏离的样本，可能是真实极端事件，也可能是录入错误或测量噪声。清洗的关键是「判断」而非「一刀切删除」：如果是错误就修正或删除，如果是真实信号（如欺诈、故障）则要保留并单独处理。

```text
异常值处理的流程：
1. 检测 —— Z-Score/IQR（单变量）、马氏距离/Isolation Forest/LOF（多变量）
2. 判断 —— 是数据错误还是真实极端值？结合业务领域知识
3. 处理 —— 删除 / 截断（winsorize）/ 盖帽（clipping）/ 变换（log）/ 保留

常用方法：
1. IQR 法 —— 超出 [Q1-1.5·IQR, Q3+1.5·IQR] 判为异常
2. 盖帽（clipping）—— 把超出分位数的值截断到边界，不丢样本
3. 变换 —— log/Box-Cox 压缩长尾，让极端值不那么极端
```

```python
import pandas as pd
import numpy as np

df = pd.DataFrame({'price': [100, 105, 98, 102, 1000000, 99, 101]})  # 混入一个错误价格

# IQR 检测
q1, q3 = df['price'].quantile([0.25, 0.75])
iqr = q3 - q1
lower, upper = q1 - 1.5 * iqr, q3 + 1.5 * iqr
outlier_mask = (df['price'] < lower) | (df['price'] > upper)
print('IQR 检测到的异常值:', df.loc[outlier_mask, 'price'].tolist())

# 盖帽处理：用 1% 和 99% 分位数截断，不丢样本
p01, p99 = df['price'].quantile([0.01, 0.99])
df['price_clipped'] = df['price'].clip(p01, p99)
print('盖帽后:', df['price_clipped'].tolist())

# winsorize：同样截断到分位数
from scipy.stats.mstats import winsorize
df['price_winsor'] = winsorize(df['price'], limits=[0.01, 0.01])
print('winsorize 后:', df['price_winsor'].tolist())
```

## Duplicate

重复值分两类：完全重复行（所有字段都一样）和「逻辑重复」（同一实体但字段略有差异，如同一用户两行记录）。完全重复直接去重即可；逻辑重复需要按业务主键（如 user_id）去重，并决定保留哪一条（最新/最完整/聚合）。

```text
重复值的处理：
1. 完全重复 —— df.drop_duplicates() 直接删除
2. 逻辑重复 —— 按业务主键去重，保留规则需明确：
   - keep='first'/'last' —— 保留第一条/最后一条
   - 按时间戳保留最新 —— sort 后再去重
   - 字段合并 —— 同一实体的多条记录取并集/最新值

为什么要去重：
1. 重复样本导致模型过拟合（训练/测试都可能出现同一条）
2. 重复记录让某些样本权重被放大
3. 重复可能是数据采集 bug 的信号，值得排查
```

```python
import pandas as pd

df = pd.DataFrame({
    'user_id': [1, 1, 2, 3, 3],
    'name': ['张三', '张三', '李四', '王五', '王五'],
    'ts': ['2026-01-01', '2026-01-05', '2026-01-02', '2026-01-03', '2026-01-01'],
})

# 完全重复行去重
print('去完全重复行:\n', df.drop_duplicates())

# 逻辑重复：同一 user_id 保留最新记录（按 ts 排序）
df_sorted = df.sort_values('ts')
df_dedup = df_sorted.drop_duplicates(subset='user_id', keep='last')
print('按 user_id 保留最新:\n', df_dedup)
```

```python
# 检查重复率，判断数据质量
dup_rate = df.duplicated().mean()
dup_key_rate = df.duplicated(subset='user_id').mean()
print(f'完全重复率: {dup_rate:.2%}，逻辑重复率(按 user_id): {dup_key_rate:.2%}')
```

## Data Validation

数据校验是在数据进入特征工程前，自动检查数据是否符合预期约束：类型对不对、范围合不合理、格式是否一致、必填字段是否为空、类别值是否在允许集合内。它像数据的「单元测试」，在数据漂移或采集 bug 发生时第一时间报警。

```text
数据校验的检查项：
1. 类型校验 —— age 是数值、日期是 datetime、id 是字符串
2. 范围校验 —— 年龄在 0~120，价格非负，比例在 0~1
3. 格式校验 —— 手机号/邮箱/日期格式、类别值在允许集合内
4. 完整性校验 —— 必填字段无缺失、主键唯一
5. 一致性校验 —— 交叉字段逻辑（如结束时间 > 开始时间）

工具：
1. Great Expectations —— 声明式数据断言，工业级校验框架
2. Pandera —— 基于 Pandas 的 schema 校验，类型 + 范围 + 正则
3. 自定义断言 —— 简单场景手写检查函数
```

```python
import pandas as pd
import numpy as np

df = pd.DataFrame({
    'age': [25, 130, -3, 40],
    'email': ['a@b.com', 'not-an-email', 'c@d.com', 'e@f.com'],
    'score': [0.5, 1.5, -0.2, 0.8],
})

# 手写校验函数，逐项检查并收集违规记录
def validate(df):
    errors = []
    if (df['age'] < 0).any() or (df['age'] > 120).any():
        errors.append(f"年龄越界: {df.loc[(df['age']<0)|(df['age']>120), 'age'].tolist()}")
    invalid_email = ~df['email'].str.match(r'^[^@]+@[^@]+\.[^@]+$')
    if invalid_email.any():
        errors.append(f"邮箱格式错误行: {df.index[invalid_email].tolist()}")
    if (df['score'] < 0).any() or (df['score'] > 1).any():
        errors.append(f"score 越界: {df.loc[(df['score']<0)|(df['score']>1), 'score'].tolist()}")
    return errors

print('校验结果:')
for e in validate(df):
    print(' -', e)
```

```python
# 用 Pandera 做声明式校验
import pandera as pa

schema = pa.DataFrameSchema({
    'age': pa.Column(int, pa.Check.in_range(0, 120)),
    'score': pa.Column(float, pa.Check.in_range(0, 1)),
})
try:
    schema.validate(df)
    print('校验通过')
except pa.errors.SchemaError as e:
    print('校验失败:', str(e).splitlines()[0])
```

## Leakage Detection

数据泄露（leakage）指模型在训练时「偷看」了它本不该看到的信息，导致训练/验证指标虚高、上线后效果崩塌。泄露的两大类：一是目标泄露（特征里混入了目标或目标派生信息），二是训练/测试污染（用全量数据做清洗/标准化/特征选择）。检测和预防是数据清洗阶段最容易被忽视却最关键的一环。

```text
数据泄露的常见形式：
1. 目标泄露 —— 特征包含目标本身或强相关派生量（如用「是否续费」预测「是否流失」）
2. 时间泄露 —— 用未来信息预测过去（时序数据用未来窗口做特征）
3. 预处理泄露 —— 在全量数据上 fit 标准化/填充/编码，再划分训练测试
4. 重复泄露 —— 训练集和测试集有重复样本或同源样本

检测与预防：
1. 检查特征与目标的相关性，异常高的特征警惕泄露
2. 特征重要性 top 特征逐个审视，是否「不该知道」
3. 清洗/填充/标准化必须在训练集上 fit，再应用到测试集
4. 时序数据严格按时间切分，禁用未来信息
5. 划分前先去重，避免同一实体跨训练/测试
```

```python
import pandas as pd
import numpy as np
from sklearn.model_selection import train_test_split

# 反面教材：在全量数据上做标准化（泄露）
df = pd.DataFrame({
    'x': np.random.randn(1000),
    'y': np.random.randn(1000) > 0,
})

# 错误做法：先标准化再划分，测试集信息「污染」了标准化参数
from sklearn.preprocessing import StandardScaler
scaler_wrong = StandardScaler().fit(df[['x']])      # 用了全量数据 fit
df['x_scaled_wrong'] = scaler_wrong.transform(df[['x']])

# 正确做法：先划分，再只在训练集上 fit
X_train, X_test, y_train, y_test = train_test_split(df[['x']], df['y'], test_size=0.2, random_state=0)
scaler = StandardScaler().fit(X_train)              # 只用训练集 fit
X_train_scaled = scaler.transform(X_train)
X_test_scaled = scaler.transform(X_test)            # 用训练集的参数 transform 测试集
print('正确流程：标准化只在训练集上 fit')
```

```python
# 检测疑似泄露的特征：与目标相关性异常高
df = pd.DataFrame({
    'feat_normal': np.random.randn(1000),
    'feat_leaky': None,
    'target': None,
})
df['target'] = (np.random.rand(1000) > 0.5).astype(int)
df['feat_leaky'] = df['target'] + np.random.randn(1000) * 0.01   # 几乎就是目标

corr = df[['feat_normal', 'feat_leaky']].corrwith(df['target'])
print('特征与目标相关性:\n', corr.round(3))
print('feat_leaky 相关过高，高度疑似目标泄露')
```

## 应用场景实战

### 场景一：电商订单数据清洗流水线

```python
import pandas as pd
import numpy as np

df = pd.DataFrame({
    'order_id': [1, 2, 2, 3, 4, 5],
    'user_id': [101, 102, 102, 103, 104, 105],
    'amount': [100, 200, 200, -50, 5000, 300],
    'created_at': ['2026-08-01', '2026-08-02', '2026-08-02',
                   '2026-08-03', '2026-08-04', '2026-08-05'],
})

# 1. 去重复（order_id 完全重复）
df = df.drop_duplicates(subset='order_id')

# 2. 修正异常：金额为负是退款，金额异常大先盖帽
df['amount'] = df['amount'].clip(lower=0)
q99 = df['amount'].quantile(0.99)
df['amount'] = df['amount'].clip(upper=q99)

# 3. 类型转换 + 校验
df['created_at'] = pd.to_datetime(df['created_at'])
assert df['order_id'].is_unique   # 去重后 order_id 应唯一（user_id 可以有重复）
print('清洗后:\n', df)
print('order_id 唯一:', df['order_id'].is_unique)
```

### 场景二：防止时序数据泄露的切分

```python
import pandas as pd
import numpy as np

# 按时间顺序的样本，必须按时间切分而非随机切分
n = 1000
df = pd.DataFrame({
    'date': pd.date_range('2026-01-01', periods=n, freq='D'),
    'sales': np.cumsum(np.random.randn(n)) + 100,
    'promo': (np.random.rand(n) > 0.7).astype(int),
})

# 前 80% 时间做训练，后 20% 做测试（禁止随机 shuffle）
split_idx = int(n * 0.8)
train = df.iloc[:split_idx]
test = df.iloc[split_idx:]

# 所有统计（均值、填充值、标准化参数）都只能从 train 计算
train_mean = train['sales'].mean()
train['sales_centered'] = train['sales'] - train_mean
test['sales_centered'] = test['sales'] - train_mean   # 用训练集的均值
print(f'训练集 {len(train)} 行，测试集 {len(test)} 行，无时间泄露')
```

## 最佳实践与踩坑记录

### 最佳实践

1. 清洗前先做 EDA（describe、缺失率、分布、异常值），理解数据再动手
2. 缺失值先分析缺失机制（MCAR/MAR/MNAR），再选策略，别默认全填均值
3. 缺失率高（如 >50%）的列直接删除，或转成「是否缺失」指示变量
4. 异常值先判断是错误还是信号，错误修正/删除，信号保留并建模
5. 去重要先识别业务主键，逻辑重复的保留规则必须明确
6. 所有清洗/填充/标准化/编码都必须「先划分，只在训练集上 fit」
7. 时序数据严格按时间切分，禁止用未来信息
8. 清洗逻辑写成可复用的 pipeline/函数，测试集只 apply 不 fit

### 踩坑记录

```text
坑 1：在全量数据上填充缺失值
结论：用含测试集的均值/中位数填充，测试集信息泄露，验证指标虚高。
原因：fillna(df.mean()) 在全量数据上算统计量，测试集的信息进入了训练。
解法：先划分，用训练集的均值/中位数填充，测试集复用训练集的填充值。

坑 2：异常值一刀切删除
结论：把欺诈交易、设备故障等「真实异常信号」删掉，模型再也学不到。
原因：没有区分「数据错误」和「真实极端事件」就删除。
解法：结合业务判断异常值性质；错误修正，真实信号保留或用鲁棒方法处理。

坑 3：随机划分时序数据
结论：训练集包含未来数据，模型「穿越」，上线预测未来时效果崩塌。
原因：train_test_split 默认随机 shuffle，破坏了时间顺序。
解法：时序数据按时间顺序切分，训练在前、测试在后，严禁 shuffle。

坑 4：逻辑重复没按主键去重
结论：同一用户在训练集和测试集各出现一次，模型靠「背用户」得分，泛化差。
原因：只去完全重复行，没识别跨行的同源/同实体重复。
解法：按业务主键（user_id、设备 id）去重，并保证同一实体不跨训练/测试。

坑 5：缺失值全填均值，丢失缺失本身的信号
结论：缺失本身可能蕴含信息（如「收入缺失」与「高风险」相关），填均值抹掉了。
原因：把缺失当成纯噪声，忽略了缺失的非随机性。
解法：加一列缺失指示变量，保留「是否缺失」这个特征。
```

## 概述

类别特征（categorical feature）是取值为有限个离散类别的特征，如城市、性别、品类、用户 ID。绝大多数模型只能吃数值，因此必须把类别「编码」成数值才能喂进模型。编码方式的选择直接决定了类别信息能被模型利用多少，是特征工程里最容易做错也最容易做出效果的一环。

```text
类别特征编码的核心思路：
1. 低基数（类别少）→ One-Hot / Ordinal，简单可解释
2. 高基数（类别多）→ Frequency / Count / Target / Hashing，压缩维度
3. 有顺序 → Ordinal；无顺序 → One-Hot 或统计编码
4. 树模型 → 统计编码（Target / CatBoost）常能带来显著增益
```

```python
import pandas as pd
import numpy as np

# 构造一个带类别特征的数据集
df = pd.DataFrame({
    'city':  ['北京', '上海', '广州', '北京', '上海', '深圳'],
    'gender': ['M', 'F', 'M', 'F', 'M', 'F'],
    'y':      [1, 0, 1, 0, 1, 1],   # 目标列（用于有监督编码）
})
print(df.dtypes)   # 类别列是 object 类型
```

## One-Hot

One-Hot（独热编码）为每个类别创建一个新的二值列，该类别出现时为 1，否则为 0。它不引入任何虚假的顺序关系，是最安全、最常用的编码方式，缺点是类别很多时维度爆炸且稀疏。

```text
核心思想：
1. k 个类别 → k 列 0/1 向量
2. 无顺序假设 —— 每个类别等距、独立
3. 缺点 —— 高基数时维度爆炸，且稀疏矩阵存储成本高
```

```python
from sklearn.preprocessing import OneHotEncoder

enc = OneHotEncoder(sparse_output=False, handle_unknown='ignore')
X = enc.fit_transform(df[['city']])
print(enc.categories_)   # 类别列表
print(X)
# 输出 6 行 4 列，每一行只有一列为 1
```

```python
# 等价用法：pandas 的 get_dummies（更直观，但无法持久化类别映射）
dummies = pd.get_dummies(df['city'], prefix='city')
print(dummies.head())
# 注意：get_dummies 不能处理「训练集未见过的类别」，OneHotEncoder 可以
```

```text
One-Hot 的注意事项：
1. 训练/测试类别集合不一致 → 用 handle_unknown='ignore'，测试集新类别全 0
2. 线性模型 + One-Hot → 需注意多重共线性（可 drop 一列避免）
3. 树模型用 One-Hot → 切分效率低，通常不如标签/统计编码
```

## Ordinal

Ordinal（顺序编码 / 标签编码）把每个类别映射成一个整数（0, 1, 2, ...）。它引入了一个「虚假」的大小顺序——类别 2 看起来比类别 0 大，这对没有天然顺序的类别是有害的，但对有天然顺序的类别（学历、等级、冷热）非常合适。

```text
核心思想：
1. 类别 → 整数标签（按出现顺序或指定顺序）
2. 有顺序的类别 → 正确；无顺序的类别 → 引入虚假顺序
3. 优点 —— 单列、无维度爆炸，树模型可直接用
```

```python
from sklearn.preprocessing import OrdinalEncoder

enc = OrdinalEncoder(categories=[['初中', '高中', '本科', '硕士', '博士']])
edu = pd.DataFrame({'edu': ['本科', '博士', '高中', '硕士']})
X = enc.fit_transform(edu)
print(X)   # [[2.] [4.] [1.] [3.]] —— 按指定顺序编码
```

```text
Ordinal 的坑：
1. 无顺序类别（如城市）用 Ordinal → 线性模型会误解「广州 > 北京」
2. 树模型对无序类别用 Ordinal 影响较小，但排序不当仍会损失信息
3. 类别顺序错误时，宁可退回 One-Hot 或统计编码
```

## Frequency

Frequency Encoding（频率编码）用每个类别在训练集中的出现频率（或占比）替换类别本身。它把高基数类别压缩成单列数值，且保留了「类别稀有度」信息——稀有类别通常是异常或需要特别处理的。

```text
核心思想：
1. 类别 → 该类别出现次数 / 总样本数（或直接用出现次数）
2. 优点 —— 单列、无维度爆炸，天然处理高基数
3. 信息 —— 类别频率本身往往与目标相关（长尾分布）
```

```python
# 频率编码：类别 → 出现频率
freq_map = df['city'].value_counts(normalize=True)
df['city_freq'] = df['city'].map(freq_map)
print(freq_map)
print(df[['city', 'city_freq']])
```

```text
Frequency 的坑：
1. 频率相同的不同类别会被合并成同一个值，损失区分度
2. 对训练集拟合、对测试集映射，测试集新类别需给默认值（如 0 或全局均值）
3. 常与 Target Encoding 配合，作为其正则化版本
```

## Count

Count Encoding（计数编码）用每个类别的出现次数替换类别，是 Frequency 的原始版本（不分母）。它在「类别出现次数本身有业务含义」的场景很有用，例如某商品被购买次数、某 IP 访问次数，出现次数越多往往越重要。

```text
核心思想：
1. 类别 → 该类别在训练集中的出现次数（整数）
2. 与 Frequency 的区别 —— 不除以总数，保留绝对数量
3. 适用 —— 计数本身有业务语义的场景（热度、活跃度）
```

```python
# 计数编码：类别 → 出现次数
count_map = df['city'].value_counts()
df['city_count'] = df['city'].map(count_map)
print(count_map)
print(df[['city', 'city_count']])
```

```text
Count/Frequency 的共同点：
1. 都属于「统计编码」，把类别替换成一个统计量
2. 训练/测试一致性 —— 统计量只能在训练集上算，测试集用映射
3. 可组合 —— 频率 + 计数 + 目标编码常一起作为特征
```

## Target Encoding

Target Encoding（目标编码 / 均值编码）用「每个类别的目标均值」替换类别，把目标信息直接编码进特征。它是有监督编码里最强的一种，能显著提升树模型和线性模型的效果，但极易过拟合和发生数据泄漏，必须配合交叉验证或平滑。

```text
核心思想：
1. 类别 → 该类别样本目标 y 的均值（回归）/ 正类占比（分类）
2. 优点 —— 直接编码了「类别与目标的关系」，信息量最大
3. 风险 —— 极易过拟合（稀有类别均值不可靠）+ 数据泄漏
```

```python
# 目标编码：类别 → 目标均值（需在训练集内做，避免泄漏）
train = df.copy()
target_map = train.groupby('city')['y'].mean()
train['city_target'] = train['city'].map(target_map)
print(target_map)
print(train[['city', 'y', 'city_target']])
```

```python
# 平滑版本（贝叶斯目标编码）：稀有类别拉向全局均值
def smoothed_target_encoding(series, y, m=10.0):
    global_mean = y.mean()
    agg = pd.DataFrame({'sum': y.groupby(series).sum(),
                        'cnt': y.groupby(series).count()})
    # (sum + m*global_mean) / (cnt + m)
    return series.map((agg['sum'] + m * global_mean) / (agg['cnt'] + m))

df['city_te'] = smoothed_target_encoding(df['city'], df['y'], m=10.0)
print(df[['city', 'y', 'city_te']])
```

```text
Target Encoding 的坑：
1. 数据泄漏 —— 用全量数据算目标均值会泄漏标签，必须交叉验证
2. 稀有类别 —— 样本少的类别均值不可靠，需平滑（拉向全局均值）
3. 训练/测试分布漂移 → 目标均值失效
```

## CatBoost Encoding

CatBoost Encoding（CatBoost 有序目标编码）是 CatBoost 库提出的目标编码变体：用「排列 + 历史累计」的方式，让每个样本的编码只用它之前的样本计算，从根本上避免「用自身标签编码自身」的泄漏。它同时内置平滑和随机排列，是工业界最稳健的目标编码实现。

```text
核心思想：
1. 排列 —— 随机打乱样本顺序
2. 只用「前面的样本」统计类别目标均值，当前样本不参与自身统计
3. 平滑 —— (sum_before + prior·a) / (count_before + a)
4. 与普通目标编码的区别 —— 消除自泄漏，无需手动交叉验证
```

```python
from category_encoders import CatBoostEncoder

# CatBoost 编码（category_encoders 库实现）
X = df[['city', 'gender']]
y = df['y']

enc = CatBoostEncoder()
X_encoded = enc.fit_transform(X, y)
print(X_encoded)
```

```python
# 交叉验证下使用 CatBoostEncoder 避免过拟合
from sklearn.model_selection import KFold
import numpy as np

kf = KFold(n_splits=5, shuffle=True, random_state=42)
X_cb = np.zeros((len(X), X.shape[1]))
for tr_idx, va_idx in kf.split(X):
    enc = CatBoostEncoder()
    enc.fit(X.iloc[tr_idx], y.iloc[tr_idx])
    X_cb[va_idx] = enc.transform(X.iloc[va_idx])
print('CV 下的 CatBoost 编码完成，无泄漏')
```

```text
CatBoost Encoding 的优势：
1. 无自泄漏 —— 不需要手动 KFold 就能安全使用
2. 稳健 —— 内置平滑，稀有类别不会被极端值带偏
3. 适用 —— 高基数类别 + 树模型的首选之一
```

## Hashing

Hashing（哈希编码 / Feature Hashing）把每个类别通过哈希函数映射到一个固定大小的向量（如 32 维），用 0/1 或 ±1 填充。它的最大优点是「无需存储类别映射」——新类别直接哈希即可，天然支持流式数据和超大规模类别，代价是可能发生哈希碰撞。

```text
核心思想：
1. 类别 → hash(类别) mod n_features → 落在固定维度向量的某个位置
2. 优点 —— 内存 O(n_features) 与类别数无关，支持新类别、流式
3. 缺点 —— 哈希碰撞（不同类别落同一格）损失信息，不可解释
```

```python
from sklearn.feature_extraction import FeatureHasher

# 哈希编码：固定维度，无需预先知道类别全集
hasher = FeatureHasher(n_features=8, input_type='string')
X_hash = hasher.transform(df['city'].astype(str))
print(X_hash.toarray())
# 每个类别映射到 8 维向量，可能出现碰撞
```

```text
Hashing 的坑：
1. 维度太小 → 碰撞严重，信息丢失；维度太大 → 稀疏
2. 不可逆 —— 无法从编码还原原始类别，不可解释
3. 适合 —— 超大规模类别（广告 ID、URL）、在线学习、流式特征
```

## 应用场景实战

### 场景一：高基数类别 + 树模型（LightGBM）编码对比

```python
import pandas as pd
import numpy as np
from sklearn.model_selection import train_test_split
from sklearn.metrics import roc_auc_score
import lightgbm as lgb

# 构造高基数类别数据：1000 个用户，每个用户的点击率不同
np.random.seed(42)
n = 50000
users = np.random.randint(0, 1000, n)
# 每个用户有潜在的真实点击率
user_ctr = np.random.rand(1000)
y = (np.random.rand(n) < user_ctr[users]).astype(int)
df = pd.DataFrame({'user': users, 'y': y})

X_tr, X_te, y_tr, y_te = train_test_split(df[['user']], y, test_size=0.2, random_state=42)

# 方式一：标签编码（Ordinal）
from sklearn.preprocessing import OrdinalEncoder
enc = OrdinalEncoder().fit(X_tr[['user']])
X_tr_o = enc.transform(X_tr[['user']])
X_te_o = enc.transform(X_te[['user']])

# 方式二：目标编码
te_map = pd.Series(y_tr).groupby(X_tr['user']).mean()
X_tr_t = X_tr['user'].map(te_map).fillna(y_tr.mean()).values.reshape(-1, 1)
X_te_t = X_te['user'].map(te_map).fillna(y_tr.mean()).values.reshape(-1, 1)

for name, Xa, Xb in [('Ordinal', X_tr_o, X_te_o), ('Target', X_tr_t, X_te_t)]:
    m = lgb.LGBMClassifier(n_estimators=100, verbose=-1)
    m.fit(Xa, y_tr)
    print(f'{name}: AUC={roc_auc_score(y_te, m.predict_proba(Xb)[:, 1]):.4f}')
# 输出类似：
# Ordinal: AUC=0.88xx
# Target:  AUC=0.93xx  → 目标编码显著更优
```

### 场景二：One-Hot vs Target 在多类别 + 线性模型上的表现

```python
from sklearn.linear_model import LogisticRegression
from sklearn.preprocessing import OneHotEncoder

# One-Hot 编码（线性模型）
oh = OneHotEncoder(handle_unknown='ignore')
X_tr_oh = oh.fit_transform(X_tr[['user']])
X_te_oh = oh.transform(X_te[['user']])

for name, Xa, Xb in [('OneHot', X_tr_oh, X_te_oh), ('Target', X_tr_t, X_te_t)]:
    clf = LogisticRegression(max_iter=1000)
    clf.fit(Xa, y_tr)
    print(f'{name} 逻辑回归: AUC={roc_auc_score(y_te, clf.predict_proba(Xb)[:, 1]):.4f}')
# OneHot 在高基数（1000 类）下维度爆炸、容易过拟合
# Target 编码只 1 列，线性模型也能学到类别与目标的关系
```

## 最佳实践与踩坑记录

### 最佳实践

1. 低基数（< 10 类）无序类别 → One-Hot 或 Ordinal，简单可靠
2. 高基数（> 100 类）→ 优先 Target / CatBoost 编码，配合树模型
3. 有天然顺序的类别 → Ordinal，并明确指定类别顺序
4. 目标编码一律在「交叉验证」内做，绝不能用全量数据算目标均值
5. 稀有类别 → 平滑目标编码或合并成「other」类，避免过拟合
6. 流式 / 超大规模类别 → Hashing，省内存、支持新类别
7. 类别编码的映射（encoder 对象）要持久化，保证训练/预测一致

### 踩坑记录

```text
坑 1：目标编码在训练前用全量数据算均值
结论：线上效果虚高，验证集 AUC 好看但实际上线崩。
原因：类别均值里包含了自己的标签，等于把答案写进特征（数据泄漏）。
解法：用 KFold 逐折拟合，或用 CatBoostEncoder（排列式），严禁全量计算。

坑 2：One-Hot 后测试集出现新类别直接报错
结论：fit 阶段没有见过的类别，transform 时抛异常。
原因：OneHotEncoder 默认 handle_unknown='error'。
解法：设 handle_unknown='ignore'，新类别编码为全 0。

坑 3：无顺序类别用了 Ordinal 喂线性模型
结论：模型误以为「类别 5 > 类别 1」，学到虚假的单调关系。
原因：整数编码引入了不存在的顺序假设。
解法：无顺序类别改用 One-Hot 或统计编码，线性模型尤其敏感。

坑 4：get_dummies 无法保证训练/测试列一致
结论：测试集类别缺失时列数对不上，模型预测报错。
原因：get_dummies 按「当前数据」生成列，不持久化类别全集。
解法：用 OneHotEncoder（可持久化 categories_），或保存列名后 reindex。

坑 5：哈希编码维度开太小导致碰撞
结论：不同类别撞进同一格，模型无法区分，效果下降。
原因：n_features 太小，类别数远超维度，碰撞概率高。
解法：维度至少开到类别数的 2 倍以上，并评估碰撞率。
```

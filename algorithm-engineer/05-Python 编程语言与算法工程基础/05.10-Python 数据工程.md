## 概述

数据工程是把数据从源头搬到可用位置的流水线工程：数据库存取、缓存、消息队列、HTTP 接口、数据校验。算法工程师的模型要上线服务，绕不开这些基础设施。掌握这一套，才能把「能跑通的脚本」变成「能上线的服务」。

```text
数据工程工具链：
1. 关系型数据库 —— SQLAlchemy（ORM）、psycopg（PostgreSQL）、PyMySQL（MySQL）
2. 缓存 —— redis-py（Redis 客户端）
3. 消息队列 —— kafka-python / confluent-kafka（Kafka）
4. HTTP —— requests（同步）、httpx（异步）
5. 服务框架 —— FastAPI + Pydantic（类型校验）
```

```python
# 数据工程的最小闭环：定义模型 → 校验 → 提供接口
from pydantic import BaseModel

class User(BaseModel):
    name: str
    age: int

print(User(name='Alice', age=30).model_dump())
```

## SQLAlchemy

SQLAlchemy 是 Python 最强大的 ORM（对象关系映射），用 Python 类映射数据库表，提供跨数据库的统一 API。它分两层：Core（SQL 表达式）和 ORM（对象映射），既照顾灵活性又照顾生产力。

```text
SQLAlchemy 核心：
1. Engine —— 数据库连接池入口
2. Session —— 工作单元，管理对象生命周期
3. 声明式模型 —— 继承 Base，类属性映射列
4. 查询 —— session.query / select 表达式
5. 跨库 —— 一套代码适配 PostgreSQL/MySQL/SQLite
```

```python
from sqlalchemy import create_engine, Column, Integer, String, select
from sqlalchemy.orm import declarative_base, Session

Base = declarative_base()

class User(Base):
    __tablename__ = 'users'
    id = Column(Integer, primary_key=True)
    name = Column(String(50))
    age = Column(Integer)

# SQLite 内存库演示（生产换 PostgreSQL 连接串）
engine = create_engine('sqlite:///:memory:')
Base.metadata.create_all(engine)

with Session(engine) as session:
    session.add(User(name='Alice', age=30))
    session.commit()
    users = session.execute(select(User).where(User.age > 20)).scalars()
    print([u.name for u in users])   # ['Alice']
```

## psycopg

psycopg 是 PostgreSQL 的 Python 驱动，psycopg3 是最新版本，性能好、支持异步、支持服务端参数和二进制传输。相比 ORM，它更底层，适合需要精确控制 SQL 和连接的高性能场景。

```text
psycopg 要点：
1. psycopg 3 —— 现代版本，支持同步和异步
2. 参数化查询 —— 用 %s 占位符防 SQL 注入
3. 连接池 —— 配合 psycopg_pool 管理连接
4. COPY —— 批量导入数据最快的方式
5. 事务 —— 自动开始，commit/rollback 控制
```

## PyMySQL

PyMySQL 是纯 Python 实现的 MySQL 驱动，无需编译 C 扩展，安装即用，是连接 MySQL 最省事的选择。它遵循 DB-API 2.0 规范，用 cursor 执行 SQL、fetch 取结果。

```text
PyMySQL 要点：
1. 纯 Python —— 无需编译，跨平台方便
2. DB-API 2.0 —— 标准 cursor / execute / fetch 接口
3. 参数化 —— %s 占位符，防 SQL 注入
4. autocommit —— 默认关闭，需手动 commit
5. 性能 —— 高频场景可换 C 驱动的 mysqlclient
```

## redis-py

redis-py 是 Redis 的官方 Python 客户端，提供 String、Hash、List、Set、Sorted Set 等数据结构的 Python 接口。Redis 常用作缓存、计数器、分布式锁、消息队列，是服务端提速的关键组件。

```text
redis-py 常用操作：
1. set/get —— 字符串键值，最基础的缓存
2. expire —— 设置过期时间
3. hset/hget —— 哈希表，存结构化对象
4. incr —— 原子自增，做计数器
5. 连接池 —— ConnectionPool 复用连接
6. 管道 pipeline —— 批量命令减少往返
```

```python
import redis

r = redis.Redis(host='localhost', port=6379, decode_responses=True)

# 字符串缓存
r.set('user:1:name', 'Alice', ex=60)     # 60 秒过期
print(r.get('user:1:name'))              # Alice

# 哈希
r.hset('user:1', mapping={'name': 'Alice', 'age': 30})
print(r.hgetall('user:1'))               # {'name': 'Alice', 'age': '30'}

# 原子计数器
r.incr('page:views')
print(r.get('page:views'))               # 1

# 管道批量执行
pipe = r.pipeline()
pipe.set('a', 1)
pipe.set('b', 2)
pipe.execute()
```

## kafka-python

kafka-python 是纯 Python 的 Kafka 客户端，API 简单，适合快速接入和测试。Kafka 是分布式消息队列，生产者发布消息到 topic，消费者按分区订阅消费，是数据流管道（如日志、埋点、实时特征）的标配。

```text
Kafka 核心概念：
1. topic —— 消息主题，逻辑上的消息分类
2. partition —— 分区，消息并行和有序的单元
3. producer —— 生产者，发消息到 topic
4. consumer —— 消费者，订阅 topic 拉消息
5. consumer group —— 消费组，组内分区负载均衡
6. offset —— 消息位点，控制消费进度
```

## confluent-kafka

confluent-kafka 是 Confluent 官方的 Kafka 客户端，底层是高性能的 C 库 librdkafka，吞吐远高于纯 Python 实现，是生产环境的推荐选择。API 分为 Producer/Consumer 类，也提供 Avro、Schema Registry 等高级能力。

```text
confluent-kafka vs kafka-python：
1. 性能 —— C 库实现，生产级吞吐，远快于纯 Python
2. 维护 —— 官方维护，功能更全（事务、幂等、Avro）
3. 复杂度 —— API 相对底层，配置项多
4. 选型 —— 生产用 confluent-kafka，快速原型用 kafka-python
```

## requests / httpx

requests 是同步 HTTP 客户端的事实标准，API 极简，适合脚本和低并发场景。httpx 是它的现代继任者，接口兼容但原生支持异步和 HTTP/2，是高并发服务调用的首选。

```text
requests vs httpx：
1. requests —— 同步、简单、生态最广
2. httpx —— 同步+异步双模式，async with 支持并发
3. 高并发 —— httpx.AsyncClient 配合 asyncio 并发请求
4. 超时 —— 都支持 timeout，务必显式设置
5. 会话 —— Session/Client 复用连接，避免重复握手
```

```python
import requests
import httpx
import asyncio

# 同步请求
r = requests.get('https://httpbin.org/get', params={'q': 'hello'},
                 timeout=10)
print(r.status_code, r.json()['args'])   # 200 {'q': 'hello'}

r2 = requests.post('https://httpbin.org/post',
                   json={'name': 'Alice'}, timeout=10)
print(r2.json()['json'])                 # {'name': 'Alice'}

# 异步并发请求（httpx + asyncio）
async def fetch_all(urls):
    async with httpx.AsyncClient(timeout=10) as client:
        resp = await asyncio.gather(*[client.get(u) for u in urls])
        return [r.status_code for r in resp]

urls = ['https://httpbin.org/get'] * 5
print(asyncio.run(fetch_all(urls)))      # [200, 200, 200, 200, 200]
```

## FastAPI

FastAPI 是高性能的现代 Web 框架，基于 ASGI 和类型注解自动生成交互式文档（Swagger）和数据校验。它异步友好、依赖注入优雅，是算法模型服务化的首选框架，性能接近 Go/Node。

```text
FastAPI 特性：
1. 类型驱动 —— 用 Pydantic 模型声明请求/响应，自动校验
2. 自动文档 —— /docs 提供 Swagger 交互式文档
3. 异步 —— 原生 async/await，支持高并发
4. 依赖注入 —— Depends 优雅管理公共逻辑
5. 高性能 —— 基于 Starlette + Pydantic
```

```python
from fastapi import FastAPI, Query
from pydantic import BaseModel
from typing import Optional

app = FastAPI()

class PredictRequest(BaseModel):
    features: list[float]
    model_version: Optional[str] = 'v1'

class PredictResponse(BaseModel):
    prediction: float
    model_version: str

@app.get('/health')
async def health():
    return {'status': 'ok'}

@app.post('/predict', response_model=PredictResponse)
async def predict(req: PredictRequest):
    # 示意：真实场景这里调用模型推理
    score = sum(req.features) / len(req.features)
    return PredictResponse(prediction=score, model_version=req.model_version)

# 启动：uvicorn main:app --reload
print(app.title)
```

## Pydantic

Pydantic 是数据校验库，用类型注解定义数据模型，运行时自动校验、类型转换、序列化。它是 FastAPI 的基石，也独立用于配置管理、请求/响应校验、数据管道里的数据契约。

```text
Pydantic 核心：
1. BaseModel —— 定义数据模型，字段用类型注解声明
2. 自动校验 —— 类型不符直接报 ValidationError
3. 自动转换 —— '30' 自动转成 30（coerce）
4. 约束 —— Field 加范围、正则、默认值
5. model_dump / model_validate —— 序列化和反序列化
```

```python
from pydantic import BaseModel, Field, field_validator

class Config(BaseModel):
    host: str = 'localhost'
    port: int = Field(default=8080, ge=1, le=65535)
    model_path: str
    batch_size: int = 32

    @field_validator('batch_size')
    @classmethod
    def check_batch(cls, v):
        if v <= 0:
            raise ValueError('batch_size 必须为正')
        return v

# 正常校验
cfg = Config(model_path='/models/x.pkl', port='9000')   # 字符串自动转 int
print(cfg.model_dump())

# 非法值报错
try:
    Config(model_path='/m', port=99999)
except Exception as e:
    print(type(e).__name__)   # ValidationError
```

## 应用场景实战

### 场景一：模型推理服务（FastAPI + Pydantic + Redis 缓存）

```python
from fastapi import FastAPI
from pydantic import BaseModel
import redis
import hashlib

app = FastAPI()
cache = redis.Redis(host='localhost', port=6379, decode_responses=True)

class Req(BaseModel):
    text: str

def model_infer(text: str) -> float:
    # 示意：真实模型推理
    return len(text) * 0.5

@app.post('/score')
def score(req: Req):
    key = 'cache:' + hashlib.md5(req.text.encode()).hexdigest()
    hit = cache.get(key)
    if hit is not None:
        return {'score': float(hit), 'cached': True}
    result = model_infer(req.text)
    cache.set(key, result, ex=300)      # 缓存 5 分钟
    return {'score': result, 'cached': False}
```

### 场景二：Kafka 消费 + 数据库写入管道

```python
from sqlalchemy import create_engine, Column, Integer, String
from sqlalchemy.orm import declarative_base, Session

Base = declarative_base()

class Event(Base):
    __tablename__ = 'events'
    id = Column(Integer, primary_key=True)
    user_id = Column(Integer)
    action = Column(String(32))

engine = create_engine('sqlite:////tmp/events.db')
Base.metadata.create_all(engine)

# 示意：从 Kafka 消费消息，写入数据库
def consume_and_store(messages):
    with Session(engine) as session:
        for m in messages:               # m 来自 Kafka consumer
            session.add(Event(user_id=m['user_id'], action=m['action']))
        session.commit()

sample = [{'user_id': 1, 'action': 'click'},
          {'user_id': 2, 'action': 'view'}]
consume_and_store(sample)
print('已写入事件表')
```

## 最佳实践与踩坑记录

### 最佳实践

1. SQL 一律用参数化查询（%s 占位符），绝不拼接字符串，防 SQL 注入
2. 数据库连接用连接池（SQLAlchemy engine / psycopg_pool），别每次请求新建连接
3. Redis 高频访问数据设过期时间，防止缓存无限膨胀
4. HTTP 请求显式设 timeout，避免服务端无响应时客户端永久挂起
5. 生产 Kafka 用 confluent-kafka（C 库高性能），原型验证可用 kafka-python
6. 服务接口用 Pydantic 做输入校验，把脏数据挡在业务逻辑之外

### 踩坑记录

```text
坑 1：SQL 字符串拼接导致注入
结论：用户输入构造 SQL，数据库被拖库。
原因：直接 f'... {input} ...' 拼接，恶意输入可执行任意 SQL。
解法：一律参数化查询，ORM 用表达式 API，杜绝拼接。

坑 2：忘记 commit 数据没写进去
结论：执行了 add/execute，但数据库里查不到。
原因：PyMySQL/SQLAlchemy 默认非 autocommit，事务未提交。
解法：显式 commit，或用 with Session 块自动提交回滚。

坑 3：httpx 异步客户端在同步代码里用 async with
结论：RuntimeError 或事件循环冲突。
原因：AsyncClient 必须在事件循环里用，同步场景直接报错。
解法：同步用 httpx.Client，异步才用 AsyncClient + asyncio.run。

坑 4：Redis 键没有过期时间导致内存暴涨
结论：缓存键越积越多，Redis 内存耗尽。
原因：set 时忘了 ex 参数，键永久驻留。
解法：缓存键一律设 TTL，或用淘汰策略（allkeys-lru）。

坑 5：Kafka 消费者组 offset 处理不当导致丢消息或重复
结论：消息要么丢要么重复消费。
原因：auto_commit 时机不对，处理前就提交会丢，处理后崩溃会重复。
解法：手动提交 offset，保证「处理成功才提交」，配合幂等消费。
```

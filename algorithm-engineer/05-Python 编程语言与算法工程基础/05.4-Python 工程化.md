## 概述

工程化是把「能跑的脚本」变成「可维护、可复现、可部署的项目」的过程：隔离环境、锁定依赖、规范日志、解析参数、管理配置。算法工程师的代码要从实验脚本走向生产服务，这些能力缺一不可。

```text
工程化的核心维度：
1. 环境隔离 —— venv/uv 隔离项目依赖，避免全局污染
2. 依赖管理 —— 锁定版本、可复现安装
3. 配置管理 —— 参数从代码里抽离到配置文件/环境变量
4. 可观测性 —— 结构化日志，出了问题能定位
5. 可复用性 —— 打包成库，pytest 可测、CI 可跑
```

```python
# 一个工程化项目的最小骨架
# project/
# ├── pyproject.toml
# ├── src/myapp/
# │   ├── __init__.py
# │   └── main.py
# └── tests/test_main.py
```

## venv

`venv` 是 Python 自带的虚拟环境工具，在项目目录下创建隔离的解释器和 site-packages。它零额外依赖、开箱即用，是最基础的隔离方案。每个项目一个 venv，避免全局依赖冲突。

```bash
# 创建与激活
python3 -m venv .venv           # 创建虚拟环境
source .venv/bin/activate       # 激活（Linux/macOS）
# .venv\Scripts\activate        # Windows
deactivate                      # 退出
```

```text
venv 要点：
1. 每个项目独立 site-packages，互不污染
2. 解释器是符号链接到系统 Python，环境不随 Python 升级而变
3. 常配合 pip freeze > requirements.txt 做依赖记录
```

## virtualenv

`virtualenv` 是 venv 的前身和增强版：支持更老的 Python 版本、更灵活的选项（指定解释器、site-packages 复制等）。现在 venv 已覆盖大多数场景，virtualenv 主要用于兼容旧环境。

```bash
pip install virtualenv
virtualenv myenv                 # 创建环境
virtualenv -p python3.11 myenv   # 指定解释器版本
source myenv/bin/activate
```

```text
virtualenv vs venv：
1. venv —— 标准库自带，Python 3.3+，零依赖，够用
2. virtualenv —— 第三方，功能更全，兼容老版本和特殊场景
3. 新项目默认 venv 即可，除非需要 virtualenv 的额外能力
```

## Poetry

Poetry 是集依赖管理、打包、发布于一体的现代工具：用 `pyproject.toml` 声明依赖，`poetry.lock` 锁定精确版本，一条命令完成环境创建和依赖安装。它把「依赖解析 + 虚拟环境」统一管理，可复现性强。

```bash
poetry init                      # 初始化项目
poetry add numpy pandas          # 添加依赖
poetry add --group dev pytest    # 添加开发依赖
poetry install                   # 按 lock 文件安装
poetry run python main.py        # 在项目环境里运行
poetry lock                      # 更新锁定文件
```

```text
Poetry 的价值：
1. 依赖 + 打包 + 发布一站式
2. pyproject.toml 声明 + poetry.lock 锁定，完全可复现
3. 自动管理虚拟环境，poetry run 无需手动 activate
```

## uv

`uv` 是 Rust 写的极速 Python 包管理器和项目管理器，由 Astral（ruff 作者）开发，速度比 pip/Poetry 快一个数量级。它既能当 pip 替代品，也能像 Poetry 一样管理整个项目（uv init / uv add / uv sync）。

```bash
uv venv                         # 创建虚拟环境（秒级）
uv pip install numpy            # 高速安装（替代 pip）
uv add numpy pandas             # 项目管理模式，写 pyproject.toml
uv sync                         # 按 lock 安装所有依赖
uv run python main.py           # 在项目环境运行
uv lock                         # 锁定依赖
```

```text
uv 的优势：
1. 极快 —— Rust 实现，并行下载，安装速度远快于 pip
2. 兼容 —— 可直接替换 pip，也提供 Poetry 式项目管理
3. 统一 —— venv、依赖解析、锁定、运行一个工具搞定
```

## pip

`pip` 是 Python 官方包安装器，从 PyPI 下载安装包。`pip install` 是使用第三方库的第一步；`pip freeze` 导出当前环境；`pip install -r` 批量安装。它不管理虚拟环境，只管装包。

```bash
pip install numpy==1.26.4       # 安装指定版本
pip install -r requirements.txt # 批量安装
pip freeze > requirements.txt   # 导出当前环境
pip uninstall numpy             # 卸载
pip install -e .                # 以可编辑模式安装本地项目
```

```text
pip 常用场景：
1. 快速装包验证想法
2. requirements.txt 记录依赖（只记录顶层，不锁传递依赖）
3. -e 可编辑安装，本地改代码立即生效
```

## pyproject.toml

`pyproject.toml` 是现代 Python 项目的统一配置中心：声明项目元数据、依赖、构建系统，还集中配置 black、ruff、pytest、mypy 等工具。它取代了 setup.py/requirements.txt 的割裂局面。

```toml
[project]
name = "myapp"
version = "0.1.0"
requires-python = ">=3.11"
dependencies = [
    "numpy>=1.26",
    "pandas>=2.0",
]

[project.optional-dependencies]
dev = ["pytest", "ruff", "mypy"]

[tool.pytest.ini_options]
testpaths = ["tests"]

[tool.ruff]
line-length = 88
```

```text
pyproject.toml 的结构：
1. [project] —— 项目元数据与依赖（PEP 621）
2. [build-system] —— 构建后端（setuptools/hatchling）
3. [tool.xxx] —— 各工具的配置统一放这里
```

## Package Management

包管理涵盖「声明依赖 → 锁定版本 → 可复现安装」全流程。关键在于锁定传递依赖：顶层写依赖范围，lock 文件锁定所有传递依赖的精确版本，保证任何机器装出来都一致。

```text
依赖管理的演进：
1. requirements.txt —— 简单，但不锁传递依赖，易漂移
2. Poetry/uv + lock —— 锁全量依赖图，可复现，是生产标准
3. 语义化版本 —— 主版本.次版本.补丁，用范围声明兼容性
```

```bash
# 用 uv 演示完整的依赖管理流
uv init myproj && cd myproj
uv add "numpy>=1.26,<2.0"     # 声明范围
uv lock                       # 生成 uv.lock 锁定全量依赖
uv sync                       # 任何机器都能装出一致环境
```

## Logging

`logging` 是标准库的日志模块，按级别（DEBUG/INFO/WARNING/ERROR）记录运行信息，支持输出到文件、控制台、多 handler、日志轮转。生产环境必须用 logging 而非 print，否则无法按级别过滤和持久化。

```python
import logging

logging.basicConfig(
    level=logging.INFO,
    format="%(asctime)s [%(levelname)s] %(name)s: %(message)s",
)

logger = logging.getLogger("trainer")

logger.debug("调试信息")
logger.info("训练开始，epoch=1")
logger.warning("学习率过高")
logger.error("梯度爆炸，loss=nan")
```

```text
日志级别（从低到高）：
DEBUG < INFO < WARNING < ERROR < CRITICAL
设置 level 后，低于该级别的日志被过滤，可随时调整详细度
```

## Argparse

`argparse` 是标准库的命令行参数解析器：把脚本的参数定义成命令行选项，自动生成 `--help`、类型转换和默认值。训练脚本用它把超参数暴露成命令行参数，实验可配置、可复现。

```python
import argparse

parser = argparse.ArgumentParser(description="训练一个模型")
parser.add_argument("--epochs", type=int, default=100, help="训练轮数")
parser.add_argument("--lr", type=float, default=0.01, help="学习率")
parser.add_argument("--data", type=str, required=True, help="数据路径")
parser.add_argument("--debug", action="store_true", help="调试模式")

args = parser.parse_args(["--data", "data.csv", "--lr", "0.05"])
print(args.epochs, args.lr, args.data, args.debug)
```

```text
argparse 要点：
1. type 指定类型，default 设默认值，help 写说明
2. action="store_true" 生成开关型布尔参数
3. required=True 强制必填，--help 自动生成帮助
```

## Pathlib

`pathlib.Path` 用面向对象的方式处理文件路径，替代 os.path 的字符串拼接。它跨平台、链式调用、读写法内建，是处理路径的现代首选。

```python
from pathlib import Path

root = Path("data") / "raw" / "train.csv"    # 用 / 拼接路径
print(root)                                  # data/raw/train.csv
print(root.name, root.suffix, root.stem)     # train.csv .csv train
print(root.parent)                           # data/raw
print(root.exists())                         # 判断是否存在

# 常用操作
Path("out").mkdir(parents=True, exist_ok=True)   # 递归建目录
for f in Path("data").glob("*.csv"):             # 通配符遍历
    print(f)

text = Path("note.txt").read_text(encoding="utf-8")  # 直接读写
Path("out.txt").write_text("hello", encoding="utf-8")
```

```text
Path vs os.path：
1. Path 是对象，/ 拼接、.parent、.name 一目了然
2. read_text/write_text 内建，省去 open() 样板
3. glob/rglob 遍历文件，替代 os.walk 的繁琐
```

## Config Management

配置管理把可调参数从代码中抽离到配置文件（YAML/TOML/JSON），实现「改配置不改代码」。推荐用配置对象（dataclass/Pydantic）统一加载和校验，再注入到业务逻辑。

```python
import tomllib

config_text = """
[model]
learning_rate = 0.01
epochs = 200
hidden_units = [128, 64]

[data]
path = "data/train.parquet"
batch_size = 32
"""

data = tomllib.loads(config_text)      # Python 3.11+ 内置 TOML 解析
print(data["model"]["learning_rate"])  # 0.01
print(data["model"]["hidden_units"])   # [128, 64]
```

```text
配置管理原则：
1. 代码里只放逻辑，可变参数进配置文件
2. 配置文件纳入版本控制（含注释，便于审计）
3. 敏感信息（密钥、口令）不放配置文件，走环境变量
```

## Environment Variables

环境变量用 `os.environ` 读写，适合存放密钥、部署环境标识等运行时才确定的配置。它不写入代码和仓库，避免敏感信息泄露，也是 12-factor app 的核心原则。

```python
import os

os.environ["MODEL_DIR"] = "/models/v1"      # 设置（运行时）
print(os.environ.get("MODEL_DIR"))          # 读取
print(os.environ.get("NOT_SET", "/default")) # 带默认值，不存在不报错
```

```bash
# 命令行注入环境变量运行
export API_KEY="secret-token"
python train.py          # 脚本内 os.environ.get("API_KEY") 读取
```

```text
环境变量最佳实践：
1. 密钥、token 用环境变量，绝不硬编码进仓库
2. 读取用 os.environ.get(key, default)，避免 KeyError
3. 部署环境（dev/staging/prod）用环境变量区分
```

## 应用场景实战

### 场景一：标准化的训练脚本入口

```python
import argparse
import logging
from pathlib import Path

logging.basicConfig(level=logging.INFO, format="%(levelname)s %(message)s")
logger = logging.getLogger("train")

def main(args):
    data_path = Path(args.data)
    logger.info(f"加载数据: {data_path}")
    if not data_path.exists():
        logger.error(f"数据文件不存在: {data_path}")
        raise SystemExit(1)
    logger.info(f"开始训练: epochs={args.epochs}, lr={args.lr}")

if __name__ == "__main__":
    parser = argparse.ArgumentParser()
    parser.add_argument("--data", required=True)
    parser.add_argument("--epochs", type=int, default=100)
    parser.add_argument("--lr", type=float, default=0.01)
    main(parser.parse_args(["--data", "data.csv", "--epochs", "50"]))
```

### 场景二：配置加载 + 环境变量注入

```python
import os
import tomllib

CONFIG = """
[training]
epochs = 300
lr = 0.001
"""

def load_config() -> dict:
    cfg = tomllib.loads(CONFIG)
    # 环境变量覆盖：TRAIN_EPOCHS=500 时优先使用
    if "TRAIN_EPOCHS" in os.environ:
        cfg["training"]["epochs"] = int(os.environ["TRAIN_EPOCHS"])
    return cfg

print(load_config()["training"])    # {'epochs': 300, 'lr': 0.001}
```

## 最佳实践与踩坑记录

### 最佳实践

1. 每个项目独立虚拟环境，全局不装项目依赖
2. 用 lock 文件锁定全量依赖，保证可复现
3. 生产环境用 logging 分级记录，别用 print
4. 路径处理统一用 pathlib.Path，别拼字符串
5. 训练超参数用 argparse 暴露成命令行参数
6. 敏感信息走环境变量，配置文件只放非敏感项
7. 用 pyproject.toml 统一管理项目元数据和工具配置

### 踩坑记录

```text
坑 1：依赖没锁版本导致环境漂移
结论：换台机器 install 出来的依赖版本不一致，行为不同甚至报错。
原因：requirements.txt 只记录顶层依赖，传递依赖版本会浮动。
解法：用 Poetry/uv 生成 lock 文件，任何环境 uv sync 装出一致版本。

坑 2：把密钥硬编码进代码
结论：API 密钥、数据库口令提交到仓库，泄露风险极高。
原因：图省事直接写死在代码或配置文件里。
解法：用环境变量或专门的密钥管理（.env 不进版本控制）。

坑 3：用 print 代替 logging
结论：生产环境无法按级别过滤日志，也无法持久化和追踪。
原因：print 简单，但缺少级别、来源、时间戳等上下文。
解法：用 logging 配 format 和 level，按模块命名 logger。

坑 4：路径用字符串拼接
结论："data" + "/" + name 在 Windows 上出错，路径难维护。
原因：不同 OS 分隔符不同，字符串拼接脆弱。
解法：用 pathlib.Path 的 / 拼接和 .parent/.name 操作。

坑 5：venv 目录提交到 git
结论：仓库体积暴增，且 venv 与机器路径强绑定，换机不可用。
原因：没在 .gitignore 排除虚拟环境目录。
解法：.gitignore 加 .venv/、__pycache__/、*.pyc。
```

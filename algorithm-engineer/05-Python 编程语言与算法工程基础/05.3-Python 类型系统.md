## 概述

Python 是动态类型语言，但通过类型注解（type hints）配合静态检查器（mypy、pyright），可以在不改变运行时行为的前提下，获得编译期级别的类型安全。它让大型项目更易维护、IDE 补全更智能，是算法工程代码走向工程化的关键一步。

```text
类型系统的核心价值：
1. 尽早发现错误 —— 类型不匹配在运行前就被静态检查器抓住
2. 更好的文档 —— 函数签名即接口说明，可读性大幅提升
3. 更强的 IDE —— 自动补全、跳转定义、重构更可靠
4. 零运行时开销 —— 注解只是元数据，不影响性能
```

```python
def scale(features: list[float], factor: float) -> list[float]:
    """注解只是提示，运行时不强制。"""
    return [x * factor for x in features]

print(scale([1.0, 2.0], 2.0))   # [2.0, 4.0]
print(scale.__annotations__)     # {'features': list[float], ...}
```

## Type Hints

类型注解用 `变量: 类型` 和 `-> 返回类型` 标注类型。它从 Python 3.5 引入，逐步演进到 PEP 604（`X | Y`）和 PEP 585（`list[int]` 内置泛型）。注解本身不参与运行，需要外部工具检查。

```python
from typing import Any

name: str = "alice"
count: int = 42
scores: list[float] = [0.9, 0.8, 0.7]
mapping: dict[str, int] = {"a": 1}
maybe: str | None = None           # PEP 604 联合类型

def process(items: list[int], *, verbose: bool = False) -> int:
    return len(items)

print(process([1, 2, 3], verbose=True))
```

```text
注解的演进（推荐用新语法）：
1. Python 3.9+：list[int], dict[str, int]（PEP 585 内置泛型）
2. Python 3.10+：X | None, X | Y（PEP 604 联合类型）
3. 老写法 typing.List[int], typing.Optional[X] 仍兼容但不推荐
4. 未标注的参数默认视为 Any
```

## Generic

泛型让类或函数可以参数化类型：同一个容器类能装不同类型，同时保持类型安全。`Generic[T]` 声明泛型类，实例化时指定具体类型，静态检查器据此推断元素类型。

```python
from typing import Generic, TypeVar

T = TypeVar("T")

class Stack(Generic[T]):
    def __init__(self) -> None:
        self._items: list[T] = []

    def push(self, item: T) -> None:
        self._items.append(item)

    def pop(self) -> T:
        return self._items.pop()

s_int: Stack[int] = Stack()
s_int.push(1)
s_int.push(2)
print(s_int.pop())          # 2
# s_int.push("x")           # 类型检查器报错
```

```text
泛型要点：
1. Generic[T] 让类携带类型参数，内部用 T 标注
2. 实例化时绑定具体类型，检查器验证传入/取出类型一致
3. 内置容器 list/dict 本身就是泛型，无需再包 Generic
```

## TypeVar

`TypeVar` 定义一个类型变量，作为泛型函数的「占位类型」。它让函数能表达「输入什么类型、输出同类型」的约束（如 `first` 返回元素本身类型），保持类型信息不丢失。

```python
from typing import TypeVar, Iterable

T = TypeVar("T")

def first(items: Iterable[T]) -> T:
    """返回可迭代对象的第一个元素，类型与元素一致。"""
    return next(iter(items))

print(first([1, 2, 3]))     # 1 (int)
print(first("abc"))         # 'a' (str)

# 带约束的 TypeVar
Num = TypeVar("Num", int, float)
def add(a: Num, b: Num) -> Num:
    return a + b

print(add(1, 2), add(1.5, 2.5))    # 3 4.0
```

```text
TypeVar 用法：
1. 无约束 T = TypeVar("T") —— 任意类型
2. 有约束 TypeVar("T", int, float) —— 限定类型范围
3. covariant/contravariant 用于协变/逆变（高级场景）
```

## Protocol

Protocol 定义「结构化类型」（结构化子类型）：不要求显式继承，只要对象实现了协议要求的属性和方法，就被视为该协议的子类型。它把鸭子类型「静态化」，让检查器也能验证接口。

```python
from typing import Protocol

class Sized(Protocol):
    def __len__(self) -> int: ...

def print_size(obj: Sized) -> None:
    print(len(obj))

# list、str、dict 都实现了 __len__，无需继承即满足协议
print_size([1, 2, 3])       # 3
print_size("hello")         # 5
print_size({"a": 1})        # 1
```

```text
Protocol 要点：
1. 结构化子类型 —— 只看结构（有没有 __len__），不看继承关系
2. 用 ... 声明方法签名，不写实现
3. 适合定义「能力接口」而非「类型层次」
```

## TypedDict

`TypedDict` 为字典定义结构化的键值类型：标注每个键的名字和值类型。它让「用 dict 当数据对象」的常见写法也具备类型检查，尤其适合 JSON 数据、API 响应这类异构字典。

```python
from typing import TypedDict

class User(TypedDict):
    name: str
    age: int
    email: str

def greet(user: User) -> str:
    return f"{user['name']}，{user['age']} 岁"

alice: User = {"name": "Alice", "age": 30, "email": "a@x.com"}
print(greet(alice))         # Alice，30 岁
# bob: User = {"name": "Bob"}   # 类型检查器报错：缺 age/email
```

```text
TypedDict 要点：
1. 只约束键名和值类型，运行时仍是普通 dict
2. 键可以加 total=False 设为可选
3. 访问缺失键仍是运行时 KeyError，静态检查器只能查标注过的字面量键
```

## Literal

`Literal[...]` 把类型限制为一组具体的字面值，用于枚举式的参数（如 `mode: Literal["train", "eval"]`）。它让检查器能在分支里做穷尽检查，防止拼错字符串。

```python
from typing import Literal

Mode = Literal["train", "eval", "infer"]

def run(mode: Mode) -> str:
    if mode == "train":
        return "开始训练"
    elif mode == "eval":
        return "开始评估"
    else:
        return "开始推理"

print(run("train"))     # 开始训练
# run("trian")          # 类型检查器报错：拼写错误被捕获
```

```text
Literal 适用场景：
1. 枚举字符串参数（模式、状态、策略名）
2. 有限集合的取值（颜色、方向、等级）
3. 配合 dict 映射做穷尽分派，检查器保证不遗漏分支
```

## Optional

`Optional[X]` 等价于 `X | None`，表示「X 或 None」。它用于显式声明可空值，提醒调用方处理 None 情况。现代写法推荐直接写 `X | None`（PEP 604）。

```python
from typing import Optional

def find_index(items: list[int], target: int) -> Optional[int]:
    """找不到时返回 None。"""
    for i, x in enumerate(items):
        if x == target:
            return i
    return None

idx = find_index([1, 2, 3], 2)
if idx is not None:               # 类型收窄：检查后 idx 变成 int
    print(f"找到，下标 {idx}")
else:
    print("未找到")
```

```text
Optional 要点：
1. Optional[X] == X | None，新代码推荐 X | None
2. 处理前先判空，检查器会自动收窄类型
3. 别用 Optional 掩盖「本该返回值却返回 None」的设计问题
```

## Union

`Union[X, Y]` 表示「X 或 Y」，允许一个值有多种可能类型。PEP 604 的 `X | Y` 是更简洁的等价写法。它用于「参数可以是多种类型」的场景，如接受 int 或 float。

```python
from typing import Union

def to_seconds(duration: Union[int, float]) -> float:
    """int 按秒，float 也按秒。"""
    return float(duration)

# PEP 604 等价写法
def to_seconds2(duration: int | float) -> float:
    return float(duration)

print(to_seconds(30), to_seconds2(1.5))   # 30.0 1.5
```

```text
Union vs Optional：
1. Union[X, Y, Z] —— 多个类型任选其一
2. Optional[X] == Union[X, None] == X | None
3. 类型过宽的 Union 会削弱检查效果，能收窄就收窄
```

## mypy / pyright

mypy 和 pyright 是两大主流静态类型检查器。mypy 是官方生态的老牌工具、插件丰富；pyright 由微软开发、速度快、IDE（VS Code Pylance）底层用的就是它。它们读源码中的注解，在运行前报告类型错误。

```text
两者的定位：
1. mypy —— 官方支持、生态成熟、可扩展插件多，适合 CI 集成
2. pyright —— 速度快、增量分析、推断更激进，适合编辑器实时反馈
3. 都可配置严格程度（strict 模式），逐项开启检查规则
```

```bash
# 安装与使用
pip install mypy pyright
mypy my_module.py            # 检查单个文件
pyright my_module.py         # 检查单个文件
mypy --strict .              # 全项目严格检查
```

```python
# 用注释精细控制检查
def legacy(x):               # type: ignore  # 忽略本行类型错误
    return x + 1

from typing import cast
val = cast(int, "10")        # 断言类型，绕过检查器的怀疑
```

```text
配置示例（pyproject.toml）：
[tool.mypy]
python_version = "3.11"
strict = true
warn_unused_ignores = true

[tool.pyright]
typeCheckingMode = "strict"
```

## 应用场景实战

### 场景一：给机器学习训练函数加完整类型约束

```python
from typing import Literal, TypedDict, Protocol

class Features(Protocol):
    def __len__(self) -> int: ...

class Result(TypedDict):
    loss: float
    accuracy: float

def train(
    X: Features,
    y: list[int],
    mode: Literal["train", "eval"] = "train",
) -> Result:
    n = len(X)
    acc = sum(y) / max(n, 1)
    return {"loss": 0.25, "accuracy": acc}

print(train([1, 2, 3, 4], [1, 0, 1, 0]))        # {'loss': 0.25, ...}
print(train("abcd", [1, 1, 1, 1], mode="eval"))
```

### 场景二：泛型缓存函数，保持输入输出类型一致

```python
from typing import TypeVar, Callable
import functools

T = TypeVar("T")

def memoize(func: Callable[..., T]) -> Callable[..., T]:
    cache: dict = {}

    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        key = (args, tuple(sorted(kwargs.items())))
        if key not in cache:
            cache[key] = func(*args, **kwargs)
        return cache[key]

    return wrapper

@memoize
def fib(n: int) -> int:
    return n if n < 2 else fib(n - 1) + fib(n - 2)

print(fib(20))      # 6765，类型信息 int 全程保留
```

## 最佳实践与踩坑记录

### 最佳实践

1. 公共函数和类的对外接口一律加类型注解，内部私有逻辑可适度省略
2. 新代码用 list[int]、X | None 新语法，避免 typing.List/Optional
3. 可空值显式用 X | None，处理前判空让检查器自动收窄
4. 字符串枚举用 Literal，防止拼写错误
5. 异构字典用 TypedDict 定义键结构，比裸 dict 更安全
6. CI 里跑 mypy/pyright，把类型错误挡在合并前

### 踩坑记录

```text
坑 1：注解了但从不运行检查器
结论：写了类型注解却不跑 mypy/pyright，等于白写。
原因：注解只是元数据，运行时不校验，不检查就发现不了错误。
解法：把 mypy/pyright 接入 CI 和 pre-commit，强制每次检查。

坑 2：过度使用 Any
结论：Any 让检查器完全失明，类型安全形同虚设。
原因：Any 与任何类型都兼容，错误会被静默吞掉。
解法：尽量用具体类型或 Protocol，只在真正不确定处用 Any 并加注释说明。

坑 3：用旧语法 typing.List 混用新语法
结论：代码里 list[int] 和 typing.List[int] 混用，风格混乱。
原因：Python 版本兼容性顾虑，导致新旧语法并存。
解法：统一用内置泛型（Python 3.9+），项目统一配置目标版本。

坑 4：Optional 未判空就使用
结论：可能值 None 时直接调用方法，运行时 AttributeError。
原因：没做 None 检查就进入后续逻辑。
解法：if x is not None 收窄后再用，或用 getattr 提供默认值。

坑 5：TypedDict 访问不存在的键
结论：拼错键名或访问缺失键，运行时 KeyError。
原因：TypedDict 只能查标注过的字面量键，动态键无法静态检查。
解法：键名用常量管理，运行时用 .get() 提供默认值。
```

## 概述

Python 性能优化的核心方法论是「先测量、再优化、最后验证」：用剖析工具定位真正的瓶颈，而不是凭直觉乱改。优化手段从低到高依次是算法改进、向量化、JIT 编译、C 扩展，成本与收益需要权衡。

```text
性能优化金字塔（自下而上，成本递增）：
1. 算法与数据结构 —— 复杂度降一个量级，收益最大
2. 向量化 NumPy —— 用 C 循环替代 Python 循环，常有 10-100 倍提升
3. JIT 编译 Numba —— 给纯 Python 数值函数加装饰器即可加速
4. 静态编译 Cython —— 类型声明后编译成 C 扩展
5. 手写 C 扩展 —— 极致性能，但开发维护成本最高

优化铁律：
没有剖析就没有优化 —— 先 profile，别盲目改代码
```

```python
import timeit

# 一个典型的可优化场景：纯 Python 循环求和
def slow_sum(n):
    s = 0
    for i in range(n):
        s += i
    return s

print(timeit.timeit('slow_sum(1_000_000)', globals=globals(), number=10))
```

## timeit

timeit 是精确测量小段代码执行时间的标准库，通过多次重复取最优/平均来消除系统抖动和缓存影响。用它做微基准测试，避免用单次 time.time() 手工计时带来的误差。

```text
timeit 使用要点：
1. 默认重复 100 万次，用 number 参数控制执行次数
2. 默认取最优值（min），可用 repeat 取多次
3. 用 globals=globals() 传入被测函数
4. 字符串语句用 setup 准备环境
5. 适合微基准，别用它测耗时数秒的大任务
```

```python
import timeit
import numpy as np

def python_sum():
    return sum(range(10_000))

def numpy_sum():
    return np.arange(10_000).sum()

# 对比两种实现
t_py = timeit.timeit(python_sum, number=1000)
t_np = timeit.timeit(numpy_sum, number=1000)
print(f'纯 Python: {t_py:.4f}s, NumPy: {t_np:.4f}s')
print(f'NumPy 快 {t_py / t_np:.1f} 倍')

# repeat 多次取稳定性
print(timeit.repeat('sum(range(1000))', number=10000, repeat=3))
```

## cProfile

cProfile 是标准库内置的统计型剖析器，记录每个函数的调用次数、总耗时、自身耗时（不含子调用）。它开销小、能覆盖整个程序，是定位热点函数的第一工具。

```text
cProfile 关键指标：
1. ncalls —— 调用次数（区分总调用/原始调用）
2. tottime —— 自身耗时，不含子函数，定位热点看它
3. cumtime —— 累计耗时，含所有子调用，定位调用链看它
4. percall —— 平均每次调用耗时
5. 输出用 pstats 排序分析，或 dump 后可视化
```

```python
import cProfile
import pstats
import io

def fib(n):
    return n if n < 2 else fib(n - 1) + fib(n - 2)

def workload():
    return fib(25)

pr = cProfile.Profile()
pr.enable()
workload()
pr.disable()

s = io.StringIO()
ps = pstats.Stats(pr, stream=s).sort_stats('cumulative')
ps.print_stats(5)          # 打印累计耗时前 5 名
print(s.getvalue())
```

## line_profiler

line_profiler 是逐行剖析工具，用 @profile 装饰器标记函数，输出每一行的执行时间和命中次数。cProfile 告诉你「哪个函数慢」，line_profiler 告诉你「函数里哪一行慢」。

```text
line_profiler 用法：
1. pip install line-profiler
2. 用 @profile 装饰目标函数（无需 import）
3. kernprof -l -v script.py 运行，自动生成逐行报告
4. 关注 % Time 最高的行 —— 那就是优化点
```

```python
# 文件 demo.py，用 kernprof -l -v demo.py 运行
# @profile 装饰器由 kernprof 注入，正常跑会 NameError

@profile
def process(items):
    total = 0
    for i in items:              # 这行命中次数最多
        total += expensive(i)
    return total

def expensive(x):
    return x * x + 2 * x + 1

if __name__ == '__main__':
    process(range(1000))
```

## memory_profiler

memory_profiler 监控代码的内存占用，逐行报告内存增量，还能用 mprof 生成随时间变化的内存曲线。定位内存泄漏、大对象复制、不必要的中间结果时非常有用。

```text
memory_profiler 用法：
1. pip install memory-profiler
2. @profile 装饰函数，python -m memory_profiler demo.py 运行
3. 关注 Increment 列 —— 每行净增内存
4. mprof run / mprof plot —— 生成内存时间曲线图
```

```python
# 用 python -m memory_profiler demo.py 运行

@profile
def build_lists():
    a = [i for i in range(1_000_000)]        # 约 8 MB
    b = [i * 2 for i in range(1_000_000)]    # 再 8 MB
    c = a + b                                # 复制，又 16 MB
    del a                                    # 释放
    return c

if __name__ == '__main__':
    build_lists()
```

## vectorization

向量化是用「整块数组运算」替代「逐元素 Python 循环」的思想：把循环交给底层 C 实现，避免 Python 解释器的逐条字节码开销。这是 NumPy 快几十上百倍的根本原因。

```text
向量化 vs 循环：
1. Python 循环 —— 每步都要解释器调度、类型检查、边界检查
2. 向量化 —— 一次调用在 C 层完成整个数组运算，无解释器开销
3. 原则 —— 能用数组运算就不用 for 循环，能用广播就不用 reshape
4. 内存 —— 向量化常产生中间数组，可用 out= 参数复用内存
```

```python
import numpy as np
import timeit

data = np.random.randn(1_000_000)

# 非向量化：逐元素循环
def loop_version():
    result = np.empty_like(data)
    for i in range(len(data)):
        result[i] = data[i] * 2 + 1
    return result

# 向量化：整块运算
def vec_version():
    return data * 2 + 1

print(f'循环: {timeit.timeit(loop_version, number=10):.4f}s')
print(f'向量化: {timeit.timeit(vec_version, number=10):.4f}s')
```

## NumPy

NumPy 是 Python 科学计算的基石，ndarray 在连续内存里存同构数据，所有运算都走高度优化的 C/Fortran 代码。性能优化第一步永远是「把纯 Python 计算改写成 NumPy 数组运算」。

```text
NumPy 性能要点：
1. 内存连续 —— C 连续（行优先）访问最快，别跳着读
2. 避免隐式复制 —— 切片是视图，花式索引才复制
3. ufunc —— 加减乘除、sin/exp 都是 C 级向量化函数
4. 减少 Python 交互 —— 一次大操作优于多次小操作
5. dtype —— 用 float32 而非 float64 可省一半内存和带宽
```

```python
import numpy as np
import timeit

n = 1_000_000

# 对比：Python 列表推导 vs NumPy 数组运算
def py_version():
    xs = list(range(n))
    return [x ** 2 for x in xs]

def np_version():
    x = np.arange(n, dtype=np.int64)
    return x ** 2

print(f'列表推导: {timeit.timeit(py_version, number=5):.4f}s')
print(f'NumPy: {timeit.timeit(np_version, number=5):.4f}s')

# 演示视图 vs 复制
a = np.arange(12).reshape(3, 4)
b = a[:2, :]        # 视图，共享内存
b[0, 0] = 999
print(a[0, 0])      # 999，原数组被改
```

## multiprocessing

multiprocessing 用多进程把 CPU 密集任务分发到多个核心并行执行，绕过 GIL 的限制，是纯 Python 计算任务获得「真并行」的主要手段。它和编译优化（Numba/Cython）正交，可以叠加使用：先加速单进程，再并行多进程。

```text
multiprocessing 性能要点：
1. 绕过 GIL —— 每个进程独立解释器，真正跑满多核 CPU
2. Pool.map —— 把任务均匀分发给进程池
3. 进程数 —— 通常设为 CPU 核数，过多反而切换开销大
4. 开销 —— 进程创建和数据序列化有成本，小任务不划算
5. 叠加 —— 先 Numba/NumPy 加速单进程，再用 multiprocessing 并行
```

```python
import multiprocessing as mp
import time

def heavy(n):
    return sum(i * i for i in range(n))

if __name__ == '__main__':
    # 单进程串行
    start = time.perf_counter()
    [heavy(20_000_000) for _ in range(4)]
    t1 = time.perf_counter() - start

    # 4 进程并行
    start = time.perf_counter()
    with mp.Pool(processes=4) as pool:
        pool.map(heavy, [20_000_000] * 4)
    t2 = time.perf_counter() - start

    print(f'单进程: {t1:.2f}s, 4 进程: {t2:.2f}s, 加速比: {t1 / t2:.1f}x')
```

## Numba

Numba 是 JIT 编译器，给纯 Python 数值函数加 @jit 装饰器，首次调用时编译成机器码，后续调用接近 C 速度。它保留 Python 的书写方式，适合有循环、难以向量化的数值计算。

```text
Numba 关键点：
1. @njit 装饰器 —— nopython 模式，编译失败会报错
2. 首次调用有编译延迟，之后缓存
3. 支持 NumPy 数组、math 库、部分 Python 语法
4. 不支持 —— 动态类型、大部分 Python 对象、pandas
5. parallel=True —— 自动并行化可并行的循环
```

```python
import numpy as np
import timeit
from numba import njit

# 纯 Python 的蒙特卡洛估算 π
def monte_carlo(n):
    count = 0
    for _ in range(n):
        x, y = np.random.random(), np.random.random()
        if x * x + y * y <= 1.0:
            count += 1
    return 4 * count / n

@njit
def monte_carlo_numba(n):
    count = 0
    for _ in range(n):
        x, y = np.random.random(), np.random.random()
        if x * x + y * y <= 1.0:
            count += 1
    return 4 * count / n

n = 5_000_000
monte_carlo_numba(1)   # 预热，触发编译
print(f'纯 Python: {timeit.timeit(lambda: monte_carlo(n), number=1):.3f}s')
print(f'Numba: {timeit.timeit(lambda: monte_carlo_numba(n), number=1):.3f}s')
```

## Cython

Cython 是 Python 的超集：在 Python 语法上加静态类型声明，编译成 C 扩展模块。对热点循环声明 cdef 类型能获得接近 C 的速度，同时仍能作为普通 Python 模块 import。

```text
Cython 工作流：
1. 写 .pyx 文件，给循环变量加 cdef int 等类型声明
2. 写 setup.py，用 cythonize 编译成 .so 扩展
3. import 编译后的模块，像普通 Python 一样调用
4. 类型越精确越快 —— 全静态类型接近 C 速度
```

```python
# fib.pyx 的内容（示意，实际需编译）
# def fib_cython(int n):
#     cdef int i
#     cdef long a = 0, b = 1
#     for i in range(n):
#         a, b = b, a + b
#     return a

# setup.py 编译脚本
from setuptools import setup
from Cython.Build import cythonize

setup(ext_modules=cythonize('fib.pyx'))
# 终端执行：python setup.py build_ext --inplace
# 之后 import fib; fib.fib_cython(100000)
```

## native extension

native extension（C 扩展）是性能优化的终极手段：直接用 C/C++ 编写 Python 模块，通过 CPython API 或 pybind11 暴露给 Python。适合极致的数值内核，但开发、调试、维护成本最高。

```text
native extension 方案对比：
1. CPython C API —— 最底层，性能最好，代码最繁琐
2. pybind11 —— 现代 C++ 绑定，简洁，生态主流
3. cffi —— 运行时绑定 C 库，无需编译 C++ 
4. 适用场景 —— 极热的数值内核、需要复用已有 C 库
```

```python
# 用 ctypes 直接调用 C 库，最轻量的 native 调用方式
import ctypes

# 平方根函数 sqrt 在数学库 libm 里，不在 libc，加载正确的库
libm = ctypes.CDLL('libm.so.6')
libm.sqrt.argtypes = [ctypes.c_double]
libm.sqrt.restype = ctypes.c_double
print(libm.sqrt(2.0))   # 1.4142135623730951

# 用 cffi 的思路（示意）：把 C 源码编译后直接调用
from cffi import FFI
ffi = FFI()
ffi.cdef('double sqrt(double);')
C = ffi.dlopen('libm.so.6')
print(C.sqrt(9.0))      # 3.0
```

## 应用场景实战

### 场景一：特征计算逐层加速

```python
import numpy as np
import timeit
from numba import njit

# 任务：对 100 万样本计算 log(1 + x^2) 的累计和
data = np.random.rand(1_000_000)

def pure_python():
    return sum(1.0 / (1.0 + x * x) for x in data)

def numpy_version():
    return np.sum(1.0 / (1.0 + data * data))

@njit
def numba_version(arr):
    total = 0.0
    for x in arr:
        total += 1.0 / (1.0 + x * x)
    return total

numba_version(data[:100])  # 预热
for name, fn in [('纯 Python', lambda: pure_python()),
                 ('NumPy', numpy_version),
                 ('Numba', lambda: numba_version(data))]:
    t = timeit.timeit(fn, number=20)
    print(f'{name}: {t:.4f}s')
```

### 场景二：用 cProfile 定位并修复热点

```python
import cProfile
import pstats
import io

def hot_loop(data):
    result = []
    for x in data:                      # 热点：Python 循环
        result.append(x ** 2 + x + 1)
    return result

def main():
    data = list(range(1_000_000))
    return hot_loop(data)

pr = cProfile.Profile()
pr.enable()
main()
pr.disable()

s = io.StringIO()
pstats.Stats(pr, stream=s).sort_stats('tottime').print_stats(3)
print(s.getvalue())

# 修复：改成 NumPy 向量化
import numpy as np
data = np.arange(1_000_000)
result = data ** 2 + data + 1     # 一行替代整个循环
print(result[-1])
```

## 最佳实践与踩坑记录

### 最佳实践

1. 先 cProfile 找到真正热点，再决定优化哪里，别凭感觉改代码
2. 优先换算法（降低复杂度），收益远大于换语言和换写法
3. 能向量化就向量化：把 Python 循环改写成 NumPy 数组运算
4. 用 timeit 验证每次优化的真实收益，保留前后对比数字
5. 纯数值循环难以向量化时用 Numba 的 @njit，性价比最高
6. 优化到满足需求就停 —— 别过度优化，代码可读性也是成本

### 踩坑记录

```text
坑 1：不 profile 直接优化
结论：花两天优化了一个只占 1% 运行时间的函数，整体毫无提升。
原因：凭直觉优化，没定位到真正的热点函数。
解法：先用 cProfile 排序 tottime，只优化累计耗时排前的函数。

坑 2：用 time.time() 单次计时
结论：同一段代码两次计时结果差好几倍，无法判断优化是否有效。
原因：系统负载、CPU 调度、缓存状态都会干扰单次计时。
解法：用 timeit 多次重复取最优，或 repeat 取多次观察稳定性。

坑 3：Numba 函数首次调用慢误判为性能差
结论：@njit 函数第一次跑比纯 Python 还慢，差点放弃。
原因：首次调用触发 JIT 编译，编译耗时远大于执行耗时。
解法：预热一次再计时，或用 cache=True 缓存编译结果。

坑 4：NumPy 在循环里做小操作
结论：向量化反而更慢。
原因：每个小数组运算都有固定开销，小数组上不如纯 Python 循环。
解法：把多个小操作合并成一次大数组运算，避免频繁进出 C 层。

坑 5：过度依赖内存剖析忽略时间剖析
结论：内存降下来了，但运行时间翻倍。
原因：为省内存反复复制小数组，CPU 开销反而增加。
解法：内存和时间要一起权衡，用 memory_profiler 和 cProfile 联合判断。
```

## 概述

训练工程把「能跑通的模型」变成「可复现、可追踪、可调优、可扩展」的训练系统。它解决的是深度学习实验的三大痛点：结果不可复现、实验难以追溯、GPU 资源浪费。

```text
训练工程的核心关注点：
1. 可复现 —— 固定随机性，同配置同结果
2. 可追踪 —— 记录超参、指标、数据版本、代码版本
3. 可调优 —— 超参搜索、早停、学习率调度
4. 资源高效 —— GPU 利用率、显存优化、分布式
```

```python
# 训练工程的骨架：配置 + 追踪 + 早停 + 断点续训
import torch

cfg = dict(lr=1e-3, epochs=100, batch_size=64, seed=42)
torch.manual_seed(cfg['seed'])          # 固定种子
for epoch in range(cfg['epochs']):
    train_loss = train_one_epoch()
    val_loss = validate()
    log(epoch, train_loss, val_loss)    # 记录到实验追踪
    if early_stop(val_loss): break       # 早停
    save_checkpoint(epoch, val_loss)     # 定期保存
```

## Dataset Versioning

数据版本化让「训练用的哪份数据」可追溯——数据会变（增删、修正标注），不记录版本就无法复现结果。

```text
数据版本化的手段：
1. DVC —— Git 管代码，DVC 管数据，dvc add 数据 + dvc push 远端
2. 哈希指纹 —— 记录数据集的 md5/sha256，变化即发现
3. 数据快照 —— 每次训练锁定数据集的不可变快照
4. 元数据 —— 记录下载源、日期、预处理脚本版本
```

```bash
# DVC 示例
dvc init
dvc add data/train.csv       # 追踪数据，生成 .dvc 文件
git add data/train.csv.dvc   # 提交哈希指针
dvc push                     # 数据推到远端存储
```

## Reproducibility

可复现 = 同代码 + 同数据 + 同随机性 → 同结果。缺一不可，其中随机性是最大的坑。

```text
影响复现的随机源：
1. 随机初始化 —— 权重初始化
2. 数据打乱 —— DataLoader 的 shuffle
3. Dropout / 数据增强 —— 训练中的随机操作
4. cuDNN —— 卷积算法选择的不确定性
5. 浮点累加顺序 —— 多卡/多线程的不可控顺序
```

```python
import torch, random, numpy as np

def set_seed(seed=42):
    random.seed(seed)
    np.random.seed(seed)
    torch.manual_seed(seed)
    torch.cuda.manual_seed_all(seed)
    torch.backends.cudnn.deterministic = True   # 确定性卷积
    torch.backends.cudnn.benchmark = False      # 关闭自动调优
```

## Seed

固定种子是复现的基础，但「固定 seed ≠ 完全可复现」，还要控制其他随机源和硬件差异。

```text
Seed 的要点：
1. 三层都要固定 —— Python random / NumPy / PyTorch（CPU+CUDA）
2. deterministic=True —— 让 cuDNN 用确定性算法（可能变慢）
3. 多卡也要 seed —— manual_seed_all
4. 生产复现 —— 记录 seed 到配置里，别写死
```

## Experiment Tracking

实验追踪记录每次训练的配置、指标、产物，让「哪个实验最好、怎么跑出来的」一目了然。

```text
常用工具：
1. TensorBoard —— 轻量，曲线 + 图可视化
2. Weights & Biases (W&B) —— 云托管，团队协作、超参对比
3. MLflow —— 自托管，实验 + 模型注册 + 部署一条龙
4. 手写 JSON —— 最简方案，把配置和指标 dump 成 json
```

## Early Stopping

早停在验证集指标不再提升时停止训练，防止过拟合、节省算力。

```python
class EarlyStopping:
    def __init__(self, patience=5, min_delta=0.0):
        self.patience = patience
        self.min_delta = min_delta
        self.best = float('inf')
        self.counter = 0

    def __call__(self, val_loss):
        if val_loss < self.best - self.min_delta:
            self.best = val_loss
            self.counter = 0
            return False          # 有提升，继续训
        self.counter += 1
        return self.counter >= self.patience   # 连续 patience 次没提升，停
```

```text
Early Stopping 的要点：
1. 监控验证集 —— 不是训练集
2. patience —— 允许几次「没提升」，太小早停太早，太大失去意义
3. 保存 best —— 早停时恢复最佳权重，而不是用最后一步的
4. 指标 —— 分类看 val_acc/val_loss，回归看 val_mse
```

## Checkpoint

Checkpoint 断点续训 + 保存最佳模型，避免训练中断前功尽弃。

```python
# 保存
torch.save({
    'epoch': epoch,
    'model': model.state_dict(),
    'optimizer': optimizer.state_dict(),
    'scheduler': scheduler.state_dict(),
    'best_val': best_val,
    'config': cfg,
}, 'ckpt.pt')

# 恢复续训
ckpt = torch.load('ckpt.pt')
model.load_state_dict(ckpt['model'])
optimizer.load_state_dict(ckpt['optimizer'])
start_epoch = ckpt['epoch'] + 1
```

```text
Checkpoint 策略：
1. best.pt —— 保存验证指标最优的权重（用于部署）
2. last.pt —— 保存最新状态（用于续训）
3. 定期保存 —— 每 N epoch 或每个 epoch 存一个
4. 保留策略 —— 只留最近 K 个，别占满磁盘
```

## Hyperparameter

超参调优是训练工程的核心循环：网格/随机/贝叶斯搜索，配合追踪和早停高效探索。

```text
超参搜索策略：
1. 网格搜索 —— 穷举所有组合，空间小可用
2. 随机搜索 —— 随机采样，比网格更高效（大部分超参是低敏感度的）
3. 贝叶斯优化 —— 用历史结果建模，智能选下一组
4. Optuna / Ray Tune —— 主流框架，支持剪枝
```

```python
import optuna

def objective(trial):
    lr = trial.suggest_float('lr', 1e-5, 1e-1, log=True)
    hidden = trial.suggest_int('hidden', 32, 512)
    # 训练并返回验证指标
    return train_and_eval(lr=lr, hidden=hidden)

study = optuna.create_study(direction='minimize')
study.optimize(objective, n_trials=50)
print(study.best_params)
```

## GPU Utilization

GPU 利用率是训练效率的直观指标：利用率低意味着数据加载/CPU 是瓶颈。

```bash
# 实时看 GPU 利用率
nvidia-smi
# 每 1 秒刷新
watch -n 1 nvidia-smi
```

```text
GPU 利用率低的常见原因：
1. 数据加载慢 —— num_workers 太少，GPU 空转等数据
2. batch 太小 —— 计算量不足，GPU 喂不饱
3. 频繁 CPU-GPU 同步 —— .item()/.cpu()/print 打断流水线
4. 单卡跑小模型 —— 模型太小，GPU 算力浪费
```

## Memory Optimization

显存优化让有限显存训更大的模型、更大的 batch。

```text
显存优化手段（从易到难）：
1. 减小 batch size —— 最直接，但可能影响收敛
2. AMP 混合精度 —— 激活存半精度，显存减半
3. 梯度累积 —— 多个小 batch 累加梯度再更新，等效大 batch
4. 梯度检查点（activation checkpoint）—— 不存中间激活，反向时重算
5. 优化器状态分片（如 ZeRO/FSDP）—— 分片优化器状态到多卡
```

```python
# 梯度累积：模拟 batch_size=256（实际每次 64）
accum_steps = 4
for i, (x, y) in enumerate(loader):
    loss = model(x) / accum_steps
    loss.backward()
    if (i + 1) % accum_steps == 0:
        optimizer.step()
        optimizer.zero_grad()
```

## 应用场景实战

### 场景一：可复现的训练脚本骨架

```python
import torch, random, numpy as np

def train(cfg):
    set_seed(cfg['seed'])
    model = build_model(cfg)
    optimizer = torch.optim.AdamW(model.parameters(), lr=cfg['lr'])
    best = float('inf')
    for epoch in range(cfg['epochs']):
        train_loss = train_one_epoch(model, optimizer)
        val_loss = validate(model)
        if val_loss < best:
            best = val_loss
            torch.save(model.state_dict(), 'best.pt')
        log({'epoch': epoch, 'train': train_loss, 'val': val_loss})
    return best
```

### 场景二：显存不足的排查与优化

```python
# 1. 查显存占用
print(torch.cuda.memory_allocated() / 1024**2, 'MB')
print(torch.cuda.max_memory_allocated() / 1024**2, 'MB')

# 2. 省显存：梯度清空用 set_to_none
optimizer.zero_grad(set_to_none=True)

# 3. 训练完释放缓存
torch.cuda.empty_cache()
```

## 最佳实践与踩坑记录

### 最佳实践

1. 所有实验统一入口：一份 config + 一个 train 脚本，别每次改代码
2. 固定 seed + deterministic，复现是工程底线
3. 训练必配早停 + best checkpoint，防过拟合 + 防中断
4. 实验追踪记录 config + 指标 + 数据/代码版本，别只记 loss
5. GPU 利用率长期低于 60% 先查数据加载，别急着上分布式
6. 显存不够先 AMP + 梯度累积，再考虑梯度检查点/FSDP

### 踩坑记录

```text
坑 1：只固定 torch seed 没固定 numpy/random
结论：数据增强、采样顺序仍随机，结果还是不可复现。
原因：NumPy 和 Python random 有自己的随机状态，没一并固定。
解法：set_seed 里同时固定 random、numpy、torch（CPU+CUDA）。

坑 2：早停用了训练集指标
结论：早停失效，模型持续过拟合却不停止。
原因：训练集 loss 一直在降，永远不会触发早停。
解法：早停监控验证集指标，训练集只用来更新参数。

坑 3：GPU 利用率高但训练慢
结论：显存没满、利用率显示 100%，但吞吐就是上不去。
原因：利用率高可能是频繁的小 kernel 切换，不是有效计算。
解法：用 torch.profiler 看算子耗时，找真正的瓶颈。

坑 4：频繁 .item() / print 拖慢训练
结论：每步 print loss 或 .item()，训练慢 2-3 倍。
原因：.item() 触发 CPU-GPU 同步，打断异步流水线。
解法：loss 累积后再 .item()，或每 N 步才同步打印一次。

坑 5：改数据没改版本号
结论：同一份配置跑出不同结果，排查半天发现是数据变了。
原因：数据更新了但没记录版本，无法定位差异。
解法：用 DVC 或哈希指纹做数据版本化，训练记录数据版本。
```

## 概述

计算机视觉的起点是把物理世界的光信号数字化成「图像」——一个由像素组成的二维数组。理解像素、分辨率、通道、颜色空间这些底层概念，是后面所有 OpenCV 操作（读取、滤波、边缘、特征）的基础，很多 bug 追到底都是「通道顺序错了」或「dtype 不对」这类低级问题。

```text
计算机视觉基础的核心概念：
1. 图像 = 二维像素数组，每个像素 = 一个或几个数值（通道）
2. 分辨率决定信息量，通道决定颜色表达，位深决定精度
3. 颜色空间是同一份数据的多种解释，转换不改信息、只改坐标
4. 计算机里图像永远是数组，显示是数组的可视化
```

```python
import numpy as np

# 一张图像本质就是 NumPy 数组
h, w, c = 480, 640, 3
img = np.zeros((h, w, c), dtype=np.uint8)   # 全黑图：480 高 x 640 宽 x 3 通道
print(img.shape, img.dtype)                  # (480, 640, 3) uint8
```

## Image

图像（Image）在计算机里就是按行、列组织的像素矩阵。灰度图是二维数组（H, W），彩色图是三维数组（H, W, C），C 是通道数。OpenCV 用 NumPy 数组承载图像，因此所有 NumPy 的索引、切片、运算都能直接作用在图像上。

```text
图像的数据结构：
1. 灰度图 —— shape (H, W)，每个元素 0~255
2. 彩色图 —— shape (H, W, C)，C 通常为 3 或 4
3. 约定 —— OpenCV 是 (高, 宽, 通道)，PIL 是 (宽, 高)，别搞混
```

```python
import numpy as np

# 构造一张 3x4 的灰度图（8 行画成 3x4 方便看）
gray = np.array([[0, 64, 128, 255],
                 [32, 96, 160, 224],
                 [16, 80, 144, 208]], dtype=np.uint8)
print(gray.shape)          # (3, 4)
print(gray[0, 0], gray[0, 3])   # 左上角 0，右上角 255
```

## Pixel

像素（Pixel）是图像的最小单元，对应传感器上一个感光点的采样值。灰度像素是一个标量（亮度），彩色像素是一个向量（各通道的强度）。像素值范围由位深决定，8 位图是 0~255，0 是黑、255 是白（灰度）/ 最大强度（彩色）。

```text
像素的两种形态：
1. 标量像素 —— 灰度图，一个数值表示亮度
2. 向量像素 —— 彩色图，(B, G, R) 或 (R, G, B) 三个分量
```

```python
import numpy as np

# 访问与修改单个像素
img = np.zeros((2, 2, 3), dtype=np.uint8)
img[0, 0] = [255, 0, 0]     # OpenCV 里是 BGR：蓝色
img[0, 1] = [0, 255, 0]     # 绿色
img[1, 0] = [0, 0, 255]     # 红色
img[1, 1] = [255, 255, 255] # 白色
print(img[0, 0])            # [255   0   0] → B=255 蓝色
```

## Resolution

分辨率（Resolution）是图像的宽高像素数，如 1920x1080 表示 1920 列、1080 行。分辨率越高信息越丰富，但内存和处理开销也越大（内存 = 宽 x 高 x 通道 x 字节/像素）。图像处理任务里，分辨率直接影响算法耗时和可检测目标的尺寸下限。

```text
分辨率相关计算：
1. 像素总数 = W * H
2. 内存占用 = W * H * C * bytes_per_pixel
3. 8 位 3 通道 1920x1080 ≈ 1920*1080*3 = 6.2 MB
```

```python
import numpy as np

# 不同分辨率的内存估算
def mem_bytes(w, h, c=3, depth=1):
    return w * h * c * depth

print(mem_bytes(1920, 1080))   # 6220800 ≈ 5.9 MB
print(mem_bytes(3840, 2160))   # 4K 是 1080p 的 4 倍像素
```

## Channel

通道（Channel）是图像里每个像素的独立分量。灰度图 1 个通道，RGB/BGR 图 3 个通道，带透明度的 RGBA/BGRA 图 4 个通道，多光谱遥感图可以有几十个通道。每个通道本质是一张独立的二维数组，叠加起来才构成彩色图。

```text
常见通道数：
1. 1 通道 —— 灰度图、二值掩码（mask）
2. 3 通道 —— RGB / BGR 彩色图
3. 4 通道 —— RGBA / BGRA，多一个 Alpha 透明度
4. 多通道 —— 高光谱 / 特征图（CNN 里的 feature map）
```

```python
import numpy as np

# 通道拆分与合并
img = np.zeros((2, 2, 3), dtype=np.uint8)
img[0, 0] = [10, 20, 30]      # B=10, G=20, R=30
b, g, r = img[..., 0], img[..., 1], img[..., 2]   # 拆出三个通道
print(b[0, 0], g[0, 0], r[0, 0])   # 10 20 30
merged = np.stack([b, g, r], axis=-1)            # 合并回 (2,2,3)
print(merged[0, 0])             # [10 20 30]
```

## 颜色空间：RGB 与 BGR

RGB 是加色模型，用红绿蓝三原色的强度叠加出颜色，是显示器、相机的自然表达。BGR 是 OpenCV 的默认通道顺序（历史原因，源自早期 BGR 位图格式）。同一份像素数据，用 RGB 还是 BGR 解释颜色会完全颠倒——这是 OpenCV 最常见的一类 bug 来源。

```text
RGB vs BGR 的关键：
1. RGB —— 通道顺序 (R, G, B)，PIL/matplotlib/大多数库默认
2. BGR —— 通道顺序 (B, G, R)，OpenCV 的 imread 默认
3. 红色在 RGB 是 (255,0,0)，在 BGR 是 (0,0,255)
```

```python
import cv2
import numpy as np

# OpenCV 读进来是 BGR，PIL/matplotlib 是 RGB
bgr = np.zeros((1, 1, 3), dtype=np.uint8)
bgr[0, 0] = [0, 0, 255]        # 这是「红色」在 BGR 下的写法
rgb = cv2.cvtColor(bgr, cv2.COLOR_BGR2RGB)   # 转成 RGB
print(bgr[0, 0], '->', rgb[0, 0])   # [0 0 255] -> [255 0 0]
```

## 颜色空间：HSV 与 HSL

HSV/HSL 把颜色从「三原色强度」换成「色相 Hue、饱和度 Saturation、亮度 Value/Lightness」的柱状模型，更贴合人眼的感知方式。色相决定是什么颜色（0~360°），饱和度决定颜色纯度，亮度决定明暗。因为颜色和亮度解耦，基于 HSV 的调色、分割比 RGB 直观得多。

```text
HSV 与 HSL 的区别：
1. HSV —— V=Value，最亮的颜色饱和度最高
2. HSL —— L=Lightness，白色在 L=100%，纯色在 L=50%
3. OpenCV 的 HSV 取值范围：H∈[0,179]，S,V∈[0,255]
```

```python
import cv2
import numpy as np

# 纯红在 HSV 下的坐标（OpenCV H 是 0~179，红色 H≈0 或 179）
red_bgr = np.uint8([[[0, 0, 255]]])
hsv = cv2.cvtColor(red_bgr, cv2.COLOR_BGR2HSV)
print(hsv)   # [[[  0 255 255]]] → H=0 红，S=255 满饱和，V=255 最亮
```

## 颜色空间：LAB 与 YUV

LAB 是感知均匀的颜色空间：L 是亮度，A 轴绿-红，B 轴蓝-黄，A、B 通道与亮度完全解耦，常用来做颜色校正、肤色检测。YUV 把亮度 Y 和色度 U、V 分离，是视频编码（如 YUV420）的基础——人眼对亮度敏感、对色度不敏感，所以可以对色度降采样省带宽。

```text
LAB 与 YUV 的用途：
1. LAB —— 感知均匀，做颜色距离、白平衡、颜色迁移
2. YUV —— 亮度色度分离，视频压缩与传输的标准格式
3. 两者都实现「亮度与颜色解耦」，适合对亮度/颜色分别处理
```

```python
import cv2
import numpy as np

img_bgr = np.zeros((1, 2, 3), dtype=np.uint8)
img_bgr[0, 0] = [0, 0, 255]      # 红
img_bgr[0, 1] = [0, 255, 0]      # 绿
lab = cv2.cvtColor(img_bgr, cv2.COLOR_BGR2LAB)
yuv = cv2.cvtColor(img_bgr, cv2.COLOR_BGR2YUV)
print('LAB:', lab[0])    # L 相近，a/b 轴一正一负区分红绿
print('YUV:', yuv[0])
```

## Grayscale

灰度（Grayscale）图只有一个亮度通道，把彩色信息丢弃、只保留明暗。转换不是简单取平均值，而是按人眼对三原色的敏感度加权：Y = 0.299R + 0.587G + 0.114B。很多算法（边缘检测、模板匹配）在灰度图上跑，既省计算又去除了颜色噪声。

```text
灰度化的加权公式：
1. 亮度加权 —— Y = 0.299R + 0.587G + 0.114B（ITU-R BT.601）
2. 简单平均 —— (R+G+B)/3，丢失感知亮度信息，不推荐
3. 单通道取用 —— 直接取某通道，只在该通道有意义时用
```

```python
import numpy as np

# 手写亮度加权灰度化
img = np.array([[[100, 150, 200]]], dtype=np.uint8)   # B=100 G=150 R=200
gray = 0.114 * img[..., 0] + 0.587 * img[..., 1] + 0.299 * img[..., 2]
print(gray)   # ≈ 0.114*100 + 0.587*150 + 0.299*200 ≈ 159.3

import cv2
gray_cv = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)
print(gray_cv)   # [[159]]，与加权公式一致
```

## Alpha

Alpha 通道是透明度信息，取值 0（全透明）到 255（不透明）。RGBA/BGRA 四通道图在图像合成、UI 渲染、抠图里用，前景按 Alpha 与背景混合：out = fg*α + bg*(1-α)。OpenCV 的 cvtColor 处理带 Alpha 图时要用对应的 COLOR_BGRA2BGR 而非 COLOR_BGR2BGR。

```text
Alpha 混合公式：
1. out = fg * (α/255) + bg * (1 - α/255)
2. α=255 → 完全取前景；α=0 → 完全取背景
```

```python
import numpy as np

# Alpha 混合：把半透明前景叠到背景上
fg = np.array([[[0, 0, 255, 128]]], dtype=np.uint8)    # 红色，α=128 半透明
bg = np.array([[[255, 255, 255, 255]]], dtype=np.uint8) # 白色背景
a = fg[..., 3:] / 255.0
out = fg[..., :3] * a + bg[..., :3] * (1 - a)
print(out)   # ≈ [[127 127 255]] 红色与白色各半 → 粉红（R 通道保持 255，B/G 各半）
```

## Bit Depth

位深（Bit Depth）是每个通道每个像素用多少比特存储，决定像素值的精度范围。8 位是 0~255（uint8），16 位是 0~65535（uint16），32 位浮点是连续值。医学影像、HDR 常是 16 位或浮点，普通相机是 8 位。位深不够会出「色带」（banding），位深过高则吃内存。

```text
常见位深与范围：
1. uint8 —— 0~255，最普遍
2. uint16 —— 0~65535，医疗 / 深度图
3. float32 —— 任意实数，中间计算、特征图、HDR
```

```python
import numpy as np

# 8 位溢出：255 + 1 会回绕到 0
a = np.array([[255]], dtype=np.uint8)
print((a + 1))         # [[0]] 溢出回绕
print(np.clip(a.astype(np.int16) + 1, 0, 255))   # 用更大位深 + clip 防溢出

# 8 位 → 浮点归一化
img = np.array([[0, 128, 255]], dtype=np.uint8)
print(img.astype(np.float32) / 255.0)   # [0. 0.502 1.]
```

## Dynamic Range

动态范围（Dynamic Range）是图像能表达的亮度跨度，即最亮与最暗之比。8 位图只有 256 级、约 48dB，HDR 图用浮点或对数编码可达十几个 EV。相机在逆光场景拍高动态范围场景时会丢细节（过曝或欠曝），HDR 技术就是多曝光合成来扩展动态范围。

```text
动态范围的关键：
1. 8 位图动态范围 ≈ 20*log10(256) ≈ 48 dB
2. 逆光/夜景场景超出传感器动态范围 → 过曝或欠曝
3. 处理高动态范围图时别用 uint8 存中间结果
```

```python
import numpy as np

# 多曝光合成 HDR 的思路：不同曝光取各自有效的亮度区间
exposures = [np.array([[10, 20, 250]], dtype=np.float32),   # 暗部清晰
             np.array([[100, 120, 200]], dtype=np.float32)] # 亮部清晰
hdr = np.mean(exposures, axis=0)
print(hdr)   # 平均融合，得到扩展后的亮度表达
```

## 应用场景实战

### 场景一：颜色分割（HSV 阈值提取目标区域）

```python
import cv2
import numpy as np

# 用 HSV 提取红色区域（OpenCV 红色 H 在 0 和 180 附近，需两段）
img = np.zeros((100, 100, 3), dtype=np.uint8)
cv2.circle(img, (30, 30), 15, (0, 0, 255), -1)    # 红色圆（BGR）
cv2.circle(img, (70, 70), 15, (0, 255, 0), -1)    # 绿色圆

hsv = cv2.cvtColor(img, cv2.COLOR_BGR2HSV)
mask1 = cv2.inRange(hsv, (0, 100, 100), (10, 255, 255))
mask2 = cv2.inRange(hsv, (170, 100, 100), (180, 255, 255))
mask = cv2.bitwise_or(mask1, mask2)               # 红色区域掩码
print('红色像素数:', np.sum(mask > 0))             # 约等于红圆面积
```

### 场景二：灰度化 + 位深转换做图像标准化

```python
import cv2
import numpy as np

# 读图 → 灰度 → 归一化到 [0,1] 浮点，喂给模型前必须做
img = np.random.randint(0, 256, (64, 64, 3), dtype=np.uint8)
gray = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)      # 8 位灰度
normalized = gray.astype(np.float32) / 255.0      # 归一化
print('dtype:', gray.dtype, '→', normalized.dtype)
print('范围:', gray.min(), gray.max(), '→', normalized.min(), normalized.max())
```

## 最佳实践与踩坑记录

### 最佳实践

1. 读图后第一时间确认 `img.shape` 和 `img.dtype`，再决定后续处理
2. OpenCV 默认 BGR，和 PIL/matplotlib 混用时先 cvtColor，别混着显示
3. 边缘、模板匹配、特征检测都在灰度图上跑，先转灰度省时间
4. 颜色分割用 HSV，不用 RGB——阈值直观且抗光照
5. 中间计算用 float32，最后一步再转回 uint8，避免溢出回绕
6. 归一化到 [0,1] 或零均值是喂深度学习模型前的固定动作

### 踩坑记录

```text
坑 1：BGR 和 RGB 混用导致颜色颠倒
结论：OpenCV 读进来是 BGR，直接用 matplotlib 显示脸是蓝的。
原因：两库通道顺序约定不同，imread 不自动转 RGB。
解法：显示前 cv2.cvtColor(img, cv2.COLOR_BGR2RGB)。

坑 2：uint8 加法溢出回绕
结论：255 + 1 变成 0，图像出现奇怪的黑色斑块。
原因：uint8 无符号溢出会模 256 回绕，不是饱和。
解法：先 astype 到 int16/float32 计算，再 np.clip 到 [0,255] 转回 uint8。

坑 3：OpenCV HSV 的 H 范围记错
结论：按 0~360 设 H 阈值，永远选不中目标。
原因：OpenCV 里 H 被缩到 0~179（360 的一半）。
解法：红色这类跨 0° 的颜色，H 阈值要分成 [0,10] 和 [170,180] 两段合并。

坑 4：忽略位深直接把 16 位图当 8 位用
结论：医学影像/深度图直接显示一片黑或一片白。
原因：uint16 值域 0~65535，显示和多数算子按 8 位解释。
解法：先归一化缩放（如 /255 或 cv2.normalize）再处理。

坑 5：Alpha 图用错转换函数
结论：RGBA 图用 COLOR_BGR2GRAY 之类错配，形状对不上报错。
原因：带 Alpha 的图是 4 通道，转换函数要带 A（BGRA2BGR/BGRA2RGBA）。
解法：先确认通道数，4 通道用带 A 的 cvtColor 编码。
```

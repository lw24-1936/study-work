## 概述

OCR（Optical Character Recognition，光学字符识别）把图像中的文字转成可编辑的文本。经典方案是两阶段：先「文字检测」定位文本区域，再「文字识别」把区域内容识别成字符序列。识别的核心难点在于「序列对齐」——图像里的字符位置与标签序列长度不对齐，CTC 用「插入空白符」的巧妙方式解决了这个问题。PaddleOCR 等一体化工具把整套流水线封装成易用产品，布局分析（Layout Analysis）和 Document AI 则把 OCR 推向整页文档的结构化理解。

```text
OCR 的技术栈：
1. 文字检测 —— 定位文本框（DB、EAST、CTPN）
2. 文字识别 —— 识别文本内容（CRNN、Transformer OCR）
3. 序列对齐 —— CTC 解决不定长序列与标签的对齐
4. 一体化 —— PaddleOCR 提供开箱即用的检测+识别+方向分类
5. 文档理解 —— 布局分析 + 版面重建 + 结构化抽取（Document AI）
```

```python
import cv2

# 文字检测（EAST 模型）的 OpenCV DNN 调用示意

img = cv2.imread('document.png')

print(f'文字检测得分图: {scores.shape}, 几何输出: {geometry.shape}')
```

## Text Detection

文字检测是 OCR 的第一步：在图像中定位所有文字区域，输出文本框（矩形或四边形）。与通用目标检测不同，文字天然是细长、密集、任意方向的，因此检测器要么用「基于分割」的方法（DBNet 预测收缩的文本核心，再扩张回完整框），要么用「基于回归」的方法（EAST、CTPN）。DBNet 是目前工业界的主流，速度快且对弯曲文本有变体支持。

```text
文字检测的三大流派：
1. 基于回归 —— EAST、CTPN 直接回归文本框
2. 基于分割 —— DBNet 预测文本区域概率图 + 阈值图，后处理扩张
3. 弯曲文本 —— 用 Bezier 曲线等表达任意形状文本

关键后处理：把概率图转成连通区域 → 拟合四边形/多边形框
```

```python
import numpy as np

def probability_map_to_boxes(prob_map, threshold=0.3):
    """分割式文字检测后处理：概率图 → 文本框（简化）"""
    binary = (prob_map > threshold).astype(np.uint8)
    # 连通域分析（OpenCV 提供）
    num_labels, labels, stats, _ = cv2.connectedComponentsWithStats(binary, connectivity=8)
    boxes = []
    for i in range(1, num_labels):       # 跳过背景 label 0
        x, y, w, h = stats[i, 0], stats[i, 1], stats[i, 2], stats[i, 3]
        if w * h > 50:                   # 过滤过小噪声区域
            boxes.append((x, y, w, h))
    return boxes

prob_map = np.random.rand(100, 100)      # 模拟文字概率图
boxes = probability_map_to_boxes(prob_map)
print(f'检测到文本框数: {len(boxes)}')
```

## Text Recognition

文字识别是把检测出的文本区域裁剪图识别成字符序列。它本质是「序列到序列」问题：图像特征序列（宽度方向）映射到字符序列。经典 CRNN 用 CNN 提特征 + RNN 建模序列上下文 + CTC 做对齐解码；Transformer 时代则用自注意力替代 RNN（如 TrOCR）。识别器需要处理不同字体、字号、模糊、光照，以及中英文、标点等大字符集。

```text
文字识别的核心流程：
1. 特征提取 —— CNN 把文本条图编码成宽度方向的特征序列
2. 序列建模 —— RNN / Transformer 建模字符间上下文依赖
3. 对齐解码 —— CTC 贪心/束搜索，或自回归解码

输出：不定长字符序列（中英文、数字、标点）
```

```python
import torch
import torch.nn as nn

class TextRecognitionBackbone(nn.Module):
    """CRNN 识别器的 CNN 特征提取部分"""
    def __init__(self, input_channels=3, output_channels=256):
        super().__init__()
        self.cnn = nn.Sequential(
            nn.Conv2d(input_channels, 64, 3, stride=1, padding=1), nn.ReLU(),
            nn.MaxPool2d((2, 2)),                              # 高度减半
            nn.Conv2d(64, 128, 3, stride=1, padding=1), nn.ReLU(),
            nn.MaxPool2d((2, 2)),
            nn.Conv2d(128, output_channels, 3, stride=1, padding=1), nn.ReLU(),
            nn.MaxPool2d((2, 1)),                              # 只压高度，保留宽度
        )
    def forward(self, x):
        return self.cnn(x)

# 输入文本条图像 [B, 3, 32, 100]（高 32，宽可变）
x = torch.randn(2, 3, 32, 100)
feat = TextRecognitionBackbone()(x)
print(f'特征序列: {feat.shape}')   # [2, 256, 4, 25] → 宽度方向 25 个时间步
```

## CTC

CTC（Connectionist Temporal Classification）是解决「不定长序列对齐」的核心技术：识别网络的输出长度（特征序列宽度）与标签字符串长度往往不一致，且不知道每个字符对应哪几帧。CTC 引入一个「空白符 blank」，允许重复字符和空白穿插，用动态规划（前向-后向算法）枚举所有能折叠成标签的对齐路径来算损失。解码时用贪心（去重复 + 去 blank）或束搜索。

```text
CTC 的核心思想：
1. blank 符 —— 引入空白符分隔重复字符
2. 多对一 —— 多个对齐路径折叠成同一个标签
3. 动态规划 —— 前向-后向算法高效求和所有路径概率
4. 解码 —— 贪心：去相邻重复 + 去 blank；束搜索更优

关键：输出时间步 T 必须 ≥ 标签长度（否则无法对齐）
```

```python
import torch
import torch.nn.functional as F

def ctc_decode(log_probs, blank=0):
    """CTC 贪心解码：每步取最大概率字符，去重复 + 去 blank"""
    # log_probs: [T, C]，每时间步的字符概率分布
    best = log_probs.argmax(dim=-1)      # [T] 每步最优字符
    result = []
    prev = blank
    for idx in best.tolist():
        if idx != prev:                   # 去相邻重复
            if idx != blank:              # 去 blank
                result.append(idx)
        prev = idx
    return result

T, C = 10, 30
log_probs = torch.randn(T, C).log_softmax(dim=-1)
decoded = ctc_decode(log_probs)
print(f'CTC 贪心解码结果（字符 id 序列）: {decoded}')
```

```python
# CTC 损失计算（PyTorch 原生支持）
input_lengths = torch.tensor([T, T])                     # 每个样本的输出时间步
targets = torch.tensor([[1, 5, 9], [2, 4]])              # 真实字符序列（不含 blank）
target_lengths = torch.tensor([3, 2])
loss = F.ctc_loss(log_probs.unsqueeze(0).repeat(2, 1, 1), targets, input_lengths, target_lengths)
print(f'CTC 损失: {loss.item():.3f}')
```

## CRNN

CRNN（Convolutional Recurrent Neural Network）是文字识别的经典架构，由「CNN + RNN + CTC」三段组成：CNN 把文本条图像编码成宽度方向的特征序列，RNN（通常用双向 LSTM）建模字符间的序列上下文，最后 CTC 做对齐与解码。它在 2015 年提出后成为业界事实标准，至今仍是很多 OCR 系统的默认识别器，简单、稳定、训练快。

```text
CRNN 三段式结构：
1. CNN —— 提特征，输出 [C, H', W'] 特征图，压平为 W' 个时间步
2. BiLSTM —— 双向建模字符序列上下文依赖
3. CTC —— 对齐 + 解码，无需逐字符标注位置

优势：无需字符级位置标注，直接端到端训练整串文本
```

```python
import torch
import torch.nn as nn

class CRNN(nn.Module):
    """CRNN 完整结构示意：CNN + BiLSTM + 分类头"""
    def __init__(self, num_classes, hidden_size=256):
        super().__init__()
        self.cnn = TextRecognitionBackbone(output_channels=256)
        self.lstm = nn.LSTM(256, hidden_size, num_layers=2, bidirectional=True, batch_first=False)
        self.fc = nn.Linear(hidden_size * 2, num_classes)

    def forward(self, x):
        feat = self.cnn(x)                       # [B, 256, H', W']
        feat = feat.squeeze(2)                   # [B, 256, W'] 去掉高度维
        feat = feat.permute(2, 0, 1)             # [W', B, 256] 时间步优先
        out, _ = self.lstm(feat)                 # [W', B, 512]
        logits = self.fc(out)                    # [W', B, num_classes]
        return logits.permute(1, 0, 2)           # [B, W', num_classes]

crnn = CRNN(num_classes=5000)
x = torch.randn(2, 3, 32, 100)
logits = crnn(x)
print(f'CRNN 输出: {logits.shape}')   # [2, W', 5000]
```

## Transformer OCR

Transformer OCR 用自注意力替代 RNN 来建模文字序列，代表是微软的 TrOCR——完全基于 Transformer 的编码器-解码器结构：图像编码器（ViT 或 CNN）把文本条编码成视觉 token，文本解码器自回归地逐字符生成。相比 CRNN，Transformer 能更好地捕捉长距离依赖和上下文，且可以天然利用大规模文本预训练，中英文混合场景表现更好。

```text
TrOCR 的结构（编码器-解码器）：
1. 图像编码器 —— ViT 把文本条图切成 patch，输出视觉特征
2. 文本解码器 —— Transformer 解码器，自回归生成字符
3. 预训练 —— 大量合成文本行数据，提升泛化

优势：更强的上下文建模、更大的并行与容量、端到端
```

```python
import torch
import torch.nn as nn

class TransformerOCRDecoder(nn.Module):
    """自回归文本解码器示意：逐步生成字符"""
    def __init__(self, d_model=256, num_classes=5000):
        super().__init__()
        self.embed = nn.Embedding(num_classes, d_model)
        self.pos = nn.Embedding(128, d_model)
        self.decoder = nn.TransformerDecoder(
            nn.TransformerDecoderLayer(d_model, nhead=8, batch_first=True), num_layers=3)
        self.head = nn.Linear(d_model, num_classes)

    def forward(self, tgt_tokens, memory, tgt_mask=None):
        # tgt_tokens: [B, L]，memory 为图像编码器输出
        tgt = self.embed(tgt_tokens) + self.pos(torch.arange(tgt_tokens.shape[1]))
        out = self.decoder(tgt.unsqueeze(1).transpose(0, 1), memory)
        return self.head(out)

dec = TransformerOCRDecoder()
tgt = torch.randint(0, 5000, (2, 10))          # 已生成的前缀
memory = torch.randn(2, 64, 256)               # 图像编码特征
logits = dec(tgt, memory)
print(f'Transformer OCR 解码输出: {logits.shape}')
```

## PaddleOCR

PaddleOCR 是百度开源的一体化 OCR 工具集，把「检测 + 方向分类 + 识别」封装成开箱即用的流水线，支持中英文等 80+ 语言，提供大量预训练模型。它的三阶段结构是：文字检测（DBNet）→ 方向分类（判断文本是否倒置，纠正 180°）→ 文字识别（CRNN/SVTR 等）。一行代码即可完成整图 OCR，是中文 OCR 场景的事实标准。

```text
PaddleOCR 的三阶段流水线：
1. 检测 —— DBNet 定位文本区域
2. 方向分类 —— 判断文本行方向，纠正旋转 180° 的文本
3. 识别 —— CRNN / SVTR 识别字符序列

特点：开箱即用、多语言、预训练丰富、支持服务化部署
```

```python
from paddleocr import PaddleOCR

# 一行初始化 + 识别（首次会下载模型）
ocr = PaddleOCR(use_angle_cls=True, lang='ch')   # 中英文，开启方向分类
result = ocr.ocr('invoice.png', cls=True)

for line in result[0]:
    box = line[0]                    # 文本框四点坐标
    text = line[1][0]                # 识别文本
    confidence = line[1][1]          # 置信度
    print(f'文本: {text}, 置信度: {confidence:.3f}')
```

## Layout Analysis

布局分析（Layout Analysis）识别文档页面的版面结构：标题、段落、表格、图片、页眉页脚等区块的位置与类型。它把「识别文字」升级到「理解版面」，是复杂文档（论文、报表、合同）结构化的前提。传统用规则 + 连通域，现代用检测/分割模型（如 PaddleOCR 的 PP-Structure、LayoutLM 系列）直接输出版面元素框与类别。

```text
布局分析的目标：
1. 版面分区 —— 定位标题/正文/表格/图片/公式等区块
2. 阅读顺序 —— 恢复多栏、混排文档的正确阅读顺序
3. 表格结构 —— 识别表格的行列结构（单元格、合并关系）
4. 输出 —— 结构化的版面树，供后续抽取使用
```

```python
import numpy as np

def analyze_layout_boxes(elements):
    """版面元素分类示意：按框尺寸/位置规则分类"""
    result = []
    for (x, y, w, h) in elements:
        if w < 50 and h < 20:
            label = 'text_line'          # 小框 → 文本行
        elif h < 15 and w > 100:
            label = 'table_row'          # 扁宽框 → 表格行
        elif w > 300 and h > 200:
            label = 'figure'             # 大框 → 图片
        else:
            label = 'paragraph'
        result.append((label, (x, y, w, h)))
    return result

elements = [(10, 10, 500, 20), (10, 40, 300, 80), (10, 150, 350, 10)]
print(analyze_layout_boxes(elements))
```

## Document AI

Document AI（文档智能）是 OCR 的终极形态：不仅识别文字，还要理解整份文档的语义，完成信息抽取、问答、分类等任务。它融合了布局分析（视觉）、OCR 文本（文本）、甚至图像（视觉）多模态信息，用多模态预训练模型（LayoutLM、LayoutLMv3、Donut、GPT-4o 视觉）端到端理解文档。应用在发票报销、合同审核、财报分析、表格抽取等场景。

```text
Document AI 的能力层次：
1. OCR —— 提取原始文字（最底层）
2. 布局分析 —— 恢复版面结构
3. 信息抽取 —— 抽取字段（金额、日期、甲方乙方）为结构化 KV
4. 文档理解 —— 整页问答、分类、摘要（多模态模型）

代表模型：LayoutLM 系列（文本+布局+图像融合）、Donut（端到端无 OCR）
```

```python
import torch

def layoutlm_input_ids(text_tokens, bbox_tokens, image_patches):
    """LayoutLM 多模态输入示意：文本 + 布局 + 图像"""
    # 实际实现会拼接三路 embedding
    text_emb = torch.randn(len(text_tokens), 768)      # 文本 embedding
    layout_emb = torch.randn(len(bbox_tokens), 768)    # 2D 位置/布局 embedding
    image_emb = torch.randn(len(image_patches), 768)   # 图像 patch embedding
    # 拼接后送入 Transformer（简化示意）
    fused = torch.cat([text_emb, layout_emb], dim=-1)
    return fused

print(layoutlm_input_ids([1, 2, 3], [(0, 0, 10, 10)] * 3, [0] * 4).shape)
```

## 应用场景实战

### 场景一：证件信息结构化抽取

```python
from paddleocr import PaddleOCR
import re

ocr = PaddleOCR(use_angle_cls=True, lang='ch')
result = ocr.ocr('id_card.png', cls=True)

# 把识别结果按关键词抽取字段
fields = {}
for line in result[0]:
    text = line[1][0]
    if '姓名' in text or '名' == text.strip()[:1]:
        fields['name'] = re.sub(r'[姓名]', '', text)
    elif '号码' in text or re.match(r'\d{17}[\dXx]', text.strip()):
        fields['id_number'] = re.search(r'\d{17}[\dXx]', text).group()
print(f'抽取到的字段: {fields}')
```

## 最佳实践与踩坑记录

### 最佳实践

1. 中文 OCR 直接上 PaddleOCR，开箱即用、效果稳定，先跑通再考虑自研
2. 识别前务必做方向分类，倒置/旋转文本是识别失败的高频原因
3. 检测出的小文本框要按高度过滤，避免把标点、噪点当文本
4. 复杂文档（多栏、表格）必须做布局分析，否则阅读顺序错乱
5. CTC 训练要求输出时间步长 ≥ 标签长度，输入文本条宽度要足够
6. 需要结构化抽取（发票、合同）时上 LayoutLM 等多模态模型，不要硬拼规则

### 踩坑记录

```text
坑 1：文字检测框太小被直接丢弃
结论：短文本（如「的」「了」单字、标点）被过滤掉，识别不完整。
原因：过滤噪声时用了过大的最小面积阈值，误伤短文本。
解法：按文本高度而非面积过滤，单字框也要保留进识别。

坑 2：CTC 输出时间步比标签还短
结论：CTC 损失报错或无法收敛，识别乱码。
原因：CNN 下采样后宽度方向时间步少于标签字符数。
解法：限制文本条最小宽度，或减小宽度方向的池化 stride。

坑 3：忘记做方向分类，旋转文本识别全错
结论：倒置、旋转 180° 的文本识别成乱码。
原因：识别器训练数据多为正向文本，对旋转敏感。
解法：检测后加方向分类器（PaddleOCR 的 use_angle_cls=True）。

坑 4：多栏文档直接按 y 坐标排序
结论：两栏布局的文字被交错拼成一句，阅读顺序错乱。
原因：只按垂直位置排序忽略了分栏结构。
解法：先做布局分析区分栏位，再栏内排序、栏间按阅读顺序拼接。

坑 5：用通用 OCR 硬套表格
结论：表格单元格文字识别对了，但行列结构全丢。
原因：通用 OCR 不建模表格的行列与合并单元格关系。
解法：用 PP-Structure 或 Table Transformer 做表格结构识别。
```

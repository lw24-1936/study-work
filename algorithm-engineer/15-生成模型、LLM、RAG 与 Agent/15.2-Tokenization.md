## 概述

Tokenization（分词/词元化）是把原始文本切成一个个 token 的过程，token 是 LLM 能理解的最小语义单位。它是所有大模型的第一道工序：文本 → token id 序列 → embedding。分词方案的好坏直接决定词表大小、训练效率和模型对罕见词/多语言的处理能力。

```text
为什么需要 Tokenization：
1. 模型只能处理离散的 token id，不能直接吃字符串
2. 词表要在「覆盖度」和「大小」之间平衡 —— 太大浪费参数，太小则 OOV 多
3. 子词分词（subword）是主流：既不像按词切分那样词表爆炸，也不像按字符切分那样序列过长

主流方案对比：
BPE → 基于频率的合并，GPT 系列使用
WordPiece → 基于似然的合并，BERT 使用
Unigram → 基于概率的删减，T5/多语言模型使用
SentencePiece → 不依赖空格预处理，T5/LLaMA 使用
```

```python
# 一个最小演示：把文本切成「字符级」token 并映射成 id
text = "Hello 世界"
chars = list(text)
vocab = {c: i for i, c in enumerate(sorted(set(chars)))}
ids = [vocab[c] for c in chars]
print(f'字符级 token: {chars}')
print(f'token id: {ids}')
```

## BPE

BPE（Byte Pair Encoding，字节对编码）是最常用的子词分词算法。它从一个字符级词表出发，反复统计「最频繁出现的相邻 token 对」，把它合并成一个新 token，直到达到目标词表大小。GPT-2、GPT-3、GPT-4 都用它。

```text
BPE 算法流程：
1. 初始化 —— 词表 = 所有字符 + 特殊 token（<eos> 等）
2. 统计 —— 在训练语料里统计所有相邻 token 对的出现频次
3. 合并 —— 选频次最高的 token 对 (a, b)，合并成新 token "ab"，加入词表
4. 迭代 —— 重复 2-3，直到词表达到设定大小

优点：能自动发现常见子词（如 "ing"、"tion"、常见词根）
缺点：贪心合并，可能产生不合理的 token；对罕见词可能切得很碎
```

```python
from collections import Counter, defaultdict

def train_bpe(corpus, num_merges=10):
    # 语料预处理：每个词后加 </w> 标记词尾，词内按字符拆分
    word_freqs = Counter(corpus)
    vocab = {c: i for w in corpus for c in w}      # 初始字符词表
    splits = {w: list(w) for w in word_freqs}

    def compute_pair_freqs():
        pairs = defaultdict(int)
        for word, freq in word_freqs.items():
            syms = splits[word]
            for i in range(len(syms) - 1):
                pairs[(syms[i], syms[i + 1])] += freq
        return pairs

    for step in range(num_merges):
        pairs = compute_pair_freqs()
        if not pairs:
            break
        best = max(pairs, key=pairs.get)           # 最频繁的 pair
        merged = ''.join(best)
        vocab[merged] = len(vocab)
        # 更新所有词的分割结果
        for word in word_freqs:
            new_syms, i = [], 0
            while i < len(splits[word]):
                if i + 1 < len(splits[word]) and (splits[word][i], splits[word][i + 1]) == best:
                    new_syms.append(merged)
                    i += 2
                else:
                    new_syms.append(splits[word][i])
                    i += 1
            splits[word] = new_syms
        print(f'merge {step + 1}: {best} -> {merged}')
    return vocab, splits

corpus = ["low", "lower", "newest", "widest"]
vocab, splits = train_bpe(corpus, num_merges=5)
print(f'词表大小: {len(vocab)}')
```

## WordPiece

WordPiece 是 BERT 使用的分词算法，和 BPE 类似但选择合并的标准不同：BPE 选「频率最高」的 pair，WordPiece 选「加入后能最大提升训练语料似然」的 pair。它用 `##` 前缀标记「非词首」的 token。

```text
WordPiece vs BPE：
1. BPE 合并标准 —— 频次最高的相邻 token 对
2. WordPiece 合并标准 —— 使 P(pair) / (P(left)·P(right)) 最大的 pair，
   即「两个子词合起来比分开更常见」的程度
3. 标记方式 —— 非词首的子词加 ## 前缀，如 "playing" → ["play", "##ing"]

优点：合并更符合语言学直觉，子词质量更高
缺点：训练更慢（每次合并都要重算似然），实现比 BPE 复杂
```

```python
# WordPiece 的核心评分：用「互信息」衡量 pair 的合并价值
def wordpiece_score(word_freqs, left, right):
    total = sum(word_freqs.values())
    # 近似：pair 概率 / (left 概率 * right 概率)
    p_pair = word_freqs.get(left + right, 0) / total
    p_left = word_freqs.get(left, 0) / total
    p_right = word_freqs.get(right, 0) / total
    if p_left == 0 or p_right == 0:
        return 0.0
    return p_pair / (p_left * p_right)

word_freqs = {"play": 100, "playing": 50, "##ing": 80, "run": 40, "running": 30}
score = wordpiece_score(word_freqs, "play", "##ing")
print(f'合并 "play" + "##ing" 的评分 = {score:.4f}（越大越该合并）')
```

## SentencePiece

SentencePiece 是 Google 提出的「语言无关」分词框架，它不依赖语言相关的预处理（如英文按空格分词），而是把文本当纯字节流处理。T5、LLaMA、Mistral 都用它。它能统一处理中日韩等无空格语言，并自带 BPE 和 Unigram 两种实现。

```text
SentencePiece 的关键设计：
1. 直接吃原始文本 —— 不需要预先按空格切词，天然支持无空格语言
2. 空格显式编码 —— 空格作为普通字符 ▁（U+2581）进入词表
3. 字节回退 —— 对词表外的字符回退到 UTF-8 字节，永不 OOV
4. 两种算法 —— 内置 BPE 和 Unigram 两种训练模式

优点：语言无关、可逆（能无损还原文本）、处理 emoji 和生僻字
```

```python
import sentencepiece as spm

# 训练一个 SentencePiece 模型（Unigram 模式）
corpus_file = "corpus.txt"
with open(corpus_file, "w", encoding="utf-8") as f:
    f.write("Hello world 你好世界。\n" * 100)

spm.SentencePieceTrainer.train(
    input=corpus_file, model_prefix="sp_model",
    vocab_size=200, model_type="unigram",
    character_coverage=0.9995,
)

sp = spm.SentencePieceProcessor(model_file="sp_model.model")
text = "Hello world 你好世界"
print(f'切分结果: {sp.encode(text, out_type=str)}')
print(f'token id:  {sp.encode(text, out_type=int)}')
print(f'还原文本:  {sp.decode(sp.encode(text, out_type=int))}')
```

## Unigram

Unigram 是一种「减量式」子词分词算法：它假设每个 token 独立出现，从一个大词表出发，反复删掉「对语料似然贡献最小」的 token，直到缩到目标大小。它对每个词的多种切分方案计算概率，最终选 Viterbi 最优路径。

```text
Unigram 算法流程（与 BPE 相反，是「从多到少」）：
1. 初始化 —— 从所有可能的子词候选开始（通常用 BPE 或启发式生成种子词表）
2. E 步 —— 用当前词表对每个词算所有切分方案的概率
3. M 步 —— 重新估计每个 token 的概率
4. 删减 —— 删掉「去掉后损失最小」的 token（对总似然影响最小的）
5. 迭代 —— 直到词表达到目标大小

优点：基于概率、可做多路径切分、可计算每个 token 的概率
缺点：训练最慢，需要维护所有切分路径
```

```python
import math

# Unigram 的切分概率计算：对 "playing" 的多种切分方案算概率
def path_prob(path, token_probs):
    p = 1.0
    for tok in path:
        p *= token_probs.get(tok, 1e-8)
    return p

token_probs = {"play": 0.3, "ing": 0.2, "##ing": 0.15, "playing": 0.05, "p": 0.1, "lay": 0.08}

word = "playing"
paths = [
    ["playing"],          # 整词
    ["play", "##ing"],    # 词根 + 后缀
    ["p", "lay", "##ing"],# 更碎的切分
]
for path in paths:
    print(f'切分 {path}: 概率 = {path_prob(path, token_probs):.6f}')

# Viterbi 会选择概率最大的切分路径
best = max(paths, key=lambda p: path_prob(p, token_probs))
print(f'最优切分: {best}')
```

## Token Budget

Token Budget（token 预算）是指在给定上下文窗口内，如何分配 token 给系统提示、历史对话、检索到的上下文和待生成的输出。LLM 的上下文窗口有限，超预算就要截断、压缩或丢弃内容，直接影响效果和成本。

```text
Token Budget 的分配策略：
1. 系统提示 —— 固定开销，尽量精简
2. 历史对话 —— 保留最近 N 轮，旧的摘要化或丢弃
3. 检索上下文 —— RAG 里按相关性排序后截断，通常占大头
4. 输出预留 —— 为模型回复预留空间，否则会被截断

成本视角：
token 数直接决定 API 成本，输入 token 比输出 token 便宜但量大。
```

```python
# 用 tiktoken 估算 token 数，规划上下文预算
import tiktoken

enc = tiktoken.get_encoding("cl100k_base")   # GPT-4 系编码

def count_tokens(text):
    return len(enc.encode(text))

CONTEXT_LIMIT = 8192
system_prompt = "You are a helpful assistant."
history = [f"user message {i}" * 5 for i in range(10)]
retrieved_docs = ["document content " * 50] * 5
reserved_output = 512

budget = CONTEXT_LIMIT - reserved_output
used = count_tokens(system_prompt)
print(f'系统提示: {used} tokens')

# 按预算从后往前塞历史，超了就丢最旧的
for msg in reversed(history):
    cost = count_tokens(msg)
    if used + cost > budget:
        break
    used += cost
print(f'加上历史后: {used} tokens（丢弃了较早的历史）')

# 检索文档占剩余预算
for doc in retrieved_docs:
    cost = count_tokens(doc)
    if used + cost > budget:
        break
    used += cost
print(f'加上检索文档后: {used} tokens，剩余给输出: {CONTEXT_LIMIT - used}')
```

## 应用场景实战

### 场景一：训练自己的 BPE 词表并应用到文本

```python
from collections import Counter, defaultdict

def train_bpe_full(corpus, num_merges=50):
    word_freqs = Counter(corpus)
    vocab = {c: i for w in corpus for c in w}
    splits = {w: list(w) for w in word_freqs}
    merges = []

    def pair_freqs():
        pairs = defaultdict(int)
        for w, f in word_freqs.items():
            for i in range(len(splits[w]) - 1):
                pairs[(splits[w][i], splits[w][i + 1])] += f
        return pairs

    for _ in range(num_merges):
        pairs = pair_freqs()
        if not pairs:
            break
        best = max(pairs, key=pairs.get)
        merges.append(best)
        vocab[''.join(best)] = len(vocab)
        for w in word_freqs:
            new, i = [], 0
            while i < len(splits[w]):
                if i + 1 < len(splits[w]) and (splits[w][i], splits[w][i + 1]) == best:
                    new.append(''.join(best)); i += 2
                else:
                    new.append(splits[w][i]); i += 1
            splits[w] = new
    return vocab, merges

# 用英文语料训练，观察合并出的子词
corpus = ["the", "the", "there", "their", "then", "that"]
vocab, merges = train_bpe_full(corpus, num_merges=8)
print(f'词表大小: {len(vocab)}')
print(f'合并顺序: {merges}')   # 会先合并 "t"+"h" 得到 "th" 等
```

### 场景二：统计 RAG 场景的 token 成本

```python
import tiktoken

enc = tiktoken.get_encoding("cl100k_base")

def estimate_cost(input_tokens, output_tokens, price_in=3, price_out=15):
    # 价格单位：每百万 token 美元（GPT-4 大致量级）
    cost = input_tokens / 1e6 * price_in + output_tokens / 1e6 * price_out
    return cost

# 模拟一次 RAG 问答：检索 5 个文档片段 + 用户问题，输出 200 token
docs = ["The transformer architecture was introduced in 2017." * 10] * 5
question = "What is the transformer architecture?"
input_text = "\n".join(docs) + "\n" + question
in_tokens = len(enc.encode(input_text))
out_tokens = 200

print(f'输入 {in_tokens} tokens + 输出 {out_tokens} tokens')
print(f'单次成本 ≈ ${estimate_cost(in_tokens, out_tokens):.4f}')
```

## 最佳实践与踩坑记录

### 最佳实践

1. 中文/多语言场景优先用 SentencePiece + Unigram，语言无关且处理无空格语言更稳
2. 词表大小通常在 32k 到 256k 之间，中文模型往往需要更大的词表覆盖汉字
3. 训练词表前先做语料清洗，控制词表里的噪声 token（乱码、孤立字符）
4. 推理时用与模型训练完全一致的 tokenizer，版本和配置都要对齐
5. 规划上下文时始终预留输出 token，避免回复被硬截断
6. 估算成本/延迟都用 token 数，不用字符数或词数（token 才是计价单位）

### 踩坑记录

```text
坑 1：训练和推理用不同的 tokenizer
结论：同一句话切出的 token id 完全不同，模型输出乱码。
原因：BPE/Unigram 的合并表不同，或者特殊 token 定义不一致。
解法：tokenizer 与模型权重一起保存和加载，杜绝不一致。

坑 2：特殊 token 没加入词表
结论：<eos>、<pad>、<bos> 等被拆成普通字符，训练/推理行为异常。
原因：训练语料不含这些 token，词表没有对应 id。
解法：训练前显式把特殊 token 加入词表，并设置正确的 id。

坑 3：中文按「字」切分导致序列过长
结论：一句中文切成几百个字符级 token，上下文很快耗尽。
原因：没有用子词分词，中文没有空格边界，按字符切分效率极低。
解法：用 SentencePiece/Unigram 训练子词词表，覆盖常用中文词组。

坑 4：忽略 token budget 导致上下文截断
结论：检索文档塞太多，把用户问题和历史对话挤出了窗口。
原因：没有预算意识，无脑拼接所有内容。
解法：预留系统+输出，按相关性排序检索结果，超预算就截断。

坑 5：用字符数估算 token 数
结论：成本/容量估算严重失真。
原因：一个 token 可能对应 1-4 个字符，中英文差异巨大。
解法：用 tiktoken 或 tokenizer 精确统计 token 数。
```

## 概述

多模态（Multimodal）让模型同时理解和生成多种信息形态——文本、图像、音频、视频。传统模型只吃单一模态，多模态模型打通了它们之间的壁垒：看图说话、文生图、语音转文字、视频理解。它让 AI 更接近人类「眼耳口并用」的感知与表达方式。

```text
多模态的核心能力：
1. 理解 —— 图像/音频/视频 → 文本描述或语义（VLM、CLIP、OCR）
2. 生成 —— 文本 → 图像/音频/视频（扩散模型、语音合成）
3. 对齐 —— 把不同模态映射到同一语义空间（图文对比学习）
4. 融合 —— 多模态信息联合推理（视觉问答、文档理解）

关键技术：跨模态对齐、统一表征、扩散模型、自回归多模态生成
```

## Vision-Language Model

Vision-Language Model（视觉语言模型，简称 VLM）是能同时处理图像和文本、并做跨模态推理的模型总称。它把图像编码成视觉 token，与文本 token 一起喂进 LLM，从而完成视觉问答、图文对话、图像描述等任务。它是「多模态大模型」的通用叫法。

```text
VLM 的典型架构：
1. 视觉编码器 —— ViT/CLIP 把图像编码成特征序列
2. 投影层 —— 把视觉特征映射到 LLM 的 token 空间
3. 语言模型 —— LLM 接收 [视觉 token + 文本 token] 联合生成

代表：LLaVA、Qwen-VL、GPT-4V、Gemini、InternVL
```

## Image-Text Embedding

Image-Text Embedding（图文嵌入）把图像和文本映射到同一个向量空间，让「图像和描述它的文字」在空间里距离很近。它是图文检索、跨模态搜索、图文匹配的地基——用一个空间统一两种模态，才能算「图和文的相似度」。

```text
图文嵌入的用途：
1. 图文检索 —— 文字搜图、图搜文字
2. 跨模态匹配 —— 判断图片和描述是否一致
3. 零样本分类 —— 用类别名作文本，和图片算相似度
4. 多模态 RAG —— 把图片也作为可检索的语义单元

核心：通过对比学习，让匹配的图文对拉近、不匹配的拉远
```

```python
import torch
from transformers import CLIPProcessor, CLIPModel

model = CLIPModel.from_pretrained("openai/clip-vit-base-patch32")
processor = CLIPProcessor.from_pretrained("openai/clip-vit-base-patch32")

def image_text_similarity(image, texts):
    inputs = processor(text=texts, images=image, return_tensors="pt", padding=True)
    outputs = model(**inputs)
    logits_per_image = outputs.logits_per_image   # (1, n_texts)
    return logits_per_image.softmax(dim=-1)

# image = Image.open("./dog.jpg")
# sims = image_text_similarity(image, ["一只猫", "一只狗", "一辆车"])
# print(sims)
print('图文相似度计算流程已定义：图像 + 候选文本 → 概率分布')
```

## CLIP

CLIP（Contrastive Language-Image Pre-training）是 OpenAI 提出的图文对比学习模型，用 4 亿图文对训练，让图像编码器和文本编码器学会「对齐」。它的杀手锏是零样本能力：不做任何微调，就能用「类别名作文本」对任意图像分类，是图文对齐的里程碑。

```text
CLIP 核心思想：
1. 双塔 —— 图像编码器 + 文本编码器，各自输出向量
2. 对比学习 —— 一个 batch 里 N 对图文，拉近对角（匹配对）、拉远其余
3. 零样本 —— 用文本描述当分类标签，算图文相似度即可分类
4. 预训练 → 迁移 —— 学到的表征可迁移到检测、分割、生成等任务

训练目标：对称的交叉熵，最大化匹配对相似度、最小化不匹配对
```

```python
import torch
import torch.nn.functional as F

def clip_contrastive_loss(image_emb, text_emb):
    # 归一化后算相似度矩阵
    image_emb = F.normalize(image_emb, dim=-1)
    text_emb = F.normalize(text_emb, dim=-1)
    logits = image_emb @ text_emb.T * 2.5    # temperature 缩放
    n = logits.shape[0]
    labels = torch.arange(n)
    # 对称交叉熵：图→文 和 文→图 两个方向
    loss_i = F.cross_entropy(logits, labels)
    loss_t = F.cross_entropy(logits.T, labels)
    return (loss_i + loss_t) / 2

# 模拟一个 batch 的图文嵌入（4 对）
img = torch.randn(4, 512)
txt = torch.randn(4, 512)
print(f'CLIP 对比损失: {clip_contrastive_loss(img, txt).item():.3f}')
```

## VLM

VLM 在本知识库语境下特指「可对话的多模态大模型」（把图像融入 LLM 的推理与生成），是 Vision-Language Model 的落地形态。它不仅能识别图片里的物体，还能做跨图推理、图文创作、读图表、看代码截图等复杂任务，是多模态应用的主战场。

```text
VLM 的进阶能力：
1. 视觉问答（VQA）—— 针对图片内容回答任意问题
2. 图文推理 —— 跨图比较、空间关系、逻辑推断
3. 图表理解 —— 读折线图、柱状图、表格截图
4. 屏幕理解 —— 看 UI 截图操作软件（GUI Agent）

训练流程：预训练对齐（图文对）→ 指令微调（多模态问答对）→ 对齐
```

## OCR + LLM

OCR + LLM 组合把「文字识别」和「语言理解」串起来：先用 OCR 从图片/扫描件里抽出文字，再交给 LLM 做理解、总结、问答。它处理的是「图片里的文字内容」，比通用 VLM 在文字识别精度上更可控，是文档数字化的经典路线。

```text
OCR + LLM 流程：
1. OCR —— 定位文字区域 + 识别文字（PaddleOCR/Tesseract/EasyOCR）
2. 结构化 —— 还原版面、表格、阅读顺序
3. LLM —— 对抽取出的文字做总结/问答/抽取字段
4. 纠错 —— LLM 顺带修正 OCR 的错别字

适用：合同、发票、证件、古籍等文字密集型图片
```

```python
from paddleocr import PaddleOCR

def ocr_extract(image_path):
    ocr = PaddleOCR(use_angle_cls=True, lang="ch")
    result = ocr.ocr(image_path, cls=True)
    lines = []
    for page in result:
        for line in page:
            text = line[1][0]       # 识别出的文字
            conf = line[1][1]       # 置信度
            lines.append((text, conf))
    return lines
```

## Document AI

Document AI（文档智能）是「OCR + LLM + 版面理解」的进阶综合方案：不仅识别文字，还理解文档的结构（标题、段落、表格、印章、签名），并做字段抽取、分类、审核等业务动作。它是企业数字化（合同、票据、报告）的核心技术。

```text
Document AI 能力层次：
1. 版面分析 —— 检测标题/正文/表格/图片的区域
2. 表格结构识别 —— 还原单元格与行列关系
3. 关键信息抽取 —— 抽字段（合同金额、发票抬头、证件号）
4. 文档理解 —— 整篇文档的问答、摘要、比对

代表：LayoutLM、Donut、Nougat（学术文档）、ERNIE-Layout
```

## Image Generation

Image Generation（图像生成）根据文本（或图像）生成新图像。主流是扩散模型：从纯噪声出发，逐步去噪还原出图像，而文本通过条件机制（如 CLIP 编码后做 cross-attention）引导生成方向。它让「文生图」「图生图」「图像编辑」成为现实。

```text
图像生成技术栈：
1. 扩散模型 —— DDPM/DDIM，逐步去噪生成
2. 条件生成 —— 文本嵌入通过 cross-attention 引导（Stable Diffusion）
3. 自回归生成 —— 图像离散成 token 逐 token 生成（DALL-E 1、LlamaGen）
4. 主流模型 —— Stable Diffusion、DALL-E 3、Midjourney、Flux

关键参数：CFG（无分类器引导强度）、步数、种子
```

```python
from diffusers import StableDiffusionPipeline
import torch

def text_to_image(prompt, steps=25):
    pipe = StableDiffusionPipeline.from_pretrained(
        "runwayml/stable-diffusion-v1-5", torch_dtype=torch.float16
    )
    pipe = pipe.to("cuda")
    image = pipe(prompt, num_inference_steps=steps, guidance_scale=7.5).images[0]
    return image

# img = text_to_image("一只戴宇航头盔的柴犬，数字艺术")
# img.save("astronaut_shiba.png")
```

## Audio/Speech/Video

音视频多模态覆盖「语音识别（ASR）、语音合成（TTS）、音频理解、视频理解」等能力。语音侧把声波转文字或从文字合成语音，视频侧把连续的图像帧 + 音频联合理解。它们让模型「听得见、说得出、看得懂动态世界」。

```text
音视频多模态能力：
1. ASR —— 语音转文字（Whisper、Paraformer）
2. TTS —— 文字转语音（VITS、Tortoise、CosyVoice）
3. 音频理解 —— 音乐/环境声/情感分类
4. 视频理解 —— 抽帧 + VLM 做动作/事件/字幕理解

视频处理要点：先抽关键帧，再逐帧或多帧联合送入 VLM
```

```python
import torch
from transformers import WhisperProcessor, WhisperForConditionalGeneration

model_id = "openai/whisper-small"
processor = WhisperProcessor.from_pretrained(model_id)
model = WhisperForConditionalGeneration.from_pretrained(model_id)

def transcribe(audio_array, sample_rate=16000):
    inputs = processor(audio_array, sampling_rate=sample_rate, return_tensors="pt")
    with torch.no_grad():
        predicted_ids = model.generate(inputs.input_features)
    return processor.batch_decode(predicted_ids, skip_special_tokens=True)[0]

# text = transcribe(audio_chunk)
print('语音识别流程已定义：音频波形 → Whisper → 文本')
```

## 应用场景实战

### 场景一：用 CLIP 做零样本图片分类

```python
from transformers import CLIPProcessor, CLIPModel
from PIL import Image

model = CLIPModel.from_pretrained("openai/clip-vit-base-patch32")
processor = CLIPProcessor.from_pretrained("openai/clip-vit-base-patch32")

def zero_shot_classify(image, class_names):
    # 用类别名当文本，与图片算相似度
    text_labels = [f"a photo of a {c}" for c in class_names]
    inputs = processor(text=text_labels, images=image, return_tensors="pt", padding=True)
    outputs = model(**inputs)
    probs = outputs.logits_per_image.softmax(dim=-1)[0]
    best = class_names[probs.argmax().item()]
    return best, probs
```

## 最佳实践与踩坑记录

### 最佳实践

1. 图文检索/零样本分类用 CLIP 系列，先试零样本再决定要不要微调
2. VLM 理解图表、截图、文档时，输入分辨率要足够，图片压缩过狠会丢信息
3. 文档抽取用「OCR + LLM」或专用 Document AI 模型，别用通用 VLM 硬读密集小字
4. 视频理解先抽关键帧再送 VLM，别逐帧全送（成本爆炸）
5. 文生图调好 CFG 和步数，CFG 过高会过饱和、步数过多边际收益递减
6. 语音识别选对采样率，Whisper 默认 16kHz，采样率不对识别率骤降

### 踩坑记录

```text
坑 1：CLIP 对专有名词/细粒度分类失效
结论：零样本分类「哈士奇 vs 阿拉斯加」几乎随机猜。
原因：CLIP 学的是粗粒度语义，细粒度类别在文本标签上区分度不足。
解法：细粒度任务收集少量数据微调，或换专用视觉模型。

坑 2：VLM 读密集小字文档时乱编
结论：把合同截图丢给 VLM，金额、日期经常看错或凭空捏造。
原因：VLM 对密集小字的识别精度不如专用 OCR，还会幻觉。
解法：文档场景走 OCR + LLM，抽取字段做后校验。

坑 3：文生图 CFG 调太高导致画面过饱和
结论：图像色彩刺眼、细节糊成一团，失去真实感。
原因：无分类器引导强度过大，模型过度迎合文本条件。
解法：CFG 控制在 7-9，过高时适当降低，配合合适步数。

坑 4：视频逐帧送 VLM 成本爆炸
结论：一个 1 分钟视频抽 1800 帧全送模型，token 烧光。
原因：视频帧间高度冗余，逐帧处理浪费大量计算。
解法：抽关键帧（每秒 1-2 帧）或做帧聚类，再联合理解。

坑 5：语音识别采样率不匹配
结论：48kHz 的音频直接喂 Whisper，识别结果一堆错字。
原因：Whisper 特征提取器按 16kHz 处理，采样率不匹配导致频谱错乱。
解法：先重采样到 16kHz 再送入模型。

坑 6：图文检索用了没对齐的向量空间
结论：图和文分别用不同模型编码，检索结果完全无关。
原因：图文必须映射到同一语义空间，否则相似度无意义。
解法：统一用 CLIP 等图文对齐模型编码，换模型要重建索引。
```

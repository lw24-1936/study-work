## 概述

大语言模型（LLM）是参数规模达到数十亿到数千亿、在海量文本上预训练的自回归模型，核心能力是「预测下一个 token」。现代 LLM 几乎都采用 Decoder-Only Transformer 架构，配合 RMSNorm、SwiGLU、RoPE 等一系列工程改进，并通过 Scaling Laws 指导规模化。

```text
LLM 的技术栈全景：
1. 架构 —— Decoder-Only Transformer + 因果掩码
2. 训练 —— 自回归语言建模（预测下一个 token）
3. 规模化 —— Scaling Laws 指导算力/数据/参数的配比
4. 效率 —— MoE、KV Cache、FlashAttention 等
5. 组件 —— RMSNorm、SwiGLU、RoPE 等现代改进
```

```python
import torch
import torch.nn as nn

# 一个 GPT 风格的最小 Decoder-Only block
class MiniGPTBlock(nn.Module):
    def __init__(self, d_model=64, n_head=4, ff=128):
        super().__init__()
        self.attn = nn.MultiheadAttention(d_model, n_head, batch_first=True)
        self.ff = nn.Sequential(
            nn.Linear(d_model, ff), nn.GELU(),
            nn.Linear(ff, d_model),
        )
        self.ln1 = nn.LayerNorm(d_model)
        self.ln2 = nn.LayerNorm(d_model)

    def forward(self, x, causal_mask):
        a = self.attn(x, x, x, attn_mask=causal_mask)[0]
        x = self.ln1(x + a)
        return self.ln2(x + self.ff(x))

x = torch.randn(2, 8, 64)
print(MiniGPTBlock()(x, None).shape)   # torch.Size([2, 8, 64])
```

## Decoder-Only Transformer

Decoder-Only Transformer 只保留原始 Transformer 的解码器部分：单向（因果）注意力 + 前馈网络。相比 Encoder-Decoder，它结构更简单、推理时能复用 KV Cache、扩展性更好，是 GPT、LLaMA、Mistral 等主流 LLM 的共同选择。

```text
为什么选 Decoder-Only：
1. 自回归生成天然匹配 —— 从左到右预测下一个 token
2. 推理高效 —— 只有单向注意力，KV Cache 可复用
3. 扩展性好 —— 结构简单，容易堆层堆参数，Scaling Law 友好
4. 少一套 encoder —— 参数量更集中，预训练目标单一

结构组成（每个 block）：
输入 → 因果自注意力 → 残差+归一化 → FFN(SwiGLU) → 残差+归一化 → 输出
```

```python
import torch
import torch.nn as nn
import math

class DecoderBlock(nn.Module):
    def __init__(self, d_model, n_head, ff_mult=4):
        super().__init__()
        self.d_model = d_model
        self.n_head = n_head
        self.qkv = nn.Linear(d_model, 3 * d_model)
        self.out = nn.Linear(d_model, d_model)
        self.ff = nn.Sequential(
            nn.Linear(d_model, d_model * ff_mult), nn.GELU(),
            nn.Linear(d_model * ff_mult, d_model),
        )
        self.norm1 = nn.LayerNorm(d_model)
        self.norm2 = nn.LayerNorm(d_model)

    def forward(self, x, mask=None):
        B, T, D = x.shape
        qkv = self.qkv(x).reshape(B, T, 3, self.n_head, D // self.n_head).permute(2, 0, 3, 1, 4)
        q, k, v = qkv[0], qkv[1], qkv[2]
        attn = (q @ k.transpose(-2, -1)) / math.sqrt(D // self.n_head)
        if mask is not None:
            attn = attn.masked_fill(mask[:, None, None, :] == 0, float('-inf'))
        attn = torch.softmax(attn, dim=-1) @ v
        attn = attn.transpose(1, 2).reshape(B, T, D)
        x = self.norm1(x + self.out(attn))
        return self.norm2(x + self.ff(x))

# 因果掩码：位置 i 只能看到位置 0..i
T = 8
causal = torch.tril(torch.ones(T, T))
print(f'因果掩码（下三角=1，上三角=0）：\n{causal.numpy().astype(int)}')
```

## Causal LM

因果语言模型（Causal LM）是 LLM 的训练和推理范式：模型只能利用当前位置之前的 token 预测下一个 token，不能「偷看未来」。这是通过因果掩码（causal mask）实现的，训练时对整句并行计算，推理时逐 token 自回归生成。

```text
训练目标（自回归语言建模）：
L = -Σ_t log P(x_t | x_1, ..., x_{t-1})

关键机制：
1. 因果掩码 —— 注意力矩阵上三角置 -inf，屏蔽未来信息
2. 训练并行 —— 输入整句，每个位置同时预测下一个 token
3. 推理串行 —— 一次生成一个 token，拼回输入继续生成
```

```python
import torch
import torch.nn as nn

# 训练时的因果 LM：并行预测整句所有位置的下一个 token
def causal_lm_loss(logits, input_ids):
    # logits: [B, T, V]，每个位置预测下一个 token
    shift_logits = logits[:, :-1, :]          # 去掉最后一个位置的预测
    shift_labels = input_ids[:, 1:]           # 标签右移一位
    return nn.functional.cross_entropy(
        shift_logits.reshape(-1, shift_logits.size(-1)),
        shift_labels.reshape(-1),
    )

logits = torch.randn(2, 8, 1000)      # 词表 1000
input_ids = torch.randint(0, 1000, (2, 8))
print(f'Causal LM 损失 = {causal_lm_loss(logits, input_ids).item():.3f}')
```

## Pretraining

预训练是在海量无标注文本上训练 LLM 的阶段，目标是让模型学会语言知识、世界知识和推理能力。预训练后得到 base model，再通过 SFT/对齐变成可对话的模型。这是 LLM 成本和算力最集中的阶段。

```text
预训练的关键要素：
1. 数据 —— 数万亿 token 的高质量文本（网页、书籍、代码、论文）
2. 目标 —— 下一个 token 预测（causal LM）
3. 规模 —— 参数、数据、算力按 Scaling Law 配比
4. 稳定性 —— 混合精度、梯度裁剪、学习率调度、loss spike 处理

数据配比（典型）：
网页 50% + 代码 20% + 书籍/论文 15% + 多语言 15%，去重 + 过滤低质。
```

```python
import torch

# 预训练循环的骨架：梯度累积 + 梯度裁剪 + 学习率 warmup
def train_step(model, batch, optimizer, scaler, grad_accum_steps=4):
    for i, (x, y) in enumerate(batch):
        with torch.autocast(device_type='cuda', dtype=torch.bfloat16):
            logits = model(x)
            loss = nn.functional.cross_entropy(
                logits.view(-1, logits.size(-1)), y.view(-1))
            loss = loss / grad_accum_steps        # 梯度累积
        scaler.scale(loss).backward()
        if (i + 1) % grad_accum_steps == 0:
            scaler.unscale_(optimizer)
            torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)  # 梯度裁剪
            scaler.step(optimizer)
            scaler.update()
            optimizer.zero_grad()
    return loss.item() * grad_accum_steps

# 模拟一个 batch
class DummyModel(torch.nn.Module):
    def forward(self, x):
        return torch.randn(x.size(0), x.size(1), 1000)

model, optimizer = DummyModel(), torch.optim.AdamW(DummyModel().parameters(), lr=1e-4)
scaler = torch.cuda.amp.GradScaler(enabled=False)  # CPU 环境示意
x = torch.randint(0, 1000, (8, 64)); y = torch.randint(0, 1000, (8, 64))
print(f'预训练 step loss = {train_step(model, [(x, y)], optimizer, scaler, grad_accum_steps=2):.3f}')
```

## Scaling Laws

Scaling Laws（缩放定律）是经验规律：模型性能随参数量、数据量、算力的增加而可预测地提升，服从幂律关系。它指导我们「在给定算力预算下，如何分配参数量和数据量才能最大化性能」，是 Chinchilla 等工作的核心结论。

```text
核心结论（Kaplan / Chinchilla）：
Loss ∝ C^(-α)，C 是算力，α ≈ 0.05 左右

Chinchilla 最优配比（约 2022）：
算力 C 给定时，最优参数 N 和数据 D 满足 D ≈ 20 × N
即：每个参数配约 20 个 token，模型和数据同步增长。

实践含义：
1. 别只堆参数不堆数据 —— 数据不足会欠拟合，浪费算力
2. 小模型 + 多数据，往往比大模型 + 少数据更划算
3. 涌现能力 —— 规模越过某阈值后突然出现的新能力
```

```python
import math

# 用幂律拟合 Loss 与算力的关系，并算 Chinchilla 最优配比
def loss_from_compute(C, a=1.0, alpha=0.05):
    return a * C ** (-alpha)

def chinchilla_optimal(C, k=20.0):
    # 给定算力，最优的参数量 N 和 token 数 D
    N = (C / (2 * k)) ** 0.5
    D = k * N
    return N, D

for C in [1e18, 1e20, 1e22, 1e24]:
    N, D = chinchilla_optimal(C)
    print(f'算力 C={C:.0e}: 最优参数 N={N:.1e}, 数据 D={D:.1e} (D/N={D/N:.0f})')
```

## MoE

混合专家（MoE，Mixture of Experts）把前馈层拆成多个「专家」，每个 token 只路由到少数几个专家（如 top-2），从而在保持总参数量巨大的同时，把每个 token 的实际计算量控制在小范围。这是 DeepSeek、Mixtral 等高效大模型的核心技术。

```text
MoE 工作原理：
1. 专家 —— N 个独立的前馈网络（如 8 个、64 个）
2. 路由 —— 门控网络 G(x) 给每个 token 打分，选出 top-k 专家
3. 稀疏激活 —— 每个 token 只计算被选中的 k 个专家（k << N）
4. 输出 —— 加权组合选中专家的输出

优势：参数总量大（知识容量大），但每个 token 的 FLOPs 只相当于稠密模型的一小部分。
挑战：负载均衡、专家坍缩、通信开销（分布式下）。
```

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class MoELayer(nn.Module):
    def __init__(self, d_model, n_experts=8, top_k=2):
        super().__init__()
        self.n_experts = n_experts
        self.top_k = top_k
        self.experts = nn.ModuleList([
            nn.Sequential(nn.Linear(d_model, d_model * 4), nn.GELU(),
                          nn.Linear(d_model * 4, d_model))
            for _ in range(n_experts)
        ])
        self.gate = nn.Linear(d_model, n_experts)

    def forward(self, x):
        B, T, D = x.shape
        x_flat = x.view(-1, D)
        logits = self.gate(x_flat)                       # [B*T, N]
        topk_weights, topk_idx = logits.topk(self.top_k, dim=-1)
        topk_weights = F.softmax(topk_weights, dim=-1)   # 归一化权重
        out = torch.zeros_like(x_flat)
        for k in range(self.top_k):
            expert_idx = topk_idx[:, k]                   # 每个 token 选中的专家
            weight = topk_weights[:, k].unsqueeze(1)
            for e in range(self.n_experts):
                mask = (expert_idx == e)
                if mask.any():
                    out[mask] += weight[mask] * self.experts[e](x_flat[mask])
        return out.view(B, T, D)

x = torch.randn(2, 16, 64)
y = MoELayer(64, n_experts=8, top_k=2)(x)
print(f'MoE 输出形状 = {y.shape}（每个 token 只算 2/8 个专家）')
```

## RMSNorm

RMSNorm 是 LayerNorm 的简化变体：去掉「减均值」和「加偏置」，只保留「除以均方根 + 缩放」。它在效果上不输 LayerNorm，但计算更快、更省显存，是 LLaMA、Mistral 等现代 LLM 的标配。

```text
RMSNorm vs LayerNorm：
LayerNorm: y = (x - μ) / √(σ² + ε) · γ + β
RMSNorm:   y = x / RMS(x) · γ，其中 RMS(x) = √(mean(x²) + ε)

区别：
1. 不减均值 —— 省一次归约运算
2. 不加偏置 β —— 少一组参数
3. 效果相当 —— 实际训练中与 LayerNorm 基本持平，推理更快
```

```python
import torch
import torch.nn as nn

class RMSNorm(nn.Module):
    def __init__(self, dim, eps=1e-6):
        super().__init__()
        self.eps = eps
        self.weight = nn.Parameter(torch.ones(dim))   # 缩放参数 γ

    def forward(self, x):
        # x: [..., dim]
        rms = torch.sqrt(x.pow(2).mean(dim=-1, keepdim=True) + self.eps)
        return x / rms * self.weight

x = torch.randn(4, 64)
ln_out = nn.LayerNorm(64)(x)
rms_out = RMSNorm(64)(x)
print(f'RMSNorm 与 LayerNorm 输出差异 = {(ln_out - rms_out).abs().mean().item():.4f}')
print(f'RMSNorm 输出均值 = {rms_out.mean(dim=-1).mean().item():.4f}（不强制为 0）')
```

## SwiGLU

SwiGLU 是一种激活函数 + 门控的组合，把传统 FFN 的「线性 + 激活」升级为「两个线性投影，一个经 Swish 激活后做门控」。它比 ReLU/GELU 更稳定、效果更好，是 LLaMA、PaLM 等模型的默认 FFN 结构。

```text
SwiGLU 定义：
SwiGLU(x, W, V) = Swish(xW) ⊙ (xV)

其中 Swish(z) = z · σ(z) = z / (1 + e^(-z))

FFN 结构对比：
传统：x → Linear → GELU → Linear → out
SwiGLU：x → Linear1(→Swish) ⊙ Linear2 → Linear3 → out

注意：SwiGLU 用了两个升维投影，通常把中间维度设为 (8/3)·d_model
以抵消额外参数，保持总参数量与传统 FFN 相当。
```

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

def swish(z):
    return z * torch.sigmoid(z)

class SwiGLU(nn.Module):
    def __init__(self, d_model, hidden=None):
        super().__init__()
        hidden = hidden or int(8 * d_model / 3)   # 补偿额外参数
        self.w1 = nn.Linear(d_model, hidden)       # 门控分支
        self.w2 = nn.Linear(d_model, hidden)       # 值分支
        self.w3 = nn.Linear(hidden, d_model)       # 输出投影

    def forward(self, x):
        return self.w3(swish(self.w1(x)) * self.w2(x))

x = torch.randn(4, 64)
out = SwiGLU(64)(x)
print(f'SwiGLU 输出形状 = {out.shape}')
```

## RoPE

RoPE（旋转位置编码，Rotary Position Embedding）把位置信息编码成「旋转」：对 query 和 key 的每对相邻维度施加一个与位置相关的旋转变换。它让注意力分数天然只依赖 token 间的相对位置，且能外推到更长的序列，是 LLaMA 等模型的标配。

```text
RoPE 原理：
1. 把 d 维向量按两个一组看成 d/2 个「复数」
2. 位置 m 的 token，其向量旋转 m·θ 角度（θ 按频率递减）
3. q_m·k_n 只依赖相对位置 (m - n)，实现相对位置编码

优势：
1. 相对位置 —— 注意力只依赖距离，符合语言直觉
2. 外推 —— 可通过调整旋转频率（如 NTK-aware）扩展到更长序列
3. 无参数 —— 不增加可学习参数
```

```python
import torch

def rotate_half(x):
    x1, x2 = x[..., :x.shape[-1] // 2], x[..., x.shape[-1] // 2:]
    return torch.cat((-x2, x1), dim=-1)

def apply_rope(q, k, position_ids):
    # 简化版 RoPE：按位置旋转
    dim = q.shape[-1]
    # 频率：θ_i = 10000^(-2i/d)
    freqs = 1.0 / (10000 ** (torch.arange(0, dim, 2).float() / dim))
    angles = position_ids.float().unsqueeze(-1) * freqs    # m * θ_i
    cos, sin = angles.cos(), angles.sin()
    # 应用到 q/k（实际实现会广播到每个 head）
    def rotate(x):
        return x * cos.unsqueeze(1) + rotate_half(x) * sin.unsqueeze(1)
    return rotate(q), rotate(k)

B, T, D = 2, 8, 64
q = torch.randn(B, T, D); k = torch.randn(B, T, D)
pos = torch.arange(T).unsqueeze(0).expand(B, T)
q_rot, k_rot = apply_rope(q, k, pos)
print(f'RoPE 后 q 形状 = {q_rot.shape}（数值不变，仅旋转）')
```

## KV Cache

KV Cache 是 LLM 推理加速的关键技术：生成时缓存历史 token 的 key 和 value，新 token 只需计算自己的 Q/K/V，再和缓存的 K/V 拼起来做注意力，避免重复计算。它把推理从 O(T²) 的重复计算降为 O(T) 的增量计算。

```text
为什么需要 KV Cache：
1. 无缓存时，生成第 t 个 token 要重新算前 t-1 个 token 的 K/V
2. 有了缓存，每步只算当前 token 的 K/V，与历史拼接待用

代价：
显存占用 = 2 × n_layers × n_heads × head_dim × seq_len × dtype
长序列时 KV Cache 显存巨大，催生了 GQA、MQA 等压缩技术。
```

```python
import torch

class KVCache:
    def __init__(self, n_layers, n_heads, head_dim, max_len=1024):
        self.k = [torch.zeros(1, n_heads, max_len, head_dim) for _ in range(n_layers)]
        self.v = [torch.zeros(1, n_heads, max_len, head_dim) for _ in range(n_layers)]
        self.seq_len = 0

    def update(self, layer, new_k, new_v):
        # new_k/new_v: [B, n_heads, 1, head_dim]
        start = self.seq_len
        self.k[layer][:, :, start:start + 1] = new_k
        self.v[layer][:, :, start:start + 1] = new_v

    def get(self, layer):
        # 返回截至当前的完整 K/V
        return self.k[layer][:, :, :self.seq_len + 1], self.v[layer][:, :, :self.seq_len + 1]

cache = KVCache(n_layers=2, n_heads=4, head_dim=16)
new_k = torch.randn(1, 4, 1, 16); new_v = torch.randn(1, 4, 1, 16)
cache.update(0, new_k, new_v)
cache.seq_len += 1
K, V = cache.get(0)
print(f'缓存后的 K 形状 = {K.shape}（长度随生成增长，避免重复计算）')
```

## 应用场景实战

### 场景一：搭一个能训练的最小 GPT 并跑通前向 + 生成

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class MiniGPT(nn.Module):
    def __init__(self, vocab=1000, d_model=64, n_head=4, n_layer=2, max_len=64):
        super().__init__()
        self.tok = nn.Embedding(vocab, d_model)
        self.pos = nn.Embedding(max_len, d_model)
        self.blocks = nn.ModuleList([DecoderBlock(d_model, n_head) for _ in range(n_layer)])
        self.ln = nn.LayerNorm(d_model)
        self.head = nn.Linear(d_model, vocab)

    def forward(self, idx):
        B, T = idx.shape
        x = self.tok(idx) + self.pos(torch.arange(T).to(idx.device))
        mask = torch.tril(torch.ones(T, T)).to(idx.device)
        for blk in self.blocks:
            x = blk(x, mask)
        return self.head(self.ln(x))

    @torch.no_grad()
    def generate(self, idx, max_new=20, temperature=1.0):
        for _ in range(max_new):
            logits = self(idx)[:, -1, :] / temperature
            probs = F.softmax(logits, dim=-1)
            next_tok = torch.multinomial(probs, num_samples=1)
            idx = torch.cat([idx, next_tok], dim=1)
        return idx

model = MiniGPT()
x = torch.randint(0, 1000, (2, 16))
logits = model(x)
print(f'logits 形状 = {logits.shape}')

start = torch.randint(0, 1000, (1, 1))
print(f'生成结果长度 = {model.generate(start, max_new=8).shape}')
```

### 场景二：计算 KV Cache 显存占用

```python
def kv_cache_memory(n_layers, n_heads, head_dim, seq_len, dtype_bytes=2):
    # 2 (K 和 V) × 层数 × 头数 × head_dim × seq_len × 字节
    return 2 * n_layers * n_heads * head_dim * seq_len * dtype_bytes

# 一个 7B 级模型：32 层、32 头、head_dim 128，bf16（2 字节）
for seq_len in [1024, 4096, 16384]:
    mem = kv_cache_memory(32, 32, 128, seq_len, 2) / 1e9
    print(f'seq_len={seq_len}: KV Cache 约 {mem:.2f} GB')
# 可见长序列下 KV Cache 可能比模型权重本身还大
```

## 最佳实践与踩坑记录

### 最佳实践

1. 新项目直接选成熟的 Decoder-Only 架构（LLaMA/Mistral 系），别从零造轮子
2. 用 RMSNorm + SwiGLU + RoPE 这套现代组合，效果和效率都优于原始 Transformer
3. 预训练前严格做数据去重和质量过滤，垃圾进垃圾出，数据质量比数量更重要
4. 算力有限时按 Chinchilla 配比，小模型多数据通常比大模型少数据划算
5. 推理必开 KV Cache，长序列场景评估 GQA/MQA 压缩显存
6. MoE 模型部署时关注负载均衡和专家通信，否则利用率上不去

### 踩坑记录

```text
坑 1：忘记加因果掩码
结论：模型能看到未来 token，训练 loss 极低但推理一塌糊涂。
原因：注意力没有屏蔽未来位置，信息泄漏。
解法：每个 block 都加下三角因果掩码，验证 attn 矩阵上三角为 -inf。

坑 2：KV Cache 显存爆炸
结论：长序列或大 batch 推理 OOM。
原因：KV Cache 随 seq_len 和 batch 线性增长，且每层每头都存。
解法：上 GQA/MQA 减少头数，或量化 KV Cache，或限制最大长度。

坑 3：RoPE 外推导致长文本质量骤降
结论：模型在训练长度内表现好，超出后困惑度飙升。
原因：旋转频率没针对更长序列调整，相对位置编码失效。
解法：用 NTK-aware / YaRN 等 RoPE 插值方法扩展上下文。

坑 4：MoE 专家负载不均
结论：少数专家被频繁选中，其余专家「饿死」，实际容量打折扣。
原因：路由塌缩，门控网络倾向把 token 发给固定几个专家。
解法：加负载均衡损失（auxiliary loss）、专家容量上限、noisy top-k。

坑 5：预训练 loss spike（损失尖峰）
结论：训练中 loss 突然飙升，甚至再也降不回来。
原因：梯度异常、数据质量问题、学习率过高导致权重跳变。
解法：梯度裁剪、监控并回滚到 spike 前的 checkpoint、降低学习率。
```

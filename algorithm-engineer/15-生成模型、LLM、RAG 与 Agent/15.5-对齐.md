## 概述

对齐（Alignment）是让 LLM 的行为符合人类偏好和价值的过程：有用、诚实、无害。预训练和 SFT 只让模型「会说话」，对齐则让它「说人想听的话」。核心是从人类偏好数据里学到一个奖励信号，再优化模型，主流的路线有 RLHF（强化学习）和 DPO（直接偏好优化）两派。

```text
对齐的技术路线：
1. RLHF —— 先训练奖励模型，再用 PPO 强化学习优化策略
2. DPO —— 跳过奖励模型，直接从偏好对里优化策略（简单稳定）
3. IPO —— 修复 DPO 的过拟合问题，引入正则化
4. ORPO —— 把 SFT 和偏好对齐合并成一步，无需参考模型

核心数据：偏好对 (prompt, 好的回答, 差的回答)，由人类或 AI 标注。
```

```python
import torch
import torch.nn as nn

# 对齐涉及的两个核心组件：策略模型（待优化）和参考模型（冻结）
class Policy(nn.Module):
    def __init__(self, d=64, vocab=1000):
        super().__init__()
        self.net = nn.Sequential(nn.Linear(d, d), nn.ReLU(), nn.Linear(d, vocab))

    def forward(self, x):
        return self.net(x)

policy = Policy()
reference = Policy()
reference.load_state_dict(policy.state_dict())   # 参考模型 = 初始策略的副本
for p in reference.parameters():
    p.requires_grad = False                        # 冻结参考模型
print(f'策略模型可训练参数 = {sum(p.numel() for p in policy.parameters() if p.requires_grad)}')
```

## RLHF

RLHF（Reinforcement Learning from Human Feedback，基于人类反馈的强化学习）分三步：先 SFT 得到初始策略，再训练一个奖励模型给回答打分，最后用 PPO 在奖励信号指导下优化策略。它是 InstructGPT、ChatGPT 的核心训练方法。

```text
RLHF 三阶段：
1. SFT —— 用指令数据微调，得到能对话的初始策略 π_SFT
2. 奖励建模 —— 用人类偏好对训练奖励模型 r_θ，学会「打分」
3. PPO —— 用 r_θ 作为奖励，强化学习优化策略 π

损失（PPO 阶段）：
maximize E[ r_θ(x, y) - β·KL(π(y|x) ‖ π_ref(y|x)) ]
KL 项防止策略偏离参考模型太远，避免「奖励黑客」。
```

```python
import torch

# 奖励模型的训练：给「好的回答」打高分，「差的回答」打低分（Bradley-Terry）
def reward_model_loss(r_chosen, r_rejected):
    # 好的回答分数应高于差的回答
    return -torch.log(torch.sigmoid(r_chosen - r_rejected)).mean()

r_chosen = torch.tensor([2.5, 3.0, 1.8])
r_rejected = torch.tensor([0.5, 1.0, 0.2])
print(f'奖励模型 loss = {reward_model_loss(r_chosen, r_rejected).item():.3f}')
```

## PPO

PPO（Proximal Policy Optimization）是 RLHF 里优化策略的强化学习算法。它用「截断的重要性采样比」限制每次更新的幅度，防止策略更新过大导致训练崩溃，是 RLHF 的事实标准优化器。

```text
PPO 核心：截断目标
L = E[ min(r_t(θ)·Â_t, clip(r_t(θ), 1-ε, 1+ε)·Â_t) ]

其中 r_t(θ) = π_θ(a|s) / π_old(a|s) 是新旧策略的概率比，Â 是优势函数。

关键点：
1. 截断 —— r_t 被限制在 [1-ε, 1+ε]，防止更新过大
2. 优势函数 —— 用 GAE 估计，衡量动作比平均好多少
3. 多轮小步更新 —— 同一批数据更新多次，但要限制幅度
```

```python
import torch

def ppo_loss(ratio, advantage, eps=0.2):
    # ratio: 新策略/旧策略概率比；advantage: 优势函数
    clipped = torch.clamp(ratio, 1 - eps, 1 + eps)
    return -torch.min(ratio * advantage, clipped * advantage).mean()

# 模拟：ratio 偏离 1 太远会被截断
ratio = torch.tensor([0.5, 1.0, 1.5, 2.0])
advantage = torch.tensor([1.0, 1.0, 1.0, 1.0])
print(f'PPO loss = {ppo_loss(ratio, advantage).item():.3f}')

# KL 惩罚：防止策略偏离参考模型太远（RLHF 中的稳定项）
def kl_penalty(log_probs_policy, log_probs_ref):
    return (log_probs_ref - log_probs_policy).mean()

lp_p, lp_ref = torch.tensor([-1.0, -1.5, -2.0]), torch.tensor([-1.2, -1.5, -1.8])
print(f'KL 惩罚 = {kl_penalty(lp_p, lp_ref).item():.3f}')
```

## DPO

DPO（Direct Preference Optimization）跳过了「训练奖励模型 + 强化学习」的复杂流程，直接从偏好对数据优化策略。它通过数学变换把 RLHF 的优化目标改写成只依赖策略和参考模型的分类损失，简单、稳定、省资源，是当前最流行的对齐方法。

```text
DPO 损失（直接偏好优化）：
L = -E[ log σ( β·log(π_θ(y_w|x)/π_ref(y_w|x)) - β·log(π_θ(y_l|x)/π_ref(y_l|x)) ) ]

关键点：
1. 无需奖励模型 —— 隐式奖励 = β·log(π_θ/π_ref)
2. 无需强化学习 —— 直接梯度下降，训练稳定
3. 需要参考模型 —— 冻结的 SFT 模型作为锚点
4. β 控制偏离参考模型的程度
```

```python
import torch
import torch.nn.functional as F

def dpo_loss(pi_chosen, pi_rejected, ref_chosen, ref_rejected, beta=0.1):
    """
    pi_*: 策略模型给好/坏回答的对数概率
    ref_*: 参考模型给好/坏回答的对数概率
    """
    pi_ratio = pi_chosen - pi_rejected
    ref_ratio = ref_chosen - ref_rejected
    logits = beta * (pi_ratio - ref_ratio)
    return -F.logsigmoid(logits).mean()

# 模拟一批偏好对
pi_chosen = torch.tensor([-1.0, -0.8, -1.2])
pi_rejected = torch.tensor([-1.5, -1.1, -1.9])
ref_chosen = torch.tensor([-1.1, -1.0, -1.3])
ref_rejected = torch.tensor([-1.3, -1.0, -1.6])
print(f'DPO loss = {dpo_loss(pi_chosen, pi_rejected, ref_chosen, ref_rejected).item():.3f}')
```

## IPO

IPO（Identity Preference Optimization）针对 DPO 的一个缺陷：DPO 的损失在训练后期会把「好回答 vs 坏回答」的概率差距推到无穷大，导致过拟合。IPO 用均方误差替代交叉熵，直接回归到一个目标概率比，训练更稳定、更不易过拟合。

```text
IPO vs DPO：
DPO：L = -log σ( β·(log(π_w/π_ref) - log(π_l/π_ref)) )，会把差距推向 +∞
IPO：L = ( log(π_w/π_ref) - log(π_l/π_ref) - 1/(2β) )²，回归到固定目标

核心区别：
1. DPO 用 sigmoid 交叉熵，本质是分类，容易过拟合
2. IPO 用 MSE，目标是让概率比的对数差等于常数 1/(2β)
3. IPO 天然有正则效果，对偏好数据噪声更鲁棒
```

```python
import torch

def ipo_loss(pi_chosen, pi_rejected, ref_chosen, ref_rejected, beta=0.5):
    # 目标：log(π_w/π_ref) - log(π_l/π_ref) 接近 1/(2β)
    log_ratio = (pi_chosen - ref_chosen) - (pi_rejected - ref_rejected)
    target = 1.0 / (2 * beta)
    return ((log_ratio - target) ** 2).mean()

pi_chosen = torch.tensor([-1.0, -0.8])
pi_rejected = torch.tensor([-1.5, -1.1])
ref_chosen = torch.tensor([-1.1, -1.0])
ref_rejected = torch.tensor([-1.3, -1.0])
print(f'IPO loss = {ipo_loss(pi_chosen, pi_rejected, ref_chosen, ref_rejected).item():.3f}')

# 对比：DPO 在 log_ratio 很大时 loss 趋近 0（过拟合），IPO 会惩罚偏离
log_ratio = torch.tensor([10.0, 20.0])   # 已经过度偏离
print(f'DPO 在过拟合时 loss = {-torch.nn.functional.logsigmoid(log_ratio).mean().item():.4f}（趋近 0）')
print(f'IPO 在过拟合时 loss = {((log_ratio - 1.0) ** 2).mean().item():.1f}（继续惩罚）')
```

## ORPO

ORPO（Odds Ratio Preference Optimization）把 SFT 和偏好对齐合并成一步训练：在标准 SFT 的交叉熵损失上，直接加一个「胜率比」的偏好项。它不需要参考模型，也不需要单独的 SFT 阶段，训练流程更简洁。

```text
ORPO 核心思想：
1. SFT 项 —— 标准 next-token 交叉熵，保持基础能力
2. 偏好项 —— odds ratio：log( π_θ(y_w)/ (1-π_θ(y_w)) ) 与 π_θ(y_l) 的比值
3. 无需参考模型 —— 用「胜率比」天然包含了对差回答的惩罚

损失：L = L_SFT + λ·L_ORPO

优势：一步到位、无需参考模型、训练数据只需偏好对。
```

```python
import torch
import torch.nn.functional as F

def orpo_loss(pi_chosen, pi_rejected, lambda_=1.0):
    """
    pi_chosen/pi_rejected: 策略给好/坏回答的对数概率
    """
    # 胜率比（odds ratio）：odds = p / (1 - p)
    log_odds_chosen = pi_chosen - F.logsigmoid(-pi_chosen)      # log(p_w/(1-p_w))
    log_odds_rejected = pi_rejected - F.logsigmoid(-pi_rejected)
    log_odds_ratio = log_odds_chosen - log_odds_rejected
    pref_term = -F.logsigmoid(log_odds_ratio).mean()
    return lambda_ * pref_term

pi_chosen = torch.tensor([-0.8, -1.0])
pi_rejected = torch.tensor([-1.6, -1.4])
print(f'ORPO 偏好项 loss = {orpo_loss(pi_chosen, pi_rejected).item():.3f}')

# SFT 项（与 ORPO 偏好项相加，构成总损失）
def orpo_total(pi_chosen, pi_rejected, sft_loss_val, lambda_=1.0):
    return sft_loss_val + orpo_loss(pi_chosen, pi_rejected, lambda_)

print(f'ORPO 总损失 = {orpo_total(pi_chosen, pi_rejected, sft_loss_val=2.0).item():.3f}')
```

## 应用场景实战

### 场景一：从偏好对训练 DPO（完整数据流）

```python
import torch
import torch.nn.functional as F

# 模拟一条偏好数据：同一个 prompt，好回答 vs 坏回答
def compute_log_prob(model_logits, token_ids):
    """给定模型 logits 和 token id，算整句的平均对数概率"""
    log_probs = F.log_softmax(model_logits, dim=-1)
    # 取每个位置对应 token 的 log prob，求平均
    gathered = log_probs.gather(-1, token_ids.unsqueeze(-1)).squeeze(-1)
    return gathered.mean(dim=-1)

# 模拟两个模型的 logits（这里用随机值演示流程）
B = 4
model_logits_chosen = torch.randn(B, 10, 100)
model_logits_rejected = torch.randn(B, 10, 100)
ref_logits_chosen = torch.randn(B, 10, 100)
ref_logits_rejected = torch.randn(B, 10, 100)
chosen_ids = torch.randint(0, 100, (B, 10))
rejected_ids = torch.randint(0, 100, (B, 10))

pi_c = compute_log_prob(model_logits_chosen, chosen_ids)
pi_r = compute_log_prob(model_logits_rejected, rejected_ids)
ref_c = compute_log_prob(ref_logits_chosen, chosen_ids)
ref_r = compute_log_prob(ref_logits_rejected, rejected_ids)

print(f'DPO loss = {dpo_loss(pi_c, pi_r, ref_c, ref_r, beta=0.1).item():.3f}')
```

### 场景二：监控对齐过程中的指标

```python
# 对齐训练中需要监控的三大指标
def monitor_metrics(pi_chosen, pi_rejected, ref_chosen, ref_rejected, beta=0.1):
    # 1. 胜率（accuracy）：好回答概率是否高于坏回答
    win = ((pi_chosen - pi_rejected) > 0).float().mean()
    # 2. 隐式奖励差距
    reward_gap = (pi_chosen - pi_rejected - (ref_chosen - ref_rejected)).mean()
    # 3. 与参考模型的 KL 散度（不应过大）
    kl = (ref_chosen - pi_chosen).mean()
    return win, reward_gap, kl

pi_c = torch.tensor([-1.0, -0.8, -1.2, -0.9])
pi_r = torch.tensor([-1.5, -1.1, -1.3, -1.4])
ref_c = torch.tensor([-1.1, -1.0, -1.1, -1.0])
ref_r = torch.tensor([-1.2, -1.0, -1.2, -1.2])

win, gap, kl = monitor_metrics(pi_c, pi_r, ref_c, ref_r)
print(f'偏好胜率 = {win:.0%}，奖励差距 = {gap:.3f}，KL 散度 = {kl:.3f}')
# 理想状态：胜率趋近 1，KL 保持在合理范围（别偏离参考太远）
```

## 最佳实践与踩坑记录

### 最佳实践

1. 偏好数据质量决定对齐上限，人工标注好于 AI 自标注，标注标准要统一
2. 优先用 DPO 而非 RLHF，DPO 简单稳定且效果接近，除非有充足算力和调参经验
3. DPO 的 β 要调：太小会过拟合偏好、太大对齐不足，从 0.1 附近开始扫
4. 始终监控与参考模型的 KL 散度，防止策略跑飞（奖励黑客）
5. 对齐会损失一部分多样性，追求有用性时别把采样温度压太低
6. ORPO 适合快速迭代，一步完成 SFT+对齐，省去参考模型

### 踩坑记录

```text
坑 1：奖励黑客（reward hacking）
结论：奖励分数很高，但回答质量反而变差。
原因：策略学会了钻奖励模型的空子，产出高分但不真实的回答。
解法：加 KL 惩罚限制偏离、提升奖励模型鲁棒性、用人类评估兜底。

坑 2：DPO 过拟合偏好数据
结论：训练集胜率接近 100%，但泛化到新 prompt 效果变差。
原因：DPO 把好/坏回答的概率差距推到无穷，记住了训练样本。
解法：换 IPO（MSE 回归）、调大 β、加早停和数据增强。

坑 3：忽略 KL 散度导致模型跑飞
结论：对齐后模型生成语法错误、重复、无意义文本。
原因：策略过度偏离参考模型，语言能力被破坏。
解法：监控 KL，超过阈值就停止或增大 β/调低学习率。

坑 4：偏好数据有偏差（长度偏差、位置偏差）
结论：模型学到「回答越长越好」或「总选第二个」等伪偏好。
原因：标注时好回答往往更长、或固定放同一位置。
解法：长度归一化、随机交换好坏位置、用多模型混合标注。

坑 5：对齐后模型「过度谨慎」
结论：模型频繁拒绝合理请求，变得无用。
原因：安全对齐过强，把无害请求也当成有害。
解法：在有用性和无害性间平衡，用更精细的安全数据，调整拒绝阈值。
```

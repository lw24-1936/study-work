## 概述

微调（Fine-Tuning）是在预训练模型基础上，用领域数据继续训练，让通用模型适应特定任务或风格。全量微调更新所有参数，成本高；参数高效微调（PEFT）只更新少量参数，用极低成本达到接近全量微调的效果，是当前的主流路线。

```text
微调方法谱系：
1. 全量微调（Full Fine-Tuning）—— 更新全部参数，效果上限高，成本高
2. SFT —— 指令微调，让 base model 学会「听指令」
3. LoRA —— 低秩适配，冻结原权重，只训练低秩增量矩阵
4. QLoRA —— LoRA + 4bit 量化，显存再降一个数量级
5. Adapter / Prefix / Prompt Tuning —— 更轻量的参数高效方案

选择原则：
显存充足且要极致效果 → 全量微调
单卡有限显存 → LoRA / QLoRA
只做简单任务适配 → Adapter / Prompt Tuning
```

```python
import torch
import torch.nn as nn

# 一个可微调的简单模型
class Model(nn.Module):
    def __init__(self, dim=64):
        super().__init__()
        self.embed = nn.Embedding(1000, dim)
        self.fc = nn.Linear(dim, 10)

    def forward(self, x):
        return self.fc(self.embed(x).mean(dim=1))

model = Model()
total = sum(p.numel() for p in model.parameters())
trainable = sum(p.numel() for p in model.parameters() if p.requires_grad)
print(f'总参数 {total}，可训练 {trainable}（微调前全部可训练）')
```

## Full Fine-Tuning

全量微调是更新预训练模型的所有参数，用目标任务的数据继续训练。它调整空间最大、理论上限最高，但需要存储和更新全部参数，显存和算力开销大，也容易发生灾难性遗忘。

```text
全量微调的特点：
1. 更新全部参数 —— 模型可以充分适应新任务
2. 效果上限高 —— 没有参数冻结带来的约束
3. 成本高 —— 需要保存完整梯度、优化器状态，显存是推理的数倍
4. 灾难性遗忘 —— 新任务训练可能冲掉预训练学到的通用能力

显存估算（7B 模型，AdamW + fp16）：
权重 14GB + 梯度 14GB + 优化器状态 28GB ≈ 56GB，单卡很难装下。
```

```python
import torch
import torch.nn as nn

# 全量微调：所有参数都开启梯度，参与更新
def full_finetune_setup(model):
    for p in model.parameters():
        p.requires_grad = True
    optimizer = torch.optim.AdamW(model.parameters(), lr=1e-5)
    return optimizer

optimizer = full_finetune_setup(Model())
trainable = sum(p.numel() for p in model.parameters() if p.requires_grad)
total = sum(p.numel() for p in model.parameters())
print(f'全量微调：可训练 {trainable}/{total} = {trainable/total:.0%}')
```

## SFT

监督微调（SFT，Supervised Fine-Tuning）是用「指令-回答」对训练模型，让预训练的 base model 学会遵循指令、对齐对话格式。它是对齐流程的第一步：base model → SFT → 偏好对齐（RLHF/DPO）。

```text
SFT 的关键点：
1. 数据 —— (instruction, input, output) 三元组，通常是人工或 GPT 生成的高质量问答
2. 目标 —— 仍是最小化 next-token 交叉熵，只是数据换成了指令对
3. 格式 —— 用统一的 chat template（如 <|user|>、<|assistant|>）包装
4. 损失掩码 —— 只在回答部分计算 loss，指令部分不参与

SFT 之后模型学会了「对话」，但可能仍有对齐/安全问题，需进一步对齐。
```

```python
import torch
import torch.nn.functional as F

# SFT 的核心：只在回答部分计算 loss（损失掩码）
def sft_loss(logits, labels, loss_mask):
    """
    logits: [B, T, V]
    labels: [B, T]  token id
    loss_mask: [B, T] 1 表示回答部分，0 表示指令部分
    """
    loss = F.cross_entropy(
        logits.view(-1, logits.size(-1)),
        labels.view(-1),
        reduction='none',
    )
    loss = loss.view(labels.shape)
    masked_loss = (loss * loss_mask).sum() / loss_mask.sum()
    return masked_loss

# 模拟一条数据：指令 + 回答，只在回答上算 loss
B, T, V = 2, 10, 1000
logits = torch.randn(B, T, V)
labels = torch.randint(0, V, (B, T))
loss_mask = torch.cat([torch.zeros(B, 4), torch.ones(B, 6)], dim=1)  # 前4是指令
print(f'SFT loss = {sft_loss(logits, labels, loss_mask).item():.3f}')

# chat template 示例
def apply_chat_template(instruction, response):
    return f"<|user|>\n{instruction}\n<|assistant|>\n{response}\n<|end|>"
print(apply_chat_template("解释什么是 LoRA", "LoRA 是一种低秩适配方法..."))
```

## LoRA

LoRA（Low-Rank Adaptation）冻结预训练权重，在旁路加一个低秩矩阵对 ΔW = BA 来近似权重更新，只训练这个低秩增量。它把可训练参数从数十亿降到数百万，显存和训练速度都大幅改善，是应用最广的 PEFT 方法。

```text
LoRA 原理：
原始：h = W·x
LoRA：h = W·x + ΔW·x = W·x + (B·A)·x

其中 W ∈ R^(d×d) 冻结，A ∈ R^(r×d)，B ∈ R^(d×r)，r << d（如 r=8、16、64）。
训练时 W 不变，只更新 A 和 B。初始化 A 高斯、B 为零，保证 ΔW 从 0 开始。

可训练参数量：2·r·d，相对 d² 大幅下降。
```

```python
import torch
import torch.nn as nn

class LoRALinear(nn.Module):
    def __init__(self, in_dim, out_dim, r=8, alpha=16):
        super().__init__()
        self.linear = nn.Linear(in_dim, out_dim, bias=False)
        self.linear.weight.requires_grad = False      # 冻结原权重
        self.lora_A = nn.Parameter(torch.randn(r, in_dim) * 0.01)
        self.lora_B = nn.Parameter(torch.zeros(out_dim, r))
        self.scale = alpha / r

    def forward(self, x):
        base = self.linear(x)
        delta = (x @ self.lora_A.T @ self.lora_B.T) * self.scale
        return base + delta

d = 512
layer = LoRALinear(d, d, r=8)
total = sum(p.numel() for p in layer.parameters())
trainable = sum(p.numel() for p in layer.parameters() if p.requires_grad)
print(f'LoRA: 总参数 {total}，可训练 {trainable} ({trainable/total:.2%})')

x = torch.randn(4, d)
print(f'输出形状 = {layer(x).shape}')
```

## QLoRA

QLoRA 在 LoRA 的基础上把冻结的基座权重量化到 4bit（NF4 格式），并引入双重量化（量化常数的再量化）和分页优化器。它让 65B 模型能在单张 48GB 卡上微调，显存需求比 LoRA 再降一个数量级，且效果几乎不损失。

```text
QLoRA 的四个关键技术：
1. NF4 量化 —— 4bit NormalFloat 格式，对正态分布的权重量化误差最小
2. 双重量化 —— 量化常数本身再做一次量化，进一步省显存
3. 分页优化器 —— 显存峰值时把优化器状态换到 CPU，避免 OOM
4. LoRA 适配器 —— 低秩增量以 fp16/bf16 训练，保证精度

效果：4bit 基座 + LoRA 微调，性能接近 16bit 全量微调。
```

```python
import torch

# 模拟 4bit 量化 + 反量化（示意 NF4 思路，实际用 bitsandbytes）
def quantize_4bit(weight):
    # 把 fp16 权重量化到 4bit：缩放到 [-8, 7] 的整数
    w_min, w_max = weight.min(), weight.max()
    scale = (w_max - w_min) / 15.0
    q = torch.clamp(torch.round((weight - w_min) / scale), 0, 15).to(torch.uint8)
    return q, w_min, scale

def dequantize_4bit(q, w_min, scale):
    return q.float() * scale + w_min

w = torch.randn(1024, 1024, dtype=torch.float16)
q, w_min, scale = quantize_4bit(w)
w_hat = dequantize_4bit(q, w_min, scale)
err = (w - w_hat).abs().mean().item()
print(f'4bit 量化平均误差 = {err:.6f}')
print(f'显存节省 = 16bit 2MB → 4bit {q.numel()/2/1e6:.2f} MB（约 1/4）')
```

## Adapter

Adapter 是在 Transformer 的每个 block 里插入一个小型瓶颈网络（先降维再升维），微调时冻结原模型，只训练这些 Adapter。每个 Adapter 参数量极小，且不同任务的 Adapter 可以独立保存、即插即用。

```text
Adapter 结构：
残差连接处插入：x → Down(d→m) → 激活 → Up(m→d) → 残差
其中 m << d（瓶颈维度，如 64）

特点：
1. 参数极少 —— 每个 Adapter 只占原层参数的百分之几
2. 任务隔离 —— 每个任务一个 Adapter，切换任务只需换 Adapter
3. 稍增推理延迟 —— 串联的瓶颈层会增加少量计算
```

```python
import torch
import torch.nn as nn

class Adapter(nn.Module):
    def __init__(self, d_model, bottleneck=64):
        super().__init__()
        self.down = nn.Linear(d_model, bottleneck)
        self.up = nn.Linear(bottleneck, d_model)
        self.act = nn.ReLU()
        # 初始化：up 层接近零，保证初始时 adapter 近似恒等
        nn.init.zeros_(self.up.weight)

    def forward(self, x):
        return x + self.up(self.act(self.down(x)))   # 残差结构

x = torch.randn(4, 512)
adapter = Adapter(512, bottleneck=64)
trainable = sum(p.numel() for p in adapter.parameters())
print(f'单个 Adapter 参数量 = {trainable}（相对 512×512 层极小）')
print(f'输出形状 = {adapter(x).shape}')
```

## Prefix Tuning

Prefix Tuning 在输入序列前拼接一段可训练的「前缀」向量（prefix），微调时冻结模型，只训练这段前缀。前缀向量通过注意力机制影响后续所有 token 的生成，相当于给模型「注入」了任务指令。

```text
Prefix Tuning 原理：
输入 = [prefix_1, ..., prefix_p, x_1, ..., x_T]
前缀是 p 个可训练的连续向量，参与每一层的注意力。

关键点：
1. 只训练前缀向量 —— 参数量极小（p × d × 层数）
2. 前缀影响全局 —— 每个位置都能 attend 到前缀，作用类似软提示
3. 稳定性 —— 前缀向量经 MLP 重参数化，训练更稳
```

```python
import torch
import torch.nn as nn

class PrefixTuning(nn.Module):
    def __init__(self, n_layer, d_model, prefix_len=16):
        super().__init__()
        self.prefix_len = prefix_len
        # 每层一个可训练前缀向量
        self.prefix = nn.Parameter(torch.randn(n_layer, prefix_len, d_model) * 0.01)

    def forward(self, layer_idx, hidden_states):
        # 把前缀拼到序列最前面
        prefix = self.prefix[layer_idx].unsqueeze(0).expand(hidden_states.size(0), -1, -1)
        return torch.cat([prefix, hidden_states], dim=1)

n_layer, d_model = 2, 64
pt = PrefixTuning(n_layer, d_model, prefix_len=16)
trainable = sum(p.numel() for p in pt.parameters())
print(f'Prefix Tuning 参数量 = {trainable}')

x = torch.randn(4, 10, d_model)
print(f'拼接前缀后形状 = {pt(0, x).shape}')
```

## Prompt Tuning

Prompt Tuning 是比 Prefix Tuning 更极端的方案：只在输入层加可训练的软提示（soft prompt），模型内部完全不改。它对小模型效果有限，但模型越大效果越接近全量微调，是「零侵入」式微调的代表。

```text
Prompt Tuning vs Prefix Tuning：
1. Prefix Tuning —— 每层都加前缀，可训练量更大
2. Prompt Tuning —— 只在 embedding 层加软提示，可训练量最小

Prompt Tuning 特点：
1. 参数量最小 —— 只需 prompt_len × d_model 个参数
2. 不侵入模型 —— 模型完全冻结，推理无需改动
3. 规模敏感 —— 小模型效果差，大模型（>10B）才接近微调
```

```python
import torch
import torch.nn as nn

class PromptTuning(nn.Module):
    def __init__(self, d_model, prompt_len=16):
        super().__init__()
        self.soft_prompt = nn.Parameter(torch.randn(prompt_len, d_model) * 0.01)

    def forward(self, input_embeds):
        # input_embeds: [B, T, d]
        prompt = self.soft_prompt.unsqueeze(0).expand(input_embeds.size(0), -1, -1)
        return torch.cat([prompt, input_embeds], dim=1)

d_model = 64
prompt = PromptTuning(d_model, prompt_len=16)
print(f'Prompt Tuning 参数量 = {sum(p.numel() for p in prompt.parameters())}')
x_emb = torch.randn(4, 10, d_model)
print(f'软提示 + embedding 形状 = {prompt(x_emb).shape}')
```

## 应用场景实战

### 场景一：用 LoRA 微调一个小模型（对比可训练参数量）

```python
import torch
import torch.nn as nn

# 把 LoRA 应用到模型的所有线性层
def apply_lora_to_linear(module, r=8, alpha=16):
    for name, child in module.named_children():
        if isinstance(child, nn.Linear):
            setattr(module, name, LoRALinear(child.in_features, child.out_features, r, alpha))
        else:
            apply_lora_to_linear(child, r, alpha)

class SmallModel(nn.Module):
    def __init__(self, d=128):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(d, d), nn.ReLU(),
            nn.Linear(d, d), nn.ReLU(),
            nn.Linear(d, 10),
        )

    def forward(self, x):
        return self.net(x)

model = SmallModel()
total_before = sum(p.numel() for p in model.parameters())
apply_lora_to_linear(model, r=8)
total_after = sum(p.numel() for p in model.parameters())
trainable = sum(p.numel() for p in model.parameters() if p.requires_grad)
print(f'应用 LoRA 前总参数: {total_before}')
print(f'应用 LoRA 后可训练: {trainable} / 总 {total_after} ({trainable/total_after:.2%})')

x = torch.randn(4, 128)
print(f'微调输出形状 = {model(x).shape}')
```

### 场景二：LoRA 合并回基座权重用于推理

```python
# 训练完 LoRA 后，把增量合并回原权重，推理时无额外开销
def merge_lora(lora_layer):
    delta = (lora_layer.lora_B @ lora_layer.lora_A) * lora_layer.scale
    merged = lora_layer.linear.weight.data + delta
    return merged

layer = LoRALinear(128, 128, r=8)
merged_w = merge_lora(layer)
print(f'合并后权重形状 = {merged_w.shape}（与原始 W 一致，可替换推理）')

# 验证合并等价性：合并前 forward == 合并后线性层 forward
x = torch.randn(2, 128)
out_lora = layer(x)
out_merged = x @ merged_w.T
print(f'合并前后输出最大差异 = {(out_lora - out_merged).abs().max().item():.2e}')
```

## 最佳实践与踩坑记录

### 最佳实践

1. 显存有限就用 LoRA/QLoRA，先用小 rank（8/16）试，效果不够再加大
2. LoRA 的 alpha 通常设为 2 倍 rank，学习率比全量微调大 1-2 个数量级
3. SFT 数据质量比数量重要，几千条高质量指令对往往胜过几十万条噪声数据
4. 一定要在回答部分用 loss mask，别把指令部分也纳入损失
5. 多任务场景用 Adapter 或独立 LoRA 模块，一个任务一个适配器，即插即用
6. 微调前先冻结基座 + 只训练适配器，避免灾难性遗忘

### 踩坑记录

```text
坑 1：SFT 数据没做 loss mask
结论：模型既学回答也学指令，生成长度失控、质量下降。
原因：指令部分也被计入交叉熵，模型试图「复述指令」。
解法：用 loss mask 只在 assistant 回答 token 上算 loss。

坑 2：LoRA rank 开太大
结论：rank=256 时参数量和全量微调差不多，失去 LoRA 意义。
原因：误以为 rank 越大越好，忽视了低秩假设。
解法：从 r=8/16 起步，用验证集调，多数任务 r≤64 足够。

坑 3：LoRA 学习率沿用全量微调的
结论：训练不收敛或收敛极慢。
原因：LoRA 只更新低秩矩阵，需要更大的学习率。
解法：LoRA 学习率通常 1e-4 量级，比全量微调（1e-5）大一个数量级。

坑 4：QLoRA 直接量化训练不稳定
结论：4bit 量化后直接用 Adam 训练出现 NaN 或发散。
原因：量化误差 + 大梯度导致低精度下溢出。
解法：用 bitsandbytes 的 NF4 + 分页优化器，梯度在 fp16/bf16 下计算。

坑 5：微调后灾难性遗忘
结论：领域任务变好，但通用能力、安全对齐显著退化。
原因：全量微调大幅更新权重，冲掉了预训练知识。
解法：用 PEFT（LoRA/Adapter）冻结基座，或混合通用+领域数据，降低学习率。
```

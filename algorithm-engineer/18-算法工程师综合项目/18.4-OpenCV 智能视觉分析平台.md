## 概述

本项目搭建一套接入摄像头/RTSP 视频流的智能视觉分析平台：实时拉流 → OpenCV 解码预处理 → 目标检测 → 多目标跟踪 → OCR 文字识别 → 业务分析（人体/车辆/物体统计），结果经 FastAPI 服务化对外输出，GPU 加速保障实时性。业务价值在于把 CV 能力从「单张图片 demo」变成「7×24 小时跑在生产上的视频分析服务」，典型落地场景是安防监控、园区车辆统计、零售客流分析。

```text
平台核心能力：
1. 视频接入 —— 摄像头/USB/RTSP 统一拉流，断线重连
2. 实时解码 —— OpenCV 抓帧、缩放、颜色转换
3. 目标检测 —— 检测人/车/物体，输出框 + 类别 + 置信度
4. 多目标跟踪 —— 跨帧关联同一目标，分配稳定 ID
5. OCR —— 车牌/证件/屏幕文字识别
6. 业务分析 —— 人数统计、车辆计数、越界/区域入侵
7. 服务化 —— FastAPI 提供检测/统计接口
8. GPU 加速 —— CUDA/TensorRT 提升推理吞吐
```

## 技术选型

| 环节 | 选择 | 理由 | 备选 |
|---|---|---|---|
| 视频接入 | OpenCV VideoCapture | 支持 RTSP/USB/文件统一接口 | FFmpeg、GStreamer |
| 图像处理 | OpenCV | 解码/缩放/颜色转换一站式，C++ 底层快 | PIL（慢）、scikit-image |
| 目标检测 | YOLOv8 | 速度和精度平衡好，生态完善 | Faster R-CNN、DETR |
| 多目标跟踪 | ByteTrack | 关联策略简单高效，MOT 榜单靠前 | DeepSORT、SORT |
| OCR | PaddleOCR | 中文识别强、部署方便 | Tesseract、CRNN |
| 服务化 | FastAPI | 异步支持好，配合 WebSocket 推流 | Flask、gRPC |
| GPU 加速 | TensorRT + CUDA | 推理吞吐提升 3-5 倍 | OpenVINO（Intel 平台） |

选型原则：实时视频分析的核心矛盾是「单帧处理延迟 × 帧率」必须跟上流，所以检测用 YOLO、跟踪用 ByteTrack、推理用 TensorRT，全程围绕「低延迟 + 高吞吐」选型。

```python
from ultralytics import YOLO

# YOLO 检测 + ByteTrack 跟踪的一体化调用
model = YOLO("yolov8n.pt")
results = model.track(source="rtsp://cam/stream", tracker="bytetrack.yaml", persist=True)
for r in results:
    for box in r.boxes:
        x1, y1, x2, y2 = box.xyxy[0].tolist()   # 框坐标
        cls = int(box.cls[0])                    # 类别
        track_id = int(box.id[0]) if box.id is not None else -1   # 跟踪 ID
        print(f"track={track_id} cls={cls} box={x1:.0f},{y1:.0f},{x2:.0f},{y2:.0f}")
```

## 架构设计

平台分「采集 → 推理 → 分析 → 输出」四层。采集层统一视频源接入，推理层跑检测/跟踪/OCR，分析层做业务逻辑（计数、越界），输出层经 FastAPI 对外提供 REST/WebSocket 接口。

```text
┌────────────────────────────────────────────────────┐
│ 采集层   RTSP/USB 拉流 → OpenCV 解码 → 帧队列        │
│          │                                         │
│ 推理层   目标检测(YOLO) → 多目标跟踪(ByteTrack)      │
│          │              → OCR(PaddleOCR)            │
│          │                                         │
│ 分析层   人体/车辆/物体统计、越界检测、区域入侵        │
│          │                                         │
│ 输出层   FastAPI REST + WebSocket 推送结果           │
└────────────────────────────────────────────────────┘
```

```python
# 生产者-消费者：拉流线程和推理线程解耦，用队列缓冲
import queue, threading
import cv2

frame_queue = queue.Queue(maxsize=30)

def producer(rtsp_url):
    cap = cv2.VideoCapture(rtsp_url)
    while True:
        ret, frame = cap.read()
        if ret:
            frame_queue.put(frame)

def consumer():
    while True:
        frame = frame_queue.get()
        dets = detector.detect(frame)
        process(frame, dets)

threading.Thread(target=producer, args=(rtsp_url,), daemon=True).start()
threading.Thread(target=consumer, daemon=True).start()
```

## 摄像头与 RTSP

视频源统一用 OpenCV VideoCapture 接入，支持 RTSP 网络流、USB 摄像头、本地文件。RTSP 流的坑在断线：网络抖动会导致 read 返回 False，必须做断线重连，否则服务静默丢帧。

```python
import cv2
import time

def open_stream(url, max_retries=5):
    for i in range(max_retries):
        cap = cv2.VideoCapture(url)
        if cap.isOpened():
            return cap
        time.sleep(2 ** i)        # 指数退避重连
    raise RuntimeError(f"无法连接视频源: {url}")

def read_with_reconnect(cap, url):
    ret, frame = cap.read()
    if not ret:
        cap.release()
        cap = open_stream(url)    # 断线重连
        return cap, None
    return cap, frame

cap = open_stream("rtsp://192.168.1.10:554/stream")
cap, frame = read_with_reconnect(cap, "rtsp://192.168.1.10:554/stream")
```

```text
视频接入要点：
1. 统一接口 —— RTSP/USB/文件都走 VideoCapture
2. 断线重连 —— read 返回 False 时释放并重连，指数退避
3. 缓冲调优 —— 设置 CAP_PROP_BUFFERSIZE 降低延迟，避免积压旧帧
4. 帧队列 —— 拉流和推理解耦，用有界队列防内存爆掉
```

## OpenCV

OpenCV 承担视频解码和图像预处理：抓帧、缩放、颜色转换（BGR→RGB）、ROI 裁剪。注意 OpenCV 默认 BGR 通道顺序，和深度学习模型的 RGB 输入不一致，转换时别搞反。

```python
import cv2

cap = cv2.VideoCapture(0)
ret, frame = cap.read()
# 预处理：缩放 + BGR 转 RGB + 归一化
frame = cv2.resize(frame, (640, 640))
rgb = cv2.cvtColor(frame, cv2.COLOR_BGR2RGB)     # BGR → RGB，喂模型前必做
roi = frame[100:400, 200:500]                     # 裁剪感兴趣区域
gray = cv2.cvtColor(frame, cv2.COLOR_BGR2GRAY)    # 灰度（OCR/边缘检测用）
```

```text
OpenCV 预处理要点：
1. BGR → RGB —— OpenCV 读入是 BGR，深度学习模型要 RGB
2. 缩放 —— 检测模型固定输入尺寸（如 640×640），先 resize
3. 归一化 —— 像素值 /255 或按模型 mean/std 归一化
4. 帧率控制 —— 按目标帧率跳帧处理，避免堆积
```

## 目标检测

目标检测定位画面里的人、车、物体，输出边界框 + 类别 + 置信度。本项目用 YOLOv8，一张图一次前向输出所有目标，速度适合实时场景。传统方法和深度方法对比见 [[13.7-目标检测传统方法]]。

```python
from ultralytics import YOLO

model = YOLO("yolov8n.pt")          # 加载预训练模型
results = model("scene.jpg", conf=0.5)   # 置信度阈值 0.5

for r in results:
    boxes = r.boxes
    for box in boxes:
        cls_name = model.names[int(box.cls[0])]   # 类别名
        conf = float(box.conf[0])                  # 置信度
        x1, y1, x2, y2 = box.xyxy[0].tolist()      # 坐标
        print(f"{cls_name} {conf:.2f} @ ({x1:.0f},{y1:.0f})-({x2:.0f},{y2:.0f})")
```

```text
目标检测选型：
1. YOLO 系列 —— 单阶段、速度快，适合实时
2. Faster R-CNN —— 双阶段、精度高，适合离线
3. 置信度阈值 —— 调 conf 平衡漏检/误检
4. NMS —— 重叠框去重，IOU 阈值一般 0.45-0.5
```

## 多目标跟踪

多目标跟踪给每个目标分配一个跨帧稳定的 ID，是「计数」和「轨迹分析」的前提。本项目用 ByteTrack：先匹配高分检测框，再用低分框二次关联，简单高效，比 DeepSORT 少了外观特征计算。

```python
import numpy as np
from scipy.optimize import linear_sum_assignment

def iou(a, b):
    """计算两个框的 IOU"""
    x1 = max(a[0], b[0]); y1 = max(a[1], b[1])
    x2 = min(a[2], b[2]); y2 = min(a[3], b[3])
    inter = max(0, x2 - x1) * max(0, y2 - y1)
    union = (a[2]-a[0])*(a[3]-a[1]) + (b[2]-b[0])*(b[3]-b[1]) - inter
    return inter / (union + 1e-9)

def associate(trackers, detections, iou_thresh=0.3):
    """匈牙利算法做框匹配：跟踪框 vs 检测框"""
    n, m = len(trackers), len(detections)
    cost = np.zeros((n, m))
    for i, t in enumerate(trackers):
        for j, d in enumerate(detections):
            cost[i, j] = 1 - iou(t, d)          # 距离 = 1 - IOU
    row, col = linear_sum_assignment(cost)
    matches = [(i, j) for i, j in zip(row, col) if cost[i, j] < 1 - iou_thresh]
    return matches
```

```text
多目标跟踪要点：
1. 两阶段关联 —— 高分配框先匹配，低分框二次关联（ByteTrack 核心）
2. 状态管理 —— 连续多帧未匹配才删除轨迹，避免 ID 跳变
3. 计数规则 —— 用「过线/进区域」事件计数，而非逐帧累加目标数
4. 遮挡处理 —— 遮挡后重识别困难，可结合外观特征（DeepSORT）
```

## OCR

OCR 识别画面中的文字，典型用途是车牌识别、证件识别、屏幕文字提取。本项目用 PaddleOCR，中文识别效果好，检测 + 识别两阶段流水线，详见 [[13.11-OCR]]。

```python
from paddleocr import PaddleOCR

ocr = PaddleOCR(use_angle_cls=True, lang="ch")
result = ocr.ocr("plate.jpg", cls=True)
for line in result:
    for box, (text, score) in line:
        if score > 0.5:
            print(f"{text} ({score:.2f})")
```

```text
OCR 在视觉平台里的用法：

3. 屏幕文字 —— 识别大屏/监控里的文字内容

```

## 人体车辆物体分析

业务分析层把检测和跟踪结果转成业务指标：人数统计、车辆计数、越界检测、区域入侵。核心是用跟踪 ID 做去重计数，用框与虚拟线/区域的位置关系判定事件。

```python
def line_crossing(tracks, line_y, direction="down"):
    """越线计数：跟踪框中心跨过虚拟线时计一次"""
    events = []
    for track in tracks:
        tid, cy_prev, cy_cur = track.id, track.prev_center_y, track.center_y
        if direction == "down" and cy_prev < line_y <= cy_cur:
            events.append((tid, "down"))       # 从上往下越线
        elif direction == "up" and cy_prev > line_y >= cy_cur:
            events.append((tid, "up"))
    return events

def in_zone(box, zone):
    """区域入侵：框中心是否落在警戒区域内"""
    cx, cy = (box[0] + box[2]) / 2, (box[1] + box[3]) / 2
    x1, y1, x2, y2 = zone
    return x1 <= cx <= x2 and y1 <= cy <= y2
```

```text
业务分析要点：
1. 去重计数 —— 按跟踪 ID 计数，别按每帧检测框数累加
2. 越界检测 —— 比较前后帧中心点与虚拟线的位置关系
3. 区域入侵 —— 框中心或面积占比判断是否进区域
4. 轨迹分析 —— 记录目标轨迹，支撑停留时长、路径分析
```

## FastAPI 服务化

检测和分析结果通过 FastAPI 对外提供：REST 接口按需查询统计，WebSocket 实时推送告警。异步设计保证视频流处理和接口响应互不阻塞。

```python
from fastapi import FastAPI
from fastapi import WebSocket
import asyncio

app = FastAPI()
stats = {"person_count": 0, "vehicle_count": 0}
event_queue = asyncio.Queue()       # 分析层产出的告警事件队列

@app.get("/stats")
async def get_stats():
    return stats                       # REST：查询实时统计

@app.websocket("/ws/events")
async def ws_events(ws: WebSocket):
    await ws.accept()
    while True:
        event = await event_queue.get()   # 分析层产出的告警事件
        await ws.send_json(event)         # WebSocket 实时推送
```

```text
服务化要点：
1. REST —— 统计查询、单图检测等请求-响应场景
2. WebSocket —— 告警、实时检测结果等推送场景
3. 异步 —— 视频处理用后台任务，不阻塞接口
4. 负载 —— 多路视频源用进程池/多 worker 并行处理
```

## GPU 加速

视频分析对推理吞吐要求高，CPU 跑 YOLO 很难跟上多路流。GPU 加速分两层：CUDA 让模型在 GPU 上推理，TensorRT 进一步做算子融合、量化、精度降级，吞吐可提升 3-5 倍。详见 [[16.3-推理优化]]。

```python
from ultralytics import YOLO

# 指定 GPU 推理
model = YOLO("yolov8n.pt")
results = model(source="rtsp://cam/stream", device=0)   # device=0 用第一块 GPU

# 导出 TensorRT 引擎再推理
model.export(format="engine", half=True)     # FP16 TensorRT 引擎
trt_model = YOLO("yolov8n.engine")
results = trt_model("scene.jpg")             # 用 TensorRT 引擎推理
```

```text
GPU 加速要点：
1. CUDA —— 模型加载到 GPU，推理用 device=0
2. TensorRT —— 导出 engine 做算子融合 + FP16/INT8 量化
3. 批处理 —— 多路流拼 batch 提升 GPU 利用率
4. 显存 —— 关注显存占用，多路流需控制 batch 大小
```

### 场景一：园区车辆越线计数

```python
import cv2
import numpy as np

# 模拟一条越线计数流水线（用检测结果演示逻辑）
line_y = 300
track_history = {}   # track_id -> 上一帧中心 y

def process_frame(detections):
    """detections: [(track_id, x1, y1, x2, y2)]"""
    events = []
    for tid, x1, y1, x2, y2 in detections:
        cy = (y1 + y2) / 2
        prev = track_history.get(tid)
        if prev is not None and prev < line_y <= cy:
            events.append(tid)          # 从上往下越线
        track_history[tid] = cy
    return events

# 三帧模拟：车辆 1 在第二帧越过 line_y=300
frames = [
    [(1, 100, 280, 150, 350)],
    [(1, 105, 290, 155, 360)],
    [(1, 110, 320, 160, 390)],
]
count = set()
for dets in frames:
    count.update(process_frame(dets))
print(f"越线车辆数: {len(count)}")
```

## 最佳实践与踩坑记录

### 最佳实践

1. 拉流和推理用生产者-消费者队列解耦，避免网络抖动拖垮推理
2. 计数按跟踪 ID 去重，用越线/进区域事件触发，别逐帧累加
3. 喂模型前把 BGR 转 RGB，OpenCV 默认通道顺序和模型输入相反
4. 多路视频流拼 batch 跑 GPU，提升利用率；单路低延迟则逐帧处理
5. RTSP 断线必须做重连，否则服务静默丢帧无告警
6. 推理走 TensorRT 引擎，吞吐和延迟都优于直接跑 PyTorch 权重

### 踩坑记录

```text
坑 1：OpenCV 读入 BGR 直接喂 RGB 训练的模型
结论：检测结果全错，类别张冠李戴、置信度飘忽。
原因：OpenCV 默认 BGR 通道顺序，深度学习模型通常按 RGB 训练。
解法：cvtColor(frame, COLOR_BGR2RGB) 后再喂模型。

坑 2：RTSP 断线后 read 一直返回空帧不重连
结论：网络抖动后服务不再处理新帧，看起来像「卡死」。
原因：VideoCapture 断开后 read 返回 False，没做重连逻辑。
解法：read 返回 False 时 release 并指数退避重连。

坑 3：按检测框数逐帧累加统计人数
结论：同一人连续 30 帧被算成 30 个人，计数严重偏高。
原因：检测每帧都输出框，逐帧累加把同一目标重复计数。
解法：用跟踪 ID 去重，或按越线/进区域事件计数。

坑 4：帧队列无限增长导致内存泄漏
结论：推理慢于拉流时队列越积越多，内存被打爆。
原因：队列无界，生产者速度超过消费者。
解法：用有界队列（maxsize），满了丢弃旧帧保持实时性。

坑 5：CPU 跑 YOLO 处理多路流延迟超标
结论：多路视频流下 CPU 推理吞吐不够，帧堆积严重。
原因：YOLO 前向计算量大，CPU 算力不足。
解法：上 GPU + TensorRT 引擎，多路拼 batch 提升吞吐。
```

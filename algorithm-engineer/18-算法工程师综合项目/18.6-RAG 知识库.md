## 概述

本项目构建一个基于 RAG（Retrieval-Augmented Generation）的企业知识库问答系统：把文档解析、切块、向量化后存入向量库，查询时做混合检索（BM25 + 向量）、重排，再把检索到的上下文喂给 LLM 生成带引用来源的回答。业务价值在于让 LLM 能回答「私有知识」而非只靠参数记忆，并给出可追溯的出处，解决大模型幻觉和知识时效性问题。

```text
RAG 知识库核心链路：
1. 文档解析 —— PDF/Word/网页提取纯文本，清洗乱码
2. Chunk —— 按语义/固定长度切块，保证块粒度合适
3. Embedding —— 文本块向量化，捕获语义
4. Vector DB —— 向量入库，ANN 检索语义相近块
5. BM25 —— 关键词倒排检索，兜底精确匹配
6. Hybrid Retrieval —— 向量 + 关键词结果融合
7. Rerank —— 对候选块精排，选最相关的 TopK
8. LLM —— 拼接上下文生成答案，带引用
9. RAG Evaluation —— 评估检索质量和答案质量
```

```python
# RAG 问答主流程
def rag_answer(query, topk=5):
    sparse_hits = bm25_search(query)            # 关键词召回
    dense_hits = vector_search(embed(query))    # 向量召回
    candidates = hybrid_fusion(sparse_hits, dense_hits)   # 融合
    chunks = rerank(query, candidates, topk)    # 精排取 TopK
    context = "\n".join(chunks)
    answer = llm_generate(query, context)       # 生成答案
    return answer, chunks                        # 答案 + 引用来源
```

## 技术选型

| 环节 | 选择 | 理由 | 备选 |
|---|---|---|---|
| 文档解析 | PyMuPDF + docx | PDF/Word 提取最稳，速度比 marker 快 | marker（复杂版面）、Unstructured |
| 切块 | 递归字符切分 | 按分隔符层级切，语义完整 | 语义切分、固定长度 |
| Embedding | BGE 中文模型 | 中文检索效果好，归一化后内积检索 | OpenAI Embedding、m3e |
| Vector DB | FAISS / Milvus | FAISS 轻量本地，Milvus 分布式生产 | Qdrant、Chroma |
| 关键词检索 | BM25 | 专有名词/精确 ID 兜底 | Elasticsearch |
| 融合 | RRF | 无需调权、稳健 | 加权求和 |
| 重排 | Cross-Encoder | 交互式精排，精度最高 | LLM 重排 |
| 生成 | 开源 LLM（Qwen/ChatGLM） | 可私有化部署，成本可控 | GPT-4（云 API） |

选型原则：检索走「双路召回 + 精排」保证上下文质量，生成走 LLM 保证答案质量。向量路抓语义、关键词路抓精确匹配，两者缺一不可。

```python
from sentence_transformers import SentenceTransformer
from rank_bm25 import BM25Okapi

class RAGRetriever:
    def __init__(self, chunks):
        self.chunks = chunks
        self.bm25 = BM25Okapi([c.split() for c in chunks])
        self.encoder = SentenceTransformer("BAAI/bge-small-zh")
        self.vecs = self.encoder.encode(chunks, normalize_embeddings=True)

    def retrieve(self, query, topk=10):
        return self.bm25.get_top_n(query.split(), self.chunks, n=topk)  # 关键词
```

## 架构设计

系统分「离线建库」和「在线问答」两条链路。离线侧解析文档、切块、向量化、建索引；在线侧对查询做检索、重排、生成，并把检索到的块作为引用来源返回。

```text
离线建库                           在线问答
┌──────────────┐                  ┌──────────────┐
│ 文档库        │                  │ 用户 query    │
└──────┬───────┘                  └──────┬───────┘
       │ 解析/切块                        │ 向量化 + 分词
       ▼                                  ▼
┌──────────────┐   ┌──────────┐   ┌──────────────┐
│ 向量库        │   │ 倒排索引  │   │ 向量召回      │  关键词召回
└──────┬───────┘   └─────┬────┘   └──────┬───────┘
       └────────┬────────┘               │
                ▼                        ▼
         ┌──────────────┐        ┌──────────────┐
         │  离线入库     │        │ Hybrid 融合   │
         └──────────────┘        └──────┬───────┘
                                        ▼
                                 ┌──────────────┐
                                 │ Rerank 精排   │
                                 │ → LLM 生成    │
                                 │ → 引用来源     │
                                 └──────────────┘
```


## 文档解析

文档解析把 PDF/Word/网页转换成干净纯文本，是 RAG 质量的起点。解析不好（乱码、表格错乱、页眉页脚混入）后续全链路都受影响。本项目用 PyMuPDF 提 PDF 文本，docx 库提 Word，解析后清洗乱码和多余空白。

```python
import fitz   # PyMuPDF

def parse_pdf(path):
    doc = fitz.open(path)
    text = ""
    for page in doc:
        text += page.get_text()
    return clean_text(text)

def clean_text(text):
    # 清洗：去乱码字符、压缩空白、去页眉页脚
    text = text.replace("\ufffd", "")          # 去替换字符（乱码）
    text = " ".join(text.split())              # 压缩空白
    return text

def parse_docx(path):
    from docx import Document
    return "\n".join(p.text for p in Document(path).paragraphs)
```

```text
文档解析要点：
1. 格式覆盖 —— PDF/Word/Markdown/网页，不同格式不同解析器
2. 表格处理 —— 表格转成 markdown 或 key-value，直接抽文本会乱
3. 清洗 —— 去页眉页脚、乱码、水印，这些是噪声
4. 结构保留 —— 标题层级、章节信息对后续切块有帮助
```

## Chunk

切块把长文档切成适合检索的片段。块太大检索粒度粗、喂给 LLM 浪费 token；块太小语义不完整。本项目用递归字符切分，按段落/句子/字符的优先级切，保证语义边界不被切断。

```python
def recursive_split(text, chunk_size=500, overlap=50, separators=["\n\n", "\n", "。", " ", ""]):
    """递归切分：优先按大分隔符切，切不动再降级"""
    if len(text) <= chunk_size:
        return [text] if text.strip() else []
    sep = separators[0]
    if sep:
        parts = text.split(sep)
    else:
        parts = [text[i:i + chunk_size] for i in range(0, len(text), chunk_size)]
    chunks, current = [], ""
    for p in parts:
        if len(current) + len(p) <= chunk_size:
            current += p + sep
        else:
            if current.strip():
                chunks.append(current.strip())
            current = p + sep
    if current.strip():
        chunks.append(current.strip())
    return chunks

text = "第一段内容。\n\n第二段内容。\n\n第三段内容。"
print(recursive_split(text, chunk_size=10))
```

```text
切块策略：
1. 递归切分 —— 段落 → 句子 → 字符，优先保语义边界
2. 重叠 —— 相邻块重叠 10-15%，避免关键信息被切在边界
3. 块大小 —— 500-800 token 常用，取决于模型上下文和检索粒度
4. 元数据 —— 块带来源/章节信息，供引用和过滤
```

## Embedding

Embedding 把文本块编码成语义向量。RAG 检索质量直接取决于向量模型和语料的匹配度。中文场景用 BGE/m3e 等中文预训练模型，向量归一化后用内积做相似度。

```python
from sentence_transformers import SentenceTransformer

model = SentenceTransformer("BAAI/bge-small-zh")
chunks = ["如何配置数据库连接", "数据库连接池的配置方法", "前端页面的样式调整"]
vecs = model.encode(chunks, normalize_embeddings=True)

query = "数据库怎么连"
qv = model.encode([query], normalize_embeddings=True)
sims = (vecs @ qv.T).ravel()
for c, s in sorted(zip(chunks, sims), key=lambda x: -x[1]):
    print(f"{s:.3f}  {c}")
```

```text
Embedding 要点：
1. 归一化 —— L2 归一化后内积 = 余弦相似度
2. 中文模型 —— bge/m3e，别用英文模型硬套中文
3. 领域适配 —— 专业领域可 fine-tune，显著提升检索
4. 维度 —— 768/1024 常见，维度高信息多但存储大
```

## Vector DB

向量库存储文本块向量并提供 ANN 检索。本地小规模用 FAISS，生产分布式用 Milvus/Qdrant。核心是「向量 + 元数据」一起存，检索时按相似度取 TopK 块。

```python
import faiss
import numpy as np

class VectorDB:
    def __init__(self, dim):
        self.index = faiss.IndexHNSWFlat(dim, 32)   # HNSW 索引
        self.chunks = []

    def add(self, chunks, vectors):
        start = len(self.chunks)
        self.chunks.extend(chunks)
        faiss.normalize_L2(vectors)                 # 归一化，内积=余弦
        self.index.add(vectors)

    def search(self, query_vec, topk=5):
        faiss.normalize_L2(query_vec)
        D, I = self.index.search(query_vec, topk)
        return [(self.chunks[i], float(D[0][j])) for j, i in enumerate(I[0])]
```

```text
Vector DB 选型：
1. FAISS —— 本地轻量，适合原型和小规模
2. Milvus —— 分布式生产，支持亿级向量 + 元数据过滤
3. Qdrant/Chroma —— 自带持久化和过滤，开发体验好
4. 元数据 —— 必须和向量一起存，支撑按来源/时间过滤
```

## BM25

BM25 做关键词检索，兜底向量检索抓不住的专有名词、精确 ID、代码标识符。它和向量检索互补：向量抓「意思相同」，BM25 抓「字面相同」。

```python
from rank_bm25 import BM25Okapi

chunks = [
    "数据库连接池的配置方法",
    "Redis 缓存雪崩的解决方案",
    "API 接口的限流策略",
    "数据库连接池调优参数",
]
bm25 = BM25Okapi([c.split() for c in chunks])
scores = bm25.get_scores("数据库连接池".split())
for c, s in sorted(zip(chunks, scores), key=lambda x: -x[1]):
    print(f"{s:.2f}  {c}")
```

```text
BM25 在 RAG 里的作用：
1. 精确匹配 —— 专有名词、ID、代码符号，向量容易漏
2. 中文分词 —— 需先分词（jieba），英文按空格即可
3. 互补 —— 和向量召回结果融合，覆盖「字面」和「语义」
```

## Hybrid Retrieval

混合检索把 BM25 和向量召回结果融合，用 RRF 排名融合，兼顾字面和语义。这是 RAG 检索质量的关键一步——单一召回都有盲区。

```python
def rrf_fusion(sparse_ranks, dense_ranks, k=60):
    scores = {}
    for ranks in (sparse_ranks, dense_ranks):
        for rank, chunk_id in enumerate(ranks):
            scores[chunk_id] = scores.get(chunk_id, 0) + 1 / (k + rank)
    return sorted(scores, key=lambda x: -scores[x])

sparse_ranks = [3, 1, 5]      # BM25 返回的块 id 排名
dense_ranks = [2, 3, 4]       # 向量返回的块 id 排名
print(rrf_fusion(sparse_ranks, dense_ranks))   # [3, 2, 1, 5, 4]
```

```text
混合检索要点：
1. RRF —— 排名倒数融合，无需调权、对分数尺度鲁棒
2. 两路都要 —— 只向量会漏专有名词，只关键词会漏同义表达
3. 召回量 —— 每路取 TopK 再融合，给重排留足候选
```

## Rerank

重排对融合后的候选块做精细排序。召回用 Bi-Encoder（快但粗），重排用 Cross-Encoder（慢但准），把最相关的块放到最前面喂给 LLM。

```python
from sentence_transformers import CrossEncoder

reranker = CrossEncoder("BAAI/bge-reranker-base")
query = "数据库连接池怎么配置"
candidates = ["数据库连接池的配置方法", "数据库连接池调优参数", "Redis 缓存雪崩的解决方案"]

pairs = [[query, c] for c in candidates]
scores = reranker.predict(pairs)
top = sorted(zip(candidates, scores), key=lambda x: -x[1])
for c, s in top:
    print(f"{s:.3f}  {c}")
```

```text
Rerank 要点：
1. Cross-Encoder —— query+doc 拼接交互打分，精度最高
2. 只对候选 —— 对召回 Top50-100 重排，别对全库跑
3. TopK 选择 —— 重排后取 3-5 块喂 LLM，控制上下文长度
```

## LLM

LLM 拼接检索到的上下文生成答案，并要求引用来源。核心是 prompt 设计：明确「只根据上下文回答」「不知道就说不知道」，抑制幻觉。模型选开源可私有化的 Qwen/ChatGLM，降低数据外泄风险。

```python
def build_prompt(query, chunks):
    context = "\n\n".join(f"[{i+1}] {c}" for i, c in enumerate(chunks))
    return f"""你是一个知识库问答助手。请只根据以下上下文回答问题，不要编造。

上下文：
{context}

问题：{query}

要求：
1. 答案必须来自上下文，引用时标注 [编号]
2. 上下文没有答案时，明确说「知识库中没有相关信息」
"""

def llm_generate(query, chunks, model):
    prompt = build_prompt(query, chunks)
    answer = model.generate(prompt)    # 调用 LLM 生成
    return answer
```

```text
LLM 生成要点：
1. Prompt —— 限定「只根据上下文」，抑制幻觉
2. 引用 —— 要求标注来源编号，答案可追溯
3. 拒答 —— 上下文无答案时明确拒答，别硬编
4. 模型 —— 私有化部署保障数据安全，云 API 成本低但敏感数据有风险
```

## RAG Evaluation

RAG 评估分三层：检索质量（命中率、召回率、MRR）、答案质量（忠实度、相关性）、端到端（是否有引用、是否拒答）。本项目用 RAGAS 框架和自定义指标评估，避免「只看答案像不像」。

```python
# RAGAS 风格评估：检索命中率 + 答案忠实度
def hit_rate(queries, retrieved_chunks, ground_truth):
    hits = sum(1 for q, chunks, gt in zip(queries, retrieved_chunks, ground_truth)
               if gt in [c["id"] for c in chunks])
    return hits / len(queries)

def mrr(queries, retrieved_chunks, ground_truth):
    reciprocal_ranks = []
    for q, chunks, gt in zip(queries, retrieved_chunks, ground_truth):
        for rank, c in enumerate(chunks):
            if c["id"] == gt:
                reciprocal_ranks.append(1 / (rank + 1))
                break
        else:
            reciprocal_ranks.append(0)
    return sum(reciprocal_ranks) / len(reciprocal_ranks)

# 示例：2 个查询，正确块分别是 "a" 和 "d"
qs = ["查询1", "查询2"]
retrieved = [
    [{"id": "a"}, {"id": "b"}, {"id": "c"}],   # 查询1：正确块 a 排第 1
    [{"id": "e"}, {"id": "d"}],                 # 查询2：正确块 d 排第 2
]
gt = ["a", "d"]

print(f"Hit Rate = {hit_rate(qs, retrieved, gt):.2f}")
print(f"MRR = {mrr(qs, retrieved, gt):.2f}")
```

```text
RAG 评估三层：
1. 检索 —— Hit Rate / Recall / MRR / NDCG，查得全不全、排得对不对
2. 答案 —— 忠实度（是否忠于上下文）、相关性（是否答到点）
3. 端到端 —— 引用准确率、拒答率、幻觉率
评估框架 —— RAGAS、TruLens，或自定义指标
```

## 应用场景实战

### 场景一：企业文档知识库完整问答

```python
from sentence_transformers import SentenceTransformer, CrossEncoder
from rank_bm25 import BM25Okapi
import numpy as np

# 模拟知识库文档块
chunks = [
    "公司报销流程：填写报销单后提交直属领导审批，审批通过后财务打款。",
    "年假制度：入职满一年可享 5 天年假，满五年可享 10 天。",
    "考勤规则：每天 9 点前打卡，迟到 3 次记一次警告。",
    "报销单需要附发票原件，电子发票可打印后提交。",
]
bm25 = BM25Okapi([c.split() for c in chunks])
encoder = SentenceTransformer("BAAI/bge-small-zh")
vecs = encoder.encode(chunks, normalize_embeddings=True)

query = "报销需要什么材料"
# 双路召回
sparse = np.argsort(-bm25.get_scores(query.split()))[:3]
qv = encoder.encode([query], normalize_embeddings=True)
dense = np.argsort(-(vecs @ qv.T).ravel())[:3]
# RRF 融合
def rrf(a, b, k=60):
    s = {}
    for r, i in enumerate(a): s[i] = s.get(i, 0) + 1/(k+r)
    for r, i in enumerate(b): s[i] = s.get(i, 0) + 1/(k+r)
    return sorted(s, key=lambda x: -s[x])
fused = rrf(sparse.tolist(), dense.tolist())
# 重排
reranker = CrossEncoder("BAAI/bge-reranker-base")
scores = reranker.predict([[query, chunks[i]] for i in fused])
best = fused[int(np.argmax(scores))]
print(f"最相关块: {chunks[best]}")
```

## 最佳实践与踩坑记录

### 最佳实践

1. 混合检索必做：向量召回抓语义、BM25 抓精确匹配，单路都有盲区
2. 切块带重叠和元数据，块大小 500-800 token，语义边界不切断
3. 重排用 Cross-Encoder 只对 TopK 候选跑，别对全库精排
4. Prompt 明确「只根据上下文回答 + 引用编号 + 不知就拒答」，抑制幻觉
5. 中文场景选 BGE/m3e 中文模型，领域差异大时 fine-tune Embedding
6. 评估分检索、答案、端到端三层，别只看答案「像不像」

### 踩坑记录

```text
坑 1：只做向量检索不做关键词检索
结论：问「API v2.3 的配置」这种精确问题，检索不到对应文档。
原因：向量检索抓语义，专有名词/版本号/ID 的精确匹配能力弱。
解法：加 BM25 关键词检索，和向量召回做混合检索。

坑 2：文档解析不清理页眉页脚和乱码
结论：检索命中一堆「第 1 页」「版权所有」这类噪声块。
原因：解析出的文本混入页眉页脚、水印、乱码字符。
解法：解析后清洗，去页眉页脚、替换乱码、压缩空白。

坑 3：切块不重叠导致关键信息被切断
结论：答案需要的上下文恰好被切在两块边界，检索不到完整信息。
原因：固定长度硬切，语义单元被拦腰截断。
解法：递归切分 + 相邻块重叠 10-15%。

坑 4：把全部候选块塞给 LLM 导致上下文溢出
结论：候选块太多超出模型上下文窗口，或答案被无关信息带偏。
原因：没控制喂给 LLM 的块数量。
解法：重排后取 TopK 3-5 块，控制上下文长度和相关性。

坑 5：评估只看答案是否通顺，不看检索质量
结论：答案看似合理但检索命中率低，换了问法就答不上来。
原因：缺少检索层评估，问题被答案的「表面合理」掩盖。
解法：分三层评估，检索用 Hit Rate/MRR，答案用忠实度/相关性。
```

## 概述

本项目构建一个 Agent 数据分析系统：用户用自然语言提问，Agent 自主规划分析步骤，调用 SQL/Python/搜索等工具查数、计算、取外部信息，经多轮 ReAct 循环完成分析并给出结论。业务价值在于把「数据分析师写 SQL + 画图 + 写报告」的流程交给 LLM 编排，让非技术业务人员也能自助取数和分析，同时通过权限与审计保证数据安全。

```text
Agent 数据分析核心能力：
1. SQL Tool —— 自然语言转 SQL，查数据库
2. Python Tool —— 执行代码做计算、清洗、可视化
3. Search Tool —— 外部信息检索，补充背景知识
4. ReAct —— 思考 → 行动 → 观察 的循环推理
5. Planning —— 拆解复杂分析任务为步骤
6. Memory —— 记住上下文、中间结果、历史偏好
7. MCP —— 标准化工具接入协议
8. 权限与审计 —— 数据访问控制和操作留痕
```

```python
# Agent 主循环：ReAct 推理 + 工具调用
def agent_run(question):
    memory = Memory()
    step = 0
    while step < max_steps:
        thought, action = llm_think(question, memory)   # 思考 + 选工具
        if action is None:
            return thought                               # 得到最终答案
        result = execute_tool(action)                    # 调用工具
        memory.add(thought, action, result)              # 记录观察
        step += 1
    return "达到最大步数，未得出确定结论"
```

## 技术选型

| 环节 | 选择 | 理由 | 备选 |
|---|---|---|---|
| LLM | Qwen / GPT-4 | 工具调用（function calling）能力强 | Claude、GLM |
| SQL 执行 | SQLAlchemy + 只读账号 | 多数据库兼容 + 只读权限保安全 | psycopg2 直连 |
| Python 执行 | 沙箱 subprocess | 隔离执行，防危险操作 | Jupyter kernel、Docker 沙箱 |
| 搜索 | 搜索 API | 补充外部背景 | 自建检索 |
| 编排 | 自研 ReAct 循环 | 可控、可审计 | LangChain / AutoGen |
| 工具接入 | MCP | 标准化协议，工具可插拔 | 自定义 function schema |
| 审计 | 日志 + 只读 + 审批 | 全链路留痕，敏感操作需审批 | 无 |

选型原则：数据分析 Agent 的核心风险是「LLM 执行了危险的 SQL/Python」，所以选型围绕安全——SQL 用只读账号、Python 用沙箱、敏感操作加审批，功能上再考虑工具调用能力。

```python
# 工具注册：统一 schema，LLM 按 schema 生成调用参数
TOOLS = [

     "parameters": {"code": {"type": "string"}}},
    {"name": "web_search", "description": "搜索外部信息",
     "parameters": {"query": {"type": "string"}}},
]
```

## 架构设计

系统分「编排层 → 工具层 → 执行层 → 安全层」。编排层跑 ReAct/Planning 循环，工具层统一工具接口（MCP），执行层真正查库/跑代码/搜索，安全层做权限校验和审计留痕。

```text
┌────────────────────────────────────────────┐
│ 编排层   ReAct 循环 + Planning 任务拆解       │
│          + Memory 上下文管理                  │
│            │                                │
│ 工具层   SQL Tool / Python Tool / Search Tool│
│          （统一 MCP 协议接入）                │
│            │                                │
│ 执行层   数据库查询 / 沙箱执行 / 搜索 API      │
│            │                                │
│ 安全层   权限校验 + 只读 + 审计日志 + 审批     │
└────────────────────────────────────────────┘
```

```python
# 工具调用带权限校验的统一入口
def execute_tool(action):
    name, args = action["tool"], action["args"]
    if not permission_check(name, args, current_user):
        raise PermissionError("无权限执行该操作")
    result = TOOL_IMPL[name](**args)      # 真正执行
    audit_log(name, args, result, current_user)   # 审计留痕
    return result
```

## SQL Tool

SQL Tool 让 Agent 用自然语言查数据库。LLM 根据表结构（schema）生成 SQL，只读账号执行，返回结果给 LLM 继续分析。关键是给 LLM 提供准确的表结构和字段说明，否则生成的 SQL 会错。

```python
import sqlalchemy as sa

def query_sql(sql: str, read_only=True):
    """只读执行 SQL，返回结果"""
    engine = sa.create_engine("postgresql://readonly_user:***@db/warehouse")
    with engine.connect() as conn:
        # 只读保护：拦截写操作
        if read_only and any(w in sql.upper() for w in ("INSERT", "UPDATE", "DELETE", "DROP")):
            raise PermissionError("只读账号禁止写操作")
        result = conn.execute(sa.text(sql))
        rows = result.fetchall()
        return {"columns": list(result.keys()), "rows": [list(r) for r in rows]}
```

```text
SQL Tool 要点：
1. Schema 注入 —— 把表结构 + 字段注释喂给 LLM，生成准确 SQL
2. 只读账号 —— 数据库层就用只读账号，双保险
3. SQL 校验 —— 拦截 INSERT/UPDATE/DELETE/DROP 等写操作
4. 结果截断 —— 返回前 N 行，避免超大结果撑爆上下文
```

## Python Tool

Python Tool 让 Agent 执行代码做计算、清洗、可视化。必须跑在沙箱里，限制可用库、执行时间、内存，防止 LLM 生成的代码删文件、连外网、跑死循环。

```python
import subprocess
import tempfile

def run_python(code: str, timeout=10):
    """沙箱执行 Python 代码"""
    with tempfile.NamedTemporaryFile(mode="w", suffix=".py", delete=False) as f:
        f.write(code)
        path = f.name
    try:
        result = subprocess.run(
            ["python3", path], capture_output=True, text=True, timeout=timeout,
        )
        return {"stdout": result.stdout, "stderr": result.stderr[:2000]}
    except subprocess.TimeoutExpired:
        return {"error": "执行超时"}
```

```text
Python Tool 安全要点：
1. 沙箱 —— subprocess 隔离执行，或 Docker 容器
2. 超时 —— 限制执行时间，防止死循环
3. 内存限制 —— 限制内存，防止 OOM
4. 依赖白名单 —— 只装 pandas/numpy/matplotlib 等分析库
```

## Search Tool

Search Tool 让 Agent 检索外部信息补充背景：查行业数据、市场信息、公开资料。用于「这个问题需要外部知识」的场景，结果作为上下文辅助分析。

```python
import requests

def web_search(query: str, topk=5):
    """调用搜索 API 返回结果摘要"""
    resp = requests.get("https://api.search.example.com/search", params={"q": query, "n": topk})
    results = resp.json()["results"]
    return [{"title": r["title"], "snippet": r["snippet"], "url": r["url"]} for r in results]
```

```text
Search Tool 要点：
1. 结果摘要 —— 返回标题 + 摘要，别塞全文进上下文
2. 结果去重 —— 多个 query 的结果去重
3. 时效性 —— 标注发布时间，优先新信息
4. 用途 —— 补充外部背景，不能替代内部数据查询
```

## ReAct

ReAct 是 Agent 的核心推理模式：Thought（思考）→ Action（行动）→ Observation（观察）循环，直到得出最终答案。LLM 边想边做，用工具返回的结果修正下一步，比一次性生成答案更可靠。

```python
def react_loop(question, max_steps=8):
    """ReAct 主循环"""
    history = []
    prompt = f"问题：{question}\n\n"
    for step in range(max_steps):
        # LLM 输出 Thought + Action 或最终 Answer
        response = llm(prompt + format_history(history))
        if "Answer:" in response:
            return response.split("Answer:")[1].strip()
        # 解析 Action：调用工具
        tool_name, tool_args = parse_action(response)
        observation = execute_tool({"tool": tool_name, "args": tool_args})
        history.append({"thought_action": response, "observation": observation})
    return "达到最大步数"
```

```text
ReAct 循环结构：
1. Thought —— LLM 分析当前状态，决定下一步
2. Action —— 调用工具（SQL/Python/搜索）
3. Observation —— 工具返回结果，喂回 LLM
4. 终止 —— LLM 输出最终 Answer 时停止
5. 上限 —— 限制步数，防止无限循环
```

## Planning

Planning 把复杂分析任务拆成子步骤，再逐个执行。复杂问题（「分析各渠道 ROI 并找出下降原因」）不适合一步到位，需要「先查数 → 再计算 → 再归因」的分步规划。

```python
def plan_and_execute(question):
    """Plan-and-Execute：先规划再执行"""
    plan = llm(f"把下面任务拆成分析步骤：\n{question}\n输出 JSON 步骤列表")
    steps = parse_json(plan)["steps"]
    results = []
    for step in steps:
        result = react_loop(step["description"])   # 每步走 ReAct
        results.append({"step": step, "result": result})
    final = llm(f"根据各步骤结果总结答案：\n{question}\n{results}")
    return final
```

```text
Planning 要点：
1. 任务拆解 —— 复杂问题先拆成可执行的子步骤
2. 步骤依赖 —— 步骤间有依赖，顺序执行
3. 中间结果 —— 每步结果传给下一步当上下文
4. 失败重试 —— 某步失败时让 LLM 换方法重试
```

## Memory

Memory 让 Agent 记住信息：短期记忆是当前对话的上下文和中间结果，长期记忆是历史偏好和常用查询。数据分析场景里，Memory 主要存「已经查到什么」「用户之前关心什么」，避免重复查数。

```python
class Memory:
    def __init__(self):
        self.short_term = []     # 当前任务的中间结果
        self.long_term = {}      # 跨会话的偏好/知识

    def add(self, thought, action, result):
        self.short_term.append({"thought": thought, "action": action, "result": result})

    def get_context(self, max_items=10):
        return self.short_term[-max_items:]   # 最近 N 条喂给 LLM

    def remember_preference(self, key, value):
        self.long_term[key] = value

memory = Memory()
memory.remember_preference("metric_preference", "用户偏好看周环比而非同比")
```

```text
Memory 分类：
1. 短期 —— 当前任务的对话历史 + 工具结果，喂给 LLM 的上下文
2. 长期 —— 跨会话的偏好、常用表、历史结论，存向量库/DB
3. 窗口 —— 短期记忆要截断，太长会超上下文
4. 检索 —— 长期记忆按相似度检索，按需取回
```

## MCP

MCP（Model Context Protocol）是标准化的工具接入协议，让 Agent 用统一方式连接 SQL、Python、搜索等工具，工具可插拔、可复用。相比自定义 function schema，MCP 的好处是工具提供方和 Agent 解耦，详见 [[15.9-MCP]]。

```python
# MCP 客户端：连接工具服务器，发现并调用工具
class MCPClient:
    def __init__(self, server_url):
        self.server = connect(server_url)      # 连接 MCP server

    def list_tools(self):
        return self.server.list_tools()        # 发现可用工具

    def call_tool(self, name, args):
        return self.server.call_tool(name, args)   # 调用工具

# 三个工具服务器：SQL / Python / Search 各自暴露为 MCP server
sql_client = MCPClient("http://sql-tool:8000")
python_client = MCPClient("http://python-tool:8001")
search_client = MCPClient("http://search-tool:8002")
```

```text
MCP 核心概念：
1. Server —— 工具提供方，暴露工具/资源
2. Client —— Agent 侧，发现并调用工具
3. Tool —— 可调用的函数，带 schema
4. 价值 —— 标准化协议，工具生态可插拔，不锁定单一框架
```

## 权限与审计

数据分析 Agent 最敏感的部分是数据安全。权限控制保证「谁能查什么」，审计保证「谁查了什么」。本项目用「只读账号 + 权限校验 + 全量审计日志 + 敏感操作审批」四层防护。

```python
import datetime

def permission_check(tool_name, args, user):
    """权限校验：按用户角色限制可访问的数据"""
    role_permissions = {
        "analyst": {"query_sql": ["sales", "orders"], "run_python": True, "web_search": True},
        "viewer": {"query_sql": ["sales"], "run_python": False, "web_search": False},
    }
    perms = role_permissions.get(user.role, {})
    if tool_name not in perms:
        return False
    if tool_name == "query_sql":
        table = extract_table(args["sql"])
        return table in perms["query_sql"]
    return perms[tool_name]

def audit_log(tool_name, args, result, user):
    """审计留痕：记录谁在何时做了什么"""
    entry = {
        "ts": datetime.datetime.now().isoformat(),
        "user": user.id,
        "tool": tool_name,
        "args": args,
        "row_count": len(result.get("rows", [])),
    }
    append_to_audit_table(entry)
```

```text
权限与审计要点：
1. 只读账号 —— 数据库层第一道防线
2. 权限校验 —— 按角色/表粒度控制访问
3. 审计日志 —— 全量记录查询内容、结果行数
4. 敏感审批 —— 大表导出、跨库查询需人工审批
```

## 最佳实践与踩坑记录

### 最佳实践

1. SQL 用只读账号 + 写操作拦截，数据库层和工具层双保险
2. Python 代码必须跑沙箱，限制超时、内存、依赖白名单
3. 把表结构 schema 喂给 LLM，生成的 SQL 才准确
4. ReAct 循环设最大步数，防止 LLM 陷入无效循环
5. 工具返回结果要截断，超大结果会撑爆上下文窗口
6. 全量审计留痕 + 敏感操作审批，数据分析 Agent 的安全底线

### 踩坑记录

```text
坑 1：LLM 生成的 SQL 直接执行写操作
结论：Agent 误把 DELETE/UPDATE 当查询执行，数据被改。
原因：没做写操作拦截，LLM 生成的 SQL 不受控。
解法：只读账号 + 拦截 INSERT/UPDATE/DELETE/DROP 关键字。

坑 2：Python 代码不设超时导致死循环
结论：LLM 生成的 while True 跑满 CPU，服务卡死。
原因：沙箱执行没有超时限制。
解法：subprocess 加 timeout，超时强杀进程。

坑 3：不给 LLM 表结构导致 SQL 全错
结论：LLM 猜字段名，生成的 SQL 各种报错。
原因：没有把 schema 和字段注释注入 prompt。
解法：把表结构 + 字段说明 + 示例数据喂给 LLM。

坑 4：工具返回完整结果撑爆上下文
结论：查询返回百万行，LLM 上下文直接溢出。
原因：没有截断工具返回结果。
解法：返回前 N 行 + 总行数提示，让 LLM 决定是否继续查。

坑 5：ReAct 循环没有步数上限
结论：LLM 反复调用同一工具陷入死循环，token 烧光。
原因：没有终止条件，LLM 在无效循环里打转。
解法：设 max_steps，超限强制终止并返回中间结果。
```

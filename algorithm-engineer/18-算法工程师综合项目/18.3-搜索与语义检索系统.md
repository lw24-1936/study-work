## 概述

本项目构建一个兼顾「关键词精确匹配」和「语义理解」的搜索引擎：倒排索引 + BM25 负责词面相关，Embedding + ANN 负责语义相关，两者经 Hybrid Search 融合，再走 Reranker 精排，最终用 Learning to Rank 输出排序。业务价值在于把传统检索的「查得准」和语义检索的「查得懂」结合起来，解决纯关键词搜不到同义表达、纯向量搜不准专有名词的问题。

```text
搜索系统核心链路：
1. 倒排索引 —— 词 → 文档列表，关键词精确命中
2. BM25 —— 词频 + 文档频率 + 长度归一化的相关性打分
3. Embedding —— 把 query 和文档编码成语义向量
4. ANN —— 向量空间里快速召回语义相近的文档
5. Hybrid Search —— 关键词结果与向量结果融合
6. Reranker —— 对融合候选做细粒度精排
7. Learning to Rank —— 用标注数据学排序函数
```

```python
# 搜索主流程：双路召回 → 融合 → 精排 → 返回
def search(query, topk=20):
    sparse_hits = bm25_search(query)       # 关键词召回
    dense_hits = ann_search(embed(query))  # 语义召回
    candidates = hybrid_fusion(sparse_hits, dense_hits)   # 融合
    ranked = rerank(query, candidates)     # 精排
    return ranked[:topk]
```

## 技术选型

| 环节 | 选择 | 理由 | 备选 |
|---|---|---|---|
| 倒排索引 | Elasticsearch | 成熟分布式倒排 + BM25 内建，运维生态好 | 自建 Lucene、Tantivy |
| BM25 | Lucene 默认打分 | 工业标准相关性公式，可调 k1/b 参数 | TF-IDF（退化版） |
| Embedding | sentence-transformers | 预训练语义向量模型开箱即用 | OpenAI Embedding、BGE |
| ANN | FAISS/HNSW | 亿级向量毫秒级检索 | Milvus、Qdrant |
| 融合 | RRF（倒数排名融合） | 无需调权、稳健 | 加权求和、分数归一化 |
| 精排 | Cross-Encoder | query-doc 交互式打分，精度最高 | Bi-Encoder（召回用） |

选型原则：召回分双路——关键词路保证「专有名词/精确 ID」查得准，向量路保证「同义改写」查得全；精排用 Cross-Encoder 做交互式打分，召回用 Bi-Encoder 做独立编码，各取所长。

```python
from rank_bm25 import BM25Okapi
from sentence_transformers import SentenceTransformer

# 双路召回器统一接口
class HybridSearcher:
    def __init__(self, docs):
        self.docs = docs
        self.bm25 = BM25Okapi([d.split() for d in docs])          # 关键词索引
        self.encoder = SentenceTransformer("BAAI/bge-small-zh")   # 语义编码
        self.doc_vecs = self.encoder.encode(docs, normalize_embeddings=True)

    def sparse_search(self, q, topk=20):
        return self.bm25.get_top_n(q.split(), self.docs, n=topk)

    def dense_search(self, q, topk=20):
        qv = self.encoder.encode([q], normalize_embeddings=True)
        sims = self.doc_vecs @ qv.T
        idx = sims.ravel().argsort()[::-1][:topk]
        return [self.docs[i] for i in idx]
```

## 架构设计

系统分「离线索引」和「在线检索」两条链路。离线侧对文档做分词、建倒排、算向量、入库；在线侧对 query 走同样的编码流程，双路召回后融合精排。

```text
离线索引                           在线检索
┌──────────────┐                  ┌──────────────┐
│ 文档库        │                  │ 用户 query    │
└──────┬───────┘                  └──────┬───────┘
       │ 分词/切块                        │ 分词 + 向量化
       ▼                                  ▼
┌──────────────┐   ┌──────────┐   ┌──────────────┐
│ 倒排索引      │   │ 向量库    │   │ 稀疏召回      │  密集召回
│ (BM25)       │   │ (ANN)    │   │ 倒排+BM25    │  向量 ANN
└──────┬───────┘   └─────┬────┘   └──────┬───────┘
       └────────┬────────┘               │
                ▼                        ▼
         ┌──────────────┐        ┌──────────────┐
         │  离线入库     │        │ Hybrid 融合   │
         └──────────────┘        └──────┬───────┘
                                        ▼
                                 ┌──────────────┐
                                 │ Reranker 精排 │
                                 │ → 返回结果     │
                                 └──────────────┘
```

```python
# 离线索引管道：文档 → 分词倒排 + 向量入库
def build_index(docs):
    terms_index = build_inverted_index(docs)     # 倒排索引
    vectors = encoder.encode(docs, normalize_embeddings=True)
    ann_index.add(vectors)                        # 向量入库
    return terms_index, ann_index
```

## 倒排索引

倒排索引是关键词检索的地基：把「文档包含哪些词」反转成「词出现在哪些文档」。查询时直接定位到包含查询词的文档列表，无需全库扫描。本项目用字典 + 倒排列表构建内存版，生产用 Elasticsearch 的 Lucene 倒排。

```python
from collections import defaultdict

def build_inverted_index(docs):
    index = defaultdict(list)
    for doc_id, doc in enumerate(docs):
        for term in set(doc.split()):          # 去重：一词一文档只记一次
            index[term].append(doc_id)
    return dict(index)

docs = ["机器学习 入门 教程", "深度学习 入门 实践", "机器学习 算法 详解", "数据 挖掘 入门"]
inv_index = build_inverted_index(docs)
print(inv_index["入门"])     # [0, 1, 3] —— 「入门」出现在这 3 篇
print(inv_index["机器学习"])  # [0, 2]
```

```text
倒排索引核心结构：
1. 词典（term dictionary）—— 词 → 倒排列表指针
2. 倒排列表（posting list）—— 词所在的文档 id 列表（含词频/位置）
3. 查询 —— 多个词做交集/并集，交集保证所有词都命中
4. 优化 —— 跳表、位图加速多词求交，压缩倒排列表省内存
```

## BM25

BM25 是倒排索引上的经典相关性打分：词频高、文档频率低（区分度大）、文档长度短的词得分更高。它比 TF-IDF 多两个可调参数 k1（词频饱和）和 b（长度归一化强度）。

```python
import math

def bm25_score(tf, df, dl, avgdl, N, k1=1.5, b=0.75):
    """单文档单词的 BM25 得分"""
    idf = math.log(1 + (N - df + 0.5) / (df + 0.5))        # IDF，稀有词权重高
    tf_part = tf * (k1 + 1) / (tf + k1 * (1 - b + b * dl / avgdl))
    return idf * tf_part

# 示例：3 个候选文档，查询词在其中的 tf/长度不同
N, avgdl = 10000, 50
print(bm25_score(3, 100, 50, avgdl, N))   # 词频 3、常见词(出现在100篇)
print(bm25_score(1, 5, 50, avgdl, N))     # 词频 1、稀有词(只出现在5篇)
# 稀有词即使词频低，得分也可能更高 → 区分度大
```

```python
from rank_bm25 import BM25Okapi

# 用现成库对整篇文档打分
corpus = [d.split() for d in docs]
bm25 = BM25Okapi(corpus)
print(bm25.get_scores("机器学习 入门".split()))   # 每篇文档的 BM25 得分
```

## Embedding

Embedding 把 query 和文档映射到统一语义向量空间，让「意思相近但字面不同」的内容也能命中。本项目用 sentence-transformers 的预训练模型编码，向量做归一化后用余弦相似度度量语义距离。

```python
from sentence_transformers import SentenceTransformer

model = SentenceTransformer("BAAI/bge-small-zh")
docs = ["怎么训练一个神经网络", "深度学习的训练流程", "今天天气很好", "如何做红烧肉"]
doc_vecs = model.encode(docs, normalize_embeddings=True)

q = "神经网络的训练方法"
qv = model.encode([q], normalize_embeddings=True)
sims = (doc_vecs @ qv.T).ravel()
for d, s in sorted(zip(docs, sims), key=lambda x: -x[1]):
    print(f"{s:.3f}  {d}")
# 语义相近的前两条得分高，天气/做饭的文档得分低
```

```text
Embedding 检索的关键点：
1. 归一化 —— 向量 L2 归一化后，余弦相似度 = 内积
2. 模型选型 —— 中文用 bge/m3e，英文用 e5/bge，需对齐训练语料
3. 查询侧优化 —— query 侧可加指令前缀（如「为这个句子生成表示」）
4. 局限 —— 专有名词、精确 ID 召回弱，需关键词路兜底
```

## ANN

向量检索依赖 ANN 快速取最近邻。文档向量入库后建 HNSW/IVF 索引，查询时毫秒级返回 TopK。本项目和推荐系统共用同一套 ANN 技术，区别是这里检索的是文档向量，详见 [[09.5-ANN]]。

```python
import faiss
import numpy as np

d = 384                       # bge-small 的维度
doc_vecs = np.random.randn(50000, d).astype("float32")
faiss.normalize_L2(doc_vecs)  # 内积检索前先归一化，等价余弦

index = faiss.IndexHNSWFlat(d, 32)
index.add(doc_vecs)

qv = np.random.randn(1, d).astype("float32")
faiss.normalize_L2(qv)
D, I = index.search(qv, k=10)   # D 是内积相似度（越大越像）
print(I, D)
```

```text
搜索场景 ANN 注意：
1. 用内积索引 + 归一化向量 = 余弦检索
2. 文档更新需增量插入或定期重建索引
3. 召回量宁多勿少，给后面 Reranker 留够候选
```

## Hybrid Search

Hybrid Search 融合关键词召回和向量召回的结果，取长补短。本项目用 RRF（Reciprocal Rank Fusion）——按每条结果在各自列表里的排名倒数求和，无需调权重，对分数尺度不敏感。

```python
def reciprocal_rank_fusion(rank_lists, k=60):
    """RRF：多路召回按排名倒数融合"""
    scores = {}
    for ranks in rank_lists:
        for rank, doc_id in enumerate(ranks):
            scores[doc_id] = scores.get(doc_id, 0) + 1.0 / (k + rank)
    return sorted(scores.items(), key=lambda x: -x[1])

sparse_ranks = ["d3", "d1", "d5"]     # BM25 召回排名
dense_ranks = ["d2", "d3", "d4"]      # 向量召回排名
fused = reciprocal_rank_fusion([sparse_ranks, dense_ranks])
print(fused)   # d3 在两路都靠前，融合后排第一
```

```text
Hybrid Search 融合策略：
1. RRF —— 排名倒数求和，无需调权、对分数尺度鲁棒，首选
2. 加权求和 —— 需先做分数归一化（min-max/rank 归一），再线性加权
3. 分数归一化 —— 不同召回器的分数不可直接比，归一化后再融合
```

## Reranker

Reranker 对融合后的候选做精排。召回用 Bi-Encoder（query/doc 独立编码、可离线），精排用 Cross-Encoder（query 和 doc 拼接后一起过模型，交互式打分），精度显著更高但更慢，只对几百个候选跑。

```python
from sentence_transformers import CrossEncoder

reranker = CrossEncoder("BAAI/bge-reranker-base")
query = "神经网络的训练方法"
candidates = ["怎么训练一个神经网络", "深度学习的训练流程", "今天天气很好"]

# Cross-Encoder：query 和每个候选拼接打分
pairs = [[query, c] for c in candidates]
scores = reranker.predict(pairs)
for c, s in sorted(zip(candidates, scores), key=lambda x: -x[1]):
    print(f"{s:.3f}  {c}")
```

```text
Bi-Encoder vs Cross-Encoder：
1. Bi-Encoder —— query/doc 独立编码，可离线缓存，快，适合召回
2. Cross-Encoder —— query+doc 拼接交互，慢，适合精排
3. 流程 —— 召回 Bi-Encoder 圈候选，精排 Cross-Encoder 打分排序
```

## Learning to Rank

Learning to Rank（LTR）用标注数据训练排序模型，把「人工调权重」变成「学一个打分函数」。三种范式：Pointwise（单文档打分回归）、Pairwise（文档对偏序）、Listwise（整列表排序）。本项目用 LightGBM 的 Lambdarank 做 Listwise 训练。

```python
import lightgbm as lgb
import numpy as np

# LTR 训练数据：每行 = query 组 + 特征 + 相关度标签
X = np.random.randn(1000, 20)
y = np.random.randint(0, 5, 1000)          # 相关度 0-4
groups = [100] * 10                        # 每个 query 100 个候选文档

train = lgb.Dataset(X, label=y, group=groups)
params = {"objective": "lambdarank", "metric": "ndcg", "ndcg_eval_at": [5, 10],
          "learning_rate": 0.05, "num_leaves": 31}
model = lgb.train(params, train, num_boost_round=100)

scores = model.predict(X[:100])            # 对某 query 的候选打分排序
print(np.argsort(-scores)[:10])            # Top10
```

```text
LTR 三种范式：
1. Pointwise —— 每个文档独立打分，回归/分类，简单但忽略排序关系
2. Pairwise —— 学习文档对偏序（A 应排在 B 前），LambdaRank 是代表
3. Listwise —— 直接优化整列表指标（NDCG），最贴近真实目标
评估指标 —— NDCG/MAP，衡量排序质量而非单点准确率
```

## 应用场景实战

### 场景一：混合检索完整流程

```python
from rank_bm25 import BM25Okapi
from sentence_transformers import SentenceTransformer, CrossEncoder
import numpy as np

docs = [
    "如何训练一个深度神经网络",
    "神经网络训练的完整流程",
    "卷积神经网络在图像识别中的应用",
    "北京今天天气晴朗",
    "红烧肉的家常做法",
]
bm25 = BM25Okapi([d.split() for d in docs])
encoder = SentenceTransformer("BAAI/bge-small-zh")
doc_vecs = encoder.encode(docs, normalize_embeddings=True)

query = "神经网络的训练方法"
# 1. 稀疏召回
sparse = bm25.get_scores(query.split())
sparse_ranks = np.argsort(-sparse)[:3]
# 2. 密集召回
qv = encoder.encode([query], normalize_embeddings=True)
dense = (doc_vecs @ qv.T).ravel()
dense_ranks = np.argsort(-dense)[:3]
# 3. RRF 融合
def rrf(ranks_list, k=60):
    scores = {}
    for ranks in ranks_list:
        for rank, i in enumerate(ranks):
            scores[i] = scores.get(i, 0) + 1 / (k + rank)
    return sorted(scores, key=lambda x: -scores[x])
fused = rrf([sparse_ranks.tolist(), dense_ranks.tolist()])
print("融合排序:", [docs[i] for i in fused])
```

### 场景二：Cross-Encoder 精排 + NDCG 评估

```python
from sentence_transformers import CrossEncoder
import numpy as np

reranker = CrossEncoder("BAAI/bge-reranker-base")
query = "神经网络的训练方法"
candidates = [docs[i] for i in fused]
pairs = [[query, c] for c in candidates]
scores = reranker.predict(pairs)
final = sorted(zip(candidates, scores), key=lambda x: -x[1])
for c, s in final:
    print(f"{s:.3f}  {c}")

# 计算 NDCG@3（理想相关度：前两条相关，第三条不相关）
def dcg(scores, k):
    return sum((2 ** rel - 1) / np.log2(i + 2) for i, rel in enumerate(scores[:k]))
def ndcg(scores, ideal, k):
    return dcg(scores, k) / dcg(ideal, k)

rel = [2, 1, 0]          # 预测顺序的相关度
ideal = sorted(rel, reverse=True)
print(f"NDCG@3 = {ndcg(rel, ideal, 3):.3f}")
```

## 最佳实践与踩坑记录

### 最佳实践

1. 关键词路和向量路都要做，专有名词靠 BM25 兜底、同义表达靠向量召回
2. 融合优先用 RRF，无需调权重，对两路分数尺度天然鲁棒
3. 召回用 Bi-Encoder、精排用 Cross-Encoder，速度和精度各取所长
4. 向量先归一化再用内积检索，等价余弦相似度且 FAISS 内积更快
5. LTR 用 Listwise（LambdaRank）直接优化 NDCG，比 Pointwise 更贴近目标
6. 中文场景选 bge/m3e 等中文语料预训练模型，别用英文模型硬套

### 踩坑记录

```text
坑 1：向量检索用欧氏距离但向量没归一化
结论：长文档向量范数大，距离被长度主导，语义被淹没。
原因：欧氏距离受向量长度影响，长文档天然离得远。
解法：L2 归一化后改内积检索，等价余弦相似度。

坑 2：两路召回分数直接加权求和
结论：BM25 分数是十几、向量相似度是 0-1，直接加权向量路被淹没。
原因：不同召回器分数尺度不一致，不可直接线性相加。
解法：用 RRF 排名融合，或先做分数归一化再加权。

坑 3：Cross-Encoder 对全库文档精排
结论：精排耗时爆炸，接口延迟到秒级。
原因：Cross-Encoder 是交互式打分，每条候选都要过一遍模型。
解法：先召回 Top100 再用 Cross-Encoder 精排，别对全库跑。

坑 4：BM25 用默认参数不调 k1/b
结论：长文档场景下相关性排序不理想。
原因：k1 控制词频饱和、b 控制长度归一化，默认值未必适配语料。
解法：用标注数据网格搜索 k1/b，或换 BM25+ 变体。

坑 5：向量模型和语料领域不匹配
结论：医学文档库用通用模型，语义召回效果差。
原因：通用预训练模型没见过领域术语，编码质量低。
解法：用领域语料 fine-tune 模型，或选领域预训练权重。
```

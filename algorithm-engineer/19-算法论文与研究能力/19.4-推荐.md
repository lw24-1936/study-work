## 概述

推荐论文按「召回 → 排序 → 精排」链路演进：Matrix Factorization 是协同过滤的经典，用隐向量建模用户与物品；Wide & Deep 把记忆和泛化结合；DeepFM 端到端学低阶和高阶特征交互；DIN 用注意力捕捉用户历史兴趣；Two-Tower 是召回阶段的标配双塔结构。理解它们就掌握了推荐系统从传统到深度学习的演进主线。

```text
推荐论文脉络：
1. 经典协同过滤 → Matrix Factorization（隐向量分解）
2. 记忆 + 泛化 → Wide & Deep（线性 + 深度组合）
3. 特征交互 → DeepFM（FM + DNN 端到端）
4. 用户兴趣建模 → DIN（历史行为注意力）
5. 召回双塔 → Two-Tower（用户塔 + 物品塔）
```

## Matrix Factorization

矩阵分解（Koren et al., 2009, Netflix Prize）解决「协同过滤的稀疏性」问题：把用户-物品评分矩阵分解成用户隐向量和物品隐向量的乘积，用低维稠密向量刻画偏好。核心是「隐因子模型」，通过梯度下降/交替最小二乘学习隐向量。

```text
论文解决的问题：
评分矩阵极度稀疏，直接算相似度不可靠，如何降维建模偏好。

核心思想：
1. 隐向量 —— 用户和物品各用一个 k 维向量表示
2. 预测评分 —— r̂ = p_u · q_i + 偏置项
3. 优化 —— 最小化预测与真实评分的平方误差 + 正则

关键贡献：
用低维隐空间替代原始稀疏矩阵，成为协同过滤的经典范式，
Netflix Prize 的获奖基础。
```

```python
def matrix_factorization_sgd(R, k=10, epochs=50, lr=0.01, lam=0.02):
    n_users, n_items = R.shape
    P = np.random.randn(n_users, k)
    Q = np.random.randn(n_items, k)
    for _ in range(epochs):
        for u in range(n_users):
            for i in range(n_items):
                if R[u, i] > 0:          # 只对有评分的项更新
                    err = R[u, i] - P[u] @ Q[i]
                    P[u] += lr * (err * Q[i] - lam * P[u])
                    Q[i] += lr * (err * P[u] - lam * Q[i])
    return P, Q
```

## Wide & Deep

Wide & Deep（Google, 2016）解决「推荐系统如何同时具备记忆和泛化能力」的问题：Wide 部分（线性模型）记忆特征组合（如「安装过 A 且见过 B」），Deep 部分（DNN）泛化到未见的组合。核心是「联合训练宽线性和深网络」，是 Google Play 推荐的落地架构。

```text
论文解决的问题：
线性模型记忆强但泛化弱，DNN 泛化强但记忆弱，如何两者兼得。

核心思想：
1. Wide —— 稀疏特征 + 交叉特征的线性组合，精确记忆
2. Deep —— 嵌入 + 多层 DNN，学习泛化表示
3. 联合训练 —— 两部分输出相加，一起反向传播

关键贡献：
提出「记忆 + 泛化」的联合建模框架，
成为工业界推荐/CTR 的经典架构模板。
```

```python
class WideAndDeep(nn.Module):
    def __init__(self, n_features, embed_dim=16, hidden=[64, 32]):
        super().__init__()
        self.wide = nn.Linear(n_features, 1)          # Wide 线性部分
        self.embed = nn.Embedding(n_features, embed_dim)
        deep_layers = []
        prev = embed_dim
        for h in hidden:
            deep_layers += [nn.Linear(prev, h), nn.ReLU()]
            prev = h
        self.deep = nn.Sequential(*deep_layers)
        self.head = nn.Linear(prev + 1, 1)

    def forward(self, x_wide, x_deep_ids):
        wide_out = self.wide(x_wide)                  # (B, 1)
        emb = self.embed(x_deep_ids).mean(dim=1)      # 池化嵌入
        deep_out = self.deep(emb)
        return torch.sigmoid(self.head(torch.cat([wide_out, deep_out], dim=-1)))
```

## DeepFM

DeepFM（华为, 2017）解决「Wide & Deep 需要手工构造交叉特征」的问题：用 FM 层自动学二阶特征交叉，DNN 学高阶交互，二者共享嵌入、端到端联合训练。核心是「FM + DNN 共享输入」，无需人工特征工程。

```text
论文解决的问题：
手工构造交叉特征成本高、易遗漏，如何端到端自动学低阶+高阶交互。

核心思想：
1. FM 组件 —— 自动建模二阶特征交叉（内积形式）
2. Deep 组件 —— 多层 DNN 学高阶非线性交互
3. 共享嵌入 —— FM 和 DNN 用同一套嵌入向量，端到端训练

关键贡献：
去掉人工特征交叉，FM 与 DNN 共享嵌入联合学习，
是 CTR 预估的经典深度模型。
```

```python
class DeepFM(nn.Module):
    def __init__(self, n_fields, n_features, embed_dim=16, hidden=[64, 32]):
        super().__init__()
        self.embed = nn.Embedding(n_features, embed_dim)
        self.fm_bias = nn.Parameter(torch.zeros(1))
        self.linear = nn.Linear(n_features, 1)
        deep_layers = []
        prev = n_fields * embed_dim
        for h in hidden:
            deep_layers += [nn.Linear(prev, h), nn.ReLU()]
            prev = h
        self.deep = nn.Sequential(*deep_layers)
        self.head = nn.Linear(prev + 1, 1)

    def forward(self, ids, sparse):
        emb = self.embed(ids)                        # (B, n_fields, d)
        # FM 二阶交叉：和平方减平方和
        fm = 0.5 * (emb.sum(1) ** 2 - (emb ** 2).sum(1)).sum(1, keepdim=True)
        deep_out = self.deep(emb.flatten(1))
        linear = self.linear(sparse) + self.fm_bias
        return torch.sigmoid(linear + fm + self.head(deep_out))
```

## DIN

Deep Interest Network（阿里, 2018）解决「用户历史行为多样、固定向量无法表达动态兴趣」的问题：用目标物品与历史行为的注意力，动态加权用户历史兴趣向量。核心是「目标激活的兴趣表示」，让用户表征随候选物品变化。

```text
论文解决的问题：
用户历史行为多样且稀疏，固定长度向量压不住，如何精准捕捉与候选相关的兴趣。

核心思想：
1. 注意力机制 —— 用候选物品与历史行为的相似度计算权重
2. 目标激活 —— 历史兴趣向量随候选物品动态变化
3. 局部激活 —— 只激活与候选相关的历史行为

关键贡献：
把注意力引入用户兴趣建模，解决「兴趣多样性」问题，
是阿里推荐精排的经典模型。
```

```python
class DIN(nn.Module):
    def __init__(self, n_features, embed_dim=16, hidden=[64, 32]):
        super().__init__()
        self.embed = nn.Embedding(n_features, embed_dim)
        self.attn = nn.Sequential(
            nn.Linear(embed_dim * 4, 36), nn.ReLU(),
            nn.Linear(36, 1))
        prev = embed_dim * 2
        for h in hidden:
            prev = h
        self.head = nn.Linear(embed_dim * 2, 1)

    def forward(self, target_id, hist_ids):
        target = self.embed(target_id)               # (B, 1, d)
        hist = self.embed(hist_ids)                  # (B, L, d)
        # 注意力：候选与历史拼接后算权重
        target_rep = target.expand_as(hist)
        attn_in = torch.cat([hist, target_rep,
                             hist - target_rep, hist * target_rep], dim=-1)
        attn_w = torch.softmax(self.attn(attn_in), dim=1)
        user = (attn_w * hist).sum(dim=1)            # 目标激活的兴趣
        return torch.sigmoid(self.head(torch.cat([user, target.squeeze(1)], dim=-1)))
```

## Two-Tower

双塔模型（Microsoft DSSM / YouTube DNN 召回, 2013-2016）解决「海量候选下如何高效召回」的问题：用户塔和物品塔分别编码成向量，线上用向量内积/最近邻检索。核心是「双塔分离 + 向量检索」，是召回阶段的事实标准架构。

```text
论文解决的问题：
全量精排海量候选计算昂贵，如何快速从百万级候选筛出少量相关项。

核心思想：
1. 双塔分离 —— 用户塔、物品塔独立编码，互不交叉
2. 向量内积 —— 相关性用两塔向量内积度量
3. 离线建索引 —— 物品向量离线算好，线上只算用户向量 + ANN 检索

关键贡献：
把召回变成「向量检索」问题，支撑工业级大规模召回，
是推荐/搜索召回阶段的标准架构。
```

```python
class TwoTower(nn.Module):
    def __init__(self, n_users, n_items, embed_dim=16, hidden=[64, 32]):
        super().__init__()
        self.user_embed = nn.Embedding(n_users, embed_dim)
        self.item_embed = nn.Embedding(n_items, embed_dim)
        self.user_tower = nn.Sequential(nn.Linear(embed_dim, hidden[0]), nn.ReLU())
        self.item_tower = nn.Sequential(nn.Linear(embed_dim, hidden[0]), nn.ReLU())

    def forward(self, user_ids, item_ids):
        u = self.user_tower(self.user_embed(user_ids))   # (B, h)
        i = self.item_tower(self.item_embed(item_ids))   # (B, h)
        return (u * i).sum(dim=-1)                        # 内积得分
```

## 应用场景实战

### 场景一：矩阵分解做评分预测

```python
R = np.array([
    [5, 3, 0, 1],
    [4, 0, 0, 1],
    [1, 1, 0, 5],
    [0, 0, 5, 4],
])
P, Q = matrix_factorization_sgd(R, k=3, epochs=100)
pred = P @ Q.T
print(np.round(pred, 1))
```

### 场景二：双塔模型做召回排序得分

```python
model = TwoTower(n_users=1000, n_items=5000)
scores = model(torch.tensor([0, 1, 2]), torch.tensor([10, 20, 30]))
print(scores)                            # 用户-物品相关性得分
```

## 最佳实践与踩坑记录

### 最佳实践

1. 召回用 Two-Tower + ANN，精排用 Wide & Deep / DeepFM / DIN
2. 冷启动或特征稀疏时 Wide 部分（记忆）比 Deep 部分更关键
3. 特征交叉不想手工做就用 DeepFM/FM，自动学二阶交互
4. 用户历史行为多样、兴趣漂移时用 DIN 的注意力动态建模
5. 双塔模型物品向量离线算好建索引，线上只算用户塔
6. 训练时双塔用 in-batch 负采样，别只给正样本

### 踩坑记录

```text
坑 1：矩阵分解只学隐向量不加偏置
结论：对评分整体偏高/偏低的用户和物品预测不准。
原因：忽略了用户和物品的全局评分偏置。
解法：加用户偏置 b_u、物品偏置 b_i 和全局均值 μ。

坑 2：双塔模型线上算物品塔
结论：线上延迟高，无法支撑大规模召回。
原因：物品向量本可离线预计算，却在线重复计算。
解法：物品向量离线批量算好建 ANN 索引，线上只算用户塔并检索。

坑 3：DeepFM 嵌入维度取 1
结论：FM 二阶交互退化成标量乘积，表达能力差。
原因：嵌入维度为 1 时向量内积就是标量相乘，丢失隐向量信息。
解法：嵌入维度至少 8-16，保证 FM 交互有足够表达空间。

坑 4：DIN 对长历史序列直接平均
结论：平均池化稀释了与候选相关的兴趣，推荐不精准。
原因：没有用注意力区分历史行为与候选的相关性。
解法：用候选物品做 query，对历史行为做注意力加权求和。

坑 5：Wide & Deep 训练时 Wide 和 Deep 分开优化
结论：两部分各自为政，联合效果打折。
原因：分开训练无法让两部分互相补偿。
解法：联合训练，输出相加后一起反向传播。
```

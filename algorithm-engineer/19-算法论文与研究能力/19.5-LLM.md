## 概述

LLM 论文串起了大语言模型的完整技术栈：Transformer 是架构底座，BERT 与 GPT 是两条路线（编码式理解 vs 自回归生成），Scaling Laws 揭示「规模即能力」，LoRA 解决高效微调，RLHF 和 DPO 解决对齐（让模型符合人类偏好），RAG 用检索增强缓解幻觉与知识过时。它们共同定义了现代 LLM 的训练与使用范式。

```text
LLM 论文脉络：
1. 架构 → Transformer（2017）
2. 预训练两条路线 → BERT（编码）/ GPT（解码自回归）
3. 规模规律 → Scaling Laws（2020）
4. 高效微调 → LoRA（2021）
5. 对齐 → RLHF（2017 思想 / InstructGPT 2022）→ DPO（2023）
6. 知识增强 → RAG（2020）
```

## Transformer

Transformer（Vaswani et al., 2017）解决「RNN 无法并行、长程依赖难」的问题：用纯自注意力架构处理序列，配多头注意力、位置编码、残差与前馈。它是 GPT、BERT 等所有 LLM 的架构基础，核心贡献是「注意力取代循环」。

```text
论文解决的问题：
序列建模的并行化瓶颈与长距离依赖衰减。

核心思想：
1. 自注意力 —— 任意位置直接交互，路径长度 O(1)
2. 多头 —— 多子空间并行关注不同关系
3. 位置编码 —— 补充顺序信息
4. 完全并行 —— 去掉循环结构

关键贡献：
成为现代 LLM 的统一架构底座，催生了整个大模型时代。
```

```python
class TransformerBlock(nn.Module):
    def __init__(self, d_model, n_heads, d_ff):
        super().__init__()
        self.attn = nn.MultiheadAttention(d_model, n_heads, batch_first=True)
        self.ff = nn.Sequential(
            nn.Linear(d_model, d_ff), nn.ReLU(), nn.Linear(d_ff, d_model))
        self.norm1 = nn.LayerNorm(d_model)
        self.norm2 = nn.LayerNorm(d_model)

    def forward(self, x):
        x = x + self.attn(self.norm1(x), self.norm1(x), self.norm1(x))[0]
        x = x + self.ff(self.norm2(x))
        return x
```

## BERT

BERT（Devlin et al., 2018）解决「如何用双向上下文做预训练表征」的问题：用 Transformer 编码器 + 掩码语言模型（MLM）+ 下一句预测（NSP）做预训练，再微调到下游任务。核心是「双向编码 + 预训练-微调范式」，革新了 NLP 任务范式。

```text
论文解决的问题：
单向语言模型只看到单侧上下文，无法充分理解语义。

核心思想：
1. 掩码语言模型 —— 随机 mask 部分 token，用双向上下文预测
2. 下一句预测 —— 判断两句话是否相邻，学句子关系
3. 预训练 + 微调 —— 先无监督预训练，再下游任务微调

关键贡献：
确立「预训练 + 微调」范式，让双向表征成为 NLP 标准，
是理解类任务（分类、问答、检索）的经典底座。
```

```python
# BERT 的 MLM 预训练目标（示意）
def mlm_loss(masked_logits, masked_labels):
    return F.cross_entropy(
        masked_logits.view(-1, masked_logits.size(-1)), masked_labels.view(-1))
```

## GPT

GPT（Radford et al., 2018 / GPT-2 2019 / GPT-3 2020）解决「如何用自回归生成做通用预训练」的问题：用 Transformer 解码器 + 因果语言模型（预测下一个 token）做预训练，靠海量数据涌现通用能力。核心是「自回归 + 规模化」，是 ChatGPT 的路线源头。

```text
论文解决的问题：
如何构建一个能生成连贯文本、并随规模涌现通用能力的模型。

核心思想：
1. 因果语言模型 —— 只看到左侧上下文，预测下一个 token
2. 自回归生成 —— 逐 token 生成，天然适合文本续写
3. 规模化 —— 参数与数据同步放大，涌现 in-context learning

关键贡献：
确立「自回归生成 + 规模化」路线，GPT-3 展示了少样本/零样本
能力，是 ChatGPT 和所有对话 LLM 的直接祖先。
```

```python
class GPTBlock(nn.Module):
    def __init__(self, d_model, n_heads):
        super().__init__()
        self.attn = nn.MultiheadAttention(d_model, n_heads, batch_first=True)
        self.ff = nn.Sequential(
            nn.Linear(d_model, 4 * d_model), nn.GELU(),
            nn.Linear(4 * d_model, d_model))
        self.norm1 = nn.LayerNorm(d_model)
        self.norm2 = nn.LayerNorm(d_model)

    def forward(self, x, mask):
        x = x + self.attn(self.norm1(x), self.norm1(x), self.norm1(x),
                          attn_mask=mask)[0]
        x = x + self.ff(self.norm2(x))
        return x
```

## Scaling Laws

Scaling Laws（Kaplan et al., 2020）解决「模型性能如何随规模变化」的问题：系统实验表明，损失随参数量、数据量、算力的增大按幂律下降，且存在可预测关系。核心是「规模即能力」，指导了后续大模型的资源配置。

```text
论文解决的问题：
投入更多参数/数据/算力，性能提升的规律是什么，如何最优分配。

核心思想：
1. 幂律下降 —— 损失与规模呈幂律关系（对数线性）
2. 三个维度 —— 参数量 N、数据量 D、算力 C 共同决定性能
3. 最优分配 —— 给定算力，可预测最优参数量与数据量

关键贡献：
为「扩大规模」提供了理论依据和资源配置公式，
是 GPT-3 及后续大模型「大力出奇迹」的科学基础。
```

```text
核心经验公式（示意）：
L(N, D) ≈ (Nc/N)^αN + (Dc/D)^αD + L∞
损失随规模增大按幂律衰减，规模不足时优先同步放大参数和数据
```

## LoRA

LoRA（Hu et al., 2021）解决「大模型全量微调成本高」的问题：冻结预训练权重，只训练低秩分解矩阵 ΔW = BA，用极少参数适配下游任务。核心是「低秩近似 + 冻结主干」，把微调参数量降几个数量级。

```text
论文解决的问题：
千亿参数模型全量微调需要海量显存与算力，无法普及。

核心思想：
1. 低秩分解 —— ΔW = B·A，r 远小于原维度
2. 冻结主干 —— 原权重 W 冻结，只更新 A、B
3. 可插拔 —— 不同任务用不同的 LoRA 增量，可合并或切换

关键贡献：
把大模型微调成本降到消费级显卡可承受，
是当前最流行的 PEFT（参数高效微调）方法。
```

```python
class LoRALayer(nn.Module):
    def __init__(self, in_dim, out_dim, rank=8, alpha=16):
        super().__init__()
        self.A = nn.Parameter(torch.randn(rank, in_dim) * 0.01)
        self.B = nn.Parameter(torch.zeros(out_dim, rank))
        self.scale = alpha / rank

    def forward(self, x):
        return (x @ self.A.T @ self.B.T) * self.scale   # ΔW 增量
```

## RLHF

RLHF（InstructGPT, Ouyang et al., 2022）解决「预训练模型输出不符合人类偏好」的问题：用人类反馈训练奖励模型，再用强化学习（PPO）优化策略，使模型输出更符合人类意图。核心是「人类偏好 → 奖励模型 → RL 优化」，是 ChatGPT 对齐的关键。

```text
论文解决的问题：
预训练只学「下一个词」，无法保证输出有帮助、诚实、无害。

核心思想：
1. 偏好标注 —— 人类对多个回答排序
2. 奖励模型 —— 用排序数据训练 RM，打分哪个回答更好
3. PPO 优化 —— 用 RL 最大化奖励，同时约束不过度偏离 SFT

关键贡献：
把「对齐人类偏好」变成可训练的 RL 目标，
是 InstructGPT/ChatGPT 的核心技术。
```

```python
def rlhf_ppo_loss(logprobs, old_logprobs, rewards, advantages, clip=0.2):
    ratio = torch.exp(logprobs - old_logprobs)
    surr1 = ratio * advantages
    surr2 = torch.clamp(ratio, 1 - clip, 1 + clip) * advantages
    return -torch.min(surr1, surr2).mean()   # PPO 目标
```

## DPO

DPO（Rafailov et al., 2023）解决「RLHF 需要奖励模型 + RL 两阶段、训练不稳定」的问题：直接从偏好数据优化策略，用隐式奖励把 RL 目标转成简单的分类损失。核心是「绕过显式奖励模型」，对齐训练更简单稳定。

```text
论文解决的问题：
RLHF 的奖励建模 + PPO 流程复杂、不稳定、难复现。

核心思想：
1. 隐式奖励 —— 把策略本身表达的偏好当作奖励
2. 直接优化 —— 用偏好对（好/坏回答）的对比损失直接优化策略
3. 无需 RL —— 去掉了奖励模型和 PPO，一个分类损失搞定

关键贡献：
把对齐从「RLHF 两阶段」简化为「DPO 单阶段」，
训练更稳定、实现更简单，成为对齐的主流替代方案。
```

```python
def dpo_loss(logp_chosen, logp_rejected, ref_chosen, ref_rejected, beta=0.1):
    pi_diff = logp_chosen - logp_rejected
    ref_diff = ref_chosen - ref_rejected
    logits = beta * (pi_diff - ref_diff)
    return -F.logsigmoid(logits).mean()   # 对比分类损失
```

## RAG

RAG（Lewis et al., 2020）解决「LLM 知识过时、易幻觉、无法引用来源」的问题：先检索相关文档，再把检索结果拼接进 prompt 让模型生成。核心是「检索 + 生成」结合，让模型基于外部知识作答。

```text
论文解决的问题：
参数化知识（模型内）固定、过时、不可溯源，如何接入外部动态知识。

核心思想：
1. 检索 —— 用 query 从知识库召回相关文档
2. 增强 —— 把检索结果拼进 prompt 作为上下文
3. 生成 —— 基于检索上下文生成回答（可带引用）

关键贡献：
把「外部知识检索」与「生成」结合，缓解幻觉、支持知识更新，
成为企业落地 LLM 的标准范式。
```

```python
def rag_pipeline(query, retriever, generator):
    docs = retriever.search(query, top_k=5)      # 1. 检索
    context = '\n'.join(doc.text for doc in docs)
    prompt = f'基于以下资料回答问题：\n{context}\n\n问题：{query}'
    answer = generator(prompt)                   # 2+3. 增强 + 生成
    return answer, docs
```

## 最佳实践与踩坑记录

### 最佳实践

1. 理解类任务选 BERT 系，生成/对话选 GPT 系
2. 规模不足时优先同步放大参数和数据，别只堆参数
3. 微调大模型用 LoRA/QLoRA，别全量微调
4. 对齐优先试 DPO，比 RLHF 简单稳定；需要复杂奖励再上 RLHF
5. 需要外部知识、可溯源、降低幻觉用 RAG
6. 位置编码、注意力掩码是 Transformer 细节，实现时别漏

### 踩坑记录

```text
坑 1：LoRA rank 取太大
结论：rank 过大时参数量逼近全量微调，失去高效意义。
原因：误以为 rank 越大效果越好，忽略了成本收益比。
解法：rank 从 4-16 起调，配合 alpha 缩放，收益饱和就停。

坑 2：RAG 检索质量差直接喂给模型
结论：召回无关文档，模型被噪声带偏，回答更差。
原因：只堆向量相似度，没有重排和质量过滤。
解法：混合检索（稀疏+稠密）+ 重排 + 相关性阈值过滤。

坑 3：DPO 用同一回答对里 logp 符号搞反
结论：优化方向反了，模型反而更偏好差回答。
原因：chosen/rejected 的 logp 减反。
解法：loss = -logsigmoid(beta*(logp_chosen - logp_rejected - ref_diff))。

坑 4：GPT 自回归训练时注意力没加因果掩码
结论：模型偷看未来 token，训练损失虚低、生成时崩坏。
原因：忘了下三角因果掩码，当前位置能看到后面的 token。
解法：自注意力加 causal mask，屏蔽未来位置。

坑 5：Scaling Laws 结论直接外推到不同架构
结论：按旧规律配置新架构的规模，资源浪费。
原因：Scaling Laws 结论依赖具体架构与数据分布，不可直接迁移。
解法：针对自己的架构小规模拟合，再外推资源配置。
```

## 概述

算法工程师把模型训练出来后，要把模型的能力「服务化」暴露给业务方调用。服务框架解决的核心问题是：如何把 Python 里的推理函数变成一个稳定、可并发、可观测的 HTTP/RPC 服务。REST 是最通用的接口风格，FastAPI 和 Flask 是 Python 两大 Web 框架，Pydantic 负责请求/响应的数据校验，WebSocket 处理长连接流式场景，gRPC 提供高性能的跨语言 RPC 通信。

```text
服务框架选型的关键维度：
1. 同步/异步 —— FastAPI 原生异步，Flask 默认同步，高并发场景差异巨大
2. 数据校验 —— Pydantic 自动校验请求体，Flask 需要手动处理
3. 通信协议 —— REST(JSON) 通用易调试，gRPC(protobuf) 高性能跨语言
4. 流式能力 —— WebSocket 双向长连接，适合 token 逐字输出的 LLM 场景
5. 生态与性能 —— 框架本身开销要远小于模型推理开销
```

```python
# 一个最小可用的模型服务骨架（FastAPI）
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI(title="模型推理服务")

class PredictRequest(BaseModel):
    text: str
    top_k: int = 5

class PredictResponse(BaseModel):
    labels: list[str]
    scores: list[float]

@app.post("/predict", response_model=PredictResponse)
def predict(req: PredictRequest):
    # 这里替换成真实模型推理
    labels = ["科技", "体育", "财经"][:req.top_k]
    scores = [0.9, 0.8, 0.7][:req.top_k]
    return PredictResponse(labels=labels, scores=scores)
```

## REST

REST（Representational State Transfer）是一种基于 HTTP 的架构风格，用「资源 + 动词」组织接口。资源用 URL 表示，操作用 HTTP 方法表示（GET 查、POST 建、PUT 改、DELETE 删）。它是目前模型服务最通用的接口风格，因为任何语言、任何客户端都能消费 JSON over HTTP。

```text
REST 的核心约定：
1. 资源导向 —— /users 是集合资源，/users/1 是单个资源
2. 方法语义 —— GET 幂等读，POST 创建，PUT 全量更新，DELETE 删除
3. 无状态 —— 每次请求自带完整上下文，服务器不保存会话状态
4. 状态码 —— 200 成功、201 创建、400 参数错、404 不存在、500 服务器错
5. 用 JSON —— 请求体和响应体默认 JSON 编码
```

```python
# REST 风格的 CRUD 示例（FastAPI 路由）
from fastapi import FastAPI, HTTPException

app = FastAPI()
db = {}  # 内存里的"模型版本表"

@app.get("/models")
def list_models():
    return list(db.values())

@app.get("/models/{model_id}")
def get_model(model_id: int):
    if model_id not in db:
        raise HTTPException(status_code=404, detail="model not found")
    return db[model_id]

@app.post("/models", status_code=201)
def create_model(name: str, version: str):
    model_id = len(db) + 1
    db[model_id] = {"id": model_id, "name": name, "version": version}
    return db[model_id]

@app.delete("/models/{model_id}")
def delete_model(model_id: int):
    if model_id not in db:
        raise HTTPException(status_code=404, detail="model not found")
    return db.pop(model_id)
```

## FastAPI

FastAPI 是 Python 目前最流行的现代 Web 框架，基于 Starlette（异步）+ Pydantic（校验），同时支持同步和异步处理函数。它自带交互式 API 文档（Swagger UI / OpenAPI），自动生成请求校验和序列化，性能接近 Node/Go 框架，是算法模型服务的首选。

```text
FastAPI 的核心特性：
1. 原生异步 —— 基于 asyncio，IO 密集的推理调用可高并发
2. 自动文档 —— /docs 自动生成 Swagger UI，/redoc 生成 ReDoc
3. 自动校验 —— Pydantic 模型自动校验请求体，非法输入返回 422
4. 依赖注入 —— Depends() 管理数据库连接、认证等复用逻辑
5. 类型驱动 —— 用 Python 类型注解驱动校验、序列化、文档
```

```python
from fastapi import FastAPI, Depends
from pydantic import BaseModel
import asyncio

app = FastAPI()

class Item(BaseModel):
    name: str
    price: float
    tags: list[str] = []

# 同步处理函数：FastAPI 自动丢进线程池
@app.post("/sync")
def sync_predict(item: Item):
    return {"name": item.name, "price": item.price * 2}

# 异步处理函数：在事件循环里跑，适合 IO 密集
@app.post("/async")
async def async_predict(item: Item):
    await asyncio.sleep(0.01)          # 模拟等待外部推理服务
    return {"name": item.name, "price": item.price * 2}

# 依赖注入：复用模型加载逻辑
def get_model():
    model = {"name": "bert-base", "loaded": True}
    return model

@app.get("/inspect")
def inspect(model=Depends(get_model)):
    return model
```

## Pydantic

Pydantic 是 FastAPI 的数据校验引擎，用类型注解定义数据模型，自动完成「JSON → Python 对象」的反序列化、字段校验、类型转换和错误提示。它还能做数据导出（.model_dump()）、序列化（.model_dump_json()）和严格校验，是服务层防御非法输入的第一道防线。

```text
Pydantic 的核心能力：
1. 类型校验 —— 声明 int 却传了 str，自动转或报错
2. 嵌套模型 —— 复杂 JSON 结构递归校验
3. 字段约束 —— Field() 限定范围、长度、正则、默认值
4. 别名与排除 —— 序列化时排除敏感字段、映射不同字段名
5. 自定义校验 —— field_validator / model_validator 做业务校验
```

```python
from pydantic import BaseModel, Field, field_validator

class PredictRequest(BaseModel):
    text: str = Field(..., min_length=1, max_length=512)
    top_k: int = Field(default=5, ge=1, le=100)
    temperature: float = Field(default=0.7, gt=0, le=2.0)

    @field_validator("text")
    @classmethod
    def strip_text(cls, v: str) -> str:
        v = v.strip()
        if not v:
            raise ValueError("text 不能为空")
        return v

# 合法输入
req = PredictRequest.model_validate({"text": "  你好  ", "top_k": 3})
print(req.text)                      # "你好"（已 strip）
print(req.model_dump_json())         # JSON 序列化

# 非法输入：抛出 ValidationError
try:
    PredictRequest.model_validate({"text": "", "top_k": 999})
except Exception as e:
    print(type(e).__name__)          # ValidationError
```

## Flask

Flask 是 Python 老牌微框架，轻量、灵活、上手快，默认同步模型（WSGI），每个请求一个线程。它不像 FastAPI 自带校验和文档，但生态成熟、教程丰富，很多早期模型服务还在用。新项目推荐 FastAPI，老项目维护、简单同步脚本式服务用 Flask 足够。

```text
Flask 与 FastAPI 的对比：
1. 并发模型 —— Flask 默认同步（可加 gunicorn 多进程），FastAPI 原生异步
2. 数据校验 —— Flask 手动解析 request.get_json()，FastAPI 自动 Pydantic
3. 文档 —— Flask 需要 flask-swagger 等插件，FastAPI 自带
4. 学习成本 —— Flask 更简单直接，FastAPI 需要理解类型注解和 asyncio
```

```python
from flask import Flask, request, jsonify

app = Flask(__name__)

@app.route("/predict", methods=["POST"])
def predict():
    data = request.get_json(silent=True) or {}
    text = data.get("text", "")
    top_k = data.get("top_k", 5)
    # 手动校验
    if not text:
        return jsonify({"error": "text 不能为空"}), 400
    return jsonify({
        "labels": ["科技", "体育"][:top_k],
        "scores": [0.9, 0.8][:top_k],
    })

if __name__ == "__main__":
    # 生产环境改用 gunicorn -w 4 -k gevent app:app
    app.run(host="0.0.0.0", port=8000)
```

## WebSocket

WebSocket 是一种基于 TCP 的全双工长连接协议，客户端和服务端建立一次连接后可以双向持续推送消息，省去 HTTP 每次握手的开销。它特别适合 LLM 逐 token 流式输出、实时推荐刷新、模型训练进度推送等「服务端主动推数据」的场景。

```text
WebSocket 的关键点：
1. 长连接 —— 一次握手后保持连接，服务端可主动推送
2. 全双工 —— 客户端服务端可同时发消息
3. 低延迟 —— 无需反复 HTTP 握手，适合流式 token
4. 状态管理 —— 连接是持久的，需要管理连接生命周期和心跳
```

```python
# WebSocket 流式输出示例（FastAPI）
from fastapi import FastAPI, WebSocket
import asyncio

app = FastAPI()

@app.websocket("/ws/stream")
async def stream(ws: WebSocket):
    await ws.accept()                    # 接受连接
    try:
        while True:
            text = await ws.receive_text()   # 接收客户端消息
            # 模拟 LLM 逐 token 输出
            for token in list(text):
                await ws.send_json({"token": token})
                await asyncio.sleep(0.05)
            await ws.send_json({"done": True})
    except Exception:
        await ws.close()                 # 异常时关闭连接
```

## gRPC

gRPC 是 Google 开源的高性能 RPC 框架，用 Protocol Buffers（protobuf）定义接口和消息，自动生成多语言客户端/服务端代码。它基于 HTTP/2，支持双向流，序列化体积小、解析快，适合服务间高吞吐、低延迟的模型调用，尤其适合跨语言场景（Python 服务、C++ 推理引擎）。

```text
gRPC 与 REST 的对比：
1. 协议 —— gRPC 用 HTTP/2 + protobuf，REST 用 HTTP/1.1 + JSON
2. 性能 —— protobuf 二进制序列化比 JSON 小 3-10 倍，解析更快
3. 类型 —— protobuf 强类型 + 代码生成，REST 弱类型
4. 流式 —— gRPC 原生支持单向/双向流，REST 需要 SSE/WebSocket
5. 调试 —— REST 可用 curl 直接调，gRPC 需要 grpcurl 等工具
```

```text
// model.proto —— 定义服务接口和消息
syntax = "proto3";

package model;

service ModelService {
  rpc Predict(PredictRequest) returns (PredictResponse);
  rpc StreamPredict(PredictRequest) returns (stream PredictResponse);
}

message PredictRequest {
  string text = 1;
  int32 top_k = 2;
}

message PredictResponse {
  repeated string labels = 1;
  repeated float scores = 2;
}
```

```python
# gRPC 服务端（Python）
import grpc
from concurrent import futures
import model_pb2
import model_pb2_grpc

class ModelServicer(model_pb2_grpc.ModelServiceServicer):
    def Predict(self, request, context):
        labels = ["科技", "体育"][:request.top_k]
        scores = [0.9, 0.8][:request.top_k]
        return model_pb2.PredictResponse(labels=labels, scores=scores)

server = grpc.server(futures.ThreadPoolExecutor(max_workers=10))
model_pb2_grpc.add_ModelServiceServicer_to_server(ModelServicer(), server)
server.add_insecure_port("[::]:50051")
server.start()
server.wait_for_termination()
```

## 应用场景实战

### 场景一：搭建一个带校验的文本分类服务

```python
# 完整示例：Pydantic 校验 + FastAPI + 模型推理
from fastapi import FastAPI
from pydantic import BaseModel, Field

app = FastAPI()

class ClassifyRequest(BaseModel):
    text: str = Field(..., min_length=1, max_length=512)

class ClassifyResponse(BaseModel):
    label: str
    score: float

# 模拟已加载的模型
def model_predict(text: str) -> tuple[str, float]:
    return ("正面", 0.93)

@app.post("/classify", response_model=ClassifyResponse)
def classify(req: ClassifyRequest):
    label, score = model_predict(req.text)
    return ClassifyResponse(label=label, score=score)

# 启动：uvicorn main:app --host 0.0.0.0 --port 8000
# 测试：curl -X POST http://localhost:8000/classify -H 'Content-Type: application/json' -d '{"text":"今天很开心"}'
```

### 场景二：LLM 流式输出服务

```python
# 用 WebSocket 实现 LLM 逐 token 流式输出
from fastapi import FastAPI, WebSocket
import asyncio

app = FastAPI()

async def fake_llm_stream(prompt: str):
    for token in ["今天", "的", "天气", "很好", "。"]:
        yield token
        await asyncio.sleep(0.1)

@app.websocket("/ws/chat")
async def chat(ws: WebSocket):
    await ws.accept()
    try:
        prompt = await ws.receive_text()
        async for token in fake_llm_stream(prompt):
            await ws.send_json({"token": token})
        await ws.send_json({"done": True})
    finally:
        await ws.close()
```

## 最佳实践与踩坑记录

### 最佳实践

1. 新项目默认选 FastAPI：原生异步 + 自动校验 + 自动文档，模型服务三件套全包
2. 请求/响应一律用 Pydantic 模型定义，别在函数里裸解析 dict
3. 模型在服务启动时加载一次（lifespan/全局变量），别每个请求重新加载
4. 推理是 CPU/GPU 密集操作，同步函数记得用 FastAPI 默认线程池或手动 offload
5. 生产环境用 gunicorn（Flask）或 uvicorn（FastAPI）多 worker，别用自带 dev server
6. 高吞吐服务间调用用 gRPC，对外的 HTTP API 用 REST
7. 流式输出（LLM token）用 WebSocket 或 SSE，别轮询

### 踩坑记录

```text
坑 1：在 FastAPI 里用同步阻塞函数跑推理
结论：CPU/GPU 密集的同步推理会阻塞事件循环，拖垮所有并发请求。
原因：async def 里的同步计算会独占事件循环，其他请求无法被调度。
解法：推理函数写成普通 def（FastAPI 自动放线程池），或显式用 run_in_executor。

坑 2：每个请求重新加载模型
结论：QPS 稍高内存就爆炸、延迟飙升。
原因：模型加载（读权重、建图）是秒级到分钟级操作，不能放请求路径。
解法：用 FastAPI lifespan 或模块全局变量，启动时加载一次，请求间复用。

坑 3：Pydantic 模型和响应模型共用导致字段泄露
结论：把内部字段（如用户 ID、内部状态）暴露给客户端。
原因：直接用内部模型当 response_model，未做字段裁剪。
解法：请求模型和响应模型分开定义，响应模型只保留需要暴露的字段。

坑 4：gRPC 消息里用 optional 字段导致默认值歧义
结论：0 和「未设置」在 proto3 里分不清，业务逻辑出错。
原因：proto3 标量字段有默认值，无法区分「未传」和「传了 0」。
解法：需要区分时用 optional 关键字或 wrapper 类型（google.protobuf）。

坑 5：WebSocket 连接不设心跳导致连接被中间层回收
结论：长时间空闲的连接被网关/代理静默断开，服务端还在等消息。
原因：中间层（Nginx/负载均衡）有空闲超时，会主动断开无流量的长连接。
解法：客户端定时发 ping/pong 心跳，服务端加超时清理逻辑。
```

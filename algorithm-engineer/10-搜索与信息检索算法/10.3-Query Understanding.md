## 概述

Query Understanding（查询理解，简称 QU）是搜索链路里「在查询进索引之前」的一层：把用户输入的原始 query 解析、纠错、扩展、结构化，让下游的召回和排序拿到一个「更干净、更完整、意图更清晰」的查询。用户表达往往很随意（错别字、口语、简称），QU 的质量直接决定搜索的天花板。

```text
Query Understanding 的职责：
1. 纠错/改写 —— 修正错别字、把口语/简称改成规范表达
2. 扩展 —— 补同义词、相关词，提升召回
3. 理解 —— 识别意图（买/学/看）和实体（人名/商品/地点）
4. 结构化 —— 输出带权重的词、实体、意图标签给下游

输入：原始 query 字符串
输出：规范化 query + 意图标签 + 实体列表 + 扩展词
```

```python
# Query Understanding 的流水线示意
def query_understanding(raw_query):
    corrected = spell_correct(raw_query)          # 1. 纠错
    rewritten = query_rewrite(corrected)          # 2. 改写（口语→规范）
    entities = recognize_entities(rewritten)      # 3. 实体识别
    intent = classify_intent(rewritten)           # 4. 意图分类
    expanded = query_expand(rewritten)            # 5. 查询扩展
    return {
        'query': rewritten, 'intent': intent,
        'entities': entities, 'expanded': expanded,
    }
```

## Query Rewrite

Query Rewrite（查询改写）把用户原始的、不规范的表达到「规范化」或「更利于召回」的形式。常见场景：口语化表达转书面语（「咋样」「多少钱」→「价格」）、简称转全称、拼写变体统一，以及把长尾 query 改写成能命中更多结果的短 query。

```text
查询改写的典型场景：
1. 口语 → 书面：「咋回事」→「怎么回事」
2. 简称 → 全称：「阿里」→「阿里巴巴」
3. 归一化：「iPhone13」/「iphone 13」/「苹果13」→ 统一表达
4. 冗余清理：去掉无意义的语气词、标点
5. 规则 vs 模型 —— 高频 case 用规则词典，长尾用 seq2seq/LLM
```

```python
def query_rewrite(query, rules=None):
    """基于规则的查询改写：简称/口语映射"""
    rules = rules or {
        '咋样': '怎么样', '多少钱': '价格', '阿里': '阿里巴巴',
        'iphone': 'iPhone', '咋回事': '怎么回事',
    }
    out = query
    for k, v in rules.items():
        out = out.replace(k, v)
    return out

print(query_rewrite('阿里 iphone 多少钱'))
# '阿里巴巴 iPhone 价格'
```

## Synonym

Synonym（同义词）处理解决「用户说的词 ≠ 文档里的词」导致的召回缺失。例如用户搜「笔记本」，文档里写的是「笔记本电脑」或「laptop」。同义词扩展通常在召回前把 query 里的词替换/扩展成同义词组，让索引里不同表达的文档都能被命中。

```text
同义词的几种来源与形式：
1. 人工词典 —— 领域专家维护（精准但贵、覆盖有限）
2. 等价替换 —— 「土豆」→「马铃薯」，直接替换
3. 单向扩展 —— 「手机」→「手机/电话/移动电话」，扩展召回
4. 数据挖掘 —— 从点击日志、query 聚类、词向量相似度自动挖掘

风险：同义词扩展过度会引入噪声，降低精度（Precision）
```

```python
SYNONYMS = {
    '笔记本': ['笔记本电脑', 'laptop', 'notebook'],
    '手机': ['电话', '移动电话', '手机'],
    '电脑': ['计算机', '电脑', 'PC'],
}

def synonym_expand(query_tokens):
    """把 query 中的词扩展成同义词组，用于召回"""
    expanded = set(query_tokens)
    for t in query_tokens:
        if t in SYNONYMS:
            expanded.update(SYNONYMS[t])
    return list(expanded)

print(synonym_expand(['笔记本', '推荐']))
# ['笔记本', '推荐', '笔记本电脑', 'laptop', 'notebook']
```

## Spell Correction

Spell Correction（拼写纠错）修正用户输入的错别字、拼音、模糊拼写。「机器学习」打成「机器学系」、「周杰伦」打成「周结论」都会导致召回失败。纠错的核心是「找最可能的正确词」——通常是编辑距离 + 语言模型（哪个候选在语料里更常见）。

```text
拼写纠错的经典方法：
1. 编辑距离 —— 找出与错词距离 ≤1~2 的候选词
2. 候选排序 —— 用词频/语言模型给候选排序，选最可能的
3. 上下文 —— 结合前后词（如 n-gram）提升纠错准确率
4. 拼音纠错 —— 中文特有：同音字替换（「结」→「杰」）

关键：纠错不能太激进，否则会把正确的长尾词「纠」成错的
```

```python
def edit_distance_1(word):
    """生成所有编辑距离为 1 的候选（删除/替换/插入/交换）"""
    letters = 'abcdefghijklmnopqrstuvwxyz'
    splits = [(word[:i], word[i:]) for i in range(len(word) + 1)]
    deletes = [L + R[1:] for L, R in splits if R]
    transposes = [L + R[1] + R[0] + R[2:] for L, R in splits if len(R) > 1]
    replaces = [L + c + R[1:] for L, R in splits if R for c in letters]
    inserts = [L + c + R for L, R in splits for c in letters]
    return set(deletes + transposes + replaces + inserts)

def spell_correct(word, vocabulary, word_freq):
    """从词典里找最可能的正确词"""
    if word in vocabulary:
        return word
    candidates = edit_distance_1(word) & vocabulary
    if not candidates:
        candidates = vocabulary     # 退化为全词典（可再算距离 2）
    return max(candidates, key=lambda w: word_freq.get(w, 0))

vocab = {'machine', 'learning', 'machinelearning'}
freq = {'machine': 100, 'learning': 200, 'machinelearning': 50}
print(spell_correct('machne', vocab, freq))   # machine
```

## Intent

Intent（意图识别）判断用户发起搜索「想干什么」——是想买（交易型）、想学/了解（信息型）、还是想导航到某个网站（导航型）。意图决定了下游的排序策略：交易意图优先推商品、信息意图优先推内容、导航意图优先推官网。

```text
常见意图分类：
1. 交易型（Transactional）—— 「买」「价格」「哪家好」→ 想成交
2. 信息型（Informational）—— 「是什么」「怎么做」「原理」→ 想了解
3. 导航型（Navigational）—— 明确想找某个站点/品牌

识别方法：
- 规则/关键词 —— 「买/多少钱」→ 交易
- 分类模型 —— 用 query 特征 + 行为特征训练多分类器
- LLM —— 现代做法，直接让大模型输出意图标签
```

```python
from sklearn.feature_extraction.text import CountVectorizer
from sklearn.linear_model import LogisticRegression

def train_intent_classifier(samples):
    """用 query 文本训练意图分类器（简化演示）"""
    texts = [s[0] for s in samples]
    labels = [s[1] for s in samples]
    vec = CountVectorizer()
    X = vec.fit_transform(texts)
    clf = LogisticRegression().fit(X, labels)
    return vec, clf

samples = [
    ('苹果手机多少钱', 'transactional'),
    ('苹果手机哪里买', 'transactional'),
    ('苹果手机是什么', 'informational'),
    ('怎么选手机', 'informational'),
    ('苹果官网', 'navigational'),
    ('小米官网', 'navigational'),
]
vec, clf = train_intent_classifier(samples)
print(clf.predict(vec.transform(['苹果手机价格'])))       # transactional
print(clf.predict(vec.transform(['苹果手机使用方法'])))   # informational
```

## Entity Recognition

Entity Recognition（实体识别，NER）从 query 中识别出有明确指代对象的实体——人名、商品名、品牌、地点、时间、型号等。识别出的实体可以用于结构化召回（精确匹配实体库）、意图绑定（「周杰伦」是歌手还是歌曲名）、以及排序加权（实体命中优先）。

```text
实体识别的价值：
1. 结构化召回 —— 实体直接匹配商品库/知识库，召回更准
2. 歧义消解 —— 「苹果」是水果、手机还是公司？结合上下文判断
3. 排序加权 —— query 里出现的实体对应的文档优先
4. 槽位抽取 —— 「5000 元以下的手机」→ {价格: <5000, 品类: 手机}

方法：词典匹配（AC 自动机）、序列标注模型（BiLSTM-CRF）、LLM
```

```python
import re

def recognize_entities(query, entity_dict):
    """词典匹配的实体识别（简化）"""
    found = []
    for entity_type, entities in entity_dict.items():
        for e in entities:
            if e in query:
                found.append((e, entity_type))
    return found

entity_dict = {
    'brand': ['苹果', '小米', '华为'],
    'category': ['手机', '电脑', '平板'],
    'price': ['便宜', '贵的', '性价比'],
}
print(recognize_entities('苹果手机性价比怎么样', entity_dict))
# [('苹果', 'brand'), ('手机', 'category'), ('性价比', 'price')]
```

## Query Expansion

Query Expansion（查询扩展）在原始 query 之外补充「相关词」以提升召回。它比同义词扩展更宽泛——可以补充上下位词（「苹果手机」扩展出「iPhone」）、相关实体、用户行为挖掘的相关词。扩展的目的是「多召回一些潜在相关文档」，再靠排序把关。

```text
查询扩展的几种方法：
1. 同义词扩展 —— 上一节的 Synonym（狭义的扩展）
2. 相关词扩展 —— 从点击日志、共现、词向量找相关词
3. 伪相关反馈（PRF）—— 先用原 query 检索，取 top-K 文档里的高频词扩展
4. 词向量/Embedding —— 找 query 词的近邻词做扩展
5. LLM 生成 —— 让大模型生成扩展 query

风险：扩展过度 → 召回噪声增大、精度下降，需控制扩展词数量和质量
```

```python
import numpy as np

def vector_query_expansion(query_tokens, word_vec, topn=3):
    """用词向量找 query 的近邻词做扩展"""
    expanded = list(query_tokens)
    for t in query_tokens:
        if t not in word_vec:
            continue
        # 找与 t 最相似的 topn 个词（排除原词）
        sims = [(w, np.dot(word_vec[t], word_vec[w])) for w in word_vec if w != t]
        sims.sort(key=lambda x: -x[1])
        expanded.extend(w for w, _ in sims[:topn])
    return list(dict.fromkeys(expanded))   # 去重保序

# 模拟词向量（正交/相近）
word_vec = {
    '手机': np.array([1, 0, 0]),
    'iphone': np.array([0.9, 0.1, 0]),
    '智能机': np.array([0.85, 0.05, 0]),
    '电脑': np.array([0, 1, 0]),
    '平板': np.array([0, 0.9, 0.1]),
}
print(vector_query_expansion(['手机'], word_vec, topn=2))
# ['手机', 'iphone', '智能机']
```

```python
def full_qu_pipeline(raw_query, vocab, freq, rules, entity_dict):
    """把各个模块串起来，输出结构化的查询理解结果"""
    corrected = spell_correct(raw_query, vocab, freq)
    rewritten = query_rewrite(corrected, rules)
    entities = recognize_entities(rewritten, entity_dict)
    expanded = synonym_expand(rewritten.split())
    return {
        'raw': raw_query,
        'corrected': corrected,
        'rewritten': rewritten,
        'entities': entities,
        'expanded': expanded,
    }

rules = {'多少钱': '价格', 'iphone': 'iPhone'}
result = full_qu_pipeline(
    'iphone 多少钱', vocab, freq, rules, entity_dict)
for k, v in result.items():
    print(f'{k}: {v}')
```

### 场景二：纠错 + 扩展对召回的提升演示

```python
def recall_demo(index, raw_query, vocab, freq):
    """对比「不纠错」和「纠错+扩展」的召回差异"""
    raw_docs = boolean_retrieval(index, raw_query)
    corrected = spell_correct(raw_query, vocab, freq)
    expanded = synonym_expand(corrected.split())
    # 用 OR 把所有扩展词召回
    ext_query = ' OR '.join(expanded)
    ext_docs = boolean_retrieval(index, ext_query)
    return raw_docs, ext_docs

index = {
    'machine': {'d1'}, 'learning': {'d1', 'd2'},
    '机器学习': {'d1', 'd2', 'd3'}, '深度学习': {'d3'},
}
raw, ext = recall_demo(index, 'machne', vocab, freq)
print(f'纠错前召回: {raw}')       # 拼错词 machne 召回为空
print(f'纠错后召回: {ext}')       # 纠成 machine + 扩展后召回更多
```

## 最佳实践与踩坑记录

### 最佳实践

1. 纠错用「编辑距离 + 词频/语言模型」，别只靠编辑距离（会把对的纠成错的）
2. 同义词/扩展要分「替换」和「扩展」两档：替换保精度、扩展保召回，别一刀切
3. 意图识别先上规则+关键词打底，再用模型/LLM 覆盖长尾
4. 实体识别优先词典匹配（快且准），模型兜底长尾和未登录实体
5. Query Understanding 的每个模块都要有「降级开关」，模块失败不能拖垮搜索
6. 所有改写/扩展都要做 AB 验证，警惕「召回涨了但精度掉了」

### 踩坑记录

```text
坑 1：纠错太激进把长尾词纠错
结论：用户搜冷门品牌「小天鹅」，被纠成「大天鹅」，召回全错。
原因：编辑距离候选里高频词压过长尾正确词，没有置信度门槛。
解法：纠错加置信度阈值，长尾词/词典命中的词不纠错，先命中再纠。

坑 2：同义词扩展过度引入噪声
结论：搜「苹果」扩展出「水果/公司/手机」一大堆，结果五花八门。
原因：一词多义没做歧义消解，盲目扩展所有义项。
解法：结合上下文/意图做词义消解，或把扩展词降权而非等价替换。

坑 3：意图识别规则太硬
结论：「苹果手机多少钱啊」识别成交易，「苹果手机怎么用」也误判成交易。
原因：只匹配「多少钱」等关键词，忽略了「怎么用」这种信息型信号。
解法：规则 + 分类模型组合，或用 LLM 做更细粒度的意图理解。

坑 4：实体识别漏掉未登录实体
结论：新上市的商品、新出道的艺人查不到，实体库没更新。
原因：纯词典匹配覆盖不了新增实体，且更新滞后。
解法：词典 + 序列标注模型 + 实时挖掘新词，多路召回实体。

坑 5：查询扩展只加词不加权
结论：扩展词和原词权重一样，导致「扩展词命中」的文档压过「原词命中」的文档。
原因：扩展阶段没把「原词优先、扩展词降权」的约束传给排序。
解法：扩展词带权重（如 0.5）传给排序，原词保持高权重。
```

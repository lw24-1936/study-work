## 概述

Hybrid Search（混合检索）把「关键词检索」和「向量语义检索」结合起来：BM25 擅长精确匹配（专有名词、型号、ID），向量检索擅长语义匹配（同义改写、模糊意图），两者互补。核心挑战是「如何融合两种不同的分数/排序」——加权融合、倒数排名融合（RRF）、以及用重排模型精排。

```text
为什么要混合检索：
1. 关键词检索强项 —— 精确词、稀有词、专有名词、代码/型号
2. 向量检索强项 —— 同义表达、语义相近、模糊查询
3. 单独用都不完美 —— BM25 不懂语义，向量检索对精确词/数字不敏感

融合的两条路线：
- 分数融合（加权、RRF）—— 把两路结果在「分数层」合并
- 重排精排（Reranker/Cross Encoder）—— 两路召回后统一送模型精排
```

```python
# 混合检索的宏观流程
def hybrid_search(query, bm25_index, vector_index, fusion='rrf'):
    bm25_results = bm25_index.search(query)      # 1. 关键词召回
    vector_results = vector_index.search(query)  # 2. 向量召回
    if fusion == 'rrf':
        return rrf_fusion([bm25_results, vector_results])
    return weighted_fusion([bm25_results, vector_results])
```

## BM25 + Vector

「BM25 + Vector」是混合检索最基础的形态：同时跑一个关键词检索（BM25，基于倒排索引）和一个向量检索（稠密 embedding 相似度，基于 ANN 索引），各自返回一个候选列表。BM25 保证「精确词一定命中」，向量保证「语义相近也能命中」，两路结果互为补充。

```text
两路检索的互补性：
1. BM25 覆盖 —— 精确词、型号（"iPhone 15 Pro"）、代码、缩写
2. Vector 覆盖 —— 同义改写（"怎么修手机" vs "手机维修"）、跨语言语义
3. 召回率提升 —— 两路并集比任何单路的召回率都高

实现要点：
- BM25 用倒排索引，向量用 ANN（HNSW/IVF）索引
- 各自独立 top-K 召回，再在融合层合并
```

```python
def bm25_search(query, index):
    """模拟 BM25 关键词召回（返回 doc → bm25 分数）"""
    results = {}
    for term in query.split():
        for doc in index.get(term, []):
            results[doc] = results.get(doc, 0) + 1   # 简化的词频累加
    return results

def vector_search(query, doc_vectors, query_encoder):
    """模拟向量召回（余弦相似度）"""
    import numpy as np
    qv = query_encoder(query)
    results = {}
    for doc, dv in doc_vectors.items():
        sim = np.dot(qv, dv) / (np.linalg.norm(qv) * np.linalg.norm(dv) + 1e-9)
        results[doc] = sim
    return results

index = {'苹果': ['d1', 'd3'], '手机': ['d1', 'd2']}
doc_vectors = {'d1': [1, 0, 0], 'd2': [0.9, 0.1, 0], 'd3': [0, 1, 0]}
def q_encoder(q):
    return [1, 0, 0] if '苹果' in q else [0, 1, 0]

print('BM25 结果:', bm25_search('苹果 手机', index))
print('Vector 结果:', vector_search('苹果 手机', doc_vectors, q_encoder))
```

## Weighted Fusion

Weighted Fusion（加权融合）把两路检索的分数归一化后按权重线性相加：final_score = α·bm25_score + (1-α)·vector_score。它简单、可解释，但难点在于两路分数「量纲不同、分布不同」——BM25 分数可以很大，向量相似度在 [-1, 1]，直接相加前必须归一化。

```text
加权融合的步骤：
1. 归一化 —— 各自分数做 min-max 或 z-score 归一化到 [0, 1]
2. 加权求和 —— final = α·norm(bm25) + (1-α)·norm(vector)
3. α 调参 —— 用验证集/AB 实验调，精确匹配场景 α 大、语义场景 α 小

风险：两路分数分布差异大时，不归一化会「一路碾压另一路」
```

```python
def minmax_normalize(scores):
    if not scores:
        return {}
    vals = list(scores.values())
    lo, hi = min(vals), max(vals)
    if hi == lo:
        return {k: 1.0 for k in scores}
    return {k: (v - lo) / (hi - lo) for k, v in scores.items()}

def weighted_fusion(bm25_scores, vector_scores, alpha=0.5):
    """归一化后加权融合"""
    bm25_n = minmax_normalize(bm25_scores)
    vec_n = minmax_normalize(vector_scores)
    fused = {}
    for doc in set(bm25_n) | set(vec_n):
        fused[doc] = alpha * bm25_n.get(doc, 0) + (1 - alpha) * vec_n.get(doc, 0)
    return dict(sorted(fused.items(), key=lambda x: -x[1]))

bm25 = {'d1': 2, 'd3': 1}
vec = {'d1': 1.0, 'd2': 0.9}
print(weighted_fusion(bm25, vec, alpha=0.5))
# {'d1': 1.0, 'd2': 0.45, 'd3': 0.25} → d1 两路都命中排最前
```

## RRF

RRF（Reciprocal Rank Fusion，倒数排名融合）是另一种融合方式：不关心分数大小，只看「每个文档在各路结果里的排名」，用排名倒数求和。它对分数的量纲完全不敏感，各路结果天然可比，是 Hybrid Search 里最简单、最鲁棒的融合方法，被 Weaviate/Elasticsearch 等广泛采用。

```text
RRF 公式：
RRF(doc) = Σ_{每个检索器 r} 1 / (k + rank_r(doc))

- rank_r(doc)：doc 在检索器 r 结果中的排名（从 0 或 1 开始）
- k：平滑常数（常取 60），防止单个排名差异过大
- 只在「命中结果」的文档上累加，未命中的贡献 0

优点：无需分数归一化、对分数分布鲁棒、实现简单
```

```python
def rrf_fusion(ranked_lists, k=60):
    """ranked_lists: 多路检索的结果列表（已按分数降序）"""
    scores = {}
    for ranked in ranked_lists:
        for rank, doc in enumerate(ranked):   # rank 从 0 开始
            scores[doc] = scores.get(doc, 0) + 1 / (k + rank)
    return dict(sorted(scores.items(), key=lambda x: -x[1]))

# 两路召回：BM25 排 [d1, d3, d5]，向量排 [d1, d2, d4]
bm25_ranked = ['d1', 'd3', 'd5']
vec_ranked = ['d1', 'd2', 'd4']
print(rrf_fusion([bm25_ranked, vec_ranked], k=60))
# d1 两路都第一 → 分数最高；d3/d5/d2/d4 各命中一路
```

## Reranker

Reranker（重排模型）是混合检索的第二阶段：两路召回（BM25 + 向量）各自返回 top-N 候选后，把候选合并去重，交给一个「更强的模型」做精排，输出最终的 top-K。重排模型通常更慢但更准（如 Cross Encoder），只在少量候选上运行，兼顾精度与效率。

```text
Reranker 在混合检索中的位置：
1. 召回阶段（快）—— BM25 + 向量各自召回 top-100
2. 合并去重 —— 得到候选集（可能 150~200 个）
3. 重排阶段（准）—— Reranker 对每个 (query, doc) 精细打分
4. 输出 top-K —— 取重排后的前 10~20 个给用户

意义：用「少量慢模型」修正「大量快模型」的排序误差
```

```python
def rerank_pipeline(query, candidates, reranker):
    """对合并后的候选用重排模型精排"""
    scored = [(doc, reranker.score(query, doc)) for doc in candidates]
    scored.sort(key=lambda x: -x[1])
    return scored

class SimpleReranker:
    def score(self, query, doc):
        # 模拟：query 与 doc 的重叠词越多分数越高（可换成 Cross Encoder）
        return len(set(query.split()) & set(doc.split()))

candidates = ['苹果 手机 评测', '苹果 电脑 发布', '小米 手机 参数', '手机 壳']
reranker = SimpleReranker()
print(rerank_pipeline('苹果 手机', candidates, reranker)[:2])
# [('苹果 手机 评测', 2), ...] → 重叠词最多的排最前
```

## Cross Encoder

Cross Encoder（交叉编码器）是一种「把 query 和 doc 拼在一起、整体编码」的深度重排模型。它把 query 和 document 同时输入一个 Transformer（如 BERT），模型内部充分交互两者的 token，输出一个相关性分数。精度高，但无法预先离线编码文档（每个 query-doc 对都要重新算），所以只适合做重排，不适合做大规模召回。

```text
Cross Encoder vs Bi-Encoder：
1. Bi-Encoder —— query 和 doc 分别编码成向量，离线算好、在线点积，快但交互弱
2. Cross Encoder —— query+doc 拼一起编码，token 间充分交互，准但慢

Cross Encoder 的特点：
- 输入：[CLS] query [SEP] document [SEP]
- 输出：[CLS] 位置向量 → 全连接 → 相关性分数（0~1）
- 无法离线缓存文档表示，每个 (query, doc) 都要实时前向
```

```python
# 用 HuggingFace 演示 Cross Encoder 的输入构造（伪代码，需装 transformers）
def cross_encoder_input(query, document, tokenizer):
    """构造 Cross Encoder 的输入序列"""
    # [CLS] query [SEP] document [SEP]
    return tokenizer(query, document, return_tensors='pt', truncation=True,
                     max_length=512)

# 概念演示：Cross Encoder 与 Bi-Encoder 的差异
def bi_encoder_score(q_vec, d_vec):
    import numpy as np
    return np.dot(q_vec, d_vec)   # 独立编码后点积，无 token 交互

# Cross Encoder 的核心优势：query 与 doc 的 token 在同一层 attention 里交互
print('Cross Encoder 输入结构: [CLS] query [SEP] document [SEP]')
print('Bi-Encoder 分数示例:', bi_encoder_score([1, 0], [0.8, 0.2]))
```

## ColBERT

ColBERT（Contextualized Late Interaction over BERT）是介于 Bi-Encoder 和 Cross Encoder 之间的「延迟交互」模型：query 和 doc 分别用 BERT 编码成「token 级向量」，然后做「token 级的最大相似度求和」。它既保留了 token 间的细粒度交互（比 Bi-Encoder 准），又允许文档 token 向量离线预存（比 Cross Encoder 快得多）。

```text
ColBERT 的核心（Late Interaction）：
1. 编码 —— query 的每个 token 和 doc 的每个 token 各自独立编码成向量
2. 交互 —— 对每个 query token，找它在 doc 里最相似的 token 向量
3. 求和 —— 所有 query token 的「最大相似度」累加作为相关性分数

MaxSim 公式：
score(q, d) = Σ_{t∈q} max_{j∈d} cos( E_q(t), E_d(j) )

优势：文档向量可离线预存（存 token 级矩阵），在线只算 query 侧 + MaxSim
```

```python
import numpy as np

def colbert_score(query_vecs, doc_vecs):
    """query_vecs/doc_vecs: [num_tokens, dim]，token 级向量"""
    # 归一化
    q = query_vecs / (np.linalg.norm(query_vecs, axis=1, keepdims=True) + 1e-9)
    d = doc_vecs / (np.linalg.norm(doc_vecs, axis=1, keepdims=True) + 1e-9)
    sim = q @ d.T                    # [num_q_tokens, num_d_tokens] 余弦相似度矩阵
    maxsim = sim.max(axis=1)         # 每个 query token 找最相似 doc token
    return maxsim.sum()

# 模拟：query 3 个 token，doc 4 个 token，各 8 维
q_vecs = np.random.randn(3, 8)
d_vecs = np.random.randn(4, 8)
print('ColBERT 分数:', round(colbert_score(q_vecs, d_vecs), 4))
```

## 应用场景实战

### 场景一：完整混合检索 + RRF 融合 + 重排

```python
def full_hybrid_search(query, bm25_index, doc_vectors, q_encoder, reranker):
    """BM25 + 向量 → RRF 融合 → Cross Encoder 重排"""
    # 1. 两路召回
    bm25 = bm25_search(query, bm25_index)
    vec = vector_search(query, doc_vectors, q_encoder)
    # 2. 转成排名列表
    bm25_ranked = [d for d, _ in sorted(bm25.items(), key=lambda x: -x[1])]
    vec_ranked = [d for d, _ in sorted(vec.items(), key=lambda x: -x[1])]
    # 3. RRF 融合
    fused = rrf_fusion([bm25_ranked, vec_ranked])
    # 4. 重排
    ranked = sorted(fused.items(), key=lambda x: -x[1])
    final = [(doc, reranker.score(query, doc)) for doc, _ in ranked]
    final.sort(key=lambda x: -x[1])
    return final

index = {'苹果': ['d1', 'd3'], '手机': ['d1', 'd2'], '评测': ['d2']}
doc_vectors = {'d1': [1, 0, 0], 'd2': [0.9, 0.1, 0], 'd3': [0, 1, 0]}
reranker = SimpleReranker()
print(full_hybrid_search('苹果 手机', index, doc_vectors, q_encoder, reranker))
```

### 场景二：加权融合 vs RRF 的对比

```python
def compare_fusion(bm25_scores, vector_scores):
    """对比加权融合和 RRF 的排序差异"""
    wf = weighted_fusion(bm25_scores, vector_scores, alpha=0.5)
    bm25_ranked = [d for d, _ in sorted(bm25_scores.items(), key=lambda x: -x[1])]
    vec_ranked = [d for d, _ in sorted(vector_scores.items(), key=lambda x: -x[1])]
    rrf = rrf_fusion([bm25_ranked, vec_ranked])
    return wf, rrf

# 两路分数量纲差异大：BM25 分数大，向量分数小
bm25_scores = {'d1': 15, 'd2': 10, 'd3': 8}
vector_scores = {'d1': 0.9, 'd4': 0.85, 'd5': 0.8}
wf, rrf = compare_fusion(bm25_scores, vector_scores)
print('加权融合:', list(wf.keys())[:3])
print('RRF 融合:', list(rrf.keys())[:3])
# RRF 对量纲不敏感，d4/d5（仅向量命中）排名相对更公平
```

## 最佳实践与踩坑记录

### 最佳实践

1. 默认用 RRF 做融合，它无需分数归一化、鲁棒性强，是混合检索的首选
2. 加权融合前必须归一化（min-max/z-score），否则分数量纲差异会「一路碾压另一路」
3. Cross Encoder 只做重排（候选 50~200 个），别用它做全量召回，延迟扛不住
4. 召回数量要给足（两路各 top-100），重排模型才有足够的候选可挑
5. ColBERT 适合「文档向量可离线预存」的场景，兼顾准度和效率
6. 融合参数（α/k）用验证集调，最终以线上 NDCG/AB 为准

### 踩坑记录

```text
坑 1：加权融合不归一化，向量路被 BM25 淹没
结论：BM25 分数普遍几百，向量相似度在 0~1，加权后向量几乎没贡献。
原因：两路分数量纲和分布差异巨大，直接相加 BM25 碾压向量。
解法：先各自归一化到 [0,1] 再加权，或直接用 RRF 绕开归一化问题。

坑 2：RRF 的 k 值设得太小
结论：k=1 时排名第 1 和第 100 的差距被放大，融合结果不稳定。
原因：1/(k+rank) 在 k 小时对排名过于敏感，噪声被放大。
解法：k 取 60（业界惯例），让排名差异平滑化。

坑 3：Cross Encoder 拿去做全量召回
结论：把 Cross Encoder 当召回模型跑全库，延迟爆炸、成本上天。
原因：Cross Encoder 每个 (query, doc) 都要实时前向，无法离线预存。
解法：Bi-Encoder/BM25 做召回，Cross Encoder 只在 top-100 候选上重排。

坑 4：召回太少，重排模型「巧妇难为无米之炊」
结论：每路只召回 top-10，合并后候选太少，重排模型没有发挥空间。
原因：召回阶段过度裁剪，真正的相关文档可能没进候选集。
解法：召回放宽到 top-100，重排后只输出 top-10，保证精度。

坑 5：向量库与倒排索引不同步
结论：新文档进库了 BM25 能查到，但向量索引还没更新，混合检索漏召回。
原因：两套索引的写入/更新节奏不一致。
解法：统一写入流程，保证两路索引的文档集合和版本一致。
```

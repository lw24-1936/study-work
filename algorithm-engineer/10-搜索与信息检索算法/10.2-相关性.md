## 概述

相关性（Relevance）回答「文档和查询有多匹配」。倒排索引解决了「哪些文档包含查询词」，相关性打分则解决「包含查询词的文档里，谁更该排前面」。从布尔检索的「有/无」，到 TF-IDF 的「词频加权」，再到 BM25 的概率模型，相关性的建模经历了从简单到精确的演进。

```text
相关性模型的演进：
1. Boolean Retrieval —— 精确匹配，只有「相关/不相关」两档
2. TF-IDF —— 词频加权，词在文档里越频繁、越稀有越重要
3. BM25 —— 概率模型，带词频饱和和长度归一化，工业界标准
4. Language Model —— 语言模型视角，算「文档生成查询的概率」

共同的核心：TF（词频）与 IDF（逆文档频率）的权衡
```

```python
# 相关性打分的统一接口：给 query 和文档，返回分数
def score(query, doc_text, model='bm25'):
    """演示三种模型的调用入口（具体实现见后文）"""
    if model == 'boolean':
        return 1 if all(w in doc_text.split() for w in query.split()) else 0
    elif model == 'tfidf':
        return tfidf_score(query, doc_text)
    else:
        return bm25_score(query, doc_text)
```

## Boolean Retrieval

布尔检索是最原始的相关性模型：把查询表达成「词与词之间用 AND/OR/NOT 连接」的布尔表达式，文档要么匹配（相关）、要么不匹配（不相关），没有「相关程度」的概念。它精确、可解释、快，但太死板，用户很难写出好的布尔表达式。

```text
布尔检索的特点：
1. AND —— 文档必须包含所有词（交集）
2. OR —— 文档包含任一词（并集）
3. NOT —— 排除包含某词的文档（差集）

优点：精确可控、结果可解释、无排序歧义
缺点：无相关性排序、无部分匹配、普通用户写不好表达式
```

```python
def boolean_retrieval(index, expression):
    """解析简单布尔表达式：如 '苹果 AND 手机 OR 电脑'（简化：按从左到右顺序处理，不实现布尔优先级）"""
    terms = expression.split()
    result = None
    op = 'OR'
    i = 0
    while i < len(terms):
        tok = terms[i]
        if tok in ('AND', 'OR', 'NOT'):
            op = tok
        else:
            docs = index.get(tok, set())
            if op == 'AND':
                result = result & docs if result is not None else docs
            elif op == 'NOT':
                result = result - docs if result is not None else set()
            else:   # OR
                result = result | docs if result is not None else docs
        i += 1
    return result

index = {'苹果': {'d1', 'd3'}, '手机': {'d1', 'd2'}, '电脑': {'d3'}}
print(boolean_retrieval(index, '苹果 AND 手机'))   # {'d1'}
print(boolean_retrieval(index, '苹果 OR 电脑'))    # {'d1', 'd3'}
```

## TF-IDF

TF-IDF（词频-逆文档频率）给每个「文档-词」对算一个权重：TF 表示词在文档里的频繁程度，IDF 表示词的稀有程度（越稀有的词区分度越高）。文档的向量化表示就是所有词的 TF-IDF 组成的向量，查询与文档的相关性用向量余弦相似度衡量。

```text
TF-IDF 公式：
tf(t, d) = 词 t 在文档 d 中出现的次数（可做 log 归一化）
idf(t) = log( N / df(t) )，N 是文档总数，df(t) 是含 t 的文档数
tfidf(t, d) = tf(t, d) × idf(t)

直觉：
- 词在文档里出现越多 → 越能代表这篇文档（TF）
- 词在很多文档都出现 → 区分度低（IDF 小）
- 「文档中频繁 + 全局稀有」的词权重最高
```

```python
import math

def compute_tfidf(docs):
    """docs: {doc_id: [tokens]}，返回 {doc_id: {term: tfidf}}"""
    N = len(docs)
    df = {}
    for tokens in docs.values():
        for t in set(tokens):
            df[t] = df.get(t, 0) + 1
    idf = {t: math.log(N / (df[t] + 1)) + 1 for t in df}   # 平滑 IDF
    result = {}
    for doc_id, tokens in docs.items():
        tf = {}
        for t in tokens:
            tf[t] = tf.get(t, 0) + 1
        total = len(tokens)
        result[doc_id] = {t: (tf[t] / total) * idf[t] for t in tf}
    return result

docs = {
    'd1': '苹果 手机 发布 苹果'.split(),
    'd2': '小米 手机 评测'.split(),
    'd3': '苹果 电脑 评测'.split(),
}
tfidf = compute_tfidf(docs)
print(tfidf['d1']['苹果'])   # 苹果在 d1 出现 2 次，权重最高
```

```python
def tfidf_score(query, doc_text, idf=None):
    """查询与文档的 TF-IDF 余弦相似度（简化：累加公共词权重）"""
    import math
    q_tokens = query.split()
    d_tokens = doc_text.split()
    score = 0.0
    for t in set(q_tokens):
        if t in d_tokens:
            tf = d_tokens.count(t) / len(d_tokens)
            # 假设全局 IDF 用简单的稀有度模拟
            idf_t = math.log(1 + 1 / max(tf, 1e-9))
            score += tf * idf_t
    return score

print(f'query「苹果 手机」 vs d1: {tfidf_score("苹果 手机", "苹果 手机 发布 苹果"):.4f}')
```

## BM25

BM25（Best Match 25）是目前最主流的「词袋 + 概率」相关性模型，是 TF-IDF 的进化版。它做了三个关键改进：词频饱和（TF 超过一定次数收益递减）、文档长度归一化（长文档不会被高频词过分抬分）、以及更合理的 IDF 形式。Elasticsearch 默认打分就是 BM25。

```text
BM25 公式：
score(d, q) = Σ_{t∈q} IDF(t) · ( tf(t,d)·(k1+1) ) / ( tf(t,d) + k1·(1 - b + b·|d|/avgdl) )

参数含义：
- k1 —— 词频饱和参数（通常 1.2~2.0），控制 TF 的边际收益
- b —— 长度归一化强度（通常 0.75），b=0 不归一、b=1 完全归一
- avgdl —— 平均文档长度
- IDF(t) = log( 1 + (N - df(t) + 0.5) / (df(t) + 0.5) )

特性：TF 饱和 + 长度惩罚 + 概率解释，鲁棒且易调参
```

```python
import math

def bm25_score(query_tokens, doc_tokens, N, df, avgdl, k1=1.5, b=0.75):
    """单个文档的 BM25 分数"""
    doc_len = len(doc_tokens)
    tf = {}
    for t in doc_tokens:
        tf[t] = tf.get(t, 0) + 1
    score = 0.0
    for t in query_tokens:
        if t not in tf:
            continue
        idf = math.log(1 + (N - df[t] + 0.5) / (df[t] + 0.5))
        numerator = tf[t] * (k1 + 1)
        denominator = tf[t] + k1 * (1 - b + b * doc_len / avgdl)
        score += idf * numerator / denominator
    return score

# 语料统计
docs = {
    'd1': '苹果 手机 苹果 苹果'.split(),
    'd2': '小米 手机 评测'.split(),
    'd3': '苹果 电脑 评测'.split(),
}
N = len(docs)
avgdl = sum(len(v) for v in docs.values()) / N
df = {}
for tokens in docs.values():
    for t in set(tokens):
        df[t] = df.get(t, 0) + 1

query = '苹果 手机'.split()
for d, tokens in docs.items():
    print(f'{d} BM25 = {bm25_score(query, tokens, N, df, avgdl):.4f}')
# d1 分数最高（苹果 TF 高且与 query 匹配）
```

## Query Likelihood

Query Likelihood（查询似然）是语言模型检索的一种打分方式：对每个文档估计一个语言模型（词的概率分布），然后计算「该文档模型生成这条查询」的概率。概率越高，说明查询越「像」从这篇文档里抽出来的，文档就越相关。

```text
Query Likelihood 思想：
P(query | doc) = Π P(t | doc)，t 为 query 中的词

P(t | doc) 的估计（需平滑，避免 0 概率）：
- 极大似然估计：P(t|doc) = tf(t,d) / |d|
- Jelinek-Mercer 平滑：P(t|doc) = λ·(tf/|d|) + (1-λ)·P(t|collection)

特点：
- 有严格的概率/生成模型解释
- 平滑是关键，否则未出现词概率为 0 导致整个 query 概率为 0
```

```python
import math

def query_likelihood(query_tokens, doc_tokens, collection_prob, lam=0.5):
    """Jelinek-Mercer 平滑的查询似然打分（用 log 避免下溢）"""
    doc_len = len(doc_tokens)
    tf = {}
    for t in doc_tokens:
        tf[t] = tf.get(t, 0) + 1
    log_prob = 0.0
    for t in query_tokens:
        p_doc = tf.get(t, 0) / doc_len
        p_coll = collection_prob.get(t, 1e-9)
        p = lam * p_doc + (1 - lam) * p_coll
        log_prob += math.log(p)
    return log_prob

# 语料级概率（词在全集中的占比）
collection_prob = {'苹果': 0.3, '手机': 0.2, '电脑': 0.2, '评测': 0.15, '小米': 0.1, '发布': 0.05}
query = '苹果 手机'.split()
for d, tokens in docs.items():
    print(f'{d} QueryLikelihood = {query_likelihood(query, tokens, collection_prob):.4f}')
```

## Language Model

语言模型（Language Model）把「相关性」重新表述为「文档语言模型生成查询的概率」。它统一了检索的数学框架，衍生出 Query Likelihood、KL 散度等多种打分方式，也是后来神经检索和 query 生成式模型的先声。相比 BM25 的「经验公式」，语言模型有更坚实的理论基础。

```text
语言模型检索的三种思路：
1. Query Likelihood —— P(query | doc)，文档生成查询（上节）
2. Document Likelihood —— P(doc | query)，查询生成文档
3. KL 散度 —— 比较 query 模型与 doc 模型的分布差异，差异越小越相关

共同基础：
- 每个文档是一个多项式分布（unigram 语言模型）
- 必须平滑，否则稀疏词导致零概率
- 可用 Dirichlet 平滑等更精细的方法替代简单插值
```

```python
import math

def kl_divergence_relevance(query_tokens, doc_tokens, collection_prob, mu=1000):
    """Dirichlet 平滑下的 KL 散度打分（负 KL 越大越相关）"""
    doc_len = len(doc_tokens)
    tf = {}
    for t in doc_tokens:
        tf[t] = tf.get(t, 0) + 1
    score = 0.0
    for t in query_tokens:
        p_doc = (tf.get(t, 0) + mu * collection_prob.get(t, 1e-9)) / (doc_len + mu)
        p_coll = collection_prob.get(t, 1e-9)
        # 简化：只累加 log 比值（正比于 -KL）
        score += math.log(p_doc / p_coll)
    return score

query = '苹果 手机'.split()
for d, tokens in docs.items():
    print(f'{d} KL-based = {kl_divergence_relevance(query, tokens, collection_prob):.4f}')
```

def rank_documents(query, docs, N, df, avgdl, collection_prob):
    """用三种模型给文档排序，对比结果"""
    q_tokens = query.split()
    results = []
    for d, tokens in docs.items():
        bm25 = bm25_score(q_tokens, tokens, N, df, avgdl)
        ql = query_likelihood(q_tokens, tokens, collection_prob)
        results.append((d, bm25, ql))
    results.sort(key=lambda x: -x[1])   # 按 BM25 降序
    return results

for row in rank_documents('苹果 评测', docs, N, df, avgdl, collection_prob):
    print(f'{row[0]}: BM25={row[1]:.3f}, QL={row[2]:.3f}')

### 场景二：BM25 调参实验（k1 / b 的影响）

```python
def bm25_param_sweep(query, docs, N, df, avgdl, k1_list, b_list):
    """扫描 k1 和 b，观察对排序的影响"""
    for k1 in k1_list:
        for b in b_list:
            scores = {d: bm25_score(query, docs[d], N, df, avgdl, k1, b)
                      for d in docs}
            top = max(scores, key=scores.get)
            print(f'k1={k1}, b={b} → top doc = {top}, score = {scores[top]:.3f}')

query = '手机 评测'.split()
bm25_param_sweep(query, docs, N, df, avgdl, k1_list=[1.2, 2.0], b_list=[0.0, 0.75, 1.0])
# b 越大长文档惩罚越重，可能改变 top 结果
```

## 最佳实践与踩坑记录

### 最佳实践

1. 生产环境默认用 BM25，参数 k1=1.2~1.5、b=0.75，再按业务微调
2. 布尔检索适合「精确过滤 + 权限/类目筛选」，不适合做相关性排序
3. IDF 计算要用「平滑版」，避免 df 接近 N 时出现除零或负数
4. 语言模型检索必须平滑，Dirichlet 平滑通常比 Jelinek-Mercer 更稳健
5. 相关性打分前先统一「分词 + 归一化」，否则模型再准也是建在错误 token 上
6. 评估相关性用 NDCG/MRR（见推荐评估），别只看「能不能命中」

### 踩坑记录

```text
坑 1：BM25 忽略词序和语义
结论：查「苹果 手机」和「手机 苹果」分数一样，且查不到「iPhone」这种同义表达。
原因：词袋模型不建模词序和语义，只看词频和 IDF。
解法：短语查询、位置邻近加分，或引入向量检索做语义补充（见 Hybrid Search）。

坑 2：TF-IDF 没有长度归一化
结论：长文档因为词多、TF 天然高，被无脑排到前面。
原因：TF 直接除文档长度做归一化，但长文档仍占便宜。
解法：用 BM25 的长度归一化（b 参数），或对 TF 做 log 压缩。

坑 3：语言模型不平滑导致零概率
结论：query 里只要有一个词在文档没出现，整篇文档概率为 0。
原因：unigram 模型里未出现词概率为 0，连乘后整体归零。
解法：Jelinek-Mercer / Dirichlet 平滑，给未出现词一个小的集合概率。

坑 4：IDF 用原始公式 df=N 时出错
结论：某词出现在所有文档里，IDF 算成 log(1)=0 或负数。
原因：标准 IDF=log(N/df)，df=N 时对数为 0，加平滑项会变负。
解法：用 BM25 的 IDF 形式 log(1+(N-df+0.5)/(df+0.5))，恒为正。

坑 5：只调相关性不评估排序质量
结论：感觉「搜得更准了」，但没量化指标，无法判断是否真的提升。
原因：缺乏 NDCG/MRR 等离线排序指标，靠主观感受。
解法：建标注数据集，用 NDCG@K 做离线回归，线上用 AB 验证。
```

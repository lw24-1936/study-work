## 概述

Learning to Rank（LTR，学习排序）用机器学习自动学习「文档排序」——输入 query-文档对的一组特征（BM25 分、点击率、价格、时效等），输出一个排序分数。相比手工调 BM25 权重，LTR 能自动组合海量特征，是搜索/推荐排序的工业标准方案。

```text
Learning to Rank 的三类方法（按训练信号粒度分）：
1. Pointwise —— 把排序当回归/分类，学习「单个文档打多少分」
2. Pairwise —— 学习「两两文档谁更该排前」，输出偏好
3. Listwise —— 直接优化整个列表的排序指标（NDCG 等）

训练数据形式：
query → 文档列表（每个文档带特征向量 + 相关性标注 0~4）
```

```python
# LTR 训练数据的标准形态
train_samples = {
    'q1': [
        {'doc': 'd1', 'features': [0.9, 0.8, 0.5], 'label': 4},   # 高度相关
        {'doc': 'd2', 'features': [0.5, 0.4, 0.9], 'label': 2},
        {'doc': 'd3', 'features': [0.1, 0.2, 0.3], 'label': 0},   # 不相关
    ],
}
print('query 数:', len(train_samples), '文档数:', sum(len(v) for v in train_samples.values()))
```

## Pointwise

Pointwise 把排序问题降级成「单文档的回归/分类」：每个 query-文档对独立预测一个分数或相关等级，训练目标是最小化预测值与标注的误差。它最简单、最容易实现，但忽略了文档之间的相对顺序——它不知道「d1 应该排在 d2 前面」这件事。

```text
Pointwise 的特点：
1. 回归 —— 预测相关分（MSE 损失），输出连续分数
2. 分类 —— 预测相关等级（交叉熵），输出 0~4 档
3. 排序 —— 用预测分数对文档降序排列

优点：简单、复用现成的回归/分类模型
缺点：不优化排序目标；标注等级不平衡时效果差
```

```python
from sklearn.linear_model import LinearRegression

def pointwise_train(samples):
    """把每个 query-文档对铺平成 (features, label) 训练回归模型"""
    X, y = [], []
    for docs in samples.values():
        for d in docs:
            X.append(d['features'])
            y.append(d['label'])
    model = LinearRegression().fit(X, y)
    return model

samples = {
    'q1': [
        {'features': [0.9, 0.8, 0.5], 'label': 4},
        {'features': [0.5, 0.4, 0.9], 'label': 2},
        {'features': [0.1, 0.2, 0.3], 'label': 0},
    ],
    'q2': [
        {'features': [0.8, 0.7, 0.6], 'label': 3},
        {'features': [0.3, 0.3, 0.2], 'label': 1},
    ],
}
model = pointwise_train(samples)
print('预测分数:', model.predict([[0.7, 0.6, 0.4], [0.2, 0.1, 0.1]]))
# [3.4, 0.5] → 分数高的排前面
```

## Pairwise

Pairwise 把排序问题建模成「两两文档的偏序分类」：对同一 query 下的两个文档，判断「哪个更相关」。训练目标是让「更相关的文档」预测分数更高。它比 Pointwise 更贴近排序本质，因为排序本质上就是一堆「谁在前谁在后」的偏序关系。

```text
Pairwise 的特点：
1. 样本构造 —— 同一 query 下任意两文档组对，高分者为正例
2. 损失 —— 常用 hinge loss / 交叉熵（RankNet 的交叉熵）
3. 训练后 —— 用预测分数排序，间接得到全序

优点：直接学习相对顺序，比 pointwise 更贴合排序
缺点：偏序数量 O(n²) 爆炸；不同 query 的文档对数不平衡
```

```python
from sklearn.linear_model import LogisticRegression

def pairwise_train(samples):
    """构造文档对 (diff = f_high - f_low)，训练分类器判断高低"""
    X, y = [], []
    for docs in samples.values():
        for i in range(len(docs)):
            for j in range(len(docs)):
                if docs[i]['label'] > docs[j]['label']:
                    diff = [a - b for a, b in zip(docs[i]['features'], docs[j]['features'])]
                    X.append(diff)
                    y.append(1)     # i 比 j 更相关
                elif docs[i]['label'] < docs[j]['label']:
                    diff = [a - b for a, b in zip(docs[i]['features'], docs[j]['features'])]
                    X.append(diff)
                    y.append(0)     # i 不如 j
    model = LogisticRegression().fit(X, y)
    return model

model = pairwise_train(samples)
# 预测两文档谁该在前：f1 - f2 为正 → d1 在前
diff = [a - b for a, b in zip([0.9, 0.8, 0.5], [0.1, 0.2, 0.3])]
print('d1 排在 d2 前面的概率:', model.predict_proba([diff])[0][1])
```

## Listwise

Listwise 直接优化「整个列表」的排序指标——把 query 下的所有文档当做一个整体，目标是让预测排序的 NDCG/DCG 等指标最大化。它最贴合最终评估，但损失函数不可微，需要近似或采样技巧，实现也更复杂。

```text
Listwise 的特点：
1. 优化目标 —— 列表级指标（NDCG、MAP），与评估一致
2. 代表算法 —— ListNet、LambdaRank、SoftRank
3. 难点 —— NDCG 不可微，需要用 softmax 近似排序 / Lambda 梯度

优点：直接优化排序质量，理论上限最高
缺点：实现复杂、样本效率低、训练不稳定
```

```python
import numpy as np

def softmax_ndcg_loss(scores, labels):
    """Listwise 的 NDCG 近似（简化演示：按预测分数顺序算 DCG/IDCG）"""
    # 理想排序的 DCG 与预测排序（scores 已按分数降序）的 DCG
    ideal = sorted(labels, reverse=True)
    gains = 2 ** np.array(labels) - 1
    ideal_gains = 2 ** np.array(ideal) - 1
    dcg = sum(gains[i] / np.log2(i + 2) for i in range(len(gains)))
    idcg = sum(ideal_gains[i] / np.log2(i + 2) for i in range(len(ideal_gains)))
    return 1 - (dcg / idcg) if idcg else 0.0

scores = np.array([2.0, 1.5, 0.5])
labels = [4, 1, 0]
print('softmax NDCG loss:', round(softmax_ndcg_loss(scores, labels), 4))
```

## RankNet

RankNet 是经典的 Pairwise 排序算法，用神经网络学习两文档的偏序关系：对同一 query 下的文档对 (i, j)，用 sigmoid 把「分数差」映射成「i 比 j 更相关」的概率，再用交叉熵作为损失。它是 LambdaRank/LambdaMART 的基础，核心贡献是把「偏序」用可微的概率损失表达出来。

```text
RankNet 核心：
P(i ▷ j) = σ( s_i - s_j ) = 1 / (1 + e^{-(s_i - s_j)})
损失（对真实偏序）：
L = -P̄·log P(i▷j) - (1-P̄)·log(1 - P(i▷j))

其中 P̄ 是真实偏序标签（i 更相关则为 1），s 是模型打分
梯度下降更新网络权重，让分数差的符号贴合真实偏序
```

```python
import numpy as np

def ranknet_prob(si, sj):
    """文档 i 比 j 更相关的概率"""
    return 1 / (1 + np.exp(-(si - sj)))

def ranknet_loss(si, sj, p_bar):
    """单对文档的交叉熵损失"""
    p = ranknet_prob(si, sj)
    return -p_bar * np.log(p + 1e-9) - (1 - p_bar) * np.log(1 - p + 1e-9)

# 真实偏序：i 比 j 更相关（p_bar=1）
si, sj = 2.0, 0.5
print('P(i▷j) =', round(ranknet_prob(si, sj), 4))   # 0.82
print('损失 =', round(ranknet_loss(si, sj, 1.0), 4))  # 分数差大 → 损失小
si, sj = 0.5, 2.0   # 分数反了
print('分数反了时的损失 =', round(ranknet_loss(si, sj, 1.0), 4))  # 损失大
```

## LambdaRank

LambdaRank 是对 RankNet 的关键改进：它观察到「排序真正关心的是交换两个文档位置对 NDCG 的改变量」，于是把梯度从「交叉熵梯度」升级为「带 ΔNDCG 加权的梯度」——交换位置对 NDCG 影响越大的文档对，梯度越大、越被优先纠正。

```text
LambdaRank 的核心思想：
Lambda 梯度 = |ΔNDCG| · (RankNet 的梯度)

其中 ΔNDCG 是「交换文档 i 和 j 的位置后 NDCG 的变化量」：
- 排名靠前（位置小）的文档对，交换影响大 → 梯度大
- 相关性差异大的文档对，交换影响大 → 梯度大

效果：直接朝着「提升 NDCG」的方向优化，而不是只优化偏序概率
```

```python
import numpy as np

def ndcg_gain(label, position):
    """位置 position（从 0 开始）上的 DCG 增益"""
    return (2 ** label - 1) / np.log2(position + 2)

def lambda_gradient(si, sj, li, lj, pos_i, pos_j):
    """计算文档对 (i,j) 的 Lambda 梯度（简化）"""
    # RankNet 部分：真实偏序 i 更相关
    p = 1 / (1 + np.exp(-(si - sj)))
    # 交换 i,j 后 NDCG 的变化量
    delta_ndcg = abs(
        (ndcg_gain(li, pos_i) + ndcg_gain(lj, pos_j)) -
        (ndcg_gain(li, pos_j) + ndcg_gain(lj, pos_i))
    )
    return delta_ndcg * (1 - p)

# 靠前位置（pos 小）的文档对，交换影响大
print('靠前位置的 lambda 梯度:', round(lambda_gradient(1.0, 0.5, 4, 0, 0, 1), 4))
print('靠后位置的 lambda 梯度:', round(lambda_gradient(1.0, 0.5, 4, 0, 9, 10), 4))
# 靠前位置的梯度更大，排序优先纠正顶部
```

## LambdaMART

LambdaMART 是 LambdaRank 与 MART（梯度提升决策树，GBDT）的结合：用提升树的集成去拟合 Lambda 梯度，是目前工业界效果最稳的 LTR 算法之一。它既继承了 GBDT 的非线性拟合能力和鲁棒性，又继承了 LambdaRank 的「直接优化 NDCG」的思想。

```text
LambdaMART 的组成：
1. MART（GBDT）—— 集成多棵回归树，逐步拟合残差/梯度
2. Lambda 梯度 —— 每轮的拟合目标是「带 ΔNDCG 加权的梯度」
3. 直接优化 NDCG —— 最终排序朝着 NDCG 最大化收敛

优势：
- 特征工程友好（树模型，不需要特征归一化）
- 对异常值和噪声鲁棒
- 效果稳定，是搜索排序的「默认强 baseline」
```

```python
from sklearn.ensemble import GradientBoostingRegressor

def lambdamart_train(samples):
    """用 GBDT 模拟 LambdaMART（演示训练-预测-排序流程）"""
    X, y, qid = [], [], []
    for q, docs in samples.items():
        for d in docs:
            X.append(d['features'])
            y.append(d['label'])
            qid.append(q)
    model = GradientBoostingRegressor(n_estimators=50, max_depth=3)
    model.fit(X, y)
    return model

def rank_query(model, docs):
    """对单个 query 的文档打分并排序"""
    scored = [(d['doc'], model.predict([d['features']])[0]) for d in docs]
    scored.sort(key=lambda x: -x[1])
    return scored

samples_ltr = {
    'q1': [
        {'doc': 'd1', 'features': [0.9, 0.8, 0.5], 'label': 4},
        {'doc': 'd2', 'features': [0.5, 0.4, 0.9], 'label': 2},
        {'doc': 'd3', 'features': [0.1, 0.2, 0.3], 'label': 0},
    ],
    'q2': [
        {'doc': 'd4', 'features': [0.8, 0.7, 0.6], 'label': 3},
        {'doc': 'd5', 'features': [0.3, 0.3, 0.2], 'label': 1},
    ],
}
model = lambdamart_train(samples_ltr)
print(rank_query(model, samples_ltr['q1']))
# [('d1', 高分), ('d2', ...), ('d3', ...)] → 按分数降序
```

## 应用场景实战

### 场景一：LTR 完整训练 + NDCG 评估

```python
import numpy as np

def evaluate_ltr(model, samples, k=10):
    """用 NDCG@k 评估训练好的 LTR 模型"""
    ndcgs = []
    for q, docs in samples.items():
        # 用原始 label 计算 NDCG（简化：取前 k 个文档的 label）
        labels = sorted([d['label'] for d in docs], reverse=True)
        def dcg(rels):
            return sum((2 ** r - 1) / np.log2(i + 2) for i, r in enumerate(rels))
        # 预测排序的 label 序列
        pred_labels = []
        for d in rank_query(model, docs)[:k]:
            pred_labels.append([x['label'] for x in docs if x['doc'] == d[0]][0])
        idcg = dcg(labels[:k])
        ndcgs.append(dcg(pred_labels) / idcg if idcg else 0.0)
    return np.mean(ndcgs)

print('NDCG@10 =', round(evaluate_ltr(model, samples_ltr), 4))
```

### 场景二：Pointwise vs Pairwise 排序效果对比

```python
def rank_by_pointwise(model, docs):
    scored = [(d['doc'], model.predict([d['features']])[0]) for d in docs]
    scored.sort(key=lambda x: -x[1])
    return [s[0] for s in scored]

def rank_by_pairwise(model, docs):
    # 用 pairwise 模型给每个文档一个「相对其他文档的得分」
    scores = {}
    for d in docs:
        s = 0.0
        for other in docs:
            if d == other:
                continue
            diff = [a - b for a, b in zip(d['features'], other['features'])]
            s += model.predict_proba([diff])[0][1]
        scores[d['doc']] = s
    return [d for d, _ in sorted(scores.items(), key=lambda x: -x[1])]

point_model = pointwise_train(samples_ltr)
pair_model = pairwise_train(samples_ltr)
print('Pointwise 排序:', rank_by_pointwise(point_model, samples_ltr['q1']))
print('Pairwise 排序:', rank_by_pairwise(pair_model, samples_ltr['q1']))
```

## 最佳实践与踩坑记录

### 最佳实践

1. 从 LambdaMART（GBDT + Lambda 梯度）起步，它是 LTR 最稳的 baseline
2. 特征用「相关性特征（BM25）+ 质量特征（点击/价格）+ 上下文特征」组合
3. 训练数据标注用多级相关（0~4），比二值相关能学到更细的排序
4. 用 NDCG@K 离线评估 + 在线 AB 双保险，别只信离线
5. 不同 query 的文档对数差异大，Pairwise/Listwise 训练要按 query 分组采样
6. 树模型天然免疫特征量纲问题，但深度 LTR 需要特征归一化

### 踩坑记录

```text
坑 1：Pointwise 训练但忽略相对顺序
结论：模型给每个文档打分看似准，但排序结果不如 Pairwise/Listwise。
原因：Pointwise 只优化单文档误差，不优化「谁在前」的相对关系。
解法：优先用 Pairwise/Listwise，或把 Pointwise 分数当特征再叠一层。

坑 2：Listwise 直接优化 NDCG 但不收敛
结论：训练 loss 一直震荡，模型学不到东西。
原因：NDCG 不可微，朴素实现用不可导的排序操作，梯度失效。
解法：用 Lambda 梯度（LambdaRank/LambdaMART）或 softmax 近似（ListNet）。

坑 3：标注数据偏置导致排序偏差
结论：位置靠前的文档因为曝光多、点击多，被误标为「更相关」。
原因：标注来自用户点击，点击受位置偏差影响，不是真实相关性。
解法：用人工标注/专家标注，或用点击模型（如 PBM）修正位置偏差。

坑 4：跨 query 的文档对数量不平衡
结论：热门 query 文档对爆炸，冷门 query 被淹没，模型偏向热门。
原因：Pairwise 样本按文档对计数，长 query 贡献过多样本。
解法：按 query 分组采样/加权，保证每个 query 贡献均衡。

坑 5：只用离线特征没有线上特征
结论：离线 NDCG 很高，上线后效果平平。
原因：离线用的特征（如完整文本）线上拿不到，或线上分布变了。
解法：特征对齐——确保训练和线上用同一套可获取的特征。
```

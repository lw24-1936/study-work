## 概述

字符串算法处理「文本匹配、模式搜索、相似度计算」等基础问题。核心矛盾在于：朴素匹配每次失配都要退回重来，导致 O(n·m) 的最坏复杂度。KMP、Z、Rabin-Karp 用「预处理 + 不回退」或「哈希」把匹配降到线性，AC 自动机扩展到多模式，后缀数组和编辑距离则解决「子串查询」和「相似度」问题。

```text
字符串算法的核心要点：
1. 预处理思想 —— 先分析模式串自身结构（前缀函数、Z 数组），匹配时避免回退
2. 哈希技巧 —— 把字符串转成数字指纹，O(1) 比较子串是否相等
3. 多模式 —— AC 自动机 = Trie + KMP，一次扫文本匹配多个模式
4. 后缀结构 —— 后缀数组支持高效子串查询、最长公共前缀
```

```python
# 朴素匹配（对照基准）：最坏 O(n·m)
def naive_match(text, pattern):
    n, m = len(text), len(pattern)
    result = []
    for i in range(n - m + 1):
        if text[i:i + m] == pattern:
            result.append(i)
    return result

print(naive_match('abababcab', 'ab'))   # [0, 2, 4, 7]
```

## KMP

KMP（Knuth-Morris-Pratt）算法在匹配失配时，利用「模式串自身的前后缀信息」跳过不可能匹配的位置，避免文本指针回退，把匹配复杂度降到 O(n + m)。它的核心是「前缀函数」（也叫 next 数组），记录每个位置的最长相等前后缀长度。

```text
复杂度：
- 预处理（前缀函数）：O(m)
- 匹配：O(n)
- 总：O(n + m)，空间 O(m)

核心思想：
1. 失配时不回退文本指针 i，只移动模式串指针 j
2. next[j] = 模式串前 j 个字符的最长相等前后缀长度
3. 失配时 j 跳到 next[j-1]，已匹配的前缀信息被复用
```

```python
def kmp_prefix_function(pattern):
    """计算 next 数组：next[i] = pattern[:i+1] 的最长相等前后缀长度"""
    m = len(pattern)
    nxt = [0] * m
    j = 0
    for i in range(1, m):
        while j > 0 and pattern[i] != pattern[j]:
            j = nxt[j - 1]      # 失配回退
        if pattern[i] == pattern[j]:
            j += 1
        nxt[i] = j
    return nxt


def kmp_search(text, pattern):
    n, m = len(text), len(pattern)
    if m == 0:
        return [0]
    nxt = kmp_prefix_function(pattern)
    result = []
    j = 0
    for i in range(n):
        while j > 0 and text[i] != pattern[j]:
            j = nxt[j - 1]
        if text[i] == pattern[j]:
            j += 1
        if j == m:
            result.append(i - m + 1)
            j = nxt[j - 1]
    return result


print(kmp_prefix_function('ababc'))   # [0, 0, 1, 2, 0]
print(kmp_search('ababcabcabababd', 'ababd'))   # [10]
```

## Z

Z 算法用「Z 数组」一次性算出「每个位置与字符串开头的最大匹配长度」：Z[i] = s[0:] 与 s[i:] 的最长公共前缀长度。它常用于「找模式串在文本中的所有出现」——把模式串拼在文本前面，中间加分隔符，再扫 Z 数组。

```text
复杂度：
- 时间：O(n + m)（线性，单次扫描）
- 空间：O(n + m)

Z 数组定义：
- Z[i] = 字符串 s 与从下标 i 开始的后缀的最长公共前缀（LCP）长度
- Z[0] 通常定义为 0（或字符串长度）

与 KMP 对比：Z 算法思路更直观（区间扩展），KMP 的前缀函数更经典
```

```python
def z_function(s):
    """Z 算法：O(n) 计算 Z 数组"""
    n = len(s)
    z = [0] * n
    l = r = 0   # [l, r) 是当前匹配到的最右区间
    for i in range(1, n):
        if i < r:
            z[i] = min(r - i, z[i - l])   # 复用已知信息
        while i + z[i] < n and s[z[i]] == s[i + z[i]]:
            z[i] += 1
        if i + z[i] > r:
            l, r = i, i + z[i]
    return z


print(z_function('aabcaabxaaaz'))   # [0, 1, 0, 0, 3, 1, 0, 0, 2, 2, 1, 0]


def z_search(text, pattern):
    """用 Z 算法找模式串所有出现位置"""
    combined = pattern + '#' + text    # 分隔符保证不跨界
    z = z_function(combined)
    m = len(pattern)
    return [i - m - 1 for i in range(len(combined))
            if z[i] == m]


print(z_search('ababcabcab', 'abc'))   # [2, 5]
```

## Rabin-Karp

Rabin-Karp 算法用「滚动哈希」把字符串比较变成整数比较：给每个子串算一个哈希值，哈希不同则一定不相等，哈希相同再逐字符确认（避免哈希碰撞）。它通过「滚动」在 O(1) 内从当前窗口哈希推出下一个窗口哈希，平均 O(n + m)。

```text
复杂度：
- 平均：O(n + m)
- 最坏：O(n·m)（大量哈希碰撞，退化成朴素匹配）
- 空间：O(1)

核心：滚动哈希（多项式哈希）
- hash(s[i:i+m]) 可以用前一个窗口的哈希 O(1) 递推
- 用大素数取模降低碰撞概率
```

```python
def rabin_karp(text, pattern, base=256, mod=10 ** 9 + 7):
    n, m = len(text), len(pattern)
    if m > n:
        return []
    result = []

    # 计算 pattern 的哈希和 text 第一个窗口的哈希
    def char_code(c):
        return ord(c)

    ph = th = 0
    for i in range(m):
        ph = (ph * base + char_code(pattern[i])) % mod
        th = (th * base + char_code(text[i])) % mod

    # base^(m-1) 用于滚动
    power = pow(base, m - 1, mod)

    for i in range(n - m + 1):
        if ph == th and text[i:i + m] == pattern:   # 哈希同再确认
            result.append(i)
        if i < n - m:                                # 滚动到下一窗口
            th = (th - char_code(text[i]) * power) % mod
            th = (th * base + char_code(text[i + m])) % mod
    return result


print(rabin_karp('ababcabcab', 'abc'))   # [2, 5]
```

## AC自动机

AC 自动机（Aho-Corasick）是「多模式匹配」的利器：在一棵 Trie 上叠加 KMP 的失败指针（fail），一次扫描文本就能找出所有模式串的出现。它是敏感词过滤、DNA 序列匹配、入侵检测系统的标准实现。

```text
复杂度：
- 建 Trie：O(总模式长度)
- 建 fail 指针：O(总模式长度)（BFS）
- 匹配：O(文本长度 + 匹配数)
- 空间：O(总模式长度 × 字母表)

核心机制：
1. Trie —— 所有模式串的前缀树
2. fail 指针 —— 失配时跳到「当前节点所代表字符串的最长后缀」节点
3. 匹配时沿 fail 链走，收集所有命中的模式
```

```python
from collections import deque

class ACNode:
    def __init__(self):
        self.children = {}
        self.fail = None
        self.output = []   # 以该节点结尾的模式串

class AhoCorasick:
    def __init__(self):
        self.root = ACNode()

    def build(self, patterns):
        # 1. 建 Trie
        for p in patterns:
            node = self.root
            for ch in p:
                node = node.children.setdefault(ch, ACNode())
            node.output.append(p)
        # 2. BFS 建 fail 指针
        q = deque([self.root])
        self.root.fail = self.root
        while q:
            node = q.popleft()
            for ch, child in node.children.items():
                if node is self.root:
                    child.fail = self.root
                else:
                    f = node.fail
                    while f is not self.root and ch not in f.children:
                        f = f.fail
                    child.fail = f.children.get(ch, self.root)
                    child.output += child.fail.output   # 继承输出
                q.append(child)

    def search(self, text):
        matches = []
        node = self.root
        for i, ch in enumerate(text):
            while node is not self.root and ch not in node.children:
                node = node.fail
            node = node.children.get(ch, self.root)
            for p in node.output:
                matches.append((i - len(p) + 1, p))
        return matches


ac = AhoCorasick()
ac.build(['he', 'she', 'his', 'hers'])
print(ac.search('ushers'))   # [(1,'she'), (2,'he'), (2,'hers')]
```

## 后缀数组

后缀数组（Suffix Array）是字符串所有后缀「按字典序排序」后的下标数组。它把「任意子串查询」转化为「后缀的前缀匹配」，配合 LCP 数组能高效解决最长重复子串、最长公共子串、子串出现次数等问题。

```text
复杂度（倍增法构建）：
- 构建：O(n log n)（倍增 + 双关键字排序）
- 查询子串：O(m log n)（m 是查询串长度）
- 空间：O(n)

核心概念：
1. 后缀数组 SA —— SA[i] = 排名第 i 的后缀的起始下标
2. 排名数组 rank —— rank[i] = 后缀 i 的排名
3. LCP 数组 —— 相邻后缀的最长公共前缀长度（Kasai 算法 O(n) 求）
```

```python
def build_suffix_array(s):
    """倍增法构建后缀数组（简化版，用排序）"""
    n = len(s)
    sa = list(range(n))
    rank = [ord(c) for c in s]
    k = 1
    while k < n:
        # 双关键字：(rank[i], rank[i+k])
        sa.sort(key=lambda i: (rank[i], rank[i + k] if i + k < n else -1))
        new_rank = [0] * n
        new_rank[sa[0]] = 0
        for i in range(1, n):
            prev, cur = sa[i - 1], sa[i]
            prev_key = (rank[prev], rank[prev + k] if prev + k < n else -1)
            cur_key = (rank[cur], rank[cur + k] if cur + k < n else -1)
            new_rank[cur] = new_rank[prev] + (prev_key != cur_key)
        rank = new_rank
        k *= 2
    return sa


s = 'banana'
sa = build_suffix_array(s)
print(sa)   # [5, 3, 1, 0, 4, 2] → a, ana, anana, banana, na, nana
for i in sa:
    print(f'  {s[i:]}')
```

## 编辑距离

编辑距离（Edit Distance / Levenshtein Distance）衡量两个字符串的相似度：把一个字符串通过「插入、删除、替换」变成另一个字符串所需的最少操作次数。它是拼写检查、DNA 比对、模糊搜索、语音识别纠错的基础，用动态规划 O(m·n) 求解。

```text
复杂度：
- 时间：O(m·n)，m、n 是两个字符串长度
- 空间：O(m·n)，可滚动数组优化到 O(min(m, n))

DP 状态转移：
dp[i][j] = s1 前 i 个字符 与 s2 前 j 个字符的编辑距离
- 字符相同：dp[i][j] = dp[i-1][j-1]
- 字符不同：dp[i][j] = 1 + min(插入, 删除, 替换)

变体：Damerau-Levenshtein 额外考虑「相邻字符交换」
```

```python
def edit_distance(s1, s2):
    m, n = len(s1), len(s2)
    dp = [[0] * (n + 1) for _ in range(m + 1)]
    for i in range(m + 1):
        dp[i][0] = i
    for j in range(n + 1):
        dp[0][j] = j
    for i in range(1, m + 1):
        for j in range(1, n + 1):
            if s1[i - 1] == s2[j - 1]:
                dp[i][j] = dp[i - 1][j - 1]
            else:
                dp[i][j] = 1 + min(dp[i - 1][j],      # 删除
                                   dp[i][j - 1],      # 插入
                                   dp[i - 1][j - 1])  # 替换
    return dp[m][n]


print(edit_distance('kitten', 'sitting'))    # 3
print(edit_distance('flaw', 'lawn'))         # 2


def similarity(s1, s2):
    """编辑距离转相似度（0~1，越大越像）"""
    d = edit_distance(s1, s2)
    return 1 - d / max(len(s1), len(s2))

print(f'相似度: {similarity("kitten", "sitting"):.2f}')   # 0.57
```

## 应用场景实战

### 场景一：KMP 做「敏感词检测」

```python
def find_sensitive_words(text, words):
    """在文本中找出所有敏感词及其位置（复用 KMP 单模式匹配）"""
    hits = []
    for word in words:
        positions = kmp_search(text, word)
        for pos in positions:
            hits.append((pos, word))
    return sorted(hits)


text = '这是一段测试文本，包含敏感词A和敏感词B'
words = ['敏感词A', '敏感词B']
print(find_sensitive_words(text, words))
# 大规模多模式场景，应改用 AC 自动机一次扫描完成
```

### 场景二：编辑距离做「拼写纠错建议」

```python
def spell_correct(word, dictionary, top_n=3):
    """从词典里找编辑距离最小的候选词，作为纠错建议"""
    scored = [(w, edit_distance(word, w)) for w in dictionary]
    scored.sort(key=lambda x: x[1])
    return scored[:top_n]


dictionary = ['apple', 'apply', 'april', 'ample', 'banana', 'orange']
print(spell_correct('appl', dictionary))
# [('apple', 1), ('apply', 1), ('april', 2)] → 提示用户可能想输入 apple/apply
```

## 最佳实践与踩坑记录

### 最佳实践

1. 单模式匹配用 KMP 或 Z（线性、无碰撞风险），别用朴素 O(n·m)
2. 多模式匹配（敏感词、关键词库）用 AC 自动机，一次扫描文本匹配全部模式
3. 需要「滚动哈希」的场景（如重复子串检测）用 Rabin-Karp，注意哈希碰撞需二次确认
4. 子串查询、最长重复子串、LCP 用后缀数组或后缀自动机
5. 字符串相似度/模糊匹配用编辑距离（DP），长字符串可加剪枝或改用 n-gram 近似
6. 涉及中文或 Unicode 时，注意按「字符」而非「字节」切分（Python 的 str 已按字符处理）

### 踩坑记录

```text
坑 1：KMP 前缀函数下标写错
结论：nxt 数组偏移一位，匹配结果错位或越界。
原因：next 定义有「最长前后缀长度」和「回跳位置」两种写法，混用导致混乱。
解法：统一用「next[i] = 前 i+1 个字符的最长相等前后缀长度」的写法。

坑 2：Rabin-Karp 哈希碰撞未二次确认
结论：不同子串哈希值相同，误报匹配位置。
原因：取模哈希存在碰撞，仅靠哈希相等就下结论。
解法：哈希相等后必须逐字符比较确认，或用双哈希降低碰撞概率。

坑 3：AC 自动机忘继承 fail 节点的输出
结论：漏报部分模式串的出现位置。
原因：一个模式串是另一个的后缀时（如 he 是 she 的后缀），不沿 fail 链收集输出会漏。
解法：建 fail 时把 fail 节点的 output 合并到当前节点。

坑 4：编辑距离 DP 表开太大 OOM
结论：两个长字符串（如 10 万字符）的 m×n 表直接内存爆炸。
原因：编辑距离空间 O(m·n)，长文本时不可接受。
解法：滚动数组降到 O(min(m,n))，或用「带状 DP」只算对角线附近。

坑 5：Z 数组没加分隔符导致跨模式匹配
结论：把模式串拼文本前不加分隔符，Z 值误跨过模式串边界。
原因：模式串后缀与文本前缀连在一起，可能产生假匹配。
解法：用不在字母表中的分隔符（如 '#'）拼接 pattern + '#' + text。
```

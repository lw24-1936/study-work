## 概述

哈希是一类「用空间换时间」的技术：通过哈希函数把任意数据映射成固定长度的指纹（或下标），从而实现 O(1) 平均查找。它不止是「字典」——Bloom Filter、Cuckoo Hash、HyperLogLog 都是哈希思想的延伸，分别解决「存在性判断」「紧凑存储」「基数估计」等大数据场景的问题。

```text
哈希的核心要点：
1. 哈希函数 —— 把任意输入映射到固定范围，要求均匀、快速、低碰撞
2. 冲突处理 —— 链地址法、开放寻址法、再哈希法是三大主流策略
3. 平均 O(1) —— 查找、插入、删除平均常数时间，最坏退化 O(n)
4. 概率结构 —— Bloom Filter / HyperLogLog 用哈希换取「近似但省内存」的答案
```

```python
# 哈希思想的最小示例
# Python dict / set 底层就是哈希表，平均 O(1) 查找
d = {'apple': 1, 'banana': 2, 'cherry': 3}
print(d['banana'])          # O(1) 平均查找

# 哈希函数：Python 内置 hash() 把对象映射成整数
print(hash('hello'))        # 每次进程内稳定，跨进程可能不同
print(hash((1, 2, 3)))      # 不可变对象才能哈希
```

## Hash Table

哈希表（Hash Table）通过哈希函数把 key 映射到数组下标，理想情况下 O(1) 完成插入、删除、查找。它是字典（dict）、集合（set）、缓存、索引等无数系统的基石，是「平均 O(1) 但最坏 O(n)」的典型代表。

```text
复杂度：
- 插入 / 删除 / 查找：平均 O(1)，最坏 O(n)（哈希冲突全挤一起）
- 遍历：O(n)（但顺序不定，Python 3.7+ 保留插入顺序）

冲突处理策略：
1. 链地址法 —— 每个桶挂一个链表/红黑树，冲突就往里塞（Java HashMap）
2. 开放寻址法 —— 冲突就探测下一个空位（线性探测/二次探测/双哈希）
3. 再哈希法 —— 换一个哈希函数重算

扩容（rehash）：
- 负载因子 = 元素数 / 桶数，超过阈值（如 0.75）就扩容并重新哈希
- 扩容是 O(n) 的昂贵操作，但均摊到每次插入仍是 O(1)
```

```python
# 手写链地址法哈希表
class MyHashMap:
    def __init__(self, cap=8):
        self.cap = cap
        self.buckets = [[] for _ in range(cap)]
        self.size = 0

    def _hash(self, key):
        return hash(key) % self.cap

    def put(self, key, value):
        idx = self._hash(key)
        for i, (k, v) in enumerate(self.buckets[idx]):
            if k == key:
                self.buckets[idx][i] = (key, value)
                return
        self.buckets[idx].append((key, value))
        self.size += 1

    def get(self, key):
        idx = self._hash(key)
        for k, v in self.buckets[idx]:
            if k == key:
                return v
        raise KeyError(key)

    def remove(self, key):
        idx = self._hash(key)
        self.buckets[idx] = [(k, v) for k, v in self.buckets[idx] if k != key]


m = MyHashMap()
m.put('a', 1); m.put('b', 2)
print(m.get('a'))     # 1
m.remove('a')
try:
    m.get('a')
except KeyError:
    print('a 已删除')


# 两数之和：哈希表把 O(n²) 降到 O(n) 的经典应用
def two_sum(nums, target):
    seen = {}
    for i, x in enumerate(nums):
        if target - x in seen:
            return [seen[target - x], i]
        seen[x] = i
    return []

print(two_sum([2, 7, 11, 15], 9))   # [0, 1]
```

## Bloom Filter

布隆过滤器（Bloom Filter）是一种「省内存的概率性集合」：用多个哈希函数把一个元素映射到位数组的多个位置。判断「是否存在」时，只要有一个位是 0 就肯定不存在（零误判），全部是 1 则「可能存在」（有误报）。它用极小的空间换来了「绝对不漏判」的存在性判断。

```text
复杂度：
- 插入 / 查询：O(k)，k 是哈希函数个数（通常几个到十几个，常数）
- 空间：O(m) 位，m 是位数组长度，远小于存储元素本身

核心特性：
1. 绝不漏判 —— 说「不存在」一定不存在，没有假阴性
2. 可能误报 —— 说「存在」可能是哈希碰撞导致的假阳性
3. 不可删除 —— 删除一个元素会误伤共享位的其他元素（可用计数 Bloom Filter）

参数估算（n 元素、期望误报率 p）：
- m = -n·ln(p) / (ln 2)²  位数组长度
- k = (m/n)·ln 2  哈希函数个数
```

```python
import math
import hashlib


class BloomFilter:
    def __init__(self, n, p=0.01):
        self.m = int(-n * math.log(p) / (math.log(2) ** 2))   # 位数组长度
        self.k = max(1, int((self.m / n) * math.log(2)))      # 哈希函数个数
        self.bits = [0] * self.m

    def _hashes(self, item):
        """用双重哈希生成 k 个位置（Kirsch-Mitzenmacher 技巧）"""
        h1 = int(hashlib.md5(item.encode()).hexdigest(), 16)
        h2 = int(hashlib.sha1(item.encode()).hexdigest(), 16)
        return [(h1 + i * h2) % self.m for i in range(self.k)]

    def add(self, item):
        for pos in self._hashes(item):
            self.bits[pos] = 1

    def contains(self, item):
        return all(self.bits[pos] for pos in self._hashes(item))


bf = BloomFilter(n=1000, p=0.01)
for word in ['apple', 'banana', 'cherry']:
    bf.add(word)

print(bf.contains('apple'))    # True（可能存在，这里是真存在）
print(bf.contains('durian'))   # False（肯定不存在）
print(f'位数组长度 m={bf.m}, 哈希函数 k={bf.k}')
```

## Cuckoo Hash

布谷鸟哈希（Cuckoo Hash）用「两个哈希函数 + 两个哈希表」，插入新元素时如果目标位置被占，就把原住民「挤」到它的另一个位置，像布谷鸟把别的鸟蛋推出巢一样。它的核心优势是「最坏情况 O(1) 查找」——查找只检查两个固定位置，没有链式扫描。

```text
复杂度：
- 查找：最坏 O(1)，只检查两个固定位置（这是最大卖点）
- 插入：均摊 O(1)，可能触发「驱逐链」甚至整体重建
- 删除：最坏 O(1)

工作原理：
1. 元素 x 有两个候选位置：h1(x) 和 h2(x)
2. 插入时两个位置都占满，就随机踢走一个，被踢的去找它另一个位置
3. 驱逐链过长或成环 → 用新哈希函数重建整张表（O(n) 罕见操作）

适用场景：
- 对查找延迟有硬性要求的系统（如路由器、缓存）
- 需要高空间利用率（可达 90%+）的紧凑存储
```

```python
class CuckooHash:
    def __init__(self, cap=16):
        self.cap = cap
        self.t1 = [None] * cap   # 表一，用 h1
        self.t2 = [None] * cap   # 表二，用 h2

    def h1(self, key):
        return hash(key) % self.cap

    def h2(self, key):
        return (hash(key) // self.cap) % self.cap   # 另一个哈希

    def lookup(self, key):
        return (self.t1[self.h1(key)] == key or
                self.t2[self.h2(key)] == key)

    def insert(self, key, max_kicks=16):
        cur = key
        for _ in range(max_kicks):
            pos = self.h1(cur)
            if self.t1[pos] is None:
                self.t1[pos] = cur
                return
            # 踢走 t1 里的原住民，它去 t2
            self.t1[pos], cur = cur, self.t1[pos]
            pos = self.h2(cur)
            if self.t2[pos] is None:
                self.t2[pos] = cur
                return
            self.t2[pos], cur = cur, self.t2[pos]
        raise RuntimeError('驱逐链过长，需重建')


ch = CuckooHash()
for k in ['a', 'b', 'c', 'd', 'e']:
    ch.insert(k)
print(ch.lookup('c'))   # True，最坏只需检查两个位置
print(ch.lookup('z'))   # False
```

## HyperLogLog

HyperLogLog（HLL）是一种「基数估计」结构：用极小的内存（通常几 KB）估算一个集合中「不同元素的数量」（基数），误差约 2%。它不存储元素本身，只利用哈希值前导零的分布规律做统计，是 Redis、Spark、数据库里「去重计数」的标准工具。

```text
复杂度：
- 添加元素：O(1)
- 查询基数：O(m)，m 是寄存器数量（通常 2^14 ≈ 16384，常数）
- 空间：O(m) 字节，与元素数量无关，几 KB 就能估几十亿去重

核心原理：
1. 对每个元素算哈希，看二进制哈希值「前导 0 的个数」
2. 前导 0 个数为 k 的概率约 1/2^(k+1)，出现大量前导 0 说明基数大
3. 分桶取平均（调和平均）+ 偏差修正，把误差压到约 1.04/√m

特性：
- 只能回答「有多少个不同元素」，不能回答「具体是哪些」
- 有约 2% 误差，但内存比精确去重（哈希表）省几个数量级
```

```python
import math
import hashlib


class HyperLogLog:
    def __init__(self, b=4):           # b=4 → 2^4=16 个寄存器（演示用小值）
        self.b = b
        self.m = 1 << b
        self.registers = [0] * self.m
        self.alpha = 0.673 if self.m == 16 else (0.7213 / (1 + 1.079 / self.m))

    def _hash(self, value):
        h = int(hashlib.md5(str(value).encode()).hexdigest(), 16)
        return h

    def add(self, value):
        h = self._hash(value)
        idx = h & (self.m - 1)              # 低 b 位决定分到哪个寄存器
        w = h >> self.b                     # 剩余高位
        # 前导 0 个数 + 1（保证至少 1）
        rho = (w.bit_length() == 0) and 1 or (w.bit_length() and 1)
        leading = 0
        ww = w
        while ww and (ww & 1) == 0:
            leading += 1
            ww >>= 1
        self.registers[idx] = max(self.registers[idx], leading + 1)

    def count(self):
        z = sum(2.0 ** -r for r in self.registers)
        estimate = self.alpha * self.m * self.m / z
        # 小基数修正
        if estimate <= 2.5 * self.m:
            zeros = self.registers.count(0)
            if zeros:
                estimate = self.m * math.log(self.m / zeros)
        return int(estimate)


hll = HyperLogLog(b=6)   # 64 个寄存器
for i in range(100000):
    hll.add(f'user_{i}')
print(f'估算基数: {hll.count()}（真实值 100000）')
```

## 应用场景实战

### 场景一：用哈希表实现 LRU 缓存

```python
from collections import OrderedDict

class LRUCache:
    """哈希表 + 双向链表，实现 O(1) 的 get/put 和淘汰"""
    def __init__(self, capacity):
        self.cap = capacity
        self.cache = OrderedDict()

    def get(self, key):
        if key not in self.cache:
            return -1
        self.cache.move_to_end(key)     # 标记为最近使用
        return self.cache[key]

    def put(self, key, value):
        if key in self.cache:
            self.cache.move_to_end(key)
        self.cache[key] = value
        if len(self.cache) > self.cap:
            self.cache.popitem(last=False)   # 淘汰最久未用


cache = LRUCache(2)
cache.put(1, 1); cache.put(2, 2)
print(cache.get(1))      # 1
cache.put(3, 3)          # 淘汰 key=2
print(cache.get(2))      # -1（已淘汰）
```

### 场景二：用 Bloom Filter 做「爬虫去重 / 缓存穿透防护」

```python
class BloomFilter:
    def __init__(self, n, p=0.01):
        import math, hashlib
        self.m = int(-n * math.log(p) / (math.log(2) ** 2))
        self.k = max(1, int((self.m / n) * math.log(2)))
        self.bits = [0] * self.m

    def _pos(self, item):
        h1 = int(hashlib.md5(item.encode()).hexdigest(), 16)
        h2 = int(hashlib.sha1(item.encode()).hexdigest(), 16)
        return [(h1 + i * h2) % self.m for i in range(self.k)]

    def add(self, item):
        for p in self._pos(item):
            self.bits[p] = 1

    def may_exist(self, item):
        return all(self.bits[p] for p in self._pos(item))


# 爬虫 URL 去重：10 万条 URL，误报率 1%，只需约 120 KB 内存
bf = BloomFilter(100000, p=0.01)
crawled = ['http://a.com/1', 'http://a.com/2', 'http://b.com/1']
for u in crawled:
    bf.add(u)

new_url = 'http://c.com/1'
if bf.may_exist(new_url):
    print('可能爬过，跳过')
else:
    print('未爬过，加入队列')
    bf.add(new_url)
```

## 最佳实践与踩坑记录

### 最佳实践

1. 需要精确的键值映射用哈希表（dict），需要省内存的存在性判断用 Bloom Filter
2. 哈希表的 key 必须可哈希（不可变），list 要转成 tuple 才能做 key
3. 自定对象做哈希 key 时同时实现 __hash__ 和 __eq__，两者必须一致
4. Bloom Filter 选参数先定误报率 p，再按公式算 m 和 k，别拍脑袋
5. 只关心「有多少个不同值」且能容忍误差时，用 HyperLogLog 省内存
6. 对查找延迟有硬要求（缓存、路由）用 Cuckoo Hash，最坏 O(1) 查找

### 踩坑记录

```text
坑 1：用可变对象当 dict 的 key
结论：TypeError: unhashable type，或 key 哈希值在插入后悄悄变化。
原因：list/dict 可变，哈希值会随内容改变，破坏哈希表不变量。
解法：可变对象转成不可变的 tuple 或 frozenset 再当 key。

坑 2：自定义对象只实现 __eq__ 不实现 __hash__
结论：对象无法放进 set 或当 dict 的 key。
原因：Python 里 __eq__ 定义后，__hash__ 默认被置为 None。
解法：同时实现 __hash__，且保证「相等对象哈希值必相等」。

坑 3：误以为 Bloom Filter 能删除元素
结论：删除会误伤共享位的其他元素，导致漏判。
原因：多个元素可能映射到同一个位，清 0 会破坏别人。
解法：用计数 Bloom Filter（每位存计数器）或干脆不用 BF 存需删除的数据。

坑 4：把 HyperLogLog 当成「去重集合」用
结论：HLL 只能估数量，不能告诉你具体有哪些元素。
原因：HLL 只保留寄存器最大值，不保存元素本身。
解法：要精确去重列表就用 set/dict；只要基数统计才用 HLL。

坑 5：哈希表负载因子过高不扩容导致退化
结论：负载因子接近 1 时冲突激增，查找从 O(1) 退化成 O(n)。
原因：桶几乎全满，开放寻址探测链极长，链地址链表拉长。
解法：监控负载因子，超 0.75 就扩容；手写哈希表别忘 rehash。
```

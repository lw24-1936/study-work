## 概述

树是「一对多」的层次结构：一个根节点，下面递归地挂子节点，没有环。它把线性结构 O(n) 的查找、插入、删除优化到 O(log n)，是数据库索引（B+ 树）、文件系统、编译原理、自动补全、路由表等几乎所有系统的骨架，理解树就是理解「有序与分层」如何带来性能飞跃。

```text
树的核心要点：
1. 二分思想 —— 二叉搜索树每次比较砍掉一半候选，复杂度降到 O(log n)
2. 平衡 —— 不平衡的树会退化成链表 O(n)，AVL/红黑树靠旋转维持平衡
3. 磁盘友好 —— B/B+ 树把多个键塞进一个节点，减少磁盘 IO 次数
4. 空间换时间 —— Trie、线段树、Fenwick 用额外空间换 O(log n) 的查询
```

```python
# 树的基本表示：节点 + 左右指针（或子节点列表）
class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right


# 三种深度优先遍历
def preorder(root):
    return [] if not root else [root.val] + preorder(root.left) + preorder(root.right)

def inorder(root):
    return [] if not root else inorder(root.left) + [root.val] + inorder(root.right)

def postorder(root):
    return [] if not root else postorder(root.left) + postorder(root.right) + [root.val]
```

## BST

二叉搜索树（Binary Search Tree）规定「左子树所有值 < 根 < 右子树所有值」，使查找、插入、删除都沿一条从根到叶的路径进行，平均 O(log n)。它是所有平衡树的基础，也是最简单的「有序字典」结构。

```text
复杂度（平均 / 最坏）：
- 查找 / 插入 / 删除：O(log n) / O(n)（树退化成链时最坏）
- 中序遍历：O(n)，输出有序序列
- 找最小/最大：O(log n)（沿左/右一路走到底）

退化问题：顺序插入 1,2,3,4,5 会得到一条链，查找退化 O(n) → 需要平衡
```

```python
class BST:
    def insert(self, root, val):
        if not root:
            return TreeNode(val)
        if val < root.val:
            root.left = self.insert(root.left, val)
        else:
            root.right = self.insert(root.right, val)
        return root

    def search(self, root, val):
        if not root or root.val == val:
            return root
        return self.search(root.left if val < root.val else root.right, val)

    def find_min(self, root):
        while root and root.left:
            root = root.left
        return root


bst = BST()
root = None
for v in [5, 3, 8, 1, 4, 7, 9]:
    root = bst.insert(root, v)
print(inorder(root))              # [1, 3, 4, 5, 7, 8, 9] 有序
print(bst.find_min(root).val)     # 1
```

## AVL

AVL 树是第一种自平衡二叉搜索树：任何节点的左右子树高度差（平衡因子）不超过 1，一旦失衡就通过「旋转」恢复。它保证最坏情况也是 O(log n)，适合「查找远多于插入删除」的场景。

```text
复杂度：
- 查找 / 插入 / 删除：O(log n)（严格保证，最坏也不退化）
- 旋转：O(1)（每次插入最多两次旋转恢复平衡）

四种失衡与旋转：
1. LL（左左）→ 右旋
2. RR（右右）→ 左旋
3. LR（左右）→ 先左旋后右旋
4. RL（右左）→ 先右旋后左旋
```

```python
class AVLNode:
    def __init__(self, val):
        self.val = val
        self.left = self.right = None
        self.height = 1


def height(n):
    return n.height if n else 0


def rotate_right(y):
    x = y.left
    y.left = x.right
    x.right = y
    y.height = 1 + max(height(y.left), height(y.right))
    x.height = 1 + max(height(x.left), height(x.right))
    return x


def rotate_left(x):
    y = x.right
    x.right = y.left
    y.left = x
    x.height = 1 + max(height(x.left), height(x.right))
    y.height = 1 + max(height(y.left), height(y.right))
    return y


def avl_insert(root, val):
    if not root:
        return AVLNode(val)
    if val < root.val:
        root.left = avl_insert(root.left, val)
    else:
        root.right = avl_insert(root.right, val)
    root.height = 1 + max(height(root.left), height(root.right))
    balance = height(root.left) - height(root.right)
    if balance > 1 and val < root.left.val:        # LL
        return rotate_right(root)
    if balance < -1 and val > root.right.val:      # RR
        return rotate_left(root)
    if balance > 1 and val > root.left.val:        # LR
        root.left = rotate_left(root.left)
        return rotate_right(root)
    if balance < -1 and val < root.right.val:      # RL
        root.right = rotate_right(root.right)
        return rotate_left(root)
    return root
```

## 红黑树

红黑树是另一种自平衡二叉搜索树，通过给节点涂红/黑并满足 5 条性质来维持「近似平衡」：最长路径不超过最短路径的 2 倍。它的平衡要求比 AVL 松，插入删除需要更少的旋转，是 C++ STL map、Java TreeMap、Linux 调度器的底层实现。

```text
复杂度：
- 查找 / 插入 / 删除：O(log n)（最坏保证）
- 旋转：插入最多 2 次旋转，删除最多 3 次，比 AVL 少

五条性质：
1. 每个节点是红或黑
2. 根节点是黑
3. 叶子（NIL）是黑
4. 红节点的两个子节点都是黑（红不相邻）
5. 从任一节点到其叶子的所有路径黑节点数相同

与 AVL 对比：红黑树插入删除更少旋转（写多读少场景优），AVL 更严格平衡（读多写少场景优）
```

```python
# 红黑树实现复杂，日常直接使用现成结构
# Python 无内置红黑树，可用第三方（如 sortedcontainers.SortedDict）
# 这里演示其「有序映射」语义：维护一个有序字典
from bisect import bisect_left, insort

class SortedMap:
    """用「有序数组 + 二分」模拟红黑树的有序映射接口（理解语义用）"""
    def __init__(self):
        self.keys = []
        self.vals = []

    def put(self, k, v):
        i = bisect_left(self.keys, k)
        if i < len(self.keys) and self.keys[i] == k:
            self.vals[i] = v
        else:
            insort(self.keys, k)
            self.vals.insert(i, v)

    def floor_key(self, k):
        """≤ k 的最大键（红黑树 O(log n) 核心能力之一）"""
        i = bisect_left(self.keys, k)
        if i < len(self.keys) and self.keys[i] == k:
            return self.keys[i]
        return self.keys[i - 1] if i > 0 else None


sm = SortedMap()
for k, v in [(5, 'a'), (3, 'b'), (8, 'c')]:
    sm.put(k, v)
print(sm.floor_key(7))   # 5（≤7 的最大键）
```

## B

B 树是一种「多路平衡搜索树」：每个节点可以存多个键和多个子节点（一个节点能塞进一个磁盘块）。它通过「矮胖」的结构大幅降低树高，从而减少磁盘 IO 次数，是磁盘/数据库索引的经典结构。

```text
复杂度（设阶为 M，即每个节点最多 M 个子节点）：
- 查找 / 插入 / 删除：O(log_M n)，树高远小于二叉树
- 一次操作磁盘 IO：O(log_M n) 次（每次访问一个节点 = 一次 IO）

核心思想：
1. 一个节点存多个键 → 树更矮，IO 更少
2. 节点分裂/合并维持「每个节点至少半满」
3. 数据可存在内部节点（B 树）或只存在叶子（B+ 树）
```

```python
# B 树的「多路」思想：对比二叉树，节点分叉数 M 越大树越矮
import math

def tree_height(n, fanout):
    """估算 n 个键、每个节点最多 fanout 个子节点时的树高"""
    return math.ceil(math.log(n + 1, fanout))

n = 10 ** 9
print(f'二叉树高度: {tree_height(n, 2)}')      # 约 30 层
print(f'B 树 (M=100) 高度: {tree_height(n, 100)}')   # 约 5 层
print(f'B 树 (M=1000) 高度: {tree_height(n, 1000)}')  # 约 3 层
# 树越矮，磁盘 IO 越少 → 这就是数据库用 B/B+ 树而非二叉树的原因
```

## B+Tree

B+ 树是 B 树的变体，也是 MySQL InnoDB 默认索引结构：所有数据只存在叶子节点，内部节点只存键做「导航」，叶子节点之间用链表相连。它把范围查询（range scan）和顺序遍历优化到了极致。

```text
复杂度：
- 查找 / 插入 / 删除：O(log_M n)，且叶子链表让范围查询是 O(k)（k 为结果数）
- 范围查询 [a, b]：先定位 a，再沿叶子链表顺序扫到 b

与 B 树的区别：
1. 数据全在叶子 → 内部节点更小，能塞更多键，树更矮
2. 叶子用链表串起来 → 天然支持范围扫描和顺序 IO
3. 查询必须走到叶子（内部节点只是路由）
```

```python
# 模拟 B+ 树的「叶子链表 + 范围扫描」思想
class LeafChain:
    """叶子节点链表：定位起点后顺序扫描"""
    def __init__(self, data):
        self.data = sorted(data)   # 有序叶子

    def range_scan(self, low, high):
        """O(log n + k)：二分定位 + 顺序扫描"""
        import bisect
        start = bisect.bisect_left(self.data, low)
        result = []
        i = start
        while i < len(self.data) and self.data[i] <= high:
            result.append(self.data[i])
            i += 1
        return result


lc = LeafChain([1, 5, 9, 13, 17, 21, 25])
print(lc.range_scan(8, 20))   # [9, 13, 17]
# 真实 B+ 树里，叶子节点是磁盘页，顺序 IO 扫描比随机 IO 快一个数量级
```

## Trie

Trie（前缀树 / 字典树）把字符串按「字符」逐层展开成一棵树：从根到某节点的路径就是一个前缀。它牺牲空间换来了「前缀匹配、自动补全、字符串集合」的 O(L) 查询（L 为字符串长度），与总字符串数量无关。

```text
复杂度（设字符串长度为 L，字母表大小 Σ）：
- 插入 / 查找 / 删除：O(L)
- 前缀匹配：O(L)
- 空间：O(总字符数 × Σ)，最坏较大（可用压缩 Trie 优化）

特点：
1. 查询与字符串数量无关，只与长度相关
2. 天然支持前缀搜索、自动补全、字典序排序
3. 常用于：搜索引擎提示、拼写检查、IP 路由（最长前缀匹配）
```

```python
class TrieNode:
    def __init__(self):
        self.children = {}
        self.is_end = False


class Trie:
    def __init__(self):
        self.root = TrieNode()

    def insert(self, word):
        node = self.root
        for ch in word:
            node = node.children.setdefault(ch, TrieNode())
        node.is_end = True

    def search(self, word):
        node = self.root
        for ch in word:
            if ch not in node.children:
                return False
            node = node.children[ch]
        return node.is_end

    def starts_with(self, prefix):
        node = self.root
        for ch in prefix:
            if ch not in node.children:
                return False
            node = node.children[ch]
        return True


trie = Trie()
for w in ['apple', 'app', 'application', 'banana']:
    trie.insert(w)
print(trie.search('app'))            # True
print(trie.search('appl'))           # False
print(trie.starts_with('app'))       # True
```

## Radix

Radix Tree（基数树 / 压缩 Trie）是 Trie 的「路径压缩」版本：把只有单个子节点的链合并成一个边，边上存整段字符串。它极大减少了节点数量和内存占用，是 Linux 内核页缓存、路由表、Redis Stream 等内存敏感系统的选择。

```text
复杂度：
- 查找 / 插入 / 删除：O(L)（L 为 key 长度），但节点数远少于 Trie
- 空间：比 Trie 省得多，单链被合并

与 Trie 的区别：
1. 边存字符串片段而非单字符 → 节点更少
2. 每个节点至少有两个子节点（或是一个 key 的终点）
3. 适合 key 稀疏、有长公共前缀的场景
```

```python
class RadixNode:
    def __init__(self, key=''):
        self.key = key          # 这条边上的字符串片段
        self.children = {}
        self.is_end = False


class RadixTree:
    def __init__(self):
        self.root = RadixNode()

    def insert(self, word):
        node = self.root
        while word:
            for ch, child in node.children.items():
                # 找与 word 的公共前缀
                common = 0
                while (common < len(word) and common < len(child.key)
                       and word[common] == child.key[common]):
                    common += 1
                if common == 0:
                    continue
                if common == len(child.key):
                    node = child            # 整段匹配，下钻
                    word = word[common:]
                else:
                    # 分裂节点：把 child.key 拆成两段
                    grand = RadixNode(child.key[common:])
                    grand.children = child.children
                    grand.is_end = child.is_end
                    child.key = child.key[:common]
                    child.children = {grand.key[0]: grand}
                    child.is_end = False
                    node = child
                    word = word[common:]
                break
            else:
                node.children[word[0]] = RadixNode(word)
                node = node.children[word[0]]
                word = ''
        node.is_end = True

    def search(self, word):
        node = self.root
        while word:
            found = False
            for ch, child in node.children.items():
                if word.startswith(child.key):
                    word = word[len(child.key):]
                    node = child
                    found = True
                    break
            if not found:
                return False
        return node.is_end


rt = RadixTree()
for w in ['romane', 'romanus', 'romulus', 'rubens']:
    rt.insert(w)
print(rt.search('romanus'))   # True
print(rt.search('roman'))     # False
```

## Heap

堆（Heap）是一种「完全二叉树」，满足堆序性质：父节点的值 ≤（或 ≥）所有子节点。它用数组紧凑存储（无需指针），是优先队列的底层实现，也是堆排序、Top-K、Dijkstra、合并 K 个有序链表的核心。

```text
复杂度（数组存储，下标 i 的左右子为 2i+1、2i+2）：
- 插入 push：O(log n)
- 取最值 peek：O(1)
- 弹出最值 pop：O(log n)
- 建堆 heapify：O(n)（自底向上调整）

性质：
1. 完全二叉树 → 数组紧凑存储，无指针开销
2. 堆序 → 堆顶是全局最值，但不保证整体有序
```

```python
import heapq

# 最小堆操作
heap = [5, 3, 8, 1, 9]
heapq.heapify(heap)          # O(n) 建堆
print(heap)                  # [1, 3, 5, 8, 9] 堆顶最小
heapq.heappush(heap, 0)      # O(log n) 插入
print(heapq.heappop(heap))   # 0，O(log n) 弹出最小
print(heapq.nsmallest(3, heap))   # [1, 3, 5] Top-3 最小


# 手写建堆（下沉操作）理解 O(n) heapify
def heapify_arr(arr):
    def sift_down(i, n):
        while 2 * i + 1 < n:
            child = 2 * i + 1
            if child + 1 < n and arr[child + 1] < arr[child]:
                child += 1
            if arr[i] <= arr[child]:
                break
            arr[i], arr[child] = arr[child], arr[i]
            i = child
    for i in range(len(arr) // 2 - 1, -1, -1):
        sift_down(i, len(arr))


a = [5, 3, 8, 1, 9]
heapify_arr(a)
print(a)   # 堆序成立，堆顶最小
```

## Segment Tree

线段树（Segment Tree）是一棵用于「区间查询 + 区间更新」的二叉树：每个节点代表一个区间，父区间是左右子区间的并。它支持 O(log n) 的区间求和/最值/更新，是「大量区间操作」场景的利器。

```text
复杂度（设数组长度 n）：
- 建树：O(n)
- 单点更新：O(log n)
- 区间查询（求和/最值）：O(log n)
- 区间更新（懒标记）：O(log n)
- 空间：O(4n)

适用：区间和、区间最大值、区间 GCD、带修改的区间统计
```

```python
class SegmentTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.tree = [0] * (4 * self.n)
        self._build(arr, 0, 0, self.n - 1)

    def _build(self, arr, node, l, r):
        if l == r:
            self.tree[node] = arr[l]
        else:
            mid = (l + r) // 2
            self._build(arr, node * 2 + 1, l, mid)
            self._build(arr, node * 2 + 2, mid + 1, r)
            self.tree[node] = self.tree[node * 2 + 1] + self.tree[node * 2 + 2]

    def _query(self, node, l, r, ql, qr):
        if ql > r or qr < l:
            return 0
        if ql <= l and r <= qr:
            return self.tree[node]
        mid = (l + r) // 2
        return (self._query(node * 2 + 1, l, mid, ql, qr) +
                self._query(node * 2 + 2, mid + 1, r, ql, qr))

    def _update(self, node, l, r, idx, val):
        if l == r:
            self.tree[node] = val
        else:
            mid = (l + r) // 2
            if idx <= mid:
                self._update(node * 2 + 1, l, mid, idx, val)
            else:
                self._update(node * 2 + 2, mid + 1, r, idx, val)
            self.tree[node] = self.tree[node * 2 + 1] + self.tree[node * 2 + 2]

    def query(self, ql, qr):
        return self._query(0, 0, self.n - 1, ql, qr)

    def update(self, idx, val):
        self._update(0, 0, self.n - 1, idx, val)


st = SegmentTree([1, 3, 5, 7, 9, 11])
print(st.query(1, 3))    # 3+5+7 = 15
st.update(2, 10)
print(st.query(1, 3))    # 3+10+7 = 20
```

## Fenwick

树状数组（Fenwick Tree / Binary Indexed Tree）用「二进制低位」做索引，用一个数组维护「前缀和」，支持 O(log n) 的单点更新和前缀和查询。它比线段树更省空间、代码更短，但只能处理「可逆运算」（如求和、异或），不适合求最值。

```text
复杂度：
- 单点更新：O(log n)
- 前缀和查询：O(log n)
- 区间和：两次前缀和相减，O(log n)
- 空间：O(n)，比线段树的 4n 省

核心操作（lowbit）：
- lowbit(x) = x & (-x)，取二进制最低位的 1
- 更新：i += lowbit(i) 向上爬
- 查询：i -= lowbit(i) 向下累加
```

```python
class FenwickTree:
    def __init__(self, n):
        self.n = n
        self.tree = [0] * (n + 1)

    def update(self, i, delta):
        i += 1
        while i <= self.n:
            self.tree[i] += delta
            i += i & (-i)

    def prefix_sum(self, i):
        """前 i 个元素的和 [0, i)"""
        s = 0
        while i > 0:
            s += self.tree[i]
            i -= i & (-i)
        return s

    def range_sum(self, l, r):
        return self.prefix_sum(r + 1) - self.prefix_sum(l)


arr = [1, 3, 5, 7, 9, 11]
ft = FenwickTree(len(arr))
for i, x in enumerate(arr):
    ft.update(i, x)
print(ft.range_sum(1, 3))    # 3+5+7 = 15
ft.update(2, 5)              # arr[2] 5 → 10（增加 5）
print(ft.range_sum(1, 3))    # 3+10+7 = 20
```

## LSM Tree

LSM 树（Log-Structured Merge Tree）是一种「为写入优化」的存储结构：写入先落到内存的 MemTable（有序），满了就刷成磁盘上的 SSTable（有序文件），后台再分层「归并合并」（Compaction）。它把随机写变成顺序写，是 LevelDB、RocksDB、Cassandra、HBase 的核心。

```text
复杂度（区别于 B+ 树）：
- 写入：O(1) 内存写 + 顺序刷盘，极快（写放大换来的）
- 点查：可能查 MemTable + 多层 SSTable，读放大
- 范围查：需要跨层归并，读放大

核心机制：
1. 写路径 —— 先写 WAL（防丢）→ 写 MemTable → 满了刷成 SSTable
2. SSTable —— 有序键值对 + 布隆过滤器加速点查
3. Compaction —— 后台把多层小文件归并成大文件，删旧版本

与 B+ 树对比：B+ 树读快写慢（随机 IO），LSM 写快读慢（顺序 IO）→ 写密集场景选 LSM
```

```python
# 模拟 LSM 的「内存 MemTable + 磁盘 SSTable + 合并」思想
import bisect

class MemTable:
    """内存有序表，模拟 LSM 的写入层"""
    def __init__(self):
        self.data = {}   # 简化用 dict + 有序 key 列表模拟

    def put(self, k, v):
        self.data[k] = v

    def flush(self):
        """刷盘：返回一个有序 SSTable（排序后的键值对列表）"""
        return sorted(self.data.items())


class LSMSim:
    def __init__(self):
        self.sstables = []   # 磁盘上的有序文件列表

    def write(self, k, v):
        mt = MemTable()
        mt.put(k, v)
        self.sstables.append(mt.flush())   # 顺序写盘

    def get(self, k):
        for sst in reversed(self.sstables):   # 新文件优先
            for kk, vv in sst:
                if kk == k:
                    return vv
        return None


lsm = LSMSim()
lsm.write('a', 1)
lsm.write('b', 2)
lsm.write('a', 99)      # 覆盖旧值
print(lsm.get('a'))     # 99（从最新 SSTable 读到新版本）
```

## 应用场景实战

### 场景一：用堆实现「合并 K 个有序链表」

```python
import heapq

class ListNode:
    def __init__(self, val=0, nxt=None):
        self.val = val
        self.next = nxt


def merge_k_lists(lists):
    heap = []
    for i, head in enumerate(lists):
        if head:
            heapq.heappush(heap, (head.val, i, head))
    dummy = tail = ListNode()
    while heap:
        val, i, node = heapq.heappop(heap)
        tail.next = node
        tail = tail.next
        if node.next:
            heapq.heappush(heap, (node.next.val, i, node.next))
    return dummy.next


def build(arr):
    head = tail = ListNode()
    for x in arr:
        tail.next = ListNode(x)
        tail = tail.next
    return head.next


def to_list(head):
    res = []
    while head:
        res.append(head.val)
        head = head.next
    return res


lists = [build([1, 4, 5]), build([1, 3, 4]), build([2, 6])]
print(to_list(merge_k_lists(lists)))   # [1, 1, 2, 3, 4, 4, 5, 6]
```

### 场景二：线段树维护区间最大值（监控场景）

```python
class MaxSegmentTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.tree = [0] * (4 * self.n)
        self._build(arr, 0, 0, self.n - 1)

    def _build(self, arr, node, l, r):
        if l == r:
            self.tree[node] = arr[l]
        else:
            mid = (l + r) // 2
            self._build(arr, node * 2 + 1, l, mid)
            self._build(arr, node * 2 + 2, mid + 1, r)
            self.tree[node] = max(self.tree[node * 2 + 1],
                                  self.tree[node * 2 + 2])

    def _query(self, node, l, r, ql, qr):
        if ql > r or qr < l:
            return float('-inf')
        if ql <= l and r <= qr:
            return self.tree[node]
        mid = (l + r) // 2
        return max(self._query(node * 2 + 1, l, mid, ql, qr),
                   self._query(node * 2 + 2, mid + 1, r, ql, qr))

    def query(self, ql, qr):
        return self._query(0, 0, self.n - 1, ql, qr)


# 监控：每分钟 CPU 使用率，查询任意时间段峰值
cpu = [40, 55, 70, 65, 80, 90, 85, 60]
mst = MaxSegmentTree(cpu)
print(f'第 2~5 分钟峰值: {mst.query(2, 5)}%')   # max(70,65,80,90)=90
```

## 最佳实践与踩坑记录

### 最佳实践

1. 读多写少用 AVL（严格平衡），写多读少用红黑树（旋转少），先分析读写比例
2. 数据库/磁盘索引用 B+ 树，范围查询和顺序 IO 是它最大的优势
3. 字符串前缀匹配、自动补全用 Trie；key 稀疏、内存紧张用 Radix 压缩
4. 优先队列/堆排序/Top-K 用二叉堆，建堆 O(n) 别一个个 push（那才是 O(n log n)）
5. 区间求和、可逆运算用 Fenwick（省空间代码短）；区间最值、复杂运算用线段树
6. 写密集型 KV 存储用 LSM 树，读密集型用 B+ 树，选型看读写放大权衡

### 踩坑记录

```text
坑 1：BST 顺序插入退化
结论：插入 1,2,3,...,n 得到一条链，查找退化成 O(n)。
原因：BST 不保证平衡，插入顺序决定树形。
解法：用 AVL/红黑树自平衡，或插入前随机打乱数据。

坑 2：线段树数组只开 2n 导致越界
结论：某些递归建树路径会用到下标 > 2n 的位置，越界报错。
原因：线段树最坏情况需要 4n 的空间（非满二叉树）。
解法：线段树数组统一开 4n。

坑 3：Fenwick 树下标从 0 开始不 +1
结论：lowbit 运算对下标 0 会死循环（i += i&-i 恒为 0）。
原因：Fenwick 的下标必须从 1 开始，0 的 lowbit 是 0。
解法：封装时内部 +1，把用户的下标映射到 [1, n]。

坑 4：误以为堆是「有序」的
结论：直接遍历堆数组得到的不是排序结果。
原因：堆只满足堆序（父≤子），不保证兄弟间有序。
解法：要排序用 heapify + 反复 heappop，或直接用 sorted。

坑 5：LSM 树忘写 WAL 导致丢数据
结论：只写内存 MemTable 就返回，进程崩溃后最近写入丢失。
原因：MemTable 还没刷成 SSTable 前，数据只在内存里。
解法：写入先落 WAL（顺序追加日志），崩溃后重放恢复。
```

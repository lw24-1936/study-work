## 概述

复杂度分析是算法工程师的基本功：在写代码之前，先判断一个算法随输入规模增长会消耗多少时间与空间，从而在候选方案之间做理性取舍。它不追求精确到毫秒，而是抓住「增长趋势」这一核心，是面试、系统设计、性能优化的共同语言。

```text
复杂度分析的核心要点：
1. 只关注增长趋势 —— 忽略常数项和低阶项，n 很大时它们无关紧要
2. 最坏/平均/最好 —— 三种情况各有意义，面试默认问最坏情况
3. 空间复杂度同样重要 —— 时间换空间、空间换时间是常见权衡
4. 摊销分析 —— 单次操作可能很贵，但均摊到一系列操作上很便宜
```

```python
import time

# 直观感受不同复杂度的增长速度
import math
for n in [10, 100, 1000, 10000]:
    print(f'n={n:>6}  O(log n)={math.log2(n):>7.1f}  '
          f'O(n)={n:>6}  O(n log n)={n * math.log2(n):>9.1f}  '
          f'O(n²)={n ** 2:>9}')
# 观察：n 每扩大 10 倍，O(n²) 扩大 100 倍，而 O(log n) 几乎不动
```

## Big-O

Big-O 表示法描述算法的「上界」：存在常数 c 和 n₀，当 n ≥ n₀ 时，f(n) ≤ c·g(n)，记作 f(n) = O(g(n))。它回答「最坏情况下，算法最多不会比 g(n) 增长得更快」，是日常最常用的记号。

```text
数学定义：
f(n) = O(g(n)) ⟺ 存在 c > 0, n₀，使对所有 n ≥ n₀ 有 f(n) ≤ c·g(n)

常见复杂度排序（从快到慢）：
O(1) < O(log n) < O(√n) < O(n) < O(n log n) < O(n²) < O(n³) < O(2ⁿ) < O(n!)

判断口诀：
1. 只看最高阶项，忽略常数（3n² + 2n + 1 → O(n²)）
2. 循环嵌套相乘，顺序循环相加
3. 二分/分治对半 → 带 log n；递归树每层减半 → log n 层
```

```python
def binary_search(arr, target):
    """O(log n)：每次对半，最多 log₂n 次比较"""
    lo, hi = 0, len(arr) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if arr[mid] == target:
            return mid
        elif arr[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1


def two_sum_brute(nums, target):
    """O(n²)：双重循环"""
    for i in range(len(nums)):
        for j in range(i + 1, len(nums)):
            if nums[i] + nums[j] == target:
                return i, j
    return -1, -1


def two_sum_hash(nums, target):
    """O(n)：哈希表把内层循环变成 O(1) 查找"""
    seen = {}
    for i, x in enumerate(nums):
        if target - x in seen:
            return seen[target - x], i
        seen[x] = i
    return -1, -1
```

## Ω

Ω（Omega）表示法描述算法的「下界」：存在常数 c 和 n₀，当 n ≥ n₀ 时，f(n) ≥ c·g(n)，记作 f(n) = Ω(g(n))。它回答「最好情况下，算法至少也要 g(n) 这个量级的代价」，描述的是一个算法不可能更快的那条底线。

```text
数学定义：
f(n) = Ω(g(n)) ⟺ 存在 c > 0, n₀，使对所有 n ≥ n₀ 有 f(n) ≥ c·g(n)

常见例子：
1. 插入排序最好情况（数组已有序）→ Ω(n)，每轮只比较一次就停
2. 比较排序的下界 → Ω(n log n)，基于比较的排序不可能更快
3. 搜索无序数组 → Ω(n)，至少要把每个元素看一遍

用途：
- 证明算法最优性：如果某问题下界是 Ω(n log n)，你做到 O(n log n) 就是最优
- 与 Big-O 配合，才能完整刻画算法在最好和最坏两端的行为
```

```python
def insertion_sort(arr):
    """最好 Ω(n)、最坏 O(n²)：已有序时内层循环一次都不进入"""
    a = arr[:]
    for i in range(1, len(a)):
        key = a[i]
        j = i - 1
        # 已有序时 arr[j] <= key 恒成立，内层 while 直接跳过 → Ω(n)
        while j >= 0 and a[j] > key:
            a[j + 1] = a[j]
            j -= 1
        a[j + 1] = key
    return a


# 比较排序下界 Ω(n log n) 的直觉：n 个元素有 n! 种排列，
# 每次比较最多排除一半可能 → 需要 log₂(n!) ≈ n log n 次比较
import math
for n in [5, 10, 20]:
    print(f'n={n}  n!={math.factorial(n)}  log₂(n!)={math.log2(math.factorial(n)):.1f}  '
          f'n log₂n={n * math.log2(n):.1f}')
```

## Θ

Θ（Theta）表示法描述算法的「紧界」：同时存在 c₁、c₂ 和 n₀，当 n ≥ n₀ 时，c₁·g(n) ≤ f(n) ≤ c₂·g(n)，记作 f(n) = Θ(g(n))。它表示算法的时间复杂度「精确地」落在 g(n) 这个量级上，上下界一致，是最「诚实」的记号。

```text
数学定义：
f(n) = Θ(g(n)) ⟺ f(n) = O(g(n)) 且 f(n) = Ω(g(n))

关键理解：
1. Θ 要求上下界一致，所以不是所有算法都有 Θ 记号
2. 归并排序 → Θ(n log n)，最好最坏平均都是 n log n
3. 快速排序 → 平均 O(n log n)、最坏 O(n²)，所以只能说平均 Θ(n log n)

三者关系：
- Big-O 是「上限」，Ω 是「下限」，Θ 是「精确」
- 面试说「这个算法 O(n)」通常心里想的是 Θ(n)，只是习惯用 Big-O 表述
```

```python
def merge_sort(arr):
    """归并排序 → Θ(n log n)，无论输入如何都固定拆半合并"""
    if len(arr) <= 1:
        return arr
    mid = len(arr) // 2
    left = merge_sort(arr[:mid])
    right = merge_sort(arr[mid:])
    return merge(left, right)


def merge(a, b):
    res = []
    i = j = 0
    while i < len(a) and j < len(b):
        if a[i] <= b[j]:
            res.append(a[i]); i += 1
        else:
            res.append(b[j]); j += 1
    res += a[i:] + b[j:]
    return res


# 归并排序时间：T(n) = 2T(n/2) + O(n)，主定理 → Θ(n log n)
print(merge_sort([5, 2, 9, 1, 7, 6]))   # [1, 2, 5, 6, 7, 9]
```

## 摊销分析

摊销分析（Amortized Analysis）考察的是「一系列操作」的总代价：单次操作可能很贵（如扩容、重建），但把它均摊到这一整段操作序列上，平均每次只有 O(1)。它打破了「只看单次最坏情况」的局限，是动态数组、并查集、哈希表扩容等场景的关键工具。

```text
三种分析方法：
1. 聚合分析 —— 算 n 次操作的总代价，再除以 n 得到均摊代价
2. 记账法（会计法）—— 每次廉价操作多存一点「信用」，贵操作时用信用抵消
3. 势能法 —— 定义势能函数 Φ，均摊代价 = 实际代价 + ΔΦ

经典结论：
- 动态数组（Python list append）→ 均摊 O(1)，扩容 O(n) 但很少发生
- 并查集（路径压缩 + 按秩合并）→ 均摊接近 O(α(n))，几乎常数
- 二叉堆插入 → O(log n)，均摊到建堆上整体 O(n)
```

```python
class DynamicArray:
    """动态数组：append 均摊 O(1)"""
    def __init__(self):
        self.cap = 1
        self.size = 0
        self.data = [None] * self.cap

    def append(self, x):
        if self.size == self.cap:      # 满了 → 扩容，代价 O(n)
            self._resize(self.cap * 2)
        self.data[self.size] = x        # 平时代价 O(1)
        self.size += 1

    def _resize(self, new_cap):
        new_data = [None] * new_cap
        for i in range(self.size):
            new_data[i] = self.data[i]
        self.data = new_data
        self.cap = new_cap


# 均摊分析：连续 append n 次，总代价 = n 次 O(1) 写入 + 扩容拷贝
# 扩容发生在 1, 2, 4, 8, ... 共拷贝 1+2+4+...+n/2 < n 次 → 总 O(n)
# 所以均摊每次 append 是 O(1)，尽管单次扩容是 O(n)
arr = DynamicArray()
for i in range(100):
    arr.append(i)
print(f'size={arr.size}, cap={arr.cap}')   # size=100, cap=128
```

## 应用场景实战

### 场景一：判断算法能否在给定数据规模下运行

```python
# 假设单台机器每秒能跑 10^8 次基本操作（约 1 亿次）
OPS_PER_SEC = 10 ** 8

def can_run(n, complexity_exponent, seconds_limit=2):
    """根据 n 和 O(n^k) 估算运行秒数"""
    ops = n ** complexity_exponent
    return ops / OPS_PER_SEC <= seconds_limit

# 数据规模 10^6 时，不同复杂度能否在 2 秒内跑完
n = 10 ** 6
for k, name in [(1, 'O(n)'), (2, 'O(n²)'), (3, 'O(n³)')]:
    ok = can_run(n, k)
    print(f'{name} 在 n={n} 时 {"能" if ok else "不能"}在 2 秒内跑完')

# 结论：n=10^6 时 O(n²)=10^12 次操作远超预算，必须找 O(n) 或 O(n log n) 方案
```

### 场景二：对数级别优化——从 O(n) 到 O(log n)

```python
# 场景：在一个已经排好序的 10^7 规模列表中反复查询元素
import bisect

sorted_list = list(range(10 ** 7))

# 线性查找 O(n)：太慢
def linear_search(arr, x):
    for i, v in enumerate(arr):
        if v == x:
            return i
    return -1

# 二分查找 O(log n)：利用 bisect 模块
def fast_search(arr, x):
    idx = bisect.bisect_left(arr, x)
    return idx if idx < len(arr) and arr[idx] == x else -1

print(fast_search(sorted_list, 9_999_999))   # O(log n)，瞬间返回
# 1000 万数据，线性查找平均 500 万次比较，二分只需约 24 次
```

## 最佳实践与踩坑记录

### 最佳实践

1. 写代码前先估算复杂度，n ≥ 10^6 时基本只能接受 O(n) 或 O(n log n)
2. 说复杂度时明确是「最坏 / 平均 / 均摊」，不要笼统地说 O(n)
3. 空间复杂度用大 O 表示额外空间，别把输入本身占的空间算进去
4. 递归算法复杂度用递归树或主定理算，别凭感觉猜
5. 面试中优先给出紧界 Θ，Big-O 上界往往不够精确
6. 涉及哈希表时默认 O(1) 平均、O(n) 最坏（哈希冲突退化）

### 踩坑记录

```text
坑 1：把 O(n) 当成「一次操作一定 n 次」
结论：Big-O 是上界不是精确值，实际常数可能差几十倍。
原因：O(100n) 和 O(n/100) 都记作 O(n)，但运行时间差 1 万倍。
解法：复杂度用来比较「增长趋势」，微观性能要用 benchmark 实测。

坑 2：忽略空间复杂度导致内存爆炸
结论：O(n²) 空间的 DP 表在 n=10^5 时直接 OOM。
原因：只盯着时间，没算二维数组占 10^10 个元素。
解法：时间空间一起估，能用滚动数组降维就降维。

坑 3：递归忘记算调用栈开销
结论：深度 n 的递归空间是 O(n)，不是 O(1)。
原因：每次递归调用都要在调用栈上分配栈帧。
解法：递归空间 = 递归深度 × 每层空间，必要时改写成迭代。

坑 4：把摊销 O(1) 当单次最坏 O(1) 用
结论：动态数组 append 偶发 O(n)，实时系统可能卡顿。
原因：扩容那一瞬间要拷贝整个数组，单次就是 O(n)。
解法：对延迟敏感的实时场景，预分配容量避免中途扩容。

坑 5：用「测试数据跑得快」代替复杂度分析
结论：小数据下 O(n²) 和 O(n log n) 看不出差别，上生产就崩。
原因：常数小的坏算法在小 n 时反而更快，误导判断。
解法：用大数据规模（10 倍、100 倍）压测，验证增长趋势。
```

## 概述

冷启动指推荐系统面对「没有历史行为数据」的对象（新用户、新内容、新场景）时，无法用协同过滤那套「从历史行为里学」的方法。核心矛盾是：没有数据就没法做个性化，但不做个性化就永远积累不了数据。解法分两类——「先用先验/内容/人口统计兜底」和「用探索策略主动获取反馈」。

```text
冷启动的三类对象：
1. User Cold Start —— 新用户没有历史交互，不知道他喜欢什么
2. Item Cold Start —— 新内容没有交互记录，不知道谁喜欢它
3. Context Cold Start —— 新场景/新品类/新地域缺乏数据

统一思路：
- 用「可迁移的先验」兜底：人口统计、内容属性、知识图谱、跨域迁移
- 用「探索」换取数据：主动曝光新内容，收集反馈后快速纳入模型
```

```python
# 冷启动的通用框架：先验兜底 → 探索曝光 → 反馈回填
def cold_start_flow(new_user, candidates):
    prior_recs = prior_based_recommend(new_user, candidates)  # 1. 先验推荐
    explore_recs = explore_new_items(candidates)              # 2. 探索新内容
    mixed = mix(prior_recs, explore_recs, explore_ratio=0.3)  # 3. 混合
    return mixed
```

## User Cold Start

新用户冷启动：用户刚注册或刚进入，没有点击、购买、收藏等任何行为。解决方案是利用「注册信息、设备、人口统计、社交关系」等零行为特征做初步画像，或引导用户主动表达偏好（选择兴趣标签），再结合热门兜底。

```text
用户冷启动策略：
1. 人口统计 —— 年龄、性别、地域 → 推该群体热门
2. 兴趣问卷 —— 注册时选兴趣标签，直接建立初始画像
3. 设备/来源 —— 手机型号、渠道、落地页 → 推断消费能力/意图
4. 社交导入 —— 通讯录/好友关系 → 好友喜欢什么推什么
5. 全局热门兜底 —— 推最热内容，快速收集第一批行为

评估：新用户前 N 次会话的点击率、留存率、次留
```

```python
def user_cold_start_recommend(new_user, hot_items, group_hot, interests=None):
    """新用户推荐：兴趣标签 > 群体热门 > 全局热门 的优先级兜底"""
    if interests:
        return [it for it in hot_items if it['tag'] in interests][:10]
    if new_user.get('group') in group_hot:
        return group_hot[new_user['group']][:10]
    return hot_items[:10]

hot_items = [{'id': 'i1', 'tag': '游戏'}, {'id': 'i2', 'tag': '美食'},
             {'id': 'i3', 'tag': '游戏'}, {'id': 'i4', 'tag': '旅游'}]
group_hot = {'18-24': [{'id': 'i1', 'tag': '游戏'}, {'id': 'i3', 'tag': '游戏'}]}

new_user = {'age': 20, 'group': '18-24', 'interests': ['游戏']}
print([it['id'] for it in user_cold_start_recommend(new_user, hot_items, group_hot, interests=new_user['interests'])])
# 优先按兴趣标签推 ['i1', 'i3']
```

## Item Cold Start

新内容冷启动：新发布的视频、商品、文章没有交互记录，协同过滤无法给它算相似度，模型也无法学它的 embedding。解决思路是利用「内容本身的属性」做 content-based 推荐，并主动给新内容分配探索流量，让它快速积累第一批反馈。

```text
新内容冷启动策略：
1. 内容属性 —— 标题、标签、封面、类目 → content-based 匹配相似用户
2. 作者先验 —— 用作者的历史表现预估新内容质量
3. 探索流量池 —— 给新内容固定比例的曝光，快速积累反馈
4. 相似内容迁移 —— 用同作者/同类目老内容的 embedding 初始化
5. 时效加权 —— 新内容在排序阶段给 boost（见重排 Freshness）

关键：新内容「第一波流量」的质量决定它能否被验证
```

```python
import numpy as np

def item_cold_start_embedding(new_item, author_emb, category_emb, alpha=0.5):
    """用作者 embedding + 类目 embedding 加权初始化新内容 embedding"""
    return alpha * author_emb + (1 - alpha) * category_emb

# 新内容没有历史，用作者和类目的向量拼一个初始化 embedding
author_emb = np.array([0.3, 0.2, 0.1])
category_emb = np.array([0.1, 0.4, 0.2])
new_emb = item_cold_start_embedding(None, author_emb, category_emb)
print('新内容初始化 embedding:', new_emb)

# 用该 embedding 找最相似的用户/内容
user_embs = np.random.randn(5, 3)
sims = user_embs @ new_emb / (np.linalg.norm(user_embs, axis=1) * np.linalg.norm(new_emb))
print('最相似用户下标:', np.argmax(sims))
```

## Context Cold Start

场景/上下文冷启动：推荐系统进入一个新品类、新地域、新渠道或新业务时，整个上下文都缺乏历史数据。老用户在新场景下也「变新」了。解决思路是「迁移学习」——把相近场景的模型/数据迁移过来，再做小样本微调。

```text
场景冷启动策略：
1. 跨域迁移 —— 从成熟品类迁移 embedding/模型到新品类
2. 预训练 + 微调 —— 用通用模型打底，少量新场景数据微调
3. 规则兜底 —— 前期用人工规则 + 热门，逐步切换到模型
4. 群体借用 —— 相似场景（如「足球」→「篮球」）的用户画像借用

挑战：新场景数据量小、分布不同，直接复用老模型容易水土不服
```

```python
from sklearn.linear_model import LogisticRegression

def context_cold_start_transfer(source_X, source_y, target_X, target_y=None):
    """跨场景迁移：源场景训练，目标场景小样本微调（这里简化为复用）"""
    model = LogisticRegression().fit(source_X, source_y)
    if target_y is not None and len(target_y) > 0:
        # 用少量目标数据继续微调（warm start）
        model = LogisticRegression(warm_start=True).fit(
            np.vstack([source_X, target_X]),
            np.hstack([source_y, target_y]))
    return model

# 源场景（成熟品类）数据充足，目标场景（新品类）数据极少
source_X = np.random.randn(1000, 10)
source_y = (source_X[:, 0] + source_X[:, 1] > 0).astype(int)
target_X = np.random.randn(20, 10)     # 新品类只有 20 条
model = context_cold_start_transfer(source_X, source_y, target_X, None)
print('迁移模型预测目标场景:', model.predict(target_X[:3]))
```

## Exploration

探索（Exploration）指系统主动尝试「不确定」的选项——推荐那些用户可能喜欢但还没被验证过的内容，以获取新的反馈数据。它和利用（Exploitation）是一对永恒的矛盾，冷启动问题的本质就是「探索不足」。

```text
探索的价值与代价：
价值 —— 发现新兴趣、验证新内容、打破「信息茧房」、打破马太效应
代价 —— 短期牺牲确定性收益，可能推用户不喜欢的、损失 CTR

探索策略：
1. ε-greedy —— 以概率 ε 随机探索，其余时间贪心利用
2. UCB —— 给「不确定性大」的选项加分（乐观估计上界）
3. Thompson Sampling —— 按后验分布采样，天然平衡探索与利用
4. 分层探索 —— 只对部分用户/流量做探索，控制整体损失
```

```python
import numpy as np

def epsilon_greedy(arm_values, epsilon=0.1):
    """ε-greedy：以 ε 概率随机探索，否则选当前最优"""
    if np.random.rand() < epsilon:
        return np.random.randint(len(arm_values))
    return int(np.argmax(arm_values))

# 模拟 1000 次决策，观察探索 vs 利用
arm_values = np.array([0.5, 0.4, 0.6])   # 三个内容/策略的当前估值
choices = [epsilon_greedy(arm_values, 0.2) for _ in range(1000)]
print('各选项被选次数:', np.bincount(choices, minlength=3))
# 大约 80% 选最优 arm2，20% 随机探索 arm0/arm1
```

## Exploitation

利用（Exploitation）指系统选择「当前已知最优」的选项，最大化短期收益。它是推荐系统的主体行为——把用户大概率会点的内容推给他。利用的问题在于：它建立在「已有数据」之上，永远无法发现新的、更好的选项，也加剧头部内容的马太效应。

```text
利用的特点：
1. 短期最优 —— 立刻最大化 CTR/GMV
2. 依赖历史 —— 只相信已经验证过的东西
3. 有天花板 —— 不探索就找不到更优解，陷入局部最优

与探索的关系：
- 纯利用 → 头部固化、新内容永远没机会、用户兴趣被锁死
- 纯探索 → 短期收益崩盘，用户体验差
- 平衡点 —— 用 Bandit 类算法动态调节，冷启动期多探索、成熟期多利用
```

```python
def greedy_exploit(arm_values):
    """纯利用：永远选当前估值最高的选项"""
    return int(np.argmax(arm_values))

# 演示纯利用的陷阱：如果 arm 估值一开始就不准，会一直选错
arm_values_wrong = np.array([0.9, 0.1, 0.2])   # 初始估值偏差很大
# 真实收益其实 arm1 最高，但系统永远选 arm0，永远发现不了
choices = [greedy_exploit(arm_values_wrong) for _ in range(100)]
print('纯利用选择分布:', np.bincount(choices, minlength=3))
# 结果 100% 选 arm0，即使它是错的，也没有机会纠正
```

## Bandit

Bandit（多臂老虎机）是解决「探索-利用权衡」的一类在线决策算法：每个「臂」代表一个待推荐的 item/策略，系统每次决策要平衡「选已知最优」（利用）和「试不确定的」（探索），在一次次反馈中逐步逼近最优。冷启动本质就是 Bandit 问题。

```text
经典 Bandit 算法：
1. ε-greedy —— 固定概率随机探索，最简单
2. UCB —— 每个臂的得分 = 均值 + 置信上界，天然探索不确定性大的臂
3. Thompson Sampling —— 每个臂维护一个 Beta 后验，按后验采样决策
4. LinUCB / Contextual Bandit —— 引入上下文特征，做个性化探索

UCB 公式：
score(a) = μ̂(a) + sqrt( 2·ln(t) / n(a) )
- μ̂(a)：臂 a 的历史平均收益
- n(a)：臂 a 被选次数，n 越小探索项越大
```

```python
import numpy as np

class UCB1:
    def __init__(self, n_arms):
        self.n_arms = n_arms
        self.counts = np.zeros(n_arms)        # 每个臂被选次数
        self.values = np.zeros(n_arms)        # 每个臂的平均收益
        self.t = 0

    def select(self):
        self.t += 1
        # 未选过的臂优先探索
        for a in range(self.n_arms):
            if self.counts[a] == 0:
                return a
        ucb = self.values + np.sqrt(2 * np.log(self.t) / self.counts)
        return int(np.argmax(ucb))

    def update(self, arm, reward):
        self.counts[arm] += 1
        n = self.counts[arm]
        self.values[arm] += (reward - self.values[arm]) / n   # 增量均值

# 三个臂真实点击率不同，UCB 应逐渐收敛到最优臂
true_ctr = [0.1, 0.3, 0.5]
bandit = UCB1(3)
for _ in range(3000):
    arm = bandit.select()
    reward = 1 if np.random.rand() < true_ctr[arm] else 0
    bandit.update(arm, reward)
print('各臂被选次数:', bandit.counts.astype(int))
print('各臂估计 CTR:', np.round(bandit.values, 3))
# 最优臂（第三个）被选次数最多，估计值逼近真实 0.5
```

```python
# Thompson Sampling：Beta 后验采样
class ThompsonSampling:
    def __init__(self, n_arms):
        self.n_arms = n_arms
        self.success = np.ones(n_arms)        # Beta(1,1) 先验
        self.failure = np.ones(n_arms)

    def select(self):
        samples = np.random.beta(self.success, self.failure)
        return int(np.argmax(samples))

    def update(self, arm, reward):
        self.success[arm] += reward
        self.failure[arm] += 1 - reward

ts = ThompsonSampling(3)
for _ in range(3000):
    arm = ts.select()
    reward = 1 if np.random.rand() < true_ctr[arm] else 0
    ts.update(arm, reward)
print('TS 各臂估计 CTR:', np.round(ts.success / (ts.success + ts.failure), 3))
```

## 应用场景实战

### 场景一：新用户首屏推荐（兴趣问卷 + 热门兜底 + Bandit 探索）

```python
def new_user_first_screen(new_user, interests, hot_items, explore_ratio=0.3):
    """新用户首屏：兴趣匹配为主，混入一定比例探索内容"""
    matched = [it for it in hot_items if it['tag'] in interests]
    others = [it for it in hot_items if it['tag'] not in interests]
    n_explore = max(1, int(len(matched) * explore_ratio))
    result = matched + others[:n_explore]
    return result[:10]

interests = ['游戏']
hot_items = [
    {'id': 'g1', 'tag': '游戏'}, {'id': 'g2', 'tag': '游戏'},
    {'id': 'g3', 'tag': '游戏'}, {'id': 'm1', 'tag': '美食'},
    {'id': 't1', 'tag': '旅游'}, {'id': 's1', 'tag': '体育'},
]
screen = new_user_first_screen({}, interests, hot_items, explore_ratio=0.3)
print([it['id'] for it in screen])
# 输出以游戏为主，混入 1 个探索内容（美食/旅游/体育之一）
```

### 场景二：新内容冷启动的探索流量分配

```python
def new_item_explore_flow(new_items, quality_scores, total_traffic=1000):
    """按质量先验给新内容分配探索流量，快速积累反馈"""
    # 质量先验：作者历史表现/内容属性打分，决定初始曝光量
    weights = np.array(quality_scores) / sum(quality_scores)
    allocated = (weights * total_traffic).astype(int)
    return dict(zip(new_items, allocated))

new_items = ['n1', 'n2', 'n3']
quality = [0.5, 0.3, 0.2]      # 作者历史表现越好，初始流量越多
print(new_item_explore_flow(new_items, quality, total_traffic=1000))
# {'n1': 500, 'n2': 300, 'n3': 200} → 质量先验决定初始探索量
```

## 最佳实践与踩坑记录

### 最佳实践

1. 新用户冷启动优先「兴趣问卷 + 群体热门」，比裸推全局热门收敛快得多
2. 新内容冷启动用「作者先验 + 类目 embedding 初始化」，别从零向量开始
3. 探索流量要「分级控制」：低质新内容少探索、高质新内容多探索，避免浪费
4. Bandit 用 UCB/Thompson Sampling 替代固定 ε-greedy，能更快收敛到最优臂
5. 冷启动是阶段性问题：用户/内容一旦积累足够反馈，就应切换到正常模型
6. 跨场景冷启动优先迁移学习，别在新场景从零训练

### 踩坑记录

```text
坑 1：新用户只推全局热门
结论：新用户首屏全是爆款，但没有个性化，留存率低。
原因：全局热门无法区分个体差异，浪费了宝贵的首屏机会。
解法：注册时引导选兴趣标签，或按人口统计分群体推「群体热门」。

坑 2：新内容零曝光，永远冷启动
结论：新内容没有探索流量，一直积累不了反馈，形成死循环。
原因：排序阶段只按历史 CTR，新内容没有分数永远排不上。
解法：给新内容固定比例的探索流量 + 时效 boost，强制进入候选。

坑 3：ε-greedy 的 ε 设太大或太小
结论：ε 太大浪费曝光、CTR 崩盘；ε 太小探索不足、新内容没机会。
原因：固定 ε 不随学习进程调整，成熟期还在一味探索。
解法：用 UCB/Thompson Sampling 动态平衡，或让 ε 随时间衰减。

坑 4：探索内容质量无门槛
结论：给低质新内容大量探索流量，用户被劣质内容赶跑。
原因：只奖励「新」，不奖励「好」，探索流量被垃圾内容污染。
解法：探索流量按质量先验分配，低质内容限流或延迟曝光。

坑 5：跨场景直接复用老模型
结论：老品类模型搬到新品类，预测全乱、指标崩盘。
原因：新场景数据分布不同，老模型没有迁移适配。
解法：预训练 + 微调，或先用规则兜底，边积累边训练。
```

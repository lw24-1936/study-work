## 概述

经典召回是推荐系统里第一批、也仍然最广泛使用的召回方法：它们不依赖深度学习，靠统计、相似度、共现和图结构，用轻量计算从海量物品里捞出候选。它们计算快、可解释、易落地，是任何推荐系统的召回基座，也是理解「协同过滤」这一推荐思想的最佳入口。

```text
经典召回的核心认知：
1. 物以类聚、人以群分 —— 协同过滤的两条腿：找相似用户（UserCF）与找相似物品（ItemCF）
2. 召回求全不求准 —— 目标是高召回率，允许牺牲一部分准确率
3. 可解释 —— 热门、共现、关联规则都能说出「为什么推荐」
4. 工程友好 —— 倒排索引 + 缓存即可服务，毫秒级返回
```

```python
# 经典召回的统一接口：输入用户，输出候选物品列表
def recall(user_id, method="itemcf"):
    if method == "hot":
        return popularity_recall(top_n=100)
    elif method == "usercf":
        return user_cf_recall(user_id)
    elif method == "itemcf":
        return item_cf_recall(user_id)
    return []

print(recall("u_1", method="itemcf"))
```

## Popularity

Popularity（热门召回）直接推荐全局最热门的物品，是「最朴素但永远有用」的兜底召回。它不需要任何用户历史，天然解决冷启动，也常作为新用户、新物品、异常降级时的保底通道。

```text
热门召回的关键点：
1. 统计口径 —— 点击量、销量、播放量，通常取近 N 天窗口抑制过时热度
2. 时间衰减 —— 用指数/牛顿冷却给热度降温，避免马太效应固化
3. 兜底价值 —— 无历史、模型失败、新流量时的保底
4. 可做分层 —— 按类目/地域/时段的热门，比全局热门更准
```

```python
import heapq
from collections import defaultdict

# 基于点击数 + 时间衰减的热门计算
def hot_score(clicks, ts, now, half_life=86400 * 7):
    return clicks / (1 + (now - ts) / half_life)   # 牛顿冷却式衰减

item_clicks = {"i_1": (10000, 1000), "i_2": (5000, 9000), "i_3": (8000, 5000)}
now = 10000
scores = {it: hot_score(c, t, now) for it, (c, t) in item_clicks.items()}
top = heapq.nlargest(2, scores.items(), key=lambda kv: kv[1])
print("热门:", [it for it, _ in top])
```

## UserCF

UserCF（基于用户的协同过滤）先找到与目标用户「口味相似」的一群用户，再把这些用户喜欢而目标用户没接触过的物品推荐给他。它适合用户数远小于物品数、且用户兴趣变化快的场景。

```text
UserCF 三步走：
1. 算相似度 —— 用共同评分/共同交互，算用户之间的余弦或 Jaccard 相似度
2. 找近邻 —— 取相似度最高的 K 个用户
3. 聚合推荐 —— 把这些近邻喜欢、目标用户没见过的物品按相似度加权打分
```

```python
import numpy as np
from collections import defaultdict

# 用户-物品交互矩阵（1 表示喜欢/点击）
R = {
    "u1": {"a": 1, "b": 1, "c": 1},
    "u2": {"a": 1, "b": 1, "d": 1},
    "u3": {"c": 1, "d": 1, "e": 1},
}

def cosine(u, v):
    items = set(R[u]) & set(R[v])
    if not items:
        return 0.0
    uv = np.array([R[u][i] for i in items])
    vv = np.array([R[v][i] for i in items])
    return float(uv @ vv / (np.linalg.norm(uv) * np.linalg.norm(vv) + 1e-9))

def user_cf(target, k=2):
    sims = {u: cosine(target, u) for u in R if u != target}
    neighbors = sorted(sims, key=sims.get, reverse=True)[:k]
    scores = defaultdict(float)
    for nb in neighbors:
        for item, r in R[nb].items():
            if item not in R[target]:
                scores[item] += sims[nb] * r
    return sorted(scores, key=scores.get, reverse=True)

print(user_cf("u1"))
# ['d', 'e'] —— u2、u3 喜欢但 u1 没接触过的物品
```

## ItemCF

ItemCF（基于物品的协同过滤）计算物品之间的相似度，把「和目标用户历史喜欢的物品相似」的物品推荐给他。它是电商场景的绝对主力：物品数相对稳定、可离线预计算相似度矩阵，线上只需查表，性能与可解释性俱佳。

```text
ItemCF 与 UserCF 的区别：
1. 相似度对象 —— ItemCF 算物品-物品相似，UserCF 算用户-用户相似
2. 计算时机 —— ItemCF 相似度矩阵可离线算好，UserCF 需在线找近邻
3. 适用场景 —— 物品数少、用户数多选 ItemCF；反之选 UserCF
4. 可解释性 —— ItemCF 可解释为「因为你看了 A，所以推荐 B」
```

```python
from collections import defaultdict
import math

# 用户-物品交互：users[user] = {item}
users = {
    "u1": {"a", "b", "c"},
    "u2": {"a", "b", "d"},
    "u3": {"c", "d", "e"},
}

def item_sim_matrix(users):
    # 统计同时喜欢两个物品的用户数，用余弦相似度
    item_users = defaultdict(set)
    for u, items in users.items():
        for i in items:
            item_users[i].add(u)
    sim = defaultdict(dict)
    items = list(item_users)
    for i in items:
        for j in items:
            if i == j:
                continue
            inter = len(item_users[i] & item_users[j])
            if inter:
                sim[i][j] = inter / math.sqrt(len(item_users[i]) * len(item_users[j]))
    return sim

def item_cf(target, sim, users):
    scores = defaultdict(float)
    for liked in users[target]:
        for j, s in sim.get(liked, {}).items():
            if j not in users[target]:
                scores[j] += s
    return sorted(scores, key=scores.get, reverse=True)

sim = item_sim_matrix(users)
print(item_cf("u1", sim, users))
# ['d', 'e'] —— 与 u1 喜欢的 a/b/c 相似度最高的物品
```

## Content-Based

Content-Based（基于内容的召回）直接用物品的内容特征（标题、标签、关键词、embedding）与用户历史偏好做匹配，不依赖其他用户的行为。它的好处是没有冷启动问题、不依赖交互数据，缺点是只能推荐「和你过去喜欢的东西相似」的内容，容易信息茧房。

```text
基于内容召回的关键点：
1. 特征表达 —— 物品的 tag/关键词/embedding（TF-IDF、Word2Vec、BERT）
2. 用户偏好 —— 把用户历史喜欢的物品特征聚合成一个偏好向量
3. 相似匹配 —— 偏好向量与候选物品向量算余弦，或用倒排索引查 tag
4. 局限性 —— 难挖掘潜在新兴趣，内容特征质量决定上限
```

```python
import numpy as np
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.metrics.pairwise import cosine_similarity

# 物品内容描述
docs = {
    "i_1": "智能手机 5G 拍照 高刷屏",
    "i_2": "智能手机 折叠屏 旗舰芯片",
    "i_3": "科幻小说 人工智能 太空",
    "i_4": "篮球鞋 缓震 实战 运动",
}
items = list(docs)
vec = TfidfVectorizer()
X = vec.fit_transform(docs.values())

# 用户历史喜欢 i_1，聚合出偏好向量，找最相似的其他物品
user_liked = ["i_1"]
pref = X[items.index(user_liked[0])]
sims = cosine_similarity(pref, X).ravel()
ranked = sorted(range(len(items)), key=lambda k: sims[k], reverse=True)
print([items[k] for k in ranked if items[k] not in user_liked])
# ['i_2', 'i_3', 'i_4'] —— 同为手机内容的 i_2 排最前
```

## Co-Occurrence

Co-Occurrence（共现召回）统计「物品 A 和物品 B 经常一起出现在同一用户行为序列/购物篮里」的频率，用共现强度作为物品相关性，是「买了又买」「看了又看」这类推荐的技术内核。

```text
共现召回的关键点：
1. 共现计数 —— 在同一会话/购物车/历史里同时出现的次数
2. 归一化 —— 用 Jaccard、点互信息（PMI）、余弦消除热门物品的共现虚高
3. 序列变体 —— 可加顺序（先看 A 后看 B），捕捉「看了又看」
4. 高效落地 —— 离线算好共现表，线上按用户历史查表合并
```

```python
from collections import defaultdict
from itertools import combinations

# 会话序列：每个会话内出现的物品
sessions = [
    ["a", "b", "c"],
    ["a", "b", "d"],
    ["b", "c", "d"],
    ["a", "c"],
]

def co_occurrence(sessions):
    pair_count = defaultdict(int)
    item_count = defaultdict(int)
    for sess in sessions:
        for i in set(sess):
            item_count[i] += 1
        for x, y in combinations(set(sess), 2):
            pair_count[(x, y)] += 1
            pair_count[(y, x)] += 1
    # 用 Jaccard 归一化
    jaccard = {}
    for (x, y), cnt in pair_count.items():
        jaccard[(x, y)] = cnt / (item_count[x] + item_count[y] - cnt)
    return jaccard

co = co_occurrence(sessions)
print("共现(a,b) Jaccard:", round(co[("a", "b")], 3))
```

## Association Rules

Association Rules（关联规则）在共现统计的基础上，用「支持度、置信度、提升度」三个指标挖掘「买了 A 就会买 B」的强规则。它是购物篮分析（Apriori、FP-Growth）的经典产物，常用于「猜你喜欢」和捆绑销售。

```text
关联规则三指标：
1. 支持度 support —— P(A∩B)，规则覆盖了多少交易
2. 置信度 confidence —— P(B|A)，买了 A 的人里买 B 的比例
3. 提升度 lift —— P(B|A)/P(B)，>1 表示正相关，=1 表示独立
```

```python
from collections import defaultdict
from itertools import combinations

transactions = [
    {"a", "b", "c"}, {"a", "b"}, {"b", "c", "d"}, {"a", "c"}, {"b", "d"},
]
n = len(transactions)

def support(itemset):
    return sum(1 for t in transactions if itemset <= t) / n

# 规则 A -> B 的三指标
def rule_metrics(A, B):
    AB = support(A | B)
    sup_A = support(A)
    sup_B = support(B)
    conf = AB / sup_A if sup_A else 0
    lift = conf / sup_B if sup_B else 0
    return AB, conf, lift

sup, conf, lift = rule_metrics({"a"}, {"b"})
print(f"a->b: support={sup:.2f}, confidence={conf:.2f}, lift={lift:.2f}")
```

## Graph Recall

Graph Recall（图召回）把用户和物品看成二部图（或同构图）上的节点，交互是边，用图上的随机游走（PersonalRank、PageRank）或图嵌入（DeepWalk、Node2Vec）来度量节点之间的相关性，捕捉多跳传递的兴趣。

```text
图召回的关键点：
1. 二部图建模 —— 用户节点、物品节点，交互作为边
2. 随机游走 —— 从目标用户出发游走，访问概率高的物品作为候选（PersonalRank）
3. 图嵌入 —— 把节点映射为向量，再用向量相似度召回
4. 多跳能力 —— 能捕捉「你的朋友的朋友喜欢」这种协同过滤单跳抓不到的关系
```

```python
from collections import defaultdict

# PersonalRank 的简化版：多轮随机游走估计物品得分
edges = defaultdict(list)
# 用户 u* 与物品 i* 之间的交互边
for u, items in {"u1": ["a", "b"], "u2": ["a", "c"], "u3": ["b", "c", "d"]}.items():
    for i in items:
        edges[u].append(i)
        edges[i].append(u)

def personal_rank(target, alpha=0.6, steps=1000):
    score = defaultdict(float)
    score[target] = 1.0
    for _ in range(steps):
        nxt = defaultdict(float)
        for node, p in list(score.items()):
            nbs = edges[node]
            if not nbs:
                continue
            for nb in nbs:
                nxt[nb] += p / len(nbs)
        for node in nxt:
            nxt[node] = alpha * nxt[node]
        nxt[target] += (1 - alpha)          # 每步以 (1-alpha) 概率跳回起点
        score = nxt
    return score

scores = personal_rank("u1")
items = [it for it in scores if not it.startswith("u")]
print(sorted(items, key=scores.get, reverse=True))
```

## 应用场景实战

### 场景一：电商「猜你喜欢」多路召回融合

```python
from collections import defaultdict

def merge_channels(user_id):
    # 多路召回结果带通道权重，合并去重并累加
    channels = [
        ("item_cf", {"i_1": 2.0, "i_2": 1.5}),
        ("hot",     {"i_3": 1.0, "i_2": 0.8}),
        ("co_occ",  {"i_1": 1.2, "i_4": 0.9}),
    ]
    merged = defaultdict(float)
    for _, items in channels:
        for it, s in items.items():
            merged[it] += s
    return sorted(merged.items(), key=lambda kv: kv[1], reverse=True)

print("融合后的候选:", merge_channels("u_1"))
# 多路命中同一物品会得到更高权重（i_1 被 item_cf 和 co_occ 同时命中）
```

### 场景二：新闻资讯的内容召回 + 热度兜底

```text
新闻资讯推荐的通路设计：
1. 主通道：基于内容的内容召回（标题/正文 embedding 与用户兴趣向量匹配），保证个性化
2. 补充通道：协同过滤（同阅读人群也读了）挖掘潜在兴趣
3. 时效通道：新发布的新闻按热度快速进入候选，保证时效性
4. 兜底通道：全局热门，新用户、异常降级时保底
```

## 最佳实践与踩坑记录

### 最佳实践

1. 永远保留一条热门通道做兜底，新用户、异常、降级时都有内容可推
2. ItemCF 的相似度矩阵离线预计算 + 定时更新，线上只做查表，性能最优
3. 共现统计要按会话切分，跨会话的「碰巧同时出现」会污染相关性
4. 热门/共现都做时间衰减，避免过时内容霸榜、马太效应固化
5. 多路召回合并时记录通道来源，便于后续分析与权重调优
6. 关联规则用提升度过滤，只看置信度会被高频物品的「假强规则」欺骗

### 踩坑记录

```text
坑 1：热门物品污染了所有共现/相似度
结论：任何物品都「相似于」超级热门物品，推荐结果千篇一律。
原因：热门物品与几乎所有物品都共现，余弦/Jaccard 归一化不足时会虚高。
解法：用提升度、PMI 等指标消除流行度偏差，或对热门物品做降权。

坑 2：ItemCF 相似度矩阵不更新
结论：新物品永远得不到推荐，下架物品还继续被推。
原因：相似度矩阵离线算好后长期不刷新，物品库变化没同步进去。
解法：相似度矩阵按天/按小时增量更新，配合物品上下线状态过滤。

坑 3：跨会话统计共现
结论：把「早上买的牛奶」和「晚上买的键盘」算成强相关。
原因：共现窗口跨了不同购物意图，把不相关行为误判为一起出现。
解法：严格按单次会话/单次购物篮切分，会话超时（如 30 分钟）即断开。

坑 4：只看置信度挖关联规则
结论：推出「买纸尿裤的人 80% 也买矿泉水」这类无意义规则。
原因：矿泉水本身高频，置信度高只是因为 base 率高，提升度可能接近 1。
解法：同时看支持度（覆盖够大）和提升度（真正正相关），阈值如 lift > 1.5。

坑 5：内容召回只用物品标签，忽略用户偏好聚合
结论：推荐退化成「同类目刷屏」，缺乏多样性。
原因：用户偏好只用最近一个物品的标签，没有聚合历史，也没有引入探索。
解法：聚合用户历史物品特征得到偏好向量，并加入随机探索与多样性约束。
```

## 概述

推荐评估回答「这套推荐系统到底好不好」。它分两个层面：离线评估用历史数据算一堆指标（CTR、Recall@K、NDCG@K 等）快速迭代，在线评估用 A/B Test 直接观测真实业务指标。两个层面缺一不可——离线好不代表线上好，线上涨了也要能归因到具体模型。

```text
推荐评估指标的分类：
1. 行为指标 —— CTR（点击率）、CVR（转化率），直接对应商业价值
2. 排序质量 —— Recall@K、Precision@K、NDCG@K、MAP@K、MRR，衡量排序/召回的准确度
3. 生态指标 —— Coverage、Diversity、Novelty，衡量内容生态健康度
4. 概率质量 —— Calibration，衡量预测概率是否可信
5. 因果验证 —— A/B Test，衡量策略变更的真实因果效应
```

```python
# 离线评估的统一输入约定
# user 真实点击/交互的 item 集合作为 ground truth
import numpy as np
ground_truth = {
    'u1': {'i1', 'i3', 'i7'},
    'u2': {'i2', 'i5'},
    'u3': {'i4', 'i6', 'i9'},
}
# 模型为每个用户推荐的 top-K 有序列表
rec_list = {
    'u1': ['i1', 'i2', 'i3', 'i8', 'i9'],
    'u2': ['i5', 'i1', 'i3', 'i2', 'i4'],
    'u3': ['i4', 'i9', 'i6', 'i1', 'i2'],
}
K = 5
```

## CTR

CTR（Click-Through Rate，点击率）是推荐/广告系统最核心的业务指标：曝光中被点击的比例。它直接反映「推荐的内容用户想不想点」，是最容易观测、对业务价值最敏感的指标之一。

```text
CTR = 点击次数 / 曝光次数

要点：
1. 受曝光位置影响大 —— 首位天然高点击，需按位置分层看
2. 受内容品类影响 —— 不同类目 CTR 基线差异巨大
3. 有天花板 —— 一味追 CTR 容易陷入「标题党」局部最优
```

```python
def ctr(clicks, impressions):
    """clicks: 点击数，impressions: 曝光数"""
    return clicks / impressions if impressions else 0.0

# 两组策略对比
clicks_a, imp_a = 8000, 100000
clicks_b, imp_b = 8500, 100000
print(f'策略A CTR = {ctr(clicks_a, imp_a):.4f}')
print(f'策略B CTR = {ctr(clicks_b, imp_b):.4f}')
print(f'提升幅度 = {(ctr(clicks_b, imp_b) - ctr(clicks_a, imp_a)) / ctr(clicks_a, imp_a):.2%}')
```

## CVR

CVR（Conversion Rate，转化率）衡量「点击之后」的进一步转化——下单、注册、付费等。它比 CTR 更接近最终商业价值，但样本量更小、噪声更大，且受「点击到转化」链路中每一步的影响。

```text
CVR = 转化次数 / 点击次数

要点：
1. 比 CTR 更深层 —— 反映内容「点进来之后是否真的有用」
2. 样本稀疏 —— 转化远少于点击，指标方差大、波动明显
3. 链路分解 —— 电商常拆成 CVR = 加购率 × 下单率 × 支付率
```

```python
def cvr(conversions, clicks):
    return conversions / clicks if clicks else 0.0

# 电商场景：点击 → 加购 → 下单 → 支付 的漏斗
clicks = 10000
add_cart, orders, paid = 2000, 500, 480
print(f'加购率 = {cvr(add_cart, clicks):.3f}')
print(f'下单率 = {cvr(orders, add_cart):.3f}')
print(f'支付率 = {cvr(paid, orders):.3f}')
print(f'整体 CVR = {cvr(paid, clicks):.4f}')
```

## Recall@K

Recall@K 衡量「用户真正感兴趣的所有 item 里，推荐列表覆盖了多少」。它关心「漏没漏」，适合召回阶段评估——召回宁可多召回也不能漏掉用户喜欢的。

```text
Recall@K = |推荐列表 ∩ 真实相关| / |真实相关|

要点：
1. 分母是用户全部相关 item，强调覆盖
2. K 越大 Recall 越高，但越大越接近「把全库都推一遍」
3. 与 Precision@K 此消彼长，需联合看
```

```python
def recall_at_k(rec, truth, k):
    rec_k = set(rec[:k])
    return len(rec_k & truth) / len(truth) if truth else 0.0

# 逐用户计算再平均
recalls = [recall_at_k(rec_list[u], ground_truth[u], K) for u in ground_truth]
print(f'Recall@{K} = {np.mean(recalls):.3f}')
# u1: {i1,i3}∩{i1,i3,i7}=2/3, u2: {i5,i2}∩{i2,i5}=2/2=1, u3: {i4,i9,i6}=3/3=1
```

## Precision@K

Precision@K 衡量「推荐列表里有多少是用户真正感兴趣的」。它关心「准不准」，用户看的是列表前几位，所以 Precision@K 更能反映用户的直接体感。

```text
Precision@K = |推荐列表 ∩ 真实相关| / K

要点：
1. 分母固定为 K，强调推荐列表的「纯净度」
2. K 越小越重要 —— 用户只认真看前几个
3. 对 K 敏感，业务上常看 Precision@1/@5/@10
```

```python
def precision_at_k(rec, truth, k):
    rec_k = set(rec[:k])
    return len(rec_k & truth) / k if k else 0.0

precisions = [precision_at_k(rec_list[u], ground_truth[u], K) for u in ground_truth]
print(f'Precision@{K} = {np.mean(precisions):.3f}')
# u1: 2/5, u2: 2/5, u3: 3/5
```

## NDCG@K

NDCG（Normalized Discounted Cumulative Gain）是「位置敏感」的排序指标：越靠前的相关 item 贡献越高，且用理想排序做归一化。它同时兼顾「相关不相关」和「排序对不对」，是排序质量最常用的综合指标。

```text
DCG@K = Σ_{i=1..K} (2^rel_i - 1) / log₂(i+1)
NDCG@K = DCG@K / IDCG@K

要点：
1. 位置折损 —— 用 log₂(i+1) 折扣，越靠后贡献越小
2. 分级相关 —— rel_i 可以是 0/1，也可以是 0~4 的多级相关
3. IDCG 是理想排序的 DCG，保证 NDCG ∈ [0, 1]
```

```python
import math

def dcg_at_k(rels, k):
    return sum((2 ** r - 1) / math.log2(i + 2) for i, r in enumerate(rels[:k]))

def ndcg_at_k(rec, truth_rel, k):
    """truth_rel: {item: 相关等级(0~4)}"""
    rels = [truth_rel.get(it, 0) for it in rec[:k]]
    idcg = dcg_at_k(sorted(truth_rel.values(), reverse=True), k)
    return dcg_at_k(rels, k) / idcg if idcg else 0.0

truth_rel = {'u1': {'i1': 3, 'i3': 2, 'i7': 1},
             'u2': {'i2': 2, 'i5': 3},
             'u3': {'i4': 3, 'i6': 1, 'i9': 2}}
ndcgs = [ndcg_at_k(rec_list[u], truth_rel[u], K) for u in truth_rel]
print(f'NDCG@{K} = {np.mean(ndcgs):.3f}')
```

## MAP@K

MAP（Mean Average Precision）先对每个用户算「各召回位置的 Precision 平均值」（AP），再对所有用户求平均。它比 Precision@K 更全面，考虑了相关 item 在列表中的整体分布，而不是只看前 K 个。

```text
AP@K = (1/|相关|) Σ_{i=1..K} P(i) · rel(i)
MAP@K = mean over users of AP@K

要点：
1. 只在「命中相关 item」的位置累加 Precision，越早命中越好
2. 对相关 item 数量少的数据更稳健
3. 是二值相关场景的常用排序指标
```

```python
def ap_at_k(rec, truth, k):
    hits, score, num_hits = 0, 0.0, 0
    for i, it in enumerate(rec[:k]):
        if it in truth:
            num_hits += 1
            score += num_hits / (i + 1)      # 该位置的 precision
    return score / len(truth) if truth else 0.0

aps = [ap_at_k(rec_list[u], ground_truth[u], K) for u in ground_truth]
print(f'MAP@{K} = {np.mean(aps):.3f}')
```

## MRR

MRR（Mean Reciprocal Rank）只关心「第一个相关 item 出现在第几位」，取这个位置的倒数再对用户平均。它适合「用户只看第一个正确答案」的场景（问答、搜索、导航），简单且对「首个命中位置」极其敏感。

```text
MRR = mean over users of (1 / rank_first_relevant)

要点：
1. 只看首个命中位置，忽略其后的一切
2. 首个命中越靠前，MRR 越接近 1
3. 适合「一锤定音」场景，不适合需要多个相关结果的场景
```

```python
def reciprocal_rank(rec, truth):
    for i, it in enumerate(rec):
        if it in truth:
            return 1.0 / (i + 1)
    return 0.0

mrr = np.mean([reciprocal_rank(rec_list[u], ground_truth[u]) for u in ground_truth])
print(f'MRR = {mrr:.3f}')
# u1 首命中位置 1 → 1.0, u2 位置 1 → 1.0, u3 位置 1 → 1.0
```

## Coverage

Coverage（覆盖率）衡量推荐系统「是否把所有 item 都激活了」——被推荐过的 item 占全库的比例。覆盖率过低说明系统只盯着少数头部内容，长尾内容没有曝光机会，不利于生态和冷启动。

```text
Coverage = |被推荐过的不同 item| / |全库 item 总数|

要点：
1. 关注长尾 —— 只推头部内容时 Coverage 极低
2. 与 Recall 互补 —— Recall 看用户维度，Coverage 看 item 维度
3. 可延伸到「类目覆盖率」「作者覆盖率」
```

```python
def coverage(rec_lists, catalog_size):
    """rec_lists: 所有用户的推荐列表（list of list）"""
    seen = set(it for rec in rec_lists for it in rec)
    return len(seen) / catalog_size if catalog_size else 0.0

# 全库 1000 个 item，每个用户推荐 5 个（K=5）
recs = [rec_list[u] for u in rec_list]
print(f'Coverage = {coverage(recs, catalog_size=1000):.4f}')
# 被推荐的不同 item 只有 {i1,i2,i3,i4,i5,i6,i8,i9} = 8 个（i7 未被任何列表推荐）
```

## Diversity

Diversity（多样性）衡量推荐列表内部条目之间的差异程度。列表里全是同类内容，用户容易疲劳；多样性高的列表能覆盖用户更多潜在兴趣。常用两两相似度的补数来度量。

```text
Diversity = 1 - (列表内两两条目相似度的均值)

要点：
1. 与「准确性」有张力 —— 多样性提升常伴随短期 CTR 下降
2. 常用类目/标签/embedding 相似度计算
3. 在线下常配合 AB 实验看「多样性 vs 留存」的长期权衡
```

```python
def intra_list_diversity(rec, item_vec):
    """用 embedding 余弦相似度度量列表内多样性"""
    import numpy as np
    vecs = np.array([item_vec[it] for it in rec])
    vecs = vecs / (np.linalg.norm(vecs, axis=1, keepdims=True) + 1e-9)
    sim = vecs @ vecs.T
    n = len(rec)
    # 去掉对角线，求两两相似度均值
    mean_sim = (sim.sum() - n) / (n * (n - 1)) if n > 1 else 0.0
    return 1 - mean_sim

item_vec = {f'i{j}': np.random.randn(8) for j in range(10)}
for it in item_vec:                                  # 让 i1,i2,i3 相似
    item_vec[it] = item_vec[it] / (np.linalg.norm(item_vec[it]) + 1e-9)
print(f'列表多样性 = {intra_list_diversity(rec_list["u1"], item_vec):.3f}')
```

## Novelty

Novelty（新颖性）衡量推荐结果中「冷门/用户没见过的」内容占比。热门内容人人都推，用户新鲜感下降；新颖性指标推动系统挖掘长尾，提升长期体验。常用条目的全局流行度倒数或 -log(pop) 来度量。

```text
Novelty(list) = (1/|list|) Σ -log₂( pop(i) / N )

要点：
1. 与热门度负相关 —— 越冷门越「新颖」
2. 新颖 ≠ 质量差 —— 需与质量门槛配合，避免推劣质长尾
3. 常与 Coverage、Diversity 一起构成「生态健康度」指标族
```

```python
import math

def novelty(rec, popularity):
    """popularity: {item: 全局交互次数}"""
    N = sum(popularity.values())
    vals = [-math.log2(popularity.get(it, 1) / N) for it in rec]
    return sum(vals) / len(vals) if vals else 0.0

popularity = {'i1': 1000, 'i2': 900, 'i3': 800, 'i4': 30, 'i5': 20,
              'i6': 10, 'i7': 500, 'i8': 5, 'i9': 3}
print(f'u1 列表新颖度 = {novelty(rec_list["u1"], popularity):.2f}')
print(f'u2 列表新颖度 = {novelty(rec_list["u2"], popularity):.2f}')
```

## Calibration

Calibration（校准）衡量「模型预测的概率是否真实」——预测 0.8 点击率的 item，实际点击率是不是真的接近 0.8。校准好的模型，概率可以直接当置信度用；校准差的模型，排序可能还行但概率不可信。

```text
校准度量：
1. Reliability Diagram —— 按预测概率分桶，画「预测 vs 实际」曲线
2. Expected Calibration Error (ECE) —— 各桶 |预测均值 - 实际均值| 的加权和
3. Brier Score —— 均方概率误差，越小越校准

要点：
- 排序模型常对校准不敏感（只比大小），但涉及阈值/出价/风险时校准很关键
- 样本不平衡、正则化、温度缩放都会影响校准
```

```python
import numpy as np

def expected_calibration_error(probs, labels, n_bins=10):
    """ECE：预测概率与实际标签频率的分桶偏差加权和"""
    bins = np.linspace(0, 1, n_bins + 1)
    ece, bin_ids = 0.0, np.digitize(probs, bins[1:-1])
    for b in range(n_bins):
        mask = bin_ids == b
        if mask.sum() == 0:
            continue
        ece += (mask.sum() / len(probs)) * abs(
            probs[mask].mean() - labels[mask].mean())
    return ece

# 模拟：预测概率与标签相互独立（未校准），ECE 应明显大于 0
probs = np.clip(np.random.normal(0.5, 0.25, 10000), 0, 1)
labels = (np.random.rand(10000) < 0.5).astype(int)
print(f'随机预测 ECE = {expected_calibration_error(probs, labels):.4f}')
```

## A/B Test

A/B Test 是评估推荐策略的「金标准」：把用户随机分到对照组（旧策略）和实验组（新策略），观察真实业务指标差异。它通过随机分流排除混淆因素，给出策略变更的因果效应，是所有离线指标的最终裁判。

```text
A/B Test 关键要素：
1. 随机分流 —— 用户按 hash 稳定分桶，保证两组同质
2. 单一变量 —— 一次只改一个策略，否则无法归因
3. 指标分层 —— 护栏指标（不显著恶化）+ 核心指标（要提升）
4. 显著性检验 —— t 检验 / 卡方检验，判断差异是否显著
5. 最小样本量 —— 提前算好需要跑多久才有统计功效

常见陷阱：
- 新奇效应（Novelty Effect）—— 新策略短期虚高，需跑够时间
- 辛普森悖论 —— 分层看才发现总体提升是「假象」
- 互斥与正交层 —— 多个实验不能互相污染
```

```python
import numpy as np
from scipy import stats

def ab_test_two_prop(conv_a, n_a, conv_b, n_b):
    """两样本比例 z 检验，返回 p 值"""
    p_a, p_b = conv_a / n_a, conv_b / n_b
    p_pool = (conv_a + conv_b) / (n_a + n_b)
    se = np.sqrt(p_pool * (1 - p_pool) * (1 / n_a + 1 / n_b))
    z = (p_b - p_a) / se if se else 0.0
    return 2 * (1 - stats.norm.cdf(abs(z)))   # 双侧 p 值

# 对照 10% CTR，实验 10.3% CTR，各 10 万样本
p = ab_test_two_prop(10000, 100000, 10300, 100000)
print(f'p 值 = {p:.4f}，{"显著" if p < 0.05 else "不显著"}')
```

## 应用场景实战

### 场景一：召回模型离线评估（Recall/Precision/Coverage 联合）

```python
def evaluate_recall_model(recall_results, truth, catalog_size, k=50):
    """recall_results: {user: [候选item]}，truth: {user: set}"""
    recall_scores = [recall_at_k(recall_results[u], truth.get(u, set()), k)
                     for u in truth]
    precision_scores = [precision_at_k(recall_results[u], truth.get(u, set()), k)
                        for u in truth]
    cov = coverage(list(recall_results.values()), catalog_size)
    return {
        f'Recall@{k}': np.mean(recall_scores),
        f'Precision@{k}': np.mean(precision_scores),
        'Coverage': cov,
    }

# 模拟：召回 1000 个用户、每个返回 50 候选
import random
random.seed(0)
catalog = 5000
recall_results = {f'u{j}': random.sample(range(catalog), 50) for j in range(1000)}
truth = {f'u{j}': set(random.sample(range(catalog), 5)) for j in range(1000)}
print(evaluate_recall_model(recall_results, truth, catalog, k=50))
```

### 场景二：精排模型排序质量评估（NDCG + MRR + A/B）

```python
def evaluate_rank_model(rank_lists, truth_rel, k=10):
    ndcgs = [ndcg_at_k(rank_lists[u], truth_rel[u], k) for u in truth_rel]
    mrr = np.mean([reciprocal_rank(rank_lists[u], set(truth_rel[u])) for u in truth_rel])
    return {f'NDCG@{k}': np.mean(ndcgs), 'MRR': mrr}

# 两个精排模型对比
model_a = {u: rec_list[u] for u in rec_list}
model_b = {u: list(reversed(rec_list[u])) for u in rec_list}   # 故意倒序的坏模型
print('模型A:', evaluate_rank_model(model_a, truth_rel))
print('模型B:', evaluate_rank_model(model_b, truth_rel))
# 模型B 的 NDCG 明显更低，说明排序质量差
```

## 最佳实践与踩坑记录

### 最佳实践

1. 召回阶段看 Recall@K + Coverage，精排阶段看 NDCG@K + MRR，别混用
2. 指标要分层：核心业务指标（CTR/CVR/GMV）+ 护栏指标（时长、留存、公平性）
3. 离线指标只做「快速淘汰」，最终以 A/B Test 为准，离线涨了线上不一定涨
4. NDCG 用多级相关（0~4）比二值更能区分排序质量
5. Calibration 用 ECE/Brier 定期监控，涉及出价和阈值的场景必须校准
6. A/B Test 提前算最小样本量，跑够时间避免新奇效应误判

### 踩坑记录

```text
坑 1：只看 CTR 不看时长/留存
结论：CTR 涨了但用户时长、次日留存都在掉，长期看是负优化。
原因：标题党、低质内容天然高 CTR，但伤用户体验。
解法：CTR 配时长、完播、留存等护栏指标一起看，做长期评估。

坑 2：离线 NDCG 大涨但线上没反应
结论：离线排序质量提升了，线上业务指标纹丝不动。
原因：离线数据有位置偏差/曝光偏差，与线上分布不一致。
解法：用逆倾向加权（IPS）修正离线指标，或直接上小流量 AB 验证。

坑 3：A/B 实验没跑够就下结论
结论：实验第 2 天看到提升就全量，结果一周后回落甚至变负。
原因：新奇效应（用户对变化短期敏感）与周期性波动。
解法：跑满一个完整周期（至少 1~2 周），看显著性检验再决策。

坑 4：多个实验互相污染
结论：两个实验同时跑，互相抢流量、指标对不上。
原因：实验层没有做互斥/正交设计，用户同时落在多个实验组。
解法：用分层实验框架（互斥层 + 正交层），保证归因清晰。

坑 5：CVR 样本太少导致指标剧烈抖动
结论：转化率每天上下波动 30%，无法判断策略好坏。
原因：转化事件稀疏，分母小、方差大。
解法：扩大样本、延长观测窗口，或改看加购率等更前置的中间指标。
```

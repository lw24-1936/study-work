## 概述

计算机组成研究「一台机器如何把程序跑起来」：CPU 取指执行、内存和 Cache 分层存储、磁盘和 IO 设备做输入输出。理解这些硬件特性，才能写出缓存友好、并行高效、IO 合理的代码。

```text
核心要点：
1. 存储层次 —— 寄存器 < Cache < 内存 < 磁盘，越快越贵越小
2. CPU 瓶颈 —— 算力、流水线、缓存命中率决定程序快慢
3. GPU 并行 —— 数千核心适合大规模数据并行（矩阵运算）
4. IO 是坑 —— 磁盘/网络 IO 往往比计算慢几个数量级
```

## CPU

CPU 是计算机的「大脑」，负责取指、译码、执行。现代 CPU 靠流水线、超标量、分支预测、多核等技术提高吞吐。

```text
CPU 核心概念：
1. 指令周期 —— 取指 → 译码 → 执行 → 写回
2. 流水线 —— 多条指令重叠执行，提高吞吐
3. 分支预测 —— 猜错要清空流水线，代价高
4. 多核/超线程 —— 真正并行 / 一核模拟两逻辑核
5. SIMD —— 一条指令处理多个数据（向量化）
```

```python
# Python 查看 CPU 信息
import os, platform
print("逻辑核数：", os.cpu_count())
print("架构：", platform.machine())
# 输出类似：逻辑核数：16，架构：x86_64
```

## GPU

GPU 有数千个轻量核心，适合大规模数据并行。深度学习训练本质是大矩阵乘法，正好契合 GPU 的 SIMT 架构。

```text
GPU 与 CPU 对比：
1. CPU —— 少数（8~64）强核心，擅长复杂控制、低延迟
2. GPU —— 数千弱核心，擅长同构数据并行、高吞吐
3. 带宽 —— GPU 显存带宽远超 CPU 内存（可达 TB/s）
4. 适用 —— 矩阵乘法、卷积、大规模并行规约
```

```python
# PyTorch 检查 GPU 与数据搬移
import torch
print("CUDA 可用：", torch.cuda.is_available())
if torch.cuda.is_available():
    print("GPU：", torch.cuda.get_device_name(0))
    x = torch.randn(1000, 1000).cuda()   # 搬到显存
    y = x @ x                            # GPU 上做矩阵乘法
    print("显存占用：", torch.cuda.memory_allocated() / 1e6, "MB")
```

```text
GPU 编程要点：数据搬移有 PCIe 开销，尽量一次搬到显存；混合精度（FP16/BF16）加速省显存；多卡用数据并行/模型并行。
```

## 内存

内存（RAM）是 CPU 直接访问的工作空间，断电丢失（易失性）。程序运行时，代码和数据都在内存里。

```text
内存相关概念：
1. 地址空间 —— 每个字节有唯一地址，CPU 按地址读写
2. 管理 —— 由 OS 分配、回收、隔离（虚拟内存）
3. 延迟 —— 内存访问延迟约几十到一百纳秒
4. 对齐 —— 数据按 4/8 字节对齐访问更快
```

```python
# 查看内存与数组占用
import psutil, numpy as np
vm = psutil.virtual_memory()
print(f"总内存 {vm.total/1e9:.1f}GB，已用 {vm.used/1e9:.1f}GB，使用率 {vm.percent}%")
a = np.zeros((1000, 1000), dtype=np.float64)
print(f"数组占用：{a.nbytes/1e6:.1f} MB")   # 1000*1000*8 字节
```

```text
内存优化：用小 dtype（float32/int8）、复用对象避免反复分配、稀疏矩阵存储、排查内存泄漏。
```

## Cache

Cache 是 CPU 与内存之间的高速小容量存储器，利用时间/空间局部性缓存最近访问的数据，缓解 CPU 与内存的速度差。

```text
Cache 层次：
L1 —— 每核私有，几十 KB，~1ns
L2 —— 每核私有，几百 KB，~4ns
L3 —— 多核共享，几 MB~几十 MB，~10ns
主存 —— 共享，几十 GB，~60-100ns

缓存行（Cache Line）—— 通常 64 字节，是缓存读写最小单位
```

```python
# 缓存友好性：顺序访问 vs 跳跃访问
import numpy as np, time
N = 8000
a = np.random.randn(N, N)
t0 = time.time(); s1 = a.sum(axis=0); t_row = time.time() - t0
t0 = time.time(); s2 = a.T.sum(axis=1); t_col = time.time() - t0
print(f"连续访问 {t_row:.4f}s vs 跳跃访问 {t_col:.4f}s")
# 连续访问通常快数倍到十几倍
```

## 磁盘

磁盘是持久化存储，断电不丢（非易失性）。HDD 靠磁头寻道，SSD 靠闪存，两者延迟和吞吐差异巨大。

```text
磁盘对比：
1. HDD —— 顺序 ~200MB/s，随机极慢（寻道 ~10ms）
2. SSD —— 顺序 ~500-7000MB/s，随机远快于 HDD
3. 顺序 vs 随机 —— 顺序访问远快于随机，尤其 HDD
4. 优化 —— 批量读写、顺序布局、用 SSD、压缩减 IO 量
```

```python
# 顺序写 vs 随机写速度差异
import os, time, random
fname = "/tmp/io_test.bin"; size = 200 * 1024 * 1024
t0 = time.time()
with open(fname, "wb") as f: f.write(b"0" * size)
print(f"顺序写 200MB：{time.time()-t0:.3f}s")
block = b"1" * 4096
t0 = time.time()
with open(fname, "r+b") as f:
    for _ in range(5000):
        f.seek(random.randrange(0, size, 4096)); f.write(block)
print(f"随机写 5000×4KB：{time.time()-t0:.3f}s")
os.remove(fname)
```

## IO

IO 指 CPU 与外部设备（磁盘、网络等）的数据交换，延迟比计算高几个数量级，是系统性能的头号瓶颈。

```text
IO 分类：
1. 阻塞 IO —— 发起后等结果，期间线程不能干别的
2. 非阻塞 IO —— 立即返回，轮询或回调处理完成
3. 异步 IO —— 发起后继续执行，完成时通知（回调/协程）
4. 优化 —— 异步化、批量、缓存热点、零拷贝
```

```python
# 异步 IO vs 阻塞 IO
import asyncio, aiohttp, time
async def dl():
    async with aiohttp.ClientSession() as s:
        await asyncio.gather(*[s.get("http://httpbin.org/delay/1") for _ in range(3)])
t0 = time.time(); asyncio.run(dl())
print(f"异步下载 3 个延迟 1s 的请求：{time.time()-t0:.2f}s（同步约 3s）")
```

## 中断

中断是外部设备通知 CPU「有事件需要处理」的机制：CPU 暂停当前任务，转去执行中断处理程序，处理完再恢复，免去轮询的浪费。

```text
中断机制：
1. 中断源 —— 硬件中断（IO 完成、时钟）+ 软件中断（系统调用、异常）
2. 处理程序 —— 短小精悍，快速响应
3. 中断向量表 —— 中断号对应处理程序入口
4. 对比轮询 —— 轮询浪费 CPU，中断让 CPU 空出来干别的
```

```python
# Python signal 是软件中断的体现
import signal, time
def handler(signum, frame):
    print(f"收到信号 {signum}（SIGINT），优雅退出"); raise SystemExit(0)
signal.signal(signal.SIGINT, handler)
print("按 Ctrl+C 触发中断...")
time.sleep(30)
```

## DMA

DMA（直接存储器访问）让设备绕过 CPU 直接在内存和设备间传数据，CPU 只负责发起和收尾，大幅降低大块数据传输的 CPU 开销。

```text
DMA 流程：
1. CPU 告诉 DMA 控制器：源地址、目的地址、长度
2. DMA 接管总线，设备 ↔ 内存直接传数据
3. 传输完成发中断通知 CPU

意义：释放 CPU、提高吞吐，典型用于磁盘读写、网络收发、显卡传输
```

```python
# 概念演示：逐字节拷贝 vs 底层批量拷贝
import time
data = bytearray(1024 * 1024)
t0 = time.time(); dst = bytearray(len(data))
for i in range(len(data)): dst[i] = data[i]
print(f"逐字节拷贝：{time.time()-t0:.6f}s")
t0 = time.time(); dst2 = data[:]      # 底层 memcpy
print(f"批量拷贝：{time.time()-t0:.6f}s")
```

## 应用场景实战

### 场景一：分析训练脚本的性能瓶颈

```python
import time, psutil, numpy as np
np.random.randn(1000000).astype(np.float32).tofile("/tmp/dummy.bin")

t0 = time.time(); X = np.random.randn(2000, 2000); y = X @ X.T
compute_time = time.time() - t0
t0 = time.time(); data = np.fromfile("/tmp/dummy.bin", dtype=np.float32)
io_time = time.time() - t0
print(f"计算 {compute_time:.3f}s vs IO {io_time:.3f}s，CPU {psutil.cpu_percent()}%")
# 计算远大于 IO → 优化计算；反之优化 IO
```

### 场景二：缓存友好 vs 不友好的矩阵遍历

```python
import numpy as np, time
N = 4000
mat = np.random.randn(N, N)
t0 = time.time(); row_sum = np.array([mat[i].sum() for i in range(N)])
row_time = time.time() - t0
t0 = time.time(); col_sum = np.array([mat[:, j].sum() for j in range(N)])
col_time = time.time() - t0
print(f"按行 {row_time:.3f}s vs 按列 {col_time:.3f}s，速度比 {col_time/row_time:.1f}x")
# 按列遍历通常慢数倍，因为每次访问都跨缓存行
```

## 最佳实践与踩坑记录

### 最佳实践

1. 性能敏感代码优先保证数据顺序访问，利用缓存局部性
2. 大数据搬移交给 numpy/memcpy 底层实现，别手写逐字节循环
3. 训练前先 profile，判断瓶颈在计算、IO 还是内存
4. 网络/磁盘 IO 密集任务用异步或线程池，避免阻塞主线程
5. 训练数据批量加载 + prefetch，让计算和 IO 重叠
6. 大数组用 float32 替代 float64，内存和带宽立省一半

### 踩坑记录

```text
坑 1：按列遍历大二维数组
结论：同样的求和，按列访问比按行慢数倍到十几倍。
原因：按列访问每次跨缓存行，Cache 命中率极低。
解法：按内存连续方向遍历，或先转置再遍历。

坑 2：训练数据一条条读，CPU 空转等 IO
结论：GPU/CPU 大部分时间在等数据，利用率低。
原因：同步阻塞加载，计算和 IO 串行。
解法：DataLoader 多 worker + prefetch，让 IO 和计算并行。

坑 3：没意识到 CPU-GPU 数据搬移开销
结论：小 tensor 反复 .cuda()/.cpu() 导致训练极慢。
原因：PCIe 搬移有固定延迟，小数据搬移得不偿失。
解法：数据一次搬到显存，在 GPU 上算完再搬回。

坑 4：用 float64 存不需要精度的数据
结论：内存占用翻倍、带宽翻倍，计算反而更慢。
原因：float64 是 float32 两倍大小，很多场景精度过剩。
解法：默认 float32，必要时再升精度。

坑 5：忽略伪共享导致多线程越并行越慢
结论：多线程各自更新相邻数据，性能不升反降。
原因：相邻变量落同一缓存行，线程互相使缓存行失效。
解法：共享数据按缓存行对齐或 padding 隔开。
```

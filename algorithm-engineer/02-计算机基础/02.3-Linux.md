## 概述

Linux 是算法工程师的主要工作环境：训练在服务器上跑，服务在容器里部署，日志在文件里查。掌握进程、权限、网络、日志、systemd、cron、ulimit，是日常运维的基本功。

```text
核心要点：
1. 一切皆文件 —— 设备、网络、进程都抽象成文件描述符
2. 进程管理 —— ps/top/kill/nice 观测和控制进程
3. 权限模型 —— 用户/组/其他 + 读/写/执行
4. 服务与任务 —— systemd 管服务，cron 管定时任务
```

## 进程

Linux 里进程是运行中的程序实例。运维核心动作就是「看进程、找进程、杀进程、调进程」。

```text
进程管理要点：
1. PID —— 进程唯一标识，PPID 是父进程
2. 状态 —— R 运行 / S 睡眠 / D 不可中断 / Z 僵尸 / T 停止
3. 信号 —— kill -15 优雅退出，kill -9 强杀
4. 优先级 —— nice 值 -20~19，越小优先级越高
```

```bash
# 进程查看与管理
ps aux | grep python                 # 找 python 进程
top -bn1 | head -15                  # 资源占用快照
pgrep -f train.py                    # 按命令行找 PID
kill -15 12345                       # 优雅终止（SIGTERM）
kill -9 12345                        # 强杀（SIGKILL）
```

```bash
# 后台运行与前台切换
python train.py > train.log 2>&1 &   # 后台运行，输出重定向到日志
jobs                                  # 查看后台任务
fg %1                                 # 1 号任务切回前台
nohup python train.py &               # 退出终端也不被杀
```

## 权限

Linux 权限模型基于「用户 - 组 - 其他」三类主体，每类有读（r）、写（w）、执行（x）三种权限。

```text
权限表示法：
-rwxr-xr--  拆解：类型（- 普通文件）+ 属主 rwx + 属组 r-x + 其他 r--
数字权限：r=4, w=2, x=1
755 = rwx r-x r-x；644 = rw- r-- r--
```

```bash
# 权限管理命令
ls -l file.txt                        # 查看权限
chmod 755 script.sh                   # 设为 rwxr-xr-x
chmod +x script.sh                    # 加执行权限
chown user:group file.txt             # 改属主属组
chown -R user:group dir/              # 递归改
```

```text
目录权限的坑：目录执行权限（x）决定能否「进入」，读权限（r）决定能否「列出」。sudo 提权配置在 /etc/sudoers。
```

## 网络

Linux 网络管理涵盖网卡配置、连接排查、端口与防火墙，是定位「服务连不上」的基础。

```bash
# 网络排查命令
ip addr                               # 查看 IP 和网卡
ip route                              # 查看路由表
ping -c 4 8.8.8.8                     # 测连通性
ss -tlnp                              # 查看监听端口
ss -tnp                               # 查看已建立连接
lsof -i :8080                         # 谁占用了 8080 端口
```

```text
网络排查思路：
1. 网络层 —— ping 网关/IP，确认物理连通
2. 传输层 —— ss 看端口是否监听、连接是否建立
3. 应用层 —— curl 请求看 HTTP 响应
4. 防火墙 —— iptables/firewalld 是否拦截
```

```bash
# 抓包分析
tcpdump -i any port 8080 -w dump.pcap   # 抓 8080 流量
tcpdump -i any host 10.0.0.5            # 抓指定主机流量
```

## 日志

Linux 日志集中在 /var/log 下，syslog/journald 是两大体系。排查问题时「先看日志」永远是第一步。

```text
日志体系：
1. syslog —— 传统日志，/var/log/syslog、messages
2. journald —— systemd 日志，用 journalctl 查看
3. 应用日志 —— 各服务自写，如 /var/log/nginx/、app.log
```

```bash
# 日志查看与分析
tail -f /var/log/syslog               # 实时跟踪
tail -n 100 app.log                   # 最后 100 行
grep -i error app.log                 # 过滤错误
journalctl -u my-service -f           # 跟踪 systemd 服务日志
journalctl --since "10 min ago"       # 按时间过滤
```

```text
日志最佳实践：结构化（JSON）便于检索、分级（生产开 INFO 以上）、logrotate 轮转防撑爆磁盘、集中收集送 ELK/Loki。
```

## systemd

systemd 是现代 Linux 的初始化系统和服务管理器，负责开机启动、服务编排、进程守护。

```ini
# /etc/systemd/system/my-trainer.service 示例
[Unit]
Description=Model Trainer Service
After=network.target

[Service]
Type=simple
User=mluser
WorkingDirectory=/opt/trainer
ExecStart=/opt/trainer/venv/bin/python train.py
Restart=always
RestartSec=5
Environment=CONFIG=/opt/trainer/config.yaml

[Install]
WantedBy=multi-user.target
```

```bash
# systemd 服务管理
systemctl daemon-reload               # 改配置后重载
systemctl start my-trainer            # 启动
systemctl enable my-trainer           # 开机自启
systemctl status my-trainer           # 查看状态
journalctl -u my-trainer -f           # 看服务日志
```

## cron

cron 是 Linux 的定时任务调度器，用于周期性执行脚本——定时拉数据、定时训练、定时清理。

```text
cron 表达式（分 时 日 月 周）：
* * * * *     每分钟
0 2 * * *     每天凌晨 2 点
*/10 * * * *  每 10 分钟
0 0 * * 1     每周一凌晨
0 9 1 * *     每月 1 号早上 9 点
```

```bash
# 编辑定时任务
crontab -e                            # 编辑当前用户任务
crontab -l                            # 查看当前任务

# crontab 内容示例
0 3 * * *  /opt/scripts/pull_data.sh >> /var/log/pull.log 2>&1
0 4 * * 0  /opt/scripts/retrain.sh
0 5 * * *  /opt/scripts/cleanup.sh
```

```text
cron 要点：环境变量与登录 shell 不同（用绝对路径）、输出重定向到日志、脚本内做失败告警、注意服务器时区。
```

## ulimit

ulimit 限制当前会话能使用的系统资源（文件数、内存、进程数等），防止单个进程耗尽系统资源。

```text
ulimit 常用限制：
1. -n —— 打开文件描述符上限（socket 也算）
2. -u —— 用户最大进程数
3. -s —— 栈大小；-c —— core dump 大小
4. -v —— 虚拟内存上限
```

```bash
# 查看和设置 ulimit
ulimit -a                             # 查看所有限制
ulimit -n                             # 当前文件描述符上限
ulimit -n 65535                       # 临时调大（当前会话有效）

# 永久生效：/etc/security/limits.conf
# * soft nofile 65535
# * hard nofile 65535
```

```text
坑点：高并发服务 fd 不够会报 "Too many open files"；systemd 服务要用 LimitNOFILE= 而非 limits.conf。
```

## 应用场景实战

### 场景一：把训练脚本封装成 systemd 服务 + 定时器

```ini
# /etc/systemd/system/retrain.service
[Unit]
Description=Nightly Model Retrain
After=network.target

[Service]
Type=oneshot
User=mluser
WorkingDirectory=/opt/ml/retrain
ExecStart=/opt/ml/retrain/venv/bin/python train.py --config config.yaml
LimitNOFILE=65535
MemoryMax=8G
CPUQuota=200%

[Install]
WantedBy=multi-user.target
```

```bash
# 用 systemd timer 定时训练（替代 cron）
cat > /etc/systemd/system/retrain.timer <<'EOF'
[Unit]
Description=Run retrain daily at 3am
[Timer]
OnCalendar=*-*-* 03:00:00
Persistent=true
[Install]
WantedBy=timers.target
EOF
systemctl daemon-reload && systemctl enable retrain.timer
systemctl list-timers                 # 查看定时器
```

### 场景二：定位「Too many open files」并修复

```bash
# 1. 查看进程打开的 fd 数与上限
PID=$(pgrep -f "python app.py")
ls /proc/$PID/fd | wc -l              # 已打开 fd 数
cat /proc/$PID/limits | grep "open files"

# 2. 临时调大
ulimit -n 65535

# 3. 永久修复：systemd 服务 [Service] 段加 LimitNOFILE=65535
systemctl daemon-reload && systemctl restart app
```

```python
# 复现 fd 泄漏：只开不关
def leak_fd():
    fds = []
    try:
        while True:
            fds.append(open("/dev/null", "r"))
    except OSError as e:
        print("触发上限：", e, "已泄漏", len(fds))
    finally:
        for f in fds: f.close()
# 正确写法：with open(...) 自动关闭
```

## 最佳实践与踩坑记录

### 最佳实践

1. 排查问题先看日志，再查进程，最后看网络
2. 长驻服务用 systemd 管理，崩溃自动重启、开机自启
3. 定时任务优先用 systemd timer（功能更强、日志更好）
4. 生产服务的资源限制写在 systemd unit 里（LimitNOFILE/MemoryMax）
5. 日志必须轮转，避免磁盘被写满
6. 权限遵循最小化原则，别用 root 跑应用服务

### 踩坑记录

```text
坑 1：cron 里脚本能手动跑，定时却不执行
结论：到了时间没任何反应，日志也没输出。
原因：cron 环境变量和登录 shell 不同，相对路径/命令找不到。
解法：脚本用绝对路径，cron 里显式设 PATH，输出重定向到日志。

坑 2：高并发服务报 "Too many open files"
结论：请求量上来后连接建立失败。
原因：进程 fd 数达到 ulimit -n 上限。
解法：systemd 服务设 LimitNOFILE=65535，并排查 fd 泄漏。

坑 3：日志不轮转导致磁盘写满
结论：某天服务全部异常，df 一看磁盘 100%。
原因：应用日志无限增长，没有 logrotate 控制。
解法：配置 logrotate 轮转 + 压缩 + 限制保留份数。

坑 4：用 kill -9 直接杀服务导致数据丢失
结论：服务被杀后数据不一致，缓冲区内容丢失。
原因：SIGKILL 不可捕获，进程没机会清理落盘。
解法：先 kill -15 给优雅退出机会，超时再 -9。

坑 5：改了 limits.conf 但服务限制没生效
结论：改完 fd 上限，重启服务还是旧值。
原因：systemd 服务不读 limits.conf，要用 unit 里的 LimitNOFILE。
解法：[Service] 段配置 LimitNOFILE，daemon-reload 重启。
```

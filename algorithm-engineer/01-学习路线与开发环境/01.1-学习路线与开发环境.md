## 概述

算法工程师的学习路线是一张「能力网络」：从计算机基础、数学、编程三根支柱出发，延伸到机器学习、深度学习、大模型与工程化部署。开发环境是这条路线落地的前提——没有一套顺手的环境，学习效率会大打折扣。

```text
核心要点：
1. 三层能力 —— 基础层（数学/计算机/编程）支撑算法层，算法层支撑业务层
2. 先修关系 —— 数学和编程是机器学习的前置，机器学习是深度学习的前置
3. 环境即生产力 —— IDE、包管理、容器、大数据平台都要提前搭好
4. 可复现 —— 环境、代码、数据、实验配置全部版本化，才能长期迭代
```

## 大数据与算法全栈能力模型

算法工程师的「全栈」指从数据到模型到服务的完整链路：能取数、能建模、能上线、能运维。

```text
算法全栈能力模型（四层）：
1. 数据层 —— SQL、数据清洗、特征工程、数据管道
2. 算法层 —— 机器学习、深度学习、推荐/搜索/NLP/CV 等方向
3. 工程层 —— Python/Java/Scala、服务框架、容器、分布式计算
4. 平台层 —— 训练平台、推理平台、监控、实验管理
```

```python
# 能力自检：描述四层能力，查漏补缺
skill_map = {
    "数据层": {"SQL": 4, "特征工程": 3, "数据管道": 2},
    "算法层": {"机器学习": 4, "深度学习": 3, "推荐系统": 2},
    "工程层": {"Python": 4, "Java": 2, "Docker": 3, "分布式": 2},
    "平台层": {"训练平台": 2, "推理服务": 2, "实验管理": 1},
}
weak = [(l, n) for l, s in skill_map.items() for n, v in s.items() if v < 3]
print("待补强：", weak)
```

## 学习阶段与先修关系

学习路线可划分为若干阶段，每个阶段有明确的前置依赖，跳过前置直接学后面的内容往往事倍功半。

```text
学习阶段：
阶段一（地基）：计算机基础 + 数学基础 + 一门主力语言
阶段二（核心）：数据结构与算法 + 传统机器学习
阶段三（进阶）：深度学习 + PyTorch
阶段四（前沿）：LLM、RAG、Agent、生成模型
阶段五（实战）：业务方向 + 工程化部署

关键先修关系：
线性代数 → 机器学习；概率统计 → 学习理论/评估指标
数据结构 → 工程代码；传统机器学习 → 深度学习 → LLM
```

## Linux/Shell/Git

Linux、Shell、Git 是「基础操作三件套」：服务器跑实验、批处理数据、管理代码版本，全都离不开。

```bash
# Shell 常用操作：统计日志、看资源、批处理
grep "ERROR" app.log | awk '{print $5}' | sort | uniq -c | sort -rn   # 统计错误来源
top -bn1 | head -20                                                   # 资源占用
df -h                                                                # 磁盘
find . -name "*.py" | xargs wc -l | tail -1                          # 统计代码行数
```

```bash
# Git 核心工作流
git init
git add -A && git commit -m "feat: 初始化实验脚本"
git branch experiment/a && git checkout experiment/a
git push origin experiment/a
git log --oneline --graph          # 提交历史
git stash / git stash pop          # 临时保存/恢复
```

## Java/Python/Scala

三门语言在大数据与算法生态里各司其职：Python 做算法实验，Java/Scala 做底层引擎与高性能服务。

```text
语言分工：
1. Python —— 算法建模、数据分析、快速原型，生态最全
2. Java —— 大数据引擎（Hadoop/HBase）与后端服务基石
3. Scala —— Spark/Flink 原生语言，函数式 + JVM
```

```python
# Python：算法实验主力
import numpy as np
X = np.random.randn(1000, 10); w = np.random.randn(10)
y = X @ w + 0.1 * np.random.randn(1000)
print(np.linalg.lstsq(X, y, rcond=None)[0][:3])   # 最小二乘解
```

```java
// Java：强类型 + JVM，大数据引擎标准语言
import java.util.*;
public class WordCount {
    public static void main(String[] a) {
        Map<String, Integer> c = new HashMap<>();
        for (String w : Arrays.asList("a", "b", "a", "c")) c.merge(w, 1, Integer::sum);
        System.out.println(c);   // {a=2, b=1, c=1}
    }
}
```

```scala
// Scala：函数式风格，Spark 官方语言
val data = List(1, 2, 3, 4, 5)
println(data.map(_ * _))                  // List(1,4,9,16,25)
println(data.foldLeft(0)(_ + _))          // 15
```

## Maven/Gradle/Poetry/uv

包管理与构建工具解决「依赖地狱」：把依赖、版本、构建流程标准化。Java/Scala 用 Maven/Gradle，Python 用 Poetry/uv。

```xml
<!-- Maven pom.xml 片段 -->
<dependencies>
    <dependency>
        <groupId>org.apache.spark</groupId>
        <artifactId>spark-core_2.12</artifactId>
        <version>3.5.0</version>
    </dependency>
</dependencies>
```

```toml
# pyproject.toml（Poetry/uv 共用格式）
[tool.poetry.dependencies]
python = "^3.11"
numpy = "^1.26"
pandas = "^2.1"
```

```bash
# uv 常用命令
uv venv                      # 创建虚拟环境
uv add numpy pandas          # 添加依赖
uv lock                      # 锁定版本
uv run python train.py       # 在项目环境运行
```

## Docker/Compose

Docker 把应用和环境打包成镜像，保证「本地能跑、服务器也能跑」；Compose 用 YAML 编排多容器应用。

```dockerfile
# Dockerfile：打包 Python 训练镜像
FROM python:3.11-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
CMD ["python", "train.py"]
```

```yaml
# docker-compose.yml：训练服务 + 数据库
services:
  trainer:
    build: .
    volumes: ["./data:/app/data", "./models:/app/models"]
    environment: {BATCH_SIZE: "64"}
  db:
    image: postgres:16
    environment: {POSTGRES_PASSWORD: example}
```

## Kubernetes 数据平台环境

Kubernetes 是数据平台的事实标准，负责编排训练/推理任务、弹性伸缩、资源隔离。

```text
K8s 核心对象：
1. Pod —— 最小调度单元；Deployment —— 管理副本、滚动更新
2. Service —— 稳定入口；ConfigMap/Secret —— 配置与敏感信息
3. Job/CronJob —— 一次性任务/定时任务（训练常用）
```

```yaml
# 训练 Job 的 YAML 片段
apiVersion: batch/v1
kind: Job
metadata: {name: train-job}
spec:
  template:
    spec:
      containers:
      - name: trainer
        image: myregistry/trainer:latest
        resources:
          requests: {memory: "4Gi", cpu: "2"}
          limits:   {memory: "8Gi", cpu: "4"}
        command: ["python", "train.py"]
      restartPolicy: Never
```

```bash
# kubectl 常用命令
kubectl get pods -n ml-platform      # 查看 Pod
kubectl logs -f train-job-xxxx       # 跟踪日志
kubectl apply -f train-job.yaml      # 提交任务
kubectl delete job train-job         # 删除任务
```

## 数据集、实验环境与工程规范

数据、实验环境与工程规范决定团队能否「持续产出」：数据要可追溯，实验要可复现，代码要可维护。

```text
数据与实验规范：
1. 数据版本化 —— DVC/数据湖管理版本；记录字段含义、来源、更新频率
2. 依赖锁定 —— requirements.txt / uv.lock，可完全还原环境
3. 配置外置 —— 超参写 yaml，不硬编码；随机种子全部固定
4. 实验记录 —— 记录数据版本 + 代码版本 + 超参 + 指标
```

```python
# 可复现实验的标准开头
import random, numpy as np, torch
def set_seed(seed=42):
    random.seed(seed); np.random.seed(seed)
    torch.manual_seed(seed); torch.cuda.manual_seed_all(seed)
    torch.backends.cudnn.deterministic = True
set_seed(42)
```

## 最佳实践与踩坑记录

### 最佳实践

1. 环境一律用版本锁（uv.lock / poetry.lock），不裸用 pip install
2. 所有实验固定随机种子，超参写进 yaml 配置文件
3. 数据、代码、环境三者版本都要记录，才能回溯任何实验
4. 大数据组件先在 Docker 起本地环境调试，再上集群
5. Git 分支按实验/任务命名，提交信息写清楚「做了什么」
6. Notebook 只做探索，可复用逻辑及时抽成 .py 模块

### 踩坑记录

```text
坑 1：依赖不锁版本，换机器就跑不起来
结论：同一份代码在不同环境结果不一致，甚至报错。
原因：numpy/pandas 等库小版本升级可能改变行为，未锁定的依赖会漂移。
解法：用 uv.lock 锁死版本，部署时 --frozen 安装。

坑 2：随机种子只设 torch 没设 numpy
结论：数据采样、初始化仍不可复现，实验结果对不上。
原因：数据管道里的 numpy/random 随机源没固定。
解法：set_seed 同时固定 random、numpy、torch、cudnn。

坑 3：超参硬编码导致实验难以管理
结论：跑了几十个实验后分不清哪个参数对应哪个结果。
原因：超参散落在代码各处，改一次要全局搜索。
解法：超参收敛到 config.yaml，启动时读入并记录。

坑 4：数据切分没固定种子导致泄漏
结论：每次 train/val 划分不同，模型「意外」见过验证集。
原因：切分前没设种子，或先整体标准化再切分。
解法：先切分再标准化，切分用 random_state=42。

坑 5：在开发机直接跑长训练任务
结论：开发机资源被占满，任务还可能被重启杀掉。
原因：开发机是共享资源，长任务没有隔离和调度。
解法：训练任务打包成镜像，提交到 K8s Job 或训练集群。
```

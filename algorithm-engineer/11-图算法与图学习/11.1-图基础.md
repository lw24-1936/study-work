## 概述

图是描述「实体与关系」最自然的数学结构：节点（Vertex）代表实体，边（Edge）代表实体之间的联系。社交网络、推荐系统、知识图谱、道路网络、分子结构背后都是图。图比表和序列更能表达拓扑信息，是图算法和图神经网络（GNN）的基础。

```text
图的核心概念：
1. 节点 Vertex —— 实体（用户/商品/词/原子）
2. 边 Edge —— 关系（好友/购买/共现/化学键）
3. 度 Degree —— 一个节点连的边数，入度/出度区分方向
4. 路径 Path —— 一串首尾相连的边，长度是边数
5. 连通性 —— 任意两节点能否通过路径到达
```

```python
import networkx as nx

# 一张最简单的图：4 个节点 5 条边
G = nx.Graph()
G.add_edges_from([(1, 2), (1, 3), (2, 3), (2, 4), (3, 4)])
print("节点:", G.nodes(), "边:", G.edges())
print("各节点度数:", dict(G.degree()))   # {1: 2, 2: 3, 3: 3, 4: 2}
print("是否连通:", nx.is_connected(G))    # True
```

## Vertex / Edge

节点和边是图的两类基本元素。节点通常有唯一 ID，边由两个端点唯一确定（无向图里 (u,v) 与 (v,u) 是同一条边）。图的规模用 V（节点数）和 E（边数）描述，几乎所有图算法的时间复杂度都用 V 和 E 表示。

```text
基本记号：
- V = 节点集合，|V| = n 表示节点数
- E = 边集合，|E| = m 表示边数
- 邻接：u 与 v 有边相连，称互为邻居
- 度：deg(v) = 与 v 相连的边数；握手定理 Σdeg = 2m
```

```python
import networkx as nx

G = nx.Graph()
G.add_nodes_from(["A", "B", "C", "D"])
G.add_edges_from([("A", "B"), ("B", "C"), ("A", "C"), ("C", "D")])

print("节点数:", G.number_of_nodes(), "边数:", G.number_of_edges())
print("A 的邻居:", list(G.neighbors("A")))   # ['B', 'C']
print("度分布:", [d for _, d in G.degree()]) # [2, 2, 3, 1]
# 握手定理验证：Σdeg = 2m
assert sum(d for _, d in G.degree()) == 2 * G.number_of_edges()
```

## Directed / Undirected

无向图（Undirected）的边没有方向，表示对称关系（好友、共现）；有向图（Directed）的边有方向，表示非对称关系（关注、引用、转账）。有向图的度分为入度（in-degree）和出度（out-degree），两者之和等于边数的两倍。

```text
有向 vs 无向：
1. 无向边 —— (u, v) 与 (v, u) 等价，deg 不分进出
2. 有向边 —— u → v 与 v → u 是两条不同的边
3. 入度 = 指向该节点的边数，出度 = 从该节点出发的边数
4. 强连通 —— 任意两节点互相可达（有向图更强条件）
```

```python
import networkx as nx

# 关注关系是有向的：A 关注 B 不代表 B 关注 A
DG = nx.DiGraph()
DG.add_edges_from([("A", "B"), ("B", "C"), ("C", "A"), ("A", "C")])

print("入度:", dict(DG.in_degree()))   # A:1 B:1 C:2
print("出度:", dict(DG.out_degree()))  # A:2 B:1 C:1
print("有向边数:", DG.number_of_edges())  # 4，比无向多一条 A↔C 的双向

# 无向化后 A-C 的双向边会塌缩成一条
print("转无向:", nx.to_undirected(DG).number_of_edges())  # 3
```

## Weighted Graph

带权图（Weighted Graph）给每条边附加一个数值权重，表示关系的强度、距离或成本。最短路、最小生成树、PageRank 的转移概率都依赖权重。权重的语义决定了算法选择：权重越大代表「越近」还是「越远」，必须先约定清楚。

```text
权重语义（最容易搞混的点）：
1. 距离/成本型 —— 权重越小越好（最短路、MST）
2. 相似度/强度型 —— 权重越大越强（推荐、社区发现）
3. 无权重时视为单位权重 1
```

```python
import networkx as nx

G = nx.Graph()
# 道路网络：权重 = 行驶时间（越小越好）
G.add_weighted_edges_from([
    ("A", "B", 5), ("A", "C", 2), ("B", "C", 1),
    ("B", "D", 4), ("C", "D", 3),
])
print("A→D 最短路径:", nx.dijkstra_path(G, "A", "D"))       # ['A', 'C', 'D']
print("最短路长度:", nx.dijkstra_path_length(G, "A", "D"))  # 5
# 取边权矩阵查看
print(nx.to_numpy_array(G))  # 邻接矩阵，非边为 0
```

## Property Graph

属性图（Property Graph）在图结构之上给节点和边附加键值对属性（label、properties），是现代图数据库（Neo4j、JanusGraph）的核心数据模型。它把「结构」和「语义」分离：结构决定拓扑，属性承载业务信息（用户的年龄、边的时间戳、交易金额）。

```text
属性图四要素：
1. 节点 —— 有 label（类型）+ 属性字典
2. 边 —— 有 type + 方向 + 属性字典
3. label/type —— 区分实体类别（:Person、:FOLLOWS）
4. 属性 —— 键值对，如 {age: 30, name: "Tom"}
```

```python
import networkx as nx

# networkx 用节点/边属性近似表达属性图
G = nx.DiGraph()
G.add_node("u1", label="User", age=30, name="Tom")
G.add_node("p1", label="Product", price=99)
G.add_node("p2", label="Product", price=149)
G.add_edge("u1", "p1", type="PURCHASED", ts="2026-08-01", amount=1)
G.add_edge("u1", "p2", type="VIEWED", ts="2026-08-10")

for n in G.nodes:
    print(n, G.nodes[n])
# 按 label 过滤节点
users = [n for n, d in G.nodes(data=True) if d.get("label") == "User"]
print("User 节点:", users)   # ['u1']
```

## Knowledge Graph

知识图谱（Knowledge Graph）是一种特殊的属性图：节点是实体（人、地点、概念），边是语义关系（主演、出生于、属于），通常组织成 (头实体, 关系, 尾实体) 的三元组形式，用 RDF/OWL 描述。它是搜索引擎、问答、推荐系统的知识底座，也是知识图谱嵌入（KGE）的学习对象。

```text
知识图谱三层：
1. 三元组 —— (s, p, o)，如 (姚明, 出生地, 上海)
2. 本体 Ontology —— 实体类别与关系的模式定义（人物/城市/电影）
3. 推理 —— 从已有三元组推导新关系（传递性：A 在 B，B 在 C → A 在 C）
```

```python
# 用三元组列表 + networkx 建模一个小知识图谱
import networkx as nx

triples = [
    ("姚明", "出生地", "上海"),
    ("姚明", "效力于", "火箭队"),
    ("上海", "属于", "中国"),
    ("火箭队", "位于", "休斯顿"),
]
KG = nx.DiGraph()
for s, p, o in triples:
    KG.add_edge(s, o, relation=p)

print("实体:", list(KG.nodes()))
# 一跳推理：姚明 → 出生地 → 上海 → 属于 → 中国
print("姚明的出生地:", [o for s, o, d in KG.out_edges("姚明", data=True) if d["relation"] == "出生地"])
# 简单传递推理：姚明出生地所属国家
birthplace = [o for s, o, d in KG.out_edges("姚明", data=True) if d["relation"] == "出生地"][0]
country = [o for s, o, d in KG.out_edges(birthplace, data=True) if d["relation"] == "属于"]
print("姚明所属国家:", country)   # ['中国']
```

## 应用场景实战

### 场景一：社交网络的关注关系分析

```python
import networkx as nx

# 构建一个微博关注网络（有向图）
G = nx.DiGraph()
G.add_edges_from([
    ("A", "B"), ("B", "C"), ("C", "A"),
    ("A", "D"), ("D", "E"), ("E", "D"),
    ("C", "E"), ("A", "C"),
])
# 入度 = 粉丝数，出度 = 关注数
fans = dict(G.in_degree())
print("粉丝数排行:", sorted(fans.items(), key=lambda x: -x[1]))
# 互相关注检测：u、v 互相关注才算，用 u < v 去重（每对只记一次）
mutual = sorted((u, v) for u, v in G.edges() if G.has_edge(v, u) and u < v)
print("互关对:", mutual)   # [('A','C'), ('D','E')]
```

### 场景二：电商商品共现图

```python
import networkx as nx
from itertools import combinations

# 用户购买记录，构建商品共现图（无向带权）
orders = [
    ["phone", "case", "film"],
    ["phone", "charger"],
    ["case", "film"],
    ["phone", "case", "charger"],
]
G = nx.Graph()
for order in orders:
    for a, b in combinations(set(order), 2):
        if G.has_edge(a, b):
            G[a][b]["weight"] += 1
        else:
            G.add_edge(a, b, weight=1)

# 权重越高的边 = 越常被一起买，是推荐「猜你喜欢」的依据
for u, v, d in sorted(G.edges(data=True), key=lambda x: -x[2]["weight"]):
    print(f"{u} - {v}: {d['weight']}")
```

## 最佳实践与踩坑记录

### 最佳实践

1. 建模前先想清楚「边有没有方向」「权重语义是距离还是强度」，这决定后面所有算法的选型
2. 图规模大（千万节点）时用邻接表或压缩稀疏表示，别用邻接矩阵（O(V²) 内存爆炸）
3. 属性图存库优先选图数据库（Neo4j），小规模实验用 networkx 足够
4. 知识图谱建模先定本体（实体类别 + 关系 schema），再灌三元组，别边灌边改 schema
5. 度分布（幂律 or 均匀）先看一眼，它决定很多算法在真实网络上的实际性能

### 踩坑记录

```text
坑 1：有向图当无向图处理
结论：关注/引用这类非对称关系被当成对称关系，粉丝数和关注数混为一谈。
原因：默认用了 nx.Graph 而非 nx.DiGraph，方向信息被丢弃。
解法：先问「关系对称吗」，不对称就用有向图，入度出度分开统计。

坑 2：权重语义搞反
结论：把「相似度」当「距离」喂给 Dijkstra，求出的最短路毫无意义。
原因：权重越大代表越近还是越远，建模时没约定，算法默认按距离处理。
解法：距离型权重直接喂；强度型权重先取倒数或负对数再喂最短路。

坑 3：邻接矩阵存大图内存爆炸
结论：百万节点的邻接矩阵需要 1e12 个元素，内存直接 OOM。
原因：邻接矩阵是 O(V²) 空间，真实网络稀疏，99% 是 0。
解法：用邻接表/CSR 稀疏格式，或 networkx 的 scipy_sparse 接口。

坑 4：知识图谱三元组有脏实体
结论：同一个实体写成「姚明」和「姚明（篮球）」两个节点，图谱被割裂。
原因：多来源数据没做实体对齐（entity resolution），ID 不统一。
解法：先做实体对齐和消歧，统一实体 ID 再建图。
```

## 概述

sitemap.json 是小程序根目录下的搜索收录配置文件，用于声明哪些页面允许被微信搜索索引（收录）、哪些页面禁止收录，并可通过 params 精确控制带特定参数的页面是否参与收录。微信「搜一搜」是用户发现小程序的重要入口，合理的 sitemap 配置决定用户能否通过关键词搜索到你的页面。

sitemap 解决的是「搜索可见性」问题：默认情况下（未提供 sitemap.json）所有页面都会被索引，但很多页面（订单详情、个人资料、支付结果）被搜索收录反而会带来隐私与安全风险。通过 rules 规则可以精确控制收录范围，同时配合页面标题、关键词等元信息提升搜索命中率与展示质量。sitemap 配置属于小程序基础配置的一部分，与 02.2 的页面配置（导航栏标题）共同决定页面在搜索场景中的表现。

```text
sitemap 与微信搜索的核心特征：
1. 默认收录 —— 未配置 sitemap.json 时所有页面默认可被索引
2. 规则驱动 —— rules 数组按顺序匹配，action 决定 allow 或 disallow
3. 参数级控制 —— params 与 matching 可精确匹配带特定 query 的页面
4. 收录有时延 —— sitemap 变更后索引更新非实时，需要等待生效
5. 展示靠元信息 —— 搜索结果展示的标题来自 navigationBarTitleText 等配置
6. 隐私相关 —— 涉及用户隐私的页面必须显式 disallow
```

## sitemap.json 配置详解

sitemap.json 位于小程序项目根目录，与 app.json 同级，结构是一个 JSON 对象，包含一个顶层 desc 字段（说明性文字）和一个 rules 数组。微信开发者工具新建项目时默认生成一份带示例规则的 sitemap.json。

```json
{
  "desc": "关于本文件的更多信息，请参考文档 https://developers.weixin.qq.com/miniprogram/dev/framework/sitemap.html",
  "rules": [
    {
      "action": "allow",
      "page": "path/to/page"
    },
    {
      "action": "disallow",
      "page": "path/to/page"
    }
  ]
}
```

规则的执行逻辑是「从上到下逐条匹配，命中即停」：微信索引器按 rules 数组顺序检查页面路径，第一条命中的规则决定该页面是否被收录，后续规则不再参与。因此 allow 与 disallow 的顺序会影响最终结果，通常把精确的、特殊的规则放在前面。

```text
sitemap.json 结构要点：
1. desc —— 顶层说明字段，官方建议保留默认描述
2. rules —— 规则数组，按顺序匹配，命中即止
3. action —— 取值 allow（允许收录）或 disallow（禁止收录）
4. page —— 页面路径，从根目录开始写，如 pages/index/index
5. params —— 可选，配合 matching 控制带 query 参数的页面
6. 不配置 rules（空数组）时所有页面默认不被索引
```

## rules 规则与匹配策略

rules 中每条规则的核心是 action 与 page 的配对。page 支持精确路径，也支持在路径末尾使用 * 通配符匹配一批页面（如 pages/goods/* 匹配 goods 目录下所有页面）。当需要控制带 query 参数的页面收录时，使用 params 与 matching 字段：

```json
{
  "desc": "商品内容页允许收录，带优惠券参数的页面不收录，个人中心禁止收录",
  "rules": [
    {
      "action": "allow",
      "page": "pages/goods/detail",
      "params": ["id"],
      "matching": "inclusive"
    },
    {
      "action": "disallow",
      "page": "pages/goods/detail",
      "params": ["from", "coupon"],
      "matching": "exclusive"
    },
    {
      "action": "disallow",
      "page": "pages/user/*"
    },
    {
      "action": "allow",
      "page": "*"
    }
  ]
}
```

```text
rules 匹配语义：
1. matching: "inclusive" —— 页面 query 包含 params 中任一参数时命中该规则
2. matching: "exclusive" —— 页面 query 不包含 params 中任一参数时命中该规则
3. 不带 params 的规则 —— 只按 page 路径匹配，忽略 query
4. 通配符 * —— 匹配路径前缀，如 pages/goods/* 匹配该目录全部页面
5. 默认兜底 —— 所有规则都不命中时，页面按「未配置」处理（默认可收录）
6. 规则顺序 —— 第一条命中的规则生效，所以 disallow 要放在 allow 之前才能拦截
```

需要特别强调的是规则顺序的重要性：上例中把「带 from/coupon 参数的详情页 disallow」放在「所有页面 allow」之前，否则兜底的 allow * 会先命中，disallow 形同虚设。微信官方建议「disallow 优先，allow 兜底」的写法，确保敏感页面一定被拦截。

```text
规则设计原则：
1. disallow 规则放在 allow 规则前面，避免被兜底规则抢先命中
2. 敏感页面用通配符整体 disallow，如 pages/order/*、pages/user/*
3. 想精确收录的页面显式 allow，并给出稳定参数（如商品 id）
4. 营销类 query 参数（from、channel、coupon）建议 exclusive 排除
5. 页面路径必须与 app.json pages 中注册的路径完全一致
6. 规则越简单越容易维护，能用通配符不要写一堆重复规则
```

## 微信搜索收录机制

微信搜一搜对小程序页面的收录，本质上是一个「抓取 → 解析 → 建立索引 → 展示」的过程。微信的索引系统会按照 sitemap.json 的规则抓取允许收录的页面，解析页面标题、关键词、正文内容，建立关键词索引，之后用户在搜一搜中输入相关关键词时，命中的页面会以卡片形式展示在搜索结果中。

```text
收录机制要点：
1. 收录入口 —— 用户在搜一搜输入关键词，微信从已收录的小程序页面中匹配
2. 抓取对象 —— 仅允许收录的页面会被抓取解析，disallow 页面不会进入索引
3. 标题来源 —— 页面 navigationBarTitleText 是搜索结果标题的主要来源
4. 描述来源 —— 页面 metaDescription 等配置影响搜索结果摘要
5. 非实时 —— sitemap 修改后索引更新需要时间（通常数小时到数天）
6. 页面可达性 —— 页面必须能从某个入口正常打开，死链页面无法被收录
```

收录并不是配置了 allow 就立刻生效：新页面首次被收录、规则调整后重新收录都存在时延，且微信会周期性重新抓取页面以更新索引。开发者无法手动提交页面给微信搜索，只能通过正确的 sitemap 规则与优质的页面元信息「被动等待」收录结果，这也是为什么页面标题、关键词要在一开始就规划好。

另外，被收录的页面会被微信索引系统缓存内容，页面下架或改为 disallow 后，旧索引需要一段时间才会从搜索结果中消失，敏感内容下架时应同步处理（页面改 404、后台下架数据）。

```text
收录时效与可见性：
1. 新页面收录通常需要数小时到数天，属正常现象
2. sitemap 规则调整后，索引按微信的抓取周期逐步更新
3. 页面内容（标题/正文）变更后，索引更新同样有时延
4. 已收录页面改为 disallow，旧索引会逐步过期，不是立即消失
5. 搜索展示结果由微信算法决定，配置正确不等于一定被搜到
6. 小程序被搜索到的前提是主体与类目合规，违规小程序会被限制搜索
```

除了 sitemap.json，mp 后台的「微信搜索 - 页面收录」模块还提供全局页面收录开关。该开关控制小程序整体是否参与微信搜索收录，默认开启；关闭后所有页面都不再参与搜索索引（等价于全局 disallow）。页面收录开关是「总闸」，sitemap.json 是「分闸」，两者共同决定收录范围：总闸关闭时 sitemap 配置不生效，总闸开启时以 sitemap 规则为准。

```text
后台页面收录开关要点：
1. 入口 —— mp 后台「微信搜索 - 页面收录」，全局开关默认开启
2. 总闸语义 —— 关闭后所有页面不被索引，sitemap 规则全部失效
3. 与 sitemap 的关系 —— 总闸开启时，细粒度控制靠 sitemap rules
4. 调整生效 —— 开关调整后索引按抓取周期逐步更新
5. 灰度能力 —— 部分能力（如页面收录）支持按比例灰度配置
6. 新号默认 —— 新注册小程序默认开启页面收录
```

## 搜索优化实践

搜索优化（ASO，App Store Optimization 在小程序场景的延伸）的目标是让页面更容易被收录、更容易在相关关键词下被搜到、展示更吸引人。小程序页面的搜索优化集中在三处：页面标题、页面关键词与描述、页面内容质量。

页面标题即 navigationBarTitleText，这是搜索结果中最重要的展示信息，也是微信索引的主要匹配对象。标题应包含用户可能搜索的核心关键词（品牌词、品类词、场景词），且保持简洁，超长标题会被截断：

```json
// pages/goods/detail.json —— 标题融入品类与场景关键词
{
  "navigationBarTitleText": "正品运动鞋 跑步鞋男款 透气轻便-某某商城"
}
```

页面级关键词与描述在页面 json 中通过 metaKeywords 与 metaDescription 配置，用于补充标题无法容纳的信息，帮助索引系统理解页面内容：

```json
{
  "navigationBarTitleText": "商品详情",
  "metaKeywords": "运动鞋,跑步鞋,男款,透气,某某商城",
  "metaDescription": "某某商城正品运动鞋专场，跑步鞋、休闲鞋、篮球鞋多品牌可选，支持七天无理由退换。"
}
```

```text
搜索优化要点：
1. 标题含核心关键词 —— navigationBarTitleText 是搜索匹配与展示的第一要素
2. metaKeywords 补充长尾词 —— 用逗号分隔，覆盖用户可能的搜索词
3. metaDescription 写清楚价值 —— 描述影响搜索结果摘要与点击率
4. 内容可被解析 —— 页面文本内容（wxml 中的文字）是索引的重要素材
5. 保持页面稳定可达 —— 频繁改路径、下架页面会破坏已收录索引
6. 不要堆砌关键词 —— 标题堆词影响体验，还可能被判定为作弊降权
```

```text
搜索优化禁忌：
1. 标题与页面内容无关的关键词堆砌
2. 通过隐藏文字、异常跳转等方式欺骗索引系统
3. 把用户隐私内容放入标题/描述诱导搜索
4. 频繁修改页面路径导致旧索引全部失效
5. 用营销词干扰搜索（如蹭其他品牌词）
6. 忽略违规内容 —— 被判定违规的页面会被下架索引
```

搜索优化的效果需要数据验证。mp 后台「统计」模块提供搜索相关数据（搜索关键词、搜索进入量、页面曝光与点击），是判断优化是否有效的唯一依据：关键词无曝光说明未被收录或标题不匹配；曝光高点击低说明标题/描述吸引力不足。建议按「收录检查 → 关键词命中检查 → 展示优化」三步循环迭代。

```text
搜索效果监控要点：
1. 后台数据 —— mp 后台统计模块查看搜索进入与关键词数据
2. 收录检查 —— 用微信搜一搜实测核心关键词，确认页面是否出现
3. 关键词命中 —— 无曝光关键词，检查标题与 metaKeywords 是否覆盖
4. 点击优化 —— 曝光高点击低，优化标题可读性与 metaDescription
5. 环比对比 —— 每次 sitemap/标题调整后对比前后数据
6. 迭代节奏 —— 索引更新有时延，数据观察周期按周为单位
```

## sitemap 与隐私合规

sitemap 不止是搜索优化工具，更是隐私与合规的边界控制手段。微信搜索收录的页面可能被任何微信用户通过关键词搜到，凡是涉及用户个人数据、交易信息、内部功能的页面，都应显式 disallow，防止敏感页面被搜索引擎建立索引。

```text
需要 disallow 的典型页面：
1. 个人中心、资料编辑页 —— 包含用户昵称、手机号等个人信息
2. 订单列表、订单详情 —— 包含收货地址、支付金额等交易隐私
3. 支付结果、退款进度页 —— 交易敏感信息
4. 登录页、授权页 —— 引导性页面收录无意义且有风险
5. 管理端、内部工具页 —— 内部功能不应暴露在搜索中
6. 临时活动页、营销页 —— 活动结束后内容过期，收录会造成误导
```

隐私合规层面的核心原则是「默认不收录敏感信息」：即使 sitemap 配置了 allow，页面内容本身也受到隐私保护相关规则约束（详见 14.2-隐私合规）。搜索结果展示的页面摘要来自页面内容，如果页面渲染了用户手机号等隐私字段，即使只 allow 了商品页，也存在隐私内容进入搜索摘要的风险。因此涉及隐私数据渲染的页面，从数据层面就要脱敏（手机号打码、地址脱敏），而不是只依赖 sitemap 拦截。

```text
隐私与合规要点：
1. sitemap disallow 是第一道防线，但不应是唯一防线
2. 页面渲染的用户隐私字段要脱敏，防止进入搜索摘要
3. 用户主动要求删除搜索内容的，平台有相关申诉流程
4. 未成年人相关内容、医疗健康等特殊类目受更严格约束
5. 被收录页面内容发生变化时，及时评估新内容的合规性
6. 隐私政策中应说明小程序页面可能被搜索收录的情况
```

## 应用场景实战

### 场景一：电商小程序 —— 商品页收录 + 订单隐私拦截

电商小程序的目标是让商品详情页尽量被搜索收录（用户搜「跑步鞋」能搜到商品页），同时保证订单、个人中心等隐私页面不被索引。

```json
// sitemap.json —— 商品页收录，隐私页面拦截，兜底 allow
{
  "desc": "关于本文件的更多信息，请参考文档 https://developers.weixin.qq.com/miniprogram/dev/framework/sitemap.html",
  "rules": [
    {
      "action": "disallow",
      "page": "pages/order/*"
    },
    {
      "action": "disallow",
      "page": "pages/user/*"
    },
    {
      "action": "disallow",
      "page": "pages/pay/*"
    },
    {
      "action": "disallow",
      "page": "pages/goods/detail",
      "params": ["from", "coupon"],
      "matching": "exclusive"
    },
    {
      "action": "allow",
      "page": "*"
    }
  ]
}
```

```json
// pages/goods/detail.json —— 商品页搜索元信息
{
  "navigationBarTitleText": "跑步鞋男款透气 轻便减震运动鞋-某某商城",
  "metaKeywords": "跑步鞋,男款,透气,减震,运动鞋,某某商城",
  "metaDescription": "某某商城跑步鞋专场，多品牌正品保障，透气轻便减震，支持七天无理由退换与运费险。"
}
```

```text
场景一要点：
1. order/user/pay 目录整体 disallow，杜绝交易与个人隐私页面进索引
2. 带营销参数（from/coupon）的商品页排除，避免低质量重复页面占用索引
3. 商品页 allow 兜底，保证所有商品详情都能参与收录
4. 商品标题自动拼接「品牌 + 品类 + 卖点 + 商城名」提升搜索命中
5. 营销参数页面排除用 exclusive，即「不带这些参数才收录」
```

### 场景二：内容社区 —— 文章页收录与活动页下架管理

内容社区的核心资产是文章页，需要最大程度被搜索收录；而限时活动页、临时话题页在活动结束后应停止收录，避免用户搜到过期内容。

```json
// sitemap.json
{
  "desc": "关于本文件的更多信息，请参考文档 https://developers.weixin.qq.com/miniprogram/dev/framework/sitemap.html",
  "rules": [
    {
      "action": "disallow",
      "page": "pages/activity/*"
    },
    {
      "action": "disallow",
      "page": "pages/article/detail",
      "params": ["preview"],
      "matching": "inclusive"
    },
    {
      "action": "allow",
      "page": "pages/article/*"
    }
  ]
}
```

活动结束后除了改 sitemap 规则，还要处理已收录页面的存量索引：活动页面内容置为已结束状态或直接下线，让旧索引自然过期；同时保证常规文章页路径长期稳定，已建立的索引持续生效。

```text
场景二要点：
1. 临时页面（活动、话题）整体 disallow，活动结束内容过期也不误导用户
2. preview 参数（预览态文章）用 inclusive 拦截，草稿不收录
3. 文章页 allow 兜底，新文章发布后无需改配置即可参与收录
4. 页面路径保持稳定，路径变更会让已收录索引失效
5. 周期性检查收录效果，通过搜一搜实测关键词命中情况
```

## 最佳实践与踩坑记录

### 最佳实践

1. 项目创建时就规划好 sitemap 规则，采用「disallow 优先、allow 兜底」的结构，避免后期大量页面路径调整
2. 隐私与交易相关目录（user、order、pay、cart）一律通配符 disallow，不依赖逐页枚举
3. 页面标题（navigationBarTitleText）按「关键词 + 卖点 + 品牌」结构设计，同时兼顾用户体验与搜索命中
4. 每个核心页面配置 metaKeywords 与 metaDescription，关键词与页面内容强相关，不堆砌
5. 营销参数（from、channel、coupon 等）通过 params + exclusive 排除，防止低质量重复页面消耗索引
6. 页面路径一旦发布就保持稳定，路径变更前评估对已收录索引的影响
7. 敏感页面不只依赖 sitemap，页面内渲染的隐私数据一律脱敏，双保险防泄漏
8. 定期（如每版本）检查 sitemap 规则与页面目录是否同步，新增隐私页面时记得补规则

### 踩坑记录

坑 1：disallow 规则写在 allow 后面，完全失效
结论：敏感页面仍然被搜索收录。
原因：rules 按顺序匹配、命中即止，兜底 allow 规则先命中了所有页面。
解法：把 disallow 规则全部放在 allow 规则之前；用「disallow 优先、allow 兜底」的结构重排规则。

坑 2：sitemap.json 语法错误导致整个文件不生效
结论：修改规则后收录行为没有变化，或开发者工具报 sitemap 解析错误。
原因：JSON 语法错误（多余逗号、中文引号、注释），微信按无效文件处理。
解法：用 JSON 校验工具检查；rules 数组元素严格按 action/page/params/matching 字段书写，JSON 不支持注释。

坑 3：页面路径与 app.json 注册路径不一致
结论：规则写了 pages/goods/detail 但收录行为异常。
原因：sitemap 的 page 路径必须与 app.json pages 数组中的注册路径完全一致，多写或少写后缀都不匹配。
解法：从 app.json 中复制路径到 sitemap 规则；检查是否漏了 . 或目录层级。

坑 4：sitemap 改了但收录迟迟不更新
结论：把页面从 disallow 改为 allow 后，搜索仍然搜不到。
原因：索引更新非实时，微信按自己的抓取周期重新收录，时延可达数小时到数天。
解法：耐心等待；确认页面可正常访问（无 404、无登录墙）；检查页面内容是否为空壳（纯 JS 渲染无文本）。

坑 5：页面内容变更后搜索摘要还是旧内容
结论：搜索结果展示的描述与页面实际内容不一致。
原因：微信索引的是周期性抓取时的页面快照，内容变更后索引尚未刷新。
解法：等索引自然更新；重要内容变更（下架、整改）时同步处理页面本身，必要时将页面改为 disallow。

坑 6：隐私页面忘记加 disallow 规则
结论：订单页、个人中心页被搜索收录，隐私信息暴露风险。
原因：未配置 sitemap.json 或兜底 allow 规则把隐私页面也放行了。
解法：上线前对照页面目录清单逐页确认规则；隐私数据渲染一律脱敏；发现已收录的敏感页面立即 disallow 并等待索引过期。

坑 7：标题堆砌关键词被降权
结论：标题写满关键词后，搜索排名反而下降甚至不被展示。
原因：微信对关键词堆砌、标题与内容不符的页面判定为低质量。
解法：标题保持自然可读，关键词自然融入；核心关键词不超过 2-3 个，其余放 metaKeywords。

坑 8：活动页下架后仍被搜到
结论：活动结束后用户仍能通过搜索进入已结束的活动页。
原因：活动页改版或下线时未同步调整 sitemap 规则，旧索引未过期。
解法：活动结束立即将活动目录改为 disallow；页面内容置为「已结束」状态；必要时整页下线让索引自然失效。

## 概述

每个小程序页面由四个文件组成（.wxml / .wxss / .js / .json），其中页面级的 .json 文件用于覆盖 app.json 中的全局窗口配置，实现「一页一配置」。页面生命周期则是页面从创建到销毁过程中框架自动回调的一系列函数（onLoad / onShow / onReady / onHide / onUnload），开发者在这些回调中完成数据加载、事件绑定、资源清理等操作。

页面配置解决「页面级差异化」问题：导航栏标题、背景色、下拉刷新开关等全局配置只需要在个别页面不同的，不必改 app.json 全局配置；页面生命周期解决「时机问题」：什么时机请求数据、什么时机刷新、什么时机清理资源，都依赖对生命周期回调的准确理解。两者是编写任何小程序页面的地基，与 02.1 的 app.json 全局配置、05.2 的 App 与 Page 注册共同构成页面体系的完整知识。

```text
页面配置与生命周期的核心特征：
1. 就近覆盖 —— 页面 json 只写差异项，未配置的项继承 app.json 的 window 配置
2. 生命周期固定 —— 五个基础回调（onLoad/onShow/onReady/onHide/onUnload）顺序不可变
3. 参数注入 —— onLoad(options) 自动接收页面路径上的 query 参数
4. 栈式管理 —— 页面按 navigateTo 入栈，最多 10 层，navigateBack 出栈
5. setData 驱动 —— 数据变更必须通过 this.setData 同步到视图层
6. 触发条件差异 —— onShow/onHide 每次前后台切换都会触发，onLoad/onUnload 只触发一次
```

## 页面 json 配置文件

每个页面目录下的同名 .json 文件就是该页面的配置，微信开发者工具新建页面时会自动生成一个空的页面 json。页面 json 里能配置的字段与 app.json 的 window 字段基本一致，语义是「覆盖全局配置」，因此页面 json 中通常只写需要与全局不同的项。

页面 json 支持的全部常用字段如下表（与 app.json 的 window 字段一一对应）：

```text
页面 json 常用字段：
1. navigationBarTitleText —— 导航栏标题文字（页面级覆盖）
2. navigationBarBackgroundColor —— 导航栏背景色（十六进制颜色）
3. navigationBarTextStyle —— 导航栏标题颜色，仅 black / white 两值
4. navigationStyle —— 导航栏样式，默认 default，custom 表示自定义导航栏
5. backgroundColor —— 窗口背景色
6. backgroundTextStyle —— 下拉 loading 样式，仅 dark / light 两值
7. enablePullDownRefresh —— 是否开启页面下拉刷新
8. onReachBottomDistance —— 距页面底部多远（px）时触发 onReachBottom
9. disableScroll —— 为 true 时页面整体禁止滚动（iOS 上对弹层类页面常用）
10. usingComponents —— 页面级引用自定义组件
```

一个真实的商品详情页页面 json：

```json
{
  "navigationBarTitleText": "商品详情",
  "navigationBarBackgroundColor": "#ffffff",
  "navigationBarTextStyle": "black",
  "backgroundColor": "#f5f5f5",
  "backgroundTextStyle": "dark",
  "enablePullDownRefresh": true,
  "onReachBottomDistance": 100,
  "usingComponents": {
    "goods-card": "/components/goods-card/goods-card"
  }
}
```

页面 json 还有一个特殊字段 `"usingComponents"`，它决定该页面可以使用哪些自定义组件。组件路径使用绝对路径（以 / 开头）更稳妥，因为相对路径在分包、插件等场景下容易解析出错。页面 json 中未声明但组件目录里存在的组件，在 wxml 中直接使用会报「Component is not found in path」错误。

```text
页面 json 配置要点：
1. 就近覆盖 —— 页面 json 优先级高于 app.json 的 window，字段级覆盖
2. 只写差异 —— 页面 json 写全量配置反而难以维护，保持最小差异原则
3. usingComponents 是页面 json 独有的高频字段，组件必须在此注册
4. 修改页面 json 无需重新上传代码，但需要重新编译生效
5. navigationBarTitleText 同时是微信搜索收录时展示的页面标题，对 SEO 有意义
6. disableScroll 仅对页面级滚动生效，不影响 scroll-view 内部滚动
```

## navigationBar 导航栏配置

导航栏（navigation bar）是页面顶部展示标题和返回按钮的区域，由微信客户端原生渲染，不是页面 wxml 的一部分，因此只能通过 json 配置，无法用 wxss 修改内部细节。导航栏相关的配置项集中在页面 json 和 app.json 的 window 字段中。

```text
navigationBar 配置项：
1. navigationBarTitleText —— 标题文字，最长约 20 个汉字，超长会截断显示省略号
2. navigationBarBackgroundColor —— 背景色，仅支持十六进制颜色值
3. navigationBarTextStyle —— 标题颜色，仅 black（黑字白底）或 white（白字黑底）
4. navigationStyle —— default 使用系统导航栏；custom 完全自定义导航栏
5. navigationBarShadow —— 导航栏阴影，可配置 backgroundColor 与 opacity
6. navigationBarFrontColor —— Android 端状态栏前景色（对应 navigationBarTextStyle）
```

自定义导航栏（navigationStyle: custom）是电商、内容类小程序的常见选择，因为系统导航栏无法做渐变、沉浸式、自定义返回按钮等效果。使用 custom 后页面内容会上移到屏幕最顶部，需要开发者自行处理状态栏高度（通过 wx.getWindowInfo 或 wx.getSystemInfoSync 获取 statusBarHeight）和安全区（底部安全距离）。

```json
{
  "navigationStyle": "custom",
  "navigationBarTitleText": "个人中心",
  "backgroundColor": "#ffffff"
}
```

```js
// 自定义导航栏页面中，通过胶囊按钮位置计算右侧可用空间
Page({
  onReady() {
    const windowInfo = wx.getWindowInfo()
    const menuButton = wx.getMenuButtonBoundingClientRect()
    console.log('状态栏高度', windowInfo.statusBarHeight)
    console.log('胶囊按钮', menuButton)
    // 导航栏高度 ≈ (胶囊顶部 - 状态栏高度) * 2 + 胶囊高度
    const navHeight =
      (menuButton.top - windowInfo.statusBarHeight) * 2 + menuButton.height
    this.setData({ statusBarHeight: windowInfo.statusBarHeight, navHeight })
  }
})
```

```text
navigationBar 配置要点：
1. custom 模式下返回按钮、标题都由开发者自己渲染，系统不再提供
2. custom 模式不影响 onPullDownRefresh、onReachBottom 等页面能力
3. 胶囊按钮（转发/胶囊）始终由微信渲染，自定义导航栏也无法隐藏
4. 状态栏文字颜色只支持 black/white，想用其他颜色必须 custom 导航栏
5. 单个页面可以随时在页面 json 覆盖全局导航栏配置，互不影响
6. 真机上自定义导航栏必须适配刘海屏与安全区，模拟器表现与真机有差异
```

## 页面生命周期

页面生命周期是指小程序框架在页面「创建 → 显示 → 渲染完成 → 隐藏 → 销毁」过程中自动调用的一系列回调函数。开发者无需手动调用，只需在 Page 构造器中按名字实现对应函数。五个基础生命周期回调按固定顺序执行：

```text
页面生命周期回调顺序：
1. onLoad —— 页面加载时触发一次，可在此接收 onLoad(options) 的 query 参数
2. onShow —— 页面每次显示时触发（首次进入与从其他页面返回都会触发）
3. onReady —— 页面初次渲染完成时触发一次，此时可安全操作节点
4. onHide —— 页面被隐藏时触发（跳转其他页面、切后台、打开半屏弹层）
5. onUnload —— 页面销毁时触发（navigateBack 出栈、redirectTo、reLaunch）
```

完整实现示例：

```js
Page({
  data: {
    goodsId: '',
    goods: null,
    loading: true
  },

  // 1. 页面加载：只触发一次，接收页面路径上的参数
  onLoad(options) {
    console.log('onLoad', options)
    // options 是 url 中 ? 后面的 query 参数对象，已自动 decode
    this.setData({ goodsId: options.id || '' })
    this.fetchGoods(options.id)
  },

  // 2. 页面显示：首次进入和每次从其他页面返回都会触发
  onShow() {
    console.log('onShow')
  },

  // 3. 初次渲染完成：只触发一次，适合做节点查询、图表初始化
  onReady() {
    console.log('onReady')
  },

  // 4. 页面隐藏：跳转其他页面、小程序切后台时触发
  onHide() {
    console.log('onHide')
  },

  // 5. 页面销毁：出栈时触发，适合清理定时器、断开连接
  onUnload() {
    console.log('onUnload')
    if (this.timer) {
      clearInterval(this.timer)
      this.timer = null
    }
  },

  fetchGoods(id) {
    wx.request({
      url: 'https://api.example.com/goods/' + id,
      success: (res) => {
        this.setData({ goods: res.data.data, loading: false })
      }
    })
  }
})
```

除五个基础回调外，页面还支持与用户交互相关的生命周期回调：onPullDownRefresh（下拉刷新触发，需页面 json 开启 enablePullDownRefresh）、onReachBottom（触底触发，配合 onReachBottomDistance）、onPageScroll（页面滚动）、onShareAppMessage（分享）、onResize（窗口尺寸变化）、onTabItemTap（tabBar 点击）等。

```text
生命周期关键时机：
1. onLoad 时页面尚未渲染完成，wxml 节点还不存在，不能做节点查询
2. onShow 每次显示都会触发，是「从详情页返回后刷新列表」的惯用位置
3. onReady 之后才能保证 wx.createSelectorQuery 拿到节点
4. onHide 不代表销毁，切后台再回来 onShow 会再次触发
5. onUnload 只发生在页面出栈时，tabBar 页面切换不会触发 onUnload
6. App 的 onLaunch 先于页面 onLoad，页面 onLoad 时 app.globalData 已就绪
```

## 页面栈与路由行为

小程序用「页面栈」管理页面跳转：navigateTo 打开新页面时新页面入栈，navigateBack 返回时当前页出栈并销毁。页面栈深度上限为 10 层，超过后 navigateTo 会静默失败（不报错也不跳转）。开发者可以通过 getCurrentPages() 拿到当前页面栈中所有页面的实例。

```js
// 跳转到商品详情页，并携带参数（新页面入栈，当前页保留）
wx.navigateTo({
  url: '/pages/goods/detail?id=1001&from=list'
})

// 关闭当前页，跳转到新页面（当前页出栈销毁，不留返回路径）
wx.redirectTo({
  url: '/pages/login/login'
})

// 返回上一页（delta 为返回层数，默认 1）
wx.navigateBack({
  delta: 1
})

// 跳转到 tabBar 页面，必须使用 switchTab，会关闭所有非 tabBar 页面
wx.switchTab({
  url: '/pages/index/index'
})

// 关闭所有页面，打开应用内某个页面（常用于登录态失效后回首页）
wx.reLaunch({
  url: '/pages/index/index'
})
```

```js
// getCurrentPages 获取页面栈，实现跨页传值或更新上一页数据
const pages = getCurrentPages()
const currentPage = pages[pages.length - 1]   // 当前页面实例
const prevPage = pages[pages.length - 2]      // 上一页实例

// 通过页面实例直接调用上一页的方法（注意 setData 路径写法）
if (prevPage) {
  prevPage.setData({
    'list[0].name': '从详情页修改了列表第一项'
  })
}
```

```text
路由行为要点：
1. navigateTo 每次调用栈深 +1，最多 10 层，超出后静默失败
2. switchTab 只能跳 tabBar 页面，且会清空非 tabBar 页面栈
3. navigateBack 触发当前页 onUnload；navigateTo 只触发当前页 onHide
4. redirectTo 用新页面替换当前页，当前页 onUnload 后立即销毁
5. getCurrentPages 拿到的页面实例可以跨页 setData，但不应滥用
6. 页面栈中的页面实例不会被垃圾回收，大对象注意及时置空
```

## 页面数据初始化与 setData

Page 构造器中的 data 是页面数据模型，wxml 通过插值表达式直接绑定 data 中的字段。data 必须在 Page 中预先声明，wxml 里用到的所有字段都应给出初始值，避免首次渲染出现 undefined 导致报错或闪烁。修改数据必须调用 this.setData，直接给 this.data 赋值不会触发视图更新（仅改变内存值）。

```js
Page({
  // 数据初始化：所有 wxml 用到的字段都要有初始值
  data: {
    list: [],
    page: 1,
    hasMore: true,
    loading: false,
    empty: false
  },

  onLoad() {
    this.fetchList()
  },

  fetchList() {
    if (this.data.loading || !this.data.hasMore) return
    this.setData({ loading: true })
    wx.request({
      url: 'https://api.example.com/list',
      data: { page: this.data.page },
      success: (res) => {
        const newList = this.data.list.concat(res.data.data.list)
        this.setData({
          list: newList,
          page: this.data.page + 1,
          hasMore: res.data.data.hasMore,
          loading: false,
          empty: newList.length === 0
        })
      }
    })
  }
})
```

setData 支持路径写法，可以只更新对象中的某个属性或数组中的某一项，避免整对象替换带来的多余渲染：

```js
// 更新嵌套对象的单个字段
this.setData({
  'user.profile.nickname': '新昵称'
})

// 更新数组指定下标项
this.setData({
  'list[3].status': 'paid'
})

// 追加数组（直接给 data 的数组 push 不会触发渲染，必须重新 setData）
const list = this.data.list
list.push(newItem)
this.setData({ list })

// 自定义事件里更新页面数据
this.setData({ count: this.data.count + 1 }, () => {
  // 第二个参数是回调，setData 完成、视图更新后触发
  console.log('视图已更新')
})
```

```text
setData 使用要点：
1. 视图更新依赖 setData，直接修改 this.data 不会触发渲染
2. setData 是逻辑层到视图层的异步通信，高频调用会明显卡顿
3. 一次 setData 的数据量不宜过大，大数据用路径更新或分包处理
4. setData 的回调在视图更新完成后触发，可做「更新后」逻辑
5. data 中不要存非渲染数据（如 DOM 节点、复杂对象），可挂在 this 上
6. setData 的 key 支持 a.b 与 arr[0] 路径语法，这是性能优化的基础
```

## 应用场景实战

### 场景一：商品详情页 —— 参数接收与返回刷新

电商场景中，列表页跳详情页并传商品 id，详情页在 onLoad 中接收参数并请求数据；用户修改了商品收藏状态返回列表页时，列表页在 onShow 中刷新收藏状态。这是页面参数与生命周期配合的典型场景。

```json
// pages/goods/detail.json
{
  "navigationBarTitleText": "商品详情",
  "enablePullDownRefresh": true
}
```

```js
// pages/goods/detail.js
Page({
  data: {
    id: '',
    goods: null,
    loading: true
  },

  onLoad(options) {
    // options.id 来自列表页跳转 url 的 ?id=xxx
    this.setData({ id: options.id })
    this.fetchDetail(options.id)
  },

  onShow() {
    // 每次回到详情页都刷新收藏状态（比如从收藏列表页回来）
    if (this.data.goods) {
      this.refreshFavorite()
    }
  },

  fetchDetail(id) {
    wx.request({
      url: 'https://api.example.com/goods/' + id,
      success: (res) => {
        this.setData({ goods: res.data.data, loading: false })
      }
    })
  },

  refreshFavorite() {
    // 轻量接口，只更新收藏字段
    wx.request({
      url: 'https://api.example.com/goods/' + this.data.id + '/favorite',
      success: (res) => {
        this.setData({ 'goods.favorited': res.data.data.favorited })
      }
    })
  }
})
```

```js
// pages/goods/list.js 中的跳转代码
goDetail(e) {
  const id = e.currentTarget.dataset.id
  wx.navigateTo({
    url: '/pages/goods/detail?id=' + id
  })
}
```

```text
场景一要点：
1. 列表页用 navigateTo 跳详情，返回时列表页状态保留，走 onShow
2. 详情页 onLoad 只执行一次，下拉刷新场景下不会重新接收参数
3. 详情页返回列表页时，列表页 onShow 触发，可在此做轻量刷新
4. 参数尽量只传 id 这类短字符串，完整对象用缓存或全局数据传递
```

### 场景二：列表页 —— 下拉刷新与触底加载

资讯流、商品流页面需要下拉刷新和上拉加载更多。页面 json 开启 enablePullDownRefresh 与 onReachBottomDistance，js 中实现 onPullDownRefresh 和 onReachBottom 两个回调即可，无需任何第三方组件。

```json
// pages/news/list.json
{
  "navigationBarTitleText": "资讯列表",
  "enablePullDownRefresh": true,
  "onReachBottomDistance": 80,
  "backgroundTextStyle": "dark"
}
```

```js
// pages/news/list.js
Page({
  data: {
    list: [],
    page: 1,
    hasMore: true,
    loading: false
  },

  onPullDownRefresh() {
    // 下拉刷新：重置页码重新拉第一页
    this.setData({ page: 1, hasMore: true })
    this.fetchList(true).finally(() => {
      // 结束下拉刷新动画，必须调用，否则菊花一直转
      wx.stopPullDownRefresh()
    })
  },

  onReachBottom() {
    // 触底：拉下一页
    if (!this.data.loading && this.data.hasMore) {
      this.fetchList(false)
    }
  },

  fetchList(reset) {
    this.setData({ loading: true })
    return new Promise((resolve) => {
      wx.request({
        url: 'https://api.example.com/news',
        data: { page: this.data.page, pageSize: 10 },
        success: (res) => {
          const rows = res.data.data.list
          const list = reset ? rows : this.data.list.concat(rows)
          this.setData({
            list,
            page: this.data.page + 1,
            hasMore: rows.length >= 10,
            loading: false
          })
          resolve()
        },
        fail: () => {
          this.setData({ loading: false })
          resolve()
        }
      })
    })
  }
})
```

```text
场景二要点：
1. enablePullDownRefresh 只对页面级滚动生效，scroll-view 需用 refresher 系列属性
2. 下拉刷新完成后必须调用 wx.stopPullDownRefresh 收起动画
3. onReachBottomDistance 单位是 px，按设计稿换算
4. 触底加载要做好 loading 与 hasMore 双重判断，防止并发重复请求
```

## 最佳实践与踩坑记录

### 最佳实践

1. 页面 json 遵循最小差异原则，只写与全局配置不同的字段，全局统一项（如导航栏主题色）放在 app.json 的 window 中管理
2. 网络请求统一在 onLoad 中发起，不要在 onReady 中发请求；onReady 只做依赖渲染完成的事情（节点查询、图表初始化）
3. 列表页「返回刷新」用 onShow + 轻量增量接口，不要在 onShow 中整页重新拉取，避免返回时列表闪动、滚动位置丢失
4. 定时器、监听器、WebSocket 连接统一在 onUnload 中清理，并用 this 上的引用保存，避免页面销毁后回调还在执行
5. setData 优先使用路径更新（'a.b'、'arr[0]'），一次合并多个字段，减少逻辑层到视图层的通信次数
6. 页面间传参只传短字符串（id、类型），复杂对象通过全局数据（app.globalData）或缓存传递
7. 自定义导航栏页面把状态栏高度、胶囊位置的计算封装成公共工具函数，所有 custom 页面复用
8. 页面栈相关跳转用统一封装的路由工具（封装 wx.navigateTo 的 url 拼接、参数编码、失败回调），方便统一埋点与异常上报

### 踩坑记录

坑 1：onShow 中整页重新请求，返回时列表闪动且滚动位置丢失
结论：从详情页返回列表页，列表被重新渲染，滚动位置回到顶部。
原因：onShow 每次显示都触发，整页重新拉取并 setData 导致视图整体重建。
解法：onShow 只做轻量增量刷新（如收藏状态），或记录 scrollTop 在 setData 后恢复滚动位置。

坑 2：navigateTo 连续跳转超过 10 层后页面不再跳转
结论：跳转第 11 个页面时静默失败，无任何报错提示。
原因：微信规定页面栈最多 10 层，超出后 navigateTo 直接失效。
解法：深层流程改用 redirectTo 替换当前页，或引导用户回首页；跳转前用 getCurrentPages().length 判断栈深。

坑 3：定时器未清理，页面销毁后回调中 setData 报错
结论：控制台报 setData:fail 或页面已销毁仍执行逻辑。
原因：onUnload 未 clearInterval/clearTimeout，定时器回调在页面销毁后继续执行。
解法：在 onUnload 中统一清理 this 上挂载的定时器与监听；回调内用 getCurrentPages 判断页面是否还存在。

坑 4：下拉刷新不生效
结论：页面 json 配置了 enablePullDownRefresh: true，但真机下拉没有反应。
原因：配置写错位置（写进了 app.json 的 window 之外）、页面内容不满一屏时下拉手势未触发，或禁用了页面滚动（disableScroll: true）。
解法：确认配置在页面 json 顶层且与 onPullDownRefresh 回调配套；检查 disableScroll 是否为 true；内容不满屏时给容器加 min-height。

坑 5：onLoad(options) 中直接使用参数导致解码问题
结论：参数包含中文或特殊字符时显示乱码或报错。
原因：url 参数在跳转时未编码，或接收时误以为框架未解码。
解法：跳转时用 encodeURIComponent 编码，onLoad 中拿到的 options 已自动 decode，直接使用即可；对象参数 JSON.stringify + encodeURIComponent 后传递。

坑 6：onReady 里拿不到节点
结论：wx.createSelectorQuery 在 onReady 中查询返回 null。
原因：onReady 表示初次渲染完成，但部分异步渲染内容或组件尚未就绪。
解法：查询包在 wx.nextTick 或 setTimeout 中执行；动态渲染的内容等数据 setData 回调后再查询。

坑 7：disableScroll 与下拉刷新、触底加载冲突
结论：设置 disableScroll: true 后 onPullDownRefresh 与 onReachBottom 都不触发。
原因：页面整体禁止滚动后，下拉手势与触底事件都没有载体。
解法：弹层类页面需要禁用滚动时，用 catchtouchmove 阻止冒泡代替 disableScroll，保留页面滚动能力；确需禁用时接受刷新功能不可用。

坑 8：switchTab 无法携带参数
结论：switchTab 跳转 tabBar 页面后，目标页 onLoad 收不到参数。
原因：微信规定 switchTab 的 url 不能带 query 参数。
解法：tabBar 页面间传参用 app.globalData、缓存或页面栈实例（getCurrentPages）方式传递。

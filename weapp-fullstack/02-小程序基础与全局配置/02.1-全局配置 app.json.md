## 概述

app.json 是小程序的全局配置文件，位于项目根目录，定义整个小程序的「骨架与默认行为」：哪些页面存在、首页是哪个、导航栏长什么样、底部 tabBar 如何组织、网络超时多久、隐私接口如何声明。微信开发者工具在编译时强制读取 app.json，配置缺失或格式错误会直接导致编译失败，因此它是小程序工程里最先被解析、也最容易踩坑的文件。

本篇章按配置项逐组讲解：pages（页面注册）、window（窗口表现）、tabBar（底部导航）、networkTimeout（网络超时）、permission 与 requiredPrivateInfos（隐私接口声明），以及 sitemapLocation、style、lazyCodeLoading、subpackages 等其他全局配置项。掌握 app.json，就等于掌握了小程序「全局视角」的开关面板；页面级 json 的覆盖规则在 02.2 中继续展开。

```text
app.json 的核心要点：
1. 强制必读 —— 编译时强制解析，语法错误直接编译失败
2. pages 必填 —— 所有页面必须注册，第一项是首页
3. window 全局默认 —— 定义导航栏与背景，可被页面 json 覆盖
4. tabBar 导航骨架 —— 2-5 个底部导航项，图标有严格限制
5. 隐私声明 —— permission 与 requiredPrivateInfos 是定位等接口的通行证
6. 修改需重新编译 —— 修改 app.json 后必须重新编译才生效
```

## pages 页面注册

pages 是 app.json 中唯一必填的配置项，值为字符串数组，每一项是页面路径（相对项目根目录，不带 .json 后缀）。数组第一项是小程序的首页（启动时默认打开）；数组顺序同时决定页面在开发者工具「编译模式」列表与页面栈中的默认顺序。新增页面后必须在此注册，否则编译警告、路由跳转报「page not found」。

页面路径的规则：以 pages/ 开头、目录名与页面四件套同名。例如页面文件位于 pages/index/index.js，注册路径就是 "pages/index/index"。路径不需要写文件扩展名，工具会自动匹配同目录下的四个文件。删掉一个页面时，也要同步从 pages 数组移除，否则编译报「找不到文件」类错误。页面数量较多时建议按业务模块规划子目录（如 pages/goods/detail），与分包配置（subpackages）配合。

```json
{
  "pages": [
    "pages/home/home",
    "pages/goods/list",
    "pages/goods/detail",
    "pages/cart/cart",
    "pages/mine/mine"
  ]
}
```

```text
pages 配置要点：
1. 必填项 —— 小程序必须有页面，pages 数组不能为空
2. 第一项即首页 —— 启动默认打开数组第一个页面
3. 路径不带后缀 —— 注册 "pages/index/index" 而非 "pages/index/index.js"
4. 新增必须注册 —— 否则编译警告、跳转报 page not found
5. 删除同步移除 —— 页面文件删除后要同步清理注册项
6. 目录分层 —— 按业务模块组织子目录，配合分包更清晰
```

## window 窗口配置

window 定义小程序的窗口表现，是整个小程序导航栏与页面背景的「默认值」。高频字段：navigationBarBackgroundColor（导航栏背景色，#rrggbb 格式）、navigationBarTitleText（导航栏标题文字）、navigationBarTextStyle（导航栏标题颜色，仅支持 black / white 两值）、backgroundColor（窗口背景色）、backgroundTextStyle（下拉 loading 的样式，dark / light）、enablePullDownRefresh（是否开启全局下拉刷新，默认 false）、onReachBottomDistance（触底加载阈值，单位 px，默认 50）、navigationStyle（导航栏样式，default 默认 / custom 自定义，custom 时需自己处理状态栏高度）。

两个容易被忽略的字段：backgroundColorTop 与 backgroundColorBottom（窗口顶部与底部背景色，仅 iOS 生效）；pageOrientation（页面横竖屏方向，portrait 竖屏 / landscape 横屏 / auto 自动旋转）。window 是全局默认值，任意页面可以通过页面自己的 json 配置同名属性覆盖——这是「全局配置 + 局部覆盖」的典型设计，页面级配置的细节在 02.2 讲解。

```json
{
  "window": {
    "navigationBarBackgroundColor": "#07c160",
    "navigationBarTitleText": "微信小程序",
    "navigationBarTextStyle": "white",
    "backgroundColor": "#f5f5f5",
    "backgroundTextStyle": "dark",
    "enablePullDownRefresh": true,
    "onReachBottomDistance": 80,
    "navigationStyle": "default",
    "pageOrientation": "portrait"
  }
}
```

```text
window 配置要点：
1. 导航栏三件套 —— 背景色 / 标题 / 文字颜色（black 或 white）
2. 下拉刷新 —— enablePullDownRefresh 全局开关，配合 onPullDownRefresh 生命周期
3. 触底加载 —— onReachBottomDistance 控制触底阈值，配合 onReachBottom
4. 自定义导航栏 —— navigationStyle 为 custom 时状态栏需自行适配
5. 仅 iOS 生效 —— backgroundColorTop / Bottom 只在 iOS 上生效
6. 页面可覆盖 —— 页面 json 的同名属性优先级高于全局 window
```

## tabBar 配置

tabBar 定义小程序底部的导航栏，适合「首页 / 列表 / 我的」这类平级核心模块。list 是核心字段，要求 2-5 项（最少 2 项、最多 5 项），每项包含：pagePath（页面路径，必须是已注册页面）、text（文字）、iconPath（未选中图标）、selectedIconPath（选中图标）。图标限制严格：仅支持本地图片路径（png/jpg，不支持网络图片与字体图标）、大小不超过 40kb、建议尺寸 81px × 81px。

tabBar 的样式字段：color（未选中文字颜色）、selectedColor（选中文字颜色）、backgroundColor（背景色）、borderStyle（上边框样式，black / white）、position（位置，bottom 底部 / top 顶部，top 时不显示图标）、custom（是否自定义 tabBar，true 时需配套自定义组件，基础库 2.5.0+ 支持）。tabBar 页面之间的跳转必须使用 wx.switchTab，wx.navigateTo 跳 tabBar 页面会失败；tabBar 页面启动不携带参数。习惯上把首页放在 list 第一项。

```json
{
  "tabBar": {
    "color": "#999999",
    "selectedColor": "#07c160",
    "backgroundColor": "#ffffff",
    "borderStyle": "black",
    "list": [
      {
        "pagePath": "pages/home/home",
        "text": "首页",
        "iconPath": "images/tab-home.png",
        "selectedIconPath": "images/tab-home-active.png"
      },
      {
        "pagePath": "pages/mine/mine",
        "text": "我的",
        "iconPath": "images/tab-mine.png",
        "selectedIconPath": "images/tab-mine-active.png"
      }
    ]
  }
}
```

```js
// tabBar 页面必须用 wx.switchTab 跳转（不能携带参数）
Page({
  goToMine() {
    wx.switchTab({
      url: '/pages/mine/mine'
    })
  }
})
```

```text
tabBar 配置要点：
1. list 数量 —— 最少 2 项，最多 5 项，超出编译报错
2. 图标限制 —— 本地 png、40kb 以内、建议 81px × 81px
3. 图标双份 —— 未选中与选中各一张，选中态才有视觉反馈
4. 跳转方式 —— tabBar 页面必须 wx.switchTab，不能 navigateTo 也不能带参
5. position —— 顶部 tabBar 不显示图标，只有文字
6. custom —— 自定义 tabBar 需配套组件，普通项目用默认即可
```

## networkTimeout 网络超时

networkTimeout 配置各类网络请求的默认超时时间，单位毫秒。四个子字段：request（wx.request 超时，默认 60000）、connectSocket（wx.connectSocket 超时，默认 60000）、uploadFile（wx.uploadFile 超时，默认 60000）、downloadFile（wx.downloadFile 超时，默认 60000）。合理设置超时能显著改善用户体验：默认 60 秒对弱网场景太长，接口联调阶段建议调短以便快速暴露问题。

超时时间不是越大越好：设置过短，弱网下正常请求被误杀；设置过长，接口挂死时用户等待过久且没有反馈。经验值是 request 在 10000-15000ms 之间，上传下载按业务体量放宽。注意两个细节：networkTimeout 是全局默认值，wx.request 调用时可以通过 timeout 参数为单个请求单独设置（基础库 2.10.0+ 支持），单请求配置优先级更高；超时触发后走 fail 回调，errMsg 形如 request:fail timeout，需要在 fail 分支给用户明确提示。

```json
{
  "networkTimeout": {
    "request": 15000,
    "connectSocket": 15000,
    "uploadFile": 30000,
    "downloadFile": 30000
  }
}
```

```js
// 单请求覆盖全局超时：上传场景单独放宽
Page({
  uploadImage() {
    wx.uploadFile({
      url: 'https://api.example.com/upload',
      filePath: 'wxfile://tmp_xxx.jpg',
      name: 'file',
      timeout: 60000, // 覆盖全局 networkTimeout.uploadFile
      success: (res) => {
        console.log('上传成功：', res.data)
      },
      fail: (err) => {
        // 超时时 err.errMsg 形如 uploadFile:fail timeout
        console.error('上传失败：', err.errMsg)
      }
    })
  }
})
```

```text
networkTimeout 要点：
1. 单位毫秒 —— 四个子字段默认均为 60000
2. 覆盖范围 —— request / connectSocket / uploadFile / downloadFile
3. 单请求覆盖 —— wx.request 的 timeout 参数优先级高于全局配置
4. 超时走 fail —— 触发后进入 fail 回调，errMsg 含 timeout
5. 经验值 —— request 建议 10-15 秒，上传下载按业务放宽
6. 用户提示 —— 超时分支必须给用户明确反馈，不能静默失败
```

## permission 与 requiredPrivateInfos

从基础库 2.32.3 起，涉及用户隐私的接口（如定位、相册、录音）必须在 app.json 中显式声明，否则调用直接失败。声明分两层：permission 描述接口用途（desc 字段必填，会展示在授权弹窗中，用户可见），requiredPrivateInfos 列出实际使用的隐私接口名。典型的 permission 声明是定位：scope.userLocation 的 desc 必须填写使用位置的具体原因（如「用于展示附近门店」），文案不清晰会被审核驳回。

常见权限 scope：scope.userLocation（精确位置）、scope.userFuzzyLocation（模糊位置，基础库 2.25.0+）、scope.userLocationBackground（后台定位）、scope.address（收货地址）、scope.record（录音）、scope.camera（摄像头）、scope.writePhotosAlbum（保存到相册）。requiredPrivateInfos 常见取值：getLocation、chooseLocation、onLocationChange、startLocationUpdate、startLocationUpdateBackground、chooseAddress、choosePoi。除了前端声明，还需在 mp 后台「设置 → 服务内容声明 → 用户隐私保护指引」中同步配置隐私协议，并配合 wx.requirePrivacyAuthorize 处理授权流程，前后端一致才能过审。

```json
{
  "permission": {
    "scope.userLocation": {
      "desc": "你的位置信息将用于展示附近的门店"
    },
    "scope.userFuzzyLocation": {
      "desc": "你的大致位置将用于推荐周边服务"
    },
    "scope.record": {
      "desc": "你的录音将用于语音搜索"
    }
  },
  "requiredPrivateInfos": [
    "getLocation",
    "chooseLocation",
    "onLocationChange",
    "startLocationUpdate"
  ]
}
```

```js
// 声明完成后，代码中调用定位接口
Page({
  getLocation() {
    wx.getLocation({
      type: 'gcj02',
      success: (res) => {
        console.log('纬度：', res.latitude, '经度：', res.longitude)
      },
      fail: (err) => {
        // 未声明 requiredPrivateInfos 时，这里报：
        // getLocation:fail the api need to be declared in the requiredPrivateInfos field in app.json
        console.error('定位失败：', err.errMsg)
      }
    })
  }
})
```

```text
permission 与 requiredPrivateInfos 要点：
1. 声明前置 —— 隐私接口不声明直接调用失败，报错信息指向 app.json
2. desc 必填 —— 授权弹窗展示的用途说明，文案要真实具体
3. 两层声明 —— permission 管用途描述，requiredPrivateInfos 管接口名单
4. 后台配套 —— mp 后台需同步配置「用户隐私保护指引」
5. 常见 scope —— 定位/模糊定位/后台定位/地址/录音/相机/相册
6. 授权时机 —— 首次调用时弹窗，用户拒绝后需引导到设置页（08.4 界面交互）
```

## 其他全局配置项

除上述核心配置外，app.json 还有一批高频辅助配置。sitemapLocation 指定 sitemap 索引文件位置（默认 "sitemap.json"，详见 02.3）；style 置为 "v2" 启用新版组件样式（button 等组件外观与旧版差异明显，升级时注意回归）；lazyCodeLoading 置为 "requiredComponents" 启用按需注入（按需注入组件与代码，减小首包，基础库 2.11.1+ 支持）；entryPagePath 可指定与 pages 第一项不同的启动页；darkmode 与 themeLocation 配合实现暗黑模式（主题变量文件 theme.json，详见 04.5）。

工程化相关配置：subpackages（分包，root 分包根目录、pages 分包页面、independent 独立分包，主包限制 2MB、整体上限详见 13.1 分包加载）；preloadRule（分包预下载规则，network 指定网络条件 all/wifi）；workers（Worker 线程代码目录）；usingComponents（全局自定义组件注册，页面无需重复注册）；requiredBackgroundModes（后台能力声明，audio 后台播放 / location 后台定位）；plugins（使用插件声明）；functionalPages（启用插件功能页）。这些配置按需启用，多数项目日常只用到 sitemapLocation 与 style。

```json
{
  "sitemapLocation": "sitemap.json",
  "style": "v2",
  "lazyCodeLoading": "requiredComponents",
  "entryPagePath": "pages/home/home",
  "usingComponents": {
    "nav-bar": "/components/nav-bar/nav-bar"
  },
  "subpackages": [
    {
      "root": "packageGoods",
      "pages": [
        "pages/goods/detail",
        "pages/goods/comment"
      ]
    }
  ],
  "preloadRule": {
    "pages/home/home": {
      "network": "all",
      "packages": ["packageGoods"]
    }
  },
  "workers": "workers"
}
```

```text
其他全局配置项要点：
1. sitemapLocation —— 索引文件位置，默认 sitemap.json
2. style v2 —— 新版组件样式，升级后 button 等组件外观变化
3. lazyCodeLoading —— 按需注入，减小首包，需基础库 2.11.1+
4. subpackages —— 分包配置，主包 2MB 限制的工程化解法（详见 13.1）
5. preloadRule —— 分包预下载，进入某页面前提前加载分包
6. darkmode —— 暗黑模式开关，配合 theme.json 主题变量
```

```json
{
  "pages": [
    "pages/home/home",
    "pages/cart/cart",
    "pages/mine/mine",
    "pages/goods/list",
    "pages/goods/detail"
  ],
  "window": {
    "navigationBarBackgroundColor": "#ffffff",
    "navigationBarTitleText": "电商小程序",
    "navigationBarTextStyle": "black",
    "backgroundColor": "#f5f5f5",
    "backgroundTextStyle": "dark"
  },
  "tabBar": {
    "color": "#999999",
    "selectedColor": "#e93b3d",
    "backgroundColor": "#ffffff",
    "borderStyle": "black",
    "list": [
      {
        "pagePath": "pages/home/home",
        "text": "首页",
        "iconPath": "images/tab-home.png",
        "selectedIconPath": "images/tab-home-active.png"
      },
      {
        "pagePath": "pages/cart/cart",
        "text": "购物车",
        "iconPath": "images/tab-cart.png",
        "selectedIconPath": "images/tab-cart-active.png"
      },
      {
        "pagePath": "pages/mine/mine",
        "text": "我的",
        "iconPath": "images/tab-mine.png",
        "selectedIconPath": "images/tab-mine-active.png"
      }
    ]
  },
  "networkTimeout": {
    "request": 15000,
    "uploadFile": 30000
  },
  "style": "v2",
  "lazyCodeLoading": "requiredComponents",
  "sitemapLocation": "sitemap.json"
}
```

```text
落地步骤：
1. 在 pages/ 下创建 5 个页面目录，各建四件套
2. 商品列表与详情是二级页面，不进 tabBar，用 wx.navigateTo 跳转
3. tabBar 图标在 images/ 下放 6 张 png（3 组未选中/选中），控制在 40kb 内
4. 首页在 pages 数组第一位，与 tabBar 第一项一致
5. 编译后模拟器点击 tab 切换三个模块，再从首页跳转商品列表验证 navigateTo
6. 用 Network 面板验证接口请求，超时配置生效
```

### 场景二：配置一个带定位能力的小程序

需要「展示附近门店」的小程序，配置隐私声明与自定义导航栏：

```json
{
  "pages": [
    "pages/index/index",
    "pages/store/detail"
  ],
  "window": {
    "navigationStyle": "custom",
    "backgroundColor": "#f5f5f5"
  },
  "permission": {
    "scope.userLocation": {
      "desc": "你的位置信息将用于展示附近的门店"
    }
  },
  "requiredPrivateInfos": [
    "getLocation",
    "chooseLocation"
  ],
  "style": "v2",
  "lazyCodeLoading": "requiredComponents",
  "sitemapLocation": "sitemap.json"
}
```

```text
落地步骤：
1. navigationStyle 为 custom 时，页面需要自绘导航栏（用组件库 nav-bar 或自定义组件）
2. 在 mp 后台「服务内容声明 → 用户隐私保护指引」中声明收集位置信息及用途
3. 页面中调用 wx.getLocation 前先 wx.getSetting 检查授权状态，未授权则引导授权
4. 用户拒绝授权时，用 wx.showModal 引导到 wx.openSetting 设置页开启
5. 真机预览验证定位：模拟器中的定位是模拟数据，真机才是真实位置
6. 审核前确认 desc 文案与隐私指引文案一致，避免审核驳回
```

## 最佳实践与踩坑记录

### 最佳实践

1. pages 数组顺序即默认页面栈顺序，把最常访问的页面放在前面，首页固定第一位
2. tabBar 图标提前用脚本或设计稿批量导出 81px × 81px 的 png，并检查单张不超过 40kb
3. 全局 window 只配置「所有页面一致」的属性（背景色、文字颜色），页面差异化配置放页面 json
4. 接口超时设置成与后台网关超时匹配（后台 10 秒，前端 15 秒），避免前端先超时导致误判
5. 隐私相关接口的 desc 文案写真实用途，并与 mp 后台的隐私保护指引保持一致，降低审核驳回率
6. 新项目直接启用 style: "v2" 与 lazyCodeLoading: "requiredComponents"，避免旧项目升级时的样式回归
7. 修改 app.json 后养成「重新编译」的习惯，配置变更不会通过热重载即时生效
8. 页面数量超过 20 个或主包接近 2MB 时，提前规划 subpackages 分包，避免后期重构

### 踩坑记录

坑 1：页面没注册，跳转报 page not found
结论：点击跳转提示「page not found」或「pages/xxx/xxx 未找到」。
原因：目标页面没有注册进 app.json 的 pages 数组。
解法：新增页面时同步注册；跳转路径与注册路径必须完全一致（含大小写）。

坑 2：tabBar list 项数不合规，编译报错
结论：编译报「tabBar.list 长度必须大于等于 2 且小于等于 5」。
原因：tabBar 只配置了 1 项，或超过了 5 项。
解法：调整 list 到 2-5 项；少于 2 个平级模块时直接用普通页面跳转，不需要 tabBar。

坑 3：tabBar 页面用 wx.navigateTo 跳转失败
结论：navigateTo 到 tabBar 页面提示「can not navigateTo a tabbar page」。
原因：tabBar 页面只能用 wx.switchTab 切换，navigateTo/redirectTo 均不可用。
解法：跳 tabBar 页面统一用 wx.switchTab；注意 switchTab 不支持携带参数，参数可用全局变量或缓存传递。

坑 4：tabBar 图标不显示
结论：tabBar 文字正常，图标空白或整页样式异常。
原因：iconPath 超过 40kb、尺寸比例异常、使用了网络图片或字体图标。
解法：图标改为本地 png 并控制在 40kb 内；重新导出 81px × 81px 资源；确认路径相对项目根目录正确。

坑 5：navigationBarTextStyle 设置其他值不生效
结论：导航栏标题颜色想设置成灰色等，样式无变化。
原因：navigationBarTextStyle 仅支持 black 与 white 两个枚举值，其他值被忽略。
解法：只能二选一；想要自定义颜色需将 navigationStyle 设为 custom 自绘导航栏。

坑 6：定位接口直接 fail，报 requiredPrivateInfos
结论：wx.getLocation 调用即失败，报「the api need to be declared in the requiredPrivateInfos field in app.json」。
原因：基础库 2.32.3 起隐私接口必须声明，app.json 中未配置 requiredPrivateInfos。
解法：在 app.json 声明所需接口；同步在 mp 后台配置用户隐私保护指引；确认线上基础库版本达标。

坑 7：permission 的 desc 缺失导致授权弹窗异常或审核被拒
结论：授权弹窗不出现，或提审时被驳回要求补充用途说明。
原因：permission 中声明的 scope 未写 desc，或 desc 文案含糊（如「用于业务需要」）。
解法：desc 必须具体描述真实用途（如「用于展示附近门店」），与隐私指引文案一致。

坑 8：修改 app.json 后热重载不生效
结论：改了 window 或 tabBar 配置，模拟器表现没变化。
原因：app.json 属于全局配置，热重载不会重新解析，需要重新编译。
解法：修改 app.json 后点击「编译」；仍不生效则清缓存后重新编译。

坑 9：启用 style v2 后按钮等组件样式突变
结论：升级 style v2 或新项目创建后，button 等组件外观与旧项目明显不同。
原因：style v2 启用了新版组件样式，组件默认外观有调整。
解法：确认团队样式基准后统一启用；旧项目升级前先回归公共组件与表单页。

坑 10：分包配置错误导致主包超限或页面不可达
结论：分包页面跳转报错，或上传时提示主包超过 2MB。
原因：分包路径写错（root 与实际目录不符）、tabBar 页面放进了分包（不允许）、主包页面过多。
解法：tabBar 页面必须留在主包；分包 root 与目录一致；上传前查看包体积报告（详见 13.1）。

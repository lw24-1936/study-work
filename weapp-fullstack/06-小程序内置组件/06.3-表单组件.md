## 概述

表单组件是页面与用户交互输入的核心，涵盖按钮、单行输入、多行输入、单选、多选、开关、滑块与各类选择器。它们承担两种职责：一是收集用户输入，二是通过 form 组件统一提交。理解表单组件的关键是 name 属性——只有设置了 name 的表单控件才会被 form 收集进 e.detail.value。此外 button 的 open-type 还承担了微信开放能力入口（联系客服、分享、获取手机号、选择头像等）的职责。

```text
表单组件一览：
1. button —— 按钮，size/type/plain/disabled/loading，form-type 与 open-type
2. input —— 单行输入框，type/placeholder/password/maxlength/confirm-type
3. textarea —— 多行输入框，auto-height/maxlength/cursor
4. checkbox/radio/switch/slider —— 选择与开关类组件
5. picker/picker-view —— 选择器：selector/multiSelector/time/date/region
6. 表单提交 —— form 组件 bindsubmit 收集 name 控件，JS 层做验证
```

## button 按钮组件

button 是使用频率最高的表单组件，尺寸（size: default/mini）、样式（type: primary/default/warn）、形态（plain 镂空）与状态（disabled、loading）覆盖了绝大多数按钮需求。它的特殊性在于两个属性：form-type 让按钮直接提交/重置所在 form；open-type 把按钮变成微信开放能力入口，可触发联系客服、分享、获取手机号、选择头像等原生能力。需要注意 2021 年隐私政策调整后，getUserInfo 不再弹授权框，昵称头像获取应改用 chooseAvatar 与 input type="nickname" 的组合。

```wxml
<!-- pages/button-demo/button-demo.wxml -->
<view class="btn-section">
  <!-- 基础样式 -->
  <button type="primary" size="default">主要按钮</button>
  <button type="default">次要按钮</button>
  <button type="warn">警告按钮</button>
  <button plain="true" type="primary">镂空按钮</button>
  <button size="mini" type="primary">小尺寸</button>
  <button disabled="true">禁用状态</button>
  <button loading="{{submitting}}" type="primary" disabled="{{submitting}}">
    {{submitting ? '提交中...' : '提交订单'}}
  </button>
</view>

<view class="btn-section">
  <!-- open-type：开放能力入口 -->
  <button open-type="contact">联系客服</button>
  <button open-type="share">转发分享</button>
  <button open-type="openSetting">打开设置页</button>
  <!-- 头像昵称填写能力：企业/个人均可使用，合规获取头像昵称 -->
  <button open-type="chooseAvatar" bindchooseavatar="onChooseAvatar">选择头像</button>
  <!-- 获取手机号：需企业主体且认证，绑定手机号验证回调 -->
  <button open-type="getPhoneNumber" bindgetphonenumber="onGetPhoneNumber">获取手机号</button>
</view>
```

```js
// pages/button-demo/button-demo.js
Page({
  data: { submitting: false },

  // open-type="chooseAvatar" 的回调：e.detail.avatarUrl 为临时文件路径
  onChooseAvatar(e) {
    const avatarUrl = e.detail.avatarUrl
    // 真实项目：wx.uploadFile 上传头像到后台，再回填显示
    this.setData({ avatarUrl })
  },

  // open-type="getPhoneNumber" 的回调：企业主体 + 已认证才返回 code
  onGetPhoneNumber(e) {
    // e.detail.code 为动态令牌，需发给后台换取手机号
    if (e.detail.code) {
      wx.request({
        url: 'https://api.example.com/login/phone',
        method: 'POST',
        data: { code: e.detail.code },
        success: (res) => {
          wx.showToast({ title: '手机号已获取', icon: 'success' })
        }
      })
    } else {
      wx.showToast({ title: '用户取消授权', icon: 'none' })
    }
  }
})
```

```text
button 组件要点：
1. size/type —— size 取 default/mini；type 取 primary/default/warn
2. plain/disabled/loading —— 镂空、禁用与加载中三态，loading 时可配 loading-text
3. form-type —— submit 提交所在 form，reset 重置；需配合 form 组件使用
4. open-type —— contact/share/getUserInfo/getPhoneNumber/chooseAvatar/openSetting 等
5. 政策注意 —— 2021 年起 getUserInfo 返回灰色默认头像昵称，改用 chooseAvatar + nickname 输入框
6. hover-class —— 默认 button-hover，可自定义按压态样式
```

## input 与 textarea 输入组件

input 是单行输入框，textarea 是多行输入框，两者共用大量属性（value、placeholder、maxlength、disabled、focus）。input 的 type 决定键盘类型（text/number/idcard/digit/safe-password/nickname），confirm-type 控制键盘右下角按钮文案（send/search/next/go/done）并由 bindconfirm 监听确认动作；textarea 则多了 auto-height 自动增高与 cursor 光标定位能力。两个组件都是原生组件，交互手感贴近系统输入，但需要注意键盘遮挡与滚动时的渲染问题。

```wxml
<!-- pages/input-demo/input-demo.wxml -->
<view class="form-card">
  <!-- 单行输入：手机号键盘 + 完成按钮 -->
  <view class="field">
    <text class="field-label">手机号</text>
    <input
      class="field-input"
      type="number"
      maxlength="11"
      placeholder="请输入手机号"
      placeholder-class="placeholder"
      value="{{phone}}"
      bindinput="onPhoneInput"
      bindblur="onPhoneBlur"
    />
  </view>

  <!-- 密码输入 -->
  <view class="field">
    <text class="field-label">密码</text>
    <input
      class="field-input"
      password="true"
      placeholder="请输入 6-20 位密码"
      maxlength="20"
      value="{{password}}"
      bindinput="onPasswordInput"
    />
  </view>

  <!-- 昵称输入：type="nickname" 支持键盘快捷填写微信昵称 -->
  <view class="field">
    <text class="field-label">昵称</text>
    <input
      class="field-input"
      type="nickname"
      placeholder="请输入昵称"
      value="{{nickname}}"
      bindinput="onNicknameInput"
    />
  </view>

  <!-- 搜索框：confirm-type="search" -->
  <view class="field">
    <input
      class="search-input"
      placeholder="搜索商品"
      confirm-type="search"
      confirm-hold="true"
      bindconfirm="onSearch"
    />
  </view>

  <!-- 多行输入：auto-height 自动增高，maxlength 限制字数 -->
  <view class="field">
    <text class="field-label">商品描述</text>
    <textarea
      class="field-textarea"
      placeholder="请输入商品描述（最多 200 字）"
      maxlength="200"
      auto-height="true"
      value="{{desc}}"
      bindinput="onDescInput"
      show-confirm-bar="false"
    />
    <text class="counter">{{desc.length}}/200</text>
  </view>
</view>
```

```js
// pages/input-demo/input-demo.js
Page({
  data: {
    phone: '',
    password: '',
    nickname: '',
    desc: ''
  },

  onPhoneInput(e) {
    // 只保留数字，防止 number 键盘在 iOS 上仍能输入其他字符
    const phone = e.detail.value.replace(/\D/g, '')
    this.setData({ phone })
  },

  onPhoneBlur() {
    if (this.data.phone.length !== 11) {
      wx.showToast({ title: '手机号格式不正确', icon: 'none' })
    }
  },

  onPasswordInput(e) {
    this.setData({ password: e.detail.value })
  },

  onNicknameInput(e) {
    this.setData({ nickname: e.detail.value })
  },

  onDescInput(e) {
    this.setData({ desc: e.detail.value })
  },

  onSearch() {
    wx.showToast({ title: '搜索：' + this.data.keyword, icon: 'none' })
  }
})
```

```text
input/textarea 要点：
1. input type —— text/number/idcard/digit/safe-password/nickname，决定键盘形态
2. confirm-type —— send/search/next/go/done，控制键盘右下角按钮；bindconfirm 监听
3. password —— 密文输入；maxlength 限制长度，-1 表示不限制
4. textarea —— auto-height 随内容增高，maxlength 默认 140，cursor 控制光标位置
5. 事件 —— bindinput 实时输入、bindblur 失焦、bindfocus 聚焦，e.detail.value 取值
6. 原生组件 —— 键盘遮挡用 cursor-spacing 与 adjust-position；滚动时注意渲染问题
```

## checkbox、radio、switch 与 slider 选择类组件

四个选择类组件分别解决多选、单选、开关与区间取值。checkbox 必须包在 checkbox-group 里才能被 form 收集，group 的 bindchange 一次性返回所有选中值数组；radio 同理包在 radio-group 中，bindchange 返回当前选中值；switch 用 checked 控制开合，bindchange 返回布尔值；slider 用 min/max/step 定义取值范围，bindchanging 在拖动中高频触发、bindchange 在松手后触发一次。四者的 color 属性都可以自定义选中态颜色。

```wxml
<!-- pages/select-demo/select-demo.wxml -->
<view class="form-card">
  <!-- 多选：checkbox-group 收集数组 -->
  <view class="field">
    <text class="field-label">兴趣标签（可多选）</text>
    <checkbox-group bindchange="onHobbiesChange">
      <label class="option" wx:for="{{hobbyOptions}}" wx:key="value">
        <checkbox value="{{item.value}}" checked="{{item.checked}}" color="#07c160" />
        <text class="option-text">{{item.label}}</text>
      </label>
    </checkbox-group>
  </view>

  <!-- 单选：radio-group 收集单值 -->
  <view class="field">
    <text class="field-label">性别</text>
    <radio-group bindchange="onGenderChange">
      <label class="option">
        <radio value="male" color="#10aeff" />男
      </label>
      <label class="option">
        <radio value="female" color="#ff80ab" />女
      </label>
    </radio-group>
  </view>

  <!-- 开关 -->
  <view class="field row-between">
    <text class="field-label">接收消息推送</text>
    <switch checked="{{pushEnabled}}" color="#07c160" bindchange="onPushChange" />
  </view>

  <!-- 滑块：价格区间 -->
  <view class="field">
    <text class="field-label">最高价格：{{priceMax}} 元</text>
    <slider
      min="10"
      max="1000"
      step="10"
      value="{{priceMax}}"
      show-value="false"
      activeColor="#ff5000"
      backgroundColor="#eeeeee"
      block-size="24"
      bindchanging="onPriceChanging"
      bindchange="onPriceChange"
    />
  </view>
</view>
```

```js
// pages/select-demo/select-demo.js
Page({
  data: {
    hobbyOptions: [
      { label: '数码', value: 'digital', checked: false },
      { label: '运动', value: 'sport', checked: true },
      { label: '美食', value: 'food', checked: false },
      { label: '旅行', value: 'travel', checked: false }
    ],
    gender: 'male',
    pushEnabled: true,
    priceMax: 300
  },

  onHobbiesChange(e) {
    // e.detail.value 为选中值的数组
    const values = e.detail.value
    this.setData({
      hobbyOptions: this.data.hobbyOptions.map((item) => ({
        ...item,
        checked: values.indexOf(item.value) > -1
      }))
    })
  },

  onGenderChange(e) {
    this.setData({ gender: e.detail.value })
  },

  onPushChange(e) {
    // e.detail.value 为布尔值
    this.setData({ pushEnabled: e.detail.value })
  },

  onPriceChanging(e) {
    // 拖动过程中高频触发：只做轻量 setData
    this.setData({ priceMax: e.detail.value })
  },

  onPriceChange(e) {
    // 松手后触发一次：适合在这里发起筛选请求
    wx.showToast({ title: '筛选价格上限：' + e.detail.value, icon: 'none' })
  }
})
```

```text
选择类组件要点：
1. checkbox —— 需包在 checkbox-group 内，group bindchange 返回选中值数组
2. radio —— 需包在 radio-group 内，bindchange 返回单个选中值
3. switch —— checked 控制状态，bindchange 返回 e.detail.value 布尔值
4. slider —— min/max/step/value 定义区间；bindchanging 拖动中、bindchange 松手后
5. color —— 四个组件都支持自定义选中/激活颜色
6. form 收集 —— checkbox-group/radio-group/switch/slider 设 name 后可被 form 收集
```

## picker 与 picker-view 选择器组件

picker 是微信封装好的选择器：mode="selector" 单选列表（range 定义选项）、mode="multiSelector" 多列联动（range 为二维数组）、mode="time" 时间、mode="date" 日期（fields 可细化到 year/month/day）、mode="region" 省市区。picker 点击后弹出原生选择层，bindchange 返回选中结果。picker-view 则是完全自定义的滚动选择器，需要自己定义每一列的内容与高度，适合做高度定制化的选择（如自定义联动、倒计时选择）。

```wxml
<!-- pages/picker-demo/picker-demo.wxml -->
<view class="form-card">
  <!-- 单选：selector -->
  <picker
    mode="selector"
    range="{{cities}}"
    value="{{cityIndex}}"
    bindchange="onCityChange"
  >
    <view class="picker-row">
      <text class="field-label">所在城市</text>
      <text class="picker-value">{{cities[cityIndex]}} →</text>
    </view>
  </picker>

  <!-- 多列联动：multiSelector（省/市） -->
  <picker
    mode="multiSelector"
    range="{{regionList}}"
    value="{{regionIndex}}"
    bindchange="onRegionChange"
    bindcolumnchange="onColumnChange"
  >
    <view class="picker-row">
      <text class="field-label">省/市</text>
      <text class="picker-value">{{regionList[0][regionIndex[0]]}} / {{regionList[1][regionIndex[1]]}} →</text>
    </view>
  </picker>

  <!-- 日期 -->
  <picker
    mode="date"
    start="2020-01-01"
    end="2030-12-31"
    value="{{birthday}}"
    bindchange="onBirthdayChange"
  >
    <view class="picker-row">
      <text class="field-label">出生日期</text>
      <text class="picker-value">{{birthday}} →</text>
    </view>
  </picker>

  <!-- 时间 -->
  <picker mode="time" start="08:00" end="22:00" value="{{appointTime}}" bindchange="onTimeChange">
    <view class="picker-row">
      <text class="field-label">预约时间</text>
      <text class="picker-value">{{appointTime}} →</text>
    </view>
  </picker>

  <!-- 省市区 -->
  <picker mode="region" value="{{regionText}}" bindchange="onRegionPick">
    <view class="picker-row">
      <text class="field-label">收货地址</text>
      <text class="picker-value">{{regionText}} →</text>
    </view>
  </picker>
</view>
```

```js
// pages/picker-demo/picker-demo.js
Page({
  data: {
    cities: ['北京', '上海', '广州', '深圳', '杭州'],
    cityIndex: 0,
    regionList: [
      ['浙江省', '江苏省', '广东省'],
      ['杭州市', '宁波市', '温州市', '南京市', '苏州市', '广州市', '深圳市']
    ],
    regionIndex: [0, 0],
    birthday: '1995-06-18',
    appointTime: '10:30',
    regionText: ['浙江省', '杭州市', '西湖区']
  },

  onCityChange(e) {
    this.setData({ cityIndex: Number(e.detail.value) })
  },

  // multiSelector 联动：某一列变化时重置后列索引
  onColumnChange(e) {
    const { column, value } = e.detail
    const regionIndex = [...this.data.regionIndex]
    regionIndex[column] = Number(value)
    if (column === 0) regionIndex[1] = 0
    this.setData({ regionIndex })
  },

  onRegionChange(e) {
    this.setData({ regionIndex: e.detail.value })
  },

  onBirthdayChange(e) {
    this.setData({ birthday: e.detail.value })
  },

  onTimeChange(e) {
    this.setData({ appointTime: e.detail.value })
  },

  onRegionPick(e) {
    // e.detail.value 为 ['浙江省','杭州市','西湖区']
    this.setData({ regionText: e.detail.value })
  }
})
```

```text
picker/picker-view 要点：
1. selector —— range 定义选项数组，value 为选中索引，bindchange 返回索引
2. multiSelector —— range 为二维数组，bindcolumnchange 处理列联动，value 为索引数组
3. time/date —— start/end 限制范围；date 的 fields 可细化 year/month/day
4. region —— 内置省市区数据，value 为 ['省','市','区'] 数组，custom-item 可自定义
5. picker-view —— 自定义滚动列，配合 picker-view-column，indicator-style 定义选中高亮
6. 数据形态 —— 各模式返回的数据结构不同（索引/字符串/数组），提交后端前统一转换
```

## 表单提交与表单验证

小程序没有内置表单校验能力，标准做法是「form 收集 + JS 验证 + API 提交」三段式：form 组件包住所有表单项，submit 按钮（form-type="submit"）触发 bindsubmit，事件回调里 e.detail.value 就是所有设置了 name 的控件的值集合；验证逻辑写在 bindsubmit 中，逐字段检查后通过 wx.request 提交到 SpringBoot 后台。密码框、协议勾选等还需要配合 disabled 提交按钮防止未同意协议就提交。

```wxml
<!-- pages/form-demo/form-demo.wxml -->
<form bindsubmit="onSubmit" bindreset="onReset">
  <view class="form-card">
    <view class="field">
      <text class="field-label">用户名</text>
      <input name="username" placeholder="请输入用户名" maxlength="20" value="{{form.username}}" bindinput="onInput" data-key="username" />
    </view>
    <view class="field">
      <text class="field-label">手机号</text>
      <input name="phone" type="number" maxlength="11" placeholder="请输入手机号" value="{{form.phone}}" bindinput="onInput" data-key="phone" />
    </view>
    <view class="field">
      <text class="field-label">性别</text>
      <radio-group name="gender">
        <label class="option"><radio value="male" checked="{{form.gender === 'male'}}" />男</label>
        <label class="option"><radio value="female" checked="{{form.gender === 'female'}}" />女</label>
      </radio-group>
    </view>
    <view class="field">
      <text class="field-label">兴趣爱好</text>
      <checkbox-group name="hobbies">
        <label class="option"><checkbox value="coding" />编程</label>
        <label class="option"><checkbox value="reading" />阅读</label>
        <label class="option"><checkbox value="music" />音乐</label>
      </checkbox-group>
    </view>
    <view class="field row-between">
      <text class="field-label">接收通知</text>
      <switch name="notify" checked="true" />
    </view>

    <!-- 协议勾选：控制提交按钮可用性 -->
    <label class="agree-row">
      <checkbox checked="{{agreed}}" bindchange="onAgreeChange" color="#07c160" />
      <text class="agree-text">我已阅读并同意《用户协议》与《隐私政策》</text>
    </label>

    <button class="submit-btn" form-type="submit" type="primary" disabled="{{!agreed || submitting}}" loading="{{submitting}}">
      提交注册
    </button>
    <button form-type="reset" type="default">重置</button>
  </view>
</form>
```

```js
// pages/form-demo/form-demo.js
Page({
  data: {
    form: { username: '', phone: '', gender: 'male', hobbies: [], notify: true },
    agreed: false,
    submitting: false
  },

  onInput(e) {
    const key = e.currentTarget.dataset.key
    this.setData({ ['form.' + key]: e.detail.value })
  },

  onAgreeChange(e) {
    this.setData({ agreed: e.detail.value.length > 0 })
  },

  onSubmit(e) {
    // e.detail.value 收集所有带 name 的控件
    const { username, phone, gender, hobbies, notify } = e.detail.value

    // 第一步：基础验证
    if (!username || username.trim().length < 2) {
      return wx.showToast({ title: '用户名至少 2 个字符', icon: 'none' })
    }
    if (!/^1[3-9]\d{9}$/.test(phone)) {
      return wx.showToast({ title: '手机号格式不正确', icon: 'none' })
    }
    if (!this.data.agreed) {
      return wx.showToast({ title: '请先同意用户协议', icon: 'none' })
    }

    // 第二步：提交后台（SpringBoot 接口）
    this.setData({ submitting: true })
    wx.request({
      url: 'https://api.example.com/user/register',
      method: 'POST',
      data: {
        username,
        phone,
        gender,
        hobbies: Array.isArray(hobbies) ? hobbies : [],
        notify: notify || false
      },
      success: (res) => {
        if (res.data.code === 0) {
          wx.showToast({ title: '注册成功', icon: 'success' })
        } else {
          wx.showToast({ title: res.data.msg || '注册失败', icon: 'none' })
        }
      },
      complete: () => this.setData({ submitting: false })
    })
  },

  onReset() {
    this.setData({ form: { username: '', phone: '', gender: 'male', hobbies: [], notify: true } })
  }
})
```

```text
表单提交要点：
1. form 收集 —— 控件必须设置 name 才会出现在 e.detail.value 中
2. bindsubmit —— submit 按钮（form-type="submit"）触发，e.detail.value 为收集结果
3. 验证分层 —— 格式校验在前端（正则、长度），业务校验（重复注册、库存）在后端
4. 提交态 —— submitting + disabled 双控，防止重复提交；loading 展示反馈
5. 协议勾选 —— 用 checkbox 控制提交按钮 disabled，合规必选项
6. 数据转换 —— checkbox-group 返回数组、switch 返回布尔、picker 返回索引/字符串，提交前统一
```

### 场景一：用户注册页（手机号验证码 + 密码 + 协议）

一个完整的注册表单：手机号、图形验证码倒计时、密码、协议勾选与提交。验证码按钮通过 setInterval 倒计时并在页面卸载时清理。

```wxml
<!-- pages/register/register.wxml -->
<form bindsubmit="onSubmit">
  <view class="register-card">
    <view class="field">
      <text class="field-label">手机号</text>
      <input name="phone" type="number" maxlength="11" placeholder="请输入手机号" value="{{phone}}" bindinput="onPhoneInput" />
    </view>
    <view class="field">
      <text class="field-label">验证码</text>
      <input name="code" type="number" maxlength="6" placeholder="6 位验证码" />
      <button class="code-btn" size="mini" type="primary" plain="{{countdown > 0}}" disabled="{{countdown > 0}}" bindtap="onSendCode">
        {{countdown > 0 ? countdown + 's 后重发' : '获取验证码'}}
      </button>
    </view>
    <view class="field">
      <text class="field-label">设置密码</text>
      <input name="password" password="true" maxlength="20" placeholder="6-20 位，含字母与数字" />
    </view>
    <label class="agree-row">
      <checkbox checked="{{agreed}}" bindchange="onAgreeChange" color="#07c160" />
      <text class="agree-text">我已阅读并同意《用户协议》</text>
    </label>
    <button class="submit-btn" form-type="submit" type="primary" disabled="{{!agreed || submitting}}" loading="{{submitting}}">
      {{submitting ? '注册中...' : '注册'}}
    </button>
  </view>
</form>
```

```js
// pages/register/register.js
Page({
  data: { phone: '', agreed: false, countdown: 0, submitting: false },

  onPhoneInput(e) {
    this.setData({ phone: e.detail.value.replace(/\D/g, '') })
  },

  onAgreeChange(e) {
    this.setData({ agreed: e.detail.value.length > 0 })
  },

  onSendCode() {
    if (this.data.countdown > 0) return
    if (!/^1[3-9]\d{9}$/.test(this.data.phone)) {
      return wx.showToast({ title: '请先输入正确手机号', icon: 'none' })
    }
    // 真实项目：wx.request 请求后台发送短信验证码
    wx.showToast({ title: '验证码已发送', icon: 'success' })
    this.setData({ countdown: 60 })
    this.timer = setInterval(() => {
      if (this.data.countdown <= 1) {
        clearInterval(this.timer)
        this.setData({ countdown: 0 })
        return
      }
      this.setData({ countdown: this.data.countdown - 1 })
    }, 1000)
  },

  onSubmit(e) {
    const { phone, code, password } = e.detail.value
    if (!/^1[3-9]\d{9}$/.test(phone)) return wx.showToast({ title: '手机号不正确', icon: 'none' })
    if (!/^\d{6}$/.test(code)) return wx.showToast({ title: '验证码为 6 位数字', icon: 'none' })
    if (!/^(?=.*[A-Za-z])(?=.*\d)[\S]{6,20}$/.test(password)) {
      return wx.showToast({ title: '密码需 6-20 位且含字母和数字', icon: 'none' })
    }
    this.setData({ submitting: true })
    wx.request({
      url: 'https://api.example.com/user/register',
      method: 'POST',
      data: { phone, code, password },
      success: (res) => {
        if (res.data.code === 0) {
          wx.showToast({ title: '注册成功', icon: 'success' })
          setTimeout(() => wx.navigateBack(), 1500)
        } else {
          wx.showToast({ title: res.data.msg || '注册失败', icon: 'none' })
        }
      },
      complete: () => this.setData({ submitting: false })
    })
  },

  onUnload() {
    if (this.timer) clearInterval(this.timer)
  }
})
```

```js
// pages/profile-edit/profile-edit.js
Page({
  data: {
    avatarUrl: '',
    defaultAvatar: '/assets/images/default-avatar.png',
    nickname: '',
    gender: 'male',
    birthday: '1995-06-18',
    bio: '',
    saving: false
  },

  onChooseAvatar(e) {
    // e.detail.avatarUrl 是临时文件路径，先上传后台拿永久地址
    const tempPath = e.detail.avatarUrl
    wx.uploadFile({
      url: 'https://api.example.com/upload/avatar',
      filePath: tempPath,
      name: 'file',
      success: (res) => {
        const data = JSON.parse(res.data)
        this.setData({ avatarUrl: data.data.url })
      }
    })
  },

  onNicknameInput(e) {
    this.setData({ nickname: e.detail.value })
  },

  onBirthdayChange(e) {
    this.setData({ birthday: e.detail.value })
  },

  onBioInput(e) {
    this.setData({ bio: e.detail.value })
  },

  onSave(e) {
    const { nickname, gender, bio } = e.detail.value
    if (!nickname || nickname.trim().length < 2) {
      return wx.showToast({ title: '昵称至少 2 个字符', icon: 'none' })
    }
    this.setData({ saving: true })
    wx.request({
      url: 'https://api.example.com/user/profile',
      method: 'PUT',

        avatarUrl: this.data.avatarUrl,
        nickname: nickname.trim(),
        gender,
        birthday: this.data.birthday,
        bio: bio || ''
      },
      success: () => wx.showToast({ title: '保存成功', icon: 'success' }),
      complete: () => this.setData({ saving: false })
    })
  }
})
```

## 最佳实践与踩坑记录

### 最佳实践

1. 所有需要提交的控件一律设置 name，且 name 与后台接口字段保持一致，减少联调转换成本
2. 输入校验分层：前端做格式与必填校验（正则、长度），后端做业务校验（重复、状态），两端规则要一致
3. 手机号、金额等输入在 bindinput 里做正则清洗（replace 掉非法字符），防止 iOS number 键盘可输入其他字符
4. 提交按钮用 submitting + disabled 双重控制，loading 展示状态，防止连点重复提交
5. 头像昵称使用官方推荐的 open-type="chooseAvatar" + input type="nickname" 组合，合规且体验好
6. bindchanging、bindinput 这类高频事件里只做轻量 setData，重逻辑放到 bindchange/bindblur 或节流处理
7. 验证码倒计时、滑块值等临时状态放在 data 中管理，定时器在 onUnload 清理，防止页面残留
8. 选择器（picker）返回的数据结构与后端约定一致（如日期统一 YYYY-MM-DD 字符串），提交前统一转换

### 踩坑记录

```text
坑 1：input 被键盘遮挡，看不清输入内容
结论：输入时键盘弹起，输入框被遮住或页面跳动。
原因：键盘高度未参与布局计算，输入框位置低于键盘顶部。
解法：设置 cursor-spacing（输入框与键盘间距）并保留 adjust-position="true"；需要固定输入栏时用 position: fixed 方案配合占位。

坑 2：textarea 在 iOS 滚动时出现白块/重影
结论：页面滚动时 textarea 区域渲染异常，出现白块或内容闪烁。
原因：textarea 是原生组件，与 WebView 渲染层存在合成差异。
解法：避免 textarea 放在滚动容器内做复杂动画；设置 fixed 属性或外层加 transform 触发重绘；基础库新版本已改善，保持基础库更新。

坑 3：auto-height 与 maxlength 同时设置，字数限制失效
结论：textarea 设置了 auto-height 和 maxlength，超出字数仍可输入。
原因：官方已知问题，auto-height 为 true 时 maxlength 不生效。
解法：maxlength 失效时在 bindinput 里手动截断 e.detail.value.slice(0, max) 后回填；或不用 auto-height 用固定高度。

坑 4：open-type="getUserInfo" 拿不到真实头像昵称
结论：getUserInfo 回调返回的是灰色默认头像与「微信用户」昵称，页面头像昵称无法获取。
原因：2021 年 4 月隐私政策调整后，getUserInfo 不再弹授权框，不再返回真实信息。
解法：改用 open-type="chooseAvatar" + input type="nickname" 让用户主动填写；后台存储用户自填信息。

坑 5：getPhoneNumber 提示获取失败或按钮无反应
结论：点击「获取手机号」按钮无回调或报错。
原因：getPhoneNumber 需要企业主体且完成微信认证；2023 年后还需在后台开通手机号快速验证组件并配置隐私协议。
解法：确认主体为企业且已认证；在 mp 后台「功能-手机号快速验证」开通；配置用户隐私保护指引中的手机号用途声明。

坑 6：slider 的 bindchanging 里请求接口导致卡顿
结论：拖动滑块时页面明显卡顿，接口请求频繁。
原因：bindchanging 在拖动过程中高频触发，每次请求+setData 造成渲染压力。
解法：拖动中只更新本地 value（轻量 setData），松手后的 bindchange 再发起筛选请求；必要时加节流。

坑 7：form 提交时部分控件值丢失
结论：bindsubmit 的 e.detail.value 里缺字段，或值为 undefined。
原因：控件没有设置 name 属性，form 无法收集；或条件渲染（wx:if）导致控件未渲染。
解法：检查所有控件是否设置 name；条件渲染的控件在提交前确认已渲染；动态表单用 dataset 或手动收集。

坑 8：checkbox 全选状态与数据不同步
结论：点全选后个别项未勾选，或取消全选后状态错乱。
原因：全选用「选中数量 === 总数量」判断，未把判断结果写回 checked，渲染状态与实际数据不一致。
解法：维护显式的 checked 数组，全选/反选时重新 map 生成选项数组再 setData。

坑 9：picker 的 date 值格式与后端不一致
结论：后端存的是时间戳，前端 picker 返回 YYYY-MM-DD 字符串，保存后日期错乱。
原因：date 模式返回固定格式字符串，未做转换直接提交。
解法：前端统一转换（Date.parse 或 formatDate）；或后端接收字符串后自行解析，接口约定写清楚。

坑 10：输入框 value 用 bindinput 回写出现光标跳动
结论：输入中文或删除字符时光标跳到末尾，输入体验差。
原因：bindinput 里 setData 回写 value，导致组件重渲染重置光标位置。
解法：表单受控输入用 data 里的 form 对象驱动且只在失焦（bindblur）时回写；实时统计字数时用 e.detail.value.length 而非重新 setData 整个 value。
```

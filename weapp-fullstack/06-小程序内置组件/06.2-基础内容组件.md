## 概述

基础内容组件负责页面中最常见的内容展示：文本、富文本、进度条与图标。它们不像视图容器那样负责布局，也不像表单组件那样负责交互输入，而是把「字、图、状态」三类信息渲染到界面上。其中 text 是纯文本的最终形态，rich-text 承载后台富文本内容，progress 表达任务进度，icon 提供内置状态图标。

```text
基础内容组件一览：
1. text —— 纯文本组件，支持选中复制、空格控制与实体解码
2. rich-text —— 富文本组件，渲染 nodes 数组或 HTML 字符串
3. progress —— 进度条组件，展示百分比进度，支持动画
4. icon —— 内置图标组件，按 type 渲染微信内置图标
5. 通用注意 —— 内容型组件不处理点击交互，交互交给外层容器或事件绑定
6. 使用原则 —— 能用 text 不用 rich-text，能本地生成不依赖后台富文本
```

## text 文本组件

text 是小程序中最基础的文本组件，对应 HTML 中的 span（行内元素），默认宽度由内容撑开，多个 text 可以并排显示。与 view 里的裸文本不同，text 提供了三个关键能力：selectable 让文本可被长按选中复制、space 控制连续空格的显示、decode 解析 HTML 实体。需要注意 text 内部只能嵌套 text，不能放 view、image 等块级组件。

```wxml
<!-- pages/text-demo/text-demo.wxml -->
<view class="section">
  <view class="section-title">基础文本与嵌套高亮</view>
  <!-- text 支持嵌套 text，实现局部样式：价格高亮 -->
  <text class="goods-name">
    商品名称
    <text class="price">¥99.90</text>
    <text class="tag">新品</text>
  </text>
</view>

<view class="section">
  <view class="section-title">可选中复制（长按文本出现选择菜单）</view>
  <!-- iOS 用 selectable，Android 在基础库 2.12.1+ 需配 user-select -->
  <text selectable user-select="true" class="order-no">订单号：2026082012345678</text>
</view>

<view class="section">
  <view class="section-title">连续空格与实体解码</view>
  <!-- space 控制空格显示：nbsp 为不换行空格 -->
  <text space="nbsp">名　　称　与　　值</text>
  <!-- decode 解析实体：&nbsp; &lt; &gt; &amp; 等 -->
  <text decode="true">&lt;text&gt; 组件 &amp; 实体 &nbsp; 示例</text>
</view>
```

```js
// pages/text-demo/text-demo.js
Page({
  data: {
    // 文本内容也可以来自数据绑定
    orderNo: '2026082012345678',
    tips: '长按我试试复制'
  }
})
```

```text
text 组件要点：
1. selectable —— 文本可选，长按出现系统选择菜单；iOS 直接生效
2. user-select —— 基础库 2.12.1+ 新增，Android 上实现可选需要同时设置
3. space —— 连续空格显示方式：ensp（半个空格）/ emsp（一个空格）/ nbsp（不换行空格）
4. decode —— 是否解码实体：&nbsp; &lt; &gt; &amp; &apos; &ensp; &emsp; 六种
5. 嵌套规则 —— text 内部只允许嵌套 text，禁止嵌套 view/image
6. 定位 —— 行内元素，宽度由内容决定，多个 text 可同行排列
```

## rich-text 富文本组件

rich-text 用于渲染带样式的富文本内容，最常见的数据来源是后台编辑的文章、商品详情、公告等 HTML 片段。它接收 nodes 属性，值可以是节点数组（更可控、性能更好），也可以是 HTML 字符串（基础库 2.4.0+ 支持）。渲染出的节点默认宽度 100%，高度自适应，但内部节点不受页面 WXSS 样式作用域影响，只能通过内联 style 控制样式。

```wxml
<!-- pages/article/article.wxml -->
<view class="article-page">
  <view class="article-title">{{title}}</view>
  <view class="article-meta">发布于 {{publishTime}}</view>

  <!-- 方式一：nodes 数组（推荐，可预处理图片宽度与安全过滤） -->
  <rich-text class="article-content" nodes="{{nodes}}" />

  <!-- 方式二：直接渲染后台 HTML 字符串（基础库 2.4.0+） -->
  <!-- <rich-text class="article-content" nodes="{{htmlContent}}" /> -->
</view>
```

```js
// pages/article/article.js
Page({
  data: {
    title: '小程序开发入门指南',
    publishTime: '2026-08-20',
    nodes: [
      {
        name: 'div',
        attrs: { class: 'article-body' },
        children: [
          { type: 'text', text: '这是一段富文本内容。' },
          {
            name: 'img',
            attrs: {
              // 关键：统一限制图片宽度，防止后台图片撑爆屏幕
              src: 'https://example.com/images/banner.png',
              style: 'max-width:100%;height:auto;display:block;'
            }
          },
          {
            name: 'p',
            attrs: {},
            children: [{ type: 'text', text: '第二段内容，支持行内样式。' }]
          }
        ]
      }
    ]
  },

  onLoad(query) {
    // 真实项目中从后台拉取文章，把后台 HTML 转成 nodes 数组
    // 转换时统一做：图片加 max-width:100%、过滤 script/style/iframe
  }
})
```

```text
rich-text 组件要点：
1. nodes 取值 —— 节点数组（推荐）或 HTML 字符串（基础库 2.4.0+）
2. 节点结构 —— { name, attrs, children }，文本节点为 { type: 'text', text }
3. 样式隔离 —— 内部节点不生效外部 class，只能使用 style 内联样式
4. 图片处理 —— 后台图片默认按原始尺寸渲染，务必统一加 max-width:100%
5. 事件限制 —— rich-text 内部节点不支持绑定事件，bindtap 拿不到内部节点信息
6. 性能 —— 富文本渲染成本高于 text，长列表慎用；不支持的标签会被忽略
```

## progress 进度条组件

progress 以进度条形式展示任务完成度，常配合上传下载、学习进度、问卷答题等场景。核心属性是 percent（0-100 的百分比数值），配合 show-info 显示百分比文字、stroke-width 控制条宽、activeColor 与 backgroundColor 控制颜色，active 开启从左到右的填充动画。动画结束后会触发 bindactiveend 事件（基础库 2.9.0+），适合在进度走完后执行下一步逻辑。

```wxml
<!-- pages/progress-demo/progress-demo.wxml -->
<view class="progress-list">
  <!-- 基础进度条：显示百分比文字，进度颜色为橙色 -->
  <view class="progress-item">
    <text class="progress-label">课程学习进度</text>
    <progress
      percent="{{coursePercent}}"
      show-info="true"
      stroke-width="8"
      activeColor="#ff9800"
      backgroundColor="#f5f5f5"
      active="true"
    />
  </view>

  <!-- 圆角进度条：不显示文字，用于紧凑场景 -->
  <view class="progress-item">
    <text class="progress-label">资料上传</text>
    <progress
      percent="{{uploadPercent}}"
      stroke-width="6"
      borderRadius="3"
      activeColor="#07c160"
      backgroundColor="#ececec"
      bindactiveend="onUploadEnd"
    />
  </view>

  <!-- 下载进度：配合 wx.downloadFile 的 onProgressUpdate 使用 -->
  <view class="progress-item">
    <text class="progress-label">安装包下载 {{downloadPercent}}%</text>
    <progress percent="{{downloadPercent}}" show-info="false" stroke-width="4" activeColor="#10aeff" />
  </view>
</view>
```

```js
// pages/progress-demo/progress-demo.js
Page({
  data: {
    coursePercent: 65,
    uploadPercent: 100,
    downloadPercent: 0
  },

  onLoad() {
    // 模拟下载进度：真实项目中使用 downloadTask.onProgressUpdate
    this.downloadTask = wx.downloadFile({
      url: 'https://example.com/files/app.apk',
      success: () => {
        wx.showToast({ title: '下载完成', icon: 'success' })
      }
    })
    this.downloadTask.onProgressUpdate((res) => {
      // res.progress 为 0-100 的整数，直接驱动进度条
      this.setData({ downloadPercent: res.progress })
    })
  },

  onUploadEnd() {
    // 进度动画走完（100%）后触发，可执行跳转或提示
    wx.showToast({ title: '上传完成', icon: 'success' })
  },

  onUnload() {
    // 页面卸载时中止下载任务，防止回调泄漏
    if (this.downloadTask) {
      this.downloadTask.abort()
    }
  }
})
```

```text
progress 组件要点：
1. percent —— 进度百分比 0-100，逻辑层负责保证数值在范围内
2. show-info —— 是否在右侧显示百分比文字（默认 false）
3. stroke-width —— 进度条宽度，单位 px，默认 6
4. 颜色控制 —— activeColor 进度条颜色，backgroundColor 轨道颜色，borderRadius 圆角
5. active 动画 —— active=true 时进度从左往右填充；active-mode 控制 backwards/forwards
6. bindactiveend —— 基础库 2.9.0+，动画结束后触发，适合做「完成」后续动作
```

## icon 图标组件

icon 渲染微信内置的矢量图标，通过 type 指定图标类型、size 控制尺寸（px）、color 控制颜色。内置图标只有 9 个语义类型：success、success_no_circle、info、warn、waiting、cancel、download、search、clear，覆盖了提示与状态类场景。内置图标数量少、样式固定，业务型图标（购物车、收藏、设置等）需要用 image 或字体图标（iconfont）方案，后者在后面的自定义组件篇会展开。

```wxml
<!-- pages/icon-demo/icon-demo.wxml -->
<view class="icon-row">
  <!-- 状态类图标：不同颜色表达不同语义 -->
  <view class="icon-cell">
    <icon type="success" size="28" color="#07c160" />
    <text>success</text>
  </view>
  <view class="icon-cell">
    <icon type="info" size="28" color="#10aeff" />
    <text>info</text>
  </view>
  <view class="icon-cell">
    <icon type="warn" size="28" color="#fa5151" />
    <text>warn</text>
  </view>
  <view class="icon-cell">
    <icon type="waiting" size="28" color="#ff9f0a" />
    <text>waiting</text>
  </view>
  <view class="icon-cell">
    <icon type="cancel" size="28" color="#999999" />
    <text>cancel</text>
  </view>
  <view class="icon-cell">
    <icon type="search" size="28" color="#666666" />
    <text>search</text>
  </view>
</view>

<!-- 空状态展示：icon + text 组合 -->
<view class="empty-state" wx:if="{{goodsList.length === 0}}">
  <icon type="search" size="64" color="#cccccc" />
  <text class="empty-text">暂无搜索结果</text>
</view>
```

```text
icon 组件要点：
1. type —— 图标类型：success / success_no_circle / info / warn / waiting / cancel / download / search / clear
2. size —— 图标尺寸，单位 px，默认 23
3. color —— 图标颜色，支持十六进制色值
4. 适用场景 —— 状态提示（成功/失败/等待）、空状态、搜索框图标
5. 局限 —— 内置图标仅 9 个且不可定制细节，业务图标用 image 或 iconfont
6. 兼容 —— 部分历史文档写作 success-no-circle，实际取值以 success_no_circle 为准
```

## 组件的使用场景

四个组件在业务中的选择主要看内容形态：纯文本与轻量高亮用 text，后台富文本（文章、商品详情）用 rich-text，需要表达完成度用 progress，语义状态提示用 icon。选择时还要考虑性能与可控性：rich-text 渲染成本高且样式不可控，能用 text 拼装的静态内容就尽量不用富文本；icon 满足不了的视觉需求尽早切换到 image 方案，避免上线后返工。

```text
场景选择决策：
1. 固定文案、局部高亮、需要复制 -> text（selectable + user-select）
2. 后台 HTML 文章、图文混排、商品详情 -> rich-text（转 nodes 数组）
3. 上传下载、学习进度、问卷答题 -> progress（percent + show-info + active）
4. 成功/失败/等待/搜索等状态提示 -> icon（内置 9 类足够覆盖）
5. 品牌图标、购物车/收藏等业务图标 -> image 或 iconfont 字体图标
6. 组合原则 —— 内容组件只负责展示，交互（点击跳转、复制回调）交给事件与 API
```

## 应用场景实战

### 场景一：商品详情页（后台富文本 + 加载进度 + 状态图标）

综合使用 rich-text、progress 与 icon 的详情页：加载后台详情数据时展示进度条占位，加载完成渲染富文本，底部用 icon 表达「正品保障」等卖点。

```wxml
<!-- pages/goods-detail/goods-detail.wxml -->
<view class="detail-page">
  <!-- 加载态：进度条表达加载进度 -->
  <view class="loading-box" wx:if="{{loading}}">
    <progress percent="{{loadPercent}}" show-info="true" stroke-width="6" activeColor="#ff5000" />
    <text class="loading-text">正在加载商品详情...</text>
  </view>

  <!-- 内容区：加载完成后展示 -->
  <block wx:else>
    <view class="goods-info">
      <text class="goods-price">
        ¥<text class="price-num">{{price}}</text>
        <text class="goods-tag" decode="true">&nbsp;包邮</text>
      </text>
      <text class="goods-name" user-select="true">{{name}}</text>
    </view>

    <!-- 后台富文本商品详情 -->
    <rich-text class="detail-content" nodes="{{detailNodes}}" />

    <!-- 卖点图标行 -->
    <view class="service-row">
      <view class="service-item">
        <icon type="success" size="18" color="#07c160" />
        <text class="service-text">正品保障</text>
      </view>
      <view class="service-item">
        <icon type="info" size="18" color="#10aeff" />
        <text class="service-text">七天无理由</text>
      </view>
      <view class="service-item">
        <icon type="waiting" size="18" color="#ff9f0a" />
        <text class="service-text">48 小时发货</text>
      </view>
    </view>
  </block>
</view>
```

```js
// pages/goods-detail/goods-detail.js
Page({
  data: {
    loading: true,
    loadPercent: 0,
    price: '99.90',
    name: '经典款保温杯 500ml',
    detailNodes: []
  },

  onLoad(options) {
    this.simulateLoad()
  },

  simulateLoad() {
    // 模拟分段加载进度（真实项目用 wx.request 回调驱动）
    let percent = 0
    this.timer = setInterval(() => {
      percent += 20
      if (percent >= 100) {
        clearInterval(this.timer)
        this.setData({ loadPercent: 100, loading: false })
        this.fetchDetail()
        return
      }
      this.setData({ loadPercent: percent })
    }, 200)
  },

  fetchDetail() {
    // 真实项目：wx.request 拉取后台商品详情 HTML
    // 这里演示把后台 HTML 转成 nodes 数组的关键步骤
    const html = '<p>精选 304 不锈钢内胆</p><img src="https://example.com/img/01.png" /><p>保温 12 小时</p>'
    this.setData({ detailNodes: this.htmlToNodes(html) })
  },

  // 简单 HTML 转 nodes：真实项目建议使用成熟的解析库（如 html2wxml）
  htmlToNodes(html) {
    const imgReg = /<img[^>]+src="([^"]+)"[^>]*>/g
    const nodes = []
    let match
    while ((match = imgReg.exec(html)) !== null) {
      nodes.push({
        name: 'img',
        attrs: {
          src: match[1],
          style: 'max-width:100%;height:auto;display:block;margin:16rpx 0;'
        }
      })
    }
    // 段落文本：按 p 标签切分
    html.replace(/<p[^>]*>([^<]*)<\/p>/g, (all, text) => {
      nodes.push({ name: 'p', attrs: { style: 'font-size:28rpx;line-height:1.8;' }, children: [{ type: 'text', text }] })
      return all
    })
    return nodes
  },

  onUnload() {
    if (this.timer) clearInterval(this.timer)
  }
})
```

### 场景二：任务中心（学习进度 + 状态图标 + 文本明细）

任务中心页面用 progress 展示每项任务的完成度，用 icon 区分任务状态（进行中/已完成/待开始），用 text 承载任务说明与可复制的兑换码。

```wxml
      <icon

        size="20"
        color="#07c160"
      />
      <icon
        wx:elif="{{item.status === 'doing'}}"
        type="waiting"
        size="20"
        color="#ff9f0a"
      />
      <icon
        wx:else
        type="info"
        size="20"
        color="#bbbbbb"
      />
    </view>
    <progress
      percent="{{item.percent}}"
      stroke-width="6"
      activeColor="#07c160"
      backgroundColor="#f0f0f0"
      active="{{item.status === 'doing'}}"
    />
    <text class="task-tip">{{item.tip}}</text>
  </view>

  <!-- 可复制兑换码 -->
  <view class="code-box">
    <text class="code-label">我的邀请码（点击复制）</text>
```

## 最佳实践与踩坑记录

### 最佳实践

1. 纯文本优先用 text，只有需要段落、图片、多级样式的富文本内容才用 rich-text，避免无谓的性能开销
2. 需要用户复制的文本（订单号、邀请码、收货地址）同时设置 selectable 与 user-select，双端都能长按复制
3. 后台富文本入库前做安全过滤（script/iframe/style 标签），渲染前统一转换成 nodes 数组并给 img 节点加 max-width:100%
4. progress 的 percent 在逻辑层统一 clamp 到 0-100，文案（如「下载中 45%」）与进度条数值保持一致
5. 图标选择遵循「先内置后自绘」：语义状态用 icon，品牌与业务图标用 image，大批量统一图标用 iconfont
6. 内容组件不直接绑业务事件，把「点击整块内容」的交互放在外层 view 上，内部保持纯展示
7. rich-text 在 wx:for 列表中逐项渲染很耗性能，长列表先用摘要文本，详情页再加载完整富文本
8. 组件样式（字号、颜色、间距）尽量收口到页面公共 class，text 局部高亮用嵌套 text + 独立 class 实现

### 踩坑记录

```text
坑 1：text 里连续空格只显示一个
结论：text 内写入多个空格，渲染出来只有一个空格。
原因：WXML 文本节点默认折叠连续空白字符，与 HTML 行为一致。
解法：需要保留空格时用 space="nbsp"（不换行空格）或 decode 配合 &nbsp; 实体。

坑 2：Android 上 text 长按无法复制
结论：selectable="true" 在 Android 上长按没有选择菜单，iOS 正常。
原因：selectable 属性 iOS 直接生效，Android 需要基础库 2.12.1+ 的 user-select 属性配合。
解法：selectable 与 user-select="true" 同时设置，并保证最低基础库版本在 2.12.1 以上。

坑 3：rich-text 里的图片撑爆屏幕
结论：后台富文本中的大图超出屏幕宽度，页面横向溢出。
原因：后台 HTML 图片没有宽度约束，rich-text 按原始尺寸渲染。
解法：转 nodes 数组时给 img 节点统一加 style="max-width:100%;height:auto;"；或后台返回时处理。

坑 4：rich-text 内部节点点击事件无效
结论：想给富文本里的链接、图片绑定 bindtap 跳转，事件不触发或拿不到目标节点。
原因：rich-text 内部节点不支持绑定事件，组件上的 bindtap 只能拿到 rich-text 本身。
解法：需要可点击富文本时自研递归渲染 nodes 的 wxml 模板；或由后台把链接语义化后单独渲染。

坑 5：rich-text 内写 class 样式不生效
结论：nodes 节点上写了 class，页面 wxss 里也定义了对应样式，渲染后没有效果。
原因：rich-text 内部节点处于独立渲染上下文，页面样式作用域不覆盖内部节点。
解法：节点样式一律用 attrs.style 内联方式；需要复用样式时在生成 nodes 时把 class 转成 style。

坑 6：progress 的 percent 超过 100 显示异常
结论：percent 传了 120，进度条满格但文字显示 120%，动画行为也异常。
原因：percent 未做边界限制，组件按原始数值渲染文本与计算动画。
解法：逻辑层 clamp 到 0-100；展示文案单独格式化，不要直接拼接组件内数值。

坑 7：部分 icon 类型真机不显示
结论：模拟器正常，真机上某个 icon 渲染为空白。
原因：内置图标在不同基础库版本上支持有差异，或 type 拼写用了连字符形式。
解法：统一使用官方列出的 9 个 type 取值；业务图标改用 image/iconfont，不依赖内置图标。

坑 8：低版本基础库 rich-text 传字符串渲染为空
结论：nodes 传 HTML 字符串，老版本手机上整个富文本区域空白。
原因：nodes 支持 String 类型需要基础库 2.4.0+，低版本只支持数组。
解法：后台设置最低基础库版本；或统一用 nodes 数组结构，不依赖字符串支持。
```

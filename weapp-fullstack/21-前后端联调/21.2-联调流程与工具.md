## 概述

联调（联调测试）是前后端协作的核心环节：小程序端、SpringBoot 后端、Vue 管理端三方按接口文档把系统打通。联调阶段的常见问题集中在四类——接口约定不一致、环境不通（代理/跨域/域名）、请求数据看不懂（抓包）、接口调试效率低（工具不会用）。本章把流程和工具串起来讲，让你遇到问题知道先做什么、用什么看、怎么定位。

流程上遵循「文档先行、分头开发、后端自测、联调验收」四步；工具上掌握三层能力：Vite 代理解决浏览器端跨域、Charles/Fiddler 解决移动端与真机抓包、Postman/Apifox 解决接口调试与自动化回归。工具是手段，流程是保障，两者配合才能把联调周期压缩到最短。

```text
联调能力全景：
1. 流程 —— 文档先行 → 并行开发 → 后端自测 → 联调 → 验收
2. 浏览器端 —— Vite proxy 代理后端，消除开发环境跨域
3. 小程序端 —— 开发工具勾选「不校验合法域名」，本地直连后端
4. 抓包 —— Charles/Fiddler 看 HTTPS 明文请求，定位数据问题
5. 调试 —— Postman/Apifox 管理接口集合、环境变量、自动化测试
6. 收尾 —— 联调记录与问题清单归档，验收通过进入提测
```

## 联调流程：文档先行到验收

联调不是从「前后端坐在一起」才开始，而是从接口文档定稿就开始。规范的四步流程能减少 80% 的联调返工：第一步接口文档先行（21.1 章节已覆盖），第二步前后端按文档并行开发，第三步后端在 Knife4j 自测通过后再通知前端，第四步进入正式联调与验收。

```text
联调四阶段：
1. 文档先行 —— 接口清单评审通过，字段、错误码、分页规则全部对齐
2. 并行开发 —— 前端按文档 mock 数据开发页面，后端按文档实现接口
3. 后端自测 —— Knife4j 里把成功/失败/边界调通，自测通过再喊联调
4. 联调验收 —— 真实环境跑通主流程，逐条核对文档字段，输出验收结论
```

联调过程中用「联调问题清单」记录每个问题，格式固定：问题描述、涉及接口、期望结果、实际结果、责任人、状态。问题闭环后清单归档，作为提测与上线的依据。一次联调至少覆盖三类场景：正常流程（下单、支付回调、订单列表）、异常流程（参数错误、Token 过期、库存不足）、边界场景（空列表、超大分页、并发下单）。

```text
联调验收检查项：
1. 主流程 —— 登录、浏览、下单、支付、订单查询全链路走通
2. 异常流程 —— 每个错误码在真实环境能触发且提示合理
3. 边界场景 —— 空数据、分页最后一页、超长文本、并发请求
4. 字段核对 —— 返回字段与文档逐一对齐，类型、单位、命名一致
5. 性能冒烟 —— 列表接口首屏耗时、图片加载、弱网表现
6. 问题归档 —— 问题清单闭环，遗留问题有明确责任人与排期
```

## 开发环境联调与 Vite 代理配置

Vue 管理端在浏览器里开发时，页面地址是 http://localhost:5173，后端是 http://localhost:8080，两者不同源，浏览器会拦截跨域请求（详见 21.3）。Vite 开发服务器内置代理能力：把 /api 开头的请求转发到后端，浏览器看到的始终是同源请求，跨域问题在开发环境直接消解。

```js
// vite.config.js
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'

export default defineConfig({
  plugins: [vue()],
  server: {
    port: 5173,
    proxy: {
      // 所有 /api 开头的请求转发到 SpringBoot 后端
      '/api': {
        target: 'http://localhost:8080',
        changeOrigin: true,        // 修改请求头 Host 为后端地址
        // rewrite: (path) => path.replace(/^\/api/, '')  // 后端无 /api 前缀时使用
      }
    }
  }
})
```

配置后，前端 axios 请求直接写相对路径 `axios.get('/api/v1/products')`，Vite 自动转发到 `http://localhost:8080/api/v1/products`。注意 changeOrigin 必须为 true，否则后端拿到的 Host 是 localhost:5173，某些按 Host 做校验的框架（如 Spring Security 的 CSRF）会出问题。如果后端接口本身没有 /api 前缀，用 rewrite 把前缀剥掉。

```text
Vite 代理要点：
1. 生效范围 —— 只作用于 vite dev server（npm run dev），不影响生产构建
2. changeOrigin —— 必须 true，否则后端可能校验 Host 失败
3. 路径匹配 —— 按前缀匹配，/api 开头的才转发，静态资源不受影响
4. 后端地址 —— target 写后端实际地址，含端口
5. 生产环境 —— 打包后由 Nginx 反代，见 22.2 章节
6. 排查方式 —— 代理不生效先看 Network 面板请求落点，再查 proxy 配置
```

小程序端没有浏览器跨域问题（wx.request 不受同源策略限制），但本地开发默认有域名校验限制：请求域名必须是 HTTPS 且在后台配置过。开发者工具里通过「详情 → 本地设置 → 勾选不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书」跳过校验，本地开发直连 http://localhost:8080 即可。

```text
小程序本地联调配置：
1. 打开开发者工具 → 右上角「详情」→「本地设置」
2. 勾选「不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书」
3. 代码里 baseUrl 指向 http://localhost:8080
4. 点击「编译」，小程序即可请求本地后端
5. 该勾选只对当前项目本地生效，真机预览与线上包不受影响
6. 注意：真机预览时手机访问不到电脑的 localhost，需用局域网 IP 或抓包工具配合
```

## 小程序端联调配置

小程序联调要区分三种形态：开发者工具模拟器（能访问 localhost）、真机预览（手机访问电脑局域网 IP 或测试服务器）、线上体验版（必须 HTTPS 合法域名）。最常见的问题是：模拟器调通后切真机预览突然全部请求失败——因为手机上的 localhost 是手机自己，不是电脑。

```js
// utils/config.js —— 环境切换集中管理
module.exports = {
  // 开发环境：工具模拟器直连本地后端
  dev: {
    baseUrl: 'http://localhost:8080/api/v1'
  },
  // 真机调试：手机通过局域网访问电脑（同一 WiFi）
  lan: {
    baseUrl: 'http://192.168.1.100:8080/api/v1'
  },
  // 测试/生产：HTTPS 合法域名
  prod: {
    baseUrl: 'https://api.example.com/api/v1'
  }
}
```

```js
// utils/request.js —— 统一请求封装
const { prod } = require('./config')

const BASE_URL = prod.baseUrl

function request(options) {
  return new Promise((resolve, reject) => {
    wx.request({
      url: BASE_URL + options.url,
      method: options.method || 'GET',
      data: options.data || {},
      header: {
        'Content-Type': 'application/json',
        'Authorization': wx.getStorageSync('token') || ''
      },
      success(res) {
        if (res.statusCode === 200 && res.data.code === 0) {
          resolve(res.data.data)
        } else if (res.statusCode === 401) {
          wx.navigateTo({ url: '/pages/login/login' })
          reject(res.data)
        } else {
          wx.showToast({ title: res.data.message || '请求失败', icon: 'none' })
          reject(res.data)
        }
      },
      fail(err) {
        wx.showToast({ title: '网络异常，请检查网络', icon: 'none' })
        reject(err)
      }
    })
  })
}

module.exports = { request, BASE_URL }
```

```text
小程序联调配置要点：
1. 模拟器 —— 本地设置勾选不校验域名，baseUrl 用 localhost
2. 真机预览 —— 手机与电脑同一 WiFi，baseUrl 用电脑局域网 IP
3. 正式环境 —— 必须 HTTPS + 后台配置 request 合法域名
4. baseUrl 集中管理 —— 不要散落在每个页面，切换环境只改一个文件
5. 请求封装 —— 统一处理状态码、业务码、Token 注入与错误提示
6. 联调方式 —— 真机调试（工具真机调试模式）比预览更利于看日志
```

## Charles 抓包

Charles 是 macOS/Windows 上最常用的 HTTP 抓包工具。抓包能让你「看见」小程序真实发出的请求与响应：URL、请求头、参数、返回体一目了然，是联调定位问题的核心手段。抓包原理是中间人代理：手机（或模拟器）把流量代理到电脑上的 Charles，Charles 解密 HTTPS 后展示明文。

```text
Charles 抓包配置步骤：
1. 电脑端 —— 安装 Charles，菜单 Proxy → Proxy Settings，勾选 HTTP Proxy，端口 8888
2. 手机代理 —— 手机连同一 WiFi，设置里手动配置 HTTP 代理：电脑 IP + 8888
3. 安装证书 —— 手机浏览器访问 chls.pro/ssl 下载并安装 Charles 根证书
4. 信任证书 —— iOS 在「设置 → 通用 → 关于本机 → 证书信任设置」开启完全信任
5. 抓 HTTPS —— 菜单 Proxy → SSL Proxying Settings，勾选 Enable SSL Proxying，
   并在 Locations 里添加 *:443（或只加目标域名）
6. 确认流量 —— 手机访问小程序，Charles 的 Structure 面板出现请求列表
```

弱网模拟是 Charles 的杀手级能力：联调时模拟 3G 网络、高延迟、丢包，验证小程序在网络抖动下的表现（loading 状态、超时处理、重试逻辑）。菜单 Proxy → Throttle Settings，勾选 Enable Throttling，预设带宽与延迟，还可以用「只限特定主机」精确模拟某个接口的慢响应。

```text
Charles 常用功能：
1. Structure 面板 —— 按域名树形展示请求，配合 Filter 过滤
2. 断点 Breakpoints —— 请求/响应到达时暂停，手工改参数再放行
3. 弱网模拟 —— Proxy → Throttle Settings，模拟 3G/高延迟/丢包
4. Map Local —— 把某个接口的响应映射到本地 JSON 文件（Mock 方案）
5. Map Remote —— 把请求重定向到另一个地址（切环境神器）
6. 重放 Repeat —— 右键请求可重放，复现问题与回归验证
```

抓包看到的数据是最真实的接口行为：后端说「我返回了 status」，前端说「我没收到」，Charles 一查就知道谁在说谎。联调排错的第一反应应该是打开 Charles 看真实请求，而不是两边各猜各的。

```text
抓包排查流程：
1. 看请求是否发出 —— 没有请求，检查代理配置与域名校验
2. 看 URL 与参数 —— 与文档比对，路径、字段名、类型是否一致
3. 看响应状态码 —— 401/404/500 分别对应不同问题方向
4. 看响应体 —— 结构是否符合 ApiResult 约定，字段是否存在
5. 看请求头 —— Content-Type、Authorization 是否携带正确
6. 定位结论 —— 前端问题改前端，后端问题提给后端，有据可依
```

## Fiddler 抓包

Fiddler 是 Windows 平台经典抓包工具，功能与 Charles 高度重合：中间人代理、HTTPS 解密、断点、弱网模拟。选型建议：macOS 用 Charles，Windows 用 Fiddler，团队统一一种工具减少沟通成本。Fiddler 4 免费，Fiddler Everywhere 支持跨平台但收费。

```text
Fiddler 抓包配置步骤：
1. 启动 Fiddler，菜单 Tools → Options → Connections，勾选 Allow remote computers to connect
2. 记下端口（默认 8888），手机 WiFi 设置 HTTP 代理：电脑 IP + 端口
3. 手机浏览器访问 http://电脑IP:8888，下载 FiddlerRoot certificate 并安装信任
4. 开启 HTTPS 解密：Tools → Options → HTTPS，勾选 Decrypt HTTPS traffic
5. 手机访问小程序，Fiddler 主列表出现请求，Inspectors 面板查看明文
6. 结束抓包记得关闭手机代理，否则手机断网
```

Fiddler 的过滤器（Filters）比 Charles 更直观：主界面下方 Filters 标签页勾选 Use Filters，可按 Host、进程、响应码过滤，只看小程序域名的请求，忽略系统与浏览器的噪音流量。联调时请求量大，不过滤根本看不清楚。

```text
Fiddler 常用功能：
1. Filters —— 按域名/响应码过滤请求，聚焦目标接口
2. Inspectors —— 请求与响应双栏查看，Headers/JSON/RAW 视图
3. Composer —— 手工构造请求调试接口，类似 Postman 的轻量版
4. AutoResponder —— 把响应替换成本地文件或固定字符串（Mock）
5. 弱网模拟 —— Rules → Performance → Simulate Modem Speeds
6. 命令行 —— 底部 QuickExec 输入 ?keyword 快速过滤，cls 清屏
```

## Postman 与 Apifox 接口调试

Postman 是接口调试的事实标准：集合（Collection）管理接口、环境变量切换地址、脚本做自动化断言。Apifox 是国产替代，把 Postman（调试）+ Swagger（文档）+ JMeter（测试）三合一，支持直接从 OpenAPI 导入接口定义，中文团队上手更快。两个工具任选其一，思路完全一致。

```text
Apifox 核心概念：
1. 项目 —— 一个项目对应一个后端服务，成员共享
2. 接口 —— 从 OpenAPI 导入或手写，与代码注解自动同步
3. 环境 —— 开发/测试/生产三套 baseUrl，一键切换
4. 变量 —— {{token}}、{{baseUrl}} 形式引用，登录后自动填充
5. 断言 —— 响应体校验（code=0、字段存在），跑完自动出报告
6. 自动化 —— 集合测试串联多个接口，回归一键执行
```

环境变量是接口调试效率的关键：登录接口返回的 token 存进环境变量，后续接口的 Authorization 头引用 {{token}}，切换环境（开发/测试/生产）只改环境配置，接口本体不用动。Apifox 内置「登录后自动提取」配置：在登录接口的后置操作里写提取表达式，自动把 token 写入环境变量。

```text
Apifox 环境变量示例：
1. 环境「开发」—— baseUrl = http://localhost:8080/api/v1
2. 环境「测试」—— baseUrl = https://test-api.example.com/api/v1
3. 环境「生产」—— baseUrl = https://api.example.com/api/v1
4. 登录接口后置操作 —— 提取 res.data.data.token → {{token}}
5. 通用请求头 —— Authorization: Bearer {{token}}
6. 集合测试 —— 按业务流编排接口顺序，一键回归
```

```text
Postman 对应能力：
1. Collection —— 接口集合，按模块建目录（商品/订单/用户）
2. Environments —— 环境变量，Manage Environments 里配置 baseUrl
3. Pre-request Script —— 请求前执行 JS（如自动生成签名）
4. Tests —— 响应后执行断言，pm.test 校验 code 与字段
5. Runner —— 集合批量执行，跑回归
6. Import —— 支持导入 OpenAPI/Swagger 文档生成接口
```

## 应用场景实战

### 场景一：Vue 管理端 + Vite 代理联调商品列表

管理端要开发商品列表页，后端接口已完成并自测通过。前端本地起 Vite 开发服务器，通过代理联调：

```text
步骤：
1. 后端启动 SpringBoot，确认 8080 端口可访问
2. 前端 npm run dev 启动 Vite，访问 http://localhost:5173
3. vite.config.js 配置 /api 代理到 http://localhost:8080
4. axios 请求写相对路径 /api/v1/products?page=1&pageSize=10
5. Network 面板确认请求落点：Request URL 显示 localhost:5173，但实际被代理转发
6. 响应结构与文档一致，列表渲染正常，联调通过
7. 若 404 —— 检查代理 target 端口、路径前缀是否与后端一致
8. 若 500 —— 后端日志定位异常，修复后热重启验证
```

```text
场景一验证点：
1. 代理生效 —— 浏览器无跨域报错，Network 面板请求正常
2. 参数传递 —— page/pageSize/keyword 完整到达后端
3. 返回解析 —— PageResult 四字段解析正确，分页组件正常
4. 错误处理 —— 后端模拟 500，前端有错误提示不白屏
```

### 场景二：小程序登录接口联调 + Charles 抓包排错

小程序登录联调时发现：模拟器里登录成功，真机上一直报「请求失败」。用 Charles 定位：

```text
步骤：
1. 电脑与手机连同一 WiFi，电脑查局域网 IP（ifconfig 或 ipconfig）
2. Charles 开启代理与 SSL Proxying，手机配代理并安装证书
3. 真机预览小程序，发起登录请求
4. Charles 里看到请求确实发出 —— 说明问题在响应侧
5. 看响应：状态码 401 + code 40100，message「未登录」
6. 对比模拟器请求：真机请求头缺少 Authorization 或 code 参数错误
7. 定位根因：真机登录时序问题，wx.login 的 code 还没回来就调了登录接口
8. 修复：登录接口调用前 await wx.login 完成，重新联调通过
```

```text
场景二验证点：
1. 抓包可见 —— 真机请求在 Charles 中明文可见（HTTPS 解密成功）
2. 请求对比 —— 模拟器与真机请求头、参数逐项对比找差异
3. 根因定位 —— 用数据说话，不靠猜
4. 回归 —— 修复后真机重跑登录 → 拉取用户信息 → 下单全链路
```

## 最佳实践与踩坑记录

### 最佳实践

1. 文档先行再联调：接口清单评审通过才开工，联调中改契约必须同步文档与双方
2. 后端自测门槛：接口没在 Knife4j/Postman 自测通过前，不通知前端开始联调
3. baseUrl 集中管理：小程序与 Vue 端各维护一个 config 文件，环境切换只改一处
4. 抓包先于猜测：联调报错第一动作是 Charles/Fiddler 看真实请求，用数据定位
5. 联调问题清单：每个问题记录接口、现象、责任人、状态，闭环归档
6. 环境隔离：联调用独立测试库/测试账号，禁止拿生产数据联调
7. 弱网必测：上线前用 Charles 弱网模拟验证 loading、超时、重试表现
8. 接口集合沉淀：Postman/Apifox 集合随项目维护，作为回归测试资产

### 踩坑记录

```text
坑 1：Vite 代理配了但请求还是 404
结论：前端请求 localhost:5173/api/... 返回 404，后端接口实际不存在该路径。
原因：后端接口没有 /api 前缀，而代理没配 rewrite 剥掉前缀。
解法：对比前后端实际路径；后端有前缀就加 rewrite: path.replace(/^\/api/, '')。

坑 2：真机预览请求全部失败，模拟器却正常
结论：模拟器调通后真机预览所有请求失败。
原因：手机上的 localhost 指向手机自己，且局域网 IP 未配置、域名校验未处理。
解法：真机预览用电脑局域网 IP 作为 baseUrl；电脑防火墙放行 8080 端口；同一 WiFi。

坑 3：Charles 只能看到 CONNECT 隧道，看不到 HTTPS 明文
结论：抓包只显示 CONNECT 请求，响应全是密文。
原因：未开启 SSL Proxying，或手机端 Charles 根证书未安装/未信任。
解法：Proxy → SSL Proxying Settings 添加 *:443；手机下载 chls.pro/ssl 证书并到证书信任设置开启完全信任。

坑 4：抓包后手机突然无法上网
结论：手机所有网络请求失败，微信都打不开。
原因：手机代理指向已关闭的 Charles（或换网后代理没改）。
解法：结束抓包立即关闭手机手动代理；Charles 退出前先断开手机代理。

坑 5：小程序请求本地后端报「不在以下 request 合法域名列表中」
结论：开发者工具编译报域名校验错误，请求被拦截。
原因：默认校验合法域名，本地 localhost 不在列表。
解法：详情 → 本地设置 → 勾选「不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书」；该配置只在本地生效。

坑 6：Token 过期后接口全部报错，前端逐个页面弹错
结论：Token 过期后每个请求都弹「未登录」，体验极差。
原因：请求封装没有统一处理 401，各页面自行处理。
解法：统一请求封装里拦截 401 → 清 token → 跳登录页；登录成功后回跳原页面。

坑 7：Apifox/Postman 调试成功，小程序里同样参数却失败
结论：同一个接口，工具里通，小程序里 500。
原因：小程序请求头 Content-Type 与工具不同，或缺少后端要求的 header。
解法：Charles 抓包对比两者请求头差异；确认 Content-Type、Authorization、自定义头一致。

坑 8：联调时改后端代码，前端等半天没反应
结论：前端以为后端改了，实际后端没重启或热部署没生效。
原因：SpringBoot 修改代码后需要重启（或配置 devtools 热部署）。
解法：约定联调环境自动重启/热部署；后端改动后主动告知前端「已生效」，用 Charles 验证返回变化。
```

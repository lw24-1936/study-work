## 概述

创建项目是代码之旅的真正起点：在微信开发者工具中填入项目名称、选择目录、指定 AppID，工具就会生成一套标准的小程序工程骨架。这套骨架的目录结构与文件职责是微信官方约定的「规范」，理解它等于理解小程序项目的组织方式——全局文件管「面」（启动逻辑、全局配置、全局样式），页面四件套管「点」（每个页面自己的逻辑、配置、结构、样式）。

本篇章从创建项目流程讲起，逐一拆解目录结构、全局文件（app.js / app.json / app.wxss）、页面四件套（js / json / wxml / wxss）、project.config.json 与 sitemap.json 的职责。掌握这些约定后，后续篇章的所有代码示例都将建立在「页面四件套 + 全局文件」这个基本盘上。

```text
项目创建与目录结构的核心要点：
1. 两种身份 —— 测试号免注册只能体验，正式 AppID 才能上传发布
2. 全局三件套 —— app.js 启动逻辑、app.json 全局配置、app.wxss 全局样式
3. 页面四件套 —— 每个页面由 js/json/wxml/wxss 四个同名文件组成
4. 文件同名约束 —— 四件套文件名必须一致，且目录名与文件名相同
5. 项目配置 —— project.config.json 是工具的项目配置，随仓库共享
6. 搜索配置 —— sitemap.json 控制页面是否被微信索引收录
```

## 创建项目流程

打开微信开发者工具，首页有「新建项目」与「导入项目」两个入口。新建项目需要填写三组信息：项目名称（本地标识，不要求与线上名称一致）、目录（本地空文件夹，工具会在此生成工程）、AppID（可填正式 AppID 或选择「测试号」）。模板选择上，基础模板有「JavaScript 基础模板」与「TypeScript 基础模板」，另有「云开发模板」；后端服务选项有「不使用云服务」与「使用云开发」。本知识库的架构是「小程序 + SpringBoot 自有后台」，因此统一选择「不使用云服务」。

测试号与正式 AppID 是新手最容易混淆的一对概念：测试号不需要注册任何账号，在工具中直接可选，秒级创建项目，但不能上传发布、没有正式接口权限、不能绑定真实业务域名，只适合体验与学习；正式 AppID 需要先按 01.2 注册小程序账号，创建后具备完整能力。导入项目则用于打开已有代码：选择项目目录，工具自动读取 project.config.json 识别 AppID 与编译设置。

```json
{
  "项目名称": "hello-miniprogram（本地标识，可随意）",
  "目录": "本地空文件夹，工具在此生成工程",
  "AppID": "正式 AppID（wx 开头）或测试号",
  "后端服务": {
    "不使用云服务": "使用自有后台（SpringBoot），本知识库统一选择",
    "使用云开发": "使用微信云开发（云函数/云数据库/云存储）"
  },
  "模板": {
    "JavaScript 基础模板": "原生 JS，生成 utils/ 工具目录",
    "TypeScript 基础模板": "TS 类型系统，生成 typings/ 目录",
    "云开发模板": "含云函数目录 cloudfunctions/"
  }
}
```

```text
创建项目要点：
1. 测试号 vs AppID —— 测试号免注册但不可上传，正式项目必须用 AppID
2. 目录即工程 —— 选空文件夹，工具负责生成全部骨架文件
3. 云服务二选一 —— 用自有 SpringBoot 后台就选「不使用云服务」
4. 模板可后改 —— 模板只是初始代码，随时可以删改，不影响项目身份
5. 导入已有项目 —— 工具识别 project.config.json 自动恢复配置
6. 创建即编译 —— 创建完成后工具自动编译并在模拟器中运行
```

## 目录结构总览

一个由「JavaScript 基础模板」创建的默认项目，目录结构如下。理解每个文件属于「全局」还是「页面」，是理解小程序工程的第一步：

```text
hello-miniprogram/
├── app.js                  # 全局逻辑：App() 实例、onLaunch 等生命周期、globalData
├── app.json                # 全局配置：pages 页面注册、window、tabBar 等
├── app.wxss                # 全局样式：作用于所有页面的公共样式
├── project.config.json     # 项目配置：AppID、编译设置、基础库版本
├── project.private.config.json  # 本地私有配置：个人设置，不提交 Git
├── sitemap.json            # 搜索索引配置：控制页面是否被微信索引
├── utils/
│   └── util.js             # 工具函数模块（模板自带，可删可扩）
├── images/                 # 静态图片资源（模板自带示例图）
└── pages/
    └── index/              # 第一个页面目录
        ├── index.js        # 页面逻辑：Page() 实例、data、生命周期、事件处理
        ├── index.json      # 页面配置：覆盖全局 window 的页面级配置
        ├── index.wxml      # 页面结构：类似 HTML 的模板
        └── index.wxss      # 页面样式：只作用于本页面的样式
```

约定俗成的扩展目录（模板不生成，团队按需自建）：components/（自定义组件）、static/（静态资源）、api/（接口请求封装）、store/（全局状态）。目录规范是工程化的第一步，建议在项目创建初期就定下来，避免后期大规模重构。

```text
目录结构要点：
1. 全局文件在根 —— app.js / app.json / app.wxss 固定在项目根目录
2. 页面按目录组织 —— pages/ 下每个目录对应一个页面
3. 页面目录即路径 —— pages/index/index 对应目录 pages/index/ 下的同名文件
4. 同名约束 —— js/json/wxml/wxss 四个文件名必须与目录名一致
5. 约定目录 —— components/、api/、utils/ 等按团队规范扩展
6. 私有配置分离 —— project.private.config.json 不提交 Git，避免团队冲突
```

## 全局文件

app.js 是小程序的逻辑入口，通过 App() 构造器注册小程序实例。App() 接收一个对象，包含 onLaunch（小程序初始化完成时触发，全局只触发一次）、onShow（从后台进入前台）、onHide（从前台进入后台）等生命周期方法与 globalData（全局共享数据）。注意：app.js 中不能调用 getApp() 获取自身，页面中通过 getApp() 拿到全局实例。

app.json 是小程序的全局配置，最核心的是 pages 数组（注册所有页面，第一项是首页）与 window（导航栏、背景色等窗口表现）。app.json 的完整字段在「02.1-全局配置 app.json」中详解，这里先看一个最小可用配置。app.wxss 是全局样式表，作用于所有页面，通常存放公共样式：通用按钮、通用间距、主题色变量等，配合 rpx 单位（见 04.1）实现多机型适配。

```js
// app.js —— 全局逻辑入口
App({
  // 小程序初始化完成（全局只触发一次）
  onLaunch() {
    console.log('小程序启动')
    // 此处适合做：登录态检查、版本更新检查、全局配置拉取
    const accountInfo = wx.getAccountInfoSync()
    console.log('运行环境：', accountInfo.miniProgram.envVersion)
  },
  // 小程序从后台进入前台
  onShow() {
    console.log('小程序进入前台')
  },
  // 小程序从前台进入后台
  onHide() {
    console.log('小程序进入后台')
  },
  // 全局共享数据：任意页面通过 getApp().globalData 访问
  globalData: {
    userInfo: null,
    baseUrl: 'https://api.example.com'
  }
})
```

```json
{
  "pages": [
    "pages/index/index",
    "pages/logs/logs"
  ],
  "window": {
    "navigationBarBackgroundColor": "#ffffff",
    "navigationBarTitleText": "Hello Miniprogram",
    "navigationBarTextStyle": "black",
    "backgroundColor": "#f5f5f5"
  },
  "style": "v2",
  "sitemapLocation": "sitemap.json"
}
```

```wxss
/* app.wxss —— 全局样式，作用于所有页面 */
page {
  /* 页面根节点：背景色、字号等基础样式 */
  background-color: #f5f5f5;
  font-size: 28rpx;
  color: #333333;
}

/* 通用按钮样式：所有页面直接复用 class */
.btn-primary {
  background-color: #07c160;
  color: #ffffff;
  border-radius: 8rpx;
}

/* 通用容器 */
.container {
  padding: 24rpx;
  box-sizing: border-box;
}
```

```text
全局三件套要点：
1. app.js —— App() 注册实例，onLaunch 全局执行一次，globalData 全局共享
2. app.json —— pages 数组注册所有页面，第一项即首页；window 定义窗口表现
3. app.wxss —— 全局样式作用于所有页面，公共样式与主题变量放这里
4. 生命周期 —— app 级生命周期与页面级生命周期（05.3）不同，注意区分
5. 页面可覆盖 —— 页面自己的 json/wxss 优先级高于全局配置
6. getApp() —— 页面中通过 getApp() 获取全局实例，读取 globalData
```

## 页面四件套

小程序的每个页面由四个同名文件组成，放在 pages/ 下以页面名命名的目录中：xxx.js（页面逻辑）、xxx.json（页面配置）、xxx.wxml（页面结构）、xxx.wxss（页面样式）。四个文件缺一不可（json 可以留空对象但文件必须存在），文件名必须与目录名完全一致，例如 pages/index/ 目录下必须是 index.js / index.json / index.wxml / index.wxss。

分工上：js 用 Page() 构造器注册页面，定义 data（页面数据）与生命周期方法、事件处理函数；json 配置页面级的窗口表现（如 navigationBarTitleText），会覆盖 app.json 中 window 的同名属性；wxml 编写页面结构，通过 {{ }} 数据绑定引用 js 中的 data；wxss 编写页面样式，只作用于当前页面。页面之间的通信与数据流设计在 03.5 数据通信中展开，这里先看一个完整的最小页面。

```js
// pages/index/index.js —— 页面逻辑
Page({
  // 页面初始数据：wxml 中通过 {{ }} 绑定
  data: {
    message: 'Hello WeChat',
    userList: [
      { id: 1, name: '张三' },
      { id: 2, name: '李四' }
    ]
  },
  // 页面加载时触发，最早可用的生命周期
  onLoad(options) {
    console.log('页面加载，参数：', options)
  },
  // 点击按钮触发的自定义事件
  handleTap() {
    this.setData({
      message: '你点击了按钮'
    })
  }
})
```

```json
{
  "navigationBarTitleText": "首页",
  "navigationBarBackgroundColor": "#07c160",
  "navigationBarTextStyle": "white",
  "usingComponents": {}
}
```

```wxml
<!-- pages/index/index.wxml —— 页面结构 -->
<view class="container">
  <text class="title">{{ message }}</text>

  <button type="primary" bindtap="handleTap">点击我</button>

  <!-- 列表渲染：wx:for 遍历 data.userList -->
  <view wx:for="{{ userList }}" wx:key="id" class="user-item">
    <text>{{ item.name }}</text>
  </view>
</view>
```

```wxss
/* pages/index/index.wxss —— 页面样式，只作用于本页面 */
.title {
  font-size: 40rpx;
  font-weight: bold;
}

.user-item {
  padding: 16rpx 0;
  border-bottom: 1rpx solid #eeeeee;
}
```

```text
页面四件套要点：
1. 同名同目录 —— js/json/wxml/wxss 四件套文件名必须一致且与目录名相同
2. js 管逻辑 —— Page() 注册、data 数据、生命周期、事件处理
3. json 管配置 —— 页面级 window 配置，覆盖全局 window 同名属性
4. wxml 管结构 —— 数据绑定 {{ }}、列表渲染 wx:for、事件绑定 bindtap
5. wxss 管样式 —— 页面样式隔离，不污染其他页面
6. setData 通信 —— 逻辑层改数据必须用 this.setData，视图层才会更新
```

## 项目配置文件

project.config.json 是微信开发者工具的项目配置文件，记录 AppID、项目名称、编译设置、基础库版本（libVersion）等信息，随项目一起提交到 Git，团队共享。工具右上角「详情」面板中看到的大部分设置最终都会写入这个文件。高频字段：appid、projectname、compileType（miniprogram）、libVersion（编译使用的基础库版本）、setting（ES6 转 ES5、压缩、urlCheck 等开关）、condition（自定义编译模式，见 01.4）、packOptions.ignore（打包时忽略的文件）。

project.private.config.json 是工具的本地私有配置：个人的界面偏好、临时 AppID 覆盖、个人编译模式等写在这里，不随项目提交 Git（模板已自动加入 .gitignore）。当两个文件配置冲突时，private 配置优先。调试过程中遇到「改配置不生效」时，优先检查是不是 private 配置覆盖了项目配置。

```json
{
  "appid": "wx1a2b3c4d5e6f7g8h",
  "projectname": "hello-miniprogram",
  "compileType": "miniprogram",
  "libVersion": "3.4.10",
  "miniprogramRoot": "",
  "setting": {
    "es6": true,
    "postcss": true,
    "minified": true,
    "urlCheck": true,
    "coverView": true,
    "ignoreUploadUnusedFiles": true
  },
  "packOptions": {
    "ignore": [
      {
        "type": "folder",
        "value": "docs"
      }
    ]
  },
  "condition": {
    "miniprogram": {
      "list": []
    }
  }
}
```

```text
项目配置文件要点：
1. project.config.json —— 项目共享配置，随 Git 提交，团队保持一致
2. libVersion —— 编译使用的基础库版本，影响可用 API 与组件（详见 02.4）
3. setting 开关 —— es6 / postcss / minified / urlCheck 是最高频的四项
4. packOptions.ignore —— 打包时忽略 docs 等非业务目录，控制包体积
5. condition —— 自定义编译模式的持久化存储位置
6. private 配置优先 —— project.private.config.json 覆盖项目配置且不提交 Git
```

## sitemap 配置文件

sitemap.json 是微信小程序的搜索索引配置文件，决定哪些页面允许被微信索引（用户可通过微信搜索找到页面）。默认配置为允许索引全部页面：

```json
{
  "desc": "关于本文件的更多信息，请参考文档 https://developers.weixin.qq.com/miniprogram/dev/framework/sitemap.html",
  "rules": [
    {
      "action": "allow",
      "page": "*"
    }
  ]
}
```

rules 数组按顺序匹配，支持精确页面路径与通配符。action 为 allow（允许索引）或 deny（禁止索引）；page 为页面路径，可用 * 通配。匹配规则是「从上到下第一条命中即生效」，因此精确规则要写在通配规则前面。app.json 中的 sitemapLocation 字段指定 sitemap 文件的位置，默认值就是 "sitemap.json"。

```json
{
  "rules": [
    {
      "action": "allow",
      "page": "pages/home/home"
    },
    {
      "action": "allow",
      "page": "pages/goods/detail"
    },
    {
      "action": "deny",
      "page": "pages/user/order"
    },
    {
      "action": "allow",
      "page": "*"
    }
  ]
}
```

```text
sitemap 配置要点：
1. 默认全允许 —— 未配置时工具提示并默认允许索引全部页面
2. rules 顺序匹配 —— 第一条命中即生效，精确规则放前面
3. action —— allow 允许索引，deny 禁止索引
4. 通配符 —— page 支持 * 通配，常用于兜底规则
5. sitemapLocation —— app.json 中指定 sitemap 文件位置，默认 sitemap.json
6. 与隐私合规相关 —— 涉及用户隐私的页面（如订单）建议 deny
```

## 应用场景实战

### 场景一：用测试号创建第一个项目并跑通页面

不注册任何账号，十分钟内跑通第一个小程序：

```text
步骤：
1. 打开微信开发者工具，点击「+」新建项目
2. 项目名称填 my-first-app，目录选择本地新建的空文件夹
3. AppID 处点击「测试号」，后端服务选「不使用云服务」
4. 模板选「JavaScript 基础模板」，点击确定，工具自动编译
5. 在目录树中展开 pages/index/，双击 index.wxml 打开
6. 把 <text> 内容改为「我的第一个小程序」，保存
7. 观察模拟器：热重载自动刷新，页面文案已更新
8. 展开 app.json，把 window.navigationBarTitleText 改为「测试应用」
9. 再新建一个页面：右键 pages/ 目录 → 新建目录 detail → 新建四个同名文件
10. 在 app.json 的 pages 数组加入 "pages/detail/detail"，重新编译
```

通过这个场景理解两件事：第一，测试号让「无账号体验开发」成为可能；第二，新增页面必须完成「建目录 + 建四件套 + 注册 app.json」三步，缺一不可。

### 场景二：用正式 AppID 创建带 tabBar 的项目骨架

为正式项目搭建基础骨架：

```text
步骤：
1. 按 01.2 注册好小程序账号，拿到正式 AppID
2. 新建项目，AppID 填入正式值，模板选「JavaScript 基础模板」
3. 规划页面：首页 pages/home/home、列表 pages/list/list、我的 pages/mine/mine
4. 在 pages/ 下依次创建三个页面目录，每个目录创建四个同名文件
5. 编辑 app.json：pages 数组按「home → list → mine」顺序注册
6. 在 app.json 中添加 tabBar 配置，三个页面分别配图标与文字
7. 编辑 app.wxss 添加公共样式（页面背景、通用按钮）
8. 每个页面的 wxml 写一行占位文案，编译后在模拟器中点击 tabBar 切换
9. 确认无误后将项目初始化 Git 仓库，首次提交，project.private.config.json 自动被忽略
```

这个骨架就是后续篇章的载体：tabBar 全局配置的细节在 02.1，页面生命周期在 05.3，组件与 API 在 06-08 篇章逐步填充。

## 最佳实践与踩坑记录

### 最佳实践

1. 目录规范在创建项目当天就定下来：pages/ 放页面、components/ 放自定义组件、api/ 放接口封装、utils/ 放工具函数，避免后期大规模移动文件
2. 新增页面固定走「建目录 → 建四件套 → 注册 app.json」三步，并把首页放在 pages 数组第一位
3. project.config.json 纳入 Git 管理保证团队编译设置一致；project.private.config.json 绝不提交
4. 页面命名统一小写英文（home、goods-detail），避免中文与大小写混用导致路径歧义
5. 全局样式只放「真全局」的样式（主题色、通用按钮），页面独有样式放页面 wxss，避免样式互相污染
6. sitemap.json 保持显式配置：涉及用户隐私的页面 deny，公开内容页 allow
7. 学习阶段用测试号反复练手，但每个正式项目第一天就用正式 AppID 创建
8. 提交代码前检查 app.json 的 pages 数组与 pages/ 目录是否一致，避免漏注册导致线上页面白屏

### 踩坑记录

坑 1：测试号项目无法上传发布
结论：测试号创建的项目点「上传」按钮报错或没有该入口，无法形成体验版/正式版。
原因：测试号是免注册的匿名体验环境，没有真实账号身份，微信不允许其发布代码。
解法：正式项目必须用注册得到的 AppID 重新创建；测试号项目只用于学习模板与练手。

坑 2：页面四件套文件名不一致导致编译报错
结论：编译提示找不到文件，如「pages/index/index.js 不存在」或页面白屏。
原因：index.wxml 写成了 index.wxml、index.js 写成了 page.js 等，文件名与目录名不一致。
解法：检查页面目录下四个文件是否与目录名完全同名，Windows/macOS 注意大小写也要一致。

坑 3：新建页面没有注册到 app.json，跳转白屏
结论：点击跳转提示「page not found」或「pages/detail/detail 未找到」。
原因：小程序规定所有页面必须先注册进 app.json 的 pages 数组才能被路由访问。
解法：新增页面后立即在 pages 数组追加对应路径（不带 .json 后缀），再编译验证。

坑 4：页面文件放错位置，被工具忽略
结论：在 pages/ 外新建的页面编译时找不到，或文件不进包。
原因：工具按 app.json pages 数组解析页面路径，目录结构不匹配时文件不会参与编译。
解法：页面必须放在 pages/ 下且目录名与注册路径一致；业务代码不要散落在项目根目录。

坑 5：project.private.config.json 被提交进 Git 仓库
结论：团队协作时他人拉取代码后 AppID/编译设置被覆盖，出现奇怪冲突。
原因：private 配置优先于项目配置，提交后把个人设置（如本地 AppID 覆盖）带给了所有人。
解法：确认 .gitignore 包含 project.private.config.json；已误提交的从仓库中移除并提交删除记录。

坑 6：导入项目后工具提示「找不到 app.json」
结论：导入已有项目后编译报「app.json: File not found」。
原因：project.config.json 中 miniprogramRoot 指向的目录与真实代码位置不符，或项目不是小程序工程。
解法：检查 project.config.json 的 miniprogramRoot 字段；导入时确认选择的是包含 app.json 的目录。

坑 7：误选云开发模板，项目多出云函数目录
结论：项目创建后出现 cloudfunctions/ 目录与云开发依赖，本地编译报错或包体积异常。
原因：创建时选了「使用云开发」或云开发模板，生成了本知识库不需要的云函数骨架。
解法：删除 cloudfunctions/ 目录并检查 app.json 是否注册了云相关配置；后续统一用「不使用云服务」创建。

坑 8：删除模板自带的 app.wxss 样式后页面排版全乱
结论：删掉模板默认样式后，页面文字顶到屏幕边缘、间距全无。
原因：模板在 app.wxss 中定义了 page 根节点的 padding 与基础字号，删除后失去全局兜底样式。
解法：保留并改造 app.wxss 中的 page 基础样式，而不是整文件删除；样式规范见 04.1 与 02.5。

## 概述

写完代码只是开始，调试才是开发日常的主旋律。微信开发者工具提供了一条完整的调试链路：编译模式（控制「跑哪个页面、带什么参数」）→ 模拟器（本地快速验证）→ 真机预览（扫码在手机上跑）→ 真机调试（手机运行、电脑看日志与断点）→ 调试器面板（Console / Network / Storage / AppData / Wxml 各司其职）→ 代码上传（形成体验版供团队验收）。

本篇章把这六段链路逐一讲透：每种调试手段解决什么问题、在什么场景下用、常见失败怎么排查。调试能力直接决定开发效率——熟练使用编译模式与调试器面板，能让「定位一个问题」的时间从小时级降到分钟级。

```text
开发调试的核心要点：
1. 编译模式 —— 控制启动页面与启动参数，按需进入任意页面
2. 模拟器 —— 本地快速验证，覆盖率最高的日常调试手段
3. 真机预览 —— 扫码在真机运行，验证模拟器覆盖不了的能力
4. 真机调试 —— 手机运行 + 电脑查看日志/断点，联调利器
5. 调试器面板 —— Console 看日志、Network 看请求、AppData 看数据
6. 上传体验版 —— 代码进入微信服务器，团队扫码验收的起点
```

## 编译模式

工具默认的「普通编译」固定编译当前打开的页面；当项目页面变多，需要直接进入某个二级页面（如商品详情、订单列表）调试时，就要用到编译模式。编译模式的核心价值是「跳过入口流程，直达目标页面，并携带指定参数」——例如直接以 id=10086 打开商品详情页，而不必每次从首页点击进入。

添加编译模式：点击工具栏编译按钮旁的下拉箭头 → 「添加编译模式」→ 填写模式名称、选择启动页面、填写启动参数（query，格式如 id=10086&type=hot）、选择进入场景（scene 场景值，模拟用户从不同入口进入，如 1001 表示发现栏小程序主入口）。配置保存在 project.config.json 的 condition 字段中，随项目提交共享。多个编译模式可以随时切换，也可以删除；「下次编译时模拟」选项用于在编译时模拟指定场景。

```js
// 页面 onLoad 的 options 参数即编译模式中填写的启动参数
Page({
  data: {
    goodsId: ''
  },
  onLoad(options) {
    // 编译模式启动参数示例：id=10086&type=hot
    // options = { id: '10086', type: 'hot' }
    console.log('接收到的参数：', options)
    this.setData({
      goodsId: options.id || ''
    })
    // 用参数请求商品详情（详见 08.1 网络请求）
    wx.request({
      url: 'https://api.example.com/goods/detail',
      data: { id: options.id },
      success: (res) => {
        console.log('商品数据：', res.data)
      }
    })
  }
})
```

```json
{
  "condition": {
    "miniprogram": {
      "list": [
        {
          "name": "商品详情-热销",
          "pathName": "pages/goods/detail",
          "query": "id=10086&type=hot",
          "scene": 1001,
          "launchMode": "default"
        },
        {
          "name": "订单列表",
          "pathName": "pages/order/list",
          "query": "status=paid",
          "scene": 1011
        }
      ]
    }
  }
}
```

```text
编译模式要点：
1. 直达页面 —— 编译模式直接以目标页面启动，跳过入口流程
2. 启动参数 —— query 以 key=value&key=value 格式填写，onLoad 的 options 接收
3. 场景值 scene —— 模拟用户从不同入口进入，验证来源统计与分流逻辑
4. 持久化 —— 编译模式保存在 project.config.json 的 condition 中，随仓库共享
5. 多模式切换 —— 下拉框随时切换，不需要的删除即可
6. 普通编译 —— 无自定义模式时编译当前打开页，日常开发够用
```

## 模拟器调试

模拟器是最高频的调试环境：保存代码 → 热重载自动刷新（或手动点「编译」），就能在模拟器中看到最新效果。模拟器工具栏提供三项关键能力：机型切换（常见 iPhone、Android 机型与屏幕尺寸，验证 rpx 适配）、网络模拟（Wi-Fi / 4G / 3G / 2G / 离线，验证弱网与断网逻辑）、清缓存（清除数据缓存、文件缓存、授权数据，模拟用户首次启动场景）。

模拟器调试的操作节奏建议：改 wxml/wxss 观察布局 → 改 js 用 Console 看日志 → 用 AppData 面板核对数据 → 用 Network 面板确认接口 → 切换机型与网络模拟做兼容验证。需要强调的是模拟器的边界：扫码、真实定位、传感器、性能表现、微信支付在模拟器中不可信或不可用，这些能力一律真机验证。

```js
// 模拟器网络模拟配合代码演示：弱网提示
Page({
  onLoad() {
    this.checkNetwork()
  },
  checkNetwork() {
    wx.getNetworkType({
      success: (res) => {
        // 模拟器网络切换为「离线」时，此处输出 networkType: none
        console.log('当前网络：', res.networkType)
        if (res.networkType === 'none') {
          wx.showToast({ title: '网络不可用，请检查网络', icon: 'none' })
        }
      }
    })
  }
})
```

模拟器工具栏左侧还有「操作」相关按钮：刷新（重新编译当前页面）、清缓存（下拉菜单区分「清除数据缓存」「清除文件缓存」「清除授权数据」「清除全部」）、更多工具（截屏、模拟地理位置等）。调试定位相关页面时，可以在模拟器中直接设置模拟位置（经纬度），配合 permission 配置验证「附近门店」类业务；扫码能力在模拟器中通过「模拟扫码」入口输入或粘贴二维码内容来触发。这些模拟能力能覆盖大部分开发期验证需求，但仍要以真机结果为准。

```text
模拟器调试要点：
1. 热重载 —— 保存代码自动刷新模拟器，关闭后需手动编译
2. 机型切换 —— 验证不同屏幕宽度下 rpx 布局是否正常
3. 网络模拟 —— 4G/3G/2G/离线四种状态，覆盖弱网分支
4. 清缓存 —— 清除授权与缓存后重编译，模拟冷启动与首次授权
5. 调试节奏 —— 布局看模拟器、日志看 Console、数据看 AppData、接口看 Network
6. 边界明确 —— 扫码/定位/支付/性能必须真机验证
```

## 真机预览与真机调试

模拟器跑通了不等于真机没问题。真机预览：点击工具栏「预览」，工具生成二维码，用手机微信扫码即可在真机上打开小程序（开发版）。预览二维码有一定有效期，过期后重新点击「预览」生成即可；预览时手机与电脑不要求同一网络，但如果小程序请求的是本地开发机的接口（如 http://192.168.x.x:8080），需要手机与电脑在同一局域网，且工具已勾选「不校验合法域名」。

真机调试与预览不同：预览只是「看效果」，真机调试是「边运行边查」。点击工具栏「真机调试」，手机扫码后，小程序在手机真机运行，电脑端实时展示 Console 日志、Network 请求、Storage 数据与 AppData，支持断点调试与单步执行。真机调试 1.0 要求手机与电脑处于同一局域网，连接不稳定时优先排查网络与防火墙；真机调试 2.0 通过云端通道连接，对网络环境要求更低。真机调试适合排查：接口联调（真机网络环境）、定位/扫码等硬件能力、真机渲染表现。

```js
// 真机调试典型场景：对比真机与模拟器的接口表现
Page({
  onLoad() {
    // 真机调试时，这里的 console.log 会实时出现在电脑端 Console 面板
    console.log('页面 onLoad 触发，当前时间戳：', Date.now())
    wx.request({
      url: 'https://api.example.com/login',
      method: 'POST',
      data: { code: 'mock-code' },
      success: (res) => {
        // 在 Network 面板查看该请求的完整响应
        console.log('登录接口响应：', res.statusCode, res.data)
      },
      fail: (err) => {
        console.error('登录接口失败：', err)
      }
    })
  }
})
```

```text
真机预览与真机调试要点：
1. 预览 —— 生成二维码扫码打开开发版，验证真机表现
2. 预览二维码有时效 —— 过期重新生成即可，不涉及代码上传
3. 局域网接口 —— 请求本地开发机接口需手机电脑同一局域网
4. 真机调试 —— 手机运行 + 电脑看日志/断点，联调与排查利器
5. 网络要求 —— 真机调试 1.0 需同一局域网，2.0 走云端通道
6. 使用场景 —— 接口联调、定位扫码等硬件能力、真机渲染差异排查
```

## 调试器面板

调试器位于工具下方（可拖拽调整位置与大小），是问题定位的主战场。核心面板：Console（日志与交互执行）、Sources（JS 源码断点调试）、Network（网络请求列表与详情）、Storage（本地缓存 key-value 查看与删除）、AppData（当前页面 data 的实时查看与修改）、Wxml（渲染后的节点树与样式，类似浏览器 Elements）。另有 Sensor（模拟陀螺仪等传感器数据）、Trace（性能追踪）、Mock（接口数据模拟）等扩展面板。

Wxml 面板的使用要点：编译后查看页面真实渲染的节点结构，点击节点右侧显示该节点的 class、style 与生效样式，可用于排查「样式为什么没生效」；AppData 面板显示当前页面 data 树，展开可实时修改字段值，修改会同步到页面渲染（等效于一次 setData），调试数据流非常高效；Storage 面板对应 wx.setStorageSync 写入的本地缓存，可逐条查看、删除，也可一键清空。

```js
// 配合 Storage 与 AppData 面板演示：缓存写入与读取
Page({
  onLoad() {
    // 写入后可在调试器 Storage 面板看到该条记录
    wx.setStorageSync('user_token', 'token-abc-123')
    // 页面数据写入后可在 AppData 面板实时查看与修改
    this.setData({
      userInfo: { nickname: '小明', level: 3 }
    })
  }
})
```

Sources 面板的断点调试对复杂逻辑很有价值：打开对应 js 文件，在行号处点击即可下断点，代码执行到断点处暂停，可单步执行（Step Over / Step Into）并查看当前作用域变量。断点配合 Console 面板的交互执行，几乎能还原浏览器 DevTools 的完整调试体验。需要注意：断点调试只对逻辑层 JS 生效，WXML 模板中的渲染问题要用 Wxml 面板排查，两者分工不同。

```text
调试器面板要点：
1. Console —— 日志输出与交互执行，小程序调试最常用的面板
2. Sources —— 源码断点调试，定位逻辑错误
3. Network —— 请求列表与详情，排查接口问题
4. Storage —— 本地缓存查看/删除，验证缓存逻辑
5. AppData —— 当前页 data 实时查看修改，修改即时反映到渲染
6. Wxml —— 渲染节点树与样式排查，类似浏览器 Elements
```

## Console 与 Network

Console 面板承载日志：console.log 输出普通信息、console.warn 输出黄色警告、console.error 输出红色错误（带堆栈）。面板顶部可按 All / Info / Warn / Error 过滤级别，日志过多时用过滤快速聚焦；Console 内可直接输入 JS 表达式执行（如 wx.getSystemInfoSync()），在 wx 命名空间下做交互式实验非常方便。小程序逻辑层的 console 输出全部汇聚到 Console 面板，真机调试时手机上的日志也会实时回流。

Network 面板承载网络请求：每次 wx.request / wx.uploadFile / WebSocket 都会记录一条请求，点击查看请求头、响应头、响应体、状态码与耗时。高频排查场景：状态码 404 说明接口路径或域名不对；500 说明服务端异常；请求没出现在列表说明代码没执行到；「url not in domain list」报错说明域名未配置到合法域名或未勾选「不校验合法域名」。Console 与 Network 配合使用是接口联调的黄金组合：Console 看业务日志与错误堆栈，Network 看请求细节与响应数据。

```js
// Console 与 Network 配合排查接口问题的典型代码
Page({
  fetchGoodsList() {
    console.log('开始请求商品列表')
    wx.request({
      url: 'https://api.example.com/goods/list',
      data: { page: 1, size: 10 },
      success: (res) => {
        // 在 Network 面板核对这里的 statusCode 与耗时
        console.log('接口状态码：', res.statusCode)
        if (res.statusCode === 200) {
          console.log('商品列表数据：', res.data)
        } else {
          console.warn('接口异常状态码：', res.statusCode)
        }
      },
      fail: (err) => {
        // 域名校验失败等网络层错误会走到这里
        console.error('请求失败：', err.errMsg)
      }
    })
  }
})
```

```text
Console 与 Network 要点：
1. 日志分级 —— log 信息 / warn 警告 / error 错误（带堆栈）
2. 级别过滤 —— 日志刷屏时用 All/Info/Warn/Error 过滤
3. 交互执行 —— Console 可直接输入 wx.xxx 表达式做实验
4. 请求详情 —— Network 查看状态码、请求头、响应体、耗时
5. 常见状态码 —— 404 路径问题、500 服务端异常、200 正常
6. 域名报错 —— url not in domain list 需配合法域名或勾选不校验
```

## 代码上传与体验版

模拟器与真机调试都只是本地行为，要让团队成员（甚至客户）在手机上稳定验收，需要把代码上传到微信服务器形成体验版。操作路径：工具栏点击「上传」→ 填写版本号（建议语义化，如 1.0.0、1.2.1）与项目备注 → 确认上传。上传前置条件：当前微信号是小程序后台的项目成员/管理员，且项目配置的 AppID 是正式 AppID（测试号无法上传）。

上传成功后，代码进入 mp 后台的「管理 → 版本管理 → 开发版本」列表。在开发版本上点击「选为体验版」即可生成体验版二维码；体验版只有「体验成员」能扫码打开，体验成员在后台「成员管理 → 体验成员」中添加（支持通过微信扫码批量添加）。体验版、开发版、正式版在代码中可以通过 wx.getAccountInfoSync().miniProgram.envVersion 区分（develop / trial / release），用于环境差异化逻辑。体验版验收通过后再走「提交审核 → 发布」流程（详见 16.1 版本管理与提审）。

```js
// 体验版环境识别：体验版与正式版走不同逻辑的经典写法
App({
  onLaunch() {
    const accountInfo = wx.getAccountInfoSync()
    const env = accountInfo.miniProgram.envVersion
    // develop: 开发版（工具预览/真机调试） trial: 体验版 release: 正式版
    if (env === 'trial') {
      console.log('体验版环境，启用验收模式')
    }
    if (env === 'release') {
      console.log('正式版环境')
    }
  }
})
```

上传前建议做一遍快速自查：把「详情 → 本地设置」中的 urlCheck（合法域名校验）临时打开并编译一次，确认没有非法域名报错；核对 libVersion 与目标基础库一致（详见 02.4）；清理掉 console.log 调试噪音，至少确认没有刷屏日志；确认 project.config.json 的 ignoreUploadUnusedFiles 已开启以减小包体积。把这些检查固定成「上传前 checklist」，能大幅减少体验版「翻车」的次数。

```text
代码上传与体验版要点：
1. 上传前置 —— 需项目成员权限 + 正式 AppID，测试号不能上传
2. 版本号 —— 建议语义化（1.0.0），与后台版本管理对齐
3. 开发版本 —— 上传后出现在 mp 后台版本管理列表
4. 体验版 —— 开发版本「选为体验版」后生成体验二维码
5. 体验成员 —— 后台添加，只有体验成员能扫码打开体验版
6. envVersion —— develop / trial / release 三环境区分，驱动差异化逻辑
```

## 应用场景实战

### 场景一：用编译模式直调商品详情页并带参数

不点首页，直接进入二级页面调试：

```text
步骤：
1. 点击工具栏编译按钮旁的下拉箭头，选择「添加编译模式」
2. 模式名称填「商品详情-调试」，启动页面选 pages/goods/detail
3. 启动参数填 id=10086&type=hot，进入场景保持默认（或选 1001）
4. 点击确定后工具按新模式编译，模拟器直接打开商品详情页
5. 在 detail.js 的 onLoad 中打印 options，Console 面板确认收到 { id: '10086', type: 'hot' }
6. 用 Network 面板确认详情接口请求带了 id=10086 参数
7. 需要模拟其他商品时，修改编译模式的 query 再编译即可
8. 调试完成后，在编译模式下拉框删除该模式，恢复普通编译
```

这个场景把「编译模式 + Console + Network」串成一条线，是页面级联调的标准姿势。

### 场景二：真机调试排查登录接口联调问题

模拟器正常但真机登录失败时的排查流程：

```text
步骤：
1. 手机与电脑接入同一局域网（真机调试 1.0 要求）
2. 点击工具栏「真机调试」，手机微信扫码
3. 手机端进入登录页，点击登录按钮触发 wx.login 与登录接口
4. 电脑端调试器 Console 面板观察日志：确认 onLoad 与登录方法执行到哪一步
5. 切换 Network 面板：确认登录请求是否发出、状态码与响应体
6. 若报 url not in domain list：确认工具已勾选「不校验合法域名」或后台已配置合法域名
7. 若请求本地开发机接口失败：确认手机与电脑同一局域网，且服务端监听 0.0.0.0
8. 用 AppData 面板核对登录成功后的 token 是否写入页面 data
9. 用 Storage 面板确认 token 是否写入本地缓存
10. 问题定位后断开真机调试，修复代码重新编译再验证
```

真机调试的价值在于「真机环境 + 完整面板」：网络环境、证书、定位等模拟器覆盖不了的问题，在真机调试中一览无余。

## 最佳实践与踩坑记录

### 最佳实践

1. 为每个核心二级页面配置一个编译模式（带典型参数），把「点进二级页」的成本降为零
2. 定位问题按固定顺序排查：Console 看日志 → Network 看请求 → AppData 看数据 → Wxml 看渲染，不要跳步
3. 接口联调优先真机调试，模拟器的网络环境与真机差异较大（证书、运营商网络、代理）
4. 上传前在本地把 urlCheck（合法域名校验）打开跑一遍，把域名问题消灭在上传前
5. 版本号统一语义化（主.次.修订），备注写清本次改动点，方便版本回溯
6. 体验成员在项目初期就添加好（开发、测试、产品、关键客户），避免验收时临时加人等待
7. 用 envVersion 区分开发版/体验版/正式版逻辑，但正式版要避免输出敏感调试日志
8. 真机调试 1.0 连不上时先查同一局域网与防火墙，而不是反复重试扫码

### 踩坑记录

坑 1：预览二维码过期，扫码打不开
结论：扫码提示「二维码已过期」或页面空白无法打开。
原因：预览二维码有一定有效期，长时间未使用或重新编译后二维码失效。
解法：在工具中重新点击「预览」生成新二维码；批量验收场景改用体验版二维码（长期有效）。

坑 2：真机调试 1.0 扫码后一直连接中
结论：手机扫码后停在「连接中」，电脑端迟迟不进入调试态。
原因：真机调试 1.0 要求手机与电脑同一局域网，公司 Wi-Fi 的 AP 隔离、防火墙策略会阻断通道。
解法：确认同一 Wi-Fi；关闭手机 VPN 与电脑防火墙；仍失败则切换到真机调试 2.0（云端通道）。

坑 3：Network 面板看不到请求记录
结论：接口明明调了，Network 面板却没有对应请求。
原因：Network 面板未选中、请求发生在编译后较早时刻被清空、或代码分支没走到 wx.request。
解法：在请求代码前后加 console.log 确认执行路径；面板顶部筛选确认类型正确；必要时清空列表后重新触发请求。

坑 4：console.log 输出在 Console 面板看不到
结论：代码里写了 console.log，面板无输出。
原因：Console 面板当前处于过滤状态（如只显示 Error）、调试器被折叠、或日志级别被过滤。
解法：将过滤切到 All；展开调试器；确认日志确实执行（加 debugger 或临时用 wx.showToast 验证）。

坑 5：真机表现与模拟器不一致，无从下手
结论：模拟器正常，真机出现样式错位、接口失败或白屏。
原因：基础库版本差异、真机网络环境（证书/域名校验）、rpx 在不同屏宽下的表现差异。
解法：用真机调试观察真机日志与请求；确认工具 libVersion 与线上基础库一致（见 02.4）；多机型预览验证。

坑 6：上传后体验版打开白屏
结论：上传成功，体验版扫码打开空白或报错。
原因：本地勾选了「不校验合法域名」而真机校验域名失败；或基础库版本低于代码要求；或上传时未重新编译导致代码陈旧。
解法：上传前重新编译并临时打开 urlCheck 验证；核对 libVersion；检查 Console 中真机报错信息。

坑 7：体验版扫码提示无权限
结论：扫码体验版提示「不在体验成员名单中」或无权访问。
原因：体验版只对体验成员开放，当前微信不在后台的体验成员列表中。
解法：在 mp 后台「成员管理 → 体验成员」添加该微信号；管理员也可在版本管理页面直接邀请。

坑 8：编译模式参数不生效
结论：编译模式配了 query，页面 onLoad 收到的 options 为空。
原因：参数没保存、编译后未重新编译、或页面被其他入口（如 tabBar 首页）启动。
解法：保存编译模式后重新编译；确认启动页面与参数格式（key=value 用 & 连接）；调试 tabBar 页面时注意 switchTab 不携带参数。

坑 9：上传提示没有权限
结论：点「上传」提示「无权限」或按钮置灰。
原因：当前微信号不是小程序后台项目成员，或项目用的是测试号。
解法：在 mp 后台「成员管理」添加项目成员；测试号项目换正式 AppID 重建。

## 概述

小程序商业化最直接的路径是接入微信广告（流量主）。流量主在小程序内展示广告位，微信按展示/点击产生广告收入，收益按月结算到账户。广告形式主要有 banner 横幅、激励视频、插屏、原生模板、视频贴片等，选择哪种形式取决于产品形态与用户场景：工具类适合激励视频与插屏，内容类适合 banner 与原生模板。

```text
广告与商业化要点：
1. 流量主 —— 小程序累计独立访客 1000+ 可开通，主体需非个人
2. 广告形式 —— banner / 激励视频 / 插屏 / 原生模板 / 视频贴片
3. 广告位 —— 后台创建广告位获取 ad-unit-id，代码里用 ad 组件加载
4. 收益 —— 按展示（CPM）与点击（CPC）计费，微信分成结算
5. 合规 —— 广告内容审核、位置规范、不可诱导点击
6. 优化 —— 填充率、eCPM、展示时机影响最终收益
```

## 流量主开通

流量主是微信广告的供给侧身份。小程序满足条件后即可在小程序后台开通流量主功能，开通后创建广告位，把广告位 ID（ad-unit-id）填进代码的 ad 组件。

```text
流量主开通条件：
1. 累计独立访客（UV）达到 1000 以上
2. 主体类型非个人（企业、个体工商户等）
3. 小程序内容合规，无违规记录
4. 已发布上线（体验版与开发版不计入 UV）
```

开通流程：

```text
开通步骤：
1. 小程序后台进入「流量主」模块，查看开通进度（UV 达标后出现开通入口）
2. 阅读并签署《微信广告服务协议》
3. 创建广告位：选择广告形式（banner/激励视频/插屏/原生模板），填写广告位名称
4. 获取 ad-unit-id（每个广告位唯一，格式 adunit-xxxxxxxxxxxxxxxx）
5. 在代码中引用 ad 组件或 API，填入 ad-unit-id
6. 提交审核通过后，广告位开始填充广告
```

流量主收益构成：

```text
收益模型：
1. CPM（千次展示成本）—— 每千次展示的收入，banner 与插屏主要靠这个
2. CPC（单次点击成本）—— 每次点击的收入，激励视频与原生广告主要靠这个
3. 分成比例 —— 微信按协议分成（开发者拿大头），结算到流量主账户
4. 结算周期 —— 月度结算，达到结算门槛后提现到对公账户/个人账户
5. 收入波动 —— 受广告主投放、季节、类目、eCPM 影响
```

## banner 广告

banner 广告是嵌入页面内容区的横幅广告，展示在页面顶部、底部或内容中间。实现方式：在 WXML 中放置 ad 组件，绑定 ad-unit-id。

```xml
<!-- pages/index/index.wxml -->
<view class="page">
  <!-- 顶部 banner 广告位 -->
  <ad unit-id="adunit-xxxxxxxxxxxxxxxx" binderror="onAdError" />
</view>
```

```js
// pages/index/index.js
Page({
  onAdError(e) {
    console.error('banner 广告加载失败', e.detail)
    // 广告位加载失败不影响页面功能，静默处理
  }
})
```

```text
banner 广告要点：
1. 位置 —— 页面顶部/底部/内容间，不能遮挡操作区
2. 尺寸 —— 宽度自适应屏幕，高度按广告类型固定
3. 加载 —— ad 组件自动加载，失败触发 binderror
4. 注意 —— 一个页面不建议堆多个 banner，影响体验且可能被判违规
5. eCPM —— banner 广告 eCPM 相对低，适合流量大的页面
```

## 激励视频

激励视频是用户主动观看完整视频后获得奖励（积分、道具、解锁功能）的广告形式，是工具类、游戏类小程序最主要的变现方式。用户看广告前需要明确「看完得奖励」的预期，看完后通过回调发放奖励。

```xml
<!-- pages/game/game.wxml -->
<ad
  unit-id="adunit-xxxxxxxxxxxxxxxx"
  ad-type="video"
  ad-theme="white"
  bindload="onVideoLoad"
  binderror="onVideoError"
  bindclose="onVideoClose"
/>
```

```js
// pages/game/game.js
Page({
  data: { videoAdReady: false },
  onLoad() {
    // 创建激励视频广告实例（推荐方式：wx.createRewardedVideoAd）
    this.videoAd = wx.createRewardedVideoAd({
      adUnitId: 'adunit-xxxxxxxxxxxxxxxx'
    })
    this.videoAd.onLoad(() => {
      this.setData({ videoAdReady: true })
    })
    this.videoAd.onError((err) => {
      console.error('激励视频加载失败', err)
    })
    this.videoAd.onClose((res) => {
      if (res && res.isEnded) {
        // 用户完整看完视频，发放奖励
        this.grantReward()
      } else {
        // 中途退出，不发放奖励，提示用户
        wx.showToast({ title: '看完视频才能领奖励', icon: 'none' })
      }
    })
  },
  watchVideo() {
    if (!this.data.videoAdReady) {
      wx.showToast({ title: '广告加载中，稍后再试', icon: 'none' })
      return
    }
    this.videoAd.show().catch(() => {
      // 重新加载后再次展示
      this.videoAd.load().then(() => this.videoAd.show())
    })
  },
  grantReward() {
    // 调用后端发放奖励（积分/道具），防止前端伪造
    wx.request({
      url: 'https://api.example.com/reward',
      method: 'POST',
      data: { type: 'video' },
      success: () => {
        wx.showToast({ title: '奖励已发放', icon: 'success' })
      }
    })
  }
})
```

```text
激励视频要点：
1. 创建方式 —— 推荐 wx.createRewardedVideoAd 实例化管理
2. 奖励判定 —— onClose 的 res.isEnded 判断是否完整观看
3. 防刷 —— 奖励发放必须走后端校验，不能只信前端回调
4. 兜底 —— show() 失败要 load() 后重试，避免用户看不了广告
5. 场景 —— 复活、翻倍奖励、解锁道具、免费次数
6. 频控 —— 同一用户一天观看次数要限制，防止薅羊毛
```

## 插屏广告

插屏广告是在页面切换、操作间隙展示的全屏广告，展示时机由开发者控制（wx.createInterstitialAd）。插屏的 eCPM 比 banner 高，但打断感强，展示频率要克制。

```js
// app.js 或页面中
App({
  onLaunch() {
    // 创建插屏广告实例（全局或页面级）
    this.interstitialAd = wx.createInterstitialAd({
      adUnitId: 'adunit-xxxxxxxxxxxxxxxx'
    })
    if (this.interstitialAd) {
      this.interstitialAd.onError((err) => {
        console.error('插屏广告错误', err)
      })
    }
  },
  showInterstitial() {
    if (this.interstitialAd) {
      this.interstitialAd.show().catch(() => {
        // 展示失败（频率限制等），静默处理
      })
    }
  }
})
```

```text
插屏广告要点：
1. 展示时机 —— 页面跳转、返回首页、操作完成后的间隙
2. 频率限制 —— 微信侧有展示频率限制，开发者侧也要控制
3. 打断感 —— 高频展示会流失用户，重要操作前不要弹
4. 失败处理 —— show() 失败多为频率限制，catch 静默
5. eCPM —— 插屏 eCPM 高于 banner，低于激励视频
6. 合规 —— 不能误触、不能诱导点击关闭按钮
```

## 广告收益优化

广告收益不是「加了广告位就有钱」，需要从填充率、eCPM、展示频控、用户体验四个维度持续调优。

```text
收益优化策略：
1. 广告位布局 —— 高流量页面放广告位，低频页面不放
2. 形式搭配 —— 激励视频做主要变现（工具/游戏），banner 做流量补充
3. 展示时机 —— 插屏在「完成一个操作」后展示，转化率最高
4. 频控平衡 —— 展示多了收益高但流失大，找到平衡点（一般每人每天 3-5 次插屏）
5. 激励场景设计 —— 让用户「主动想看广告」：翻倍、加速、解锁
6. 数据复盘 —— 关注填充率/eCPM/点击率，低于行业均值排查原因
7. 合规底线 —— 禁止诱导点击、遮挡关闭按钮、误触广告
```

```text
合规红线（违反会被封禁广告功能）：
1. 诱导点击 —— 引导用户点击广告获取奖励
2. 遮挡 —— 广告上叠透明层诱导误触
3. 频繁弹出 —— 插屏过度展示
4. 违规内容 —— 广告内容与小程序定位不符的投诉
5. 虚假宣传 —— 广告位标注虚假收益
6. 未成年人 —— 面向未成年人的广告内容合规审核
```

## 应用场景实战

### 场景一：工具类小程序激励视频变现

以「证件照制作」小程序为例，核心功能免费，高级功能（高清导出、去水印）通过看激励视频解锁。

```js
// pages/make/make.js
Page({
  data: {
    rewardAd: null,
    remainFree: 3 // 每天免费导出次数
  },
  onLoad() {
    this.rewardAd = wx.createRewardedVideoAd({
      adUnitId: 'adunit-xxxxxxxxxxxxxxxx'
    })
    this.rewardAd.onClose((res) => {
      if (res && res.isEnded) {
        this.unlockExport()
      }
    })
  },
  onExportTap() {
    if (this.data.remainFree > 0) {
      this.exportImage()
      return
    }
    // 免费次数用完，看广告解锁
    wx.showModal({
      title: '今日免费次数已用完',
      content: '观看视频广告可立即解锁高清导出',
      confirmText: '看广告解锁',
      success: (res) => {
        if (res.confirm) {
          this.rewardAd.show().catch(() => {
            this.rewardAd.load().then(() => this.rewardAd.show())
          })
        }
      }
    })
  },
  unlockExport() {
    // 后端校验 + 记录解锁
    wx.request({
      url: 'https://api.example.com/unlock',
      method: 'POST',
      data: { type: 'export' },
      success: () => this.exportImage()
    })
  },
  exportImage() {
    // 真实导出逻辑
  }
})
```

### 场景二：内容类小程序多广告位组合

以「资讯阅读」小程序为例，首页 banner + 文章详情页底部 banner + 阅读 3 篇后插屏的组合。

```xml
<!-- pages/detail/detail.wxml -->
<view class="article">
  <rich-text nodes="{{content}}" />
</view>
<!-- 文章底部 banner -->
<ad unit-id="adunit-banner-detail" />
```

```js
// pages/detail/detail.js
Page({
  data: { readCount: 0 },
  onLoad() {
    // 全局创建的插屏实例（app.js 里创建）
    const app = getApp()
    this.interstitial = app.interstitialAd
  },
  onArticleRead() {
    const count = this.data.readCount + 1
    this.setData({ readCount: count })
    // 每读 3 篇展示一次插屏
    if (count % 3 === 0 && this.interstitial) {
      this.interstitial.show().catch(() => {})
    }
  }
})
```

```text
组合策略：
1. banner —— 常驻流量位，页面底部
2. 插屏 —— 阅读里程碑触发（每 3 篇），频率可控
3. 激励视频 —— 评论/收藏等互动行为后奖励
4. 原生模板 —— 信息流中插入原生样式广告，体验更好
5. 数据监控 —— 每个广告位单独统计 eCPM 与填充率
```

## 最佳实践与踩坑记录

### 最佳实践

1. 广告位创建后先在体验版验证，确认填充正常再提审发布
2. 激励视频奖励发放一律走后端接口校验，前端回调只能作为触发信号
3. 插屏广告用全局实例（App 里创建），避免每个页面重复创建
4. 广告加载失败（binderror/onError）要静默处理，绝不能阻塞业务功能
5. 高频操作场景（支付完成、提交成功）不做广告打断，用户最反感
6. 用埋点统计每个广告位的曝光/点击/收益，每周复盘调优

### 踩坑记录

坑 1：体验版测试时广告位一直不填充
结论：体验版/开发版看不到广告或填充率极低。
原因：广告填充与账号 UV、广告主投放、测试环境有关，新广告位有冷启动期。
解法：用真实环境多机型测试；关注后台「流量主-数据」看填充率，冷启动期正常 1-3 天。

坑 2：激励视频看完没触发奖励
结论：用户完整看完视频，但 onClose 没触发或奖励没发。
原因：onClose 注册时机在 show 之后、广告实例被重新创建、回调里判断条件写错。
解法：onLoad 时就注册 onClose；用实例方法管理（createRewardedVideoAd 单例）；奖励发放走后端防重复。

坑 3：插屏广告频繁弹窗被用户投诉
结论：用户差评、卸载，甚至投诉广告骚扰。
原因：展示时机设计不合理（进页面就弹、每次返回都弹）。
解法：控制频率（每人每天最多 3-5 次）、只在关键里程碑展示、加开关可关闭。

坑 4：诱导点击广告被判违规
结论：广告功能被封禁，收益清零。
原因：广告位上加「点击领红包」等诱导文案，或透明遮罩诱导误触。
解法：广告位周围不放置诱导元素，保持广告独立展示；收到违规通知立即整改并申诉。

坑 5：流量主开通条件不满足
结论：后台看不到流量主入口。
原因：累计独立访客未达 1000，或主体是个人类型。
解法：先提升 UV（分享、搜索优化）；个人主体无法开通，需升级企业主体。

坑 6：广告收入与预期差距大
结论：广告位有了但收益很低。
原因：广告位在低流量页面、eCPM 低、展示频率过低或广告形式不匹配。
解法：把广告位移到高流量页面；工具类优先激励视频；关注填充率与 eCPM 数据持续调优。

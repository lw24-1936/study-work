## 概述

微信分享是社交裂变的核心能力：用户把小程序卡片发给好友或群聊，或分享到朋友圈，为产品带来低成本的自然流量。分享能力围绕 onShareAppMessage（聊天分享配置）、onShareTimeline（朋友圈分享）、open-type="share" 按钮与 withShareTicket（群身份识别）展开，配合分享参数追踪可以实现完整的分享转化漏斗统计。

```text
分享能力要点速览：
1. 入口 —— 右上角菜单「转发」与 open-type="share" 按钮
2. 配置 —— onShareAppMessage 返回 { title, path, imageUrl }
3. 朋友圈 —— onShareTimeline 独立配置，单页模式展示
4. 统计 —— 无官方成功回调，靠参数追踪与平台数据
5. 群场景 —— withShareTicket + getShareInfo 识别群身份
6. 合规 —— 禁止诱导分享，卡片内容需符合平台规范
```

## onShareAppMessage 与分享卡片

onShareAppMessage 是 Page 上的生命周期函数，也是「聊天分享」的唯一配置入口。当用户点击页面右上角菜单的「转发」，或点击页面内 open-type="share" 的按钮时，微信会调用该函数获取分享内容，并把返回值渲染成发给好友/群聊的分享卡片。函数必须同步返回一个对象，包含 title（分享标题）、path（落地页路径，可带参数）、imageUrl（分享图片）三个可选字段，缺省的字段微信会用默认值兜底。

微信的默认行为：未配置任何分享逻辑时，转发菜单直接置灰不可点；定义了 onShareAppMessage 后菜单恢复可用，默认分享当前页面。因此「想让页面可被分享，就必须在 Page 里实现 onShareAppMessage」是最基本的一条规则。

```js
// pages/goods/detail.js
Page({
  data: {
    goods: null
  },

  onLoad(options) {
    // 页面加载时预取分享所需的商品数据（分享参数必须同步返回，不能现取）
    this.fetchGoods(options.id)
  },

  fetchGoods(id) {
    wx.request({
      url: 'https://api.example.com/goods/detail',
      data: { id },
      success: (res) => {
        this.setData({ goods: res.data.data })
      }
    })
  },

  onShareAppMessage() {
    const goods = this.data.goods || {}
    return {
      title: `【限时特价】${goods.title || '精选好物'}`,
      path: `/pages/goods/detail?id=${goods.id}&from=share`,
      imageUrl: goods.shareImage || goods.cover
    }
  }
})
```

```text
onShareAppMessage 关键点：
1. 定义位置 —— Page 构造器中，与 onLoad/onShow 同级
2. 触发时机 —— 点击右上角「转发」菜单或 open-type="share" 按钮
3. 返回值 —— { title, path, imageUrl }，缺省字段用默认值兜底
4. 同步返回 —— 分享参数需提前准备好，异步返回值可能不生效
5. 菜单入口 —— 未定义该函数时，「转发」菜单置灰不可点
6. 默认值 —— title 默认页面标题，path 默认当前页面路径，imageUrl 默认页面截图
```

## 分享按钮与主动分享

button 组件通过 open-type="share" 变成官方分享按钮，点击后同样触发页面的 onShareAppMessage。与菜单分享的区别在于：按钮可以放在页面的任何位置、可以自定义文案与样式，还可以通过 data-* 属性区分多个分享入口（比如「分享海报」与「邀请好友」两个按钮分享不同内容）。

需要特别强调的是：小程序不支持代码主动调起分享。早期版本的 wx.shareAppMessage 接口已经下线，现在没有任何 API 能代替用户手势弹出分享面板，分享必须由用户点击「转发」菜单或 open-type="share" 按钮触发。这是微信防止滥用分享的设计，做「分享得奖励」类功能时必须依赖用户真实点击。

```xml
<!-- pages/goods/detail.wxml -->
<view class="goods-actions">
  <button class="btn btn-primary" open-type="share" data-type="share" bindtap="onShareTap">分享给好友</button>
  <button class="btn btn-plain" bindtap="onCopyLink">复制链接</button>
</view>
```

```css
/* pages/goods/detail.wxss —— 覆盖 button 默认样式 */
.btn {
  margin: 0;
  padding: 20rpx 48rpx;
  border-radius: 44rpx;
  font-size: 28rpx;
  line-height: 1.5;
}
.btn::after {
  border: none; /* 去掉 button 默认边框 */
}
.btn-primary {
  background: #fa5151;
  color: #ffffff;
}
.btn-plain {
  background: #f7f7f7;
  color: #333333;
}
```

```js
// pages/goods/detail.js（节选）
Page({
  onShareTap() {
    // open-type="share" 的按钮 bindtap 依然会触发，适合做点击埋点
    wx.request({
      url: 'https://api.example.com/stat/share-click',
      method: 'POST',
      data: { goodsId: this.data.goods.id, source: 'button' }
    })
  },

  onShareAppMessage(res) {
    // res.from 区分来源：'menu'（右上角菜单）或 'button'（分享按钮）
    // res.target 在 from 为 button 时是按钮组件实例，可通过 dataset 区分入口
    const type = res.from === 'button' ? (res.target && res.target.dataset.type) : 'menu'
    const goods = this.data.goods || {}
    return {
      title: type === 'share' ? `【拼团价】${goods.title}` : `快来一起买 ${goods.title}`,
      path: `/pages/goods/detail?id=${goods.id}&from=${type}`,
      imageUrl: goods.shareImage
    }
  }
})
```

```text
分享按钮要点：
1. 用法 —— <button open-type="share">，点击触发页面 onShareAppMessage
2. 样式 —— button 默认样式可完全覆盖（::after 去边框），做成任意外观
3. 多入口 —— 多个分享按钮用 data-type 区分，在 res.target.dataset 中读取
4. 埋点 —— 按钮的 bindtap 正常触发，可用于统计分享点击量
5. 禁止主动 —— wx.shareAppMessage 已下线，无法代码调起分享
6. 依赖手势 —— 分享必须由用户点击触发，分享奖励逻辑要围绕真实点击设计
```

## 分享到朋友圈

分享到朋友圈由独立的生命周期函数 onShareTimeline 配置（基础库 2.11.3 起支持）。页面实现了 onShareTimeline 后，右上角菜单才会出现「分享到朋友圈」入口；返回值支持 title、query、imageUrl 三个字段，其中 query 会拼接到落地页路径上。

朋友圈分享与聊天分享有本质区别：朋友圈里没有完整的小程序分享卡片，只有「标题 + 图片」的基础信息，且内容以「单页模式」打开——用户点击后直接以单页形式查看该页面，页面无法跳转、无法再次转发，登录、支付等部分开放能力也受限。因此适合分享到朋友圈的页面必须是「自包含」的：内容完整、不依赖登录态、不依赖多页跳转（比如一篇文章、一张海报、一个商品详情）。

```js
// pages/article/detail.js
Page({
  data: {
    article: null
  },

  onLoad(options) {
    this.fetchArticle(options.id)
  },

  fetchArticle(id) {
    wx.request({
      url: 'https://api.example.com/article/detail',
      data: { id },
      success: (res) => this.setData({ article: res.data.data })
    })
  },

  // 分享到朋友圈（右上角菜单 → 分享到朋友圈）
  onShareTimeline() {
    const article = this.data.article || {}
    return {
      title: article.title || '好文推荐',
      query: `id=${article.id}&from=timeline`, // 会拼接到落地页路径
      imageUrl: article.coverImage // 建议使用网络图片，真机兼容性最好
    }
  }
})
```

```text
分享到朋友圈要点：
1. 定义方式 —— 页面实现 onShareTimeline()，菜单出现「分享到朋友圈」
2. 返回参数 —— { title, query, imageUrl }，title 默认页面标题
3. 展示形式 —— 仅标题 + 图片基础信息，没有完整分享卡片与描述文字
4. 打开方式 —— 单页模式，内容不可再次转发、不可跳转其他页面
5. 能力限制 —— 无 shareTicket，登录、支付等部分能力在单页模式下受限
6. 落地设计 —— 页面需自包含（内容完整、免登录），避免白屏与跳出
```

## 分享回调与数据统计

微信官方不提供「分享成功 / 分享失败」的确定性回调，这是很多团队踩坑的地方。onShareAppMessage 的入参 res 只有 from（menu 或 button）和 target（按钮来源），分享是否真正发出、接收方是否打开，都无法直接感知。可靠的统计方案有三条路：

一是点击埋点：分享按钮的 bindtap 记录「分享点击量」；二是参数追踪：在分享 path 中携带来源参数（如 from=share、inviter=uid），接收方落地页 onLoad 读取参数并上报，形成「分享 → 打开」的转化漏斗；三是平台数据：小程序后台「数据分析 → 分享分析」提供微信官方统计的分享次数、分享回流用户等指标，不依赖自建埋点。

群分享场景还有一个进阶能力：分享者通过 wx.showShareMenu({ withShareTicket: true }) 开启群标识后，分享到群里的卡片被好友打开时，接收方 onLoad 的 options.shareTicket 里带有当次分享的 ticket。调用 wx.getShareInfo 可拿到加密数据，传给服务端用 session_key 解密即可得到 openGId（群的唯一标识），从而识别「来自同一个群的用户」——这是拼团、砍价、群打卡类玩法的数据基础。注意 shareTicket 是一次性的，仅当次分享有效。

```js
// 分享者页面：开启 withShareTicket
Page({
  onLoad() {
    wx.showShareMenu({
      withShareTicket: true // 分享到群后，接收方才能拿到 shareTicket
    })
  },

  onShareAppMessage() {
    return {
      title: '邀请你一起参与拼团',
      path: '/pages/group/detail?id=888&from=share'
    }
  }
})
```

```js
// 接收者落地页：解析分享来源与群标识
Page({
  onLoad(options) {
    // 1. 记录分享来源（漏斗统计）
    const from = options.from || 'direct'
    this.reportShareVisit({ from, id: options.id })

    // 2. 群分享场景：用 shareTicket 换取群信息
    if (options.shareTicket) {
      this.resolveGroup(options.shareTicket)
    }
  },

  resolveGroup(shareTicket) {
    wx.getShareInfo({
      shareTicket,
      success: (res) => {
        // encryptedData / iv 不能在前端解密，交给服务端
        wx.request({
          url: 'https://api.example.com/wx/group/decode',
          method: 'POST',
          data: {
            encryptedData: res.encryptedData,
            iv: res.iv
          },
          success: (r) => {
            const openGId = r.data.openGId // 群唯一标识
            console.log('当前用户来自群：', openGId)
          }
        })
      }
    })
  },

  reportShareVisit(data) {
    wx.request({
      url: 'https://api.example.com/stat/share-visit',
      method: 'POST',
      data
    })
  }
})
```

```java
// SpringBoot 侧解密 getShareInfo 的加密数据（简化实现）
@RestController
@RequestMapping("/wx/group")
public class GroupController {

    @Autowired
    private UserService userService; // 登录时缓存了用户的 session_key

    @PostMapping("/decode")
    public Result<Map<String, Object>> decode(@RequestBody DecodeReq req,
                                              @RequestHeader("Authorization") String token) {
        // 1. 根据登录态拿到该用户的 session_key
        String sessionKey = userService.getSessionKeyByToken(token);
        // 2. 解密得到 openGId（需要 BouncyCastle 或 hutool 的 AES/CBC/PKCS7 支持）
        String openGId = WxBizDataCrypt.decrypt(sessionKey, req.getEncryptedData(), req.getIv(), "openGId");
        return Result.ok(Map.of("openGId", openGId));
    }
}
```

```text
分享统计与群识别要点：
1. 无官方回调 —— 微信不提供分享成功/失败回调，别在回调里写发奖逻辑
2. 点击埋点 —— open-type="share" 按钮的 bindtap 统计分享点击
3. 参数追踪 —— path 携带 from/inviter 等参数，落地页上报形成转化漏斗
4. 平台数据 —— 后台「数据分析 → 分享分析」查看官方分享统计
5. shareTicket —— 开启 withShareTicket 后，群分享接收方才能拿到 ticket
6. 解密链路 —— getShareInfo 的 encryptedData 需服务端用 session_key 解密得到 openGId
```

## 分享卡片定制与场景差异

分享卡片的观感直接影响点击率，定制围绕三个字段展开：title 是分享标题，建议控制在 30 字以内并突出利益点（价格、折扣、稀缺性），超出长度会被截断；path 必须以 / 开头，指向线上真实存在的页面，可以携带参数用于落地页还原状态与渠道归因；imageUrl 是分享图片，支持本地路径、代码包路径与网络图片，推荐 5:4 比例、内容清晰无水印，不配置时微信默认截取页面顶部区域作为图片。

同一个页面可以有多个分享入口，通过按钮的 data-* 属性区分，在 onShareAppMessage 里根据 res.target.dataset 返回不同的标题与 path，实现「一个页面多种分享姿势」。此外，分享的三种场景差异也要在设计时考虑清楚：好友聊天是完整卡片（标题 + 图片 + 小程序标识）；群聊卡片与好友一致，但可以携带 shareTicket 拿到群身份；朋友圈只有基础信息且以单页模式打开，无法带出卡片描述。

```xml
<!-- pages/activity/index.wxml：同一页面两个分享入口 -->
<view class="entry">
  <button open-type="share" data-type="poster" class="btn">生成专属海报</button>
  <button open-type="share" data-type="invite" class="btn">邀请好友助力</button>
</view>
```

```js
// pages/activity/index.js
const app = getApp()

Page({
  data: {
    activity: null
  },

  onLoad(options) {
    this.setData({ activity: { id: options.id || 10086, title: '国庆大促' } })
  },

  onShareAppMessage(res) {
    const uid = app.globalData.uid || ''
    const activity = this.data.activity || {}
    const type = res.from === 'button' ? (res.target && res.target.dataset.type) : 'menu'

    if (type === 'poster') {
      // 分享海报：带海报生成页参数
      return {
        title: '生成你的专属大促海报',
        path: `/pages/poster/index?aid=${activity.id}&uid=${uid}`,
        imageUrl: 'https://cdn.example.com/share/poster.png'
      }
    }

    // 默认邀请入口：带邀请人 uid，落地页可做助力关系绑定
    return {
      title: `【${activity.title}】邀请你一起领福利`,
      path: `/pages/activity/index?aid=${activity.id}&inviter=${uid}`,
      imageUrl: '/assets/share/activity.png' // 代码包内图片
    }
  }
})
```

```text
分享卡片定制要点：
1. title —— 30 字以内，突出利益点与行动号召，超出会被截断
2. path —— 以 / 开头指向真实页面，可带参数用于还原状态与归因
3. imageUrl —— 支持本地/代码包/网络图片，推荐 5:4 清晰无水印图
4. 默认值 —— 未配置时用页面标题、当前路径、页面截图兜底
5. 多入口 —— 按钮 data-type + res.target.dataset 区分分享内容
6. 场景差异 —— 好友/群聊是完整卡片，朋友圈仅基础信息且单页打开
```

## 应用场景实战

### 场景一：电商商品详情页分享（带渠道参数 + 自定义分享图）

需求：商品详情页支持分享给好友与朋友圈，分享卡片带商品图与拼团价，落地页根据 from 参数区分渠道统计转化。

```xml
<!-- pages/goods/detail.wxml -->
<view class="page">
  <image class="cover" src="{{goods.cover}}" mode="aspectFill" />
  <view class="info">
    <view class="title">{{goods.title}}</view>
    <view class="price">¥{{goods.price}}</view>
  </view>
  <view class="actions">
    <button class="btn share" open-type="share" bindtap="onShareTap">分享给好友</button>
    <button class="btn buy" bindtap="onBuy">立即购买</button>
  </view>
</view>
```

```js
// pages/goods/detail.js
const app = getApp()

Page({
  data: {
    goods: {},
    uid: ''
  },

  onLoad(options) {
    this.setData({ uid: app.globalData.uid })
    this.fetchGoods(options.id)
  },

  fetchGoods(id) {
    wx.request({
      url: 'https://api.example.com/goods/detail',
      data: { id },
      success: (res) => {
        const goods = res.data.data
        // 预热分享图，缓存到本地，避免分享时临时拉网络图失败
        if (goods.shareImage) {
          wx.getImageInfo({ src: goods.shareImage, fail: () => {} })
        }
        this.setData({ goods })
      }
    })
  },

  onShareTap() {
    // 分享点击埋点
    wx.request({
      url: 'https://api.example.com/stat/share-click',
      method: 'POST',
      data: { goodsId: this.data.goods.id, page: 'goods-detail' }
    })
  },

  onShareAppMessage() {
    const { goods, uid } = this.data
    return {
      title: `【拼团价】${goods.title} 仅需 ¥${goods.price}`,
      path: `/pages/goods/detail?id=${goods.id}&from=share&inviter=${uid}`,
      imageUrl: goods.shareImage || goods.cover
    }
  },

  onShareTimeline() {
    const { goods } = this.data
    return {
      title: `【拼团价】${goods.title} 仅需 ¥${goods.price}`,
      query: `id=${goods.id}&from=timeline`,
      imageUrl: goods.shareImage
    }
  },

  onBuy() {
    wx.navigateTo({ url: `/pages/order/confirm?id=${this.data.goods.id}` })
  }
})
```

效果：好友/群聊打开的是完整商品卡片，落地页带 inviter 参数可绑定上下级关系；朋友圈打开的是单页商品详情，标题与商品图直接可读；后台通过 from 参数统计 share 与 timeline 两条渠道的打开转化。

### 场景二：群分享裂变（shareTicket + 服务端解密识别同群用户）

需求：拼团活动页开启 withShareTicket，用户分享到群后，同群好友打开落地页时识别是否「同一群的用户」，是则解锁拼团资格，防止跨群组团刷单。

```js
// pages/group/detail.js —— 拼团落地页
Page({
  onLoad(options) {
    // 开启 withShareTicket 要在分享之前完成，通常放在页面 onLoad
    wx.showShareMenu({ withShareTicket: true })

    if (options.shareTicket) {
      // 从群分享卡片进入：解析群身份
      wx.getShareInfo({
        shareTicket: options.shareTicket,
        success: (res) => {
          wx.request({
            url: 'https://api.example.com/group/join',
            method: 'POST',
            data: {
              groupId: options.id,
              encryptedData: res.encryptedData,
              iv: res.iv
            },
            success: (r) => {
              if (r.data.data.sameGroup) {
                wx.showToast({ title: '同群用户，拼团成功', icon: 'success' })
              } else {
                wx.showToast({ title: '请与群友一起参与', icon: 'none' })
              }
            }
          })
        }
      })
    }
  },

  onShareAppMessage() {
    return {
      title: '3 人成团，快来一起拼',
      path: `/pages/group/detail?id=${this.options.id}&from=group-share`,
      imageUrl: 'https://cdn.example.com/share/group.png'
    }
  }
})
```

```java
// GroupJoinService.java —— 服务端校验同群逻辑
@Service
public class GroupJoinService {

    public boolean isSameGroup(String sessionKey, String encryptedData, String iv, String groupId) {
        // 1. 解密得到 openGId（同一群的 openGId 相同）
        String openGId = WxBizDataCrypt.decrypt(sessionKey, encryptedData, iv, "openGId");
        // 2. 查询该拼团单当前已加入用户的 openGId 集合
        Set<String> members = groupMapper.selectOpenGIdsByGroupId(groupId);
        if (members.contains(openGId)) {
            return true; // 与已有成员同群
        }
        // 3. 非同一群：拒绝加入（防刷单）
        return false;
    }
}
```

说明：WxBizDataCrypt 解密需要 AES-128-CBC + PKCS7，JDK 自带 PKCS5Padding，生产环境建议引入 hutool 的 SecureUtil.aes 或 BouncyCastle 实现 PKCS7 填充，并在解密后校验 watermark（appid 与时间戳），防止伪造数据。

## 最佳实践与踩坑记录

### 最佳实践

1. 每个可分享的页面都实现 onShareAppMessage，否则右上角菜单「转发」置灰，用户想分享都找不到入口
2. 分享 path 统一带上来源参数（from、inviter、channel），落地页 onLoad 读取并上报，形成完整的分享转化漏斗
3. 商品、内容类页面使用自定义 imageUrl（首图/海报图），默认截图的点击率明显偏低
4. 需要群身份识别（拼团、砍价、群打卡）才开启 withShareTicket，普通分享保持关闭，避免不必要的加解密开销
5. 分享标题控制在 30 字以内、突出利益点；分享图用 5:4 比例、关键信息居中，避免被裁剪
6. 分享落地页设计为「免登录可见核心内容」，新用户打开先看到价值，再引导登录，减少跳出
7. 分享参数在 onLoad/onShow 阶段预取缓存，不要在 onShareAppMessage 里发起网络请求
8. 分享点击（bindtap）、落地页打开（onLoad 上报）双通道埋点，与后台「分享分析」互相印证

### 踩坑记录

```text
坑 1：页面没写 onShareAppMessage，转发菜单置灰
结论：用户无法通过右上角菜单转发该页面。
原因：微信规定页面未实现 onShareAppMessage 时，菜单「转发」项不可用。
解法：所有需要传播的页面都实现 onShareAppMessage，哪怕只返回默认对象。

坑 2：onShareAppMessage 里发异步请求，返回空对象导致分享内容丢失
结论：分享卡片变成默认标题/截图，或干脆分享失败。
原因：onShareAppMessage 需要同步返回分享参数，异步拿到的数据来不及参与拼装。
解法：分享所需数据（标题、图片）在页面 onLoad 时预取并缓存，分享时同步拼装返回。

坑 3：分享 path 写错（漏了开头的 / 或指向不存在的页面）
结论：好友点开分享卡片报「页面不存在」或直接打不开。
原因：path 必须以 / 开头且必须是代码中真实注册的页面路径。
解法：path 统一写成 /pages/xxx/xxx?id=1 形式，上线前用开发者工具点开分享卡片自测。

坑 4：自定义 imageUrl 用本地临时路径，真机上分享图不显示
结论：模拟器正常，真机分享卡片图片空白。
原因：imageUrl 对部分本地路径兼容性差，临时文件在分享时可能已被回收。
解法：优先使用网络图片（HTTPS 域名），或代码包内的静态图片路径。

坑 5：没有官方分享成功回调，用「点击即上报」统计导致数据虚高
结论：分享统计数字远大于实际成功分享量，运营误判活动效果。
原因：微信不提供分享成功/失败回调，点击埋点无法区分「点了」与「真发出去了」。
解法：用「分享点击 + 落地页打开（带 from 参数）」双指标衡量转化，避免单一点击口径。

坑 6：分享标题超长被截断，利益点被砍掉
结论：卡片标题显示不全，价格/优惠信息丢失。
原因：分享标题有长度限制，超长部分被微信截断。
解法：标题控制在 30 字以内，把最关键的卖点放在前面。

坑 7：还在用 wx.shareAppMessage 主动调起分享，线上报错
结论：点击按钮无任何反应，控制台报接口不存在。
原因：wx.shareAppMessage 旧接口已下线，小程序不允许代码主动调起分享。
解法：改用 open-type="share" 按钮 + onShareAppMessage，分享必须由用户手势触发。

坑 8：没开 withShareTicket 就调 wx.getShareInfo，拿不到数据
结论：getShareInfo 失败或返回空，群身份识别功能失效。
原因：shareTicket 只有在分享前通过 wx.showShareMenu({ withShareTicket: true }) 开启后才返回。
解法：在分享入口页面的 onLoad 里先调用 showShareMenu 开启，再引导用户分享；且 shareTicket 一次有效，不能复用。
```

## 概述

扫码与外部跳转解决「小程序之外的用户如何进来」的问题：线下物料扫码、短信/邮件链接、App 内跳转等场景，通过二维码、URL Scheme、URL Link 与官方短链把用户带回小程序。这些能力大多依赖服务端接口（access_token）生成，并有主体、发布状态、有效期等平台限制，同时 web-view 与域名校验约束了小程序向外部跳转的边界。

```text
扫码与外部跳转要点速览：
1. 扫码 —— 小程序码与「扫普通链接二维码」两种进入方式
2. Scheme —— weixin://dl/business 形式，App/短信场景拉起
3. URL Link —— wxaurl.cn 官方短链，营销落地首选
4. 短链 —— w.url.cn/s 短链接，适合短信与线下物料
5. 生成 —— 均需服务端接口 + access_token，有配额与有效期
6. 边界 —— web-view 业务域名校验，小程序对外跳转受限
```

## 扫码进入小程序

扫码是小程序最重要的线下入口，分为两种形态：小程序码（圆形带 logo 的专用码）和普通二维码（内容是普通 URL）。扫小程序码直接打开对应页面，通过 scene 参数携带业务数据；扫普通链接二维码时，微信识别出链接后，根据后台配置的「扫普通链接二维码打开小程序」规则跳转到小程序。

普通链接二维码的价值在于「复用已有二维码」：线下物料、包装、海报上印的往往是 https://m.example.com/goods/1001 这样的链接，无需全部换成小程序码。配置步骤：进入小程序后台「开发管理 → 开发设置 → 扫普通链接二维码打开小程序」，开启开关，配置二维码规则（链接前缀，如 https://m.example.com/），下载校验文件放到该域名根目录，再分别配置测试链接与正式链接。扫码进入后，页面 onLoad 的 options 里能拿到参数：扫小程序码时 options.scene 携带编码后的场景参数；扫普通链接二维码时 options.q 携带编码后的完整原始链接。

```js
// pages/landing/index.js —— 统一处理两种扫码入口
Page({
  onLoad(options) {
    let entry = {}
    if (options.q) {
      // 扫普通链接二维码进入：q 是 URL 编码的完整链接
      const rawUrl = decodeURIComponent(options.q)
      entry = { type: 'link', url: rawUrl, params: this.parseQuery(rawUrl) }
    } else if (options.scene) {
      // 扫小程序码进入：scene 是 URL 编码的场景参数
      const sceneStr = decodeURIComponent(options.scene)
      entry = { type: 'wxacode', params: this.parseQuery(sceneStr) }
    }
    // 上报渠道，用于线下物料归因
    this.reportEntry(entry)
  },

  parseQuery(str) {
    const query = str.includes('?') ? str.split('?')[1] : str
    const params = {}
    query.split('&').forEach((kv) => {
      const [k, v] = kv.split('=')
      if (k) params[k] = decodeURIComponent(v || '')
    })
    return params
  },

  reportEntry(entry) {
    wx.request({
      url: 'https://api.example.com/stat/entry',
      method: 'POST',
      data: { type: entry.type, channel: entry.params.channel || 'direct' }
    })
  }
})
```

服务端生成小程序码使用 wxacode 系列接口（需要 access_token，因此只能在 SpringBoot 服务端调用）：wxacode.get 生成固定小程序码（全量上限 10 万个，适合一次性物料）；wxacode.getUnlimited 生成无限制小程序码（scene 参数最长 32 个可见字符，适合每个用户/每笔订单一张的动态码）。scene 常见用法是把「id 与渠道」压缩成短字符串，如 `a=1001&c=p1`，落地页再解析还原。

```java
// WxacodeService.java —— 生成无限制小程序码
@Service
public class WxacodeService {

    public byte[] createUnlimitedCode(String scene, String page) {
        String token = wechatApi.getAccessToken();
        String url = "https://api.weixin.qq.com/wxa/getwxacodeunlimit?access_token=" + token;
        Map<String, Object> body = new HashMap<>();
        body.put("scene", scene);            // 最长 32 个可见字符
        body.put("page", page);              // 已发布版本中存在的页面路径
        body.put("check_path", true);
        body.put("env_version", "release");  // release / trial / develop
        body.put("width", 430);              // 码宽，默认 430px
        ResponseEntity<byte[]> resp = restTemplate.postForEntity(url, body, byte[].class);
        // 成功时返回图片二进制；失败时返回 JSON（errcode/errmsg）
        return resp.getBody();
    }
}
```

```text
扫码进入要点：
1. 两种码 —— 小程序码（scene 传参）与普通链接二维码（q 传完整链接）
2. 配置 —— 后台「扫普通链接二维码打开小程序」配置前缀规则 + 校验文件
3. 参数 —— options.scene 与 options.q 都是 URL 编码，务必 decodeURIComponent
4. 生成 —— wxacode.get 固定码上限 10 万，getUnlimited 无限制但 scene 限 32 字符
5. 页面要求 —— 码指向的页面必须是线上版本中真实存在的路径
6. 归因 —— 二维码统一带渠道参数（channel），扫码上报做线下物料效果分析
```

## URL Scheme 拉起

URL Scheme 用于从微信之外的场景拉起小程序：App 内点击、短信链接、邮件正文、微信外 H5 页面。生成的 scheme 形如 weixin://dl/business/?t=xxxxxxxx，用户在微信内打开该链接时会直接跳转到小程序指定页面。官方对 URL Scheme 有明确限制：仅支持非个人主体、且已发布的小程序使用；生成的 scheme 有有效期与数量配额，不能无限生成。

生成方式有两条：后台「工具」模块可以手动生成（适合测试与临时投放），生产环境通过服务端接口 POST https://api.weixin.qq.com/wxa/generatescheme 生成。请求参数核心是 jump_wxa（目标页面 path 与 query）、is_expire（是否过期）、expire_type（0 固定时间 / 1 相对时间）、expire_time（固定过期时间戳）、expire_interval（相对有效期，单位分钟，最长 30 天）。不传 is_expire 或传 false 可生成长期有效的 scheme，但长期 scheme 总数有上限，应评估后再生成。

```java
// UrlSchemeService.java —— 生成 URL Scheme
@Service
public class UrlSchemeService {

    public String createScheme(String path, String query, int expireDays) {
        String token = wechatApi.getAccessToken();
        String url = "https://api.weixin.qq.com/wxa/generatescheme?access_token=" + token;

        Map<String, Object> jumpWxa = new HashMap<>();
        jumpWxa.put("path", path);
        jumpWxa.put("query", query);
        jumpWxa.put("env_version", "release");

        Map<String, Object> body = new HashMap<>();
        body.put("jump_wxa", jumpWxa);
        body.put("is_expire", true);
        body.put("expire_type", 1);                          // 相对时间
        body.put("expire_interval", expireDays * 24 * 60);   // 单位：分钟，最长 30 天

        String resp = restTemplate.postForObject(url, body, String.class);
        JSONObject json = JSON.parseObject(resp);
        if (json.getIntValue("errcode") != 0) {
            throw new BizException("生成 URL Scheme 失败：" + json.getString("errmsg"));
        }
        return json.getString("openlink"); // weixin://dl/business/?t=xxx
    }
}
```

Scheme 打开后，小程序落地页 onLoad 的 options 里直接包含 jump_wxa.query 中携带的参数（与页面跳转参数格式一致），无需额外解析。注意 scheme 是一次性消费还是可复用：普通 scheme 可被多次打开，但生成配额有限，同样的活动链接建议服务端缓存复用，避免重复生成打满配额。

```text
URL Scheme 要点：
1. 用途 —— App/短信/邮件/微信外 H5 拉起小程序指定页面
2. 限制 —— 非个人主体 + 已发布小程序，个人主体无法使用
3. 有效期 —— 默认 30 天，可配固定时间或相对时间；长期 scheme 有数量上限
4. 生成 —— 服务端接口 generatescheme（access_token），后台工具可手动生成
5. 参数 —— jump_wxa.query 中的参数直接进入落地页 onLoad 的 options
6. 配额 —— 每日生成数量有上限，相同链接应缓存复用
```

## URL Link 与短链

URL Link 是微信官方短链的一种：服务端调用 POST https://api.weixin.qq.com/wxa/generate_urllink 生成形如 https://wxaurl.cn/xxxxx 的链接，用户点击后在微信内拉起小程序。URL Link 的定位是「可传播的营销链接」：短信、邮件、广告投放、H5 落地页都可以使用，比 weixin:// 开头的 scheme 更友好（可以在任何地方展示、复制、传播）。与 URL Scheme 一样，URL Link 仅支持非个人主体且已发布的小程序，默认有效期 30 天，也可生成长期有效的链接（有数量上限）。

小程序短链接则是另一条接口：POST https://api.weixin.qq.com/wxa/genwxashortlink，参数包含 page_url（必须是线上版本存在的页面路径，以 / 开头）、page_title（页面标题）、is_permanent（是否永久有效，false 时 30 天有效，true 时永久有效且每个小程序数量有限）、query（页面参数）。生成结果形如 https://w.url.cn/s/xxxxx，适合短信营销与线下物料场景——短链码短、不易被短信平台截断、微信内直接拉起。

```java
// ShortLinkService.java —— 生成 URL Link 与小程序短链接
@Service
public class ShortLinkService {

    // 生成 URL Link（wxaurl.cn）
    public String createUrlLink(String path, String query, int expireDays) {
        String token = wechatApi.getAccessToken();
        String url = "https://api.weixin.qq.com/wxa/generate_urllink?access_token=" + token;

        Map<String, Object> body = new HashMap<>();
        body.put("path", path);
        body.put("query", query);
        body.put("is_expire", true);
        body.put("expire_type", 1);
        body.put("expire_interval", expireDays * 24 * 60); // 最长 30 天
        body.put("env_version", "release");

        String resp = restTemplate.postForObject(url, body, String.class);
        JSONObject json = JSON.parseObject(resp);
        return json.getString("url_link"); // https://wxaurl.cn/xxxxx
    }

    // 生成小程序短链接（w.url.cn/s）
    public String createShortLink(String pageUrl, String query, boolean permanent) {
        String token = wechatApi.getAccessToken();
        String url = "https://api.weixin.qq.com/wxa/genwxashortlink?access_token=" + token;

        Map<String, Object> body = new HashMap<>();
        body.put("page_url", pageUrl);   // 线上版本页面路径，如 pages/goods/detail
        body.put("page_title", "商品详情");
        body.put("is_permanent", permanent); // true 永久有效（数量有限），false 30 天
        body.put("query", query);

        String resp = restTemplate.postForObject(url, body, String.class);
        JSONObject json = JSON.parseObject(resp);
        return json.getString("link"); // https://w.url.cn/s/xxxxx
    }
}
```

```text
URL Link 与短链要点：
1. URL Link —— wxaurl.cn 短链，营销落地首选，默认 30 天可配
2. 短链接 —— w.url.cn/s/xxx，短信/线下物料场景，可配永久
3. 页面要求 —— page_url/path 必须是线上版本真实存在的页面
4. 生成方式 —— 服务端接口（access_token），后台工具可手动生成
5. 限制 —— 非个人主体 + 已发布；永久链接有数量上限
6. 落地 —— query 参数直接进入 onLoad 的 options，与页面跳转一致
```

## 外部跳转限制与域名校验

小程序向外部跳转的能力是受限的，理解边界才能设计出正确的入口方案。核心限制有三条：

第一，小程序内嵌 H5 必须用 web-view 组件，且加载的域名必须在后台「开发管理 → 开发设置 → 业务域名」中配置：每个业务域名需下载校验文件放到域名根目录，域名必须已备案且支持 HTTPS，数量有上限。web-view 内的 H5 只能在同一批业务域名内跳转，不能自由打开任意网址；H5 里也不能直接使用小程序的 wx API，只能通过 wx.miniProgram.navigateTo/postMessage 等少量方法与小程序通信，登录态需要 H5 自己维护或通过 URL 参数传递。

第二，小程序自身的网络请求（wx.request、wx.uploadFile、wx.downloadFile、WebSocket）同样受「合法域名」约束：域名需备案、HTTPS、在后台服务器域名中配置后，真机才能访问。开发者工具里可以勾选「不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书」方便本地调试，但上线前必须确保所有域名配置齐全。

第三，小程序不能直接打开浏览器或任意外部链接（没有 window.open 之类的概念），也不能随意拉起其他 App。从外部「进入」小程序只有官方通道：二维码/小程序码、URL Scheme、URL Link、短链接、微信搜索与分享卡片；从小程序「出去」到 H5 只能走业务域名内的 web-view。

```xml
<!-- pages/webview/index.wxml —— 业务域名内的 H5 -->
<web-view src="{{src}}" bindmessage="onMessage" />
```

```js
// pages/webview/index.js
Page({
  data: {
    src: 'https://h5.example.com/activity/2026?from=weapp' // 必须在业务域名白名单内
  },

  onMessage(e) {
    // H5 通过 wx.miniProgram.postMessage 传回的数据（在特定时机触发）
    console.log('H5 传来的消息：', e.detail.data)
  }
})
```

```text
外部跳转限制要点：
1. web-view —— 只能加载业务域名内的 H5，域名需校验文件 + HTTPS + 备案
2. H5 能力 —— H5 内不能直接调 wx API，只能走 miniProgram 通信与 URL 传参
3. 合法域名 —— request/uploadFile/downloadFile/WebSocket 域名需后台配置
4. 本地调试 —— 开发者工具可关闭域名校验，真机与线上必须全量配置
5. 对外出口 —— 小程序不能打开任意链接/浏览器，出去只能走业务域名 web-view
6. 进入通道 —— 外部进小程序只有二维码、Scheme、Link、短链、搜索、分享等官方入口
```

## 应用场景实战

### 场景一：线下物料「扫普通链接二维码」进入 + 渠道归因

需求：线下海报、包装印的是 https://m.example.com/s?c=poster01 这样的普通链接二维码，用户扫码直接进入小程序活动页，后台按渠道（c 参数）统计各物料带来的访问量。

第一步，后台配置：登录 mp.weixin.qq.com → 开发管理 → 开发设置 → 扫普通链接二维码打开小程序，开启功能，二维码规则填 https://m.example.com/，下载校验文件上传到 m.example.com 域名根目录，测试链接填 https://m.example.com/s?c=test，正式链接填 https://m.example.com/s。第二步，前端解析上报：

```js
// pages/activity/landing.js —— 扫码落地页
Page({
  onLoad(options) {
    let channel = 'direct'
    let entryType = 'unknown'

    if (options.q) {
      // 扫普通链接二维码：q 是 URL 编码后的完整链接
      const rawUrl = decodeURIComponent(options.q)
      entryType = 'qrcode-link'
      const m = rawUrl.match(/[?&]c=([^&]+)/)
      channel = m ? m[1] : 'direct'
    } else if (options.scene) {
      // 扫小程序码：scene 是 URL 编码参数
      entryType = 'qrcode-wxacode'
      const sceneStr = decodeURIComponent(options.scene)
      const m = sceneStr.match(/c=([^&]+)/)
      channel = m ? m[1] : 'direct'
    }

    this.setData({ channel })
    wx.request({
      url: 'https://api.example.com/stat/entry',
      method: 'POST',
      data: { entryType, channel, time: Date.now() }
    })
  }
})
```

第三步，后台（SpringBoot）落库统计，管理端（Vue）按渠道展示访问量报表。这套链路下，每一批物料换一个 c 参数即可评估 ROI。

### 场景二：短信营销用 URL Link 拉起指定页面

需求：大促前向老用户发送短信，短信内嵌链接，用户点击后在微信内打开小程序优惠券页，并自动识别手机号对应的用户身份。

服务端在发短信前先生成带参数的 URL Link：

```java
// MarketingService.java
@Service
public class MarketingService {

    public String buildSmsLink(String mobile, String couponId) {
        // 1. 生成带用户标识与券 ID 的 URL Link（7 天有效，与活动期对齐）
        String link = shortLinkService.createUrlLink(
                "pages/coupon/receive",
                "c=sms&m=" + mobile + "&couponId=" + couponId,
                7);

        // 2. 组装短信内容（短链避免被短信网关截断）
        return "【示例商城】大促福利：点击领取 50 元优惠券 " + link + " 退订回T";
    }
}
```

小程序端落地页解析参数并领取：

```js
// pages/coupon/receive.js
Page({
  onLoad(options) {
    // URL Link 携带的 query 自动进入 options
    const { c, m, couponId } = options
    if (!couponId) {
      wx.showToast({ title: '链接无效或已过期', icon: 'none' })
      return
    }
    wx.request({
      url: 'https://api.example.com/coupon/receive',
      method: 'POST',
      data: { channel: c, mobile: m, couponId },
      success: (res) => {
        if (res.data.code === 0) {
          wx.showToast({ title: '领取成功', icon: 'success' })
        } else {
          wx.showToast({ title: res.data.msg, icon: 'none' })
        }
      }
    })
  }
})
```

注意：手机号明文放在链接里会有隐私与安全风险，生产环境建议用短 token 代替手机号（服务端映射），并校验链接时效与领取频次。

## 最佳实践与踩坑记录

### 最佳实践

1. access_token 与所有生成接口（scheme/link/短链/小程序码）统一封装在 SpringBoot 服务端，前端不接触任何微信密钥
2. 所有外部链接、二维码统一带渠道参数（c/channel、scene），后台可归因，运营才能评估每个渠道的 ROI
3. 落地页设计为「免登录可见核心内容」，从链接/扫码进来的用户先看到价值，再引导登录，降低跳出率
4. 按场景选型：短信/邮件用 URL Link 或短链，App 内拉起用 URL Scheme，线下物料用二维码（复用已有链接用普通链接二维码）
5. 校验文件、业务域名、合法域名在提审前配置完成并真机自测，不要在提审后才发现域名问题
6. 相同参数的生成结果做服务端缓存（按 path+query 维度），避免重复生成打满配额
7. 长期有效链接（永久短链、长期 scheme）数量有限，先评估必要性再生成，用完及时下线
8. 链接有效期与活动周期对齐：活动 7 天就生成 7 天的链接，避免过期链接残留造成用户投诉

### 踩坑记录

```text
坑 1：扫普通链接二维码没有任何反应
结论：扫码后停留在扫码结果页或提示无法打开，没有进入小程序。
原因：后台「扫普通链接二维码打开小程序」未开启、二维码规则前缀与链接不匹配、校验文件缺失或域名不可达。
解法：核对规则前缀（必须与链接前缀完全匹配）、校验文件能通过 https 访问、测试链接与正式链接都配置并保存。

坑 2：生成的 URL Scheme 打开提示失败
结论：短信/App 里点击 scheme 提示「无法打开」或跳转空白。
原因：小程序未发布（仅体验版）、主体为个人、或 jump_wxa 的页面路径不存在。
解法：确认小程序已发布且页面真实存在；个人主体改用其他入口（如短链）；先用后台工具手动生成验证。

坑 3：scene/query 里的中文与特殊字符乱码
结论：落地页解析出的渠道名、用户 ID 变成乱码。
原因：微信对 scene 与 q 参数做 URL 编码，未 decodeURIComponent 直接使用。
解法：onLoad 里先 decodeURIComponent 再解析；生成端只放安全字符（字母数字与 =&）。

坑 4：小程序码 scene 参数被截断
结论：解析出的参数不完整，业务数据缺失。
原因：scene 最长 32 个可见字符，直接拼接长 JSON 或完整手机号会超限。
解法：scene 只放短编码（如 a=1001&c=p1），完整数据由服务端根据编码还原。

坑 5：开发者工具里点 scheme/短链打不开
结论：本地调试时外部链接无法拉起小程序。
原因：scheme、URL Link 需要在微信客户端环境（真机）中打开，工具内没有对应的拉起通道。
解法：用微信开发者工具「预览」生成真机预览，在手机微信里验证；或直接手机访问链接测试。

坑 6：永久短链/长期 scheme 生成报错（数量超限）
结论：接口返回 errcode，永久链接生成失败。
原因：每个小程序的长期链接/永久短链有总数上限，超出后拒绝生成。
解法：评估后只对长期活动生成永久链接；临时活动一律用 30 天有效期链接；必要时联系微信广告/开放平台提升额度。

坑 7：web-view 白屏
结论：小程序内嵌 H5 页面一片空白，或提示「无法打开网页」。
原因：域名未加入业务域名白名单、校验文件缺失、域名未备案或非 HTTPS。
解法：后台业务域名配置 + 校验文件部署 + 域名备案与 HTTPS；开发者工具勾选「不校验业务域名」只用于本地调试。

坑 8：短信里的长链接被运营商/网关截断
结论：用户收到的短信链接不完整，点击后 404。
原因：短信平台对超长链接有长度限制，完整链接被截断。
解法：一律使用 w.url.cn/s 短链或 wxaurl.cn 链接，短链码短且微信内直接拉起，不要直接放长 URL。
```

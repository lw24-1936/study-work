## 概述

内容社区小程序是「UGC 内容生产与消费」的轻量社区形态：用户发布图文帖、评论互动、点赞分享，后台负责内容安全检测与 feed 流分发，管理端完成内容审核治理。与电商小程序相比，社区的核心资产是用户生成的内容，核心挑战是内容合规（微信审核红线）与 feed 流的读取性能。

本项目以「发布-审核-分发-互动」为主线，覆盖图文发帖、评论、点赞、分享、关注关系、feed 流、管理端内容治理的完整链路，并在发布链路中前置接入微信内容安全检测（文本 + 图片），保证违规内容不进 feed。整个项目同样采用「小程序 + SpringBoot 后台 + Vue 管理端」三段式架构，互动计数用 Redis 扛高并发，最终一致性落库。

```text
项目目标与业务价值：
1. 支持图文发帖、评论、点赞、分享的完整互动闭环
2. 内容审核前置：发布即检测，违规内容不进 feed、不对外展示
3. 关注关系 + feed 流：关注流（只看关注的人）与推荐流（按热度/时间）双 feed
4. 管理端内容治理：审核队列、违规下架、举报处理
5. 完整的计数体系：帖子点赞数、评论数、粉丝数，Redis 原子计数 + 异步落库
6. 社交裂变：分享卡片带来源参数，追踪传播路径与回流效果
```

## 技术选型

社区场景读多写少、互动频繁，因此在电商项目技术栈（SpringBoot + MySQL + Redis）基础上，重点强化 Redis 的角色：互动计数、feed 缓存、审核幂等键都放在 Redis。内容安全检测直接复用微信开放能力（msgSecCheck / imgSecCheck），不自建审核模型。

```text
技术选型与理由：
小程序（原生） —— 图文选择、上传、分享、订阅等微信能力对接直接
SpringBoot 3 + Java 17 —— 与电商项目同栈，团队心智统一
MySQL 8 —— 帖子/评论/关注关系等结构化数据落库
Redis —— 点赞/评论/粉丝计数（INCR 原子操作）、feed 缓存、幂等键
微信内容安全接口 —— msgSecCheck 文本检测 + imgSecCheck 图片检测，无需自建模型
对象存储（OSS） —— 帖子图片上传后存 OSS，CDN 加速展示
Vue 3 + Element Plus —— 管理端审核队列、内容列表、图片预览
JWT —— 与电商项目统一登录态方案
```

## 架构设计

社区系统按「内容生产链路」与「内容消费链路」两条主线组织：生产链路（发帖 → 检测 → 审核 → 入库）与消费链路（拉 feed → 看详情 → 点赞/评论/分享），两条链路在计数与缓存层交汇。

```text
架构分层图：
┌──────────────────────────────────────────────┐
│ 小程序端（WXML / WXSS / JS）                  │
│ 发布页/feed 流/帖子详情/评论/点赞/分享/         │
│ 关注页/个人主页                                │
└───────────────────┬──────────────────────────┘
                    │ HTTPS + JSON + JWT
┌───────────────────▼──────────────────────────┐
│ 后台 SpringBoot                               │
│ 发布/审核/feed/评论/点赞/关注/计数/文件上传     │
└───────────────┬──────────────┬───────────────┘
                │              │
        ┌───────▼──────┐ ┌─────▼──────┐
        │ MySQL        │ │ Redis      │
        │ 帖子/评论/    │ │ 计数/缓存/  │
        │ 关注/审核记录 │ │ 幂等/feed   │
        └──────────────┘ └────────────┘

模块划分：
1. 内容模块 —— 发帖（图文）、帖子详情、删除
2. 互动模块 —— 评论（含回复）、点赞、分享计数
3. 关系模块 —— 关注/取关、粉丝数、关注列表
4. feed 模块 —— 关注流（拉模式）、推荐流（时间+热度）
5. 审核模块 —— 文本/图片安全检测、人工审核队列、违规下架
6. 管理端模块 —— 审核、内容列表、举报处理、用户治理
```

## 需求分析与数据建模

社区系统的核心角色：内容生产者（发帖、互动）、内容消费者（浏览、点赞、评论、关注）、运营审核人员（审核、下架）。核心业务约束有四条：所有 UGC 内容必须过安全检测才能对外可见；点赞/关注必须幂等（重复点击不重复计数）；feed 翻页不能重复或漏数据；帖子/评论删除后计数必须回退，否则数字虚高。

围绕这些约束，数据模型按「内容 / 互动 / 关系 / 计数」四组表设计。计数以 Redis 为准、MySQL 冗余落库，点赞记录用唯一索引保证幂等。核心建表 SQL 如下：

```sql
-- 帖子表：图文内容，图片以 JSON 数组存放 URL
CREATE TABLE `post` (
  `id`            BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  `user_id`       BIGINT UNSIGNED NOT NULL COMMENT '作者ID',
  `content`       TEXT            NOT NULL COMMENT '正文（纯文本）',
  `images`        JSON            DEFAULT NULL COMMENT '图片URL数组',
  `topic_id`      BIGINT UNSIGNED DEFAULT NULL COMMENT '话题ID，可空',
  `like_count`    INT UNSIGNED    NOT NULL DEFAULT 0 COMMENT '点赞数（冗余计数）',
  `comment_count` INT UNSIGNED    NOT NULL DEFAULT 0 COMMENT '评论数（冗余计数）',
  `share_count`   INT UNSIGNED    NOT NULL DEFAULT 0 COMMENT '分享打开数',
  `audit_status`  TINYINT         NOT NULL DEFAULT 0 COMMENT '0待审核 1通过 2驳回 3违规下架',
  `audit_reason`  VARCHAR(128)    DEFAULT NULL COMMENT '驳回/下架原因',
  `status`        TINYINT         NOT NULL DEFAULT 1 COMMENT '1正常 0已删除',
  `created_at`    DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  KEY `idx_user_created` (`user_id`, `created_at`),
  KEY `idx_audit_created` (`audit_status`, `created_at`)

-- 评论表：parent_id 支持二级回复
CREATE TABLE `comment` (
  `id`               BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  `post_id`          BIGINT UNSIGNED NOT NULL,
  `user_id`          BIGINT UNSIGNED NOT NULL,
  `parent_id`        BIGINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '0为一级评论，否则为被回复的评论ID',
  `reply_to_user_id` BIGINT UNSIGNED DEFAULT NULL COMMENT '被回复的用户ID',

  `like_count`       INT UNSIGNED    NOT NULL DEFAULT 0,
  `status`           TINYINT         NOT NULL DEFAULT 1 COMMENT '1正常 0已删除',

  KEY `idx_post_created` (`post_id`, `created_at`)

  `id`          BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,

  `target_id`   BIGINT UNSIGNED NOT NULL,

  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_user_target` (`user_id`, `target_type`, `target_id`)

-- 关注关系表：user_id 关注 follow_user_id
CREATE TABLE `follow` (
  `id`            BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  `user_id`       BIGINT UNSIGNED NOT NULL COMMENT '关注者',
  `follow_user_id` BIGINT UNSIGNED NOT NULL COMMENT '被关注者',
  `created_at`    DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_follow` (`user_id`, `follow_user_id`),
  KEY `idx_follow_user` (`follow_user_id`, `created_at`)

-- 用户计数表：粉丝数/发帖数等聚合指标
CREATE TABLE `user_stats` (
  `user_id`    BIGINT UNSIGNED NOT NULL,
  `fans`       INT UNSIGNED    NOT NULL DEFAULT 0 COMMENT '粉丝数',

  `target_id`   BIGINT UNSIGNED NOT NULL,
  `reason`      VARCHAR(128)    DEFAULT NULL COMMENT '举报原因',
  `status`      TINYINT         NOT NULL DEFAULT 0 COMMENT '0待处理 1已处理 2忽略',
  `created_at`  DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  KEY `idx_status` (`status`, `created_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='举报表';
```

```text
数据建模要点：
1. 帖子图片用 JSON 数组存 URL，简单场景不用拆表；量大再拆 post_image 表
2. 计数字段（like_count 等）是冗余列，以 Redis 实时值为准，定时异步回写
3. like_record 唯一索引 (user_id, target_type, target_id) 保证点赞幂等
4. follow 表同样用唯一索引防重复关注，删除行即取关
```

## 小程序端核心功能实现

小程序端包含六个核心页面：发布页、feed 流首页、帖子详情、关注流、个人主页、我的。发布页使用 wx.chooseMedia 选图（最多 9 张）、wx.uploadFile 逐张上传，最后提交帖子内容：

```js
// pages/publish/publish.js —— 图文发布
const { publishPost } = require('../../api/post')
const { uploadImage } = require('../../utils/upload')

Page({
  data: {
    content: '',
    images: [],      // 本地临时路径
    publishing: false
  },

  onChooseImage() {
    const remain = 9 - this.data.images.length
    if (remain <= 0) {
      wx.showToast({ title: '最多 9 张图片', icon: 'none' })
      return
    }
    wx.chooseMedia({
      count: remain,
      mediaType: ['image'],
      sizeType: ['compressed'],   // 压缩图，图片审核接口也有大小限制
      success: (res) => {
        const paths = res.tempFiles.map(f => f.tempFilePath)
        this.setData({ images: this.data.images.concat(paths) })
      }
    })
  },

  removeImage(e) {
    const index = e.currentTarget.dataset.index
    this.setData({ images: this.data.images.filter((_, i) => i !== index) })
  },

  async submit() {
    const content = this.data.content.trim()
    if (!content && this.data.images.length === 0) {
      wx.showToast({ title: '写点内容或选张图片吧', icon: 'none' })
      return
    }
    if (this.data.publishing) return
    this.setData({ publishing: true })
    wx.showLoading({ title: '发布中' })
    try {
      // 1. 先逐张上传图片，拿到 OSS URL
      const urls = []
      for (const path of this.data.images) {
        urls.push(await uploadImage(path))
      }
      // 2. 提交帖子：服务端先同步文本审核，图片异步审核，审核中状态为「待审核」
      await publishPost({ content, images: urls })
      wx.hideLoading()
      wx.showToast({ title: '发布成功，审核后可见', icon: 'none' })
      setTimeout(() => wx.switchTab({ url: '/pages/feed/feed' }), 1200)
    } catch (e) {
      wx.hideLoading()
      wx.showToast({ title: e.message || '发布失败', icon: 'none' })
    } finally {
      this.setData({ publishing: false })
    }
  }
})
```

```js
// utils/upload.js —— 图片上传封装
const BASE_URL = 'https://api.example.com'

function uploadImage(filePath) {
  return new Promise((resolve, reject) => {
    wx.uploadFile({
      url: BASE_URL + '/api/upload/image',
      filePath,
      name: 'file',
      header: { Authorization: 'Bearer ' + wx.getStorageSync('token') },
      success(res) {
        const data = JSON.parse(res.data)
        if (data.code === 0) {
          resolve(data.data.url)
        } else {
          reject(new Error(data.message))
        }
      },
      fail: reject
    })
  })
}

module.exports = { uploadImage }
```

feed 流首页承担主要消费入口：下拉刷新、触底加载，翻页用游标（cursor）而非页码，保证新帖子插入时翻页不重不漏。点赞用乐观更新，先改界面、失败回滚：

```js
// pages/feed/feed.js —— 推荐 feed 流
const { getFeed } = require('../../api/feed')
const { likePost, unlikePost } = require('../../api/like')

Page({
  data: {
    posts: [],
    cursor: null,     // 上一页最后一条帖子的 id
    hasMore: true,
    loading: false
  },

  onLoad() {
    this.load(true)
  },

  onPullDownRefresh() {
    this.load(true).finally(() => wx.stopPullDownRefresh())
  },

  onReachBottom() {
    this.load(false)
  },

  async load(reset) {
    if (this.data.loading || (!reset && !this.data.hasMore)) return
    this.setData({ loading: true })
    const res = await getFeed({
      cursor: reset ? null : this.data.cursor,
      size: 10
    })
    const posts = reset ? res.data.list : this.data.posts.concat(res.data.list)
    this.setData({
      posts,
      cursor: res.data.nextCursor,
      hasMore: res.data.hasMore,
      loading: false
    })
  },

  /** 点赞：乐观更新 + 失败回滚 */
  async toggleLike(e) {
    const id = e.currentTarget.dataset.id
    const post = this.data.posts.find(p => p.id === id)
    if (!post) return
    const liked = !post.liked
    this.setData({
      posts: this.data.posts.map(p =>
        p.id === id
          ? { ...p, liked, likeCount: Math.max(0, p.likeCount + (liked ? 1 : -1)) }
          : p
      )
    })
    try {
      liked ? await likePost(id) : await unlikePost(id)
    } catch (err) {
      // 回滚
      this.setData({
        posts: this.data.posts.map(p =>
          p.id === id
            ? { ...p, liked: !liked, likeCount: Math.max(0, p.likeCount + (liked ? -1 : 1)) }
            : p
        )
      })
      wx.showToast({ title: '操作失败', icon: 'none' })
    }
  },

  goDetail(e) {
    wx.navigateTo({ url: '/pages/post/detail?id=' + e.currentTarget.dataset.id })
  },

  /** 分享到会话/朋友圈：返回分享卡片配置 */
  onShareAppMessage(e) {
    const post = this.data.posts.find(p => p.id === e.target.dataset.id)
    if (!post) return {}
    return {
      title: (post.content || '分享一条动态').slice(0, 20),
      path: '/pages/post/detail?id=' + post.id + '&from=share&shareBy=' + post.userId
    }
  },

  onShareTimeline() {
    return { title: '来看看大家的最新动态' }
  }
})
```

帖子详情页承载评论与分享：评论提交后刷新列表，分享打开时带 from=share 参数，服务端据此给被分享帖子增加打开计数：

```js
// pages/post/detail.js —— 帖子详情与评论
const { getPostDetail, getComments, addComment } = require('../../api/post')
const { reportPost } = require('../../api/report')

Page({
  data: {
    post: null,
    comments: [],
    commentText: '',
    page: 1,
    hasMore: true
  },

  async onLoad(options) {
    this.postId = Number(options.id)
    // 通过分享卡片进入：上报一次分享回流，服务端对帖子 share_count + 1
    if (options.from === 'share') {
      const { reportShareOpen } = require('../../api/share')
      reportShareOpen(this.postId, options.shareBy)
    }
    await this.loadPost()
    this.loadComments(true)
  },

  async loadPost() {
    const res = await getPostDetail(this.postId)
    this.setData({ post: res.data })
  },

  async loadComments(reset) {
    const page = reset ? 1 : this.data.page + 1
    const res = await getComments({ postId: this.postId, page, pageSize: 20 })
    const comments = reset
      ? res.data.list
      : this.data.comments.concat(res.data.list)
    this.setData({
      comments,
      page,
      hasMore: res.data.list.length === 20
    })
  },

  onReachBottom() {
    this.loadComments(false)
  },

  async submitComment() {
    const content = this.data.commentText.trim()
    if (!content) {
      wx.showToast({ title: '评论内容不能为空', icon: 'none' })
      return
    }
    if (content.length > 500) {
      wx.showToast({ title: '评论最多 500 字', icon: 'none' })
      return
    }
    await addComment({ postId: this.postId, content })
    this.setData({ commentText: '' })
    wx.showToast({ title: '评论成功', icon: 'success' })
    this.loadComments(true)
    this.loadPost() // 刷新评论数
  },

  onReport() {
    wx.showActionSheet({
      itemList: ['垃圾广告', '违法违规', '人身攻击', '其他'],
      success: async (res) => {
        await reportPost({
          targetId: this.postId,
          targetType: 1,
          reason: ['垃圾广告', '违法违规', '人身攻击', '其他'][res.tapIndex]
        })
        wx.showToast({ title: '已提交举报', icon: 'success' })
      }
    })
  },

  onShareAppMessage() {
    const p = this.data.post
    return {
      title: (p ? p.content : '动态分享').slice(0, 20),
      path: '/pages/post/detail?id=' + this.postId + '&from=share&shareBy=' + (p ? p.userId : '')
    }
  }
})
```

## 后台服务实现

后台的核心是四个服务：发帖与审核链路、feed 流、互动计数、关注关系。先看发帖服务——发布时同步做文本安全检测，图片异步检测，未过审的帖子对其他人不可见：

```java
// service/PostService.java —— 发布与审核链路（节选）
@Service
@RequiredArgsConstructor
public class PostService {

    private final PostMapper postMapper;
    private final ContentSecurityService securityService;
    private final UserStatsMapper userStatsMapper;

    /**
     * 发布帖子：文本同步审核，图片异步审核
     * 审核结果决定 audit_status：1 直接可见，0 待人工复核，2 驳回
     */
    @Transactional(rollbackFor = Exception.class)
    public Long publish(Long userId, PublishPostDTO dto) {
        Post post = new Post();
        post.setUserId(userId);
        post.setContent(dto.getContent());
        post.setImages(dto.getImages());
        post.setAuditStatus(AuditStatus.PENDING);
        postMapper.insert(post);

        // 1. 文本同步检测：明确违规直接驳回
        SecurityResult textResult = securityService.checkText(dto.getContent());
        if (textResult.isViolation()) {
            postMapper.updateAudit(post.getId(), AuditStatus.REJECTED, textResult.getReason());
            throw new BizException(4401, "内容包含违规信息：" + textResult.getReason());
        }
        // 2. 文本疑似违规（review）或含图片：进人工审核队列
        if (textResult.isReview() || dto.getImages() != null && !dto.getImages().isEmpty()) {
            postMapper.updateAudit(post.getId(), AuditStatus.PENDING, null);
        } else {
            postMapper.updateAudit(post.getId(), AuditStatus.PASSED, null);
        }

        // 3. 图片异步检测：结果回调后更新状态
        if (dto.getImages() != null && !dto.getImages().isEmpty()) {
            securityService.checkImagesAsync(post.getId(), dto.getImages());
        }

        userStatsMapper.incrPostCount(userId);
        return post.getId();
    }
}
```

内容安全服务封装微信检测接口。文本走 msgSecCheck（version=2），返回 suggest 为 pass / risky / review；图片走 imgSecCheck，大小不超过 1M，需先用 https URL 或上传后的地址检测：

```java
// service/ContentSecurityService.java —— 微信内容安全检测
@Service
@RequiredArgsConstructor
public class ContentSecurityService {

    private final WechatApiClient wechatApiClient; // 封装 access_token 获取与 HTTP 调用
    private final PostMapper postMapper;

    private static final Map<Integer, String> ERRCODE_MSG = Map.of(
            87014, "内容含有违法违规内容",
            87015, "内容命中用户举报机制"
    );

    /**
     * 文本检测：调用 wxa/msg_sec_check?version=2
     * 返回建议：pass 合规 / review 人工复核 / risky 违规
     */
    public SecurityResult checkText(String content) {
        Map<String, Object> body = new HashMap<>();
        body.put("content", content);
        body.put("version", 2); // v1 已废弃，必须传 version=2
        Map<String, Object> resp = wechatApiClient.post(
                "https://api.weixin.qq.com/wxa/msg_sec_check", body);

        Integer errcode = (Integer) resp.get("errcode");
        if (errcode != null && errcode != 0) {
            // 检测接口异常（如内容为空、频率限制）：按 review 处理，转人工
            return SecurityResult.review(ERRCODE_MSG.getOrDefault(errcode, "检测失败"));
        }
        Map<String, Object> result = (Map<String, Object>) resp.get("result");
        String suggest = result == null ? "pass" : String.valueOf(result.get("suggest"));
        return switch (suggest) {
            case "risky" -> SecurityResult.violation("含违规内容");
            case "review" -> SecurityResult.review("疑似违规，待人工复核");
            default -> SecurityResult.pass();
        };
    }

    /**
     * 图片检测：调用 wxa/img_sec_check（media_url 方式）
     * 图片要求：大小不超过 1M，建议 750*1334 像素以内
     */
    public void checkImagesAsync(Long postId, List<String> urls) {
        // 逐张检测，任何一张 risky 则整帖驳回并下架
        for (String url : urls) {
            Map<String, Object> body = new HashMap<>();
            body.put("media_url", url);
            Map<String, Object> resp = wechatApiClient.post(
                    "https://api.weixin.qq.com/wxa/img_sec_check", body);
            Integer errcode = (Integer) resp.get("errcode");
            if (errcode != null && errcode != 0) {
                postMapper.updateAudit(postId, AuditStatus.REJECTED,
                        ERRCODE_MSG.getOrDefault(errcode, "图片含违规内容"));
                return;
            }
        }
        // 全部通过：若当前仍处于待审核且无文本风险，置为通过
        postMapper.updateAuditIfPending(postId, AuditStatus.PASSED);
    }
}
```

feed 流采用「拉模式 + 游标分页」：关注流直接查我关注的作者的帖子，推荐流按时间倒序 + 热度加权。拉模式对中小规模最简单可靠，关注人数上千后再升级推拉结合：

```java
// service/FeedService.java —— 关注流（拉模式）
@Service
@RequiredArgsConstructor
public class FeedService {

    private final FollowMapper followMapper;
    private final PostMapper postMapper;
    private final LikeService likeService;

    /**
     * 关注流：我关注的人的已过审帖子，按 id 倒序，游标分页
     * cursor = 上一页最后一条帖子的 id，翻页不重不漏
     */
    public FeedPage<PostVO> followFeed(Long userId, Long cursor, int size) {
        List<Long> followIds = followMapper.selectFollowUserIds(userId);
        if (followIds.isEmpty()) {
            return FeedPage.empty();
        }
        // 查 size+1 条判断是否还有下一页
        List<PostVO> list = postMapper.selectFeedByUserIds(followIds, cursor, size + 1);
        boolean hasMore = list.size() > size;
        if (hasMore) {
            list = list.subList(0, size);
        }
        // 批量标记当前用户是否已点赞（一次 IN 查询，避免 N+1）
        likeService.fillLikedFlag(userId, list);
        Long nextCursor = list.isEmpty() ? null : list.get(list.size() - 1).getId();
        return FeedPage.of(list, hasMore, nextCursor);
    }
}
```

点赞计数是社区系统的性能关键点：记录行落 MySQL（唯一索引防重复），计数用 Redis INCR 原子操作，再异步回写 MySQL 冗余列：

```java
// service/LikeService.java —— 点赞/取消赞
@Service
@RequiredArgsConstructor
public class LikeService {

    private final LikeRecordMapper likeRecordMapper;
    private final PostMapper postMapper;
    private final StringRedisTemplate redis;

    private static final String POST_LIKE_KEY = "post:like:";

    /**
     * 点赞：MySQL 唯一索引兜底幂等，Redis 原子计数
     */
    @Transactional(rollbackFor = Exception.class)
    public void like(Long userId, Integer targetType, Long targetId) {
        try {
            likeRecordMapper.insert(userId, targetType, targetId);
        } catch (DuplicateKeyException e) {
            return; // 已点赞，幂等返回
        }
        String key = POST_LIKE_KEY + targetId;
        Long count = redis.opsForValue().increment(key); // INCR 原子 +1
        if (count != null && count == 1) {
            // 首次计数：以 MySQL 现有值为基准初始化，避免计数归零
            Long dbCount = (long) postMapper.selectById(targetId).getLikeCount();
            redis.opsForValue().increment(key, dbCount);
        }
    }

    @Transactional(rollbackFor = Exception.class)
    public void unlike(Long userId, Integer targetType, Long targetId) {
        int rows = likeRecordMapper.deleteByUserTarget(userId, targetType, targetId);
        if (rows == 0) {
            return; // 未点赞，幂等返回
        }
        redis.opsForValue().decrement(POST_LIKE_KEY + targetId); // DECR 原子 -1
    }

    /** 定时任务：把 Redis 计数回写 MySQL（每 5 分钟，仅更新有变更的 key） */
    @Scheduled(fixedDelay = 300_000)
    public void flushCounters() {
        // scan 出 post:like:* 的 key，逐个回写 post.like_count
        // 回写后不删除 key，继续作为实时值使用
    }
}
```

```java
        redis.opsForValue().decrement("user:following:" + userId);
    }
```

access_token 是调用微信内容安全接口的前置条件，必须缓存复用，频繁刷新会被限流：

```java
// service/WechatApiClient.java —— access_token 缓存（节选）
@Service
public class WechatApiClient {

    @Value("${wechat.appid}")      private String appid;
    @Value("${wechat.appsecret}")  private String appsecret;

    private final StringRedisTemplate redis;
    private static final String TOKEN_KEY = "wechat:access_token";

    /**
     * 获取 access_token：优先取 Redis 缓存，过期再刷新
     * 微信返回 7200 秒有效期，提前 200 秒刷新，避免边界过期
     */
    public String getAccessToken() {
        String token = redis.opsForValue().get(TOKEN_KEY);
        if (token != null) {
            return token;
        }
        synchronized (this) { // 多实例部署时用分布式锁，防止并发刷新
            token = redis.opsForValue().get(TOKEN_KEY);
            if (token != null) {
                return token;
            }
            String url = "https://api.weixin.qq.com/cgi-bin/token?grant_type=client_credential"
                    + "&appid=" + appid + "&appsecret=" + appsecret;
            // HTTP GET 解析 { access_token, expires_in }
            Map<String, Object> resp = httpGetJson(url);
            token = (String) resp.get("access_token");
            int expiresIn = ((Number) resp.get("expires_in")).intValue();
            redis.opsForValue().set(TOKEN_KEY, token, Duration.ofSeconds(expiresIn - 200));
            return token;
        }
    }
}
```

### 场景一：用户发布一篇图文帖并完成审核的完整链路走查

以「发布一篇带 3 张图片的旅行帖」为例，完整走查生产链路：

```text
步骤：
1. 用户进入发布页，输入文字、wx.chooseMedia 选择 3 张压缩图片（sizeType=compressed）
2. 前端逐张 wx.uploadFile 上传到后台，后台存 OSS 返回 URL
```

### 场景二：关注流 feed 的构建与翻页走查

模拟用户关注了 A、B 两位作者后浏览关注流，验证游标分页的正确性：

```text
步骤：
1. 用户关注作者 A 和 B（POST /api/follow/follow，Redis 粉丝数 +1，MySQL 落关系行）
2. 打开关注流页，GET /api/feed/follow?size=10，cursor 为空
3. 后台查出关注列表 [A, B]，SQL 组装 IN 条件，取两人已过审帖子按 id 倒序 11 条
4. 返回前 10 条与 nextCursor=最后一条 id，前端渲染
5. 用户上滑触底，GET /api/feed/follow?size=10&cursor=1012
6. 后台 SQL 追加 AND id < 1012，取出更早的帖子，翻页无重复
7. 此时 A 发布新帖（id=1200），用户下拉刷新，新帖出现在第一条
8. 继续翻页仍是 id < 1012 的旧数据，新帖不会打乱已翻页数据的顺序
9. 用户取消关注 B 后刷新，B 的帖子从关注流消失，但推荐流仍可能展示
10. 性能验证：关注 500 人时 SQL 命中 IN 索引，单次查询 < 50ms，无需引入推模式
```

## 最佳实践与踩坑记录

### 最佳实践

1. 内容审核前置到发布链路：文本同步检测、图片异步检测、人工队列兜底，违规内容在源头上挡住
2. 所有 UGC 接口（发帖、评论、昵称、签名）统一过安全检测，不放过任何一个入口
3. feed 翻页用游标分页（WHERE id < cursor），不要用 offset，新数据插入时不重不漏
4. 点赞/关注等计数走 Redis INCR/DECR 原子操作 + MySQL 唯一索引幂等，定时回写冗余列
5. 列表页批量查询「我是否已点赞/已关注」，一次 IN 查询填充标志位，杜绝 N+1
6. 计数展示以 Redis 实时值为准，详情页与列表页数字一致；落库用「增量回写」避免覆盖
7. 分享统计只统计「分享打开」不统计「分享行为」，path 带 from 参数，行为可信可验证
8. access_token 缓存 7000 秒提前刷新，内容检测接口的高频调用不被打回

### 踩坑记录

坑 1：msgSecCheck 一直返回接口报错，文本检测全部失败
结论：发布接口报「调用内容安全接口失败」，所有帖子进不了审核。
原因：msgSecCheck v1 已于 2021 年废弃，旧文档的调用方式返回 errcode 错误；新接口要求带 version=2。
解法：接口改为 wxa/msg_sec_check?version=2，按 result.suggest（pass/review/risky）判断，不再依赖 v1 的 errcode 语义。

坑 2：图片检测超限，imgSecCheck 频繁失败
结论：帖子图片检测大面积失败，全部被转人工。
原因：imgSecCheck 对图片大小与像素有硬性限制（大小不超过 1M、像素过高会被拒），用户原图经常超标。
解法：发布端用 sizeType=compressed 压缩图，上传前先压缩到 1M 以内；服务端检测失败时降级为人工审核，不直接驳回用户内容。

坑 3：点赞计数对不上，帖子点赞数忽大忽小
结论：并发点赞/取消赞后，MySQL 里 like_count 与 like_record 行数不一致。
原因：计数直接用「先查后 set」或 update like_count = like_count + 1 与删除记录不在同一原子路径，并发下互相覆盖。
解法：计数改 Redis INCR/DECR 原子操作，like_record 唯一索引兜底幂等；定时任务把 Redis 值回写 MySQL 冗余列。

坑 4：feed 翻页出现重复和漏数据
结论：下拉刷新后再翻页，帖子重复出现或跳过了某条。
原因：用 page/offset 分页时，新帖子插入改变了 offset 的语义，同一帖子在两次查询中落在不同偏移。
解法：改游标分页，where id < cursor order by id desc；刷新与翻页共用同一查询，只是 cursor 不同。

坑 5：帖子删除后计数没回退，详情页数字虚高
结论：作者删帖后，feed 里已看不到帖子，但个人主页统计还显示原点赞数。
原因：删除只改了 status，没有同步回退 like_count 与 Redis 计数。
解法：删除/下架统一走「内容下线」服务：更新 status、清理 feed 缓存、扣减计数、通知相关方；计数回退用 Redis 原子操作。

坑 6：分享统计完全失真
结论：分享数远超实际打开数，运营以为传播效果极好。
原因：在小程序里「分享行为」本身无法可靠统计（用户分享后不一定会打开，分享回调不保证触发），统计口径错了。
解法：只统计「分享打开」：分享卡片 path 带 from=share，详情页 onLoad 检测到后上报一次打开计数；统计口径向运营说明清楚。

坑 7：access_token 频繁刷新被微信限流
结论：内容检测接口突然全部返回 45009（reach max api daily quota limit）。
原因：每次请求都重新获取 access_token，或缓存过期时间设得太短，触发刷新频率限制。
解法：access_token 缓存 7000 秒（官方 7200 秒有效期提前 200 秒刷新），多实例部署用分布式锁保证只刷新一次。

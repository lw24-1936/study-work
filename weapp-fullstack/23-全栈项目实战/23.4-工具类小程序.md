## 概述

工具类小程序（证件照、计算器、翻译、天气、二维码、垃圾分类查询等）是微信生态里数量最多、门槛最低的一类小程序：单次任务 30 秒到 2 分钟即可完成，用完即走，不依赖复杂的后台业务。它的核心价值在于「把一件小事做得极快极好」，技术形态上多数工具纯前端即可实现，少部分（翻译、OCR 等）需要调用第三方 API 或自建后台。

工具类小程序的商业化路径清晰：广告变现（激励视频、banner、插屏）、会员/解锁、导流到付费服务。由于业务逻辑简单，这类项目非常适合做多端发布（uni-app/Taro 一次编写多端）与轻量化设计（秒开、小包体）的工程实践。本篇章围绕工具能力、广告变现、多端发布、轻量化设计、用户留存五个方面展开，全部给出可运行代码。

```text
工具类小程序核心知识点：
1. 工具能力 —— 证件照/计算器/翻译等，纯前端实现或调用第三方 API
2. 广告变现 —— 激励视频解锁高级功能、banner 流量位，开通流量主后接入
3. 多端发布 —— uni-app/Taro 一次编写，编译到微信/支付宝/抖音/H5 多端
4. 轻量化设计 —— 启动快、首屏优化、包体积控制，主包控制在 2MB 内
5. 用户留存 —— 收藏、历史记录、每日签到、分享回流提升次日留存
6. 平台约束 —— 各平台审核规范、API 差异与包体积限制需分别适配
```

## 核心工具能力设计

工具类小程序的能力按实现方式分两大类：纯前端实现（计算器、单位换算、文字处理、时间戳转换、JSON 格式化）与调 API 实现（翻译、OCR、天气、证件照 AI 抠图）。设计原则是「能本地绝不联网」：本地实现启动快、无网络依赖、无调用成本，还能在弱网环境保持可用。

```text
工具能力分类：
1. 纯前端 —— 计算器、进制转换、字数统计、JSON 格式化、时间戳转换，零网络请求
2. 调 API —— 翻译、OCR 文字识别、天气查询、汇率，需要 appid/key 与网络
3. 混合型 —— 证件照：本地选图裁剪压缩，AI 换底色/抠图才调服务端
4. 交互模式 —— 宫格首页聚合多个工具入口，每个工具独立页面/分包
5. 数据安全 —— 涉及用户图片/文本的工具，处理完即删，不落服务端
6. 权限克制 —— 只用必要的 API（相册、相机），不申请无关权限，通过审核更快
```

证件照工具是典型的混合型工具：选图、裁剪、缩放、压缩全部本地完成，只有需要 AI 抠图换底色时才调服务端。本地处理链路为：wx.chooseMedia 选图 → getImageInfo 拿尺寸 → canvas 绘制裁剪 → canvasToTempFilePath 导出 → compressImage 压缩：

```js
// pages/tools/idphoto.js —— 证件照本地处理
Page({
  data: { src: '', result: '', sizeText: '' },
  chooseImage() {
    wx.chooseMedia({
      count: 1,
      mediaType: ['image'],
      sizeType: ['original'],
      success: (res) => {
        const file = res.tempFiles[0]
        this.setData({ src: file.tempFilePath })
        this.makeIdPhoto(file.tempFilePath)
      }
    })
  },
  // 1 寸证件照：2.5cm x 3.5cm，300dpi 下为 295 x 413 像素
  makeIdPhoto(path) {
    wx.getImageInfo({
      src: path,
      success: (info) => {
        const W = 295, H = 413
        const ctx = wx.createCanvasContext('idphoto', this)
        // 按 3:4 比例居中裁剪原图，再等比缩放绘制到目标画布
        const targetRatio = W / H
        const imgRatio = info.width / info.height
        let sx = 0, sy = 0, sw = info.width, sh = info.height
        if (imgRatio > targetRatio) {      // 原图更宽：裁左右
          sw = info.height * targetRatio
          sx = (info.width - sw) / 2
        } else {                            // 原图更高：裁上下
          sh = info.width / targetRatio
          sy = (info.height - sh) / 2
        }
        ctx.drawImage(path, sx, sy, sw, sh, 0, 0, W, H)
        ctx.draw(false, () => {
          wx.canvasToTempFilePath({
            canvasId: 'idphoto',
            destWidth: W,
            destHeight: H,
            fileType: 'jpg',
            quality: 0.9,
            success: (res) => {
              // 导出后再压缩一次，控制最终文件体积
              wx.compressImage({
                src: res.tempFilePath,
                quality: 80,
                success: (r) => {
                  this.setData({ result: r.tempFilePath })
                }
              })
            }
          }, this)
        })
      }
    })
  },
  save() {
    wx.saveImageToPhotosAlbum({
      filePath: this.data.result,
      success: () => wx.showToast({ title: '已保存到相册' }),
      fail: () => wx.showToast({ title: '保存失败，请检查相册权限', icon: 'none' })
    })
  }
})
```

翻译工具需要调第三方 API。以百度通用翻译为例，请求需要 appid + salt + sign 签名（sign = MD5(appid + q + salt + 密钥)）。注意：密钥放在前端等于公开，生产环境必须由 SpringBoot 服务端代理，前端只请求自己的域名：

```js
// utils/translate.js —— 翻译 API 调用（演示签名方式，生产环境请走服务端代理）
const md5 = require('./md5')
const APP_ID = '你的AppID'
const SECRET_KEY = '你的密钥' // 严禁写死在正式环境前端代码里

function translate(text, from = 'auto', to = 'en') {
  const salt = Date.now()
  const sign = md5(`${APP_ID}${text}${salt}${SECRET_KEY}`)
  return new Promise((resolve, reject) => {
    wx.request({
      url: 'https://fanyi-api.baidu.com/api/trans/vip/translate',
      method: 'POST',
      header: { 'content-type': 'application/x-www-form-urlencoded' },
      data: { q: text, from, to, appid: APP_ID, salt, sign },
      success: (res) => {
        if (res.data.error_code) {
          reject(new Error(res.data.error_msg))
        } else {
          resolve(res.data.trans_result)
        }
      },
      fail: reject
    })
  })
}
module.exports = { translate }
```

计算器类纯前端工具注意浮点精度问题：JavaScript 中 0.1 + 0.2 !== 0.3。展示前统一用 toFixed 或基于整数的定点运算处理，避免用户看到 0.30000000000000004 这类结果。

```text
工具能力设计要点：
1. 本地优先 —— 能纯前端实现的工具绝不发网络请求，保证秒开与离线可用
2. API 签名 —— 第三方 API 的 appid/key 放服务端代理，前端不保存密钥
3. 图片链路 —— 选图-裁剪-导出-压缩四步在本地完成，控制产物体积
4. 精度处理 —— 计算类工具用定点/整数运算或 toFixed 规避浮点误差
5. 隐私克制 —— 用户图片文本处理完即弃，不落库不传服务端
6. 权限最小化 —— 只在用户主动触发时申请相册/相机权限
```

## 广告变现

广告是工具类小程序最主要的收入来源。接入前提是开通「流量主」：小程序累计独立访客（UV）不低于 1000 且无违规记录，在公众平台「流量主」模块申请开通，审核通过后创建广告位获得 adUnitId。

```text
广告位类型与选择：
1. banner 广告 —— 页面底部横幅，展示位置固定，收益较低但稳定，适合工具首页
2. 激励视频 —— 用户主动点击观看完整视频后发奖励，eCPM 最高，用于解锁高级功能
3. 插屏广告 —— 页面切换时全屏展示，用户干扰大，工具类慎用，避免影响口碑
4. 格子广告/原生模板 —— 信息流样式，与内容混排，按场景选择
5. 收益规律 —— 激励视频 eCPM 通常高于 banner，但填充率受用户画像与时段影响
6. 合规红线 —— 严禁诱导点击（「点广告领红包」类文案）、广告遮挡功能、误触广告
```

激励视频解锁高级功能是工具类小程序的标准变现模型：用户点击「看视频解锁高清导出/去水印/批量处理」→ 播放完整激励视频 → isEnded 为 true → 发放一次使用机会。广告对象全局复用，页面退出时销毁：

```js
// utils/rewardedAd.js —— 激励视频广告封装
let rewardedAd = null

function createRewardedAd(adUnitId, onReward) {
  if (!wx.createRewardedVideoAd) {
    wx.showToast({ title: '当前微信版本不支持激励视频', icon: 'none' })
    return null
  }
  rewardedAd = wx.createRewardedVideoAd({ adUnitId })
  rewardedAd.onError((err) => {
    // 广告拉取/播放失败：降级处理，不能卡死用户主流程
    console.error('激励视频错误', err)
    wx.showToast({ title: '广告加载失败，请稍后再试', icon: 'none' })
  })
  rewardedAd.onClose((res) => {
    // isEnded === true 表示完整观看，才能发放奖励
    if (res && res.isEnded) {
      onReward()
    } else {
      wx.showToast({ title: '完整观看后才能解锁', icon: 'none' })
    }
  })
  return rewardedAd
}

function showRewardedAd(adUnitId, onReward) {
  const ad = rewardedAd || createRewardedAd(adUnitId, onReward)
  if (!ad) return
  // 直接 show 可能因未加载失败，失败后先 load 再 show
  ad.show().catch(() => ad.load().then(() => ad.show()))
}

module.exports = { showRewardedAd }
```

页面中的使用方式：高级功能按钮点击后调 showRewardedAd，onReward 里发放使用次数（本次会话内本地发放，涉及余额/积分则上报服务端）。banner 广告直接在 WXML 里用 ad 组件声明：

```wxml
<!-- pages/index/index.wxml —— 工具首页底部 banner 广告位 -->
<view class="page">
  <view class="tool-grid">...</view>
  <!-- banner 广告：位置固定页面底部，不得遮挡功能入口 -->
  <ad unit-id="adunit-xxxxxxxxxxxxxxxx" ad-type="banner" ad-theme="white"></ad>
</view>
```

```js
// pages/tools/idphoto.js —— 激励视频解锁「高清无压缩导出」
unlockHdExport() {
  showRewardedAd('adunit-hd-export', () => {
    // 完整看完：本次会话内允许一次高清导出
    this.setData({ hdAllowed: true })
    wx.showToast({ title: '已解锁，可高清导出', icon: 'none' })
  })
}
```

广告合规是工具类小程序的高危区：诱导点击（如广告上叠加「领红包」角标）、诱导分享、广告遮挡核心功能都会导致广告位被处罚甚至封禁流量主资格。广告组件本身有固定样式，不要用透明层或点击劫持手段覆盖它。

```text
广告变现要点：
1. 开通条件 —— 累计独立访客 UV 不低于 1000 且无违规，公众平台申请开通
2. 激励视频 —— 用户主动触发、完整观看（isEnded）后发放奖励
3. 广告对象 —— createRewardedVideoAd 全局复用，页面卸载时销毁
4. 降级处理 —— 广告加载失败不能卡用户，toast 提示后允许用户继续使用基础功能
5. 奖励记账 —— isEnded 只是触发信号，涉及余额的奖励以服务端记录为准
6. 合规红线 —— 禁止诱导点击、遮挡功能、点击劫持，违者封禁流量主
```

## 多端发布

工具类业务逻辑简单、跨端诉求强，是 uni-app / Taro 跨端框架的最佳适用场景：一次编写，编译到微信小程序、支付宝小程序、抖音小程序、百度小程序、H5，甚至打包成 App。选择原则：只做微信端用原生；确定多端就用跨端框架，避免后期重复开发。

```text
跨端方案对比：
1. uni-app —— Vue 语法，pages.json 配置，HBuilderX/CLI 编译，生态成熟
2. Taro —— React 语法，支持 React/Vue，编译到多端与 React Native
3. 原生微信 —— 能力最直接，但多端时每端一套代码，维护成本翻倍
4. 差异点 —— 登录、支付、存储、路由 API 各端不同，框架统一封装一层
5. 条件编译 —— 平台特有逻辑用条件编译隔离，微信专属能力单独分支
6. 取舍 —— 强依赖微信能力（订阅消息/蓝牙/NFC）的功能仍需条件编译或原生插件
```

uni-app 的写法：页面用 Vue 组件语法，API 统一走 uni.* 命名空间（uni.request / uni.login / uni.setStorageSync），编译到微信端时自动映射为 wx.*：

```vue
<!-- pages/tools/translate.vue —— uni-app 翻译工具页 -->
<template>
  <view class="page">
    <textarea v-model="text" placeholder="输入要翻译的内容" maxlength="500" />
    <button type="primary" :disabled="loading" @tap="doTranslate">
      {{ loading ? '翻译中...' : '翻译' }}
    </button>
    <view v-if="result" class="result">{{ result }}</view>
  </view>
</template>
<script>
export default {
  data() { return { text: '', result: '', loading: false } },
  methods: {
    async doTranslate() {
      if (!this.text.trim()) return
      this.loading = true
      try {
        // uni.request 在微信端自动映射为 wx.request
        const res = await uni.request({
          url: 'https://api.example.com/translate',
          method: 'POST',
          data: { text: this.text }
        })
        this.result = res.data.result
      } catch (e) {
        uni.showToast({ title: '翻译失败', icon: 'none' })
      } finally {
        this.loading = false
      }
    }
  }
}
</script>
```

Taro 的条件编译：用 process.env.TARO_ENV 区分目标平台（weapp / alipay / h5 / rn 等），平台差异逻辑写成独立函数按端分发。以登录为例，微信端用 code2session，支付宝端用 authcode，两套参数完全不一样：

```jsx
// utils/auth.js —— Taro 多端登录差异处理
import Taro from '@tarojs/taro'

export async function getLoginCode() {
  if (process.env.TARO_ENV === 'weapp') {
    // 微信小程序：wx.login 获取临时 code
    const { code } = await Taro.login()
    return { platform: 'weapp', code }
  }
  if (process.env.TARO_ENV === 'alipay') {
    // 支付宝小程序：getAuthCode 获取授权码
    const { authCode } = await Taro.getAuthCode({ scopes: 'auth_base' })
    return { platform: 'alipay', authCode }
  }
  if (process.env.TARO_ENV === 'h5') {
    // H5：走自有账号体系
    return { platform: 'h5', token: getH5Token() }
  }
  throw new Error('当前平台暂不支持登录')
}
```

uni-app 也提供条件编译注释（编译期裁剪代码，不参与打包）：

```js
// #ifdef MP-WEIXIN

wx.requestSubscribeMessage({ tmplIds: ['TMPL_ID'] })
// #endif
// #ifndef MP-WEIXIN
// 其他端：提示该能力暂未开放

// #endif
```

多端发布不只是代码问题，还有平台运营差异：每个平台都要单独注册账号、单独提审、单独维护版本；各平台类目与隐私政策要求不同（如支付宝对金融类目更严格）；微信支付、支付宝支付参数不同，支付逻辑必须按端分支。

```text
多端发布要点：
1. 框架选型 —— 仅微信用原生，多端用 uni-app（Vue）或 Taro（React）
2. API 映射 —— uni.request/login 等统一封装，编译时映射到各端原生 API
3. 条件编译 —— 微信专属能力（订阅消息/支付/蓝牙）用条件编译隔离
4. 登录差异 —— 微信 code、支付宝 authcode、H5 自有 token，按端分发
5. 支付差异 —— 各端支付参数与拉起方式不同，支付模块单独适配
6. 运营差异 —— 每端独立注册提审发版，类目与隐私政策要求不同
```

## 轻量化设计

工具类小程序的用户耐心极短，打开必须快、占内存必须小。轻量化设计围绕三个指标：启动耗时（目标秒开）、包体积（主包 2MB 红线）、运行时性能（首屏渲染快）。

```text
轻量化三指标：
1. 启动耗时 —— 从点击到可交互目标 1 秒内，减少首屏请求与初始化逻辑
2. 包体积 —— 主包不超过 2MB，单个分包不超过 2MB，全部分包合计不超过 20MB
3. 首屏渲染 —— 首页无大图、无重逻辑，骨架屏占位，数据懒加载
4. 图片策略 —— 图标用 iconfont/矢量，位图压缩，不把示例图打进包里
5. 代码策略 —— 按需引入 UI 组件库，移除无用依赖，开启 tree shaking
6. 运行策略 —— 按需注入（lazyCodeLoading）、分包预下载、数据预拉取
```

分包是控制主包体积的核心手段：每个工具独立分包，首页只保留宫格入口，用户点进哪个工具才加载哪个分包。工具类小程序非常适合「首页 + N 个工具分包」的结构：

```json
// app.json —— 分包 + 按需注入 + 预下载
{
  "pages": [
    "pages/index/index"
  ],
  "subPackages": [
    {
      "root": "packages/idphoto",
      "pages": ["pages/crop"]
    },
    {
      "root": "packages/translate",
      "pages": ["pages/index"]
    },
    {
      "root": "packages/calculator",
      "pages": ["pages/index"]
    }
  ],
  "preloadRule": {
    "pages/index/index": {
      "network": "all",
      "packages": ["packages/idphoto"]
    }
  },
  "lazyCodeLoading": "requiredComponents"
}
```

配置说明：subPackages 把每个工具拆成分包，主包只剩首页与公共代码，轻松压到 2MB 内；preloadRule 在首页空闲时预下载高频工具分包（证件照），点开即用；lazyCodeLoading: "requiredComponents" 让自定义组件按需注入，减少首屏 JS 体积。注意：tabBar 页面必须在主包，分包页面不能作为 tabBar 页。

包体积自查手段：开发者工具「详情 - 基本信息」看代码包大小；上传时工具会提示是否超限；每次发版前检查主包与各分包大小，发现异常（如误打包了设计稿图片）立即排查。图片资源统一走 CDN，不放本地包。

```text
轻量化设计要点：
1. 分包结构 —— 每个工具一个分包，主包只留首页与公共代码
2. 预下载 —— 高频工具用 preloadRule 在首页预下载，点开即用
3. 按需注入 —— lazyCodeLoading: requiredComponents 减少首屏 JS
4. 图片外置 —— 图标用 iconfont，位图走 CDN，本地包不放示例图
5. 组件按需 —— UI 组件库按需引入，禁止整包 import
6. 体积检查 —— 每次发版前检查主包/分包大小，超限先优化再上传
```

## 用户留存

工具类小程序「用完即走」是天然属性，留存手段的目标是「下次还想用、用得顺手」：历史记录降低重复操作成本，收藏让高频工具一键可达，每日签到制造回访动机，分享回流带来新用户。

```text
留存手段：
1. 历史记录 —— 翻译历史/查询历史自动保存，一键复用，降低重复成本
2. 收藏 —— 常用工具可收藏置顶，首页宫格支持自定义排序
3. 每日签到 —— 签到得积分，连续签到加码，制造每日回访动机
4. 分享回流 —— 自定义分享卡片 + 分享得使用次数，社交裂变
5. 订阅召回 —— 低频订阅消息（周报/积分到期）唤醒沉默用户
6. 指标 —— 次日留存、7 日留存、人均使用次数、人均时长是核心观测项
```

历史记录用本地缓存即可（登录后可同步服务端实现多端打通）。注意存储上限：单个 key 最大 1MB、总缓存 10MB，历史记录必须做容量上限与去重，防止无限膨胀：

```js
// utils/history.js —— 本地历史记录（去重 + 容量上限）
const MAX = 50

function add(key, item) {
  const list = wx.getStorageSync(key) || []
  list.unshift(item) // 最新记录放最前
  // 去重：内容相同只保留最新一条，避免重复翻译占满记录
  const seen = new Set()
  const dedup = []
  for (const it of list) {
    const mark = it.sign || it.content
    if (!seen.has(mark)) {
      seen.add(mark)
      dedup.push(it)
    }
    if (dedup.length >= MAX) break // 超上限截断
  }
  wx.setStorageSync(key, dedup)
}

function list(key) {
  return wx.getStorageSync(key) || []
}

module.exports = { add, list }
```

每日签到必须以服务端日期为准（用户改手机时间刷签到的漏洞），且同一天只能签到一次，用 Redis SETNX 原子保证：

```js
// pages/user/sign.js —— 签到页
sign() {
  wx.request({
    url: `${getApp().globalData.baseUrl}/api/sign`,
    method: 'POST',
    success: (res) => {
      if (res.data.code === 0) {
        const d = res.data.data
        wx.showToast({ title: `签到成功，+${d.points} 积分`, icon: 'none' })
        this.setData({ signed: true, streak: d.streak })
      } else {
        wx.showToast({ title: res.data.msg, icon: 'none' })
      }
    }
  })
}
```

```java
// SignController.java —— 签到接口（Redis SETNX 防重复签到）
@RestController
public class SignController {

    @PostMapping("/api/sign")
    public Result<SignVO> sign(@RequestHeader("Authorization") String token) {
        Long userId = userService.parseUserId(token);
        String today = LocalDate.now().toString(); // 以服务端日期为准
        // SETNX：同一天只能成功设置一次，天然防重复签到
        Boolean first = redisTemplate.opsForValue()
                .setIfAbsent("sign:" + userId + ":" + today, "1", Duration.ofDays(2));
        if (!Boolean.TRUE.equals(first)) {
            throw new BizException("今日已签到");
        }
        // 连续签到：昨天签过则连续天数 +1，否则从 1 重新开始
        boolean yesterdaySigned = Boolean.TRUE.equals(
                redisTemplate.hasKey("sign:" + userId + ":" + LocalDate.now().minusDays(1)));
        int streak = yesterdaySigned
                ? Integer.parseInt(redisTemplate.opsForValue().get("sign:" + userId + ":streak")) + 1
                : 1;
        redisTemplate.opsForValue().set("sign:" + userId + ":streak",
                String.valueOf(streak), Duration.ofDays(7));
        signMapper.insert(SignRecord.builder()
                .userId(userId).date(today).streak(streak).build());
        return Result.success(new SignVO(true, streak, streak));
    }
}
```

分享回流：onShareAppMessage 自定义分享标题与图片，配合「分享后解锁/加次数」机制形成传播。注意分享激励要符合微信规范（禁止诱导分享的强制手段，如分享后才可用），合规做法是「分享可额外获得」而非「不分享不可用」。

```text
4. 分享 —— 自定义分享卡片，分享得额外次数而非强制分享
```

## 应用场景实战

### 场景一：证件照工具完整链路（选图 → 裁剪 → 导出 → 保存）

以 1 寸证件照制作为例，完整串联本地图片处理链路：

```text
步骤：
1. 首页宫格点击「证件照」，进入工具页
2. 点击「选择照片」，wx.chooseMedia 从相册选图
3. getImageInfo 获取原图尺寸，按 3:4 居中裁剪
4. canvas 绘制到 295x413 画布（1 寸 300dpi 标准）
5. canvasToTempFilePath 导出为 jpg，再 compressImage 压缩
6. 预览结果，wx.saveImageToPhotosAlbum 保存到相册
7. 需要红底/蓝底时点击「换底色」，调服务端 AI 抠图接口合成
```

工具页完整代码（裁剪绘制部分）：

```js
// pages/tools/idphoto.js —— 完整处理流程
Page({
  data: { src: '', result: '', busy: false },
  chooseImage() {
    wx.chooseMedia({
      count: 1,
      mediaType: ['image'],
      sourceType: ['album', 'camera'],
      success: (res) => {
        const file = res.tempFiles[0]
        this.setData({ src: file.tempFilePath, busy: true })
        this.process(file.tempFilePath)
      }
    })
  },
  process(path) {
    wx.getImageInfo({
      src: path,
      success: (info) => {
        const W = 295, H = 413
        const ctx = wx.createCanvasContext('idphoto', this)
        const ratio = W / H
        const imgRatio = info.width / info.height
        let sx = 0, sy = 0, sw = info.width, sh = info.height
        if (imgRatio > ratio) {
          sw = info.height * ratio
          sx = (info.width - sw) / 2
        } else {
          sh = info.width / ratio
          sy = (info.height - sh) / 2
        }
        ctx.drawImage(path, sx, sy, sw, sh, 0, 0, W, H)
        ctx.draw(false, () => {
          wx.canvasToTempFilePath({
            canvasId: 'idphoto',
            destWidth: W,
            destHeight: H,
            fileType: 'jpg',
            success: (res) => {
              wx.compressImage({
                src: res.tempFilePath,
                quality: 80,
                success: (r) => this.setData({ result: r.tempFilePath, busy: false })
              })
            }
          }, this)
        })
      }
    })
  },
  save() {
    if (!this.data.result) return
    wx.saveImageToPhotosAlbum({
      filePath: this.data.result,
      success: () => wx.showToast({ title: '已保存' }),
      fail: () => {
        // 用户拒绝过相册权限时引导去设置页开启
        wx.showModal({
          title: '需要相册权限',
          content: '请在设置中允许保存到相册',
          success: (res) => {
            if (res.confirm) wx.openSetting()
          }
        })
      }
    })
  }
})
```

```text
场景一验收点：
1. 本地完成裁剪缩放压缩，全程无网络请求，弱网可用
2. 导出图片清晰度达标（destWidth/destHeight 决定分辨率，不能省略）
3. 保存失败时引导开启相册权限，不静默失败
```

```text

2. 普通用户限 500 字/次；点击「看视频解锁长文本」触发激励视频
3. onClose 且 isEnded 为 true 时，服务端发放一次长文本额度
```

Taro 侧的多端登录与解锁逻辑：

```jsx
// pages/translate/index.jsx —— Taro 翻译工具（多端 + 激励视频）
import Taro from '@tarojs/taro'
import { getLoginCode } from '../../utils/auth'
import { requestTranslate } from '../../api/translate'

export default function TranslatePage() {
  const [text, setText] = useState('')
  const [result, setResult] = useState('')

  async function doTranslate() {
    const { code, platform } = await getLoginCode() // 多端登录差异已封装
    const data = await requestTranslate({ text, code, platform })
    setResult(data.result)
  }

  function unlockLongText() {
    // 微信端：激励视频解锁长文本额度
    if (process.env.TARO_ENV === 'weapp') {
      const ad = Taro.createRewardedVideoAd({ adUnitId: 'adunit-longtext' })
      ad.onClose((res) => {
        if (res && res.isEnded) {
          Taro.request({ url: '/api/quota/grant', method: 'POST' })
          Taro.showToast({ title: '已解锁长文本' })
        }
      })
      ad.show().catch(() => ad.load().then(() => ad.show()))
    } else {
      // 其他端：降级为积分兑换或直接提示
      Taro.showToast({ title: '该端暂不支持解锁', icon: 'none' })
    }
  }

  return (
    <view>
      <textarea value={text} onInput={(e) => setText(e.detail.value)} />
      <button onClick={doTranslate}>翻译</button>
      {text.length > 500 && <button onClick={unlockLongText}>看视频解锁长文本</button>}
      <text>{result}</text>
    </view>
  )
}
```

```text
场景二验收点：
1. 多端登录差异收敛在 auth 模块，业务代码不分叉
2. 激励视频仅在微信端启用，其他端有降级路径
3. 长文本额度以服务端发放为准，防重复薅
4. 各端独立编译、独立提审，版本号分别维护
```

## 最佳实践与踩坑记录

### 最佳实践

1. 工具类小程序首页保持「一眼看懂」：宫格入口 + 搜索，不放复杂运营位，降低决策成本
2. 高频工具全部本地实现（零网络请求），保证秒开与离线可用；只有翻译/OCR 等必要场景才调 API
3. 第三方 API 的 appid/key 一律放 SpringBoot 服务端代理，前端只请求自有域名，防止密钥泄露被薅
4. 广告位数量克制：每页最多一个 banner + 按需激励视频，用户体验优先，避免投诉与违规
5. 激励视频奖励发放以服务端记录为准，isEnded 只是触发信号，杜绝前端伪造与重复领取
6. 包体积红线意识：主包 2MB，图片/字体/组件按需加载，每次发版前检查分包大小
7. 历史记录/收藏做容量上限与去重（单 key 1MB、总缓存 10MB），防止本地缓存无限膨胀
8. 确定多端就尽早引入跨端框架并建立「平台差异清单」，登录/支付/存储逐项核对，避免后期补条件编译的返工

### 踩坑记录

```text
坑 1：激励视频在开发者工具里无法完整测试
结论：开发者工具中广告为模拟展示，onClose 行为与真机不一致，出现「模拟器能解锁、真机不行」。
原因：激励视频广告依赖真实广告填充，工具模拟环境不返回 isEnded 等真实字段。
解法：广告逻辑以真机预览/体验版验证为准；开发者工具只验证 UI 与调用链，发布前用多台真机回归。

坑 2：激励视频广告重复创建导致无法展示
结论：每次点击解锁都 createRewardedVideoAd 一次，第二次起广告不弹出或报错。
原因：同一广告位重复创建实例，旧实例未销毁，组件状态冲突。
解法：广告实例全局复用，首次创建后缓存；页面 onUnload 时销毁，onShow 再按需重建。

坑 3：激励视频奖励被重复发放
结论：用户断网/杀进程重进后反复领取同一奖励，积分或次数虚高。
原因：奖励发放只看前端 onClose 回调，没有服务端幂等校验。
解法：发放前调用服务端接口并携带订单/会话标识，服务端按用户+标识去重；已发过则拒绝。

坑 4：证件照导出图片模糊
结论：真机导出 1 寸证件照发虚，打印不清晰。
原因：canvasToTempFilePath 未设置 destWidth/destHeight，导出分辨率低于画布实际尺寸。
解法：显式设置 destWidth=295、destHeight=413 与画布一致；导出后 compressImage 压缩，quality 不低于 80。

坑 5：主包超 2MB 无法上传
结论：工具多、图片多，主包 2MB 超限，开发者工具上传报错。
原因：所有工具与图片资源都塞在主包，没有做分包。
解法：每个工具独立分包（subPackages），tabBar 页保留主包；图片走 CDN/iconfont，删除包内大图。

坑 6：翻译 API 密钥写在前端被薅羊毛
结论：上线后第三方 API 调用量暴涨，产生高额账单。
原因：appid/密钥直接写在 JS 里，任何人反编译小程序即可提取密钥无限调用。
解法：密钥只放服务端，前端请求自有域名代理转发；服务端对单用户做限流与配额。

坑 7：多端编译后微信专属 API 残留导致其他端报错
结论：支付宝/抖音端运行时报 wx is not defined 或功能异常。
原因：wx.requestSubscribeMessage、wx.createRewardedVideoAd 等微信 API 未用条件编译隔离。
解法：所有平台差异代码用条件编译包裹（uni-app 用 #ifdef，Taro 用 process.env.TARO_ENV）；建立差异清单逐项核对。

坑 8：本地历史记录无限膨胀，小程序越用越卡
结论：翻译记录/查询记录存了几百上千条，storage 超限写入失败，页面加载变慢。
原因：setStorageSync 不做容量上限与去重，数据无限增长。
解法：封装统一的 history 工具类，去重 + 上限 50 条 + 超限截断；同步考虑 1MB 单 key 上限。

坑 9：签到用前端日期判断被改时间刷漏洞
结论：用户把手机时间改到明天可提前签到，连续签到天数被刷高。
原因：签到日期取的是设备本地时间（new Date()），未与服务端对齐。
解法：签到日期一律用服务端 LocalDate.now() 判定；Redis SETNX 保证同一天只能成功一次。

坑 10：banner 广告遮挡功能入口被投诉
结论：广告位覆盖工具按钮或输入框，用户误触广告，体验差且可能被判违规。
原因：banner 放页面中部或与可点击区域重叠，位置设计不合理。
解法：banner 固定页面底部并预留安全边距，不与任何功能区域重叠；上线前真机逐页面走查广告位。
```

## 概述

电商小程序是微信生态内最常见的商业形态：用户在小程序内浏览商品、选择规格、加入购物车、下单，并通过微信支付完成交易；后台（SpringBoot）负责商品、库存、订单、支付等核心业务；管理端（Vue）承载商品上架、订单履约、用户管理等运营动作。与 H5 商城相比，小程序拥有微信登录免注册、微信支付闭环、订阅消息触达等原生能力；与 App 相比，开发成本更低、获客入口更多、迭代更快。

本项目以「完整交易闭环」为目标，覆盖从商品展示到支付回调的每一个环节，重点解决 SKU 规格选择、并发扣库存防超卖、微信支付回调验签、订单状态机这四个电商系统的核心难题。整个项目是「小程序 + SpringBoot 后台 + Vue 管理端」三段式架构，与知识库前面的篇章（登录、支付、SpringBoot、Vue）形成完整的全栈串联。

```text
项目目标与业务价值：
1. 打通「浏览-加购-下单-支付-订单」完整交易闭环，跑通微信支付
2. 用 SKU 规格体系支撑多规格商品（颜色/尺寸/套餐）的售卖与价格区分
3. 用库存锁定与扣减机制保证并发下单不超卖、不超卖负数
4. 沉淀用户体系：微信登录 + token 会话 + 收货地址管理
5. 管理端覆盖商品、订单、用户三大运营模块，支撑日常运营
6. 通过订阅消息提醒（发货通知）与优惠券等手段提升复购
```

## 技术选型

小程序端采用原生框架（WXML/WXSS/JS），不做跨端抽象，微信能力对接最直接；后台采用 SpringBoot + MyBatis-Plus + MySQL + Redis 的经典组合，交易数据强一致落库；管理端采用 Vue3 + Element Plus，表格、表单、弹窗等后台场景组件齐全。支付对接微信支付 V3 接口，使用 APIv3 密钥与商户私钥签名体系。

```text
技术选型与理由：
小程序（原生） —— 微信登录/支付/分享能力对接最直接，无跨端框架的编译负担
SpringBoot 3 + Java 17 —— 生态成熟、上手快，适合快速搭建 RESTful API
MyBatis-Plus —— 单表 CRUD 零 SQL，复杂查询仍可用 XML 手写
MySQL 8 —— 交易数据强一致落库，事务保证订单与库存原子性
Redis —— 热点商品缓存、购物车缓存、幂等键、计数统计
微信支付 V3 —— APIv3 密钥 + 商户私钥签名体系，回调验签比 V2 更安全
Vue 3 + Element Plus —— 管理端组件齐全，商品表单/SKU 表格开发效率高
JWT —— 小程序端与管理端统一的登录态方案
```

```text
模块划分：
```

## 需求分析与数据建模

电商系统有三个核心角色：C 端用户（浏览、购买、查询订单）、运营人员（上架商品、发货、处理售后）、系统（保证库存与金额的正确性）。核心业务流程是「浏览 → 加购 → 确认订单 → 支付 → 发货 → 完成」，其中最关键的业务约束有四点：下单必须锁库存防止超卖；同一支付回调不能重复入账；订单金额不能由前端传入，必须服务端按 SKU 单价重新计算；未支付订单必须超时自动关闭并释放库存。

围绕上述约束，数据模型按「用户 / 商品与库存 / 购物车 / 订单 / 支付」五组表设计。购物车允许存 Redis 也允许存库，本项目选库表方案，便于多端同步与后台查看。核心建表 SQL 如下：

## 小程序端核心实现

小程序端包含七个页面：首页（分类+商品列表）、商品详情（SKU 选择）、购物车、下单确认、支付、订单列表、订单详情。所有网络请求统一封装，自动携带 JWT，401 时自动重新登录重试。

```js
// utils/request.js —— 统一请求封装
const BASE_URL = 'https://api.example.com'

function request(method, url, data) {
  return new Promise((resolve, reject) => {
    wx.request({
      url: BASE_URL + url,
      method,
      data,
      header: {
        'Content-Type': 'application/json',
        Authorization: 'Bearer ' + (wx.getStorageSync('token') || '')
      },
      success(res) {
        if (res.statusCode === 401) {
          // token 过期：重新登录后重试一次，避免用户频繁重新进入
          reloginAndRetry(method, url, data, resolve, reject)
          return
        }
        if (res.data.code === 0) {
          resolve(res.data) // { code, message, data }
        } else {
          wx.showToast({ title: res.data.message, icon: 'none' })
          reject(new Error(res.data.message))
        }
      },
      fail(err) {
        wx.showToast({ title: '网络异常', icon: 'none' })
        reject(err)
      }
    })
  })
}

function reloginAndRetry(method, url, data, resolve, reject) {
  wx.login({
    success: async (res) => {
      const login = await wx.request({
        url: BASE_URL + '/api/auth/login',
        method: 'POST',
        data: { code: res.code }
      })
      wx.setStorageSync('token', login.data.data.token)
      request(method, url, data).then(resolve).catch(reject)
    }
  })
}

module.exports = {
  get: (url, data) => request('GET', url, data),
  post: (url, data) => request('POST', url, data)
}
```

首页商品列表使用触底加载（onReachBottom）与下拉刷新（onPullDownRefresh），分类切换后重置分页：

```js
// pages/home/home.js
const { getCategories, getProducts } = require('../../api/product')

Page({
  data: {
    categories: [],
    activeCategory: 0,   // 0 表示全部
    products: [],
    page: 1,
    pageSize: 10,
    hasMore: true,
    loading: false
  },

  onLoad() {
    this.loadCategories()
    this.loadProducts(true)
  },

  async loadCategories() {
    const res = await getCategories()
    this.setData({ categories: [{ id: 0, name: '全部' }, ...res.data] })
  },

  async loadProducts(reset) {
    if (this.data.loading || (!reset && !this.data.hasMore)) return
    this.setData({ loading: true })
    const page = reset ? 1 : this.data.page + 1
    const res = await getProducts({
      categoryId: this.data.activeCategory || undefined,
      page,
      pageSize: this.data.pageSize
    })
    const products = reset
      ? res.data.list
      : this.data.products.concat(res.data.list)
    this.setData({
      products,
      page,
      hasMore: res.data.list.length === this.data.pageSize,
      loading: false
    })
  },

  onReachBottom() {
    this.loadProducts(false)
  },

  onPullDownRefresh() {
    this.loadProducts(true)
    wx.stopPullDownRefresh()
  },

  switchCategory(e) {
    this.setData({ activeCategory: e.currentTarget.dataset.id })
    this.loadProducts(true)
  },

  goDetail(e) {
    wx.navigateTo({
      url: '/pages/product/detail?id=' + e.currentTarget.dataset.id
    })
  }
})
```

```js
// pages/product/detail.js —— SKU 选择逻辑
const { getProductDetail } = require('../../api/product')
const { addCart } = require('../../api/cart')

Page({
  data: {
    product: null,
    skuList: [],
    specGroups: [],   // [{ name: '颜色', values: ['红色','蓝色'] }, { name: '尺寸', values: ['M','L'] }]
    selected: {},     // { 颜色: '红色', 尺寸: 'M' }
    currentSku: null, // 匹配到的 SKU
    canBuy: false,
    quantity: 1,
    showSku: false
  },

  async onLoad(options) {
    const res = await getProductDetail(options.id)
    this.setData({
      product: res.data.product,
      skuList: res.data.skuList,
      specGroups: this.buildSpecGroups(res.data.skuList)
    })
  },

  /** 从 SKU 列表聚合出规格维度（去重、保序） */
  buildSpecGroups(skuList) {
    const map = {}
    for (const sku of skuList) {
      for (const [name, value] of Object.entries(sku.specs)) {
        if (!map[name]) map[name] = { name, values: new Set() }
        map[name].values.add(value)
      }
    }
    return Object.values(map).map(g => ({ name: g.name, values: [...g.values] }))
```

下单接口是本系统的核心，涉及「锁库存 + 生成订单 + 生成支付单」三步，必须在一个事务里完成。扣库存使用 SELECT ... FOR UPDATE 行锁，并按 skuId 排序加锁避免死锁；金额全部由服务端按 SKU 单价重算，不信任前端传价：

```java
// service/OrderService.java
@Service
@RequiredArgsConstructor
public class OrderService {

    private final StockMapper stockMapper;
    private final SkuMapper skuMapper;
    private final OrdersMapper ordersMapper;
    private final OrderItemMapper orderItemMapper;
    private final PaymentMapper paymentMapper;
    private final CartMapper cartMapper;
    private final IdempotentService idempotentService;

    /**
     * 创建订单：锁库存 -> 算金额 -> 落订单 -> 落支付单
     * 幂等：同一 bizId 只允许成功一次
     */
    @Transactional(rollbackFor = Exception.class)
    public OrderNoVO createOrder(Long userId, CreateOrderDTO dto) {
        // 1. 幂等校验：bizId 已处理过则直接返回原订单号
        String orderNo = idempotentService.getProcessedOrderNo(userId, dto.getBizId());
        if (orderNo != null) {
            return new OrderNoVO(orderNo);
        }

        // 2. 明细按 skuId 排序，保证多 SKU 加锁顺序一致，避免死锁
        List<CreateOrderDTO.Item> items = dto.getItems().stream()
                .sorted(Comparator.comparing(CreateOrderDTO.Item::getSkuId))
                .toList();

        BigDecimal total = BigDecimal.ZERO;
        List<OrderItem> orderItems = new ArrayList<>();

        for (CreateOrderDTO.Item item : items) {
            // 2.1 行锁锁定库存行，防止并发超卖
            Stock stock = stockMapper.selectBySkuIdForUpdate(item.getSkuId());
            if (stock == null || stock.getAvailable() < item.getQuantity()) {
                throw new BizException(4001, "库存不足");
            }
            Sku sku = skuMapper.selectById(item.getSkuId());
            if (sku == null || sku.getStatus() != 1) {
                throw new BizException(4002, "商品已下架");
            }
            // 2.2 扣可用库存、加锁定库存（支付成功后再转实扣）
            stock.setAvailable(stock.getAvailable() - item.getQuantity());
            stock.setLocked(stock.getLocked() + item.getQuantity());
            stockMapper.updateById(stock);

            // 2.3 服务端重算金额，杜绝前端传价
            BigDecimal amount = sku.getPrice().multiply(BigDecimal.valueOf(item.getQuantity()));
            total = total.add(amount);

            OrderItem oi = new OrderItem();
            oi.setProductId(sku.getProductId());
            oi.setSkuId(sku.getId());
            oi.setProductTitle(productMapper.selectById(sku.getProductId()).getTitle());
            oi.setSkuSpecs(sku.getSpecs());
            oi.setSkuImage(sku.getImage());
            oi.setPrice(sku.getPrice());
            oi.setQuantity(item.getQuantity());
            orderItems.add(oi);
        }

        // 3. 生成订单号并落库
        String newOrderNo = OrderNoGenerator.next(); // 如 202608201530001234567890
        Orders order = new Orders();
        order.setOrderNo(newOrderNo);
        order.setUserId(userId);
        order.setTotalAmount(total);
        order.setFreight(BigDecimal.ZERO);
        order.setPayAmount(total);
        order.setStatus(OrderStatus.PENDING_PAY);
        order.setReceiverName(dto.getReceiver().getName());
        order.setReceiverPhone(dto.getReceiver().getPhone());
        order.setReceiverAddress(dto.getReceiver().getAddress());
        order.setExpireAt(LocalDateTime.now().plusMinutes(30)); // 30 分钟未支付自动关闭
        ordersMapper.insert(order);
        orderItemMapper.batchInsert(orderItems);

        // 4. 生成支付单（一单对一支付单，重新支付时新建）
        Payment payment = new Payment();
        payment.setPaymentNo(OrderNoGenerator.paymentNo());
        payment.setOrderNo(newOrderNo);
        payment.setUserId(userId);
        payment.setAmount(total);
        payment.setStatus(PaymentStatus.PENDING);
        paymentMapper.insert(payment);

        // 5. 清空已购的购物车项，记录幂等键
        cartMapper.deleteBySkuIds(userId, items.stream().map(CreateOrderDTO.Item::getSkuId).toList());
        idempotentService.markProcessed(userId, dto.getBizId(), newOrderNo);

        return new OrderNoVO(newOrderNo);
    }
}
```

支付服务端：统一下单使用微信支付 V3 接口，商户私钥做 RSA-SHA256 签名，返回给小程序端的是经过二次签名的 requestPayment 参数：

```java
// service/WechatPayV3Service.java
@Service
public class WechatPayV3Service {

    @Value("${wechat.pay.appid}")      private String appid;
    @Value("${wechat.pay.mchid}")      private String mchid;
    @Value("${wechat.pay.serial-no}")  private String serialNo;
    @Value("${wechat.pay.notify-url}") private String notifyUrl;
    @Value("${wechat.pay.private-key-path}") private String privateKeyPath;

    private PrivateKey privateKey;

    @PostConstruct
    public void init() throws Exception {
        try (InputStream in = new FileInputStream(privateKeyPath)) {
            this.privateKey = PemUtils.loadPrivateKey(in); // apiclient_key.pem
        }
    }

    /**
     * 统一下单（v3/jsapi），返回小程序端 wx.requestPayment 参数
     * amount 单位：元；微信接口金额单位：分
     */
    public Map<String, String> jsapiPay(String openid, String paymentNo, BigDecimal amount) throws Exception {
        // 1. 构造请求体
        Map<String, Object> body = new HashMap<>();
        body.put("appid", appid);
        body.put("mchid", mchid);
        body.put("description", "商城订单-" + paymentNo);
        body.put("out_trade_no", paymentNo);
        body.put("notify_url", notifyUrl);

        Map<String, Object> amountMap = new HashMap<>();
        amountMap.put("total", amount.movePointRight(2).intValue()); // 元 -> 分
        amountMap.put("currency", "CNY");
        body.put("amount", amountMap);

        Map<String, Object> payer = new HashMap<>();
        payer.put("openid", openid);
        body.put("payer", payer);

        String bodyJson = JSON.toJSONString(body);
        String url = "https://api.mch.weixin.qq.com/v3/pay/transactions/jsapi";
        long timestamp = System.currentTimeMillis() / 1000;

        // 2. 构造签名串并生成 Authorization 头
        String message = "POST\n" + url + "\n" + timestamp + "\n" + bodyJson + "\n";
        String auth = "WECHATPAY2-SHA256-RSA2048 "
                + "mchid=\"" + mchid + "\","
                + "nonce_str=\"" + UUID.randomUUID().toString().replace("-", "") + "\","
                + "timestamp=\"" + timestamp + "\","
                + "serial_no=\"" + serialNo + "\","
                + "signature=\"" + rsaSign(message) + "\"";

        // 3. 发起请求（省略 HTTP 细节，返回 JSON 中取 prepay_id）
        Map<String, Object> resp = httpPostJson(url, bodyJson, auth);
        String prepayId = (String) resp.get("prepay_id");

        // 4. 用 prepay_id 构造小程序端支付参数（第二次签名）
        String nonceStr = UUID.randomUUID().toString().replace("-", "");
        Map<String, String> params = new HashMap<>();
        params.put("timeStamp", String.valueOf(timestamp));
        params.put("nonceStr", nonceStr);
        params.put("package", "prepay_id=" + prepayId);
        params.put("signType", "RSA");
        String payMessage = appid + "\n" + timestamp + "\n" + nonceStr + "\n"
                + "prepay_id=" + prepayId + "\n";
        params.put("paySign", rsaSign(payMessage));
        return params;
    }

    private String rsaSign(String message) throws Exception {
        Signature sig = Signature.getInstance("SHA256withRSA");
        sig.initSign(privateKey);
        sig.update(message.getBytes(StandardCharsets.UTF_8));
        return Base64.getEncoder().encodeToString(sig.sign());
    }
}
```

支付回调是资金入账的唯一入口，必须验签、解密、幂等三步齐全，防止伪造回调与重复入账：

```java
// controller/PayCallbackController.java
@RestController
@RequestMapping("/api/pay")
@RequiredArgsConstructor
public class PayCallbackController {

    private final PayCallbackService payCallbackService;

    /**
     * 微信支付 V3 回调
     * 微信用平台证书私钥签名请求头，resource 用 APIv3Key 做 AES-256-GCM 加密
     */
    @PostMapping("/wechat/notify")
    public Map<String, Object> notify(@RequestBody String body,
                                      @RequestHeader("Wechatpay-Signature") String signature,
                                      @RequestHeader("Wechatpay-Timestamp") String timestamp,
                                      @RequestHeader("Wechatpay-Nonce") String nonce,
                                      @RequestHeader("Wechatpay-Serial") String serial) {
        // 1. 验签：用微信支付平台证书公钥验证签名，防止伪造回调
        // 2. 解密 resource：AES-256-GCM，密钥为 APIv3Key，得到明文 JSON
        // 3. 解析 out_trade_no / transaction_id / trade_state
        // 4. 幂等处理：支付单已成功则直接返回 SUCCESS，不重复入账
        boolean ok = payCallbackService.handlePayment(body, signature, timestamp, nonce, serial);

        Map<String, Object> resp = new HashMap<>();
        resp.put("code", ok ? "SUCCESS" : "FAIL");
        resp.put("message", ok ? "成功" : "失败");
        return resp; // 非 SUCCESS 时微信会按策略重试
    }
}
```

```java
// service/PayCallbackService.java —— 回调核心处理（节选）
@Service
@RequiredArgsConstructor
public class PayCallbackService {

    private final PaymentMapper paymentMapper;
    private final OrdersMapper ordersMapper;

    public boolean handlePayment(String body, String signature, String timestamp,
                                 String nonce, String serial) {
        try {
            // 1. 验签失败直接返回 false，微信会重试
            if (!verifySignature(body, signature, timestamp, nonce, serial)) {
                log.warn("支付回调验签失败");
                return false;
            }
            // 2. 解密得到明文
            String plain = aesGcmDecrypt(extractResource(body));
            JSONObject data = JSON.parseObject(plain);
            String paymentNo = data.getString("out_trade_no");
            String transactionId = data.getString("transaction_id");

            // 3. 幂等：支付单已成功则直接返回，避免重复入账
            Payment payment = paymentMapper.selectByPaymentNo(paymentNo);
            if (payment == null) {
                log.warn("回调支付单不存在 paymentNo={}", paymentNo);
                return false;
            }
            if (payment.getStatus() == PaymentStatus.SUCCESS) {
                return true; // 重复回调，直接应答成功
            }

            // 4. 校验金额：回调金额必须与支付单金额一致，防止篡改
            long callbackFen = data.getJSONObject("amount").getLong("total");
            long expectFen = payment.getAmount().movePointRight(2).longValue();
            if (callbackFen != expectFen) {
                log.error("回调金额不一致 paymentNo={}", paymentNo);
                return false;
            }

            // 5. 更新支付单 + 订单状态（同一事务）
            payment.setStatus(PaymentStatus.SUCCESS);
            payment.setTransactionId(transactionId);
            payment.setPaidAt(LocalDateTime.now());
            paymentMapper.updateById(payment);

            Orders order = ordersMapper.selectByOrderNo(payment.getOrderNo());
            order.setStatus(OrderStatus.PAID);
            order.setPayTime(LocalDateTime.now());
            ordersMapper.updateById(order);
            return true;
        } catch (Exception e) {
            log.error("支付回调处理异常", e);
            return false;
        }
    }
}
```

```java
// service/OrderService.java —— 关闭订单并释放库存（节选）
@Transactional(rollbackFor = Exception.class)
public void closeOrder(String orderNo) {
    Orders order = ordersMapper.selectByOrderNoForUpdate(orderNo);
    if (order == null || order.getStatus() != OrderStatus.PENDING_PAY) {
        return; // 已支付或已关闭，跳过
    }
    // 归还锁定库存：locked 减少、available 增加
    List<OrderItem> items = orderItemMapper.selectByOrderId(order.getId());
    for (OrderItem item : items) {
        stockMapper.releaseLocked(item.getSkuId(), item.getQuantity());
    }
    order.setStatus(OrderStatus.CANCELLED);
    ordersMapper.updateById(order);
}
```

```text
1. 下单事务内用 SELECT ... FOR UPDATE 锁库存行，多 SKU 按 id 排序加锁防死锁

6. 订单状态只由服务端驱动，小程序端展示结果但不作为业务依据
7. 定时任务关闭超时单，与支付回调「并发竞态」用行锁 + 状态判断兜底
```

## 支付闭环与订单状态机

支付闭环是电商系统的资金命脉，完整链路为：小程序端创建订单（锁库存）→ 后台调微信统一下单拿 prepay_id → 小程序端 wx.requestPayment 拉起收银台 → 用户支付 → 微信异步回调后台 → 验签解密、幂等入账、订单转已支付 → 后台发货 → 用户确认收货或超时自动完成。所有资金状态变更都以回调为准，前端支付结果仅作提示。

```text
订单状态机：
10 待支付 ──支付回调──> 20 已支付 ──发货──> 30 已发货 ──确认收货/超时──> 40 已完成
   │                      │
   ├─超时/取消──> 50 已取消      └─申请退款──> 60 退款中 ──退款成功──> 70 已退款

状态流转规则：
1. 10 -> 20 仅由支付回调驱动，且回调需验签 + 金额比对
2. 10 -> 50 由用户取消或定时任务超时关闭，同时释放锁定库存
3. 20 -> 30 由管理端发货操作驱动，记录 ship_time
4. 30 -> 40 由用户确认收货或发货后 15 天自动完成
5. 20 -> 60 -> 70 退款流程调用微信退款接口，退款回调成功后才落 70
6. 非法状态迁移直接抛业务异常，状态字段 TINYINT 常量枚举定义
```

退款同样走微信支付 V3：后台调用退款接口（/v3/refund/domestic/refunds），微信异步回调退款结果，退款成功后将订单置为已退款并回补库存。退款金额不能超过实付金额，退款单号用新的业务号。

```java
// service/RefundService.java（节选）
@Service
@RequiredArgsConstructor
public class RefundService {

    private final PaymentMapper paymentMapper;
    private final OrdersMapper ordersMapper;

    /**
     * 发起退款：校验订单已支付 -> 调微信退款接口 -> 状态置退款中
     * 退款结果以微信退款回调为准，回调成功才置 70 并回补库存
     */
    @Transactional(rollbackFor = Exception.class)
    public void refund(String orderNo, String operator) {
        Orders order = ordersMapper.selectByOrderNo(orderNo);
        if (order == null || order.getStatus() != OrderStatus.PAID) {
            throw new BizException(4301, "订单状态不允许退款");
        }
        Payment payment = paymentMapper.selectByOrderNo(orderNo);
        if (payment == null || payment.getStatus() != PaymentStatus.SUCCESS) {
            throw new BizException(4302, "支付单不存在或未支付成功");
        }
        // 调微信退款接口（此处省略签名与 HTTP 细节）
        // POST /v3/refund/domestic/refunds
        // { out_trade_no, out_refund_no, amount: { refund, total, currency } }
        order.setStatus(OrderStatus.REFUNDING);
        ordersMapper.updateById(order);
    }
}
```

```text
支付闭环要点：
1. 资金链路只有一条：统一下单 -> 拉起支付 -> 回调入账 -> 发货 -> 完成
2. 回调入账必须「验签 + 解密 + 幂等 + 金额比对」四步齐全
3. 退款是独立业务号（out_refund_no），与支付单解耦，避免状态互踩
4. 前端 wx.requestPayment 的 fail 不代表支付失败，以回调为准，可引导用户查订单
5. 回调处理失败返回 FAIL，微信会重试（次数有限），所以处理逻辑必须可重入
6. 对账兜底：每日定时拉取微信账单与本地支付单比对，发现差异人工介入
```

## 应用场景实战

### 场景一：用户从浏览到支付完成的完整链路走查

以「购买一件红色 M 码 T 恤」为例，完整链路：

```text
步骤：
1. 用户打开小程序首页，下拉刷新，看到分类 Tab 与商品列表（GET /api/product/list?page=1）
2. 点击商品进入详情页，加载商品信息与 SKU 列表（GET /api/product/detail?id=1001）
3. 点击「加入购物车」，弹层中选择 颜色=红色、尺寸=M，系统匹配出 SKU 并校验库存
4. 购物车页勾选商品，点击「去结算」，跳转下单确认页（填/选收货地址，展示实付金额）
5. 点击「提交订单」，前端生成 bizId，POST /api/order/create，后台事务内锁库存、算金额、落订单与支付单
6. 后台调微信统一下单（POST /v3/pay/transactions/jsapi）拿到 prepay_id，返回 requestPayment 参数
7. 小程序端 wx.requestPayment 拉起微信收银台，用户输入密码完成支付
8. 微信异步回调后台 /api/pay/wechat/notify，验签解密后订单转「已支付」，用户看到订单详情
9. 运营在管理端对已支付订单点击「发货」，填入物流单号，订单转「已发货」
10. 用户收到货确认收货（或 15 天自动完成），订单转「已完成」，交易闭环结束
```

### 场景二：高并发下单的库存防护与幂等走查

模拟 100 个用户同时抢购 10 件库存的商品，验证系统如何保证不超卖：

```text
步骤：
1. 100 个请求同时到达 /api/order/create，各自携带不同的 bizId
2. 所有请求先做幂等校验（Redis 查 bizId），首次请求全部通过
3. 多个请求竞争同一 SKU 库存行的行锁（SELECT ... FOR UPDATE），逐个串行进入
4. 第一个请求扣减 available 10 -> 9 成功；后续请求依次扣减至 available = 0
5. 第 11 个请求进入时发现 available < quantity，抛出「库存不足」，事务回滚
6. 同一用户快速连点两次提交：第二次携带相同 bizId，幂等校验直接返回第一次的订单号，不重复扣库存
7. 未支付订单 30 分钟到期，定时任务扫描关闭订单，locked 库存回补 available
8. 抢购结束后核对：订单数 = 库存数，available + locked + 销量 = 总库存，账实相符
```

## 最佳实践与踩坑记录

### 最佳实践

1. 金额计算全部在服务端用 BigDecimal 完成，数据库 DECIMAL(10,2)，前端只做展示，禁止前端传价
2. 库存设计成 available/locked 双口径，下单锁库存、支付后实扣，支持「锁单不锁死」的电商通用模型
3. 订单明细做商品快照（标题、规格、单价），后续改价、下架都不影响历史订单展示与对账
4. 所有资金入口（下单、回调、退款）都要幂等：bizId 幂等键 + 唯一索引 + 状态判断三重保险
5. 回调处理函数设计成可重入：先查状态、先验签、先比对金额，再落库，微信重试多少次都不会重复入账
6. 支付参数（timeStamp/nonceStr/package/paySign）必须由后台签名生成，小程序端只透传
7. 多 SKU 下单按 skuId 排序后加锁，从根源上避免交叉等待死锁
8. 用定时任务 + 状态判断兜底「超时关单」，与用户主动取消共用同一个关闭方法，保证库存释放逻辑唯一

### 踩坑记录

坑 1：金额用 Float 导致订单金额对不上
结论：支付金额出现 0.30000000000000004 之类的误差，对账失败。
原因：Float/Double 是二进制浮点，0.1+0.2 无法精确表示；微信支付按分计算，误差会被放大。
解法：数据库 DECIMAL(10,2)，Java 用 BigDecimal，元转分用 movePointRight(2) 而非乘法。

坑 2：下单时没锁库存，抢购瞬间超卖
结论：并发下单把库存扣成负数，卖出超过库存量的订单。
原因：先查后扣（select -> if -> update）不是原子操作，并发下多个请求读到同一可用库存。
解法：扣减用 SELECT ... FOR UPDATE 行锁串行化，或在 update 语句里加 where available >= quantity 条件并检查影响行数。

坑 3：支付回调被重复处理，订单金额入账两次
结论：微信重试回调（或网络重传）导致支付单被更新两次，状态错乱。
原因：回调处理没有先查支付单状态，每次回调都执行更新。
解法：处理前先查 status，已成功直接返回 SUCCESS；更新语句再加 where status = 待支付 条件，影响行数为 0 即重复。

坑 4：回调验签不通过，以为是微信问题
结论：所有回调都返回 FAIL，微信反复重试，日志全是验签失败。
原因：使用 APIv3Key 去验签；V3 回调签名用的是微信支付平台证书的公钥，不是 APIv3Key 本身。
解法：下载微信支付平台证书（或证书序列号对应的公钥）做验签；APIv3Key 只用于解密 resource。开发期可用微信官方 SDK 的 AutoCertificateService 自动更新证书。

坑 5：订单超时后库存一直锁着不释放
结论：用户下单不支付，库存被锁定，可用库存越来越少。
原因：没有超时关单机制，或关单任务与支付回调同时发生时状态被覆盖。
解法：下单时写入 expire_at，定时任务扫描关闭；关闭与支付回调竞态用「行锁 + status 判断」兜底，谁先拿到锁谁生效。

坑 6：多 SKU 下单偶发死锁
结论：两个订单包含不同顺序的多个 SKU，互相等待对方持有的库存锁。
原因：线程 A 先锁 SKU1 再锁 SKU2，线程 B 先锁 SKU2 再锁 SKU1，形成交叉等待。
解法：对订单明细按 skuId 排序后统一顺序加锁；同时事务要短平快，锁内不做网络调用。

坑 7：小程序端支付成功后订单仍显示待支付
结论：用户已付款，订单详情却还是「待支付」，用户投诉。
原因：前端 wx.requestPayment 的 success 回调只代表支付成功，但后台回调可能延迟几秒才到。
解法：支付成功后跳订单详情页并轮询订单状态（每 2 秒查一次，最多 10 次），以服务端状态为准；切勿在前端直接改订单状态。

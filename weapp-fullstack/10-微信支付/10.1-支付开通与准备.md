## 概述

微信支付是交易类小程序（电商、预约、知识付费等）的核心闭环能力。在写任何支付代码之前，必须先完成一系列资质与配置层面的准备工作：以非个人主体申请微信支付商户号、获取 API 证书与 APIv3 密钥、将小程序与商户号关联、按业务形态选择支付产品。这些准备工作的质量直接决定后续开发的顺利程度，本篇章是 10.2 支付流程、10.3 支付回调、10.4 退款对账的前置基础。

```text
本章核心要点：
1. 开通前提 —— 企业/个体工商户等非个人主体，需营业执照、法人身份证、对公账户
2. 商户号 —— 商户在微信支付侧的收款账户标识（mchid），通过 pay.weixin.qq.com 申请
3. 结算周期 —— 默认 T+1 结算到对公银行账户，费率按签约类目确定（标准 0.6% 起）
4. API 证书 —— apiclient_cert.pem / apiclient_key.pem，商户请求微信支付 API 的身份凭证
5. APIv3 密钥 —— 商户在商户平台设置的 32 位密钥，用于回调报文解密与平台证书管理
6. 支付产品 —— 小程序用 JSAPI 支付（小程序支付），另有 Native、H5、App 支付可选
```

## 商户号申请与开通条件

微信支付商户号（mchid）是收款主体在微信支付体系中的唯一账户标识，所有下单、退款、对账请求都以 mchid 作为身份维度。商户号通过微信支付商户平台（pay.weixin.qq.com）申请，审核通过后即可获得 10 位数字的商户号。商户号与小程序 AppID 是两个不同的标识：AppID 标识小程序应用，mchid 标识收款商户，二者通过「关联」建立绑定关系。

开通微信支付有硬性的主体门槛。个人主体小程序不能开通微信支付，也不能经营虚拟支付类业务；企业、个体工商户、政府/事业单位、社会团体等非个人主体可以申请。申请时需要提交营业执照、法人身份证、对公银行账户三类核心资质，其中对公账户用于验证商户主体真实性（小额打款验证或法人微信扫码验证）以及后续资金结算。

```text
商户号申请流程：
1. 访问 pay.weixin.qq.com，使用已认证的小程序/公众号管理员微信扫码登录
2. 选择「申请入驻」，填写主体类型（企业/个体工商户/事业单位等）
3. 上传营业执照、法人身份证照片，填写对公账户信息（开户行、账号）
4. 超级管理员扫码授权，选择验证方式（对公打款 1-3 个工作日 / 法人微信扫码即时）
5. 提交后等待审核，通常 1-5 个工作日，短信与邮件通知结果
6. 审核通过后登录商户平台，在「账户中心 - 商户信息」查看商户号
7. 在「产品中心」申请开通需要的支付产品（JSAPI 支付等）
8. 在「账户中心 - 商家信息 - 结算账户」确认结算银行卡与结算周期（默认 T+1）
```

申请通过后重点关注三类信息：商户号 mchid、结算账户与结算周期、签约费率。结算周期默认 T+1（交易次日把应结金额结算到对公账户），部分优质商户可申请缩短；费率按行业类目确定，标准类费率 0.6%，部分行业（如民生、教育）有优惠费率，签约前以商户平台展示的费率为准。财务视角下，结算金额 = 交易金额 - 手续费 - 退款金额，对账时需要把这些口径都算进去。

```text
开通条件核对清单：
1. 主体类型 —— 非个人主体（企业/个体工商户/政府/其他组织），个人主体不可开通
2. 营业执照 —— 在有效期内，经营范围与实际业务匹配（电商类目需含相关经营项目）
3. 法人身份证 —— 法人姓名与营业执照一致，支持 OCR 识别
4. 对公账户 —— 企业需对公银行账户；个体工商户可提供经营者个人结算卡（部分银行支持）
5. 小程序账号 —— 已注册且完成微信认证（认证非强制，但部分能力依赖认证）
6. 类目匹配 —— 小程序服务类目与收款业务一致，虚拟商品（知识付费等）需符合平台规则
```

## API 证书与 APIv3 密钥

微信支付 API 安全体系由三层凭证构成：商户 API 证书（用于商户请求微信支付 API 时签名身份认证）、APIv3 密钥（用于解密微信回调报文、管理平台证书）、微信支付平台证书（用于商户验签微信回调与应答）。前两个需要商户自己持有，第三个由微信侧签发、通过 SDK 自动下载管理。

商户 API 证书是一对 RSA 密钥文件：apiclient_cert.pem（公钥证书，含商户号与证书序列号）与 apiclient_key.pem（私钥，必须严格保密）。证书在商户平台「账户中心 - API 安全 - API 证书」申请下载，下载时商户平台会要求用 API 密钥设置工具配合操作。证书有效期通常为 5 年，到期前需在商户平台重新申请并替换线上配置，建议提前一个月处理。

APIv3 密钥是商户在「账户中心 - API 安全 - APIv3 密钥」自行设置的 32 位随机字符串（字母数字组合）。它有两个作用：一是解密微信支付回调报文的 resource 字段（AES-256-GCM 算法），二是配合自动下载微信支付平台证书。APIv3 密钥设置后不可查看，只能重置；一旦重置，旧密钥立即失效，所有依赖旧密钥的解密逻辑都会失败。

```text
凭证对照表：
1. 商户号 mchid —— 商户身份标识，下单/退款/查询请求都要带
2. 商户 API 证书 —— apiclient_cert.pem（公钥）+ apiclient_key.pem（私钥），请求签名用
3. 证书序列号 —— 商户平台 API 安全页展示，请求头 Wechatpay-Serial 与签名信息中携带
4. APIv3 密钥 —— 32 位字符串，解密回调 resource 与下载平台证书用
5. 微信支付平台证书 —— 微信侧公钥证书，验签微信回调/应答用，SDK 自动管理
6. 私钥安全 —— apiclient_key.pem 与 APIv3 密钥泄露等于支付凭证泄露，必须加密存储
```

Java 服务端使用官方 SDK（com.github.wechatpay-apiv3:wechatpay-java）时，先定义支付配置属性，再用 RSAAutoCertificateConfig 构建全局配置对象。RSAAutoCertificateConfig 会自动下载微信支付平台证书并按需轮换，开发者只需提供商户私钥与 APIv3 密钥：

```java
// WechatPayProperties.java —— 微信支付配置属性类
import lombok.Data;
import org.springframework.boot.context.properties.ConfigurationProperties;
import org.springframework.stereotype.Component;

@Component
@ConfigurationProperties(prefix = "wechat.pay")
@Data
public class WechatPayProperties {

    /** 商户号（mchid），商户平台 -> 账户中心 -> 商户信息 查看 */
    private String merchantId;

    /** 商户 API 证书序列号，商户平台 -> 账户中心 -> API 安全 -> API 证书 查看 */
    private String merchantSerialNumber;

    /** 商户 API 私钥 apiclient_key.pem 的本地路径（或密钥管理服务注入） */
    private String privateKeyPath;

    /** APIv3 密钥，商户平台 -> 账户中心 -> API 安全 -> APIv3 密钥 设置 */
    private String apiV3Key;

    /** 小程序 AppID */
    private String appId;

    /** 支付结果回调地址，必须是公网可访问的 HTTPS 域名下的接口 */
    private String notifyUrl;

    /** 退款结果回调地址 */
    private String refundNotifyUrl;
}
```

```yaml
# application.yml —— 支付相关配置（生产环境建议改为环境变量或配置中心注入）
wechat:
  pay:
    merchant-id: 1900000109
    merchant-serial-number: 3775B6A45ACD58B4BA10827F447FEED
    private-key-path: /etc/wechatpay/apiclient_key.pem
    api-v3-key: your-32-char-api-v3-key-set-in-merchant-platform
    app-id: wx1234567890abcdef
    notify-url: https://api.example.com/api/pay/notify
    refund-notify-url: https://api.example.com/api/pay/refund-notify
```

```java
// PayClientConfig.java —— 构建微信支付 SDK 全局配置
import com.wechat.pay.java.core.Config;
import com.wechat.pay.java.core.RSAAutoCertificateConfig;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration
public class PayClientConfig {

    /**
     * 自动证书模式：SDK 首次调用时自动下载微信支付平台证书，
     * 之后定期轮换，无需手工维护平台证书文件。
     * 三个参数分别对应：商户号、商户私钥文件路径、商户证书序列号。
     */
    @Bean
    public Config wechatPayConfig(WechatPayProperties props) {
        return new RSAAutoCertificateConfig.Builder()
                .merchantId(props.getMerchantId())
                .privateKey(props.getPrivateKeyPath())
                .merchantSerialNumber(props.getMerchantSerialNumber())
                .apiV3Key(props.getApiV3Key())
                .build();
    }
}
```

证书下载后先用 openssl 自检，确认文件完整、证书与私钥匹配，再接入代码，避免把「证书没配对」的问题带进联调阶段：

```bash
# 1. 查看证书基本信息（序列号应与商户平台 API 安全页展示的一致）
openssl x509 -in apiclient_cert.pem -noout -serial -subject -dates

# 2. 校验证书与私钥是否匹配（两个 modulus 的 md5 一致才说明配对）
openssl x509 -noout -modulus -in apiclient_cert.pem | openssl md5
openssl rsa  -noout -modulus -in apiclient_key.pem | openssl md5

# 3. 检查私钥文件权限，生产环境应仅限运行用户可读
ls -l apiclient_key.pem   # 期望 -rw-------，属主为服务运行用户
```

## 支付配置

商户号申请成功后，还需要完成一系列绑定与配置，小程序才能真正收款。最核心的一步是「小程序 AppID 与商户号关联」：在商户平台「产品中心 - AppID 账号管理」发起关联申请，或在小程序后台「微信支付」入口关联已有商户号。关联后的小程序调用 wx.requestPayment 时，收银台才能正确识别收款商户。一个商户号可以关联多个 AppID（多个小程序/公众号共用同一商户号收款），一个 AppID 只能关联一个商户号。

回调地址（notify_url）是支付成功、退款成功等异步通知的接收接口，必须满足三个条件：公网可访问、HTTPS 协议、返回符合微信约定的应答格式。v3 接口的回调地址在下单请求中动态传入，不需要在商户平台预先登记白名单；但 H5 支付需要在商户平台「产品中心 - 开发配置」配置 H5 支付域名（需 ICP 备案），Native 支付需要配置扫码回调链接，公众号 JSAPI 支付需要配置 JSAPI 支付授权目录。小程序支付不需要配置支付目录。

```text
支付配置清单：
1. AppID 关联 —— 商户平台「产品中心 - AppID 账号管理」关联小程序 AppID
2. 回调域名 —— 服务器域名已在小程序后台配置为 request 合法域名（业务基础）
3. 回调地址 —— 下单接口传 notify_url，HTTPS 公网可达，返回 code=SUCCESS 应答
4. H5 支付 —— 商户平台开发配置中登记 H5 支付域名（需备案，用于浏览器内支付）
5. Native 支付 —— 配置扫码支付回调链接（收款码场景）
6. 结算账户 —— 确认结算银行卡信息正确，避免提现/结算失败
```

域名与回调地址的配置可以沉淀为一个校验脚本，上线前批量检查配置完整性：

```bash
#!/usr/bin/env bash
# check-pay-config.sh —— 上线前支付配置自检脚本（示意）
set -e

BASE="https://api.example.com"

echo "== 1. 检查回调域名是否可访问 =="
curl -sI --max-time 5 "${BASE}/api/pay/notify" | head -1

echo "== 2. 检查证书私钥文件与权限 =="
test -r /etc/wechatpay/apiclient_key.pem && echo "私钥可读: OK"
stat -c '%a' /etc/wechatpay/apiclient_key.pem

echo "== 3. 检查小程序后台合法域名（需人工登录确认）=="
echo "request 合法域名应包含: ${BASE}"

echo "== 4. 检查商户号与 AppID 关联（需人工登录商户平台确认）=="
echo "商户平台 -> 产品中心 -> AppID 账号管理 应看到小程序 AppID"
```

## 支付产品选择

微信支付按终端形态提供多种支付产品，选错产品会导致拉起支付失败或审核被拒。小程序内支付只能使用「JSAPI 支付」（官方文档中小程序支付即 JSAPI 支付在小程序端的具体形态），流程是后端调 JSAPI 下单接口拿到 prepay_id，前端 wx.requestPayment 拉起微信收银台。公众号内 H5 页面用 JSAPI 支付（需配置授权目录）；微信外的手机浏览器用 H5 支付；PC 端扫码用 Native 支付；iOS/Android 原生 App 用 App 支付。

```text
支付产品对比：
1. JSAPI 支付（小程序支付）—— 小程序/公众号内拉起收银台，本知识库主力产品
2. Native 支付 —— PC 网站展示二维码，用户微信扫码付款，需配置扫码回调
3. H5 支付 —— 微信外手机浏览器支付，需在商户平台配置 H5 支付域名（备案）
4. App 支付 —— 原生 App 内调起微信支付，需开放平台移动应用与 SDK 接入
5. 小程序虚拟支付 —— 微信内购买虚拟物品/知识付费，受平台虚拟支付规则严格限制
6. 选型口诀 —— 小程序内用 JSAPI，浏览器用 H5，PC 扫码用 Native，原生 App 用 App
```

产品选型可以用代码固化下来，避免不同端混用：

```java
// PayProduct.java —— 支付产品枚举
public enum PayProduct {
    JSAPI("小程序/公众号内拉起收银台"),
    NATIVE("PC 端二维码扫码支付"),
    H5("微信外手机浏览器支付"),
    APP("原生 App 内调起微信支付");

    private final String desc;

    PayProduct(String desc) {
        this.desc = desc;
    }

    /** 按调用端选型 */
    public static PayProduct of(String clientType) {
        return switch (clientType) {
            case "miniprogram", "mp" -> JSAPI;  // 小程序、公众号 H5 -> JSAPI
            case "browser" -> H5;               // 微信外浏览器 -> H5
            case "pc" -> NATIVE;                // PC 网页 -> Native 扫码
            case "app" -> APP;                  // 原生 App -> App 支付
            default -> throw new IllegalArgumentException("未知客户端类型: " + clientType);
        };
    }

    @Override
    public String toString() {
        return name() + "（" + desc + "）";
    }
}
```

## 应用场景实战

### 场景一：从零申请商户号并完成小程序关联

以企业主体为例，从申请到可以联调的完整操作清单：

```text
步骤：
1. 确认主体 —— 企业营业执照在有效期内，经营范围包含实际业务
2. 准备资质 —— 营业执照照片、法人身份证正反面、对公账户开户行与账号
3. 申请入驻 —— pay.weixin.qq.com 扫码登录，选择「申请入驻 - 企业」
4. 填写信息 —— 主体信息、经营信息（类目/费率）、结算账户、超级管理员
5. 完成验证 —— 推荐法人微信扫码验证（即时），或对公打款验证（1-3 个工作日）
6. 等待审核 —— 1-5 个工作日，通过后短信通知，登录查看商户号
7. 设置密钥 —— 账户中心 - API 安全：设置 APIv3 密钥，申请 API 证书并下载
8. 开通产品 —— 产品中心开通「JSAPI 支付」，关联小程序 AppID
9. 配置回调 —— 准备 HTTPS 回调域名，联调时在下单接口传入 notify_url
10. 验证联调 —— 用 0.01 元真实小额支付跑通 10.2 的完整流程后销毁测试订单
```

申请完成后，建议把配置项整理成一张对照表存档，方便后续联调时快速排查问题：

```text
配置对照表（示例）：
1. 小程序 AppID —— wx1234567890abcdef（小程序后台 - 开发 - 开发管理 - 开发设置）
2. 商户号 mchid —— 1900000109（商户平台 - 账户中心 - 商户信息）
3. 商户证书序列号 —— 3775B6A45ACD58B4BA10827F447FEED（API 安全 - API 证书）
4. APIv3 密钥 —— 32 位随机串（API 安全 - APIv3 密钥，设置后不可查看）
5. 回调域名 —— api.example.com（已备案 + HTTPS 证书，Nginx 反代到 SpringBoot）
6. 关联状态 —— 商户平台 - 产品中心 - AppID 账号管理 中状态为「已关联」
```

### 场景二：用 openssl 与 Java 验证证书密钥配置正确

证书与密钥配置错误是支付联调第一天的头号报错源，用下面的脚本在写代码前先自检：

```bash
# 1. 证书与私钥配对校验
CERT_MOD=$(openssl x509 -noout -modulus -in apiclient_cert.pem | openssl md5)
KEY_MOD=$(openssl rsa -noout -modulus -in apiclient_key.pem | openssl md5)
if [ "$CERT_MOD" = "$KEY_MOD" ]; then
  echo "证书与私钥匹配: OK"
else
  echo "证书与私钥不匹配: FAIL（请重新下载证书）"
  exit 1
fi

# 2. 证书序列号（用于配置 merchantSerialNumber）
echo "证书序列号: $(openssl x509 -in apiclient_cert.pem -noout -serial | cut -d= -f2)"

# 3. APIv3 密钥长度校验（必须是 32 位）
V3KEY_LEN=${#API_V3_KEY}
[ "$V3KEY_LEN" -eq 32 ] && echo "APIv3 密钥长度: OK (32)" || echo "APIv3 密钥长度错误: $V3KEY_LEN"
```

自检通过后用下面的 Java 代码验证 SDK 配置能正常完成平台证书下载（网络可达 + 凭证正确）：

## 最佳实践与踩坑记录

### 最佳实践

1. 开通前先核对营业执照经营范围与小程序类目是否匹配收款业务，避免审核驳回后反复提交
2. APIv3 密钥与商户私钥严格区分环境：开发/测试/生产各用一套，生产密钥只放在配置中心或环境变量，禁止写入代码仓库
3. 商户私钥与 APIv3 密钥在团队内按「最小权限」分发：开发给测试环境密钥，生产密钥仅运维与核心开发持有
4. 证书到期前一个月在监控里加提醒，证书过期会导致所有支付请求签名失败，且不可热修复
5. 结算账户、提现操作归财务管理，开发者只负责 API 侧配置，职责分离降低资金风险
6. 上线前用 0.01 元小额真实支付完整跑一遍「下单 - 支付 - 回调 - 退款」，验证后再销毁测试数据
7. 一个商户号关联多个 AppID 时，把 AppID 与商户号的绑定关系记录在配置中心并加注释，避免多人协作时改错

### 踩坑记录

坑 1：个人主体无法开通微信支付
结论：个人主体小程序不能开通微信支付，也不能经营虚拟支付类业务。
原因：微信支付仅对企业、个体工商户等非个人主体开放，个人主体类目不含交易类。
解法：业务涉及收款必须提前注册企业/个体工商户主体；已注册个人号的需用企业主体重新注册。

坑 2：把 APIv2 密钥当成 APIv3 密钥配置
结论：配置了 32 位密钥仍然解密失败或下载证书失败。
原因：APIv2 密钥（商户 API 密钥）与 APIv3 密钥是两个不同的密钥，v3 接口与回调解密只认 APIv3 密钥。
解法：在商户平台「账户中心 - API 安全」分别查看；APIv3 密钥在「APIv3 密钥」菜单设置，与 APIv2 密钥互不影响。

坑 3：证书与私钥不匹配导致签名校验失败
结论：所有请求返回 401 签名错误或 401 平台证书序列号不匹配。
原因：apiclient_cert.pem 与 apiclient_key.pem 不是同一对密钥（常见于多人协作、文件覆盖、从旧环境拷贝）。
解法：用 openssl modulus md5 校验配对；不配对则到商户平台重新下载整套证书。

坑 4：商户私钥或 APIv3 密钥被提交进 Git 仓库
结论：密钥泄露后攻击者可伪造支付请求、解密回调报文，甚至篡改退款。
原因：开发时把 pem 文件放项目目录，随手 git add 提交。
解法：立即重置 APIv3 密钥并重新申请证书；把 *.pem 加入 .gitignore；历史提交用工具清理；密钥改放环境变量/配置中心。

坑 5：回调域名未备案或非 HTTPS 导致回调失败
结论：用户支付成功但商户后台收不到回调，订单永远停留在待支付。
原因：回调地址必须是公网可达的 HTTPS 域名；未备案域名或 IP 直连被微信侧拒绝。
解法：使用已备案域名 + HTTPS 证书；联调阶段可用内网穿透工具（如 ngrok）临时接收回调，上线前切回正式域名。

坑 6：证书到期未更新，支付全线失败
结论：某天所有支付下单请求突然报签名错误，线上无法收款。
原因：商户 API 证书有效期通常 5 年，到期后自动失效，请求签名不再被认可。
解法：监控证书到期时间，到期前一个月在商户平台重新申请证书并替换；切换时保证新旧证书短时间并存平滑过渡。

坑 7：H5 支付域名未在商户平台配置
结论：H5 支付拉起时报「商家参数格式有误」或直接提示不在支付授权目录。
原因：H5 支付要求商户平台「开发配置」中登记支付域名（需备案），且与实际请求域名一致。
解法：在商户平台登记 H5 支付域名；小程序支付不受该配置影响，无需配置支付目录。

坑 8：用个人微信收款码替代微信支付
结论：交易走个人收款码，无法获取支付回调、无法退款、无法对账，且涉嫌违规经营被限制收款。
原因：个人收款码不面向商户经营场景，没有商户号体系。
解法：正规业务一律走商户号 + JSAPI 支付；个人收款码只允许线下小额个人转账场景使用。

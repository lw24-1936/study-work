## 概述

wx.request 是小程序发起 HTTPS 网络请求的唯一标准 API，小程序没有浏览器环境的 fetch/XHR，所有与 SpringBoot 后台的交互都必须走它。本章覆盖 wx.request 的完整用法（url、method、header、data、回调函数）、请求参数与响应处理、超时设置与并发限制，以及工程上必做的 Promise 化请求封装、拦截器设计与防重复请求。

```text
网络请求 API 的核心内容：
1. wx.request —— 小程序唯一的 HTTP 请求 API，HTTPS 域名需在后台配置
2. 请求与响应 —— method/data/header 参数与 res.data/statusCode 响应结构
3. 超时与并发 —— timeout 参数、app.json networkTimeout、同域名并发上限 10
4. Promise 化 —— 基础库 2.10.2 起支持 Promise 风格，await 直接使用
5. 请求封装 —— 统一 baseURL、token 注入、错误处理、loading 控制
6. 拦截器与防重复 —— 请求/响应钩子设计，pending Map 去重与 abort
```

## wxrequest 基础用法

wx.request 接收一个配置对象，最核心的字段是 url、method、data、header，以及 success、fail、complete 三个回调。请求成功（收到 HTTP 响应，无论状态码）走 success，网络层失败（域名不可达、超时、未配置合法域名）走 fail，无论成败都会执行 complete。小程序发起的请求必须使用 HTTPS 协议，且域名需要在微信公众平台「开发 - 开发设置 - 服务器域名」中配置为 request 合法域名，否则真机上请求会直接失败。

```js
// 基础 GET 请求
wx.request({
  url: 'https://api.example.com/api/goods/list',
  method: 'GET',
  data: { category: 'phone', page: 1, size: 20 },
  success(res) {
    // res.statusCode 为 HTTP 状态码，2xx 表示 HTTP 层成功
    if (res.statusCode === 200) {
      console.log('响应数据', res.data);
    }
  },
  fail(err) {
    console.error('网络请求失败', err);
  },
  complete() {
    console.log('请求结束，无论成败都会执行');
  }
});
```

```js
// 基础 POST 请求，data 为 Object 时默认以 JSON 序列化传输
wx.request({
  url: 'https://api.example.com/api/user/login',
  method: 'POST',
  data: {
    code: 'wx-login-code',
    nickname: '张三'
  },
  header: {
    'Content-Type': 'application/json'
  },
  success(res) {
    console.log(res.data);
  },
  fail(err) {
    console.error('登录请求失败', err);
  }
});
```

```text
wx.request 基础要点：
1. url —— 必填，必须是 HTTPS 合法域名，开发工具可勾选「不校验合法域名」临时调试
2. method —— 可选，默认 GET；支持 OPTIONS/GET/HEAD/POST/PUT/DELETE/TRACE/CONNECT
3. data —— GET 时拼接为 query 参数，POST 等请求体传输，支持 String/Object/ArrayBuffer
4. success —— HTTP 响应到达即触发，与状态码无关，4xx/5xx 也走 success
5. fail —— 网络错误、超时、域名未配置等传输层失败才走 fail
6. complete —— 无论成功失败都执行，适合做 loading 关闭等收尾工作
```

## 请求参数与响应处理

method 决定 data 的传输方式：GET 时 data 会被序列化拼接到 url 的 query 中，POST/PUT 等作为请求体；header 用于携带 Content-Type、Authorization 等，默认 Content-Type 为 application/json。成功回调的 res 对象包含 data（响应体，dataType 为 json 时自动解析）、statusCode（HTTP 状态码）、header（响应头）、cookies、profile 等字段。错误处理要分层：HTTP 状态码表示传输层结果，业务成败靠后台返回的业务码（如 code 字段），两者必须分开判断。

```js
// GET 请求：data 自动拼接为 query
wx.request({
  url: 'https://api.example.com/api/goods/list',
  data: { category: 'phone', page: 1, size: 20 },
  success(res) {
    // 实际请求地址等价于 /api/goods/list?category=phone&page=1&size=20
    console.log(res.data);
  }
});
```

```js
// 完整响应对象结构
wx.request({
  url: 'https://api.example.com/api/goods/detail?id=1001',
  success(res) {
    const { statusCode, data, header, cookies } = res;
    console.log('HTTP 状态码', statusCode);   // 200
    console.log('响应体', data);              // 后台返回的 JSON（含业务 code）
    console.log('响应头', header);            // { 'content-type': 'application/json', ... }
    console.log('Cookie', cookies);

    // 业务码判断：后台约定 code === 0 表示业务成功
    if (statusCode === 200 && data.code === 0) {
      // 业务数据在 data.data
      this.setData({ goods: data.data });
    } else {
      wx.showToast({ title: data.message || '业务处理失败', icon: 'none' });
    }
  }
});
```

```js
// 携带自定义 header（token、版本号等）
wx.request({
  url: 'https://api.example.com/api/order/create',
  method: 'POST',
  data: { goodsId: 1001, count: 2 },
  header: {
    'Content-Type': 'application/json',
    Authorization: 'Bearer eyJhbGciOi...',
    'X-App-Version': '1.2.0'
  },
  success(res) {
    console.log(res.data);
  }
});
```

```text
请求参数与响应处理要点：
1. GET 传参 —— data 自动拼 query，嵌套对象会被序列化，复杂结构建议手写 query 字符串
2. POST 传参 —— 默认 application/json，data 为 Object 时自动 JSON 序列化
3. 响应结构 —— res.data 响应体、res.statusCode HTTP 状态码、res.header 响应头
4. 双层判断 —— 先判 statusCode 2xx，再判业务 code，两层都要处理
5. dataType —— 默认 json 自动解析；接口返回非 JSON 时改 dataType: 'text' 或 responseType: 'arraybuffer'
6. 特殊字符 —— 中文字符与 & 等符号交给小程序自动处理，复杂参数手动 encodeURIComponent
```

## 超时设置与并发限制

wx.request 默认超时 60 秒，可通过 timeout 参数（单位毫秒）为单次请求设置超时，也可在 app.json 的 networkTimeout 中配置全局默认值。超时后请求进入 fail 回调，errMsg 形如 request:fail timeout。并发方面，官方限制同一域名下 wx.request、wx.uploadFile、wx.downloadFile 的并发请求数上限为 10 个，超出上限的请求会排队等待或直接失败（不同基础库表现略有差异），因此批量请求场景需要在封装层自行控制并发。

```json
// app.json —— 全局网络超时配置（单位毫秒）
{
  "networkTimeout": {
    "request": 10000,
    "connectSocket": 10000,
    "uploadFile": 60000,
    "downloadFile": 60000
  }
}
```

```js
// 单次请求覆盖全局超时：5 秒超时
wx.request({
  url: 'https://api.example.com/api/goods/detail',
  data: { id: 1001 },
  timeout: 5000,
  success(res) {
    console.log(res.data);
  },
  fail(err) {
    // 超时后 err.errMsg 包含 timeout
    console.error(err.errMsg);
  }
});
```

```js
// 并发控制：封装一个最多同时发起 4 个请求的队列
function runWithConcurrency(tasks, limit) {
  const results = [];
  let index = 0;
  let running = 0;

  return new Promise((resolve, reject) => {
    function next() {
      if (index >= tasks.length && running === 0) {
        resolve(results);
        return;
      }
      while (running < limit && index < tasks.length) {
        const current = index++;
        running++;
        tasks[current]()
          .then((res) => { results[current] = res; })
          .catch((err) => { results[current] = err; })
          .finally(() => {
            running--;
            next();
          });
      }
    }
    next();
  });
}

// 使用：一次拉取 30 页数据，但并发控制在 4 个以内
const tasks = Array.from({ length: 30 }, (_, i) => () =>
  new Promise((resolve, reject) => {
    wx.request({
      url: 'https://api.example.com/api/goods/list',
      data: { page: i + 1, size: 20 },
      success: resolve,
      fail: reject
    });
  })
);

runWithConcurrency(tasks, 4).then((list) => {
  console.log('全部拉取完成', list.length);
});
```

```text
超时与并发要点：
1. 默认超时 —— wx.request 默认 60 秒，生产环境务必显式设置更短的 timeout
2. 全局配置 —— app.json networkTimeout 可配置 request/connectSocket/uploadFile/downloadFile 四项
3. 单次覆盖 —— 单次请求的 timeout 参数优先级高于全局配置
4. 并发上限 —— 同一域名并发请求上限 10 个，超出排队或失败，基础库版本不同表现不同
5. 主动控制 —— 批量接口用并发队列，避免一次性发起大量请求
6. 超时提示 —— 超时进入 fail，需给用户「网络异常，请稍后重试」的反馈
```

## Promise 化与请求封装

从基础库 2.10.2 开始，wx.request 在不传 success/fail/complete 回调时返回 Promise，可以直接用 async/await 书写异步逻辑。但要注意：Promise 风格下 resolve 的仍是 res 响应对象，HTTP 4xx/5xx 并不会 reject，状态码判断依然要自己做。工程上更常见的做法是封装统一的 request 模块：集中管理 baseURL、超时、token 注入、状态码处理、错误提示与 loading，页面只关心业务数据。

```js
// Promise 风格：基础库 2.10.2+，不传回调直接 await
async function loadGoods() {
  const res = await wx.request({
    url: 'https://api.example.com/api/goods/detail',
    data: { id: 1001 }
  });
  // 注意：4xx/5xx 也会 resolve，必须自己判断 statusCode
  if (res.statusCode === 200 && res.data.code === 0) {
    return res.data.data;
  }
  throw new Error(res.data.message || '请求失败');
}
```

```js
// utils/request.js —— 统一请求封装（项目标准做法）
const BASE_URL = 'https://api.example.com';

const STATUS_TEXT = {
  400: '请求参数错误',
  401: '登录已过期，请重新登录',
  403: '没有权限访问',
  404: '资源不存在',
  500: '服务器开小差了',
  502: '网关错误',
  504: '服务响应超时'
};

function request(options) {
  return new Promise((resolve, reject) => {
    const token = wx.getStorageSync('token');
    wx.request({
      url: `${BASE_URL}${options.url}`,
      method: options.method || 'GET',
      data: options.data || {},
      timeout: options.timeout || 10000,
      header: {
        'Content-Type': 'application/json',
        Authorization: token ? `Bearer ${token}` : '',
        ...options.header
      },
      success(res) {
        if (res.statusCode >= 200 && res.statusCode < 300) {
          const body = res.data;
          if (body && body.code === 0) {
            resolve(body.data);
          } else {
            wx.showToast({ title: (body && body.message) || '业务处理失败', icon: 'none' });
            reject(body || res);
          }
        } else if (res.statusCode === 401) {
          // 登录态失效：清 token，跳登录页（登录页自身请求需跳过该逻辑）
          wx.removeStorageSync('token');
          wx.showToast({ title: '登录已过期，请重新登录', icon: 'none' });
          setTimeout(() => {
            wx.reLaunch({ url: '/pages/login/login' });
          }, 800);
          reject(res);
        } else {
          wx.showToast({ title: STATUS_TEXT[res.statusCode] || '请求失败', icon: 'none' });
          reject(res);
        }
      },
      fail(err) {
        wx.showToast({ title: '网络异常，请稍后重试', icon: 'none' });
        reject(err);
      }
    });
  });
}

module.exports = {
  get(url, data, options) {
    return request({ url, data, method: 'GET', ...options });
  },
  post(url, data, options) {
    return request({ url, data, method: 'POST', ...options });
  },
  put(url, data, options) {
    return request({ url, data, method: 'PUT', ...options });
  },
  del(url, data, options) {
    return request({ url, data, method: 'DELETE', ...options });
  },
  request
};
```

```js
// 页面中使用封装
const api = require('../../utils/request.js');

Page({
  data: { list: [], loading: false },
  async onLoad() {
    this.setData({ loading: true });
    try {
      const list = await api.get('/api/goods/list', { page: 1, size: 20 });
      this.setData({ list });
    } catch (e) {
      // 错误已在封装层统一提示，这里处理业务兜底
    } finally {
      this.setData({ loading: false });
    }
  }
});
```

```text
Promise 化与封装要点：
1. Promise 风格 —— 基础库 2.10.2+ 支持，不传回调返回 Promise，可用 await
2. 不自动 reject —— 4xx/5xx 也会 resolve，状态码判断不能省
3. 统一 baseURL —— 环境差异（dev/test/prod）只在封装层切换
4. token 注入 —— 请求层统一读取 storage 并写入 Authorization，页面零感知
5. 错误分层 —— HTTP 状态码、业务 code、网络异常三档分别处理
6. 页面瘦身 —— 页面只写业务代码，网络细节全部收敛在 utils/request.js
```

## 拦截器设计与防重复请求

小程序没有 axios 那样的原生拦截器，但可以在封装层实现同样的效果：请求发出前执行前置钩子（注入 token、加时间戳、防重复检查、开 loading），响应返回后执行后置钩子（解包数据、401 统一处理、关 loading）。防重复请求是高频需求，典型场景是用户双击提交按钮导致订单重复创建：维护一个 pending Map，以「method + url + 序列化参数」为 key，请求在途时直接复用同一个 Promise 或调用 RequestTask.abort() 取消旧请求。

```js
// utils/request.js 增强版 —— 拦截器钩子 + 防重复请求
const BASE_URL = 'https://api.example.com';
const pendingMap = new Map();   // key -> Promise，用于去重
const taskMap = new Map();      // key -> RequestTask，用于 abort

function buildKey(options) {
  return `${options.method || 'GET'}_${options.url}_${JSON.stringify(options.data || {})}`;
}

// 请求前拦截：token 注入、公共参数、loading
function requestInterceptor(options) {
  const token = wx.getStorageSync('token');
  options.header = {
    'Content-Type': 'application/json',
    Authorization: token ? `Bearer ${token}` : '',
    ...options.header
  };
  return options;
}

// 响应后拦截：状态码与业务码处理
function responseInterceptor(res, options, resolve, reject) {
  if (res.statusCode >= 200 && res.statusCode < 300) {
    const body = res.data;
    if (body && body.code === 0) {
      resolve(body.data);
    } else {
      reject(body || res);
    }
  } else if (res.statusCode === 401) {
    wx.removeStorageSync('token');
    wx.reLaunch({ url: '/pages/login/login' });
    reject(res);
  } else {
    reject(res);
  }
}

function request(options, config = {}) {
  const key = buildKey(options);
  const { dedupe = true } = config;

  // 防重复：相同请求在途时直接复用
  if (dedupe && pendingMap.has(key)) {
    return pendingMap.get(key);
  }

  const promise = new Promise((resolve, reject) => {
    const finalOptions = requestInterceptor({ ...options });
    const task = wx.request({
      ...finalOptions,
      success(res) {
        responseInterceptor(res, finalOptions, resolve, reject);
      },
      fail(err) {
        reject(err);
      },
      complete() {
        pendingMap.delete(key);
        taskMap.delete(key);
      }
    });
    taskMap.set(key, task);
  });

  if (dedupe) {
    pendingMap.set(key, promise);
  }
  return promise;
}

// 取消某个在途请求（如用户离开页面时）
function abort(key) {
  const task = taskMap.get(key);
  if (task) {
    task.abort();
    taskMap.delete(key);
    pendingMap.delete(key);
  }
}

module.exports = { request, abort, buildKey };
```

```js
// 下单页：防重复提交
const api = require('../../utils/request.js');

Page({
  data: { submitting: false },
  async onSubmit() {
    if (this.data.submitting) return;   // 按钮级兜底
    this.setData({ submitting: true });
    try {
      const order = await api.request(
        { url: '/api/order/create', method: 'POST', data: { goodsId: 1001, count: 2 } },
        { dedupe: true }                // 在途重复请求自动复用，杜绝双单
      );
      wx.showToast({ title: '下单成功', icon: 'success' });
      wx.navigateTo({ url: `/pages/order/detail?id=${order.id}` });
    } catch (e) {
      // 错误提示已在封装层处理
    } finally {
      this.setData({ submitting: false });
    }
  }
});
```

```text
拦截器与防重复要点：
1. 前置钩子 —— 发送前统一做 token 注入、参数加工、loading 计数
2. 后置钩子 —— 响应后统一解包、错误提示、401 跳登录
3. pending Map —— 以 method+url+参数 为 key 记录在途请求，重复请求复用 Promise
4. RequestTask.abort —— wx.request 返回的任务对象支持 abort()，可主动取消
5. 登出兜底 —— 防重复不等于禁用重复，按钮 disabled + 请求层去重双保险
6. 页面卸载清理 —— onUnload 中 abort 未完成请求，避免回调操作已销毁页面
```

## 应用场景实战

### 场景一：登录请求与 token 注入完整闭环

用统一封装实现登录流程：登录接口获取 token 写入 storage，后续所有请求自动携带 token，token 失效时统一跳转登录页：

```js
// api/auth.js —— 登录相关接口
const api = require('../utils/request.js');

function login(code) {
  return api.post('/api/user/login', { code });
}

module.exports = { login };
```

```js
// pages/login/login.js
const auth = require('../../api/auth.js');

Page({
  data: { loading: false },
  async onLoginTap() {
    this.setData({ loading: true });
    try {
      // 1. 微信登录获取临时 code
      const { code } = await new Promise((resolve, reject) => {
        wx.login({ success: resolve, fail: reject });
      });
      // 2. 后端用 code 换 token（code2session 逻辑在 SpringBoot 侧）
      const data = await auth.login(code);
      // 3. 写入本地缓存，后续请求由封装层自动注入
      wx.setStorageSync('token', data.token);
      wx.setStorageSync('userInfo', data.userInfo);
      // 4. 回跳来源页
      const pages = getCurrentPages();
      if (pages.length > 1) {
        wx.navigateBack();
      } else {
        wx.reLaunch({ url: '/pages/index/index' });
      }
    } catch (e) {
      wx.showToast({ title: '登录失败，请重试', icon: 'none' });
    } finally {
      this.setData({ loading: false });
    }
  }
});
```

```js
// 登录成功后拉取用户订单：无需手动带 token
const api = require('../../utils/request.js');

Page({
  async onLoad() {
    const orders = await api.get('/api/order/list', { page: 1 });
    this.setData({ orders });
  }
});
```

```text
场景一关键步骤：
1. wx.login 获取 code，交给后台换取 token
2. token 写入 storage，封装层请求前自动注入 Authorization
3. 401 时封装层统一清 token 并 reLaunch 到登录页
4. 登录成功按页面栈深度决定返回还是重定向首页
5. 业务页面完全感知不到 token 的存在
```

### 场景二：列表页加载 + 下拉刷新 + 防重复请求

电商列表页常见的完整请求场景：首次加载、下拉刷新、上拉加载更多，同时避免刷新与加载并发冲突：

```js
// pages/goods-list/goods-list.js
const api = require('../../utils/request.js');

Page({
  data: {
    list: [],
    page: 1,
    hasMore: true,
    loading: false
  },
  onLoad() {
    this.loadPage(1);
  },
  onPullDownRefresh() {
    this.loadPage(1, () => wx.stopPullDownRefresh());
  },
  onReachBottom() {
    if (!this.data.hasMore || this.data.loading) return;
    this.loadPage(this.data.page + 1);
  },
  async loadPage(page, done) {
    if (this.data.loading) return;          // 请求层 + 页面层双防重复
    this.setData({ loading: true });
    try {
      const res = await api.get('/api/goods/list', { page, size: 20 });
      const list = page === 1 ? res.list : this.data.list.concat(res.list);
      this.setData({
        list,
        page,
        hasMore: list.length < res.total
      });
    } catch (e) {
      wx.showToast({ title: '加载失败', icon: 'none' });
    } finally {
      this.setData({ loading: false });
      if (done) done();
    }
  }
});
```

## 最佳实践与踩坑记录

### 最佳实践

1. 所有请求统一走封装层（utils/request.js），禁止页面里散落裸 wx.request，方便后续加埋点、加密、灰度
2. baseURL 按环境区分（dev/test/prod），通过构建时注入的环境变量切换，严禁写死在页面里
3. 每个请求显式设置超时（建议 5-10 秒），避免默认 60 秒导致用户长时间无反馈
4. HTTP 状态码与业务码分层处理：2xx 表示传输成功，code === 0 表示业务成功，两者都要校验
5. token 注入、401 处理、loading 控制全部收敛在封装层，页面只关心业务数据
6. 提交类接口（下单、支付、评价）务必防重复请求，按钮 disabled + 请求层 pending Map 双保险
7. 分页与列表请求统一管理 page/hasMore/loading 状态，防止重复加载与数据错乱
8. 页面 onUnload 时 abort 未完成的请求，避免异步回调操作已销毁的页面实例

### 踩坑记录

```text
坑 1：真机请求失败「url not in domain list」
结论：模拟器正常，真机预览所有请求都失败。
原因：未在微信公众平台配置 request 合法域名，或域名不是 HTTPS；开发工具勾选了「不校验合法域名」掩盖了问题。
解法：在「开发 - 开发设置 - 服务器域名」添加 request 合法域名；生产环境域名必须 HTTPS 且有有效证书；本地调试用工具的不校验选项，上线前关闭。

坑 2：接口返回 404/500 却走了 success，页面误判成功
结论：后台报错，前端却进入了成功分支，展示空数据。
原因：wx.request 只要收到 HTTP 响应就走 success，4xx/5xx 状态码不会触发 fail。
解法：success 回调里必须判断 res.statusCode，非 2xx 一律按失败处理；fail 只处理网络层错误。

坑 3：GET 请求传复杂对象，后台收到的是空参数
结论：GET 带数组或嵌套对象参数，后台 request.getParameter 取不到值。
原因：wx.request 对 GET data 的序列化规则与后端解析不一致，嵌套对象/数组会被转成 a[0]=1 这类格式或直接丢弃。
解法：GET 复杂参数手动拼 query 字符串并用 encodeURIComponent 编码；或改用 POST 传 JSON。

坑 4：并发请求超过 10 个，部分请求挂起或失败
结论：批量拉取数据时，部分请求长时间无响应或直接失败。
原因：同域名并发请求数上限为 10，超出部分排队或失败，不同基础库表现不同。
解法：封装层做并发队列控制（如同时最多 4 个）；批量场景分批请求；必要时把接口改为批量聚合接口。

坑 5：401 后所有在途请求都弹「登录已过期」
结论：token 过期后，页面瞬间弹出多个重复的登录过期提示。
原因：多个并发请求同时返回 401，各自都执行了 toast 与跳转逻辑。
解法：401 处理加全局标记（如 window 级变量或模块级 flag），只处理第一次；后续 401 静默，统一跳登录。

坑 6：登录接口自身 401 导致死循环跳登录页
结论：登录页调用登录接口时收到 401，被封装层强制 reLaunch 回登录页，反复横跳。
原因：401 处理逻辑没有排除登录相关接口。
解法：登录接口（以及 token 刷新接口）传配置跳过 401 跳转，如 options.skipAuthCheck = true；401 处理前判断该标记。

坑 7：Promise 风格下 4xx/5xx 不 reject，漏判状态码
结论：用 await wx.request 后，接口 500 时没有走 catch，页面照常渲染空数据。
原因：Promise 风格 resolve 的是 res 响应对象，HTTP 错误状态不会导致 reject。
解法：await 后必须检查 res.statusCode；更稳妥的做法是使用统一封装，由封装层完成状态码判断。

坑 8：超时时间设置过长或漏设，用户等待无反馈
结论：弱网环境下请求长时间转圈，用户以为卡死。
原因：未设置 timeout，使用默认 60 秒；或全局 loading 没有超时兜底。
解法：单请求显式设置 5-10 秒超时；app.json networkTimeout 配置全局默认；loading 最长展示时间做兜底，超时强制关闭。
```

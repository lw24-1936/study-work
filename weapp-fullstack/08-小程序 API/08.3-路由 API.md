## 概述

路由 API 控制小程序页面之间的跳转与返回，包括 wx.navigateTo（保留当前页入栈）、wx.redirectTo（关闭当前页替换）、wx.switchTab（切换 tabBar 页面）、wx.navigateBack（返回上一页）、wx.reLaunch（关闭所有页面重新打开）。小程序用「页面栈」管理页面实例：栈底是第一个打开的页面，栈顶是当前展示的页面，栈深度上限 10 层。理解页面栈模型与每个 API 对栈的操作方式，是写出正确导航逻辑的前提。

```text
路由 API 的核心内容：
1. 页面栈模型 —— 栈底首页、栈顶当前页，最多 10 层
2. wx.navigateTo —— 压栈跳转，可传参，保留返回路径
3. wx.redirectTo / wx.switchTab —— 替换当前页 / 只跳 tabBar 页
4. wx.navigateBack / wx.reLaunch —— 出栈返回 / 清栈重开
5. 参数传递 —— url query 传参、eventChannel 通道、页面栈实例通信
6. 失败处理 —— 栈满、跳 tabBar 页、路径错误等常见失败场景
```

## 路由体系与页面栈

小程序启动后，微信按 app.json 的 pages 数组打开首页并维护一个页面栈。每次 wx.navigateTo 往栈顶压入新页面，wx.navigateBack 弹出栈顶页面，wx.redirectTo 用新页面替换栈顶，wx.reLaunch 清空整个栈。页面栈可通过 getCurrentPages() 获取，返回页面实例数组，最后一个是当前页。页面生命周期与栈操作联动：压栈时新页面触发 onLoad/onShow、旧页面 onHide；出栈时新页面 onUnload、旧页面重新 onShow。

```js
// 查看当前页面栈
Page({
  onShow() {
    const pages = getCurrentPages();
    console.log('页面栈深度', pages.length);
    console.log('当前页', pages[pages.length - 1]);
    console.log('上一页', pages[pages.length - 2]);
  }
});
```

```js
// 在任意页面（非 tabBar 页）打印路由状态，理解栈模型
function printRouteStack() {
  const pages = getCurrentPages();
  const routes = pages.map((p) => p.route);
  console.log(`当前栈深度 ${pages.length}：`, routes.join(' -> '));
  // 示例输出：pages/index/index -> pages/goods/list -> pages/goods/detail
}

printRouteStack();
```

```text
页面栈要点：
1. 栈结构 —— 栈底为首页，栈顶为当前页，数组顺序即页面层级
2. 深度上限 —— 页面栈最多 10 层，超过则 navigateTo 失败
3. 生命周期联动 —— 入栈触发新页 onLoad/onShow，出栈触发旧页 onShow
4. getCurrentPages —— 返回页面实例数组，最后一个为当前页
5. tabBar 页 —— 在栈中只有一个实例，switchTab 不会重复压栈
6. 实例操作 —— 页面实例可读 data、调方法，但禁止跨页 setData 渲染
```

## wxnavigateto 页面跳转

wx.navigateTo 是最常用的跳转 API：当前页面保留在栈中（触发 onHide），新页面压入栈顶（触发 onLoad/onShow）。url 支持携带 query 参数，参数在目标页面的 onLoad(options) 中接收，微信会自动解码一次。传对象等复杂数据时先 JSON.stringify 再 encodeURIComponent，接收端直接 JSON.parse，不要再手动二次解码。navigateTo 不能跳转 tabBar 页面，且页面栈满 10 层时会失败。

```js
// 基础跳转 + 传参
wx.navigateTo({
  url: '/pages/goods/detail?id=1001&from=home',
  success() {
    console.log('跳转成功');
  },
  fail(err) {
    console.error('跳转失败', err);
  }
});
```

```js
// 目标页 onLoad 接收参数
Page({
  onLoad(options) {
    console.log(options.id);    // 1001
    console.log(options.from);  // home
  }
});
```

```js
// 传递复杂对象：先序列化再编码，接收端直接 JSON.parse
const goods = { id: 1001, name: '手机', price: 2999 };
wx.navigateTo({
  url: '/pages/goods/detail?goods=' + encodeURIComponent(JSON.stringify(goods))
});
```

```js
// 接收复杂对象
Page({
  onLoad(options) {
    if (options.goods) {
      // 微信已自动解码一次，这里直接 JSON.parse，不要二次 decodeURIComponent
      const goods = JSON.parse(options.goods);
      console.log(goods.name);
    }
  }
});
```

```js
// 使用 eventChannel 在新旧页面之间双向传数据（基础库 2.7.3+）
// 页面 A：跳转并监听页面 B 的回传
wx.navigateTo({
  url: '/pages/goods/select',
  events: {
    onSelect(result) {
      console.log('页面 B 回传的选择结果', result);
    }
  },
  success(res) {
    // 向页面 B 传递初始数据
    res.eventChannel.emit('init', { maxCount: 3 });
  }
});
```

```js
// 页面 B：接收初始数据并在返回前回传结果
Page({
  onLoad() {
    const channel = this.getOpenerEventChannel();
    channel.on('init', (data) => {
      console.log('收到初始化数据', data);
    });
  },
  onChoose(item) {
    const channel = this.getOpenerEventChannel();
    channel.emit('onSelect', { id: item.id, name: item.name });
    wx.navigateBack();
  }
});
```

```text
wx.navigateTo 要点：
1. 压栈跳转 —— 旧页面保留（onHide），新页面入栈（onLoad/onShow），可返回
2. query 传参 —— url 后跟 ?key=value&key2=value2，onLoad(options) 接收
3. 自动解码 —— 微信对 url 参数自动解码一次，接收端不要二次 decode
4. 对象传参 —— JSON.stringify + encodeURIComponent，接收端 JSON.parse
5. eventChannel —— events 参数监听回传，eventChannel.emit 传初始数据，双向通信
6. 限制 —— 不能跳 tabBar 页，页面栈满 10 层失败
```

## wxredirectto 与 wxswitchtab

wx.redirectTo 关闭当前页面（触发 onUnload），用新页面替换栈顶，适用于表单提交成功、登录完成等「不需要返回」的场景。wx.switchTab 用于切换到 tabBar 页面：会关闭所有非 tabBar 页面，但 tabBar 页面在栈中只有一个实例；switchTab 的 url 不能携带参数，重复切换同一个 tab 不会重新触发 onLoad。两者都不能跳转 tabBar 页之外的目标——switchTab 只能跳 tabBar 页，redirectTo 不能跳 tabBar 页。

```js
// redirectTo：提交成功后替换当前页，防止用户返回重复提交
Page({
  onSubmitSuccess(orderId) {
    wx.redirectTo({
      url: `/pages/order/detail?id=${orderId}`,
      success() {
        console.log('已替换当前页面');
      }
    });
  }
});
```

```js
// switchTab：切换到底部 tab
wx.switchTab({
  url: '/pages/index/index',
  success() {
    console.log('切换到首页 tab');
  },
  fail(err) {
    // 目标不是 tabBar 页面时会失败
    console.error(err);
  }
});
```

```json
// app.json —— tabBar 配置，switchTab 只能跳这里注册的页面
{
  "tabBar": {
    "list": [
      { "pagePath": "pages/index/index", "text": "首页" },
      { "pagePath": "pages/cart/cart", "text": "购物车" },
      { "pagePath": "pages/mine/mine", "text": "我的" }
    ]
  }
}
```

```text
redirectTo 与 switchTab 要点：
1. redirectTo —— 关闭当前页并用新页替换栈顶，当前页 onUnload
2. redirectTo 限制 —— 不能跳转 tabBar 页面
3. switchTab —— 只能跳 tabBar 配置的页面，url 不能带参数
4. 单实例 —— tabBar 页面栈中只有一份，重复 switchTab 不触发 onLoad（触发 onShow）
5. 清非 tab 页 —— switchTab 会关闭所有非 tabBar 页面
6. 适用场景 —— 提交成功用 redirectTo，底部导航切换用 switchTab
```

## wxnavigateback 与 wxrelaunch

wx.navigateBack 从栈中弹出页面，delta 参数控制返回层数（默认 1）。返回的页面不会重新触发 onLoad，只会触发 onShow，因此返回后需要刷新数据的逻辑应写在 onShow 里。wx.reLaunch 关闭所有页面（整个页面栈清空）并打开新页面，可带参数，也能打开 tabBar 页面，常用于退出登录、强制回首页等「不留返回路径」的场景。navigateBack 跨页回传数据推荐用 eventChannel 或全局状态，而不是跨页 setData。

```js
// navigateBack：返回上一页 / 返回两层
wx.navigateBack();                 // 等价于 delta: 1
wx.navigateBack({ delta: 2 });     // 返回两层
```

```js
// 返回后刷新数据：返回的页面只触发 onShow，刷新逻辑放这里
Page({
  onShow() {
    // 每次回到本页（首次进入或从下级页面返回）都会执行
    this.refreshList();
  },
  refreshList() {
    // 拉取最新列表
  }
});
```

```js
// reLaunch：清空页面栈，强制回到指定页面
Page({
  onLogout() {
    wx.removeStorageSync('token');
    wx.reLaunch({
      url: '/pages/login/login',
      success() {
        console.log('已清空页面栈并打开登录页');
      }
    });
  }
});
```

```js
// navigateBack 配合 eventChannel 回传数据
// 页面 A：跳转选择页并监听回传
wx.navigateTo({
  url: '/pages/address/select',
  events: {
    onAddressSelected(address) {
      console.log('收到选择的地址', address);
      this.setData({ address });
    }
  }
});
```

```js
// 页面 B：确认选择后回传并返回
Page({
  onConfirm(address) {
    this.getOpenerEventChannel().emit('onAddressSelected', address);
    wx.navigateBack();
  }
});
```

```text
navigateBack 与 reLaunch 要点：
1. navigateBack —— 出栈返回，delta 默认 1，delta 超出栈深则回到栈底
2. 不触发 onLoad —— 返回页面只触发 onShow，刷新逻辑写在 onShow
3. reLaunch —— 关闭所有页面清空栈，可带参，可打开 tabBar 页
4. 回传数据 —— eventChannel / 全局 store / storage，不要跨页 setData
5. 适用场景 —— 返回用 navigateBack，退出登录/强制首页用 reLaunch
6. 栈底保护 —— 栈底页面调用 navigateBack 无效，先判断页面栈深度
```

## 页面栈操作与跳转失败处理

getCurrentPages() 返回页面实例数组，可用于读取路由信息、获取上一页实例调用其方法，但绝不能跨页 setData（隐藏页面不渲染，且违背组件通信原则）。跳转失败的高频原因：navigateTo 页面栈满 10 层、navigateTo/redirectTo 目标是 tabBar 页面、switchTab 目标不是 tabBar 页面、页面路径未注册或拼写错误、url 参数超长。生产项目应封装统一跳转工具，处理栈满降级、登录拦截、埋点上报。

```js
// 统一跳转封装：处理栈满降级
function safeNavigate(url) {
  const pages = getCurrentPages();
  if (pages.length >= 10) {
    // 栈满时用 redirectTo 替换当前页，保证跳转可用
    wx.redirectTo({ url });
  } else {
    wx.navigateTo({ url });
  }
}

// 带登录校验的跳转
function navigateWithAuth(url) {
  const token = wx.getStorageSync('token');
  if (!token) {
    wx.navigateTo({ url: '/pages/login/login' });
    return;
  }
  safeNavigate(url);
}

module.exports = { safeNavigate, navigateWithAuth };
```

```js
// 读取上一页实例并调用其方法（推荐做法，替代跨页 setData）
function callPrevPage(method, ...args) {
  const pages = getCurrentPages();
  const prev = pages[pages.length - 2];
  if (prev && typeof prev[method] === 'function') {
    prev[method](...args);
  }
}

// 使用：详情页返回前通知列表页刷新
callPrevPage('refreshList');
```

```js
// 跳转失败统一处理
wx.navigateTo({
  url: '/pages/goods/detail?id=1001',
  success() {
    console.log('跳转成功');
  },
  fail(err) {
    console.error('跳转失败：', err.errMsg);
    // errMsg 示例：navigateTo:fail webview count limit exceed（栈满）
    // 示例：navigateTo:fail can not navigateTo a tabbar page（目标为 tabBar 页）
    wx.showToast({ title: '页面打开失败', icon: 'none' });
  }
});
```

```text
页面栈操作与失败处理要点：
1. getCurrentPages —— 只读操作，拿实例调方法可以，跨页 setData 禁止
2. 栈满降级 —— 页面栈 10 层上限，满了用 redirectTo 或先 navigateBack
3. 目标限制 —— navigateTo/redirectTo 不能跳 tabBar 页，switchTab 只能跳 tabBar 页
4. 路径校验 —— 目标页必须在 app.json pages 中注册且路径拼写正确
5. 失败回调 —— 跳转都传 success/fail，失败给用户反馈并上报
6. 统一封装 —— 跳转工具集中处理登录拦截、栈满降级、埋点，页面不裸调 wx API
```

## 应用场景实战

### 场景一：商品列表 → 详情 → 下单的完整页面栈流转

电商核心路径：列表页进入详情页（navigateTo 传对象参数），详情页跳转下单页（navigateTo 传商品与数量），下单成功后 redirectTo 到订单详情（防止返回重复提交），再 navigateBack 回列表刷新：

```js
// pages/goods/list.js —— 列表页
Page({
  onGoodsTap(e) {
    const goods = e.currentTarget.dataset.goods;
    wx.navigateTo({
      url: '/pages/goods/detail?goods=' + encodeURIComponent(JSON.stringify(goods))
    });
  },
  onShow() {
    // 从详情页返回时刷新（返回只触发 onShow）
    this.refreshList();
  }
});
```

```js
// pages/goods/detail.js —— 详情页
Page({
  data: { goods: null, count: 1 },
  onLoad(options) {
    // 微信自动解码一次，直接 JSON.parse
    const goods = JSON.parse(options.goods);
    this.setData({ goods });
  },
  onBuyTap() {
    const { goods, count } = this.data;
    wx.navigateTo({
      url: `/pages/order/confirm?goodsId=${goods.id}&count=${count}`,
      events: {
        // 监听下单页回传的支付结果，用于埋点
        onPaid(result) {
          console.log('支付结果', result);
        }
      }
    });
  }
});
```

```js
// pages/order/confirm.js —— 下单页
Page({
  data: { goodsId: 0, count: 1, submitting: false },
  onLoad(options) {
    this.setData({ goodsId: options.goodsId, count: Number(options.count) });
  },
  async onSubmit() {
    if (this.data.submitting) return;
    this.setData({ submitting: true });
    try {
      const order = await api.post('/api/order/create', {
        goodsId: this.data.goodsId,
        count: this.data.count
      });
      // 提交成功：redirectTo 替换当前页，防止返回重复提交
      wx.redirectTo({
        url: `/pages/order/detail?id=${order.id}`,
        success: () => {
          this.getOpenerEventChannel().emit('onPaid', { success: true });
        }
      });
    } finally {
      this.setData({ submitting: false });
    }
  }
});
```

```text
场景一关键步骤：
1. 列表 -> 详情用 navigateTo + 对象参数（序列化 + 编码）
2. 详情 -> 下单用 navigateTo + eventChannel 双向通信
3. 下单成功用 redirectTo，栈顶替换，杜绝返回重复提交
4. 列表页 onShow 刷新，返回后数据最新
5. 页面栈深度保持 2-3 层，远离 10 层上限
```

### 场景二：登录拦截与强制回首页

未登录用户访问需登录页面时跳转登录页，登录成功后按来源决定返回或重定向；退出登录时 reLaunch 清栈强制回首页：

```js
// utils/auth.js —— 登录拦截封装
function ensureLogin(url) {
  const token = wx.getStorageSync('token');
  if (token) {
    safeNavigate(url);
    return true;
  }
  // 未登录：记录来源页，登录成功后回跳
  wx.setStorageSync('login_redirect', url);
  wx.navigateTo({ url: '/pages/login/login' });
  return false;
}

// 登录成功后的回跳逻辑（登录页调用）
function handleLoginSuccess() {
  const redirect = wx.getStorageSync('login_redirect');
  wx.removeStorageSync('login_redirect');
  if (redirect) {
    wx.redirectTo({ url: redirect });   // 替换登录页，回跳来源
  } else {
    wx.switchTab({ url: '/pages/index/index' });
  }
}
```

```js
// pages/mine/mine.js —— 退出登录
Page({
  onLogoutTap() {
    wx.showModal({
      title: '提示',
      content: '确定退出登录吗？',
      success: (res) => {
        if (!res.confirm) return;
        wx.removeStorageSync('token');
        wx.removeStorageSync('userInfo');
        // reLaunch 清空整个页面栈，不留任何业务页面
        wx.reLaunch({ url: '/pages/index/index' });
      }
    });
  }
});
```

```text
场景二关键步骤：
1. ensureLogin 统一拦截，未登录记录来源页
2. 登录成功 redirectTo 回跳来源页（替换登录页）
3. 无来源页时 switchTab 回首页
4. 退出登录 reLaunch 清空页面栈，防止返回键回到已退出状态页面
5. 登录页自身禁止 ensureLogin 拦截，避免死循环
```

## 最佳实践与踩坑记录

### 最佳实践

1. 优先 navigateTo 保留返回路径；表单提交成功后用 redirectTo 替换当前页，防止返回重复提交
2. 大量数据不走 url 传参，用 eventChannel、全局 store 或 storage，url 只传 id 等短参数
3. tabBar 切换统一 switchTab，且不要在 switchTab 的 url 上带参数（不生效）
4. 页面栈接近 10 层时主动用 redirectTo 或 reLaunch 收敛，避免跳转失败
5. 跳转统一封装成工具函数，集中处理登录拦截、栈满降级、埋点上报
6. 返回后需要刷新数据的逻辑一律写在 onShow，不要依赖跨页 setData
7. 传对象参数统一 JSON.stringify + encodeURIComponent，接收端 JSON.parse，规范写在团队文档里
8. 登录、退出登录等状态变更跳转用 reLaunch 清栈，杜绝返回键进入状态不一致的页面

### 踩坑记录

```text
坑 1：navigateTo 跳 tabBar 页面失败
结论：从普通页面 navigateTo 到 tab 页，控制台报 can not navigateTo a tabbar page。
原因：tabBar 页面只能用 switchTab 或 reLaunch 打开，navigateTo/redirectTo 不允许。
解法：目标页是 tab 页时改用 wx.switchTab；reLaunch 也可以打开 tab 页但会清空页面栈。

坑 2：页面栈超过 10 层跳转失败
结论：连续跳转多层后 navigateTo 失败，报 webview count limit exceed。
原因：页面栈深度上限 10 层，超过后 navigateTo 直接失败，无任何提示用户看到的就是点不动。
解法：封装跳转工具，栈满时降级为 redirectTo；业务上控制跳转层级（列表->详情->下单即可，不要无限下钻）。

坑 3：switchTab 传参数不生效
结论：switchTab 的 url 带了 ?id=xxx，目标页 onLoad 里 options 是空的。
原因：switchTab 的 url 不支持 query 参数，参数被忽略。
解法：改用 reLaunch（可带参数）或先把参数写入 storage/全局变量，再 switchTab，目标页 onShow 读取。

坑 4：参数包含 & 或中文导致解析错乱
结论：传参包含特殊字符时，目标页拿到的参数被截断或乱码。
原因：& 会被当成参数分隔符，中文等特殊字符未编码导致解析异常。
解法：参数值统一 encodeURIComponent 编码后再拼 url；接收端直接使用（微信自动解码一次），不要二次解码。

坑 5：接收端二次 decodeURIComponent 导致 JSON 解析失败
结论：JSON.parse(options.goods) 抛错，或数据中 % 字符被破坏。
原因：微信对 url 参数已自动解码一次，开发者又手动 decode 一次，JSON 字符串里的 % 等字符被二次转义。
解法：只编码一次、只解码一次——发送端 encodeURIComponent，接收端直接 JSON.parse，禁止再调 decodeURIComponent。

坑 6：navigateBack 返回后页面数据是旧的
结论：从详情页返回列表页，列表还是旧数据，新增/修改的内容看不到。
原因：返回的页面不会重新触发 onLoad，只触发 onShow；刷新逻辑写在 onLoad 里永远不执行。
解法：需要刷新的逻辑移到 onShow；或用 eventChannel 在返回前通知上一页刷新。

坑 7：getCurrentPages 跨页 setData 不生效
结论：用 pages[pages.length-2].setData 改上一页数据，返回后发现页面没变化。
原因：隐藏页面（onHide 状态）setData 不触发渲染，数据改了视图不更新，属于误用页面栈。
解法：返回刷新用 onShow 或调用上一页暴露的方法（prev.refreshList()）；数据共享用全局 store / storage。

坑 8：退出登录后按返回键回到已退出状态页面
结论：退出登录用 navigateBack 返回首页，用户按返回键又回到个人中心，还带着旧登录态 UI。
原因：退出登录没有清空页面栈，业务页面实例还留在栈中。
解法：退出登录、切换账号等状态变更统一 wx.reLaunch 清空页面栈；需要回跳的页面在 onShow 里校验登录态兜底。

坑 9：页面路径未注册或拼写错误，跳转无反应
结论：点击跳转毫无反应，控制台报页面路径错误或页面不存在。
原因：目标页没有在 app.json 的 pages 数组注册，或路径大小写/拼写与目录不一致。
解法：新建页面时确保 app.json pages 已注册（开发者工具新建页面会自动注册）；跳转路径用绝对路径 /pages/xxx/xxx 与注册路径保持一致。
```

## 概述

界面交互 API 是 wx 命名空间下与用户反馈、页面外观、滚动行为相关的 API 集合，包括消息提示（wx.showToast / wx.showModal / wx.showLoading / wx.showActionSheet）、导航栏与标签栏控制、页面滚动、下拉刷新、背景与文字样式设置等。这些 API 是小程序「操作 → 反馈」闭环的核心：任何网络请求、表单提交、增删改操作，都需要通过它们给用户明确的视觉反馈，体验好坏往往取决于提示是否及时、准确、不打扰。本文按「反馈弹窗 → 导航外观 → 滚动与刷新 → 背景样式」的顺序展开，所有代码示例均可在开发者工具中直接运行。

```text
界面交互 API 全景：
1. 消息提示 —— wx.showToast 轻提示 / wx.showModal 模态弹窗 / wx.showLoading 加载中 / wx.showActionSheet 操作菜单
2. 导航栏 —— wx.setNavigationBarTitle / wx.setNavigationBarColor 动态修改当前页导航栏
3. 标签栏 —— wx.setTabBarBadge / wx.removeTabBarBadge 角标，wx.showTabBar / wx.hideTabBar 显隐
4. 滚动 —— wx.pageScrollTo 页面滚动到指定位置（px）
5. 刷新 —— wx.startPullDownRefresh / wx.stopPullDownRefresh 配合页面 onPullDownRefresh
6. 背景 —— wx.setBackgroundColor / wx.setBackgroundTextStyle 下拉区域背景与 loading 样式
```

## 消息提示类 API

wx.showToast 是最常用的轻量提示，展示在屏幕中部，默认 1.5 秒后自动消失。它支持四种内置图标（success / error / loading / none），也支持通过 image 参数传入自定义图片（image 优先级高于 icon，设置 image 后 icon 失效）。title 在带 icon 时最多约 7 个汉字，超出会被截断；icon 为 none 时文字最多两行。mask 参数为 true 时会在 toast 下层显示透明蒙层，阻止用户触摸页面其他区域，适合「保存中、提交中」等需要防误触的场景。

```js
// pages/demo/toast.js
Page({
  // 基础成功提示
  showSuccess() {
    wx.showToast({
      title: '保存成功',
      icon: 'success',   // success / error / loading / none
      duration: 2000,    // 单位毫秒，默认 1500
      mask: true         // 显示蒙层，防止触摸穿透
    })
  },

  // 纯文字提示（无图标，适合不确定语义的提示）
  showText() {
    wx.showToast({
      title: '网络开小差了，请稍后重试',
      icon: 'none',
      duration: 2500
    })
  },

  // 自定义图标
  showCustomImage() {
    wx.showToast({
      title: '打卡成功',
      image: '/assets/images/checkin.png', // 自定义图片路径，优先级高于 icon
      duration: 2000
    })
  }
})
```

wx.showModal 是模态弹窗，常用于「确认 / 取消」型决策（删除确认、支付确认、协议确认）。通过 confirmText / cancelText 自定义按钮文字（最多 4 个字符），confirmColor / cancelColor 设置按钮颜色。success 回调返回 res.confirm 与 res.cancel 两个布尔值，业务逻辑必须同时考虑用户点击「取消」和点击遮罩层关闭两种情况。基础库 2.11.0 起支持 editable 参数，弹窗内直接提供输入框，输入内容通过 res.content 返回，可用来做「填写备注后确认」「输入邀请码」等轻量输入场景，省去跳转页面的成本。

```js
// pages/demo/modal.js
Page({
  // 确认删除弹窗
  confirmDelete() {
    wx.showModal({
      title: '删除确认',
      content: '删除后不可恢复，确定删除这条记录吗？',
      confirmText: '删除',
      cancelText: '再想想',
      confirmColor: '#e64340', // 删除类操作用红色警示
      cancelColor: '#999999',
      success: (res) => {
        if (res.confirm) {
          this.doDelete()       // 用户点了「删除」
        } else if (res.cancel) {
          console.log('用户取消删除')
        }
      }
    })
  },

  // 可输入弹窗（基础库 2.11.0+）
  inputRemark() {
    wx.showModal({
      title: '添加备注',
      editable: true,
      placeholderText: '请输入备注内容（选填）',
      success: (res) => {
        if (res.confirm) {
          console.log('用户输入的备注：', res.content)
        }
      }
    })
  },

  doDelete() {
    // 实际删除逻辑，成功后给 toast 反馈
    wx.showToast({ title: '已删除', icon: 'success' })
  }
})
```

```text
消息提示类 API 要点：
1. showToast 的 title 带 icon 时最多约 7 个汉字，超长会被截断，长文案用 icon: none 或 showModal
2. image 参数与 icon 互斥，设置 image 后 icon 不生效
3. duration 单位是毫秒，默认 1500，建议控制在 1500-3000 之间，过长会拖慢连续操作
4. mask: true 可以防止提示期间用户误触页面，提交类操作建议开启
5. showModal 的 success 回调同时有 confirm 与 cancel 两个字段，都要处理
6. showModal 支持 editable 输入，输入内容在 res.content 中，注意低版本基础库不支持
```

## 加载反馈与操作菜单

wx.showLoading 展示全屏 loading 态，配合 wx.hideLoading 成对使用，用于网络请求等异步任务期间。它的 title 支持换行（最多 6 个字内最佳），mask 参数同样可以阻止触摸穿透。**必须成对调用**：showLoading 之后如果不调用 hideLoading，loading 不会自动消失，会一直盖住页面，这是最常见的线上事故之一。另外 showLoading 与 showToast 互斥，loading 显示期间调用 showToast 会被忽略，必须先 hideLoading 再弹 toast。

```js
// pages/demo/loading.js
Page({
  data: { submitting: false },

  submitOrder() {
    if (this.data.submitting) return   // 防止重复提交
    this.setData({ submitting: true })

    wx.showLoading({
      title: '订单提交中',
      mask: true                        // 提交期间禁止触摸
    })

    wx.request({
      url: 'https://api.example.com/order/create',
      method: 'POST',
      timeout: 10000,
      success: (res) => {
        wx.hideLoading()                // 请求结束立即关闭 loading
        this.setData({ submitting: false })
        if (res.data.code === 0) {
          wx.showToast({ title: '下单成功', icon: 'success' })
        } else {
          wx.showModal({
            title: '下单失败',
            content: res.data.msg,
            showCancel: false           // 只有一个「确定」按钮的提示型弹窗
          })
        }
      },
      fail: () => {
        wx.hideLoading()
        this.setData({ submitting: false })
        wx.showToast({ title: '网络异常，请重试', icon: 'none' })
      }
    })
  }
})
```

wx.showActionSheet 从底部弹出操作菜单，itemList 传入按钮文字数组（最大 6 个），用户点击后 success 回调返回 tapIndex（从 0 开始的下标）。用户点击遮罩层或「取消」时进入 fail 回调，errMsg 包含 "cancel" 字样，需要在 fail 中判断并静默处理，不要弹错误提示。典型用途：选择图片来源（拍照/相册）、选择分享渠道、长按列表项后的操作菜单。

```js
// pages/demo/actionsheet.js
Page({
  // 选择图片来源
  chooseSource() {
    wx.showActionSheet({
      itemList: ['拍照', '从手机相册选择'],
      itemColor: '#576b95',
      success: (res) => {
        switch (res.tapIndex) {
          case 0:
            this.pickImage('camera')
            break
          case 1:
            this.pickImage('album')
            break
        }
      },
      fail: (res) => {
        // 用户取消时 errMsg 为 showActionSheet:fail cancel，这里静默处理
        if (!res.errMsg.includes('cancel')) {
          console.error('ActionSheet 异常：', res.errMsg)
        }
      }
    })
  },

  pickImage(sourceType) {
    wx.chooseMedia({
      count: 1,
      mediaType: ['image'],
      sourceType: [sourceType],
      success: (res) => {
        console.log('选择的图片：', res.tempFiles[0].tempFilePath)
      }
    })
  }
})
```

```text
加载反馈与操作菜单要点：
1. showLoading 必须与 hideLoading 成对调用，否则 loading 永不消失
2. showLoading 与 showToast 互斥，先 hideLoading 再弹 toast
3. 多请求并发时用计数器管理 hideLoading，全部完成才关闭
4. showActionSheet 的 itemList 最多 6 项，超长会直接 fail
5. ActionSheet 点击遮罩层取消会走 fail 回调，用 errMsg.includes('cancel') 判断
6. 菜单操作一般配合防重复提交的状态锁（submitting 标志）使用
```

## 导航栏与标签栏控制

wx.setNavigationBarTitle 动态修改当前页面导航栏标题，适合「标题随数据变化」的场景（如「订单详情-编号 10086」）；静态标题应直接写在页面 json 的 navigationBarTitleText 里，不要每次进页面都调用 API。wx.setNavigationBarColor 修改导航栏背景色与前景色，注意 frontColor 只支持 #ffffff 与 #000000 两个值，其他颜色不生效；animation 参数可以控制颜色切换的过渡动画。

```js
// pages/order/detail.js
Page({
  onLoad(options) {
    // 动态标题：订单详情 + 订单号
    wx.setNavigationBarTitle({
      title: '订单详情-' + (options.orderNo || '')
    })

    // 深色主题导航栏（白字 + 深色背景）
    wx.setNavigationBarColor({
      frontColor: '#ffffff',      // 仅支持 #ffffff 或 #000000
      backgroundColor: '#1f2937',
      animation: {
        duration: 400,
        timingFunc: 'easeIn'      // linear / easeIn / easeOut / easeInOut
      }
    })
  }
})
```

标签栏相关 API 围绕 tabBar 页面展开。wx.setTabBarBadge 给指定 tab 设置角标（index 为 tab 下标，text 最多 4 个字符），常用于「待付款 3 单」「消息 12 条」这类未读计数；计数归零后用 wx.removeTabBarBadge 移除角标。wx.showTabBar / wx.hideTabBar 控制整个标签栏的显隐，可带 animation 动画，一般用于全屏场景（阅读、播放视频）临时隐藏。注意这些 API 只能在 tabBar 页面调用，非 tabBar 页面调用会报 "not TabBar page"。

```js
// pages/cart/cart.js —— 购物车 tab 页
Page({
  onShow() {
    // 每次回到页面刷新角标
    this.refreshBadge()
  },

  refreshBadge() {
    // 模拟从后台拉取购物车数量
    wx.request({
      url: 'https://api.example.com/cart/count',
      success: (res) => {
        const count = res.data.data || 0
        if (count > 0) {
          wx.setTabBarBadge({ index: 1, text: String(count > 99 ? '99+' : count) })
        } else {
          wx.removeTabBarBadge({ index: 1 })
        }
      }
    })
  },

  // 进入沉浸式浏览，隐藏标签栏
  enterFullscreen() {
    wx.hideTabBar({ animation: true })
  },

  exitFullscreen() {
    wx.showTabBar({ animation: true })
  }
})
```

```text
导航栏与标签栏控制要点：
1. 静态标题写页面 json 的 navigationBarTitleText，动态标题才用 setNavigationBarTitle
2. setNavigationBarColor 的 frontColor 只支持 #ffffff / #000000 两值
3. setTabBarBadge 的 text 最多 4 个字符，超长显示异常
4. 角标 API 只能在 tabBar 页面调用，非 tabBar 页面会报错
5. 角标数量建议在 onShow 中刷新（页面每次可见都拉最新数据）
6. hideTabBar 隐藏后用户无法切换 tab，仅限全屏类场景使用
```

## 页面滚动与下拉刷新

wx.pageScrollTo 把页面滚动到指定位置，scrollTop 单位为 px（不是 rpx），duration 控制动画时长（默认 300ms）。最常用的是「回到顶部」：scrollTop 传 0。基础库 2.7.3 起支持 selector 参数，直接传入 CSS 选择器滚动到指定元素位置，与 scrollTop 二选一。注意滚动动画在不同机型上表现有差异，iOS 上过大的 duration 可能导致动画失效直接跳转，建议真机验证。

```js
// pages/list/list.js
Page({
  // 回到顶部按钮
  scrollToTop() {
    wx.pageScrollTo({
      scrollTop: 0,
      duration: 300
    })
  },

  // 滚动到指定元素（基础库 2.7.3+）
  scrollToComment() {
    wx.pageScrollTo({
      selector: '#comment-section',
      duration: 300
    })
  }
})
```

下拉刷新是小程序列表页的标配能力，由「页面 json 开启 + 页面生命周期回调 + 关闭动画 API」三部分组成：页面 json 中设置 enablePullDownRefresh: true 开启下拉手势，设置 backgroundTextStyle: dark（loading 三个点为深色，浅色背景页必配）；Page 中实现 onPullDownRefresh 回调拉取最新数据；数据回来后调用 wx.stopPullDownRefresh() 收起刷新动画。代码里也可以主动调用 wx.startPullDownRefresh() 触发一次下拉刷新（会触发 onPullDownRefresh 回调），适合「进入页面自动刷新」的场景。

```json
// pages/list/list.json —— 开启下拉刷新
{
  "enablePullDownRefresh": true,
  "backgroundTextStyle": "dark",
  "backgroundColor": "#f5f6fa"
}
```

```js
// pages/list/list.js
Page({
  data: {
    list: [],
    page: 1,
    loading: false
  },

  onPullDownRefresh() {
    // 下拉刷新：重置分页拉第一页
    this.fetchList(1, () => {
      wx.stopPullDownRefresh()   // 数据回来后收起刷新动画
    })
  },

  onReachBottom() {
    // 触底加载下一页（与下拉刷新配套的常见组合）
    if (!this.data.loading) {
      this.fetchList(this.data.page + 1)
    }
  },

  fetchList(page, done) {
    this.setData({ loading: true })
    wx.request({
      url: 'https://api.example.com/goods/list?page=' + page,
      success: (res) => {
        const items = res.data.data.list
        this.setData({
          list: page === 1 ? items : this.data.list.concat(items),
          page: page
        })
      },
      complete: () => {
        this.setData({ loading: false })
        if (done) done()
      }
    })
  },

  // 代码主动触发下拉刷新（如进入页面自动刷新）
  onShow() {
    if (this.data.firstShow) {
      wx.startPullDownRefresh()
    } else {
      this.setData({ firstShow: true })
    }
  }
})
```

```text
页面滚动与下拉刷新要点：
1. pageScrollTo 的 scrollTop 是 px 不是 rpx，duration 默认 300ms
2. selector 与 scrollTop 二选一，同时传以 selector 为准
3. 下拉刷新三件套：json 开 enablePullDownRefresh + onPullDownRefresh 回调 + stopPullDownRefresh 收尾
4. backgroundTextStyle 只支持 dark / light，控制下拉 loading 点颜色，浅色背景必须配 dark
5. startPullDownRefresh 会触发 onPullDownRefresh，注意与 stopPullDownRefresh 配对
6. scroll-view 组件内的滚动不触发页面的 onPullDownRefresh，两者机制不同
```

## 页面背景与文字样式

wx.setBackgroundColor 与 wx.setBackgroundTextStyle 动态设置窗口背景色与下拉区域的文字/loading 样式。需要说明的是，这两个 API 控制的不是页面内容区背景（内容区背景用 WXSS 的 page 选择器设置），而是「下拉露出区域」与下拉 loading 指示器的样式：比如用户下拉超过一屏时露出的背景颜色，以及下拉刷新三个点的颜色深浅。它们在深色主题切换、运营活动换肤时使用。

```js
// pages/theme/theme.js
Page({
  // 切换深色下拉背景
  applyDarkPullStyle() {
    wx.setBackgroundColor({
      backgroundColor: '#1f2937'   // 下拉露出区域的背景色
    })
    wx.setBackgroundTextStyle({
      textStyle: 'light'           // dark / light，配合深色背景用 light
    })
  },

  // 切回浅色
  applyLightPullStyle() {
    wx.setBackgroundColor({
      backgroundColor: '#f5f6fa'
    })
    wx.setBackgroundTextStyle({
      textStyle: 'dark'
    })
  }
})
```

```text
页面背景与文字样式要点：
1. setBackgroundColor 影响下拉露出区域，不是页面内容背景
2. setBackgroundTextStyle 只支持 dark / light 两个值
3. 深色下拉背景配 textStyle: light，浅色背景配 dark
4. 页面内容背景用 WXSS 的 page 选择器，不要用这个 API 代替
5. 这两个 API 更适合在主题切换、活动换肤等动态场景使用，静态样式优先 json 配置
6. 暗黑模式适配可参考本库 04.5-暗黑模式与主题适配 篇章
```

## 应用场景实战

### 场景一：意见反馈提交页的完整反馈闭环

一个典型的表单提交页，串联 showActionSheet（选择反馈类型）、showLoading（提交中）、showToast（成功）、showModal（失败详情）四个 API，并处理防重复提交。

```js
// pages/feedback/feedback.js
Page({
  data: {
    types: ['功能异常', '体验建议', '内容举报'],
    typeIndex: -1,
    content: ''
  },

  // 点击反馈类型，弹出选择菜单
  chooseType() {
    wx.showActionSheet({
      itemList: this.data.types,
      success: (res) => {
        this.setData({ typeIndex: res.tapIndex })
      }
    })
  },

  onContentInput(e) {
    this.setData({ content: e.detail.value })
  },

  submit() {
    const { typeIndex, content } = this.data
    if (typeIndex < 0) {
      wx.showToast({ title: '请选择反馈类型', icon: 'none' })
      return
    }
    if (!content.trim()) {
      wx.showToast({ title: '请填写反馈内容', icon: 'none' })
      return
    }

    wx.showLoading({ title: '提交中', mask: true })
    wx.request({
      url: 'https://api.example.com/feedback/submit',
      method: 'POST',
      data: { type: this.data.types[typeIndex], content },
      timeout: 15000,
      success: (res) => {
        wx.hideLoading()
        if (res.data.code === 0) {
          wx.showToast({ title: '提交成功', icon: 'success', duration: 2000 })
          // toast 显示期间延迟返回上一页，让用户看到成功提示
          setTimeout(() => wx.navigateBack(), 1800)
        } else {
          wx.showModal({
            title: '提交失败',
            content: res.data.msg || '请稍后重试',
            showCancel: false
          })
        }
      },
      fail: () => {
        wx.hideLoading()
        wx.showModal({
          title: '网络异常',
          content: '请检查网络后重试',
          showCancel: false
        })
      }
    })
  }
})
```

### 场景二：订单列表页的下拉刷新与角标联动

订单列表是 tabBar 页面，需求：下拉刷新订单列表、待付款数量显示在标签栏角标、列表顶部提供「回到顶部」按钮。

```json
// pages/order/order.json
{
  "enablePullDownRefresh": true,
  "backgroundTextStyle": "dark",
  "navigationBarTitleText": "我的订单"
}
```

```js
// pages/order/order.js
Page({
  data: {
    orders: [],
    page: 1,
    hasMore: true,
    showTopBtn: false
  },

  onShow() {
    this.refreshOrderBadge()
  },

  onPullDownRefresh() {
    this.fetchOrders(1, () => wx.stopPullDownRefresh())
  },

  onReachBottom() {
    if (this.data.hasMore) {
      this.fetchOrders(this.data.page + 1)
    }
  },

  fetchOrders(page, done) {
    wx.request({
      url: 'https://api.example.com/order/list?page=' + page,
      success: (res) => {
        const data = res.data.data
        this.setData({
          orders: page === 1 ? data.list : this.data.orders.concat(data.list),
          page,
          hasMore: data.hasMore
        })
        // 拉取到数据后同步角标（待付款数）
        this.refreshOrderBadge()
      },
      complete: () => { if (done) done() }
    })
  },

  refreshOrderBadge() {
    wx.request({
      url: 'https://api.example.com/order/unpaid-count',
      success: (res) => {
        const count = res.data.data || 0
        if (count > 0) {
          wx.setTabBarBadge({ index: 1, text: String(count > 99 ? '99+' : count) })
        } else {
          wx.removeTabBarBadge({ index: 1 })
        }
      }
    })
  },

  // 监听页面滚动，出现「回到顶部」按钮
  onPageScroll(e) {
    this.setData({ showTopBtn: e.scrollTop > 600 })
  },

  scrollToTop() {
    wx.pageScrollTo({ scrollTop: 0, duration: 300 })
  }
})
```

## 最佳实践与踩坑记录

### 最佳实践

1. 封装统一的 feedback 工具模块（showSuccess / showError / showConfirm / showLoading），全项目复用同一套提示规范，避免每个页面写法漂移
2. toast 语义化：成功用 icon: success，失败用 icon: none 或 error，纯提示用 none，不要所有场景都套 success 图标
3. loading 与请求生命周期严格配对：请求 complete/fail 中必然 hideLoading，并用计数器处理并发请求（全部完成才关闭）
4. 所有提交类按钮加「状态锁 + mask」双保险，防止用户双击重复提交订单
5. 静态 UI 文案优先走 json 配置（navigationBarTitleText、backgroundColor），API 只用于真正需要动态变化的场景
6. 角标类数据在 onShow 中刷新而不是 onLoad，保证每次回到页面都是最新值
7. 下拉刷新与触底加载共用同一个 fetch 函数，通过 page 参数区分，避免两套逻辑不一致
8. 按钮文案遵循平台规范：删除类操作 confirmText 用「删除」+ 红色 confirmColor，普通确认用「确定」

### 踩坑记录

坑 1：showToast 标题过长被截断显示不全
结论：带 icon 的 toast 标题超过约 7 个汉字会被截断，用户看到「保存成…」这样的残缺文案。
原因：toast 单行区域宽度有限，icon 占据部分空间，超长文本被容器裁剪。
解法：短文案（≤7 字）用带 icon 的 toast；长文案用 icon: none（支持两行）或改用 showModal 承载完整信息。

坑 2：showLoading 之后直接 showToast 不生效
结论：loading 显示期间调用 wx.showToast 被忽略，页面没有任何提示，用户以为点击没反应。
原因：showLoading 与 showToast 在界面层互斥，同一时刻只能显示一种。
解法：先 wx.hideLoading() 再 showToast；部分旧基础库版本 hideLoading 后立即 showToast 仍会被吞，可加 50-100ms 的 setTimeout 间隔。

坑 3：showLoading 忘记 hideLoading 导致页面永久被蒙层盖住
结论：线上出现页面一直转圈、无法点击的「卡死」事故，定位发现是某个请求异常分支漏掉了 hideLoading。
原因：showLoading 不会自动消失，任何提前 return / 异常分支都会导致成对调用被破坏。
解法：把 hideLoading 放进请求的 complete 回调（无论成败都执行）；业务代码中所有 return 分支逐一检查。

坑 4：showModal 的 editable 输入内容拿不到
结论：基础库低于 2.11.0 的机型上 res.content 为空，备注内容丢失。
原因：editable 参数是 2.11.0 才支持的能力，低版本基础库直接忽略该参数。
解法：调用前用 wx.canIUse('showModal.object.editable') 做能力检测，不支持时降级为跳转独立输入页面。

坑 5：showActionSheet 的 itemList 超过 6 项直接 fail
结论：菜单只弹出部分选项或直接失败，线上反馈「选择按钮消失」。
原因：官方限制 itemList 最大 6 项，超过后 API 直接报错进入 fail 回调。
解法：超过 6 个选项时拆分菜单或改为列表页承载；fail 回调中用 errMsg.includes('cancel') 区分「用户取消」与「真实异常」。

坑 6：setNavigationBarColor 的 frontColor 传了其他颜色不生效
结论：导航栏文字颜色没有变成期望的蓝色/绿色，仍然只有黑白两态。
原因：官方规定 frontColor 仅支持 #ffffff 与 #000000，其余色值静默忽略。
解法：想用品牌色做导航栏时，把 backgroundColor 设成品牌色、frontColor 保持黑白即可；不要试图传任意色值。

坑 7：setTabBarBadge 在非 tabBar 页面调用报错
结论：普通页面调用 wx.setTabBarBadge 控制台报 "setTabBarBadge:fail not TabBar page"。
原因：标签栏角标 API 只对 tabBar 配置的页面生效。
解法：在 app.js 或工具函数中先判断当前页面是否为 tabBar 页面（对比 getCurrentPages 栈顶路径与 app.json 的 tabBar.list 路径），非 tabBar 页面不调用。

坑 8：下拉刷新开启后 onPullDownRefresh 不触发
结论：页面 json 配了 enablePullDownRefresh，但下拉没有刷新动画、回调也不执行。
原因：常见两种：一是 enablePullDownRefresh 写错位置（应写在页面 json 而不是 app.json）；二是页面用了 scroll-view 包裹内容，滚动发生在 scroll-view 内部而非页面级滚动。
解法：确认配置写在页面 json 顶层；列表页用页面级滚动（view + wx:for）而不是 scroll-view，除非需要固定表头等特殊布局。

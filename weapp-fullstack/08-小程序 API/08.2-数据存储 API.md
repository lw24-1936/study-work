## 概述

数据存储 API 是 wx 命名空间中与网络请求并列的高频 API 组，提供键值对的本地缓存能力：wx.setStorage 写入、wx.getStorage 读取、wx.removeStorage 删除、wx.clearStorage 清空，以及对应的同步版本 setStorageSync/getStorageSync/removeStorageSync/clearStorageSync。小程序本地缓存用于保存登录态、用户信息、列表数据、页面状态等，配合过期时间与版本号设计，可以在启动速度和用户体验上获得显著收益。

```text
数据存储 API 的核心内容：
1. 基础 API —— setStorage / getStorage / removeStorage / clearStorage 及同步版本
2. 同步与异步 —— 同步版阻塞线程适合小数据，异步版适合大数据与频繁读写
3. 存储限制 —— 单个 key 上限 1MB，总存储上限 10MB，超限写入失败
4. 数据类型 —— Object/Array 自动序列化，存储与读取类型保持一致
5. 缓存策略 —— 登录态、列表、配置的缓存方案，过期时间与缓存版本设计
6. 存储安全 —— 本地缓存明文可读，敏感信息不得入缓存
```

## 存储 API 基础用法

本地缓存是键值对（key-value）存储，key 为字符串，value 支持字符串、数字、布尔值、Object、Array 等类型。异步版本 wx.setStorage/getStorage 通过 success/fail 回调获取结果；写入大对象或频繁读写时优先用异步版本，避免阻塞逻辑层线程。读取一个不存在的 key 时，异步 getStorage 的 res.data 与同步 getStorageSync 都返回空字符串，需要用 `data !== ''` 判断存在性，而不是直接 if (data)。

```js
// 异步写入与读取
wx.setStorage({
  key: 'userInfo',
  data: { nickname: '张三', avatar: 'https://...', level: 5 },
  success() {
    console.log('写入成功');
  },
  fail(err) {
    console.error('写入失败', err);
  }
});

wx.getStorage({
  key: 'userInfo',
  success(res) {
    // res.data 为完整对象，自动反序列化
    console.log(res.data.nickname);
  },
  fail(err) {
    console.error('读取失败', err);
  }
});
```

```js
// 删除与清空
wx.removeStorage({
  key: 'userInfo',
  success() {
    console.log('删除成功');
  }
});

wx.clearStorage({
  success() {
    console.log('已清空全部缓存');
  }
});
```

```js
// 查看存储使用情况
wx.getStorageInfo({
  success(res) {
    console.log('当前 key 列表', res.keys);
    console.log('当前占用空间(KB)', res.currentSize);
    console.log('限制空间(KB)', res.limitSize);
  }
});
```

```text
存储 API 基础要点：
1. 键值对 —— key 为字符串，value 支持原生类型、Object、Array
2. 异步回调 —— setStorage/getStorage 通过 success/fail 获取结果
3. 不存在返回空字符串 —— getStorage 读取不存在的 key 返回 ''，用 !== '' 判断
4. 存储信息 —— getStorageInfo 可查看 keys、currentSize、limitSize
5. 自动序列化 —— Object 存储时自动 JSON 序列化，读取时自动反序列化
6. 持久化 —— 缓存常驻本地，杀掉小程序进程不丢失，清微信缓存/卸载才清除
```

## 同步与异步 API

同步版本 API（setStorageSync、getStorageSync、removeStorageSync、clearStorageSync、getStorageInfoSync）执行时阻塞逻辑层 JS 线程，代码更简洁但吞吐量低；异步版本不阻塞线程，通过回调返回结果。判断依据是数据大小与调用频率：登录态、页面配置这类小数据、低频读写用同步版完全没问题；接口返回的大列表、频繁写入的埋点数据应使用异步版。同步 API 在写入失败时会抛出异常，需要用 try/catch 包裹。

```js
// 同步写入与读取 —— 适合小数据、低频操作
try {
  wx.setStorageSync('token', 'eyJhbGciOi...');
  const token = wx.getStorageSync('token');
  console.log(token);
} catch (e) {
  // 存储失败（如空间不足）会抛异常
  console.error('存储异常', e);
}
```

```js
// 同步删除与清空
wx.removeStorageSync('token');
wx.clearStorageSync();

// 同步查看存储信息
const info = wx.getStorageInfoSync();
console.log(info.keys, info.currentSize, info.limitSize);
```

```js
// 异步写入大列表 —— 不阻塞线程
const bigList = Array.from({ length: 5000 }, (_, i) => ({ id: i, name: `商品${i}` }));
wx.setStorage({
  key: 'goodsCache',
  data: bigList,
  success() {
    console.log('大列表缓存完成');
  }
});
```

```text
同步与异步 API 要点：
1. 同步版 —— setStorageSync/getStorageSync 等，代码直观，阻塞逻辑层线程
2. 异步版 —— 回调返回结果，不阻塞线程，适合大对象与频繁读写
3. 异常处理 —— 同步 API 写入失败抛异常，必须 try/catch
4. 选型 —— 小数据低频用同步，大数据高频用异步
5. 混用注意 —— 同一 key 同步写异步读没问题，但要避免并发写同一 key 互相覆盖
6. 初始化 —— 页面 onLoad 里同步读小配置最快，异步读大列表避免白屏卡顿
```

## 存储限制与数据类型

官方对本地缓存有明确限制：单个 key 允许存储的最大数据长度为 1MB，整个小程序的存储上限为 10MB（不同平台与基础库版本可能有差异）。超过限制的 setStorage/setStorageSync 会失败（异步走 fail，同步抛异常）。value 支持 String、Number、Boolean、Object、Array，Object 与 Array 会被自动 JSON 序列化存储；需要注意的是 Date 等特殊对象会被序列化成字符串，存进去再取出来类型就变了。

```js
// 检查容量并做兜底：写入前估算体积，超限时清理旧缓存
function safeSetStorage(key, data) {
  try {
    wx.setStorageSync(key, data);
    return true;
  } catch (e) {
    // 空间不足：先清理最旧的缓存，再重试一次
    clearOldestCache();
    try {
      wx.setStorageSync(key, data);
      return true;
    } catch (e2) {
      console.error('存储失败', e2);
      return false;
    }
  }
}

// 清理策略示例：删除所有带 cache 前缀且过期的 key
function clearOldestCache() {
  const info = wx.getStorageInfoSync();
  info.keys.forEach((key) => {
    if (key.indexOf('cache:') === 0) {
      wx.removeStorageSync(key);
    }
  });
}
```

```js
// 类型陷阱：Date 对象会被序列化为字符串
const birthday = new Date('2000-01-01');
wx.setStorageSync('birthday', birthday);
const read = wx.getStorageSync('birthday');
console.log(typeof read, read);   // string "2000-01-01T00:00:00.000Z"，不是 Date 对象
```

```text
存储限制与类型要点：
1. 单 key 上限 —— 单个 key 最大 1MB，超限写入失败
2. 总量上限 —— 整个小程序本地缓存上限 10MB
3. 支持类型 —— String/Number/Boolean/Object/Array，Object 自动 JSON 序列化
4. 类型陷阱 —— Date 等特殊对象会被序列化成字符串，类型丢失
5. 容量管理 —— 定期清理过期缓存，写入前做体积评估
6. 失败兜底 —— 写入失败要有降级策略（清理旧缓存重试或提示用户）
```

## 数据缓存策略

缓存的核心价值是用空间换速度：二次进入页面时先渲染缓存数据，再异步拉取最新数据覆盖，用户感知的加载速度大幅提升。典型缓存对象包括登录态（token、userInfo）、列表数据（商品、订单、消息）、配置数据（公告、开关、版本说明）。缓存必须设计过期时间：写入时记录 expiresAt 时间戳，读取时比较，过期即删除并返回空。缓存结构变更时用版本号控制：缓存版本升级则整体清空，避免旧结构与新代码不兼容。

```js
// utils/storage.js —— 带过期时间的缓存封装（项目标准做法）
const PREFIX = 'app:';

// ttlSeconds 传 0 表示永不过期
function set(key, value, ttlSeconds) {
  const payload = {
    value,
    expiresAt: ttlSeconds ? Date.now() + ttlSeconds * 1000 : 0
  };
  wx.setStorageSync(PREFIX + key, payload);
}

function get(key) {
  const raw = wx.getStorageSync(PREFIX + key);
  if (!raw) return null;
  if (raw.expiresAt && raw.expiresAt < Date.now()) {
    wx.removeStorageSync(PREFIX + key);
    return null;
  }
  return raw.value;
}

function remove(key) {
  wx.removeStorageSync(PREFIX + key);
}

// 按前缀批量清理（账号切换、退出登录时用）
function clearByPrefix(prefix) {
  const info = wx.getStorageInfoSync();
  info.keys.forEach((key) => {
    if (key.indexOf(PREFIX + prefix) === 0) {
      wx.removeStorageSync(key);
    }
  });
}

module.exports = { set, get, remove, clearByPrefix };
```

```js
// 缓存版本控制 —— 结构升级时整体失效
const CACHE_VERSION = 3;

function checkCacheVersion() {
  const current = wx.getStorageSync('cache_version');
  if (current !== CACHE_VERSION) {
    wx.clearStorageSync();
    wx.setStorageSync('cache_version', CACHE_VERSION);
  }
}

// app.js onLaunch 中调用
checkCacheVersion();
```

```js
// 登录态缓存：token + userInfo + 过期时间
function saveLoginState(data) {
  wx.setStorageSync('token', data.token);
  wx.setStorageSync('userInfo', data.userInfo);
  wx.setStorageSync('login_expires', Date.now() + 7 * 24 * 3600 * 1000); // 7 天
}

function isLoginValid() {
  const token = wx.getStorageSync('token');
  const expires = wx.getStorageSync('login_expires');
  return !!token && expires > Date.now();
}

// 退出登录：清用户相关缓存
function logout() {
  wx.removeStorageSync('token');
  wx.removeStorageSync('userInfo');
  wx.removeStorageSync('login_expires');
  // 清理该用户专属的业务缓存（购物车、草稿等）
  clearByPrefix('user:');
}
```

```js
// 列表缓存：先渲染缓存再刷新
Page({
  data: { list: [] },
  onLoad() {
    // 1. 先读缓存立即渲染
    const cached = storage.get('list:goods:page1', 300); // 5 分钟有效
    if (cached) {
      this.setData({ list: cached });
    }
    // 2. 再异步拉最新数据覆盖
    this.refresh();
  },
  async refresh() {
    const res = await api.get('/api/goods/list', { page: 1 });
    storage.set('list:goods:page1', res.list, 300);
    this.setData({ list: res.list });
  }
});
```

```text
缓存策略要点：
1. 缓存对象 —— 登录态、列表、配置三类高频缓存，按业务拆分 key
2. 过期时间 —— 写入 expiresAt 时间戳，读取时比较，过期即删
3. 缓存版本 —— cache_version 字段控制，结构升级整体清空
4. key 命名 —— 「模块:业务:标识」三段式，如 app:list:goods:page1
5. 先缓存后网络 —— 二次进入先渲染缓存再刷新，提升感知速度
6. 账号隔离 —— 用户维度缓存加 user:id 前缀，退出/切换账号时按前缀清理
```

## 存储安全

本地缓存是明文存储的，虽然小程序沙箱比浏览器更封闭，但数据仍可能通过 root 设备、逆向工具、开发者工具被读取。因此密码、支付密钥、身份证号、完整手机号等敏感信息严禁写入本地缓存；token 可以存缓存（这是行业通行做法），但要遵循短时效原则：token 有效期短（如 7 天）、过期可刷新、服务端可吊销，即使泄露影响也可控。真正的敏感数据必须只存在于服务端，小程序端只展示不落盘。

```js
// 错误示范：敏感信息明文入缓存
wx.setStorageSync('password', '123456');
wx.setStorageSync('payKey', 'sk_live_xxx');
wx.setStorageSync('idCard', '110101199001011234');

// 正确做法：只存低敏展示数据与短时效 token
wx.setStorageSync('token', 'eyJhbGciOi...');              // 短时效、可吊销
wx.setStorageSync('userInfo', { nickname: '张三' });       // 脱敏后的展示数据
// 敏感字段（手机号完整号、身份证）只从服务端接口按需获取，用后即弃
```

```js
// token 泄露的止损设计：服务端可吊销 + 本地及时清理
function onSecurityAlert() {
  // 后台检测到异常后下发强制下线指令
  wx.removeStorageSync('token');
  wx.removeStorageSync('userInfo');
  wx.showToast({ title: '账号安全提醒，请重新登录', icon: 'none' });
  wx.reLaunch({ url: '/pages/login/login' });
}
```

```text
存储安全要点：
1. 明文存储 —— 本地缓存可被读取，不是加密存储
2. 禁存清单 —— 密码、支付密钥、身份证号、完整手机号等敏感信息不得入缓存
3. token 例外 —— token 可存缓存，但短时效 + 服务端可吊销
4. 脱敏展示 —— 缓存里只放展示所需的最小字段
5. 强制下线 —— 服务端检测异常时可下发指令清理本地登录态
6. 真敏感数据 —— 只存在于服务端数据库，接口按需返回，前端用后即弃
```

## 应用场景实战

### 场景一：商品列表缓存 + 先渲染后刷新

电商首页场景：第一次进入拉取接口并缓存 5 分钟，二次进入先渲染缓存再后台刷新，弱网下即使接口失败也能展示旧数据：

```js
// utils/storage.js —— 带过期时间的缓存封装（见上文，此处引用）
const storage = require('../../utils/storage.js');
const api = require('../../utils/request.js');

Page({
  data: {
    list: [],
    fromCache: false,   // 标记当前数据来源，用于展示提示
    loading: false
  },
  onLoad() {
    this.renderCache();
    this.fetchList();
  },
  onPullDownRefresh() {
    this.fetchList(() => wx.stopPullDownRefresh());
  },
  // 1. 缓存优先：5 分钟内直接展示缓存
  renderCache() {
    const cached = storage.get('list:home', 300);
    if (cached && cached.length) {
      this.setData({ list: cached, fromCache: true });
    }
  },
  // 2. 网络刷新：成功后覆盖缓存与页面
  async fetchList(done) {
    if (this.data.loading) return;
    this.setData({ loading: true });
    try {
      const res = await api.get('/api/goods/home', { size: 20 });
      storage.set('list:home', res.list, 300);
      this.setData({ list: res.list, fromCache: false });
    } catch (e) {
      // 网络失败时保留缓存数据，弱网下用户仍有内容可看
      if (!this.data.list.length) {
        wx.showToast({ title: '加载失败，请检查网络', icon: 'none' });
      }
    } finally {
      this.setData({ loading: false });
      if (done) done();
    }
  }
});
```

```text
场景一关键步骤：
1. 缓存 key 带命名空间：app:list:home
2. 读取时校验过期时间，过期自动失效
3. 先渲染缓存再发请求，页面秒开
4. 网络失败不破坏缓存数据，弱网可读旧数据
5. 下拉刷新强制走网络，成功后覆盖缓存
```

### 场景二：多账号切换的登录态与缓存隔离

一个设备多个账号的场景：登录、切换、退出时保证缓存不串号，用户 A 的购物车不会出现在用户 B 的页面上：

```js
// utils/account.js —— 账号会话管理
const storage = require('./storage.js');

const CURRENT_USER_KEY = 'session:current';
const USER_PREFIX = 'user:';

function saveSession(user) {
  // 用户维度数据带 userId 前缀，与账号隔离
  wx.setStorageSync(CURRENT_USER_KEY, user.id);
  storage.set(`${USER_PREFIX}${user.id}:info`, user, 0);
  wx.setStorageSync('token', user.token);
}

function switchAccount(userId) {
  // 切换账号：清掉上一个账号的专属缓存，但保留全局配置缓存
  const currentId = wx.getStorageSync(CURRENT_USER_KEY);
  if (currentId && currentId !== userId) {
    storage.clearByPrefix(`${USER_PREFIX}${currentId}`);
  }
  saveSession({ id: userId, token: '' });
}

function logout() {
  const currentId = wx.getStorageSync(CURRENT_USER_KEY);
  if (currentId) {
    storage.clearByPrefix(`${USER_PREFIX}${currentId}`);
  }
  wx.removeStorageSync('token');
  wx.removeStorageSync(CURRENT_USER_KEY);
}

module.exports = { saveSession, switchAccount, logout };
```

```js
// 页面使用：购物车数据按当前账号读取
const account = require('../../utils/account.js');
const storage = require('../../utils/storage.js');

Page({
  onShow() {
    const userId = wx.getStorageSync('session:current');
    const cart = storage.get(`user:${userId}:cart`, 0);
    this.setData({ cart: cart || [] });
  }
});
```

```text
场景二关键步骤：
1. 当前账号 id 单独存储，作为缓存前缀的依据
2. 用户维度数据一律 user:{id}:xxx 命名，天然隔离
3. 切换账号清旧账号缓存，保留全局配置缓存
4. 退出登录清 token 与用户缓存，不留痕迹
5. 全局缓存（公告、配置）不带用户前缀，所有账号共享
```

## 最佳实践与踩坑记录

### 最佳实践

1. 统一封装 storage.js（带前缀、过期时间、版本号），页面禁止裸用 wx.setStorageSync
2. 写操作频繁或数据量大时用异步 API，避免阻塞逻辑层线程导致卡顿
3. 所有缓存必须设计过期时间与缓存版本，避免脏数据长期驻留
4. 缓存 key 用「模块:业务:标识」三段式命名并集中管理常量，杜绝魔法字符串
5. 敏感信息（密码、支付密钥、身份证）严禁入缓存，token 短时效且服务端可吊销
6. 退出登录与账号切换必须清理用户维度缓存，防止数据串号
7. 列表类缓存遵循「先渲染缓存、再异步刷新」策略，提升二次进入体验
8. 上线前梳理一遍缓存清单：哪些该缓存、有效期多久、版本升级怎么清，形成文档

### 踩坑记录

```text
坑 1：用 if (data) 判断缓存是否存在，存 0/false 时误判
结论：存了数字 0 或布尔 false，再读取时被当成「不存在」。
原因：getStorageSync 对不存在的 key 返回空字符串，而 0/false/'' 都是 falsy 值，if (data) 无法区分。
解法：用 data !== '' 判断存在性；或用封装层统一返回 null 表示不存在，与合法空值区分。

坑 2：同步 API 频繁读写导致页面卡顿
结论：列表页滚动卡顿、点击响应慢，定位到是 onShow 里同步读写大对象。
原因：setStorageSync/getStorageSync 阻塞逻辑层线程，大对象序列化耗时明显。
解法：大数据与高频读写改用异步 API；确实要同步的场景控制单次数据量。

坑 3：写入超过 1MB 的 key 静默失败
结论：接口返回的大列表缓存失败，页面二次进入还是走网络。
原因：单个 key 上限 1MB，超限写入被拒绝，异步版走 fail 没提示。
解法：写入前评估数据体积，超限拆分为多个 key（如按页拆分）或只缓存摘要字段；写入失败做兜底提示。

坑 4：缓存了 undefined 值，读取时行为异常
结论：把接口返回的某个 undefined 字段直接存了，读取时拿到异常数据。
原因：setStorageSync 的 data 为 undefined 时行为不确定（部分环境抛错，部分存 null）。
解法：写入前统一做默认值处理，undefined 转 null 或空字符串；封装层对 data 做合法性校验。

坑 5：过期缓存只判不删，存储越积越满
结论：明明写了过期时间，storage 总量还是不断增长，最终写满。
原因：读取时只做了过期判断返回 null，没有顺手 remove，过期数据永远留在缓存里。
解法：get 命中过期数据时立即 remove；定期（如每次启动）清理过期 key。

坑 6：账号切换后旧用户数据残留，出现串号
结论：用户 B 登录后看到用户 A 的购物车/浏览记录。
原因：缓存 key 没有按用户隔离，或切换账号时没有清理旧用户缓存。
解法：用户维度 key 统一 user:{id}:xxx 前缀；切换与退出时按前缀批量清理。

坑 7：开发者工具清缓存，真机却还有旧数据
结论：调试时在工具里 clearStorageSync 生效，真机上旧缓存还在，行为不一致。
原因：工具与真机的存储是独立环境，工具的操作不影响真机；真机需要走「清除缓存」或代码清理。
解法：真机调试前用代码触发清理（如缓存版本号升级自动清空）；版本发布时提高 CACHE_VERSION。

坑 8：把密码、手机号明文存进缓存
结论：应用被逆向后，用户密码、完整手机号在缓存中被直接读出。
原因：本地缓存明文存储，没有加密，逆向工具可直接读取 storage 内容。
解法：敏感字段一律不落缓存；必须展示时服务端按需返回并脱敏；token 短时效并支持服务端吊销。

坑 9：缓存 Date 对象，读取后类型变成字符串
结论：存了日期对象，读出来是字符串，日期计算全部出错。
原因：Object 自动 JSON 序列化，Date 被转成 ISO 字符串，类型信息丢失。
解法：日期统一存时间戳（Number），读取后 new Date(timestamp) 还原；或自定义序列化格式。
```

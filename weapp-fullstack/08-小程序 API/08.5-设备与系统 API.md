## 概述

设备与系统 API 是 wx 命名空间下与硬件环境、系统状态相关的 API 集合，包括系统信息（wx.getSystemInfoSync 系列）、网络状态（wx.getNetworkType / wx.onNetworkStatusChange）、剪贴板（wx.setClipboardData / wx.getClipboardData）、震动（wx.vibrateShort / wx.vibrateLong）、扫码（wx.scanCode）、电池（wx.getBatteryInfo）、位置（wx.getLocation / wx.chooseLocation）、蓝牙与 NFC 等。这类 API 直接暴露手机硬件与系统能力，是小程序区别于普通 H5 的典型优势，但也伴随着平台差异大、权限要求多、真机与模拟器行为不一致三大特点，开发时必须时刻以真机为准。本章按「信息读取 → 轻量交互 → 位置权限 → 硬件外设」的顺序展开。

```text
设备与系统 API 全景：
1. 系统信息 —— wx.getSystemInfoSync / wx.getWindowInfo / wx.getDeviceInfo / wx.getAppBaseInfo
2. 网络状态 —— wx.getNetworkType 查询 + wx.onNetworkStatusChange 监听切换
3. 剪贴板与震动 —— wx.setClipboardData / wx.getClipboardData / wx.vibrateShort / wx.vibrateLong
4. 扫码与电池 —— wx.scanCode 扫二维码/条形码/小程序码，wx.getBatteryInfo 查询电量
5. 位置 —— wx.getLocation 获取坐标 / wx.chooseLocation 打开地图选点，需 scope.userLocation 授权
6. 硬件外设 —— 蓝牙（openBluetoothAdapter 系列）与 NFC（wx.getNFCAdapter），仅部分机型支持
```

## 系统信息获取

wx.getSystemInfoSync 是历史最悠久的系统信息 API，一次返回设备型号、系统版本、屏幕尺寸、状态栏高度、安全区等全部信息，开发中大量用于「iPhone 刘海屏适配」「横竖屏适配」。但该 API 自基础库 2.20.1 起被官方标记为废弃，官方建议拆分使用 wx.getWindowInfo（窗口与屏幕）、wx.getDeviceInfo（设备硬件）、wx.getAppBaseInfo（应用与基础库）三个新 API。老代码可以继续运行，但新代码应直接使用新 API，并用 wx.canIUse 或基础库版本判断做兼容。

```js
// pages/device/info.js
Page({
  data: {
    info: {}
  },

  onLoad() {
    // 新 API：窗口信息（2.20.1+）
    const windowInfo = wx.getWindowInfo()
    // 新 API：设备硬件信息
    const deviceInfo = wx.getDeviceInfo()
    // 新 API：应用与基础库信息
    const appBaseInfo = wx.getAppBaseInfo()

    this.setData({
      info: {
        // 窗口信息
        windowWidth: windowInfo.windowWidth,
        windowHeight: windowInfo.windowHeight,
        pixelRatio: windowInfo.pixelRatio,
        statusBarHeight: windowInfo.statusBarHeight,   // 刘海屏适配核心
        safeArea: windowInfo.safeArea,
        // 设备信息
        brand: deviceInfo.brand,        // 品牌，如 Apple / HUAWEI
        model: deviceInfo.model,        // 型号，如 iPhone 14 Pro / Pixel 7
        system: deviceInfo.system,      // 系统版本，如 iOS 17.0 / Android 14
        platform: deviceInfo.platform,  // ios / android / devtools / windows / mac
        // 应用与基础库
        SDKVersion: appBaseInfo.SDKVersion,
        version: appBaseInfo.version,   // 微信版本号
        language: appBaseInfo.language,
        theme: appBaseInfo.theme        // light / dark
      }
    })

    // 平台判断：iOS 与安卓在布局、权限、API 行为上有差异
    const isIOS = deviceInfo.system.indexOf('iOS') === 0
    const isDevtools = deviceInfo.platform === 'devtools'
    console.log('iOS:', isIOS, '开发者工具:', isDevtools)
  }
})
```

```js
// 兼容写法：低版本基础库降级到 getSystemInfoSync
function getSystemInfoSafe() {
  if (wx.getWindowInfo && wx.getDeviceInfo && wx.getAppBaseInfo) {
    return {
      ...wx.getWindowInfo(),
      ...wx.getDeviceInfo(),
      ...wx.getAppBaseInfo()
    }
  }
  // 老基础库降级（2.20.1 之前）
  return wx.getSystemInfoSync()
}
```

```text
系统信息获取要点：
1. getSystemInfoSync 已废弃，新代码用 getWindowInfo + getDeviceInfo + getAppBaseInfo
2. statusBarHeight + safeArea 是刘海屏/挖孔屏适配的核心数据
3. windowWidth/windowHeight 是逻辑像素（px），随横竖屏变化，需监听 wx.onWindowResize
4. pixelRatio 用于图片清晰度选择：高清图 = 逻辑尺寸 × pixelRatio
5. platform 可区分 ios / android / devtools，system 以 "iOS" 前缀判断 iOS
6. 屏幕尺寸以 windowWidth 为准，不要用 screenWidth（screenWidth 是物理屏，横屏时不变）
```

## 网络状态与剪贴板

wx.getNetworkType 查询当前网络类型，返回值 networkType 可能是 wifi、2g、3g、4g、5g、unknown、none。它常用于「弱网提示」「大图降清晰度」「视频自动播放策略」等场景。wx.onNetworkStatusChange 监听网络状态变化，在网络切换（wifi 断开、4G 掉线、恢复连接）时触发回调，适合做「断网横幅提示 + 恢复后自动重试」。注意监听器要在页面 onUnload 中用 wx.offNetworkStatusChange 移除，否则会泄漏并造成重复触发。

```js
// pages/network/network.js
Page({
  data: {
    networkType: 'unknown',
    isConnected: true
  },

  onLoad() {
    this.checkNetwork()

    // 监听网络切换
    wx.onNetworkStatusChange((res) => {
      // res.isConnected 是否联网；res.networkType 当前网络类型
      this.setData({
        isConnected: res.isConnected,
        networkType: res.networkType
      })
      if (res.isConnected) {
        wx.showToast({ title: '网络已恢复', icon: 'none' })
      } else {
        wx.showToast({ title: '网络已断开', icon: 'none' })
      }
    })
  },

  onUnload() {
    // 必须移除监听，防止页面销毁后仍被回调
    wx.offNetworkStatusChange(this.onNetworkChange)
  },

  checkNetwork() {
    wx.getNetworkType({
      success: (res) => {
        this.setData({ networkType: res.networkType })
      }
    })
  },

  // 判断是否高速网络，用于决定是否加载高清图/自动播放视频
  isHighSpeed() {
    const type = this.data.networkType
    return type === 'wifi' || type === '4g' || type === '5g'
  }
})
```

剪贴板 API 用于复制/读取文本：wx.setClipboardData 写入剪贴板，wx.getClipboardData 读取剪贴板内容。典型场景是「复制订单号」「复制邀请码」「复制收货地址」。注意 wx.setClipboardData 成功后系统会自动弹出「内容已复制」的提示，开发者不要再额外调用 wx.showToast，否则会出现两个提示叠在一起。

```js
// pages/clipboard/clipboard.js
Page({
  data: {
    orderNo: '20260820000123'
  },

  // 复制订单号
  copyOrderNo() {
    wx.setClipboardData({
      data: this.data.orderNo,
      success: () => {
        // 注意：这里不要再 wx.showToast，系统会自动提示「内容已复制」
        console.log('复制成功')
      },
      fail: (err) => {
        console.error('复制失败', err)
      }
    })
  },

  // 读取剪贴板
  readClipboard() {
    wx.getClipboardData({
      success: (res) => {
        wx.showModal({
          title: '剪贴板内容',
          content: res.data || '（空）',
          showCancel: false
        })
      }
    })
  }
})
```

```text
网络状态与剪贴板要点：
1. getNetworkType 返回 wifi / 2g / 3g / 4g / 5g / unknown / none
2. onNetworkStatusChange 必须配套 offNetworkStatusChange 在 onUnload 移除
3. 开发者工具的网络类型恒为 wifi，弱网/5g 判断必须真机验证
4. setClipboardData 自带「内容已复制」系统提示，不要重复 showToast
5. 剪贴板读取要处理空内容与敏感信息（密码等不应写入剪贴板）
6. 部分安卓机型 5G 网络会被系统识别为 4g，判断高速网络时兜底处理
```

## 震动扫码与电池信息

wx.vibrateShort 短震动（约 15ms）与 wx.vibrateLong 长震动（约 400ms）用于强化操作反馈，比如扫码成功、抢到红包、摇一摇抽奖。vibrateShort 自基础库 2.13.0 起支持 type 参数（heavy / medium / light），控制震动强度，旧基础库忽略该参数。注意：开发者工具和模拟器没有震动效果，必须在真机验证；部分安卓机型上 vibrateLong 不生效，只能靠 vibrateShort 替代。

```js
// pages/vibrate/vibrate.js
Page({
  // 抽奖命中时的强反馈
  onWin() {
    wx.vibrateShort({ type: 'heavy' })   // heavy / medium / light
    // 配合其他反馈
    wx.showToast({ title: '中奖了', icon: 'success' })
  },

  // 普通点击反馈（轻震）
  onTap() {
    wx.vibrateShort({ type: 'light' })
  }
})
```

wx.scanCode 调起微信扫一扫，支持扫描二维码、条形码、小程序码等，success 回调返回 result（扫码内容）、scanType（barCode / qrCode / datamatrix / pdf417）、charSet（字符集）、path（扫到小程序码时返回对应的小程序页面路径）等字段。它是线下场景的入口神器：扫码登录、扫码核销、扫码进店、扫码绑定设备。注意：只有扫到小程序码时 res.path 才有值，普通二维码/条形码只有 result；scanType 参数可限定可扫的码类型。

```js
// pages/scan/scan.js
Page({
  // 扫码核销（优惠券/订单）
  scanAndVerify() {
    wx.scanCode({
      scanType: ['qrCode', 'barCode', 'datamatrix', 'pdf417'],
      success: (res) => {
        console.log('扫码内容：', res.result)
        console.log('码类型：', res.scanType)
        // 扫到小程序码时才有 path
        if (res.path) {
          console.log('小程序码路径：', res.path)
        }
        // 拿着结果去后台核销
        wx.request({
          url: 'https://api.example.com/coupon/verify',
          method: 'POST',
          data: { code: res.result, scanType: res.scanType },
          success: (resp) => {
            wx.showToast({
              title: resp.data.code === 0 ? '核销成功' : '核销失败',
              icon: resp.data.code === 0 ? 'success' : 'none'
            })
          }
        })
      },
      fail: (err) => {
        console.error('扫码失败：', err.errMsg)
      }
    })
  }
})
```

wx.getBatteryInfo 获取设备电量，返回 level（0-100）与 isCharging（是否充电中）。注意官方文档明确该 API 目前仅支持安卓系统，iOS 上调用会进入 fail 回调，使用时必须做平台判断与降级。电量信息可以用于「低电量省流模式」「大文件下载前提示」等场景。

```js
// pages/battery/battery.js
Page({
  onLoad() {
    const deviceInfo = wx.getDeviceInfo()
    if (deviceInfo.platform !== 'ios') {
      wx.getBatteryInfo({
        success: (res) => {
          console.log('电量：', res.level + '%', '充电中：', res.isCharging)
          if (res.level < 20 && !res.isCharging) {
            wx.showToast({ title: '电量不足 20%', icon: 'none' })
          }
        },
        fail: (err) => {
          console.warn('获取电量失败（部分机型不支持）：', err.errMsg)
        }
      })
    } else {
      // iOS 不支持，直接降级处理
      console.log('iOS 不支持 getBatteryInfo')
    }
  }
})
```

```text
震动扫码与电池信息要点：
1. vibrateShort 约 15ms，vibrateLong 约 400ms，type 参数需基础库 2.13.0+
2. 模拟器/开发者工具没有震动效果，必须真机验证
3. scanCode 的 result 是扫码内容，path 只有扫到小程序码才有值
4. scanType 参数可限定可扫类型，缩短识别时间
5. getBatteryInfo 仅支持安卓，iOS 调用会 fail，必须平台判断降级
6. 扫码/震动类反馈要克制，高频操作过度震动会被用户反感
```

## 位置能力

wx.getLocation 获取用户当前坐标，type 参数决定坐标系：wgs84（国际标准 GPS 坐标）或 gcj02（火星坐标系，国内地图与后台逆地址解析通用），国内业务基本都用 gcj02。isHighAccuracy + highAccuracyExpireTime 可开启高精度模式（耗电更高）。success 回调返回 latitude、longitude、accuracy（精度，米）、speed、altitude 等字段。**关键前置条件**：app.json 必须声明 requiredPrivateInfos: ["getLocation"]，并且需要用户授权 scope.userLocation，两者缺一不可，否则真机直接 fail。

```json
// app.json —— 位置接口必须在 requiredPrivateInfos 中声明
{
  "permission": {
    "scope.userLocation": {
      "desc": "用于展示您附近的商家与配送距离"
    }
  },
  "requiredPrivateInfos": ["getLocation", "chooseLocation"]
}
```

```js
// pages/location/location.js
Page({
  data: {
    latitude: 0,
    longitude: 0
  },

  onLoad() {
    this.checkLocationAuth()
  },

  // 检查位置授权
  checkLocationAuth() {
    wx.getSetting({
      success: (res) => {
        if (res.authSetting['scope.userLocation']) {
          this.getLocation()
        } else {
          // 申请授权
          wx.authorize({
            scope: 'scope.userLocation',
            success: () => this.getLocation(),
            fail: () => this.openSettingGuide()   // 拒绝后引导去设置页
          })
        }
      }
    })
  },

  getLocation() {
    wx.getLocation({
      type: 'gcj02',                 // wgs84 / gcj02
      isHighAccuracy: true,
      highAccuracyExpireTime: 4000,  // 高精度模式超时（毫秒）
      success: (res) => {
        this.setData({
          latitude: res.latitude,
          longitude: res.longitude
        })
        console.log('坐标：', res.latitude, res.longitude, '精度：', res.accuracy + 'm')
      },
      fail: (err) => {
        console.error('定位失败：', err.errMsg)
      }
    })
  },

  // 授权被拒绝：引导用户去设置页打开
  openSettingGuide() {
    wx.showModal({
      title: '需要位置权限',
      content: '请在设置中开启位置权限，以便为您推荐附近的商家',
      confirmText: '去设置',
      success: (res) => {
        if (res.confirm) {
          wx.openSetting({
            success: (settingRes) => {
              if (settingRes.authSetting['scope.userLocation']) {
                this.getLocation()
              }
            }
          })
        }
      }
    })
  }
})
```

wx.chooseLocation 打开微信自带的地图选点页面，用户在地图上选一个点后返回该点的 name、address、latitude、longitude（gcj02 坐标）。适合「填写收货地址」「选择活动场地」「外卖送餐地址」等场景，省去自己画地图的成本。同样需要 scope.userLocation 授权与 requiredPrivateInfos 声明。

```js
// pages/address/address.js
Page({
  data: { address: {} },

  chooseAddress() {
    wx.chooseLocation({
      success: (res) => {
        // res: { name, address, latitude, longitude }
        this.setData({ address: res })
        console.log('选点：', res.name, res.address, res.latitude, res.longitude)
      },
      fail: (err) => {
        // 用户点击地图页左上角返回也算取消，errMsg 含 cancel
        if (!err.errMsg.includes('cancel')) {
          console.error('选点失败：', err.errMsg)
        }
      }
    })
  }
})
```

```text
位置能力要点：
1. app.json 必须声明 requiredPrivateInfos: ["getLocation"]，否则真机 fail
2. 需要 scope.userLocation 授权，拒绝后用 wx.openSetting 引导开启
3. 国内业务用 gcj02 坐标系，与地图 SDK、后台逆地址解析保持一致
4. chooseLocation 返回 name / address / latitude / longitude（gcj02）
5. 高精度模式更耗电，非必要场景用默认精度
6. 定位结果要缓存与降级：定位失败时回退到上次成功的位置或默认城市
```

## 蓝牙与 NFC

蓝牙 API 面向 IoT 场景：连接蓝牙耳机、智能手环、蓝牙打印机、蓝牙秤、智能门锁等硬件设备。完整流程分六步：openBluetoothAdapter 初始化蓝牙适配器 → startBluetoothDevicesDiscovery 开始搜索 → onBluetoothDeviceFound 监听发现设备 → createBLEConnection 建立连接 → getBLEDeviceServices / getBLEDeviceCharacteristics 读取服务与特征值 → notifyBLECharacteristicValueChange + onBLECharacteristicValueChange / writeBLECharacteristicValue 收发数据。结束后依次 closeBLEConnection 与 closeBluetoothAdapter 释放资源。

```js
// pages/ble/ble.js
Page({
  data: {
    devices: [],
    connected: false
  },

  // 第一步：初始化适配器
  openAdapter() {
    wx.openBluetoothAdapter({
      success: () => {
        console.log('蓝牙适配器已打开')
        this.startDiscovery()
      },
      fail: (err) => {
        // 常见原因：手机蓝牙未开启 / 系统不支持蓝牙
        wx.showModal({
          title: '蓝牙不可用',
          content: '请检查手机蓝牙是否已开启',
          showCancel: false
        })
      }
    })
  },

  // 第二步：开始搜索
  startDiscovery() {
    wx.startBluetoothDevicesDiscovery({
      allowDuplicatesKey: false,
      success: () => console.log('开始搜索设备'),
      fail: (err) => console.error('搜索失败：', err.errMsg)
    })
    // 第三步：监听发现设备
    wx.onBluetoothDeviceFound((res) => {
      const found = res.devices.map((d) => ({
        deviceId: d.deviceId,
        name: d.name || '未知设备',
        RSSI: d.RSSI
      }))
      this.setData({ devices: found })
    })
  },

  // 第四步：连接设备
  connect(deviceId) {
    wx.createBLEConnection({
      deviceId,
      success: () => {
        this.setData({ connected: true })
        this.readServices(deviceId)
      },
      fail: (err) => {
        console.error('连接失败：', err.errMsg)
      }
    })
  },

  // 第五步：读取服务与特征值
  readServices(deviceId) {
    wx.getBLEDeviceServices({
      deviceId,
      success: (res) => {
        console.log('发现服务：', res.services)
      }
    })
    wx.getBLEDeviceCharacteristics({
      deviceId,
      serviceId: '0000180f-0000-1000-8000-00805f9b34fb', // 电池服务示例
      success: (res) => {
        console.log('发现特征值：', res.characteristics)
      }
    })
  },

  // 第六步：收尾释放
  disconnect(deviceId) {
    wx.closeBLEConnection({ deviceId })
    wx.closeBluetoothAdapter({
      success: () => {
        this.setData({ connected: false })
      }
    })
  }
})
```

NFC 能力通过 wx.getNFCAdapter() 获取适配器，支持 ISO 14443 A/B 等技术的读写（NFC 标签、公交卡读取等），startDiscovery 开始轮询，onDiscovered 在发现 NFC 卡时回调。注意三点：仅部分支持 NFC 的安卓机型可用（iOS 不支持该 API）；Android 6.0+ 上蓝牙搜索与 NFC 轮询都需要定位权限；NFC 只支持读写模式，不支持模拟门禁卡（卡模拟需要手机硬件级支持，与小程序 API 无关）。

```js
// pages/nfc/nfc.js
Page({
  readNFC() {
    const nfc = wx.getNFCAdapter()
    if (!nfc) {
      wx.showToast({ title: '当前设备不支持 NFC', icon: 'none' })
      return
    }
    nfc.startDiscovery({
      success: () => {
        nfc.onDiscovered((res) => {
          console.log('发现 NFC 卡片，支持技术：', res.techs)
          // res.messages 为读取到的 NDEF 数据
          if (res.messages && res.messages.length > 0) {
            console.log('NDEF 数据：', res.messages)
          }
        })
      },
      fail: (err) => {
        console.error('NFC 启动失败：', err.errMsg)
      }
    })
  }
})
```

```text
蓝牙与 NFC 要点：
1. 蓝牙六步流程：open → discovery → onFound → createBLEConnection → services/characteristics → 收发数据
2. 结束后必须 closeBLEConnection + closeBluetoothAdapter 释放资源，否则耗电
3. Android 6.0+ 蓝牙搜索需要定位权限，需在 manifest/授权流程中处理
4. BLE 数据收发基于特征值（Characteristic），不是传统串口，需理解 UUID 与 notify/write 语义
5. NFC 仅支持部分安卓机型，iOS 不支持 wx.getNFCAdapter，必须先做能力检测
6. NFC 不支持模拟门禁卡，卡模拟属手机硬件能力，与小程序 API 无关
```

## 应用场景实战

### 场景一：设备信息上报与网络监控

应用启动时采集设备信息上报后台（用于兼容性统计、机型分布分析），同时监控网络状态，断网时显示横幅提示。

```js
// app.js
App({
  onLaunch() {
    this.reportDeviceInfo()
    this.monitorNetwork()
  },

  reportDeviceInfo() {
    // 采集设备信息（新 API + 兼容降级）
    const info = this.getSafeSystemInfo()
    wx.request({
      url: 'https://api.example.com/device/report',
      method: 'POST',
      data: {
        platform: info.platform,
        system: info.system,
        model: info.model,
        brand: info.brand,
        SDKVersion: info.SDKVersion,
        windowWidth: info.windowWidth,
        statusBarHeight: info.statusBarHeight
      },
      success: () => console.log('设备信息上报成功')
    })
  },

  getSafeSystemInfo() {
    if (wx.getWindowInfo && wx.getDeviceInfo && wx.getAppBaseInfo) {
      return { ...wx.getWindowInfo(), ...wx.getDeviceInfo(), ...wx.getAppBaseInfo() }
    }
    return wx.getSystemInfoSync()
  },

  monitorNetwork() {
    wx.onNetworkStatusChange((res) => {
      if (!res.isConnected) {
        // 断网横幅（全局提示）
        wx.showToast({ title: '网络已断开', icon: 'none', duration: 3000 })
      }
    })
  }
})
```

### 场景二：门店扫码签到 + 位置校验

店员/顾客扫码签到，扫码结果与定位结合：先 wx.getLocation 拿坐标，再 wx.scanCode 拿门店码，后台校验门店位置与扫码位置距离，防止远程代签。

```js
// pages/checkin/checkin.js
Page({
  data: {
    checking: false
  },

  startCheckin() {
    if (this.data.checking) return
    this.setData({ checking: true })

    // 第一步：获取位置（先确保授权）
    this.ensureLocationAuth((latitude, longitude) => {
      // 第二步：扫码
      wx.scanCode({
        scanType: ['qrCode'],
        success: (res) => {
          this.submitCheckin(res.result, latitude, longitude)
        },
        fail: () => this.setData({ checking: false })
      })
    })
  },

  ensureLocationAuth(callback) {
    wx.getSetting({
      success: (res) => {
        if (res.authSetting['scope.userLocation']) {
          this.getLocation(callback)
        } else {
          wx.authorize({
            scope: 'scope.userLocation',
            success: () => this.getLocation(callback),
            fail: () => {
              this.setData({ checking: false })
              this.openSettingGuide()
            }
          })
        }
      }
    })
  },

  getLocation(callback) {
    wx.getLocation({
      type: 'gcj02',
      success: (res) => callback(res.latitude, res.longitude),
      fail: () => {
        this.setData({ checking: false })
        wx.showToast({ title: '定位失败，请开启定位', icon: 'none' })
      }
    })
  },

  submitCheckin(code, latitude, longitude) {
    wx.showLoading({ title: '签到中', mask: true })
    wx.request({
      url: 'https://api.example.com/checkin/submit',
      method: 'POST',
      data: { storeCode: code, latitude, longitude },
      success: (res) => {
        wx.hideLoading()
        this.setData({ checking: false })
        if (res.data.code === 0) {
          wx.showToast({ title: '签到成功', icon: 'success' })
          // 签到成功给个轻震动反馈
          wx.vibrateShort({ type: 'light' })
        } else {
          wx.showModal({
            title: '签到失败',
            content: res.data.msg || '请确认已在门店范围内',
            showCancel: false
          })
        }
      },
      fail: () => {
        wx.hideLoading()
        this.setData({ checking: false })
        wx.showToast({ title: '网络异常', icon: 'none' })
      }
    })
  },

  openSettingGuide() {
    wx.showModal({
      title: '需要位置权限',
      content: '签到需要获取您的位置，请在设置中开启',
      confirmText: '去设置',
      success: (res) => {
        if (res.confirm) wx.openSetting()
      }
    })
  }
})
```

## 最佳实践与踩坑记录

### 最佳实践

1. 统一封装 device.js 工具模块：getWindowInfo / getDeviceInfo / getAppBaseInfo / getNetworkType 全部收敛到一个文件，兼容降级写一次，页面只调封装函数
2. 系统信息只取一次并缓存：onLaunch 采集后存全局，不要在每次 onShow 重复调用
3. 网络监听严格配对：onNetworkStatusChange 与 offNetworkStatusChange 成对，onUnload 必移除，防止页面销毁后回调泄漏
4. 权限拒绝统一走「引导 openSetting」流程：getLocation 授权拒绝后不要反复弹窗，一次引导 + 说明用途文案（app.json permission.desc）
5. 位置信息缓存 + 降级：定位失败回退上次成功坐标或默认城市，保证页面不空白
6. 蓝牙/NFC 等硬件流程用状态机管理（idle / opening / discovering / connecting / connected），避免用户连点导致流程错乱
7. 硬件类功能必须真机测试矩阵：iOS + 安卓 + 不同基础库版本各测一轮，模拟器行为仅作参考
8. 所有设备能力调用前用 wx.canIUse 检测，低版本基础库降级或隐藏入口

### 踩坑记录

坑 1：getSystemInfoSync 在部分新机型上拿不到 statusBarHeight
结论：新机型（尤其挖孔屏）上 windowHeight/statusBarHeight 数值异常或为 0，布局错乱。
原因：getSystemInfoSync 已废弃，新机型窗口参数由 getWindowInfo 提供，旧 API 数据不完整。
解法：改用 wx.getWindowInfo() 获取 statusBarHeight / safeArea；老基础库用 getSystemInfoSync 兜底，并做 0 值保护。

坑 2：开发者工具上 networkType 恒为 wifi，5g 判断全部失效
结论：代码里写好的「5g 显示高清图」逻辑在开发者工具永远走不到。
原因：开发者工具模拟的是本机网络，网络类型固定返回 wifi。
解法：弱网/5g 相关逻辑必须在真机验证；真机上部分安卓机 5G 也会被识别为 4g，判断高速网络用 wifi/4g/5g 白名单而非精确匹配。

坑 3：setClipboardData 后自己又 showToast，出现两个提示
结论：复制成功后屏幕同时出现系统「内容已复制」和自己写的 toast，体验很怪。
原因：setClipboardData 成功后系统会自动弹出复制成功的提示，无需开发者再提示。
解法：setClipboardData 的 success 回调里不要再调用 wx.showToast，只做业务处理（如关闭弹层）。

坑 4：getLocation 真机 fail，报 "getLocation:fail the api need to be declared in the requiredPrivateInfos field in app.json"
结论：开发者工具正常，真机上一调用 getLocation 就报错。
原因：2022 年 7 月起微信要求位置类接口必须在 app.json 的 requiredPrivateInfos 中显式声明，未声明真机直接拒绝。
解法：app.json 添加 "requiredPrivateInfos": ["getLocation", "chooseLocation"]，并重新编译上传；同时在 permission 中配置授权用途说明。

坑 5：用户拒绝位置授权后，getLocation 永久 fail
结论：用户第一次点「拒绝」后，后续所有 getLocation 调用都直接失败，页面功能不可用。
原因：scope.userLocation 授权一旦拒绝，不会再次自动弹授权框。
解法：getSetting 检测 authSetting['scope.userLocation'] 为 false 时，用 wx.openSetting 引导用户去设置页手动开启，并说明用途。

坑 6：Android 上蓝牙搜不到任何设备
结论：蓝牙适配器打开成功，但 startBluetoothDevicesDiscovery 一直搜不到设备。
原因：Android 6.0+ 蓝牙扫描需要位置权限（部分机型还要开启定位服务），未授权或定位关闭时扫描静默失败。
解法：扫描前先申请位置权限并检查定位开关；用 onBluetoothDeviceFound 统计回调次数，长时间无结果给出提示。

坑 7：iOS 上 vibrateShort 无效果
结论：安卓震动正常，iOS 上点击没有任何反应。
原因：iOS 对震动 API 调用时机有要求，且部分版本 vibrateShort 需要在用户手势（touch 事件）回调内同步调用才生效。
解法：在 bindtap 等用户手势回调内直接调用 vibrateShort；异步回调（如请求返回后）里调用可能被系统忽略，必要时用 vibrateLong 兜底。

坑 8：NFC 在 iOS 上调用 wx.getNFCAdapter 直接报错
结论：功能在安卓测试通过，iOS 真机上 NFC 功能完全不可用。
原因：wx.getNFCAdapter 仅支持部分安卓机型，iOS 端未开放该 API。
解法：调用前判断 platform，iOS 隐藏 NFC 入口并提示「当前设备不支持」；安卓机型也要做能力检测（部分机型无 NFC 硬件）。

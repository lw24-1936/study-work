## 概述

微信小程序从基础库 2.11.0 起支持暗黑模式（DarkMode）：在 app.json 中开启 `darkmode` 后，小程序会跟随系统外观（浅色/深色）自动切换主题。原生导航栏、tabBar 等系统组件的颜色由 theme.json 中对应字段控制，页面内自定义样式则通过 CSS 变量（var()）与 `@media (prefers-color-scheme: dark)` 媒体查询两套机制适配。

暗黑模式不是简单地把背景换成黑色，而是整套色彩体系的切换：背景、文字、分割线、图标、图片都要有明暗两套取值，且要保证对比度与可读性。工程上正确的做法是「设计两套语义化色板 → 通过主题变量注入 → 页面零散色值全部改为变量引用」，而不是在几十个页面里用媒体查询逐个覆盖。

```text
暗黑模式核心认知：
1. 开关 —— app.json 配置 darkmode: true，主题能力才会注入
2. 配置 —— theme.json 定义 light/dark 两套变量，themeLocation 指定路径
3. 系统 —— 原生导航栏/tabBar 颜色跟随 theme.json 自动切换
4. 页面 —— WXSS 通过 var(--变量) 与 prefers-color-scheme 适配自定义样式
5. 感知 —— wx.getSystemInfoSync().theme 读取当前主题，wx.onThemeChange 监听切换
6. 强制 —— wx.setTheme 可在运行时强制指定浅色/深色，覆盖系统外观
```

## 暗黑模式配置基础

开启暗黑模式需要两步：app.json 中设置 `"darkmode": true`；在项目根目录提供 theme.json（路径可用 `themeLocation` 字段自定义，默认就是项目根目录的 theme.json）。theme.json 中必须同时定义 `light` 与 `dark` 两套配置，分别对应系统浅色与深色外观。

开启后微信客户端的原生能力会自动跟随：导航栏背景色与文字颜色、下拉 loading 背景、页面背景、tabBar 配色都会读取 theme.json 中对应的键。原生组件自动适配意味着「导航栏 + tabBar」这类系统层界面不需要写一行页面代码。自定义导航栏（navigationStyle: custom）与页面内自绘内容则必须自己适配。

主题切换时机由微信控制：系统切换外观时，微信会重新应用对应主题，页面会重新渲染；开发者工具中可通过工具栏切换「外观」模拟深浅色，真机则直接切换系统设置观察。

```json
// app.json —— 开启暗黑模式
{
  "pages": [
    "pages/index/index",
    "pages/mine/mine"
  ],
  "darkmode": true,
  "themeLocation": "theme.json"
}
```

```json
// theme.json —— 项目根目录，两套主题缺一不可
{
  "light": {
    "navigationBarBackgroundColor": "#ffffff",
    "navigationBarTextStyle": "black",
    "backgroundColor": "#f7f8fa",
    "backgroundTextStyle": "light",
    "backgroundColorTop": "#f7f8fa",
    "backgroundColorBottom": "#f7f8fa",
    "tabBarBackgroundColor": "#ffffff",
    "tabBarBorderStyle": "black",
    "tabBarColor": "#999999",
    "tabBarSelectedColor": "#07c160"
  },
  "dark": {
    "navigationBarBackgroundColor": "#1c1c1e",
    "navigationBarTextStyle": "white",
    "backgroundColor": "#1c1c1e",
    "backgroundTextStyle": "dark",
    "backgroundColorTop": "#1c1c1e",
    "backgroundColorBottom": "#1c1c1e",
    "tabBarBackgroundColor": "#1c1c1e",
    "tabBarBorderStyle": "white",
    "tabBarColor": "#8e8e93",
    "tabBarSelectedColor": "#07c160"
  }
}
```

```text
配置基础要点：
1. darkmode —— app.json 中置 true 才启用暗黑模式，未开启则全部配置不生效
2. themeLocation —— 指定 theme.json 路径，默认项目根目录，可自定义子目录
3. light/dark —— theme.json 必须同时定义两套，缺一套时另一套直接失效
4. 原生字段 —— navigationBar/backgroundColor/tabBar 系列控制系统层颜色
5. 自动适配 —— 原生导航栏与 tabBar 由微信读取 theme.json 自动切换
6. 自绘内容 —— 自定义导航栏、页面内 WXML 样式必须自己写适配逻辑
```

## theme.json 主题变量

theme.json 除了系统级字段，还支持开发者自定义字段，且必须放在 `custom` 节点下。custom 中的字段会作为 CSS 变量注入到页面样式中，WXSS 中通过 `var(--字段名)` 引用，浅色与深色各给一套值，页面里写一次变量引用即可自动跟随主题。

变量命名规范：字段名以字母开头，可以包含字母、数字与中划线/下划线，不要以数字或 `--` 开头。引用时建议带上 fallback：`var(--textColor, #333333)`，这样即使变量未注入（低版本基础库、未开启 darkmode），页面也有默认样式可看。

主题变量让「改色」变成改一处配置：设计稿定好两套语义化色板（主色、背景、文字主次、分割线、卡片背景、危险色等），在 custom 中定义后，所有页面统一引用，后续换肤只需改 theme.json。

```json
// theme.json —— 自定义主题变量（custom 节点）
{
  "light": {
    "custom": {
      "primaryColor": "#07c160",
      "pageBgColor": "#f7f8fa",
      "cardBgColor": "#ffffff",
      "textColor": "#1f1f1f",
      "textSubColor": "#999999",
      "dividerColor": "#ececec",
      "dangerColor": "#e64340"
    }
  },
  "dark": {
    "custom": {
      "primaryColor": "#07c160",
      "pageBgColor": "#111111",
      "cardBgColor": "#1c1c1e",
      "textColor": "#f2f2f2",
      "textSubColor": "#8e8e93",
      "dividerColor": "#2c2c2e",
      "dangerColor": "#ff4d4f"
    }
  }
}
```

```css
/* pages/index/index.wxss —— 页面内引用主题变量 */
.page {
  /* var() 引用注入的变量，逗号后是 fallback 默认值 */
  background-color: var(--pageBgColor, #f7f8fa);
}

.card {
  background-color: var(--cardBgColor, #ffffff);
  color: var(--textColor, #1f1f1f);
}

.card-title {
  color: var(--textColor, #1f1f1f);
}

.card-sub {
  color: var(--textSubColor, #999999);
}

.divider {
  background-color: var(--dividerColor, #ececec);
  height: 2rpx;
}

.price {
  color: var(--dangerColor, #e64340);
}
```

```text
主题变量要点：
1. custom 节点 —— 自定义字段必须放在 theme.json 的 custom 中才会注入
2. var() 引用 —— WXSS 中 var(--字段名) 使用，字段名大小写敏感
3. fallback —— var(--xxx, 默认值) 兜底，低版本基础库或未开 darkmode 时样式不丢
4. 命名 —— 字段名以字母开头，避免数字开头与 -- 前缀
5. 语义化 —— 按「主色/背景/文字/分割线」语义命名，而不是按具体色值命名
6. 一处修改 —— 换肤只改 theme.json，页面代码零改动
```

## 页面内适配方案

页面内自绘内容的适配有两条路径：CSS 变量方案与媒体查询方案。CSS 变量方案（推荐）——所有颜色引用 theme.json 注入的变量，主题切换时变量值自动变化，无需任何额外代码。媒体查询方案——在 WXSS 中写 `@media (prefers-color-scheme: dark) { ... }` 覆盖深色样式，适合少量特殊样式或无法用变量的场景。

JS 侧需要感知主题时，用 `wx.getSystemInfoSync().theme` 读取当前主题（'light' / 'dark'），通过 `wx.onThemeChange(callback)` 监听系统切换。典型场景：切换主题时替换图片素材（浅色 logo 与深色 logo）、切换页面级 class、上报埋点。注意 onThemeChange 回调里拿到的 `res.theme` 是切换后的主题。

图片适配是暗黑模式最容易遗漏的部分：白底商品图在深色背景下刺眼，浅色 PNG 图标在深色下不可见。方案有三：准备两套素材按主题切换 src；使用 SVG 或 CSS 绘制可继承变量的图形；给图片容器加圆角卡片背景，让图片与背景解耦。深色模式下还可以给图片加一层遮罩（深色半透明）降低亮度。

```css
/* 媒体查询方案：适用于少量特殊覆盖 */
@media (prefers-color-scheme: dark) {
  .page {
    background-color: #111111;
  }
  .card {
    background-color: #1c1c1e;
  }
}
```

```js
// pages/index/index.js —— JS 侧主题感知
Page({
  data: {
    theme: 'light',
    logo: '/assets/logo-light.png'
  },

  onLoad() {
    const { theme } = wx.getSystemInfoSync();
    this.applyTheme(theme);

    // 监听系统主题切换
    wx.onThemeChange((res) => {
      this.applyTheme(res.theme);
    });
  },

  applyTheme(theme) {
    this.setData({
      theme,
      // 主题相关资源按主题切换
      logo: theme === 'dark' ? '/assets/logo-dark.png' : '/assets/logo-light.png'
    });
  }
});
```

```xml
<!-- pages/index/index.wxml —— 主题 class 切换 -->
<view class="page {{theme === 'dark' ? 'page-dark' : ''}}">
  <image class="logo" src="{{logo}}" mode="aspectFit" />
  <view class="card">
    <text class="card-title">暗黑模式适配示例</text>
    <text class="card-sub">当前主题：{{theme}}</text>
  </view>
</view>
```

```text
页面适配要点：
1. 首选变量 —— 颜色全部引用 var(--变量)，主题切换自动生效，无需额外代码
2. 媒体查询 —— @media (prefers-color-scheme: dark) 覆盖特殊样式
3. 读取主题 —— wx.getSystemInfoSync().theme 返回 light/dark
4. 监听切换 —— wx.onThemeChange 回调参数 res.theme 为切换后的主题
5. 图片适配 —— 双素材切换 src，或 SVG/CSS 绘制，或深色遮罩降亮度
6. class 切换 —— 页面根节点挂 theme class，配合 CSS 覆盖局部细节
```

## 自定义主题与主题切换

在暗黑模式基础上可以做「跟随系统 / 浅色 / 深色」三档自定义切换：默认跟随系统，用户手动选择后覆盖系统外观。实现方式是在用户选择时调用 `wx.setTheme({ theme: 'light' | 'dark' })`，并把选择持久化到 storage，下次启动时恢复。

`wx.setTheme` 仅在 app.json 开启 darkmode 时生效，且优先于系统外观；调用后当前小程序立即按指定主题渲染，theme.json 中对应的一套配置生效。注意 setTheme 影响的是当前小程序实例，不影响其他小程序与微信全局。

多主题扩展时，theme.json 可以定义多套（light/dark/更多自定义名），但系统级字段只有 light 与 dark 会被微信识别；扩展主题的差异应全部通过 custom 变量承载，页面逻辑只认变量名，不认主题名，这样新增主题零页面改动。主题切换的持久化与恢复逻辑统一放 app.js 的 onLaunch 中处理。

```json
// app.json —— 开启暗黑模式是 setTheme 生效的前提
{
  "darkmode": true,
  "themeLocation": "theme.json"
}
```

```js
// app.js —— 启动时恢复用户主题选择
App({
  onLaunch() {
    const savedTheme = wx.getStorageSync('userTheme'); // 'light' | 'dark' | ''
    if (savedTheme === 'light' || savedTheme === 'dark') {
      wx.setTheme({ theme: savedTheme });
    }
  }
});
```

```js
// pages/settings/settings.js —— 三档切换
Page({
  data: {
    // 0 跟随系统，1 浅色，2 深色
    modeIndex: 0,
    modes: ['跟随系统', '浅色', '深色']
  },

  onLoad() {
    const savedTheme = wx.getStorageSync('userTheme');
    const modeIndex = savedTheme === 'light' ? 1 : savedTheme === 'dark' ? 2 : 0;
    this.setData({ modeIndex });
  },

  onModeChange(e) {
    const modeIndex = Number(e.detail.value);
    const themeMap = ['', 'light', 'dark'];
    const theme = themeMap[modeIndex];

    if (theme) {
      wx.setTheme({ theme });
      wx.setStorageSync('userTheme', theme);
    } else {
      // 跟随系统：清除强制选择，回到系统外观
      wx.removeStorageSync('userTheme');
      const { theme: current } = wx.getSystemInfoSync();
      wx.setTheme({ theme: current });
    }
    this.setData({ modeIndex });
  }
});
```

```xml
<!-- pages/settings/settings.wxml -->
<view class="page">
  <view class="card">
    <text class="card-title">外观模式</text>
    <picker mode="selector" range="{{modes}}" value="{{modeIndex}}" bindchange="onModeChange">
      <view class="picker-value">{{modes[modeIndex]}} ›</view>
    </picker>
  </view>
</view>
```

```text
自定义主题要点：
1. wx.setTheme —— 运行时强制切换主题，仅 darkmode 开启时生效
2. 三档设计 —— 跟随系统/浅色/深色，默认跟随系统读取 wx.getSystemInfoSync().theme
3. 持久化 —— 用户选择写入 storage，onLaunch 恢复，避免每次启动重置
4. 恢复跟随 —— 清除 storage 并把主题切回系统当前值
5. 多主题 —— 扩展主题差异全部走 custom 变量，页面只认变量不认主题名
6. 作用域 —— setTheme 只影响当前小程序实例，不影响微信全局
```

### 场景二：设置页「跟随系统 / 浅色 / 深色」三档切换

提供用户可感知的主题设置：默认跟随系统，手动选择后立即生效并持久化，重启不丢失。

```js
// app.js —— 全局恢复主题
App({
  onLaunch() {
    const savedTheme = wx.getStorageSync('userTheme');
    if (savedTheme === 'light' || savedTheme === 'dark') {
      wx.setTheme({ theme: savedTheme });
    }
  }
});
```

```js
// pages/settings/settings.js
Page({
  data: {
    modes: ['跟随系统', '浅色', '深色'],
    modeIndex: 0
  },

  onLoad() {
    const saved = wx.getStorageSync('userTheme');
    const index = saved === 'light' ? 1 : saved === 'dark' ? 2 : 0;
    this.setData({ modeIndex: index });
  },

  onModeChange(e) {
    const index = Number(e.detail.value);
    const theme = ['', 'light', 'dark'][index];

    if (theme) {
      wx.setTheme({ theme });
      wx.setStorageSync('userTheme', theme);
    } else {
      wx.removeStorageSync('userTheme');
      const { theme: current } = wx.getSystemInfoSync();
      wx.setTheme({ theme: current });
    }
    this.setData({ modeIndex: index });
    wx.showToast({ title: '已切换外观', icon: 'none' });
  }
});
```

```xml
<!-- pages/settings/settings.wxml -->
<view class="page">
  <view class="cell">

      <view class="cell-value">{{modes[modeIndex]}} ›</view>
    </picker>
  </view>
</view>
```

```css
  color: var(--subText, #999999);

}
```

```text
场景要点：
1. 系统层 —— 导航栏/tabBar 颜色写在 theme.json 系统字段，自动适配
2. 页面层 —— 自定义样式全部引用 custom 变量，零散色值禁止写死
3. 图片 —— 深色模式叠加半透明遮罩降低白底图亮度
4. 三档切换 —— setTheme 强制主题，storage 持久化，onLaunch 恢复
5. 监听 —— onThemeChange 同步 JS 侧状态（isDark）驱动条件渲染
6. 验证 —— 工具切换外观 + 真机切换系统深浅色双端验证
```

## 最佳实践与踩坑记录

### 最佳实践

1. 颜色一律通过 theme.json custom 变量注入，页面中禁止写死色值，后续换肤只改一处
2. 每个 var() 引用都写 fallback 默认值，未开启 darkmode 或低版本基础库时样式不丢失
3. 色板按语义命名（pageBg/cardBg/mainText/subText/divider/priceColor），不要按色值命名
4. 图标素材优先用 SVG/CSS 绘制或准备两套图，白底 PNG 在深色下必须处理
5. 用 wx.getSystemInfoSync().theme 初始化 JS 侧主题状态，用 wx.onThemeChange 同步变化
6. 用户主题选择持久化到 storage，app.js onLaunch 恢复，三档设计（跟随/浅/深）覆盖主流诉求
7. 上线前把主要页面在深色模式下完整过一遍：列表、弹窗、表单、空态、toast 都要验证
8. 原生导航栏与 tabBar 的颜色交给 theme.json 系统字段，不要用 setNavigationBarColor 手动设置

### 踩坑记录

坑 1：themeLocation 路径写错导致编译报错或主题不生效
结论：app.json 配置 themeLocation 指向不存在的路径时，构建直接失败或暗黑模式无效果。
原因：微信按 themeLocation 查找 theme.json，路径错误则无法加载两套配置。
解法：themeLocation 保持默认不写（根目录 theme.json 最稳）；自定义路径必须与文件实际位置一致。

坑 2：自定义变量名以数字或 -- 开头导致注入失败
结论：custom 中定义了变量，但 WXSS 里 var() 取不到值，样式回退到 fallback。
原因：注入的 CSS 变量命名不合规（数字开头、-- 前缀），微信端注入失败。
解法：字段名一律以字母开头，仅含字母、数字、中划线/下划线。

坑 3：var() 没有 fallback，低版本基础库样式全丢
结论：开启 darkmode 的代码在基础库 2.11.0 以下或未开启 darkmode 时页面变白板。
原因：主题变量只在 darkmode 开启且基础库支持时才注入，var() 取不到值时整条声明失效。
解法：所有 var() 都写默认值，如 var(--cardBg, #ffffff)；关键页面做基础库版本检测。

坑 4：白底图片素材在深色模式下刺眼
结论：深色背景下白色或浅色商品图高亮刺眼，页面观感差。
原因：图片是静态资源，不随主题变量变化，浅色素材直接暴露在深色背景上。
解法：准备两套素材按主题切换 src；或给图片叠加深色半透明遮罩；或图片容器加卡片背景与图片解耦。

坑 5：开发者工具模拟器里切换了外观但页面没变化
结论：工具中已经切换「外观」为深色，页面样式纹丝不动。
原因：工具未开启暗黑模式模拟能力，或项目未开启 darkmode，或工具版本过旧。
解法：工具「详情 - 本地设置」勾选模拟器支持暗黑模式；确认 app.json 已配置 darkmode: true；升级开发者工具。

坑 6：tabBar 颜色键名写错导致暗黑下配色混乱
结论：深色模式下 tabBar 文字/背景颜色与预期不符。
原因：theme.json 中 tabBar 相关键名写错（如把 tabBarColor 写成 tabColor），微信读取不到对应键。
解法：严格按文档键名：tabBarBackgroundColor、tabBarBorderStyle、tabBarColor、tabBarSelectedColor。

坑 7：wx.setNavigationBarColor 手动设置的颜色不跟随主题
结论：用 wx.setNavigationBarColor 动态改过导航栏颜色的页面，深色模式下导航栏仍是浅色。
原因：手动设置的导航栏颜色优先级高于 theme.json，且不会随主题切换自动还原。
解法：导航栏颜色交给 theme.json 原生字段；必须动态改色的页面在 onThemeChange 中同步重新设置。

坑 8：prefers-color-scheme 媒体查询在部分机型不生效
结论：依赖 @media (prefers-color-scheme: dark) 的页面在部分安卓真机上不切换。
原因：旧版内核对该媒体特性支持不全，或小程序 WebView 未透传系统外观。
解法：主方案用 theme.json 变量（微信注入，与内核无关），媒体查询只做辅助覆盖；真机验证。

## 概述

CSS Grid 是二维网格布局方案，在 WXSS 中与 Flex 形成互补：Flex 擅长一维排列（行或列），Grid 擅长同时控制行与列，适合九宫格入口、卡片流、瀑布流、栅格系统等经典页面结构。小程序 WebView 渲染基于系统内核（iOS WKWebView、Android XWeb 或系统 WebView），现代基础库环境下 grid 属性可正常使用，但低版本安卓内核存在兼容缺口，需要结合 rpx、flex 兜底与真机验证来落地。

Grid 的核心思路是把容器划分为「轨道」（行与列），子元素放进网格单元，再通过跨列、跨行、命名区域与对齐属性精确控制每个元素的位置。与 rpx 配合后，Grid 是搭建小程序信息流页面最高效的工具。

```text
Grid 布局核心认知：
1. 二维 —— display:grid 同时管理行与列，flex 管一维、grid 管二维
2. 轨道 —— grid-template-columns/rows 定义行列轨道，fr 分配剩余空间
3. 间距 —— gap 统一控制行列间距，替代 margin 避免溢出
4. 区域 —— grid-template-areas 命名布局，代码即结构图
5. 对齐 —— justify-items/align-items 控制单元格内元素对齐
6. 组合 —— rpx 适配尺寸、flex 做单维流、grid 做网格，三者组合实现经典布局
```

## Grid 布局基础

把容器设置为 `display: grid` 后，容器进入网格模式，直接子元素自动成为网格项（grid item），依次落入网格单元。核心属性是 `grid-template-columns`（列轨道）与 `grid-template-rows`（行轨道），轨道尺寸支持固定值（rpx/px）、百分比与 fr 单位。

`fr`（fraction）是 Grid 特有的弹性单位，表示剩余空间按比例分配。`1fr 2fr` 表示第二列是第一列的两倍宽；与百分比不同，fr 计算的是扣除 gap 之后的剩余空间，因此 fr 与 gap 混用不会像「百分比 + margin」那样溢出换行。`repeat(3, 1fr)` 等价于 `1fr 1fr 1fr`，三列等宽，这是九宫格与双列卡片流最常用的写法。

下面是一个完整的九宫格示例页面（WXML + WXSS）：

```xml
<!-- pages/grid/grid.wxml -->
<view class="page">
  <view class="grid-demo">
    <view class="cell" wx:for="{{9}}" wx:key="*this">
      <text>{{index + 1}}</text>
    </view>
  </view>
</view>
```

```css
/* pages/grid/grid.wxss */
.page {
  padding: 24rpx;
  background-color: #f7f8fa;
}

.grid-demo {
  display: grid;
  /* 三列等宽：repeat(3, 1fr) 等价于 1fr 1fr 1fr */
  grid-template-columns: repeat(3, 1fr);
  /* 三行固定高度 */
  grid-template-rows: repeat(3, 160rpx);
  /* 行列间距统一 20rpx，等价于 row-gap 与 column-gap 同时设置 */
  gap: 20rpx;
}

.cell {
  display: flex;
  align-items: center;
  justify-content: center;
  background-color: #ffffff;
  border-radius: 16rpx;
  color: #333333;
  font-size: 32rpx;
}
```

`gap` 是 `row-gap` 与 `column-gap` 的简写，替代传统「子元素 margin + 容器负 margin」的间距方案。使用 gap 后子元素之间不会叠加边距，也不会撑破容器，是 Grid/Flex 布局中控制间距的首选。

```text
Grid 基础属性速记：
1. display:grid —— 开启网格，直接子元素成为网格项
2. grid-template-columns —— 定义列轨道，如 repeat(3, 1fr)、200rpx 1fr
3. grid-template-rows —— 定义行轨道，不设置时行高由内容撑开
4. fr 单位 —— 剩余空间按比例分配，1fr 2fr 即 1:2，与 gap 兼容不溢出
5. gap —— 行列间距统一控制，语法 gap: 20rpx 或 gap: 20rpx 30rpx（行 列）
6. 固定值 —— 轨道支持 rpx/px/百分比，如 grid-template-columns: 200rpx 1fr
```

## Grid 进阶属性

基础轨道之外，Grid 提供了跨列跨行、命名区域与对齐控制三组能力，用于实现复杂页面结构。

跨列跨行通过 `grid-column` / `grid-row` 实现：`grid-column: 1 / 3` 表示从第 1 条网格线到第 3 条网格线（占两列），`grid-column: span 2` 表示跨 2 列，`grid-column: 1 / -1` 表示横跨整行。栅格系统中的 `col-6` 就是靠 span 实现的。

命名区域 `grid-template-areas` 用字符串为每个单元格命名，配合子元素的 `grid-area: 名称` 完成放置。区域名必须以字母开头，同名的格子必须构成矩形，空位用 `.`（点）占位。这种写法把布局结构直接画在 CSS 里，可读性极高，适合「顶部导航 + 侧栏 + 主体 + 底部」这类后台型页面。

对齐控制分两层：`justify-items` / `align-items` 控制网格项在单元格内的对齐（水平/垂直），`justify-content` / `align-content` 控制整个网格在容器内的分布。`place-items: center center` 是两者的简写，让所有网格项在各自单元格内居中。

```xml
<!-- pages/grid/areas.wxml -->
<view class="layout">
  <view class="header">顶部导航</view>
  <view class="aside">侧栏菜单</view>
  <view class="main">主体内容</view>
  <view class="footer">底部栏</view>
</view>
```

```css
/* pages/grid/areas.wxss */
.layout {
  display: grid;
  grid-template-columns: 200rpx 1fr;
  grid-template-rows: 100rpx 1fr 100rpx;
  /* 第一行两格都叫 header；第二行左 aside 右 main；第三行整行 footer */
  grid-template-areas:
    "header header"
    "aside  main"
    "footer footer";
  gap: 16rpx;
  height: 100vh;
}

.header { grid-area: header; background-color: #07c160; }
.aside  { grid-area: aside;  background-color: #f2f3f5; }
.main   { grid-area: main;   background-color: #ffffff; }
.footer { grid-area: footer; background-color: #e8e8e8; }
```

```text
Grid 进阶属性速记：
1. grid-column —— 跨列，grid-column: span 2 跨两列，1 / -1 横跨整行
2. grid-row —— 跨行，grid-row: span 2 跨两行，用于卡片不等高场景
3. grid-template-areas —— 命名区域，同名区域必须构成矩形，空位用 . 占位
4. grid-area —— 子元素声明归属区域，值必须与 areas 中的名称一致
5. justify-items —— 网格项在单元格内水平对齐（start/center/end/stretch）
6. align-items —— 网格项在单元格内垂直对齐，place-items 是两者简写
7. justify-content/align-content —— 整个网格在容器内的分布（用于总尺寸小于容器时）
```

## 栅格系统与经典页面布局

栅格系统（Grid System）源自 Bootstrap 的 12 栅格思想：把一行等分为 12 列，内容按 2/3/4/6/12 列宽度组合。在小程序里用 grid 实现栅格比 flex 更简洁——只需 `repeat(12, 1fr)` 定义 12 列，再为每种跨度写一个类即可。栅格适合后台管理页、表单布局、数据看板等对比例敏感的场景。

经典页面布局指电商、内容类小程序反复出现的页面骨架，按层划分：

第一层是「导航栏 + 内容区 + tabBar」。原生 tabBar 在 app.json 中配置（2-5 个 tab，支持文字与图标），内容区是页面主体；需要自定义导航栏时设置 `"navigationStyle": "custom"`，用 `wx.getMenuButtonBoundingClientRect()` 获取胶囊按钮位置做避让。第二层是内容区内部的经典形态：九宫格入口（金刚区）、卡片流、瀑布流。

九宫格入口是首页最常见的形态：图标 + 文字的组合入口，grid 三列或四列排布，点击通过 `data-*` 携带标识跳转。卡片流是电商列表的核心形态：双列商品卡（图 + 标题 + 价格），grid 两列 + gap 即完成。瀑布流是内容社区形态：两列不等高卡片，WebView 渲染可用 CSS 多列 `column-count`，或采用「左右两个列容器 + JS 分列」方案保证各端一致。

```json
// app.json —— 原生 tabBar 配置
{
  "pages": [
    "pages/index/index",
    "pages/category/category",
    "pages/cart/cart",
    "pages/mine/mine"
  ],
  "tabBar": {
    "color": "#999999",
    "selectedColor": "#07c160",
    "backgroundColor": "#ffffff",
    "borderStyle": "black",
    "list": [
      { "pagePath": "pages/index/index", "text": "首页" },
      { "pagePath": "pages/category/category", "text": "分类" },
      { "pagePath": "pages/cart/cart", "text": "购物车" },
      { "pagePath": "pages/mine/mine", "text": "我的" }
    ]
  }
}
```

```xml
<!-- pages/grid/nine.wxml —— 九宫格入口 -->
<view class="grid-nav">
  <view
    class="nav-item"
    wx:for="{{navs}}"
    wx:key="id"

  >
    <image class="nav-icon" src="{{item.icon}}" mode="aspectFit" />

```

```css

  border-radius: 20rpx;
}

.nav-item {
  display: flex;
  flex-direction: column;
  align-items: center;
  padding: 20rpx 0;

```

```text
经典页面布局清单：
1. 导航栏 —— 原生导航栏由页面 json 配置；自定义导航栏需用 getMenuButtonBoundingClientRect 避让胶囊
2. tabBar —— app.json 配置 2-5 个 tab，list 内 pagePath 必须在 pages 中注册
3. 九宫格 —— repeat(3/4, 1fr) 网格 + 图标文字，data-id 携带跳转参数
4. 卡片流 —— 双列商品卡 repeat(2, 1fr)，卡内纵向 flex 排列图/标题/价格
5. 瀑布流 —— 方案 A 用 column-count: 2 + break-inside: avoid；方案 B 用左右双列容器 JS 分列
6. 栅格系统 —— repeat(12, 1fr) + span 类实现 col-3/col-4/col-6/col-12
```

## 响应式适配方案

小程序天然以 rpx 做尺寸适配：任何屏幕宽度都按 750rpx 换算，`750rpx = 屏幕宽度`，因此 grid 轨道用 rpx 即可随屏幕等比缩放。但 rpx 是「等比放大」而非「按断点重排」：在大屏（iPad、折叠屏）上所有元素会被放大，视觉密度失衡，此时需要媒体查询配合。

`@media (min-width: 768px)` 等媒体查询在 WXSS 中可用，注意媒体查询内使用 px 单位（rpx 在媒体查询判定中不适用），用 px 覆盖 rpx 尺寸，实现「手机端 rpx 流式布局，平板端固定宽度居中」的经典降级。另一个响应式利器是 `repeat(auto-fill, minmax(320rpx, 1fr))`：minmax 让轨道在最小 320rpx 与弹性 1fr 之间伸缩，容器变宽时自动增加列数，无需媒体查询即可实现卡片数自适应。

实际页面中 flex 与 grid 组合使用：页面纵向骨架（导航/内容/底部）用 flex 列排布，内容区内部的网格用 grid；单行横向排列（标签栏、操作栏）用 flex，多行网格（九宫格、卡片墙）用 grid。rpx 负责等比尺寸，媒体查询负责断点重排，grid/flex 负责结构，三者组合覆盖全部适配场景。

```css
/* 响应式双列卡片流：窄屏 2 列，宽屏自动增加列数 */
.goods-grid {
  display: grid;
  /* auto-fill 自动填充轨道，minmax 保证最小 320rpx，剩余空间按 1fr 弹性分配 */
  grid-template-columns: repeat(auto-fill, minmax(320rpx, 1fr));
  gap: 20rpx;
}

/* 平板及以上：整体内容限宽居中，避免 rpx 等比放大导致元素过大 */
@media (min-width: 768px) {
  .page-wrap {
    width: 1000px;
    margin: 0 auto;
  }
  .goods-grid {
    grid-template-columns: repeat(4, 1fr);
  }
  .nav-text {
    font-size: 14px;   /* 媒体查询内用 px，覆盖 rpx 的等比放大 */
  }
}
```

```text
响应式适配要点：
1. rpx —— 750rpx 等于屏幕宽度，轨道与间距默认用 rpx 等比缩放
2. auto-fill —— repeat(auto-fill, minmax(320rpx, 1fr)) 让列数随容器宽度自动增减
3. minmax —— 轨道最小/最大尺寸区间，与 1fr 组合实现弹性列宽
4. 媒体查询 —— @media (min-width: 768px) 内使用 px 单位覆盖 rpx 放大效果
5. 组合 —— 纵向骨架用 flex、网格内容用 grid、尺寸用 rpx、断点用媒体查询
6. 大屏 —— iPad/折叠屏需额外验证，必要时整体限宽 1000px 居中
```

## 最佳实践与踩坑记录

### 最佳实践

1. 间距统一用 gap 控制，不要用「子元素 margin + 父元素负 margin」的旧方案，避免溢出与间距叠加问题
2. 网格列宽优先写 fr 而非百分比，fr 自动扣除 gap 后的剩余空间，天然不溢出
3. 页面纵向骨架（导航/内容/底部）用 flex column，内容区网格用 grid，单行横排用 flex，按场景选工具而不是只用一种
4. 图片容器固定宽高比（固定高度 + aspectFill，或 aspect-ratio），防止图片加载完成后布局跳动、瀑布流错位
5. 列表渲染的 wx:key 使用数据唯一 id，不用 index，避免增删数据后复用错乱
6. 关键布局不要只看模拟器，真机预览验证 grid 表现（安卓内核差异集中爆发点）
7. 栅格类（col-3/col-6 等）抽成公共样式文件，页面直接引用，避免重复编写
8. 复杂布局先画网格草图（几行几列、谁跨几格）再写代码，减少反复调试

### 踩坑记录

坑 1：低版本安卓 WebView 不支持 grid，真机布局塌陷
结论：grid 在部分旧安卓机型上完全不生效，子元素纵向堆叠成一行。
原因：grid 是 CSS 较新特性，旧版系统 WebView（Chrome 57 以下内核）不支持。
解法：提升最低基础库版本；或对 grid 关键页面用 flex 兜底（flex-wrap 双列方案）；上线前真机矩阵验证。

坑 2：fr 与固定宽度、gap 混用导致内容溢出
结论：grid-template-columns: 300rpx 1fr 1fr 且总宽不够时出现横向溢出或压缩。
原因：固定宽度轨道与 gap 之和超过容器宽度时，fr 轨道被压缩到 0 甚至溢出。
解法：固定轨道用百分比或计算好余量；间距用 gap 统一管理；必要时用 minmax(0, 1fr) 允许 fr 轨道收缩。

坑 3：九宫格点击取不到 data 参数
结论：bindtap 事件里 e.target.dataset.id 为 undefined。
原因：点击落在图标 image 上时，target 是 image 而不是携带 data 的 nav-item。
解法：一律用 e.currentTarget.dataset 取参数；或把 data-* 同时挂在 image 上。

坑 4：瀑布流图片加载后高度变化导致错位
结论：column-count 瀑布流中图片加载完成前高度为 0，加载后卡片全部挤到错误位置。
原因：多列布局按内容高度动态排布，图片异步加载改变高度引起重排。
解法：图片容器固定宽高比（aspect-ratio 或固定高度 + widthFix）；或改用左右双列容器方案，由 JS 按高度均衡分列。

坑 5：column-count 在部分安卓机型不生效
结论：WebView 渲染下 column-count 瀑布流在部分安卓上仍为单列。
原因：多列布局属性在内核实现上兼容性差，且与 overflow 等属性组合时失效。
解法：用「左列 + 右列」两个 flex 容器，JS 侧按卡片高度交替 push 数据；需要 WebView 方案时配合 -webkit-column-count 前缀并真机验证。

坑 6：grid-template-areas 名称写错导致整个布局失效
结论：写 grid-template-areas 后页面布局完全错乱或全堆在左上角。
原因：区域名必须以字母开头，不能以数字开头；同名区域必须是矩形；字符串中每行单元格数量必须与列数一致。
解法：命名用字母开头的小写单词；对照轨道行列数检查字符串；空位用 . 补齐。

坑 7：模拟器正常、真机 grid 错位
结论：开发者工具中布局完美，安卓真机上列数、间距表现不一致。
原因：工具基于 Chromium（V8），真机安卓端 WebView 内核版本落后或为 XWeb 定制内核，grid 支持度与工具不同。
解法：以真机预览为准调试；设置合理的最低基础库；关键页面加 flex 兜底样式。

坑 8：大屏设备 rpx 等比放大导致布局溢出
结论：iPad 或折叠屏上元素被 rpx 放大，双列卡片过大、页面显得空旷甚至溢出。
原因：rpx 按屏幕宽度等比换算，大屏宽度大则一切变大，rpx 是等比缩放而非断点重排。
解法：大屏用 @media (min-width: 768px) 以 px 单位覆盖关键尺寸；整体容器限宽居中；grid 列数改用 repeat(auto-fill, minmax(...)) 自适应。

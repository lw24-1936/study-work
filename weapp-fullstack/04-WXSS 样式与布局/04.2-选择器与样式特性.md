## 概述

选择器决定「样式规则作用到哪些节点」，是 WXSS 的地基。小程序没有 DOM 与浏览器，选择器作用的对象是 WXML 渲染出的组件节点树，官方明确支持 .class、#id、element、element,element、::after、::before 六类基础选择器，后代、子代等组合选择器在实战中广泛使用，但属性选择器与通配符 * 存在兼容性风险。

样式特性则回答「多条规则冲突时谁生效」：优先级按「行内样式 > id > class > 标签」的权重计算，!important 可以强行压过一切；同时部分属性（颜色、字号、行高）会沿节点树向下继承，全局样式 app.wxss 与页面样式、组件样式隔离共同构成完整的样式作用域体系。

```text
选择器与样式特性要点：
1. 基础选择器 —— .class、#id、element、群组、::after、::before
2. 组合选择器 —— 后代、子代 >、相邻 +、通用兄弟 ~（实战可用）
3. 优先级 —— 行内 > id > class > 标签，权重数值化计算
4. !important —— 最高优先级，可压过行内样式，谨慎使用
5. 继承 —— color、font-size、line-height 等属性向下继承
6. 隔离 —— 自定义组件默认样式隔离，页面与全局样式进不去
```

## 基础选择器

class 选择器（.类名）是日常开发使用频率最高的选择器，一个节点可以同时挂多个 class，配合状态类（如 .active）实现样式切换；id 选择器（#id）权重高、唯一性强，适合定位单个节点（selectComponent 定位组件也依赖 id）；标签选择器直接命中组件类型，常用于统一重置（button、input 的默认样式覆盖）。WXML 中同一节点可叠加多个 class，渲染时按 wxss 中书写顺序与优先级综合生效。

```wxml
<!-- pages/index/index.wxml -->
<view class="card active" id="mainCard">
  <text class="title">基础选择器演示</text>
  <text class="badge">NEW</text>
</view>
<button class="btn">默认按钮（标签选择器重置后）</button>
```

```wxss
/* pages/index/index.wxss */
/* class 选择器 */
.card {
  margin: 24rpx;
  padding: 24rpx;
  background: #ffffff;
  border-radius: 16rpx;
}

/* 状态类：与 .card 叠加生效 */
.active {
  border: 2rpx solid #07c160;
}

/* id 选择器：权重高，可覆盖 class 同属性 */
#mainCard {
  box-shadow: 0 8rpx 24rpx rgba(0, 0, 0, 0.08);
}

/* 标签选择器：统一重置 button 默认样式 */
button {
  background: none;
  border-radius: 0;
  padding: 0;
  margin: 0;
  line-height: inherit;
  font-size: inherit;
}

.btn {
  background-color: #07c160;
  color: #ffffff;
  border-radius: 40rpx;
  height: 72rpx;
  line-height: 72rpx;
  text-align: center;
  font-size: 28rpx;
}
```

伪元素 ::after 与 ::before 是基础选择器中最实用的两个：它们不需要额外 WXML 节点，即可为元素追加装饰内容（角标、箭头、分割线、清除浮动）。content 属性必填（可为空字符串），position 定位配合父节点 relative 使用。需要注意伪元素不响应 bindtap 等事件（事件绑定需真实节点），且部分低版本基础库对伪元素动画支持有限。

```wxss
/* 伪元素实战：价格角标 */
.price-tag {
  position: relative;
  display: inline-block;
  padding: 8rpx 24rpx;
  background: #ff5000;
  color: #ffffff;
  border-radius: 8rpx;
  font-size: 28rpx;
}

/* 右上角小三角 */
.price-tag::after {
  content: '';
  position: absolute;
  right: -12rpx;
  top: 0;
  border: 12rpx solid transparent;
  border-left-color: #ff5000;
}
```

```text
基础选择器要点：
1. class —— 最常用，可多类叠加，配合状态类切换样式
2. id —— 唯一节点定位，权重高，selectComponent('#id') 也依赖它
3. 标签 —— 统一重置组件默认样式（button、input 等）
4. ::after/::before —— 免节点装饰：角标、箭头、分割线
5. content —— 伪元素必须声明 content（可为空字符串）
6. 局限 —— 伪元素不响应事件，动画兼容性弱于真实节点
```

## 组合选择器

组合选择器把多个基础选择器组合起来，按节点树关系精确定位。后代选择器（.a .b）选中 .a 内部任意层级的 .b；子代选择器（.a > .b）只选中直接子级；相邻兄弟选择器（.a + .b）选中紧随其后的同级节点；通用兄弟选择器（.a ~ .b）选中其后所有同级节点；群组选择器（.a, .b）把多条规则合并声明。官方文档未将组合选择器列入支持清单，但在现代基础库与主流真机上均可正常工作，使用时应控制层级深度（不超过 3 层），并避免依赖复杂组合，防止低版本基础库兼容问题。

```wxml
<!-- pages/index/index.wxml -->
<view class="list">
  <view class="item">
    <text class="label">名称</text>
    <text class="value">组合选择器</text>
  </view>
  <view class="item">
    <text class="label">类型</text>
    <text class="value">后代/子代/兄弟</text>
  </view>
  <view class="item active">
    <text class="label">状态</text>
    <text class="value">当前选中</text>
  </view>
</view>
```

```wxss
/* pages/index/index.wxss */
/* 后代选择器：.list 内所有 .item */
.list .item {
  padding: 24rpx;
  border-bottom: 1rpx solid #eeeeee;
}

/* 子代选择器：.item 的直接子级 text 才生效 */
.item > .label {
  color: #999999;
  font-size: 26rpx;
}

/* 相邻兄弟：.active 后紧邻的 .value 高亮 */
.active + .value {
  color: #07c160;
}

/* 群组选择器：多个选择器共用一条规则 */
.label,
.value {
  display: block;
  line-height: 1.6;
}
```

组合选择器是「按结构定位」而非「按语义定位」，结构一调整样式就可能失效。可维护性优先的做法：能用单 class 表达就不用组合选择器；列表类结构（item 内部各字段）用「父 class + 子 class」的组合最常用，既清晰又稳定。

```text
组合选择器要点：
1. 后代 .a .b —— 任意层级后代，最常用
2. 子代 .a > .b —— 仅直接子级，结构更精确
3. 兄弟 .a + .b / .a ~ .b —— 同级相邻/全部后续节点
4. 群组 .a, .b —— 合并声明相同规则，减少重复
5. 层级 —— 建议不超过 3 层，深了难维护且易出兼容问题
6. 定位 —— 按结构定位，改 WXML 结构时同步检查组合选择器
```

## 样式优先级与 !important

多条规则命中同一节点同一属性时，由优先级决定谁生效。小程序优先级规则与 CSS 一致，按权重数值比较：行内 style 权重 1000，id 选择器 100，class/伪类/属性选择器 10，标签/伪元素选择器 1。权重只按「选择器里各类的数量」累加，不按出现顺序；权重相同时，后书写的规则覆盖先书写的。!important 声明拥有最高优先级，可以压过行内样式与其他所有规则。

```wxss
/* 优先级计算示例 */
.card { color: #333333; }                    /* 权重 10（1 个 class） */
#mainCard { color: #ff5000; }                /* 权重 100（1 个 id）—— 胜出 */
view.card .title { color: #07c160; }         /* 权重 21（2 class + 1 标签） */
.card .title { color: #000000; }             /* 权重 20，输给上面 21 */

/* 同权重比顺序：后写的覆盖先写的 */
.title { color: #333333; }
.title { color: #666666; }                   /* 同权重，这条生效 */

/* !important：最高优先级，压过行内样式 */
.card { color: #07c160 !important; }
```

```wxml
<!-- 行内样式权重 1000，无 !important 时必赢 -->
<view class="card" style="color: #ff5000;">文字颜色</view>
```

优先级计算题是面试与联调高频考点：比如 .a .b .c（30）与 #d（100）比，id 赢；十个 class（100）与一个 id（100）比，因为权重是各类计数，class 再多也只在 10 的维度累加，仍输给 id（id 是 100 的维度，同维度才比数量）。记住一句话：id 压 class，class 压标签，行内压一切，!important 压行内。

!important 是把双刃剑：它能快速解决「样式覆盖不掉」的燃眉之急，但会破坏正常的优先级层级，导致后续所有覆盖都必须加 !important，形成「谁后写谁加 !important」的恶性循环。正确姿势是优先排查权重与书写顺序，!important 只用于覆盖第三方组件样式等确实无法用权重解决的场景。

```text
优先级规则：
1. 权重 —— 行内 1000 > id 100 > class 10 > 标签 1，累加比较
2. 顺序 —— 权重相同比书写顺序，后写的生效
3. 维度 —— class 数量再多也输给单个 id（不同维度不混算）
4. !important —— 最高优先级，可压过行内样式
5. 滥用 —— 破坏层级，导致后续覆盖全要加 !important
6. 排查 —— 覆盖失败先查权重与顺序，别急着上 !important
```

## 继承与重置

CSS 中部分属性具有继承性：父节点设置了，子节点没有显式声明时自动沿用。可继承属性主要是文本相关：color、font-size、font-family、font-weight、line-height、text-align、visibility、opacity 等；不可继承的主要是盒模型与布局相关：margin、padding、border、width、height、background、position、display、flex 相关属性等。合理利用继承可以大幅减少重复声明，例如在 page 根节点设置全局字体与颜色，所有文本自动继承。

```wxss
/* app.wxss —— 利用继承设置全局文本基调 */
page {
  color: #333333;            /* 页面所有文本默认继承 */
  font-size: 28rpx;
  line-height: 1.6;
  background-color: #f7f7f7; /* background 不继承，但根节点设置同样覆盖全页 */
}
```

```wxml
<!-- 文本颜色/字号未单独声明时，全部继承 page 的设定 -->
<view class="container">
  <text>一级文本（继承）</text>
  <view>
    <text>嵌套文本（继续继承）</text>
  </view>
</view>
```

与继承相对的是重置：小程序没有浏览器默认样式差异，但 button、input、textarea、switch 等表单组件自带微信默认样式，且部分组件（如 button 的默认边框、背景）权重较高，需要主动重置。重置一般集中在 app.wxss：统一 button 的边框圆角背景、input 的默认边框、textarea 的默认 padding。注意 WXSS 不支持通配符 *，重置必须逐标签声明；个别无法用 class 覆盖的组件默认样式，可用 !important 兜底。

```wxss
/* app.wxss —— 组件默认样式重置 */
button {
  padding: 0;
  margin: 0;
  border: none;
  border-radius: 0;
  background: none;
  color: inherit;
  font-size: inherit;
  line-height: inherit;
  text-align: center;
}

button::after {
  border: none;              /* 去掉 button 默认的边框伪元素 */
}

input,
textarea {
  border: none;
  background: transparent;
  padding: 0;
  font-size: inherit;
  color: inherit;
}
```

```text
继承与重置要点：
1. 可继承 —— color、font-size、font-family、line-height、text-align
2. 不可继承 —— margin、padding、border、width、height、background
3. 活用 —— page 根节点设置文本基调，子节点自动继承免重复
4. 重置 —— button/input 等组件默认样式需主动覆盖
5. 无通配符 —— WXSS 不支持 *，重置要逐标签声明
6. 兜底 —— 组件顽固默认样式用 !important 处理
```

## 全局样式与样式隔离

样式作用域分三层：app.wxss 全局样式作用于所有页面（与页面样式同权重时，页面样式后加载所以覆盖全局）；页面 wxss 只作用于当前页面；自定义组件有自己的 wxss，且默认开启样式隔离（styleIsolation: isolated），此时页面样式与 app.wxss 都无法作用于组件内部，组件样式也无法外溢影响页面。隔离机制保证组件样式自包含，是组件库可靠性的基础。

```json
// components/my-card/my-card.json —— 组件样式隔离配置
{
  "component": true,
  "styleIsolation": "isolated"
}
```

styleIsolation 有三种取值：isolated（默认）——组件样式完全隔离，外部样式进不来、组件样式出不去；apply-shared ——页面 wxss 可以影响组件内部，组件 wxss 不影响页面（常用于主题定制场景：页面想统一覆盖组件库颜色）；shared ——双向共享，页面与组件样式互相影响（易产生冲突，谨慎使用）。注意继承属性不受隔离影响：即使 isolated，页面设置的 color、font-size 等可继承属性仍会传入组件内部文本。

```wxml
<!-- pages/index/index.wxml —— 页面使用自定义组件 -->
<my-card title="样式隔离演示" />
<view class="page-tip">页面自身样式正常作用于页面节点</view>
```

```wxss
/* pages/index/index.wxss —— 页面样式 */
.page-tip {
  color: #999999;
  font-size: 26rpx;
}

/* 注意：以下规则对 my-card 组件内部节点无效（isolated 隔离） */
my-card {
  margin: 24rpx;
}
```

```wxss
/* components/my-card/my-card.wxss —— 组件内部样式 */
.card {
  padding: 24rpx;
  background: #ffffff;
  border-radius: 16rpx;
  box-shadow: 0 4rpx 12rpx rgba(0, 0, 0, 0.05);
}

.card-title {
  font-size: 30rpx;
  font-weight: 600;
  color: #333333;
}
```

组件根节点（组件标签本身）可以被页面样式选中并设置外部布局（margin 等），但进入组件内部的样式一律被隔离。若确实需要在组件内部响应外部类，可配置 styleIsolation: 'apply-shared' 或在组件内使用 externalClasses 外部样式类（把组件内部某节点开放给页面传类名，详见 07.1-Component 构造器）。

```text
样式作用域与隔离：
1. app.wxss —— 全局样式，作用于所有页面，做公共基础设置
2. 页面 wxss —— 局部样式，同权重下覆盖全局样式
3. isolated —— 组件默认隔离：外部样式进不去，组件样式出不来
4. apply-shared —— 页面样式可影响组件内部，主题定制常用
5. shared —— 双向共享，冲突风险高，谨慎使用
6. 例外 —— 继承属性（color、字号）不受隔离限制，仍会传入组件
```

## 应用场景实战

### 场景一：列表卡片 + 伪元素角标 + 状态类切换

电商列表页：卡片右下角用 ::after 画价格标签、右上角用状态类切换「售罄/在售」外观，全部用 class 与伪元素实现，不增加额外 WXML 节点。

```wxml
<!-- pages/list/list.wxml -->
<view class="card {{item.soldOut ? 'card-soldout' : ''}}"
      wx:for="{{goodsList}}" wx:key="id">
  <image class="card-img" src="{{item.image}}" mode="aspectFill" />
  <view class="card-body">
    <text class="card-name">{{item.name}}</text>
    <text class="card-price">¥{{item.price}}</text>
  </view>
</view>
```

```wxss
/* pages/list/list.wxss */
.card {
  position: relative;
  margin: 24rpx 32rpx;
  background: #ffffff;
  border-radius: 16rpx;
  overflow: hidden;
}

/* 伪元素：右下角价格角标 */
.card::after {
  content: '促销';
  position: absolute;
  right: 0;
  bottom: 0;
  background: #ff5000;
  color: #ffffff;
  font-size: 20rpx;
  padding: 6rpx 16rpx;
  border-radius: 16rpx 0 12rpx 0;
}

/* 状态类：售罄置灰 */
.card-soldout {
  opacity: 0.6;
}

.card-soldout .card-name {
  color: #999999;
}

.card-img {
  width: 100%;
  height: 320rpx;
}

.card-body {
  padding: 20rpx 24rpx 32rpx;
}

.card-name {
  display: block;
  font-size: 30rpx;
  color: #333333;
}

.card-price {
  display: block;
  margin-top: 8rpx;
  font-size: 36rpx;
  color: #ff5000;
}
```

要点：角标用 ::after 省掉一个 view 节点；售罄用状态类切换整卡外观，数据驱动（soldOut 布尔）而非行内样式硬编码。

### 场景二：主题定制 —— apply-shared 让页面样式进入组件库

页面想统一覆盖组件库的主题色（例如把默认蓝色按钮改成品牌绿）。组件库保持 isolated 时页面无法覆盖内部样式，将组件配置为 apply-shared 后，页面 wxss 中的规则即可进入组件内部生效，同时组件样式仍不外溢，兼顾定制与隔离。

```json
// components/base-button/base-button.json
{
  "component": true,
  "styleIsolation": "apply-shared"
}
```

```wxml
<!-- pages/theme/theme.wxml -->
<base-button title="品牌绿按钮" />
<base-button title="危险操作" custom-class="btn-danger" />
```

```wxss
/* components/base-button/base-button.wxss —— 组件默认样式 */
.btn {
  height: 80rpx;
  line-height: 80rpx;
  border-radius: 40rpx;
  background-color: #1989fa;   /* 组件库默认蓝色 */
  color: #ffffff;
  text-align: center;
  font-size: 30rpx;
}
```

```wxss
/* pages/theme/theme.wxss —— apply-shared 下可覆盖组件内部样式 */
/* 同权重、后加载，覆盖组件默认蓝色 */
.btn {
  background-color: #07c160;
}

/* 危险操作：页面额外注入的状态类同样生效 */
.btn-danger {
  background-color: #e64340;
}
```

要点：apply-shared 只允许「页面 → 组件」单向流入，组件样式不外溢，可控性比 shared 好得多；组件内部若用更高权重（id/!important）声明，页面仍覆盖不掉，组件设计时应避免在内部使用 !important。

## 最佳实践与踩坑记录

### 最佳实践

1. 样式一律用 class 驱动，少用 id 选择器（权重高、复用性差），标签选择器只用于统一重置
2. 选择器层级控制在 3 层以内，组合选择器跟着 WXML 结构走，结构变动同步排查样式
3. 状态样式用独立状态类（.active、.soldout）叠加在基础类上，数据驱动切换
4. 全局文本基调（颜色、字号、行高）设在 page 根节点，利用继承减少重复声明
5. 组件默认样式重置集中放 app.wxss，button::after 边框等顽固样式单独处理
6. 组件库样式隔离保持 isolated，需要主题定制的组件再单独开 apply-shared
7. 不使用通配符 * 与属性选择器，兼容性由 class 体系保证
8. 覆盖失败先查权重与书写顺序，最后才考虑 !important，且加注释说明原因

### 踩坑记录

```text
坑 1：页面 wxss 选择不到自定义组件内部元素
结论：.card-title { color: red } 写在页面里，组件内部标题颜色不变。
原因：自定义组件默认 styleIsolation: isolated，页面样式被隔离在组件外。
解法：样式写进组件自己的 wxss；确需外部定制的组件开 apply-shared 或用 externalClasses。

坑 2：app.wxss 对组件内部完全不生效
结论：app.wxss 里设了全局 button 样式，自定义组件里的 button 还是默认外观。
原因：isolated 隔离下全局样式同样进不了组件内部。
解法：组件内部自带样式；需要全局影响的组件显式配置 styleIsolation。

坑 3：class 写得再多也盖不过一个 id 或行内样式
结论：.card .title .text { color: red } 覆盖不了 <text style="color: blue">。
原因：优先级分维度计算，class 数量再多也只是 10 的维度，行内 1000 直接碾压。
解法：覆盖行内样式只能靠 !important；或改造模板，动态值改走 class 切换。

坑 4：button 默认边框和背景死活去不掉
结论：button { border: none; background: none } 写了，真机上还有灰边。
原因：button 的边框来自 ::after 伪元素，背景是组件默认样式，权重高于普通 class。
解法：额外写 button::after { border: none; }，并在 app.wxss 统一重置 button。

坑 5：通配符 * 重置静默失效
结论：* { box-sizing: border-box } 写进 app.wxss，页面盒模型没任何变化。
原因：WXSS 不支持通配符选择器，该规则被忽略且不报错。
解法：逐标签声明 view, text, image, button, input { box-sizing: border-box; }。

坑 6：属性选择器在部分真机上不生效
结论：[data-type="hot"] { color: red } 模拟器正常，某安卓真机上样式丢失。
原因：属性选择器不在官方支持清单内，低版本基础库/部分内核不支持。
解法：改用 class（.type-hot）承载该状态，别依赖属性选择器。

坑 7：继承属性导致组件内部文本颜色「莫名」被外部影响
结论：页面设置了 color: #999，isolated 组件内部没写颜色的文本也变灰了。
原因：color、font-size 等可继承属性不受样式隔离限制，会穿透进入组件。
解法：组件内部文本显式声明颜色与字号，不依赖默认继承。

坑 8：!important 用多后新样式再也覆盖不掉
结论：组件库样式带 !important，页面想改颜色，加 !important 也不行。
原因：同为 !important 时比权重与顺序，组件内部选择器权重更高则页面仍输。
解法：优先提升选择器权重（多写一层父级 class）对抗；确实无解时用外部样式类机制。
```

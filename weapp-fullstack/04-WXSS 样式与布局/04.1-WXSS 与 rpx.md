## 概述

WXSS（WeChat Style Sheets）是小程序的样式语言，语法与 CSS 高度一致，任何会写 CSS 的开发者都能零成本上手。在此基础上 WXSS 做了两处关键扩展：一是新增了 rpx 响应式尺寸单位，让一套样式代码在不同屏幕宽度的设备上自动等比缩放；二是支持 @import 导入外部样式文件，配合 app.wxss 全局样式实现样式复用。

掌握 WXSS 的核心是理解「rpx 如何工作」与「样式从哪来」：rpx 以 750 为基准宽度做等比换算，解决多机型适配；样式则按 app.wxss 全局、页面 wxss 局部、@import 导入、行内 style 四个来源分层生效，优先级层层递进。

```text
WXSS 核心要点：
1. 语法 —— 与 CSS 一致，支持选择器、盒模型、Flex、Grid 等大部分特性
2. rpx —— 响应式单位，750rpx 恒等于屏幕宽度，自动等比适配
3. 换算 —— px = rpx / 750 × 屏幕宽度，设计稿 750 宽可 1:1 标注
4. @import —— 导入公共样式文件，只能放文件顶部，相对路径
5. 分层 —— app.wxss 全局、页面 wxss 局部、行内 style 优先级最高
6. 局限 —— 通配符 * 无效、部分选择器与属性在低版本基础库不支持
```

## WXSS 与 CSS 的关系

WXSS 不是一门新语言，而是 CSS 的扩展子集：选择器（class、id、标签、伪元素）、盒模型（margin、padding、border）、布局（flex、grid）、字体、颜色、过渡动画等 CSS 能力在 WXSS 中都能正常使用。开发者可以用写 CSS 的方式写 WXSS，且因为小程序没有浏览器，天然绕开了浏览器默认样式差异问题（不用写 CSS Reset 兼容不同浏览器）。

WXSS 相比 CSS 的差异主要在三点。第一，新增 rpx 单位（下一节详解）；第二，支持 @import 导入（语法与 CSS 一致但用途更广泛，常用于导入公共样式）；第三，选择器支持范围受限，官方文档明确列出的选择器包括 .class、#id、element、element,element（群组）、::after、::before 六类，后代选择器、子选择器等在实际开发中可用，但属性选择器、通配符 * 等存在兼容性风险，不推荐依赖。

```wxss
/* pages/index/index.wxss —— 与 CSS 几乎一致的写法 */
.page {
  background-color: #f5f5f5;
  min-height: 100vh;
}

.card {
  margin: 20rpx;
  padding: 24rpx;
  border-radius: 16rpx;
  background: #ffffff;
  box-shadow: 0 4rpx 12rpx rgba(0, 0, 0, 0.05);
}

.card::after {
  /* 伪元素：右下角角标 */
  content: 'NEW';
  position: absolute;
  top: 0;
  right: 0;
  background: #ff6600;
  color: #ffffff;
  font-size: 20rpx;
  padding: 4rpx 12rpx;
  border-radius: 0 16rpx 0 12rpx;
}
```

需要注意，小程序没有 DOM 概念，WXSS 的「标签选择器」选择的是 WXML 中的组件标签（view、text、image、button 等），而不是 HTML 标签；同样没有浏览器默认样式，view 默认无内边距无边框，button、input 等表单组件则有微信自带的默认样式，需要自定义时通过 class 覆盖。

```text
WXSS 与 CSS 的关系：
1. 超集 —— 大部分 CSS 语法与属性直接可用，无需学习成本
2. rpx —— 独有的响应式单位，CSS 没有，是小程序适配的核心
3. @import —— 官方支持的样式导入语法，CSS 中同样存在
4. 选择器 —— 官方明确支持 6 类基础选择器，复杂选择器慎用
5. 无浏览器 —— 没有默认样式差异，不必写浏览器兼容 Reset
6. 组件样式 —— button、input 等组件自带默认样式，需主动覆盖
```

## rpx 尺寸单位与适配原理

rpx（responsive pixel，响应式像素）是小程序独有的尺寸单位。它规定：屏幕宽度在任何设备上都是 750rpx。也就是说，无论手机屏幕物理宽度是 320px、375px 还是 414px，都被等分为 750 份 rpx，1rpx 的实际像素值随设备宽度动态变化。换算公式为 px = rpx / 750 × 屏幕宽度(px)。

例如 iPhone 6/7/8 屏幕宽 375px 时，1rpx = 0.5px，750rpx = 375px 正好铺满屏宽；iPhone 12 宽 390px 时，1rpx ≈ 0.52px；iPad 宽 768px 时，1rpx ≈ 1.024px。开发者工具中可在「模拟器 - 机型选择」切换不同设备观察 rpx 的自动换算效果。

```js
// utils/rpx.js —— rpx 与 px 互转工具（需要时在逻辑层使用）
function rpx2px(rpx) {
  const windowWidth = wx.getWindowInfo ? wx.getWindowInfo().windowWidth
    : wx.getSystemInfoSync().windowWidth;
  return rpx / 750 * windowWidth;
}

function px2rpx(px) {
  const windowWidth = wx.getWindowInfo ? wx.getWindowInfo().windowWidth
    : wx.getSystemInfoSync().windowWidth;
  return px * 750 / windowWidth;
}

module.exports = { rpx2px, px2rpx };
```

适配原理的本质：设计稿通常按 750 宽出图，标注的 px 数值直接写成 rpx 即可 1:1 使用（750 设计稿 1px = 1rpx）。页面里所有尺寸用 rpx 声明后，微信渲染层按「当前设备宽度 / 750」的比例缩放，从而实现一套代码在 320px 小屏到 414px 大屏上的等比适配。

使用 rpx 有两点需要留意。其一，rpx 是按屏幕宽度等比缩放，不是按物理像素精细适配，在 iPad 等宽屏设备上元素会被放大很多，通常需要配合 max-width 限制内容区最大宽度；其二，rpx 换算结果会四舍五入到物理像素，极小尺寸（如 1rpx 边框）在不同设备上可能出现粗细不均，1px 细线建议直接用 px 声明。

```text
rpx 换算与适配原理：
1. 基准 —— 任何设备屏幕宽都等于 750rpx，与物理像素无关
2. 公式 —— px = rpx / 750 × 屏宽，设计稿 750 宽 1:1 标注
3. 示例 —— 375px 屏：1rpx = 0.5px；768px 屏：1rpx ≈ 1.024px
4. 适配 —— 等比缩放实现多机型适配，一套代码处处可用
5. 大屏 —— iPad 等宽屏会等比放大，用 max-width 限制内容宽度
6. 边界 —— 1rpx 级细线会四舍五入不均，1px 边框直接用 px
```

## 样式导入与全局样式

WXSS 支持 @import 导入其他样式文件，语法为 @import "路径";。被导入的文件通常是与页面无关的公共样式（变量、工具类、组件样式），放在项目任意位置，通过相对路径引用。@import 必须写在样式文件的最顶部（其他规则之前），否则会被忽略；导入路径不能是网络 URL，必须是项目内的相对路径。

```wxss
/* styles/common.wxss —— 公共样式文件 */
.page-container {
  padding: 24rpx;
  box-sizing: border-box;
}

.flex-center {
  display: flex;
  align-items: center;
  justify-content: center;
}

.text-ellipsis {
  overflow: hidden;
  white-space: nowrap;
  text-overflow: ellipsis;
}
```

```wxss
/* pages/index/index.wxss —— 页面样式文件顶部导入 */
@import "../../styles/common.wxss";

/* 导入后即可使用 common.wxss 中的类 */
.banner {
  height: 320rpx;
  border-radius: 16rpx;
}
```

全局样式方面，小程序有三层来源：app.wxss 是全局样式，作用于所有页面（组件样式隔离时会受限，见 04.2 章节）；每个页面的 wxss 只作用于当前页面；@import 导入的样式属于「引入它的文件」的作用域。同名选择器发生冲突时，页面 wxss 的规则优先级高于 app.wxss 中同权重的规则（后加载覆盖先加载，页面样式在全局样式之后生效）。

```wxss
/* app.wxss —— 全局样式：公共基础设置 */
page {
  background-color: #f7f7f7;
  color: #333333;
  font-size: 28rpx;
  font-family: -apple-system, BlinkMacSystemFont, "Helvetica Neue", sans-serif;
}

/* 全局统一重置表单类组件默认样式 */
button {
  border-radius: 0;
  background: none;
  padding: 0;
  margin: 0;
  line-height: inherit;
}
```

```text
样式导入与全局样式：
1. @import —— 语法 @import "相对路径";，必须位于文件最顶部
2. 限制 —— 只支持项目内相对路径，不支持网络 URL 与变量拼接
3. app.wxss —— 全局样式，作用于所有页面，适合公共基础设置
4. 页面 wxss —— 局部样式，只作用于当前页面，覆盖全局同权规则
5. 复用 —— 公共类抽到 common.wxss，各页面 @import 复用
6. 组件 —— 自定义组件默认样式隔离，app.wxss 对其不生效（04.2 详述）
```

## 行内样式与优先级

WXSS 同样支持在 WXML 标签上用 style 属性写行内样式，并且支持 {{ }} 动态绑定，这是实现「样式随数据变化」的最直接方式。行内样式的优先级高于所有选择器规则（class、id、标签），只有 !important 能覆盖它。因此正确的分工是：静态样式一律写进 wxss class，动态变化的样式（宽度、位移、颜色、显示隐藏）用行内 style 绑定。

```wxml
<!-- pages/index/index.wxml —— 行内样式动态绑定 -->
<view class="progress-bar">
  <!-- 动态宽度用行内 style，静态外观用 class -->
  <view class="progress-inner" style="width: {{progress}}%; background-color: {{barColor}};"></view>
</view>

<!-- 动态显隐：wx:if 优先于 style 控制 -->
<view style="color: {{isVip ? '#ff6600' : '#999999'}};">会员专享价 ¥{{price}}</view>
```

```wxss
/* pages/index/index.wxss —— 静态样式放 class */
.progress-bar {
  height: 16rpx;
  border-radius: 8rpx;
  background-color: #eeeeee;
  overflow: hidden;
}

.progress-inner {
  height: 100%;
  border-radius: 8rpx;
  transition: width 0.3s ease;
}
```

```js
// pages/index/index.js —— 数据驱动样式
Page({
  data: {
    progress: 30,
    barColor: '#07c160',
    isVip: true,
    price: 99
  }
});
```

优先级顺序（从低到高）：标签选择器 < class 选择器 < id 选择器 < 行内 style（!important 例外，详情见 04.2 的优先级计算）。行内样式虽然优先级最高，但不可复用、难以维护、且每次 setData 更新都会重新解析，所以只用于「必须由数据驱动」的少量动态属性。能用 wxss 类 + 状态切换（如 .active 类）表达的交互，优先用类切换而非行内样式。

```text
行内样式与优先级：
1. 动态绑定 —— style="width: {{progress}}%" 支持插值，随数据更新
2. 优先级 —— 行内 style 高于 id/class/标签选择器，仅 !important 可压过
3. 分工 —— 静态样式写 class，动态属性用行内 style，各司其职
4. 性能 —— 行内样式不可复用且随 setData 反复解析，少用
5. 替代 —— 状态切换优先用 class（.active 类），可读性更好
6. 边界 —— 行内样式无法做伪元素（::after 等）与媒体查询
```

## 应用场景实战

### 场景一：750 设计稿商品卡片，一套样式适配所有机型

UI 按 750 宽设计稿出图，卡片宽 686rpx（左右各留 32rpx 边距）、图片 300rpx 见方、价格 32rpx 字号。全部尺寸按设计稿标注直接写 rpx，在 iPhone SE（320px 宽）与 iPhone 15 Pro Max（430px 宽）上等比缩放，视觉比例一致。

```wxml
<!-- pages/goods/goods.wxml -->
<view class="goods-card">
  <image class="goods-img" src="{{goods.image}}" mode="aspectFill" />
  <view class="goods-info">
    <text class="goods-name">{{goods.name}}</text>
    <view class="goods-bottom">
      <text class="goods-price">¥{{goods.price}}</text>
      <text class="goods-sales">已售 {{goods.sales}} 件</text>
    </view>
  </view>
</view>
```

```wxss
/* pages/goods/goods.wxss —— 所有尺寸均为设计稿标注值，直接写 rpx */
.goods-card {
  display: flex;
  margin: 32rpx 32rpx 0;        /* 左右留白与设计稿一致 */
  padding: 24rpx;
  background: #ffffff;
  border-radius: 16rpx;
}

.goods-img {
  width: 300rpx;
  height: 300rpx;
  border-radius: 12rpx;
  flex-shrink: 0;
}

.goods-info {
  flex: 1;
  margin-left: 24rpx;
  display: flex;
  flex-direction: column;
  justify-content: space-between;
}

.goods-name {
  font-size: 30rpx;             /* 标题 30rpx */
  color: #333333;

  display: -webkit-box;
  -webkit-box-orient: vertical;
```

验证方式：开发者工具模拟器切换 iPhone SE、iPhone 15、iPad 机型，卡片视觉比例不变，仅整体缩放。iPad 上若觉得卡片过大，给 .goods-card 加 max-width: 700px 并 margin: 0 auto 居中限制。

### 场景二：@import 公共样式 + 行内样式实现主题切换

把通用工具类抽到 common.wxss 用 @import 引入；主题色这类「随配置变化」的值用行内 style 绑定，实现一套代码切换不同皮肤（配合 04.5 暗黑模式章节可升级为完整主题方案）。

```wxss
/* styles/common.wxss —— 公共工具类 */
.row {
  display: flex;
  align-items: center;
}

.row-between {
  display: flex;
  align-items: center;
  justify-content: space-between;
}

.col {
  display: flex;
  flex-direction: column;
}

.ellipsis {
  overflow: hidden;
  white-space: nowrap;
  text-overflow: ellipsis;
}
```

```wxml
<!-- pages/theme/theme.wxml -->
<!-- 引入的公共类负责布局，行内样式绑定主题色 -->
<view class="row-between nav-bar" style="background-color: {{theme.navBg}};">
  <text style="color: {{theme.navText}};">{{title}}</text>
  <text class="ellipsis" style="color: {{theme.subText}};">{{subtitle}}</text>
</view>

<view class="row card">
  <view class="col card-left">
    <text style="color: {{theme.primary}};">主要指标</text>
    <text style="color: {{theme.text}};">{{value}}</text>
  </view>
  <button style="background-color: {{theme.primary}}; color: #ffffff;">立即购买</button>
</view>
```

```js
// pages/theme/theme.js
Page({
  data: {
    title: '主题演示',
    subtitle: 'Theme Demo',
    value: '88%',
    // 主题配置：切换这套对象即可换肤

      navBg: '#07c160',
      navText: '#ffffff',
      subText: '#e8f8ef',
      primary: '#07c160',
      text: '#333333'
    }
  },

  switchTheme() {
    this.setData({
      theme: {
        navBg: '#ff6600',
        navText: '#ffffff',
        subText: '#fff3e6',
        primary: '#ff6600',
        text: '#333333'
      }
    });
  }
});
```

```wxss
/* pages/theme/theme.wxss —— 静态布局样式 */
.nav-bar {
  height: 88rpx;
  padding: 0 32rpx;
}

.card {
  margin: 32rpx;
  padding: 24rpx;
  background: #ffffff;
  border-radius: 16rpx;
  justify-content: space-between;
}

.card-left {
  flex: 1;
}

.card button {
  margin-left: 24rpx;
  border-radius: 40rpx;
  font-size: 26rpx;
  padding: 0 32rpx;
  height: 64rpx;
  line-height: 64rpx;

```

要点：布局类（间距、排列、圆角）全部沉淀为公共类复用；颜色等「主题变量」通过行内 style 从 JS 数据注入，切换主题只改 data，不动 wxss。

## 最佳实践与踩坑记录

### 最佳实践

1. 设计稿统一按 750 宽出图，标注值直接写 rpx，1px = 1rpx，减少换算出错
2. 静态样式一律写 wxss class，只有数据驱动的动态属性才用行内 style
3. 公共工具类（flex 布局、文本截断、间距）抽到 styles/common.wxss，页面 @import 复用
4. app.wxss 只放全局基础设置（page 背景、字体、颜色、组件默认样式重置），不放业务样式
5. 1px 细线边框（分割线、描边）用 px 声明，避免 rpx 四舍五入导致粗细不均
6. 大屏设备（iPad）用 max-width 限制内容区宽度，防止 rpx 等比放大过度
7. 字号体系统一规范（如 24/26/28/30/32rpx 五档），不要随手写任意值
8. 每写一个页面先检查：能用公共类吗？能用 class 切换吗？行内样式越少越好

### 踩坑记录

```text
坑 1：@import 写在了其他样式规则后面，导入不生效
结论：文件顶部 @import 正常，放到中间或末尾后公共类全部失效。
原因：CSS/WXSS 规范要求 @import 必须位于所有规则之前，否则整条被忽略。
解法：@import 统一放 wxss 文件第一行；多个导入按依赖顺序排列。

坑 2：WXSS 里写通配符 * 重置样式完全无效
结论：* { box-sizing: border-box; } 写在 app.wxss，页面盒模型没变化。
原因：WXSS 不支持通配符选择器，官方支持列表中没有 *。
解法：改为逐个声明 view, text, image, button, input, textarea { box-sizing: border-box; }。

坑 3：rpx 在 iPad 上被放得过大
结论：手机上比例正常的页面在 iPad 上元素巨大，布局错乱。
原因：rpx 按屏幕宽度等比缩放，iPad 宽度近 768px，是手机的 2 倍。
解法：容器加 max-width: 700px 并居中；或对平板做媒体查询单独降级。

坑 4：1rpx 边框真机上时有时无、粗细不均
结论：模拟器看着正常的 1rpx 边框，部分安卓机显示 0 或变粗。
原因：rpx 换算后四舍五入到物理像素，不同设备像素比下舍入结果不同。
解法：1px 细线直接用 px 声明；或用 transform: scale(0.5) 实现半像素线。

坑 5：模拟器切换机型后 rpx 布局「没变化」
结论：切换机型预览，卡片尺寸看起来几乎一样，以为 rpx 没生效。
原因：开发者工具窗口缩放会整体缩放渲染，视觉上掩盖了 rpx 换算差异。
解法：用「真机调试/预览」验证；或对比 iPad 与 iPhone 查看明显差异。

坑 6：行内样式写错优先级，覆盖不掉微信组件默认样式
结论：给 button 写了 class 设置 background 透明，真机上还是绿色默认样式。
原因：部分组件（button、switch 等）默认样式权重较高或带了内部样式。
解法：先重置组件默认样式（app.wxss 中统一重置 button 等），再用 class 覆盖；必要时用行内 style。

坑 7：@import 路径写错，编译报「文件不存在」
结论：页面样式文件 @import 相对路径算错一层，工具直接编译失败。
原因：@import 相对路径以「当前 wxss 文件所在目录」为基准，多写少写 ../ 都会报错。
解法：路径从当前文件出发逐层数；养成用 ../ 返回上级再进入 styles 目录的固定写法。

坑 8：rpx 与 px 混用导致元素对不齐
结论：列表项高度用 rpx，分隔线用 px，真机上线条位置偏离。
原因：rpx 随屏宽缩放而 px 固定，混用后相对位置在不同机型漂移。
解法：同一组件/同一行内元素统一单位；布局尺寸全 rpx，仅 1px 细线类例外。
```

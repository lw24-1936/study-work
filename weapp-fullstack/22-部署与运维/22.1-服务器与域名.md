## 概述

小程序前端运行在微信客户端内，但它的业务数据全部来自自有后台（SpringBoot 服务）。要让小程序能通过 wx.request 访问后台接口，就必须有一台公网可达的服务器、一个备案过的域名、一条正确的 DNS 解析，以及一张合法的 HTTPS 证书（微信要求所有 request 请求域名必须为 HTTPS 且已在小程序后台配置为合法域名）。本章从零开始梳理这条上线链路：服务器怎么选、域名怎么备案和解析、证书怎么申请和续期、安全组怎么配，覆盖「买机器 → 绑域名 → 上 HTTPS → 开端口」的完整流程。

```text
上线前的硬性条件：
1. 一台公网服务器 —— 阿里云/腾讯云/华为云等，大陆地域需要备案
2. 一个已备案域名 —— 大陆服务器解析域名前必须完成 ICP 备案
3. HTTPS 证书 —— 微信小程序 request 合法域名强制要求 HTTPS
4. DNS 解析 —— A 记录指向服务器 IP，生效后才能访问
5. 安全组放行 —— 云平台安全组必须开放 80/443/22 端口
6. 微信后台配置 —— request 合法域名填入 https://api.你的域名.com
```

## 服务器选型

服务器是小程序后台的运行载体。选型主要看四个维度：厂商、配置、地域、操作系统。

国内主流云厂商是阿里云、腾讯云、华为云，三者产品形态基本一致（ECS/CVM/ECS），新用户都有低价促销（轻量应用服务器通常更便宜，适合起步）。地域选择上，大陆地域（北京、上海、杭州、深圳、广州等）访问快但域名必须备案；香港及海外地域免备案、开箱即用，但跨境链路延迟高（通常 50-150ms），且微信接口回调、支付回调等对大陆机房更友好，生产环境建议直接选大陆地域。

```text
服务器配置参考：
1. 入门（个人学习/低流量）—— 2 核 2G，1M 固定带宽，40G 云盘
2. 标准（正式上线）—— 2 核 4G，3-5M 固定带宽，50G 云盘
3. 进阶（业务增长）—— 4 核 8G，5-10M 带宽或按量计费，SSD 云盘
4. 带宽 —— 1M 约 128KB/s，图片/文件多的业务优先按量计费
5. 系统 —— Ubuntu 22.04 LTS 或 CentOS 7.9（已停止维护，新机器建议 AlmaLinux/Rocky）
6. 登录方式 —— 优先 SSH 密钥登录，关闭密码登录，禁用 root 远程登录
```

操作系统推荐 Ubuntu 22.04 LTS：apt 软件源齐全、Nginx/Java/Docker 安装一条命令搞定、社区资料多。CentOS 7 官方已停止维护（2024-06 EOL），存量 CentOS 7 机器应尽快迁移；新购机器不要再用 CentOS 7。购买后第一件事是初始化环境：

```shell
# Ubuntu 22.04 初始化（以 root 或 sudo 用户执行）
apt update && apt upgrade -y
apt install -y vim curl wget git unzip ufw

# 创建部署用户（不使用 root 跑业务）
adduser deploy
usermod -aG sudo deploy

# 配置 SSH 密钥登录（本地生成公钥后追加到服务器）
mkdir -p /home/deploy/.ssh
echo "ssh-rsa AAAAB3NzaC1yc2E...你的公钥" >> /home/deploy/.ssh/authorized_keys
chown -R deploy:deploy /home/deploy/.ssh
chmod 700 /home/deploy/.ssh
chmod 600 /home/deploy/.ssh/authorized_keys
```

```text
选型要点：
1. 新用户促销价续费贵，购买前确认续费价格，避免迁移成本
2. 生产环境启用 SSH 密钥登录并关闭密码登录（/etc/ssh/sshd_config 中 PasswordAuthentication no）
3. 云盘选 SSD，数据库与日志分开目录，便于扩容与备份
4. 固定带宽适合访问量平稳的业务；突发流量用按量计费带宽
5. 先买低配机器跑通全流程，再按监控数据扩容，避免起步浪费
6. 服务器到期前做好数据备份（快照 + 定期导出数据库）
```

## 域名备案与解析

大陆服务器上架设网站/接口服务，域名必须完成 ICP 备案。备案是工信部对网站主办者实名信息的管理制度，由云厂商代提交（阿里云、腾讯云均有备案系统）。个人备案与企业备案要求不同：个人备案不能经营类内容（不能有交易、支付功能），企业备案需要营业执照。整个流程通常需要 7-20 个工作日，其中管局审核 3-20 个工作日不等。

```text
ICP 备案流程：
1. 准备资料 —— 身份证/营业执照、域名实名认证截图、网站负责人信息
2. 云厂商备案系统提交 —— 填写主体信息、网站信息、上传证件
3. 初审 —— 云厂商 1-2 个工作日核验，不合格会驳回修改
4. 幕布拍照/人脸核验 —— 部分省份需要背景幕布照片或 App 人脸核验
5. 管局审核 —— 提交到通信管理局，一般 3-20 个工作日
6. 备案号下发 —— 通过后需在网站底部展示备案号并链接到工信部网站
```

备案期间域名不能解析到大陆服务器对外提供访问（否则会被拦截/关停），但可以先把机器、代码、证书全部准备好，备案通过后立刻上线。备案还有一个隐含要求：服务器需购买满一定时长（阿里云要求 ECS 包年包月 3 个月以上才能备案），所以「先买服务器再备案」是标准顺序。

域名注册建议与备案同厂（阿里云万网/腾讯云 DNSPod）：域名实名认证、备案、解析、续费在一个控制台完成。域名注册后必须做实名认证（.com 等后缀强制），实名信息要与备案主体一致，否则备案会被驳回。域名到期前 30 天厂商会短信提醒，务必设置自动续费——域名过期被抢注是毁灭性事故，等于线上业务全部作废。

```shell
# 注册域名的基本要求
# 1. 选择注册商：阿里云万网 / 腾讯云 / 西部数码等，价格差异不大
# 2. 后缀选择：优先 .com/.cn，避免小众后缀备案与微信校验受限
# 3. 实名认证：提交身份证/营业执照信息，一般 1-3 个工作日生效
# 4. 开启自动续费并预留续费资金，防止到期断服
# 5. WHOIS 隐私保护：开启后域名注册信息不公开，减少垃圾邮件与钓鱼
whois example.com | grep -E "Expiry|Registrar"
# Registry Expiry Date: 2027-08-20T00:00:00Z
# Registrar: Alibaba Cloud Computing Ltd.
```

域名解析（DNS）是把域名指向服务器 IP 的过程。最常用的是 A 记录（域名 → IPv4 地址）和 CNAME 记录（域名 → 另一个域名别名）。在云厂商的云解析/DNS 控制台添加记录后，全球 DNS 节点会逐步生效，TTL（默认 600 秒）到期后全部生效。

```shell
# 添加 A 记录：api.example.com -> 1.2.3.4
# 在云解析控制台添加：
# 记录类型 A | 主机记录 api | 记录值 1.2.3.4 | TTL 600

# 验证解析是否生效
dig api.example.com +short
# 输出：1.2.3.4

# 或用 nslookup
nslookup api.example.com
# Server:		8.8.8.8
# Address:	8.8.8.8#53
# Name:	api.example.com
# Address: 1.2.3.4

# 查看解析传播情况（不同地区 DNS 是否一致）
dig @114.114.114.114 api.example.com +short
dig @8.8.8.8 api.example.com +short
```

```text
解析要点：
1. A 记录用于域名直连 IPv4；CNAME 用于指向 CDN/负载均衡别名
2. 小程序 request 合法域名不能带端口，所以 Web 服务必须走 80/443
3. 解析修改后本地可能被缓存，用 dig 指定公共 DNS 验证最可靠
4. TTL 设小一点（600 秒）方便上线切换，稳定后再调大
5. 域名需要实名认证（.com/.cn 等均要求），与备案主体一致
6. 多个子域名规划：api.example.com 给后台、admin.example.com 给管理端、www.example.com 给官网
```

## HTTPS 证书

微信小程序强制要求 request 合法域名必须为 HTTPS，且证书不能过期、不能是自签名证书。HTTPS 证书按验证级别分为 DV（域名验证，免费/几十元）、OV（组织验证，几百到上千元）、EV（扩展验证，最贵，浏览器地址栏显示企业名）。个人和小团队用 DV 证书完全够用，验证域名所有权即可签发。

```text
证书类型对比：
1. DV —— 只验证域名所有权，签发快（几分钟），免费，适合小程序后台
2. OV —— 验证企业主体真实性，证书中带企业信息，适合 To B/政务场景
3. EV —— 最高级别，地址栏显示企业名称，银行/金融常用，价格最高
4. 免费证书来源 —— Let's Encrypt（90 天自动续期）、阿里云/腾讯云免费 DV（1 年）
5. 证书内容 —— 私钥 server.key + 证书链 server.pem（含中间证书），两者都要放对位置
```

申请免费证书最主流的方案是 Let's Encrypt + certbot 或 acme.sh。acme.sh 是纯 Shell 脚本，安装简单、自动续期可靠，推荐使用：

```shell
# 安装 acme.sh（Let's Encrypt 免费证书签发工具）
curl https://get.acme.sh | sh -s email=you@example.com

# 设置默认 CA 为 Let's Encrypt
~/.acme.sh/acme.sh --set-default-ca --server letsencrypt

# 签发证书（DNS 方式验证，需要域名解析已在 DNS 服务商配置好 API 密钥）
# 阿里云 DNS 方式：
export Ali_Key="你的AccessKeyId"
export Ali_Secret="你的AccessKeySecret"
~/.acme.sh/acme.sh --issue --dns dns_ali -d api.example.com

# 腾讯云 DNS 方式：
export DP_Id="你的DNSPod ID"
export DP_Key="你的DNSPod Token"
~/.acme.sh/acme.sh --issue --dns dns_dp -d api.example.com

# 安装证书到 Nginx 目录（自动生成 nginx 配置文件片段）
~/.acme.sh/acme.sh --install-cert -d api.example.com \
  --key-file /etc/nginx/ssl/api.example.com.key \
  --fullchain-file /etc/nginx/ssl/api.example.com.pem \
  --reloadcmd "systemctl reload nginx"

# 查看证书有效期
openssl x509 -in /etc/nginx/ssl/api.example.com.pem -noout -dates
# notBefore=Aug 10 00:00:00 2026 GMT
# notAfter=Nov  8 00:00:00 2026 GMT
```

acme.sh 安装后会自动写入 crontab 定时任务，每 60 天检查一次并自动续期，续期后自动执行 reloadcmd 重载 Nginx，全程无需人工干预。也可以不用 acme.sh，直接使用阿里云/腾讯云控制台申请的免费 DV 证书（有效期 1 年），手动下载 pem/key 上传服务器，但每年要手动续期一次。

```text
证书要点：
1. 微信小程序对证书要求严格：证书链完整、域名匹配、不过期
2. 免费证书有效期短（90 天/1 年），必须配置自动续期，过期=线上事故
3. 证书私钥权限设为 600，只允许 root 和 nginx 用户读取
4. 小程序后台配置的合法域名必须与证书域名完全一致（含子域名）
5. 证书到期前 30 天微信后台会提示，但别依赖人工，自动化续期才是正解
6. 测试环境可以用自签名证书，但小程序真机请求会失败，联调必须用正式证书
```

## 安全组与防火墙

云服务器有双层防护：云平台的安全组（网络层，在虚拟化层生效）和操作系统内部的防火墙（ufw/firewalld/iptables）。安全组在流量进入服务器之前过滤，系统防火墙在服务器内部过滤。生产环境建议两层都开启，遵循最小权限原则：只开放业务需要的端口，其他全部拒绝。

```text
必须开放的端口：
1. 22 —— SSH 管理端口（建议限制来源 IP 或改用密钥登录）
2. 80 —— HTTP，用于 301 跳转 HTTPS 和证书验证
3. 443 —— HTTPS，小程序与浏览器访问的主要入口
4. 3306 —— MySQL（生产环境禁止对外开放，仅内网/本机访问）
5. 6379 —— Redis（生产环境禁止对外开放，加密码并绑定 127.0.0.1）
6. 8080/9000 等应用端口 —— 不直接暴露，由 Nginx 反代，或仅内网
```

云平台安全组配置：在控制台「安全组 → 配置规则 → 入方向」添加规则，协议 TCP、端口 22/80/443、授权对象 0.0.0.0/0（或指定 IP）。数据库端口不要在安全组放行，SpringBoot 连本机数据库走内网即可。

```shell
# Ubuntu ufw 防火墙配置
ufw default deny incoming
ufw default allow outgoing
ufw allow 22/tcp
ufw allow 80/tcp
ufw allow 443/tcp
ufw enable
ufw status verbose
# Status: active
# To                         Action      From
# --                         ------      ----
# 22/tcp                     ALLOW       Anywhere
# 80/tcp                     ALLOW       Anywhere
# 443/tcp                    ALLOW       Anywhere

# CentOS/AlmaLinux firewalld 配置
firewall-cmd --permanent --add-service=ssh
firewall-cmd --permanent --add-service=http
firewall-cmd --permanent --add-service=https
firewall-cmd --reload
firewall-cmd --list-all
```

```text
安全组要点：
1. 云平台安全组与系统防火墙是两层，都要配置，别只开一层
2. 数据库端口（3306/6379）永远不要对公网开放，这是被勒索/挖矿攻击的首要入口
3. SSH 端口可以改成高位端口（如 2222）降低被扫描概率，但注意安全组同步放行
4. 安全组规则修改立即生效，配置错误会直接导致线上失联，修改前确认当前会话
5. 用 nmap 从外部扫一遍确认只暴露了 22/80/443：nmap -p- 你的IP
6. 服务器被入侵后的第一动作：快照 + 断网 + 查 /var/log/auth.log 登录记录
```

## 应用场景实战

### 场景一：新购服务器初始化并开放 80/443/22

以阿里云 ECS（Ubuntu 22.04）为例，从购买到可部署应用的完整步骤：

```text
步骤：
1. 控制台购买 ECS：2 核 4G、地域选华东（杭州）、系统 Ubuntu 22.04、40G 高效云盘
2. 设置 root 密码或绑定密钥对，购买后记录公网 IP（如 1.2.3.4）
3. 进入「安全组 → 配置规则 → 入方向」，添加 22/80/443 三条 TCP 规则
4. SSH 登录：ssh root@1.2.3.4
5. 执行系统更新并安装基础工具（apt update && apt install vim curl wget git unzip ufw）
6. 创建 deploy 部署用户并配置 SSH 密钥登录
7. 开启 ufw 防火墙，放行 22/80/443，deny 其他入站
8. 验证：从本地浏览器访问 http://1.2.3.4 应被拒绝（还没装 Web 服务），ssh 正常
9. 用 nmap 从外部确认端口开放情况：nmap -p 22,80,443 1.2.3.4
```

```shell
# 服务器端初始化脚本（节选）
apt update && apt upgrade -y
apt install -y vim curl wget git unzip ufw nginx
systemctl enable --now nginx

# 验证 Nginx 安装成功
curl -I http://127.0.0.1
# HTTP/1.1 200 OK
# Server: nginx/1.18.0 (Ubuntu)

# 本机验证安全组：服务器上 curl 公网 IP 的 80 端口应通
curl -I http://1.2.3.4
# HTTP/1.1 200 OK
```

```text
验收标准：
1. ssh root@IP 能登录（22 通）
2. 浏览器访问 http://IP 出现 Nginx 默认页（80 通）
3. HTTPS 尚未配置，443 暂时不通属于正常
4. 3306/6379 从外网不可达（telnet IP 3306 应超时）
5. 服务器已具备部署 SpringBoot 与 Vue 的环境基础
6. 后续章节（22.2 Nginx、22.3 应用部署）在此机器上继续
```

### 场景二：域名备案、解析与免费 HTTPS 证书全流程

假设已有域名 example.com（已在域名服务商完成实名认证），把它接入小程序后台接口：

```text
步骤：
1. 确认服务器满足备案条件（大陆地域 + 已购买 3 个月以上），在云厂商备案系统提交主体信息
2. 填写网站信息：网站名称（如「XX 小程序服务」）、网站负责人、备案性质（个人/企业）
3. 上传身份证/营业执照，完成人脸核验，提交管局审核（等待 7-20 个工作日）
4. 备案通过后，在云解析控制台添加记录：
   - A 记录：api.example.com -> 服务器公网 IP（TTL 600）
   - A 记录：admin.example.com -> 服务器公网 IP
5. 安装 acme.sh，为 api.example.com 签发 Let's Encrypt 证书（DNS 验证）
6. 证书安装到 /etc/nginx/ssl/，后续 22.2 章配置 Nginx 时引用
7. 登录微信公众平台 -> 开发管理 -> 开发设置 -> 服务器域名，添加 request 合法域名 https://api.example.com
8. 小程序端 wx.request 的 url 改为 https://api.example.com/...，真机预览验证
```

```shell
# 签发并安装证书（腾讯云 DNSPod 验证）
export DP_Id="12345"
export DP_Key="abcdef123456"
~/.acme.sh/acme.sh --issue --dns dns_dp -d api.example.com

~/.acme.sh/acme.sh --install-cert -d api.example.com \
  --key-file /etc/nginx/ssl/api.example.com.key \
  --fullchain-file /etc/nginx/ssl/api.example.com.pem \
  --reloadcmd "systemctl reload nginx"

# 验证证书链完整（微信要求证书链必须完整，否则真机请求报错）
openssl s_client -connect api.example.com:443 -servername api.example.com \
  </dev/null 2>/dev/null | grep -E "subject=|issuer="
# subject=CN = api.example.com
# issuer=CN = R10, O = Let's Encrypt

# 确认解析与证书一致
curl -v https://api.example.com/ 2>&1 | grep "SSL certificate verify ok"
```

验收标准：
1. dig api.example.com +short 输出服务器公网 IP
2. https://api.example.com 浏览器可访问且地址栏有锁标
3. openssl s_client 显示证书 CN 与域名一致、证书链完整
4. 微信后台「服务器域名」已配置且校验通过（保存时平台会验证 HTTPS 可达）

## 最佳实践与踩坑记录

### 最佳实践

1. 起步阶段先用云厂商促销的轻量应用服务器（2 核 2G 约百元/年），跑通全流程后再按需升级，避免一次性买贵
2. 生产环境全部走 HTTPS，80 端口只做 301 跳转；小程序合法域名、证书、Nginx 配置三者域名必须完全一致
3. SSH 一律密钥登录并禁用 root 密码登录，数据库端口永不对外开放，安全组按最小权限配置
4. 域名、服务器、证书放在同一家云厂商，备案、解析、续期管理集中，减少跨厂商协调成本
5. 证书续期必须自动化（acme.sh cron 或云厂商托管证书），并加一个「证书剩余天数」监控告警
6. 上线前把「备案-解析-证书-安全组」的完整操作记录写成文档（含账号、到期时间、续费提醒），防止人走失联
7. 服务器时间必须校准（timedatectl set-timezone Asia/Shanghai），HTTPS 证书校验、日志时间戳都依赖系统时间
8. 小程序后台配置合法域名后，每次接口变更只改解析/Nginx，不需要重新提审小程序（域名白名单变更需重新发布）

### 踩坑记录

```text
坑 1：大陆服务器域名未备案直接解析，被云厂商阻断
结论：未备案域名解析到大陆服务器后，访问会被拦截并提示备案；微信小程序 request 也直接失败。
原因：大陆 ICP 备案是强制要求，云厂商会阻断未备案域名的 80/443 流量。
解法：先备案再解析；急用的话临时用香港/海外服务器过渡，备案通过后再切回大陆。

坑 2：买了海外服务器，小程序接口延迟高且偶尔超时
结论：香港/海外服务器的接口延迟普遍 100ms 以上，小程序端表现为首屏慢、偶发超时。
原因：跨境链路经国际出口，抖动大；微信支付回调、access_token 拉取也依赖大陆机房。
解法：生产环境使用大陆地域服务器；海外服务器只用于免备案的临时演示环境。

坑 3：免费证书到期忘记续期，线上 HTTPS 全部报错
结论：Let's Encrypt 证书 90 天到期，未续期导致小程序请求全部失败、浏览器报警。
原因：证书有效期短，人工续期靠不住，特别是节假日期间。
解法：用 acme.sh 自动续期并配置 reloadcmd；在监控系统加证书到期告警（剩余 15 天告警）。

坑 4：证书链不完整，小程序真机请求报 SSL 错误
结论：浏览器访问正常，但小程序真机请求报「证书无效/SSL handshake failed」。
原因：只部署了域名证书，缺少中间证书（chain），微信客户端校验更严格。
解法：使用 acme.sh 的 fullchain-file（完整证书链）；用 openssl s_client 验证 issuer 链完整。

坑 5：安全组没放行 443，证书配置好后依然无法访问
结论：Nginx 配置全部正确，但 https 访问一直超时。
原因：云平台安全组默认只放行了 22，443 端口被安全组拦截。
解法：检查安全组入方向是否放行 443；安全组与 ufw 是两层，都要放行。

坑 6：域名解析生效慢，排查半天以为服务器挂了
结论：修改解析后本地访问还是旧 IP，误判为服务器故障。
原因：本地 DNS 缓存和运营商递归服务器缓存导致解析未及时更新。
解法：用 dig @8.8.8.8 和 dig @114.114.114.114 指定公共 DNS 验证；解析前把 TTL 调小。

坑 7：小程序后台配置合法域名时提示「域名校验失败」
结论：在微信后台保存 request 合法域名时提示校验失败，保存不了。
原因：微信校验时要求域名已正确解析且 HTTPS 证书有效，且校验下载文件可达或证书链完整。
解法：先确认 dig 解析正确、https 可访问；校验配置的是主域名（可配置带端口），确认 Nginx 对该域名返回 200。

坑 8：使用 .app/.top 等新顶级域名，部分厂商备案或微信校验受限
结论：小众后缀域名在个别云厂商无法备案或微信校验不稳定。
原因：管局对部分新顶级域名备案有限制，微信校验服务对稀有后缀支持不完善。
解法：域名尽量选 .com/.cn 等主流后缀；购买前先确认支持 ICP 备案。
```

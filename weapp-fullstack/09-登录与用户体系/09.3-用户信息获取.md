## 概述

2021 年之前，小程序可以用 wx.getUserInfo 或 wx.getUserProfile 弹一个授权框，用户点同意后一次性拿到头像、昵称、性别等完整资料。2021 年 4 月起微信调整策略：wx.getUserProfile 不再弹出授权框，返回的是匿名头像与「微信用户」默认昵称；2022 年 10 月 25 日起，头像昵称必须改用「头像昵称填写能力」（button open-type=chooseAvatar + input type=nickname），由用户主动选择填写。手机号获取也从「授权 + 加密数据解密」演进为「手机号快速验证组件」（button open-type=getPhoneNumber + code 换手机号）。

这套调整的本质是隐私合规要求：平台不再允许「一次授权拿走全部用户信息」，改为「按需、最小化、用户主动」的信息收集模式。本篇章讲解现行合规的用户信息获取方式：头像昵称填写、手机号快速验证、剩余可用的授权 scope，以及配套的隐私保护指引与隐私协议要求。登录链路（09.1）与 token 会话（09.2）负责「知道用户是谁」，本篇章负责「合规地拿到用户资料」。

```text
用户信息获取核心要点：
1. getUserProfile 已废弃 —— 不再弹授权框，返回匿名数据，请勿再使用
2. 头像昵称填写 —— button chooseAvatar + input nickname，用户主动填写
3. 手机号快速验证 —— button getPhoneNumber + e.detail.code 换手机号
4. scope.userInfo 已废弃 —— 不存在「一次性授权拿全部资料」的弹窗
5. 隐私保护指引 —— 收集任何用户信息前必须在后台声明用途
6. 最小化收集 —— 用户拒绝填写也要能正常使用核心功能
```

## getUserProfile 的废弃与替代

wx.getUserProfile 于 2021 年 4 月 13 日起调整：调用后不再弹出授权弹窗，返回的头像是灰色默认头像，昵称是「微信用户」，gender 恒为 0。2022 年 10 月 25 日之后，头像昵称能力强制切换为「头像昵称填写能力」，getUserProfile 与旧的 getUserInfo 均不再提供真实用户信息。仍在线上运行的旧代码要尽快替换，否则用户资料永远拿不到真实值，且审核时可能被拒。

替代方案是「头像昵称填写能力」：头像通过 button 组件设置 open-type=chooseAvatar，用户点击后弹出微信头像选择面板，chooseavatar 事件返回临时文件路径；昵称通过 input 组件设置 type=nickname，用户输入时微信会唤起昵称联想，blur/input 事件取值。两者都是「用户主动动作」触发，不需要任何授权弹窗，也允许用户拒绝填写。

兼容处理：可以在页面加载时用 wx.canIUse 判断当前基础库是否支持新能力，支持则走填写能力，不支持则提示升级微信版本。注意新旧代码不能混用——不要「先调 getUserProfile 失败再降级」，直接整体迁移到填写能力即可。

```js
// 兼容判断示例：检测基础库是否支持头像昵称填写能力
Page({
  onLoad() {
    const supportAvatar = wx.canIUse('button.open-type.chooseAvatar')
    const supportNickname = wx.canIUse('input.type.nickname')
    this.setData({
      supportAvatar,
      supportNickname,
      // 老代码判断：新能力可用就不再使用 getUserProfile
      useNewAbility: supportAvatar && supportNickname
    })
  }
})
```

```text
getUserProfile 要点：
1. 已废弃 —— 2021.4.13 起不再弹授权框，返回匿名头像与「微信用户」
2. 强切时间点 —— 2022.10.25 起必须使用头像昵称填写能力
3. 返回值不可信 —— 匿名头像、昵称恒为「微信用户」、gender 恒为 0
4. 不要降级兼容 —— 直接迁移到填写能力，新旧混用没有意义
5. 审核风险 —— 仍用旧接口收集头像昵称的代码可能被审核拒绝
6. 服务端兜底 —— 头像昵称允许为空，数据库字段给默认值
```

## 头像昵称填写能力

头像昵称填写能力由两个组件配合：头像用 button（open-type=chooseAvatar），昵称用 input（type=nickname）。用户点击头像按钮会弹出「选择头像」面板，可从微信头像或相册/拍照中选择；chooseavatar 事件返回的 e.detail.avatarUrl 是本地临时文件路径，必须先上传到自己的服务器（wx.uploadFile），拿到服务器返回的正式 URL 后才能保存和展示。昵称输入框 type=nickname 唤起微信昵称联想，用户可一键填入自己的微信昵称，也可手动修改。

工程要点：头像临时路径不能直接入库——临时文件会失效，页面刷新后图片 404，必须上传。上传时机建议「选择后立即上传」，不要攒到提交时才传，避免用户中途放弃导致上传失败。昵称要做长度与内容校验（建议 1-20 字符，去除空白），敏感词校验可走后端内容安全接口（见 14.1-内容安全 篇章）。用户有权不填：头像给默认图，昵称给「微信用户」或随机昵称，不能因为资料不全就限制功能。

```wxml
<!-- pages/profile/edit.wxml —— 头像昵称填写 -->
<view class="form">
  <view class="form-item">
    <text class="label">头像</text>
    <button class="avatar-btn" open-type="chooseAvatar" bind:chooseavatar="onChooseAvatar">
      <image class="avatar" src="{{avatarUrl}}" mode="aspectFill"></image>
      <text class="tip">点击选择头像</text>
    </button>
  </view>
  <view class="form-item">
    <text class="label">昵称</text>
    <input type="nickname" class="nickname-input" placeholder="请输入昵称"
           value="{{nickname}}" bind:blur="onNicknameInput" />
  </view>
  <button class="submit-btn" bindtap="onSubmit" disabled="{{submitting}}">保存</button>
</view>
```

```js
// pages/profile/edit.js —— 头像上传 + 昵称校验 + 提交
Page({
  data: {
    avatarUrl: '/images/default-avatar.png',
    nickname: ''
  },

  // 1. 选择头像 -> 立即上传到服务器
  onChooseAvatar(e) {
    const tempPath = e.detail.avatarUrl
    wx.uploadFile({
      url: 'https://api.example.com/api/upload/avatar',
      filePath: tempPath,
      name: 'file',
      success: (res) => {
        const data = JSON.parse(res.data)
        if (data.code === 0) {
          this.setData({ avatarUrl: data.data.url })   // 服务器正式 URL
        } else {
          wx.showToast({ title: '头像上传失败', icon: 'none' })
        }
      },
      fail: () => {
        wx.showToast({ title: '网络异常，上传失败', icon: 'none' })
      }
    })
  },

  onNicknameInput(e) {
    this.setData({ nickname: e.detail.value.trim().slice(0, 20) })
  },

  // 2. 提交资料到用户中心
  onSubmit() {
    const nickname = this.data.nickname
    if (nickname && nickname.length < 2) {
      wx.showToast({ title: '昵称至少 2 个字符', icon: 'none' })
      return
    }
    this.setData({ submitting: true })
    wx.request({
      url: 'https://api.example.com/api/user/profile',
      method: 'PUT',
      header: { 'Authorization': 'Bearer ' + wx.getStorageSync('token') },
      data: { nickname, avatar: this.data.avatarUrl },
      success: (res) => {
        this.setData({ submitting: false })
        if (res.data.code === 0) {
          wx.setStorageSync('userInfo', res.data.data)
          wx.showToast({ title: '保存成功' })
          setTimeout(() => wx.navigateBack(), 800)
        }
      }
    })
  }
})
```

```text
头像昵称填写要点：
1. 头像 —— button open-type=chooseAvatar，事件取临时路径
2. 临时路径必须上传 —— 入库的是服务器 URL，不是本地临时文件
3. 昵称 —— input type=nickname，用户主动填写，可唤起微信昵称联想
4. 允许不填 —— 头像给默认图、昵称给默认值，不强制、不阻断功能
5. 校验 —— 昵称长度限制、内容安全检测，头像校验文件类型与大小
6. 上传时机 —— 选择后立即上传，避免攒到提交时失败
```

## 手机号快速验证

获取用户手机号的合规方式是「手机号快速验证组件」：button 设置 open-type=getPhoneNumber，用户点击后微信弹出确认框（展示脱敏手机号），用户同意后触发 getphonenumber 事件，事件里 e.detail.code 是手机号换取凭证（5 分钟有效、一次性），把这个 code 传给后端，后端调微信接口换取真实手机号。

后端换取接口是 POST https://api.weixin.qq.com/wxa/business/getuserphonenumber?access_token=ACCESS_TOKEN，请求体为 { "code": "e.detail.code" }，返回 phone_info 对象（含 phoneNumber、purePhoneNumber、countryCode）。注意这个接口需要 access_token（服务端凭 AppID+AppSecret 调用 gettoken 接口获取），与 code2session 不是同一个接口。使用前提：小程序为企业/个体工商户主体且已完成微信认证，并在小程序后台「用户隐私保护指引」中声明收集手机号。

2023 年起，getPhoneNumber 返回的 encryptedData/iv 解密方式逐渐下线，新代码一律用 code 换取方式。手机号属于敏感个人信息，入库必须加密存储或脱敏展示；每个用户可获取次数建议服务端记录并限制（防止接口被恶意刷取，微信侧也有频率限制）。用户点击取消不会触发 getphonenumber 事件，要做失败兜底。

```wxml
<!-- pages/order/confirm.wxml —— 下单页手机号快速验证 -->
<button class="phone-btn" open-type="getPhoneNumber" bind:getphonenumber="onGetPhoneNumber">
  使用微信手机号快速填写
</button>
```

```js
// pages/order/confirm.js —— 用 code 换手机号并绑定
Page({
  onGetPhoneNumber(e) {
    const { code, errMsg } = e.detail
    if (!code) {
      // 用户取消或调用失败（errMsg 含 fail/cancel 时无 code）
      wx.showToast({ title: '已取消，可手动输入手机号', icon: 'none' })
      return
    }
    // 把 code 发给后端换取手机号
    wx.request({
      url: 'https://api.example.com/api/user/phone',
      method: 'POST',
      header: { 'Authorization': 'Bearer ' + wx.getStorageSync('token') },
      data: { code },
      success: (res) => {
        if (res.data.code === 0) {
          const { phone } = res.data.data
          this.setData({ phone: maskPhone(phone) })
          wx.showToast({ title: '绑定成功' })
        } else {
          // code 失效等原因：提示重试
          wx.showToast({ title: res.data.msg || '获取失败', icon: 'none' })
        }
      }
    })
  }
})

function maskPhone(phone) {
  return phone.replace(/^(\d{3})\d{4}(\d{4})$/, '$1****$2')
}
```

```java
// 后端：code 换手机号（WechatApiClient.java 补充方法）
public PhoneInfo getPhoneNumber(String code) {
    String accessToken = getAccessToken();   // 内部调用 gettoken 并缓存
    String url = "https://api.weixin.qq.com/wxa/business/getuserphonenumber?access_token=" + accessToken;
    HttpHeaders headers = new HttpHeaders();
    headers.setContentType(MediaType.APPLICATION_JSON);
    HttpEntity<String> entity = new HttpEntity<>("{\"code\":\"" + code + "\"}", headers);
    ResponseEntity<PhoneResp> resp = restTemplate.postForEntity(url, entity, PhoneResp.class);
    if (resp.getBody() == null || resp.getBody().getErrcode() != 0) {
        throw new BizException("手机号获取失败");
    }
    return resp.getBody().getPhoneInfo();
}
```

```text
手机号快速验证要点：
1. 组件 —— button open-type=getPhoneNumber，用户点击触发
2. code 换手机号 —— e.detail.code 发给后端，后端调 getuserphonenumber
3. 前提条件 —— 企业/个体主体 + 微信认证 + 隐私指引声明手机号
4. 加密存储 —— 手机号属敏感信息，入库加密、展示脱敏
5. 取消兜底 —— 用户取消无 code，走手动输入或跳过
6. 频率限制 —— 服务端记录获取次数，防恶意刷取
```

## 用户信息授权机制

授权机制经历了大调整：scope.userInfo 已废弃（wx.authorize 的 scope.userInfo、wx.getUserInfo 均不再返回真实信息）；wx.getUserProfile 同步废弃。当前仍可用的授权 scope 主要是地理位置（scope.userLocation）、相册（scope.writePhotosAlbum）、摄像头（scope.camera）、麦克风（scope.record）等能力类授权，这些通过 wx.authorize 或组件能力触发，与用户资料无关。

原则变化：用户资料类信息不再走「授权弹窗」，改走「用户主动动作」（选择头像、输入昵称、点击手机号按钮）；能力类授权（位置、相机等）仍保留弹窗，但必须在隐私保护指引中声明，且弹窗时机要克制——用户真正使用该能力时再触发，拒绝后要给出替代方案（如手动输入地址）。wx.authorize 调用后若用户曾拒绝，不会再次弹窗，需引导用户在设置页开启（wx.openSetting）。

```js
// 能力类授权示例：获取位置（需要时再申请，拒绝给降级方案）
Page({
  onGetLocation() {
    wx.authorize({
      scope: 'scope.userLocation',
      success: () => {
        wx.getLocation({ type: 'gcj02', success: (res) => {
          // 使用经纬度
        }})
      },
      fail: () => {
        wx.showModal({
          title: '需要位置权限',
          content: '不开启定位将无法使用附近门店功能，可在设置中开启',
          confirmText: '去设置',
          success: (res) => {
            if (res.confirm) {
              wx.openSetting()   // 跳转设置页手动开启
            }
          }
        })
      }
    })
  }
})
```

```text
用户信息授权要点：
1. scope.userInfo 已废弃 —— 不存在用户资料类授权弹窗
2. 能力类授权仍在 —— 位置/相册/摄像头/麦克风等走 wx.authorize
3. 弹窗克制 —— 用到再申请，禁止启动时连环弹授权框
4. 拒绝要降级 —— 拒绝后给替代方案，并引导 wx.openSetting 开启
5. 声明在先 —— 授权对应的隐私接口需在隐私指引中声明
6. 权限可撤销 —— 用户可在微信设置里随时关闭已授权能力
```

## 隐私保护与合规

隐私合规是 2023 年后小程序上线的硬门槛。核心机制是「用户隐私保护指引」：开发者在 mp 后台「设置-服务内容声明-用户隐私保护指引」中声明收集哪些用户信息（头像、昵称、手机号、位置等）及用途，声明后才可调用对应隐私接口；用户首次进入小程序时弹出隐私协议弹窗（由 wx.requirePrivacyAuthorize 或隐私弹窗按钮触发），用户同意后才能调用隐私接口。

技术侧要点：基础库 2.32.3 及以上支持隐私相关 API（wx.getPrivacySetting、wx.requirePrivacyAuthorize、wx.onNeedPrivacyAuthorization），2.33.0 及以上支持隐私弹窗按钮（button open-type=agreePrivacyAuthorization）。兼容处理：低版本基础库直接放行（不弹隐私弹窗），高版本按隐私协议流程走；未同意隐私协议时调用隐私接口会失败（errno 104 等），要在失败回调里引导用户先同意协议。头像昵称填写、手机号快速验证、位置等均属隐私接口，必须在指引中声明对应项。

合规红线：不得在用户同意前收集任何个人信息；不得收集与业务无关的信息；收集的手机号、位置等敏感信息需加密存储并限制访问；隐私政策文本要真实、可读，与实际收集行为一致，否则审核不通过甚至被下架。

```js
// 隐私协议处理：进入前检查，未同意则弹窗引导
const { request } = require('../utils/request')

async function ensurePrivacyAgreed() {
  // 低版本基础库无隐私接口，直接放行
  if (!wx.getPrivacySetting) return true
  const setting = await new Promise((resolve) => {
    wx.getPrivacySetting({
      success: resolve,
      fail: () => resolve({ needAuthorization: false })
    })
  })
  return !setting.needAuthorization
}

// 页面中使用：先确认隐私协议，再调头像/手机号等隐私接口
Page({
  async onLoad() {
    const agreed = await ensurePrivacyAgreed()
    if (!agreed) {
      wx.showModal({
        title: '隐私保护提示',
        content: '请先同意《用户隐私保护指引》后使用',
        confirmText: '去同意',
        success: (res) => {
          if (res.confirm) wx.openPrivacyContract()   // 打开隐私协议页
        }
      })
    }
  }
})
```

```text
隐私保护要点：
1. 隐私保护指引 —— mp 后台声明收集项与用途，声明后才能调隐私接口
2. 隐私弹窗 —— 用户首次进入需同意协议，同意后才可收集信息
3. 基础库版本 —— 2.32.3+ 支持隐私 API，低版本直接放行
4. 未同意要引导 —— 隐私接口调用失败时引导用户先同意协议
5. 最小化收集 —— 只收业务必需信息，与业务无关的一律不收
6. 存储合规 —— 手机号等敏感信息加密存储、脱敏展示、限制访问
```

## 应用场景实战

### 场景一：新用户引导页完成头像昵称 + 手机号一站式完善

需求：用户首次进入小程序，引导页展示「完善资料」流程：选头像、填昵称、微信手机号一键绑定，全部完成后进入首页。

```wxml
<!-- pages/guide/guide.wxml -->
<view class="guide">
  <button open-type="chooseAvatar" bind:chooseavatar="onChooseAvatar">
    <image src="{{avatarUrl}}" mode="aspectFill"></image>
  </button>
  <input type="nickname" placeholder="请输入昵称" bind:blur="onNickname" />
  <button open-type="getPhoneNumber" bind:getphonenumber="onPhone">
    {{phone ? phone : '微信手机号一键绑定'}}
  </button>
  <button bindtap="onFinish" disabled="{{!finished}}">进入小程序</button>
</view>
```

```js
// pages/guide/guide.js —— 三步资料完善
Page({
  data: { avatarUrl: '', nickname: '', phone: '', finished: false },

  onChooseAvatar(e) {
    wx.uploadFile({
      url: 'https://api.example.com/api/upload/avatar',
      filePath: e.detail.avatarUrl,
      name: 'file',
      success: (res) => {
        const data = JSON.parse(res.data)
        this.setData({ avatarUrl: data.data.url })
        this.checkFinish()
      }
    })
  },

  onNickname(e) {
    this.setData({ nickname: e.detail.value.trim() })
    this.checkFinish()
  },

  onPhone(e) {
    const { code } = e.detail
    if (!code) return
    wx.request({
      url: 'https://api.example.com/api/user/phone',
      method: 'POST',
      header: { 'Authorization': 'Bearer ' + wx.getStorageSync('token') },
      data: { code },
      success: (res) => {
        if (res.data.code === 0) {
          this.setData({ phone: res.data.data.phone })
          this.checkFinish()
        }
      }
    })
  },

  checkFinish() {
    const { avatarUrl, nickname, phone } = this.data
    this.setData({ finished: !!(avatarUrl && nickname && phone) })
  },

  onFinish() {
    wx.request({
      url: 'https://api.example.com/api/user/profile',
      method: 'PUT',
      header: { 'Authorization': 'Bearer ' + wx.getStorageSync('token') },
      data: { nickname: this.data.nickname, avatar: this.data.avatarUrl },
      success: () => wx.reLaunch({ url: '/pages/index/index' })
    })
  }
})
```

### 场景二：资料页「已拒绝过隐私协议」的合规恢复流程

需求：用户首次进入时拒绝了隐私协议，后续点击「绑定手机号」时隐私接口调用失败，需要引导用户重新同意协议后再绑定。

```js
// pages/profile/bind.js —— 隐私协议拒绝后的恢复流程
Page({
  onBindPhone() {
    const that = this
    wx.request({
      url: 'https://api.example.com/api/user/phone/precheck',
      method: 'GET',
      success(res) {
        // 后端返回 privacyBlocked=true 表示隐私协议未同意
        if (res.data.data.privacyBlocked) {
          wx.showModal({
            title: '需要同意隐私协议',
            content: '绑定手机号需要您先同意《用户隐私保护指引》',
            confirmText: '去同意',
            success: (modalRes) => {
              if (modalRes.confirm) {
                // 用隐私弹窗按钮能力重新发起同意流程
                wx.requirePrivacyAuthorize({
                  success: () => that.triggerPhoneButton(),
                  fail: () => wx.showToast({ title: '未同意协议，无法绑定', icon: 'none' })
                })
              }
            }
          })
        }
      }
    })
  },

  triggerPhoneButton() {
    // 引导用户重新点击 getPhoneNumber 按钮（可编程触发组件状态）
    this.setData({ showPhoneBtn: true })
  }
})
```

两个场景的共性设计：
1. 用户主动动作驱动 —— 头像/昵称/手机号全部由用户点击或输入触发
2. 分步校验 —— 每完成一步更新状态，全部完成才可提交
3. 隐私合规前置 —— 隐私接口前先确认协议，拒绝可恢复
4. 失败可重试 —— code 失效、上传失败都有明确提示与重试路径

## 最佳实践与踩坑记录

### 最佳实践

1. 全部迁移到头像昵称填写能力与手机号快速验证组件，彻底移除 getUserProfile/getUserInfo 调用
2. 头像选择后立即上传拿服务器 URL，入库、展示、分享都用正式 URL，绝不用临时路径
3. 昵称与头像允许为空，数据库给默认值，不因资料不全限制核心功能
4. 手机号 code 换取后立即加密入库，前端只展示脱敏号码
5. 隐私保护指引声明与实际收集行为保持一致，收集前先检查并引导用户同意协议
6. 能力类授权（位置等）用到再申请，拒绝给替代方案并引导 wx.openSetting
7. 手机号获取次数服务端记录限流，避免接口被恶意刷取
8. 所有用户提交内容（昵称、头像）走内容安全检测，防违规内容入库

### 踩坑记录

```text
坑 1：还在用 getUserProfile 拿真实头像昵称
结论：线上拿到的一律是灰色头像与「微信用户」，用户资料形同虚设。
原因：2021 年 4 月起 getUserProfile 不再弹窗，2022 年 10 月起强制切换。
解法：改用 button chooseAvatar + input nickname 填写能力，整体迁移。

坑 2：头像临时路径直接入库，页面刷新后图片 404
结论：头像保存成功，隔天打开全变裂图。
原因：chooseavatar 返回的是本地临时文件路径，会随会话失效。
解法：选择后立即 wx.uploadFile 上传，入库用服务器返回的正式 URL。

坑 3：强制要求填写头像昵称才能进入小程序
结论：提交审核被拒，提示「诱导用户授权」或「强制收集信息」。
原因：引导页要求用户必须完善资料才能使用，违反最小化收集原则。
解法：资料完善做成可跳过流程，默认头像 + 默认昵称，用户可后续补全。

坑 4：手机号还在用 encryptedData + session_key 解密
结论：2023 年后部分用户解密失败，手机号获取不稳定。
原因：getPhoneNumber 的 encryptedData 方式逐步下线，改为 code 换取。
解法：改用 e.detail.code + 后端 getuserphonenumber 接口换取手机号。

坑 5：未在隐私保护指引声明「手机号」，getPhoneNumber 直接失败
结论：按钮点击后无响应或报隐私接口未授权。
原因：收集手机号未在 mp 后台隐私指引中声明，接口被平台拦截。
解法：后台「用户隐私保护指引」声明手机号及用途，重新提交审核通过后生效。

坑 6：getPhoneNumber 按钮被快速重复点击，code 一次性失效
结论：第二次点击拿到的 code 换取时报错，用户以为功能坏了。
原因：code 5 分钟有效且只能用一次，重复点击生成多个 code 只留最后使用。
解法：点击后置 loading 防重复；失败时提示重新点击获取新 code。

坑 7：昵称不做校验，脏数据与违规昵称入库
结论：库里出现超长昵称、空白昵称、违规内容，运营被约谈。
原因：input 只做了取值，没做长度限制与内容安全检测。
解法：前端限制长度去空白，后端二次校验并调内容安全接口检测。

坑 8：隐私协议被拒后没有恢复路径，功能永久不可用
结论：用户误点拒绝后，手机号绑定永远失败，只能卸载重装。
原因：未处理隐私接口失败的引导流程。
解法：隐私接口失败时识别原因，引导用户通过隐私弹窗/协议页重新同意。
```

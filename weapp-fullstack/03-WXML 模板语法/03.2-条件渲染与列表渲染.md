## 概述

条件渲染与列表渲染是 WXML 控制属性的两大主力：wx:if / wx:elif / wx:else 根据条件决定节点是否渲染，hidden 用样式控制显示隐藏；wx:for 把数组数据循环渲染为节点列表，配合 wx:key 提升列表复用与更新性能。两者解决的是「页面按数据状态动态生成结构」的问题，几乎所有页面都离不开它们。

条件渲染解决「要不要渲染」，列表渲染解决「渲染多少份」。两者常组合使用：列表数据为空时渲染空态提示，加载中渲染 loading，加载完成渲染列表，这是电商、内容类小程序页面三态（加载中/空/有数据）的标准实现。block 标签则为多条相邻节点提供不产生真实节点的分组容器。

```text
条件渲染与列表渲染核心要点：
1. wx:if —— 条件为 true 才渲染节点，惰性渲染，切换时销毁与重建
2. wx:elif / wx:else —— 与 wx:if 相邻使用，多分支互斥匹配
3. hidden —— 节点始终渲染，仅通过 display:none 控制显隐
4. wx:for —— 数组循环渲染，默认 item/index 变量，可重命名
5. wx:key —— 列表复用标识，属性名字符串或 *this，不写会告警
6. block —— 不渲染真实节点的分组容器，配合 wx:if / wx:for 使用
```

## wx:if 条件渲染

wx:if 是 WXML 的条件渲染指令：属性值为 true 时渲染该节点及其子节点，为 false 时不渲染（连节点都不存在于页面结构中）。它与 wx:elif、wx:else 组成完整的 if-elif-else 多分支结构，同一时刻只有一个分支生效。

基本用法与多分支结构：

```wxml
<!-- pages/order/order.wxml -->
<view wx:if="{{ orderStatus === 0 }}">订单待支付</view>
<view wx:elif="{{ orderStatus === 1 }}">订单已支付，等待发货</view>
<view wx:elif="{{ orderStatus === 2 }}">订单已发货</view>
<view wx:else>订单已完成或已取消</view>
```

wx:elif 与 wx:else 必须紧跟在前一个分支节点之后，中间不能插入其他节点，否则不生效：

```wxml
<!-- 错误示范：wx:else 前插入了 view，else 分支失效 -->
<view wx:if="{{ isLogin }}">已登录</view>
<view>分割线</view>
<view wx:else>未登录</view>

<!-- 正确示范：三个分支必须相邻 -->
<view wx:if="{{ isLogin }}">已登录</view>
<view wx:elif="{{ isRegistering }}">注册中</view>
<view wx:else>未登录</view>
```

wx:if 的惰性渲染特性：条件为 false 时节点完全不会渲染，也没有对应的组件实例；条件从 false 变为 true 时，节点被重新创建（组件的 created/attached 等生命周期会重新执行），从 true 变为 false 时节点被销毁。因此 wx:if 适合「初始状态基本不变」的场景，频繁切换会产生较大的销毁重建开销：

```wxml
<view wx:if="{{ showDetail }}" class="detail-panel">
  <!-- 该区域首次渲染 showDetail 为 false 时不生成，
       之后每次切换都会重建内部组件、重新执行生命周期 -->
  <custom-component bind:load="onDetailLoad"></custom-component>
</view>
```

```js
// pages/order/order.js
Page({
  data: {
    orderStatus: 1,
    isLogin: true,
    isRegistering: false,
    showDetail: false
  },
  onShowDetail() {
    // 切换条件渲染状态
    this.setData({ showDetail: !this.data.showDetail })
  }
})
```

```text
wx:if 要点：
1. 惰性渲染 —— 条件为 false 时节点不生成，页面结构里不存在该节点
2. 多分支 —— wx:if + wx:elif + wx:else 相邻书写，同一时刻只有一个分支渲染
3. 互斥匹配 —— 自上而下匹配，命中一个分支后其余分支不再判断
4. 切换开销 —— 条件变化时销毁旧节点、重建新节点，组件生命周期重新执行
5. 适用场景 —— 初始条件明确且基本不变（登录态、空态、权限位）适合 wx:if
6. 频繁切换 —— 高频切换的显隐不要用 wx:if，改用 hidden 减少重建开销
```

## hidden 与 wx:if 的选择

hidden 是另一种显隐控制方式：节点始终被渲染，只是通过 display:none 样式隐藏。hidden 属性的值同样是布尔表达式，true 表示隐藏，false 表示显示。

基本用法：

```wxml
<!-- pages/index/index.wxml -->
<view hidden="{{ loading }}">内容已加载完成</view>
<view hidden="{{ !loading }}">加载中...</view>
```

hidden 与 wx:if 的本质区别决定了它们的适用场景：

```wxml
<!-- wx:if：不满足条件时节点根本不存在 -->
<view wx:if="{{ showBanner }}">活动 Banner（不存在于页面时无任何渲染成本）</view>

<!-- hidden：节点始终存在，只是 display:none -->
<view hidden="{{ !showBanner }}">活动 Banner（始终占用节点，切换只改样式）</view>
```

```text
wx:if vs hidden 对比：
1. 渲染时机 —— wx:if 条件为 false 时不渲染节点；hidden 始终渲染节点
2. 切换成本 —— wx:if 切换要销毁/重建节点与组件实例；hidden 只切换 display 样式
3. 初始成本 —— wx:if 初始为 false 时零渲染成本；hidden 无论是否显示都渲染
4. 生命周期 —— wx:if 切换会重新触发组件生命周期；hidden 不会
5. 使用建议 —— 初始条件大概率不变用 wx:if；高频切换、节点内部无重型组件用 hidden
6. 组合注意 —— 同一节点不要同时使用 wx:if 与 hidden，语义冲突且难以维护
```

## wx:for 列表渲染

wx:for 是 WXML 的列表渲染指令：属性值为数组时，为数组的每一项生成一份节点副本。默认约定：数组当前项变量名为 item，下标变量名为 index。可以用 wx:for-item 与 wx:for-index 重命名，嵌套循环时重命名是必须的。

基本用法与默认变量：

```wxml
<!-- pages/goods/goods.wxml -->
<view class="goods-item" wx:for="{{ goodsList }}" wx:key="id">
  <view class="goods-name">{{ item.name }}</view>
  <view class="goods-price">¥{{ item.price }}</view>
  <view class="goods-index">第 {{ index + 1 }} 个</view>
</view>
```

```js
// pages/goods/goods.js
Page({
  data: {
    goodsList: [
      { id: 1, name: '蓝牙耳机', price: 199 },
      { id: 2, name: '机械键盘', price: 399 },
      { id: 3, name: '显示器', price: 1299 }
    ]
  }
})
```

重命名循环变量：wx:for-item 重命名当前项，wx:for-index 重命名下标。嵌套 wx:for 时，内层循环默认也使用 item/index，会覆盖外层同名变量，因此内层必须重命名才能同时访问两层数据：

```wxml
<!-- 嵌套列表：分类下有商品列表，内层重命名为 product -->
<view class="category" wx:for="{{ categoryList }}" wx:for-item="category" wx:for-index="cIdx" wx:key="id">
  <view class="category-name">{{ cIdx + 1 }}. {{ category.name }}</view>
  <view class="product" wx:for="{{ category.products }}" wx:for-item="product" wx:key="id">
    <!-- 这里既能访问内层 product，也能访问外层 category -->
    <text>{{ product.name }}（{{ category.name }} 分类）</text>
  </view>
</view>
```

```js
// 对应 data
Page({
  data: {
    categoryList: [
      { id: 11, name: '数码配件', products: [{ id: 111, name: '数据线' }, { id: 112, name: '充电头' }] },
      { id: 12, name: '键鼠外设', products: [{ id: 121, name: '机械键盘' }] }
    ]
  }
})
```

wx:for 支持直接遍历数组字面量，也支持遍历对象（item 为对象的值）；注意 wx:for 中调用 setData 更新数组时，用路径式 key 更新单条数据更高效：

```wxml
<!-- 数组字面量 -->
<view wx:for="{{ [1, 2, 3, 4, 5] }}">{{ item }}</view>
<!-- 遍历对象的值 -->
<view wx:for="{{ scoreMap }}">{{ index }}: {{ item }} 分</view>
```

```js
// 更新列表单项
Page({
  data: { goodsList: [{ id: 1, name: '蓝牙耳机', price: 199 }] },
  onPriceChange(e) {
    // 路径式更新：只更新第 0 项的 price，其余不变
    this.setData({ 'goodsList[0].price': 159 })
  }
})
```

```text
wx:for 要点：
1. 默认变量 —— item 表示当前项，index 表示下标，直接可用
2. 重命名 —— wx:for-item="xxx" wx:for-index="i" 自定义变量名
3. 嵌套循环 —— 内层必须重命名（wx:for-item="product"），否则覆盖外层 item
4. 遍历范围 —— 支持数组、数组字面量、对象（item 为值）、字符串（item 为字符）
5. 更新方式 —— 单条更新用 'list[0].field' 路径式 setData，避免整数组替换
6. 必配 wx:key —— 列表循环必须写 wx:key，否则控制台告警且复用性能差
```

## wx:key 与列表复用

wx:key 用于给列表项指定唯一标识，帮助框架在数据变化时复用节点、做最小化更新（diff）。wx:key 的值有两种写法：item 中某个属性名的字符串（如 "id"），或特殊值 *this（item 本身是字符串/数字等基本类型时）。

属性名写法：wx:key 的值直接写属性名字符串，不需要 {{ }} 包裹：

```wxml
<!-- wx:key="id"：以 item.id 作为唯一标识，注意不是 wx:key="{{item.id}}" -->
<view class="goods-item" wx:for="{{ goodsList }}" wx:key="id">
  {{ item.name }} - ¥{{ item.price }}
</view>

<!-- *this：item 是字符串/数字基本类型时使用 -->
<view wx:for="{{ ['苹果', '香蕉', '橙子'] }}" wx:key="*this">
  {{ item }}
</view>
```

wx:key 的作用在列表重排、增删时体现最明显。没有 wx:key 时框架按下标复用节点，重排会导致节点内容错位（复用了错误的节点）；有 wx:key 时框架按 key 精确匹配，节点随数据移动而移动，内部状态（输入框内容、滚动位置、组件状态）得以保留：

```wxml
<!-- 有 wx:key 的场景：列表项内部有输入框，重排后输入内容跟随对应数据 -->
<view wx:for="{{ list }}" wx:key="id">
  <input value="{{ item.name }}" data-id="{{ item.id }}" bindinput="onInput"/>
</view>
```

```js
// 列表重排（如按价格排序）时，wx:key 保证节点与数据正确对应
Page({
  data: {
    list: [
      { id: 1, name: '商品A', price: 99 },
      { id: 2, name: '商品B', price: 199 },
      { id: 3, name: '商品C', price: 299 }
    ]
  },
  sortByPrice() {
    const list = [...this.data.list].sort((a, b) => a.price - b.price)
    this.setData({ list })
  }
})
```

不写 wx:key 时，控制台会输出告警：Now you can provide attr "wx:key" for a "wx:for" to improve performance。告警只是提示，不影响运行，但列表项带内部状态（输入框、checkbox）时一定要写 wx:key，否则会出现状态错位这类隐蔽 bug：

```text
wx:key 要点：
1. 取值规则 —— 属性名字符串（wx:key="id"）或 *this（基本类型数组），不加 {{ }}
2. 常见错误 —— wx:key="{{item.id}}" 是错误的写法，wx:key 不接受表达式
3. 复用机制 —— 框架按 key 匹配节点与数据，重排/增删时精确复用节点
4. 状态保留 —— 带输入框、checkbox、组件状态的列表必须写 wx:key，防止状态错位
5. 告警提示 —— 不写 wx:key 控制台输出 performance 告警
6. 唯一性 —— key 值必须在同列表内唯一，重复 key 会导致复用错乱
```

## block 标签

block 是 WXML 内置的分组标签：它不会渲染成任何真实节点，只用于把多条相邻节点包成一组，统一施加控制属性（wx:if、wx:for）。因为不产生节点，不会影响页面结构、样式与 flex 布局。

block 配合 wx:if 分组条件渲染多条节点：

```wxml
<!-- 登录成功提示三连：三个 view 共用一个条件 -->
<block wx:if="{{ isLogin }}">
  <view>欢迎回来，{{ nickname }}</view>
  <view>今日签到有礼</view>
  <view>查看我的订单</view>
</block>
<block wx:else>
  <view>请先登录</view>
  <view>登录后可同步购物车</view>
</block>
```

block 配合 wx:for 分组列表渲染多条节点，避免为列表额外包一层 view 影响布局：

```wxml
<!-- 每条订单渲染两行内容，不需要额外的容器 view -->
<block wx:for="{{ orderList }}" wx:for-item="order" wx:key="orderNo">
  <view class="order-no">订单号：{{ order.orderNo }}</view>
  <view class="order-status">{{ order.statusText }}</view>
</block>
```

```js
// pages/order/order.js
Page({
  data: {
    isLogin: true,
    nickname: '小明',
    orderList: [
      { orderNo: '202608200001', statusText: '已发货' },
      { orderNo: '202608200002', statusText: '待支付' }
    ]
  }
})
```

block 的另一个用途是配合 wx:for 与 wx:key：如果列表项需要多节点结构，block 本身不产生节点，wx:key 可以写在 block 上：

```wxml
<block wx:for="{{ list }}" wx:key="id">
  <view>{{ item.title }}</view>
  <view class="divider"></view>
</block>
```

```text
block 要点：
1. 不产生节点 —— block 只是逻辑分组容器，渲染后页面结构中不存在
2. 适用 wx:if —— 多条相邻节点共用一个条件时用 block 包裹
3. 适用 wx:for —— 列表项是多节点结构时用 block 包裹，避免多余容器 view
4. 不影响布局 —— 不会破坏 flex/grid 布局，不会产生多余边距
5. 可写 wx:key —— block 上可以直接写 wx:key
6. 注意 —— block 不能加 class/style，样式要写到内部真实节点上
```

## 应用场景实战

### 场景一：商品列表页三态切换（加载中 / 空态 / 有数据）

列表页标准三态：请求后台前显示加载中，请求成功但列表为空显示空态与去逛逛按钮，有数据显示商品列表。三个状态互斥，用 wx:if / wx:elif / wx:else 实现，列表用 wx:for + wx:key 渲染。

```wxml
<!-- pages/goods/list.wxml -->
<view class="page">
  <!-- 状态一：加载中 -->
  <view class="status-panel" wx:if="{{ loading }}">
    <view class="loading-text">加载中...</view>
  </view>

  <!-- 状态二：空态 -->
  <view class="status-panel" wx:elif="{{ goodsList.length === 0 }}">
    <view class="empty-text">暂无商品</view>
    <button class="go-btn" bindtap="goExplore">去逛逛</button>
  </view>

  <!-- 状态三：有数据，列表渲染 -->
  <block wx:else>
    <view class="goods-item" wx:for="{{ goodsList }}" wx:key="id">
      <image class="goods-img" src="{{ item.image }}" mode="aspectFill"></image>
      <view class="goods-info">
        <view class="goods-name">{{ item.name }}</view>
        <view class="goods-price-row">
          <text class="price">¥{{ item.price }}</text>
          <text class="sales" wx:if="{{ item.sales > 0 }}">已售 {{ item.sales }} 件</text>
        </view>
      </view>
      <view class="stock-tag" wx:if="{{ item.stock <= 0 }}">缺货</view>
    </view>
    <view class="load-more" wx:if="{{ hasMore }}">上拉加载更多</view>
  </block>
</view>
```

```js
// pages/goods/list.js
Page({
  data: {
    loading: true,
    goodsList: [],
    hasMore: true
  },
  onLoad() {
    this.fetchGoods()
  },
  fetchGoods() {
    this.setData({ loading: true })
    wx.request({
      url: 'https://api.example.com/goods/list',
      success: (res) => {
        this.setData({
          loading: false,
          goodsList: res.data.list,
          hasMore: res.data.hasMore
        })
      },
      fail: () => {
        this.setData({ loading: false })
        wx.showToast({ title: '加载失败', icon: 'none' })
      }
    })
  },
  goExplore() {
    wx.switchTab({ url: '/pages/index/index' })
  }
})
```

### 场景二：多 Tab 内容切换与嵌套分类列表

两个能力合一：Tab 切换用 wx:if 互斥切换内容面板（每个面板内部状态独立）；分类列表用嵌套 wx:for（外层分类、内层商品，内层必须 wx:for-item 重命名）渲染。

```wxml
<!-- pages/home/home.wxml -->
<view class="tab-bar">
  <view class="tab-item {{ activeTab === 0 ? 'active' : '' }}" bindtap="switchTab" data-tab="0">推荐</view>
  <view class="tab-item {{ activeTab === 1 ? 'active' : '' }}" bindtap="switchTab" data-tab="1">分类</view>
</view>

<!-- 面板一：推荐（wx:if 切换） -->
<view class="tab-panel" wx:if="{{ activeTab === 0 }}">
  <view class="recommend-item" wx:for="{{ recommendList }}" wx:key="id">
    <view class="rec-title">{{ item.title }}</view>
    <view class="rec-meta">热度 {{ item.hot }} · {{ item.author }}</view>
  </view>
</view>

<!-- 面板二：分类（嵌套 wx:for，内层重命名） -->
<view class="tab-panel" wx:elif="{{ activeTab === 1 }}">
  <view class="category" wx:for="{{ categoryList }}" wx:for-item="category" wx:key="id">
    <view class="category-title">{{ category.name }}</view>
    <view class="category-products">
      <view class="product-chip" wx:for="{{ category.products }}" wx:for-item="product" wx:key="id">
        {{ product.name }}
      </view>
    </view>
  </view>
</view>
```

```js
// pages/home/home.js
Page({
  data: {
    activeTab: 0,
    recommendList: [
      { id: 1, title: '新品上市：真无线降噪耳机', hot: 12000, author: '数码频道' },
      { id: 2, title: '夏季清凉家电选购指南', hot: 8600, author: '家电频道' }
    ],
    categoryList: [
      { id: 11, name: '数码配件', products: [{ id: 111, name: '数据线' }, { id: 112, name: '充电头' }] },
      { id: 12, name: '键鼠外设', products: [{ id: 121, name: '机械键盘' }, { id: 122, name: '鼠标' }] }
    ]
  },
  switchTab(e) {
    const tab = Number(e.currentTarget.dataset.tab)
    this.setData({ activeTab: tab })
  }
})
```

```text
场景实战要点：
1. 三态切换 —— wx:if / wx:elif / wx:else 实现加载中、空态、有数据三态互斥
2. 空态兜底 —— 列表接口返回空数组时必须有空态提示与引导按钮
3. Tab 切换 —— 面板级切换用 wx:if，配合 data-tab + dataset 获取点击目标
4. 嵌套列表 —— 外层 wx:for-item="category"、内层 wx:for-item="product" 必重命名
5. wx:key 规范 —— 所有列表都写 wx:key，带内部状态的面板切换用 wx:if 保证重建
6. 状态独立 —— 每个 Tab 面板内容多、状态复杂时，wx:if 切换会自动重建面板
```

## 最佳实践与踩坑记录

### 最佳实践

1. 页面三态（加载中/空/有数据）统一用 wx:if / wx:elif / wx:else 实现，三个分支互斥且可读性强，比分散的 hidden 组合更可靠
2. 高频切换的显隐（弹层开关、面板折叠）用 hidden；低频切换或初始状态确定的（登录态、权限位、空态）用 wx:if，减少常驻节点
3. 嵌套 wx:for 一律重命名循环变量（wx:for-item="product" wx:for-index="pIdx"），外层变量名带语义前缀，杜绝变量覆盖
4. 所有 wx:for 都写 wx:key：列表项用唯一属性名字符串，基本类型数组用 *this，宁可多余不可缺失
5. 列表数据更新用路径式 setData（'list[0].field'），避免整数组 setData 造成大量节点 diff
6. 列表项需要多节点结构时用 block wx:for 而不是包裹 view，避免破坏 flex 布局产生多余层级
7. 分类等层级结构在后台接口就组织好父子关系，前端只做一层渲染，不在 WXML 里做数据转换

### 踩坑记录

```text
坑 1：wx:else 不生效，两个分支同时渲染
结论：wx:if / wx:else 之间隔了其他节点，else 分支完全失效，页面出现重复内容。
原因：wx:elif / wx:else 必须紧跟在 wx:if（或上一个 wx:elif）节点之后，中间不能有别的节点。
解法：检查三个分支是否相邻书写；需要分组时用 block 包裹多条节点，block 与 block 相邻。

坑 2：wx:key="{{item.id}}" 写法报错且列表告警
结论：写了 wx:key 依然输出性能告警，列表复用错乱。
原因：wx:key 的值不是表达式，不能加 {{ }}；wx:key="{{item.id}}" 会被当成字面量字符串处理。
解法：直接写 wx:key="id"（属性名字符串）；item 是基本类型时写 wx:key="*this"。

坑 3：嵌套 wx:for 内层拿不到外层数据
结论：嵌套循环里引用外层 item 的字段全部渲染为空。
原因：内层循环默认变量名也是 item/index，覆盖了外层的 item，外层数据无法访问。
解法：外层或内层用 wx:for-item 重命名，如外层 wx:for-item="category"、内层 wx:for-item="product"。

坑 4：频繁切换 wx:if 导致页面卡顿
结论：弹层、折叠面板用 wx:if 频繁开关，明显卡顿，切换时有闪烁。
原因：wx:if 每次切换都销毁并重建节点与组件实例，重组件面板反复创建销毁开销大。
解法：高频切换改用 hidden（始终渲染，只切 display:none）；重型内容首次渲染后再用 hidden 常驻。

坑 5：列表项输入框内容在重排后错位
结论：列表排序或删除后，输入框里的内容跑到了别的商品上。
原因：没有 wx:key 时框架按下标复用节点，数据与节点错位，输入框内容没有跟随数据。
解法：列表写 wx:key="id"；输入内容通过 bindinput + data-id 实时写回 data，保证数据是唯一真相。

坑 6：block 上写 class 不生效
结论：block 标签写了 class 想控制整组样式，结果样式完全无效。
原因：block 不渲染成真实节点，class/style 无处挂载，被框架忽略。
解法：样式写到 block 内部的真实节点上；block 只用于逻辑分组。

坑 7：条件渲染的组件生命周期被反复触发
结论：wx:if 包裹的自定义组件，每次显示隐藏都重新请求数据、重置状态。
原因：wx:if 切换会销毁重建组件实例，created/attached/onLoad 重新执行。
解法：希望保留组件状态用 hidden 替代 wx:if；或组件内做数据缓存，attached 时先读缓存再刷新。
```

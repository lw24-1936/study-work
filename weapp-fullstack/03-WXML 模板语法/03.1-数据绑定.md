## 概述

数据绑定是 WXML 最核心的机制：逻辑层（JS）通过 Page 的 data 保存页面状态，视图层（WXML）用 Mustache 语法（双花括号 {{ }}）把 data 中的数据渲染到页面上。数据绑定是单向的，数据只能从逻辑层流向视图层，视图层无法直接修改 data，必须通过 setData 更新数据后由框架自动触发视图层重新渲染，这也是小程序双线程模型与浏览器 DOM 操作最本质的区别。

WXML 的数据绑定能力覆盖四类场景：内容（文本节点）、组件属性（src/id/class 等）、控制属性（wx:if 等）、以及关键字（true/false）。除此之外，花括号内还支持数据路径取值、简单运算、组合与展开，足以应付绝大多数页面渲染需求。

```text
WXML 数据绑定核心要点：
1. 语法 —— {{ }} 双花括号 Mustache 语法，写在 WXML 的文本节点或属性值中
2. 数据源 —— 绑定表达式基于页面 Page.data（或组件 Component 的 data/properties）
3. 更新方式 —— 只能通过 setData 修改数据触发渲染，直接改 this.data 不生效
4. 能力范围 —— 内容绑定、属性绑定、控制属性绑定、关键字绑定
5. 表达能力 —— 支持数据路径、算术/逻辑/三元运算、字符串拼接、组合与展开
6. 边界 —— 不支持函数调用、不支持复杂语句，复杂逻辑放 JS 或 WXS
```

## Mustache 语法

Mustache 语法用双花括号 {{ }} 包裹表达式，出现在两个位置：文本节点（标签内容）和属性值（标签属性）。框架在渲染时把表达式求值结果替换进去，并在依赖数据变化时自动更新。

文本节点绑定是使用频率最高的形式，花括号内的表达式会作为字符串渲染出来：

```wxml
<!-- pages/index/index.wxml -->
<view class="greeting">你好，{{ nickname }}！</view>
<view>当前登录用户：{{ user.name }}</view>
<view>今日签到次数：{{ signCount }} 次</view>
<view>积分余额：{{ points }}</view>
```

组件属性绑定可以把 data 中的值动态设置到属性上，支持任意属性，包括 id、class、src、style、data-* 自定义属性：

```wxml
<!-- 属性绑定：src、id、class 均可用 {{ }} -->
<image src="{{ avatarUrl }}" mode="aspectFill" class="avatar {{ isVip ? 'avatar-vip' : '' }}"></image>
<view id="item-{{ index }}" data-id="{{ itemId }}" style="color: {{ themeColor }}">属性绑定示例</view>
```

控制属性绑定用于把 data 中的布尔值传给 wx:if、hidden、wx:for 等控制属性，驱动条件渲染与列表渲染：

```wxml
<view wx:if="{{ isLogin }}">已登录，欢迎回来</view>
<view hidden="{{ loading }}">加载完成后的内容</view>
<view wx:for="{{ orderList }}">{{ item.orderNo }}</view>
```

页面 JS 侧通过 data 提供数据，通过 setData 更新数据：

```js
// pages/index/index.js
Page({
  data: {
    nickname: '小明',
    user: { name: '小明', level: 3 },
    signCount: 5,
    points: 1280,
    avatarUrl: 'https://example.com/avatar/10001.png',
    isVip: true,
    themeColor: '#07c160',
    isLogin: true,
    loading: false,
    orderList: [{ orderNo: '202608200001' }, { orderNo: '202608200002' }]
  },
  onLoad() {
    // 模拟异步加载后更新数据
    setTimeout(() => {
      this.setData({ signCount: 6, points: 1300 })
    }, 1000)
  }
})
```

```text
Mustache 语法要点：
1. 文本节点 —— {{ 表达式 }} 直接写在标签内容中，渲染为字符串
2. 属性值 —— {{ 表达式 }} 写在属性名="..." 中，支持 id/class/src/style/data-* 等
3. 控制属性 —— wx:if / hidden / wx:for 等属性的取值同样用 {{ }} 包裹
4. 关键字 —— true/false 必须写成 {{ true }} / {{ false }}，直接写 true 会被当作字符串
5. 使用边界 —— {{ }} 不能用于标签名和属性名（如 <{{ tagName }}>、<view {{ attr }}> 均不合法）
6. 渲染时机 —— 首次渲染取 data 当前值，之后每次 setData 触发依赖节点的局部更新
```

## 数据路径

数据路径（Data Path）是指花括号内通过点号（.）与方括号（[]）组合的方式定位 data 中的嵌套数据。路径表达式不需要在 JS 中预先声明，WXML 直接按路径取值即可，取不到的路径渲染为空字符串而不会报错。

点号路径用于对象属性访问，方括号用于数组索引访问，两者可以任意嵌套组合：

```wxml
<!-- pages/user/user.wxml -->
<view>{{ user.name }}（等级 Lv.{{ user.level }}）</view>
<view>所在城市：{{ user.address.city }}</view>
<view>第一个订单号：{{ orders[0].orderNo }}</view>
<view>订单总金额：{{ orders[0].items[0].price }} 元</view>
```

```js
// pages/user/user.js
Page({
  data: {
    user: {
      name: '小明',
      level: 3,
      address: { city: '上海', district: '浦东新区' }
    },
    orders: [
      {
        orderNo: '202608200001',
        items: [{ name: '蓝牙耳机', price: 199 }, { name: '数据线', price: 29 }]
      }
    ]
  }
})
```

路径表达式同样支持方括号加字符串键的形式，适用于键名包含特殊字符（如连字符、点号）的对象：

```wxml
<!-- 键名含特殊字符时使用方括号字符串键 -->
<view>{{ user['user-name'] }}</view>
<view>{{ orderMap['202608200001'] }}</view>
```

```js
// 对应 data
Page({
  data: {
    'user-name': '小明', // 键名含连字符，无法用点号路径访问
    orderMap: { '202608200001': { status: '已发货' } }
  }
})
```

路径表达式还可以参与运算（数据路径运算），例如 {{ object.key }}、{{ array[0] }}、{{ object.key + ' 后缀' }}，路径只是取值手段，取值结果可以继续参与表达式运算：

```wxml
<view>优惠后价格：{{ goods.price * goods.discount }} 元</view>
<view>第 {{ currentIndex + 1 }} / {{ total }} 页</view>
```

```text
数据路径要点：
1. 点号路径 —— object.key 访问对象属性，可多层嵌套 user.address.city
2. 数组索引 —— array[0] 访问数组元素，可与点号混用 orders[0].orderNo
3. 字符串键 —— object['key'] 用于键名含特殊字符（连字符、空格、点号）的对象
4. 容错性 —— 路径不存在时渲染为空字符串，不抛异常，不会白屏
5. 路径运算 —— 路径取出的值可以继续参与算术、拼接等表达式运算
6. 性能提示 —— 路径层级过深（超过 3-4 层）会影响 setData diff 性能，深层数据建议拍平
```

## 运算与逻辑

花括号内不仅仅是取值，还支持完整的简单表达式运算：算术运算、逻辑运算、三元运算、字符串拼接、比较运算。这些能力让模板在渲染时就能完成轻度计算，不必为每个展示值单独准备 data 字段。

算术运算支持加、减、乘、除、取模，括号可以改变优先级：

```wxml
<view>单价 × 数量：{{ price * count }} 元</view>
<view>含税金额：{{ (price * count * 1.13).toFixed ? '' : '' }}{{ price * count * 1.13 }} 元</view>
<view>余额不足提示：{{ balance - price * count }}</view>
<view>凑单差价：{{ targetPrice % price }}</view>
```

逻辑运算支持与（&&）、或（||）、非（!），常用于组合多个条件的判断：

```wxml
<view wx:if="{{ isVip && level >= 3 }}">高级会员专属折扣</view>
<view hidden="{{ !isLogin || isTrial }}">登录用户可见</view>
<view wx:if="{{ isVip || hasCoupon }}">可享优惠</view>
```

三元运算与字符串拼接是模板中最常用的两种表达式形式，三元运算做条件取值，拼接做文本组合：

```wxml
<!-- 三元运算：按条件输出不同内容 -->
<view class="{{ isVip ? 'vip-label' : 'normal-label' }}">{{ isVip ? 'VIP 会员' : '普通用户' }}</view>
<view>订单状态：{{ status === 2 ? '已发货' : status === 3 ? '已完成' : '处理中' }}</view>

<!-- 字符串拼接：{{ "字面量" + 变量 }} -->
<view>{{ "订单号：" + orderNo }}</view>
<view>{{ "共 " + total + " 件商品，合计 " + (totalPrice / 100) + " 元" }}</view>
```

比较运算支持 >、<、>=、<=、==、!=、===、!==，注意 === 是严格相等，类型不同时为 false：

```wxml
<view wx:if="{{ score >= 90 }}">优秀</view>
<view wx:elif="{{ score >= 60 }}">及格</view>
<view wx:else>不及格</view>
<view wx:if="{{ status === 1 }}">待支付（数字 1 才匹配，字符串 '1' 不匹配）</view>
```

需要特别强调表达式的能力边界：花括号内不能调用函数（{{ fn() }} 不生效），不能使用 new、let/const 声明、if 语句等，也不能访问 Page 上的方法。这是模板语言刻意限制的，目的是保证视图层渲染的确定性与性能：

```wxml
<!-- 错误示范：以下写法均不生效 -->
<view>{{ formatPrice(price) }}</view>          <!-- 函数调用不生效 -->
<view>{{ Math.max(a, b) }}</view>              <!-- 全局对象不可用 -->
<view>{{ if (a > b) return '大' }}</view>      <!-- 语句不生效 -->
```

```text
运算与逻辑要点：
1. 算术 —— + - * / % 与括号优先级，常用于价格、数量、金额计算
2. 逻辑 —— && || ! 组合多个条件，驱动 wx:if / hidden
3. 三元 —— 条件 ? A : B 做模板内条件取值，可嵌套但可读性差
4. 拼接 —— "字符串" + 变量 拼接文本，字面量必须加引号
5. 比较 —— > < >= <= == != === !==，类型敏感场景用 ===
6. 边界 —— 不支持函数调用、语句、声明；复杂计算必须在 JS 里算好放 data，或使用 WXS
```

## 组合与展开

组合（Composition）与展开（Spread）解决的是「如何把多个数据拼成一个对象/数组再使用」的问题，最常见的使用场景是给 template 模板传参：把页面 data 中的几个字段组合成一个完整对象，一次性传给模板。

数组组合允许在花括号内直接写数组字面量，字面量与变量可以混用：

```wxml
<!-- 数组组合：字面量 + 变量混用 -->
<view wx:for="{{ [1, 2, 3, 4, 5] }}">{{ item }}</view>
<view wx:for="{{ [zero, 1, 2, 3, 4] }}">{{ item }}</view>
<view wx:for="{{ [header, ...middleList, footer] }}">{{ item.title }}</view>
```

```js
// pages/list/list.js
Page({
  data: {
    zero: 0,
    header: { title: '头部' },
    middleList: [{ title: '中间项 1' }, { title: '中间项 2' }],
    footer: { title: '尾部' }
  }
})
```

对象组合用于给模板传参：把对象字面量直接写在 data 属性中，键值对与变量混用：

```wxml
<!-- 对象组合：data 属性中直接写键值对 -->
<template is="productCard" data="{{ title: product.name, price: product.price, image: product.image }}"></template>

<!-- 等价写法：先组合成对象字面量再传入 -->
<template is="productCard" data="{{ { title: product.name, price: product.price } }}"></template>
```

展开运算符（...）把已有对象的所有键值对展开合并到新对象中，是模板传参最优雅的写法。展开的字段可以被后面的键覆盖，也可以追加新字段：

```wxml
<!-- 展开运算符：...product 展开全部字段，再追加 showPrice -->
<template is="productCard" data="{{ ...product, showPrice: true }}"></template>

<!-- 多对象展开合并：后面的覆盖前面的同名键 -->
<template is="productCard" data="{{ ...baseInfo, ...priceInfo, saleTag: '限时特惠' }}"></template>
```

```js
// pages/index/index.js
Page({
  data: {
    product: {
      name: '蓝牙耳机',
      price: 199,
      image: 'https://example.com/img/headphone.png',
      sales: 1200
    },
    baseInfo: { name: '蓝牙耳机', brand: '某品牌' },
    priceInfo: { price: 199, originPrice: 259 }
  }
})
```

```text
组合与展开要点：
1. 数组组合 —— {{ [字面量, 变量, ...] }} 混用字面量与变量构造数组
2. 对象组合 —— data 属性内直接写 键: 值 或 {{ {键: 值} }} 对象字面量
3. 展开对象 —— {{ ...obj }} 把对象全部键值展开，是模板传参的标准姿势
4. 合并覆盖 —— {{ ...a, ...b }} 后者覆盖前者同名键，可追加新字段
5. 主战场 —— 组合/展开主要服务 template 的 data 传参（详见 03.3 模板与引用）
6. 注意 —— 展开运算符不能展开数组元素到对象，{{ ...arr }} 不产生预期效果
```

## 数据绑定注意事项

数据绑定有几个高频出错点，写错不会报错，但渲染结果完全不符合预期，是最容易「悄悄出错」的一类问题。逐个梳理：

第一，字符串字面量必须加引号。花括号内不加引号的标识符会被当作数据路径去 data 中取值，取不到就渲染为空：

```wxml
<!-- {{ hi }} 会被当成 data.hi 取值，data 中没有 hi 则渲染为空 -->
<view>{{ hi }}</view>
<!-- 正确写法：字符串字面量加双引号或单引号 -->
<view>{{ "hi" }}</view>
<view>{{ 'hi' }}</view>
```

第二，属性值中的字符串字面量存在引号冲突：属性值外层用双引号包裹时，内层字符串字面量再用双引号会与外层冲突，应改用单引号：

```wxml
<!-- 错误写法：外层双引号与内层双引号嵌套，易解析出错 -->
<view data-tip="{{ "点击查看详情" }}">提示</view>
<!-- 正确写法：内层使用单引号 -->
<view data-tip="{{ '点击查看详情' }}">提示</view>
```

第三，关键字 true/false/null 的写法。在属性值中直接写 checked="false" 时，false 是字符串而不是布尔值，字符串 "false" 恒为真值，复选框仍会被选中。必须用 {{ false }} 包裹：

```wxml
<!-- 错误写法：checked="false" 是字符串 "false"，复选框依然选中 -->
<checkbox checked="false"></checkbox>
<!-- 正确写法：{{ false }} 才是布尔 false -->
<checkbox checked="{{ false }}"></checkbox>
```

第四，花括号与关键字之间不要有空格。官方文档明确说明：花括号和引号之间如果有空格，将最终被解析成为字符串。经典对比：

```wxml
<view wx:if="{{false}}">1</view>   <!-- 正确：布尔 false，不渲染 -->
<view wx:if="{{ false }}">2</view> <!-- 错误：被解析为字符串 "false"，恒为真，始终渲染 -->
```

第五，数据更新必须走 setData。直接修改 this.data.xxx 不会触发视图更新，这是小程序双线程模型决定的：视图层与逻辑层数据不共享，setData 才会把数据通过桥接通道同步到视图层：

```js
// 错误写法：直接改 this.data 不触发渲染
this.data.count = 2

// 正确写法：setData 触发渲染
this.setData({ count: 2 })

// 更新嵌套字段：支持路径式 key
this.setData({ 'user.name': '小红', 'orders[0].status': '已发货' })
```

第六，绑定表达式不要太复杂。表达式在每次渲染时都会求值，过长的表达式既影响可读性也影响性能；多个字段参与计算的场景，建议在 JS 中算好放进 data，或在 WXS 中封装（见 05.5 WXS 脚本）。

```text
数据绑定注意事项：
1. 字面量加引号 —— {{ "hi" }} 是字符串，{{ hi }} 是取 data.hi 的值
2. 引号冲突 —— 属性值内层字符串用单引号 {{ 'hi' }}，避免与外层双引号嵌套
3. 关键字 —— checked="false" 是字符串恒为真，必须写 checked="{{ false }}"
4. 空格陷阱 —— wx:if="{{ false }}" 带空格会被解析成字符串 "false"，恒为 true
5. setData —— 只有 setData 能触发渲染；支持 'user.name'、'orders[0].x' 路径式更新
6. 复杂度 —— 表达式保持简单，复杂计算放 JS 或 WXS，避免模板内长表达式
```

## 应用场景实战

### 场景一：用户信息卡片

用户中心页顶部信息卡片：展示头像、昵称、等级、会员状态、积分，涉及文本绑定、属性绑定、三元运算、字符串拼接与逻辑判断的综合运用。

```wxml
<!-- pages/user/user.wxml -->
<view class="user-card">
  <image class="user-avatar" src="{{ user.avatarUrl }}" mode="aspectFill"></image>
  <view class="user-info">
    <view class="user-name">
      {{ user.nickname }}
      <text class="vip-tag" wx:if="{{ user.isVip }}">VIP{{ user.vipLevel }}</text>
    </view>
    <view class="user-meta">{{ user.gender === 1 ? '男' : '女' }} · {{ user.city }} · {{ "注册 " + user.regDays + " 天" }}</view>
    <view class="user-points">积分：{{ user.points }}　{{ user.points >= 1000 ? '可兑换好礼' : '再攒 ' + (1000 - user.points) + ' 分可兑换' }}</view>
  </view>
  <view class="member-bar" wx:if="{{ !user.isVip }}">
    开通会员享 {{ memberDiscount }} 折优惠，点击开通 →
  </view>
</view>
```

```js
// pages/user/user.js
Page({
  data: {
    user: {
      avatarUrl: 'https://example.com/avatar/10001.png',
      nickname: '小明',
      isVip: true,
      vipLevel: 3,
      gender: 1,
      city: '上海',
      regDays: 365,
      points: 1280
    },
    memberDiscount: 8.8
  },
  onLoad() {
    // 模拟从后台（SpringBoot 接口）拉取用户信息
    wx.request({
      url: 'https://api.example.com/user/profile',
      success: (res) => {
        this.setData({ user: res.data.user })
      }
    })
  }
})
```

### 场景二：购物车行项目与模板组合传参

购物车列表每个行项目展示商品名、单价、数量、小计与优惠标记，需要价格计算（单价 × 数量）、三元判断（是否有优惠）与展开传参（把商品对象展开传给模板）的组合使用。

```wxml
<!-- pages/cart/cart.wxml -->
<view class="cart-item" wx:for="{{ cartList }}" wx:key="id">
  <view class="item-main">
    <view class="item-name">{{ item.name }}</view>
    <view class="item-price-row">
      <text class="price">¥{{ item.price * item.count }}</text>
      <text class="origin-price" wx:if="{{ item.price < item.originPrice }}">¥{{ item.originPrice * item.count }}</text>
      <text class="save-tag" wx:if="{{ item.price < item.originPrice }}">省 {{ (item.originPrice - item.price) * item.count }} 元</text>
    </view>
    <view class="item-count">数量：{{ item.count }}　{{ item.count >= 5 ? '已达批发优惠门槛' : '再买 ' + (5 - item.count) + ' 件享批发价' }}</view>
  </view>
  <view class="item-total">小计 ¥{{ (item.price * item.count).toFixed ? item.price * item.count : 0 }}</view>
</view>
```

## 最佳实践与踩坑记录

### 最佳实践

1. 页面 data 保持扁平：能一层结构表达就不要嵌套三层以上，深层路径既影响 setData diff 性能，也让模板可读性变差；后台返回的深层 JSON 在 JS 里先拍平再 setData
2. 模板只做轻量表达式：展示类计算（价格 × 数量、三元取文案）留在模板，涉及多次运算、格式化（金额、日期）的逻辑一律在 JS 算好或封装 WXS 函数
3. 优先使用 === 而不是 ==：模板中比较订单状态、商品类型等场景统一用严格相等，避免数字与字符串意外相等导致的分支错乱
4. 字符串字面量统一用单引号：{{ 'xxx' }} 避免与属性值外层双引号冲突，形成统一风格，减少引号嵌套错误
5. setData 使用路径式 key 精准更新：this.setData({ 'user.name': '小红' }) 比整对象替换性能更好、意图更清晰
6. 布尔渲染统一走 {{ true }}/{{ false }}：任何布尔属性（checked、disabled、wx:if）都不要直接写 true/false 裸关键字
7. 模板中的展示字段集中管理：需要动态拼接的文案（如「共 X 件」）在 data 中集中定义，模板内拼接尽量简短，便于后期国际化和文案调整

### 踩坑记录

```text
坑 1：{{ hi }} 不带引号导致渲染空白
结论：页面文本渲染为空，控制台无任何报错，排查半天才发现是字符串字面量没加引号。
原因：花括号内不加引号的标识符被当作数据路径处理，去 data 中取 data.hi，取不到就渲染为空字符串。
解法：字符串字面量必须写 {{ "hi" }} 或 {{ 'hi' }}；怀疑取值失败时先在 data 中确认字段存在。

坑 2：checked="false" 复选框依然选中
结论：checkbox 的 checked 写死 false 后仍然默认选中，与预期完全相反。
原因：checked="false" 中 false 是字符串，字符串 "false" 转为布尔值后是 true，所以复选框被选中。
解法：布尔属性一律写 checked="{{ false }}"，让框架按布尔值处理。

坑 3：wx:if="{{ false }}" 带空格导致条件恒为真
结论：wx:if 条件永远成立，该隐藏的内容一直显示。
原因：官方文档明确，花括号和引号（关键字）之间有空格时，会被解析成字符串 "false"，字符串恒为真值。
解法：wx:if="{{false}}" 关键字紧贴花括号，不要写 {{ false }} 这种带空格的写法。

坑 4：直接修改 this.data 页面不更新
结论：this.data.count = 2 执行后视图毫无变化，刷新才显示。
原因：小程序双线程模型中视图层与逻辑层数据不共享，只有 setData 会把数据同步到视图层并触发渲染。
解法：所有数据更新统一走 this.setData({...})；需要更新嵌套字段时用 'user.name' 路径式 key。

坑 5：属性值内双引号嵌套导致解析异常
结论：data-tip="{{ "点击查看" }}" 这类写法在部分场景解析异常或渲染错误。
原因：属性值外层已用双引号，内层字符串字面量再用双引号造成引号嵌套冲突。
解法：属性值内的字符串字面量统一用单引号，data-tip="{{ '点击查看' }}"。

坑 6：模板内调用函数 {{ formatPrice(price) }} 无效
结论：想复用 JS 里的格式化函数，结果渲染为空。
原因：WXML 模板表达式不支持函数调用，也不支持访问 Page 上的方法，这是模板语言的刻意限制。
解法：格式化逻辑在 JS 中预先算好放进 data；或定义 WXS 模块在模板中调用（见 05.5 WXS 脚本）。

坑 7：深层嵌套 data 导致 setData 性能问题
结论：列表大且字段嵌套深时，setData 频繁触发页面卡顿。
原因：setData 每次都会对 data 做 diff 并序列化传输，深层大对象增大开销；路径式更新写错时容易整对象覆盖。
解法：data 扁平化；用路径式 key 更新单个字段；大数据更新前先评估体积（见 13.3 setData 性能优化）。
```

## 概述

小程序是双线程架构：逻辑层（JavaScript 运行环境）与视图层（WXML/WXSS 渲染环境）相互隔离，逻辑层不能直接操作 DOM，视图层也不能直接拿到 JS 变量。唯一的桥梁就是 Page 实例上的 data 与 setData：data 声明初始数据，setData 把更新后的数据从逻辑层发送到视图层，触发 WXML 重新渲染。除了「逻辑层与视图层」这条纵向通道，数据还经常需要在页面与页面、页面与组件、组件与组件之间横向流动，形成完整的通信体系。

本章覆盖数据通信的五个层次：data 定义与更新、setData 机制与性能、页面间传参（URL query、getCurrentPages、EventChannel）、组件间通信（properties、triggerEvent、selectComponent）、全局数据 globalData。

```text
数据通信体系：
1. data —— 页面数据的唯一声明来源，JSON 可序列化对象
2. setData —— 逻辑层到视图层的数据通道，key 路径精准更新
3. 页面间传参 —— navigateTo URL query、getCurrentPages、EventChannel
4. 组件间通信 —— properties 下传、triggerEvent 上抛、selectComponent 直取
5. globalData —— App 级共享内存数据，非响应式需手动同步
6. 性能红线 —— setData 数据量要小、频率要低、路径要精准
```

## data 数据定义与读取

每个 Page 构造器都可以声明一个 data 对象，它是页面初始渲染数据的唯一来源。WXML 中通过双大括号插值 {{ }} 读取 data 中的字段，逻辑层通过 this.data 读取。data 中的值必须是 JSON 可序列化的类型（字符串、数字、布尔、数组、对象、null），不能放函数、Date 实例、Map 等类型，因为 data 要经过序列化传输到视图层。

```js
// pages/index/index.js
Page({
  // data 定义：所有需要渲染到视图层的数据都要在这里初始化
  data: {
    title: '微信小程序',
    count: 0,
    user: {
      name: '张三',
      level: 1
    },
    list: ['苹果', '香蕉', '橘子'],
    showLoading: true
  },

  onLoad() {
    // 逻辑层读取：this.data 始终同步反映最新值
    console.log(this.data.title);        // 微信小程序
    console.log(this.data.user.name);    // 张三
    console.log(this.data.list.length);  // 3
  }
});
```

```wxml
<!-- pages/index/index.wxml -->
<view>{{title}}</view>
<view>数量：{{count}}</view>
<view>用户：{{user.name}}，等级 Lv.{{user.level}}</view>
<view wx:for="{{list}}" wx:key="*this">{{item}}</view>
```

要点：data 中未初始化的字段在 WXML 中取值为 undefined，插值位置渲染为空，不会报错，但建议所有会用到的渲染字段都提前初始化，既方便阅读，也避免 setData 时临时补字段导致的类型不稳定。

```text
data 定义要点：
1. 类型 —— 仅限 JSON 可序列化类型，禁止函数、Date、Map 等
2. 初始化 —— 所有渲染字段提前声明，避免 undefined 渲染空白
3. 读取 —— 逻辑层用 this.data.xxx 同步读取，永远是最新值
4. 渲染 —— 视图层用 {{ }} 插值读取，支持嵌套路径 user.name
5. 分层 —— 只放渲染需要的数据，纯逻辑数据放普通属性或闭包
6. 命名 —— 与 WXML 插值保持同名，修改时两处同步
```

## setData 数据更新机制

setData 是逻辑层向视图层发送数据的唯一官方通道，语法为 this.setData(data, callback)。第一个参数是一个对象，key 可以是顶层字段名，也支持路径写法（如 'a.b'、'list[0].name'），实现深层精准更新；第二个参数是视图层渲染完成后的回调。setData 有一个容易被忽略的特性：调用后 this.data 会立即同步更新为新值，但视图层的渲染是异步的（逻辑层把数据发给视图层，视图层在渲染线程完成 diff 与重绘），所以 callback 才是「渲染真正完成」的时机。

```js
Page({
  data: {
    user: { name: '张三', level: 1 },
    list: [{ id: 1, price: 99 }, { id: 2, price: 199 }]
  },

  onLoad() {
    // 顶层字段更新
    this.setData({ 'user.name': '李四' });   // key 路径写法，精准更新嵌套字段

    // 数组下标更新
    this.setData({ 'list[0].price': 89 });   // 只更新第一个商品的 price

    // 合并多个字段，一次调用（推荐）
    this.setData({
      'user.level': 2,
      'list[1].price': 179
    }, () => {
      // 视图层渲染完成后的回调
      console.log('渲染完成，当前 this.data 已是新值');
    });

    // 注意：setData 调用后 this.data 立即同步更新
    console.log(this.data.user.name);  // 立即输出 李四，无需等待渲染
  },

  addCount() {
    // 经典错误示范：直接改 this.data 不触发渲染
    // this.data.count = this.data.count + 1;  // 视图不会更新！

    // 正确写法
    this.setData({ count: this.data.count + 1 });
  }
});
```

setData 的性能直接影响页面流畅度：数据量越大、频率越高，视图层 diff 与重绘成本越高。官方建议单次 setData 数据尽量小（远小于 1MB 上限）、避免高频调用、避免 setData 整个大对象。高频场景（滚动进度、拖拽、实时输入）应合并或节流后再 setData。

```text
setData 关键点：
1. 同步更新 —— 调用后 this.data 立即是新值，无需等待
2. 异步渲染 —— 视图层渲染异步进行，callback 才是渲染完成时机
3. 路径更新 —— key 支持 'a.b'、'list[0].x'，精准命中避免整对象传输
4. 合并调用 —— 多个字段一次 setData，减少通信次数
5. 性能红线 —— 控制单次数据量、降低调用频率、不做无谓更新
6. 禁忌 —— 直接 this.data.x = v 修改不会触发视图更新
```

## 页面间传参

页面跳转是数据通信的高频场景。最基础的方式是 wx.navigateTo 的 url 上带 query 参数，目标页在 onLoad(options) 中接收。query 参数全部是字符串，复杂对象需要 JSON.stringify 序列化后再传输，且 url 有长度限制（建议控制在 1024 字符内），特殊字符必须 encodeURIComponent 编码。

```js
// pages/list/list.js —— 跳转并传参
Page({
  goDetail(e) {
    const id = e.currentTarget.dataset.id;
    // 数字 id 会被转成字符串，复杂参数需要序列化 + 编码
    wx.navigateTo({
      url: '/pages/detail/detail?id=' + id + '&name=' + encodeURIComponent('苹果手机')
    });
  }
});

// pages/detail/detail.js —— 接收参数
Page({
  onLoad(options) {
    console.log(options.id);    // '1001'，注意是字符串
    console.log(options.name);  // 苹果手机（已自动解码）
  }
});
```

当需要在跳转后反向通信（详情页改动了数据，返回列表页要刷新）时，有两条常用路线。其一是 getCurrentPages() 获取页面栈，直接操作前一页实例；其二是 EventChannel（事件通道），由 wx.navigateTo 的 events 参数与 success 回调中的 eventChannel 建立双向通道，适合回调式通信，比操作页面栈更干净。

```js
// pages/list/list.js —— 使用 EventChannel 接收详情页回传
Page({
  goDetail() {
    wx.navigateTo({
      url: '/pages/detail/detail?id=1001',
      // events：监听目标页通过 eventChannel 发来的事件
      events: {
        onUpdated(res) {
          console.log('详情页回传：', res.data);   // { favorite: true }
          this.refreshList();                      // 刷新列表
        }
      },
      success(res) {
        // res.eventChannel：向目标页发消息
        res.eventChannel.emit('initData', { from: 'list' });
      }
    });
  },

  refreshList() {
    // 也可以直接用页面栈方式：取上一页实例 setData
    const pages = getCurrentPages();          // 页面栈数组，最后一个是当前页
    const prevPage = pages[pages.length - 2]; // 上一页
    prevPage.setData({ 'detail.favorited': true });
  }
});

// pages/detail/detail.js —— 目标页接收与回传
Page({
  onLoad(options) {
    // 获取打开本页时建立的 EventChannel
    const channel = this.getOpenerEventChannel();
    if (channel) {
      channel.on('initData', (data) => {
        console.log('收到来源页消息：', data);   // { from: 'list' }
      });
      // 主动回传
      channel.emit('onUpdated', { favorite: true });
    }
  }
});
```

页面栈机制本身也是一种通信资源：getCurrentPages() 返回栈内所有页面实例，可以读取任意页面的 data、调用其方法，但只建议用于「取上一页」这类轻量场景，跨多层修改页面状态容易造成数据流混乱。

```text
页面间传参方式对比：
1. URL query —— 简单参数首选，onLoad(options) 接收，全为字符串
2. encodeURIComponent —— 特殊字符与中文必须编码，否则截断或乱码
3. EventChannel —— navigateTo 建立双向事件通道，回调式通信最规范
4. getCurrentPages —— 页面栈取上一页实例，轻量同步场景可用
5. 大体积数据 —— 超过 url 限制的走 globalData 或 Storage 中转
6. 栈上限 —— 页面栈最多 10 层，navigateTo 超出会静默失败
```

## 组件间通信

自定义组件与页面（或组件与组件）之间有三条标准通道。父传子用 properties（属性），子传父用 triggerEvent（自定义事件），页面主动操作组件用 selectComponent 获取组件实例。三条通道组合起来可以覆盖绝大多数组件通信场景。

```js
// components/counter/counter.js —— 子组件
Component({
  properties: {
    // 父组件传入的初始值（父传子）
    initValue: {
      type: Number,
      value: 0
    }
  },
  data: {
    count: 0
  },
  lifetimes: {
    attached() {
      this.setData({ count: this.properties.initValue });
    }
  },
  methods: {
    add() {
      this.setData({ count: this.data.count + 1 });
      // 子传父：triggerEvent 抛出自定义事件，detail 携带数据
      this.triggerEvent('change', { value: this.data.count });
    }
  }
});
```

```wxml
<!-- pages/index/index.wxml —— 父页面使用组件 -->
<!-- bind:change 监听子组件抛出的 change 事件，detail 即 triggerEvent 的第二个参数 -->
<counter init-value="{{startCount}}" bind:change="onCounterChange" id="myCounter" />
```

```js
// pages/index/index.js —— 父页面
Page({
  data: {
    startCount: 5,
    total: 0
  },

  onCounterChange(e) {
    // e.detail 就是子组件 triggerEvent 传来的数据
    this.setData({ total: e.detail.value });
  },

  resetCounter() {
    // selectComponent 获取组件实例，直接调用其方法或 setData
    const counter = this.selectComponent('#myCounter');
    if (counter) {
      counter.setData({ count: 0 });
    }
  }
});
```

注意 properties 传入对象/数组时是引用传递：子组件内直接修改 properties 对象的内部字段会影响父组件的数据，容易造成隐性耦合，需要修改时应复制一份再操作。兄弟组件（同一页面下的两个组件）之间没有直接通道，标准做法是：子组件 triggerEvent 上报到页面，页面再通过另一个组件的 properties 或 selectComponent 下发，即「页面中转」模式。

```text
组件间通信三条通道：
1. properties —— 父传子，声明属性类型与默认值，单向数据流
2. triggerEvent —— 子传父，detail 携带数据，父页面 bind:事件 接收
3. selectComponent —— 页面主动获取组件实例，调用方法或 setData
4. 对象传值 —— properties 传对象是引用共享，内部修改会波及父组件
5. 兄弟通信 —— 无直接通道，经页面中转：上报 + 下发
6. 命名规范 —— 事件名小写加连字符（bind:my-event），属性用驼峰
```

## 全局数据 globalData

globalData 是 App 实例上挂载的全局对象，定义在 app.js 中，任何页面或组件通过 getApp() 都能访问。它常用来存放登录态、用户信息、系统信息等「一次获取、处处使用」的数据，避免每个页面重复请求或重复传参。

```js
// app.js
App({
  globalData: {
    userInfo: null,        // 登录后填充
    token: '',
    systemInfo: null       // 设备信息
  },

  onLaunch() {
    // 启动时从本地缓存恢复，实现「缓存预热」
    const token = wx.getStorageSync('token');
    if (token) {
      this.globalData.token = token;
    }
    this.globalData.systemInfo = wx.getSystemInfoSync();
  }
});
```

```js
// pages/profile/profile.js —— 读取与写入全局数据
const app = getApp();

Page({
  data: {
    nickname: '未登录'
  },

  onShow() {
    // 读取
    if (app.globalData.userInfo) {
      this.setData({ nickname: app.globalData.userInfo.nickname });
    }
  },

  login() {
    // 模拟登录成功后写入
    app.globalData.userInfo = { nickname: '张三', avatar: 'https://...' };
    // globalData 不是响应式的！改完必须手动 setData 同步到视图
    this.setData({ nickname: app.globalData.userInfo.nickname });
  }
});
```

globalData 是纯内存数据，App 被杀掉（冷启动）后即丢失，因此需要持久化的数据（token、用户信息）要与 wx.setStorageSync 搭配：写入时双写，启动时读取预热。另外 globalData 不具备响应式能力，修改它不会触发任何页面更新，页面必须在 onShow 或修改后主动 setData 同步，这是新手最容易踩的坑。

```text
globalData 使用要点：
1. 定义 —— app.js 的 App({ globalData: {...} })，全局唯一实例
2. 读取 —— getApp().globalData.xxx，页面与组件通用
3. 非响应式 —— 修改后不会自动触发视图更新，需手动 setData
4. 生命周期 —— 纯内存数据，冷启动丢失，需配合 Storage 持久化
5. 适用场景 —— 登录态、用户信息、系统信息等全局共享数据
6. 慎用 —— 大对象与高频变更数据放 globalData 会带来隐性耦合
```

## 应用场景实战

### 场景一：商品列表跳详情 + EventChannel 回传收藏状态

电商类页面最常见的联动：列表页展示商品，点击进入详情页，详情页收藏商品后返回，列表页要立刻反映收藏状态。这里组合使用 URL query 传 id、EventChannel 回传事件，比页面栈直改更解耦。

```wxml
<!-- pages/goods/goods.wxml -->
<view class="goods-card" wx:for="{{goodsList}}" wx:key="id"
      data-id="{{item.id}}" bindtap="goDetail">
  <text>{{item.name}}</text>
  <text class="price">¥{{item.price}}</text>
  <text wx:if="{{item.favorited}}" class="tag">已收藏</text>
</view>
```

```js
// pages/goods/goods.js
Page({
  data: {
    goodsList: [
      { id: 1, name: '蓝牙耳机', price: 199, favorited: false },
      { id: 2, name: '机械键盘', price: 399, favorited: false }
    ]
  },

  goDetail(e) {
    const id = e.currentTarget.dataset.id;
    wx.navigateTo({
      url: '/pages/goods/detail?id=' + id,
      events: {
        // 详情页收藏后回传
        onFavorited(res) {
          const list = this.data.goodsList.map(item =>
            item.id === res.id ? { ...item, favorited: true } : item
          );
          this.setData({ goodsList: list });
        }
      }
    });
  }
});
```

```js
// pages/goods/detail.js —— 详情页
Page({
  data: { id: null, favorited: false },

  onLoad(options) {
    this.setData({ id: Number(options.id) });  // query 是字符串，转数字
  },

  onFavorite() {
    this.setData({ favorited: true });
    const channel = this.getOpenerEventChannel();
    if (channel) {
      channel.emit('onFavorited', { id: this.data.id });
    }
  }
});
```

要点：query 只传轻量 id；收藏状态这种「回执」用 EventChannel 事件；列表页在事件回调里用 map 精准更新对应项，而不是整列表 setData。

### 场景二：购物车组件与页面双向联动

购物车组件负责加减数量，页面顶部展示总价，底部展示合计，还要支持页面主动清空购物车。完整演示 properties（初始数据下传）、triggerEvent（数量变化上抛）、selectComponent（页面主动清空）三条通道的协同。

```js
// components/cart-item/cart-item.js
Component({
  properties: {
    item: { type: Object, value: {} }   // 父页面传入的商品对象
  },
  methods: {
    add() {
      this.triggerEvent('change', { id: this.properties.item.id, delta: 1 });
    },
    minus() {
      this.triggerEvent('change', { id: this.properties.item.id, delta: -1 });
    },
    // 供页面通过 selectComponent 调用的清空方法
    clear() {
      this.setData({ 'item.count': 0 });
    }
  }
});
```

```wxml
<!-- pages/cart/cart.wxml -->
<view class="summary">共 {{totalCount}} 件，合计 ¥{{totalPrice}}</view>

<cart-item wx:for="{{cartList}}" wx:key="id"
           item="{{item}}" bind:change="onItemChange" id="cart-{{item.id}}" />

<button bindtap="clearAll">清空购物车</button>
```

```js
// pages/cart/cart.js
Page({
  data: {
    cartList: [
      { id: 1, name: '牛奶', price: 5, count: 2 },
      { id: 2, name: '面包', price: 8, count: 1 }
    ],
    totalCount: 3,
    totalPrice: 18
  },

  onItemChange(e) {
    const { id, delta } = e.detail;
    // 用路径写法精准更新对应项的数量
    const index = this.data.cartList.findIndex(i => i.id === id);
    this.setData({
      ['cartList[' + index + '].count']: this.data.cartList[index].count + delta
    });
    this.calcTotal();
  },

  calcTotal() {
    let count = 0, price = 0;
    this.data.cartList.forEach(i => {
      count += i.count;
      price += i.count * i.price;
    });
    this.setData({ totalCount: count, totalPrice: price });
  },

  clearAll() {
    // selectComponent 批量清空所有购物车组件
    this.data.cartList.forEach(i => {
      const comp = this.selectComponent('#cart-' + i.id);
      if (comp) comp.clear();
    });
    this.calcTotal();
  }
});
```

要点：父子数据流单向（父传 properties、子抛 triggerEvent），页面是唯一的数据中枢；数量变化用数组下标路径 setData，避免整数组重传；selectComponent 的 id 选择器要求 id 全局唯一，用商品 id 拼接保证唯一性。

## 最佳实践与踩坑记录

### 最佳实践

1. data 中初始化所有渲染字段：类型明确、可读性好，避免 undefined 渲染空白与 setData 时类型漂移
2. setData 优先用 key 路径精准更新嵌套字段（'user.name'、'list[0].price'），不要整个对象重传
3. 多个字段更新合并为一次 setData 调用，高频场景（输入、滚动、拖拽）先节流合并再发送
4. 页面跳转参数只传 id 等轻量标识，复杂对象优先走 EventChannel、globalData 或 Storage，注意 url 长度限制
5. 组件通信严格单向：父传 properties、子抛 triggerEvent、页面用 selectComponent 兜底，避免直接跨层改数据
6. globalData 只放「读多写少」的全局数据（登录态、用户信息、系统信息），写入时同步双写 Storage，冷启动时读取预热
7. 纯逻辑数据（不参与渲染的临时变量）放 data 之外，减少每次 setData 的序列化开销
8. 视图层渲染依赖多个数据时，先计算好再 setData，让 WXML 只做插值，不在模板里写复杂表达式

### 踩坑记录

```text
坑 1：直接修改 this.data 视图不更新
结论：this.data.count = 1 后页面毫无反应，数据变了但界面没变。
原因：视图层只认 setData 通道发来的数据，直接改 this.data 只改了逻辑层内存。
解法：所有视图更新一律 this.setData({...})；只在读取场景用 this.data。

坑 2：setData 传了 undefined 值导致字段丢失
结论：setData({ 'user.name': undefined }) 后 WXML 中 user.name 渲染为空，甚至报 undefined。
原因：data 需要 JSON 序列化传输，undefined 字段在序列化时被丢弃。
解法：不存在的值用 null 占位；setData 前校验字段是否存在，避免传 undefined。

坑 3：高频 setData 导致页面卡顿掉帧
结论：滚动、拖拽、实时输入时频繁 setData，页面明显卡顿。
原因：每次 setData 都要序列化、跨线程传输、视图层 diff 重绘，高频调用成本叠加。
解法：节流/合并（如 16ms 一帧只发一次）；只更新变化的最小字段；能用 WXS 响应的交互用 WXS。

坑 4：navigateTo 传参特殊字符被截断或乱码
结论：url 带中文、&、= 等字符时，目标页收到的参数被截断或乱码。
原因：query 字符串未编码，& = 被当作参数分隔符解析，中文按原始编码传输。
解法：所有参数先 encodeURIComponent 再拼接，接收端自动解码；超长数据走 globalData 或 Storage。

坑 5：页面栈超过 10 层后 navigateTo 静默失败
结论：连续跳转 11 次后，最后一次 navigateTo 没有任何反应也不报错。
原因：小程序页面栈深度上限为 10 层，超出后 navigateTo 直接失败。
解法：用 wx.redirectTo 替换当前页（详情类页面）或 wx.switchTab 切 tab；必要时重新组织跳转层级。

坑 6：修改 globalData 后页面不刷新
结论：login() 里改了 app.globalData.userInfo，页面头像昵称还是旧的。
原因：globalData 是普通内存对象，不具备响应式，修改不会通知任何页面。
解法：修改后手动 this.setData 同步；依赖全局数据的页面在 onShow 里重新读取并 setData。

坑 7：组件 properties 传对象被内部修改，父组件数据被连带改掉
结论：子组件里改了 this.properties.item.xxx，父页面 data 中对应对象也跟着变了。
原因：对象/数组按引用传递，子组件改的是同一个对象。
解法：子组件内部先拷贝（JSON.parse(JSON.stringify(x)) 或 {...x}）再操作；只读不写 properties。

坑 8：EventChannel 监听重复触发或内存泄漏
结论：详情页多次 emit，列表页回调执行多次；页面销毁后事件仍被触发。
原因：on() 注册的监听未随页面销毁移除，或页面栈残留旧监听。
解法：在 onUnload 中调用 channel.off('事件名')；emit 前确认 channel 存在；避免在回调里做重量级操作。
```

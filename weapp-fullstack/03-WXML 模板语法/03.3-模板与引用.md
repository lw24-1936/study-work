## 概述

模板与引用解决「结构复用」问题：同一段 WXML 结构（商品卡片、订单行、空态提示）在多个页面重复出现时，用 template 定义一次、随处引用，避免复制粘贴；跨文件复用则通过 import 与 include 引入其他 .wxml 文件。模板是纯展示层的复用单元，没有独立逻辑、没有样式隔离、没有生命周期，这与自定义组件（Component）有本质区别。

三种引用机制定位不同：template 是「定义-引用」模型，先定义模板再按名引用；import 引入其他文件中的 template 定义；include 则是把目标文件内容整体拷贝到当前位置，连模板外的普通结构代码也能复用。理解三者的边界（是否能递归、是否传递、拷贝还是引用）是本章的核心。

```text
模板与引用核心要点：
1. template —— 用 name 定义模板，用 is 按名引用，data 传参
2. 模板作用域 —— 模板内只能访问传入的 data，不能访问页面 data 与方法
3. import —— 引入其他文件的 template 定义，不能递归引用、引用不传递
4. include —— 拷贝目标文件除 template/wxs 外的全部代码到当前位置
5. 传参方式 —— data="{{...item}}" 展开传参，支持对象组合
6. 与组件区别 —— 模板无逻辑/样式隔离/生命周期；自定义组件全都有
```

## template 模板定义与使用

template 是 WXML 中的模板标签：用 name 属性给模板命名，模板内部书写可复用的结构代码；使用时用 <template is="模板名"> 按名引用，并用 data 属性传入数据。模板本身不渲染任何节点，只有被 is 引用时才会渲染出内部结构。

定义与引用（同文件内）：

```wxml
<!-- pages/index/index.wxml -->
<!-- 定义模板：商品卡片 -->
<template name="goodsCard">
  <view class="goods-card">
    <image class="goods-img" src="{{ image }}" mode="aspectFill"></image>
    <view class="goods-name">{{ name }}</view>
    <view class="goods-price">¥{{ price }}</view>
  </view>
</template>

<!-- 引用模板：data 传入数据 -->
<template is="goodsCard" data="{{ ...goods1 }}"></template>
<template is="goodsCard" data="{{ ...goods2 }}"></template>
```

```js
// pages/index/index.js
Page({
  data: {
    goods1: { image: 'https://example.com/img/a.png', name: '蓝牙耳机', price: 199 },
    goods2: { image: 'https://example.com/img/b.png', name: '机械键盘', price: 399 }
  }
})
```

is 的值可以是动态表达式，根据条件选择渲染哪个模板：

```wxml
<!-- 动态模板：is="{{ type === 'video' ? 'videoCard' : 'imageCard' }}" -->
<template is="{{ itemType }}" data="{{ ...item }}"></template>
```

```js
Page({
  data: {
    itemType: 'videoCard',
    item: { title: '演示视频', duration: '03:25', cover: 'https://example.com/img/cover.png' }
  }
})
```

模板内可以正常书写事件绑定，事件处理函数定义在使用该模板的页面 JS 中，通过 dataset 传参：

```wxml
<template name="goodsCard">
  <!-- 模板内绑定事件：handler 在页面 JS 中定义 -->
  <view class="goods-card" bindtap="onGoodsTap" data-id="{{ id }}">
    <image class="goods-img" src="{{ image }}" mode="aspectFill"></image>
    <view class="goods-name">{{ name }}</view>
    <view class="goods-price">¥{{ price }}</view>
  </view>
</template>
```

```js
// 页面 JS：模板内的事件处理函数在这里
Page({
  onGoodsTap(e) {
    const id = e.currentTarget.dataset.id
    wx.navigateTo({ url: '/pages/goods/detail?id=' + id })
  }
})
```

```text
template 要点：
1. 定义 —— <template name="模板名">...</template>，name 在文件内唯一
2. 引用 —— <template is="模板名" data="..."></template>，is 支持动态表达式
3. 不渲染自身 —— template 标签本身不产生节点，只渲染内部结构
4. 传参 —— data 属性传入模板所需数据，模板内直接用字段名
5. 事件 —— 模板内可写 bindtap 等事件绑定，处理函数在使用方页面 JS 中
6. 复用单位 —— 适合纯展示结构的复用；带逻辑交互的复用应选自定义组件
```

## 模板传参与作用域

模板作用域是理解模板的关键：模板内部只能访问传入 data 中的数据，不能访问页面 data 中的其他字段，也不能调用页面 JS 的方法。传入什么、模板里才能用什么，模板与页面之间没有隐式数据通道。

传参的三种姿势：整体传对象、按字段传、展开传：

```wxml
<!-- pages/goods/list.wxml -->
<template name="goodsCard">
  <view class="goods-card">
    <view>{{ name }} / {{ price }} 元 / 库存 {{ stock }}</view>
  </view>
</template>

<!-- 姿势一：整体传对象，模板内用 {{ item.xxx }} 访问 -->
<template is="goodsCard" data="{{ item: goods }}"></template>
<!-- 等价写法：data="{{ { item: goods } }}" -->

<!-- 姿势二：按字段展开传，模板内直接用字段名 -->
<template is="goodsCard" data="{{ name: goods.name, price: goods.price, stock: goods.stock }}"></template>

<!-- 姿势三（推荐）：展开运算符，模板内直接用字段名 -->
<template is="goodsCard" data="{{ ...goods }}"></template>
```

```js
Page({
  data: {
    goods: { name: '蓝牙耳机', price: 199, stock: 50, sales: 1200 }
  }
})
```

传入的 data 在模板中组合生效：展开与追加字段混用，追加字段可覆盖展开的同名键：

```wxml
<!-- 展开全部字段，再追加/覆盖展示位标记 -->
<template is="goodsCard" data="{{ ...goods, showStock: true, price: '特惠 ' + price }}"></template>

<!-- 多对象展开合并 -->
<template is="goodsCard" data="{{ ...base, ...sale, tag: '限时特惠' }}"></template>
```

作用域隔离的正确理解：模板内部不能访问页面 data 的未传字段，传什么用什么；反之，模板内部声明的变量（如 wx:for 的 item）也不影响页面。基于此，模板适合接收「完整的展示数据对象」，页面在 JS 中组装好再传入：

```js
// 页面 JS：组装好完整数据再传模板
Page({
  data: { goodsList: [] },
  onLoad() {
    wx.request({
      url: 'https://api.example.com/goods/list',
      success: (res) => {
        // 后台数据缺字段时，在 JS 中补齐默认值，模板不做兜底逻辑
        const list = res.data.list.map((g) => ({
          ...g,
          showStock: true,
          salesText: g.sales > 0 ? '已售 ' + g.sales + ' 件' : '新品'
        }))
        this.setData({ goodsList: list })
      }
    })
  }
})
```

```text
模板传参与作用域要点：
1. 数据来源 —— 模板只能访问 data 传入的字段，页面其他 data 不可见
2. 整体传参 —— data="{{ item: obj }}" 模板内 {{ item.xxx }} 访问
3. 展开传参 —— data="{{ ...obj }}" 字段平铺，模板内直接用字段名，最常用
4. 组合传参 —— 展开 + 追加字段混用，追加字段可覆盖同名键
5. 方法隔离 —— 模板不能调用页面方法，事件处理函数虽在页面 JS 但模板内只能绑定名字
6. 数据组装 —— 缺字段、默认值、格式化在页面 JS 完成，模板保持纯展示
```

## import 引用

import 用于在 WXML 文件中引入其他文件的 template 定义：<import src="目标文件路径" />。import 之后，当前文件就能用 is 引用目标文件中定义的 template。import 有两条硬性规则：不能递归引用、引用不传递。

基本用法：把模板定义抽到独立文件，多个页面 import 复用：

```wxml
<!-- components/templates/goods-card.wxml（模板定义文件） -->
<template name="goodsCard">
  <view class="goods-card" bindtap="onGoodsTap" data-id="{{ id }}">
    <image class="goods-img" src="{{ image }}" mode="aspectFill"></image>
    <view class="goods-name">{{ name }}</view>
    <view class="goods-price">¥{{ price }}</view>
  </view>
</template>
```

```wxml
<!-- pages/index/index.wxml：import 后即可引用 -->
<import src="../../components/templates/goods-card.wxml" />
<template is="goodsCard" data="{{ ...goods1 }}"></template>
<template is="goodsCard" data="{{ ...goods2 }}"></template>
```

规则一：不能递归引用。A 文件 import 了 B 文件，B 文件不能再 import A 文件（直接或间接循环都不行），否则会陷入循环引用错误：

```wxml
<!-- a.wxml -->
<import src="b.wxml" />   <!-- a 引 b -->
<template is="cardB"></template>

<!-- b.wxml -->
<import src="a.wxml" />   <!-- b 又引 a：递归引用，不允许 -->
<template is="cardA"></template>
```

规则二：引用不传递（非传递性）。A import 了 B，B import 了 C，A 只能使用 B 中的 template，不能使用 C 中的 template。需要哪个文件的模板，就 import 哪个文件：

```wxml
<!-- a.wxml：只 import 了 b，只能使用 b 中的模板 -->
<import src="b.wxml" />
<template is="cardB"></template>  <!-- 可用 -->
<template is="cardC"></template>  <!-- 不可用：cardC 定义在 c.wxml 中 -->

<!-- b.wxml -->
<import src="c.wxml" />
<template name="cardB">...</template>

<!-- c.wxml -->
<template name="cardC">...</template>
```

import 引用的模板名冲突处理：同一文件内多次 import 的模板若同名，后 import 的覆盖先 import 的（文件内定义优先）：

```wxml
<import src="card-a.wxml" />  <!-- 定义 goodsCard -->
<import src="card-b.wxml" />  <!-- 也定义 goodsCard：覆盖 card-a 的版本 -->
<template is="goodsCard" data="{{ ...item }}"></template>  <!-- 实际用的是 card-b 的 -->
```

```text
import 要点：
1. 语法 —— <import src="路径" /> 引入其他文件的 template 定义
2. 使用 —— import 后即可用 is 引用目标文件中的 template
3. 递归禁止 —— A 引 B、B 不能再引 A，循环引用报错
4. 不传递 —— A 引 B、B 引 C，A 不能用 C 的模板，需要就再 import
5. 同名覆盖 —— 多处 import 的模板同名时后定义覆盖先定义
6. 定位 —— import 只引入 template 定义，目标文件的其他代码不生效
```

## include 引用

include 与 import 定位不同：include 是「拷贝语义」，把目标文件除了 template 与 wxs 之外的整个代码原样拷贝到 include 所在位置，相当于就地粘贴。因此 include 可以复用普通的结构代码（view 片段、公共头部底部），这是 import 做不到的。

基本用法：把公共头部抽成独立文件，页面 include 引入：

```wxml
<!-- components/header.wxml（公共头部片段） -->
<view class="page-header">
  <text class="header-title">{{ pageTitle }}</text>
  <view class="header-sub">共 {{ total }} 条数据</view>
</view>
```

```wxml
<!-- pages/list/list.wxml：include 相当于把上面代码粘贴到这里 -->
<include src="../../components/header.wxml" />
<view class="content">列表内容...</view>
```

include 的拷贝特性：目标文件中的普通代码、wx:if、wx:for 等全部生效，且能访问当前页面的 data（因为代码是被拷贝进来的，运行在当前页面上下文中）：

```wxml
<!-- components/common-parts.wxml -->
<view class="tip-bar" wx:if="{{ showTip }}">{{ tipText }}</view>
<view class="divider"></view>
```

```wxml
<!-- pages/index/index.wxml -->
<include src="../../components/common-parts.wxml" />
<!-- 展开后等价于： -->
<!-- <view class="tip-bar" wx:if="{{ showTip }}">{{ tipText }}</view> -->
<!-- <view class="divider"></view> -->
<!-- showTip / tipText 直接取当前页面的 data -->
```

```js
// pages/index/index.js —— include 进来的代码直接使用页面 data
Page({
  data: {
    showTip: true,
    tipText: '本周会员日双倍积分',
    pageTitle: '首页',
    total: 12
  }
})
```

include 与 template 的边界：include 目标文件中的 template 定义与 wxs 不会被拷贝（官方规则：除 template/wxs 外全部引入）。如果 include 的文件里写了 template，需要另外 import 才能使用：

```wxml
<!-- parts.wxml：包含 template 定义与普通结构 -->
<template name="innerCard">...</template>
<view class="common-tip">公共提示</view>
```

```wxml
<!-- 使用方：include 只拷贝了 common-tip，innerCard 模板需要用 import 引入 -->
<include src="parts.wxml" />
<import src="parts.wxml" />
<template is="innerCard" data="{{ ...item }}"></template>
```

```text
include 要点：
1. 拷贝语义 —— 目标文件代码原样拷贝到 include 位置，相当于就地粘贴
2. 排除项 —— template 定义与 wxs 不会被拷贝，其余代码全部引入
3. 上下文 —— 拷贝进来的代码运行在使用方页面上下文，直接访问页面 data
4. 适用场景 —— 公共头部、底部、脚注、无模板化的重复片段
5. 与 import 分工 —— 复用 template 定义用 import，复用普通结构代码用 include
6. 注意 —— include 的位置即代码生效的位置，多次 include 同一文件会重复渲染
```

## WXML 引用规则与组件的关系

import / include 是 WXML 层面的引用机制，只解决「结构代码复用」；自定义组件（Component）是能力更完整的复用单元。两者是不同层级的东西，可以组合使用，但职责边界要清楚。

三种复用手段的完整对比：

```text
template / import / include vs 自定义组件：
1. template —— 纯结构复用，无逻辑、无样式隔离、无生命周期，传参靠 data
2. import —— 引入 template 定义，不能递归、不传递，只认模板
3. include —— 拷贝普通结构代码，不能拷贝 template/wxs，上下文是使用方页面
4. 自定义组件 —— 独立 JS 逻辑、样式隔离（默认）、生命周期、属性（properties）
5. 通信 —— 模板靠 data 单向传参；组件靠 properties 传入 + triggerEvent 传出
6. 选型 —— 纯展示片段用模板；有交互/状态/复用多处用组件；公共静态片段用 include
```

自定义组件的引用方式完全不同：不需要 import/include，而是在 json 配置文件的 usingComponents 中声明，然后像内置组件一样使用标签：

```json
// pages/index/index.json —— 组件引用在 json 中配置，不是 WXML 引用
{
  "usingComponents": {
    "goods-card": "/components/goods-card/goods-card"
  }
}
```

```wxml
<!-- pages/index/index.wxml —— 组件按标签使用 -->
<goods-card goods="{{ goods }}" bind:buy="onBuy"></goods-card>
```

```js
// components/goods-card/goods-card.js —— 组件有独立逻辑
Component({
  properties: {
    goods: { type: Object, value: {} }
  },
  methods: {
    onBuy() {
      this.triggerEvent('buy', { id: this.data.goods.id })
    }
  }
})
```

选型判断：页面里同一结构出现 2 次以上、且后续大概率要加交互逻辑时，直接用自定义组件一步到位；只是纯展示、无状态、无事件交互的片段用 template；跨页面固定不变的静态片段（页头页尾、版权信息）用 include。模板与组件可以混用：模板内部也可以使用自定义组件标签。

```text
引用规则与组件关系要点：
1. 层级不同 —— import/include 是 WXML 结构引用；usingComponents 是组件注册
2. 组件引用 —— 在页面/组件 json 的 usingComponents 中声明路径
3. 组件能力 —— 逻辑、样式隔离、生命周期、properties/triggerEvent 通信
4. 模板局限 —— 无逻辑无隔离无生命周期，只能 data 单向传参
5. 组合使用 —— 模板内可以使用组件标签，两者不冲突
6. 选型标准 —— 纯展示用模板，有交互状态用组件，静态片段用 include
```

## 应用场景实战

### 场景一：商品卡片模板跨页面复用（template + import）

商品卡片在两个页面复用：首页推荐位与商品列表页。把卡片定义抽到独立文件 goods-card.wxml，两页 import 后各传各的数据；模板内绑定点击事件跳转详情。

```wxml
<!-- components/templates/goods-card.wxml -->
<template name="goodsCard">
  <view class="goods-card" bindtap="onCardTap" data-id="{{ id }}">
    <image class="goods-img" src="{{ image }}" mode="aspectFill"></image>
    <view class="goods-info">
      <view class="goods-name">{{ name }}</view>
      <view class="goods-tags">
        <text class="tag" wx:if="{{ isHot }}">热卖</text>
        <text class="tag tag-sale" wx:if="{{ price < originPrice }}">特惠</text>
      </view>
      <view class="goods-price-row">
        <text class="price">¥{{ price }}</text>
        <text class="sales">{{ salesText }}</text>
      </view>
    </view>
  </view>
</template>
```

```wxml
<!-- pages/index/index.wxml：首页推荐位 -->
<import src="../../components/templates/goods-card.wxml" />
<view class="recommend-title">为你推荐</view>
<view class="goods-grid">
  <block wx:for="{{ recommendGoods }}" wx:key="id">
    <template is="goodsCard" data="{{ ...item }}"></template>
  </block>
</view>
```

```wxml
<!-- pages/goods/list.wxml：商品列表页 -->
<import src="../../components/templates/goods-card.wxml" />
<view class="goods-list">
  <block wx:for="{{ goodsList }}" wx:key="id">
    <template is="goodsCard" data="{{ ...item }}"></template>
  </block>
</view>
```

```js
// pages/index/index.js（列表页 JS 结构相同）
Page({
  data: {
    recommendGoods: [
      { id: 1, name: '蓝牙耳机', price: 199, originPrice: 259, image: 'https://example.com/img/a.png', isHot: true, salesText: '已售 1200 件' },
      { id: 2, name: '机械键盘', price: 399, originPrice: 399, image: 'https://example.com/img/b.png', isHot: false, salesText: '已售 560 件' }
    ]
  },
  onCardTap(e) {
    const id = e.currentTarget.dataset.id
    wx.navigateTo({ url: '/pages/goods/detail?id=' + id })
  }
})
```

### 场景二：公共页头页脚复用（include）

多个页面的顶部标题栏（带页面标题与返回提示）与底部版权信息完全一致，用 include 抽成公共片段，页面 include 引入即可，代码直接使用各页面自己的 data。

```wxml
<!-- components/page-chrome.wxml -->
<view class="page-header">
  <view class="header-title">{{ pageTitle }}</view>
  <view class="header-sub">{{ headerSub }}</view>
</view>
<view class="page-body">
  <!-- 页面主体内容由使用方写在 include 之后 -->
</view>
```

```wxml
<!-- pages/order/order.wxml -->
<include src="../../components/page-chrome.wxml" />
<view class="order-list">
  <view class="order-item" wx:for="{{ orderList }}" wx:key="orderNo">{{ item.orderNo }}</view>
</view>
<include src="../../components/footer.wxml" />
```

```wxml
<!-- components/footer.wxml -->
<view class="page-footer">
  <text>Copyright 2026 示例商城 · 客服热线 400-000-0000</text>
</view>
```

```js
// pages/order/order.js —— include 的代码直接读这些 data
Page({
  data: {
    pageTitle: '我的订单',
    headerSub: '共 ' + 3 + ' 笔订单',
    orderList: [
      { orderNo: '202608200001' },
      { orderNo: '202608200002' },
      { orderNo: '202608200003' }
    ]
  }
})
```

```text
场景实战要点：
1. 跨页复用 —— 模板定义放独立文件，页面 import 后按 is 引用
2. 列表套模板 —— wx:for + block 中引用模板，data="{{...item}}" 展开传参
3. 模板内事件 —— bindtap 绑定 + data-id 传参，处理函数在使用方页面
4. include 页头 —— 公共标题栏代码直接访问各页面自己的 data（pageTitle）
5. 静态片段 —— 版权、客服信息用 include 复用，改一处全局生效
6. 组合使用 —— include 页头、import 模板、wx:for 列表可在同一页面共存
```

## 最佳实践与踩坑记录

### 最佳实践

1. 模板只做纯展示：模板内不写复杂逻辑，字段加工（默认值、文案拼接、格式化）在页面 JS 组装完成再传入，模板保持「给什么渲染什么」
2. 传参统一用展开运算符：data="{{...item}}" 比逐个字段传参简洁，字段增减时模板与调用方无需同步修改；需要追加标记时 {{...item, flag: true}}
3. 模板文件按目录归集：公共模板放 components/templates/ 下按业务命名，一个文件一个模板（或一组强关联模板），避免大杂烩文件
4. 事件处理函数在页面统一实现：模板内只绑定名字，处理函数在页面 JS 集中管理，用 data-id 传参而非在模板内做逻辑
5. include 只放静态片段：页头、页脚、版权、提示条等不变内容用 include；含交互的内容即使简单也考虑组件化
6. 需要交互就直接上组件：模板无法承载状态与样式隔离，交互复杂、多处复用的结构（点赞、购物车按钮、stepper）直接用自定义组件，避免模板后期重构
7. 复用结构超过两个页面使用就抽取：先出现 2 次再抽模板，避免过度抽象；抽取时同步补充 data 缺省值约定

### 踩坑记录

```text
坑 1：import 后模板不生效，控制台报 template not found
结论：import 了文件但 is 引用时报找不到模板，页面渲染空白。
原因：import 不具备传递性——A import B、B import C，A 只能用 B 的模板；或目标文件路径写错。
解法：需要哪个文件的模板就 import 哪个文件，检查 src 相对路径（从当前文件出发，注意层级 ../）。

坑 2：A import B、B import A 导致编译报错
结论：两个文件互相 import，编译直接报循环引用错误。
原因：import 不允许递归引用，直接或间接循环都会报错。
解法：模板依赖做成单向；公共模板下沉到公共目录（components/templates/），各文件只依赖公共层。

坑 3：模板内访问页面 data 的字段全部为空
结论：模板里写了 {{ pageTitle }} 之类的字段，渲染为空。
原因：模板作用域隔离，只能访问 data 传入的字段，页面 data 的字段必须显式传进来。
解法：用 data="{{...obj}}" 展开传入；或 data="{{ title: pageTitle, ...item }}" 组合传参。

坑 4：include 的文件里有 template 定义却用不了
结论：include 了包含 template 定义的文件，is 引用时报找不到模板。
原因：官方规则 include 只拷贝除 template/wxs 外的代码，template 定义不会被拷贝进来。
解法：模板定义用 import 引入；include 只用于普通结构代码；需要两者时 import 与 include 都写。

坑 5：include 同一文件多次导致内容重复渲染
结论：页面里 include 了两次同一个文件，公共片段出现两份。
原因：include 是拷贝语义，include 一次拷贝一份，多次 include 自然重复。
解法：确认只 include 一次；结构相同但位置不同的场景，考虑改成模板 + data 区分。

坑 6：模板内事件绑定点击无响应
结论：模板里写了 bindtap="onTap"，点击没有反应。
原因：模板本身不绑定事件上下文，处理函数必须在引用该模板的页面 JS 中定义；漏定义或函数名拼写不一致都会静默失败。
解法：在页面 JS 中定义同名处理函数；模板内通过 data-id 传参，用 e.currentTarget.dataset.id 取值。

坑 7：用模板复用的结构想加独立逻辑，改造成本高
结论：模板复用的商品卡片要加「加入购物车」交互与独立状态，模板难以承载。
原因：模板无独立逻辑、无样式隔离、无生命周期，交互状态无处安放。
解法：交互需求出现时立即重构为自定义组件（Component），模板回归纯展示场景。
```

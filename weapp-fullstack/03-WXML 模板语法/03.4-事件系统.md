## 概述

事件系统是 WXML 交互的基石：用户触摸、输入、提交表单时产生事件，通过 bind/catch 等绑定方式把事件与页面 JS 中的处理函数关联起来。与浏览器 DOM 事件类似，小程序事件也有捕获与冒泡阶段，但语法与事件对象（target/currentTarget/dataset）有自己的体系，列表渲染场景中 target 与 currentTarget 的区别、data-* 自定义数据传参是最常见的考点与踩坑点。

小程序事件分为「冒泡事件」（如 tap、longpress、input 的 change 类）与「非冒泡事件」（如 input 的 input 事件、scroll-view 的 scroll 事件等，不做冒泡传播）。事件处理函数统一接收一个 event 对象，通过它获取事件类型、触发节点、绑定节点、附加数据（dataset）与触摸信息，这也是 WXML 与 JS 交互的唯一通道。

```text
事件系统核心要点：
1. 绑定方式 —— bind / catch / mut-bind，冒泡行为各不相同
2. 事件类型 —— tap、longpress、input、change、submit 等内置事件
3. 事件对象 —— event 携带 type/timeStamp/target/currentTarget/detail/touches
4. 节点区分 —— target 是事件源节点，currentTarget 是绑定事件的节点
5. 传参通道 —— data-xxx 自定义属性经 event.currentTarget.dataset 获取
6. 组件事件 —— 自定义组件用 triggerEvent 上抛事件，父级 bind:xxx 接收
```

## 事件绑定 bind 与事件类型

事件绑定就是把节点上的事件与页面 JS 中的处理函数关联：bind 前缀（bindtap、bind:input）绑定事件，事件发生时调用对应处理函数。bind 绑定的事件默认会冒泡（冒泡事件类型），处理函数接收 event 对象作为参数。

两种等价的绑定写法：传统连写（bindtap）与冒号写法（bind:tap），冒号写法是官方推荐的新风格，两者混用不影响功能：

```wxml
<!-- pages/index/index.wxml -->
<button bindtap="onBtnTap">连写风格</button>
<button bind:tap="onBtnTap">冒号风格（推荐）</button>
<view bindtap="onViewTap">点击 view</view>
<image bind:error="onImgError" src="{{ imgUrl }}"></image>
```

常用事件类型速览（绑定在对应组件上）：

```wxml
<!-- 触摸类：view/button/image 等通用 -->
<view bindtap="onTap" bindlongpress="onLongPress">长按与点击</view>

<!-- 输入类：input 组件 -->
<input bindinput="onInput" bindfocus="onFocus" bindblur="onBlur" bindconfirm="onConfirm" />

<!-- 表单类：表单组件 -->
<form bindsubmit="onSubmit" bindreset="onReset">
  <button form-type="submit">提交</button>
</form>

<!-- 选择类：picker、switch、checkbox、radio -->
<picker bindchange="onPickerChange" range="{{ cityList }}"></picker>
<switch bindchange="onSwitchChange" />

<!-- 滚动与加载类：scroll-view、image 等 -->
<scroll-view bindscroll="onScroll" bindscrolltolower="onReachBottom"></scroll-view>
<image bindload="onImgLoad" binderror="onImgError" src="{{ url }}"></image>
```

处理函数定义在页面 JS 中，统一接收 event 参数：

```js
// pages/index/index.js
Page({
  onBtnTap() {
    wx.showToast({ title: '按钮被点击', icon: 'none' })
  },
  onInput(e) {
    // input 事件的 value 在 e.detail.value 中
    console.log('输入内容：', e.detail.value)
  },
  onSwitchChange(e) {
    console.log('开关状态：', e.detail.value)
  },
  onSubmit(e) {
    // form 表单的字段值集合在 e.detail.value 中
    console.log('表单数据：', e.detail.value)
  },
  onReachBottom() {
    console.log('滚动到底部，加载下一页')
  }
})
```

```text
bind 与事件类型要点：
1. 绑定语法 —— bindtap 与 bind:tap 等价，冒号写法是官方推荐风格
2. 冒泡事件 —— tap、longpress、touchstart、touchmove、change 等会冒泡
3. 非冒泡事件 —— input、scroll、load 等不冒泡（input 组件自身不冒泡）
4. 事件类型 —— 触摸类、输入类、表单类、选择类、滚动类覆盖全部内置组件
5. 处理函数 —— 在页面 JS 定义，接收 event 对象；漏定义时控制台告警
6. 传参方式 —— 绑定处不能直接传参，用 data-xxx + dataset 传递（见后文）
```

## 事件冒泡与阻止（catch、mut-bind）

事件传播分两个阶段：捕获阶段（从根节点向事件源节点传播）与冒泡阶段（从事件源节点向根节点传播）。默认绑定（bind）在冒泡阶段触发，事件会沿着节点树一路冒泡，父节点上的同类 bind 绑定会依次触发。要阻止冒泡，用 catch 绑定。

冒泡示例：点击内层 view，外层 view 的 bindtap 也会触发：

```wxml
<view class="outer" bindtap="onOuterTap">
  外层容器
  <view class="inner" bindtap="onInnerTap">内层按钮</view>
</view>
```

```js
// 点击内层时，onInnerTap 与 onOuterTap 都会触发（事件冒泡到外层）
Page({
  onInnerTap() { console.log('内层触发') },
  onOuterTap() { console.log('外层触发（冒泡到达）') }
})
```

catch 阻止冒泡：把内层绑定改为 catchtap，事件在内层处理后就停止传播，外层不再触发：

```wxml
<view class="outer" bindtap="onOuterTap">
  外层容器
  <view class="inner" catchtap="onInnerTap">内层按钮（catch 阻止冒泡）</view>
</view>
```

```js
// 点击内层时只有 onInnerTap 触发，onOuterTap 不再触发
Page({
  onInnerTap() { console.log('内层触发') },
  onOuterTap() { console.log('外层不会触发') }
})
```

mut-bind（互斥事件绑定）：与 catch 不同，mut-bind 触发自身处理函数，但阻止祖先节点上同类 mut-bind 绑定再次触发；祖先节点上的 bind 绑定仍会触发。同一事件类型的 mut-bind 在冒泡路径上只触发最靠近事件源的那个：

```wxml
<!-- 场景 A：内层 mut-bind、外层 bind —— 两个都会触发 -->
<view bind:touchstart="onOuter">
  <view mut-bind:touchstart="onInner">内层（mut-bind）</view>
</view>

<!-- 场景 B：内外都是 mut-bind —— 只触发内层 -->
<view mut-bind:touchstart="onOuter2">
  <view mut-bind:touchstart="onInner2">内层（mut-bind）</view>
</view>
```

```js
// 场景 A：点击内层，onInner 与 onOuter 都触发
// 场景 B：点击内层，只有 onInner2 触发，onOuter2 被互斥阻止
Page({
  onInner() {}, onOuter() {},
  onInner2() { console.log('只触发内层 mut-bind') },
  onOuter2() { console.log('不会触发') }
})
```

捕获阶段绑定：基础库 2.8.2+ 支持捕获阶段事件绑定，capture-bind 与 capture-catch 前缀。捕获阶段从根向叶子传播，capture-catch 可以中断捕获与后续传播：

```wxml
<!-- 捕获阶段：capture-bind:tap 先于 bindtap 触发 -->
<view capture-bind:tap="onCaptureOuter">
  <view capture-bind:tap="onCaptureInner" bindtap="onBubble">
    <view>点击这里</view>
  </view>
</view>
<!-- 触发顺序：onCaptureOuter → onCaptureInner → onBubble -->
```

```text
冒泡与阻止要点：
1. bind —— 冒泡阶段触发，事件沿节点树向上传播，父级同类绑定依次触发
2. catch —— 阻止冒泡，处理后事件不再向上传播（父级 bind 与 mut-bind 都不触发）
3. mut-bind —— 互斥绑定，触发自身但阻止祖先同类 mut-bind；不阻止祖先 bind
4. 最内层优先 —— 同类 mut-bind 在冒泡路径上只触发最靠近事件源的那个
5. 捕获阶段 —— capture-bind / capture-catch（2.8.2+），先于冒泡阶段执行
6. 选择 —— 独立按钮用 bind；「点击子元素不触发父级」用 catch；滑动类冲突用 mut-bind
```

## 事件对象 event 详解

事件处理函数的第一个参数 event 携带事件的完整信息，字段包括：type（事件类型）、timeStamp（触发时间戳）、target（事件源节点）、currentTarget（绑定节点）、detail（附加数据）、touches（触摸点数组）、changedTouches（变化的触摸点）、mark（事件源 mark 属性，2.7.1+）。

完整的事件对象结构：

```js
// 事件对象 event 的典型结构
{
  type: 'tap',                    // 事件类型
  timeStamp: 1781568000000,       // 事件生成时的毫秒时间戳
  target: {                       // 事件源节点（实际被点到的节点）
    id: 'inner',
    dataset: { id: 3 },
    offsetTop: 100,
    offsetLeft: 20
  },
  currentTarget: {                // 绑定事件处理的节点（处理函数所在的节点）
    id: 'card-3',
    dataset: { id: 3 },
    offsetTop: 80,
    offsetLeft: 0
  },
  detail: {                       // 附加信息，随事件类型不同而不同
    x: 120, y: 340,               // tap：点击坐标
    value: 'hello'                // input/change：组件当前值
  },
  touches: [                      // 当前屏幕上的触摸点数组（多指）
    { identifier: 0, pageX: 120, pageY: 340, clientX: 60, clientY: 200 }
  ],
  changedTouches: [               // 本次事件变化的触摸点
    { identifier: 0, pageX: 120, pageY: 340, clientX: 60, clientY: 200 }
  ],
  mark: { from: 'card' }          // 事件源节点上 mark:xxx 属性集合（2.7.1+）
}
```

detail 字段随事件类型变化，是获取组件值的主要通道：

```wxml
<input bindinput="onInput" placeholder="输入商品名" />
<slider bindchange="onSlider" min="0" max="100" />
<form bindsubmit="onSubmit">
  <input name="phone" placeholder="手机号" />
  <input name="code" placeholder="验证码" />
  <button form-type="submit">提交</button>
</form>
```

```js
Page({
  onInput(e) {
    // input 事件：e.detail.value 是输入框内容
    console.log('输入内容：', e.detail.value)
  },
  onSlider(e) {
    // slider 事件：e.detail.value 是当前滑块值
    console.log('滑块值：', e.detail.value)
  },
  onSubmit(e) {
    // form 提交：e.detail.value 是表单内所有带 name 字段的集合
    console.log('表单数据：', e.detail.value) // { phone: '...', code: '...' }
  }
})
```

touches 与 changedTouches 用于触摸类事件（touchstart/touchmove/touchend），实现滑动、拖拽、手势：

```js
Page({
  onTouchMove(e) {
    // touches[0] 是第一个触摸点，pageX/pageY 是相对页面的坐标
    const touch = e.touches[0]
    console.log('手指位置：', touch.pageX, touch.pageY)
  },
  onTouchEnd(e) {
    // touchend 时 touches 为空，变化点信息在 changedTouches 中
    const touch = e.changedTouches[0]
    console.log('手指抬起位置：', touch.pageX, touch.pageY)
  }
})
```

```text
事件对象要点：
1. type —— 事件类型字符串（tap/input/change/submit...）
2. timeStamp —— 事件生成时的毫秒时间戳
3. target / currentTarget —— 事件源节点与绑定节点，两者 dataset 都可能用到
4. detail —— 事件附加数据：input 的 value、form 的字段集合、tap 的坐标
5. touches / changedTouches —— 触摸点数组，滑动拖拽手势编程的基础
6. mark —— 事件源 mark:xxx 属性集合（2.7.1+），可跨节点携带标识
```

## currentTarget 与 target 的区别

target 与 currentTarget 是事件对象里最容易混淆的两个字段，冒泡场景下两者指向不同节点：target 是事件源（实际触发事件的节点，永远是冒泡起点），currentTarget 是当前处理函数绑定所在的节点。事件冒泡过程中，target 始终不变，currentTarget 随冒泡路径变化——当前执行到哪个节点的处理函数，currentTarget 就是哪个节点。

经典场景：列表卡片内有点赞按钮，卡片与按钮都绑定了 tap：

```wxml
<!-- pages/list/list.wxml -->
<view class="card" bindtap="onCardTap" data-type="card">
  <view class="card-title">{{ item.title }}</view>
  <view class="like-btn" catchtap="onLikeTap" data-id="{{ item.id }}">点赞</view>
</view>
```

```js
// pages/list/list.js
Page({
  onCardTap(e) {
    // 点击卡片空白处：target 与 currentTarget 都是卡片节点
    // 点击点赞按钮（未用 catch 时）：target 是点赞按钮，currentTarget 是卡片
    console.log('target 的 dataset：', e.target.dataset)          // 按钮的 { id: ... } 或卡片的 { type: 'card' }
    console.log('currentTarget 的 dataset：', e.currentTarget.dataset) // 始终是卡片的 { type: 'card' }
  },
  onLikeTap(e) {
    // catchtap 阻止了冒泡，这里只处理点赞
    // target 与 currentTarget 都是点赞按钮本身
    const id = e.currentTarget.dataset.id
    console.log('点赞商品 id：', id)
  }
})
```

核心规律与使用建议：

```text
currentTarget 与 target 的区别：
1. target —— 事件源节点：实际被点中的最内层节点，冒泡全程不变
2. currentTarget —— 绑定节点：当前执行处理函数的节点，冒泡中逐层变化
3. 同一节点 —— 点击处没有嵌套子节点时，两者相同
4. 取值原则 —— 取「绑定时想传的数据」用 currentTarget.dataset；取「用户实际点了什么」用 target.dataset
5. 冒泡路径 —— 事件从 target 冒泡到根，途中每个 bind 节点的处理函数里 currentTarget 都是该节点自身
6. 常见 bug —— 列表项点击事件里用 e.target.dataset 取列表项 id，点到子元素时取到 undefined
```

## dataset 自定义数据

data-* 自定义属性是 WXML 向事件处理函数传参的标准通道：在节点上写 data-xxx="值"，事件触发后在 event.currentTarget.dataset 中按驼峰规则取值。规则：data- 前缀后的属性名转小写，连字符（-）转驼峰（item-id → itemId），因此 data-item-id 取 dataset.itemId。

基本用法与命名转换规则：

```wxml
<!-- pages/goods/list.wxml -->
<view class="goods-item" wx:for="{{ goodsList }}" wx:key="id"
      bindtap="onGoodsTap"
      data-id="{{ item.id }}"
      data-item-name="{{ item.name }}"
      data-index="{{ index }}">
  {{ item.name }}
</view>
```

```js
// pages/goods/list.js
Page({
  onGoodsTap(e) {
    // data-id → dataset.id；data-item-name → dataset.itemName；data-index → dataset.index
    const { id, itemName, index } = e.currentTarget.dataset
    console.log('点击了：', id, itemName, '下标：', index)
    wx.navigateTo({ url: '/pages/goods/detail?id=' + id })
  }
})
```

dataset 传参的三个注意点：值会被转成字符串（数字 3 取出来是 "3"）；data- 后的字母统一转小写（data-ItemID 取 dataset.itemid）；在冒泡场景中取值要用 currentTarget.dataset（绑定的节点）而不是 target.dataset（实际点中的子节点）：

```wxml
<!-- 命名与取值对照 -->
<view data-USER-Id="1001" data-order-no="202608200001" bindtap="onTap">示例</view>
```

```js
Page({
  onTap(e) {
    // data-USER-Id → dataset.userid（大写转小写）
    // data-order-no → dataset.orderNo（连字符转驼峰）
    console.log(e.currentTarget.dataset.userid)   // "1001"
    console.log(e.currentTarget.dataset.orderNo)  // "202608200001"
  }
})
```

dataset 也可以传对象（基础库 2.8.1+ 支持），但对象会做 JSON 序列化，注意体积与性能：

```wxml
<view data-product="{{ item }}" bindtap="onTap">传对象</view>
```

```js
Page({
  onTap(e) {
    const product = e.currentTarget.dataset.product
    console.log(product.name, product.price)
  }
})
```

```text
dataset 要点：
1. 定义 —— data-xxx="值"，写在绑定事件节点的属性上
2. 取值 —— event.currentTarget.dataset.xxx（冒泡场景不要用 target）
3. 命名转换 —— 连字符转驼峰（item-id → itemId），大写转小写（ItemID → itemid）
4. 类型 —— 属性值统一转为字符串，数字 "3" 需 Number() 转换
5. 对象传参 —— data-product="{{ item }}" 可传对象（2.8.1+），有序列化开销
6. 传参通道 —— 列表渲染中「给处理函数传当前项数据」的唯一标准姿势
```

## 组件自定义事件

自定义组件（Component）与页面之间的事件通信通过 triggerEvent 完成：组件内部调用 this.triggerEvent('事件名', detail, options) 抛出事件，使用方在组件标签上 bind:事件名（或 bind事件名）接收。事件名可以自由定义，detail 承载数据，options 控制是否冒泡（bubbles）、是否可跨组件边界（composed）、是否进入捕获阶段（capturePhase）。

组件侧触发事件：

```js
// components/stepper/stepper.js —— 步进器组件
Component({
  properties: {
    value: { type: Number, value: 1 },
    min: { type: Number, value: 1 },
    max: { type: Number, value: 99 }
  },
  methods: {
    onMinus() {
      const next = this.data.value - 1
      if (next < this.data.min) return
      this.setData({ value: next })
      // 上抛自定义事件 change，detail 携带新值
      this.triggerEvent('change', { value: next })
    },
    onPlus() {
      const next = this.data.value + 1
      if (next > this.data.max) return
      this.setData({ value: next })
      this.triggerEvent('change', { value: next })
    }
  }
})
```

```wxml
<!-- components/stepper/stepper.wxml -->
<view class="stepper">
  <view class="step-btn" bindtap="onMinus">-</view>
  <view class="step-num">{{ value }}</view>
  <view class="step-btn" bindtap="onPlus">+</view>
</view>
```

页面侧接收事件：

```wxml
<!-- pages/cart/cart.wxml -->
<stepper value="{{ item.count }}" min="1" max="99" bind:change="onCountChange" data-id="{{ item.id }}" />
<!-- 也支持连写风格：bindchange="onCountChange" -->
```

```js
// pages/cart/cart.js
Page({
  data: {
    cartList: [{ id: 1, name: '蓝牙耳机', price: 199, count: 2 }]
  },
  onCountChange(e) {
    // detail 是组件 triggerEvent 传出的数据
    const { value } = e.detail
    // data-id 是使用方在组件标签上自定义的属性，走 dataset
    const id = e.currentTarget.dataset.id
    console.log('商品', id, '数量改为', value)
    this.setData({ 'cartList[0].count': value })
  }
})
```

冒泡型自定义事件：triggerEvent 第三个参数 options 中 bubbles: true 让事件像内置事件一样冒泡，composed: true 允许跨组件边界传播：

```js
// 组件内触发可冒泡的自定义事件
Component({
  methods: {
    onAction() {
      this.triggerEvent('action', { code: 'buy' }, {
        bubbles: true,       // 允许冒泡到祖先节点
        composed: true,      // 允许跨组件边界
        capturePhase: false  // 是否进入捕获阶段
      })
    }
  }
})
```

```text
组件自定义事件要点：
1. 触发 —— 组件内 this.triggerEvent('事件名', detail, options)
2. 接收 —— 使用方 bind:事件名="handler"（或 bind事件名），e.detail 取数据
3. 命名 —— 事件名自由定义，建议语义化（change、submit、action、select）
4. detail —— 传出的数据对象，接收方从 e.detail 读取
5. options —— bubbles/composed/capturePhase 控制传播行为
6. 配套 —— 组件标签上的 data-* 属性仍走 dataset，与自定义事件 detail 分工
```

## 应用场景实战

### 场景一：商品列表点击、点赞与冒泡控制

列表卡片：点击卡片跳详情（bindtap + data-id），点击点赞按钮只点赞不跳转（catchtap 阻止冒泡），点赞后按钮状态变化（setData 更新），长按弹出操作菜单（longpress）。

```wxml
<!-- pages/goods/list.wxml -->
<view class="goods-item" wx:for="{{ goodsList }}" wx:key="id"
      bindtap="onCardTap" bindlongpress="onCardLongPress"
      data-id="{{ item.id }}">
  <image class="goods-img" src="{{ item.image }}" mode="aspectFill"></image>
  <view class="goods-info">
    <view class="goods-name">{{ item.name }}</view>
    <view class="goods-price">¥{{ item.price }}</view>
  </view>
  <!-- catchtap：点赞不触发卡片的跳转 -->
  <view class="like-btn {{ item.liked ? 'liked' : '' }}"
        catchtap="onLikeTap" data-id="{{ item.id }}">
    {{ item.liked ? '已赞' : '点赞' }} {{ item.likeCount }}
  </view>
</view>
```

```js
// pages/goods/list.js
Page({
  data: {
    goodsList: [
      { id: 1, name: '蓝牙耳机', price: 199, image: 'https://example.com/img/a.png', liked: false, likeCount: 12 },
      { id: 2, name: '机械键盘', price: 399, image: 'https://example.com/img/b.png', liked: true, likeCount: 45 }
    ]
  },
  onCardTap(e) {
    // currentTarget 是卡片节点，data-id 取卡片 id
    const id = e.currentTarget.dataset.id
    wx.navigateTo({ url: '/pages/goods/detail?id=' + id })
  },
  onCardLongPress(e) {
    const id = e.currentTarget.dataset.id
    wx.showActionSheet({
      itemList: ['收藏', '举报'],
      success: (res) => console.log('对商品', id, '执行：', res.tapIndex)
    })
  },
  onLikeTap(e) {
    // catchtap 阻止冒泡，点击点赞不会触发 onCardTap
    const id = e.currentTarget.dataset.id
    const index = this.data.goodsList.findIndex((g) => g.id === id)
    // 路径式 setData 更新单项
    this.setData({
      ['goodsList[' + index + '].liked']: !this.data.goodsList[index].liked,
      ['goodsList[' + index + '].likeCount']: this.data.goodsList[index].liked
        ? this.data.goodsList[index].likeCount - 1
        : this.data.goodsList[index].likeCount + 1
    })
  }
})
```

### 场景二：表单提交与组件自定义事件联动

下单页：表单（收货人、手机号、备注）bindsubmit 提交校验；数量用自定义 stepper 组件，bind:change 同步数量；提交后携带订单数据请求后台。

```wxml
<!-- pages/order/create.wxml -->
<form bindsubmit="onSubmit" bindreset="onReset">
  <view class="form-group">
    <view class="label">收货人</view>
    <input name="receiver" placeholder="请输入收货人姓名" />
  </view>
  <view class="form-group">
    <view class="label">手机号</view>
    <input name="phone" type="number" maxlength="11" placeholder="请输入手机号" />
  </view>
  <view class="form-group">
    <view class="label">购买数量</view>
    <stepper value="{{ count }}" min="1" max="99" bind:change="onCountChange"></stepper>
  </view>
  <view class="form-group">
    <view class="label">备注</view>
    <textarea name="remark" placeholder="选填"></textarea>
  </view>
  <view class="submit-bar">
    <button form-type="submit">提交订单</button>
    <button form-type="reset" class="reset-btn">重置</button>
  </view>
</form>
```

```js
// pages/order/create.js
Page({
  data: {
    count: 1,
    goods: { id: 1001, name: '蓝牙耳机', price: 199 }
  },
  onCountChange(e) {
    // 组件自定义事件：detail.value 是 stepper 的新数量
    this.setData({ count: e.detail.value })
  },
  onSubmit(e) {
    // form 提交：e.detail.value 是所有带 name 字段的集合
    const form = e.detail.value
    if (!form.receiver) {
      wx.showToast({ title: '请填写收货人', icon: 'none' })
      return
    }
    if (!/^1\d{10}$/.test(form.phone)) {
      wx.showToast({ title: '手机号格式不正确', icon: 'none' })
      return
    }
    const orderData = {
      goodsId: this.data.goods.id,
      count: this.data.count,
      receiver: form.receiver,
      phone: form.phone,
      remark: form.remark
    }
    wx.request({
      url: 'https://api.example.com/order/create',
      method: 'POST',
      data: orderData,
      success: (res) => {
        wx.showToast({ title: '下单成功', icon: 'success' })
        wx.navigateTo({ url: '/pages/order/detail?orderNo=' + res.data.orderNo })
      }
    })
  },
  onReset() {
    this.setData({ count: 1 })
  }
})
```

```text
场景实战要点：
1. 冒泡控制 —— 卡片跳转 + 子按钮独立操作：子按钮用 catchtap 阻断冒泡
2. 列表传参 —— data-id + e.currentTarget.dataset.id 是列表点击的标准姿势
3. 状态更新 —— 点赞等局部状态用路径式 setData 精准更新单条
4. 表单事件 —— bindsubmit 的 e.detail.value 汇总全部 name 字段
5. 组件联动 —— stepper bind:change 上抛数量，页面 setData 同步
6. 校验前置 —— 表单提交在 JS 中校验后组装订单数据请求后台
```

## 最佳实践与踩坑记录

### 最佳实践

1. 列表点击一律用 data-id + currentTarget.dataset：绑定处不传参，处理函数内用 e.currentTarget.dataset 取数据，永不依赖 target，规避子节点干扰
2. 子元素独立操作一律 catchtap：卡片内点赞、删除、收藏等按钮用 catch 阻断冒泡，避免误触父级跳转
3. dataset 值统一按字符串处理：需要数字时显式 Number() 转换，避免 "3" === 3 之类的类型陷阱
4. 事件处理函数命名语义化：on 前缀 + 动作（onCardTap、onLikeTap、onCountChange），与 data 字段命名风格一致，便于维护
5. 高频事件（touchmove、input）处理函数内不做重逻辑：节流/防抖或只做必要 setData，避免频繁触发造成卡顿
6. 组件自定义事件用冒号风格 bind:change：与组件 props 区分清晰；事件名统一小写驼峰（change、countChange）
7. 表单数据获取统一走 bindsubmit：不要逐字段 bindinput 收集，e.detail.value 一次拿全，校验在提交函数内集中完成

### 踩坑记录

```text
坑 1：列表点击用 e.target.dataset 取不到 id
结论：点击列表项里的图片或子元素时，onCardTap 里 e.target.dataset.id 为 undefined，跳转失败。
原因：e.target 是事件源（实际点中的子节点），子节点上没有 data-id；冒泡时绑定节点是 currentTarget。
解法：取「绑定节点」的数据一律用 e.currentTarget.dataset；需要知道用户点了哪个子元素才用 target。

坑 2：catchtap 写在外层导致内层事件全部失效
结论：把 catchtap 绑在外层容器上，内层按钮的 bindtap 全部不触发。
原因：catch 阻止的是「本节点之后」的冒泡，事件从内层冒泡到外层时在外层被吞掉，但内层处理仍会先执行——实际场景中常见的是 catch 层级放错导致预期混乱。
解法：明确语义——内层子按钮用 catch 阻止冒泡到外层；外层容器保持 bind，不要反向使用。

坑 3：data-item-id 取值时拼错驼峰名
结论：写了 data-item-id，代码里取 dataset.item_id 或 dataset.itemId 拼错，得到 undefined。
原因：dataset 命名规则是连字符转驼峰（item-id → itemId）、大写转小写（ItemID → itemid），拼写不一致取不到。
解法：按规则写 dataset.itemId；取值前先 console.log(e.currentTarget.dataset) 核对实际键名。

坑 4：表单 bindsubmit 拿不到输入值
结论：bindsubmit 触发后 e.detail.value 是空对象。
原因：表单内 input/textarea 没写 name 属性，form 无法收集字段；或按钮没加 form-type="submit"。
解法：每个需提交的输入组件加 name；提交按钮加 form-type="submit"；重置按钮加 form-type="reset"。

坑 5：自定义组件 triggerEvent 后父级无响应
结论：组件里 triggerEvent('change', ...) 执行了，页面 bind:change 没反应。
原因：事件名拼写不一致（组件触发 change、页面监听 countChange）；或组件未在页面 json 的 usingComponents 注册。
解法：核对事件名完全一致；确认 usingComponents 注册正确；用 e.detail 接收数据而不是 e.value。

坑 6：dataset 传数字类型被转成字符串
结论：data-count="{{ 3 }}" 取出是 "3"，与数字 3 严格相等比较失败。
原因：WXML 属性值本质是字符串，dataset 中的值统一为字符串类型。
解法：取出后 Number() 转换；或传对象 data-info="{{ item }}" 保持原始类型（注意序列化开销）。

坑 7：onReachBottom 与按钮点击冲突，页面反复触发加载
结论：滚动到底部自动加载与手动点击加载都触发，数据重复请求。
原因：滚动事件（bindscroll/scrolltolower）与点击事件处理函数里都调用了加载逻辑，且未做防重。
解法：加载函数加 loading 锁（this.data.loading 为 true 时直接 return）；区分事件源用 e.type 判断。

坑 8：input 事件里直接 setData 整页数据导致输入卡顿
结论：bindinput 里 setData 大对象，输入一个字卡一下。
原因：input 事件高频触发，每次 setData 全量 diff 大对象开销大。
解法：只 setData 单个字段（'form.phone': e.detail.value）；对搜索类输入做防抖（300ms 后再请求）。
```

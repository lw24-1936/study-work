## 概述

微信支付服务端是整个交易系统的资金咽喉：统一下单生成支付凭证、回调确认收款、退款原路退回、对账保证账实相符。微信支付采用 APIv3 协议，与开放接口最大的区别是**双向证书体系**——请求用商户私钥签名，响应和回调要用微信平台证书验签，回调报文里的敏感数据用 APIv3 密钥做 AES-256-GCM 解密。任何一步做错，轻则支付失败，重则资金风险。

本章以微信支付 v3 协议为准（2026 年标准方案），覆盖 JSAPI 统一下单、支付结果回调的验签解密与幂等处理、退款与状态查询、商户证书/平台证书管理、每日对账五个环节，配合 10.2 小程序端支付流程章节，构成完整的支付闭环。

```text
支付服务端的核心要点：
1. 统一下单：POST /v3/pay/transactions/jsapi，返回 prepay_id，再生成前端拉起支付所需的签名参数
2. 金额单位是「分」，整型传输，禁止使用浮点数
3. 回调必须验签（平台证书）+ 解密（AES-256-GCM，APIv3 密钥）+ 幂等处理，返回 SUCCESS/FAIL
4. 退款走 POST /v3/refund/domestic/refunds，退款结果异步通知，需查询确认
5. 商户私钥（apiclient_key.pem）用于请求签名；平台证书用于验证微信响应与回调
6. 每日对账下载微信账单与本地订单比对，处理单边账，保证资金安全
```

## 统一下单（JSAPI）

小程序支付属于 JSAPI 支付，用户在小程序内拉起收银台。流程：服务端下单 → 拿到 prepay_id → 服务端生成签名参数返回前端 → 前端 wx.requestPayment 拉起支付。

```text
JSAPI 统一下单流程：
1. 前端提交商品信息，服务端创建业务订单（状态：待支付）
2. 服务端调用统一下单接口，传入 openid 与金额，获取 prepay_id
3. 服务端用 prepay_id 生成小程序端拉起支付所需的参数（timeStamp/nonceStr/package/paySign）
4. 前端 wx.requestPayment 拉起收银台，用户确认支付
5. 支付结果由微信异步回调 notify_url 通知服务端，服务端确认订单
```

Java 实现——先封装 APIv3 签名客户端。APIv3 的签名串规则为 `HTTP方法\nURL路径\n时间戳\n随机串\n请求体\n`，用商户私钥做 SHA256withRSA：

```java
package com.example.pay.client;

import lombok.extern.slf4j.Slf4j;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.http.*;
import org.springframework.stereotype.Component;
import org.springframework.web.client.RestTemplate;

import java.nio.charset.StandardCharsets;
import java.security.KeyFactory;
import java.security.PrivateKey;
import java.security.Signature;
import java.security.spec.PKCS8EncodedKeySpec;
import java.util.Base64;
import java.util.UUID;

@Slf4j
@Component
public class WechatPayV3Client {

    private final RestTemplate restTemplate;

    @Value("${pay.mchid}")
    private String mchid;                 // 商户号

    @Value("${pay.merchant-serial-no}")
    private String merchantSerialNo;      // 商户证书序列号（apiclient_cert.pem 的序列号）

    @Value("${pay.merchant-private-key-path}")
    private String privateKeyPath;        // apiclient_key.pem 路径

    public WechatPayV3Client(RestTemplate restTemplate) {
        this.restTemplate = restTemplate;
    }

    /**
     * 发送带 APIv3 签名的 POST 请求
     * @param path     接口路径（不含域名），如 /v3/pay/transactions/jsapi
     * @param bodyJson 请求体 JSON 字符串
     */
    public String postWithSign(String path, String bodyJson) {
        long timestamp = System.currentTimeMillis() / 1000;
        String nonceStr = UUID.randomUUID().toString().replace("-", "");
        // 待签名串：POST\n/v3/pay/transactions/jsapi\n时间戳\n随机串\n请求体\n
        String message = "POST\n" + path + "\n" + timestamp + "\n" + nonceStr
                + "\n" + bodyJson + "\n";
        String signature = rsaSign(message);

        HttpHeaders headers = new HttpHeaders();
        headers.setContentType(MediaType.APPLICATION_JSON);
        // 认证头格式：WECHATPAY2-SHA256-RSA2048 mchid="",nonce_str="",signature="",timestamp="",serial_no=""
        String authorization = "WECHATPAY2-SHA256-RSA2048 "
                + "mchid=\"" + mchid + "\","
                + "nonce_str=\"" + nonceStr + "\","
                + "signature=\"" + signature + "\","
                + "timestamp=\"" + timestamp + "\","
                + "serial_no=\"" + merchantSerialNo + "\"";
        headers.set(HttpHeaders.AUTHORIZATION, authorization);

        HttpEntity<String> entity = new HttpEntity<>(bodyJson, headers);
        String url = "https://api.mch.weixin.qq.com" + path;
        ResponseEntity<String> response =
                restTemplate.postForEntity(url, entity, String.class);
        return response.getBody();
    }

    /** 用商户私钥做 SHA256withRSA 签名 */
    private String rsaSign(String message) {
        try {
            String pem = new String(
                    java.nio.file.Files.readAllBytes(
                            java.nio.file.Path.of(privateKeyPath)),
                    StandardCharsets.UTF_8);
            // 去掉 PEM 头尾与换行，得到纯 Base64 的 PKCS8 私钥
            String base64 = pem.replace("-----BEGIN PRIVATE KEY-----", "")
                    .replace("-----END PRIVATE KEY-----", "")
                    .replaceAll("\\s", "");
            byte[] keyBytes = Base64.getDecoder().decode(base64);
            PKCS8EncodedKeySpec spec = new PKCS8EncodedKeySpec(keyBytes);
            PrivateKey privateKey = KeyFactory.getInstance("RSA").generatePrivate(spec);
            Signature signature = Signature.getInstance("SHA256withRSA");
            signature.initSign(privateKey);
            signature.update(message.getBytes(StandardCharsets.UTF_8));
            return Base64.getEncoder().encodeToString(signature.sign());
        } catch (Exception e) {
            throw new WechatPayException("APIv3 签名失败: " + e.getMessage(), e);
        }
    }
}
```

下单服务：

```java
package com.example.pay.service;

import com.example.pay.client.WechatPayV3Client;
import com.example.pay.exception.WechatPayException;
import com.fasterxml.jackson.databind.JsonNode;
import com.fasterxml.jackson.databind.ObjectMapper;
import lombok.extern.slf4j.Slf4j;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.stereotype.Service;

import java.security.KeyFactory;
import java.security.PrivateKey;
import java.security.Signature;
import java.security.spec.PKCS8EncodedKeySpec;
import java.util.Base64;
import java.util.LinkedHashMap;
import java.util.Map;
import java.util.UUID;

@Slf4j
@Service
public class WechatPayService {

    private static final String JSAPI_ORDER_PATH = "/v3/pay/transactions/jsapi";

    private final WechatPayV3Client payV3Client;
    private final ObjectMapper objectMapper;

    @Value("${wechat.appid}")
    private String appid;

    @Value("${pay.mchid}")
    private String mchid;

    @Value("${pay.notify-url}")
    private String notifyUrl;

    @Value("${pay.merchant-private-key-path}")
    private String privateKeyPath;

    public WechatPayService(WechatPayV3Client payV3Client, ObjectMapper objectMapper) {
        this.payV3Client = payV3Client;
        this.objectMapper = objectMapper;
    }

    /**
     * JSAPI 统一下单
     * @param openid     支付用户 openid
     * @param outTradeNo 商户订单号（业务订单号）
     * @param totalFee   金额（单位：分）
     * @param description 商品描述（≤127 字符）
     * @return 前端拉起支付所需参数
     */
    public JsapiPayParams createJsapiOrder(String openid, String outTradeNo,
                                           Integer totalFee, String description) {
        Map<String, Object> body = new LinkedHashMap<>();
        body.put("appid", appid);
        body.put("mchid", mchid);
        body.put("description", description);
        body.put("out_trade_no", outTradeNo);
        body.put("notify_url", notifyUrl);
        Map<String, Object> amount = new LinkedHashMap<>();
        amount.put("total", totalFee);          // 单位：分，整型
        amount.put("currency", "CNY");
        body.put("amount", amount);
        Map<String, Object> payer = new LinkedHashMap<>();
        payer.put("openid", openid);
        body.put("payer", payer);

        String bodyJson = writeJson(body);
        String response = payV3Client.postWithSign(JSAPI_ORDER_PATH, bodyJson);
        try {
            JsonNode json = objectMapper.readTree(response);
            String prepayId = json.get("prepay_id").asText();
            log.info("统一下单成功 outTradeNo={} prepayId={}", outTradeNo, prepayId);
            return buildJsapiPayParams(prepayId);
        } catch (Exception e) {
            throw new WechatPayException("统一下单响应解析失败: " + response, e);
        }
    }

    /**
     * 根据 prepay_id 生成小程序端 wx.requestPayment 所需参数
     * 签名串：appid\n时间戳\n随机串\npackage(prepay_id=xxx)\n
     */
    private JsapiPayParams buildJsapiPayParams(String prepayId) {
        String timeStamp = String.valueOf(System.currentTimeMillis() / 1000);
        String nonceStr = UUID.randomUUID().toString().replace("-", "");
        String packageStr = "prepay_id=" + prepayId;
        String message = appid + "\n" + timeStamp + "\n" + nonceStr
                + "\n" + packageStr + "\n";
        String paySign = signWithMerchantKey(message);
        return JsapiPayParams.builder()
                .timeStamp(timeStamp)
                .nonceStr(nonceStr)
                .packageStr(packageStr)
                .signType("RSA")
                .paySign(paySign)
                .build();
    }

    private String signWithMerchantKey(String message) {
        try {
            String pem = new String(
                    java.nio.file.Files.readAllBytes(
                            java.nio.file.Path.of(privateKeyPath)),
                    java.nio.charset.StandardCharsets.UTF_8);
            String base64 = pem.replace("-----BEGIN PRIVATE KEY-----", "")
                    .replace("-----END PRIVATE KEY-----", "")
                    .replaceAll("\\s", "");
            PrivateKey privateKey = KeyFactory.getInstance("RSA")
                    .generatePrivate(new PKCS8EncodedKeySpec(
                            Base64.getDecoder().decode(base64)));
            Signature signature = Signature.getInstance("SHA256withRSA");
            signature.initSign(privateKey);
            signature.update(message.getBytes(java.nio.charset.StandardCharsets.UTF_8));
            return Base64.getEncoder().encodeToString(signature.sign());
        } catch (Exception e) {
            throw new WechatPayException("生成支付签名失败: " + e.getMessage(), e);
        }
    }

    private String writeJson(Object obj) {
        try {
            return objectMapper.writeValueAsString(obj);
        } catch (Exception e) {
            throw new WechatPayException("JSON 序列化失败", e);
        }
    }
}
```

要点总结：

```text
统一下单要点：
1. 金额单位是分（total: 100 表示 1 元），整型，禁止 Double/Float 运算
2. out_trade_no 使用业务订单号，保证幂等：同一订单号重复下单会返回原 prepay_id

5. prepay_id 2 小时有效，生成后尽快返回前端拉起支付
6. 前端 success 只做 UI 提示，订单「已支付」状态必须等回调确认
```

## 支付回调处理

用户支付成功后，微信会向 notify_url 异步发送支付结果通知。回调处理是支付服务端最核心、最容易出错的环节，标准动作是「验签 → 解密 → 幂等更新订单 → 返回 SUCCESS」。

回调请求头携带签名信息：`Wechatpay-Timestamp`、`Wechatpay-Nonce`、`Wechatpay-Signature`、`Wechatpay-Serial`（平台证书序列号）。验签流程：

```text
回调验签与解密流程：
1. 取出请求头 Wechatpay-Timestamp/Nonce/Signature/Serial
2. 用 Serial 找到对应的微信平台证书（本地缓存，缺失时从 /v3/certificates 下载）
3. 验签串：时间戳\n随机串\n请求体\n，用平台证书公钥做 SHA256withRSA 验证
4. 验签通过后用 APIv3 密钥（32 字节）对 resource.ciphertext 做 AES-256-GCM 解密
5. 解密得到订单支付结果 JSON，处理业务
6. 处理成功返回 {"code":"SUCCESS","message":"成功"}；失败返回 FAIL，微信会重试
```

AES-256-GCM 解密实现：

```java
package com.example.pay.util;

import com.example.pay.exception.WechatPayException;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.stereotype.Component;

import javax.crypto.Cipher;
import javax.crypto.spec.GCMParameterSpec;
import javax.crypto.spec.SecretKeySpec;
import java.nio.charset.StandardCharsets;
import java.util.Base64;

@Component
public class WechatPayResourceDecryptor {

    @Value("${pay.apiv3-key}")
    private String apiV3Key;   // APIv3 密钥，32 字节，商户平台设置

    /**
     * 解密回调 resource（AES-256-GCM）
     * @param ciphertext     resource.ciphertext（Base64）
     * @param nonce          resource.nonce（12 字节随机串）
     * @param associatedData resource.associated_data
     */
    public String decrypt(String ciphertext, String nonce, String associatedData) {
        try {
            // APIv3 密钥必须是 32 字节
            SecretKeySpec keySpec = new SecretKeySpec(
                    apiV3Key.getBytes(StandardCharsets.UTF_8), "AES");
            // GCM：nonce 12 字节，认证标签 128 位（16 字节，追加在密文尾部）
            GCMParameterSpec gcmSpec = new GCMParameterSpec(
                    128, nonce.getBytes(StandardCharsets.UTF_8));
            Cipher cipher = Cipher.getInstance("AES/GCM/NoPadding");
            cipher.init(Cipher.DECRYPT_MODE, keySpec, gcmSpec);
            byte[] plain = cipher.doFinal(Base64.getDecoder().decode(ciphertext));
            return new String(plain, StandardCharsets.UTF_8);
        } catch (Exception e) {
            throw new WechatPayException("回调报文解密失败: " + e.getMessage(), e);
        }
    }
}
```

验签实现（依赖平台证书，见「证书管理」章节的 PlatformCertManager）：

```java
/** 验证回调签名 */
public boolean verifyNotifySignature(String timestamp, String nonce,
                                     String signature, String body) {
    // 时间戳防重放：与当前时间差超过 5 分钟直接拒绝
    long ts;
    try {
        ts = Long.parseLong(timestamp);
    } catch (NumberFormatException e) {
        return false;
    }
    if (Math.abs(System.currentTimeMillis() / 1000 - ts) > 300) {
        log.warn("回调时间戳过期，疑似重放攻击: {}", timestamp);
        return false;
    }
    // 验签串：时间戳\n随机串\n请求体\n
    String message = timestamp + "\n" + nonce + "\n" + body + "\n";
    try {
        return platformCertManager.verify(
                message, signature, platformCertManager.getLatestPublicKey());
    } catch (Exception e) {
        log.error("回调验签异常", e);
        return false;
    }
}
```

幂等处理订单（核心）：

```java
package com.example.pay.service;

import com.example.order.entity.Order;
import com.example.order.enums.OrderStatus;
import com.example.order.mapper.OrderMapper;
import lombok.extern.slf4j.Slf4j;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

import java.time.LocalDateTime;

@Slf4j
@Service
public class PayNotifyService {

    private final OrderMapper orderMapper;

    public PayNotifyService(OrderMapper orderMapper) {
        this.orderMapper = orderMapper;
    }

    /**
     * 处理支付成功回调，幂等：同一订单只处理一次
     * @return true 处理成功（回 SUCCESS），false 处理失败（回 FAIL 让微信重试）
     */
    @Transactional
    public boolean handlePaidNotify(String outTradeNo, String transactionId,
                                    Integer paidTotal, LocalDateTime successTime) {
        Order order = orderMapper.selectByOutTradeNo(outTradeNo);
        if (order == null) {
            log.error("回调订单不存在 outTradeNo={}", outTradeNo);
            return false;
        }
        // 幂等：已是支付成功状态，直接返回成功（微信可能重复通知）
        if (order.getStatus() == OrderStatus.PAID) {
            log.info("重复回调，忽略 outTradeNo={}", outTradeNo);
            return true;
        }
        // 状态校验：只有「待支付」才能流转到「已支付」
        if (order.getStatus() != OrderStatus.WAIT_PAY) {
            log.error("订单状态异常，拒绝处理 outTradeNo={} status={}",
                    outTradeNo, order.getStatus());
            return false;
        }
        // 金额校验：回调金额必须与订单金额一致，防止篡改
        if (!order.getTotalFee().equals(paidTotal)) {
            log.error("回调金额与订单不一致 outTradeNo={} orderFee={} paidFee={}",
                    outTradeNo, order.getTotalFee(), paidTotal);
            return false;
        }
        // 更新订单状态
        order.setStatus(OrderStatus.PAID);
        order.setTransactionId(transactionId);
        order.setPaidTime(successTime);
        orderMapper.updateById(order);
        // 后续业务：扣库存、生成权益、发订阅消息等（建议异步执行）
        orderService.afterPaid(order);
        log.info("订单支付成功 outTradeNo={} transactionId={}", outTradeNo, transactionId);
        return true;
    }
}
```

要点总结：

```text
回调处理要点：
1. 验签是安全底线：必须用平台证书验证签名，时间戳防重放（超 5 分钟拒绝）
2. 解密用 AES-256-GCM，nonce 与 associated_data 都来自 resource 字段
3. 幂等三件套：查订单存在 → 已处理直接返回成功 → 状态机校验（待支付才能流转）
4. 金额校验：回调 total 必须等于订单金额，防止中间人篡改
5. 返回 SUCCESS 表示不再通知；返回 FAIL 微信会重试（最多 6 次）
6. 回调处理里只做必要状态更新，重业务（库存/消息）异步化，快速返回
```

```java
package com.example.pay.service;

import com.example.pay.client.WechatPayV3Client;
import com.fasterxml.jackson.databind.JsonNode;
import com.fasterxml.jackson.databind.ObjectMapper;
import lombok.extern.slf4j.Slf4j;
import org.springframework.stereotype.Service;

import java.util.LinkedHashMap;
import java.util.Map;
import java.util.UUID;

@Slf4j
@Service
public class WechatRefundService {

    private static final String REFUND_PATH = "/v3/refund/domestic/refunds";
    private static final String REFUND_QUERY_PATH = "/v3/refund/domestic/refunds/{out_refund_no}";

    private final WechatPayV3Client payV3Client;
    private final ObjectMapper objectMapper;

    /** 发起退款（幂等：out_refund_no 唯一，重复调用返回原退款单） */
    public String createRefund(String outTradeNo, Integer refundFee,
                               Integer totalFee, String reason) {
        String outRefundNo = "R" + outTradeNo + UUID.randomUUID().toString().substring(0, 4);
        Map<String, Object> body = new LinkedHashMap<>();
        body.put("out_trade_no", outTradeNo);
        body.put("out_refund_no", outRefundNo);
        body.put("reason", reason);
        body.put("notify_url", refundNotifyUrl);
        Map<String, Object> amount = new LinkedHashMap<>();
        amount.put("refund", refundFee);   // 退款金额（分）
        amount.put("total", totalFee);     // 原订单金额（分），必须与下单时一致
        amount.put("currency", "CNY");
        body.put("amount", amount);

        String response = payV3Client.postWithSign(REFUND_PATH, writeJson(body));
        JsonNode json = objectMapper.readTree(response);
        String refundId = json.get("refund_id").asText();
        log.info("退款受理成功 outRefundNo={} refundId={}", outRefundNo, refundId);
        // 落退款单表，状态 PROCESSING，等退款结果回调或主动查询
        refundRecordService.create(outTradeNo, outRefundNo, refundFee, reason);
        return refundId;
    }

    /** 查询退款状态（主动兜底：回调丢失时用） */
    public JsonNode queryRefund(String outRefundNo) {
        String path = REFUND_QUERY_PATH.replace("{out_refund_no}", outRefundNo);
        String response = payV3Client.getWithSign(path);
        return objectMapper.readTree(response);
    }
}
```

退款状态机与注意事项：

```text
退款状态说明：
1. SUCCESS —— 退款成功，资金已原路退回
2. CLOSED —— 退款关闭（如超时未处理、金额校验失败）
3. PROCESSING —— 退款处理中，最终结果以回调或查询为准
4. ABNORMAL —— 退款异常，需人工介入
5. 退款结果同样走 notify_url 异步通知，处理逻辑与支付回调一致：验签、解密、幂等
6. 部分退款可多次发起，累计退款金额不得超过原订单金额
7. 订单支付成功（含部分退款）后 1 年内可发起退款，超期需走线下
```

要点总结：

```text
退款要点：
1. out_refund_no 是退款单唯一键，幂等关键；重复发起同一退款单返回原退款结果
2. amount.total 必须与原订单金额一致，amount.refund 为本次退款金额
3. 退款单落库记录状态，以回调为准，主动查询兜底
4. 退款金额 ≤ 原订单金额，部分退款可多次；全额退款后订单置为已退款
5. 退款也走 v3 签名，与下单同一套客户端
6. 退款失败（如余额不足）返回明确错误码，记录并告警人工处理
```

## 证书管理

APIv3 的证书体系是双证书结构，两者的作用完全不同，混淆是高频事故源：

```text
两类证书的区别：
1. 商户证书（apiclient_cert.pem + apiclient_key.pem）—— 商户身份，请求签名用私钥，公钥证书序列号放进 Authorization 头
2. 平台证书（wechatpay 开头的平台证书）—— 微信身份，验证微信的响应与回调签名用公钥
3. 商户证书在商户平台「账户中心-API 安全」申请下载，1 张证书对应一个商户号
4. 平台证书由微信签发，有效期约 5 年，但会轮换，需要动态下载更新
5. APIv3 密钥（apiv3_key）是 32 字节字符串，用于回调/证书报文的 AES-256-GCM 解密，与证书无关
6. 商户私钥泄露 = 资金风险，必须最小权限 + 密钥管理（如 KMS 托管）
```

平台证书的获取与轮换：首次对接或证书更新时，调用 `GET /v3/certificates`（需商户签名），响应中的证书密文用 APIv3 密钥解密得到证书内容。生产实现一个 PlatformCertManager：

```java
package com.example.pay.cert;

import lombok.extern.slf4j.Slf4j;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.stereotype.Component;

import java.security.MessageDigest;
import java.security.cert.CertificateFactory;
import java.security.cert.X509Certificate;
import java.util.Base64;
import java.util.concurrent.ConcurrentHashMap;

/**
 * 平台证书管理器：本地缓存证书（serial -> X509Certificate）
 * 微信平台证书会轮换，验签失败时需重新拉取 /v3/certificates 更新
 */
@Slf4j
@Component
public class PlatformCertManager {

    /** 平台证书序列号 -> 证书对象 */
    private final ConcurrentHashMap<String, X509Certificate> certCache =
            new ConcurrentHashMap<>();

    /** 从 /v3/certificates 拉取并缓存全部平台证书 */
    public void refreshCertificates() {
        // 1. 调用 GET /v3/certificates（带 APIv3 签名，见 WechatPayV3Client.getWithSign）
        // 2. 响应 data[].encrypt_certificate 用 APIv3 密钥 AES-256-GCM 解密
        // 3. 得到 PEM 证书文本，解析为 X509Certificate 存入 certCache
        // 4. 解密方式与回调 resource 完全一致（AES-256-GCM + apiv3_key）
        log.info("平台证书刷新完成，当前 {} 张", certCache.size());
    }

    /** 按序列号取证书，不存在则触发刷新后重取 */
    public X509Certificate getBySerial(String serialNo) {
        X509Certificate cert = certCache.get(serialNo);
        if (cert == null) {
            refreshCertificates();
            cert = certCache.get(serialNo);
        }
        return cert;
    }

    /** 取最新证书（验签默认用） */
    public X509Certificate getLatest() {
        return certCache.values().stream()
                .max(java.util.Comparator.comparing(X509Certificate::getNotAfter))
                .orElseThrow(() -> new IllegalStateException("平台证书为空，请先拉取"));
    }

    /** 用证书公钥验签（SHA256withRSA） */
    public boolean verify(String message, String signatureBase64, X509Certificate cert) {
        try {
            java.security.Signature sig = java.security.Signature.getInstance("SHA256withRSA");
            sig.initVerify(cert.getPublicKey());
            sig.update(message.getBytes(java.nio.charset.StandardCharsets.UTF_8));
            return sig.verify(Base64.getDecoder().decode(signatureBase64));
        } catch (Exception e) {
            log.error("验签异常", e);
            return false;
        }
    }
}
```

证书文件放置规范：

```text
证书文件管理规范：
1. 商户私钥（apiclient_key.pem）权限 600，路径配置在环境变量/配置中心，禁止进 Git
2. 商户证书与私钥按环境隔离：测试环境用测试商户号，生产环境用正式商户号
3. 平台证书动态拉取缓存，每次验签失败先尝试刷新再判失败
4. 商户证书过期（有效期 5 年）前 30 天告警，提前在商户平台重新申请
5. APIv3 密钥与证书分开存储，不放在同一配置文件
6. 密钥轮换时平滑过渡：新旧证书并存一段时间，避免切换瞬间验签失败
```

要点总结：

```text
证书管理要点：
1. 请求签名用商户私钥，验签用平台证书公钥，方向相反，不要搞混
2. 商户私钥是资金级机密：KMS/密钥管理 + 最小权限 + 审计日志
3. 平台证书会轮换：必须支持动态下载与缓存更新，验签失败先刷新再重试
4. 证书按环境隔离（测试/生产商户号不同），配置通过环境变量注入
5. APIv3 密钥（32 字节）用于解密回调与证书报文，与签名无关
6. 过期前告警 + 平滑轮换，避免证书过期导致全站支付不可用
```

## 对账

对账是资金安全的最后一道防线：每天比对微信侧账单与本地订单，发现「单边账」并处理。

```text
对账流程：
1. 每日定时（如凌晨 1 点）调用账单下载接口获取前一日微信账单
2. 下载交易账单：GET /v3/bill/tradebill?bill_date=2026-08-19&bill_type=ALL
3. 响应返回 download_url（账单文件地址），GET 下载 CSV 文件（压缩格式）
4. 解析 CSV，逐笔与本地订单比对：金额、状态、单号
5. 生成对账结果：一致（平账）、本地有微信无（本地已支付但微信无记录）、微信有本地无（微信扣款但本地未确认）
6. 异常单进入待处理队列，人工或自动补偿（补确认订单 / 发起退款 / 告警）
```

账单文件列（交易账单 CSV）：

```text

```

注意：CSV 里金额单位是**元**（字符串，如 1.00），本地订单是**分**（100），比对时换算。

```java
/**
 * 日对账主逻辑（伪代码骨架）
 */
public void dailyReconcile(LocalDate billDate) {
    // 1. 下载前一日交易账单
    String downloadUrl = billService.downloadTradeBill(billDate, "ALL");
    List<BillRecord> billRecords = billService.parseBillCsv(downloadUrl);

    // 2. 本地订单（前一日产生交易的全部订单）
    List<Order> localOrders = orderMapper.selectByDateRange(billDate);

    // 3. 按 out_trade_no 建立映射
    Map<String, BillRecord> billMap = billRecords.stream()
            .collect(Collectors.toMap(BillRecord::getOutTradeNo, r -> r, (a, b) -> a));

    for (Order order : localOrders) {
        BillRecord bill = billMap.get(order.getOutTradeNo());
        if (bill == null) {
            // 本地已支付但微信账单无记录：可能是异步延迟或异常，告警并复查
            reconcileAlarm("微信账单缺少本地订单", order.getOutTradeNo());
        } else if (!bill.getAmountYuanToFen().equals(order.getTotalFee())) {
            // 金额不一致：严重告警，人工介入
            reconcileAlarm("金额不一致", order.getOutTradeNo());
        }
    }
    // 4. 反向检查：微信账单有但本地无 → 扣款未确认，补确认或退款
    for (BillRecord bill : billRecords) {
        if (!localOrderMap.containsKey(bill.getOutTradeNo())) {
            reconcileAlarm("本地缺少微信账单记录（可能回调丢失）", bill.getOutTradeNo());
            payNotifyService.handlePaidNotify(bill.getOutTradeNo(),
                    bill.getTransactionId(), bill.getAmountYuanToFen(), bill.getTradeTime());
        }
    }
    // 5. 生成对账报表，记录对账批次
    reconcileReportService.generate(billDate,
            billRecords.size(), localOrders.size(), mismatchList);
}
```

对账的兜底价值：回调丢失（网络问题、代码 bug）时，微信侧已扣款而本地订单仍是待支付，对账能发现并补确认，避免「用户付了钱但没拿到货」的客诉与资损。

要点总结：

```text
对账要点：
1. 每日固定时间对账，账单日期用前一日（T-1），节假日顺延规则注意
2. CSV 金额是元、本地是分，比对前必须统一单位
3. 双向比对：本地→微信（查漏扣）与 微信→本地（查漏确认）都要做
4. 金额不一致、单边账都要告警并留痕，人工介入闭环
5. 对账能兜住回调丢失：发现微信已扣款未确认时补确认
6. 账单文件仅限当日有效，下载失败需重试，连续失败告警
```

```java
/** 用户申请退款 */
@PostMapping("/refund/apply")
public Result<Void> applyRefund(@RequestBody RefundApplyRequest req,
                                @RequestHeader("X-UserId") Long userId) {
    // 1. 校验订单归属与状态（已支付/未全额退款）
    Order order = orderService.getOwnedOrder(userId, req.getOrderId());
    if (order.getStatus() != OrderStatus.PAID) {
        return Result.fail("ORDER_STATUS_ERROR", "当前订单状态不可退款");
    }
    // 2. 校验退款金额 ≤ 已支付金额 - 已退款金额
    int alreadyRefunded = refundRecordService.sumRefunded(order.getId());
    int refundFee = req.getRefundFee() != null ? req.getRefundFee()
            : order.getTotalFee() - alreadyRefunded;   // 默认全额退剩余
    if (refundFee <= 0 || refundFee > order.getTotalFee() - alreadyRefunded) {
        return Result.fail("REFUND_AMOUNT_ERROR", "退款金额不合法");
    }
    // 3. 发起微信退款
    refundService.createRefund(order.getOutTradeNo(), refundFee,
            order.getTotalFee(), req.getReason());
    // 4. 订单状态流转：PAID → REFUNDING
    orderService.markRefunding(order, refundFee);
    return Result.ok();
}
```

```text
场景二验证要点：
1. 全额退款：微信侧到账、本地订单置 REFUNDED、退款记录完整

3. 退款回调：验签解密后更新退款单状态，幂等防重复
```

## 最佳实践与踩坑记录

### 最佳实践

1. 金额一律以「分」为单位的整型存储与传输，数据库用 INT/BIGINT，禁止 Double/Float
2. out_trade_no 复用业务订单号、out_refund_no 独立生成，两者都是幂等键，重复调用不产生重复单
3. 回调处理按「验签 → 防重放 → 解密 → 幂等状态机 → 金额校验 → 返回 SUCCESS」固定顺序执行
4. 回调内只做订单状态更新，扣库存/发消息等重业务异步化，保证快速返回
5. 商户私钥走密钥管理（KMS/配置中心），权限最小化，审计日志记录访问
6. 每日对账自动化，双向比对 + 金额校验 + 异常告警，兜住回调丢失
7. 平台证书动态刷新，验签失败先刷新证书再判失败；过期前 30 天告警
8. 测试环境使用独立测试商户号，金额用小额，回调地址用内网穿透工具联调

### 踩坑记录

```text
坑 1：金额单位混淆（元/分），用户少付钱
结论：下单金额 1.00 元存成 1 分，订单实际只收 0.01 元。
原因：前端传元、后端按分处理，或 JSON 里 total 传了浮点。
解法：全链路统一「分」整型；下单金额服务端计算；回调金额与订单金额严格比对。

坑 2：回调不验签直接信任报文内容
结论：攻击者伪造回调把订单置为已支付，未付款发货造成资损。
原因：回调接口没验签，直接按 body 更新订单状态。
解法：必须用平台证书验签 + 时间戳防重放；验签失败返回 FAIL 并告警。

坑 3：回调处理不幂等，重复通知重复发货
结论：微信重试回调时订单被重复处理，商品发了两份。
原因：回调直接 update 订单状态，没有先查状态判断是否已处理。
解法：幂等三件套——查订单、已支付直接返回成功、状态机校验（待支付才流转）。

坑 4：回调返回非 SUCCESS 或 HTTP 500，微信重试风暴
结论：微信连续重试 6 次回调，日志刷屏，重业务被重复执行。
原因：处理失败或代码异常导致返回 FAIL，微信按策略重试。
解法：业务处理失败先捕获异常返回 FAIL 让微信重试；但已成功处理的情况必须返回 SUCCESS。

坑 5：APIv3 签名格式错误，下单报 401
结论：统一下单返回 401 Unauthorized，错误信息含签名校验失败。
原因：签名串拼接错误（漏了 \n、路径带了域名、请求体与实际发送不一致）。
解法：严格按「POST\n路径\n时间戳\n随机串\n请求体\n」拼串；用官方验签工具核对；请求体必须与签名时完全一致。

坑 6：商户证书与平台证书搞混，验签一直失败
结论：回调验签失败率 100%，回调永远处理不了。
原因：用商户证书的公钥去验微信的签名，方向搞反。
解法：请求签名用商户私钥；验微信签名用平台证书公钥；两个证书分别管理。

坑 7：商户证书过期，全站支付突然不可用
结论：统一下单全部报证书错误，支付功能瘫痪。
原因：商户证书有效期 5 年，到期未续，也没有告警。
解法：监控证书有效期，过期前 30 天告警；提前在商户平台申请新证书并平滑切换。

坑 8：退款不校验已退金额，重复退款
结论：部分退款场景下多次申请，累计退款超过订单金额。
原因：退款前没查已退款总额，金额校验缺失。
解法：退款前计算已退总额，本次退款 ≤ 订单金额 - 已退金额；out_refund_no 保证幂等。

坑 9：忽略对账，回调丢失导致用户付钱没拿到货
结论：用户已扣款但订单长期待支付，客诉与资损。
原因：只靠回调确认订单，回调丢失后没有兜底机制。
解法：每日对账双向比对，发现微信已扣款未确认的订单自动补确认并告警。
```

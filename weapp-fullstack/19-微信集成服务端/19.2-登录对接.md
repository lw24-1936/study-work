## 概述

小程序登录的核心诉求是「服务端拿到用户的微信身份（openid）并建立会话」。由于小程序端无法安全保管任何密钥，登录必须走「wx.login 拿 code → 服务端用 code 换 openid/session_key」的授权码模式：code 一次性有效，AppSecret 全程只出现在服务端，用户身份由此可信。换回来的 session_key 是解密用户敏感数据（手机号、微信运动等）的钥匙，必须服务端保管、绝不返回前端。

本章覆盖登录全链路：code2session 换取身份、用户敏感数据 AES 解密、session_key 的安全管理、用户落库策略，以及登录态（JWT token + 用户信息）的签发与返回。配合 18.1-JWT 认证章节，构成「小程序免密登录 → 服务端建会话」的完整闭环。

```text
登录对接的核心要点：
1. 前端 wx.login 获取一次性 code，服务端用 code + AppSecret 调 code2session 换 openid
2. code2session 返回 openid（用户唯一标识）、session_key（解密钥匙）、unionid（多端打通标识）
3. 手机号等敏感数据用 AES-128-CBC 解密，key 为 session_key，必须校验 watermark
4. session_key 只存服务端（Redis），不返回前端、不落日志，过期自动失效
5. 用户表以 openid 为唯一键，首次登录自动建号，unionid 用于多端账号打通
6. 登录成功签发 JWT token 返回前端，后续请求携带 token 即可，无需再调微信
```

## code2session

小程序端 `wx.login()` 会得到一个临时凭证 code（5 分钟有效、一次性、与 openid 不直接对应），把它交给服务端，由服务端携带 AppSecret 调用微信接口换取用户身份：

```text
GET https://api.weixin.qq.com/sns/jscode2session?appid=APPID&secret=APPSECRET&js_code=CODE&grant_type=authorization_code
```

成功响应：

```json
{
  "openid": "oXk5v5FjYtUqM-xxxxxxxxxxxx",
  "session_key": "t0Xk5v5FjYtUqM-xxxxxxxxxxxx==",
  "unionid": "o6_bmjrPTlm6_2sgVt7hMZOPfL2M"
}
```

失败响应：

```json
{
  "errcode": 40029,
  "errmsg": "invalid code, hints: [ req_id: xxx ]"
}
```

```text
code2session 关键信息：
1. openid —— 用户在小程序下的唯一标识，不同小程序不同；同一用户同一小程序永远不变
2. session_key —— 解密用户敏感数据的密钥，随 openid 一起返回，需服务端妥善保管
3. unionid —— 绑定微信开放平台后才有；同一开放平台账号下，不同小程序/公众号共享同一 unionid
4. code 一次性有效，5 分钟过期，重复使用返回 40029
5. grant_type 固定为 authorization_code
6. 该接口不需要 access_token，用 AppID + AppSecret 直接换，调用频率不受 token 配额影响
```

SpringBoot 实现登录服务（核心方法）：

```java
package com.example.wechat.service;

import com.example.wechat.client.WechatApiClient;
import com.example.wechat.exception.WechatApiException;
import com.fasterxml.jackson.databind.JsonNode;
import lombok.extern.slf4j.Slf4j;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.stereotype.Service;

import java.util.HashMap;
import java.util.Map;

@Slf4j
@Service
public class WechatLoginService {

    private final WechatApiClient wechatApiClient;
    private final SessionKeyService sessionKeyService;

    @Value("${wechat.appid}")
    private String appid;

    @Value("${wechat.secret}")
    private String secret;

    public WechatLoginService(WechatApiClient wechatApiClient,
                              SessionKeyService sessionKeyService) {
        this.wechatApiClient = wechatApiClient;
        this.sessionKeyService = sessionKeyService;
    }

    /**
     * code2session：用前端传来的 code 换取微信身份
     * @return openid/session_key/unionid
     */
    public WechatSession code2Session(String code) {
        // 注意：该接口不走 access_token，而是 appid+secret 直接换，需独立拼 URL
        String url = "https://api.weixin.qq.com/sns/jscode2session"
                + "?appid=" + appid + "&secret=" + secret
                + "&js_code=" + code + "&grant_type=authorization_code";
        JsonNode json = wechatApiClient.getRaw(url);
        if (json.has("errcode") && json.get("errcode").asInt() != 0) {
            throw new WechatApiException(
                    json.get("errcode").asInt(), json.get("errmsg").asText());
        }
        String openid = json.get("openid").asText();
        String sessionKey = json.get("session_key").asText();
        String unionid = json.has("unionid") ? json.get("unionid").asText() : null;

        // session_key 立即存入 Redis，供后续数据解密使用（TTL 2 小时）
        sessionKeyService.save(openid, sessionKey);
        return new WechatSession(openid, sessionKey, unionid);
    }

    /** 完整登录入口：code → 身份 → 用户落库 → 登录态 */
    public LoginResult login(String code) {
        WechatSession session = code2Session(code);
        // 用户落库（不存在则创建）
        User user = userService.findOrCreateByOpenid(session.getOpenid(), session.getUnionid());
        // 签发 JWT 登录态
        String token = jwtUtil.generateToken(user.getId(), user.getOpenid());
        log.info("用户登录成功 openid={} userId={}", session.getOpenid(), user.getId());
        return LoginResult.of(token, user);
    }
}
```

要点总结：

```text
code2session 要点：
1. 该接口参数是 appid + secret，与需要 access_token 的接口不同，封装时注意区分
2. code 只能使用一次，前端每次 wx.login 都会生成新 code，服务端无需缓存 code
3. 拿到 openid 后立即把 session_key 存入 Redis（2 小时 TTL），与登录态生命周期对齐
4. unionid 可能不存在（未绑定开放平台），代码必须判空
5. 登录接口要加限流（如按 IP/设备 每分钟 10 次），防止恶意刷 code
6. 失败时记录 errcode，40029 说明 code 过期或重复使用，可引导前端重新 wx.login
```

## 数据解密

部分用户敏感数据（手机号、微信运动步数、保存到通讯录的原始数据等）在通过 getPhoneNumber 等接口返回时是加密的。加密算法固定为 AES-128-CBC，密钥为 session_key，IV 与密文随接口一起返回：

```text
解密算法说明：
1. 加密算法：AES-128-CBC，密钥 = session_key（Base64 解码后 16 字节）
2. 填充方式：PKCS7（Java 中用 PKCS5Padding 等价实现）
3. 入参：session_key、iv、encryptedData 三个 Base64 字符串
4. 解密结果：JSON 字符串，内含业务数据 + watermark（含 appid 与时间戳）
5. 必须校验 watermark.appid 与自身 appid 一致，防止数据被篡改或密钥错配
6. 解密失败（如 session_key 过期）时返回 40003 或解密异常，需引导用户重新登录
```

Java 完整实现：

```java
package com.example.wechat.util;

import com.example.wechat.exception.WechatApiException;
import com.fasterxml.jackson.databind.JsonNode;
import com.fasterxml.jackson.databind.ObjectMapper;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.stereotype.Component;

import javax.crypto.Cipher;
import javax.crypto.spec.IvParameterSpec;
import javax.crypto.spec.SecretKeySpec;
import java.nio.charset.StandardCharsets;
import java.util.Base64;

@Component
public class WechatDataDecryptor {

    private final ObjectMapper objectMapper;

    @Value("${wechat.appid}")
    private String appid;

    public WechatDataDecryptor(ObjectMapper objectMapper) {
        this.objectMapper = objectMapper;
    }

    /**
     * AES-128-CBC 解密微信敏感数据
     * @param sessionKey    登录时获得的 session_key（Base64）
     * @param iv            微信返回的 IV（Base64）
     * @param encryptedData 微信返回的密文（Base64）
     * @return 解密后的 JSON 字符串（含 watermark）
     */
    public String decrypt(String sessionKey, String iv, String encryptedData) {
        try {
            byte[] key = Base64.getDecoder().decode(sessionKey);
            byte[] ivBytes = Base64.getDecoder().decode(iv);
            byte[] encrypted = Base64.getDecoder().decode(encryptedData);

            SecretKeySpec keySpec = new SecretKeySpec(key, "AES");
            IvParameterSpec ivSpec = new IvParameterSpec(ivBytes);
            // 微信使用 AES-128-CBC + PKCS7，Java 侧用 PKCS5Padding（两者等价）
            Cipher cipher = Cipher.getInstance("AES/CBC/PKCS5Padding");
            cipher.init(Cipher.DECRYPT_MODE, keySpec, ivSpec);
            byte[] plain = cipher.doFinal(encrypted);
            return new String(plain, StandardCharsets.UTF_8);
        } catch (Exception e) {
            throw new WechatApiException(-1, "微信数据解密失败: " + e.getMessage());
        }
    }

    /** 解密并校验 watermark，返回业务数据节点 */
    public JsonNode decryptAndVerify(String sessionKey, String iv, String encryptedData) {
        String plain = decrypt(sessionKey, iv, encryptedData);
        try {
            JsonNode node = objectMapper.readTree(plain);
            String watermarkAppid = node.path("watermark").path("appid").asText();
            if (!appid.equals(watermarkAppid)) {
                throw new WechatApiException(-1, "解密数据 watermark 校验失败，appid 不一致");
            }
            return node;
        } catch (WechatApiException e) {
            throw e;
        } catch (Exception e) {
            throw new WechatApiException(-1, "解密结果解析失败: " + e.getMessage());
        }
    }
}
```

```java
    Map<String, Object> body = new HashMap<>();
    body.put("code", code);
    JsonNode result = wechatApiClient.post(
            "/wxa/business/getuserphonenumber", Map.of(), body);
    String phone = result.path("phone_info").path("purePhoneNumber").asText();

    return phone;
```

要点总结：

```text
数据解密要点：
1. 加密方式是 AES-128-CBC + PKCS7，密钥 session_key 16 字节，Java 用 PKCS5Padding 即可
2. 解密结果必须校验 watermark.appid，防止密钥错配或数据被替换
3. session_key 过期后解密必然失败，此时应返回明确提示并让用户重新登录
4. 手机号优先用 getuserphonenumber 新接口（code 换手机号，零解密成本）
5. 解密出的敏感数据立即落库使用，明文禁止打印到日志
6. 手机号脱敏展示（138****8000），完整号码只存库不外泄
```

## session_key 管理

session_key 是用户维度的敏感密钥，泄露等于用户数据可以被任意解密。微信官方对它的态度非常明确：**只在服务端保存和使用**。

```text
session_key 管理规范：
1. 不返回前端 —— 前端永远拿不到 session_key，只有服务端 code2session 时持有
2. 服务端存储 —— 存 Redis，key 为 openid，TTL 2 小时与登录态对齐
3. 不落日志 —— 日志、异常信息、监控上报中禁止出现 session_key 明文
4. 不落数据库 —— 明文不进 MySQL，Redis 过期即销毁；确需持久化则必须加密存储
5. 随登录态一起失效 —— 用户退出或 token 过期时同步删除 session_key
6. 无官方固定有效期 —— 官方未承诺过期时间，实践中按 2 小时与登录态保持一致最稳妥
```

SpringBoot 实现：

```java
package com.example.wechat.service;

import org.springframework.data.redis.core.StringRedisTemplate;
import org.springframework.stereotype.Service;

import java.time.Duration;

@Service
public class SessionKeyService {

    private static final String SESSION_KEY_PREFIX = "wechat:session_key:";
    private static final Duration SESSION_KEY_TTL = Duration.ofHours(2);

    private final StringRedisTemplate redisTemplate;

    public SessionKeyService(StringRedisTemplate redisTemplate) {
        this.redisTemplate = redisTemplate;
    }

    /** 保存 session_key，TTL 2 小时 */
    public void save(String openid, String sessionKey) {
        redisTemplate.opsForValue().set(
                SESSION_KEY_PREFIX + openid, sessionKey, SESSION_KEY_TTL);
    }

    /** 读取 session_key，不存在说明已过期 */
    public String get(String openid) {
        return redisTemplate.opsForValue().get(SESSION_KEY_PREFIX + openid);
    }

    /** 登录态失效时同步删除 */
    public void delete(String openid) {
        redisTemplate.delete(SESSION_KEY_PREFIX + openid);
    }

    /** 会话是否有效（解密前置检查） */
    public boolean isValid(String openid) {
        String key = get(openid);
        return key != null && !key.isEmpty();
    }
}
```

配套的安全注意：

```text
session_key 安全红线：
1. 任何接口都不允许把 session_key 返回给前端（包括调试接口、测试环境）
2. 前端需要解密时，把 encryptedData + iv 传给服务端，由服务端解密后回传结果
3. 前后端都要对解密接口做鉴权（携带用户 token），防止他人拿别人的数据来解密
4. session_key 变更以最新一次 code2session 为准，旧 key 立即作废
5. Redis 若被攻破，session_key 会泄露 —— 生产环境 Redis 必须设密码并限制内网访问
6. 服务端解密失败的日志只记 openid 与错误类型，不记密文与明文
```

## 用户落库与登录态返回

拿到 openid 后，业务系统需要自己的用户表。设计原则：**openid 是天然的唯一键，首次出现自动建号**。表结构：

```sql
CREATE TABLE `t_user` (
  `id`            BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '用户主键',
  `openid`        VARCHAR(64)     NOT NULL COMMENT '微信 openid，小程序内唯一',
  `unionid`       VARCHAR(64)     DEFAULT NULL COMMENT '微信 unionid，多端打通标识',
  `nickname`      VARCHAR(64)     DEFAULT NULL COMMENT '昵称',
  `avatar_url`    VARCHAR(512)    DEFAULT NULL COMMENT '头像地址',
  `phone`         VARCHAR(20)     DEFAULT NULL COMMENT '手机号（脱敏存储或加密存储）',
  `gender`        TINYINT         DEFAULT 0 COMMENT '性别：0 未知 1 男 2 女',
  `status`        TINYINT         NOT NULL DEFAULT 1 COMMENT '状态：1 正常 0 禁用',
  `last_login_at` DATETIME        DEFAULT NULL COMMENT '最近登录时间',
  `created_at`    DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at`    DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP
                                   ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_openid` (`openid`),
  KEY `idx_unionid` (`unionid`)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COMMENT = '微信小程序用户表';
```

查询建号逻辑（幂等）：

```java
package com.example.user.service;

import com.example.user.entity.User;
import com.example.user.mapper.UserMapper;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

import java.time.LocalDateTime;

@Service
public class UserService {

    private final UserMapper userMapper;

    public UserService(UserMapper userMapper) {
        this.userMapper = userMapper;
    }

    /** 按 openid 查用户，不存在则创建（登录主路径调用） */
    @Transactional
    public User findOrCreateByOpenid(String openid, String unionid) {
        User user = userMapper.selectByOpenid(openid);
        if (user != null) {
            // 已有账号：补充 unionid（首次绑定开放平台后出现）并刷新登录时间
            boolean changed = false;
            if (unionid != null && !unionid.equals(user.getUnionid())) {
                user.setUnionid(unionid);
                changed = true;
            }
            if (changed) {
                userMapper.updateById(user);
            }
            return user;
        }
        // 新用户自动建号
        User newUser = new User();
        newUser.setOpenid(openid);
        newUser.setUnionid(unionid);
        newUser.setStatus(1);
        newUser.setLastLoginAt(LocalDateTime.now());
        userMapper.insert(newUser);
        return newUser;
    }
}
```

要点总结：

```text
用户落库与登录态要点：
1. openid 建唯一索引，作为用户身份唯一键；查不到就建，天然幂等
2. unionid 用于多端打通（公众号/H5/其他小程序），没有开放平台绑定时为 null
3. token 只存 userId + openid 等最小信息，用户资料变化不影响 token 有效性
4. 返回给前端的用户信息必须脱敏（手机号、身份证等）
5. 登录接口统一走 Result 包装，错误码区分：0 成功、40029 code 无效、-1 系统异常
6. 登录态过期（token 失效）后前端自动重新 wx.login 静默续期，用户无感知
```

## 应用场景实战

### 场景一：完整的小程序登录链路（前端 + 服务端）

前端小程序侧（页面 onLoad 时静默登录）：

```javascript
// utils/auth.js
function login() {
  return new Promise((resolve, reject) => {
    wx.login({
      success: (res) => {
        if (res.code) {
          // 1. wx.login 拿到一次性 code
          wx.request({
            url: 'https://api.example.com/api/auth/login',
            method: 'POST',
            data: { code: res.code },
            success: (resp) => {
              const { code, data } = resp.data;
              if (code === 0) {
                // 2. 拿到 token 与用户信息，本地存储
                wx.setStorageSync('token', data.token);
                wx.setStorageSync('userInfo', data.user);
                resolve(data);
              } else {
                reject(new Error(resp.data.message));
              }
            },
            fail: reject
          });
        } else {
          reject(new Error('wx.login 失败: ' + res.errMsg));
        }
      }
    });
  });
}
```

服务端时序与前面代码串起来：wx.login → code → /api/auth/login → code2session → session_key 存 Redis → 用户落库 → 签发 JWT → 返回 token + user。后续所有请求携带 `Authorization: Bearer <token>`，由 Spring Security / 拦截器解析（见 18.2 章节）。

```text
场景一验证清单：
1. 首次登录：数据库新增一条 t_user 记录，openid 正确，返回 token 有效
2. 再次登录：不重复建号，last_login_at 刷新，返回同一 userId
3. 用同一 code 调两次登录接口：第二次返回 40029，前端需重新 wx.login
4. token 带过期时间，过期后访问业务接口返回 401，前端自动重新登录
```

### 场景二：获取并绑定手机号

业务需要手机号（如配送类小程序），前端引导用户点击授权按钮：

```xml
<!-- pages/profile/index.wxml -->
<button open-type="getPhoneNumber" bindgetphonenumber="onGetPhone">
  授权手机号
</button>
```

```javascript
// pages/profile/index.js
Page({
  onGetPhone(e) {
    if (e.detail.errMsg !== 'getPhoneNumber:ok') {
      wx.showToast({ title: '已取消授权', icon: 'none' });
      return;
    }
    // e.detail.code 交给服务端换取手机号
    wx.request({
      url: 'https://api.example.com/api/user/phone',
      method: 'POST',
      header: { Authorization: 'Bearer ' + wx.getStorageSync('token') },
      data: { code: e.detail.code },
      success: (res) => {
        if (res.data.code === 0) {
          wx.showToast({ title: '绑定成功', icon: 'success' });
        }
      }
    });
  }
});
```

服务端：

```java
@PostMapping("/user/phone")
public Result<Void> bindPhone(@RequestBody PhoneBindRequest request,
                              @AuthenticationPrincipal Long userId) {
    String phone = phoneService.getPhoneNumber(request.getCode());
    userService.bindPhone(userId, phone);   // 脱敏落库并标记已验证
    return Result.ok();
}
```

```text
场景二验证清单：
1. 新用户（未授权过）点击按钮：弹窗授权，同意后服务端拿到真实手机号
2. 已授权过再次点击：e.detail.code 依然有效（同一用户同一手机号）
3. 用错误 code 调接口：返回微信错误码，前端提示重新授权
4. 数据库 phone 字段存储脱敏或加密值，日志中无明文手机号
```

## 最佳实践与踩坑记录

### 最佳实践

1. 登录接口只接收 code，AppSecret 永远只在服务端，前端与网络层都不可能出现密钥
2. session_key 存 Redis 且 TTL 与登录态对齐（2 小时），不返回前端、不落日志、不落明文库
3. 用户表以 openid 唯一索引建号，unionid 判空处理，绑定开放平台后自动回填
4. 手机号等敏感数据优先用 getuserphonenumber 新接口，旧 decrypt 方式保留兼容即可
5. 解密必须校验 watermark.appid；解密结果立即使用，禁止打印明文
6. 登录态用 JWT（短过期 + 可刷新），前端存储 token 后请求头携带，服务端无状态校验
7. 登录接口加限流防刷（IP/设备维度），code2session 失败的错误码记录监控
8. 返回给前端的用户信息脱敏，内部字段（openid 全量、unionid）不出现在响应中

### 踩坑记录

```text
坑 1：code 被重复使用导致登录偶发失败
结论：同一 code 调两次 code2session，第二次返回 40029 invalid code。
原因：code 一次性有效；前端请求重试、双击、或日志系统重放请求都会造成重复使用。
解法：前端登录只触发一次；服务端捕获 40029 后返回明确提示让前端重新 wx.login。

坑 2：session_key 存到前端本地存储，用户数据可被任意解密
结论：攻击者拿到 session_key + encryptedData 即可解密任意敏感数据。
原因：开发时图省事把 session_key 随登录响应返回给前端缓存。
解法：session_key 只存服务端 Redis；前端需要解密时上传 encryptedData + iv 由服务端解密。

坑 3：AES 解密报错 "InvalidAlgorithmParameterException" 或解密出乱码
结论：手机号解密失败率高，偶发能解出但中文乱码。
原因：算法/填充不匹配（用了 ECB 或 NoPadding）、iv 处理错误、session_key 已过期。
解法：统一用 AES/CBC/PKCS5Padding；iv 与 key 都要 Base64 解码；解密前检查 session_key 是否存在。

坑 4：忽略 watermark 校验，数据被伪造
结论：接口返回的手机号与用户实际不符，客诉频发。
原因：只解密不校验 watermark.appid，任意 session_key 配任意密文都可能解出数据。
解法：解密后强制校验 watermark.appid 与自身 appid 一致，不一致直接拒绝。

坑 5：还在用旧版手机号解密方式，新基础库/新账号失效
结论：getPhoneNumber 返回的 e.detail 没有 encryptedData，只有 code，旧流程直接报错。
原因：2021 年起微信调整手机号能力，新版本只返回 code，需走 getuserphonenumber 接口。
解法：切换为 POST /wxa/business/getuserphonenumber 用 code 换手机号；旧方式仅兼容老版本。

坑 6：openid 前后端不一致导致用户重复创建
结论：同一用户数据库出现多条记录，订单归属错乱。
原因：后端存储/查询时 openid 大小写或编码不一致（如 URL 编码、尾随空格）。
解法：openid 统一小写存储并建唯一索引；插入前 trim；落库冲突时按唯一键幂等处理。

坑 7：没绑定开放平台，unionid 一直为 null
结论：期望通过 unionid 打通公众号与小程序账号，结果两边各建一套用户。
原因：unionid 需要小程序绑定微信开放平台账号后才返回。
解法：登录互通前先完成开放平台绑定；未绑定时降级用 openid 各自隔离。

坑 8：登录态 token 不设过期，安全审计不过
结论：token 永久有效，用户禁用后仍可访问业务接口。
原因：JWT 签发时未设置过期时间，也没有登出失效机制。
解法：token 设短过期（2 小时）+ refresh 机制；用户禁用/注销时在 Redis 黑名单中失效。
```

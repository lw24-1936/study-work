## 概述

路由（vue-router）与权限是管理后台的骨架：路由决定「页面长什么样、怎么跳转」，权限决定「谁能看、谁能点」。后台的权限模型通常分两级：菜单/页面级权限（用户能进入哪些路由）与按钮级权限（页面内能操作哪些功能）。本章覆盖 vue-router 4 的基础配置、登录后根据用户权限动态注册路由（addRoute）、全局路由守卫（token 校验与白名单）、按钮权限指令（v-permission）以及由路由表驱动菜单生成的完整链路。

```text
路由与权限要点：
1. vue-router 4 —— createRouter + createWebHistory，routes 数组声明路由
2. 嵌套路由 —— layout 作为父路由，页面作为子路由，形成后台框架
3. 动态路由 —— 登录后按权限 addRoute 注入，未授权页面不存在即不可访问
4. 路由守卫 —— beforeEach 统一处理 token 校验、登录跳转、权限校验
5. 按钮权限 —— v-permission 指令按权限点控制操作按钮显隐
6. 菜单生成 —— 由路由表递归生成侧边栏菜单，路由与菜单一份数据源
7. 白名单 —— 登录页、404 等公开路由在守卫中放行
```

## vue-router 基础

vue-router 4 是 Vue3 官方的路由库，核心 API：`createRouter` 创建路由实例，`createWebHistory` 使用 HTML5 History 模式（地址无 #，生产需 Nginx 配置 fallback 到 index.html），`routes` 数组声明路由表。管理后台的标准做法：`/login` 独立页面，`/` 挂载 layout 布局组件，业务页面全部作为 layout 的子路由渲染在 `<router-view>` 中。

```bash
npm install vue-router
```

```ts
// src/router/index.ts —— 路由入口
import { createRouter, createWebHistory } from 'vue-router'
import Layout from '@/layout/index.vue'
import type { RouteRecordRaw } from 'vue-router'

// 静态路由：所有人可见，无需权限
export const constantRoutes: RouteRecordRaw[] = [
  {
    path: '/login',
    name: 'Login',
    component: () => import('@/views/login/index.vue'),
    meta: { title: '登录', hidden: true }
  },
  {
    path: '/',
    component: Layout,
    redirect: '/dashboard',
    children: [
      {
        path: 'dashboard',
        name: 'Dashboard',
        component: () => import('@/views/dashboard/index.vue'),
        meta: { title: '工作台', icon: 'DataBoard' }
      }
    ]
  },
  {
    path: '/:pathMatch(.*)*',
    name: 'NotFound',
    component: () => import('@/views/error/404.vue'),
    meta: { title: '404', hidden: true }
  }
]

const router = createRouter({
  history: createWebHistory(),
  routes: constantRoutes
})

export default router
```

```ts
// src/main.ts —— 挂载路由
import { createApp } from 'vue'
import App from './App.vue'
import router from './router'

const app = createApp(App)
app.use(router)
app.mount('#app')
```

嵌套路由与命名路由跳转：

```ts
// 编程式导航
import { useRouter } from 'vue-router'
const router = useRouter()

router.push('/system/user')          // 路径跳转
router.push({ name: 'UserList' })    // 命名路由跳转
router.replace('/login')             // 替换当前记录（登录后不保留历史）
router.back()                        // 后退
```

```vue
<!-- 模板中声明式导航 -->
<template>
  <router-link to="/system/user">用户管理</router-link>
  <!-- 当前路由组件渲染位置 -->
  <router-view />
</template>
```

meta 字段约定：title 用于菜单与面包屑、icon 用于菜单图标、hidden 控制是否出现在菜单中。路由懒加载用 `component: () => import(...)`，按页面拆包，首屏只加载当前页。

```text
vue-router 基础要点：
1. History 模式 —— 地址干净，但生产环境必须配置 Nginx try_files 回退 index.html
2. 嵌套结构 —— layout 父路由 + 页面子路由，子路由 path 不写前导 /
3. 懒加载 —— 所有业务页面 () => import()，路由级代码分割
4. meta 约定 —— title/icon/hidden 三个字段支撑菜单与面包屑
5. 404 兜底 —— /:pathMatch(.*)* 捕获未匹配路径，防止白屏
6. 命名规范 —— name 与组件文件名保持一致，便于调试与命名跳转
```

## 动态路由

后台权限的核心思想：路由表不在初始化时全部注册，而是登录成功后根据当前用户的角色/权限码，把允许访问的路由动态 addRoute 注入。这样未授权的页面在路由表里根本不存在，用户即使手输 URL 也会落到 404，天然实现页面级权限隔离。权限数据由 SpringBoot 后台下发（RBAC 模型见 18.4），前端路由表通过 meta.roles 或 meta.permission 声明访问条件。

```ts
// src/router/dynamic.ts —— 动态路由表（按模块声明权限要求）
import type { RouteRecordRaw } from 'vue-router'

// 需要权限的路由，meta.permission 声明访问所需权限码
export const asyncRoutes: RouteRecordRaw[] = [
  {
    path: '/system',
    component: () => import('@/layout/index.vue'),
    redirect: '/system/user',
    meta: { title: '系统管理', icon: 'Setting' },
    children: [
      {
        path: 'user',
        name: 'SystemUser',
        component: () => import('@/views/system/user/index.vue'),
        meta: { title: '用户管理', permission: ['system:user:list'] }
      },
      {
        path: 'role',
        name: 'SystemRole',
        component: () => import('@/views/system/role/index.vue'),
        meta: { title: '角色管理', permission: ['system:role:list'] }
      }
    ]
  },
  {
    path: '/order',
    component: () => import('@/layout/index.vue'),
    redirect: '/order/list',
    meta: { title: '订单管理', icon: 'List' },
    children: [
      {
        path: 'list',
        name: 'OrderList',
        component: () => import('@/views/order/list/index.vue'),
        meta: { title: '订单列表', permission: ['order:list'] }
      }
    ]
  }
]
```

按权限过滤并注册路由：

```ts
// src/utils/permission.ts —— 过滤 + 注册动态路由
import router from '@/router'
import { asyncRoutes } from '@/router/dynamic'
import type { RouteRecordRaw } from 'vue-router'

// 递归过滤：只保留当前用户有权限的路由
export function filterAsyncRoutes(routes: RouteRecordRaw[], permissions: string[]): RouteRecordRaw[] {
  return routes.filter((route) => {
    const routePermission = route.meta?.permission as string[] | undefined
    // 没声明权限要求的路由直接放行；声明了则必须命中用户权限之一
    const allowed = !routePermission || routePermission.some((p) => permissions.includes(p))

    if (allowed && route.children) {
      route.children = filterAsyncRoutes(route.children, permissions)
    }
    return allowed
  })
}

// 动态注册：返回被注册的路由（用于菜单生成）
export function setupDynamicRoutes(permissions: string[]) {
  const accessible = filterAsyncRoutes(asyncRoutes, permissions)
  accessible.forEach((route) => router.addRoute(route))
  return accessible
}
```

退出登录时的清理（重置路由）：动态 addRoute 的路由无法直接删除，标准做法是保留一份初始路由表，退出后重新创建 router 实例替换。

```ts
// src/router/index.ts —— 追加 resetRouter 支持
import { createRouter, createWebHistory } from 'vue-router'
import { constantRoutes } from './constant' // 静态路由单独一个文件

const router = createRouter({
  history: createWebHistory(),
  routes: constantRoutes
})

// 重置路由：清空所有动态路由，回到初始状态
export function resetRouter() {
  const newRouter = createRouter({
    history: createWebHistory(),
    routes: constantRoutes
  })
  // 用新实例替换（配合 provide/inject 或直接赋值给导出变量）
  router.replace('/login')
  return newRouter
}

export default router
```

```text
动态路由要点：
1. 先登录后注册 —— 动态路由必须在拿到用户权限之后 addRoute
2. meta.permission —— 路由上声明所需权限码，与后台权限点一一对应
3. 递归过滤 —— 父子路由都要过滤，父无权限则整棵子树移除
4. 404 兜底顺序 —— 动态路由注册在 404 之后会匹配失败，见踩坑 3
5. 退出清理 —— resetRouter 重建实例或清空动态路由，防止权限残留
6. 刷新恢复 —— 页面刷新后动态路由丢失，需在守卫中重新注册（见下一节）
```

## 路由守卫

全局前置守卫 `router.beforeEach` 是权限控制的枢纽，每次路由跳转前执行。典型流程：判断是否登录（token 是否存在）→ 未登录且目标不在白名单则跳登录页 → 已登录访问登录页则跳首页 → 首次进入时拉取用户信息并注册动态路由。守卫里做「补齐动作」（拉权限、addRoute），页面组件里只消费数据。

```ts
// src/router/guard.ts —— 全局路由守卫
import router from './index'
import { useUserStore } from '@/stores/user'

// 白名单：不需要登录即可访问
const whiteList = ['/login']

router.beforeEach(async (to, from, next) => {
  const userStore = useUserStore()
  const hasToken = userStore.token

  if (hasToken) {
    if (to.path === '/login') {
      // 已登录还去登录页，直接回首页
      next({ path: '/' })
      return
    }

    if (userStore.permissions.length === 0) {
      try {
        // 首次进入：拉取用户信息与权限码
        await userStore.getUserInfo()
        // 根据权限注册动态路由
        userStore.generateRoutes()
        // 动态路由注册是异步的，必须 replace 重新进入目标路由
        next({ ...to, replace: true })
        return
      } catch (error) {
        // 拉取用户信息失败（token 失效等）：清除并回登录页
        userStore.resetToken()
        next(`/login?redirect=${encodeURIComponent(to.fullPath)}`)
        return
      }
    }

    next()
  } else {
    if (whiteList.includes(to.path)) {
      next()
    } else {
      // 未登录访问受保护页面：记录来源，登录后跳回
      next(`/login?redirect=${encodeURIComponent(to.fullPath)}`)
    }
  }
})
```

守卫中动态路由注册的关键细节：`addRoute` 是同步的，但新增路由后当前导航的匹配是旧的，必须 `next({ ...to, replace: true })` 重新触发一次导航，否则第一次跳转会落到 404。

登录页读取 redirect 并跳回：

```ts
// src/views/login/index.vue —— 登录成功后的跳转逻辑
import { useRoute, useRouter } from 'vue-router'

const route = useRoute()
const router = useRouter()

function handleLoginSuccess() {
  // 优先回到来源页，否则去首页
  const redirect = (route.query.redirect as string) || '/'
  router.replace(redirect)
}
```

```text
路由守卫要点：
1. 单一入口 —— 所有跳转检查集中在 beforeEach，页面不各自判断
2. 白名单 —— 登录页、公开页必须在白名单，否则死循环跳转
3. token 校验 —— 有 token 不等于权限有效，拉取失败要清理并回登录
4. next({ ...to, replace: true }) —— 动态路由注册后必须重新导航
5. redirect 参数 —— 记录来源页，登录后回跳，体验闭环
6. 避免死循环 —— 守卫内跳转的目标必须能通过守卫检查
```

## 按钮权限

页面级权限控制「能进哪个页面」，按钮级权限控制「页面上能点哪个按钮」。实现方式：自定义指令 `v-permission`，值为权限点字符串或数组，指令的 mounted 钩子检查当前用户权限，不满足则移除元素。权限点由后台统一管理（如 system:user:add、system:user:delete），与接口权限点一致。

```ts
// src/directives/permission.ts —— 按钮权限指令
import type { Directive, DirectiveBinding } from 'vue'
import { useUserStore } from '@/stores/user'

// 判断用户是否拥有权限点
export function hasPermission(permission: string | string[]): boolean {
  const userStore = useUserStore()
  const permissions = userStore.permissions

  if (Array.isArray(permission)) {
    return permission.some((p) => permissions.includes(p))
  }
  return permissions.includes(permission)
}

const permissionDirective: Directive = {
  mounted(el: HTMLElement, binding: DirectiveBinding) {
    const { value } = binding
    if (value === undefined || value === null) return

    const required = Array.isArray(value) ? value : [value]
    const allowed = required.some((p) => hasPermission(p))
    if (!allowed) {
      // 移除按钮节点，实现显隐控制
      el.parentNode?.removeChild(el)
    }
  }
}

export default permissionDirective
```

```ts
// src/main.ts —— 注册指令
import permission from '@/directives/permission'

const app = createApp(App)
app.directive('permission', permissionDirective)
```

模板中使用：

```vue
<template>
  <!-- 拥有 system:user:add 权限才显示新增按钮 -->
  <el-button v-permission="'system:user:add'" type="primary" @click="openDialog">
    新增用户
  </el-button>

  <!-- 数组：满足任一权限点即显示 -->
  <el-button v-permission="['system:user:edit', 'system:user:reset']" @click="handleReset">
    重置密码
  </el-button>

  <!-- 无权限时的兜底写法（不推荐，判断逻辑散落） -->
  <el-button v-if="hasPermission('system:user:delete')" type="danger">删除</el-button>
</template>

<script setup lang="ts">
import { hasPermission } from '@/directives/permission'
</script>
```

权限点与后端 RBAC 的关系：角色 -> 权限点集合由后台维护（18.4），登录后 `/user/info` 接口返回当前用户的权限点数组，前端存入 Pinia（20.4）。前端权限只是 UI 控制，真正的安全边界在后台接口层——后台同样校验权限点，前端隐藏按钮只是提升体验。

```text
按钮权限要点：
1. 指令方式 —— v-permission 集中管理显隐逻辑，模板最干净
2. 权限点命名 —— 模块:实体:动作（system:user:add），与接口权限一一对应
3. 数组语义 —— 多权限点用 some（任一满足），需要 all 时自行扩展
4. 前后端双校验 —— 前端控制 UI，后台校验接口，安全边界在后台
5. 权限来源 —— 登录后接口下发，存 Pinia，页面与指令共享
6. 兜底处理 —— 指令只处理 mounted，动态新增按钮需配合组件 key 刷新
```

## 菜单生成

菜单由「已注册的动态路由」生成，一份数据源保证菜单与路由永远一致：有路由权限就有菜单，无权限的菜单自然消失。生成逻辑是递归遍历路由表，利用 meta.title（菜单文案）、meta.icon（图标）、meta.hidden（是否隐藏）渲染 el-menu。子路由转成 el-sub-menu，叶子路由转成 el-menu-item。

```ts
// src/utils/menu.ts —— 路由转菜单数据结构
import type { RouteRecordRaw } from 'vue-router'

export interface MenuItem {
  path: string
  title: string
  icon?: string
  children?: MenuItem[]
}

// 递归转换：路由表 -> 菜单树
export function buildMenuTree(routes: RouteRecordRaw[]): MenuItem[] {
  const menus: MenuItem[] = []
  routes.forEach((route) => {
    // hidden 的路由不进菜单
    if (route.meta?.hidden) return

    const item: MenuItem = {
      path: resolvePath(route),
      title: (route.meta?.title as string) || route.name?.toString() || '',
      icon: route.meta?.icon as string | undefined
    }

    // 有子路由且有非 hidden 子项时继续递归
    if (route.children && route.children.length > 0) {
      const children = buildMenuTree(route.children)
      if (children.length > 0) {
        item.children = children
        menus.push(item)
      }
    } else {
      menus.push(item)
    }
  })
  return menus
}

// 拼接父子路径：/system + user -> /system/user
function resolvePath(route: RouteRecordRaw, parentPath = ''): string {
  const path = route.path.startsWith('/') ? route.path : `${parentPath}/${route.path}`
  return path.replace(/\/+/g, '/')
}
```

布局侧边栏渲染菜单树：

```vue
<!-- src/layout/components/SidebarMenu.vue —— 递归菜单组件 -->
<template>
  <template v-for="item in menus" :key="item.path">
    <!-- 有子菜单 -->
    <el-sub-menu v-if="item.children && item.children.length" :index="item.path">
      <template #title>
        <el-icon v-if="item.icon"><component :is="item.icon" /></el-icon>
        <span>{{ item.title }}</span>
      </template>
      <!-- 递归渲染子菜单 -->
      <SidebarMenu :menus="item.children" />
    </el-sub-menu>

    <!-- 叶子菜单 -->
    <el-menu-item v-else :index="item.path">
      <el-icon v-if="item.icon"><component :is="item.icon" /></el-icon>
      <span>{{ item.title }}</span>
    </el-menu-item>
  </template>
</template>

<script setup lang="ts">
import type { MenuItem } from '@/utils/menu'

  menus: MenuItem[]

// 递归组件需要自己引用自己

</script>
```

```vue
<!-- src/layout/index.vue —— 侧边栏接入菜单树 -->
<template>

```

```text
菜单生成要点：
1. 单数据源 —— 菜单来自已注册路由，权限过滤一次，菜单/路由天然一致
2. 递归组件 —— 子菜单嵌套用组件自引用，菜单层级无上限
3. meta.hidden —— 详情页、404 等不进菜单的路由用 hidden 标记
4. 动态图标 —— <component :is="icon" /> 按 meta.icon 字符串渲染组件
5. 路径拼接 —— 嵌套子路由 path 相对时需拼接父路径
6. 刷新保持 —— 菜单树存 Pinia，刷新后由守卫重新生成，不依赖页面状态
```

## 应用场景实战

### 场景一：登录后按角色生成路由与菜单

完整走一遍「登录 -> 拉权限 -> 注册动态路由 -> 生成菜单 -> 进入工作台」：

```text
实现步骤：
1. 用户打开 /system/user，守卫发现无 token，跳转 /login?redirect=%2Fsystem%2Fuser
2. 登录表单提交，调用 /auth/login 拿到 token，存入 Pinia 并持久化（20.4）
3. 守卫检测到 token 存在且 permissions 为空，调用 getUserInfo()
4. /user/info 返回角色与权限码数组，如 ['system:user:list', 'system:user:add', 'order:list']
5. setupDynamicRoutes 过滤 asyncRoutes，只注册有权限的路由
6. buildMenuTree 生成菜单树存入 Pinia，SidebarMenu 渲染侧边栏
7. next({ ...to, replace: true }) 重新进入目标路由，正常渲染页面
8. 无 order 权限的用户，订单菜单不显示，手输 /order/list 落到 404
```

核心代码（守卫与 store 协作）：

```ts
// src/stores/user.ts —— 用户 store（关键部分，完整版见 20.4）
import { defineStore } from 'pinia'
import { login, getUserInfo } from '@/api/auth'
import { setupDynamicRoutes } from '@/router/dynamic'
import { buildMenuTree } from '@/utils/menu'

export const useUserStore = defineStore('user', {
  state: () => ({
    token: localStorage.getItem('token') || '',
    name: '',
    permissions: [] as string[],
    menuTree: [] as ReturnType<typeof buildMenuTree>
  }),
  actions: {
    async loginAction(form: { username: string; password: string }) {
      const res = await login(form)
      this.token = res.data.token
      localStorage.setItem('token', this.token)
    },
    async getUserInfo() {
      const res = await getUserInfo()
      this.name = res.data.name
      this.permissions = res.data.permissions
      // 注册动态路由并生成菜单树
      const accessibleRoutes = setupDynamicRoutes(this.permissions)
      this.menuTree = buildMenuTree(accessibleRoutes)
    },
    logout() {
      this.token = ''
      this.permissions = []
      this.menuTree = []
      localStorage.removeItem('token')
    }
  }
})
```

```text
验证清单：
1. 未登录访问任何业务页都跳到登录页，且登录后回到原页面
2. 登录成功后侧边栏只显示有权限的菜单，工作台默认打开
3. 修改账号角色（后台操作），重新登录后菜单随之变化
4. 手输无权限路径（如 /order/list）显示 404 页面
5. 刷新页面路由与菜单保持，不闪 404 不丢高亮
6. 退出登录后清空权限，再访问业务页重新要求登录
```

## 最佳实践与踩坑记录

### 最佳实践

1. 权限数据只从后台获取（登录接口返回权限码数组），前端不做角色硬编码，角色变更无需发版
2. 路由表分两个文件：constantRoutes（公开路由）与 asyncRoutes（权限路由），职责清晰
3. 页面级权限用动态路由实现（未注册即不存在），按钮级权限用 v-permission 指令实现，两层各司其职
4. 守卫中统一处理 token 校验、拉取用户信息、注册动态路由，页面组件不感知权限流程
5. 菜单由路由生成，杜绝「路由一份、菜单一份」的双份维护
6. 权限点命名统一「模块:实体:动作」三段式，与后台接口权限点完全一致
7. 退出登录必须重置路由（resetRouter）并清空 Pinia 权限数据，防止账号切换权限残留
8. 前端权限只是体验优化，所有敏感接口后台必须二次校验权限

### 踩坑记录

```text
坑 1：登录后第一次跳转页面白屏或 404
结论：登录成功进入 /system/user 显示空白或 404。
原因：动态路由 addRoute 后当前导航仍按旧路由表匹配，目标路由未命中。
解法：守卫中动态路由注册完成后 next({ ...to, replace: true }) 重新触发导航，不要直接 next()。

坑 2：动态路由注册后刷新页面 404
结论：刷新任意业务页都落到 404。
原因：动态路由是内存态，刷新后丢失，守卫又因 permissions 非空跳过重新注册。
解法：守卫中判断 permissions 为空才拉取并注册；把拉取条件改为「token 存在且动态路由未注册」的标记位。

坑 3：动态路由注册在 404 路由之后，访问仍 404
结论：addRoute 注册成功，但访问该路径仍匹配到 404。
原因：vue-router 按注册顺序匹配，通配 404 先注册时优先匹配。
解法：404 路由放最后注册；或动态路由注册后再追加 404 兜底（router.addRoute 404 在动态注册之后）。

坑 4：守卫内跳登录页形成死循环
结论：浏览器卡死或控制台大量重定向报错。
原因：登录页不在白名单，未登录访问 /login 又被守卫拦截跳 /login。
解法：白名单必须包含 /login；白名单判断放在最前面，token 存在且访问 /login 时跳首页。

坑 5：token 过期后接口报 401，但前端还停留在页面
结论：登录状态已失效，页面仍可操作，操作时报错。
原因：守卫只在导航时校验 token，无导航动作时 token 过期无法感知。
解法：axios 响应拦截器统一处理 401（清除 token 跳登录，见 20.4），与路由守卫双保险。

坑 6：v-permission 对 el-table-column 内的按钮不生效
结论：操作列里加 v-permission 的按钮仍然显示。
原因：指令 mounted 时元素可能还未渲染完成，或按钮被表格缓存复用。
解法：操作列模板中改用 v-if="hasPermission('xxx')" 判断；或对表格行使用 row-key 强制刷新。

坑 7：菜单高亮与路由不一致（父级菜单不高亮）
结论：进入子页面时父级菜单不展开、不高亮。
原因：default-active 只匹配精确 path，子路由未在菜单 index 中体现层级。
解法：default-active 用当前路由 path，配合 el-menu 的 unique-opened 与 default-openeds 展开父级；或按 meta.activeMenu 指定高亮项。

坑 8：退出登录后切换账号，看到上个账号的菜单
结论：A 账号退出，B 账号登录后菜单包含 A 的权限菜单。
原因：动态路由未清理，新账号注册的新路由叠加在旧路由之上。
解法：退出时 resetRouter（重建路由实例）并清空 Pinia 的 permissions/menuTree；若无法重建实例，记录已注册路由名并在退出时逐个 removeRoute。
```

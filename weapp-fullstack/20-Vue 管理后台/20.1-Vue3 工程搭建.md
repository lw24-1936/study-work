## 概述

Vue 管理后台是整个「微信小程序 + SpringBoot + Vue 管理后台」全栈架构中的 B 端部分，负责商品、订单、用户、运营配置等管理功能。本章以 Vue3 + TypeScript + Vite 为技术底座，讲解工程从零创建、目录规范、构建配置、代码规范与环境管理，为后续 Element Plus 布局、路由权限、Pinia 状态管理、axios 请求封装打下基础。管理后台与小程序共用同一个 SpringBoot 后台，通过 REST API 交互，因此工程搭建阶段就要规划好接口代理、环境变量与跨域方案。

```text
Vue3 工程搭建要点：
1. Vite —— 新一代构建工具，基于 esbuild 与 Rollup，开发冷启动毫秒级
2. vue-ts 模板 —— TypeScript + Vue3 组合式 API 的标准起点
3. 目录规范 —— src 下按 api/components/layout/router/stores/views 分层
4. vite.config.ts —— alias 别名、dev server 代理是联调的关键配置
5. 代码规范 —— ESLint 9 flat config + Prettier，统一团队风格
6. 环境变量 —— .env.development / .env.production 区分多套环境
7. 依赖管理 —— 运行时依赖与开发依赖分离，lock 文件必须入库
```

## Vite 创建项目与模板选择

Vite 是 Vue3 官方推荐的构建工具，开发环境基于原生 ES Module 按需编译（esbuild），无需打包整个应用即可启动，热更新（HMR）毫秒级生效；生产构建使用 Rollup 做 tree-shaking 与代码分割。创建 Vue3 + TypeScript 项目有两条主流路径：`npm create vite@latest` 选择 vue-ts 模板（干净基础），或 `npm create vue@latest`（create-vue，Vue 官方脚手架，可在创建时勾选 Router、Pinia、ESLint、Prettier 等选项，适合直接生成后台项目骨架）。

```bash
# 方式一：Vite 官方模板（vue-ts = Vue3 + TypeScript）
npm create vite@latest admin-web -- --template vue-ts

# 方式二：Vue 官方脚手架 create-vue（交互式勾选 router/pinia/eslint/prettier）
npm create vue@latest admin-web

# 进入目录安装依赖并启动
cd admin-web
npm install
npm run dev
```

方式二的交互式选项示意：

```text
create-vue 交互选项：
1. TypeScript?  —— 选择 Yes（后台项目建议全程 TS）
2. JSX 支持?    —— 不需要可 No（模板语法足够）
3. Vue Router?  —— Yes（20.3 路由与权限的基础）
4. Pinia?       —— Yes（20.4 状态管理的基础）
5. ESLint?      —— Yes，并选择 ESLint + Prettier 组合
6. 单元测试?    —— 后台项目可选 Vitest，本知识库不强制
```

`npm create vite@latest` 生成的基础工程结构如下：

```text
admin-web/
├── index.html            # 入口 HTML，挂载 #app
├── package.json          # 依赖与脚本
├── tsconfig.json         # TS 总配置（引用子配置）
├── tsconfig.app.json     # src 代码的 TS 配置
├── tsconfig.node.json    # vite.config.ts 等 Node 侧配置
├── vite.config.ts        # Vite 构建与开发服务器配置
├── public/               # 静态资源（不经过构建，直接复制）
└── src/
    ├── main.ts           # 应用入口：创建实例、挂载插件
    ├── App.vue           # 根组件
    ├── vite-env.d.ts     # Vite 客户端类型声明
    ├── assets/           # 资源文件（图片、字体等）
    └── components/       # 组件目录
```

入口文件 `src/main.ts` 与 `index.html` 是应用启动的最小闭环：

```ts
// src/main.ts —— 最小入口（后续逐步挂载 router、pinia、element-plus）
import { createApp } from 'vue'
import App from './App.vue'
import './style.css'

createApp(App).mount('#app')
```

```html
<!-- index.html —— Vite 的入口 HTML，script 使用 module 方式加载 main.ts -->
<!DOCTYPE html>
<html lang="zh-CN">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>商城管理后台</title>
  </head>
  <body>
    <div id="app"></div>
    <script type="module" src="/src/main.ts"></script>
  </body>
</html>
```

```text
创建项目要点：
1. 模板选 vue-ts —— Vue3 + TS 是管理后台的主流组合，类型安全可控
2. create-vue 可选型 —— 需要 router/pinia/eslint 就一次勾选，省去手工配置
3. index.html 不能删 —— Vite 以它为入口，div#app 与 module script 缺一不可
4. node 版本要求 —— Vite 5 需要 Node 18+，先 node -v 确认
5. 首次启动 —— npm run dev 默认 5173 端口，终端会输出访问地址
6. 版本注意 —— create vite 交互式命令在非交互 shell 里要加 -- --template 透传
```

## 项目结构与 vite 配置文件

工程创建后第一步是把 src 目录按职责划分好。后台项目的推荐结构：api 放接口模块、layout 放整体布局、views 放页面、stores 放 Pinia 仓库、utils 放工具函数（请求封装、token 管理等）、directives 放自定义指令。约定优于配置，目录一旦确定就不要再随意变动，否则 import 路径满天飞。

```text
后台项目 src 目录规范：
src/
├── api/          # 接口请求模块（按业务域拆分：user.ts、order.ts、product.ts）
├── assets/       # 静态资源（图片、字体）
├── components/   # 通用业务组件（分页、搜索表单、状态标签）
├── directives/   # 自定义指令（v-permission 按钮权限）
├── layout/       # 后台布局（侧边栏 + 顶栏 + 主内容区）
├── router/       # 路由配置（静态路由 + 动态路由表）
├── stores/       # Pinia 仓库（user、app、permission）
├── styles/       # 全局样式与主题变量（index.scss、element 覆盖）
├── utils/        # 工具函数（request.ts、auth.ts、validate.ts）
├── views/        # 页面组件（按模块分目录：system/user、order/list）
├── App.vue       # 根组件
├── main.ts       # 应用入口
└── vite-env.d.ts # 环境变量类型声明
```

vite.config.ts 是工程配置的核心：`resolve.alias` 定义 `@` 指向 src，配合 tsconfig 的 paths 让 TS 与 Vite 的路径解析一致；`server.proxy` 把开发环境的 `/api` 请求转发到本地 SpringBoot（8080），从而规避开发期跨域。生产环境则通过 Nginx 反向代理，配置思路与 dev proxy 相同。

```ts
// vite.config.ts —— 别名 + 开发代理 + 构建配置
import { fileURLToPath, URL } from 'node:url'
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'

export default defineConfig({
  plugins: [vue()],
  resolve: {
    alias: {
      // @ 指向 src，import { request } from '@/utils/request'
      '@': fileURLToPath(new URL('./src', import.meta.url))
    }
  },
  server: {
    host: '0.0.0.0', // 允许局域网访问（手机真机调试时有用）
    port: 5173,
    proxy: {
      // 所有 /api 开头的请求转发到 SpringBoot 后台
      '/api': {
        target: 'http://localhost:8080', // 后台地址
        changeOrigin: true               // 修改请求 Host 头为后台域名
        // 若后台接口没有 /api 前缀，用 rewrite 去掉：
        // rewrite: (path) => path.replace(/^\/api/, '')
      }
    }
  },
  build: {
    outDir: 'dist',
    chunkSizeWarningLimit: 1500 // 单包超过 1500KB 才告警，避免分包提示噪音
  }
})
```

alias 要同时让 TypeScript 认识，tsconfig 中声明 paths，否则编辑器报红、`vue-tsc` 构建失败：

```json
// tsconfig.json —— 关键片段
{
  "compilerOptions": {
    "baseUrl": ".",
    "paths": {
      "@/*": ["src/*"]
    },
    "moduleResolution": "bundler",
    "target": "ES2020",
    "strict": true
  }
}
```

```text
项目结构配置要点：
1. @ 别名 —— 深层相对路径 ../.. 极易写错，统一用 @ 指向 src
2. proxy 代理 —— 开发期前端无跨域问题，代理目标指向本地 SpringBoot
3. changeOrigin —— 必须为 true，否则后台校验 Host 时可能拒绝请求
4. 目录分层 —— api/layout/stores/views 各司其职，组件与页面分离
5. tsconfig paths —— 与 vite alias 保持一致，双配置缺一不可
6. host 0.0.0.0 —— 需要手机/其他机器访问时才能用，默认 localhost 即可
```

## 依赖管理与 package json

后台项目的依赖分为两类：dependencies 是运行时依赖（vue、vue-router、pinia、element-plus、axios），devDependencies 是构建与开发期依赖（vite、typescript、eslint、prettier、vue-tsc、@vitejs/plugin-vue）。安装时用 `npm install <pkg>` 写入 dependencies，`npm install -D <pkg>` 写入 devDependencies，不要混淆，否则生产部署会多装无用的开发依赖。

```json
// package.json —— 商城管理后台完整依赖清单
{
  "name": "admin-web",
  "version": "1.0.0",
  "private": true,
  "type": "module",
  "scripts": {
    "dev": "vite",
    "build": "vue-tsc -b && vite build",
    "preview": "vite preview",
    "lint": "eslint .",
    "lint:fix": "eslint . --fix",
    "format": "prettier --write \"src/**/*.{ts,vue}\""
  },
  "dependencies": {
    "@element-plus/icons-vue": "^2.3.1",
    "axios": "^1.7.2",
    "element-plus": "^2.7.6",
    "pinia": "^2.1.7",
    "pinia-plugin-persistedstate": "^3.2.1",
    "vue": "^3.4.29",
    "vue-router": "^4.3.3"
  },
  "devDependencies": {
    "@types/node": "^20.14.2",
    "@vitejs/plugin-vue": "^5.0.5",
    "eslint": "^9.5.0",
    "eslint-plugin-vue": "^9.26.0",
    "prettier": "^3.3.2",
    "typescript": "^5.4.5",
    "typescript-eslint": "^7.13.1",
    "vite": "^5.3.1",
    "vue-tsc": "^2.0.21"
  }
}
```

常用依赖操作命令：

```bash
# 安装运行时依赖（写入 dependencies）
npm install axios element-plus vue-router pinia

# 安装开发依赖（写入 devDependencies）
npm install -D vite typescript eslint prettier vue-tsc

# 安装指定版本
npm install element-plus@2.7.6

# 查看过时依赖
npm outdated

# 升级依赖
npm update
```

包管理器选择：npm 是默认选择，无需额外安装；pnpm 通过硬链接 + 符号链接复用全局存储，安装速度快、磁盘占用小，且默认严格依赖声明（幽灵依赖问题少），中大型团队推荐。无论用哪个，`package-lock.json` 或 `pnpm-lock.yaml` 都必须提交到 Git：lock 文件锁定精确版本，保证团队与 CI 环境安装出完全一致的依赖树。

```bash
# pnpm 安装与常用命令（命令风格与 npm 基本一致）
npm install -g pnpm
pnpm install
pnpm add element-plus
pnpm add -D typescript
pnpm run dev
```

```text
依赖管理要点：
1. 依赖分类 —— 运行时进 dependencies，构建期进 devDependencies
2. lock 文件 —— package-lock.json / pnpm-lock.yaml 必须入库，禁止 gitignore
3. 版本范围 —— ^1.7.2 表示允许 1.x 内升级，锁大版本不锁小版本
4. 团队统一 —— 全组用同一个包管理器（npm 或 pnpm），避免双 lock 文件冲突
5. 脚本规范 —— dev/build/lint/format 命名统一，新人上手零成本
6. build 脚本 —— vue-tsc -b && vite build：先类型检查再打包，质量前置
```

## ESLint 与 Prettier 规范

ESLint 负责代码质量（未使用变量、隐式 any、console 残留等），Prettier 负责代码格式（分号、引号、缩进、换行）。两者职责分离：ESLint 查「对不对」，Prettier 管「好不好看」。ESLint 9 起采用 flat config（eslint.config.js 替代 .eslintrc.js），配合 eslint-plugin-vue 与 typescript-eslint 即可覆盖 .vue 与 .ts 文件。

```js
// eslint.config.js —— ESLint 9 flat config（Vue3 + TS 推荐配置）
import js from '@eslint/js'
import vue from 'eslint-plugin-vue'
import tseslint from 'typescript-eslint'

export default tseslint.config(
  { ignores: ['dist/**', 'node_modules/**', 'public/**'] },
  js.configs.recommended,
  ...tseslint.configs.recommended,
  ...vue.configs['flat/recommended'],
  {
    files: ['**/*.{ts,vue}'],
    languageOptions: {
      parserOptions: {
        parser: tseslint.parser,
        extraFileExtensions: ['.vue']
      }
    },
    rules: {
      'vue/multi-word-component-names': 'off', // 允许单文件名（如 index.vue）
      '@typescript-eslint/no-explicit-any': 'warn', // any 降级为警告
      'vue/no-v-html': 'warn'
    }
  }
)
```

```json
// .prettierrc.json —— Prettier 格式化规则
{
  "semi": false,
  "singleQuote": true,
  "printWidth": 100,
  "trailingComma": "none",
  "endOfLine": "lf"
}
```

```json
// .prettierignore —— 不参与格式化的文件
dist
node_modules
public
package-lock.json
```

ESLint 与 Prettier 的配合：格式类问题交给 Prettier，规则类问题交给 ESLint。避免两者规则冲突，eslint-plugin-vue 的 prettier 相关规则可关闭（prettier 自己管格式即可）。编辑器侧建议安装 ESLint 与 Prettier 扩展并开启 format on save，实现保存即格式化。

```bash
# 命令行执行
npm run lint        # 检查全部代码
npm run lint:fix    # 自动修复可修复问题
npm run format      # Prettier 全量格式化
```

```text
代码规范要点：
1. flat config —— ESLint 9 用 eslint.config.js，旧 .eslintrc 写法已废弃
2. 分工明确 —— ESLint 管质量，Prettier 管格式，不要混用
3. lint:fix —— 提交前先跑，自动修复缩进、引号、分号类问题
4. no-explicit-any —— 后台项目建议 warn 起步，关键类型仍要显式声明
5. 与编辑器联动 —— 保存时自动格式化，减少人工对齐成本
6. 规范先行 —— 项目第一天就配好，后期补配置会面临海量存量报错
```

## 环境变量与构建模式

管理后台至少需要开发、测试、生产三套环境。Vite 通过根目录下的 .env 文件管理环境变量，规则：只有 `VITE_` 前缀的变量会暴露给前端代码（通过 import.meta.env 读取），防止把密钥类配置打进包。`.env.development` 在 `npm run dev` 时生效，`.env.production` 在 `npm run build` 时生效，同名变量后者覆盖前者。

```bash
# .env.development —— 开发环境（npm run dev 加载）
VITE_APP_TITLE=商城管理后台（开发环境）
VITE_APP_BASE_URL=/api
VITE_APP_UPLOAD_URL=/api/upload
```

```bash
# .env.production —— 生产环境（npm run build 加载）
VITE_APP_TITLE=商城管理后台
VITE_APP_BASE_URL=https://api.example.com/api
VITE_APP_UPLOAD_URL=https://api.example.com/api/upload
```

```bash
# .env —— 所有环境共用的公共变量（可选）
VITE_APP_NAME=weapp-shop-admin
```

TS 项目需要为 import.meta.env 声明类型，编辑器才能智能提示：

```ts
// src/vite-env.d.ts —— 环境变量类型声明
/// <reference types="vite/client" />

interface ImportMetaEnv {
  readonly VITE_APP_TITLE: string
  readonly VITE_APP_BASE_URL: string
  readonly VITE_APP_UPLOAD_URL: string
}

interface ImportMeta {
  readonly env: ImportMetaEnv
}
```

代码中读取环境变量：

```ts
// src/utils/config.ts —— 集中读取，避免散落各处
export const appTitle = import.meta.env.VITE_APP_TITLE

export const baseURL = import.meta.env.VITE_APP_BASE_URL

export const uploadURL = import.meta.env.VITE_APP_UPLOAD_URL

// 内置模式判断
export const isProd = import.meta.env.PROD
export const isDev = import.meta.env.DEV
```

```text
环境变量要点：
1. VITE_ 前缀 —— 只有带此前缀的变量会进入 import.meta.env，密钥类绝不写这里
2. 按模式加载 —— development 对应 dev，production 对应 build，文件命名严格
3. 修改需重启 —— .env 改动后必须重启 dev server 才生效
4. 类型声明 —— vite-env.d.ts 声明后才有提示与类型检查
5. 集中读取 —— 统一封装到 config.ts，页面里不要直接 import.meta.env
6. 生产环境 —— BASE_URL 直接写线上域名，由 Nginx 或网关转发
```

## 应用场景实战

### 场景一：从零创建商城管理后台工程并启动

以「weapp-shop-admin」为例，完整走一遍创建到启动的流程：

```bash
# 1. 创建项目（vue-ts 模板，非交互式写法）
npm create vite@latest weapp-shop-admin -- --template vue-ts

# 2. 安装基础依赖
cd weapp-shop-admin
npm install
npm install vue-router pinia element-plus @element-plus/icons-vue axios
npm install -D prettier eslint eslint-plugin-vue typescript-eslint

# 3. 整理目录
mkdir -p src/{api,layout,router,stores,utils,views,styles,directives,components}

# 4. 配置 vite.config.ts 的 alias 与 proxy（见上文完整配置）

# 5. 启动开发服务器
npm run dev
```

验证清单：

```text
启动验证：
1. 终端输出 Local: http://localhost:5173/，浏览器打开看到 Hello Vue 页面
2. 修改 src/App.vue 后页面秒级热更新，无需手动刷新
3. 新建 src/views/Dashboard.vue，App.vue 中 import 引用，路径可用 @/views/Dashboard
4. 运行 npm run build，dist 目录生成且无类型错误
5. 运行 npm run lint，无 error 级别问题
6. package-lock.json 已生成并纳入 Git 管理
```

### 场景二：配置代理实现前后端本地联调

本地同时启动 SpringBoot（8080）与 Vue dev server（5173），通过代理打通：

```ts
// vite.config.ts —— 完整联调代理配置
server: {
  port: 5173,
  proxy: {
    '/api': {
      target: 'http://localhost:8080',
      changeOrigin: true
    },
    // 文件上传单独代理（SpringBoot 上传接口）
    '/upload': {
      target: 'http://localhost:8080',
      changeOrigin: true
    }
  }
}
```

```ts
// src/utils/request.ts —— 请求地址使用相对路径，由代理转发
import axios from 'axios'

const request = axios.create({
  baseURL: '/api', // 开发环境被 vite proxy 转发到 8080
  timeout: 10000
})

export default request
```

```text
联调验证：
1. 后台启动后，浏览器访问 http://localhost:8080/api/health 确认可达
2. 前端调用 request.get('/user/list')，实际请求为 http://localhost:5173/api/user/list
3. 观察 SpringBoot 日志，确认收到来自 5173 转发的请求且无跨域报错
4. 若后台报跨域，优先检查 changeOrigin 与后台 CORS 配置（见 21.3）
5. 生产环境去掉代理，baseURL 使用 .env.production 的完整域名
6. 联调完成后把代理配置提交，团队成员 clone 即可复现
```

## 最佳实践与踩坑记录

### 最佳实践

1. 项目第一天就配置好 ESLint + Prettier + TS strict，后期再补会面对海量存量报错，几乎无法推行
2. 所有路径统一走 `@/` 别名，禁止出现 ../../ 这种深层相对路径，重构目录时只需改一处
3. 环境变量集中到 utils/config.ts 读取，页面代码不直接触碰 import.meta.env，便于维护与测试
4. 依赖锁定：lock 文件必须提交，团队统一包管理器，升级依赖单独提交并跑全量回归
5. build 脚本保留 vue-tsc 类型检查步骤，让类型错误在 CI 阶段暴露而不是上线后
6. 提交前强制跑 lint:fix 与 format，可配置 husky + lint-staged 实现提交前自动检查
7. Node 版本用 .nvmrc 或 engines 字段声明，避免团队成员版本不一致导致构建差异
8. dist 产物不进 Git 仓库，发布由 CI 构建或服务器构建，保证产物可追溯

### 踩坑记录

```text
坑 1：npm create vite 在 CI/非交互 shell 中卡住等待选择模板
结论：命令长时间无响应，默认停在模板选择界面。
原因：npm create vite@latest 默认是交互式命令，需要手动选择框架与模板。
解法：追加 -- --template vue-ts 透传参数，一条命令直达，如 npm create vite@latest admin -- --template vue-ts。

坑 2：配置了 @ 别名但编辑器与 vue-tsc 仍然报错
结论：import 路径带 @ 时编辑器红色波浪线，npm run build 报找不到模块。
原因：只配了 vite.config.ts 的 alias，tsconfig.json 的 paths 未同步配置。
解法：tsconfig 中声明 baseUrl 与 paths 映射 @/* -> src/*，两边保持一致。

坑 3：dev 代理配置了但请求仍然 404 或跨域
结论：页面请求 /api/xxx 返回 404，或控制台报 CORS 错误。
原因：rewrite 写错导致路径不匹配；或 changeOrigin 未开，后台校验 Host 拒绝；或代理路径与请求前缀不一致。
解法：确认请求前缀与 proxy 的 key 完全一致；后台无 /api 前缀时用 rewrite 去掉；changeOrigin 置 true。

坑 4：import.meta.env.VITE_APP_XXX 读取为 undefined
结论：页面拿到 undefined，接口 baseURL 变成 undefined。
原因：变量名没有 VITE_ 前缀被过滤；或修改 .env 后没有重启 dev server。
解法：变量统一加 VITE_ 前缀；修改 .env 后重启 npm run dev；在 vite-env.d.ts 补类型声明排查拼写。

坑 5：npm run build 通过，但部署后页面白屏
结论：生产环境访问页面空白，控制台报资源路径错误。
原因：打包时资源使用绝对路径 /assets/xxx，部署在子路径或未配 base。
解法：部署在域名根路径时无需处理；部署在子路径时 vite.config.ts 配置 base: '/admin/'，或 Nginx 做路径映射。

坑 6：ESLint 8 老配置直接搬到 ESLint 9 报错
结论：eslint 启动即报 .eslintrc.js 已废弃、config 解析失败。
原因：ESLint 9 全面切换 flat config，不再读取 .eslintrc 系列文件。
解法：改写为 eslint.config.js（flat config 写法，见上文），旧项目可暂用 ESLint 8 或升级迁移工具。

坑 7：团队一半人用 npm 一半人用 pnpm，lock 文件互相覆盖
结论：每次有人提交都产生 package-lock.json 与 pnpm-lock.yaml 的冲突，依赖版本漂移。
原因：两个包管理器各自维护 lock 文件，安装结果不一致。
解法：全组统一包管理器，删除另一种 lock 文件；或约定 npm 作为唯一标准并在 README 注明。

坑 8：npm run dev 报端口 5173 被占用
结论：启动报 Port 5173 is already in use，服务起不来。
原因：上一个 dev server 未退出，或其它进程占用端口。
解法：vite.config.ts 设置 strictPort: false（自动换端口）或手动指定 port；排查占用进程后结束它。
```

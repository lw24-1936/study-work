## 概述

Element Plus 是 Vue3 生态最主流的桌面端组件库，基于 TypeScript 开发，提供表单、表格、弹窗、菜单、分页等 60+ 组件，覆盖管理后台 90% 以上的界面需求。本章讲解 Element Plus 的安装与引入方式（完整引入 vs 按需引入）、后台标准布局（侧边栏 + 顶栏 + 主内容区）、主题定制（CSS 变量与暗黑模式）、通用组件封装（分页、搜索表单、状态标签）以及图标与样式体系，目标是让读者能独立搭建出结构清晰、风格统一的管理后台界面。

```text
UI 框架与布局要点：
1. 引入方式 —— 完整引入开发快，按需引入产物小，后台项目推荐按需 + 自动导入
2. 布局组件 —— el-container 家族组合出后台三段式骨架（侧边栏/顶栏/主区）
3. 主题定制 —— CSS 变量覆盖主色，useDark 一行切换暗黑模式
4. 通用组件 —— 分页、搜索表单、状态标签抽成公共组件，避免重复代码
5. 图标体系 —— @element-plus/icons-vue 提供 300+ SVG 图标，配合 el-icon 使用
6. 样式规范 —— 全局样式与 scoped 样式分层，变量统一走 CSS 变量
```

## Element Plus 安装与引入

Element Plus 的引入有两条路线：完整引入（app.use(ElementPlus) 注册全部组件）与按需引入（unplugin-vue-components 自动按需注册）。完整引入代码简单、开发体验好，缺点是打包体积大（全部组件 + 样式约几百 KB gzip）；按需引入配合自动导入插件，模板里直接用组件、不写 import，Vite 会按需打包，产物显著减小。管理后台组件使用面广，两种方式都常见：追求首屏性能选按需，追求简单省事选完整引入。

```bash
# 安装 Element Plus
npm install element-plus

# 按需引入需要的两个构建插件
npm install -D unplugin-vue-components unplugin-auto-import
```

完整引入方式（main.ts）：

```ts
// src/main.ts —— 完整引入 Element Plus
import { createApp } from 'vue'
import ElementPlus from 'element-plus'
import zhCn from 'element-plus/es/locale/lang/zh-cn'
import 'element-plus/dist/index.css'
import App from './App.vue'

const app = createApp(App)

// 注册全部组件与插件，locale 指定中文
app.use(ElementPlus, { locale: zhCn })

app.mount('#app')
```

按需引入方式（vite.config.ts 配置自动导入插件）：

```ts
// vite.config.ts —— 按需引入 + 自动导入
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import AutoImport from 'unplugin-auto-import/vite'
import Components from 'unplugin-vue-components/vite'
import { ElementPlusResolver } from 'unplugin-vue-components/resolvers'

export default defineConfig({
  plugins: [
    vue(),
    // 自动导入 ElMessage、ElMessageBox 等 API 风格组件
    AutoImport({
      resolvers: [ElementPlusResolver()]
    }),
    // 模板中使用的组件自动按需注册
    Components({
      resolvers: [ElementPlusResolver()]
    })
  ]
})
```

按需引入后，模板里直接用组件，无需手动 import：

```vue
<template>
  <!-- 组件自动按需注册，无需 import -->
  <el-button type="primary">新增用户</el-button>
  <el-table :data="rows">
    <el-table-column prop="name" label="姓名" />
  </el-table>
</template>

<script setup lang="ts">
// API 风格组件（消息提示、确认框）由 AutoImport 自动引入
function handleSave() {
  ElMessage.success('保存成功')
}
</script>
```

```text
Element Plus 引入要点：
1. locale —— 不设置中文包，分页、日期选择器等组件默认英文
2. 完整引入 —— app.use(ElementPlus, { locale: zhCn })，CSS 必须同时引入
3. 按需引入 —— 两个 unplugin 插件缺一不可，组件与 API 分别自动导入
4. 样式产物 —— 完整引入打包一次全量样式，按需引入样式跟随组件按需打包
5. 版本匹配 —— element-plus 2.x 对应 Vue3，不要与 element-ui（Vue2）混淆
6. 自动导入的 ElMessage —— 直接使用即可，无需手动 import，类型由插件生成
```

## 布局组件与后台骨架

Element Plus 的布局体系：`el-container` 是外层容器，内部组合 `el-aside`（侧边栏）、`el-header`（顶栏）、`el-main`（主内容区）、`el-footer`（底部）；`el-menu` 提供导航菜单，配合 `router` 属性可直接驱动 vue-router 跳转。后台标准骨架是「左侧菜单 + 顶部栏 + 内容区」，菜单常与路由联动（详见 20.3 菜单生成）。下面是 layout/index.vue 的完整实现：

## 主题定制

Element Plus 基于 SCSS 变量 + CSS 变量两套体系。运行时主题通过 CSS 变量覆盖（如 `--el-color-primary`），无需重新编译，改 `:root` 即可全局生效；深度定制（如换品牌主色、调整圆角）可以通过 SCSS 的 `@forward ... with` 在构建期覆盖主题变量，生成定制版样式。暗黑模式官方提供了 dark css-vars 文件，配合 html 上的 dark class 切换。

构建期 SCSS 覆盖（推荐用于换主色）：

```scss
// src/styles/element/index.scss —— 覆盖 Element Plus 主题变量
@forward 'element-plus/theme-chalk/src/common/var.scss' with (
  $colors: (
    'primary': (
      'base': #2f54eb
    ),
    'success': (
      'base': #52c41a
    ),
    'warning': (
      'base': #faad14
    ),
    'danger': (
      'base': #f5222d
    )
  )
);
```

```ts
// src/main.ts —— 引入定制主题（注意：用 index.scss 而不是 dist/index.css）
import 'element-plus/theme-chalk/src/index.scss'
import './styles/element/index.scss'
```

运行时 CSS 变量覆盖（无需构建，适合主题色可切换需求）：

```css
/* src/styles/index.css —— 全局覆盖 */
:root {
  --el-color-primary: #2f54eb;
  --el-color-primary-light-3: #5b7ff0;
  --el-color-primary-light-5: #93abf5;
  --el-color-primary-light-7: #c2d0fa;
  --el-color-primary-light-8: #d9e2fc;
  --el-color-primary-light-9: #ecf0fe;
  --el-color-primary-dark-2: #2543bc;
  --el-border-radius-base: 4px;
  --el-font-size-base: 14px;
}
```

暗黑模式切换：

```bash
# 暗黑模式依赖 @vueuse/core 的 useDark（也可自己写 class 切换）
npm install @vueuse/core
```

```ts
// src/composables/useTheme.ts —— 暗黑模式切换
import { useDark, useToggle } from '@vueuse/core'

export function useTheme() {
  // useDark 自动给 html 添加/移除 dark class
  const isDark = useDark()
  const toggleDark = useToggle(isDark)
  return { isDark, toggleDark }
}
```

```ts
// src/main.ts —— 引入暗黑模式样式（dark class 生效时覆盖组件配色）
import 'element-plus/theme-chalk/dark/css-vars.css'
```

```text
主题定制要点：
1. 两套体系 —— SCSS 变量构建期覆盖（体积小），CSS 变量运行期覆盖（灵活）
2. 主色覆盖 —— 改 --el-color-primary 一组变量（含 light/dark 衍生色）
3. 暗黑模式 —— html.dark + dark/css-vars.css，组件自动切换配色
4. useDark —— 基于 prefers-color-scheme 初始化，可持久化用户选择
5. 引入顺序 —— 定制 scss 必须在 theme-chalk index.scss 之前 @forward
6. 派生色 —— 只改 base 不改 light-3/5/7/8/9，hover/禁用态颜色会失真
```

## 通用组件封装

后台项目里分页、搜索表单、状态标签几乎每个列表页都会用到，抽成通用组件能大幅减少重复代码。封装原则：props 驱动、事件上抛、不写死业务数据。下面是三个高频通用组件。

分页组件（封装 el-pagination，外部只需传入 total）：

```vue
<!-- src/components/AppPagination.vue —— 通用分页组件 -->
<template>
  <div class="pagination-wrapper">
    <el-pagination
      v-model:current-page="currentPage"
      v-model:page-size="pageSize"
      :total="total"
      :page-sizes="[10, 20, 50, 100]"
      layout="total, sizes, prev, pager, next, jumper"
      background
      @size-change="handleSizeChange"
      @current-change="handleCurrentChange"
    />
  </div>
</template>

<script setup lang="ts">
import { ref, watch } from 'vue'

const props = defineProps<{
  total: number
}>()

const emit = defineEmits<{
  (e: 'change', page: number, pageSize: number): void
}>()

const currentPage = ref(1)
const pageSize = ref(10)

// 删除数据后当前页可能超出总页数，自动回退
watch(
  () => props.total,
  () => {
    const maxPage = Math.max(1, Math.ceil(props.total / pageSize.value))
    if (currentPage.value > maxPage) {
      currentPage.value = maxPage
    }
  }
)

function handleSizeChange(size: number) {
  currentPage.value = 1 // 切换每页条数回到第一页
  emit('change', currentPage.value, size)
}

function handleCurrentChange(page: number) {
  emit('change', page, pageSize.value)
}
</script>

<style scoped>
.pagination-wrapper {
  display: flex;
  justify-content: flex-end;
  margin-top: 16px;
}
</style>
```

状态标签组件（把业务状态映射为彩色标签）：

```vue
<!-- src/components/StatusTag.vue —— 通用状态标签 -->
<template>
  <el-tag :type="tagType" :effect="effect">{{ label }}</el-tag>
</template>

<script setup lang="ts">
import { computed } from 'vue'

// 状态映射表由使用方传入，组件本身不关心业务
const props = defineProps<{
  status: number | string
  map: Record<
    number | string,
    { label: string; type: 'success' | 'info' | 'warning' | 'danger' | 'primary' }
  >
  effect?: 'light' | 'dark' | 'plain'
}>()

const tagType = computed(() => props.map[props.status]?.type ?? 'info')
const label = computed(() => props.map[props.status]?.label ?? String(props.status))
</script>
```

搜索表单组件（收起/展开 + 重置 + 查询）：

```vue
<!-- src/components/SearchForm.vue —— 通用搜索表单（简化版） -->
<template>
  <el-form :inline="true" :model="model" class="search-form">
    <slot />
    <el-form-item>
      <el-button type="primary" :icon="Search" @click="handleSearch">查询</el-button>
      <el-button :icon="Refresh" @click="handleReset">重置</el-button>
    </el-form-item>
  </el-form>
</template>

<script setup lang="ts">
import { Search, Refresh } from '@element-plus/icons-vue'

const props = defineProps<{
  model: Record<string, unknown>
}>()

const emit = defineEmits<{
  (e: 'search'): void
  (e: 'reset'): void
}>()

function handleSearch() {
  emit('search')
}

function handleReset() {
  // 由父组件定义重置逻辑（清空字段并重新查询）
  emit('reset')
}
</script>
```

```text
通用组件封装要点：
1. 数据驱动 —— 组件只认 props，业务数据由使用方传入（如状态映射表）
2. 事件上抛 —— 交互结果通过 emit 通知父组件，不在子组件里写业务
3. 分页回退 —— 删数据后自动纠正页码，避免空页
4. 类型完整 —— defineProps/defineEmits 用 TS 泛型声明，编辑器有提示
5. 插槽扩展 —— 搜索表单用 slot 承载表单项，组件保持通用
6. 命名规范 —— AppPagination、StatusTag 这类语义化命名，一目了然
```

## 图标与样式体系

Element Plus 的图标独立成包 `@element-plus/icons-vue`，提供 300+ 个 SVG 图标，用法是 `<el-icon><组件名 /></el-icon>` 包裹，图标尺寸与颜色继承 el-icon 的 size/color 属性。后台项目常用图标：菜单图标（DataBoard、Setting、List）、操作图标（Plus、Edit、Delete、Search、Refresh）、反馈图标（Warning、SuccessFilled）。两种注册方式：按需 import 或 main.ts 全量注册（后台图标数量有限，全量注册省心）。

按需引入：

```vue
<template>
  <el-button :icon="Plus" type="primary">新增用户</el-button>
  <el-icon :size="20" color="#409eff">
    <Search />
  </el-icon>
</template>

<script setup lang="ts">
import { Plus, Search } from '@element-plus/icons-vue'
</script>
```

全量注册（main.ts）：

```ts
// src/main.ts —— 全量注册图标为全局组件
import * as ElementPlusIconsVue from '@element-plus/icons-vue'

for (const [key, component] of Object.entries(ElementPlusIconsVue)) {
  app.component(key, component)
}
```

```vue
<!-- 全量注册后模板直接使用，无需 import -->
<template>
  <el-icon><DataBoard /></el-icon>
</template>
```

样式体系：全局样式（reset、全局变量）放 src/styles，组件内样式用 scoped 隔离；需要穿透子组件（如弹窗、表格内部）时用 `:deep()`。背景色、文字色、边框统一用 Element Plus 暴露的 CSS 变量，保证暗黑模式自动适配。

```text
图标与样式要点：
1. el-icon 包裹 —— 图标组件必须放在 el-icon 内，尺寸/颜色由 el-icon 控制
2. 全量 vs 按需 —— 后台全量注册简单，纯按需能再省一点体积
3. 变量化样式 —— 颜色一律用 --el-* 变量，暗黑模式零改动适配
4. scoped 隔离 —— 组件样式默认 scoped，穿透内部用 :deep()
5. 公共类 —— page-container / table-toolbar 抽成全局类，页面复用
6. 图标语义 —— 删除用 Delete、新增用 Plus、搜索用 Search，风格统一
```

## 最佳实践与踩坑记录

### 最佳实践

1. 后台项目优先按需引入 + 自动导入，产物体积小且开发体验与完整引入几乎一致
2. main.ts 中统一注册 Element Plus 与图标，locale 固定中文，团队不再各自处理
3. 布局组件与页面组件分离：layout 只负责骨架，页面组件只负责业务，职责单一
4. 高频 UI 片段（分页、状态标签、搜索表单）优先抽通用组件，出现第三次重复就抽象
5. 颜色、圆角、间距统一走 CSS 变量（--el-*），业务色值集中定义在 styles 目录
6. 暗黑模式在项目初期就接入，后期补适配要逐个页面排查，成本极高
7. el-table 操作列固定右侧（fixed="right"），数据列给 min-width 防止挤压
8. 组件封装用 defineProps/defineEmits 的 TS 泛型写法，类型即文档

### 踩坑记录

```text
坑 1：完整引入后样式完全错乱或组件无样式
结论：组件渲染出来了但没有样式，或样式被全局 reset 打乱。
原因：只引入了 JS（app.use(ElementPlus)），漏掉 import 'element-plus/dist/index.css'；或全局样式覆盖了组件样式。
解法：main.ts 中按顺序引入 CSS；全局 reset 放在组件库样式之后；必要时排查 * 选择器是否误伤。

坑 2：按需引入后 ElMessage 弹出无样式或报错
结论：ElMessage.success 能弹出但无样式，或直接报 ElMessage is not defined。
原因：AutoImport 插件未配置 ElementPlusResolver；或 message 样式需要额外引入（新版已内置，旧版需单独处理）。
解法：vite.config.ts 的 AutoImport 中配置 resolvers: [ElementPlusResolver()]；确认插件版本与 element-plus 2.x 匹配。

坑 3：分页组件显示英文
结论：el-pagination 显示 Total 50 items 等英文文案。
原因：未设置中文 locale，组件默认 en 语言包。
解法：完整引入时 app.use(ElementPlus, { locale: zhCn })；按需引入时在 App.vue 外层包裹 el-config-provider :locale="zhCn"。

坑 4：el-menu 点击不跳转或高亮不跟随
结论：点击菜单地址不变，或路由变了菜单不高亮。
原因：el-menu 没开 router 属性（index 只是标识不是路径）；default-active 绑定的是固定字符串而非当前路由。
解法：el-menu 加 router 属性，index 写路由路径；default-active 绑定 computed 的 route.path。

坑 5：SCSS 覆盖主题色不生效
结论：按文档覆盖 $colors 后主色没变。
原因：@forward with 必须发生在组件库样式引入之前，顺序反了会被默认变量覆盖；或项目没装 sass。
解法：安装 sass（npm i -D sass）；自定义 scss 先 @forward 再引入 theme-chalk 的 index.scss，顺序不可颠倒。

坑 6：暗黑模式只切了背景，组件还是亮色
结论：html 加了 dark class，但表格、弹窗仍是白色。
原因：只用了 useDark 切 class，没有引入 element-plus/theme-chalk/dark/css-vars.css。
解法：main.ts 引入 dark/css-vars.css；确认 dark class 挂在 html 上而不是 body（useDark 默认挂 html）。

坑 7：scoped 样式改不动 el-dialog / el-table 内部
结论：在页面里写 .el-dialog__title 样式不生效。
原因：scoped 会给选择器加 data 属性，而弹窗/表格内部 DOM 不带该属性，选择器匹配不到。
解法：用 :deep(.el-dialog__title) 穿透；或把弹窗内容抽成独立组件再写 scoped 样式。

坑 8：el-container 布局高度塌陷，侧边栏只显示一行
结论：侧边栏菜单没有撑满整屏，页面高度异常。
原因：el-container 默认高度由内容决定，没有给外层容器 100vh。
解法：外层 .app-wrapper 设 height: 100vh；同时 html/body/#app 设 height: 100%。

坑 9：表格列挤压，操作按钮换行
结论：列多了之后表格错乱，操作列按钮挤成两行。
原因：列宽只给了部分 prop 列，操作列未固定且无 min-width。
解法：数据列用 min-width 自适应，操作列 width 固定并用 fixed="right" 吸底。
```

## 概述

Spring Security 是 Spring 生态的事实标准安全框架，提供认证（Authentication，你是谁）、授权（Authorization，你能干什么）、防护（CSRF、Session 固定、点击劫持等）一整套能力。小程序项目引入 Spring Security 后，配合 18.1 的 JWT，可以构建标准的「无状态 JWT 认证 + 细粒度 RBAC 授权」体系，替代手写拦截器，把安全逻辑交给框架管理。

Spring Security 的核心执行模型是过滤器链（Filter Chain）：请求进入后依次经过多个过滤器，完成 CSRF 检查、认证信息装配、匿名用户处理、授权决策等步骤。开发者要做的主要事情是：声明 SecurityFilterChain 配置、实现 UserDetailsService 与 PasswordEncoder、自定义 JWT 过滤器插入链中、用 authorizeHttpRequests 与 @PreAuthorize 声明授权规则。

```text
Spring Security 集成要点：
1. 认证与授权分离 —— AuthenticationManager 管认证，授权规则声明式配置
2. 过滤器链模型 —— 请求依次过过滤器，JWT 过滤器插入 UsernamePasswordAuthenticationFilter 之前
3. 声明式安全 —— authorizeHttpRequests 配置 URL 级规则，@PreAuthorize 配置方法级规则
4. 密码安全 —— BCryptPasswordEncoder 加盐哈希，禁止明文存储
5. 无状态集成 —— 关闭 Session 与 CSRF，适配 JWT 认证模式
6. 与 18.1 JWT 无缝衔接 —— 自定义过滤器验签后写入 SecurityContext，业务无感知
```

## Security 配置

引入依赖后，Spring Security 会提供一套默认安全配置：所有请求都要认证、默认生成登录页、默认用户名为 user 且密码随机打印在启动日志。这套默认行为不适合 API 项目，必须显式声明配置类接管。

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-security</artifactId>
</dependency>
```

配置类核心是暴露一个 SecurityFilterChain Bean。注意 WebSecurityConfigurerAdapter 在 Spring Security 5.7 起已被标记废弃，6.x 彻底移除，官方推荐组件化写法：在 @Configuration 类中定义 SecurityFilterChain、PasswordEncoder、AuthenticationManager 等 Bean，并在 @EnableWebSecurity 注解下生效。

```java
package com.example.security.config;

import com.example.security.filter.JwtAuthenticationFilter;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.http.HttpMethod;
import org.springframework.security.authentication.AuthenticationManager;
import org.springframework.security.config.annotation.authentication.configuration.AuthenticationConfiguration;
import org.springframework.security.config.annotation.method.configuration.EnableMethodSecurity;
import org.springframework.security.config.annotation.web.builders.HttpSecurity;
import org.springframework.security.config.annotation.web.configuration.EnableWebSecurity;
import org.springframework.security.config.http.SessionCreationPolicy;
import org.springframework.security.crypto.bcrypt.BCryptPasswordEncoder;
import org.springframework.security.crypto.password.PasswordEncoder;
import org.springframework.security.web.SecurityFilterChain;
import org.springframework.security.web.authentication.UsernamePasswordAuthenticationFilter;

@Configuration
@EnableWebSecurity
@EnableMethodSecurity
public class SecurityConfig {

    private final JwtAuthenticationFilter jwtAuthenticationFilter;

    public SecurityConfig(JwtAuthenticationFilter jwtAuthenticationFilter) {
        this.jwtAuthenticationFilter = jwtAuthenticationFilter;
    }

    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        http
            // 无状态 API：关闭 CSRF 与 Session
            .csrf(csrf -> csrf.disable())
            .sessionManagement(sm -> sm.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
            // URL 级授权规则
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/api/auth/login", "/api/auth/refresh").permitAll()
                .requestMatchers("/api/public/**").permitAll()
                .requestMatchers(HttpMethod.GET, "/api/goods/**").permitAll()
                .requestMatchers("/api/admin/**").hasRole("ADMIN")
                .anyRequest().authenticated()
            )
            // 自定义 JWT 过滤器插在用户名密码过滤器之前
            .addFilterBefore(jwtAuthenticationFilter, UsernamePasswordAuthenticationFilter.class);
        return http.build();
    }

    @Bean
    public PasswordEncoder passwordEncoder() {
        return new BCryptPasswordEncoder();
    }

    @Bean
    public AuthenticationManager authenticationManager(AuthenticationConfiguration configuration) throws Exception {
        return configuration.getAuthenticationManager();
    }
}
```

配置的语义：permitAll 的路径完全放行（登录、刷新、公开接口）；hasRole("ADMIN") 要求认证用户必须拥有 ROLE_ADMIN 权限（hasRole 自动补 ROLE_ 前缀）；anyRequest().authenticated() 兜底要求所有未显式放行的请求都必须认证。规则从上到下匹配，先匹配先生效。

```text
Security 配置要点：
1. WebSecurityConfigurerAdapter 已废弃，改用 SecurityFilterChain Bean + 组件化配置
2. 无状态 API 必须关闭 CSRF 与 Session，否则 JWT 认证会被默认表单登录干扰
3. authorizeHttpRequests 替代旧的 antMatchers/authorizeRequests，路径匹配用 requestMatchers
4. hasRole 自动加 ROLE_ 前缀，hasAuthority 精确匹配权限字符串，两者不要混用
5. 规则按声明顺序匹配，具体路径放前面、anyRequest 兜底放最后
6. 配置类必须加 @EnableWebSecurity（以及 @EnableMethodSecurity 启用方法级安全）
```

## 过滤器链

Spring Security 把安全逻辑实现为一条过滤器链：请求进入后按顺序经过 SecurityContextPersistenceFilter、CsrfFilter、UsernamePasswordAuthenticationFilter、FilterSecurityInterceptor 等过滤器，最终到达业务 Controller。每个过滤器只负责一件事，认证信息通过 SecurityContextHolder 在线程内传递。

对于 JWT 认证，标准做法是自定义一个过滤器继承 OncePerRequestFilter，从 Authorization 头解析 token、验签、构造 Authentication 并写入 SecurityContextHolder。OncePerRequestFilter 保证同一请求即使被转发多次也只执行一次过滤逻辑：

```java
package com.example.security.filter;

import com.example.security.jwt.JwtUtil;
import io.jsonwebtoken.Claims;
import org.springframework.security.authentication.UsernamePasswordAuthenticationToken;
import org.springframework.security.core.GrantedAuthority;
import org.springframework.security.core.authority.SimpleGrantedAuthority;
import org.springframework.security.core.context.SecurityContextHolder;
import org.springframework.security.web.authentication.WebAuthenticationDetailsSource;
import org.springframework.stereotype.Component;
import org.springframework.web.filter.OncePerRequestFilter;

import javax.servlet.FilterChain;
import javax.servlet.ServletException;
import javax.servlet.http.HttpServletRequest;
import javax.servlet.http.HttpServletResponse;
import java.io.IOException;
import java.util.List;

@Component
public class JwtAuthenticationFilter extends OncePerRequestFilter {

    private final JwtUtil jwtUtil;

    public JwtAuthenticationFilter(JwtUtil jwtUtil) {
        this.jwtUtil = jwtUtil;
    }

    @Override
    protected void doFilterInternal(HttpServletRequest request, HttpServletResponse response,
                                    FilterChain filterChain) throws ServletException, IOException {
        String auth = request.getHeader("Authorization");
        if (auth != null && auth.startsWith("Bearer ")) {
            try {
                Claims claims = jwtUtil.parseToken(auth.substring(7));
                Long userId = claims.get("uid", Long.class);
                String role = claims.get("role", String.class);

                // 把 token 中的角色转成 GrantedAuthority，hasRole/hasAuthority 依赖它
                List<GrantedAuthority> authorities =
                        List.of(new SimpleGrantedAuthority("ROLE_" + role));

                UsernamePasswordAuthenticationToken authentication =
                        new UsernamePasswordAuthenticationToken(userId, null, authorities);
                authentication.setDetails(
                        new WebAuthenticationDetailsSource().buildDetails(request));
                // 写入 SecurityContext，后续授权过滤器与业务代码通过它取当前用户
                SecurityContextHolder.getContext().setAuthentication(authentication);
            } catch (Exception e) {
                // token 无效：清空上下文，不设置认证，授权规则会拒绝访问
                SecurityContextHolder.clearContext();
            }
        }
        filterChain.doFilter(request, response);
    }
}
```

过滤器通过 addFilterBefore 插入到 UsernamePasswordAuthenticationFilter 之前，因为 JWT 是自带凭证的无状态认证，不需要走表单登录过滤器。插入位置决定执行顺序：JWT 过滤器先执行，若验签通过则后续过滤器直接放行，若失败则进入授权过滤器时因无认证信息而返回 401/403。

```text
过滤器链要点：
1. Spring Security 是过滤器链架构，认证过滤器负责装身份，授权过滤器负责判权限
2. 自定义 JWT 过滤器必须继承 OncePerRequestFilter，避免转发时重复执行
3. 验签通过后构造 UsernamePasswordAuthenticationToken 写入 SecurityContextHolder
4. 角色/权限要转成 GrantedAuthority 列表，权限判断才有依据
5. addFilterBefore 把 JWT 过滤器插在 UsernamePasswordAuthenticationFilter 之前
6. 验签失败不要抛异常打断链路，清空上下文交给授权过滤器统一拒绝即可
```

## 认证流程

Spring Security 的认证流程围绕 AuthenticationManager 展开：认证入口（如登录接口）调用 authenticationManager.authenticate(token)，AuthenticationManager 把请求分发给对应的 AuthenticationProvider，Provider 调用 UserDetailsService 加载用户、用 PasswordEncoder 比对密码，成功则返回已认证的 Authentication 对象。

默认的 ProviderManager 内部维护多个 AuthenticationProvider，按支持的 token 类型分发：DaoAuthenticationProvider 处理 UsernamePasswordAuthenticationToken，它依赖 UserDetailsService 与 PasswordEncoder 两个组件。用户信息的来源自定义为数据库，实现 UserDetailsService 接口即可：

```java
package com.example.security.service;

import com.example.mapper.SysUserMapper;
import com.example.entity.SysUser;
import org.springframework.security.core.userdetails.User;
import org.springframework.security.core.userdetails.UserDetails;
import org.springframework.security.core.userdetails.UserDetailsService;
import org.springframework.security.core.userdetails.UsernameNotFoundException;
import org.springframework.stereotype.Service;

@Service
public class UserDetailsServiceImpl implements UserDetailsService {

    private final SysUserMapper userMapper;

    public UserDetailsServiceImpl(SysUserMapper userMapper) {
        this.userMapper = userMapper;
    }

    @Override
    public UserDetails loadUserByUsername(String username) throws UsernameNotFoundException {
        SysUser user = userMapper.findByUsername(username);
        if (user == null) {
            // 用户名不存在必须抛 UsernameNotFoundException，Provider 会转成认证失败
            throw new UsernameNotFoundException("用户不存在: " + username);
        }
        return User.withUsername(user.getUsername())
                .password(user.getPassword())   // 必须是 BCrypt 哈希，不能是明文
                .roles(user.getRoleCode())      // roles() 自动补 ROLE_ 前缀
                .disabled(user.getStatus() == 0) // 状态为 0 的账号禁止登录
                .build();
    }
}
```

密码加密使用 BCryptPasswordEncoder：BCrypt 是自带盐的慢哈希算法，每次加密同一密码产生的哈希串都不同（盐随机），且计算成本可调，能有效抵御彩虹表与暴力破解。注册时用 encoder.encode(plainPassword) 存库，认证时框架自动调用 encoder.matches(rawPassword, hash) 比对：

```java
@Service
public class AuthService {

    private final AuthenticationManager authenticationManager;
    private final PasswordEncoder passwordEncoder;
    private final SysUserMapper userMapper;
    private final JwtUtil jwtUtil;

    // 构造器注入省略

    /** 登录：认证通过后签发 JWT */
    public Map<String, Object> login(String username, String password) {
        Authentication authentication = authenticationManager.authenticate(
                new UsernamePasswordAuthenticationToken(username, password));
        // 认证通过：从 principal 拿用户信息，签发双 token
        UserDetails principal = (UserDetails) authentication.getPrincipal();
        SysUser user = userMapper.findByUsername(principal.getUsername());
        Map<String, Object> data = new HashMap<>();
        data.put("accessToken", jwtUtil.createAccessToken(user.getId(), user.getUsername(), user.getRoleCode()));
        return data;
    }

    /** 注册：密码 BCrypt 加密后入库 */
    public void register(String username, String rawPassword, String roleCode) {
        SysUser user = new SysUser();
        user.setUsername(username);
        user.setPassword(passwordEncoder.encode(rawPassword));
        user.setRoleCode(roleCode);
        userMapper.insert(user);
    }
}
```

```text
认证流程要点：
1. AuthenticationManager（默认 ProviderManager）是认证入口，分发到 Provider 执行
2. DaoAuthenticationProvider 依赖 UserDetailsService（加载用户）与 PasswordEncoder（比对密码）
3. 用户不存在必须抛 UsernameNotFoundException，否则无法区分「用户不存在」与「密码错误」
4. BCryptPasswordEncoder 自带随机盐，相同密码两次加密结果不同，不可逆不可反查
5. 存库用 encode()，认证比对由框架调用 matches()，业务代码禁止自己比对密码
6. 认证成功后 principal 保存用户信息，业务代码通过 SecurityContextHolder 获取
```

## 授权

授权解决「认证通过后能访问什么」的问题。Spring Security 提供两层授权：URL 级（过滤器层，在 SecurityFilterChain 中用 authorizeHttpRequests 声明）与方法级（AOP 层，用 @PreAuthorize 等注解声明）。两层可以叠加：URL 规则做粗粒度拦截，方法注解做细粒度控制。

URL 级授权常用表达式：

```java
.authorizeHttpRequests(auth -> auth
    // permitAll：完全放行，无需认证
    .requestMatchers("/api/auth/**", "/api/public/**").permitAll()
    // hasRole：拥有指定角色（自动补 ROLE_ 前缀，即要求 ROLE_ADMIN）
    .requestMatchers("/api/admin/**").hasRole("ADMIN")
    // hasAnyRole：拥有任一角色即可
    .requestMatchers("/api/operator/**").hasAnyRole("ADMIN", "OPERATOR")
    // hasAuthority：精确匹配权限字符串（不补前缀）
    .requestMatchers("/api/order/delete").hasAuthority("order:delete")
    // 按 HTTP 方法区分
    .requestMatchers(HttpMethod.POST, "/api/order/**").hasRole("ADMIN")
    // 兜底：必须认证
    .anyRequest().authenticated()
)
```

角色与权限的区别：角色（ROLE_ADMIN）是粗粒度的身份分组，权限（order:delete）是细粒度的操作许可。hasRole 判断时自动补 ROLE_ 前缀，要求 SecurityContext 中的 GrantedAuthority 是 ROLE_ADMIN；hasAuthority 则精确匹配原样字符串。实践中推荐「URL 用角色、方法用权限」的组合：URL 层用 hasRole 挡掉明显越权的模块，方法层用 hasAuthority 精确到按钮级操作。

Spring Security 6 的另一个变化是 antMatchers 废弃、mvcMatchers 废弃，统一改用 requestMatchers，路径匹配规则基于 AntPathMatcher 或 PathPatternParser（默认）。升级项目时把所有 antMatchers 批量替换为 requestMatchers 即可。

```text
授权要点：
1. 授权分 URL 级与方法级两层，URL 粗粒度、方法细粒度，可叠加使用
2. hasRole 自动补 ROLE_ 前缀，hasAuthority 精确匹配，两者不可混用
3. antMatchers/mvcMatchers 已废弃，统一使用 requestMatchers
4. permitAll 与 authenticated 是两种兜底策略，公开接口放行、其余必须认证
5. 角色分组面向粗粒度模块，权限字符串面向细粒度操作（如 order:delete）
6. 授权规则按声明顺序匹配，anyRequest 必须放最后
```

## 方法级安全

URL 级授权只能按路径控制，无法表达「只能操作自己的订单」「只有创建者能删除」这类需要结合业务数据的规则。方法级安全通过 AOP 在方法调用前执行 SpEL 表达式，支持访问方法参数与 Spring Bean，表达能力更强。

启用方法级安全只需在配置类加 @EnableMethodSecurity（Spring Security 6 中替代了旧的 @EnableGlobalMethodSecurity），然后就可以在方法上使用注解：

```java
package com.example.controller;

import org.springframework.security.access.prepost.PreAuthorize;
import org.springframework.security.access.annotation.Secured;
import org.springframework.security.core.Authentication;
import org.springframework.web.bind.annotation.*;

import java.util.Map;

@RestController
@RequestMapping("/api/order")
public class OrderController {

    /** 角色控制：只有管理员能删除订单 */
    @DeleteMapping("/{id}")
    @Secured("ROLE_ADMIN")
    public void deleteOrder(@PathVariable Long id) {
        // 删除逻辑
    }

    /** 权限控制：拥有 order:export 权限才能导出 */
    @GetMapping("/export")
    @PreAuthorize("hasAuthority('order:export')")
    public void exportOrders() {
        // 导出逻辑
    }

    /** 数据归属控制：普通用户只能操作自己的订单 */
    @GetMapping("/{id}")
    @PreAuthorize("hasRole('ADMIN') or @orderService.isOwner(#id, authentication.principal)")
    public Map<String, Object> getOrder(@PathVariable Long id) {
        // 查询逻辑
        return Map.of("orderId", id);
    }

    /** 结合方法参数：按 userId 判断 */
    @PutMapping("/{id}/status")
    @PreAuthorize("@orderService.canUpdate(#id, #status, authentication.principal)")
    public void updateStatus(@PathVariable Long id, @RequestParam String status) {
        // 状态更新逻辑
    }
}
```

@PreAuthorize 与 @Secured 的区别：@PreAuthorize 支持完整的 SpEL 表达式（hasAuthority、hasRole、@bean 调用、参数引用），是首选；@Secured 只支持角色名数组，能力有限，属于旧式写法。注解中的 #id 引用方法参数，authentication 引用当前认证对象，@orderService 引用 Spring Bean，这三者是方法级安全最常用的 SpEL 变量。

配合 Bean 方法做复杂判断：

```java
package com.example.service;

import org.springframework.stereotype.Service;

@Service("orderService")
public class OrderService {

    /** 判断订单是否属于当前用户，供 @PreAuthorize 调用 */
    public boolean isOwner(Long orderId, Object principal) {
        Long currentUserId = (Long) principal; // JWT 过滤器写入的 principal 是 userId
        // 查订单归属
        return orderMapper.findOwnerId(orderId).equals(currentUserId);
    }

    /** 判断能否更新订单状态 */
    public boolean canUpdate(Long orderId, String status, Object principal) {
        if ("CANCEL".equals(status)) {
            return isOwner(orderId, principal);
        }
        return principal != null;
    }
}
```

```text
方法级安全要点：
1. @EnableMethodSecurity 启用方法级安全，替代废弃的 @EnableGlobalMethodSecurity
2. @PreAuthorize 支持 SpEL，是首选；@Secured 只支持角色数组，属于旧式写法
3. SpEL 中 #参数名 引用方法参数，authentication 引用认证对象，@bean 调用 Spring Bean
4. 方法级安全适合数据归属、状态流转等 URL 规则表达不了的细粒度控制
5. 表达式结果为 false 时抛 AccessDeniedException，统一异常处理返回 403
6. URL 级与方法级规则都要配置，方法注解不是 URL 规则的替代品
```

## 应用场景实战

### 场景一：JWT + Spring Security 完整登录认证

把 18.1 的 JwtUtil、本篇章的 SecurityConfig、UserDetailsServiceImpl、JwtAuthenticationFilter 组合起来，就得到一个完整的无状态认证体系。登录接口使用 AuthenticationManager 完成标准认证流程，认证通过后签发 JWT：

```java
package com.example.controller;

import com.example.security.jwt.JwtUtil;
import com.example.entity.SysUser;
import com.example.mapper.SysUserMapper;
import org.springframework.security.authentication.AuthenticationManager;
import org.springframework.security.authentication.UsernamePasswordAuthenticationToken;
import org.springframework.security.core.Authentication;
import org.springframework.security.core.context.SecurityContextHolder;
import org.springframework.web.bind.annotation.*;

import java.util.HashMap;
import java.util.Map;

@RestController
@RequestMapping("/api/auth")
public class LoginController {

    private final AuthenticationManager authenticationManager;
    private final SysUserMapper userMapper;
    private final JwtUtil jwtUtil;

    public LoginController(AuthenticationManager authenticationManager,
                           SysUserMapper userMapper, JwtUtil jwtUtil) {
        this.authenticationManager = authenticationManager;
        this.userMapper = userMapper;
        this.jwtUtil = jwtUtil;
    }

    @PostMapping("/login")
    public Map<String, Object> login(@RequestBody Map<String, String> body) {
        String username = body.get("username");
        String password = body.get("password");

        // 1. 标准认证：ProviderManager -> DaoAuthenticationProvider -> UserDetailsService -> BCrypt 比对
        Authentication authentication = authenticationManager.authenticate(
                new UsernamePasswordAuthenticationToken(username, password));
        // 2. 认证通过后写入 SecurityContext（本次请求内可访问）
        SecurityContextHolder.getContext().setAuthentication(authentication);

        // 3. 签发 JWT
        SysUser user = userMapper.findByUsername(username);
        String accessToken = jwtUtil.createAccessToken(user.getId(), user.getUsername(), user.getRoleCode());
        String refreshToken = jwtUtil.createRefreshToken(user.getId());

        Map<String, Object> data = new HashMap<>();
        data.put("accessToken", accessToken);
        data.put("refreshToken", refreshToken);
        return data;
    }

    /** 获取当前登录用户：业务代码统一从 SecurityContext 取 */
    @GetMapping("/me")
    public Map<String, Object> me() {
        Authentication authentication = SecurityContextHolder.getContext().getAuthentication();
        Long userId = (Long) authentication.getPrincipal(); // JWT 过滤器写入的是 userId
        SysUser user = userMapper.findById(userId);
        Map<String, Object> data = new HashMap<>();
        data.put("userId", user.getId());
        data.put("username", user.getUsername());
        data.put("role", user.getRoleCode());
        return data;
    }
}
```

部署后的请求链路：POST /api/auth/login（permitAll）→ AuthenticationManager 认证 → 签发 token；GET /api/user/profile（需认证）→ JwtAuthenticationFilter 验签 → 写入 SecurityContext → authorizeHttpRequests 检查已认证 → Controller 从 SecurityContext 取用户。

### 场景二：URL 级 + 方法级授权组合控制

管理后台常见的权限组合：模块级用 URL 规则拦截，按钮级用方法注解控制。例如订单管理模块，查询接口管理员与运营都能看，删除接口仅管理员，导出接口要求 order:export 权限：

```java
package com.example.controller;

import org.springframework.security.access.prepost.PreAuthorize;
import org.springframework.security.access.annotation.Secured;
import org.springframework.web.bind.annotation.*;

import java.util.ArrayList;
import java.util.List;
import java.util.Map;

@RestController
@RequestMapping("/api/order")
public class OrderAdminController {

    /** 查询：URL 层已放行给 ADMIN/OPERATOR，方法层不再重复限制 */
    @GetMapping("/list")
    public List<Map<String, Object>> list(@RequestParam(required = false) Integer page) {
        return new ArrayList<>(); // 查询逻辑省略
    }

    /** 删除：仅管理员，@Secured 写角色名（带 ROLE_ 前缀） */
    @DeleteMapping("/{id}")
    @Secured("ROLE_ADMIN")
    public void delete(@PathVariable Long id) {
        // 删除逻辑省略
    }

    /** 导出：细粒度权限字符串，由 18.4 的权限模型分配 */
    @GetMapping("/export")
    @PreAuthorize("hasAuthority('order:export')")
    public void export() {
        // 导出逻辑省略
    }

    /** 退款：管理员或运营，且必须是本人操作时用数据归属判断 */
    @PostMapping("/{id}/refund")
    @PreAuthorize("hasAnyRole('ADMIN', 'OPERATOR') and @orderService.isOwner(#id, authentication.principal)")
    public void refund(@PathVariable Long id) {
        // 退款逻辑省略
    }
}
```

组合规则的设计原则：URL 层管「模块能不能进」，方法层管「操作能不能做」，数据层管「数据能不能碰」。三层各司其职，避免把复杂规则堆在某一层，导致配置难以维护。

## 最佳实践与踩坑记录

### 最佳实践

1. 一律使用组件化配置（SecurityFilterChain Bean），不要再用 WebSecurityConfigurerAdapter，Spring Security 6 已彻底移除该类
2. 无状态 API 项目必须关闭 CSRF 与 Session：JWT 认证下 CSRF 无意义，Session 会引入不必要的状态
3. 角色与权限分开管理：URL 层用 hasRole 控制模块，方法层用 hasAuthority 控制操作，权限字符串按 模块:操作 命名（如 order:delete）
4. 密码一律 BCrypt 加密存储，禁止明文、MD5、SHA1 等可逆或快速哈希；BCrypt 成本因子默认 10，重要系统可调高
5. 自定义 JWT 过滤器只做「验签 + 装配身份」，不抛异常不写响应，拒绝逻辑统一交给授权过滤器，保持过滤器职责单一
6. 认证失败与授权失败区分处理：401 表示未认证（没 token 或 token 失效），403 表示无权限（有身份但没资格），统一异常处理中分别映射
7. 方法级安全表达式保持简单，复杂归属判断抽到 Service Bean 方法里，@PreAuthorize 只写薄薄一层调用
8. 用户状态（禁用/删除）要在 UserDetailsService 中体现（isEnabled 等），保证禁用账号无法登录，而不是只在业务层拦截

### 踩坑记录

```text
坑 1：依赖 spring-boot-starter-security 后所有接口都 401，且出现默认登录页
结论：引入依赖后请求全部被拦截，浏览器访问出现登录表单，接口调用返回 401。
原因：Spring Security 默认配置要求所有请求认证，并启用表单登录与 Session。
解法：编写 SecurityConfig 暴露 SecurityFilterChain Bean，显式配置 permitAll 与认证规则。

坑 2：用 WebSecurityConfigurerAdapter 写配置，Spring Boot 3 启动直接报错
结论：启动报 ClassNotFoundError 或提示该类已移除，项目无法运行。
原因：Spring Security 6 移除了 WebSecurityConfigurerAdapter，5.7 起已废弃。
解法：改为组件化配置：定义 SecurityFilterChain Bean，@EnableWebSecurity 声明在配置类上。

坑 3：antMatchers 报错或警告，升级后路径匹配全部失效
结论：antMatchers/mvcMatchers 在 Spring Security 6 中已移除，编译报错或运行时规则不生效。
原因：6.0 起统一为 requestMatchers API。
解法：全部替换为 requestMatchers("/api/**")，方法级区分用 requestMatchers(HttpMethod.GET, "/api/**")。

坑 4：JWT 过滤器验签失败抛异常，导致 500 而不是 401
结论：token 无效时接口返回 500，前端无法区分「未登录」与「服务端错误」。
原因：自定义过滤器里抛出的 JwtException 直接冒泡，未被认证入口捕获，进入全局异常处理变成 500。
解法：过滤器内捕获 JWT 异常并 clearContext()，不抛异常；由授权过滤器产生 401/403，或统一异常处理捕获 AuthenticationException。

坑 5：hasRole("ADMIN") 永远不生效，接口一直 403
结论：URL 规则写了 hasRole("ADMIN")，但管理员请求始终 403。
原因：授权判断依赖 SecurityContext 中的 GrantedAuthority，而 JWT 过滤器写入的权限与 ROLE_ 前缀不匹配（如写了 ADMIN 而非 ROLE_ADMIN）。
解法：JWT 过滤器中构造 SimpleGrantedAuthority("ROLE_" + role)，与 hasRole 的前缀约定对齐；或用 hasAuthority 精确匹配。

坑 6：UserDetailsService 用户不存在时不抛异常，认证直接 500
结论：登录不存在的用户名时返回 500，而不是「用户名或密码错误」。
原因：loadUserByUsername 返回 null，DaoAuthenticationProvider 无法处理，内部抛异常。
解法：用户不存在必须抛 UsernameNotFoundException；Provider 会将其转为 BadCredentialsException，配合统一异常处理返回 401。

坑 7：密码用 MD5 存库，认证永远失败
结论：注册时密码 MD5 存库，登录时 BCrypt 比对永远不通过。
原因：PasswordEncoder 统一用 BCrypt 比对，库里的 MD5 哈希无法匹配。
解法：注册时用 passwordEncoder.encode(rawPassword) 存 BCrypt 哈希；存量 MD5 数据做迁移，登录时先 BCrypt 比对，失败再兼容 MD5 并升级。

坑 8：开了 @EnableMethodSecurity 但注解不生效
结论：@PreAuthorize 注解写了但完全没拦截，无权限也能调用。
原因：方法级安全依赖 AOP，注解扫描需要 @EnableMethodSecurity 且配置类被组件扫描覆盖。
解法：确保配置类加 @EnableMethodSecurity；检查方法所在 Bean 是否被 Spring 管理（不能 new 出来）；切面未被拦截时检查代理是否生效。
```

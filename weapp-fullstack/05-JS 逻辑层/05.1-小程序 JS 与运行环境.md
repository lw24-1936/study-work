## 概述

小程序代码运行在微信客户端提供的容器中，分为逻辑层与视图层两个线程：逻辑层（App Service）运行 JavaScript，承载业务逻辑；视图层（WebView 或 Skyline）渲染 WXML/WXSS。两个线程通过 setData 通信，逻辑层无法直接操作 DOM。这种双线程架构是小程序与普通 H5 最本质的区别。

运行环境按端划分：iOS 逻辑层使用 JavaScriptCore 引擎，Android 使用 V8 引擎，开发者工具基于 Chromium（V8）。不同引擎对 ES6+ 语法的支持存在差异，代码要经过开发者工具的 ES6 转 ES5 编译，并注意 Proxy 等特性在 iOS 端不可依赖。JS 侧没有 window/document，也没有 Node 的 fs/path，模块系统采用 CommonJS，耗时计算可以放到 Worker 线程。

```text
运行环境核心认知：
1. 双线程 —— 逻辑层 JS 线程 + 视图层渲染线程，setData 桥接通信
2. 引擎 —— iOS JavaScriptCore、Android V8、开发者工具 Chromium V8
3. 语法 —— ES6+ 经编译转 ES5 下发，真机按引擎能力执行
4. 无 DOM —— 无 window/document，渲染靠 WXML，逻辑靠 wx.* API
5. 模块 —— CommonJS（require/module.exports），Node 内置模块不可用
6. Worker —— wx.createWorker 开独立线程做耗时计算，postMessage 通信
```

## 运行环境与 JS 引擎

小程序不是跑在浏览器里的网页，逻辑层 JavaScript 运行在微信注入的独立 JS 引擎线程中，与界面渲染完全隔离。不同端使用不同引擎：iOS 端逻辑层运行在 JavaScriptCore（JSC，iOS 系统内置引擎）上；Android 端运行在 V8 引擎上（随微信客户端集成，或基于 XWeb/系统 WebView 的 V8）；开发者工具基于 Chromium 内核的 V8；Windows/Mac 桌面端微信也使用 V8 体系。

引擎差异集中在 ES6+ 新特性与个别标准行为上：iOS 的 JavaScriptCore 对 Proxy、部分 Reflect 方法等特性的支持不完整，官方明确提示不要在线上代码依赖 Proxy；V8 对新特性跟进较快，开发者工具里能跑通的语法真机不一定能跑通。因此工程上统一在开发者工具中开启「ES6 转 ES5」（必要时配合增强编译），用基础库版本控制能力边界。

运行环境的信息可以通过 API 读取：`wx.getSystemInfoSync()` 返回 platform（ios/android/devtools/windows/macos）、系统版本、微信版本；`wx.getAppBaseInfo()` 返回 SDKVersion（基础库版本）；`wx.canIUse()` 检测某个 API 或能力是否存在。上线前用这些信息做能力降级是常规操作。

```js
// utils/env.js —— 运行环境检测
function getEnvInfo() {
  const info = wx.getSystemInfoSync();
  return {
    platform: info.platform,          // ios / android / devtools / windows / macos
    system: info.system,              // 如 "iOS 17.2"、"Android 14"
    version: info.version,            // 微信版本号
    SDKVersion: info.SDKVersion,      // 基础库版本，如 "3.4.0"
    model: info.model,                // 设备型号
    screenWidth: info.screenWidth,    // 屏幕宽度 px
    pixelRatio: info.pixelRatio       // 像素比
  };
}

// 能力检测：判断是否支持某个 API
function canUse(apiPath) {
  return wx.canIUse(apiPath);         // 如 'onThemeChange'、'createWorker'
}

module.exports = { getEnvInfo, canUse };
```

```js
// app.js —— 启动时记录运行环境
App({
  onLaunch() {
    const { getEnvInfo } = require('./utils/env');
    const env = getEnvInfo();

      console.warn('当前环境不支持 Worker，耗时计算将回退到主线程');
```


## 双线程模型与 setData 通信

小程序采用双线程架构：逻辑层（App Service）运行在小程序 JS 引擎线程中，负责业务逻辑与数据处理；视图层由每个页面一个 WebView（或 Skyline 渲染线程）组成，负责 WXML 模板渲染与样式呈现。两个线程之间没有共享内存，数据传递必须经过微信客户端原生层转发的通信桥。

数据流向是单向的：逻辑层通过 `this.setData({ path: value })` 把数据推送到视图层，视图层 diff 后更新对应节点；视图层的事件（tap、input 等）通过 bind/catch 绑定转发回逻辑层执行回调。setData 发送的数据会被序列化（JSON 化）跨线程传输，因此 data 中只能放可序列化的值，函数、Date 实例、循环引用对象都不能放。

setData 的语义要记牢：调用后 `this.data` 同步更新，视图层异步渲染；支持路径更新（`'user.name'`、`'list[0].title'`），只传变化的字段能显著减少传输量。频繁、大数据量 setData 是页面卡顿的第一大原因，性能优化篇会展开讲（见 [[13.3-setData 性能优化]]）。

```js
// pages/counter/counter.js —— 双线程通信最小示例
Page({
  data: {
    count: 0,
    user: { name: '张三', level: 1 }
  },

  onTapAdd() {
    // 视图层 tap 事件 -> 逻辑层回调 -> setData 回推视图层
    this.setData({
      count: this.data.count + 1
    });
  },

  onTapLevelUp() {
    // 路径更新：只传变更字段，减少序列化数据量
    this.setData({
      'user.level': this.data.user.level + 1
    });
  }
});
```

```xml
<!-- pages/counter/counter.wxml -->
<view class="page">
  <view class="count">{{count}}</view>
  <view class="level">等级：{{user.level}}</view>
  <button bindtap="onTapAdd">加一</button>
  <button bindtap="onTapLevelUp">升级</button>
</view>
```

```text
双线程模型要点：
1. 逻辑层 —— App Service，单一 JS 线程，所有页面共享，任务串行执行
2. 视图层 —— 每页面一个 WebView（Skyline 渲染为独立渲染线程）
3. 通信桥 —— 数据经微信客户端原生层转发，不共享内存
4. setData —— 逻辑层推数据到视图层，可序列化数据，路径更新
5. 单向流 —— 数据下行 setData，事件上行 bindtap 等回调
6. 性能 —— this.data 同步更新、视图异步渲染，大数据频繁 setData 会卡顿
```

## ES6 与 ES6+ 支持情况

小程序 JavaScript 支持 ES6 及大部分 ES6+ 特性。开发者工具默认开启「ES6 转 ES5」，代码在编译期被 Babel 转换后再打包上传，因此语法层面的兼容性主要靠编译兜底；真机执行的是转换后的代码，运行时能力（Promise、async/await 等）取决于引擎与基础库。

常用特性支持情况：箭头函数、模板字符串、解构赋值、展开运算符、默认参数、let/const、Class、Set/Map、Object.assign、Array.from/includes/find 等在 iOS 与 Android 均可使用；Promise 由基础库提供 polyfill（iOS JSC 原生也支持）；async/await 需要基础库与引擎支持，低版本环境需开启「增强编译」降级为 Generator + Promise 实现。

需要特别注意的边界：Proxy 在 iOS JavaScriptCore 上支持不完整，官方不推荐依赖（基础库自身也避免使用）；Reflect 部分方法、WeakRef、String.prototype.replaceAll 等新 API 视引擎版本而定；所有新 API 上线前用真机验证，必要时用 wx.canIUse 检测后降级。

```js
// pages/es6/es6.js —— ES6+ 特性实际使用
Page({
  data: {
    list: [],
    summary: ''
  },

  onLoad() {
    // 解构 + 默认参数 + 模板字符串
    const { page = 1, size = 10 } = { page: 2 };
    const url = `/api/goods?page=${page}&size=${size}`;

    // 箭头函数 + Class + 展开运算符
    class Cart {
      constructor(items = []) {
        this.items = items;
      }
      add(item) {
        this.items = [...this.items, item];
      }
    }
    const cart = new Cart([{ id: 1 }]);
    cart.add({ id: 2 });

    // Promise 链 + async/await
    this.fetchData(url).then((res) => {
      // Set 去重、Array.from、includes
      const ids = [...new Set(res.map((g) => g.id))];
      const list = res.filter((g) => !g.offSale && ids.includes(g.id));
      this.setData({ list, summary: `共 ${list.length} 件商品` });
    });
  },

  async fetchData(url) {
    const res = await new Promise((resolve) => {
      setTimeout(() => {
        resolve([
          { id: 1, name: '苹果', offSale: false },
          { id: 2, name: '香蕉', offSale: false },
          { id: 1, name: '苹果', offSale: false }
        ]);
      }, 100);
    });
    return res;
  }
});
```

```text
ES6+ 支持要点：
1. 编译 —— 开发者工具默认 ES6 转 ES5，语法兼容靠编译期兜底
2. 常用特性 —— 箭头函数/模板字符串/解构/展开/Class/Set/Map 均可用
3. Promise —— 基础库提供 polyfill，链式调用与 all/race 正常使用
4. async/await —— 较新环境原生支持，低版本需「增强编译」降级
5. Proxy —— iOS JavaScriptCore 支持不完整，官方不建议依赖
6. 新 API —— 上线前真机验证，配合 wx.canIUse 做能力检测与降级
```

## 与浏览器和 Node 的差异

小程序 JS 运行环境既不是完整浏览器也不是 Node，可以理解为「带 wx 全局对象的定制 JS 引擎」。与浏览器相比：没有 window、document、navigator 等全局对象，没有 DOM，不能操作页面节点（渲染由 WXML 模板驱动）；全局对象上挂载的是 wx 命名空间（wx.request、wx.setStorage 等），另有关键全局函数 App/Page/Component/getApp/getCurrentPages。

浏览器常用能力在小程序里都有对应替代：localStorage/Cookie 用 wx.setStorageSync/getStorageSync；fetch/XHR 用 wx.request；WebSocket 用 wx.connectSocket；alert/confirm 用 wx.showModal；URL 跳转用 wx.navigateTo 系列；事件监听用 wx.onXxx。console 可用，日志输出到开发者工具控制台。

与 Node 相比：没有完整的 Node 模块系统，fs/path/process/Buffer/Stream 等内置模块全部不可用；模块机制是 CommonJS（require/module.exports），不支持 require('fs') 这类 Node 核心模块；npm 包需要先在开发者工具中「构建 npm」生成 miniprogram_npm 目录才能 require；没有 process.env，环境配置用配置文件或 wx.getAccountInfoSync 区分环境。

```js
// utils/http.js —— 用 wx.request 替代 fetch 的封装
function request(url, method = 'GET', data = {}) {
  return new Promise((resolve, reject) => {
    wx.request({
      url,
      method,
      data,
      header: { 'Content-Type': 'application/json' },
      success: (res) => {
        if (res.statusCode === 200) {
          resolve(res.data);
        } else {
          reject(new Error('HTTP ' + res.statusCode));
        }
      },
      fail: (err) => reject(err)
    });
  });
}

module.exports = { request };
```

```js
// utils/store.js —— 替代 localStorage 的封装
function get(key, defaultValue = null) {
  try {
    const value = wx.getStorageSync(key);
    return value === '' || value === undefined ? defaultValue : value;
  } catch (e) {
    return defaultValue;
  }
}

function set(key, value) {
  wx.setStorageSync(key, value);
}

function remove(key) {
  wx.removeStorageSync(key);
}

module.exports = { get, set, remove };
```

```text
差异对照要点：
1. 无 DOM —— 没有 window/document，不能操作节点，渲染靠 WXML
2. wx 全局 —— 全局对象挂 wx 命名空间与 App/Page/Component/getApp
3. 存储 —— localStorage/Cookie 用 wx.setStorageSync 系列替代
4. 网络 —— fetch/XHR 用 wx.request，WebSocket 用 wx.connectSocket
5. 模块 —— CommonJS 模块系统，Node 内置模块（fs/path/process）不可用
6. npm —— 第三方包需「构建 npm」生成 miniprogram_npm 后才能 require
```

## 多线程 Worker

逻辑层是单线程的，大量耗时计算（大数据排序、加密、图片处理、JSON 序列化）会阻塞业务逻辑，导致页面交互卡顿。小程序提供 Worker 线程承载耗时计算：通过 `wx.createWorker('workers/xxx.js')` 创建，Worker 运行在独立的 JS 引擎线程中，与逻辑层通过 postMessage/onMessage 双向通信。

Worker 文件放在项目根目录的 workers 目录下，会被打包进主包（计入包体积）；worker 内可以使用 require 引用其他模块，但线程内没有 DOM、没有界面，大部分 wx API 不可用，需要系统能力时由主线程获取后通过 postMessage 传入。官方限制同一个小程序同时最多运行 1 个 Worker 实例。

通信协议：主线程用 `worker.postMessage(data)` 发送、`worker.onMessage(cb)` 接收；Worker 内部用 `self.onmessage` 接收、`self.postMessage(data)` 回传。数据同样要求可序列化。任务完成后主线程调用 `worker.terminate()` 销毁 Worker，避免常驻占用资源；小程序退出时 Worker 自动销毁。

```js
// workers/sort.js —— Worker 线程内执行的排序任务
// 在 workers 目录下，随主包打包
self.onmessage = (e) => {
  const { taskId, list, key } = e.data;

  // 耗时计算：大数据量排序
  const sorted = list
    .map((item) => ({ ...item }))
    .sort((a, b) => (b[key] || 0) - (a[key] || 0));

  // 回传主线程
  self.postMessage({ taskId, sorted });
};
```

```js
// pages/report/report.js —— 主线程使用 Worker
Page({
  data: {
    result: []
  },

  onLoad() {
    // 创建 Worker，路径相对于项目根目录
    const worker = wx.createWorker('workers/sort.js');
    this._worker = worker;

    // 接收 Worker 回传结果
    worker.onMessage((res) => {
      this.setData({ result: res.sorted });
      // 任务结束销毁 Worker
      worker.terminate();
    });

    // 构造 10 万条数据，丢给 Worker 排序
    const rawList = [];
    for (let i = 0; i < 100000; i++) {
      rawList.push({ id: i, score: Math.random() * 1000 });
    }
    worker.postMessage({ taskId: 1, list: rawList, key: 'score' });

    wx.showLoading({ title: '排序中' });
  },

  onUnload() {
    // 页面销毁时清理 Worker，防止泄漏
    if (this._worker) {
      this._worker.terminate();
    }
  }
});
```

```text
Worker 要点：
1. 创建 —— wx.createWorker('workers/xxx.js')，文件必须在 workers 目录
2. 数量 —— 官方限制同时最多 1 个 Worker 实例
3. 通信 —— postMessage 发送、onMessage 接收，数据可序列化
4. 限制 —— Worker 内无 DOM 无界面，大部分 wx API 不可用
5. 打包 —— workers 目录计入主包体积，require 模块需在包内
6. 销毁 —— 任务结束 terminate()，页面卸载时清理，小程序退出自动销毁
```

## 应用场景实战

### 场景一：大数据列表在 Worker 中排序去重

会员列表页需要对数万条记录按积分排序并分组统计，直接在主线程做会阻塞 setData 与交互，交给 Worker。

```js
// workers/rank.js —— Worker 线程：排序 + 分组统计
self.onmessage = (e) => {
  const { taskId, members } = e.data;

  // 按积分降序
  const sorted = members
    .slice()
    .sort((a, b) => (b.score || 0) - (a.score || 0));

  // 按等级分组统计
  const groupMap = {};
  sorted.forEach((m) => {
    const level = m.level || 'L1';
    groupMap[level] = (groupMap[level] || 0) + 1;
  });

  self.postMessage({ taskId, sorted, groupMap });
};
```

```js
// pages/rank/rank.js
Page({
  data: {
    topList: [],
    groupMap: {},
    loading: true
  },

  onLoad() {
    this.startRankTask();
  },

  startRankTask() {
    const worker = wx.createWorker('workers/rank.js');
    this._worker = worker;

    worker.onMessage((res) => {
      // 只把 Top 50 传给视图层渲染，避免大数据 setData
      this.setData({
        topList: res.sorted.slice(0, 50),
        groupMap: res.groupMap,
        loading: false
      });
      worker.terminate();
    });

    // 模拟拉取 5 万条会员数据
    const members = [];
    for (let i = 0; i < 50000; i++) {
      members.push({
        id: i,
        name: '会员' + i,
        score: Math.floor(Math.random() * 10000),
        level: 'L' + (i % 5 + 1)
      });
    }
    worker.postMessage({ taskId: 'rank', members });
  },

  onUnload() {
    if (this._worker) {
      this._worker.terminate();
    }
  }
});
```

### 场景二：运行环境检测与能力降级

发布前做环境兼容性检查：不同平台与基础库版本给出不同处理路径，防止低版本环境白屏。

```js
// app.js —— 启动时环境检测与降级
const MIN_SDK = '2.11.0';   // 本示例要求的最低基础库

function compareVersion(v1, v2) {
  const a = v1.split('.').map(Number);
  const b = v2.split('.').map(Number);
  for (let i = 0; i < 3; i++) {
    if ((a[i] || 0) !== (b[i] || 0)) {
      return (a[i] || 0) > (b[i] || 0) ? 1 : -1;
    }
  }
  return 0;
}

App({
  onLaunch() {
    const info = wx.getSystemInfoSync();
    const sdkVersion = info.SDKVersion;

    console.log('运行环境：', info.platform, '系统', info.system, '基础库', sdkVersion);

    // 基础库过低：提示升级微信
    if (compareVersion(sdkVersion, MIN_SDK) < 0) {
      wx.showModal({
        title: '版本过低',
        content: '当前微信版本过低，请升级后使用',
        showCancel: false
      });
      return;
    }

    // 能力降级：不支持 Worker 时标记降级模式
    const degraded = !wx.canIUse('createWorker');
    this.globalData = { degraded, platform: info.platform };
  }
});
```

```js
// utils/http.js —— Promise 封装 wx.request（避免回调地狱）
function request(url, method = 'GET', data = {}) {
  return new Promise((resolve, reject) => {
    wx.request({
      url,
      method,
      data,
      timeout: 10000,
      success: (res) => {
        if (res.statusCode >= 200 && res.statusCode < 300) {
          resolve(res.data);
        } else {
          reject(new Error('请求失败：HTTP ' + res.statusCode));
        }
      },
      fail: (err) => reject(err)
    });
  });
}

// 并发请求：Promise.all 合并多个接口
async function loadHomeData() {
  const [banner, goods, notice] = await Promise.all([
    request('/api/banner'),
    request('/api/goods?page=1'),
    request('/api/notice')
  ]);
  return { banner, goods, notice };
}

module.exports = { request, loadHomeData };
```

## 最佳实践与踩坑记录

### 最佳实践

1. 逻辑层代码只使用 wx.* API 与全局函数（App/Page/getApp），不做任何 window/document 假设
2. setData 最小化：只传变更字段路径（'user.name'），大列表只传视图需要的部分
3. 耗时计算（排序、加密、图片处理）一律丢 Worker，主线程保持响应
4. 项目开启「ES6 转 ES5」与「增强编译」，新 API 用 wx.canIUse 检测后再用
5. 公共代码抽到 utils 目录用 CommonJS 导出，npm 包通过「构建 npm」引入
6. 网络请求封装成 Promise 形式（promisify），配合 async/await 避免回调地狱
7. 上线前在低版本真机上验证语法兼容，重点检查 async/await、数组新方法与展开运算符
8. 环境信息（platform/SDKVersion）在 onLaunch 统一采集，作为线上问题排查的第一手数据

### 踩坑记录

坑 1：在逻辑层使用 window/document 报 ReferenceError
结论：页面加载即报错「window is not defined」，白屏。
原因：逻辑层运行在无 DOM 的 JS 引擎线程中，不存在浏览器全局对象。
解法：所有浏览器能力改用 wx 对应 API（wx.request、wx.setStorageSync 等）；不要引入依赖 DOM 的第三方库。

坑 2：setData 传输大对象导致页面卡顿白屏
结论：一次 setData 传几 MB 数据或高频 setData 后，页面滚动卡顿、渲染延迟。
原因：setData 数据要 JSON 序列化跨线程传输，数据量越大桥接开销越大。
解法：只传变更字段路径；列表分页渲染；大数据处理放 Worker，只回传结果。

坑 3：async/await 在低版本安卓真机报语法错误
结论：开发者工具一切正常，旧安卓真机上页面报错或功能失效。
原因：真机引擎版本过旧，对 async/await 原生支持不足，编译未降级。
解法：开启「增强编译」将 async/await 转为 ES5；或提升最低基础库版本；上线前真机验证。

坑 4：require Node 内置模块（fs/path）报 module not found
结论：require('fs') 直接报错，页面逻辑中断。
原因：小程序不是 Node 环境，没有 Node 核心模块。
解法：改用小程序的 wx API（存储用 wx.setStorage，路径处理自己写）；npm 包需先构建 npm 生成 miniprogram_npm。

坑 5：Worker 里调用 wx.showToast 等界面 API 无效
结论：Worker 中调用 wx API 静默失败或报错，界面无任何反应。
原因：Worker 线程没有界面能力，大部分 wx API 不可用。
解法：Worker 内只做纯计算，需要提示/存储等能力时 postMessage 回主线程，由主线程调用 wx API。

坑 6：wx.request 回调里 this 丢失
结论：success 回调里访问 this.setData 报「Cannot read property 'setData' of undefined」。
原因：普通函数回调的 this 不指向页面实例。
解法：回调使用箭头函数；或 const that = this 保存引用；或直接用封装好的 Promise 版 request。

坑 7：依赖 Proxy 做响应式，iOS 端行为异常
结论：使用 Proxy 实现的数据监听在 iOS 真机上不触发或行为错误。
原因：iOS JavaScriptCore 对 Proxy 支持不完整，官方明确不建议依赖。
解法：不依赖 Proxy/Reflect 做核心逻辑；响应式需求改用 setData 数据流或自定义事件方案。

坑 8：开发者工具正常、真机语法报错
结论：工具里跑通的代码，旧安卓/iOS 真机上语法级报错。
原因：工具内核是桌面 Chromium V8，语法支持领先于真机引擎。
解法：ES6 转 ES5 兜底；新特性用 canIUse 检测；建立真机兼容测试矩阵，重点机型回归。

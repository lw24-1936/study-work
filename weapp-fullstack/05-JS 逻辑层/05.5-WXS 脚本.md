## 概述

WXS（WeiXin Script）是小程序视图层的一套脚本语言，运行在视图层（渲染线程）中，与 WXML 处于同一线程，因此可以在模板渲染时直接完成数据计算与格式化，不必把处理逻辑放回逻辑层。WXS 是 JavaScript 的 ES5 子集，语法与 JS 高度相似但能力受限：不能调用 wx.* API，不能作为事件回调，不能操作页面节点。

```text
WXS 核心概念：
1. 视图层脚本 —— 运行在渲染线程，与 WXML 同线程，可与 WXML 数据绑定直接配合
2. 减少通信 —— 在视图层完成格式化计算，避免「逻辑层计算 + setData 回传」的往返开销
3. ES5 子集 —— 语法基于 ES5，不支持 let/const/箭头函数等 ES6+ 特性
4. 模块机制 —— 通过 module.exports 导出，<wxs> 标签或 require 引用
5. 能力受限 —— 不能调 wx API、不能操作节点、不能作为事件处理函数
6. 适用场景 —— 价格/日期/手机号等格式化、数组过滤映射、模板内复杂运算
```

## WXS 概念与运行机制

WXS 的设计动机来自小程序的性能模型：逻辑层与视图层分离，逻辑层通过 setData 把数据传给视图层，视图层再渲染。如果视图层需要的只是「把 100 分转成 ¥1.00」「把时间戳转成昨天 12:00」「把数组过滤出前 3 条」，这些计算如果在逻辑层做，就要先算好再 setData 一次；如果直接在视图层用 WXS 算，则省掉了这次通信。

```text
为什么需要 WXS：
1. setData 有成本 —— 每次 setData 都要走逻辑层与视图层的桥接通信，频繁调用影响性能
2. 视图层就地计算 —— 格式化、过滤等纯计算放在视图层完成，减少 setData 次数
3. 渲染数据自包含 —— 原始数据一次性 setData 到视图层，展示形态由 WXS 按需计算
4. 配合数据绑定 —— WXS 函数可以直接在 {{ }} 中调用，如 {{format.price(item.price)}}
5. 历史背景 —— 早期没有 WXS 时，这类计算只能在 JS 层做模板字符串拼接再回传
6. 注意边界 —— WXS 不是万能的，复杂业务逻辑与数据请求仍应在逻辑层完成
```

```js
// 不使用 WXS 的写法：逻辑层先格式化再 setData（每次数据变化都要往返通信）
Page({
  data: { list: [] },
  onLoad() {
    const raw = [{ name: '可乐', price: 350 }, { name: '薯片', price: 650 }]
    this.setData({
      list: raw.map((item) => ({ ...item, priceText: '¥' + (item.price / 100).toFixed(2) })),
    })
  },
})
```

```wxml
<!-- 使用 WXS 的写法：逻辑层只传原始数据，格式化在视图层完成 -->

  module.exports.formatPrice = function (cents) {
    return '¥' + (cents / 100).toFixed(2)
  }
</wxs>

  <text>{{item.name}} - {{fmt.formatPrice(item.price)}}</text>

```

```js
// 逻辑层：直接 setData 原始数据，不再做格式化
Page({
  data: { list: [] },
  onLoad() {
    this.setData({
      list: [{ name: '可乐', price: 350 }, { name: '薯片', price: 650 }],
    })
  },
})
```

两种写法的渲染结果一致，但使用 WXS 时逻辑层不再关心展示格式，数据变化时也不需要重新格式化整个列表。这种「原始数据 + 视图层格式化」的模式是 WXS 最核心的价值。

## WXS 语法与模块

WXS 语法基于 ES5，支持 var、function、对象/数组字面量、if/else、switch、for/while、三元表达式、字符串方法、JSON 对象等。与 JS 的差异：不能用 let/const（只有 var）、不能用箭头函数与模板字符串、不能用解构与展开运算符、不能用 Promise/async/await、不能用 class；日期与正则需要用 getDate() 与 getRegExp() 创建。

```js
// utils/format.wxs —— 独立的 .wxs 文件
// 注意：wxs 文件内只能用 var，不能用 let/const
var DIGITS = ['零', '一', '二', '三', '四', '五', '六', '七', '八', '九']

// 分转元字符串
function fenToYuan(cents) {
  return (cents / 100).toFixed(2)
}

// 手机号脱敏：138****8000
function maskPhone(phone) {
  if (!phone || phone.length !== 11) return phone
  return phone.substring(0, 3) + '****' + phone.substring(7)
}

// 时间戳转 yyyy-MM-dd（wxs 中用 getDate() 创建日期）
function formatDate(timestamp, separator) {
  var date = getDate(timestamp)
  var y = date.getFullYear()
  var m = date.getMonth() + 1
  var d = date.getDate()
  m = m < 10 ? '0' + m : '' + m
  d = d < 10 ? '0' + d : '' + d
  return y + (separator || '-') + m + (separator || '-') + d
}

// 千分位格式化：1234567 -> 1,234,567
function thousands(num) {
  var str = String(num)
  var result = ''
  var count = 0
  for (var i = str.length - 1; i >= 0; i--) {
    result = str.charAt(i) + result
    count++
    if (count % 3 === 0 && i > 0) {
      result = ',' + result
    }
  }
  return result
}

module.exports = {
  fenToYuan: fenToYuan,
  maskPhone: maskPhone,
  formatDate: formatDate,
  thousands: thousands,
}
```

```wxs
  var date = getDate(timestamp)

```

```text
WXS 模块要点：
1. <wxs src> —— 引用外部 .wxs 文件，src 必须是相对路径，module 属性自定义模块名
2. 内联模块 —— <wxs module="xxx"> 内直接写脚本，适合短小逻辑
3. module.exports —— wxs 内导出接口的唯一方式，与 CommonJS 风格一致
4. 文件间引用 —— wxs 文件内可用 require('./xxx.wxs') 引用其他 wxs 文件
5. 独立作用域 —— 每个 wxs 模块作用域独立，模块内 var 不污染其他模块
6. 重复定义 —— 同一页面中 module 名重复时后定义者覆盖先定义者，需避免重名
```

## WXS 常见用法

WXS 最常见的三大类用法：格式化（价格、日期、手机号、证件号）、数组处理（过滤、映射、排序）、模板内条件运算（状态文案映射、进度计算）。下面给出可运行的完整示例。

```wxs
// utils/product.wxs —— 商品展示相关处理
// 价格：分转元 + 千分位 + 保留两位小数
function formatPrice(cents) {
  if (cents === null || cents === undefined) return '0.00'
  var yuan = (cents / 100).toFixed(2)
  var parts = yuan.split('.')
  parts[0] = thousands(parts[0])
  return parts.join('.')
}

function thousands(str) {
  var result = ''
  var count = 0
  for (var i = str.length - 1; i >= 0; i--) {
    result = str.charAt(i) + result
    count++
    if (count % 3 === 0 && i > 0) {
      result = ',' + result
    }
  }
  return result
}

// 过滤出「进行中」的活动（status === 1）并取前 n 条
function activeList(list, n) {
  if (!list || list.length === 0) return []
  var result = []
  for (var i = 0; i < list.length; i++) {
    if (list[i].status === 1) {
      result.push(list[i])
      if (result.length >= (n || 10)) break
    }
  }
  return result
}

// 库存充足判断：库存 > 0 且未下架
function inStock(item) {
  return item.stock > 0 && item.onSale !== false
}

// 计算折扣（原价/现价），保留一位小数
function discount(original, current) {
  if (!original || !current) return '10'
  var d = (current / original) * 10
  return d.toFixed(1)
}

module.exports = {
  formatPrice: formatPrice,
  activeList: activeList,
  inStock: inStock,
  discount: discount,
}
```

```wxml

<!-- 价格展示 -->

  <text class="price">¥{{p.formatPrice(item.price)}}</text>
  <text wx:if="{{item.originalPrice}}" class="origin">¥{{p.formatPrice(item.originalPrice)}}</text>
  <text wx:if="{{item.originalPrice}}" class="tag">{{p.discount(item.originalPrice, item.price)}}折</text>
</view>

<!-- 数组过滤：只渲染进行中的活动 -->

  {{act.title}}
</view>
```

```wxs
// utils/date.wxs —— 消息列表时间处理
function messageTime(timestamp) {
  var now = getDate()
  var date = getDate(timestamp)
  var diff = now.getTime() - date.getTime()
  var minute = 60 * 1000
  var hour = 60 * minute
  var day = 24 * hour
  if (diff < minute) return '刚刚'
  if (diff < hour) return Math.floor(diff / minute) + ' 分钟前'
  if (diff < day) return Math.floor(diff / hour) + ' 小时前'
  if (diff < 2 * day) return '昨天'
  return formatDate(date)
}

function formatDate(date) {
  var y = date.getFullYear()
  var m = date.getMonth() + 1
  var d = date.getDate()
  m = m < 10 ? '0' + m : '' + m
  d = d < 10 ? '0' + d : '' + d
  return y + '-' + m + '-' + d
}

module.exports = {
  messageTime: messageTime,
}
```

```text
WXS 常见用法要点：
1. 价格格式化 —— 分转元、千分位、折扣计算，电商列表页高频使用
2. 日期处理 —— 相对时间（刚刚/n 分钟前/昨天）、绝对时间，注意用 getDate() 创建日期
3. 数组处理 —— filter/map 逻辑在 wxs 中实现，减少 setData 的数据量
4. 状态映射 —— 状态码转文案、类型转图标 class，直接在模板中取值
5. 脱敏处理 —— 手机号、身份证、银行卡号的中间打码
6. 工具链 —— 把通用 wxs 放 utils/ 目录，各页面 <wxs src> 复用
```

## WXS 与 JS 的差异

WXS 是 JS 的子集，二者差异是面试与踩坑的高频点。核心差异：语法能力（ES5 子集）、运行环境（视图层）、API 权限（不能调 wx.*）、交互能力（不能当事件回调）。

```text
WXS 与 JS 的主要差异：
1. 运行位置 —— WXS 运行在视图层渲染线程，JS 运行在逻辑层
2. 语法版本 —— WXS 只支持 ES5 子集；JS 支持 ES6+（增强编译转译）
3. 变量声明 —— WXS 只有 var（无 let/const、无块级作用域）
4. 新语法 —— WXS 无箭头函数、模板字符串、解构、展开、class、Promise、async/await
5. 内置对象 —— WXS 无 wx.* API、无 DOM/BOM，日期用 getDate()、正则用 getRegExp() 创建
6. 事件绑定 —— WXS 函数不能作为 bindtap 等事件回调（事件回调必须写在逻辑层 js 中）
7. 数据绑定 —— WXS 函数可在 {{ }} 中直接调用并参与表达式运算
8. 导出方式 —— WXS 只用 module.exports；JS 还可用 ES6 import/export
```

```wxml
<!-- 错误示例：WXS 函数不能作为事件回调 -->
<wxs module="bad">
  module.exports.handleTap = function () { return 1 }
</wxs>
<!-- 下面的 bindtap 绑定不会生效，点击无反应 -->
<view bindtap="bad.handleTap">点击</view>

<!-- 正确做法：事件回调必须写在 Page 的 js 中 -->
<view bindtap="onTap">点击</view>
```

```js
// pages/index/index.js —— 事件回调的正确位置
Page({
  onTap() {
    console.log('tap')
  },
})
```

```text
差异带来的常见问题：
1. 在 wxs 中写箭头函数 —— 直接语法报错，改为 function
2. 在 wxs 中用 new Date() —— 报错或行为异常，改用 getDate()
3. 在 wxs 中调 wx.getStorageSync —— 报错「wx is not defined」
4. 用 wxs 函数绑定事件 —— 静默失败，事件不触发
5. 在 wxs 中使用模板字符串 —— 语法报错，用字符串拼接 +
6. 忘记 module.exports —— WXML 中调用模块方法返回 undefined
```

## WXS 性能注意

WXS 的核心价值是减少 setData 通信，但它本身也有执行成本，使用不当反而更慢。性能相关要点集中在：计算量控制、渲染时机、与逻辑层的分工边界。

```text
WXS 性能注意点：
1. 就地计算省通信 —— 格式化类小计算放 wxs 收益最大，减少 setData 往返
2. 避免重计算 —— wxs 函数在每次渲染求值时执行，循环体内调用要注意次数
3. 大数据量谨慎 —— 在 wxs 中对超大数组做 O(n^2) 过滤会拖慢渲染线程
4. 首次渲染成本 —— wxs 模块加载与编译有一定开销，短逻辑内联即可
5. 分工边界 —— 复杂业务、数据请求、状态变更仍在逻辑层，wxs 只做展示计算
6. 长列表 —— 几千条数据的列表建议分页或逻辑层预处理，不要全量丢给 wxs
7. 调试 —— wxs 中可用 console.log 调试，输出在开发者工具控制台
8. 版本兼容 —— wxs 相关能力随基础库迭代，老基础库上需做能力检测
```

一个常见的反面示例：在 wxs 中对整页商品列表做多重循环过滤。假设 1000 个商品、每个商品还要遍历规格数组，视图层每次渲染都要执行这些循环，会明显卡顿。这类场景应在逻辑层分页或预处理，只把最终展示数据传给视图层。

```wxs
// utils/filter.wxs —— 示例：轻量过滤（可用），避免重度计算
function cheapGoods(list, maxPrice) {
  var result = []
  if (!list) return result
  for (var i = 0; i < list.length; i++) {
    if (list[i].price <= maxPrice) {
      result.push(list[i])
    }
    // 控制结果数量，避免一次性渲染过多
    if (result.length >= 50) break
  }
  return result
}

module.exports = { cheapGoods: cheapGoods }
```

```text
性能判断口诀：
1. 计算量小、调用频繁（格式化）-> 放 wxs，省通信
2. 计算量大、一次性的（全量过滤排序）-> 放逻辑层，避免阻塞渲染
3. 结果集巨大的（几千条）-> 分页，别让视图层一次渲染
4. 需要 wx API 或事件 -> 只能在逻辑层，别无选择
```

### 场景二：消息列表的智能时间展示

实现聊天/消息列表的「刚刚 / n 分钟前 / 昨天 / 日期」时间显示，原始时间戳一次 setData，展示完全交给 wxs：

```wxs
// utils/message-time.wxs
function pad(n) {
  n = n < 10 ? '0' + n : '' + n
  return n
}

function smartTime(timestamp) {
  if (!timestamp) return ''
  var now = getDate()
  var date = getDate(timestamp)
  var diff = now.getTime() - date.getTime()
  var minute = 60 * 1000
  var hour = 60 * minute
  var day = 24 * hour
  if (diff < minute) return '刚刚'
  if (diff < hour) return Math.floor(diff / minute) + ' 分钟前'
  if (diff < day && now.getDate() === date.getDate()) {
    return '今天 ' + pad(date.getHours()) + ':' + pad(date.getMinutes())
  }
  if (diff < 2 * day) return '昨天 ' + pad(date.getHours()) + ':' + pad(date.getMinutes())
  if (now.getFullYear() === date.getFullYear()) {
    return pad(date.getMonth() + 1) + '-' + pad(date.getDate())
  }
  return date.getFullYear() + '-' + pad(date.getMonth() + 1) + '-' + pad(date.getDate())
}

module.exports = { smartTime: smartTime }
```

## 最佳实践与踩坑记录

### 最佳实践

1. 遵循「原始数据 + 视图层格式化」模式：逻辑层只 setData 原始字段，展示格式统一由 wxs 计算，减少重复格式化与通信
2. 公共 wxs 放 utils/ 目录：format.wxs、date.wxs 等按职责拆分，页面用 <wxs src> 复用，与 JS 工具函数形成对应
3. 轻量计算放 wxs、重量计算放逻辑层：格式化、状态映射、简单过滤用 wxs；排序、聚合、大数组处理放 JS
4. wxs 内只写 ES5：统一用 var 和 function，避免团队中有人写箭头函数/模板字符串导致编译报错
5. 事件回调永远写在逻辑层：wxs 函数只用于数据绑定，bindtap 等事件绑定 Page/Component 的方法
6. 控制循环次数：wxs 函数在每次渲染求值，循环内调用 wxs 方法注意复杂度，必要时结果限流（如取前 N 条）
7. 模块命名唯一：wxml 中 module 名不要重复，避免后定义覆盖先定义导致诡异的渲染结果
8. 先测真机：wxs 的差异在模拟器与真机表现基本一致，但性能问题（大数据量）要在真机验证

### 踩坑记录

```text
坑 1：wxs 中用了 ES6 语法直接编译报错
结论：wxs 文件里写箭头函数或 let 声明，编译报语法错误。
原因：WXS 只支持 ES5 子集，不支持 let/const/箭头函数/模板字符串等。
解法：wxs 中统一使用 var 与 function 写法；复杂逻辑放逻辑层 js 处理。

坑 2：wxs 里调用 wx API 报错
结论：在 wxs 中调用 wx.getStorageSync 或 wx.request，报「wx is not defined」。
原因：WXS 运行在视图层，没有 wx 对象，也没有任何逻辑层 API。
解法：需要的数据在逻辑层取好通过 setData 传入；wxs 只做纯计算。

坑 3：wxs 函数绑定事件不生效
结论：bindtap 绑定了 wxs 模块的方法，点击毫无反应。
原因：WXS 函数不能作为事件处理函数，事件回调只能写在 Page/Component 的 js 中。
解法：事件回调定义在逻辑层 js 中，wxs 只处理数据展示。

坑 4：wxs 中用 new Date() 返回异常
结论：wxs 中使用 new Date() 得不到预期日期对象，日期格式化结果错误或报错。
原因：WXS 中日期对象需要通过 getDate() 创建，而非 new Date()。
解法：wxs 中统一使用 getDate(timestamp)，正则同理使用 getRegExp()。

坑 5：wxml 中调用 wxs 模块方法返回 undefined
结论：{{fmt.xxx()}} 渲染为空或 undefined，但 wxs 文件看起来没问题。
原因：wxs 文件没有 module.exports 导出，或 <wxs> 的 module 名与调用名不一致。
解法：wxs 文件末尾 module.exports = { ... } 导出；检查 src 路径与 module 名拼写。

坑 6：大数组在 wxs 中过滤导致列表卡顿
结论：几千条数据的列表在 wxs 中过滤排序，页面滚动明显卡顿。
原因：wxs 函数每次渲染都会重新执行，大量循环阻塞了视图层渲染线程。
解法：大数据量在逻辑层分页或预处理，wxs 只处理小数据量的展示计算。

坑 7：页面内重复定义同名 wxs 模块
结论：两个 <wxs module="fmt"> 同时存在，其中一个的方法调用全部失效。
原因：同页面重复定义 module 名时，后定义覆盖先定义。
解法：保证 module 名在页面内唯一；公共逻辑抽到公共 wxs 文件用 src 引入。

坑 8：wxs 修改后页面不更新
结论：改了 wxs 文件重新编译，页面渲染结果仍是旧逻辑。
原因：开发者工具对 wxs 的增量编译偶尔不刷新。
解法：清缓存重新编译；wxs 文件修改后可在 wxml 中改动任意字符触发重新渲染验证。
```

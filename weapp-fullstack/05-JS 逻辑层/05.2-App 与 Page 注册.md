## 概述

小程序由 App 与 Page 两类注册入口构成：app.js 中的 `App()` 注册小程序实例，承载全局生命周期与全局数据；每个页面目录下的 js 文件用 `Page()` 注册页面实例，承载页面数据、生命周期与交互方法。二者是双线程模型下逻辑层的两大基石。

App() 每个小程序只有一个，全局只执行一次初始化；Page() 每个页面一个，页面每次进入都会创建新的页面实例。页面数据定义在 data 中，修改必须通过 this.setData，方法直接定义在 Page 参数对象上（与 Vue 的 methods 写法不同）。理解注册时机与启动流程，是排查「页面拿不到全局数据」「方法找不到」等高频问题的前提。

```text
App 与 Page 核心认知：
1. App() —— 全局唯一，注册小程序实例，onLaunch 全局只触发一次
2. globalData —— 全局共享数据，非响应式，修改不触发页面渲染
3. Page() —— 每页面一个实例，data + 生命周期 + 方法三要素
4. data —— 页面初始数据，只能通过 this.setData 修改
5. 方法 —— 事件处理与自定义方法直接写在 Page 参数对象上
6. 时机 —— App 先于 Page 注册，冷启动先 onLaunch 再页面 onLoad
```

## App 注册与全局生命周期

app.js 是逻辑层的全局入口，通过 `App({ ... })` 注册小程序实例。App() 的参数对象可以包含生命周期回调与自定义字段（globalData、自定义方法）。生命周期回调有四个：`onLaunch`（小程序初始化完成时触发，全局只触发一次，可拿启动参数）、`onShow`（小程序启动或从后台进入前台）、`onHide`（小程序从前台进入后台）、`onError`（脚本错误统一上报）。

App 实例中的 this 指向 App 实例，生命周期回调里可以通过 this 访问 globalData 与自定义方法。注意 App() 中不能调用 `wx.navigateTo` 等页面路由 API——App 级没有页面上下文，启动瞬间页面栈尚未就绪；需要跳转应放在页面生命周期中，或在 onLaunch 里用 wx.reLaunch 延迟执行。

一个完整的 app.js 骨架：

```js
// app.js
App({
  // 全局共享数据：登录态、用户信息、全局配置
  globalData: {
    token: '',
    userInfo: null,
    systemInfo: null
  },

  // 小程序初始化：全局只触发一次
  onLaunch(options) {
    console.log('小程序启动', options.scene);   // options.scene 为启动场景值

    // 恢复登录态
    const token = wx.getStorageSync('token');
    if (token) {
      this.globalData.token = token;
    }

    // 缓存系统信息，全局只查一次
    this.globalData.systemInfo = wx.getSystemInfoSync();

    // 记录错误日志
    wx.onError && wx.onError((err) => {
      console.error('全局错误', err);
    });
  },

  // 从后台进入前台
  onShow() {
    console.log('小程序进入前台');
  },

  // 进入后台
  onHide() {
    console.log('小程序进入后台');
  },

  // 脚本错误统一处理
  onError(msg) {
    console.error('脚本错误', msg);
  },

  // 自定义全局方法
  setToken(token) {
    this.globalData.token = token;
    wx.setStorageSync('token', token);
  }
});
```

```text
App 注册要点：
1. 唯一性 —— 每个小程序只能有一个 App() 实例，重复调用报错
2. onLaunch —— 全局初始化一次，可拿启动参数 options.scene
3. onShow/onHide —— 前后台切换钩子，适合做会话续期、数据刷新
4. onError —— 脚本错误回调，配合日志上报定位线上问题
5. this —— 生命周期内 this 指向 App 实例，可访问 globalData 与自定义方法
6. 禁路由 —— App 中不可调用 navigateTo 等页面路由 API
```

## globalData 全局数据

globalData 是 App 实例上的全局共享数据区，设计用途是跨页面共享轻量数据：登录 token、用户信息、全局配置、系统信息等。任何页面/组件通过 `getApp().globalData` 读取与修改，App 生命周期中通过 this.globalData 访问。

关键特性：globalData 是非响应式的。修改 globalData 不会触发任何页面重新渲染，页面必须在需要时主动读取或通过 setData 把值同步到页面 data。这与 Vuex/Pinia 的状态管理完全不同——小程序没有全局响应式状态，全局数据 + 手动同步是标准做法。

globalData 适合放「启动时一次性获取、之后基本不变」的数据（系统信息、登录态）；不适合放频繁变化的大数据（列表、购物车明细）——高频变化数据放页面 data 或 storage，由页面自行管理。另外注意 globalData 中的对象被页面修改后是同一引用，跨页面共享可变对象时要小心意外串改。

```js
// app.js —— 全局数据初始化
App({
  globalData: {
    token: '',
    userInfo: null,
    cartCount: 0
  },

  onLaunch() {
    this.globalData.token = wx.getStorageSync('token') || '';
  }
});
```

```js
// pages/mine/mine.js —— 页面读取与同步全局数据
const app = getApp();

Page({
  data: {
    userInfo: null,
    cartCount: 0
  },

  onShow() {
    // 页面每次展示时从全局同步数据（非响应式，必须手动同步）
    this.setData({
      userInfo: app.globalData.userInfo,
      cartCount: app.globalData.cartCount
    });
  },

  onLoginTap() {
    // 模拟登录后写入全局数据
    app.globalData.userInfo = { nickname: '微信用户', avatar: '' };
    app.globalData.cartCount = 3;
    wx.setStorageSync('userInfo', app.globalData.userInfo);

    // 手动同步到页面 data，触发视图更新
    this.setData({
      userInfo: app.globalData.userInfo,
      cartCount: app.globalData.cartCount
    });
  }
});
```

```xml
<!-- pages/mine/mine.wxml -->
<view class="page">
  <view class="user-info">
    <text>{{userInfo ? userInfo.nickname : '未登录'}}</text>
    <text>购物车 {{cartCount}} 件</text>
  </view>
  <button bindtap="onLoginTap">模拟登录</button>
</view>
```

```text
globalData 要点：
1. 定义 —— App() 参数中的自定义字段，跨页面共享
2. 读取 —— getApp().globalData 获取，App 内用 this.globalData
3. 非响应式 —— 修改不触发渲染，页面需主动读取/手动 setData 同步
4. 适用范围 —— 登录态、用户信息、系统配置等低频变化数据
5. 不适用 —— 高频变化的大数据放页面 data 或 storage 管理
6. 引用共享 —— 对象是同一引用，跨页面修改需注意意外串改
```

## Page 注册与 data 定义

每个页面由目录下的四件套组成（js/json/wxml/wxss），其中 js 文件通过 `Page({ ... })` 注册页面实例。Page() 参数对象包含三部分：`data`（页面初始数据）、生命周期回调（onLoad/onShow/onReady/onHide/onUnload 等）、页面方法（事件处理与自定义方法）。

data 必须是对象，字段会在页面创建时被序列化后注入视图层，WXML 中通过 `{{字段}}` 绑定。data 中只能放可序列化数据（字符串、数字、数组、普通对象），不能放函数、Date 实例、循环引用对象。修改 data 的唯一正确方式是 `this.setData({ path: value })`——支持点路径与数组下标（`'user.name'`、`'list[0].title'`），setData 之后 this.data 同步更新、视图异步刷新。

页面生命周期执行顺序：onLoad（页面创建，接收路由参数 options）→ onShow（页面显示）→ onReady（首帧渲染完成）→ 交互 → onHide（页面隐藏）→ onUnload（页面销毁）。onLoad 只执行一次，onShow 每次展示都会执行，数据刷新逻辑通常放 onShow。

```js
// pages/detail/detail.js —— 完整 Page 注册示例
Page({
  // 页面初始数据：必须为可序列化对象
  data: {
    goodsId: 0,
    goods: null,
    quantity: 1,
    loading: true
  },

  // 页面创建：接收路由参数（唯一执行一次）
  onLoad(options) {
    this.setData({
      goodsId: Number(options.goodsId) || 0
    });
    this.fetchGoods();
  },

  // 页面显示：每次进入都会触发
  onShow() {
    console.log('页面显示');
  },

  // 首帧渲染完成
  onReady() {
    console.log('页面就绪');
  },

  // 页面隐藏（切后台或被覆盖）
  onHide() {
    console.log('页面隐藏');
  },

  // 页面销毁（navigateBack 等）
  onUnload() {
    console.log('页面卸载');
  },

  // 自定义方法：模拟拉取商品详情
  fetchGoods() {
    setTimeout(() => {
      this.setData({
        goods: { id: this.data.goodsId, title: '示例商品', price: '99.00' },
        loading: false
      });
    }, 300);
  }
});
```

```text
Page 注册要点：
1. data —— 初始数据对象，可序列化，WXML 通过 {{字段}} 绑定
2. setData —— 唯一修改方式，支持 'a.b' 点路径与 'list[0].x' 下标
3. 生命周期 —— onLoad(一次) -> onShow(每次) -> onReady -> onHide -> onUnload
4. onLoad(options) —— 接收 navigateTo 等传来的路由查询参数
5. 实例 —— 页面方法中 this 指向页面实例，可直接 this.setData
6. 四件套 —— js 注册逻辑、json 页面配置、wxml 结构、wxss 样式
```

## 页面方法

页面方法分为两类：事件处理函数（通过 bindtap/bindinput 等绑定到 WXML 事件）与普通自定义方法。两者都直接定义在 Page() 参数对象上——这是小程序与 Vue（methods 包裹）写法上的明显区别。方法之间通过 `this.方法名()` 互相调用。

事件处理函数的第一个参数是事件对象 e：`e.currentTarget.dataset` 取携带的 data-* 参数（必须用 currentTarget 而不是 target，target 可能指向触发事件的最深子节点）；`e.detail` 取组件抛出的数据（input 的 value、picker 的选中值等）。input 输入、表单提交、列表点击是三个最高频场景。

命名规范建议：事件处理函数用 `onXxx` 或 `handleXxx` 前缀，自定义方法用动词短语，避免与 data、生命周期名、setData 等保留字冲突。方法里访问数据用 this.data，修改用 this.setData，异步回调注意 this 指向（用箭头函数或提前保存 const that = this）。

```xml
<!-- pages/form/form.wxml -->
<view class="page">
  <input
    class="input"
    placeholder="输入商品名称"
    value="{{keyword}}"
    bindinput="onInput"
    data-field="keyword"
  />
  <button bindtap="onSearchTap">搜索</button>

  <view
    class="goods-item"
    wx:for="{{list}}"
    wx:key="id"
    bindtap="onItemTap"
    data-id="{{item.id}}"
  >
    {{item.title}}
  </view>
</view>
```

```js
// pages/form/form.js
Page({
  data: {
    keyword: '',
    list: [
      { id: 1, title: '苹果' },
      { id: 2, title: '香蕉' },
      { id: 3, title: '橙子' }
    ]
  },

  // 事件处理：输入框，e.detail.value 是当前输入值
  onInput(e) {
    this.setData({ keyword: e.detail.value });
  },

  // 事件处理：按钮点击，组合当前输入发起搜索
  onSearchTap() {
    const keyword = this.data.keyword.trim();
    if (!keyword) {
      wx.showToast({ title: '请输入关键词', icon: 'none' });
      return;
    }
    this.doSearch(keyword);
  },

  // 事件处理：列表项点击，currentTarget.dataset 取参数
  onItemTap(e) {
    const { id } = e.currentTarget.dataset;
    wx.navigateTo({ url: '/pages/detail/detail?goodsId=' + id });
  },

  // 自定义方法：被事件处理函数调用
  doSearch(keyword) {
    console.log('搜索关键词：', keyword);
    // 实际项目这里调用 wx.request 请求后台
  }
});
```

```text
页面方法要点：
1. 直接定义 —— 方法与生命周期平级写在 Page() 参数对象上，无 methods 包裹
2. currentTarget —— 取 data-* 参数用 e.currentTarget.dataset，勿用 target
3. e.detail —— 取组件事件数据（input 的 value、picker 的 index）
4. 互调 —— 方法内 this.方法名() 调用，this 指向页面实例
5. 命名 —— onXxx/handleXxx 做事件处理，避免与保留字冲突
6. 异步 this —— 回调内用箭头函数或 const that = this 保住 this
```

## 注册时机与启动流程

理解注册时机才能写出健壮的初始化逻辑。完整冷启动流程：用户打开小程序 → 微信下载/加载代码包 → 创建逻辑层（App Service）→ 执行 app.js 注册 App 实例 → 触发 onLaunch（拿启动参数、初始化全局数据）→ 创建第一个页面实例 → 页面 onLoad（拿路由参数）→ onShow → onReady 首帧渲染完成 → 用户开始交互。

关键时序结论：App() 先于任何 Page() 执行；onLaunch 在页面 onLoad 之前触发；onLaunch 里发起的异步请求不一定在页面 onLoad 时已完成——页面不能假设 globalData 一定就绪，要自己做兜底（见踩坑 1）。热启动（小程序已在后台，再次进入）不重新执行 onLaunch，只触发 App.onShow 与页面的 onShow。

页面实例的创建时机：每次 navigateTo/switchTab/reLaunch 进入页面时创建新实例，返回（navigateBack）时销毁；tabBar 页面首次切换时创建后常驻，不会因切 tab 销毁。页面栈最多 10 层，超出后 navigateTo 失败。运行时可用 `getCurrentPages()` 获取页面栈数组（最后一个是当前页），用于跨页面取数或页面栈诊断。

```js
// app.js —— 全局初始化
App({
  globalData: { bootTime: Date.now() },

  onLaunch(options) {
    console.log('1. App onLaunch，场景值', options.scene);
    // 恢复登录态（同步完成，页面 onLoad 可安全读取）
    const token = wx.getStorageSync('token') || '';
    this.globalData.token = token;
  },

  onShow() {
    console.log('2. App onShow（热启动也触发）');
  }
});
```

```js
// pages/index/index.js —— 页面侧启动流程
Page({
  data: { token: '' },

  onLoad(options) {
    console.log('3. Page onLoad');
    const app = getApp();
    // 同步初始化完成的全局数据可以直接读
    this.setData({ token: app.globalData.token });
  },

  onShow() {
    console.log('4. Page onShow');
  },

  onReady() {
    console.log('5. Page onReady，首帧渲染完成');
  }
});
```

```js
// 页面栈诊断：getCurrentPages 使用示例
function getPageStackInfo() {
  const pages = getCurrentPages();
  return {
    depth: pages.length,                       // 页面栈深度，最多 10
    current: pages[pages.length - 1].route,    // 当前页 route，如 pages/index/index
    all: pages.map((p) => p.route)
  };
}
```

```text
注册时机要点：
1. 顺序 —— App() 先于 Page()，onLaunch 先于页面 onLoad
2. 冷启动 —— 下载代码 -> 创建 App -> onLaunch -> 页面 onLoad/onShow/onReady
3. 热启动 —— 不重复 onLaunch，只触发 App.onShow 与页面 onShow
4. 实例 —— 每次进入页面创建新实例，navigateBack 销毁；tab 页切走不销毁
5. 页面栈 —— 最多 10 层，getCurrentPages() 获取栈数组做诊断
6. 兜底 —— onLaunch 的异步初始化结果页面不能假设就绪，需自行兜底
```

## 应用场景实战

### 场景一：全局登录态管理

登录态是全局数据的典型场景：App 启动恢复 token，页面按需拉取用户信息，登录成功后写回全局与 storage，退出登录时清理。所有页面统一从 globalData 读取，保证状态一致。

```js
// app.js
App({
  globalData: {
    token: '',
    userInfo: null
  },

  onLaunch() {
    // 同步恢复登录态，页面 onLoad 可安全读取
    this.globalData.token = wx.getStorageSync('token') || '';
    this.globalData.userInfo = wx.getStorageSync('userInfo') || null;
  },

  // 全局登录方法：页面与组件共用
  login(code) {
    return new Promise((resolve, reject) => {
      // 实际项目：wx.request 携带 code 请求后台 code2session 换 token
      setTimeout(() => {
        const token = 'token-' + Date.now();
        const userInfo = { nickname: '微信用户', avatar: '' };
        this.globalData.token = token;
        this.globalData.userInfo = userInfo;
        wx.setStorageSync('token', token);
        wx.setStorageSync('userInfo', userInfo);
        resolve(userInfo);
      }, 200);
    });
  },

  // 全局登出方法
  logout() {
    this.globalData.token = '';
    this.globalData.userInfo = null;
    wx.removeStorageSync('token');
    wx.removeStorageSync('userInfo');
  }
});
```

```js
// pages/mine/mine.js —— 页面使用全局登录态
const app = getApp();

Page({
  data: {
    userInfo: null,
    logged: false
  },

  onShow() {
    // 每次展示同步全局状态（onShow 而非 onLoad：登录返回后要刷新）
    this.syncUser();
  },

  syncUser() {
    const userInfo = app.globalData.userInfo;
    this.setData({
      userInfo,
      logged: !!userInfo
    });
  },

  async onLoginTap() {
    wx.showLoading({ title: '登录中' });
    try {
      // 实际项目：wx.login 获取 code 后调用 app.login(code)
      const userInfo = await app.login('mock-code');
      this.setData({ userInfo, logged: true });
      wx.showToast({ title: '登录成功' });
    } finally {
      wx.hideLoading();
    }
  },

  onLogoutTap() {
    app.logout();
    this.syncUser();
    wx.showToast({ title: '已退出', icon: 'none' });
  }
});
```

```xml
<!-- pages/mine/mine.wxml -->
<view class="page">
  <view class="user-card" wx:if="{{logged}}">
    <text>{{userInfo.nickname}}</text>
    <button size="mini" bindtap="onLogoutTap">退出登录</button>
  </view>
  <view class="user-card" wx:else>
    <text>未登录</text>
    <button size="mini" bindtap="onLoginTap">登录</button>
  </view>
</view>
```

### 场景二：购物车角标跨页面同步

购物车数量需要全局共享：加购页修改数量后，首页与「我的」页角标同步更新。globalData 存数量，页面 onShow 时同步到自己的 data，实现「全局数据 + 手动同步」的标准模式。

```js
// app.js
App({
  globalData: {
    cartCount: 0
  },

  // 全局加购方法：修改 globalData 并持久化
  addToCart(goodsId) {
    this.globalData.cartCount += 1;
    wx.setStorageSync('cartCount', this.globalData.cartCount);
    return this.globalData.cartCount;
  }
});
```

```js
// pages/goods/goods.js —— 商品页加购
const app = getApp();

Page({
  data: {
    goodsList: [
      { id: 1, title: '苹果', price: '9.90' },
      { id: 2, title: '香蕉', price: '5.90' }
    ]
  },

  onAddCart(e) {
    const { id } = e.currentTarget.dataset;
    const count = app.addToCart(id);
    // 同步回页面自身（本页可能也有角标）
    this.setData({ cartCount: count });
    wx.showToast({ title: '已加入购物车', icon: 'success' });
  }
});
```

## 最佳实践与踩坑记录

### 最佳实践

1. globalData 只放低频全局数据（token、用户信息、系统信息），高频变化数据放页面 data 或 storage
2. 登录态 storage 与 globalData 双写，App.onLaunch 同步恢复，页面 onShow 统一同步
3. 事件处理方法统一命名 handleXxx/onXxx，自定义方法用动词短语，避免与 data/生命周期名冲突
4. 嵌套数据用路径更新（'user.name'、'list[0].title'），减少 setData 传输量
5. 初始化逻辑放 onLaunch，页面数据获取放 onLoad，页面级状态刷新放 onShow
6. 公共逻辑（登录、请求封装、格式化）抽到 utils 模块，不要全部塞进 App
7. onUnload 中清理定时器、Worker、全局监听器，防止页面销毁后资源泄漏
8. 冷启动参数用 wx.getLaunchOptionsSync 读取，场景值用于渠道统计

### 踩坑记录

坑 1：onLaunch 异步请求未完成，页面 onLoad 里 globalData 为空
结论：页面加载时 getApp().globalData.token 是空字符串，接口 401。
原因：onLaunch 里发起的是异步请求，页面 onLoad 同步执行时请求还没返回。
解法：登录态用同步 API（getStorageSync）在 onLaunch 恢复；异步初始化结果用回调/Promise 通知页面，或页面 onLoad 自行兜底重新获取。

坑 2：App 中调用 wx.navigateTo 跳转失败
结论：onLaunch 里调 wx.navigateTo 报错或跳转无反应。
原因：App 级没有页面上下文，onLaunch 时页面栈尚未就绪，路由 API 不可用。
解法：跳转逻辑放页面生命周期；必须全局跳转的用 wx.reLaunch 并延迟（setTimeout）到页面就绪后执行。

坑 3：修改 globalData 后页面不更新
结论：登录后改了 globalData.userInfo，页面上还是显示未登录。
原因：globalData 是非响应式的，修改不会触发任何页面渲染。
解法：页面在 onShow 里主动同步 globalData 到 data 并 setData；或封装全局事件通知页面刷新。

坑 4：直接赋值 this.data.xxx 不生效
结论：this.data.list.push(item) 之后页面没有新数据。
原因：直接改 this.data 不会走 setData 通道，视图层收不到更新。
解法：所有修改必须 this.setData({ list: [...] })；需要先改数组再 setData 时，先拷贝再赋值。

坑 5：方法名与保留字冲突导致页面异常
结论：页面方法里定义了 data 或 setData 同名方法，调用时报错或行为怪异。
原因：Page() 参数对象会被框架解析，data/setData/onLoad 等是保留字段，覆盖后框架逻辑被破坏。
解法：自定义方法避免使用 data、setData、onLoad、onShow 等保留名；命名用 handleXxx 前缀。

坑 6：wx.request 回调里 this 指向丢失
结论：success 回调中 this.setData 报错「Cannot read property 'setData' of undefined」。
原因：普通 function 回调的 this 不是页面实例，而是调用上下文。
解法：回调用箭头函数；或 const that = this 保存引用；推荐用 Promise 封装（见 05.1 的 request 封装）。

坑 7：getApp() 返回 undefined
结论：某些时机调用 getApp() 拿到 undefined，访问 globalData 直接报错。
原因：在 app.js 的 App() 定义之前调用 getApp()，或在 App() 构造器内直接调用 getApp()，实例尚未创建完成。
解法：页面/组件中再调用 getApp()；App 内部用 this.globalData，不要调用 getApp()。

坑 8：页面栈超过 10 层 navigateTo 失败
结论：连续跳转十几次后，navigateTo 静默失败，页面停留原处。
原因：小程序页面栈上限 10 层，超出后路由 API 直接失败。
解法：多层跳转用 wx.redirectTo 替换当前页或 wx.reLaunch 重置栈；业务上避免深链导航。

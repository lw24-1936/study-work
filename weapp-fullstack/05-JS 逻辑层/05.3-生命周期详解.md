## 概述

生命周期是小程序运行时对「应用、页面、组件」从创建到销毁全过程的阶段划分，每个阶段对应一个回调函数，开发者在这些回调里完成初始化、数据加载、状态刷新与资源清理。理解生命周期是编写稳定小程序的前提：数据加载放错阶段会导致重复请求、白屏闪烁、内存泄漏等问题，而登录态刷新、页面参数解析、定时器清理等操作几乎都依赖生命周期时机。

```text
生命周期核心概念：
1. 三个层级 —— 应用（App）、页面（Page）、组件（Component），各自有独立生命周期回调
2. 阶段划分 —— 创建、显示、就绪、隐藏、销毁，不同阶段对应不同回调函数
3. 触发时机 —— 由用户操作与系统事件驱动（打开小程序、切换页面、切后台、返回、销毁）
4. 执行顺序 —— 应用先于页面、页面先于组件，首次进入与后续进入顺序不同
5. 参数传递 —— onLoad 接收页面跳转参数，onLaunch/onShow 接收启动场景参数
6. 数据加载 —— 按阶段选择合适的加载时机，避免重复请求与白屏
```

## 应用生命周期（App）

应用生命周期是整一个小程序实例的生命周期，回调注册在项目根目录的 app.js 中，通过 App() 构造器声明。App() 在小程序启动时执行一次，因此 onLaunch 是整个小程序最早执行的代码，适合做全局初始化；onShow/onHide 在前后台切换时触发，适合做登录态检查与全局状态刷新。

```js
// app.js
App({
  // 小程序初始化完成时触发，整个生命周期只执行一次
  onLaunch(options) {
    console.log('App.onLaunch', options)
    // options 常用字段：
    // path        —— 打开小程序的页面路径，如 pages/index/index
    // query       —— 打开小程序的 query 参数对象
    // scene       —— 打开小程序的场景值（1001 发现栏主入口、1011 扫描二维码等）
    // shareTicket —— 通过分享卡片打开时的票据，可换取群信息
    // referrerInfo —— 来源信息 { appId, extraData }，如从其他小程序跳转而来

    // 全局初始化：读取本地缓存中的登录态
    const token = wx.getStorageSync('token')
    this.globalData.token = token || ''
    this.globalData.userInfo = wx.getStorageSync('userInfo') || null
  },

  // 小程序从后台进入前台（或首次启动）时触发，每次进入都会执行
  onShow(options) {
    console.log('App.onShow', options)
    // 适合做：登录态过期检查、版本更新检查、数据同步
    this.checkSession()
  },

  // 小程序从前台进入后台时触发（按 Home 键、切到其他 App）
  onHide() {
    console.log('App.onHide')
    // 适合做：保存草稿、停止轮询、记录离开时间点
    this.globalData.lastHideTime = Date.now()
  },

  // 小程序发生 JS 脚本错误或 API 调用失败时触发
  onError(error) {
    console.error('App.onError', error)
    // 生产环境可上报错误到监控平台
    // wx.request({ url: 'https://api.example.com/log/error', data: { msg: String(error) } })
  },

  // 打开不存在的页面时触发，可做兜底跳转（基础库 2.3.0+）
  onPageNotFound(res) {
    console.warn('App.onPageNotFound', res)
    // res.path —— 访问不存在的页面路径
    // res.query —— 页面参数
    // res.isEntryPage —— 是否是小程序启动的第一个页面
    // 统一跳回首页，避免白屏
    wx.reLaunch({
      url: '/pages/index/index',
    })
  },

  // Promise 未被 catch 捕获时触发（基础库 2.10.0+）
  onUnhandledRejection(res) {
    console.error('App.onUnhandledRejection', res.reason)
  },

  globalData: {
    token: '',
    userInfo: null,
    lastHideTime: 0,
  },

  // 自定义方法：检查登录态是否过期
  checkSession() {
    const token = this.globalData.token
    if (!token) return
    const expireAt = wx.getStorageSync('tokenExpireAt') || 0
    if (Date.now() > expireAt) {
      // token 过期，清理登录态，跳转登录页
      this.globalData.token = ''
      wx.removeStorageSync('token')
      wx.removeStorageSync('userInfo')
    }
  },
})
```

```text
App 生命周期要点：
1. onLaunch —— 首次启动时执行一次，适合初始化全局数据、读取本地缓存
2. onShow —— 每次进入前台执行（含首次启动），适合登录态检查与数据同步
3. onHide —— 切入后台时执行，适合保存状态、停止高频任务
4. onError —— 全局错误捕获，生产环境应上报监控平台
5. onPageNotFound —— 页面不存在时兜底跳转，防止用户看到白屏
6. 注意 —— onLaunch 中 wx.request 等异步 API 在新版本可能延迟执行，关键数据优先用同步缓存
```

需要特别说明的是 getApp() 的用法：在 app.js 中通过 this.globalData 读写全局数据；在其他页面与组件中通过 getApp() 获取应用实例。getApp() 只能在 App() 注册完成之后调用，不要在 app.js 顶层或 App() 回调内部使用 getApp()，此时实例尚未创建完成，会得到 undefined。

## 页面生命周期（Page）

页面生命周期是每个页面从创建到销毁的过程，回调注册在 pages/xxx/xxx.js 中，通过 Page() 构造器声明。一个页面包含五个核心生命周期函数：onLoad、onShow、onReady、onHide、onUnload，其中 onLoad 与 onReady 只执行一次，onShow 与 onHide 可多次执行。

```js
// pages/detail/detail.js
Page({
  data: {
    id: '',
    detail: null,
    commentCount: 0,
  },

  // 页面加载时触发（首次创建），只执行一次
  // options 为页面跳转参数：navigateTo({ url: '/pages/detail/detail?id=1001' }) 时 options.id === '1001'
  onLoad(options) {
    console.log('Page.onLoad', options)
    this.setData({ id: options.id || '' })
    // 首次数据加载放在这里，因为能拿到路由参数
    this.fetchDetail(options.id)
  },

  // 页面显示时触发，每次页面出现在屏幕上都会执行（含首次进入、从后台回来、从其他页面返回）
  onShow() {
    console.log('Page.onShow')
    // 适合做：从详情页返回时刷新列表状态、从后台回前台刷新数据
    this.refreshCommentCount()
  },

  // 页面初次渲染完成时触发，只执行一次
  // 此时可以安全使用 wx.createSelectorQuery 等节点查询 API
  onReady() {
    console.log('Page.onReady')
    this.setNavBarTitle()
  },

  // 页面隐藏时触发（跳转到其他页面、小程序切后台、打开半屏弹窗）
  onHide() {
    console.log('Page.onHide')
    // 清理定时器、停止动画
    if (this.timer) {
      clearInterval(this.timer)
      this.timer = null
    }
  },

  // 页面卸载时触发（navigateBack 返回、redirectTo 重定向、页面被销毁）
  onUnload() {
    console.log('Page.onUnload')
    // 最后的清理机会：解绑事件、关闭 WebSocket、取消未完成的请求
  },

  fetchDetail(id) {
    // 模拟请求
    this.setData({ detail: { id, name: '示例商品' } })
  },

  refreshCommentCount() {
    this.setData({ commentCount: Math.floor(Math.random() * 100) })
  },

  setNavBarTitle() {
    wx.setNavigationBarTitle({ title: '商品详情' })
  },
})
```

除了五个核心生命周期，Page 还支持一组页面事件处理函数，它们在特定交互时机被触发，也常被归入生命周期范畴：

```js
// pages/list/list.js
Page({
  data: {
    list: [],
    page: 1,
    hasMore: true,
    scrollTop: 0,
  },

  // 下拉刷新：需要先在页面配置中开启 enablePullDownRefresh: true
  onPullDownRefresh() {
    console.log('onPullDownRefresh')
    this.setData({ page: 1, hasMore: true })
    this.fetchList(1, () => {
      wx.stopPullDownRefresh() // 数据加载完成后手动停止刷新动画
    })
  },

  // 上拉触底：滚动到页面底部时触发，适合加载更多
  onReachBottom() {
    console.log('onReachBottom')
    if (this.data.hasMore) {
      this.fetchList(this.data.page + 1)
    }
  },

  // 用户点击右上角菜单「转发」时触发，返回自定义分享内容
  onShareAppMessage() {
    return {
      title: '快来查看商品列表',
      path: '/pages/list/list',
      imageUrl: '/assets/share.png',
    }
  },

  // 用户点击右上角菜单「分享到朋友圈」时触发（基础库 2.11.3+）
  onShareTimeline() {
    return {
      title: '商品列表',
      query: 'from=timeline',
    }
  },

  // 页面滚动时触发，scrollTop 为纵向滚动距离
  onPageScroll(e) {
    // 滚动超过 300px 时显示「回到顶部」按钮
    this.setData({ showBackTop: e.scrollTop > 300 })
  },

  // 页面尺寸变化时触发（如横竖屏切换、iPad 分屏）
  onResize(e) {
    console.log('onResize', e.size)
  },

  // 点击 tabBar 某一项时触发
  onTabItemTap(item) {
    console.log('onTabItemTap', item)
  },

  fetchList(page, done) {
    // 模拟分页请求
    const list = this.data.list.concat([`item-${page}-1`, `item-${page}-2`])
    this.setData({ list, page, hasMore: page < 3 })
    if (done) done()
  },
})
```

```text
Page 生命周期与事件要点：
1. onLoad —— 首次加载，接收路由参数，适合首次数据请求
2. onShow —— 每次显示都触发，适合「返回后刷新」类需求
3. onReady —— 首次渲染完成，之后才能做节点查询
4. onHide/onUnload —— 隐藏与销毁，负责停止任务与释放资源
5. 页面事件 —— 下拉刷新、触底加载、分享、滚动、尺寸变化等均有独立回调
6. 注意 —— onShow 可能先于 onReady 执行，节点相关操作不能放在 onShow
```

## 组件生命周期（Component）

自定义组件（Component 构造器）拥有独立于页面的生命周期。官方推荐使用 lifetimes 字段声明组件生命周期，它包含 created、attached、ready、moved、detached 五个阶段；pageLifetimes 字段用于监听组件所在页面的生命周期事件（show、hide、resize）。

```js
// components/card/card.js
Component({
  properties: {
    title: { type: String, value: '' },
    count: { type: Number, value: 0 },
  },

  data: {
    isReady: false,
  },

  lifetimes: {
    // 组件实例被创建时触发，此时不能调用 setData，也不能访问节点
    created() {
      console.log('component created')
      // 只能做纯数据初始化：记录创建时间等
      this._createdAt = Date.now()
    },

    // 组件实例进入页面节点树时触发，可以调用 setData 了
    attached() {
      console.log('component attached')
      this.setData({ isReady: true })
      // 注意：此时节点尚未完成布局，createSelectorQuery 查询要在 ready 之后
    },

    // 组件布局完成后触发，可以做节点查询、绑定事件
    ready() {
      console.log('component ready')
      const query = this.createSelectorQuery()
      query.select('.card').boundingClientRect((rect) => {
        console.log('card rect', rect)
      }).exec()
    },

    // 组件被移动（从节点树一个位置移到另一个位置）时触发
    moved() {
      console.log('component moved')
    },

    // 组件从页面节点树移除时触发，做资源清理
    detached() {
      console.log('component detached')
      if (this._timer) {
        clearInterval(this._timer)
      }
    },

    // 组件方法报错时触发（基础库 2.4.1+）
    error(err) {
      console.error('component error', err)
    },
  },

  pageLifetimes: {
    // 组件所在页面显示时触发
    show() {
      console.log('page show -> component show')
    },
    // 组件所在页面隐藏时触发
    hide() {
      console.log('page hide -> component hide')
    },
    // 组件所在页面尺寸变化时触发
    resize(size) {
      console.log('page resize', size)
    },
  },

  methods: {
    onTap() {
      this.triggerEvent('cardtap', { id: this.properties.title })
    },
  },
})
```

```text
Component 生命周期要点：
1. created —— 实例创建，不能 setData、不能查节点，只做内部变量初始化
2. attached —— 进入节点树，可 setData，但节点查询需等 ready
3. ready —— 布局完成，可执行 createSelectorQuery 节点查询
4. moved/detached —— 被移动与移除，detached 必须清理定时器与监听
5. pageLifetimes —— show/hide/resize 监听所在页面，替代旧版 pageLifetimes 写法
6. 旧写法 —— 直接写在 Component 顶层（attached() {}）在基础库 2.2.3 后不推荐，优先用 lifetimes
```

组件生命周期与页面生命周期的关系是嵌套的：页面渲染时挂载其内部的组件，因此组件的 created/attached 会发生在页面初次渲染过程中；页面销毁时组件随之 detached。理解这一嵌套关系是排查「组件拿不到数据」「页面隐藏组件还在跑」等问题的关键。

## 生命周期执行顺序

首次进入小程序的完整执行顺序是固定的，理解它才能确定「在哪一步做什么」。以「冷启动直接打开 pages/index/index」为例：

```text
首次冷启动完整顺序：
1. App.onLaunch  —— 应用实例创建，全局初始化
2. App.onShow    —— 应用进入前台
3. Page.onLoad   —— 首页创建，接收启动参数（scene 等场景信息在 App 层）
4. Page.onShow   —— 首页显示
5. （页面渲染，挂载内部组件：Component.created -> Component.attached）
6. Page.onReady  —— 首页首次渲染完成
7. （组件布局完成：Component.ready）
```

用 console.log 实际打印的顺序（以基础库 2.x 为准）：

```text
控制台输出顺序：
[App] onLaunch
[App] onShow
[Page] onLoad
[Page] onShow
[Component] created
[Component] attached
[Page] onReady
[Component] ready
```

页面跳转与返回时的顺序：

```text
A 页面 navigateTo 到 B 页面：
1. A.onHide       —— A 被覆盖隐藏
2. B.onLoad       —— B 创建
3. B.onShow       —— B 显示
4. B.onReady      —— B 渲染完成
（A 保留在页面栈中，不触发 onUnload）

B 页面 navigateBack 返回 A：
1. B.onUnload     —— B 出栈销毁
2. A.onShow       —— A 重新显示（A 的 onLoad/onReady 不会再次触发）
```

切后台与回前台：

```text
按 Home 键切后台：
1. Page.onHide    —— 当前页面隐藏（每个在栈中的页面都会触发 onHide）
2. App.onHide     —— 应用进入后台

从后台回前台：
1. App.onShow     —— 应用回到前台
2. Page.onShow    —— 当前页面重新显示（页面栈中所有页面触发 onShow）
```

```text
执行顺序要点：
1. 首次进入 —— App.onLaunch -> App.onShow -> Page.onLoad -> onShow -> onReady
2. 组件介入 —— 组件 created/attached 在页面渲染过程中，早于 Page.onReady
3. 页面返回 —— 返回只触发 onUnload + 前页 onShow，前页不重新 onLoad
4. 前后台 —— 切后台先页面 onHide 再 App.onHide；回前台先 App.onShow 再页面 onShow
5. tab 切换 —— 每个 tab 页首次进入走完整生命周期，再次切换只触发 onShow/onHide
6. 冷热启动 —— 冷启动（被销毁后重新打开）走完整流程；热启动（后台 5 分钟内回前台）只触发 onShow
```

这里有一个高频考点：navigateTo 最多只能打开 10 层页面栈，超过后 navigateTo 会失败；此时应使用 redirectTo（替换当前页）或 reLaunch（重开）。页面栈深度也直接影响 onUnload 的触发时机——只有出栈的页面才会 onUnload。

## 生命周期与数据加载

数据加载是生命周期最典型的应用场景。核心原则：首次数据在 onLoad 加载（能拿到路由参数），返回刷新类数据在 onShow 加载，滚动加载与下拉刷新用页面事件，销毁时清理未完成的异步任务。

典型的电商商品详情页数据加载模式：

```js
// pages/product/product.js
Page({
  data: {
    id: '',
    product: null,
    loading: true,
    error: '',
    comments: [],
  },

  onLoad(options) {
    // 首次进入：解析路由参数，加载商品主数据
    this.setData({ id: options.id })
    this.loadProduct(options.id)
  },

  onShow() {
    // 每次显示：刷新可能变化的数据（如库存、已购状态）
    // 用标志位避免与 onLoad 的首次加载重复
    if (this.data.product) {
      this.loadStock(this.data.id)
    }
  },

  onReady() {
    // 渲染完成后：记录曝光埋点
    this.reportExpose()
  },

  onUnload() {
    // 离开页面：取消进行中的请求标记，避免 setData 报错
    this._unloaded = true
    if (this._requestTask) {
      this._requestTask.abort()
    }
  },

  loadProduct(id) {
    this.setData({ loading: true, error: '' })
    // 用 wx.request 返回的 RequestTask 保存引用，便于 onUnload 中 abort
    this._requestTask = wx.request({
      url: 'https://api.example.com/product/detail',
      data: { id },
      success: (res) => {
        if (this._unloaded) return // 页面已销毁，放弃 setData
        this.setData({ product: res.data.data, loading: false })
      },
      fail: () => {
        if (this._unloaded) return
        this.setData({ error: '加载失败，请重试', loading: false })
      },
    })
  },

  loadStock(id) {
    // 轻量请求：只刷新库存等变化数据
  },

  reportExpose() {
    // 埋点上报
  },

  // 下拉刷新：重新拉取主数据
  onPullDownRefresh() {
    this.loadProduct(this.data.id)
    setTimeout(() => wx.stopPullDownRefresh(), 300)
  },
})
```

```text
生命周期与数据加载要点：
1. 首次数据 —— 放 onLoad，可拿到路由参数，且只执行一次
2. 返回刷新 —— 放 onShow，配合标志位避免重复请求
3. 滚动加载 —— onReachBottom 触底分页，注意 hasMore 判断
4. 下拉刷新 —— onPullDownRefresh + 页面配置 enablePullDownRefresh
5. 异步安全 —— onUnload 标记销毁状态，回调里先判断再 setData
6. 请求取消 —— 保存 RequestTask 引用，onUnload 时 abort，防止请求泄漏
```

## 应用场景实战

### 场景一：电商商品详情页的生命周期管理

完整实现一个包含「首次加载、返回刷新、下拉刷新、销毁清理」的商品详情页：

```js
// pages/product/product.js
const request = require('../../utils/request')

Page({
  data: {
    id: '',
    product: null,
    loading: true,
    error: '',
    isFavorite: false,
    countdown: '',
  },

  onLoad(options) {
    // 步骤 1：解析参数
    this.setData({ id: options.id })
    // 步骤 2：首次加载商品详情
    this.fetchProduct(options.id)
    // 步骤 3：启动秒杀倒计时定时器
    this.startCountdown(3600)
  },

  onShow() {
    // 从购买页返回时刷新库存与收藏状态
    if (this.data.product) {
      this.fetchStock(this.data.id)
    }
  },

  onUnload() {
    // 清理定时器，防止页面销毁后定时器继续执行
    if (this._countdownTimer) {
      clearInterval(this._countdownTimer)
    }
    // 标记已销毁，异步回调中不再 setData
    this._destroyed = true
  },

  onPullDownRefresh() {
    this.fetchProduct(this.data.id, () => wx.stopPullDownRefresh())
  },

  onShareAppMessage() {
    return {
      title: this.data.product ? this.data.product.name : '商品详情',
      path: `/pages/product/product?id=${this.data.id}`,
    }
  },

  fetchProduct(id, done) {
    this.setData({ loading: true, error: '' })
    request.get('/product/detail', { id }).then((res) => {
      if (this._destroyed) return
      this.setData({ product: res, loading: false, isFavorite: res.isFavorite })
      if (done) done()
    }).catch(() => {
      if (this._destroyed) return
      this.setData({ loading: false, error: '网络异常，请重试' })
      if (done) done()
    })
  },

  fetchStock(id) {
    request.get('/product/stock', { id }).then((res) => {
      if (this._destroyed || !this.data.product) return
      this.setData({ 'product.stock': res.stock })
    })
  },

  startCountdown(totalSeconds) {
    const update = () => {
      const h = String(Math.floor(totalSeconds / 3600)).padStart(2, '0')
      const m = String(Math.floor((totalSeconds % 3600) / 60)).padStart(2, '0')
      const s = String(totalSeconds % 60).padStart(2, '0')
      this.setData({ countdown: `${h}:${m}:${s}` })
      totalSeconds -= 1
    }
    update()
    this._countdownTimer = setInterval(update, 1000)
  },
})
```

### 场景二：应用级全局初始化与登录守卫

在 app.js 中完成全局初始化，并在需要登录的页面做登录守卫：

```js
// app.js
App({
  onLaunch() {
    // 1. 读取本地登录态
    const token = wx.getStorageSync('token')
    this.globalData.token = token
    // 2. 静默登录：无 token 时用 wx.login 换 code，交给后台换 session
    if (!token) {
      this.silentLogin()
    }
    // 3. 检查更新（小程序版本升级提示）
    this.checkUpdate()
  },

  onShow() {
    // 回到前台时刷新登录态（token 可能在后台被清除）
    const token = wx.getStorageSync('token')
    if (token !== this.globalData.token) {
      this.globalData.token = token
    }
  },

  onPageNotFound(res) {
    wx.reLaunch({ url: '/pages/index/index' })
  },

  onError(err) {
    // 上报到监控服务
    console.error('global error:', err)
  },

  silentLogin() {
    wx.login({
      success: (res) => {
        // res.code 传给 SpringBoot 后台，换取 openid + token
        wx.request({
          url: 'https://api.example.com/auth/login',
          method: 'POST',
          data: { code: res.code },
          success: (loginRes) => {
            const data = loginRes.data.data
            wx.setStorageSync('token', data.token)
            wx.setStorageSync('tokenExpireAt', Date.now() + data.expiresIn * 1000)
            this.globalData.token = data.token
          },
        })
      },
    })
  },

  checkUpdate() {
    if (!wx.canIUse('getUpdateManager')) return
    const updateManager = wx.getUpdateManager()
    updateManager.onUpdateReady(() => {
      wx.showModal({
        title: '更新提示',
        content: '新版本已经准备好，是否重启应用？',
        success: (res) => {
          if (res.confirm) {
            updateManager.applyUpdate()
          }
        },
      })
    })
  },

  globalData: {
    token: '',
  },
})
```

## 最佳实践与踩坑记录

### 最佳实践

1. 首次数据请求放在 onLoad：它能拿到路由参数且只执行一次，是「详情页、列表页首次加载」的标准位置
2. 返回刷新放在 onShow：从二级页返回、从后台回前台需要刷新数据时用 onShow，但要用标志位避免与 onLoad 重复请求
3. 节点操作放在 onReady 之后：wx.createSelectorQuery、组件内 this.createSelectorQuery 必须等渲染完成，否则查询结果为空
4. 资源清理集中在 onUnload/detached：定时器、WebSocket、监听器、RequestTask 统一在销毁回调中清理，防止内存泄漏
5. 异步回调先判断销毁状态：页面卸载后 setData 会告警且浪费性能，回调开头用 this._destroyed 之类的标志位拦截
6. 全局初始化只放必要内容：onLaunch 中避免大量同步阻塞操作，wx.request 等异步 API 在新版本中可能延迟执行，关键数据用 wx.getStorageSync 同步读取
7. onPageNotFound 必须兜底：正式项目配置统一跳首页，避免用户访问失效分享链接时白屏
8. 埋点与统计放到对应生命周期：曝光埋点放 onReady/onShow（去重），离开埋点放 onHide/onUnload

### 踩坑记录

```text
坑 1：onShow 里做节点查询拿不到节点
结论：onShow 触发时页面可能尚未完成首次渲染，createSelectorQuery 查询结果为空。
原因：首次进入时 onShow 早于 onReady 执行，节点还未渲染完成。
解法：节点查询统一放在 onReady 或 onShow 中加 wx.nextTick 包裹，确认渲染完成后再查询。

坑 2：页面返回后数据不刷新
结论：从详情页返回列表页，列表数据没有更新。
原因：返回时列表页只触发 onShow，不触发 onLoad，开发者把刷新逻辑只写在了 onLoad。
解法：把「返回后需要刷新」的数据请求放到 onShow，并用标志位避免首次进入时与 onLoad 重复请求。

坑 3：定时器导致页面销毁后仍执行 setData
结论：页面已 navigateBack 销毁，定时器回调仍在执行，控制台报「setData:fail」警告，且浪费性能。
原因：定时器在 onUnload 中没有被清理。
解法：onLoad/onReady 中启动的定时器统一在 onUnload 中 clearInterval/clearTimeout；组件定时器在 detached 中清理。

坑 4：冷启动分享链接打开后找不到页面
结论：用户从失效的分享卡片进入，小程序提示「页面不存在」或白屏。
原因：分享的页面路径已不存在或已改名，未配置兜底处理。
解法：App 中配置 onPageNotFound，统一 wx.reLaunch 到首页；分享路径使用稳定页面并做好版本兼容。

坑 5：navigateTo 超过 10 层页面栈导致跳转失败
结论：连续跳转 10 次以上，navigateTo 静默失败，页面无反应。
原因：小程序页面栈上限为 10 层。
解法：深层跳转改用 redirectTo 或 reLaunch；用 getCurrentPages().length 检查栈深度后决定跳转方式。

坑 6：onLaunch 中请求登录接口，页面 onLoad 拿不到登录态
结论：页面 onLoad 里判断 token 为空，但 App.onLaunch 中的静默登录尚未完成。
原因：onLaunch 的异步请求晚于页面 onLoad 执行完成，两者是并行关系而非顺序关系。
解法：登录流程用 Promise 封装并存入 App.globalData.loginPromise，页面在 onShow 中 await 该 Promise 后再取登录态。

坑 7：tabBar 页面切后台再回来，onShow 被多次触发
结论：切换 tab 与前后台切换都会触发 onShow，导致接口重复请求。
原因：onShow 的触发来源多样（首次进入、tab 切换、后台回前台、页面返回）。
解法：用时间戳或数据版本号做节流，例如 500ms 内的重复 onShow 只请求一次。

坑 8：组件 attached 中查节点结果为空
结论：组件在 attached 中执行 this.createSelectorQuery 查询，返回 null。
原因：attached 时组件刚进入节点树，布局尚未完成。
解法：节点查询放到组件 ready 生命周期中执行。
```

## 概述

小程序逻辑层（JS）运行在独立的 JS 引擎中，代码按「模块」组织：每个 .js 文件就是一个模块，通过 CommonJS 规范（module.exports / require）或 ES6 模块语法（import / export）在模块间共享代码。良好的模块化设计把公共逻辑（请求封装、日期格式化、防抖节流、常量配置）从页面中抽离，是代码可维护、可测试、可复用的基础。

```text
模块化核心概念：
1. 文件即模块 —— 每个 .js 文件独立作用域，通过导出/导入共享
2. 双规范 —— CommonJS（module.exports/require）与 ES6（import/export）均受支持
3. 相对路径 —— require 必须使用相对路径（./ 或 ../），不支持绝对路径导入本地文件
4. 缓存机制 —— 模块首次 require 后缓存，多次引用返回同一实例（单例）
5. 分包隔离 —— 主包与分包、分包与分包之间存在代码引用限制
6. 目录约定 —— utils/、config/、constants/ 等目录承担不同职责
```

## CommonJS：module.exports 与 require

CommonJS 是小程序最早的模块规范，也是官方文档的主推写法。每个模块通过 module.exports 导出接口，其他模块通过 require('相对路径') 引入。require 支持 .js 与 .json 文件（.json 会被解析为对象），路径必须相对当前文件，且可以省略 .js 后缀。

```js
// utils/format.js —— 被导出的工具模块
function padZero(num) {
  return num < 10 ? '0' + num : '' + num
}

function formatDate(date, separator) {
  separator = separator || '-'
  const y = date.getFullYear()
  const m = padZero(date.getMonth() + 1)
  const d = padZero(date.getDate())
  return y + separator + m + separator + d
}

// 方式一：module.exports 导出整个对象
module.exports = {
  formatDate: formatDate,
  padZero: padZero,
}
```

```js
// pages/list/list.js —— 使用 require 引入
const format = require('../../utils/format')

Page({
  data: {
    today: '',
  },
  onLoad() {
    this.setData({
      today: format.formatDate(new Date()),
    })
  },
})
```

exports 是 module.exports 的别名引用，两种导出方式可以混用，但要注意它们指向同一个对象：

```js
// utils/math.js
exports.add = function (a, b) {
  return a + b
}
exports.sub = function (a, b) {
  return a - b
}
// 等价于 module.exports = { add, sub }，但不能直接给 exports 重新赋值：
// exports = { ... } 会断开与 module.exports 的引用，导致导出为空对象
```

```js
// app.js 中引用
const math = require('./utils/math')
console.log(math.add(1, 2)) // 3
```

require 的模块具有缓存特性：同一个模块第一次 require 时执行并缓存，之后再次 require 直接返回缓存对象。这意味着模块顶层代码只执行一次，模块内保存的状态（如请求实例、配置对象）是全局共享的，这也是「单例」的实现基础。

```text
CommonJS 要点：
1. module.exports —— 导出模块接口，支持对象、函数、类等任意值
2. exports —— 是 module.exports 的引用别名，直接赋值 exports = {} 会失效
3. require 路径 —— 必须相对路径（./ 或 ../），可省略 .js 后缀
4. 缓存 —— 模块只执行一次，多次 require 返回同一对象，天然单例
5. 循环引用 —— 模块 A 引用 B、B 又引用 A 时，先加载方拿到的是不完整导出，应避免
6. require 位置 —— 可写在代码任意位置（函数内动态 require 也合法，但不推荐）
```

## ES6 import/export 与混用

微信开发者工具默认开启「增强编译」，支持将 ES6 语法转译为 ES5，因此可以直接使用 import/export 编写模块。ES6 模块是静态语法：import 必须写在文件顶层，导出名在编译期确定，因此比 CommonJS 更适合静态分析和 tree-shaking（去除未使用的代码）。

```js
// utils/request.js —— 使用 export 导出
export function get(url, data) {
  return request('GET', url, data)
}

export function post(url, data) {
  return request('POST', url, data)
}

function request(method, url, data) {
  return new Promise((resolve, reject) => {
    wx.request({
      url,
      method,
      data,
      success: (res) => resolve(res.data),
      fail: reject,
    })
  })
}

export default request
```

```js
// pages/index/index.js —— 使用 import 引入
import request, { get, post } from '../../utils/request'

Page({
  onLoad() {
    get('/banner').then((res) => {
      console.log(res)
    })
  },
})
```

ES6 模块的几种导入导出形式：

```js
// utils/const.js
export const APP_NAME = '示例商城'          // 命名导出：常量
export const VERSION = '1.0.0'
const MAX_PAGE = 10                          // 未导出的成员，模块外部不可见
export default { APP_NAME, VERSION }         // 默认导出：整个对象

// 使用端
import config from '../../utils/const'       // 默认导出，名称可自定义
import { APP_NAME, VERSION } from '../../utils/const'  // 命名导出，名称必须一致
import * as all from '../../utils/const'     // 命名空间导入
import { APP_NAME as Name } from '../../utils/const'   // 重命名
```

```text
ES6 模块要点：
1. 静态导入 —— import 必须位于文件顶层，不能在函数或条件语句中
2. 默认导出 —— export default 每文件一个，导入时名称可自定义
3. 命名导出 —— export const/function，导入时名称必须与导出名一致，可用 as 重命名
4. 命名空间 —— import * as xxx 一次导入全部命名导出
5. 混用注意 —— 同一文件不要混用 module.exports 与 export default，行为容易混乱
6. npm 支持 —— 工具菜单「构建 npm」后可通过 import 引入第三方包（miniprogram_npm 目录）
```

开发团队通常会统一规范：新代码统一使用 ES6 语法（import/export + async/await），因为开发者工具会自动转译且生态兼容性最好；第三方 npm 包经「构建 npm」后同样用 import 引入。注意 async/await 也依赖增强编译，旧基础库（1.x）不支持。

## 分包公共代码与引用规则

当小程序超过主包 2MB 限制时，需要启用分包（subpackages）。分包与模块化直接相关的是代码引用规则：主包与分包、分包与分包之间不能随意 require，违反规则会在编译时报错或运行失败。

```text
分包引用规则：
1. 主包可以引用主包 —— 任意主包模块之间可以互相 require
2. 分包可以引用主包 —— 分包内的代码可以 require 主包中的公共模块
3. 主包不能引用分包 —— 主包代码 require 分包文件会报错（分包未加载）
4. 分包之间不能互相引用 —— 不同分包之间 require 不被允许
5. 独立分包 —— 不依赖主包运行，不能 require 主包代码（反之可以）
6. 分包异步化 —— 基础库 2.23.0+ 可用 require.async 异步加载其他分包模块
```

因此公共代码（请求封装、工具函数、常量）必须放在主包目录（如根目录 utils/、libs/），供所有分包引用。示例目录结构：

```text
项目目录结构（含分包）：
miniprogram/
├── app.js / app.json / app.wxss
├── utils/                  # 公共代码：必须放主包
│   ├── request.js          # 请求封装
│   ├── format.js           # 格式化工具
│   └── auth.js             # 登录态工具
├── pages/                  # 主包页面
│   ├── index/
│   └── ...
└── packageA/               # 分包 A（app.json subpackages 中声明）
    ├── pages/
    │   └── activity/
    └── components/
```

```json
// app.json —— 分包声明
{
  "pages": ["pages/index/index", "pages/user/user"],
  "subpackages": [
    {
      "root": "packageA",
      "name": "activity",
      "pages": ["pages/activity/activity"]
    }
  ]
}
```

```js
// packageA/pages/activity/activity.js —— 分包内引用主包公共模块（合法）
const request = require('../../../utils/request')
const { formatPrice } = require('../../../utils/format')

Page({
  onLoad() {
    request.get('/activity/info').then((res) => {
      console.log(formatPrice(res.price))
    })
  },
})
```

分包异步化（require.async）可以突破「主包不能引用分包」的限制，用于按需加载：

```js
// pages/index/index.js —— 主包页面异步加载分包模块（基础库 2.23.0+）
Page({
  onLoad() {
    // 需要时再加载分包 A 中的模块，不会增加主包体积
    require.async('../packageA/utils/ad.js').then((mod) => {
      console.log(mod.showAd())
    })
  },
})
```

```text
分包公共代码要点：
1. 公共代码放主包 —— utils/、components/ 等公共资源必须位于主包
2. 单向依赖 —— 分包 → 主包合法，主包 → 分包、分包 → 分包不合法
3. 独立分包 —— 完全独立，不能 require 主包，适合活动页、营销页
4. 体积预算 —— 主包 ≤ 2MB、单个分包 ≤ 2MB、整个小程序 ≤ 20MB
5. 按需加载 —— require.async 实现分包模块异步化，兼顾体积与加载速度
6. 公共组件同理 —— 公共自定义组件放主包，分包通过绝对路径引用
```

## 工具函数组织（utils 目录）

utils/ 目录是小程序工程中最常见的公共代码目录，存放与页面无关的纯函数工具：格式化、防抖节流、请求封装、存储封装等。组织原则：纯函数、无副作用、不依赖页面上下文、单一职责，便于单元测试与多页面复用。

```js
// utils/format.js —— 格式化工具集合
function padZero(num) {
  return num < 10 ? '0' + num : '' + num
}

// 时间戳转 yyyy-MM-dd HH:mm:ss
function formatDateTime(timestamp) {
  const date = new Date(timestamp)
  const y = date.getFullYear()
  const m = padZero(date.getMonth() + 1)
  const d = padZero(date.getDate())
  const h = padZero(date.getHours())
  const min = padZero(date.getMinutes())
  const s = padZero(date.getSeconds())
  return y + '-' + m + '-' + d + ' ' + h + ':' + min + ':' + s
}

// 相对时间：刚刚 / n 分钟前 / n 小时前 / 昨天 / 日期
function timeAgo(timestamp) {
  const diff = Date.now() - timestamp
  const minute = 60 * 1000
  const hour = 60 * minute
  const day = 24 * hour
  if (diff < minute) return '刚刚'
  if (diff < hour) return Math.floor(diff / minute) + ' 分钟前'
  if (diff < day) return Math.floor(diff / hour) + ' 小时前'
  if (diff < 2 * day) return '昨天'
  return formatDateTime(timestamp).slice(0, 10)
}

// 手机号脱敏：138****8000
function maskPhone(phone) {
  return phone.replace(/^(\d{3})\d{4}(\d{4})$/, '$1****$2')
}

// 价格格式化：分转元并保留两位小数
function formatPrice(cents) {
  return (cents / 100).toFixed(2)
}

module.exports = {
  formatDateTime,
  timeAgo,
  maskPhone,
  formatPrice,
}
```

```js
// utils/debounce.js —— 防抖与节流
// 防抖：连续触发时只执行最后一次（适合搜索输入、resize）
function debounce(fn, wait) {
  let timer = null
  return function (...args) {
    if (timer) clearTimeout(timer)
    timer = setTimeout(() => {
      fn.apply(this, args)
    }, wait)
  }
}

// 节流：固定时间间隔内最多执行一次（适合滚动、点击）
function throttle(fn, interval) {
  let last = 0
  return function (...args) {
    const now = Date.now()
    if (now - last >= interval) {
      last = now
      fn.apply(this, args)
    }
  }
}

module.exports = { debounce, throttle }
```

```js
// utils/request.js —— 请求封装（Promise + 统一拦截）
const BASE_URL = 'https://api.example.com'

function request(options) {
  return new Promise((resolve, reject) => {
    const token = wx.getStorageSync('token')
    wx.request({
      url: BASE_URL + options.url,
      method: options.method || 'GET',
      data: options.data || {},
      header: {
        'Content-Type': 'application/json',
        Authorization: token ? 'Bearer ' + token : '',
      },
      success: (res) => {
        const body = res.data
        if (body.code === 0) {
          resolve(body.data)
        } else if (body.code === 401) {
          // 登录过期：清 token 跳登录页
          wx.removeStorageSync('token')
          wx.navigateTo({ url: '/pages/login/login' })
          reject(new Error('未登录'))
        } else {
          wx.showToast({ title: body.msg || '请求失败', icon: 'none' })
          reject(new Error(body.msg))
        }
      },
      fail: (err) => {
        wx.showToast({ title: '网络异常', icon: 'none' })
        reject(err)
      },
    })
  })
}

module.exports = {
  get(url, data) {
    return request({ url, method: 'GET', data })
  },
  post(url, data) {
    return request({ url, method: 'POST', data })
  },
}
```

```js
// utils/storage.js —— 存储封装（带过期时间）
function set(key, value, expireMs) {
  const data = {
    value: value,
    expireAt: expireMs ? Date.now() + expireMs : 0,
  }
  wx.setStorageSync(key, data)
}

function get(key) {
  const data = wx.getStorageSync(key)
  if (!data) return null
  if (data.expireAt && Date.now() > data.expireAt) {
    wx.removeStorageSync(key)
    return null
  }
  return data.value
}

module.exports = { set, get }
```

```text
utils 目录组织要点：
1. 纯函数优先 —— 不依赖页面与 this，输入输出确定，方便单测与复用
2. 按职责拆文件 —— format.js / debounce.js / request.js / storage.js 各管一事
3. 请求封装 —— 统一 baseUrl、token 注入、错误码处理、401 拦截跳登录
4. 存储封装 —— 统一序列化并支持过期时间，避免散落 wx.setStorageSync 调用
5. 防抖节流 —— 搜索、滚动等高频场景必备，实现要支持 this 绑定
6. 命名 —— 文件小驼峰（formatDate.js），导出方法动词开头（getXxx/setXxx/formatXxx）
```

## 常量、配置与命名规范

常量与配置集中管理可以避免「魔法数字」散落各页面。常见的组织方式：config/ 放环境相关配置（接口域名、AppID、开关），constants/ 放业务枚举（订单状态、支付方式），两者都可以被页面与工具模块引用。

```js
// config/index.js —— 环境配置
const ENV = 'prod' // dev / test / prod

const CONFIG = {
  dev: {
    baseUrl: 'https://dev-api.example.com',
    debug: true,
  },
  test: {
    baseUrl: 'https://test-api.example.com',
    debug: true,
  },
  prod: {
    baseUrl: 'https://api.example.com',
    debug: false,
  },
}

module.exports = {
  baseUrl: CONFIG[ENV].baseUrl,
  debug: CONFIG[ENV].debug,
  appId: 'wx1234567890abcdef',
  version: '1.0.0',
}
```

```js
// constants/order.js —— 业务枚举常量
```

命名规范方面，业内比较通用的约定如下：

```text
命名规范建议：
1. 文件命名 —— 页面与组件目录小驼峰（pages/orderDetail/），公共 js 小驼峰（format.js）
2. 变量 —— 小驼峰（userName），布尔值用 is/has/can 前缀（isLoading）
3. 常量 —— 全大写加下划线（MAX_PAGE_SIZE、ORDER_STATUS.PAID）
4. 方法 —— 动词开头（getUserList/handleTap/setData 相关用 setXxx）
5. 私有成员 —— 下划线前缀约定（this._timer），仅内部使用
6. data 字段 —— 与渲染相关的小驼峰（list/loading/error），避免下划线命名
7. 组件属性 —— properties 用 kebab-case 传给 WXML，JS 内小驼峰访问
8. 目录职责 —— pages（页面）、components（组件）、utils（工具）、config（配置）、constants（枚举）、api（接口层）
```

api/ 目录是可选的接口层组织方式：把每个业务域的接口调用集中到一个文件，页面只调用 api 层方法，不直接写 wx.request，进一步解耦。

```js
// api/product.js —— 接口层
const { get, post } = require('../utils/request')

module.exports = {
  getDetail(id) {
    return get('/product/detail', { id })
  },
  getList(page) {
    return get('/product/list', { page })
  },
  createOrder(data) {
    return post('/order/create', data)
  },
}
```

## 应用场景实战

### 场景一：完整的请求封装与登录拦截

实现一个带 token 注入、401 拦截、请求失败重试的请求模块，并组织到 utils/ 与 api/ 目录：

```js
// utils/request.js —— 增强版请求封装
const config = require('../config/index')

let refreshing = false
let waitQueue = [] // 等待 token 刷新完成的任务队列

function request(options) {
  const { url, method, data, retry } = options
  return new Promise((resolve, reject) => {
    const token = wx.getStorageSync('token')
    wx.request({
      url: config.baseUrl + url,
      method: method || 'GET',
      data: data || {},
      timeout: 10000,
      header: {
        'Content-Type': 'application/json',
        Authorization: token ? 'Bearer ' + token : '',
      },
      success: (res) => {
        const body = res.data
        if (body.code === 0) {
          resolve(body.data)
        } else if (body.code === 401) {
          // 并发请求同时 401 时只刷新一次 token
          if (refreshing) {
            waitQueue.push({ resolve, reject, url, method, data })
            return
          }
          refreshing = true
          refreshToken()
            .then(() => {
              refreshing = false
              // 重放等待中的请求
              waitQueue.forEach((item) => {
                request({ url: item.url, method: item.method, data: item.data })
                  .then(item.resolve)
                  .catch(item.reject)
              })
              waitQueue = []
              // 重放当前请求
              if (!retry) {
                request({ url, method, data, retry: true })
                  .then(resolve)
                  .catch(reject)
              }
            })
            .catch(() => {
              refreshing = false
              waitQueue = []
              wx.removeStorageSync('token')
              wx.navigateTo({ url: '/pages/login/login' })
              reject(new Error('登录已过期'))
            })
        } else {
          reject(new Error(body.msg || '请求失败'))
        }
      },
      fail: (err) => {
        reject(err)
      },
    })
  })
}

// 用 wx.login 的 code 换取新 token
function refreshToken() {
  return new Promise((resolve, reject) => {
    wx.login({
      success: (res) => {
        wx.request({
          url: config.baseUrl + '/auth/refresh',
          method: 'POST',
          data: { code: res.code },
          success: (r) => {
            wx.setStorageSync('token', r.data.data.token)
            resolve()
          },
          fail: reject,
        })
      },
      fail: reject,
    })
  })
}

module.exports = {
  get: (url, data) => request({ url, method: 'GET', data }),
  post: (url, data) => request({ url, method: 'POST', data }),
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. 统一模块规范：团队内新代码统一用 ES6 import/export（增强编译自动转译），旧代码逐步迁移，避免混用导致 review 成本高
2. 公共代码只放主包：utils/、api/、config/、公共组件全部位于主包，分包只放自己特有的页面与组件，规避分包引用限制
3. 请求封装统一出口：所有网络请求走 utils/request.js，统一 baseUrl、token、错误码处理，页面不直接写 wx.request
4. 常量集中管理：业务枚举（订单状态、支付方式）放 constants/，环境配置放 config/，杜绝魔法数字散落页面
5. 工具函数保持纯函数：格式化、脱敏等工具不依赖 this 与页面上下文，保证可测试、可复用
6. 接口层（api/）解耦：每个业务域一个 api 文件，页面只调 api 方法，后续接口变更只改 api 层
7. 模块内部状态谨慎共享：利用 require 缓存实现单例（如请求实例），但要避免在模块顶层保存易失状态（如 token）
8. 注意体积预算：公共代码虽然可以复制进分包「省事」，但会重复增加体积，优先用分包引用主包的合法路径

### 踩坑记录

```text
坑 1：require 路径写错导致模块找不到
结论：编译报错 module 'xxx' is not defined，或运行时 require 返回 undefined。
原因：require 必须使用相对路径，且相对于当前文件；写成绝对路径（/utils/xxx）或漏写层级（../../）都会失败。
解法：以当前文件为基准计算相对路径；开发者工具中对 require 路径有自动补全提示，善用「/」前缀的全局搜索确认文件位置。

坑 2：直接给 exports 赋值导致导出为空
结论：require 得到空对象，调用导出的方法报 undefined is not a function。
原因：exports 只是 module.exports 的引用，执行 exports = { ... } 后二者断开，导出仍指向原空对象。
解法：导出对象用 module.exports = { ... }；只添加属性时用 exports.xxx = ...。

坑 3：主包 require 分包代码编译报错
结论：主包页面 require 分包内模块时，构建报「模块不属于主包」或运行时报错。
原因：分包代码在分包加载时才可用，主包不能引用分包模块。
解法：公共模块移动到主包目录；需要按需加载时使用 require.async（基础库 2.23.0+）。

坑 4：独立分包里 require 主包工具直接报错
结论：独立分包页面一进入就报「xxx is not defined」或白屏。
原因：独立分包不依赖主包运行，主包代码默认不可用。
解法：独立分包内准备自包含的工具代码，或将分包改为普通分包；只有明确需要独立加载的场景才用 independent。

坑 5：模块顶层代码执行了副作用，多次进入页面状态被污染
结论：页面第一次正常，第二次进入时数据残留上一次的状态。
原因：模块被 require 缓存，顶层声明的对象（如数组、Map）在多个页面实例间共享。
解法：模块只导出工厂函数或纯函数，实例级状态放在 Page 的 data 中；确需共享时用 getApp().globalData 并显式初始化。

坑 6：import 写在函数内部导致编译错误
结论：报错「import 语句只能出现在顶层」或转译后行为异常。
原因：ES6 import 是静态语法，不允许出现在函数、条件语句中。
解法：import 全部提到文件顶部；确实需要动态加载时用 require（CommonJS 允许任意位置）或 require.async。

坑 7：同一文件混用 module.exports 与 export default
结论：打包后部分导出丢失，调用报 undefined。
原因：增强编译对两种导出方式的混用处理不一致，行为不可预期。
解法：一个文件只使用一种导出体系；npm 包代码不动，自己的业务代码统一 ES6 或统一 CommonJS。

坑 8：修改 utils 代码后页面不生效
结论：改了工具函数，重新编译后页面还是旧行为。
原因：开发者工具对 require 依赖的增量编译偶尔不刷新缓存。
解法：点击工具菜单「清缓存 - 清除全部缓存」后重新编译；提交前在真机预览验证一次。
```

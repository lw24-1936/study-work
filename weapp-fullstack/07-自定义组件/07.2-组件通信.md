## 概述

小程序组件化之后，页面、组件、组件之间需要交换数据与状态，这就是组件通信。官方提供四种标准方式：父组件通过 properties 向子组件传值（单向数据流），子组件通过 triggerEvent 触发自定义事件把数据上报给父组件，父组件通过 selectComponent 直接获取子组件实例调用其方法，组件之间还可以通过 relations 建立关联关系。此外，业务上常用 getApp().globalData 共享全局状态、用事件总线解耦跨层级通信。掌握这些方式的适用场景与边界，是组织复杂页面结构的基础。

```text
组件通信方式全景：
1. properties —— 父传子，单向数据流，最常用
2. triggerEvent —— 子传父，自定义事件 + detail 传参
3. selectComponent —— 父拿子，直接调用子组件实例方法与数据
4. relations —— 组件关系，父子/祖先后代组件直接交互
5. getApp().globalData —— 全局数据共享，非响应式
6. 事件总线 —— 任意组件间解耦通信，需手动管理监听
```

## 父传子 properties 单向数据流

父组件（或页面）通过组件标签上的属性向子组件传值，子组件在 properties 中声明接收。数据流向是单向的：父组件是数据源，子组件只能读取，不应直接修改。子组件需要基于属性做内部状态时，通过 observers 同步到自己的 data 中。

```js
// components/goods-card/goods-card.js
Component({
  properties: {
    title: {
      type: String,
      value: ''
    },
    price: {
      type: Number,
      value: 0
    },
    // 复杂数据：对象、数组都可以直接传
    goods: {
      type: Object,
      value: () => ({})
    }
  },
  data: {
    formattedPrice: '0.00'
  },
  observers: {
    // 属性变化时派生内部展示数据
    price(price) {
      this.setData({ formattedPrice: price.toFixed(2) })
    }
  }
})
```

```xml
<!-- components/goods-card/goods-card.wxml -->
<view class="goods-card">
  <text class="title">{{title}}</text>
  <text class="price">¥{{formattedPrice}}</text>
</view>
```

页面使用：

```xml
<!-- pages/home/home.wxml -->
<goods-card
  title="{{goods.name}}"
  price="{{goods.price}}"
  goods="{{goods}}"
/>
```

```js
// pages/home/home.js
Page({
  data: {
    goods: {
      id: 1001,
      name: '红富士苹果',
      price: 5.8
    }
  }
})
```

```text
父传子要点：
1. 声明 —— 子组件 properties 声明类型与默认值，未声明的属性会被忽略
2. 单向 —— 数据从父流向子，子组件内不要直接 setData 修改 properties
3. 动态更新 —— 父组件 setData 修改属性，子组件 observers 同步响应
4. 复杂数据 —— 对象/数组直接传引用，修改内部字段注意不要直接改父数据
5. 初始化时机 —— 属性值在 attached 时已就绪，attached 中可以读取
6. 与 data 配合 —— 属性只读，内部可变状态放 data，用 observers 做桥接
```

## 子传父 triggerEvent 自定义事件

子组件通过 this.triggerEvent(name, detail, options) 触发自定义事件，父组件在标签上通过 bind:事件名 或 bind事件名 监听，事件对象 e.detail 携带子组件传来的数据。options 支持 bubbles（是否冒泡）、composed（是否穿越组件边界）、capturePhase（是否进入捕获阶段）三个开关，默认均为 false。

```js
// components/stepper/stepper.js
Component({
  properties: {
    value: {
      type: Number,
      value: 1
    }
  },
  methods: {
    onPlus() {
      const newValue = this.data.value + 1
      this.setData({ value: newValue }, () => {
        // detail 里的数据会出现在父组件的事件对象 e.detail 中
        this.triggerEvent('change', { value: newValue })
      })
    }
  }
})
```

```xml
<!-- components/stepper/stepper.wxml -->
<view class="stepper">
  <text class="num">{{value}}</text>
  <button size="mini" bindtap="onPlus">+</button>
</view>
```

父组件监听：

```xml
<!-- pages/cart/cart.wxml -->
<!-- bind:change 与 bindchange 两种写法等价 -->
<stepper value="{{count}}" bind:change="onCountChange" />
```

```js
// pages/cart/cart.js
Page({
  data: {
    count: 1
  },
  onCountChange(e) {
    // e.detail 就是子组件 triggerEvent 的第二个参数
    const value = e.detail.value
    this.setData({ count: value })
  }
})
```

事件需要跨越多层组件边界时，必须显式开启冒泡与穿越：

```js
// 深层子组件
methods: {
  onSelect() {
    this.triggerEvent('selectitem', { id: this.data.id }, {
      bubbles: true,    // 允许事件冒泡
      composed: true,   // 允许穿越组件边界，最终到达页面
      capturePhase: false
    })
  }
}
```

```xml
<!-- 页面无需逐层转发，直接监听即可 -->
<wrapper-list bind:selectitem="onSelectItem" />
```

```text
triggerEvent 要点：
1. 事件名 —— 官方建议用全小写连字符命名（如 change-value），WXML 绑定大小写不敏感
2. detail —— 第二个参数，出现在父组件 e.detail 中，是传参的唯一通道
3. bubbles —— 是否冒泡，默认 false，仅当前父组件能收到
4. composed —— 是否穿越组件边界，跨层级监听必须与 bubbles 一起开
5. capturePhase —— 是否触发捕获阶段监听，一般用不到
6. 目标与来源 —— 事件对象中 currentTarget 是绑定监听的节点，target 是触发事件的组件
```

## 父拿子 selectComponent

selectComponent 让父组件（或页面）通过 id/class 选择器直接获取子组件实例，进而读取子组件 data、调用子组件 methods。它适合「父组件主动驱动子组件」的场景，例如表单页统一校验、父组件控制子组件重置。注意调用时机：页面 onReady 之后组件才渲染完成，此时才能获取到实例。

```js
// components/input-field/input-field.js
Component({
  properties: {
    label: {
      type: String,
      value: ''
    }
  },
  data: {
    value: '',
    error: ''
  },
  methods: {
    onInput(e) {
      this.setData({ value: e.detail.value, error: '' })
    },
    // 供父组件调用：校验当前输入
    validate() {
      if (!this.data.value.trim()) {
        this.setData({ error: this.data.label + '不能为空' })
        return false
      }
      return true
    },
    reset() {
      this.setData({ value: '', error: '' })
    }
  }
})
```

```xml
<!-- pages/order-form/order-form.wxml -->
<input-field id="nameField" label="收货人" />
<input-field id="phoneField" label="手机号" />
<button type="primary" bindtap="onSubmit">提交订单</button>
<button bindtap="onReset">重置表单</button>
```

```js
// pages/order-form/order-form.js
Page({
  onSubmit() {
    // 页面 onReady 之后才能拿到组件实例
    const nameComp = this.selectComponent('#nameField')
    const phoneComp = this.selectComponent('#phoneField')
    const nameOk = nameComp.validate()
    const phoneOk = phoneComp.validate()
    if (!nameOk || !phoneOk) {
      wx.showToast({ title: '请检查表单内容', icon: 'none' })
      return
    }
    // 读取子组件内部数据
    const payload = {
      name: nameComp.data.value,
      phone: phoneComp.data.value
    }
    console.log('提交订单：', payload)
  },
  onReset() {
    // 调用子组件方法
    this.selectComponent('#nameField').reset()
    this.selectComponent('#phoneField').reset()
  }
})
```

组件内部也可以获取自己的子组件，例如容器组件统一控制内部列表项：

```js
// components/accordion/accordion.js
Component({
  methods: {
    // 收起所有子项（accordion-item 是它的子组件）
    collapseAll() {
      const items = this.selectComponent('.accordion-item')
      // 注意：selectComponent 只返回第一个匹配实例
      if (items) {
        items.setActive(false)
      }
    }
  }
})
```

```text
selectComponent 要点：
1. 选择器 —— 支持 id 与 class 选择器，只返回第一个匹配的组件实例
2. 时机 —— 必须在组件渲染完成后调用，页面 onReady 之后最安全
3. 能力 —— 返回的实例可以读 data、调用 methods、setData
4. 传参 —— 组件标签上的 data-xxx 属性在事件对象 dataset 中可取
5. 替代方案 —— 需要批量操作多个同类子组件时，优先用 relations（详见 07.4）
6. 耦合 —— 直接操作实例会提高耦合度，事件驱动优先、selectComponent 兜底
```

## 兄弟组件与全局通信

两个同级的兄弟组件之间没有直接的通信通道，常见三种方案：通过共同的父组件中转（最推荐）、通过 getApp().globalData 共享全局状态、通过事件总线解耦。

方案一：父组件中转。子组件 A 通过 triggerEvent 上报，父组件处理后通过 properties 下发给子组件 B，数据流清晰可追踪。

```xml
<!-- 父组件 wxml -->
<view class="search-page">
  <search-input bind:search="onSearch" />
  <goods-list list="{{filteredList}}" />
</view>
```

```js
// 父组件 js
Component({
  data: {
    allList: [],
    filteredList: []
  },
  methods: {
    onSearch(e) {
      const keyword = e.detail.keyword
      const filtered = this.data.allList.filter(item => item.name.indexOf(keyword) > -1)
      this.setData({ filteredList: filtered })
    }
  }
})
```

方案二：getApp().globalData。适合登录态、用户信息、全局配置这类「全 App 共享」的数据。globalData 不是响应式的，修改后不会自动刷新界面，需要结合 setData 或事件通知。

```js
// app.js
App({
  globalData: {
    token: '',
    userInfo: null
  },
  onLaunch() {
    // 启动时读取本地缓存的登录态
    this.globalData.token = wx.getStorageSync('token') || ''
  }
})
```

```js
// 任意页面/组件中读写
const app = getApp()

// 读
const token = app.globalData.token

// 写
app.globalData.token = 'new-token'
wx.setStorageSync('token', app.globalData.token)
```

方案三：事件总线。适合「两个没有共同父级的组件」或「跨页面状态联动」。实现一个极简的发布订阅器，事件触发方 emit，监听方 on/off。关键是要在组件 detached 时解绑，否则会造成内存泄漏与重复触发。

```js
// utils/event-bus.js —— 极简事件总线
class EventBus {
  constructor() {
    this._handlers = {}
  }

  // 订阅
  on(name, fn) {
    if (!this._handlers[name]) {
      this._handlers[name] = []
    }
    this._handlers[name].push(fn)
  }

  // 取消订阅
  off(name, fn) {
    const list = this._handlers[name]
    if (!list) return
    const index = list.indexOf(fn)
    if (index > -1) {
      list.splice(index, 1)
    }
  }

  // 发布
  emit(name, ...args) {
    const list = this._handlers[name] || []
    list.forEach(fn => fn.apply(null, args))
  }
}

module.exports = new EventBus()
```

```js
// components/header-cart/header-cart.js —— 购物车角标，监听商品变化
const eventBus = require('../../utils/event-bus')

Component({
  data: {
    count: 0
  },
  lifetimes: {
    attached() {
      // 订阅「购物车变化」事件
      this._onCartChange = (count) => {
        this.setData({ count: count })
      }
      eventBus.on('cart-change', this._onCartChange)
    },
    detached() {
      // 必须解绑，防止内存泄漏与重复触发
      eventBus.off('cart-change', this._onCartChange)
    }
  }
})
```

```js
// components/add-cart-btn/add-cart-btn.js —— 加入购物车按钮
const eventBus = require('../../utils/event-bus')

Component({
  methods: {
    onAddCart() {
      // 加入购物车后广播事件
      const newCount = wx.getStorageSync('cartCount') + 1
      wx.setStorageSync('cartCount', newCount)
      eventBus.emit('cart-change', newCount)
    }
  }
})
```

```text
兄弟与全局通信要点：
1. 父级中转 —— 最清晰可控，优先使用；兄弟组件数量少时首选
2. globalData —— 适合全局状态（token/用户信息），非响应式，改后要手动刷新界面
3. 事件总线 —— 适合跨层级、跨页面解耦，订阅后必须成对解绑
4. 生命周期 —— 总线监听建议在 attached 订阅、detached 解绑
5. 命名规范 —— 事件名统一前缀（如 cart-change），避免业务事件互相覆盖
6. 状态管理 —— 复杂全局状态可引入 mobx-miniprogram 等库，但小项目慎用，避免过度设计
```

## 通信方式选型与样式隔离

不同通信方式解决不同层级的问题，选型看两个维度：数据流向（上/下/平级/全局）与耦合度（显式传递还是隐式共享）。样式隔离（styleIsolation）虽然不是数据通信，但它决定了组件样式的作用域，影响组件复用与外部定制，是组件化工程必须理解的一环。

```text
通信方式选型：
1. 父传子数据 -> properties（单向，显式，最常用）
2. 子报数据给父 -> triggerEvent（detail 传参，事件驱动）
3. 父主动驱动子 -> selectComponent（直接调用实例方法）
4. 组件树内关联 -> relations（linked/unlinked 回调 + getRelationNodes）
5. 全局共享数据 -> getApp().globalData（非响应式）
6. 跨层级解耦 -> 事件总线（需手动管理订阅）
```

styleIsolation 在 Component 构造器的 options 中配置，有三种取值：isolated（默认，组件内外样式完全隔离）、apply-shared（页面与 app 样式可以影响组件，组件样式不影响外部）、shared（组件与页面样式互相影响）。基础库 2.10.1 起也支持在组件 json 中配置 styleIsolation。

```js
// components/custom-nav/custom-nav.js
Component({
  options: {
    // 允许页面全局样式渗透进组件（如字体、主题色变量）
    styleIsolation: 'apply-shared'
  }
})
```

```json
// components/custom-nav/custom-nav.json —— 等效配置
{
  "component": true,
  "styleIsolation": "apply-shared"
}
```

```text
styleIsolation 取值：
1. isolated —— 默认。组件 wxss 与外部完全隔离，外部样式（含 app.wxss）进不来
2. apply-shared —— 页面与 app 样式可以影响组件，组件样式不反向影响页面
3. shared —— 组件与页面样式互相影响（双向共享）
4. 组件之间 —— 无论哪种取值，组件与组件默认互不影响，只有页面这一层参与共享
5. 旧版兼容 —— 基础库 2.10.1 之前用 options.addGlobalClass: true 等价于 apply-shared
6. 用途 —— 需要全局主题色/字体进入组件时用 apply-shared；做组件库默认保持 isolated
```

样式隔离对组件通信的影响在于：组件库类组件（如 07.5 的自定义组件库）必须保持 isolated，外部定制通过 externalClasses 或 properties 控制；业务组件（如项目内的导航栏）用 apply-shared 继承页面主题，减少重复样式。

## 应用场景实战

### 场景一：购物车数量联动与总价计算

页面包含商品列表，每行一个数量选择器子组件。父页面通过 properties 把数量传给子组件，子组件通过 triggerEvent 上报新数量，父页面更新列表并实时计算总价——完整覆盖「父传子 + 子传父」双向通信。

```xml
<!-- pages/cart/cart.wxml -->
<view class="cart-page">
  <view class="cart-item" wx:for="{{cartList}}" wx:key="id">
    <view class="item-info">
      <text class="name">{{item.name}}</text>
      <text class="price">单价 ¥{{item.price}}</text>
    </view>
    <stepper
      value="{{item.count}}"
      min="1"
      max="9"
      bind:change="onCountChange"
      data-id="{{item.id}}"
    />
    <text class="subtotal">小计 ¥{{item.price * item.count}}</text>
  </view>
  <view class="total-bar">
    <text>合计：¥{{totalPrice}}</text>
  </view>
</view>
```

```js
// pages/cart/cart.js
Page({
  data: {
    cartList: [
      { id: 1, name: '红富士苹果', price: 5.8, count: 2 },
      { id: 2, name: '海南香蕉', price: 3.5, count: 3 }
    ],
    totalPrice: 0
  },
  onLoad() {
    this.calcTotal()
  },
  onCountChange(e) {
    // 通过 dataset 拿到是哪一行商品
    const id = e.currentTarget.dataset.id
    const newCount = e.detail.value
    const cartList = this.data.cartList.map(item => {
      if (item.id === id) {
        // 用新数量生成新对象，避免直接改原对象
        return Object.assign({}, item, { count: newCount })
      }
      return item
    })
    this.setData({ cartList: cartList }, () => {
      this.calcTotal()
    })
  },
  calcTotal() {
    const total = this.data.cartList.reduce((sum, item) => {
      return sum + item.price * item.count
    }, 0)
    this.setData({ totalPrice: Math.round(total * 100) / 100 })
  }
})
```

```js
// components/stepper/stepper.js —— 子组件：数量选择器
Component({
  properties: {
    value: { type: Number, value: 1 },
    min: { type: Number, value: 0 },
    max: { type: Number, value: 99 }
  },
  methods: {
    onMinus() {
      if (this.data.value <= this.data.min) return
      this.change(this.data.value - 1)
    },
    onPlus() {
      if (this.data.value >= this.data.max) return
      this.change(this.data.value + 1)
    },
    change(newValue) {
      this.setData({ value: newValue }, () => {
        this.triggerEvent('change', { value: newValue })
      })
    }
  }
})
```

```xml
<!-- components/stepper/stepper.wxml -->
<view class="stepper">
  <view class="btn" bindtap="onMinus">-</view>
  <text class="num">{{value}}</text>
  <view class="btn" bindtap="onPlus">+</view>
</view>
```

运行效果：点击任意商品的加减按钮，该行数量变化，底部合计金额实时重新计算。数据流向为「子组件 triggerEvent 上报 → 父页面 setData 更新列表 → 父页面重算总价」，父子各司其职。

### 场景二：selectComponent 驱动的表单校验

表单页包含多个输入子组件，提交按钮统一通过 selectComponent 获取子组件实例，逐个调用 validate 方法校验，全部通过后读取各字段值组装提交数据。

```js
// components/input-field/input-field.js —— 输入子组件
Component({
  properties: {
    label: { type: String, value: '' },
    type: { type: String, value: 'text' },
    placeholder: { type: String, value: '' }
  },
  data: {
    value: '',
    error: ''
  },
  methods: {
    onInput(e) {
      this.setData({ value: e.detail.value, error: '' })
    },
    validate() {
      if (!this.data.value.trim()) {
        this.setData({ error: this.data.label + '不能为空' })
        return false
      }
      if (this.data.type === 'number' && !/^1\d{10}$/.test(this.data.value)) {
        this.setData({ error: '请输入正确的手机号' })
        return false
      }
      this.setData({ error: '' })
      return true
    },
    getValue() {
      return this.data.value
    }
  }
})
```

```xml
<!-- components/input-field/input-field.wxml -->
<view class="field">
  <text class="label">{{label}}</text>
  <input
    class="input"
    type="{{type}}"
    value="{{value}}"
    placeholder="{{placeholder}}"
    bindinput="onInput"
  />
  <text class="error" wx:if="{{error}}">{{error}}</text>
</view>
```

```js
// pages/order-form/order-form.js
Page({
  onSubmit() {
    const nameComp = this.selectComponent('#nameField')
    const phoneComp = this.selectComponent('#phoneField')

    // 逐个校验，校验失败的子组件自己显示错误文案
    const nameOk = nameComp.validate()
    const phoneOk = phoneComp.validate()
    if (!nameOk || !phoneOk) {
      wx.showToast({ title: '请检查表单内容', icon: 'none' })
      return
    }

    // 全部通过，读取值并提交（模拟）
    const orderData = {
      name: nameComp.getValue(),
      phone: phoneComp.getValue()
    }
    console.log('提交订单：', orderData)
    wx.showToast({ title: '提交成功', icon: 'success' })
  },
  onReset() {
    this.selectComponent('#nameField').reset && this.selectComponent('#nameField').reset()
    this.selectComponent('#phoneField').reset && this.selectComponent('#phoneField').reset()
  }
})
```

这个场景展示 selectComponent 的典型价值：父组件在「提交」这个时机主动驱动子组件执行校验逻辑，不需要子组件预先知道校验时机，校验规则封装在子组件内部，父组件只关心「过没过」。

## 最佳实践与踩坑记录

### 最佳实践

1. 通信方式按层级选：父子用 properties + triggerEvent，兄弟用父级中转，全局用 globalData，跨层级解耦用事件总线，不要一律用事件总线把数据流搞乱
2. 自定义事件名统一 kebab-case（如 change-value），并加业务前缀（如 cart-change），避免不同组件的事件名冲突
3. triggerEvent 的 detail 只传必要数据，不要整个把 this.data 塞进去，减少序列化开销与耦合
4. 需要跨多层组件传递事件时，明确在 triggerEvent 第三参数开 bubbles: true 与 composed: true，并注释说明监听方
5. selectComponent 只在「父主动驱动子」的场景使用（表单校验、重置、展开收起），常规数据交换优先事件驱动
6. 事件总线订阅函数保存引用（this._handler = fn），在 detached 中成对解绑，防止内存泄漏与重复触发
7. globalData 只放「写一次、多处读」的全局数据，业务状态尽量留在页面/组件内部，避免全局污染
8. 组件库组件保持 styleIsolation: isolated，外部定制走 externalClasses 与 properties；业务组件按需开 apply-shared

### 踩坑记录

```text
坑 1：triggerEvent 事件名大小写不一致，事件收不到
结论：bind:changeValue 监听，子组件 triggerEvent('changevalue') 触发，页面无响应。
原因：WXML 事件绑定大小写不敏感，changeValue 与 changevalue 会被归一化处理，两边写法不一致就匹配不上。
解法：事件名统一用全小写连字符（change-value），触发与监听都写同一个名字，杜绝大小写歧义。

坑 2：子组件事件不冒泡，嵌套组件里父组件收不到
结论：多层组件嵌套，内层子组件 triggerEvent 后，只有直接父组件能收到，页面监听不到。
原因：triggerEvent 默认 bubbles: false、composed: false，事件不会跨组件边界传播。
解法：需要跨层级监听时显式开启 this.triggerEvent(name, detail, { bubbles: true, composed: true })。

坑 3：onReady 之前调用 selectComponent 返回 null
结论：页面 onLoad 里 this.selectComponent('#id') 拿到 null，调用方法报错。
原因：页面 onLoad 时组件尚未渲染完成，组件实例还不存在。
解法：selectComponent 统一放在 onReady 及之后调用；组件内获取子组件同理要等 ready。

坑 4：子组件直接改 properties 值，父组件数据不同步
结论：子组件 setData 修改 properties 后界面变了，父组件里数据还是旧值，刷新后又变回去。
原因：properties 是单向数据流，子组件的修改不会同步回父组件数据源。
解法：修改动作通过 triggerEvent 上报，由父组件 setData；子组件内部展示用 data 副本（observers 桥接）。

坑 5：getApp().globalData 修改后界面不更新
结论：改了 globalData 里的用户信息，页面显示的还是旧数据。
原因：globalData 是普通对象，不是响应式数据，修改不会触发任何渲染。
解法：修改后手动 setData 同步到页面 data；或封装成 store，用事件/订阅机制通知所有依赖方刷新。

坑 6：事件总线忘记解绑，组件重复执行回调
结论：页面反复进入退出后，事件触发一次却执行了多次回调，数据被重复累加。
原因：组件每次 attached 都订阅，detached 没解绑，旧实例的回调还挂在总线上。
解法：订阅时把回调函数存为实例属性（this._onXxx），detached 中 eventBus.off(name, this._onXxx)；off 时传入与 on 相同的函数引用。

坑 7：组件样式被页面样式意外覆盖或反之
结论：组件里写的样式不生效，或者组件的样式污染了页面其他区域。
原因：styleIsolation 默认 isolated，但页面 wxss 里的标签选择器、类选择器在 apply-shared 或误配 shared 时会互相穿透。
解法：明确设置 options.styleIsolation；组件库组件保持 isolated；需要主题渗透用 apply-shared 并在注释中说明。
```

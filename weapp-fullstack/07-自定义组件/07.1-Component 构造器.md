## 概述

Component 构造器是微信小程序自定义组件的唯一入口，它比 Page 构造器多出 properties、observers、externalClasses、relations 等能力，用来封装可复用的 UI 与逻辑单元。一个组件由 js、json、wxml、wxss 四个文件组成，js 文件通过 Component({...}) 声明组件的属性、数据、方法与生命周期，json 文件通过 component: true 标记该目录是组件。组件拥有独立的样式作用域与数据作用域，页面通过属性传值、事件回调与组件交互，这是小程序组件化的基础。

```text
Component 构造器核心能力：
1. properties —— 声明外部传入的属性（类型、默认值、变化监听）
2. data —— 组件内部数据，通过 setData 更新
3. methods —— 组件方法，事件处理函数必须写在这里
4. lifetimes —— 组件自身生命周期（created/attached/ready/moved/detached）
5. pageLifetimes —— 页面生命周期监听（show/hide/resize）
6. observers —— 数据监听器，监听 data 与 properties 的变化
```

## Component 定义与组件四件套

自定义组件必须由四个文件组成，且四件套同名、放在同一目录下。js 文件是组件的核心，所有声明都通过 Component 构造器完成；json 文件声明 component: true，否则该目录会被当作页面处理；wxml 定义模板结构；wxss 定义样式，默认与页面样式隔离。

```text
组件四件套：
components/stepper/
├── stepper.js      # Component 构造器，声明属性/数据/方法/生命周期
├── stepper.json    # {"component": true}，标记这是一个组件
├── stepper.wxml    # 组件模板结构
└── stepper.wxss    # 组件样式，默认隔离，不影响外部
```

最简组件完整代码：

```json
// components/stepper/stepper.json
{
  "component": true,
  "usingComponents": {}
}
```

```js
// components/stepper/stepper.js
Component({
  properties: {
    value: {
      type: Number,
      value: 1
    }
  },
  data: {
    current: 1
  },
  methods: {
    onPlus() {
      this.setData({ current: this.data.current + 1 })
    }
  }
})
```

```xml
<!-- components/stepper/stepper.wxml -->
<view class="stepper">
  <view class="num">{{current}}</view>
  <button size="mini" bindtap="onPlus">+</button>
</view>
```

```css
/* components/stepper/stepper.wxss */
.stepper {
  display: flex;
  align-items: center;
}
.num {
  margin: 0 16rpx;
  font-size: 32rpx;
}
```

使用组件前，需要在使用方的 json（页面或另一个组件）中通过 usingComponents 注册组件路径，然后在 wxml 中像使用内置组件一样使用：

```json
// pages/index/index.json
{
  "usingComponents": {
    "stepper": "/components/stepper/stepper"
  }
}
```

```xml
<!-- pages/index/index.wxml -->
<stepper value="{{2}}" />
```

Component 与 Page 的最大区别在于职责与能力：Page 是页面入口，承载导航与整页生命周期；Component 是可复用单元，拥有 properties、observers、relations、externalClasses 等 Page 没有的能力，并且样式默认隔离。事件处理函数在 Page 中直接写在顶层，在 Component 中必须写在 methods 里，写在顶层不会被识别。

```text
Component vs Page：
1. 定位 —— Page 是页面入口，Component 是可复用 UI 单元
2. 属性 —— Component 有 properties 接收外部传值，Page 没有
3. 方法 —— Component 的方法必须放在 methods 中，Page 的方法直接写顶层
4. 生命周期 —— Component 用 lifetimes（created/attached/ready），Page 用 onLoad/onShow/onReady
5. 样式 —— Component 默认样式隔离，Page 受全局样式影响
6. 注册 —— Component 通过 usingComponents 被页面或其他组件引用，Page 注册在 app.json 的 pages 中
```

补充一点：页面也可以使用 Component 构造器构造（官方支持），此时页面生命周期 onLoad/onShow 等直接写在构造器参数顶层，同时可以复用 observers 等组件能力，适合对页面做数据监听等增强。

## properties 属性定义

properties 是组件对外暴露的接口，父组件（或页面）通过属性向组件传值。每个属性可以简写为只声明类型，也可以完整声明 type、value、observer 三项。属性类型支持 String、Number、Boolean、Object、Array、null（null 表示任意类型）。

```js
// components/custom-card/custom-card.js
Component({
  properties: {
    // 简写：只声明类型
    title: String,
    // 完整写法：类型 + 默认值
    desc: {
      type: String,
      value: '暂无描述'
    },
    // 对象类型：value 用函数返回，避免多个组件实例共享同一个引用
    user: {
      type: Object,
      value: () => ({})
    },
    // 数组类型：同样建议函数返回
    tags: {
      type: Array,
      value: () => []
    },
    // 布尔类型
    showFooter: {
      type: Boolean,
      value: true
    },
    // 任意类型
    extra: null
  }
})
```

页面传值方式：

```xml
<!-- pages/index/index.wxml -->
<custom-card
  title="限时特价"
  desc="今日下单立减 5 元"
  user="{{userInfo}}"
  tags="{{['新品', '热卖']}}"
  showFooter="{{false}}"
/>
```

```js
// pages/index/index.js
Page({
  data: {
    userInfo: { name: '张三', age: 18 }
  }
})
```

properties 是单向数据流：数据只能从父组件流向子组件，子组件内部不建议直接修改 properties。如果子组件需要基于属性值维护内部状态，正确的做法是用 observers 把属性变化同步到 data，再使用 data 中的副本。

```text
properties 要点：
1. 类型 —— String/Number/Boolean/Object/Array/null，null 表示任意类型
2. 默认值 —— value 字段声明，Object/Array 用函数返回避免引用共享
3. 单向数据流 —— 子组件不应直接修改 properties，内部可变副本放 data
4. 布尔陷阱 —— 属性为 Boolean 时，checked="false" 会被当作字符串（非空即 true），必须写 checked="{{false}}"
5. 旧版 observer —— properties 中可写 observer 监听属性变化，但官方不推荐，建议统一用 observers 字段
6. 属性更新 —— 父组件 setData 修改属性值后，子组件会收到新值，可用 observers 响应
```

## data 数据与 methods 方法

data 是组件的内部数据，初始值在构造器中声明，运行时通过 this.setData 更新。与 Page 相同，直接修改 this.data.xxx 不会触发视图更新，必须走 setData。methods 中定义组件的方法，事件绑定 bindtap="onXxx" 对应的方法必须存在于 methods 中，这是 Component 与 Page 的语法差异之一。

```js
// components/hello-card/hello-card.js
Component({
  properties: {
    name: {
      type: String,
      value: '微信用户'
    }
  },
  data: {
    greeting: '你好',
    clickCount: 0
  },
  methods: {
    onGreet() {
      // 事件处理函数写在 methods 中
      this.setData({
        greeting: '你好，' + this.data.name,
        clickCount: this.data.clickCount + 1
      })
    },
    reset() {
      // 组件方法可以被页面通过 selectComponent 调用
      this.setData({
        greeting: '你好',
        clickCount: 0
      })
    }
  }
})
```

```xml
<!-- components/hello-card/hello-card.wxml -->
<view class="card">
  <text class="greeting">{{greeting}}</text>
  <text class="count">已点击 {{clickCount}} 次</text>
  <button size="mini" bindtap="onGreet">打招呼</button>
  <button size="mini" bindtap="reset">重置</button>
</view>
```

```css
/* components/hello-card/hello-card.wxss */
.card {
  padding: 24rpx;
  background: #f7f7f7;
  border-radius: 16rpx;
}
.greeting {
  display: block;
  font-size: 36rpx;
  font-weight: 600;
}
.count {
  display: block;
  margin: 12rpx 0;
  color: #888;
  font-size: 26rpx;
}
```

setData 的第二个参数是回调函数，在数据更新完成、视图渲染完成后执行，常用于「更新后通知父组件」这类场景：

```js
methods: {
  onPlus() {
    this.setData({ current: this.data.current + 1 }, () => {
      // 视图已更新，可以安全地做后续操作
      this.triggerEvent('change', { value: this.data.current })
    })
  }
}
```

```text
data 与 methods 要点：
1. setData —— 唯一的视图更新入口，直接改 this.data 不会触发渲染
2. methods —— 所有组件方法（含事件处理）必须写在 methods 中，写在顶层不生效
3. this —— 方法内 this 指向组件实例，可用 this.data 读、this.setData 写
4. setData 回调 —— 第二参数在渲染完成后执行，适合联动触发事件
5. 数据量控制 —— setData 只传变化字段，减少视图层通信开销（详见 13.3）
6. 私有数据 —— 与渲染无关的中间数据可用纯数据字段存放（详见 07.4）
```

## lifetimes 生命周期与 pageLifetimes

组件生命周期通过 lifetimes 字段声明，包括 created、attached、ready、moved、detached 五个阶段。created 时组件实例刚创建，可以读 this.data，但不能调用 setData；attached 时组件进入页面节点树，属性值已初始化，可以 setData；ready 时视图层布局完成，可以获取节点信息、selectComponent 查找子组件。moved 在组件被移动到树的其他位置时触发，detached 在组件被移除时触发，适合做清理工作。

```js
// components/life-demo/life-demo.js
Component({
  data: {
    stage: ''
  },
  lifetimes: {
    created() {
      // 组件实例创建，this.data 可用，但不能 setData
      console.log('created：组件实例创建')
    },
    attached() {
      // 进入页面节点树，属性值已就绪，可以 setData
      console.log('attached：组件挂载到节点树')
      this.setData({ stage: 'attached' })
    },
    ready() {
      // 视图层布局完成，可获取节点信息
      console.log('ready：组件布局完成')
    },
    moved() {
      console.log('moved：组件被移动到其他位置')
    },
    detached() {
      // 组件被移除，做清理：解绑事件、清除定时器
      console.log('detached：组件被移除')
    }
  }
})
```

组件还可以通过 pageLifetimes 监听所在页面的状态，包括 show、hide、resize 三个回调。pageLifetimes 的生命周期是「页面级的」，在组件内部监听自己所在页面的显示隐藏，常用于「页面显示时刷新数据」这类需求。

```js
// components/life-demo/life-demo.js
Component({
  pageLifetimes: {
    show() {
      // 组件所在页面显示时触发
      console.log('pageLifetimes.show：页面显示')
    },
    hide() {
      // 组件所在页面隐藏时触发（如切后台、跳转其他页面）
      console.log('pageLifetimes.hide：页面隐藏')
    },
    resize(size) {
      // 页面尺寸变化时触发，size 含 windowWidth/windowHeight
      console.log('pageLifetimes.resize：', size.windowWidth, size.windowHeight)
    }
  }
})
```

组件生命周期与页面生命周期的交叉顺序（首次渲染时，可通过 console 日志在开发者工具中验证）：

```text
组件生命周期执行顺序：
1. created —— 实例创建，不能 setData
2. attached —— 进入节点树，可以 setData，属性值就绪
3. ready —— 布局完成，可以获取节点信息、selectComponent
4. moved —— 节点位置移动（少见）
5. detached —— 实例销毁，做清理

与页面的交叉顺序（首次渲染）：
1. 页面 onLoad
2. 页面 onShow
3. 组件 created
4. 组件 attached
5. 页面 onReady
6. 组件 ready

注意事项：
1. created 中调用 setData 会报错，只能读 this.data
2. attached 中拿不到节点信息（要用 SelectorQuery 需等 ready）
3. detached 中及时清除定时器、解绑事件，防止内存泄漏
4. 旧版生命周期（attached/ready 直接写在 Component 顶层）不推荐，统一用 lifetimes
```

## observers 数据监听器

observers 用于监听 data 与 properties 中字段的变化，在字段被 setData 修改后、视图渲染前触发。它比 properties 里的旧版 observer 更强大：支持监听对象深层字段、同时监听多个字段、通配符监听，且官方推荐把属性变化监听统一收敛到 observers 中。

```js
// components/observer-demo/observer-demo.js
Component({
  data: {
    count: 0,
    user: {
      name: '张三',
      age: 18
    }
  },
  observers: {
    // 监听单个字段，回调参数是变化后的新值
    count: function (newVal, oldVal) {
      console.log('count 变化：', oldVal, '->', newVal)
    },
    // 监听对象下的某个子字段
    'user.name': function (name) {
      console.log('user.name 变化：', name)
    },
    // 通配符：监听 user 下任意子字段的变化，回调参数是整个 user 对象
    'user.**': function (user) {
      console.log('user 深层字段变化：', user)
    },
    // 同时监听多个字段，回调参数按声明顺序传入
    'count, user.age': function (count, age) {
      console.log('count 或 user.age 变化：', count, age)
    }
  },
  methods: {
    onAdd() {
      this.setData({ count: this.data.count + 1 })
    },
    onRename() {
      this.setData({ 'user.name': '李四' })
    }
  }
})
```

observers 最常见的用途是「属性变化后派生内部状态」——例如父组件传入金额，子组件自动计算税费并展示：

```js
// components/order-amount/order-amount.js
Component({
  properties: {
    amount: {
      type: Number,
      value: 0
    }
  },
  data: {
    tax: 0,
    total: 0
  },
  observers: {
    // 属性变化也会触发 observers
    amount(amount) {
      const tax = Math.round(amount * 0.06 * 100) / 100
      this.setData({
        tax: tax,
        total: amount + tax
      })
    }
  }
})
```

```text
observers 要点：
1. 监听范围 —— 同时监听 data 与 properties 的变化
2. 触发时机 —— setData 之后、视图渲染之前
3. 合并触发 —— 同一帧内对同一字段多次 setData，只触发一次，取最终值
4. 通配符 —— 'a.**' 监听 a 下所有子字段；'**' 监听所有字段（性能差，慎用）
5. 多字段 —— 'a, b' 逗号分隔同时监听，回调参数按顺序传入
6. 死循环风险 —— 在 observer 中 setData 被监听的同一字段会再次触发，必须加条件判断或监听其他字段
```

## 应用场景实战

### 场景一：商品数量选择器组件

实现一个完整的 stepper 组件：父页面通过 properties 传入当前数量、上下限，子组件通过 methods 处理加减，通过 triggerEvent 把新数量上报给父页面，父页面更新购物车数据。

```js
// components/stepper/stepper.js
Component({
  properties: {
    value: {
      type: Number,
      value: 1
    },
    min: {
      type: Number,
      value: 0
    },
    max: {
      type: Number,
      value: 99
    }
  },
  data: {
    current: 1
  },
  lifetimes: {
    attached() {
      // 用属性值初始化内部状态
      this.setData({ current: this.data.value })
    }
  },
  observers: {
    // 父组件修改 value 时同步内部状态（如购物车数量被外部重置）
    value(newVal) {
      this.setData({ current: newVal })
    }
  },
  methods: {
    onMinus() {
      if (this.data.current <= this.data.min) return
      this.setData({ current: this.data.current - 1 }, () => {
        this.triggerEvent('change', { value: this.data.current })
      })
    },
    onPlus() {
      if (this.data.current >= this.data.max) return
      this.setData({ current: this.data.current + 1 }, () => {
        this.triggerEvent('change', { value: this.data.current })
      })
    }
  }
})
```

```xml
<!-- components/stepper/stepper.wxml -->
<view class="stepper">
  <view class="btn {{current <= min ? 'disabled' : ''}}" bindtap="onMinus">-</view>
  <view class="num">{{current}}</view>
  <view class="btn {{current >= max ? 'disabled' : ''}}" bindtap="onPlus">+</view>
</view>
```

```css
/* components/stepper/stepper.wxss */
.stepper {
  display: flex;
  align-items: center;
}
.btn {
  width: 56rpx;
  height: 56rpx;
  line-height: 56rpx;
  text-align: center;
  background: #eee;
  border-radius: 8rpx;
}
.btn.disabled {
  color: #bbb;
}
.num {
  min-width: 72rpx;
  text-align: center;
  font-size: 32rpx;
}
```

页面接入：

```xml
<!-- pages/cart/cart.wxml -->
<stepper value="{{count}}" min="1" max="9" bind:change="onCountChange" />
```

```js
// pages/cart/cart.js
Page({
  data: {
    count: 1
  },
  onCountChange(e) {
    const value = e.detail.value
    this.setData({ count: value })
    wx.showToast({ title: '数量：' + value, icon: 'none' })
  }
})
```

这个场景覆盖了 Component 构造器的核心用法：properties 接收外部值、lifetimes 初始化、observers 同步属性变化、methods 处理交互、triggerEvent 与父组件通信。

### 场景二：observers 驱动的表单校验组件

利用 observers 监听输入值变化，输入过程中实时校验，错误提示自动显示或消失，校验通过后通过事件把合法值上报给页面。

```js
// components/price-input/price-input.js
Component({
  properties: {
    label: {
      type: String,
      value: '价格'
    }
  },
  data: {
    inputValue: '',
    errorText: ''
  },
  observers: {
    inputValue(value) {
      // 非法的金额格式（最多两位小数）给出错误提示
      if (value && !/^\d+(\.\d{1,2})?$/.test(value)) {
        this.setData({ errorText: '请输入合法金额，最多两位小数' })
        return
      }
      this.setData({ errorText: '' })
      const num = value === '' ? 0 : Number(value)
      // 校验通过，把数值上报给父组件
      this.triggerEvent('change', { value: num })
    }
  },
  methods: {
    onInput(e) {
      this.setData({ inputValue: e.detail.value })
    }
  }
})
```

```xml
<!-- components/price-input/price-input.wxml -->
<view class="price-input">
  <text class="label">{{label}}</text>
  <input
    class="input"
    type="digit"
    value="{{inputValue}}"
    placeholder="0.00"
    bindinput="onInput"
  />
  <text class="error" wx:if="{{errorText}}">{{errorText}}</text>
</view>
```

```css
/* components/price-input/price-input.wxss */

```

```js
// pages/goods-edit/goods-edit.js
Page({
  data: {
    price: 0,
    marketPrice: 0
  },
  onPriceChange(e) {
    this.setData({ price: e.detail.value })
  },
  onMarketPriceChange(e) {
    this.setData({ marketPrice: e.detail.value })
  },
  onSubmit() {
    // 页面数据已由子组件通过事件实时同步，直接提交即可
    console.log('提交：', this.data.price, this.data.marketPrice)
  }
})
```

这个场景展示了 observers 的典型用法：监听输入值做实时派生（校验结果、派生数值），并且通过 triggerEvent 把处理结果回传给父组件，父组件无需关心校验细节。

## 最佳实践与踩坑记录

### 最佳实践

1. 组件目录四件套同名同目录，json 中固定写 {"component": true, "usingComponents": {}}，使用方通过 usingComponents 注册后再使用
2. 所有事件处理函数与可复用方法统一写进 methods，保持 Component 构造器顶层只放声明式配置（properties/data/options/relations）
3. 属性默认值 Object/Array 一律用函数返回（value: () => []），避免多个组件实例共享同一引用导致数据串扰
4. 属性变化的监听统一用 observers 字段，不要再往 properties 里写旧版 observer，功能更强且避免两套机制并存
5. created 阶段只做只读操作（记录日志、读 this.data），一切需要 setData 的初始化放到 attached
6. detached 中清理定时器、解绑事件总线监听，配合 pageLifetimes.hide 处理页面级暂停逻辑
7. 组件 wxss 默认隔离，需要页面样式渗透时显式配置 styleIsolation（详见 07.2），不要用 !important 硬顶
8. 一个组件只做一件事：体积过大、职责过多的组件拆分成多个小组件，通过组件嵌套与通信组合（详见 07.2）

### 踩坑记录

```text
坑 1：组件 json 忘记写 component: true
结论：使用组件时报「组件未注册」或页面直接报错白屏。
原因：json 未声明 component: true 时，该目录会被当作页面解析，usingComponents 中找不到对应组件。
解法：组件目录的 .json 必须包含 {"component": true}；报错时先检查 json 再检查 usingComponents 路径。

坑 2：方法写在 Component 顶层，事件绑定不生效
结论：bindtap="onTap" 绑定后点击无反应，控制台报「Component is not found in path」或方法未定义。
原因：Component 构造器中事件处理函数必须写在 methods 里，写在顶层的方法不会被注册为事件处理函数（与 Page 语法不同）。
解法：把组件方法统一移入 methods；检查组件 js 是否误用了 Page 的写法。

坑 3：在 created 生命周期中调用 setData
结论：报错「Cannot read property 'setData' of undefined」或数据不生效。
原因：created 时组件实例刚创建，视图层尚未就绪，不允许 setData。
解法：created 只做只读逻辑；初始化数据放到 attached 中执行 setData。

坑 4：子组件直接修改 properties 导致数据流混乱
结论：子组件内 setData 修改属性值，界面变了但父组件数据没变，下次属性更新又把值改回去。
原因：properties 是单向数据流，父组件持有数据源，子组件修改的是自己的副本，父组件不会感知。
解法：需要修改时通过 triggerEvent 通知父组件改；组件内部基于属性派生状态时，用 observers 同步到 data 再使用。

坑 5：observer 里 setData 同一字段造成死循环
结论：页面卡死或 setData 高频触发，控制台刷屏。
原因：observers 在字段变化后触发，observer 内 setData 该字段又触发 observers，无限循环。
解法：observer 内加条件判断（值相同直接 return）；或监听派生字段而不是源字段；不要在一次 setData 里同时改监听字段。

坑 6：Boolean 属性传 "false" 字符串不生效
结论：<comp disabled="false" /> 期望禁用，实际仍然可用。
原因：布尔属性直接写字符串会被当作非空字符串处理，转 Boolean 后为 true。
解法：布尔属性必须写 disabled="{{false}}" 或 disabled="{{condition}}"，不要写裸字符串。

坑 7：同一帧多次 setData 同字段，observer 只触发一次
结论：observer 里的日志只打印一次，误以为监听没生效。
原因：observers 的触发时机是渲染前，同帧内对同一字段的多次修改会合并，只触发一次且取最终值。
解法：observer 内不要依赖触发次数做累加逻辑，需要过程性统计时在 setData 前自己累加。
```

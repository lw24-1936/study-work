## 概述

自定义组件的基础能力（Component 构造器、properties、通信、behaviors、插槽）覆盖了常规开发，进阶特性解决的是工程化场景：纯数据字段避免渲染层无谓更新、外部样式类让使用者能定制组件外观、relations 让父子组件建立运行时关系、抽象节点让组件支持多实现。这四个特性是组件库与复杂业务组件的必备能力。

```text
组件进阶特性：
1. pureDataPattern —— 纯数据字段不参与渲染，减少 setData 传输
2. lifetimes 顺序 —— created -> attached -> ready，生命周期时点严格
3. externalClasses —— 外部样式类，使用者从外部覆盖组件样式
4. relations —— 组件间声明式关系（父子/兄弟），运行时互相调用
5. 抽象节点 —— 组件内部声明抽象节点，外部提供具体实现
6. 扩展 —— behaviors 中引用自身 usingComponents，实现递归组件
```

## 纯数据字段

纯数据字段（pure data field）是指不用于 WXML 渲染、仅用于逻辑计算的数据。默认情况下，Component 的 data 里所有字段都会在 setData 时被序列化传输到视图层，即使这些字段从不参与渲染。用 pureDataPattern 指定正则，匹配到的字段会被标记为纯数据，不参与渲染传输。

```js
// components/stats-card/stats-card.js
Component({
  options: {
    pureDataPattern: /^_/ // 以 _ 开头的字段是纯数据
  },
  properties: {
    list: { type: Array, value: [] }
  },
  data: {
    _total: 0,      // 纯数据：只用于内部计算
    _avg: 0,        // 纯数据
    displayText: '' // 普通数据：参与渲染
  },
  observers: {
    'list': function (list) {
      // 在监听器里计算纯数据，不触发视图更新
      const _total = list.reduce((s, i) => s + i.value, 0)
      const _avg = list.length ? (_total / list.length) : 0
      this.setData({ _total, _avg, displayText: `共 ${_total} 元` })
    }
  }
})
```

```text
纯数据字段要点：
1. 匹配规则 —— options.pureDataPattern 传正则，常见 /^_/ 下划线前缀
2. 生效范围 —— 仅组件 data 内生效，properties 不适用
3. 传输优化 —— 纯数据不进入渲染层，setData 数据量变小
4. 使用场景 —— 中间计算结果、缓存值、临时状态
5. 注意 —— 纯数据仍可用 setData 更新，只是不触发渲染
```

## 组件生命周期顺序

组件的 lifetimes 定义了组件实例从创建到销毁的完整生命周期：created、attached、ready、moved、detached。理解执行顺序对资源管理（监听器注册、定时器清理）至关重要。

```js
// components/life-demo/life-demo.js
Component({
  lifetimes: {
    created() {
      // 组件实例刚被创建，此时还不能 setData
      // 适合初始化纯 JS 数据（不依赖 this.data 渲染）
      console.log('created: 实例创建，data 已初始化')
    },
    attached() {
      // 组件被插入页面节点树，可以 setData
      // 适合请求数据、注册监听
      console.log('attached: 已挂载到页面，可 setData')
    },
    ready() {
      // 组件布局完成，可以操作节点（selectComponent 等）
      console.log('ready: 视图已就绪')
    },
    moved() {
      // 组件在节点树中移动位置
      console.log('moved: 节点位置变化')
    },
    detached() {
      // 组件被移除，清理定时器与监听
      console.log('detached: 已销毁，清理资源')
    }
  },
  pageLifetimes: {
    show() { console.log('页面显示（组件视角）') },
    hide() { console.log('页面隐藏（组件视角）') },
    resize(size) { console.log('页面尺寸变化', size) }
  }
})
```

```text
生命周期执行顺序：
1. 首次创建 —— created -> attached -> ready
2. 页面切换 —— show / hide（pageLifetimes）
3. 节点移动 —— moved
4. 销毁 —— detached
5. 关键约束 —— created 阶段不能 setData，attached 之后才行
```

## 外部样式类

默认情况下，组件样式是隔离的，页面无法直接覆盖组件内部节点的样式。externalClasses 允许组件声明一个「外部样式类」，使用者在引用组件时传入自己的 class，这些 class 会应用到组件内部声明的节点上。

```js
// components/custom-btn/custom-btn.js
Component({
  externalClasses: ['my-class'] // 声明可被外部覆盖的样式类
})
```

```xml
<!-- components/custom-btn/custom-btn.wxml -->
<view class="btn my-class">按钮</view>
```

```xml
<!-- pages/index/index.wxml 使用 -->
<custom-btn my-class="red-btn" />
```

```css
/* pages/index/index.wxss */
.red-btn {
  background: #fa5151;
  color: #fff;
}
```

```text
外部样式类要点：
1. 声明 —— externalClasses 数组列出可覆盖的类名
2. 传参 —— 使用组件时以「类名同名属性」传入（my-class 对应 my-class）
3. 覆盖 —— 外部类的优先级高于组件内部同名类
4. 用途 —— 组件库主题定制、业务差异样式
5. 限制 —— 只影响 class 样式，不影响内联 style
```

## relations 组件关系

relations 用于在组件之间声明「组件关系」，让父组件能直接拿到子组件实例、子组件能访问父组件，兄弟组件也能互相通信。典型场景是树形组件（如菜单、折叠面板、表格）需要父组件统一管理子组件状态。

```js
// components/tabs/tabs.js
Component({
  relations: {
    './tab-item': {
      type: 'child',           // 声明 tab-item 是自己的孩子
      linked(target) {
        // 子组件挂载时触发，target 是子组件实例
        console.log('子组件加入', target)
      },
      unlinked(target) {
        console.log('子组件移除', target)
      }
    }
  },
  methods: {
    switchTab(index) {
      this.getRelationNodes('./tab-item').forEach((item, i) => {
        item.setData({ active: i === index })
      })
    }
  }
})
```

```js
// components/tab-item/tab-item.js
Component({
  relations: {
    '../tabs/tabs': {
      type: 'ancestor' // 声明 tabs 是祖先
    }
  },
  methods: {
    onTap() {
      const tabs = this.getRelationNodes('../tabs/tabs')
      if (tabs.length) tabs[0].switchTab(this.data.index)
    }
  }
})
```

```text
relations 关系类型：
1. parent —— 父节点关系（子组件声明）
2. child —— 子节点关系（父组件声明）
3. ancestor —— 祖先关系（跨层级）
4. descendant —— 后代关系（跨层级）
5. getRelationNodes —— 获取关系节点数组（实例列表）
```

## 抽象节点与扩展

抽象节点（abstract nodes）让组件在内部声明一个「占位节点」，由使用方传入具体组件实例。它解决的问题：组件库提供通用容器（如列表），但列表项的具体实现由业务方决定。扩展则指用 behaviors 组合构造更复杂的组件，或在 behaviors 里引用组件自身实现递归。

```js
// components/generic-list/generic-list.js
Component({
  options: {
    abstractNodes: ['selectable'] // 声明抽象节点 selectable
  },
  properties: {
    items: { type: Array, value: [] }
  }
})
```

```xml
<!-- components/generic-list/generic-list.wxml -->
<view wx:for="{{items}}" wx:key="id">
  <selectable item="{{item}}" />
</view>
```

```xml
<!-- pages/index/index.json 指定抽象节点实现 -->
{
  "usingComponents": {
    "generic-list": "/components/generic-list/generic-list",
    "selectable": "/components/product-item/product-item"
  }
}
```

```xml
<!-- pages/index/index.wxml -->
<generic-list items="{{products}}" />
```

递归组件是扩展的经典用法：在组件的 behaviors 中引用组件自身，实现树形数据渲染（如菜单树、组织架构、评论嵌套）。

```js
// components/tree-node/tree-node.js
Component({
  options: { multipleSlots: true },
  relations: {
    './tree-node': { type: 'child' }
  },
  behaviors: [{
    // 通过 behaviors 里的 usingComponents 引用自身
    options: {
      usingComponents: {
        'tree-node': '/components/tree-node/tree-node'
      }
    }
  }],
  properties: {
    node: { type: Object, value: null }
  }
})
```

```text
抽象节点与递归要点：
1. abstractNodes —— 声明抽象节点名，用方括号 options 配置
2. 实现注入 —— 使用方在 json 的 usingComponents 里映射具体组件
3. 递归组件 —— behaviors 里 usingComponents 引用自身
4. 适用场景 —— 树形菜单、评论嵌套、动态列表项
5. 性能注意 —— 递归层级过深会卡顿，控制深度或改扁平数据
```

## 应用场景实战

### 场景一：带外部样式类的评分组件

封装一个支持外部定制的评分组件，页面使用时覆盖颜色与尺寸。

```js
// components/rate/rate.js
Component({
  externalClasses: ['rate-class', 'star-class'],
  properties: {
    value: { type: Number, value: 0 },
    max: { type: Number, value: 5 }
  },
  data: {
    stars: [1, 2, 3, 4, 5]
  },
  observers: {
    'max': function (max) {
      this.setData({ stars: Array.from({ length: max }, (_, i) => i + 1) })
    }
  },
  methods: {
    onTap(e) {
      const index = e.currentTarget.dataset.index
      this.triggerEvent('change', { value: index })
    }
  }
})
```

```xml
<!-- components/rate/rate.wxml -->
<view class="rate rate-class">
  <text
    class="star star-class {{index <= value ? 'on' : ''}}"
    wx:for="{{stars}}"
    wx:key="*this"
    data-index="{{item}}"
    bindtap="onTap"
  >★</text>
</view>
```

```css
/* components/rate/rate.wxss */
.star { font-size: 40rpx; color: #ccc; }
.star.on { color: #ffb800; }
```

```xml
<!-- pages/index/index.wxml -->
<rate value="{{3}}" bind:change="onRate" />
<rate value="{{4}}" class="large" />
```

```css
/* pages/index/index.wxss */
.large { font-size: 64rpx; }
```

### 场景二：用 relations 实现折叠面板

父组件 accordion 统一管理子项展开状态，点击子项标题切换展开，同一时间只展开一项。

```js
// components/accordion/accordion.js
Component({
  relations: {
    './accordion-item': { type: 'child' }
  },
  data: { activeIndex: -1 },
  methods: {
    toggle(index) {
      const active = this.data.activeIndex === index ? -1 : index
      this.setData({ activeIndex: active })
      this.getRelationNodes('./accordion-item').forEach((item, i) => {
        item.setData({ expanded: i === active })
      })
    }
  }
})
```

```js
// components/accordion-item/accordion-item.js
Component({
  relations: {
    '../accordion/accordion': { type: 'parent' }
  },
  properties: {
    title: { type: String, value: '' },
    index: { type: Number, value: 0 }
  },
  data: { expanded: false },
  methods: {
    onHeaderTap() {
      const parent = this.getRelationNodes('../accordion/accordion')
      if (parent.length) parent[0].toggle(this.data.index)
    }
  }
})
```

```xml
<!-- pages/index/index.wxml -->
<accordion>
  <accordion-item index="0" title="商品说明">
    <view>正品保障，支持 7 天无理由退货</view>
  </accordion-item>
  <accordion-item index="1" title="配送说明">
    <view>下单后 48 小时内发货</view>
  </accordion-item>
</accordion>
```

## 最佳实践与踩坑记录

### 最佳实践

1. 内部计算字段统一用纯数据字段（下划线前缀 + pureDataPattern），减少视图层传输数据量
2. 定时器、全局监听（如 wx.onNetworkStatusChange）在 attached 注册、detached 清理，防止内存泄漏
3. 组件库开发时优先用外部样式类 + CSS 变量双方案，兼顾旧版本兼容
4. relations 只用于「结构固定」的父子关系（树、列表、面板），动态多变的场景用事件通信更简单
5. 递归组件控制深度，超过 3 层用扁平数据 + 展开态渲染
6. 组件默认开启样式隔离，需要页面影响组件内部时显式声明 externalClasses，不要用 styleIsolation: 'apply-shared' 一刀切

### 踩坑记录

坑 1：created 生命周期里调用 setData 报错
结论：created 阶段调用 setData 无效或报错，数据更新不上。
原因：created 时组件还未挂载到节点树，渲染层不可用。
解法：数据初始化放 created（只改 this.data 或普通变量），setData 放 attached 之后。

坑 2：外部样式类覆盖不生效
结论：传入的 class 没有作用到组件内部节点。
原因：类名属性传参时写成了驼峰（myClass）而非连字符（my-class），或 externalClasses 未声明。
解法：externalClasses 数组里声明什么名字，使用方就传什么属性名，保持一致。

坑 3：relations 的 getRelationNodes 返回空数组
结论：父子组件互相找不到对方。
原因：relations 声明的路径与组件实际引用路径不一致，或组件尚未 attached。
解法：路径必须与 usingComponents 中注册的路径完全一致；在 linked 回调之后再用 getRelationNodes。

坑 4：纯数据字段正则写错导致渲染数据丢失
结论：本应渲染的字段不更新。
原因：pureDataPattern 匹配范围过大（如 /.*/ 匹配所有字段），把渲染字段也标记为纯数据。
解法：用窄正则（如 /^_/），只标记明确的前缀字段，写完自测渲染。

坑 5：递归组件爆栈或死循环
结论：树形数据递归渲染导致栈溢出或性能卡顿。
原因：递归组件无深度限制，数据成环或层级过深。
解法：渲染前校验数据无环、限制最大深度；业务上改成按需展开（懒加载子节点）。

坑 6：detached 没清理监听导致内存泄漏
结论：页面反复进出后内存持续上涨，组件事件重复触发。
原因：attached 里注册的监听（定时器、全局事件）未在 detached 移除。
解法：attached 保存句柄，detached 统一 clearInterval / off 事件。

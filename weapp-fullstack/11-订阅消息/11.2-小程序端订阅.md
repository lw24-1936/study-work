## 概述

小程序端订阅是整个订阅消息链路的第一环：用户在小程序内同意订阅某个模板后，微信服务端才会为「用户 + 模板」登记一条下发额度，后续服务端才能调用 subscribeMessage.send 下发消息。订阅动作必须由用户主动触发，微信通过 wx.requestSubscribeMessage 接口和 open-type="subscribe" 按钮两种方式呈现授权弹窗。

订阅环节直接决定触达能力的天花板：用户不接受订阅，后续一切下发都无从谈起。因此本章节聚焦订阅接口的正确调用方式、订阅结果（accept/reject/ban）的处理、订阅按钮与订阅状态查询、引导时机的设计，以及用户拒绝后的重新订阅策略。这些细节直接影响订阅转化率和用户对产品的信任度。

```text
本章核心要点：
1. 调用接口 —— wx.requestSubscribeMessage 传入 tmplIds 数组拉起授权弹窗
2. 三种结果 —— 回调中每个模板返回 accept / reject / ban 三种状态
3. 触发约束 —— 必须在用户点击事件回调中调用，onLoad 里调用不弹窗
4. 订阅按钮 —— open-type="subscribe" 按钮面向长期订阅消息场景
5. 状态查询 —— wx.getSetting withSubscriptions 可查询订阅状态
6. 额度策略 —— 一次性订阅每次下发前都可能需要重新订阅
```

## requestSubscribeMessage 订阅接口详解

wx.requestSubscribeMessage 是引导一次性订阅消息授权的核心 API。调用时传入 tmplIds 数组（模板 ID 列表，最多 3 个），微信会弹出订阅授权面板，展示每个模板的标题与关键词预览，用户勾选后点击「允许」即完成订阅。调用必须发生在用户点击行为的回调中（如 button 的 bindtap、catchtap），在 onLoad、onShow 等生命周期里调用不会弹出授权面板，直接走 fail 回调。

成功回调里 res 是一个以模板 ID 为 key 的对象，每个 key 的取值有三种：accept 表示用户同意订阅（获得 1 条额度）；reject 表示用户拒绝（未获得额度）；ban 表示用户曾勾选「总是保持以上选择，不再询问」且当前选择为拒绝，或该模板已被系统判定不可再弹（如 7 天内重复弹窗被拦截）。需要特别注意的是，用户同意后 7 天内同一模板不再重复弹出授权面板，连续同意最多 2 次。

```text
wx.requestSubscribeMessage 要点：
1. tmplIds —— 模板 ID 数组，一次最多 3 个，超出或为空直接 fail
2. 触发方式 —— 必须在用户点击事件回调中调用，生命周期中调用不弹窗
3. success 回调 —— res[tmplId] 返回 accept / reject / ban
4. accept —— 用户同意，获得该模板 1 条下发额度
5. reject —— 用户拒绝，未获得额度；拒绝后 7 天内再次调用不弹窗
6. ban —— 用户勾选「总是保持以上选择，不再询问」或系统拦截，需引导去设置页
```

一个完整的调用示例，同时处理成功、失败与每种订阅结果：

```javascript
// pages/order/detail.js —— 引导订阅发货提醒
Page({
  data: {
    orderId: '',
    shippingTemplateId: 'xYZp2uHnRoL8z8k_4yQbB'
  },

  // 用户点击「订阅发货提醒」按钮触发
  onSubscribeTap() {
    wx.requestSubscribeMessage({
      tmplIds: [this.data.shippingTemplateId],
      success: (res) => {
        const status = res[this.data.shippingTemplateId];
        if (status === 'accept') {
          wx.showToast({ title: '订阅成功，发货时将通知您', icon: 'none' });
          // 通知后台记录订阅状态（11.4 合规要求：授权记录落库）
          this.reportSubscribe('accept');
        } else if (status === 'reject') {
          wx.showToast({ title: '已取消订阅，可在订单页随时开启', icon: 'none' });
          this.reportSubscribe('reject');
        } else if (status === 'ban') {
          // 用户勾选过「不再询问」，需要去设置页手动开启
          this.showSettingGuide();
          this.reportSubscribe('ban');
        }
      },
      fail: (err) => {
        // err.errMsg 形如 requestSubscribeMessage:fail can only be invoked by user TAP gesture
        console.error('订阅调用失败', err);
        wx.showToast({ title: '请点击页面上的订阅按钮', icon: 'none' });
      }
    });
  },

  reportSubscribe(status) {
    wx.request({
      url: 'https://api.example.com/api/subscribe/record',
      method: 'POST',
      data: { templateId: this.data.shippingTemplateId, status }
    });
  },

  showSettingGuide() {
    wx.showModal({
      title: '开启发货提醒',
      content: '您选择了不再询问，可前往设置页重新开启发货通知',
      confirmText: '去设置',
      success: (res) => {
        if (res.confirm) {
          // 通过 open-type="openSetting" 按钮或 wx.openSetting 打开设置页
          wx.openSetting();
        }
      }
    });
  }
});
```

订阅结果的统计埋点很重要：accept 比例（订阅转化率）是衡量订阅引导设计的关键指标，reject 与 ban 的比例分别对应「引导文案不给力」与「用户彻底关闭」。埋点数据上报到后台后，可以在数据看板中按页面、按模板、按版本分析，为后续优化提供依据（11.4 数据统计章节会展开）。

## 订阅按钮与订阅状态查询

除了 wx.requestSubscribeMessage，微信还提供了 open-type="subscribe" 的 button 组件。用户点击该按钮会弹出订阅授权面板，通过 bindsubscribe 接收订阅结果（event.detail.errMsg 形如 subscribe:ok / subscribe:fail），通过 binderror 接收面板无法弹出的错误。该按钮形态主要面向长期订阅消息场景，一次性订阅消息统一使用 wx.requestSubscribeMessage，两者不要混用。

订阅状态查询使用 wx.getSetting 的 withSubscriptions 参数（基础库 2.10.1 及以上）：开启后 res.subscriptionsSetting.itemSettings 会返回用户对本小程序订阅过的模板状态，key 为模板 ID，值为 accept / reject / ban。查询结果可以用于展示「已订阅」标识、决定是否展示订阅引导按钮，也可以用于判断用户是否还有额度可用（itemSettings 中 accept 但额度已用完后，状态仍可能显示 accept，因此额度判断仍需结合本地记录与下发结果）。

```text
订阅按钮与状态查询：
1. open-type="subscribe" —— 订阅按钮组件，主要面向长期订阅消息场景
2. bindsubscribe —— 订阅成功回调，event.detail.errMsg 为 subscribe:ok
3. binderror —— 订阅面板无法弹出时的错误回调
4. wx.getSetting —— 传 withSubscriptions: true 查询订阅状态
5. itemSettings —— 返回 { 模板ID: 'accept' | 'reject' | 'ban' }
6. 版本兼容 —— withSubscriptions 需基础库 2.10.1+，低版本需 canIUse 判断
```

订阅按钮的 WXML 与状态查询代码示例：

```xml
<!-- pages/settings/subscribe.wxml —— 消息设置页 -->
<view class="subscribe-setting">
  <view class="setting-item">
    <view class="setting-text">
      <text>发货通知</text>
      <text class="setting-desc">商品发货与签收时提醒您</text>
    </view>
    <button
      wx:if="{{!subscribed}}"
      open-type="subscribe"
      bindsubscribe="onSubscribeOk"
      binderror="onSubscribeError"
      size="mini"
    >开启</button>
    <text wx:else class="setting-status">已开启</text>
  </view>
</view>
```

```javascript
// pages/settings/subscribe.js —— 查询并展示订阅状态
Page({
  data: {
    subscribed: false,
    templateId: 'xYZp2uHnRoL8z8k_4yQbB'
  },

  onLoad() {
    this.checkSubscribeStatus();
  },

  // 查询用户对发货通知模板的订阅状态
  checkSubscribeStatus() {
    wx.getSetting({
      withSubscriptions: true,
      success: (res) => {
        const itemSettings = (res.subscriptionsSetting || {}).itemSettings || {};
        const status = itemSettings[this.data.templateId];
        // accept 表示订阅过；reject/ban 或不存在表示未开启
        this.setData({ subscribed: status === 'accept' });
      },
      fail: () => {
        // 低版本基础库不支持，按未订阅处理
        this.setData({ subscribed: false });
      }
    });
  },

  onSubscribeOk(e) {
    // event.detail.errMsg === 'subscribe:ok'
    this.setData({ subscribed: true });
    wx.showToast({ title: '已开启发货通知', icon: 'success' });
  },

  onSubscribeError(e) {
    console.error('订阅面板无法弹出', e.detail.errMsg);
    wx.showToast({ title: '暂无法开启，请稍后再试', icon: 'none' });
  }
});
```

订阅状态查询有一个容易被忽略的语义：itemSettings 反映的是「用户是否订阅过/是否允许弹窗」，并不反映「剩余额度」。用户 accept 一次并下发消费后，itemSettings 仍可能是 accept，但额度已经为 0。因此「是否还能收到消息」的判断应该以服务端下发结果（43101）与本地额度记录为准，前端状态只用于 UI 展示。

## 订阅场景设计与引导时机

订阅引导的转化率高度依赖时机：用户刚完成一个动作、正处于「期待后续反馈」的心理状态时，订阅意愿最强。典型的高转化时机包括支付成功页、下单成功页、预约提交成功页、报名成功页——这些场景下用户对「通知我结果」有明确的诉求，弹窗与业务动作无缝衔接，接受率可以到 40%-70%。反过来，进入小程序首页就弹订阅、浏览商品过程中突然弹订阅，接受率往往低于 20%，还会招致反感。

引导时机设计要遵循三个原则：与用户动作强相关（订阅的内容就是用户刚做的事情的后续）、即时性（动作完成后立刻弹，不要延迟到下一次进入）、克制（一次只推 1-2 个模板，绝不每次进入都弹）。同一模板在用户拒绝或同意后 7 天内不会再次弹出授权面板，因此「每个页面都放一个订阅入口」没有意义，要设计固定的订阅触点。

```text
订阅引导时机设计：
1. 支付成功页 —— 订阅支付回执与发货提醒，转化率最高的场景
2. 下单/预约提交后 —— 订阅订单状态提醒，与用户期待强相关
3. 活动报名成功后 —— 订阅活动开始提醒，用户有明确预期
4. 订单详情页 —— 提供「提醒我发货/签收」按钮，作为额度不足的兜底入口
5. 设置页 —— 提供订阅开关，用户可随时重新开启
6. 禁止场景 —— 首页弹窗、浏览中弹窗、每次进入都弹，都会大幅拉低接受率
```

订阅弹窗中的模板数量也直接影响转化率：一次弹窗超过 3 个模板（接口上限），或一次展示 3 个但用户只关心其中 1 个，都会让用户犹豫后整体拒绝。建议优先策略：支付成功页一次弹 2 个模板（支付回执 + 发货通知），把转化率最高的模板放在第一位；其余模板放在订单详情页的按钮入口，用户按需订阅。一次性订阅「每次下发前都可能需要重新订阅」的特性决定了：订阅入口必须是可持续触达的（按钮、开关），而不是只在首次流程里弹一次。

## 用户拒绝处理与重新订阅

用户拒绝订阅是常态，一次性订阅的接受率通常在 30%-60%，不必把拒绝当成失败。拒绝处理的正确姿势是：记录拒绝结果（埋点）、不在同一会话中反复弹窗（系统 7 天限制之外，业务侧也不要对同一模板连续弹出）、在业务页面保留「重新订阅」的入口，让用户之后随时可以补订。切忌用诱导性文案（如「不订阅将无法使用」）胁迫用户，这既违反平台规范，也会被用户举报。

重新订阅的入口通常放在业务结果页与设置页：订单详情页的「提醒我发货」按钮、预约详情页的「开始前提醒我」按钮、消息设置页的开关。用户点击后再次调用 wx.requestSubscribeMessage（若 7 天冷却期已过，会重新弹出授权面板）。对 ban 状态的用户（勾选了「总是保持以上选择，不再询问」），wx.requestSubscribeMessage 不再弹窗，必须通过 open-type="openSetting" 按钮或 wx.openSetting 引导用户进入设置页手动开启。

```text
拒绝与重新订阅策略：
1. 拒绝是常态 —— 接受率 30%-60% 属正常，记录结果并埋点即可
2. 不纠缠 —— 拒绝后同一会话不反复弹窗，7 天内系统也不再弹
3. 保留入口 —— 业务页/设置页提供「开启提醒」按钮，随时可补订
4. ban 处理 —— 勾选「不再询问」后接口不再弹窗，引导去设置页开启
5. 设置页 —— wx.openSetting 打开，用户可管理订阅消息开关
6. 文案克制 —— 不诱导、不胁迫，说明订阅用途即可
```

处理三种订阅结果的完整逻辑（页面 JS）：

```javascript
// pages/order/detail.js —— 发货提醒订阅与重新订阅
Page({
  data: {
    orderId: '20260820001',
    shipTemplateId: 'xYZp2uHnRoL8z8k_4yQbB',
    subscribed: false,   // 是否显示「已开启」状态
    banned: false        // 用户是否勾选了「不再询问」
  },

  onLoad() {
    this.checkStatus();
  },

  // 进入页面时查询订阅状态与是否被 ban
  checkStatus() {
    wx.getSetting({
      withSubscriptions: true,
      success: (res) => {
        const itemSettings = (res.subscriptionsSetting || {}).itemSettings || {};
        const status = itemSettings[this.data.shipTemplateId];
        this.setData({
          subscribed: status === 'accept',
          banned: status === 'ban'
        });
      }
    });
  },

  // 订阅/重新订阅入口（按钮 tap 触发）
  onSubscribeTap() {
    // ban 状态直接引导去设置页，不再调用订阅接口
    if (this.data.banned) {
      this.openSettingGuide();
      return;
    }
    wx.requestSubscribeMessage({
      tmplIds: [this.data.shipTemplateId],
      success: (res) => {
        const status = res[this.data.shipTemplateId];
        if (status === 'accept') {
          this.setData({ subscribed: true });
          wx.showToast({ title: '发货后将通知您', icon: 'success' });
          this.report(status);
        } else if (status === 'reject') {
          wx.showToast({ title: '可在订单页随时开启提醒', icon: 'none' });
          this.report(status);
        } else if (status === 'ban') {
          this.setData({ banned: true });
          this.openSettingGuide();
          this.report(status);
        }
      },
      fail: (err) => {
        console.error('订阅失败', err);
      }
    });
  },

  openSettingGuide() {
    wx.showModal({
      title: '开启发货提醒',
      content: '您之前选择了不再询问，请到设置页重新开启',
      confirmText: '去设置',
      success: (res) => {
        if (res.confirm) {
          wx.openSetting({
            success: (r) => {
              // 设置页返回后刷新订阅状态
              this.checkStatus();
            }
          });
        }
      }
    });
  },

  report(status) {
    wx.request({
      url: 'https://api.example.com/api/subscribe/record',
      method: 'POST',
      data: {
        templateId: this.data.shipTemplateId,
        status,
        orderId: this.data.orderId,
        page: 'order/detail'
      }
    });
  }
});
```

重新订阅后额度恢复 1 条：用户再次 accept 一次，服务端就再次获得 1 条下发额度。因此「订单签收提醒」这类需要第二次下发的场景，正确的做法是在第一次下发（发货提醒）完成后，通过订单详情页的入口让用户再订阅一次签收提醒，而不是期望一次订阅覆盖两次通知。

## 应用场景实战

### 场景一：支付成功页组合订阅两个模板

用户支付成功后立即弹出订阅面板，同时引导订阅「支付成功通知」与「订单发货通知」两个模板，完整实现：

```xml
<!-- pages/pay/result.wxml —— 支付成功页 -->
<view class="pay-result">
  <view class="pay-status">支付成功</view>
  <view class="pay-amount">¥ 299.00</view>

  <view class="subscribe-card">
    <view class="subscribe-title">订阅消息提醒</view>
    <view class="subscribe-desc">支付凭证与发货进度将通过微信服务通知发送给您</view>
    <button
      class="subscribe-btn"
      bindtap="onSubscribeTap"
      disabled="{{subscribed}}"
    >{{subscribed ? '已开启提醒' : '开启提醒'}}</button>
  </view>
</view>
```

```javascript
// pages/pay/result.js —— 支付成功页订阅逻辑
const TEMPLATES = {
  paid: 'qweR1tGXnQmL9y7j_3xWpA',      // 支付成功通知
  shipped: 'xYZp2uHnRoL8z8k_4yQbB'     // 订单发货通知
};

Page({
  data: {
    orderNo: '20260820001',
    subscribed: false
  },

  onLoad(options) {
    // 支付回调成功进入本页，orderNo 由支付流程传入
    this.setData({ orderNo: options.orderNo || '' });
  },

  onSubscribeTap() {
    wx.requestSubscribeMessage({
      tmplIds: [TEMPLATES.paid, TEMPLATES.shipped],
      success: (res) => {
        const paid = res[TEMPLATES.paid] === 'accept';
        const shipped = res[TEMPLATES.shipped] === 'accept';
        if (paid || shipped) {
          this.setData({ subscribed: true });
          wx.showToast({ title: '已开启消息提醒', icon: 'success' });
        }
        // 上报订阅结果（模板维度），后台记录授权（11.4 合规要求）
        wx.request({
          url: 'https://api.example.com/api/subscribe/record',
          method: 'POST',
          data: {
            orderNo: this.data.orderNo,
            templates: {
              [TEMPLATES.paid]: res[TEMPLATES.paid],
              [TEMPLATES.shipped]: res[TEMPLATES.shipped]
            }
          }
        });
      },
      fail: (err) => {
        // 非用户点击触发的调用会走到这里
        console.error('订阅调用失败', err.errMsg);
      }
    });
  }
});
```

该场景的关键设计：订阅弹窗与支付成功动作无缝衔接；两个模板一次弹窗完成；订阅结果按模板维度上报，后台可统计每个模板的转化率。用户若只勾选了发货通知，后台记录里支付通知模板为 reject，后续额度判断就有据可依。

### 场景二：订单详情页的「提醒我发货」动态订阅入口

当用户对发货通知模板的额度已用完（服务端下发返回 43101）时，订单详情页展示订阅按钮，用户点击重新订阅。页面根据服务端返回的订阅状态动态渲染：

```javascript
// pages/order/detail.js —— 动态订阅入口
Page({
  data: {
    orderId: '20260820001',
    needSubscribe: false,     // 是否展示订阅按钮
    shipTemplateId: 'xYZp2uHnRoL8z8k_4yQbB'
  },

  onLoad(options) {
    this.setData({ orderId: options.id });
    this.fetchSubscribeState();
  },

  // 从服务端查询：该用户对发货模板是否还有可用额度
  fetchSubscribeState() {
    wx.request({
      url: 'https://api.example.com/api/subscribe/status',
      data: {
        orderId: this.data.orderId,
        templateId: this.data.shipTemplateId
      },
      success: (res) => {
        // res.data.quota: 0 表示额度已用完，需要重新订阅
        this.setData({ needSubscribe: res.data.quota <= 0 });
      }
    });
  },

  onSubscribeTap() {
    wx.requestSubscribeMessage({
      tmplIds: [this.data.shipTemplateId],
      success: (res) => {
        const status = res[this.data.shipTemplateId];
        if (status === 'accept') {
          this.setData({ needSubscribe: false });
          wx.showToast({ title: '发货时将通知您', icon: 'success' });
        }
      }
    });
  }
});
```

```xml
<!-- pages/order/detail.wxml 片段 -->
<view class="order-card">
  <view class="order-status">待发货</view>
  <button
    wx:if="{{needSubscribe}}"
    class="subscribe-btn"
    bindtap="onSubscribeTap"
  >提醒我发货</button>
  <view wx:else class="order-tip">已开启发货提醒</view>
</view>
```

服务端查询接口（SpringBoot 简化版）：

```java
// SubscribeStatusController.java —— 查询用户订阅额度状态
@RestController
@RequestMapping("/api/subscribe")
public class SubscribeStatusController {

    private final SubscribeRecordMapper recordMapper;

    public SubscribeStatusController(SubscribeRecordMapper recordMapper) {
        this.recordMapper = recordMapper;
    }

    /**
     * 返回用户对某模板的可用额度。
     * quota 为 0 时小程序端展示重新订阅入口。
     */
    @GetMapping("/status")
    public Map<String, Object> status(@RequestParam String openid,
                                      @RequestParam String templateId) {
        // 订阅次数 - 成功下发次数 = 剩余额度（由服务端记录表统计）
        int subscribed = recordMapper.countSubscribe(openid, templateId);
        int sent = recordMapper.countSent(openid, templateId);
        Map<String, Object> result = new HashMap<>();
        result.put("quota", Math.max(0, subscribed - sent));
        return result;
    }
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. 订阅调用统一放在用户点击事件回调里，页面生命周期中绝不调用，避免静默失败
2. 一次弹窗最多 2-3 个模板，把转化率最高的模板放第一位，模板越多接受率越低
3. 订阅时机绑定业务动作（支付成功、预约提交后立即弹），不要在首页或浏览中弹窗
4. 订阅结果按模板维度上报埋点（accept/reject/ban），用数据驱动引导文案与时机优化
5. 拒绝后 7 天内系统不再弹同一模板，业务侧在同一会话内也不要重复弹，避免骚扰
6. 为每个高频模板在业务详情页保留「开启提醒」按钮，额度用完或拒绝后可随时补订
7. ban 状态的用户走 wx.openSetting 引导，不要再调 requestSubscribeMessage 徒劳
8. 用 wx.getSetting withSubscriptions 展示订阅状态，但额度判断以服务端记录与 43101 为准

### 踩坑记录

```text
坑 1：在 onLoad 里调用 requestSubscribeMessage，弹窗不出现
结论：调用无任何反应，success/fail 都不触发，或直接返回 fail。
原因：wx.requestSubscribeMessage 必须由用户点击行为触发，生命周期回调里调用不会弹出授权面板。
解法：把订阅调用放到 button 的 bindtap / catchtap 事件回调中，或在 open-type="subscribe" 按钮的 bindsubscribe 中处理。

坑 2：tmplIds 传了 4 个模板或传空数组
结论：接口直接 fail，提示参数错误，弹窗不出现。
原因：tmplIds 数组长度上限为 3，且不能为空；传了未选用的模板 ID 也会失败。
解法：控制单次弹窗模板数 ≤ 3，且模板必须是公众平台已选用并审核通过的；模板 ID 从配置读取避免手误。

坑 3：一次性订阅场景用了 open-type="subscribe" 按钮
结论：按钮点击后没有任何反应或行为异常，订阅无法完成。
原因：open-type="subscribe" 按钮主要面向长期订阅消息场景，一次性订阅消息需要 wx.requestSubscribeMessage。
解法：一次性订阅统一用 wx.requestSubscribeMessage；确属长期订阅场景才使用 open-type="subscribe" 按钮。

坑 4：用户拒绝后 7 天内反复调用订阅，误以为接口坏了
结论：用户第一次拒绝后，后续调用都直接返回 reject，弹窗不再出现。
原因：平台规定同一模板 7 天内不重复弹出订阅面板，这是反骚扰机制而非故障。
解法：拒绝后不要在同一会话内重复弹；7 天后再尝试；业务侧记录拒绝时间，配合系统限制安排补订时机。

坑 5：只处理 accept，忽略 reject 和 ban
结论：用户拒绝或 ban 后没有任何反馈，额度不足时用户无感知，后续收不到消息也不知道为什么。
原因：代码只写了 success 里 accept 分支，reject/ban 分支缺失或为空。
解法：三种状态分别处理：accept 提示成功并上报；reject 提示可随时补订；ban 引导去设置页。

坑 6：订阅弹窗文案没讲清用途，接受率极低
结论：订阅接受率长期低于 20%，后台统计 reject 比例异常高。
原因：订阅弹窗时机突兀（进首页就弹）、模板过多、用户不知道订阅后能获得什么。
解法：弹窗绑定业务动作；一次最多 2-3 个模板；在页面里先用文案说明「将通知您发货进度」再触发订阅。

坑 7：开发者工具里 accept，真机上却是 ban
结论：开发者工具调试时订阅正常，真机上返回 ban，用户收不到消息。
原因：工具与真机的订阅状态不同步；用户可能在真机上勾选过「总是保持以上选择，不再询问」，或历史设备上拒绝过。
解法：以真机为准；ban 状态走设置页引导；测试时在工具里清除缓存/重新编译，真机上删除小程序重进可重置部分状态。

坑 8：withSubscriptions 返回 undefined 导致页面报错
结论：wx.getSetting 回调里读 subscriptionsSetting 时报 TypeError。
原因：基础库低于 2.10.1 不支持 withSubscriptions，或 itemSettings 不存在（用户未订阅过任何模板）。
解法：先 wx.canIUse('getSetting.withSubscriptions') 做能力检测；读取时用 (res.subscriptionsSetting || {}).itemSettings || {} 兜底。
```

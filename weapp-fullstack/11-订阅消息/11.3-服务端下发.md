## 概述

服务端下发是订阅消息链路中由 SpringBoot 后台承担的环节：小程序端完成用户订阅后，后台在业务事件发生时（订单发货、支付成功、预约提醒）调用微信订阅消息接口，向用户推送服务通知。下发的两个前置条件是 access_token（调用凭证）与用户的订阅额度（订阅消息授权），两者缺一不可。

服务端下发涉及四个核心问题：access_token 的获取与缓存（2 小时有效期、每日获取次数有限）、subscribeMessage.send 接口的调用与参数组装（touser/template_id/page/data/miniprogram_state）、下发频率控制（避免骚扰与触发平台限流）、错误码处理（区分可重试与不可重试错误）。本篇章给出完整的 SpringBoot 实现与生产级注意事项。

```text
本章核心要点：
1. access_token —— GET /cgi-bin/token 获取，2 小时有效，必须缓存
2. 下发接口 —— POST /cgi-bin/message/subscribe/send，携带 access_token
3. 参数核心 —— touser 为用户 openid，data 对应模板 {{xxx.DATA}} 占位符
4. 频率限制 —— access_token 每日获取 2000 次，send 接口超限返回 45009
5. 错误处理 —— 43101 用户拒收不消耗额度且不可硬发，40001 需刷新 token
6. 日志与幂等 —— 每次下发落库，批量任务做好去重与失败补偿
```

## access_token 获取与缓存

access_token 是调用微信服务端接口的全局唯一凭证，由 AppID 与 AppSecret 换取。获取接口为 GET https://api.weixin.qq.com/cgi-bin/token?grant_type=client_credential&appid=APPID&secret=APPSECRET，返回 access_token 与 expires_in（有效时长 7200 秒，即 2 小时）。access_token 被小程序后台的所有微信接口共用（订阅消息下发、内容安全检测、生成小程序码等），必须在服务端统一获取、统一缓存、统一分发。

access_token 有两个必须遵守的约束：一是有效期 2 小时，过期后调用接口返回 40001；二是获取接口有每日频率限制（每个 AppID 每天最多获取 2000 次），且重复获取会使之前的 access_token 立即失效。因此生产环境必须缓存 access_token：缓存中有效就直接复用，临近过期或缺失才回源微信获取一次，绝不能每次下发都重新获取。

```text
access_token 要点：
1. 接口 —— GET /cgi-bin/token?grant_type=client_credential&appid=APPID&secret=APPSECRET
2. 返回 —— {"access_token": "...", "expires_in": 7200}
3. 有效期 —— 2 小时，过期后接口调用返回 40001 invalid credential
4. 频率限制 —— 每日获取上限 2000 次，超限返回 45009
5. 失效规则 —— 有效期内重复获取会使旧 token 立即失效，并发获取互相踢
6. 缓存策略 —— Redis 缓存 + 提前 5 分钟过期 + 加锁防并发回源
```

SpringBoot 实现：Redis 缓存 + synchronized 双重检查 + 提前过期，保证多线程、多实例下 token 只回源获取一次：

```java
// AccessTokenService.java —— access_token 获取与缓存
import com.fasterxml.jackson.databind.JsonNode;
import org.springframework.data.redis.core.StringRedisTemplate;
import org.springframework.stereotype.Service;
import org.springframework.web.client.RestTemplate;

import java.util.concurrent.TimeUnit;

@Service
public class AccessTokenService {

    private static final String TOKEN_URL =
        "https://api.weixin.qq.com/cgi-bin/token?grant_type=client_credential&appid=%s&secret=%s";
    private static final String CACHE_KEY = "wechat:access_token";

    private final RestTemplate restTemplate;
    private final StringRedisTemplate redisTemplate;
    private final WechatProperties props;

    public AccessTokenService(RestTemplate restTemplate, StringRedisTemplate redisTemplate,
                              WechatProperties props) {
        this.restTemplate = restTemplate;
        this.redisTemplate = redisTemplate;
        this.props = props;
    }

    /**
     * 获取 access_token：优先读缓存，缓存缺失或过期才回源微信。
     * 加锁 + 双重检查，避免并发请求同时回源导致 token 互相失效。
     */
    public String getAccessToken() {
        String cached = redisTemplate.opsForValue().get(CACHE_KEY);
        if (cached != null && !cached.isEmpty()) {
            return cached;
        }
        synchronized (this) {
            cached = redisTemplate.opsForValue().get(CACHE_KEY);
            if (cached != null && !cached.isEmpty()) {
                return cached;
            }
            String url = String.format(TOKEN_URL, props.getAppId(), props.getAppSecret());
            JsonNode resp = restTemplate.getForObject(url, JsonNode.class);
            if (resp != null && resp.has("access_token")) {
                String token = resp.get("access_token").asText();
                long expiresIn = resp.get("expires_in").asLong();
                // 提前 5 分钟过期，避免边界时刻 token 已失效但缓存仍命中
                redisTemplate.opsForValue().set(CACHE_KEY, token, expiresIn - 300, TimeUnit.SECONDS);
                return token;
            }
            throw new WechatApiException(
                resp == null ? -1 : resp.path("errcode").asInt(-1),
                resp == null ? "获取 access_token 响应为空" : resp.path("errmsg").asText());
        }
    }
}
```

多实例部署时，synchronized 只能约束单实例内的并发。更稳妥的方案是用 Redis 分布式锁（SETNX + 过期时间）保证全集群同一时刻只有一个实例回源获取 token，其余实例等待锁释放后读缓存。获取失败时（网络抖动、频率超限）不要裸抛异常，应返回缓存中「即将过期」的旧 token 兜底或降级为记录告警，避免业务链路被 token 故障整体拖垮。

## subscribeMessage.send 接口与参数组装

下发接口为 POST https://api.weixin.qq.com/cgi-bin/message/subscribe/send?access_token=ACCESS_TOKEN，请求体为 JSON。核心参数：touser 是接收用户的 openid（必须是小程序内获取的 openid，与 appid 一一对应）；template_id 是公众平台选用的模板 ID；page 是用户点击消息后跳转的小程序页面路径（可带 query 参数）；data 是模板内容数据，每个键对应模板关键词编号，值为 { "value": ... }；miniprogram_state 声明消息的版本环境（developer 开发版 / trial 体验版 / formal 正式版，默认 formal）；lang 为语言（zh_CN / en_US / zh_TW，默认 zh_CN）。

data 的组装必须与模板关键词严格对应：模板选用时确定的「thing1 商品名称、number2 订单号、phrase3 发货状态」，下发时 data 就必须是 thing1/number2/phrase3 三个键，多一个键、少一个键、键名写错都会返回 47003。value 的类型与长度同样受限：thing 限 20 个汉字、phrase 限 5 个汉字、number 为数字、time 为秒级时间戳、amount 为分单位的金额。

```text
subscribeMessage.send 参数：
1. touser —— 用户 openid，必须是小程序 code2session 获取的 openid
2. template_id —— 公众平台选用的模板 ID，配置化统一管理
3. page —— 点击消息跳转的页面路径，可带 query（pages/order/detail?id=1）
4. data —— { 关键词编号: { value: 值 } }，键名与模板严格对应
5. miniprogram_state —— developer / trial / formal，默认 formal
6. lang —— zh_CN / en_US / zh_TW，默认 zh_CN
```

SpringBoot 完整实现，含 data 组装与字段截断：

```java
// SubscribeMessageService.java —— 订阅消息下发
import com.fasterxml.jackson.databind.JsonNode;
import org.springframework.stereotype.Service;
import org.springframework.web.client.RestTemplate;

import java.util.LinkedHashMap;
import java.util.Map;

@Service
public class SubscribeMessageService {

    private static final String SEND_URL =
        "https://api.weixin.qq.com/cgi-bin/message/subscribe/send?access_token=%s";

    private final RestTemplate restTemplate;
    private final AccessTokenService accessTokenService;

    public SubscribeMessageService(RestTemplate restTemplate,
                                   AccessTokenService accessTokenService) {
        this.restTemplate = restTemplate;
        this.accessTokenService = accessTokenService;
    }

    /**
     * 下发订单发货通知。
     *
     * @param openid     用户 openid
     * @param templateId 发货通知模板 ID
     * @param goodsName  商品名称（thing 类型，限 20 汉字）
     * @param orderNo    订单号（number 类型）
     * @param orderId    订单主键，用于拼跳转页面
     */
    public void sendShipNotice(String openid, String templateId, String goodsName,
                               String orderNo, long orderId) {
        Map<String, Object> data = new LinkedHashMap<>();
        data.put("thing1", Map.of("value", truncate(goodsName, 20))); // 商品名称
        data.put("number2", Map.of("value", orderNo));                 // 订单号
        data.put("phrase3", Map.of("value", "已发货"));               // 发货状态

        Map<String, Object> body = new LinkedHashMap<>();
        body.put("touser", openid);
        body.put("template_id", templateId);
        body.put("page", "pages/order/detail?id=" + orderId);
        body.put("miniprogram_state", "formal");
        body.put("data", data);

        send(body);
    }

    /**
     * 通用下发：拼 URL、调接口、校验返回码。
     * 返回微信原始返回体，由调用方决定重试或记录。
     */
    public JsonNode send(Map<String, Object> body) {
        String url = String.format(SEND_URL, accessTokenService.getAccessToken());
        JsonNode resp = restTemplate.postForObject(url, body, JsonNode.class);
        int errcode = resp == null ? -1 : resp.path("errcode").asInt(-1);
        if (errcode != 0) {
            // 40001 access_token 失效：清缓存重试一次
            if (errcode == 40001) {
                accessTokenService.invalidate();
                resp = restTemplate.postForObject(
                    String.format(SEND_URL, accessTokenService.getAccessToken()), body, JsonNode.class);
                errcode = resp == null ? -1 : resp.path("errcode").asInt(-1);
            }
            if (errcode != 0) {
                throw new WechatApiException(errcode, resp == null ? "响应为空" : resp.path("errmsg").asText());
            }
        }
        return resp;
    }

    /** thing 类型字段截断：超过 20 个字符截断，避免 47003 */
    private String truncate(String s, int max) {
        if (s == null) {
            return "";
        }
        return s.length() <= max ? s : s.substring(0, max);
    }
}
```

page 参数的注意点：路径不能带域名前缀，不能以斜杠开头（pages/order/detail 而非 /pages/order/detail），不能带 .html 后缀；query 参数用 ? 拼接，多个参数用 & 连接。若用户点击消息时小程序已打开，微信直接在当前会话内打开对应页面；未打开则先拉起小程序再跳转。开发与体验阶段记得把 miniprogram_state 设为 developer/trial，否则消息里跳转的页面在开发版/体验版不可见。

## 下发频率控制与限流

订阅消息的频率约束来自两个层面：平台接口限制与业务体验要求。平台层面，send 接口有每分钟/每日的调用限额，超限返回 45009（接口调用超过限额）或 45011（api minute-quota reach limit），需要退避重试或削峰；access_token 获取每日 2000 次，必须靠缓存压住。业务层面，同一用户频繁收到消息会招致拒收甚至举报，服务端应主动控制单用户、单模板的发送节奏。

业务侧频率控制的两个抓手：一是每用户每模板的发送间隔控制（如同一订单的发货、签收提醒间隔数天，天然低频）；二是批量下发任务的削峰（定时任务分批发送，每批间隔数秒，避免瞬间打满接口限额）。同时把「用户拒收（43101）」视为退订信号：记录后停止对该用户该模板的后续下发，而不是反复重试。

```text
下发频率控制：
1. 平台限额 —— send 接口有调用频率限制，超限返回 45009/45011
2. token 限额 —— access_token 每日 2000 次，必须缓存复用
3. 用户频控 —— 同一用户同一模板控制发送节奏，避免骚扰
4. 批量削峰 —— 大批量发送分批执行，每批间隔数秒
5. 拒收即退订 —— 43101 记录为退订，停止对该用户该模板下发
6. 幂等去重 —— 同一业务事件只发一次，定时任务重跑不重复下发
```

Redis 实现单用户频控与下发去重：

```java
// SubscribeRateLimiter.java —— 下发频控与幂等
import org.springframework.data.redis.core.StringRedisTemplate;
import org.springframework.stereotype.Component;

import java.time.Duration;

@Component
public class SubscribeRateLimiter {

    private final StringRedisTemplate redisTemplate;

    public SubscribeRateLimiter(StringRedisTemplate redisTemplate) {
        this.redisTemplate = redisTemplate;
    }

    /**
     * 同一用户同一模板 N 秒内只允许下发 1 条。
     * 返回 true 表示通过频控可以发送。
     */
    public boolean tryAcquire(String openid, String templateId, long seconds) {
        String key = "subscribe:limit:" + openid + ":" + templateId;
        Boolean ok = redisTemplate.opsForValue().setIfAbsent(key, "1", Duration.ofSeconds(seconds));
        return Boolean.TRUE.equals(ok);
    }

    /**
     * 幂等：同一业务事件（如订单 20260820001 的发货通知）只下发一次。
     * 返回 true 表示该事件尚未下发过。
     */
    public boolean tryMarkSent(String openid, String templateId, String bizKey) {
        String key = "subscribe:sent:" + openid + ":" + templateId + ":" + bizKey;
        Boolean ok = redisTemplate.opsForValue().setIfAbsent(key, "1", Duration.ofDays(30));
        return Boolean.TRUE.equals(ok);
    }
}
```

下发日志必须落库：每次下发记录 openid、模板 ID、业务单号、请求参数摘要、返回 errcode、下发时间。日志表既是排查问题的依据（为什么用户没收到消息），也是数据统计（11.4）与合规审计（授权记录）的基础。批量任务执行时以日志表 + Redis 幂等键双重去重，任务失败重跑不会重复下发。

## 错误码处理与重试

subscribeMessage.send 的成功返回是 {"errcode": 0, "errmsg": "ok"}，其余 errcode 均需按类型处理。错误码分为三类：可自动重试的（40001 token 失效清缓存重试、45009/45011 频率超限退避重试、系统繁忙）、业务性错误不可重试（40003 openid 无效、40037 模板无效、47003 参数不匹配、43101 用户拒收）、配置/权限类错误需人工介入（48001 功能未授权、41030 页面路径错误）。

43101 是最需要正确理解的错误码：它表示用户拒收（未订阅、额度用完、或用户主动关闭），此时下发未消耗额度。把 43101 当系统故障反复重试是典型错误——既浪费调用额度，又不会成功。正确处理是：记录该用户对该模板「无额度/拒收」，在业务侧标记为待补订状态，引导用户重新订阅（小程序端展示订阅按钮）。

```text
常用错误码速查：
1. 0 —— 成功
2. 40001 —— access_token 无效或过期，清缓存重新获取后重试一次
3. 40003 —— openid 无效，检查是否与当前 appid 匹配（公众号/小程序混用常见）
4. 40037 —— 模板 ID 无效，检查 template_id 是否选用且未被下线
5. 41030 —— page 路径不正确，去掉域名前缀与 .html 后缀
6. 43101 —— 用户拒收（无订阅关系或额度用完），不重试，记录退订
7. 45009 / 45011 —— 接口调用超过限额，退避后重试或丢弃
8. 47003 —— 模板参数不匹配，检查 data 键名/类型/长度
9. 48001 —— api 功能未授权，检查小程序类目与接口权限
```

错误码枚举与重试策略实现：

```java
// SubscribeError.java —— 错误码分类
public enum SubscribeError {

    SUCCESS(0, "成功", Retry.NONE),
    INVALID_TOKEN(40001, "access_token 无效", Retry.ONCE),
    INVALID_OPENID(40003, "openid 无效", Retry.NONE),
    INVALID_TEMPLATE(40037, "模板 ID 无效", Retry.NONE),
    BAD_PAGE(41030, "page 路径不正确", Retry.NONE),
    USER_REJECT(43101, "用户拒收", Retry.NONE),
    RATE_LIMIT(45009, "接口调用超过限额", Retry.BACKOFF),
    MINUTE_LIMIT(45011, "频率限制", Retry.BACKOFF),
    DATA_MISMATCH(47003, "模板参数不匹配", Retry.NONE),
    API_FORBIDDEN(48001, "api 功能未授权", Retry.NONE);

    private final int code;
    private final String desc;
    private final Retry retry;

    SubscribeError(int code, String desc, Retry retry) {
        this.code = code;
        this.desc = desc;
        this.retry = retry;
    }

    public int getCode() { return code; }

    public String getDesc() { return desc; }

    public Retry getRetry() { return retry; }

    public enum Retry {
        NONE,      // 业务错误，不重试
        ONCE,      // 重试一次（如 40001 刷新 token）
        BACKOFF    // 退避重试（频率超限）
    }
}
```

```java
// SubscribeSendTask.java —— 带错误处理的批量下发（定时任务）
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.scheduling.annotation.Scheduled;
import org.springframework.stereotype.Component;

import java.util.List;

@Component
public class SubscribeSendTask {

    private static final Logger log = LoggerFactory.getLogger(SubscribeSendTask.class);

    private final SubscribeMessageService subscribeMessageService;
    private final SubscribeRecordMapper recordMapper;
    private final SubscribeRateLimiter rateLimiter;

    public SubscribeSendTask(SubscribeMessageService subscribeMessageService,
                             SubscribeRecordMapper recordMapper,
                             SubscribeRateLimiter rateLimiter) {
        this.subscribeMessageService = subscribeMessageService;
        this.recordMapper = recordMapper;
        this.rateLimiter = rateLimiter;
    }

    /** 每分钟扫描一次待发送的订单提醒，每次最多处理 100 条 */
    @Scheduled(fixedDelay = 60_000)
    public void flushPending() {
        List<PendingMessage> pending = recordMapper.findPending(100);
        for (PendingMessage msg : pending) {
            // 幂等：已发送过的不再处理（任务重跑安全）
            if (!rateLimiter.tryMarkSent(msg.getOpenid(), msg.getTemplateId(), msg.getBizKey())) {
                recordMapper.markSkipped(msg.getId(), "duplicated");
                continue;
            }
            try {
                subscribeMessageService.send(msg.toBody());
                recordMapper.markSuccess(msg.getId());
            } catch (WechatApiException e) {
                SubscribeError error = SubscribeError.valueOf(e.getErrcode());
                if (error.getRetry() == SubscribeError.Retry.NONE) {
                    // 43101 等业务错误：标记为最终失败/退订，不再重试
                    recordMapper.markFailed(msg.getId(), e.getErrcode(), e.getMessage());
                    if (e.getErrcode() == 43101) {
                        recordMapper.markUnsubscribed(msg.getOpenid(), msg.getTemplateId());
                    }
                } else if (error.getRetry() == SubscribeError.Retry.BACKOFF) {
                    // 频率超限：保留待发送状态，等待下一个周期重试
                    recordMapper.markPending(msg.getId());
                    log.warn("订阅下发触发频率限制，稍后重试: {}", e.getMessage());
                    break; // 频率超限时停止本批，避免继续触发
                } else {
                    // 40001：内部已自动刷新 token 重试一次，仍失败则记录
                    recordMapper.markFailed(msg.getId(), e.getErrcode(), e.getMessage());
                }
            } catch (Exception e) {
                // 网络异常等：保留待发送状态，下个周期重试
                recordMapper.markPending(msg.getId());
                log.error("订阅下发网络异常", e);
            }
        }
    }
}
```

重试策略总结：40001 在 send 内部自动刷新 token 重试一次；45009/45011 与网络异常保留待发送状态退避重试（指数退避：1s、2s、4s...封顶 60s）；43101/40003/47003 等业务错误立即终止该条消息，绝不重试；同一批任务中遇到频率超限要中断本批发送，防止继续触发限流。

## 应用场景实战

### 场景一：支付回调后下发支付成功通知

用户完成支付，微信支付回调通知后台，后台确认订单后下发「支付成功通知」订阅消息。完整链路代码：

```java
// PayNotifyController.java —— 支付回调中触发订阅消息下发
import com.fasterxml.jackson.databind.JsonNode;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
@RequestMapping("/api/pay")
public class PayNotifyController {

    private final OrderService orderService;
    private final SubscribeMessageService subscribeMessageService;
    private final SubscribeRateLimiter rateLimiter;

    public PayNotifyController(OrderService orderService,
                               SubscribeMessageService subscribeMessageService,
                               SubscribeRateLimiter rateLimiter) {
        this.orderService = orderService;
        this.subscribeMessageService = subscribeMessageService;
        this.rateLimiter = rateLimiter;
    }

    /**
     * 微信支付结果回调（真实项目需先验签与解密，见 10.3）。
     * 支付成功后：更新订单状态 -> 下发支付成功通知 -> 记录下发日志。
     */
    @PostMapping("/notify")
    public String notify(@RequestBody JsonNode body) {
        // 1. 验签解密后取出商户订单号（此处省略验签细节，见 10.3）
        String outTradeNo = body.path("out_trade_no").asText();
        Order order = orderService.markPaid(outTradeNo);

        // 2. 幂等：同一订单只发一次支付成功通知
        if (!rateLimiter.tryMarkSent(order.getOpenid(), TEMPLATE_ORDER_PAID, "paid:" + outTradeNo)) {
            return "success"; // 已发送过，直接返回
        }

        // 3. 下发支付成功通知（thing 订单号 + amount 实付金额）
        try {
            subscribeMessageService.sendPaidNotice(
                order.getOpenid(),
                TEMPLATE_ORDER_PAID,
                order.getOrderNo(),
                order.getPaidAmountFen(),
                order.getId()
            );
        } catch (WechatApiException e) {
            // 43101 等错误记录日志，不影响支付回调主流程
            log.error("支付成功通知下发失败, order={}, errcode={}", outTradeNo, e.getErrcode());
            if (e.getErrcode() == 43101) {
                orderService.markNeedResubscribe(order.getId(), TEMPLATE_ORDER_PAID);
            }
        }
        return "success";
    }
}
```

### 场景二：定时任务批量下发发货提醒

仓库发货后批量触发通知：发货系统写入待发送队列，定时任务分批下发，处理频率限制与失败重试：

```java
// ShipRemindJob.java —— 发货提醒批量下发
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.scheduling.annotation.Scheduled;
import org.springframework.stereotype.Component;

import java.util.List;

@Component
public class ShipRemindJob {

    private static final Logger log = LoggerFactory.getLogger(ShipRemindJob.class);

    private final ShipTaskMapper taskMapper;
    private final SubscribeMessageService subscribeMessageService;
    private final SubscribeRateLimiter rateLimiter;

    public ShipRemindJob(ShipTaskMapper taskMapper,
                         SubscribeMessageService subscribeMessageService,
                         SubscribeRateLimiter rateLimiter) {
        this.taskMapper = taskMapper;
        this.subscribeMessageService = subscribeMessageService;
        this.rateLimiter = rateLimiter;
    }

    /**
     * 每 30 秒处理一批发货通知，每批 50 条。
     * 控制节奏：单用户单模板 60 秒内最多 1 条。
     */
    @Scheduled(fixedDelay = 30_000)
    public void sendShipNotices() {
        List<ShipTask> tasks = taskMapper.findTodo(50);
        for (ShipTask task : tasks) {
            // 频控：同一用户 60 秒内不重复下发
            if (!rateLimiter.tryAcquire(task.getOpenid(), task.getTemplateId(), 60)) {
                continue; // 该用户暂缓，下个周期再试
            }
            try {
                subscribeMessageService.sendShipNotice(
                    task.getOpenid(),
                    task.getTemplateId(),
                    task.getGoodsName(),
                    task.getOrderNo(),
                    task.getOrderId()
                );
                taskMapper.markSuccess(task.getId());
            } catch (WechatApiException e) {
                if (e.getErrcode() == 43101) {
                    // 用户拒收：标记退订，不再尝试
                    taskMapper.markUnsubscribed(task.getId(), task.getOpenid());
                } else if (e.getErrcode() == 45009 || e.getErrcode() == 45011) {
                    // 触发平台限流：停止本批，等下一个周期
                    log.warn("发货通知触发频率限制，本批暂停: errcode={}", e.getErrcode());
                    break;
                } else {
                    taskMapper.markFailed(task.getId(), e.getErrcode());
                }
            }
        }
    }
}
```

对应的待发送任务表 SQL：

```sql
-- ship_task.sql —— 发货通知待发送任务表
CREATE TABLE ship_task (
    id           BIGINT PRIMARY KEY AUTO_INCREMENT,
    openid       VARCHAR(64)  NOT NULL COMMENT '用户 openid',
    template_id  VARCHAR(64)  NOT NULL COMMENT '订阅消息模板 ID',
    goods_name   VARCHAR(64)  NOT NULL COMMENT '商品名称',
    order_no     VARCHAR(64)  NOT NULL COMMENT '订单号',
    order_id     BIGINT       NOT NULL COMMENT '订单主键',
    status       TINYINT      NOT NULL DEFAULT 0 COMMENT '0待发送 1成功 2失败 3退订',
    errcode      INT          DEFAULT NULL COMMENT '最后一次失败的微信错误码',
    retry_count  INT          NOT NULL DEFAULT 0 COMMENT '重试次数',
    create_time  DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    update_time  DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    KEY idx_status (status),
    KEY idx_openid_template (openid, template_id)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COMMENT ='发货通知待发送任务';
```

批量下发任务的三个要点：任务表状态机（待发送/成功/失败/退订）保证可追踪；Redis 幂等键防止任务重跑重复下发；遇到 45009/45011 立即中断本批，避免继续触发限流把问题扩大。

## 最佳实践与踩坑记录

### 最佳实践

1. access_token 全局缓存 + 提前 5 分钟过期 + 双重检查加锁，单实例 synchronized、多实例用 Redis 分布式锁，杜绝并发回源互相踢 token
2. 模板 ID、AppID、AppSecret 全部配置化（application.yml / 配置中心），AppSecret 只放服务端环境变量，严禁进代码仓库
3. 下发逻辑统一封装为 SendService，data 组装、字段截断、40001 自动重试都在一处处理，业务方只管传业务参数
4. 每次下发必落库（openid、模板、业务单号、errcode、时间），既是排查依据也是统计与合规审计的数据源
5. 43101 一律视为退订信号：标记用户退订状态，停止后续下发，转引导重新订阅
6. 批量发送分批削峰（每批 50-100 条 + 间隔），遇 45009/45011 立即中断本批，等下一周期
7. 幂等设计：同一业务事件（订单号 + 模板 + 用户）只允许下发一次，Redis setIfAbsent 或数据库唯一索引兜底
8. 测试环境用 miniprogram_state=developer/trial，避免正式配置下发到开发版页面跳转失败；上线前用真机完整验证一条消息

### 踩坑记录

```text
坑 1：每次下发都重新获取 access_token
结论：下发偶发失败，报 40001 invalid credential，或 token 频繁失效。
原因：重复调用 /cgi-bin/token 会使之前的 token 立即失效，并发请求互相踢；且每日 2000 次额度很快耗尽返回 45009。
解法：access_token 缓存到 Redis，有效期设 expires_in - 300 秒；获取加锁防并发；只有缓存缺失或 40001 时才回源。

坑 2：多实例部署并发刷新 token 互相失效
结论：集群部署后 token 频繁失效，下发大面积报 40001。
原因：每个实例各自获取 token，A 实例获取后 B 实例再获取，A 的 token 失效。
解法：用 Redis 分布式锁保证全集群同一时刻只有一个实例获取 token；其余实例等待后读缓存；token 存共享 Redis。

坑 3：openid 与 appid 不匹配，报 40003
结论：下发报 40003 invalid openid，但 openid 明明存在。
原因：openid 是公众号/开放平台/其他小程序获取的，与当前小程序 appid 不匹配；不同 appid 下 openid 不通用。
解法：确认 touser 使用当前小程序 code2session 返回的 openid；多端产品按 appid 区分存储用户 openid。

坑 4：page 参数写错报 41030
结论：下发成功但用户点击消息无法跳转，或直接报 41030 页面路径不正确。
原因：page 带了域名前缀、以斜杠开头、带了 .html 后缀，或页面路径在小程序中不存在。
解法：page 填小程序内页面路径（pages/order/detail?id=1），不带域名与后缀；跳转前在小程序里确认路径存在。

坑 5：data 键名与模板不匹配报 47003
结论：下发报 47003 template parameter mismatch，消息发不出去。
原因：模板关键词编号是 thing1/number2/phrase3，代码里写成了 thing01/商品名称 等不存在的键；或 value 类型/长度不符。
解法：以公众平台模板详情里的关键词编号为准；thing 字段先截断到 20 字符；写个单元测试用真实模板数据跑一遍。

坑 6：43101 反复重试，用户被骚扰
结论：43101 错误持续刷日志，部分用户收到重复尝试但永远失败。
原因：把 43101 当临时错误重试；实际上 43101 表示用户拒收/无额度，重试不会成功。
解法：43101 直接标记退订，停止对该用户该模板下发；在业务侧记录待补订状态，前端引导重新订阅。

坑 7：miniprogram_state 没配，测试环境消息跳转失败
结论：测试阶段下发成功，但点击消息跳转的页面打不开。
原因：默认 miniprogram_state=formal（正式版），开发版/体验版页面在正式版环境不可见。
解法：开发测试用 miniprogram_state=developer/trial，正式发布用 formal；多环境配置 template 下发参数。

坑 8：批量任务失败重跑造成重复下发
结论：定时任务超时重跑后，同一用户收到多条相同消息。
原因：任务没有幂等，重跑时重新扫描「待发送」记录再次下发。
解法：下发前用 Redis 幂等键（openid+模板+业务单号）判重，或给下发记录表加唯一索引；已成功记录不再重发。
```

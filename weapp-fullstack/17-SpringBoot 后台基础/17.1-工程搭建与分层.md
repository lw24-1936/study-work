## 概述

Spring Boot 是构建微信小程序后台服务的首选框架，它基于 Spring Framework 自动配置机制，让开发者用最少的配置快速启动一个可运行的 Web 服务。本章以「小程序后台」为目标工程，完整讲解从 Spring Initializr 生成项目、Maven 结构、分层架构、包结构到多环境配置的整套工程搭建方法，后续 17.2-17.5 的所有代码都建立在本章工程之上。

```text
本章核心内容：
1. Spring Initializr —— start.spring.io 在线生成 Spring Boot 3.x 工程骨架
2. Maven 结构 —— pom.xml、parent、starter 依赖、spring-boot-maven-plugin 构建插件
3. 分层架构 —— controller/service/mapper/entity/dto/vo 各层职责与依赖方向
4. 包结构 —— com.example.xxx 根包、启动类必须放在根包位置
5. 配置文件 —— application.yml 与 application-dev/prod.yml 多环境切换
6. 可运行 —— 每一步都有完整可执行的代码与验证命令
```

## Spring Initializr 快速创建工程

Spring Initializr（start.spring.io）是 Spring 官方提供的在线项目生成器，它根据开发者选择的构建工具、语言、Spring Boot 版本与依赖，生成一个可以直接导入 IDE 并启动的完整工程。对于微信小程序后台，一般选择 Maven + Java + Spring Boot 3.x（当前推荐使用 Spring Boot 3.2 以上的稳定版本，要求 JDK 17+），核心依赖包括 Web、MyBatis-Plus（或 MyBatis）、MySQL 驱动、Redis、Lombok 与 Validation。

在 start.spring.io 页面依次选择：Project 选 Maven、Language 选 Java、Spring Boot 选 3.x 最新稳定版、Group 填 com.example、Artifact 填 mall-admin（示例工程名），然后添加依赖。生成的工程通过 zip 下载，解压后就是一个标准 Maven 工程。

```text
start.spring.io 依赖选择（小程序后台标准套餐）：
1. Spring Web —— 提供 MVC 与内嵌 Tomcat，REST 接口的基础
2. MyBatis Framework / MyBatis-Plus —— 数据库访问（17.4 详解）
3. MySQL Driver —— MySQL 8.x JDBC 驱动
4. Spring Data Redis —— Redis 缓存与分布式锁（17.5 详解）
5. Validation —— JSR-380 参数校验（17.3 详解）
6. Lombok —— 简化实体类 getter/setter/构造器样板代码
7. Spring Configuration Processor —— yml 配置提示，可加可不加
```

生成命令同样支持通过 curl 直接拉取，适合团队统一脚手架或 CI 场景。例如生成一个 groupId 为 com.example、artifactId 为 mall-admin 的工程：

```bash
# 用 curl 从 start.spring.io 生成工程 zip（依赖用 dependencies 参数逗号分隔）
curl https://start.spring.io/starter.zip \
  -d type=maven-project \
  -d language=java \
  -d bootVersion=3.2.5 \
  -d groupId=com.example \
  -d artifactId=mall-admin \
  -d name=mall-admin \
  -d packageName=com.example.mall \
  -d javaVersion=17 \
  -d dependencies=web,validation,data-redis,mybatis,mysql,lombok \
  -o mall-admin.zip

# 解压并进入工程目录
unzip mall-admin.zip -d mall-admin
cd mall-admin
```

解压后目录即包含 pom.xml、src/main/java、src/main/resources 与 src/test 四个核心部分。Spring Boot 3.x 要求 JDK 17 以上，2.7.x 及以下版本才是 JDK 8 时代的主流选择；如果是维护老项目且服务器只有 JDK 8，则选择 2.7.x，两者在后续章节的 API 使用上略有差异（如 jakarta 包名与 javax 包名）。

```text
Spring Boot 版本选型：
1. Spring Boot 3.x —— 需要 JDK 17+，javax 全面迁移为 jakarta，推荐新项目使用
2. Spring Boot 2.7.x —— 支持 JDK 8，javax 包名，老项目维护场景
3. 版本尽量用偶数小版本的稳定版，避免用 M 里程碑版与 RC 候选版
4. 团队新项目统一一个版本，避免各人电脑版本不一致导致行为差异
5. 生成后立即用 mvn -v 确认本地 Maven 与 JDK 版本匹配
6. 国内网络下载依赖慢时，在 settings.xml 配置阿里云镜像仓库
```

## Maven 工程结构与 pom.xml

Maven 是 Java 生态的事实标准构建工具，负责依赖管理、编译、测试与打包。Spring Boot 工程的 pom.xml 有三个关键要素：parent 继承（spring-boot-starter-parent 统一管理依赖版本）、starter 依赖（spring-boot-starter-* 按需引入功能模块）、构建插件（spring-boot-maven-plugin 负责把工程打成可执行 jar）。

```xml
<?xml version="1.0" encoding="UTF-8"?>
<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 https://maven.apache.org/xsd/maven-4.0.0.xsd">
    <modelVersion>4.0.0</modelVersion>

    <!-- 继承 Spring Boot 父工程：统一管理 starter 依赖版本，无需手写版本号 -->
    <parent>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-parent</artifactId>
        <version>3.2.5</version>
        <relativePath/>
    </parent>

    <groupId>com.example</groupId>
    <artifactId>mall-admin</artifactId>
    <version>0.0.1-SNAPSHOT</version>
    <name>mall-admin</name>
    <description>微信小程序商城后台服务</description>

    <properties>
        <java.version>17</java.version>
        <mybatis-plus.version>3.5.5</mybatis-plus.version>
    </properties>

    <dependencies>
        <!-- Web：MVC + 内嵌 Tomcat，提供 REST 接口能力 -->
        <dependency>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-web</artifactId>
        </dependency>
        <!-- Validation：JSR-380 参数校验 -->
        <dependency>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-validation</artifactId>
        </dependency>
        <!-- Redis：缓存与分布式锁 -->
        <dependency>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-data-redis</artifactId>
        </dependency>
        <!-- MyBatis-Plus：增强版 MyBatis，自带 CRUD 与分页 -->
        <dependency>
            <groupId>com.baomidou</groupId>
            <artifactId>mybatis-plus-spring-boot3-starter</artifactId>
            <version>${mybatis-plus.version}</version>
        </dependency>
        <!-- MySQL 驱动 -->
        <dependency>
            <groupId>com.mysql</groupId>
            <artifactId>mysql-connector-j</artifactId>
            <scope>runtime</scope>
        </dependency>
        <!-- Lombok：编译期生成样板代码 -->
        <dependency>
            <groupId>org.projectlombok</groupId>
            <artifactId>lombok</artifactId>
            <optional>true</optional>
        </dependency>
        <!-- 测试 -->
        <dependency>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-test</artifactId>
            <scope>test</scope>
        </dependency>
    </dependencies>

    <build>
        <plugins>
            <!-- 打包插件：生成可执行 fat jar，mvn package 后 java -jar 直接运行 -->
            <plugin>
                <groupId>org.springframework.boot</groupId>
                <artifactId>spring-boot-maven-plugin</artifactId>
                <configuration>
                    <excludes>
                        <exclude>
                            <groupId>org.projectlombok</groupId>
                            <artifactId>lombok</artifactId>
                        </exclude>
                    </excludes>
                </configuration>
            </plugin>
        </plugins>
    </build>
</project>
```

starter 是 Spring Boot 的依赖聚合机制：一个 starter 把某个功能所需的全部 jar（含传递依赖）打包成一组，开发者只需引入一个坐标，Spring Boot 自动配置就会生效。例如 spring-boot-starter-web 包含 spring-web、spring-webmvc、内嵌 Tomcat、jackson 等；spring-boot-starter-data-redis 包含 lettuce 客户端与 spring-data-redis。

```text
Maven 核心命令与机制：
1. mvn clean —— 清理 target 目录
2. mvn compile —— 编译主代码到 target/classes
3. mvn package —— 打包，配合 spring-boot-maven-plugin 生成可执行 jar
4. mvn spring-boot:run —— 直接以 Maven 方式启动应用
5. mvn dependency:tree —— 查看依赖树，排查依赖冲突
6. 版本号管理：继承 parent 的依赖不用写版本，第三方依赖（如 MyBatis-Plus）显式声明版本
```

## 经典分层架构

Spring Boot 后台工程采用经典的分层架构（Layered Architecture），按职责把代码划分为表现层、业务层、数据访问层与领域模型层。分层的核心价值是「依赖方向单一」：上层依赖下层，下层不反向依赖上层，每一层只做自己的事，可独立测试、可替换实现。

```text
小程序后台分层职责：
1. controller —— 表现层：接收 HTTP 请求、参数校验入口、调用 service、返回 Result
2. service —— 业务层：业务逻辑、事务边界、调用 mapper 与其他 service
3. mapper —— 数据访问层：数据库 SQL 操作（MyBatis-Plus BaseMapper 或 XML）
4. entity —— 实体层：与数据库表一一对应的 POJO
5. dto —— 数据传输对象：接口入参/出参，与 entity 解耦，防止表结构直接暴露
6. vo —— 视图对象：面向页面展示的聚合数据，如分页 VO、用户 VO
7. 依赖方向：controller -> service -> mapper，entity/dto/vo 被各层引用但不互相依赖
```

一个商品列表查询的典型调用链：Controller 接收 GET 请求参数 -> 组装成 QueryDTO 调用 Service -> Service 校验业务规则并调用 Mapper -> Mapper 执行 SQL 返回 Entity -> Service 把 Entity 转换为 VO 返回 -> Controller 用 Result 包装后响应。示例代码如下：

```java
// controller/ProductController.java —— 表现层，只做参数接收与结果包装
package com.example.mall.controller;

import com.example.mall.common.Result;
import com.example.mall.dto.ProductQueryDTO;
import com.example.mall.service.ProductService;
import com.example.mall.vo.ProductVO;
import jakarta.validation.Valid;
import lombok.RequiredArgsConstructor;
import org.springframework.web.bind.annotation.*;

import java.util.List;

@RestController
@RequestMapping("/api/products")
@RequiredArgsConstructor
public class ProductController {

    private final ProductService productService;

    @GetMapping
    public Result<List<ProductVO>> list(@Valid ProductQueryDTO query) {
        return Result.success(productService.listProducts(query));
    }

    @GetMapping("/{id}")
    public Result<ProductVO> detail(@PathVariable Long id) {
        return Result.success(productService.getProduct(id));
    }
}
```

```java
// service/ProductService.java —— 业务层，承载业务规则与事务
package com.example.mall.service;

import com.example.mall.dto.ProductQueryDTO;
import com.example.mall.vo.ProductVO;
import org.springframework.transaction.annotation.Transactional;

import java.util.List;

public interface ProductService {

    List<ProductVO> listProducts(ProductQueryDTO query);

    @Transactional(readOnly = true)
    ProductVO getProduct(Long id);
}
```

```java
// mapper/ProductMapper.java —— 数据访问层
package com.example.mall.mapper;

import com.baomidou.mybatisplus.core.mapper.BaseMapper;
import com.example.mall.entity.Product;
import org.apache.ibatis.annotations.Mapper;

@Mapper
public interface ProductMapper extends BaseMapper<Product> {
}
```

```java
// entity/Product.java —— 实体层，对应 product 表
package com.example.mall.entity;

import com.baomidou.mybatisplus.annotation.IdType;
import com.baomidou.mybatisplus.annotation.TableId;
import com.baomidou.mybatisplus.annotation.TableName;
import lombok.Data;

import java.math.BigDecimal;
import java.time.LocalDateTime;

@Data
@TableName("product")
public class Product {

    @TableId(type = IdType.AUTO)
    private Long id;

    private String name;

    private BigDecimal price;

    private Integer stock;

    private Integer status;

    private LocalDateTime createTime;

    private LocalDateTime updateTime;
}
```

```text
分层架构要点：
1. Controller 禁止写业务逻辑与直接操作数据库，只做参数绑定与结果返回
2. Service 是事务边界所在，@Transactional 只能加在 Service 方法上
3. Mapper 只负责数据访问，不出现业务判断
4. Entity 不直接暴露给前端，接口出入参一律用 DTO/VO
5. 层间用接口而非实现类依赖（面向接口编程），方便 mock 与替换
6. 各层命名规范统一：XxxController、XxxService/XxxServiceImpl、XxxMapper
```

## 包结构与启动类位置

包结构（Package Structure）按「域 + 层」组合组织：根包是 groupId 对应的 com.example.mall，启动类放在根包下，其余按业务域拆分子包。启动类（标注 @SpringBootApplication 的类）的位置有硬性要求：必须放在根包（com.example.mall）下，因为 @SpringBootApplication 默认扫描它所在包及其子包，放错位置会导致组件扫描不到、接口 404。

```text
推荐包结构（com.example.mall 根包）：
com.example.mall
├── MallAdminApplication.java      # 启动类（必须在根包！）
├── config/                        # 配置类：MybatisPlusConfig、RedisConfig、CorsConfig 等
├── controller/                    # 表现层：UserController、ProductController、OrderController
├── service/                       # 业务接口：UserService、ProductService
│   └── impl/                      # 业务实现：UserServiceImpl、ProductServiceImpl
├── mapper/                        # 数据访问：UserMapper、ProductMapper + mapper XML 目录
├── entity/                        # 实体：User、Product、Order
├── dto/                           # 入参对象：LoginDTO、ProductQueryDTO
├── vo/                            # 出参对象：UserVO、PageResult
├── common/                        # 通用：Result、BusinessException、ErrorCode、全局异常处理
├── enums/                         # 枚举：OrderStatusEnum、ErrorCodeEnum
├── util/                          # 工具：JwtUtil、IdGenerator
└── interceptor/                   # 拦截器：LoginInterceptor、TraceIdFilter
```

启动类代码是最简单也最容易放错位置的文件。它本身只做三件事：标注 @SpringBootApplication、定义 main 方法、调用 SpringApplication.run：

```java
// 必须位于根包 com.example.mall 下
package com.example.mall;

import org.mybatis.spring.annotation.MapperScan;
import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;
import org.springframework.scheduling.annotation.EnableScheduling;

@SpringBootApplication
@MapperScan("com.example.mall.mapper")   // 批量注册 Mapper，替代逐个 @Mapper
@EnableScheduling                         // 开启定时任务（可选）
public class MallAdminApplication {

    public static void main(String[] args) {
        SpringApplication.run(MallAdminApplication.class, args);
    }
}
```

@SpringBootApplication 是一个组合注解，等价于 @SpringBootConfiguration + @EnableAutoConfiguration + @ComponentScan（默认扫描启动类所在包及其子包）。因此凡是需要被 Spring 管理的组件（@Controller、@Service、@Component、@Configuration），都必须放在根包之下；放到根包之外则扫描不到，运行时报「NoSuchBeanDefinitionException」或接口 404。

```text
启动类与包结构注意点：
1. 启动类必须放在根包，这是组件扫描的默认边界
2. @MapperScan 写在启动类上批量扫描 Mapper 接口，避免每个 Mapper 加 @Mapper
3. 新增的类先确认包路径是否在根包之下，再写代码
4. 子包按业务域划分（user/order/product），域内再分 controller/service
5. config 包集中放 @Configuration 配置类，避免配置散落
6. 单元测试类放在 src/test/java 的同名包下，测试启动类可直接 @SpringBootTest 引用主启动类
```

## 配置文件与多环境

Spring Boot 使用 application.yml（或 application.properties）集中管理配置，支持多环境 profile 拆分：application.yml 放公共配置，application-dev.yml / application-prod.yml 放各环境差异配置，通过 spring.profiles.active 激活。小程序后台开发期连本地 MySQL/Redis，生产期连云服务器，多环境配置是上线前必须做好的基本功。

```yaml
# src/main/resources/application.yml —— 公共配置
server:
  port: 8080
  servlet:
    context-path: /api        # 统一前缀，所有接口路径以 /api 开头

spring:
  profiles:
    active: dev               # 激活的环境：dev / prod，可用 -Dspring.profiles.active 覆盖
  application:
    name: mall-admin
  jackson:
    date-format: yyyy-MM-dd HH:mm:ss
    time-zone: GMT+8

mybatis-plus:
  configuration:
    map-underscore-to-camel-case: true   # 下划线字段自动映射驼峰属性
    log-impl: org.apache.ibatis.logging.stdout.StdOutImpl  # 开发期打印 SQL
  global-config:
    db-config:
      id-type: auto
      logic-delete-field: deleted        # 逻辑删除字段（17.4 详解）
```

```yaml
# src/main/resources/application-dev.yml —— 本地开发环境
spring:
  datasource:
    driver-class-name: com.mysql.cj.jdbc.Driver
    url: jdbc:mysql://localhost:3306/mall?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai
    username: root
    password: root123
  data:
    redis:
      host: localhost
      port: 6379
      database: 0
      password:

logging:
  level:
    com.example.mall: debug      # 项目包日志级别 debug，方便开发期排查
    org.springframework: warn
```

```yaml
# src/main/resources/application-prod.yml —— 生产环境（敏感信息用环境变量注入，不写死）
spring:
  datasource:
    driver-class-name: com.mysql.cj.jdbc.Driver
    url: jdbc:mysql://${MYSQL_HOST}:${MYSQL_PORT}/${MYSQL_DB}?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai
    username: ${MYSQL_USER}
    password: ${MYSQL_PASSWORD}
  data:
    redis:
      host: ${REDIS_HOST}
      port: ${REDIS_PORT}
      database: 1
      password: ${REDIS_PASSWORD}

logging:
  level:
    com.example.mall: info
  file:
    name: /var/log/mall-admin/app.log    # 日志落盘路径
```

启动时通过命令行参数指定激活环境：开发机直接 `mvn spring-boot:run -Dspring-boot.run.profiles=dev`，生产服务器用 `java -jar mall-admin-0.0.1-SNAPSHOT.jar --spring.profiles.active=prod`。除 profile 外，配置的优先级从高到低依次为：命令行参数 > Java 系统属性 > 环境变量 > application-{profile}.yml > application.yml > 默认值，理解这个优先级可以解决「改了配置不生效」的排查问题。

```text
配置文件要点：
1. 公共配置放 application.yml，环境差异配置放 application-{env}.yml
2. 生产环境密码、密钥一律用环境变量或配置中心注入，禁止明文提交 Git
3. server.port 默认 8080，小程序 request 合法域名要求 HTTPS + 443，部署时由 Nginx 转发
4. context-path 统一 /api 前缀，与小程序端 request 封装、Nginx 反代规则保持一致
5. 配置优先级：命令行参数 > 系统属性 > 环境变量 > profile 文件 > 默认值
6. 修改配置后需重启生效（@ConfigurationProperties 可配 refresh 但默认不支持热更新）
```

## 应用场景实战

### 场景一：从 start.spring.io 生成工程并启动第一个接口

完整流程：生成工程 -> 导入 IDE -> 写一个健康检查接口 -> mvn 启动 -> curl 验证。

```text
步骤：
1. 浏览器打开 start.spring.io，选择 Maven + Java 17 + Spring Boot 3.2.x
2. Group 填 com.example，Artifact 填 mall-admin，依赖勾选 Web / Validation / MySQL / Lombok
3. 点击 GENERATE 下载 mall-admin.zip，解压后用 IDEA 以 Maven 工程导入
4. 在根包下新建 controller/HelloController.java（见下方代码）
5. 终端执行 mvn spring-boot:run 启动，观察控制台 "Started MallAdminApplication"
6. 新开终端执行 curl http://localhost:8080/api/hello 验证返回
```

```java
package com.example.mall.controller;

import com.example.mall.common.Result;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
@RequestMapping("/hello")
public class HelloController {
```

## 最佳实践与踩坑记录

### 最佳实践

1. 新项目一律用 Spring Boot 3.x + JDK 17+，不要为了「兼容旧环境」启动新项目还用 2.x，后续升级成本远大于迁移成本
2. 依赖版本交给 parent 统一管理，第三方库（MyBatis-Plus、Redisson）单独声明版本并抽取到 properties 里，便于统一升级
3. 启动类固定在根包，全团队遵守「根包之下」的放置规则，用 @MapperScan 批量注册 Mapper
4. 配置文件按 dev/prod 拆分，生产配置全部走环境变量，配合 .gitignore 防止敏感信息入库
5. 接口统一加 /api 前缀（context-path 或 Controller 前缀），与 Nginx 反代、小程序合法域名配置天然对齐
6. Controller 只做「接参数、调 service、包 Result」，业务逻辑与事务一律下沉 Service，这是后续一切规范的地基
7. 每个业务域（user/order/product）建立独立子包，域内再分 controller/service/mapper，避免包结构按「技术分层优先」导致后期混乱
8. 工程创建后立即提交 Git 并在 README 写明启动方式、JDK 版本、依赖的 MySQL/Redis 版本，团队协作零门槛

### 踩坑记录

```text
坑 1：启动类没放在根包，所有 Controller 扫描不到，接口全部 404
结论：接口 404 且控制台无任何映射日志，spring 容器里找不到 Controller Bean。
原因：@SpringBootApplication 的组件扫描默认以启动类所在包为根，启动类放错位置导致扫描范围错误。
解法：把启动类移到根包（如 com.example.mall），确认所有组件类都在根包及其子包下。

坑 2：8080 端口被占用，启动报 Port 8080 was already in use
结论：应用启动失败，报 Address already in use: bind。
原因：本地已有进程占用 8080（如上次未关闭的 java 进程、其他服务）。
解法：lsof -i:8080 找到 PID 后 kill，或修改 server.port；优先 kill 旧进程避免端口越改越乱。

坑 3：Maven 依赖下载慢或失败，构建卡在 Downloading
结论：首次构建长时间卡在下载，甚至报 Cannot resolve ... dependency 错误。
原因：默认中央仓库 maven.aliyun 网络访问慢或不稳定，代理环境更是经常失败。
解法：在 ~/.m2/settings.xml 配置阿里云镜像 <mirror>，同时配置 JDK 8 之外的镜像时注意仓库 id 冲突。

坑 4：application.yml 缩进写错，启动报 YAML parse error
结论：启动直接失败，报 org.yaml.snakeyaml.parser.ParserException。
原因：YAML 对缩进严格敏感，Tab 与空格混用、冒号后少空格都会解析失败。
解法：统一用两个空格缩进，禁止 Tab；IDEA 中开启 yml 语法校验；出错时看报错行号附近。

坑 5：JDK 版本与 Spring Boot 版本不匹配，启动报 UnsupportedClassVersionError
结论：启动报 java.lang.UnsupportedClassVersionError: 类文件版本错误。
原因：Spring Boot 3.x 编译目标为 JDK 17，本地却是 JDK 8/11。
解法：安装 JDK 17+ 并切换 JAVA_HOME；确认 IDEA 的 Project SDK 与 Maven 使用的 JDK 一致（Settings - Build Tools - Maven - JDK）。

坑 6：改了 application.yml 不生效，配置还是旧值
结论：明明改了端口/数据源，启动后行为没变。
原因：配置优先级冲突——命令行参数、环境变量、系统属性的优先级高于 application.yml，或者 IDE 里缓存了旧配置。
解法：用 --spring.profiles.active 与 --server.port 显式覆盖排查；确认激活的是哪个 profile；重启 IDE 清理缓存再试。

坑 7：Lombok 注解不生效，报 cannot find symbol getXxx()
结论：编译报错，找不到实体类的 getter/setter 方法。
原因：未安装 Lombok 插件（IDEA 需启用 Annotation Processing），或依赖 scope 配置问题。
解法：IDEA 安装 Lombok 插件并勾选 Settings - Build - Compiler - Annotation Processors - Enable annotation processing；确认 pom 中 lombok 依赖存在。

坑 8：多环境切换后连错数据库，数据被写进错误环境
结论：开发环境联调时发现数据出现在生产库或测试库。
原因：spring.profiles.active 没生效或配置覆盖，误连了其他环境的数据库。
解法：启动时强制 --spring.profiles.active=prod 并用日志/数据库名双重确认；生产数据库账号与开发隔离，最小权限原则。
```

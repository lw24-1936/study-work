## 概述

小程序端传来的参数不可信，后台必须做两层防线：第一层是声明式参数校验（JSR-380 / Bean Validation），用注解声明规则，框架自动校验；第二层是结构化日志（SLF4J + Logback），把请求、异常、业务关键事件记录下来，配合 traceId 串联一次请求的完整链路。参数校验保证「坏数据进不来」，日志保证「出了问题查得到」。

```text
本章核心内容：
1. validation 校验 —— spring-boot-starter-validation 与 JSR-380 规范
2. 校验注解 —— @NotNull/@NotBlank/@Size/@Pattern/@Email 等常用注解
3. 分组校验 —— groups 分组 + @Validated(GroupA.class) 按场景差异化校验
4. 自定义校验 —— @Constraint 组合注解 + ConstraintValidator 实现
5. 日志框架 —— SLF4J 门面 + Logback 实现，logback-spring.xml 滚动配置
6. traceId 链路 —— MDC 存 traceId、过滤器生成、日志格式统一、敏感信息脱敏
```

## 参数校验基础与常用注解

Bean Validation（JSR-380）是 Java 官方的声明式校验规范，Spring Boot 通过 spring-boot-starter-validation 引入 Hibernate Validator 实现。用法是给 DTO 字段加校验注解，框架在校验不通过时抛出异常，由 17.2 的全局异常处理器统一转成 Result。校验注解本身是元数据，与业务代码解耦，规则一目了然。

```xml
<!-- pom.xml 依赖：Spring Boot 3.x 引入 validation starter -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-validation</artifactId>
</dependency>
```

常用校验注解按「非空校验、内容校验、格式校验、数值校验」四类划分。注意 @NotNull 与 @NotBlank 的区别：@NotNull 只检查非 null（空字符串 "" 会通过），@NotBlank 检查非 null 且去掉首尾空格后长度大于 0（字符串场景首选）；@NotEmpty 用于集合/数组/字符串非空。格式类注解 @Pattern 用正则表达式，@Email 校验邮箱格式（宽松校验，只查基本格式）。

```java
// dto/UserRegisterDTO.java —— 常用注解全覆盖示例
package com.example.mall.dto;

import jakarta.validation.constraints.*;
import lombok.Data;

import java.math.BigDecimal;

@Data
public class UserRegisterDTO {

    @NotBlank(message = "用户名不能为空")
    @Size(min = 3, max = 20, message = "用户名长度必须在 3-20 之间")
    private String username;

    @NotBlank(message = "密码不能为空")
    @Size(min = 6, max = 32, message = "密码长度必须在 6-32 之间")
    private String password;

    @NotBlank(message = "昵称不能为空")
    @Size(max = 30, message = "昵称最长 30 个字符")
    private String nickname;

    @Email(message = "邮箱格式不正确")
    private String email;

    @Pattern(regexp = "^1[3-9]\\d{9}$", message = "手机号格式不正确")
    private String phone;

    @Min(value = 1, message = "年龄最小为 1")
    @Max(value = 150, message = "年龄最大为 150")
    private Integer age;

    @DecimalMin(value = "0.01", message = "充值金额最小 0.01 元")
    @DecimalMax(value = "10000.00", message = "充值金额最大 10000 元")
    private BigDecimal rechargeAmount;

    @NotNull(message = "性别不能为空")
    private Integer gender;

    @AssertTrue(message = "必须同意用户协议")
    private Boolean agreed;
}
```

```text
校验注解速查：
1. @NotNull —— 值不能为 null（不检查空串）；@NotBlank —— 字符串非 null 且去空格后非空
2. @NotEmpty —— 集合/Map/数组/字符串不能为空
3. @Size(min,max) —— 字符串长度、集合大小范围
4. @Min/@Max —— 数值最小值/最大值；@DecimalMin/@DecimalMax —— BigDecimal 场景
5. @Pattern —— 正则表达式校验（手机号、身份证等自定义格式）
6. @Email —— 邮箱格式；@AssertTrue/@AssertFalse —— 布尔条件（勾选协议等）
```

## DTO 校验与 Controller 触发

校验注解只声明规则，必须由 @Valid 或 @Validated 触发才会生效。Controller 层有两种典型触发场景：@RequestBody 参数（POST/PUT 的 JSON 体）加 @Valid 或 @Validated，校验失败抛 MethodArgumentNotValidException；GET 查询参数直接绑定到 DTO 字段时加 @Validated，校验失败抛 BindException。两种异常在 17.2 的全局处理器中都已处理，返回统一 Result。

```java
// controller/UserController.java —— 两种触发方式
package com.example.mall.controller;

import com.example.mall.common.Result;
import com.example.mall.dto.UserRegisterDTO;
import com.example.mall.dto.UserQueryDTO;
import com.example.mall.service.UserService;
import com.example.mall.vo.UserVO;
import jakarta.validation.Valid;
import lombok.RequiredArgsConstructor;
import org.springframework.validation.annotation.Validated;
import org.springframework.web.bind.annotation.*;

import java.util.List;

@RestController
@RequestMapping("/users")
@RequiredArgsConstructor
@Validated          // 类级 @Validated：让 @PathVariable/@RequestParam 上的校验注解生效
public class UserController {

    private final UserService userService;

    /** @RequestBody 场景：@Valid 触发 DTO 字段校验 */
    @PostMapping("/register")
    public Result<Long> register(@Valid @RequestBody UserRegisterDTO dto) {
        return Result.success(userService.register(dto));
    }

    /** GET 查询参数绑定 DTO 场景：@Validated 触发校验 */
    @GetMapping
    public Result<List<UserVO>> list(@Validated UserQueryDTO query) {
        return Result.success(userService.listUsers(query));
    }

    /** 路径参数校验：依赖类级 @Validated */
    @GetMapping("/{id}")
    public Result<UserVO> detail(@PathVariable @Min(value = 1, message = "id 必须大于 0") Long id) {
        return Result.success(userService.getUser(id));
    }
}
```

```java
// dto/UserQueryDTO.java —— GET 查询参数 DTO
package com.example.mall.dto;

import jakarta.validation.constraints.Max;
import jakarta.validation.constraints.Min;
import jakarta.validation.constraints.Pattern;
import lombok.Data;

@Data
public class UserQueryDTO {

    @Min(value = 1, message = "页码最小为 1")
    private Integer pageNum = 1;

    @Min(value = 1, message = "每页条数最小为 1")
    @Max(value = 100, message = "每页条数最大为 100")
    private Integer pageSize = 10;

    @Pattern(regexp = "^[a-zA-Z0-9_-]{1,20}$", message = "关键字格式不正确")
    private String keyword;
}
```

一个高频误区：只加了 @Valid 但没引入 validation starter，注解是 jakarta.validation 包下的接口，缺依赖会直接编译不过；另一个误区是 GET 参数校验失败抛的是 BindException 而不是 MethodArgumentNotValidException，两个处理器都要写。校验失败时 Spring 会把所有字段错误收集在 BindingResult 里，全局处理器用 getFieldErrors() 逐条取 defaultMessage 拼接，前端能一次看到所有问题字段。

```text
校验触发要点：
1. @RequestBody 场景用 @Valid（或 @Validated），失败抛 MethodArgumentNotValidException
2. GET 参数绑定 DTO 场景用 @Validated，失败抛 BindException
3. @PathVariable/@RequestParam 上的校验注解需要类级 @Validated 才能生效
4. 校验注解必须配合 validation starter，否则 jakarta.validation 包缺失编译失败
5. message 属性写用户可读文案，全局处理器拼接后直接展示给用户
6. 校验失败默认快速失败（FastFail）还是收集全部错误，由 provider 配置决定
```

## 分组校验与自定义校验

分组校验解决「同一个 DTO 在不同场景规则不同」的问题：例如用户注册时 username 必填，更新资料时 username 可空。做法是定义 marker 接口（分组标识），注解上用 groups 属性指定分组，Controller 用 @Validated(GroupA.class) 指定激活哪个分组。不写 groups 的注解属于默认分组（Default）。

```java
// dto/group/CreateGroup.java 与 UpdateGroup.java —— 分组标识（空接口即可）
package com.example.mall.dto.group;

public interface CreateGroup {
}
```

```java
package com.example.mall.dto.group;

public interface UpdateGroup {
}
```

```java
// dto/UserDTO.java —— 分组差异化校验
package com.example.mall.dto;

import com.example.mall.dto.group.CreateGroup;
import com.example.mall.dto.group.UpdateGroup;
import jakarta.validation.constraints.NotBlank;
import jakarta.validation.constraints.NotNull;
import jakarta.validation.constraints.Null;
import lombok.Data;

@Data
public class UserDTO {

    /** 新增时 id 必须为空（由数据库自增），更新时 id 必填 */
    @Null(groups = CreateGroup.class, message = "新增时不能传 id")
    @NotNull(groups = UpdateGroup.class, message = "更新时必须传 id")
    private Long id;

    /** 仅新增时必填，更新时可空 */
    @NotBlank(groups = CreateGroup.class, message = "用户名不能为空")
    private String username;

    @NotBlank(message = "昵称不能为空")
    private String nickname;
}
```

```java
// Controller 中按场景激活分组
@PostMapping
public Result<Long> create(@Validated(CreateGroup.class) @RequestBody UserDTO dto) {
    return Result.success(userService.create(dto));
}

@PutMapping("/{id}")
public Result<Void> update(@PathVariable Long id,
                           @Validated(UpdateGroup.class) @RequestBody UserDTO dto) {
    dto.setId(id);
    userService.update(dto);
    return Result.success();
}
```

自定义校验注解用于内置注解表达不了的业务规则，例如「密码必须包含数字与字母」。实现分两步：定义标注 @Constraint 的注解，实现 ConstraintValidator 接口写校验逻辑。自定义注解可以组合多个内置注解（组合约束），也可以完全自定义逻辑。

```java
// annotation/PasswordValid.java —— 自定义校验注解
package com.example.mall.annotation;

import com.example.mall.validation.PasswordValidator;
import jakarta.validation.Constraint;
import jakarta.validation.Payload;

import java.lang.annotation.*;

@Documented
@Constraint(validatedBy = PasswordValidator.class)
@Target({ElementType.FIELD, ElementType.PARAMETER})
@Retention(RetentionPolicy.RUNTIME)
public @interface PasswordValid {

    String message() default "密码必须包含字母和数字，且长度 8-20 位";

    Class<?>[] groups() default {};

    Class<? extends Payload>[] payload() default {};
}
```

```java
// validation/PasswordValidator.java —— 校验逻辑实现
package com.example.mall.validation;

import com.example.mall.annotation.PasswordValid;
import jakarta.validation.ConstraintValidator;
import jakarta.validation.ConstraintValidatorContext;

public class PasswordValidator implements ConstraintValidator<PasswordValid, String> {

    @Override
    public boolean isValid(String value, ConstraintValidatorContext context) {
        if (value == null) {
            return true;   // 非空性由 @NotBlank 负责，本校验器不管 null
        }
        boolean hasLetter = value.chars().anyMatch(Character::isLetter);
        boolean hasDigit = value.chars().anyMatch(Character::isDigit);
        return value.length() >= 8 && value.length() <= 20 && hasLetter && hasDigit;
    }
}
```

```text
分组与自定义校验要点：
1. 分组用空接口做标识，注解 groups 属性指定所属分组，未指定的归 Default 分组
2. @Validated(XxxGroup.class) 激活分组后，只校验属于该组及 Default 组的注解
3. 自定义注解必须标注 @Constraint 并声明 message/groups/payload 三个属性
4. ConstraintValidator 中 value 为 null 时通常返回 true，非空判断交给 @NotBlank
5. 自定义校验器在 Spring 容器中可注入依赖（如查库校验用户名唯一），写进 isValid 即可
6. 组合约束：用多个内置注解标注自定义注解，实现「一个注解 = 多条规则」
```

## SLF4J 与 Logback 日志框架

SLF4J 是日志门面（Facade），Logback 是底层实现，两者都是 Log4j 作者 Ceki 的作品，Spring Boot 默认日志栈就是「SLF4J + Logback + Log4j2 适配」。业务代码只面向 org.slf4j.Logger 编程，不直接依赖 Logback 类，底层实现可以无缝切换。日志级别从低到高：TRACE < DEBUG < INFO < WARN < ERROR，日志框架只输出「大于等于配置级别」的日志。

```java
// 日志使用规范：类内声明 Logger 的两种方式
package com.example.mall.service.impl;

import lombok.extern.slf4j.Slf4j;
import org.springframework.stereotype.Service;

@Slf4j          // Lombok 自动生成 private static final Logger log
@Service
public class OrderServiceImpl {

    public void createOrder(Long productId, Integer quantity) {
        // 占位符 {} 代替字符串拼接，避免无谓的对象创建
        log.debug("开始创建订单：productId={}, quantity={}", productId, quantity);

        try {
            // 业务逻辑...
        } catch (Exception e) {
            // error 级别必须带异常对象，堆栈才能打印
            log.error("创建订单失败：productId={}", productId, e);
        }
    }
}
```

```java
// 不用 Lombok 时手动声明（效果等价）
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;

public class OrderServiceImpl {
    private static final Logger log = LoggerFactory.getLogger(OrderServiceImpl.class);
}
```

logback-spring.xml 放在 src/main/resources 下，负责日志格式、级别、输出目标（控制台/文件）与滚动策略。生产环境要求：按天滚动、保留 N 天、单文件大小限制、ERROR 单独归档，这样排查问题时按日期翻日志即可。注意文件名必须是 logback-spring.xml（带 -spring），Spring Boot 才会用自身的扩展机制处理其中的 profile 标签。

```xml
<!-- src/main/resources/logback-spring.xml -->
<?xml version="1.0" encoding="UTF-8"?>
<configuration>

    <!-- 日志格式：时间 | 级别 | traceId | 线程 | 类名:行号 | 消息 -->
    <property name="PATTERN"
              value="%d{yyyy-MM-dd HH:mm:ss.SSS} [%level] [%X{traceId:-}] [%thread] %logger{36}:%line - %msg%n"/>

    <!-- 控制台输出：开发环境用 -->
    <appender name="CONSOLE" class="ch.qos.logback.core.ConsoleAppender">
        <encoder>
            <pattern>${PATTERN}</pattern>
            <charset>UTF-8</charset>
        </encoder>
    </appender>

    <!-- 滚动文件输出：按天 + 大小双维度滚动 -->
    <appender name="FILE" class="ch.qos.logback.core.rolling.RollingFileAppender">
        <file>/var/log/mall-admin/app.log</file>
        <rollingPolicy class="ch.qos.logback.core.rolling.SizeAndTimeBasedRollingPolicy">
            <!-- 按天滚动，%i 是当天内超过大小上限后的序号 -->
            <fileNamePattern>/var/log/mall-admin/app.%d{yyyy-MM-dd}.%i.log</fileNamePattern>
            <maxFileSize>100MB</maxFileSize>
            <maxHistory>30</maxHistory>
            <totalSizeCap>10GB</totalSizeCap>
        </rollingPolicy>
        <encoder>
            <pattern>${PATTERN}</pattern>
            <charset>UTF-8</charset>
        </encoder>
    </appender>

    <!-- ERROR 单独归档，排查问题只看 error 日志 -->
    <appender name="ERROR_FILE" class="ch.qos.logback.core.rolling.RollingFileAppender">
        <file>/var/log/mall-admin/error.log</file>
        <filter class="ch.qos.logback.classic.filter.LevelFilter">
            <level>ERROR</level>
            <onMatch>ACCEPT</onMatch>
            <onMismatch>DENY</onMismatch>
        </filter>
        <rollingPolicy class="ch.qos.logback.core.rolling.SizeAndTimeBasedRollingPolicy">
            <fileNamePattern>/var/log/mall-admin/error.%d{yyyy-MM-dd}.%i.log</fileNamePattern>
            <maxFileSize>100MB</maxFileSize>
            <maxHistory>30</maxHistory>
        </rollingPolicy>
        <encoder>
            <pattern>${PATTERN}</pattern>
            <charset>UTF-8</charset>
        </encoder>
    </appender>

    <!-- 环境差异化：dev 输出 debug 到控制台，prod 输出 info 到文件 -->
    <springProfile name="dev">
        <root level="INFO">
            <appender-ref ref="CONSOLE"/>
        </root>
        <logger name="com.example.mall" level="DEBUG"/>
    </springProfile>

    <springProfile name="prod">
        <root level="INFO">
            <appender-ref ref="CONSOLE"/>
            <appender-ref ref="FILE"/>
            <appender-ref ref="ERROR_FILE"/>
        </root>
        <logger name="com.example.mall" level="INFO"/>
    </springProfile>
</configuration>
```

```text
日志框架要点：
1. SLF4J 门面 + Logback 实现，业务代码只 import org.slf4j，实现可替换
2. 日志格式统一：时间 | 级别 | traceId | 线程 | 类:行号 | 消息，全团队一致
3. 占位符 {} 传参，禁止字符串拼接；error 级别必须带异常对象 e 才能打堆栈
4. 生产配置按天滚动 + maxHistory 保留 30 天 + 大小上限，防止磁盘写满
5. ERROR 单独归档，配合监控告警按错误文件做聚合
6. 文件名必须 logback-spring.xml，才能使用 springProfile 做环境差异化
```

## traceId 链路与日志规范

traceId 是一次请求的全局唯一标识：小程序端发起请求 -> 后台 Filter 生成 traceId 存入 MDC（Mapped Diagnostic Context）-> 同一请求的 Controller/Service/日志都带上它 -> 响应时通过 header 回传。排查问题时 grep traceId 就能拿到一次请求经过的全部日志。MDC 是 SLF4J 提供的线程级上下文 Map，配合 logback 的 %X{traceId} 占位符输出。

```java
// interceptor/TraceIdFilter.java —— 生成/透传 traceId
package com.example.mall.interceptor;

import jakarta.servlet.FilterChain;
import jakarta.servlet.ServletException;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;
import org.slf4j.MDC;
import org.springframework.stereotype.Component;
import org.springframework.web.filter.OncePerRequestFilter;

import java.io.IOException;
import java.util.UUID;

@Component
public class TraceIdFilter extends OncePerRequestFilter {

    private static final String TRACE_ID = "traceId";
    private static final String HEADER = "X-Trace-Id";

    @Override
    protected void doFilterInternal(HttpServletRequest request,
                                    HttpServletResponse response,
                                    FilterChain filterChain) throws ServletException, IOException {
        // 透传前端/网关带来的 traceId，没有则生成新的
        String traceId = request.getHeader(HEADER);
        if (traceId == null || traceId.isBlank()) {
            traceId = UUID.randomUUID().toString().replace("-", "").substring(0, 16);
        }
        MDC.put(TRACE_ID, traceId);
        response.setHeader(HEADER, traceId);
        try {
            filterChain.doFilter(request, response);
        } finally {
            MDC.remove(TRACE_ID);   // 必须清理，避免线程池复用导致 traceId 串线
        }
    }
}
```

MDC 底层是 ThreadLocal，而 Spring Boot 默认使用 Tomcat 线程池处理请求，线程会复用。因此过滤器 finally 里必须 MDC.remove，否则下一个请求会读到上一个请求的 traceId。同理，异步任务（@Async）、线程池（ExecutorService）内不会自动继承 MDC，需要在提交任务时手动传递，或使用 TaskDecorator 包装。

```java
// config/TraceIdTaskDecorator.java —— 异步任务传递 traceId
package com.example.mall.config;

import org.slf4j.MDC;
import org.springframework.core.task.TaskDecorator;

import java.util.Map;

public class TraceIdTaskDecorator implements TaskDecorator {

    @Override
    public Runnable decorate(Runnable runnable) {
        // 提交任务时快照当前线程的 MDC
        Map<String, String> contextMap = MDC.getCopyOfContextMap();
        return () -> {
            if (contextMap != null) {
                MDC.setContextMap(contextMap);
            }
            try {
                runnable.run();
            } finally {
                MDC.clear();
            }
        };
    }
}
```

```java
// config/AsyncConfig.java —— 线程池装配 TaskDecorator
package com.example.mall.config;

import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.scheduling.annotation.EnableAsync;
import org.springframework.scheduling.concurrent.ThreadPoolTaskExecutor;

import java.util.concurrent.Executor;
import java.util.concurrent.ThreadPoolExecutor;

@Configuration
@EnableAsync
public class AsyncConfig {

    @Bean("asyncExecutor")
    public Executor asyncExecutor() {
        ThreadPoolTaskExecutor executor = new ThreadPoolTaskExecutor();
        executor.setCorePoolSize(4);
        executor.setMaxPoolSize(8);
        executor.setQueueCapacity(200);
        executor.setThreadNamePrefix("async-");
        executor.setTaskDecorator(new TraceIdTaskDecorator());
        executor.setRejectedExecutionHandler(new ThreadPoolExecutor.CallerRunsPolicy());
        executor.initialize();
        return executor;
    }
}
```

日志规范还包含敏感信息脱敏：手机号、身份证、银行卡、密码禁止明文打印。做法是全局 Logback 转换器（MessageConverter）正则脱敏，或写日志工具方法统一脱敏。脱敏格式如 138****1234：保留前 3 后 4，中间用 * 替换。

```java
// util/SensitiveUtil.java —— 脱敏工具
package com.example.mall.util;

public class SensitiveUtil {

    /** 手机号脱敏：138****1234 */
    public static String maskPhone(String phone) {
        if (phone == null || phone.length() != 11) {
            return phone;
        }
        return phone.substring(0, 3) + "****" + phone.substring(7);
    }

    /** 身份证脱敏：前 4 后 4，中间 * */
    public static String maskIdCard(String idCard) {
        if (idCard == null || idCard.length() < 8) {
            return idCard;
        }
        return idCard.substring(0, 4) + "**********" + idCard.substring(idCard.length() - 4);
    }

    /** 邮箱脱敏：a***@qq.com */
    public static String maskEmail(String email) {
        if (email == null || !email.contains("@")) {
            return email;
        }
        int at = email.indexOf('@');
        return email.charAt(0) + "***" + email.substring(at);
    }
}
```

```text
traceId 与日志规范要点：
1. Filter 里生成 traceId 写入 MDC，响应头回传，logback 用 %X{traceId:-} 输出
2. MDC 是 ThreadLocal，过滤器 finally 必须 remove，防止线程池复用串线
3. 异步任务不继承 MDC，用 TaskDecorator 快照/恢复上下文
4. 日志禁止打印明文密码/手机号/身份证，统一走脱敏工具或全局转换器
5. 日志分级：debug 打调试细节、info 打关键业务节点、warn 打可恢复问题、error 打异常
6. 异常日志必须带堆栈（最后一个参数传异常对象），否则线上无法定位
```

## 最佳实践与踩坑记录

### 最佳实践

1. 所有对外接口的入参 DTO 必须加校验注解，校验规则写在字段旁，评审时一眼可查
2. @NotBlank 用于字符串、@NotNull 用于对象/包装类型、@NotEmpty 用于集合，按类型选对注解，不要一律 @NotNull
3. message 写面向用户的文案（「手机号格式不正确」），不要写「phone regex failed」这类开发语言
4. 增改接口共用一个 DTO 时用分组校验（CreateGroup/UpdateGroup），避免复制两个几乎相同的 DTO
5. 日志格式全团队统一（含 traceId），Filter 生成 traceId 并回传响应头，线上排查按 traceId grep
6. 敏感字段（密码/手机号/身份证）日志一律脱敏，密码本身只存加密摘要、永不落日志
7. 日志分级使用：业务关键节点 info、可恢复异常 warn、未知异常 error 带堆栈，禁止到处 debug
8. 生产 logback 配置按天滚动 + 30 天保留 + 大小上限，接 ELK/Loki 时用 JSON 格式输出方便解析

### 踩坑记录

```text
坑 1：@Valid 校验不生效，非法参数直接进业务代码
结论：接口收到空用户名/超长昵称，校验注解形同虚设。
原因：pom 里没引入 spring-boot-starter-validation（Spring Boot 2.3+ 不再默认内置）；或 @Valid 没写。
解法：确认依赖存在；@RequestBody 前加 @Valid（或 @Validated）；GET 参数 DTO 前加 @Validated。

坑 2：GET 参数校验失败返回的不是统一 Result，而是 400 默认错误页
结论：GET 接口参数非法时返回 Spring 默认 Bad Request 结构。
原因：GET 参数绑定失败抛 BindException，而处理器只写了 MethodArgumentNotValidException（@RequestBody 场景）。
解法：GlobalExceptionHandler 增加 @ExceptionHandler(BindException.class) 处理器，同样转 Result。

坑 3：@PathVariable 上的校验注解不生效
结论：路径参数加 @Min/@Pattern 完全没校验，负数 id 照样进查询。
原因：路径/请求头参数上的约束需要类级 @Validated 才生效，方法级 @Valid 只管方法参数对象。
解法：Controller 类上加 @Validated；单参数校验也可用 Spring 6.1+ 的 @Validated 直接标注方法参数。

坑 4：异步线程里 traceId 丢失或串线
结论：@Async 方法打印的日志没有 traceId，或带着上一个请求的 traceId。
原因：MDC 是 ThreadLocal，线程池复用时子线程不继承父线程 MDC，且未清理。
解法：TaskDecorator 在提交任务时 getCopyOfContextMap 快照、执行时恢复、finally clear；Filter 里也必须 MDC.remove。

坑 5：日志里打出了明文手机号/密码，合规审查不过
结论：日志文件里出现完整手机号、身份证甚至用户密码。
原因：业务日志直接 log.info("用户手机号：{}", user.getPhone())，未脱敏。
解法：日志统一走脱敏工具；密码只允许打印「已加密」标记；更彻底的做法是全局 Logback MessageConverter 正则替换。

坑 6：logback.xml 命名错误导致配置不生效
结论：自定义的日志滚动、级别配置全部没生效，还是默认控制台输出。
原因：文件名写成了 logback.xml，Spring Boot 的 springProfile 扩展只对 logback-spring.xml 生效。
解法：文件命名为 logback-spring.xml；如需 logback.xml 则不能用 springProfile/springProperty 标签。

坑 7：error 日志没带异常对象，线上看不到堆栈
结论：日志只有一行「下单失败」，完全无法定位出错代码行。
原因：log.error("下单失败：{}", orderId) 没传异常对象，堆栈不会打印。
解法：异常分支统一 log.error("描述：参数", 参数, e)，把异常对象作为最后一个参数。

坑 8：校验注解只写了类路径没配 message，提示语是英文默认文案
结论：校验失败提示 "must not be blank" 这类英文，前端直接展示很突兀。
原因：注解没写 message 属性，用了框架默认文案。
解法：每个校验注解写中文 message；或配置 MessageSource 做国际化，按语言包取文案。

坑 9：同一个 DTO 新增/更新规则冲突，改一个坏另一个
结论：新增时必填的字段，更新时也被强制必填，或反之。
原因：一个 DTO 两组规则没分组，注解混在一起无法区分场景。
解法：用 groups 分组（CreateGroup/UpdateGroup），@Validated(分组) 按场景激活；规则确实差异大的拆成两个 DTO。
```

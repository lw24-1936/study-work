## 概述

数据库访问层是后台与 MySQL 之间的桥梁。本章使用 MyBatis-Plus（MyBatis 的增强工具）作为持久层框架：实体注解映射表结构、BaseMapper 内置单表 CRUD、LambdaQueryWrapper 类型安全条件构造、Page 分页、自定义 SQL XML 满足复杂查询，再配合 @Transactional 事务、dynamic-datasource 多数据源与代码生成器，覆盖小程序后台开发中的绝大多数数据访问场景。

```text
本章核心内容：
1. MyBatis-Plus —— 依赖引入、MybatisPlusConfig 配置、实体注解 @TableName/@TableId
2. BaseMapper —— 内置单表 CRUD，零 SQL 完成增删改查
3. LambdaQueryWrapper —— 类型安全的条件构造器，防 SQL 注入
4. 分页查询 —— 分页插件 + Page 对象 + 自定义 SQL 分页
5. 事务 —— @Transactional 传播行为与回滚规则
6. 多数据源与代码生成 —— dynamic-datasource 的 @DS 切换、代码生成器批量产出
```

## MyBatis-Plus 集成与实体映射

MyBatis-Plus（简称 MP）是 MyBatis 的增强工具，只做增强不做改变：不改变 MyBatis 原有能力，额外提供通用 Mapper（BaseMapper）、通用 Service（IService）、条件构造器与分页插件，单表 CRUD 不用写 SQL。Spring Boot 3.x 使用 mybatis-plus-spring-boot3-starter，2.7.x 使用 mybatis-plus-boot-starter。

```xml
<!-- pom.xml：Spring Boot 3.x 依赖 -->
<dependency>
    <groupId>com.baomidou</groupId>
    <artifactId>mybatis-plus-spring-boot3-starter</artifactId>
    <version>3.5.5</version>
</dependency>
<dependency>
    <groupId>com.mysql</groupId>
    <artifactId>mysql-connector-j</artifactId>
    <scope>runtime</scope>
</dependency>
```

```yaml
# application.yml 中的 MyBatis-Plus 配置
mybatis-plus:
  mapper-locations: classpath*:mapper/**/*.xml      # 自定义 SQL XML 位置
  configuration:
    map-underscore-to-camel-case: true               # create_time -> createTime 自动映射
    log-impl: org.apache.ibatis.logging.stdout.StdOutImpl  # 开发期控制台打印 SQL
  global-config:
    db-config:
      id-type: auto                                  # 主键策略：数据库自增
      logic-delete-field: deleted                    # 全局逻辑删除字段
      logic-delete-value: 1
      logic-not-delete-value: 0
```

分页插件等 MyBatis-Plus 的拦截器必须手动注册为 Bean，否则分页、乐观锁等功能不生效。分页插件放 config 包，通过 MybatisPlusInterceptor 添加 PaginationInnerInterceptor：

```java
// config/MybatisPlusConfig.java
package com.example.mall.config;

import com.baomidou.mybatisplus.annotation.DbType;
import com.baomidou.mybatisplus.extension.plugins.MybatisPlusInterceptor;
import com.baomidou.mybatisplus.extension.plugins.inner.OptimisticLockerInnerInterceptor;
import com.baomidou.mybatisplus.extension.plugins.inner.PaginationInnerInterceptor;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration
public class MybatisPlusConfig {

    @Bean
    public MybatisPlusInterceptor mybatisPlusInterceptor() {
        MybatisPlusInterceptor interceptor = new MybatisPlusInterceptor();
        // 分页插件：第一个参数指定数据库类型，自动生成 limit 方言
        interceptor.addInnerInterceptor(new PaginationInnerInterceptor(DbType.MYSQL));
        // 乐观锁插件：配合 @Version 注解使用（可选）
        interceptor.addInnerInterceptor(new OptimisticLockerInnerInterceptor());
        return interceptor;
    }
}
```

实体类通过注解与表结构映射：@TableName 指定表名（省略时默认类名转下划线，Product 自动对应 product 表）、@TableId 指定主键（type = IdType.AUTO 表示数据库自增）、@TableField 处理字段映射与填充策略（如 fill = FieldFill.INSERT 让插入时自动填充创建时间）。逻辑删除字段加 @TableLogic 后，所有删除操作自动变为 UPDATE deleted = 1，查询自动追加 deleted = 0 条件。

```java
// entity/Product.java —— 实体映射完整示例
package com.example.mall.entity;

import com.baomidou.mybatisplus.annotation.*;
import lombok.Data;

import java.math.BigDecimal;
import java.time.LocalDateTime;

@Data
@TableName("product")
public class Product {

    @TableId(type = IdType.AUTO)
    private Long id;

    private String name;

    private BigDecimal price;

    private Integer stock;

    /** 1 上架 0 下架 */
    private Integer status;

    /** 逻辑删除：0 未删 1 已删，查询自动过滤 */
    @TableLogic
    private Integer deleted;

    /** 插入时自动填充当前时间 */
    @TableField(fill = FieldFill.INSERT)
    private LocalDateTime createTime;

    /** 插入与更新时自动填充 */
    @TableField(fill = FieldFill.INSERT_UPDATE)
    private LocalDateTime updateTime;
}
```

```java
// config/MyMetaObjectHandler.java —— 自动填充处理器（配合 FieldFill）
package com.example.mall.config;

import com.baomidou.mybatisplus.core.handlers.MetaObjectHandler;
import org.apache.ibatis.reflection.MetaObject;
import org.springframework.stereotype.Component;

import java.time.LocalDateTime;

@Component
public class MyMetaObjectHandler implements MetaObjectHandler {

    @Override
    public void insertFill(MetaObject metaObject) {
        this.strictInsertFill(metaObject, "createTime", LocalDateTime.class, LocalDateTime.now());
        this.strictInsertFill(metaObject, "updateTime", LocalDateTime.class, LocalDateTime.now());
    }

    @Override
    public void updateFill(MetaObject metaObject) {
        this.strictUpdateFill(metaObject, "updateTime", LocalDateTime.class, LocalDateTime.now());
    }
}
```

```text
集成与映射要点：
1. 分页插件必须注册 MybatisPlusInterceptor Bean，否则 Page 参数被忽略、分页不生效
2. 实体与表通过 @TableName/@TableId/@TableField 映射，开启 map-underscore-to-camel-case 后下划线字段免配置
3. 主键策略统一 IdType.AUTO（自增），分布式场景才考虑雪花 ID（ASSIGN_ID）
4. 逻辑删除字段加 @TableLogic，业务代码无感，但注意唯一索引场景会冲突（踩坑记录详述）
5. createTime/updateTime 用 MetaObjectHandler 自动填充，业务代码不再手写时间
6. 复杂查询/多表联查写 XML（mapper 目录），单表 CRUD 用 BaseMapper 即可
```

## BaseMapper CRUD 与 LambdaQueryWrapper

BaseMapper 内置了单表全部 CRUD 方法：insert、deleteById、updateById、selectById、selectList、selectCount、selectPage 等，继承它即可零 SQL 完成基础操作。条件查询用 Wrapper 构造：LambdaQueryWrapper 用方法引用（Product::getStatus）代替字符串列名，编译期就能发现拼写错误，且参数全部预编译占位符，天然防 SQL 注入。

```java
// mapper/ProductMapper.java
package com.example.mall.mapper;

import com.baomidou.mybatisplus.core.mapper.BaseMapper;
import com.example.mall.entity.Product;
import org.apache.ibatis.annotations.Mapper;

@Mapper
public interface ProductMapper extends BaseMapper<Product> {
}
```

```java
// service/impl/ProductServiceImpl.java —— BaseMapper + LambdaQueryWrapper 用法
package com.example.mall.service.impl;

import com.baomidou.mybatisplus.core.conditions.query.LambdaQueryWrapper;
import com.example.mall.entity.Product;
import com.example.mall.mapper.ProductMapper;
import lombok.RequiredArgsConstructor;
import org.springframework.stereotype.Service;

import java.util.List;

@Service
@RequiredArgsConstructor
public class ProductServiceImpl {

    private final ProductMapper productMapper;

    /** 单条插入：主键自增后回填到实体 */
    public Long addProduct(Product product) {
        productMapper.insert(product);
        return product.getId();
    }

    /** 按主键查询 */
    public Product getById(Long id) {
        return productMapper.selectById(id);
    }

    /** 条件查询：status=1 且价格区间，按 id 倒序 */
    public List<Product> listOnSale(BigDecimal minPrice, BigDecimal maxPrice) {
        return productMapper.selectList(new LambdaQueryWrapper<Product>()
                .eq(Product::getStatus, 1)
                .ge(minPrice != null, Product::getPrice, minPrice)
                .le(maxPrice != null, Product::getPrice, maxPrice)
                .orderByDesc(Product::getId));
    }

    /** 更新：只更新非 null 字段 */
    public void updateProduct(Product product) {
        productMapper.updateById(product);
    }

    /** 条件更新：下架某分类全部商品（批量更新，不走实体） */
    public void offShelfByCategory(Long categoryId) {
        productMapper.update(null, new LambdaUpdateWrapper<Product>()
                .eq(Product::getCategoryId, categoryId)
                .set(Product::getStatus, 0));
    }

    /** 条件删除：逻辑删除某分类商品 */
    public void deleteByCategory(Long categoryId) {
        productMapper.delete(new LambdaQueryWrapper<Product>()
                .eq(Product::getCategoryId, categoryId));
    }

    /** 统计：在售商品数 */
    public long countOnSale() {
        return productMapper.selectCount(new LambdaQueryWrapper<Product>()
                .eq(Product::getStatus, 1));
    }
}
```

常用条件方法速查：eq（等于）、ne（不等于）、gt/ge（大于/大于等于）、lt/le（小于/小于等于）、like（模糊，自动加 %）、in（IN 集合）、between（区间）、isNull/isNotNull（空判断）。条件方法第一个参数是 boolean 类型，为 false 时该条件不拼接，配合「参数为空就不过滤」的场景非常实用。

```text
CRUD 与条件构造器要点：
1. 单表增删改查零 SQL，BaseMapper 方法名即语义（selectById/updateById/deleteById）
2. LambdaQueryWrapper 方法引用列名，编译期检查，杜绝字符串列名拼写错误
3. 条件方法第一个 boolean 参数控制是否拼接，实现「可选过滤条件」免手写 if
4. 更新默认只更新非 null 字段（updateById），全字段更新用 UpdateWrapper.set 显式指定
5. 链式调用 orderByDesc/limit/last 可以组合，但 last("limit 1") 要谨慎防注入
6. 逻辑删除字段配置后，delete 自动转 UPDATE，查询自动带 deleted=0，业务无感
```

## 分页查询

MyBatis-Plus 分页分两步：注册 PaginationInnerInterceptor（已在上文配置），查询时把 Page 对象作为 selectPage 的第一个参数。插件会在执行前拦截 SQL，自动拼接 LIMIT 并执行 COUNT 查询，把结果回填到 Page 对象。分页结果用 17.2 的 PageResult 包装返回给小程序端。

```java
// service/impl/ProductServiceImpl.java —— 分页查询
import com.baomidou.mybatisplus.core.metadata.IPage;
import com.baomidou.mybatisplus.extension.plugins.pagination.Page;

public IPage<Product> pageProducts(long pageNum, long pageSize, String keyword, Integer status) {
    Page<Product> page = new Page<>(pageNum, pageSize);
    return productMapper.selectPage(page, new LambdaQueryWrapper<Product>()
            .like(keyword != null && !keyword.isBlank(), Product::getName, keyword)
            .eq(status != null, Product::getStatus, status)
            .orderByDesc(Product::getId));
}
```

```java
// controller/ProductController.java —— 分页接口返回 PageResult
package com.example.mall.controller;

import com.baomidou.mybatisplus.core.metadata.IPage;
import com.example.mall.common.PageResult;
import com.example.mall.common.Result;
import com.example.mall.entity.Product;
import com.example.mall.service.ProductService;
import lombok.RequiredArgsConstructor;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RestController;

@RestController
@RequestMapping("/products")
@RequiredArgsConstructor
public class ProductController {

    private final ProductService productService;

    @GetMapping("/page")
    public Result<PageResult<Product>> page(
            @RequestParam(defaultValue = "1") long pageNum,
            @RequestParam(defaultValue = "10") long pageSize,
            @RequestParam(required = false) String keyword,
            @RequestParam(required = false) Integer status) {
        IPage<Product> page = productService.pageProducts(pageNum, pageSize, keyword, status);
        return Result.success(PageResult.of(page));
    }
}
```

复杂查询（多表联查、分组、子查询）用自定义 SQL：在 mapper 接口写方法，resources/mapper 目录放同名 XML，SQL 写在 XML 里。自定义分页查询同样把 Page 作为第一个参数，MP 自动追加 LIMIT；多表联查的分页，总条数 SQL 由插件自动生成（基于查询 SQL 包一层 COUNT），group by 等场景需手动注意。

```xml
<!-- resources/mapper/OrderMapper.xml —— 自定义 SQL 分页联查 -->
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE mapper PUBLIC "-//mybatis.org//DTD Mapper 3.0//EN"
        "http://mybatis.org/dtd/mybatis-3-mapper.dtd">
<mapper namespace="com.example.mall.mapper.OrderMapper">

    <!-- 订单列表联查商品名与用户昵称：resultType 直接映射到 VO -->
    <select id="selectOrderPage" resultType="com.example.mall.vo.OrderVO">
        SELECT o.id, o.order_no AS orderNo, o.amount, o.status,
               o.create_time AS createTime,
               p.name AS productName, u.nickname AS userName
        FROM `order` o
        LEFT JOIN product p ON o.product_id = p.id
        LEFT JOIN user u ON o.user_id = u.id
        <where>
            <if test="status != null">
                AND o.status = #{status}
            </if>
            <if test="userName != null and userName != ''">
                AND u.nickname LIKE CONCAT('%', #{userName}, '%')
            </if>
        </where>
        ORDER BY o.id DESC
    </select>
</mapper>
```

```java
// mapper/OrderMapper.java —— 自定义分页方法：Page 必须作为第一个参数
package com.example.mall.mapper;

import com.baomidou.mybatisplus.core.metadata.IPage;
import com.baomidou.mybatisplus.extension.plugins.pagination.Page;
import com.example.mall.vo.OrderVO;
import org.apache.ibatis.annotations.Mapper;
import org.apache.ibatis.annotations.Param;

@Mapper
public interface OrderMapper {

    IPage<OrderVO> selectOrderPage(Page<OrderVO> page,
                                   @Param("status") Integer status,
                                   @Param("userName") String userName);
}
```

```text
分页要点：
1. 分页依赖 PaginationInnerInterceptor，没注册时 selectPage 返回全部数据（或报错）
2. Page 对象必须是 selectPage 的第一个参数，插件据此改写 SQL 追加 LIMIT
3. 分页参数做上限约束（pageSize 最大 100），防止恶意大分页拖垮数据库
4. 自定义 SQL 分页：方法第一个参数写 Page<T>，XML 里 SQL 不带 LIMIT
5. 联查 VO 字段用 AS 别名与驼峰对应，或开启下划线映射自动转换
6. 小程序端「上拉加载更多」传 pageNum+1，PageResult 返回 pages 判断是否到底
```

## 事务管理

事务保证一组数据库操作要么全部成功、要么全部失败。Spring 事务用 @Transactional 声明：标注在 Service 方法上，方法内抛 RuntimeException（及其子类）自动回滚，正常返回自动提交。事务边界建议放在 Service 层而不是 Controller 层：Controller 只做编排，事务要与业务单元对齐。

```java
// service/impl/OrderServiceImpl.java —— 下单事务：扣库存 + 建订单 + 记流水，全成或全败
package com.example.mall.service.impl;

import com.example.mall.common.BusinessException;
import com.example.mall.common.ErrorCode;
import com.example.mall.entity.Order;
import com.example.mall.entity.Product;
import com.example.mall.mapper.OrderMapper;
import com.example.mall.mapper.ProductMapper;
import lombok.RequiredArgsConstructor;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

@Service
@RequiredArgsConstructor
public class OrderServiceImpl {

    private final ProductMapper productMapper;
    private final OrderMapper orderMapper;

    @Transactional(rollbackFor = Exception.class)
    public Long createOrder(Long userId, Long productId, Integer quantity) {
        // 1. 查商品（带行锁：for update 防止并发超卖）
        Product product = productMapper.selectByIdForUpdate(productId);
        if (product == null) {
            throw new BusinessException(ErrorCode.PRODUCT_NOT_FOUND);
        }
        if (product.getStock() < quantity) {
            throw new BusinessException(ErrorCode.PRODUCT_STOCK_NOT_ENOUGH);
        }

        // 2. 扣库存
        product.setStock(product.getStock() - quantity);
        productMapper.updateById(product);

        // 3. 建订单
        Order order = new Order();
        order.setUserId(userId);
        order.setProductId(productId);
        order.setQuantity(quantity);
        order.setAmount(product.getPrice().multiply(new BigDecimal(quantity)));
        order.setStatus(0);   // 0 待支付
        orderMapper.insert(order);

        // 4. 任意一步抛异常（如库存不足），前面已执行的 update/insert 全部回滚
        return order.getId();
    }
}
```

@Transactional 关键属性：rollbackFor（默认只回滚 RuntimeException 与 Error，checked 异常不会回滚，因此写业务代码统一抛 RuntimeException 或显式 rollbackFor = Exception.class）、propagation（传播行为：REQUIRED 默认，方法内调用另一个带事务的方法时加入当前事务）、isolation（隔离级别，默认数据库默认级别）、readOnly（只读事务优化，查询方法可标注）、timeout（超时秒数，防止长事务）。

```text
事务属性速查：
1. rollbackFor = Exception.class —— 让 checked 异常也触发回滚，业务代码强烈建议显式声明
2. propagation = REQUIRED —— 默认：有事务则加入，无则新建，嵌套调用合并为一个事务
3. propagation = REQUIRES_NEW —— 挂起当前事务开新事务，独立提交回滚（如日志记录场景）
4. propagation = NESTED —— 嵌套事务，内层回滚不影响外层已提交部分（依赖 Savepoint）
5. readOnly = true —— 只读查询优化，配合 @Transactional(readOnly = true) 标注查询方法
6. 自调用陷阱：同类内 this.method() 调用不走代理，@Transactional 失效（踩坑记录详述）
```

## 多数据源

多数据源场景：读写分离（主库写、从库读）、多业务库（订单库/用户库分离）、与第三方系统共用库。dynamic-datasource-spring-boot-starter（苞米豆出品）是 Spring Boot 多数据源的成熟方案：数据源配置在 yml 中声明，@DS("库名") 注解切换数据源，默认数据源用 @DS("master") 或不用注解。它基于 AOP 实现，注解标注在 Service 方法上，方法内所有 Mapper 走指定数据源。

```xml
<!-- pom.xml -->
<dependency>
    <groupId>com.baomidou</groupId>
    <artifactId>dynamic-datasource-spring-boot3-starter</artifactId>
    <version>4.3.1</version>
</dependency>
```

```yaml
# application.yml —— 多数据源配置
spring:
  datasource:
    dynamic:
      primary: master                  # 默认数据源
      strict: false                    # 未匹配到数据源时不报错，走 primary
      datasource:
        master:
          url: jdbc:mysql://localhost:3306/mall?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai
          username: root
          password: root123
          driver-class-name: com.mysql.cj.jdbc.Driver
        slave:
          url: jdbc:mysql://localhost:3306/mall_read?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai
          username: root
          password: root123
          driver-class-name: com.mysql.cj.jdbc.Driver
        order-db:
          url: jdbc:mysql://localhost:3306/mall_order?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai
          username: root
          password: root123
          driver-class-name: com.mysql.cj.jdbc.Driver
```

```java
// 使用 @DS 切换数据源
package com.example.mall.service.impl;

import com.baomidou.dynamic.datasource.annotation.DS;
import com.example.mall.entity.Order;
import com.example.mall.mapper.OrderMapper;
import lombok.RequiredArgsConstructor;
import org.springframework.stereotype.Service;

import java.util.List;

@Service
@RequiredArgsConstructor
public class OrderQueryServiceImpl {

    private final OrderMapper orderMapper;

    /** 读操作走从库（读写分离） */
    @DS("slave")
    public List<Order> listOrders() {
        return orderMapper.selectList(null);
    }

    /** 跨库场景：订单库查询 */
    @DS("order-db")
    public Order getOrder(Long id) {
        return orderMapper.selectById(id);
    }

    /** 默认数据源 master：不加 @DS 即可 */
    public void saveOrder(Order order) {
        orderMapper.insert(order);
    }
}
```

使用注意：@DS 只对方法内的 Mapper 调用生效，事务与数据源切换的先后顺序有讲究——@Transactional 开启事务时会先绑定数据源，因此 @DS 要标在事务方法上；同库操作共用事务没问题，跨数据源操作不共享事务（分布式事务需要 Seata 等方案，超出本章范围）。动态数据源切换基于 ThreadLocal，切面结束后自动清理，不需要手动处理。

```text
多数据源要点：
1. yml 用 spring.datasource.dynamic.datasource 声明各库，primary 指定默认库
2. @DS("库名") 标注在 Service 方法上，方法内所有 SQL 走该库；不标走 primary
3. 读写分离：写接口默认 master，只读查询标 @DS("slave")
4. @DS 与 @Transactional 同时使用时，@DS 必须标在事务方法上，保证事务绑定正确数据源
5. 跨数据源没有本地事务，需要分布式事务时引入 Seata/ShardingSphere
6. 生产环境多库密码用环境变量注入，禁止明文写在 yml 提交 Git
```

MyBatis-Plus 代码生成器根据数据库表结构一键生成 entity、mapper、service、controller 全套代码，消除重复的建类工作。使用方式：引入 mybatis-plus-generator 依赖（3.5.1+ 新版用 FastAutoGenerator 链式 API），写一个一次性运行的生成器 main 方法，配置数据源、包名、表名即可。

## 应用场景实战

### 场景一：商品管理后台的 CRUD + 分页 + 逻辑删除

场景目标：完成商品模块全部数据访问能力：新增、条件分页查询、上下架、逻辑删除，全部基于 BaseMapper + LambdaQueryWrapper，不写一行 SQL。

```text
步骤：
1. 建表 product（含 deleted/create_time/update_time 字段），写建表 SQL
2. 创建 Product 实体与 ProductMapper（继承 BaseMapper）
3. 注册分页插件与自动填充处理器
4. Service 实现新增/分页/上下架/删除四个方法
5. curl 验证：分页返回 total、上下架状态变化、删除后列表不再出现
```

```sql
-- 建表 SQL：product 商品表
CREATE TABLE `product` (
    `id`          BIGINT       NOT NULL AUTO_INCREMENT COMMENT '主键',
    `name`        VARCHAR(128) NOT NULL COMMENT '商品名称',
    `price`       DECIMAL(10,2) NOT NULL DEFAULT '0.00' COMMENT '价格',
    `stock`       INT          NOT NULL DEFAULT 0 COMMENT '库存',
    `status`      TINYINT      NOT NULL DEFAULT 1 COMMENT '1上架 0下架',
    `deleted`     TINYINT      NOT NULL DEFAULT 0 COMMENT '0未删 1已删',
    `create_time` DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    `update_time` DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    PRIMARY KEY (`id`),
    KEY `idx_status` (`status`)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COMMENT = '商品表';
```

```java
// service/impl/ProductAdminServiceImpl.java —— 商品管理核心方法
package com.example.mall.service.impl;

import com.baomidou.mybatisplus.core.conditions.query.LambdaQueryWrapper;
import com.baomidou.mybatisplus.core.conditions.update.LambdaUpdateWrapper;
import com.baomidou.mybatisplus.core.metadata.IPage;
import com.baomidou.mybatisplus.extension.plugins.pagination.Page;
import com.example.mall.entity.Product;
import com.example.mall.mapper.ProductMapper;
import lombok.RequiredArgsConstructor;
import org.springframework.stereotype.Service;

@Service
@RequiredArgsConstructor
public class ProductAdminServiceImpl {

    private final ProductMapper productMapper;

    public Long create(Product product) {
        productMapper.insert(product);
        return product.getId();
    }

    public IPage<Product> page(long pageNum, long pageSize, String keyword, Integer status) {
        return productMapper.selectPage(new Page<>(pageNum, pageSize),
                new LambdaQueryWrapper<Product>()
                        .like(keyword != null && !keyword.isBlank(), Product::getName, keyword)
                        .eq(status != null, Product::getStatus, status)
                        .orderByDesc(Product::getId));
    }

    public void changeStatus(Long id, Integer status) {
        productMapper.update(null, new LambdaUpdateWrapper<Product>()
                .eq(Product::getId, id)
                .set(Product::getStatus, status));
    }

    /** 逻辑删除：实际执行 UPDATE product SET deleted=1 WHERE id=? AND deleted=0 */
    public void delete(Long id) {
        productMapper.deleteById(id);
    }
}
```

### 场景二：下单扣库存的并发安全与事务回滚

场景目标：实现「查库存 + 扣库存 + 建订单」的原子操作：事务保证全部成功或全部回滚，行锁（SELECT ... FOR UPDATE）防止并发超卖。

```text
步骤：
1. ProductMapper 增加 selectByIdForUpdate 自定义方法（XML 写 for update）
2. OrderServiceImpl.createOrder 加 @Transactional(rollbackFor = Exception.class)
3. 用两个并发请求模拟抢购：库存 5，两人各买 3，验证不会超卖
4. 验证回滚：故意传入超量 quantity，观察订单表无新增、库存未变
```

```xml
<!-- resources/mapper/ProductMapper.xml -->
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE mapper PUBLIC "-//mybatis.org//DTD Mapper 3.0//EN"
        "http://mybatis.org/dtd/mybatis-3-mapper.dtd">
<mapper namespace="com.example.mall.mapper.ProductMapper">

    <!-- 行级锁查询：事务内锁定该行，并发更新串行化，防止超卖 -->
    <select id="selectByIdForUpdate" resultType="com.example.mall.entity.Product">
        SELECT * FROM product WHERE id = #{id} FOR UPDATE
    </select>
</mapper>
```

```java
// mapper/ProductMapper.java —— 补充方法
@Mapper
public interface ProductMapper extends BaseMapper<Product> {
    Product selectByIdForUpdate(@Param("id") Long id);
}
```

```bash
# 场景验证脚本（库存 5，两个并发订单各买 3）
# 请求 1
curl -X POST http://localhost:8080/api/orders -H "Content-Type: application/json" \
  -d '{"productId":1,"quantity":3}'
# 请求 2（几乎同时发出）
curl -X POST http://localhost:8080/api/orders -H "Content-Type: application/json" \
  -d '{"productId":1,"quantity":3}'

# 期望结果：一个成功一个失败（code=3002 库存不足），最终库存 = 5-3 = 2，订单表只有 1 条
# 失败响应：{"code":3002,"message":"商品库存不足","data":null}
```

```text
场景要点回顾：
1. 事务方法内任何 RuntimeException 都会回滚之前所有 SQL，用 curl 观察订单表/库存变化验证
2. FOR UPDATE 行锁让并发扣库存串行化，是「乐观锁 vs 悲观锁」中悲观锁方案
3. 无锁方案必须用「UPDATE ... SET stock = stock - n WHERE stock >= n」的原子 SQL + 影响行数判断
4. 事务 + 锁只解决单库一致性，Redis 预扣减（17.5）用于削峰，两者可结合
```

## 最佳实践与踩坑记录

### 最佳实践

1. 单表 CRUD 用 BaseMapper + LambdaQueryWrapper，只有多表联查、复杂统计才写 XML，代码量减半且类型安全
2. 事务注解统一 rollbackFor = Exception.class，业务异常抛 RuntimeException 子类（BusinessException），保证任何失败都回滚
3. 所有表建 deleted 逻辑删除字段 + create_time/update_time，配合全局配置与自动填充，审计追溯有据可查
4. 分页参数做上限约束（pageSize <= 100），列表查询加 orderBy，避免全表扫描与随机排序
5. 查询只取需要的字段：列表场景定义 VO 而非把整个 Entity 塞给前端，敏感字段（如手机号）不进 VO
6. 生产环境关闭 SQL 日志（log-impl 只在 dev 配置），防止敏感 SQL 落盘
7. 表结构与索引在设计阶段确认：查询条件列建索引（如 status、user_id），禁止 SELECT * 联查大表
8. 数据库账号最小权限：应用账号只授业务库 DML，DDL 由 DBA/发布流程执行

### 踩坑记录

```text
坑 1：分页不生效，selectPage 返回全量数据
结论：接口返回 records 是全部数据，total 等于表行数。
原因：MybatisPlusInterceptor 没注册为 Bean，分页插件未生效，Page 参数被 MyBatis 忽略。
解法：config 包注册 MybatisPlusInterceptor + PaginationInnerInterceptor(DbType.MYSQL)；注意 Spring Boot 3 用 mybatis-plus-spring-boot3-starter 的包名。

坑 2：@Transactional 不生效，异常后数据没回滚
结论：方法内第二步抛异常，第一步的 insert 还是提交了。
原因：同类内自调用（this.createOrder()）不走 Spring 代理；或方法不是 public；或异常被 try-catch 吞掉。
解法：事务方法跨类调用（注入另一个 Service）；方法必须是 public；不要在事务方法内 catch 掉业务异常，需要补偿逻辑时先 catch 再抛出或使用 TransactionTemplate。

坑 3：checked 异常没触发回滚
结论：方法抛 IOException/自定义 checked 异常，数据照样提交。
原因：@Transactional 默认只回滚 RuntimeException 与 Error，checked 异常不触发。
解法：统一抛 RuntimeException 子类；或显式 @Transactional(rollbackFor = Exception.class)。

坑 4：逻辑删除字段与唯一索引冲突，重复插入报 Duplicate entry
结论：删除后再次插入同 user_id 数据，报唯一索引冲突。
原因：deleted 参与唯一索引，逻辑删除只是置 1，唯一约束仍拦截。
解法：唯一索引改成 (user_id, deleted) 复合且 deleted 用时间戳/自增代替固定 1（删除时写 deleted = id）；或唯一字段业务校验后再插入。

坑 5：查询结果字段全是 null 或列名对不上
结论：联查 VO 里字段为 null，create_time 取不到值。
原因：关闭了 map-underscore-to-camel-case；或 XML 没写 AS 别名；或 resultType 写错类。
解法：开启 map-underscore-to-camel-case；联查列用 AS 驼峰别名；复杂映射用 resultMap 显式映射。

坑 6：updateById 把不该改的字段清空了
结论：编辑商品后，价格/库存字段变成 null 或默认值。
原因：前端传了不完整的对象，updateById 只更新非 null 字段但前端把空值传成 null 或没传导致覆盖逻辑错乱；或实体里存在数据库默认值字段被 null 覆盖。
解法：明确「局部更新」语义——只 set 需要更新的字段用 UpdateWrapper；编辑接口的 DTO 单独设计，必传字段用校验注解约束；给数据库字段加 NOT NULL 兜底。

坑 7：多数据源切到从库后，刚写入的数据查不到
结论：写主库成功后立刻查询，从库返回旧数据。
原因：MySQL 主从复制有延迟，读写分离下读请求走了从库。
解法：强一致场景（下单后立即查订单）强制走主库（不加 @DS 或 @DS("master")）；容忍延迟场景走从库；对延迟敏感的接口加「最近写入标记」策略。

坑 8：代码生成器生成的 SQL/表结构不一致，启动报 Table 'product' doesn't exist
结论：应用启动成功但查询报表不存在。
原因：生成器基于某环境表生成代码，但运行环境（dev/prod）数据库没有对应表或表名带前缀（t_product）。
解法：统一由 SQL 迁移脚本（Flyway/Liquibase 或手工 SQL 文件）管理建表，代码与库同步；addTablePrefix 与建表脚本保持一致。

坑 9：大分页性能差，翻到第 1000 页卡死
结论：pageNum 很大时查询越来越慢，数据库 CPU 飙升。
原因：LIMIT 10000, 10 需要扫描并丢弃前 10000 行。
解法：限制最大 pageNum 或用「游标分页」（WHERE id > lastId ORDER BY id LIMIT 10），小程序上拉加载场景天然适合游标分页；为 orderBy 字段建索引。
```

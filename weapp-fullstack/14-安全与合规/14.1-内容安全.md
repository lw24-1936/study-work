## 概述

微信小程序的内容安全检测是平台提供的 UGC（用户生成内容）合规基础设施，通过 security.msgSecCheck、security.imgSecCheck 等接口对文本、图片、音频、视频进行违规内容识别。凡是涉及用户评论、发帖、上传图片的小程序，都必须在内容入库前完成安全检测，否则一旦被平台巡检发现违规内容，轻则警告、下架内容，重则封禁接口权限甚至整号封禁。

内容安全建设分为三层：第一层是服务端接入微信内容安全接口做实时检测；第二层是本地敏感词过滤与异步审核队列兜底；第三层是对违规内容做拦截、提示、记录、人工复审的完整闭环。本章从接口协议、服务端集成、违规处理、审核策略四个维度展开，所有代码示例基于 SpringBoot 后台 + 小程序前端。

```text
内容安全的核心要点：
1. 文本检测 —— security.msgSecCheck，同步接口，检测后返回 pass/review/risky 结论
2. 图片检测 —— security.imgSecCheck 同步检测小图，media_check_async 异步检测大图/视频/音频
3. 违规特征 —— 接口返回 errcode 87014 表示内容含有违法违规内容
4. 前置条件 —— 调用前必须持有有效 access_token，且需在小程序后台申请内容安全接口权限
5. 处理闭环 —— 拦截发布、提示用户、记录日志、人工复审四步缺一不可
6. 频率限制 —— 内容安全接口共享 400 次/分钟的调用配额，需要做本地缓存与降级
```

## 内容安全能力概览

微信内容安全接口属于「微信开放接口」中的 security 系列，由小程序后台调用，服务端持有 access_token 后发起 HTTPS 请求。整个能力矩阵覆盖文本、图片、音频、视频四类内容，其中文本与图片是最常见的高频场景。

```text
微信内容安全接口矩阵：
1. security.msgSecCheck —— 文本同步检测（POST /wxa/msg_sec_check）
2. security.imgSecCheck —— 图片同步检测（POST /wxa/img_sec_check）
3. security.media_check_async —— 图片/音频/视频异步检测（POST /wxa/media_check_async）
4. security.media_check_sync —— 按 trace_id 查询异步检测结果（POST /wxa/media_check_sync）
5. access_token —— 所有安全接口共用的调用凭证，需缓存复用
6. 开通方式 —— 小程序后台「开发-开发设置-接口设置」申请内容安全权限
```

调用内容安全接口前必须先获取 access_token。access_token 通过 cgi-bin/token 接口换取，有效期 7200 秒，必须在服务端缓存复用（推荐存 Redis 并提前 200 秒刷新），千万不能每个请求都重新获取——token 接口本身有 2000 次/天的调用上限，频繁换取必然触发限流。

```java
// WechatTokenService.java —— access_token 获取与缓存（SpringBoot 完整实现）
@Service
@Slf4j
public class WechatTokenService {

    private static final String TOKEN_URL =
        "https://api.weixin.qq.com/cgi-bin/token?grant_type=client_credential&appid=%s&secret=%s";
    private static final String TOKEN_KEY = "wechat:access_token";

    @Value("${wechat.appid}")
    private String appid;

    @Value("${wechat.secret}")
    private String secret;

    @Resource
    private StringRedisTemplate redisTemplate;

    @Resource
    private RestTemplate restTemplate;

    /** 获取 access_token：先读 Redis 缓存，未命中或过期则重新换取 */
    public String getAccessToken() {
        String token = redisTemplate.opsForValue().get(TOKEN_KEY);
        if (StringUtils.hasText(token)) {
            return token;
        }
        synchronized (this) {
            token = redisTemplate.opsForValue().get(TOKEN_KEY);
            if (StringUtils.hasText(token)) {
                return token;
            }
            String url = String.format(TOKEN_URL, appid, secret);
            Map<String, Object> resp = restTemplate.getForObject(url, Map.class);
            if (resp == null || resp.get("access_token") == null) {
                log.error("获取 access_token 失败: {}", resp);
                throw new BizException("微信 access_token 获取失败");
            }
            // expires_in 为 7200 秒，提前 200 秒过期，避免边界失效
            int expiresIn = ((Number) resp.get("expires_in")).intValue() - 200;
            redisTemplate.opsForValue().set(TOKEN_KEY,
                resp.get("access_token").toString(), Duration.ofSeconds(expiresIn));
            return resp.get("access_token").toString();
        }
    }
}
```

```text
access_token 使用要点：
1. 有效期 7200 秒，必须缓存复用，禁止每个请求重新换取
2. 换取接口每日调用上限 2000 次，滥用会被限流（errcode 45009）
3. 用 synchronized + 双检锁防止缓存击穿，Redis 设置过期时间自动淘汰
4. AppSecret 只存在于服务端配置，严禁出现在小程序代码中
5. 多个微信接口（内容安全、订阅消息、支付等）共用同一个 access_token
6. token 失效（errcode 40001）时主动删除缓存并重试一次
```

## 文本内容安全检测 msgSecCheck

msgSecCheck 是使用频率最高的内容安全接口，用于检测用户输入的文本（评论、昵称、帖子正文、聊天内容等）是否包含违法违规内容。同步接口，请求与响应都在毫秒级完成，适合在发布接口中同步调用。

接口协议：POST https://api.weixin.qq.com/wxa/msg_sec_check?access_token=ACCESS_TOKEN，请求体为 JSON。旧版（不传 version 或 version=1）仅返回 errcode，errcode 为 0 表示合规、87014 表示内容违规；新版（version=2）返回更精细的 result.suggest（pass 通过 / review 建议人工复审 / risky 违规）与 label 分类标签，推荐使用 version=2。

```java
// ContentSecurityService.java —— 文本检测完整实现
@Service
@Slf4j
public class ContentSecurityService {

    private static final String MSG_CHECK_URL =
        "https://api.weixin.qq.com/wxa/msg_sec_check?access_token=%s";

    @Resource
    private WechatTokenService tokenService;

    @Resource
    private RestTemplate restTemplate;

    /**
     * 文本安全检测（version=2）
     * @param content 待检测文本，建议单段不超过 2500 字，超长分段检测
     * @param openid  用户 openid，用于风险用户追溯
     * @return pass / review / risky
     */
    public String checkText(String content, String openid) {
        Map<String, Object> body = new HashMap<>();
        body.put("content", content);
        body.put("version", 2);
        body.put("scene", 2);          // 1 资料 2 评论 3 论坛 4 社交日志
        body.put("openid", openid);

        String url = String.format(MSG_CHECK_URL, tokenService.getAccessToken());
        HttpHeaders headers = new HttpHeaders();
        headers.setContentType(MediaType.APPLICATION_JSON);
        HttpEntity<Map<String, Object>> entity = new HttpEntity<>(body, headers);

        Map<String, Object> resp = restTemplate.postForObject(url, entity, Map.class);
        if (resp == null) {
            throw new BizException("内容安全检测服务无响应");
        }
        Integer errcode = ((Number) resp.getOrDefault("errcode", 0)).intValue();
        if (errcode != 0) {
            // 87014 内容违规；40001 token 失效；45009 触发频率限制
            if (errcode == 87014) {
                return "risky";
            }
            log.warn("msgSecCheck 调用异常 errcode={} errmsg={}", errcode, resp.get("errmsg"));
            throw new BizException("内容安全检测服务异常: " + resp.get("errmsg"));
        }
        // version=2 时返回 result.suggest: pass / review / risky
        Map<String, Object> result = (Map<String, Object>) resp.get("result");
        if (result == null) {
            return "pass";
        }
        String suggest = (String) result.get("suggest");
        return suggest == null ? "pass" : suggest;
    }
}
```

```text
msgSecCheck 检测要点：
1. 请求地址固定为 wxa/msg_sec_check，参数带 access_token 查询串
2. version=2 返回 suggest（pass/review/risky）与 label，比旧版只报 87014 更精细
3. label 分类：100 正常、10001 广告、20001 时政、20002 色情、20003 辱骂、20006 违法犯罪、20008 欺诈、20012 低俗、20013 版权、21000 其他
4. review（建议复审）结果不能直接放行，应进人工复审队列
5. 超长文本分段检测后再汇总结论，任一段 risky 则整体拦截
6. 接口共享 400 次/分钟配额，并发高峰需本地缓存 + 降级策略
```

## 图片内容安全检测 imgSecCheck

图片检测用于用户上传头像、帖子图片、商品图等场景。小图（建议 1MB 以内）可用 security.imgSecCheck 同步检测，multipart/form-data 方式提交；大图、视频、音频走 media_check_async 异步检测，提交后拿到 trace_id，再通过 media_check_sync 轮询结果，或配置消息推送接收检测结果。

```java
// ContentSecurityService.java —— 图片同步检测完整实现
public boolean checkImage(MultipartFile file) {
    String url = String.format(IMG_CHECK_URL, tokenService.getAccessToken());

    HttpHeaders headers = new HttpHeaders();
    headers.setContentType(MediaType.MULTIPART_FORM_DATA);
    // 构造 multipart/form-data，字段名必须为 media
    MultiValueMap<String, Object> form = new LinkedMultiValueMap<>();
    form.add("media", new ByteArrayResource(file.getBytes()) {
        @Override
        public String getFilename() {
            return file.getOriginalFilename();
        }
    });
    HttpEntity<MultiValueMap<String, Object>> entity = new HttpEntity<>(form, headers);

    Map<String, Object> resp = restTemplate.postForObject(url, entity, Map.class);
    if (resp == null) {
        throw new BizException("图片检测服务无响应");
    }
    Integer errcode = ((Number) resp.getOrDefault("errcode", 0)).intValue();
    // 87014 表示图片违规，其他 errcode 按服务异常处理（不能误伤正常图片）
    return errcode != 87014;
}
```

```java
// 异步检测（大图/视频/音频）完整实现
public String checkMediaAsync(String mediaUrl, int mediaType, String openid) {
    // mediaType: 2 图片 3 音频 4 视频
    Map<String, Object> body = new HashMap<>();
    body.put("media_url", mediaUrl);
    body.put("media_type", mediaType);
    body.put("version", 2);
    body.put("openid", openid);
    body.put("scene", 2);

    String url = String.format(MEDIA_CHECK_ASYNC_URL, tokenService.getAccessToken());
    HttpHeaders headers = new HttpHeaders();
    headers.setContentType(MediaType.APPLICATION_JSON);
    HttpEntity<Map<String, Object>> entity = new HttpEntity<>(body, headers);

    Map<String, Object> resp = restTemplate.postForObject(url, entity, Map.class);
    if (resp == null || resp.get("trace_id") == null) {
        throw new BizException("异步检测提交失败: " + resp);
    }
    return resp.get("trace_id").toString();
}

// 按 trace_id 查询异步检测结果
public String queryMediaCheckResult(String traceId) {
    Map<String, Object> body = new HashMap<>();
    body.put("trace_id", traceId);
    String url = String.format(MEDIA_CHECK_SYNC_URL, tokenService.getAccessToken());
    HttpHeaders headers = new HttpHeaders();
    headers.setContentType(MediaType.APPLICATION_JSON);
    HttpEntity<Map<String, Object>> entity = new HttpEntity<>(body, headers);
    Map<String, Object> resp = restTemplate.postForObject(url, entity, Map.class);
    if (resp == null || ((Number) resp.getOrDefault("errcode", 0)).intValue() != 0) {
        return "pass"; // 查询失败按通过处理，配合人工抽检兜底
    }
    // result.suggest: pass / review / risky
    Map<String, Object> result = (Map<String, Object>) resp.get("result");
    return result == null ? "pass" : (String) result.get("suggest");
}
```

小程序端上传图片后调用后台检测接口，完整的链路是：前端选择图片 → wx.uploadFile 上传到自家服务器 → 服务器先落盘（或暂存 OSS）→ 调 imgSecCheck 检测 → 通过则入库，违规则删除文件并返回提示。

```text
图片检测要点：
1. 同步接口 imgSecCheck 适合小图（建议 1MB 以内），表单字段名必须是 media

4. 检测失败（网络异常、限流）时应先拦截入库并标记「待人工审核」，严禁直接放行
5. 违规图片文件要及时删除（OSS/本地磁盘），避免违规内容长期留存
6. 头像、商品图、相册等所有用户图片入口都要接检测，不能只检主图
```

## 违规内容处理

检测出违规内容后，处理动作必须形成闭环：拦截发布、提示用户、记录日志、人工复审。拦截是第一步——违规内容绝对不能入库；提示是用户体验的一部分——要告诉用户为什么被拦；日志是审计与追溯的依据；人工复审则针对 review（存疑）结果，避免机器误判伤害正常用户。

```java
// ContentController.java —— 发布接口整合内容安全检测
@RestController
@RequestMapping("/api/content")
public class ContentController {

    @Resource
    private ContentSecurityService securityService;

    @Resource
    private ContentAuditLogService auditLogService;

    @PostMapping("/publish")
    public Result publish(@RequestBody @Valid PublishRequest request,
                          @RequestHeader("X-Openid") String openid) {
        // 第一步：本地敏感词快速过滤（毫秒级，拦截明显违规）
        List<String> hits = securityService.filterLocal(request.getContent());
        if (!hits.isEmpty()) {
            auditLogService.record(openid, "LOCAL_BLOCK", hits.toString());
            return Result.fail("内容包含违禁词：" + String.join("、", hits));
        }
        // 第二步：微信内容安全接口检测
        String suggest = securityService.checkText(request.getContent(), openid);
        if ("risky".equals(suggest)) {
            auditLogService.record(openid, "WX_BLOCK", request.getContent());
            return Result.fail("内容疑似违规，请修改后重新发布");
        }
        if ("review".equals(suggest)) {
            // 存疑内容进人工复审队列，不直接展示
            auditLogService.enqueueManualReview(openid, request.getContent());
            return Result.fail("内容需要人工审核，请稍后查看结果");
        }
        // 第三步：通过，正常入库
        Long contentId = contentService.save(openid, request.getContent());
        auditLogService.record(openid, "PASS", String.valueOf(contentId));
        return Result.success(contentId);
    }
}
```

```java
// ContentAuditLogService.java —— 审核日志与人工复审队列
@Service
@Slf4j
public class ContentAuditLogService {

    @Resource
    private JdbcTemplate jdbcTemplate;

    /** 记录每一次检测动作，供审计与追溯 */
    public void record(String openid, String action, String detail) {
        // 日志中不记录完整文本，只记录截断内容与结论，保护用户隐私
        String safeDetail = detail.length() > 200 ? detail.substring(0, 200) : detail;
        jdbcTemplate.update(
            "INSERT INTO content_audit_log(openid, action, detail, create_time) VALUES (?,?,?,NOW())",
            openid, action, safeDetail);
        log.info("[内容安全] openid={} action={} detail={}", openid, action, safeDetail);
    }

    /** 进入人工复审队列（review 结果或异步检测未出结论的内容） */
    public void enqueueManualReview(String openid, String content) {
        jdbcTemplate.update(
            "INSERT INTO content_manual_review(openid, content, status, create_time) VALUES (?,?,'PENDING',NOW())",
            openid, content);
    }
}
```

```text
违规内容处理闭环：
1. 拦截 —— risky 内容不入库、不展示、不返回给用户
2. 提示 —— 明确告知用户内容未通过审核及原因，引导修改
3. 记录 —— 每次检测动作写审计日志（openid、结论、时间），日志脱敏截断
4. 复审 —— review 与检测异常内容进人工复审队列，管理端处理
5. 追溯 —— 同一 openid 多次违规要标记风险用户，触发更严格审核
6. 上报 —— 涉及违法犯罪的内容（赌博、诈骗、色情）按平台要求留存证据并配合处置
```

## 内容审核策略

单靠同步检测不够：微信接口有 400 次/分钟的配额，峰值期必然打满；异步检测的结果是延迟到达的；机器检测对擦边内容也会误判。因此生产环境必须设计「本地过滤 + 同步检测 + 异步兜底 + 人工复审」的分层审核策略。

```text
分层审核策略：
1. 第一层 本地敏感词 —— DFA 算法 + 词库（从数据库/配置中心热加载），毫秒级拦截明显违规
2. 第二层 同步检测 —— msgSecCheck/imgSecCheck 实时检测，决定内容能否立即展示
3. 第三层 异步兜底 —— 大文件、视频、音频走 media_check_async，结果出来后回写状态
4. 第四层 人工复审 —— review 结果、异步未决内容、用户举报内容进管理端人工队列
5. 兜底降级 —— 微信接口限流/故障时，内容先标记「待审核」不公开，防止漏检
6. 举报通道 —— 提供用户举报入口，举报内容强制进人工复审
```

```java
// 本地敏感词过滤（DFA 简化版，词库热加载）
@Service
public class SensitiveWordFilter {

    private volatile Set<String> wordSet = new HashSet<>();

    /** 从数据库/配置中心加载词库，支持运营后台热更新 */
    public void reload(List<String> words) {
        this.wordSet = new HashSet<>(words);
    }

    /** 返回命中的敏感词列表，空列表表示通过 */
    public List<String> filter(String content) {
        List<String> hits = new ArrayList<>();
        for (String word : wordSet) {
            if (content.contains(word)) {
                hits.add(word);
            }
        }
        return hits;
    }
}
```

```java
// 异步审核任务 —— 对暂存内容做二次检测并回写状态
@Component
public class AsyncAuditTask {

    @Resource
    private ContentSecurityService securityService;

    @Resource
    private JdbcTemplate jdbcTemplate;

    /** 定时扫描待审核内容，调用检测接口并回写结果（每 30 秒一轮） */
    @Scheduled(fixedDelay = 30000)
    public void auditPendingContents() {
        List<Map<String, Object>> pending = jdbcTemplate.queryForList(
            "SELECT id, content, openid FROM content WHERE audit_status = 'PENDING' LIMIT 50");
        for (Map<String, Object> row : pending) {
            Long id = ((Number) row.get("id")).longValue();
            String content = (String) row.get("content");
            String openid = (String) row.get("openid");
            try {
                String suggest = securityService.checkText(content, openid);
                String status = "risky".equals(suggest) ? "REJECTED"
                    : "review".equals(suggest) ? "MANUAL" : "PASSED";
                jdbcTemplate.update(
                    "UPDATE content SET audit_status = ? WHERE id = ?", status, id);
            } catch (Exception e) {
                // 单条失败不影响其他内容，下轮重试
                log.warn("异步审核失败 id={}", id, e);
            }
        }
    }
}
```

```text
审核策略落地要点：
1. 敏感词词库要可运营：管理后台增删词、热更新、按分类（政治/色情/广告）区分
2. 限流降级要有开关：微信接口不可用时切「先审后发」模式而非「全放行」
3. 审核状态机：PENDING → PASSED/REJECTED/MANUAL，状态可追溯可回滚
4. 风险用户分级：多次违规用户的内容强制走人工审核，正常用户走快速通道
5. 检测结果缓存：相同内容（如同一篇文章多次提交）用哈希去重，避免重复扣配额
6. 数据留存：审核日志按监管要求留存，删除用户数据时同步清理
```

## 应用场景实战

### 场景一：社区小程序评论发布接入全文安全检测

一个社区类小程序，用户在帖子下发表评论，要求评论实时可见但必须经过内容安全检测。完整实现：小程序端提交评论 → 后台先本地敏感词过滤 → 再调 msgSecCheck → 违规拦截、通过入库、review 进复审队列。

```java
// CommentController.java —— 评论发布完整链路
@RestController
@RequestMapping("/api/comment")
public class CommentController {

    @Resource
    private ContentSecurityService securityService;

    @Resource
    private CommentService commentService;

    @Resource
    private ContentAuditLogService auditLogService;

    @PostMapping("/add")
    public Result add(@RequestBody @Valid CommentRequest request,
                      @RequestHeader("X-Openid") String openid) {
        // 1. 长度与格式校验（@Valid 已处理），空内容直接拒绝
        // 2. 本地敏感词过滤
        List<String> hits = securityService.filterLocal(request.getContent());
        if (!hits.isEmpty()) {
            auditLogService.record(openid, "COMMENT_LOCAL_BLOCK", hits.toString());
            return Result.fail("评论包含违禁内容，请修改后重试");
        }
        // 3. 微信接口同步检测
        String suggest = securityService.checkText(request.getContent(), openid);
        if ("risky".equals(suggest)) {
            auditLogService.record(openid, "COMMENT_WX_BLOCK", request.getContent());
            return Result.fail("评论内容疑似违规，已被拦截");
        }
        // 4. 保存评论（review 结果标记为待人工审核，不对外展示）
        Comment comment = commentService.save(openid, request.getContent(),
            "review".equals(suggest) ? AuditStatus.MANUAL : AuditStatus.PASSED);
        return Result.success(comment.getId());
    }
}
```

### 场景二：图片社区的上传检测与异步复审

图片社区小程序，用户上传相册图片（可能超过 1MB），要求：小图同步检测即时拦截，大图提交异步检测，检测期间图片标记「审核中」仅本人可见，结果出来后更新状态，违规图片自动删除。

```java
// ImageUploadController.java —— 图片上传检测完整链路
@PostMapping("/api/content/uploadImage")
public Result uploadImage(@RequestParam("media") MultipartFile file,
                          @RequestHeader("X-Openid") String openid) {
    // 1. 基础校验：类型与大小
    String contentType = file.getContentType();
    if (contentType == null || !contentType.startsWith("image/")) {
        return Result.fail("仅支持图片文件");
    }
    if (file.getSize() > 10 * 1024 * 1024) {
        return Result.fail("图片不能超过 10MB");
    }
    // 2. 落盘或上传 OSS，拿到可访问 URL
    String objectUrl = ossService.upload(file);
    // 3. 按大小分流：小图同步检测，大图异步检测
    if (file.getSize() <= 1024 * 1024) {
        boolean safe = securityService.checkImage(file);
        if (!safe) {
            ossService.delete(objectUrl);
            auditLogService.record(openid, "IMG_WX_BLOCK", objectUrl);
            return Result.fail("图片未通过安全检测");
        }
        ImageRecord record = imageService.save(openid, objectUrl, AuditStatus.PASSED);
        return Result.success(record);
    }
    // 4. 大图：先保存为审核中状态，再提交异步检测
    ImageRecord record = imageService.save(openid, objectUrl, AuditStatus.PENDING);
    String traceId = securityService.checkMediaAsync(objectUrl, 2, openid);
    imageService.bindTraceId(record.getId(), traceId);
    return Result.success(record);
}
```

```java
// AsyncImageAuditTask.java —— 定时查询异步检测结果
@Component
public class AsyncImageAuditTask {

    @Resource
    private ContentSecurityService securityService;

    @Resource
    private ImageService imageService;

    /** 每分钟轮询一次待审核图片的异步检测结果 */
    @Scheduled(fixedDelay = 60000)
    public void pollAsyncResults() {
        List<ImageRecord> pending = imageService.listPending();
        for (ImageRecord record : pending) {
            if (record.getTraceId() == null) {
                continue;
            }
            String suggest = securityService.queryMediaCheckResult(record.getTraceId());
            if ("pass".equals(suggest)) {
                imageService.updateStatus(record.getId(), AuditStatus.PASSED);
            } else if ("risky".equals(suggest)) {
                imageService.updateStatus(record.getId(), AuditStatus.REJECTED);
                ossService.delete(record.getUrl());   // 违规图片物理删除
            }
            // review 结果保持待审核，转人工队列
        }
    }
}
```

```text
场景落地清单：
1. 评论/发帖类：本地过滤 → 同步检测 → 违规拦截 → 通过入库 → review 转人工
2. 图片类：小图同步检测、大图异步检测，审核中仅作者可见
3. 所有 UGC 入口统一封装在 ContentSecurityService，禁止各业务各自调微信接口
4. 审核状态字段（audit_status）是内容表的必备字段，查询接口必须过滤未通过内容
5. 违规文件（OSS/磁盘）要及时删除，防止存储侧残留违规内容
6. 异步任务要幂等：同一 trace_id 重复查询结果一致，避免重复回写
```

## 最佳实践与踩坑记录

### 最佳实践

1. 所有微信内容安全调用收敛到一个 ContentSecurityService，统一处理 token、限流、降级、日志，业务方只关心 suggest 结论
2. access_token 统一缓存（Redis，提前 200 秒过期），全局只有一个获取入口，双检锁防击穿
3. 采用「本地敏感词 + 同步检测 + 异步兜底 + 人工复审」四层策略，微信接口只做第二道防线
4. 检测结果必须落库（audit_status + 审计日志），审核结论可追溯，配合平台巡检与用户投诉举证
5. 接口异常（限流 45009、网络错误）时默认「先审后发」，把内容标记待审核而非直接放行，宁可损失体验不冒违规风险
6. 生产环境开通前先在小程序后台申请内容安全接口权限，并用测试号验证返回结构（version=2 与 version=1 响应不同）
7. 敏感词词库走运营后台管理并热更新，代码里只留默认兜底词表
8. 对高风险用户（多次违规、新注册号）提升审核等级，普通用户走快速通道，平衡体验与安全

### 踩坑记录

```text
坑 1：没申请内容安全权限，接口报 48001 api unauthorized
结论：调用 msgSecCheck 返回 errcode 48001（api 未授权），无法检测。
原因：内容安全接口需要在小程序后台「开发-开发设置-接口设置」中申请开通，个人主体部分接口默认不可用。
解法：提审前在后台申请内容安全权限；个人主体无法开通的，改用云函数内容安全或第三方检测服务。

坑 2：每请求都重新获取 access_token，触发 45009 限流
结论：高并发下频繁调用 cgi-bin/token，接口返回 45009（调用超过限额），内容检测全部失败。
原因：token 接口每日上限 2000 次，有效期 7200 秒，逐请求换取必然超限。
解法：用 Redis 缓存 access_token 并按 expires_in 提前 200 秒过期；获取处加 synchronized 双检锁。

坑 3：把微信返回的 review（建议复审）当通过直接放行
结论：version=2 返回 suggest=review 的内容直接展示，出现擦边内容被平台警告。
原因：review 表示机器判断存在风险但不确定，属于「需人工确认」的中间态，不是放行信号。
解法：review 结果一律进人工复审队列，复审通过前不对外展示；管理端提供批量复审工具。

坑 4：同步 imgSecCheck 传大图，接口报错或超时
结论：大于 1MB 的图片调 imgSecCheck 经常超时或返回非预期错误，且占用大量配额。
原因：同步图片检测对文件大小有限制，大图同步检测耗时不可控。
解法：小图走 imgSecCheck 同步检测，大图/视频/音频走 media_check_async 异步检测 + 轮询 trace_id。

坑 5：微信接口超时/限流时直接放行，导致违规内容漏检
结论：高峰期内容安全接口偶发超时，代码 catch 后返回「通过」，违规内容上线后被平台巡检抓到。
原因：异常处理写成了「检测失败 = 无违规」，把服务异常当成了检测通过。
解法：异常与限流默认拦截（内容标记待审核/拒绝发布），配合人工复审兜底；监控接口错误率并告警。

坑 6：检测后不落库不记日志，平台要求举证时无据可依
结论：用户投诉「我的内容为什么被删」，平台巡检要求说明违规处理记录，拿不出审计数据。
原因：内容检测结果只做了内存判断，没有持久化审核结论与日志。
解法：内容表加 audit_status 字段，审核动作写 content_audit_log（openid、结论、时间），日志内容脱敏截断。

坑 7：违规图片只标记状态不删文件，OSS 里残留违规内容
结论：图片标记为违规但源文件仍存在 OSS，平台抽查存储内容时仍认定违规。
原因：只更新了数据库状态，没有执行文件删除。
解法：违规图片在状态回写后同步删除 OSS/本地文件；删除失败要告警重试，确保物理删除。

坑 8：本地敏感词写死在代码里，运营无法及时更新词库
结论：新出现的违规词（变形词、谐音词）无法及时拦截，只能等微信接口兜底，接口配额被大量消耗。
原因：词库硬编码，更新一次要重新发版。
解法：词库存数据库/配置中心，管理后台可增删，服务启动与定时任务热加载；配合正则匹配变形词。
```

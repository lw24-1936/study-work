## 概述

小程序后台接口安全的目标是保证「数据不被窃听、请求不被伪造、参数不被篡改、数据不被泄露」。小程序端的所有网络请求默认走 HTTPS 加密通道，后台需要在域名白名单、参数校验、注入防护、签名防刷、数据脱敏五个维度构建纵深防御。

接口安全的本质是假设攻击者：能抓包看到所有请求、能伪造任意请求体、能批量重放请求、能尝试注入恶意数据。因此前端校验只是体验优化，服务端校验才是安全边界；HTTPS 只解决传输层窃听，业务层防护（参数校验、签名、限流、脱敏）必须由后台独立完成。本章所有代码基于 SpringBoot 3 + 小程序 wx.request 场景。

```text
接口安全的核心要点：
1. HTTPS —— 小程序强制 HTTPS 请求，后台配置 request 合法域名与有效证书
2. 参数校验 —— 服务端对每个入参做类型、长度、格式、枚举校验，前端校验不可信
3. 防注入 —— MyBatis 参数化查询防 SQL 注入，输出编码与过滤防 XSS
4. 签名防刷 —— 接口签名 + 时间戳 + nonce 防篡改防重放，Redis 限流防刷
5. 数据脱敏 —— 手机号、身份证等敏感数据接口层脱敏，日志层脱敏
6. 纵深防御 —— 传输加密、参数校验、鉴权、限流、审计层层叠加，不依赖单点防护
```

## HTTPS 与合法域名

微信小程序对网络请求有硬性约束：wx.request、wx.uploadFile、wx.downloadFile、wx.connectSocket 只能请求 HTTPS 域名，且域名必须在小程序后台「开发-开发管理-开发设置-服务器域名」中配置为 request 合法域名。未配置的域名在线上环境直接报「url not in domain list」。

合法域名要求：必须 HTTPS（证书有效、TLS 1.2 及以上）、域名已完成 ICP 备案、不能是 IP 地址或 localhost、不能带端口。开发阶段可以在开发者工具勾选「不校验合法域名」调试，但上传体验版/正式版必须配置真实域名。

```text
HTTPS 与域名配置要点：
1. request 合法域名：wx.request 使用的后台域名，线上必须配置且为 HTTPS
2. uploadFile/downloadFile 合法域名：文件上传下载单独配置，与 request 分开
3. socket 合法域名：WebSocket 场景单独配置 wss:// 域名
4. 证书要求：证书链完整、在有效期内、与域名匹配，过期会导致请求失败
5. 域名变更限制：request 合法域名每月可修改 50 次，上线前规划好域名
6. 开发者工具可勾选「不校验合法域名」仅用于本地调试，不可带到线上
```

小程序端统一请求封装（自动携带登录态、统一错误处理）：

```js
// utils/request.js —— 小程序网络请求统一封装
const BASE_URL = 'https://api.example.com'

function request(path, method = 'GET', data = {}) {
  return new Promise((resolve, reject) => {
    wx.request({
      url: `${BASE_URL}${path}`,
      method,
      data,
      timeout: 10000,
      header: {
        'Content-Type': 'application/json',
        // 登录后由 app.js 注入 token，后台校验身份
        'Authorization': `Bearer ${getApp().globalData.token || ''}`
      },
      success(res) {
        if (res.statusCode === 200 && res.data.code === 0) {
          resolve(res.data.data)
        } else if (res.statusCode === 401) {
          // token 过期：跳登录
          getApp().relogin()
          reject(new Error('登录已过期'))
        } else {
          wx.showToast({ title: res.data.message || '请求失败', icon: 'none' })
          reject(new Error(res.data.message))
        }
      },
      fail(err) {
        wx.showToast({ title: '网络异常，请稍后重试', icon: 'none' })
        reject(err)
      }
    })
  })
}

module.exports = {
  get: (path, data) => request(path, 'GET', data),
  post: (path, data) => request(path, 'POST', data)
}
```

```text
HTTPS 落地清单：
1. 证书用正规 CA 签发（Let's Encrypt / 云厂商免费证书），禁用自签名证书上线
2. 证书部署后检查证书链完整，用在线工具验证 TLS 1.2/1.3 与证书有效期
3. 域名配置变更后，小程序端需重新上传提审才能生效（域名配置随代码版本走）
4. 多环境（dev/test/prod）域名分开管理，环境变量注入 BASE_URL
5. 小程序端不拼接不可信 URL，防止将外部地址传入 wx.request 造成 SSRF 类风险
6. 上线前用真机关闭「不校验合法域名」选项验证全部接口可用
```

## 服务端参数校验

前端表单校验只是体验，服务端校验才是安全边界。SpringBoot 使用 spring-boot-starter-validation 的 Jakarta Bean Validation 规范做声明式校验：@Validated + @NotBlank、@Length、@Pattern、@Min/@Max、@Email 等注解，配合全局异常处理器统一返回校验错误。

校验规则设计原则：白名单优先（枚举值用 @Pattern 限定而非黑名单过滤）、长度必限（防超长字段撑爆数据库与日志）、数值范围必限（防负数、超大数绕过业务规则）、类型必对（防字符串注入数字字段）。对于「手机号、身份证」等格式敏感字段，用正则严格校验。

```xml
<!-- pom.xml 依赖 -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-validation</artifactId>
</dependency>
```

```java
// dto/RegisterRequest.java —— 请求参数 DTO，注解式校验

public class RegisterRequest {

    @NotBlank(message = "手机号不能为空")
    @Pattern(regexp = "^1[3-9]\\d{9}$", message = "手机号格式不正确")
    private String phone;

    @NotBlank(message = "验证码不能为空")
    @Length(min = 4, max = 6, message = "验证码长度不正确")
    private String code;

    @NotBlank(message = "昵称不能为空")
    @Length(min = 1, max = 20, message = "昵称长度需在 1-20 个字符之间")
    private String nickname;

    @Min(value = 0, message = "年龄不能为负数")
    @Max(value = 150, message = "年龄不合法")
    private Integer age;

    @Pattern(regexp = "^(MALE|FEMALE|UNKNOWN)$", message = "性别枚举值不合法")
    private String gender;
}
```

```java
            .findFirst()
            .orElse("参数不合法");
```

```text
参数校验要点：
1. 前端校验（required、maxlength）只是体验，后端校验才是安全边界，必须双端都做
2. 所有请求 DTO 加 @Valid，全局异常处理器统一返回校验错误，禁止在校验失败时返回 500
3. 字符串长度必限（@Length），防止超长字段触发数据库错误或日志注入
4. 枚举字段用 @Pattern 白名单限定，禁止直接拼接进 SQL 或动态逻辑
5. JSON 反序列化时对未知字段默认忽略（@JsonIgnoreProperties(ignoreUnknown = true)），防止参数污染
6. 分页参数限制 max 值（如每页最多 100 条），防止一次拉全库拖垮服务
```

## 防注入 SQL 注入与 XSS

SQL 注入与 XSS（跨站脚本）是后台接口最常见的两类注入攻击。SQL 注入的根因是把用户输入直接拼进 SQL 语句；XSS 的根因是把用户输入直接当 HTML/脚本渲染。防护原则：参数化查询 + 输入校验 + 输出编码，三层叠加。

MyBatis 中 #{} 是预编译参数占位（安全），${} 是字符串拼接（危险）。动态排序、动态表名等必须用 ${} 的场景，要先用白名单映射校验。XSS 防护分为存储型（入库前过滤/转义）与反射型（输出时编码），管理后台（Vue）渲染用户内容时同样需要转义。

```java
// mapper/UserMapper.java —— 参数化查询防 SQL 注入
@Mapper
public interface UserMapper {

    // 正确：#{} 预编译，参数值不会被当作 SQL 执行
    @Select("SELECT * FROM user WHERE nickname LIKE CONCAT('%', #{keyword}, '%')")
    List<User> searchByNickname(@Param("keyword") String keyword);

    // 错误：${} 直接拼接，keyword 传入 "'; DROP TABLE user; --" 即可注入
    // @Select("SELECT * FROM user WHERE nickname LIKE '%${keyword}%'")
}
```

```java
// mapper/UserMapper.xml —— XML 中动态排序的安全写法（白名单映射）
<select id="listUsers" resultType="com.example.entity.User">
    SELECT * FROM user
    <if test="orderBy != null">
        ORDER BY
        <choose>
            <when test="orderBy == 'createTime'">create_time</when>
            <when test="orderBy == 'nickname'">nickname</when>
            <!-- 白名单之外的排序字段直接拒绝，不拼接进 SQL -->
            <otherwise>id</otherwise>
        </choose>
        <choose>
            <when test="order == 'asc'">ASC</when>
            <otherwise>DESC</otherwise>
        </choose>
    </if>
</select>
```

```java
// util/XssUtil.java —— XSS 过滤与转义工具
public final class XssUtil {

    private XssUtil() {
    }

    /** 输出到 HTML 前转义，防止反射型/存储型 XSS */
    public static String escapeHtml(String input) {
        if (input == null) {
            return null;
        }
        return input.replace("&", "&amp;")
                   .replace("<", "&lt;")
                   .replace(">", "&gt;")
                   .replace("\"", "&quot;")
                   .replace("'", "&#39;");
    }

    /** 存储前剥离危险标签（富文本场景配合白名单 sanitizer 使用） */
    public static String stripScript(String input) {
        if (input == null) {
            return null;
        }
        return input.replaceAll("(?i)<script.*?</script>", "")
                   .replaceAll("(?i)javascript:", "")
                   .replaceAll("(?i)onerror\\s*=", "onerror_disabled=");
    }
}
```

```java
// controller/UserController.java —— 入库前过滤 + 输出时转义
@PostMapping("/profile")

    // 输入侧：昵称等展示字段存储前剥离脚本
    String safeNickname = XssUtil.stripScript(request.getNickname());
    userService.updateNickname(request.getUserId(), safeNickname);
```

```text
防注入要点：
1. SQL 一律用 #{} 参数化查询，${} 只允许出现在白名单映射后的场景
2. 动态排序字段用 switch/choose 白名单转换，禁止把前端传的字段名直接拼 SQL
3. 用户展示内容（昵称、评论）入库前剥离脚本，输出到页面时做 HTML 转义
4. 富文本编辑器内容用白名单 sanitizer（如 OWASP Java HTML Sanitizer），只留安全标签
5. 管理后台（Vue）渲染用户内容时用 {{ }} 插值（自动转义），v-html 必须二次消毒
6. 数据库账号最小权限：业务账号只授 DML 权限，禁止 DDL 权限，降低注入影响面
```

## 签名防刷与限流

接口签名用于防止请求被篡改与伪造：客户端与后台约定 appSecret，把参数（含 timestamp、nonce）按规则排序拼接后做 HMAC-SHA256，生成 sign 随请求携带；后台用同样的规则重算 sign，不一致即拒绝。timestamp 用于防过期重放（超过 5 分钟拒绝），nonce 用于防同参数重复提交（Redis SETNX 去重）。

限流用于防止接口被刷：Redis 实现滑动窗口/令牌桶，按用户、按 IP、按接口维度限流；登录、验证码、支付、搜索等高危接口限流阈值更严格。签名 + 时间戳 + nonce + 限流四件套组合，才能有效对抗批量脚本攻击。

```java
// util/SignUtil.java —— 签名生成与校验（完整实现）
@Component
public class SignUtil {

    @Value("${app.sign.secret}")
    private String signSecret;

    /** 服务端校验签名：参数排序拼接 + HMAC-SHA256 */
    public boolean verifySign(Map<String, String> params, String clientSign) {
        // 1. 时间戳防重放：超过 5 分钟视为过期请求
        String timestamp = params.get("timestamp");
        if (timestamp == null) {
            return false;
        }
        long ts;
        try {
            ts = Long.parseLong(timestamp);
        } catch (NumberFormatException e) {
            return false;
        }
        if (Math.abs(System.currentTimeMillis() / 1000 - ts) > 300) {
            return false;
        }
        // 2. 重算签名并比对（常量时间比较，防时序攻击）
        String expect = buildSign(params);
        return MessageDigest.isEqual(
            expect.getBytes(StandardCharsets.UTF_8),
            clientSign.getBytes(StandardCharsets.UTF_8));
    }

    /** 签名规则：剔除 sign 字段后按 key 字典序拼接 key=value&... 再 HMAC-SHA256 */
    public String buildSign(Map<String, String> params) {
        return params.entrySet().stream()
            .filter(e -> !"sign".equals(e.getKey()))
            .sorted(Map.Entry.comparingByKey())
            .map(e -> e.getKey() + "=" + e.getValue())
            .collect(Collectors.joining("&"))
            .transform(s -> hmacSha256(s, signSecret));
    }

    private String hmacSha256(String data, String secret) {
        try {
            Mac mac = Mac.getInstance("HmacSHA256");
            mac.init(new SecretKeySpec(secret.getBytes(StandardCharsets.UTF_8), "HmacSHA256"));
            byte[] bytes = mac.doFinal(data.getBytes(StandardCharsets.UTF_8));
            StringBuilder sb = new StringBuilder();
            for (byte b : bytes) {
                sb.append(String.format("%02x", b));
            }
            return sb.toString();
        } catch (Exception e) {
            throw new BizException("签名计算失败");
        }
    }
}
```

```java
// util/RateLimiter.java —— Redis 滑动窗口限流（完整实现）
@Component
public class RateLimiter {

    @Resource
    private StringRedisTemplate redisTemplate;

    /**
     * 滑动窗口限流
     * @param key    限流维度 key，如 "rate:login:openid_123"
     * @param window 窗口秒数
     * @param limit  窗口内最大次数
     */
    public boolean allow(String key, long window, long limit) {
        long now = System.currentTimeMillis();
        String zsetKey = key;
        // 清理窗口外的旧记录
        redisTemplate.opsForZSet().removeRangeByScore(zsetKey, 0, now - window * 1000);
        Long count = redisTemplate.opsForZSet().zCard(zsetKey);
        if (count != null && count >= limit) {
            return false;
        }
        // 当前请求入窗口
        redisTemplate.opsForZSet().add(zsetKey, String.valueOf(now) + "_" + Thread.currentThread().getId(), now);
        redisTemplate.expire(zsetKey, Duration.ofSeconds(window + 1));
        return true;
    }
}
```

```java
// controller/AuthController.java —— 登录接口防刷（签名 + 限流 + nonce 防重放）
@RestController
@RequestMapping("/api/auth")
public class AuthController {

    @Resource
    private SignUtil signUtil;

    @Resource
    private RateLimiter rateLimiter;

    @Resource
    private StringRedisTemplate redisTemplate;

    @PostMapping("/login")
    public Result login(@RequestBody LoginRequest request) {
        // 1. 接口签名校验：防伪造请求
        Map<String, String> params = request.toParamMap();
        if (!signUtil.verifySign(params, request.getSign())) {
            return Result.fail("签名校验失败");
        }
        // 2. nonce 防重放：同一 nonce 只能使用一次
        Boolean firstUse = redisTemplate.opsForValue()
            .setIfAbsent("nonce:" + request.getNonce(), "1", Duration.ofMinutes(10));
        if (Boolean.FALSE.equals(firstUse)) {
            return Result.fail("请求已过期，请重试");
        }
        // 3. 按用户 + IP 限流：同一账号 1 分钟最多 10 次登录尝试
        String key = "rate:login:" + request.getPhone();
        if (!rateLimiter.allow(key, 60, 10)) {
            return Result.fail("操作过于频繁，请稍后再试");
        }
        // 4. 业务登录逻辑
        return Result.success(userService.login(request.getPhone(), request.getCode()));
    }
}
```

```text
签名防刷与限流要点：
1. 签名参数必须包含 timestamp 与 nonce，缺一不可；签名算法与密钥只存服务端
2. 时间戳校验窗口 5 分钟内，nonce 用 Redis SETNX 保证一次有效，双保险防重放
3. 登录、验证码、支付、搜索等接口必须限流，阈值按业务定（登录 1 分钟 10 次等）
4. 限流要按用户、IP、接口多维度叠加，防止单维度绕过（换 IP 刷）
5. 签名校验失败、限流命中都要记审计日志，用于识别攻击特征
6. 客户端 secret 分环境管理，泄露后服务端可一键轮换并支持多版本签名兼容过渡
```

## 数据脱敏

数据脱敏指在展示、传输、日志环节隐藏敏感信息的中间部分，只保留必要前缀/后缀，防止敏感数据泄露。常见脱敏规则：手机号 138****5678、身份证 110***********1234、邮箱 zh***@example.com、姓名 张*。脱敏要在接口返回层与日志层分别处理。

接口层脱敏推荐用 Jackson 自定义序列化器 + 注解：DTO 字段标注 @Sensitive，序列化时自动脱敏，业务代码零侵入；后台管理端需要查看明文时走独立接口并做权限校验与操作审计。日志层脱敏用 logback 自定义 Converter 或 AOP，确保任何日志输出都不含明文敏感字段。

```java
// util/DesensitizeUtil.java —— 脱敏工具（完整实现）
public final class DesensitizeUtil {

    private DesensitizeUtil() {
    }

    /** 手机号：保留前 3 后 4 */
    public static String phone(String phone) {
        if (phone == null || phone.length() < 7) {
            return phone;
        }
        return phone.replaceAll("(\\d{3})\\d{4}(\\d{4})", "$1****$2");
    }

    /** 身份证：保留前 6 后 4 */
    public static String idCard(String idCard) {
        if (idCard == null || idCard.length() < 10) {
            return idCard;
        }
        return idCard.replaceAll("(\\d{6})\\d+(\\w{4})", "$1********$2");
    }

    /** 邮箱：保留首字母与域名 */
    public static String email(String email) {
        if (email == null || !email.contains("@")) {
            return email;
        }
        String[] parts = email.split("@");
        String name = parts[0];
        String maskedName = name.length() <= 2
            ? name.substring(0, 1) + "***"
            : name.substring(0, 2) + "***";
        return maskedName + "@" + parts[1];
    }

    /** 姓名：保留姓氏 */
    public static String name(String name) {
        if (name == null || name.length() <= 1) {
            return name;
        }
        return name.substring(0, 1) + "*".repeat(name.length() - 1);
    }
}
```

```java
// serializer/SensitiveSerializer.java —— Jackson 脱敏序列化器
public class SensitiveSerializer extends JsonSerializer<String> {

    private final SensitiveType type;

    public SensitiveSerializer(SensitiveType type) {
        this.type = type;
    }

    @Override
    public void serialize(String value, JsonGenerator gen, SerializerProvider serializers)
            throws IOException {
        if (value == null) {
            gen.writeNull();
            return;
        }
        switch (type) {
            case PHONE -> gen.writeString(DesensitizeUtil.phone(value));
            case ID_CARD -> gen.writeString(DesensitizeUtil.idCard(value));
            case EMAIL -> gen.writeString(DesensitizeUtil.email(value));
            case NAME -> gen.writeString(DesensitizeUtil.name(value));
            default -> gen.writeString(value);
        }
    }
}

enum SensitiveType { PHONE, ID_CARD, EMAIL, NAME }
```

```text
1. 手机号、身份证、邮箱、姓名、地址、银行卡号都属于默认脱敏字段
2. 接口层用 Jackson 注解自动脱敏，业务代码零侵入，避免遗漏
```

## 应用场景实战

### 场景一：小程序登录接口接入签名、nonce 防重放与限流

登录接口是攻击者最常刷的接口（撞库、验证码轰炸、批量注册）。完整防护链路：小程序端生成 timestamp/nonce/sign 请求头 → 后台校验签名 → nonce 去重 → 按手机号限流 → 验证码校验 → 登录成功签发 JWT。

```js
// utils/sign.js —— 小程序端签名生成
const CryptoJS = require('./crypto-js')  // crypto-js 库，npm 安装

const APP_SECRET = 'client-side-secret'  // 生产环境由服务端下发，避免硬编码

function buildSign(params) {
  // 1. 过滤空值与非业务字段，剔除 sign 本身
  const keys = Object.keys(params)
    .filter((k) => params[k] !== undefined && params[k] !== null && params[k] !== '' && k !== 'sign')
    .sort()
  // 2. 字典序拼接 key=value&...
  const raw = keys.map((k) => `${k}=${params[k]}`).join('&')
  // 3. HMAC-SHA256 计算签名
  return CryptoJS.HmacSHA256(raw, APP_SECRET).toString(CryptoJS.enc.Hex)
}

function withSign(data) {
  const timestamp = String(Math.floor(Date.now() / 1000))
  const nonce = `${timestamp}${Math.random().toString(36).slice(2, 10)}`
  const params = { ...data, timestamp, nonce }
  return {
    ...params,
    sign: buildSign(params)
  }
}

module.exports = { withSign }
```

### 场景二：用户列表接口的越权防护与脱敏

用户列表/详情接口的两大风险：越权（普通用户访问他人数据）与泄露（接口返回明文手机号）。完整实现：接口鉴权（JWT 解析用户身份）→ 水平越权校验（资源归属检查）→ 返回脱敏 DTO → 管理员查看明文走审计接口。

```java
// controller/OrderController.java —— 水平越权防护（完整实现）
@RestController
@RequestMapping("/api/order")
public class OrderController {

    @Resource
    private OrderService orderService;

    /** 查询订单详情：必须校验订单归属当前登录用户，防水平越权 */
    @GetMapping("/{orderId}")
    public Result getOrder(@PathVariable Long orderId,
                           @RequestHeader("Authorization") String token) {
        Long userId = userService.parseUserId(token);
        Order order = orderService.getById(orderId);
        if (order == null) {
            return Result.fail("订单不存在");
        }
        // 关键：校验订单归属，他人订单返回「不存在」而非「无权限」细节
        if (!order.getUserId().equals(userId)) {
            return Result.fail("订单不存在");
        }
        return Result.success(orderService.toVO(order));
    }

    /** 管理员查看订单明文手机号：权限校验 + 审计 */
    @GetMapping("/admin/{orderId}")
    @RequireRole("ADMIN")
    public Result getOrderForAdmin(@PathVariable Long orderId,
                                   @RequestHeader("Authorization") String token) {
        Long adminId = userService.parseUserId(token);
        Order order = orderService.getById(orderId);
        auditLogService.record("ADMIN_VIEW_ORDER", adminId, orderId);
        return Result.success(orderService.toAdminVO(order));  // 明文 DTO
    }
}
```

```text
场景落地清单：
1. 登录等高危接口：签名 + nonce + 限流 + 验证码四层防护，缺一不可
2. 所有涉及资源归属的接口（订单、评论、收藏）必须校验资源 userId 与当前用户一致
3. 越权访问统一返回「不存在」语义，不暴露资源是否存在的信息
4. 普通接口返回脱敏 DTO，明文查看走独立的管理员接口并记录审计
5. 拦截器统一做签名校验，业务代码不重复实现，白名单接口（微信回调）单独配置
6. 上线前用安全测试用例覆盖：越权、注入、重放、超限、脱敏五类场景
```

## 最佳实践与踩坑记录

### 最佳实践

1. 安全边界在服务端：前端校验只做体验，所有校验、鉴权、限流逻辑必须在 SpringBoot 服务端实现
2. 参数校验用 Bean Validation 注解集中声明，全局异常处理器统一返回，禁止每个 Controller 手写 if 校验
3. 所有 SQL 使用 #{} 参数化查询，${} 场景（动态排序）一律白名单映射，从代码规范上杜绝注入
4. 签名 + 时间戳 + nonce + 限流四件套用于高危接口（登录、支付、验证码），普通查询接口用鉴权 + 限流即可
5. 敏感字段三层脱敏：接口返回层（Jackson 注解）、日志层（AOP/logback）、数据库查询层（测试数据脱敏）
6. 越权防护是重灾区：每个资源接口都要做归属校验，且统一返回「不存在」避免信息泄露
7. 安全配置（密钥、secret）走环境变量/配置中心，禁止硬编码进代码仓库，泄露后可轮换
8. 上线前做一轮安全自查：抓包验证签名与脱敏、构造注入 payload、批量重放请求、检查日志无明文

### 踩坑记录

```text
坑 1：忘了配置 request 合法域名，线上请求全部失败
结论：真机上 wx.request 报「url not in domain list」，接口全部调不通。
原因：开发者工具勾选了「不校验合法域名」调试正常，体验版/正式版未配置 request 合法域名。
解法：小程序后台「开发-开发管理-开发设置-服务器域名」配置 request 合法域名；开发工具关闭不校验选项验证。

坑 2：HTTPS 证书过期或证书链不完整，请求偶发失败
结论：线上接口时而正常时而超时，真机报「request:fail」。
原因：证书链缺失中间证书，或证书过期未续期，客户端校验证书失败。
解法：部署完整证书链（含中间证书），配置证书到期监控告警，提前续期；用在线 SSL 检测工具验证。

坑 3：只做前端校验，绕过小程序直接调接口注入脏数据
结论：抓包直接 POST 接口，超长文本、负数金额、非法枚举全部入库，管理后台数据混乱。
原因：前端表单校验只是体验，服务端没有 Bean Validation 校验。
解法：所有请求 DTO 加 @Valid 与长度/格式/枚举校验，全局异常处理器统一返回校验错误。

坑 4：MyBatis 用了 ${} 拼接导致 SQL 注入
结论：安全扫描发现 nickname 搜索接口存在 SQL 注入漏洞，可拖库。
原因：搜索条件用了 LIKE '%${keyword}%'，用户输入被直接拼进 SQL。
解法：改为 #{keyword} 参数化 + CONCAT 拼接；动态排序字段用白名单映射，禁止 ${} 直接拼接。

坑 5：昵称渲染未转义，管理后台被存储型 XSS 攻击
结论：用户在昵称里提交 <script>alert(1)</script>，管理后台打开用户列表弹窗。
原因：昵称存储未过滤、Vue 渲染用了 v-html 或后台未转义输出。
解法：入库前 stripScript 过滤，输出用 {{ }} 插值自动转义；富文本内容用白名单 sanitizer。

坑 6：接口没有限流，验证码接口被刷爆
结论：短信验证码接口被脚本批量调用，短信费用暴涨，用户收到骚扰短信投诉。
原因：验证码接口无频控，攻击者循环调用即可触发大量短信。
解法：按手机号 + IP 双重限流（1 分钟 N 次）；验证码有效期与尝试次数限制；异常流量告警。

坑 7：签名校验忘了校验时间戳和 nonce，重放攻击得逞
结论：攻击者抓包后循环重放同一登录/下单请求，重复下单成功。
原因：只校验了 sign 是否正确，没校验 timestamp 时效与 nonce 唯一性。
解法：签名参数强制包含 timestamp（5 分钟窗口）与 nonce（Redis SETNX 一次性），两者都校验。

坑 8：订单详情接口没做归属校验，水平越权泄露他人数据
结论：遍历订单 ID 可查看任意用户订单，含手机号、地址等隐私信息。
原因：getOrder 只按 orderId 查询，没有校验订单归属与当前登录用户。
解法：解析 token 拿 userId，校验 order.userId == userId；不匹配统一返回「订单不存在」。

坑 9：接口直接返回明文手机号，被爬虫批量抓取
结论：用户列表接口返回明文手机号，数据被爬虫抓取用于营销骚扰。
原因：DTO 直接映射数据库字段，没有脱敏处理。
解法：接口层 Jackson 注解脱敏；明文查看走独立管理员接口 + 权限校验 + 审计日志。
```

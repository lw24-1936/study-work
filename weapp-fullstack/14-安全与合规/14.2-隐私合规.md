## 概述

隐私合规是小程序上线的硬性要求。微信平台自 2023 年 9 月起强制执行用户隐私保护指引机制：小程序在收集用户信息（昵称、手机号、位置、相册、摄像头等）前，必须先声明「用户隐私保护指引」，并在用户授权前展示隐私弹窗，否则相关隐私接口无法正常调用，提审也会被拒。

隐私合规建设分为四个层面：隐私协议与指引声明（在后台填写收集的信息与用途）、隐私接口与弹窗（wx.getPrivacySetting、wx.onNeedPrivacyAuthorization 等）、权限申请规范（按需申请、最小化授权、scope 权限体系）、个人信息处理与法规合规（个人信息保护法、儿童信息保护、第三方 SDK 合规）。本章结合小程序端代码与 SpringBoot 后台，给出完整的隐私合规落地方案。

```text
隐私合规的核心要点：
1. 指引声明 —— 小程序后台填写「用户隐私保护指引」，声明收集的信息类型与用途
2. 隐私弹窗 —— 首次收集用户信息前必须弹窗告知，用户同意后才能调用隐私接口
3. 按需授权 —— 权限按业务场景最小化申请，能不用就不申请，拒绝后引导开启
4. 告知义务 —— 收集前告知用途、存储方式、删除渠道，禁止超范围收集
5. 法规底线 —— 遵循个人信息保护法（PIPL），14 岁以下儿童信息需监护人同意
6. SDK 合规 —— 接入的第三方 SDK 也要在隐私指引中声明，否则审核不通过
```

## 隐私协议与用户隐私保护指引

用户隐私保护指引是微信平台要求小程序开发者在小程序后台「设置-服务内容声明-用户隐私保护指引」中填写的声明文件，内容包括：小程序收集哪些用户信息（手机号、位置、相册、摄像头、麦克风、身份证号等）、收集用途、存储方式、联系方式、用户如何管理（查询、更正、删除、注销）等。

填写指引后，微信会生成隐私协议文本，用户可在小程序内通过 wx.openPrivacyContract 打开查看。指引中声明的信息类型必须与实际收集行为一致——后台声明了「收集用户位置」而代码没调用，或代码调用了 getLocation 但指引没声明，都会被平台检测并拒绝提审或限制接口调用。

```text
隐私保护指引填写要点：
1. 信息类型逐项勾选：位置、相册、摄像头、麦克风、手机号、身份证、通讯录等，与实际使用一一对应
2. 用途描述具体化：例如「用于展示附近的商家」而非笼统的「用于业务需要」
3. 填写开发者联系方式：邮箱/电话，用于用户隐私投诉
4. 提供用户管理渠道：在小程序内提供隐私政策全文、删除个人信息、注销账号的入口
5. 指引变更需重新提审：新增收集项必须更新指引并重新提交审核
6. 后台声明与代码行为必须一致，平台会做自动化比对检测
```

小程序端获取并展示隐私协议（含协议名称与打开协议页面）：

```js
// utils/privacy.js —— 隐私协议工具
function getPrivacySetting() {
  return new Promise((resolve, reject) => {
    if (!wx.getPrivacySetting) {
      // 基础库低于 2.32.3 不支持隐私接口，直接放行（老版本兼容）
      resolve({ needAuthorization: false, privacyContractName: '' })
      return
    }
    wx.getPrivacySetting({
      success: resolve,
      fail: reject
    })
  })
}

// pages/index/index.js —— 页面中展示隐私协议入口
Page({
  onLoad() {
    getPrivacySetting().then((res) => {
      // res.needAuthorization: 是否需要进行隐私授权
      // res.privacyContractName: 隐私协议名称，如《用户隐私保护指引》
      this.setData({
        needPrivacy: res.needAuthorization,
        contractName: res.privacyContractName || '用户隐私保护指引'
      })
    })
  },

  openPrivacyContract() {
    if (wx.openPrivacyContract) {
      wx.openPrivacyContract({
        fail: () => wx.showToast({ title: '暂无法打开隐私协议', icon: 'none' })
      })
    }
  }
})
```

```text
隐私协议相关接口：
1. wx.getPrivacySetting —— 查询是否需要隐私授权、获取协议名称
2. wx.openPrivacyContract —— 打开隐私协议页面，展示指引全文
3. wx.onNeedPrivacyAuthorization —— 监听隐私授权需求，开发者弹出自定义弹窗
4. wx.requirePrivacyAuthorize —— 模拟触发隐私弹窗（用于自测流程）
5. app.json 配置 __usePrivacyCheck__: true —— 开启隐私检测（基础库 2.32.3+）
6. 隐私弹窗在真机上才会出现，开发者工具需开启「模拟隐私弹窗」或真机预览验证
```

## 隐私相关接口与隐私弹窗

微信在基础库 2.32.3 起引入隐私接口机制：当小程序首次调用涉及用户隐私的接口（wx.getLocation、wx.chooseMedia、wx.getUserProfile 等）时，微信会先弹出隐私授权弹窗，用户同意后才继续执行。开发者可以使用 wx.onNeedPrivacyAuthorization 监听授权需求并弹出自定义弹窗，或使用 button 的 open-type="agreePrivacyAuthorization" 让用户主动确认。

```js
// pages/index/index.js —— 自定义隐私弹窗（完整实现）
Page({
  onLoad() {
    // 注册隐私授权监听：微信在需要授权时回调
    if (wx.onNeedPrivacyAuthorization) {
      wx.onNeedPrivacyAuthorization((resolve) => {
        // resolve 必须被调用：{ event: 'agree' } 或 { event: 'disagree' }
        this.showPrivacyDialog(resolve)
      })
    }
  },

  showPrivacyDialog(resolve) {
    // 缓存 resolve，等用户点击按钮后再调用
    this._privacyResolve = resolve
    this.setData({ showPrivacyDialog: true })
  },

  handleAgree() {
    this.setData({ showPrivacyDialog: false })
    if (this._privacyResolve) {
      this._privacyResolve({ event: 'agree' })   // 用户同意，继续后续操作
      this._privacyResolve = null
    }
  },

  handleDisagree() {
    this.setData({ showPrivacyDialog: false })
    if (this._privacyResolve) {
      this._privacyResolve({ event: 'disagree' }) // 用户拒绝，中断后续操作
      this._privacyResolve = null
    }
  }
})
```

```wxml
<!-- pages/index/index.wxml —— 自定义隐私弹窗（底部弹出层） -->
<view class="privacy-dialog" wx:if="{{showPrivacyDialog}}">
  <view class="privacy-dialog-content">
    <view class="privacy-dialog-title">隐私保护提示</view>

      在使用本功能前，请阅读并同意
      <text class="privacy-link" bindtap="openPrivacyContract">{{contractName}}</text>，
      我们将仅在本功能范围内使用您的信息。
    </view>
    <view class="privacy-dialog-btns">
      <button size="mini" bindtap="handleDisagree">不同意</button>
      <!-- open-type="agreePrivacyAuthorization" 是官方推荐的同意按钮 -->
      <button size="mini" type="primary" open-type="agreePrivacyAuthorization"
              bindagreeprivacyauthorization="handleAgree">同意并继续</button>
    </view>
  </view>
</view>
```

```text
隐私弹窗实现要点：
1. onNeedPrivacyAuthorization 的回调参数 resolve 必须调用，否则用户操作会卡死
2. 同意按钮推荐使用 open-type="agreePrivacyAuthorization"，行为与微信原生一致
3. 用户点击「不同意」后，涉及隐私的接口调用会失败，需要引导用户手动开启
4. 隐私弹窗的自测：开发者工具「详情-本地设置」勾选模拟隐私弹窗，或真机预览
5. 小程序使用「基础库 2.32.3 以下」时隐私接口不存在，代码要做能力降级（wx.xxx 判空）
6. app.json 中开启 "__usePrivacyCheck__": true 后，未声明收集的信息类型会被拦截
```

## 权限申请规范

小程序权限体系基于 scope 授权：每个敏感能力对应一个 scope，调用前需通过 wx.authorize 或接口自身触发授权弹窗。核心原则是按需申请、最小化授权——只在用户真正使用该功能时申请，绝不冷启动时一上来就要所有权限；用户拒绝后要能优雅降级，并提供 wx.openSetting 引导入口。

```text
常用 scope 权限列表：
1. scope.userLocation —— 位置信息（wx.getLocation）
2. scope.userLocationBackground —— 后台定位（需特殊资质）
3. scope.record —— 麦克风录音（wx.startRecord / recorder-manager）
4. scope.camera —— 摄像头（camera 组件 / wx.scanCode）
5. scope.writePhotosAlbum —— 保存到相册（wx.saveImageToPhotosAlbum）
6. scope.bluetooth —— 蓝牙（wx.openBluetoothAdapter）
7. scope.albums —— 读写相册（wx.chooseMedia，基础库 2.21.3+）
8. scope.werun —— 微信运动数据
9. scope.addPhoneCalendar / scope.addPhoneContact —— 添加日历/通讯录
10. scope.invoiceTitle / scope.invoice —— 发票抬头与发票信息
```

```js
// utils/permission.js —— 权限申请统一封装
const SCOPE_MAP = {
  location: 'scope.userLocation',
  record: 'scope.record',
  camera: 'scope.camera',
  album: 'scope.albums'
}

/**
 * 申请权限：首次申请 -> 弹授权框；拒绝过 -> 引导去设置页开启
 * @param {string} key 权限键（location/record/camera/album）
 */
function ensureScope(key) {
  const scope = SCOPE_MAP[key]
  return new Promise((resolve, reject) => {
    wx.getSetting({
      success(res) {
        // 已授权，直接继续
        if (res.authSetting[scope]) {
          resolve()
          return
        }
        // 从未申请过或之前拒绝过：调用 authorize 触发授权弹窗
        wx.authorize({
          scope,
          success: resolve,
          fail() {
            // 用户拒绝：弹窗引导去设置页
            wx.showModal({
              title: '需要权限',
              content: '该功能需要相关权限，请在设置中开启',
              confirmText: '去设置',
              success(modalRes) {
                if (modalRes.confirm) {
                  wx.openSetting({
                    success(settingRes) {
                      if (settingRes.authSetting[scope]) {
                        resolve()
                      } else {
                        reject(new Error('用户未授权'))
                      }
                    }
                  })
                } else {
                  reject(new Error('用户取消授权'))
                }
              }
            })
          }
        })
      },
      fail: reject
    })
  })
}

module.exports = { ensureScope }
```

```js
  getNearby() {
    ensureScope('location')
      .then(() => {
        wx.getLocation({
          type: 'gcj02',

            // 拿到经纬度请求后台
            this.requestNearby(res.latitude, res.longitude)
          }
        })

      })
```

```text
权限申请规范：
1. 按需申请 —— 只在用户点击具体功能时申请，禁止进入页面就弹一堆授权框
2. 最小化 —— 能不用真实位置就不用（如只选城市用 wx.chooseLocation 替代 getLocation）
3. 拒绝降级 —— 权限被拒后功能降级可用（如定位失败用默认城市），并给设置引导
4. 主动告知 —— 申请权限前先用文案说明用途（如「用于为您推荐附近门店」）
5. 可撤销 —— 用户可在小程序「设置-权限管理」中随时关闭权限，代码需处理权限被关的场景
6. 不要滥用 —— 头像昵称使用「头像昵称填写能力」（button open-type="chooseAvatar" + input type="nickname"），不要再调 wx.getUserProfile 弹窗
```

## 个人信息处理

个人信息处理覆盖收集、存储、使用、传输、删除全生命周期。收集阶段要告知用途并取得同意；存储阶段要加密并限制访问；使用阶段要遵循最小必要原则；传输阶段必须走 HTTPS；用户提出删除或注销账号时，要能完整删除或匿名化处理其个人信息。

后台端（SpringBoot）的个人信息处理要点：手机号等敏感字段加密存储（AES 或国密 SM4），查询接口默认脱敏；日志中禁止打印明文手机号、身份证号；提供账号注销接口，注销后清理或匿名化用户数据。

```java
// 手机号等敏感信息加密存储（AES-GCM 简化示例，密钥从配置中心注入）
@Component
public class CryptoUtil {

    @Value("${app.crypto.key}")
    private String base64Key;

    private SecretKey key;

    @PostConstruct
    public void init() {
        byte[] keyBytes = Base64.getDecoder().decode(base64Key);
        this.key = new SecretKeySpec(keyBytes, "AES");
    }

    public String encrypt(String plain) {
        if (plain == null) {
            return null;
        }
        try {
            Cipher cipher = Cipher.getInstance("AES/GCM/NoPadding");
            cipher.init(Cipher.ENCRYPT_MODE, key);
            byte[] cipherText = cipher.doFinal(plain.getBytes(StandardCharsets.UTF_8));
            // 输出格式：IV + 密文，Base64 编码
            byte[] iv = cipher.getIV();
            ByteBuffer buf = ByteBuffer.allocate(iv.length + cipherText.length);
            buf.put(iv).put(cipherText);
            return Base64.getEncoder().encodeToString(buf.array());
        } catch (Exception e) {
            throw new BizException("加密失败");
        }
    }

    public String decrypt(String encrypted) {
        if (encrypted == null) {
            return null;
        }
        try {
            byte[] data = Base64.getDecoder().decode(encrypted);
            byte[] iv = Arrays.copyOfRange(data, 0, 12);           // GCM IV 12 字节
            byte[] cipherText = Arrays.copyOfRange(data, 12, data.length);
            Cipher cipher = Cipher.getInstance("AES/GCM/NoPadding");
            cipher.init(Cipher.DECRYPT_MODE, key, new GCMParameterSpec(128, iv));
            return new String(cipher.doFinal(cipherText), StandardCharsets.UTF_8);
        } catch (Exception e) {
            throw new BizException("解密失败");
        }
    }
}
```

```java
// UserAccountController.java —— 账号注销与数据删除（完整实现）
@RestController
@RequestMapping("/api/user")
public class UserAccountController {

    @Resource
    private UserService userService;

    @Resource
    private CryptoUtil cryptoUtil;

    @Resource
    private AuditLogService auditLogService;

    /** 注销账号：清理登录凭证 + 匿名化个人数据 */
    @DeleteMapping("/account")
    public Result deleteAccount(@RequestHeader("Authorization") String token) {
        Long userId = userService.parseUserId(token);

        // 1. 业务数据匿名化：订单、评论等保留业务记录，但替换为匿名标识
        userService.anonymize(userId);

        // 2. 删除登录凭证与缓存
        userService.invalidateToken(userId);

        // 3. 删除/匿名化手机号等敏感字段
        userService.clearSensitiveFields(userId);

        // 4. 记录注销审计（不含个人信息本体）
        auditLogService.record("ACCOUNT_DELETE", userId);
        return Result.success();
    }

    /** 导出我的数据（个人信息可携带权） */
    @GetMapping("/data/export")
    public Result exportData(@RequestHeader("Authorization") String token) {
        Long userId = userService.parseUserId(token);
        UserDataDto dto = userService.collectUserData(userId);
        return Result.success(dto);
    }
}
```

```text
个人信息处理规范：
1. 收集告知 —— 收集前告知类型与用途，通过隐私弹窗/隐私政策取得同意
2. 最小收集 —— 只收集业务必需字段，能不用真实手机号就用 open-type="getPhoneNumber" 授权的加密手机号
3. 加密存储 —— 手机号、身份证等敏感字段加密存储，密钥独立管理（配置中心/KMS）
4. 传输安全 —— 全链路 HTTPS，小程序端不缓存敏感个人信息到本地 Storage
5. 删除请求 —— 提供注销/删除入口，注销后清理或匿名化数据，删除操作留审计
6. 访问控制 —— 后台管理端按角色限制敏感数据查看权限，操作留痕
```

## 合规要点

隐私合规的法规基础是《个人信息保护法》（PIPL，2021 年 11 月生效）、《数据安全法》以及《儿童个人信息网络保护规定》等。对小程序开发者而言，最重要的落地动作是：取得用户同意、最小必要收集、提供删除渠道、保护儿童信息、管理第三方 SDK。

儿童信息保护是重点：面向 14 周岁以下未成年人的小程序，收集其个人信息须取得监护人同意，并在隐私政策中单独说明儿童信息处理规则。微信平台对涉及儿童类目（教育、儿童社区）的小程序审核更严格，需要提供监护人同意机制。

```text
合规要点清单：
1. 个人信息保护法 —— 处理个人信息需「告知 + 同意」，敏感个人信息（生物识别、医疗、金融账户等）需单独同意
2. 数据安全法 —— 重要数据分类分级，跨境传输需安全评估（小程序数据默认存储国内，跨境场景要申报）
3. 儿童信息 —— 14 周岁以下收集个人信息需监护人同意，儿童类目小程序要单独声明处理规则
4. 第三方 SDK —— 统计、地图、推送、广告等 SDK 都要在隐私指引中声明名称与用途，按微信《第三方 SDK 使用指引》操作
5. 隐私政策全文 —— 小程序内提供可打开的完整隐私政策，包含收集清单、用途、存储期限、联系方式
6. 监管动作 —— 用户投诉、平台巡检、监管抽查的应对材料：隐私指引、日志、删除流程都要可举证
```

```java
// 手机号快速验证组件回调 —— 微信授权手机号（非明文传输，安全合规）
@RestController
@RequestMapping("/api/user")
public class PhoneController {

    @Resource
    private WechatApiClient wechatApiClient;

    @Resource
    private UserService userService;

    /** 小程序端 open-type="getPhoneNumber" 回调，用 code 换手机号 */
    @PostMapping("/phone/bind")
    public Result bindPhone(@RequestBody BindPhoneRequest request) {
        // code 由小程序端 getPhoneNumber 回调提供，5 分钟有效
        String phoneInfo = wechatApiClient.getPhoneNumber(request.getCode());
        // phone_info.phoneNumber 为明文手机号，仅用于绑定，不回传前端
        userService.bindPhone(request.getOpenid(), phoneInfo);
        // 前端只返回成功/失败，不返回手机号明文
        return Result.success();
    }
}
```

```text
法规落地自查清单：
1. 收集的每一项信息都能在隐私指引中找到声明，且用途描述一致
2. 敏感信息（手机号、身份证、位置）有加密存储与访问控制
3. 有注销/删除入口，且真实可执行（不能只是前端按钮，后端要真正清理）
4. 儿童类目小程序有监护人同意机制与儿童信息保护条款
5. 所有第三方 SDK 已列入隐私指引，SDK 版本及时更新（旧版 SDK 可能违规收集）
6. 后台日志、测试环境数据不含真实个人信息（用脱敏测试数据）
```

## 应用场景实战

### 场景一：电商小程序冷启动隐私弹窗 + 按需申请位置权限

电商小程序启动时不申请任何权限，进入「附近门店」页面时按需申请定位。完整链路：启动检查隐私需求 → 首次使用定位时弹自定义隐私弹窗 → 用户同意后申请 scope.userLocation → 拒绝则引导去设置页并降级为默认城市。

```js
// app.js —— 启动时初始化隐私监听
App({
  onLaunch() {
    // 注册全局隐私授权监听（自定义弹窗展示在需要授权的页面）
    if (wx.onNeedPrivacyAuthorization) {
      wx.onNeedPrivacyAuthorization((resolve) => {
        // 转发给当前页面处理，页面展示弹窗
        const pages = getCurrentPages()
        const current = pages[pages.length - 1]
        if (current && current.handlePrivacyResolve) {
          current.handlePrivacyResolve(resolve)
        } else {
          // 兜底：直接同意（用户已在小程序设置中确认过隐私政策）
          resolve({ event: 'agree' })
        }
      })
    }
  }
})
```

```js
// pages/nearby/nearby.js —— 附近门店页面
const { ensureScope } = require('../../utils/permission')

Page({
  data: { city: '上海', loading: false },

  onLoad() {
    this.requestStores(this.data.city)   // 先按默认城市加载，不阻塞
  },

  // 用户点击「定位到当前位置」
  locateMe() {
    ensureScope('location')
      .then(() => {
        wx.getLocation({
          type: 'gcj02',
          success: (res) => {
            this.setData({ loading: true })
            wx.request({
              url: 'https://api.example.com/api/store/nearby',
              data: { lat: res.latitude, lng: res.longitude },
              success: (resp) => this.renderStores(resp.data.data),
              complete: () => this.setData({ loading: false })
            })
          }
        })
      })
      .catch(() => {
        // 拒绝定位：降级为默认城市，并 toast 提示
        wx.showToast({ title: '未授权定位，已使用默认城市', icon: 'none' })
        this.requestStores(this.data.city)
      })
  }
})
```

### 场景二：内容社区小程序接入第三方统计 SDK 的合规处理

社区小程序接入友盟/腾讯分析等第三方统计 SDK，需在隐私指引中声明 SDK 信息，并在代码中按微信合规要求初始化。微信要求第三方 SDK 在《小程序第三方 SDK 使用指引》的合规范围内使用，且不能违规收集用户信息。

```js
// app.js —— 合规接入第三方统计 SDK
App({
  onLaunch() {
    // 1. 隐私指引中已声明：SDK 名称、用途（数据统计与用户行为分析）、收集的信息类型
    // 2. 等待隐私授权确认后再初始化 SDK（避免未授权前就开始收集）
    if (wx.getPrivacySetting) {
      wx.getPrivacySetting({
        success: (res) => {
          if (!res.needAuthorization) {
            // 用户已在设置中同意，初始化统计 SDK
            this.initAnalytics()
          }
          // needAuthorization 为 true 时，等 onNeedPrivacyAuthorization 同意后再初始化
        }
      })
    }
  },

  initAnalytics() {
    // 以腾讯移动分析（MTA）为例，正式接入时替换为所选 SDK 的初始化代码
    if (typeof mta !== 'undefined') {
      mta.App.init({
        appID: '你的AppID',
        statPullUpSpecial: true
      })
    }
  }
})
```

```text
场景落地清单：
1. 冷启动不申请权限，权限全部推迟到功能使用时按需申请
2. 隐私弹窗在真机预览验证，确认弹窗出现时机与同意/拒绝分支都正确
3. 权限被拒要有降级路径，不能因拒绝权限导致功能完全不可用
4. 第三方 SDK 按「先同意后初始化」的原则接入，避免未授权收集
5. SDK 列表、版本、用途在隐私指引与内部台账中同步维护
6. 上线前用「隐私检测」工具自查：后台声明 vs 代码实际调用是否一致
```

## 最佳实践与踩坑记录

### 最佳实践

1. 隐私合规从产品设计阶段就介入：功能评审时同步评审「收集了什么、为什么收集、如何删除」，避免上线后补课
2. app.json 开启 __usePrivacyCheck__: true，让平台在开发阶段就暴露隐私问题，而不是提审时才被拒
3. 所有隐私接口（getPrivacySetting/onNeedPrivacyAuthorization）做能力判空，兼容基础库 2.32.3 以下的老版本用户
4. 权限申请统一封装（ensureScope），所有页面复用同一套「申请-拒绝-引导设置」流程，避免各写各的
5. 敏感字段加密存储 + 日志脱敏 + 接口脱敏三层防护，明文手机号只存在于授权回调的处理瞬间
6. 提供真实可用的注销与数据删除入口，并做成自动化测试用例，防止「假注销」
7. 第三方 SDK 建立台账：名称、版本、用途、收集字段、隐私指引声明状态，定期核对
8. 每季度做一次隐私自查：对照隐私指引逐项核对代码中的 wx API 调用与后台数据字段

### 踩坑记录

```text
坑 1：未填写用户隐私保护指引，隐私接口全部调用失败
结论：getLocation、chooseMedia 等接口直接 fail，控制台报「需要用户授权隐私协议」。
原因：小程序未在小程序后台填写用户隐私保护指引，隐私接口机制强制拦截。
解法：后台「设置-服务内容声明-用户隐私保护指引」完整填写并提交；注意填写后需要一定时间生效。

坑 2：隐私指引声明与代码实际收集行为不一致，提审被拒
结论：审核反馈「实际收集的信息与隐私指引声明不符」，要求整改后重新提审。
原因：后台勾选了「位置」，代码里却通过 chooseMedia 收相册且未声明；或声明了但代码没调用。
解法：上线前逐项核对：代码中每个隐私 wx API 调用，都能在指引声明中找到对应项；增删功能同步更新指引。

坑 3：onNeedPrivacyAuthorization 的 resolve 没有调用，用户操作卡死
结论：点击「同意」后页面无响应，按钮一直转圈，功能无法继续。
原因：自定义弹窗把 resolve 存起来，但用户点击后忘记调用 resolve({ event: 'agree' })。
解法：同意/不同意分支都必须调用 resolve；弹窗关闭（含 onUnload）时兜底调用 resolve({ event: 'disagree' })。

坑 4：进入页面就一次性申请所有权限，用户反感且转化率暴跌
结论：启动即弹三四个授权框，大量用户直接退出小程序。
原因：把权限申请放在了 onLoad 里批量触发，违背最小化授权原则。
解法：权限推迟到功能使用点申请；一次只申请一个权限；申请前先说明用途文案。

坑 5：用户拒绝定位后没有降级，功能完全不可用
结论：用户拒绝定位权限后，附近页面白屏，只能退出小程序。
原因：代码在授权失败分支里直接 return，没有提供默认城市等降级路径。
解法：授权失败走降级逻辑（默认城市/手动选择），并用 toast 说明；提供「去设置」引导入口。

坑 6：SDK 未在隐私指引中声明，提审被拒或线上被警告
结论：审核反馈「发现未声明的小程序第三方 SDK」，要求补充声明。
原因：接入了统计/地图/推送 SDK，但隐私指引里没有列出 SDK 名称与用途。
解法：隐私指引中补充 SDK 声明（名称、用途、收集的信息）；SDK 按「用户同意后再初始化」接入。

坑 7：注销接口只删了 token，用户数据实际还在库里
结论：用户注销后再次登录，历史订单、评论、手机号全部还在，被投诉「假注销」。
原因：注销逻辑只清了登录凭证，没有清理或匿名化业务数据与敏感字段。
解法：注销流程完整实现：匿名化业务数据（订单保留但去标识化）、删除敏感字段、清理缓存与 token、写审计日志。

坑 8：本地 Storage 缓存了明文手机号/身份证等敏感信息
结论：安全扫描发现本地缓存含敏感明文，且用户换设备登录时敏感数据残留。
原因：为省请求把用户手机号等直接 setStorage 到本地。
解法：敏感信息不落本地 Storage，需要时从服务端接口获取并脱敏展示；必须缓存时加密存储并设置过期。

坑 9：开发者工具看不到隐私弹窗，以为没生效
结论：本地调试时隐私弹窗不出现，以为代码没写对，反复排查。
原因：隐私弹窗机制只对基础库 2.32.3+ 生效，且开发者工具需要开启「模拟隐私弹窗」或在真机预览。
解法：开发者工具「详情-本地设置」勾选模拟隐私弹窗；用真机预览验证；确认基础库版本已切换。
```

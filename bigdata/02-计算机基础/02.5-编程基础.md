## 概述

编程是大数据工程落地的工具：写 Spark/Flink 作业用 Java/Scala/Python，写 ETL 脚本用 Python/Shell，写自定义 UDF 和序列化器需要懂并发、IO 与序列化。本章聚焦大数据开发最常用的三件事——三大语言的核心语法、并发与 IO 的正确姿势、序列化/测试/调试的工程能力。这些是后面所有代码示例的基础。

```text
编程基础的四个维度：
1. 语言 —— Java/Python/Scala 语法与生态
2. 并发 —— 多线程、锁、线程池、异步
3. 数据 —— IO、序列化、序列化格式（JSON/Protobuf/Avro）
4. 工程 —— 单元测试、调试、性能分析
```

## Java

Java 是大数据生态的第一语言：Hadoop、Hive、Flink、Kafka 都用 Java 编写，性能与稳定性经过海量生产验证。核心语法是类与对象、集合框架、Stream API、异常处理。大数据开发常用 Java 写 Flink 作业、自定义序列化器、以及组件的插件扩展。JDK 版本注意兼容（大数据组件多要求 JDK 8/11/17）。

```text
Java 要点：
1. 面向对象 —— 类/接口/继承/多态，强类型静态语言
2. 集合 —— List/Map/Set，ArrayList 随机访问、LinkedList 增删
3. Stream —— map/filter/reduce 函数式处理，类似 Spark 的算子
4. 异常 —— 受检异常（必须捕获）与非受检异常（运行时）
```

```java
// Java：集合 + Stream 演示
import java.util.*;
import java.util.stream.Collectors;

public class JavaDemo {
    public static void main(String[] args) {
        List<String> words = Arrays.asList("spark", "flink", "hadoop", "kafka");
        // 过滤 + 转换 + 收集
        List<String> upper = words.stream()
                .filter(w -> w.length() > 4)
                .map(String::toUpperCase)
                .collect(Collectors.toList());
        System.out.println(upper);   // [SPARK, FLINK, HADOOP, KAFKA]

        // Map 统计词频
        Map<String, Long> freq = words.stream()
                .collect(Collectors.groupingBy(w -> w, Collectors.counting()));
        System.out.println(freq);
    }
}
```

## Python

Python 是数据分析和算法的主流语言，靠 Pandas/NumPy/PySpark 在大数据领域占有一席之地。语法简洁、动态类型、库生态丰富，适合数据探索、ETL 脚本、机器学习。大数据里用 PySpark/PyFlink 写计算作业，用 Pandas 做小数据量的本地分析，用 requests 调 API。注意 GIL 限制多线程 CPU 计算，需用多进程或向量化。

```text
Python 要点：
1. 动态类型 —— 无需声明类型，灵活但需靠测试保证正确性
2. 数据结构 —— list/dict/set/tuple + 推导式（list comprehension）
3. GIL —— 全局解释器锁，多线程不能并行 CPU 计算，用 multiprocessing
4. 生态 —— Pandas/NumPy 数据分析，requests 网络，pytest 测试
```

```python
# Python：数据分析风格演示
import pandas as pd

df = pd.DataFrame({
    "order_id": [1, 2, 3, 4],
    "amount": [10.0, 25.0, 15.0, 30.0],
    "status": ["paid", "paid", "refunded", "paid"],
})

# 过滤 + 分组聚合
paid = df[df["status"] == "paid"]
print(paid.groupby("status")["amount"].sum())
print(df["amount"].mean())
```

## Scala

Scala 是 Spark 的原生语言，融合面向对象与函数式编程，类型系统强大。函数式特性（不可变集合、高阶函数、模式匹配）让数据处理代码简洁优雅。虽然 PySpark 降低了入门门槛，但写高性能、可维护的 Spark 作业和读 Spark 源码，Scala 仍是首选。核心概念：val/var、case class、模式匹配、隐式转换。

```text
Scala 要点：
1. val vs var —— val 不可变（推荐）、var 可变，函数式风格优先 val
2. case class —— 不可变数据类，自带 equals/hashCode/copy，做数据模型
3. 模式匹配 —— match/case 解构数据，比 if-else 链更清晰
4. 高阶函数 —— map/flatMap/filter/reduce，与 Spark RDD 算子一致
```

```scala
// Scala：函数式数据处理
case class Order(id: Int, amount: Double, status: String)

object ScalaDemo {
  def main(args: Array[String]): Unit = {
    val orders = List(
      Order(1, 10.0, "paid"),
      Order(2, 25.0, "paid"),
      Order(3, 15.0, "refunded")
    )
    // filter + map + 模式匹配
    val total = orders
      .filter(_.status == "paid")
      .map(_.amount)
      .sum
    println(s"paid total: $total")

    orders.foreach {
      case Order(id, _, "refunded") => println(s"order $id refunded")
      case _ =>
    }
  }
}
```

## 并发

并发让程序同时做多件事，是高性能系统的核心。Java/Scala 用线程、线程池、锁、原子类、Future/CompletableFuture；Python 用多线程（IO 密集）/多进程（CPU 密集）/asyncio（异步 IO）。大数据里，executor 的并发度、UDF 里的共享状态、Kafka 消费者多线程都是并发问题。核心挑战是竞态条件（race condition）与死锁。

```text
并发要点：
1. 线程池 —— 复用线程避免频繁创建销毁，Executors.newFixedThreadPool
2. 锁 —— synchronized/ReentrantLock 保证互斥，代价是性能与死锁风险
3. 原子类 —— AtomicInteger/CAS 无锁更新，比锁更轻量
4. Future —— 异步获取结果，CompletableFuture 支持回调编排
5. Python —— IO 密集用线程，CPU 密集用多进程，asyncio 处理大量并发 IO
```

```java
// Java：线程池 + 并发累加
import java.util.concurrent.*;
import java.util.concurrent.atomic.AtomicInteger;

public class ConcurrencyDemo {
    public static void main(String[] args) throws Exception {
        ExecutorService pool = Executors.newFixedThreadPool(4);
        AtomicInteger counter = new AtomicInteger(0);

        for (int i = 0; i < 1000; i++) {
            pool.submit(counter::incrementAndGet);
        }
        pool.shutdown();
        pool.awaitTermination(10, TimeUnit.SECONDS);
        System.out.println("counter = " + counter.get());  // 1000
    }
}
```

## IO

IO 是数据进出的通道，分文件 IO、网络 IO、内存映射等。Java 的 IO 从传统 BIO（阻塞流）演进到 NIO（非阻塞 + Channel/Buffer）和 NIO.2（异步）。大数据里，Kafka/Netty 用 NIO 实现高吞吐网络，Spark/Flink 用 mmap 和零拷贝优化 IO。理解「阻塞 vs 非阻塞」「同步 vs 异步」「缓冲 vs 直接」是写出高性能 IO 代码的前提。

```text
IO 要点：
1. BIO —— 阻塞流（InputStream/OutputStream），简单但每连接一线程
2. NIO —— Channel + Buffer + Selector，非阻塞多路复用，高并发基础
3. 零拷贝 —— FileChannel.transferTo / mmap，减少内核与用户态拷贝
4. 缓冲 —— BufferedInputStream 攒批减少系统调用
```

```java
// Java：NIO 多路复用简单演示（Selector 监听）
import java.nio.channels.*;
import java.net.*;

public class NIOServer {
    public static void main(String[] args) throws Exception {
        Selector selector = Selector.open();
        ServerSocketChannel server = ServerSocketChannel.open();
        server.bind(new InetSocketAddress(8080));
        server.configureBlocking(false);
        server.register(selector, SelectionKey.OP_ACCEPT);

        System.out.println("监听 8080，等待连接...");
        while (true) {
            selector.select();
            for (SelectionKey key : selector.selectedKeys()) {
                if (key.isAcceptable()) {
                    SocketChannel client = server.accept();
                    client.configureBlocking(false);
                    client.register(selector, SelectionKey.OP_READ);
                    System.out.println("新连接: " + client.getRemoteAddress());
                }
            }
            selector.selectedKeys().clear();
        }
    }
}
```

## 序列化

序列化把对象转成字节流（用于传输或存储），反序列化还原。大数据里序列化无处不在：Spark 广播变量和 Shuffle、Kafka 消息、RPC 参数。格式分文本（JSON/XML，可读但慢）和二进制（Java 原生 Serializable、Kryo、Protobuf、Avro，快且紧凑）。选择标准：跨语言支持、性能、schema 演进。

```text
序列化要点：
1. JSON —— 文本、可读、跨语言，但体积大、解析慢
2. Protobuf —— 二进制、跨语言、紧凑高效，gRPC 默认，需定义 schema
3. Avro —— 二进制、自带 schema 演进，Hadoop 生态常用
4. Kryo —— Java 对象高性能序列化，Spark 常用（比 Serializable 快数倍）
5. 关键 —— 序列化对象要 Serializable，注意 transient 字段不序列化
```

```java
// Java：原生序列化演示
import java.io.*;

public class SerializeDemo {
    static class Order implements Serializable {
        String id;
        double amount;
        transient String secret;   // transient 不序列化

        Order(String id, double amount) {
            this.id = id;
            this.amount = amount;
            this.secret = "tmp";
        }
    }

    public static void main(String[] args) throws Exception {
        Order o = new Order("1001", 99.9);
        // 序列化到字节数组
        ByteArrayOutputStream bos = new ByteArrayOutputStream();
        ObjectOutputStream oos = new ObjectOutputStream(bos);
        oos.writeObject(o);
        byte[] bytes = bos.toByteArray();
        System.out.println("序列化字节数: " + bytes.length);

        // 反序列化
        ObjectInputStream ois = new ObjectInputStream(new ByteArrayInputStream(bytes));
        Order restored = (Order) ois.readObject();
        System.out.println("restored.secret = " + restored.secret);  // null
    }
}
```

## 测试

测试是代码质量的底线。单元测试（JUnit for Java/Scala、pytest for Python）验证函数逻辑，集成测试验证组件交互。大数据开发的测试难点是「依赖集群环境」——常用做法是本地模式（Spark local、Flink mini cluster）、测试容器（Testcontainers）、mock 外部依赖。测试驱动开发（TDD）在大数据里同样适用，尤其是 UDF 和纯逻辑函数。

```text
测试要点：
1. 单元测试 —— 测单个函数/类，JUnit/pytest，快速、隔离
2. 断言 —— assertEquals/assertTrue，验证预期输出
3. 本地模式 —— Spark/Flink 的 local 模式跑测试，免集群
4. Testcontainers —— 用 Docker 起真实依赖（Kafka/DB）做集成测试
```

```java
// Java：JUnit 单元测试
import org.junit.Test;
import static org.junit.Assert.*;

public class AmountUtilsTest {
    public static double tax(double amount) {
        return amount * 1.13;
    }

    @Test
    public void testTax() {
        assertEquals(113.0, tax(100.0), 0.001);
    }
}
```

```python
# Python：pytest 单元测试
def tax(amount):
    return amount * 1.13

def test_tax():
    assert tax(100.0) == 113.0

# 运行：pytest test_file.py
```

## 调试

调试是定位 bug 的能力，分打断点（IDE/调试器）、打日志、性能分析三类。Java 用 IDE 断点调试和 jstack/jmap 分析，Python 用 pdb/print，分布式系统还要看日志和指标。大数据作业的调试难点在于「分布式、难复现」，所以更依赖日志、指标和可观测性，而非单步调试。核心心法是「缩小范围、还原现场、验证假设」。

```text
调试要点：
1. 断点调试 —— IDE 断点 + 单步，适合本地复现的逻辑 bug
2. 日志 —— 关键路径打日志，分布式排障的主要手段
3. 性能分析 —— jstack 看线程栈、jmap 看堆、profiler 找热点
4. 分布式 —— 用指标/日志聚合定位，而非单步调试
```

```shell
# JVM 进程调试
jstack <pid> > thread.dump     # 线程栈，看死锁/卡顿
jmap -heap <pid>               # 堆概览，看内存分布
jstat -gcutil <pid> 1000       # 每秒看 GC 情况

# Python 调试
python3 -m pdb script.py       # 进入调试器
```

```python
# Python 内联调试：用 breakpoint() 暂停并进入 pdb
def process(order):
    total = order["amount"] * 1.13
    breakpoint()   # 这里暂停，交互式检查 total
    return total
```

## 应用场景实战

### 场景一：用 Scala 写一个 WordCount 并本地测试

```scala
// WordCount.scala：Spark 本地模式跑通 + 断言
import org.apache.spark.sql.SparkSession

object WordCount {
  def main(args: Array[String]): Unit = {
    val spark = SparkSession.builder()
      .master("local[2]")
      .appName("WordCount")
      .getOrCreate()

    val counts = spark.sparkContext
      .parallelize(Seq("hello spark", "hello flink", "spark streaming"))
      .flatMap(_.split(" "))
      .map(w => (w, 1))
      .reduceByKey(_ + _)
      .collect()
      .toMap

    assert(counts("hello") == 2)
    assert(counts("spark") == 2)
    println(counts)
    spark.stop()
  }
}
```

### 场景二：用 Python 写一个带测试的 ETL 转换函数

```python
# etl.py：数据清洗函数
def clean_order(raw: dict) -> dict:
    """清洗订单：金额补默认、状态标准化"""
    amount = raw.get("amount", 0.0)
    status = raw.get("status", "")
    status = "paid" if status in ("paid", "shipped") else status
    return {"order_id": raw["order_id"], "amount": amount, "status": status}

# test_etl.py：pytest 测试
def test_clean_order():

    assert clean_order({"order_id": 2, "status": "shipped"})["status"] == "paid"

# 运行：pytest test_etl.py -v
```

## 最佳实践与踩坑记录

### 最佳实践

1. 优先用不可变数据结构（Scala val / Python tuple），减少并发与共享状态问题
2. 共享可变状态用原子类或锁保护，避免裸的竞态条件
3. 大数据序列化用 Kryo/Protobuf，别用 Java 原生 Serializable（慢且大）
4. UDF 和纯逻辑函数必须写单元测试，用本地模式跑，不依赖集群
5. 并发优先用线程池和 Future，别手写裸线程管理
6. Python CPU 密集计算用多进程或向量化，别用多线程（受 GIL 限制）
7. 调试分布式作业靠日志和指标，本地逻辑 bug 才用断点单步

### 踩坑记录

```text
坑 1：多线程累加共享变量结果不对
结论：counter 结果小于预期，且每次运行值不同。
原因：i++ 非原子操作，多线程同时读改写导致更新丢失（竞态）。
解法：用 AtomicInteger、synchronized，或改用并发安全集合。

坑 2：Python 多线程算 CPU 密集任务反而更慢
结论：加了多线程，耗时没降反升。
原因：GIL 限制，CPU 密集任务多线程无法真正并行，还有切换开销。
解法：改用 multiprocessing 多进程，或用 NumPy 向量化。

坑 3：Spark 作业对象没序列化导致 NotSerializableException
结论：作业提交时报对象不可序列化。
原因：闭包捕获了不可序列化的对象，Shuffle/广播时需要序列化。
解法：让对象实现 Serializable、用 Kryo、或把不可序列化字段标 transient。

坑 4：生产环境靠 print 调试导致日志刷屏
结论：日志被 print 淹没，真正有用的信息被冲掉。
原因：图省事用 print 代替日志框架，无级别控制。
解法：用 slf4j/log4j 分级打印，生产关 debug 级别，关键路径打 info/warn。
```

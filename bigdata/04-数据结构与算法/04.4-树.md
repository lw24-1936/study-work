## 概述

树（Tree）是「一对多」的分层结构，用节点和父子边表达层级关系，是对线性结构的扩展。它解决的核心问题是「如何在有序、可动态更新的数据上实现高效查找」。从二叉搜索树到自平衡树（AVL/红黑树），再到为磁盘优化的 B 树/B+ 树、为字符串优化的 Trie/Radix、为区间查询优化的线段树/树状数组，以及为写优化设计的 LSM Tree——它们共同撑起了数据库索引、内存堆、路由表和分布式存储。

```text
树的家族图谱与分工：
1. BST/AVL/红黑树 —— 内存中的有序查找（O(log n)）
2. B 树 / B+ 树   —— 磁盘上的索引（减少磁盘 IO）
3. Trie / Radix    —— 字符串前缀匹配与压缩
4. Heap            —— 极值维护（优先队列底层）
5. Segment Tree / Fenwick —— 区间查询与单点更新
6. LSM Tree        —— 写放大优化，KV 存储底层
```

```python
class TreeNode:
    """通用二叉树节点。"""
    __slots__ = ('val', 'left', 'right')
    def __init__(self, val, left=None, right=None):
        self.val, self.left, self.right = val, left, right
```

## BST

二叉搜索树（Binary Search Tree，BST）满足「左子树所有值 < 根 < 右子树所有值」，中序遍历即得有序序列。查找、插入、删除平均 O(log n)——每步根据大小关系下降一层，把问题规模减半。但 BST 不保证平衡：插入有序序列时会退化成链表，复杂度跌到 O(n)。这是后续 AVL/红黑树要解决的问题。

```text
BST 要点：
1. 左 < 根 < 右，中序遍历有序
2. 平均 O(log n)，最坏 O(n)（退化成链）
3. 插入 —— 从根往下找空位挂上
4. 删除 —— 叶子直接删；单子树用子节点顶替；双子节点用后继替换
```

```python
class BST:
    def __init__(self):
        self.root = None

    def insert(self, val):
        self.root = self._insert(self.root, val)

    def _insert(self, node, val):
        if node is None:
            return TreeNode(val)
        if val < node.val:
            node.left = self._insert(node.left, val)
        elif val > node.val:
            node.right = self._insert(node.right, val)
        return node

    def search(self, val):
        node = self.root
        while node:
            if val == node.val:
                return True
            node = node.left if val < node.val else node.right
        return False

    def inorder(self):
        out = []
        def walk(n):
            if n:
                walk(n.left); out.append(n.val); walk(n.right)
        walk(self.root)
        return out

bst = BST()
for v in [5, 3, 8, 1, 4, 7, 9]:
    bst.insert(v)
print("中序遍历 =", bst.inorder())   # [1,3,4,5,7,8,9]
print("search(7) =", bst.search(7))
```

## AVL

AVL 树是第一种自平衡二叉搜索树，用「平衡因子」（左子树高 - 右子树高）约束：任一节点平衡因子绝对值 ≤ 1，失衡时通过旋转（左旋/右旋/左右/右左）恢复平衡。因此它保证高度始终是 O(log n)，查找/插入/删除严格 O(log n)。代价是插入删除要维护平衡、常数较大，适合查询远多于写入的场景。

```text
AVL 要点：
1. 平衡因子 ∈ {-1, 0, 1}，超出即旋转
2. 四种旋转 —— LL 右旋、RR 左旋、LR 先左后右、RL 先右后左
3. 严格平衡 —— 高度始终 O(log n)，查询最快
4. 代价 —— 每次插入可能多次旋转，写性能不如红黑树
```

```python
class AVLNode:
    __slots__ = ('val', 'left', 'right', 'height')
    def __init__(self, val):
        self.val, self.left, self.right, self.height = val, None, None, 1

def height(n):
    return n.height if n else 0

def rotate_right(y):
    x = y.left
    y.left, x.right = x.right, y
    y.height = 1 + max(height(y.left), height(y.right))
    x.height = 1 + max(height(x.left), height(x.right))
    return x

def rotate_left(x):
    y = x.right
    x.right, y.left = y.left, x
    x.height = 1 + max(height(x.left), height(x.right))
    y.height = 1 + max(height(y.left), height(y.right))
    return y

def avl_insert(node, val):
    if node is None:
        return AVLNode(val)
    if val < node.val:
        node.left = avl_insert(node.left, val)
    else:
        node.right = avl_insert(node.right, val)
    node.height = 1 + max(height(node.left), height(node.right))
    bf = height(node.left) - height(node.right)
    if bf > 1 and val < node.left.val:       # LL
        return rotate_right(node)
    if bf < -1 and val > node.right.val:     # RR
        return rotate_left(node)
    if bf > 1 and val > node.left.val:       # LR
        node.left = rotate_left(node.left); return rotate_right(node)
    if bf < -1 and val < node.right.val:     # RL
        node.right = rotate_right(node.right); return rotate_left(node)
    return node

root = None
for v in [10, 20, 30, 40, 50, 25]:   # 顺序插入也会被旋转平衡
    root = avl_insert(root, v)
print("AVL 根 =", root.val, "树高 =", height(root))   # 高约 3，不会退化成链
```

## 红黑树

红黑树（Red-Black Tree）是另一种自平衡 BST，用节点「红/黑」颜色 + 五条性质维持近似平衡（最长路径不超过最短路径的 2 倍），比 AVL 宽松，因此插入删除的旋转次数更少、写性能更好。它是 C++ STL 的 map/set、Java 的 TreeMap、Linux 内核调度器等众多标准库的默认实现，是「读写均衡」场景的首选平衡树。

```text
红黑树要点：
1. 五条性质 —— 根黑、叶黑、红节点子必黑、任一节点到叶黑高相同
2. 近似平衡 —— 树高 ≤ 2log(n+1)，查找仍 O(log n)
3. 插入/删除最多 2~3 次旋转，写性能优于 AVL
4. 应用 —— TreeMap/HashMap 桶、Linux 完全公平调度器
```

```python
class RBNode:
    __slots__ = ('val', 'left', 'right', 'color')   # color: 'R' 或 'B'
    def __init__(self, val, color='R'):
        self.val, self.left, self.right, self.color = val, None, None, color

def rb_black_height(node):
    """验证性质：统计根到叶的黑色节点数是否一致。"""
    if node is None:
        return 1   # NIL 视为黑色
    lh, rh = rb_black_height(node.left), rb_black_height(node.right)
    assert lh == rh, "红黑树性质被破坏：黑高不一致"
    return lh + (1 if node.color == 'B' else 0)

# 构造一棵合法的小红黑树，验证黑高一致
root = RBNode(2, 'B')
root.left, root.right = RBNode(1, 'B'), RBNode(3, 'B')
root.left.left = RBNode(0, 'R')
print("黑高 =", rb_black_height(root))   # 2
```

## B 树

B 树（B-Tree）是「多路平衡搜索树」：每个节点可存多个键、有多个子节点（阶数 m，子节点数在 [m/2, m] 之间）。它的核心设计目标是把树「压矮」——一个节点存几百个键，树高只有 3~4 层，从而把磁盘 IO 次数降到最低。B 树适合「键和值一起存、需要范围扫描」的索引，也是 B+ 树的前身。

```text
B 树要点：
1. 多路 —— 节点存多个键，子树数量大，树极矮
2. 磁盘友好 —— 一个节点对应一次磁盘 IO，树高决定 IO 次数
3. 所有叶子同层 —— 严格平衡
4. 键值同存 —— 内部节点也存数据，范围查询不如 B+ 树
```

```python
class BTreeNode:
    def __init__(self, leaf=True):
        self.keys = []          # 有序键列表
        self.children = []      # 子节点（叶子为空）
        self.leaf = leaf

    def search(self, key):
        """节点内顺序/二分查找，返回 (子节点, 下标)。"""
        i = 0
        while i < len(self.keys) and key > self.keys[i]:
            i += 1
        if i < len(self.keys) and key == self.keys[i]:
            return self, i
        return (None if self.leaf else self.children[i]), i

# 演示：一个 3 阶 B 树节点的构造与查找
leaf = BTreeNode(leaf=True)
leaf.keys = [10, 20, 30]
root = BTreeNode(leaf=False)
root.keys = [15]
root.children = [BTreeNode(leaf=True), leaf]
root.children[0].keys = [5, 12]
print("查找 20 →", root.search(20)[0].keys[root.search(20)[1]])  # 20
```

## B+Tree

B+ 树是 B 树的改进版，是关系数据库索引（MySQL InnoDB、PostgreSQL）的事实标准。区别在于：数据只存叶子节点，内部节点只存键做「路由」；叶子节点用链表串起来，支持高效范围扫描和顺序遍历。这样非叶子节点能存更多键、树更矮，且范围查询只需定位起点后沿叶子链表一路扫，无需回溯。

```text
B+ 树要点：
1. 数据全在叶子 —— 内部节点纯索引，树更矮
2. 叶子链表 —— 范围查询/全表扫描高效
3. 查询稳定 —— 任何查询都走到叶子，IO 次数固定
4. 应用 —— MySQL InnoDB 聚簇索引（主键索引叶存整行）
```

```python
class BPlusLeaf:
    def __init__(self):
        self.keys = []
        self.next = None       # 指向下一个叶子，构成链表

    def range_scan(self, lo, hi):
        """沿叶子链表做范围扫描。"""
        out = []
        node = self
        while node:
            for k in node.keys:
                if lo <= k <= hi:
                    out.append(k)
            node = node.next
        return out

leaf1, leaf2, leaf3 = BPlusLeaf(), BPlusLeaf(), BPlusLeaf()
leaf1.keys, leaf2.keys, leaf3.keys = [1, 3, 5], [7, 9, 11], [13, 15, 17]
leaf1.next, leaf2.next = leaf2, leaf3
print("范围 [6, 14] =", leaf1.range_scan(6, 14))   # [7,9,11,13]
```

## Trie

字典树（Trie，前缀树）用「公共前缀共享」的方式存储字符串集合：每条边代表一个字符，从根到某节点的路径就是该节点的前缀。查找、插入的时间复杂度只与字符串长度相关，与集合大小无关，是 O(len)。它天然支持前缀匹配、自动补全、字符串集合的交集查询，是搜索引擎提示词、IP 路由、拼写检查的经典结构。

```text
Trie 要点：
1. 复杂度与集合大小无关 —— 只取决于字符串长度 O(len)
2. 前缀共享 —— 节省空间，天然支持前缀查询
3. 应用 —— 自动补全、路由表、词频统计
4. 代价 —— 空间消耗大（节点数多），可用 Radix 压缩
```

```python
class TrieNode:
    def __init__(self):
        self.children = {}
        self.is_end = False

class Trie:
    def __init__(self):
        self.root = TrieNode()

    def insert(self, word):
        node = self.root
        for ch in word:
            node = node.children.setdefault(ch, TrieNode())
        node.is_end = True

    def search(self, word):
        node = self.root
        for ch in word:
            if ch not in node.children:
                return False
            node = node.children[ch]
        return node.is_end

    def has_prefix(self, prefix):
        node = self.root
        for ch in prefix:
            if ch not in node.children:
                return False
            node = node.children[ch]
        return True

trie = Trie()
for w in ["apple", "app", "banana"]:
    trie.insert(w)
print("search('app') =", trie.search("app"))        # True
print("has_prefix('ban') =", trie.has_prefix("ban"))  # True
```

## Radix

基数树（Radix Tree，压缩前缀树）是 Trie 的压缩版：把「只有一个子节点的链」合并成一条边，边上存一整段字符串而非单个字符。这样大幅减少节点数和内存占用，同时保留前缀查询能力。Linux 的页缓存、路由表（Radix/IP 路由）、Redis 的 Rax 结构都用了基数树。

```text
Radix 要点：
1. 压缩 —— 合并单分支链，节点存多字符段
2. 省内存 —— 节点数远少于 Trie
3. 应用 —— Linux 页缓存、IP 路由表、Redis Rax
4. 保留前缀能力 —— 压缩不丢失前缀匹配语义
```

```python
class RadixNode:
    def __init__(self, key=""):
        self.key = key          # 该边存储的字符串段
        self.children = {}      # 首字符 -> 子节点
        self.is_end = False

def radix_insert(root, word):
    """简化演示：按首字符分流，同首字符合并到一条边。"""
    if not word:
        root.is_end = True
        return
    ch = word[0]
    if ch not in root.children:
        root.children[ch] = RadixNode(word)
        root.children[ch].is_end = True
    else:
        child = root.children[ch]
        # 找公共前缀（简化：假设整段相同或首字符相同）
        i = 0
        while i < min(len(child.key), len(word)) and child.key[i] == word[i]:
            i += 1
        if i == len(child.key):
            radix_insert(child, word[i:])
        else:
            # 分裂边（真实实现的核心操作，这里示意）
            child.key = child.key[:i]

r = RadixNode()
for w in ["apple", "apply", "apricot"]:
    radix_insert(r, w)
print("根节点子边首字符 =", list(r.children.keys()))   # ['a']
```

## Heap

堆（Heap）是一棵「完全二叉树」且满足堆性质：大顶堆父节点 ≥ 子节点、小顶堆父节点 ≤ 子节点。它用数组存储（下标 i 的左右孩子是 2i+1、2i+2），无需指针。堆的插入和删除堆顶都是 O(log n)（上浮/下沉），取堆顶 O(1)。它是优先队列的底层实现，也是堆排序、Top-K、Huffman、数据流中位数的核心。

```text
堆要点：
1. 完全二叉树 + 数组存储，i 的孩子为 2i+1 / 2i+2
2. 插入上浮、删除下沉，均 O(log n)
3. 大顶堆取最大、小顶堆取最小，O(1)
4. 应用 —— 优先队列、堆排序、Top-K、中位数维护
```

```python
class MaxHeap:
    def __init__(self):
        self.a = []

    def push(self, x):              # O(log n) 上浮
        self.a.append(x)
        i = len(self.a) - 1
        while i > 0:
            parent = (i - 1) // 2
            if self.a[parent] >= self.a[i]:
                break
            self.a[parent], self.a[i] = self.a[i], self.a[parent]
            i = parent

    def pop(self):                  # O(log n) 下沉
        top = self.a[0]
        self.a[0] = self.a[-1]
        self.a.pop()
        i, n = 0, len(self.a)
        while True:
            l, r = 2 * i + 1, 2 * i + 2
            largest = i
            if l < n and self.a[l] > self.a[largest]:
                largest = l
            if r < n and self.a[r] > self.a[largest]:
                largest = r
            if largest == i:
                break
            self.a[i], self.a[largest] = self.a[largest], self.a[i]
            i = largest
        return top

h = MaxHeap()
for v in [3, 1, 4, 1, 5, 9, 2]:
    h.push(v)
print("堆顶 =", h.pop(), "次大 =", h.pop())   # 9, 5
```

## Segment Tree

线段树（Segment Tree）是处理「区间查询 + 区间/单点更新」的二叉树：每个节点维护一个区间的聚合信息（和、最值），父节点的值由左右孩子合并而来。区间查询和更新都是 O(log n)。它适合「频繁查询区间和/最值，且有更新操作」的场景——静态前缀和无法更新，线段树两者兼顾。

```text
线段树要点：
1. 区间聚合 —— 每个节点存一段区间的和/最值
2. 查询/更新 O(log n) —— 区间可拆成 O(log n) 个节点
3. 适用 —— 区间和、区间最值、区间修改（配懒惰标记）
4. 空间 —— 约 4n
```

```python
class SegmentTree:
    def __init__(self, nums):
        self.n = len(nums)
        self.tree = [0] * (4 * self.n)
        self._build(nums, 1, 0, self.n - 1)

    def _build(self, nums, node, l, r):
        if l == r:
            self.tree[node] = nums[l]
            return
        mid = (l + r) // 2
        self._build(nums, node * 2, l, mid)
        self._build(nums, node * 2 + 1, mid + 1, r)
        self.tree[node] = self.tree[node * 2] + self.tree[node * 2 + 1]

    def query(self, ql, qr, node=1, l=0, r=None):
        if r is None:
            r = self.n - 1
        if ql > r or qr < l:
            return 0
        if ql <= l and r <= qr:
            return self.tree[node]
        mid = (l + r) // 2
        return (self.query(ql, qr, node * 2, l, mid) +
                self.query(ql, qr, node * 2 + 1, mid + 1, r))

st = SegmentTree([1, 3, 5, 7, 9, 11])
print("区间和 [1,3] =", st.query(1, 3))   # 3+5+7 = 15
```

## Fenwick

树状数组（Fenwick Tree，Binary Indexed Tree）是线段树的「精简版」：用数组的二进制结构维护前缀和，单点更新和前缀和查询都是 O(log n)，代码量极小、常数极小。它只支持「前缀聚合 + 单点更新」（区间和可通过两次前缀和相减得到），不支持区间更新（除非用差分技巧）。是竞赛和工程中「区间和」类问题的最轻量方案。

```text
Fenwick 要点：
1. lowbit(i) = i & (-i)，树状数组的核心操作
2. 前缀和查询 O(log n) —— 不断减 lowbit
3. 单点更新 O(log n) —— 不断加 lowbit
4. 比线段树省空间（n+1）且常数小，但功能少
```

```python
class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def update(self, i, delta):      # 单点增加 delta
        i += 1
        while i <= self.n:
            self.bit[i] += delta
            i += i & (-i)

    def prefix_sum(self, i):         # 前缀和 [0, i)
        s, i = 0, i
        while i > 0:
            s += self.bit[i]
            i -= i & (-i)
        return s

    def range_sum(self, l, r):       # 区间和 [l, r)
        return self.prefix_sum(r) - self.prefix_sum(l)

fw = Fenwick(6)
for i, v in enumerate([1, 3, 5, 7, 9, 11]):
    fw.update(i, v)
print("区间和 [1, 4) =", fw.range_sum(1, 4))   # 3+5+7 = 15
```

## LSM Tree

LSM Tree（Log-Structured Merge Tree，日志结构合并树）是「写优化」的存储结构：写入先落到内存 MemTable（有序结构如跳表），满了刷成磁盘上的有序 SSTable；后台 Compaction 不断把小 SSTable 合并成大 SSTable，并清理过期/删除数据。它把随机写变成顺序写，写入吞吐极高，是 LevelDB、RocksDB、Cassandra、HBase 等 KV 存储的核心。代价是读要查多层（MemTable + 多个 SSTable），需配布隆过滤器加速。

```text
LSM Tree 要点：
1. 写优化 —— 顺序追加写，牺牲读性能换写吞吐
2. 分层 —— MemTable(内存) → SSTable(磁盘)，Compaction 合并
3. 读放大 —— 读可能查多层，用布隆过滤器 + 索引加速
4. 应用 —— RocksDB、LevelDB、Cassandra、HBase
```

```python
class LSMSketch:
    """LSM 写路径的最简演示：MemTable -> SSTable 刷盘。"""
    def __init__(self, memtable_limit=4):
        self.memtable = {}      # 内存有序表（这里用 dict 示意）
        self.limit = memtable_limit
        self.sstables = []      # 已刷盘的磁盘段

    def put(self, k, v):
        self.memtable[k] = v
        if len(self.memtable) >= self.limit:
            self._flush()

    def _flush(self):
        # 刷盘：把 MemTable 排序后写成不可变 SSTable
        sst = sorted(self.memtable.items())
        self.sstables.append(dict(sst))
        self.memtable.clear()
        print(f"刷盘：写入 SSTable-{len(self.sstables)}，{len(sst)} 条")

    def get(self, k):
        if k in self.memtable:          # 先查内存
            return self.memtable[k]
        for sst in reversed(self.sstables):   # 再从新到旧查磁盘
            if k in sst:
                return sst[k]
        return None

lsm = LSMSketch()
for i in range(10):
    lsm.put(f"k{i}", i)
print("get('k7') =", lsm.get("k7"))
```

## 应用场景实战

### 场景一：用 B+ 树思想理解数据库主键索引的聚簇存储

```text
MySQL InnoDB 的聚簇索引就是一棵 B+ 树：

[内部节点：只存主键做路由，如 (10) (20) (30)]
       /        |        \        \
[叶子节点1] [叶子节点2] [叶子节点3] [叶子节点4]
  pk 1,3,5    pk 7,9      pk 12,15   pk 21,24
  | 整行数据  | 整行数据  | 整行数据 | 整行数据
  +---- 叶子间用双向链表串起来，支持范围扫描

查询 WHERE id BETWEEN 7 AND 15：
1. 从根定位到叶子节点 2（id=7 所在）
2. 沿叶子链表向后扫到叶子节点 3（id=15）
3. 无需回溯内部节点，范围扫描高效
```

### 场景二：用堆实时维护 Top-K 热门商品

```python
import heapq

class TopKHotItems:
    """流式维护访问量最高的 K 个商品，内存只存 K 个。"""
    def __init__(self, k):
        self.k = k
        self.heap = []      # (计数, 商品id) 最小堆

    def add(self, item_id):
        for i, (cnt, iid) in enumerate(self.heap):
            if iid == item_id:
                self.heap[i] = (cnt + 1, iid)
                heapq.heapify(self.heap)
                return
        heapq.heappush(self.heap, (1, item_id))
        if len(self.heap) > self.k:
            heapq.heappop(self.heap)

    def top(self):
        return sorted(self.heap, reverse=True)

topk = TopKHotItems(3)
for item in ["A", "B", "A", "C", "A", "B", "D", "C", "C"]:
    topk.add(item)
print("Top-3 热门 =", topk.top())   # [('A',3), ('C',3), ('B',2)]
```

## 最佳实践与踩坑记录

### 最佳实践

1. 有序且需频繁插入删除用平衡树，只读有序数据直接排序后二分，别过度设计
2. 磁盘索引用 B+ 树（数据在叶子 + 链表范围扫描），内存索引用红黑树/跳表
3. 写多读少的 KV 用 LSM Tree，读多写少用 B+ 树或哈希索引
4. 区间和/最值查询用线段树或树状数组，静态数据用前缀和更简单
5. 字符串前缀匹配用 Trie/Radix，比哈希 + 遍历更高效
6. 堆用于流式 Top-K 和优先队列，复杂度 O(n log k) 远优于全排序

### 踩坑记录

```text
坑 1：BST 插入有序数据退化成链表
结论：查找从 O(log n) 退化到 O(n)，大数据量下灾难性变慢。
原因：BST 不保证平衡，顺序插入形成单链。
解法：用 AVL/红黑树等自平衡结构，或插入前先随机打乱顺序。

坑 2：用平衡树当优先队列用
结论：实现复杂、常数大，性能不如堆。
原因：优先队列只需取极值，平衡树是「杀鸡用牛刀」。
解法：取极值/动态 Top-K 场景直接用堆（heapq）。

坑 3：B+ 树索引列加了函数导致索引失效
结论：WHERE func(col)=x 走不了索引，全表扫描。
原因：B+ 树按原始列值有序，函数破坏了可比较性。
解法：查询条件避免对索引列做函数/运算，必要时建函数索引。

坑 4：线段树数组开小了导致越界
结论：区间查询结果错误或越界崩溃。
原因：线段树最坏需要 4n 空间，开 2n 或 3n 会越界。
解法：统一开 4n 空间，或改用树状数组（n+1 即可）。

坑 5：LSM Tree 读放大导致点查变慢
结论：单个 key 查询要遍历多层 SSTable，延迟高。
原因：写多版本分散在各层，Compaction 不及时则层数增多。
解法：配布隆过滤器跳过不存在层，定期 Compaction 控制层数。
```

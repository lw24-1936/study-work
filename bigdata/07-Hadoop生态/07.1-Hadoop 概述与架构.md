## 概述

Hadoop 是大数据时代的开山框架，第一次让「用廉价商用机集群处理海量数据」成为现实。它由三个核心组件构成：HDFS（分布式存储）、YARN（资源调度）和 MapReduce（批处理计算），外加 Common 提供公共基础库。虽然如今 Spark/Flink 已取代 MapReduce 成为主流计算引擎，但 Hadoop 的 HDFS 与 YARN 仍是众多大数据平台的存储与调度底座，理解其架构是进入大数据领域的起点。

```text
Hadoop 三大组件分工：
1. HDFS —— 存储层：大文件切块分布存储，副本容错（数据在哪）
2. YARN —— 调度层：统一管理集群 CPU/内存资源，分配给各计算框架
3. MapReduce —— 计算层：分而治之的批处理编程模型（Map + Reduce）
4. Common —— 公共库：RPC、序列化、配置、工具类
```

```text
Hadoop 的核心设计哲学：
1. 廉价硬件 —— 用普通服务器集群替代昂贵小型机，靠软件容错
2. 移动计算 —— 把计算搬到数据所在节点，避免搬海量数据
3. 横向扩展 —— 加机器即扩容，线性扩展存储和计算
4. 容错优先 —— 假设节点会挂，副本 + 重试保证可靠性
```

## 核心概念

Hadoop 的五大核心概念：整体架构（存储与计算解耦的主从设计）、Common（公共基础库）、HDFS（分布式存储）、YARN（资源调度）、MapReduce（批处理计算）。

### Hadoop 架构

Hadoop 采用主从（Master/Slave）架构，按「存储」和「计算」解耦设计。存储侧 NameNode（主）+ DataNode（从），计算调度侧 ResourceManager（主）+ NodeManager（从），计算任务由 ApplicationMaster 协调在 Container 里执行。这种解耦让不同计算框架（MapReduce/Spark/Flink）可以共享同一套 HDFS 存储和 YARN 调度。

```text
Hadoop 主从架构总览：
存储层：NameNode（元数据主节点）+ DataNode（数据从节点）
调度层：ResourceManager（资源主节点）+ NodeManager（节点从节点）
计算层：ApplicationMaster（应用协调）+ Container（执行单元）
协调层：ZooKeeper（主节点高可用/选举）
```

```xml
<!-- core-site.xml：Hadoop 全局配置 -->
<configuration>
  <!-- 默认文件系统（HDFS） -->
  <property>
    <name>fs.defaultFS</name>
    <value>hdfs://mycluster</value>
  </property>
  <!-- 临时目录 -->
  <property>
    <name>hadoop.tmp.dir</name>
    <value>/hadoop/tmp</value>
  </property>
</configuration>
```

```text
架构演进脉络：
Hadoop 1.x —— MapReduce 既是计算框架又是资源调度，耦合严重
Hadoop 2.x —— 引入 YARN，计算与调度解耦，多框架共存
Hadoop 3.x —— 纠删码、多 NameNode、容器化支持，进一步成熟
```

### Common

Hadoop Common 是 Hadoop 所有模块共享的基础库，提供配置管理、RPC 通信、序列化（Writable）、文件系统抽象（FileSystem API）、认证（Kerberos）等底层能力。它让上层模块（HDFS/YARN/MapReduce）共享同一套基础设施，也对外提供统一的编程接口。

```text
Common 提供的公共能力：
1. Configuration —— 统一的 XML 配置读取与参数传递
2. RPC —— 基于 Protobuf 的远程过程调用框架
3. Writable —— 序列化接口（比 Java 原生序列化紧凑高效）
4. FileSystem —— 文件系统抽象，统一访问 HDFS/本地/对象存储
5. 安全 —— Kerberos 认证、权限控制
```

```java
// Common 的 Configuration 与 FileSystem 使用
import org.apache.hadoop.conf.Configuration;
import org.apache.hadoop.fs.FileSystem;
import org.apache.hadoop.fs.Path;

Configuration conf = new Configuration();
conf.set("fs.defaultFS", "hdfs://mycluster");

FileSystem fs = FileSystem.get(conf);
// 统一的文件系统接口，屏蔽底层差异
fs.mkdirs(new Path("/user/demo"));
fs.close();
```

### HDFS

HDFS 是 Hadoop 的分布式文件系统，专为大文件顺序读写、一次写多次读设计。它把大文件切成块（默认 128MB）分布到多个 DataNode，靠 3 副本保证容错，元数据集中在 NameNode。HDFS 是整个 Hadoop 生态的数据底座，也是数据湖底层存储的经典选择。

```text
HDFS 核心特征：
1. 大文件优先 —— 块 128MB，为顺序大文件吞吐优化
2. 副本容错 —— 默认 3 副本，机架感知放置，坏盘自动恢复
3. 元数据分离 —— 元数据在 NameNode 内存，数据在 DataNode 磁盘
4. 一次写多次读 —— 不支持随机写，追加为主
```

```shell
# HDFS 基本操作
hdfs dfs -mkdir -p /data/raw
hdfs dfs -put local_file.txt /data/raw/
hdfs dfs -ls /data/raw/
hdfs dfs -get /data/raw/local_file.txt ./
hdfs dfs -rm -r /data/raw/local_file.txt
```

### YARN

YARN（Yet Another Resource Negotiator）是 Hadoop 的资源管理与调度层，把集群的 CPU/内存抽象成「Container」统一分配，让 MapReduce、Spark、Flink 等多个计算框架共享同一集群资源。它由 ResourceManager（全局调度）、NodeManager（节点管理）和 ApplicationMaster（应用协调）组成，是 Hadoop 2.x 之后的核心架构升级。

```text
YARN 核心组件：
1. ResourceManager —— 全局资源调度，接收应用提交、分配 Container
2. NodeManager —— 每个节点的代理，监控资源、管理 Container 生命周期
3. ApplicationMaster —— 每个应用一个，向 RM 申请资源、协调任务执行
4. Container —— 资源抽象单元（CPU + 内存），任务在其中运行
```

```yaml
# 提交一个 Spark 应用到 YARN 上运行（示意）
spark-submit \
  --master yarn \
  --deploy-mode cluster \
  --num-executors 4 \
  --executor-memory 4g \
  --executor-cores 2 \
  my_job.py
```


### MapReduce

MapReduce 是 Hadoop 的批处理编程模型，把大数据处理抽象成 Map（映射，逐条转换）和 Reduce（归约，按 key 聚合）两个阶段，框架自动处理数据分布、并行、shuffle、容错。它让程序员不用关心分布式细节，只需写 Map/Reduce 两个函数。如今它更多作为「分布式计算思想」存在，实际计算由 Spark/Flink 承接。

```text
MapReduce 编程模型：
1. Map —— 输入 <k1, v1>，输出中间 <k2, v2> 键值对
2. Shuffle —— 框架自动按 key 分区、排序、传输到 Reducer
3. Reduce —— 对同一 key 的 value 列表做聚合，输出最终结果
4. 框架负责 —— 数据切分、并行、容错、负载均衡
```

```java
// 经典 WordCount
public static class WordCountMapper
        extends Mapper<LongWritable, Text, Text, IntWritable> {
    private final static IntWritable one = new IntWritable(1);
    private Text word = new Text();

    public void map(LongWritable key, Text value, Context context)
            throws IOException, InterruptedException {
        for (String w : value.toString().split("\\s+")) {
            word.set(w);
            context.write(word, one);
        }
    }
}
```

## 工作原理

Hadoop 的工作分「存储」和「计算」两条链路。存储链路：客户端写数据先向 NameNode 申请块位置，拿到 DataNode 列表后建立写入流水线（Pipeline），数据以「包（packet）」为单位依次流经各 DataNode，每个 DataNode 收到后写本地并转发下游，全部写完回传 ACK。计算链路：客户端提交作业到 ResourceManager，RM 分配 Container 启动 ApplicationMaster，AM 申请资源启动任务，任务从 HDFS 读数据、计算、写回 HDFS。

```text
HDFS 写数据流程：
1. 客户端向 NameNode 请求创建文件，NameNode 检查权限/路径并分配块
2. NameNode 返回第一个块的 DataNode 列表（按机架感知选 3 个节点）
3. 客户端建立 DataNode 流水线（dn1 → dn2 → dn3），数据逐级写入
4. 每块写完 DataNode 回传 ACK，客户端再申请下一块
5. 全部写完客户端关闭流，NameNode 持久化元数据
```

```text
YARN 作业提交流程：
1. 客户端向 ResourceManager 提交 Application
2. RM 找一个 NodeManager 分配 Container 启动 ApplicationMaster
3. AM 向 RM 申请执行任务所需的 Container 资源
4. RM 按调度器策略把 Container 分配到各 NodeManager
5. AM 在各 Container 里启动任务（Map/Reduce 或 Executor）
6. 任务完成，AM 注销并释放资源
```

```text
HDFS 读数据流程：
1. 客户端向 NameNode 请求文件块位置
2. NameNode 返回块所在的 DataNode 列表（就近排序）
3. 客户端从最近的 DataNode 直接读块数据
4. 读完一块继续读下一块，直到文件读完
```

## 常用命令与配置

Hadoop 的日常运维围绕 hdfs、yarn、mapred 三组命令展开：hdfs 管存储（文件增删查 + 管理）、yarn 管资源（应用/节点/队列）、mapred 管 MapReduce 作业。下面按用途列出高频命令。

```shell
# 文件系统操作（hdfs dfs）
hdfs dfs -ls /                     # 列目录
hdfs dfs -mkdir -p /data/raw       # 建目录
hdfs dfs -put a.txt /data/raw/     # 上传
hdfs dfs -get /data/raw/a.txt ./   # 下载
hdfs dfs -cat /data/raw/a.txt      # 查看内容
hdfs dfs -du -h /                  # 统计空间占用
hdfs dfs -setrep -w 3 /data/raw/   # 设置副本数并等待完成
hdfs dfs -chmod -R 755 /data/      # 改权限
hdfs dfs -chown user:group /data/  # 改属主

# 管理命令（hdfs dfsadmin）
hdfs dfsadmin -report              # 集群健康报告（节点/容量/块）
hdfs dfsadmin -safemode get        # 查看安全模式状态
hdfs dfsadmin -safemode leave      # 离开安全模式
hdfs dfsadmin -refreshNodes        # 刷新节点白名单/黑名单

# 健康检查（hdfs fsck）
hdfs fsck / -files -blocks -locations   # 检查块健康与副本
```

```shell
# 资源调度命令（yarn）
yarn application -list            # 列出所有应用
yarn application -status <app_id> # 查看应用状态
yarn application -kill <app_id>   # 杀掉应用
yarn logs -applicationId <app_id> # 查看应用日志
yarn node -list -all              # 列出所有节点
yarn queue -status <queue>        # 查看队列状态

# MapReduce 作业（mapred / hadoop）
hadoop jar my-job.jar com.example.Job /in /out   # 提交 MR 作业
mapred job -list                  # 列出 MR 作业
mapred job -status <job_id>       # 查看作业状态
mapred job -kill <job_id>         # 杀掉作业
```

```text
常用配置项速查（对应配置文件见下一节）：
fs.defaultFS        —— 默认文件系统地址（core-site.xml）
dfs.replication     —— 副本数，默认 3（hdfs-site.xml）
dfs.blocksize       —— 块大小，默认 128MB（hdfs-site.xml）
yarn.nodemanager.resource.memory-mb —— 节点可用内存（yarn-site.xml）
mapreduce.framework.name —— 执行框架，yarn（mapred-site.xml）
```

## 配置文件解析

Hadoop 集群的配置集中在四份 XML 文件，每份负责一个模块，部署时把这份文件分发到所有节点。核心字段含义如下。

```xml
<!-- core-site.xml：全局公共配置 -->
<configuration>
  <!-- 默认文件系统，客户端和所有组件都通过它定位 HDFS -->
  <property>
    <name>fs.defaultFS</name>
    <value>hdfs://mycluster</value>
  </property>
  <!-- Hadoop 临时目录，默认 /tmp 会被系统清理，生产必须改 -->
  <property>
    <name>hadoop.tmp.dir</name>
    <value>/hadoop/tmp</value>
  </property>
  <!-- 机架感知拓扑脚本，用于副本放置和任务调度 -->
  <property>
    <name>net.topology.script.file.name</name>
    <value>/etc/hadoop/topology.py</value>
  </property>
</configuration>
```

```xml
<!-- hdfs-site.xml：HDFS 配置 -->
<configuration>
  <!-- 副本数，生产默认 3 -->
  <property>
    <name>dfs.replication</name>
    <value>3</value>
  </property>
  <!-- 块大小（字节），默认 134217728 = 128MB -->
  <property>
    <name>dfs.blocksize</name>
    <value>134217728</value>
  </property>
  <!-- NameNode 元数据目录，多目录逗号分隔做冗余 -->
  <property>
    <name>dfs.namenode.name.dir</name>
    <value>/hadoop/hdfs/namenode</value>
  </property>
  <!-- DataNode 数据目录，多盘逗号分隔 -->
  <property>
    <name>dfs.datanode.data.dir</name>
    <value>/data/disk1,/data/disk2</value>
  </property>
</configuration>
```

```xml
<!-- yarn-site.xml：YARN 配置 -->
<configuration>
  <!-- ResourceManager 调度器：Capacity（默认）/ Fair -->
  <property>
    <name>yarn.resourcemanager.scheduler.class</name>
    <value>org.apache.hadoop.yarn.server.resourcemanager.scheduler.capacity.CapacityScheduler</value>
  </property>
  <!-- NodeManager 可用内存（MB） -->
  <property>
    <name>yarn.nodemanager.resource.memory-mb</name>
    <value>49152</value>
  </property>
  <!-- NodeManager 可用 CPU 核数 -->
  <property>
    <name>yarn.nodemanager.resource.cpu-vcores</name>
    <value>16</value>
  </property>
</configuration>
```

```xml
<!-- mapred-site.xml：MapReduce 配置 -->
<configuration>
  <!-- 执行框架，Hadoop 2.x 后固定为 yarn -->
  <property>
    <name>mapreduce.framework.name</name>
    <value>yarn</value>
  </property>
  <!-- Map 任务内存（MB） -->
  <property>
    <name>mapreduce.map.memory.mb</name>
    <value>4096</value>
  </property>
  <!-- Reduce 任务内存（MB） -->
  <property>
    <name>mapreduce.reduce.memory.mb</name>
    <value>8192</value>
  </property>
</configuration>
```

```text
配置文件分工：
core-site.xml   —— 全局：文件系统地址、临时目录、机架感知、安全
hdfs-site.xml   —— HDFS：副本数、块大小、NameNode/DataNode 目录、HA
yarn-site.xml   —— YARN：调度器、NodeManager 资源、日志聚合
mapred-site.xml —— MapReduce：执行框架、Map/Reduce 内存
四份文件都要分发到集群所有节点，改完用 refresh 或滚动重启生效
```

## 应用场景实战

### 场景一：从零搭建一个 Hadoop 集群的组件部署规划

```text
小型集群（10 节点）部署规划：
1. 3 个管理节点 —— NameNode(Active/Standby) + JournalNode + ZooKeeper + ResourceManager(HA)
2. 7 个数据节点 —— DataNode + NodeManager
3. 存储 —— 每节点多块数据盘，挂载为 DataNode 数据目录
4. 计算 —— Spark on YARN，与 MapReduce 共享同一套 HDFS/YARN

配置文件分工：
core-site.xml —— 全局（fs.defaultFS、安全）
hdfs-site.xml —— HDFS（副本数、块大小、NameNode 目录、HA）
yarn-site.xml —— YARN（调度器、资源上限）
mapred-site.xml —— MapReduce（框架名、内存）
```

### 场景二：用 HDFS + YARN 跑一个离线批处理任务

```shell
# 1. 上传数据到 HDFS
hdfs dfs -put sales_20240814.csv /data/raw/sales/

# 2. 用 MapReduce 或 Spark 处理
hadoop jar my-job.jar com.example.SalesAggregator \
  -Dmapreduce.job.reduces=4 \
  /data/raw/sales /data/dwd/sales_agg

# 3. 验证结果
hdfs dfs -ls /data/dwd/sales_agg
hdfs dfs -cat /data/dwd/sales_agg/part-r-00000 | head
```

### 场景三：用 YARN 队列隔离生产与开发任务

```shell
# 1. 在 capacity-scheduler.xml 里建 prod/dev 两个队列（配置见 07.4）
# 2. 生产任务提交到 prod 队列，保证资源下限
hadoop jar etl-job.jar com.example.DailyETL \
  --queue prod.etl /data/raw /data/dwd

# 3. 开发调试任务提交到 dev 队列，不影响生产
spark-submit --master yarn --queue dev.adhoc test_job.py

# 4. 观察队列资源使用，确认隔离生效
yarn queue -status prod
yarn queue -status dev
```

## 性能与调优

Hadoop 性能调优围绕「存储吞吐」和「计算资源」两条线展开。存储侧关键是块大小与副本数——块太大并行度低、太小元数据膨胀；副本数越高读吞吐越好但写放大和存储成本上升。计算侧关键是 Container 资源配比，内存配少了任务被杀、配多了浪费集群资源。

```text
存储侧调优：
1. 块大小 —— 默认 128MB，超大数据集可调 256MB 减少元数据；小文件场景反而要合并
2. 副本数 —— 热数据 3 副本，冷数据用纠删码（EC）省 50%+ 空间
3. 多盘并行 —— DataNode 数据目录配多块盘，读写吞吐线性提升
4. 压缩 —— 中间结果和冷数据开压缩（Snappy/LZ4），省空间省网络
```

```text
计算侧调优：
1. Container 内存 —— JVM 堆 + 堆外 + 预留，按 1.5 倍堆估算，防超限被杀
2. 并行度 —— Mapper 数 = 输入分片数，块大小决定分片；Reducer 数按数据量估
3. 调度器 —— 生产用 Capacity 队列隔离，多租户用 Fair 公平共享
4. 数据局部性 —— 保持「移动计算」优先，任务调度到数据所在节点
```

```shell
# 观测调优对象
hdfs dfsadmin -report            # 看节点容量、副本、坏盘
hdfs fsck / -files -blocks       # 看块分布与副本健康
yarn node -list -all             # 看各节点资源与 Container 分配
yarn queue -status <queue>       # 看队列资源使用与等待任务
```

## 安全与权限

生产 Hadoop 集群默认关闭认证，任何客户端都能伪装成任意用户访问数据，必须做安全加固。核心是开启 Kerberos 认证（身份鉴权）+ HDFS 权限（POSIX 风格 rwx + ACL）+ 服务级授权（SASL RPC）。开启后所有组件通过 principal + keytab 认证，未认证的请求直接拒绝。

```shell
# 1. 查看 HDFS 文件权限与属主（POSIX 风格）
hdfs dfs -ls /data/
hdfs dfs -getfacl /data/sensitive/      # 查看 ACL

# 2. 设置权限与 ACL
hdfs dfs -chmod 750 /data/sensitive/    # rwxr-x---
hdfs dfs -setfacl -m user:bob:rwx /data/sensitive/   # 给 bob 加 ACL

# 3. Kerberos 认证（开启后）
kinit -kt /etc/security/keytabs/hdfs.keytab hdfs/mycluster@REALM
klist                                    # 查看当前票据

# 4. 服务级授权开关（core-site.xml）
# hadoop.security.authentication=kerberos
# hadoop.security.authorization=true
```

```text
安全加固要点：
1. 开启 Kerberos —— 身份认证，未认证客户端直接拒绝
2. 开 authorization —— 服务级授权，组件之间也要鉴权
3. 权限模型 —— POSIX rwx + ACL 细粒度授权，敏感目录最小权限
4. 委托令牌 —— 长任务用 Delegation Token 续期，避免重复认证
5. 传输加密 —— RPC/数据传输开加密，防中间人窃听
```

## 故障排查

Hadoop 故障排查从「集群层 → 存储层 → 计算层」逐层定位。先看集群整体健康（节点是否全活、是否安全模式），再看存储（块是否健康、副本是否齐全），最后看计算（应用状态、日志、资源）。

```shell
# 1. 集群健康总览
hdfs dfsadmin -report          # 看 DataNode 存活、容量、坏盘
yarn node -list -all           # 看 NodeManager 状态

# 2. 存储层排查
hdfs dfsadmin -safemode get    # 是否卡在安全模式（副本不足常见）
hdfs fsck / -files -blocks -locations 2>&1 | grep -E "MISSING|UNDER|CORRUPT"

# 3. 计算层排查
yarn application -list -appStates ALL   # 看所有应用状态
yarn application -status <app_id>       # 看具体应用失败原因
yarn logs -applicationId <app_id> | grep -iE "error|exception"

# 4. 服务日志
tail -f $HADOOP_LOG_DIR/hdfs-hadoop-namenode-*.log
tail -f $HADOOP_LOG_DIR/yarn-hadoop-resourcemanager-*.log
```

```text
三类典型故障速查：
1. NameNode 挂 / 卡安全模式 —— 看 safemode 状态、fsck 副本、edits 是否积压
2. 任务一直 PENDING —— 资源不足排队、队列配额满、节点失联
3. 写入慢/失败 —— DataNode 磁盘满、网络带宽、副本数过高、坏盘
```

## 常见问题

```text
Q1: Hadoop 1.x 和 2.x/3.x 的核心区别是什么？
A: 1.x 里 MapReduce 既管计算又管调度，新框架无法共享资源；2.x 引入 YARN 把计算与调度解耦，多框架共存；3.x 增加纠删码、多 NameNode、容器化支持。

Q2: HDFS 和本地文件系统有什么区别？
A: HDFS 是分布式的，文件切块分布到多机、3 副本容错、一次写多次读、不支持随机写；本地文件系统单机、无副本、支持随机写。HDFS 适合大文件顺序读写，不适合海量小文件和低延迟随机读。

Q3: 为什么 Hadoop 不适合海量小文件？
A: 每个文件/块在 NameNode 内存都占约 150-200 字节元数据，百万小文件吃上百 MB 内存，NameNode 内存成为瓶颈。小文件应合并（HAR/SequenceFile/Parquet）或迁移到对象存储。

Q4: MapReduce 和 Spark 的关系？
A: MapReduce 是 Hadoop 原始的批处理模型，中间结果落磁盘、shuffle 开销大；Spark 用内存计算 + DAG 调度，快一到两个数量级。两者都跑在 YARN 上，现在新项目基本用 Spark/Flink 取代 MapReduce。

Q5: YARN 里的 Container 是什么？
A: Container 是 YARN 的资源抽象单元，封装 CPU + 内存 + 运行环境，任务都跑在 Container 里，资源以 Container 为单位申请和回收，NodeManager 用 cgroup 隔离。

Q6: NameNode 挂了集群还能用吗？
A: 不配 HA 时 NameNode 是单点，挂了整个集群不可用；配 HA（Active/Standby + JournalNode + ZKFC）后自动切换，秒级恢复。生产必须配 HA。

Q7: 数据写入 HDFS 后为什么不能修改？
A: HDFS 是 write-once-read-many 设计，文件写完只能追加不能随机改，这是为高吞吐顺序写做的取舍；要更新用「重写新文件 + 原子替换」或改用 HBase/Hudi 等支持更新的存储。
```

## 面试题

```text
1. 说说 Hadoop 的整体架构和组件分工。
   答：Hadoop 由 HDFS（存储）、YARN（调度）、MapReduce（计算）、Common（公共库）四部分构成。HDFS 负责大文件切块分布存储 + 副本容错；YARN 统一管理集群资源（RM/NM/AM/Container）；MapReduce 提供 Map+Reduce 批处理模型；Common 提供 RPC、序列化、配置等基础库。存储与计算解耦，多框架共享同一套底座。

2. Hadoop 的「移动计算」是什么意思？
   答：把计算任务调度到数据所在的节点执行，而不是把海量数据搬到计算节点，避免跨网络搬数据的开销。数据局部性是 MapReduce/Spark 调度的核心原则。

3. HDFS 为什么把块设成 128MB 这么大？
   答：大块能减少寻址开销和 NameNode 元数据量（同样数据量块数更少），提升顺序读写吞吐；但块太大会降低并行度和故障恢复粒度。128MB 是吞吐、并行度、元数据开销之间的平衡。

4. YARN 解决了什么问题？
   答：解决 Hadoop 1.x 里「计算与资源调度耦合」的问题——1.x 只有 MapReduce 能跑，新框架无法共享集群资源。YARN 把资源调度抽成独立层，MapReduce/Spark/Flink/Tez 都能跑在上面，集群利用率大幅提升。

5. 一个 MapReduce 作业的执行流程？
   答：客户端提交作业 → RM 启动 ApplicationMaster → AM 申请 Container 启动 Map 任务 → Map 读 HDFS 分片输出中间结果 → Shuffle 按 key 分区排序传输 → Reduce 聚合输出 → 结果写回 HDFS。

6. 为什么生产集群必须开 Kerberos？
   答：Hadoop 默认无认证，任何客户端都能伪装成任意用户（如 hdfs 超级用户）读写数据，安全风险极高。Kerberos 强制身份认证 + 服务级授权，配合权限控制才能保证多租户数据安全。

7. HDFS 与对象存储（S3/OSS）选型怎么选？
   答：需要高性能顺序读写、与 Hive/Spark 深度集成、自建机房用 HDFS；海量小文件、存算分离、弹性扩缩容、云上部署用对象存储（配合 Iceberg/Hudi 表格式）。现代湖仓多走「对象存储 + 表格式」。
```

## 最佳实践与踩坑记录

### 最佳实践

1. 生产集群 NameNode 和 ResourceManager 都要配 HA，消除单点
2. 数据节点配多块盘，DataNode 数据目录多盘并行提升吞吐
3. 计算框架统一跑在 YARN 上，用队列（Queue）隔离不同业务
4. 副本数默认 3，冷数据用纠删码省空间
5. 小文件合并后再入 HDFS，避免元数据膨胀
6. 开启 Kerberos 认证，生产集群必须做安全加固
7. 监控 NameNode 内存、DataNode 磁盘、YARN 资源使用率

### 踩坑记录

```text
坑 1：Hadoop 1.x 时代把 MapReduce 既当计算又当调度
结论：无法运行 Spark 等新框架，资源利用率低。
原因：计算与调度耦合在 MapReduce 里，新框架无法共享资源。
解法：升级 Hadoop 2.x+，用 YARN 统一调度，多框架共存。

坑 2：NameNode 单点故障导致整个集群不可用
结论：NameNode 挂掉，所有读写失败，业务停摆。
原因：未配置 HA，NameNode 是存储层的单点。
解法：配 NameNode HA（Active/Standby + JournalNode + ZKFC）。

坑 3：大量小文件压垮 NameNode
结论：NameNode 内存耗尽，集群变慢甚至不可用。
原因：每个小文件都占 NameNode 内存元数据，百万小文件吃上百 MB。
解法：合并小文件，或改用 HBase/对象存储。

坑 4：YARN 资源没隔离导致任务互相抢占
结论：一个任务占满资源，其他任务饿死或超时。
原因：所有任务进默认队列，无资源隔离和配额控制。
解法：按业务建队列（Capacity Scheduler），设配额和抢占。

坑 5：DataNode 磁盘满但未监控
结论：写入失败，副本缺失，数据面临风险。
原因：数据盘无监控告警，磁盘写满才发现。
解法：监控磁盘使用率，设阈值告警，定期清理临时数据。
```

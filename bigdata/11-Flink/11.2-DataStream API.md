## 概述

DataStream API 是 Flink 最核心的编程接口，用于编写有状态的流处理程序。一条数据流由 Source（数据源）、一连串 Transformation（转换算子）和 Sink（输出端）组成，数据以 DataStream<T> 的形式在算子间流动。相比 SQL/Table API，DataStream API 提供更底层的控制能力（自定义状态、定时器、水位线、分区），适合复杂实时逻辑。DataStream API 与 Table API 可互相转换，共享同一运行时。

```text
DataStream 程序结构：
1. 获取执行环境 —— StreamExecutionEnvironment.getExecutionEnvironment()
2. 定义 Source —— 从消息队列、文件、Socket、自定义源读取
3. 应用 Transformation —— map/flatMap/filter/keyBy/window/process 等
4. 输出 Sink —— 写 Kafka、数据库、文件或自定义
5. execute() 触发 —— 惰性执行，只有 execute 才真正提交作业
```

```java
import org.apache.flink.api.common.functions.FlatMapFunction;
import org.apache.flink.api.java.tuple.Tuple2;
import org.apache.flink.streaming.api.datastream.DataStream;
import org.apache.flink.streaming.api.environment.StreamExecutionEnvironment;
import org.apache.flink.util.Collector;

public class WordCount {
    public static void main(String[] args) throws Exception {
        StreamExecutionEnvironment env = StreamExecutionEnvironment.getExecutionEnvironment();
        env.setParallelism(1);

        DataStream<String> text = env.socketTextStream("localhost", 9999);

        DataStream<Tuple2<String, Integer>> counts = text
            .flatMap(new FlatMapFunction<String, Tuple2<String, Integer>>() {
                @Override
                public void flatMap(String value, Collector<Tuple2<String, Integer>> out) {
                    for (String w : value.split(" ")) {
                        out.collect(new Tuple2<>(w, 1));
                    }
                }
            })
            .keyBy(t -> t.f0)
            .sum(1);

        counts.print();
        env.execute("WordCount");
    }
}
```

## Source

Source 是数据流的入口，负责从外部系统读取数据并转成 DataStream。Flink 内置了从集合、文件、Socket、Kafka、Kinesis 等读取的连接器，也支持自定义 SourceFunction（简单源）与新一代 Source API（支持事件时间、水位线、精确控制）。生产中最常用的是 Kafka Source，它天然支持分区并行读取与消费位点管理。

```text
Source 要点：
1. 内置源 —— fromElements/fromCollection/socketTextStream/readTextFile
2. 连接器源 —— KafkaSource、KinesisSource、FileSource 等
3. 自定义源 —— SourceFunction（旧）与 Source API（新，支持水位线与分片）
4. 并行读取 —— Kafka 按分区分配，一个分区一个并行实例
5. 水位线 —— 事件时间场景 Source 负责生成水位线（或由上游携带）
```

```java
import org.apache.flink.api.common.eventtime.WatermarkStrategy;
import org.apache.flink.connector.kafka.source.KafkaSource;
import org.apache.flink.connector.kafka.source.enumerator.initializer.OffsetsInitializer;
import org.apache.flink.api.common.serialization.SimpleStringSchema;

// 方式一：简单集合源
DataStream<String> fromCollection = env.fromElements("a", "b", "c");

// 方式二：Kafka Source（生产主流）
KafkaSource<String> kafkaSource = KafkaSource.<String>builder()
    .setBootstrapServers("kafka-broker:9092")
    .setTopics("orders")
    .setGroupId("flink-orders-group")
    .setStartingOffsets(OffsetsInitializer.latest())
    .setValueOnlyDeserializer(new SimpleStringSchema())
    .build();

DataStream<String> kafkaStream = env
    .fromSource(kafkaSource, WatermarkStrategy.noWatermarks(), "Kafka Source");
```

## Transformation

Transformation 是对 DataStream 的转换操作，分为无状态与有状态两类。无状态转换如 map、flatMap、filter、mapPartition 等，逐条处理不保留状态；有状态转换如 keyBy + 聚合（sum/reduce/aggregate）、窗口、join、process 等，需要维护状态。Transformation 返回新的 DataStream，形成算子链，是数据流处理逻辑的主体。

```text
Transformation 要点：
1. 无状态 —— map / flatMap / filter，逐条转换，不保留历史
2. 有状态 —— keyBy 后的 sum/reduce/aggregate、window、process，跨记录维护状态
3. 分区类 —— keyBy/rebalance/rescale/broadcast/shuffle，改变数据分发
4. 合并类 —— union（同类型多流合并）、connect（异类型流，配合 CoProcessFunction）
5. 类型安全 —— lambda 常需 returns() 显式声明返回类型（泛型擦除）
```

```java
import org.apache.flink.api.common.functions.MapFunction;
import org.apache.flink.api.common.functions.RichMapFunction;

DataStream<Integer> nums = env.fromElements(1, 2, 3, 4, 5);

// map：无状态转换
DataStream<Integer> doubled = nums.map(n -> n * 2);

// filter：过滤
DataStream<Integer> evens = nums.filter(n -> n % 2 == 0);

// RichMapFunction：可访问运行时上下文（并行度、状态等）
DataStream<Integer> withIndex = nums.map(new RichMapFunction<Integer, Integer>() {
    @Override
    public Integer map(Integer v) {
        return v * getRuntimeContext().getIndexOfThisSubtask();
    }
});

// 分流（侧输出）：把偶数主输出、奇数走侧输出
final OutputTag<Integer> oddTag = new OutputTag<Integer>("odd") {};
SingleOutputStreamOperator<Integer> mainStream = nums.process(
    new ProcessFunction<Integer, Integer>() {
        @Override
        public void processElement(Integer v, Context ctx, Collector<Integer> out) {
            if (v % 2 == 0) out.collect(v);
            else ctx.output(oddTag, v);
        }
    });
```

## Sink

Sink 是数据流的出口，把处理结果写入外部系统。Flink 提供打印（print）、文件（StreamingFileSink）、Kafka、JDBC、ES 等 Sink。Sink 通常实现两阶段提交（TwoPhaseCommitSinkFunction）以配合 Checkpoint 实现端到端 Exactly-Once（如 Kafka 事务性写入）。自定义 Sink 要处理好幂等与事务，避免故障恢复时重复写。

```text
Sink 要点：
1. 内置 —— print / writeAsText / StreamingFileSink（滚动文件输出）
2. 连接器 —— KafkaSink、JdbcSink、ElasticsearchSink 等
3. Exactly-Once —— KafkaSink 用两阶段提交 + 事务实现精确一次
4. 自定义 —— 实现 SinkFunction 或 RichSinkFunction，注意幂等
5. 性能 —— 批量写、异步写、控制并发，避免拖慢上游
```

```java
import org.apache.flink.connector.kafka.sink.KafkaSink;
import org.apache.flink.connector.kafka.sink.KafkaRecordSerializationSchema;
import org.apache.flink.connector.base.DeliveryGuarantee;

// Kafka Sink：配合 Checkpoint 实现 Exactly-Once
KafkaSink<String> kafkaSink = KafkaSink.<String>builder()
    .setBootstrapServers("kafka-broker:9092")
    .setRecordSerializer(KafkaRecordSerializationSchema.builder()
        .setTopic("orders-out")
        .setValueSerializationSchema(new SimpleStringSchema())
        .build())
    .setDeliveryGuarantee(DeliveryGuarantee.EXACTLY_ONCE)  // 事务写入
    .build();

DataStream<String> result = /* ... */;
result.sinkTo(kafkaSink);

// 简单 print 调试
result.print();
```

## KeyBy

KeyBy 是 Flink 的分区算子，按 key 的哈希把数据路由到对应子任务，使相同 key 的数据进入同一个算子实例。它是使用 Keyed State 与窗口的前提：只有 keyBy 之后，状态才按 key 隔离、窗口才按 key 分组。keyBy 会触发一次数据重分布（网络传输），是流处理里最常见的 Shuffle 操作。key 的选择要足够散列，避免热点。

```text
KeyBy 要点：
1. 作用 —— 相同 key 的数据路由到同一子任务，为 Keyed State/窗口做准备
2. 哈希分区 —— 默认 key.hashCode() % parallelism，key 分布不均会导致热点
3. key 提取 —— 支持字段名、KeySelector（lambda/匿名类）
4. 前提 —— 后续有状态算子（window/process/聚合）必须先 keyBy
5. 与状态关系 —— Keyed State 按 key 隔离存储，随 key 一起路由
```

```java
import org.apache.flink.api.java.tuple.Tuple3;

// 按字段名 keyBy（POJO/Tuple）
DataStream<Tuple3<String, Long, Double>> orders = /* ... */;
orders.keyBy(t -> t.f0);   // 按第一个字段（user_id）

// 按多个 key 组合（复合键）
orders.keyBy(t -> Tuple2.of(t.f0, t.f1));

// KeySelector 返回类型要可哈希，避免用 null key
DataStream<Order> orderStream = /* ... */;
KeyedStream<Order, String> keyed = orderStream.keyBy(Order::getUserId);

// keyBy 之后做有状态聚合
keyed.sum("amount");
```

## ProcessFunction

ProcessFunction 是 DataStream API 里最底层的算子，提供了「逐条处理 + 访问状态 + 注册定时器」的完整能力。它有三个核心回调：processElement（每条数据）、onTimer（定时器触发）、open（初始化，获取状态）。基于 ProcessFunction 可实现 KeyedProcessFunction（带 Keyed State 与定时器）、CoProcessFunction（双流）、ProcessWindowFunction（窗口处理）。

```text
ProcessFunction 要点：
1. 能力 —— 访问状态（ValueState 等）、注册/删除定时器、获取当前 key
2. processElement —— 处理每条记录，可读写状态、注册定时器
3. onTimer —— 定时器触发时执行，常用于超时检测、延迟处理
4. KeyedProcessFunction —— 需先 keyBy，状态与定时器按 key 隔离
5. 用途 —— 超时告警、会话超时、自定义窗口、复杂状态机
```

```java
import org.apache.flink.api.common.state.ValueState;
import org.apache.flink.api.common.state.ValueStateDescriptor;
import org.apache.flink.streaming.api.functions.KeyedProcessFunction;
import org.apache.flink.util.Collector;

// 场景：订单支付超时检测（下单后 10 分钟未支付则告警）
public class PayTimeoutProcess extends KeyedProcessFunction<String, Order, String> {
    private ValueState<Order> orderState;

    @Override
    public void open(Configuration parameters) {
        ValueStateDescriptor<Order> desc =
            new ValueStateDescriptor<>("order", Order.class);
        orderState = getRuntimeContext().getState(desc);
    }

    @Override
    public void processElement(Order order, Context ctx, Collector<String> out) throws Exception {
        if ("create".equals(order.status)) {
            orderState.update(order);
            // 注册 10 分钟后的定时器
            ctx.timerService().registerProcessingTimeTimer(
                ctx.timerService().currentProcessingTime() + 10 * 60 * 1000);
        } else if ("pay".equals(order.status)) {
            // 已支付，删除定时器
            Order created = orderState.value();
            if (created != null) {
                ctx.timerService().deleteProcessingTimeTimer(
                    created.ts + 10 * 60 * 1000);
                orderState.clear();
            }
        }
    }

    @Override
    public void onTimer(long timestamp, OnTimerContext ctx, Collector<String> out) throws Exception {
        Order order = orderState.value();
        if (order != null) {
            out.collect("订单超时未支付: " + order.orderId);
            orderState.clear();
        }
    }
}
```

## 应用场景实战

### 场景一：实时订单金额统计（完整 DataStream 作业）

```java
import org.apache.flink.api.common.eventtime.WatermarkStrategy;
import org.apache.flink.api.common.functions.MapFunction;
import org.apache.flink.api.java.tuple.Tuple2;
import org.apache.flink.connector.kafka.source.KafkaSource;
import org.apache.flink.connector.kafka.sink.KafkaSink;
import org.apache.flink.streaming.api.datastream.DataStream;
import org.apache.flink.streaming.api.environment.StreamExecutionEnvironment;
import org.apache.flink.api.common.serialization.SimpleStringSchema;

public class RealtimeOrderStat {
    public static void main(String[] args) throws Exception {
        StreamExecutionEnvironment env = StreamExecutionEnvironment.getExecutionEnvironment();
        env.enableCheckpointing(60_000);   // 开启 Checkpoint

        // Source：读 Kafka 订单 JSON
        KafkaSource<String> source = KafkaSource.<String>builder()
            .setBootstrapServers("kafka:9092")
            .setTopics("orders")
            .setGroupId("realtime-order-stat")
            .setStartingOffsets(OffsetsInitializer.latest())
            .setValueOnlyDeserializer(new SimpleStringSchema())
            .build();

        DataStream<String> raw = env
            .fromSource(source, WatermarkStrategy.noWatermarks(), "orders-source");

        // Transformation：解析 -> keyBy -> 聚合
        DataStream<Tuple2<String, Double>> parsed = raw
            .map(new MapFunction<String, Tuple2<String, Double>>() {
                @Override
                public Tuple2<String, Double> map(String json) {
                    // 简化：按逗号分隔 user_id,amount
                    String[] parts = json.split(",");
                    return new Tuple2<>(parts[0], Double.parseDouble(parts[1]));
                }
            });

        DataStream<String> result = parsed
            .keyBy(t -> t.f0)
            .sum(1)
            .map(t -> t.f0 + ":" + t.f1);

        // Sink：写回 Kafka
        KafkaSink<String> sink = KafkaSink.<String>builder()
            .setBootstrapServers("kafka:9092")
            .setRecordSerializer(KafkaRecordSerializationSchema.builder()
                .setTopic("order-stats")
                .setValueSerializationSchema(new SimpleStringSchema())
                .build())
            .build();

        result.sinkTo(sink);
        env.execute("RealtimeOrderStat");
    }
}
```

### 场景二：双流关联——订单与支付流匹配

```java
// 用 connect + CoProcessFunction 实现订单流与支付流的关联
public class OrderPayMatch {
    public static void main(String[] args) throws Exception {
        StreamExecutionEnvironment env = StreamExecutionEnvironment.getExecutionEnvironment();
        env.setParallelism(1);

        DataStream<Order> orders = env.fromElements(
            new Order("o1", "create"), new Order("o1", "pay"));
        DataStream<Pay> pays = env.fromElements(new Pay("o1", 100.0));

        orders.keyBy(o -> o.orderId)
            .connect(pays.keyBy(p -> p.orderId))
            .process(new CoProcessFunction<Order, Pay, String>() {
                private ValueState<Order> orderState;
                private ValueState<Pay> payState;

                @Override
                public void open(Configuration parameters) {
                    orderState = getRuntimeContext().getState(
                        new ValueStateDescriptor<>("order", Order.class));
                    payState = getRuntimeContext().getState(
                        new ValueStateDescriptor<>("pay", Pay.class));
                }

                @Override
                public void processElement1(Order o, Context ctx, Collector<String> out) throws Exception {
                    Pay p = payState.value();
                    if (p != null) {
                        out.collect("匹配成功: " + o.orderId + " 金额 " + p.amount);
                        payState.clear();
                    } else {
                        orderState.update(o);
                    }
                }

                @Override
                public void processElement2(Pay p, Context ctx, Collector<String> out) throws Exception {
                    Order o = orderState.value();
                    if (o != null) {
                        out.collect("匹配成功: " + o.orderId + " 金额 " + p.amount);
                        orderState.clear();
                    } else {
                        payState.update(p);
                    }
                }
            })
            .print();

        env.execute("OrderPayMatch");
    }
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. 有状态算子（窗口/聚合/process）前必须先 keyBy，否则状态语义错误
2. 使用 lambda 时显式 returns() 声明类型，避免泛型擦除导致的编译/运行错误
3. 复杂逻辑用 ProcessFunction 而非堆叠多个简单算子，可同时访问状态与定时器
4. 生产 Sink 要配 Checkpoint + Exactly-Once 语义，避免故障重复写
5. key 的选择要保证散列均匀，避免热点 key 导致数据倾斜
6. Source 的分区数要与 Kafka 分区对齐，充分并行读取
7. 调试用 print，上线前换成正式 Sink 并关注反压

### 踩坑记录

```text
坑 1：lambda 泛型擦除导致运行时报错
结论：作业启动即抛「could not determine TypeInformation」异常。
原因：Java lambda 的泛型信息在编译期被擦除，Flink 无法推断返回类型。
解法：使用 returns(TypeInformation/TypeHint) 显式声明返回类型。

坑 2：忘记 keyBy 直接使用 Keyed State
结论：运行时抛「Keyed state can only be used on a keyed stream」。
原因：Keyed State 依赖 key 分区，未 keyBy 的流无 key 上下文。
解法：在使用 Keyed State 前先调用 keyBy()。

坑 3：KeyBy 的 key 分布不均导致热点
结论：个别子任务数据量远超其他，出现反压与延迟。
原因：key 哈希不均（如少数热门用户占据大量数据）。
解法：设计更散列的复合 key，或对热点 key 做打散处理。

坑 4：Sink 未做幂等导致故障恢复重复写
结论：作业从 Checkpoint 恢复后，下游出现重复数据。
原因：Sink 未实现两阶段提交，At-Least-Once 语义下会重复提交。
解法：用支持事务的 Sink（KafkaSink EXACTLY_ONCE），或自定义幂等写。

坑 5：Socket 源生产误用导致数据丢失
结论：生产环境用 socketTextStream，断连后数据全丢且无法恢复。
原因：Socket 源无容错与位点管理，仅适合本地调试。
解法：生产改用 Kafka 等带位点管理的连接器 Source。
```

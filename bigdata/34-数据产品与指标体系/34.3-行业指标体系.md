## 概述

行业指标体系是电商与互联网广告领域通行的度量语言，覆盖交易侧（GMV、订单、转化、复购、Funnel）与广告投放侧（Impression、Click、CTR、CVR、CPM、CPC、CPA、ROAS）两大维度。统一、可复用的指标口径是数据分析与业务决策的基础，本专题逐一拆解每个指标的定义、计算公式与 SQL 实现。
```text
行业指标体系框架
- 交易侧：GMV → 订单 → 转化 → 复购 → Funnel（漏斗）
- 广告侧：Impression → Click → CTR / CVR
- 计费侧：CPM / CPC / CPA（成本口径）
- 效果侧：ROAS（收入回报口径）
- 核心：口径统一 + 分层拆解 + 可下钻归因
```

## GMV

GMV（Gross Merchandise Volume，商品交易总额）是电商最核心的规模指标，指统计期内所有成交订单的金额总和，通常取「支付口径」以保证资金真实性。GMV 可拆解为「用户数 × 客单价 × 频次」，也可按渠道、品类、新老客下钻，是衡量平台体量与增长的第一指标。
```text
GMV 要点
- 口径：支付金额（已支付，排除退款与未支付）
- 拆解：GMV = 支付用户数 x 客单价 = 用户数 x 频次 x 客单价
- 变体：净 GMV（扣除退款）、GTV（交易额）、GMV 增速
- 局限：GMV 不含退货与优惠，需结合净额看真实收入
```
```sql
-- GMV 及其人均拆解
SELECT
    COUNT(DISTINCT order_id)                    AS order_cnt,
    SUM(pay_amount)                             AS gmv,
    COUNT(DISTINCT user_id)                     AS pay_users,
    ROUND(SUM(pay_amount) / COUNT(DISTINCT user_id), 2) AS gmv_per_user
FROM dwd_order_detail
WHERE order_status = 'paid'
  AND dt = '2026-08-14';
```

## 订单

订单指标刻画交易规模与结构，核心包括订单量（成交单数）、客单价（AOV，平均每单金额）、件单价（平均每件商品金额）与连带率（每单商品件数）。订单量反映转化规模，客单价与件单价反映价格与组合策略效果，是 GMV 拆解的下钻维度。
```text
订单要点
- 订单量：统计期成交订单数（去重订单号）
- 客单价 AOV = GMV / 订单数
- 件单价 = GMV / 商品件数
- 连带率 = 商品件数 / 订单数（衡量凑单与捆绑效果）
```
```sql
-- 订单核心指标：订单量、客单价、件单价、连带率
SELECT
    COUNT(DISTINCT order_id)                  AS order_cnt,
    SUM(pay_amount)                           AS gmv,
    ROUND(SUM(pay_amount) / COUNT(DISTINCT order_id), 2) AS avg_order_value,
    ROUND(SUM(pay_amount) / SUM(quantity), 2) AS avg_item_price,
    ROUND(SUM(quantity) / COUNT(DISTINCT order_id), 2)   AS items_per_order
FROM dwd_order_detail
WHERE order_status = 'paid'
  AND dt = '2026-08-14';
```

## 转化

转化率衡量用户从访问到完成目标动作（下单、支付）的比例，是漏斗效率的核心指标。常见口径有「访问 → 下单转化率」「下单 → 支付转化率」，按设备、渠道、页面拆解可定位转化瓶颈环节。转化率受流量质量、页面体验、价格策略多重因素影响。
```text
转化要点
- 访问转化率 = 下单用户数 / 访问用户数
- 支付转化率 = 支付用户数 / 下单用户数
- 整体转化率 = 支付用户数 / 访问用户数
- 拆解维度：渠道 / 设备 / 落地页 / 新老客
```
```sql
-- 转化漏斗：访问 → 下单 → 支付
SELECT
    COUNT(DISTINCT visitor_id)                                       AS visitors,
    COUNT(DISTINCT CASE WHEN order_id IS NOT NULL THEN visitor_id END) AS order_visitors,
    COUNT(DISTINCT CASE WHEN pay_time IS NOT NULL THEN visitor_id END) AS pay_visitors,
    ROUND(COUNT(DISTINCT CASE WHEN order_id IS NOT NULL THEN visitor_id END)
        / COUNT(DISTINCT visitor_id), 4) AS visit_to_order_rate,
    ROUND(COUNT(DISTINCT CASE WHEN pay_time IS NOT NULL THEN visitor_id END)
        / COUNT(DISTINCT CASE WHEN order_id IS NOT NULL THEN visitor_id END), 4) AS order_to_pay_rate
FROM dwd_page_visit_log
WHERE dt = '2026-08-14';
```

## 复购

复购指用户在统计期内多次购买的行为，复购率 = 购买 2 次及以上的用户数 / 总购买用户数。复购率反映用户忠诚度与商品/服务的复购属性，是衡量留存与 LTV 的重要中间指标。复购周期（相邻两单间隔）与复购品类则是运营优化的抓手。
```text
复购要点
- 复购率 = 复购用户数 / 总购买用户数
- 复购用户：统计期内购买 >= 2 次的用户
- 复购周期：相邻两单平均时间间隔
- 用途：衡量商品粘性、评估会员与促销策略
```
```sql
-- 复购率计算
SELECT
    COUNT(DISTINCT user_id)                                       AS total_buyers,
    COUNT(DISTINCT CASE WHEN order_cnt >= 2 THEN user_id END)     AS repeat_buyers,
    ROUND(COUNT(DISTINCT CASE WHEN order_cnt >= 2 THEN user_id END)
        / COUNT(DISTINCT user_id), 4) AS repurchase_rate
FROM (
    SELECT
        user_id,
        COUNT(DISTINCT order_id) AS order_cnt
    FROM dwd_order_detail
    WHERE order_status = 'paid'
      AND dt >= '2026-08-01' AND dt <= '2026-08-14'
    GROUP BY user_id
) t;
```

## Funnel

漏斗（Funnel）按用户旅程的关键步骤（曝光 → 点击 → 加购 → 下单 → 支付）统计每步的转化人数与相邻转化率，用于定位流失最严重的环节。漏斗分析是增长与体验优化的核心工具，通过逐步下钻可精确定位「哪一步损失了多少用户」。
```text
漏斗分析要点
- 典型路径：曝光 → 点击 → 加购 → 下单 → 支付
- 每步指标：该步用户数 + 上一步到该步的转化率
- 定位价值：相邻转化率骤降处即瓶颈环节
- 注意：漏斗步骤间需口径一致（同一批用户、同一时间窗）
```
```sql
-- 全链路转化漏斗
SELECT
    step_order,
    step,
    uv,
    ROUND(uv / FIRST_VALUE(uv) OVER (ORDER BY step_order), 4) AS overall_rate
FROM (
    SELECT 1 AS step_order, '曝光' AS step, COUNT(DISTINCT visitor_id) AS uv FROM dwd_exposure_log WHERE dt='2026-08-14'
    UNION ALL
    SELECT 2, '点击', COUNT(DISTINCT visitor_id) FROM dwd_click_log WHERE dt='2026-08-14'
    UNION ALL
    SELECT 3, '加购', COUNT(DISTINCT visitor_id) FROM dwd_cart_log WHERE dt='2026-08-14'
    UNION ALL
    SELECT 4, '下单', COUNT(DISTINCT user_id) FROM dwd_order_detail WHERE dt='2026-08-14'
    UNION ALL
    SELECT 5, '支付', COUNT(DISTINCT user_id) FROM dwd_order_detail WHERE dt='2026-08-14' AND order_status='paid'
) t
ORDER BY step_order;
```

## Impression

Impression（曝光 / 展示量）指广告或内容被展示给用户的次数，是广告计费与效果分析的起点。曝光量既可按「广告请求后成功渲染」统计，也可按「可见曝光」（viewable impression，50% 面积可见至少 1 秒）统计，后者更接近真实触达。曝光是 CTR、CPM 等指标的分母基础。
```text
曝光要点
- 定义：广告被展示的次数（一次展示计 1）
- 可见曝光：50% 像素可见且持续 >= 1 秒
- 去重口径：按用户去重得到 reach（触达人数）
- 用途：衡量投放规模与触达能力
```
```sql
-- 曝光量统计（按广告计划）
SELECT
    campaign_id,
    COUNT(1)               AS impressions,
    COUNT(DISTINCT user_id) AS reach_uv
FROM dwd_ad_exposure_log
WHERE dt = '2026-08-14'
GROUP BY campaign_id;
```

## Click

Click（点击量）指用户对广告或链接的点击次数，反映广告对用户的即时吸引力。点击量是连接曝光与转化的中间环节，与曝光结合得到 CTR，与转化结合得到 CVR。点击去重后得到点击人数（click UV），可进一步分析单人多点与无效点击。
```text
点击要点
- 定义：用户点击广告的次数
- 点击率 = 点击量 / 曝光量（见 CTR）
- 异常：机器刷量会导致点击虚高，需反作弊过滤
- 用途：评估创意吸引力、优化素材与落地页
```
```sql
-- 点击量统计（按广告计划）
SELECT
    campaign_id,
    COUNT(1)               AS clicks,
    COUNT(DISTINCT user_id) AS click_uv
FROM dwd_ad_click_log
WHERE dt = '2026-08-14'
GROUP BY campaign_id;
```

## CTR

CTR（Click-Through Rate，点击率）= 点击量 / 曝光量，衡量广告创意与人群匹配度的核心效率指标。CTR 越高说明广告越能吸引目标用户点击。行业 CTR 通常在 0.5%~5% 区间，受素材质量、人群定向、广告位位置等因素影响，是优化投放的第一步指标。
```text
CTR 要点
- 公式：CTR = 点击量 / 曝光量
- 意义：创意吸引力与人群匹配效率
- 参考：信息流广告 CTR 约 1%~3%
- 优化：素材、文案、定向、出价共同影响 CTR
```
```sql
-- 点击率 CTR 计算
SELECT
    e.campaign_id,
    e.impressions,
    c.clicks,
    ROUND(c.clicks / e.impressions, 4) AS ctr
FROM (
    SELECT campaign_id, COUNT(1) AS impressions
    FROM dwd_ad_exposure_log WHERE dt='2026-08-14' GROUP BY campaign_id
) e
LEFT JOIN (
    SELECT campaign_id, COUNT(1) AS clicks
    FROM dwd_ad_click_log WHERE dt='2026-08-14' GROUP BY campaign_id
) c ON e.campaign_id = c.campaign_id;
```

## CVR

CVR（Conversion Rate，转化率）= 转化数 / 点击数，衡量点击后的转化效率，反映落地页与商品承接能力。转化定义依目标而定（注册、下单、支付、留资）。CVR 低通常指向落地页体验差、价格无优势或目标用户错配，需要与 CTR 分开定位问题。
```text
CVR 要点
- 公式：CVR = 转化数 / 点击数
- 意义：落地页承接能力与成交效率
- 与 CTR 区分：CTR 看「愿不愿意点」，CVR 看「点完买不买」
- 优化：落地页、促销、商品页加载速度
```
```sql
-- 转化率 CVR 计算（转化 = 下单）
SELECT
    c.campaign_id,
    c.clicks,
    v.conversions,
    ROUND(v.conversions / c.clicks, 4) AS cvr
FROM (
    SELECT campaign_id, COUNT(1) AS clicks
    FROM dwd_ad_click_log WHERE dt='2026-08-14' GROUP BY campaign_id
) c
LEFT JOIN (
    SELECT campaign_id, COUNT(1) AS conversions
    FROM dwd_ad_conversion_log WHERE dt='2026-08-14' GROUP BY campaign_id
) v ON c.campaign_id = v.campaign_id;
```

## CPM

CPM（Cost Per Mille，千次展示成本）= 广告花费 / 曝光量 × 1000，是品牌广告最常用的计费方式，按展示次数收费，与是否点击无关。CPM 衡量「触达一千人的成本」，适合以曝光和品牌认知为目标的投放，不直接保证点击与转化。
```text
CPM 要点
- 公式：CPM = 花费 / 曝光量 x 1000
- 计费：按千次曝光付费，与点击无关
- 适用：品牌曝光、新品预热、大促造势
- 参考：信息流 CPM 约 10~50 元区间（行业差异大）
```
```sql
-- 千次展示成本 CPM
SELECT campaign_id, cost, impressions,
       ROUND(cost / impressions * 1000, 2) AS cpm
FROM dws_ad_campaign_daily
WHERE dt = '2026-08-14';
```

## CPC

CPC（Cost Per Click，单次点击成本）= 广告花费 / 点击量，是效果广告最常用的计费方式，按点击付费。CPC 只对「有效点击」收费，能规避纯曝光浪费，但需配合反作弊过滤无效点击。CPC 与 CTR、CVR 结合可计算完整获客成本链路。
```text
CPC 要点
- 公式：CPC = 花费 / 点击量
- 计费：按点击付费，曝光不收费
- 适用：效果投放、App 下载、电商引流
- 注意：无效点击会推高真实 CPC，需反作弊
```
```sql
-- 单次点击成本 CPC
SELECT campaign_id, cost, clicks,
       ROUND(cost / clicks, 2) AS cpc
FROM dws_ad_campaign_daily
WHERE dt = '2026-08-14';
```

## CPA

CPA（Cost Per Action，单次行动成本）= 广告花费 / 转化数，按用户完成特定动作（下单、注册、付费）计费，是效果广告的终极计费方式。CPA 直接绑定业务目标，风险最低，但媒体通常要求较高或采用 oCPA（智能出价）方式优化到目标 CPA。
```text
CPA 要点
- 公式：CPA = 花费 / 转化数
- 计费：按转化动作付费（下单 / 注册 / 付费）
- 变体：oCPA 由平台自动出价优化到目标成本
- 意义：直接衡量「获取一个真实客户」的成本
```
```sql
-- 单次转化成本 CPA
SELECT campaign_id, cost, conversions,
       ROUND(cost / conversions, 2) AS cpa
FROM dws_ad_campaign_daily
WHERE dt = '2026-08-14';
```

## ROAS

ROAS（Return On Ad Spend，广告支出回报率）= 广告带来的收入 / 广告花费，衡量每花 1 元广告费带来的直接收入。ROAS 是效果广告的终极效果指标，ROAS > 1 才不亏损（但还需扣除商品成本）。与之相关的 ROI（投资回报率）=（收入 - 成本）/ 成本，口径更宽。
```text
ROAS 要点
- 公式：ROAS = 广告收入 / 广告花费
- 意义：每 1 元广告费的直接回报
- 阈值：ROAS > 1 仅覆盖广告费，需结合毛利率看真实盈利
- 与 ROI 区别：ROAS 只看广告费，ROI 含全部成本
```
```sql
-- 广告支出回报率 ROAS
SELECT campaign_id, cost, revenue,
       ROUND(revenue / cost, 2) AS roas
FROM dws_ad_campaign_daily
WHERE dt = '2026-08-14';
```

## 应用场景实战

### 场景一：广告投放效果日报

投放团队需要每天查看各广告计划的曝光、点击、成本与效果指标，快速定位表现差的计划做调整。将曝光、点击、转化、花费四张表汇总成一张效果宽表，一次性算出 CTR、CVR、CPC、CPA、ROAS 全套指标。
```sql
-- 广告效果指标日报宽表
INSERT OVERWRITE TABLE dws_ad_effect_daily
SELECT
    e.campaign_id,
    e.impressions,
    c.clicks,
    v.conversions,
    s.cost,
    s.revenue,
    ROUND(c.clicks / e.impressions, 4)  AS ctr,
    ROUND(v.conversions / c.clicks, 4)  AS cvr,
    ROUND(s.cost / c.clicks, 2)         AS cpc,
    ROUND(s.cost / v.conversions, 2)    AS cpa,
    ROUND(s.cost / e.impressions * 1000, 2) AS cpm,
    ROUND(s.revenue / s.cost, 2)        AS roas
FROM (SELECT campaign_id, COUNT(1) AS impressions FROM dwd_ad_exposure_log WHERE dt='2026-08-14' GROUP BY campaign_id) e
LEFT JOIN (SELECT campaign_id, COUNT(1) AS clicks FROM dwd_ad_click_log WHERE dt='2026-08-14' GROUP BY campaign_id) c
    ON e.campaign_id = c.campaign_id
LEFT JOIN (SELECT campaign_id, COUNT(1) AS conversions FROM dwd_ad_conversion_log WHERE dt='2026-08-14' GROUP BY campaign_id) v
    ON e.campaign_id = v.campaign_id
LEFT JOIN (SELECT campaign_id, SUM(cost) AS cost, SUM(revenue) AS revenue FROM dws_ad_campaign_daily WHERE dt='2026-08-14' GROUP BY campaign_id) s
    ON e.campaign_id = s.campaign_id;
```

### 场景二：GMV 波动归因下钻

GMV 环比下滑，需要定位是「用户少了」「频次降了」还是「客单价降了」。用指标拆解法把 GMV 拆成支付用户数、人均频次、客单价三个因子，逐层下钻到渠道与品类，找到下滑根因。
```sql
-- GMV 三因子拆解（用户数 x 频次 x 客单价）
SELECT
    COUNT(DISTINCT user_id)                                   AS pay_users,
    COUNT(DISTINCT order_id)                                  AS order_cnt,
    SUM(pay_amount)                                           AS gmv,
    ROUND(COUNT(DISTINCT order_id) / COUNT(DISTINCT user_id), 2) AS freq_per_user,
    ROUND(SUM(pay_amount) / COUNT(DISTINCT order_id), 2)      AS aov,
    ROUND(SUM(pay_amount) / COUNT(DISTINCT user_id), 2)       AS arpu
FROM dwd_order_detail
WHERE order_status = 'paid' AND dt = '2026-08-14';

-- 下钻到渠道
SELECT
    channel,
    SUM(pay_amount)                       AS gmv,
    COUNT(DISTINCT user_id)               AS pay_users,
    ROUND(SUM(pay_amount) / COUNT(DISTINCT order_id), 2) AS aov
FROM dwd_order_detail
WHERE order_status = 'paid' AND dt = '2026-08-14'
GROUP BY channel
ORDER BY gmv DESC;
```

## 最佳实践与踩坑记录

### 最佳实践

1. 口径统一并文档化：GMV 是否含退款、转化算下单还是支付，必须写入指标字典，杜绝同名不同义。
2. 支付口径优先：GMV、订单、转化等交易指标一律用「已支付」口径，未支付与已退款单独列示。
3. 广告指标按天归因：CTR、CVR、CPA 等按「曝光/点击发生日」归因，避免跨天数据错位。
4. 反作弊先行：点击与转化前先过滤机器刷量与无效流量，否则 CPC、CPA 严重失真。
5. 漏斗口径对齐：漏斗每步必须用同一批用户、同一时间窗，否则相邻转化率无意义。
6. 拆解到根因：指标波动不只看总量，务必下钻到「用户 x 频次 x 客单价」和渠道/品类。
7. 区分 ROAS 与 ROI：对外汇报明确口径，ROAS 只看广告费，避免误读为整体盈利。

### 踩坑记录
```text
坑 1：GMV 用了「下单金额」而非「支付金额」
  结论：GMV 虚高，与财务对账不一致
  原因：下单未支付、超时取消的订单被计入
  解法：统一取 order_status='paid' 口径，退款与未支付单独出报表

坑 2：CTR 与 CVR 分母搞混
  原因：CTR 分母是曝光、CVR 分母是点击，混用导致指标完全失真
  解法：牢记链路曝光→点击→转化，每级指标的分子是下一级的分母

坑 3：跨天归因导致转化率错位
  原因：用户前一天点击、后一天转化，按点击日统计会漏算转化
  解法：明确归因窗口（如点击后 7 天内转化），转化按点击日回填统计

坑 4：复购率分母用「全部用户」而非「购买用户」
  原因：把未购买用户也放进分母，复购率被严重稀释
  解法：复购率分母必须是「统计期内有购买的用户」

坑 5：漏斗用 UNION 拼多表但未对齐去重键
  原因：有的表按 visitor_id、有的按 user_id，ID 口径不一致导致漏斗断裂
  解法：统一用同一标识符（如匿名访客 ID），或先做 ID 打通再建漏斗
```

## 概述

SQL（Structured Query Language）是操作关系型数据库的标准语言，也是大数据分析的基础功。Hive、Spark SQL、Presto/Trino、ClickHouse 都实现了 SQL 方言——学会标准 SQL 后，写这些引擎的查询只是语法细节差异。本主题覆盖 SQL 的查询核心：投影、过滤、聚合、多表关联、集合运算、CTE、窗口函数、条件表达式、NULL 和日期处理。

```text
SQL 语句的逻辑执行顺序（与书写顺序不同，理解它才能写对查询）：
1. FROM        —— 确定数据来源，先做 JOIN
2. WHERE       —— 行级过滤
3. GROUP BY    —— 分组
4. HAVING      —— 分组后过滤
5. SELECT      —— 投影，计算聚合/表达式
6. ORDER BY    —— 排序
7. LIMIT       —— 截断
```

```sql
-- 示例表结构
CREATE TABLE orders (
    order_id   BIGINT,
    user_id    BIGINT,
    amount     DECIMAL(10, 2),
    status     STRING,
    created_at TIMESTAMP
);
```

## SELECT 与投影

SELECT 决定返回哪些列以及如何计算。除了直接取列，还支持常量、表达式、别名（AS）、去重（DISTINCT）和限制返回行数（LIMIT）。投影发生在逻辑执行顺序的后半段，所以 WHERE 里不能引用 SELECT 里定义的别名（部分引擎如 MySQL 的 HAVING/ORDER BY 可以）。

```text
SELECT 要点：
1. 别名 —— AS 可省略，但列名含函数/表达式时建议显式写
2. DISTINCT —— 去重，代价是排序/哈希，大数据量慎用
3. LIMIT —— 只截断结果集，不做优化，大表别依赖它省资源
4. 表达式 —— 算术、字符串拼接、类型转换都可在 SELECT 里做
```

```sql
-- 基础投影
SELECT order_id, user_id, amount FROM orders;

-- 别名与表达式
SELECT order_id AS id,
       amount * 1.1 AS amount_with_tax
FROM orders;

-- 去重
SELECT DISTINCT status FROM orders;

-- 截断
SELECT * FROM orders ORDER BY created_at DESC LIMIT 10;
```

## WHERE 与过滤

WHERE 在分组前做行级过滤，是查询优化最重要的一环。支持比较运算、逻辑运算（AND/OR/NOT）、范围（BETWEEN）、集合（IN）、模式匹配（LIKE）和空值判断（IS NULL）。过滤条件能不能走索引、能不能下推到存储层，直接决定查询快慢。

```text
WHERE 要点：
1. AND 优先级高于 OR，复杂条件务必加括号
2. IN 等价于多个 OR，子查询 IN 可能触发慢查询
3. LIKE '%xx%' 无法走索引，前缀匹配 LIKE 'xx%' 可以
4. 对列做函数（WHERE year(created_at)=2024）会阻止索引下推，改成范围比较
```

```sql
-- 比较与逻辑
SELECT * FROM orders WHERE amount > 100 AND status = 'paid';

-- 范围与集合
SELECT * FROM orders
WHERE amount BETWEEN 50 AND 200
  AND status IN ('paid', 'shipped');

-- 模式匹配
SELECT * FROM orders WHERE status LIKE 'ship%';

-- 空值判断
SELECT * FROM orders WHERE status IS NOT NULL;
```

## GROUP BY 与聚合

GROUP BY 把行按指定列分组，配合聚合函数（COUNT/SUM/AVG/MAX/MIN）计算组级统计。SELECT 里出现的非聚合列必须出现在 GROUP BY 中（否则多数引擎报错）。过滤分组用 HAVING（在聚合之后），过滤原始行用 WHERE（在聚合之前）。

```text
聚合函数与分组要点：
1. COUNT(*) 计数所有行，COUNT(col) 忽略 NULL
2. COUNT(DISTINCT col) 精确去重计数，大表可换近似算法（见 17-大数据算法）
3. HAVING 可引用聚合结果和 SELECT 别名，WHERE 不能
4. GROUP BY 常伴随排序，多个分组列时注意分组键顺序
```

```sql
-- 分组聚合
SELECT user_id, COUNT(*) AS order_cnt, SUM(amount) AS total
FROM orders
GROUP BY user_id;

-- HAVING 过滤分组
SELECT user_id, COUNT(*) AS order_cnt
FROM orders
GROUP BY user_id
HAVING COUNT(*) >= 3;

-- 多列分组
SELECT status, DATE(created_at) AS d, COUNT(*) AS cnt
FROM orders
GROUP BY status, DATE(created_at);
```

## JOIN 与多表关联

JOIN 把多张表按关联键合并成一张宽表。类型分 INNER（只保留两边都匹配）、LEFT（保留左表全部）、RIGHT、FULL（两边都保留）、CROSS（笛卡尔积）。大数据场景下 JOIN 是最昂贵的操作之一，关联键的选择、表的大小和是否发生数据倾斜决定性能。

```text
JOIN 类型与要点：
1. INNER JOIN —— 两边都存在的记录，最常用
2. LEFT JOIN —— 左表全保留，右表无匹配补 NULL，是事实表关联维表的标准写法
3. FULL JOIN —— 两边都保留，用于对账/差异分析
4. 关联键类型要一致，否则隐式转换拖慢甚至出错
5. 大表 JOIN 大表注意数据倾斜（见 31-大数据性能优化）
```

```sql
-- INNER JOIN：订单关联用户
SELECT o.order_id, u.name, o.amount
FROM orders o
INNER JOIN users u ON o.user_id = u.user_id;

-- LEFT JOIN：保留所有订单，无用户信息补 NULL
SELECT o.order_id, u.name
FROM orders o
LEFT JOIN users u ON o.user_id = u.user_id;

-- FULL JOIN：对账（找出两边独有的记录）
SELECT COALESCE(o.order_id, r.order_id) AS order_id,
       o.amount AS online_amount, r.amount AS refund_amount
FROM online_orders o
FULL JOIN refunds r ON o.order_id = r.order_id;
```

## UNION 与集合运算

UNION 把多个查询结果纵向拼接（要求列数、类型一致）。UNION 去重（等价 UNION DISTINCT），UNION ALL 不去重（性能更好，优先用）。EXCEPT/INTERSECT 做差集/交集。集合运算常用来合并多分区、多月数据或对账。

```text
UNION 要点：
1. UNION ALL 不去重，性能远好于 UNION，明确无重复时用它
2. UNION 去重会触发排序/哈希，大数据量代价高
3. 各分支列数、顺序、类型必须一致，否则报错
4. 各分支单独 ORDER BY 无效，排序要放在整个 UNION 之后
```

```sql
-- 合并两个月的订单数据
SELECT order_id, amount, created_at FROM orders_202401
UNION ALL
SELECT order_id, amount, created_at FROM orders_202402;

-- 去重合并
SELECT user_id FROM orders_202401
UNION
SELECT user_id FROM orders_202402;

-- 交集：两个月都下单的用户
SELECT user_id FROM orders_202401
INTERSECT
SELECT user_id FROM orders_202402;
```

## CTE 与子查询

CTE（Common Table Expression，WITH 子句）给子查询起名，让复杂查询可读、可复用。子查询则直接嵌套在 FROM/WHERE/SELECT 里。CTE 分非递归和递归（Recursive CTE）两种，后者用 UNION ALL 自引用实现层级遍历（组织树、路径展开）。相比子查询，CTE 更清晰，且可在同一查询中多次引用。

```text
CTE 要点：
1. 一个 WITH 可定义多个 CTE，后面的可引用前面的
2. 递归 CTE 必须 UNION ALL，且要有终止条件
3. CTE 是「语法糖」，多数引擎会内联展开，别指望它物化缓存结果
4. 复杂逻辑拆成多步 CTE，比一坨嵌套子查询好维护
```

```sql
-- 非递归 CTE：先聚合再过滤
WITH user_total AS (
    SELECT user_id, SUM(amount) AS total
    FROM orders GROUP BY user_id
)
SELECT * FROM user_total WHERE total > 1000;

-- 递归 CTE：展开组织层级
WITH RECURSIVE org_tree AS (
    SELECT id, name, manager_id, 1 AS level
    FROM employees WHERE manager_id IS NULL
    UNION ALL
    SELECT e.id, e.name, e.manager_id, t.level + 1
    FROM employees e
    INNER JOIN org_tree t ON e.manager_id = t.id
)
SELECT * FROM org_tree;
```

## 窗口函数

窗口函数（Window Function）在「不折叠行」的前提下做跨行计算，是数据分析最有价值的 SQL 能力。语法 OVER (PARTITION BY ... ORDER BY ...)，PARTITION BY 分组（不折叠），ORDER BY 定义窗口内顺序。常见三类：排序（ROW_NUMBER/RANK/DENSE_RANK）、聚合（SUM/AVG/COUNT 做运行累计）、取值（LAG/LEAD/FIRST_VALUE/LAST_VALUE）。

```text
窗口函数要点：
1. ROW_NUMBER 唯一连续、RANK 并列跳号、DENSE_RANK 并列不跳号
2. 聚合窗口加 ORDER BY 是「截至当前行」的运行累计，不加是整组累计
3. LAG/LEAD 取前/后第 N 行，做环比、留存常用
4. 窗口函数在 WHERE 之后执行，不能直接放 WHERE，需套一层子查询
```

```sql
-- 每个用户按金额排名
SELECT order_id, user_id, amount,
       ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY amount DESC) AS rn
FROM orders;

-- 运行累计：截至当前订单的累计金额
SELECT order_id, user_id, amount,
       SUM(amount) OVER (PARTITION BY user_id ORDER BY created_at) AS cum_amount
FROM orders;

-- LAG 取上一行：计算相邻订单时间差
SELECT order_id, created_at,
       LAG(created_at) OVER (PARTITION BY user_id ORDER BY created_at) AS prev_time
FROM orders;
```

## CASE 表达式

CASE 是 SQL 的「if-else」，分简单 CASE（匹配单个值）和搜索 CASE（匹配布尔条件）两种，可在 SELECT、WHERE、GROUP BY、ORDER BY 中使用。行转列（PIVOT 的朴素实现）、条件计数、分桶、数据脱敏都靠它。

```text
CASE 要点：
1. 搜索 CASE（WHEN 条件 THEN）比简单 CASE 更灵活，用得更多
2. 条件计数 = SUM(CASE WHEN ... THEN 1 ELSE 0 END)
3. 每个 WHEN 顺序求值，命中即停，注意条件顺序
4. 无 ELSE 且都不命中时返回 NULL
```

```sql
-- 条件计数：各状态的订单数
SELECT
    SUM(CASE WHEN status = 'paid' THEN 1 ELSE 0 END) AS paid_cnt,
    SUM(CASE WHEN status = 'shipped' THEN 1 ELSE 0 END) AS shipped_cnt,
    SUM(CASE WHEN status = 'refunded' THEN 1 ELSE 0 END) AS refunded_cnt
FROM orders;

-- 分桶
SELECT order_id, amount,
    CASE
        WHEN amount < 50 THEN '小额'
        WHEN amount < 500 THEN '中额'
        ELSE '大额'
    END AS bucket
FROM orders;
```

## NULL 处理

NULL 表示「未知/缺失」，不等于空串、不等于 0，任何与 NULL 的比较结果都是 NULL（不是 TRUE 也不是 FALSE），这是 SQL 最容易踩坑的地方。处理 NULL 靠 IS NULL/IS NOT NULL、COALESCE（取第一个非空）、NULLIF（相等返回 NULL）、IFNULL/NVL（引擎方言）。

```text
NULL 要点：
1. NULL = NULL 结果是 NULL 而非 TRUE，判断空值必须用 IS NULL
2. 聚合函数忽略 NULL，但 COUNT(*) 计数所有行
3. COALESCE(a, b, c) 返回第一个非空值，做缺省值填充
4. LEFT JOIN 未匹配的右表列是 NULL，用 COALESCE 补默认值
```

```sql
-- 判断空值
SELECT * FROM orders WHERE status IS NULL;

-- COALESCE 填缺省
SELECT order_id, COALESCE(status, 'unknown') AS status
FROM orders;

-- NULLIF：除零保护
SELECT order_id,
       amount / NULLIF(cnt, 0) AS avg_amount
FROM order_stats;
```

## 日期函数

日期是分析中最常见的维度，日期函数负责解析、截断、加减、格式化和取差。标准 SQL 有 EXTRACT、DATE_TRUNC、CURRENT_DATE；各引擎又有方言（MySQL 的 DATE_FORMAT、Hive 的 date_add/datediff、PostgreSQL 的 age）。大数据里常把时间戳截断到天/小时做聚合。

```text
日期函数要点：
1. DATE_TRUNC(单位, ts) 截断到天/小时/月，是分组聚合的标配
2. 跨天判断用 datediff 而非时间戳相减
3. 时区要先统一再比较，避免 UTC 与本地时间混用
4. 字符串转日期用 to_date/str_to_date，注意格式串大小写（MM 月 vs mm 分）
```

```sql
-- 截断到天做聚合
SELECT DATE_TRUNC('day', created_at) AS d, COUNT(*) AS cnt
FROM orders
GROUP BY DATE_TRUNC('day', created_at);

-- 日期加减与取差
SELECT order_id,
       created_at + INTERVAL '1 day' AS next_day,
       DATEDIFF('day', created_at, CURRENT_DATE) AS days_ago
FROM orders;

-- 提取分量
SELECT EXTRACT(YEAR FROM created_at) AS yr,
       EXTRACT(MONTH FROM created_at) AS mon
FROM orders;
```

## 应用场景实战

### 场景一：计算每个用户的首单、最近一单和复购情况

```sql
-- 用户订单行为画像：首单时间、最近一单时间、订单数、累计金额
WITH order_ranked AS (
    SELECT user_id, order_id, amount, created_at,
           ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY created_at ASC) AS first_rn,
           ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY created_at DESC) AS last_rn
    FROM orders
)
SELECT user_id,
       MAX(CASE WHEN first_rn = 1 THEN created_at END) AS first_order_time,
       MAX(CASE WHEN last_rn = 1 THEN created_at END) AS last_order_time,
       COUNT(*) AS order_cnt,
       SUM(amount) AS total_amount
FROM order_ranked
GROUP BY user_id
HAVING COUNT(*) > 1;   -- 只保留复购用户
```

### 场景二：按月统计 GMV 与环比增长

```sql
-- 月度 GMV + 环比（用 LAG 取上个月）
WITH monthly AS (
    SELECT DATE_TRUNC('month', created_at) AS mon,
           SUM(amount) AS gmv
    FROM orders
    WHERE status IN ('paid', 'shipped')
    GROUP BY DATE_TRUNC('month', created_at)
)
SELECT mon,
       gmv,
       LAG(gmv) OVER (ORDER BY mon) AS prev_gmv,
       ROUND((gmv - LAG(gmv) OVER (ORDER BY mon)) * 1.0
             / NULLIF(LAG(gmv) OVER (ORDER BY mon), 0), 4) AS mom_growth
FROM monthly
ORDER BY mon;
```

## 最佳实践与踩坑记录

### 最佳实践

1. 写查询先想逻辑执行顺序（FROM -> WHERE -> GROUP BY -> HAVING -> SELECT -> ORDER BY），别按书写顺序推理
2. 过滤条件尽量写进 WHERE 而非 HAVING，能下推就下推
3. 关联维表统一用 LEFT JOIN，事实表为主表
4. 能 UNION ALL 就别 UNION，除非明确要去重
5. 复杂查询拆 CTE，一层一件事
6. 窗口函数配 ORDER BY 和 PARTITION BY 写全，别漏导致结果意外
7. 日期聚合统一截断（DATE_TRUNC）再 GROUP BY，避免时间戳精度差异

### 踩坑记录

```text
坑 1：WHERE 里引用 SELECT 别名
结论：多数引擎报「未知列」错误。
原因：WHERE 在 SELECT 之前逻辑执行，别名此时尚未定义。
解法：把别名表达式原样写进 WHERE，或套一层子查询/CTE。

坑 2：用 NULL 做等值比较
结论：WHERE col = NULL 永远返回空结果集。
原因：NULL 与任何值的比较结果都是 NULL，不满足 WHERE 的布尔过滤。
解法：改用 IS NULL / IS NOT NULL。

坑 3：COUNT(col) 与 COUNT(*) 混用
结论：列含 NULL 时计数偏少，统计口径不一致。
原因：COUNT(col) 忽略 NULL 行，COUNT(*) 计数所有行。
解法：明确语义，统计行数用 COUNT(*)，统计非空值用 COUNT(col)。

坑 4：LIKE '%关键词%' 全表扫描
结论：大表模糊查询极慢，甚至拖垮集群。
原因：前导通配符导致无法利用索引，只能逐行匹配。
解法：前缀能确定就写 '关键词%'；必须全模糊时用倒排索引/搜索引擎。

坑 5：UNION 去重导致结果行数莫名变少
结论：本来重复的行被去掉了，数据量对不上。
原因：UNION 默认 DISTINCT，会对合并结果整体去重。
解法：无去重需求时用 UNION ALL。
```

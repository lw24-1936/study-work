## 概述

推荐系统与深度学习是数据价值变现的核心技术：推荐从「协同过滤 + 矩阵分解」演进到「深度 CTR 预估（Wide&Deep/DeepFM/DIN）」，深度学习从「Transformer 架构」演进到「BERT/GPT 预训练范式」，再到「Diffusion 生成模型、RAG 检索增强、LoRA 微调、DPO 对齐」。这组论文串起了「推荐 + NLP + 生成式 AI」的技术主线，是理解现代数据应用（推荐、搜索、LLM）的必读。

```text
两条技术主线：
1. 推荐系统 —— MF → Wide&Deep → DeepFM → DIN（CTR 预估演进）
2. 深度学习 —— Transformer → BERT/GPT → ViT → Diffusion → RAG/LoRA/DPO（生成式 AI 演进）
```

## MF 矩阵分解

MF（Matrix Factorization，矩阵分解）是推荐系统协同过滤的经典：把「用户-物品评分矩阵」分解成「用户隐向量矩阵 × 物品隐向量矩阵」，用低维隐向量刻画用户偏好和物品属性，预测评分 = 两个隐向量的内积。它解决了「评分矩阵稀疏」的问题，是 Netflix Prize 的冠军技术，也是 SVD++、ALS 等后续方法的基础。

```text
MF 论文要点：
1. 核心 —— 评分矩阵 R ≈ U × V^T，U 用户隐向量、V 物品隐向量
2. 预测 —— 评分 = 用户向量 · 物品向量（内积）
3. 训练 —— 梯度下降/ALS 最小化重建误差
4. 影响 —— 协同过滤的里程碑，推荐系统的基石
```

```python
import numpy as np

# MF 梯度下降训练（简化）
def matrix_factorization(R, k=10, steps=100, lr=0.01):
    n_users, n_items = R.shape
    U = np.random.rand(n_users, k)   # 用户隐向量
    V = np.random.rand(n_items, k)   # 物品隐向量
    for _ in range(steps):
        for i in range(n_users):
            for j in range(n_items):
                if R[i, j] > 0:
                    e = R[i, j] - U[i] @ V[j]
                    U[i] += lr * (e * V[j])
                    V[j] += lr * (e * U[i])
    return U @ V.T

R = np.array([[5, 3, 0, 1], [4, 0, 0, 1], [1, 1, 0, 5], [0, 0, 5, 4]])
pred = matrix_factorization(R)
print("预测评分矩阵（重建）:\n", np.round(pred, 1))
```

## Wide-Deep

Wide & Deep（2016，Google）把「记忆（Wide）与泛化（Deep）」结合：Wide 部分用线性模型记住「共现特征」（如「用户装过 A 且看 B」），Deep 部分用 DNN 学习「泛化特征」（隐式特征组合）。两者联合训练，兼顾「推荐已知高频组合」和「泛化到未见组合」。它应用于 Google Play 的 App 推荐，是「记忆 + 泛化」双塔思想的代表作。

```text
Wide & Deep 论文要点：
1. Wide 组件 —— 线性模型 + 交叉特征，记忆高频共现
2. Deep 组件 —— DNN，学习隐式特征组合，泛化
3. 联合训练 —— Wide 和 Deep 输出相加，一起优化
4. 影响 —— 「记忆 + 泛化」框架，CTR 预估的经典范式
```

```python
import torch.nn as nn

class WideDeep(nn.Module):
    def __init__(self, wide_dim, deep_dim, hidden=64):
        super().__init__()
        self.wide = nn.Linear(wide_dim, 1)          # 记忆：线性
        self.deep = nn.Sequential(
            nn.Linear(deep_dim, hidden), nn.ReLU(),
            nn.Linear(hidden, 1)                     # 泛化：DNN
        )

    def forward(self, wide_x, deep_x):
        return self.wide(wide_x) + self.deep(deep_x)  # 相加
```

## DeepFM

DeepFM（2017，华为）是 Wide & Deep 的改进：用 FM（因子分解机）替代 Wide 部分，让「低阶特征交互」也自动学习（不需要人工设计交叉特征），Deep 部分仍是 DNN。FM 部分和 DNN 部分共享输入 embedding，端到端训练。它解决了 Wide & Deep「需要人工特征工程」的痛点，是 CTR 预估的重要演进。

```text
DeepFM 论文要点：
1. FM 组件 —— 自动学习二阶特征交互（替代人工交叉）
2. Deep 组件 —— DNN 学习高阶交互
3. 共享 embedding —— FM 和 DNN 共享特征向量，端到端
4. 影响 —— 无需人工特征工程的 CTR 预估
```

```python
import torch.nn as nn

class DeepFM(nn.Module):
    def __init__(self, n_fields, emb_dim=8, hidden=64):
        super().__init__()
        self.emb = nn.Embedding(n_fields, emb_dim)
        self.fm_linear = nn.Linear(n_fields, 1)     # 一阶
        self.deep = nn.Sequential(                  # DNN 高阶
            nn.Linear(n_fields * emb_dim, hidden), nn.ReLU(),
            nn.Linear(hidden, 1))

    def fm_interaction(self, x_emb):
        # 二阶交互：0.5 * (sum^2 - sum of square)
        s = x_emb.sum(dim=1)
        return 0.5 * (s ** 2 - (x_emb ** 2).sum(dim=1)).sum(dim=1, keepdim=True)

    def forward(self, x):
        x_emb = self.emb(x)
        return self.fm_linear(x.float()) + self.fm_interaction(x_emb) + self.deep(x_emb.flatten(1))
```

## DIN

DIN（2018，阿里）引入「注意力机制」到 CTR 预估：用户兴趣是多样的，不同候选物品应该激活用户不同的兴趣。DIN 用「候选物品与用户历史行为的注意力加权」计算用户兴趣表示——与候选物品相关的历史行为权重大、无关的权重小。它解决了「固定长度向量无法表达多样兴趣」的问题。

```text
DIN 论文要点：
1. 注意力 —— 用户历史行为按「与候选物品的相关性」加权
2. 兴趣激活 —— 候选不同，激活的用户兴趣不同
3. 局部激活 —— 只激活相关的历史行为，不是全量平均
4. 影响 —— 注意力机制进入 CTR 预估的开山作
```

```python
import torch
import torch.nn as nn

class DIN(nn.Module):
    def __init__(self, emb_dim=8, hidden=32):
        super().__init__()
        self.att = nn.Sequential(                  # 注意力打分
            nn.Linear(emb_dim * 3, hidden), nn.ReLU(),
            nn.Linear(hidden, 1))

    def forward(self, target, history):
        # target: (B, d), history: (B, T, d)
        t = target.unsqueeze(1).expand_as(history)          # (B, T, d)
        concat = torch.cat([history, t, history * t], dim=-1)  # 交互
        score = self.att(concat).squeeze(-1)                 # (B, T)
        weight = torch.softmax(score, dim=1).unsqueeze(-1)   # 注意力权重
        return (weight * history).sum(dim=1)                  # 加权兴趣表示
```

## Transformer

Transformer（2017，Google）用「自注意力（Self-Attention）+ 多头注意力」取代 RNN 的序列建模，实现「并行处理整个序列」。核心是注意力机制：Q（查询）、K（键）、V（值），输出 = softmax(QK^T/√d)V，捕捉任意两位置的依赖。它解决了 RNN「无法并行、长程依赖难学」的问题，是 BERT/GPT/ViT 等一切现代模型的架构基础。

```text
Transformer 论文要点：
1. 自注意力 —— 序列内任意两位置的依赖，一次性计算
2. 多头注意力 —— 多个注意力头，捕捉不同子空间的关系
3. 位置编码 —— 弥补注意力「无序」的缺陷，注入位置信息
4. 影响 —— BERT/GPT/ViT/Diffusion 的架构底座
```

```python
import torch
import torch.nn as nn

class SelfAttention(nn.Module):
    def __init__(self, d_model=64, n_head=8):
        super().__init__()
        self.n_head = n_head
        self.d_k = d_model // n_head
        self.wq = nn.Linear(d_model, d_model)
        self.wk = nn.Linear(d_model, d_model)
        self.wv = nn.Linear(d_model, d_model)

    def forward(self, x):
        B, T, _ = x.shape
        Q = self.wq(x).view(B, T, self.n_head, self.d_k).transpose(1, 2)
        K = self.wk(x).view(B, T, self.n_head, self.d_k).transpose(1, 2)
        V = self.wv(x).view(B, T, self.n_head, self.d_k).transpose(1, 2)
        attn = torch.softmax(Q @ K.transpose(-2, -1) / (self.d_k ** 0.5), dim=-1)
        out = (attn @ V).transpose(1, 2).reshape(B, T, -1)
        return out
```

## BERT

BERT（2018，Google）开创了「预训练 + 微调」范式：用「掩码语言模型（MLM）+ 下一句预测（NSP）」在无标注语料上预训练 Transformer 编码器，学出通用的语言表示，再在下游任务微调。它把 NLP 从「每个任务从头训练」变成「预训练大模型 + 小成本微调」，是预训练范式的里程碑。

```text
BERT 论文要点：
1. 预训练 —— MLM（掩码预测）+ NSP（下一句预测）自监督
2. 双向编码 —— 相比 GPT 的单向，BERT 用双向上下文
3. 微调 —— 预训练后在下游任务小成本微调
4. 影响 —— 预训练范式的里程碑
```

## GPT

GPT（2018~，OpenAI）走「生成式预训练」路线：用「自回归语言模型（预测下一个词）」单向预训练 Transformer 解码器，靠「规模 + 数据」实现涌现能力。从 GPT-1 到 GPT-4，核心思想是「语言建模即一切」——预测下一个 token 就能学会推理、写作、代码。它催生了 ChatGPT 和整个大模型时代。

```text
GPT 论文要点：
1. 自回归 —— 单向预测下一个 token
2. 规模法则 —— 参数量、数据量、算力越大，能力越强
3. 涌现 —— 规模足够大时涌现推理、few-shot 等能力
4. 影响 —— ChatGPT、大模型时代的开端
```

## ViT

ViT（2020，Google）把 Transformer 引入计算机视觉：把图像切成固定大小的 patch，每个 patch 展平成一个「词」，当作序列输入标准 Transformer。它证明「纯 Transformer（无卷积）在大规模数据上超越 CNN」，是「Transformer 大一统」在视觉上的里程碑。

```text
ViT 论文要点：
1. patch 切分 —— 图像切成 patch，展平成 token
2. 标准 Transformer —— 不加卷积，纯注意力
3. 大规模数据 —— 大数据上超越 CNN
4. 影响 —— 视觉 Transformer、多模态模型（CLIP）的基础
```

## Diffusion

Diffusion（扩散模型，DDPM 2020）是生成模型的新范式：前向过程逐步给数据加噪（直到纯噪声），反向过程学习「去噪」逐步还原数据。它生成质量高、训练稳定，是 Stable Diffusion、DALL-E 等文生图模型的基础，逐步取代 GAN 成为生成模型主流。

```text
Diffusion 论文要点：
1. 前向加噪 —— 逐步加高斯噪声，直到纯噪声
2. 反向去噪 —— 学习逐步去噪，还原数据
3. 生成 —— 从噪声开始，逐步去噪生成样本
4. 影响 —— Stable Diffusion、DALL-E 的底座
```

## RAG

RAG（2020，Meta）是「检索增强生成」：把「检索」和「生成」结合——先从知识库检索相关文档，再把文档拼进 prompt 让 LLM 生成，解决「LLM 知识过时、幻觉、缺乏私有知识」的问题。它是「让 LLM 用上外部知识」的主流方案，也是企业落地 LLM 的标准架构。

```text
RAG 论文要点：
1. 检索 —— 从知识库检索与问题相关的文档
2. 增强 —— 把文档拼进 prompt，作为生成依据
3. 生成 —— LLM 基于检索结果生成
4. 解决 —— 知识过时、幻觉、私有知识缺失
```

## LoRA

LoRA（2021，微软）是「低秩适配」的参数高效微调方法：冻结预训练权重，只训练「低秩分解的增量矩阵（ΔW = BA）」，大幅减少可训练参数（如减少 1000 倍），让大模型微调在消费级显卡上可行。它解决了「全量微调大模型成本过高」的问题，是 PEFT 的代表作。

```text
LoRA 论文要点：
1. 低秩分解 —— ΔW = BA，B、A 是低秩矩阵
2. 冻结主干 —— 只训练低秩增量，参数减少上千倍
3. 可插拔 —— 不同任务训练不同的 LoRA，切换成本低
4. 影响 —— 大模型高效微调的标准方法
```

## DPO

DPO（2023，斯坦福）是「直接偏好优化」：把 RLHF（先训奖励模型 + PPO 强化学习）简化为「直接在偏好数据上做分类损失优化」，无需单独训奖励模型、无需强化学习。它让「对齐人类偏好」从复杂的两阶段 RLHF 变成简单的监督学习，是对齐（Alignment）方法的重要演进。

```text
DPO 论文要点：
1. 直接优化 —— 用偏好对（好回答 vs 坏回答）直接优化策略
2. 省去奖励模型 —— 不用单独训 RM，不用 PPO
3. 稳定 —— 监督学习式损失，训练更稳定
4. 影响 —— 对齐方法的简化，替代 RLHF 的候选
```

## 应用场景实战

### 场景一：推荐系统 CTR 预估选型

```text
CTR 预估模型演进选型：
- 特征少、要可解释 → 逻辑回归 + 人工交叉
- 要自动特征交互 → DeepFM（FM 替代人工交叉）
- 用户兴趣多样、行为丰富 → DIN（注意力激活兴趣）
- 冷启动、数据少 → Wide&Deep（记忆强）
```

### 场景二：LLM 落地架构（RAG + LoRA + DPO）

```text
企业 LLM 落地的标准组合：
1. RAG —— 检索企业知识库，解决私有知识和幻觉
2. LoRA —— 低成本微调领域适配
3. DPO —— 对齐企业偏好（不要有害/无关回答）
```

## 最佳实践与踩坑记录

### 最佳实践

1. 读论文按「要解决问题 → 核心思想 → 与前任的差异」三步走
2. 推荐论文关注「特征交互」的演进线（人工 → FM → 注意力）
3. 深度学习论文关注「架构统一」线（Transformer 大一统）
4. 把论文的「为什么这样设计」映射到自己场景，别只记结论
5. 大模型时代重点读 RAG/LoRA/DPO，这是落地的关键

### 踩坑记录

```text
坑 1：把论文里的 SOTA 数字当普适结论
结论：在自己场景复现不了论文效果。
原因：论文效果依赖特定数据、算力、调参，直接迁移不成立。
解法：关注方法思想和适用前提，别迷信数字。

坑 2：混淆 BERT（双向）和 GPT（单向）的适用场景
结论：用 BERT 做生成、用 GPT 做理解，效果差。
原因：BERT 双向编码适合理解，GPT 自回归适合生成。
解法：理解类任务用 BERT 系，生成类用 GPT 系。

坑 3：RAG 当万能药，忽略检索质量
结论：检索到不相关文档，生成反而更差。
原因：RAG 效果上限由检索质量决定，垃圾进垃圾出。
解法：先优化检索（分块、embedding、重排），再谈生成。

坑 4：LoRA 秩设太高，参数没省下来
结论：微调成本没降多少。
原因：LoRA 的秩 r 越大，可训练参数越多，失去高效意义。
解法：r 从 8~16 起步，够用即可，别盲目加大。
```

## 概述

隐私计算（Privacy-Preserving Computation）是一类在「数据不出域、不泄露原始信息」的前提下实现数据价值流通的技术集合，目标是让数据「可用不可见」。核心技术包括差分隐私（DP，加噪保护统计结果）、联邦学习（FL，模型聚合代替数据集中）、安全多方计算（SMPC，多方联合计算不暴露输入）、同态加密（HE，密文上直接运算），各自在安全性与计算开销间做不同取舍。

```text
隐私计算技术对比
- 差分隐私 DP：加噪声，轻量，输出带统计噪声，适合统计发布
- 联邦学习 FL：数据不动模型动，适合跨机构联合建模
- 安全多方计算 SMPC：强安全但通信/计算开销大，适合中小规模
- 同态加密 HE：密文运算，安全性最高但性能开销极大
- 选型：按「数据量 x 安全等级 x 算力预算」综合权衡
```

## Differential Privacy

差分隐私（Differential Privacy，DP）是一种可数学证明的隐私保护范式：对任意只差一条记录的两个相邻数据集 D 与 D'，算法输出落入同一集合的概率之比不超过 e^ε，从而保证「单条记录是否参与」几乎不影响输出。实现机制主要有 Laplace 机制（数值型加噪声）与指数机制（离散型按效用采样），噪声量由全局敏感度与隐私预算 ε 决定，ε 越小隐私越强但可用性越低。

```text
差分隐私核心要点
- 定义：Pr[M(D) ∈ S] ≤ e^ε · Pr[M(D') ∈ S]（相邻数据集 D、D'）
- ε 隐私预算：越小隐私越强、可用性越低
- Laplace 机制：数值型，加 Lap(Δf/ε) 噪声，Δf 为全局敏感度
- 指数机制：离散型，按 exp(ε·u/2Δu) 概率采样
- 组合性质：多次查询预算累加，需全局预算管理
```

```python
import numpy as np

def laplace_mechanism(query_result, sensitivity, epsilon):
    """Laplace 机制：向查询结果注入满足 ε-DP 的噪声"""
    scale = sensitivity / epsilon
    noise = np.random.laplace(loc=0.0, scale=scale)
    return query_result + noise

# 示例：统计平均消费金额（数值型查询）
true_mean = 250.0
sensitivity = (1000.0 - 0.0) / 1000   # 单条记录对均值的最大影响
epsilon = 0.5                          # 隐私预算
noisy_mean = laplace_mechanism(true_mean, sensitivity, epsilon)
print(f"真实均值={true_mean:.2f}, 加噪后={noisy_mean:.2f}")
```

## Federated Learning

联邦学习（Federated Learning，FL）让各参与方在本地数据上训练模型，仅上传模型参数或梯度到中心服务器聚合，实现「数据不动、模型动」。按数据分布分为横向联邦（特征相同、样本不同，如不同银行）、纵向联邦（样本相同、特征不同，如银行+电商）、联邦迁移学习。核心算法 FedAvg 对各客户端本地参数按样本量加权平均，常结合差分隐私或同态加密防止梯度反推原始数据。

```text
联邦学习核心要点
- 原则：数据不出域，仅交换模型参数/梯度
- 横向联邦：特征相同、样本不同（跨机构同业务）
- 纵向联邦：样本相同、特征不同（跨机构互补特征）
- FedAvg：服务器对各客户端参数按样本量加权平均
- 安全增强：梯度加 DP 噪声 / 同态加密聚合防泄露
```

```text
FedAvg 一轮流程示意
1. 服务器下发全局模型参数 W_t 给 K 个客户端
2. 客户端 k 用本地数据 D_k 训练 E 轮，得到本地参数 W_k
3. 客户端上传 W_k（或梯度 ΔW_k）至服务器
4. 服务器聚合：W_{t+1} = Σ (|D_k| / Σ|D_k|) · W_k
5. 重复 1-4 直至收敛，全程原始数据不离开本地
```

## SMPC

安全多方计算（Secure Multi-Party Computation，SMPC/MPC）允许多个参与方在不暴露各自私有输入的前提下，联合计算一个函数 f(x1, x2, ..., xn) 并各自得到输出。核心技术包括加性秘密共享（把值拆成和为原值的多份）、Shamir 秘密共享（基于多项式插值，t+1 份可还原）、混淆电路（任意函数转布尔电路逐门求值）与不经意传输（OT，发送方不知接收方选了哪个值）。SMPC 安全性强，但通信与计算开销大。

```text
安全多方计算核心要点
- 目标：多方联合计算 f(x1,...,xn)，不暴露各自输入
- 加性秘密共享：x 拆成 n 份，和 = x，单份无信息
- Shamir 秘密共享：多项式插值，任意 t+1 份可还原
- 混淆电路：任意函数转布尔电路，逐门安全求值
- 不经意传输 OT：发送方不知接收方选择了哪个值
- 代价：通信/计算开销大，适合中小规模计算
```

```text
加性秘密共享示例（三方，模 2^32）
明文 x = 123
拆分：s1 = 987654321, s2 = 500, s3 = (x - s1 - s2) mod 2^32
还原：x = (s1 + s2 + s3) mod 2^32
性质：任意两方都无法还原 x，需三方联合
加法可本地完成：x + y 的份额 = s_i^x + s_i^y（无需通信）
```

## Homomorphic Encryption

同态加密（Homomorphic Encryption，HE）允许在密文上直接进行运算，解密结果等同于对明文做同样运算，实现「算而不见」。按能力分为部分同态（PHE，仅支持加法或乘法其一，如 Paillier 加法、ElGamal 乘法）与全同态（FHE，同时支持加减乘，如 BGV/BFV/CKKS/TFHE）。同态加密安全性最高，但密文膨胀与计算开销极大，目前多用于隐私求交、密文推理、联邦聚合等中小规模场景。

```text
同态加密核心要点
- 性质：E(x) ⊕ E(y) = E(x + y)，密文运算解密等于明文运算
- 部分同态 PHE：仅加法或乘法其一（Paillier/ElGamal）
- 全同态 FHE：加减乘全支持（BGV/BFV/CKKS/TFHE）
- 自举 Bootstrapping：刷新噪声实现无限次运算（代价高）
- 局限：密文膨胀 + 计算开销大，尚难大规模落地
```

```text
Paillier 加法同态性质示意
加密：E(3)、E(4)
密文运算：E(3) ⊗ E(4) = E(7)   （密文乘法对应明文加法）
同态加法：E(x) · E(y) = E(x + y)
同态数乘：E(x)^k      = E(k · x)
解密：D(E(7)) = 7
应用：密文下的平均值、加权和、隐私求交
```

## 应用场景实战

### 场景一：差分隐私统计发布

统计部门要对外发布「各年龄段平均消费金额」的统计报表，但不能泄露任何个人记录。对每个分组的均值查询注入满足 ε-DP 的 Laplace 噪声后再发布，实现统计可用性与个体隐私的平衡。

```python
import numpy as np

def dp_grouped_mean(raw_means, group_sizes, value_range, epsilon):
    """对分组均值发布做差分隐私保护"""
    results = []
    for mean, n in zip(raw_means, group_sizes):
        # 单条记录对均值的最大影响 = 值域宽度 / 组内人数
        sensitivity = (value_range[1] - value_range[0]) / n
        noise = np.random.laplace(0.0, sensitivity / epsilon)
        results.append(round(mean + noise, 2))
    return results

# 三个年龄段真实均值
raw_means = [180.5, 320.2, 260.8]
group_sizes = [5000, 8000, 3000]
value_range = (0.0, 1000.0)
epsilon = 0.5

published = dp_grouped_mean(raw_means, group_sizes, value_range, epsilon)
for i, v in enumerate(published):
    print(f"年龄段 {i}: 真实均值={raw_means[i]:.2f}, 发布值={v}")
```

### 场景二：跨机构联邦学习安全聚合

三家银行要在不共享客户数据的前提下联合训练风控模型。每方本地训练后上传模型参数，服务器用安全聚合（结合加性秘密共享）合并参数，任意一方或服务器都无法窥探他方参数，最终各方获得更强的全局模型。

```text
联邦安全聚合流程（结合 SMPC 示意）
1. 各方本地训练，得到参数向量 W_1, W_2, W_3
2. 各方把参数拆成加性秘密共享份额发给其他方
3. 服务器只收集「份额和」，得到聚合参数 ΣW_k / 3
4. 任何单方只见份额，无法还原他方完整参数
5. 服务器下发聚合参数，各方更新本地模型进入下一轮
参数 = 模型权重（如逻辑回归系数 / 神经网络梯度）
```

## 最佳实践与踩坑记录

### 最佳实践

1. 按场景选技术：统计发布选 DP，跨机构建模选 FL，小规模高安全选 SMPC，不盲目上同态加密。
2. 隐私预算统一管理：DP 需设全局预算并拆分到各查询，防止预算耗尽导致后续无法发布。
3. FL 必配安全增强：联邦学习仅传梯度仍可能被反推数据，需叠加 DP 噪声或同态加密聚合。
4. 敏感度计算要精确：DP 噪声量依赖全局敏感度，算大浪费可用性、算小泄露隐私，务必按真实查询推导。
5. SMPC 控制数据规模：多方计算通信开销大，先做数据抽样或降维，避免性能失控。
6. 明确信任模型：区分「半诚实」（诚实但好奇）与「恶意」敌手，SMPC 协议按需选择对抗强度。
7. 保留可解释性与合规说明：发布结果时标注噪声与隐私参数，便于审计与合规举证。

### 踩坑记录

```text
坑 1：DP 隐私预算无上限，反复查询耗尽预算
  结论：多次查询后隐私保护形同虚设，可反推个体信息
  原因：未做全局预算管理与查询配额，忽略了组合性质
  解法：设全局 ε 预算，按查询拆分并达到上限后拒绝进一步查询

坑 2：DP 敏感度算成全局最大值而非该查询敏感度
  原因：直接用「数据全局最大值」代替「该查询函数敏感度」
  解法：按查询类型推导敏感度（均值=(max-min)/n，计数=1），精准加噪

坑 3：FL 只传明文梯度，被梯度反推攻击还原训练样本
  原因：高维梯度可编码样本信息，明文上传等于变相泄露数据
  解法：梯度加 DP 噪声，或用同态加密/SMPC 做安全聚合

坑 4：同态加密直接用于海量明细计算，性能崩溃
  原因：FHE 密文膨胀数百上千倍、运算慢数个数量级
  解法：HE 只用于聚合/求交等小规模中间结果，明细仍走明文或 SMPC

坑 5：SMPC 协议按「恶意敌手」实现却按「半诚实」假设部署
  原因：协议强度与部署假设错配，实际环境存在恶意方导致协议不安全
  解法：明确真实信任模型，按最强敌手假设选型或引入承诺/零知识证明
```

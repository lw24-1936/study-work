## 概述

频率估计（Frequency Estimation）是统计流中每个元素出现次数的近似算法，Top-K 是找出出现次数最多的 k 个元素。精确统计需要 O(n) 内存存每个元素的计数（n 是不同元素数），在海量日志、实时点击流里不可行。频率估计算法用固定内存近似每个元素的频次（Count-Min Sketch 只高估不低估），Top-K 用堆/计数器结构维护「可能是前 k 的元素」。它们是热门商品、热搜词、流量监控、异常检测的基础。

```text
频率与 Top-K 的核心问题：
1. 频率估计 —— 近似统计每个元素出现次数，固定内存
2. 频繁项 —— 找出出现次数超过阈值（如 1%）的元素
3. Top-K —— 找出出现次数最多的 k 个元素
4. 约束 —— 单遍扫描、内存有限、允许误差
```

## Count-Min Sketch

Count-Min Sketch（CMS）是最常用的频率估计结构：用 d 个哈希函数、w 列计数器矩阵，每个元素哈希到每行的一个计数器并 +1；查询时取「d 个计数器的最小值」作为频率估计。它只高估不低估（min 保证 ≥ 真实值），误差由 w（列数）和 d（行数）控制，空间 O(d·w)，是「用最小内存换有界误差」的经典设计。

```text
Count-Min Sketch 要点：
1. 结构 —— d 行 × w 列计数器，d 个哈希函数
2. 更新 —— 元素在每个哈希函数对应的计数器 +1
3. 查询 —— 取 d 个计数器的最小值（min）
4. 误差 —— 只高估不低估，误差 ε ≈ 2e/w（概率 1-δ 内），δ=(1/2)^d
5. 空间 —— O(d·w)，与元素数无关
```

```python
import random
import hashlib

class CountMinSketch:
    def __init__(self, width=2000, depth=5):
        self.w, self.d = width, depth
        self.table = [[0] * width for _ in range(depth)]

    def _hashes(self, x):
        for i in range(self.d):
            h = int(hashlib.md5(f"{i}:{x}".encode()).hexdigest(), 16)
            yield h % self.w

    def add(self, x, count=1):
        for i, j in enumerate(self._hashes(x)):
            self.table[i][j] += count

    def query(self, x):
        return min(self.table[i][j] for i, j in enumerate(self._hashes(x)))

cms = CountMinSketch(width=2000, depth=5)
freq = {}
for _ in range(100000):
    k = random.randint(0, 500)
    cms.add(f"item_{k}")
    freq[f"item_{k}"] = freq.get(f"item_{k}", 0) + 1

# 对比真实频率（CMS 只高估）
for k in [0, 1, 100]:
    key = f"item_{k}"
    print(f"{key}: CMS 估计 {cms.query(key)}，真实 {freq[key]}")
```

## Count Sketch

Count Sketch 是 Count-Min Sketch 的改进，解决 CMS「只高估、有偏」的问题：每行哈希除选位置外，还生成一个 ±1 符号，更新时计数器 += ±1，查询时取「中位数」而非最小值。因为有正负抵消，Count Sketch 的估计是无偏的（期望等于真实值），误差同样 O(1/√w)。它用于需要「无偏频率估计」的场景（如特征哈希、二阶矩估计）。

```text
Count Sketch 要点：
1. 结构 —— 同 CMS，但每行多了 ±1 符号
2. 更新 —— 计数器 += ±1（符号由哈希决定）
3. 查询 —— 取中位数（而非 min），无偏估计
4. 对比 CMS —— CMS 有偏（只高估）、Count Sketch 无偏
```

```python
import random
import hashlib

class CountSketch:
    def __init__(self, width=2000, depth=5):
        self.w, self.d = width, depth
        self.table = [[0] * width for _ in range(depth)]

    def _cell(self, x, i):
        h = int(hashlib.md5(f"{i}:{x}".encode()).hexdigest(), 16)
        pos = h % self.w
        sign = 1 if (h >> self.w) & 1 else -1
        return pos, sign

    def add(self, x, count=1):
        for i in range(self.d):
            pos, sign = self._cell(x, i)
            self.table[i][pos] += sign * count

    def query(self, x):
        est = []
        for i in range(self.d):
            pos, sign = self._cell(x, i)
            est.append(sign * self.table[i][pos])
        return sorted(est)[len(est) // 2]   # 中位数

cs = CountSketch(width=2000, depth=7)
true_freq = {}
for _ in range(100000):
    k = random.randint(0, 500)
    key = f"item_{k}"
    cs.add(key)
    true_freq[key] = true_freq.get(key, 0) + 1

key = "item_42"
print(f"Count Sketch 估计 {cs.query(key)}，真实 {true_freq[key]}")
```

## Misra-Gries

Misra-Gries（MG）是找「频繁项」的确定性算法：维护 k 个计数器，元素来了若已有计数器则 +1，否则若计数器未满则新增，否则所有计数器 -1（删除一批计数为 0 的项）。它保证「频率 > N/k 的元素一定被记录」，只用 O(k) 内存。MG 是确定性保证（不像 CMS 是概率保证），适合「找超过 1% 频率的项」这类阈值场景。

```text
Misra-Gries 要点：
1. 结构 —— k 个计数器，每个记「元素 + 计数」
2. 更新 —— 有则 +1，无则（满则全体 -1）新增
3. 保证 —— 频率 > N/(k+1) 的元素一定在结果里
4. 确定性 —— 无随机性，保证式而非概率式
```

```python
def misra_gries(stream, k):
    counters = {}
    for x in stream:
        if x in counters:
            counters[x] += 1
        elif len(counters) < k:
            counters[x] = 1
        else:
            for key in list(counters.keys()):
                counters[key] -= 1
                if counters[key] == 0:
                    del counters[key]
    return counters

stream = []
true = {}
for _ in range(100000):
    k = random.randint(0, 100)
    stream.append(f"i{k}")
    true[f"i{k}"] = true.get(f"i{k}", 0) + 1

# 找频率 > 1% 的项（即 > 1000）
mg = misra_gries(stream, 100)
for key, cnt in sorted(mg.items(), key=lambda x: -x[1])[:5]:
    print(f"{key}: MG 估计 {cnt}，真实 {true[key]}")
```

## Frequent Items 频繁项

频繁项（Frequent Items）指「出现频率超过给定阈值 φ（如 1%）」的元素。解决它的算法分两类：确定性（Misra-Gries、SpaceSaving，保证找到所有频繁项）和概率性（Count-Min Sketch + 堆，近似但省内存）。SpaceSaving 是实际系统里更常用的：它维护 k 个计数器，满了就用「最小计数项」替换新元素（并继承其计数），保证频率 > N/k 的项都被保留。

```text
频繁项要点：
1. 定义 —— 频率 > φ·N 的元素（φ 是阈值，如 1%）
2. 确定性算法 —— Misra-Gries、SpaceSaving（保证不漏）
3. 概率算法 —— CMS + 堆（近似，省内存）
4. 应用 —— 热点检测、异常流量、DDoS 检测
```

```python
import heapq

def space_saving(stream, k):
    """SpaceSaving：维护 k 个计数器，满了用最小项替换"""
    counters = {}
    for x in stream:
        if x in counters:
            counters[x] += 1
        elif len(counters) < k:
            counters[x] = 1
        else:
            # 找到计数最小的项，替换为新元素（继承计数+1）
            min_key = min(counters, key=counters.get)
            counters[x] = counters[min_key] + 1
            del counters[min_key]
    return counters

ss = space_saving(stream, 100)
top = sorted(ss.items(), key=lambda x: -x[1])[:3]
for key, cnt in top:
    print(f"{key}: SpaceSaving {cnt}，真实 {true[key]}")
```

## Heavy Hitters 重磅项

Heavy Hitters 是「频繁项」的推广，允许误差：找出所有「频率 > φ·N」的元素，同时保证「频率 < (φ-ε)·N」的元素不被输出（ε 是误差容限）。它用 ε-近似框架描述——牺牲一点精度换更少内存。经典实现是 Count-Min Sketch 的 Heavy Hitters 变体：CMS 估计频率 + 小顶堆维护候选 Top-K，定期用 CMS 查询过滤掉非频繁项。

```text
Heavy Hitters 要点：
1. 定义 —— 频率 > φN 的项（φ-ε 近似，ε 是误差容限）
2. 与频繁项区别 —— 允许误差带，内存更省
3. 实现 —— CMS 估计 + 堆维护候选，误差可控
4. 应用 —— 网络流量监控、热点商品、搜索引擎热门词
```

```python
# Heavy Hitters：CMS + 小顶堆维护候选 Top-K
def heavy_hitters(stream, k, width=2000, depth=5):
    cms = CountMinSketch(width, depth)
    heap = []   # (count, key) 小顶堆
    for x in stream:
        cms.add(x)
        # 用 CMS 估计更新堆
        est = cms.query(x)
        if any(h[1] == x for h in heap):
            heap = [(est, h[1]) if h[1] == x else h for h in heap]
        elif len(heap) < k:
            heapq.heappush(heap, (est, x))
        else:
            min_est, min_key = heap[0]
            if est > min_est:
                heapq.heapreplace(heap, (est, x))
    return sorted(heap, reverse=True)

hh = heavy_hitters(stream, 10)
for cnt, key in hh[:3]:
    print(f"{key}: Heavy Hitter 估计 {cnt}")
```

## Top-K Streaming

Top-K Streaming 是「实时维护出现次数最多的 k 个元素」的问题，是 Heavy Hitters 的特例（φ 取第 k 大频率）。核心数据结构是「小顶堆 + 计数结构」：堆里维护当前 Top-K 候选，配合 CMS/SpaceSaving 估计频率，新元素频率超过堆顶就替换。它支撑热搜榜、热卖榜、实时 Top 主播等场景。

```text
Top-K 流式要点：
1. 问题 —— 实时维护频率最高的 k 个元素
2. 结构 —— 小顶堆维护候选 + 计数结构估计频率
3. 更新 —— 新元素估计频率超过堆顶则替换
4. 应用 —— 热搜榜、热卖榜、实时排行
```

```python
import heapq

def top_k_streaming(stream, k):
    heap = []          # (freq, key) 小顶堆，堆顶是第 k 大
    freq = {}
    for x in stream:
        freq[x] = freq.get(x, 0) + 1
        f = freq[x]
        if any(h[1] == x for h in heap):
            heap = [(f, h[1]) if h[1] == x else h for h in heap]
            heapq.heapify(heap)
        elif len(heap) < k:
            heapq.heappush(heap, (f, x))
        elif f > heap[0][0]:
            heapq.heapreplace(heap, (f, x))
    return sorted(heap, reverse=True)

top = top_k_streaming(stream, 5)
print("实时 Top-5:", [(k, c) for c, k in top])
```

## 应用场景实战

### 场景一：实时热搜词统计

```python
# 用 Count-Min Sketch 实时统计搜索词频率，找 Top 热搜
import random

words = ["股票", "天气", "电影", "旅行", "美食", "健身", "编程", "游戏"]
stream = [random.choice(words) for _ in range(100000)]

cms = CountMinSketch(width=5000, depth=5)
heap = []
for w in stream:
    cms.add(w)
    est = cms.query(w)
    if any(h[1] == w for h in heap):
        heap = [(est, h[1]) if h[1] == w else h for h in heap]
    elif len(heap) < 3:
        heapq.heappush(heap, (est, w))
    elif est > heap[0][0]:
        heapq.heapreplace(heap, (est, w))

print("实时热搜 Top-3:", [(w, c) for c, w in sorted(heap, reverse=True)])
```

### 场景二：异常流量检测（频繁 IP）

```python
# 用 SpaceSaving 找访问最频繁的 IP，识别刷流量
import random
ips = [f"10.0.{random.randint(0, 50)}.{random.randint(0, 255)}" for _ in range(200000)]
# 注入一个异常高频 IP
ips += ["10.0.99.99"] * 5000

ss = space_saving(ips, 100)
top_ip = max(ss, key=ss.get)
print(f"最频繁 IP: {top_ip}，访问 {ss[top_ip]} 次（异常）")
```

## 最佳实践与踩坑记录

### 最佳实践

1. 频率估计用 Count-Min Sketch，需无偏用 Count Sketch
2. CMS 参数：w 控精度、d 控置信度，w=2e5、d=5 通常够用
3. 找频繁项用 SpaceSaving（比 Misra-Gries 误差更小）
4. Top-K 用小顶堆维护候选，别全量排序
5. 分布式场景 CMS 可「按位相加」合并（各分区合并）
6. 哈希用高质量 64 位哈希，保证计数器均匀分布

### 踩坑记录

```text
坑 1：CMS 查询取最大值而非最小值
结论：频率估计被严重高估。
原因：CMS 每个计数器都是高估，取 max 会放大误差，min 才最接近真实。
解法：查询取 d 个计数器的最小值。

坑 2：CMS 参数 w 太小导致误差过大
结论：频繁项排名错乱。
原因：w 小则哈希冲突多，计数器被无关元素污染。
解法：按误差需求选 w（ε≈2e/w），w 至少几万起步。

坑 3：Top-K 堆里比较「估计频率」而非「真实频率」
结论：估计误差导致真正高频项被挤掉。
原因：CMS 估计有误差，堆按估计值排序会误判。
解法：候选替换时留裕量，或用 SpaceSaving 这类更稳的结构。

坑 4：Misra-Gries 忘了处理「全体 -1 后删 0」
结论：计数器里残留大量计数为 0 的项，占满空间。
原因：只减不删，0 计数项不清除。
解法：每次全体 -1 后删除计数归 0 的项。

坑 5：把近似频率当精确值做除法/比例
结论：比例计算误差放大。
原因：近似频率有误差，二次运算放大。
解法：明确近似边界，比例类指标用采样或更精确的结构。
```

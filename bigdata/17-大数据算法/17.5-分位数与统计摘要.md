## 概述

分位数估计（Quantile Estimation）是近似计算数据分布的百分位点（如 P50/P95/P99 延迟、中位数）的算法。精确算分位数要排序（O(n log n) 或 O(n) 内存），海量流式数据不可行。分位数摘要算法用固定内存维护「数据分布的压缩表示」，支持查询任意百分位，误差可控。它是监控延迟 P99、性能分析、数据倾斜诊断的基础设施。

```text
分位数估计的核心问题：
1. 精确分位数 —— 需全量排序，海量/流式不可行
2. 近似分位数 —— 固定内存压缩分布，任意百分位查询
3. 误差 —— 通常是「相对误差」或「秩误差」，可控
4. 应用 —— P99 延迟监控、性能分析、数据倾斜诊断
```

## t-digest

t-digest 是目前最流行的分位数摘要：把数据聚成「簇」（centroid），每个簇记录均值和权重（元素个数），用「簇的大小与数据密度成反比」的规则控制聚类——在分布尾部（数据稀疏、对分位数敏感）用更小的簇、在中间（数据密集）用更大的簇。这样用 O(k) 个簇逼近分布，对极端分位（P99.9）尤其准。它是 Elasticsearch、Datadog 等系统的默认分位数实现。

```text
t-digest 要点：
1. 结构 —— 聚成簇（centroid），每簇存均值 + 权重
2. 规则 —— 尾部用小簇（精细）、中间用大簇（压缩）
3. 优势 —— 对极端分位（P99/P99.9）准确，内存 O(k)
4. 可合并 —— 两个 t-digest 可合并（并集摘要）
```

```python
import random
import bisect

class TDigest:
    """简化版 t-digest（概念示意）"""
    def __init__(self, delta=100):
        self.delta = delta
        self.centroids = []   # [mean, weight]

    def add(self, x):
        # 找到最近的簇
        if not self.centroids:
            self.centroids.append([x, 1])
            return
        idx = min(range(len(self.centroids)),
                  key=lambda i: abs(self.centroids[i][0] - x))
        c = self.centroids[idx]
        # 简化：直接合并（真实 t-digest 有簇大小限制）
        w = c[1]
        c[0] = (c[0] * w + x) / (w + 1)
        c[1] = w + 1

    def quantile(self, q):
        total = sum(c[1] for c in self.centroids)
        target = q * total
        cum = 0
        for mean, w in sorted(self.centroids):
            cum += w
            if cum >= target:
                return mean
        return self.centroids[-1][0]

td = TDigest()
data = [random.expovariate(1.0) for _ in range(100000)]  # 指数分布（重尾）
for x in data:
    td.add(x)

print(f"P50 ≈ {td.quantile(0.5):.3f}（真实 ln2≈0.693）")
print(f"P95 ≈ {td.quantile(0.95):.3f}（真实 -ln(0.05)≈3.0）")
```

## KLL

KLL（Karnin-Lang-Liberty）是理论上最优的分位数摘要算法：用「分层采样」的压缩器（compactor）逐层合并数据，每层保留固定数量的采样值，层与层之间按比例下采样。它提供严格的「秩误差」保证（rank error ≤ ε·n），空间 O(1/ε · log εn)，是 Apache DataSketches 的分位数实现，误差边界可证明、比 t-digest 更理论完备。

```text
KLL 要点：
1. 结构 —— 多层压缩器，逐层下采样
2. 保证 —— 秩误差 ≤ ε·n，可证明
3. 空间 —— O(1/ε · log εn)
4. 实现 —— Apache DataSketches 标准实现
```

```python
# KLL 概念：分层压缩器（简化）
class KLLSketch:
    def __init__(self, k=200):
        self.k = k
        self.levels = []   # 每层一个排序列表

    def add(self, x):
        self.levels.append([x])
        self._compress()

    def _compress(self):
        # 层满则合并压缩（简化：只保留最近层）
        pass

    def quantile(self, q):
        all_vals = sorted(v for lvl in self.levels for v in lvl)
        if not all_vals:
            return None
        idx = int(q * (len(all_vals) - 1))
        return all_vals[idx]
```

## Greenwald-Khanna

Greenwald-Khanna（GK）是经典的分位数摘要算法：维护有序的样本元组 (v, g, Δ)，其中 g 是「到上一个样本之间的秩差」、Δ 是「误差上界」，通过合并相邻元组压缩（当 g+Δ < 2εn 时可合并）。它保证任意分位数的秩误差 ≤ ε·n，空间 O(1/ε · log(εn))，是最早的「有误差保证的分位数摘要」，也是 KLL 的理论前身。

```text
Greenwald-Khanna 要点：
1. 结构 —— 有序元组 (v, g, Δ)，v 样本值、g 秩差、Δ 误差界
2. 压缩 —— 相邻元组满足 g+Δ < 2εn 时合并
3. 保证 —— 分位数秩误差 ≤ ε·n
4. 空间 —— O(1/ε · log(εn))
```

```text
GK 元组含义：
(v_i, g_i, Δ_i) 表示：值 v_i 的真实秩在 [Σg, Σg + ΣΔ] 区间内
压缩：当 g_i + g_{i+1} + Δ_{i+1} < 2εn，合并 (v_i, v_{i+1})
```

## Quantile Sketch 分位数摘要

「分位数摘要」是这一类数据结构的统称（t-digest、KLL、GK 都是具体实现），核心是「用有界内存维护能回答任意分位数查询的分布压缩」。选型上：要极端分位准确（监控 P99）用 t-digest；要理论误差保证（可证明）用 KLL；要简单实现用 GK。工程上多数系统（ES、Prometheus、DataSketches）内置了现成实现，直接调用即可。

```text
分位数摘要选型：
1. t-digest —— 极端分位准，监控/日志分析首选
2. KLL —— 秩误差可证明，DataSketches 默认
3. GK —— 经典算法，理论前身
4. 实践 —— 直接调用 ES/Prometheus/DataSketches 内置实现
```

## Approximate Median 近似中位数

近似中位数是分位数估计的特例（q=0.5）。方法有：随机采样求中位数（简单，误差 O(1/√k)）、分层/分段近似、以及用分位数摘要（t-digest/KLL）直接查 P50。大数据里「求近似中位数」常用「分桶 + 找到中位数所在桶再插值」的方法，内存 O(桶数)。近似中位数用于「收入中位数」「响应时间中位」等场景。

```text
近似中位数要点：
1. 采样法 —— 随机抽 k 个，排序取中位，误差 O(1/√k)
2. 分桶法 —— 分桶计数，定位中位数所在桶再插值
3. 摘要法 —— t-digest/KLL 查 P50
4. 内存 —— O(k) 或 O(桶数)，远小于全量
```

```python
import random
import statistics

def approx_median_reservoir(stream, k=1000):
    pool = []
    for i, x in enumerate(stream, 1):
        if i <= k:
            pool.append(x)
        elif random.randint(1, i) <= k:
            pool[random.randint(0, k - 1)] = x
    return statistics.median(pool)

data = [random.expovariate(1.0) for _ in range(100000)]
est = approx_median_reservoir(iter(data))
print(f"近似中位数 {est:.3f}（真实 ln2≈0.693）")
```

## Streaming Percentile 流式百分位

流式百分位是「数据持续流入，实时回答当前分布的百分位」的问题。挑战是数据总量未知、不能回看、内存有限。解法就是流式分位数摘要（t-digest/KLL），每次更新 O(log k) 或摊还 O(1)，查询任意分位 O(k) 或更快。它支撑实时监控（滚动窗口的 P99 延迟）、实时风控（实时评分的分位阈值）。

```text
流式百分位要点：
1. 约束 —— 流式、总量未知、内存有限
2. 结构 —— t-digest/KLL，增量更新
3. 查询 —— 任意分位实时回答
4. 应用 —— 实时 P99 监控、滚动窗口分位
```

```python
import random
import time

# 实时监控：流式更新 t-digest，随时查 P99 延迟
class LatencyMonitor:
    def __init__(self):
        self.td = TDigest()

    def observe(self, latency_ms):
        self.td.add(latency_ms)

    def p99(self):
        return self.td.quantile(0.99)

mon = LatencyMonitor()
for _ in range(100000):
    # 模拟延迟：大部分 10ms，偶尔 500ms（慢请求）
    lat = 500 if random.random() < 0.01 else random.uniform(5, 20)
    mon.observe(lat)

print(f"P99 延迟 ≈ {mon.p99():.1f} ms（预期接近慢请求 500ms）")
```

## 应用场景实战

### 场景一：API 响应时间 P99 监控

```python
# 用 t-digest 做实时 P50/P95/P99 延迟监控
mon = LatencyMonitor()
import random
for _ in range(50000):
    mon.observe(random.expovariate(1/20))  # 平均 20ms 的延迟
print(f"P50={mon.td.quantile(0.5):.1f}ms  P95={mon.td.quantile(0.95):.1f}ms  P99={mon.td.quantile(0.99):.1f}ms")
```

### 场景二：数据倾斜诊断（分位数看分布）

```python
# 用分位数诊断某列数据分布是否倾斜
values = [1] * 90000 + [1000] * 9000 + [100000] * 1000  # 严重倾斜
td = TDigest()
for v in values:
    td.add(v)
print(f"P50={td.quantile(0.5)}  P90={td.quantile(0.9)}  P99={td.quantile(0.99)}  P100={td.quantile(1.0)}")
# P50=1 而 P99=100000，说明严重倾斜，需做数据倾斜处理
```

## 最佳实践与踩坑记录

### 最佳实践

1. 监控延迟分位用 t-digest（尾部准确），要可证明误差用 KLL
2. 精确分位只需少量数据（<10 万）时直接排序，别上摘要
3. 摘要内存按「可接受误差」定，别盲目加大
4. 分布式聚合用摘要的可合并性（逐分区摘要再合并）
5. 关注「相对误差」还是「秩误差」，按业务选结构

### 踩坑记录

```text
坑 1：用平均值代替分位数做延迟监控
结论：少数慢请求被平均淹没，感知不到性能问题。
原因：延迟是重尾分布，均值对极端值不敏感。
解法：监控 P95/P99，用分位数摘要，别只看均值。

坑 2：小数据量也上分位数摘要
结论：误差比精确排序还大，纯属多余。
原因：摘要算法有误差，数据少时精确排序更快更准。
解法：数据量小（<10 万）直接排序求分位，海量才用摘要。

坑 3：分位数摘要簇数太少
结论：极端分位（P99.9）误差大。
原因：簇数少，尾部稀疏区域逼近不足。
解法：按误差需求设簇数/参数，尾部敏感场景加大。

坑 4：误以为分位数摘要是精确的
结论：业务把 P99 当精确值用，出问题。
原因：摘要是近似，有秩误差或相对误差。
解法：明确误差边界，关键决策留裕量。

坑 5：合并分位数摘要用错方式
结论：合并后分位严重失真。
原因：不同摘要合并有特定语义（t-digest 合并簇、KLL 合并层），不能简单平均。
解法：用摘要自带的可合并操作，别自己拼。
```

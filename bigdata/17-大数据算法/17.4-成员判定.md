## 概述

成员判定（Membership）回答「元素是否在集合里」的问题，是缓存穿透防护、去重、黑名单、爬虫判重的基础。精确判定要存全部元素（O(n) 内存），海量场景不可行。概率型成员判定结构用极小内存给出「可能在 / 一定不在」的答案——允许假阳性（误报存在）、绝不假阴性（不漏报不存在）。代表结构是 Bloom Filter 及其变体（Counting Bloom、Cuckoo、Quotient、XOR）。

```text
成员判定的核心权衡：
1. 精确集合 —— O(n) 内存，海量不可行
2. Bloom Filter —— O(n) 位（比精确省一个数量级），允许假阳性
3. 无假阴性 —— 说不存在就一定不存在，说存在可能误报
4. 应用 —— 缓存穿透、去重、黑名单、爬虫判重
```

## Bloom Filter 布隆过滤器

Bloom Filter 是最经典的成员判定结构：m 位的位数组 + k 个哈希函数。插入元素时，把它哈希到 k 个位置并置 1；查询时检查这 k 个位置是否都为 1，有一个 0 就「一定不存在」，全 1 则「可能存在」（可能假阳性）。空间 O(m)，假阳性率 ≈ (1-e^(-kn/m))^k，由位数组大小和哈希函数个数决定。

```text
Bloom Filter 要点：
1. 结构 —— m 位位数组 + k 个哈希函数
2. 插入 —— k 个哈希位置置 1
3. 查询 —— k 个位置全 1 才「可能存在」，有 0 则「一定不存在」
4. 假阳性率 —— 由 m/n（每位元素数）和 k 决定
5. 无假阴性 —— 说不存在一定正确
6. 不支持删除 —— 删一个元素会误删共享位的其他元素
```

```python
import hashlib

class BloomFilter:
    def __init__(self, n, p=0.01):
        # n 预计元素数，p 目标假阳性率
        import math
        self.m = int(-n * math.log(p) / (math.log(2) ** 2))  # 位数组大小
        self.k = int(self.m / n * math.log(2)) + 1           # 哈希函数个数
        self.bits = [0] * self.m

    def _hashes(self, x):
        for i in range(self.k):
            h = int(hashlib.md5(f"{i}:{x}".encode()).hexdigest(), 16)
            yield h % self.m

    def add(self, x):
        for pos in self._hashes(x):
            self.bits[pos] = 1

    def contains(self, x):
        return all(self.bits[pos] for pos in self._hashes(x))

bf = BloomFilter(n=10000, p=0.01)
for i in range(10000):
    bf.add(f"item_{i}")

# 存在的元素一定命中，不存在的可能误报
print("存在的元素命中:", bf.contains("item_42"))
fp = sum(1 for i in range(10000, 20000) if bf.contains(f"item_{i}"))
print(f"10000 个不存在的元素里误报 {fp} 个（假阳性率约 {fp/10000:.2%}）")
```

## Counting Bloom Filter 计数布隆

Counting Bloom Filter（CBF）解决 Bloom Filter「不能删除」的问题：把每个位换成一个小计数器（如 4 位），插入时对应计数器 +1，删除时 -1。代价是空间放大（每位变多位的计数器）。CBF 用于「元素会动态增删」的场景（如缓存键的加入和过期移除）。计数器位数要够（4 位最大 15），否则溢出导致假阴性。

```text
Counting Bloom Filter 要点：
1. 改进 —— 位数组 → 计数器数组，支持删除
2. 插入/删除 —— 对应计数器 +1/-1
3. 代价 —— 空间放大（每位 4 位计数器 = 4 倍）
4. 风险 —— 计数器溢出（超过最大计数值）导致假阴性
```

```python
class CountingBloomFilter:
    def __init__(self, n, p=0.01, counter_bits=4):
        import math
        self.m = int(-n * math.log(p) / (math.log(2) ** 2))
        self.k = int(self.m / n * math.log(2)) + 1
        self.counters = [0] * self.m

    def _hashes(self, x):
        for i in range(self.k):
            h = int(hashlib.md5(f"{i}:{x}".encode()).hexdigest(), 16)
            yield h % self.m

    def add(self, x):
        for pos in self._hashes(x):
            self.counters[pos] += 1

    def remove(self, x):
        for pos in self._hashes(x):
            if self.counters[pos] > 0:
                self.counters[pos] -= 1

    def contains(self, x):
        return all(self.counters[pos] > 0 for pos in self._hashes(x))

cbf = CountingBloomFilter(n=10000)
cbf.add("apple")
cbf.add("apple")
print("删除前:", cbf.contains("apple"))
cbf.remove("apple")
print("删一次后:", cbf.contains("apple"))   # 还有一次，仍在
cbf.remove("apple")
print("删两次后:", cbf.contains("apple"))   # 已删，不在
```

## Cuckoo Filter 布谷鸟过滤器

Cuckoo Filter 是支持删除、且空间效率优于 CBF 的结构：用「布谷鸟哈希」——每个元素有两个候选桶（由两个哈希函数定位），插入时若两桶都满则「踢出」一个旧元素（像布谷鸟把别的鸟蛋踢出巢），被踢的重新找自己的另一个桶，迭代直到稳定。每个桶存「指纹」（元素的短哈希），空间比 Bloom Filter 更省（尤其低假阳性时），且支持删除和计数。

```text
Cuckoo Filter 要点：
1. 结构 —— 桶数组，每桶存若干指纹（短哈希）
2. 插入 —— 两个候选桶，满了踢出一个旧指纹（布谷鸟置换）
3. 查询 —— 检查两个候选桶是否含指纹
4. 删除 —— 移除指纹即可（天然支持）
5. 优势 —— 低假阳性时空间优于 Bloom，支持删除
```

```python
import hashlib

class CuckooFilter:
    def __init__(self, num_buckets=1000, bucket_size=4):
        self.buckets = [[] for _ in range(num_buckets)]
        self.bsize = bucket_size
        self.nb = num_buckets

    def _fp(self, x):
        return int(hashlib.md5(x.encode()).hexdigest()[:8], 16) & 0xFFFF  # 16 位指纹

    def _idx(self, x, fp):
        h = int(hashlib.md5(x.encode()).hexdigest(), 16)
        i1 = h % self.nb
        i2 = (i1 ^ (fp * 0x9E3779B9)) % self.nb   # 用指纹算第二个桶
        return i1, i2

    def insert(self, x, max_kicks=500):
        fp = self._fp(x)
        i1, i2 = self._idx(x, fp)
        for bucket in (self.buckets[i1], self.buckets[i2]):
            if len(bucket) < self.bsize:
                bucket.append(fp)
                return True
        # 两桶都满，踢出一个
        i = i1
        for _ in range(max_kicks):
            bucket = self.buckets[i]
            victim = bucket[random.randint(0, len(bucket) - 1)]
            bucket[bucket.index(victim)] = fp
            fp = victim
            i = (i ^ (fp * 0x9E3779B9)) % self.nb
            if len(self.buckets[i]) < self.bsize:
                self.buckets[i].append(fp)
                return True
        return False   # 踢了太多轮，插入失败（需扩容）

    def contains(self, x):
        fp = self._fp(x)
        i1, i2 = self._idx(x, fp)
        return fp in self.buckets[i1] or fp in self.buckets[i2]

cf = CuckooFilter(num_buckets=3000)
for i in range(8000):
    cf.insert(f"item_{i}")
print("命中:", cf.contains("item_100"))
print("不存在元素误报数:", sum(1 for i in range(8000, 12000) if cf.contains(f"item_{i}")))
```

## Quotient Filter 商过滤器

Quotient Filter（QF）是另一种支持删除的成员判定结构：把指纹哈希拆成「商」（q 位，定位槽）和「余数」（r 位，存在槽里），用开放寻址解决冲突。它比 Bloom Filter 更好的「缓存局部性」（连续内存、顺序访问），且支持合并两个 QF、动态扩容。适合「需要高缓存命中率、频繁插入删除」的场景。

```text
Quotient Filter 要点：
1. 结构 —— 哈希拆「商」（定位槽）+「余数」（槽内存储）
2. 冲突 —— 开放寻址（线性探测），用元数据位标记
3. 优势 —— 缓存局部性好、支持删除、支持合并
4. 对比 —— 比 Bloom 顺序访问更友好，空间相当
```

```text
Quotient Filter 结构（概念）：
哈希值 h = 商(q 位) + 余数(r 位)
槽数组：每个槽存 [余数, is_occupied, is_continuation, is_shifted]
查询：定位商对应的槽，沿 continuation 链找匹配余数
```

## XOR Filter

XOR Filter 是「只读、不可变」场景（集合构建后不再改）下空间最省的成员判定结构：它比 Bloom Filter 更省空间（接近理论下限），但一旦构建就不能再插入，只支持查询。原理是把每个元素的指纹 XOR 进 3 个哈希槽，查询时 XOR 这三个槽恢复指纹比对。适合「静态黑名单、静态字典」这类一次性构建、大量查询的场景。

```text
XOR Filter 要点：
1. 场景 —— 只读、构建一次查询多次的静态集合
2. 原理 —— 指纹 XOR 进 3 个槽，查询 XOR 恢复比对
3. 优势 —— 空间比 Bloom Filter 更省（接近最优）
4. 限制 —— 不可增删，改集合要重建
```

```python
# XOR Filter 概念示意（简化版）
import hashlib

class XORFilter:
    def __init__(self, size):
        self.size = size
        self.table = [0] * size

    def build(self, items):
        for x in items:
            fp = int(hashlib.md5(x.encode()).hexdigest()[:8], 16)
            # 把指纹 XOR 进 3 个哈希槽（简化：单槽演示）
            self.table[fp % self.size] ^= fp

    def contains(self, x):
        fp = int(hashlib.md5(x.encode()).hexdigest()[:8], 16)
        return self.table[fp % self.size] == fp   # 简化：不严谨，仅示意 XOR 思想

xf = XORFilter(4096)
xf.build([f"item_{i}" for i in range(1000)])
print("XOR Filter 命中:", xf.contains("item_5"))
```

## 应用场景实战

### 场景一：缓存穿透防护

```python
# 用 Bloom Filter 挡住「查不存在的数据」击穿缓存打爆数据库
class CacheWithBloom:
    def __init__(self, cache, bloom):
        self.cache = cache
        self.bloom = bloom

    def get(self, key):
        # 布隆说「一定不存在」，直接返回 None，不打数据库
        if not self.bloom.contains(key):
            return None
        if key in self.cache:
            return self.cache[key]
        # 布隆说「可能存在」，查数据库
        value = self.query_db(key)
        if value is not None:
            self.cache[key] = value
        return value

    def query_db(self, key):
        return {"id": key} if key.startswith("real") else None

# 预先把所有存在的 key 灌进布隆
bf = BloomFilter(n=100000)
for i in range(100000):
    bf.add(f"real_{i}")

cache_bloom = CacheWithBloom({}, bf)
print("不存在的 key 被拦截:", cache_bloom.get("not_exist") is None)
print("存在的 key 查询:", cache_bloom.get("real_42"))
```

### 场景二：URL 去重（爬虫判重）

```python
# 爬虫用 Bloom Filter 判重，避免重复抓取
seen = BloomFilter(n=10000000, p=0.001)
def crawl(url):
    if seen.contains(url):
        return "已抓过，跳过"
    seen.add(url)
    return f"抓取 {url}"

print(crawl("https://example.com/page1"))
print(crawl("https://example.com/page1"))   # 重复，跳过
```

## 最佳实践与踩坑记录

### 最佳实践

1. 预计元素数 n 和假阳性率 p 定好后算 m 和 k，别拍脑袋
2. 只读静态集合用 XOR Filter（最省空间）
3. 需要删除用 Counting Bloom 或 Cuckoo Filter
4. 低假阳性（<1%）时 Cuckoo Filter 空间优于 Bloom
5. 缓存局部性敏感用 Quotient Filter
6. 哈希函数个数 k = (m/n)·ln2，别随意加多

### 踩坑记录

```text
坑 1：Bloom Filter 假阳性导致业务错误
结论：把「可能存在」当「一定存在」，误拦截了正常请求。
原因：忽略了布隆的假阳性特性，误报率没控制好。
解法：按可接受误报率设计 p，关键业务对「可能命中」做二次精确校验。

坑 2：用 Bloom Filter 做删除
结论：删一个元素误删了共享位的其他元素，导致假阴性。
原因：标准 Bloom 位共享，删除会破坏其他元素。
解法：需要删除用 Counting Bloom / Cuckoo Filter。

坑 3：预计元素数 n 低估，布隆塞满
结论：假阳性率远超设计值，查询大量误报。
原因：实际元素数远超 n，位数组过载。
解法：n 留余量（预估 1.5~2 倍），或用可扩展布隆（Scalable Bloom）。

坑 4：Cuckoo Filter 插入踢出死循环
结论：插入失败或踢出次数过多。
原因：表接近满时布谷鸟置换可能陷入循环。
解法：负载率控制在 80% 以下，满了扩容重建。

坑 5：哈希函数质量差导致聚集
结论：假阳性率偏离理论值。
原因：哈希分布不均，某些位被频繁置 1。
解法：用 MurmurHash3/xxHash 等高质量哈希。
```

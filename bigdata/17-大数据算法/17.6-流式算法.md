## 概述

流式算法（Streaming Algorithms）是在「数据以流的形式持续到达、只能单遍扫描、无法回看、内存远小于数据总量」的约束下做计算的算法。它不存全量数据，只维护一个「有界的摘要结构（sketch/synopsis）」，用这个摘要回答聚合、计数、采样等问题。核心指标是「近似精度」与「内存/时间的权衡」——流式算法的目标是用亚线性（sublinear，通常是 O(log N) 或 O(1/ε)）空间逼近需要全量数据才能精确计算的结果。

```text
流式算法的核心约束与目标：
1. 单遍 —— 数据只扫一遍，不能回看历史
2. 有界内存 —— 摘要结构 O(log N) 或 O(1/ε)，远小于 N
3. 在线 —— 每个元素到达时 O(1) 或 O(log N) 更新
4. 近似 —— 用 ε 控制误差，用 (1-δ) 控制置信度
```

```text
流式算法 vs 批处理算法：
- 批处理：能随机访问、可多遍扫描、内存可装下数据
- 流式：单遍、不能回看、内存固定，只能用摘要近似
- 代表：滑动窗口、指数直方图、时间衰减、在线聚合、近似连接、流式采样
```

## Sliding Window

滑动窗口在流上维护「最近 N 个元素」（按个数或按时间）的视图，并在这个窗口上做聚合。它解决「我只关心最近一段数据」的需求，同时把内存限制在 O(N)（或更小）。实现上有两类：固定大小窗口（count-based，最近 N 条）与时间窗口（time-based，最近 T 秒/分钟）。聚合的增量更新是关键——维护一个「可逆」的聚合量（如 sum/count），新元素进来加、旧元素滑出减，摊还 O(1)，避免每次滑窗 O(N) 重算。

```text
滑动窗口要点：
1. 窗口 —— 最近 N 个元素（计数窗口）或最近 T 时间（时间窗口）
2. 增量更新 —— sum/count 可逆，滑入加、滑出减，O(1) 摊还
3. 不可逆聚合 —— max/min/分位数需单调队列或摘要结构
4. 内存 —— O(窗口大小)，有界可控
```

```python
from collections import deque

class SlidingWindowSum:
    """计数窗口：维护最近 N 个元素的和，O(1) 摊还更新"""
    def __init__(self, n):
        self.n = n
        self.window = deque()
        self.total = 0

    def add(self, x):
        self.window.append(x)
        self.total += x
        if len(self.window) > self.n:      # 滑出最旧元素
            self.total -= self.window.popleft()
        return self.total

sw = SlidingWindowSum(3)
for x in [1, 2, 3, 4, 5]:
    print(f"加入 {x} 后窗口和 = {sw.add(x)}")   # 1,3,6,9,12
```

```python
from collections import deque

class SlidingWindowMax:
    """单调队列维护窗口最大值：队首始终是当前窗口最大值的下标"""
    def __init__(self, n):
        self.n = n
        self.q = deque()        # 存下标，值单调递减
        self.arr = []

    def add(self, x):
        self.arr.append(x)
        i = len(self.arr) - 1
        while self.q and self.arr[self.q[-1]] <= x:
            self.q.pop()                        # 淘汰不可能成为最大值的旧元素
        self.q.append(i)
        # 淘汰滑出窗口的下标
        while self.q and self.q[0] <= i - self.n:
            self.q.popleft()
        return self.arr[self.q[0]]              # 队首即窗口最大值

mx = SlidingWindowMax(3)
for x in [1, 3, -1, -3, 5, 3]:
    print(f"加入 {x} 后窗口最大值 = {mx.add(x)}")   # 1,3,3,3,5,5
```

## Exponential Histogram

指数直方图（Exponential Histogram / DGIM 算法）在滑动窗口上近似统计「1 的个数」，用 O((1/ε)·log² N) 空间给出 (1±ε) 误差的估计。核心思想：把窗口里连续的 1 合并成「桶」，桶的大小（桶内 1 的个数）只能取 1, 2, 4, 8, … 的 2 的幂；同一大小的桶最多保留 (1/ε)+1 个，超了就两两合并升级成更大桶。统计时「各桶大小之和 + 最老桶的一半」就是估计值。它把精确计数所需的 O(N) 空间压到 O(log² N)，是「用误差换内存」的典型。

```text
指数直方图要点：
1. 目标 —— 滑动窗口内 1 的个数，误差 (1±ε)
2. 桶大小 —— 2 的幂（1,2,4,8...），同大小桶最多 (1/ε)+1 个
3. 合并 —— 超量同大小桶两两合并升级，保持桶数 O((1/ε)log N)
4. 估计 —— 桶大小和 + 最老桶一半（补偿被截断的桶）
5. 空间 —— O((1/ε)·log² N)，远小于精确的 O(N)
```

```python
from collections import deque, Counter

class ExponentialHistogram:
    """近似统计滑动窗口内 1 的个数（DGIM 算法）"""
    def __init__(self, window_size, eps=0.5):
        self.N = window_size
        self.k = int(1 / eps) + 1          # 同大小桶的上限
        self.buckets = deque()             # 每个桶 (时间戳, 桶大小)

    def add(self, bit):
        if bit == 1:
            self.buckets.append((len(self.buckets), 1))
            self._merge()
        while self.buckets and len(self.buckets) - self.buckets[0][0] >= self.N:
            self.buckets.popleft()         # 淘汰滑出窗口的桶

    def _merge(self):
        cnt = Counter(s for _, s in self.buckets)
        for s in sorted(cnt):              # 同大小超 k 个则两两合并升级
            while cnt[s] > self.k:
                cnt[s] -= 2
                cnt[2 * s] += 1
        self.buckets = deque((0, s) for s in sorted(cnt) for _ in range(cnt[s]))

    def count(self):
        if not self.buckets:
            return 0
        return sum(s for _, s in self.buckets) - self.buckets[0][1] // 2

# 模拟：窗口 20 个元素，统计其中 1 的个数
import random
eh = ExponentialHistogram(window_size=20, eps=0.5)
stream = [1 if random.random() < 0.6 else 0 for _ in range(50)]
exact_ones = sum(stream[-20:])
for b in stream:
    eh.add(b)
print(f"指数直方图估计 {eh.count()}，精确值 {exact_ones}（误差可控）")
```

## Time Decay

时间衰减给每个数据点按「距离当前时间的远近」加权：越新的数据权重越高、越旧的数据权重越低，衰减函数常取指数衰减 w(t) = λ^Δt（0<λ<1）或 (1-α)^Δt。它用于「近期行为更能代表当前状态」的场景（热门排行、趋势、异常检测、推荐）。实现上，很多时间衰减统计量（如衰减和、衰减计数）可以用「上次时间戳 + 乘法缩放」在 O(1) 内增量维护，无需重算历史。

```text
时间衰减要点：
1. 权重 —— 越新权重越高，w(Δt) = λ^Δt 或 (1-α)^Δt
2. 半衰期 —— 权重降到一半所需时间，t½ = ln(0.5)/ln(λ)
3. 增量维护 —— 记录上次更新时间戳，乘 λ^Δt 缩放旧值，O(1)
4. 用途 —— 热门排行、趋势、异常检测、在线学习
```

```python
class ExponentialDecaySum:
    """指数衰减和：S = Σ x_i · λ^(t_now - t_i)，O(1) 增量更新"""
    def __init__(self, lam=0.9):
        self.lam = lam
        self.S = 0.0
        self.last_t = 0

    def add(self, x, t):
        dt = t - self.last_t
        self.S = self.S * (self.lam ** dt) + x   # 旧值整体衰减 + 新值
        self.last_t = t
        return self.S

eds = ExponentialDecaySum(lam=0.5)   # 半衰期 1 个时间单位
for t, x in [(1, 10), (2, 20), (3, 30)]:
    print(f"t={t} 衰减和 = {eds.add(x, t):.1f}")
# 输出：10.0, 25.0, 42.5 —— 越老的值衰减越狠
```

## Online Aggregation

在线聚合在数据流式到达时「增量」维护聚合统计量，不必存储全部数据。求和/计数/均值可逆、易增量；方差/标准差用 Welford 算法在线更新；分位数用 t-digest / q-digest 摘要近似；直方图用等宽/等频桶在线合并。这类算法是实时指标（实时大盘、实时 QPS、实时 P99 延迟）的基石，内存 O(1) 或 O(摘要大小)。

```text
在线聚合要点：
1. 可逆聚合 —— sum/count/mean 增量更新，O(1)
2. 方差 —— Welford 算法，数值稳定、单遍在线
3. 分位数 —— t-digest / q-digest 近似摘要，O(桶数)
4. 用途 —— 实时指标大盘、实时监控告警
```

```python
class Welford:
    """Welford 算法：在线维护均值和方差（数值稳定）"""
    def __init__(self):
        self.n = 0
        self.mean = 0.0
        self.M2 = 0.0        # 平方差累计量

    def add(self, x):
        self.n += 1
        delta = x - self.mean
        self.mean += delta / self.n
        self.M2 += delta * (x - self.mean)

    def variance(self):
        return self.M2 / self.n if self.n > 0 else 0.0

w = Welford()
for x in [2, 4, 4, 4, 5, 5, 7, 9]:
    w.add(x)
print(f"在线均值 {w.mean:.2f}，方差 {w.variance():.2f}（真实 mean=5, var=4）")
```

```python
# 在线近似分位数（t-digest 简化示意：用等宽桶压缩）
class ApproxQuantile:
    def __init__(self, buckets=100):
        self.values = []
        self.buckets = buckets

    def add(self, x):
        self.values.append(x)
        if len(self.values) > self.buckets * 10:
            # 压缩：只保留均匀抽取的代表点
            step = len(self.values) // self.buckets
            self.values = sorted(self.values)[::step]

    def quantile(self, q):
        s = sorted(self.values)
        idx = int(q * (len(s) - 1))
        return s[idx]

aq = ApproxQuantile()
import random
for _ in range(100000):
    aq.add(random.expovariate(1.0))
print(f"近似 P99 = {aq.quantile(0.99):.2f}（真实 P99 ≈ 4.6）")
```

## Approximate Join

近似连接解决「两个大数据流无法全部缓存、精确 join 代价过高」的问题：用采样或 sketch（Bloom Filter、Count-Min Sketch）近似估计「连接结果的大小/基数」，或做「滑动窗口 join」只连接时间上接近的记录。典型问题：广告曝光流与点击流 join，精确 join 要缓存全部记录，近似 join 用 Bloom Filter 判断「曝光是否可能有点击」，把内存降到 O(m) 位。流式场景还有「基于时间窗口的等值连接」，只保留窗口内的记录做匹配。

```text
近似连接要点：
1. 动机 —— 两流无法全缓存，精确 join 内存/时间不可行
2. 方法 —— Bloom Filter 近似成员判定、Count-Min 估计 join 基数
3. 窗口 join —— 只匹配时间窗口内的记录对
4. 误差 —— 以可接受的误报/漏报换内存
```

```python
import random
import hashlib

class BloomFilter:
    def __init__(self, m, k):
        self.m = m
        self.k = k
        self.bits = [0] * m

    def _hashes(self, x):
        h = hashlib.md5(str(x).encode()).digest()
        for i in range(self.k):
            yield int.from_bytes(h[i*2:i*2+2], 'big') % self.m

    def add(self, x):
        for i in self._hashes(x):
            self.bits[i] = 1

    def maybe_contains(self, x):
        return all(self.bits[i] for i in self._hashes(x))

# 曝光流 -> Bloom Filter；点击流 -> 查 Bloom 近似 join
bf = BloomFilter(m=100000, k=3)
exposures = [f"ad_{random.randint(0, 10000)}" for _ in range(50000)]
for e in exposures:
    bf.add(e)

clicks = [f"ad_{random.randint(0, 10000)}" for _ in range(10000)]
matches = sum(1 for c in clicks if bf.maybe_contains(c))
print(f"近似 join 命中 {matches} 次点击（Bloom Filter 内存 {bf.m//8} 字节）")
```

## Stream Sampling

流式采样在「总量未知、单遍」的数据流上抽取有代表性的样本，已在数据采样一节详述蓄水池采样。这里的重点是流式场景下的变体：加权蓄水池（A-ES 算法，权重大的元素更可能被保留）、滑动窗口采样（只保留最近 N 个再抽）、以及「偏差校正」——当样本需要代表整个流而非当前窗口时，用时间衰减权重校正。它们分别服务「等概率抽样」「重要性抽样」「近期关注」三类流式需求。

```text
流式采样要点：
1. 等概率 —— 蓄水池采样，每个元素最终被选概率 k/N
2. 加权 —— A-ES 加权蓄水池，权重大者更可能保留
3. 滑动窗口 —— 只对最近 N 个元素抽样（关注近期）
4. 偏差校正 —— 时间衰减权重，让样本贴合当前分布
```

```python
import random

def weighted_reservoir(stream, k):
    """A-ES 加权蓄水池：元素带权重 w，最终保留概率 ∝ w"""
    import heapq
    heap = []
    for item, w in stream:
        if w <= 0:
            continue
        key = random.random() ** (1.0 / w)   # 指数技巧
        if len(heap) < k:
            heapq.heappush(heap, (key, item))
        elif key > heap[0][0]:
            heapq.heapreplace(heap, (key, item))
    return [item for _, item in heap]

stream = ((f"e{i}", 1 if i % 100 != 0 else 1000) for i in range(1000))
sample = weighted_reservoir(stream, 10)
print("加权蓄水池采样结果:", sample[:5], "...（权重大的更可能被保留）")
```

## 应用场景实战

### 场景一：实时滑动窗口 QPS 与峰值监控

```python
from collections import deque
import time

class SlidingQPS:
    """维护最近 60 秒的请求计数，实时 QPS 与峰值"""
    def __init__(self, window_seconds=60):
        self.window = window_seconds
        self.q = deque()          # 存 (时间戳, 数量)
        self.total = 0

    def hit(self, ts=None):
        ts = ts or time.time()
        self.q.append((ts, 1))
        self.total += 1
        # 淘汰 60 秒前的计数
        cutoff = ts - self.window
        while self.q and self.q[0][0] < cutoff:
            self.total -= self.q.popleft()[1]
        return self.total / self.window

qps = SlidingQPS(window_seconds=60)
base = time.time()
for i in range(1000):
    qps.hit(base + i * 0.05)      # 每 50ms 一个请求
print(f"实时 QPS ≈ {qps.hit(base + 50):.1f}（真实约 20）")
```

### 场景二：时间衰减热门商品排行

```python
class DecayingCounter:
    """带时间衰减的商品热度：热度 = Σ λ^(t - t_i)，O(1) 更新"""
    def __init__(self, lam=0.99):
        self.lam = lam
        self.heat = {}
        self.last = {}

    def view(self, item, t):
        if item in self.heat:
            dt = t - self.last[item]
            self.heat[item] = self.heat[item] * (self.lam ** dt) + 1
        else:
            self.heat[item] = 1
        self.last[item] = t

    def top(self, k):
        return sorted(self.heat.items(), key=lambda x: -x[1])[:k]

dc = DecayingCounter(lam=0.9)
# 商品 A 早期火爆、商品 B 近期火爆
for t in range(10):
    dc.view("A", t)
for t in range(9, 12):
    dc.view("B", t)
print("热度排行:", dc.top(2))    # B 因更近期而排前，体现时间衰减
```

## 最佳实践与踩坑记录

### 最佳实践

1. 关心最近 N 条/最近 T 秒用滑动窗口，聚合量选可逆的（sum/count）以便 O(1) 增量更新
2. 窗口最大值/最小值用单调队列，别每窗重扫
3. 需要在超大窗口近似计数用指数直方图（DGIM），误差 ε 控制内存
4. 强调近期行为的场景用时间衰减，半衰期按业务含义设定
5. 实时均值和方差用 Welford 算法，数值稳定、单遍在线
6. 流式 join 优先用 Bloom Filter 近似成员判定，内存比精确 join 低几个数量级

### 踩坑记录

```text
坑 1：窗口聚合每次滑窗都重算 O(N)
结论：QPS 计算在高峰时 CPU 飙升、延迟雪崩。
原因：没做增量更新，每个元素到达都全量扫窗口。
解法：维护可逆聚合量，滑入加、滑出减，摊还 O(1)。

坑 2：用不可逆聚合量做增量窗口
结论：窗口 max/min 的「减旧值」逻辑错误，结果不对。
原因：max/min 不可逆，旧最大值滑出后无法简单「减」出来。
解法：用单调队列/双端队列维护窗口 max/min，或换可逆聚合。

坑 3：时间衰减忘了缩放旧值
结论：衰减和不随时间衰减，历史值永远全权重。
原因：只加新值、没对旧累计量乘 λ^Δt。
解法：每次更新先乘 λ^(Δt) 缩放旧值再累加新值。

坑 4：指数直方图桶合并丢了最老桶的误差补偿
结论：估计值系统性偏低。
原因：最老桶可能被窗口截断，直接求和会低估。
解法：减去最老桶一半（或按 DGIM 规则做误差补偿）。

坑 5：Bloom Filter 近似 join 没评估误报影响
结论：业务把「可能命中」当「精确命中」，误报放大错误。
原因：Bloom Filter 有假阳性，小 m 时误报率高。
解法：按误报率 p 选 m 和 k（m = -n·ln p/(ln2)²），并对结果标注「近似」。
```

## 概述

外存算法（External Memory Algorithms）是「数据大到内存装不下、必须放在磁盘上」时的高效算法。它的核心指标不是 CPU 时间，而是 I/O 次数——磁盘一次随机读写（约 10ms）比内存访问慢 5~6 个数量级，所以外存算法的设计目标是把 I/O 降到最少，用「按块（block/page）读写」「顺序扫描」「多路归并」等手段摊薄 I/O 成本。数据库的 B+Tree、LSM Tree、SSTable，以及大数据的 External Sort，都是外存算法的经典形态。

```text
外存算法的 I/O 模型：
1. 内存 —— 能装 M 个元素（主存大小）
2. 块 —— 磁盘按 B 个元素一块读写（块大小）
3. I/O 复杂度 —— 一次块读写计一次 I/O，这是外存算法的复杂度单位
4. 目标 —— 顺序读（快）多、随机读（慢）少，I/O 次数最小化
```

```text
内存算法关注 CPU 时间（O(N log N) 排序），外存算法关注 I/O 次数
（O(N/B · log_{M/B}(N/B)) 次 I/O），单次 I/O ≈ 10ms 是主要成本。
```

## External Sort

外排序（External Sort）在内存装不下全部数据时排序：用「多路归并」把「内存内排序 + 磁盘间归并」结合。经典两步：① 分块读入内存排序（内排序），每块写回磁盘成为「有序段（run）」；② 多路归并——用堆/败者树从每个 run 读一块进内存，每次取最小输出，run 用完再读下一块。I/O 复杂度 O(N/B · log_{M/B}(N/B))。大数据里的 MapReduce Shuffle 排序、数据库 ORDER BY 大结果集都靠它。

```text
外排序要点：
1. 阶段一 —— 分块读入内存内排序，写回有序 run
2. 阶段二 —— 多路归并（堆/败者树），逐个 run 读块合并
3. 内存分配 —— 尽量多路归并，减少归并轮数（log 的底数）
4. I/O —— O(N/B · log_{M/B}(N/B)) 次块读写
```

```python
import heapq

def external_sort(blocks):
    """blocks: 分块读入的数据；模拟 run 生成 + 多路归并"""
    runs = [sorted(b) for b in blocks]           # 阶段一：每块内排序成 run
    heap = [(run[0], i, 0) for i, run in enumerate(runs) if run]
    heapq.heapify(heap)                          # 阶段二：多路归并
    result = []
    while heap:
        val, i, pos = heapq.heappop(heap)
        result.append(val)
        if pos + 1 < len(runs[i]):
            heapq.heappush(heap, (runs[i][pos+1], i, pos+1))
    return result

data = [[5, 1, 9, 3], [8, 2, 7, 4], [6, 0, 11, 10]]
print("外排序结果:", external_sort(data))
```

## External Hashing

外哈希（External Hashing）在内存装不下哈希表时，用「多轮划分」把数据按哈希桶分到磁盘文件，再逐个桶进内存处理。典型是「哈希连接」的分区阶段：把两个大关系按连接键哈希分到 k 个桶文件，保证「同键必同桶」，然后每对桶在内存里 join。核心思想是「用哈希把大问题切成能在内存解决的小问题」。k 的选择要保证每桶能装进内存，否则要递归再哈希。

```text
外哈希要点：
1. 划分 —— 按哈希函数把数据分到 k 个桶（磁盘文件）
2. 性质 —— 相同键一定进同一个桶（哈希一致性）
3. 分治 —— 每桶独立进内存处理，桶间无依赖
4. 递归 —— 桶太大装不下内存时，对该桶递归再哈希
```

```python
import hashlib

def external_hash_partition(records, num_buckets):
    """把记录按哈希键划分到 num_buckets 个桶（模拟磁盘分区）"""
    buckets = [[] for _ in range(num_buckets)]
    for key, val in records:
        h = int(hashlib.md5(str(key).encode()).hexdigest(), 16)
        buckets[h % num_buckets].append((key, val))
    return buckets

records = [(f"k{i % 20}", i) for i in range(1000)]
buckets = external_hash_partition(records, 8)
print("各桶记录数:", [len(b) for b in buckets])
for b in buckets:
    keys = {k for k, _ in b}
    assert all(k in keys for k, _ in b)
print("同键同桶性质成立 ✓")
```

## External Merge

外归并（External Merge）是外排序第二阶段「多路归并」的泛化，也指「合并多个磁盘上的有序文件/段」的通用操作。核心是用「败者树」或「k 路最小堆」在 k 个有序输入里反复取最小元素输出，每路用一个内存缓冲区（input buffer）批量读块、一个输出缓冲区（output buffer）批量写块，避免逐元素 I/O。它是 External Sort 的归并阶段，也是 LSM Tree Compaction、数据库归并排序 join 的基础原语。

```text
外归并要点：
1. 输入 —— k 个有序 run/文件
2. 结构 —— k 路堆或败者树，每次取全局最小
3. 缓冲 —— 每路 input buffer + 全局 output buffer，批量 I/O
4. 复杂度 —— O(N/B) 次 I/O（每块读写一次）
```

```python
import heapq

def external_merge(sorted_runs, block=3):
    """多路归并 k 个有序 run，按块输出（模拟 output buffer）"""
    heap = [(run[0], i, 0) for i, run in enumerate(sorted_runs) if run]
    heapq.heapify(heap)
    result, buffer = [], []
    while heap:
        val, i, pos = heapq.heappop(heap)
        buffer.append(val)
        if len(buffer) == block:          # 输出缓冲满，写块
            result.extend(buffer)
            buffer = []
        if pos + 1 < len(sorted_runs[i]):
            heapq.heappush(heap, (sorted_runs[i][pos+1], i, pos+1))
    return result + buffer

runs = [[1, 4, 7], [2, 5, 8], [3, 6, 9]]
print("多路归并结果:", external_merge(runs))
```

## B-Tree

B 树是多叉平衡搜索树，每个节点存多个键（最多 2t-1 个）和多个子指针（最多 2t 个），所有叶子在同一深度。它专为磁盘设计：一个节点正好一个磁盘块（页），一次 I/O 读入一个节点，节点内多键用二分查找，扇出大（数百上千），树高极低（3~4 层就能索引十亿条记录），I/O 次数 = 树高。插入删除通过「节点分裂/合并」保持平衡，是数据库索引、文件系统目录的经典结构。

```text
B 树要点：
1. 节点 —— 一个节点一个磁盘块，多键多子
2. 扇出 —— 分支数大（数百），树高 O(log_t N) 极低
3. 平衡 —— 所有叶子同深度，插入分裂、删除合并
4. I/O —— 一次查找 = 树高次 I/O（3~4 次覆盖十亿级）
```

```python
class BNode:
    def __init__(self, t, leaf=True):
        self.t, self.leaf = t, leaf
        self.keys, self.children = [], []

class BTree:
    def __init__(self, t):
        self.t, self.root = t, BNode(t)

    def search(self, key, node=None):
        node = node or self.root
        i = 0
        while i < len(node.keys) and key > node.keys[i]:
            i += 1
        if i < len(node.keys) and node.keys[i] == key:
            return node, i
        return None if node.leaf else self.search(key, node.children[i])

    def insert(self, key):
        if len(self.root.keys) == 2 * self.t - 1:     # 根满，先分裂
            nr = BNode(self.t, leaf=False)
            nr.children.append(self.root)
            self._split(nr, 0)
            self.root = nr
        self._insert_nonfull(self.root, key)

    def _split(self, p, i):
        t, c = self.t, p.children[i]
        new = BNode(t, c.leaf)
        p.keys.insert(i, c.keys[t - 1])
        p.children.insert(i + 1, new)
        new.keys, c.keys = c.keys[t:], c.keys[:t - 1]
        if not c.leaf:
            new.children, c.children = c.children[t:], c.children[:t]

    def _insert_nonfull(self, n, key):
        i = len(n.keys) - 1
        if n.leaf:
            n.keys.append(None)
            while i >= 0 and key < n.keys[i]:
                n.keys[i + 1] = n.keys[i]; i -= 1
            n.keys[i + 1] = key
        else:
            while i >= 0 and key < n.keys[i]:
                i -= 1
            i += 1
            if len(n.children[i].keys) == 2 * self.t - 1:
                self._split(n, i)
                if key > n.keys[i]:
                    i += 1
            self._insert_nonfull(n.children[i], key)

bt = BTree(3)
for k in [10, 20, 5, 6, 12, 30, 7, 17]:
    bt.insert(k)
print("B 树查找 12:", bt.search(12) is not None, "| 查找 99:", bt.search(99) is not None)
```

## B+Tree

B+ 树是 B 树的变体，是数据库索引的事实标准（MySQL InnoDB、PostgreSQL 都用它）。区别：所有数据（或数据指针）只存叶子节点，叶子之间用链表串起来；非叶子节点只存键做「导航」。这样做的收益：① 叶子链表支持高效范围查询（顺序扫叶子）；② 非叶子节点不存数据，扇出更大、树更矮；③ 查找任何键都走到底（等长路径），I/O 稳定。范围查询和顺序扫描是 B+ 树相对 B 树的杀手级优势。

```text
B+ 树相对 B 树：
1. 数据只存叶子 —— 非叶子只做索引导航
2. 叶子链表 —— 范围查询、顺序扫描高效
3. 扇出更大 —— 非叶子无数据，一页能装更多键，树更矮
4. 查找等长 —— 所有查找都到叶子，I/O 次数稳定
```

```python
class BPlusLeaf:
    def __init__(self):
        self.keys, self.values, self.next = [], [], None

class BPlusTree:
    def __init__(self, order=4):
        self.order, self.root = order, BPlusLeaf()

    def insert(self, key, value):
        leaf = self.root
        pos = 0
        while pos < len(leaf.keys) and key > leaf.keys[pos]:
            pos += 1
        leaf.keys.insert(pos, key)
        leaf.values.insert(pos, value)
        if len(leaf.keys) > self.order:      # 叶子满，分裂
            mid = len(leaf.keys) // 2
            new = BPlusLeaf()
            new.keys, new.values = leaf.keys[mid:], leaf.values[mid:]
            leaf.keys, leaf.values = leaf.keys[:mid], leaf.values[:mid]
            new.next, leaf.next = leaf.next, new

    def range_scan(self, start, end):
        result, leaf = [], self.root
        while leaf:
            for k, v in zip(leaf.keys, leaf.values):
                if start <= k <= end:
                    result.append((k, v))
            leaf = leaf.next
        return result

bp = BPlusTree(order=3)
for k, v in [(5, 'a'), (1, 'b'), (9, 'c'), (3, 'd'), (7, 'e'), (11, 'f')]:
    bp.insert(k, v)
print("B+ 树范围查询 [3,9]:", bp.range_scan(3, 9))
```

## LSM Tree

LSM 树（Log-Structured Merge-Tree）是「写优化」的存储结构，核心思想：把随机写变成顺序写。写入先进内存的 MemTable（有序，如跳表/红黑树），写满后整个刷成磁盘上的一个有序文件（SSTable），磁盘上的多个 SSTable 靠后台 Compaction 合并。读取时从 MemTable 到各级 SSTable 逐层查（配合 Bloom Filter 加速）。它牺牲一点读性能换极高的写吞吐，是 RocksDB、LevelDB、HBase、Cassandra、ClickHouse（MergeTree）的底层结构。

```text
LSM 树要点：
1. 写路径 —— 写 MemTable（内存），满则刷成有序 SSTable（顺序写）
2. 读路径 —— MemTable → 各级 SSTable，逐层查，Bloom Filter 加速
3. 写放大 —— Compaction 合并会重写数据，写放大需权衡
4. 适用 —— 写密集场景，写吞吐极高、读需多层查找
```

```python
class LSMTree:
    """LSM 树简化：MemTable + 多层 SSTable"""
    def __init__(self, limit=4):
        self.mem, self.limit, self.sstables = {}, limit, []

    def put(self, k, v):
        self.mem[k] = v
        if len(self.mem) >= self.limit:
            self.sstables.append(dict(sorted(self.mem.items())))
            self.mem = {}

    def get(self, k):
        if k in self.mem:
            return self.mem[k]
        for sst in reversed(self.sstables):     # 从新到旧查
            if k in sst:
                return sst[k]
        return None

lsm = LSMTree(limit=3)
for k, v in [("a", 1), ("b", 2), ("c", 3), ("d", 4), ("e", 5)]:
    lsm.put(k, v)
print("LSM 读 a:", lsm.get("a"), "| 读 e:", lsm.get("e"), "| 层数:", len(lsm.sstables))
```

## SSTable

SSTable（Sorted String Table）是 LSM 树落盘的「有序不可变」键值文件，是 LevelDB/RocksDB 的核心磁盘格式。特征：① 键有序存储，支持顺序扫描；② 不可变（immutable），写满后不再修改，靠 Compaction 生成新文件；③ 带稀疏索引和 Bloom Filter，加速点查（不用顺序扫整个文件）；④ 通常按块组织，块内有压缩。它把「乱序写」在内存里排好序，落盘后天然有序，是「顺序写、顺序读」能高效的关键。

```text
SSTable 要点：
1. 有序 —— 键排序存储，支持顺序扫描、范围查询
2. 不可变 —— 写满即封口，修改靠新文件 + 合并
3. 索引 —— 稀疏索引 + Bloom Filter，点查 O(1) 级定位
4. 分块 —— 按块组织，块内压缩，顺序 I/O 友好
```

```python
import bisect

class SSTable:
    """有序键值 + 稀疏索引 + Bloom Filter"""
    def __init__(self, data):
        self.data = dict(sorted(data))
        self.keys = sorted(self.data.keys())
        self.bloom = set(self.keys)             # 简化 Bloom

    def get(self, key):
        if key not in self.bloom:               # Bloom 过滤，直接判不存在
            return None
        pos = bisect.bisect_left(self.keys, key)
        return self.data[self.keys[pos]] if pos < len(self.keys) and self.keys[pos] == key else None

sst = SSTable([("k1", 1), ("k5", 5), ("k3", 3), ("k9", 9), ("k2", 2)])
print("SSTable 查 k3:", sst.get("k3"), "| 查 k99:", sst.get("k99"))
```

## Compaction

Compaction（压实/合并）是 LSM 树后台的核心操作：把多层 SSTable 中「键范围重叠」的文件合并成更少、更有序的新文件，同时删除过期版本（update/delete 的旧值）、去除重复键。它解决两个问题：① 读放大——SSTable 层数越多，一次点查要查的层越多，Compaction 控制层数；② 空间放大——旧版本数据占空间，Compaction 回收。策略有 Size-Tiered（按大小分层合并，写放大低、空间放大高）和 Leveled（按层容量逐层合并，读放大低、写放大高）。

```text
Compaction 要点：
1. 合并 —— 重叠 SSTable 归并成新文件，去旧版本、去重
2. 控制读放大 —— 层数越少，点查越少层
3. 回收空间 —— 删除过期版本、墓碑
4. 策略 —— Size-Tiered（写友好）/ Leveled（读友好）
```

```python
def compaction(sstables):
    """合并多层 SSTable，去旧版本（保留最新值）"""
    merged = {}
    for sst in sorted(sstables, key=lambda s: s.get("seq", 0)):   # 旧->新
        merged.update(sst["data"])           # 新值覆盖旧值
    return dict(sorted(merged.items()))

level0 = {"seq": 0, "data": {"a": 1, "b": 2}}
level1 = {"seq": 1, "data": {"a": 2, "c": 3}}
print("Compaction 结果:", compaction([level0, level1]))   # a=2 覆盖 a=1
```

```python
import heapq, random

def external_sort_file(chunks):
    runs = [sorted(c) for c in chunks]       # 阶段一：内排序成 run
    heap = [(r[0], i, 0) for i, r in enumerate(runs) if r]

random.shuffle(big)
```

### 场景二：LSM 树实现高性能 KV 写入

```python
class MiniLSM:
    """写优化的 KV 存储：随机写变顺序写，读多层 + Bloom 过滤"""
    def __init__(self, threshold=5):
        self.mem, self.threshold, self.levels = {}, threshold, []

    def put(self, k, v):
        self.mem[k] = v
        if len(self.mem) >= self.threshold:
            self.levels.append((set(self.mem.keys()), dict(sorted(self.mem.items()))))
            self.mem = {}

    def get(self, k):
        if k in self.mem:
            return self.mem[k]
        for bloom, sst in reversed(self.levels):   # 新层先查
            if k in bloom and k in sst:
                return sst[k]
        return None

kv = MiniLSM()
for i in range(20):
    kv.put(f"key{i}", i * 10)
print("读 key15:", kv.get("key15"), "| 读 key99:", kv.get("key99"), "| 层数:", len(kv.levels))
```

## 最佳实践与踩坑记录

### 最佳实践

1. 大数据量排序用外排序（多路归并），归并路数尽量大以减少归并轮数
2. 范围查询、顺序扫描多的场景用 B+ 树（叶子链表），别用 B 树
3. 写密集场景用 LSM 树，随机写转顺序写，写吞吐高
4. LSM 树的 SSTable 一定配 Bloom Filter 和稀疏索引，避免点查全文件扫描
5. Compaction 策略按读写比选：写多读少用 Size-Tiered，读多写少用 Leveled
6. 外哈希分区时保证每桶能装进内存，否则递归再哈希

### 踩坑记录

```text
坑 1：外排序归并路数太少导致多轮归并
结论：大文件排序 I/O 次数暴增，慢几个数量级。
原因：归并轮数 = log_k(N/M)，k 太小轮数就多，每轮都要重读重写全量数据。
解法：把内存尽量分给输入缓冲，提高归并路数 k，减少轮数。

坑 2：B 树节点扇出设计太小
结论：树高过高，单次查找 I/O 次数多，索引效率差。
原因：节点没对齐磁盘块大小，扇出小，log 底数小导致树高。
解法：节点大小 = 磁盘页大小，扇出做到数百，树高压到 3~4 层。

坑 3：LSM 树不配 Bloom Filter
结论：点查每次都要扫多层 SSTable，读性能极差。
原因：点查要逐层查找，层数多时 I/O 放大严重。
解法：每层 SSTable 配 Bloom Filter，不存在的键直接跳过。

坑 4：Compaction 过于激进导致写放大爆炸
结论：写吞吐骤降，磁盘寿命缩短。
原因：频繁 Compaction 反复重写同一批数据，写放大几十倍。
解法：按业务调 Compaction 触发阈值和策略，权衡写放大与读/空间放大。

坑 5：SSTable 设计成可变的
结论：更新直接改文件，破坏顺序写，性能崩坏。
原因：SSTable 不可变是「顺序写」的前提，可变会引入随机写。
解法：SSTable 只读不写，更新走「新版本 + Compaction 去旧」。
```

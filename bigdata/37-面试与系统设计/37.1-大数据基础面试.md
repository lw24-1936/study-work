## 概述

大数据岗位面试的第一关是「基础」：数据结构算法（手撕代码的常客）、SQL（分析岗必考）、Hadoop/Hive（大数据工程师的入门组件）。这些问题考察的是「基础是否扎实」——不涉及高深的调优，但要求对原理和细节有清晰的理解。本主题按「核心概念 + 高频面试题（含参考答案）+ 关键代码」组织。

```text
大数据基础面试的考察重点：
1. 数据结构算法 —— 手撕：排序、查找、哈希、树、动态规划
2. SQL —— 窗口函数、JOIN、分组、去重、执行计划
3. Hadoop —— HDFS 读写、MapReduce 流程、YARN 调度
4. Hive —— 分区、分桶、UDF、调优
```

## 数据结构与算法面试

数据结构和算法是大数据岗位的「手撕代码」常客。高频题集中在：数组/链表（反转、环检测）、哈希（两数之和、去重）、树（遍历、BST、最近公共祖先）、排序查找（快排、Top-K、二分）、字符串（反转、匹配）、动态规划（背包、最长子序列）、图（BFS/DFS、最短路）。大数据岗位的算法题通常偏「基础 + 结合实际场景」（如用堆做 Top-K 日志分析）。

```text
高频算法题清单：
1. 排序 —— 快排、归并（手写 + 复杂度）
2. Top-K —— 小顶堆 / 快排分区
3. 二分查找 —— 有序数组、旋转数组
4. 哈希 —— 两数之和、最长无重复子串
5. 链表 —— 反转、环检测、合并有序
6. 树 —— 层序遍历、最近公共祖先
7. DP —— 最长递增子序列、背包
```

```python
# 手撕：Top-K（小顶堆，O(n log k)）
import heapq

def top_k(nums, k):
    heap = nums[:k]
    heapq.heapify(heap)
    for x in nums[k:]:
        if x > heap[0]:
            heapq.heapreplace(heap, x)
    return heap

# 手撕：快排
def quicksort(arr):
    if len(arr) <= 1:
        return arr
    pivot = arr[0]
    left = [x for x in arr[1:] if x <= pivot]
    right = [x for x in arr[1:] if x > pivot]
    return quicksort(left) + [pivot] + quicksort(right)

print(top_k([3, 1, 5, 7, 2, 8, 4, 6], 3))   # [6, 7, 8]
print(quicksort([3, 1, 5, 7, 2, 8, 4, 6]))
```

## SQL 与执行计划面试

SQL 是数据分析岗的必考，重点在「复杂查询」和「执行计划」两个层面。复杂查询考窗口函数（排名、累计、环比）、多表 JOIN、分组聚合、去重；执行计划考「怎么优化慢查询」——会看 EXPLAIN、理解索引失效、谓词下推、join 顺序。高频题：连续登录天数、Top-N 每组、环比增长、去重计数。

```text
SQL 高频考点：
1. 窗口函数 —— ROW_NUMBER/RANK/LAG/LEAD、累计求和
2. JOIN —— INNER/LEFT/FULL 的区别和场景
3. 分组 —— GROUP BY + HAVING、去重 COUNT(DISTINCT)
4. 执行计划 —— EXPLAIN、索引、下推、join 顺序
```

```sql
-- 高频题：每组的 Top-N（每个部门工资前 3）
SELECT dept, name, salary
FROM (
    SELECT dept, name, salary,
           ROW_NUMBER() OVER (PARTITION BY dept ORDER BY salary DESC) AS rn
    FROM employees
) t WHERE rn <= 3;

-- 高频题：连续登录天数（用 ROW_NUMBER 差值分组）
SELECT user_id, COUNT(*) AS consecutive_days
FROM (
    SELECT user_id, login_date,
           DATE_SUB(login_date, INTERVAL ROW_NUMBER() OVER (
               PARTITION BY user_id ORDER BY login_date) DAY) AS grp
    FROM logins
) t GROUP BY user_id, grp HAVING COUNT(*) >= 3;
```

## Hadoop 面试

Hadoop 面试考「HDFS 原理」和「MapReduce 流程」：HDFS 的 NameNode/DataNode 职责、块和副本机制、写流程（流水线）、高可用（HA/Federation）；MapReduce 的 map/shuffle/reduce 三阶段、Shuffle 细节（spill/merge/copy/sort）、Combiner、Partitioner、容错重试。高频题：为什么 HDFS 块是 128MB、小文件问题、Shuffle 过程、MapReduce 和 Spark 区别。

```text
Hadoop 高频面试题：
1. HDFS 读写流程（客户端→NameNode→DataNode）
2. 块为什么是 128MB（寻址 vs 并行度权衡）
3. 小文件问题（NameNode 内存压力）
4. Shuffle 过程（spill/merge/copy/sort）
5. Combiner 和 Partitioner 的区别
6. MapReduce vs Spark（落盘 vs 内存）
```

```text
Shuffle 过程（面试必背）：
Map 端：输出写环形缓冲区 → spill 分区排序 → merge 合并
Reduce 端：copy 拉取 → sort/merge 归并 → reduce 聚合
```

## Hive 面试

Hive 面试考「Hive 架构和调优」：Metastore 作用、内部表/外部表区别、分区/分桶、静态/动态分区、UDF/UDAF/UDTF 三类函数、调优（Map Join、谓词下推、小文件治理、数据倾斜）。高频题：内部表和外部表区别（删表时数据是否删）、分区和分桶区别、怎么解决数据倾斜、Hive 和传统数据库区别。

```text
Hive 高频面试题：
1. 内部表 vs 外部表 —— 删表时外部表保留数据
2. 分区 vs 分桶 —— 分区按目录裁剪、分桶按哈希散列
3. 数据倾斜 —— 加盐、Map Join、Skew Join
4. UDF/UDAF/UDTF —— 一行进一行出/多行进一行出/一行进多行出
5. Hive vs 传统数据库 —— 离线批处理 vs 在线事务
```

## 应用场景实战

### 场景一：手撕「两个有序数组的中位数」

```python
# 面试手撕：二分法求两个有序数组的中位数
def find_median_sorted_arrays(nums1, nums2):
    if len(nums1) > len(nums2):
        nums1, nums2 = nums2, nums1
    m, n = len(nums1), len(nums2)
    lo, hi = 0, m
    while lo <= hi:
        i = (lo + hi) // 2
        j = (m + n + 1) // 2 - i
        if i < m and nums2[j-1] > nums1[i]:
            lo = i + 1
        elif i > 0 and nums1[i-1] > nums2[j]:
            hi = i - 1
        else:
            left_max = max(nums1[i-1] if i > 0 else float('-inf'),
                           nums2[j-1] if j > 0 else float('-inf'))
            if (m + n) % 2 == 1:
                return left_max
            right_min = min(nums1[i] if i < m else float('inf'),
                            nums2[j] if j < n else float('inf'))
            return (left_max + right_min) / 2

print(find_median_sorted_arrays([1, 3], [2]))        # 2.0
print(find_median_sorted_arrays([1, 2], [3, 4]))     # 2.5
```

### 场景二：手撕「连续登录天数」SQL

```sql
-- 计算每个用户的最长连续登录天数
WITH numbered AS (
    SELECT user_id, login_date,
           ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY login_date) AS rn
    FROM logins
    GROUP BY user_id, login_date   -- 先去重
)
SELECT user_id, MAX(consecutive) AS max_consecutive_days
FROM (
    SELECT user_id, COUNT(*) AS consecutive
    FROM numbered
    GROUP BY user_id, DATE_SUB(login_date, INTERVAL rn DAY)
) t GROUP BY user_id;
```

## 最佳实践与踩坑记录

### 最佳实践

1. 算法题先「暴力解」再「优化解」，展示思路过程
2. SQL 题先想「逻辑执行顺序」，窗口函数是得分点
3. Hadoop 题背熟「读写流程 + Shuffle 细节」，这是区分度所在
4. Hive 题把「内部/外部表、分区/分桶、倾斜」三大件吃透
5. 答原理题用「是什么 → 为什么 → 怎么做」结构

### 踩坑记录

```text
坑 1：算法题直接写最优解，说不出思路
结论：代码对了但沟通分低。
原因：面试官想看的是「解题思路」，不是背答案。
解法：先讲暴力解 → 分析瓶颈 → 优化，边写边说。

坑 2：SQL 窗口函数和 GROUP BY 混用
结论：窗口函数放 WHERE 里报错。
原因：窗口函数在 WHERE 之后执行，不能直接过滤。
解法：窗口函数结果套一层子查询再过滤。

坑 3：分不清内部表和外部表
结论：答错「删表后数据是否还在」。
原因：没记住「外部表数据由 HDFS 管理，删表不删数据」。
解法：记牢「内部表 Hive 管理生命周期，外部表数据独立保留」。

坑 4：Shuffle 细节说不全
结论：答「map 输出到 reduce」就完了，得分低。
原因：Shuffle 是 Hadoop 面试的区分度考点，细节（spill/merge）才是重点。
解法：背熟「环形缓冲区→spill→merge→copy→sort→reduce」全流程。

坑 5：把 Hive 当数据库，答不出「为什么慢」
结论：答「Hive 是数据库」这种错误认知。
原因：没理解 Hive 是「SQL 编译成 MR/Tez」的批处理引擎，不是事务数据库。
解法：理解 Hive 的定位（离线数仓 SQL 层），区别于 OLTP 数据库。
```

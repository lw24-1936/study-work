## 概述

RDD（Resilient Distributed Dataset，弹性分布式数据集）是 Spark 最核心的抽象，表示一个不可变、可分区、可并行计算的数据集合。它通过血缘（Lineage）记录计算过程，实现容错；通过 Partition 实现并行；通过懒加载与缓存实现性能优化。RDD 是 DataFrame/Dataset 的底层基础。

```text
要点
- 不可变：一旦创建不可修改，只能生成新的 RDD
- 可分区：数据按 Partition 切分，分布到集群各节点
- 可并行：每个 Partition 对应一个 Task 并行计算
- 可容错：通过血缘 Lineage 重算丢失的分区，无需复制数据
- 可缓存：可将中间结果持久化到内存/磁盘加速复用
```

## Partition

Partition 是 RDD 数据的物理切分单元，一个 RDD 被切分成多个 Partition，分布到不同 Executor 上。Partition 的数量直接决定了任务的并行度，一个 Partition 对应一个 Task。合理的 Partition 数量应使每个 Partition 的数据量适中（通常几十 MB 到几百 MB），避免过少导致负载不均、过多导致调度开销。

```text
要点
- RDD 的逻辑数据被切分为多个 Partition
- 一个 Partition 对应一个 Task，是并行度的单位
- 分区数由数据源、默认并行度或用户指定决定
- 通过 getNumPartitions 查看分区数
- 分区过多/过少都会影响性能
```

```scala
import org.apache.spark.rdd.RDD

val rdd: RDD[Int] = sc.parallelize(1 to 100, 4)   // 4 个分区
println(s"分区数 = ${rdd.getNumPartitions}")          // 4

// 查看每个分区的数据分布
val perPartition = rdd.mapPartitionsWithIndex { (idx, iter) =>
  Iterator(s"分区 $idx 包含: ${iter.mkString(",")}")
}
perPartition.collect().foreach(println)
```

## Transformation

Transformation 是从一个 RDD 生成另一个 RDD 的操作，如 map、filter、flatMap、reduceByKey 等。它不立即执行，只记录下运算逻辑，形成新的 RDD 与血缘关系。Transformation 分为窄依赖（无需 Shuffle）和宽依赖（需要 Shuffle）两类，宽依赖 Transformation 是 Stage 划分与性能瓶颈的关键。

```text
要点
- 输入一个或多个 RDD，输出新 RDD
- 惰性执行，只在 Action 触发时才真正计算
- 窄依赖：map/filter/flatMap/mapPartitions 等
- 宽依赖：groupByKey/reduceByKey/join/sortByKey 等
- 构成 RDD 血缘 Lineage，是容错的基础
```

```python
from pyspark import SparkContext

sc = SparkContext(appName="TransformationDemo")
rdd = sc.parallelize(["hello world", "hello spark", "spark rdd"])

# 多个 Transformation 串联，均为惰性，不触发计算
words = rdd.flatMap(lambda line: line.split(" "))   # 窄依赖
pairs = words.map(lambda w: (w, 1))                  # 窄依赖
counts = pairs.reduceByKey(lambda a, b: a + b)       # 宽依赖（Shuffle）

# 尚未执行，只有调用 Action 才真正计算
print("到这里为止没有任何计算发生")
```

## Action

Action 是触发 RDD 真正计算的算子，它会启动一个 Job，把计算结果返回给 Driver 或写入外部存储。常见的 Action 有 collect、count、reduce、take、saveAsTextFile、foreach 等。每调用一次 Action 就会触发一个 Job，是 Spark 惰性求值机制的执行入口。

```text
要点
- 触发 Job 的执行入口，产生实际计算结果
- 返回 Driver 端：collect/count/first/take/reduce
- 写入外部存储：saveAsTextFile/saveAsSequenceFile
- 每调用一次 Action 触发一个 Job
- 慎用 collect：数据量大时会导致 Driver OOM
```

```scala
val rdd = sc.parallelize(1 to 1000000)

val count = rdd.count()            // Action：返回元素个数
val sum = rdd.reduce(_ + _)        // Action：求和
val firstFew = rdd.take(5)         // Action：取前 5 个

println(s"count=$count, sum=$sum, firstFew=${firstFew.mkString(",")}")

// 写入磁盘也是 Action
rdd.saveAsTextFile("/tmp/numbers")
```

## Lazy

Lazy（惰性求值）是 Spark 的核心设计：所有 Transformation 不会立即执行，只记录计算逻辑，直到遇到 Action 才一次性构建执行计划并运行。惰性求值让 Spark 能够整体优化执行计划（如合并连续的窄依赖算子、重排算子顺序），减少不必要的中间结果落盘与网络传输。

```text
要点
- Transformation 只构建 DAG，不产生数据
- Action 触发时才真正执行
- 允许 Spark 全局优化：算子融合、列裁剪、谓词下推
- 避免中间结果反复物化，节省 IO 与内存
- 副作用操作（如累加器更新）也受惰性影响
```

```scala
import org.apache.spark.util.LongAccumulator

val rdd = sc.parallelize(1 to 1000)
val acc: LongAccumulator = sc.longAccumulator("filtered")

// 下面这行是惰性 Transformation，累加器此时不会更新
val filtered = rdd.filter { x =>
  if (x % 2 == 0) acc.add(1)   // 惰性阶段不会执行
  x > 500
}

println(s"Action 之前累加器值 = ${acc.value}")   // 0，证明尚未执行

val result = filtered.collect()                    // 触发真正计算
println(s"Action 之后累加器值 = ${acc.value}")     // 才被更新
```

## Dependency

Dependency（依赖）描述 RDD 之间如何生成，是血缘关系的具体表现形式。分为窄依赖（NarrowDependency，父 RDD 的每个分区最多被一个子分区使用）与宽依赖（ShuffleDependency，父 RDD 的分区被多个子分区使用）。窄依赖支持在单个节点上流水线式计算，宽依赖则必须经过 Shuffle，是 Stage 切分的边界。

```text
要点
- 窄依赖：子分区只依赖单个父分区，如 map/filter/union
- 宽依赖：子分区依赖多个父分区，如 groupByKey/join
- 窄依赖可合并到同一 Stage 内流水线执行
- 宽依赖触发 Shuffle，划分新 Stage
- 可通过 rdd.dependencies 查看依赖类型
```

```scala
val rdd = sc.parallelize(1 to 100)

val mapped = rdd.map(_ * 2)                 // 窄依赖
val grouped = mapped.groupBy(_ % 10)        // 宽依赖

// 查看 RDD 的依赖类型
println(s"mapped 的依赖: ${mapped.dependencies.head.getClass.getSimpleName}")
println(s"grouped 的依赖: ${grouped.dependencies.head.getClass.getSimpleName}")

// 查看完整血缘
println(grouped.toDebugString)
```

## Shuffle

Shuffle 是宽依赖 Transformation 触发的数据重分布过程：把上游每个分区的数据按 key 重新划分，将相同 key 的数据汇聚到下游同一分区。Shuffle 涉及磁盘读写与网络传输，是 Spark 中开销最大的环节。其核心组件是 ShuffleManager，负责 Shuffle 写（Shuffle Write）与读（Shuffle Read）两阶段。

```text
要点
- 触发条件：宽依赖算子（groupByKey/reduceByKey/join 等）
- 写阶段：Map 端把数据按 key 分区落盘（Shuffle Write）
- 读阶段：Reduce 端拉取对应分区的数据（Shuffle Read）
- 是网络 IO、磁盘 IO、数据倾斜的主要来源
- 可通过减少 Shuffle 次数、预聚合等方式优化
```

```python
from pyspark import SparkContext

sc = SparkContext(appName="ShuffleDemo")

# 构造一个会发生 Shuffle 的操作
rdd = sc.parallelize([("a", 1), ("b", 2), ("a", 3), ("c", 4), ("b", 5)], 2)

# reduceByKey 触发 Shuffle：相同 key 汇聚到同一分区
reduced = rdd.reduceByKey(lambda x, y: x + y)
print(reduced.collect())

# 对比：mapValues 不触发 Shuffle（窄依赖）
mapped = rdd.mapValues(lambda v: v * 10)
print(mapped.collect())
```

## Cache

Cache（缓存）将 RDD 的中间结果持久化到内存或磁盘，供后续 Action 复用，避免重复计算。默认用 cache() 把数据缓存到内存（StorageLevel.MEMORY_ONLY），也可用 persist() 指定存储级别（如 MEMORY_AND_DISK、DISK_ONLY）。缓存是惰性的，需在 Action 触发后才真正物化，适合被多次复用的中间结果。

```text
要点
- cache() 等价于 persist(MEMORY_ONLY)
- persist() 可指定多种存储级别
- 缓存是惰性的，Action 触发后才真正缓存
- 适合被多个 Action 复用的 RDD，避免重复计算
- 内存不足时按 LRU 淘汰，可配合磁盘级别容错
```

```scala
import org.apache.spark.storage.StorageLevel

val rdd = sc.textFile("/data/large_logs").flatMap(_.split(" ")).map((_, 1))

rdd.persist(StorageLevel.MEMORY_AND_DISK)   // 缓存到内存 + 磁盘

// 第一次 Action 触发计算并缓存
val total = rdd.count()

// 后续 Action 直接读缓存，不再重算
val distinct = rdd.keys.distinct().count()

println(s"total=$total, distinct=$distinct")

rdd.unpersist()   // 手动释放缓存
```

## Checkpoint

Checkpoint 是把 RDD 的数据物化到可靠的分布式存储（如 HDFS），并切断其血缘，用于长血缘链路的容错与迭代计算的稳定。与缓存不同，Checkpoint 的数据在 Application 结束后仍存在，且重算成本高时能避免长链路重放。使用前需设置 checkpoint 目录，且 Checkpoint 会额外触发一次 Job 计算。

```text
要点
- 将 RDD 数据写入 HDFS 等可靠存储，切断血缘
- 用于超长血缘、迭代算法、关键中间结果容错
- 需先 sc.setCheckpointDir() 指定目录
- 会额外触发一次 Job 完成物化
- 数据持久存在，不随 Application 结束而消失
```

```scala
sc.setCheckpointDir("hdfs://namenode:8020/spark/checkpoint")

// 构造一个长血缘的迭代计算
var rdd = sc.parallelize(1 to 1000)
for (i <- 1 to 50) {
  rdd = rdd.map(_ + 1)   // 50 次 map，血缘越来越长
}

rdd.checkpoint()          // 标记 checkpoint，触发后物化并切断血缘
println(rdd.count())      // 触发 checkpoint 物化

// 查看血缘：checkpoint 后血缘被截断
println(rdd.toDebugString)
```

## 应用场景实战

### 场景一：日志词频统计（WordCount）

RDD 最经典的入门实战，完整串联 map/flatMap/reduceByKey 等 Transformation 与 saveAsTextFile Action，理解 Lazy 与 Shuffle 机制。

```python
from pyspark import SparkContext

sc = SparkContext(appName="WordCount")

lines = sc.textFile("/data/access.log")

word_counts = (lines
               .flatMap(lambda line: line.split(" "))        # 切词
               .map(lambda word: (word, 1))                   # 映射为键值对
               .filter(lambda t: len(t[0]) > 0)               # 过滤空词
               .reduceByKey(lambda a, b: a + b))              # 聚合（Shuffle）

word_counts.saveAsTextFile("/out/wordcount")   # Action 触发执行
print("词频统计完成")
```

### 场景二：缓存加速的迭代 PageRank

利用 RDD 的缓存与宽依赖 join，实现 PageRank 迭代算法，展示 Cache 在多次复用场景下的加速价值。

```scala
import org.apache.spark.rdd.RDD

// 构造图：每个节点指向一个邻居列表
val links: RDD[(Int, Array[Int])] = sc.parallelize(Seq(
  (1, Array(2, 3)), (2, Array(3)), (3, Array(1, 2))
))

var ranks: RDD[(Int, Double)] = links.mapValues(_ => 1.0)

// 迭代 10 轮
for (i <- 1 to 10) {
  // 宽依赖 join，产生 Shuffle
  val contributions = links.join(ranks).flatMap {
    case (_, (neighbors, rank)) =>
      neighbors.map(n => (n, rank / neighbors.length))
  }
  ranks = contributions.reduceByKey(_ + _).mapValues(0.15 + 0.85 * _)
  ranks.cache()   // 缓存，供下一轮复用，避免重复计算
}

ranks.collect().foreach { case (node, rank) =>
  println(s"节点 $node 的 PageRank = $rank")
}
```

## 最佳实践与踩坑记录

### 最佳实践

1. 优先用窄依赖算子，减少 Shuffle 次数；能用 reduceByKey 就不要用 groupByKey + map。
2. 合理设置分区数，使每个 Partition 数据量适中，避免单分区过大导致倾斜或过小导致调度开销。
3. 对会被多次复用的 RDD 主动 cache/persist，用 `rdd.unpersist()` 及时释放不再使用的缓存。
4. 长血缘或迭代算法及时 checkpoint，切断血缘防止重算爆炸。
5. 用 take/first 代替 collect 预览数据，避免 Driver 端拉取全量导致 OOM。
6. 大数据量写盘优先 saveAsTextFile/parquet 等 Action，而非 collect 回 Driver。
7. 使用 Kryo 序列化（`spark.serializer=org.apache.spark.serializer.KryoSerializer`）降低 Shuffle 与缓存的数据体积。

### 踩坑记录

```text
坑 1：collect 拉取全量导致 Driver OOM
结论：Driver 内存溢出，应用崩溃
原因：用 collect 把千万级数据拉回 Driver 端，超出 Driver 内存
解法：改用 write/saveAsTextFile 落盘，或用 take 取少量样本预览

坑 2：缓存了却未生效
结论：重复执行 Action 仍然重算，缓存无加速
原因：cache() 是惰性的，第一次 Action 后才物化；或内存不足数据被淘汰
解法：确保在复用前先触发一次 Action 物化；内存紧张时用 MEMORY_AND_DISK

坑 3：频繁 Shuffle 导致任务极慢
结论：宽依赖算子过多，网络与磁盘 IO 成为瓶颈
原因：连续使用 groupByKey、join 等宽依赖算子，每步都全量 Shuffle
解法：合并算子、用 map-side 预聚合（reduceByKey/aggregateByKey）减少 Shuffle 数据量

坑 4：checkpoint 目录未设置报错
结论：调用 checkpoint() 抛异常
原因：未调用 sc.setCheckpointDir() 指定 checkpoint 目录
解法：先 setCheckpointDir 指向 HDFS 等可靠存储，再调用 checkpoint

坑 5：长血缘导致 StackOverflow
结论：迭代上百次后 Driver 抛出栈溢出
原因：RDD 血缘链条过长，toDebugString 或 DAG 构建递归过深
解法：定期 checkpoint 切断血缘；或改用 DataFrame 的高阶算子
```
